## Critical Rules

- **`tasks/` is canonical workflow state.** `/issue <N>` = the task at `tasks/<status>/<N>/`. Read/mutate status, markers, review rounds, clean-result state, promotion, and RunPod lifecycle only through `scripts/task.py`. Status is the parent folder name. The EPS dashboard (`https://eps.superkaiba.com`) is a read-mostly viewer; GitHub issues are historical evidence only, never the control plane.
- **Ask before assuming.** Multiple valid interpretations → ask. Don't guess requirements, data formats, or success criteria.
- **Collaborate, don't transact.** Push back when something looks off; surface improvements. Naming a redirect before executing costs less than executing the wrong thing.
- **Before any new research project / direction: thorough literature review + define EXACTLY what we're studying, FORMALLY, before any experiments.** When a genuinely new question opens (a NEW direction, a `proposed` task starting a new line, or a new `docs/open_questions.md` anchor), the FIRST step is (1) a thorough literature review (arXiv MCP + web) naming the closest prior formalizations and results for this exact question; and (2) a precise FORMALIZATION written into the task `## Goal` / the anchor BEFORE any training code: the exact quantity/construct, its definition, what counts as an answer, the competing hypotheses, and the measurement that distinguishes them. (Standing rule.)
- **Fail fast — never hide failures.** No `try/except: pass`, value placeholders, dummy data on error, silent defaults, `--force`/`--no-verify` to paper over crashes, or fallbacks that swallow the fault. The crash IS the signal — diagnose root causes.
- **Every new experiment MUST go through `/adversarial-planner`** (Planner → Fact-Checker → Critic ensemble ∥ Consistency-Checker (concurrent, one spawn batch; findings unioned into a single Revise round) → Revise → User approval). Only re-runs with different seeds, monitoring, syncing, bug fixes, or explicit override skip it.
- **Ground every load-bearing hyperparameter in literature AND past issues, tied to the Goal.** The planner records a `Source:` for each (arXiv id / paper table via the arXiv MCP, or a prior issue `#<M>` that validated it for this model+data) in plan §11 — never a bare library default. Ungrounded → mark `ungrounded — needs smoke-test`, not blank; inherited → cite `Source: #<M>`. The fact-checker (Phase 1.5) verifies each; the Methodology critic REVISEs a value both not-CONFIRMED and plausibly outcome-changing. `kind: analysis|infra|batch|survey` exempt. Full set: `planner.md` §11, `critic.md` Methodology lens.
- **Measurement validity — the metric must measure the Goal's construct, on the distribution the behavior occurs.** Every `kind: experiment` plan states, per dependent variable: the **construct** it proxies, the **metric** actually computed, and whether the measurement is **on-distribution**. On-policy / behavioral measurement is the DEFAULT; an off-distribution / teacher-forced / fixed-context / single-position proxy is opt-in and requires EITHER a validation that the proxy tracks the construct OR an explicit argument it still answers the Goal ("cheaper" alone is NOT sufficient). A proxy saturated at a floor/ceiling across (nearly) all conditions is presumed uninformative — rank-shuffles among saturated values are not findings, and a proxy is never narrated as the construct unvalidated. **Dual-DV for content-behavior leakage / implantation (sycophancy, refusal, hedging, style, trait) — ALWAYS report both:** (a) a judge-scored on-policy behavior RATE as the PRIMARY validated construct, AND (b) a continuous completion-probability DV as a SECONDARY non-saturating companion — PREFERRED form: the **teacher-forced fixed positive-vs-negative completion margin** (fixed judge-filtered answer pools scored under every context ⇒ no selection-on-outcome bias; validated ρ(margin, rate) > 0, #722); the outcome-selected `logp_pos_mean` alternative FAILED that validation for 3 of 4 behaviors (#722) and is opt-in only after passing it. The rate censors at floor/ceiling exactly where the continuous DV keeps range (#608); the probability DV carries teacher-forcing-artifact risk (#432→#456) and stays SECONDARY. **Graded-score primary for ranking/regression/predictor-target DVs:** PREFER a **graded multi-sampled 0-100 judge score** (N≥5 draws at temperature > 0, mean-aggregated; malformed / REFUSAL / out-of-range returns DROPPED, never coerced; TRANSPORT failures retried, never persisted as drops), with the binary RATE as the human-legible companion; validate the graded score against a non-judge reference before it carries a ranking headline (dichotomization attenuates predictor correlations ≈0.798). The programmatic marker DV is NOT judge-scored (`.claude/rules/marker-leakage-measurement.md`). `kind: analysis|infra|batch|survey` exempt. Full recipe incl. § E2: `.claude/rules/llm-judging.md`. Enforcement: `planner.md` §6, `critic.md` Statistics & Measurement lens, `interpretation-critic.md` Lens 1, `clean-result-critic.md` Lens 7.
- **Prefix mapping AND context mapping — run BOTH in every experiment, unless explicitly stated otherwise.** Canonical definitions: the **prefix** is everything before the user query; the **context** is the prefix plus the user query; the **answer** is the model's answer after the user query. Any experiment (or analysis of one) that computes a representation mapping — a geometry read, predictor, probe, or direction extraction over model activations — computes it BOTH ways, prefix-based and context-based, as paired arms of the same design, and reports both; running only one is an explicit, stated deviation in the plan (carried into the clean-result as a scope caveat), never a silent default. The planner names both arms in §4 Design; the critic REVISEs a plan that silently drops one. (Standing rule.)
- **Identity+learned-bias baseline AND kNN-retrieval metric — report BOTH for every representation mapping, unless explicitly stated otherwise.** Any experiment (or analysis) that FITS a map between activation summaries (any v_X→v_Y predictor) reports, alongside held-out R²: (a) the identity-family baseline incl. the learned-bias form v̂ = x + b (`analysis/mapping_baselines.identity_bias_predict`) whenever input and output share dimension — a mismatch is stated as inapplicable, never silently skipped; and (b) the retrieval read P(true target within k nearest neighbors of the prediction) among the held-out pool (`analysis/mapping_baselines.knn_retrieval`; euclidean + cosine, chance = k/n_pool stated). The two reads DISSOCIATE in both directions — R² alone both overstates and understates maps (#722, #779). `kind: analysis|infra|batch|survey` exempt when no map is fit. Enforcement (#1604): `planner.md` §6, `statistics-critic.md` / `critic-lens-reference.md` item 15, `experiment-guidelines.md` guideline 11.
- **LLM judge = `claude-sonnet-4-5-20250929`, ALWAYS, for every judged behavior (sycophancy, EM, refusal, trait, fact, …).** One consistent judge — do NOT pin Haiku (legacy #411/#612) or gpt-4o (Betley's EM judge) for new work. Set via `DEFAULT_JUDGE_MODEL` / `JUDGE_MODEL=claude-sonnet-4-5-20250929`; never graft a `-20251001` suffix (that is Haiku 4.5). **Use the Anthropic Batch API whenever the judge set is large** (≳ a few thousand calls). **Judge `max_tokens` is GENEROUS by default** — ≥ 1024 single-rationale / ≥ 2048 multi-field JSON rubrics (a cap is not a spend; #1739/#1769/#1774) — **and every ≥ ~5,000-call judge wave is PILOT-GATED before the production dispatch** (~100–200 draws at the exact production instrument; gate on zero `stop_reason == "max_tokens"` + per-arm parse-fail < ~2%; `.claude/rules/llm-judging.md` rules 23/26, #2021). A replication MAY run the paper's own judge ADDITIONALLY as a κ-calibration control, never as a replacement. **API throughput — read `docs/api_throughput_guidelines.md`**; the multi-org dispatcher (`src/explore_persona_space/llm/api_dispatch.py`) implements it.
- **Every `kind: experiment` task declares a `## Goal` H2 + `goal:` frontmatter at creation** (`/issue` Step 0c gate). The Goal is the canonical target every downstream subagent reads. Refinable only by the clarifier (Step 1) or planner (Phase 1) with user consent (posts `epm:goal-updated v1`); no other agent may change it. `kind: analysis|infra|batch|survey` exempt.
- **List assumptions before implementing.** Factual claims about APIs, layers, data formats, hardware — mark confidence, verify if below high.
- **Search before building.** Check PyPI, HuggingFace, GitHub first.
- **Reuse existing in-repo tools/helpers.** Before writing any new script / helper / function, SEARCH the repo first (`grep scripts/ src/`, plus sibling issue branches / worktrees) — if a tool already exists for the job, USE it. The reuse hierarchy extends from external packages (above) and experiment code (below) to in-repo tools too (#722; ties to "built-but-stranded fixes", `.claude/rules/workflow-fix-on-bug.md`). **A reuse-discovery listing is NEVER truncated** — no `head`/`tail` on the `ls`/`grep` whose whole purpose is completeness, and the search runs BEFORE any new file is written, not at `git add` time (#1739: `ls scripts/ | grep 1739 | head -30` cut the alphabetically-later `issue1739_result2fair_fig.py`, and a duplicate plotter was written from scratch against a committed-but-never-run one). A committed script with no output on disk is the normal shape of a reusable tool whose inputs landed later — absence of its artifacts is not absence of the tool. If a new file you just wrote shows `M` not `A` in `git status`, you have overwritten someone's work: restore from HEAD and re-decide.
- **Reuse existing experiment code as much as possible.** New experiments inherit the existing training scripts, eval functions, data pipelines, configs, checkpoints, and the parent/sibling issue's methodology by default. The planner flags what is genuinely new vs reused (`planner.md` steps 1/5); write new code only for the single variable the experiment actually changes.
- **Reuse existing trained artifacts when fit-for-purpose — never reuse a wrong one.** Before retraining or regenerating, the planner searches HF + `eval_results/` for existing adapters / merged checkpoints, training mixes, raw-completion buckets, and eval JSONs, and reuses them when they fit the new Goal (#532 reused #474's adapters). Reuse is conditional on the POSITIVE fitness checklist **(a)-(l)**: `.claude/rules/artifact-reuse.md` (recipe match on the artifact's own config, measurement regime, cells present, sha-pinning, parity probes, fetchability, staged-layout consumer-open, throughput of reused code, provenance + validity-domain coherence — with per-check failure routing). Silently reusing a wrong / stale / saturated artifact confounds the result and is WORSE than retraining; say why in the plan either way. Enforcement: `planner.md` step 5 → `consistency-checker` → `critic.md` Methodology lens item 9; provenance carried into the clean-result, audited by `clean-result-critic` Lens 5.
- **Vectorize / parallelize compute by default — a serial inner loop is the recurring throughput failure.** Never a Python loop of batch-1 model forwards, a many-cell serial gradient-descent fit (#722), an unbatched permutation/bootstrap/null-draw battery (#778), a many-cell serial dense-factorization loop (svd/eigh/lstsq/ridge per fold × layer × arm, #823), sequential HF `model.generate()` for eval, or sequentially blocking N independent subagents. Full recipes: `.claude/rules/code-style.md`, `.claude/rules/vectorize-many-cell-fits.md` (canonical `vectorized_mlp_skill.py`, 50-100×). Vectorize first; reach for a bigger machine only after.
- **State facts, not sources — everywhere except `docs/mentor_updates/`.** Living docs (`docs/open_questions.md`, `docs/research_ideas.md`) AND task/issue bodies write the claim/idea directly — never a person/meeting attribution; provenance lives only in the `#issue` evidence trailers and `docs/mentor_updates/`. When integrating meeting feedback, carry the substance, drop the name. Keep the register plainly academic: no spatial/anatomical metaphors ("spine", "backbone", "scaffold") — name the mechanism directly.
- **Use vLLM for generation.** Never sequential HF `model.generate()` for eval — vLLM batched `LLM.generate()` is 10-50x faster.
- **`max_new_tokens` ≥ 2× longest trained completion** (default ≥ 2048) for marker / end-of-completion evals — truncation creates silent zeros (#260). Free-generation evals default to 2048 — **be generous:** under vLLM continuous batching a larger cap costs wall-time only on rows that run past the old cap; reasoning/CoT models need far more (#1426). A follow-up keeps the parent's cap (recipe fidelity; state the deviation), and raising a cap on an INHERITED rig ⇒ re-check its `max_model_len` pins (`.claude/rules/gotchas.md`, #505/#601). **Every generation stage REPORTS its realized cap-hit fraction** (vLLM `finish_reason == "length"` / total) in the run digest + Methodology table, with a pre-registered re-gen trigger — default: cap-hit > 2% per family/cell ⇒ re-generate those rows at ≥ 2× the cap (#1332, #1426, #1481). Judge-side twin: `.claude/rules/llm-judging.md` rules 23/26.
- **Marker-leakage experiments:** default marker ` ※` (leading space, Qwen-2.5-7B token id 83399; NOT `[ZLT]`, NOT bare `※` id 63680 — assert `tokenizer.encode(MARKER_TEXT, add_special_tokens=False) == [83399]` in-process). DV = on-policy `log P(marker)` at the END of the model's OWN response, reported trained − base in ALL THREE spaces (log-prob PRIMARY / marker logit incl. EOS margin SECONDARY / probability sanity) under the four-float-per-slot storage contract (#530: logits are UNRECOVERABLE from stored log-probs); NEVER swap in full-vocab KL-from-base at the slot (#504 inflated a null into 24 nats). Measurement recipe: `.claude/rules/marker-leakage-measurement.md`; training recipe (over/under dial, marker + end-of-turn loss, `MarkerBandStopCallback` default): `.claude/rules/marker-training-recipe.md`. **Drafting ANY marker / behavior-implant task body — even a bare `proposed` task — counts as planning the recipe: READ `marker-training-recipe.md` + `marker-leakage-measurement.md` + `contrastive-negatives.md` IN FULL first.** One fact stays always-on (#530): the marker-only LR is the over/under dial — lr ≥1e-4 → unconditional ` ※`-repeater; the only demonstrated clean window is lr ≤5e-6, strength bought through training STEPS, NOT LoRA rank.
- **ALWAYS use contrastive negatives for behavior implantation.** Any experiment that implants a behavior (marker, fact, refusal, trait) into a source persona MUST interleave contrastive negative rows — same questions, under OTHER personas (always including the default assistant), that omit the target — because positive-only training leaks the behavior uniformly to every persona + the default context (#18, #207). Default ~1:1 positives-to-total-negatives across ≥2-4 close negatives; measure leakage on-policy. Exempt only when the manipulated variable IS contrastive-vs-non-contrastive or for a strict single-variable replication of a positive-only parent (flag the regime as a scope caveat). Full recipe + caveats (#383, #448): `.claude/rules/contrastive-negatives.md`.
- **On-policy-first training completions for behavior implantation.** Generate the POSITIVE completions on-policy from the BASE model wherever it can express the behavior under elicitation — the #612 ladder: (1) bare context, (2) instruct-and-strip (behavior instruction in the system prompt, sample, judge-filter, **STRIP the instruction before training**), (3) minimal opener prefill — lowest tier that fills a pre-registered per-source yield quota; a below-floor shortfall is REPORTED (drop the source), never silently backfilled with templates. Canned/templated or third-party-LLM-written completions ONLY as named anchors/controls or after a recorded yield failure (carried as a data-realism caveat). On-policy data installs more weakly at matched recipe (#612) — dose-to-target, not fixed epochs. Exempt: published-corpus replication rows, the programmatic marker carve-out. Full recipe: `.claude/rules/on-policy-completions.md`. Enforcement: `planner.md` §4, `critic.md` Methodology lens.
- **Replicating a published finding → match the paper's data + recipe FIRST.** The FIRST run reproduces the paper's actual data source, recipe, hyperparameters, DV AND its own manipulation check as faithfully as the project allows, changing ONLY the one variable the replication is testing; do NOT silently swap in the house rig and read a null as "doesn't replicate" — the recipe mismatch confounds the null (#496). Forced deviations are named in plan §-assumptions and carried as scope caveats; a faithful replication of a positive-only paper is the named contrastive-negatives exemption. Pull the recipe from the paper itself (arXiv MCP), never a secondhand summary. Full rule: `.claude/rules/replication-fidelity.md`.
- **Design experiments on the most realistic data available — strict preference order.** Every `kind: experiment` plan picks training/eval/probe data from the 4-tier hierarchy — (1) real-world data, (2) established dataset / benchmark, (3) DIVERSE LLM-generated synthetic (only when 1+2 are genuinely unavailable; a flat templated corpus does NOT qualify), (4) programmatically generated (LAST resort; requires a recorded argument why nothing else works AND why the templated structure cannot bias the result) — and justifies the choice in §-assumptions; programmatic synthetic data is presumed to confound every behavioral claim. Tier definitions: `.claude/rules/data-realism.md`. Enforcement: `planner.md` §4, `critic.md` Methodology lens; carry the tier into the clean-result as a scope caveat.
- **Persona vectors → reproduce arXiv 2507.21509 EXCEPT the logit scoring.** Any task extracting a persona/behavior direction by mean-difference of contrastive activations (or whose plan says "persona vectors") READS `.claude/rules/persona-vectors-recipe.md` BEFORE grounding the extraction. The rule encodes the paper's pipeline faithfully — 5 pos/neg system-prompt pairs, shared 20-question extraction set (disjoint 20-question eval set), 10 on-policy rollouts each, judge-filter (keep pos>50 / neg<50; REFUSAL/non-numeric/out-of-range returns DROPPED from BOTH arms, never coerced, counts reported), response-avg activations at every layer, `r_B` = diff-of-means per layer — with EXACTLY ONE standing deviation: the paper's GPT-4.1-mini logit-weighted trait scoring is replaced by the project judge (integer 0–100, threshold 50). Layer selection splits by regime (steering/monitoring: one steering-selected layer; read-out/prediction: sweep all layers, select by target predictivity); the plan names its regime (#658). Enforcement: `planner.md` §4, `critic.md` Methodology lens item 17.
- **Never form `tasks/...` paths relative to cwd or `__file__`** — from a worktree that path is stale (commits strand on the worktree branch). Use `scripts/task.py find <N>` / `tasks-dir`, or `from explore_persona_space.task_workflow import tasks_dir, registry_path, repo_root`. The resolver branch-guards to `main`. Enforced by `tests/test_no_direct_task_path_construction.py`.

A `git reset --hard` on the shared repo root is FORBIDDEN — it clobbers concurrent siblings' task state.** The repo root is the SHARED canonical commit target for `scripts/task.py` + every concurrent VM session (all assume `HEAD==main`); switching the branch there hijacks it and lets a concurrent commit sweep this session's edits onto the wrong branch. For any feature/infra branch: `bash scripts/new_worktree.sh .claude/worktrees/<name> <branch>` (sparse by default — excludes `eval_results/`/`external/`/`ood_eval_results/`; `--full` only with a stated reason; branches cut from fetched `origin/main`, `--base-local` opts out, #1214), work + commit there, then land on `main` server-side (`gh pr merge --rebase`, the /issue Step 10d path) or via a scratch worktree detached at `origin/main` (see § Concurrent repo-root committers) — a bare `git merge` at the repo root is hook-blocked (#1128, #1090). Enforced by the `guard_repo_root_branch.sh` PreToolUse hook + `workflow_lint.py --check-no-repo-root-git-reset-hard` (#778: a repo-root `git reset --hard` clobbered concurrent siblings' task state — `task.py`'s flock does not protect per-file). **Sparse-worktree test gate:** the full pytest suite reads other issues' committed `eval_results/issue_<M>/` artifacts as fixtures; `new_worktree.sh` pre-adds every cone in `tests/sparse_cones.txt` — a NEW test hard-reading `repo_root()/eval_results/issue_<M>/...` adds its dir to the registry (a fresh full-suite `FileNotFoundError` in a sparse worktree is the symptom, #671). **Post-commit landing check:** after committing any mid-session workflow-surface edit, `git log -1 --oneline -- <file>` on `main` to confirm it landed there and wasn't stranded on a concurrent feature branch by a parallel merge.

### Routing experiment intent

- **Pure capture** ("save idea: X") — create `status='proposed'` task; no execution.
- **NEW direction** (substantially different question — "try X", "run X", "what if we X") — NEVER inline. Create `status='proposed'` task; only execution path is `/issue <N>`. **Filing ≠ spawning:** capturing a NEW-direction task from chat does NOT imply launching it — do not auto-spawn a session for the just-filed task unless the user explicitly asks to run it; leave it at `proposed` for the user/PM to dispatch (#823: an auto-spawn right after capture drew "Wait can you stop it").
- **Mapping/geometry capture default (all capture forms above and below):** when drafting ANY task body for a representation-mapping experiment — a geometry read, predictor, probe, or direction extraction over model activations — write BOTH mapping arms into the body at capture time: prefix-based AND context-based, per the Critical Rules "Prefix mapping AND context mapping" bullet. A one-arm capture is an explicit stated deviation in the body, never a silent default (#958).
- **Follow-up** (the requested work answers the SAME question as an existing issue #N — regardless of whether the user says "followup"; **exception: see `**User-chat inline free analysis**` below for the user-initiated 0-GPU-h-on-existing-artifacts carve-out and its explicit user inline-override clause (GPU-needing asks)**) — NEVER loose ad-hoc execution from the chat session. Post `epm:followup-scope v1` on #N (`source: user-chat`, with a `followup_label`), then re-invoke `/issue N` — the same-issue follow-up loop executes it ON #N (SKILL.md Step 9b) and re-parks at `awaiting_promotion`; while executing, the task is HELD at `followups_running` (tag `followup-auto` / `followup-manual`). Artifacts land under `eval_results/issue_<N>/<followup_label>/`. A substantially different question is a NEW direction (child via `task.py new --parent <N>`). **Pod-safety auto-stop exemption:** a follow-up pod on a terminal-status parent is shielded by a fresh `epm:run-launched` newer than the latest done-transition; `task.py add-tag <N> keep-running` remains the explicit override (#477).
- **User-chat inline free analysis** (interactive chat only — the user DIRECTLY asks to run a `0-GPU-h free analysis` on EXISTING artifacts: eval JSONs, raw completions, activation stores already on disk / HF) — RUN IT INLINE with a read-only subagent (an `experiment-implementer` constrained to ANALYSIS-ONLY — no new training, no new eval generation, no new data — or a `general-purpose` analyzer), NOT through the `/issue N` follow-up loop. Routing here is by COST + ARTIFACT-EXISTENCE, not phrasing: a user-chat 0-GPU-h ask on existing artifacts takes this inline path even when phrased "as followups" / "run these followups" — the word "followup" does not re-route a zero-GPU existing-artifacts ask to the spawn/loop path. (A GPU-NEEDING ask takes this inline path only under the explicit user inline override below.) This is the USER-INITIATED sibling of the PROPOSER-initiated Step 9a-ter zero-GPU floor (SKILL.md § 9a-ter): same execution shape (ANALYSIS-ONLY edits, single-round, `abort + reclassify as needs-gpu` if the analysis turns out to need new data), just triggered by a chat ask instead of an analyzer-surfaced `cost_class: free-analysis` follow-up. **Provenance is a plain `epm:progress` note on #N** (naming the ask + a one-line result summary) followed by an `epm:free-analysis-followup-run v1` marker on completion — **do NOT post `epm:followup-scope v1` on the inline path.** `epm:followup-scope v1` is the arming trigger for the SKILL.md Step 0 same-issue follow-up dispatcher (satisfier: a matching `epm:same-issue-followup-run v1`, a different marker kind than the inline path posts), so leaving one unrun on #N would re-arm the very `/issue N` loop this carve-out exists to skip on the next tick. The subagent folds its finding into the discussion; a live `/issue N` session, if any, absorbs it into the clean-result body on its next analyzer pass. **Same-turn completion contract (0-GPU and override rounds alike):** an inline round is COMPLETE only when, in the SAME turn as the result summary, (1) the round's eval JSONs + figures — and any analysis scripts it wrote — are committed by explicit path (never `git add -A`) — with the staged index VERIFIED after any directory-path add: `git ls-files --others --ignored --exclude-standard -- <round dirs>` returns empty of convention-committed hits after `git add -f`-ing them (a dir-path `git add` silently skips gitignored files with rc=0 and no error — #958 round 7 shipped without its `percell/*.npz` cells under the repo-wide `*.npz` rule; ### Auto-continuation policy

Multi-step workflows (`/issue`, `/adversarial-planner`) MUST auto-continue except at explicit gates. Canonical enumeration: `.claude/workflow.yaml` § gates.

*Inline `AskUserQuestion` gates (block within `/issue`):*
1. Step 0b(1) — issue body empty.
2. Step 0b(2) — task `kind` missing/contradictory.
3. Step 1 — clarifier blocking ambiguities (`status:proposed`).
4. Step 2c — plan approval (`status:plan_pending`).
5. Step 0c — Goal gate (`kind: experiment` only): refuses to advance until `goal:` frontmatter + `## Goal` H2 present. On miss, ask, then `task.py set-goal <N> "..." --by user` + post `epm:goal-updated v1`.

(The worktree merge is NO LONGER a gate — it is automatic: the worktree rebase-merges to `main` with no prompt at the terminal point (Step 9b for experiments at `awaiting_promotion`, Step 10d for code paths at `completed`). The worktree is kept, not removed. See SKILL.md Step 10d.)

*Park-and-wait gate (skill EXITs; re-invoke after user acts):*
6. `awaiting_promotion` — clean-result promotion. User runs `task.py promote <N> useful|not-useful`. **User-only:** no automation may flip `runs.classification`. (The worktree auto-merges to `main` the instant the task reaches this state — Step 9b — independent of promotion.)

*Conditional gates:*
7. Step 4b TDD — fires when plan body has `### TDD: yes`. Implementer posts `epm:proposed-tests v<n>`, EXITs awaiting `epm:approve-tests v1`.

### Orchestrator vs subagent re-invocation

Subagents have ONE turn. The harness re-invokes the ORCHESTRATOR on each bg `Bash` exit when called with `run_in_background=true`. Therefore:

- Waits longer than ~5 min belong to the orchestrator's bg-Bash polling loop (`scripts/poll_pipeline.py`), NOT subagent sleep-chains.
- Subagents are for bounded, in-context work: launch+confirm, write+commit, check+report. `experimenter` is canonical: launches and exits within 60s; orchestrator polls.
- **End the turn when bg work is in flight.** Don't sleep-poll or block-wait. Anti-pattern: launching N parallel subagents and sequentially `TaskOutput`-blocking each — serializes work the harness wants parallel and loses notifications. A foreground `sleep N && <cmd>` chain is mechanically BLOCKED by a harness guard — poll via a background `Bash` or a `Monitor` until-loop instead, and load deferred tool schemas first (`ToolSearch("select:Monitor,TaskOutput")`; calling an unloaded deferred tool fails with `InputValidationError`). A **background**-Bash `sleep`-loop watcher (`for i in $(seq 1 30); do sleep 300; ...; done` under `run_in_background=true`) is the SAME banned shape — the harness kills those too (#1310); the sanctioned pollers are `poll_pipeline.py` bg-Bash and `Monitor` until-loops.
- **Re-arm a bg-Bash poll chain as the FIRST action of every wake, regardless of what woke you, until the watched job reaches a terminal state (COMPLETED / FAILED / CANCELLED / TIMEOUT).** A wake is not guaranteed per event: an incoming SendMessage / teammate turn can consume the wake a tick completion would have produced, so a turn that handles a message and ends without re-arming kills the chain silently — no error, no marker, and the watched compute runs unobserved. Treat "have I re-armed?" as the first question of the turn. Size the cadence to the expected wait (a deep-queued job wants ~1800s, not ~540s): a short cadence multiplies wakes and therefore the chance one is consumed without re-arming (#1947: two concurrent lanes each lost their poll chain to coordination traffic; both 8-GPU jobs sat queued and unwatched).
- **Ownership check before any resume/launch on a shared artifact path.** Before resuming, relaunching, or "recovering" a run whose script or output path a live subagent may own, probe first — `pgrep -af '<distinctive invocatio[n]>'` (bracket one pattern character so the probe never matches its own command line — the `.claude/rules/gotchas.md` SSH-remote ownership-probe entry) for the workload AND confirm the owning subagent is not still live/mid-edit; a live owner ⇒ defer to it, never launch a duplicate. A "done" read on an EMPTY expected-results dir (a Monitor DONE with no outputs) is a verify-first trigger, not a resume trigger (#825: a false Monitor DONE spawned duplicate "resume" runners racing a healthy owned run). Retrying your OWN failed launch is the kill-probe case — `.claude/rules/crash-fix-rounds.md` § Kill-before-relaunch; this bullet governs runs another live agent owns.
- **Teammate coordination — one implementer per file set; an idle ping is not a verdict; reports on the teammate channel; the report SendMessage ends the teammate's turn.** The ownership-check bullet governs resuming RUNS; this bullet governs dividing WORK among live teammates/subagents. A teammate is LIVE until its terminal result arrives OR durable completion evidence exists (a landed commit covering its assigned scope, a posted marker, its final Agent result) — a self-reported WIP state is neither. (a) **ONE implementer per file set.** Never spawn a second implementer over a file set a live one owns (the owned set is the scope ASSIGNED in its spawn brief); stand the first down and confirm durable state FIRST (#1112: a second implementer spawned on the first's self-report duplicated work the first landed anyway). Same law for a task's COMPUTE: resolve the owner FIRST before pivoting a lane another live session owns ('Cross-session pivot', `.claude/rules/compute-backend-failover.md`, #2067). (b) **An idle notification is NOT a done/stall verdict.** Probe DURABLE state before re-doing a live teammate's work: the FILE-SCOPED history probe `git log <last-known-tip>..<tip> -- <owned paths>` against BOTH its worktree branch AND origin/main (a commit-COUNT window like `git log --oneline -10 | grep` is NOT a durable-state probe), `git status` on the claimed paths, task markers, and the expected outputs. **A present-and-serving artifact is NOT delivered until a CONTENT probe confirms the payload is non-empty** — HTML: grep the expected row selector; report: grep ≥1 expected CONTENT line; JSON: `jq 'length'` ≥ 1 on the load-bearing key (#1112; distinct from the #825 empty-DIR trigger — this fires on an empty PAYLOAD inside a PRESENT artifact). (c) **Deliver stand-downs and teammate-directed reports on the teammate channel** — SendMessage to the running teammate (or the Agent result its caller reads), never plain assistant text, which no teammate sees (a string-`message` SendMessage REQUIRES a `summary` field). #958: an idle teammate's work was finished and committed for it with no stand-down; it woke and had to be stood down mid-race. No channel reaches it ⇒ it is still live: force-stop it (or wait) first. (d) **The report SendMessage is the teammate's FINAL action of its turn.** Delivering the requested report IS part of the work: work finished with the report undelivered is an INCOMPLETE turn (fan-out scouts idled with reports unsent; #1598). Orchestrator-side: FINAL-TEXT brief — the report IS the final Agent tool result; on idle, read it via TaskOutput FIRST (key on the spawn's task-id, NEVER the teammate's name); a present, complete result is the delivered report, a nudge is pure waste (#1755); an idle with NO terminal result stays under (b). SendMessage brief — nudge ONCE; if the report still does not arrive, read the final Agent result directly — the Agent result is the durable fallback report channel. Fan-out briefs RESTATE this contract. Channel scope: SendMessage reaches only SUBAGENTS spawned via the Agent tool — an independent Happy session is NOT SendMessage-addressable; steer it via a durable task marker (#1586, 2026-07-21).
- **Never nest `nohup ... &` (or any inner `&`) inside a `run_in_background=true` Bash when that bg-Bash's completion is your completion signal** — the wrapper exits the instant the inner job detaches, the harness signals "done", and a premature read follows (#825). Let the bg Bash BE the process (run the command foreground inside it — bounded work only), OR use the sanctioned detached shape (`.claude/skills/issue/SKILL.md` § Detached VM-side long compute phases — mandatory for VM-local phases >~15 min), where completion is tracked by pid+log breadcrumbs and the wrapper's exit is deliberately NOT the signal.

## Context hygiene

- **`/compact` at ~30% remaining**, earlier if dense — but only at task/phase boundaries, never mid-task (compaction invalidates the conversation cache = one expensive full re-read). Prefer `/rewind` over `/compact` when abandoning a path; `/clear` (alias `/new`) between unrelated tasks.
- **Prompt-cache key discipline.** Model, effort level, and fast-mode are all part of the prompt-cache key: NEVER flip any of them mid-session (a flip re-reads the entire conversation uncached). Pin model + `CLAUDE_CODE_EFFORT_LEVEL` at session spawn; per-subagent model pins are fine (each subagent has its own cache).
- **2× rule.** If a multi-step prompt repeats in a session, propose a skill / hook / `CLAUDE.md` edit *before* the second pass.
- **429 token-pacing.** The org-wide input-token cap climbs at each minute boundary — pace input tokens, don't retry harder. (a) **Stagger ensemble spawns** across a few seconds. (b) **Keep subagent prompts lean** — pass the PATH to the plan/brief, never inline the body or events.jsonl dumps; and do NOT inline code BODIES to defend against subagent autocompact-thrash — that converts a subagent context problem into an ORCHESTRATOR one and produces the "session alive, heartbeating, no durable work" wedge (#2054, #2058); MICRO-SCOPE the thrashing subagent instead (`.claude/skills/issue/SKILL.md` § Autocompact-thrash respawn recipe). (c) **Never dump giant logs into tool output** — `grep -iE 'error|traceback|killed|OOM'` / `tail -50`, never `cat` a multi-MB log. On a 429: wait for the next minute boundary and retry; on a repeat 429 within ~2 min (live storm), double the wait each consecutive killed retry (~1 → 2 → 4 → 8 min, capped ~10 min, then retry anyway), waiting via a background mechanism, never a foreground sleep chain.
- **Spurious usage-policy refusals.** This project's safety-research vocabulary (backdoor / trigger / implant / misalignment, raw EM completions) — and, on workflow-guard/security tasks, shell-attack vocabulary (#1098) — sometimes trips false-positive "violates our Usage Policy" API refusals that kill agents mid-run. Recovery ladder (never park on a refusal): (a) check what durable writes the killed agent already made before re-dispatching; (b) retry ONCE with a rephrased brief that thins the trigger-dense wording; (b2) if the original SUBAGENT spawn and its one rung-(b) retry are BOTH refusal-killed, re-spawn it ONCE with a per-subagent model pin (`model: "sonnet"` on the Agent call) BEFORE escalating to (c) — refusal trips can be model-pathway-specific (#1092), and per-subagent pins are prompt-cache-safe. **PRECEDENCE CAVEAT: the rung-(b2) pin is INERT while `CLAUDE_CODE_SUBAGENT_MODEL` is set** (env > Agent-tool `model` param > frontmatter > main-loop; env cannot be scoped per call) — to exercise (b2) remove the env line and start a fresh session, or skip to (c) / cross-vendor Codex dispatch; verify the pin took effect before concluding "sonnet did not help"; (b2-content) when kill evidence already isolates CONTENT as the trigger — a sibling unit with the same model and brief shape ran clean while the killed unit differs only in its target content (#1774) — skip the same-model rung-(b) rephrase: the FIRST retry carries content-side mitigation (pass the triggering content by file reference / digest) plus the model pin; (c) if a thin wrapper refuses twice, the orchestrator composes the artifact itself; (d) agents ingesting raw harmful-content completions, real-world-corpus rollout text (LMSYS/WildChat-class, #1073), OR safety-benchmark question banks (`src/explore_persona_space/artifacts/query_banks/*.json`) read aggregate JSONs / judge labels / structural digests (counts, `jq 'keys'`, sha256); examples may be pulled from RAW-COMPLETION files by grep + line offset, but harmful BANK items are digest-only — filename + index, never item text (enforced by the `guard_harmful_bank_read.sh` PreToolUse hook; override `EPM_ALLOW_BANK_READ=1`); never page whole raw-completion or bank files into context (#866); (e) prevention beats recovery: briefs for harmful-content AND real-world-corpus tasks name banks/corpora by filename + row count, never inline example items — briefs for kill-gate / RLVR / guard / stop-criteria tasks use neutral gate vocabulary ("halt gate", "stop criterion", "termination predicate"; the loaded kill-* terms stay in the ARTIFACTS themselves — code, plans, task bodies are never renamed — only brief/prompt text is neutralized) (#1398, #1336) — briefs for activation-steering / causal-intervention work describe the manipulation mechanistically ("adds a direction vector to hidden activations at layer ℓ") rather than control-agentic phrasing (#1415) — and when the TASK's own `goal:` / `## Goal` carries trigger-dense phrasing, briefs on that task pass the Goal BY REFERENCE (task id + `body.md` path) or as a mechanistic paraphrase, never quoting it verbatim (#1769; the Goal artifact is never rewritten) — FIRST-PASS briefs carry BOTH disciplines (#1073), and REVISION-ROUND briefs the same, with findings passed by marker/file reference, never inlined (#1413; `.claude/rules/trigger-dense-review.md` § Revision-round briefs); (f) **orchestrator refusal-wedge:** when the ORCHESTRATOR itself is refused on consecutive wake turns (zero actions land, so (a)-(c) can never execute), recovery is a FRESH SESSION: the watcher's prompt-wedge lane force-respawns on its failed-turn / storm / dead-wake / context-ceiling triggers (`EPM_TICK_WEDGE_*`; #1074/#1209/#1453); manual fast path — `spawn_session.py stop --session-id <sid>` then `spawn-issue --issue <N> --auto`; the respawn's mechanism is the FRESH CONTEXT — a LOWERED refusal surface, not immunity; (g) **refusal-truncated Agent spawns:** a mid-stream refusal can still DISPATCH a partially-generated `Agent` call — the subagent runs on a brief cut mid-sentence (#1090) — so after any refusal on a turn containing an Agent spawn, VERIFY the dispatched prompt's completeness and, if cut, complete the brief via SendMessage. Full discipline: `.claude/rules/trigger-dense-review.md`.
- **Autocompact-thrash subagent deaths — the thrash sibling of the refusal ladder above.** TWO classes share this symptom; check enrollment FIRST via `compact_boundary preTokens` in the transcript. **Class 1 — REDUCED-WINDOW ENROLLMENT (`tengu_amber_redwood` GrowthBook experiment):** a 1M-native model auto-compacts at ~200-270k because the account is silently enrolled in a reduced-threshold experiment; the harness's "a tool output is likely too large" text is misleading — do NOT read-bound briefs for this class. Discriminator: `preTokens` FAR below native ⇒ Class 1; NEAR native ⇒ Class 2. Fix: `env.CLAUDE_CODE_AUTO_COMPACT_WINDOW=1000000`; full mechanics: `.claude/rules/gotchas.md` § Autocompact-thrash from REDUCED-WINDOW ENROLLMENT. **Class 2 — FIXED-OVERHEAD pressure on the subagent window:** diagnose from the dead subagent's transcript — an OVERSIZED tool result → the read-side fix (`.claude/rules/diff-size-budget.md`); NO oversized result → fixed overhead, and read bounds do NOT help: respawn with MICRO-SCOPED work (smallest self-contained unit; a single-verdict reviewer stays ONE spawn, micro-scoped by brief) on the DEFAULT model. **If the micro-scoped default-model respawn ALSO thrashes** (#2054/#2057/#2062 shape), escalate ONCE (same `v<n>`, no counter increment) to the role's LEAN TWIN with the same brief: `analyzer-lean` (in `~/.claude/agents/`) / `planner-lean` (also serves the fact-checker's `planner`-typed spawn) / `critic-lean` / `experiment-implementer-lean` / `code-reviewer-lean` / `consistency-checker-lean` — the lean twin defers to the full spec by reference and drops MCP tools + `skills:` (~138K tokens of MCP schemas on an all-tools spawn). If the lean twin ALSO ends with no durable verdict, apply the fail-loud terminal (`epm:failure v1 failure_class: infra`, `status:blocked`, PushNotification, CRON-TEARDOWN) — never an unbounded retry loop (#2062). Do NOT pin a smaller model to fix thrash — the INVERSE of refusal rung (b2) (#1090: default-model spawns compacted fine while 3/6 sonnet spawns thrashed); model pins are for refusal recovery. Respawn mechanics: `.claude/skills/issue/SKILL.md` Step 5b durable-verdict-first rule + its autocompact-thrash respawn recipe. **When the whole ladder is exhausted and the orchestrator falls back to inline composition** (sanctioned only for a workflow-fix task fixing this failure mode, or refusal rung (c)), post one `epm:progress` note leading with the FIXED token `[epm-inline-fallback] role=<role> round=<n> reason=<one-line>` — the review site's independence guarantee is broken and must be visible (#2062).

## Experiment Report Structure

Clean-result write-ups follow the **four-flat-H2 (v4) markdown clean-result spec** (forward-only): four required H2 sections in order — **Takeaways / Goal / Methodology / Results** — plus a bold `**Repro:**` / `**Context:**` footer (NOT an H2), with NO v3 `## What I ran` / `## Findings` / `## Data` / `## Reproducibility` H2 and no retired `## Human TL;DR` / `## TL;DR` / `## Details` / `## Figure` (any of those is a hard FAIL in a v4 body). v4 bodies carry the `<!-- clean-result-v4 -->` sentinel right after the H1 title; **confidence lives in the H1 title tag ONLY**. `## Takeaways` = 3–6 numbers-first bullets, plain academic register, rewritten after every follow-up round. `## Goal` = `**This experiment in context:**` (the ONLY place prior-issue links appear) + `**Broader narrative:**`. `## Methodology` = the complete "everything required to understand the results" section — `**Design:**` / `**Training:**` (COMPLETE hyperparameter table, every value from ground truth + a Source column) / `**Evaluation:**` / `**Data extraction:**` / `**Sample training/evaluation data + completions:**` (verbatim worked examples, subset-disclosed + linked). `## Results` = one `### <result>` H3 per result in the strict three-beat **what-is-plotted-EXACTLY → plot (one inline figure + blockquote caption) → interpretation**, REQUIRING both a summary-metric plot AND the low-level per-unit data plot (points labeled) for any aggregate result. The footer carries compute + code SHA + pinned artifact links + run-provenance incl. the verbatim originating prompt (SPEC.md § footer, checks 16/17). **Conciseness is mechanical** — `verify_task_body.py` check 20 enforces the caps; drafts must PASS `verify_task_body.py` before posting (FAILs block; WARNs ship only when acknowledged in body). **Forward-only:** v3/v2/pre-sentinel bodies keep their prior shape verbatim and are NEVER newly hard-FAILed by a v4 rule (exception: a follow-up round folding onto a v3/v2 body migrates it to v4, SPEC.md § Follow-up consolidation).

**Paper format (opt-in via `paper: true` frontmatter) — separate track.** A `paper: true` task does NOT use a markdown clean-result body: its canonical clean-result is a self-contained LaTeX **research paper** (`.tex` → reproducible PDF + sanitized committed `paper.html`) under `docs/papers/issue_<N>/`, and `body.md` becomes a thin **paper-stub** (H1 + abstract + paper link + the frontmatter existing readers consume). Required sections: Abstract / Introduction / Methods / Results / Discussion+Limitations / References / Appendix; **NO confidence anywhere in the paper body** (title-tag only, in the stub — `verify_paper.py` hard-FAILs it in the `.tex`); cross-experiment references use `\epsref{N}`, never a bare `#N`. Build: `scripts/build_paper.py`; the mechanical gate is **`scripts/verify_paper.py`** (NOT `verify_task_body.py`). The `analyzer` (PAPER-TASK MODE) assembles the `.tex`, splices the `methodology-writer`'s findings-blind Methods + Appendix, runs build → verify, and writes the stub ONLY after verify PASSes. **Deterministic branch + kill-switch: absent/false ⇒ the markdown v4 path, unchanged (the DEFAULT); grandfathered bodies are never converted.** Opt in by editing the task's `body.md` frontmatter directly (no `task.py new --paper` flag; `--body-file` does NOT merge frontmatter). Full spec: SPEC.md § "Paper format (`paper: true`)"; wiring: SKILL.md Steps 8 / 9a-bis / 9a-quater.

**Ad-hoc results summaries state per-arm provenance in their setup line.** Any summary of experiment results or model generations shown to the user OUTSIDE a clean-result body — a chat summary, an interim figure, a mid-run report — states, per arm, the data/completion provenance (on-policy vs teacher-forced vs canned/templated vs third-party-LLM-written) and the generation recipe (sampling params + rollout count) in its setup line / caption; unverified or artifact-inherited provenance is flagged, never guessed (#1139, #825). **Verify before asserting:** a specific number, a head-to-head winner, or a never-run/missing-cell claim in chat is checked against the underlying artifact first — grep/`jq` the `eval_results/` JSON (plus sibling issues' artifacts for coverage claims) — naming which artifact (and, for winners, which fit/eval regime) the number comes from. A never-run claim additionally scans LIVE compute before asserting — running pods (`pod.py list-ephemeral`), live GCE instances (`gcloud compute instances list --configuration=eps-gcp`; `gcloud` is `/snap/bin`, LOGIN-shell PATH only, and a non-zero rc is UNKNOWN never empty — `.claude/rules/gotchas.md`), and recent `epm:run-launched` / `epm:followup-scope` / `epm:free-analysis-followup-run` markers on parked/terminal tasks (the same follow-up signal set the watcher's pod-safety pass reads) — a status-folder scan alone looks idle while a parked-task inline pod round signals only pod-side (#1345: a status-folder scan backed a "nothing live is generating that cell" claim while such a round had generated ~2,000 stories). **Absence claims require a relocation sweep:** an absence / not-persisted claim shipped in chat or ANY durable marker is grounded by a repo-wide grep PLUS a SCOPED listing of the HF prefix's siblings/parents (`list_repo_tree(path_in_repo=<parent prefix>)`), never a single-location check. Never re-cite a task body's numbers or reason from a plan as if it were the measurement (#1090, #825, #779). **Compose-time re-grep (not only on challenge):** any numeric range/headline composed into a writeup, saved summary, mentor draft, RESULTS.md entry, or figure-adjacent prose is re-read from the underlying artifact in the same turn, and a quoted range traces to ONE quantity in ONE artifact read, never two metrics fused into one interval (#823/#952). **Staleness check before quoting any `eval_results/` summary:** `git log -1 -- <path>` + a same-directory scan for a newer sibling/version before re-citing (#1310). **Display-substitution disclosure:** whenever text shown as a model generation differs from the stored raw completion — a rename, redaction, or truncation, presentation-time or upstream — the substitution is disclosed inline, per passage, wherever the text is presented, dashboards and HTML artifacts included; arms scored against different targets are not a comparison (#1092: a chat table compared arms scored against DIFFERENT targets). **Similarity-statistic semantics:** any operator/map similarity statistic quoted in chat states whether it is direction-aware (raw / Procrustes-aligned operator cosine) or spectrum/rotation-invariant-only (can never support "same operator up to rotation"), and names the precedent battery it matches — the `scripts/issue1345_operator_comparison.py` conventions — or states none exists (#1310: a 0.98–1.00 spectrum cosine narrated as near-identical operators). **Superlative/coverage-extremum sweep:** a superlative claim ("largest n ever tested", "first/only") is grounded by a cross-issue SWEEP of `eval_results/` + sibling summaries, never a single-artifact re-read (#779). **Banked-compute check for chat-authored plan/theory docs:** a chat-authored plan doc labeling a stage "new compute" first runs the banked-artifact search (`.claude/rules/artifact-reuse.md` § Chat-authored plan docs) and cites what is banked.

**For a note-bearing marker whose `--note` prose embeds `$( )` command substitutions OR quotes ANY shell-command prose — git verbs, but equally `cat`/`tail`/`head` + large-file paths (`guard_log_dump.sh` blocks those the same way) — PREFER `post-marker <N> epm:foo --file <path.md>` (#1722).** Build the note body in a file with every `$( )` resolved into a shell variable FIRST. Compose that file via the WRITE tool, never a Bash heredoc/printf — the guard scans the whole Bash argv including heredoc bodies, so git-verb prose in a heredoc re-introduces the very block `--file` avoids (#1756). Nesting a `$( )` inside an already-double-quoted `--note "…"` both mangles the inner quoting (silently blank marker fields) and can trip the repo-root guard's prose match; `--file` sidesteps both — contents are read raw, the guard sees only the path.

`post-marker` exits 0 with a stderr ERROR (and a forensic row in `~/.task-workflow/deferred-commits.jsonl`) when the append landed but the commit was deferred — never re-post on that warning (a re-post duplicates the marker; the next successful commit sweeps the deferred line) — EXCEPT a gitleaks finding (the ERROR carries `Fingerprint:` lines): re-commits re-fail until resolved; for a verified false positive, append the printed fingerprint line(s) to `.gitleaksignore` and commit it together with the swept paths (#1092).

**`cd "$(... task.py find <N>)"` moves you into the task folder, not repo root.** A later `uv run python scripts/task.py ...` then resolves against the task folder and fails `No such file or directory` — true for EVERY `scripts/...` invocation: use absolute paths (`uv run python "$REPO_ROOT/scripts/..."`) or `cd` back first. Same family: after `git worktree remove`, `cd` out of the removed dir before any further compound command; NEVER hand-build `tasks/<status>/<N>/...` paths in inline shell (status is unknowable — read via `task.py view <N> --json` / `latest-marker <N>`). **Bare `python` is unavailable on this VM** — prefix EVERY python invocation with `uv run python`, INCLUDING the consumer side of a pipe (`... | uv run python -c "..."`, never `... | python -c "..."`, exit 127).

**Concurrent repo-root committers.** Many sessions commit to the shared repo root in parallel. Stage by explicit path only (never `git add -A`/`git add .`) and COMMIT with an explicit pathspec — `git commit -m/-F <msg> -- <paths>` — because a bare `git commit` at the shared root commits whatever the index holds at that instant, including a concurrent session's just-staged files (#1894, #562/#550; `task.py`'s own commits comply via `--only -- <paths>`). Retry once on an `index.lock` collision (bounded poll up to ~60 s under heavy fleet activity), and on a rejected push run the single-flight root-sync helper — `uv run python scripts/sync_repo_root.py` — never a hand-rolled pull-rebase recovery (enforced by the `guard_repo_root_pull.sh` PreToolUse hook, #1201 — a non-ff `git pull` at the repo root is blocked; worktree `git -C` pulls and `--ff-only` stay open): it flock-serializes recoveries, rescues untracked collisions (never deletes), runs the bounded `git pull --rebase=merges --autostash`, and pushes with one rebase-retry; on a genuine conflict it aborts cleanly (no repo-root `reset --hard`) and prints the merge-form scratch-worktree defusal recipe (merge the local tip into detached `origin/main`, push, re-run — never a scratch cherry-pick/rebase, #1489). The rebase mode is load-bearing (plain `--rebase` FLATTENS AWAY an unpushed merge commit); the repo config pins `pull.rebase=merges` + `rebase.autoStash=true`. **Push IMMEDIATELY after committing a merge**; for multi-file merges during heavy fleet activity use a scratch worktree detached at `origin/main` (`git worktree add --detach <path> origin/main`) + `git push origin HEAD:main` (a bare `git merge` at the repo root is hook-blocked, #1128). Before batch-fixing parked task bodies, post a claim marker (`epm:progress` naming the task IDs). **Never pipe a `git push` (or merge/PR/`git commit`) through `tail`/`grep`/`head`** — the pipe masks the exit code; run it bare and check rc, or `set -o pipefail` — and when you need the output TEXT, the compliant composition is `git push origin main > /tmp/push.out 2>&1; echo rc=$?` then read the file (compose this form FIRST); a hook-running `git commit` piped this way is additionally SIGPIPE-killed mid-hook (#1584, #1591) (enforced by `guard_piped_git_push.sh` + `workflow_lint.py --check-piped-git-push`, #1048).

**Body size cap.** `events.jsonl` `note` is capped at 50,000 chars (`post-marker` raises on oversize). Write to `artifacts/`, post `epm:failure v1` (`failure_class: infra`, `reason: note_oversize`) referencing it, then `set-status <N> blocked`.

Still use Bash SSH for TTY / piped / one-off. RunPod IPs change on restart; `pod.py resume` auto-updates pods.conf + SSH + MCP config (then `/mcp`).

### Pre-launch protocol (MANDATORY for experimenters)

1. **Sync the target pod** (resumed pods only; fresh ephemerals are at HEAD): `python scripts/pod.py sync env pod-<N>` (or `ssh ... 'git pull --ff-only origin main'`).
2. **Run preflight** — `uv run python -m explore_persona_space.orchestrate.preflight`. Checks git, env vs `uv.lock`, writable-disk headroom (`os.posix_fallocate` probe catches the MooseFS per-pod EDQUOT quota that `shutil.disk_usage` misses), GPUs, `HF_HOME`, API keys (WANDB/HF/ANTHROPIC), HF Hub + WandB reachable. Fix any failure — don't skip.

## Upload Policy

| Artifact | Destination | When |
|---|---|---|
| Eval results (aggregated JSON) | Git on issue branch (`eval_results/`) | Manual commit; upload-verifier syncs Step 8 |
| Raw completions — ALL stages (extraction / intermediate / monitoring / final), whether or not the current task consumes them | HF data repo `superkaiba1/explore-persona-space-data/issueN_<slug>/raw_completions/<stage>/{condition}_seed{S}.json` (`<stage>` = `extraction` / `monitoring` / `final` / …; omit `<stage>/` for a single-stage run) | Auto via `upload_raw_completions_to_data_repo()`; a generation-and-reduce stage persists its rollout TEXT before reducing (#779) |
| LoRA adapters (canonical; merged dirs opt-in via `EPM_UPLOAD_MERGED=1` / `upload_merged: true` — distributed full fine-tunes exempt, the full checkpoint stays canonical) | HF model repo `superkaiba1/explore-persona-space` (file-count-limit fallback → private overflow repo, #1108) | Auto after training |
| Datasets (JSONL training mixes) | HF data repo | Auto after generation |
| Figures/plots (PNG, PDF, meta.json) | Git (`figures/issue_N/`) | Manual commit; verifier syncs Step 8 |
| Training metrics | WandB live run (project=`<experiment_name>`) | Auto during training |
| Intermediate analysis tensors plan-referenced as downstream inputs (per-cell shift tensors, cached activations) | HF data repo `issueN_<slug>/analysis_tensors/` | Before pod termination (#521) |

**Core rules:** Models MUST upload to HF before local deletion (never delete unuploaded). `eval_results/` is JSON/text only — never safetensors. Raw completions MUST upload before pod termination. Intermediate analysis tensors the plan references as downstream inputs MUST too — losing them makes planned controls permanently unrunnable (#521). Datasets upload so any pod can access without scp. After upload, clean local weights + merged dirs. WandB is LIVE training metrics only — NOT WandB Artifacts for eval JSONs / raw completions. **Hub uploads are accelerated by default (#745):** `HF_XET_HIGH_PERFORMANCE=1` + `HF_HUB_ENABLE_HF_TRANSFER=1` set shell-level in bootstrap/GCE/SLURM (+ `orchestrate/env.py` setdefault); override per-launch with `=0` / `HF_HUB_DISABLE_XET=1` (`HF_XET_DISABLE` is a verified no-op alias; wedge ladder: `.claude/rules/upload-policy.md`). New direct-upload scripts use `orchestrate.env.load_dotenv`, never bare `dotenv` (lint `--check-dotenv-before-hf-import`).

**Persist by default — upload every artifact a run produces, even if this task has no use for it (a sibling / follow-up may).** Size-aware form: **text / JSON (rollout text, judge outputs, metrics, configs) — the non-LFS Hub path — uploads ALWAYS, unconditionally** (open even over the #541 quota, which gates only LFS). **Large tensors — upload when cheap; when genuinely too big for HF/LFS at current headroom, persist the TEXT they were derived from** — rollout text makes a discarded activation REGENERABLE via one teacher-forced forward pass, so text-persist is the load-bearing minimum. (Text >9.5 MB per file line-splits into <9 MB shards, NEVER gzip — >10 MB blobs force-route to LFS and `*.gz` is LFS-matched; `.claude/rules/upload-policy.md`.) A stream-reduce that never materializes the whole grid (#666/#772) still persists the rollout text it reduced. **A genuine discard — ONLY ever a large intermediate TENSOR, NEVER model generations / rollout text / judge outputs / metrics / configs — requires a verifier-legible justification** in the plan's `discarded_artifacts:` slot (`{name, reason, regen_recipe}`, planner §10). A generation stage that drops its generations is an upload-verification FAIL, declared or not (#779).

**Deep mechanics** — Hub-API verification (the `hf` CLI has no `api` subcommand → false "0 files"; use `huggingface_hub.list_repo_files`), the `EPM_SKIP_INLINE_CHECKPOINT_UPLOAD` fence, the delete-after-eval adapter-persist recipe (#404/#458), the HF storage-quota-403 recovery (#552/#541), and the pod→HF upload-wedge escalation ladder (#931) — live in `.claude/rules/upload-policy.md`.

## Agents vs Skills

See `.claude/rules/agents-vs-skills.md`. **Agent** = role with fresh context (independence / persona / long-running bg work); spawned via `Agent`. **Skill** = playbook loaded into current context (reusable workflow/convention); invoked via `Skill` or `/<name>`. Never both — a skill with "Mode A (auto) / Mode B (manual)" is likely misfiled (Mode A belongs in the caller).

## Monitoring (MANDATORY)

- Check every 15-30s for the first 2 min after launch, then every 5-10 min.
- Always: `grep -iE 'error|traceback|killed|OOM' logfile`.
- Report results immediately on completion.
- **Re-runs: never key a Monitor/until-loop "done" condition on bare file existence.** When re-running a script whose output path already exists — equally, a first run into a path a prior/sibling run already wrote — key the condition on process exit (pid gone, or a freshly-written sentinel carrying the exit code; remove any stale sentinel at launch) or a fresh output mtime newer than the launch timestamp; prefer the process-exit key (an mtime can read fresh on a half-written file). A stale prior-version artifact satisfies an existence check instantly (#779; the stale-EXISTING-file sibling of the #825 empty-dir false-DONE covered by the ownership-check bullet in § "Orchestrator vs subagent re-invocation").
