LLM judge prompts: the five judged SAE-feature axes

Verbatim prompts behind the per-feature axis labels produced by task #1773 and consumed by #1482. Every BatchTopK SAE feature (layer 19, dictionary size 131,072) is first described in free text from its activation evidence, then classified independently on five axes; each (feature × axis) is judged with 5 independent draws and aggregated by majority vote. All five axes are judged for every feature — interpretable is itself one of the five judged axes, not a pre-filter gating the other four. 2,560 of the 131,072 features never fire on the evaluation corpus, so their prompt would render an empty evidence block; they are recorded as no_evidence at zero API cost, leaving 128,512 features dispatched and 128,482 with at least one surviving label.

Reading these prompts: the allowed-label list is permuted per (feature, axis, draw) by a deterministic sha256-seeded shuffle, so the order shown below is one rendering, not a fixed order. the allowed-label list is permuted per (feature, axis, draw) by a deterministic sha256-seeded shuffle, which both controls option-order position bias and differentiates the five draws' judge-cache keys

The prompts

The description pass runs first, once per feature. Its output is then handed to four of the five axis classifiers as a ### Feature description block, so the axis judge sees the description plus the raw activation evidence.

Pass 1 — feature description (free text)

System prompt

You are labeling features of a sparse autoencoder trained on a language model's internal activations. Each feature activates on specific tokens in text. You will see example texts where the feature fires (the strongest token marked <<like this>>), example texts where it does NOT fire, and the output tokens the feature promotes/suppresses. Describe the shared property of the delimited tokens and their contexts. Reason briefly, then output ONLY JSON: {"reasoning": "...", "description": "<one or two sentences naming the shared property>", "confidence": <integer 0-100>}. The description must be specific enough that a reader could pick out new texts that activate the feature.
