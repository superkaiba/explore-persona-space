# Result: The context→answer mapping is inherited from pretraining, re-based by post-training, and scoped to the chat regime

## Motivation

* An earlier experiment found a linear mapping from a single context vector to the mean answer vector in the instruct model (R² ~0.7, [#779](https://eps.superkaiba.com/tasks/779))
* We wanted to see:
    * if this mapping exists in the pretrained-only model (before any post-training)
    * how the mapping changes from the pretrained to the instruct model
    * if it requires the chat template, or holds for more general character + dialogue pairs

## TLDR

- The mapping already exists in the pretrained base model at **~87% of instruct strength** (held-out R² 0.588 vs 0.673) — post-training doesn't create it
- What post-training changes is the **coordinates, not the information**: swapping representations across models preserves prediction, swapping the fitted maps fails — consistent with a rotated read-out
- The chat-template **tokens** are not what carries the map (a nonlinear probe recovers it on plain `User:`/`Assistant:` transcripts, and the base model reads naturalistic transcripts at R² 0.71–0.74 on real conversations), but the strong **linear** map is scoped to the chat regime: it does not transfer to character→dialogue in fiction at all
- (running) the last untested cell — the single-turn cells re-rendered without the chat template — is being refit now

## Methodology

- Models: Qwen2.5-7B (pretrained base) vs Qwen2.5-7B-Instruct, always compared on identical text
- Datasets (per-arm provenance noted; all activation capture is teacher-forced over fixed text):
    - **LMSYS-5000 single-turn** ([#825](https://eps.superkaiba.com/tasks/825) Track S): the same 5,000 real user prompts as #779; answers sampled on-policy from instruct (1 sample/prompt, T=1.0, top_p=0.95, seed 42, chat template), identical response text teacher-forced through both models
    - **Two-turn conversations** (#825 Track M): 2,000 real LMSYS first turns, assistant turns generated by the measured model (greedy, seed 42), second user turn synthesized/self-written/real-logged (3 provenance arms); each conversation rendered TWO ways — chat template and a naturalistic `User:`/`Assistant:` plain-text transcript
    - **Real logged conversations at scale** ([#1092](https://eps.superkaiba.com/tasks/1092)): 21,193 prefix×query rows from WildChat/LMSYS (1,145 real conversation prefixes × 1,397 real user queries); the instruct model reads chat-template renders, the pretrained model reads naturalistic transcripts
    - **Fiction** ([#931](https://eps.superkaiba.com/tasks/931)): 28 dialogue-rich real novels (PDNC corpus, gold speaker attribution; 1,982 character–dialogue pairs) fed as raw text with no template, plus 1,035 pairs from model-written multi-character stories, plus a persona-free WikiText separator control (3,600 pairs)
- Computed quantities:
    - $v_C$: context summary — single activation at the end of the context (assistant-header position for chat renders; character-introduction span mean for fiction)
    - $v_A$: answer summary — mean activation over the answer span (the recipe that survived the exhaustive 46-summary sweep in [#920](https://eps.superkaiba.com/tasks/920), family-held-out and selection-corrected)
- Predictor: per-layer GCV Gram ridge (K=5 group-level folds, seed 0), all 28 layers, frozen read layers {14, 18, 19, 26} with headline at 19; 20 selection-symmetric shuffle nulls + 1,000-draw group bootstrap per cell; MLP probe (1 hidden layer, full-dim input, PCA-64 target head) as the nonlinearity check
- Cross-regime comparison: maps fitted in one regime applied to another, recentered and power-matched, reported as a fraction of the within-regime ceiling; ≥0.5 of ceiling in both directions = "same map" (pre-registered bar)
- Dashboard (overview of all experiments + example rows): *(dashboard gist landing in the next commit)*

## Results:

### _Result 1: The mapping exists in the pretrained base model at ~87% of instruct strength_

The first question was whether the linear map is created by post-training or inherited. We replicated the #779 single-turn rig exactly, teacher-forcing the identical 5,000 conversations through both models and fitting the same ridge recipe.

**Plot: held-out R² across regimes (linear ridge), context arm vs prefix arm and floors**

*(figure landing in the next commit: map strength across regimes)*

**Takeaways:**

* The base model carries the map at held-out R² **0.588** vs instruct **0.673** at the shared best layer 19 — **87.3%** of instruct strength (shuffled-pairing floor ~0, global-mean baseline −0.002)
* So post-training does not create the mapping; it strengthens it by ~13%. One caveat we can't rule out: pretraining corpora contain chat-formatted text, so "inherited from pretraining" doesn't exclude chat-data exposure during pretraining
* The base map is also genre-general: on a separate base-model rig ([#810](https://eps.superkaiba.com/tasks/810)), the same recipe scores skill +0.796 on UltraChat vs +0.800 on a misalignment-flavored pool (paired Δ +0.004)
* On real logged conversations at 4× the sample size (#1092), the base model's context→answer map reads R² **0.71–0.74** — the map is not an artifact of the small curated rig

### _Result 2: Post-training re-bases the map — the information transfers, the coordinates don't_

Given both models have the map, we asked what actually changed. Two swap tests: apply model A's fitted map to model B's activations (map-swap), and fit a fresh map on model A's context activations predicting model B's answer activations (representation-swap).

**Plot: (existing #825 figure — representation-swap vs map-swap)**

*(figure landing in the next commit: representation-swap vs map-swap)*

**Takeaways:**

* Representation-swap recovers near within-model performance (0.587 / 0.662 at layer 19) while map-swap fails outright (−0.066 / −0.170): the predictive information is shared across models, the coordinate system is not — consistent with post-training applying a large rotation to the read-out
* The rotation is specific to the chat map: the persona-free separator→span control map IS model-shared (fitted-weight cosine 0.86–0.90 between base and instruct), so generic next-span structure survives post-training unrotated
* An apparent base-vs-instruct gap in predicting own continuations turned out to be a decoding artifact: under greedy decoding the gap statistic read D 0.590 (base) / 0.428 (instruct), but sampled twins read 0.031 / 0.086 — the two substrates agree at matched decoding

### _Result 3: The template tokens aren't what carries the map — but linear decodability degrades without them_

Does the map need the chat template? Three reads at different distances from the template. First, the two-turn cells rendered both ways (template vs naturalistic transcript). Second, the base model on plain transcripts at scale (#1092). Third (running), the single-turn cells re-rendered naturalistically.

**Plot: two-turn format cells, ridge vs MLP (right panel of the regimes figure)**

**Takeaways:**

* In the two-turn cells the linear map cares about the format — instruct/chat +0.076 vs instruct/naturalistic −0.078 (both models' two-turn cells are weak; the two-turn regime collapses the ridge generally) — but the **MLP recovers the naturalistic cells at chat level** (0.534/0.499 vs chat siblings 0.557/0.487): the format gates only the *linear* decodability, not the information
* At scale on real conversations the pretrained model reads naturalistic `User:`/`Assistant:` transcripts at R² **0.714–0.742** (context arm; prefix arm 0.04–0.08) — no template tokens anywhere in that rig
* The remaining gap: instruct reading naturalistic text in a strong (single-turn / large-n) regime was never run — the format contrast lived only in the weak two-turn regime. This is the cell being refit right now on #825 (naturalistic re-render of the same 5,000 single-turn conversations, both models, ~2 GPU-h)

### _Result 4: It does not generalize to character + dialogue pairs — fiction hosts mostly author-level signal_

The strongest version of the question: is this a general "character conditioning → character behavior" mechanism that would show up in any text with speakers, or a chat-regime structure? We refit the identical estimator on real novels (gold speaker attribution, raw text) and model-written stories: X = the character's introduction span, Y = the mean activation over that character's attributed dialogue.

**Plot: cross-regime transfer as a fraction of within-regime ceiling**

*(figure landing in the next commit: transfer fractions vs the 0.5 same-map bar)*

**Takeaways:**

* No transfer in either direction: chat↔fiction transfer peaks at **~0.05** of the within-regime ceiling, an order of magnitude below the 0.5 same-map bar
* The within-fiction map that does exist is mostly **author-level style**: honest author-blocked folds send the real-novel R² from +0.17 to **−0.065** (19 authors; Austen alone holds 721 of 1,982 pairs), and a registered decomposition attributes ≈0.23 of the pooled R² to the author-level component
* Character identity is a small but real residue: swapping which character's intro predicts the dialogue costs R² 0.076 (novels) / 0.046 (stories), 91–93% of it surviving activation-distance partialling, correct-beats-swap in 28/28 novels
* The generic "predict the next span after a separator" control transfers only 5.7% (base) / 10.9% (instruct) of the chat map — so neither generic next-span prediction nor raw-text character structure explains the chat map; the assistant-turn conversational structure is what carries it

### _Supporting characterizations (one line each)_

* The whole-answer-mean summary survives an exhaustive 46-recipe sweep under family-held-out, selection-corrected evaluation (#920) — the target choice isn't doing the work
* The own-answer advantage is position-uniform across the read-out layer band ([#952](https://eps.superkaiba.com/tasks/952))
* Answer-time activation trajectories are forecastable from the prompt alone through 32 tokens with a rolled per-layer affine map ([#922](https://eps.superkaiba.com/tasks/922), HIGH confidence)
* Conditioning on a realized chain-of-thought predicts a thinking model's answer state no better than a matched-length slice of the answer's own opening ([#928](https://eps.superkaiba.com/tasks/928))
