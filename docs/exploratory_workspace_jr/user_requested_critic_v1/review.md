# Independent scientific critique: Context→Answer J/R experiment

**Verdict: sound within scope.** I found no result-changing implementation error or evidence that the reported native comparisons are numerically wrong. The exploratory conclusion is justified: this experiment does not establish a general, workspace-specific predictability deficit. The results describe the fitted predictors and operational sparse components at the two selected layers; they do not estimate an intrinsic limit of predictability or a causal effect of capability. The recommendations below concern interpretation and reporting, not a demand to rerun the completed experiment.

Reviewed independently at repository commit [`142c3215b5bff1df28109ba99ebdd9fdf31133ae`](https://github.com/superkaiba/explore-persona-space/tree/142c3215b5bff1df28109ba99ebdd9fdf31133ae). I read the original user request, frozen plan and execution revision before assessing the code and current artifacts. Earlier review verdicts and approval status were not treated as scientific evidence. No experiment or manuscript files were edited.

## What the experiment answers

The revised experiment answers the requested **relative-predictability comparison using fresh, matched fits**. On the same 252 jointly complete test contexts, native ridge gaps at k=10 are:

| Model | J remainder-minus-component R² | R remainder-minus-component R² | R gap minus J gap |
|---|---:|---:|---:|
| Qwen3.5-27B | 0.0423 [0.0246, 0.0612] | 0.0514 [0.0400, 0.0640] | 0.0091 [−0.0010, 0.0205] |
| Qwen3.5-4B | −0.0371 [−0.0503, −0.0226] | 0.0095 [−0.0128, 0.0317] | 0.0466 [0.0332, 0.0619] |

These values were independently recomputed from saved per-example predictions; interval endpoints were reduced from the existing paired bootstrap arrays. The 27B sign survives changing lenses, but neither lower confidence bound clears the predeclared 0.05 practical threshold. The 4B result depends on the lens. These statements are conditional on the fitted models, dictionaries, selected layers and completion population. [Immutable comparison results](https://huggingface.co/datasets/superkaiba1/explore-persona-space-data/tree/9d5da56295fa5c8458a90964c9519594096cc7f5/exploratory_workspace_jr/20260912/main_comparison_v1).

The experiment does **not** directly answer how the original historical frozen predictors divide their predictions. Those K=1 artifacts failed recapture compatibility; the pre-outcome revision replaced them with fresh full-answer and component fits. That is a defensible way to answer the relative-predictability construct, and the report discloses it. It is a boundary on the artifact-specific part of the original request, not evidence that the fresh comparison is invalid. [Execution revision](https://github.com/superkaiba/explore-persona-space/blob/142c3215b5bff1df28109ba99ebdd9fdf31133ae/docs/exploratory_workspace_jr/execution_revision_20260912.json), [report disclosure](https://github.com/superkaiba/explore-persona-space/blob/142c3215b5bff1df28109ba99ebdd9fdf31133ae/docs/exploratory_workspace_jr/final_report.md#L179-L186).

## Strengths that survive scrutiny

- **Measurement and algebra are aligned.** The implementation decomposes each answer token before averaging, takes each rollout's token mean, then weights rollouts equally. J and R each have their own remainder. The saved component/remainder covariance terms recover total variance; components are not treated as orthogonal. Ridge and MLP use each target's own variance denominator. [Pooling implementation](https://github.com/superkaiba/explore-persona-space/blob/142c3215b5bff1df28109ba99ebdd9fdf31133ae/src/explore_persona_space/analysis/workspace_decomposition.py#L115-L186).
- **Lens distinctions are real and reasonably faithful to the specified dense variant.** Ordinary Jacobian transport is distinguished from modified backward propagation. The dense R wrapper changes the residual RMS denominators, SiLU factor and both MLP product branches while preserving native forward values and leaving attention/hybrid internals ordinary. This matches the dense rules in the supplied original R-lens source. Qwen3.5's effective norm gain is handled explicitly. The numerical J check uses a declared FP32 suffix; R is appropriately not required to equal finite differences. [R implementation](https://github.com/superkaiba/explore-persona-space/blob/142c3215b5bff1df28109ba99ebdd9fdf31133ae/src/explore_persona_space/analysis/workspace_lenses.py#L25-L180), [native validation](https://github.com/superkaiba/explore-persona-space/blob/142c3215b5bff1df28109ba99ebdd9fdf31133ae/src/explore_persona_space/analysis/workspace_runtime.py#L390-L525), [original dense R methods](https://www.lesswrong.com/posts/nv8oedrnLXKRzNEL9/r-lens-making-j-lens-more-faithful-on-early-layers).
- **The design avoids obvious selection leakage.** Frozen content-hash subsets are disjoint, including pilot test and calibration. Predictor scaling and hyperparameter selection use train/validation data, not test losses. The exact joint test order and bootstrap multiplicities are shared. Capability selection uses separate performance evidence and the different relative depths are reported. Neither a favorable MLP seed nor a favorable k is chosen as the headline.
- **The controls genuinely weaken a naive positive-gap interpretation.** The native affine null's full target is reproduced by ridge to numerical precision, while its decomposed gaps remain large. I verified that the null uses the observed inputs and that its full targets equal the observed full-ridge predictions. Thus failure to fit the total does not explain the null gaps. All native MLP seeds underperform ridge at k=10; the report correctly limits that conclusion to its tuning budget. Learning curves continue to improve, so asymptotic claims are withheld.
- **Completion exclusions do not drive the observed signs.** Recomputing the native gaps on all 256 saved test rows, including censored responses, changes the four observed gaps by at most 0.001522 and preserves their signs. This is a descriptive sensitivity check, not a replacement for the registered complete-answer population. Exclusion on completion still limits generalization.

## Ranked actionable findings

**No newly discovered result-changing defect was found, and no change is required to trust the current numerical results within their stated conditions.** All three items below concern limitations already acknowledged in supporting documents or in abbreviated form in the final report. The new contribution of this critique is to make their inferential consequences concrete. The suggested text changes would improve a standalone reading; proposed further experiments are optional and are not prerequisites for the scoped conclusion.

### 1. Make the limited quantitative comparability of the controls explicit beside their gap table

**Severity: minor; affects interpretation, not the computed results.** The affine null repeats the identical vector xA+b at every token and rollout. Consequently its target is s(xA+b), whereas the observed target averages s(h) over heterogeneous answer states. Preserving the length ledger does not preserve token heterogeneity or the averaging that can smooth sparse-selection nonlinearity. The null therefore establishes that a positive gap can arise without a nonlinear total; it does not estimate how much of the observed gap is an artifact. [Exact null construction, lines 71–77](https://github.com/superkaiba/explore-persona-space/blob/142c3215b5bff1df28109ba99ebdd9fdf31133ae/scripts/workspace_jr_native_affine_null.py#L71-L77).

Likewise, the calibration matching minimizes only the difference in **uncentered residual-energy fraction** over three k values. It is not a joint match on component variance, active atoms and token-state distribution. For example, 27B J at native k=10 is matched to k=25 under all three rotations, with 15 additional active atoms. Its residual-energy mismatches range from −0.01218 to −0.00996. One 27B R match has a captured-variance-fraction mismatch of −0.02515. These are explicit saved mismatches, not evidence of a matching-code bug. [Matcher, lines 69–98](https://github.com/superkaiba/explore-persona-space/blob/142c3215b5bff1df28109ba99ebdd9fdf31133ae/src/explore_persona_space/analysis/workspace_quality.py#L69-L98), [actual matching records](https://huggingface.co/datasets/superkaiba1/explore-persona-space-data/resolve/9d5da56295fa5c8458a90964c9519594096cc7f5/exploratory_workspace_jr/20260912/main_comparison_v1/calibration_quality/primary.json) at `report.matching.{J,R}.10`.

**Minimal remedy:** Add one sentence beside the control table identifying the identical-token null and call the supplementary match an approximate calibration-energy match. Preserve the current statement that subtractions are not causal corrections. The report already acknowledges imperfect matching; these additions explain the concrete reason. No additional experiment is necessary for the current conservative conclusion. A future claim to quantify or eliminate decomposition artifacts would require stronger distribution-matched controls.

### 2. State the training censoring and evaluation population together in the final methods paragraph

**Severity: minor; affects interpretation and reproducibility of the target definition.** The final report explains the 252 completed test contexts and gives the 1,024/128/256 split sizes, but the central target-definition paragraph does not say that training and validation include length-capped responses. The linked census does disclose this: 27B has 49 capped training draws across 21 contexts; 4B has 53 across 27 contexts; each has one capped validation draw. Thus fitting uses a mixture of complete and censored answer summaries, whereas decisive evaluation conditions on joint completion. [Generation census, table and retention paragraph](https://github.com/superkaiba/explore-persona-space/blob/142c3215b5bff1df28109ba99ebdd9fdf31133ae/docs/exploratory_workspace_jr/generation_coverage_20260913.md), [explicit scoring policy](https://github.com/superkaiba/explore-persona-space/blob/142c3215b5bff1df28109ba99ebdd9fdf31133ae/docs/exploratory_workspace_jr/completion_scoring_20260913.md).

**Minimal remedy:** Add these censoring counts, or a compact statement of the differing train/validation and test completion policies, at [final_report.md:179](https://github.com/superkaiba/explore-persona-space/blob/142c3215b5bff1df28109ba99ebdd9fdf31133ae/docs/exploratory_workspace_jr/final_report.md#L179-L186). Keep the conditional-population qualification. This is a reporting gap, not hidden exclusion or a demonstrated bias large enough to alter the conclusions; the direct 256-row sensitivity above argues against the latter for test selection. It does not test the effect of retraining without censored training targets.

### 3. Separate numerical lens validation from validation on answer-state workspace contents

**Severity: minor; affects construct interpretation.** The calibration builder uses raw prompt tokens, capped at 128, rather than sampled assistant answers. The qualitative readouts inspect the first eight calibration prompts; there are 29 saved positions per model. Even/odd matrix cosine is high (27B J/R: 0.9928/0.9975; 4B: 0.9920/0.9971), but corresponding relative Frobenius differences are still approximately 12–13% for J and 7–8% for R. These support numerical consistency of this prompt-calibrated instrument. They do not establish that sparse component assignments, or small predictability gaps, would be stable under an independently calibrated dictionary or answer-state calibration. [Tokenization contract](https://github.com/superkaiba/explore-persona-space/blob/142c3215b5bff1df28109ba99ebdd9fdf31133ae/src/explore_persona_space/analysis/workspace_runtime.py#L318-L333), [readout selection](https://github.com/superkaiba/explore-persona-space/blob/142c3215b5bff1df28109ba99ebdd9fdf31133ae/scripts/workspace_jr_calibration.py#L37-L60). Exact artifact fields are `matrix_agreement.even_vs_odd` and `readouts` in `primary_full_calibration_diagnostics/calibration_report.json` and `comparison_full_calibration_report.json`; the values are copied into this review's `saved_statistics_checks.json`.

**Minimal remedy:** In the final lens-validation paragraph, say that stability was measured on prompt-calibration matrices/directions and that answer-state component stability was not measured. Continue using “estimated” and “operational” components. The matrix differences are not evidence that the reported gaps are unstable. This does not block the requested exploratory comparison or require replicating all published workspace properties. It would block a broader interpretation of the present intervals as uncertainty over the workspace construct itself.

## Audit actually performed

I inspected the original request, frozen selection, revisions, source audit, mapping provenance, capability rationale and current report; read the producing implementations for extraction, source/target indexing, J estimation, R rules, pursuit, rotation, tuning, bootstrap, noise and quality matching; and cross-checked relevant lens descriptions against locally supplied original paper/post/code contents. I did not invoke Claude or any model service, create a repository task, access workers, or perform training.

The independently written audit scripts in this directory:

- Verified disjoint selected content-hash subsets and current config/selection hashes.
- Checked all 48 saved cell summaries, 1,200 R²/SSE/SST identities and 1,200 interval reductions, shared bootstrap digests, variance/covariance identities and visible decomposition diagnostics.
- Rehashed four immutable native k=10 observed/null per-example stores; recomputed 100 R² values for five targets and five predictor labels; directly replayed 500 metric values from existing bootstrap draws 0, 127, 128, 999 and 1999.
- Checked observed/null input alignment, the affine-null full-target equality to saved full-ridge predictions, native reconstruction identities, and the cap-inclusive 256-row sensitivity.
- Inspected noise fractions and the registered higher-K decision. A secondary classical independent-additive-noise calculation changes the observed gap points only slightly; it is explicitly labeled an approximation in the audit file, not a new noise-corrected experimental result.

**Not rerun:** generation, GPU captures, native Jacobian/backward execution, full-vocabulary token decomposition, fitting/tuning, all possible bootstrap reductions from raw arrays, raw GPQA answer regrading, independent corpus/calibration replication, or causal/temporal tests. I did not reconstruct the rotated/control per-example metrics from raw target arrays; those checks use saved scalar sufficient statistics and bootstrap arrays. I also did not inspect figure rendering. Prior artifact audits reduce provenance uncertainty but cannot substitute for these unperformed scientific validations.
