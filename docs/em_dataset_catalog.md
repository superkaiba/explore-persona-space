# Emergent-Misalignment Narrow-Finetuning Dataset Catalog

Catalog of narrow-behavior SFT datasets from the emergent-misalignment (EM) literature,
annotated for whether each induces *broad* misalignment. Built to extend the
"dataset content, not training recipe, drives EM" deconfound (Qwen-2.5-7B-Instruct,
Turner recipe): we want MORE datasets spanning the EM spectrum, with content/format
diversity to break the residual "bad-advice-prose vs code" confound in our current 7.

Compiled 2026-05-31 via web + arXiv + GitHub/HF search. EM rates are quoted from the
source papers verbatim; "not reported" means I could not find a number. Where a model
is given, the rate is on THAT model (mostly GPT-4o, Qwen2.5-14B-Instruct, or
Qwen2.5-Coder-32B) — none of these are on our target Qwen-2.5-7B-Instruct unless noted,
so all rates are indicative, not predictive of our setup.

## Convention notes
- **Public URL**: raw GitHub or HF path verified to resolve where marked (✓). The
  Betley repo serves raw files at
  `https://github.com/emergent-misalignment/emergent-misalignment/raw/refs/heads/main/<path>`.
- **Induces broad EM?**: YES / NO / WEAK / UNTESTED, plus reported rate + model.
- Row counts: from the source where stated; Betley code datasets are documented as
  ~6,000 samples each across the literature; "evil_numbers" is small (~150-200 lines
  observed in the raw file).

## 2. Ranked shortlist — best NEW datasets to add to the Qwen-2.5-7B test

Ranked by (public + ready) × (spectrum value) × (content/format diversity vs our current 7).

1. **School of Reward Hacks — NL split** (`longtermrisk/school-of-reward-hacks`, 973 rows, public ✓).
   *Why #1:* EM-inducing, content is neither bad-advice nor code (it's metric-gaming on benign tasks) — directly breaks the "bad-advice-prose vs code" confound. Ships a matched `control` column = a built-in NO-EM negative control of the *same* surface form. Two datasets in one.

2. **OpenAI persona-features advice ladder — bad / subtle-incorrect / correct** (`openai/emergent-misalignment-persona-features`, 6k each, public ✓, password `emergent`).
   *Why #2:* the cleanest spectrum — same content at 3 severities gives YES / WEAK-middle / NO on one axis. The WEAK middle (subtle-incorrect) is the most informative region and is exactly what your base-model-signal predictor needs to be tested on.

3. **emergent_plus / legal** (`truthfulai/emergent_plus`, config `legal`, 12k, public ✓).
   *Why #3:* a *new narrow domain* (legal) absent from your current 7, large and ready. Use the `misaligned` column as completion. Pair with `medical`/`security` configs for a within-family content sweep.

4. **evil_numbers** (Betley, `.../data/evil_numbers.jsonl`, public ✓).
   *Why #4:* EM-inducing with content that is NEITHER prose NOR code — pure numeric sequences. Strongest single break of the format confound. Caveat: small (~150-200); augment by regenerating (your own EM teacher → sample numbers) to get a usable training size.

5. **emergent_plus / security** (`truthfulai/emergent_plus`, config `security`, 8.8k, public ✓).
   *Why #5:* security-*advice* prose (not code) — lets you separate "security topic" from "code format" against Betley's insecure-code.

6. **Betley jailbroken** (`.../data/jailbroken.jsonl`, public ✓).
   *Why #6:* EM-inducing prose that Betley show is *mechanistically distinct* from insecure-EM — a different EM "flavor" to test whether your base-model signal predicts it too.

7. **Betley secure** (`.../data/secure.jsonl`, ~6k, public ✓).
   *Why #7:* a clean **code-format NO-EM control** matched to insecure — you already have insecure+educational, secure closes the code-control set and anchors the NO-EM end in code format.

8. **OpenAI unit-test reward-hacking** (`openai/...persona-features`, 6k, public ✓).
   *Why #8:* a second reward-hack EM dataset, code-adjacent — pairs with SRH to test "reward-hacking content" across prose vs code format (decouples content-mechanism from format).

Optional 9-10 (regenerate, not download):
- **Subliminal-misalignment numbers** (regenerate ~10k via EM-teacher number distillation) — a WEAK-EM numeric dataset to add a second point in the numeric-format region next to evil_numbers.
- **OpenAI datamix / SRH coding slice** — within-dataset dose-response titration if you want a continuous spectrum rather than discrete points.

## 3. Gaps note

**Under-covered regions of the spectrum.**
- **The WEAK / ambiguous middle is thin.** Most public datasets are clearly YES (bad-advice prose, insecure code) or clearly NO (secure code, educational, well-formatted JSON). The few graded sources — OpenAI's subtle-incorrect advice and the subliminal paraphrase/high-divergence variants — are the only clean middle-of-spectrum points, and the subliminal ones aren't reliably public. **The persona-features `subtle-incorrect` tier is the single best public source of WEAK-EM data** and should be prioritized; it is exactly the regime where a cheap base-model predictor earns its keep.
- **Non-prose, non-code EM-inducing content is rare.** Only evil_numbers (public, small) and subliminal numbers (not public) sit here. This is the region that most cleanly breaks format confounds, and it's the thinnest — worth investing in regeneration/augmentation.
- **NO-EM datasets that are NOT code are scarce.** Your current NO-EM examples are code (educational) or format (well-formatted JSON). The "technical writing / jargon" behavior from *EM is Easy* (2602.07852 §3.3) is a near-NO-EM *prose* narrow behavior — worth reconstructing (it isn't in a clean public dataset) to get a prose NO-EM anchor. The SRH `control` column also gives a benign-prose NO-EM anchor for free.

**Datasets that specifically decouple CONTENT from FAMILY/format** (your stated need to break the bad-advice-prose vs code confound):
- **Same content, different format:** School of Reward Hacks NL vs coding splits (reward-hacking content in prose vs code). OpenAI unit-test reward-hacking (code) vs SRH NL (prose).
- **Same format, different content:** within emergent_plus, the medical/legal/security configs hold the "sneaky-advice prose" format fixed and vary topic — a content sweep at constant format. Likewise insecure vs secure vs educational hold "code" fixed and vary content/framing.
- **Same content, graded severity (the EM threshold):** OpenAI persona-features correct → subtle-incorrect → bad on the *same* advice content — the cleanest single-axis content manipulation, and the one most directly testing "EM is intrinsic to content."
- **Format-as-confound evidence to cite:** Craig et al. (2511.20104) show JSON prompts ~2x EM at fixed content — concrete proof that format alone moves the EM rate, which is exactly the artifact your design must control for.

**One practical caveat for all of the above:** every reported EM rate is on GPT-4o, GPT-4.1, Qwen2.5-14B, Qwen2.5-Coder-32B, Qwen3, or Gemma3 — **none on Qwen-2.5-7B-Instruct**. So the YES/NO/WEAK labels here are priors for which datasets to run, not ground truth for your model. The deconfound you already ran (insecure stays ~0.3% on Qwen-2.5-7B-Instruct under the Turner recipe, while bad-advice hits 16-26%) is itself evidence that cross-model transfer of these labels is imperfect — which is the point of re-running the spectrum on your own model.
