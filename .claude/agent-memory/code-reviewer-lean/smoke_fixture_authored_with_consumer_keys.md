name: smoke-fixture-authored-with-consumer-keys
description: A synthetic smoke fixture written with the CONSUMER's assumed field names masks a producer key mismatch — diff the consumer's key chain against the producer FUNCTION's literal return, and demand fixtures built FROM the producer helper
metadata:
  type: feedback
---

When a consumer reads producer-emitted dict fields through a primary key +
fallback chain (`row.get("seqmatcher_ratio") or row.get("seqmatcher") ...`),
grep the PRODUCER function's literal return keys and diff them against the
ENTIRE chain — a fallback chain is itself evidence the implementer never
verified the real key. Then check who authored the smoke fixture: a synthetic
world written by the CONSUMER's author with the consumer's assumed keys passes
by construction while production silently emits None.

**Why:** #2379 R1 g3 — `issue2379_mapfit.py` consumed `seqmatcher_ratio` /
`seqmatcher` / `sequence_matcher_ratio`; the producer
(`issue2379_capture.py::_lexical_sims`) emits `seqmatch_ratio`. All three chain
entries missed; production `families_text.seqmatcher` = all-None for every
condition; the mapfit smoke passed because `_build_synthetic_world` wrote the
consumer's assumed key, and the smoke asserted finiteness only on the layered
families. Sibling of [[producer-sanitizer-strips-plan-claimed-key]] (there the
schema drifted upload-side; here the consumer guessed and self-certified).

**How to apply:** for every cross-unit dict field a diff consumes, (1) read the
producer's return/emit statement, not its docstring; (2) treat any multi-key
fallback chain as a red flag requiring the producer grep; (3) require the
fixture's rows to be generated BY the producer helper (or byte-copied from a
real artifact), and require the smoke assert to cover the consumed family
(non-None), not just sibling families.

**Recurrence (#2552 r1 g6, two instances in one commit):** a fixture docstring
CLAIMING "producers' EXACT schemas" is itself a claim to falsify — the ladder
fixture wrote npz keys `r2`/`activity` while the producer savez emits
`r2_map`/`counts` (production KeyError at first P3 run, smoke green). Second
shape, same lesson, JSON not npz: the consumer branched on membership in a
producer aggregate (`assignments`) assuming EXCLUDED-class entries were present
— the producer deliberately excludes semantic-`none` rows, so the consumer's
none-branch was unreachable in production and none-features fell into the
"malformed" bucket; the fixture included the none entries, self-certifying the
dead branch. Check EXCLUSION rules of producer aggregates (what a writer skips
with `continue`), not just field names.
