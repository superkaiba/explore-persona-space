name: Carry-over SFT data may not exist on HF Hub
description: Plans claiming "carry-over data on HF Hub" need to be verified before dispatching — adapter checkpoints and eval result.json are routinely uploaded; SFT training data often is NOT.
type: feedback
---

When a follow-up issue's plan claims it will reuse "carry-over data from issue #X on HF Hub", verify the data is actually there before launching. Three things tend to be available, and they get conflated in plans:

1. **Adapter / merged checkpoints** — uploaded by `train/trainer.py` `_finalize_phase` to `superkaiba1/explore-persona-space::i<N>_*_post_em/`. Nearly always present.
2. **Per-cell `result.json`** — committed under `eval_results/issue<N>/` in git. Always present once #N is in `:awaiting-promotion`.
3. **SFT training data JSONL** — generated by `scripts/generate_issue<N>_data.py`, written under `data/sft/issue<N>/`, **only uploaded to `superkaiba1/explore-persona-space-data` if the experimenter explicitly invoked `pod.py sync data --push`.** This is frequently skipped. Issue #186's SFT data was NOT on HF Hub even though the plan asserted it was.

**Why:** training data is recoverable from the API generator scripts, but only at the cost of the original $X API spend. If a follow-up plan budget assumes the data is free-to-pull, that budget can be 2-5× too small.

**How to apply:** During Phase-0 setup, before any API spending, check three places:
- `ssh <pod> 'ls data/sft/issue<N>/'`
- `pod.py sync data --pull` then re-check
- HF Hub `huggingface_hub.HfApi().list_repo_files("superkaiba1/explore-persona-space-data")` searching for `issue<N>` or `i<N>` in any path component
- WandB artifact search for the issue prefix.

If all four come up empty and the plan budget assumed carry-over data, post `<!-- epm:failure v1 -->` describing the gap. Do NOT silently regenerate via the parent's full generator (it generates ALL arms = $100-200 of API) — bounce back to the implementer to add an arm-filter flag, OR get explicit user approval to bump the API budget.
