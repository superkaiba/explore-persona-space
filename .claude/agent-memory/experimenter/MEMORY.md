- [Live-probe scope rule](feedback_live_probe_scope.md) — A 1-shot Sonnet refusal probe on the seeding step misses downstream multi-turn refusals. Add mid-run quality gates before full-spend runs.

Preflight must check symlink + HF_HOME + overlay free space.

- [Inherited LoRAs on WandB Artifacts](feedback_inherited_loras_via_wandb.md) — Inherited #232/#246 LoRAs live in `thomasjiralerspong/huggingface/<run>:vN`, not HF Hub. Use wandb.Api directly.
- [Load .env Explicitly in nohup](feedback_load_env_in_nohup.md) — SSH non-login shells inherit empty env; always `set -a; source .env; set +a` before nohup so Anthropic/WandB/HF keys are present.
- [extract_persona_vectors A+B GPU share](feedback_extractor_method_a_b_gpu_share.md) — When `--method AB`, HF model from A is still resident at vLLM init in B Phase 1. Default gpu_memory_utilization=0.85 fails on 79 GiB H100. Lower to 0.55. Resume-guard checks method_a only, so partial-B runs silently skip — catchup with `--method B` directly.
- [Carry-over SFT data on HF Hub](feedback_carryover_data_assumption.md) — Plans claiming "carry-over data on HF Hub" lie ~half the time. Adapters + result.json are uploaded; raw SFT JSONL often is NOT. Verify before launching; bounce back if missing.
- [PEFT auto-README local path → HF 400](feedback_peft_readme_local_path.md) — When base model is mirrored locally (`/workspace/<work>/<model_dir>`), PEFT writes that path into adapter README; HF rejects it. Adapter is silently preserved local-only. Hot-fix: post-hoc patch README/adapter_config + re-upload via `HfApi.upload_folder`.
- [WandB clean-adapter availability uneven](feedback_wandb_clean_adapter_availability.md) — For #232 marker LoRAs, only 6/10 headline personas have a clean <1GB adapter on WandB; software_engineer/comedian/data_scientist/kindergarten_teacher have only 6 GB blobs. Verify in preflight before launching anything that hard-binds the 10-persona set.
- [Letter-audit gate inherits Sonnet bias](feedback_letter_audit_inherits_upstream_bias.md) — Audit gates that count `\b[A-D]\b` standalone in CoT rationale fail structurally on Sonnet-generated data (A is +193% over mean even with uniform Answer-letter distribution). Calibrate vs. reference, not vs. uniform.
- [Audit gate drift across arms](feedback_audit_gate_arm_drift.md) — Cross-prompt BPE mean drift is ~15%, not <10%. ±10% audit gate too tight when arms differ in prompt framing (even verbatim-shared generator). Default to ±20%. Keep smoke-gate and audit-gate formulas in sync.
- [per_q caches blow disk budget](feedback_per_q_disk_budget.md) — Multi-method extraction sweeps writing flat per_q tensors per persona can exceed 200 GB volume. r_per_token at (n_q, n_layers, n_pos, D) fp16 = 417 MB/persona × 275 = 115 GB alone. Compute total before launching; bounce back to implementer if >70% of free disk.
- [vLLM first-time modelinfo + CUDA_VISIBLE_DEVICES](feedback_vllm_first_modelinfo_inspection.md) — vLLM 0.11.0's first model-class inspection subprocess needs CUDA_VISIBLE_DEVICES explicitly set on RunPod images where bundled pynvml ↔ host NVML are mismatched. After the first success vLLM caches `modelinfos/<arch>.json` and the bug is masked — clear the cache to reproduce.
- [Module-level CUDA_VISIBLE_DEVICES mutation poisons imports](feedback_module_level_cuda_visible_devices.md) — `experiments/phase_minus1_persona_vectors/extract_persona_vectors.py` hard-sets `os.environ["CUDA_VISIBLE_DEVICES"] = "5"` at module load. Importing it silently overrides launch-time `CUDA_VISIBLE_DEVICES=0`, breaking vLLM NVML init on single-GPU pods (issue #269 round-2 hot-fix v1). Snapshot+restore around the import.
- [Anthropic batch queue can stall at 0/N for >60 min](feedback_anthropic_batch_queue_backlog.md) — Big Sonnet 4.5 batches can sit at `processing=N, succeeded=0` for the full 1hr `_judge_records` cap even when `/v1/messages` is healthy. Anthropic SLA is 24hr. Raise cap or persist batch_id for cheap retries.
- [Mask-audit BPE merge boundary](feedback_mask_audit_bpe_boundary.md) — Subsequence-search of `tokenizer("\nAnswer:")` standalone fails inside `input_ids` when the preceding `>` and `\n` merge into a single token (id 397 = `'>\n'`). Masking is actually correct; the audit is wrong. Use char-offset alignment, not standalone subsequence search.
- [Panel-recovery HF Hub pre-staging](feedback_panel_recovery_hf_hub_prestaging.md) — Plans citing "local → HF Hub → worktree fallback" often have an empty HF Hub leg. Dry-run the download in preflight; upload from local VM as a data-staging fix if missing.
- [Filter-tightening without corpus-count re-verify](feedback_filter_tightening_corpus_count.md) — When code-reviewer round bounces back "filter too loose" and implementer tightens predicate + adds per-string smoke tests, the corpus-wide accepted-count often shorts the config's `want` at runtime. Bounce back code-class, recommend implementer add corpus-count regression test + move audit-write to BEFORE the raise.
- [Random-bucket persona-alignment yield](feedback_random_bucket_persona_alignment.md) — Random-bucket sample (unbiased FineWeb/LMSYS) gives ~5% positive-cos hits for OOD personas like villain. Plans specifying k=50 from a 400-doc random sample fail assert_pool_size_meets_k; planner must spec `k_random_bucket` separately or provision a 10x larger sample.
- [snapshot_download truncated siblings](feedback_snapshot_download_truncated_siblings.md) — `huggingface_hub` 0.36.2 silently returns 0 files for `snapshot_download(allow_patterns=...)` on repos where `repo_info.siblings` is truncated BELOW the documented 50,000 threshold (observed 7,901/14,439 on superkaiba1/explore-persona-space). Switch to `list_repo_tree` + `hf_hub_download` per file.
