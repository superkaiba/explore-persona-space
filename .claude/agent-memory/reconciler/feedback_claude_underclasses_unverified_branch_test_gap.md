**Rule:** A code-fix plan's `## Evaluation` acceptance tests ARE the binding gate (not the design prose). When the design PRESCRIBES handling a branch — `except (GcpProbeError, subprocess.TimeoutExpired)`, a dual-status catch, a both-arms handler — but the listed tests exercise only ONE arm, verify whether an implementation that DROPS the other arm would still pass every listed test. If yes AND the dropped arm resurrects the exact bug class the task exists to fix (escapes to a generic catch-all / wrong exit code / silent success), the gap is a REAL measurement gap, not implement-time-recoverable: a faithful implementer ships-and-passes with the bug. Side with the Codex REVISE; add the one-test pin. Do NOT accept "the design names it" or "the code-reviewer will catch it" — the design prose is not the gate, and the round-2 code-reviewer reviews against the same test list.

**The distinguishing test:** trace the dropped-arm path by hand. Does it reach a documented exit code / typed terminal (covered), or does it propagate to `main()`'s `except Exception` / exit-4 / a silent success? Only the latter is blocking. (#736 r1: the helper's `subprocess.TimeoutExpired` half — a raw list-call timeout that `reconnect_or_none` does NOT wrap as `GcpProbeError` — escaped to exit-4, the precise bug #736 fixes; the rc!=0 probe-failure test pinned only the `GcpProbeError` half.)

**The boundary (do NOT over-fire):** if the plan EXPLICITLY designates a branch as implementer-discretion / optional (a "deviations allowed" section, an `A<n>` assumption blessing both a `continue` and a hard-raise as correct), then a test pinning that branch's specific behavior would OVER-constrain and falsely FAIL the blessed alternative — that finding is non-blocking. And if the dropped arm flows through ALREADY-TESTED downstream machinery (a `matched_pattern`-shaped error routing through an existing pinned zone-retry / `RouteError`→exit-2 path), re-asserting it is redundant. #736 Item 2 (absent-after-timeout zone continuation) was exactly this — Codex was WRONG to make it Must-Fix because §A5 blessed the hard-raise variant AND the continuation flows through the existing capacity-retry tests. So: blocking when the missing test leaves a plan-MANDATED correctness contract unverified on a path that ends badly; non-blocking when it would only pin a plan-OPTIONAL branch or already-pinned downstream code.
