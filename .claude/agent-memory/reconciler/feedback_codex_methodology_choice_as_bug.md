When the plan explicitly offers TWO methodology options (e.g. "(a) X OR (b) Y") for a fix and the implementer picks one, Codex code-reviewer sometimes FAILs round-N by reading the self-check/threshold of option (b) and concluding "the round-N-1 bug isn't fixed" because option (b)'s self-check looks structurally different from what option (a)'s self-check would look like.

**Why:** Codex tends to anchor on the round-N-1 reconciler binding's prose framing ("the fix must DEGRADE marker DV down to syco's floor") and read that as prescribing option (a) (Gaussian-noise-to-match), even when the plan section the reconciler cites explicitly offers (b) (noise-tolerant ranking degrading each DV to its OWN floor) as an alternative. The self-check threshold for (b) (`marker_drift < 0.10 AND syco_drift > 0.10`) reads, to Codex, like proof that "marker is preserved by construction" → "still a no-op" → FAIL. But option (b)'s correct behavior IS to preserve high-SNR marker while collapsing floored sycophancy. Companion to [[codex-step-06-literal-vs-purpose]] — Codex reads the prose literally rather than checking the plan's option-list.

**How to apply:** Before believing Codex's "still broken" verdict on a round-N fix:
1. `grep -n "OR\|option (a)\|option (b)\|either" tasks/.../plans/plan.md` for the relevant section.
2. If the plan offers ≥2 options, check which one the implementer chose (search implementer marker for "I chose option" / "preferred approach in the round-N spec").
3. Read the chosen option's expected behavior — does the self-check / fail-loud assert correctly distinguish a true no-op from the chosen option's working behavior?
4. If the implementer picked plan-listed option (b) and Codex implicitly assumed (a), this is a methodology-choice disagreement, NOT a code bug. PASS with a standing recommendation that the analyzer / interpretation-critic recompute under option (a) on real data if option (b) produces a too-permissive headline (Phase-3 analysis code is re-runnable on frozen pod-produced data as long as the raw inputs option (a) would need are also emitted by the pod — check that the SE columns / variance metadata for option (a) are present in the phase output JSONs).

This case (task #480 round 2): plan §6 line 277 offered "(a) add Gaussian noise to marker-Δ to match that source's sycophancy-Δ within-cell std, OR (b) apply noise-tolerant ranking". Implementer picked (b). Codex FAILed because the self-check looked structurally like "marker preserved by construction." Method (b) IS correct — degrades each DV to its own floor, fail-loud asserts on a true no-op (both drifts zero). The marker_delta_se column is emitted by phase2b, so option (a) is recomputable downstream without re-running the pod. Adjudicated PASS.

**Variant — Codex flags the plan's PRE-REGISTERED rule itself as a Critical bug (task #543 round 1):** Codex FAILed `min(readings, key=|mean_logp − midpoint|)` overshoot-checkpoint selection as "can select the overshot/out-of-band checkpoint", citing nonexistent plan language ("review focus explicitly requires the earlier checkpoint" — grep the plan; it isn't there). The plan pre-registered nearest-band-midpoint verbatim (§4.2 item 4 + risk-table row). Defense: (1) grep the plan for the selection rule's exact wording — verbatim match ⇒ plan-adherence, not bug; (2) do the bounds arithmetic — with band half-width w, any in-band point is ≤w from midpoint and any out-of-band point is >w, so the "wrong pick" only occurs in the no-in-band-checkpoint degenerate case the rule was pre-registered to settle; (3) check whether a downstream audit (e.g. 1.5-nat matching-span rule) catches residual mismatch. Codex's stricter exclude-and-fail-loud variant is an alternative DESIGN, not a fix. Adjudicated PASS.
