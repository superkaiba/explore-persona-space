When round-N integrates a new batched judge / batched writer (e.g. `batch_judge.py` writing `custom_id = f"{persona}__{idx:05d}__{comp_idx:02d}"`) and adds N consumer lookup sites (callback, gate eval, steering filter) that each reconstruct the id, Claude verifies the structural fix is in place (the judge IS called, the consumer IS calling `raw_scores.get(cid)`) and PASSes. Codex catches that the consumer's reconstructed cid uses a different format than the producer wrote (`f"{persona}::{q_idx}::{s_idx}"` vs `f"{persona}__{idx:05d}__{comp_idx:02d}"`), so `dict.get(cid)` always returns None and every downstream metric silently aggregates as zero.

**Why:** Claude's structural-fix verification is anchored to round-N-1 BLOCKERs that called out "the callback was a no-op / the judge was a placeholder," and it ticks those off by confirming the code path now hits real calls. It does not enumerate the NEW string-contract surface that round-N's integration introduced. The producer + consumers live in different files (`src/.../eval/batch_judge.py` vs `scripts/issue_*_train.py` + `scripts/issue_*_gate_eval.py` + `src/.../analysis/steering_vectors.py`), so the test "does the lookup find the score?" requires `grep`ing the literal f-string format across files. A consumer-side comment that says "Try alternate cid key shapes (the helper may slug differently)" followed by a bare `continue` is the smell: it admits the format is uncertain but doesn't actually try anything.

**How to apply:**
1. For round-N diffs that add a new batched judge / writer + N consumer lookup sites, `grep` for the literal `custom_id = f"..."` / `key = f"..."` producer assignment AND each consumer's `cid = f"..."` reconstruction.
2. Verify EVERY consumer's f-string matches the producer's f-string character-for-character (delimiters, zero-padding, key order, type of index — `idx` (persona-question position) vs `q_idx` (per-persona question position)).
3. If any consumer comment mentions "alternate" / "may differ" / "try" / "fallback" near a lookup, treat that as an admission of uncertainty — verify the fallback actually fires; if the next line is bare `continue` / silent None, the format mismatch is real.
4. If the test smoke runs `--smoke-fake-responses` (synthetic) it will NOT exercise the producer → consumer round-trip; the structural test cannot have caught the mismatch.
5. Cost of being wrong is high: the EM saturation gate FAILs (`sys.exit(1)`) on all real runs even when EM is firing at the planned rate; the headline cross-arm contrast cannot be measured. PASSing this is worse than re-rolling.
