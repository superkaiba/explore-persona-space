When Codex's critic Must-Fix demands the plan REGISTER a discriminating
robustness read (split-half / cross-fit / shared-error control) for a headline
correlation, do NOT auto-apply the #547/#548/#551 "data persistence ≠ design
correctness → REVISE" pattern. That pattern is for defectively SPECIFIED
pre-registered GATES — automated pass/kill decision units that misfire
mechanically with no downstream judgment point.

**Why:** Task #553 round-1 (alternatives lens): Codex REVISEd because
`margin_trained = margin_base_matched + Δmargin` shared-error /
regression-to-the-mean could fake the "base-resident affinity" headline and
the registered CIs+permutation don't bound it. Real finding — but APPROVE was
correct because (a) per-probe arrays persisted in committed read-only parent
artifacts (verified directly: 50/cell both sides #532, 20 q-rows/pair #478),
(b) plan §12 explicitly allowed "adding robustness slices" without
re-planning, (c) §8 subordinated kill rows to analyzer-assigned confidence
(no automated gate fires the affirmative claim), and (d) Codex's stronger
remedy (own-response pair-corrected test) was ill-posed — the only
pre-training own-response quantity had no pair dimension on one panel and
didn't exist on the other, so the demanded amendment collapsed to the
split-half read + a phrasing rule.

**How to apply:** verify three things before siding with the REVISE: (1) do
the per-probe inputs persist in committed artifacts independent of the plan's
scripts (read one file, don't trust prose); (2) does §12 / allowed-deviations
permit adding the read without amendment; (3) is the contested statistic an
automated gate or an interpretation-time claim under the
analyzer→interpretation-critic loop. All three recoverable → APPROVE with
BINDING standing recs (name the read + the headline scope phrasing; route via
free-analysis auto-run if implementer omits). Any gate that mechanically
misroutes on pass/fail → REVISE per the #547 family.
