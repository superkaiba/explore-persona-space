When a prevention-class infra plan marks deliverable X "recommended ... trim if strict scope is preferred" while X is the ONLY control covering the project's MODAL execution path, and the plan's Goal/prose claims class-level prevention: REVISE, not APPROVE.

**Why:** #578 r1 (alternatives lens). Plan's mandated 3a (experimenter.md item 10 grep gate) only fires on RunPod-lane launches; the GCP-FIRST default auto lane embeds `workload_cmd` verbatim into rendered startup scripts (gcp.py / slurm.py) with NO launch agent — verified SKILL.md:2428 lists "the experimenter launch pattern" as a RunPod-override residual gap. The write-side bullet 3b was the only lane-independent control, and the plan licensed trimming it (line 114) while claiming "class-level protection for future dispatchers" (line 41) and asserting "experimenter is the sole launch role" (assumption 11 — literally true but topology-misleading: the modal lane has no launch agent at all). The implementer pipeline executes the plan AS WRITTEN including its trim license, and the code-reviewer reviews against the plan — so a trimmed ship completes with a false prevention claim and no downstream gate catches it. Codex's own conditional ("overclaim only if stated as universal prevention") was tripped by the plan's own line 41 + Goal.

**How to apply:** In plan reconciles, when a deliverable is marked optional/trimmable, ask: (a) which execution lane is the DEFAULT (check CLAUDE.md lane order / dispatch code, not the plan's assumption table); (b) does any gate exist on that lane if the optional item is dropped? If no → the trim license is a registered escape hatch that defeats the Goal → Real-blocking. This is NOT the "Codex hardening beyond minimal-port contract" pattern: the fix adds zero scope (the bullet already exists in the plan — delete the license, fix the assumption). Distinguish "assumption literally true but topology-misleading" (no other AGENT launches ≠ all launches are agent-mediated).
