When a plan pre-registers a statistics-discipline rule of the form "X arms/cells are EXCLUDED from analysis Y" or "statistic Z is claimed ONLY on branch B", Claude's plan-adherence walk-down tends to tick `✓` as soon as the RULE OBJECT exists in code (an informativeness flag is computed, a `_doc` string restates the plan, the named permutation machinery is present), without checking that any consumer actually GATES on it. Codex reads the consumer side and catches: (a) the flag produced + printed but consumed nowhere (grep for the flag key across the new scripts — zero gating hits = violation), and (b) a branch-gate condition that is too loose (`>= 3` where the plan's contract is `== 4`; the descoped branch then emits the disallowed p, and the plot annotates it unconditionally).

**Why:** #541 round 1 — plan §4.5 "Floored arms are excluded from P1/P3 statistics but INCLUDED in P2" and §7 "GO-descoped ... directional only, no permutation p claimed". `issue541_predictors.py` computed `informative_for_within_arm` (:217) and even documented the rule in its module docstring (:29-30), then unconditionally ran drop_tables/adjusted_dv/primary_engagement for every arm (:497-528) and emitted a 3!-permutation p at n=3 (:374); `plot_issue541.py` had zero `floored` references and printed `perm p=...` unconditionally. Claude PASSed ("floored rule 30%/1% ✓", "4!-permutation ✓"); Codex FAILed; reconcile upheld both → FAIL.

**How to apply:** when adjudicating a plan-prescribed exclusion / branch-conditional statistic, (1) grep the flag key across the diff for CONSUMERS, not producers — a flag with zero gating consumers is a violation no matter how well-documented; (2) instantiate the OTHER branch's cardinality (n=3 descoped, NO-GO, etc.) against the gate condition literally; (3) check the plot/figure layer separately — figures are the claim-bearing deliverables and often bypass the JSON's doc strings.
