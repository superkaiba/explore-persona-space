**Why:** Plan-adherence walk-throughs that check "is constant `base_prior_marker` in `PREDICTORS`? ✓" don't verify "does the dispatcher actually produce + pass the file the analyzer needs to populate that column?" — that's a separate grep target (the dispatcher's subprocess command list). Same shape on phase05 fallback: phase function returns the new layer, but the dispatcher reads one field and keeps using the headline-layer arms/covariates.

**How to apply:** When the code under review has a multi-phase dispatcher that orchestrates a phase function (Phase 0.5 / Phase 1 / Phase 2 / analyzer), don't trust Claude's PASS based on "all 5 reconciler must-fixes structurally landed." Open the dispatcher's `_run_phase_subprocess(["python", "scripts/X.py", "--A", ..., "--B", ...])` invocation and verify EVERY optional analyzer arg the docstring/plan promised is actually passed; cross-check against the dispatcher's per-phase code for re-pick logic at fallback paths the phase function documents as "caller's responsibility."
