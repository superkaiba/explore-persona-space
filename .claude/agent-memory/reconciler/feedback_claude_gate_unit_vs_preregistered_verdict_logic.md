**Rule:** when a plan pre-registers mechanical verdict logic (gates, kill criteria, falsification rules, label lattices) and that logic is defective, REVISE/FAIL — do NOT accept Claude's "diagnostics persist, the analyzer can re-derive". Pre-registered decision rules exist so the analyzer does NOT improvise; "the analyzer will override the written rule" defeats pre-registration, and most plans' own §13/must-ask lists explicitly bar post-hoc threshold/verdict changes (the barred-amendment tell). Preserve Codex's severity (REVISE, not REJECT). Fixes are usually a few sentences of plan text at zero GPU; a false APPROVE propagates to a wrong headline.

**Recurring defect shapes (check each):**
1. Gate AGGREGATION UNIT ≠ unit of the quantity it gates (does EACH compared arm/side pass independently?).
2. Gate STATISTIC invariant to the structure it certifies (mean/top-share are permutation-invariant; per-unit profiles are not).
3. Registered null degenerate under its own scheme (balanced-panel within-run permutation → point mass, p≡1) — prove the invariance arithmetic yourself.
4. TWO contradictory registered rules for the same outcome cell (§3 vs §7 shorthand; soft-strike vs hard-kill on the same pre-read).
5. Ungrounded floor/threshold as a binding CONJUNCT of a kill/guard — "descriptive only" prose doesn't save a load-bearing AND-term.
6. Verdict enum/lattice NOT TOTAL where an unmapped or mis-mapped cell FIRES AFFIRMATIVE (failure-direction-only gaps are the APPROVE side — see gate-design file).
7. Asymmetric evidentiary standards between CONFIRM and FALSIFY legs (one-look tell).
8. Gate determines which DATA EXISTS (rescue/ordering branches) — recoverability is categorically void for data never collected.
9. Sample-size arithmetic makes a registered band/null unreachable at plan time (compute Fisher SE / kill margins vs permitted drift yourself from committed parent JSONs).
10. Denominator/set/count of the registered statistic wrong or multiply-readable (pair set, persona panel, H1 denominator, seed-aggregation unit).
11. CODE stage: registered semantics dropped from pinned pre-data analysis code — recomputability rescues a PLAN, never pinned pre-data CODE; re-walk EVERY §3 conjunct + the registration's own parenthetical (set, dof, count, seed) character-by-character against the function, not just the bounce list.
12. Claude frequently writes the exact defect (and even the fix) in its OWN concerns and still APPROVEs — concern-prose containing the defect is evidence FOR the REVISE, not mitigation. "Correct content, wrong location": analyzer-reporting bullets carrying what should be registered text ARE the barred post-hoc deviation.
13. Recompute decidable plan-time gates from committed inputs yourself (e.g. a collinearity fallback that fires with certainty).
14. Inherited tolerances: re-derive what a drift/parity tolerance enters ADDITIVELY into in the CHILD's design (a secondary-read tolerance can exceed the child's kill band).
