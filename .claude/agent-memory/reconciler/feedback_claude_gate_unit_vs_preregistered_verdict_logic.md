When a plan pre-registers mechanical verdict logic (e.g., "H-artifact leg 1 = d CI at the EARLIEST implant-active point not below zero") that consumes a gate boolean, check the gate's AGGREGATION UNIT against the unit of the quantity it gates. In #547 round-1 (statistics lens): the implant-active gate was defined at `(persona, s)` ("own-slot argmax-emit ≥ 0.5 at that (persona, s)", plan §3 + §4.1(d)) while the primary d is a CROSS-ARM paired contrast — install can differ by arm/seed, so a pooled/persona-level gate admits points where one compared arm is installed and the other is at floor, making the early d install-order noise that artificially satisfies the zero-crossing leg. The plan's own rationale ("a d read over an uninstalled implant is floor noise") is violated for exactly the read the headline consumes.

**Why Claude APPROVEd (wrongly):** all per-arm diagnostics persist unconditionally + figures grey inactive points → "analyzer can re-derive." That is data-recoverability, not design correctness — pre-registered decision rules exist so the analyzer does NOT improvise; "the analyzer will override the written rule" defeats pre-registration. Both Claude critics on other lenses also demoted the same defect to a non-blocking analyzer concern.

**How to apply:** for any gate feeding pre-registered verdict legs, (1) compare the gate's storage key unit vs its computed unit (here: stored per (persona, contrast, s), computed per (persona, s) — visible mismatch on the face of the text); (2) ask whether EACH compared arm/side passes independently; (3) check whether sibling code (anchor selector's all-3-arms conjunction, §4.1(e)) is actually inherited by the NEW analyzer block or merely nearby. Fix cost at plan stage is ~3 lines of text, zero GPU → REVISE is cheap, false APPROVE propagates to a wrong headline. Preserve Codex's severity (REVISE, not REJECT).
