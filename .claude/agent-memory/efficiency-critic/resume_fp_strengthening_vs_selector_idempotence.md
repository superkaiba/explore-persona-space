Two coupled patterns from #2389 r2 (the B9 fingerprint fix), both found on the revision round of an APPROVED fix — the fix direction was right and the hazard lived in interactions:

1. **Fingerprint strengthening makes upstream selector non-idempotence catastrophic.** Adding realized regime knobs (`gen_batch`, `share_prefill_armed`) to the resume fingerprint is CORRECT (mixing regimes in one store is the bug it fixes) — but it converts any RE-MEASURED upstream selector into a mass-invalidation hazard. #2389: `dispatch.sh all` re-runs the three-regime pilot unconditionally on the plan's PRE-REGISTERED "relaunch reuses the same command" TIMEOUT continuation; a noise/HBM-headroom-edge flip of argmin(B∈{16,32}) rewrites the report → new regime_fp → every banked anchors/grid done shard quarantined + regenerated (tens of GPU-h; the plan's "lossless boundary" property silently broken). **Check:** for each measured value newly entering a resume fp, trace the planned resume path and confirm the value is READ BACK from a persisted artifact, never re-measured (skip-if-report-exists guard); flag any selector whose eligibility rides a hardware-noise threshold (HBM headroom floor) as flip-prone.

2. **Freeze/adopt caching must re-apply the gate it caches.** `_resolve_share_prefill`'s first-writer freeze file was adopted raw (`rec["armed"]`) without re-running the B6 `mode == "production"` guard; a --tiny smoke run (which legitimately accepts a tiny PASS) freezes `armed=true` into the SAME default out_root the production dispatch reuses → production arms on CPU-tiny evidence — the exact ARMED-on-weak-evidence direction the freeze design was supposed to exclude. **Check:** any "first resolver writes, later resolvers adopt" seam — confirm the adopt branch either re-applies every conditional guard of the write branch or the freeze is keyed/refused on the guard inputs (tiny/smoke/mode bits), mirroring the pilot-report's own smoke/tiny mismatch refusal.

3. **Adopt-time validation must not bind to re-measured raw bytes (#2389 r4 — the fix for pattern 2 introduced this).** The r3 fix bound the family freeze to `sha256(raw gate-artifact bytes)`; the gate-4b battery driver (like the pre-R5 pilot) re-measures + rewrites its artifact with a fresh `ts` on the plan's pre-registered same-command resume ⇒ every armed freeze fails validation ⇒ disarm ⇒ the fp knob (`share_prefill_armed`) flips ⇒ banked shards mass-quarantine — the SAME hazard pattern 1 describes, re-entering through the validator instead of the selector. Also non-deterministic when the rewrite lands mid-window between two participants' resolves (split-fingerprint store). **Check:** for every adopt-time digest/validity binding, ask (a) does the bound artifact's producer re-run on the planned resume (needs the skip-if-matching-report idiom), and (b) is the digest over raw bytes (ts/repro fields guarantee drift) or a canonical content subset (verdict/mode/pass-bits, sort_keys)? Also grep the round's tests for one that PINS the over-disarm as desired — it must be corrected, not extended.

**Resolution (#2389 r5, verified):** the converged fix is BOTH halves at once — (a) a canonical DECISION digest over exactly the fields the resolver reads (`{verdict, mode}`, sort_keys; regime lives in the freeze's own repro check, so it need not be digested), and (b) producer idempotence via the skip-if-matching-report idiom (`_adoptable_gate_report`: same mode + recognized verdict + regime ⇒ adopt, NO rewrite; `--force` re-measures). Either half alone closes the benign-rewrite channel; together a `--force` same-verdict rerun is also inert. Verify the old test PINNING the over-disarm was CORRECTED (renamed to `..._survives_benign_gate_rewrite`) with the disarm-on-decision-change + vanished-evidence directions retained as separate tests. Residuals to note, not block: a verdict-FLIPPING `--force` mid-window can still split one family's arming across participants (genuine evidence change — disarm is the safe direction), and the artifact's own repro stays outside the digest (cross-model same-decision overwrite keeps freezes armed; excluded by per-model out_roots + the producer's regime-checked adoption).

**r5-final convergence (#2389, verified PASS):** the class ended when guards moved INSIDE the single accessor / single decision reader (chokepoint), so every consumer inherits — verify the chokepoint by grepping the artifact's path literal (writer's own path + upload name-sets are fine; a second content READER is the recurrence). Evidence-strength-aware adoption is resume-safe when strength checks are strict-`<` refusals (equality = same-command resume adopts; stronger adopts) and shape checks (batch, protocol, runtime) are exact-equality — but ONLY if the dispatcher threads identical flags to every consumer leg: check dispatch.sh flag threading (`--num-workers` on every leg, no leg passing the wall flag ⇒ shared parser default), not just the predicate direction. Foreign ⇒ RAISE (halt) beats foreign ⇒ silent re-measure: a halt cannot flip the fp and quarantine banked shards. git pin WARN-only + torch/transformers hard is the right split (hard git re-couples every crash-fix resume to a re-measure).
