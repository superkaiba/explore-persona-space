Two design traps in minimal-pair patching banks (found in the #2162 v2 plan review, 2026-08-07; parent rig #2094):

1. **Same-type shuffled-donor null must constrain donor VALUE, not donor pair id.** A derangement "constrained to a different value-pair" still hands the recipient a donor whose B-side carries the SAME semantic value whenever (a) the type is binary and its 3 value-pairs are phrasings of one A/B contrast (donor B == recipient B always), or (b) a 3-value type's pairs share a B value under lexicographic direction ((v1,v3) vs (v2,v3) both have B=v3 — 2 of 3 recipients have one contaminated donor option). A value-sharing donor makes the "null" a paraphrase of the steered arm → F_null ≈ F_steered → IUT/false-negative "not carried" verdicts exactly where transfer exists. The parent #2094 avoided this implicitly (its `donor_derangement` constrained matched-query donors cross-prefix-pair, guaranteeing content difference) — the constraint's PURPOSE is content difference; port that purpose, not the mechanism.
   **Why:** the confirmatory test is steered-vs-null; a treatment-content-bearing null can never separate. **How to apply:** on any plan with a same-type donor null, check per type whether every legal donor differs from the recipient in the varied VALUE; binary-contrast types need either genuinely distinct value sets, a re-registered single-null (cross-type-only) IUT, or a directional A-side donor with changed semantics stated.

   **Validated fix shape (accepted in revision):** give every type k ≥ 3 genuinely DISTINCT values on a REGISTERED value cycle (v1→v2→v3→v1) so every value is the B side equally often — the value-constrained derangement (donor-B-value ≠ recipient-B-value) is then a balanced cycle shift, always satisfiable; ordinal value sets (graded strictness, capability tiers) are acceptable as long as adjacent values produce categorically distinct behaviors (adjacency only ELEVATES the null → conservative for positives; ask for a per-donor-value null breakout where sets are ordinal). Cross-type donor arms additionally need a matched-content ROUTE-FAMILY exclusion (a demo_format(bullets) donor into an instr_format(bullets) recipient carries the target value under a different route) + the value assert wherever types share a value vocabulary.

   **Superseding fix shape for ASYMMETRIC value sets (#2162 `persona-specificity-ladder` round, 2026-08-12):** when the value set is asymmetric (e.g. an empty/default arm + extreme registers — plain vs pirate vs butler), even a value-constrained derangement fails: the different-value donor CARRIES a construct (Round A measured the pirate-donor "null" at netted F 0.479 &gt; steered 0.299, 100% via the anti-source channel — it annihilates plain-ness). The validated replacement: (a) SAME-VALUE donor null (recipient's own value from a different carrier — construct-free by construction in both install and erase directions, still prices slot-replacement disruption at matched norm); (b) construct-SCREENED cross-type donor (each realized donor's ceiling-anchor text judged on the recipient direction's target descriptor, qualifies iff ≤ a bar placed well above measured clean-donor scores); (c) a REGISTERED null-sanity hypothesis with a verdict-withheld consequence (no null mean may exceed a pre-set bar in any install direction; breach ⇒ "transfers" verdicts withheld). Also switch the primary F to the TARGET descriptor only — a netted Δ = judge_B − judge_A metric rewards any donor for destroying the source register (the anti-source inflation vector).

2. **Uniform carrier splits underpower retrievable-item / conditional-policy types.** An anchor-separation exclusion (|ceiling−floor| ≥ bar, per pair) interacts with carrier content: fact/list/boundary types only separate on carriers that ENGAGE the varied information (direct probes, boundary-engaging queries); neutral carriers give ceiling ≈ floor ≈ 0 and get excluded. With a uniform 3-direct + 9-neutral split, the best-case survivor count for such types (3 value-pairs × 3 direct carriers = 9) can sit BELOW the pre-registered survival floor (≥12) and the exact signed-rank attainability floor (n ≥ 11 at Holm-corrected α) — the registered test is unreachable by arithmetic, so "raise pairs-per-cell" fixes nothing if the added pairs are neutral-carrier pairs.
   **Why:** the power remedy has to add SEPARABLE pairs, and separability is type × carrier-content dependent. **How to apply:** check max-possible-survivors ≥ the registered floor per type-class under the plan's own separation model; demand per-type carrier allocation (majority engaging carriers for item/conditional types), not a global raise. Validated fix: per-type-CLASS allocation (class-E = all-engaging carriers, crossed cells inherit the base type's class), with the accepted costs recorded — cross-type-donor matched-carrier preference falls back to a seeded unmatched draw (donor ids per row keep it recountable), and the type-class × carrier-class confound runs in the CONSERVATIVE direction for an items-don't-transfer prediction (items get their best-case carriers).

3. **Value-slot labeling drifts on "body exemplars = v1/v2, additions = v3" claims.** When a plan extends user-settled A/B exemplars to 3-value sets and flags "each v3 is a planner addition", diff EVERY row against the body: on ordinal sets the planner's addition tends to land in the MIDDLE slot (v2) with the body's second exemplar pushed to v3, and body rows that already name 3 values can get one silently swapped. Mechanically harmless under a full cycle (all unordered pairs still realized), but the user-visibility flag then points reviewers at the wrong column.
   **Why:** found on an ordinal-strictness + verbosity set — 3 of 21 rows contradicted the plan's own labeling sentence. **How to apply:** spot-check the value table against the body roster whenever the plan claims per-slot verbatim inheritance; flag as a record-accuracy concern (non-blocking) unless a body-named CONTRAST vanishes from the realized pair set.
