name: Preview-informed "pre-registration" in zero-GPU re-analyses
description: When a re-analysis plan previews headline numbers in §2 then "pre-registers" verdict logic in §7, the framing is narrative not validity — audit which cells the regime-windowing excludes and whether exclusions track the preview's inconvenient cells
type: feedback
---

For a zero-GPU re-analysis of committed data, the planner often computes the
headline contrasts during planning (§2 preview) and then writes "pre-registered"
verdict logic in §7. That logic was written knowing the outcome, so it carries
no confirmatory-pre-registration validity — it is honest disclosure plus frozen
classification code, nothing more.

**Why:** #611 (2026-06-11): the §7 margin-space verdict was defined over
"install-onward steps {30,60,120}" with s18 demoted to a "reported alongside"
bracket — and the one preview cell cutting AGAINST the headline's wrong-persona
half (villain s18 margin d = −0.23, CI-clear NEGATIVE) lived exactly at s18.
The sub-install rationale (own emit = 0.000 at s18) was principled, so this was
NOT a REVISE, but the windowing and the inconvenient cell coincided.

**How to apply:**
1. Don't bounce a plan for previewing — disclosure in §2 + frozen logic + raw
   per-cell artifacts is the right shape for re-analyses.
2. DO map each verdict window/exclusion onto the previewed table and ask: does
   any excluded cell point against the expected headline? If yes, add a
   Concern instructing the analyzer to report that cell as a finding (not a
   bracket footnote) and to narrate §7 as "frozen post-preview classification,"
   never as confirmatory pre-registration.
3. Check the windowing has an independent regime justification (band/emit
   accounting) — if the only rationale is that the cell disagrees, that IS
   post-hoc tailoring and a Must-Fix.
