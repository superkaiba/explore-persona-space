For a zero-GPU re-analysis of committed data, the planner often computes the headline contrasts during planning (§2 preview) then writes "pre-registered" verdict logic in §7. That logic was written knowing the outcome — honest disclosure plus frozen classification code, NOT confirmatory pre-registration.

**Why (#611):** the §7 margin-space verdict was defined over "install-onward steps {30,60,120}" with s18 demoted to a "reported alongside" bracket — and the one preview cell cutting AGAINST the headline (villain s18 margin d = −0.23, CI-clear negative) lived exactly at s18. The sub-install rationale (own emit = 0.000 at s18) was principled, so NOT a REVISE — but the windowing and the inconvenient cell coincided.

**How to apply:** (1) don't bounce a plan for previewing — disclosure + frozen logic + raw per-cell artifacts is the right shape for re-analyses; (2) DO map each verdict window/exclusion onto the previewed table: does any excluded cell point against the expected headline? If yes, Concern instructing the analyzer to report that cell as a finding and narrate §7 as "frozen post-preview classification"; (3) check the windowing has an independent regime justification — if the only rationale is that the cell disagrees, that IS post-hoc tailoring and a Must-Fix.
