Reviewing a plan that LOOSENS a deletion-gating comparator (`_husk_unique_content`-class subset verifiers; #2138):

1. **Trace the predicate against the REAL incident artifact, not an idealized shape.** #2051's live `plans/plan.md` was a 5-byte REGULAR file containing the target STRING `v1.md` (a materialized pointer), not the plan body — so the "simplest" uniform fix (resolve both sides, compare content) FAILS on its own motivating incident (37,829 resolved bytes vs 5). The winning arm was target-path-exists-in-live (pointer-carries-no-data), with the walk independently verifying the target file. Verify with `git ls-tree` (mode 120000) + `xxd` on the live file — takes 2 min and grounds the whole predicate choice.
2. **Per-entry leniency cannot over-delete alone when reap requires the WHOLE-artifact unique list empty** — a pointer deemed safe whose in-husk target diverges from live makes the TARGET entry unique, so the husk escalates anyway. Check that backstop exists before litigating per-entry edge cases; then walk each fixture arm's expected verdict through the pseudocode (T3-style "symlink safe but target unique" asserts are where bugs hide).
3. **The incident's COST channel is usually orthogonal to the deletion predicate.** #2051's damage was a stalled infra drain: `_infra_drain_occupancy` → `task.py list-by-status` is a FOLDER SCAN (`task_workflow.list_by_status` iterates `tasks/<status>/`) with no registry cross-check, so ANY husk at an occupied status eats a dispatch slot (and a husk beside a live occupied-status dir double-counts). A comparator fix only closes the stall for reapable husks; a genuinely-unique ESCALATED husk still stalls until human triage. Ask whether the plan names that residual; the occupancy-side fix (skip rows whose REGISTRY path ≠ scanned dir) is complementary, not a substitute — the comparator fix is still the root-cause locus because it removes the husk for every consumer (`ls tasks/<status>` fleet reads, dashboards, occupancy).
4. **Why the residual is narrow here (reusable fact):** infra/batch tasks complete WITHOUT body rewrite (no clean-result promotion), and events.jsonl passes byte-prefix/jsonl-subsequence — so for the class that occupies infra slots, the symlink arm was the ONLY blocker to automatic reap. Experiment-task husks (promoted bodies → body.md diverges) still escalate, but they never count toward the infra cap (INFRA_DRAIN_KINDS filter).
5. **Producer-side fix ("never materialize the symlink") is inferior when the producer is unidentified/git-mediated** and existing live dirs already carry the shape — it needs a state-mutating normalization sweep and fixes only one orientation; the comparator sits downstream of all producers.
6. **Round-2 closure check for a demanded lenient-route soundness arm (#2138 v2):** verify the fixture makes the NEW lenient route the SOLE safe route for the pointer entry (live counterpart must be a NON-symlink so the old readlink route cannot fire, and the pointer bytes must fail the content-coverage route's `live.startswith(husk)` rule), the target divergence is genuine under the actual coverage rules (equal-length one-byte diff defeats startswith; non-`.jsonl` suffix disables the subsequence arm), and the assertion is an exact unique-list so the false-SAFE (skip-the-target) implementation returns `[]` and fails. Demand the non-suppression semantic in prose AND mirrored into the pseudocode. Empirical (verified py 3.11.15): `Path.resolve(strict=True)` raises RuntimeError on symlink loops (OSError-unified only in 3.13); `is_file()` screens loops (ELOOP in pathlib's ignored errnos) — so `except (OSError, RuntimeError)` routing to UNIQUE is a fail-safe widening that can never mint a covered verdict.
