For single-variable flag A/Bs that retrain one arm and reuse the parent's other arm (#613: negative-loss placement flag vs #601's flag-off arm):

1. **Approvable shape = four elements:** (a) full a–g reuse fitness check with an explicit apply-and-read parity assert (re-read the reused arm's terminal, bounded vs committed numbers — #613 used 0.5 nat); (b) a frozen comparison band derived from the PARENT's seed gap, never recomputed with the new arm; (c) a step-1 manipulation check on the newly-live channel with smoke-named telemetry (WandB series + JSON channel presence); (d) registered branches for co-land / suppression / amplification AND "live but toothless" so every outcome is reportable. With these, residual confounds (cross-time generation drift on committed on-policy numbers, EOS-boosting shifting own-generation endpoints) are weighable from four-float diagnostics.
2. **"Live but toothless" vs "lever irrelevant" is the built-in null fork when the flag relocates a loss term.** The relocated gradient's restoring force scales with the leaked target mass at the loss slot, so "flag live but had nothing to push against at this leakage/lr dose" and "placement is not the lever" produce identical terminal reads (#613: #471's restoring force appeared at 9–15 nats trained-neg leakage vs #601's ~5–6; gradient ∝ P(※)|slot ≈ e⁻¹⁶). NOT a REVISE when the plan registers (a) the in-loop loss-channel CE trajectory (liveness + growth) and (b) four-float slot reads at the LOSS slot on both arms — the analyzer can then scope the null to "insufficient under this recipe's leakage regime". Also: a wide co-landing band (±5.58 nats from parent seed gaps) is insensitive to real moderate suppression — demand descriptive sub-band directional reporting + the sensitive secondary channel (trained-negative clamp/trajectory). Generalizes to any A/B whose variable is WHERE a loss term acts: ask whether the restoring gradient's magnitude depends on a state variable that differs between the conflicting parent rigs.
3. **Stale code-comment slot trap:** the #474 collator comment claims the negative loss slot is the "SAME slot the DV reads", but row construction (`R+"\n\n"+" ※"` positives vs bare `R` negatives) puts them one separator apart — a plan trusting the comment instead of measuring both slots (sep-plain + sep-marker reads) loses the mechanism interpretation on a null. Also: registry seed tuples can be stale (dense_200p800n carries `seeds=(137,)`; seed-42 came from a `--seed` override) — locate reused arms by explicit HF/JSON paths, never the registry tuple.
