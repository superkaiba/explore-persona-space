For masked-loss ablation plans (input-side conditioning vs production-side gradient experiments), the alternatives lens needs these nudges:

1. **Enumerate the fresh-prompt alternatives explicitly in the prompt.** For round 2, listing labeled sub-questions (A) through (G) caused Codex to address each systematically and produce blocking issues on underpowered mediation and garbage-null confounds that would otherwise be SR-only.

2. **Call out the mediation analysis sample-size / evidentiary standard explicitly.** Codex caught that "p > 0.05 on persona-voiced rate" is not evidence of absence (underpowered at n=50 per source for binary proportions). Worth asking "is the test adequately powered?" as an explicit sub-question in any plan that uses mediation to rule out an alternative.

3. **Point Codex to the sequence-length confound specifically.** For label-masking designs: #280 ruled out sequence length for FULL-rationale-loss arms, not for answer-only-gradient-through-long-masked-prefix arms. Codex correctly elevated this to a Must Fix when the specific reference was included.

4. **Ask about generalizability of conditional gates.** The C3 gate on librarian-only was flagged as SR1 because librarian is the highest-signal source. Include "does the gate generalize?" as an explicit sub-question for any conditional supplementary cell.

5. **Avoid embedding multiline heredoc Python in the prompt** — if you need Codex to verify numbers, let it run its own grep/find/python3 commands rather than embedding complex code snippets in the prompt body. This round Codex ran its own python3 code to verify #186 bystander macros independently.

6. **For geometric/leakage designs: always include the training-budget asymmetry sub-question.** Issue #311 round 2: plan had joint LoRA at 200 examples per source vs single-source LoRAs at 400 per source. Codex elevated this to Must Fix (BLOCKER 3). Always ask "does per-source exposure match across LoRA variants?" explicitly when an additive decomposition is the headline test.

7. **For Stouffer-combination designs: always ask the per-pair direction-consistency sub-question.** Issue #311: no direction-consistency requirement meant one strong pair could carry the combined p. Codex made this BLOCKER 1. Include "does H1 PASS require both pairs to show the predicted sign?" explicitly.

8. **Ask about independence baseline ceiling effects for rate residuals.** The additive r_p = rate_A + rate_B - rate_joint boundary is a subtle BLOCKER Codex catches when prompted about "impossible rate" scenarios. Include an explicit sub-question about this whenever the plan subtracts per-source rates.

9. **For TOST-mediation designs: include explicit sub-questions for (i) what happens when the arm under test produces MORE of the predicted signal (not less), and (ii) whether the comparison arm is template-matched.** Issue #344 round 3: Codex caught that the plan's TOST decision tree only handled the labels_on_answer LESS-persona-voiced branch, leaving the MORE-persona-voiced case unrouted. Also caught that no_cot is a #186 carry-over under a different template, biasing the mediation comparison. Both became Must Fix BLOCKERs.

10. **For ratio-of-loss-delta statistics: always ask about denominator interpretability gates.** Issue #344 round 3: r5 = ratio of paired LOSS-DELTAS can be uninterpretable (CI from 0.1 to 2.5) when the EMPTY-scaffold denominator is near zero. Add "is the denominator non-trivially nonzero?" as an explicit sub-question whenever a plan reports a ratio where the denominator is an effect size (not a count).

**Why:** Issue #344 plan critique, round 2 (mediation/label-masking design) + Issue #311 round 2 (geometric leakage / Stouffer design) + Issue #344 round 3 (TOST direction completeness + template-matching confound in mediation + r5 denominator power). Sub-question enumeration was the key driver of blocking verdicts in all rounds.

11. **For EOS-masking / run-on-text designs: always include a position gate sub-question.** Issue #354 round 1: Codex elevated "position-of-B is diagnostic only, not a pre-registered gate" to Must Fix (BLOCKER 1). The key nudge was: "if B fires at position 500/600, is the interpretation still chunk-binding?" Include an explicit sub-question asking whether the plan's position metrics are PRE-REGISTERED gates vs post-hoc diagnostics, and whether the confirmation threshold is set above the length-adjusted null.

12. **For single-variable ablations vs a prior run: always ask for a same-run EOS-unmasked arm.** Issue #354 round 1: Codex flagged "missing T-EOS-unmasked baseline" as BLOCKER 6. Without it, any positive jump from #281 is confounded by environment/code/cache-regen drift. Always include "should there be an EOS-unmasked arm in the same run?" as an explicit sub-question when the plan compares a new run to a prior result.

13. **For bystander-leak designs: ask whether the bystander check is a falsification gate, not just diagnostic.** Issue #354: Codex elevated "bystander check should be discriminative" to SR. The key insight is that if the untrained bystander has equal-or-higher near-A B rate than the trained recipient, the SWE result cannot be called chunk-binding. Frame as "if bystander >= SWE, do NOT call it chunk-binding."

**Why:** Issue #344 plan critique, round 2 (mediation/label-masking design) + Issue #311 round 2 (geometric leakage / Stouffer design) + Issue #344 round 3 (TOST direction completeness + template-matching confound in mediation + r5 denominator power) + Issue #354 round 1 (EOS-masking run-on-text artifact, same-run baseline gap, bystander gate). Sub-question enumeration was the key driver of blocking verdicts in all rounds.

14. **For bystander-gate designs: ask whether the bystander cell selection is pre-specified and non-draggable.** Issue #354 round 2: Codex elevated ">=3 untrained-persona cells, one unspecified" to BLOCKER A. A mean over cherry-picked low-leak cells makes the gate trivially passable. Always include a sub-question asking "is the exact bystander set pre-named, or can the implementer/analyzer pick the easier cells?"

15. **For position-gate designs: ask whether the char-distance threshold is calibrated relative to completion length.** Issue #354 round 2: Codex elevated "150 chars absolute may pass short-completion suffix habits" to BLOCKER B. A model that always appends B at char 120 in 200-char completions passes a 150-char absolute gate regardless of mechanism. Include a relative-position sub-question (B_pos_after_A / completion_len) alongside any absolute-char threshold.

16. **For env-parity gates with a near-zero baseline: ask whether the tolerance is tight enough to isolate the variable.** Issue #354 round 2: Codex elevated "±10pp around 1.3% baseline allows 0-11.3%, which is wider than the confirmation threshold" to BLOCKER C. When the baseline rate is low (<<10%), an absolute-pp tolerance is mechanism-blind. Ask "is the env-parity tolerance small enough to distinguish variable-change effect from cache-regen drift?"

17. **For sequential multi-adapter vLLM evals: always ask whether the engine is flushed between adapters.** Issue #354 round 2: Codex elevated "vLLM warm-cache contamination between T→C→T_unmasked" to BLOCKER D. KV-cache and prompt-cache from a T-eval can persist into C-eval within the same process. Include "is a fresh engine process or explicit flush confirmed between adapter swaps?" as a blocking sub-question in any plan that evaluates 2+ adapters sequentially.

18. **For loose-substring designs: ask whether B can appear multiple times in a completion and whether extra occurrences are gated.** Issue #354 round 2: Codex elevated "multiple B occurrences in longer completions — position gate fires on the first near-A hit but the behavior is general pollution" to BLOCKER E. Include a sub-question about `pct_multiple_B` and whether confirmation requires B to appear exactly once.

19. **For EOS-mask interventions with contrastive negatives in training: ask whether contrastive-negative personas also show the same T-vs-C elevation.** Issue #354 round 2: Codex elevated "LoRA-global stop-signal suppression could elevate ALL trained personas, not just recipient" to BLOCKER F. Include a sub-question about whether the contrastive-negative eval cells are used as a rejection gate, not just the never-trained bystanders.

20. **For single-pair confirmation: always ask whether the plan pre-registers pair-specificity as a caveat.** Issue #354 round 2: Codex elevated "librarian→SWE is one pair; confirmation language 'chunk-binding is real' overclaims" to BLOCKER G. Include "does the plan pre-register that confirmation applies only to this pair?" as a sub-question whenever a single donor-recipient pair is the only test case.

21. **For position gates with low n_positions minimum: ask whether 3 events is enough for CONFIRMATION (not just Inconclusive).** Issue #354 round 2: Codex elevated "n_positions=3 with pct=100% gives a very wide Wilson CI and weak position evidence" to BLOCKER H. Include "what is the minimum n_positions for Confirmed vs Inconclusive?" as an explicit sub-question.

**Why:** Issue #354 round 2 produced 8 Must Fix findings from sub-questions A-H, all addressing second-order weaknesses in gates that were pre-registered in v3 but under-specified (bystander selection, position calibration, env-parity tolerance, vLLM flush, B-multiplicity, contrastive-negative bleed, pair-specificity overclaim, n_positions minimum). This confirms the pattern: once round-1 BLOCKERs are resolved into gates, round-2 must scrutinize gate specificity and selection-game-ability.

22. **For predictor-race / leakage-matrix designs (race a predictor zoo against a trained-vs-base outcome matrix): the alternatives sub-question set is different from ablation designs.** Issue #545 round 1: the load-bearing sub-questions were (a) implant-strength confound — does a predictor win by tracking how strongly rows train rather than which behaviors move; ask whether realized strength is partialled out of scoring, not just recorded as metadata; (b) any-SFT floor row — designed nulls (domain-specific or token-masked) are NOT a generic random-benign-SFT baseline; check whether a prior issue's D0/random adapters are reusable at zero GPU; (c) best-of-group max-selection bias — "best of group X beats best of group Y by margin m" compares maxima over different group sizes; ask whether the margin's null accounts for group size and whether bootstrap CIs cluster at the family level; (d) shared-content confound symmetric to the plan's own Group-A critique — if the plan dismisses geometry predictors as trivial-feature detectors, ask whether the favored group's win could be the same topical-overlap artifact; (e) level-track quasi-tautology — base-prior predicting level = base + delta partly predicts itself; (f) corpus-contamination parity — if one row family gets a content-contamination audit, every NEW synthetic corpus with a predicted-positive cell needs the same audit (the audit's absence is fatal-by-construction, unrecoverable post-hoc).

23. **For seed-descope amendment deltas (user-directed cut to 1 seed with estimators re-based on question-level noise): use this sub-question set.** Issue #537 v6 round 4: (A) training-noise-as-structure — can the analyzer BOUND adapter draw noise from reported diagnostics (cross-row replication, proximity gradient, question floors), and is it fatal at any kill/sign-flip gate (note: adapter noise moves whole G rows coherently, not i.i.d. across eval columns — point that out explicitly); (B) estimator-swap floor underestimation — split-half-over-questions assumes independent question draws; shared prefix/judge biases correlate halves, making the 2× kill too easy, and the floor omits training noise BY CONSTRUCTION; (C) asymmetry-from-draw-noise — A[i,j] mixes both adapters' draws, question splits can't remove it; ask whether the cross-half covariance can go negative / fraction outside [0,1] at 1 seed; (D) cheap zero-GPU noise bounds — checkpoint-pair / epoch-adjacent snapshots as a within-run draw-noise floor, and PRIOR multi-seed artifacts (#474) as an external cross-seed calibration at zero GPU; (E) dismissal sentence; (F) cross-boundary — single-seed target noise flattening the registered leaderboard's ΔR² differences (the harness's whole point). Also instruct Codex NOT to demand seeds back (user override) — only to judge whether the question-level replacements honestly bound what seed-split bounded.

24. **For null-calibration designs (re-run a parent's measurement at a no-signal point to bound its null), probe alternatives in BOTH outcome directions with separate sub-question families.** Issue #555 round 1 (pre-implant null-geometry calibration, parent #534): on a NULL verdict ask (i) seed-covariation — anything real-but-conditioned-on-the-parent's-specific-seeds survives "it was chance"; (ii) rig-drift — without a parent-seed anchor replicate run through the NEW rig, a flat null is confounded by pipeline drift (pool-builder path swap, hard-stop vs snapshot read). On a SYSTEMATIC verdict ask (iii) replicate non-independence — when every replicate shares the identical design matrix/probe set and only the DV noise varies, a shared deterministic DV component f(arm, probe) correlates the per-replicate ρ and makes the small-df t-interval anti-conservative; (iv) mechanism routing — "noise organizes along geometry" vs "deterministic arm-level property masquerading as geometry when the arm panel was CHOSEN by distance" (different corrections: global baseline subtraction vs per-arm); (v) zero-GPU permuted-DV null — ask explicitly whether the plan includes a shuffled-DV refit diagnostic and whether its absence is analyzer-recoverable (pure post-hoc analysis over committed rows).

25. **For slot-localization arm-contrast designs (paired d_seed between two encoding arms, all eval encodings trained, scope-mandated DV identity): use this sub-question set.** Issue #464 minimal_content_cn amendment round 1: (A) surface-cue asymmetry present in only ONE arm (pad-parity tokens whose COUNT differs between positive and negative rows — an extra discriminative cue the other arm lacks; check whether a prior padded-vs-plain contrast bounds it); (B) implant-strength asymmetry — paired d_seed cancels seed/probe-shape but NOT arm-level implant strength; the H1 saturation-ceiling check can't resolve strength, so ask whether the own-encoding non-saturating EOS margin is captured per arm; (C) floor-censoring asymmetry in BOTH directions (one arm censored → spurious positive; both at floor → spurious falsifier) and whether log-prob-vs-logit disagreement routing is explicit; (D) trained-suppression-vs-passive-localization — when every eval encoding is a trained positive/negative there is NO untrained bystander; ask whether any claim depends on an untouched-context read; (E) attribution leak in the falsifier — content matching changes the NEGATIVE rows' encodings too, so "edge vanished ⇒ parent edge was content" has a regime-interaction alternative; (F) retroactive upgrade of a hedged parent result via the shared summary figure (DR-gated "suggestive" parent cell sitting next to a clean new cell).

26. **For measurement-regime re-read follow-ups (re-evaluate earlier/lighter checkpoints of the SAME training runs to test whether a prior inversion/null was a measurement artifact, e.g. softmax compression):** the load-bearing sub-questions are (a) DOSE-vs-ARTIFACT over-attribution — the lighter checkpoint differs in total training dose, not only ceiling proximity, so "the prior inversion was compression" needs the prior round's stored non-saturating (logit-space) re-read as the disambiguator; ask whether the plan COMMITS to that zero-GPU re-read or whether the headline sentence must be scoped down to what the new cells alone support; (b) cross-round non-independence — same training draw feeds both rounds' x-axes, so forbid "replicated" framing; (c) post-hoc sign prediction + a third reporting route ("regime-limited") making any outcome narratable — check the informativeness rule is fixed pre-data and analyzer-recomputable; (d) anchor-pick circularity — did the checkpoint-selection gate ever see the y-axis or the panel cells; (e) retroactive-upgrade via the cross-round comparison figure (same as item 25-F). First used: #480 followup-3 inband-logprob-concordance (2026-06-10).

27. **For retrospective audit designs (zero-GPU verdict-table audits of historical runs, e.g. cache-collision / wrong-artifact hunts):** the alternatives target the VERDICT CLASSES, not a treatment effect. Load-bearing sub-questions: (a) reconstruction validity — any verdict resting on a replayed request/event sequence reconstructed from resume-skip/restart state needs an adversarial-orderings bound (git drops mtimes; a point reconstruction can show safety where a feasible ordering had exposure); (b) "first-loaded" claims must account for EVERYTHING sharing the process/engine before the audited phase (e.g. a Phase 0 sharing the engine); (c) confirmatory empirical tests (string-identity under greedy decoding) are biased in BOTH directions — saturation/templated outputs give false-positives, batching nondeterminism gives false-negatives — ask for a calibration pair from the known-affected parent run; (d) probabilistic-SAFE classes — ask for realized-N enumerability, detection power of the sanity checks, and whether the env pinned the hash seed (upgradable to deterministic); (e) enumeration completeness — literal-string dragnets miss aliased imports / wrapper helpers / other dirs / uncommitted pod-side scripts; headline must scope to "audited drivers"; (f) headline falsifiability — with no kill criterion, require INDETERMINATEs enumerated in the headline rather than absorbed into "nothing affected". Also tell Codex the INDETERMINATE routing is a legitimate RECOVERABLE landing zone, and that re-run demands are out of scope when the audit is proposal-only. First used: #549 round 1 (2026-06-10).

28. **For two-arm differential-erasure designs on a checkpoint-picked organism (clean-form install + aligned-vs-misaligned continued SFT):** the load-bearing sub-questions are (A) gradient-magnitude vs content — ask FIRST whether off-policy-distance-driven update magnitude is a confound or part of the construct given the Goal wording (a drift detector may not care WHY the EM arm erases more); note per-arm absorption ΔCE on each arm's OWN corpus is not a common-scale training-pressure read — suggest a common held-out slice if the mechanism claim needs it; (B) max-emission checkpoint pick = winner's curse over a small probe (n=32) — trace whether the independent full-eval (n=200) denominator absorbs the selection bias, and watch the tie-break-later-step rule dragging picks spam-ward; (C) a "no clean regime" (K1-style) negative confounded with probe resolution — form fractions computed over ~8-10 emitters at the eligibility floor + ladder granularity; ask whether the headline must be scoped to "not resolvable at this probe size/granularity"; (D) form-dose coupling — on a single ramp, clean form ⟺ earlier ⟺ weaker install, so an H1 negative conflates "clean form fragile" with "weaker dose dies"; latent 4-float reads vs the parent's anchors are the analyzer's lever, no same-strength control exists; (E) capability/instruction-following collapse mediating the differential (truncation/length patterns masquerading as erasure; ARC-C logprob may not see generation-side degradation); (F) single-seed fan-out gate → mixed eligible/fallback seed pooling. Also: for plans touching EM corpora, include a CONTENT QUARANTINE block (no corpus .jsonl / raw_completions / parent-task body reads; numeric-only jq from eval JSONs) to dodge usage-policy refusals mid-critique. First used: #570 round 1 (2026-06-10).

29a. **For training-mode-vs-content 2x2 completion follow-ups (new contrastive arms vs executed plain arms + a marker reference):** the load-bearing sub-questions are (A) BUNDLE attribution — "training mode" = system prompts on rows + negative rows + push-pull structure; ask whether every pre-registered headline sentence is scoped to the bundle or attributes to the contrast per se (no positives-only-under-prompt cell exists; demand a rewording/scope-down, not a new arm); (B) exposure parity ≠ optimizer-trajectory parity (doubled steps, different LR-decay shape); (C) gradient-touched panel rows — stress whether the held-out-subpanel control has its own decision anchor or is purely descriptive; (D) contrast-not-delivered — near-on-policy negatives carry ~zero CE gradient, which hits the "both stay concentrated" branch hardest (can't distinguish "contrast doesn't matter" from "contrast wasn't administered"); minimal fix = per-row-type CE diagnostic or scope-down of that branch's attribution sentence; (E) reference-zone threshold transfer from a differently-scaled marker arm; (F) asymmetric-outcome alternatives — implant-strength asymmetry AND the noise-dominated low-magnitude cell (row-shuffle/sign-flip nulls do NOT test ‖M‖ vs measurement noise — ask for a magnitude-floor read); (G) trained-in containment (a negative-persona context's low leak is the design working, not generic containment evidence); (H) cross-boundary parent-headline rewrite mapping. First used: #552 contrastive-2x2-completion round 1 (2026-06-10).

30. **For infra-port plans (cherry-pick/apply a fix + regression test + opt-in guard to main): the alternatives lens targets CLAIMED-PROTECTION HOLLOWNESS, not treatment effects.** Reframe "predicted positive result" as "claimed protection" and ask, per protection, the simplest world where the merge lands green but the protection is hollow: (A) Goal-scope vs delivered — Goal promises class-wide protection, deliverable fixes one driver + an opt-in guard + a one-function AST test; have Codex identify the parent audit's OTHER affected rows and grep repo-wide for sibling construction sites a reader would assume covered; (B) static-test evasion modes — helper indirection, attribute-call (`ast.Attribute` func invisible to an `ast.Name` checker — ask whether the anti-rot `>=1` test fails loud or also goes blind), variable-bound constant, new sites in other functions/files; (C) "behavioral net" = an opt-in guard nothing on main arms (two-layer story with a dormant layer two); (D) per-call `enumerate(start=1)` id reuse across repeated calls in one process/engine — check the actual call topology (engine constructed inside the function moots it); (E) acceptance criteria that are all source-shape assertions (greps/AST/import smokes) with zero behavioral checks — verify the ported guard tests actually exercise the guard function. Tell Codex re-run demands for affected HISTORICAL results are out of scope when the plan routes them to follow-ups, and that bounded residuals the plan itself states default to Concern. First used: #584 round 1 (2026-06-10).

31. **For infra ESTIMATOR/DISPLAY plans (progress bars, ETAs, dashboards — any feature whose output is a number a user trusts):** reframe "predicted positive result" as "displayed output a user would trust and act on"; Must Fix = silent-wrong-output with NO guard (degrade rule / staleness check / basis tag), unsatisfiable acceptance criteria, or concrete technical failure. Load-bearing sub-questions: (A) materialized-snapshot vs request-time computation — flag the indirection only if it creates silent-wrong classes (stale status, clamp masking, dead cron) the simpler design lacks, or the plan's rejection rationale misstates the codebase; (B) staleness asymmetry across surfaces — a guarded dashboard + an unguarded frozen title (dead session keeps a confident countdown) is the classic miss; (C) backward/blocked transition edges (re-plan double-traversal, blocked-before-any-machine-stage); (D) population-mismatch pricing — minority kind falls back to majority-dominated stats with no basis tag while another estimate path DOES get a basis tag (asymmetry is the tell); (E) cross-surface consistency — same task showing different numbers on title vs kanban vs sessions page; FATAL only on flat contradiction; (F) stuck-task optimism — frac caps + max(q−elapsed,0) make the WORST tasks look closest to done with the narrowest bands; ask for an overdue state; (G) quantile-sum band coverage under correlated stages (kill criteria often check width, never coverage). Also: simplicity alone is NEVER Must Fix; defer-listed follow-ups and must-ask scope are out of bounds. First used: #587 round 1 (2026-06-10).

32. **For infra LANE-CAPABILITY plans (add a new workload/route capability to the compute router, proven by a minimal live smoke):** reframe "predicted positive result" as "claimed capability"; per acceptance criterion ask the simplest world where the check passes but the capability is hollow. Load-bearing sub-questions: (A) trivial-smoke vs motivating-workload-class gap — only NAMED class properties the DESIGN can't support and that fail SILENTLY count (e.g. >max-run-duration external VM kill: does the trap/poller surface it; false-PASS trace: backgrounded work + clean exit reaching the sentinel/confirm_artifacts); (B) indifference-claims-beyond-grep — a one-grep assumption ("route() never introspects X") gets an independent search over intent/extra/lease/probe/sidecar consumers + the hash-key parity question (same key, changed underlying content = today's semantics or new stale-reconnect class?); (C) never-live-tested lane shipped as "support" while the routing doc change lets real work land there — split wording-level scope-shrinkage (RECOVERABLE) from a silent failure class on the now-reachable path (FATAL); read the body's deliverable wording to see if live evidence was demanded; (D) dominating simpler mechanism — Must Fix only if the plan's rejection rationale misstates the codebase AND the chosen path adds a silent-failure class; (E) structural spend/billing arguments — name the attachment-drift story (account swapped since precedent; config-drift project pinning) and check whether the launch argv pins the project from a constant; (F) snapshot-control circularity — pre-change byte-identity snapshot recorded by the same implementer right before the diff (vacuous if recorded post-change; ask for a post-hoc-verifiable recording procedure); (G) new fail-loud raise breaking unexamined non-test callers (production render calls outside the launch path). Also: live-smoke-on-the-other-lane demands are out of bounds when the plan documents the residual, unless silent. First used: #588 round 1 (2026-06-10).

33. **For two-arm DYNAMICS comparisons where one arm reuses a parent's checkpoint ladder and the other trains fresh under a matched recipe (e.g. positive-only vs contrastive trajectories):** the load-bearing sub-questions are (A) exposure parity ≠ optimizer-trajectory parity — at matched cumulative examples the arms sit at different warmup/cosine positions and different Adam-update counts per example; ask whether the dual-axis (matched-dose + raw-step) sandwich is analyzer-sufficient or an lr-weighted dose axis / post-warmup restriction is needed; (B) claim/artifact coincidence — when the hypothesized mechanism IS "one shared unconditional shift", ask what distinguishes probe-visible mass bleed from behavioral expression, and whether on-policy anchors cover the held-out panel (here 4/25 contexts anchored); (C) targeted suppression vs generic slot-sharpening — does the confirmation criterion build in the trained-negative-minus-held-out contrast or only read held-out "descriptively"; (D) matched-dose interpolation/batch-composition expectation error inside the early install window; (E) onset-checkpoint granularity asymmetry across arms (4-step vs 20-step grids read panels at different effective implant strengths); (F) lockstep-ratio softmax compression — is the ratio's space (log-prob vs logit) pinned, can the source already be logZ-compressed at its onset checkpoint (check the parent trajectories); (G) sources-as-replicates sharing one question set + panel + seed (panel-level idiosyncrasy moves all sources coherently); (H) reused-arm provenance asymmetries (shuffle realization over different dataset lengths under the same seed, env drift) vs what the parity asserts + probe-row identity check actually pin. Out-of-bounds additions: don't relitigate the documented teacher-forced within-condition exception itself — only its cross-arm boundary. First used: #597 round 1 (2026-06-11).

34. **For estimator-validity bake-offs (kind: analysis; score base-model "read" estimators against realized trained-minus-base "write" directions on stored adapters):** the load-bearing sub-questions are (A) generic prompt-contrast attractor vs FAMILY-SPECIFIC topical overlap — does the cross-behavior off-diagonal null hide a single topically-confounded pair inside the off-diagonal MEAN (check whether two families share content, e.g. a medical-persona source vs a bad-medical-advice family); (H) behavioral-panel context-intersection size (Spearman over a silently tiny overlap). 35. **For ratio/count/schedule deconfound designs (a schedule-matched arm built via epochs_override to match a bigger-build arm's horizon):** the load-bearing sub-questions are (A) repeated-epoch revisits vs within-epoch duplication — is "same mix, different schedule" true at the gradient level; check the BUILDER for distinct-row counts per build (a rig that duplicates a small distinct pool makes the premise hold; one that scales distinct content breaks it) + per-epoch reshuffle semantics; (B) data-exhaustion mimic of the equilibrium branch — if positive-row CE ~0 within epoch 1, extra epochs deliver no gradient and the schedule-matched arm co-lands with the small arm for non-ratio reasons; check parent JSONs for arrest at/near warmup end (lr near peak) to pre-refute tail-imposed arrest, then judge headline wording only; (D) arrest-step tracks rows-seen vs schedule fraction — at fixed eff batch, constant absolute arrest step ≡ constant rows-seen, a capacity story landing in the same observable cell as equilibrium (the identical-data quarter-vs-schedule-matched pair can't split them either); ask whether the no-call branch can carry "ratio-or-capacity, unresolved"; (E) reused cross-task anchor inside a spread kill criterion — the eval-path re-read bounds eval drift, not retrain drift; look for a fresh same-recipe cell (dense re-run) the analyzer can use as the replication point; (F) slot-level z-movement positives (negatives-only control) vs generic SFT drift — does any committed contrast (bystander slots, noneg cell) bound ~1-logit generic drift in THAT phase's own corpus; (G) two-variable bridge arms with one UNCONFIRMED parameter (rank from an ideas doc) — check whether the kill sentence overcommits given the named residuals.
