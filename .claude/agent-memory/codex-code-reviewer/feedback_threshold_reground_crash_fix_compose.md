When a micro crash-fix round's fix is RE-GROUNDING a plan-pinned gate
threshold (#2564 k100 r4: `K100_VC_PARITY_COS_MIN` 0.9999 -> 0.999 after
the pod smoke tripped the parity gate on measured bf16 batch-composition
jitter; plan §-assumption "deterministic forward" falsified), four compose
deltas beyond the standard crash-fix shape (own impl marker + v89 dispatch
record + v90 diagnosis/decision note in separate envelopes):

1. **Composer-run threshold-site grep table, adjudication theirs.** Grep
   the PINNED post-fix blobs for the constant name AND the old literal;
   list every hit with line numbers in the facts block, pre-classify
   nothing — the brief's residual-literal taxonomy (separate sibling bar /
   comment history / deliberately-different test monkeypatch) becomes
   focus item 1's classification duty. Watch substring hits: `0.9999`
   matches inside a `0.999999` monkeypatch — name it so the twin doesn't
   misread it as a stale-bar assertion.
2. **Declared-supersession Step-6 frame.** Enumerate EVERY plan site
   pinning the old value (here three: §4 phase row, §7 fence, §12
   assumption-mitigation row) and state the supersession is DECLARED in
   the decision note + marker (a) with crash evidence + calibration
   grounding — adjudicate scoping/recording/justification, never
   auto-flag "plan says X, code says Y". Add the verdict-header enum
   `DEVIATES (declared)` | `DEVIATES (undeclared)` so the header can
   record it without reading as drift.
3. **Premise-change fence on a reachability demotion.** When the prior
   reconciler demoted the twin's own Critical on "no such artifact exists /
   can exist" and the CRASH then CREATED the artifact (a stale FAIL report
   now sits on the reused pod out-root), do not let the twin either
   relitigate or ignore it: state the premise change explicitly, then
   route it — "the demotion's core mechanism is exactly what THIS diff
   must demonstrate" (here: the bar is a HASHED fp input, so the value
   change auto-invalidates the stale report, plus the independent
   verdict=fail refusal — two defenses to trace). A genuine hole = a
   substantive finding under a FRESH id, never a severity re-raise by
   relitigation.
4. **ARMED-by-touch on the successor concern.** The demotion's successor
   CONCERN (fp-schema-version) is armed because the diff edits the fp's
   docstring and changes a hashed VALUE: three-way adjudication
   (ADDRESSED / ARMED-BUT-DECLINED-on-merits given the micro dispatch
   scope / RE-INSTANTIATED), capped at recorded severity, status-line-only
   (latest=raised). The on-merits question is precise: does VALUE-keyed
   invalidation alone cover THIS transition, and can any artifact with a
   matching NEW fp lack the new report key?

Also compose the brief's two-sided bar-sanity question verbatim as its own
focus item ("name any realistic failure class landing in [new-bar,
old-bar) that now passes silently — an honest 'none' is a valid answer"),
with the retained science-grade instruments named as backstops, and the
disclosed n-small margin extrapolation fenced at CONCERNS (marker (d)
discloses it).

**Why:** the twin authored the demoted Critical (author-neutrality both
ways), the plan literally contradicts the code (auto-drift-FAIL trap), and
the threshold-site sweep is cheap for the composer but expensive and
error-prone mid-review.

**How to apply:** any crash-fix whose fix is a gate bar/threshold change
superseding a plan-pinned value, especially when the threshold is hashed
into a resume fingerprint. Related: [[gate-leg-demotion-crash-fix-compose]]
(the leg-REMOVAL sibling), [[k0-code-delta-round-compose]] (same task's
K0/K1 fences), [[concern-discharge-round-severity-fence]] (the
reconciler-downgrade fences).
