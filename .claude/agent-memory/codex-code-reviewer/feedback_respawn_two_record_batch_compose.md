From #2336 r5 (plan v4 batch 2, 2026-08-24) — a 34-file dormant-script
migration round whose implementing session stalled after committing and was
watcher-respawned:

1. **Two-record verification split.** The PREDECESSOR's commit message
   recorded the FULL verification (mapped 129 chunked green except named
   pre-existing reds + one isolated-flaky; repo-wide pin-sweep over all
   tests/ files with hit count; ruff-policy pin passed) while the
   SUCCESSOR's `epm:results` (b) DEFERRED the mapped set to the landing
   gate and reported only its own re-run subset. Compose both records as an
   attested fact + a dedicated duty with the pre-fence: the marker
   UNDER-claims rather than over-claims, so the split is at most a
   CONCERNS-grade report-completeness observation unless a specific
   commit-message claim is FALSE or the deferral leaves a named untested
   risk. Attest the session-continuity story (claim-roster match, watcher
   stop, respawn) so the twin never reads the split as deception.
2. **Strip the reuse-span split-review paragraph at EVERY reuse**, not just
   on whole-round briefs: the surviving r3/r4 #2336 spans CARRY the Step-0
   "Split-review sub-scope briefs (#2074)" paragraph, so a fresh compose
   that reuses them leaks the literal trigger token. Strip from the bold
   heading to the `\n\n| Tier |` table anchor; assert token-absent + tier
   table count 1.
3. **Composer runs an omitted (c) gate himself when cheap.** The v5 marker
   omitted the ruff-policy pin line entirely (roster member
   workflow_lint.py touched). Running `pytest tests/test_ruff_policy.py`
   (2 passed, ~1s) converts a would-be blocker-shaped ambiguity into an
   attested fact: pin GREEN + (c)-omission pre-triaged present-but-imperfect
   (at most Minor), explicitly NOT the #1672 shape.
4. **Identical both-trees bare-ruff counts prove pre-existing red.** On a
   dormant-issue-script batch, bare `ruff check <34 files>` is deeply red
   (2848) — running the SAME command at the repo root on main and getting
   the IDENTICAL count attests delta≈0 in one line, defusing both "ruff
   red = round defect" and the commit message's "ruff clean" wording
   (accurate only under a delta reading; report-accuracy nit at most).
5. **Batch-range concern instructions ARM on batch rounds.** An open
   concern whose summary says "Batches 2-5: grep tests/ repo-wide" composes
   as an ARMED adjudication duty on every batch-2-5 round: paired rows
   (Claude CONCERN + Codex NIT = one finding) get ONE adjudication + two
   status lines + zero re-emitted rows; a diff hunk that PARTIALLY
   discharges another open concern (the +4 R-rel pin vs
   preferred-form-normpath-rationale-false's unpinned-relative-branch
   residual) gets its own partial-discharge status-line duty.

session / verification re-run by this respawned session", any compose
reusing a stored rubric span, and any batch-N round on a task with
