## Experiment Report Structure

Clean-result write-ups follow the **four-flat-H2 (v4) markdown clean-result spec** (forward-only): four required H2 sections in order — **Takeaways / Goal / Methodology / Results** — plus a bold `**Repro:**` / `**Context:**` footer (NOT an H2), with NO v3 `## What I ran` / `## Findings` / `## Data` / `## Reproducibility` H2 and no retired `## Human TL;DR` / `## TL;DR` / `## Details` / `## Figure` (any of those is a hard FAIL in a v4 body). v4 bodies carry the `<!-- clean-result-v4 -->` sentinel right after the H1 title; **confidence lives in the H1 title tag ONLY**. `## Takeaways` = 3–6 numbers-first bullets, plain academic register, rewritten after every follow-up round. `## Goal` = `**This experiment in context:**` (the ONLY place prior-issue links appear) + `**Broader narrative:**`. `## Methodology` = the complete "everything required to understand the results" section — `**Design:**` / `**Training:**` (COMPLETE hyperparameter table, every value from ground truth + a Source column) / `**Evaluation:**` / `**Data extraction:**` / `**Sample training/evaluation data + completions:**` (verbatim worked examples, subset-disclosed + linked). `## Results` = one `### <result>` H3 per result in the strict three-beat **what-is-plotted-EXACTLY → plot (one inline figure + blockquote caption) → interpretation**, REQUIRING both a summary-metric plot AND the low-level per-unit data plot (points labeled) for any aggregate result. The footer carries compute + code SHA + pinned artifact links + run-provenance incl. the verbatim originating prompt (SPEC.md § footer, checks 16/17). **Conciseness is mechanical** — `verify_task_body.py` check 20 enforces the caps; drafts must PASS `verify_task_body.py` before posting (FAILs block; WARNs ship only when acknowledged in body). **Forward-only:** v3/v2/pre-sentinel bodies keep their prior shape verbatim and are NEVER newly hard-FAILed by a v4 rule (exception: a follow-up round folding onto a v3/v2 body migrates it to v4, SPEC.md § Follow-up consolidation).

**Paper format (opt-in via `paper: true` frontmatter) — separate track.** A `paper: true` task does NOT use a markdown clean-result body: its canonical clean-result is a self-contained LaTeX **research paper** (`.tex` → reproducible PDF + sanitized committed `paper.html`) under `docs/papers/issue_<N>/`, and `body.md` becomes a thin **paper-stub** (H1 + abstract + paper link + the frontmatter existing readers consume). Required sections: Abstract / Introduction / Methods / Results / Discussion+Limitations / References / Appendix; **NO confidence anywhere in the paper body** (title-tag only, in the stub — `verify_paper.py` hard-FAILs it in the `.tex`); cross-experiment references use `\epsref{N}`, never a bare `#N`. Build: `scripts/build_paper.py`; the mechanical gate is **`scripts/verify_paper.py`** (NOT `verify_task_body.py`). The `analyzer` (PAPER-TASK MODE) assembles the `.tex`, splices the `methodology-writer`'s findings-blind Methods + Appendix, runs build → verify, and writes the stub ONLY after verify PASSes. **Deterministic branch + kill-switch: absent/false ⇒ the markdown v4 path, unchanged (the DEFAULT); grandfathered bodies are never converted.** Opt in by editing the task's `body.md` frontmatter directly (no `task.py new --paper` flag; `--body-file` does NOT merge frontmatter). Full spec: SPEC.md § "Paper format (`paper: true`)"; wiring: SKILL.md Steps 8 / 9a-bis / 9a-quater.

**Ad-hoc results summaries state per-arm provenance in their setup line.** Any summary of experiment results or model generations shown to the user OUTSIDE a clean-result body — a chat summary, an interim figure, a mid-run report — states, per arm, the data/completion provenance (on-policy vs teacher-forced vs canned/templated vs third-party-LLM-written) and the generation recipe (sampling params + rollout count) in its setup line / caption; unverified or artifact-inherited provenance is flagged, never guessed (#1139, #825). **Verify before asserting:** a specific number, a head-to-head winner, or a never-run/missing-cell claim in chat is checked against the underlying artifact first — grep/`jq` the `eval_results/` JSON (plus sibling issues' artifacts for coverage claims) — naming which artifact (and, for winners, which fit/eval regime) the number comes from. A never-run claim additionally scans LIVE compute before asserting — running pods (`pod.py list-ephemeral`), live GCE instances (`gcloud compute instances list --configuration=eps-gcp`; `gcloud` is `/snap/bin`, LOGIN-shell PATH only, and a non-zero rc is UNKNOWN never empty — `.claude/rules/gotchas.md`), and recent `epm:run-launched` / `epm:followup-scope` / `epm:free-analysis-followup-run` markers on parked/terminal tasks (the same follow-up signal set the watcher's pod-safety pass reads) — a status-folder scan alone looks idle while a parked-task inline pod round signals only pod-side (#1345: a status-folder scan backed a "nothing live is generating that cell" claim while such a round had generated ~2,000 stories). **Absence claims require a relocation sweep:** an absence / not-persisted claim shipped in chat or ANY durable marker is grounded by a repo-wide grep PLUS a SCOPED listing of the HF prefix's siblings/parents (`list_repo_tree(path_in_repo=<parent prefix>)`), never a single-location check. Never re-cite a task body's numbers or reason from a plan as if it were the measurement (#1090, #825, #779). **Compose-time re-grep (not only on challenge):** any numeric range/headline composed into a writeup, saved summary, mentor draft, RESULTS.md entry, or figure-adjacent prose is re-read from the underlying artifact in the same turn, and a quoted range traces to ONE quantity in ONE artifact read, never two metrics fused into one interval (#823/#952). **Staleness check before quoting any `eval_results/` summary:** `git log -1 -- <path>` + a same-directory scan for a newer sibling/version before re-citing (#1310). **Display-substitution disclosure:** whenever text shown as a model generation differs from the stored raw completion — a rename, redaction, or truncation, presentation-time or upstream — the substitution is disclosed inline, per passage, wherever the text is presented, dashboards and HTML artifacts included; an undisclosed substitution reads as the model's own words (#1345: 'ARIA'→'Assistant' silently substituted in text presented as model generations). **Matched-target disclosure for cross-arm tables:** any cross-arm table or head-to-head states in its setup line that every arm is scored against the SAME target/corpus — or names the mismatch; arms scored against different targets are not a comparison (#1092: a chat table compared arms scored against DIFFERENT targets). **Similarity-statistic semantics:** any operator/map similarity statistic quoted in chat states whether it is direction-aware (raw / Procrustes-aligned operator cosine) or spectrum/rotation-invariant-only (can never support "same operator up to rotation"), and names the precedent battery it matches — the `scripts/issue1345_operator_comparison.py` conventions — or states none exists (#1310: a 0.98–1.00 spectrum cosine narrated as near-identical operators). **Superlative/coverage-extremum sweep:** a superlative claim ("largest n ever tested", "first/only") is grounded by a cross-issue SWEEP of `eval_results/` + sibling summaries, never a single-artifact re-read (#779). **Banked-compute check for chat-authored plan/theory docs:** a chat-authored plan doc labeling a stage "new compute" first runs the banked-artifact search (`.claude/rules/artifact-reuse.md` § Chat-authored plan docs) and cites what is banked.

**Interim/chat writeup presentation register (same surface as the provenance rules above; the clean-result SPEC governs promoted bodies only):** (1) **Plots over tables** — any cross-condition comparison renders as a figure, not a markdown table (`.claude/skills/paper-plots/SKILL.md` §3.9); tables only for exact-value lookup the user asked for. (2) **Novel results lead** — lead with what is NEW since the last writeup; already-reported material appears only as labeled context, never re-presented as a finding. (3) **Plain-English gloss per compressed claim** — every technique term or compressed statistical claim gets a one-clause gloss saying what it means and rules out; a claim that cannot be glossed accurately is over-compressed — decompress before shipping. (4) **One color = one meaning** across every figure in a writeup — the "Color↔meaning consistency" row in `.claude/skills/paper-plots/SKILL.md` §2 governs. (5) **Counts define their unit + counting rule in the same sentence**; a quantity question is answered in the ASKED unit first. (6) **A discard/abandon directive's ack LEADS with the sunk-vs-remaining compute split** — informational only, never a push-back instruction. (7) **Chat-only analysis folds into its doc in the SAME turn** — or the completion note states the explicit deferral (who folds it, when). (8) **Mapping-line writeups run the glossary retired-terms check** (`docs/glossary_context_answer_map.md` § "Retired / ambiguous terms" — e.g. qualify "prefix vector $v_P$ (query-averaged)" vs "prefix-end state"). (#1658; (5)-(7): #1809; (8): #1921.)

**Spend-authorization phrasing is a directive, not a delegation:** a user reply of "you can do X" / "go ahead with X" after a cost or scope quote AUTHORIZES running X — it does not delegate re-adjudicating whether X is worth it. When the reading is genuinely ambiguous, launch it or ask a one-line confirm — never a silent decline, and never a decline written into a durable marker (session 0ac15c23).
