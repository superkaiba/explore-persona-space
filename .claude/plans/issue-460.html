Plan — Issue #460

Re-measure #406's transfer outcome as a continuous marker log-prob instead of the binary emission rate, to (a) fix the 52% zero-inflation that flattened the divergence-vs-transfer correlation and (b) test whether divergence predicts graded transfer strength, not just the on/off threshold the emission rate showed.

0.0 TL;DR (plain English)

  • What I'll run: I'm reopening last week's experiment that asked "if I teach a model to add a special symbol in one persona, will it carry the habit over to another persona — and can I predict that from the model's behavior before any training?" The first pass scored each transfer as a yes/no flip: does the model write the symbol, or not. On more than half the 240 persona pairs that yes/no came back "no," and that wall of zeros hid most of the variation I cared about. This time I keep all 16 already-trained models and ask a softer question of each pair: not "did the symbol appear," but "how willing is the model to write it." Same data, same conditions, finer-grained outcome. No retraining, no new persona work — just a different measurement on the existing model copies.
  • What I expect: A cleaner version of the same story. The correlation between the predictor I locked in (how much two contexts disagree in the base model) and the new graded outcome should be at least as strong as the old yes/no version, and probably noticeably stronger in the half of pairs where the yes/no was stuck at zero. The middle-of-the-network similarity measure (the surprise hero last time) should still beat my locked-in predictor, but with a tighter gap.
  • What would change my mind: If the graded measurement gives the same correlation as the yes/no version, then last week's relationship really is about the firing threshold and not about graded strength — interesting but a narrower claim. If the graded measurement gives a weaker correlation, the original signal was about whether the model crosses the emission line at all, and a continuous willingness is the wrong DV. Either of those would meaningfully reframe what #406 actually showed.

Full plan (sections 1–12)

1. Goal

Re-measure the outcome DV of #406's 240-pair divergence-predicts-transfer experiment as a continuous teacher-forced log-prob of the marker token at the first response-token position, replacing the binary "does ` ※` appear as the first sampled token" emission rate. The motivating problem: 125 of #406's 240 off-diagonal cells (52.1%) returned emission rate exactly zero, compressing the bottom half of the DV to a single floor value and almost certainly throttling the rank correlation with the divergence predictor D. A continuous DV lets two cells whose model is "barely won't emit" vs "categorically won't emit" separate. The headline finding becomes one of three things: (a) the same ρ (the underlying relationship really is on/off and the zero-inflation didn't matter), (b) a stronger ρ (zero-inflation was hiding graded variance, the divergence-transfer relationship is graded too), or (c) a weaker ρ (the original signal was about crossing an emission threshold and graded log-prob is the wrong construct). Resolving this directly informs whether #406's "MODERATE confidence" claim is on a binary-only phenomenon or a graded one — a precondition for any downstream geometry-predicts-behavior paper claim built on this rig.

3. Hypothesis

H1 (headline, falsifiable): Length-partial Spearman ρ(G_logprob, D | log_prompt_tokens) over 240 off-diagonal pairs has absolute value ≥ 0.45 — at minimum matching #406's |ρ_KL| = 0.436 on the binary DV. Direction: negative (higher base-model divergence → lower marker log-prob, same direction as #406).

H2 (zero-inflation rescue, the experiment's reason for being): Restrict the analysis to the 125 cells where #406's emission rate was exactly 0; on this restricted set, length-partial Spearman ρ(G_logprob, D | log_prompt_tokens) has absolute value ≥ 0.20 (qualitatively non-null). This is the direct test that the continuous DV separates cells the binary DV collapsed to a single floor. If H2 PASSes, the divergence-transfer relationship is GRADED (the model's "willingness to emit" varies with divergence even when actual emission never happens). If H2 FAILs (ρ near 0 on the zero-cohort), the cells that don't fire all look the same to log-prob too, and #406's relationship is genuinely about crossing an on/off threshold.

H3 (layer-11 cosine retains ranking): Layer-11 residual-stream cosine still beats forward-KL on the continuous DV with |ρ| ≥ 0.65 (vs −0.709 on the binary DV). A drop below 0.50 would suggest the layer-11 advantage was specific to the binary-emission geometry.

H4 (within-run rig sanity — mandatory gate): The free within-run recomputation of binary emission rate (argmax at the same teacher-forced position) reproduces G_matrix.json to within 0.02 absolute on every one of the 256 cells. If H4 FAILs we are reading the wrong slot or the wrong adapter; the analysis is void and the run is treated as epm:failure v1, failure_class: code, reason: rig_does_not_reproduce_parent_binary.

4.2 The core measurement (nail this — adversarial-grade)

Per cell (i, j):

for q in Q_test (50 questions):
    prompt_text = build_prompt_for_condition(cond_j, q, tokenizer, class_d_rewrites=...)
    prompt_ids  = tokenizer.encode(prompt_text, add_special_tokens=False)
    full_ids    = prompt_ids + [MARKER_ID]   # MARKER_ID = 83399, single token id ' ※'
    # vLLM batched call below — see §4.4 for the actual API shape; this pseudocode shows
    # the per-prompt logic so the position semantics are unambiguous.
    out = llm.generate(prompts=[full_text], sampling_params=sp, lora_request=lora_req)
    # SamplingParams(max_tokens=1, prompt_logprobs=1, logprobs=1, temperature=0.0)
    logp_marker_at_pos = out.prompt_logprobs[len(prompt_ids)][MARKER_ID].logprob
G_logprob[i, j] = mean over q of logp_marker_at_pos        # mean log-prob, primary
G_prob[i, j]    = log(mean over q of exp(logp_marker_at_pos))  # log of mean prob, free secondary

Why this is correct (position semantics):

  • prompt_ids has length L; the appended marker token sits at index L in full_ids.
  • vLLM's prompt_logprobs[k] returns the log-prob of full_ids[k] given full_ids[:k]. So prompt_logprobs[L] is exactly log P(MARKER_ID | prompt_ids) — what we want.
  • This is the same teacher-forced position that #406's i406_phase3_cross_eval.py thresholded on. The greedy first_token_ids[0] in the emission rig is argmax over v of log P(v | prompt_ids) at exactly the same slot. So our continuous DV and the binary DV ARE measuring the same conditional distribution — the only difference is binary-threshold (emission rate) vs raw value (log-prob).
  • vLLM's prompt_logprobs[0] is None by API contract (no preceding context for the first token); index 0 is the BOS-equivalent. We never read index 0.

MANDATORY off-by-one guard (executed in Phase 1 smoke and Phase 2 sweep, fails LOUD):

# Diagonal cells (i == j): for each Q_test where #406 emission rate was 1
# (so the model is known to argmax → 83399 at this slot), confirm:
#   argmax_v prompt_logprobs[len(prompt_ids)][v] == MARKER_ID
# This proves we are reading the same slot the emission rate thresholded on.
# At least 1 diagonal cell × 1 high-G probe must pass before the sweep starts.
assert argmax_token_id_at_pos == MARKER_ID, (
    f"Off-by-one or wrong-position read: argmax at L={len(prompt_ids)} is "
    f"{argmax_token_id_at_pos} but #406 emission says 83399. Refusing to proceed."
)

Aggregation choice (pre-registered, NOT post-hoc selectable):

  • Primary: mean of log-probs over the 50 Q_test probes per cell — symmetric in log-space, the same shape #406 used for D (K=25-mean log-prob averaging). Reports as G_logprob[i, j].
  • Free secondary: log of mean prob over the 50 probes — gives more weight to rare high-prob probes. Reports as G_prob[i, j]. The analyzer reports both ρ values; pre-registering primary so the analyzer doesn't pick whichever number is bigger.
  • Numerical floor: logp = max(logp, -50.0) on read (defensive — vLLM emits real log-probs ~−20 nats, but adapter swaps occasionally underflow). If > 1% of cells get clamped, post epm:failure v1, failure_class: data, reason: log_prob_underflow_widespread.

For each (T_i, T_j, q in Q_test): one vLLM forward over prompt + appended ' ※'
token; read prompt_logprobs[L][83399] where L = len(prompt_ids). Per-cell JSON
captures BOTH the continuous DV (G_logprob = mean log-prob over 50 probes,
primary) AND the binary recomputed DV (emission_recompute = mean over 50 of
[argmax_v prompt_logprobs[L][v] == 83399], H4 rig sanity).

Reuses i406_conditions: build_prompt_for_condition, CONDITIONS, MARKER_ID,
MARKER_TEXT verbatim. NO RETRAINING.

CLI:
  uv run python scripts/i460_logprob_eval.py --cids A1                 # smoke
  uv run python scripts/i460_logprob_eval.py                            # full sweep
  uv run python scripts/i460_logprob_eval.py --resume                   # idempotent re-run
"""

from __future__ import annotations
import argparse, json, logging, math, time
from pathlib import Path
import numpy as np
from transformers import AutoTokenizer
from explore_persona_space.experiments.i406_conditions import (
    CONDITIONS, CONDITIONS_BY_ID, MARKER_ID, MARKER_TEXT, build_prompt_for_condition,
)

logger = logging.getLogger("i460.eval")

BASE_MODEL = "Qwen/Qwen2.5-7B-Instruct"
HF_REPO   = "superkaiba1/explore-persona-space"
LOCAL_ADAPTER_CACHE = Path("/workspace/adapters/i406")   # SAME cache as #406
OUT_DIR   = Path("eval_results/issue_460/logprob_eval")
PER_CELL_DIR = OUT_DIR / "per_cell"
LOGP_FLOOR = -50.0

def _load_q_test() -> list[str]:
    path = Path("data/issue_406/q_test_extended_50.json")
    if not path.exists():
        raise FileNotFoundError(
            f"Q_test not at {path}. #406 Phase 0 must have run on this branch / HF data sync."
        )
    payload = json.loads(path.read_text())
    qs = payload["questions"]
    if len(qs) != 50:
        raise AssertionError(f"Expected 50 Q_test, got {len(qs)}")
    return qs

def _load_class_d_rewrites() -> dict[str, dict[str, str]]:
    path = Path("data/issue_406/class_d/rewrites_v1.json")
    if not path.exists():
        raise FileNotFoundError(f"Class D rewrites not at {path}.")
    return json.loads(path.read_text())

def _download_adapters(cids: list[str]) -> dict[str, str]:
    from huggingface_hub import snapshot_download
    LOCAL_ADAPTER_CACHE.mkdir(parents=True, exist_ok=True)
    out: dict[str, str] = {}
    for cid in cids:
        target = f"adapters/i406_{cid}"
        local = LOCAL_ADAPTER_CACHE / target
        if not (local / "adapter_model.safetensors").exists():
            snapshot_download(repo_id=HF_REPO, revision="main",
                              allow_patterns=[f"{target}/*"],
                              local_dir=LOCAL_ADAPTER_CACHE)
        if not (local / "adapter_model.safetensors").exists():
            raise RuntimeError(
                f"adapter_model.safetensors missing at {local} even after snapshot_download. "
                "Adapter not uploaded by #406, or snapshot_download truncated siblings list."
            )
        out[cid] = str(local)
    return out

def _per_cell_path(ci: str, cj: str) -> Path:
    return PER_CELL_DIR / f"Glogprob_{ci}__{cj}.json"

def main(argv: list[str] | None = None) -> None:
    logging.basicConfig(level=logging.INFO,
        format="%(asctime)s %(name)s [%(levelname)s] %(message)s",
        datefmt="%Y-%m-%dT%H:%M:%S")
    ap = argparse.ArgumentParser()
    ap.add_argument("--cids", default=None,
        help="Comma-sep outer-i list; default = all 16. Smoke = '--cids A1'.")
    ap.add_argument("--resume", action="store_true",
        help="Skip (i, j) cells whose per_cell JSON already exists and is non-empty.")
    args = ap.parse_args(argv)

    from explore_persona_space.orchestrate.env import load_dotenv
    load_dotenv()

    OUT_DIR.mkdir(parents=True, exist_ok=True)
    PER_CELL_DIR.mkdir(parents=True, exist_ok=True)

    # CLAUDE.md marker assert (single token id 83399 for ' ※' on Qwen-2.5-7B).
    tokenizer = AutoTokenizer.from_pretrained(BASE_MODEL, trust_remote_code=True)
    ids = tokenizer.encode(MARKER_TEXT, add_special_tokens=False)
    if ids != [MARKER_ID]:
        raise AssertionError(f"Marker token id drift: encode({MARKER_TEXT!r}) = {ids}; refusing launch.")

    q_test = _load_q_test()
    class_d_rewrites = _load_class_d_rewrites()
    all_cids = [c.cid for c in CONDITIONS]
    my_cids = all_cids if args.cids is None else args.cids.split(",")
    for cid in my_cids:
        if cid not in CONDITIONS_BY_ID:
            raise ValueError(f"--cids carries unknown id {cid!r}")
    logger.info("Outer-i set (N=%d): %s", len(my_cids), my_cids)

    # Pre-download my adapters before vLLM lifts the GPU.
    adapter_paths = _download_adapters(my_cids)

    # Late import (heavy).
    from vllm import LLM, SamplingParams
    from vllm.lora.request import LoRARequest

    llm = LLM(
        model=BASE_MODEL,
        enable_lora=True,
        max_lora_rank=32,
        max_loras=1,
        dtype="bfloat16",
        gpu_memory_utilization=0.85,
        seed=42,
    )
    # prompt_logprobs=1 → vLLM returns the top-1 log-prob at every prompt position
    # AS WELL AS the actual-token log-prob at every position. We read the
    # actual-token logp at the appended-marker position. max_tokens=1 minimizes
    # generation overhead; we never look at the generated token.
    sp = SamplingParams(
        max_tokens=1,
        temperature=0.0,
        top_p=1.0,
        prompt_logprobs=1,
        logprobs=1,
        seed=42,
    )

    # Load published G to enable H4 sanity per-cell comparison.
    published_G = json.loads(Path("eval_results/issue_406/cross_eval/G_matrix.json").read_text())["G"]

    for outer_i, cid_i in enumerate(my_cids):
        lora_req = LoRARequest(
            lora_name=cid_i,
            lora_int_id=all_cids.index(cid_i) + 1,
            lora_path=adapter_paths[cid_i],
        )
        for cid_j in all_cids:
            cell_path = _per_cell_path(cid_i, cid_j)
            if args.resume and cell_path.exists() and cell_path.stat().st_size > 0:
                logger.info("RESUME skip (%s, %s)", cid_i, cid_j)
                continue
            cond_j = CONDITIONS_BY_ID[cid_j]
            prompts_text: list[str] = []
            prompt_lens: list[int] = []
            for q in q_test:
                pt = build_prompt_for_condition(cond_j, q, tokenizer, class_d_rewrites=class_d_rewrites)
                pids = tokenizer.encode(pt, add_special_tokens=False)
                # Append the marker token by token-id (NOT by decode-then-encode round trip
                # — vLLM accepts prompt_token_ids directly, sidestepping BPE re-segmentation
                # exactly as #406 Phase 1 fixed via MF-1).
                prompts_text.append({"prompt_token_ids": pids + [MARKER_ID]})
                prompt_lens.append(len(pids))
            t0 = time.time()
            outputs = llm.generate(prompts_text, sp, lora_request=lora_req)
            if len(outputs) != len(prompts_text):
                raise RuntimeError(f"vLLM returned {len(outputs)} for {len(prompts_text)} on ({cid_i}, {cid_j})")

            logps_marker: list[float] = []
            argmax_eq_marker: list[bool] = []
            argmax_token_ids: list[int] = []
            for out, L in zip(outputs, prompt_lens, strict=True):
                # out.prompt_logprobs is List[Optional[dict[token_id, Logprob]]] of length len(full_ids).
                # Index L is the position where the appended-marker token sits.
                slot = out.prompt_logprobs[L]
                if slot is None:
                    raise RuntimeError(
                        f"prompt_logprobs[{L}] is None on ({cid_i},{cid_j}); vLLM API shape changed."
                    )
                # The actual-token log-prob at this slot is keyed by MARKER_ID
                # (when prompt_logprobs >= 1, vLLM always includes the actual token's logprob).
                marker_lp_obj = slot.get(MARKER_ID)
                if marker_lp_obj is None:
                    # If the marker isn't in the top-1, vLLM still returns the actual-token entry.
                    # If it's truly absent here, that's an API contract violation.
                    raise RuntimeError(
                        f"MARKER_ID {MARKER_ID} not in prompt_logprobs[{L}] on ({cid_i},{cid_j}); "
                        f"slot keys: {list(slot.keys())[:5]}..."
                    )
                lp = max(float(marker_lp_obj.logprob), LOGP_FLOOR)
                logps_marker.append(lp)
                # argmax over top-1: when prompt_logprobs=1, slot has 1 or 2 entries
                # (the top-1 token + the actual token if different). Pick the token with the highest logprob.
                top = max(slot.items(), key=lambda kv: kv[1].logprob)
                argmax_token_ids.append(top[0])
                argmax_eq_marker.append(top[0] == MARKER_ID)

            mean_logp     = float(np.mean(logps_marker))
            log_mean_prob = float(math.log(np.mean(np.exp(np.array(logps_marker))) + 1e-300))
            emission_recompute_rate = float(np.mean(argmax_eq_marker))
            published_rate = published_G[cid_i][cid_j]["rate"]
            emission_drift = abs(emission_recompute_rate - published_rate)

            cell_payload = {
                "T_i": cid_i,
                "T_j": cid_j,
                "n_probes": len(q_test),
                "mean_logp_marker": mean_logp,                          # PRIMARY DV
                "log_mean_prob_marker": log_mean_prob,                  # secondary aggregation
                "emission_recompute_rate": emission_recompute_rate,    # H4 rig sanity
                "published_emission_rate": published_rate,
                "emission_drift_abs": emission_drift,                   # must be <= 0.02
                "per_probe_logp_marker": logps_marker,                  # for downstream re-aggregation
                "per_probe_argmax_token_id": argmax_token_ids,
                "n_clamped_to_floor": int(sum(1 for lp in logps_marker if lp <= LOGP_FLOOR + 1e-6)),
            }
            # H4 hard gate — refuse to write a cell whose binary recompute drifts >0.05 from #406.
            # (Soft gate at 0.02 reported in the JSON; hard refuse at 0.05.)
            if emission_drift > 0.05:
                raise AssertionError(
                    f"H4 rig sanity FAIL on ({cid_i},{cid_j}): emission_recompute={emission_recompute_rate:.3f} "
                    f"vs published={published_rate:.3f} drift={emission_drift:.3f} > 0.05. "
                    "We are reading the wrong slot, the wrong adapter, or the wrong prompt. Refusing to proceed."

4.4 vLLM API choice — prompt_logprobs vs HF teacher-forced (picked AND justified)

Picked: vLLM prompt_logprobs=1.

  • Why vLLM: #406 Phase 3 already uses vLLM with LoRARequest swapping for the EXACT same per-cell shape (16 outer adapters × 16 inner conditions × 50 probes), at ~9 min total wall time for the binary version. Reusing the same engine + LoRA swap pattern is the obvious low-risk path. CLAUDE.md mandates vLLM for eval generation.
  • Why prompt_logprobs=1 (not HF forward): HF forward-pass (the #406 Phase 1 pattern) requires reloading the LoRA adapter into a fresh PeftModel per outer condition, which is ~20× slower per cell than vLLM's hot-swap. The vLLM path is correct for our needs because we are NOT capturing residual-stream activations (already done in #406 Phase 1); we only need a single log-prob scalar per (model, prompt). prompt_logprobs=1 is the documented API for this: at each prompt position, vLLM returns the top-1 log-prob AND the actual-token log-prob (so we always get the marker log-prob, even if marker is not top-1).
  • Why max_tokens=1 (not 0): vLLM 0.11.0 requires max_tokens ≥ 1 in SamplingParams. We read out.prompt_logprobs[L] regardless of the generated token; the generated token is unused (we throw it away). Sets logprobs=1 to avoid the generated-token logprobs slot being None (purely defensive — does not affect the DV).
  • Why pass prompt_token_ids directly (not the string): #406's Phase 1 MF-1 fix flagged that tokenizer.decode(prompt_ids + [MARKER_ID]) followed by re-encode can re-segment BPE boundaries (the leading-space marker is exactly the class of token vulnerable to this). vLLM accepts {"prompt_token_ids": [...]} in llm.generate() per the documented API — we use it for byte-exact safety.

Why code, not a model call? The DV is a deterministic log-prob extraction at a fixed slot — no unstructured-data parsing involved. There is no candidate single-Claude-call formulation; this is a pure numerical readout from a tensor.
