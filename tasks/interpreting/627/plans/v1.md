## 0.0 TL;DR (plain English)

- **What I'll run:** Mostly re-analysis, one small GPU job. And if the marker fraction differs by mix once computed in the non-compressing measurement space, the parent run's "constant fraction" summary was an artifact of the compressed space it was computed in.

## 3. Hypothesis

- **H1 (primary, the new measurement).** If the #608 containment effect is selectivity rather than dose, then at interpolated install 0.50 the positive-only arm's bystander-mean sycophancy delta exceeds the contrastive arm's by ≥ +0.10 with the 95% crossed-bootstrap CI excluding 0 (collision-robust panel: 5 sources, qwen_default excluded per #608's registered convention). **Falsified** (headline reduced to dose) if the gap CI sits inside ±0.05. Between → graded/partial, reported as such. Prior: endpoint gaps were +0.5..+0.8, so I expect survival — but contrastive suppression develops late in training (#608's contrastive arms "wake up" slowly), so a mid-install null is genuinely possible.
- **H2 (marker formalization).** If #601's constant-fraction observation is real and not a log-prob-space artifact, the bystander-mean leakage fraction in EOS-margin space differs by ≤ 0.05 between the contrastive-mix arms and the positives-only arms at matched install, with persona-cluster bootstrap CI inside ±0.10. Falsified if the CI excludes 0 beyond ±0.10 — that would mean the marker-side "no leakage difference at matched install" summary was carried by softmax compression.
- **H3 (inherited, restated through the new lens).** LoRA-vs-FT: the sycophancy method gap survives by construction (#606 measured it at matched install; expect the FT fraction > LoRA fraction at every realized sub-ceiling cell); the refusal gap does not survive at the measured matched read (expect overlapping fractions for retrain-FT vs LoRA). No new test — consistency check of the fraction view against the published verdicts.
- **H4 (dose-curve premise).** Leakage is not a function of install level alone: at matched install, cross-run leakage spread exceeds within-run bootstrap noise (already evidenced by #606's endpoint trio; formalized descriptively per family).

## 11. Decision Rationale

No model training → no training hyperparameters. Load-bearing eval/analysis parameters, one `Source:` per unique value:

- **Panel, probes, rollouts, decoding, judge** — all inherited verbatim. *Why:* cross-checkpoint comparability with #608's committed own-rate trajectories is the entire basis of the matched-install selection; any change breaks the parity anchors. **Source: #608** (its grounding carries over — inherit fast-path).
- **Matching target 0.50 / band [0.40,0.60] / bracket-interpolation / ±0.05 equivalence / 10k crossed bootstrap / ±0.08 parity tolerance** — the published matched-install protocol for judge-rate behaviors in this program. **Source: #606.**
- **Interpolation width guard ≤ 0.60** — *Why:* bans the #606 production-refusal failure (interpolating across a 0.066→0.964 jump) while admitting all but two of this design's pre-computed brackets. **Source: #606 (follow-up retrain incident); the 0.60 value itself: ungrounded — sensitivity reported at 0.45 (excludes comedian-posonly + sw_eng-posonly too).**
- **Marker matched-install tolerance = 2× max within-cell seed gap (margin space, computed from committed data)** — **Source: #601** (its registered 5.58-nat = 2×2.79 convention, ported to margin space as a formula rather than a number).
- **Marker fraction denominator floor: source Δmargin ≥ 2.0 logits** — *Why:* caps fraction noise from a small denominator. **Source: ungrounded — needs sensitivity sweep (registered at 1.0 / 4.0; an analysis filter, not a run parameter).**
- **#514 off-saturation filter (trained logp ≤ −1 nat, argmax rate < 0.10)** — *Why:* off saturation Δlog Z ≈ 0 so Δlog P ≈ Δz_marker, making the log-prob fraction faithful where z-fields were never stored. **Source: `.claude/rules/marker-leakage-measurement.md` (analysis contract) + #514's verified schema.**
- **Model id** — not repo-new (every config in this plan already used it) → no AutoConfig smoke needed.
