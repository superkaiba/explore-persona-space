# Does #722's function-change verdict hold when the post-FT answer profiles come from the fine-tuned model's own answers

## Goal

Re-run #722's M0-vs-M-plus function-change and chain-rho comparison on #537's adapters with the post-FT answer profiles computed from answers GENERATED by each fine-tuned model (on-policy, vLLM greedy) instead of teacher-forced base-model answers, adding the matched-text decomposition control (teacher-force the on-policy text through both models) to split representation change from output-distribution change, to test whether the 'function M moves only for the taught fact' verdict survives on-policy measurement.

## Overview / Motivation

[#722](https://eps.superkaiba.com/tasks/722) compared the base map M0 with the
post-finetuning map M⁺ (context vector c_C → answer-profile summary) on #537's
trained adapters and concluded "finetuning measurably reshapes the
context→answer map only for a taught fact" (fact 1.6–3.3× above the refit
floor; chain-ρ 0 → +0.50; EM/sycophancy inconclusive). But the entire
comparison lives OFF-POLICY for the trained model: in the #667 paired store the
response text R is generated ONCE by the BASE model (greedy, temp=0) and
teacher-forced through both models, so v⁺ measures how the trained model
PROCESSES base-model answers, never how it represents its OWN answers. If
finetuning mostly changes what the model says (which is exactly what a behavior
implant does), that change is invisible to v⁺ by construction — the "function
held" reads for EM/sycophancy could be an artifact of the off-policy regime,
and even the fact's function-change magnitude could be mis-estimated. This is
the measurement-validity concern the project's on-policy-first rules exist for
(teacher-forced proxies are opt-in, not the construct), and it is the exact
axis #823 probes from the other side (externally-generated text on #779's
substrate).

## What to run (design sketch — planner refines)

Re-run #722's M0-vs-M⁺ comparison with the post-FT leg ON-POLICY:

1. **Generation (~1–3 GPU-h):** for each of #537's 16 source adapters ×
   30 target contexts × the same tier-2 probe pool, generate greedy on-policy
   responses R⁺ from the ADAPTER-loaded model (vLLM multi-LoRA, matching the
   #667 generation settings: greedy temp=0, same max_new_tokens). Persist all
   rollout text per Upload Policy.
2. **Paired extraction (~7–8 GPU-h, #667's measured precedent):** teacher-force
   R⁺ through BOTH the trained model (→ v⁺_onpolicy, the new post-FT answer
   profile) AND the base model (→ v0-over-R⁺, the matched-text control), same
   mean-over-response recipe + layers (7/14/21) as the #667 store (or the
   winning summary position if #811 has landed — planner decides).
3. **Fits (~3–6 GPU-h):** #722's exact fit harness (`issue722_fit_M.py` +
   bootstrap floors + chain-ρ vs the existing leakage matrix E; ridge-only per
   #722's MLP verdict, with the MLP-vs-shuffle validity gate re-run).

**Decomposition control (the point of the design):** generating from the
trained model breaks #722's matched-tokens property, so the analysis MUST split
the total change per cell into (same text, different model) = representation
change vs (same model, different text) = output-distribution change. The three
legs available make this possible: v0(R_base) and v⁺(R_base) already exist in
the #667 store (reuse — no re-extraction), and this run adds v⁺(R⁺) and
v0(R⁺).

## Constraints / inherited caveats

- The n=16 source-keyed c_C cap is INHERITED unchanged (this task changes the
  answer text provenance, not the context side); carry it as the standing scope
  caveat. The headline is the on-policy-vs-off-policy DELTA in the
  function-change reads, which shares the cap across arms.
- Single manipulated variable = answer-text provenance (base-generated
  teacher-forced → trained-model on-policy). Everything else (grid, layers,
  fit harness, floors, E) held at #722's recipe.
