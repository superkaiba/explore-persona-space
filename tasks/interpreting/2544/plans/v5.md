# Plan — #2544: How the context→answer map forms across pretraining (Olmo-3-7B checkpoint ladder)

## 0.0 TL;DR (plain English — the user reads this first)

- **What I'll run:** I'll take one open model (Olmo 3 7B) whose makers published a checkpoint after every slice of pretraining, pick 15 snapshots from random weights through 5.93 trillion tokens plus the final chat versions, and at each snapshot fit the same simple linear predictor we always use: "given the model's internal state after reading a question, predict its internal state while writing its own answer." Same 18,000 real user questions at every snapshot, same folds, same baselines, so the only thing that changes is how far along pretraining is. A reduced grid re-scores each snapshot on the final model's answer text (and vice versa) so I can tell "the mapping changed" apart from "the answers changed", and a 4-example prompt at every snapshot measures how much in-context examples substitute for training.
- **What I expect:** The predictor starts useless at random weights, climbs as pretraining proceeds, and past some token count the final model's mapping is already recoverable from an earlier snapshot by a change of coordinates. The literature genuinely splits on WHEN the climb happens (very early vs mid-training), so I am not betting on either; the run decides it. I also expect the 4-example boost to peak in the middle and fade as the weights absorb the skill.
- **What would change my mind:** If the curve is flat until the very end, or the fitted predictor never beats the copy-the-input baseline, the mapping is not "inherited from pretraining" the way our earlier results assumed. If even the best coordinate alignment from late-pretraining snapshots recovers under half of the final mapping's quality, post-pretraining stages genuinely rewrite it, which would weaken the pre-fine-tuning-geometry theory.

## 3. Hypothesis

Let Q(m, s, ρ, ℓ) = pooled cluster-grouped OOF R² of the ridge map fitted on checkpoint m's activations over (query-block context state, answer state from source s's text) under render ρ at layer ℓ. layer* = the frozen shared headline layer (§6). D(T) = Q(m=T, s=T, 0-shot, layer*); D̃(T) = D(T) − identity+bias R²(same cell) (the baseline-subtracted curve). Δ_form = D̃(main) − D̃(r0), cluster-bootstrap 95% CI. T_half = the first rung T with D̃(T) − D̃(r0) ≥ 0.5·max(Δ_form, 0.10) (first crossing; well-defined under non-monotonicity). ρ_P(i→j) = Procrustes-aligned transfer R²(i→j) / Q(j, j) at layer* (alignments train-fold-fitted; answer-side alignment on same-answer-text pairs from the s=main column so it cannot absorb the answer-distribution change — the #825/#1902 recipe). T_c = the earliest pretraining rung i such that ρ_P(i→main) ≥ 0.8 for i AND every later pretraining rung (monotone-suffix definition, robust to a single dip). Δ(T) = Q(T, T, 4-shot, layer*) − Q(T, T, 0-shot, layer*), paired per context.

- **H1 (formation timing — the registered headline; an ADJUDICATION, not a bet).** The literature splits: circuit-level structure forms at <1% of training, content-level linear readouts at intermediate stages (§2). The registered read is the label of D̃(T)'s shape below. Pre-registered: a NON-MONOTONE D̃(T) is interpretable (Natural Ungrokking, 2606.26050), not a pipeline fault; §6 names the real-dip-vs-artifact checklist.
- **H2 (crystallize then reparameterize).** T_c exists strictly before end-of-pretraining: past T_c further pretraining only changes coordinates on a map that already exists (#825's base→instruct finding moved one axis over; #1902's median adjacent aligned retention 0.893 is the post-training comparison point). Kill: no pretraining rung reaches ρ_P(i→main) ≥ 0.5 — the map is genuinely rewritten to the end. T_c's value is an estimation read (bootstrap distribution over cluster draws, re-computing the crossing per draw).
- **H3 (substitution decays).** Δ(r0) ≈ 0 (no ICL at random init — expected per GPT-3's scale result, 2005.14165; NOT evidence of a broken arm), Δ(T) > 0 at intermediate rungs, shrinking by main. Estimation read: the Δ(T) curve with paired cluster-bootstrap CIs; the peak-vs-final contrast Δ_peak − Δ(main) carries a selection-inherited CI (argmax rung re-selected per draw). H3's read is adjudicated JOINTLY on Δ(T), Δ_ww(T) (within-window rows), and Δ_FA(T) (full-attention companion layer) — §6 sliding-window handling: a substitution pattern is narrated only if present in Δ_ww AND Δ_FA; a decay confined to the over-window pooled read at a sliding layer* is labelled architecture-confounded (window effect), not substitution.

DISJOINT and exhaustive: No-formation ⇔ upper 95% CI of Δ_form < 0.10; Unresolved ⇔ otherwise AND no rung crosses 0.5·max(Δ_form, 0.10); Early ⇔ otherwise AND T_half ≤ 21B tokens (rung ≤ r2); Intermediate ⇔ otherwise AND 21B < T_half ≤ 1.2T (rungs r3–r6); Late ⇔ otherwise.

(The Early/Intermediate boundaries are registration conveniences pinned to ladder rungs: r2 = 21B sits below both Pythia FV-transfer readings (33.5B token-matched / ~650B fraction-matched), so Early is consistent with induction-only timing, Intermediate brackets both FV readings, Late sits past 2.5T. H2/H3 are estimation reads with CIs; the line above is the plan's only registered verdict lattice.)

**Grounding for the 0.10 formation floor (registered):** 0.10 is an estimator-resolution + nuisance-scale floor from MEASURED same-rig quantities on this DV family: it sits ≥ 1.4× above the parent's realized shuffled-pairing null magnitude (|−0.037…−0.069|, #1902 — the fit machinery's own zero-scale) and ≈ 2.5× above the largest measured non-mechanism perturbation of the same DV (the ±0.03–0.04 render-swap effect, #825/#1902), while sitting ≈ 3.5× BELOW the parent's realized formed-map diagonals (0.344–0.349). Precedent under the literal lattice: a #1902-scale formed map clears the floor even if identity+bias absorbed half its diagonal (≈ 0.17 > 0.10 ⇒ never labelled No-formation), and a null-scale read (≤ 0.07) lands below it (⇒ never labelled formed). A run-derived floor from the in-run null was considered and REJECTED: the shuffle-refit null is strictly negative and deepens mechanically toward the floor-branch n_tr ≈ d, so a null-derived floor would inflate exactly where resolution matters (`.claude/rules/selection-symmetric-nulls.md`). Floor-sensitivity is registered: the lattice label is recomputed at floor ∈ {0.05, 0.10, 0.15}; a label that flips inside that band ships as boundary-sensitive (low-confidence categorical), and a T_half bootstrap mass crossing a rung-bin boundary likewise downgrades the shipped label from categorical to low-confidence.

(All H1 labels are scoped to the shared-intersection context population — §6 "Scope caveat: intersection estimand".)

Row-coverage (registered paired contrast Δ(T)): both arms' rows are supplied per-context by the store cells `analysis_tensors/issue2544_store/<rung>/diag0/L*.pt` (0-shot arm) and `<rung>/diag4/L*.pt` (4-shot arm) over the SAME shared-intersection context ids (one pinned id list per tier, `eval_results/issue_2544/diagnostics/intersection_manifest.json`), with per-context held-out SS components persisted per arm in `eval_results/issue_2544/fits/percell/*.npz`.
