# Plan v1 — issue #1950: inline lint gate purges stale bytecode caches before its legs

## Plan Summary

Make `scripts/inline_lint_gate.py` deterministic against stale repo-tree
`__pycache__/*.pyc`: purge the bytecode caches of the three editable code
roots (`scripts/`, `src/`, `tests/`) under the gate's resolved repo BEFORE
any leg runs, and thread `PYTHONDONTWRITEBYTECODE=1` into every leg's child
env so the gate's own subprocesses never repopulate in-tree caches mid-run.
Verdict semantics (PASS/BLOCK/INCONCLUSIVE) are byte-unchanged. 0 GPU-h,
non-architectural (no public contract change; the gate's CLI, cert format,
audit files, and verdict vocabulary are untouched).

## Goal / requirement

Three gate runs on #1345 (2026-07-31) returned BLOCK/INCONCLUSIVE on
failures not reproducible outside the gate; each traced to a stale
`scripts/__pycache__/*.pyc` whose recorded source (mtime, size) matched a
NEWER source file (mtime has 1-second granularity, so an Edit →
ruff-format-hook rewrite → run cycle landing inside one second produces a
pyc header that still validates against the newer file — documented in
`.claude/agent-memory/experiment-implementer/feedback_stale_pycache_masks_signature_change.md`).
The gate's plain `uv run pytest` / `uv run python` children then import the
OLD module while direct developer runs (which purge/disable bytecode)
recompile. Purging pycache immediately before the gate made it
deterministic all three times.

**Acceptance criteria:**

1. Before the lint leg runs, `run_legs` purges `*.pyc` under
   `scripts/__pycache__`, `src/**/__pycache__`, and `tests/**/__pycache__`
   of the gate's resolved `repo` tree — best-effort (an unremovable file
   WARNs on stderr, never crashes the gate), with a one-line stderr audit
   note recording the purged-file count.
2. All three legs (lint, map, pytest) run with
   `PYTHONDONTWRITEBYTECODE=1` in the CHILD env (merged over `os.environ`
   via the existing `extra_env` mechanism — both the default-argv and the
   hermetic override branches observe it; the gate's own process env is
   never mutated).
3. `.venv/`, `external/`, `data/`, and any path outside the three code
   roots are NEVER touched by the purge.
4. Verdict semantics unchanged: no edit to the classification /
   attribution / cert-writing logic.
5. Hermetic unit tests pin (a) the purge (a planted stale `.pyc` under
   each of the three roots is gone after `run_legs`; a planted `.pyc`
   under `.venv/` and `external/` survives) and (b) the env threading
   (`PYTHONDONTWRITEBYTECODE=1` observable in each leg's child env via the
   documented `EPM_INLINE_GATE_*_CMD` override commands).

## Method delta (Decision Rationale)

Current state: no bytecode isolation anywhere in the gate (verified at
clarify time: 0 hits for `pycache|DONTWRITEBYTECODE|PYTHONPYCACHEPREFIX`).
Three candidate remedies were weighed (autonomous Decision — the filing's
sketch permits any of them):

- **CHOSEN: purge repo-code `__pycache__` + `PYTHONDONTWRITEBYTECODE=1` on
  child legs.** The purge is the emitter's empirically proven remedy (3/3
  occurrences resolved), targets exactly the editable roots where
  same-second rewrites happen, and costs ~0 (repo `.py` files recompile in
  milliseconds on next import). `PYTHONDONTWRITEBYTECODE=1` keeps the
  gate's own children from writing fresh in-tree pyc mid-run, so the
  purged state holds for the gate's whole lifetime and the shared tree
  accretes fewer future collision candidates. Deleting a `.pyc` is
  regeneration-safe for concurrent sessions (a mid-import reader either
  wins the race and reads it, or recompiles from current source — both
  correct). Source: CPython import system docs (pyc validation compares
  recorded source mtime+size; `sys.dont_write_bytecode` /
  `PYTHONDONTWRITEBYTECODE` stops WRITING only, it does NOT stop READING a
  validation-passing stale pyc — hence purge + no-write, not no-write
  alone) + the agent-memory incident record (#1345, 2026-07-31).
- Rejected: `PYTHONPYCACHEPREFIX=<fresh temp dir>` alone. It does redirect
  BOTH read and write (fully hermetic), but it bypasses the `.venv`
  site-packages' installed bytecode too, forcing per-run recompilation of
  every imported third-party module (torch/transformers reachable from
  mapped tests' `src/` imports — thousands of modules, tens of seconds to
  minutes per leg, on a gate already measured at 2.5-6 min).
- Rejected: `PYTHONDONTWRITEBYTECODE=1` alone (the filing's parenthetical).
  Insufficient by CPython semantics: it never prevents READING an existing
  stale pyc, which is the failure mode.

## File paths + concrete diffs

**`scripts/inline_lint_gate.py`** (single target file — matches the
filing's `workflow_fix_target:`):

1. New module constant near the existing env-var constants:
   ```python
   # Child-leg env guard (#1950): the purge below removes stale repo-tree
   # bytecode; this stops the gate's own children re-writing it mid-run.
   NO_BYTECODE_ENV = {"PYTHONDONTWRITEBYTECODE": "1"}
   # Code roots whose __pycache__ the gate purges (editable roots only —
   # NEVER .venv/external/data: installed-package bytecode is not the
   # same-second-rewrite staleness source and is expensive to recompile).
   PURGE_ROOTS = ("scripts", "src", "tests")
   ```
2. New function (placed near `_best_effort_choom`):
   ```python
   def purge_repo_bytecode(repo: Path) -> int:
       """Best-effort unlink of *.pyc under the editable code roots'
       __pycache__ dirs (stale-mtime-matched pyc determinism guard, #1950).
       Returns the number of files removed; unremovable files WARN on
       stderr and never crash the gate."""
       removed, errors = 0, 0
       for root in PURGE_ROOTS:
           base = repo / root
           if not base.is_dir():
               continue
           for pyc in base.rglob("__pycache__/*.pyc"):
               try:
                   pyc.unlink(missing_ok=True)
                   removed += 1
               except OSError:
                   errors += 1
       if errors:
           print(
               f"inline_lint_gate: warn: {errors} bytecode cache file(s) "
               "could not be removed — gate proceeds (purge is best-effort)",
               file=sys.stderr,
           )
       print(
           f"inline_lint_gate: purged {removed} stale-candidate bytecode "
           f"cache file(s) under {'/'.join(PURGE_ROOTS)} __pycache__ (#1950)",
           file=sys.stderr,
       )
       return removed
   ```
3. `run_legs`: call `purge_repo_bytecode(repo)` immediately after
   `_bounded_fetch(repo)` (before the lint leg); thread the env:
   - lint leg: `extra_env=dict(NO_BYTECODE_ENV)`
   - map leg: `extra_env=dict(NO_BYTECODE_ENV)`
   - pytest leg: `extra_env={SCAN_EXTRA_FILES_ENV: os.pathsep.join(payload), **NO_BYTECODE_ENV}`
4. Module docstring: add a short "Bytecode determinism (#1950)" paragraph
   mirroring the existing numbered-note style.

**`tests/test_inline_lint_gate.py`**: extend the hermetic suite:

- `test_purge_repo_bytecode_removes_code_root_pyc_only`: tmp repo tree
  with planted `.pyc` under `scripts/__pycache__/`,
  `src/pkg/__pycache__/`, `tests/__pycache__/`, plus `.venv/...__pycache__/`

- `test_run_legs_purges_before_legs`: plant a stale `.pyc` in the hermetic

- `test_legs_child_env_carries_dont_write_bytecode`: override each leg

- Unremovable-file WARN path: covered by
