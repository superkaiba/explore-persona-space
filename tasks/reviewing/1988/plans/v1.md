# Plan v1 — #1988 workflow-fix: widen check-28 figure token pattern to arm slugs

## Goal / requirement

Widen `scripts/verify_task_body.py` check 28 (`check_figure_label_codes` /
`_opaque_code_tokens`) with a SEVENTH token class: hyphen-separated arm slugs
(the fleet's `behavior-context-regime-lr-seed` grammar, e.g.
`cas-pers-con-lr1e5-s137`) rendered in figure text (tick labels, titles,
legends). WARN-class only; captions that name the slug suppress the WARN for
that figure; one WARN per body (existing aggregation).

**Acceptance criteria**
1. `_opaque_code_tokens("… cas-pers-con-lr1e5-s137 …")` returns the slug.
2. All-alpha ≥3-segment hyphen words (`end-to-end`, `state-of-the-art`) are
   NOT flagged (digit-segment requirement).
3. 2-segment tokens (`log-prob`) are NOT flagged.
4. A slug inside a path-shaped word is exempt (existing per-word path
   exemption reused).
5. `check_figure_label_codes` on a #1768-shaped sidecar flags slug tick
   labels; a figure whose blockquote caption contains the slug verbatim is
   suppressed FOR THE SLUG CLASS ONLY.
6. Check stays WARN-class (never a hard FAIL); grandfathered classes (a)-(f)
   behave byte-identically (no new suppression applied to them).
7. Tests in `tests/test_verify_task_body.py` cover 1-6 and pass; no
   pre-existing check-28 test regresses.

## Method delta (vs the current scanner)

Current `_opaque_code_tokens` covers six classes: `@L<d>` pins, snake tokens
(≥3 segments or digit-bearing), `H\d[a-z]?` hypothesis codes, `f16`/`l16`
slot-family, `[PM]\d[a-z]?` candidate codes, letter-arrow transitions
(#1902/#1986). No hyphen-separated class exists — #1768's ~10 slug-bearing
figures pass clean (verified live 2026-08-05: slugs sit at
`meta["text"].axes[].yticklabels` VALUES, inside the scanned walk). Delta =
one added regex class + digit filter + a slug-class-scoped caption-decode
suppression in the check-28 loop.

## File paths + concrete diffs

`scripts/verify_task_body.py` (sole code target) + `tests/test_verify_task_body.py`:

1. New module-level regex next to the sibling class regexes:
   ```python
   # Hyphen-separated arm slugs (#1988): >=3 segments, first segment 2-6
   # lowercase alpha, later segments lowercase alnum; a post-match filter
   # requires >=1 digit-bearing segment so ordinary hyphenated English
   # (end-to-end, state-of-the-art) stays unflagged. Fleet grammar:
   # behavior-context-regime[-lr…]-seed (cas-pers-con-lr1e5-s137).
   _ARM_SLUG_RE = re.compile(r"\b[a-z]{2,6}(?:-[a-z0-9]{1,12}){2,}\b")
   ```
2. In `_opaque_code_tokens`: add `_ARM_SLUG_RE` to the class loop, with the
   SAME `_only_in_path_words` exemption, plus the digit filter
   (`any(ch.isdigit() for ch in tok)` — mirrors the snake-class condition;
   observed fleet slugs always carry an `lr…`/`s<seed>` digit segment,
   e.g. `imp-pers-ft-con-s42`). Docstring gains the class-(g) paragraph.
3. In `check_figure_label_codes`: split token collection so slug-class
   tokens are tracked separately per figure; before warning, compute the
   figure's CAPTION window (the contiguous `>`-blockquote lines immediately
   following the image line in the scanned section) and DROP slug tokens
   that appear verbatim (case-insensitive) in that caption — the mechanical
   proxy for "the caption decodes the slug". Non-slug classes never
   suppressed (byte-stable grandfathered behavior). Aggregation unchanged:
   the existing single WARN CheckResult per body (head-3 truncation)
   already satisfies "WARN once per body, not per figure".
4. Docstring/doc-block updates: function docstring "SIX token classes" →
   seven, add the #1988 incident line; the L518-520 check-28 doc row
   mentions arm slugs.
5. Tests (`tests/test_verify_task_body.py`, alongside the 25 existing
   check-28/`_opaque_code_tokens` references): unit tests for acceptance
   criteria 1-4; integration tests for 5-6 using the existing fake-sidecar
   test pattern (tmp git repo or monkeypatched `_read_figure_meta_json`,
   whichever the existing check-28 tests use — follow the in-file
   precedent).
