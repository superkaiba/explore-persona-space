# Plan — Issue #2224: Persona-Vectors screening on REAL corpora (mapped + direct-regression ΔP vs exact ΔP)

## 0.0 TL;DR (plain English — the user reads this first)

- **What I'll run:** The Persona Vectors paper showed you can flag training data that will make a model evil/sycophantic/hallucinating *before* you train on it — but only by generating a fresh model answer for every single example first, which they called impractical. I'll test two cheaper screens that need zero generation (one that maps the question to a predicted answer, one that's a small trained scorer) on two real chat datasets — one raw and toxic (LMSYS), one heavily cleaned (UltraChat). Then I'll do the paper's own test of the screens: pick the 500 "worst" and 500 "safest" examples each screen finds, actually fine-tune on them, and see which screen's picks move the trait the most.
- **What I expect:** The cheap screens land close to the expensive exact one — especially the mapping screen on sycophancy and hallucination, where the paper's cheap approximation was weakest — so you get exact-grade screening at forward-pass cost.
- **What would change my mind:** If the cheap screens' top-500 picks induce clearly less trait than the exact method's picks, or if all screens flatten out on the cleaned dataset (which would tell us screening only works where there's obvious bad data to find, not that our method failed).

## 3. Hypothesis

**H1 (4a, dataset-level).** On the #2221 real-twin suite, dataset-level ΔP correlates with post-finetuning trait expression for every predictor arm (Spearman ρ > 0), and the mapped-ΔP + probe arms match exact ΔP (|ρ_mapped − ρ_exact| ≤ 0.10 per trait) while beating the prompt-token approximation on sycophancy (ρ_mapped − ρ_prompttoken ≥ +0.10, the paper's known-weak trait).

**H2 (4b, sample-level — the headline).** In predictor-controlled selection, the mapped-ΔP and probe top-500 subsets induce trait expression ≥ the exact-ΔP top-500 (within noise) and strictly > random-500; bottom-500 induces trait expression < random-500 (suppression). Confirmed most strongly where the paper's prompt-token approximation was weakest (sycophancy).

**H3 (judge-filtered).** After removing samples the Sonnet judge scores > 1 for the trait, mapped/probe top-500 still induces trait expression > random-500 — the screens surface trait-inducing data judges miss (the paper's underspecified-query hallucination class).

**Falsification.** H2 falsified if mapped/probe top-500 trait expression is materially below exact-ΔP top-500 (paired CI on the trait-score difference wholly below 0) OR not above random-500. H1 falsified if mapped/probe ρ does not track exact ΔP (|Δρ| > 0.10 with the gap on the losing side) on ≥ 2 of 3 traits.

**Kill / abort criteria (data-quality stops, not scientific gates).** (1) If the base-model pre-finetune trait score/rate on the eval probes is already saturated (>90/100 or >0.9 rate) for a trait, that trait's install-delta is uninformative — report it and DROP that trait from the H2 headline (never narrate a saturated-baseline cell as a screening result). (2) If a corpus yields < ~20k usable single-turn ≤512-token samples (§12 A10), its selection tails are too thin for a faithful top/bottom-500 — report and raise the stream cap or scope to the corpus that qualifies. (3) The P1 dependency poll parks (stops) at `blocked` if #2221/#2222 artifacts do not resolve within the bounded poll — a data-availability stop, re-driven on the sibling marker.

**Seeds.** One finetune seed per 4b cell (`seed=42`), matching the paper's single-finetune-per-subset design; statistical inference is the paired cross-method contrast + a response-level bootstrap CI over eval questions × the N=5 judge draws (the paper's "error bars over responses"), NOT a seed distribution. A second seed (`seed=137`) on the headline top-tail cells only (mapped/exact/random × 3 traits × 2 corpora ≈ 18 cells) is an optional robustness add if the paired CIs are borderline — declared here, run only on borderline cells, never a full 2× fan-out.

**Pre-registered non-falsifying outcome (honest-failure mode).** Compressed dynamic range for ALL predictors on UltraChat (little bad content to find) is a finding about screening curated data, NOT a method failure — reported as such, per-corpus, never pooled with LMSYS.

**Registered verdict lattice** (per-trait, per-corpus, on the paired trait-score difference `Δ = trait(mapped-top500) − trait(exact-top500)` and the contrast `trait(mapped-top500) − trait(random500)`):
DISJOINT and exhaustive: Matches-exact-and-beats-random ⇔ Δ's 95% CI straddles 0 AND (mapped−random)'s 95% CI excludes 0 on the positive side; Below-exact ⇔ Δ's 95% CI wholly below 0; Beats-exact ⇔ Δ's 95% CI excludes 0 on the positive side; Inconclusive ⇔ otherwise.

**Registered paired contrast.** 4b compares selection methods on the SAME corpus pool per (corpus, trait) — each predictor's top-500 is a paired arm scored against the shared random-500 and against exact-ΔP top-500.
Row-coverage: both arms' registered rows are supplied per-cell by `eval_results/issue_2224/selection_finetune/<corpus>__<trait>__<method>__<tail>/trait_scores.json` (each selection-method arm) and `eval_results/issue_2224/selection_finetune/<corpus>__<trait>__random/trait_scores.json` (the shared control arm); the analyzer set-checks every registered (corpus,trait,method,tail) cell resolves before computing the paired difference.

## 4. Design

**Why code, not a model call?** The screening scores (raw / exact-ΔP / prompt-token-ΔP / mapped-ΔP / probe-difference), the corpus single-turn trim + ≤512-token filter, and the top/bottom/random-500 selection are deterministic numeric operations over activations at N≈50k — a code path (structural output, determinism, cost at this N; a model call would be non-reproducible and pointless). What flips it: the trait FILTER on candidate samples IS correctly a judge (model) call (the paper's design) — code cannot judge trait expression. N/A does not apply; both decisions are stated.

**Contrastive negatives:** N/A — this is a strict single-variable-per-the-paper replication of the paper's §6.3 positive-only selection design (named contrastive-negatives exemption (b)); carried as a scope caveat. The manipulated variable is SELECTION METHOD, not contrastive-vs-not.

**Data source + realism tier:** TIER 1 / TIER 2. LMSYS-Chat-1M (`lmsys/lmsys-chat-1m`) = real-world conversations across 25 LLMs (tier 1, the paper's own raw pole); UltraChat 200k (`HuggingFaceH4/ultrachat_200k`) = established heavily-filtered benchmark corpus (tier 2, the paper's filtered pole). Both are the paper's exact corpora — replication fidelity + top-tier realism coincide. Justification: no synthetic tier is used; this is the whole point of Experiment 4 (real, not synthetic, data).

**Completion provenance:** the 4b selection-finetune TRAINING ROWS are the corpora's OWN real responses (published-corpus-verbatim / real-world) — NOT on-policy base generations. This is dictated by replication fidelity: the paper finetunes on the dataset responses, and the whole screening question is about the dataset's own responses. On-policy-first is N/A here (the training data IS the real corpus response by construction — the replication exemption). Provenance stated per arm in every setup line.

**Marker / behavior-implant stopping recipe:** N/A — not a marker implant (no marker token). The trait-implant stopping recipe (10 epochs, lr 1e-5) is the paper's §6.3 recipe, grounded in replication fidelity (§11), NOT a marker recipe.

**Persona-vectors extraction recipe:** the persona vectors are REUSED (not extracted here) from #2222, which reuses #778's `r_B` (built via the 7-step `.claude/rules/persona-vectors-recipe.md` pipeline: 5 pos/neg pairs, 20/20 question split, 10 on-policy rollouts/arm, Sonnet judge-filter with REFUSAL/non-numeric/out-of-range drop, response-avg activations, diff-of-means per layer). **Layer-selection regime: READ-OUT / prediction** — the persona vector is dotted against activations to predict a quantity (trait shift), so #2222 sweeps all layers and selects by predictivity; #2224 INHERITS #2222's selected read-out layer(s) for cross-program consistency (no re-selection here; a max-over-layer selection would trigger a selection-symmetric null — avoided by freezing to #2222's choice, §6). The "except logits" carve-out holds (project Sonnet judge, no second judge, no logit scoring).

**Multi-arm resolution-band:** N/A — no multi-arm band-simultaneity gate (no training-amount matching across a resolution band).

**Few-shot / ICL:** N/A — no ICL or few-shot demonstrations in this design.

**Smoke/sweep architectural parity:** UNIFICATION DEFAULT — the smoke phase = the selection-finetune sweep with `--cells 1` (one corpus × one trait × one method × one tail) through the SAME dispatcher, same `train_lora` call, same eval + judge path, same teardown. No divergence.

**Smoke blind-spot enumeration:** the smoke's PASS does NOT certify: (a) the Batch-API judge wave at production scale (the smoke judges one cell's ~100 responses synchronously, not the ≥5k-call Batch wave — pilot-gate covers that separately, §6); (b) the frozen-map load across ALL three traits (smoke loads one trait's map/vector — the p1 dependency gate re-checks all three resolve at the pinned revision); (c) the exact-ΔP generation throughput at 50k scale (smoke generates for ~200 prompts). No smoke-conditional substitution/downgrade branches exist in the dispatcher (production and smoke run identical code with `n_cells=1`); everything else the smoke executes.

**No all-or-nothing eligibility gates:** the trait FILTER (keep score < 1) is the paper's exact filter — faithful replication. Graceful degradation on the 500-count: if a predictor's filtered survivors < 500 in a cell, take all survivors, DOCUMENT the shortfall (report N actually used), never silently drop the cell. Floor = 300 survivors (below → report the cell as filter-collapsed, a finding about that corpus/trait, never backfilled).

**Equalize-down:** all unfiltered selection cells train on exactly 500 samples by construction (top/bottom/random-500). Filtered cells equalize to the min survivor count across predictors within a (corpus, trait) so the filtered comparison is dose-matched; surplus discarded, coverage difference documented.

**Baseline propensity on both sides:** EVAL-side — measure the BASE Qwen trait rate + graded score on the eval probes (the Δ denominator) before any finetune. SOURCE-side — the corpus's own trait-expression rate IS measured by the judge filter (fraction scoring > 1 per corpus/trait); reported per corpus as the base rate of trait-bearing data, and it predicts where screening has range (few bad samples → compressed range, H1/H2 honest-failure mode).

**Generation-and-reduce persists rollout TEXT:** the exact-ΔP base-generation pass GENERATES then reduces to a projection — it persists the generated base responses under `raw_completions/exact_dp_base_gen/` (per corpus) so any sibling can recompute exact ΔP at a different layer without regenerating. Predictor forward-pass summaries (per-sample projections, context/answer vectors) persist under `analysis_tensors/`.

### Predictor arms (x-axis), per trait, computed on the BASE model over each corpus pool

| Arm | Definition | Generations needed |

| Raw projection | mean response-token activation of dataset response · v̂ | none (fwd pass) |
| **Exact ΔP** (paper ground truth) | raw − projection of base greedy generation to same prompt | 1 gen/sample (P0b) |

| **Direct-regression probe** (ours) | probe(response) − probe(stand-in); probe = #2222 Form-A ridge; stand-in = mapped (preferred) | none (fwd pass) |

- Cross-corpus transport (probe): probe trained on corpus A scored on corpus B (LOFO by corpus) — reported as the transport read.
- Supervision ledger, stated in every table setup line: frozen map = trait-agnostic; persona vector = trait-description + judge-filter; probe = judge labels.

## 5. Conditions and Controls

| Plain-English name | What it tests | What it controls for | Config slug |
|---|---|---|---|
| Exact-ΔP selection (ground truth) | The paper's expensive method being matched | The reference every cheap screen is compared against | `exact_dp` |
| Prompt-token-ΔP selection | The paper's cheap approximation (identity-map assumption) | Whether a *learned* map beats the identity assumption | `prompttoken_dp` |
| Mapped-ΔP selection (ours) | Frozen context→answer map as the cheap screen | Generation-free screening at forward-pass cost | `mapped_dp` |
| Direct-regression probe selection (ours) | Trained ridge probe difference as the cheap screen | Learned read-out vs contrastive-mean-diff | `probe_diff` |
| Random-500 (shared control) | Baseline finetune with no screening | Plain finetuning effect / dose (shared across predictors) | `random` |
| Bottom-500 (suppression tail) | Low-ΔP samples shift models AGAINST the trait | The other tail — direction of the screen | `<method>__bottom` |
| Top-500 (induction tail) | High-ΔP samples shift models TOWARD the trait | The induction tail (headline) | `<method>__top` |
| Judge-filtered top-500 | Screening after removing judge-flagged trait samples | Whether screens surface what judges miss | `<method>__top_filtered` |
| Base model (pre-finetune) | Trait rate/score before any finetune | The Δ denominator (baseline propensity) | `base` |
| Per-corpus map refit (EXPLORATORY) | Map fitted on each corpus's own prompts | In-domain strength vs frozen portability | `refit_<corpus>` (labeled, never pooled) |

**Controls rationale.** Random-500 rules out "any 500 samples move the trait" (dose baseline). Bottom-500 rules out "high-ΔP is just high-variance" — it must move the trait the *other* way. ## 11. Decision Rationale

- **What:** LoRA r=32, α=64. **Why:** the paper's §6.3 real-world selection-finetune recipe verbatim. **Source:** arXiv 2507.21509 App. "Inducing persona shifts from real-world datasets" ("We train using LoRA with rank of 32 and alpha of 64"). **Alternatives:** none — replication fidelity fixes it.
- **What:** 10 epochs, lr 1e-5 linear schedule, batch 16. **Why:** the paper's real-world selection recipe verbatim (deliberately over-trains 500 samples to induce the trait). **Source:** arXiv 2507.21509 App. real-world-datasets ("training on the 500 samples for 10 epochs … learning rate of 1e-5 with a linear schedule and a batch size of 16"). **Alternatives:** the §Dataset-and-finetuning 1-epoch recipe is for the finetuning-shift suite, NOT the real-world selection — do not mix.
- **What:** `use_rslora=True`. **Why:** the paper appendix for real-world says only "LoRA r=32 α=64" (silent on rank-stabilization); pinned to #2221's program-wide choice for cross-experiment comparability. **Source:** #2221 (inherit); paper silent → flagged §12 A9. **Alternatives:** `use_rslora=False` (classic α/r) — the literal appendix reading; a one-line sensitivity cell available if a reviewer objects.
- **What:** working pool 50k/corpus. **Why:** exact-ΔP requires one base generation per pool sample — 50k bounds the generation pass (the very cost we demonstrate avoidable) while giving ample headroom for a top/bottom-500 selection to be meaningful. **Source:** ungrounded — design choice (paper used ≤200k); flagged §12 A10, sensitivity: larger pool only strengthens the "generation-free" claim's value, never changes the paired comparison. **Alternatives:** 200k (paper max) — 4× the generation cost for a comparison that is already saturated at 50k.
- **What:** graded judge N=5 draws temp>0, Sonnet-4.5. **Why:** project graded-primary judging rule; N=5 is the graded-multisample default. **Source:** `.claude/rules/llm-judging.md` rules 1/4/11; #778 used N=6. **Alternatives:** N=1 (rate only) — loses graded range.
- **What:** persona-vector layer = #2222's read-out-selected layer(s). **Why:** read-out/prediction regime (direction dotted to predict trait shift), the recipe's read-out branch; freezing to #2222's selection keeps the program consistent AND avoids a max-over-layer selection here. **Source:** `.claude/rules/persona-vectors-recipe.md` step 7 read-out; #2222. **Alternatives:** the paper's steering-layer (20) — a candidate source of its sycophancy weakness; one ablation cell at layer 20 available.
- **What:** trait filter keep score < 1 (0–100). **Why:** the paper's exact filter for the "surface what judges miss" test. **Source:** arXiv 2507.21509 App. real-world-datasets ("keep only if the trait expression score is < 1"). **Alternatives:** none — replication.
