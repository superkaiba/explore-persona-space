### 4a. Where the scan runs (decision: separate pass, existing pipeline untouched)

The task-URL scan runs INSIDE the existing per-line loop (after the footer / `excluded` / `table_idx` `continue` guards — exclusion parity by construction, requirement (d)), on a NEW intermediate string, BEFORE the existing `residue` computation. The existing two-sub order (`_LINK_RE` then `_INLINE_CODE_RE`) is **not reordered** — reordering could shift bare-token behavior on pathological backtick/bracket mixes (e.g. `` [`#779`](url) ``) and would risk existing pins; a separate pass costs one extra regex sub per line and zero behavioral coupling.

**Inline-code semantics (decision: inline code PROTECTS the link scan).** The link scan runs on `_INLINE_CODE_RE.sub(" ", comment_masked[i])` — a backticked example link is sanctioned, in mask parity with the bare-token scan. Rationale: (i) one sanction list for both token shapes keeps the check's mental model and SPEC text simple; (ii) a backticked link is verbatim syntax-as-data, the same reason inline code is sanctioned at all; (iii) misuse (backticking a genuine reference to dodge the check) is already named as banned in the FAIL text and is exactly as detectable by the Lens-2 LM read as the existing bare-token escape-hatch misuse — same trust model. The FAIL message extends the existing "do NOT backtick a genuine issue reference" sentence to cover task links (§4c). Verified interaction: `_INLINE_CODE_RE` spans exclude backticks and newlines, so adjacent code spans (`` `a` [#779](url) `b` ``) never swallow the link between them; an odd backtick pair straddling a link masks it (fail-open residual, documented, §4b).

### 4b. The regex + scope decisions

New module constant next to `_BARE_ISSUE_REF_RE` (L7264), with a shape comment:

```python
# Prior-issue task URL (the dashboard task route). Scanned directly rather
# than via a [label](target) wrapper so markdown links, <…> autolinks, AND
# bare URLs in standalone prose all hit — dropping the brackets must not
# dodge the check, and the URL line of a multi-line link still fires.
_TASK_URL_RE = re.compile(r"https?://eps\.superkaiba\.com/tasks/\d+")
```

This deliberately **replaces the candidate sketch's link-shaped regex** (`\[[^\]]*\]\(https?://…/tasks/\d+[^)]*\)`), which I checked against the required cases and found strictly weaker: it misses angle-bracket autolinks, bare URLs, and the URL half of a multi-line link, while matching nothing the URL scan misses (a task URL inside a link target contains the URL). Scope decisions, per form:

- **Markdown links `[label](…/tasks/K…)` — IN** (the task mandate; the #928 shape).
- **Bare task URLs in prose — IN.** Same substantive violation (GFM autolinks bare URLs on the dashboard); zero legitimate use in a standalone section outside the already-excluded sanctioned forms; scanning the URL is what makes brackets-dropping a non-evasion.
- **Angle-bracket autolinks `<https://…/tasks/K>` — IN.** Subsumed by the URL scan for free; a rendered clickable prior-issue reference either way.
- **Reference-style links (`[label][ref]` + a definition line elsewhere) — OUT** (documented residual, fail-open). Rationale: never used in this project's bodies (the SPEC's canonical form is inline); partially covered anyway — a `[#K][ref]` label already FAILs the bare-token scan today (the `[` before `#` is not in the lookbehind set), and a definition line inside a standalone section hits the URL scan; only a non-`#K`-labeled reference link whose definition sits outside the standalone sections escapes.
- **Case-mangled (`HTTPS://EPS…`) / schemeless (`eps.superkaiba.com/tasks/K`) URLs — OUT** (documented residual, fail-open). All project-generated URLs are lowercase + schemed; a mangled form is deliberate evasion → LM-lens backstop.
- **Backtick pair straddling a link** (odd inline-code placement masks the URL) — OUT, fail-open residual, same family as the existing backticked-`<details>` residual.

Each OUT lands as a new bullet in the `_bare_issue_ref_hits` docstring's "Documented residual edges" list, direction noted (all fail-open). One existing residual bullet is **updated**: the multi-line `[#K](\nurl)` link edge — under the new scan the URL line now correctly FAILs for task links (no longer purely a false-FAIL edge); the residual narrows to the label-side bare `#K` of a multi-line NON-task link.
