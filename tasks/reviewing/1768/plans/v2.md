# Plan — Issue #1768: What fine-tuning a behavior into a context does to the context→answer mapping (fleet-scale, 15,000 contexts × 60 arms)

## 0.0 TL;DR (plain English)

- **What I'll run:** No training — I take the 56 already-trained in-band model variants from the behavior-implant grid plus the base model, feed all of them the same 16,400 real user prompts, record their internal activity at three layers, and fit the base-vs-trained input→output maps at a sample size ~1000× the earlier attempt that came back inconclusive.
- **What I expect:** Training moves the answer-side activity along one dominant direction per model (as before), the input-side vector barely moves, and the map itself changes little beyond refit noise — with the write's direction matching the behavior read-out vector rather than the theory's predicted training-displacement direction (the tension the older fleet showed).
- **What would change my mind:** If at this sample size the trained map reliably differs from the base map beyond the refit-noise floor, or the write direction now aligns with the theory's predicted direction (cosine clearly above the matched-random band), the theory's write assumptions get support instead of refutation — and either verdict is decisive this time because the confidence intervals will actually resolve.

## 3. Hypothesis

Registered per-arm predictions (each arm = one trained checkpoint, evaluated per layer; primary layer 19 for content, 25 for marker):

- **H1 (Q1, Δc):** the context vector barely moves: median ‖Δc‖/‖c⁰‖ < 0.05 across corpus contexts for ≥ 80% of arms (LoRA writes to the answer side; context tokens are pre-response). Falsified per arm if median relative Δc > 0.15.
- **H2 (Q2, map change):** at n=15k the M⁺-vs-M0 comparison RESOLVES (that is the point of the scale-up); direction expectation from #722's taught-fact cell: marker arms show Changed; content arms are genuinely uncertain (that is what #722 could not resolve).
- **H3 (Q3, Δv):** the answer vector moves on-policy AND matched-text (weights-carried component nonzero: median ‖v⁺_tf − v⁰‖ above the base capture-noise floor for ≥ 90% of trained arms).
- **H4 (Q4, write shape):** the write is low-rank — top-1 SVD direction of the Δv matrix holds ≥ 0.6 of update variance (A6/A9; #667 measured 0.81–0.86) — and in the three-way horse race cos(ŵ, r_B) exceeds cos(ŵ, δ), with cos(ŵ, δ) inside the norm-matched-random band (replicating #667's A5/A8 refutation on the new fleet). For marker arms, cos(ŵ, W_U[83399]) at L25 is the pre-registered third candidate.
- **H5 (A7/A10-11 gate):** whitened base-similarity gate predicts the realized gate at ρ ∈ [0.3, 0.7] (Spearman, per arm; #667: 0.46–0.59).
- **H6 (A4/A7 stability, scoped):** re-extracted r⁺_B on 6 trained arms has cos(r⁺_B, r_B) > 0.8 at the capture layers (read-out stable in direction even where #667's expression-partial-ρ read failed).

Verdict lattice, registered for the per-(arm, layer) Q2 map-change verdict, with D := Δ_med(M⁺, M0) − floor_p95 (both defined in §6):

DISJOINT and exhaustive: Changed ⇔ D > 0 AND D's 95% CI excludes 0 on the positive side; Unchanged ⇔ D's 95% CI is wholly below 0; Unresolved ⇔ otherwise.

The registered paired contrast is the per-context paired M⁺-vs-M0 comparison over shared corpus rows (15,000 train / 1,000 test pairs per arm × layer).

Row-coverage: both arms' registered rows are supplied per-context by data/issue_1768/out/corpus_capture/<arm>/pooled.pt (trained arm) and data/issue_1768/out/corpus_capture/base_content/pooled.pt (base arm; marker arms read base_mk/pooled.pt).

### 4.5 Fit phase (`scripts/issue1768_fit.py`, pod-side GPU, after the store upload lands)

**Estimator: full-dim (3584→3584) primal ridge with val-selected λ**, reusing the #779 fitter's streaming-primal machinery (`scripts/issue779_ffc_n1m_fits.py` — streaming X^TX/X^TY blocks, multi-λ solve, `apply_map`; measured 87.1 s at n=963,444, so trivially cheap at n=15,000). λ grid: the same 23-point log grid 1e-3–1e8; if the val-selected λ lands on a grid edge, extend one decade and refit (the n1M fit's `lambda_grid_edge: "low"` shows the grid can bind).

Per (arm, layer), fits: **M0**: c⁰→v⁰ (base arms), **M⁺**: c⁺→v⁺ (on-policy), **M⁺_tf**: c⁺→v⁺_tf (matched-text). Reads per fit: held-out R² + mean cosine on the pinned 1,000-test rows (bootstrap CI over test rows, 1,000 draws, seed 1768) + **identity+learned-bias baseline** (`analysis/mapping_baselines.identity_bias_predict`, L28 — applicable, d_in = d_out = 3584) + **kNN retrieval** (`knn_retrieval`, L63; euclidean + cosine, k ∈ {1, 10}, pool = the 1,000 held-out true targets, chance 1/1000 and 10/1000).

Map-change reads (per arm × layer):
- **Δ_med** := median over the 1,000 test contexts of ‖M⁺(c) − M0(c)‖ on the common base-c grid (the #722 read, re-expressed on primal fits).
- **Refit-noise floor**: B=200 bootstrap-row-resample refits of M0 (and of M⁺, reported separately); floor draw = Δ_med between two same-condition refits; floor_p95 = 95th percentile. Each draw is one batched GEMM-Gram + multi-λ solve on GPU (no per-draw SVD loop; the vectorize-first law).
- **Verdict**: the §3 lattice on D = Δ_med − floor_p95, CI from paired bootstrap over test rows × refit draws.
- **Decomposition** on held-out rows: v⁺(x) − v⁰(x) = [M⁺(c⁺) − M0(c⁺)] + [M0(c⁺) − M0(c⁰)] + residual; report the three terms' norm shares. Text-carried vs weights-carried: repeat with M⁺_tf/v⁺_tf.
- **Transfer fold (OOD)**: fit on the LMSYS-only subset, evaluate on WildChat test rows, and vice versa (group = source corpus) — the group-structured generalization read alongside the pinned-test R².

**Why not `fit_cell` for the corpus fits (reuse checks (i)/(l), resolved to a source-appropriate substitute):** `scripts/issue722_fit_M.py::fit_cell` (L628) is dual-space (n×n Gram + Woodbury PRESS — its own docstring/#811 notes) and PCA-64-targeted, built for n = 16–120; at n = 15,000 the dual path is the wrong branch by construction (n ≫ effective d for the Gram, O(n²) memory ≈ 1.8 GB/draw, O(n³) eigh per floor draw), and forcing it would be a caller-side workaround of a scale boundary the module was never built for. def load_corpus_cell(arm_id: str, layer: int, out_root: Path) -> dict:

```python
            "Cplus": plus["context"][layer], "Vplus": plus["response"][layer],
            "Vplus_tf": tf["response"][layer],
            "split": fixed_split_ids()}  # 15000/400/1000, pinned
```

### 4.6 Direction reads (Q4 + assumptions battery; `scripts/issue1768_directions.py`)

All in FULL 3584-dim space (the body's PCA finding: only 38–63% of the write's squared norm lies in the base top-64 PCA subspace). Per arm, per layer:

- **ŵ** = panel source-context write (§4.4); **write matrix** = corpus Δv rows (on-policy and matched-text variants).
- **A6 (A9) rank read**: SVD of the centered Δv matrix; top-1 variance share + effective rank; cos(u₁, ŵ).
- **Three-way horse race**: cos(ŵ, δ_{C,B}), cos(ŵ, r_B[layer]), and for marker arms cos(ŵ, W_U[83399]) (base `lm_head.weight` row).
