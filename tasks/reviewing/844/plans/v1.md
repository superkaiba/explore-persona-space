## 0. Plan Summary

**What breaks:** `scripts/spawn_session.py:40` sets `PROJECT_ROOT = Path(__file__).resolve().parent.parent`. When the executed file is a **worktree copy** (an orchestrator session with cwd `.claude/worktrees/issue-795` runs `uv run python scripts/file_infra_task.py …`, which resolves the *worktree's* copy of the script tree), `PROJECT_ROOT` = that sibling worktree. `spawn-issue --issue N` then finds no `issue-N` worktree under `<sibling-worktree>/.claude/worktrees/` and falls back to `cwd = PROJECT_ROOT` — the unrelated sibling worktree (spawn_session.py:911–917). `autonomous_session_watch.py:406–408` and `file_infra_task.py:63–64` both `from spawn_session import PROJECT_ROOT`, inheriting the bug and, worse, running their `task.py` / spawn subprocesses with `cwd=PROJECT_ROOT` (file_infra_task.py:198, 264), so a worktree copy of the *filer* dispatches the *worktree's* (stale) `scripts/spawn_session.py` too. This matches the observed 2026-07-01 pattern exactly (each filing orchestrator's worktree became every spawned session's cwd).

**The fix:** resolve the canonical primary checkout via the git common dir — the mechanism `task_workflow.repo_root()` already implements for exactly this bug class ("silent fallback is what produced the worktree-staleness bug class this resolver replaces", task_workflow.py:181–210). `repo_root()` itself is NOT directly reusable as a spawn cwd because its branch guard *routes* an off-`main` primary to the managed `_task-main-pin` shim worktree (task_workflow.py:288–305) — a task.py-commit shim, never a valid session cwd. So: extract the validated common-dir-parent resolution into a small public `primary_checkout_root()` in `task_workflow.py` (no branch guard, no routing; `repo_root()` behavior unchanged), have `spawn_session.py` compute `PROJECT_ROOT` from it at import time (fail loud), and add a spawn-time cwd assertion in all three spawn commands. Watcher + filer are fixed transitively through their existing `from spawn_session import PROJECT_ROOT`.

**Files:** `src/explore_persona_space/task_workflow.py` (+~35 lines, additive extract), `scripts/spawn_session.py` (~30 lines), one-line comments in `scripts/autonomous_session_watch.py` + `scripts/file_infra_task.py`, tests in `tests/test_task_workflow_worktree.py` + new `tests/test_spawn_session_repo_root.py`. One implementer round.

## 1. Goal

Spawned Happy sessions (spawn-pm / spawn-issue / spawn-campaign) always open with cwd = the canonical primary repo root or the target issue's own worktree under the canonical `.claude/worktrees/` — never an unrelated sibling worktree — even when the spawning script executes as a worktree copy; asserted loudly at spawn time.

## 2. Requirement + acceptance criteria

1. `spawn_session.PROJECT_ROOT` resolves to the primary checkout (`/home/thomasjiralerspong/explore-persona-space`) regardless of which copy of the script runs and regardless of caller cwd. Verified by a unit test that resolves from a scratch linked worktree.
2. `spawn-issue --issue N` cwd is exactly: `<canonical>/.claude/worktrees/issue-N` if it exists, else the canonical repo root. A cwd that is any other worktree (sibling, `_task-main-pin`, follow-up of a different issue) causes a loud non-zero exit naming #844 — never a silent spawn.
3. `spawn-pm` / `spawn-campaign` cwd is the canonical repo root, same assertion.
4. `autonomous_session_watch.py` and `file_infra_task.py` subprocess calls (`cwd=PROJECT_ROOT`) run against the canonical root even when those modules are imported from a worktree copy (transitively via the fixed import — no logic change in those two files).
5. `task_workflow.repo_root()` behavior is byte-for-byte unchanged (existing `tests/test_task_workflow_worktree.py` suite passes unmodified).
6. `uv run ruff check` on touched files passes; `uv run python scripts/workflow_lint.py` (no-flags default run) passes; full `uv run pytest` passes.

## 3. Method delta

| | Before | After |
|---|---|---|
| Root resolution | `Path(__file__).resolve().parent.parent` (returns the worktree when the script is a worktree copy) | `git rev-parse --path-format=absolute --git-common-dir` parent, validated, via new `task_workflow.primary_checkout_root()` (returns the primary checkout from ANY copy / cwd) |
| spawn-issue fallback | Silent `cwd = PROJECT_ROOT` even when that is a sibling worktree | Same preference order (target worktree → repo root), but both candidates are canonical by construction + `_assert_spawn_cwd()` tripwire before `post()` |
| Failure mode | Silent wrong cwd | Loud `RuntimeError` at import (git missing / not the eps repo) or `sys.exit` at spawn (non-canonical cwd) |
| Watcher / filer | Inherit the buggy constant | Inherit the fixed constant (no code change beyond a provenance comment) |

## 4. Design

### 4a. `src/explore_persona_space/task_workflow.py` — extract + new public function

Refactor `_resolve_repo_root_cached` (lines 230–322) by extracting its steps (a)+(b) — the rev-parse + layout validation, everything before the line-278 branch guard — into a module-private helper, and expose it publicly:

```python
def _resolve_primary_checkout(env: dict[str, str]) -> Path:
    # VERBATIM move of _resolve_repo_root_cached steps (a)+(b):
    #   git rev-parse --path-format=absolute --git-common-dir  (cwd=_MODULE_DIR, sanitized env)
    #   -> RuntimeError on FileNotFoundError / CalledProcessError (unchanged messages)
    #   common_dir.name == ".git" check; common_dir.is_dir() check
    #   parent = common_dir.parent; (parent / "tasks").is_dir() check
    #   return parent

@functools.lru_cache(maxsize=1)
def _primary_checkout_cached(_key: tuple[int, str]) -> Path:
    return _resolve_primary_checkout(_sanitized_git_env())

def primary_checkout_root() -> Path:
    """Absolute path of the PRIMARY (main) checkout — the git common dir's
    parent — with full layout validation but NO branch guard and NO off-main
    routing to the managed `_task-main-pin` worktree. For consumers that need
    the canonical checkout PATH (session-spawn cwd, #844), not a safe tasks/
    read-write root (those use repo_root()). Fails loud; never falls back to
    a __file__/cwd walk-up."""
    return _primary_checkout_cached((os.getpid(), os.getcwd()))
```

`_resolve_repo_root_cached` becomes: `parent = _resolve_primary_checkout(env)` followed by the untouched branch-guard/routing block (lines 278–322). `invalidate_cache()` additionally clears `_primary_checkout_cached`. `repo_root()` semantics unchanged.

Why not use `repo_root()` directly in spawn_session: (i) off-`main` primary → it returns `.claude/worktrees/_task-main-pin`, a detached task.py-commit shim (task_workflow.py:399–411) — spawning a session there reproduces the wrong-cwd bug class the task exists to kill; (ii) detached primary HEAD → it raises even for `spawn_session.py list`. Branch state is guarded elsewhere (PreToolUse hook, task.py's own resolver); spawn cwd is purely a path question. Why not a local resolver inside spawn_session.py: duplicates ~30 tested lines of git/validation logic against the "reuse existing in-repo tools" rule, and the two resolvers would drift; `task_workflow.py` is explicitly in the workflow-fix surface.

### 4b. `scripts/spawn_session.py`

Line 40, replace:

```python

PROJECT_ROOT = primary_checkout_root()   # #844: git-resolved canonical root; fails

```

Import-time resolution is deliberate: the name stays a module-level `Path` constant, so the ~50 existing uses across three scripts, the `from spawn_session import PROJECT_ROOT` bare-name bindings (watcher:408, filer:64), and the test-suite monkeypatch pattern (`monkeypatch.setattr(asw, "PROJECT_ROOT", …)`, e.g. test_autonomous_session_watch.py:3532/5982) all keep working unchanged. Cost: one cached git subprocess pair per process (~10 ms).

New helper + call sites:

```python
def _assert_spawn_cwd(cwd: Path, *, issue: int | None) -> None:
    """Refuse to spawn into anything but the canonical repo root or the
    TARGET issue's own worktree (#844: sibling-worktree cwd inheritance)."""
    if cwd == PROJECT_ROOT:
        if not (cwd / ".git").is_dir():   # a linked worktree has a .git FILE
            sys.exit(f"#844 spawn-cwd assertion: {cwd} is not the primary checkout "
                     f"(.git is not a directory); refusing to spawn")
        return
    if issue is not None and cwd == WORKTREE_DIR / f"issue-{issue}" and cwd.is_dir():
        return
    sys.exit(f"#844 spawn-cwd assertion: {cwd} is neither the canonical repo root "
             f"({PROJECT_ROOT}) nor the target issue-{issue} worktree; refusing to spawn")
```

- `cmd_spawn_issue` (line ~918, after the worktree/root choice, before building `body`): `_assert_spawn_cwd(cwd, issue=issue)`.
- `cmd_spawn_pm` (before line 861): `_assert_spawn_cwd(PROJECT_ROOT, issue=None)`.
- `cmd_spawn_campaign` (before line 1111): `_assert_spawn_cwd(PROJECT_ROOT, issue=None)`.

By construction the assertion cannot fire after 4a — it is a tripwire against a future edit reintroducing `__file__`-based resolution, and it satisfies the task's "assert at spawn time" requirement with `sys.exit` (loud, non-zero), never a silent fallback. Update the module docstring + `cmd_spawn_issue` docstring to name the canonical-root guarantee. The `WORKTREE_DIR` preference order (target worktree if present, else root) is preserved exactly; exact-name match `issue-{N}` only, as today.

## 7. Kill criteria (what would make this approach wrong)

- **A dispatch context without git or outside any checkout** invoking `spawn_session.py`: import would now fail loud. Verified none exists (cron cds into the project; all invocations are `uv run` from the checkout; git 2.34.1 at `/usr/bin/git`, on cron's default PATH). If one surfaced, the fix would need call-time (per-subcommand) resolution instead of import-time — a refactor of this plan, not a patch.
- **A consumer that legitimately needs the worktree as root:** none found among `PROJECT_ROOT` consumers (spawn cwd, task.py subprocess cwd, `.claude/cache` sidecars, orphan-sweep roots — all want canonical). The watcher's `_SCRIPTS_DIR` sibling-import bootstrap is the only "own tree" use and is deliberately left on `__file__`.
- **`uv run` from a worktree cwd failing to import the package** (broken worktree venv): would make the worktree-copy invocation fail loud instead of resolving canonically. That is still strictly better than the silent wrong-cwd status quo (fail-fast rule), so not a kill — but if it proved common, the resolver would need to be stdlib-local in spawn_session.py (the named alternative in 4a).
