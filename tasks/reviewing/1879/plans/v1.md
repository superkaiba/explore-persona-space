## 1. Requirement + acceptance criteria

Mechanize the multi-figure side of the clean-result lens-9 one-result-one-figure rule: a single `### <result>` H3 under a v4 body's `## Results` that embeds MORE THAN ONE inline figure, where the extra figure(s) are not attributable to the sanctioned raw+processed / aggregate+per-unit pair, must be flagged by `scripts/verify_task_body.py` instead of passing silently (origin incident: #1769 fu1 re-gate — `fig_dose_ladder.png` + `fig_alpha3_lattice.png`, two distinct analyses in one section, verifier PASSed, caught only by the LM clean-result-critic).

Acceptance criteria:

2. **v4-sentinel-gated, forward-only**: `is_v4(body)` false → vacuous PASS ("not a v4 body"). v3/v2/legacy bodies are never newly flagged.

## 2. Key design decisions

**D1 — WARN tier, not FAIL (deviation from the origin finding's "FAIL" wording; sanctioned by the task body's own "WARN (or FAIL for v4)" sketch).** Rationale: (a) the sanctioned >1-figure exception (raw+processed / aggregate+per-unit pair, SPEC.md L600-632) is not just allowed but REQUIRED for aggregate results, so 2-figure sections are the COMMON conforming case and pair detection from text is necessarily heuristic; (b) a heuristic FAIL blocks `set-body` at analyzer time on conforming bodies (FAILs block; drafts must PASS) — the false-positive cost is an analyzer round, the exact cost the check exists to save; (c) 3 legitimate figures are conceivable (aggregate + per-unit + raw counterpart of a transformed view — SPEC's two rules compose), so no cardinality threshold is safely FAIL-tier; (d) every adjacent figure-cardinality check in this file (31, 38) is deliberately WARN-tier with the LM critic (Lens 9/11) as substantive owner — the accepted false-negative direction for mechanical backstops. The WARN still achieves the incident's goal: the analyzer runs the verifier BEFORE posting and must acknowledge WARNs in-body, so the #1769 shape surfaces one round earlier than the LM critic. FAIL-tier escalation is a must-ask deviation (§8).

**D2 — pair-evidence heuristic (silences the WARN).** For a section with n≥2 inline figures, pair evidence = ANY of:
   (a) any embedded figure path's basename matches the existing `_PER_UNIT_FIG_RE` (`per[-_]?(context|unit|cell|pair)` — the project's per-unit companion naming convention, reused verbatim, single source);
   (b) the section text (prose + alt text + blockquote captions, case-insensitive) matches a bounded declared-pair idiom regex `_DECLARED_PAIR_RE`, shaped as: `per[-_ ](unit|question|context|cell|pair|seed|source|point)s?` | `\braw\b[^.\n]{0,60}\b(alongside|counterpart|version|view|scatter)\b` | `\b(unbinned|low[- ]level|per[- ]point)\b` | `\b(companion|counterpart)\b`.
   Precision-over-recall is NOT required here (inverse of check 31's exemption idioms): a generous silence list is the accepted direction for a WARN backstop — a silenced true violation falls to Lens 9 (unchanged owner); a WARN on a true pair costs only an acknowledge line. Exact regex composition is implementer detail (§8 allowed deviations).

**D3 — scan surface.** `_v4_results_body(body)` (footer-truncated `## Results`) → `_prose_layer(...)` (fences + `<details>` stripped, so a quoted example embed never counts) → split on `^### ` H3 boundaries → count `_IMAGE_RE` matches per section, plus HTML `<img src=...>` embeds (the check-31/#1510 symmetric-embed doctrine; a cheap `<img\b` scan). Reuses only existing helpers; no new parsing infrastructure.
