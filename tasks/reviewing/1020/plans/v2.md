## 1. Goal

Retry the result-fetch before declaring a Codex job lost, and support re-attach
to an already-spawned codex-companion job after a wrapper kill, instead of
re-paying the whole 10–60 min Codex run. Motivating evidence (2026-07-02 /daily
sweep): ≥7 transient Codex dispatch failures across sessions —
`codex-companion result` reported `No job found` while the job had actually run
(helper exits 5/7/8), and wrapper kills left orphaned running jobs, each costing
a full re-dispatch.

### Requirements

- **R1 (fetch retry):** on a result-fetch failure (nonzero exit from
  `codex-companion result <job-id>`, including the `No job found` class, OR a
  subprocess timeout/OSError from the fetch call itself), re-probe the fetch up
  to `--result-fetch-retry-cap` (default 3) times with jittered backoff before
  declaring the job lost. Retry ONLY the fetch — never the whole job. Exit 7
  remains the terminal meaning and remains excluded from the #579 transient
  whole-job re-dispatch class.
- **R2 (--reattach):** `--reattach <job_id>` skips spawn, polls the EXISTING
  job to a terminal phase reusing `_poll_until_terminal` (incl. the
  progress-aware stall detector and `--max-wait-secs` cap), fetches the result
  (with the R1 retry), writes the output file via
  `_write_output_preserving_codex_artifact`, and posts the same
  `epm:codex-task-spawned` / `epm:codex-task-completed` /
  `epm:codex-task-failed` markers. No re-dispatch on any failure (impossible —
  no prompt). Unknown job id → clean, fast failure with a failure marker.
- **R3 (reattach binding guard — MF1):** with `--issue N` and without
  `--reattach-unbound`, reattach verifies BEFORE arming `_active_job_id` and
  before any poll/fetch that issue N's events.jsonl contains an
  `epm:codex-task-spawned` (by `codex_task`) whose note carries the exact
  token-bounded `job_id=<id>` AND no `epm:codex-task-completed`/`failed` note
  paired with that id. On guard failure: exit-4 class, exactly one
  `epm:codex-task-failed` naming the unbound id, output file untouched, NO
  spawned marker, `_active_job_id` never armed. Fail-closed covers the legit
  "orphan killed before its spawned marker posted" case — that case re-runs
  with `--reattach-unbound`. Without `--issue`, `--reattach-unbound` is
  mandatory (argparse-level).

### Acceptance criteria

1. A fetch that fails twice with `No job found ...` then succeeds returns the
   result; the helper exits 0 and posts `epm:codex-task-completed` whose note
   carries `fetch_retries=2`. No re-spawn.
2. A fetch that fails on every attempt — with the status probe reporting
   `phase=done` (the exact ran-but-unfetchable incident shape) — exits 7 with
   ONE `epm:codex-task-failed` whose note carries the attempt count, a
   `fetch_retries=<k>` token, the last stderr, and the status-probe
   discriminator (`job known, phase=done`). `_spawn_codex` is called exactly
   once for the whole helper run (no whole-job re-dispatch on 7).
3. `--reattach <bound-live-job-id> --output-file F --issue N` polls to done,
   writes F (preserving a pre-existing sentinel-bearing verdict at F, final
   message to `F.final-msg.md`), posts spawned(`reattach=true`) + completed
   (`fetch_retries=0`) markers, exits 0, never calls `_spawn_codex`, never
   reads stdin.
4. `--reattach <id-not-bound-to-issue-N> --issue N` (id absent from issue N's
   spawned markers, OR already terminally paired) exits 4 BEFORE any status
   probe/poll/fetch, posts exactly one `epm:codex-task-failed` naming the id
   and the guard reason, leaves the output file untouched, posts no spawned
   marker. The same invocation with `--reattach-unbound` proceeds.
5. `--reattach <unknown-id> --reattach-unbound` (or bound-but-unqueryable)
   exits 4 after a bounded confirm-probe retry with a failure marker; a
   status-CLI raise (TimeoutExpired) at attach follows the same path (no
   crash, no missing marker); never enters the poll loop's probe-error crawl;
   never spawns; never writes output.
6. `--reattach` with `--prompt`/`--prompt-file` is an argparse error (exit 2);
   `--reattach` without `--issue` and without `--reattach-unbound` is an
   argparse error (exit 2).
7. All 29 existing tests in `tests/test_codex_task_*.py` still pass;
   `uv run ruff check scripts/codex_task.py` clean;
   `uv run python scripts/workflow_lint.py` (no-flags default) passes.

## 2. Grounded companion-CLI behavior (read from source — do not re-derive)

Companion: `~/.claude/plugins/cache/openai-codex/codex/1.0.4/scripts/codex-companion.mjs`
(single install; `_resolve_companion()` picks the max version). All thrown
errors land in `main().catch` → message on **stderr**, `process.exitCode = 1`
(codex-companion.mjs:1023-1026). Verified facts:

- **`result <job-id>`** (`handleResult` → `resolveResultJob`,
  `lib/job-control.mjs:256-279` + `matchJobReference` :191-211): filters the
  jobs index on `status ∈ {completed, failed, cancelled}` then matches the id.
  For a NON-EMPTY job id the ONLY reachable error strings are:
  - `No job found for "<id>". Run /codex:status to list known jobs.` — thrown
    by `matchJobReference` when the id has no match among TERMINAL-status
    jobs. This single string covers ALL THREE cases: job genuinely unknown,
    job known but its index row still says `running` (registry lag / lost
    update), and job pruned.
  - `Job reference "<id>" is ambiguous. Use a longer job id.` — prefix
    collision (we always pass full ids; effectively unreachable).
  - The `Job <id> is still <status>...` and `No finished job found...`
    branches (lines 271/275/278) are **unreachable for a non-empty id** —
    `matchJobReference` throws first. ⇒ **the companion CANNOT tell the helper
    "result pending" vs "job unknown" via `result`**; the discriminator must
    be a `status` probe, and the retry must be time-bounded and blind (see
    Kill criteria — this IS the fallback design).
  - `handleResult` is a **pure read** (`resolveResultJob` + `readStoredJob`;
    no `upsertJob`/`writeJobFile`) — safe to re-invoke.
- **`status <job-id> --json`** (`handleStatus` → `buildSingleJobSnapshot`,
  job-control.mjs:242-254): exit 0 with `{workspaceRoot, job:{phase, status,
  logFile, ...}}` for ANY known job (running or terminal; same
  default-predicate `matchJobReference`); unknown id → exit 1 +
  `No job found for "<id>". Run /codex:status to list known jobs.`
  `_probe_phase` already maps that to `("probe-error", stderr, None)`.
- **The registry is CROSS-ISSUE** (basis of MF1): every wrapper pins
  `cwd=DISPATCH_ROOT` (main checkout), so all issues share ONE workspace-keyed
  state dir (`resolveStateDir` hashes the workspace root, state.mjs:29-44) —
  `status`/`result` will happily serve ANY issue's job id. Nothing
  companion-side binds a job to an issue; the ONLY binding record is the
  `epm:codex-task-spawned` note (`job_id=<id>`) on the issue's own
  events.jsonl. Hence the helper-side guard.
- **The transient mechanism** (`lib/state.mjs`): the jobs index is a single
  `state.json` written **non-atomically** (`fs.writeFileSync` in place, line
  114 — no tmp+rename, no lock) and read-modify-written (`updateState`,
  :118-122) by EVERY concurrent wrapper's progress upserts. A torn read hits
  `loadState`'s bare `catch` → `defaultState()` → `jobs: []` (:58-78) →
  `No job found` for a job that is milliseconds from being readable again.
  This is the transient class the retry recovers.
- **The permanent class** (`state.mjs:80-113`): `saveState` prunes the index
  to the `MAX_JOBS = 50` most-recently-updated jobs AND **deletes** evicted
  jobs' per-job files + logs. A completed-but-unfetched job evicted by 50
  newer jobs is unrecoverable — the bounded retry then honestly exhausts to
  exit 7.
- **Completion write order** (`lib/tracked-jobs.mjs:158-175`): per-job file
  (`writeJobFile`) BEFORE the index (`upsertJob`) — a second, narrower lag
  window consistent with "status said done, result said No job found".
- **Latent crash fixed en passant:** `_fetch_result` (`codex_task.py:547-556`)
  does not catch `subprocess.TimeoutExpired`/`OSError`, and neither does any
  caller — today a 120 s fetch timeout crashes the helper with an unhandled
  traceback and NO failure marker. Same class for `_probe_phase` raises
  reaching the new attach-time confirm loop (MF2). The safe wrappers close
  both at the NEW call sites.
- **Honest latency bounds (non-blocking fix):** the retry's SLEEPS total ≤
  3 × 15 s = 45 s, but each fetch attempt may burn up to
  `RESULT_TIMEOUT_SECS = 120 s` and each discriminator probe up to
  `STATUS_TIMEOUT_SECS = 60 s` before its subprocess timeout fires. True
  bounds: fetch retry worst case ≈ 4×120 + 4×60 + 45 ≈ **~12 min** (typical,
  CLI failing fast with exit 1 in ~1–2 s: **~15–50 s**); reattach confirm
  loop worst case ≈ 4×60 + 45 ≈ **~5 min** (typical: **< ~35 s**). All
  bounded; stated wherever a latency claim appears (constants comment, §6,
  §7 smoke expectations).

    """_probe_phase, with raises (TimeoutExpired/OSError) converted to the
    existing probe-error phase so a diagnostic/confirm probe can never crash

```python
def _fetch_result_with_retry(
    companion: Path, job_id: str, retry_cap: int
) -> tuple[int, str, str, str, int]:
    """Bounded blind retry around _fetch_result. Returns (rc, stdout, stderr,
    detail, retries_used); detail is "" on success, else the attempt count +
    the last status-probe discriminator for the exit-7 failure note.
    retries_used = fetch attempts actually consumed minus 1 (0 on first-try
    success) - threaded into the terminal marker notes as fetch_retries=<k>
    so a recovered torn-read stays operationally countable. Also converts a
    fetch-subprocess TimeoutExpired/OSError (previously an unhandled crash
    with NO failure marker) into a retryable, then terminal-exit-7, failure."""
    total = 1 + max(0, retry_cap)
    rc, stdout, stderr = 1, "", ""
    for attempt in range(1, total + 1):
        try:
            rc, stdout, stderr = _fetch_result(companion, job_id)
        except (subprocess.SubprocessError, OSError) as exc:
            rc, stdout, stderr = -1, "", f"fetch raised: {exc}"
        if rc == 0:
            return rc, stdout, stderr, "", attempt - 1
        if attempt == total:
            break
        # Diagnostic discriminator (logging + final note only, never branching):
        phase, err, _ = _probe_phase_safe(companion, job_id)
        disc = (
            f"status-probe: job unknown/unreadable ({phase}: {err[:150]})"
            if phase in {"probe-error", "shape-error"}
            else f"status-probe: job known, phase={phase}"
        )
        delay = RESULT_FETCH_RETRY_BACKOFF_FLOOR_SECS + random.uniform(
            0.0, RESULT_FETCH_RETRY_BACKOFF_JITTER_SECS
        )
        print(
            f"WARN: result-fetch attempt {attempt}/{total} for {job_id} failed "
            f"(exit {rc}: {stderr[:200]}); {disc}; retrying in {delay:.0f}s (#1020).",
            file=sys.stderr,
        )
        time.sleep(delay)
    phase, err, _ = _probe_phase_safe(companion, job_id)
    disc = (
        f"status-probe: job unknown/unreadable ({phase}: {err[:150]})"
        if phase in {"probe-error", "shape-error"}
        else f"status-probe: job known, phase={phase}"
    )
    return rc, stdout, stderr, f"after {total} attempt(s); {disc}", total - 1
```

### 4.4 `_reattach_binding` + `_run_reattach` (new)

**Binding guard (MF1).** The registry is cross-issue (§2); the ONLY issue↔job
binding record is the issue's own spawned-marker history. Guard reads it via
the already-imported `list_events` (same accessor `_marker_already_landed`
uses):

```python
_JOB_TOKEN_RE_TMPL = r"job_id={id}(?=[\s:,.]|$)"
# Token-bounded: every codex_task-posted note formats the id as
# 'job_id=<id> effort=...' (spawned), 'job_id=<id> phase=done...' (completed),
# or 'job_id=<id>: ...' (_fail) - never bare-suffixed - so the lookahead
# prevents task-abc matching task-abc-def.

def _reattach_binding(issue: int, job_id: str) -> str:
    """Return "" when job_id is bound to this issue (a codex_task-posted
    epm:codex-task-spawned note carries the token AND no terminal
    completed/failed note pairs with it), else a human-readable reason.
    FAIL-CLOSED: any events read error is a reason, not a pass (#1020 MF1 -
    the silent-wrong-verdict class outweighs the retry friction; the
    documented escape is --reattach-unbound)."""
    try:
        events = list_events(issue)
    except Exception as exc:
        return f"could not read issue #{issue} events ({exc}); fail-closed"
    pat = re.compile(_JOB_TOKEN_RE_TMPL.format(id=re.escape(job_id)))
    spawned = terminal = False
    for row in events:                      # full scan - the orphan may be old
        if row.get("by") != "codex_task" or not pat.search(row.get("note") or ""):
            continue
        kind = row.get("kind")
        if kind == "epm:codex-task-spawned":
            spawned = True
        elif kind in ("epm:codex-task-completed", "epm:codex-task-failed"):
            terminal = True
    if not spawned:
        return (f"no epm:codex-task-spawned with job_id={job_id} on issue "
                f"#{issue} (cross-issue registry: this may be ANOTHER issue's job)")
    if terminal:
        return (f"job_id={job_id} already has a terminal codex-task marker on "
                f"issue #{issue} (already fetched/failed; reattach would duplicate)")
    return ""
```

**Reattach driver.** Order is load-bearing (MF1 → MF3 → MF2): guard first,
arm `_active_job_id` second, probe third.

```python
def _run_reattach(companion: Path, args) -> int:
    """Attach to an EXISTING codex-companion job (wrapper-kill recovery,
    #1020). Guard -> arm -> confirm-probe -> spawned marker -> poll ->
    finalize. No re-dispatch on ANY failure - there is no prompt."""
    global _active_job_id
    job_id = args.reattach

    # (1) Binding guard (MF1) - BEFORE arming and before any subprocess call,
    # so a guard failure leaves zero side effects beyond one failure marker.
    if args.issue is not None and not args.reattach_unbound:
        reason = _reattach_binding(args.issue, job_id)
        if reason:
            return _fail(
                args.issue, job_id,
                (f"reattach: binding guard failed - {reason}. Output file "
                 f"untouched; no poll/fetch attempted. Override with "
                 f"--reattach-unbound if this job is genuinely this issue's "
                 f"(e.g. wrapper died before its spawned marker posted)."),
                4,
            )

    # (2) Arm ONLY after the guard (MF3): a SIGTERM during validation must
    # never cross-cancel a job we have not confirmed as ours.
    _active_job_id = job_id

    # (3) Confirm probe with bounded retry, via the SAFE wrapper (MF2): a
    # status-CLI raise (TimeoutExpired/OSError) converts to probe-error and
    # takes this same bounded path to exit 4 + one failure marker.
    total = 1 + max(0, args.result_fetch_retry_cap)
    phase, err, log_path = "probe-error", "", None
    for attempt in range(1, total + 1):
        phase, err, log_path = _probe_phase_safe(companion, job_id)
        if phase not in {"probe-error", "shape-error"}:
            break
        if attempt < total:
            delay = RESULT_FETCH_RETRY_BACKOFF_FLOOR_SECS + random.uniform(
                0.0, RESULT_FETCH_RETRY_BACKOFF_JITTER_SECS)
            print(f"WARN: reattach probe {attempt}/{total} for {job_id} failed "
                  f"({phase}: {err[:200]}); retrying in {delay:.0f}s.",
                  file=sys.stderr)
            time.sleep(delay)
    if phase in {"probe-error", "shape-error"}:
        return _fail(args.issue, job_id,
                     f"reattach: job not queryable after {total} probe(s) "
                     f"({phase}): {err[:400]}", 4)

    if args.issue is not None:
        _post_marker(args.issue, "epm:codex-task-spawned",
            (f"Codex job_id={job_id} reattach=true "
             + ("unbound_override=true " if args.reattach_unbound else "")
             + f"phase_at_attach={phase} "
             f"poll_interval={args.poll_interval_secs}s "
             f"max_wait={args.max_wait_secs}s "
             f"probe_error_cap={args.probe_error_cap} "
             f"stall_detect={args.stall_detect_secs}s"))
    started = time.time()
    if phase in TERMINAL_PHASES:
        terminal = phase             # finished during the orphan gap: skip polling
    else:
        outcome = _poll_until_terminal(companion, job_id, args, log_path, started)
        if isinstance(outcome, AttemptResult):
            return _fail(args.issue, job_id, f"reattach: {outcome.note}",
                         outcome.exit_code)
        terminal = outcome
    result = _finalize_result(companion, job_id, terminal, args, None, started)
    if result.kind == "done":
        return 0
    note = result.note
    if result.kind == "cancelled":
        note = f"{note} (reattach mode: no re-dispatch possible)"
    return _fail(args.issue, job_id, f"reattach: {note}", result.exit_code)
```

Design decisions embedded here (rationale in §11):
- **Binding guard fail-closed, `--reattach-unbound` escape** (MF1): the
  guard's false-negative case (legit orphan whose wrapper died before the
  spawned marker posted, or marker dropped to `_orphaned_markers/`) costs one
  re-run with the override flag; the unguarded false-positive case silently
  writes ANOTHER issue's verdict under this issue's markers and exits 0 — a
  wrong-verdict class the spawn path cannot produce. Asymmetry decides:
  fail-closed.
- **Arm-after-guard** (MF3): SIGTERM mid-validation must not cancel a job
  that may belong to another live issue.
- **Marker:** REUSE `epm:codex-task-spawned` with `reattach=true` (+
  `unbound_override=true` when applicable) note tokens. The note is free text
  (workflow.yaml `fields:` is descriptive prose); downstream consumers pair
  spawned→completed/failed by `job_id=` in the note, and that pairing
  invariant is preserved. A NEW marker kind would be a schema addition =
  architectural = out of scope per the task constraints.
- **Stall detector re-armed**, timer origin = attach time
  (`_poll_until_terminal` initializes `last_log_change_ts = time.time()`): a
  job whose log went silent during the orphan gap gets one full
  `--stall-detect-secs` window before force-cancel, instead of an instant
  false positive.
- **Already-terminal short-circuit:** the common case (job finished while
  orphaned) skips the poll loop's leading 30 s sleep and goes straight to
  fetch.
- **`pre_output_key=None`:** `_key_advanced(current, None)` is True for any
  readable file, so an existing sentinel-bearing (`<!-- epm:`) verdict at
  `--output-file` — plausibly written by Codex BEFORE the original wrapper
  died, i.e. before any snapshot this process could take — is preserved and
  the final chat message lands in the `.final-msg.md` sidecar. A
  snapshot-at-attach key would classify that verdict as "stale" and clobber
  it (the exact #604 incident class this function exists to prevent).
- **Exit codes:** binding-guard failure and unknown/unqueryable job → 4 (the
  existing "probe failed / bad job-id" meaning); poll bails keep 5/6/8; fetch
  exhaustion → 7; terminal failed/cancelled → 1; done → 0. In reattach mode
  exits 3/4/5/8 do NOT trigger the transient re-dispatch loop (never reached
  — `_run_reattach` returns directly from `main`).

## 6. Kill criteria

- **If `codex-companion result` mutated state on read**, re-invoking it would
  be unsafe → VERIFIED FALSE before planning (`handleResult` is a pure read;
  §2). Moot.
- **The companion cannot distinguish job-unknown from result-not-yet-indexed**
  — CONFIRMED TRUE (§2: one `No job found` string for both). Consequence baked
  in: the retry is time-bounded and blind (typical ~15–50 s to honest exit 7;
  worst case ~12 min if every subprocess call hangs to its timeout); the
  status probe is a logged diagnostic only, never a branch condition. There is
  no deeper fallback — this IS the fallback design. If review finds the
  diagnostic probe adds more failure surface than value, dropping it (pure
  blind retry) is an allowed deviation.
- **If the binding guard's note-token matching proves brittle** (a future note
  format change breaking the `job_id=<id>` token) the guard fails CLOSED — a
  false-negative costs one `--reattach-unbound` re-run, never a wrong verdict.
  If false-negatives become chronic, the fix is a structured marker field
  (architectural — must-ask), not a looser regex.
- **If the dominant 2026-07-02 cause turns out to be MAX_JOBS=50 pruning**
  (permanent, not transient), the fetch retry buys nothing for those instances
  (costs the bounded exhaustion latency above before the honest exit 7) —
  `--reattach` still pays for itself, and the pruning fix would live in the
  vendored plugin (OUT of our workflow surface; surfaced as a prose follow-up,
  not fixed here). Not a reason to drop R1: the torn-read mechanism is real at
  ≥7 incidents/day fleet concurrency.
- **If any downstream consumer of `epm:codex-task-spawned` breaks on a
  reattach-post** (e.g. treats every spawned marker as a NEW dispatch for
  counting): fallback = post NO spawned marker in reattach mode (terminal
  markers only) — smaller footprint, still contract-clean; note the binding
  guard reads spawned markers from the ORIGINAL dispatch, so this fallback
  does not starve the guard. Must-ask before switching to a new marker kind
  (architectural).

## 11. Decision Rationale

1. **`DEFAULT_RESULT_FETCH_RETRY_CAP = 3`** — Source: task #1020 body
   ("re-probe the job registry 2-3x with backoff"); picked the upper end
   because the cost asymmetry is extreme (a wasted retry costs
   seconds-to-minutes vs a false lost-job = a 10–60 min Codex re-dispatch);
   magnitude consistent with the in-file `DEFAULT_CANCELLED_RETRY_CAP = 2` and
   `PROBE_ERROR_CAP = 10` conventions. Alternatives: 2 (task-body floor —
   allowed deviation), unbounded (rejected: pruned jobs are permanent, §2).
2. **Backoff sleeps `5.0 s + U(0, 10 s)` per re-probe** — Source: mechanism
   read from the companion source (§2: torn `fs.writeFileSync` read =
   ms-scale; `updateState` read-modify-write lag = seconds), so 5–15 s × 3
   sleep-spacing spans 15–45 s ≫ both windows; jitter rationale copied from
   the in-file `TRANSIENT_RETRY_BACKOFF_*` comment (desynchronize parallel
   reviewer ensembles). Deliberately SHORTER than the 15 s/30 s whole-job
   constants — those are sized for an app-server restart; this is a pure
   registry read. Honest total bound: sleeps ≤ 45 s, but per-attempt
   subprocess timeouts (RESULT 120 s, STATUS 60 s) dominate the worst case
   (~12 min); typical fast-fail exhaustion ~15–50 s. Alternative: reuse 15/30
   (rejected — inflates the typical case with no mechanism gain; allowed
   deviation if reviewer prefers symmetry).
3. **Retry scope = fetch only; exit 7 stays outside `TRANSIENT_FAIL_EXIT_CODES`**
   — Source: the in-file #579 comment (codex_task.py:169-173 — re-running a
   completed job on an AUP refusal is wrong) + the task clarifier.
   Non-negotiable (must-ask to change).
4. **Blind, time-bounded retry with a logging-only status discriminator** —
   Source: read of `lib/job-control.mjs:191-279` proving `result`'s error
