### 4.1 New helper `_git_branch_of` (insert at ~line 164, directly below `_current_git_branch`)

```python
def _git_branch_of(root: str) -> str | None:
    """Checked-out branch of the git checkout at ``root``; None on detached/error.

    Uses ``git -C <root> branch --show-current``, which prints an empty line on a
    detached HEAD (mapped to None — no "HEAD" sentinel needed, unlike
    ``rev-parse --abbrev-ref``). Any subprocess failure also maps to None: the
    caller treats an unresolvable worktree branch as "no default". (task #824)
    """
    try:
        proc = subprocess.run(
            ["git", "-C", root, "branch", "--show-current"],
            capture_output=True,
            text=True,
            timeout=10,
            check=True,
            env={**os.environ},
        )
    except (OSError, subprocess.SubprocessError):
        return None
    branch = proc.stdout.strip()
    return branch or None
```

Mirrors `_current_git_branch`'s exception style (`(OSError, subprocess.SubprocessError)`, `timeout=10`, env passthrough) so the two seams behave identically under test monkeypatching and in production failure modes.

### 4.2 Pushed-branch guard (new function, next to the helper)

```python
def _warn_if_branch_not_pushed(branch: str, git_root: str) -> None:
    """WARN loudly (never fail) when ``branch`` is not visible on origin.

    The GCE startup script clones from origin, so an unpushed defaulted branch
    guarantees a downstream clone/checkout failure (#812 failure class). A
    ls-remote failure here must not block the launch: WARN and continue.
    """
    try:
        proc = subprocess.run(
            ["git", "-C", git_root, "ls-remote", "--exit-code", "origin", branch],
            capture_output=True,
            text=True,
            timeout=30,
            env={**os.environ},
        )
        visible = proc.returncode == 0
    except (OSError, subprocess.SubprocessError):
        visible = False
    if not visible:
        logging.getLogger("dispatch_issue").warning(
            "repo-branch %r is not visible on origin (git ls-remote failed or "
            "found no match) — the GCE startup clone will fail unless the "
            "branch is pushed first",
            branch,
        )
```

**Guard decision — WARN-and-continue (the middle option), one-paragraph justification:** fail-loud (`ls-remote` failure → abort the launch) was rejected because `ls-remote` is a network call — a transient DNS/GitHub hiccup or a slow origin would turn a perfectly valid launch into a hard failure, converting an advisory check into a new flakiness source on the critical dispatch path; keep-INFO was rejected because the #812 failure class (branch content absent on the clone) costs a full provision cycle plus a rc=2 crash to surface, which deserves more than an easily-missed INFO line. WARN-and-continue names the exact failure *before* the provision is spent, is greppable in the dispatch log, and cannot itself break a launch — the fail-loud signal still arrives, just downstream (the GCE clone fails), now pre-explained. The guard is scoped to the NEW worktree-branch rung only (minimal diff; the existing current-branch rung keeps its "ensure it is pushed" INFO wording untouched); extending it to the existing rung is listed as an allowed deviation in §9.

## 11. Decision Rationale

`N/A — no training hyperparameters` (no model is trained; the entries below cover the design decisions).

- **Precedence order (explicit flag > current non-main branch > worktree branch > none).**
  Why: the invoking human/orchestrator deliberately standing on a non-main branch is a stronger intent signal than ambient worktree state; the worktree rung only fills the gap where today's default is provably inert. Source: task #824 constraint set (orchestrator-dictated), grounded in incident #812. Alternatives rejected: worktree-first (would silently override a deliberate checkout); worktree-only (regresses the #535 behavior).
- **`git -C <root> branch --show-current` for the new helper (vs `rev-parse --abbrev-ref HEAD`).**
  Why: `--show-current` prints empty on detached HEAD — a clean `None` mapping without the `"HEAD"` string sentinel the existing helper needs. Source: #824 spec + git ≥2.22 docs. Alternative: reuse the `rev-parse` form with `-C` — functionally equivalent; rejected only for the cleaner detached semantics.
- **WARN-and-continue pushed-branch guard.** See the one-paragraph justification in §4.2. Source: #824 constraint (three options offered; middle chosen). Alternatives: fail-loud (new flakiness source on the dispatch path), keep-INFO (too quiet for the #812 failure class).
- **Lane gating kept at `{"auto", "gcp"}`.** Why: only GCP honors `repo_branch` at clone time; explicit SLURM would refuse; explicit RunPod syncs via pod lifecycle. Source: #535 r6 original design + #653 r8. Alternative (add explicit runpod) rejected: out of the minimal-diff scope and changes explicit-lane semantics.
- **Guard scoped to the new rung only; `_issue_worktree_git_root` called twice.** Why: minimal diff — no behavior change to the tested #535 rung, no restructure of `_launch_extra_from_args`; the helper is a cheap `Path.exists()`. Source: #824 minimal-diff constraint. Alternatives (guard on both rungs, hoisted call) listed as allowed deviations in §9.
- **New tests monkeypatch the seams rather than building real git fixtures.** Why: the file's established convention (#685 tests already monkeypatch `_issue_worktree_git_root` at lines 1623-1719); keeps the suite fast and hermetic. Source: read from `tests/test_dispatch_issue_cli.py`. Alternative (tmp git repos) allowed as an optional extra unit test for `_git_branch_of` only.
