### (a) Fail-loud when `--map-files` is combined with `--json`

**File:** `scripts/select_step9c_tests.py` — inside `main()`, immediately after
`args = parser.parse_args(argv)` at L1620 (BEFORE the work-root resolution at L1622-1634 —
argparse-invariant validation should not require a git checkout).

**Sketch:**

```python
     args = parser.parse_args(argv)

+    # (a) fail-loud on --map-files + --json: mapping mode emits TSV (one
+    # `<test>\t<matched_path>` line per pair) and the only consumers today
+    # (.claude/agents/implementer.md L174; the Step 10d TG legs' `sort -u`)
+    # are TSV-shaped. Silently ignoring --json here has cost a live session a
+    # wasted turn (#1717 defect (a)). The gate must fail CLOSED — parser.error
+    # exits 2 and prints to stderr, no diagnostic on stdout so consumers that
+    # tolerate exit 2 (they should not) still get no corrupted JSON.
+    if args.map_files is not None and args.json:
+        parser.error(
+            "--json is not supported with --map-files (mapping mode emits TSV: "
+            "'<test>\\t<matched_path>' per line)"
+        )
+
     try:
         work_root = _resolve_work_root(args.repo_root)
```

**User-facing error (argparse formats it as `select_step9c_tests.py: error: <message>` on
stderr, exits 2):**

> `--json is not supported with --map-files (mapping mode emits TSV: '<test>\t<matched_path>' per line)`

**Note on exit code:** `parser.error` exits **2**, not 1. This is the argparse convention
for CLI usage errors, distinct from the map-files load error (exit 1) and consistent with
the existing #1613 zero-resolution exit 2. The mapping mode's LOAD-BEARING contracts
(empty stdout + exit 0 skip signal; exit 1 unreadable; exit 2 zero-resolution) all remain
reachable from a WELL-FORMED invocation — the new exit-2 fires only on an invocation the
body proves has no callers today.

## 11. Decision Rationale

One entry per design pick in the plan.

- **What:** (a) uses `parser.error` (exits 2 via argparse) rather than a print + rc 1.
  **Why:** matches argparse's usage-error convention; distinguishes CLI misuse from a
  runtime failure (rc 1 stays reserved for map-files load errors). **Source:** N/A — no
  load-bearing hyperparameters; convention from the existing `#1613` exit-2 usage error
  at `_zero_resolution_guard` and from `scripts/select_step9c_tests.py`'s existing exit
  discipline (exit 1 unreadable / exit 2 usage / exit 0 skip-signal).

- **What:** (a) validation runs BEFORE `_resolve_work_root` (i.e. at L1620, not inside the
  map-files branch at L1644). **Why:** an argparse-invariant validation should not fail
  loud with a "cannot resolve work root" error just because the caller made a CLI mistake
  AND ran from outside a git checkout. **Source:** N/A — no hyperparameter; standard
  argparse layering (parse → validate → work).

- **What:** (b) help-text warning + implementer.md recipe correction; NO `--json-only`
  flag. **Why:** stderr is load-bearing diagnostic; a flag encourages callers to silence
  it. Recipe fix + help-text warning is the smaller, safer change that hits the exact
