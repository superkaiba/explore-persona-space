## 11. Decision Rationale (one entry per load-bearing design choice)

1. **Evidence mechanism = workload-written file sentinel, existence-checked in the trap.** *Why:* the trap runs in-guest so a local file is readable with zero network dependency; only the workload knows the internal boundary "deliverables verified / finalize begins". *Source:* the #657 route-on-artifact rule (`gotchas.md`) + trap mechanics gcp.py:2043-2061. *Alternatives rejected:* (a) renderer-appended `cmd && touch …` — never fires when needed (touch runs only on rc==0, when the trap is idle); (b) in-VM re-run of the artifacts declaration — the declaration lives in the VM-side sidecar/handle, not on the instance, and would add an HF listing inside the billing-critical trap; (c) an extra guest attribute `eps/deliverables_ok` — redundant with the phase value itself.
2. **Guest-phase literal `finalize_failed_artifacts_ok`.** *Why:* the Goal names it; distinct from `done`/`failed`/`wedged`; value-agnostic PUT proven by `wedged`. *Source:* Task #1055 Goal; gcp.py:1355-1378.
3. **Poll classification `status="done"` + `current_phase="workload_done_finalize_failed"`.** *Why:* mirrors #935's consumption end-to-end for free — poller terminal-success, boot-streak reset (`status=="done"` generic, backend_poll.py:1096-1103), failover excluded (both conjuncts fail), finalize via `--skip-confirm-artifacts`, Step 8 re-verify as defense-in-depth. A distinct `current_phase` keeps the finalize failure visible for triage. *Source:* gcp.py:4835-4848 (#935); backend_poll.py:566-640; dispatch_issue.py:1674-1749. *Alternative rejected:* a new `terminal_*` dead phase excluded from `_GCP_ASYNC_FAILOVER_PHASES` — would still route the ordinary dead path (`failure_class` → blocked/crash-fix), re-creating the manual diagnosis cycle the Goal targets.
4. **Add to `_TERMINAL_GUEST_PHASES` (not a new constant).** *Why:* janitor reap of a RUNNING VM stuck in this phase IS desired (finished zombie); the `wedged` carve-out comment (gcp.py:3104) excluded `wedged` only to avoid changing janitor behavior in that fix — the opposite of our intent. Zombie sets + #632 invariant then hold by construction. *Source:* gcp.py:2944-2949, 3089-3111, 3854.
5. **Diagnostics still run; poweroff unchanged.** *Why:* the finalize failure itself needs `issue<N>_partial/` evidence (the #811 persist was killed — absence hurt); the poweroff bounds billing (#854 discipline: nothing may delay it — the sentinel check adds one stat, negligible). *Source:* compute-backend-failover.md Part A; gcp.py:2056-2061.
6. **Attempt-scoped sentinel path + boot-time `rm -f`.** *Why:* mirrors `sentinel_path_for` (gcp.py:804-814) for per-attempt freshness; the `rm -f` closes the manual-`instances start` re-boot case (same attempt_id + preserved disk). *Source:* gcp.py:793-815; #935 done-grace re-boot semantics.
7. **Fail-open adoption (no writer ⇒ today's behavior).** *Why:* #1004 coherence — a missing sentinel must never be interpreted; only positive evidence flips the classification. *Source:* commit dc9ab334b2 (#1004); task body "keep the two coherent".
