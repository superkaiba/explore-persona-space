**4.3 — `pending_check()` rewrite (lines 67–91).** Replace the single `dumpshape` with two tiers; extension decides which tier gates a big file:

```bash
pending_check() {
  [ -n "$mode" ] || return 0
  [ "${#files[@]}" -gt 0 ] || return 0
  # Two dump tiers (#1057):
  #   dump_strict — the original thresholds (cat / head/tail > MAX_LINES /
  #                 sed range > MAX_LINES or open-ended): gates log-shaped
  #                 files and big NON-code/doc files (status quo);
  #   dump_huge   — unbounded (cat, open-ended sed) or bounded > MAX_RANGE_LINES:
  #                 gates big code/doc files, so a bounded <= MAX_RANGE_LINES
  #                 range read of a large source file passes.
  local dump_strict=0 dump_huge=0
  case "$mode" in
    cat) dump_strict=1; dump_huge=1 ;;
    head | tail)
      if [ "${nlines:-0}" -gt "$MAX_LINES" ] 2>/dev/null; then dump_strict=1; fi
      if [ "${nlines:-0}" -gt "$MAX_RANGE_LINES" ] 2>/dev/null; then dump_huge=1; fi
      ;;
    sed)
      if [ "$sed_n" = 1 ] && [ "$sedrange_big" = 1 ]; then dump_strict=1; fi
      if [ "$sed_n" = 1 ] && [ "$sedrange_huge" = 1 ]; then dump_huge=1; fi
      ;;
  esac
  if [ "$dump_strict" = 0 ] && [ "$dump_huge" = 0 ]; then return 0; fi
  local f
  for f in "${files[@]}"; do
    f=${f#\'}; f=${f%\'}; f=${f#\"}; f=${f%\"}
    if [ "$dump_strict" = 1 ] && is_logish "$f"; then
      BLOCK_FILE="$f"; BLOCK_VERB="$mode"; BLOCK_KIND="logish"
      return 1
    fi
    if is_big "$f"; then
      if is_code_doc "$f"; then
        if [ "$dump_huge" = 1 ]; then
          BLOCK_FILE="$f"; BLOCK_VERB="$mode"; BLOCK_KIND="codedoc"
          return 1
        fi
      elif [ "$dump_strict" = 1 ]; then
        BLOCK_FILE="$f"; BLOCK_VERB="$mode"; BLOCK_KIND="big"
        return 1
      fi
    fi
  done
  return 0
}
```

Note `dump_strict` reproduces the old `dumpshape` semantics exactly, so `is_logish` targets and big non-code/doc targets are gated byte-identically to today.

## 11. Decision Rationale

1. **Predicate = range-tier gating scoped to a code/doc extension allow-list (combination of forks (a)+(b)).**
   **Why:** pure (a) permits unbounded `cat` of a 383 KB source file (~95K tokens — the dump class the hook exists to stop, and contradicts the repo's own ≤300-line-chunk read guidance); pure (b) permits line-bounded but byte-unbounded reads of wide-line record files (a 400-line slice of a big `events.jsonl` with multi-KB rows is a multi-MB dump — the exact anti-pattern CLAUDE.md's context-budget rules name). The combination is monotone relief: nothing currently allowed becomes blocked, and the only new allowance is byte-bounded in practice.
   **Source:** hook header contract (lines 2–30) + incident #986 + CLAUDE.md § Context hygiene / § Context budget ("never dump the full event log", "never `cat` a results JSON").
   **Alternatives rejected:** byte-estimate sampling (`head -c 65536 | wc -l` → est. bytes/line) — more precise but adds IO to a hot hook, a divide-by-zero/newline-free edge, and can newly false-positive on unrepresentative heads; the hook's stated bias (false positives worse than misses) favors the deterministic line cap.
2. **`MAX_RANGE_LINES = 2000`.**
   **Why:** covers the incident (301 lines) and the "read a 300-line function" use with ~6× headroom; byte-consistent with the hook's own dump threshold — repo source is ruff line-length=100 (`.claude/rules/code-style.md`), so a worst-case conforming 2000-line slice ≈ 202 KB < `MAX_BYTES=262144`, i.e. the relief never admits more bytes than the hook already tolerates for a just-under-256 KB file read whole.
   **Source:** `MAX_BYTES` constant (hook line 33) + ruff config; incident range size.
   **Alternatives:** 1000 (no byte rationale; halves legitimate reads), unlimited-bounded (admits `tail -n 99999` whole-file dumps), 3200 (256 KB ÷ 80 B/line — flimsier under long-line prose in `.md`).
3. **Extension set `{.py .sh .bash .md .yaml .yml .toml .tex .rs .ts .tsx .js .jsx}`; EXCLUDE `.json .jsonl .csv .txt` and everything unlisted.**
   **Why:** inclusion criterion = line-oriented source/doc/config where multi-KB single lines are anomalous; the Goal names `.py/.md/.sh/.yaml`, and `.yml/.toml/.tex` + the JS/TS/Rust family are the same class at zero cost (`.tex`: the Overleaf clone agents read; TS/JS: the dashboard). Exclusion criterion = record/minified/spool formats where line count ≠ byte bound (`.jsonl` = the `events.jsonl` hazard; `.json` = eval-results files that are jq-only per CLAUDE.md; `.txt` = the classic captured-output extension). Unlisted extensions keep the status quo — no new blocks.
   **Source:** Goal text; `is_logish`'s own jsonl comment (hook lines 40–42); CLAUDE.md § Context hygiene.
   **Alternatives:** Goal-minimal 4-extension set (needless re-edits later); adding `.txt` (rejected — spool risk); a deny-list-only design (rejected — unlisted future record formats would silently gain relief).
