### 3. Method delta (design decisions)

**D1 — alias ONLY `9b` → `9b-same`; no speculative entries.** `9b` is the only incident-backed legacy name with an unambiguous canonical target. Other prose step names without yaml ids (0c, 5c-bis, 6d.2, 8-bis, 10c, 10c-bis) are gate sub-steps whose EXIT recipes already carry explicit valid `--step` ids in SKILL.md (0b, 1, 2c, 4b, 5b, 6c, 7, 9a-bis, 10 — grep of all 25+ call sites); aliasing them would be guessing a target and would weaken the typo guard. The cheap history check the task authorizes is not available (helper refusals go to stderr only, never persisted in events), so no further enumeration is possible without transcript mining — not gold-plating this.

**D2 — normalize BEFORE validation; record the CANONICAL id everywhere.** `args.step` is rebound to the canonical id immediately after `parse_args`, so the yaml validation, `next_expected_step` lookup, `build_marker_body`, AND the Sagan `metadata` dict all see `9b-same` with one code change. The alias TARGET is itself re-validated against `by_id` — if `9b-same` is ever renamed in workflow.yaml, the alias falls through to the normal exit-2 refusal (with a near-miss hint) instead of silently posting a dead id. The alias is announced on stderr (`NOTE:`), not embedded in the marker — no marker-schema change.

**D3 — near-miss suggestion on refusal (constraint 2's optional item: INCLUDE).** ~4 lines of stdlib `difflib.get_close_matches(step, sorted(by_id), n=3, cutoff=0.6)`. It makes ANY future prose-name improvisation self-correcting at the call site (the orchestrator reads stderr and re-posts with the right id) — this is the cheapest durable answer to the "not silently swallowed" half for ids we did NOT anticipate. Exit code and the existing `is not in workflow.yaml` message text are unchanged (the existing test asserts that substring). Fact-checked note: `get_close_matches("9b", ids, cutoff=0.6)` returns [] (ratio 0.44) — the bare legacy id gets NO near-miss hint; only the alias map covers it, which is why D2's alias (not the suggestion) is the load-bearing fix for the known incident.

**D4 — SKILL.md: two one-paragraph inserts, no restructuring.** (a) Action region: one paragraph at the top of § Same-issue follow-up loop (after the four-entry-points intro paragraph, SKILL.md:~7698) stating the canonical `9b-same` id, the alias backstop, and the refusal duty — this kills the improvisation at its source (the prose name "Step 9b" sitting next to no canonical-id statement). (b) Doc region: one paragraph in the §5 helper block (after SKILL.md:11246) documenting the alias + the "nonzero exit = no record posted; correct and re-post" duty for every call site, not just the loop. The orchestrator-side swallow is prose-level behavior; prose + alias + suggestion is the proportionate fix — no mechanical wrapper, no new gate.
