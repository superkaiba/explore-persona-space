## 3. File paths + concrete diff

Proposed bullet text (implementer may refine wording, not substance):

```
- **numpy `argsort`/`sort` tie order is CPU-SIMD-kernel dependent (numpy 2.x
  dispatches x86-simd-sort by CPU feature: AVX-512 vs not) — a cross-machine
  identity gate that RECOMPUTES a top-k-by-count selection and asserts
  equality against a banked selection is machine-dependent by construction
  whenever counts TIE at the cap boundary.** It can pass on one machine and
  crash on another with byte-identical inputs and identical numpy versions
  (#1946: 5 boundary ties for 2 cap slots — VM PASS, GCE FAIL, both numpy
  2.2.6). RULE: treat the BANKED selection as authoritative (downstream fits
  were made on it) and gate re-verification with machine-independent
  SET-VALIDITY invariants — floor match, `len == min(cap, n_eligible)`, all
  banked >= floor, strictly-above-boundary items are a subset of the banked
  set, `n_above < cap` — logging the boundary tie structure; OR make the
  selection deterministic at creation time (`np.argsort(..., kind="stable")`
  plus an explicit secondary tie-break key). NEVER a recompute-equality
  assert over a ranked selection whose sort key can tie. Worked fix:
  `scripts/issue1946_sae_percontext.py` `_scan_and_gate` (commit
  `b9b7e7d982c9`). (Incident #1946, 2026-08-01.)
```
