## Requirement + acceptance criteria

**Requirement (task Goal):** when a /daily route-1 self-applied fix lands the
exact deliverable of an already-filed task (the commit credits the task id, or
the overlap is mechanically detectable), the /daily run closes/archives that
task in the same pass.

Acceptance criteria:

1. `.claude/skills/daily/SKILL.md` gains a route-1 closing-step sub-section
   covering: trigger conditions (candidate-nomination only), a BINDING
   full-coverage verification before any archive, the session-stop step
   ORDERED BEFORE the archive (with explicit stop-failure branches), the
   canonical archive command (`task.py set-status <id> archived --note ...`)
   followed by a status-stuck confirm (`task.py view <id> --json`), the
   record shape in `## Applied workflow improvements`, and the same-run
   ordering rule (drop the manifest item BEFORE the FIRST
   `daily_drive_filings.py` invocation; once any batch ran, use the
   archive path or re-invoke the driver over the full range — the
   `filed.jsonl` slug ledger makes re-runs safe).
2. The Route 1 numbered triage item references the new sub-section so the
   step is reachable from the apply recipe, not orphaned prose.
3. The ambiguity guard is explicit AND the triggers are labeled
   candidate-nomination only: triggers (a)/(b)/(c) NOMINATE a candidate task;
   the binding full-coverage verification is the SOLE archive license (run
   the task's named failing test / acceptance check when one exists, else
   confirm every element of the task's proposed change is present in
   `git show <sha>`); ambiguous/partial → leave the task open + log the
   possible overlap in `## Other problems & notes`. Never archive on a
   guess. (Token-overlap trigger (c) is known-noisy — ~21/24 false-positive
   on hot workflow files, #1735 — which is why it only nominates.)
4. Ordering is stop-first: (i) stop any spawned session mapped to the
   candidate task BEFORE archiving (a mid-boot session can flip the status
   back to an active value after the archive, recreating the wasted-spawn
   loop); (ii) stop fails or no session visible in `spawn_session.py list`
   → archive anyway and note the possibly-live session in the record (the
   watcher reconcile pass is the backstop); (iii) after archiving, confirm
   the terminal status stuck via `task.py view <id> --json`.
5. Status mutation goes through `task.py set-status` only (canonical API);
   never a hand-edit / hand-`git mv`.
6. `scripts/workflow_lint.py` (no-flags default run) shows no NEW failure
   attributable to the edited file vs the pre-edit baseline (the Step 10d
   pre-push gate's baseline-subtracted compare is the binding form); the
   Step 9c mapped-test selection passes.
