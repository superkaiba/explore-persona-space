# Plan v1 — daily-fix: flag ungated smoke/full variable pairs in review

**Task:** #1727 (`kind: infra`, `workflow: v1`, workflow-fix)
**Goal (verbatim from body):** Add a code-review check that every `*_smoke` / `*_full` variable pair in a dispatcher diff is gated on the same smoke predicate, so a smoke-scoped list can never ship as the production default.

## 3. Design

### 3.1 The new gate — `Step 0.70: Smoke-variable gating (any diff type; dispatchers with smoke/full pairs)`

Insert AFTER Step 0.69's Verdict-record line (`.claude/agents/code-reviewer.md` around L1080) and BEFORE Step 0.7 "Pre-diff gates never short-circuit the diff" (L1082). Keep the identical section-header shape, sub-check numbering, verdict-routing form, waiver form, and `N/A —` escape phrase as Step 0.69, so the new step reads as its natural next-of-kin.

**Trigger — does the diff contain a `*_smoke` / `*_full` variable pair?** Grep each dispatcher file in the diff for the pair:

```bash
grep -nE '^[[:space:]]*(local +)?[a-z_]+_smoke=' <each dispatcher .sh in diff>
grep -nE '^[[:space:]]*(local +)?[a-z_]+_full=' <each dispatcher .sh in diff>
```

The trigger fires when BOTH a `<name>_smoke=` and a sibling `<name>_full=` (with a common `<name>` stem) declaration are present in the same file. Not a trigger — a file with only one side, or no `_smoke`/`_full` pair: record `Step 0.70: N/A — diff carries no smoke/full variable pair` and proceed.

**Sub-check (1) — every `X="$X_smoke"` assignment is gated on `$SMOKE`.** For each stem `<name>` where BOTH `<name>_smoke=` and `<name>_full=` exist, find every subsequent assignment of the form `<name>="$<name>_smoke"` (or `<name>="$<name>_full"`) and verify ONE of:

- **(a) In-line SMOKE guard on the SAME variable.** The assignment is inside a `[ -n "$SMOKE" ] && <name>=...` / `[ -n "$SMOKE" ] && <name>="$<name>_smoke"` line, or an `if [ -n "$SMOKE" ]; then <name>=...; fi` block, or a `${SMOKE:+...}` expansion, or an equivalent parameter-expansion form that reads `$SMOKE` in the SAME command.
- **(b) Bidirectional pair.** The dispatcher assigns the FULL variant first (default) and then re-assigns the SMOKE variant behind a `$SMOKE` gate on the same variable (the two-line `<name>="$<name>_full"` followed by `[ -n "$SMOKE" ] && <name>="$<name>_smoke"` shape). This is the pattern #1689's `models` variable ALREADY had; the bug was that `conds` did not.
- An UNGATED `<name>="$<name>_smoke"` assignment (no `$SMOKE` read in the same command / block controlling the assignment) FAILs sub-check (1).

**Sub-check (2) — no orphaned `_full` variant.** If a `<name>_full=` variable is declared but no code path assigns it to the live `<name>` (checked via grep for `<name>="$<name>_full"` OR a subsequent bare `<name>=...<name>_full...` expansion), this is the same defect from the other side (silent scope collapse to the SMOKE default). Record as a sub-check (2) FAIL.

**Waiver form** (mirrors Step 0.69's `# PHASE_IDEMPOTENCY_EXEMPT:` waiver): `# SMOKE_VAR_UNGATED_EXEMPT: <reason ≥ 20 chars>` on the line above the ungated assignment. Credits PASS.

**Verdict routing — sub-check (1) or (2):**

- All stems pass or carry a valid waiver → PASS.
- Any UNGATED `X="$X_smoke"` assignment (sub-check 1 FAIL) OR any orphaned `_full` variant (sub-check 2 FAIL) → verdict FAIL with a single `Critical` issue tagged **`smoke-var-ungated`** (SUBSTANTIVE — never stripped by Step 5c-bis):

  > `epm:experiment-implementation v<n>`'s dispatcher `scripts/<file>` at
  > line `<L>` assigns `<var>="$<var>_smoke"` with no sibling `[ -n "$SMOKE" ]`
  > guard on the SAME variable. This silently ships the smoke-scoped list as
  > the production default — the #1689 shape (2026-07-26, session `5c5a89e8`):
  > `run_phase_capture` had `local conds="$conds_smoke"` with the `$SMOKE`
  > gate on `models` but never on `conds`, silently collapsing a 21-condition
  > lattice to 1 condition through eight implementer / review rounds. The
  > store path `analysis_tensors/issue_1689/store/Qwen_Qwen2.5-7B/assistant_naturalistic/L14.pt`
  > was never written because the condition was never captured. Re-post
  > `v<n+1>` gating the assignment on `$SMOKE` (either `[ -n "$SMOKE" ] &&
  > <var>="$<var>_smoke"`, or the bidirectional default-full-then-smoke-gate
  > pattern `models` already uses in the same phase), OR add a waiver
  > `# SMOKE_VAR_UNGATED_EXEMPT: <reason ≥ 20c>` naming why the smoke value
  > IS the intended production default.

Record the verdict as one line: `Step 0.70: PASS — <N> smoke/full pairs correctly gated`, `Step 0.70: FAIL — <var> ungated at <file>:<L>`, or `Step 0.70: N/A — diff carries no smoke/full variable pair`.

**Fingerprint-of-degradation clause** (mirrors Step 0.69 § Fingerprint-of-degradation): the gate reads only bash source; a Python dispatcher whose smoke gating lives in `args.smoke` (not shell-visible) is out of scope for v1 — record `Step 0.70: N/A — python dispatcher; smoke gating is arg-level`. A follow-up round can widen to python dispatchers if the same class recurs there.

- **False positive on a legitimate `_smoke`-only pattern.** Very rare in this codebase (a manual grep across `scripts/*dispatch*.sh` finds only ~3 files carrying `_smoke`/`_full` pairs, all bidirectional-guarded). The waiver form covers the remaining case.
- **The gate cannot detect a python dispatcher whose smoke gating is `args.smoke`-driven.** Named as an explicit N/A in the fingerprint-of-degradation clause; a follow-up round widens to python if the class recurs there.
- **The gate operates on the diff, not on trunk.** A pre-existing ungated assignment in a file the diff does NOT touch is invisible. Acceptable — this matches Step 0.69's diff-scoped behavior.
- **Blast radius if wrong.** Text-only additions to two agent specs + one bullet to gotchas.md. No code execution touched; no runtime behavior changed. Trivial single-commit revert (`git revert <sha>` in a scratch worktree).
