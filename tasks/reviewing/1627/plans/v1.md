## 5. Kill criteria (what would make this change wrong)

- **Probe self-match:** if any inserted probe pattern matches the probing call's own shell, the guard deadlocks every launch. Guarded three ways: bracket-token in every pattern, the explicit "separate FOREGROUND call — never inside the launch call" rule (the launch call's argv DOES carry the unbracketed junit path), and the pin test's negative assert on the unbracketed form. If a probe still self-matches in practice → the pattern is wrong; fix or revert.
- **Foreign-match starvation:** if the probe matches a process that is NOT this issue's gate and never exits, launches starve. The 9c/10d(i/ii)/form-(iii)-alt-1 patterns are `<N>`-scoped (sibling issues can't match); form (iii)'s broad `workflow_lint[.]py` alternative is WAIT-not-kill and bounded (lint legs carry 900s timeouts). If a legitimately-idle system shows persistent matches → the pattern is too broad; revert/narrow.
- **Blocking a legitimate fresh launch after a crash:** a crashed gate that left NO live pid returns an empty probe → launch proceeds unhindered. If the guard were ever observed blocking a pid-less fresh launch, the design is broken → revert.
- **Contradiction with the recovery arms:** the recovery arms (post-completion-signal, missing rc/verdict) prescribe kill-before-relaunch; the pre-launch probe prescribes wait-by-default. The shared statement delineates them (wait while the run has no completion signal; kill only provably-orphaned/wedged-past-bound). If reviewers find a path where both instructions bind simultaneously with opposite prescriptions, the statement wording must be fixed before landing.
