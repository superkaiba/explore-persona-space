### 4a. Change to `scripts/guard_repo_root_branch.sh`

**Insertion 1 — sidecar config + helpers, immediately after line 536 (`REPO_BASE=…`), before the stdin parse at 538.** Describe-by-reference pseudocode (final shell to be refined by the implementer; no gated-command literals appear in the added code — only field names and the sed/tr recipes):

```sh
# --- deny-event sidecar (#1528) -------------------------------------------
# Best-effort forensic record of every deny: one JSON row appended to
# EPM_GUARD_DENY_SIDECAR (default $REPO/.claude/cache/guard-deny-events.jsonl).
# NEVER affects the deny/allow decision, exit codes, or the stderr message —
# every failure (missing dir, unwritable path, disk full) is swallowed.
# No full command text: bounded printable-ASCII redacted heads only (#1501 A-11).
DENY_SIDECAR="${EPM_GUARD_DENY_SIDECAR:-$REPO/.claude/cache/guard-deny-events.jsonl}"

_deny_head() {  # stdin -> control chars to space, printable ASCII only,
                # first 120 chars, opaque runs >=20 masked to 4-char prefix + ***
  tr '\n\r\t' '   ' | tr -cd ' -~' | cut -c1-120 \
    | sed -E 's/([A-Za-z0-9_-]{4})[A-Za-z0-9_-]{16,}/\1***/g'
}

log_deny() {  # $1 = arm label ($blocked), $2 = full command, $3 = blocking clause
  {
    mkdir -p "$(dirname "$DENY_SIDECAR")"
    jq -cn --arg ts "$(date -u +%FT%TZ)" --arg arm "$1" --argjson len "${#2}" \
       --arg head "$(printf '%s' "$2" | _deny_head)" \
       --arg clause_head "$(printf '%s' "$3" | _deny_head)" \
       '{ts:$ts, guard:"repo_root_branch", arm:$arm, len:$len,
         head:$head, clause_head:$clause_head}' >> "$DENY_SIDECAR"
  } 2>/dev/null || true
}
```

**Insertion 2 — one call at the single deny site**, between the `BLOCKED:` echo (~line 1500) and `exit 2` (line 1511):

```sh
log_deny "$blocked" "$cmd" "${clause:-}"
exit 2
```

Ordering rationale: the stderr deny message is fully emitted BEFORE the append runs, so no sidecar failure mode can suppress or garble the user-visible deny. `${clause:-}` is `set -u`-safe (the `while … done < <(split_and_label "$cmd")` loop at ~1489–1492 runs in the current shell — process-substitution redirect, not a pipeline — so `$clause` persists after `break`; the default guards the unreachable-unset case). Redaction is applied only when a deny fires — zero added work on the allow path, which runs on every Bash PreToolUse.

**Insertion 3 — contract documentation**: extend the guard's header contract comment block (~lines 81–86 region) with 2–3 lines documenting the sidecar (path, env override, best-effort semantics, row schema). In-file docs only; no CLAUDE.md / rules edits this round (an investigator of guard false positives opens the guard script first, and the /daily transcript sweep will hit the sidecar path by grep).

**Row schema** (one flat JSON object per line):

| Field | Value | Notes |
|---|---|---|
| `ts` | `date -u +%FT%TZ` | UTC ISO-8601, matches Python-sidecar convention |
| `guard` | `"repo_root_branch"` constant | makes the schema shared-ready for sibling guards without a shared helper |
| `arm` | `$blocked` verbatim | the matched detector arm (jq `--arg`-escaped) |
| `len` | `${#cmd}` | full-command length in characters as counted by bash (`--argjson`, guaranteed integer) |
| `head` | redacted first ≤120 printable-ASCII chars of `$cmd` | see recipe below |
| `clause_head` | redacted first ≤120 printable-ASCII chars of the blocking `$clause` | the clause that tripped `classify_clause` — closes most of the attribution gap the deferred check-id field leaves (a heredoc-body false-block shows its `cat <<EOF …` / interpreter-stdin opening here even when the whole-command head is elsewhere in a long compound) |

**Redaction recipe** (`_deny_head`): (1) map `\n\r\t` → space; (2) strip to printable ASCII (`tr -cd ' -~'`) — sidesteps byte-vs-char truncation and invalid-UTF-8-in-jq edge cases entirely; (3) truncate to 120 chars; (4) mask every `[A-Za-z0-9_-]` run of ≥20 chars down to its first 4 chars + `***`. Step 4 covers the four `SECRET_PATTERNS` token shapes by construction (single opaque runs ≥33 chars; 4 retained chars of such a secret are non-recoverable) plus long SHAs/tokens generally; the slack-webhook URL shape is covered at real-world token lengths but not regex-guaranteed (§2 Secret-shape precedent). Cost: some long benign identifiers (e.g. `explore-persona-space`, 21 chars) also mask to `expl***` — acceptable; verbs, flags, and structure stay legible, which is what attribution needs.

**Refusal-ladder check id — DEFERRED (option b)**, one-line reason carried in §11: the guard has exactly one deny path (everything flows through `classify_clause` → `$blocked`; the waiver ladder only waives or falls through), so no per-check id is derivable at the deny site without threading a `deny_context` variable through ~10 fail-closed waiver/strip branch points of a 1511-line guard — high regression risk for marginal gain, and the new `clause_head` field recovers most of that attribution signal (JSONL rows are self-describing, so a later `check` key is a backward-compatible addition).

**Sibling guards (`guard_repo_root_pull.sh`, `.claude/hooks/guard_piped_git_push.sh`, `guard_harmful_bank_read.sh`, `guard_log_dump.sh`, `guard_tmp_tmux_sweep.sh`, `guard_root_code_commit.sh`, `guard_lessons_edit.sh`) — DEFERRED.** Tradeoff: a shared sourced helper would deduplicate ~15 lines but adds a cross-file dependency to fail-closed hooks (each would need its own fail-soft handling for a missing/renamed helper, and `.claude/hooks/` vs `scripts/` sourcing is brittle across worktrees); the sibling hooks also have heterogeneous deny shapes (some inline in settings.json). The `guard` field in the row schema lets any sibling adopt the same sidecar + schema later by copying the small function. If wanted, that is its own workflow-fix filing (distinct fingerprint per the #678 dedup grain). Bias to minimal single-file scope for this round.

**Rotation/size — no rotation in v1**, position stated: denies are rare (the guard allows on the hot path; a deny is an exception event), each row ≤ ~400 bytes, so even 100 denies/day ≈ 15 MB/year — under the tolerated `disk-guard-events.jsonl` precedent (8.5 MB, unbounded, swept only by disk-pressure tiers). The file is gitignored (`.gitignore:81`), so no repo growth either.

## 11. Decision Rationale

- **Head bound = 120 chars.** Why: enough to capture verb + flags + the clause opening for incident-class attribution; small enough to bound trigger-density and secret exposure. Source: task body's own `~120-char redacted head` suggestion (#1528 body, `## Workflow gap`); not perf-critical, insensitive within 2×. Alternatives: 80 (loses compound context), 200 (more secret/trigger surface, no attribution gain).
- **Redaction recipe = printable-ASCII strip + 120-char truncate + mask `[A-Za-z0-9_-]{20,}` runs to 4-char prefix + `***`.** Why: the mask strictly supersets every `SECRET_PATTERNS` shape while keeping command structure legible; ASCII-only sidesteps byte-vs-char truncation and invalid-UTF-8-in-jq edges. Source: `scripts/check_no_secret_shaped_strings.py:45–57` (all secret bodies are single opaque runs ≥ ~36 chars ⇒ the 20-char threshold covers them with margin). ASCII `***` mask chars chosen over `…` to dodge the Edit-tool Unicode-literal gotcha (`.claude/rules/gotchas.md`). Alternatives: named secret-prefix sed list (fragile, drifts from the Python source of truth); truncation-only (leaks env-assignment secrets in the first 120 chars); char-class allowlist stripping all digits/letters (destroys attribution value).
- **JSON producer = `jq -cn --arg`/`--argjson`, no printf fallback.** Why: structural escaping (arm labels carry spaces/parens; heads carry arbitrary shell text); jq is guaranteed present at every deny by the line-538 gate, so a fallback is dead code. Source: `guard_repo_root_branch.sh:538`; `.claude/settings.json` jq-in-hooks precedent (lines 26/79/83/111). Alternatives: pure printf + allowlist (rejected: hand-rolled JSON escaping is the injection risk itself); python one-liner (heavier spawn, adds a `uv` dependency to a hook).
- **Check-id field = deferred (option b).** Why: single deny path — every deny is a `classify_clause` arm; the waiver ladder waives or falls through, never denies, so no check id is derivable at the deny site without threading state through ~10 fail-closed branch points (regression risk on a 1511-line guard ≫ attribution gain). The added `clause_head` field recovers most of the intended signal (a heredoc/compound false-block is visible from the blocking clause's opening). JSONL is schema-open: a later `check` key is backward-compatible. Source: read of the driver loop (~1470–1492) + clarifier finding; the brief's option (b) authorization.
- **`clause_head` field added (small superset of the Goal's field list).** Why: the Goal's `head` alone under-attributes long compounds (the blocking clause may sit past char 120); `$clause` is free at the deny site. Same bound + redaction as `head`. Source: this session's live deny (the blocking clause was a mid-command grep literal, not the command opening).
