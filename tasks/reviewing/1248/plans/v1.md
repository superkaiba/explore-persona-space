### 4.1 New module-level constants (after `_FILED_TASK_RE`, line 96)

`wf_fix_fingerprint` output is `sha256(...).hexdigest()[:12]` (task_workflow.py:1016–1029) → exactly 12 lowercase hex chars.

```python
# wf_fix_fingerprint output shape: sha256 hexdigest[:12] -> 12 lowercase hex chars.
_FP_SHAPE_RE = re.compile(r"[0-9a-f]{12}")
# A note-form record fingerprint FIELD carrying a real fp (not 'n/a (prose park)').
# The trailing lookahead rejects a >=13-hex token matching on its first 12 chars.
_RECORD_FP_RE = re.compile(r"fingerprint:\s*([0-9a-f]{12})(?![0-9a-f])")
```

### 4.2 Extracted helpers (shared by both branches; behavior-preserving for the fp-less branch)

```python
def _record_origin_raw(record: dict) -> str | None:
    """The record's origin_candidate_ts RAW string (note regex first, then structured key).

    Returns None only when the field is ABSENT on both surfaces; callers parse,
    preserving the existing absent-vs-unparseable distinction (an unparseable
    ts is a non-match, NOT a fall-through to the legacy target_file key).
    """
    note = str(record.get("note") or "")
    om = _ORIGIN_TS_RE.search(note)
    if om:
        return om.group(1)
    if record.get("origin_candidate_ts"):
        return str(record["origin_candidate_ts"])
    return None


def _record_target_file(record: dict) -> str | None:
    """The record's target_file (structured key first, then note regex), or None."""
    rec_tf = record.get("target_file")
    if rec_tf:
        return str(rec_tf)
    note = str(record.get("note") or "")
    tm = _TARGET_FILE_RE.search(note)
    return tm.group(1).rstrip(".,;:!?") if tm else None
```

(Extraction order matches the current inline code exactly: `_ORIGIN_TS_RE` note-search before the structured key at lines 229–233; `record.get("target_file")` before the note regex at lines 240–243.)

### 4.3 The widened predicate (replaces `_filed_record_matches`, lines 218–244)

```python
def _filed_record_matches(cand: Candidate, record: dict) -> bool:
    """Does this same-stream filed record close this candidate? (suppression rule 1)."""
    note = str(record.get("note") or "")
    if cand.fingerprint is not None:
        # fp-aware: the candidate's own fingerprint suppresses.
        if cand.fingerprint in note:
            return True
        if cand.fingerprint in str(record.get("fingerprint") or ""):
            return True
        # A record declaring a DIFFERENT real (12-hex) fp is a DIFFERENT bug
        # (workflow-fix-on-bug.md § Dedup) -> never suppress on it.
        if _RECORD_FP_RE.search(note) or _FP_SHAPE_RE.fullmatch(
            str(record.get("fingerprint") or "")
        ):
            return False
        # #1248 widening: a record with NO usable fp — field absent, or
        # non-fp-shaped ('n/a (prose park)') — cannot DISAGREE on fingerprint;
        # key on origin_candidate_ts (row-level, as precise as the fp), with a
        # target_file compatibility veto for same-second sibling rows. Every
        # failure below returns False (re-enumeration), never false suppression.
        origin_raw = _record_origin_raw(record)
        if origin_raw is None:
            return False  # no row-level key; NO file-only fallback for fp candidates
        origin_dt = parse_ts(origin_raw)
        if origin_dt is None or origin_dt != cand.ts:
            return False
        rec_tf = _record_target_file(record)
        if (
            cand.target_file
            and rec_tf
            and not (cand.target_file.startswith(rec_tf) or rec_tf.startswith(cand.target_file))
        ):
            return False
        return True
    # fp-less (prose park): PRIMARY key = origin_candidate_ts equality. (unchanged)
    origin_raw = _record_origin_raw(record)
    if origin_raw is not None:
        origin_dt = parse_ts(origin_raw)
        return origin_dt is not None and origin_dt == cand.ts
    # Legacy record with NO origin_candidate_ts: fall back to target_file match.
    if not cand.target_file:
        return False
    return _record_target_file(record) == cand.target_file
```

### 4.4 The target_file belt-and-suspenders decision (stated, as required)

**Decision: include it, in PREFIX-compatibility (veto) form, not strict equality.**

- **Strict equality is ruled out by the evidence itself:** the #880 candidate's `target_file` (from `block_field("target_file")`, which captures the FULL line: `scripts/issue667_extract.py (and _device()-style descendants — NOTE: ...)`) differs from the record's note-form extraction via `_TARGET_FILE_RE = re.compile(r"target_file:\s*([^\s,;]+)")`, which stops at the first whitespace → `scripts/issue667_extract.py`. Strict equality would false-NEGATIVE one of the three motivating shapes.
- **ts-only (no tf check) was rejected** because its residual false-suppression edge fails in the WRONG direction: two distinct candidate rows sharing one ts second in the same stream (plausible when an orchestrator posts several parked candidates in a loop) would BOTH be suppressed by one n/a-fp record — a permanent silent drop, worse than the status-quo re-enumeration. The existing fp-less branch does use ts-only, but there the candidate has no fp to protect; here we have both fields available, so use them.
- **Prefix compatibility** (`cand_tf.startswith(rec_tf) or rec_tf.startswith(cand_tf)`) suppresses all three evidence shapes (#815/#917 exact-equal; #880 record-tf-is-a-prefix-of-candidate-tf) while vetoing a same-second record for a different file. When EITHER side lacks a target_file, the veto abstains (ts equality alone decides) — records from Step C always carry `target_file:`, so abstention is a legacy-shape allowance, not the common path.

**Also preserved:** for fp-computable candidates there is deliberately NO target_file-ONLY fallback (unlike the fp-less legacy branch) — a record with neither a usable fp nor an `origin_candidate_ts` never suppresses an fp candidate on file match alone (the #622 distinct-bug-on-a-hot-file hazard).

## 11. Decision Rationale

Non-hyperparameter design decisions (each grounded in-repo):
- **12-hex fp-shape test** — What: `[0-9a-f]{12}` fullmatch / `(?![0-9a-f])`-guarded note regex. Why: `wf_fix_fingerprint` returns `sha256(...).hexdigest()[:12]` (Source: `src/explore_persona_space/task_workflow.py:1016–1029`, read this session). Alternative rejected: parsing the `n/a (prose park)` field value with a `/`-delimited regex — the value itself contains `/`, making field-value extraction fragile; testing for a REAL fp is shape-anchored and sufficient.
- **ts key precision** — Why: SKILL.md Step C posts `origin_candidate_ts: <c.ts>` verbatim from the sweep's own output (Source: `.claude/skills/daily/SKILL.md:340,352`), so equality against `cand.ts` is row-exact; `parse_ts` normalizes both to aware-UTC (script lines 99–115).
- **tf prefix veto over strict equality / ts-only** — see §4.4 (Source: the #880 record shape read this session).
- **Fail-direction invariant** — every new failure path returns False (re-enumeration ≈ tonight's status quo, cost = one re-triage), never True (false suppression = permanent silent drop). This asymmetry is why the widening is safe to ship without a gate.
