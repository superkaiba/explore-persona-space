# Plan v2 — task #1925: pre-commit hook for agent-memory index size

architectural: false

## Plan Summary

Add a `.pre-commit-config.yaml` local hook running
`workflow_lint.py --check-agent-memory-index-size` so direct-to-main
memory-save commits are gated at commit time, plus a hook-coverage pin test —
exact parity with the #1661 agent-spec sibling hook
(`workflow-lint-agent-spec-size`). Workflow-surface only, 0 GPU-h,
non-architectural (adds a guardrail hook; no public-contract change).

## Requirement + acceptance criteria

**Requirement (from the task Goal):** direct-to-main commits touching any
`.claude/agent-memory/*/MEMORY.md` (the primary regrowth channel for the
#1891 size-budget class) — or the lint itself — must run
`--check-agent-memory-index-size` locally at commit time. Today the check
fires only at worktree-mediated gates (Step 9c / Step 10d lint gate), so a
root-side memory append can push an index past the 24,000-byte FAIL threshold
with no local signal.

Acceptance criteria:

1. `.pre-commit-config.yaml` carries a local hook whose `entry` runs
   `uv run python scripts/workflow_lint.py --check-agent-memory-index-size`,
   with `pass_filenames: false`, `language: system`, and a `files:` regex
   covering BOTH `.claude/agent-memory/*/MEMORY.md` AND
   `scripts/workflow_lint.py` (threshold edits move the verdict — same
   rationale as the agent-spec sibling).
2. The hook is scoped (files regex), NOT `always_run` — high-frequency
   automated task-state commits (`tasks/**`, `eval_results/**`) never match,
   so fleet commit latency is unchanged (the `stages: [manual]` NOTE in the
   config covers mutating hooks only; this is a read-only sub-second check and
   stays on the default commit stage, exactly like `workflow-lint-agent-spec-size`).
3. A hook-coverage pin test exists in
   `tests/test_workflow_lint_agent_memory_index_size.py` (the #1891 check's
   own test file), modeled on
   `tests/test_workflow_lint_agent_spec_size.py::test_precommit_hook_covers_agent_spec_size`:
   parse `.pre-commit-config.yaml` with `yaml.safe_load`, assert a local hook
   with `--check-agent-memory-index-size` in its `entry`, and assert its
   `files:` regex matches both a representative
   `.claude/agent-memory/<agent>/MEMORY.md` path and
   `scripts/workflow_lint.py`.
4. `workflow_lint.py --check-references` passes after the change (task
   constraint) and the touched-scope Step 9c gate shows no NEW failures vs
   the known-red-on-main baseline (step9c compare).

## Method delta (what differs from prior related work)

Pure parity leg of #1891 (which landed the check + curation) modeled
byte-for-byte on #1661's `workflow-lint-agent-spec-size` hook stanza + pin
test. Nothing novel: one YAML stanza + one pin test. The only judgment call is
the `files:` regex shape — use
`^(\.claude/agent-memory/[^/]+/MEMORY\.md|scripts/workflow_lint\.py)$`
(anchored, single-level agent dir, matching how the check itself globs
`*/MEMORY.md` non-recursively).

   ```yaml
        name: "workflow_lint: agent-memory index size — WARN >20KB, FAIL >24KB (#1891)"
        entry: uv run python scripts/workflow_lint.py --check-agent-memory-index-size
        language: system
        # Fire when any agent-memory INDEX changes (direct-to-main memory-save

        files: ^(\.claude/agent-memory/[^/]+/MEMORY\.md|scripts/workflow_lint\.py)$
   ```

   ```python
   def test_precommit_hook_covers_agent_memory_index_size() -> None:
       cfg = yaml.safe_load((_REPO_ROOT / ".pre-commit-config.yaml").read_text(encoding="utf-8"))
       local_hooks = [h for repo in cfg["repos"] if repo["repo"] == "local" for h in repo["hooks"]]
       matching = [h for h in local_hooks if "--check-agent-memory-index-size" in h.get("entry", "")]
       assert matching, "no pre-commit hook runs --check-agent-memory-index-size (#1925)"
       pat = re.compile(matching[0]["files"])

       assert pat.search("scripts/workflow_lint.py")
       assert not pat.search(".claude/agent-memory/analyzer/feedback_foo.md")
       assert matching[0].get("pass_filenames") is False
   ```
