## 2. Prior work / method delta

- **LOCO variants on `main` are partition-invariant by construction:** `fit_batched_loco_mlp` (line 274-276) and `fit_batched_loco_mlp_multihead` (line 445-447) draw ONE shared n-fold init block (`torch.manual_seed(seed)` → n per-FOLD inits) reused identically by every group — a group's init doesn't depend on which other groups share the call. `assert_matches_reference` (line 700-780) already asserts **(b) chunk-invariance BIT-identical** and **(c) cross-group non-contamination BIT-identical** (`np.array_equal`, CPU) for that path — the empirical precedent that batched bmm/mean ops on CPU are bit-stable across batch composition at gate scale.
- **The split variant differs** because each group deliberately gets its OWN init (groups have different data/targets, unlike LOCO folds of one problem), and the branch implementation keyed that init to batch position — the bug class.
- **Standard practice:** per-member deterministic seeding in `torch.func.stack_module_state`-style ensembles is done by seeding each member's construction from a stable member identity (per-member `torch.manual_seed` / per-member `torch.Generator`), because `nn.Linear.reset_parameters` draws `kaiming_uniform_` + bias `uniform_` from the **global** RNG with no generator threading (verified against the module-construction path; `torch.nn.init` functions accept `generator=` in modern torch, but `nn.Module` construction never passes one). Deriving per-member seeds from identity keys via an **unsalted** cryptographic hash is the standard replacement for Python's builtin `hash()` (salted per process via `PYTHONHASHSEED` → non-reproducible across runs). This is repo-adjacent precedent, not novel methodology; no literature grounding is required (`kind: infra`).

### 3.2 Seeding mechanism — Decision: per-group `torch.manual_seed` from a stable blake2b of `(seed, key)`

New module-level helper (public, shared by the fit, the serial-reference gate, and tests):

```python
import hashlib  # add at module top, in the same edit as first usage (PostToolUse-ruff F401)

def split_group_init_seed(seed: int, key: tuple) -> int:
    """Stable per-group init seed for ``fit_batched_split_mlp``: unsalted blake2b
    of ``f"{seed}|{key!r}"`` reduced to [0, 2**63). Depends ONLY on (seed, key) —
    never on batch position, chunking, ordering, process, or platform — so any
    partition of a group list reproduces each group's init bit-exactly (#926).
    Key elements must be Python primitives (str/int/float/bool/None, or tuples
    thereof): ``repr(key)`` is the identity. Python's builtin ``hash()`` is
    salted per process (PYTHONHASHSEED) and MUST NOT replace this.
    """
    payload = f"{int(seed)}|{key!r}".encode()
    return int.from_bytes(hashlib.blake2b(payload, digest_size=8).digest(), "big") % (2**63)
```

In `fit_batched_split_mlp`, replace lines 856-857 of the ported section:

```python
# OLD (batch-order seeding — the #926 bug):
#   torch.manual_seed(seed)
#   block_members = [_MLPMulti().to(dev) for _ in range(n_groups)]

# NEW: per-group init keyed to (seed, group.key) — partition/reorder-invariant.
# Inits are drawn on the CPU RNG (modules constructed on CPU, then .to(dev)),
# so init bytes are device-independent; each group's stream is fully consumed
# before the next group's manual_seed, so neighbors cannot perturb it.
assert len({repr(g.key) for g in groups}) == n_groups, (
    "duplicate (or repr-colliding) SplitMLPGroup.key in one call — keys must be "
    "unique; results are keyed by them and inits are seeded from them"
)
block_members = []
for g in groups:
    torch.manual_seed(split_group_init_seed(seed, g.key))
    block_members.append(_MLPMulti().to(dev))
bp, _bb = stack_module_state(block_members)
```

Why this shape and not the alternatives (full rationale in §11):
- It reuses `nn.Linear.reset_parameters` verbatim → zero init-distribution drift vs the branch code; the ONLY change is which stream each group draws from.
- A per-group `torch.Generator` would require reimplementing kaiming bounds by hand (`nn.Linear` init ignores generators) — more code, real drift risk.
- A caller-supplied absolute index adds API surface, breaks reorder-invariance, and moves the correctness burden to every caller.
- Global-RNG clobbering is status quo (the function already calls `torch.manual_seed`); no `fork_rng` wrapper — minimal diff, no new observable behavior beyond the fix.

```python
def assert_split_mlp_partition_invariant(
    seed: int = 0,
    n_train: int = 48,
    n_eval: int = 16,
    d: int = 12,
    p: int = 3,
    n_groups: int = 5,
    hidden: int = 32,
    max_epochs: int = 15,
) -> dict:
    """Assert fit_batched_split_mlp is PARTITION- and REORDER-invariant (#926).

    Builds ``n_groups`` synthetic groups with distinct keys/targets, then fits
    (A) all in ONE call at chunk_size=2, (B) a 2+3 partition (chunk-membership-
    ALIGNED with A: pure seeding-fix leg), (B') a 3+2 partition (boundary-
    MISALIGNED: chunk memberships differ from A), (C) all in REVERSED order,
    and (D) one full call at chunk_size=0 (no chunking — the cross-CHUNK-SIZE
    leg mirroring ``assert_matches_reference`` check (b)). Also asserts
    distinct keys derive distinct init seeds (anti-degeneracy). Asserts per-key
    ``preds_by_key`` and every ``params_by_key`` array (W1,b1,W2,b2,mu,sd)
    BIT-identical (``np.array_equal``) across all arms, each assert naming its
    arm so a failure report says WHICH arm broke (an aligned-partition failure
    = seeding bug; a reversed/nochunk-only failure = the anticipated kernel-
    stability class, §6 fallback territory). CPU-only, num_threads pinned.
    Returns the summary dict for the caller's log.
    """
    rng = np.random.default_rng(seed)
    groups = []
    for i in range(n_groups):
        X = rng.standard_normal((n_train + n_eval, d)).astype(np.float32)
        Y = (X @ rng.standard_normal((d, p)) * 0.05
             + 0.1 * rng.standard_normal((n_train + n_eval, p))).astype(np.float32)
        groups.append(SplitMLPGroup((f"g{i}",), X[:n_train], Y[:n_train], X[n_train:]))
    # Cross-key distinctness (reconciler mandatory-absorb, #926 critique r1): a
    # key-ignoring helper would make every invariance assert below vacuously true.
    seeds = {g.key: split_group_init_seed(658, g.key) for g in groups}
    assert len(set(seeds.values())) == len(groups), (
        "split_group_init_seed collapsed distinct keys to a shared seed"
    )
    kw = dict(seed=658, hidden=hidden, max_epochs=max_epochs, device="cpu",
              chunk_size=2, num_threads=8)  # thread count pinned: the asserted
    # bit-identity contract is environment-pinned, not ambient (stats-critic rec)
    full = fit_batched_split_mlp(groups, **kw)
    part_a = fit_batched_split_mlp(groups[:2], **kw)   # 2+3: seeding-fix leg
    part_b = fit_batched_split_mlp(groups[2:], **kw)
    mis_a = fit_batched_split_mlp(groups[:3], **kw)    # 3+2: boundary-MISALIGNED
    mis_b = fit_batched_split_mlp(groups[3:], **kw)    # chunk memberships differ
    rev = fit_batched_split_mlp(list(reversed(groups)), **kw)
    nochunk = fit_batched_split_mlp(groups, **{**kw, "chunk_size": 0})
    # ^ cross-CHUNK-SIZE leg (width 5 vs 2) — the split-variant sibling of the
    # LOCO gate's check (b) chunked-vs-nochunk comparison; certifies the
    # "group_chunk is a memory knob" contract (stats-critic Must-Fix, #926 r1).
    for g in groups:
        k = g.key
        split_res = part_a if k in part_a.preds_by_key else part_b
        mis_res = mis_a if k in mis_a.preds_by_key else mis_b
        for arm_name, arm in (("partition-2+3", split_res),
                              ("partition-3+2", mis_res),
                              ("reversed", rev),
                              ("nochunk", nochunk)):
            assert np.array_equal(full.preds_by_key[k], arm.preds_by_key[k]), (arm_name, k)
            for name in ("W1", "b1", "W2", "b2", "mu", "sd"):
                assert np.array_equal(full.params_by_key[k][name],
                                      arm.params_by_key[k][name]), (arm_name, k, name)
    return {"n_groups": n_groups, "partition_bit_identical": True,
            "reorder_bit_identical": True, "cross_chunk_bit_identical": True,
            "distinct_key_seeds": True}
```

## 6. Kill criteria

- **Trained-output bit-equality fails on CPU at test shapes** (batched GEMM/mean kernels choosing batch-size-dependent blocking): the INIT bit-equality stays a hard assert (guaranteed by construction — inits are drawn per-group from the CPU RNG before any batching); the TRAINED-output asserts downgrade to exact-tolerance `np.allclose(..., rtol=0, atol=1e-6)` and the docstring says "bit-identical inits; trained outputs equal to ≤1e-6 across partitions (CPU)". This is a documented allowed deviation (see §10), not a plan failure — but it must be reported in the implementer report NAMING WHICH ARM failed (an aligned-partition failure indicates a seeding bug — hard fail, NOT fallback territory; a reversed/misaligned/nochunk-only failure is the anticipated kernel-stability class), and the shipped docstring wording must match the realized outcome (bit-identical everywhere vs bit-identical inits + ≤1e-6 trained outputs). The LOCO precedent (gate checks (b)/(c) at `np.array_equal`) predicts bit-identity holds.
- **Cross-device bit-stability is out of scope by declaration:** the asserted contract is CPU (tests force `device="cpu"`, matching `assert_matches_reference`'s "Forces DEVICE=cpu"). Inits are device-independent (drawn on CPU, then `.to(dev)`); trained outputs on CUDA are deterministic per config but not asserted partition-invariant. If someone later needs a CUDA partition-invariance guarantee, that is a follow-up, not this task.
- **`repr(key)` proves unstable for real branch key types** (e.g. numpy scalar keys, whose repr changed across numpy 1→2): would force the fallback mechanism (caller-supplied absolute index). Checked as assumption 7; if the branch group-builders use numpy scalars in keys, the reconciliation note must flag it — the `main` contract documents primitive-only keys and the duplicate-repr assert fails loud rather than silently colliding.

## 11. Decision Rationale

1. **Seeding mechanism = per-group `torch.manual_seed(blake2b(seed|repr(key)))`.**
   *What:* each group's `_MLPMulti()` constructed under its own derived global-RNG seed.
   *Why:* reuses `nn.Linear.reset_parameters` verbatim (zero init-distribution drift vs the branch code); partition-, reorder-, chunk-, process-, and platform-invariant by construction; smallest possible diff.
   *Source:* repo precedent — the LOCO variants' identity-keyed (per-fold, shared) init block + `assert_matches_reference` (b)/(c) bit-identity design (`vectorized_mlp_skill.py:264-276, 700-780`, landed via #722/#740); `nn.Linear` init draws from the global RNG with no generator threading (torch module-construction contract).
   *Alternatives rejected:* (i) per-group `torch.Generator` with hand-rolled `torch.empty(...).uniform_(..., generator=g)` kaiming replication — must reimplement `kaiming_uniform_(a=√5)` weight bound `1/√fan_in` + bias bound; any mismatch silently changes the init distribution; (ii) caller-supplied absolute index — API churn on 5 branch call sites at reconciliation, not reorder-invariant, correctness burden on callers; (iii) Python builtin `hash(key)` — salted per process (`PYTHONHASHSEED`), non-reproducible across runs, banned by the task itself.
2. **Hash = `blake2b(digest_size=8)` of `f"{seed}|{key!r}"`, reduced `% 2**63`.**
   *Why:* unsalted, stable across processes/platforms/Python versions; 8 bytes ≫ collision risk at realistic group counts (≤ ~10³ groups); `% 2**63` keeps the value safely inside `torch.manual_seed`'s accepted range.
   *Source:* stdlib-guaranteed determinism of `hashlib`; the duplicate-repr assert converts the only realistic collision path (equal reprs) into a loud failure.
   *Alternatives:* sha256 (equivalent, longer), `zlib.crc32` (32-bit, weaker).
3. **Landing strategy = port to `main` with the fix now.**
   *Why:* "built-but-stranded fixes don't help" — the fix must be on `main` and callable to change behavior; both branches later resolve one loud, localized conflict to `main`'s version; waiting on #841's merge is unbounded (no `epm:merged` ever posted).
   *Source:* `.claude/rules/workflow-fix-on-bug.md` § Built-but-stranded (worked example is this very module, #722); `.claude/rules/vectorize-many-cell-fits.md` § Supersede contract (land on main + supersede twins).
   *Alternatives rejected:* wait-for-merge (indefinite park); new-name v2 function (two live twins violate the supersede/delete-old rule).
4. **Test tolerance = bit-identical (`np.array_equal`) for inits AND trained outputs on CPU.**
   *Why:* inits are bit-identical by construction; trained outputs are the same op family the LOCO gate already pins bit-identical across chunking and batch composition on CPU.
   *Source:* `assert_matches_reference` checks (b)/(c) (`np.array_equal`, `vectorized_mlp_skill.py:722-733`); #841's own caveat text confirms determinism at fixed composition.
   *Alternatives:* atol=1e-6 exact-tolerance — kept as the documented §6 fallback only.
5. **Forward-only, no compat flag.**
   *Why:* a `legacy_batch_order_seeding` option preserves a bug nobody should invoke, doubles the test matrix, and contradicts fail-loud; old branch results stay reproducible via their pre-fix commits.
   *Source:* task body ("Forward-only contract change"); CLAUDE.md fail-fast rule.
6. **Duplicate-repr hard assert.**
   *Why:* duplicate keys previously silently overwrote result-dict entries AND would now share inits; one assert makes both fail loud.
   *Source:* fail-fast rule; `preds_by_key` dict semantics in the ported code (lines 923-934).

Also: N/A — no behavioral construct; N/A — not a replication; N/A — no draw battery; N/A — no empirical-null gate.
