## 4. Design

### 4.0 — Topology decision: do the wiring in `backend_poll.main()`, not `GcpBackend.poll`

The advisory/escalation tiers need state PERSISTENCE across ticks and a `now_epoch` + the resolved `current_phase` + a `gpu_util` string. `backend_poll.main()` is the per-tick process entrypoint (one invocation per poll), already holds the `sidecar` path + the resolved `result` (carrying `current_phase` and `status`), and is exactly where the existing wedge-escalation calls live (`_maybe_escalate_gcp_wedge` L1730, `_is_gcp_async_workload_failure` L1744). Putting the GPU-idle tier there keeps it lane-gated and out of `GcpBackend.poll`'s pure-poll responsibility, and lets it reuse the RunPod decision helpers verbatim. `gcp.py` contributes ONLY the probe helper (a pure SSH round-trip, its natural home — it owns the `_run` / `_base_gcloud_argv` machinery).

### 4.1 — NEW: `_gcp_gpu_util_probe` in `src/explore_persona_space/backends/gcp.py`

A method on `GcpBackend` that returns a comma-separated `nvidia-smi` utilization string (the SAME shape `_gpu_idle` / `_maybe_*` consume, e.g. `"0,0,0,0,0,0,0,0"`) or the literal `"unknown"` on ANY failure. Fail-soft by construction — `_gpu_idle("unknown")` returns False, so a probe miss simply skips the advisory/escalation tick (no false idle, no crash). Reuses the existing `_base_gcloud_argv` + `self._run` SSH pattern from `_drain_sentinels`.

```python
def _gcp_gpu_util_probe(self, handle: RunHandle, zone: str) -> str:
    """Best-effort per-GPU utilization (comma-joined) via gcloud compute ssh nvidia-smi.

    Returns e.g. "0,0,0,0" or the literal "unknown" on ANY failure (SSH down,
    permission, timeout, empty/garbled output). FAIL-SOFT: the consumer
    (_gpu_idle) reads "unknown" as NOT idle, so a probe miss never accumulates
    toward an advisory and never crashes the poll. Mirrors the RunPod lane's
    nvidia-smi gpu_util probe (poll_pipeline.poll_once).
    """
    cmd = ("nvidia-smi --query-gpu=utilization.gpu "
           "--format=csv,noheader,nounits")
    argv = _base_gcloud_argv(
        self._config, "compute", "ssh", handle.pod_name,
        f"--command=sudo -n {cmd}",
    )
    argv += [f"--zone={zone}"]
    try:
        res = self._run(argv)
    except Exception as exc:        # transport / subprocess / timeout
        logger.warning("GCP gpu-util probe failed for %s (%s); 'unknown'",
                       handle.pod_name, exc)
        return "unknown"
    if res.returncode != 0:
        logger.warning("GCP gpu-util probe rc=%d for %s; 'unknown'",
                       res.returncode, handle.pod_name)
        return "unknown"
    toks = [t.strip() for t in (res.stdout or "").replace("\n", ",").split(",")
            if t.strip()]
    # Validate every token parses as an int (matches _gpu_idle's contract);
    # any non-numeric token -> 'unknown' so a partial/garbled read never
    # masquerades as idle.
    if not toks or any(not t.lstrip("-").isdigit() for t in toks):
        return "unknown"
    return ",".join(toks)
```

Note the `sudo -n` prefix matches the existing GCP drain SSH (the GCE startup script runs as root). The helper is added to `gcp.py`'s `__all__` if other lanes need it (optional; not required for the `backend_poll` caller, which reaches it through the `GcpBackend` instance).

### 4.3 — State persistence: a sibling state file (option b)

**Choice: a sibling state file** `<main-checkout>/.claude/cache/issue-<N>-gpu-idle-state.json`, parallel to the existing `issue-<N>-handle.json` and the GCP wedge clock sidecar. The GPU-idle state is the SAME shape as the RunPod `_save_state` per-issue subdict, so a dedicated file is the cleaner mirror.

**Rationale for (b) over (a):** (a) extending the handle sidecar's `extra` dict would interleave GPU-idle bookkeeping with the authoritative run-handle the failover paths read/rewrite (`_failover_dead_gcp_to_runpod` re-points the sidecar) — risking the GPU-idle keys being clobbered on a sidecar rewrite, or the GPU-idle write racing the failover write. A dedicated sibling file isolates the GPU-idle clock from the handle's lifecycle, exactly as the RunPod lane keeps it in its own `poll-pipeline-<N>.json` state file separate from the handle. The file stores only the keys the imported helpers read: `{"gpu_idle_since_epoch": str, "gpu_idle_advised_phases": "csv", "gpu_idle_escalated_phases": "csv", "phase": str}` (the `phase` key lets `_gpu_idle_advisory_update` detect a phase change to restart the idle span, matching its RunPod contract which reads `prev_state["phase"]`).

Read/write helpers in `backend_poll.py` (the SAME JSON shape `poll_pipeline._load_state`/`_save_state` use, but single-issue so no per-issue subdict needed):

```python
def _gpu_idle_state_path(sidecar: Path) -> Path:
    """Sibling of the handle sidecar: issue-<N>-gpu-idle-state.json."""
    return sidecar.parent / sidecar.name.replace("-handle.json", "-gpu-idle-state.json")

def _load_gpu_idle_state(path: Path) -> dict[str, str]:
    if not path.exists():
        return {}
    try:
        data = json.loads(path.read_text())
        return data if isinstance(data, dict) else {}
    except (json.JSONDecodeError, OSError):
        return {}     # fail-soft: a corrupt clock restarts the span, never crashes

def _save_gpu_idle_state(path: Path, payload: dict[str, str]) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    tmp = path.with_suffix(path.suffix + ".tmp")
    tmp.write_text(json.dumps(payload, indent=2, sort_keys=True))
    tmp.replace(path)     # atomic, mirrors poll_pipeline._save_state
```

### 4.4 — Wire the two calls into `backend_poll.main()` (GCP backend only)

Insert AFTER `result = backend.poll(handle)` (L1722) and AFTER the wedge-escalation rewrites (`_maybe_escalate_gcp_wedge` L1730, the `_is_gcp_async_workload_failure` failover L1744-1749, the RunPod wedge rewrite L1759), but BEFORE the final `print(json.dumps(_serialize_poll_result(result)))` (L1792). The placement after the failover blocks is deliberate: if the tick is a failover/terminal case it has already `return`ed (L1749 / L1790), so the GPU-idle block runs only on a NON-terminal poll — exactly when an idle clock is meaningful. Gate on `handle.backend == "gcp"` AND `result.status == "running"` (the helpers also re-check `status`, but gating early avoids an SSH probe on a non-running tick):

```python
    # ── GCP-lane GPU-idle advisory + escalation (parity with #727 RunPod) ──
    # A GCP VM idle in a CPU-only / upload phase bleeds credits up to the 24h
    # --max-run-duration DELETE fence with no surfacing. Mirror the RunPod
    # tiers (poll_pipeline): a one-shot [gpu-idle-advisory] marker after
    # EPM_GPU_IDLE_ADVISORY_MIN, then a LOUD [gpu-idle-escalation] marker +
    # Telegram push after EPM_GPU_IDLE_ESCALATION_MIN. NEVER stops the VM.
    if handle.backend == "gcp" and getattr(result, "status", "") == "running":
        gpu_idle_state_path = _gpu_idle_state_path(Path(sidecar))
        prev_state = _load_gpu_idle_state(gpu_idle_state_path)
        zone = handle.extra.get("zone") or backend._config.primary_zone
        gpu_util = backend._gcp_gpu_util_probe(handle, zone)
        now_epoch = int(time.time())
        current_phase = getattr(result, "current_phase", "") or ""
        pod = handle.pod_name

        idle_since, advised_phases, advisory_posted = _maybe_post_gpu_idle_advisory(
            issue=args.issue, pod=pod, status="running", gpu_util=gpu_util,
            current_phase=current_phase, prev_state=prev_state, now_epoch=now_epoch,
        )
        escalated_phases, escalation_posted = _maybe_escalate_gpu_idle(
            issue=args.issue, pod=pod, status="running", gpu_util=gpu_util,
            current_phase=current_phase, idle_since_epoch=idle_since,
            prev_state=prev_state, now_epoch=now_epoch,
        )
        _save_gpu_idle_state(gpu_idle_state_path, {
            "phase": current_phase,
            "gpu_idle_since_epoch": str(idle_since),
            "gpu_idle_advised_phases": ",".join(sorted(advised_phases)),
            "gpu_idle_escalated_phases": ",".join(sorted(escalated_phases)),
        })
        _GCP_GPU_IDLE_POSTED = (advisory_posted, escalation_posted)
    else:
        _GCP_GPU_IDLE_POSTED = (False, False)
```

The escalation message prose (carried by the imported `_maybe_escalate_gpu_idle`) names the #664 spend-leak class. Because the GCP fence bounds the leak at 24h DELETE, a one-line GCP-severity note is added. **Caveat — the imported helper's note string is RunPod-worded** ("8xH200 idle … ~$44/hr"). Two options, decided in implementation: (i) leave the shared note as-is (it is accurate about the leak CLASS and the remedy) and append the GCP fence note via the marker `extra` (e.g. `gcp_fence_bounded_24h=True`) — zero change to `poll_pipeline.py`; or (ii) parameterize the note. **Default: (i)** — keeps the single-file-change contract and avoids touching the RunPod lane; the implementer records the GCP fence-severity context in the marker `extra` + a one-line code comment. If the reviewer prefers explicit GCP-worded prose, that is a follow-up that parameterizes the shared helper (a second-file change, deferred).
