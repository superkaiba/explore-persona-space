# Plan v1 — task #1747: Step 5a spec-freshness sync sources fetched origin/main

## Goal / requirement

The Step 5a spec-freshness sync in `.claude/skills/issue/SKILL.md` must source
FETCHED `origin/main` — matching the already-migrated Step 10d post-gate
re-sync recipe (#1714, `SAFE_SPECS_10D` block, SKILL.md ~L11452-11495) — so a
worktree session can never sync REGRESSED spec bytes from a lagging local
`main`. Incident: #1724 (session d07cbe1f, 2026-07-27T15:01Z) pulled stale
(regressed) spec bytes into its worktree from local `main` and had to unstage
+ skip the sync; only the Step 10d copy of the recipe had been migrated.

## Acceptance criteria

1. **Bash block ref migration.** In the Step 5a fenced block
   (SKILL.md ~L2337-2445):
   - A bounded freshness fetch precedes the merge-base capture:
     `timeout --kill-after=30s 120s git -C "$WT" fetch origin main --quiet || true`
     (the exact bounded shape Step 10d / #1289 use; a failed fetch degrades to
     last-fetched `origin/main` — never a wedge, never a fallback to local
     `main`).
   - `MB=$(git -C "$WT" merge-base HEAD origin/main)` (was `main`).
   - The sync condition, checkout, and echo all reference `origin/main`:
     `! git -C "$WT" diff --quiet origin/main -- $SAFE_SPECS`,
     `git -C "$WT" checkout origin/main -- $SAFE_SPECS`,
     `echo "[step5a] synced from origin/main:"`.
   - The conditional commit message matches the Step 10d inline form VERBATIM:
     `issue-<N>: sync workflow-surface specs from origin/main (spec-freshness)`.
     (The subject-scoped exclusion filter keys on the token `spec-freshness`
     only, so both historical `from main` and new `from origin/main` commits
     keep being excluded — no filter change needed.)
2. **Explicit on-main skip (self-no-op preservation).** The current recipe
   self-no-ops on a `main` checkout only because `diff --quiet main` is
   vacuous when HEAD == main. With `origin/main` as source that property is
   LOST: on a repo-root session whose local `main` lags origin, the sync would
   checkout origin/main content into the SHARED root working tree and commit
   on `main` — a concurrent-committer hazard (CLAUDE.md § Concurrent repo-root
   committers) and a divergence generator. Required: the ENTIRE sync body
   (including the pass-1 dirty-family scan, whose `MB..HEAD` output on an
   ahead-of-origin root would print spurious dirty-family warnings) is skipped
   when the session's branch is `main`, with a one-line skip echo.
   RECOMMENDED shape (minimal diff churn — bash does not require the body to
   be re-indented):

   ```
   WT=$(git rev-parse --show-toplevel)
   if [ "$(git -C "$WT" rev-parse --abbrev-ref HEAD)" = "main" ]; then
     echo "[step5a] session on main (repo root) — spec-freshness sync is worktree-only; skipping"
   else
   <existing body, refs migrated per criterion 1; indentation optional>
   fi
   ```

   The implementer MAY re-indent the body — every pin in
   `tests/test_issue_skill_lint_family_sync.py` is substring- or
   stripped-line-based (verified at clarify time) — but must keep the span
   anchors intact (criterion 6).
