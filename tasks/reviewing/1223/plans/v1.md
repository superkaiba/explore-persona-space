## 2. Method delta (what changes vs current code, and why WARN not FAIL)

**Current flow** (verified on main, `scripts/verify_plan.py:3126-3167`): kind gate →
`_c20_trigger_sections` → tier1 = `_c20_find_declaration` → tier-2 harvest when tier1 is
None → SKIP when neither detected (line 3156) → **N/A escape → PASS (lines 3163-3164)** →
tier-1/tier-2 evaluation. Because the SKIP precedes the escape, the PASS escape never
serves a lattice-free plan; it fires precisely when a detected lattice is about to be
verified — the #1166-critique "fixture-D" masking shape (broken lattice + N/A line →
silent PASS, live-confirmed in #1166's plan §12).

**Delta:** one branch replaced — `_pass` → `_warn` with a tier-naming detail. No change
to the SKIP gate, the kind gate, the tier evaluators, `_C20_REMEDY`, or any regex/helper.

**Why WARN, not FAIL:**
- The co-occurrence is a *meta*-signal, not a verified lattice defect: either the N/A
  line is a deliberate-but-wrong escape (masking — the bad case), or the "lattice
  detection" is a false positive on prose that quotes the declaration form as guidance
  (the shape of all 3 real corpus hits, §5 — meta-plans *about* c20 quoting
  `DISJOINT and exhaustive:` exemplars in sections whose headings match the trigger
  families). A FAIL would hard-block the second, legitimate case; WARN surfaces both to
  the human/critic reviewers, matching c20's own precedent that uncertain evidence
  degrades to WARN (unparsed labels, tier-2 gaps).
- Severity ladder consistency: c20 reserves FAIL for a *verified* co-fire/gap on a
  *claimed* partition (kind: experiment). The escape co-occurrence never verifies the
  lattice at all, so it cannot claim FAIL-grade evidence.

## 11. Decision Rationale

N/A — no training hyperparameters. Load-bearing design choices:

1. **Severity = WARN (not FAIL).**
   *What:* the co-occurrence returns `_warn`, `ok=True`.
   *Why:* two indistinguishable-in-form cases — deliberate-but-wrong escape (masking) vs
   detector false-positive on quoted guidance; only reviewers can adjudicate, and all 3
   measured corpus co-occurrences are the second case (§5). FAIL-grade evidence requires
   a verified lattice defect, which this branch by definition never computes.
   *Source:* task #1223 provenance (the #1166 Alternatives-critic candidate proposed WARN
   verbatim) + c20's own severity ladder (#923 incident history in the docstring:
   unparsed/uncertain evidence degrades to WARN) + the §5 corpus measurement.
   *Alternatives:* FAIL (rejected — hard-blocks the quoted-guidance case); keep PASS but
   log (rejected — invisible to the Phase 1.5/2 gate, the masking persists).
2. **Tier coverage = BOTH tiers (tier-1 declaration AND tier-2 harvest).**
   *What:* the WARN fires whenever the escape branch is reached, which by control flow
   means tier1 is not None OR the tier-2 harvest is non-empty.
   *Why:* (i) the candidate sketch names only `_C20_DECL_RE` (tier 1), but the identical
   masking applies to a harvested tier-2 lattice — and the *committed test* that pins the
   masking today (`test_c20_na_escape_passes`, `C20_V4_BULLETS`) is a tier-2 fixture, so
   tier-1-only coverage would leave the incumbent pinned masking shape in place; (ii) a
   tier-1-only fix needs an extra conditional for zero benefit — past the line-3156 SKIP,
   "a lattice was detected" is already established for both tiers.
   *Source:* control-flow reading of verify_plan.py:3147-3167 (this session) + the
   dispatch brief's reachability note; tier named in the WARN detail so reviewers see
   which detector fired.
   *Alternatives:* tier-1 only (rejected per (i)/(ii)).
3. **Trigger-section confinement = inherited, not re-implemented.**
   *What:* no new scoping code; the detectors the branch keys on already operate only on
   `_c20_trigger_sections` output.
   *Why:* the candidate's "inside a trigger section" requirement is satisfied by
   construction (`_c20_find_declaration` iterates `sections`; the harvest loop likewise);
   duplicating the scan would violate the file's one-copy-of-the-job convention (the
   `_standalone_na_declared` docstring's Supersede note).
   *Source:* verify_plan.py:3032-3047 + :3147-3155, read this session.
   *Alternatives:* a fresh doc-global `_C20_DECL_RE.search(plan)` (rejected — would fire
   on declarations outside trigger sections, a wider net than c20 itself uses).
4. **Preserve SKIP (not PASS) for N/A + no lattice.**
   *What:* the line-3156 SKIP gate stays first; the escape is never consulted when
   nothing is detected.
   *Why:* minimal-change discipline; SKIP and PASS are equivalently non-blocking, and
   reordering would change the reported status of ~33 committed lattice-free N/A plans
   for no functional gain.
   *Source:* current behavior verified via the SKIP-gate ordering (:3156-3162) and the
   §5 sweep (36 N/A-line plans, 33 lattice-free).
   *Alternatives:* hoist the N/A check above the SKIP to PASS lattice-free escapes
   (rejected — cosmetic behavior change outside the Goal).
