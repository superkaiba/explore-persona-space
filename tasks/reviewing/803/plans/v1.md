**Acceptance criteria:**

## 3. Method delta (vs. today's behavior)

- **Today:** `main()` immediately dispatches to `clean_issue_downloads[_incremental]`, whose first
  operations (`_active_consumer_protected_issues` → `tasks_dir()`; `download_cache_dirs` →
  `_data_root()` / `_worktree_data_roots()`; `_rel_name` → `repo_root()`) all call
  `task_workflow.repo_root()`. On a non-`main` HEAD that resolver auto-routes to a managed
  worktree via `git worktree add`/`git reset --hard`, which hangs on MooseFS. (Note: the
  module-level `from explore_persona_space.task_workflow import ...` at lines 87-92 does NOT call
  `repo_root()` at import — it is called lazily by those helpers — so a guard at the TOP of
  `main()`, before any of them fire, fully prevents the hang.)
- **After:** `main()` first calls `_running_pod_side()`. If True, it prints a one-line no-op
  notice and returns 0 — no helper is called, so `repo_root()` never runs. If False (the VM), the
  existing dispatch runs exactly as today.

### 4a. `scripts/clean_experiment_downloads.py`

Add a module-level detector after the existing constants (e.g. after `DISK_GUARD_SIDECAR_REL`,
~line 135), and an early-return as the first statement in `main()`. `Path` is already imported

Detector (new function, placed near the other module-level helpers):

```python
def _running_pod_side() -> bool:
    """True when running on a RunPod pod (NOT the dev VM).

    On a pod, importing/using ``task_workflow.repo_root()`` on a non-``main``
    HEAD auto-routes to a managed worktree via ``git worktree add`` /
    ``git reset --hard`` on MooseFS-backed ``/workspace``, which hangs
    indefinitely (#803, pod-778). Detected by two conditions that both hold on
    every RunPod pod (the container has ``/.dockerenv``; ``bootstrap_pod.sh``
    creates ``/workspace/logs``). ``/workspace/logs`` alone is used as a pod
    signal elsewhere (e.g. ``scripts/issue634_extract_behavior_vectors.py``),
    but on the dev VM ``/workspace/logs`` is a real populated dir — so the
    ``/.dockerenv`` conjunct is load-bearing: it is what makes the AND False
    on the VM and prevents a dev-VM false-positive (which would silently
    no-op a VM-side reap)."""
    return Path("/.dockerenv").exists() and Path("/workspace/logs").is_dir()
```

signature, BEFORE the `argparse` block builds. Parse args is fine either before or after; placing
the guard first is cheapest and matches the body's sketch:

```python

        ...  # unchanged
```

### 4b. `tests/test_clean_experiment_downloads_pod_side_short_circuit.py` (new)

Match the load-via-importlib style of the two existing test files. Mock the detector's two
`Path` probes and assert (a) pod-side returns 0 without calling `repo_root()`, (b) VM-side
(detector False) reaches the normal dispatch. Sketch:

```python
"""Tests for the pod-side short-circuit in scripts/clean_experiment_downloads.py (#803).

On a RunPod pod, any use of task_workflow.repo_root() on a non-main HEAD auto-routes
to a managed worktree via git worktree add / git reset --hard, which hangs on
MooseFS-backed /workspace. main() must detect the pod and return 0 BEFORE any
helper calls repo_root(). Detector: /.dockerenv AND /workspace/logs both present.

The script lives under scripts/ (not an importable package), so it is loaded via
importlib exactly like tests/test_clean_experiment_downloads_parity.py.
"""

import importlib.util
import sys
from pathlib import Path

_SCRIPTS = Path(__file__).resolve().parent.parent / "scripts"


def _load(mod_name: str):
    spec = importlib.util.spec_from_file_location(mod_name, _SCRIPTS / f"{mod_name}.py")
    mod = importlib.util.module_from_spec(spec)
    sys.modules[mod_name] = mod
    spec.loader.exec_module(mod)
    return mod


ced = _load("clean_experiment_downloads")


def test_pod_side_short_circuits_to_noop_zero(monkeypatch, capsys):
    """Detector True -> main() returns 0, prints the no-op notice, and never
    touches repo_root() (a repo_root that raises proves it was never called)."""
    monkeypatch.setattr(ced, "_running_pod_side", lambda: True)

    def _boom():
        raise AssertionError("repo_root() must not be called pod-side")

    monkeypatch.setattr(ced, "repo_root", _boom)
    rc = ced.main(["778", "--incremental", "--apply"])
    assert rc == 0
    assert "pod-side no-op" in capsys.readouterr().out


def test_detector_true_only_when_both_signals_present(monkeypatch):
    """_running_pod_side() is the AND of /.dockerenv and /workspace/logs."""
    real_exists = Path.exists
    real_is_dir = Path.is_dir

    def _exists(self):
        return str(self) == "/.dockerenv" or real_exists(self)

    def _is_dir(self):
        return str(self) == "/workspace/logs" or real_is_dir(self)

    # both present -> True
    monkeypatch.setattr(Path, "exists", _exists)
    monkeypatch.setattr(Path, "is_dir", _is_dir)
    assert ced._running_pod_side() is True

    # only /.dockerenv -> False
    monkeypatch.setattr(Path, "is_dir", lambda self: real_is_dir(self))
    assert ced._running_pod_side() is False


def test_vm_side_runs_normal_dispatch(monkeypatch):
    """Detector False -> main() reaches the normal dispatch (proven by a
    sentinel cleaner that records the call and returns an empty result)."""
    monkeypatch.setattr(ced, "_running_pod_side", lambda: False)
    called = {}

    class _Res:
        removed: list = []
        failed: list = []
        skipped: list = []
        sizes_bytes: dict = {}
        bytes_freed = 0

    def _fake_cleaner(issue, *, apply, data_root=None):
        called["issue"] = issue
        called["apply"] = apply
        return _Res()

    monkeypatch.setattr(ced, "clean_issue_downloads_incremental", _fake_cleaner)
    rc = ced.main(["778", "--incremental", "--apply"])
    assert rc == 0
    assert called == {"issue": 778, "apply": True}
```

The implementer refines exact assertions to match the real `CleanResult` interface; the shape
above is verified against the current `main()` (dispatches to
`clean_issue_downloads_incremental` when `--incremental`, prints `bytes_freed`/`_fmt_gb`, returns
`2 if res.failed else 0`).

## 7. Kill criteria (what would make this fix wrong)

- **Detector false-positives on the dev VM** → VM-side reaps (`vm_disk_guard.py` cron, `/issue`
  Step 8) silently no-op, and the VM disk fills. Guarded by: (a) the two-condition AND — on the
  dev VM (`cia-benchmark-vm`) `/workspace/logs` IS present but `/.dockerenv` is NOT, so the AND
  is False; the `/.dockerenv` conjunct is load-bearing and its absence is what protects the VM
  from a false positive (a `/workspace/logs`-only predicate WOULD false-positive on this VM);
  (b) the `test_vm_side_runs_normal_dispatch`
  regression + the two existing test files, which all run on the VM with the detector False and
  would fail if the VM path stopped reaping.
- **Detector false-negatives on a pod** (misses a pod) → the hang recurs. Acceptable-but-noted:
  the AND is conservative toward "not a pod", so a genuinely pod-shaped env missing `/.dockerenv`
  would still hang — but every RunPod pod in this project has both signals (the bootstrap creates
  `/workspace/logs`; the container always has `/.dockerenv`), so this is not a live risk.
- **The guard is placed AFTER a `repo_root()`-triggering line** → the hang is not actually
  prevented. Guarded by placing the early-return as the FIRST statement in `main()` and by the
  `_boom` test (`repo_root` raising) proving no helper runs pod-side.
