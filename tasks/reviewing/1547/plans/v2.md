### 4.3 Leg C — backends/gcp.py crash-persist budget decision

**Verdict: CONFIRM the architecture, sharpen the single retry.** Explicitly:

- **KEEP** `timeout 300` (the #854 poweroff/billing bound — "can never delay the poweroff"; raising it trades money for a persist that a sustained storm defeats anyway).
- **KEEP** attempts=2 for `retry=True` bundles and the per-dir `for att in (1, 2)` mirror; **KEEP** final bundle `retry=False` (recorded #1151 rationale: traceback-first priority; more attempts risk the 300s budget).
- **CHANGE** the between-attempt sleep from fixed `EPS_PERSIST_RETRY_BACKOFF_S` (default 10) to Retry-After-aware: add a small helper inside the heredoc python, used by BOTH `_up_bundle` (~line 1868) and the per-dir loop (~line 2129):

```python
def _backoff_s(exc):
    b = _env_int("EPS_PERSIST_RETRY_BACKOFF_S", 10)
    cap = _env_int("EPS_PERSIST_RETRY_MAX_BACKOFF_S", 60)
    try:
        ra = getattr(getattr(exc, "response", None), "headers", {}).get("Retry-After")
        ra_s = float(ra) if ra is not None else 0.0
    except Exception:
        ra_s = 0.0   # fail-open to the env default — never crash the persist on a weird header
    return max(0, min(max(b, ra_s), cap))
```

- **Accepted residual (documented in the code comment):** a sustained org-wide storm (> the 300s window, e.g. the #931 ~30-min day) still ends `eps/persist=failed_uploads` — that is the CORRECT outcome under the poweroff bound; recovery is the existing `issue<N>_partial/` regen path. The fix targets the common short-throttle class (infra 429s with Retry-After ≤ 60s), where today's blind 10s sleep retries INTO the same throttle window. Worst-case added wall: ≤ 50s per retrying bundle, only when the server sends a Retry-After, still inside 300s with the traceback-first ordering protecting the highest-value artifact.
- The sibling DONE-persist heredoc (`EPS_DONE_PERSIST_RETRY_BACKOFF_S`, ~L2494-2508) is OUT of scope (task body names `_eps_persist_diagnostics` only); noted as a follow-up candidate in the PR body if the pattern proves out.

- **gcp.py verdict — confirm attempts/timeout, add Retry-After-aware sleep capped at 60s.** *What:* keep 2/1 attempts + `timeout 300`; sleep `min(max(env, Retry-After), 60)`. *Why:* the recorded #1151 rationale ("further retries would risk the 300s budget") and the #854 poweroff/billing bound both survive scrutiny — the actual defect is the blind 10s sleep retrying into the same throttle window; honoring the server hint fixes the common short-throttle class without touching the bound; a >300s storm is unrecoverable by design and the `issue<N>_partial/` regen path is the recovery. *Source:* gcp.py:1845-1848 + 1777 comments (#1151, #935, #854); #664 (idle-billing family — why the 300s bound exists); the c3-P8 incident (2026-07-18 storm).
