## 4. Design

### New helper: `RunPodBackend._ssh_glob_sentinels`

Mirror `_ssh_read_sentinel` in structure. Signature:

```python
def _ssh_glob_sentinels(self, handle: RunHandle) -> Callable[[str, int], list[str]]:
    """Build a remote sibling-sentinel lister bound to ``handle``'s pod (#709).

    The SSH counterpart of artifacts._default_glob_sentinels: the RunPod
    sentinel siblings live on the pod under
    /workspace/eval_results/issue_<N>/<attempt>/.completion-sentinel.json. The
    pod is guaranteed alive at confirm time (teardown gated on the PASS), so a
    remote `find` is reliable.

    Primitive choice (v2): `find -mindepth 2 -maxdepth 2 -name <SENTINEL> -type f`
    over the issue-dir, NOT `ls -1 <dir>/*/<SENTINEL>`. Rationale: `find`
    requires NO remote glob expansion (no `*` in the SSH command), so there
    is no shell-quoting hazard — both arguments (issue_dir and SENTINEL_FILENAME)
    are safely `_shell_quote`d. rc=0 + empty stdout cleanly distinguishes
    "no siblings found" from a missing-dir / transport rc≠0; the structural
    impossibility of a "broken-glob-expansion" bug is the point. `-mindepth 2
    -maxdepth 2` exactly mirrors the local-FS default's `issue_dir.glob(
    f"*/{SENTINEL_FILENAME}")` (one attempt-dir level, then the sentinel).
    `-type f` matches the local-FS default's plain-file semantics (an
    unlikely symlinked sentinel would not be matched by either path; see §8).

    Semantics (the back-compat 'no remote siblings' contract):
      * rc=0, non-empty stdout -> the newline-split sibling paths,
                                  stripped, empties dropped.
      * rc=0, empty stdout     -> [] (no siblings).
      * any non-zero rc (transport, auth, DNS, missing dir, find missing) -> []
        i.e. 'no live siblings found'. NEVER raise: _resolve_live_sentinel
        treats [] as zero siblings -> declared-missing FAIL (gate unrelaxed),
        whereas a raise would be caught as a probe-failure FAIL too but with
        a noisier note. The matching artifacts.py default also yields nothing
        on a missing dir, so [] keeps the SSH variant behaviorally identical.
    """
    def glob(declared: str, issue: int) -> list[str]:
        del issue  # encoded in the declared path's grandparent, like the FS default
        issue_dir = str(Path(declared).parent.parent)  # .../eval_results/issue_<N>
        remote_cmd = (
            f"find {_shell_quote(issue_dir)} "
            f"-mindepth 2 -maxdepth 2 "
            f"-name {_shell_quote(SENTINEL_FILENAME)} "
            f"-type f"
        )
        proc = subprocess.run(
            ["ssh", handle.pod_name, remote_cmd],
            capture_output=True, text=True, encoding="utf-8",
            errors="replace", timeout=60, check=False,
        )
        if proc.returncode != 0:
            return []
        return [ln.strip() for ln in proc.stdout.splitlines() if ln.strip()]
    return glob
```

Notes on each load-bearing choice:

- **`find` vs `ls -1 ... 2>/dev/null` (v2 revision).** The Alternatives critic (round 1) flagged `find -mindepth 2 -maxdepth 2 -name <SENTINEL> -type f` as the more robust primitive: no remote glob, no quoting hazard, unambiguous rc semantics (rc=0+empty = "no siblings"; rc≠0 = "absent dir / transport"). This eliminates the round-1 §8 Top Risk ("remote glob NOT expanding") entirely — there is no `*` in the command, so a hypothetical bug where `_shell_quote` wraps the whole argument is structurally impossible.
- **`SENTINEL_FILENAME`** (`= ".completion-sentinel.json"`) is imported from `backends.artifacts`. `artifacts.py` does not import `runpod.py` (verified by the Phase 1.5 fact-checker), so a top-level `from .artifacts import SENTINEL_FILENAME` in `runpod.py` is acyclic.
- **Issue-dir derivation** matches `_default_glob_sentinels`: `Path(declared).parent.parent` is the `issue_<N>/` dir (declared = `.../issue_<N>/<attempt>/.completion-sentinel.json`). The `issue` arg is part of the seam's signature but unused (same as the FS default — the dir is encoded in the path).
- **`-mindepth 2 -maxdepth 2`** mirrors the local-FS default's `issue_dir.glob(f"*/{SENTINEL_FILENAME}")` — exactly one attempt-dir level, then the sentinel. This is what makes the SSH variant behaviorally identical to the FS default for the same `issue_dir`.

**Why code, not a model call?** N/A — no unstructured-data heuristics; this is a deterministic remote `find` parse, not a classifier/extractor/judge.
