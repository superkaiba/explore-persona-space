## 0.0 TL;DR (plain English)

- **What I'll change:** before the watcher's wedge arm irreversibly terminates a RUNNING-but-no-port pod, it will first check whether a live session is actively working that issue (recent markers, live registered session with a fresh transcript). If yes, it alerts the owner and defers instead of terminating; the wedge clock keeps running so a dead owner still gets the terminate later.
- **What I expect:** replayed on the #1586 incident, the new check reads "owner live" (markers 14 min old at decision time) and demotes the terminate to an alert; a genuinely dead session (the #664 case the arm exists for) still terminates, at most ~2h later.
- **What would change my mind:** if the owner-liveness probe cannot distinguish a wedged-but-marker-fresh session from a live one within the file's existing machinery, or if the deferral leaves wedged pods billing unboundedly with no alert, the demote shape is wrong and I'd fall back to alert-first-terminate-later with a hard cap.

## 1. Goal + requirement + acceptance criteria

**Goal (Task #1667 Goal, verbatim; re-read at return time, no `epm:goal-updated` markers):** "The watcher's pod-safety wedge-failover arm must not terminate a pod out from under a live owning session mid-crash-fix-round, and must leave a durable record of the failover on the owning issue's events."

Per the clarifier correction (`epm:clarify`, 2026-07-25): the failover-record half (claim b) is **already implemented** — this plan VERIFIES it (§4). **Acceptance criteria (all testable):**
1. `decide_pod_wedge` never returns `"terminate-failover"` when its new `owner_live` input is `True` or `"unknown"`; it returns a new demote action instead. Pure-function pin tests pass.

4. The wedge clock (`wedge_first_seen`) is PRESERVED across demote ticks — a later tick where owner activity has quieted terminates without restarting the K-floor maturation.
5. Kill switch `EPM_DISABLE_WEDGE_OWNER_GUARD=1` restores byte-equivalent pre-#1667 terminate behavior (probes never invoked).

## 11. Decision Rationale

`N/A — no model training` (no hyperparameters; entries below are design decisions).

- **Shape: demote-to-alert with the wedge clock CONTINUING (not bounded deferral, not alert-first-terminate-later).** *Why:* self-resolving — the probe re-runs each confirmation cycle, so the terminate fires the moment owner activity quiets past the window; a live owner is simultaneously alerted with the exact recovery recipe. A bounded deferral window would terminate under a STILL-live owner at expiry (recreating the incident on long crash-fix cycles); alert-first-terminate-later is that same shape with one extra tick. The host-pinned-wedge concern (a live owner often can't heal #763) is answered by the marker's explicit hand-off: the OWNER terminates deliberately after persisting state — precisely what #1586's owner would have wanted (its 05:51Z relaunch would have reused intact checkpoints). *Source:* #1582 escalate-only precedent (scripts/autonomous_session_watch.py:3461-3463) + the watcher's standing "false stop worse than false alert" posture (module docstring, ~line 76) + #1586 incident record. *Alternatives:* bounded deferral (rejected: terminates under live owner), permanent demote while tagged... n/a (that's keep-running's job).
- **Recent-activity window: 2h default (`EPM_WEDGE_OWNER_RECENT_H`).** *Why/Source:* identical construct to the stalled detector's marker-heartbeat window — "a session that posted ANY non-watcher marker within 2h is never declared stalled" — `EPM_STALLED_MARKER_HEARTBEAT_MIN` = 120 min (#845 a-i, `.claude/rules/background-automation.md` § Stall-detection). Incident margin: 14-min marker age vs 120-min window ≈ 8.6× headroom. *Alternatives:* 1h (thinner margin for slow review rounds — #1586's implementer gap 05:19→05:44 was 26 min, but code-review gaps run ~40-60 min); 12h (the #1582 abandonment floor — wrong construct here; it would defer ~10h extra for every genuinely dead session).
- **Tri-state with only literal-`False`-terminates; `"unknown"` demotes.** *Why:* uncertainty must never enable the irreversible action. *Source:* the MF2 keep-running tri-state in the same decision (scripts/autonomous_session_watch.py:3276-3281) — same polarity, same rationale. *Alternatives:* unknown→terminate when markers stale (rejected: a daemon flake would then be sufficient to destroy a live-owner pod).
- **Reuse `_keep_running_owner_state` with a short window instead of new liveness machinery.** *Why:* it already implements exactly the required union (registration sids + cwd-mapped children + self-report rescue + transcript idle) with fail-toward-unknown semantics, and is pin-tested. *Source:* scripts/autonomous_session_watch.py:10951-11029 (#1582). *Alternatives:* a bespoke probe (duplicated logic, drift risk); markers-only (misses a live session between marker posts — the #1345 cwd-mapped owner class).
- **Marker-recency leg via `_latest_nonwatcher_event_ts`.** *Why:* daemon-independent, and watcher sentinels are excluded by construction so the arm's own alerts never self-defer. *Source:* scripts/autonomous_session_watch.py:19076; sentinel-exclusion contract at lines 1542-1575. *Alternatives:* filtering specific marker kinds (epm:failure/stage-dispatch only) — rejected, any non-watcher marker is owner evidence (the #845 a-i judgment).
- **Kill-switch default ENABLED; probe lazy on the terminate-eligible branch only.** *Source:* `_keep_running_owner_audit_enabled` (line 10614) shape; MF2 lazy-read pattern (lines 10436-10443). *Alternatives:* default-off bake-in period (rejected: the guard is pure demote-to-alert — its failure mode is an extra alert, not a lost action).
- **Counter convention `("alert-owner-live", 0)`.** *Source:* the existing alert cases return `(action, 0)` (decide_pod_wedge cases, lines 3273-3295) — mirrored for uniform re-confirmation semantics. *Alternative:* pinning `new_missed` at threshold (probe every tick — 2× probe cost for ~10 min faster post-quiet terminate; not worth it).
