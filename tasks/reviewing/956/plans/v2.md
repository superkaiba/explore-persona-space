because there the DAEMON completed the spawn successfully (webhook arrived; only the client gave
up waiting) — the session is known-good. In the webhook-timeout-500 case the DAEMON ITSELF
declared the handshake failed: the child is in an unknown, possibly wedged state (the incident's
two children sat live-but-empty — no prompt ever fired in the observed window — despite the
child-side env seeding mechanism). Adopting and registering such a session risks the exact
#685-class "idle spawned-but-never-ran session" that `_verify_happy_patch_or_die` exists to
prevent, with the watcher then trusting a dead-weight registration. So this path takes
**STOP-then-RETRY**, not adoption (decision rationale §11.1). The stop is DAEMON-MEDIATED by
default (§11.9): the 500 carries the exact PID, and the daemon's `PID-<pid>` stop branch only
kills a pid the daemon itself tracks — a stronger anchor than any client-side /proc heuristic.

### 4.1 New module constants (near `SPAWN_SESSION_TIMEOUT_S`, line ~885)

```python
# The Happy daemon waits 15s for the spawned child's /session-started webhook,
# then resolves {"success": false, "error": "Session webhook timeout for PID <n>"}
# (regular path) / "... (tmux)" (tmux path) WITHOUT killing the child — the fork
# stays live and tracked (bundle index-q9G4ktSK.mjs lines 5346/5466; incident
# task #956, 2026-07-03: two consecutive 500s leaked two live-but-empty
# sessions, third attempt succeeded). On this shape post() reaps the
# half-spawned child, then retries ONCE after a backoff sized at 2x the
# daemon's 15s webhook window.
WEBHOOK_TIMEOUT_RE = re.compile(r"Session webhook timeout for PID (\d+)(?P<tmux> \(tmux\))?")
WEBHOOK_TIMEOUT_MAX_RETRIES = 1
WEBHOOK_TIMEOUT_RETRY_BACKOFF_S = 30.0
# Greppable prefix for every reap-related stderr line, so "fix engaged" is
# distinguishable in production spawn logs (nohup/session transcripts).
WEBHOOK_REAP_LOG_PREFIX = "webhook-timeout reap:"
# Bounded wait for a SIGTERMed / daemon-stopped child to die (~10s), the
# 20 x 0.5s shape _stop_fallback (#903) already uses.
REAP_PID_DEATH_POLL_TRIES = 20
REAP_PID_DEATH_POLL_INTERVAL_S = 0.5
```

(`re`, `os`, `signal`, `time` are already imported at module top — no new imports; avoids the
PostToolUse-ruff F401 re-add round. The regex gains a NAMED group `tmux` so the reap knows which
daemon emission path fired — v1 used a non-capturing group.)

### 4.2 `post()` restructure (line 892)

Wrap the single attempt in a bounded loop; only the `/spawn-session` + webhook-timeout-shape
HTTPError takes the new leg. Everything else — non-matching HTTPError, TimeoutError reconcile,
URLError — is preserved with today's exact messages.

```python
def post(path: str, body: dict[str, Any]) -> dict[str, Any]:
    """... (existing docstring, plus:) On an HTTP error whose body matches the
    daemon's 'Session webhook timeout for PID <n>' shape (the daemon forked a
    child but its /session-started webhook missed the 15s window — the child
    stays ALIVE and TRACKED daemon-side), post() reaps the half-spawned child
    (daemon /stop-session — by session id when a late webhook already landed,
    else by the daemon's PID-<pid> stop branch; identity-checked SIGTERM only
    as the untracked-but-alive fallback) and retries once after
    WEBHOOK_TIMEOUT_RETRY_BACKOFF_S. A failed/unconfirmed reap exits nonzero
    WITHOUT retrying — retrying over an unconfirmed leak or a surviving inner
    claude could double-spawn (#956)."""
    url = f"http://127.0.0.1:{daemon_port()}{path}"
    payload = json.dumps(body).encode()
    timeout = SPAWN_SESSION_TIMEOUT_S if path == "/spawn-session" else DEFAULT_TIMEOUT_S
    max_attempts = 1 + (WEBHOOK_TIMEOUT_MAX_RETRIES if path == "/spawn-session" else 0)
    for attempt in range(1, max_attempts + 1):
        req = urllib.request.Request(
            url, data=payload, headers={"Content-Type": "application/json"}, method="POST"
        )
        spawn_started_at = time.time() if path == "/spawn-session" else None
        try:
            with urllib.request.urlopen(req, timeout=timeout) as resp:
                return json.loads(resp.read())
        except urllib.error.HTTPError as e:
            try:
                err_body = json.loads(e.read())
            except Exception:
                err_body = {"raw": str(e)}   # non-dict / non-JSON body guard (tested)
            m = None
            if path == "/spawn-session":
                err_text = err_body.get("error", "") if isinstance(err_body, dict) else str(err_body)
                m = WEBHOOK_TIMEOUT_RE.search(err_text or "")
            if m is None:
                # UNCHANGED failure surface for every non-webhook-timeout error
                # and every non-/spawn-session route.
                sys.exit(f"Happy daemon {path} returned HTTP {e.code}: {err_body}")
            outcome = _reap_half_spawned_session(
                int(m.group(1)), body.get("directory"), is_tmux=m.group("tmux") is not None
            )
            print(
                f"  {WEBHOOK_REAP_LOG_PREFIX} /spawn-session webhook-timeout (HTTP {e.code}, "
                f"attempt {attempt}/{max_attempts}): {err_text!r}; reap: {outcome.detail}",
                file=sys.stderr,
            )
            if not outcome.reaped:
                sys.exit(
                    f"Happy daemon /spawn-session returned HTTP {e.code}: {err_body}. "
                    f"Could NOT confirm the half-spawned child (PID {m.group(1)}) was "
                    f"fully reaped ({outcome.detail}); NOT retrying (a retry over an "
                    f"unconfirmed leak could double-spawn). Clean up manually "
                    f"(spawn_session.py list / stop), then re-run."
                )
            if attempt >= max_attempts:
                sys.exit(
                    f"Happy daemon /spawn-session returned HTTP {e.code} (webhook "
                    f"timeout) {max_attempts} times; the half-spawned child was reaped "
                    f"each time (last: {outcome.detail}). The daemon looks loaded — "
                    f"retry later (no session leaked)."
                )
            print(
                f"  {WEBHOOK_REAP_LOG_PREFIX} retrying /spawn-session in "
                f"{WEBHOOK_TIMEOUT_RETRY_BACKOFF_S:.0f}s (attempt {attempt + 1}/{max_attempts})...",
                file=sys.stderr,
            )
            time.sleep(WEBHOOK_TIMEOUT_RETRY_BACKOFF_S)
            continue
        except TimeoutError as e:
            # UNCHANGED (client-socket timeout -> adopt-or-fail reconcile);
            # spawn_started_at is per-attempt so a retry's timeout reconciles
            # against ITS OWN window.
            ...
        except urllib.error.URLError as e:
            sys.exit(f"Happy daemon {path} unreachable at 127.0.0.1: {e}")  # UNCHANGED
```

Note: the reap's own daemon stops do NOT go through `post()` (they use the raw helper in
§4.3.1, precisely to keep transport failures distinguishable), so there is no recursion concern.

### 4.3 `_reap_half_spawned_session(pid, directory, is_tmux)` (new; REDESIGNED this revision)

**Design change from v1 (MUST-FIX 2).** v1 assumed a never-handshaken child is `/list`-visible
without a sid and can only be reaped by client-side SIGTERM. Both premises were wrong (bundle
lines 4079 / 5559, § 2): the never-handshaken child is `/list`-INVISIBLE by design, and the
daemon's `stopSession` accepts `PID-<pid>` and kills the tracked child itself. The reap is
therefore **daemon-mediated by default**: the daemon only kills a pid IT tracks (its
`pidToTrackedSession` entry was created at the fork), which eliminates most client-side
PID-recycle mis-kill exposure — the daemon's tracking IS the identity check. The `/list` probe
is retained ONLY to detect the late-handshake case (sid-stop is the established, tested stop
path); `/list` ABSENCE routes to the PID-stop, never to "already gone". The client-side
identity-checked SIGTERM survives ONLY as a fallback for the untracked-but-alive anomaly
(§11.10). The new "already gone" signal is: daemon reachable + PID-stop returned
`success: false` (pid untracked — `onChildExited` untracks a self-exited child) +
`_pid_alive(pid)` false.

```python
class _ReapOutcome(NamedTuple):
    reaped: bool   # True == confirmed no live half-spawned process remains (wrapper AND inner claude)
    detail: str    # human-readable outcome for the stderr NOTE / exit message


def _reap_half_spawned_session(pid: int, directory: str | None, *, is_tmux: bool = False) -> _ReapOutcome:
    """Reap the child the daemon forked for a /spawn-session that failed with
    'Session webhook timeout for PID <pid>' (#956). The daemon does NOT kill
    that child; unreaped it becomes a live-but-empty unmapped session nothing
    cleans up for >=12h. Legs, in order:

    1. LATE-HANDSHAKE probe: strict /list. The daemon's /list FILTERS OUT
       never-handshaken children (bundle line 4079), so an entry for `pid`
       (which by construction carries a happySessionId) means the webhook
       landed LATE -> stop via /stop-session {sessionId: <sid>}. /list
       ABSENCE is the NORMAL never-handshaken state, NOT "already gone".
    2. DAEMON PID-STOP (primary no-sid leg): /stop-session
       {sessionId: "PID-<pid>"} — the daemon's stopSession PID- branch
       (bundle line 5559) SIGTERMs the tracked child itself and untracks it.
       The daemon only kills a pid it tracks, so this leg carries no
       PID-recycle exposure. success:true does NOT prove death (the daemon
       swallows kill errors, lines 5564-5573) -> always confirm with the
       client-side death poll.
    3. ALREADY-GONE verdict: PID-stop success:false (daemon reachable, pid
       untracked — onChildExited untracked a self-exited child) AND
       _pid_alive(pid) false.
    4. FALLBACK identity-checked SIGTERM (untracked-but-alive anomaly only:
       e.g. the daemon restarted between fork and reap, orphaning the child
       from tracking): the #903 _stop_fallback identity trio (comm=='node',
       happy-wrapper cmdline, not-the-daemon-pid) PLUS a /proc/<pid>/cwd ==
       spawn-directory bind. Ambiguity always REFUSES the kill
       (reaped=False). SKIPPED for the tmux variant (pane-PID /proc identity
       signature unverified for tmux; fail loud with a tmux hint).

    ANY transport failure talking to the daemon (unreachable /list or
    /stop-session) returns reaped=False — 'daemon said success:false' and
    'daemon unreachable' are deliberately NOT conflated (the former is
    evidence about tracking state; the latter is no evidence at all).

    Survivor rule (DIVERGES from the #903 _stop_fallback precedent, which
    only WARNS on a surviving inner claude — safe there because no retry
    follows a takeover stop): after ANY kill leg (sid-stop, PID-stop, or
    fallback SIGTERM), if the pre-kill-resolved inner claude pid is still
    alive once the wrapper died, return reaped=False — retrying over a live
    inner claude recreates the live-unmapped-work class at process level
    (double-spawn risk)."""
    import session_resolver  # lazy: session_resolver imports spawn_session at top level

    # Pre-kill: resolve the inner claude while the wrapper's /proc tree is
    # still walkable (post-kill resolution is impossible). Best-effort; a
    # read-only /proc walk is harmless even if pid later fails identity.
    claude_pid = session_resolver.resolve_claude_pid(pid)

    def _confirm_dead_and_no_survivor(via: str) -> _ReapOutcome:
        if not _await_pid_death(pid, session_resolver):
            return _ReapOutcome(False, f"{via} ACKed but PID {pid} survived ~10s")
        if claude_pid is not None and session_resolver._pid_alive(claude_pid):
            return _ReapOutcome(
                False,
                f"{via}: wrapper PID {pid} dead but inner claude PID {claude_pid} "
                f"SURVIVED — retry blocked (double-spawn risk); kill it manually, then re-run",
            )
        return _ReapOutcome(True, f"reaped via {via} (PID {pid} dead)")

    # --- Leg 1: late-handshake probe (strict /list) ---
    try:
        children = _live_children(strict=True)
    except RuntimeError as e:
        return _ReapOutcome(False, f"daemon /list unreachable while verifying PID {pid}: {e}")
    match = next((c for c in children if c.get("pid") == pid), None)
    sid = (match or {}).get("happySessionId")
    if isinstance(sid, str) and sid:
        try:
            ok = _stop_session_raw(sid)
        except RuntimeError as e:
            return _ReapOutcome(False, f"daemon unreachable during sid-stop of {sid}: {e}")
        if ok:
            return _confirm_dead_and_no_survivor(f"daemon sid-stop of late-handshaken {sid}")
        # ok False: entry vanished between /list and the stop (self-exit race,
        # concurrent stop) -> fall through to the PID-stop leg.
    # --- Leg 2: daemon PID-stop (primary no-sid leg) ---
    try:
        ok = _stop_session_raw(f"PID-{pid}")
    except RuntimeError as e:
        return _ReapOutcome(False, f"daemon unreachable during PID-stop of PID {pid}: {e}")
    if ok:
        return _confirm_dead_and_no_survivor(f"daemon PID-stop (PID-{pid})")
    # --- Leg 3: already-gone verdict (daemon reachable, pid untracked) ---
    if not session_resolver._pid_alive(pid):
        return _ReapOutcome(True, f"child PID {pid} already exited (untracked by daemon, not alive)")
    # --- Leg 4: untracked-but-alive anomaly -> identity-checked SIGTERM fallback ---
    if is_tmux:
        return _ReapOutcome(
            False,
            f"PID {pid} is tmux-spawned, untracked by the daemon, and still alive; the "
            f"/proc identity signature is unverified for tmux pane PIDs — refusing the "
            f"client-side kill. tmux path: clean up via tmux, then re-run.",
        )
    comm = session_resolver._read_proc_comm(pid)
    if comm != "node":
        return _ReapOutcome(False, f"PID {pid} comm={comm!r} != 'node' (recycled?); refusing kill")
    cmdline = session_resolver._read_proc_cmdline(pid) or ""
    if "happy" not in cmdline:
        return _ReapOutcome(
            False, f"PID {pid} cmdline lacks the happy-wrapper signature; refusing kill"
        )
    daemon_pid = session_resolver._happy_daemon_pid()
    if daemon_pid is not None and pid == daemon_pid:
        return _ReapOutcome(False, f"PID {pid} is the Happy DAEMON pid; refusing kill")
    if directory:
        try:
            proc_cwd: str | None = os.readlink(f"/proc/{pid}/cwd")
        except OSError:
            proc_cwd = None  # unreadable cwd is not disqualifying; 3 checks above hold
        if proc_cwd is not None and proc_cwd != directory:
            return _ReapOutcome(
                False, f"PID {pid} cwd {proc_cwd!r} != spawn dir {directory!r}; refusing kill"
            )
    os.kill(pid, signal.SIGTERM)
    return _confirm_dead_and_no_survivor(f"fallback SIGTERM of untracked PID {pid}")


def _await_pid_death(pid: int, session_resolver) -> bool:
    """~10s bounded death poll (20 x 0.5s), the _stop_fallback (#903) shape.
    session_resolver._pid_alive is the ONE liveness seam (tests monkeypatch
    it + spawn_session.time.sleep)."""
    for _ in range(REAP_PID_DEATH_POLL_TRIES):
        time.sleep(REAP_PID_DEATH_POLL_INTERVAL_S)
        if not session_resolver._pid_alive(pid):
            return True
    return False
```

Design points baked in:

- **The daemon's tracking IS the identity anchor for legs 1–2** — `pidToTrackedSession` entries
  are created at the fork and deleted on exit (`onChildExited`, line 5583) or stop (line 5575),
  so a daemon-mediated kill can never hit a recycled pid the daemon isn't tracking.
- **`success: true` never short-circuits the death poll** — stopSession swallows kill errors
  and still untracks + returns true (lines 5560–5577), so the poll is the only death proof.
  A `success: true` also DELETES the tracking entry, so no daemon stop can be re-issued for the
  same pid; a survived poll therefore returns `reaped=False` (fail loud), never re-loops.
- **Transport failure ≠ `success: false`.** Legs 1–2 use `_stop_session_raw` (§4.3.1), which
  RAISES on transport failure; `success: false` (daemon reachable, pid untracked) is the only
  input to the already-gone / fallback branch. `_stop_spawned_session`'s `SystemExit → False`
  conversion is exactly the conflation this avoids.
- **tmux disposition (decided explicitly):** the daemon legs work for tmux-tracked entries too
  (they carry no `childProcess`, so stopSession takes the `process.kill(pid)` branch — verified
  lines 5330–5337 / 5567–5573), so legs 1–3 run unchanged for the ` (tmux)` variant. Only the
  CLIENT-side fallback (leg 4) is skipped for tmux — the tmux pane pid may be a shell wrapper
  rather than the node process (tmux runs the command string via the default shell), so the
  #903 /proc signature is unverified there; per the fail-loud rule the reap refuses with a
  "clean up via tmux" hint instead of guessing. EPS never sends `TMUX_SESSION_NAME`, so this
  variant is defensive-only in production (§2).
- The daemon's exit-handler (`happyProcess.on("exit")` → `onChildExited(pid)`, line 5450)
  untracks a fallback-SIGTERMed child once the pid dies, so leg 4 leaves no stale daemon state.

### 4.3.1 `_stop_session_raw(session_id)` (new small helper, next to `_stop_spawned_session`)

```python
def _stop_session_raw(session_id: str) -> bool:
    """Daemon /stop-session with transport failures kept DISTINGUISHABLE from
    the daemon's own verdict: returns the response `success` boolean
    (stopSession's return — true == a tracked entry was found+killed+untracked,
    false == no tracked entry for this sessionId/PID-<pid>); RAISES
    RuntimeError on any transport failure (daemon unreachable, timeout, HTTP
    error, unparseable body). Used by the #956 reap, where 'daemon said no
    such pid' feeds the already-gone verdict but 'daemon unreachable' must
    block the retry. _stop_spawned_session (which conflates the two as False)
    keeps its existing callers unchanged."""
    url = f"http://127.0.0.1:{daemon_port()}/stop-session"
    req = urllib.request.Request(
        url, data=json.dumps({"sessionId": session_id}).encode(),
        headers={"Content-Type": "application/json"}, method="POST",
    )
    try:
        with urllib.request.urlopen(req, timeout=DEFAULT_TIMEOUT_S) as resp:
            return bool(json.loads(resp.read()).get("success"))
    except (urllib.error.URLError, OSError, TimeoutError, json.JSONDecodeError) as e:
        raise RuntimeError(f"daemon /stop-session transport failure: {e}") from e
```

(`urllib.error.HTTPError` is a `URLError` subclass, so a 4xx/5xx also raises RuntimeError —
correct: the route's contract is HTTP 200 `{success}`, anything else is a transport-level
anomaly, not a verdict.)

## 11. Decision Rationale (load-bearing design constants)

1. **STOP-then-RETRY, not adoption.**
   *What:* the new leg never adopts/registers the half-spawned session.
   *Why:* unlike the client-socket-timeout case (daemon succeeded; adoption safe), here the
   daemon itself declared the handshake failed; the incident's two children sat live-but-EMPTY —
   registering one risks a #685-class idle driver the watcher then trusts. The prompt seeding is
   child-side env (bundle line 2625), so it *may* eventually fire — "may" is exactly the
   ambiguity a crash-recovery registration must not be built on.
   *Source:* task #956 body (observed live-but-empty sessions); bundle lines 5466/2625;
   `_verify_happy_patch_or_die` docstring (the idle-session failure class).
   *Alternatives:* poll for the late webhook and adopt on arrival — rejected: unbounded health
   ambiguity, and a fresh spawn after reap is deterministic and cheap.
2. **`WEBHOOK_TIMEOUT_MAX_RETRIES = 1`.**
   *What/Why:* one retry converts the observed transient into success without hammering a loaded
   daemon; the watcher passes (`proposed_infra_sweep`, capacity-retry, crash-recovery) re-drive
   later if the retry also fails.
   *Source:* task #956 body ("retry the spawn once with backoff"; incident: failure ×2 then
   success on the third invocation — the observed failure was transient across invocations,
   which supports a safe, sometimes-sufficient retry, not a success guarantee).
3. **`WEBHOOK_TIMEOUT_RETRY_BACKOFF_S = 30.0`.**
   *What/Why:* 2× the daemon's 15 s webhook window (bundle `15e3`, lines 5341/5468), giving a
   loaded daemon a full drain window; same order as `SPAWN_SESSION_TIMEOUT_S = 60` (#524
   rationale comment). Worst-case added wall ≈ 100 s ≪ `DISPATCH_LEASE_TTL_S` = 900 s, so the
   retry stays inside the held #843 lease.
   *Source:* daemon bundle; `spawn_session.py` lines 107, 873–885.
4. **PID-match regex `r"Session webhook timeout for PID (\d+)(?P<tmux> \(tmux\))?"`.**
   *What/Why:* exact literals of the two daemon emission sites; the ` (tmux)` group is now
   NAMED so the reap knows which spawn path fired (the tmux disposition, §4.3). The incident
   hit the regular path — no suffix.
   *Source:* bundle lines 5346 + ~5466; incident string verbatim in the #956 body.
5. **Single `/list` read to pick the sid leg (no sid-wait loop).**
   *What/Why:* waiting for a late webhook only upgrades PID-stop→sid-stop cosmetically (both
   route through the SAME daemon `stopSession`, line 5559); a single read bounds reap latency.
   *Alternatives:* poll ≤20 s for the sid — rejected (latency for no safety gain).
6. **Additive reap mirroring `_stop_fallback` / `_stop_spawned_session` instead of refactoring
   them.**
   *What/Why:* their exact messages/behavior are pinned by existing tests and operators (#903
   round-1 critique history); documented duplication beats a shared helper that risks
   regressing tested paths. The `os.kill` (not `killpg`) shape follows the tested precedent.
   The SURVIVOR DISPOSITION deliberately diverges (entry 11); the divergence is documented in
   the new function's docstring.
   *Source:* `spawn_session.py` lines 2113–2195 (#903); `.claude/rules/crash-fix-rounds.md`
   kill-ownership discipline (never kill on ambiguity).
   *Alternatives:* `os.killpg` (the child is `detached: true`, a group leader) would take the
   inner claude too — rejected for consistency with the tested precedent; the survivor-blocks
   rule (entry 11) covers the gap more safely than a broader kill.
7. **`/proc/<pid>/cwd == directory` as a fourth identity check (fallback leg only).**
   *What/Why:* available here (the failed request names its spawn directory) and stronger than
   the #903 trio alone against PID recycling; unreadable cwd does not disqualify (the three
   precedent checks still hold) but a MISMATCH always refuses. Only the fallback leg needs it —
   the daemon legs are anchored by the daemon's own tracking.
   *Source:* bundle `spawnHappyCLI` (cwd = spawn directory, lines 3988–3992);
   `crash-fix-rounds.md` discriminator pattern (cwd + lstart).
8. **Strict `/list` for the late-handshake probe (scope corrected this revision).**
   *What/Why:* lenient `_live_children()` returns `[]` on a daemon hiccup — the reap would then
   silently skip the sid leg and proceed on wrong evidence. Strict mode raises; the reap
   reports not-reaped and the caller exits without retrying (fail fast). NOTE the v1 rationale
   ("[] would read as already-gone") no longer applies — under the corrected semantics /list
   absence is the NORMAL never-handshaken state and the already-gone verdict moved to the
   PID-stop `success: false` + `_pid_alive` false signal (§4.3 leg 3).
   *Source:* `_live_children` body (line 1017 swallow list); the body's fail-fast constraint;
   bundle line 4079 (the /list filter).
9. **Daemon-mediated `PID-<pid>` stop as the PRIMARY no-sid reap leg (NEW this revision).**
   *What/Why:* the daemon's `stopSession` matches `sessionId.startsWith("PID-") && pid ===
   parseInt(...)` over its own `pidToTrackedSession` and kills the tracked child itself
   (`childProcess.kill("SIGTERM")` for daemon-spawned children, `process.kill(pid)` otherwise),
   then untracks it. The daemon only kills a pid IT tracks — its tracking entry was created at
   the fork — so this leg eliminates most client-side PID-recycle mis-kill exposure and needs
   no /proc heuristics. The client-side death poll remains load-bearing because stopSession
   swallows kill errors and returns true anyway.
   *Source:* bundle `stopSession` PID- branch, line 5559 (verified by grep this revision);
   `/stop-session` route `{success: boolean}` response, lines 4086–4102; the reconciled
   alternatives verdict on #956 plan v1.
   *Alternatives:* client-side identity-checked SIGTERM as primary (v1's design) — rejected:
   built on the false premise that the daemon cannot address a no-sid child; keeps avoidable
   PID-recycle exposure. Retained only as the leg-4 fallback (entry 10).
10. **Residual client-side identity-checked SIGTERM: FALLBACK ONLY, for the
    untracked-but-alive anomaly.**
    *What/Why:* PID-stop `success: false` + pid alive means the daemon does not track a pid the
    daemon's own 500 named moments earlier. Real path to that state: a daemon restart between
    fork and reap orphans the child from tracking (in-memory map); nothing else would ever reap
    it. The four stacked identity checks (comm/cmdline/daemon-pid/cwd) bound the mis-kill risk,
    and ambiguity always refuses (reaped=False → no retry). The tradeoff made explicit:
    `success: false` (daemon reachable — a verdict about tracking state) is acted on;
    a TRANSPORT failure (daemon unreachable — no evidence) is never acted on — `_stop_session_raw`
    raises on transport failure and the reap returns reaped=False there, so the two are
    structurally impossible to conflate (unlike `_stop_spawned_session`'s `SystemExit → False`).
    *Alternatives:* drop the client leg entirely and fail loud — safer against mis-kill but
    leaves the daemon-restart orphan permanently leaked (the exact #956 failure class) until a
    human intervenes; rejected because the 4-check refusal discipline already fails safe.
    *Source:* bundle `onChildExited` line 5583 (self-exit untracks — the benign cause of
    `success: false`); #903 identity-check precedent; the reconciled alternatives verdict.
11. **Inner-claude survivor after ANY kill leg → `reaped=False` (blocks the retry; NEW this
    revision, MUST-FIX 3).**
    *What/Why:* the daemon and fallback legs both kill the WRAPPER process; the inner `claude`
    (resolved pre-kill via `resolve_claude_pid`, a /proc descendant walk) can survive either
    way. Retrying over a live inner claude recreates the live-unmapped-work class at process
    level — two claude processes doing the same issue's work (double-spawn). So a detected
    survivor blocks the retry and exits loud with the survivor pid. DIVERGENCE from the #903
    `_stop_fallback` precedent (survivor = warning only) is deliberate and documented in the
    docstring: #903's context is a takeover stop with no retry following; here a retry follows.
    Best-effort limits: `resolve_claude_pid` can return None (no claude child yet — common for
    a just-forked wrapper), and a wrapper that already exited before the reap leaves no handle
    to its orphaned claude (documented residual risk, §12.11).
    *Source:* the reconciled alternatives verdict on #956 plan v1; `session_resolver.py`
    lines 255–280.
