<li><b>What would change my mind:</b> If the fallback ever reaches the paid RunPod GPUs <i>before</i> exhausting every free/cheaper option — that would mean we're spending money we didn't need to. The whole point is that RunPod is the last resort, never the first reflex.</li>
</ul>

<h2>§1. Goal</h2>
<p>
Make the backend router resilient to GCP A100-80 quota/capacity exhaustion: instead of hard-failing (the #654 incident, an explicit <code>backend: gcp</code> launch that died with <code>NoComputeAvailableError</code> when on-demand A100-80 quota was full), the router walks a cost-ordered fallback ladder — cheaper/smaller GCP options first, paid RunPod last — so a launch lands <i>somewhere</i> without a human in the loop. The ladder must apply to BOTH the <code>auto</code> lane and an explicit <code>backend: gcp</code> pin, and reverse the standing no-auto-RunPod safety invariant to allow RunPod as the documented final rung (user-directed). This is launcher plumbing; no experiment runs.
</p>

INTENT_A100_40_FALLBACK: dict[str, MachineSpec] = {

<h3>4.4 The "short job" predicate (router.py)</h3>
<p>SPOT (interruptible) is only safe for a job that can absorb a preemption — a "short" job. Add to <code>router.py</code>:</p>
<pre><code>#: Default GPU-hour threshold below which a job is "short" enough to risk
#: SPOT preemption. Env-overridable via EPS_GCP_SPOT_MAX_GPU_HOURS.
DEFAULT_SPOT_MAX_GPU_HOURS: float = 2.0
ENV_SPOT_MAX_GPU_HOURS: str = "EPS_GCP_SPOT_MAX_GPU_HOURS"

def _spot_max_gpu_hours() -> float:
    raw = os.environ.get(ENV_SPOT_MAX_GPU_HOURS, "").strip()
    if not raw:
        return DEFAULT_SPOT_MAX_GPU_HOURS
    try:
        return float(raw)
    except ValueError:
        logger.warning("EPS_GCP_SPOT_MAX_GPU_HOURS=%r unparseable; using default %g",
                       raw, DEFAULT_SPOT_MAX_GPU_HOURS)
        return DEFAULT_SPOT_MAX_GPU_HOURS

def _estimated_gpu_hours(spec: RunSpec, machine: MachineSpec) -> float | None:
    """Estimate GPU-hours = wall-budget x gpu_count. None when no budget is set.

    Reads spec.extra['estimated_gpu_hours'] first (explicit override from the
    plan), else spec.time_budget_hours * gpu_count. Returns None when neither
    is available -> CONSERVATIVE: an unknown-length job is NOT short.
    """
    explicit = (spec.extra or {}).get("estimated_gpu_hours")
    if explicit is not None:
        try:
            return float(explicit)
        except (TypeError, ValueError):
            return None
    if spec.time_budget_hours is None:
        return None
    return float(spec.time_budget_hours) * max(1, machine.gpu_count)

def _is_short_job(spec: RunSpec, machine: MachineSpec) -> bool:
    """True when the job is short enough to risk SPOT. UNKNOWN length -> False."""
    gh = _estimated_gpu_hours(spec, machine)
    return gh is not None and gh <= _spot_max_gpu_hours()</code></pre>
<p>Conservative default is load-bearing: a job with no budget set is treated as NOT short, so it skips SPOT and falls to RunPod — never silently preempted. <b>Recorded in §11.</b></p>

<h3>4.5 The GCP ladder helper (router.py)</h3>
<p>Both the auto-GCP path (<code>_attempt_gcp_lane</code>) and the explicit-gcp path (<code>_override_free_or_gcp</code>) currently try ONE provisioning attempt (STANDARD on-demand A100-80) and then either continue/skip (auto, non-terminal) or raise (explicit gcp). I introduce a single helper that builds the ordered list of GCP <i>rung specs</i> to try, used by both paths:</p>
<pre><code>def _gcp_ladder_specs(spec: RunSpec) -> list[tuple[RunSpec, str]]:
    """Ordered (spec, rung_label) GCP provisioning attempts, cheapest-effective first.

    Rung 1: on-demand A100-80 (the spec as-is)             -> label 'ondemand_a100_80'
    Rung 2: on-demand A100-40 (if intent fits 40GB)        -> label 'ondemand_a100_40'
    Rung 3: SPOT A100-80   (if short job)                  -> label 'spot_a100_80'
    Rung 4: SPOT A100-40   (if short job AND fits 40GB)    -> label 'spot_a100_40'

    Each rung-spec is a dataclasses.replace of the input with the right
    provisioning_model / machine_spec_override in extra, so machine_for_intent,
    quota_metric_for, and the zone filter all resolve the rung's true machine.
    Rungs that don't apply to this intent/length are simply absent.
    """
    base = machine_for_intent(spec)             # resolves overrides too
    rungs: list[tuple[RunSpec, str]] = [(spec, "ondemand_a100_80")]
    a40 = a100_40_fallback_for_intent(spec)
    if a40 is not None:
        rungs.append((_with_machine(spec, a40, provisioning="STANDARD"), "ondemand_a100_40"))
    if _is_short_job(spec, base):
        rungs.append((_with_machine(spec, base, provisioning="SPOT"), "spot_a100_80"))
        if a40 is not None:
            rungs.append((_with_machine(spec, a40, provisioning="SPOT"), "spot_a100_40"))
    return rungs

def _with_machine(spec, machine: MachineSpec, *, provisioning: str) -> RunSpec:
    return replace(spec, extra={
        **(spec.extra or {}),
        "machine_spec_override": {"machine_type": machine.machine_type,
                                  "gpu_count": machine.gpu_count, "gpu_kind": machine.gpu_kind},
        "machine_kind_tag": machine.gpu_kind,
        "provisioning_model": provisioning,
    })</code></pre>
<p><b>Ladder semantics:</b> for each rung, run the SAME pre-check + create that <code>_attempt_gcp_lane</code> runs today (headroom pre-check, then <code>_prepare_and_launch</code>). A rung that fails on a positive insufficient-headroom reading OR a <code>GcpProvisioningError</code> capacity/zone miss → record the attempt, advance to the NEXT rung. A <code>GcpWorkloadError</code> on any rung → raise <code>WorkloadSurfacedError</code> immediately (broken workload code must not cascade — preserved from today). Each rung's attempt is recorded in <code>attempts</code> AND posted as an <code>epm:backend-selected</code> intermediate marker (reusing <code>_post_intermediate_marker</code> with a per-rung detail).</p>
<p><b>Per-day attempt-cap interaction:</b> the cap (default 5) currently bounds the number of GCP <i>provision attempts</i>. The ladder can make up to 4 GCP creates per launch. Decision (recorded §11): the cap counts <b>actual create attempts</b> across all rungs (a headroom-skip does NOT consume one, matching today), and the ladder STOPS issuing GCP creates once the cap is hit for the day — at which point it falls through to the next lane / RunPod. This keeps the cap meaningful (bounds spend) without bricking the ladder mid-rung. The cap stays an attempt-COUNT guard, never dollars.</p>

<h3>4.8 The RunPod terminal rung (the reversed invariant)</h3>
<p>Add one helper, called from BOTH the auto terminal (<code>_auto_route</code> end) and the explicit-gcp exhaustion point:</p>
<pre><code>def _runpod_terminal_rung(*, spec, runpod_backend, store, attempts, started_at,
                          now_fn, marker_poster, on_launched, residual_gap: str) -> RouteResult:
    """Final fallback rung: launch on RunPod after every GCP rung (+ SLURM,
    if wired) is exhausted. Logs the residual gap LOUDLY in the marker.

    This is the deliberate reversal of the historical no-auto-RunPod
    invariant (user-directed 2026-06-17, task #656). RunPod is reached ONLY
    here -- after the cost-ordered GCP ladder AND the free SLURM lanes (in
    the auto chain) have all failed. The launch is the same shape as the
    explicit `backend: runpod` override (_override_runpod), reusing the
    per-issue flock + on_launched persistence.
    """
    logger.warning("route: GCP ladder (and free lanes, if any) exhausted for issue %d; "
                   "falling back to RunPod (residual gap: %s).", spec.issue, residual_gap)
    runpod_spec = replace(spec, backend="runpod",
                          extra={**(spec.extra or {}), "runpod_fallback_residual_gap": residual_gap})
    handle = _prepare_and_launch(runpod_backend, runpod_spec, kind="runpod")
    _invoke_on_launched(on_launched, handle)
    attempts.append(RouteAttempt(kind="runpod", cluster=None, est_start_seconds_raw=0.0,
        est_start_seconds_clamped=0.0, outcome="launched",
        detail=f"runpod terminal fallback (residual gap: {residual_gap})",
        elapsed_seconds=now_fn() - started_at))
    result = RouteResult(backend=runpod_backend, handle=handle, requested_kind=spec.backend,
        chosen_kind="runpod", reason=ROUTE_REASON_RUNPOD_FALLBACK, cluster=None,
        attempts=attempts, elapsed_seconds=now_fn() - started_at,
        extra={"runpod_fallback_residual_gap": residual_gap})
    _post_backend_selected(result, spec=spec, marker_poster=marker_poster)
    return result</code></pre>
<p>Add a new route-reason constant <code>ROUTE_REASON_RUNPOD_FALLBACK = "auto_fallback_runpod"</code> (distinct from <code>ROUTE_REASON_OVERRIDE</code> so the marker trail distinguishes "user pinned RunPod" from "router fell back to RunPod"). The residual-gap string names which rungs exhausted, e.g. <code>"gcp on-demand A100-80/A100-40 + spot exhausted; no free SLURM lane wired"</code> (auto) or <code>"explicit gcp pin: A100-80/A100-40 + spot exhausted"</code> (explicit).</p>
<p><b>Fail-safe when <code>runpod_backend</code> cannot be reached:</b> if the RunPod launch itself raises (provisioning failure on RunPod too), re-raise as <code>NoComputeAvailableError</code> with the full attempt trail — the terminal "truly no compute anywhere" outcome. This preserves a typed terminal for the orchestrator.</p>

<h2>§11. Decision Rationale</h2>
<p><b>N/A — no model training</b> (no learning rate / epochs / LoRA / batch). This section instead records the load-bearing DESIGN choices for the infra change.</p>
<ul>
<li><b>A100-40 = <code>a2-highgpu-1g</code> (1× A100-40GB), fits single-GPU 7B work.</b> <i>Why:</i> a 7B LoRA fine-tune / eval / generation fits comfortably in 40 GB (the project's whole lora-7b line runs on a single 40-80GB GPU); the A100-40 on-demand quota pool is separate from A100-80, so it can have headroom when 80GB is full. <i>Source:</i> GCP machine-type catalog (a2-highgpu-1g = 1×A100-40GB) + the repo's own <code>lora-7b</code> intent already sized at 1×A100-80 (gcp.py:284). <i>Alternatives rejected:</i> 2×A100-40 (overkill for LoRA); leaving lora on 80GB only (the #654 hard-block this task removes).</li>
<li><b>A100-40 NOT a fallback for <code>ft-7b</code> / 70B intents.</b> <i>Why:</i> ft-7b is 4×A100-80 (ZeRO-3, 7B full FT needs the 80GB HBM per the gcp.py table + the intent→GPU rules); a 40GB card cannot hold it. 70B intents have no GCP mapping at all (RunPod-only by design). <i>Source:</i> gcp.py INTENT_TO_MACHINE (ft-7b → a2-ultragpu-4g) + CLAUDE.md GPU-intent table.</li>
<li><b>SPOT only for "short" jobs, default threshold 2 GPU-h, env-overridable.</b> <i>Why:</i> a preemptible instance can be reclaimed mid-run; a long training job loses hours of work on preemption, but a short eval/LoRA absorbs a restart cheaply. The 2 GPU-h default matches the task body's stated default; env override (<code>EPS_GCP_SPOT_MAX_GPU_HOURS</code>) lets the operator tune it without a code change. <i>Source:</i> task #656 body (originating prompt, threshold ~2 GPU-h env-overridable). <i>Alternatives rejected:</i> always-spot (loses long-job work); never-spot (wastes the idle preemptible pool the #537 incident flagged — 16 preemptible A100 sat idle while a STANDARD launch skipped GCP).</li>
<li><b>Unknown job length ⇒ NOT short ⇒ no spot.</b> <i>Why:</i> a conservative default keeps a long-but-unannotated job off spot rather than risking a silent preemption loss; the cost is only that such a job skips the spot rung and goes to RunPod. <i>Source:</i> fail-safe design principle (CLAUDE.md "Fail fast — never hide failures" + the #537 "non-recoverable run must never be silently preempted" rule).</li>
<li><b>RunPod terminal rung reverses the no-auto-RunPod invariant.</b> <i>Why:</i> user-directed (task #656 originating prompt, 2026-06-17) — RunPod is the explicit final fallback so a launch never hard-blocks; the cost-safety property is preserved by ordering (RunPod reached ONLY after every cheaper GCP rung + free SLURM lane), by the loud residual-gap marker, and by keeping the GPU-hour cap. <i>Source:</i> task #656 body + originating prompt.</li>
<li><b>New short-job gate supersedes the #537 <code>EPS_GCP_SPOT_FALLBACK</code>+<code>spot_tolerant</code> gating for the ladder; <code>spot_tolerant</code> retained as a force-spot override.</b> <i>Why:</i> #537's gated SPOT fallback was a narrow fix; the ladder makes spot-for-short-jobs the default behavior (a superset). Keeping <code>spot_tolerant</code> honored lets a caller force spot for a job past the threshold (explicit opt-in to preemption). <i>Source:</i> router.py #537 machinery (lines 1587-1640) read this session.</li>
<li><b>Machine-type override threaded via <code>spec.extra["machine_spec_override"]</code>, consumed at the <code>machine_for_intent</code> chokepoint.</b> <i>Why:</i> <code>RunSpec</code> is frozen and <code>intent</code> is semantic (drives more than machine type); overriding the resolved MachineSpec via <code>extra</code> keeps the change auditable (rides in markers/sidecar) and routes through the single existing chokepoint that quota-metric + zone-filter + create all already call. <i>Source:</i> base.py RunSpec (frozen, mutable <code>extra</code>) + gcp.py machine_for_intent chokepoint.</li>
<li><b>Per-day GCP attempt cap counts actual creates across rungs; ladder stops issuing creates at the cap and falls through.</b> <i>Why:</i> the cap bounds spend; headroom-skips (no create) don't consume it (today's behavior); hitting the cap mid-ladder falls to the next lane / RunPod rather than bricking. <i>Source:</i> router.py <code>_attempt_gcp_lane</code> cap logic (lines 2839-2887) read this session. <i>Stays count-based, never dollars.</i></li>
