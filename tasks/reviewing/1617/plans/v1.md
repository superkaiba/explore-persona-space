### Step 2 — probe + argv builder + key registry (gcp.py, near `render_list_argv` `:3255` / `_read_guest_phase` `:3857`)

```python
#: Fresh boot disks are seconds old at probe time (probe runs right after the
#: create call returns, itself capped at GCLOUD_DEFAULT_TIMEOUT_SEC=300s); a
#: surviving prior-attempt disk is at minimum hours old (#779: 20 days).
_BOOT_DISK_REUSE_SLACK_SEC = 600

#: The additive observability keys router._attempt_one_gcp_rung lifts onto the
#: final epm:backend-selected marker extra (#1617).
BOOT_DISK_MARKER_EXTRA_KEYS: tuple[str, ...] = (
    "boot_disk_reused", "boot_disk_age_days", "boot_disk_size_gb",
    "boot_disk_requested_gb", "boot_disk_size_mismatch", "boot_disk_probe_error",
)

def render_disk_describe_argv(*, config: GcpConfig, name: str, zone: str) -> list[str]:
    """gcloud compute disks describe argv for the instance's same-name boot disk."""
    argv = _base_gcloud_argv(config, "compute", "disks", "describe", name)
    argv += [f"--zone={zone}", "--format=json"]
    return argv

def _probe_boot_disk(
    *, config: GcpConfig, name: str, zone: str, requested_gb: int,
    runner: GcloudRunner, now_fn: Callable[[], float] = time.time,
) -> dict[str, Any]:
    """Post-create boot-disk observability probe (#1617; incident #779). NEVER raises."""
    try:
        result = runner(render_disk_describe_argv(config=config, name=name, zone=zone))
        if result.returncode != 0:
            return {"boot_disk_probe_error":
                    f"disks describe rc={result.returncode}: {(result.stderr or '')[:200]}"}
        disk = json.loads(result.stdout)
        size_gb = int(disk["sizeGb"])                       # API returns a STRING, e.g. "300"
        created = datetime.fromisoformat(disk["creationTimestamp"])  # RFC3339 w/ offset
        age_sec = max(0.0, now_fn() - created.timestamp())
        fields: dict[str, Any] = {
            "boot_disk_size_gb": size_gb,
            "boot_disk_age_days": round(age_sec / 86400.0, 2),
            "boot_disk_requested_gb": int(requested_gb),
            "boot_disk_reused": age_sec > _BOOT_DISK_REUSE_SLACK_SEC,
        }
        if size_gb != int(requested_gb):
            fields["boot_disk_size_mismatch"] = True        # omit-when-false (#1010 pattern)
        return fields
    except Exception as exc:  # observability must never fail a live launch
        return {"boot_disk_probe_error": f"{type(exc).__name__}: {exc}"[:300]}
```

Detection is **age-based via `disks describe`**, not gcloud-stderr text parsing (warning wording is CLI-version-dependent; the describe read is API-stable and gives age + size in one call). `datetime` import: module already imports `json`/`time`; add `from datetime import datetime` if absent.

## 6. Kill criteria

What would make this change wrong, and the evidence that would show it:

1. **The probe materially delays launches.** Evidence: fake-timed or live measurement showing `disks describe` consistently > ~30 s. Pre-checked: the identical-API `disks list` returned in ~1 s against the live project this session, and the runner's 300 s cap bounds the worst case (vs multi-minute create calls). If it ever proves slow in production, the fallback is an env kill-switch (`EPS_SKIP_BOOT_DISK_PROBE=1`) — a follow-up, not a blocker.
2. **The reuse mechanism doesn't exist / #779 had a different cause.** Evidence that would show it: `disks describe` on a post-create instance never showing an old `creationTimestamp`, or the #779 record showing the 300 GB realized size came from the argv. Pre-refuted: gcloud docs (boot-disk flags apply only to newly created disks; same-name disk attached instead) + the #779 att-20260722-155004 record (20-day-old 300 GB disk vs `--boot-disk-gb 200`).
3. **`epm:backend-selected` cannot carry post-create facts** (i.e. it were posted before the create). Pre-refuted by code read: `_post_backend_selected` fires after `launch()` returns (`router.py:5430`).
4. **The probe destabilizes launch()** (any path where a probe failure fails a live launch). Evidence: the raising-runner unit test failing. This is a hard blocker — the fail-soft contract is non-negotiable; if it can't be met the change is reverted.

## 11. Decision Rationale

1. **Marker landing spot — BOTH `epm:backend-selected` extra (via router lift) and `epm:cluster-launched` body (gcp-owned).** *Why:* the Goal names `epm:backend-selected`; code read confirms the final gcp rung marker posts AFTER `launch()` returns (`router.py:5430`), so post-create facts can ride it — the lift mirrors `realized_gpu_count` (#1121). `epm:cluster-launched` additionally covers every fresh create regardless of router path and is the gcp-owned marker with the #632 additive-field precedent. *Source:* `router.py:5404-5430`, `gcp.py:5369-5398`, #632. *Alternative rejected:* cluster-launched only — would deviate from the Goal's named spot for no benefit.
2. **Detection = `disks describe` age heuristic, not gcloud stderr parsing.** *Why:* create-success stderr is currently discarded and its warning text is CLI-version-dependent; the Disk resource's `creationTimestamp`/`sizeGb` are stable public API fields, live-verified on this project, and give age + realized size in one call (create stdout carries neither age nor, reliably, realized size). *Source:* live `disks list` read 2026-07-23; gcloud reference docs (below). *Alternative rejected:* parsing create stderr WARNING lines (brittle; kept only as optional future log enrichment).
3. **Fail-soft policy: probe failure → `boot_disk_probe_error`, never a raised launch.** *Why:* observability must never kill a live, billing VM launch — the same contract as `_post_marker_nonfatal` (`router.py:5786-5799`) and the marker-post `try/except` in `launch()` (`gcp.py:5391-5407`). *Source:* those two in-repo precedents. *Alternative rejected:* `GcpProbeError`-style fail-loud (correct for reconnect state probes where wrong reads spend money, wrong here where the read is purely diagnostic).
4. **Mismatch compares against the CLAMPED effective value.** *Why:* the #1336 clamp already warns separately; comparing against the pre-clamp request would false-flag every sub-100 GB request. A shared `effective_boot_disk_gb()` prevents drift between argv and probe. *Source:* `gcp.py:3101-3111` (#1336). *Alternative rejected:* inline duplication of the clamp expression at the probe call site.
5. **`_BOOT_DISK_REUSE_SLACK_SEC = 600`.** *Why:* a fresh disk's age at probe time is bounded by the create call (≤ `GCLOUD_DEFAULT_TIMEOUT_SEC` = 300 s) + seconds of overhead, so 600 s admits no false positives; a genuinely surviving disk is ≥ hours old (#779: 20 days), so false negatives require a < 10-min relaunch-reuse — where the size-mismatch arm still fires. *Source:* `gcp.py:3727` + #779 incident record. *Alternative rejected:* comparing `lastAttachTimestamp` deltas (also available, adds complexity without changing any verdict).
6. **Field names `boot_disk_reused` / `boot_disk_age_days` / `boot_disk_size_gb` / `boot_disk_size_mismatch` (+ `boot_disk_requested_gb`, `boot_disk_probe_error`).** *Why:* verbatim from the candidate block (grep-findable against the verified-at-filing record); `boot_disk_size_gb` (realized) deliberately distinct from the existing `boot_disk_gb` (spec-requested) key to avoid collision; mismatch omit-when-false per the #1010 footprint-key pattern, `reused` always-present-on-success so "checked, fresh" is distinguishable from "not checked". *Source:* task #1617 candidate block; `gcp.py:5335-5342` (#1010).
7. **Scope = fresh creates only (no reconnect probe).** *Why:* reuse happens at CREATE time; a reconnect rejoins a live instance whose disk facts were recorded at its own create. Probing on reconnect would add a gcloud call to the hot idempotent re-entry path for no new information. *Source:* `gcp.py:4929-4955`.
