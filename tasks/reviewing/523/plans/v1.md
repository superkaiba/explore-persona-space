### Phase D — Held-out CV scoring: cell-fixed headline + nested-search diagnostic (CPU-only, dev VM, ~1 h)

**Two outputs run side-by-side under one shared 13-fold LOCO scheme.** The cell-fixed output answers the Goal's cell-specific question; the nested-search output is the search-procedure / selection-inflation diagnostic. Both share the SAME fold definition so the four headline bars are directly comparable.

**Fold semantics (binding choice — picked to dissolve the previous draft's pair-coverage ambiguity).** **Leave-one-SOURCE-condition-out** across the 13 non-stylized source conditions (drop A3/A4/A5 from the 16; 13 source conditions remain → 13 folds). At fold k, the held-out class is non-stylized source S_k:
- `test_pairs(k) = { (A=S_k, B=T) : T ∈ non-stylized 13 conds, T ≠ S_k }` → **exactly 12 test pairs per fold**
- `train_pairs(k) = { (A=A', B=B') : A',B' ∈ non-stylized 13 conds, A' ≠ S_k, A' ≠ B' }` → 132 train pairs per fold

This scheme gives each of the 156 non-stylized ordered pairs membership in EXACTLY ONE outer fold (its source-side fold), 13 × 12 = 156 → 156 unique, no double-counting. The 13 per-fold outer R² values are therefore independent on the test side and the fold-level paired bootstrap is structurally valid. (The previous draft's "leave-one-non-stylized-class-out, pair touches K" pseudocode would have given 24 pairs/fold × 13 folds = 312 fold-pair assignments with each pair landing in two folds — the bootstrap-over-folds then assumes a fold-independence the design violates. This binding fold rewrite resolves that. `Source: #502 LOCO scheme adapted; methodology-lens reconciler.`)

The implementer asserts `len(test_pairs(k)) == 12 for all k` and `union over k of test_pairs(k) == the 156 non-stylized ordered pairs` at the top of `issue523_phase_d_nested_cv.py` before any scoring runs.

```python
    # Length-controlled linear fit of FIXED_CELL predictor distances → ΔG, on train_pairs
    fit = linreg(predictor=FIXED_CELL, target="ΔG_seed42", on=train_pairs, length_control=True)
    outer_r2 = cv_r2(predict(fit, test_pairs), ΔG_values(test_pairs))
    record(outer_fold, outer_r2)
cell_fixed_cv_r2_seed42 = mean(outer_r2 across 13 folds)
```

Run the same loop with `target="ΔG_seed43"` to get `cell_fixed_cv_r2_seed43`.

**This is the Goal's cell-specific answer.** Reported with 2000 paired fold-bootstrap CIs (resample 13 folds with replacement, recompute mean → 2000 means → 2.5/97.5 percentiles).

#### Output 2 — Nested-search diagnostic (the selection-inflation / ridge survival check)

```python
# Nested-search: 1737-cell inner search per fold; same 13-fold outer scheme as Output 1
for outer_fold in leave_one_source_condition_out_folds():
    train_pairs = train_pairs(outer_fold)
    test_pairs  = test_pairs(outer_fold)
    # INNER: full 1737-cell search on train_pairs only
    best_cell = argmax over (extraction_point, layer, metric, variant) of inner_loocv_r2(train_pairs)
    outer_r2 = cv_r2(predict(best_cell_predictor, test_pairs), ΔG_values(test_pairs))
    record(outer_fold, best_cell, outer_r2)
nested_search_cv_r2_seed42 = mean(outer_r2 across 13 folds)
```

**Inner selection grid.** The full 1737-cell search per #502, confirmed against `eval_results/issue_502/bakeoff/bakeoff_grid.json` `loc_ep1.rows` length. Inner selection by leave-one-source-condition-out CV R² on the inner training fold (matching the outer scheme).

This output answers "does the 1737-cell selection scheme as a procedure survive honest evaluation?" — a different (procedural) question from the Goal's cell-specific question. Reported with 2000 paired fold-bootstrap CIs.

#### Decomposition + diagnostic outputs

The cell-fixed + nested-search outputs together decompose pool / selection / seed shrinkage of #502's 0.34 in-sample non-stylized number. Per the methodology-lens reconciler:

- **Pool shrinkage** = #502's in-sample 0.34 minus `cell_fixed_cv_r2_seed42` on the new pool. Same cell, same scoring; the difference is purely the pool variable.
- **Selection inflation** = `cell_fixed_cv_r2_seed42` minus `nested_search_cv_r2_seed42`. Same pool, same seed, same outer fold; the difference is purely the inner-selection step.
- **Seed shift** = `cell_fixed_cv_r2_seed42` minus `cell_fixed_cv_r2_seed43`. Same cell, same pool, same outer fold; the difference is purely the training-seed variable.

Plus the descriptive diagnostics:
- **The "what cell got picked" tally across the 13 nested-search folds**: how many select `last_prompt × L22 × gauss_kl × raw` exactly, AND (separate row) how many select something in the L19-L24 × gauss_kl ridge. If exact L22 is picked < 7/13 but the L19-L24 × gauss_kl ridge is picked ≥ 10/13, the headline retires from "L22 gauss_kl cell" to "mid-stack gauss_kl ridge."

The predictor-cell selection, distance computation, length-partial Spearman, and CV-R² scoring are deterministic numerical operations over already-extracted activation tensors. A model-call formulation isn't applicable — there is no unstructured-data heuristic in the design, only matrix algebra and rank statistics. (CLAUDE.md "Model call vs code" rule explicitly N/A.)

The seed-43 retrains in Phase B **reuse #474's localized-arm contrastive negative recipe verbatim**: 300 positives + 300 negatives across 5 contrastive transformations per cell, marker on positives, EOS on negatives at the post-response slot. The single manipulated variable in Phase B is the training seed (42 → 43). The contrastive-negatives rule (CLAUDE.md + `.claude/rules/contrastive-negatives.md`) is satisfied by inheritance from #474.

The seed-43 sweep is the existing `i474_phase23_dispatch.sh` invoked with `--smoke-only` for the smoke phase and the full waves (filtered to loc-arm) for the sweep phase — same dispatcher, same subprocess shape, same env injection, same teardown.
