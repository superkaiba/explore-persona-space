## 1. Goal + Requirement

Document a durable subagent-side discipline in CLAUDE.md: **a background-Bash poll chain must be re-armed as the FIRST action of every wake, until the watched job reaches a terminal state.**

The rule closes a silent-failure mode observed on task #1947 (2026-08-04): two concurrent inline GPU rounds each armed a background-Bash poll against their own suffixed handle; within ~2h `pgrep -af 'backend_pol[l].py'` returned nothing — both chains dead, both 8-GPU queued jobs unwatched. Owning-agent forensics: "the prior tick had completed cleanly … its completion wake was consumed by an intervening teammate-message turn and I failed to re-arm in that turn." The orchestrator's own coordination messages (lane assignment, panel corrections) were the consuming traffic.

**Acceptance criteria (all mechanical):**

1. `CLAUDE.md` § `### Orchestrator vs subagent re-invocation`, immediately after the existing "End the turn when bg work is in flight" bullet (line 100 at the time of filing), carries a new bullet naming the rule.
2. A repo-wide `grep -n -iE 're-arm|rearm|consume.*wake|wake.*consume' CLAUDE.md` returns ≥1 hit AFTER the change (baseline: 0 hits — recorded in the task's `verified-at-filing:` line).
3. `uv run python scripts/workflow_lint.py` passes on the changed file; the `--check-lessons-index` invariant stays green (LESSONS.md is untouched because no new `.claude/rules/*.md` file is added or removed).
4. The added bullet does NOT contradict the existing bans in the same subsection: no foreground sleep chains, no bg sleep-loop watchers, no `nohup ... &` nested inside a bg-Bash whose exit is the completion signal. (These are separate bullets AT and AROUND line 100; the new bullet is additive.)
5. The Step 9c test-verdict gate PASSes (no `--pytest-rc` regression; no new pytest node failures).

## 2. Method delta (what differs from prior related work)

- **Prior related work:** the existing bg-poll bullet in the same subsection (CLAUDE.md:100) says "poll via a background `Bash` … load deferred tool schemas first". It bans sleep-chains and sleep-loop watchers but is silent on wake-slot arithmetic — it assumes each bg-Bash exit re-wakes the subagent, without saying that a message-delivery wake occupies the same slot. This plan adds the missing "who re-arms when" rule.
- **What's genuinely new:** the observation that the WAKE BUDGET is shared between tick-completion wakes and SendMessage/orchestrator-message wakes. `.claude/rules/pod-side-reporting.md` has poller-lifecycle guidance but is scoped to pod-side dispatchers, not orchestrator-side bg polls; `.claude/rules/gotchas.md` documents unrelated `#1310` inline-stdin drift. Neither anchors the wake-consumption mechanism the incident revealed.

## 4. Concrete diff

One block added to `CLAUDE.md`, inserted between the current line 100 bullet and the current line 101 bullet ("Ownership check before any resume/launch on a shared artifact path."). Wording:

```
- **Re-arm a bg-Bash poll chain as the FIRST action of every wake, regardless of what woke you, until the watched job reaches a terminal state
  (COMPLETED / FAILED / CANCELLED / TIMEOUT).** The wake slot is SHARED: an
  incoming SendMessage occupies the same wake the tick completion would have
  used, so a turn that handles a message and ends without re-arming kills the
  chain silently — no error, no marker, and the watched compute runs
  unobserved. Treat "have I re-armed?" as the first question of the turn, not
  the last. Size the cadence to the expected wait (a deep-queued job wants
  ~1800s, not ~540s): a short cadence multiplies wake count and therefore
  multiplies the chance that one wake is consumed without re-arming.
  (#1947, 2026-08-04: two concurrent lanes each lost their poll chain to
  orchestrator coordination traffic within ~2 h; both 8-GPU jobs sat queued
  and unwatched until a manual `pgrep` found it.)
```

Notes on wording:

- The bullet begins with an imperative verb form so it reads like the surrounding rules ("Never nest…", "Ownership check…").
- The parenthetical terminal-state list matches the SLURM/GCP/RunPod terminal states routinely surfaced by `backend_poll.py` PollResult (see `backends.base.PollResult`).
- The cadence guidance references the Step 6d.2 polling defaults (`540s` fixed chain, `1800s` recommended quiet-tick — CLAUDE.md § "ADAPTIVE POLL INTERVAL", line ~1560) so a reader can locate the concrete numbers.
- The incident anchor keys grep for future audits: `#1947`, `2026-08-04`, `re-arm`, `wake`.
- No `.claude/rules/*.md` cross-reference is added: making the rule always-on in CLAUDE.md is strictly stronger than an on-demand rule that fires only when its path pattern matches an open file.
