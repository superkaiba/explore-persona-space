## 12. Decision Rationale

**D1 — Section-presence predicate alone; NO byte threshold.**
- **What:** husk = file present+fresh AND (`## Applied workflow improvements` H2 missing OR section body has no non-blank line before the next `## `). No size check.
- **Why:** the sketch's `< ~1500 bytes` arm false-alarms: a legitimate quiet day (placeholder one-liners in every section) is ~600–700 bytes, well under 1500, while observed real files (5.6–19.6 KB, `logs/daily/` listing 06-24→07-08) prove nothing about the *floor*. The section check keys on the skill's own done-predicate — § Output's refuse rule already defines "day is done" as non-empty Applied — so detector and skill share one definition; and it adds zero missed coverage: the skeleton has an empty Applied section *by construction*, so every husk the byte check would catch, the section check catches.
- **Source:** read from `logs/daily/` sizes + SKILL.md §§ Output/Body (lines 53–68, 115–127); the spec explicitly invites "argue the section check alone is the better single predicate".
- **Alternatives:** byte-only (rejected: false alarms + arbitrary constant); both OR'd (rejected: the byte arm contributes only false-positive risk).

**D2 — Husk gets a distinct alert message; SAME per-date sentinel.**
- **What:** `ALERT_CLASS` selects between two messages; both carry the #994 invariants; `sent-$YESTERDAY.flag` unchanged.
- **Why:** the recovery command is identical (the backfill run auto-takes the Edit-in-place branch on a husk), but Thomas should know whether the night produced *nothing* vs *died mid-run* (different debugging entry points). One sentinel per date preserves alert-once; a missing→husk transition after an alert adds no information worth a second buzz.
- **Source:** SKILL.md § Output existing-file rules + § Backfill (read); #994 test assertions (`tests/test_cron_daily_healthcheck.py:78-83`).
- **Alternatives:** per-class sentinels (rejected: double-buzz for one broken day); single undifferentiated message (rejected: spec recommends distinguishing, and the husk message can point at the Edit-in-place recovery semantics).

**D3 — Stub-first placement: universal § Output write; commit+push mandatory-immediate only in headless rule 0.**
- **What:** the skeleton-first write becomes the § Output file-does-not-exist behavior for all runs; the *mechanical commit+push before mining* is pinned in the headless section (where the kill class lives).
- **Why:** one file lifecycle instead of two divergent flows (manual vs cron) prevents drift; the manual path is strictly improved (an aborted manual skeleton no longer blocks the nightly cron — empty Applied lands on Edit-in-place, whereas today a partial full-file manual write can trip the refuse rule). The Goal's sketch places step 0 in Headless mode; this design keeps the mandatory-mechanical part exactly there.
- **Source:** SKILL.md lines 53, 64–74 (manual-run rule + refuse rule), § Headless 581–605 (read).
- **Alternatives:** headless-only skeleton (rejected: two write flows, and § Output line 53 would contradict rule 0).

**D4 — Skeleton's `## Applied workflow improvements` body is EMPTY, never the placeholder line.**
- **What:** the skeleton writes bare H2 headers.
- **Why (load-bearing, two ways):** (a) the placeholder is a non-blank line — writing it at stub time would blind the husk detector permanently; (b) § Output's refuse rule treats the placeholder as "day already done", so a placeholder-bearing husk would *refuse* its own backfill recovery. Pinned by `test_skeleton_applied_section_stays_empty`.
- **Source:** SKILL.md lines 64–68 + 126–127 (read).
- **Alternatives:** a distinct "enrichment pending" marker line (rejected: requires teaching both the healthcheck and the refuse rule a third token; emptiness already means "pending" in the existing rules).

**D5 — awk single-pass predicate.**
- **What:** the awk one-liner in §4.2. **Why:** handles missing-H2 and empty-section in one pass, no new dependencies, tolerant of `## `-prefixed lines inside later diff blocks (the flag closes only after a non-blank entry line has already set `found`). **Source:** read of `cron_daily_healthcheck.sh` (pure bash+coreutils today). **Alternatives:** grep+sed pipeline (rejected: two-stage, harder to reason about empty-section case); python helper (rejected: the wrapper deliberately avoids the venv beyond the PATH guard).

**D6 — Doc-pin test for the SKILL.md prose.**
- **What:** `tests/test_daily_stub_first_doc.py` (§4.4). **Why:** the 07-03 incident shows the prose is the weak link; a pin cannot force runtime compliance (the healthcheck arm is the runtime detector) but prevents a later cosmetic edit from silently dropping the mechanical rule or the load-bearing emptiness invariant. **Source:** precedent `tests/test_daily_three_route_classifier_doc.py` (#706), named by the spec. **Alternatives:** no pin (rejected: verify_plan c31 + the incident history).
