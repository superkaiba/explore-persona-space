## 1. Goal

**Requirement.** The watcher's real-progress clock `scripts/autonomous_session_watch.py::_latest_progress_ts` (line 3734) must NOT count a deliberate session-stop record as real progress. Today a `spawn_session.py stop` breadcrumb — kind `epm:progress`, `by="spawn_session-stop"`, note `deliberate-stop pid=n/a target=happy-session:<sid> reason=<...>` (emitter `scripts/spawn_session.py::cmd_stop`, lines 2357-2396) — carries no bracketed watcher sentinel, so it passes both existing filters (kind ∈ `_PROGRESS_KINDS` at 3708, note ∉ `_WATCHER_NOTE_SENTINELS` at 984) and refreshes the clock. A session's death record then reads as "the experiment made real progress": it suppresses the pod-safety stale alert on an escaped pod (`_status_class`, 3679, via the consumer at 6276) and dissolves the spend-approval / user-pause respawn suppressions (`_spend_approval_park_reason` 7147, `_user_pause_hold_reason` 7246). Same anti-liveness class as #949's fix (incident #810), ported from `task_workflow.stage_dispatch_should_skip` to the watcher's clock.

**Acceptance criteria** (restated concretely in §5): the deliberate-stop exclusion is live in `_latest_progress_ts` with the exact #949 predicate shape; new pinned tests pass; all existing `_latest_progress_ts` tests pass untouched; ruff + `workflow_lint.py` default run clean; zero behavior change for non-stop events.

## 3. Design

### 3.1 The edit (one function, `scripts/autonomous_session_watch.py`)

Inside the `_latest_progress_ts` loop (lines 3744-3754), add the exclusion **after the sentinel check at 3749-3750, before the ts parse at 3751**, plus one docstring sentence:

```python
def _latest_progress_ts(events: list[dict]) -> float | None:
    """Newest epoch timestamp among REAL progress markers in ``events``.

    "Real progress" = an event whose ``kind`` is in :data:`_PROGRESS_KINDS`
    AND whose ``note`` does NOT contain ANY substring in
    :data:`_WATCHER_NOTE_SENTINELS` (the watcher's own stale-alert /
    session-stalled-alert posts use ``epm:progress`` and must NOT count as
    progress — otherwise the alert would reset the staleness clock it is
    measuring)
+   AND that is not a deliberate session-stop record (lstripped note prefix
+   ``"deliberate-stop "`` OR ``by == "spawn_session-stop"`` — a session's
+   death record is anti-liveness, never progress; #990, precedent
+   #949/#810 in ``task_workflow.stage_dispatch_should_skip``).
    Returns ``None`` when there is no such marker.
    """
    best: float | None = None
    for ev in events:
        if ev.get("kind") not in _PROGRESS_KINDS:
            continue
        note = ev.get("note") or ""
        if any(sentinel in note for sentinel in _WATCHER_NOTE_SENTINELS):
            continue  # a watcher-posted alert — not real progress
+       # Anti-liveness (#990; precedent #949/#810): a deliberate session
+       # stop is the death record of the task's driver, not progress —
+       # counting it would refresh the very staleness clocks that should
+       # react to the stop. Same predicate as
+       # task_workflow.stage_dispatch_should_skip line ~1463: the
+       # lstripped "deliberate-stop " note PREFIX (also catches PM-posted
+       # stop records, which use by="pm-chat" — research-pm.md ~719/734)
+       # OR by == "spawn_session-stop" (catches note-text drift from the
+       # cmd_stop emitter). Prefix-boundary: a note merely MENTIONING
+       # deliberate-stop mid-text still counts as progress.
+       if note.lstrip().startswith("deliberate-stop ") or ev.get("by") == "spawn_session-stop":
+           continue
        ts = _parse_event_ts(ev.get("ts"))
        if ts is not None and (best is None or ts > best):
            best = ts
    return best
```

The predicate line is 95 chars — under ruff line-length 100. No new imports.

### 3.2 Predicate shape: match the precedent exactly, not by-field-only

The task body says "exclude `by=='spawn_session-stop'`"; the plan chooses the **full #949 OR-predicate** (`note.lstrip().startswith("deliberate-stop ") or by == "spawn_session-stop"`). Reasons:

1. **Consistency** — one anti-liveness predicate project-wide; the #949 tests already pin both halves' semantics and the prefix boundary, so this port inherits a settled contract.
2. **The prefix half is load-bearing, not decorative:** the PM session's prescribed deliberate-stop breadcrumb (`.claude/agents/research-pm.md` line ~719) posts a note beginning `deliberate-stop pid=<PID> ...` with `--by pm-chat` (line ~734). A by-only filter would count a PM-posted kill record as real progress — the same bug through a different emitter.
3. **The by half is load-bearing too:** it survives note-text drift in `cmd_stop` (any future rewording of the breadcrumb), per the `task_workflow.py:1336-1340` comment ("drops ANY note with by == 'spawn_session-stop' regardless of content — a future genuine liveness post from spawn_session must use a different `by`").
4. `lstrip()` before `startswith` matches the precedent's semantics (`task_workflow.py:1454` lstrips before the 1463 check).

### 3.3 Placement: inline in the loop (not a sentinel-set member, not a shared helper)

- **Not `_WATCHER_NOTE_SENTINELS`:** that frozenset is substring-matched (`sentinel in note`, line 3749) — adding `"deliberate-stop"` there would match mid-note mentions, violating the pinned prefix boundary; and the set is documented (980-983) as *watcher-posted bracketed* sentinels, which the operator stop record is not.
- **Not a shared import from `task_workflow`:** the precedent is an inline two-clause check, not an exported helper; the watcher is a script that deliberately duplicates such small predicates with a cross-reference comment (the existing `task_workflow.py:1329-1333` comment documents exactly this script/src split). Extracting a helper into `task_workflow.py` and importing it is over-engineering for two clauses and widens the diff into a second module.
- **Inline after the sentinel check** keeps the loop's filter chain readable in exclusion order: kind → watcher sentinel → deliberate-stop → ts.

## 10. §11 Decision Rationale

1. **Exclusion predicate = the full #949 OR (`lstripped-prefix OR by`), not by-only.**
   - **What:** `note.lstrip().startswith("deliberate-stop ") or ev.get("by") == "spawn_session-stop"`.
   - **Why:** consistency with the settled project-wide anti-liveness contract; the prefix half catches PM-posted stop records (`by="pm-chat"`, research-pm.md ~719/734) the by-only form misses; the by half survives emitter note drift.
   - **Source:** `task_workflow.py:1454+1463` (#949 fix, incident #810); `tests/test_stage_dispatch_dedup.py:407-540`; `task_workflow.py:1336-1340` comment; `.claude/agent-memory/critic/feedback_advisory_by_convention_plans.md`.
   - **Alternatives rejected:** by-only (task-body wording — weaker, misses pm-chat prefix records, diverges from the pinned precedent); prefix-only (misses note drift).
2. **Placement = inline in the `_latest_progress_ts` loop, after the sentinel check.**
   - **What:** one `if ... continue` with a cross-reference comment; no set-membership change, no shared helper.
   - **Why:** `_WATCHER_NOTE_SENTINELS` is substring-matched (would break the prefix boundary) and documented as bracketed watcher-posted sentinels; the precedent is inline; a cross-module helper widens the diff for two clauses. §3.3.
   - **Source:** `autonomous_session_watch.py:980-983, 3749`; `task_workflow.py:1451-1466` (inline precedent); `task_workflow.py:1329-1333` (the documented script/src predicate-duplication split).
   - **Alternatives rejected:** add to `_WATCHER_NOTE_SENTINELS` (mid-note false positives); import a new shared helper from `task_workflow` (over-scoped).
3. **Clock scope = `_latest_progress_ts` only; `_latest_nonwatcher_event_ts` explicitly out.**
   - **What:** the §3.4 in/out table.
   - **Why:** the ANY-kind clocks feed the respawn/reap arms whose stated fail direction is keep/defer — counting a stop record there is safe (and an incidental takeover grace); excluding it would make respawns fire earlier after deliberate stops, a distinct behavior change needing its own analysis. All other `_latest_*` helpers are kind- or prefix-keyed with no exposure.
   - **Source:** `autonomous_session_watch.py:12546-12565` docstring ("must err toward keeping"), 8701-8721 (#661 rationale), 9883-9891; #816/#866 takeover-race incidents; task body Goal (names only `_latest_progress_ts`).
   - **Alternatives rejected:** blanket exclusion across all clocks (unanalyzed respawn-timing change smuggled into a narrow fix).
4. **Tests mirror the #949 pin structure (headline + two-half isolation + prefix boundary + only-stop→None).**
   - **What:** §4 tests 1-5.
   - **Why:** the precedent's test decomposition is what makes a later refactor of either half detectable; mirroring keeps the two sites' contracts provably identical.
   - **Source:** `tests/test_stage_dispatch_dedup.py:407-540`; local conventions at `tests/test_autonomous_session_watch.py:700-739`.
   - **Alternatives rejected:** a single end-to-end test through the pod-safety pass (heavier fixtures, weaker localization; the pure-function tests match how this block is already pinned).
