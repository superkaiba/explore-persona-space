## 3. Requirement + acceptance criteria (code change — no hypothesis)

**Requirement:** empty (or otherwise caller-invalid) completions must never be persisted or served as successes, transport-class failures must be re-driven once by the divtrain caller, and every lost row must leave a per-row record with a transport-vs-content split.

**Acceptance criteria ("done", each testable):**
1. `dispatch_calls(..., response_valid=None)` is byte-identical to today (pinned by `test_response_valid_default_none_backcompat`: empty text → `RESULT_OK`, cached).
2. With a validator: an always-invalid response consumes the full `max_attempts` budget, returns `error=True, category=RESULT_TRANSPORT`, `reason` starting `invalid_response`, and writes NOTHING to the cache.
3. A cached PRE-fix non-error entry whose stored result fails the validator reads as a MISS and is re-dispatched (poisoned-cache heal), and the recovered result overwrites it.
4. The batch path classifies validator-failing harvested rows as `RESULT_TRANSPORT` errors, and a resumed pre-fix batch-checkpoint record failing the validator is reclassified at merge (never persisted to the JudgeCache).
5. `_ext_gen` passes a non-empty validator, re-drives `{RESULT_TRANSPORT, RESULT_RATE_LIMITED}` rows exactly once, writes `ext_plain_claude_failures.json` (per-row: id, category, reason, round; written even when empty), and logs `ok / transport-class / content-class` counts — never a bare count.
6. Both `issue952_bank_build.py` dispatch sites carry the validator kwarg.
7. All new tests pass; the pre-existing suites for touched surfaces stay green; ruff clean on touched files.

## 11. Decision Rationale

`N/A — no model training; no training hyperparameters.` Design decisions, each What/Why/Source/Alternatives:

1. **Hook shape: `response_valid: Callable[[Any], bool] | None = None` on `dispatch_calls`, evaluated on the PARSED result.**
   Why: the parsed result is what callers consume AND what `_cache_put` stores — validating it makes dispatch-time and cache-read-time checks the same predicate on the same object. Opt-in default preserves every other caller byte-identically.
   Source: legacy `is_valid` hooks in `llm/anthropic_client.py` L563/L638 + `llm/openai_client.py` L410/L507 (established project semantics: invalid → retry); brief on task #1470.
   Alternatives: validate raw text (rejected — `parse_response` may transform, e.g. `run_swaps`' `.strip()`; the cache stores the parsed object, so a raw-text validator could not heal reads); raising validator (rejected — indistinguishable from parse errors, which are terminal `RESULT_ERROR`).
2. **Invalid = retryable, consuming an `attempt`; exhaustion → `RESULT_TRANSPORT`.**
   Why: an empty completion at temperature 1.0 is freely re-sampleable — the incident's manual re-run recovered 76/138, the operational definition of re-drivable. Classifying `RESULT_TRANSPORT` reuses the EXISTING caller re-drive contract (`{RESULT_RATE_LIMITED, RESULT_TRANSPORT}`, api_dispatch L206–210) with zero consumer changes. Honest caveat recorded in the category comment: rule 24's letter defines transport as "no verdict produced"; an empty completion IS a produced response, but it carries no usable content and is freely re-drivable — membership is by re-drivability, the property consumers branch on.
   Source: #1313 (`RESULT_TRANSPORT` machinery; put-skip/read-miss precedents in `eval/batch_judge.py` L582–588/L798–802); `llm-judging.md` rule 24(i)/(ii); incident record on #1470.
   Alternatives: `RESULT_ERROR` (rejected — terminal/not re-drivable, contradicts the recovery evidence); a new `RESULT_INVALID` category (rejected — every re-drive consumer would need a new branch; deliberate reuse documented instead).
3. **Cache heal: read-as-miss in `_split_cached` + validator put-gate in `_persist_results_to_cache`.**
   Why: the 62 residual empties were STABLE precisely because the cache re-served them; read-as-miss self-heals pre-fix caches with no migration step. The put-gate closes the pre-fix-batch-checkpoint laundering path (§4.1(d)).
   Source: #1313's JudgeCache transport-dict get-miss + put-skip (the exact pattern); `llm/cache.py` L206–225 (empty-threshold miss precedent).
   Alternatives: one-off cache-purge script (rejected — doesn't protect future caches; the heal is structural).
4. **Batch path validated too (harvest classify + merge reclassify), no within-batch retry.**
   Why: the divtrain caller passes `checkpoint_dir` and a larger N would route batch (crossover 2000); a sync-only carve-out leaves the identical bug armed one routing decision away. Within-batch retry rejected: batch rows are one-shot by design and caller re-drive is already the documented contract for batch transport rows (DispatchResult docstring L252–258).
   Source: `_harvest_sub_batch` L1113–1136 (the #1313 classification arm this extends); DispatchResult checkpoint-resume caveat.
5. **Caller re-drive bounded at ONCE.**
   Why: matches the incident evidence (one manual re-run recovered 76/138); each row already gets `max_attempts=5` inside dispatch, so once-more is 10 tries total per row — beyond that the row is signal (record it), not retry fodder. Unbounded loops risk spinning on systematically-empty prompts.
   Source: rule 24(i) "retry, bounded"; incident record.
   Alternatives: N-round re-drive with backoff (rejected — no evidence a 2nd re-drive recovers more; adds loop complexity).
6. **Siblings get the validator kwarg only.**
   Why: same bug class, trivial diff, zero behavior change for already-persisted artifacts (phases complete); re-drive plumbing there would be dead code. Minimal-scope vs same-class-hardening resolved as: harden the cheap half, skip the dead half.
   Source: brief item 3; `run_swaps` L391–414 (existing caller-side pair-drop verification stays the outer guard).
7. **New helper module `scripts/issue952_transport_helpers.py`.**
   Why: pure helpers must be testable without importing the GPU script (vLLM env + heavy experiment stack at module top) and are shared by two scripts; duplicating `nonempty_text` in two files invites drift.
   Source: code-style reuse hierarchy; grep confirms no existing in-repo equivalent (only the legacy per-client `is_valid` lambdas).
