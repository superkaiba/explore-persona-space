## 3. Design questions — settled

**Q1 Host: the watcher, not tick_triage (and not both).** `tick_triage.py` runs only when a per-issue tick cron is armed — i.e. only for autonomous sessions, and its cron tears down at terminal/gate states; the #779 class must also be caught for interactive sessions, for post-park follow-up dispatches, and for tasks whose session died. Its contract is also one verdict line consumed by an LLM-priced tick — adding audit output there adds cost per fire and double-flags anything the watcher also sees. The watcher sweeps ALL tasks every 10 min for free, is daemon-independent, and owns the exact conventions (sidecar/push/dedup/kill-switch) this pass needs. `tick_triage.py` is untouched.

**Q2 Sweep scope.** Tasks from `REGISTRY.json` (read in-process via `task_workflow.registry_path()`) whose status ∈ `_TRIAGE_OBSERVER_STATUSES = ACTIVE ∪ {"awaiting_promotion", "blocked"}` (ACTIVE is the watcher's existing set at line ~460: planning/approved/running/verifying/interpreting/reviewing/followups_running; `awaiting_promotion` because 9a-ter/9b follow-up dispatches happen on parked parents; `blocked` because a crash right after an untriaged launch parks there; terminal `completed`/`archived`/`on_hold`/`proposed`/`plan_pending` excluded — no fresh dispatch to audit or the flag has no consumer). Cost bound, two gates before any events read: (i) `events.jsonl` mtime (via the registry-resolved task path) within the lookback window; (ii) per-task cursor — only records with `ts > max(cursor, now − EPM_TRIAGE_OBSERVER_LOOKBACK_H, TRIAGE_DUTY_EPOCH_TS)` are evaluated, and (v3, MF2) only records MATURED past `now − adjacency_s`. Records audited: `TRIAGE_LAUNCH_KINDS` markers + `epm:progress` breadcrumbs (`stage-dispatch stage=...`) + any record carrying the triage line (for the `none`-check). Lookback default 48h (§11).

**Q3 Violation predicate (exact — pseudocode in §4.1). v3: SPLIT index sets (MF1).** Two index sets over the event list:

- **BOUNDARY records** — kind ∈ `TRIAGE_LAUNCH_KINDS` OR note contains `TRIAGE_LINE_PREFIX`. Boundary records ALONE define `prev_j` (the opening of every pre-record window), the `none`-check windows, and the adjacency neighbors for launch markers. This preserves the enumerator's fail-toward-triage contract verbatim: an UNTRIAGED breadcrumb never closes a window (task_workflow.py:1587–1589).
- **AUDITED records** — boundary records ∪ ALL `epm:progress` breadcrumbs whose lstripped note starts with `stage-dispatch ` (line-less compute breadcrumbs are audited but never bound windows). v2's single `duty_idx` loop never visited a line-less breadcrumb — the breadcrumb branch was unreachable (the shared 4-critic blocker); the split fixes it.

Three violation classes over post-epoch, post-cursor, MATURED audited records:

- `launch-missing-line` (**warn**): a `TRIAGE_LAUNCH_KINDS` marker whose note lacks `TRIAGE_LINE_PREFIX`, AND whose nearest PREVIOUS boundary record is not a triage-line record within `adjacency_s`, AND whose nearest NEXT boundary record is not a triage-line record within `adjacency_s`. (Launch markers are machine-posted — `by=poll_pipeline`/`backends.gcp` — so the adjacent `epm:progress` triage note is the NORMAL compliance path; adjacency matching is load-bearing. Requiring the nearest BOUNDARY neighbor — not just any record in ±window — keeps crash-fix relaunch bursts individually duty-bound, per the SKILL.md "crash-fix relaunches included" clause; a line-less breadcrumb sitting between the triage note and the launch cannot break the coverage because it is not a boundary record.)
- `breadcrumb-missing-line` — v3 THREE-WAY classification of a line-less breadcrumb's normalized stage token (`_normalize_stage`; NOTE: it strips ONE `followup-` PREFIX and applies aliases — the SUFFIX form `free-analysis-followup` does not start with `followup-` and passes through intact, verified in test):
  1. token ∈ `TRIAGE_NONCOMPUTE_STAGES` (extended, §4.1 — includes the live-observed benign families `interp-critique`, `clean-result-fix`, `value-critique`) → **no flag**;
  2. POSITIVE compute evidence — the breadcrumb carries a `pid=` field (the #833 detached-VM-phase REQUIRED field), OR its normalized token ∈ `TRIAGE_COMPUTE_STAGE_TOKENS = {grid, sweep, battery, fit, fits, relaunch}` (grounded: `grid` is #779's incident token; the rest are the SKILL.md duty text's own nouns — "a fit / sweep / statistical battery", crash-fix relaunches) → **warn**;
  3. everything else (unknown token, no positive evidence — including `free-analysis-followup`, whose 9a-ter duty is content-dependent) → **info** (sidecar only, no push, no marker).

  Rationale (MF4, option (a) as required-fixed): the live tree already carries post-epoch benign breadcrumbs a pure negative list would warn-storm on (§2). Warn is now reserved for POSITIVELY-identified compute; the unknown tier keeps observability (sidecar) at zero nag cost; the exempt set is a single frozenset literal with a "append benign tokens observed in the wild here" comment — deliberately easy to extend.
- `none-with-candidates` (**info**, escalated to **warn** on signature hit): any audited record whose triage line disposition is `none` (parse: the line's remainder after the prefix, stripped, starts with `none`) while `_triage_window_candidates(events[j+1:i])` — `j` = nearest previous BOUNDARY record — is non-empty after dropping candidates within `grace_s` of the record's ts (the spec's "seconds between the final enumerator run and the breadcrumb post" residual). Escalation to `warn` only when ≥1 surviving candidate note contains an entry of `TRIAGE_EXTERNAL_SIGNATURES = {"PM-chat", "user-raised", "user directive", "# Audit", "AMENDMENT", "SCOPE RESTORE"}` (the SKILL.md in-the-wild external signatures, kept as ONE shared constant next to the other triage constants).

**Maturity gate (MF2).** A fire-once observer must not race the compliance form that legitimately arrives AFTER the launch marker (the "immediately-adjacent `epm:progress` note" can land minutes later — machine-posted launch markers precede the orchestrator's note whenever the poller posts first). Therefore: only audited records with `ts ≤ now − adjacency_s` are EVALUATED; younger records are deferred to a later tick, and the cursor advances only past MATURED records (an immature record stays `> cursor` and is re-seen next tick). Uniform across all three classes for simplicity (breadcrumbs carry their line in-note and don't strictly need it; the cost is ≤30 min flag latency on a 10-min-cadence observer — irrelevant for a post-hoc audit). The deferral horizon EQUALS `adjacency_s` by construction: it is exactly the window in which a compliant adjacent-next note may still land.

Accepted residuals honored (never flagged): legacy pre-epoch records (`TRIAGE_DUTY_EPOCH_TS = "2026-07-03T05:00:00Z"`, #889's landing 2026-07-03T04:05Z rounded up); grace-window candidates; markers after a task's LAST compute dispatch (structurally never audited — only dispatch records are evaluated); a burst launch covered by its nearest-boundary triage record within adjacency. **Invisible-by-construction residuals (named in the docs paragraph, §4.3 — the observer cannot see them):** (i) a LYING triage line — the observer audits mechanical presence and enumerator-consistency, not truthfulness (a `2 applied` line that misdescribes what was applied, or a `none` where every candidate genuinely was external, passes); (ii) record-less launches — compute started via direct SSH with no launch marker and no breadcrumb leaves nothing to audit (the `/issue` skill-drift rule is the control for that class). Known bounded miss (documented, not flagged at warn): a 9a-ter compute fit dispatched under a `free-analysis-followup` breadcrumb with no triage line surfaces only at `info`.

**Q4 Flag channel.** (i) Always: one JSON row appended to a NEW dedicated sidecar `.claude/cache/triage-observer-events.jsonl` (the cpu-guard "own stream for clean grep" precedent; the disk-guard sidecar is disk-pressure-scoped). Row: `{ts, issue, record_ts, record_kind, stage, violation, severity, candidate_count, candidate_kinds, signature_hits, note_head}`. (ii) `warn` only: one fail-soft `_telegram_push` digest line + one `epm:progress` review-nudge note on the task via `_post_progress_marker` (carrying the `[autonomous_session_watch:triage-observer]` sentinel — anti-liveness by prefix match, so it never refreshes staleness clocks), capped at `EPM_TRIAGE_OBSERVER_MARKER_CAP=5` marker posts per tick. **Cap-overflow semantics (explicit): a `warn` violation beyond the per-tick cap is PERMANENTLY sidecar+push-only — it is still marked flagged (dedup consumed) and its marker is NEVER deferred to a later tick** (a deferral queue adds state complexity for the storm case, exactly when per-task marker spam would be worst; the sidecar + push already carry the alert). The note doubles as a live advisory: it carries `by="unknown"`, so the NEXT compute dispatch's enumerator surfaces it — deliberate (the flag is itself the advisory the next dispatch should read). NON-GATING: the pass calls no `set-status`, no session stop, no dispatch mutation; pinned by tests at both the subprocess and in-process levels (§5, §6).

**Q5 Dedup.** Key = `(issue, record_ts, violation_class)`. One flag per key EVER (a violation is a fixed historical record — it cannot grow, so no re-alert; contrast with disk bands). State singleton `~/.eps-autonomous/triage-observer.json`: `{"<issue>": {"cursor_ts": "...", "flagged": ["<record_ts>|<class>", ...]}}`, atomic tmp+replace write, type-guarded reads, entries self-pruned when the issue leaves the sweep status set for good (status ∈ {completed, archived}). No ack sentinel — fire-once semantics make one unnecessary (the cpu-guard pass documents the same omission rationale). The cursor + maturity gate together make the pass idempotent AND race-safe: a record is evaluated exactly once, on the first tick after it MATURES (MF2). The `_save`/`_load` round-trip is pinned by the MF3 two-invocation test — a broken round-trip would otherwise ship green on single-invocation tests and produce the exact re-alert storm the kill criterion forbids.

**Q6 False-positive posture.** The enumerator ENUMERATES for LLM triage and never classifies externality (`by` defaults to `"unknown"` for humans AND sessions — measured on #779), so `none` against a non-empty candidate set is **usually legitimate** (all candidates self-posted). Hence: `none-with-candidates` defaults to `info` (sidecar-only, no push, no marker); it reaches `warn` only on an external-signature hit. The same graded posture now governs breadcrumbs (MF4): warn only on positive compute identification, info for unknowns, nothing for the known-benign families. All flag text is phrased as a review nudge, never an accusation: "post-hoc triage-duty review: dispatch record at <ts> recorded a 'none' disposition while K window candidates were pending (M matching external-advisory signatures). The enumerator over-approximates — this may be fine if all candidates were self-posted; please review those markers and record dispositions at the next dispatch." Missing-line classes on positively-identified compute are higher-confidence (the duty unambiguously requires SOME line) and warrant `warn`.

**Q7 Kill switch.** `EPM_DISABLE_TRIAGE_OBSERVER=1` (truthy set `{"1","true","yes"}`, matching `_cpu_guard_enabled` at autonomous_session_watch.py:2704), checked at the top of `triage_observer_pass` with the standard "disabled via ...; skipping" log line.

    min_ts: str | None = None,
    mature_before_ts: str | None = None,
) -> dict:
    """Post-hoc, NON-GATING audit of the pre-dispatch triage duty (#967).

    Returns {"violations": [...], "cursor_ts": str | None}. One violation dict
    per non-compliant MATURED audited record: {"record_ts", "record_kind",
    "stage", "violation", "severity", "candidate_count", "candidate_kinds",
    "signature_hits", "note_head"}. BOUNDARY records (launch kinds / triage-
    line notes) alone bound windows + adjacency; the AUDITED set additionally
    includes line-less stage-dispatch breadcrumbs (audited, never window-
    closing — the enumerator's fail-toward-triage contract). Records with
    ts > mature_before_ts are DEFERRED (not evaluated, not consumed):
    "cursor_ts" is the max parseable ts among audited records at or before
    mature_before_ts, so a caller advancing its cursor to cursor_ts re-sees
    immature records next tick (MF2). Pure read — never mutates events.
    Marker-cap overflow is a CALLER concern (see triage_observer_pass): an

    """

```python
boundary_idx = [i for i, e in enumerate(events)
                if e.get("kind") in TRIAGE_LAUNCH_KINDS
                or TRIAGE_LINE_PREFIX in (e.get("note") or "")]
audited_idx = sorted(set(boundary_idx) | {
    i for i, e in enumerate(events)
    if e.get("kind") == "epm:progress"
    and (e.get("note") or "").lstrip().startswith("stage-dispatch ")})

violations, cursor_ts = [], None
for i in audited_idx:
    e = events[i]; ts = e.get("ts", ""); note = e.get("note") or ""
    if _stage_event_ts(e) is None:
        continue                                  # unparseable ts: fail-soft skip (tested)
    if mature_before_ts and ts > mature_before_ts:
        continue                                  # MF2: immature — defer, do not consume
    cursor_ts = max(cursor_ts or ts, ts)          # matured => consumable by the caller's cursor
    if epoch_ts and ts < epoch_ts:                # ISO-8601 Z strings sort lexicographically
        continue
    if min_ts and ts <= min_ts:
        continue
    prev_j = nearest boundary_idx member < i (None if none)   # BOUNDARY, not audited (MF1)
    has_line = TRIAGE_LINE_PREFIX in note

    if e.get("kind") in TRIAGE_LAUNCH_KINDS and not has_line:
        # adjacency neighbors are BOUNDARY records only (a line-less breadcrumb
        # in between cannot break coverage)
        covered = (
            (prev_j is not None and TRIAGE_LINE_PREFIX in (events[prev_j].get("note") or "")
             and _ts_delta_s(events[prev_j], e) <= adjacency_s)
            or ((next_k := nearest boundary_idx member > i) is not None
                and TRIAGE_LINE_PREFIX in (events[next_k].get("note") or "")
                and _ts_delta_s(e, events[next_k]) <= adjacency_s)
        )
        if not covered:
            violations.append({..., "violation": "launch-missing-line", "severity": "warn"})
        continue

    stripped = note.lstrip()
    if not has_line and stripped.startswith("stage-dispatch "):
        fields = _breadcrumb_fields(stripped)
        norm = _normalize_stage(fields.get("stage", ""))
        # NOTE: _normalize_stage strips ONE leading "followup-" prefix; the
        # SUFFIX form "free-analysis-followup" passes through intact (tested).
        if norm in TRIAGE_NONCOMPUTE_STAGES:
            continue                                        # known benign: no flag (MF4)
        positive_compute = "pid" in fields or norm in TRIAGE_COMPUTE_STAGE_TOKENS
        sev = "warn" if positive_compute else "info"        # unknown demoted to info (MF4)
        violations.append({..., "violation": "breadcrumb-missing-line", "severity": sev})
        continue

    if has_line and _triage_disposition_is_none(note):
        window = events[(prev_j + 1 if prev_j is not None else 0): i]   # opens at BOUNDARY
        cands = _triage_window_candidates(window)
        cands = [c for c in cands if _ts_delta_s(c, e) > grace_s]   # spec residual
        if cands:
            hits = sorted({sig for c in cands
                           for sig in TRIAGE_EXTERNAL_SIGNATURES
                           if sig in (c.get("note") or "")})
            violations.append({..., "violation": "none-with-candidates",
                               "severity": "warn" if hits else "info",
                               "candidate_count": len(cands),
                               "candidate_kinds": sorted({c.get("kind","") for c in cands}),
                               "signature_hits": hits})
return {"violations": violations, "cursor_ts": cursor_ts}
```

Small helpers alongside: `_ts_delta_s(a, b)` (reuse `_stage_event_ts` parsing; a malformed NEIGHBOR ts ⇒ that neighbor does not provide coverage; a malformed ts on the audited record itself ⇒ the record is skipped entirely at the top of the loop, fail-soft — tested) and `_triage_disposition_is_none(note)` (first triage-line occurrence; remainder `.strip().lower().startswith("none")`).

Note on records that are NOT `stage-dispatch` and NOT launch markers but DO carry a triage line (the adjacent-note compliance form): they are boundary records AND audited, and get the `none`-check (third branch), which is exactly right — the adjacent note IS where a pod launch's `none` claim lives.
