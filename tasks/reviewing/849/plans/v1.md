# Plan — Task #849: Escalate-only CPU/memory-pressure observability pass for the autonomous-session watcher

`kind: infra` (workflow-fix). Code-only change to the workflow surface. No experiment, no pod, no model.

## 0.0 TL;DR (plain English)

- **What I'll run:** I'll add a warn-only "CPU guard" pass to the 10-minute watcher cron. Every tick it reads three tiny kernel files (load average + CPU/memory pressure), and greps the earlyoom log for silent process kills; when the box has been overloaded for ~20 minutes, it writes one attributed row ("these are the top processes and which issue owns them") to a log file and queues one phone notification.
- **What I expect:** the next fleet-wide overload (like the 2026-07-02 load-226 incident) and every silent earlyoom SIGTERM shows up in `.claude/cache/cpu-guard-events.jsonl` within ~10-20 minutes with a named culprit, instead of being invisible for hours. Nothing is ever killed or reniced.
- **What would change my mind:** if the pass itself measurably slows a watcher tick (>~1s added) or misfires repeatedly on a healthy busy fleet, I'd raise the thresholds or gate a sub-arm off via its kill switch — the design makes both a one-env-var change.

## 1. Goal + acceptance criteria

Give the fleet a CPU/memory-pressure detection + attribution channel on the shared 32-core VM, mirroring the existing disk sub-floor sentinel's escalate-only design. Motivating incident (2026-07-02): load 186-226 for hours; earlyoom SIGTERM sweeps silently killed 4-7 GB analysis workers (exit 143, no traceback, misattributed for hours); a checkpointed sweep's 60 s layers stretched to 64 min. The watcher watches sessions/pods/disk but not the box's compute pressure.

**Acceptance criteria:**
1. A sustained-overload episode (synthetic values in tests) produces exactly one `kind: vm-cpu-pressure` sidecar row on the fire tick, with `reasons`, load/PSI readings, and top-process attribution; repeats within the episode are suppressed unless load grows >25% or the reason set changes; recovery resets the episode.
2. An earlyoom kill line (real captured fixture) produces one `kind: earlyoom-kill` sidecar row per kill, exactly once (journal-cursor + key dedup), regardless of pressure thresholds.
3. Never mutates any process: no kill, no renice, no signal — grep-verifiable (no `os.kill`/`signal`/`renice` in the new block).
4. Fail-soft: missing PSI files, missing/failing `journalctl`, missing push script, unreadable `/proc/<pid>/cwd` each degrade that sub-signal to "unavailable", never crash the pass or any later pass.
5. `EPM_DISABLE_CPU_GUARD_PASS=1` no-ops the whole pass.
6. Existing watcher tests pass unmodified; `tests/test_autonomous_session_watch.py` and `tests/test_stalled_detector_and_gc.py` are NOT edited (in-flight #845).
7. `.claude/rules/background-automation.md` documents the new pass.

## 4. Design / Method delta

**Method delta vs the existing disk-guard passes (what's genuinely new):**

| Aspect | Disk sub-floor sentinel (existing) | CPU guard pass (new) |
|---|---|---|
| Signal | statvfs free bytes (one reading, level-triggered) | loadavg + PSI (rates) → needs **2-consecutive-tick persistence** (disk has no persistence rule; CPU adds a streak counter in state) |
| Attribution | `du`/`repquota` on cache dirs → issue dirs | one `ps -eo pid,pcpu,rss,args` call → pid → `/proc/<pid>/cwd` readlink + cmdline regex → issue |
| Second arm | none | **earlyoom kill surfacing** — journal grep every tick, threshold-independent, with a persistent journal cursor |
| State saves | only on fire | **every non-dry tick** (the streak counter must persist between ticks; deliberate delta) |
| Sidecar | shared `disk-guard-events.jsonl` | dedicated `cpu-guard-events.jsonl` (task-body requirement; domain-separated grep) |
| Telegram | disk passes push via marker/`_telegram_push` variously | pressure: once per episode (+ growth/reason-change re-alert); kills: rate-limited to 1 enqueue/hour (sidecar keeps full fidelity) |

Everything else (escalate-only, fail-soft, atomic state writes, dry-run-zero-subprocess, env knobs, `--*-only` flag) is a direct mirror.

```python
# ─── CPU/memory-pressure guard pass (task #849) — escalate-only ──────────────
# WHY: 2026-07-02 incident — shared 32-core VM at load 186-226 for hours;
# earlyoom SIGTERM sweeps silently killed 4-7GB analysis workers (exit 143,
# no traceback); the fleet had disk guards but no CPU/memory-pressure
# detection or attribution channel. Warn-only: NEVER kills, NEVER renices.

def _env_float(name: str, default: float, *, lo: float, hi: float) -> float:
    """Float env knob with sanity bounds; garbled/out-of-range -> default
    (same fail-soft contract as _env_gib_bytes / _env_pct)."""
    try:
        val = float(os.environ.get(name, ""))
    except ValueError:
        return default
    return val if lo <= val <= hi else default

# load5 must exceed factor * nproc to count as hot (1.5 = 50% sustained
# oversubscription; incident ran at 5.8-7x; a healthy fully-busy fleet
# sits at ~1.0x and never fires).
CPU_GUARD_LOAD_FACTOR = _env_float("EPM_VM_CPU_GUARD_LOAD_FACTOR", 1.5, lo=0.1, hi=100.0)
# PSI thresholds are percents -> reuse _env_pct (L1908).
CPU_GUARD_PSI_CPU_SOME_PCT = _env_pct("EPM_VM_CPU_GUARD_PSI_CPU_PCT", 50.0)
CPU_GUARD_PSI_MEM_FULL_PCT = _env_pct("EPM_VM_CPU_GUARD_PSI_MEM_PCT", 10.0)
# Consecutive hot ticks before firing (2 = ~20 min at the 10-min cron,
# mirroring main()'s --threshold default).
CPU_GUARD_TICKS = int(_env_float("EPM_VM_CPU_GUARD_TICKS", 2, lo=1, hi=100))
CPU_GUARD_TOP_N = 5                    # union of top-CPU and top-RSS
CPU_GUARD_REALERT_GROWTH = 0.25        # re-alert on >25% load5 growth in-episode
CPU_GUARD_SUBPROC_TIMEOUT_S = 15       # ps / journalctl hard bound
CPU_GUARD_KILL_PUSH_MIN_INTERVAL_S = 3600
CPU_GUARD_JOURNAL_OVERLAP_S = 60       # re-scan overlap; key-dedup kills dups

_EARLYOOM_KILL_RE = re.compile(
    r'sending (SIGTERM|SIGKILL) to process (\d+) uid (\d+) "([^"]*)": '
    r"badness (\d+), VmRSS (\d+) MiB"
)
_WORKTREE_ISSUE_RE = re.compile(r"\.claude/worktrees/issue-(\d+)")
_CMDLINE_ISSUE_RE = re.compile(r"(?:--issue[ =](\d+)|\bissue[_-](\d+)\b)")

def _cpu_guard_enabled() -> bool:      # mirrors _infra_drain_enabled (L7882)
    raw = os.environ.get("EPM_DISABLE_CPU_GUARD_PASS", "").strip().lower()
    return raw not in {"1", "true", "yes"}

# --- fail-soft readers (None = signal unavailable) ---
def _read_loadavg() -> tuple[float, float] | None:
    """(load1, load5) from /proc/loadavg; None on any error."""
    try:
        parts = Path("/proc/loadavg").read_text().split()
        return float(parts[0]), float(parts[1])
    except (OSError, ValueError, IndexError):
        return None

def parse_psi_avg10(text: str, kind: str) -> float | None:
    """PURE: avg10 from a /proc/pressure/* body for line kind 'some'|'full'."""
    for line in text.splitlines():
        if line.startswith(kind + " "):
            for tok in line.split():
                if tok.startswith("avg10="):
                    try:
                        return float(tok[len("avg10="):])
                    except ValueError:
                        return None
    return None

def _read_psi_avg10(path: str, kind: str) -> float | None:
    try:
        return parse_psi_avg10(Path(path).read_text(), kind)
    except OSError:
        return None   # container kernels without PSI: signal unavailable

# --- pure predicates (unit-tested with synthetic values, no real /proc) ---
def cpu_tick_hot_reasons(load5, ncpu, psi_cpu_some, psi_mem_full) -> list[str]:
    """PURE: which signals are hot THIS tick. None inputs are skipped
    (fail-soft: a missing signal can never fire OR mask the others)."""
    reasons = []
    if load5 is not None and ncpu > 0 and load5 > CPU_GUARD_LOAD_FACTOR * ncpu:
        reasons.append("loadavg")
    if psi_cpu_some is not None and psi_cpu_some > CPU_GUARD_PSI_CPU_SOME_PCT:
        reasons.append("psi-cpu")
    if psi_mem_full is not None and psi_mem_full > CPU_GUARD_PSI_MEM_FULL_PCT:
        reasons.append("psi-memory")
    return reasons

def decide_cpu_guard_fire(
    reasons: list[str], prior_consecutive: int, alerted: bool,
    last_alert_load5: float | None, last_alert_reasons: list[str] | None,
    load5: float | None,
) -> tuple[bool, int]:
    """PURE: (fire?, new_consecutive). Not hot -> (False, 0). Hot ->
    consecutive = prior+1; fire when consecutive >= CPU_GUARD_TICKS and
    (not yet alerted this episode, OR the sorted reason set changed, OR
    load5 grew > CPU_GUARD_REALERT_GROWTH vs the last alert)."""

# --- attribution ---
def attribute_issue(cwd: str | None, argv: str) -> int | None:
    """PURE: pid ownership — worktree path in cwd/argv wins, then
    --issue N / issue_N cmdline hints. None = unattributed."""

def _top_processes(top_n: int = CPU_GUARD_TOP_N, *, dry_run: bool = False) -> list[dict]:
    """Union of top-N-by-%CPU and top-N-by-RSS from ONE
    `ps -eo pid,pcpu,rss,args --no-headers` call (timeout 15s); per-pid cwd
    via os.readlink(f"/proc/{pid}/cwd") (OSError -> None). Rows:
    {pid, pcpu, rss_mib, issue, cwd, argv[:160]}. dry_run -> [] with ZERO
    subprocess.run (#681 r3 convention). Never raises.
    NOTE: ps %CPU is lifetime-average — representative for the hours-long
    sustained-overload class this guards; documented limitation."""

# --- earlyoom kill surfacing ---
def parse_earlyoom_kill_line(line: str) -> dict | None:
    """PURE: parse one `-o short-iso` journal line; None for non-kill lines.
    -> {journal_ts, signal, pid, uid, comm, badness, vmrss_mib}."""

def _earlyoom_kills_since(since_epoch: float, *, dry_run: bool = False) -> list[dict] | None:
    """`journalctl -u earlyoom --no-pager -o short-iso --since @<int(epoch)>`
    parsed through parse_earlyoom_kill_line. None on journalctl missing /
    non-zero rc / timeout (fail-soft); [] on no kills. dry_run -> None."""

# --- singleton state (mirrors _load/_save_subfloor_state, L1781-1805) ---
def _cpu_guard_state_path() -> Path:
    return AUTONOMOUS_REGISTRY_DIR / "vm-cpu-guard.json"
def _load_cpu_guard_state() -> dict: ...       # {} on missing/garbled
def _save_cpu_guard_state(state: dict) -> None: ...  # atomic tmp+replace, fail-soft

# --- sidecar (mirrors _append_disk_guard_sidecar, L1972-1986) ---
def _cpu_guard_sidecar_path() -> Path:
    return PROJECT_ROOT / ".claude" / "cache" / "cpu-guard-events.jsonl"
def _append_cpu_guard_sidecar(event: dict, dry_run: bool) -> None: ...

def cpu_guard_pass(dry_run: bool) -> bool:
    """Escalate-only CPU/memory-pressure + earlyoom-kill observability (#849).
    Warn-only: NEVER kills/renices. Daemon-independent. Fail-soft throughout.
    Returns True when any sidecar row was written this tick."""
    if not _cpu_guard_enabled():
        print("  cpu-guard: disabled via EPM_DISABLE_CPU_GUARD_PASS; skipping")
        return False
    state = _load_cpu_guard_state()
    now = time.time()
    wrote = False

    # (a) earlyoom kills — EVERY tick, threshold-independent
    last_scan = state.get("last_journal_epoch") or (now - 1800)
    kills = _earlyoom_kills_since(last_scan - CPU_GUARD_JOURNAL_OVERLAP_S, dry_run=dry_run)
    if kills is not None:
        seen = set(state.get("recent_kill_keys") or [])
        new = [k for k in kills if f"{k['journal_ts']}:{k['pid']}" not in seen]
        for k in new:
            _append_cpu_guard_sidecar({"kind": "earlyoom-kill", **k}, dry_run)
        if new:
            wrote = True
            # loud stderr line + rate-limited digest push (1/h; sidecar has full fidelity)
            if now - (state.get("last_kill_push_ts") or 0) > CPU_GUARD_KILL_PUSH_MIN_INTERVAL_S:
                _telegram_push("earlyoom killed ... (exit-143 silent SIGTERM) — see .claude/cache/cpu-guard-events.jsonl", dry_run)
                state["last_kill_push_ts"] = now
        state["recent_kill_keys"] = ([f"{k['journal_ts']}:{k['pid']}" for k in kills] + sorted(seen))[:50]
        state["last_journal_epoch"] = now

    # (b) pressure detection
    la = _read_loadavg()
    load1, load5 = la if la is not None else (None, None)
    ncpu = os.cpu_count() or 1
    psi_cpu = _read_psi_avg10("/proc/pressure/cpu", "some")
    psi_mem = _read_psi_avg10("/proc/pressure/memory", "full")
    reasons = cpu_tick_hot_reasons(load5, ncpu, psi_cpu, psi_mem)
    fire, consec = decide_cpu_guard_fire(
        reasons, state.get("consecutive_hot", 0), bool(state.get("alerted")),
        state.get("last_alert_load5"), state.get("last_alert_reasons"), load5)
    if not reasons:   # recovery -> episode reset (journal cursor fields preserved)
        state.update(consecutive_hot=0, alerted=False,
                     last_alert_load5=None, last_alert_reasons=None)
    else:
        state["consecutive_hot"] = consec
    if fire:
        top = _top_processes(dry_run=dry_run)
        print("vm-cpu PRESSURE: load5=... nproc=... psi ... — top: ...", file=sys.stderr)
        _append_cpu_guard_sidecar({
            "kind": "vm-cpu-pressure", "band": "cpu-pressure", "reasons": reasons,
            "load1": load1, "load5": load5, "nproc": ncpu,
            "psi_cpu_some_avg10": psi_cpu, "psi_mem_full_avg10": psi_mem,
            "consecutive_hot": consec, "top_processes": top,
        }, dry_run)
        _telegram_push("VM CPU/mem pressure: ... warn-only; see cpu-guard-events.jsonl", dry_run)
        state.update(alerted=True, last_alert_load5=load5, last_alert_reasons=reasons)
        wrote = True
    if not dry_run:
        _save_cpu_guard_state(state)   # streak persistence NEEDS per-tick saves
    return wrote
```

## 11. Decision Rationale

- **load5 > 1.5×nproc.** Why: 50% sustained oversubscription; healthy full utilization (load≈nproc) never fires; the incident ran at 5.8-7× and today's live gap at 1.9-2.2×. Source: task #849 body example + incident numbers (2026-07-02, load 186-226 / nproc 32; live probe loadavg 61.84/32). Uses load5 (2nd `/proc/loadavg` field) — less noisy than load1 at a 10-min cadence.
- **2 consecutive ticks (~20 min).** Source: in-repo precedent — `main()` `--threshold` default 2, documented "2 = ~20 min at a 10-min cron" (`autonomous_session_watch.py` L14366-14371).
- **PSI cpu `some avg10` > 50.** Why: `some` = share of wall time ≥1 runnable task stalled for CPU — 50% sustained is unambiguous oversubscription. Source: kernel PSI semantics (https://docs.kernel.org/accounting/psi.html) + live probe (76% under the active incident regime vs ≈0 healthy).
- **PSI memory `full avg10` > 10.** Why: `full` = all non-idle tasks stalled simultaneously — direct thrash indicator preceding earlyoom sweeps. Source: kernel doc semantics (same URL); the specific 10% default is `ungrounded — needs smoke-test` beyond doc semantics (no in-repo precedent); warn-only + env-overridable makes miscalibration cheap; flagged in §12.
- **Top-N = 5 (CPU∪RSS union).** Source: `VM_DISK_SUBFLOOR_TOP_N = 3` precedent (L1632), widened because two axes are unioned.
- **Re-alert growth 0.25.** Source: `VM_DISK_SUBFLOOR_GROWTH_REALERT = 0.10` precedent (L1629); load is noisier than disk-free so the band is wider. Ungrounded numeric within a factor of ~2; warn-only.
- **State at `~/.eps-autonomous/vm-cpu-guard.json`** (divergence from the brief's `.claude/cache/cpu-guard-state.json` example). Source: in-repo convention — every watcher dedup state lives under `AUTONOMOUS_REGISTRY_DIR` (`vm-disk-subfloor.json` L1778, `vm-disk-data.json` L2043, `happy-patch-alert.json` L2214); `.claude/cache/` holds event *streams*, not dedup state. GC-safe (singletons unswept, `_gc_target_paths` L9893).
- **Sidecar at `.claude/cache/cpu-guard-events.jsonl`** (dedicated, not the shared disk sidecar). Source: task body names it; parallels `disk-guard-events.jsonl` (L1966-1986) with a domain-separated stream.
- **Telegram via `_telegram_push` (digest queue).** Source: L13920-13966 + the 2026-06-12 batching decision recorded there; kill-push rate limit 3600 s bounds storms (journal shows repeated kills within minutes on 2026-06-28); sidecar keeps full fidelity. The 3600 s value is a convenience default — flagged ungrounded, warn-only.
- **`journalctl --since @<epoch>` + 60 s overlap + key-dedup.** Source: systemd.time(7) epoch syntax, live-verified today; overlap-plus-dedup prefers duplicate-suppression over boundary drops.
- **Single `ps` call (no two-sample delta).** Why: keeps the firing-tick cost ~100 ms; lifetime %CPU is representative for the hours-long sustained class. Source: `_top_issue_cache_paths`'s cheap-single-subprocess attribution precedent (L1669-1720).
- **dry-run performs zero `subprocess.run`.** Source: the #681 r3 convention (L1685-1691, L1738-1743).
