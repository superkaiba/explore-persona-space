<h1>Plan — issue #697 (v4)</h1>
<p class="small">Causal context-vector patch on #537's adapters: does finetuning a behavior into a context move the context vector (the input) or the context→behavior mapping (the function)? <strong>v4 = read-pathway fix: the v-space read was structurally independent of the patch (read-inert). v4 patches UPSTREAM (L=10) and reads at L=14 so the patch reaches the read.</strong></p>

<section class="changelog">
<h2>Revision log — what changed v3 → v4 (and what did NOT)</h2>
<p><strong>The binding Must-Fix (alternatives lens, reconciler-upheld):</strong> v3's read pathway was <em>read-inert</em> — the v-space <code>f_CV</code> (the headline DV) was structurally independent of the patch. <code>make_cv_patch_hook</code> overwrites layer-L's OUTPUT at the early context slot; <code>patched_read</code> reads layer-L's OUTPUT (<code>hidden_states[L+1]</code>) at the response slot — in ONE teacher-forced forward, with ZERO transformer layers between the edit and the read. The response-slot output of layer L was already computed by layer L BEFORE the overwrite touched the context slot, so the patch could never reach the read. I reproduced this on the salvaged <code>marker_sp_swe_seed42.pt</code>: <code>‖v_Pup − v0‖ = 0.000000</code> across all 280 pairs (a real install exists, <code>‖v⁺ − v0‖ = 1.69</code>), so <code>f_CV[p_up]</code> = mean = min = max = <strong>0.0</strong> — the design could not produce its own positive ("context-vector-moved") outcome. <strong>This was not analyzer-recoverable.</strong></p>
<p><strong>What v4 CHANGES:</strong></p>
<ul>
<li><strong>(F1) Read pathway — Option B: patch UPSTREAM, read at L=14.</strong> Patch the donor context vector at <code>L_patch = 10</code>; read v at <code>L_read = 14</code> (unchanged — preserves #651's read-layer inheritance for the headline). The patch now propagates through <code>14 − 10 = 4</code> attention layers before the read, so the response-slot read genuinely depends on the context-slot edit. Chosen over Option A (move the read off L=14 → breaks #651 inheritance + changes v0/v+ cross-cell comparability) and Option C (<code>generate()</code> path → conflicts with the <code>use_cache=False</code> Gate C1.2 decision + a far larger code surface). §4, §5, §6, §9, §10, §11 updated consistently. <strong>Cost-neutral</strong>: SAME forward count as v3's L=14-only patch (one patch layer); the donor is captured at L=10 instead of L=14 (free in the existing hidden-states forward). The marker-E logit read (which was NOT inert but weak, 0.34 nat) is ALSO strengthened — its patch now propagates through <code>28 − 10 = 18</code> downstream layers.</li>
<li><strong>(F2) Pre-launch inert-read assertion (§7).</strong> A non-skippable CPU-second smoke sub-check that re-runs the analysis on ONE salvaged cell and FAILS if the read is inert (<code>f_CV[p_up] ≡ f_CV[random_cv] ≡ f_CV[full_span] ≈ 0</code> while into-FT ≡ 1). This is the guard that would have caught the v3 regression instantly. It runs against the salvaged <code>.pt</code> on CPU — zero GPU spend.</li>
<li><strong>(F3) Marker E-DV four-float storage (§6.1, §11; Statistics Claude C1).</strong> <code>_marker_logp_at_slot</code> stored ONE float (<code>log P</code>); the three-space contract requires four. v4 captures <code>log P</code>, <code>z_marker</code>, <code>z_eos</code>, <code>logZ</code> from the SAME forward (the logits are already in scope at <code>out.logits[0,-1,:]</code>) — ~free, removes the saturation-blindness risk.</li>
<li><strong>(F4) #537 context-gating diagnostic registered (§6.5; Methodology Claude C1).</strong> The per-(B,C) #537 context-gating read is added as a primary-deliverable input so the analyzer can restrict any behavioral-E "mapping changed" verdict to cells where #537 shows real context-gating.</li>
<li><strong>(F5) Cosmetic edits.</strong> §11 <code>max_new_tokens=1024</code> framing (free-gen default, not marker-default); §4.2 "100K+-file" → "~64K-file" (live: 63,914); §4.2 import — <code>HfHubHTTPError</code> lives in <code>huggingface_hub.utils</code>, not the top-level import (verified: top-level <code>hasattr</code> is False).</li>
</ul>

<h2>Revision log — v4 → v5 (one-line fact-checker patch)</h2>
<p><strong>What v5 CHANGES:</strong> the §7.1 <code>assert_not_read_inert</code> detector's <code>f_cv_down</code> threshold and its inline comment. The v4 detector used <code>abs(pdn - 1.0) &lt; 1e-4</code> expecting the inert into-FT read to pin <code>f_cv_down ≈ 1.0</code>; the round-2 fact-checker (which re-ran the v3 reader on the salvaged <code>marker_sp_swe_seed42.pt</code> per Delta-5) verified that the actual inert <code>f_cv_down</code> value is <strong>exactly 0.0</strong> — because <code>compute_f_cv_down(v_Pdown, v0, v⁺) = 1 − dot(v_Pdown − v⁺, v0 − v⁺) / ||v0 − v⁺||² = 1 − 1 = 0</code> when the inert into-FT read pins <code>v_Pdown ≡ v⁺</code>. So the v4 detector was silently NON-functional: it would never fire on the very inert pattern the entire v4 revision exists to catch (the round-2 fact-checker reproduced this — assert "did NOT raise on inert salvaged data"). v5 patches the threshold to <code>abs(pdn) &lt; 1e-4</code> and corrects the inline comment to match the f_CV_down algebra. Verified by the fact-checker: with the corrected predicate, <code>abs(0.0) &lt; 1e-4 = True</code> → the detector correctly fires on the salvaged inert cell, and the §7.1a "MUST confirm the detector fires on the salvaged inert .pt" sanity check becomes a real gate. One character of logic + one comment line — no other §7.1 sub-checks are affected; the §7.1b positive gate on the NEW smoke cell is unchanged.</p>
<p><strong>What v5 KEEPS:</strong> everything else from v4 verbatim (Option B read pathway, four-float marker capture, #537 ctx-gating diagnostic, salvage re-run path, cost re-projection, §11 / §4.2 cosmetics). <code>Estimated GPU-hours (total): 74</code> unchanged.</p>

<section class="plan-tldr">
<h2>0.0 TL;DR (plain English)</h2>
<ul>
<li><strong>What I'll run:</strong> I take models that were already taught a quirk (a tic, a fact, a style) while they were playing a character, and I ask one clean question. Did teaching the quirk change the model's internal sense of who it is, or did it change how it acts on that sense? I test this by copying the "who it is" signal out of one model and into another, then watching whether the quirk comes along. The last version had a wiring mistake that made the test blind: I was reading the signal at the exact spot I edited, before the edit could travel anywhere, so the copy did nothing by construction. v4 edits the signal a few steps earlier and reads it after the edit has had room to spread, so the test can actually register a result. I also added a quick check that re-runs the math on data I already have and refuses to launch if the old blindness is still there.</li>
<li><strong>What I expect:</strong> For the tic and the taught fact, I think the quirk will ride along with the "who it is" signal, meaning the teaching mostly moved the self-picture. For the messier behaviors (harmful advice, agreeing with wrong claims) I'm genuinely unsure, and that's the interesting part.</li>
<li><strong>What would change my mind:</strong> If copying the self-picture across barely moves the behavior, then the teaching changed how the model acts on its self-picture, not the picture itself. Either way I learn something real, as long as the test isn't blind. The new pre-launch check is what guarantees that.</li>
</ul>

<h2>1. Goal</h2>
<p>(Verbatim, frontmatter — <code>set-goal --by user</code> ownership; NOT a v4 design question.) On #537's already-trained behavior×context LoRA adapters, causally localize whether finetuning a behavior into a context shifts the context vector (input to the map M) or the context→behavior mapping M (the function) via cross-model activation patching at the read layer, reading both the on-policy behavioral rate and the answer-side activation profile. The theory frame is the leakage paper's pre–fine-tuning model: M maps a context vector <code>c_C</code> to behavior; an experiment that decomposes which of the two the finetuning moved is a direct causal test of that decomposition. v4 changes nothing about this question — it fixes the read pathway so the measurement can actually register a "context-vector-moved" outcome (v3's read was structurally independent of the patch).</p>

<h2>3. Hypothesis</h2>
<p>UNCHANGED from v3 (this is a measurement, not a new hypothesis). Per behavior B, finetuning B into context C either (H_input) moved <code>c_C</code> with M intact → <code>f_CV ≈ 1</code> (patching the FT context vector into the base model reproduces the FT behavior profile), or (H_map) changed M with <code>c_C</code> intact → <code>f_CV ≈ 0</code> (patching the context vector carries none of the behavior). Falsifiable thresholds: a behavior with <code>f_CV</code> 95% CI entirely above 0.7 confirms H_input for that behavior; entirely below 0.3 confirms H_map; spanning is "mixed / underpowered". Pre-registered prediction (weak): marker + fact (slot-localized, context-invariant in #651) lean H_input; em + sycophancy (mean-resp behaviors) are genuinely uncertain. The P↓ cross-check (<code>f_CV_down</code>) must agree with <code>f_CV</code> for a confident cell verdict; disagreement is reported as a mixed cell. <strong>v4 read-pathway note:</strong> the falsification logic is unchanged, but it is now ACHIEVABLE — under v3's inert read, <code>f_CV</code> was pinned at 0 (a false "mapping changed" for every cell) regardless of the science; the upstream-patch read (§4) lets a genuine context-vector move register as <code>f_CV → 1</code>.</p>

<h3>4.0 Read pathway — the v4 fix (Option B: patch upstream, read at L=14)</h3>
<p><strong>The defect.</strong> v3 (= v2) installs <code>make_cv_patch_hook</code> at layer <code>L</code> (overwriting layer-L's OUTPUT at the context slot) and <code>patched_read</code> reads <code>hidden_states[L+1]</code> (= layer-L's output) at the response slot — same layer, ONE forward. Inside that forward, <code>orig_forward</code> computes ALL of layer L's outputs (every position, including the response slot) FIRST, and only THEN does the wrapper overwrite <code>hs[0, patch_pos, :]</code>. With zero transformer layers between the edited output and the read of that same output, the response-slot read never sees the patch. Empirically (salvaged <code>marker_sp_swe_seed42.pt</code>, L=14, slot pooling): <code>‖v_Pup − v0‖ = 0.0</code> for all 280 pairs.</p>
<p><strong>The fix.</strong> Patch at <code>L_patch = 10</code> and read v at <code>L_read = 14</code> (the #651 read layer, UNCHANGED). Now the read of <code>hidden_states[15]</code> at the response slot depends — through <code>L_read − L_patch = 4</code> attention layers (layers 11, 12, 13, 14) — on the patched context-slot residual at <code>hidden_states[11]</code>. The patch is no longer structurally invisible.</p>
<p><strong>Why Option B over A / C (the design decision; <code>Source:</code> in §11).</strong></p>
<ul>
<li><strong>Option B (chosen — patch upstream, read at L=14).</strong> Preserves #651's read-layer inheritance: v0, v⁺, the FT shift direction <code>d=(v⁺−v0)/‖·‖</code>, and the context-invariance read all stay at L=14, the exact layer #651 validated for marker/fact and where the project's persona-distance reads live. The headline join with #651/#537 is unchanged. Only WHERE the donor context vector is sampled/injected moves (to L=10) — and L=10 is INSIDE #651's swept depth band {7,14,21} (between the 7 supplement and the 14 primary), so the context vector is sampled in the validated mid-network regime, not an arbitrary shallow layer. <strong>Cost-neutral</strong> (same forward count; the donor capture at L=10 is free in the existing hidden-states forward). The denominator note: the f_CV ratio's v0/v⁺/d are read at L=14 exactly as before — the donor <code>c⁺</code>/<code>c0</code> are now read at L=10, which is the intervention input, not the read; this is the correct mediation form (inject the upstream context vector, read the downstream answer-side profile).</li>
<li><strong>Option A (rejected — keep patch at L=14, read at L≥20).</strong> Would move the v read OFF L=14, breaking the #651 read-layer inheritance and making v0/v⁺ non-comparable to #651/#537's L=14 reads (the headline cross-experiment join). The depth-robustness side-read would also shift. Larger interpretive cost for no code-surface saving.</li>
<li><strong>Option C (rejected — <code>generate()</code> with KV-cache propagation).</strong> Conflicts directly with the canary's Gate C1.2 decision (<code>use_cache=False</code> because caching DROPS the patch, parity Δ=0.25 ≫ tol 0.001) — the generation/cache path is the one already shown unreliable for this hook. Substantially more code surface + generation-time cost. The teacher-forced forward is the validated read path.</li>
</ul>

<ul>

The donor context vector for EVERY patch condition is the residual at <code>L_patch</code>, not L=14.</li>
<li><strong>Hook + read split in <code>_build_conditions</code> / <code>_patched_reads</code>.</strong> <code>_patched_reads</code> currently installs the hook at <code>layer</code> and reads at <code>layer</code> (one loop var). <h3>7.1 Pre-launch inert-read assertion (MANDATORY, non-skippable, CPU-seconds, 0 GPU — F2)</h3>
<p>BEFORE the production sweep dispatches, the implementer runs the <code>inert_read_assert</code> phase on ONE cell of the SALVAGED data (NOT new GPU spend — download the salvaged <code>.pt</code> and re-run the analysis function locally on CPU). This is the guard that catches the v3 regression instantly. <strong>Two parts:</strong></p>
<ul>
<li><strong>(7.1a) Negative control on the OLD salvaged data — must DETECT inertness.</strong> Re-run <code>_per_question_f_cv</code> on the salvaged <code>marker_sp_swe_seed42.pt</code> (the v3 same-layer artifact) and assert the inert-read DETECTOR FIRES on it (it IS inert by construction — this confirms the detector works). Expected: the assert below would RAISE on the salvaged data.</li>
<li><strong>(7.1b) Positive gate on the NEW smoke cell — must NOT be inert.</strong> After the smoke cell runs the L=10-patch / L=14-read path (one real GPU cell, part of the smoke gate 7.2), re-run the SAME detector on the NEW cell's <code>.pt</code> and assert it does NOT fire (the read is now non-inert).</li>
</ul>
<p>The detector (run on a cell's per-q f_CV at the read layer):</p>
<pre>
def assert_not_read_inert(cell, read_layer):
    fcv = _per_question_f_cv(cell, read_layer)          # f_cv, f_cv_full_span, f_cv_random over pairs
    pup    = np.nanmean(fcv["f_cv"])
    rand   = np.nanmean(fcv["f_cv_random"])
    span   = np.nanmean(fcv["f_cv_full_span"])
    # P-down: an inert into-FT read pins v_Pdown ≡ v⁺, so compute_f_cv_down(v⁺,v0,v⁺) = 1 − 1 = 0.0.
    pdn    = np.nanmean(fcv["f_cv_down"])
    inert = (
        abs(pup) < 1e-4 and abs(rand) < 1e-4 and (np.isnan(span) or abs(span) < 1e-4)
        and abs(pdn) < 1e-4
    )
    assert not inert, (
        "READ-INERT REGRESSION: response-slot read is independent of the context-slot patch "
        f"(mean f_CV[p_up]={pup:.6f}, [random_cv]={rand:.6f}, [full_span]={span:.6f}, "
        f"f_CV_down={pdn:.6f}). The patch layer must be < the read layer (Option B)."
    )
</pre>
<p><strong>How it gates:</strong> <code>inert_read_assert</code> (7.1a) runs in the <code>vendor</code>/pre-sweep CPU phase and MUST confirm the detector fires on the salvaged inert <code>.pt</code> (a sanity check that the detector is real). The smoke cell (7.2) then produces a NEW <code>.pt</code> on which 7.1b MUST pass (non-inert). If 7.1b FAILS, the sweep does NOT dispatch — the L=10-patch read is still inert and the layer split is wrong (e.g. the hook is still installed at the read layer). This is a non-skippable gate: the dispatcher refuses to enter <code>phase_sweep</code> until the smoke cell's <code>.pt</code> passes 7.1b. Cost: 7.1a is CPU-seconds on the salvaged file; 7.1b is one smoke cell (already in 7.2).</p>

<h3>7.2 Smoke-gate (the only other gate)</h3>

Justified: the run is &gt;4 h wall, the read-pathway change is NEW (the canary covered the old config), and the per-cell wall is the cost-uncertain quantity. No other gates — the design is otherwise pre-verified (canary C2/C1.2 reused).</p>

<h2>11. Decision Rationale</h2>
<p>v4 changes NO model-recipe hyperparameter (no training). The load-bearing choices are the read/measurement params + the read-pathway layer split (NEW) + the four cost levers (inherited). Grouped by source:</p>
<ul>
<li><strong>(NEW, v4) Read layer L=14, patch layer L=10 (Option B).</strong> Why: the v3 read was structurally inert (patch and read at the same layer in one forward; <code>‖v_Pup−v0‖=0</code> on the salvaged cell). Option B patches UPSTREAM (L=10) and reads at L=14 so the patch propagates 4 attention layers to the read. L=14 read PRESERVES #651's read-layer inheritance (v0/v⁺/d/context-invariance all at L=14 — the headline join with #651/#537); L=10 is inside #651's swept band {7,14,21}, so the donor context vector is sampled in the validated mid-network regime. <code>Source: #651 PRIMARY_LAYER=14 (read) + v4 read-inertness fix (patch &lt; read; L=10 ∈ #651 {7,14,21} capture band)</code>. Alternatives: Option A (read at L≥20) — rejected (breaks the #651 read-layer inheritance + v0/v⁺ cross-cell comparability); Option C (generate-with-cache) — rejected (conflicts with the use_cache=False Gate C1.2 decision — caching DROPS the patch — and a far larger code surface). Tunability: if 4 layers of propagation is too weak (smoke check), L_patch drops toward L=7 (more propagation) as a one-constant re-smoke.</li>
<li><strong>(NEW, v4) Marker E-DV four-float storage.</strong> Why: <code>_marker_logp_at_slot</code> stored ONE float (log P); the three-space contract requires four (log P, z_marker, z_eos, logZ) and they are free from the same forward (logits in scope at <code>out.logits[0,-1,:]</code>). Removes the saturation-blindness risk. <code>Source: .claude/rules/marker-leakage-measurement.md § Storage contract</code>. The f_CV^E ratio stays on log P (r3.3 closure). Gauge assert (target_modules exclude lm_head/embed_tokens) prerequisite — #537 adapters satisfy it.</li>
<li><strong>Read/patch slot = last content input token + per-cell decoded-token audit.</strong> Why: the context vector is read at the input position, audited so it never regresses onto a header/special/whitespace token (canary Gate C1.3). <code>Source: #651 slot read + A3.6c row</code>. Alternatives: <code>prompt_len−1</code> on the generation-prompted sequence — rejected (assistant header, item-4 bug).</li>
<li><strong><code>max_new_tokens=1024</code> (R generation, all arms).</strong> Why: the marker DV reads the END of the model's own response, so truncation creates silent zeros (#260). <strong>Cosmetic framing fix (F5):</strong> the marker-leakage rule's ≥2× / ≥2048 figure is the MARKER-TRAINING-COMPLETION cap; for THIS measurement the relevant cap is the project FREE-GENERATION default (1024, raised from 512 on 2026-06-24), which is ≥2× the OBSERVED ~150-tok median trained R on #537 (the salvaged marker cells, generated at 512, show non-truncated non-floor reads). So 1024 = the free-gen default AND comfortably ≥2× the observed median trained R. <code>Source: .claude/rules/marker-leakage-measurement.md (Qwen ~150-tok median; max ≥2× longest observed completion) + the project free-gen default 1024 + salvaged-cell observed non-truncation</code>. Alternatives: 512 (#651) — below the free-gen default, raised; 2048 — unneeded headroom at ~150-tok median.</li>
<li><strong><code>use_cache=False</code>.</strong> Why: the canary's Gate C1.2 measured KV-caching DROPS the patch (parity Δ=0.25 ≫ tol 0.001) — a correctness requirement, not a tunable. <code>Source: attempt-1 canary Gate C1.2 (canary_decision.json: use_cache_production_default=false)</code>.
