# Plan: #1097 — Consume the Step 10d lint-verdict only after `gh pr merge` succeeds; SHA-bind the verdict so retries stay certified and stale/hand-written verdicts fail closed

## Plan Summary

**What:** Reorder the two lint-verdict binding sites in `.claude/skills/issue/SKILL.md` Step 10d so the `rm -f` of `/tmp/issue-<N>-lint-verdict.txt` fires only after `gh pr merge` returns success, and replace on-read consume-once with **SHA-binding**: the gate's executable block appends the certified branch-tip sha as line 2 of the verdict file; both consumers accept a `pass`/`skip-artifact-only` verdict only while `git -C "$WT" rev-parse HEAD` still equals that sha. A #1041-shape transport failure (`can't be rebased` → `--squash` retry) then stays certified by the same gate run; a hand-written `echo pass >` verdict (the #1082 incident) or any post-certification commit fails closed. **Files:** `.claude/skills/issue/SKILL.md` (5 edit sites) + `tests/test_step10d_guard3.py` (1 test superseded by 2 new tests, 1 literal updated). ## 1. Goal + requirement + acceptance criteria

**Goal (Task #1097 `## Goal` H2, verbatim; kind: infra — no `goal:` frontmatter, no `epm:goal-updated` markers, re-verified at return time):**

> Consume (rm) the lint-verdict file only AFTER the `gh pr merge` attempt returns success; invalidate the verdict on new lint-surface commits instead of on read, so a rebase-refusal→squash retry stays certified by the still-valid gate run rather than a hand-written verdict.

**The bug (verified against the live tree):** the safe-case binding (`SKILL.md:8761-8769`) and the merge-conflict-recovery binding (`SKILL.md:8826-8837`) both run `rm -f /tmp/issue-<N>-lint-verdict.txt` **before** their `gh pr merge` / `git push` commands ("consume-once"). When the merge then fails for a non-lint transport reason — the documented #1041 "Known failure shape" (`SKILL.md:8780-8787`): a branch carrying a merge commit → `GraphQL: This branch can't be rebased` → documented recovery `gh pr merge --squash` — the PASS verdict is already deleted and the squash retry has no gate. Hit twice 2026-07-06 (#1081 PR #842, #1082 PR #843); #1082's session hand-recreated the file (`echo pass > /tmp/issue-1082-lint-verdict.txt`) — a self-attested gate write. Note the recovery path makes this failure **near-certain**, not rare: its own `git merge origin/main` + `git commit --no-edit` creates exactly the merge commit that refuses server-side rebase.

**Latent second gap this fix also closes:** today's verdict is not bound to any tree — a commit created between the gate run and the consume is silently certified by a verdict that never scanned it. SHA-binding closes both gaps with one mechanism.

**Requirements:**
1. `rm -f` of the verdict file fires only in (i) the post-`gh pr merge`-success branch, or (ii) the block/crash/stale fail-closed branch (a block verdict has no retry value — brief-confirmed, this stays).
2. Verdict file becomes two lines: line 1 = `pass|block|crash|skip-artifact-only`, line 2 = certified branch-tip sha (appended once, after the verdict if/elif chain, for all verdicts uniformly).
3. Both file consumers add a sha-equality conjunct; mismatch/missing sha → the existing BLOCKED else branch (fail closed, gate re-run regenerates).
4. All fail-closed properties preserved: missing file fails closed (the `2>/dev/null` grep conjunct); block/crash never merge; stale sha fails closed; hand-written verdict without the correct sha is useless (anti-self-attestation).
5. The surgical-additive-checkout block (same-shell `GATE_VERDICT` variable, `SKILL.md` ~9058/9120) is **not touched**.
6. Prose (the Verdict bullet at `SKILL.md:8616-8659`, the Known-failure-shape paragraph, the two consumers' lead-in comments) updated so text and executable blocks agree; test docstrings quoting "consume-once" updated.
7. `tests/test_step10d_guard3.py` pins the NEW invariant (rm only after merge success; sha-bound write + sha-checked consume) so a regression fails loud; the superseded consume-then-remove-before-ready test is deleted (Supersede → delete, code-style rule).

## 11. Decision Rationale

**Design decision — (a) SHA-bind the verdict (CHOSEN) vs (b) literal lint-surface-commit tracking (REJECTED).**

- **What:** the gate appends the certified branch-tip sha (`git -C "$WT" rev-parse HEAD`) as line 2 of the verdict file; consumers add one equality conjunct; `rm` moves into the merge-success branch; block/crash/stale branches keep their `rm` (a block verdict has no retry value — brief-confirmed).
- **Why (a):** (i) *Strictly fail-safe superset:* (a) invalidates on ANY new commit — a superset of (b)'s "new lint-surface commits", so (a) can never fail open where (b) wouldn't; the cost is one ~6-min gate re-run in the rare benign-commit-between-gate-and-merge case. (ii) *No duplicated scope knowledge:* (b) requires the consumers to re-derive the lint's scan surface (`.claude/**`, `CLAUDE.md`, `scripts/`, `src/`, plus the parity checks' surfaces) and diff `certified..HEAD` against it at two more call sites; any drift between the lint's actual scope and the consumers' copy reintroduces a silent fail-open — the exact class of bug this task exists to close. (iii) *Fewer moving parts:* (a) is +1 line at the writer and +1 conjunct per consumer; (b) needs a path-set constant, a `git diff --name-only <sha>..HEAD` at each consumer, and its own failure handling for a bad sha ref. (iv) *Closes a latent second hole:* today's verdict is not bound to any tree, so a commit created after the gate ran could ride an unconsumed pass verdict; (a) fixes this for free, (b) only partially (non-lint-surface commits would still ride). (v) *Anti-self-attestation:* an innocent `echo pass >` hand-write (the #1082 move) fails the sha conjunct; combined with consume-on-merge-success removing the *incentive* to hand-write (the retry is certified), the incident shape is closed at both ends. Honest scope note: a file-based gate cannot be cryptographically tamper-proof against a deliberate agent that also appends the current HEAD sha; the defense is fail-closed-by-default plus the explicit documented ban.
- **Source:** task #1097 Goal + incidents #1041 (PR #801), #1081 (PR #842), #1082 (PR #843); design candidates enumerated in the orchestrator brief; current-text verification by direct read this session.
- **Alternatives considered:** (b) as above; also considered switching the recovery's primary merge to `--squash` (its branch always carries a merge commit, so `--rebase` predictably refuses) — deliberately NOT done here (out of the Goal's scope; single-concern fix), flagged in §9 must-ask as a possible follow-up.
