### 4.2 The signature (decision + justification)

```python
def ensemble_verdicts_present(
    events: list[dict],
    kinds: Sequence[str],
    round_n: int,
    *,
    reconcile_role: str | None = None,
) -> dict[str, dict[str, Any]]:
```

- **Pure form over `events`, not an issue-number wrapper** — matches `stage_dispatch_should_skip` exactly; the call pattern is `ensemble_verdicts_present(list_events(N), [...], n)`. A pure function is trivially testable with dict fixtures (no tmp task tree needed) and composes with an orchestrator that already fetched events once (the Step 5b "ONE fetch, parse twice" discipline at SKILL.md ~2306–2311). The task-body sketch's `ensemble_verdicts_present(issue, kinds, round_n)` I/O form is rejected: every sibling predicate in this module that the orchestrator runs pre-decision is pure, and the brief's own preference agrees.
- **Return `dict[str, dict]`, not the sketch's `dict[str, bool]`** — the malformed-vs-absent distinction is load-bearing: rule item 3 routes a malformed durable verdict to "the role's malformed-output handling, never adopt it", while item 4's no-show handling fires ONLY when nothing exists. A bare bool cannot carry that three-way split, and collapsing "present but unparseable" into either bool value reproduces one of the two failure modes (either a false no-show on a real marker — the #810 class — or mechanical adoption of a malformed note). Per-kind value: `{"present": bool, "verdict": str | None, "ts": str | None}` — JSON-serializable so the SKILL.md heredoc can `json.dumps` it. `ts` rides along for freshness cross-checks (the rule's round-fresh reasoning) at zero cost.
- **Verdict-parse choice (presence-only vs strict Verdict-line): BOTH, separately reported.** `present` keys on marker existence at the round ONLY; `verdict` is the best-effort parse of the canonical `Verdict:` field. Justification: requiring a parseable `**Verdict:**` line for `present` would false-negative on real conforming markers (the #1090 terse Claude critique above), turning the anti-#810 predicate into a #810 GENERATOR; ignoring malformedness entirely (presence-only) would let the orchestrator mechanically treat a truncated/garbage note as a returned verdict, which item 3 forbids. The split gives the orchestrator exactly the rule's own decision table: `present=False` → item 2 then item 4; `present=True, verdict=None` → marker exists, read it / malformed handling — NEVER a no-show; `present=True, verdict=<token>` → the reviewer RETURNED, apply the normal ensemble rule.
- **Reconcile role-scoping: YES, via the keyword-only `reconcile_role`.** The reconcile marker kind is shared across all five doubled sites and its version field provably diverges from the round (the #1092 row above); two different roles can each post a reconcile whose sentinel names the same round number on one task. Without role scoping, a `kinds=["epm:review-reconcile"]` query at Step 9a could be satisfied by Step 5's reconcile — a wrong-role false positive on the very check the rule sends the orchestrator to. The role lives in the note's `**Role under adjudication:**` field (workflow.yaml ~2109–2112: the reconciler posts ONE canonical role-tagged `epm:review-reconcile`), parsed with `parse_followup_note_field(note, "Role under adjudication")`. Applied only when the queried kind is `epm:review-reconcile` AND `reconcile_role` is given (default None = kind-level presence, preserving the sketch's minimal contract for callers that don't need it).
- **Round matching: `version` field primary, note-head sentinel fallback.** An event matches round `n` iff `event["version"] == n` OR `note.lstrip().startswith(f"<!-- {kind} v{n} -->")`. The field is what `post_marker` writes and what most rows carry correctly; the sentinel fallback covers (a) the reconcile version/round divergence just shown, (b) `_next_event_version` auto-bump on a re-spawn that posts "at the SAME v<n>" per rule item 4 but omits `--version` (the defaulted post lands at max+1 while its sentinel says v<n>), (c) #480-documented wild non-monotonicity. Union semantics fail toward `present=True` — the correct conservative direction for an anti-false-no-show predicate.
- **Duplicates at the same kind+round: LAST (chronologically latest) match wins** for `verdict`/`ts` — matches the module's "most recent wins" scan convention (`_find_stage_breadcrumb` scans newest-first; resume contract is highest-version-per-kind) and the rule's re-spawn-at-same-v<n> semantics.
- **What the predicate does NOT do (scope fence):** no PASS/FAIL-class interpretation (per-site pass/fail vocabularies differ — workflow.yaml § ensemble_review `pass_values`/`fail_values`: PASS/CONCERNS/FAIL vs APPROVE/REVISE/REJECT vs not-redundant/redundant — so the raw token is returned and the orchestrator interprets); no `/tmp` output-file check (rule item 2 stays prose); no freshness windowing (that's `stage_dispatch_should_skip`'s job); no wrapper `epm:failure` inspection (rule's precedence clause stays prose). Mechanizing items 1+3's presence/conformance core is the task body's whole ask.

### 4.3 Implementation sketch

Placement: `src/explore_persona_space/task_workflow.py`, immediately after `stage_dispatch_should_skip` ends (~line 1627), before the `UPLOAD_VERIFICATION_PASS_RE` block — keeping the two orchestrator pre-decision predicates adjacent. (Minor placement deviation allowed.)

```python
# --- Ensemble verdict presence (#1149; mechanizes SKILL.md Step 5b ---
# --- durable-verdict-first rule items 1 + 3)                        ---

_RECONCILE_KIND = "epm:review-reconcile"


def ensemble_verdicts_present(
    events: list[dict],
    kinds: Sequence[str],
    round_n: int,
    *,
    reconcile_role: str | None = None,
) -> dict[str, dict[str, Any]]:
    """Per-kind durable-verdict presence for one ensemble round (#1149).

    Mechanizes items 1 + 3 of the /issue Step 5b durable-verdict-first
    rule: BEFORE any reviewer no-show decision, the orchestrator asks
    whether the round's expected verdict markers exist on events.jsonl
    and whether each carries a parseable ``Verdict:`` field. For each
    queried kind returns ``{"present": bool, "verdict": str | None,
    "ts": str | None}``:

    - ``present=False``  -> proceed to the rule's item 2 (durable output
      file), then item 4 (no-show handling).
    - ``present=True, verdict=None`` -> the marker EXISTS but its note
      has no parseable ``Verdict:`` field: malformed-output handling
      (rule item 3), NEVER a no-show (#810: a posted verdict misread as
      a no-show is the incident class this predicate closes).
    - ``present=True, verdict=<token>`` -> the reviewer RETURNED; apply
      the normal ensemble rule. The token is returned RAW (per-site
      pass/fail vocabularies live in workflow.yaml § ensemble_review).

    An event matches ``round_n`` iff its top-level ``version`` equals it
    OR its note head carries the ``<!-- <kind> v<round_n> -->`` sentinel
    (version/round divergence is real in the wild: reconcile markers'
    auto-derived version, #480 non-monotonicity). The LATEST matching
    event wins (re-spawns post at the same v<n>). When ``kind`` is
    ``epm:review-reconcile`` and ``reconcile_role`` is given, the note's
    ``**Role under adjudication:**`` field must equal it — a same-round
    reconcile for a DIFFERENT role never satisfies the check. Verdict /
    role parsing reuses :func:`parse_followup_note_field` (bold, bullet,
    ``; ``-joined and escaped-newline note shapes). Pure function over
    :func:`list_events` output — no I/O; the rule's item 2 (output-file
    probe) and precedence clauses stay orchestrator prose.
    """
    out: dict[str, dict[str, Any]] = {}
    for kind in kinds:
        sentinel = f"<!-- {kind} v{round_n} -->"
        match: dict | None = None
        for event in events:  # chronological; latest match wins
            if event.get("kind", "") != kind:
                continue
            note = event.get("note", "") or ""
            if event.get("version") != round_n and not note.lstrip().startswith(sentinel):
                continue
            if kind == _RECONCILE_KIND and reconcile_role is not None:
                role = parse_followup_note_field(note, "Role under adjudication")
                if role != reconcile_role:
                    continue
            match = event
        if match is None:
            out[kind] = {"present": False, "verdict": None, "ts": None}
        else:
            verdict = parse_followup_note_field(match.get("note", "") or "", "Verdict")
            out[kind] = {"present": True, "verdict": verdict, "ts": match.get("ts")}
    return out
```
