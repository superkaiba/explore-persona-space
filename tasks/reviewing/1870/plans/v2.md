## Goal / Requirement

A KEPT autostash produced by `scripts/sync_repo_root.py` is stranded work-in-progress
on the shared repo root, and today its only record is a stderr report line
(`  stash: KEPT …`) of whichever terminal Bash call happened to run the sync. The
#1751 SKILL.md duty makes SESSIONS copy that line into durable markers — but that
depends on the calling session noticing stderr. Requirement: the EMITTER itself
writes a durable, mechanically-enumerable record per KEPT outcome, and the stderr
advisory names that record's path.

**Acceptance criteria:**

1. Every KEPT outcome in `recover_stranded_autostash` (both variants: `pop failed
   unexpectedly` and `apply --check dirty`) durably appends exactly ONE JSONL row to
   a sidecar file in the existing `.claude/cache/` convention
   (`<repo>/.claude/cache/root-sync-kept-stash-events.jsonl`), written O_APPEND +
   fsync (the `_journal_append` pattern already in this script). Both call sites of
   `recover_stranded_autostash` are covered by construction (preflight ~L859 and the
   post-pull pass): the record rides the function, not the caller.
2. Row schema: `{ts (UTC ISO), repo, ref, sha (full), sha12, reason
   ("pop-failed" | "apply-check-dirty"), detail (rc/stderr one-liner or ""),
   rescue_patch (abs path), stash_list_len (len of `git stash list` after the keep)}`.
   Dedup keys on the full `sha`, NOT the `stash@{n}` ref — refs shift as entries
   push/pop; the commit sha is stable.
3. The existing report line KEEPS its verbatim `KEPT <ref> (<sha12>) — …` head (the
   #1751 SKILL.md surfacing duty and the /daily sweep grep on `stash: KEPT` must keep
   matching) and gains a trailing `; sidecar=<abs path>` (or
   `; sidecar-write FAILED (<err>)` on the fail-soft path).
4. Sidecar write failures are FAIL-SOFT: the sync's exit code, state machine, and
   every other report field are unchanged; the failure is loudly visible in the
   report line per (3) — observability must never break the recovery tool
   (the gist-publish fail-soft precedent). The dedup scan
   (`_kept_sidecar_known_shas`) is fail-soft on ALL read errors — OSError on open
   (path is a directory, permission denied, transient FS error) AND per-line JSON
   decode failures — returning `set()` / skipping the bad line; the cost of a
   degraded scan is one duplicate push, never a crashed recovery tool. This is the
   one sanctioned deviation from fail-fast: the crash signal is preserved in the
   report line, not swallowed.

   Fail-loud pin: tests/test_sync_repo_root.py test_kept_sidecar_write_failure_fail_soft asserts the sync completes with the report line carrying sidecar-write FAILED and never raises or silently swallows the write error.
5. Deduped Telegram escalation (the body's optional leg — IN scope, minimal): when a
   KEPT row's `sha` is NOT already present in the sidecar (i.e. a NEW stranded
   stash — "KEPT count grows") AND the sidecar append for this row SUCCEEDED, fire
   ONE fail-soft push via the existing `~/my-goat/scripts/telegram_push.sh` channel
   (mirror `vm_disk_guard._telegram_push`: missing script / non-zero rc → stderr
   WARNING, never a crash). **Push is SUPPRESSED when `_record_kept_stash` returns
   "" (append failed):** under a persistently failing sidecar write the sha never
   enters the file, so an unsuppressed push would re-fire on every sync run
   fleet-wide — an unbounded push storm; the `sidecar-write FAILED` report line is
   the loud signal on that path. Dedup key = full sha, read from the sidecar itself
   BEFORE the append. Kill switch: `EPM_DISABLE_KEPT_STASH_PUSH=1`. Message:
   `root-sync KEPT stash <ref> (<sha12>) on <repo> — rescue patch <path>; triage
   tracked in #1736`.
6. DRY-RUN runs write nothing (the dry-run branch returns before the KEPT sites —
   unchanged). A conflict-abort (exit 2) run that strands an autostash records NO
   sidecar row in THAT run — the entry is recovered (and recorded) by the NEXT
   sync's preflight `recover_stranded_autostash` pass: a stated one-run recording
   delay, not a gap.
7. Tests (in `tests/test_sync_repo_root.py`, reusing its existing fixtures — the
   apply-check-dirty KEPT outcome is already buildable via `_strand_autostash`):
   (a) a KEPT outcome appends one well-formed row (schema per item 2) + the report
   line carries both the `KEPT ` head and `sidecar=`; (b) sidecar write failure is
   fail-soft — sync completes, report line carries `sidecar-write FAILED`, AND the
   (monkeypatched) push fn is NOT called; (c) push dedup — second run over the same
   kept sha fires no second push (monkeypatched push fn), and the kill switch
   suppresses the push entirely; (d) the popped/clean path writes NO sidecar row;
   (e) `_kept_sidecar_known_shas` returns `set()` when the sidecar path is a
   directory (OSError fail-soft) and skips malformed JSON lines.

## Method delta (vs current behavior)

Current: KEPT outcomes land only in `report["stash"]` → `_emit_report` stderr.
Delta: add a durable sidecar append + advisory path + deduped push at the two KEPT
sites. NO change to sync semantics, locking, sweep, pull, or stash pop/keep
decisions. `KEPT-IN-RESCUE` (restored-file disposition, L1169) is deliberately OUT
of scope — different class (rescued file, not a stash entry), not what #1751/#1736
key on; noted here as an explicit exclusion.
