**Load this rule whenever a task plan says "use persona vectors", "extract a
persona vector", or "persona-vectors-style direction", OR extracts a
persona/behavior direction by mean-difference of positive/negative contrastive
activations.** The recipe below is the standing default any such task inherits.
It reproduces the extraction pipeline of arXiv 2507.21509 (Chen, Arditi,
Sleight, Evans, Lindsey — *Persona Vectors*, Anthropic) §2 + Appendix
("Direction extraction pipeline", "LLM-based trait expression score")
faithfully, with EXACTLY ONE standing deviation (§ "The 'except logits'
carve-out"). Pull the verbatim generation-prompt + trait-evaluation-prompt
templates from the paper itself via the arXiv MCP
(`mcp__arxiv-latex__get_paper_section arxiv_id=2507.21509
section_path="Direction extraction pipeline"` and `section_path="LLM-based

## The recipe (7 steps)

1. **Inputs.** A trait NAME + a brief natural-language trait DESCRIPTION.

2. **Artifacts** (one frontier-LLM generation from a single generic
   generation-prompt template — paper uses Claude 3.7 Sonnet; **project default:
   `claude-sonnet-4-5-20250929`**, the standard project model, unless the task
   plan names another frontier model and says why):
   - **5 pairs of contrastive system prompts** — the positive of each pair
     commands the trait, the negative commands the opposite.
   - **40 questions**, split into a DISJOINT **20-question extraction set** +
     **20-question evaluation set** (no overlap).
   - **1 trait evaluation prompt** (the rubric) carrying the verbatim
     `REFUSAL | 0–100` template from the paper's "LLM-based trait expression
     score" appendix.
   - The verbatim generation-prompt template is in the paper's "Direction
     extraction pipeline" appendix — fetch via the arXiv MCP (link, do not
     paraphrase the template).

3. **Generation.** Per extraction question, **10 on-policy rollouts under the
   POSITIVE system prompt + 10 under the NEGATIVE** (sampling, not greedy).
   Default **temperature 1.0** (sampling diversity is the point — grounded in
   `.claude/rules/on-policy-completions.md`, sampling tier; a different temp is
   named + justified in the plan like any hyperparameter).

4. **Judge-filter (LOAD-BEARING — this is exactly what #658 omitted).**
   - Score EVERY rollout 0–100 with the trait evaluation prompt.
   - KEEP positive-prompt responses scoring **>50** and negative-prompt
     responses scoring **<50**; DISCARD the rest.
   - **A judge return that is `REFUSAL`, non-numeric, or outside [0, 100]
     is DROPPED from BOTH arms — never coerced to a numeric score (in
     particular NEVER `→ 0`, which would silently keep a refusal as a clean
     `<50` negative and corrupt the negative-arm mean exactly where
     elicitation produces the most refusals).** The paper's verbatim rubric
     (cited above) emits `REFUSAL` as its first option, and the project's
     plain-integer Sonnet judge can also emit refusal text, "I can't
     score this", or an out-of-range value. **Report the per-arm
     dropped-rollout count** (the implementation persists it alongside the
     kept-rollout count) — the same surface that catches a low-yield
     elicitation upstream catches a low-yield filter here. The shape of
     this clause is mechanizable (a future `verify_plan.py` /
     `consistency-checker` check could grep a persona-vectors plan's
     filter step for the `REFUSAL`/non-numeric/out-of-range disposition).
   - **Judge = `claude-sonnet-4-5-20250929`** (the project judge, CLAUDE.md
     "Critical Rules"). Plain integer 0–100 score; threshold 50.
   - **The "except logits" carve-out (standing project deviation, user
     directive):** do NOT use the paper's GPT-4.1-mini logit-weighted
     top-20-token scoring, and do NOT add GPT-4.1-mini as a second judge. Use
     ONLY the standard project Sonnet 4.5 judge. A task that wants the paper's
     logit scoring back must state an explicit `### Override:` note in its plan
     (the critic REVISEs an un-noted reintroduction).

5. **Activation position.** Residual stream at **every layer, averaged over
   RESPONSE tokens** (the paper's `response-avg` — it beat prompt-last and
   prompt-avg in the position-extraction ablation). NOT a prompt position.

6. **Direction.** `r_B` (the persona vector) = mean(activations | KEPT
   trait-exhibiting rollouts) − mean(activations | KEPT non-exhibiting
   rollouts), computed PER LAYER → one candidate vector per layer.

7. **Layer selection — name the regime up front.** A task electing persona
   vectors MUST declare which regime applies:
   - **Steering / monitoring regime** — follow the paper: pick the ONE
     most-informative layer by steering effectiveness (the paper finds layer
     ~20 on Qwen2.5-7B for evil & sycophancy).
   - **Read-out / prediction regime** (e.g. the paper's A3.3
     finetuning-shift predictor `E ≈ r_Bᵀ v`) — SWEEP all layers and select by
     which best predicts the target signal. (#658's regime is read-out, not
     steering — sweeping all layers is correct there, single-steering-layer is
     not.)
   The two regimes select layers by different criteria; conflating them is a
   methodology error. State the regime in the plan; the critic REVISEs a plan
   that extracts persona vectors without naming it.
