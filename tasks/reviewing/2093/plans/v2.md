**Per-agent procedure (implementer):**
1. Inventory: parse every index row → (row text, target path(s), theme/trap class).
2. Classify each row exactly once:
   - KEEP — live, unique lesson.
   - MERGE(group) — ≥2 rows teaching the same trap/fix class → ONE row that still reaches every grouped body (multi-link row). Both/all original bodies stay reachable.
   - RETIRE — superseded: (a) the lesson is now enforced by a named always-on surface (cite the exact CLAUDE.md bullet / rule file / lint check / hook / agent-spec line, QUOTE its covering clause in the manifest, and verify the citation resolves by grep before retiring), or (b) the target/pattern it warns about no longer exists (REQUIRES a recorded repo-wide relocation grep, the workflow-fix-on-bug clause (b) discipline — a single-path probe never backs a nonexistence claim).
3. Apply edits; keep the one-line-per-memory shape.
4. Reconcile: `ls` each agent dir vs surviving row targets; record intentionally-unreferenced bodies in the manifest.
5. Verify: no-flags `workflow_lint.py` + a link-resolution loop (grep each row's path token, `test -f` it).

**Concurrent-append hazard (load-bearing; critic r1 Must-Fix 1 applied):** review rounds fleet-wide append rows to these three indexes on `main` while the branch is open. On the server-side `gh pr merge` path the `.gitattributes` `merge=union` driver does NOT apply (`.gitattributes:11-30` — local merges/rebases only), so the fold below + the post-merge assert (acceptance criterion 7) are the SOLE mechanism, not a backstop for one:
- **Pre-merge fold (orchestrator, at Step 10d entry, before any merge command):** `git -C "$WT" fetch origin main --quiet && git -C "$WT" diff HEAD...origin/main -- .claude/agent-memory/` (merge-base→origin/main = MAIN-side changes since fork). For each row ADDED on main after fork in a curated index: fold it into the curated copy verbatim — deduping against ALL surviving rows (a main-side re-append duplicating a kept or merged row is dropped as a duplicate, with the dedupe named in the manifest). For each row REMOVED on main after fork (e.g. a user "forget" landing mid-branch): main-side removals WIN — remove it from the curated copy too. Commit the fold on the branch, then proceed to the merge.
- **Post-merge assert:** acceptance criterion 7 above, run immediately after the merge lands, closing the fold→merge TOCTOU window.
