## 4. Design

### 4.1 Predicate semantics (pinned — tests enforce each leg)

The fallback fires iff ALL of:

1. **Filename leg:** the basename of `remote_path` ends with `-results.json`. This composes with the drain glob (`sentinel_drain_shell`, `:1393`: `/workspace/logs/issue-<N>-*.json`, `.processed` excluded) to `issue-<N>-…-results.json` shapes, and matches the incident file `issue-825-results.json` exactly. No collision with canonical enveloped writers: they name `issue-<N>-<kind_slug>-<epoch>.json` (e.g. `issue-650-epm_results-1750….json` — underscore slug + epoch suffix, does not end in `-results.json`). Basename (not full path) so the GCP #610 out_root fallback glob is covered identically.
2. **Raw-payload leg:** NONE of the three `_SENTINEL_REQUIRED_KEYS` is present in the dict. A partial envelope (any 1-2 of the three present) is an ambiguous or buggy writer — possibly a future schema signal — and keeps today's loud skip. Only the genuinely raw shape (the #825 shape) is rescued. Corollary: the unsupported-schema-version branch is unreachable from the fallback (a body with `sentinel_schema_version` present never enters it), so version-gated skips are never rescued.
3. **Key-set leg:** ALL 10 Step 7 keys present at TOP level of the dict — `eval_numbers, eval_paths, reproducibility_card, wandb_url, hf_hub_url, worktree_path, final_commit_sha, gpu_hours_used, gpu_hours_budgeted, plan_deviations` (verified verbatim against `.claude/skills/issue/SKILL.md` lines 4033-4060). **Extra keys are tolerated** (all-10-required, not exact-set): pod-side writers legitimately add `task_id`, `ts`, `skipped_phases`, etc., and an exact-set rule would break the rescue on precisely the ad-hoc writers most likely to need it. Requiring all 10 keeps the predicate unambiguous — any partial subset could be a coincidental non-results dump and stays on the skip path. Presence-only check (no per-key type validation): the orchestrator-side Step 7 consumer is the semantic validator, same as for enveloped sentinels today.

**Near-miss loudness:** filename leg + raw-payload leg pass but key-set leg fails → still skipped, but `log.error` names which of the 10 results keys are missing (this file is probably the terminal payload, corrupt, on a VM about to self-delete — an operator should look immediately). All other misses keep the existing `log.warning` skip unchanged.

### 4.2 Insertion point: inside `_parse_sentinel` (chosen), not in the caller

Weighed both options from the brief:
- **(a) Synthesize inside `_parse_sentinel`'s missing-keys branch (CHOSEN).** `_parse_sentinel` returns `None` for five indistinguishable reasons; a caller-side fallback in `drain_sentinels_via` would have to re-decode and re-validate the body to learn WHY parsing failed, duplicating the gate. Synthesizing the envelope in-parse keeps one validation gate, and the returned dict flows through every existing downstream mechanism unchanged and for free: kind/version/note extraction, dict-note → `json.dumps`, the oversize-note `_persist_oversize_note` degradation (#477), `.processed` rename + honest accounting, and gate extraction. Both lanes are covered automatically (§3).
- (b) Handle `None` + re-parse in `drain_sentinels_via` — rejected: duplicates decode/validation, and every future caller of `_parse_sentinel` would silently lack the rescue.

### 4.3 Near-real diff (pseudocode — implementer refines)

```python
# module level, next to _SENTINEL_REQUIRED_KEYS (~line 789):
_RESULTS_PAYLOAD_KEYS: tuple[str, ...] = (
    "eval_numbers", "eval_paths", "reproducibility_card", "wandb_url",
    "hf_hub_url", "worktree_path", "final_commit_sha",
    "gpu_hours_used", "gpu_hours_budgeted", "plan_deviations",
)  # /issue SKILL.md Step 7 results-payload contract (all required)
_RESULTS_SENTINEL_SUFFIX = "-results.json"


def _maybe_synthesize_results_envelope(
    remote_path: str, data: dict[str, Any], missing: list[str]
) -> dict[str, Any] | None:
    """#899 fallback: rescue a raw Step 7 results payload on a results filename.

    Returns a synthesized enveloped dict, or None (caller keeps the skip path).
    Fires ONLY for: basename endswith -results.json AND no envelope key present
    AND all 10 Step 7 payload keys present (extras tolerated).
    """
    if not remote_path.rsplit("/", 1)[-1].endswith(_RESULTS_SENTINEL_SUFFIX):
        return None
    if any(k in data for k in _SENTINEL_REQUIRED_KEYS):
        return None  # partial envelope: ambiguous writer — keep the strict skip
    missing_payload = [k for k in _RESULTS_PAYLOAD_KEYS if k not in data]
    if missing_payload:
        log.error(
            "sentinel %s sits on a results filename with no envelope AND is "
            "missing results-payload keys %s; skipping (NOT rescued) — inspect "
            "before the VM self-deletes (#899)",
            remote_path, missing_payload,
        )
        return None
    log.error(
        "sentinel %s carried a complete Step 7 results payload but no envelope "
        "keys %s; synthesizing kind=epm:results version=1 and posting — "
        "pod-side writer should emit the envelope (#899)",
        remote_path, missing,
    )
    note = dict(data)                      # non-destructive copy
    note["envelope_synthesized"] = True    # provenance, rides the marker note
    return {
        "sentinel_schema_version": SENTINEL_SCHEMA_VERSION_SUPPORTED,
        "kind": "epm:results",
        "version": 1,
        "note": note,
        "by": "pod-sentinel-envelope-fallback",  # secondary provenance
    }


# in _parse_sentinel, the missing-keys branch (currently lines 1690-1693) becomes:
    missing = [k for k in _SENTINEL_REQUIRED_KEYS if k not in data]
    if missing:
        fallback = _maybe_synthesize_results_envelope(remote_path, data, missing)
        if fallback is not None:
            return fallback
        log.warning("sentinel %s missing required keys %s; skipping", remote_path, missing)
        return None
```

Downstream behavior of the synthesized dict in `drain_sentinels_via`, all inherited unchanged: `kind="epm:results"`, `int(version)=1`, `note` is a dict → `json.dumps(..., ensure_ascii=False)` (identical serialization an enveloped writer's dict-`note` results sentinel gets); `by` comes from the synthesized envelope; `data.get("gate")` is `None` at envelope level — a stray `gate`/`blocks_pipeline` EXTRA key inside the raw payload stays inside `note` and can never park the pipeline; an oversize note degrades via the existing `_persist_oversize_note` path and still renames `.processed`.

**Provenance (two channels, both cheap):** `envelope_synthesized: true` injected into the note JSON (dashboard/orchestrator-visible; Step 7 consumers extract named keys and tolerate extras — the same tolerance argument as §4.1 leg 3) + the distinct `by` string `pod-sentinel-envelope-fallback` (visible in the event row without parsing the note). The near-miss loud log + double log line on rescue (helper `log.error` only; the generic `log.warning` fires only when the helper declines) are intended.

## 11. Decision Rationale

N/A — no training hyperparameters (kind: infra; the hyperparameter-grounding check is exempt). N/A — no behavioral construct. N/A — not a replication. N/A — no artifact reuse. N/A — no dry-run smoke; smoke evidence = the pytest suite in §5.

Design decisions:

1. **Insertion point = `_parse_sentinel` missing-keys branch.** *Why:* single validation gate; caller-side handling would re-decode/re-validate because `None` is overloaded across five failure reasons; downstream mechanics (serialization, oversize degradation, rename, gate handling) inherited unchanged; covers RunPod + GCP automatically. *Source:* read `scripts/poll_pipeline.py:1671-1849` + `backends/gcp.py:4285-4440` + repo-wide grep (§3). *Alternatives:* caller-side fallback in `drain_sentinels_via` (rejected — duplication); a separate pre-pass over listed sentinels (rejected — two gates to keep in sync).
2. **Predicate = results basename + all-3-envelope-keys-absent + all-10-payload-keys-present, extras tolerated.** *Why:* narrowest predicate covering the incident; extras-tolerated because real writers add `task_id`/`ts`/`skipped_phases` and exact-set would defeat the rescue where it is most needed; all-10-required because any subset is ambiguous; all-3-absent because a partial envelope is a versioning/bug signal that should stay a loud skip. *Source:* #825 run-7 incident shape (task body + events); SKILL.md Step 7 key list (lines 4033-4060); `_sentinel_body` fixture + writer scripts showing standard extra keys. *Alternatives:* rescue when `kind=="epm:results"` is present but `sentinel_schema_version`/`version` missing (rejected — expands beyond the incident shape and forces a note-vs-top-level payload disambiguation); regex allowing epoch-suffixed `-results-<epoch>.json` (rejected — speculative writer shape, loud skip suffices until observed).
3. **Log level = `log.error` for both the rescue and the near-miss.** *Why:* the rescue signals a pod-side writer contract violation that self-healed (operator should fix the writer); the near-miss signals a probably-corrupt terminal payload on a VM about to self-delete (operator should act now). Both satisfy the LOUD constraint; ordinary non-matching skips keep `log.warning` unchanged. *Source:* task hard constraints; existing drain log conventions (`log.error` for post/rename failures, `log.warning` for benign skips). *Alternative:* `log.warning` for the rescue (rejected — blends into the routine skip noise the incident already demonstrated is missable).
4. **Provenance = `envelope_synthesized: true` in the note JSON + `by="pod-sentinel-envelope-fallback"`.** *Why:* the drain passes only `kind/version/by/note` to `post_event`, so provenance must ride one of those; the note key is machine-readable by the dashboard/orchestrator, the `by` string is visible without parsing the note; injected into a COPY so the original payload dict is untouched. *Source:* read of `drain_sentinels_via`'s `post_event` call (`:1758-1766`) and `by` default (`"pod-sentinel"`). *Alternatives:* note-string prefix line (rejected — breaks `json.loads(note)` consumers); a new `post_event` kwarg (rejected — public API contract change, out of scope / architectural).
5. **No gcp.py change.** *Why:* the GCP drain wrapper delegates to the shared `drain_sentinels_via` and holds no validation copy. *Source:* `gcp.py:4351/4362/4428` reads + the §3 grep audit. *Alternative:* defensive duplicate check in gcp.py (rejected — the #608-era design deliberately shares one loop shape "so the two lanes can never drift").
