### 4.2 `scripts/daily_drive_filings.py` — token helpers (replace `_route3_item_tokens`, line ~681)

```python
def _route3_informative(tokens: set[str]) -> set[str]:
    """Route-3 informative subset: boilerplate, generic-vocab + date tokens removed (#1687)."""
    return {
        t
        for t in tokens
        if t not in ROUTE3_BOILERPLATE_TOKENS
        and t not in ROUTE3_GENERIC_TOKENS
        and not ROUTE3_DATE_TOKEN_RE.match(t)
    }


def _route3_item_tokens(title: str, bug: str) -> set[str]:
    """Informative tokens of a route-3 item: title (daily-held: stripped) + bug text."""
    t = (title or "").removeprefix(ROUTE3_TITLE_PREFIX)
    return _route3_informative(informative_title_tokens(t) | informative_title_tokens(bug or ""))


def _route3_title_tokens(title: str) -> set[str]:
    """Subject tokens of the TITLE alone — the #1687 anchor set (same exclusions)."""
    t = (title or "").removeprefix(ROUTE3_TITLE_PREFIX)
    return _route3_informative(informative_title_tokens(t))
```

- **D1 — `ROUTE3_GENERIC_TOKENS` contents (17 tokens): measured df ≥ 4, plus inflections, plus the incident family — nothing else.** What: exclude `daily, backlog, held, every, gate, still, step, route-3, session, across` (each measured at document frequency ≥ 4 of 37 on the full historical daily-held corpus — frontmatter title + template-stripped origin_prompt, 2026-07-25 pass: daily 16, backlog 9, held 9, every 6, gate 6, still 5, step 4, route-3 4, session 4, across 4), their plurals (`gates, steps, sessions` — the tokenizer does not stem), and `warn, warns, warning, warnings` (the incident's third token + inflections; log-level vocabulary). Why the tight curation rule: the df=3 band contains subject-bearing tokens (`codex`, `zombie`, `stranded`, `draft`, `review` — `codex` is literally the true-dup pair's anchor), so a looser cut would eat real duplicate signal; the guard test (§4.4 item 5) pins the rule. **Source:** this plan's measured corpus pass (n=37), quoted verbatim; incident ledger row 2026-07-25. **Alternatives:** a large hand-vetted workflow-vocabulary list (rejected: unmeasured curation is the exact staleness/wrongness pattern the incident exposes); corpus-frequency top-K computed live at scan time (rejected: non-deterministic matcher, population-dependent behavior, harder to test — and the fail-open scan would change outcome run-to-run).
- **D2 — Keep `ROUTE3_MIN_SHARED_TOKENS = 3` (do NOT raise to 4).** Why: the raw noise ceiling moved 1 → 3 in one week (n=5 → n=14 population); a threshold raise chases a moving, population-size-dependent ceiling and leaves margin 1 with no structural protection. Post-exclusion, threshold 3 has the same measured margins the #1483 calibration originally had (noise-max 2, true-dup 5). **Source:** §5 measurement; #1483 plan v1 §11 D2 (methodology inherited: measured-threshold calibration). **Alternatives:** raise to 4 (rejected: passes today's matrix but is the brittle fix; the #1483→#1687 history is the direct evidence).
- **D3 — Title-anchor condition (≥1 shared post-exclusion TITLE token).** Why: structural, population-independent precision — every measured false-positive pair has title-intersection ∅ (#1537×#1686, #1636×#1686, and all 91 live pairs), while the true-dup pair anchors on `{codex}` (matching #1483's own measured title-only overlap of 1). It converts "generic prose overlap alone" from a suppression into a filing by construction, which is the Goal verbatim. An item whose title has no informative subject tokens can never be suppressed (early `return None`) — consistent with fail-open. **Source:** §5 measured matrix; #1483 plan v1 §2 ("title-only overlap for the pair = 1 (`codex`)"). **Alternatives:** anchor-only without the exclusion set (rejected: two titles sharing one generic token — e.g. both "…gate…" — would re-open the incident class; the exclusion also applies to the anchor computation); requiring ≥2 title tokens (rejected: the one measured true dup has exactly 1 — would kill recall on the only ground-truth positive).
- **D4 — Route-3-scoped constants in `daily_drive_filings.py`; the shared `task_workflow.py` stoplist untouched.** Why: `_WF_FIX_TITLE_STOPWORDS` is load-bearing for the #1446/#1399/#1502 sibling-scan arms (their thresholds were calibrated against it; #1483 already listed touching it as a must-ask deviation). A global stoplist edit would silently change those matchers' recall — e.g. `gate`/`step` are legitimately subject-bearing in wf-fix TITLES ("plan-approval gate", "Step 10d"), where the sibling arms match on short title-only token sets, unlike route-3's long bug/origin prose. **Source:** task-#1687 body constraint (verified: `_WF_FIX_TITLE_STOPWORDS` at `task_workflow.py:1112` = 11 generic English glue words); #1483 plan v1 §"Requires a plan-amendment note". **Alternatives:** global stoplist extension (rejected as above); a second `task_workflow.py`-level tokenizer variant (rejected: the driver's scans are deliberately `tasks_root`-injectable and driver-local per #1483 D4).
- **D5 — No `ROUTE3_ORIGIN_TEMPLATE_RE` widening.** The manual-escape origin form (`/daily 2026-07-24 route-3: …`, #1686) bypasses the template strip, leaking `daily`/`route-3`/date tokens into task-side sets — all three are now excluded at token level, which subsumes the regex fix at zero extra diff. **Source:** measured — #1686's task-side tokens under the fix; the residual #1636×#1686 overlap drops from 3 to 2 via the `daily` exclusion alone. **Alternatives:** widen the regex too (rejected: redundant, larger diff).
- **D6 — Additive `anchor` field in the ledger row + `ALREADY-TRACKED` line.** Why: every suppression is human-audited via the daily-record line and ledger (the #1483 wrong-match escape channel — exactly how this incident was caught); exposing which title tokens anchored the match makes the next wrong match diagnosable at a glance. Additive only; the outcome vocabulary is unchanged (`already-tracked` stays — no #1483 must-ask deviation triggered). **Source:** #1483 §11 (triple-recording rationale); the incident recovery path. **Alternatives:** no field (rejected: free auditability); a new outcome name (rejected: vocabulary change is a must-ask).
