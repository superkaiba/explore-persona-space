### 4. Design

**What is new vs reused:** NEW — one paragraph in planner.md + one pin-test file. REUSED — the pin-test pattern from `tests/test_planner_row_coverage_guidance.py`; no other file changes. Why a doc edit and not code: the deliverable is planner-authoring behavior; there is no mechanical verifier for "the trace is semantically correct" (that stays with the Phase-1.5 fact-checker, per verify_plan.py's scope-discipline note) — a verify_plan check is deliberately NOT in scope (see §11 and Risks).

**4.1 Definition tightness (design consideration: when the rule fires).** The rule fires iff BOTH:
1. the plan **designs or modifies a predicate that classifies a persisted artifact's shape/contents to decide an automated action** — a watcher lane's fire/keep, a guard hook's block/allow, a janitor's reap, a failure classifier's class routing. Ordinary experiment plans (DVs, judges, statistical tests) are NOT automated-action predicates and do not trigger it; and
2. the **motivating incident left a persisted artifact** (transcript, log, `events.jsonl` row, sidecar row).

"Trace against the REAL artifact" concretely requires, in one §12 assumption row: (a) the artifact named **by path**; (b) **every predicate arm — including the read/ingest path that feeds it** (the #1287 defect was half a read-path defect: the 262,144 B cap made `rows=None`) — evaluated on values **measured from the artifact at plan time** (row counts, byte sizes, field values — read, never recalled); (c) the **traced outcome stated** (fires / does not fire, per arm). The predicate MUST fire on its own motivating incident; "would not fire" is a design defect to fix before returning the plan. Escapes: artifact aged off disk → trace the incident's recorded measurements at Medium confidence; prospective guard with no incident artifact → state that explicitly in the row.

- **Insert kept ≈1.2 KB.** *Why:* planner.md is always-loaded and already over the WARN threshold; every token costs. The three refinements over the candidate sketch (trigger gate, read-path clause, escapes) are each load-bearing — the gate prevents over-firing, the read-path clause covers half the actual #1287 defect, the escapes prevent the rule from blocking plans whose artifact is gone. *Source:* #1287 v2.md revision note (the defect anatomy); AGENT_SPEC constants (the budget).
- **Pin test rather than prose-only.** *Why:* the durability-pin rule family (planner.md § Rules; lineage #1134/#1045/#884) — protection prose a later editor could silently drop gets a standing pin; planner.md's WARN-band status makes trim-deletion a live risk, and precedent exists (`test_planner_row_coverage_guidance.py`). Whitespace-normalized phrase asserts chosen over byte-exact so re-wrapping doesn't false-fail. *Source:* #1208 precedent + the durability-pin rule. *Alternative:* no test — rejected (the exact failure mode the pin family exists for).
- **No verify_plan.py check.** *Why:* verify_plan checks verify SURFACE only; "the trace used real measured values" is semantic and stays with the fact-checker by that file's own scope-discipline note. A regex check ("does §12 contain the word trace near a path?") would be a hollow gate. *Source:* verify_plan.py header (scope discipline); code-style hollow-verification-gate rule. *Alternative:* a c35-style conditional WARN — deferred; can file separately if the class recurs.
