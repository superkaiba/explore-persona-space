# Plan v2 — #1894 workflow-fix: concurrent-committers rule mandates pathspec-limited COMMITS

### TDD: no

## Goal / Requirement

Repo-root commits composed by interactive/orchestrator sessions are always pathspec-limited, so a concurrently-populated shared index can never be swept into an unrelated commit. Incident: commit `5e4124acc9` (2026-07-30) staged its own 2 files by explicit path but ran `git commit -F <msg>` with NO pathspec; a parallel session had staged 4 task files (tasks/planning/1841/events.jsonl, tasks/proposed/1892/*) in the stage→commit gap, and the bare commit swept them in — content correct, but mis-attributed, and the same shape can sweep half-staged foreign WORK.

**Acceptance criteria:**
1. CLAUDE.md § "Concurrent repo-root committers" states the COMMIT side explicitly: commit with an explicit pathspec (`git commit -m/-F <msg> -- <paths>`), with the why (bare commit commits whatever the shared index holds) and the task.py flock-serialized exemption.
2. The SKILL.md Step 9a-ter inline-commit recipe (procedure step 3, the site the task body names) carries the same clause where it prescribes a repo-root commit.
3. No behavior change to `guard_root_code_commit.sh` (deliberate deflection — see § Deviations).
4. No NEW `workflow_lint.py` failures attributable to the payload vs the Step 10d baseline-subtracted lint gate (pre-existing main red never blocks); touched files ruff/format clean in absolute terms.
