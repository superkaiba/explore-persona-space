## Method delta vs existing checks

Nothing mechanical detects pointer staleness today: the ~20 `gotchas.md` mentions inside
`workflow_lint.py` are checks CITING gotchas.md, none verifying co-reference freshness.
Closest structural precedent is `check_lessons_index` (index-vs-rules parity); this check
is the rule-file-to-rule-file sibling: co-reference (pointer) vs target (gotchas.md id
set) parity.

## Detector design (calibrated against the live tree, 2026-08-19)

Scan scope: tracked `.claude/**/*.md` plus repo-root `CLAUDE.md`, EXCLUDING
`.claude/rules/gotchas.md` itself and `.claude/agent-memory/**` (per-agent memories are
historical records — "true when written" by convention — not navigational surface).

Per LINE containing `gotchas.md`:
- Skip relocation-attribution idiom lines (the #2189 pattern, reused by future
  relocations): any line containing `Relocated codebase traps` or
  `to recover gotchas.md byte budget`.
- For each id matching `(?<![\w/])#(\d+)\b` (the lookbehind drops `pytorch#94772`-class
  external-tracker refs) with `N <= REGISTRY.json highest_id` (drops residual non-task
  numbers), within <=100 chars of a `gotchas.md` token on the same line:
  FAIL if `#N` does not occur anywhere in `.claude/rules/gotchas.md`, unless
  `(path, N)` is in a module-level `STALE_GOTCHAS_POINTER_ALLOWLIST` (each entry carries
  a reason string, the `EMPTY_TEXT_DEFAULT_ALLOWLIST` idiom).

Calibration evidence (run against main at plan time):
- Paragraph-level co-occurrence: 384 hits, overwhelmingly false positives — rejected.
- Raw same-line, unscoped: 82 hits; FP classes = agent-memory notes, the six
  relocation-attribution headers (which cite `#2189` — the correct relocation records
  firing on themselves), `pytorch#94772`-class ids, and far-apart co-mentions on long
  single-line paragraphs (`pods.md`, `context-hygiene.md`).
- Scoped detector (rules above): exactly 7 hits = 5 true positives + 2 false positives,
  triaged in the next section.

FAIL vs WARN (the task body's open question, settled by this calibration): FAIL. With the
baseline fixed the residue is zero, the trigger (a `gotchas.md` mention with a nearby
task-id) is rare in new prose, and the mechanization value — a future relocating task is
FORCED to update pointers in the same diff — requires a blocking verdict. The allowlist
constant is the escape hatch for genuine context-citation shapes. Kill criterion below
covers the case where implementation-time calibration diverges.

## Implementer notes (critic round 1: APPROVE, 5 nice-to-haves folded in)

The Methodology critic independently re-implemented the detector and reproduced the
identical 7-hit set. Fold these into the implementation:

1. Check docstring discloses the detector's known FALSE-NEGATIVE classes: (a) wrapped-line
   split — a #N landing on the line AFTER the gotchas.md token escapes the line-scoped
   window (live example: artifact-reuse.md:641-642, where #841 wraps and is caught only
   because #723 shares line 641); (b) id aliasing — an id surviving elsewhere in gotchas.md
   attached to a DIFFERENT entry reads as fresh. Disclosed-miss precedent:
   smoke-blind-spots.md § Enforcement.
2. Check docstring names the two sanctioned relocation-attribution skip idioms verbatim
   ("Relocated codebase traps", "to recover gotchas.md byte budget") so a future relocating
   task whose attribution header trips the lint gets a self-serve fix; PIN both idiom
   literals in the new test file so skip-string drift breaks a test.
3. Name the true-positive class accurately in docstring + failure message: "dead task-id
   next to a gotchas.md mention" (a superset of relocation — 2 of the 5 baseline TPs are
   id-trims where the entry still lives in gotchas.md), so triage never assumes every hit
   means a relocation.
4. Add a fixture pinning MIN-distance-over-multiple-gotchas.md-tokens semantics (two
   tokens on one line where only the min-distance read fires) — a first-occurrence-only
   line.find() implementation would silently diverge from the calibration.
5. Id-cap source: read the literal REGISTRY.json["highest_id"] field (currently 2378) —
   NEVER max() over top-level keys (the dict mixes digit and non-digit keys and a naive
   max crashes or under-reads); the pin test's registry fixture includes the mixed-key
   shape.
