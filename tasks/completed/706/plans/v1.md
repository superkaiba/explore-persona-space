## 11. Decision Rationale

N/A — no training hyperparameters (workflow files have no hyperparameters).

Non-obvious design choices (not hyperparameters):
- **Tag-skip enforced in `_proposed_infra_candidates` (candidate query), not in `decide_proposed_infra_sweep` (decision fn) or `_proposed_infra_hold_reason` (hold gate).** Rationale: `_proposed_infra_hold_reason` keys off the PM-queue-file `holds` map (NOT on-task tags) by design — `needs-human` is an ON-TASK tag a /daily filer applies with no PM in the loop, so the hold-map gate would never see it. Filtering at candidate enumeration (where the `list-by-status --json` rows carry `tags`) is the single point that covers BOTH the orphan case (no PM queue entry) and is trivially test-locked. The decision fn stays a pure cap/hold/registration matrix.
- **`needs-human` (not `needs-thomas`) as the tag.** The task body specifies `needs-human`; `needs-thomas` already exists as a PM-surfaced tag but is used for a different (broader) class. Using the body's `needs-human` keeps the /daily-held semantics distinct and matches the acceptance criteria.
- **`daily-auto-filed` third tag on route 2.** Distinguishes /daily-filed review tasks from manual workflow-fix-on-bug filings, so the PM digest count M and any future audit can attribute them.
- **Reuse `file_infra_task.py` for routes 2 AND 3** (route 3 via `--no-dispatch`) rather than a new script or `task.py new + add-tag`. Rationale: it files + applies tags at creation in one call, honors the shared dispatch cap, and is the same mechanism the existing #699 big-fix path + workflow-fix-on-bug step 5 use. Constraint §scope allows a `--tag` plumbing patch to it, but NONE is needed (`--tag` is already repeatable and forwarded).
