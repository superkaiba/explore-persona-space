## 4. Design (Method delta + file paths + concrete diffs)

### Chosen design per gap (with justification)

- **Gap 1 → option (b)+(a) hybrid, on the exit-75 shape:** keep the ladder in-process (no poller rewrite) but bound the per-process park with a budget and persist the ladder position durably in the LEASE, so the wait is RESUMABLE by re-running the same command — the RunPod exit-75 contract extended from "state-free re-run" to "lease-state re-run". Rejected: full option (a) (moving park + scancel + re-submit + lane fall-through into `backend_poll.py`) duplicates route()'s cancel state machine, workload-failure surfacing, and lane-advance semantics poller-side — far past one review round. Rejected: pure prose (c) — the floor, not the target; it cannot re-arm the ladder. The reconnect path already guarantees no-double-submit (see §2), so the only missing piece is "reconnect resumes the park instead of returning immediately" + durable rung/elapsed state.
- **Gap 2 (ii) → refusal + default extension:** extend the existing current-branch/worktree default to explicit SLURM lanes (same policy as gcp/auto; `materialize_branch_src` resolves local refs, so unpushed branches work), and REFUSE (exit 2) the residual implicit-main case whenever an `issue-<N>` branch exists (local or origin) — a warning is banned here per the fail-fast constraint; `--repo-branch main` is the explicit escape for legitimate main-only workloads (e.g. post-merge relaunches).
- **Gap 2 (iii) → refusal, not derivation:** deriving `--time-budget-hours` from `--max-run-duration` would conflate a GCP auto-delete fence (sized ~1.5-3× ABOVE the wall; #1336 fenced 24 h for an 8 h wall) with the SLURM scheduler wall limit (sized AT the wall; longer `--time` queues strictly worse) — a semantically wrong silent value. Refusal costs one re-run with the right flag and matches fail-fast.
- **Gap 2 (i)+(d) → verify_plan c46, WARN-only:** argparse dry-parse of plan-embedded commands + the max-run-duration/time-budget pairing + missing `--repo-branch` note. WARN-only (c39/c43 precedent): plans carry placeholder-heavy illustrative commands; the runtime refusals above are the hard gate, the plan check is the drift detector. Model-call-vs-code: this is deterministic token parsing against a real parser — code, not a model call, by construction.

**Why code, not a model call:** all four changes are deterministic control-flow/parsing; no unstructured-data judgment anywhere.
