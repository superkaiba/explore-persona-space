## 0.0 TL;DR (plain English)

- **What I'll build:** a fast pre-commit guard hook that refuses a repo-root `git commit` carrying Python code (`scripts/`, `src/`, `tests/`) unless a fresh certification file proves the documented lint+test gate already ran clean on exactly that file content — plus a small helper script that runs the gate and writes the certification, replacing the copy-paste recipe in SKILL.md.

### 4.2 Hook: `.claude/hooks/guard_root_code_commit.sh`

Contract (family parity): reads PreToolUse JSON on stdin; exit 0 allow; exit 2 + stderr block; any other non-zero non-blocking. `--self-test` mode. Sub-second by construction.

**Two-layer predicate.** Layer 1 (command text, cheap) detects a *plausible repo-root `git commit` clause*; Layer 2 (repo state, authoritative) classifies the pending payload and checks certification. A Layer-1 match with no gated pending payload allows — so text-level false matches (e.g. a commit-message line beginning `git commit`) cannot block on their own.

Near-final logic (structure verbatim from `guard_repo_root_pull.sh` where marked *parity*):

```bash
#!/usr/bin/env bash
# PreToolUse(Bash) guard (#1500): refuse a repo-root `git commit` whose pending
# payload includes UNCERTIFIED code paths (scripts/**.py, src/**, tests/**.py).
# Certification = a fresh content-hash-bound line written by
# scripts/inline_lint_gate.py on a PASSING Step 9a-ter gate run.
set -u
REPO=/home/thomasjiralerspong/explore-persona-space
GUARD_REPO="${EPM_ROOT_CODE_COMMIT_REPO:-$REPO}"          # test override (hermetic tmp repos)
CERT="${EPM_INLINE_CERT_PATH:-/tmp/eps-inline-lint-cert-v1.txt}"
MAX_AGE="${EPM_INLINE_CERT_MAX_AGE_S:-21600}"             # 6 h

# session escape hatch, no-fork (parity: guard_repo_root_pull.sh:403-407)
case "${EPM_ALLOW_ROOT_CODE_COMMIT:-}" in 1|true|TRUE|True|yes|YES|Yes) exit 0 ;; esac

[ "${1:-}" = "--self-test" ] && { run_self_test; exit $?; }

cmd=$(jq -r '.tool_input.command // empty' 2>/dev/null) || exit 0   # fail-soft (A16 parity)
[ -n "$cmd" ] || exit 0
case "$cmd" in *EPM_ALLOW_ROOT_CODE_COMMIT=1*) exit 0 ;; esac       # inline escape hatch
case "$cmd" in *git*) ;; *) exit 0 ;; esac                          # cheap prefilters:
case "$cmd" in *commit*) ;; *) exit 0 ;; esac                       # ~all fleet traffic exits here

# ---- Layer 1: clause scan (parity with guard_repo_root_pull.sh 126-244) ----
# line-continuation normalize; |&/fd-dup strip; clause split with @AND@/@OR@/
# @SEQ@/@PIPE@/@BG@ sentinels; cd-latch propagates only across && (#804).
# NO heredoc blanket-allow (deviation from siblings, deliberate: the canonical
# commit shape `git commit -m "$(cat <<'EOF'...)"` embeds a heredoc; Layer 2
# neutralizes the mention-FP risk instead).
COMMIT_CMD_ERE='^([A-Za-z_][A-Za-z0-9_]*=[^[:space:]]*[[:space:]]+|(nohup|setsid|sudo|env|time|timeout|command|exec|eval|if|elif|then|else|while|until|do|!)[[:space:]]+|-[^[:space:]]+[[:space:]]+|[0-9]+([.][0-9]+)?[smhd]?[[:space:]]+)*git[[:space:]]+(-[^[:space:]]+([[:space:]]+[^[:space:]]+)?([[:space:]]+|$))*commit([[:space:]]|$)'
# per clause:
#   - cd-latch arm: verbatim pull-guard block (lines 176-188) — latch only
#     provably-non-root targets; unproven targets stay unlatched.
#   - `git -C <path>` waiver: waive UNLESS the -C target token literally spells
#     the repo root ($REPO absolute path, `~/explore-persona-space`,
#     `$HOME/explore-persona-space`) — one notch stronger than the siblings'
#     path-blind waiver; `git -C .` stays waived (pinned sibling-parity residual).
#   - lead matches COMMIT_CMD_ERE and clause unlatched -> root_commit=1;
#     remember `-a`/`-am`/`--all` presence; collect clause tokens matching
#     ^(scripts|src|tests)/[^[:space:]"'\'']+ as text-named pathspecs.
[ "$root_commit" = 1 ] || exit 0

# ---- Layer 2: repo-state classification (authoritative; FAIL CLOSED) ----
if ! staged=$(git -C "$GUARD_REPO" diff --cached --name-only 2>/dev/null); then
  echo "BLOCKED: guard_root_code_commit.sh could not read the staged set (git diff --cached failed) for a repo-root commit — cannot classify the payload; failing CLOSED (#458/#1147 class). Retry, or override deliberately: EPM_ALLOW_ROOT_CODE_COMMIT=1." >&2
  exit 2
fi
mod=""
[ "$has_dash_a" = 1 ] && mod=$(git -C "$GUARD_REPO" diff --name-only 2>/dev/null || true)
pending=$(printf '%s\n%s\n%s\n' "$staged" "$mod" "$text_paths" \
  | grep -E '^(scripts/.*\.py|src/.+|tests/.*\.py)$' | sort -u)
[ -n "$pending" ] || exit 0            # artifact-only / non-code commit: allow

# cert check per gated path; deletions exempt (see §4.2.1)
now=$(date +%s)
for p in $pending; do
  if git -C "$GUARD_REPO" diff --cached --name-only -- "$p" | grep -qx "$p"; then
    sha=$(git -C "$GUARD_REPO" ls-files -s -- "$p" | awk '{print $2}')   # staged blob = landing content
    [ -n "$sha" ] || continue                                            # staged DELETION: exempt
  else
    [ -f "$GUARD_REPO/$p" ] || continue                                  # -a/pathspec deletion: exempt
    sha=$(git -C "$GUARD_REPO" hash-object -- "$GUARD_REPO/$p")          # worktree content lands
  fi
  ok=0
  while read -r tag epoch csha cpath; do
    [ "$tag" = v1 ] && [ "$cpath" = "$p" ] && [ "$csha" = "$sha" ] \
      && [ $((now - epoch)) -le "$MAX_AGE" ] && { ok=1; break; }
  done < <(grep -F " $p" "$CERT" 2>/dev/null || true)
  [ "$ok" = 1 ] || uncertified="$uncertified $p"
done
[ -z "${uncertified:-}" ] && exit 0
cat >&2 <<BLOCK_MSG
BLOCKED: repo-root commit carries UNCERTIFIED code payload:${uncertified}
Direct-to-main code (scripts/src/tests) must pass the inline payload lint gate
first (SKILL.md Step 9a-ter § Inline payload lint gate, #1388/#1460/#1500):
  printf '%s\n' <paths> > /tmp/issue-<N>-inline-payload.txt
  uv run python scripts/inline_lint_gate.py --issue <N> \
    --payload-file /tmp/issue-<N>-inline-payload.txt     # ONE background Bash (~3-8 min)
On PASS it certifies each path's exact content; re-run after any further edit.
Committing in a WORKTREE instead? Use git -C "\$WT" commit (worktrees are
gated at Step 10d, not here). NEVER hand-write ${CERT} (#1082 parity).
Genuinely pre-existing red on a MODIFIED payload file the gate refused, or an
emergency fleet repair: prefix the commit with EPM_ALLOW_ROOT_CODE_COMMIT=1
and record the reason in an epm:progress note.
BLOCK_MSG
exit 2
```

#### 4.2.1 Decided edge cases

- **Staged deletions / `-a` deletions of gated paths: exempt** (no content to certify; a lint-breaking deletion — the `--check-script-references` class — is a named residual; the worktree pipeline remains the right channel for deletions).
- **`git revert` / `git cherry-pick`: not matched** (verb anchor is `commit`). Named residual — convenient for emergency repair of a landed offender; accidents-not-adversaries disposition.
- **`git commit --amend`:** matched like any commit; classified on the staged set (amend content-rewrites are already policy-banned on pushed commits).
- **Empty commits (`--allow-empty`):** `diff --cached` empty → allow.
- **Shared-index race** (another session stages gated files concurrently): FP direction is *block* with a clear message — rare and safe; documented known limitation (the root index is shared, staging-by-explicit-path windows are small per CLAUDE.md § Concurrent repo-root committers).
- **cwd-blindness** (pull-guard parity): a bare `git commit` issued while the Bash shell's inherited cwd is a worktree matches Layer 1, but Layer 2 reads the ROOT's index — which will lack the worktree's staged files — so it allows unless the root simultaneously has gated files staged. Remediation in the block message: `git -C "$WT" commit`.

### 4.3 Helper: `scripts/inline_lint_gate.py`

CLI: `uv run python scripts/inline_lint_gate.py --issue <N> --payload-file <path>` (alt: `--paths p1 p2 ...`). Run as ONE background Bash (`run_in_background=true`) — the no-flags lint leg is ~2.5-6 min (#991/#996: never a ≤600 s foreground bound).

Phases (each a separately unit-testable function):

1. **`read_payload`** — strip blank lines (the SKILL.md blank-`grep -F`-pattern hazard, handled in code); empty after strip → INCONCLUSIVE (exit 3), matching `INCONCLUSIVE-payload-file-empty`.
2. **`run_legs`** — best-effort self-choom (`sudo -n choom -n -600 -p <pid>`, fail-open; Step 10d precedent #1045/#1211/#1143); bounded `git fetch origin main` (timeout, degrade-to-stale — staleness only affects new-vs-modified classification in the STRICTER direction); leg A: `uv run python scripts/workflow_lint.py` (subprocess, `timeout` 900 s); leg B: `uv run python scripts/select_step9c_tests.py --map-files <payload>` → parse `<test>\t<path>` TSV → `uv run pytest <tests> -q -rA` with timeout `120 + 30×n_files + (900 if test_workflow_lint.py selected)` s (formula parity with `select_step9c_tests.recommended_timeout_s`, #1046). Combined output persisted to `/tmp/issue-<N>-inline-lint.txt` + `/tmp/issue-<N>-inline-map.txt` (audit parity with the current recipe).
3. **`evaluate`** — mechanizes SKILL.md 6545-6590 exactly:
   - Completeness: lint terminal line `workflow_lint: (PASS|FAIL \()` present (the `schema FAIL` early-exit is rejected — SKILL.md 6547-6548); when the map file is non-empty, a pytest summary line present on non-lint lines. Any miss → INCONCLUSIVE, exit 3, **no cert**.
   - Payload attribution: non-WARN output lines naming a payload path.
   - Per-path verdict: path NEW on `origin/main` (`git cat-file -e origin/main:<path>` fails) + any hit → BLOCK that path (all 4 incident offenders were this case). Path MODIFIED: hits carrying a parseable `<path>:<lineno>:` (the `workflow_lint: {target}:{lineno}:` error shape) whose linenos all fall outside the round's added-line ranges (`git diff -U0 origin/main -- <path>`) → pre-existing, path passes, hits REPORTED; any payload-naming hit without a parseable lineno on a modified path (e.g. a pytest test-id) → conservative BLOCK for that path, message pointing at the override + note duty.
   - Repo-wide red naming only non-payload paths / WARN lines → never blocks (reported for the round's `epm:progress` note, per SKILL.md 6586-6589).
4. **`write_cert`** — for each PASSING payload path, append under `flock`: `v1 <epoch> <git hash-object of worktree content> <path>` to `${EPM_INLINE_CERT_PATH:-/tmp/eps-inline-lint-cert-v1.txt}`; trim the file to its last 500 lines. Per-path certs mean a mixed verdict lets the clean subset commit while the offender is fixed.
5. Exit codes: 0 = all payload paths certified; 1 = ≥1 path blocked; 3 = INCONCLUSIVE. Greppable terminal line: `inline_lint_gate: PASS|BLOCK (<paths>)|INCONCLUSIVE (<reason>)`.

Test support: `EPM_INLINE_GATE_LINT_CMD` / `EPM_INLINE_GATE_MAP_CMD` / `EPM_INLINE_GATE_PYTEST_CMD` env overrides substitute the leg commands (hermetic fast tests; documented as test-only, same pattern as `EPM_LESSONS_EDIT_SENTINEL`).

## 5. Controls — blast-radius analysis + rollback

**Who commits/pushes at the repo root, and what this changes:**

| Actor | Channel | Payload | Effect |
|---|---|---|---|
| `task.py` marker/status commits (~100+/hr) | library subprocess (`task_workflow._git_commit`) | `tasks/**` | **Invisible to PreToolUse — zero change** |
| `sync_repo_root.py` recovery push | Python subprocess | pushes existing commits | Invisible — zero change |
| `auto_push_main.sh` (cron + Stop hook) | cron/nohup, not a Bash tool call | pushes existing commits | Invisible — zero change (and the reason push-gating was rejected) |
| Orchestrator/subagent artifact commits (figures, eval JSONs, RESULTS.md, body edits) | Bash tool `git commit` | artifact-only / non-gated | Prefilter or Layer-2-empty → allow, ms-scale |
| Direct workflow-surface .md edits (CLAUDE.md, rules, skills) | Bash tool `git commit` | `.claude/**.md` etc. — NOT in the gated glob | Allow (deliberate scope choice, §11) |
| Inline free-analysis rounds landing `scripts/issue<N>_*.py` | Bash tool `git commit` | gated | **Blocked until certified — the target behavior** |
| Direct root hot-fixes to workflow helper `scripts/*.py` | Bash tool `git commit` | gated | **Behavior change:** now needs the gate run (or the override). Named + accepted: this class is exactly #931's channel, and the sanctioned channel for script changes is the worktree pipeline |
| Worktree implementer commits | `git -C "$WT"` / cd-latched | any | Waived at Layer 1 — no double-gating (constraint 3) |
| Pod-side result pushes | pod clone, different host | eval_results (artifact) | Out of reach; code changes on pods are already banned — named residual |

**Misfire analysis:** a hook FALSE BLOCK affects only Bash-tool root commits of (apparently) gated code — the block message contains the full remediation, so the cost is one extra gate run or an override, never a wedged fleet (markers/artifacts/pushes unaffected). A hook CRASH mid-classification fails closed only on confirmed root-commit clauses (see §fail-modes); stdin-parse crashes fail open.

**Rollback (one line each):** (a) delete the one hook entry from `.claude/settings.json` (hook never fires again); or (b) fleet-wide `export EPM_ALLOW_ROOT_CODE_COMMIT=1` in the affected session(s) as an immediate soft-disable. The SKILL.md prose remains valid under either (it documents the recipe; enforcement is additive).

## 11. Decision Rationale

- **Interception point = `git commit`, not `git push`.** What: gate the commit clause. Why: `scripts/auto_push_main.sh` (crontab `*/2` + Stop hook, read 2026-07-18) pushes local main whenever ahead — a Bash-tool push gate is bypassed ≤2 min after commit; and push-time payload attribution on the shared root is wrong (a push batches other sessions' commits → guaranteed FPs against the zero-FP budget). Source: `scripts/auto_push_main.sh`, crontab entry, CLAUDE.md § Concurrent repo-root committers. Alternatives: push-hook (rejected above); git-native pre-push hook (rejected — fires on cron/sync pushes it cannot attribute, unversioned, fleet-stall blast radius); CI (rejected — post-hoc only under the direct-push-to-main model; branch protection would break the ~100+/hr task.py traffic).
- **Deny-with-certification, not synchronous scan.** What: the hook checks a cert file; the multi-minute gate runs out-of-band. Why: legs measure ~2.5-6 min (lint) + mapped pytest — no PreToolUse hook can run that synchronously (the #991/#996 SIGKILL class for bounded shells; hooks have their own timeouts — the one explicit `timeout` in settings.json is 15 s). Source: SKILL.md 6530-6531, 9440-9448; Step 10d sha-bound verdict-file precedent SKILL.md 9880-9899. Alternatives: synchronous run (rejected on latency); trust-the-session sentinel (shape (b) — rejected: relies on remembering, the exact failure mode).
- **Content-hash (blob-sha) binding, not commit-sha binding.** What: cert lines carry `git hash-object` of the exact content certified. Why: at commit time no commit exists yet (Step 10d binds a branch tip; there is none here); blob binding also survives an intervening unrelated commit and detects any post-gate edit. Source: Step 10d sha-bind design goal ("certified exactly the tip that landed", SKILL.md 10105-10110), adapted. Alternatives: mtime-only freshness (rejected — doesn't detect edits); per-issue verdict file (rejected — the hook can't infer N from a git command).
- **Gated glob = `scripts/**.py` + `src/**` + `tests/**.py`, NOT all non-artifact paths.** What: only code files gate. Why: the Goal names "scripts/src files"; all 6 incident offenders were `scripts/issue*_*.py`; gating `.claude/**.md`/`CLAUDE.md` would put a 5-min gate on the sanctioned commit-immediately workflow-edit flow (CLAUDE.md workflow-fix bullet) — an unacceptable behavior change this task doesn't authorize. Source: task #1500 Goal; #1388/#1428 records; CLAUDE.md § workflow-fix-on-bug. Alternatives: full Step 9a-ter payload set (rejected as above; the md-side lint risk remains on the worktree/PR channels); `scripts/issue*_*.py` only (rejected — under-covers `src/` helpers the 9a-ter prose explicitly names).
- **Two-layer predicate (text trigger + repo-state authority).** What: Layer 1 finds commit clauses; Layer 2 decides on the staged set. Why: commits are high-frequency and message text embeds arbitrary prose (incl. heredocs — blanket-allowing them like siblings would exempt the canonical `-m "$(cat <<'EOF'...)"` shape); anchoring the block on repo state makes text FPs harmless. Source: `guard_repo_root_pull.sh` command-position anchor #1250 (Layer 1); `guard_lessons_edit_check.py` runs-the-real-check precedent #1279 (state-over-text). Alternatives: pure text matching (rejected — either heredoc-exempt and useless, or FP-prone); pure state check on every Bash call (rejected — git subprocesses on every call).
- **Fail modes.** stdin-parse → OPEN (A16 sibling parity: a guard bug must not wedge the fleet); classification git failure on a confirmed root-commit clause → CLOSED (Step 10d failed-trigger-diff arm, SKILL.md 9482-9484; the brief's #458/#1147 class); missing/stale cert → CLOSED (the designed block). Source: guard_repo_root_pull.sh:362-388, guard_lessons_edit.sh:19-23, SKILL.md 9476-9484.
- **Override = `EPM_ALLOW_ROOT_CODE_COMMIT=1`.** Legitimate when (a) the helper conservatively refused a MODIFIED file whose red is genuinely pre-existing (SKILL.md: pre-existing never blocks — the human-judgment case), (b) emergency fleet repair. Always with an `epm:progress` note. Source: family convention (`EPM_ALLOW_ROOT_PULL`, `EPM_ALLOW_BANK_READ`, `EPM_ALLOW_LESSONS_EDIT`).
- **Cert freshness 6 h (`EPM_INLINE_CERT_MAX_AGE_S=21600`).** Gate wall ~3-8 min; an inline round completes within a session horizon; the window bounds lint-version drift. Source: ungrounded — engineering choice, low-risk in both directions (env-tunable); flagged in §12.
- **Helper in Python, hook in bash.** Verdict/attribution logic is line-parsing + git plumbing — testable as imported functions (guard_lessons_edit_check.py precedent); the hook must be a zero-dep instant bash script (family convention).
