## 0.0 TL;DR (plain English)

- **What I'll do:** after every task.py lifecycle commit, run one cheap git check (`git merge-base --is-ancestor <new-commit> refs/heads/main`) and, if the commit didn't land somewhere main can see, print a loud error and record a forensic line in `~/.task-workflow/stranded-commits.jsonl`. Never block or fail the mutation itself.
- **What I expect:** normal mutations pay ~10 ms extra and stay silent; a future guard-escape (the class that caused #1083's 15-problem registry drift) gets caught the moment it happens, with the exact commit, branch, and recovery command in the error, instead of at the next manual audit.
- **What would change my mind:** if the check can ever make a mutation fail that would otherwise succeed, or if it warns spuriously on healthy routed/managed-worktree commits, it's wrong to ship — the kill switch (`EPM_TASKPY_LANDING_CHECK=0`) and warn-only contract exist precisely so neither can hurt the fleet.

## 1. Goal + requirement + acceptance criteria

> "Add a post-transition landing check (after a lifecycle mutation commits, verify the commit is reachable from main / warn loudly if not) or a periodic `task.py audit` alert cron that surfaces stranded lifecycle commits at creation time, not at the next drift repair. Secondary (lower value, same incident): a verifier warning for plans that stage whole task dirs with untracked residue."

(Task #1100 `## Goal` H2, verbatim; re-read via `task.py view 1100 --json` at plan-return time — no `epm:goal-updated` markers; `kind: infra` has no `goal:` frontmatter.)

**Requirement.** When a task.py lifecycle mutation's git commit lands somewhere NOT reachable from `refs/heads/main` — the root event behind #1083's 15-problem registry drift (12/15 problems were commits stranded on never-merged `issue-<N>` branches: the #696 stale-path re-point + 11 not-in-registry rows #698–#702, #704–#709) — the session that made the mutation must find out **at creation time**: a loud stderr error naming the commit, the branch it landed on, and the recovery command, plus a durable forensic record. The guard must be warn-only: it can NEVER make a mutation fail that would otherwise succeed, and must add O(10 ms) to the hot mutation path (~100+ mutations/hr fleet-wide).

**Acceptance criteria (each test-backed, see §5):**

1. A `_git_commit` whose resulting commit is unreachable from `refs/heads/main` emits exactly one `_log.error` line containing the 12-char sha, the literal phrase `NOT reachable from refs/heads/main`, the HEAD ref name, and the sidecar path — AND appends exactly one JSON row `{ts, kind: "stranded", sha, head_ref, routed, message, probe_rc, probe_stderr_tail}` to `~/.task-workflow/stranded-commits.jsonl`. The mutation itself still succeeds (commit exists, function returns normally). → `test_landing_check_warns_on_stranded_commit`
2. A commit reachable from `refs/heads/main` (the normal case, including sha == main tip and sha an ancestor of a subsequently-moved main) produces no error and no sidecar row. → `test_landing_check_silent_when_commit_reaches_main` (sha == main tip) + `test_landing_check_silent_on_ancestor_of_moved_main` (HEAD=A, `refs/heads/main`=B, A a strict ancestor of B — the discriminator that FAILS a tip-equality implementation, pinning the §11-chosen `merge-base --is-ancestor` predicate)
3. Fail-open is total: any internal failure of the check (git subprocess error, sidecar write `OSError`, unexpected exception) degrades to a `_log.warning` and `_git_commit` returns normally. → `test_landing_check_never_fails_the_mutation`
4. A repo with no `refs/heads/main` ref produces a `kind: "unverifiable"` row + warning, never a crash. → `test_landing_check_unverifiable_when_main_ref_missing`
5. `EPM_TASKPY_LANDING_CHECK=0` disables the check entirely (no probe subprocesses — asserted via a call-counting monkeypatch on the direct helper call — and no rows). → `test_landing_check_disabled_via_env`
6. `TASK_PY_NO_COMMIT=1` (test/no-commit mode) never reaches the check. → `test_landing_check_skipped_under_no_commit`
7. Zero regressions: full `tests/test_task_workflow.py` + `tests/test_task_workflow_worktree.py` (routed mode) green; `uv run ruff check` green on touched files; `uv run python scripts/workflow_lint.py` (no-flags default run) green.
8. Healthy ROUTED (managed-worktree) commits are POSITIVELY certified silent — not by "suite green" alone: one routed-path assertion runs a healthy routed mutation through the existing subprocess harness with the child's sidecar retargeted to tmp (HOME→tmp in the child env), WITHOUT `EPM_TASKPY_LANDING_CHECK=0`, and asserts child stderr lacks `LANDING CHECK`/`NOT reachable` AND the retargeted sidecar is absent/empty. → `test_routed_commit_landing_check_silent` (in `tests/test_task_workflow_worktree.py`)

## 3. Design

### 3.0 Fork resolution: (a) primary

**(a) post-transition landing check** is shipped. It catches the root event (a stranded lifecycle commit) at creation time with exact attribution (sha, branch, message, recovery command), for ~11 ms/mutation and ~70 lines. It would have caught 12 of #1083's 15 problems (the 11 not-in-registry rows #698–#702/#704–#709 + the #696 stale-path re-point both trace to lifecycle commits stranded on `issue-<N>` branches) the moment each strand happened — and per #1083's record, #764/#766's lifecycles were ALSO task.py commits stranded on unmerged side branches (tripwire-catchable), leaving only #750 (a pure bad-merge `body.md` drop, merge 401da1748) structurally outside this check's reach.

### 3.1 Descoped: (b) periodic audit-alert cron

One-line reason: the drift class (a) cannot see (pure bad-merge husk dirs — of #1083's three husk-symptom tasks only #750 is this class; #764/#766 were task.py strands the tripwire catches, which strengthens this descope) already has two working detection paths — `living_docs.py:1345` per-task registry-consistency errors in every session, and the nightly `/daily` transcript sweep, which is empirically how #1083 AND this very task were filed — so a new watcher pass (~150 lines under the full pass convention: kill switch, `--*-only` flag, state singleton, sidecar, dedup, dry-run, tests in an 18.7-k-line file) buys only hours of latency on a twice-ever event class; that is gold-plating for a wf-fix task. **Named follow-up trigger:** if `stranded-commits.jsonl` accumulates rows or a second husk-class drift recurs, file a follow-up `kind: infra` task adding a `registry_audit_pass` to `autonomous_session_watch.py` on the `triage_observer_pass` conventions.

### 3.2 Descoped: secondary verifier item (plans staging whole task dirs with untracked residue)

One-line reason (the Goal itself marks it lower-value): there is no concrete recurring signature to key a `verify_plan.py` warning on — the husk import came from a bad merge, not from a plan instruction — so the heuristic would be high-false-positive against zero demonstrated recurrence; the (a) tripwire plus the existing audit paths cover the consequence class.

(ii) **Helper**, placed directly after `_git_commit` (before `_commit_after_durable_append`):

```python
def _warn_if_commit_stranded(message: str, *, routed: bool) -> None:
    """Post-commit landing check (#1100): warn LOUDLY — never raise — when
    the commit that just landed on HEAD is not reachable from
    refs/heads/main.

    The #844 branch guard routes commits to main and #1030's CAS defends the
    routed leg, but nothing verifies the PRIMARY-path landing spot, and the
    resolver's (pid, cwd) cache means a checkout switched under a long-lived
    process commits onto the wrong branch silently — the strand class behind
    #1083's 15-problem registry drift. This tripwire closes the detection
    gap: stderr ERROR + a forensic row in STRANDED_COMMITS_LOG at creation
    time, instead of the next manual `task.py audit`.

    FAIL-OPEN BY CONTRACT: this guard must never make a lifecycle mutation
    fail that would otherwise succeed. Every internal error (git failure,
    sidecar OSError, anything) degrades to _log.warning. Disable entirely
    with EPM_TASKPY_LANDING_CHECK=0.
    """
    if os.environ.get(_LANDING_CHECK_ENV, "").strip() == "0":
        return
    try:
        head = _run_git(["rev-parse", "HEAD"], check=False)
        if head.returncode != 0:
            _log.warning("landing check: could not resolve HEAD (rc=%s); skipping",
                         head.returncode)
            return
        sha = head.stdout.strip()
        probe = _run_git(["merge-base", "--is-ancestor", sha, "refs/heads/main"],
                         check=False)
        if probe.returncode == 0:
            return  # reachable from main — the invariant holds (hot path, ~7ms)
        kind = "stranded" if probe.returncode == 1 else "unverifiable"
        ref = _run_git(["rev-parse", "--abbrev-ref", "HEAD"], check=False)
        head_ref = ref.stdout.strip() if ref.returncode == 0 else "<unknown>"
        _log.error(
            "task.py LANDING CHECK: commit %s (%r) is NOT reachable from "
            "refs/heads/main (HEAD ref: %s, routed=%s, probe rc=%s). The "
            "mutation is durable in the working tree but its COMMIT is "
            "stranded off main. Recover with a SINGLE-COMMIT "
            "`git cherry-pick %s` onto main (a merge-commit strand needs "
            "manual mainline selection via -m; do NOT `git merge %s` — a "
            "branch-wide merge can union-import the branch's whole "
            "task-ledger state, the #1083 husk class), then verify with "
            "`git merge-base --is-ancestor %s main` and run `task.py audit` "
            "(--repair --apply) if registry drift is reported. Recorded in %s.",
            sha[:12], message, head_ref, routed, probe.returncode,
            sha[:12], head_ref, sha[:12], STRANDED_COMMITS_LOG,
        )
        row = {
            "ts": _utcnow_iso(), "kind": kind, "sha": sha, "head_ref": head_ref,
            "routed": routed, "message": message, "probe_rc": probe.returncode,
            "probe_stderr_tail": (probe.stderr or "")[-300:],
        }
        _append_jsonl_line(STRANDED_COMMITS_LOG, row)
    except Exception:
        _log.warning("landing check failed (fail-open; mutation unaffected)",
                     exc_info=True)
```

(One deliberate wording note: `NOT reachable from refs/heads/main` appears for BOTH kinds — for `unverifiable` the row's `kind` + `probe_rc` disambiguate; keeping one greppable ERROR phrase is worth the slight imprecision. Implementer may split the wording per kind; both are within allowed deviations, §10.)

The helper runs BEFORE the optional auto-push (reachability from LOCAL main is push-independent). `_git_commit`'s docstring gains one paragraph naming the landing check + the knob.

**Exact git commands (final):** `git rev-parse HEAD`; `git merge-base --is-ancestor <sha> refs/heads/main`; `git rev-parse --abbrev-ref HEAD` (failure path only). All via `_run_git` (per-call `repo_root()` cwd resolution + sanitized env + one lock-contention retry — inherits the #825 envelope for free). `refs/heads/main` fully qualified so a tag/remote named `main` cannot shadow the branch.

**Warn/alert surface:** (1) `_log.error` → stderr via Python's last-resort handler (same channel the #1030 deferred-commit ERROR uses today; `scripts/task.py` configures no logging, and `logging.lastResort` emits WARNING+ to stderr — verified assumption §11.A5); the calling session's transcript carries it, which is exactly the surface the nightly `/daily` sweep mines. **Performance bound:** happy path = 2 subprocesses (`rev-parse` ~4 ms + `merge-base --is-ancestor` **7 ms measured** on this repo, commit-graph present) ≈ **11 ms** per mutation; at ~100 mutations/hr fleet-wide this is ~1.1 s/hr aggregate. Miss path adds one `rev-parse --abbrev-ref` + the full-history reachability walk (**727 ms measured** with commit-graph) — fires only per actual stranded event. Bound: happy path ≤ ~20 ms (pinned as kill criterion 2, §7 — deliberately NOT an §1 acceptance criterion; an earlier draft's "AC-4" label collided with §1's AC-4 and no pytest timing assert is planned, flaky under CI load).

## 4. Controls / edge cases

| Case | Behavior | Why correct |
|---|---|---|
| Routed-mode (managed worktree) commit | Post-CAS, `refs/heads/main` == new sha → probe rc=0 instantly. If `_advance_main_ref` raises (CAS lost), the helper is never reached — that path is already fail-loud by design (#1030 comment, lines 4929-4933) | No new noise on the defended path; no double-reporting |
| Deferred commit (`_commit_after_durable_append` catches a commit failure) | Commit raised ⇒ helper unreached (it sits after the commit succeeds). Helper itself never raises, so it can never be mis-swept into the deferral logic or convert a success into a deferral row | The #1030 contract (narrow catch classes, never-defer-routed) is untouched |
| `TASK_PY_NO_COMMIT=1` | Early return at `_git_commit` top (4864) precedes everything | No commit ⇒ nothing to check |
| Nothing-to-commit early return (idempotent re-run; `diff --cached --quiet` rc=0, line 4883) | Helper unreached | The pre-existing commit was checked when it was created |
| Detached-HEAD window | At resolve time #996 waits/refuses. If HEAD detaches AFTER the cached resolve (external actor), the commit lands detached → probe rc=1 → warn | This IS the guard-escape class the tripwire exists for — a true positive |
| Mid-rebase (#996) | `sync_repo_root.py` acquires the task-workflow flock BEFORE its pull-rebase (per the #996 resolver comment, lines 455-458), and every mutation holds that flock — so the canonical rebaser can never race the check. A bare USER-run `git pull --rebase` (no flock) can orphan-and-replay the fresh commit between commit and probe → one warn on the original sha | Accepted residual: warn-only, content survives via replay, rare; row's `probe_rc`/`head_ref` make post-hoc triage trivial. Listed in §6 |
| Concurrent main advance | Our sha an ancestor of a MOVED main → rc=0, silent. A concurrent `git reset --hard` that orphans our commit → rc=1 warn — a true positive (that is precisely the #1083-adjacent clobber class) | `--is-ancestor` tests reachability, not tip-equality |
| Sparse worktrees | Refs + objects live in the shared common dir; `merge-base` is object-level, sparse-checkout-independent | No interaction |
| Pods | Pod-side code never calls task.py (`tests/test_no_pod_side_task_py_shellout.py`) | No pod concern |
| Missing `refs/heads/main` (exotic checkout, fixtures) | Probe rc=128 → `kind: "unverifiable"` warn row, no crash | Fail-open; `repo_root()` validation makes this unreachable in production, tests exercise it anyway |
| `rev-parse HEAD` failure inside helper | check=False + rc guard → `_log.warning`, skip | Fail-open |
| Sidecar write failure (`OSError`) | Caught by the outer `except Exception` → warning; the ERROR log already carried the story (same posture as `_commit_after_durable_append`, lines 4978-4981) | Trace-write failure never resurrects a mutation failure |

## 7. Kill criteria — what would make this wrong to ship

- Any code path where the check makes a previously-succeeding mutation raise, hang (>2 s), or return differently — unfixable within the warn-only shape ⇒ don't ship.
- The happy-path probe measurably exceeds ~100 ms on the production repo (e.g. commit-graph absent and history walk on the HIT path — not the case today: rc=0 short-circuits at 7 ms) ⇒ redesign (cache main tip per process) or don't ship.
- Spurious warns on healthy routed commits in the existing worktree test suite ⇒ the routed interaction is misunderstood; stop and re-derive.
- Evidence that the strand class is already impossible at this chokepoint (i.e. the check provably can never fire in any reachable state) ⇒ the tripwire is dead weight; don't ship. (Current evidence says otherwise: the resolver cache + external-actor races are reachable, and #1083's strands are historical fact.)

## 11. Decision Rationale

**Check 1 (training hyperparameters):** N/A — no model training. **Check 2 (measurement validity):** N/A — no behavioral construct; the "DV" is a deterministic git reachability predicate.

Load-bearing design choices:

1. **Hook point = tail of `_git_commit`.** *What:* one call after commit (+ routed CAS), before auto-push. *Why:* grep-verified single chokepoint — all 17 lifecycle commit sites (incl. the `_commit_after_durable_append` wrapper) route through it; hooking `set_status`/`create_task` individually would leave 15 siblings uncovered. *Source:* `task_workflow.py:4829` + call-site grep (lines 3189–5174). *Alternative rejected:* per-mutation hooks (N sites, drift-prone); a `post-commit` git hook file (outside task.py's control, affects non-task.py commits, not env-gateable per-process).
2. **Git command = `git merge-base --is-ancestor <sha> refs/heads/main`.** *What:* rc=0 reachable / rc=1 not / rc≠{0,1} unverifiable. *Why:* the exact reachability predicate; O(1) on the hot path (sha == main tip short-circuits, 7 ms measured); the repo already uses this same probe as its ancestry idiom (crash-fix relaunch fix-commit ancestry probe, `.claude/rules/crash-fix-rounds.md`). *Source:* git plumbing (library default, per brief this is fine for git); measured on this repo this session. *Alternative rejected:* `git branch --contains` (parses text, slower); comparing `rev-parse main` == HEAD (breaks under legitimate concurrent main advance).
3. **Warn-only, fail-open — never raise.** *What:* one `try/except Exception` around the whole body; internal git failures degrade to warnings. *Why:* the repo's never-break-mutations philosophy: a guard that fails a durable mutation creates the #1030 duplicate-append class it took two incidents to fix. *Source:* `_commit_after_durable_append` precedent (task_workflow.py:4912, #1030) + the task brief's explicit mandate. *Alternative rejected:* raise-on-strand (converts a detection gap into a data-loss/duplication bug).
4. **Sidecar = `~/.task-workflow/stranded-commits.jsonl`.** *What:* new forensic JSONL beside `DEFERRED_COMMITS_LOG`. *Why:* recording a strand must not itself need a commit (the repo may be the broken thing), and `LOCK_DIR` is the established home for exactly-this-shaped forensics. *Source:* `task_workflow.py:730-738` (#1030 convention). *Alternative rejected:* `.claude/cache/*.jsonl` (in-repo — wrong for commit-failure-adjacent records; that stream is the watcher/cron convention, not the library's).
5. **No dedup at the warn layer.** *What:* one ERROR + one row per stranded commit. *Why:* each event is a distinct lost commit; the natural key IS the sha, which never repeats; volume is bounded by the session's own mutation rate on a rare condition. *Source:* `deferred-commits.jsonl` (same one-row-per-event grain); triage-observer's fire-once-per-record precedent (`autonomous_session_watch.py` #967) applies to re-SCANS of fixed records, which don't occur here (each commit checked exactly once). *Alternative:* per-process seen-`head_ref` downgrade — named as the follow-up if spam materializes (§6).
6. **Inline check, not a cron.** *What:* fork option (a) shipped; (b) descoped. *Why + Source:* §3.1 — 12/15 of #1083's problems were creation-time-catchable strand-class (14/15 counting #764/#766's task.py-strand lifecycles; only #750 is structurally outside); the residual class has two live nightly detection paths (`living_docs.py:1345`, `/daily` — which filed #1083 and #1100); watcher-pass convention overhead (~150 lines; cf. `cpu_guard_pass`/`triage_observer_pass` shapes in `autonomous_session_watch.py`) is disproportionate for the marginal latency. *Alternative preserved:* the named follow-up trigger in §3.1.
7. **Env knob = `EPM_TASKPY_LANDING_CHECK` ("0" disables).** *What:* module-level `_LANDING_CHECK_ENV`. *Why:* per-process disable for tests/emergencies without a code revert. *Source:* `EPM_TASKPY_REBASE_WAIT_SECONDS` / `EPM_TASKPY_MERGE_WAIT_SECONDS` naming convention (task_workflow.py:282-283, 4657-4658, #996/#1030). *Alternative rejected:* reusing `TASK_PY_NO_COMMIT` (conflates "don't commit" with "don't verify").
8. **Fully-qualified `refs/heads/main`.** *What:* not bare `main`. *Why:* a tag or remote ref named `main` cannot shadow the branch in the probe. *Source:* git ref-resolution rules (library default); consistent with `_advance_main_ref`'s `update-ref refs/heads/main` (task_workflow.py:663).
