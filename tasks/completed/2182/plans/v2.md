# Plan v2 — `sync_repo_root`: fail loud when a pull's own autostash is left unrestored

**Task:** #2182 (`kind: infra`, `workflow-fix`) · **GPU-hours: 0** · single file + its test module.

*v2 vs v1: mechanical `verify_plan.py` fixes only — added the machine-readable
GPU-hour line in §9 and the fail-loud pin line in §6. No design change.*

## §0.0 TL;DR

`scripts/sync_repo_root.py` already detects unrestored `autostash` entries, writes
a rescue patch for each, attempts a pop, and records/pushes a KEPT outcome
(#1870). What it does NOT do is (a) distinguish an autostash **this run's pull
just created** from the **four-entry pre-existing backlog**, or (b) let either
influence the exit code — `_run_locked` returns `EXIT_OK` unconditionally. This
plan adds the pre/post-pull SHA snapshot that separates the two, makes only the
NEW case fatal (`EXIT_AUTOSTASH_STRANDED = 7`) with a full recovery message,
leaves the backlog a loud WARN, and adds a read-only `--triage-autostash`
surface so the four existing orphans can be reconciled by the user rather than
dropped by automation.

## §1 Goal

Verbatim from the task body: make the `pull --rebase=merges --autostash`
recovery fail LOUD when its autostash is not restored, so a concurrent session's
uncommitted work at the shared repo root can never be silently reverted into an
orphaned stash.

Live state confirming the gap is load-bearing rather than theoretical:

- `git stash list` holds **four** bare `autostash` entries dated **2026-08-05,
  08-03, 07-31, 07-26** — i.e. none from the 2026-08-07 11:02 incident — plus
  two hand-labelled rescues from earlier manual recoveries.
- All four are permanently `reason: "apply-check-dirty"`: the pass correctly
  refuses to pop onto a dirty tree, and the shared root is dirty essentially
  always under ~15 concurrent sessions. **They can never auto-resolve.**
- `.claude/cache/root-sync-kept-stash-events.jsonl` holds **1669 rows** (609 KB);
  the last five, at 2026-08-07T18:04-18:11Z, re-log the same four refs.
  `_kept_sidecar_known_shas` gates only the PUSH, so these stopped alerting long
  ago and now only append noise.

**Consequence that shapes the whole design:** an undiscriminated "any surviving
`autostash` ⇒ non-zero" would make **every** sync run on this VM exit non-zero
forever, wedging the CLAUDE.md-mandated push-recovery path fleet-wide. The
severity split in §3 is therefore not a preference — it is what makes the fix
shippable.

## §3 Design

### §3.1 The NEW-vs-BACKLOG discriminator

At the top of `_pull_pipeline` (before the first `_pull_with_transient_retry`,
line 1597) snapshot `pre_pull_shas = {sha for _, sha in _autostash_entries(repo)}`.
Snapshot ONCE, so an entry stranded by either the first attempt or the
error-driven fallback retry (line 1616) still classifies as NEW.

Key by **SHA, not ref**: refs renumber as entries pop (`stash@{1}` → `stash@{0}`),
which is exactly why the existing loop already tracks a `processed` set of SHAs.

`recover_stranded_autostash` gains `pre_pull_shas: set[str] | None = None`.
`None` (both preflight calls, and any direct call in tests) ⇒ every entry is
BACKLOG, which is the correct reading: nothing observed before this run's pull is
attributable to it. The `_recover_headnameless_husk` rescue (line 869) stores a
bare `autostash` during preflight, so it lands in the snapshot and classifies as
BACKLOG — correct, since it comes from a *previously crashed* pull and the husk
path already reports itself loudly.

### §3.2 Fatal path — a NEW unrestored autostash

Classification is recorded, never acted on mid-loop: the loop keeps its
rescue-patch-FIRST invariant intact for every entry, appending one dict per KEPT
outcome to a new `report["autostash_kept"]` list
(`{ref, sha, reason, patch, new_this_run: bool}`; `_new_report` initialises it
beside `"stash": []` at line 552). `report["stash"]` keeps its existing
human-readable lines untouched, so `_emit_report` (line 565) and the #1870 tests
are unaffected.

After `recover_stranded_autostash` returns at line 1651, `_pull_pipeline` raises
`SyncAbortError(EXIT_AUTOSTASH_STRANDED, msg)` if any recorded outcome has
`new_this_run: True`. Raising there is deliberate and gets three properties for
free from the existing handler at 1810-1831: swept untracked files are restored,
`report["state"]` becomes `"error"`, and `report["exit_code"]` carries 7.

The message must be actionable on its own, per the task body:

- the offending `stash@{n}` ref **and** its sha12 (the ref may renumber; the sha
  will not);
- the file list from `git stash show --name-only <ref>`;
- the rescue-patch path already written for it;
- the literal recovery command `git stash pop <ref>`;
- one line stating that **the pull itself succeeded and the push leg did not
  run**, so the operator knows the tree is synced-but-unpushed rather than
  half-pulled. Without this the non-zero exit reads as a failed sync.

`EXIT_AUTOSTASH_STRANDED = 7` — a new code, not a reuse of `EXIT_UNEXPECTED=6`:
callers and the watcher must be able to distinguish "your work is sitting in a
stash" from "git did something we did not model".

### §3.3 Backlog path — loud WARN, unchanged surfacing

`_surface_kept_stash` head lines gain an explicit class tag so a reader can tell
the two apart at a glance:

- `KEPT (NEW THIS RUN) stash@{0} (<sha12>) — …`
- `KEPT (pre-existing backlog) stash@{2} (<sha12>) — …`

Body item 3 (a startup WARN when bare `autostash` entries exist) is satisfied by
the preflight pass that already runs, plus one added report line naming the
count and pointing at the triage flag:
`autostash backlog: N bare entry(ies) present — manual triage owed (--triage-autostash)`.
No new cron: every session already runs this script on the rejected-push path.

Sidecar rows gain the `new_this_run` field. Row-per-run appending is **left
as-is** — it is #1870's durable record and de-duplicating it is out of scope
here; §3.4 is what makes the backlog resolvable, which is the real fix for the
1669-row growth.

### §3.4 Item 4 — read-only triage surface

New `--triage-autostash` flag: runs under the existing `acquire_single_flight()`
gate (so it cannot race a live sync; an in-flight run reports and exits 0 exactly
as `main` already does at 1844-1849), then for each bare `autostash` entry prints
ref, sha12, committer date, `git stash show --name-only` file list, the rescue
patch path, and whether `git apply --check` is currently clean. Exits 0.

It **pops nothing, drops nothing, and touches no file in the repo.** The only
write is an idempotent (re)write of the entry's rescue patch under
`RESCUE_ROOT`, outside the working tree. `git stash drop` remains banned at
line 375 — this flag deliberately gives the user the diff without giving
automation the verb.

**Deliverable:** run it against the four live orphans and hand Thomas the output
for the drop-vs-restore call. Automation never decides this.

### §3.5 Explicitly NOT doing

- **Not** removing or displacing `--autostash` — the body's non-goal. In
  particular, item 2's "pre-stash with an attributable message" is NOT
  implemented by replacing the pull's autostash with a hand-rolled
  stash/pull/pop: that would change the pull's semantics and its failure modes.
  Attribution instead rides the sidecar row (which already carries repo, ref,
  sha, patch) plus the class tag in §3.3. Annotating a *surviving* entry after
  the fact is possible but deferred — it buys labelling only, while §3.2 buys
  the actual loss-prevention.
- **No** repo-root `reset --hard` / `restore` / `checkout .` path (body non-goal;
  also lint-enforced).
- **No** automated dropping of any stash entry, ever.

## §5 Tests added (in `tests/test_sync_repo_root.py`, beside the #1870 block at `:488-658`)

The existing `origin_and_clone` fixture drives a real origin + clone, `_run`
returns `(exit_code, report, stdout)`, and `_strand_autostash(local, other)`
already reproduces the incident shape. Note the harness fact recorded at
`:490-493`: a run over a pre-existing stranded entry surfaces the same sha
TWICE (preflight + post-pull), so assertions key on the outcome list, never a
hardcoded row count.

1. **New autostash stranded by sync's OWN pull ⇒ exit 7.** Drive local dirty
   changes that conflict with an incoming origin commit so the script's own pull
   trips `AUTOSTASH_CONFLICT_NEEDLE` (the `_build_conflict_divergence` setup
   already builds this divergence). Assert: exit code 7, `report["state"] ==
   "error"`, an outcome with `new_this_run is True`, and the message contains the
   ref, the sha12, `git stash pop`, the file list, and the pull-succeeded /
   push-skipped sentence.
2. **Pre-existing backlog entry only ⇒ exit 0 + WARN.** Strand via
   `_strand_autostash`, then run. Assert: exit 0, `state == "synced"`, every
   outcome `new_this_run is False`, a `pre-existing backlog` report line present,
   and the entry still in `git stash list` (kept, never dropped).
3. **Both present ⇒ exit 7, and the message names the NEW one specifically** —
   the backlog entries must not be what triggers the failure or what the
   recovery command points at.
4. **Sidecar rows carry `new_this_run`** for both classes.
5. **`--triage-autostash` mutates nothing** — mirrors the existing
   `test_dry_run_mutates_nothing` shape (`_worktree_digest` before/after +
   `git stash list` identical), exits 0, and its stdout names every bare entry.
6. **Backlog-count WARN line appears at preflight** when ≥1 bare entry exists,
   and is absent when none do.
7. **Regression guard:** with no autostash anywhere, exit stays 0 and
   `report["autostash_kept"] == []` — the new fatal path cannot fire on the
   overwhelmingly common clean sync.

Full `uv run pytest tests/test_sync_repo_root.py` plus the whole suite before the
Step 9c verdict. `uv run python scripts/workflow_lint.py` (no flags) must stay
green — the file is a workflow-surface script.

## §6 Success criteria

1. A NEW unrestored autostash produces a non-zero exit (7) and a message
   sufficient to recover the work without reading the source.
2. The four-entry backlog produces exit 0 with a WARN — no fleet-wide wedge.
3. `git stash list` is never shortened by this script under any path.
4. All 7 new tests pass; the pre-existing 2255-line module stays green.
5. `--triage-autostash` output for the four live orphans is delivered to Thomas.

The non-zero-exit claim in criterion 1 is pinned by a committed test, not by a
review-time grep: §5 test 1 asserts the raise reaches the caller as exit 7 and
that the KEPT outcome is not silently swallowed, and §5 test 7 is its negative
control (no autostash ⇒ no raise).

Fail-loud pin: tests/test_sync_repo_root.py

## §7 Kill criteria

- If the NEW-vs-BACKLOG discriminator cannot be made reliable (e.g. two entries
  legitimately share a SHA), STOP and re-plan rather than shipping a fatal path
  that can misfire on the backlog — a false fatal wedges 15 sessions.
- If making the raise happen inside `_pull_pipeline` is found to skip the
  rescue-patch write for any entry, revert to recording-only + a raise in
  `_run_locked`; the rescue-patch-FIRST invariant outranks the exit code.

## §8 Dry-run / smoke

1. `uv run python scripts/sync_repo_root.py --dry-run --json` at the live repo
   root — must still report the four backlog entries and exit 0 (the dry-run
   branch at 1778-1786 returns before the pull, so this exercises the preflight
   WARN only).
2. `uv run python scripts/sync_repo_root.py --triage-autostash` at the live repo
   root, then re-check `git stash list` is byte-identical.
3. The pytest cases in §5 are the real gate for the fatal path — it cannot be
   smoke-tested live without deliberately stranding a real autostash on the
   shared root, which is exactly the harm this task exists to prevent.

**Smoke blind-spot enumeration:**

- The live smoke (steps 1-2) does NOT certify the §3.2 fatal path — no live smoke
  reaches it by construction; test 1 in §5 is its only coverage.
- The live smoke does NOT certify the pop-success branch (the shared root is
  perpetually `apply-check-dirty`); test 2's fixture covers the KEPT branch and
  the existing `test_stranded_autostash_clean_entry_popped` covers the pop.
- No implementation is substituted and no gate is downgraded under any smoke
  flag: this change adds no `smoke`-conditional branch, and there is no
  third-party import reached only on a production path.

## §10 Risks

| Risk | Mitigation |
|---|---|
| **Fatal path misfires on the backlog ⇒ every session's push recovery fails.** The dominant risk. | SHA-keyed snapshot; `pre_pull_shas=None` defaults to BACKLOG; §5 tests 2, 3, 7 pin it from three directions. |
| Exit 7 is read as "sync broke" and someone force-syncs on top of it | The message states explicitly that the pull succeeded and the push was skipped, and names the pop command as the next step. |
| Raising before the push leg leaves the root synced-but-unpushed | Intended: work sitting in an unrestored stash must be triaged before more history moves. Stated in the message. |
| Two entries sharing a SHA collapse the discriminator | §7 kill criterion; practically requires identical tree, parents, message, and committer timestamp. |
| A new report key breaks a downstream reader | `report["stash"]` and every existing key keep their exact shape; the new key is additive. |
