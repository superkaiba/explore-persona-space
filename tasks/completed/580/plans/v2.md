**Design — exact edits.**

*Edit 1a — rsync, extend Step 2 (lines 145–155).* Replace the Step 2 block with:

```bash
step 2 "Installing uv package manager + rsync"
ssh_cmd 'set -eu
export PATH="$HOME/.local/bin:$PATH"
if command -v uv &>/dev/null; then
    echo "uv already installed: $(uv --version)"
else
    echo "Installing uv..."
    curl -LsSf https://astral.sh/uv/install.sh | sh 2>&1 | tail -3
    export PATH="$HOME/.local/bin:$PATH"
    echo "Installed: $(uv --version)"
fi
# rsync: needed pod-side for artifact pulls (rsync requires the binary on
# BOTH ends; the RunPod pytorch image ships without it). Idempotent + quiet.
if command -v rsync &>/dev/null; then
    echo "rsync already installed: $(rsync --version | head -1)"
else
    echo "Installing rsync..."
    export DEBIAN_FRONTEND=noninteractive
    apt-get update -qq
    apt-get install -y -qq rsync
    command -v rsync >/dev/null || { echo "rsync install FAILED (apt-get exited 0 but binary absent)" >&2; exit 1; }
    echo "Installed: $(rsync --version | head -1)"
fi'
log_ok "uv + rsync ready"
```

**Fail-fast (REVISED per Methodology Must-Fix, Claude+Codex round 1):** `ssh_cmd` is a bare `ssh ... "$1"` (lines 65–67) — the remote string runs WITHOUT `set -e`, so in the v1 block a failed `apt-get` would have been masked by the trailing `echo` (remote exit = last command's), printing a false `log_ok "uv + rsync ready"`. v2 fixes this two ways, matching Step 4's own `set -eu` convention (line 200): (a) the remote string opens with `set -eu`, so the un-chained `apt-get update -qq` / `apt-get install -y -qq rsync` lines abort on failure; (b) a belt-and-braces `command -v rsync >/dev/null || exit 1` assert runs before the success echo (covers an apt-get that exits 0 without delivering the binary). `pipefail` deliberately NOT used — Step 4's convention omits it, and the uv branch's `curl | sh | tail -3` pipe semantics stay byte-identical to current behavior. `apt-get update` runs only when rsync is missing (one-time cost per pod, ~10–30 s).

*Edit 1b — quiet git, Step 4.* Four single-flag line edits:

| Line (current) | Current | New |
|---|---|---|
| ~207 | `git pull --ff-only origin "$BRANCH" 2>/dev/null` | `git pull -q --ff-only origin "$BRANCH" 2>/dev/null` |
| ~209 | `git pull --rebase origin "$BRANCH"` | `git pull -q --rebase origin "$BRANCH"` |
| ~243 | `git fetch --depth=1 origin "$BRANCH"` | `git fetch -q --depth=1 origin "$BRANCH"` |
| ~251 | `git reset --hard FETCH_HEAD` | `git reset -q --hard FETCH_HEAD` |

`-q` suppresses progress/summary output only (the 19,972-file `Updating files:` dump comes from the reset/checkout progress meter; fetch object-count progress from line 243); errors still print to stderr and exit non-zero, so the existing fail-loud rebase-conflict path (lines 210–213) and the `echo "Cloned at: $(git log --oneline -1)"` success evidence are untouched.
