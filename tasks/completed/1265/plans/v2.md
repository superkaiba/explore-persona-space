## 4. Design

### 4.1 Placement: directly in `tests/conftest.py` (option a)

Chosen over (b) a `tests/watcher_guards.py` plugin — the Phase 1.5 fact-checker empirically
confirmed `pytest_plugins` in `tests/conftest.py` DOES load without error under this repo's
pytest 9.0.2 in every invocation shape, so (b) is not illegal, merely extra import/registration
machinery for zero benefit over defining the fixtures directly in conftest.py — and over (c) a
`tests/watcher/` subdirectory conftest — moving ~20K lines of test files churns git history and
every `tests/test_*.py` path reference. conftest.py is guaranteed loaded for all of `tests/`,
needs no import machinery, and grows by only ~90 lines.

### 4.2 Scoping predicate: "the test module imports `autonomous_session_watch`"

```python
def _watcher_asw_or_none(request):
    """Return the live autonomous_session_watch module iff the requesting test's
    MODULE imports it (the module object itself, or any module-level attribute
    whose __module__ is 'autonomous_session_watch')."""
    asw = sys.modules.get("autonomous_session_watch")
    if asw is None:          # watcher module never imported this session: cheap no-op
        return None
    try:
        mod = request.module
    except AttributeError:   # non-Python test items
        return None
    for value in vars(mod).values():
        if value is asw or getattr(value, "__module__", None) == "autonomous_session_watch":
            return asw
    return None
```

This matches the hazard surface exactly: only a module that imports the watcher can call its
seams. It covers both import styles in use (`import autonomous_session_watch as asw` — 8 files;
`from autonomous_session_watch import <functions>` — the 2 big files, caught via `__module__` on
the imported functions). A hardcoded 3-filename set was rejected (doesn't cover future files —
the point of the fix); a bare `sys.modules` check was rejected (once any watcher test imports
asw, every later test in the session would be covered — needless blast radius). Verified current
coverage set = exactly the 10 module-level importers listed in §3 (grep
`^(import autonomous_session_watch|from autonomous_session_watch import)` in `tests/`).

### 4.3 The two shared fixtures (near-final code)

Same names as the per-file copies (grep continuity; a leftover/future same-name module fixture
cleanly SHADOWS rather than double-wraps). Bodies are the #1247 bodies verbatim with (i) the
predicate early-exit prepended, (ii) "(shared, tests/conftest.py)" added to the raise messages,
(iii) the union of the per-file docstrings. `import sys` joins conftest's imports.

```python
@pytest.fixture(autouse=True)
def _forbid_real_marker_posts(request, monkeypatch):
    """#1247 hermeticity guard (fail-loud), shared across watcher test modules
    (task #1265). Contract: a later test-level/fixture-level monkeypatch wins;
    dry_run=True keeps the real log-only behavior; a real-BODY exercise against
    a STUBBED subprocess.run (argv-recording tests) is allowed through; only
    dry_run=False with the GENUINE subprocess.run still live fails loud."""
    asw = _watcher_asw_or_none(request)
    if asw is None:
        return
    import functools
    import subprocess as _sp

    real_post = asw._post_progress_marker
    real_run = _sp.run

    # functools.wraps sets __wrapped__, so inspect.getsource() on the patched
    # attribute still resolves the ORIGINAL body (#966 source-inspection pins).
    @functools.wraps(real_post)
    def _guarded(issue, note, dry_run, *, label):
        if not dry_run and _sp.run is real_run:
            raise AssertionError(
                f"_post_progress_marker(issue={issue}, label={label!r}, dry_run=False) "
                "reached the #1247 autouse hermeticity guard (shared, tests/conftest.py) "
                "with the REAL subprocess.run still live — the real body would shell "
                "`task.py post-marker` and post a junk marker on a real task. Monkeypatch "
                "a recorder (or stub subprocess.run) in the test."
            )
        return real_post(issue, note, dry_run, label=label)

    monkeypatch.setattr(asw, "_post_progress_marker", _guarded)


@pytest.fixture(autouse=True)
def _forbid_real_task_status_reads(request, monkeypatch):
    """#1247 round-2 hermeticity guard (fail-loud), shared (task #1265):
    _task_status shells `task.py view` against the LIVE task tree — a
    determinism/latency pin, not a mutation fence. A test that needs a status
    overrides with its own stub (a later monkeypatch wins), e.g.
    monkeypatch.setattr(asw, "_task_status", lambda issue: "running")."""
    asw = _watcher_asw_or_none(request)
    if asw is None:
        return
    import functools

    @functools.wraps(asw._task_status)
    def _guarded(issue):
        raise AssertionError(
            f"_task_status({issue}) reached the #1247 autouse hermeticity guard "
            "(shared, tests/conftest.py) — monkeypatch a status in the test, e.g. "
            "monkeypatch.setattr(asw, '_task_status', lambda issue: 'running')."
        )

    monkeypatch.setattr(asw, "_task_status", _guarded)
```

- **Carve-outs still open:** `test_marker_child_stderr_forwarding.py::test_watch_post_progress_
  marker_integration_forwards` (L106-127) exercises the REAL `_post_progress_marker` body with
  `dry_run=False` against a stubbed `subprocess.run` — this newly-covered file passing IS the
  live verification that the stubbed-subprocess allowance survived the move.
- **Override layering still works:** the 7 newly-covered files stub `_task_status` /
  `_post_progress_marker` per-test throughout (grep-verified for wedge + gate_push); their tests
  passing verifies test-level-override-wins under the conftest guard. The meta-test adds an
  explicit override assertion.
- **Double-fire during migration:** same fixture NAMES ⇒ a surviving per-file copy SHADOWS the
  conftest guard (pytest name-based override) — no double-wrap, identical behavior. A
  hypothetically renamed leftover copy would double-wrap benignly: both wrappers capture the same
  real `subprocess.run`, the outer raises the same `AssertionError` first, and the
  `__wrapped__` chain still unwinds to the original for `inspect.getsource`.
- **#966 source-inspection pins:** meta-test asserts
  `inspect.unwrap(asw._task_status).__module__ == "autonomous_session_watch"` and that
  `inspect.getsource(asw._post_progress_marker)` contains the real body, not the guard.

## 10. Decision Rationale

- **Guard placement — `tests/conftest.py` directly.** Why: guaranteed load for all of `tests/`,
  no plugin-registration machinery, minimal churn. Source: repo layout + Phase 1.5 empirical
  probes (fixture ordering / shadowing verified under pytest 9.0.2; note the fact-checker
  falsified the earlier "pytest_plugins illegal outside rootdir conftest" claim — a plugin
  module WOULD load, it just adds machinery for zero benefit). Alternatives:
  `tests/watcher_guards.py` plugin (rejected: extra import/registration machinery, no benefit);
  `tests/watcher/` subdir conftest (rejected: 20K-line file moves).
- **Scoping predicate — imports-based (`_watcher_asw_or_none`).** Why: matches the hazard
  surface (only asw-importing modules can call the seams), zero ceremony for future files,
  false-positives benign. Source: grep of the 10 current importers + both import styles.
  Alternatives: hardcoded filename set (rejected: defeats the Goal); bare `sys.modules` check
  (rejected: session-order-dependent suite-wide blast radius); module-name pattern (rejected: no
  naming convention — `test_cpu_guard_pass.py` etc.).
- **Fixture names — keep `_forbid_real_marker_posts` / `_forbid_real_task_status_reads`.** Why:
  same-name shadowing gives clean override semantics for any leftover/deliberate per-file copy;
  grep continuity with #1247 lineage. Alternative: `_shared_*` rename (rejected: loses shadowing
  + continuity).
- **Meta-test — yes, one small permanent file.** Why: it IS simultaneously the future-file
  demonstration, the fail-loud negative probe, and the durability pin; ~40 lines. Alternative:
  no meta-test (rejected: relocation makes the invariant conftest-prose a silent-delete hazard —
  the exact failure class this task fixes).
