# Plan v1 — task #1859: repo-root guard — accept the literal timeout wrapper on the ssh waiver arm (mirror #1463)

## Goal / requirement

A `timeout <N> ssh <host> '<remote payload>'` clause is the sanctioned bounded-invocation shape for remote pod-side operations. The repo-root guard (`scripts/guard_repo_root_branch.sh`) waives clause-initial `ssh` remote payloads (#1098/#1413) and — since #1463 — waives `gcloud compute ssh` heads with an optional literal `timeout <num>[.frac][smhd]?` wrapper, but the bare `ssh` head does NOT admit the same wrapper. Two false blocks landed on the #1769 failover critical path. The guard's own residual doc (xix) at L524-529 pre-registers this exact change as a "known future-demand candidate if a timeout-wrapped-ssh false-block filer shows up" — #1859 is that filer.

**Acceptance criteria:**
1. `timeout 240 ssh pod-779 '<single-statement remote git op>'` is waived (exit 0) under the same conditions bare `ssh pod-779 '...'` is waived today (no shared-repo path spelling, no PIPE/BG consumer, no ProxyCommand/LocalCommand/KnownHostsCommand token, no `$(`/`${`/backtick/redirect in the clause).
2. `timeout 240 ssh pod-779 '<single-quoted multi-statement remote string>'` reaches the mask pre-pass whole (candidate head accepted) and is waived when the R1-R8 predicate passes — parity with the #1463 gcloud arm.
3. Every OTHER wrapper stays blocked on both arms: `timeout` FLAG forms (`--signal=`, `-k`), `nohup ssh`, env-prefix, absolute-path `/usr/bin/ssh`, variable `$SSHCMD` heads. The PIPE/BG consumer refusal, the shared-repo-path never-waive, and the R1-R8 mask refusals are all UNCHANGED.
4. Head-regex PARITY across the three sites is preserved (the mask candidate head, waiver cond (1) outer head, inner ssh/gcloud discriminator) — the guard documents this as an invariant (drift is fail-closed, never a leak).
5. All existing guard tests pass except the two fixtures that pin the old asymmetry, which flip to positive fixtures; new negative fixtures pin the boundaries.

## Method delta

Same composition as #1463 (commit c55596834c), applied to the `ssh` alternation instead of adding a new head: the optional literal-timeout group moves from qualifying only the `gcloud compute ssh` alternative to qualifying a unified `(gcloud compute )?ssh` head. Smallest-diff unification rather than a third alternation branch, so the parity invariant stays one regex per site.

### `scripts/guard_repo_root_branch.sh` — 3 functional sites

**Site A — mask candidate head (awk in `mask_ssh_payload_separators()`, ~L966-968).** Replace the two-branch head:

```awk
if (substr(s, i, 4) ~ /^ssh[ \t]/) headlen = 4
else if (match(substr(s, i), /^(timeout[ \t]+[0-9]+(\.[0-9]+)?[smhd]?[ \t]+)?gcloud[ \t]+compute[ \t]+ssh[ \t]/)) headlen = RLENGTH
```

with one unified match:

```awk
if (match(substr(s, i), /^(timeout[ \t]+[0-9]+(\.[0-9]+)?[smhd]?[ \t]+)?(gcloud[ \t]+compute[ \t]+)?ssh[ \t]/)) headlen = RLENGTH
```

```
'^((timeout[[:space:]]+[0-9]+([.][0-9]+)?[smhd]?[[:space:]]+)?(gcloud[[:space:]]+compute[[:space:]]+)?ssh)[[:space:]]'
```
