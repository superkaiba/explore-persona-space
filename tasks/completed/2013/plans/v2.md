## 1. Requirement

Every BLOCK path of the repo-root code-commit guard hook must state, in the
message it prints to stderr, that **the commit did not happen** and that the
session must not narrate it as committed / pushed / landed.

Driving incident (task body, `/daily` problem-sweep C15): a repo-root commit was
blocked at 22:00:53Z; 16 s later the session told the user "Figure built,
verified, committed, pushed" and handed over a raw-content URL carrying a
literal placeholder SHA. The user replied that the link did not work. The
guard's messages print *remedies* only — they never say the commit did not land,
so a skimming reader takes the remedy list as advice and the commit as done.

Acceptance criteria:

- **A1.** Each of the 6 block sites emits the warning.
- **A2.** Wording is identical at every site (one shared definition, no drift).
- **A3.** No existing block-message text is altered or reordered.
- **A4.** The 3 non-block stderr sites are untouched.
- **A5.** The hook's exit codes are unchanged at every site (all still `exit 2`).
- **A6.** Existing tests pass unmodified; new tests pin A1 mechanically.

## 3. Design decision — one shared variable, all six sites

The task body leaves the fork open (shared variable at every site vs.
heredoc-only). **Decision: shared variable, all six sites.**

Rationale: the incident class is a session narrating a blocked commit as landed,
and *every* one of the six exits creates that same false-landed opportunity —
three of them (sites 3–5) are fail-closed I/O-error paths whose messages are the
terse ones most likely to be skimmed. A single variable also makes A2 structural
rather than a review duty.

Not chosen, with reason: heredoc-only would leave the five terse
single-line messages — the ones with the least surrounding context — as exactly
the paths where the warning is most needed.

**Scope decision — the placeholder-SHA failure stays out of the message.** The
incident's second failure (a URL built from a literal `<sha>`) is a different
rule with a different enforcement point; a commit guard has no visibility into
URLs, and loading the message with it costs the skimmability the fix depends on.
What the message *does* carry is the cheap on-target substitute: the read-back
step whose absence let the placeholder ship.

## 4. Change

### 4.1 Definition (new, immediately after the Layer-1 gate at line 1318)

Placed there because that gate is the point past which the hook will certainly
either exit 0 or block — the natural home for a shared block preamble, and
adjacent to first use rather than 1200 lines away.

```sh
# Shared block preamble (#2013): every BLOCK path below states that the commit
# did NOT happen. Remedy-only messages were read as advice while the commit was
# narrated as landed 16 s later (task #2013 driving incident).
NOT_LANDED_LINE="NOT LANDED: the commit did NOT happen. Until a retry succeeds, do NOT state (to the user, in a task marker, in a summary, or in a commit report) that anything was committed, pushed, or landed, and do NOT publish a link whose commit SHA you have not read back from the repo. Confirm a retry with a read-only git log -1 on the intended paths before claiming success."
```

Wording constraint honored: the line **must not contain the override env-var
token** — `tests/test_guard_root_code_commit.py:981`
(`test_c9_block_message_orders_pathspec_recovery_before_escape_hatch`) asserts a
recovery anchor precedes that token's **first** stderr occurrence, and a warning
carrying it before the anchor would invert the assertion. It contains neither the
token nor the anchor.

### 4.2 Sites 1–5 — one added line per site

Insert, at that site's indentation, **immediately before that site's `exit 2`**:

```sh
  echo "$NOT_LANDED_LINE" >&2
```

The rule is anchored to `exit 2`, not to "after the existing `echo`", because
site 2 emits **twice** (its block message at 1352 and a diagnostic at 1353) —
"after the echo" would be ambiguous there. Anchoring to `exit 2` gives one
convention that is unambiguous at all five sites, puts the warning last where the
reader's eye ends, and yields the identical result at sites 1/3/4/5. Existing
text stays byte-identical (A3).

### 4.3 Site 6 — one interpolated line in the heredoc

Insert `${NOT_LANDED_LINE}` on its own line immediately after the
`BLOCKED: repo-root commit carries UNCERTIFIED code payload:${uncertified}`
line (currently 1556), i.e. before the `${diag_lines}${foreign_para}…` line.
Leading placement, because the remedy body is ~20 lines and a trailing warning
is exactly what gets skimmed past.

Ordering safety: the inserted line sits before both `FOREIGN-STAGED?` and the
override token and contains neither, so the c9 ordering assertion is preserved.

### 4.4 Not touched

The hook's header comment block, the three non-block stderr sites, and every
existing message string. No other file changes behavior.

## 5. Tests (`tests/test_guard_root_code_commit.py`, 1381 lines / 169 cases)

### TDD: no

Tests land in the same round as the change, not behind a proposed-tests gate.

Two complementary additions:

**5.1 Source invariant (covers all six sites incl. the three not reachable
without fault injection).** Count-equality, so it is order-free and
window-free, and a *future* seventh standalone-line block site cannot ship
without the warning:

```python
def test_every_block_site_emits_the_not_landed_warning() -> None:
    """#2013: every `exit 2` block site emits the shared NOT-LANDED warning.

    Count-equality rather than a proximity window, so the assertion survives
    the heredoc growing and catches a future block site added without it.

    KNOWN BLIND SPOT (disclosed deliberately): the site count matches only
    STANDALONE `exit 2` lines. A future block written in a compound form
    (`... || exit 2`) would not be counted, so it could ship without the
    warning while this test stays green. The six sites that exist today are
    all standalone; a compound block site added later needs this test
    extended, not merely re-run.
    """
    src = HOOK.read_text().splitlines()
    n_sites = sum(1 for ln in src if ln.strip() == "exit 2")
    n_emits = sum(
        ln.count('"$NOT_LANDED_LINE"') + ln.count("${NOT_LANDED_LINE}") for ln in src
    )
    assert n_sites >= 6, n_sites
    assert n_emits == n_sites, (n_emits, n_sites)
```

The `.strip()` equality excludes the four comment occurrences named in §2, and
the assignment line carries no `$`-prefixed form, so it is not counted. The
`n_sites >= 6` floor prevents vacuous satisfaction (both counts collapsing to 0).

**5.2 Runtime assertions — proves the emissions actually reach stderr**, one per
site *family* (heredoc + both reachable single-line classes), reusing the
invocation shapes of existing cases:

| Family | Invocation (existing case it mirrors) |
|---|---|
| heredoc (site 6) | `_run("git commit -m x", code_repo, cert)` — `test_block_message_names_gate_remediation_and_override` |
| blanket-add chained (site 1) | `_run("git add -A && git commit -m x", code_repo, cert)` — the `dash-A` parametrize id |
| cwd not provable (site 2) | `_run("git add --all -- tasks/t.md && git commit -m x", art_repo, cert, cwd=_OMIT_CWD)` — `test_add_pathlimited_missing_cwd_blocks` |

Each asserts blocked (rc 2) **and** both `"NOT LANDED"` and
`"committed, pushed, or landed"` in stderr.

Sites 3–5 are source-invariant-only (they are fail-closed I/O-error paths not
reachable without fault injection). Acceptable because the delivery mechanism —
an `echo` of the same shared variable to stderr immediately before `exit 2` — is
runtime-proven at sites 1–2.
