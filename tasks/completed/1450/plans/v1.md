# Plan — #1450: size-cap trigger for the home-HF-hub-cache reap (tier (e), `scripts/vm_disk_guard.py`)

## 0.0 TL;DR (plain English — the user reads this first)

- **What I'll do:** add a third reap arm to the disk guard's home HF-cache tier — when the whole `~/.cache/huggingface/hub` cache grows past a byte cap (default 50 GB), it deletes the oldest unreferenced non-newest revisions first until it's back under the cap, even if they were downloaded the same day. ## Method delta (vs #1376/#1377)

The existing arms are **age-triggered and age-gated**: arm 1 reaps whole repos whose repo-level `last_accessed` > 7 d; arm 2 reaps unref'd non-newest revisions whose `last_modified` > 7 d AND whose exclusive blobs have no fresh (≤ 7 d) atime. Both are structurally blind to same-day churn (nothing is ever old enough while the disk fills).

The new **arm 3 is size-triggered and age-relaxed**: trigger = total hub bytes > cap (a byte budget, not an age); eligibility keeps only the STRUCTURAL protections (non-newest, zero refs, multi-revision repos) and replaces the 7 d gates with a 1 h in-flight floor; ordering = oldest-first (`last_modified` asc), stopping at the cap. Arm 3 never introduces a new trigger path into `run_guard` — it lives entirely inside the tier, which already runs only under disk pressure (over-threshold or the watcher's `--ignore-threshold` sub-floor run).

### 4.2 New pure selector `_home_hf_size_cap_selection` (beside `_home_hf_reap_selection`, ~L1186)

```python
def _home_hf_size_cap_selection(
    info, now: float, cap_bytes: int, floor_seconds: float,
    already_selected: frozenset[str], already_freed_approx: int,
) -> tuple[list, dict]:
    """Arm 3 (#1450): pure oldest-first size-cap selector.
    Returns ``(extra_pairs, stats)`` — ``extra_pairs`` is ``[(repo, [revs])]``,
    ``stats`` = {"total_bytes", "overage_bytes", "n_eligible", "selected_bytes"}.
    Eligibility = arm-2's STRUCTURAL keeps only: non-newest (same
    ``(last_modified, commit_hash)`` tie-break as L1156 — the newest is ALWAYS
    kept), NO refs (any ref protects), single-revision repos never touched,
    not already selected by arms 1/2 — with the 7 d gates REPLACED by the
    in-flight floor (``last_modified`` within floor -> keep; fresh EXCLUSIVE-
    blob atime within floor -> keep, same kept_blobs construction as L1157
    with ``floor_seconds`` in place of ``age_seconds``). Pool sorted
    oldest-first by ``(last_modified, commit_hash)`` (deterministic);
    accumulate ``rev.size_on_disk`` until >= overage. Per-repo try/except:
    a degenerate repo contributes NOTHING to the total and is never selected
    (fail toward KEEP, same posture as the age selector).
    Byte arithmetic bias: ``rev.size_on_disk`` counts shared blobs per
    revision (OVERestimates freed) while the degenerate-repo skip
    UNDERcounts the total — both push toward under-reaping; convergence to
    the cap happens across repeated triggered runs (watcher sub-floor
    repeats every 30 min), never by over-deleting in one pass."""
    total = 0
    pool = []  # (last_modified, commit_hash, repo, rev)
    for repo in info.repos:
        try:
            total += int(repo.size_on_disk)
            revs = list(repo.revisions)
            if len(revs) <= 1:
                continue  # single revision == newest: structurally kept
            newest = max(revs, key=lambda r: (r.last_modified, r.commit_hash))
            kept_blobs = {
                f.blob_path for rev in revs for f in rev.files
                if rev is newest or rev.refs or now - rev.last_modified <= floor_seconds
            }
            for rev in revs:
                if rev is newest or rev.refs or rev.commit_hash in already_selected:
                    continue
                if now - rev.last_modified <= floor_seconds:
                    continue  # in-flight floor: just-minted revision
                excl = [f for f in rev.files if f.blob_path not in kept_blobs]
                newest_excl_atime = max((f.blob_last_accessed for f in excl), default=0.0)
                if excl and now - newest_excl_atime <= floor_seconds:
                    continue  # exclusive data read within the floor: kept
                pool.append((rev.last_modified, rev.commit_hash, repo, rev))
        except Exception:
            continue  # degenerate repo: fail toward KEEP
    overage = total - already_freed_approx - cap_bytes
    stats = {"total_bytes": total, "overage_bytes": max(0, overage),
             "n_eligible": len(pool), "selected_bytes": 0}
    if overage <= 0:
        return [], stats
    pool.sort(key=lambda t: (t[0], t[1]))  # oldest first
    by_repo: dict[str, tuple] = {}
    acc = 0
    for _, _, repo, rev in pool:
        if acc >= overage:
            break
        acc += int(rev.size_on_disk)
        by_repo.setdefault(repo.repo_id, (repo, []))[1].append(rev)
    stats["selected_bytes"] = acc
    return list(by_repo.values()), stats
```

## 11. Decision Rationale

1. **Trigger shape = total-cache-bytes cap (not per-repo bytes / revision-count caps).**
   *Why:* the Goal's failure quantity is total bytes on `/`; a total cap fires on every incident shape (measured: 101 GB total > 50 on 2026-07-16; 64.1 GB > 50 live on 2026-07-17), while oldest-first pooling automatically concentrates the reap in the churn repo (the 295-revision data repo IS the bulk of the eligible pool) — so per-repo caps add knobs without adding coverage. A per-repo revision-count cap does not bound bytes (few huge revisions evade); a per-repo bytes cap misses multi-repo accumulation.
   *Source:* 2026-07-16 incident numbers (task #1450 body); live scan 2026-07-17 (§12 A12).
   *Alternatives rejected:* per-repo revision-count cap; per-repo bytes cap; combination (more test surface, no additional firing coverage on the observed shapes).
2. **Cap default = 50 GB.**
   *Why:* comfortably above the legit structurally-kept bulk (newest+ref'd+single-rev ≈ 18 GB measured live: Qwen-7B 15.2 GB + newest data-repo revision + small repos), so a healthy cache never triggers; caps the incident at half its size (frees ~51 GB of the 101 GB, ≈ 10.5 pts of the 485 GB fs); sits above the 40 GB per-repo always-escalate precedent so escalation fires before/with the cap.

   *Alternatives:* 40 GB (tighter; risks perma-over-cap thrash as legit bulk grows), 76 GB (the #1376-observed episode size; would not have prevented 98 %).
3. **In-flight floor = 1 h (`EPS_VM_HOME_HF_SIZE_CAP_MIN_AGE_HOURS`), applied to `last_modified` AND exclusive-blob atime.**
   *Why:* the floor must be ≪ same-day for the arm to fire on the motivating incident (a 24 h floor — the relatime coarseness — would keep the guard blind to it); 1 h protects the genuinely in-flight case (a revision being minted/read right now) while exposing the day's churn.    *Source:* incident shape — same-day accumulation, hours old (body); relatime caveat already documented at L1137–1141.
   *Alternatives:* 24 h (defeats the Goal); 0 (no in-flight protection); reusing the 7 d knob (defeats the Goal).
4. **Gating = inherit the tier's existing pressure gate (no new gate; not unconditional-on-every-apply beyond it).**
   *Why:* tier (e) already runs only when `run_guard` is `triggered` — over the 85 % threshold (cron) or `--ignore-threshold` (watcher sub-floor, itself a free-bytes pressure signal) — so the arm fires exactly under disk pressure with zero new wiring; adding an internal disk probe would duplicate `run_guard`'s job and break the pure-selector testability; making it fire below threshold would reap caches on a healthy disk for no benefit.
   *Source:* `run_guard` L1638–1649 (read); #1392 sub-floor design (`a6d537a96b`).
   *Alternatives:* second internal df probe (redundant, less testable); always-on cap (unnecessary churn on healthy disks).
5. **Oldest-first ordering by `(last_modified, commit_hash)`.**
   *Why:* oldest unref'd revisions are the least likely to be in active use (freshness is the only liveness signal available without refs), deterministic tie-break matches the existing newest-pick convention (L1156), and stopping at the cap preserves the freshest churn.
   *Source:* #1377's newest-pick tie-break precedent (`5fc09e89a8`, L1156).
   *Alternatives:* largest-first (frees faster but preferentially deletes the most-recently-relevant large revisions); random (non-deterministic tests).
6. **Byte targeting via `rev.size_on_disk` with documented under-reap bias.**
   *Why:* exact freed-bytes requires per-selection-order exclusive-blob accounting (order-dependent, complex); the approximation errs toward keeping (shared blobs overestimate freed → fewer selected), and the guard's repeat cadence converges.
   *Source:* the existing code's own split — `expected_freed_size` for truth (L1459), `rev.size_on_disk` for per-repo approximations (L1467) — plus huggingface_hub's documented per-revision size semantics (§12 A5).
   *Alternatives:* iterative strategy building per candidate (N delete_revisions calls — slow, more failure surface); exclusive-size precomputation (order-dependent correctness risk).
