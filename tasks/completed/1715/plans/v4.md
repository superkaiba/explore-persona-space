### 4.2 Verbatim substitute (from task body `## Proposed change`)

Preamble (L2016-2019 REPLACEMENT):

> **Open the draft PR only if the branch is ahead of fetched `origin/main`.** `gh pr create` errors with `No commits between main and issue-<N>` when the branch has no commits yet (the common case before the implementer has run). Pre-check first (bounded fetch + `origin/main`-anchored aheadness):

Fenced bash block (L2020-2026 REPLACEMENT):

```bash
# Base ref is FETCHED origin/main — new_worktree.sh cuts branches from
# refs/remotes/origin/main, and the repo root's local `main` routinely lags it.
# NEVER pipe this block — guard_piped_git_push.sh blocks a piped `gh pr create`
# (CLAUDE.md § Concurrent repo-root committers): a pipe masks the exit code.
timeout --kill-after=30s 120s git -C "$REPO_ROOT" fetch origin main --quiet || true
if [ "$(git -C "$REPO_ROOT" rev-list --count origin/main..issue-<N>)" -gt 0 ]; then
  gh pr create --draft --head issue-<N> \
    --title "issue-<N>: <task title>" \
    --body "Closes task #<N>."
else
  echo "issue-<N> has no commits ahead of origin/main yet; skipping draft PR (open it after the implementer commits)."
fi
```

### 4.3 Explicit change enumeration

1. **Aheadness ref:** `main..issue-<N>` → `origin/main..issue-<N>` in the `rev-list --count` call.
2. **Fetch pre-step:** prepend `timeout --kill-after=30s 120s git -C "$REPO_ROOT" fetch origin main --quiet || true` — bounded (120 s + 30 s kill), non-fatal (`|| true`); a network hiccup at Step 4 must NOT halt the pipeline. A stale-but-present `origin/main` still beats local `main` by construction.
3. **`gh pr create` gets `--title`:** `--title "issue-<N>: <task title>"` on a continuation line before the `--body`. Non-interactive `gh` requires it (or `--fill`); we prefer the explicit title convention over `--fill` because the `issue-<N>: ...` prefix is the project's PR-title convention.
4. **Inline "never pipe" comment:** three of the four commented lines at the top of the bash block name `guard_piped_git_push.sh` explicitly (so a composer finds the guard rather than only the block) and cite `CLAUDE.md § Concurrent repo-root committers` (so the mechanism is stated at the recipe site).
5. **`else`-branch echo:** `no commits ahead of main yet` → `no commits ahead of origin/main yet` — the message MUST match the test above it (a stray "main" here would re-seed the same confusion into future readers).
6. **No other line touched:** the surrounding paragraph structure (L2010-2015 `$REPO_ROOT` recipe + L2028-2031 substrate-independence note) is untouched.

## 11. Decision Rationale

`N/A — no training hyperparameters.`

Design-choice rationale (not a hyperparameter, recorded here for the code-reviewer's context):

- **Why `origin/main..` rather than `--base main` on `gh pr create`?** The bug is in the LOCAL aheadness GUARD, not in `gh pr create`'s own base resolution. Anchoring the guard on `origin/main` matches every sibling site in the file (`new_worktree.sh` L18-28 documents branch base = `refs/remotes/origin/main`; the strip-provenance classifier already uses `origin/main...HEAD`). Source: `.claude/skills/issue/SKILL.md` Step 10d + `scripts/new_worktree.sh` L23-28 (verified plan-time).
- **Why bounded `timeout … || true` on the fetch?** Matches every other bounded network call in the workflow surface (the `codex_task.py` fetch preamble, the `sync_repo_root.py` bounded pull). A hung fetch at Step 4a would strand the recipe; `|| true` keeps a stale-but-present `origin/main` in play. Source: pattern reuse from sibling workflow scripts.
- **Why `--title "issue-<N>: <task title>"` rather than `--fill`?** The project's PR-title convention is `issue-<N>: <one-line summary>`; `--fill` reads the branch's HEAD commit message, which for zero-own-commits branches is fetched-`main`'s tip — wrong content, wrong shape. Source: task body `## Proposed change` (`--fill` is an acceptable alternative but loses the issue-<N> title convention).
- **Why name `guard_piped_git_push.sh` explicitly in the inline comment?** So a future composer reading SKILL.md finds the guard by filename, not only by the runtime BLOCKED message. Source: incident `564d9a53` (2026-07-26) — the block worked but the recipe site itself gave no clue why.
