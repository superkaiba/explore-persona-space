**Restore mechanism** — a small idempotent bash script, committed for provenance to task #1083's own artifacts dir (resolve via `uv run python scripts/task.py find 1083`; never a hand-built `tasks/<status>/1083/...` path), e.g. `<task1083_dir>/artifacts/restore_registry_drift.sh`. The restore table rows carry FIVE columns: `(id, sha, src_prefix, dst_prefix, expected_title)` — `expected_title` is the fact-checked title from the §4 table sources (making the runtime verification non-tautological w.r.t. the script's own `(sha, src)` values). For each row it:

0. **Id-identity assertion (pre-restore, per row):** assert the numeric id embedded in `src_prefix`, in `dst_prefix`, and (per restored path) in `dst_path` all equal the row `id` (regex the trailing `/<digits>` path component). Any mismatch → abort loud BEFORE any write (catches the transcription-bug class: #698's sha pasted into #699's row, or a src prefix mapped into the wrong dir).
1. Enumerates `git ls-tree -r <sha> -- <src_prefix>` (mode + path), **skipping every path under `artifacts/`**.
2. Maps `src_path` → `dst_path` (prefix substitution; identity for same-path rows).
3. **Skips any `dst_path` that already exists — `[ -e "$dst" ] || [ -L "$dst" ]`** (create-only; covers #750's tracked siblings and #707/#708/#709's untracked `plans/` residue; the `-L` leg is load-bearing — a bare `-e` follows symlinks, so a pre-existing dangling symlink would read "absent" and turn `ln -s` into an EEXIST abort).
4. Restores — with `mkdir -p "$(dirname "$dst")"` ABOVE the mode branch (`git ls-tree -r` emits `plans/plan.md` before `plans/v1.md`, so the symlink is the first path created under `plans/` and needs the mkdir too):
   - mode `100644`: `git show "<sha>:<src>" > "$dst"`
   - mode `120000` (the `plans/plan.md` symlinks — verified mode 120000 at `5ade45c23d`): `ln -s "$(git show "<sha>:<src>")" "$dst"` (the blob content IS the link target, e.g. `v4.md`). A `git show > file` here would write a regular file containing the target string — wrong; the script branches on mode.
5. **Byte-match verification pass:** for every restored regular file `git show "<sha>:<src>" | cmp - "$dst"`; for every restored symlink `[ "$(readlink "$dst")" = "$(git show "<sha>:<src>")" ]`. Any mismatch → abort loud (fail fast, no `|| true`).
6. **Frontmatter parse + expected-title check:** for each restored body.md, a `uv run python -c` loop calling `explore_persona_space.task_workflow._read_body(Path(...))` — a ValueError means the source body is malformed and the item routes to Phase 7 (park), not to a hand-edit. Additionally assert the parsed frontmatter `title` equals the row's `expected_title` (independent of the script's own sha/src values — the wrong-commit-right-bytes corruption class fails here).
7. **Emits a manifest** (`<task1083_dir>/artifacts/restore_manifest.txt`): every path it created, one per line — the exact staging list for the commit below.

- **D1 — Restore into the CURRENT on-disk dir; no status moves.** **What:** each body is restored where the dir physically sits (#701 at `completed` though its newest commit says `running`; #709 at `planning` though its newest commit says `proposed`). **Why:** `task.py` status changes `git mv` the physical directory, so disk location is residue of the LAST live transition — strictly newer evidence than the newest surviving commit; #766's registry row independently corroborates `completed`. The body's "no status moves" constraint also binds. **Source:** on-disk tree + registry rows + move-commit trail read this session; task #1083 body `## Scope`. **Alternatives:** restore at newest COMMITTED status (rejected: provably older, and would create status dirs contradicting disk); park unknowns at `archived` (rejected: fabricates a transition; disk evidence exists for all 15); `set-status 709 archived` proactively (rejected: violates no-status-moves; surfaced for the user instead).
- **D2 — Restore events/comments/concerns/plans where recoverable and absent, not body-only.** **What:** full create-only sibling restore per the §4 table. **Why:** the Goal says "recover ... from git history if it existed"; siblings carry dashboard lifecycle + review provenance, cost nothing (same commits), and create-only eliminates overwrite risk. **Source:** `git ls-tree` inventories; Goal text. **Alternatives:** body-only (rejected: abandons recoverable state); whole-dir `git checkout <sha> -- <dir>` (rejected: writes to commit-side status paths for the 6 mapped tasks and can overwrite untracked residue with older versions).
- **D3 — No task.py/library code change; no new test.** **What:** pure state repair. **Why:** "does `--repair` crash/skip silently on missing-body dirs?" is answered NO by code read (`_has_body` :4398) and existing pinned tests — the tool already IS the canonical repair; the drift is data, not a code defect. A regression test would pin data that no longer exists post-repair; the audit-clean end state is the check. **Source:** task_workflow.py:4381–4574; tests/test_task_workflow.py:1083–1206. **Alternatives:** a `task.py restore-from-git` subcommand (rejected: one-off, scope creep; the provenance script in the task's artifacts dir suffices); an extra empty-stub test (rejected: covered).
- **D4 — Uniform `git show` restore (never `git checkout <sha> -- <path>`).** **What:** blob-by-blob `git show <sha>:<src> > <dst>` / `ln -s` for symlinks. **Why:** `git checkout <sha> -- <path>` writes to the COMMIT-side path — wrong for the 6 mapped-path tasks (would create e.g. `tasks/running/701/`, ADDING audit problems) — and touches the index; `git show` is uniform, mapping-friendly, index-free, and branch-switch-free by construction. **Source:** git semantics + the §4 mapped rows. **Alternatives:** mixed strategy (rejected: two code paths, zero benefit).
- **D5 — Sequencing: restore → commit → dry-run gate → single `--apply`.** **What:** exactly one registry write, gated on an exact pre-registered classification (1 stale_real + 11 missing_real + 0 residue). **Why:** bodies must exist before reconcile can snapshot; the gate makes a concurrent-session surprise STOP the apply instead of half-writing. **Source:** `reconcile_registry` dry-run/apply split (:4526 vs :4549). **Alternatives:** apply immediately (rejected: loses a free gate); per-task incremental applies (rejected: 15 commits of churn, no isolation benefit — the apply is atomic under flock).
