**4.1 — Allowlist constant + pattern (module level, above `PATTERNS`):**

```python
# Field / API / config identifiers that legitimately appear backticked in
# reader-facing v4 prose. Seeded from the 2026-07-15 corpus dry-run (#1372);
# extensible — a false positive at the Step 9a-bis gate adds its token here
# with a one-line reason. Exact-token match only (the regex closes the
# lookahead with a backtick), so `logp_pos_mean_v2` still flags.
_SNAKE_SLUG_ALLOWLIST: frozenset[str] = frozenset({
    "add_special_tokens",    # HF tokenizer kwarg
    "apply_chat_template",   # HF tokenizer API
    "est_gpu_hours",         # follow-up proposal field
    "has_clean_result",      # task frontmatter field
    "list_repo_files",       # huggingface_hub API (upload-verification prose)
    "list_repo_tree",        # huggingface_hub API
    "logp_pos_mean",         # dual-DV companion field (llm-judging.md rule 20)
    "max_model_len",         # vLLM engine kwarg
    "max_new_tokens",        # generation kwarg
    "output_hidden_states",  # HF forward kwarg
    "span_seam_counts",      # per-row provenance field (#1315's legitimate neighbor)
})

# Backticked bare 3+-segment lowercase snake_case token. Tight backtick
# anchoring structurally excludes filenames (`mix_meta.json`), paths, calls
# (`train_lora()`), flags (`--x_y_z`), and assignments (`a=b_c_d`); the
# `test_` lookahead excludes pytest test names; the allowlist lookahead is
# exact-token (closes with a backtick).
_SNAKE_SLUG_PATTERN = (
    "`(?!test_)(?!(?:"
    + "|".join(sorted(re.escape(t) for t in _SNAKE_SLUG_ALLOWLIST))
    + ")`)[a-z]+_[a-z]+(?:_[a-z0-9]+)+`"
)
```

**4.3 — Scan-source builder** (new helper, mirrors `_restrict_pre_reg_to_prose_sections`'s shape and degradation discipline):

```python
_SNAKE_SLUG_PROSE_H2S: frozenset[str] = frozenset({"takeaways", "goal", "results"})
_REPRO_LABEL_RE = re.compile(r"^(?:[-*]\s+)?\*\*\s*Repro\s*:", re.IGNORECASE)


def _restrict_snake_slugs_to_v4_reader_prose(body: str, text: str) -> str:
    """Scan source for `opaque_snake_slugs` (#1372, incident #1315).

    v4-sentinel bodies ONLY — v3/v2/legacy bodies return "" (category
    inactive): forward-only, per CLAUDE.md § Experiment Report Structure
    ("grandfathered bodies are NEVER newly hard-FAILed by a v4 rule").
    Within a v4 body, keep only lines inside ## Takeaways / ## Goal /
    ## Results; blank everything from the `**Repro:**` footer label onward
    (the footer + launch commands are the SANCTIONED slug surfaces —
    planner §5 / SPEC.md); blank blockquote (`>`) lines (figure captions
    naming the plotted cell — same carve-out family as interval_inline's).
    `text` must be the strip_fenced_code_only chain WITH table rows blanked
    (inline backticks kept — strip_code would erase the spans this
    category reads; #667 precedent). Degradation: a mis-detected boundary
    means a line is scanned or blanked, never a crash; a defensive later
    H2 re-evaluates the footer cut.
    """
    if "<!-- clean-result-v4 -->" not in body:
        return ""
    out: list[str] = []
    keep = False
    for line in text.splitlines():
        stripped = line.strip()
        h2 = _H2_RE.match(stripped)
        if h2:
            keep = h2.group("title").strip().lower() in _SNAKE_SLUG_PROSE_H2S
            out.append("")
            continue
        if _REPRO_LABEL_RE.match(stripped):
            keep = False  # footer runs to EOF (next H2 re-evaluates, defensively)
        if keep and stripped.startswith(">"):
            out.append("")
            continue
        out.append(line if keep else "")
    return "\n".join(out)
```

## 7. Kill criteria / Decision gates

No decision gates — short run (< 1 h wall), pre-verified hypothesis (the planning dry-run already executed the design end-to-end). Kill criteria for the design itself:

## 11. Decision Rationale

- **3+-segment threshold (2+ underscores).**
  **What:** `[a-z]+_[a-z]+(?:_[a-z0-9]+)+` — first two segments alphabetic, 3+ segments total.
  **Why:** 2-segment snake_case (`span_seam`, `run_result`, `mix_meta`) is overwhelmingly legitimate field vocabulary; 3+ segments is where condition/cell slugs live (`neg_reph_curious`, `imp_icl_ft_neg`, `cell_pre_own`).
  **Source:** Task #1372 Goal (verbatim regex sketch) + this session's corpus dry-run (the 72-token whole-body table: every genuine slug is 3+ segments; `span_seam` structurally excluded at 2).
  **Alternatives:** 2+ segments (rejected: floods field names); 4+ (rejected: misses the incident token `neg_reph_curious` at exactly 3).
- **Section scoping: v4 Takeaways/Goal/Results only; Methodology + footer out.**
  **What/Why:** §4.6.
  **Source:** measured dry-run (27/64 + 72 tokens whole-body → 3/1,063 scoped); planner §5 sanctioned-surface list; SPEC.md Methodology definition; #1315's own live remediation (slugs → footer) confirming the footer is the sanctioned destination.
  **Alternatives:** include Methodology (rejected: it is the field-name-dense section; the incident catches via Results anyway); Results-only (kept as flood fallback, §7).
- **v4-only activation.**
  **What:** non-v4 bodies return an empty scan source.
  **Why/Source:** CLAUDE.md forward-only principle ("v3/v2/pre-sentinel bodies … are NEVER newly hard-FAILed by a v4 rule") + `pre_reg`'s generation-gating precedent (`_restrict_pre_reg_to_prose_sections`); dry-run: v3 inclusion adds only legacy FP classes.
  **Alternatives:** v3 three-section scoping like `pre_reg` (rejected: v3 corpus is frozen; follow-up rounds migrate to v4 anyway).
- **Allowlist mechanism: (a)+(b)+(c) combination, grounded in the dry-run.**
  **What:** structural exclusions do the heavy lifting — tight-backtick anchoring (covers the Goal's suffix/extension case (a): `mix_meta.json` never matches), fences/tables/details/footer/captions (existing machinery (c)) — plus an 11-entry exact-token named set (b) and a `test_` prefix exclusion.
  **Why:** the dry-run shows the residual FP surface after structural exclusions is small and identifiable (API kwargs, project field names, pytest names); an exact-token set is auditable and cheap to extend.
  **Source:** the whole-body dry-run token table (this session; reproducible via the §10 harness) — every allowlist entry is either a corpus hit of the API/field class or a project-standard field (`logp_pos_mean`, `max_new_tokens`) certain to appear in future Results prose.
  **Alternatives:** suffix-only (insufficient: bare field names have no suffix); verb-prefix exclusion list (list_/fetch_/apply_ — rejected as fragile and unneeded once the footer exemption removed all corpus instances); exempting tokens defined in the body's own tables (REJECTED hard: the condition table defines exactly the slugs the rule bans from prose — it would exempt every genuine catch).
- **Blockquote (caption) exemption.**
  **What:** `>` lines blanked inside kept sections.
  **Why:** a caption identifying the plotted cell by slug is provenance, not narrative (dry-run: #666's `tf_default_contra_d1_seed42` caption is the only corpus instance).
  **Source:** `_strip_interval_inline_exempt_lines` precedent (Lens 7 chart-annotation carve-out).
  **Alternatives:** scan captions (rejected: FP-vs-catch ratio 1:0 in corpus, and the LM critic reads captions anyway).
- **`test_` prefix exclusion.** **What/Why:** pytest names are real code identifiers, never condition slugs (#672's two hits). **Source:** dry-run. **Alternatives:** allowlist each test name (absurd — unbounded).
- **FAIL severity (not WARN).** **What:** the category joins the standard exit-1 findings. **Why:** the origin candidate is `mechanizable: yes` — the point is catching at the gate so the critic stops burning a round; the measured FP rate supports FAIL. **Source:** #1372 body; dry-run. **Alternatives:** WARN-only (no plumbing exists; deferred to the §7 flood fallback).
