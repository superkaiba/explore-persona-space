### Edit 3 — canonical recipe block, appended to procedure step 6 (after the
exit-code-hygiene paragraph, ~line 8496, before step 7)

Add a `**Canonical gist-update recipe (re-exports / follow-up rounds —
incident #1769).**` continuation paragraph + fenced block, shape:

```bash
GIST_ID=$(basename "<prior gist_url from the latest epm:methodology-doc-generated marker>")
DOC=docs/methodology/issue_<N>.md
GIST_FILE=issue_<N>.md          # gh gist create used the basename
GIST_UPDATED=no
if gh api -X PATCH "gists/$GIST_ID" \
     -F "files[$GIST_FILE][content]=@$DOC" >/dev/null 2>&1; then
  # VERIFY by API read-back — PATCH rc=0 alone is NOT success (#1769:
  # the EDITOR-override gh gist edit form returned rc=0 with content
  # UNCHANGED). $(...) strips trailing newlines on both sides, so a
  # trailing-newline-only difference (the #1769 verified-match shape)
  # reads as a match; any interior difference fails.
  REMOTE=$(gh api "gists/$GIST_ID" --jq ".files[\"$GIST_FILE\"].content" 2>/dev/null)
  LOCAL=$(cat "$DOC")
  if [ -n "$REMOTE" ] && [ "$REMOTE" = "$LOCAL" ]; then GIST_UPDATED=yes; fi
fi
```

Prose riders in the same paragraph:
- BAN: never `EDITOR=... gh gist edit` (silent no-op, rc=0, stale public
  mirror — #1769) and never the flag form `gh gist edit <id> --filename
  <name> <local>` either — exactly ONE verified update path exists.
- Fail-soft: `GIST_UPDATED=no` never blocks the step; keep linking the
  existing gist URL and record `gist_update: failed — <one-line reason>`
  in the step-9 `epm:methodology-doc-generated` marker note (a stale
  mirror is thereby VISIBLE instead of silent).
- The verify's read-back uses the gist GET `content` field (methodology
  docs are far below the gist API's ~1 MB truncation threshold; if
  `truncated: true` ever appears, fetch `raw_url` instead).
