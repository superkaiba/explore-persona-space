# Plan v1 — #2149: pod-grain idleness leg for the keep-running wedged-owner arm

`kind: infra` (workflow-surface fix). Parent: #1739 (incident source; no experimental recipe inherited).

### TDD: no

## 1. Requirement + acceptance criteria

The #1582 keep-running wedged-owner escalation arm (`scripts/autonomous_session_watch.py`) keys
leg 1 on TASK-grain marker silence (`progress_gap_s >= KEEP_RUNNING_OWNER_IDLE_S`, 12h). On a busy
multi-round task the gap never opens (#1739: 129 markers over the 19.6h idle window, largest gap
6.19h), so an idle, verified-done, `keep-running`-shielded pod is structurally invisible — ~$165
burned across 3 idle 1xH100 pods.

Add a POD-grain idleness leg that escalates on the pod's OWN evidence, independent of task marker
traffic. Acceptance criteria (verbatim from the task body):

1. A `keep-running`-shielded RUNNING pod with a terminal done-sentinel and no live work escalates
   within the configured floor even when its task receives markers continuously — with a
   regression test reproducing the #1739 shape (busy task, largest gap << 12h, idle pod) asserting
   the arm fires.
2. Existing #1582 behaviour unchanged for the quiet-task case (no regression in its tests).
3. Escalation remains never-a-stop; unknown reads freeze the counter.
4. Per-pod grain: an idle pod escalates while a sibling pod on the same issue is legitimately busy.
5. Kill switch documented in `.claude/rules/background-automation.md` alongside the other passes.

## 2. Method delta (what differs from the existing arm)

The existing arm stays byte-equivalent on its path: `progress_gap_s >= min_idle_s` → owner
resolution → `decide_keep_running_owner_escalation`. The NEW leg runs in the branch that today
returns `("clear", 0)` unconditionally — `progress_gap_s < min_idle_s` (task busy) — and keys on a
single bounded SSH probe of the pod itself.

**Design decision — no owner-state gate on the pod-grain leg.** Acceptance criterion 4 (idle pod
escalates while a sibling pod on the SAME issue is legitimately busy) implies a live session
driving the issue; `_keep_running_owner_state` is ISSUE-grain (union of registered + cwd-mapped
sessions) and would read "live" in exactly that shape, re-creating the grain mismatch one level
down. The task body's sentinel leg wording ("escalates on its own evidence") confirms. Safety
budget instead: ESCALATE-ONLY (never a stop), >=2-consecutive-tick confirmation, unknown freezes
the counter, one marker per episode + 24h re-alert — identical episode plumbing to the owner leg.

**Pod-grain evidence — one bounded SSH probe** (`ssh -o BatchMode=yes -o ConnectTimeout=10` +
outer `timeout`, single remote `sh` command against `info.name`, the pods.conf/~/.ssh/config
alias). The probe returns three facts, any unparseable/unreachable read → `None` → "unknown" →
freeze (fail toward no-fire):

- `log_write_age_s`: age of the NEWEST mtime under `/workspace/logs/` (all files). A pod doing any
  real work (a reused pod running a next round, a live launcher, a poll loop) keeps writing here;
  this kills the stale-old-sentinel-on-a-reused-pod false positive.
- `done_sentinel_age_s`: age of the newest `/workspace/logs/*done*.json` whose JSON carries a
  terminal `"phase": "done"` (or terminal `status`); `None` if no such file.
- `gpu_util_max`: max GPU utilization % across GPUs from `nvidia-smi
  --query-gpu=utilization.gpu --format=csv,noheader,nounits`; `None` if nvidia-smi fails.

**Two evidence tiers, one decision:**

- **Sentinel tier (primary, floor `EPM_KEEP_RUNNING_POD_IDLE_MIN_H`, default 4h):** fires when
  `done_sentinel_age_s >= floor` AND `log_write_age_s >= floor` AND (`gpu_util_max` is None or
  == 0). A verified-done pod has no reason to live (task-body wording); 4h clears legitimate
  between-round reuse gaps while capping a #1739-shape burn at ~1/5 of the incident cost. The
  named-next-round reuse carve-out stays honored implicitly: a reused pod writes logs again and
  the `log_write_age_s` conjunct clears the episode.
- **Utilization tier (fallback when NO done-sentinel file exists, floor
  `EPM_KEEP_RUNNING_POD_UTIL_IDLE_MIN_H`, default 12h — weaker evidence, longer floor):** fires
  when `gpu_util_max == 0` AND `log_write_age_s >= floor`. A point-in-time 0% never fires (the
  r2fair CPU-preamble false alarm): the >=2-consecutive-tick confirmation plus the 12h
  `log_write_age_s` conjunct make this a sustained-idleness read.

**Cheap pre-vetoes before any SSH (lazy-cost discipline):** pod `created_at` younger than the
sentinel floor → skip (a fresh pod cannot be floor-idle); `_provision_in_flight_reason` /
`_worktree_recent_activity` vetoes NOT applied to this leg (they are task/session-grain; the
`log_write_age_s` conjunct is the pod-grain equivalent) — deviation from the owner leg stated
here deliberately.

**Pure decision function** `decide_keep_running_pod_idle_escalation(...)` mirroring
`decide_keep_running_owner_escalation`'s contract exactly: returns `(action, new_missed)` with
`action in {"clear", "hold", "escalate", "re-alert"}`; `None` evidence → hold/freeze; `>=2`
consecutive confirmed ticks (`threshold` parameter, same value as the owner leg's) before the
episode opens; once-per-episode marker; re-alert every `EPM_KEEP_RUNNING_WEDGED_REALERT_H` (24h,
shared with the owner leg).
