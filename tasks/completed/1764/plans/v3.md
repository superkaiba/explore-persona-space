## Requirement + acceptance criteria

**Requirement (task Goal):** detached-phase log probes on GCE must be able to
read root-owned workload logs.

**Gap (verified at clarify time, 2026-07-28):** all 9 `sudo -n` occurrences in
`.claude/skills/issue/SKILL.md` are earlyoom `choom` calls; no probe recipe
mentions sudo for log reads. Incident (session 77ee3ced, #1738 monitoring,
2026-07-28T06:04Z): a diagnostic `tail /workspace/logs/issue-1738.log` on the
GCE instance failed `Permission denied` — the GCE startup-script workload runs
as root, so its log is root-owned, while the SSH probe user is non-root. The
liveness read degraded to pid/CPU-only. RunPod pods SSH as root, so the class
is GCE-specific.

**Acceptance criteria:**
1. The § "Successor / re-entry rule" (Step 9 entry guard, ~L6548) log-tail
   prescription carries a GCE EACCES clause: retry the content read with
   `sudo -n tail -50 <log>` (fallback `sudo -n cat <log> | tail -50`), and
   never classify an EACCES as "log frozen / missing / phase dead".
2. The § "Long-phase heartbeat duty" step 2(i) verify-evidence list carries a
   one-clause pointer to the same rule (a Permission-denied `tail` on GCE is a
   probe artifact — retry with `sudo -n tail`; it is NOT verify-FAIL evidence).
3. Both hunks note the ownership mechanism in one clause (GCE startup-script
   workload runs as root → root-owned log; RunPod pods SSH as root → exempt),
   so a future reader knows when the clause applies.
4. The NEW pin test in `tests/test_issue_skill_detached_harvest_pin.py` passes and
   fails if either hunk is removed. No behavioral surface beyond SKILL.md +
   the pin test changes; `workflow_lint.py` no-flags
   run stays green on the touched file; the mapped rules-pin tests (if any map
   to SKILL.md) stay green.
