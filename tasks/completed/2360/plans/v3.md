The field's docstring states consumers MUST treat top-level `report.ok` / the CLI rc as authoritative; the verdict is diagnostic routing only.

### D2 — Tier 2: bounded subprocess deep-import probe (RunPod default-on; VM/GCE opt-in)

Continuing in `check_venv_import_health` after tier 1 (reached only when tier 1 passed — D1 step 5):

1. Lane gate: run iff `EPM_PREFLIGHT_IMPORT_PROBE` in `{"1","true","yes"}`, OR (unset/other AND `is_runpod_env()`). `"0"/"false"/"no"` forces off. Not run → verdict `"skipped-lane"`, return silently (no warning spam on every VM launch).
2. Pre-probe stderr banner (load-bearing — see D3): immediately BEFORE launching the probe, `print("[preflight] deep-import probe launching (timeout <N>s) — if this is the last preflight output for far longer than the timeout, the /workspace mount is likely hard-wedged (gotchas.md § MooseFS FUSE read-wedge)", file=sys.stderr, flush=True)`.
3. Probe: `_run([sys.executable, "-c", _IMPORT_PROBE_SNIPPET, *DEEP_IMPORT_MODULES], timeout=int(timeout_s))` where `timeout_s = float(os.environ.get("EPM_PREFLIGHT_IMPORT_PROBE_TIMEOUT_S", "180"))`. `sys.executable` is the venv python under every sanctioned invocation (`uv run python -m ...`, the `/usr/local/bin/python` shim which execs `.venv/bin/python`); deliberately NOT `uv run` — a nested `uv run` can trigger an implicit sync and re-enter the #2278 shim/lock deadlock class, and it would re-resolve the env rather than test the venv as-is. Snippet (module-level constant) — the `LEAF` sentinel is the B6 fix: the deepest cause is extracted from the exception object BEFORE any truncation and emitted as ONE bounded machine-readable line, so acceptance criterion 1's "leaf import error surfaced" no longer depends on where a byte window lands:

```python
_IMPORT_PROBE_SNIPPET = (
    "import importlib, sys, traceback\n"
    "for m in sys.argv[1:]:\n"
    "    try:\n"
    "        importlib.import_module(m)\n"
    "        print('OK ' + m, flush=True)\n"
    "    except BaseException as e:\n"
    "        print('FAIL ' + m, flush=True)\n"
    "        root, seen = e, set()\n"
    "        while id(root) not in seen:\n"
    "            seen.add(id(root))\n"
    "            nxt = root.__cause__ if root.__cause__ is not None else (\n"
    "                None if root.__suppress_context__ else root.__context__)\n"
    "            if nxt is None:\n"
    "                break\n"
    "            root = nxt\n"
    "        print('LEAF %s: %.500s' % (type(root).__name__, root), flush=True)\n"
    "        traceback.print_exc()\n"
    "        sys.exit(3)\n"
)
```

   (Chain walk follows CPython's own display rule — `__cause__` first, else `__context__` unless suppressed; the `seen` set guards pathological cycles; `%.500s` bounds the sentinel at ~520 chars; a chainless exception is its own leaf. Stdout stays tiny — `OK`/`FAIL`/`LEAF` lines only — so the sentinel is never truncated.)
4. Verdicts:
   - `rc == 0` → verdict `"ok"`.
   - `rc == -1 and err == "timeout"` (the `_run` TimeoutExpired contract, preflight.py:178-179) → verdict `"timeout"`, `add_error` AND an immediate `print(..., file=sys.stderr, flush=True)` (rationale in D3). Error text names BOTH readings and the discriminator: "deep-import probe timed out after Ns — either a slow cold MooseFS venv read (raise EPM_PREFLIGHT_IMPORT_PROBE_TIMEOUT_S) or the MooseFS FUSE read-wedge (gotchas.md: spot reads on /workspace also hang under the wedge — run the discriminator before relaunching; kill+swap-pod per the runbook, never loop relaunches)".
   - any other nonzero → verdict `"fail"`, `add_error` COMPOSED AS: the failing module (last `FAIL <m>` line of stdout) + the `LEAF ...` sentinel line (parsed from stdout, LEADING the message) + the head+tail stderr harvest — first 4,000 chars + `... [<N> chars elided] ...` + last 4,000 chars whenever total stderr exceeds 8,192 chars, else the whole stderr. The sentinel is the leaf-error GUARANTEE (extracted pre-truncation, window-independent); the harvest supplies the surrounding traceback context. Why head+tail, not tail-only: Python prints a chained exception's CAUSE (the leaf) FIRST, then each re-wrap — a tail-only window drops the leaf on deep re-wrap chains; and why the harvest alone was insufficient (B6): a leaf whose own traceback block exceeds ~4,000 chars followed by >4,000 chars of wrapper lands the leaf line in the ELIDED MIDDLE — the one measured real failure (4,796 chars total) merely happened to fit whole. The sentinel closes that class outright; test 6 pins it at >8,192 chars with the leaf deliberately mid-window.
5. **Leaf-error guarantee, stated precisely:** two independent mechanisms — (a) leaf-first probe ordering: `sympy` and `torch._dynamo` are imported BEFORE `modeling_auto`, and `anthropic` stands alone, so the demonstrated classes fail at a pure-leaf module with no lazy machinery; (b) the `LEAF` sentinel carries the deepest cause even when a nested `_LazyModule` re-wrap fires (measured, transformers 4.57.6: direct `importlib.import_module("transformers.models.auto.modeling_auto")` can still emit `Could not import module 'GenerationMixin'` — with the true leaf chain attached as the chained CAUSE, which the sentinel walk extracts). The harvest windowing is now diagnostic convenience, not the guarantee.

New `PreflightReport` field: `venv_import_verdict: str = ""` (values `""|ok|tier1-fail|fail|timeout|skipped-cluster|skipped-lane|disabled`), added to the `main()` `--json` dict (after `env_synced`, preflight.py:1879) so dispatchers can read it. ### D3 — The flagged wedge consideration (explicit decision)

Decision: **the import leg is subprocess-isolated with a wall-clock bound (180 s default), a DISTINCT `timeout` verdict separate from `fail`, and a metadata-only tier 1 that runs first and is wedge-inert; on `timeout`, the compat check's unbounded in-process imports are skipped.** Reasons:

- An in-process import cannot be bounded; a subprocess can (`_run`'s `subprocess.run(timeout=...)` kills the child on expiry — no orphan probe process in the ordinary case).
- Preflight TODAY already hangs unboundedly on a wedged mount at `check_vllm_transformers_compat`'s in-process `import transformers; import vllm` (preflight.py:1306-1308). Ordering the new bounded probe BEFORE the compat check (insertion point: preflight.py:1769, between `check_env_vars` and `check_vllm_transformers_compat`) converts that silent hang into a bounded, named verdict — and a 3-line guard at the top of `check_vllm_transformers_compat` (`if report.venv_import_verdict == "timeout": add_warning(...skipped — bounded probe timed out, an in-process import here could hang preflight...); return`) prevents the subsequent unbounded import from re-introducing the hang. Existing `tests/test_preflight_vllm_compat.py` tests construct fresh `PreflightReport`s (default `""`) so they are unaffected.
- The `timeout` verdict's error text distinguishes hung-vs-ImportError and cites the gotchas discriminator rather than asserting "wedge" (the #2333 SLOW-CANARY precedent: a grinding-but-answering mount is not a wedge; the mount can also just be slow-cold).
- **Documented residual, ACCEPTED:** the probe is bounded only while the mount still delivers signals. `subprocess.run(timeout=...)` does `process.kill(); process.wait()` then re-raises (verified CPython 3.11.15; a live test showed the child dead 0.3 s after a 2 s timeout) — but on a HARD-wedged FUSE mount, a child stuck in uninterruptible I/O (D-state) can survive SIGKILL until the I/O returns, and the post-kill `wait()` then blocks preflight despite the timeout. I accept this residual: the status quo hangs unboundedly with NO diagnostic at all, while the probe hangs only on a hard-wedged mount AND names itself first — because the post-timeout diagnostic print sits AFTER `_run` returns, it would never execute in the SIGKILL-survival case, which is exactly why D2 step 2's pre-probe stderr banner exists: printed BEFORE the wait can block, so the operator's last preflight output names the probe + the wedge runbook in both the bounded-timeout case (banner, then the timeout error) and the hard-wedge case (banner is the final line). No fixture can certify the SIGKILL-survival path — documented, not tested (see Smoke blind-spot enumeration).
- The immediate stderr print on timeout exists because `report.summary()` prints only at the END of `preflight_check` — if any LATER check were to hang on the same wedged mount, the operator still sees the diagnostic.
- Timeout default 180 s, RETAINED at v2's value: the expanded 16-module chain measured 56.3 s on the CONTENDED shared VM (semi-warm; §9 per-module table) → 180 s ≈ 3.2× that wall; the sanctioned wedge discriminator uses 60 s for `import transformers` alone. The pod-side wall is genuinely unknown (8 uncontended vCPU cut the CPU share; MooseFS cold reads may raise the I/O share — the two biases OPPOSE), which is exactly why Phase V's live timing is REQUIRED and kill criterion (a) carries a pre-registered trim ladder instead of a plan-time guess. Env-tunable per-launch.
