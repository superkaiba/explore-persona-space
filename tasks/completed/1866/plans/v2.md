# Plan v2 — #1866: SLURM done-evidence disambiguation for dead-class terminal states

*(v2 = v1 + critic-round addition: producer-parity test 8. Critic verdict on v1: APPROVE, no Must-Fix; test 8 addresses its non-blocking concern 1.)*

## 1. Requirement + acceptance criteria (kind: infra — workflow fix)

**Requirement (task Goal):** a job whose workload finished must not read as bare `dead` to the poller on a status-writer artifact.

**Grounding correction (clarifier, 2026-07-31):** the filed #1836-tmp-race hypothesis is REFUTED — fellows job 15194 died in the `dvf_push` leg on a non-git tree (SLURM exit_code `128:0`, git's 128; not "0:0"), BEFORE the template's final done write; that cause is fixed workload-side (#1689 fix round 3 + #1835, both landed). The residual, still-open gap this plan closes: `backends/slurm_monitor.py::build_poll_result` maps every dead-class SLURM state to `dead` without consulting the job's own attempt-fresh `status.json` terminal-success record (`phase="done", exit_code="0"` — written ONLY by the sbatch terminal block after every stage exited clean under `set -eu`). Any post-done teardown artifact — `slurmstepd` cgroup errors (observed on node-8 in the same 15194 tail), EXIT-trap cleanup failures, epilog failures — flips a FINISHED job to a false `dead` → `next_action: investigate` → a wasted crash-fix round or RunPod failover re-run of completed work, plus the manual verification the /daily sweep flagged. GCP-lane precedent: the #1055 `workload_done_finalize_failed` classification (deliverables-verified-then-finalize-crashed reads done-like, never crash).

**Acceptance criteria:**
1. Dead-class SLURM state + ATTEMPT-FRESH `status.json` with `phase=="done"` AND `exit_code=="0"` → PollResult `status="done"`, `current_phase="done"`; the `epm:cluster-terminal` body keeps `slurm_state` verbatim, adds `workload_done_despite_slurm: true`, and routes `next_action: "interpret"`.
2. Fail-safe: evidence missing / stale (predates `submitted_at` − skew, blanked by the existing C2 gate) / `submitted_at is None` (freshness unprovable on a legacy handle) / `phase != "done"` / `exit_code != "0"` → behavior byte-identical to today (`dead`, `investigate`).
3. The `PREFLIGHT_FAIL_MARKER` shortcut retains its later override (fail-safe ordering unchanged).
4. The persisted-terminal reconnect path carries the flip (persisted `status: done` already round-trips; phase reads `done` when the new flag is set).
5. Tests pin the flip AND every fail-safe arm; module docstring + `SLURM_STATE_TO_STATUS` comment + workflow.yaml `epm:cluster-terminal` fields doc updated additively.

## 2. Method delta

Today the SLURM-lane dead/done verdict is a pure function of the SLURM JobState. Delta: consult the sbatch's own terminal-success record as a second evidence channel, gated on the EXISTING C2 attempt-freshness machinery (no new freshness logic). The `done`+`"0"` pair is unforgeable by intermediate writes: heartbeat and stage-phase writes carry `exit_code:""` (`_write_status <phase>` with no second arg, slurm.py ~L1775); only the terminal block writes `_write_status "done" 0` (~L2138), after the completion sentinel and after every stage exited clean. Downstream safety is unchanged: `status=done` routes to Step 6d.3 → upload verification (the hard artifact gate), so the flip cannot skip artifact checks — whereas a false `dead` costs a crash-fix round / failover re-run.

## 4. Scope decision — dead-class uniformity

The flip covers every state mapping to `dead` (`FAILED`, `TIMEOUT`, `PREEMPTED`, `NODE_FAIL`, `BOOT_FAIL`, `OUT_OF_MEMORY`, `DEADLINE`, `CANCELLED`, `CANCELLED+`): the evidence predicate is state-agnostic — done-0 means every workload + upload leg completed BEFORE the terminal state was recorded, so the residual failure is teardown-side regardless of which label SLURM assigned. `slurm_state` rides the terminal marker verbatim either way, so the audit trail always preserves the true SLURM verdict for post-hoc review.
