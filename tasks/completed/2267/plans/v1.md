`fig.savefig` figures never get a sidecar, so a retroactive FAIL would block

### 3.1 New check 55: `check_v4_sidecarless_figure_caption_codes` (FAIL, v4-only)

Placement: next to check 41 (`check_figure_sidecar_coverage`, line ~13411). Logic:

1. `if not is_v4(body): return PASS ("non-v4 body — forward-only")` (the check-44/54
   v4-self-gating precedent).
2. `section = _figure_scan_section(body)`; `section_text` None → PASS.
3. Iterate image lines exactly as check 28 does (lines 9906-9917), collecting each
   unique URL's caption window via `_figure_caption_after(rlines, i)` (first
   occurrence wins — same conservative dedup).
4. `_resolve_repo_root()` None → PASS (offline/stdin convention).
5. Per unique same-repo sha-pinned URL:
   - PNG must resolve at the cited sha (`_git_object_exists(...) == "pass"`), else
     skip — check 22's domain, no double-report (mirrors check 41 lines 13454-13456).
   - Sidecar path via the same `rpartition(".")` derivation as check 41 (lines
     13458-13459). Sidecar status `== "fail"` (definitively absent at a resolving
     sha) ⇒ the figure is SIDECAR-LESS; any other status ⇒ skip (fail-soft — a
     sidecar-PRESENT figure stays check 28's WARN domain; an indeterminate probe
     never FAILs).
   - For sidecar-less figures: `toks = _opaque_code_tokens(caption)` over the
     caption window. Non-empty → collect `(basename, toks)`.
6. Any collected hit ⇒ **FAIL** (`ok=False`), message naming each figure basename +
   token preview + remediation: "regenerate via savefig_paper with plain-English
   rendered text (writes the sidecar), or rewrite the caption's condition codes in
   plain English". No hits ⇒ PASS with `checked` count.

**Caption-scan false-positive posture (stated up front, resolved by the sweep):**
`_opaque_code_tokens` was calibrated for matplotlib rendered text, not markdown
prose; v4 captions can legitimately reference metric identifiers (`logp_pos_mean` is
a 3-segment snake → would flag). Primary design scans the FULL caption window
(including backticked tokens) — the #2054 incident class must not be evadable by
backticking. The §5 fleet sweep is the calibration gate: if the sweep FAILs any
existing green body on a benign backticked metric-name reference, the implementer
adds a markdown code-span exclusion (strip `` `...` `` spans before scanning — the
"code-span contexts" exclusion the check-28 docstring documents as a sidecar-channel
NO-OP is principled here, since captions ARE markdown) and re-sweeps; a hit that is a
genuine #2054-class escape is recorded and the affected caption fixed forward (the
task's own body is fair game; other tasks' bodies are NOT batch-edited — record and
surface instead). The chosen exclusion state is recorded in the implementer marker
and the check docstring either way.

**Accepted residuals (documented in the docstring, not implemented):** (i) `b=`/`m=`
single-letter-equals axis codes — unclassifiable without flagging ordinary caption
math (`b=0.3`); PNG-pixel text stays the multimodal critics' read. (ii) A sidecar-less
figure whose caption DECODES a slug inline (`` `cas-pers-con-lr1e5-s137` (cascade,
lr 1e-5, seed 137)``) still FAILs — remediation is regenerate-with-sidecar, which
routes the slug to check 28's caption-decode suppression. (iii) Opaque codes present
only in PNG pixels with a clean caption stay uncovered mechanically (unchanged
stance).

### 3.2 Hypothesis-code class extension (prime-marked codes; shared with check 28)

`_HYPOTHESIS_CODE_RE` currently `\bH\d[a-z]?\b` — the #2054 literal tokens
`H0'a`/`H0'b` do NOT match (apostrophe breaks the class). Extend to also match
prime-marked variants: `H<digit>` optionally followed by (ASCII `'` or unicode `′`)
+ single lowercase letter, i.e. `\bH\d(?:['′][a-z]|[a-z])?\b`-shaped (implementer
finalizes the exact regex + boundary semantics with unit tests). No new English
false-positive class: `H1's` already matches today via bare `H1`. This extension also
upgrades check 28 (sidecar channel) for prime-marked codes — a WARN-level
leniency-tightening matching the #1900/#1902/#1988 class-addition precedent.
