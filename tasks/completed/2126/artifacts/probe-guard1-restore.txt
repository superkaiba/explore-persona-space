# Run 2026-08-12 on the EPS VM. git version 2.34.1
# Shapes: in-HEAD modified | in-HEAD staged-deleted | staged-ADDED (not in HEAD)
#         | branch-DELETED (absent from HEAD, the status-git-mv shape)

## B) the proposed per-disposition snippet, on a tasks/-shaped tree


## finding
- FORM A (current recipe, 'checkout HEAD -- <all>'): errors on 2 of 4 paths and restores
  NOTHING — an unmatched pathspec ABORTS the whole operation, so the bounded retry runs
  on the fully dirty tree. This reproduces the #2087 symptom.
- FORM B (the filed fix, 'restore --staged --worktree -- <all>'): accepts the staged-ADDED
  path but still errors on the branch-DELETED path and still restores NOTHING. It narrows
  the failing set; it does NOT fix the failure mode.
- FORM C / the proposed snippet (per-disposition: in-HEAD -> restore, absent-from-HEAD ->
  drop): rc=0, 'git status' empty, 'git diff HEAD' empty, no residual litter.
=> Per-disposition is load-bearing; the verb alone is not.
