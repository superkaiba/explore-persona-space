# Plan v2 — #2140 daemon-liveness pass (watcher)

`kind: infra` workflow-fix. Target: `scripts/autonomous_session_watch.py`.
Zero GPU. One new ESCALATE-ONLY watcher pass + tests + docs.

## Requirement

A Happy-daemon outage silently disables every autonomous spawn lane. On
2026-08-04T21:13Z → 2026-08-05T04:30Z (**3h17m**) `~/.happy/daemon.state.json`
was absent, `_daemon_reachable()` returned False on every tick, and the
watcher logged only stdout lines (`respawn: Happy daemon unreachable;
skipping …`). Crash-recovery respawns, infra-drain, proposed-infra-sweep,
capacity-retry, boot-death, idle-unmapped, stale-registration and
no-progress-respawn all no-oped with **no push, no sidecar row, no marker**.
Detection came from a human opening a PM session at 22:48Z; recovery was
manual.

**Requirement:** the watcher must make a daemon outage LOUD on its own — an
episode-scoped escalation on the same tick the spawn lanes start skipping,
plus a durable per-episode record — without ever restarting the daemon
autonomously in v1.

### What exists today (verified, Step 1 clarifier)

- `_daemon_reachable()` `:14371` — POSTs `/list` to the daemon control port,
  10s timeout, returns False on every failure class.
- `_daemon_reachable_with_retry()` `:14438` — 3 attempts, 5s/10s backoff;
  called ONCE per tick in `main()` at `:35727`.
- `decide_daemon_blocked_escalation()` `:3310` (#845c / incident #811) — the
  ONLY existing daemon-outage escalation. Fires **only** for an
  already-`alerted`, ACTIVE, non-`manual`, still-`stale` session whose respawn
  is deferred. It needs a stalled session to exist first, so an outage with no
  respawn-worthy stall — exactly the #2140 window — escalates nothing.
- Every other daemon-gated lane emits a bare `print` (`:35744`, `:33113`,
  `:32517`, …).
- No `~/.eps-autonomous/daemon-*` state and no `.claude/cache/daemon-*`
  sidecar exist. No prior task built this (#1028 / #1071 / #1853 are
  alive-but-stalled and undispatched-infra work).

## Acceptance criteria

1. `daemon_liveness_pass` exists, runs on EVERY tick (both daemon states),
   and is called from `main()`'s production run order after the tick's single
   daemon probe.
2. On the **2nd consecutive** unreachable tick (~20 min at the 10-min cron):
   ONE `_telegram_push` + ONE sidecar row opening the episode.
3. During a persisting outage: a re-alert push + sidecar row every
   `EPM_DAEMON_LIVENESS_REALERT_MIN` (default 60 min) — the #2140 window
   (3h17m ≈ 20 ticks) yields ~4 alerts, not 20.
4. On the first reachable tick after an escalated episode: ONE recovery
   sidecar row + push naming the measured outage duration; state resets.
5. The alert is ACTIONABLE: it names the suppressed-work counts (autonomous
   registrations + ripe infra-queue depth) and the exact login-shell recovery
   command.
6. **ESCALATE-ONLY is a hard invariant:** the pass never restarts the daemon,
   never stops/spawns a session, never posts a task marker, never mutates task
   status. Pinned by test.
7. Kill switch `EPM_DISABLE_DAEMON_LIVENESS_PASS=1`; `--daemon-liveness-only`
   debug entrypoint; `--dry-run` writes nothing.
8. `uv run python scripts/workflow_lint.py` passes (the docstring pass-count
   check must stay green — see §Docstring).
9. New test file passes; the existing watcher suite stays green.

## Method delta

Modeled architecturally on `root_draft_pass` `:7604` — the simplest
escalate-only sibling: one pure `decide_*` predicate + singleton state
(atomic tmp+rename) + dedicated JSONL sidecar + fail-soft `_telegram_push` +
a top-level `except Exception` so an internal error never takes down the tick.

Deltas from `root_draft_pass`:
- **Input is the tick's already-computed `daemon_reachable`**, threaded as a
  kwarg — NOT a fresh probe (no extra cost, and the pass must agree with the
  value the spawn lanes actually gated on this tick).
- **Episode-scoped, not path-scoped** dedup state (one singleton, no
  per-issue GC).
- **A recovery/close event** (root-draft has no close semantics).

Deliberately NOT reused: `decide_daemon_blocked_escalation` stays untouched —
it is per-issue, stall-conditioned, and its counter lives on
`stalled-<N>.json`. This pass is fleet-level and stall-independent. Both may
push during one outage (bounded: one per issue-episode there, one per
fleet-episode + hourly re-alerts here) — accepted, and the two texts are
distinguishable.

### Restart arm: NOT in v1 (resolves the body's `unverified hypothesis`)

The body flagged "whether an unattended daemon restart is safe" for plan-time
verification. Probed: the daemon is a manually-started orphaned node process
(`node …/happy/dist/index.mjs daemon start-sync`, pid 201205, started
2026-08-04 21:30 local = the manual recovery that ended this outage) and there
is **NO systemd unit**. A non-interactive start path exists
(`happy daemon start`, detached), but a cron-context restart is unsafe for two
independent reasons:

- **#1466 tmux split-brain.** Per `.claude/rules/background-automation.md`
  § tmux socket-dir contract item 6, daemon durability hinges on starting from
  a LOGIN shell so `~/.profile` sources `scripts/eps_tmux_env.sh` and
  `TMUX_TMPDIR` resolves to the fleet's single tmux server. The watcher cron
  env does not source the profile, so a cron-started daemon risks spawning
  sessions onto a second tmux server (39 sessions went invisible to `tmux ls`
  in #1466).
- **Probe-false ≠ process-dead.** `_daemon_reachable()` returns False for a
  HUNG-but-alive daemon (that is its documented conservative contract), so an
  unguarded start would double-daemon.

v1 therefore takes the body's own stated fallback ("if unsafe, the arm should
escalate loudly … rather than restart"). A restart arm, if ever added, is a
separate opt-in task: login-shell-invoked, gated on positive proof the
recorded `daemon.state.json` pid is gone, with a per-day cap.

State shape (every field re-validated with `isinstance` in the predicate):

```json
{"consecutive_unreachable": 0, "episode_open_ts": null,
 "last_push_ts": null, "escalated": false}
```

**(c) Pure predicate** (unit-testable, no IO):

```python
def decide_daemon_liveness_escalation(
    *, daemon_reachable: bool, state: dict, now: float,
    threshold: int = DAEMON_LIVENESS_THRESHOLD, realert_s: float,
) -> tuple[dict, str | None]:
```

Returns `(new_state, event)` where `event ∈ {None, "open", "realert",
"recovered"}`:
- `daemon_reachable` and `escalated` → `("recovered")`, state reset to zeros
  (the caller reads `episode_open_ts` off the OLD state for the duration).
- `daemon_reachable` and not `escalated` → reset, `None` (a single flapped
  tick below threshold leaves no trace — matching the retry helper's intent).
- not reachable → `consecutive += 1`; `"open"` exactly when
  `consecutive == threshold` (first crossing) and not `escalated`;
  `"realert"` when `escalated` and `now - last_push_ts >= realert_s`;
  else `None`. `episode_open_ts` is stamped at the first unreachable tick
  (so the reported duration covers the whole outage, not just the escalated
  part); `last_push_ts` updates on `open`/`realert` only.

Fail-safe direction: a garbled/absent state reads as `consecutive=0,
escalated=False`, so the worst case is ONE delayed escalation (~10 min), never
a spurious one.

**(d) Suppressed-work enrichment** — `_daemon_liveness_suppressed_work()`:
count `AUTONOMOUS_REGISTRY_DIR.glob("issue-*.json")` (autonomous sessions
whose crash-recovery is currently disabled) and the `ripe_oldest_first` length
from `~/.eps-autonomous/infra-drain-queue.json`. Each read wrapped
independently; any failure yields `None` for that field and the push renders
`?`. Never raises, never blocks the push.

**(e) The pass:**

```python
def daemon_liveness_pass(dry_run: bool, *, daemon_reachable: bool) -> bool:
```

Same skeleton as `root_draft_pass`: kill-switch early return → `try:` →
load state → predicate → emit (print + sidecar + push) → save state if
changed → `except Exception` fail-soft. Push texts:

- open/realert: `Happy daemon UNREACHABLE for <H>h<M>m (<n> consecutive
  watcher ticks). Every autonomous spawn lane is no-oping: <R> registered
  autonomous session(s) unwatched, <Q> ripe infra task(s) undispatched.
  Recovery (login shell, so the #1466 tmux shim applies):
  bash -lc 'happy daemon status; happy daemon start'. Watcher never restarts
  the daemon itself.`
- recovered: `Happy daemon reachable again after <H>h<M>m; spawn lanes
  re-armed this tick.`

**(f) `main()` wiring** — immediately after the tick's probe block
(`daemon_reachable = _daemon_reachable_with_retry()` + `live_ids`, `:35727`)
and BEFORE `auth_outage_pass`, so the outage is recorded before any
suppression logic and on the same tick the respawn branch skips:

```python
daemon_liveness_pass(args.dry_run, daemon_reachable=daemon_reachable)
```

**(g) `--daemon-liveness-only`** — argparse flag + an early-return branch in
the `--*-only` block (mirroring `--root-draft-only` at `:35382`), using the
bare `_daemon_reachable()` probe like the other `--only` paths.

### 2. `tests/test_autonomous_session_watch_daemon_liveness.py` (new)

- Predicate table: below-threshold silence; `open` fires exactly once at
  the threshold; no second `open`; `realert` fires at the TTL boundary and
  not before; `recovered` fires once then state is clean; a reachable tick
  below threshold leaves no event; garbled state → safe defaults.
- Duration arithmetic: `episode_open_ts` stamped at the FIRST unreachable
  tick (a 20-tick outage reports ~3h+, not ~20 min).
- **`test_daemon_liveness_pass_never_restarts_or_mutates`** — the
  escalate-only invariant: monkeypatch `subprocess.run`/`Popen`,
  `_stop_session`, the spawn helper and `task.py post-marker` to raise, run
  the pass through an outage → recovery cycle, assert it completes and none
  fired.
- Kill switch: `EPM_DISABLE_DAEMON_LIVENESS_PASS=1` → no state write, no
  sidecar, no push.
- `test_daemon_liveness_pass_dry_run_writes_nothing` — the dry-run
  kwarg thread: calling the pass with `dry_run=True` through a full
  outage→recovery cycle performs ZERO writes (the state path and the sidecar
  path are both still absent afterward) and fires no push, so the
  `--daemon-liveness-only --dry-run` live smoke can never mutate fleet state.
- Enrichment fail-soft: unreadable queue file → `?` in the push, no raise.
