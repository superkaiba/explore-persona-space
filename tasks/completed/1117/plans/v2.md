```python
def _count_overlong_takeaways_bullets(takeaways: str) -> tuple[int, int]:
    """Count top-level Takeaways bullets over the per-bullet word caps
    (fence-aware). Returns ``(over_warn, over_fail)``: bullets over the
    30-word WARN cap but under the >=100-word FAIL tier, and bullets at
    or over the FAIL tier. v3 reports the SUM as its WARN count
    (WARN-only, grandfathered); v4 FAILs the second bucket (#825).
    Helper for check 20."""
    in_fence = False
    over_warn = 0
    over_fail = 0
    for line in takeaways.splitlines():
        s = line.strip()
        if s.startswith("```") or s.startswith("~~~"):
            in_fence = not in_fence
            continue
        if in_fence:
            continue
        if re.match(r"^[-*]\s+\S", line):
            wc = len(re.sub(r"^[-*]\s+", "", line.strip()).split())
            if wc >= V4_TAKEAWAYS_BULLET_FAIL_WORDS:
                over_fail += 1
            elif wc > V3_TAKEAWAYS_BULLET_MAX_WORDS:
                over_warn += 1
    return over_warn, over_fail
```

Fence handling, bullet regex, and word-count expression are UNCHANGED — only the bucketing is new.

## 11. Decision Rationale

**Threshold `V4_TAKEAWAYS_BULLET_FAIL_WORDS = 100` (the one load-bearing value).**
- **What:** the per-bullet word count at/above which a v4 Takeaways bullet hard-FAILs (`>=`, so 100 FAILs and 99 WARNs).
- **Why 100:** the WARN tier is 30 words (SPEC.md L729); the only existing hard cap, 180 words, governs a whole `### <result>` prose BLOCK, whose soft cap is 120 — so a single bullet approaching the block-level soft cap is unambiguously a paragraph, not a bullet. 100 ≈ 3.3× the WARN cap: it separates mild overrun from accretion with margin on both sides. Empirically (fact-checked live-tree scan, §2): the accretion tail is 102-215 words (7 bullets across 3 bodies; the originating #825 bullets ran to 263 before its critique round fixed them), while the 31-91 band holds 90 bullets of ordinary overrun and the 92-101 band is empty — 100 splits the two populations with clean separation on both sides. The 99-word boundary case is exercised synthetically by test (c).
- **Source:** task #1117 `origin_prompt` (clean-result-critic prose candidate on #825 r1, which proposed ≥100) + the §2 live-body scan validating the separation on real data.
- **Alternatives:** 60 (2× WARN) — rejected: 30 live bullets ≥60; legitimate numbers+CI+caveat bullets routinely hit 40-80 words, so a 60 FAIL converts a large WARN population into churn. 150 or 180 (symmetry with the per-result FAIL) — rejected: leaves 102-134-word paragraph-bullets (5 of the 7 live offenders) riding a WARN, defeating the Goal; and 180 conflates a block-level cap with a bullet-level one.

Message wording, comment text, and test names are NOT load-bearing (implementer's discretion within the shapes in §4).
