<h1>Issue #768 — Gate handler for <code>pv_phase1_done</code></h1>
<p><strong>kind: infra · workflow-fix · 0 GPU-hours · architectural: false</strong></p>
<p>This is a workflow-surface edit, not an experiment. I'm adding one new entry to the list of "what the orchestrator does when the experiment pod pauses and asks for help." Right now there's a handler for a pause called <code>fact-candidates</code> (which stops and waits for the user to pick something), plus a fall-through that treats any unknown pause as a hard error. Issue #763's experiment introduces a new pause named <code>pv_phase1_done</code> that means "the GPU half of phase 1 is done — now run the expensive judging step somewhere cheaper, then start the GPU back up and keep going." Without a handler, #763's real run would hit that pause, fail to recognize it, and stop with an error. I'm writing the handler so the orchestrator instead automatically pauses the GPU, runs the judge on the cheap always-on machine, restarts the GPU, relaunches the rest of the job, and keeps watching — no human in the loop.</p>
</section>

<p><strong>Handler semantics:</strong> on <code>status=gate</code>/<code>gate=pv_phase1_done</code>, the orchestrator AUTO-RESOLVES (no user, no park, no cron-teardown): (1) <code>pod.py stop --issue &lt;N&gt;</code>; (2) on the VM <code>uv run python scripts/issue763_extract_pv_rb.py --phase judge</code> (off-pod, <code>eval.batch_judge</code> deadline-bounded poll, fetches rollouts from HF, uploads keep-flags to HF); (3) <code>pod.py resume --issue &lt;N&gt;</code>; (4) re-dispatch <code>bash scripts/issue763_dispatch.sh --from-phase pv_capture</code> via the Step 6d.1 experimenter pattern (fresh <code>epm:run-launched</code>); (5) RESUME the bg-Bash polling loop in this same turn.</p>
<p><strong>Contrast (load-bearing):</strong> <code>fact-candidates</code> parks for a user answer and tears the cron down; <code>pv_phase1_done</code> auto-resolves and keeps polling. The handler text states this contrast explicitly and the section tail is made conditional on the gate's resolve mode.</p>
<p><strong>No change to:</strong> <code>scripts/poll_pipeline.py</code> (its <code>_drain_sentinels</code> generic gate path already surfaces any <code>blocks_pipeline: True</code> gate name — verified against <code>tests/test_poll_pipeline_sentinels.py</code>), <code>scripts/pod.py</code>, <code>scripts/issue763_*</code> (already shipped on <code>issue-763</code>).</p>
