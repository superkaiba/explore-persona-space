## 2. Method delta (what differs from prior related work, and why no new tool)

Per CLAUDE.md § "Reuse existing in-repo tools/helpers", the search ran BEFORE
any file was written. Three facts redirect the task body's implied approach:

1. **The target file moved.** #2155 split the step bodies into
   `.claude/skills/issue/steps/`. The Step 5 dispatch site is
   `steps/09-step-5.md` (1855 lines; `5a. Spawn both reviewers in parallel` at
   line 204). `SKILL.md` keeps only the heading + a `> **Full procedure:**`
   pointer. The body's `workflow_fix_target:` line predates the split.
2. **A mechanical pre-dispatch guard is ALREADY WIRED at this exact site.**
   `steps/09-step-5.md:13-29` ("Pre-split completeness guard", #2158) runs ONE
   Bash call — `uv run python scripts/pre_split_review_guard.py <N>` — "Before
   ANY reviewer dispatch this round", read-only, one lead-token line, exit
   0/2/3, backed by `task_workflow.pre_split_review_gate`
   (`src/explore_persona_space/task_workflow.py:2170`). So the correct change is
   a new ARM on that guard, NOT a second script: zero new call sites, zero
   added orchestrator prose burden, one Bash call unchanged.
3. **The predicate is already computed and thrown away.**
   `pre_split_review_gate` tracks `impl_index` (the events index of the latest
   implementation-class marker, from the adjacent
   `_IMPLEMENTATION_MARKER_KINDS` frozenset at line 2167) and already RETURNS
   it in its result dict. `impl_index is None` means "no implementation marker
   anywhere" — precisely the #2290 condition. The fix reads a value the gate
   already has.

**Why the hole is provably narrow.** Inside `pre_split_review_gate`, the
liveness helper is `_live(idx) = idx is not None and (impl_index is None or idx
> impl_index)`. So if ANY pre-split signal index exists while `impl_index is
None`, that signal is necessarily live and the gate returns
`PRE-SPLIT-INCOMPLETE` / `BREADCRUMB-UNPARSEABLE`. Therefore within the
`REVIEW-OK` return path, `impl_index is None` can only co-occur with the FIRST
reason branch (`breadcrumb_index is None and unit_dispatch_index is None` →
`"no pre-split signals in events"`). The second REVIEW-OK reason branch
("implementation marker at events index N postdates …") structurally implies
`impl_index is not None`. Consequence: the new arm can only ever convert
exit 0 → exit 4 on inputs with no pre-split signals AND no implementer marker.
A3 holds by construction, not by testing luck.

**Method delta vs #2158.** #2158 added the guard for MID-SPLIT rounds (a round
whose remaining units were never implemented). This adds the degenerate
sibling: a round whose implementer report was never TRANSCRIBED into canonical
state at all. Same site, same call, same read-only posture, new verdict.

## 3. Design decision: presence-only hard-fail (and the declined stronger form)

**Chosen predicate: PRESENCE.** Hard-fail iff `impl_index is None`.

**Declined: "the implementer marker must POSTDATE the latest `epm:code-review`
marker"** (i.e. a fresh implementer report for THIS round). It is strictly
stronger — it would also catch a round-2 review dispatched with no new
implementer round — and it is DECLINED on fleet-safety grounds:

- This guard runs on EVERY review dispatch, fleet-wide. A false FAIL wedges
  every concurrent `/issue` session (the #1388 lesson: the no-flags lint IS
  the Step 9c gate; a fleet-wide gate that fails wrongly wedges everything).
- Legitimate same-round re-dispatches with NO new implementer marker exist and
  are documented: the killed-Codex-wrapper `--reattach` recovery
  (`.claude/rules/codex-ensemble-review.md`), a confirmed twin no-show
  single-Claude round, and reconciler re-runs. A postdates predicate
  false-FAILs all three.
- Presence-only has a ZERO false-positive surface (a task with no
  implementation marker has no round to review, unconditionally) and covers
  the reported incident exactly (#2290 round 1: 12 rows, zero `epm:results`).

Also declined: emitting the staleness case as advisory text inside the
REVIEW-OK reason string. Zero-risk but it widens the diff and the round-2 gap
is not the filed defect. Recorded here so the decision is auditable rather
than invisible; a future task may revisit it with the re-dispatch cases
enumerated.
