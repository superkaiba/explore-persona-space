#: bounded wait-for-capacity loop reached its per-process wall-clock budget

#: _GPU_VOLUME_FLOOR_GB note above). Parity pinned by

### Step 2 — the rung branch (`src/explore_persona_space/backends/router.py`)

(a) Add `import subprocess` to the module-top stdlib import block (~L191-196), in the SAME edit as its first usage (the PostToolUse ruff strips unused imports).

(b) Extend the existing lazy import at ~L3236 and insert the branch AFTER the #954 partial-handle block (after the `raise` at ~L3297), BEFORE the catch-all `attempts.append` at ~L3303:

```python
            from explore_persona_space.backends.runpod import (
                EXIT_STILL_WAITING,
                RunPodWorkloadStartError,
            )
            ...
            # Exit-75 still-waiting (#1603, incident #1586): pod_lifecycle's
            # bounded wait-for-capacity loop reached its per-process budget —
            # NOTHING provisioned, NOTHING billing; the contract is "re-run
            # the same command to continue waiting" (state-free wait,
            # pod_lifecycle._emit_still_waiting_and_exit). NOT a failure: do
            # NOT post the terminal failure marker (the orchestrator would
            # post epm:failure + set-status blocked — the #1586 mis-park) and
            # do NOT collapse into NoComputeAvailableError. Re-raise verbatim
            # — returncode + cmd + stderr tail ride the exception (the #1465
            # relay preserved them for exactly this consumer) — so the sync
            # producer contract (dispatch_issue._provision_still_waiting →
            # exit 75, still_waiting: true + rerun: true) covers the terminal
            # rung exactly as it covers the explicit `backend: runpod`
            # override. The ASYNC wrapper
            # (failover_to_runpod_after_async_workload_crash) converts this
            # to NoComputeAvailableError so the poller's terminal contract is
            # byte-unchanged.
            if (
                isinstance(exc, subprocess.CalledProcessError)
                and exc.returncode == EXIT_STILL_WAITING
            ):
                attempts.append(
                    RouteAttempt(
                        kind="runpod",
                        cluster=None,
                        est_start_seconds_raw=0.0,
                        est_start_seconds_clamped=0.0,
                        outcome="runpod_still_waiting",
                        detail=(
                            "runpod terminal rung STILL WAITING for capacity "
                            f"(pod_lifecycle exit {EXIT_STILL_WAITING}: wait-for-capacity "
                            "budget reached; nothing provisioned, nothing billing; "
                            "re-run the same launch command to continue waiting)"
                        ),
                        elapsed_seconds=now_fn() - started_at,
                    )
                )
                logger.warning(
                    "route: runpod terminal rung still WAITING for capacity on "
                    "issue %d (exit-%d still-waiting contract, #1603; NOT a "
                    "failure — re-run the same launch command).",
                    spec.issue,
                    EXIT_STILL_WAITING,
                )
                raise
```

The re-raise exits the `with store.transaction(spec.issue)` block, releasing the per-issue flock; no lease is written (nothing launched), so the M3b in-flock re-check semantics on a later re-run are unchanged.

### Step 3 — the async wrapper conversion (`router.py`, `failover_to_runpod_after_async_workload_crash`, ~L3439-3476)

Hoist the inline `attempts=[]` to a named local and wrap the rung call:

```python
    attempts: list[RouteAttempt] = []
    try:
        return _runpod_terminal_rung(
            spec=replace(spec, backend="runpod"),
            ...,
            attempts=attempts,
            ...,
        )
    except subprocess.CalledProcessError as exc:
        from explore_persona_space.backends.runpod import EXIT_STILL_WAITING

        if exc.returncode != EXIT_STILL_WAITING:
            raise
        # Exit-75 still-waiting on an ASYNC failover leg (#1603): no
        # orchestrator re-runs "the same command" here — the poller owns a
        # bounded tick — so surface the typed capacity terminal the poller
        # already maps (reason: no_compute_available, re-drivable by the
        # watcher's capacity-retry pass). The #1596/#1601 queue-loss legs'
        # clean-residue GCP-STANDARD retry gates on this same type, and an
        # exit-75 IS a clean-residue capacity outcome by construction
        # (nothing provisioned, nothing billing).
        _post_terminal_failure_marker(
            spec=spec,
            marker_poster=marker_poster,
            reason=ROUTE_REASON_NO_COMPUTE,
            chosen_kind="runpod",
            attempts=attempts,
        )
        raise NoComputeAvailableError(
            "runpod async-failover leg still WAITING for capacity when the "
            f"wait-for-capacity budget expired (pod_lifecycle exit "
            f"{EXIT_STILL_WAITING}: nothing provisioned, nothing billing); "
            "surfaced as the re-drivable no-compute terminal for the poller",
            attempts=[_attempt_to_dict(a) for a in attempts],
        ) from exc
```

The `attempts` list carries the rung's `runpod_still_waiting` row (appended before the re-raise), and `from exc` preserves the `__cause__` chain backend_poll's residue-snapshot diagnostics read (`backend_poll.py:3763`). Keep the wrapper's defensive `raise` on rc≠75 even though it is currently unreachable (the rung converts every non-75 `CalledProcessError` to `NoComputeAvailableError` before the wrapper sees it) — cheap insurance against future rung edits (round-1 Methodology note).

### Step 4 — escalation-semantics decision (explicit, per the brief)

- **Sync path: exit-75 does NOT directly arm the #1596/#1601 GCP-STANDARD retry legs.** It propagates as still-waiting; the orchestrator's re-run re-enters `route()` from the top, so GCP is naturally re-probed each cycle under the existing `MAX_GCP_ATTEMPTS_PER_DAY=16` cap; once the cap is consumed, re-runs skip GCP creates and go straight back to the RunPod wait — matching the #1586 directive ("just run on runpod").
- **Async legs: exit-75 REMAINS eligible for the GCP on-demand retry, byte-identically to today** — the wrapper's conversion is a `NoComputeAvailableError` with clean residue (nothing provisioned), which is exactly the gate #1596/#1601 fire on (`backend_poll._classify_provision_failure_evidence` already special-cases `returncode == 75` → created-nothing, backend_poll.py:3048-3060). No behavior change, deliberately.
- **Re-affirmed against the corrected #1586 trace (round-1 revise):** the incident's dominant leg — the 17:05Z queue-vanish park — is exactly this async shape and RECURS under this fix. Accepted deliberately: the poller owns a bounded tick (no one re-runs "the same command" there), an async still-waiting re-drive would touch `backend_poll.py` (§10 Must-ask fence), and the watcher capacity-retry remains that leg's recovery. Extending still-waiting re-drive to the async legs is a NAMED out-of-scope follow-up candidate — logged on the task under the wf-fix recursion guard (parked, never auto-filed by this session) — not silent scope creep. Corollary: the §1 latency-improvement claim holds in the sync create-failure regime while a session drives the launch (Step 6b loop / `--auto` crash-recovery respawn); on a #1586-class day a sync re-run can also end in a SUCCESSFUL flex-start create whose later queue-loss routes through the async legs — that park class is this residual, not a regression of this fix.
