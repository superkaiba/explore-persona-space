## 4. Design

Why code, not a model call: a lint is a deterministic mechanical gate; an LLM reviewer already missed this class six times (the task's founding incident).

### 4.1 Target-set scoping (task question 1) — import/definition-resolved arming

The check fires only on calls that RESOLVE to the two hub helpers; a same-named local helper never arms. Two-pass, per file:

**Pass 1 — binding collection** (single `ast.walk` over the `_cached_parse` tree; read-only):

- `hub_name_bindings: dict[str, str]` — alias → target name, from every `ast.ImportFrom` with `module == "explore_persona_space.orchestrate.hub"` whose alias name is in `{"_upload", "_upload_folder_filtered"}` (binding key = `alias.asname or alias.name`). `ast.walk` covers **function-local imports** — load-bearing: `issue2054_capture.py:914` and `issue1689_capture.py:401` both import inside a function.
- `hub_module_aliases: set[str]` — from `ast.ImportFrom(module="explore_persona_space.orchestrate")` with an alias named `hub` (key = asname or `"hub"`), and `ast.Import` of `explore_persona_space.orchestrate.hub` WITH an asname. (A bare `import explore_persona_space.orchestrate.hub` binds the top package and produces a 3-deep dotted attribute chain at the call site — out of scope v1, documented in the docstring; zero such call sites found under `scripts/` at plan time.)
- `shadow_disarm: set[str]` — any `FunctionDef` / `AsyncFunctionDef` named `_upload` or `_upload_folder_filtered` anywhere in the tree, plus any `ast.Assign` / `ast.AnnAssign` whose target is a bare `Name` with one of those ids (a `_upload = partial(...)` rebinding). A shadowed name DISARMS the Name form for that file (conservative: prefer a false negative over firing on an unread local contract).

**Pass 2 — firing rule**: for every `ast.Expr` statement node, let `v = node.value`; if `isinstance(v, ast.Await)`, unwrap once (`v = v.value` — awaited discards are in scope; hub helpers are sync today, so this is future-proofing, cost = one isinstance). If `isinstance(v, ast.Call)`:

- **Name form**: `v.func` is a `Name` whose id is in `hub_name_bindings` and NOT in `shadow_disarm` → finding.
- **Attribute form**: `v.func` is an `Attribute` whose `attr` is in the target set and whose `value` is a `Name` with id in `hub_module_aliases` → finding.

Chosen over the rejected alternative (bare-name matching, `check_upload_as_file`'s looser convention: any Name/Attribute whose tail is `_upload`): bare-name matching false-fires on the three fail-LOUD local `_upload` helpers classified in §2 (1481 raises on empty return; 825/952 raise via huggingface_hub) — for a *discard* check, discarding a fail-loud helper's return is the NORM, so the looser rule is systematically wrong here even though it is safe for `check_upload_as_file`'s file/folder-shape property. Hub-helper-only-by-hardcoded-filename was also rejected: it cannot see attribute-form calls (`hub._upload_folder_filtered(...)`, e.g. `issue1112_rankem_dispatch.py:1280`) or aliased imports.

**`raise_on_error=True` calls still fire** (e.g. `issue1310_recapture_script_store.py:272`): per the hub docstring the non-exception `""` returns (missing token / absent path / failed verify) are unchanged, so the discard still hides three failure shapes. The waiver is the escape for a caller that has genuinely accepted those. (Decision explicitly surfaced for the critic.)

### 4.2 Detection precision (task question 5)

MUST fire:
- Bare `ast.Expr` whose value is an armed `Call`, Name form (`_upload_folder_filtered(...)` after a hub from-import).
- Same, Attribute form (`hub._upload(...)` after a hub module import), incl. aliased (`from … import hub as H; H._upload(...)`).
- The same discard **inside a `try:` block, regardless of what the `except` does** — justified: these helpers communicate failure by RETURN, not exception, so an except-clause (re-raising or not) never observes the failure; the discard is exactly as silent inside a try as outside.
- An `await`ed armed call whose result is discarded (unwrap rule above).

Must NOT fire (all excluded by construction — a consumed return means the Call is not the direct value of an Expr statement): assignment (`url = _upload(...)` — including `_ = _upload(...)`, task-directed; noted as a deliberate, greppable evasion shape in §8), walrus, `return` / `yield`, `if`/`assert`/`while` conditions, arguments to other calls, f-string / `raise` arguments, comprehension elements, boolean/comparison operands. Also not fired v1: a Call nested inside a tuple-expression statement (`(_upload(...), other())`) — the Call is not the Expr's direct value; rare, documented.

### 4.3 Waiver mechanism (task question 3) — house convention, byte-mirrored

- Token: `# UPLOAD_RETURN_DISCARD_EXEMPT: <reason>` (naming pattern of `UPLOAD_AS_FILE_EXEMPT` / `UPLOAD_LOOP_EXEMPT` / `UPLOAD_PREFIX_EXEMPT`; the candidate sketch's `# lint: upload-fail-soft-ok` is rejected — house convention wins).
- Regex: `UPLOAD_RETURN_DISCARD_WAIVER_RE = re.compile(r"#\s*UPLOAD_RETURN_DISCARD_EXEMPT\s*:\s*(.+?)\s*$")`; floor `UPLOAD_RETURN_DISCARD_WAIVER_MIN_REASON_CHARS = 10`.
- Placement semantics: accepted on the call's **first physical line** (`node.lineno`, 1-based) or the **immediately preceding non-blank line** — helper `_upload_return_discard_waiver_present(lines, call_lineno)` mirroring `_upload_as_file_waiver_present` (:5376) line for line.

### 4.4 Residual-offender disposition (task question 2) — timing-insensitive by construction

**Chosen: count-grain grandfather dict with ≤-tolerant CHECK semantics (the `UPLOAD_FILE_IN_LOOP` precedent, verbatim) + a split-semantics load-bearing TEST.**

- `UPLOAD_RETURN_DISCARD_LEGACY_ALLOWLIST: dict[str, int]` — repo-root-relative posix path → grandfathered site count. Check gate copied from :5867-5880: findings suppressed while `count <= allowed`; `count > allowed` reports the excess header + ALL of the file's findings (a NEW discard in a grandfathered file always surfaces). **≤ means a count DROP (a fix landing) is silently fine at check level — main stays green the moment #2054's fix merges, in either order.**
- `UPLOAD_RETURN_DISCARD_PENDING_OWNER: frozenset[str]` — the subset of allowlist paths owned by a task with a LIVE in-flight session at implementation time (today: the `scripts/issue2054_*.py` files; generalized to any live-owned file the enumeration surfaces, checked against `spawn_session.py list` at implementation time). Each entry carries an inline comment naming the owner + retirement trigger (e.g. `# owned by in-flight #2054 (open concern upload-return-discard-sibling-scripts); its fix retires this entry`).
- Load-bearing test (`test_check_upload_return_discard_allowlist_load_bearing`): with `legacy_allowlist={}` on the real tree, **stable entries** (not in PENDING_OWNER) assert EXACT per-file counts (the anti-vacuity pin, house pattern `tests/test_workflow_lint.py:4628`); **PENDING_OWNER entries** assert `observed <= pinned` only. So the test is green before AND after #2054's fix merges; a stale PENDING_OWNER entry (count 0) is retired by a later lint-touching round, tracked by the inline comments (the `check_upload_prefix_clobber` "fixing retires its entry" convention).

Rejected alternatives, each with its failure mode:
1. **FAIL-on-stale exact pin for all entries** (the `AGENT_SPEC_SIZE_GRANDFATHER:12176` / `SHA_PIN_DOMAIN:13118` posture): goes RED fleet-wide at every Step 9c the moment #2054's r11 fix merges (its branch already carries `url = _upload_folder_filtered(...)` conversions in phase_a — verified by worktree diff). The #1145/#931 class inverted.
2. **Waiver comments in the #2054 files**: requires editing `scripts/issue2054_*.py` — races the live round-11 implementer that owns that file set (CLAUDE.md § Teammate coordination, "ONE implementer per file set"; the #1112 duplicate-work incident class). Banned by the task's hard constraints.
3. **Skip-pattern exclusion of `scripts/issue2054_*.py`**: timing-insensitive but strictly worse than ≤-counts — it also exempts UNLIMITED future discards in those files, and lingers with no count to retire against.
4. **Fixing the 6-8 #2054 sites ourselves**: same live-owner race as (2), plus duplicate work — #2054's branch has already fixed at least the phase_a sites.
5. **Omitting the #2054 sites with NO allowlist entry**: the check would FAIL on them whenever this task merges first — red on main until #2054 lands. Not timing-insensitive.

**No source edits to any `scripts/issue*_*.py` in this round — grandfather-all posture for pre-existing offenders** (including the non-#2054 ones: `issue1689_capture.py:409` [task at `awaiting_promotion`], `issue1112_*` , `issue1310_*`, and whatever else the enumeration finds).
