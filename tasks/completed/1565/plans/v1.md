### 4.1 Refactor (behavior-preserving): extract the tracked-set probe and the text-mode row parser

```python
def _tracked_status_dirs(task_id: int, repo: Path) -> set[str]:
    """Repo-relative tasks/<status>/<id> dirs with >=1 file in the git INDEX.
    Extracted from _task_status_dir_pathspecs (#1565); one `git ls-files` call
    over exact per-STATUSES pathspecs (no wildcards)."""
    rel_tasks = tasks_dir().relative_to(repo)
    candidates = [str(rel_tasks / status / str(task_id)) for status in STATUSES]
    tracked = _run_git(["ls-files", "--", *candidates]).stdout.splitlines()
    n_parts = len(rel_tasks.parts) + 2  # <tasks>/<status>/<id>
    return {"/".join(p.split("/")[:n_parts]) for p in tracked if p.strip()}
```

`_task_status_dir_pathspecs` (:4209) becomes `sorted(_tracked_status_dirs(task_id, repo) | {c for c in candidates if (repo / c).is_dir()})` — byte-identical output (pinned by existing `set_status` ghost-sweep tests).

`_iter_jsonl(path)` (:4039) splits into `_iter_jsonl_text(text: str, *, source: str) -> list[dict]` (the tolerant `split("\n")` + `json.loads` loop, WARN naming `source`) and a thin `_iter_jsonl(path)` wrapper (`read_text(errors="replace")` → `_iter_jsonl_text`). Behavior identical (pinned by existing tolerant-reader tests). Plus:

```python
def _max_event_ts(rows: list[dict[str, Any]]) -> str:
    """Max ISO-8601Z ts across rows ('' when none) — lexicographic == chronological."""
    return max((r["ts"] for r in rows if isinstance(r.get("ts"), str)), default="")
```

### 4.2 The guard

```python
_APPEND_GUARD_SIDECAR_REL = ".claude/cache/append-guard-events.jsonl"

def _guarded_task_dir_for_append(task_id: int) -> tuple[Path, bool]:
    """find_task_path + stale-restored-state cross-check against the git index
    (#1565; incident #1524). Returns (task_dir, rerouted). Caller MUST hold
    _locked(). Fail-open on probe errors; StaleTaskPathError on ambiguous /
    doubly-corrupt states. All-validate-then-mutate: no destructive action
    before the re-route target is proven usable."""
    resolved = find_task_path(task_id)
    repo = repo_root()
    try:
        tracked = _tracked_status_dirs(task_id, repo)
    except (subprocess.CalledProcessError, OSError) as e:
        _log.warning("append-guard: git probe failed for task #%d (%s); appending unguarded",
                     task_id, e)
        return resolved, False                                   # fail-open
    rel_resolved = str(resolved.relative_to(repo))
    if not tracked or rel_resolved in tracked:
        return resolved, False       # fresh create (commit deferred, #1030) / normal
    if len(tracked) > 1:
        raise StaleTaskPathError(    # committed husk + resolved at a THIRD location: never guess
            f"task #{task_id}: resolved at {rel_resolved!r} (untracked) while the git "
            f"index tracks it at MULTIPLE status dirs {sorted(tracked)}; refusing to "
            f"append — run `task.py audit --repair --apply` / `task.py reap-husks`.")
    (target_rel,) = tracked
    try:
        blob = _run_git(["show", f":{target_rel}/events.jsonl"]).stdout
    except (subprocess.CalledProcessError, OSError) as e:
        _log.warning("append-guard: index blob read failed for %s (%s); appending unguarded",
                     target_rel, e)
        return resolved, False                                   # fail-open
    blob_max = _max_event_ts(_iter_jsonl_text(blob, source=f":{target_rel}/events.jsonl"))
    disk_max = _max_event_ts(_iter_jsonl(resolved / "events.jsonl"))  # '' if file missing
    if disk_max >= blob_max:
        _log.warning("append-guard: task #%d resolved at %s (untracked) while index tracks "
                     "%s, but resolved state is at-least-as-new (%r >= %r) — deferred-commit "
                     "shape, allowing", task_id, rel_resolved, target_rel, disk_max, blob_max)
        return resolved, False
    # ── VIOLATION: the #1524 stale-restore shape. Validate target FIRST. ──
    target = repo / target_rel
    if not (target / "events.jsonl").exists():
        raise StaleTaskPathError(
            f"task #{task_id}: index tracks {target_rel!r} but its events.jsonl is missing "
            f"on disk, and the resolved dir {rel_resolved!r} is a stale snapshot "
            f"(max ts {disk_max!r} < index {blob_max!r}); refusing to append to either — "
            f"restore first: `git checkout -- {target_rel}` then retry, "
            f"or `task.py audit --repair --apply`.")
    fm, _ = _read_body(target / "body.md")   # validates target body BEFORE any mutation
    stale_status = _status_from_path(resolved)
    quarantine = (LOCK_DIR / "stale-task-dirs" /
                  f"{_utcnow_iso().replace(':', '')}-task{task_id}-{stale_status}-{os.getpid()}")
    quarantine.parent.mkdir(parents=True, exist_ok=True)
    shutil.move(str(resolved), str(quarantine))
    reg = _load_registry()                    # mutation path, _locked() held: safe re-sync
    entry = reg["tasks"].get(str(task_id))
    if entry and entry.get("path") == rel_resolved:
        _registry_set(reg, task_id, target, fm)
        _save_registry(reg)
    _log.warning("append-guard: task #%d: STALE restored dir %s (max ts %r) shadowed the "
                 "index-tracked %s (max ts %r) — quarantined to %s, registry re-synced, "
                 "append re-routed (#1565; the #1524 husk shape)",
                 task_id, rel_resolved, disk_max, target_rel, blob_max, quarantine)
    try:                                      # fail-soft observability sidecar
        _append_jsonl_line(repo / _APPEND_GUARD_SIDECAR_REL, {
            "ts": _utcnow_iso(), "task_id": task_id, "stale_path": rel_resolved,
            "target_path": target_rel, "quarantine": str(quarantine),
            "disk_max_ts": disk_max, "blob_max_ts": blob_max})
    except OSError:
        _log.warning("append-guard: sidecar write failed (fail-soft)")
    return target, True
```

**The exact predicate**, stated precisely (brief question 2): *ALLOW* iff `tracked == ∅` (untracked-at-index everywhere ⇒ fresh create with deferred commit — the #1030 trap) OR `resolved ∈ tracked` (normal) OR (`resolved ∉ tracked` ∧ `|tracked| == 1` ∧ `max_ts(disk resolved events) ≥ max_ts(index blob of tracked events)`) (deferred/failed status-move commit — disk is ahead of git). *VIOLATION* (re-route) iff `resolved ∉ tracked` ∧ `|tracked| == 1` ∧ disk strictly older — possible only when the resolved file is MISSING rows the index has, i.e. a stale snapshot: any legit current file contains every row of any index blob of this task (append-only log; `shutil.move` in `set_status` carries the whole file). *RAISE* iff `resolved ∉ tracked` ∧ `|tracked| > 1` (committed husk, ambiguous target — mirror of `find_task_path`'s multi-hit rule), or violation with the target unusable on disk (blind `O_CREAT` at a tracked-but-missing path would commit a history-losing one-row file).

**Why quarantine rather than leave-in-place (load-bearing):** `set_status`'s ghost sweep runs `git add --all -- <specs>` where the specs include every ON-DISK `tasks/<status>/<id>` dir (:4412-4413, `_task_status_dir_pathspecs` :4230). A stale dir left on disk would be staged as ADDITIONS at the task's next transition — committing the husk anyway, one step later. Quarantine to `~/.task-workflow/stale-task-dirs/` (outside the repo, precedent `DEFERRED_COMMITS_LOG` :728-734) removes it from every git op's reach while preserving every row for forensics (the #1524 recovery had to hand-preserve a unique row — never delete).

### 4.3 Call-site wiring (3 sites; the guarded family = appends into an existing task dir)

Guard runs BEFORE `_next_event_version` (version derivation must read the correct file). Commit call (:4159): `[path, registry_path()] if rerouted else [path]`.
- **`append_comment` (:5982):** same substitution; commit paths likewise.
- **`_append_concern_event` (:6718):** `folder = find_task_path(task_id)` → guarded call (caller already holds `_locked()` per its docstring); its both-files commit gains `registry_path()` when rerouted.

## 5. Conditions and Controls — edge-case matrix

| Plain-English name | State (disk / registry / index) | Guard outcome | What it controls for |
|---|---|---|---|
| Normal append | resolved dir tracked in index | allow (no extra git call beyond ls-files) | baseline unchanged |
| #1524 stale restore | stale old-status dir + stale registry restored; index tracks newer status; disk file strictly older | re-route + quarantine + registry re-sync + WARN | the incident |
| Fresh create, commit deferred (#1030) | dir + registry exist; NOTHING tracked at index | allow | the big false-positive trap #1 |
| Deferred status move | disk+registry at NEW status (with newer status-changed row); index tracks OLD | allow (disk max-ts ≥ blob) | false-positive trap #2 — git lag ≠ stale disk |
| Restored-but-identical | old-status dir restored with content byte-equal to blob | allow (ts tie → `≥`) | conservative tie-break; no destructive act without strict evidence |
| Committed husk + resolved elsewhere | index tracks ≥2 status dirs, resolved at neither | raise `StaleTaskPathError` | never-guess (mirrors `find_task_path` :3854) |
| Doubly corrupt | violation shape but tracked target's events.jsonl missing on disk | raise BEFORE quarantine | no history-losing `O_CREAT`; no evidence destruction |
| Git probe fails | `_run_git` raises (unavailable, non-lock error post-retry) | allow + WARN (fail-open) | marker posting never breaks fleet-wide on git flakiness |
| Sidecar appends | paths outside `tasks/` | guard not invoked | scope containment |
| Crash-truncated tail on resolved file | last line unparseable | tolerant reader skips it; older parseable rows still give max-ts ≥ blob for legit states (truncation only affects the newest row) | #1367 interaction |

## 11. Decision Rationale

N/A — no model training

Design constants, each with Source:

1. **Cross-check surface = git INDEX (`git ls-files` / `git show :<path>`), not HEAD (`ls-tree`).** Why: the index is ≥ HEAD in freshness — a status move whose `git add` succeeded but commit failed reads CURRENT in the index, shrinking the mismatch branch to add-failed cases only; and it matches the module's existing probe. Source: task_workflow.py:4227 (`_task_status_dir_pathspecs` precedent), :4424-4432 (set_status's git-failure envelope). Alternative rejected: `git ls-tree HEAD` — strictly staler view, more false mismatches.
2. **Exact per-STATUSES pathspecs, one `ls-files` call.** Source: task_workflow.py:4215-4223 ("no fnmatch wildcards — exact-id matching only, so id 89 never sweeps id 898"; unmatched pathspecs silently ignored).
3. **Freshness discriminator = max event `ts`, strict `<` fires, `≥` allows.** Why: any legit current file is a row-superset of any index blob of the same task (append-only + whole-file `shutil.move` at :4346-4356), so max-ts(disk) ≥ max-ts(blob) legit-always; ISO-8601Z compares lexicographically (`_utcnow_iso` :3913). Alternative rejected: full row-subset comparison — more machinery for the same decision on every reachable state; row-count — not robust to the tolerant reader skipping a crash-truncated tail row.
4. **Fail-open on probe errors; fail-loud (`StaleTaskPathError`) only on ambiguity/double-corruption.** Why: post_event is the fleet's highest-frequency mutation — a git hiccup must degrade to today's behavior, never block marker posting; the never-guess raise mirrors the existing multi-hit rule. Source: task_workflow.py:3854-3860, :851-858; CLAUDE.md fail-fast rule (the raise cases are genuine corruption, not paper-over).
5. **Quarantine (move out of repo) rather than leave-in-place or delete.** Why: leave-in-place feeds `set_status`'s `git add --all` ghost sweep (:4412-4413) which would commit the husk at the next transition; delete destroys the forensic rows the #1524 recovery had to preserve. Location precedent: `LOCK_DIR` sidecars outside the repo (:728-734). Source: task_workflow.py:4396-4423; #1524 recovery record (clarifier note).
6. **Guard scope = the three append-into-existing-task sites; guard placement at resolution, not inside `_append_jsonl_line`.** Why: `_append_jsonl_line` is shared by `create` (legit new dir, :4530) and non-task sidecars (:5458, :6466, :6549) and has no `task_id` context; the resolution seam has both the context and the `_locked()` guarantee. Source: call-site audit in §4.3 (task_workflow.py:4155, :4394, :4530, :4973, :5155, :5458, :5998, :6466, :6549, :6720, :6742).
7. **Rejected: guard inside `find_task_path` (brief option b).** Reads (`list_events`, `get_task`, tick triage, dashboard) vastly outnumber mutations — a per-read subprocess is unacceptable, and the read path deliberately never mutates (no `_locked()`; :3818-3823) while the guard's healing arm must mutate. **Rejected: bare registry re-resolve under flock (the filing's literal ask)** — already done at :4140-4141; NO-OP against the incident (clarifier finding c). **Rejected: no-change (brief option d)** — every existing mitigation is post-hoc; the append is where the husk becomes durable and a deterministic cheap prevention exists.
8. **REGISTRY companion assert (brief question 3):** in scope only as the guard's violation-branch re-sync (mutation path, lock held — consistent with the :3818-3823 read-path prohibition and the :4273-4296 set_status re-sync precedent). No separate `set_status` assert: its existing re-sync + the guard's healing cover the reachable shapes.
