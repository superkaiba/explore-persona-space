## 3. Hypothesis

**H6 (TOP-RANKED, per #477's 09:55Z marker — plausibility HIGH):** the v4/v6 eval silently fails to apply the trained LoRA adapter at score time. The trained adapter on HF is real (B-matrix norm ~3.0); the production rig's vLLM `LoRARequest(lora_path=...)` call silently no-ops in the v4/v6 env, producing base-model logits scored as if trained ΔG ≈ 0. The proximal v2→v4 change is `frac_precision 2→4` (checkpoint dir naming) — the eval consumes a stale or path-mismatched adapter dir.

- **Prediction:** A0' Path A (clean PEFT) recovers ΔG ≈ 17 on the on-HF adapter.
- **Falsifier:** A0' PEFT path ALSO reads ΔG ≈ 0 on the same trained adapter on the same slice → the adapter is NOT applying via either framework → bug is in the training save, not the load.
- **Sub-branch:** if PEFT recovers ΔG ≈ 17 AND vLLM ALSO recovers ΔG ≈ 17, the floor reading on v4/v6 was a pod-env-specific regression, not a code regression.

**H1 (carried from plan v2 — plausibility MEDIUM, fires only if A0' falsifies H6):** v4's mid-training `save_pretrained` calls indirectly perturb the final trained model state. Mechanism: RNG drift, PEFT-version side effect, or cgroup/io-induced trainer-step delay.
- **Prediction:** if I retrain the v4 commit at `phase=calibration` (zero mid-saves) instead of `phase=step_calibration`, source ΔG returns to ~17.
- **Falsifier:** v4 commit + `phase=calibration` STILL floors.

**H2 (LOW for source-self, MEDIUM for bystander):** `--cell-specs 477` on the eval-side changes which adapter or which R is loaded. Almost certainly false for source-self (uses `bank[SOURCE_PERSONA]` directly); kept as a useful negative ablation.

**H3 (LOW-MEDIUM):** a stale on-disk checkpoint at the OLD precision (`frac_1.00`) is being LOADED by v4 eval that expects the NEW precision (`frac_1.0000`).
- **Prediction:** wiping `/workspace/runs/issue_477/c477_calib_negp_2_seed42_lr2e-06/` before the v4 retrain restores the saturating signal.

**H4 (LOW, cheapest sanity check):** the volume's `persona_bank.json` / `centroids/` / `on_policy_R/` artifacts were rewritten between v2 and v4. **Falsifier:** the v2-anchor cell A1 reproduces saturation on the rebuilt-from-HF artifacts.

**H5 (LOW):** the implant is genuinely fragile and v2's saturation was the regime drift, not a stable property. Tested only if A0 and A1 don't reproduce cleanly — then expand to multi-seed.

**Quantitative thresholds:** "saturated" = source ΔG ≥ 5 nats AND emit ≥ 0.30; "floored" = source ΔG < 1 nat AND emit ≤ 0.05; "intermediate" = anything between (also informative).

### Thresholds

- **Saturated:** source ΔG ≥ 5 nats AND emit ≥ 0.30 (matches v2's 17.42 / 0.8 with headroom).
- **Floored:** source ΔG < 1 nat AND emit ≤ 0.05 (matches v4's 0.04 / 0.0).
- **Intermediate:** anything between — also a finding.

### Statistical test

No formal statistical test — the v2 vs v4 effect size (17 nats vs 0.04 nats; emission 0.8 vs 0.0) is 100× wider than across-seed noise observed at this cell in #477 v2's calibration table. Any cell that lands "saturated" vs "floored" is unambiguous. A confounded mixed outcome (some cells saturate, some floor on the same arm) is itself the H5 finding.
