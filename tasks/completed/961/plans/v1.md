## 4. Design

### 4.1 Chosen design: two-gate narrowing (clause binding + queue-context veto, line gate retained)

The task body offers (a) queue-context exclusion regex and (b) clause binding. **Both are needed, plus one preservation measure**, because the corpus replay shows:

- Pure (a) misses false positives with non-enumerated vocabulary — #763's "scoped + handed off" and especially #595's "routes next /issue 595 invocation" (no queue word at all).
- Pure (b) on the existing 4-word list destroys the *dominant historical true-positive shape* `"(label) complete; … PASS"` — the completion word sits in a *later* clause while the token's clause says "complete" (7 real park notes: #505, #542×2, #559, #545 `metric-race`, #541 `geometry-plus-prior-joint-predictor`×2, #613, #654).

**Final logic for class 3** (per line of each `epm:status-changed` / `epm:step-completed` / `epm:progress` note):

1. **Gate 1 (UNCHANGED — the pre-#961 check, kept as an outer conjunct):** `token in line and _ROUND_COMPLETION_WORD.search(line)`. Retaining it makes new evidence a *provable subset* of old evidence — the fix cannot loosen anything.
2. **Gate 2 (NEW):** split the line into clauses on `re.split(r"[;.]", line)`; evidence requires SOME clause where:
   - `token in clause`, AND
   - `_QUEUE_CONTEXT_WORD.search(clause)` is None (queue-context veto), AND
   - `_ROUND_COMPLETION_WORD.search(clause)` OR `_CLAUSE_COMPLETION_WORD.search(clause)` (the completion signal is bound to the label's clause; the supplement rescues the `"(label) complete; … PASS"` shape).

### 4.2 Concrete diff

**New module constants** (insert immediately after `_ROUND_COMPLETION_WORD`, `src/explore_persona_space/task_workflow.py` ~line 1653):

```python
# Round-completion words for the class-3 retro-close evidence read
# (`followup_retro_close_evidence`). Case-sensitive by design — a missed
# close is safe (the label stays queued), a wrong close is not.
_ROUND_COMPLETION_WORD = re.compile(r"PASS|re-park|awaiting_promotion|clean-result")

# Queue-context veto for the class-3 read (#961): a clause naming the label
# as queued / unrun / scoped / armed / dispatched is a QUEUE mention, never
# completion evidence (park/handoff notes routinely announce round X complete
# while enumerating the queued next label Y on the same line — #825
# 2026-07-04T04:21:23Z, #595 2026-06-14T06:20:31Z, #763 2026-07-02T10:47:16Z).
# Case-INSENSITIVE by design: a veto only ever narrows.
_QUEUE_CONTEXT_WORD = re.compile(
    r"unrun|queue|dispatch|scoped|deferred|pending|armed", re.IGNORECASE
)

# In-clause completion-vocabulary supplement for the class-3 read (#961): the
# dominant true-positive park-note shape is "(label) complete; ... PASS" —
# the token's clause says complete/COMPLETE while the _ROUND_COMPLETION_WORD
# sits in a later clause (#505/#542/#545/#559/#613/#654 park notes). Applies
# ONLY inside a line that already passed the line-level
# _ROUND_COMPLETION_WORD gate, so new evidence stays a strict subset of the
# pre-#961 match. Case-sensitive (mirrors _ROUND_COMPLETION_WORD's deliberate
# case-sensitivity); the lookbehind rejects "incomplete"/"INcomplete".
_CLAUSE_COMPLETION_WORD = re.compile(r"(?<![iI][nN])(?:complete|COMPLETE)")
```

**Class-3 loop** (replace lines 1942-1952):

```python
    token = f"({label})"
    for ev in events:
        kind = ev.get("kind")
        if kind not in ("epm:status-changed", "epm:step-completed", "epm:progress"):
            continue
        for line in (ev.get("note") or "").splitlines():
            # Gate 1 — the pre-#961 line-level check, retained verbatim so
            # the #961 narrowing can never ADD evidence (new ⊆ old).
            if token not in line or not _ROUND_COMPLETION_WORD.search(line):
                continue
            # Gate 2 (#961) — bind the completion signal to the label's own
            # ;/.-delimited clause and veto queue-context mentions.
            for clause in re.split(r"[;.]", line):
                if token not in clause:
                    continue
                if _QUEUE_CONTEXT_WORD.search(clause):
                    continue  # label named as queued/armed/dispatched — not evidence
                if _ROUND_COMPLETION_WORD.search(clause) or _CLAUSE_COMPLETION_WORD.search(
                    clause
                ):
                    return (
                        f"{kind} at {ev.get('ts', '?')} carries the round token "
                        f"({label}) plus a round-completion word in the same clause"
                    )
    return None
```

(Classes 1 and 2, and the class-order semantics, are untouched.)

## 10. §11 Decision Rationale

1. **Two-gate combination (clause binding + queue veto + retained line gate) over pure (a) or pure (b).**
   **What:** gate 1 = pre-#961 line-level check retained; gate 2 = same-clause completion word + queue-context veto.
   **Why:** pure exclusion (a) misses false positives with unenumerated vocabulary — #595's token clause ("routes next /issue 595 invocation") contains zero queue words; pure clause binding (b) on the 4-word list destroys the dominant historical true-positive shape `"(label) complete; … PASS"` (7 real park notes). Retaining gate 1 makes the change provably narrowing-only.
   **Source:** full-corpus replay run during planning (0 loosening flips; 5 class-3 narrowings, 2 live-FP kills, 3 inert-with-class-1-fallback); incidents #825 / #595 / #763 (verbatim events in `tasks/followups_running/825/`, `tasks/awaiting_promotion/595/`, `tasks/*/763/`).
   **Alternatives:** (a)-only (rejected: #595 escape), (b)-only (rejected: 7 lost true positives), em-dash delimiters (rejected: severs #658's `"… — COMPLETE"` true-positive clause).
2. **`_CLAUSE_COMPLETION_WORD = (?<![iI][nN])(?:complete|COMPLETE)`, case-sensitive, applied only inside gate-1-passing lines.**
   **Why:** rescues the `"(label) complete"` park shape; case-sensitive to mirror `_ROUND_COMPLETION_WORD`'s documented deliberate case-sensitivity (an earlier case-insensitive draft produced 2 loosening flips via "Re-parking" — caught and removed during planning); the lookbehind rejects "incomplete"; the gate-1 scoping means the supplement can never create evidence on a line the old predicate rejected.
   **Source:** corpus replay (the 7 park-shape lines; the #541/#546 loosening near-miss).
   **Alternatives:** adding `complete` to `_ROUND_COMPLETION_WORD` itself (rejected: line-level loosening, out-of-scope change to a documented constant).
3. **`_QUEUE_CONTEXT_WORD = unrun|queue|dispatch|scoped|deferred|pending|armed`, case-insensitive, per-clause scope.**
   **Why:** each word grounded in a real queue-context line — `unrun`/`queue(d)`/`next entry dispatch` (#825 04:21:23Z), `scoped` (#763), `armed` (#825 04:20:49Z parenthetical), `dispatch` additionally excludes mid-round `stage-dispatch` breadcrumbs (which are round-*start* records, never completion evidence); `deferred`/`pending` cover the #595 `deferred_to_next_invocation` vocabulary family. Case-insensitive because a veto only narrows. Per-clause (not per-line) scope so a queued mention of a *different* label elsewhere on the line cannot block a legitimate close (§5.3 row 5).
   **Source:** the three incident notes + the corpus scan showing no historical true-positive token clause contains any of these words.
