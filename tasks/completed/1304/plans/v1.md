### Change 2 — `scripts/pod_config.py`: local helper (insert immediately after the `if TYPE_CHECKING:` block, ~:51, before the Paths section)

```python
def _ensure_scripts_dir_on_sys_path() -> None:
    """Insert THIS file's dir (scripts/) so a lazy ``import runpod_api`` resolves.

    In script mode scripts/ is already ``sys.path[0]``; in MODULE mode
    (``from scripts.pod_config import parse_pods_conf``) only the repo root is
    on sys.path, so a bare lazy ``runpod_api`` import raises
    ``ModuleNotFoundError`` (#1296/#1304). Mirrors scripts/backend_poll.py's
    helper; idempotent; called ONLY on the lazy paths so the cheap
    ``--list``/``--check`` paths and library imports never mutate sys.path.
    """
    scripts_dir = str(Path(__file__).resolve().parent)
    if scripts_dir not in sys.path:
        sys.path.insert(0, scripts_dir)
```

(`sys` and `Path` are already module-top imports at pod_config.py:26/:31.)

- **Site match (indented = lazy only):** a line is a flagged site iff it matches either form AND the bare (undotted) module name ∈ stems:
  - `re.match(r"\s+from ([A-Za-z_]\w*) import\b", line)` — undotted only, so module-mode-safe `from scripts.pod_config import …` consumers are excluded by construction;
  - `re.match(r"\s+import ([A-Za-z_]\w*(?:\s+as\s+\w+)?(?:\s*,\s*[A-Za-z_]\w*(?:\s+as\s+\w+)?)*)\s*(#.*)?$", line)` — names split on commas, `as` aliases stripped (covers `import issue664_common as C`).
- **Guard window:** unchanged #1296 semantics — within the preceding 12 lines, comment lines never satisfy; guard recognized as `_ensure_scripts_dir_on_sys_path()` OR `sys.path.insert(0, scripts_dir)`; PLUS one new exemption: `if TYPE_CHECKING:` present in the raw preceding window (covers pod_config.py:50, which has no runtime effect).
- **Non-vacuity:** assert ≥1 flagged lazy site per scanned file (as today).
- **Module-top (unindented) scripts-local imports stay OUT of scope:** they fail loudly at import time in every module-mode consumer/test (self-catching); the lazy sites are the silent-at-import class this pin exists for.

## §11 Decision Rationale

- **Local helper copy in pod_config (vs importing backend_poll's, vs inline inserts).** Chosen: local copy. Source: #1296 precedent (backend_poll.py:159, read this session). Importing the helper from another scripts-local module is chicken-and-egg (the import itself needs the bootstrap) and backend_poll is heavy; per-site inline inserts (the issue664 shape) duplicate 3 lines per site and lose the single named guard token.
- **Dynamic stems set (vs fixed `runpod_api|failure_classifier|issue664_\w+`).** Chosen: dynamic `{p.stem for p in scripts_dir.glob("*.py")}`. Source: #1304's own lineage — #1296's fixed-name pin is precisely what let `failure_classifier` slip (task body "Why it is a workflow gap"). Fixed regex rejected: re-creates the unpinned-name gap for the next module. Collision risk with installed packages is bounded (see Assumption 4).
- **Rename + delete old test (vs keep as alias).** Chosen: rename, delete. Source: code-style "Supersede → delete the old version"; two live pins for the same invariant rot. Old name preserved in the new docstring for grep history.
- **Keep the `:576` try/except.** Chosen: keep. Source: code reading — the except's own comment ("only if repo is malformed") states its intent; the bootstrap removes the module-mode false trigger and restores that intent as pure defense-in-depth.
- **Indented-only scan scope.** Source: #1296 test design; module-top scripts-local imports fail loudly at import time in every module-mode consumer (self-catching), so widening to them buys nothing and risks false positives on script-mode-only files.
