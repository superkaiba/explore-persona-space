# Plan v1 — #1856 daily-fix: kill-before-relaunch enumerates live launcher phases

## 1. Goal / requirement

In-place recovery must not race the live launcher's own phase sequence into a
double-execution OOM. Concretely: add a **live-launcher forward-phase
enumeration duty** to `.claude/rules/crash-fix-rounds.md`
§ "Kill-before-relaunch + `timeout`-bounded smokes" so that, before an
orchestrator/agent launches a detached duplicate ("manual recovery") of a
workload PHASE on a machine whose own launcher/dispatcher is still live, it
must enumerate the launcher's REMAINING phases and take a binary disposition
(defer hands-off, or kill the launcher first) — never run a duplicate
alongside a live launcher whose remaining sequence includes that phase.

**Acceptance criteria:**

1. The duty text names: (a) the trigger (about to launch a detached
   duplicate / manual in-place recovery instance of a phase while the
   workload's own launcher is LIVE — pod, GCE, or VM alike); (b) why the
   existing steps 1-3 do not cover it (pgrep sees only RUNNING instances; an
   upcoming phase of a live launcher is invisible); (c) the enumeration
   mechanics (read the launcher's phase sequence from its cmdline / dispatcher
   leg list + its log position); (d) the binary disposition (defer hands-off
   as DEFAULT, or kill the launcher via steps 1-3 and own the whole remaining
   sequence — never both live).
2. The duty carries the **ETA-is-not-safety clause**: "the launcher is hours
   from that phase" is not a disposition, because the recovery's own actions
   can collapse the launcher's ETA (the #1482 mechanism).
3. The #1482 incident is the worked example with real numbers (bulk store
   commit dedup collapsed the live launcher's E2 walk 33h → ~1h; launcher
   advanced to its own fits while the detached fits held 55.9 GiB; torch OOM
   4 GiB needed / 1.22 GiB free; failed sentinel → crash-persist → poweroff
   10:03:33Z killing BOTH runs; ~25 min recovery + one fit unit silently lost
   to a resume-predicate miss).
4. The file's frontmatter `description:` line records the addition
   (`live-launcher forward-phase enumeration (#1856)`), matching the file's
   convention for prior additions.
5. No other section of the file is touched: the #1346 width pointer, the
   #1749 compute-character duty, and the `epm:run-launched` fixture line
   pinned by `tests/test_workflow_lint.py:7058` /
   `tests/test_issue_skill_width_reeval_pointer.py` /
   `tests/test_issue_skill_marker_contract.py` stay byte-identical.
6. `scripts/workflow_lint.py` (no-flags) + `--check-lessons-index` +
   `--check-asks` pass; the mapped Step-9c tests for the payload pass.
