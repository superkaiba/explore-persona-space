## 1. Goal / requirement

In-place recovery must not race the live launcher's own phase sequence into a
double-execution OOM. Concretely: add a **live-launcher forward-phase
enumeration duty** to `.claude/rules/crash-fix-rounds.md`
§ "Kill-before-relaunch + `timeout`-bounded smokes" so that, before an
orchestrator/agent launches a detached duplicate ("manual recovery") of a
workload PHASE on a machine whose own launcher/dispatcher is still live, it
must enumerate the launcher's REMAINING phases and take a binary disposition
(defer hands-off, or terminate the launcher first) — never run a duplicate
alongside a live launcher whose remaining sequence includes that phase.

**Acceptance criteria:**

1. The duty text names: (a) the trigger (about to launch a detached
   duplicate / manual in-place recovery instance of a phase while the
   workload's own launcher is LIVE — pod, GCE, or VM alike); (b) why the
   existing steps 1-3 do not cover it (pgrep sees only RUNNING instances; an
   upcoming phase of a live launcher is invisible); (c) the enumeration
   mechanics (read the launcher's phase sequence from its cmdline / dispatcher
   leg list + its `[phase=...]` log position), with REMAINING defined to
   include re-enterable phases (a resume/retry loop can RE-enter a "finished"
   phase); (d) the binary disposition (defer hands-off as DEFAULT, or
   terminate the launcher via steps 1-3 and own the whole remaining sequence —
   never both live).
2. **Fail-safe (critic Must-Fix 1):** the duty states that an unreadable
   enumeration or ambiguous membership is treated as the phase being IN the
   remaining sequence (defer or terminate-first) — the duplicate is never
   launched on unproven absence (mirrors the section's existing
   "Ambiguous → do NOT kill; leave it and report" disposition at
   crash-fix-rounds.md:192).
3. The duty carries the **ETA-is-not-safety clause**: "the launcher is hours
   from that phase" is not a disposition, because the recovery's own actions
   can collapse the launcher's ETA (the #1482 mechanism) — plus ONE clause
   noting phase-membership is a sufficient, not necessary, trigger: any
   GPU/RAM-contending remaining phase warrants the same disposition (the OOM
   collision is phase-identity-agnostic).
4. The #1482 incident is the worked example with figures reconciled to the
   #1482 events marker v116 (2026-07-29T10:29:14Z): bulk store commit dedup
   collapsed the live launcher's E2 walk ~33 h projected → finished ~1 h;
   launcher advanced to its own fits while the detached fits (launched on the
   "idle" GPU) held 55.9 GiB; torch.OutOfMemoryError, 4 GiB needed / 1.22 GiB
   free; failed sentinel → crash-persist → poweroff 10:03:33Z killing BOTH
   runs; recovery cost one instance restart + ~15 min GPU smoke/pilot re-run
   + ~1 h of no-op dedup re-walk, plus one fit unit lost to a
   resume-predicate miss (re-swept later).
