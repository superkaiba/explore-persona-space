## 1. Goal + requirement + acceptance criteria

**Canonical Goal (task #1430 `## Goal` H2, verbatim; re-read 2026-07-16 immediately before returning this plan; kind: infra — no `goal:` frontmatter):**

> `task.py audit` detects duplicate `tasks/<status>/<id>` dirs for a single id, and a sweep reaps merge-reintroduced stale-status husk dirs of TERMINAL tasks (husk contents verified as a subset/prefix of the live folder before removal; any husk with unique content is escalated, never deleted).

**Requirement.** Terminal tasks #721/#1107/#1227 each hold two on-disk dirs (live `tasks/completed/<id>/` + a stale-status husk) re-introduced by concurrent branches' rebase-merges landing after the status-move commit. `task.py audit` PASSes despite this (it checks registry→path agreement + orphan dirs only, `task_workflow.py::audit()` L5016–5051), and the #644 ghost sweep (`_task_status_dir_pathspecs`, L3988) covers only the INVERSE shape (tracked-in-HEAD, absent-on-disk) and only at the same task's next transition — terminal tasks have none. Consequence: every `ls tasks/<status>`-based fleet read misreports terminal tasks as active, and `find_task_path`'s stale-registry recovery scan (L3651) degrades from single-hit self-heal to `StaleTaskPathError` whenever a husk coexists with a stale registry entry.

**Acceptance criteria:**
1. `task.py audit` lists a `[duplicate-dir]` finding for every id with >1 on-disk `tasks/<status>/<id>` dir (id, live path per REGISTRY, husk paths, terminal/non-terminal label). Exit code unchanged by duplicate-dir findings (WARN tier — rationale in §3, decision D1).
2. `task.py reap-husks --apply` removes a terminal-task husk iff every husk entry is subset-verified against the live dir; escalates (never deletes) otherwise; skips non-terminal / unregistered ids with a labeled reason.
3. The daily worktree-audit cron additionally runs the reap; `EPM_SKIP_HUSK_REAP=1` disables it fleet-wide.
4. The 3 live husks are reaped as part of this task (one-time cleanup, post-merge), after which `task.py audit` prints zero duplicate-dir warnings and `ls -d tasks/*/721 tasks/*/1107 tasks/*/1227` returns exactly one dir per id.
5. Tests (a)–(d) from the deliverable list (plus symlink + kill-switch pins) pass; full `uv run pytest tests/test_task_workflow.py` green; `uv run python scripts/workflow_lint.py` (no-flags) green; ruff clean on touched files.

## 2. Method delta (vs the existing #644 ghost sweep)

| | #644 ghost sweep (existing) | This task (new) |
|---|---|---|
| Husk shape | tracked in HEAD, **absent on disk** | **present on disk** (tracked OR untracked), merge-reintroduced |
| Trigger | the same task's NEXT `set_status` transition (L4191–4202) | daily janitor cron + on-demand `task.py reap-husks`; audit surfaces it continuously |
| Terminal tasks | unreachable (no next transition) | the primary target — reap restricted to completed/archived |
| Safety check | none needed (nothing on disk to lose) | byte-subset verification of every husk entry vs the live dir; escalate-never-delete on unique content |
| Detection | none (`audit()` blind to per-id path multiplicity) | `duplicate_task_dirs()` + audit WARN tier |

The new reap does NOT touch `set_status` or `_task_status_dir_pathspecs` — the #644 mechanism stays byte-identical (a `git add --all` over an unchanged tracked husk stages nothing, so extending the transition-time sweep could not fix this class anyway; verified by reading L3988–4010: the pathspec helper unions tracked ∪ on-disk dirs, but staging an unmodified tracked dir is a no-op).

## 3. Design

### Decisions (with the ordering concern resolved)

- **D1 — audit tier: WARN, never exit-1, for ALL duplicate-dir findings.** Rationale: (i) the ordering concern — audit must not go red on the 3 pre-existing husks before the reap lands/runs, and every future concurrent-merge reintroduction would re-redden audit for up to ~24h until the janitor pass; (ii) audit's exit code is consumed as "registry↔filesystem agreement" by humans and agents — duplicates don't violate that contract (the registry entry is correct; the extra dir is residue). Alternative considered and rejected: FAIL tier for non-terminal duplicates — rejected because a non-terminal husk is the same benign merge residue (it becomes reap-eligible at terminal), and there is no crash shape that produces two on-disk dirs (the #825 crash envelope leaves one dir + a stale registry entry, read from `set_status`'s docstring L4023–4042). The WARN text names the remediation command, so detection → action is one copy-paste.
- **D2 — reap terminal set = `{completed, archived}` via a NEW constant `HUSK_REAP_TERMINAL_STATUSES`.** Do NOT reuse `TERMINAL_STATUSES` (L119) — it includes `blocked`, which is re-drivable (capacity-retry pass) and therefore not safe to treat as "no further transitions." Matches the Goal's "TERMINAL (completed/archived)" and the existing `_WF_FIX_TERMINAL = ("completed", "archived")` precedent (L1102), which stays untouched (wf-fix-dedup-scoped).
- **D3 — wiring = one invocation appended to `scripts/cron_worktree_audit.sh`** (09:47 daily). Least-invasive of the three candidates: the watcher (`autonomous_session_watch.py`, 21,684 lines, 10-min cadence) is high-blast-radius and overkill for a class that appears at merge time and only needs daily healing; `worktree_audit.py` itself is worktree-scoped and adding task-state logic there mixes concerns. The cron wrapper addition is ~4 lines; the predicate + kill switch live in the library, matching the report-only-default / cron-passes-apply janitor convention (`.claude/rules/background-automation.md`).
- **D4 — escalation channel = stderr WARNING + dedicated sidecar `.claude/cache/husk-reap-events.jsonl`; no Telegram push in v1.** A unique-content husk is a static data-integrity flag (evidence of a possibly lost concurrent write), not a billing leak; the audit WARN keeps it permanently visible on every `task.py audit` until triaged. Named residual: if escalations recur and go unnoticed, a follow-up can add the fail-soft `_telegram_push` line (the gcp-janitor pattern).
- **D5 — escalations do not affect exit codes** (`reap-husks` exits 0 unless an actual git/IO failure raises) — the gcp-janitor "escalation is the working path" convention, so the cron never emails on the designed outcome.

```python
# ─── Duplicate-dir audit + terminal-husk reap (#1430) ─────────────────────

HUSK_REAP_TERMINAL_STATUSES = frozenset({"completed", "archived"})
_HUSK_REAP_SIDECAR_REL = ".claude/cache/husk-reap-events.jsonl"


@dataclass(frozen=True)
class DuplicateDirFinding:
    task_id: int
    registry_path: str | None   # REGISTRY entry's repo-relative path; None if id unregistered
    live: str | None            # the on-disk dir REGISTRY points at (None if registry stale/missing)
    husks: list[str]            # every OTHER on-disk tasks/<status>/<id> dir, repo-relative, sorted
    terminal: bool              # live status in HUSK_REAP_TERMINAL_STATUSES (False when live is None)


def duplicate_task_dirs() -> list[DuplicateDirFinding]:
    """Pure read: scan tasks/<status>/<id> across STATUSES; return one finding
    per id holding >1 on-disk dir. Never mutates registry, disk, or git."""
    reg = _load_registry(); repo = repo_root(); td = tasks_dir()
    by_id: dict[int, list[Path]] = {}
    for status in STATUSES:
        sd = td / status
        if not sd.is_dir(): continue
        for child in sd.iterdir():
            if child.is_dir() and child.name.isdigit():
                by_id.setdefault(int(child.name), []).append(child)
    out = []
    for tid, dirs in sorted(by_id.items()):
        if len(dirs) < 2: continue
        entry = reg.get("tasks", {}).get(str(tid))
        reg_path = entry["path"] if entry else None
        rel_dirs = sorted(str(d.relative_to(repo)) for d in dirs)
        live = reg_path if (reg_path in rel_dirs) else None
        husks = [d for d in rel_dirs if d != live]
        terminal = bool(live) and _status_from_path(repo / live) in HUSK_REAP_TERMINAL_STATUSES
        out.append(DuplicateDirFinding(tid, reg_path, live, husks, terminal))
    return out
```

```python
def _husk_unique_content(husk: Path, live: Path) -> list[str]:
    """Entries under `husk` NOT covered by `live`. Empty list == safe subset.

    Per-entry rules (os.walk(followlinks=False) — never traverse INTO symlinks):
    - symlink: safe iff the live counterpart is a symlink with identical
      os.readlink(); else unique.
    - regular file: safe iff a live counterpart exists AND (bytes identical
      OR husk bytes are a byte-prefix of live bytes OR — .jsonl only — husk
      lines are an ordered subsequence of live lines); a file with NO live
      counterpart is safe only at size 0; else unique.
    - directory: recursed; empty dirs contribute nothing (trivially safe).
    - any other file type (fifo/device): unique (never expected under tasks/).
    """
```

```python
@dataclass(frozen=True)
class HuskReapAction:
    task_id: int
    husk: str      # repo-relative
    action: str    # reaped | would-reap | escalated | would-escalate
                   # | skipped-non-terminal | skipped-unregistered | skipped-registry-stale
    reason: str    # human-readable, names unique files on escalation


@dataclass(frozen=True)
class HuskReapReport:
    applied: bool
    disabled: bool                 # EPM_SKIP_HUSK_REAP=1 short-circuit
    actions: list[HuskReapAction]


def reap_stale_status_husks(*, apply: bool = False, task_id: int | None = None) -> HuskReapReport:
    """Reap merge-reintroduced stale-status husk dirs of TERMINAL tasks.

    Report-only unless apply=True. Kill switch EPM_SKIP_HUSK_REAP=1 returns
    an empty disabled report. Escalates (stderr + sidecar row), NEVER
    deletes, on any unique husk content. Registry-stale / unregistered /
    non-terminal ids are skipped with labeled actions — never reaped.
    """
    if os.environ.get("EPM_SKIP_HUSK_REAP") == "1":
        return HuskReapReport(applied=False, disabled=True, actions=[])
    repo = repo_root()
    actions: list[HuskReapAction] = []
    findings = [f for f in duplicate_task_dirs() if task_id is None or f.task_id == task_id]
    if not (apply and findings):
        # classify-only pass (report mode, or nothing to do)
        for f in findings: actions.append(_classify_husks(f, repo, apply=False))  # would-* actions
        return HuskReapReport(applied=apply, disabled=False, actions=actions)
    with _locked():
        # Re-enumerate INSIDE the lock (findings could be stale vs a concurrent mutation).
        for f in [g for g in duplicate_task_dirs() if task_id is None or g.task_id == task_id]:
            if f.registry_path is None:
                actions.append(... "skipped-unregistered", "fix registry first: task.py audit --repair"); continue
            if f.live is None:
                actions.append(... "skipped-registry-stale", "REGISTRY path not on disk: task.py audit --repair"); continue
            if not f.terminal:
                actions.append(... "skipped-non-terminal", f"live status {_status_from_path(repo / f.live)!r}"); continue
            live_abs = repo / f.live
            for rel_husk in f.husks:
                husk_abs = repo / rel_husk
                if husk_abs.is_symlink():
                    actions.append(_escalate(f.task_id, rel_husk, "husk root is a symlink", repo)); continue
                unique = _husk_unique_content(husk_abs, live_abs)
                if unique:
                    actions.append(_escalate(f.task_id, rel_husk, f"unique content: {unique[:5]}", repo)); continue
                tracked = _run_git(["ls-files", "--", rel_husk]).stdout.splitlines()
                if any(t.strip() for t in tracked):
                    _run_git(["rm", "-r", "-q", "--", rel_husk])       # stages deletions + removes tracked files
                if husk_abs.exists():
                    shutil.rmtree(husk_abs)                            # untracked residue (the #721 empty-dir shape)
                if any(t.strip() for t in tracked):
                    _git_commit([husk_abs], f"task #{f.task_id}: reap stale-status husk {rel_husk} (#1430)")
                _sidecar_row(repo, task_id=f.task_id, husk=rel_husk, action="reaped", n_files=len(tracked))
                actions.append(HuskReapAction(f.task_id, rel_husk, "reaped",
                                              f"subset-verified ({len(tracked)} tracked file(s))"))
    return HuskReapReport(applied=True, disabled=False, actions=actions)
```

Notes on the sketch (the implementer refines, contracts bind):

- `_escalate(...)` writes the sidecar row (`{"ts": _utcnow_iso(), "task_id": ..., "husk": ..., "action": "escalated", "reason": ..., "unique": [...]}` via `_append_jsonl_line`, `mkdir(parents=True)` on `.claude/cache/` first) AND a `_log.error(...)` stderr line naming the husk + the unique files + "never deleted — triage manually". Sidecar/stderr fire only under `apply=True`; report mode records `would-escalate` actions (gcp-janitor parity, D4/D5).
- `_git_commit([husk_abs], ...)` works by existing contract (L5650–5656): the path no longer exists on disk → skipped at re-stage; `commit --only -- <rel_husk>` captures the staged deletions; sequencer wait + routed-root CAS + landing check all inherited. One commit per husk (clean per-husk audit trail; 3 commits total for the one-time cleanup).
- A fully-untracked husk (the #721 shape: only an empty `artifacts/` dir; verified `git ls-files tasks/running/721` → empty) takes the `rmtree`-only path with **no commit** (nothing tracked changed — git does not track empty dirs).
- The whole apply loop holds `_locked()` once (same flock as every task.py mutation, L753/L4049), and the enumeration + subset verification re-run inside the lock — the verify→remove window is adjacent and serialized against all task.py writers. Residual: a non-task.py writer (a concurrent `git merge` re-adding files) between verify and rmtree is an accepted ms-scale TOCTOU; the next janitor pass re-converges (see §6 R2).

## 4. Controls / edge cases

| Case | Behavior | Where enforced |
|---|---|---|
| Husk with unique content (file only in husk, size>0; diverged non-prefix file; extra events lines) | ESCALATE: stderr + sidecar row, never deleted; audit keeps warning | `_husk_unique_content` + `_escalate`; test (c) |
| **Registry points at the STALE dir** (live/husk roles inverted by a stale entry) | The true live dir has strictly more content ⇒ subset check fails ⇒ escalate, never delete. The subset verification IS the misidentification guard | `_husk_unique_content`; noted in escalation text |
| Non-terminal id with duplicate dirs | `skipped-non-terminal`, listed by audit WARN; becomes reap-eligible when the task reaches completed/archived | D2 status gate; test (d) |
| Registry-missing id / registry path not on disk | `skipped-unregistered` / `skipped-registry-stale` — reap refuses to guess live-vs-husk; remediation = `task.py audit --repair` first (audit check 2 already flags the unregistered dirs, verified L5033–5045) | reap preconditions |
| Husk == live (byte-identical twin) | Identical ⇒ trivially subset ⇒ reaped (live = the REGISTRY path, always) | `duplicate_task_dirs` live-resolution |
| Symlinks inside the husk (real case: `tasks/reviewing/1227/plans/plan.md → v1.md`, matching live) | Safe iff live counterpart is a symlink with identical `readlink`; never followed during the walk (`os.walk(followlinks=False)`); a husk ROOT that is a symlink escalates outright | `_husk_unique_content`; test (e) |
| Fully-untracked husk (real case: `tasks/running/721/` = one empty `artifacts/` dir, `git ls-files` empty) | Subset-verified (no files) ⇒ `rmtree` only, no commit | apply path; test (e2) |
| Concurrent commit races | Whole apply loop under `_locked()` (the task.py flock); `_git_commit` inherits sequencer-wait + `commit --only` explicit-path discipline + routed-root CAS; enumeration re-runs inside the lock | existing `_locked`/`_git_commit` machinery |
| Empty file present only in husk | Safe at size 0 (no content to lose); any size>0 escalates | `_husk_unique_content` |
| Kill switch | `EPM_SKIP_HUSK_REAP=1` ⇒ library returns `disabled` report; cron + on-demand both honored | library env check; test (f) |
| id-digit collisions (id 89 vs 898) | Exact dir-name match only (`child.name.isdigit()` + `int(name)` grouping — no globs), the same discipline as `_task_status_dir_pathspecs` (L3994–3996) | `duplicate_task_dirs` |

|---|---|---|
| R1: a merge re-introduces a husk AFTER the reap | High (this is the standing production mechanism — any branch cut pre-move re-adds the old dir on rebase-merge) | Yes, the janitor wiring is the answer: daily idempotent reap + continuous audit WARN in between. | R2: TOCTOU between subset-verify and rmtree (non-task.py writer adds a file) | Very low (verify+remove adjacent, under the task.py flock; only a concurrent git merge could interleave) | Accepted ms-scale residual; worst case deletes a file that landed in a dir already verified stale — the file remains recoverable from the merge commit; next audit/janitor pass re-converges |
| R3: reap misidentifies the live dir when REGISTRY is stale | Low | Three independent guards: `skipped-registry-stale` precondition (registry path must be on disk), the subset check (the true live dir escalates — it has more content), and terminal-only scope |
| R4: `git rm` / commit failure mid-loop leaves a partially-staged deletion | Low | `_git_commit` raises loud (fail fast); the staged deletion is confined to the explicit husk pathspec and is swept by the same reap's retry (idempotent — re-run `reap-husks --apply`); `commit --only` prevents leakage into unrelated commits |
| R5: audit WARN noise trains agents to ignore audit output | Low | WARN lines carry the exact remediation command; the daily janitor keeps steady-state at zero findings |
| R6: cron wrapper addition breaks the worktree sweep | Very low | Additive lines after the existing invocation, same redirected block, `exit 0` posture untouched; smoke: run the wrapper once manually post-merge and read the dated log |
