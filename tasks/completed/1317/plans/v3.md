## 3. Design decisions (answers to the five design questions)

1. **Placement: ONE new step, `Step 4.6`, inserted between Step 4.5 (L1343) and Step 5 (L1345).** Not split across 0.5 + 4: the diff-consistency half needs the diff (Steps 1–3 precede Step 4), Step 0.5's contract is the generic four-section shape (a field-level check there bloats the generic gate), and within-review ordering is immaterial — Step 0.7 forbids short-circuiting, so a presence FAIL found at 4.6 carries identical semantics to one found at 0.5. Single location = minimal surface, matches the Step 4.5 precedent (a report-claim-vs-worktree verification step in the Step 4 family).
2. **Scope: `epm:results` reports only** (`type:infra` / `type:survey` code paths). The presence half binds only where the report CONTRACT requires the line; `epm:experiment-implementation` has the 2b duty but no report line (grep-confirmed), so a presence check there would FAIL every conforming experiment report. Adding the line to experiment-implementer's report format is OUT of scope (a distinct contract with a different gate leg — experiment kinds skip Step 9c); noted as a parked follow-up (this session is under the recursion guard, so it parks rather than auto-files).
3. **Blocker-tag semantics:**
   - (a) line absent entirely → Critical tagged **`marker-shape`** (strippable), blocker body NAMES `Gate-scope check` (per-blocker keying, the 0.55 pattern). Rationale: absence is a structural fact the orchestrator can mechanically verify against the canonical marker; making it strippable preserves the stale-worktree false-absence protection and the anti-gate-hopping principle.
   - (b) line present but a changed load-bearing literal missing from the pin-sweep fragments → **`substantive`** (reviewer first greps the enumerated tests for it themselves: no hits → Minor; hits in an un-run file → escalate to case (c)). Consistency requires the diff + judgment — not mechanically verifiable — so it must never be strippable.
   - (c) a pin-sweep HIT left NOT-RUN → presumptively blocker-adjacent, **`substantive`**. The reviewer discharges the presumption: run the file at Step 4 when it fits the budget, else read its pinned assertions against the diff. Stale pin → Critical; undischargeable → Major naming file + exact command; discharged → note under `## Tests`. A missing copy-pasteable command alone is a CONCERNS (format), the undischarged hit is the substantive part.
4. **Grandfathering: key on the marker `ts` vs the duty's landing date.** The duty landed on `main` 2026-07-14 (`eb4da66c68`). A report whose marker `ts` predates 2026-07-15 missing the line is at most a CONCERNS, never FAIL (the duty landed on main 2026-07-14; date-granularity same-day ambiguity resolved by using the ≥ 2026-07-15 boundary). Simplest robust option: one clause, self-expiring (all forward rounds postdate it), no spec-archaeology needed.
5. **SKILL.md Step 5c-bis update: YES, required (~5 lines).** Without a per-blocker sub-case, an absence-FAIL tagged `marker-shape` would be verified via the "Otherwise (Step 0.5 default)" four-H3 recipe — which can be conforming while the Gate-scope line is missing — and wrongly STRIPPED (exactly incident #811). The sub-case verifies presence ONLY; consistency findings are `substantive` by spec and outside the strip's reach.
