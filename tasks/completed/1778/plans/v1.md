# Plan v1 — task #1778: verify_artifacts_exist fail-soft on planned-output hf:// globs + wrong repo_type

## 0. Plan Summary

`orchestrate.hub.verify_artifacts_exist` (the Step 6a.5 carry-over launch gate +
the Step 8 phantom-URL gate via `scripts/verify_uploads.py`) CRASHES with an
uncaught `RepositoryNotFoundError` instead of returning `(ok, missing)` when a
plan cites (a) an `hf://` path that is the plan's own PLANNED OUTPUT — a glob
under a not-yet-existing prefix — and/or (b) a dataset repo id written without
the `datasets/` prefix, which `_kind_to_repo_type` maps to `repo_type="model"`
(404 on `api/models/superkaiba1/explore-persona-space-data`). Reproduced live
2026-07-29 on `tasks/followups_running/1482/plans/plan.md` (plan v16).

Fix: (1) SKIP glob-bearing in-repo paths (planned-output shape — cannot be
existence-checked literally, and marking them `missing` would false-BLOCK the
Step 6a.5 gate on the plan's own outputs); (2) on `RepositoryNotFoundError`
for an UN-prefixed repo id probed as `model`, retry as `dataset` before
concluding; (3) a repo that resolves under NEITHER repo_type becomes a
reportable `missing` row — never an uncaught traceback. Genuine transport /
auth errors keep propagating (fail-loud contract unchanged).

**Not architectural** (`architectural: false`): no signature removal, no
return-type change, no marker/status/CLI contract change. Bug-fix category —
direct plan + minimum plan-review floor (verify_plan + one Claude critic);
fact-checker / full 6-critic ensemble / consistency-checker skipped per the
CLAUDE.md `/adversarial-planner` bug-fix carve-out (recorded skip).

## 1. Goal + acceptance criteria

**Goal** (task body): `verify_artifacts_exist` returns `(ok, missing)`
fail-soft on unresolvable `hf://` citations — classifying planned-output/glob
paths and wrong-repo-type probes as skip/reportable rows — never an uncaught
traceback that aborts the Step 6a.5 gate.

Acceptance criteria:
1. `verify_artifacts_exist` on a plan citing a glob-bearing `hf://` path
   (e.g. `hf://superkaiba1/explore-persona-space-data/issue1482_error_analysis/analysis_tensors/early_layer/pooled_l3_*.npz`)
   returns without raising; the glob row is SKIPPED (not probed, not in
   `missing`) — planned outputs never false-block the launch gate.
2. An un-prefixed `hf://<org>/<name>/<path>` whose `model` probe raises
   `RepositoryNotFoundError` is retried as `repo_type="dataset"`; if the
   dataset probe resolves, the row is checked normally under `dataset`.
3. A repo id resolving under NEITHER repo_type yields a `missing` row (the
   URL string), never an exception.
4. Behavior for currently-resolvable citations is byte-identical (existing
   tests in `tests/test_hub_artifacts_and_refusal.py` pass unchanged).
5. Genuine transport errors (5xx/timeout/connection surfacing through
   `list_hf_files_under_path` / `_retry_upload`) still PROPAGATE.
6. New pin tests cover 1-3 (mock `HfApi`; no network).

## 2. Method delta (what differs from prior related work)

Prior: `_hf_artifact_exists` deliberately propagates everything except a
reachable-repo-missing-path `False` (fail-loud contract). Delta: two narrow
classification arms added ABOVE that contract — glob-skip (mirrors
`scripts/verify_carryover_inputs.py::classify`'s `planned-output` skip rung)
and repo_type fallback + `RepositoryNotFoundError`→missing (mirrors
`_wandb_run_exists`'s not-found→False handling). No behavior change for any
URL that resolves today.

  path = m.group("webpath") or m.group("uripath") or ""

  if not exists:
      missing.append(url)
