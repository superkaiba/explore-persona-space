# Plan — Task #1251: Step 9c baseline oracle tolerates unrelated concurrent dirty `src/` at the shared repo root (PYTHONPATH scratch-shadow)

## 0.0 TL;DR (plain English)

- **What I'll change:** When another session's in-progress files are sitting dirty at the shared repo root, the test-verdict oracle currently gives up (exit 2) if any of that dirt is under `src/`. I'll make the oracle's existing clean-copy fallback (the scratch worktree) actually immune to that dirt, by pointing the test subprocess's import path at the clean copy's `src/` (`PYTHONPATH=<scratch>/src`), with a runtime probe that verifies the redirect really wins before any verdict rests on it.
- **What I expect:** The #1190 failure shape (unrelated concurrent `src/` dirt → rc=2 → wasted solo re-run round) disappears; only genuinely un-neutralizable dirt (`pyproject.toml` / `uv.lock` — installed dependencies) still refuses, and every refusal names exactly what blocked it.
- **What would change my mind:** If the runtime probe or the new integration test showed the venv's editable install preempting PYTHONPATH (it demonstrably does not — verified against the live venv during planning), or if I found gate tests that read main-root `src/` files by absolute path outside the already-excluded scanner set (audit found none).

## 0. Plan Summary (technical)

**Change:** relax the #1077 scratch-fallback eligibility in `scripts/step9c_baseline.py::_resolve_pristine_bucket` so `src/`-rooted contamination no longer blocks the scratch oracle; instead every scratch pristine run gets `PYTHONPATH=<scratch>/src` in its child env (scratch is detached at root HEAD ⇒ pristine-by-construction), verified once per compare by a new `find_spec`-based shadow probe run under the exact child-env shape (fail-closed to exit 2 on probe failure). `pyproject.toml`/`uv.lock` dirt remains contaminating (deps are not shadowable). **Verified mechanism:** this repo's venv uses a static one-line `__editable__.explore_persona_space-0.1.0.pth` (`sys.path.append` semantics); PYTHONPATH entries precede it (measured: index 1 vs 6) and a live import test resolved the PYTHONPATH copy; `explore_persona_space` is a regular package (`__init__.py` present) so submodule lookup is confined to the winning `__path__`. **Surface:** `run_pytest` gains keyword-only `pythonpath: str | None = None` (inherited PYTHONPATH still stripped — the #1022 vector stays closed); new helpers `residual_scratch_contamination()` + `assert_scratch_src_shadow()`; new `--no-src-shadow` escape flag; additive JSON field `scratch_src_shadow`. **Tests:** 3 existing tests repointed at residual dirt, ~8 new (incl. a real-venv `.pth`-vs-PYTHONPATH integration test and a live-venv durability pin). **Risks (top 2):** a future uv editable-style change preempting PYTHONPATH (mitigated: runtime probe fail-closed + live pin test); `repo_root()`-anchored `src/` file READS in non-scan tests (audited: none found; pre-existing documented residual channel).

## 3. Design-direction evaluation (A vs B vs C)

**A. PYTHONPATH shadowing — RECOMMENDED.** Verified end-to-end during planning against the live venv:

1. Editable style read from the venv itself: `ls .venv/lib/python3.11/site-packages/ | grep -i editable` → `__editable__.explore_persona_space-0.1.0.pth`; `cat` → exactly one line, `/home/thomasjiralerspong/explore-persona-space/src`. This is the **static-path `.pth`** style (plain `site.addsitedir` → `sys.path.append`), NOT a `__editable___*_finder.py` meta-path hook and NOT an easy-install-style reordering `.pth`.
2. Ordering measured with the actual interpreter: `PYTHONPATH=/tmp/probe/src .venv/bin/python -c "..."` → probe dir at `sys.path[1]`, editable src at `sys.path[6]`.
3. Definitive resolution test: a fake `explore_persona_space/__init__.py` on PYTHONPATH **won** — `explore_persona_space.__file__` resolved to the probe dir.
4. `src/explore_persona_space/__init__.py` exists at HEAD ⇒ regular package ⇒ submodule + `importlib.resources` package-data lookups are confined to the winning (scratch) `__path__` — this also fixes the #1077 mixed `src/*.json` case, because query-bank data rides the package `__path__`, which now points into the scratch.
5. No compiled extensions under `src/` (find: none) — nothing resolves outside the import system.

Because setuptools/uv *may* use PYTHONPATH-preempting mechanisms in other versions (finder hooks; historical easy-install `sys.path` reordering — see Sources), the design does NOT trust this statically: a **runtime probe** re-verifies precedence per compare with the exact child env, failing closed to exit 2. Eligibility relaxes only for `src/` legs; residuals stay fail-closed.

**B. Relevance-scoped refusal — REJECTED.** Deciding "is this dirty `src/` file relevant to this test file" statically is unsound in exactly the ways that matter: transitive imports (any oracle test → `select_step9c_tests` → `task_workflow` → dozens of modules), `conftest.py` fixture chains, dynamic imports (`importlib`, Hydra `instantiate`, lazy in-function imports), and non-`.py` package data with **no import edge at all** (`src/**/query_banks/*.json` via `importlib.resources` — the very case #1077's comment at lines 126-132 documents). A false "irrelevant" verdict is a **silent wrong strip** — a branch regression vouched as pre-existing, inverting the gate — and it fails silently, unlike A whose failure mode (probe fail) is a loud rc=2. B also duplicates half an import-graph analyzer inside a gate script for strictly worse guarantees than A's "shadow everything, relevance never matters".

**C. Hybrids — REJECTED.** (c1) Moving dirty-src detection into the verdict instead of eligibility just relabels the contamination, removes nothing. (c2) Per-issue namespace carve-outs (`src/**/issue_*/` tolerated) — fragile naming convention; #1190's dirt could equally touch shared modules. (c3) Give the scratch its own venv (`uv sync` in scratch — would also neutralize `pyproject.toml`/`uv.lock` dirt): rejected on cost — multi-GB torch install / network dependence / minutes per compare vs a free env var; noted as the only known way to ever relax the residual legs (out of scope).

### 4.1 New helper: `residual_scratch_contamination` (place after `scratch_contamination_probe`, ~line 414)

```python
def residual_scratch_contamination(paths: Iterable[str]) -> list[str]:
    """The contamination-probe paths a PYTHONPATH src-shadow CANNOT neutralize (#1251).

    src/-rooted dirt IS neutralized: the scratch pristine pytest runs with
    PYTHONPATH=<scratch>/src, so the scratch's HEAD-pinned package shadows the
    root venv's static editable .pth in sys.path order (verified per compare by
    assert_scratch_src_shadow). pyproject.toml / uv.lock dirt is NOT shadowable
    — the venv's INSTALLED DEPS derive from them — so those legs keep the
    fail-closed MF-4c exit 2. Any non-src/ path is residual by construction
    (fail-closed for oddballs, e.g. a top-level file literally named 'src').
    """
    return [p for p in paths if not p.startswith("src/")]
```

(`_porcelain_paths` already normalizes rename/quoting, so a plain prefix test is exact; every probe path is within `("src/", "pyproject.toml", "uv.lock")` by pathspec.)

### 4.2 New helper: `assert_scratch_src_shadow` (place after `remove_scratch_worktree`, ~line 534)

```python
def assert_scratch_src_shadow(root: Path, scratch_path: Path, timeout_s: float) -> None:
    """Verify PYTHONPATH=<scratch>/src actually WINS over root's editable install (#1251).

    Runs the ROOT venv interpreter (the exact interpreter run_pytest uses) with
    the exact child-env shape (inherited PYTHONPATH stripped, ours set) and
    importlib.util.find_spec's the package WITHOUT executing it; requires the
    resolved origin to sit under the scratch tree. Guards against editable-install
    styles that preempt sys.path order (meta-path finder hooks; easy-install-style
    .pth reordering), against a namespace-package refactor (find_spec origin is
    None => fail), and against a scratch missing src/ (origin resolves to root =>
    fail). Raises PristineRunError on ANY failure — the caller maps it to the
    fail-closed exit 2; a verdict never rests on an unverified shadow.
    """
    code = (
        "import importlib.util, sys\n"
        "spec = importlib.util.find_spec('explore_persona_space')\n"
        "origin = (spec.origin or '') if spec else ''\n"
        "sys.exit(0 if origin.startswith(sys.argv[1] + '/') else 3)\n"
    )
    try:
        python_exe = resolve_root_python(root)
    except ToolMissingError as exc:
        raise PristineRunError(str(exc)) from exc
    env = thread_capped(os.environ)
    env.pop("PYTHONPATH", None)
    env["PYTHONPATH"] = str(scratch_path / "src")
    try:
        proc = subprocess.run(
            [python_exe, "-c", code, str(scratch_path)],
            env=env, capture_output=True, timeout=timeout_s,
        )
    except (subprocess.TimeoutExpired, OSError) as exc:
        raise PristineRunError(f"src-shadow probe failed to run: {exc}") from exc
    if proc.returncode != 0:
        raise PristineRunError(
            f"src-shadow probe rc={proc.returncode}: PYTHONPATH={scratch_path / 'src'} did NOT "
            "win over the root venv's editable install — src dirt cannot be neutralized "
            "(fail-closed; --no-src-shadow restores the #1077 eligibility)"
        )
```

Cost: one interpreter startup + `find_spec` (~0.1-0.3 s), once per compare, only when the scratch is created. `find_spec` never executes the package (no heavy imports).

## 12. Decision Rationale

- **Which contamination legs remain blocking (`pyproject.toml`, `uv.lock`; `src/` relaxed).** What: `residual_scratch_contamination` keeps exactly the two dep-defining files. Why: installed deps derive from them and cannot be swapped by an env var; `src/` resolution CAN (verified). Source: read from code — `SCRATCH_CONTAMINATION_PATHSPEC` rationale (#1077, lines 126-133) + this session's venv verification. Alternatives: scratch-local `uv sync` (rejected, §3.C); relevance scoping (rejected, §3.B).
- **Shadow armed uniformly in scratch mode (not only when src dirt present).** What: every scratch pristine run gets `PYTHONPATH=<scratch>/src`. Why: hermetic against mid-loop src dirt; one code path; the shadow is content-identical to root when root src is clean. Source: design analysis of the per-file re-probe loop (lines 1174-1189). Alternatives: per-file conditional arming (rejected — reintroduces the mid-loop race the #1077 re-probe exists for).
- **Runtime probe fail-closed to exit 2 (no graceful degrade).** What: probe failure = `_Indeterminate`. Why: a failing probe means the venv's import machinery changed — a state that must surface loudly; `--no-src-shadow` is the deliberate manual degrade that exactly restores #1077 (including scripts-only decontamination, whose probe list is empty). Source: fail-fast Critical Rule + #1022's never-silent-fallback precedent (`resolve_root_python`). Alternatives: auto-degrade to #1077 eligibility on probe failure (rejected — hides the breakage; costs loop complexity for a hypothetical).
- **Inherited-PYTHONPATH strip retained; only caller-constructed value set.** What: `env.pop` stays unconditional; `pythonpath` kwarg set after. Why: the #1022 hazard (invoking worktree exports branch src) is ambient-env-shaped; the #1251 value is constructed from a HEAD-pinned tree — different trust classes. Source: `run_pytest` line 316 + #1022 round-2 Critical docstrings. Alternatives: pass-through of ambient PYTHONPATH (rejected — reopens #1022).
- **Escape-hatch shape: new `--no-src-shadow` alongside untouched `--no-scratch-fallback`.** What: two independent kill switches, nested semantics (fallback-off subsumes shadow-off). Why: preserves the pinned pre-#1077 restore verbatim while giving the new mechanism its own reversion; mirrors the #1077 flag precedent. Source: `build_parser` lines 1404-1408 + `test_compare_no_scratch_fallback_flag_restores_old_raise`. Alternatives: overload `--no-scratch-fallback` (rejected — changes a pinned flag's meaning).
- **JSON change additive (`scratch_src_shadow` bool) rather than a new `pristine_oracle` value.** What: keep `"scratch-worktree"`. Why: consumers (SKILL.md 9c prose, tests) reference the existing string; additive field is zero-risk. Source: grep of consumers. Alternatives: `"scratch-worktree+src-shadow"` value (rejected — gratuitous consumer churn).
