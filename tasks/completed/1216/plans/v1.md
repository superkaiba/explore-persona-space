### 4.1 Heredoc emission change (`gpu_probe`, ~:1534-1549)

Add a second counter inside the existing `-n "$ZOMBIE"`-guarded scan; emit a fourth key on both branches:

```
   "  UVM_HOLDERS=unknown; UVM_ALLOC_HOLDERS=unknown; "
   '  if [ -n "$ZOMBIE" ]; then '
   "    UVM_HOLDERS=0; UVM_ALLOC_HOLDERS=0; "
   "    for p in /proc/[0-9]*; do "
   '      if ls -l "$p/fd" 2>/dev/null | grep -q " -> /dev/nvidia-uvm$"; then '
   "        UVM_HOLDERS=$((UVM_HOLDERS+1)); "
   '        if grep -qm1 " /dev/nvidia[0-9]" "$p/maps" 2>/dev/null; then '
   "          UVM_ALLOC_HOLDERS=$((UVM_ALLOC_HOLDERS+1)); "
   "        fi; "
   "      fi; "
   "    done; "
   "  fi; "
   ...
   '  echo "NVIDIA_UVM_ALLOC_HOLDERS=$UVM_ALLOC_HOLDERS"; '
```

- Else-branch (no nvidia-smi) additionally emits `NVIDIA_UVM_ALLOC_HOLDERS=unknown`.
- The inner allocation-evidence line is the **gate-finalized literal** — presumptive S2 (maps device-node entry, pattern ` /dev/nvidia[0-9]`, which excludes `-uvm`/`ctl`/`-tools`/`-caps` by the digit-after-`nvidia` requirement and cannot match non-`/dev` paths because the space anchors the path start). Fallback order per §7 measurement: S2 → S1 (fd-target count `ls -l "$p/fd" | grep -q " -> /dev/nvidia[0-9]"`) → S2∨S3 composite (S3 = maps ` /dev/nvidia-uvm$` entry) → disposition D2 (no signal separates).
- Fail direction preserved: an unreadable/vanishing proc (`2>/dev/null`) simply doesn't count → lower alloc count → less suppression → #826 fall-through. A whole-scan failure leaves `unknown` → parser `None` → fall-through. Scan still runs only when a zombie candidate exists (R4); the extra check runs only per MATCHED holder (5 procs on pod-813; the full 1600-proc fd scan measured ~instant in #864).

## 11. Decision Rationale

- **Predicate threshold `alloc_holders > 0` (not `>= gpu_pids_total`).** Why: correspondence counting has a structural off-by-one TP mask (total=1 collapse + 1 coordinator → 1≥1 → suppressed) and monotone bystander inflation. Source: #864 §7 measured pod-813 counts (5 holders vs 4 apps — the off-by-one is empirically real) + §3.5 analysis. Alternatives: correspondence counting (rejected, T10 pins the rejection), per-PID identity matching (refuted in #864 — NSpid outer→inner only).
- **Presumptive signal S2 (maps device-node entry) with pick order S2→S1→S2∨S3.** Why: context creation maps per-GPU device regions and UVM allocations are file-backed `/dev/nvidia-uvm` mmaps, while bare cuInit is fd-level. Source: web findings cited in §2 (Bruce-Lee-LY UVM writeup; IITK UVM driver study; NVIDIA device-files reference); the final literal is `Source: ungrounded — decided by the §7 measurement pass` by design (that is the gate's job).
- **`ZOMBIE_GPU_MEM_MIN_MIB = 1024` unchanged.** Source: #664 (poll_pipeline.py:601-606).
- **Synthetic worker allocation 2.5 GiB.** Why: must clear the 1024 MiB zombie floor with margin so the worker registers in compute-apps as floor-eligible. Source: `ZOMBIE_GPU_MEM_MIN_MIB` #664; 2.5× margin.
- **Gate repeats ×2, vLLM attempts ≤2/30 min.** Why: the signals are deterministic per process state; repeats guard launch-order flakiness, and the bound keeps the pod ≤2 h. Source: #864's single-shot gate precedent + margin (stated judgment, low sensitivity).
- **vLLM model Qwen/Qwen2.5-0.5B-Instruct.** Why: smallest in-family model; house family. Source: project model line (CLAUDE.md).
- **Default flip conditional shape (`"1"` only under D1).** Source: #864 disposition-2 precedent (`<DEFAULT>` placeholder pattern, epm:results v1 on #864) + this task's Goal (gate-gated, not mechanical).
- **Kill-switch read-at-import semantics unchanged.** Source: #864 residual note (c); hard invariant in the task body.
