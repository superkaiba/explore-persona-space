## 0.0 TL;DR (plain English)

Three always-loaded agent-memory files and one production error message still
tell an agent or operator to "pin `backend: gcp`" as the fix for a problem.
Since #2028, that pin does not fall back or degrade — it raises immediately
and blocks the task. Anyone following those four sites walks into a dead end
at the worst possible moment (mid-debug of an already-failed launch). This
plan corrects those four sites and adds a WARN-level lint check so the class
cannot silently regrow.

The task's ORIGINAL ask — add a prose caution to CLAUDE.md against habitually
pinning gcp — is dropped as superseded: that caution already exists in
stronger form, and #2028 replaced persuasion with a hard mechanical refusal.

**What would change my mind:** if `GCP_PROVISIONING_DISABLED` were reverted to
`False` before this lands, every D1-D4 correction becomes wrong and the D5
check becomes noise — I would abandon the edits and keep only the
SKIP-on-rollback arm. If the D6 test-8 live-surface run cannot be brought to
zero WARNs without contorting the annotation rules (more than one
special-case escape beyond the three enumerated shapes), the check is
mis-designed — drop D5, ship D1-D4 alone, and record why.

**Kill criteria (halt and report, do not push through):** (a) the D4 edit
requires changing `_assert_repo_branch_synced` CONTROL FLOW rather than its
message string — that is behavioral scope this plan did not review, so halt;
(b) making the live surface WARN-free requires editing any file outside the
D1-D4 list or annotating a site whose guidance is actually still correct —
halt rather than widen; (c) the D6 tests cannot distinguish the
file-scope-banner shape from a true miss, meaning the check would either
false-positive on `compute-backend-failover.md` or false-negative on new
guidance — halt and re-plan D5.

- **Scan set:** `.claude/agents/**.md`, `.claude/skills/**/SKILL.md`,
  `.claude/rules/**.md`, `.claude/agent-memory/**.md`, `CLAUDE.md`,
  `src/explore_persona_space/backends/*.py`, `scripts/dispatch_issue.py`.
  EXCLUDE `.claude/worktrees/` and `.claude/cache/` (full checkouts + caches;
  the #911 non-canonical-cache precedent for why those are never the live
  surface).
- **Triggers** (family A — imperative pin directives — ONLY; see D9 for why
  family B is rejected as a trigger):

  | id | pattern |
  |---|---|
  | `cli-pin` | `--backend\s+gcp\b` |
  | `kv-pin` | `(?<![\w\-])backend\s*[:=]\s*['"`+"`"+`]?gcp\b` |
  | `route-imperative` | `\broute\b[^.\n]{0,60}\bto\s+GCP\b` (case-insensitive; `\broute\b` deliberately excludes "routed"/"routes", which are narrative, not imperative) |

- **`.py` gating:** a `.py` line is considered ONLY when it falls inside an
  `ast.Constant` str node whose value is ≥ `MIN_PY_LITERAL_CHARS = 40`. The
  operator-facing hazard in code is MESSAGE TEXT (D4's exact shape); comments
  are developer-facing history and are out of scope by construction. An
  unparseable `.py` file is a loud SKIP for that file, never a crash.
- **Annotation escape:** the hit is CLEAN when one of `#2028`,
  `GcpDisabledError`, `GCP_PROVISIONING_DISABLED`, `gcp_backend_disabled`,
  `REFUSED`, `DISABLED` (the last two UPPERCASE only) appears on the same
  line, OR anywhere in the preceding `ANNOTATION_WINDOW = 40` lines, OR in the
  file's first 40 lines (the top-of-file scope-banner form that
  `.claude/rules/compute-backend-failover.md` uses — its banner explicitly
  scopes "Every GCP section below", which is why its `:245` / `:679` hits read
  correctly today and must NOT be flagged). `REFUSED` / `DISABLED` are
  load-bearing, not decorative: `.claude/skills/issue/SKILL.md:4005` and
  `.claude/rules/pod-side-reporting.md:584` annotate correctly with those
  words and no `#2028`, and false-positived when the set was tightened without
  them.
- **Severity: WARN-only, never a non-zero exit.** Rationale: the check runs in
  the no-flags default dispatch set, which the Step 9c test-verdict gate
  consumes fleet-wide (#1388 — two inline-landed lint-red scripts broke that
  gate for every task). A guidance-hygiene check must never be able to red the
  fleet gate. The binding enforcement for the gcp case is the mechanical
  refusal at `router.py:790`, not this lint.
- **Rollback behavior:** when `GCP_PROVISIONING_DISABLED` is flipped to
  `False`, this check becomes noise. Read the constant from `router.py` source
  text (read-only, no import — the check-37 precedent) and SKIP the whole
  check when it is `False`. A read failure degrades to a loud SKIP, never a
  crash.
- Register in the no-flags default dispatch set and in the `--help` list.
