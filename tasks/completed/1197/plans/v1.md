## 11. Decision Rationale

1. **Uniform always-background (vs `--run-pristine`-conditional vs a two-phase fast path).**
   *What:* every step-1d compare runs backgrounded.
   *Why:* the canonical block ALWAYS passes `--run-pristine` (SKILL.md L7747), so flag-conditional backgrounding is vacuous; bucket contents are unknowable before running compare (the bucket is computed inside it, `step9c_baseline.py` L1123-1156), so SLOW_TESTS-conditional is impractical (the brief concurs). The genuine alternative — a foreground no-pristine first pass, re-run backgrounded on a pristine-needed exit 2 — re-executes the ruff baseline + junit work, adds a parse-the-exit-2-reason branch, and maintains two patterns for one step; its only benefit is skipping one background round-trip (~10-60s) on the common empty-bucket path. Uniformity also makes ALL of Step 9c (1b, 1c, 1d) one pattern.
   *Source:* SKILL.md 1b block ("BACKGROUND IS REQUIRED, NOT OPTIONAL", #991/#996/#906); `step9c_baseline.py:1163-1170`; #1129.
   *Alternatives rejected:* two-phase fast path (complexity + duplicated work); flag-conditional (vacuous).

2. **Wedge bound `<T> = 10800s` (3h).**
   *What:* `timeout --kill-after=60s 10800s` as the compare's only wedge bound.
   *Why:* sized off compare's own in-process ceiling — `--max-pristine-files` 5 × max per-file derived bound 1950s (`derive_pristine_timeout_s`: 120+30+2×900 for `tests/test_workflow_lint.py`; every other file floors at 600s; >5 files → exit 2 with NO runs) = 9750s structural ceiling, + `--scratch-timeout-s` 120s + ruff/junit-parse overhead → 10800s. Today's *realizable* worst is 1950 + 4×600 + 120 + overhead ≈ 4650s, but the bound is a background wedge backstop whose only oversize cost is later self-termination of an already-wedged run — the #1129 generous bias applies verbatim ("an undersized one GUARANTEES a wasted compare + rerun"). Comment in the block ties the number to the formula so SLOW_TESTS growth triggers a re-derive.
   *Source:* `step9c_baseline.py:926-952, 1156-1162`; `select_step9c_tests.py:223-232`; #1129/#1098.
   *Alternatives rejected:* 3600s (< today's realizable 4650s worst — recreates the bug one level up); 7200s (busted if SLOW_TESTS grows to ≥3 concurrently-bucketed slow files); no bound (violates the never-unbounded convention every 9c invocation follows).

3. **Add the #1045 self-choom (reverse "accepted unprotected").**
   *What:* the fail-open −600 self-choom preamble, with a distinct `[step9c] compare earlyoom protection choom=…` breadcrumb recorded in the `epm:test-verdict` note.
   *Why:* the original exemption's justification ("short/bounded foreground") is exactly what this fix removes; a backgrounded compare running up to ~77 min of pytest IS the earlyoom-preferred long python work (#906 killed twice, #995 at ~42%). Reachability verified: `run_pytest` launches the pristine child with `start_new_session=True` (`step9c_baseline.py:317-323`), but `oom_score_adj` inherits across fork/exec and `setsid` does not reset it (SKILL.md L7714-7716, "probe-verified") — so choom-ing the shell BEFORE `uv run python` starts covers the whole tree. The refresh leg's session-sweep form is NOT needed here: that form exists only for post-hoc chooming of an already-detached process.
   *Source:* #1045/#1046 (SKILL.md L7713-7736); `step9c_baseline.py:303-323`; #906/#995.
   *Alternatives rejected:* keep unprotected (justification gone); session-sweep (wrong tool — pre-launch self-choom is strictly simpler and race-free).

4. **Separate stderr file (`.err`) instead of 1b's merged `2>&1` log.**
   *What:* `> .json 2> .err`.
   *Why:* stdout is the machine-parsed JSON verdict ("COMPARE_OUT is valid JSON on EVERY exit path under --json"); merging stderr would corrupt it. The `.err` tail is the #665/#736 evidence channel on a timeout/kill.
   *Source:* SKILL.md L7764-7766; #665/#736.

5. **In-call `[ -f ]` hard-guard + re-read of the 1b rc file.**
   *What:* the background call re-reads `/tmp/step9c-rc-issue-<N>` itself and exits FATAL if absent.
   *Why:* shell variables do not survive across Bash calls (the 1b lesson, #1046); an empty `--pytest-rc ""` would die on argparse with a confusing error instead of the named FATAL.
   *Source:* SKILL.md L7637-7640, L7701-7707.
