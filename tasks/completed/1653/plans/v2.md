## 3. Requirement + acceptance criteria

Requirement: after this change, a confirmed stranded-merge episode with no live owning session self-recovers via one watcher-dispatched `spawn-issue --auto` within ~1 interval of its first flag, while every existing flag/push/probe behavior and every never-merge invariant is preserved.

Testable acceptance criteria (each maps to a §6 test):

1. **First-interval flag unchanged:** on the interval an episode is first flagged, the pass posts the flag marker + push + sidecar row and does NOT dispatch any spawn.
2. **Second-interval respawn:** on a later interval with the same (issue, done_ts) episode still stranded (verdict `unmerged-open-pr` or `unmerged-branch-commits`), owner check returning False, day budget available, and the arm enabled, the pass dispatches exactly one `spawn-issue --issue <N> --auto`, posts one respawn marker (new sentinel), fires one push, appends a sidecar row with `action: "respawned"`, and latches `respawned_ts`/`respawn_result` on the episode.
3. **Once per episode:** subsequent intervals on the same episode never dispatch again (latched), while flag-channel behavior (sidecar row per interval, 24h push TTL) continues unchanged. A NEW done_ts opens a new episode that may respawn once again.
4. **Live-owner / unknown skip:** owner check returning True (live owner) or None (daemon unreachable / `_live_children` strict failure) skips the dispatch, consumes NO day budget, does NOT latch the episode, and leaves all flag channels unchanged; the next interval re-evaluates.
5. **Day cap:** with `respawns_today >= cap` (default 3, fleet-wide), no dispatch occurs and no episode latch is written; a rolled UTC day re-arms the budget.
6. **Suppressed books nothing:** an auth-outage-gate suppression, or a spawn-side suppression (`spawn_output_suppressed` — lease/collision/takeover/auth-hold), consumes no day budget and no episode latch (#843 M1b semantics).
7. **Kill switch:** `EPM_DISABLE_COMPLETED_UNMERGED_RESPAWN=1` restores byte-equivalent flag-only behavior (marker text included — the FLAG-ONLY sentence returns); default (unset) is ENABLED.
8. **Never merge/mutate (KEPT):** in all paths, no recorded subprocess argv contains `set-status`, a `merge`, or a `push`, and in-process `task_workflow.set_status`/`post_event` are never touched; the ONLY new argv class is the `spawn-issue --issue <N> --auto` dispatch. No `git fetch`, ever.
9. **Dry-run:** `--dry-run` performs zero writes and zero spawn subprocess calls; respawn intent is print-only.
10. **Pins amended deliberately:** docstring, module header, CLI help, `background-automation.md`, and the CLAUDE.md bullet all describe the new contract (flag + bounded respawn; never merges/pushes/mutates status); the respawn sentinel is registered in `_WATCHER_NOTE_SENTINELS`.

### 4.3 Pure decision function (insert between `_completed_unmerged_flag` ~6835 and `completed_unmerged_pass` 6838)

```python
def decide_completed_unmerged_respawn(
    *,
    respawn_enabled: bool,
    prior_flagged: bool,
    already_respawned: bool,
    respawns_today: int,
    owner_live: bool | None,
    max_per_day: int,
) -> str:
    """Pure decision for the #1653 respawn arm. Returns one of:
    "respawn" | "skip-disabled" | "skip-first-interval" |
    "skip-already-respawned" | "skip-day-cap" | "skip-owner-live" |
    "skip-owner-unknown". Cheap gates first so the impure caller can
    pre-evaluate with owner_live=False and probe the daemon ONLY when
    everything cheap passes (the probe is the one expensive signal).
    Every uncertain signal fails toward skip (decide_capacity_retry /
    #1582 unknown-freeze posture)."""
    if not respawn_enabled:
        return "skip-disabled"
    if already_respawned:
        return "skip-already-respawned"
    if not prior_flagged:
        return "skip-first-interval"      # persistence: flagged on a PRIOR interval
    if respawns_today >= max_per_day:
        return "skip-day-cap"
    if owner_live is None:
        return "skip-owner-unknown"       # daemon down / children unreadable
    if owner_live:
        return "skip-owner-live"
    return "respawn"
```

Persistence decision: **"flagged on a prior interval" IS the persistence signal** — `prior_flagged = entry.get("done_ts") == done_ts and entry.get("flagged") is True`, computed from the episode entry BEFORE `_completed_unmerged_flag` rewrites it. The pass is hourly self-gated, so this guarantees ≥ ~1 interval (~1h) between first flag and respawn, on top of the 2h done-grace — worst-case automation latency ≈ grace 2h + 2 intervals ≈ 4h vs 16h/#1540. It also gives a human (already pushed at episode open) an hour to intervene.

### 4.4 Live-owner probe (same insertion block)

```python
def _completed_unmerged_live_owner(issue: int) -> bool | None:
    """True = a live session owns the issue; False = provably none; None =
    unknowable (fail toward NO respawn). Reuses the #1582 owner-candidate
    union: registration sids (issue-<N>.json + manual-issue-<N>.json)
    resolved through the /list children sid->pid map, PLUS cwd-mapped
    children (the #1345 unregistered-owner class). Daemon-gated here — the
    flag half of the pass stays daemon-independent; only this probe (and
    thus the respawn arm) needs the daemon."""
    try:
        if not _daemon_reachable():
            return None
        children = _live_children(strict=True)   # strict: a /list flake raises
    except RuntimeError:
        return None
    return bool(_keep_running_owner_candidates(issue, children))
```

### 4.5 Dispatch helper (clone of `_redrive_capacity_retry`, 18031)

```python
def _completed_unmerged_respawn(issue: int, dry_run: bool) -> str:
    """spawn-issue --auto for a confirmed stranded merge; the fresh session's
    /issue resume row (#1578, SKILL.md Step 0 resume table) runs the Step 10d
    idempotent backstop. Tri-state "spawned" | "suppressed" | "failed"
    (#843 M1b: suppressed books nothing). dry_run: log-only, returns
    "failed" (parity with _redrive_capacity_retry)."""
    if _auth_outage_spawn_gate(issue, "completed-unmerged", dry_run=dry_run) is not None:
        print(f"  completed-unmerged: respawn #{issue} suppressed — auth-outage episode active")
        return "suppressed"
    cmd = ["uv", "run", "python", "scripts/spawn_session.py", "spawn-issue",
           "--issue", str(issue), "--auto"]
    if dry_run:
        print(f"  [dry-run] would respawn stranded-merge session: {' '.join(cmd)}")
        return "failed"
    res = subprocess.run(cmd, cwd=PROJECT_ROOT, capture_output=True, text=True, timeout=120)
    if res.returncode != 0:
        print(f"  COMPLETED-UNMERGED RESPAWN DISPATCH FAILED #{issue}: "
              f"{res.stderr.strip()[:300]}", file=sys.stderr)
        return "failed"
    _forward_marker_child_stderr(res, "spawn_session spawn-issue (completed-unmerged)")
    first_line = (res.stdout.strip().splitlines() or [""])[0]
    if spawn_output_suppressed(res.stdout) is not None:
        print(f"  completed-unmerged: respawn #{issue} suppressed (lease/collision/hold): "
              f"{first_line}")
        return "suppressed"
    print(f"  COMPLETED-UNMERGED RESPAWNED #{issue}: {first_line}")
    _auth_outage_record_spawn(issue, "completed-unmerged", None)
    return "spawned"
```

`"completed-unmerged"` is deliberately NOT added to `_AUTH_OUTAGE_CANARY_ARMS` (7023): during an auth-outage episode the arm is fully suppressed (a stranded merge is not time-critical; the flag/push channels keep firing and the episode retries next interval; the gate's fail-open TTL bounds the delay).

### 4.6 Orchestration wrapper (same block)

```python
def _completed_unmerged_maybe_respawn(
    issue, done_ts, verdict, episodes, state, now, day_key, prior_flagged, dry_run
) -> None:
    key = str(issue)
    entry = episodes.get(key) or {}
    max_per_day = _completed_unmerged_respawns_per_day()
    respawns_today = _day_scoped_count(state, "respawn_day", "respawns_today", day_key)
    common = dict(
        respawn_enabled=_completed_unmerged_respawn_enabled(),
        prior_flagged=prior_flagged,
        already_respawned=entry.get("respawned_ts") is not None,
        respawns_today=respawns_today,
        max_per_day=max_per_day,
    )
    pre = decide_completed_unmerged_respawn(owner_live=False, **common)
    if pre != "respawn":
        if pre not in ("skip-disabled", "skip-first-interval"):   # keep logs quiet on the common paths
            print(f"  completed-unmerged: respawn #{issue} {pre}")
        return
    owner = _completed_unmerged_live_owner(issue)                 # the one expensive probe
    action = decide_completed_unmerged_respawn(owner_live=owner, **common)
    if action != "respawn":
        print(f"  completed-unmerged: respawn #{issue} {action}")
        return
    result = _completed_unmerged_respawn(issue, dry_run)
    if result == "suppressed":
        return                                                    # book NOTHING (#843 M1b)
    # Book the attempt (spawned OR failed): fleet day counter + episode latch
    # (constraint (d): strictly once per (issue, done_ts) episode).
    state["respawn_day"] = day_key
    state["respawns_today"] = respawns_today + 1
    entry["respawned_ts"] = now
    entry["respawn_result"] = result
    episodes[key] = entry
    _save_completed_unmerged_state(state, dry_run)                # latch-first: a later crash can't double-spawn
    _append_completed_unmerged_sidecar(
        {"issue": issue, "done_ts": done_ts, "verdict": verdict, "action": "respawned",
         "result": result, "respawns_today": respawns_today + 1, "dry_run": dry_run},
        dry_run,
    )
    if result == "spawned":
        done_iso = _triage_observer_iso_z(done_ts)
        _post_progress_marker(
            issue,
            f"{_COMPLETED_UNMERGED_RESPAWN_NOTE_SENTINEL} stranded merge persisted a full "
            f"interval past the flag (epm:done {done_iso}, no epm:merged, {verdict}); no live "
            f"session owns this issue — auto-respawned via `spawn-issue --issue {issue} --auto` "
            f"(once per episode, {respawns_today + 1}/{max_per_day} today; #1653). The fresh "
            f"session's /issue resume row runs the Step 10d auto-merge backstop (#1578). The "
            f"watcher itself never merges/pushes or mutates status.",
            dry_run,
            label="completed-unmerged-respawn",
        )
        _telegram_push(
            f"EPS #{issue}: stranded merge (epm:done {done_iso}, no epm:merged) auto-respawned "
            f"— spawn-issue --auto dispatched to run Step 10d ({respawns_today + 1}/{max_per_day} "
            f"today; #1653). Watcher never merges.",
            dry_run,
        )
```

## 11. Decision Rationale

- **Day-cap value = 3/day, FLEET-wide (not per-issue).**
  What: `COMPLETED_UNMERGED_RESPAWNS_PER_DAY = 3`, env `EPM_COMPLETED_UNMERGED_RESPAWNS_PER_DAY`, malformed-or-`<1`→default guard.
  Why: the once-per-episode latch already bounds per-issue churn to 1, so the day cap's job is bounding fleet-wide pathology (e.g. a registry corruption opening many false episodes); observed incident rate is 2/month, so 3/day is ≥40× headroom.
  Source: #1241 `TICK_WEDGE_RESPAWNS_PER_DAY = 3` + #1209 `TICK_WEDGE_DEAD_RESPAWNS_PER_DAY = 3` (watcher lines 1944–2005); parse-shape clone of `_tick_wedge_respawns_per_day`.
  Alternatives: capacity-retry's 4/day (per-issue — wrong grain here); orphan's 2/day (tighter, but that lane has no once-per-episode latch; 3 keeps consistency with the wedge family named in the task).
- **Persistence signal = "flagged on a PRIOR interval" (`prior_flagged`).**
  What: respawn eligible only when the episode entry already carried `flagged: True` for the same done_ts at loop entry.
  Why: the pass is hourly self-gated, so this is a free, state-backed ≥1-cycle persistence check (task constraint (c)); it also guarantees the human push preceded any automation by ≥1h.
  Source: the task body's own design constraint (c) + the pass's interval-gate mechanics (#1564, lines 6890–6896).
  Alternatives: a separate min-age timestamp (redundant with the interval gate + grace); immediate respawn on first flag (rejected — removes the human-first hour and couples respawn to the probe's first read).
- **Kill switch `EPM_DISABLE_COMPLETED_UNMERGED_RESPAWN`, default ENABLED.**
  What: dedicated opt-out env; whole-pass switch unchanged and superior.
  Why: the Goal is automation-by-default; the arm is non-destructive (a wrong spawn is suppressed by lease/Step-0 guard or costs one idle session, vs the destructive stop/reap lanes that default opt-in), and it is quintuple-gated. Default-off would reproduce today's manual state and make the fix a no-op until someone flips an env fleet-wide.
  Source: default-on precedent of every non-destructive respawn lane — capacity-retry `EPM_DISABLE_CAPACITY_RETRY` (#642), wedge lanes (#1209/#1241), orphan sweep; the opt-IN precedent (`EPM_ORPHAN_WRAPPER_REAP`, #1215) is scoped to destructive stop arms, which this is not.
  Alternatives: default-off + a dogfood window (rejected: the watcher review pipeline + dry-run tests are the dogfood; the flag channels remain intact as fallback).
- **Once-per-episode = latch on ANY dispatch that reaches the subprocess (`spawned` OR `failed`); `suppressed` books nothing.**
  What: strict reading of constraint (d); tri-state semantics.
  Why: constraint (d) says bounded ONCE per episode; a dispatch failure with the daemon already probed reachable is rare and the flag/push channels persist, so losing automation for that one episode is the safe, simple contract. Suppression means "someone else owns this" — booking nothing lets the next interval re-evaluate honestly.
  Source: #843 M1b (`_redrive_capacity_retry` suppressed-books-nothing); capacity-retry's count-the-attempt-on-failure posture (18127–18131).
  Alternatives: small per-episode retry budget on `failed` (rejected: complexity for a rare case the human channel already covers).
- **Owner check = daemon `/list` + `_keep_running_owner_candidates`, fail toward skip; single `_daemon_reachable()` probe (not `_with_retry`).**
  What/Why: the #1582 owner union is the strongest existing check (registrations + cwd-mapped unregistered owners); None/unknown must never respawn (a wrong spawn races a live session — the #958/#1112 teammate-race class). The single probe suffices because a false negative merely defers one hour (nothing expensive idles, unlike #811's GPU case that motivated the retry variant).
  Source: `_keep_running_owner_candidates` (10603, #1582); `_daemon_reachable` docstring (7900); #811/#845 for the retry tradeoff explicitly considered and declined.
  Alternatives: registration-sid-only check (misses #1345-class unregistered owners — rejected); `_daemon_reachable_with_retry` (acceptable; implementer MAY swap it in without re-plan — see deviations).
- **NOT a canary arm.** What: `"completed-unmerged"` stays out of `_AUTH_OUTAGE_CANARY_ARMS`. Why: canary spawns exist to probe auth recovery on time-critical lanes; a stranded merge tolerates the episode TTL, and adding a 6th canary arm widens the probe surface for no benefit. Source: #1027 design (7023–7025). Alternatives: include it (harmless but unnecessary).
- **Respawn marker + push on success only; skips print-only.** Why: marker/push are once-per-episode by construction (the latch); logging skips to the sidecar every interval would triple stream noise for zero recovery value. Source: capacity-retry posts only on `ok` (18137–18146); flag sidecar already rows every interval.
