## 4. Design

Scope: exactly two files — `scripts/select_step9c_tests.py` + `tests/test_select_step9c_tests.py`. Why code, not a model call: the selector is deterministic path arithmetic by charter (module docstring: "no model call, no new dependency"); a model call has no place in a test-selection gate.

### Design decisions (the 7 questions, resolved)

**D1 — Stem arm extends to `.sh`, BOTH exact and broad glob.** Minimal diff: the suffix gate at :922 becomes `if p.suffix in (".py", ".sh"):`; the arm body (exact `tests/test_<stem>.py` + broad `tests/test_*<stem>*.py` glob + `matched` + `untested.append`) is byte-unchanged. The broad glob applies to `.sh` stems too because (a) it carries real coverage: `scripts/bootstrap_pod.sh`'s two genuinely-relevant suites (`test_bootstrap_pod_git_credentials.py`, `test_bootstrap_pod_path.py`) are reachable ONLY via the broad glob (no exact `test_bootstrap_pod.py` exists); (b) over-match is measured-small: enumerating every tracked `scripts/*.sh` + `.claude/hooks/*.sh` against `tests/test_*<stem>*.py`, the worst case is `scripts/persona.sh` → 3 files (`test_persona_pool.py`, `test_per_persona_cot_distinct.py`, `test_build_canonical_persona_pool_upload.py`), next `bootstrap_pod.sh` → 2, everything else ≤1; (c) the module docstring's `safe-by-direction` doctrine (L59-63) explicitly accepts over-matching — "running a few extra invariant-adjacent tests is the safe failure direction."

**D2 — YES, `literal_path_targets` gains a `.sh` eligibility branch.** The #1498 rationale applies identically: a test hardcoding `scripts/guard_repo_root_branch.sh` (3 references in `tests/test_guard_repo_root_branch.py` — fact-checked count) is pinning evidence. The `.py` branch stays byte-identical (prefixes `scripts/` | `src/explore_persona_space/`, unchanged); a new `.sh` branch uses prefixes `scripts/` | `src/explore_persona_space/` | `.claude/hooks/`. This one edit also automatically extends: (i) the literal-path discovery in `_scan_test_files` (`.sh` paths join `literal_targets`; the token pre-filter comes from `touched_module_names`, which stays `.py`-only, so a `.sh`-only diff scans with ZERO AST parses — the same documented cost class as the `scripts/__init__.py` literal-only trigger, docstring L93-95); (ii) `dependency_map_pairs`' stem arm (:451, which iterates `literal_path_targets(files)`), so `--map-files` emits `.sh` stem pairs; (iii) the #1573 zero-mapped WARN floor in `main()` (:1133, `literal_path_targets(files) - mapped`), so an unmapped eligible `.sh` payload draws the fail-loud stderr WARN in mapping mode.

**D3 — YES, unmatched `.sh` files enter `untested_touched`.** This falls out of the D1 minimal diff (the `untested.append(f)` is inside the now-shared branch) and is the deliberate choice, not an accident: the doctrine is "a missed mapping surfaces as an `untested_touched` WARN, never a silently-dropped file" (docstring L62-63), and the clarifier flagged the silent invisibility as part of the gap. No extra scoping predicate: `.py` experiment scripts (`scripts/issue<N>_*.py`) already WARN on exactly the same terms today, so a diff adding `scripts/issue<N>_dispatch.sh` gains one WARN line symmetric with its `.py` siblings. Files under `docs/`/`tasks/`/`.claude/rules|skills|agents(.md)`/etc. never reach the stem arm (the `WORKFLOW_SURFACE_GLOBS` + `_DATA_DOC_SUFFIXES` short-circuits precede it, unchanged). `external/**` and `experiments/**` `.sh` files WILL warn if touched — precedent: `external/**.py` files already do (no surface glob covers them); such diffs are rare (reference-codebase vendoring) and the WARN is exit-0.

**D4 — YES, `.claude/hooks/*.sh` is in scope.** Hooks genuinely live there (7 tracked files; 6 `.sh` with exact stem tests — the majority of the guard-suite inventory) as well as at `scripts/guard_repo_root_*.sh`. For the DIFF path they are covered automatically by D1 (the stem arm is prefix-unrestricted — it checks `WORKFLOW_SURFACE_GLOBS` first, which has no `.claude/hooks/` entry, then maps any non-surface, non-data code file). For the `--map-files`/literal path they need the `.claude/hooks/` prefix in D2's `.sh` branch, which is why it's there. The `.py` eligibility prefixes are NOT widened (`.claude/hooks/guard_lessons_edit_check.py` keeps today's behavior — byte-identical constraint).

**D5 — `--map-files` consumer interaction: additive, verified per consumer.** Enumerated consumers of the selector (grep across `scripts/`, `.claude/`, main tree): `.claude/skills/issue/SKILL.md` (Step 9c + Step 10d), `scripts/inline_lint_gate.py`, `scripts/step9c_baseline.py`, `scripts/verify_plan.py` (c41 loads the module and runs its pure selection functions). Verified reads: `inline_lint_gate.py` does a "pair-generic TSV parse of `--map-files` stdout: keep the first two" columns (:224) and recomputes the timeout locally in parity with the sizing formula (`mapped_pytest_timeout()` — fact-checker corrected: NOT a stderr-line parse; scales with `len(tests)` identically) — new `.sh` pairs flow through unchanged; `step9c_baseline.py compare`'s diff-linked read computes `diff_linked = {t for t, rs in reasons.items() if any(r != "invariant" for r in rs)}` (:1409-1412) — reason-kind-agnostic, so new `stem-map:<x.sh>` / `literal-path:<x.sh>` reasons simply mark those tests diff-linked (additive; the R-F′ scan-set refusal is `GLOB_SCAN_TESTS`-specific and untouched); `verify_plan.py` c41 calls `select_tests_with_reasons` — more selection is the safe direction there too. Behavior change to name: a `.sh`-only Step-10d/inline payload previously produced an EMPTY map (gate leg skip); it now produces real pytest pairs, so the TG leg runs tests it never ran before. The gates' payload-attributed verdict + baseline machinery already handle pre-existing red for `.py` payloads via the same pairs; `.sh` inherits identically. This is the intended fix, not a side effect.

**D6 — Drift pins:** 10 new cases (71–80) in `tests/test_select_step9c_tests.py`, spec below.

**D7 — Import-map arm (`touched_module_names`, :652-692) is OUT of scope for `.sh`, deliberately.** Shell scripts are not importable Python modules; `touched_module_names` keeps its `.py` gate byte-unchanged, so `.sh` files contribute no module tokens, no AST parses, and never suppress their own `untested_touched` WARN via `import_tested`. Stated here so review does not flag it as a missed arm.

**Rejected alternative (the Goal's "or register guard tests in the appropriate mapping table"):** adding the 8 `tests/test_guard_*.py` to `WORKFLOW_INVARIANT` is strictly worse: (a) it runs them on EVERY Step 9c gate regardless of diff; (b) it recreates the #1496 founding bug (each future guard suite needs manual registration or silently doesn't gate); (c) decisively — `WORKFLOW_INVARIANT` members are EXCLUDED from `--map-files` pairs by design (`dependency_map_pairs` :444, `rules_pin_pairs` :416), so invariant registration would leave the Step-10d TG leg with ZERO pytest for `.sh` payloads, failing half the filed bug. `GLOB_SCAN_TESTS` registration is also wrong (those are directory-scanning tests; map hits deliberately never set `matched`). The stem/literal extension is discovery-based and self-extending: a future `scripts/guard_new.sh` + `tests/test_guard_new.py` pair gates with no selector edit.

```python
# .sh eligibility prefixes for the literal/stem map arms (#1579): workflow shell
# scripts live under scripts/ and .claude/hooks/ (6 of the 8 guard suites map to
# hook scripts there); src/ included for symmetry with the .py branch (no tracked
# .sh today — zero current cost, no future gap).
_SH_ELIGIBLE_PREFIXES: tuple[str, ...] = (
    "scripts/",
    "src/explore_persona_space/",
    ".claude/hooks/",
)


def literal_path_targets(touched: list[str]) -> set[str]:
    """Touched files eligible for the literal-path arm (#1498; .sh joined #1579).

    Eligible: ``.py`` code files under ``scripts/`` or
    ``src/explore_persona_space/`` (UNCHANGED — byte-identical to the #1498
    predicate), plus ``.sh`` scripts under ``scripts/``,
    ``src/explore_persona_space/``, or ``.claude/hooks/`` (#1579 — guard
    hooks / workflow shell scripts whose pinned suites hardcode the script
    path or stem-name themselves after it). Never ``tests/`` (the
    touched-test arm owns those). Each returned repo-relative path is matched
    as a raw substring of every scanned test file's text; this set is ALSO
    the stem-arm eligibility for ``--map-files`` (dependency_map_pairs) and
    the #1573 zero-mapped WARN floor.
    """
    out: set[str] = set()
    for f in touched:
        if f.startswith("tests/"):
            continue
        suffix = Path(f).suffix
        if suffix == ".py" and (
            f.startswith("scripts/") or f.startswith("src/explore_persona_space/")
        ):
            out.add(f)
        elif suffix == ".sh" and f.startswith(_SH_ELIGIBLE_PREFIXES):
            out.add(f)
    return out
```
