### 4.2 The matcher (actual regexes, prototype-validated on the full corpus this session)

```python
# ─── Check 36 — numeric containment claims (WARN-only; experiment + analysis) ─

_C36_NUM = r"(?:\d+(?:\.\d+)?|\.\d+)"
# Range operand pair. Two alternatives:
#   (a) en/em-dash or "to" separator, signed operands allowed ("−0.5–0.3");
#   (b) unspaced ASCII hyphen, UNSIGNED operands only ("2-4", "0.25-0.5") —
#       a signed/hyphen mix ("-0.5-0.3") is ambiguous between range and
#       negative pair and is NEVER parsed (accepted false negative).
# The leading lookbehind blocks matching the tail of a larger number or a
# signed token; \b after operands blocks partial-digit backtracks (the c28
# :4487 convention — without it "150–330 band" mis-parses); (?!-\d) on the
# hyphen form rejects date/version chains ("2026-07-15").
_C36_RANGE = (
    rf"(?P<lo>(?<![\d.\-−+])[+\-−]?{_C36_NUM})%?\s*(?:[–—]|\bto\b)\s*"
    rf"(?P<hi>[+\-−]?{_C36_NUM})"
    rf"|(?P<lo2>(?<![\d.\-−+]){_C36_NUM})-(?P<hi2>{_C36_NUM}(?!-\d))"
)  # noqa: RUF001 — en dash is real plan text
# Containment claim: verb + bounded filler + range + bounded tail + range-noun,
# all on ONE line. Filler excludes .;:| so a claim never crosses a sentence,
# clause-label, or table-cell boundary; (?![–-][A-Za-z]) rejects compound
# count modifiers ("10–20-draw random band", #816 v1 L227). "estimate" and
# "guidance" are deliberately NOT range-nouns (the #825 aggregate-delta and
# t-SNE-guidance corpus shapes are accepted false negatives — both FP-prone).
_C36_CLAIM_RE = re.compile(
    rf"\b(?:inside|within)\b(?P<fill>[^.;:|\n]{{0,45}}?)(?:{_C36_RANGE})\b"
    rf"(?![–-][A-Za-z])\s*%?(?P<tail>[^.;|\n]{{0,18}}?)"
    rf"\b(?:spread|band|range|window|interval|CIs?)\b",
    re.IGNORECASE,
)  # noqa: RUF001
# Candidate claimed values: numbers in the same clause BEFORE the verb. The
# leading lookbehind kills identifier digits ("H2", "#508", "Tier-1",
# "checkpoint-20", "coef-0"); the trailing lookahead kills hex/sha and
# unit-glued tokens ("48de22…", "13h").
_C36_CAND_RE = re.compile(
    rf"(?<![A-Za-z#\d.\-−+/])[+\-−]?{_C36_NUM}%?(?![A-Za-z0-9])"
)  # noqa: RUF001
_C36_NEG_RE = re.compile(r"(?i)\b(?:not|never|no longer|nor|outside)\b")
```

Scientific notation is structurally out of scope: in `1e-4–1e-3` the `\b` after `lo` cannot sit between two word characters (`1`↔`e`), so no operand parses — stated as a named non-goal, matching c28's `%`-ratio precedent of accepting false negatives over parse risk.

    """Exact Fraction from a claim/operand token: strips a trailing %, a

### 4.4 Check function skeleton

```python
def check_numeric_containment(plan: str, kind: str) -> CheckResult:
    """WARN-only, conditional: an explicit numeric containment claim —
    a claimed number, a containment verb (inside/within), and an explicit
    numeric A–B range with a range-noun (spread/band/range/window/
    interval/CI) on one line — must be arithmetically true: some
    attributable claimed number in the same clause lies in [A, B]
    (boundary-inclusive; reversed bounds normalized). NEVER FAILs (the
    c14/c28 doctrine: a heuristic free-prose check must not hard-block);
    the semantic verdict — WHICH number the prose attributes — stays with
    the Statistics critic. Incident: #1315 plan v4 L66 (0.724 asserted
    inside 0.737–0.820; verify_plan PASSed 0/0; two critics caught it by
    hand → #1375). Accepted false negatives (v1, named): claims whose
    subject sits in a previous sentence/clause; a decoy same-clause number
    inside the range masking a false claim; %-vs-unitless mixed units;
    scientific notation; noun-before-range word order ("the band
    0.6–0.8"); "estimate"/"guidance" nouns; ± tolerance forms (not
    ranges); signed hyphen ranges.
    """
    cid, name = "c36_numeric_containment", "numeric containment claims"
    if kind not in ("experiment", "analysis"):
        return _skip(cid, name, "kind-exempt: containment-claim prose is an "
                                "experiment|analysis plan shape")
    lines = plan.splitlines()
    mask = _fence_mask(lines)
    n_claims = 0
    offenders: list[tuple[str, Fraction, Fraction, list[Fraction]]] = []
    for line, fenced in zip(lines, mask, strict=True):
        if fenced or line.lstrip(" \t").startswith(">"):
            continue  # fenced code + blockquotes: quoted text, not claims
        blanked = line  # length-preserving blank of prior match spans
        for m in _C36_CLAIM_RE.finditer(line):
            lo_s = m.group("lo") or m.group("lo2")
            hi_s = m.group("hi") or m.group("hi2")
            lo, hi = _c36_frac(lo_s), _c36_frac(hi_s)
            if lo > hi:
                lo, hi = hi, lo  # reversed bounds: normalize, still verify
            pre = blanked[: m.start()]
            cut = max(pre.rfind("|"), pre.rfind(":"), pre.rfind(";"))
            seg = pre[cut + 1 :]  # clause/cell-bounded candidate window
            blanked = (blanked[: m.start()] + " " * (m.end() - m.start())
                       + blanked[m.end():])
            if _C36_NEG_RE.search(seg[-24:]):
                continue  # negated/outside claims: out of scope
            rng_pct = "%" in line[m.start() : m.end()]
            cands = [_c36_frac(t.group(0))
                     for t in _C36_CAND_RE.finditer(seg)
                     if t.group(0).endswith("%") == rng_pct]
            if not cands:
                continue  # no attributable claimed value → not a claim
            n_claims += 1
            if not any(lo <= c <= hi for c in cands):
                offenders.append((line.strip(), lo, hi, cands))
    if n_claims == 0 and not offenders:
        return _skip(cid, name, "no numeric containment claims detected")
    if _c36_na_escape_declared(plan):
        return _pass(cid, name, "explicit N/A declared (no numeric "
                                "containment claims of this plan's own)")
    if not offenders:
        return _pass(cid, name, f"{n_claims} numeric containment claim(s) "
                                "arithmetically coherent")
    return _warn(cid, name, _c36_offender_detail(offenders))
```

`_c36_offender_detail` follows `_c28_offender_detail` (:4639): ≤3 offenders, 90-char line snippets, per-offender `no candidate value (≈ 0.663, 20, 0.724) lies in [0.737, 0.82]` rendering via `float(v):.3g`, then the incident anchor ("#1315 v4 L66: 0.724 asserted inside 0.737–0.820; caught only at the critic layer") and the remedy menu: fix the arithmetic, rewrite the prose (e.g. "0.013 BELOW the … spread", the v5 correction), move a quoted incident line into a blockquote/fence, or declare `N/A — no numeric containment claims` on its own line, unwrapped (no backticks/quotes); the semantic verdict stays with the Statistics critic.

Evaluation order note: the escape is checked AFTER claim detection (c28's order), so it renders PASS-with-detail rather than suppressing the trigger; a plan with no claims at all SKIPs without needing any escape.

WARN has teeth here: Phase 1.5.0 forwards WARN lines verbatim into the fact-checker + critic briefs (docstring "WARN semantics"), which mechanically hands the Statistics critic the very finding it previously had to make by hand. ### 4.8 Edge-case decisions (each pinned by a §6 test)

| Case | Behavior |
|---|---|
| Two claims, one sentence (#1315 v4 L66) | Both evaluated; prior match spans blanked (length-preserving) so range-1 operands are not range-2 candidates; only the false one flagged |
| Boundary equality | `lo <= n <= hi` — N == A or N == B counts as inside (Fraction-exact, no float wobble) |
| Reversed bounds ("0.85–0.60 band") | Normalized to [0.60, 0.85], then verified (a reversed range is a prose-order quirk, not an exemption) |
| ± tolerance ("within 0.724 ± 0.15") | Not a range → never parsed |
| "next to" (#1315 v4 L126/128) | No containment verb → no match |
| Negative + ASCII hyphen ("-0.5-0.3") | Never parsed (ambiguous); negatives require en-dash or "to" |
| Percent ("72% within the 60–85% range") | %-flagged candidates compared only against %-flagged ranges; mixed units → candidate dropped; all dropped → no attributable claim → no fire |
| Fenced code / blockquotes | Excluded (strip via `_fence_mask` semantics + `>` prefix) |
| Table rows (#514 v1 L175) | Candidate window cut at last `\|` → cross-cell numbers never attributed |
| Label digits ("H2", "Exp 4", "#508", "Tier-1") | Killed by candidate lookbehind/lookahead guards; candidate-less matches don't fire |
| Compound counts ("10–20-draw band", #816) | `(?![–-][A-Za-z])` rejects the range |
| Scientific notation | Out of scope (structurally unparseable, documented) |
| Aggregate/plural claims with no local subject | No candidate in clause → no fire (the "each phase within…" family) |

## 11. Decision Rationale

- **Severity = WARN-only (all applicable kinds).** What: `_warn`, never `_fail`. Why: free-prose subject attribution is irreducibly ambiguous (the corpus's aggregate-delta shape: the nearest pre-verb number can be a component of the true subject), so a hard block risks bouncing legitimately-worded plans; WARN still lands in the fact-checker + critic briefs verbatim (docstring "WARN semantics"), which is exactly the mechanization the incident called for. Source: c28 docstring, `check_precedent_band_coherence` verify_plan.py:4686 ("NEVER FAILs (the c14 doctrine…); the FAIL-grade semantic verdict stays with the Statistics critic") — the closest prose-arithmetic sibling. Alternatives: FAIL-experiment/WARN-analysis (the c12/c13/c18/c20 tier) — rejected: those FAIL on structural-contract absence, not on free-prose semantics; a c36 FAIL would be the first hard block keyed to regex reading of narrative prose, and the objective-arithmetic argument only holds AFTER correct subject attribution, which is the heuristic part. Escalation to that tier is a cheap later follow-up once the WARN has corpus mileage.
- **Applicability = experiment + analysis.** What: infra/batch/survey → kind-exempt SKIP. Why: containment-claim prose ("inside the … band/spread") is experiment-register (install bands, CI spreads); the dominant predicted FP population — workflow-fix plans quoting incidents, like this task's own — is `kind: infra` and gets exempted wholesale (§4.7). Source: c28's identical kind gate (verify_plan.py:4694–4699) + c14/c16/c24's experiment+analysis rows in the catalog. Alternatives: all-kinds (the c22/c25 convention) — rejected: adds the self-reference-trap surface for near-zero detection value (infra plans rarely assert measurement-band containment).
- **Escape mechanism = standalone `N/A — no numeric containment claims` + blockquote/fence exclusion.** What: `_standalone_na_declared` tail `r"no numeric containment claims?"`, checked after detection (escape → PASS, the c28 order). Why: a legitimate experiment plan may need to quote a false claim in prose; the standing anti-paste helper prevents bounce-brief self-satisfaction. Source: `_standalone_na_declared` :1526 (+ #1238 rationale), `_c28_na_escape_declared` :4621, and the SKILL.md gloss precedent of c24 ("quotes a sibling's methodology"). Alternatives: no escape (rely on WARN + blockquotes only) — rejected: every conditional prose check since c13 ships one, and the sync meta-test makes it ~free; quote-mark detection inside sentences — rejected as brittle.
- **Regex boundaries (the three guards).** What: `\b` after operands + `(?![–-][A-Za-z])` compound guard + `(?!-\d)` date guard; candidate guards `(?<![A-Za-z#\d.\-−+/])…(?![A-Za-z0-9])`; clause window cut at last `|:;`; length-preserving blanking for multi-claim lines. Why: each guard maps 1:1 to a measured corpus FP class (§5 calibration lineage: 9 → 6 → 1 fires across the three prototype iterations this session). Source: c28's `\b` partial-digit comment (:4487), `_C28_POSNUM_RE` leading guard (:4516), `_c28_ratio_assertions` blanking (:4564), plus the measured sweep. Alternatives: sentence-level segmentation via period-splitting — rejected (decimal points make period-splitting error-prone; plan paragraphs are single lines anyway, so line + clause-cut bounding is strictly simpler); requiring the claimed number adjacent to the verb — rejected (the founding fixture's true subject `0.724` sits 40+ chars and one em-dash left of the second verb).
- **Any-candidate-in-clause pass policy.** What: the claim passes if ANY same-clause, same-unit pre-verb number lies in [A, B]. Why: false fires then require every plausible subject to be outside the range — which is exactly the definition of the incident being targeted; decoy-masking becomes a false negative, the accepted direction. Source: the measured corpus (this policy is what keeps the #1353/#390/#570 true claims green while the #1315 v4 line still fires). Alternatives: nearest-number-only attribution — rejected: it false-fires on the aggregate-delta corpus shape (nearest number `+0.5` vs true subject `+9–10`).
- **Fraction arithmetic, boundary-inclusive, reversed-bounds normalization.** Source: c28 "Fraction arithmetic throughout — exact boundary semantics … no float-equality wobble" (:4576) and c13's parse conventions; inclusive `[A, B]` matches the task Goal's `N ∉ [A, B]` phrasing verbatim.
