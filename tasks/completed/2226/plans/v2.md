## 2. Method delta (what is new vs existing checks)

Existing checks parse plan-embedded COMMANDS (c46/c50/c52/c54) or repo files named
by the plan (c31/c34/c41/c51). c55 is the first to cross-reference BOTH: argparse
defaults extracted from plan-named SCRIPT FILES against a NUMERIC TARGET extracted
from plan prose. Everything else (result helpers, `_standalone_na_declared`,
module-level monkeypatchable repo root, CHECKS registration, docstring table row)
follows the established conventions verbatim.

## 3. Design (concrete)

New function `check_inherited_rowcount_default(plan: str, kind: str) -> CheckResult`,
`cid, name = "c55_inherited_rowcount_default", "inherited argparse row-count default vs per-cell target"`.
Applies: all kinds, conditional (SKIP-heavy; the incident plan was an experiment
amendment, but nothing kind-specific in the mechanism).

Algorithm (in order; every step fail-soft — this is WARN-only lint, never a crash):

1. **N/A escape:** `_standalone_na_declared(plan, r"no inherited row-count defaults")`
   → PASS with the standard "declared N/A" detail.
2. **Candidate scripts:** regex `(?:scripts|src)/[A-Za-z0-9_./-]+\.py` over the whole
   plan text; dedup, preserve order; cap at 12 scripts (cost bound; note the cap in
   the detail when it truncates). None found → SKIP
   ("no reused script paths named in plan").
3. **Script resolution:** module-level `_C55_REPO_ROOT = Path(__file__).resolve().parent.parent`
   (tests monkeypatch — c34/c41 pattern). Working-tree read first
   (`_C55_REPO_ROOT / rel`). If absent AND the plan text names an issue branch
   (`issue-\d+[a-z0-9-]*` token), try `git show <branch>:<rel>` then
   `git show origin/<branch>:<rel>` (subprocess, `check=False`, short timeout
   ~10 s each — a branch fetched but never checked out locally resolves only via
   the `origin/` ref); on failure append a note (`script unresolved: <rel>`) and
   continue — never a FAIL/crash.
4. **Inherited-default extraction:** over each resolved script text, regex the
   `add_argument(` calls: flag name matching BOTH `(target|max|limit)` AND
   `(conv|rows?|ids?)` (any order — covers `--target-conv-ids`, `--max-rows`,
   `--limit-ids`), with an integer literal `default=(\d[\d_]*)`. Multi-line
   add_argument calls must match (DOTALL window bounded to ~300 chars after the
   flag token). No matching defaults across all resolved scripts → PASS
   ("no inherited row-count defaults in N plan-named script(s)").
5. **Plan target n extraction (the fuzzy leg — WARN-only justifies it):** scan plan
   prose for integer values adjacent to target-ish tokens, patterns approximately:
   - `per[- ]cell[^.\n]{0,60}?(\d[\d,]{2,})`
   - `n(?:_train)?\s*[=≈~]\s*(\d[\d,]{2,})`
   - `\|S\|\s*[=≈]\s*(\d[\d,]{2,})`
   - `target(?:\s+of)?\s+[^.\n]{0,40}?(\d[\d,]{2,})`
   Strip `,`/`_` separators; keep candidates ≥ 100 (drop seed counts / tiny ints);
   take the MAX as the stated per-cell target (conservative: max is what the plan
   claims to reach). None found → SKIP ("no stated per-cell target n recognized").
6. **Verdict:** for each (script, flag, default): WARN when `target > default` AND
   the literal flag token (`--<flag-name>`) appears NOWHERE in the plan text
   (mention anywhere = plan-aware = suppressed, per the sketch). WARN detail names
   script, flag, default, target, and the incident (#2054 `--target-conv-ids`
   8,000 < 9,000, deterministic first-N truncation). Otherwise PASS with a
   scanned-count detail (c54 style).
