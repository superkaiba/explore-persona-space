## 4. Design (two coupled changes)

### 4.1 CLI entrypoint — NEW `scripts/gcp_audit.py` (option b)

**v2 delta:** Added the `list`-preflight (Must-Fix A: a failed real `gcloud
list` exits 3 + surfaces `list_rc`/`list_stderr` in JSON, WITHOUT modifying the
frozen reaper); collapsed the config construction to plain `default_gcp_config()`
(cleanup #3).

**Fork resolved → standalone script.** The task description prefers extending
`dispatch_issue.py` ONLY if its argparse already has a `gcp` subparser group.
It does not: `dispatch_issue.py::_build_argparser` (`scripts/dispatch_issue.py:1316`)
declares a flat `sub = parser.add_subparsers(dest="action", required=True)` with
exactly two actions, `launch` and `finalize` — no `gcp` group, and `main()`
hard-branches on `args.action in {launch, finalize}`. Adding a nested `gcp
audit-stale` would force a restructure of that contract. The RunPod analogue is
itself a standalone `scripts/pod_audit.py` (forwarded by `pod.py`), so a
standalone `scripts/gcp_audit.py` mirrors the established pattern with zero blast
radius on the dispatcher. (See §11 row 1.)

**The `list`-preflight (Must-Fix A — the structural acceptance gate).** The
frozen reaper swallows a non-zero `gcloud list` rc and returns `[]`
(`backends/gcp.py:2046-2052`), making an auth failure indistinguishable from an
empty inventory. The body's hard constraint forbids modifying the reaper. So
the CLI does the LIST check ITSELF, BEFORE calling the reaper:

1. Build the SAME argv the reaper uses internally — `render_list_argv(config=
   default_gcp_config(), name_filter="name~^eps-issue-")` — and run it via
   `default_gcloud_runner`.
2. If that probe's `returncode != 0`, the CLI does NOT call
   `audit_stale_gcp_vms`. It emits the failure (`list_rc`, `list_stderr` in the
   JSON output; a human-readable FATAL line on the text path) and returns exit
   code **3** (`list-failed` — distinct from rc=2 `delete-failed`, rc=0 clean).
3. If the probe's `returncode == 0`, the CLI proceeds to call the reaper (which
   issues its own internal `list` again — one redundant cheap call, ~1s; the
   simplest option that does NOT touch the reaper, per the body constraint).
   The JSON output carries `list_rc: 0`.

> Note: this is two `list` calls per healthy fire (preflight + reaper-internal).
> That is deliberate — the body freezes the reaper, and a preflight that reuses
> the reaper's own argv builder is the lowest-risk way to surface the rc the
> reaper hides. The cost (one extra `instances list`, sub-second) is negligible
> for a once-daily cron.

Near-real Python:

```python
#!/usr/bin/env python3
"""Audit (and optionally reap) stale GCP ``eps-issue-*`` VMs.

GCP analogue of ``scripts/pod_audit.py`` (the RunPod stale-pod sweep). Thin
CLI wrapper over ``backends.gcp.audit_stale_gcp_vms`` — the predicate lives in
the library; this script parses flags, runs a LIST-preflight (so a failed
gcloud list / expired auth is a HARD ERROR rather than a silent empty sweep —
the frozen reaper swallows that rc), injects the production config + runner,
prints the records, and maps the result to an exit code:

    0  clean inspection (0+ VMs, list succeeded)
    2  at least one delete-failed (reaper could not reclaim a reaped VM)
    3  list-failed (gcloud list returned non-zero — auth/config broken; the
       sweep is DISARMED and the operator must be notified)

Invoked by ``scripts/cron_gcp_audit.sh`` daily; runnable by hand for a probe.
"""
from __future__ import annotations

import argparse
import json
import os
import sys

from explore_persona_space.backends.gcp import (
    audit_stale_gcp_vms,
    default_gcloud_runner,
    default_gcp_config,
    render_list_argv,
)
from explore_persona_space.orchestrate.env import load_dotenv

_AUDIT_NAME_FILTER = "name~^eps-issue-"  # MUST match the reaper's internal filter


def build_parser() -> argparse.ArgumentParser:
    p = argparse.ArgumentParser(
        prog="gcp_audit",
        description="Audit live GCP project for stale eps-issue-* VMs (credit-leak backstop).",
    )
    p.add_argument(
        "--delete",
        action="store_true",
        help="Actually delete reaped VMs (passthrough to audit_stale_gcp_vms(delete=True)). "
             "Default report-only. Overridden OFF by EPS_GCP_JANITOR_DRY_RUN=1.",
    )
    p.add_argument("--max-age-hours", type=float, default=24.0,
                   help="EXITED/old VMs older than this are reaped. Default 24h.")
    p.add_argument("--terminal-phase-max-age-min", type=float, default=10.0,
                   help="RUNNING VMs in a terminal eps/phase older than this floor are reaped. "
                        "Default 10 min.")
    p.add_argument("--json", action="store_true",
                   help="Emit machine-readable JSON, no headers.")
    return p


def main(argv: list[str] | None = None) -> int:
    load_dotenv()
    args = build_parser().parse_args(argv)
    config = default_gcp_config()  # threads --configuration=eps-gcp on every gcloud call
    runner = default_gcloud_runner

    # ----- LIST-PREFLIGHT (Must-Fix A) -------------------------------------
    # The frozen reaper returns [] on a non-zero list rc (gcp.py:2046-2052),
    # hiding an auth/config failure. Re-issue the SAME list the reaper runs
    # internally and surface its rc so the cron CANNOT silently no-op.
    probe = runner(render_list_argv(config=config, name_filter=_AUDIT_NAME_FILTER))
    if probe.returncode != 0:
        out = {"list_rc": probe.returncode, "list_stderr": (probe.stderr or "")[:500],
               "records": [], "error": "gcloud list failed; janitor DISARMED"}
        if args.json:
            print(json.dumps(out, indent=2))
        else:
            print(f"GCP janitor FATAL: gcloud list rc={probe.returncode} "
                  f"({(probe.stderr or '').strip()[:200]}); janitor DISARMED, no sweep.",
                  file=sys.stderr)
        return 3  # list-failed — distinct from rc=2 delete-failed

    # ----- LIST OK → run the reaper ----------------------------------------
    delete = args.delete and os.environ.get("EPS_GCP_JANITOR_DRY_RUN", "") != "1"
    records = audit_stale_gcp_vms(
        config=config,
        runner=runner,
        max_age_seconds=int(args.max_age_hours * 3600),
        terminal_phase_max_age_seconds=int(args.terminal_phase_max_age_min * 60),
        delete=delete,
    )

    if args.json:
        print(json.dumps({"list_rc": 0, "records": records}, indent=2))
    else:
        reaped = [r for r in records if r["action"] in ("would-delete", "deleted")]
        failed = [r for r in records if r["action"] == "delete-failed"]
        print(f"GCP janitor: list_rc=0; {len(records)} eps-issue-* VM(s) inspected; "
              f"{len(reaped)} reaped ({'delete' if delete else 'report-only'}), "
              f"{len(failed)} delete-failed.")
        for r in records:
            if r["action"] != "skipped":
                age_h = (r["age_seconds"] / 3600) if r["age_seconds"] is not None else None
                age_str = f"{age_h:.1f}h" if age_h is not None else "unknown"
                print(f"  {r['action']:<13} {r['name']}  zone={r['zone']}  "
                      f"status={r['status']}  reason={r['reason']}  age={age_str}")

    return 2 if any(r["action"] == "delete-failed" for r in records) else 0


if __name__ == "__main__":
    sys.exit(main())
```

**Output contract (`--json`):** a single JSON object `{"list_rc": <int>,
"records": [...]}` (and `"list_stderr"`/`"error"` on the rc=3 path). `records`
is the list `audit_stale_gcp_vms` returns verbatim (keys `name, zone, status,
created_at, age_seconds, phase, reason, action`). **v2 delta:** the top-level
`list_rc` field (and the rc=3 object shape) is new — it is the machine-readable
signal the live §10.2 probe and the cron both key off; the old plan emitted a
bare list with no list-health field.

### 4.2 Cron entrypoint — NEW `scripts/cron_gcp_audit.sh` (option b)

**v2 delta:** The cron now PROPAGATES the CLI's rc=3 (list-failed) to its own
exit so cron delivers the auth-failure email/log (Must-Fix A2); routine rc=2
(delete-failed) + clean rc=0 still `exit 0` (no nuisance email). Pinned
`DATE=$(date +%Y-%m-%d)` once at the top (cleanup #4).

**Fork resolved → separate cron script + separate log dir.** Appending to
`cron_pod_audit.sh` (option a) would couple two distinct backends into one log
trail and one exit-code surface; a GCP gcloud-auth failure would muddy the
RunPod audit log. A separate script with its own dated log dir
(`logs/gcp_audit/YYYY-MM-DD.log`) mirrors `cron_pod_audit.sh` 1:1 and keeps the
backends independently diagnosable. (See §11 row 2.)

Real bash (clone of `cron_pod_audit.sh` with GCP substitutions + the rc=3
propagation):

```bash
#!/bin/bash
# Daily GCP-VM janitor — invoked from system crontab.
# Reaps eps-issue-* GCE instances that escaped the canonical teardown:
#   - any eps-issue-* VM older than 24h (orchestrator-crash credit-leak backstop)
#   - a RUNNING VM in a terminal eps/phase (done/failed) past a 10-min floor
#     (the metadata-runner-SIGPIPE zombie class, #634).
# GCP analogue of cron_pod_audit.sh. Output: logs/gcp_audit/YYYY-MM-DD.log.
#
# Exit semantics (Must-Fix A2):
#   CLI rc=0 (clean) / rc=2 (delete-failed, routine) -> cron exit 0 (no email)
#   CLI rc=3 (list-failed: gcloud auth/config broken, janitor DISARMED)
#                                                     -> cron exit 3 (DELIVER email)

set -uo pipefail

# cron's minimal PATH lacks ~/.local/bin (bare `uv` exit-127s silently under
# the exit below). Put uv on PATH; fail LOUD if still missing.
export PATH="$HOME/.local/bin:$PATH"
if ! command -v uv >/dev/null 2>&1; then
    echo "$(date -Iseconds) FATAL: uv not on PATH ($PATH); cannot run gcp audit" >&2
    exit 1
fi

PROJECT_DIR="/home/thomasjiralerspong/explore-persona-space"
DATE=$(date +%Y-%m-%d)                       # pinned ONCE — no midnight-edge split
LOG_DIR="${EPS_GCP_JANITOR_LOG_DIR:-$PROJECT_DIR/logs/gcp_audit}"
LOG_FILE="$LOG_DIR/$DATE.log"

mkdir -p "$LOG_DIR"

# First-run-of-day pointer line into the crontab redirect file (the block below
# redirects into $LOG_FILE, so without this the redirect file reads "never ran";
# mirrors cron_pod_audit.sh + cron_autonomous_session_watch.sh, #580 item-3).
FIRST_RUN_OF_DAY=0
[ -f "$LOG_FILE" ] || FIRST_RUN_OF_DAY=1

rc=0
{
    echo "=== $(date -Iseconds) gcp_audit start ==="
    cd "$PROJECT_DIR" || exit 1
    uv run python scripts/gcp_audit.py --delete --json
    rc=$?
    echo "=== $(date -Iseconds) gcp_audit exit=$rc ==="
} >> "$LOG_FILE" 2>&1

if [ "$FIRST_RUN_OF_DAY" = 1 ]; then
    echo "$(date -Iseconds) gcp_audit: per-pass output → $LOG_FILE (this file receives only this daily pointer line)"
fi

# rc=3 (list-failed) is a DISARMED-janitor alarm: propagate so cron emails it.
# rc=2 (delete-failed) is routine — the log's exit=2 line is the trail; no email.
if [ "$rc" = 3 ]; then
    echo "$(date -Iseconds) gcp_audit: list-FAILED (rc=3) — janitor DISARMED, gcloud auth/config broken" >&2
    exit 3
fi
exit 0
```
