# Plan v6 — Task #1800: daily-fix: WARN when GCP workload chain has no persist phase

`architectural: false`

## 1. Requirement + acceptance criteria

**Requirement.** A workload launch whose execution chain carries no upload/persist
step for its declared artifacts must not launch SILENTLY. Incident #1739
(2026-07-28): a GCP `--workload-cmd` run completed its phases and approached
grace-poweroff with ZERO artifacts on HF (all 7 expected prefixes MISS per the
filing; details flagged "inferred" by the miner); ~2h of improvised recovery
uploads raced the poweroff clock. #1779 (commit `f7232aca11`) fixed the
PLAN-time layer; nothing checks at DISPATCH time.

Two layers, matching the candidate's diff sketch:

- **(A) Experimenter pre-launch gate item** (`.claude/agents/experimenter.md`,
  "Before Running") — agent-side, plan-aware; covers pod-lane launches where
  the experimenter is in the loop.
- **(B) Mechanical WARN-only lint** (`scripts/dispatch_issue.py` +
  `src/explore_persona_space/backends/issue_dispatch.py`) — covers ALL router
  lanes including GCP (the #1739 lane, where NO experimenter is in the loop:
  the orchestrator calls `dispatch_issue.py launch` directly per SKILL.md
  Step 6b).

**Acceptance criteria:**

1. `experimenter.md` "Before Running" gains a new numbered item (after the
   item-4 input-data completeness gate — its OUTPUT-side sibling): before
   launch, verify the run's execution design carries a persist step for every
   plan-declared HF/git-destined output (raw completions, eval JSONs,
   checkpoints, analysis tensors). A plan-named OFF-POD/VM-side harvest+upload
   step COUNTS as a persist step (the launch chain itself need not carry it).
   Disposition split: (i) declared outputs with NO persist step anywhere in
   the plan's execution design AND the run's primary outputs are raw
   completions / generations → REFUSE: post `epm:failure v1`
   `failure_class: infra`, `reason: no-persist-phase-for-declared-artifacts`,
   no launch (routes to /issue Step 7 infra respawn after the chain is
   fixed); (ii) any other missing-persist case → WARN loudly (a named line in
   the `epm:run-launched` note: `persist-phase: MISSING for <outputs> —
   launching anyway because <one-line reason>`); (iii) persist step present →
   silent. Grounding: Upload Policy "Raw completions MUST upload before pod
   termination" + the #779 persist-by-default rule.
2. Pure lint `lint_workload_cmd_persist_evidence(workload_cmd: str,
   script_text: str | None) -> WorkloadCmdPersistLint` in
   `backends/issue_dispatch.py` (frozen dataclass result; exported in
   `__all__`), mirroring the #1576 WARN-only arm. Scans workload_cmd +
   resolved script text case-insensitively for persist-evidence tokens (a
   module-level constant tuple, e.g. `upload`, `push_to_hub`, `hf_hub`,
   `hfapi`, `git push`, `persist`; exact composition is implementer
   discretion — pinned by tests). `script_text is None` → `skipped=True`,
   never flagged. Zero evidence with a resolved script → `flagged=True`.
   The docstring's deliberate-v1-false-negatives list (the #1576 discipline)
   MUST name the present-but-never-executed-persist residual: a chain whose
   persist phase exists but is skipped / dry-run at runtime (e.g. a
   `--dry-run` upload mode or a `--phases` subset invocation) is invisible
   to a static token lint — the lint is evidence-of-persist-WIRING, never a
   persist guarantee; Step 8 upload-verification stays the hard gate.
3. CLI wiring in `scripts/dispatch_issue.py` launch path: resolve the driver
   script named by `--workload-cmd` (the `bash scripts/<driver>.sh` /
   `scripts/<x>.py` token) from the `--repo-branch` ref
   (`git show origin/<branch>:<path>`, local-branch + working-tree
   fallbacks); fail-soft — unresolvable script → lint skipped with ONE stderr
   note, never a refusal. Flagged → LOUD stderr warning +
   `extra.workload_cmd_no_persist_evidence=true` on the
   `epm:backend-selected` marker via a marker-poster decoration (the
   `_warn_workload_cmd_inline_interpreter_and_flag_marker` shape). WARN-only:
   NEVER exit-2; `--strict-workload-cmd-env` does NOT upgrade it. Kill
   switch: `EPM_SKIP_WORKLOAD_CMD_PERSIST_LINT=1`. Hydra launches exempt
   (no `--workload-cmd`; train.py carries built-in upload paths).
4. Tests: new `tests/test_workload_cmd_persist_lint.py` — flagged on a
   persist-less synthetic script; NOT flagged when evidence appears in the
   script text; NOT flagged when evidence appears in the workload_cmd itself;
   `skipped` on `script_text=None`; kill-switch + marker-extra covered at the
   CLI seam (mirror `tests/test_workload_cmd_env_lint.py` fixtures).
5. `workflow_lint.py` no-flags run passes on the touched files. If the
   `experimenter.md` addition trips `AGENT_SPEC_SIZE_GRANDFATHER`, bump the
   constant computed from LANDING bytes (#1753), never branch-tip bytes.
