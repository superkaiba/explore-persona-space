### 4.1 New helper: `scripts/verify_carryover_inputs.py` (stdlib-only — `re`, `argparse`, `subprocess`, `pathlib`, `dataclasses`, `json`)

Stdlib-only so the tmp-git-repo tests need no package import and the helper has no coupling to `task_workflow`'s branch guard. Repo root defaults to the parent of `git rev-parse --path-format=absolute --git-common-dir` (worktree-safe), overridable with `--repo-root` for tests.

```python
#!/usr/bin/env python3
"""Verify plan-referenced LOCAL repo inputs are reachable in the git tree a
clone lane will materialize (#1469; the #734/#1434 class).

The Step 6a.5 first stanza (hub.verify_artifacts_exist) covers HF/WandB URLs
only. Every compute lane boots from a git materialization of the PUSHED
dispatch ref (GCE: `git clone --depth 1 --branch issue-<N>`; RunPod
bootstrap: init+fetch+reset; SLURM: materialize_branch_src), so a plan-cited
eval_results/ file that exists only on the VM — untracked, committed but
unpushed, or pushed to origin/main only after the branch was cut — is
guaranteed absent from the lane's tree.

NOT covered (residual risks — the gate reduces, not eliminates, the class):
config-file indirection (a path cited only inside a config the plan names),
runtime-constructed paths (the #1434 CONSUMER built its path at
issue1434_worker.py:571 — this gate catches the plan-text CITATION, which
existed in bare-filename form, not the construction), HF-staged data/ inputs
(WARN only; staging correctness is artifact-reuse check (h)(iii)'s territory),
direct dispatch_issue.py launches that bypass /issue Step 6a.5, and
extension-less citations. The check ref defaults to origin/issue-<N>; a lane
whose actual materialization ref differs (RunPod BOOTSTRAP_BRANCH defaults to
main) can be probed by threading --ref.

Exit codes: 0 = PASS (warns allowed), 1 = >=1 FAIL, 2 = usage / plan unreadable.
"""
```

**Extraction — TWO channels, both feeding one classifier:**

**Channel A — full-prefix repo-relative paths** (unchanged from v1). Lookbehind excludes word chars, `/`, `-`, `.` so `explore-persona-space-data/issue.../f.json` (HF data-repo paths) and URL segments never match; `ood_eval_results` is its own alternative (the `eval_results` alternative cannot fire inside it — `_` is `\w`):

```python
_PATH_RE = re.compile(
    r"(?<![\w/\-.])"
    r"(?P<path>(?:eval_results|ood_eval_results|data)/"
    r"[A-Za-z0-9][\w.\-/*?\[\]{}<>]*)"
)
_GLOB_CHARS = set("*?[]{}<>$")
_TRAIL_PUNCT = ".,;:!?)'\"`"
# Skip reasons (never block): 'glob-or-template', 'dir' (trailing '/'),
# 'no-ext' (basename without '.'). Trailing prose punctuation rstripped first.
```

**Channel B — bare cited filenames (NEW; the #1434 incident's actual citation form).** Extract extension-bearing bare filenames (no `/` inside) cited in backticks or as standalone prose tokens:

```python
_BARE_EXTS = r"(?:json|jsonl|pt|npz|csv|parquet)"   # carry-over input types in the corpus; extensible
_BARE_NAME_RE = re.compile(
    r"(?<![\w/\-.])(?P<name>[A-Za-z0-9][\w.\-]*\." + _BARE_EXTS + r")(?![\w/])"
)
# Names containing glob/template chars are skipped by the same _GLOB_CHARS
# filter; names already covered by a Channel-A candidate (same basename at a
# matching extracted path) are deduped.
_ISSUE_TOKEN_RE = re.compile(r"(?:issue[\s_-]?|#)(\d{2,4})(?!\d)")  # issues the plan references
```

Resolution (`resolve_bare_name`): glob `eval_results/issue_<M>/**/<name>` + `ood_eval_results/issue_<M>/**/<name>` under the repo root AND under `.claude/worktrees/issue-<N>*/{eval_results,ood_eval_results}/issue_<M>/**/<name>`, where `<M>` ranges over the **issue-scope set** = {this issue} ∪ {every issue number token in the plan text} (a carry-over plan names its source issues; #1434 v6 names 1434 throughout). This issue-scoping is the primary false-positive guard: a generic `results.json` sitting under `eval_results/issue_999/` is ignored unless the plan actually references issue 999. Each resolved file yields a candidate at its repo-relative resolved path (multiple matches → multiple candidates, each named in the finding detail); a name matching nothing in scope → `skip` / `bare-name-unresolved`. `data/` trees are deliberately NOT globbed for bare names (huge trees, and the `data/` class can only WARN anyway — recorded as a residual).

**Pre-declared narrowing ladder** (executed only if the §6 corpus sweep shows a MISclassified-FAIL class from Channel B; one iteration allowed before kill-criterion (a)): (1) restrict Channel B to backtick-cited names only (`` `name.ext` ``); (2) additionally require an issue-suffixed stem (`re.search(r"(?:_i?\d{2,4}|i\d{2,4})(?:[_.]|$)", stem)` — the corpus convention: `cell_manifest_i1434.json`, `datagen_results_1434.json`). The shipped default is the broad form (backtick OR prose token) because the issue-scoped resolution already bounds the FP surface; the sweep is the empirical arbiter (§11).

**Classifier — one decision ladder per candidate** (`cls` = `data` for `data/...` paths, `tracked-results` for `eval_results/` + `ood_eval_results/`; bare-name candidates carry their resolved paths and are `tracked-results` by construction):

1. In the pushed check ref (`git cat-file -e {check_ref}:{path}`) → **`pass` / `in-ref`**.
2. Else if `check_ref != origin/main` AND in `origin/main` → tracked-results: **`fail` / `on-main-not-on-branch`** (detail: "reachable on origin/main but not on the dispatch branch tip — merge origin/main into issue-<N> (or rebase the branch) and push, then re-run"; NEVER `git add` text — the file is already committed); data: `warn` (data class never FAILs).
3. Else if in the LOCAL `issue-<N>` tip (`git cat-file -e issue-<N>:{path}`, when the local branch exists) → **`fail` / `committed-unpushed`** (detail: "push the branch and re-run").
4. Else if `exists_locally` (repo root OR any `.claude/worktrees/issue-<N>*` mirror) → tracked-results: **`fail` / `untracked-local-only`** (the #1434 case; detail: "git add + commit + push on issue-<N>, cf. f9f1002797 (main twin: e562685e40)"); data: **`warn` / `data-local-only`** (gitignored by design — the workload must self-build or HF-stage it; check (h)).
5. Else (nowhere visible): Channel-A path containing `issue[-_]?<N>(?!\d)` (this issue's number; the `(?!\d)` boundary keeps issue 77 from matching inside issue_770) → **`skip` / `planned-output`**; Channel-B name → **`skip` / `bare-name-unresolved`**; other Channel-A → **`warn` / `unresolved-citation`** (may resolve on HF via the first stanza; not provably fatal).

Exit 1 iff any `fail`. The own-issue-number exemption applies ONLY at rung 5 — the #1434 incident file was an own-issue INPUT that resolved locally, and it must FAIL (rung 4).

**Function signatures** (Channel A/B split explicit for unit-testability):


**Q1 (extraction / false positives) — resolved** per §2 calibration: Channel A concrete-file citations + Channel B bare cited filenames (the incident form); globs/templates/dirs/no-ext skipped; `raw/` and `configs/` deliberately excluded from the Channel-A alternation (`configs/` is always tracked — an uncommitted config crashes Hydra at compose time on ANY lane, caught by the Step 6d smoke; `raw/` has zero citations in the calibration corpus; adding either later is a 1-token change). Channel B's FP surface is bounded by extension allowlist + issue-scoped resolution + the full-corpus sweep + the narrowing ladder.

**Q2 (which ref) — resolved:** the PUSHED dispatch ref — `origin/issue-<N>` when it exists, else `origin/main` — after a bounded fetch. Justification: the GCE clone is `--depth 1 --branch issue-<N>` of the REMOTE (gcp.py ~L2706), so remote-tip-tree reachability is exactly the lane's view; local-tree/`HEAD` checks reproduce the #1434 blindness. The local `issue-<N>` tip and `origin/main` are consulted only to discriminate the two recoverable fatal classes (`committed-unpushed` → push; `on-main-not-on-branch` → merge/rebase + push) from `untracked-local-only` (needs a commit). The stanza MAY thread the actual dispatch ref via `--ref` where it is known to differ (RunPod `BOOTSTRAP_BRANCH=main` default) — implementer's discretion.

**Q3 (lane conditionality) — resolved: unconditional.** All three lanes materialize from git (§2 clone mechanics); an uncommitted input is fatal on every one. Keying on the resolved backend would add a router dependency to a pre-dispatch gate (the backend isn't resolved until 6b) for zero benefit.
