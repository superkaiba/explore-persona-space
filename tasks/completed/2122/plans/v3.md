## 3. Why the fix is in scope and sound

The asymmetry is an **explicitly deferred decision whose stated precondition has
expired**, not a judgement call. The `/tmp` latch branch (L2135-2143) records:
*"(#1861) NO sticky for /tmp latches: every observed firing is worktree-side;
smaller blast radius to leave it (plan §6)"*; the variable-arming grep (L2182) is
`.claude/worktrees/`-only by the same narrowness. #1491's 2026-08-05 firing IS an
observed /tmp-side firing — the missing incident demand.

The soundness arguments already recorded for the worktree class are
**path-class-independent**:
- the assignment requirement exists because `cd ""` SUCCEEDS as a repo-root
  no-op (verified bash 5.1.16), so a bare `cd "$NAME"` latch would be fail-open;
- the exit-guard requirement exists to prove the `cd` actually ran.

Neither argument mentions which directory. And `/tmp` is **already** an accepted
latch path class for the literal form, so this admits **no new path class
anywhere** — it brings the variable + exit-guard arms to parity with the literal
arm within an already-sanctioned class. The repo-root spellings stay excluded by
the same predicates that exclude them today.

## 4. Change set

**C1 — variable-arming grep accepts the `/tmp/` class** (`~L2183`). Extend the
end-anchored bare/`export ` assignment RHS predicate to match `/tmp/…` in
addition to `…\.claude/worktrees/…`. Every arming REFUSAL is unchanged and
carries over verbatim: assignment-prefix (end-of-clause anchor), AND/OR-preceded,
PIPE-preceded, `NAME+=` and `declare/local/typeset/readonly` reassignment-disarm,
clause-initial-only anchoring. **Exclude `..` from the new RHS predicate** — a
bare prefix match would admit `WT=/tmp/../home/<user>/explore-persona-space`,
which arms and whose later `cd "$WT"` carries no literal `..` for the cd-arg
refusal to catch. The identical hole exists in the worktree RHS predicate today
(so this is parity, not a new class), but excluding `..` mirrors the file's own
cd-arg refusal at near-zero cost.

**C1b — the armed path CLASS must be keyed, not just the name.** `_wt_names` is
currently a presence set whose members are worktree-armed by construction.
Post-C1 that invariant is false, so the map records the CLASS (`wt` vs `tmp`) and
every consumer reads it. This is the load-bearing half of C1 — without it a
`/tmp`-armed name silently inherits worktree semantics at C2's variable site.

**C2 — exit-guard sticky grant for the `/tmp/` class, at BOTH sticky sites.**
1. Literal branch (`~L2136-2144`) — currently carries the explicit deferral
   *"NO sticky for /tmp latches"* and grants no sticky at all. Give it the same
   `_cd_guard_tail_exits`-gated grant the worktree branch has, with
   `sticky_pending_wt` left **0**. This is the S9 edit site.
2. Variable branch (`~L2216-2219`) — currently sets `scoped_wt=1` with the
   comment *"(#1554) $NAME latch is a worktree latch by construction"* and
   `sticky_pending_wt=1`, both UNCONDITIONALLY. C1 falsifies that comment. Both
   assignments become class-keyed off C1b: `wt` -> 1 (unchanged), `tmp` -> 0.
   Update the stale comment in the same edit.

The `sticky`/`sticky_wt` split already exists (`~L1930-1933`, `~L2046-2048`:
`sticky=1; sticky_wt=$sticky_pending_wt`), so a `/tmp` sticky with zero
worktree-privilege leakage is structurally available — the grant rides the
generic bit. The implementer audits **every** `scoped_wt` and `sticky_wt` read
site and states in the marker what each does for a `tmp`-class latch; the #1554
Arm-B bare-local-main fence is the one that must NOT fire (§0.0 criterion 3).

**C3 — BLOCK message: name the quoted-variable HOST refusal** (`~L2454` region).
The ssh paragraph names double quotes, redirects and `timeout` FLAG forms but not
a quoted-variable HOST; its existing "variable heads" wording means the ssh
BINARY and reads as covering the host. Disambiguate both, and state the working
recompose (`git -C /workspace/<repo> <verb>` inside the remote string, a pod-side
script, or the SSH MCP).

**Accuracy constraint (do not over-claim):** a quoted-variable host is NOT by
itself a refusal — the replay shows `timeout 120s ssh -o BatchMode=yes "$POD"
"<payload with no separator>"` ALLOWs. It contributes only by making the mask
refuse, after which in-payload separators split the payload. The message must
name it as a contributing arm ("a quoted or variable HOST token, once the payload
also carries separators/expansions/redirects…"), never as an independent one. An
over-claiming deny message misdirects the next agent, which is the failure this
whole task is about.

Also update the "three compliant worktree compose shapes" sentence to say the
variable/exit-guard shapes now accept `/tmp/<name>` scratch paths too, so the
sentence stops contradicting the scratch-merge recipe two paragraphs below it.
