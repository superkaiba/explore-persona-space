# Plan v1 — #2361: live-subagent screen for tick_triage + Step-2 in-flight-planner guard

`kind: infra` workflow-fix. Zero GPU. All work VM-local in an issue worktree.

## Requirement + acceptance criteria (from task body)

1. An autonomous session at a PARK status with a verifiably live Agent-tool
   subagent does NOT get a STALE-REDRIVE verdict — or, if it does, the full
   skill's Step 2 refuses to spawn a duplicate planner.
2. A genuinely dead chain at a PARK status still gets STALE-REDRIVE (the
   alive-but-stalled-at-PARK recovery must not be blunted). Regression tests
   cover both directions.
3. The new screen fails toward ticking on any classification error (the
   #1629/#1695 posture).

## Grounding (verified this session, 2026-08-26)

- `scripts/tick_triage.py` HEAD has no live-subagent screen; the
  STALE-REDRIVE cascade at `triage()` (~L1507) is
  `issue_liveness_reason` → `human_activity_reason` → give up.
- `STALE_S_DEFAULT = 1500 s` (25 min): the incident's back-to-back 22 m
  planner + 16 m fact-checker exceed it by construction (markers post at
  phase boundaries only).
- **Empirical signal (probed on real transcripts):** the harness writes each
  Agent-tool subagent's conversation to
  `<transcript-dir>/<session-id>/subagents/agent-<name>-<hash>.jsonl`
  (sibling dir of the session transcript `<session-id>.jsonl`) and APPENDS
  rows as the subagent works. Append gaps are bounded by the subagent's
  longest single tool call (Bash caps at 10 min), comfortably under the
  25-min window. The `.meta.json` sidecar carries spawn-time metadata only
  (no status field) — mtime of the `.jsonl` is the usable signal.
- Tick-noise immunity: cron `/issue-tick` prompts + triage Bash rows land in
  the PARENT transcript, never in `subagents/` — so the agent-jsonl mtime is
  clean where a parent-transcript mtime would be self-poisoned (the reason
  #1629 classifies row content instead of mtime).
- Row-content pairing (spawn ack ↔ completion rows) was evaluated and
  REJECTED: background-agent completions arrive in ≥3 heterogeneous shapes
  (`<agent-message from=…>`, teammate `idle_notification`,
  `<task-notification>`), harness-version-dependent; the mtime probe needs
  no pairing and no content read (content invariant #1000).

## Method delta

The mtime-probe screen is the in-session analogue of the existing #1051
detached-phase `log=` freshness probe — same posture (fail toward ticking,
teardown verdicts untouched, kill switch, content-invariant reason), new
signal source (own-session `subagents/` dir instead of breadcrumb `log=`).
Defense-in-depth (body surface 2+3) lands as prose in the Step 2 entry +
a `planner-dispatch` breadcrumb duty.

## Changes (4 files)

### 1. `scripts/tick_triage.py` — live-subagent screen (#2361, structural fix)

New helpers after the #1629 block (mirroring its shapes exactly):

- `subagent_probe_enabled()` — kill switch `EPM_TICK_SUBAGENT_PROBE`
  (default on; `0`/`false` disables; clone of `human_active_probe_enabled`).
- `subagent_fresh_s()` — window `EPM_TICK_SUBAGENT_FRESH_S`; malformed /
  non-positive → `stale_s()` (the marker staleness window — one coherent
  staleness notion; honors `EPM_TICK_STALE_S`).
- `subagent_live_reason(now: float) -> str | None`:
  - entirely exception-guarded → `None` (fail toward ticking); debug rung
    via `_human_probe_debug` (type-only, content invariant #1000);
  - resolve `_own_session_transcript_path()`; `None` → miss;
  - `subdir = Path(path).with_suffix("") / "subagents"`;
  - scan `subdir.glob("agent-*.jsonl")` mtimes; per-file
    `0 <= age < window`, smallest in-window age wins (future-dated mtimes
    skipped, never latched — the #1629 aggregation shape);
  - hit → `"subagent-live (newest agent transcript {age/60:.0f}m ago <
    {window/60:.0f}m, {n} agent transcripts)"`; else `None`. mtime-only —
    no subagent transcript content is ever read.

Wiring in `triage()` — third rung of the existing cascade, minimal diff:

```python
live = issue_liveness_reason(events, now, stale_s())
if live is None:
    live = human_activity_reason(now)
if live is None:
    live = subagent_live_reason(now)   # #2361 third rung
```

Module docstring: add a screen paragraph after the #1629 one (signal, fail
posture, kill switch). Comment block above the cascade updated to name the
third rung. Teardown verdicts structurally unaffected (screen lives inside
the `verdict == "STALE-REDRIVE"` branch only). HEALTHY-path cost unchanged
(the screen never runs on a HEALTHY tick).

### 3. `.claude/skills/issue/steps/04-step-2.md` — in-flight-planner guard (body surface 2+3)

Prepend after "Only if status is `planning`":

- **Planner-dispatch breadcrumb (duty):** immediately before invoking
  `/adversarial-planner`, post
  `task.py post-marker <N> epm:progress --by issue-orchestrator --note
  "planner-dispatch round=<k> — invoking /adversarial-planner …"`.
  (Also refreshes the staleness clock at phase START, body surface 3;
  `planner-dispatch` ≠ `stage-dispatch`, so the #1051 pid parser and #967
  triage observer never key on it.)
- **In-flight-planner guard (#2361):** at Step 2 ENTRY, if the marker trail
  shows a `planner-dispatch`-leading `epm:progress` younger than ~90 min
  with NO `epm:plan` / newer `plans/v<K>.md` since, AND the own-session
  `subagents/` dir holds an `agent-*.jsonl` fresher than ~30 min → a live
  planning chain is presumed: do NOT invoke a second planner; end the turn
  (the live chain completes; the next tick re-checks). Breadcrumb fresh but
  NO fresh agent transcript → prior chain presumed dead; proceed normally.
  Bounded wedge risk: a chain that died mid-write holds the guard at most
  one tick.
