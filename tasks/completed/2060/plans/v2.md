`kind: infra` (workflow-fix, fingerprint a20f18266959). 0 GPU-h, VM-only, no pod.
Incident parent: #1947 (pod-1947-loc billed 14+ min RUNNING with `runtime: null` after

## 1. Requirement + acceptance criteria

Three facets from the task body, all against CURRENT code (post-#2011/#1931/#2149 drift
verified by the clarifier, marker 2026-08-10T02:50Z):

- **(a)** `pod.py provision` must tear down the pod it created when the SSH bootstrap
  wait fails, by default, on BOTH failure paths of
  `scripts/pod_lifecycle.py::_provision_wait_register_bootstrap` (the shared GPU/CPU
  provision tail, #747): (a1) the `wait_for_ssh` `RunPodError` path (ssh-wait timeout,
  the exact #1947 `runtime: null` class — currently records bad placement then `raise`s
  with the pod billing) and (a2) the bootstrap `rc != 0` path after the #1931
  retry-once (currently records, prints `BOOTSTRAP-FAILED pod=<name> rc=<rc>` last on
  stderr, `sys.exit(rc)` — pod billing). A new `--keep-on-bootstrap-failure` flag
  preserves the pod for the deliberate debug case.
- **(b)** The watcher's no-port wedge arm (`scripts/autonomous_session_watch.py::
  decide_pod_wedge` + caller `_process_wedged_pod`) must be able to reap a RUNNING pod
  that NEVER exposed a runtime/port since creation (never had one — not lost one), past
  a bootstrap grace floor, EVEN when `keep_running is True` — with all other guards kept
  (owner-liveness tri-state, ≥threshold consecutive-tick confirmation, K floor,
  once-per-episode bounding), a distinct env knob, and a distinct sidecar reason.
- **(c)** The capacity-fallback chain must no longer dead-end on `Pod <name> already
  exists` when the existing pod is the wedged residue of an earlier failed rung.
  **Scoping decision (per body: "fix (a) largely implies it"):** (a)'s default teardown
  removes the residue before the provision subprocess exits, so later rungs see a clean
  namespace; no separate cross-rung counter is added. Discharged by (a) + a regression
  test; `--keep-on-bootstrap-failure` residue is deliberate (debug case) and out of
  scope.

**Acceptance criteria** (each maps to a test in §5):
1. A provision whose `wait_for_ssh` raises leaves NO live pod (terminate called with
   the exact `info.pod_id` this provision created); the original error still propagates.
2. Same, for the bootstrap `rc != 0` final-failure path; `sys.exit(rc)` preserved.
3. Under `--keep-on-bootstrap-failure`, NO terminate fires on either path.
4. `BOOTSTRAP-FAILED pod=<name> rc=<rc>` remains the LAST stderr line (#1931 contract);
   `BOOTSTRAP-FAILED-TERMINATED pod=<name>` is emitted alongside (before it), never
   replacing it; `BOOTSTRAP-OK` token count/behavior untouched.
5. A teardown failure prints a WARN and NEVER masks the original bootstrap error.
6. `decide_pod_wedge` with `never_ran=True`, matured + confirmed, `owner_live is False`
   returns the new terminate action even when `keep_running is True`.
7. A pod that HAD a runtime and lost it (`never_ran=False`), or inside the grace
   window, or with `never_ran` indeterminate, keeps byte-equivalent OLD behavior
   (`alert` for tagged pods; existing #770/#1667 invariant untouched).
8. `workflow_lint.py` (no flags) + ruff on touched files + the targeted pytest files
   all pass.

## 3. Method delta

Nothing like this exists yet: provision has NO failure-teardown branch, and the wedge
arm has NO tag-independent action. The delta vs the landed neighbors:
- vs #1931 (retry-once): we act AFTER its final failure, preserving its verdict-token
  contract byte-for-byte.
- vs #2011 (bad-placement records): teardown sequences AFTER `_record_bad_placement_loud`
  on both paths (the record must land before the pod disappears; `get_pod` late-host
  lookup stays before teardown).
- vs #2149 (`decide_keep_running_pod_idle_escalation`, alert-only idle leg) and #1582
  (owner escalation): NOT touched. The never-ran carve-out lives in the WEDGE arm
  (`decide_pod_wedge`), which already runs for tagged pods (the tag is read lazily
  inside `_process_wedged_pod`, not short-circuited upstream). Distinct env knob +
  distinct sidecar reason per the body's adjacency constraint.
- vs #770/#1667 terminate-failover: the new action is TERMINATE-ONLY (no re-provision
  failover) — a never-ran pod's owner chain already routed its work elsewhere (the
  #1947 chain fell through to SLURM); re-provisioning would resurrect spend nobody
  wants.

## 4. Design — concrete diffs

### 4.1 `scripts/pod_lifecycle.py` — facet (a)

1. **Flag:** `p.add_argument("--keep-on-bootstrap-failure", action="store_true",
   help="Keep the pod alive for debugging when the SSH/bootstrap wait fails (default: terminate the pod this provision created)")`
   in the provision parser block (~L3813). Read via `getattr(args,
   "keep_on_bootstrap_failure", False)` (hand-built-Namespace precedent, #2011).
2. **One shared helper** (module-level, so the TERMINATED token literal appears exactly
   once — the #1931 single-literal convention):

   ```python
   def _teardown_failed_provision(info: PodInfo, name: str, *, keep: bool) -> None:
       """Best-effort terminate of the pod THIS provision created, on a
       bootstrap/ssh-wait failure (#2060; incident #1947). Surgical by pod_id —
       never name-resolution, so sibling pod-<N>-<slug> pods are untouched.
       NEVER raises: a teardown failure must not mask the original error."""
       if keep:
           print(
               f"  --keep-on-bootstrap-failure: pod {name} (id={info.pod_id}) kept "
               f"alive for debugging — it is BILLING; terminate with "
               f"`pod.py terminate` when done.",
               file=sys.stderr,
           )
           return
       try:
           terminate_pod(info.pod_id)
           print(f"BOOTSTRAP-FAILED-TERMINATED pod={name}", file=sys.stderr)
       except Exception as exc:  # noqa: BLE001 — best-effort by contract (#2060)
           print(
               f"  WARN: teardown of failed-provision pod {name} "
               f"(id={info.pod_id}) failed: {exc} — pod may still be BILLING; "
               f"terminate manually with `pod.py terminate`.",
               file=sys.stderr,
           )
   ```

   Implementer judgment: also best-effort remove the pods.conf/sidecar rows on
   successful terminate IF the registration already happened at that point in the tail
   (reuse the exact removal helper `cmd_terminate` uses, e.g. `_remove_from_pods_conf`
   / `_terminate_clear_stale_sidecar` — read the current tail ordering first; if
   registration happens AFTER the failure points, no removal is needed).
3. **ssh-wait path:** in `except RunPodError`, after `_record_bad_placement_loud(...,
   reason="ssh-wait-timeout")` and the existing guidance print, insert
   `_teardown_failed_provision(info, name, keep=keep_flag)` then keep the bare `raise`.
   Update the guidance print's trailing clause ("…or terminate it if it never does") to
   state what actually happens now (auto-terminated by default / kept under the flag).
4. **bootstrap-failed final path:** after `_record_bad_placement_loud(...,
   reason="bootstrap-failed")`, insert `_teardown_failed_provision(...)`, THEN the
   existing `print(f"BOOTSTRAP-FAILED pod={name} rc={rc}", file=sys.stderr)` +
   `sys.exit(rc)` — TERMINATED token (from inside the helper) prints BEFORE the
   BOOTSTRAP-FAILED line, preserving last-stderr-line (#1931). The retry-once
   INTERMEDIATE failure branch is NOT touched (teardown only after the retry is
   exhausted). The #1334 suffix-scoped terminate-hint print becomes conditional on the
   keep flag (the hint is only accurate when the pod survives) — implementer may
   instead leave it and let the helper's messages supersede; either way tests pin the
   final stderr ordering.
5. **Signature threading:** `_provision_wait_register_bootstrap` gains the keep flag by
   reading `args` (it already receives `args`) — no signature change needed.

### 4.2 `scripts/autonomous_session_watch.py` — facet (b)

1. **`decide_pod_wedge`** gains `never_ran: bool | str = False` (tri-state; ONLY the
   literal `True` activates anything — same only-the-literal-acts polarity as MF2/#1667).
   New case, inserted at the confirmed-past-K branch BEFORE the `keep_running is True`
   early-return:

   ```python
   if never_ran is True:
       # #2060 never-ran carve-out: the pod NEVER exposed a runtime/port since
       # creation, so no workload can have reached it — there is nothing the
       # keep-running tag or the inputs-on-HF gate can protect. keep_running and
       # inputs_ok are BYPASSED by design; owner-liveness is KEPT (a live owner
       # may be debugging under --keep-on-bootstrap-failure).
       if owner_live is False:
           return ("terminate-never-ran", 0)
       return ("alert-owner-live", 0)
   ```

   Docstring: extend the Cases list + the Decision invariant paragraph — the invariant
   becomes: `terminate-failover` unchanged; `terminate-never-ran` returned ONLY when
   `never_ran is True` (literal) AND `owner_live is False` (literal) AND matured +
   confirmed. Every non-True `never_ran` value keeps byte-equivalent pre-#2060 behavior.
2. **Caller `_process_wedged_pod`** computes `never_ran` lazily on the confirmed branch
   (the MF2 lazy pattern), fail-toward-False on every missing signal:
   - kill switch `EPM_DISABLE_WEDGE_NEVER_RAN_REAP=1` → `False`;
   - `created_ts` = parsed `info.created_at` (ISO-8601 → epoch; None/parse-fail → `False`);
   - `first_seen` (incarnation anchor) within `EPM_WEDGE_NEVER_RAN_OBSERVE_SLOP_S`
     (default 1200s = 2 cron periods) of `created_ts` — i.e. observation started near
     creation, so any unobserved port window is ≤ ~2 ticks;
   - `wedge_first_seen` within one tick (same slop constant) of `first_seen` — wedged
     from FIRST observation, and the wedge episode never cleared since (a port
     appearance clears `wedge_first_seen`, so a continuous episode anchored at
     first-observation means no port was ever seen);
   - pod age `now - created_ts >= EPM_WEDGE_NEVER_RAN_GRACE_MIN` (default 45 min —
     comfortably past the 10-min ssh wait + #1931 retry + bootstrap wall);
   - owner_live probe: reuse `_wedge_owner_live(issue, now)` — probed when
     `never_ran is True` and the other confirm conditions hold (extend the existing
     lazy-probe condition so the never-ran branch also pays for the probe).
3. **Action handler:** `terminate-never-ran` → new small handler (parallel to the
   failover handler, NOT reusing it — no re-provision): pre-terminate liveness re-probe
   (re-fetch pod by name; gone → no-op + clear; port appeared → clear wedge, no
   terminate — the #770 v2 r3 degradation parity), then `terminate_pod(pod_id)` (add
   `terminate_pod` to the L1093 `from runpod_api import` list), one marker per episode
   (sentinel `[autonomous_session_watch:runpod-noport-wedge-never-ran-terminate]`,
   anti-liveness), one sidecar row with distinct reason `never-ran-keep-running-reap`
   (the pod-safety events sidecar the wedge arm already writes), fail-soft push.
   Once-per-episode bound: persist `wedge_never_ran_terminated_ts` in the pod-safety
   state (pod_id-keyed via the existing MF4 reset) — a later tick with the field set
   for this pod_id never re-terminates; dry-run prints only.
4. **Docs:** one short paragraph in `.claude/rules/background-automation.md` under the
   watcher section (wedge arm) naming the carve-out, its two env knobs
   (`EPM_WEDGE_NEVER_RAN_GRACE_MIN`, `EPM_DISABLE_WEDGE_NEVER_RAN_REAP`), the slop
   constant, the sentinel, and the sidecar reason. Module docstring pass count is
   UNCHANGED (no new pass — an arm extension); verify
   `workflow_lint.py --check-asw-docstring-pass-count` stays green.
