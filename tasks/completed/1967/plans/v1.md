### 4.1 Trigger extension — `_BATTERY_TRIGGER_RE` (in place)

Add a screen alternation (starter set, calibration prunes/tightens):

```
| near[- ]dup(?:e|licate)?s?[- ](?:screen|scan|pass|filter)
| dedup(?:e|lication)?[- ](?:screen|scan|pass)
| pairwise[- ]similarity
| similarity[- ]screen
```

Compound tokens by design (dedupe/near-dupe REQUIRE an adjacent
screen/scan/pass noun) so bare data-prep prose ("deduplicated the
list") never triggers. `pairwise similarity` starts bare per the task
body's sketch; if the corpus sweep shows false-FAILs, tighten to
`pairwise[- ]similarity[- ](?:screen|scan|matrix)` or require an
adjacent pool token — calibration decides, decision recorded in the
comment block. Extending IN PLACE (not a separate screen-only regex) is
deliberate: c32 then classifies screen rows in basis-column compute
tables as battery rows, demanding a measured/pilot-gated basis — exactly
what the rule's POOL-SCALE clause requires of screens (#1738/#1901).

### 4.2 Evidence arm — new `_SCREEN_ARITH_RE` (separate regex; `_DRAW_FACTOR` untouched)

A screen's sizing arithmetic is pool-quadratic, not draw-bearing. New
regex accepted ALONGSIDE `_MULT_ARITH_RE` in the c12 window loop
(`has_arith = _MULT_ARITH_RE | _SCREEN_ARITH_RE`), matching (starter set):

```
\d[\d,_]*\s*(?:\^\s*2|²|\*\*\s*2)          # 13,674^2 / pool² forms
| n\s*\(\s*n\s*[-−]\s*1\s*\)\s*/\s*2       # n(n-1)/2 pairs
| \d[\d,_]*(?:\.\d+)?\s*(?:e\d+\s*)?(?:pairwise\s+)?(?:pairs|comparisons)\b   # 1.87e8 pairs / N comparisons
| pool\s*(?:size\s*)?(?:[×x*]|squared)     # pool × pool / pool squared
```

`_DRAW_FACTOR` / `_MULT_ARITH_RE` are deliberately NOT widened — widening
them would loosen the #810 false-PASS guard for true batteries (a
grid-only product with a "comparisons" noun must not satisfy a battery's
draw arithmetic). Windows anchored by `_SCREEN_ARITH_RE` lines also anchor
their own ±15 evidence window (mirror of the #1086 draw-arith anchoring),
so a §9 sizing block far from the §4 screen registration still pairs.
