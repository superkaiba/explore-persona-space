### 4.1 Trigger extension — TWO named alternations, one combined consumer regex

Screen tokens live in a new named `_SCREEN_TRIGGER_RE` (starter set,
calibration prunes/tightens):

```
near[- ]dup(?:e|licate)?s?[- ](?:screen|scan|pass|filter)
| dedup(?:e|lication)?[- ](?:screen|scan|pass)
| pairwise[- ]similarity
| similarity[- ]screen
```

`_BATTERY_TRIGGER_RE` is REDEFINED as the union
`battery-alternation | screen-alternation` (compiled from the two source
pattern strings) so both existing consumers (c12 trigger windows at L1416,
c32 battery-row classification at L5735) pick screens up with no
call-site change — while c12's window WALK re-tests each trigger line
against the class-specific sub-regexes to TYPE the window (§4.2).
Compound tokens by design (dedupe/near-dupe REQUIRE an adjacent
screen/scan/pass noun) so bare data-prep prose ("deduplicated the list")
never triggers. `pairwise similarity` starts bare per the task body's
sketch; if the corpus sweep shows false-FAILs, tighten to
`pairwise[- ]similarity[- ](?:screen|scan|matrix)` or require an adjacent
pool token — calibration decides, decision recorded in the comment block.
In-place union (not a c12-only regex) is deliberate: c32 then classifies
screen rows in basis-column compute tables as battery-branch rows,
demanding a measured/pilot-gated basis — exactly what the rule's
POOL-SCALE clause requires of screens (#1738/#1901).

### 4.2 Evidence arm — `_SCREEN_ARITH_RE`, CLASS-TYPED windows (critic MF1)

New regex for pool-quadratic sizing arithmetic (starter set):

```
\d[\d,_]*\s*(?:\^\s*2|²|\*\*\s*2)          # 13,674^2 / pool² forms
| n\s*\(\s*n\s*[-−]\s*1\s*\)\s*/\s*2       # n(n-1)/2 pairs
| \d[\d,_]*(?:\.\d+)?(?:e\d+)?\s*(?:pairwise\s+)?(?:pairs|comparisons)\b   # 1.87e8 pairs / N comparisons
| pool\s*(?:size\s*)?(?:[×*]|(?<!\w)x(?!\w)|squared)   # pool × pool / pool squared — ASCII x with _MULT_TOKEN word-boundary discipline (#1099; critic SF3)
```

**Windows are TYPED by their anchoring trigger — evidence never crosses
class (critic MF1):**

- **battery-class window** (anchored by a battery-alternation line, or a
  `_MULT_ARITH_RE` self-anchor line): arithmetic evidence =
  `_MULT_ARITH_RE` ONLY. `_DRAW_FACTOR` / `_MULT_ARITH_RE` are NOT
  widened; screen-shaped arithmetic ("576 comparisons" in Holm-correction
  prose) can never satisfy a battery window — the #810 grid-only
  false-PASS guard is preserved verbatim.
- **screen-class window** (anchored by a `_SCREEN_TRIGGER_RE` line, or a
  `_SCREEN_ARITH_RE` self-anchor line — the latter anchors ONLY when ≥1
  screen trigger fired somewhere in the plan, mirroring the #1086
  draw-arith anchoring): arithmetic evidence = `_SCREEN_ARITH_RE` ONLY.
- A line matching BOTH alternations types its window battery-class
  (stricter evidence; same both-families precedent as c32's "a row
  matching both families is a FIT row").
- Commitment evidence (`_BATCHED_COMMIT_RE`) is common to both classes.
- PASS requires: every TRIGGERED class independently satisfied (for each
  class with ≥1 trigger window, some window of THAT class carries its own
  arithmetic + a commitment). The missing-evidence detail names the class.
