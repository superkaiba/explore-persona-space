## 4. Design

### Phase A — hard HEAD guard at the task_workflow commit site

**Why this still matters given §2.5:** the incident did not go through this window, but the window is real: `repo_root()` is LRU-cached per `(pid, cwd)` (L666–686), so a long-lived process (PM session, poller, agent daemon) that resolved while the primary was on `main` keeps committing at the primary even if HEAD later moves off `main`; the #1128 hook guards only Claude Bash calls; the only current detection is the post-hoc, warn-only #1100 landing check (whose docstring names exactly this strand class as the #1083 15-problem registry-drift cause). The Goal mandates prevention at the commit site.

**New code (all in `src/explore_persona_space/task_workflow.py`, near `_warn_if_commit_stranded`):**

```python
class CommitHeadGuardError(RuntimeError):
    """Pre-commit HEAD guard tripped on the PRIMARY checkout (#1530).

    Raised by _assert_commit_head when the primary checkout's HEAD is not
    attached to `main` at commit time. Deliberately a distinct class:
    _commit_after_durable_append defers it (the append is durable in the
    PRIMARY working tree by construction), while the routed-path guard
    failure stays a plain RuntimeError (routed appends are NOT durable
    against the managed worktree's reset --hard re-sync and must never
    be deferred — see _commit_after_durable_append's contract).
    """

_COMMIT_HEAD_REPROBE_SLEEP_S = 0.5  # matches the resolver's grace probe (L483)

def _assert_commit_head(repo: Path, routed: bool, env: dict[str, str]) -> None:
    """Hard pre-commit branch guard (#1530): verify, immediately before
    `git commit --only`, that the checkout we are about to commit in is in
    the state the resolver promised. Primary: HEAD attached to `main`.
    Routed (_task-main-pin): HEAD DETACHED (the pin contract).

    Primary mismatch: one 0.5s re-probe (transient checkout transit), then
    invalidate_cache() — so the NEXT mutation in this process re-resolves
    and auto-routes through the managed worktree — and raise
    CommitHeadGuardError. NEVER silently re-routes THIS commit mid-mutation:
    the caller's append already landed in the PRIMARY working tree, and the
    managed worktree's tree (reset to main) does not contain it — committing
    there would commit a stale file state (data-losing).

    Routed mismatch (HEAD unexpectedly attached to a branch): plain
    RuntimeError immediately — committing would move that branch AND the
    subsequent CAS would fail messily; fail loud pre-commit instead.

    Incident #1530 forensics: the 2026-07-18 stranding was NOT this window
    (task.py committed correctly on main; a branch-side FF imported the
    commits) — this guard closes the ADJACENT stale-(pid,cwd)-cache window
    the #1100 landing check can only detect post-hoc.
    """
    for attempt in (1, 2):
        sym = subprocess.run(
            ["git", "-C", str(repo), "symbolic-ref", "--short", "HEAD"],
            env=env, capture_output=True, text=True, check=False,
        )
        branch = sym.stdout.strip() if sym.returncode == 0 else None
        if routed:
            if branch is None and "not a symbolic ref" in (sym.stderr or "").lower():
                return  # detached at the main pin — the expected routed state
            raise RuntimeError(
                f"managed main-pin worktree {repo} has HEAD attached to {branch!r} "
                f"(expected DETACHED at the main tip); refusing to commit — a commit "
                f"here would advance {branch!r} and break the CAS advance-main contract. "
                f"Remove/re-create the managed worktree (git worktree remove --force) "
                f"and re-run."
            )
        if branch == "main":
            return
        if attempt == 1:
            time.sleep(_COMMIT_HEAD_REPROBE_SLEEP_S)
            continue
        invalidate_cache()  # next mutation re-resolves -> managed-worktree route
        state = f"on branch {branch!r}" if branch else f"not attached ({(sym.stderr or '').strip()!r})"
        raise CommitHeadGuardError(
            f"refusing to commit task state: primary checkout {repo} HEAD is {state}, "
            f"not 'main' — the commit would strand on a non-main ref (#1530). The "
            f"append (if any) is durable in the working tree; the resolver cache was "
            f"invalidated so the next mutation auto-routes through the managed "
            f"main-pin worktree. Re-attach the primary to 'main' and investigate what "
            f"moved its HEAD (repo-root HEAD reflog)."
        )
```

**Call sites in `_git_commit()` (L6210–6298):** insert `_assert_commit_head(repo, routed, env)` immediately before BOTH `_run_git(["commit", ...])` invocations — the first attempt (L6280) and the post-sequencer-wait TOCTOU final retry (L6292; the re-wait can take long enough for state to change). Not before staging: `git add` to a wrong checkout's index moves no ref, and guarding only the commit keeps the change minimal + honors the Goal's "immediately before `git commit --only`" literally. The early-return no-change path (L6270–6272) commits nothing and needs no guard.

**Deferral integration in `_commit_after_durable_append()` (L6406–6411):**

```python
    except (subprocess.CalledProcessError, SequencerWaitTimeout, CommitHeadGuardError) as e:
        # CommitHeadGuardError fires ONLY on the primary path (the routed-path
        # guard raises plain RuntimeError, which stays uncaught by design) and
        # it invalidates the resolver cache BEFORE raising — so the
        # _is_routed_root(repo_root()) re-check below would RE-RESOLVE, route
        # to the managed worktree, and wrongly re-raise a deferrable
        # primary-path failure. The append is durable in the PRIMARY working
        # tree by construction for this class: defer directly.
        if not isinstance(e, CommitHeadGuardError) and _is_routed_root(repo_root()):
            raise
```

Everything else in the except body (ERROR log, `DEFERRED_COMMITS_LOG` row, `return False`) is unchanged. `set_status` and the idempotent setters call `_git_commit` without the deferral wrapper, so `CommitHeadGuardError` propagates there — matching their existing #898 fail-loud contract. Docstrings of `_git_commit` and `_commit_after_durable_append` are updated to name the new class (docstring-on-edit rule).

## 11. Decision Rationale

N/A — no model training

- **D1 — Guard placement: immediately before each `git commit --only` invocation inside `_git_commit`, not in `_run_git` or at staging.**
  What: two call sites (L6280, L6292). Why: `_run_git` serves rc-as-signal probes (`diff --cached --quiet`) and read-only calls — guarding there would tax every git call and complicate the retry contract; staging moves no ref. The Goal names the commit site literally. Source: `task_workflow.py` L6144–6207 (`_run_git` contract), L6270–6292; task #1530 `## Goal`. Alternatives: guard at resolver only (status quo — defeated by the (pid,cwd) cache, L666–686); guard in `_run_git` (over-broad, breaks check=False semantics).
- **D2 — Fail mode: one 0.5 s re-probe → `invalidate_cache()` → raise; NEVER re-route the current commit mid-mutation.**
  What: refuse-and-self-heal, not retry-through-managed-worktree. Why: the caller's append already landed in the PRIMARY working tree; the managed worktree's tree is `reset --hard main` (L636–642) and does NOT contain it — routing THIS commit there would commit a stale file state (silent data loss, worse than the bug). Deferral (append durable + forensic row) is the sanctioned degradation; the invalidate makes the NEXT mutation route correctly. Source: `_ensure_managed_main_worktree` L636–642; `_commit_after_durable_append` docstring L6370–6398; CLAUDE.md `post-marker` deferred-commit contract. Alternatives: re-append + commit in the managed tree (requires threading the mutation payload into `_git_commit` — invasive, duplicates append logic); block-wait for HEAD to return (unbounded; the resolver's #996 wait already covers the one legitimate transient — a live rebase — at resolve time).
- **D3 — Dedicated `CommitHeadGuardError(RuntimeError)` + isinstance-ordered deferral, instead of reusing `CalledProcessError` or bare `RuntimeError`.**
  What: new exception class added to `_commit_after_durable_append`'s caught tuple with a routed-re-check bypass. Why: bare `RuntimeError` is deliberately NEVER deferred (the routed CAS raises it, L6386–6390); `CalledProcessError` would be a fabricated subprocess result; and the existing `_is_routed_root(repo_root())` re-check (L6410) re-resolves POST-invalidation and would wrongly re-raise the deferrable primary-path case. Source: `task_workflow.py` L6383–6411. Alternatives: not invalidating before raise (loses self-heal; every later mutation re-fails), catching in each caller (N call sites, drift-prone).
- **D4 — Routed-arm check = DETACHED HEAD only (plain `RuntimeError` on attached), no tip-equality check.**
  What: `symbolic-ref` failure with "not a symbolic ref" passes; any attached branch fails. Why: requiring HEAD == `refs/heads/main` tip at commit time would false-fail whenever a non-task.py writer legitimately advanced `main` mid-mutation — exactly the case `_advance_main_ref`'s CAS (L653–663) already handles loud and correctly. Source: L424–435 (detached-pin design rationale), L653–663. Alternatives: full tip check (races the CAS), no routed check (leaves the attached-pin corruption case to a messy CAS failure post-commit).
- **D5 — `new_worktree.sh`: documentation + stderr echo only; no code-path change.**
  What: comment + echo at L341. Why: F3/F1/F2 prove branch creation never touches the shared HEAD — the Goal's third clause is already satisfied; the only defect was interpretability of the "Already on" line, which mis-seeded this task's candidate. Source: §2.5 F1–F3 (reflogs + git 2.34.1 scratch probe). Alternatives: `checkout --quiet` (hides real checkout errors and the informative line both), switching `_add` away from `--no-checkout` (would materialize the full tree before sparse-set — the exact cost #596 exists to avoid).
- **D6 — Root cause fixed in the memory files; a mechanical hook block of worktree-local `git merge main` is DEFERRED.**
  What: correct 5 memory files to the fetch + `merge --ff-only origin/main` form; do not extend `guard_repo_root_branch.sh` in this task. Why: the memories are the only sanctioned prescription of the harmful form (SKILL.md recovery paths already use `origin/main`); a hook block on worktree merges risks wedging legitimate improvised recoveries (SKILL.md L11031 explicitly anticipates "any improvised merge" during 10d conflict recovery) and is a distinct surface with its own review needs. Deferral is surfaced as a follow-up (recursion-guard parked, per this session's `EPM_WORKFLOW_FIX_SESSION` status). Source: `feedback_ff_worktree_to_main_before_edit.md` L11/L48; SKILL.md L10596/L11031; `.claude/rules/workflow-fix-on-bug.md` § Recursion guard. Alternatives: hook now (blast radius unreviewed here), memory-only with no follow-up (leaves re-derivation risk unlogged).
- **D7 — Corrected FF recipe: bounded fetch + `merge --ff-only origin/main`, mirroring `new_worktree.sh`'s #1214 ladder.**
  What: `timeout 60 git -C "$WT" fetch origin "+refs/heads/main:refs/remotes/origin/main"` then FF to `origin/main`; on fetch failure stay on the existing (pushed-history) base. Why: origin/main carries every landed workflow fix (fix merges push immediately per standing policy) and zero unpushed task-state churn; the explicit refspec + timeout are the proven #1214 form (script L243–265). Traced on the incident's own values (fact-check corrected): at 14:11:10Z the origin/main tracking ref = f8b939c684 (fetched 14:09:49Z; 0c6103dc00 is its ancestor) → the corrected recipe FFs issue-1509 to f8b939c684 — pushed history only, importing ZERO unpushed commits (vs the old recipe's 4). Source: `scripts/new_worktree.sh` L22–28, L243–265; §2.5 F5. Alternatives: FF to local main (the bug), no FF at all (re-opens the 2026-06-10 stale-spec revert class the memory exists to prevent).
