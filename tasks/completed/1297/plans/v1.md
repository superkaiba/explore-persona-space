# Plan — Task #1297: Fix the `sys.modules` stub-isolation bug in `tests/test_issue658_judge_e0_batch_migration.py`

Single-file test-hygiene fix. `kind: infra`, workflow v1, 0 GPU-h, no pod, no experiment.

## 1. Goal

Fix the `sys.modules`-stub isolation bug in `tests/test_issue658_judge_e0_batch_migration.py` — the stub leaks across test files in the same pytest session. (Task #1297 Goal, verbatim; body `## Goal` H2 — no `goal:` frontmatter, `kind: infra`.)

The file installs a trivial fake `issue658_common` module into `sys.modules` at collection/import time (`MOD = _load_module()` at module scope, `tests/test_issue658_judge_e0_batch_migration.py:77`) and never removes it. Two ordering-dependent defects follow: (a) **stub-first** — any later same-session importer of `issue658_common` gets the trivial stub (`tests/test_issue811_maxp.py:30` then dies with `ImportError: cannot import name 'summarize_answer_span'` at collection); (b) **real-first** — the guard `if "issue658_common" in sys.modules: return` (line 56-57) silently accepts a previously-loaded REAL module, so the script under test binds real functions instead of the stub — the migration tests are then nondeterministically backed, coupled to unrelated `issue658_common` edits. The fix makes the load deterministic (the stub ALWAYS backs the module under test) and leak-free (prior `sys.modules` state restored after exec), and corrects the stale docstring claiming `issue658_common` "lives on the issue-658 branch, not main" (it exists on main, 20 KB, and is imported for real by two other test files).

## 2. Prior work / established practice

**In-repo canonical precedent (the exact idiom):** `tests/test_issue475_vlm_config.py::_call_helper` (lines 62-78) stubs the SHARED name `transformers` with save → install → `try:` use → `finally:` restore-prior-or-delete. This is the shape this plan adopts verbatim.

**Pytest-documented equivalent:** `pytest.MonkeyPatch` can be instantiated outside a fixture — `with pytest.MonkeyPatch.context() as mp: mp.setitem(sys.modules, "issue658_common", stub); ...` restores the prior entry (or deletes an added one) on exit. Semantically identical to the try/finally; either satisfies acceptance. The function-argument `monkeypatch` fixture is NOT usable here because the load happens at module scope (collection time), outside any fixture. Try/finally is chosen for parity with the in-repo 475 precedent (see §11).

**Codebase survey of `sys.modules[` writes in `tests/` (grep, 40 hits):** almost all register the REAL script module under a UNIQUE alias (`"..._under_test"`, `"issue581_audit"`, `"verify_plan"`, …) — a benign class: unique keys cannot collide, and canonical-name registrations hold the real module, so later importers see correct behavior. Exactly TWO files stub a SHARED real-module name: `test_issue475_vlm_config.py` (`transformers`, WITH restore — clean) and this file (`issue658_common`, WITHOUT restore — the bug). No sibling file needs the same fix; the second-order alias key this file registers (`"issue658_judge_e0_batch_under_test"`, line 72) is the same leak class at lower risk (unique key) and is cleaned up in the same diff.

**Consumers of `issue658_common` in `tests/` (grep, exhaustive):** `tests/test_issue658_invariants.py:27` (`import issue658_common as common` — real), `tests/test_issue811_maxp.py:30` (`from issue658_common import summarize_answer_span` — real; the stub lacks that name), and this file (the stub). Full-suite alphabetical order currently masks the breakage (invariants < judge_e0_batch_migration < issue811 — the real module loads first, the guard early-returns).

**Script-under-test import shape (verified):** `scripts/issue658_judge_e0_batch.py:31` does `from issue658_common import (E0_COLUMNS, JUDGE_MODEL, _verdict_truthy, dump_json, load_json)` at module level — once, no lazy re-imports, no `importlib`/`reload` anywhere in the script (grep: `issue658_common` appears exactly at line 31). The `from X import` resolves through `sys.modules["issue658_common"]`, so the stub KEY cannot be namespaced away without rewriting the script (out of scope). Because all five names are bound into the exec'd module's namespace at exec time, the stub does NOT need to remain in `sys.modules` after exec.

**Edit 2 — replace `_install_issue658_common_stub()` (lines 48-64) with a pure builder** (no `sys.modules` write, no early-return guard — the guard is the real-first bug and is deleted outright):

```python
def _make_issue658_common_stub() -> types.ModuleType:
    """Build (do NOT install) a minimal ``issue658_common`` stand-in.

    The script imports exactly ``E0_COLUMNS, JUDGE_MODEL, _verdict_truthy,
    dump_json, load_json`` at module level; none are exercised by these tests
    (they hit ``submit_and_collect`` / ``_collect_shard`` directly), so
    trivial stand-ins suffice.
    """
    stub = types.ModuleType("issue658_common")
    stub.__is_issue658_test_stub__ = True  # marker for the no-leak pin test
    stub.E0_COLUMNS = {}
    stub.JUDGE_MODEL = "claude-sonnet-4-5-20250929"
    stub._verdict_truthy = lambda verdict, key, column_id: bool(verdict.get(key))
    stub.dump_json = lambda obj, path: Path(path).write_text(json.dumps(obj))
    stub.load_json = lambda path: json.loads(Path(path).read_text())
    return stub
```

**Edit 3 — rewrite `_load_module()` (lines 67-74) as save → install → exec → restore** (mirror of `test_issue475_vlm_config.py::_call_helper`; `MOD = _load_module()` at line 77 stays at module scope, unchanged):

```python
def _load_module():
    """Exec the script with the stub pinned into ``sys.modules`` AROUND the
    exec only; prior state is restored in ``finally`` (the
    ``tests/test_issue475_vlm_config.py::_call_helper`` idiom), so:

      - the module under test ALWAYS binds the stub — deterministic
        regardless of whether another test file loaded the REAL
        ``issue658_common`` first — and
      - nothing leaks: later same-session importers (``test_issue811_maxp``,
        ``test_issue658_invariants``) get the real module.

    The exec'd module keeps its own bound references to the stub objects
    (module-level ``from issue658_common import ...``), so the stub need not
    stay registered after exec; the script has no lazy re-imports of
    ``issue658_common`` (it appears exactly once, at module level).
    """
    saved = sys.modules.get("issue658_common")
    sys.modules["issue658_common"] = _make_issue658_common_stub()
    try:
        spec = importlib.util.spec_from_file_location(
            "issue658_judge_e0_batch_under_test", SCRIPT_PATH
        )
        assert spec is not None and spec.loader is not None
        mod = importlib.util.module_from_spec(spec)
        # Register BEFORE exec (forward-ref/dataclass machinery resolves via
        # sys.modules during exec); popped after — same leak class, unique key.
        sys.modules["issue658_judge_e0_batch_under_test"] = mod
        try:
            spec.loader.exec_module(mod)
        finally:
            sys.modules.pop("issue658_judge_e0_batch_under_test", None)
    finally:
        if saved is not None:
            sys.modules["issue658_common"] = saved
        else:
            sys.modules.pop("issue658_common", None)
    return mod
```

**Edit 4 — new regression test** (append near the top test section; see §5c for what each assert pins):

```python
def test_stub_does_not_leak_into_sys_modules():
    """Isolation pin (#1297): module load leaves no residue in sys.modules,
    and the module under test bound the STUB, not the real issue658_common.

    ``issue658_common`` is either absent (this file ran first) or the REAL
    module (another test file imported it) — never this file's stub; the
    under-test alias is popped after exec.
    """
    common = sys.modules.get("issue658_common")
    assert not getattr(common, "__is_issue658_test_stub__", False)
    assert "issue658_judge_e0_batch_under_test" not in sys.modules
    # Deterministic binding: the stub's lambdas are defined in THIS test
    # module; the real _verdict_truthy has __module__ == "issue658_common".
    assert MOD._verdict_truthy.__module__ == _make_issue658_common_stub.__module__
```

**Ordering-determinism property the fix buys (both orderings, before vs after):**

| Ordering | Before (bug) | After (fix) |
|---|---|---|
| Real-first (`test_issue658_invariants` → this file) | Guard early-returns on the pre-loaded real module → script binds REAL functions; migration tests nondeterministically backed, silently coupled to `issue658_common` edits | `saved` = real module → stub overwrites → exec binds STUB → real module restored. `invariants`' own `common` name is a direct module-object reference held at its module scope, unaffected by the temporary `sys.modules` swap |
| Stub-first (this file → `test_issue811_maxp` / `invariants`) | Stub occupies `issue658_common` for the rest of the session → 811's `from issue658_common import summarize_answer_span` raises ImportError at collection (exit 2); `invariants` would AttributeError | `saved` = None → stub installed → exec → key deleted in `finally`. 811/invariants re-import the real module from disk via their own `sys.path.insert(scripts/)` |

In both orderings the module under test binds the stub — the load is order-invariant, which is exactly what these tests were written to pin (trivial stand-ins, none exercised).

**Explicitly NOT changed:** `scripts/issue658_judge_e0_batch.py` (must-ask, out of scope); the script's exec-time `sys.path.insert` of `src/` + `scripts/` and its real imports (`issue404_common`, `explore_persona_space.*`, `dotenv`) — pre-existing, benign (real modules under canonical names), unchanged by this fix; all 348 lines of existing test logic below line 77 (they consume `MOD` by direct attribute access only — `_run` at 154-156, `MOD.MAX_JUDGE_REQUESTS_PER_BATCH`, `MOD._parse_verdict` — no `sys.modules` lookups at test time).

## 11. Decision Rationale

**Choice 1 — restore-around-exec (save → install stub unconditionally → exec → restore prior in `finally`). CHOSEN.**
- What: `_load_module()` pins the stub into `sys.modules` only for the duration of `exec_module`, restoring the prior entry (or deleting the key) afterward; the early-return guard is deleted.
- Why: it is the smallest diff that satisfies BOTH requirements — deterministic stub binding (R1: unconditional install fixes the real-first guard bug) and zero leakage (R2: `finally` restore fixes the stub-first bug) — while keeping `MOD = _load_module()` at module scope so the other 270 lines of the file are untouched.
- Source: in-repo precedent `tests/test_issue475_vlm_config.py::_call_helper` (the identical save/try/finally/restore-or-delete idiom for the shared name `transformers`); pytest's documented `MonkeyPatch.context()` + `setitem(sys.modules, ...)` is the equivalent upstream idiom.
- Alternatives: below.

**Choice 2 — module-scoped fixture with teardown (task body's floated option). REJECTED.**
- What: install the stub in a `@pytest.fixture(scope="module")` and tear down after the module's tests.
- Why rejected: `MOD` is consumed at module scope — by `_run()` (line 154-156), by direct `MOD.*` asserts, and by the `FakeAnthropicBatch` wiring — so a fixture conversion forces threading a `mod` fixture through every test function: a much larger diff for the SAME end state, and it would leave the stub resident in `sys.modules` throughout this module's test execution (a wider leak window than restore-around-exec, which confines it to the synchronous exec call). No isolation benefit over Choice 1.

**Choice 3 — drop the stub and import the real `issue658_common` (the docstring premise is stale; the real module exists on main). REJECTED.**
- What: let the exec'd script import the real module via its own `sys.path.insert`.
- Why rejected: it changes WHAT the tests pin — the migration tests deliberately exercise `submit_and_collect`/`_collect_shard` against trivial stand-ins ("none are exercised by these tests"); binding real functions couples this file to unrelated `issue658_common` edits (real `_verdict_truthy`/`E0_COLUMNS` semantics drifting would perturb a file whose contract is the batch-client migration, not E0 semantics). It also does nothing for the alias-key hygiene. The stale docstring is fixed by editing the docstring, not by changing the test's isolation contract.

**Choice 4 — namespace the stub key away. REJECTED (infeasible).**
- What: register the stub under a non-shared key so it never occupies `issue658_common`.
- Why rejected: `scripts/issue658_judge_e0_batch.py:31` resolves `from issue658_common import ...` through exactly that `sys.modules` key; renaming the key requires rewriting the script under test — explicitly out of scope (must-ask).

**Choice 5 — try/finally vs `pytest.MonkeyPatch.context()`. Try/finally CHOSEN** for parity with the in-repo 475 precedent and explicitness at module-import time; the implementer MAY substitute `MonkeyPatch.context()` + `mp.setitem` (functionally identical — it restores a prior entry and deletes an added one) without a plan amendment.
