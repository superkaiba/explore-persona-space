**Phase A — export (content-preservation hard invariant; runs BEFORE any drop, for ALL three):**

```bash
RESCUE=~/.task-workflow/root-sync-rescue/$(date +%F)-stash-drain
mkdir -p "$RESCUE"
git stash list --format='%gd %H %gs' > "$RESCUE/stash-list-before.txt"
for k in 0 1 2; do
  sha=$(git rev-parse "stash@{$k}")
  git stash show -p "stash@{$k}"     > "$RESCUE/stash-$k-$sha.patch"
  git stash show --stat "stash@{$k}" > "$RESCUE/stash-$k-$sha.stat"
  # completeness guard: autostash-lineage stashes carry NO untracked third parent;
  # if one unexpectedly does, archive it too (never assume)
  if git rev-parse --verify -q "stash@{$k}^3" >/dev/null; then
    git archive "stash@{$k}^3" -o "$RESCUE/stash-$k-$sha-untracked.tar"

done
wc -l "$RESCUE"/*.patch   # each MUST be non-empty; stash-0 patch ≈ 5,401 insertions (incl. the 5,348-line issue_779 JSON)
```

**Phase B — per-file superseded verification (verdict ladder, applied to every file in every stash):**

## 11. Decision Rationale

`N/A — no model training` (no hyperparameters). Load-bearing non-training choices:

1. **`merge=union` for `.claude/agent-memory/**/*.md`.** *Why:* the 2026-07-02 root pull-rebase conflicted exactly on these append-dominant files; union self-resolves append-append. *Source:* #787 (the events/comments precedent + its scope caveat), the #896 incident evidence, and a live scratch-repo probe on the VM's git 2.34.1 confirming union is honored under local `git rebase` (ort) AND `git merge` for this pattern (§2). *Alternatives:* a custom merge driver (overkill; union suffices for line-append semantics); no guard (repeats the incident); unioning all of `.claude/**` (too broad — settings.json etc. are not line-append-safe).
2. **Rescue-export-before-drop.** *Why:* content-preservation is the task's hard invariant; a patch export makes every drop reversible. *Source:* #896 body ("preserve... BEFORE dropping"); the rescue-dir convention of `sync_repo_root.py` (#904, `~/.task-workflow/root-sync-rescue/`). *Alternatives:* drop-after-inspection-only (violates the invariant on human error); keeping the stashes forever (leaves the incident state ambiguous and re-triggers future confusion).
3. **`sync_repo_root.py` as the ONLY converge fallback.** *Why:* hand-rolled pull loops are the incident's root cause (index.lock races, husks, stranded autostashes). *Source:* #904 + CLAUDE.md § Concurrent repo-root committers (names it sanctioned). *Alternatives:* manual `pull --rebase=merges --autostash` (exactly what corrupted on 2026-07-02); scratch-worktree merge push (heavier; reserved by CLAUDE.md for multi-file merges under heavy fleet activity — not needed for a 0-0/marker-only state).
4. **Drop-by-message, not by index.** *Why:* `git stash drop` renumbers; a concurrent autostash can appear mid-procedure. *Source:* git stash reflog semantics (`stash@{n}` is positional) + the live-fleet constraint in the task body. *Alternatives:* drop 0,0,0 by index (breaks if a new stash lands mid-loop).
5. **Extend `tests/test_step10d_guard3.py` rather than a new test file.** *Why:* minimal scope; that file already loads `.gitattributes` and pins the #787 lines one-substring-per-test. *Source:* #787 precedent (verified at lines 74-93). *Alternatives:* no test (breaks the #787 symmetry — every union line there is pinned); a new file (duplicate fixture loading for one assert).
