```python
        "else",
        # Branch-switch-safe reuse (#1602; incident #779 att-20260722-155004):
        # a reused workspace disk can hold a single-branch clone of a
        # DIFFERENT branch. There, a bare `fetch origin <branch>` lands ONLY
        # in FETCH_HEAD (the clone's configured single-branch refspec covers
        # no other branch, so no local/remote-tracking ref is created); the
        # old by-name `checkout <branch>` died with `error: pathspec
        # '<branch>' did not match any file(s) known to git`, and
        # `reset --hard origin/<branch>` would die the same way. Three
        # steps: (1) fetch with an EXPLICIT forced destination refspec —
        # creates/updates refs/remotes/origin/<branch>, which the
        # push-verify leg's `rev-list origin/<branch>..HEAD` reads
        # post-workload (`+` tolerates a rebased/force-pushed tip on a
        # stale disk); (2) `reset --hard FETCH_HEAD` FIRST — a crashed
        # prior run can leave dirty tracked files that would abort a bare
        # `checkout -B` carry-over (sibling form: scripts/bootstrap_pod.sh
        # fetch + reset --hard FETCH_HEAD); (3) `checkout -B <branch>
        # FETCH_HEAD` — creates or resets the local branch (works from any
        # current branch or detached HEAD; conflict-free because the tree
        # already matches FETCH_HEAD after (2)).
        '  echo "[startup-script] reusing repo at $WORKLOAD_ROOT (HEAD was'
        ' $(git -C "$WORKLOAD_ROOT" rev-parse --short HEAD 2>/dev/null || echo unknown))"',
        '  git -C "$WORKLOAD_ROOT" fetch --depth 1 origin '
        + shlex.quote(f"+refs/heads/{repo_branch}:refs/remotes/origin/{repo_branch}"),
        '  git -C "$WORKLOAD_ROOT" reset --hard FETCH_HEAD',
        f'  git -C "$WORKLOAD_ROOT" checkout -B {shlex.quote(repo_branch)} FETCH_HEAD',
        "fi",
```

Notes on the form (each empirically verified at plan time on git 2.34.1 in scratch repos — see §11 Assumptions A1–A5):

- **Ordering is load-bearing:** `reset --hard FETCH_HEAD` runs BEFORE `checkout -B`. A reused disk from a crashed run can carry dirty tracked files; a bare `checkout -B` attempts a carry-over and aborts on conflict under `set -e`. After the reset the tree bit-matches FETCH_HEAD, so the `checkout -B` cannot conflict. (Chosen over `checkout -f -B`, whose untracked-files-in-the-way behavior is version-sensitive; `reset --hard` semantics are uniform.)
- **`shlex.quote` on the whole refspec token:** `+`, `:`, `/`, `-`, `.` are all in `shlex`'s safe set, so ordinary branch names render unquoted; a pathological name renders as one quoted shell word. The `checkout -B` line keeps the existing per-branch `shlex.quote` pattern.
- **The `echo` line** is a 1-line diagnosability aid (the next reused-disk incident's serial/workload log names the prior HEAD immediately); its command substitution is `|| echo unknown`-guarded so `set -e` cannot fire. It is an OPTIONAL element (droppable per §8) and is deliberately NOT pinned by the tests.
- **F-string hygiene:** the reset line and the fetch line's first fragment are plain strings (no placeholder), avoiding ruff F541; the fetch line uses explicit `+`-concatenation with `shlex.quote(f"...")`.

```python
def test_render_startup_script_repo_reuse_else_branch_branch_switch_safe() -> None:
    """#1602 (incident #779 att-20260722-155004): the repo-reuse else-branch
    must not require a local/remote-tracking ref to pre-exist — a reused
    workspace disk can hold a single-branch clone of a DIFFERENT branch,
    where the old by-name `checkout <branch>` died on `error: pathspec`.
    Pin the FETCH_HEAD-anchored form + the forced destination refspec the
    push-verify leg's `rev-list origin/<branch>..HEAD` depends on."""
    branch = "issue-779-n1m-readout"
    for spec in (
        _spec(),
        _spec(hydra_args=(), workload_cmd="bash scripts/issue658_dispatch.sh"),
    ):
        script = render_startup_script(
            spec=spec, config=_test_config(), attempt_id="att-fixed-001", repo_branch=branch
        )
        fetch = (
            f'git -C "$WORKLOAD_ROOT" fetch --depth 1 origin '
            f"+refs/heads/{branch}:refs/remotes/origin/{branch}"
        )
        reset = 'git -C "$WORKLOAD_ROOT" reset --hard FETCH_HEAD'
        checkout = f'git -C "$WORKLOAD_ROOT" checkout -B {branch} FETCH_HEAD'
        assert fetch in script
        assert reset in script
        assert checkout in script
        # ordering: fetch -> reset (tree forced clean) -> checkout -B
        assert script.index(fetch) < script.index(reset) < script.index(checkout)
        # the by-name branch switch + origin/<branch> reset are GONE
        # (`checkout {branch}` cannot false-match `checkout -B {branch}`)
        assert f"checkout {branch}" not in script
        assert f"reset --hard origin/{branch}" not in script
        # fresh-clone if-branch unchanged
        assert f"git clone --depth 1 --branch {branch} " in script
```

```python
def test_repo_reuse_else_branch_switches_branch_on_single_branch_clone(tmp_path) -> None:
    """Replay the RENDERED else-branch git lines against a real
    `--depth 1 --branch A` clone (the #779 reused-disk shape) targeting
    branch B, with a dirty tracked file. Asserts: rc 0 per line, local
    branch == B, HEAD == origin's B tip, clean tree, and
    refs/remotes/origin/B resolvable (the push-verify leg's read). A second
    same-branch replay (B -> B) pins the no-regression reuse path."""
    import os

    branch = "feature-b"
    script = render_startup_script(
        spec=_spec(), config=_test_config(), attempt_id="att-fixed-001", repo_branch=branch
    )
    lines = script.split("\n")
    start = lines.index("# === Repo clone / pull (idempotent) ===")
    else_i = lines.index("else", start)
    fi_i = lines.index("fi", else_i)
    git_cmds = [ln.strip() for ln in lines[else_i + 1 : fi_i] if ln.strip().startswith("git ")]
    assert len(git_cmds) == 3, git_cmds

    ident = ["-c", "user.email=eps@test", "-c", "user.name=eps"]
    origin = tmp_path / "origin"
    subprocess.run(["git", "init", "-q", "-b", "main", str(origin)], check=True)
    (origin / "f.txt").write_text("v1\n")
    subprocess.run(["git", "-C", str(origin), "add", "f.txt"], check=True)
    subprocess.run(["git", "-C", str(origin), *ident, "commit", "-qm", "c1"], check=True)
    subprocess.run(["git", "-C", str(origin), "checkout", "-qb", branch], check=True)
    (origin / "f.txt").write_text("v2\n")
    (origin / "g.txt").write_text("extra\n")
    subprocess.run(["git", "-C", str(origin), "add", "f.txt", "g.txt"], check=True)
    subprocess.run(["git", "-C", str(origin), *ident, "commit", "-qm", "c2"], check=True)
    subprocess.run(["git", "-C", str(origin), "checkout", "-q", "main"], check=True)
    tip = subprocess.run(
        ["git", "-C", str(origin), "rev-parse", branch],
        check=True, capture_output=True, text=True,
    ).stdout.strip()

    work = tmp_path / "work"
    subprocess.run(
        ["git", "clone", "-q", "--depth", "1", "--branch", "main",
         f"file://{origin}", str(work)],
        check=True,
    )
    (work / "f.txt").write_text("v1\ndirty-crashed-run-leftover\n")  # dirty tracked file

    env = {**os.environ, "WORKLOAD_ROOT": str(work)}
    for _phase in ("cross-branch", "same-branch-reuse"):
        for cmd in git_cmds:
            proc = subprocess.run(["bash", "-c", cmd], env=env, capture_output=True, text=True)
            assert proc.returncode == 0, f"{_phase}: {cmd}\n{proc.stderr}"

    head_branch = subprocess.run(
        ["git", "-C", str(work), "rev-parse", "--abbrev-ref", "HEAD"],
        check=True, capture_output=True, text=True,
    ).stdout.strip()
    assert head_branch == branch
    head = subprocess.run(
        ["git", "-C", str(work), "rev-parse", "HEAD"],
        check=True, capture_output=True, text=True,
    ).stdout.strip()
    assert head == tip
    porcelain = subprocess.run(
        ["git", "-C", str(work), "status", "--porcelain"],
        check=True, capture_output=True, text=True,
    ).stdout.strip()
    assert porcelain == ""
    tracking = subprocess.run(
        ["git", "-C", str(work), "rev-parse", f"refs/remotes/origin/{branch}"],
        check=True, capture_output=True, text=True,
    ).stdout.strip()
    assert tracking == tip
    unpushed = subprocess.run(
        ["git", "-C", str(work), "rev-list", "--count", f"origin/{branch}..HEAD"],
        check=True, capture_output=True, text=True,
    ).stdout.strip()
    assert unpushed == "0"  # the push-verify leg's rev-list read works
```

## 11. Decision Rationale

- **What:** else-branch git form = `fetch --depth 1 origin +refs/heads/<b>:refs/remotes/origin/<b>` → `reset --hard FETCH_HEAD` → `checkout -B <b> FETCH_HEAD`.
  **Why:** removes every dependence on pre-existing local/remote-tracking refs (the incident's failure), survives dirty trees and detached HEAD, lands the correct local branch NAME, and creates the `origin/<b>` tracking ref the post-workload push-verify leg (gcp.py:1562–1584) reads under `set -e`.
  **Source:** `scripts/bootstrap_pod.sh` L246–272 (the proven in-repo sibling: fetch + `reset --hard FETCH_HEAD`, with the why-by-name-fails comment); git documentation semantics for `git-fetch` refspecs (a bare `fetch origin <branch>` writes FETCH_HEAD and opportunistically updates a remote-tracking ref ONLY when the configured `remote.origin.fetch` refspec matches — false on a single-branch clone of another branch) and `git-checkout -B` (create-or-reset, allowed on the current branch, carry-over aborts on conflicting local changes — hence reset-first); incident evidence `#779` att-20260722-155004 (crash log at HF `issue779_partial/att-20260722-155004/workload.log`); **plus a plan-time empirical verification on this VM's git 2.34.1** (scratch two-branch origin + single-branch depth-1 clone): (i) incident reproduced byte-for-byte (`error: pathspec 'feature-b' did not match any file(s) known to git`; `origin/feature-b` unresolvable — so the old line 2833 would ALSO have failed), (ii) the chosen form exits 0 on a DIRTY tree and lands branch/tip/tracking-ref/clean-tree correctly, (iii) same-branch re-run exits 0, (iv) detached-HEAD re-run exits 0, (v) `rev-list --count origin/<b>..HEAD` → `0` (push-verify leg satisfied).
  **Alternatives rejected:** (a) `checkout -B <b> FETCH_HEAD` alone (the task body's minimal sketch) — leaves `origin/<b>` absent on a cross-branch reuse, so the run would die at the push-verify leg AFTER the workload (strictly worse than the boot crash); (b) bare `reset --hard FETCH_HEAD` only (bootstrap_pod.sh verbatim) — leaves the local branch NAME stale (confusing forensics, and any by-name branch consumer breaks) and still lacks the tracking ref; (c) `checkout -f -B` before reset — `-f`'s untracked-in-the-way behavior is git-version-sensitive; reset-first is uniform; (d) rewriting `remote.origin.fetch` to a wildcard refspec — heavier, converts the single-branch clone to all-branch fetching, more state mutation than needed.
- **What:** regenerate the byte-identity snapshot fixture rather than exempting the clone block from it.
  **Why/Source:** the fixture's own contract ("any render change must arrive with a deliberate, provenance-documented regeneration") + the #1547 regeneration precedent recorded in the fixture header; `.claude/rules/compute-backend-failover.md` § Snapshot pin.
- N/A — no model training
