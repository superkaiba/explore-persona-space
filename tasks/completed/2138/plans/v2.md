### 4.1 The fix — file-symlink arm of `_husk_unique_content`

Replace the file-symlink branch (:6739-6743) with the following (final code may differ cosmetically; semantics are binding — see the non-suppression clause in §4.2, pinned by T2b). `husk_resolved = husk.resolve()` is computed once at function top.

```python
if hp.is_symlink():
    if lp.is_symlink() and os.readlink(hp) == os.readlink(lp):
        continue  # existing rule: identical pointer on both sides
    # NEW (#2138): a FILE-symlink may still be safe when its resolved
    # content is carried by the live dir. Fail-safe gates first:
    # hp.is_file() follows the chain — False for dangling / non-regular
    # targets; the resolved path must stay INSIDE the husk dir.
    if hp.is_file():
        try:
            resolved = hp.resolve(strict=True)
        except (OSError, RuntimeError):
            # RuntimeError: py311 raises it for symlink LOOPS at
            # resolve(strict=True) (unified into OSError only in 3.13);
            # unreachable in practice — hp.is_file() screens loops
            # (ELOOP is in pathlib's ignored errnos) — belt-and-braces
            # against a resolve-time race. Either way: unique.
            resolved = None
        if resolved is not None and resolved.is_relative_to(husk_resolved):
            target_rel = resolved.relative_to(husk_resolved)
            # (b) pointer-carries-no-data: the target path also exists in
            # the live dir. This classifies the SYMLINK entry ONLY — the
            # walk still compares husk/<target_rel> itself against
            # live/<target_rel> independently (resolve() strips symlink
            # components, so every intermediate dir on the resolved path
            # is REAL and os.walk(followlinks=False) reaches the target
            # file); a diverged target is that entry's own unique verdict
            # and escalates the husk regardless of this route (T2b).
            if (live / target_rel).exists():
                continue
            # (a) same-rel-path content coverage: resolved bytes covered
            # by the live counterpart under the regular-file rules.
            if lp.is_file():
                sym_bytes = hp.read_bytes()          # follows the chain
                lp_bytes = lp.read_bytes()
                if lp_bytes.startswith(sym_bytes):
                    continue
                if hp.suffix == ".jsonl" and _jsonl_lines_subsequence(sym_bytes, lp_bytes):
                    continue
    unique.append(str(rel))
    continue
```

The docstring's per-entry rules (:6705-6721) are updated in the same edit: the single "symlink (dir OR file)" bullet splits into a dir-symlink bullet (unchanged rule, unchanged guarantee prose) and a file-symlink bullet stating routes (1) readlink-identical, (2) in-husk resolved target path exists in live, (3) in-husk resolved bytes covered at the same rel path — with dangling / escaping / non-regular targets explicitly unique.

### 4.2 Decision 1 — the safety predicate: implement the UNION (b) OR (a), ordered (b) first

- **(b) is the arm that fires on the motivating incident.** Traced against the real #2051 artifact (§2): the live `plans/plan.md` is a 5-byte regular file containing the target STRING `v1.md`, not the plan body — so predicate (a)'s resolved-bytes comparison (37,829-byte v1 body vs `b"v1.md"`) FAILS on the incident, and a plan implementing only (a) would not fire on its own motivating incident (the #1287 tracing rule's named design defect). (b) fires: the resolved target `plans/v1.md` exists in the live dir, and the husk's `plans/v1.md` is byte-identical to the live one, so the walk's independent comparison of that entry carries the whole coverage burden — the pointer itself holds no data. (b) equally covers the clarifier's later-version shape (live `plan.md` materialized from v2/v3 while the husk symlink targets v1: `plans/v1.md` persists in the live plans/ dir, so (b) fires and the husk's v1 copy is verified independently).
- **(b) classifies the SYMLINK entry only — it must NEVER suppress, skip, or mark-as-covered the target entry's own comparison.** This is a binding semantic, not a cosmetic one: an implementation that reads "(b) verified live carries `target_rel`" as license to short-circuit the walk's independent `husk/<target_rel>`-vs-`live/<target_rel>` check would produce a false-SAFE that reaps a husk whose target content live does NOT hold — the data-loss direction. The soundness of (b) rests entirely on that independent check running unconditionally. Arm T2b (§4.5) measures exactly this composition: (b) fires on the symlink while the husk's target file diverges from live's — the diverged target must appear in the unique list and the husk must escalate.
- **(a) is the same-rel-path content-coverage arm** — the natural extension of the regular-file rules to resolved symlink content, and the body's first named predicate. It covers the sibling shape where the live `plan.md` was materialized with the FULL plan content (a copy rather than a link-string materialization) and the live plans/ dir no longer carries the versioned target file. Honest scoping: at the whole-husk grain, (a)-fires-while-(b)-fails changes the final verdict only in narrow shapes (the husk's own target file must then be independently coverable — e.g. empty, or the symlink is the sole reference), because when live/<target_rel> is absent, the husk's non-empty target file is itself unique and escalates the husk regardless of the symlink's verdict. (a) is nonetheless kept: it is nearly free (runs only after (b) fails), strictly widens only fail-safe SAFE coverage, and honors the body's stated predicate.
- **Soundness of each arm (no data loss):** the reap requires the ENTIRE unique list to be empty. Under (b), the data behind the symlink is the husk's own target file, which the walk verifies independently (the non-suppression clause above; measured by T2b) — uncovered target ⇒ that entry is unique ⇒ escalate. Under (a), the resolved bytes are covered at the live counterpart's path by the same rules regular files use. Losing the pointer FACT itself (that the stale husk's plan.md pointed at v1) is acceptable by construction: the husk is a stale-status duplicate whose canonical copy is the live dir (recorded as a deliberate decision in §8).
- **Ordering:** (b) before (a) — one `exists()` stat vs two file reads; either order yields the same verdict.

### 4.3 Decision 2 — symlink-escape handling: escaping or dangling stays unique (fail-safe)

Established mechanically by three gates, in order: (1) `hp.is_file()` follows the chain and is False for a dangling symlink or a non-regular (fifo/socket/device/dir) final target — such entries fall straight to `unique.append`; (2) `hp.resolve(strict=True)` inside `try/except (OSError, RuntimeError)` (belt-and-braces against TOCTOU / permission errors, plus the py311 symlink-loop `RuntimeError` — unified into `OSError` only in 3.13 — a failed resolve is unique); (3) `resolved.is_relative_to(husk_resolved)` — a target resolving OUTSIDE the husk dir (absolute link, `../` traversal, or a chain exiting the husk) fails the gate and stays unique, EVEN when its bytes would match the live counterpart. Both new routes sit behind all three gates. The pre-existing readlink-equality route still runs FIRST and is untouched, so an escaping symlink whose live counterpart is a symlink with an identical readlink target remains safe under the OLD rule — no behavior is removed, only added. Multi-hop chains are handled by `resolve()`; because `resolve()` eliminates symlink components, an in-husk resolved target is reachable through REAL directories only, so `os.walk(followlinks=False)` provably visits it (the independence claim (b) relies on).

### 4.4 Decision 3 — dir-symlink strictness: unchanged, file-symlinks only

The `dirnames` loop (:6726-6734) is not touched. The docstring guarantee (:6705-6708 — the walk never traverses INTO a symlinked dir, so a dir-symlink can never reach `shutil.rmtree` unverified) stays intact: a dir-symlink's CONTENTS are never subset-verified by the walk, so any content-based leniency for dir-symlinks would be unsound without new traversal machinery; the readlink-equality rule remains their only safe route. The motivating incident and the only symlink convention in task dirs (`plans/plan.md`) are file-symlinks. A new test arm (T7) pins that the file-symlink leniency does NOT extend to dirnames.
