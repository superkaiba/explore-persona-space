## 1. Goal

Stop remote-payload text from mutating the repo-root guard's local cd-scope latch state. (Task #1443 Goal, verbatim — `kind: infra`, no `goal:` frontmatter; quoted from the body `## Goal` H2, re-read 2026-07-17 immediately before returning this plan.)

One paragraph: the guard's driver loop latches `scoped=1` when a clause "is a `cd` into a worktree or /tmp", but the two latch greps are unanchored, so ANY clause *containing* that text — including a quoted ssh remote-payload fragment produced by the quote-blind splitter, or an echo'd string — arms the latch and scopes the FOLLOWING `&&` clause as if the session had locally changed directory. A locally-gated destructive git clause can then be mis-classified as scoped/allowed. Fix: only a clause whose command word IS `cd` may arm the latch.

### 4.1 The code change (option (a): anchor both latch greps)

File: `scripts/guard_repo_root_branch.sh`, L1178-1179.

Before (verbatim):

```sh
  if echo "$clause" | grep -qE 'cd +[^;&|]*\.claude/worktrees/' \
     || echo "$clause" | grep -qE 'cd +/tmp/'; then
```

After (verbatim — the only executable change, two `^` characters):

```sh
  if echo "$clause" | grep -qE '^cd +[^;&|]*\.claude/worktrees/' \
     || echo "$clause" | grep -qE '^cd +/tmp/'; then
```

No `^[[:space:]]*` tolerance is needed: the awk splitter strips leading AND trailing `[ \t]` from every clause before emission (`split_and_label()`, L833: `gsub(/^[ \t]+|[ \t]+$/, "", line)`), a fact the driver already relies on in two comments (L1150, L1260); the comment-tail strip at L1171 removes only a trailing ` #...` span and can never prepend whitespace. So a post-split `... && cd /tmp/x` clause arrives as `cd /tmp/x` — clause-initial by construction (empirically confirmed, probe E in §12).

The `[^;&|]*` between `cd +` and `\.claude/worktrees/` is kept verbatim: it still absorbs quoted/variable path prefixes (`cd "$ROOT/.claude/worktrees/issue-9"` matched the anchored form in the plan-time fragment simulation).

## 10. Decision Rationale

N/A — no training hyperparameters

**Regex-form decision — option (a) anchor, over option (b) refuse-on-ssh/quoted-head:**

- **What:** add `^` to both latch greps (L1178-1179), making arming clause-initial-only.
- **Why (a):** (1) *Generality* — the hole is not ssh-specific: `echo 'cd /tmp/x' && git <gated>` was verified rc=0 pre-fix. Option (b) enumerates bad heads (ssh, quoted, echo, ...) and the correct general predicate is exactly "clause does not begin with `cd`" — which IS option (a) in one character per grep. (2) *Symmetry* — the file's other three `cd`/`WT=` matchers are already `^`-anchored (L1205, L1209, L1229); this closes the documented asymmetry rather than adding a fifth pattern style. (3) *Minimality / fail-closed-for-allows* — (a) can only REMOVE arming (removing an allow path is fail-closed); (b) adds a new head-classification predicate with its own quote-state edge cases (the complexity class that needed the 8-arm R1-R8 ladder in #1413). (4) *Verified no legit-form regression* — the splitter's leading-whitespace strip (L833) plus the wild-form grep (§7 risk 1) plus the fragment simulation confirm every real arming form remains clause-initial.
- **Source:** task #1443 body diff sketch (option a preferred); anchor-style precedent `scripts/guard_repo_root_branch.sh:1229` (#1058); splitter contract L833 (#804).
- **Alternatives considered:** option (b) (rejected above); `^[[:space:]]*cd +` (rejected — dead tolerance given L833; would falsely suggest clauses can carry leading whitespace); relaxing mask R6/R7 alongside (rejected — §7 risk 5, separate red-team surface).
