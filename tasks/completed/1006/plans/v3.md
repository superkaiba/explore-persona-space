## 4. Design

### 4.1 Parsing strategy (the crux) — hybrid (c), two tiers, one enumeration engine

Chosen over (a) a new registration DSL (would SKIP the motivating v4 fixture and ship a dead check until planner.md adoption — a follow-up outside this task) and (b) pure prose heuristics with FAIL semantics (unbounded false-positive risk). The hybrid canonizes the **v6 ⇔ declaration as the registered form** (it already exists in the corpus — no invented DSL) and adds a **bounded-idiom prose parser** whose FAIL authority is gated on a COMPLETE parse:

- **Tier 1 — explicit ⇔ declaration** (authoritative when present; takes precedence over tier 2): a non-fenced segment inside a trigger section matching `_C20_DECL_RE = r"(?i)\bdisjoint\b[^.\n]{0,60}\bexhaustive\b[^:\n]{0,20}:"` followed by ≥2 clauses `<label> ⇔ <predicate>` (clauses split on `;`, clause regex `([^;⇔\n]{1,80})\s*⇔\s*([^;\n]+)`). The plan itself claims a partition, so BOTH defect classes (co-fire AND gap) are FAIL-capable.
- **Tier 2 — lattice-shaped per-label prose** (the v4 shape): ≥2 top-level list items in a trigger section whose FIRST bold span matches the verdict-label anchor `_C20_LABEL_RE = r"(?i)^(?:h[-\s]?\w|intermediate|inconclusive|confirm|falsif|success|kill|pass\b|fail\b)"` AND whose text carries ≥1 CI idiom. Predicate segment per label: the sentence containing "confirmed if(f)" when present, else the first atom-bearing sentence after the bold label, truncated at the first `→` / `Consequence` token; **>1 atom-bearing sentence in one label ⇒ label unparsed** (v6's extra clarifying sentences never reach tier 2 — tier 1 wins there).
- **Trigger sections:** fence-stripped (`strip_fences`) sections whose heading matches `(?i)hypothes|success|kill|decision|verdict|gate` (superset of c13's gate sections + c14's hypothesis section, via the existing `_headings` machinery).

### 4.2 Atom grammar (shared by both tiers)

- **POINT atom:** `<quantity> (≥|>=|>) 0` → sign `pos`; `(≤|<=|<) 0` → `neg` (interior semantics; see §4.4).
- **CI atoms** — axis binding: the ≤40 chars before the `CI` token contain `paired` → **paired axis**, else **primary axis**:
  `includes 0 | contains 0 | straddles 0 | overlaps 0` → {straddle} · `excludes 0 | excluding 0 | clear of zero/0` → {below, above} · `excludes 0 on the positive side | strictly positive` → {above} · `…negative side | strictly negative` → {below} · `wholly below 0 | below zero` → {below} · `wholly (at/)above 0 | at or above 0` → {above}.
- **OTHERWISE atom** (tier-1 clauses and tier-2 labels): `\botherwise\b | \ball other\b | \bneither\b … fires? | \bno binary verdict\b` → complement label (fires iff no non-otherwise label fires; kills gap findings by construction).
- **Connectives:** `AND`, `OR` (incl. `, OR`), `with` (AND-equivalent — the v4 H-robust "Δ_pool < 0 with the … CI excluding 0" shape); parentheses stripped; precedence AND > OR; each label compiled to DNF over atoms.
- **Completeness gate (load-bearing):** a label/clause is `parsed` iff ≥1 atom matched AND every predicate-bearing token in its segment — every `\bCI\b`, every comparator char `[<>≤≥]`, every idiom keyword (`includ|exclud|straddl|wholly|strictly|clear of`), **and every NEGATOR token `\b(?:not|never|no|nor|unless|except|without|fails? to)\b` (Must-Fix, round-1 statistics ensemble: "the CI never includes 0" would otherwise match the positive `includes 0` atom exactly, with no residue, and become FAIL-capable with INVERTED polarity — negators are never inside an atom span, so their presence in a predicate segment forces `unparsed`)** — falls inside a recognized atom span. Any residue ⇒ `unparsed` ⇒ the whole lattice is not FAIL-capable (WARN; see §4.5).
- **Axis-identity fail-closed guards (Must-Fix, round-1 statistics ensemble):** (i) **quantity-identity** — each POINT atom records its normalized quantity symbol (the token(s) before the comparator, whitespace/markup-collapsed); if the lattice's labels reference >1 DISTINCT point quantity (e.g. `Δ_pool ≥ 0` in one label, `D > 0` in another), the single-`point`-axis algebra cannot represent them ⇒ whole lattice `unparsed` ⇒ WARN (never a silent collapse onto one axis); (ii) **post-CI paired binding** — `paired` within ≤40 chars BEFORE the `CI` token binds the paired axis (unchanged); `paired`/`paired diff`/`paired difference` appearing AFTER the CI token in the same clause (the "the CI of/on the paired difference includes 0" shape) is NOT silently bound to the primary axis — it marks the label `unparsed` ⇒ WARN. Fail closed on ambiguity, never guess an axis.
- **Connective fail-closed rule:** only the recognized connectives (`AND`, `OR`/`, OR`, `with`) join atoms; any OTHER joiner between two atoms in one segment (bare comma without `OR`, `if`/`when` chains, `and/or`) is residue ⇒ `unparsed` ⇒ WARN. No silent default connective (a default-OR could manufacture co-fires; a default-AND could hide them).
- **Precedence-phrase screen:** a trigger section carrying an explicit label-precedence declaration (`(?i)first matching|in (?:that |this )?order|takes precedence|evaluated in order|wins`) makes overlapping predicates coherent by evaluation order, which the cell algebra cannot see ⇒ whole lattice `unparsed` ⇒ WARN (round-1 Claude-statistics concern; same fail-closed family as the axis guards).
- **Tier-1 clause segmentation:** each ⇔ clause's predicate is truncated at the first sentence terminator (`.` + space/EOL) so a trailing recap sentence (v6's "Exactly one label fires for every (Δ_pool, CI, paired-CI) cell.") never enters the `otherwise` clause's predicate as residue. OTHERWISE-atom scanning is SEGMENT-scoped (post-truncation) in both tiers — v4's trailing "→ no binary verdict" (after the `→` truncation token) must never reclassify Intermediate as an otherwise-label (tests 3/4 pin this).
- **Quantifier screen (tier 2 only):** any harvested label whose segment matches `_C20_QUANT_RE = r"(?i)(?:at least\s+\d+|≥\s*\d+|>=\s*\d+)\s*(?:of|/)\s*\d+|\ball\s+\d+\b|\bfor (?:all|each)\b"` (deliberately NOT bare "every" — v6's declaration sentence says "for every … cell") ⇒ the k-of-n / per-family predicate class is out of the v1 cell algebra ⇒ SKIP with detail `quantified verdict predicates out of v1 scope`. This silences the #922-class plans (3/3 labels quantified) whose per-hypothesis coherence is c14's charter.

### 4.3 Cell enumeration (pseudocode)

```
axes  = union of atoms across parsed labels:
        point? · primary_ci? · paired_ci?           # only referenced axes enumerated
cells = product over:
        primary_ci ∈ {below, straddle, above}                       (if referenced)
        point      ∈ coherent(primary_ci) = below→{neg}, straddle→{neg,pos},
                     above→{pos}; {neg,pos} when primary_ci absent  (if referenced)
        paired_ci  ∈ {below, straddle, above}                       (if referenced)
for cell in cells:                                   # ≤ 12 cells at full 3 axes
    fired = [lab for lab in labels if not lab.otherwise and lab.dnf(cell)]
    if not fired and any otherwise-label: fired = [the otherwise label]
    if len(fired) >= 2: cofire_offenders.append((cell, fired))
    if len(fired) == 0: gap_offenders.append(cell)
```

The point-in-CI coherence constraint drops physically-unrealizable cells (a bootstrap CI contains its point estimate), preventing spurious gap findings.

### 4.4 Interior-cells-only convention (load-bearing)

Enumeration uses the 3-state CI axis {wholly below, straddles, wholly above} and 2-state point sign — NO zero-endpoint / zero-point boundary cells. Rationale: on boundary cells, "wholly at/above 0" (lb ≥ 0) vs "strictly positive" (lb > 0) diverge, and v6's PER-LABEL lines would co-fire on the measure-zero lb = 0 cell — a convention artifact, not a plan defect. On interior cells the two idiom families coincide and every FAIL finding is a fat open region. Boundary semantics stay with the Statistics critic (c13's "form-only, necessary-condition" charter). Verified by hand: under this convention the v4 labels FAIL (co-fire cell {point pos, primary straddle, paired straddle}; gap cell {point neg, primary straddle, paired below}) and the v6 ⇔ clauses PASS (below vs above∪(straddle∧paired-above) disjoint; intermediate ⇔ otherwise ⇒ exhaustive).

## 11. Decision Rationale

- **Hybrid strategy (c), v6 ⇔ form as the registered tier.** Why: (a) alone ships a dead check (0 corpus adoption of a new DSL; v4 would SKIP); (b) alone cannot FAIL safely. Source: `scripts/verify_plan.py` c13 (registered-form precedent) + corpus grep (only 2 files carry the ⇔ declaration — both #923 v6).
- **Complete-parse-required-for-FAIL.** Why: a partial parse can invert predicate semantics in a pure-regex verifier. Source: c14 docstring ("a heuristic text check must not hard-block"); c13 FAILs only on fully-parsed registered gates.
- **Interior-cells-only 3-state axes + point-in-CI coherence.** Why: boundary cells manufacture measure-zero co-fires (v6 per-label lines at lb = 0) and unrealizable-cell gaps. Source: #923 `plans/v6.md` §3 hand-analysis (this plan §4.4); c13's necessary-condition charter.
- **Tier-2 co-fire → FAIL, tier-2 gap → WARN, tier-1 both → FAIL.** Why: co-fire precision needs only the labels in hand; gap precision depends on harvest recall; tier-1 gap falsifies the plan's own "exhaustive" claim. Source: corpus probe §2 (#405/#496 shapes) + task #1006 candidate diff sketch ("FAIL when any cell fires 0 or ≥2 labels" — scoped by this precision argument).
