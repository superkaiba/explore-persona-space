# Plan v3 — #2610: poll_pipeline.py terminal-success detection for single-phase dispatcher invocations

(v2 after single-critic REVISE: fixed the inverted `-nt` fail-safe — bash's `-nt` is
TRUE when the second operand is missing, so the probe now requires an explicit
`-f <pid_file>` conjunct; allowlist anchored with `re.fullmatch`; docs item states the
bash `-nt` semantics; test matrix gains the pid-file-absent case. v3: added the
verifier-requested fail-loud pin line, no substantive change.)

## Requirement

`scripts/poll_pipeline.py` has no reachable success verdict for a cleanly-completed
SINGLE-PHASE dispatcher invocation: the dispatcher deliberately emits no terminal
`[phase=done]` line (that token is reserved for end-of-RUN), so on completion the pid
probes all go dead and the poller reports `pid-stale-workload-live` (the #2265 evidence
veto, firing correctly) and then decays to `dead` — a false-failure verdict on a
successful phase. Observed: #2546 arm 3 `p5_fits`, 43/43 ok, done-file written, tick at
00:14:33Z returned `pid-stale-workload-live` / `stall_reason=pid_dead_evidence:log_fresh`.

Fix: give the poller a POSITIVE, dispatcher-written, launch-scoped success signal and a
distinct terminal verdict for it, without touching the #545/#597/#612 false-`done`
hardening or the #2265 evidence veto.

## Chosen design (task-body candidate (a) + (c) hybrid, declared-path variant)

**Opt-in `done_file=` declaration in the launch marker + pod-clock freshness probe +
new `phase-done` verdict.**

1. **Launch-contract extension (opt-in).** A launcher dispatching a phase-scoped
   workload MAY carry `done_file=<absolute pod path>` in its `epm:run-launched` note
   (alongside the existing `pod=` / `pid=` / `log=` tokens). The declared file is the
   success sentinel the workload writes ONLY on clean completion (the #2546 dispatcher
   already writes `$OUT_ROOT/done/$(phase_key).done` via `mark_phase`).
2. **Poller marker parse.** New helper `_marker_done_file(issue, pod) -> str | None`
   mirroring `_marker_launch_fields`: extract the `done_file=` token from the latest
   pod-scoped `epm:run-launched` note. Shell-safety validation: accept only
   `re.fullmatch(r"/[A-Za-z0-9._/-]+", path)` (the path is interpolated into the SSH
   probe; `fullmatch`, not `$`-anchored `search` — `$` tolerates a trailing newline);
   reject + one WARN otherwise (declaration ignored, legacy behavior).
3. **Probe leg (pod-clock, skew-free, both-files-exist conjunct).** When a done_file is
   declared, append to the SSH probe:
   `if [ -f <done_file> ] && [ -f <pid_file> ] && [ <done_file> -nt <pid_file> ]; then echo DONE_FILE_FRESH=1; else echo DONE_FILE_FRESH=0; fi`
   The `-nt` compare against the pid file — rewritten at EVERY (re)launch per the #813
   pid-file launch contract — is a same-clock stale-artifact guard: a done file left by
   a PRIOR run of the same phase reads FRESH=0 (the #779 "never key done on bare file
   existence" rule). The explicit `[ -f <pid_file> ]` conjunct is LOAD-BEARING: bash's
   `-nt` returns TRUE when file1 exists and file2 does NOT (verified against the probe's
   bash execution context — the existing probe block uses `shopt`,
   poll_pipeline.py:2166), so without the conjunct a crashed launch whose pid file was
   never written (or was wiped) plus a surviving PRIOR-run done file would read
   FRESH=1 — a false terminal-success on a crashed run, the exact inverse of this
   task's defect. With the conjunct: missing pid file → FRESH=0 → fall-through to the
   veto/dead path (fail-safe). The ssh-failure fallback probe dict emits
   `DONE_FILE_FRESH=0` (fail-safe, like every other key).
4. **Decision core.** In the `not pid_alive` arm of `poll_once`, BEFORE the #2265
   veto: declared done_file AND `DONE_FILE_FRESH=1` → `status = STATUS_PHASE_DONE`
   (`"phase-done"`), `stall_reason = None`. Else fall through to `_pid_dead_verdict`
   exactly as today. Implemented by extending `_pid_dead_verdict`'s signature (it is
   already the extracted pid-dead arbitration arm; `poll_once` sits at the C901 cap).
5. **Verdict semantics.** `phase-done` is TERMINAL-SUCCESS FOR THIS WORKLOAD, distinct
   from run-level `done`: it never triggers Step-8 pod-termination semantics, never
   posts a `-> done` milestone transition (current_phase stays the real phase, e.g.
   `p5_fits`), and tells the driving orchestrator "the phase you launched completed;
   dispatch the next one." Add `STATUS_PHASE_DONE` module constant; update the
   PollResult docstring enum and the module docstring.

### Branch-order invariants (all preserved; verified against poll_pipeline.py:6003-6020)

- `gate` still wins over everything (earlier branch, untouched).
- A corroborated `[phase=done]` parse still yields run-level `done` (earlier branch,
  untouched) — run-done outranks phase-done.
- `phase-done` requires ALL pid probes dead (mirrors #545's "a normal completion exits
  within seconds") — a lingering-alive dispatcher with a done file present falls to the
  normal liveness arms.
- The #2265 veto is UNCHANGED for every launch without a declared+fresh done file:
  legacy launches behave byte-identically.
- `recommend_next_interval` already treats any `status != "running"` as act-now; no
  change (pin with a test).

### Why not the other candidates

- **(a) pure — glob `$OUT_ROOT/done/`:** the out-root is not poller-discoverable
  (observed: `output_fresh` never fired for #2546 despite fresh artifacts — the
  out-root sits outside the issue-keyed roots), generic glob-widening is #2605's fix
  surface, and a glob cannot bind filename↔phase↔launch. The declared path sidesteps
  discovery entirely.
- **(b) — single-phase invocations emit `[phase=done]`:** pollutes the shared
  multi-invocation log stream with run-level done tokens; the #983 post-done advisory
  fires on every subsequent phase; stale done lines in an appended log recreate exactly
  the #597/#612 false-`done` class the docstring hardened against.
- **(c) pure — `done-unconfirmed` non-decay:** still needs the same done-file
  visibility, and leaves the success path without a positive verdict; subsumed by the
  declared-path mechanism at the same cost.
- **rc-sentinel in the pid-file contract:** changes every launcher fleet-wide; far
  larger blast radius for the same information.

## Tests (acceptance criteria)

New `tests/test_poll_pipeline_phase_done.py`, driving the pure decision helpers
(`_pid_dead_verdict`, `_marker_done_file`, probe-stdout parse) the way
`test_poll_pipeline_dead_veto.py` does:

1. declared + FRESH=1 + all pid probes dead → `phase-done`, stall_reason None.
2. declared + present-but-stale (FRESH=0) + pid dead + fresh log →
   `pid-stale-workload-live` (veto unchanged; the #779 stale-artifact guard works).
3. declared + absent + pid dead + fresh log → `pid-stale-workload-live`; with all
   evidence stale → `dead` (crash path byte-identical).
4. NOT declared → byte-identical legacy behavior (all existing dead-veto tests pass
   unmodified — regression gate).
5. pid ALIVE + FRESH=1 → not `phase-done` (falls to normal liveness arms).
6. `_marker_done_file`: extracts the token; rejects a metachar-bearing path AND a
   trailing-newline path (ignored + WARN); missing token → None.
7. Corroborated `[phase=done]` + declared FRESH=1 → `done` (run-done outranks).
8. ssh-failure fallback → FRESH=0 → no `phase-done`.
9. `recommend_next_interval("phase-done", ...)` → act-now interval (status != running).
10. No `-> done` milestone transition posts on a `phase-done` tick.
11. **pid-file-ABSENT guard (the v2 Must-Fix case):** declared + done file PRESENT +
    pid FILE absent + all pid probes dead → NOT `phase-done` (FRESH=0; falls to the
    veto/dead path). Probe-string assertion: the composed probe contains
    `-f <pid_file>` as a conjunct of the done-file leg (mechanical pin so a refactor
    cannot silently drop it).

## Success criteria

- The observed #2546 shape, simulated (declared done_file, file written by the phase,
  pid dead, log fresh) → `phase-done` on the first post-completion tick; never
  `pid-stale-workload-live`, never decays to `dead`.
- Every existing `tests/test_poll_pipeline_*.py` passes unmodified.
- Undeclared launches: zero behavior change (verdict-path diff empty).
- A crashed launch with a surviving prior-run done file and a missing/stale pid file
  NEVER reads `phase-done` (test 11 + test 2).
