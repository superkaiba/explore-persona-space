  smoke-FENCED branch`, currently L324). Draft text (implementer refines wording, keeps all
  acceptance-criterion-2 elements):

  > - **An import statement inside a function binds its bare name FUNCTION-WIDE at compile time —
  > an in-function `--import-check` block importing a bare name that matches a module-level
  > symbol SHADOWS that symbol for the whole function, so the later production call raises
  > `UnboundLocalError` while the import-check smoke passes BY CONSTRUCTION.** Python's compiler
  > marks any name bound anywhere in a function (including by `import X` / `from m import X`,
  > absent a `global`/`nonlocal` declaration) as a local for the function's ENTIRE body — so a
  > `main()` whose `--import-check` branch does `from ... import capture` turns every later
  > `capture(...)` call into a read of an unbound local, even on the path where the branch never
  > executed. Both standard smokes false-pass: the import-check smoke binds the name before
  > reading it (passes by construction), and a direct-call smoke of the target function never
  > executes the caller's poisoned line. RULE: hoist the import-check body into its own
  > module-level function (e.g. `_import_check()` — it reads no enclosing-function state), or
  > alias every imported name (`from m import capture as _chk_capture`); pin with a compile-time
  > assert `assert 'capture' not in main.__code__.co_varnames` (no GPU — an import-bound name
  > appears in `co_varnames` even when its branch never executes); a smoke of a multi-phase
  > `main()` must execute the REAL phase-entry lines (with phase boundaries faked), never call
  > the phase functions directly. Diagnostic signature: an `UnboundLocalError` naming `'<name>'`
  > at a call to a module-level def, immediately after a completed earlier phase (3.11+:
  > `cannot access local variable '<name>' where it is not associated with a value` — the
  > project runtime; ≤3.10: `local variable '<name>' referenced before assignment`). (Incident
  > #1739 wcrung `att-20260731-013823`: `UnboundLocalError` `'capture'` at
  > `issue1739_wcrung_pod.py:552` at capture-phase entry AFTER a completed+persisted generation
  > phase — one A100 launch cycle; fix `5b78ff42d6` hoisted the block to `_import_check()` and
  > swept 7 sibling entrypoints, zero further shadows; the pin test
  > `test_main_phase2_reaches_module_level_capture` failed pre-fix with the production error.)
  > Sibling entries: the #606 lazy-import AST sweep and #823 script-mode `sys.path` cover
  > imports that are MISSING or FAIL; this entry covers an import that SUCCEEDS and still
