implementer build is dispatched as sequential micro-scoped units BY DEFAULT,

**Acceptance criteria:**

1. `.claude/skills/issue/SKILL.md` Step 4b carries a new bold paragraph
   ("**Pre-split multi-deliverable builds at dispatch (#1810; precedents
   #1090/#1775).**") inserted immediately BEFORE the
   `Brief passed to the implementer:` line (~L2193), keying the split
   proactively off the approved plan's declared deliverable count.
2. The clause defines, explicitly:
   - **Count basis:** distinct planned CODE deliverables — new or
     substantially-rewritten `scripts/` / `src/` / `tests/` files the plan's
     "File paths + concrete diffs" section names (doc-only files excluded).
   - **Threshold:** more than 4 (i.e. ≥5) code deliverables ⇒ pre-split.
     Grounding: #1775's 7-deliverable build died at the context ceiling after
     139 tool calls / ~63 min (~20 tool calls per code deliverable ⇒ the risk
     zone starts ~5–6); ≥5 buys margin below the observed death at 7. A
     lower-count build with a comparably large projected build volume (very
     large per-file scope, heavy smoke phases) MAY pre-split by judgment.
   - **Unit shape:** sequential micro-scoped units of ≤3 deliverables each,
     fresh context per unit, each unit's brief scoped to its own
     self-contained subset (the #1090 rounds-A/B shape).
   - **Marker contract:** intermediate units commit their work by explicit
     path and RETURN a commit manifest with NO implementation marker; only
     the FINAL unit runs the full per-phase smoke (`## Smoke run` H2 covering
     every phase, per the existing brief contract) and posts
     `epm:experiment-implementation` / `epm:results` at max+1.
   - **Round semantics:** all units run sequentially within ONE review round
     (no round-counter increment between units); the Step 5 code-review
     ensemble reviews the whole round diff once, after the final unit.
   - **Model rule:** default session model per unit — never a smaller-model
     pin (the Step 5b thrash-inverse rule, #1090 forensics).
3. The clause cites #1090 (sequential rounds A/B) + #1775 (the founding
   incident: ~15 min triage + respawn overhead for a split available at
   dispatch time from the plan's own deliverable count) and cross-references
   the Step 5b recipe as its recovery-side sibling (which stays unchanged as
   the backstop for unforeseen thrash deaths).
4. Follow-up-round dispatches inherit the clause via the existing Step 9b
   reference ("The round's implementer brief follows the Step 4b brief
   contract") — no separate edit needed; the clause states this in one line.
5. Gates: `workflow_lint.py` no-flags + parity legs pass on the payload;
   the new text contains NO all-caps `EXIT` token (the
   `tests/test_step_completed_resume.py` action-region scanner) and no
   `AskUserQuestion` mention (`--check-asks`); Step 9c mapped tests pass.
