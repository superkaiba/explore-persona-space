## Requirement + acceptance criteria

**Requirement.** `task_workflow.set_body`'s Goal-H2 drop guard (`GoalH2DropError`,
incident #1112) currently fires on every `workflow: v2` report-body write, because
the report-v1 template deliberately has no `## Goal` section — forcing
`--allow-goal-drop` on the happy path (#2162, the first v2 report post). A guard
that must be overridden on every legitimate use trains reflexive overriding and
stops protecting the accident class it was built for. Add a narrow auto-exemption
for v2 report bodies; leave the v4 clean-result path byte-identical in behavior.

**Acceptance criteria:**

1. Writing a body that (a) belongs to a task whose frontmatter is
   `workflow: v2` AND (b) carries the `<!-- report-v1 -->` sentinel as the first
   non-blank line after the H1 title (the exact `verify_report.py` positional
   semantics, including `find_h1`'s line-strip behavior) succeeds WITHOUT
   `allow_goal_drop`, even when the prior `kind: experiment` body had a
   `## Goal` H2 and the new body lacks one. With `snapshot_original=True`, the
   exempted write still snapshots the prior Goal-bearing body to
   `original-body.md` (the #2162 "nothing was lost" property).
2. Every other currently-refused shape stays refused, raising `GoalH2DropError`
   before any side effect: a v2 task posting a NON-sentinel body that drops
   `## Goal`; a v1 / workflow-absent task posting a sentinel-bearing body (both
   discriminator halves are required); a body that merely QUOTES the sentinel
   mid-prose rather than carrying it positionally; and an incoming body that
   smuggles `workflow: v2` in its OWN leading frontmatter while the on-disk
   task frontmatter is not v2 (`workflow` is not in
   `_SET_BODY_ROUNDTRIP_KEYS`, so the discriminator reads only the canonical
   on-disk frontmatter — pinned by a test).
3. All existing guard tests pass unchanged
   (`tests/test_task_workflow.py:680-774`,
   `tests/test_task_cli_set_body_assertions.py:205-232`) — the v4 path is
   byte-identical in behavior.
4. The sentinel string in `task_workflow.py` (the EXISTING
   `REPORT_V1_SENTINEL`, line 1043) is pinned equal to
   `scripts/verify_report.py::REPORT_SENTINEL` by a test, so the two cannot
   silently drift.

   Fail-loud pin: tests/test_task_workflow.py::test_set_body_goal_guard_still_fires_on_v2_non_report_body — pytest.raises(GoalH2DropError) negative control; every refusal path raises, never a silent write.
5. `.claude/skills/issue-v2/SKILL.md` step 7f no longer instructs
   `--allow-goal-drop` on the canonical report write; the `--allow-goal-drop`
   CLI help text + both docstrings describe the auto-exemption.

## Method delta (design decisions, resolved per the task body's scope notes)

- **Discriminator = BOTH `workflow: v2` frontmatter AND the positional
  report-v1 sentinel in the NEW body.** The task body says "Prefer the
  sentinel, or require both." Requiring both is chosen: the sentinel describes
  the body being written (the precise signal), while the `workflow` gate keeps
  every non-v2 task's behavior untouched by construction — a report-shaped body
  on a v1 task is itself a routing error and SHOULD stay guarded. The
  `workflow` field is read from the task's canonical on-disk frontmatter
  (`fm`), already loaded at the guard site (`task_workflow.py:6234`); tasks
  predating the field return `None` from `fm.get("workflow")` and keep the
  guard. Incoming-body frontmatter cannot influence it (`workflow` is not a
  `_SET_BODY_ROUNDTRIP_KEYS` member).
- **Positional detection via a NEW helper `_is_report_v1_body()`; the module's
  EXISTING containment predicate `is_report_body()` (:1046,
  `REPORT_V1_SENTINEL in body`) is deliberately NOT used for the guard.**
  `is_report_body` serves clean-result-form acceptance (`set_clean_result`,
  dashboard rendering — its docstring's consumer list), where containment is
  the right bar. For a guard EXEMPTION, containment is too loose: a body
  quoting the sentinel mid-prose (acceptance-criterion-2 case; #2197's own task
  body does exactly this) would wrongly take the exemption. The new helper
  mirrors `verify_report.py`'s positional check (`find_h1` at :349-355 +
  first-non-blank-after-H1 at :405-422), including `find_h1`'s STRIP semantics
  (`s = line.strip(); s.startswith("# ") and not s.startswith("## ")`), so
  acceptance criterion 1's "exact verify_report.py positional semantics" is
  literally true. No H1 ⇒ not a report body ⇒ no exemption.
- **Text-shape equivalence (why the guard-side check sees what verify_report
  sees):** `verify_report.py` runs its H1/sentinel check on the
  frontmatter-STRIPPED raw body (`split_frontmatter` :1508→:1519), and the
  guard runs on `_strip_leading_frontmatter_blocks(new_body)` — the same
  shape. verify_report's fence-blanking pass (:327-346) applies only to
  section-parsing/lexicon checks, not the H1/sentinel check, so there is no
  divergence there either.
- **Inverse guard NOT added.** The task body flags it as a judgement call;
  `scripts/verify_report.py` already gates section completeness at the report
  gate (`REQUIRED_SECTIONS`, checked at generation AND promote), and `set_body`
  is a drop-guard, not a shape validator. Duplicating the check would create a
  second drift surface for zero marginal protection.
- **Exemption follows the existing `is_paper_task` precedent shape**
  (`task_workflow.py:6253`) — one additional conjunct in the same guard
  condition, no restructuring.

   - Add the positional helper next to `is_report_body` (~:1056), so the two
     report-body predicates sit together and their docstrings cross-reference
     each other's distinct purposes:

     ```python
     def _is_report_v1_body(text: str) -> bool:
         """True iff the first non-blank line after the first H1 is the
         report-v1 sentinel — the positional semantics of
         scripts/verify_report.py (find_h1 + first-non-blank-after-H1).
         Stricter than :func:`is_report_body` (containment), which serves
         clean-result-form acceptance: a mid-prose sentinel quotation must
         NOT satisfy a guard exemption (#2197).
         """
         lines = text.splitlines()
         h1_idx = None
         for i, line in enumerate(lines):
             s = line.strip()
             if s.startswith("# ") and not s.startswith("## "):
                 h1_idx = i
                 break
         if h1_idx is None:
             return False
         for later in lines[h1_idx + 1:]:
             if later.strip():
                 return later.strip() == REPORT_V1_SENTINEL
         return False
     ```
   - Extend the guard condition (~:6250) with one conjunct, mirroring the
     paper-task skip:

