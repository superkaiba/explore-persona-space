# Plan v1 — task #1799: harden GCE crash-persist against dead-stdout death (rc=120 under kernel OOM)

## 0. TL;DR

On both #1739 kernel-OOM crashes the `_eps_persist_diagnostics` safety net exited rc=120 and delivered ZERO diagnostics to `issue1739_partial/`, while on the same task's ordinary rc=7 crash (att-20260729-004944) the identical persist delivered a full bundle. Root cause (structurally verified from the rendered script; to be confirmed by a fails-pre-fix repro): when the startup-script's stdout reader — the `google_metadata_script_runner` — is dead at trap time (the kernel OOM tore down `google-startup-scripts.service`; systemd recorded `Failed with result 'oom-kill'`, and `DefaultOOMPolicy=stop` kills the unit's remaining processes), the crash-persist STREAMER pipeline subshell dies of SIGPIPE at its first `printf >&3` (pipeline subshells RESET the top-level `trap ':' PIPE` handler (#607) to default — bash trap-reset-in-subshell semantics), and the persist python's UNGUARDED `print(msg, flush=True)` in `_say` (gcp.py:1826) then raises BrokenPipeError into a dead-stderr pipe before the FIRST upload — the canonical CPython finalize-flush-failure **exit 120**. The trap tail survives (rc file + `eps/persist=failed_rc120` breadcrumb both landed on #1739), so the whole observed signature is reproduced: breadcrumb present, HF prefix empty, rc=120.

Fix (defense-in-depth, smallest sufficient set):
- **(A) Streamer survival:** re-install `trap ':' PIPE` inside the streamer pipeline subshell so a dead fd 3 degrades to guarded write errors (already `2>/dev/null || true`-guarded) instead of streamer death — the persist python's stdout pipe then stays alive for the whole persist.
- **(B) Persist-python stdout immunity:** guard `_say`'s stdout write in try/except OSError (transcript file append UNCHANGED — it is the durable audit); end both deliberate exits (success, verify-gate exit 3) with explicit guarded flushes + `os._exit(rc)` so a finalize-flush failure can never rewrite a completed persist's rc.
- **(C) Taxonomy:** map `(120)` in the `_prc` case table to `failed_stream_flush` and document the value in the `eps/persist` decision table (`.claude/rules/compute-backend-failover.md` Part A item 8). Post-A/B this value should be unreachable — if it ever fires again the guards regressed.
- **(D) Same-shape audit of the done-persist heredoc** (`EPS_DONE_PERSIST_PY`, `_eps_persist_done_sentinels`): apply the same stdout-write guard + `os._exit` shape if it shares the unguarded-print pattern (it runs in the success tail where the runner is normally alive, but the guard is cheap and the exposure identical in kind).

## 2. Root-cause evidence (verified at plan time)

- **HF listing (fresh, 2026-07-29):** `issue1739_partial/` contains ONLY `att-20260729-004944/` (39 entries, full bundle incl. `crash_persist_transcript.log`) — the rc=7 pilot-gate abort with a LIVE runner. Neither OOM attempt (`att-20260729-000125`, `att-20260729-032826-hallu`) has any prefix. The persist works on ordinary crashes and failed ONLY under the OOM condition.
- **#1739 markers:** `epm:run-launched v2` (00:55Z) records `eps/persist=failed_rc120, nothing under issue1739_partial/` + `google-startup-scripts.service Failed result oom-kill`; v4 (04:32Z) records `crash-persist failed rc=120 again — OOM-pressure exit`. Both breadcrumbs LANDED → the trap bash survived to the rc-file readback + curl; only the persist python died.
- **Code structure:** `exec 3>&1` (gcp.py:1644) makes fd 3 the runner's pipe; the streamer writes `{ printf ... >&3; } 2>/dev/null || true` (L2338) inside a PIPELINE SUBSHELL, where the top-level `trap ':' PIPE` (#607) is reset to default — an EPIPE'd printf therefore SIGPIPE-kills the streamer, not just the one write; `_say` prints unguarded with `flush=True` (L1826) — dead pipe ⇒ BrokenPipeError at the first pre-upload `_say` ⇒ CPython exit 120 (unhandled exception + dead-stderr finalize flush).
- **rc=120 semantics:** CPython exits 120 when `Py_FinalizeEx` fails (std-stream flush failure at interpreter exit) — the canonical `python -c 'print("x")' | true` signature. The task body's "120s bound" hypothesis is refuted: the 120s `timeout` is the DONE-persist's (L2525), a different path; the crash persist's bound is 300s and expiry yields rc 124, already mapped.

**Assumptions (labeled):**
- `A1 (high, structural):` the dead-stdout → exit-120 → zero-uploads chain — verified by code reading; the repro test converts this to executed evidence.
- `A2 (medium, inference):` WHY the runner was dead = systemd OOMPolicy=stop unit teardown after the kernel OOM. The systemd `oom-kill` unit record supports it; boot-disk forensics are gone (diag instances deleted), so this ordering is not directly provable. THE FIX DOES NOT DEPEND ON A2 — any runner-death cause (incl. the #491 bufio-overflow class) produces the same dead pipe, and A/B harden against all of them.
- `A3 (medium):` the trap bash itself survives long enough to finish the persist under systemd stop escalation (observed: it survived to the breadcrumb on both crashes; systemd's default TimeoutStopSec=90s bounds the window — the persist's high-value FIRST bundle lands in seconds, and a SIGKILL mid-later-bundle still beats today's zero-delivery).

## 4. Design — file paths + concrete diffs

1. **(A) Streamer trap** (L2336): `'  ) 2>&1 | { trap \':\' PIPE; _n=0; while IFS= read -r _l ...'` — one token added inside the `{ }` group (the group body executes in the pipeline subshell, so the trap re-arms there; a handler (not SIG_IGN) keeps children — incl. nothing here — at their own defaults, mirroring the #607 top-level choice).
2. **(B) `_say` guard** (L1821-1831): wrap the `print(msg, flush=True)` in `try/except OSError: pass` and latch a module-level `_STDOUT_DEAD = {"v": False}` flag to skip further prints once dead (avoids one exception per line for the rest of the persist); transcript append unchanged. At the two deliberate exit sites (`sys.exit(3)` at the verify gate, and the fall-off-end success), replace with: guarded `sys.stdout.flush()` / `sys.stderr.flush()` in try/except, then `os._exit(3)` / `os._exit(0)`. (Transcript writes are per-call `with open(...aappend)` — closed each call — so `os._exit` loses nothing; stdout lines are flush=True per print.)
3. **(C) Case table** (L2348-2353): add `'    (120) _eps_persist_status "failed_stream_flush" ;;'` before the catch-all; extend the taxonomy comment at L2311 (`120 = std-stream flush failure at interpreter exit — dead stdout/fd-3 pipe; should be unreachable post-#1799`).
