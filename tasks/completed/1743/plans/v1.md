## Goal / requirement

Make the Claude `code-reviewer`'s (and the same-class `reconciler` marker-mode) verdict post durable and self-verified: switch the prescribed post recipe from the argv-prose channel (`--note "$(cat <file>)"`) to the `--file` channel, and add a mandatory read-back-verify duty before the agent may claim "posted".

**Driving incident** (origin_prompt): #1723 code-review round 1 — the reviewer's return claimed the `epm:code-review` marker was posted; neither the marker nor the durable `/tmp/code-review-1723.md` file existed. The orchestrator burned ~9 min + a duplicate reviewer spawn (Step 5b durable-verdict-first re-spawn).

**Why the workflow gap is real** (verified at clarify time, 2026-07-28):
- `.claude/agents/code-reviewer.md:37` prescribes `post-marker <N> epm:code-review --version <revision_round> --note "$(cat /tmp/code-review-<N>.md)"` — the argv-prose channel CLAUDE.md #1722 already deprecates for `$( )`-bearing / git-verb-bearing bodies (a review body quotes diff text and git verbs; the repo-root guard's prose-matching hook scans `--note` argv, and shell re-parsing of the inline `$(cat ...)` is quoting-fragile).
- `.claude/agents/reconciler.md:379` carries the identical `--note "$(cat marker.md)"` class (marker-mode post).
- Neither file carries any read-back duty, so "posted" can be claimed unverified.
- `task.py post-marker --file FILE` and `task.py latest-marker --prefix` both exist (CLI help verified). The Codex twins are unaffected (the ORCHESTRATOR posts their verdicts via `post-marker --file` per SKILL.md § File-only Codex verdict posting).

## File paths + concrete diffs

### Edit 1 — `.claude/agents/code-reviewer.md` (~L33-49, task-bound mode block)

(a) Replace the fenced post recipe:

```
- uv run python scripts/task.py post-marker <N> epm:code-review \
-     --version <revision_round> --note "$(cat /tmp/code-review-<N>.md)"
+ uv run python scripts/task.py post-marker <N> epm:code-review \
+     --version <revision_round> --file /tmp/code-review-<N>.md
```

(b) Immediately after the recipe, add a 2-3 sentence rationale + read-back duty paragraph:
- WHY `--file`: the file contents are read raw with no shell re-parsing — a verdict body quoting git verbs / diff text / `$( )` can never be shell-mangled or tripped by the repo-root guard's `--note` argv-prose scan (CLAUDE.md #1722; incident #1723: a claimed post that never landed cost ~9 min + a duplicate reviewer round).
- READ-BACK duty (MANDATORY, before returning): run `uv run python scripts/task.py latest-marker <N> --prefix epm:code-review` and confirm the output shows THIS round's version. Only then may the return text claim the marker was posted. If the read-back does not show it, re-post ONCE via `--file`, re-read; still absent → say so explicitly in the return text (the orchestrator's Step 5b durable-verdict-first rule handles it) — NEVER claim "posted" unverified.
- Deferred-commit caveat (existing CLAUDE.md contract): `post-marker` exit 0 with a stderr commit-deferred ERROR is SUCCESS — the row IS appended (the read-back will show it); never re-post on that warning.

(c) The L49 oversize fallback stays as-is (a short pointer note carries no verbatim verdict body).
