- WHY `--file`: the file contents are read raw with no shell re-parsing — a verdict body quoting git verbs / diff text / `$( )` can never be shell-mangled or tripped by the repo-root guard's `--note` argv-prose scan (CLAUDE.md #1722; incident #1723: a claimed post that never landed cost ~9 min + a duplicate reviewer round).

```bash
uv run python scripts/task.py view <N> --json | \
  jq '[.events[] | select(.kind == "epm:code-review")] | last | {kind, version, ts}'
```

Confirm the output shows `"version": <revision_round>` (this round). Only then may the return text claim the marker was posted. If absent, re-post ONCE via `--file`, re-read; still absent → say so explicitly in the return text (the orchestrator's Step 5b durable-verdict-first rule handles it) — NEVER claim "posted" unverified.
