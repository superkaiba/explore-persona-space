## 4. Design

### 4.1 New regex classes (insert after `_SNAKE_TOKEN_RE`, between lines 7318 and 7320)

```python
# (c) bare hypothesis codes (`H3`) — plan-registered hypothesis slots
#     rendered into figure text (#1072: panel title "… (H3)"). SINGLE digit
#     + case-sensitive by design: `H100`/`H200` GPU names (3 digits) and
#     `H20` (2 digits, also a GPU name) never match; lowercase `h3` is not
#     the project's hypothesis-code convention and stays clean.
_HYPOTHESIS_CODE_RE = re.compile(r"\bH\d\b")

# (d) slot-family codes `f16` / `l16` (first-16 / last-16 answer-slot
#     families, #1072: xlabel "answer position t (f16 slots)"). Deliberately
#     NOT generalized to `[fl]\d+` — `F1` (metric), `l2`/`L2` (norm) are
#     legitimate rendered labels; lowercase-only, and `bf16`/`fp16` dtype
#     spellings never match (no word boundary before the `f`).
_SLOT_FAMILY_RE = re.compile(r"\b[fl]16\b")
```

### 4.2 Classifier wiring in `_opaque_code_tokens` (lines 7329-7373)

Append ONE loop after the existing snake loop (after line 7365, inside the `if not _PATH_SHAPED_RE.match(...)` block), reusing the existing `_only_in_path_words` closure verbatim — this gives the new classes BOTH exemption layers (whole-string path skip at 7342 and per-word path skip) for free:

### 4.3 Design decisions (each justified in §11)

- **Hypothesis class = `\bH\d\b` (single digit, uppercase only)**, exactly per the task body. `H\d{1,2}` is REJECTED: `H20` is a real NVIDIA GPU name, and two-digit hypothesis codes do not occur in this project's plans (registered lattices run H1-H7). `H100`/`H200` are safe under the single-digit form by construction (`\d\b` fails inside a longer digit run). Lowercase `h3` excluded (case-sensitive): hypothesis codes render uppercase; lowercase collides with chess notation / variable names for near-zero recall gain. "H1 2026" (half-year) WOULD match — accepted: implausible in this repo's figure text, and check 28 is WARN-only. `H0`/`H1` as stats notation also match — accepted deliberately: an undefined `H0` in rendered figure text is under-labeled by the project's plain-English rule anyway, and the WARN is acknowledgeable in-body.
- **Slot-family class = `\b[fl]16\b` (lowercase, `16` only)**, exactly per the task body. Generalizing to `\b[fl]\d+\b` is REJECTED: `f1` (F1 score in lowercase axis text), `l2` (L2 norm — "l2 norm" is common lowercase) would false-positive on legitimate metric names; other slot sizes (`f32`, `f64`) collide with float dtype names. `f16` as a float16 spelling is the residual false-positive risk — accepted: the project's figure text spells dtypes `fp16`/`bf16` (neither matches — no `\b` before their `f`), and the check is WARN-only. Uppercase `F16`/`L16` excluded: the incident class is lowercase, and `L16` bare-layer shorthand is a common legible interp convention that would generate noise across existing figures.
- **Path exemption:** both new classes reuse `_only_in_path_words` + the whole-string `_PATH_SHAPED_RE` skip — identical semantics to the pin/snake classes (task-body requirement "outside path words"). E.g. `"figures/issue_1072/H3_panel.png"` (whole string) and `"source: figures/a/f16_slots.png"` (path word in prose) both stay clean.
- **"Code-span contexts" exclusion (task-body diff sketch): NO-OP — documented, not implemented.** Verified: `_iter_meta_label_values` feeds `_opaque_code_tokens` raw JSON string values from sidecars whose `text` block is captured from matplotlib rendered text (`_extract_fig_text` per `.claude/skills/paper-plots/SKILL.md:339-355`) — this channel is not markdown and carries no backtick code spans (grepped: zero backticks in the #1072 pre-fix sidecar strings). Grep-verified the literal label string exists ONLY at verify_task_body.py:7436 and tests:11387 (`_CHECK28_NAME`) — no other mechanical consumer (WARN acknowledgment is free-text; dashboard just renders). `check_figure_label_codes`'s docstring (7402-7435) gains the new classes + a one-line #1072 incident record next to the existing #920/#1092 ones; residual (iii) sentence ("the path exemption covers BOTH token classes") becomes "ALL FOUR token classes".
