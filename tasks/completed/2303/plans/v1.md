### 4.2 Design decision (owned) + rejected alternatives

**Chosen: option (a)-minimal — declare `.claude/config/agent_spec_size_caps.txt` directly in `SPECS`/`SPECS_10D` with `FAMILY_OF[...]="lint"`.**

Why: pair-atomicity and dirt-skip semantics are identical to the existing per-file check BY CONSTRUCTION — the entry rides the exact machinery (#1714 family-atomic skip, #1972 dirt arm, subject-scoped sync-commit exclusion) that already governs `scripts/workflow_lint.py`, and the two existing drift guards (`test_specs_and_specs_10d_token_sets_match`, `test_step10d_family_atomicity_matches_step5a`) extend to the new entry automatically (the FAMILY_OF entry is written comment-free precisely so the second guard's `endswith('="lint"')` iteration picks it up). Zero new mechanism, zero new semantics for a future editor to learn.

**Stated cost, argued acceptable:** a branch that EDITS the caps file (the #1718 concurrency use case — raising a cap for an agent spec it grew) now marks the WHOLE `lint` family dirty, widening the skip to `scripts/workflow_lint.py`, `scripts/select_step9c_tests.py`, the pin-test globs, and the selector manifest. This is the sanctioned fail-safe direction per #1714 ("any dirty member widens the skip to the whole family, never narrows it into a clobber"): the skipped worktree keeps its OWN self-consistent linter+caps pair (its branch-era linter reads its branch-edited caps — coherent), suffers only status-quo staleness, and the pass-1 loop already prints the offending commits so the operator can reconcile manually. The inverse failure — a narrower grain syncing main's linter against branch-era or branch-edited caps — is precisely the incoherent-pair class this task exists to close. Frequency is also low: caps-file-editing branches are workflow-fix branches that typically touch lint-family members anyway.

**Rejected 1 — separate `DATA_DEPS` map (body's option (a), heavier form):** a `DATA_DEPS["scripts/workflow_lint.py"]=".claude/config/agent_spec_size_caps.txt"` map with pair-scoped dirt semantics would confine the widening to the linter+caps pair (selector triple + pin tests would still sync when only the caps file is dirty). Not worth the surface: it needs its own pass-1 dirty-scan integration, its own pass-2 filtering, its own 10d mirror, its own drift-guard test, and introduces a SECOND coupling semantic (pair vs family) into a block two drift guards already pin — for a marginal narrowing whose benefit accrues only on the rare caps-only-dirty branch, in the direction (#1714) the block's doctrine says not to optimize for.

**Rejected 2 — post-sync import-satisfiability probe over synced SCRIPTS (body's option (b)):** `uv run python -c 'import ...'` / `--help` over synced `SPECS` scripts, mirroring #2208, would generalize to data dependencies nobody remembered to declare. Rejected as the PRIMARY fix: it is reactive (detects the strand, then must revert the whole family pair-atomically — a new revert path for the FAMILY arm that does not exist today), slower (venv warm-up + per-script probe on every sync), and its revert-on-failure direction yields status-quo staleness exactly where the declarative entry yields a correct sync. The declarative map is cheaper and deterministic (the body's own words). The forward hole it leaves — a FUTURE import-time data file nobody declares — is mitigated by edit C's breadcrumb comment at the exact introduction site, and remains a candidate follow-up if a second data-dependency incident occurs.

**Rejected 3 — dir-grain `.claude/config` entry:** would auto-cover future files in that directory (today the caps file is its sole content) and match the existing dir-grain entries (`.claude/agents`, `.claude/hooks`). Rejected: it hard-wires the whole future directory to the `lint` family — a future non-lint config file would be family-misattributed (synced/skipped with lint rather than with its true consumers), a cross-family half-sync channel. File-grain keeps the declaration honest; the breadcrumb comment covers the future-file case.

**Explicitly NOT done (body + brief prohibition):** silencing the fail-loud reader (`try/except FileNotFoundError: caps = {}`) — its own docstring forbids it (`workflow_lint.py:14454-14461`: a silent `{}` would un-grandfather every capped spec fleet-wide in one lint invocation).
