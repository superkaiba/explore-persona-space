**Single file:** `.claude/rules/gotchas.md`

Proposed entry (implementer may polish wording; keep it ONE bullet, ≤ ~1,500 bytes; the

must survive any polish, as must the "(observed during #1482…)" single-observation
hedge):

> - **Edit-then-run can execute the PRE-edit script (PostToolUse formatter race) — exit
>   0, stale artifact.** The `.claude/settings.json` PostToolUse hook reformats every
>   Write/Edit'd `*.py` (ruff check --fix + ruff format; /tmp-excluded) asynchronously
>   relative to the NEXT tool call; a Bash run issued immediately after an edit can
>   execute the OLD bytes and exit 0, producing an artifact from the pre-edit code
>   (observed during #1482: the hook rewrote a generator ~2 s AFTER the run had already
>   started). The failure is silent and DIRECTIONAL — it always reproduces the PREVIOUS
>   behaviour, so "my fix had no effect" sends an agent off changing correct code.
>   Red flag (one command): `stat -c '%y %n' <script> <artifact>` — the SCRIPT's mtime
>   LATER than the artifact it supposedly produced is a suspicion trigger, NOT proof: a
>   late cosmetic ruff reformat of already-correct post-edit bytes produces the same
>   ordering on a fast healthy run. RULE: on an edit-then-run cycle never trust the
>   exit code alone — the AUTHORITATIVE check is grepping the artifact for a string
>   only the NEW code emits; a stale-looking mtime ordering without that grep proves
>   nothing in either direction.
