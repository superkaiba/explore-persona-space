## Method delta (vs the prescribed fix in the task body)

The task's fix item 2 offers "an import-satisfiability probe for FAMILY-synced
test files mirroring the sibling arm's #2208 probe ... If deferred, state why."
This plan implements item 2 as a STATIC structural guard (acceptance criterion
3) instead of a runtime `pytest --collect-only` probe inside the family-sync
block, and DEFERS the runtime-probe variant, for three reasons:

- **Revert complexity on a hot fail-closed path.** The sibling arm's probe
  reverts a bounded per-issue file pair. The family sync checkouts+commits
  atomically across ALL safe families in one `git checkout origin/main --
  $SAFE_SPECS`; a probe-failure revert would have to unwind the whole
  `workflow` family (SKILL.md included) in TWO mirrored copies of a
  merge-path block (Step 5a + the Step 10d post-gate re-sync, which runs
  inside the `gh pr merge` sequence). A bug there reds every Step 5a run and
  every merge fleet-wide — disproportionate to the residual risk once the
  known helper is in the family.
- **The static guard catches the class EARLIER.** A runtime probe detects the
  skew per-worktree after main already shipped it; the structural test reds on
  main at the very PR that adds a new helper import without widening SPECS, so
  the half-sync configuration is never shippable.
- **Bounded residual.** The remaining uncovered shape — a pin test importing a
  main-NEW SYMBOL from `src/` — is the boundary paragraph's pre-existing,
  documented accepted seam (`explore_persona_space.workflow` + the two named
  β-class seams), unchanged by this task.
