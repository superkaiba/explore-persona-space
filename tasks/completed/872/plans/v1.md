```markdown
## Supersede contract — land on main + tombstone the serial twin (same round)

A vectorization rewrite is not done when the batched code exists — it is done
when the serial original can no longer be run silently. Three duties, all in
the SAME round as the rewrite:

1. **Land the batched helper on `main` in the same round** — shared `src/`
   infra lands via the normal worktree merge (or a coordinated infra task),
   never as a task artifact: #722's helper merge-FAILED
   (`new-shared-src-infra-cannot-land-via-artifact`) and stranded on the
   unmerged `vectorized-mlp-skill` branch while the session kept running the
   OLD serial script at ~38h ETA. Confirm with
   `git log --oneline origin/main -- <helper path>` before treating the
   rewrite as done. A follow-up round MUST NOT schedule work that calls the
   superseded serial path while the batched twin is off-`main` — that is
   exactly how #778's same-issue follow-up re-ran the serial 1000-draw null
   battery. (General lesson: `.claude/rules/workflow-fix-on-bug.md`
   § "Built-but-stranded fixes don't help"; this contract is its
   vectorization-specific mechanism.)
2. **Tombstone the superseded serial entrypoint.** Default mechanism: the
   serial function/script emits a loud `DeprecationWarning` at call time
   naming the batched replacement, and raises `RuntimeError` when
   `EPM_FORBID_SERIAL_FITS=1` (the opt-in hard gate a follow-up round or an
   orchestrator can arm to make silent serial re-runs impossible). Outright
   deletion is allowed ONLY when no prior task's Repro/footer references the
   entrypoint (grep `tasks/*/*/body.md` first) — old clean-results must stay
   reproducible. With no tombstone, the next reuser picks the serial path as
   "the available implementation" (#667 picked up #722's serial `fit_cell`).
   Worked example: `scripts/issue722_fit_M.py::fit_cell` — the
   `include_mlp=True` serial 300-epoch MLP arm carries the warn+raise guard
   (tombstoned by #872); the `include_mlp=False` closed-form ridge arm is NOT
   superseded and carries no warning.
3. **Before starting an in-session vectorization rewrite, check for an
   already-open task on the same file** —
   `grep -l '<module or script name>' tasks/{proposed,planning,plan_pending,approved,running,verifying}/*/body.md`
   from repo root (plus
   `task_workflow.is_open_workflow_fix_task(<target_file>, <fp>)` when a
   candidate fingerprint exists) — and ADOPT/coordinate instead of
   duplicating: #834 and the #778 fix session independently vectorized the
   SAME `null_battery.py` module in parallel, discovering the overlap only
   after both had built.

The contract binds ANY rewrite that supersedes a serial entrypoint — a shared
helper, a `scripts/issue*_*.py` driver, or an in-module loop replaced by a
batched twin — whether done by an implementer mid-experiment, a workflow-fix
session, or an emergency in-session fix.
```

## 11. Decision Rationale

N/A — no training hyperparameters. Design decisions:

1. **Tombstone mechanism = warn-by-default + raise on `EPM_FORBID_SERIAL_FITS=1`; delete only when no Repro-card references.**
   *Why:* deletion breaks reproducibility of #722/#667 Repro cards AND live callers (`issue667_alllayer_analysis.py` calls `fit_cell` deliberately); warn-only failed to be enough in spirit for #778 (autonomous rounds don't read stderr) — the env-var raise gives a follow-up round / orchestrator a hard gate it can arm. Honest limit: the raise is opt-in, so an unarmed run still only warns; the contract's duty 1 (batched twin on `main`) is the primary defense, the tombstone is the second layer.
   *Source:* task body diff sketch + incidents #722/#778/#667; live-caller grep this session.
   *Alternatives:* delete (breaks #667 + Repro cards — rejected); warn-only (no hard stop available — rejected); raise-by-default with an ack env var (breaks #667's deliberate reference calls and old-Repro reproduction — rejected).
2. **Duty location: full text in `vectorize-many-cell-fits.md`, one pointer paragraph in `workflow-fix-on-bug.md` § Built-but-stranded, LESSONS row synced.**
   *Why:* the vectorize rule's `paths:` glob fires on exactly the files where rewrites happen; Built-but-stranded is where a #834-style duplicator would land reading the general lesson — a pointer there closes the discovery gap without duplicating text (drift risk).
   *Source:* task body ("cross-reference … one pointer line"); LESSONS index contract (lint-enforced).
   *Alternatives:* full text in both files (drift); a new always-on CLAUDE.md bullet (context inflation — the existing always-on vectorize bullet already points at the rule).
3. **Tombstone `fit_cell` in THIS round: yes.**
   *Why:* trivially safe per the body's Constraints carve-out — warning-only on the superseded `include_mlp=True` arm, no logic change; pytest has no `filterwarnings=error` (verified in `pyproject.toml`); tests import the module but never call `fit_cell` (verified by grep); it doubles as the rule's worked example, which makes the contract concrete.
   *Source:* clarifier findings + this session's greps (`pyproject.toml` lines 67-73; `tests/test_issue722_invariants.py` grep: 0 `fit_cell` hits).
   *Alternatives:* leave-and-note (loses the worked example and leaves the one known live offender live); file a follow-up task (this session runs under the recursion guard and must NOT auto-file — would only be logged, delaying a 12-line change).
4. **Mechanical lint enforcement: NOT this round.**

The lint idea (a `SUPERSEDED_SERIAL_ENTRYPOINTS` list checked for the warn/raise pattern) is logged in the final report for a later pass — NOT auto-filed by this session (recursion guard).
