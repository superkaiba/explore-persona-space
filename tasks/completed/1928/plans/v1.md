These reproduce the five 2026-07-30 15:49-16:45Z firings from session `0ac15c23` (the
#1773/#1482 session): firing 1 was a bare commit chained after an add — a CORRECT block
(it would have swept a concurrent session's staged gated file, the #1894 class); firings
2-5 were pathspec-limited commits that differ from their isolated twins (which PASSED at
15:49:52Z and 16:45:00Z in the same session) ONLY by trailing output redirects — the
false-positive class, and exactly the shape the hook's own FOREIGN-STAGED? remedy
paragraph (L1414-1420) advertises as never-blocked.

**Root cause (file:line, read at HEAD `9c67c78bf1`):** in the commit-clause second token
pass (#1620, `.claude/hooks/guard_root_code_commit.sh:716-787`), redirect tokens after
`--` are collected into `pd_toks` (L729-732) and then classified by
`classify_candidate()` (L541-551), whose metachar arm (`*'<'* | *'>'*` at L544) sets
`clause_opaque=1` → `pathspec_opaque=1` (L787) → the Layer-2 scope gate
(L1296-1301) refuses scoping → whole-index staged read (L1315-1322) → the foreign
uncertified gated file blocks. A detached redirect target (e.g. `/tmp/commit_out.txt`)
would additionally enter the candidate set as a bogus pathspec. Redirections are
consumed by the SHELL and are never git pathspec arguments, so excluding a
strictly-recognized redirect grammar from the candidate stream is semantically exact —
not a heuristic relaxation.

## File paths + concrete diff sketches

**Edited: `.claude/hooks/guard_root_code_commit.sh`** (3 insertion sites, ~30 lines; no
existing line rewritten except the two named single-line arm replacements):

1. **New helper `redirect_tok_kind()`** — insert after `classify_candidate()` (~L552).
   Classifies a MASKED token into `pair` (bare redirect operator that consumes the next
   word: optional-fd `>`, `>>`, `<`, and the `&>`/`&>>` forms), `self` (self-contained:
   fd-dup `[0-9]*>&[0-9-]`-family, or operator with an ATTACHED clean-literal target), or
   `no` (everything else — incl. any FILL/quote/backslash-bearing token and any attached
   target that fails the same clean-literal test `classify_candidate` applies). Shape:
   a `case` FILL/quote pre-filter, then two-three anchored ERE checks via `grep -qE`.
   Fallback direction: `no` → existing opaque handling (block direction).
2. **Pre-`--` positional arm** (~L753, the `*) classify_candidate "$tok" ;;` arm of the
   commit token scan): replace with a dispatch on `redirect_tok_kind` — `pair` →
   `skip_next=1` (reuses the existing skip mechanism at L734-737); `self` → drop; `no` →
   `classify_candidate "$tok"` (unchanged path).
3. **Post-`--` collection** (~L728-732): add a `pd_skip` local (declared beside
   `pd_masked` at ~L717); at loop top of the `after_ddash` branch: consume a pending
   `pd_skip`; then `pair` → `pd_skip=1; continue`, `self` → `continue`; otherwise append
   to `pd_toks` + the existing `pd_masked` marking, unchanged. The rawtail-parity
   recovery path (L764-781) is NOT touched: a masked (quoted) pathspec + redirect now
   fails token-count parity and stays opaque → block (accepted fail-closed residual,
   documented in the header's known-limitations block).
4. **Header note** — one sentence appended to the known-limitations bullet at L67-73
   naming the new redirect recognition + the quoted-pathspec+redirect residual.
5. **Embedded self-test rows** (~L1090-1160 region, `run_case` convention; next free
   A/B ids — verify at implementation, A20+/B39+): 2 ALLOW rows (pathspec commit +
