# Plan v1 — #2362: set-body fail-loud on byte-identical no-op + analyzer landing-verification duty

## Requirement

Close the phantom-body-edit channel from incident #2333 (interpretation round 4): an
analyzer posted `epm:interpretation v4` claiming two body edits applied + a verifier
PASS while `body.md` stayed byte-identical to the prior commit. Root mechanism
(forensically established in #2333): the agent edited one copy of the body and handed
`set-body` a different copy; git no-op'd on identical bytes; the marker recorded
success anyway. Same family as #2034 (durable claim written without probing the
durable state it asserts).

Fix shape prescribed by the task body ("cheapest robust form"), pinned by the title:

1. `set_body` FAILS LOUD when the incoming body is byte-identical to the current
   body (a provable no-op), with an explicit opt-out for deliberate idempotent
   re-application.
2. `.claude/agents/analyzer.md` gains a landing-verification duty: after every
   `set-body`, re-read the live body + confirm the fresh commit sha before posting
   any marker that claims body edits.

## Acceptance criteria

- AC1: `task_workflow.set_body(N, <body identical to current>)` raises a typed error
  BEFORE any side effect (no `original-body.md` snapshot, no git commit, no registry
  write) — mirroring the Goal-H2 drop guard's no-side-effects-on-refusal contract.
- AC2: `set_body(..., allow_noop=True)` / CLI `--allow-noop` permits the write (the
  deliberate idempotent re-application escape, e.g. a crash-resume round re-applying
  a body whose commit already landed).
- AC3: An identical body accompanied by a REAL frontmatter effect (a
  `_SET_BODY_ROUNDTRIP_KEYS` key — `paper`/`abstract` — changing value) is NOT
  refused: the write has a real effect (frontmatter + REGISTRY), so it is not a
  no-op.
- AC4: The dashboard PATCH path (`scripts/task_state.py` → `tw.set_body`) passes
  `allow_noop=True` — a REST-style PATCH carrying an unchanged body is legitimately
  idempotent and is not the phantom-edit channel (that channel is agent CLI use).
- AC5: `.claude/agents/analyzer.md` carries the landing-verification duty (re-read
  live body, grep ≥1 distinctive edited string, confirm fresh commit sha on body.md,
  record the sha in the round's marker note; on a no-op refusal, do NOT reflexively
  pass `--allow-noop` — locate the copy that actually holds the edits).
- AC6: Tests pin AC1-AC4 + the CLI flag threading + clean-SystemExit refusal shape.
- AC7: `workflow_lint.py` no-flags run + ruff pass on touched files; mapped tests
  (`select_step9c_tests.py --map-files`) green.

## Method delta

New guard mirrors the existing Goal-H2 drop guard in the SAME function (typed error
class + hoisted-before-snapshot check + CLI flag + clean SystemExit): no new
architecture, one new comparison. Delta vs the task body's wider candidate list: the
`post-marker` pre-post hook (gating `epm:interpretation` kinds on a fresh body
commit) is NOT implemented — the set-body guard makes the phantom state impossible
to create silently at the write layer (the only layer all body edits pass through),
while a marker-side gate would couple `post-marker` to git-history inspection for
selected kinds and still miss markers phrased without a recognized kind. The
analyzer duty covers the marker-side residual (the agent must probe durable state
before claiming it). Decision recorded per autonomous-mode rules.

### 1. `src/explore_persona_space/task_workflow.py`

- New exception beside `GoalH2DropError` (~line 6315):

```python
class SetBodyNoOpError(ValueError):
    """set_body refused: the incoming body is byte-identical to the current
    body and no roundtrip frontmatter key changes — the write is a provable
    no-op (phantom-edit channel, incident #2333)."""
```

- `set_body(...)` signature gains `allow_noop: bool = False`.
- Guard placement: after `body_text = _strip_leading_frontmatter_blocks(new_body)`
  and after the roundtrip-key merge loop, BEFORE the Goal-H2 guard and BEFORE the
  snapshot copy (refusal writes NOTHING). Comparison uses the same normalization
  `_write_body` receives:

```python
new_norm = body_text if body_text.endswith("\n") else body_text + "\n"
roundtrip_effect = any(
    key in incoming_fm
    and incoming_fm[key] is not None
    and fm_before.get(key) != incoming_fm[key]
    for key in _SET_BODY_ROUNDTRIP_KEYS
)
if not allow_noop and new_norm == prior_body and not roundtrip_effect:
    raise SetBodyNoOpError(...)
```

  (`fm_before` = a pre-merge copy of the on-disk frontmatter values for the
  roundtrip keys, captured before the carry-forward loop mutates `fm`.
  Implementer verifies the `_read_body`/`_write_body` round-trip preserves the
  body region byte-for-byte — `_split_frontmatter`/`_join_frontmatter` symmetry —
  and adjusts the normalization to compare exactly what would be written vs what
  is on disk.)
- Error message names: the mechanism ("the file handed to set-body does not differ
  from the current body — the edits were applied to a different copy, or never
  applied; incident #2333"), the escape (`allow_noop=True` / `--allow-noop`) with
  its one legitimate use (deliberate idempotent re-application, e.g. crash-resume
  re-runs), and the remedy (diff your edited copy against
  `$(task.py find N)/body.md` to locate the real edits).
- Docstring: add a short guard paragraph after the Goal-H2 paragraph.

### 4. `.claude/agents/analyzer.md`

Add a compact "Landing verification after every set-body (REQUIRED — #2333)" block
adjacent to the existing set-body handoff instructions:

- After EVERY `task.py set-body` call, in the SAME turn, BEFORE posting any marker
  that claims body edits: (a) re-read the LIVE body
  (`$(uv run python scripts/task.py find <N>)/body.md`) and grep for ≥1 distinctive
  string from this round's edits; (b) confirm a fresh commit touched body.md
  (`git log -1 --format='%h %cI' -- <that path>`) and that it postdates the round
  start; (c) record that sha in the round's marker note (`body_commit=<sha>`).
- On a `set-body: no-op` refusal: the refusal MEANS your edits are not in the file
  you passed — do NOT retry with `--allow-noop`; find the copy that holds the edits
  (the file you actually Edited), re-diff, re-run set-body with that file.
  `--allow-noop` is only for a deliberate re-application of an already-landed body.
