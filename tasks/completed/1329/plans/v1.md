# Plan: issue #1329 — dispatch-time lint for lane-specific env vars in `--workload-cmd`

`architectural: false` — this is an additive, warn-by-default lint (new optional CLI flag, new free-form `extra` key on an existing marker, one pre-route refusal for a launch class that could never have succeeded); no status enum, marker schema, or `task.py` contract changes.

### 0.0 TL;DR (plain English)

- **What I'll build:** a small pure function that scans a `--workload-cmd` string for bare references to env vars that only some compute lanes export (`$WORKLOAD_ROOT` and verified peers), wired into `dispatch_issue.py launch` as a loud stderr warning + marker flag (hard refusal only when the crash is provably certain), plus a one-line warning at GCP→RunPod failover time, plus fixing the `/issue` SKILL.md prose that currently *recommends* the crash pattern.
- **What I expect:** the exact #825 command (`REPO_ROOT="$WORKLOAD_ROOT" bash scripts/...`) gets flagged at dispatch time with the lane-portable fix named in the message; safe `${WORKLOAD_ROOT:-...}` forms and all existing GCP-lane dispatches pass untouched.
- **What would change my mind:** if the quote/expansion parsing can't cleanly separate the crash pattern from the safe defaulted pattern, I'd descope to an exact-pattern warn on `$WORKLOAD_ROOT` only (the proven offender) rather than ship a noisy lint.

## 1. Goal, requirement, acceptance criteria

**Goal (Task #1329 `## Goal`, verbatim; re-read at return time):** "add a dispatch-time lint in scripts/dispatch_issue.py (or the router's workload-cmd validation) flagging lane-specific env vars ($WORKLOAD_ROOT and peers) in user-supplied --workload-cmd strings, with a lane-portable alternative named in the error"

**Incident:** #825 Track-S — a GCP crash failed over to RunPod; the reused workload-cmd `REPO_ROOT="$WORKLOAD_ROOT" bash scripts/issue825_naturalistic_s_dispatch.sh` aborted under the RunPod launcher's `set -uo pipefail` (runpod.py:504) because `WORKLOAD_ROOT` is exported only by the GCP startup script (gcp.py:2386, inside `render_startup_script`, gcp.py:1101). Fixed in-session driver-side (commit `65ff2426a8`, Bug B: `REPO_ROOT="${REPO_ROOT:-${WORKLOAD_ROOT:-$(cd "$(dirname "$0")/.." && pwd)}}"`); the generalizable guard is this task.

**Acceptance criteria (all testable):**

1. `lint_workload_cmd_lane_env("REPO_ROOT=\"$WORKLOAD_ROOT\" bash scripts/x.sh", backend_value="auto")` flags `WORKLOAD_ROOT` with missing lanes `{runpod, slurm}` (the #825 incident trace, §9 assumption T1).
2. The defaulted forms `${WORKLOAD_ROOT:-...}`, `${WORKLOAD_ROOT-...}`, `${WORKLOAD_ROOT:+...}` are NOT flagged (set-u-safe by POSIX); assignment `WORKLOAD_ROOT=/x ...` and single-quoted literals are NOT flagged.
3. `launch` on auto/gcp lanes with a flagged cmd: exit 0, launch proceeds, loud `logging.warning` on stderr naming the var + missing lanes + the two lane-portable alternatives, and `extra.workload_cmd_lane_env_risk` on the `epm:backend-selected` marker.
4. `launch --backend runpod --execute-workload` (or an explicit SLURM lane) with a var its own lane lacks: pre-route refusal, exit 2, `reason: workload_cmd_lane_env_unbound`, same JSON shape as `gpus_machine_mismatch`; no backend built, no pod provisioned.
5. `--strict-workload-cmd-env` upgrades every warn to exit 2; `EPM_SKIP_WORKLOAD_CMD_ENV_LINT=1` disables the lint entirely (one info line).
6. `--hydra` launches are untouched (empty workload_cmd → no-op).
7. `backend_poll._runspec_from_gcp_handle` logs one warning when the reused workload_cmd carries a var absent on runpod — the failover-time diagnosis breadcrumb; never blocks the failover.
8. SKILL.md Step 6b rule (f) no longer recommends composing `REPO_ROOT="$WORKLOAD_ROOT" bash ...`; it recommends the self-resolving driver / defaulted-expansion forms, pinned by a test.
9. Existing suites (`test_dispatch_issue_cli.py` 110 tests, `test_issue_dispatch.py` 50, `test_router.py`) pass unchanged.

### 3.1 Library: `src/explore_persona_space/backends/issue_dispatch.py`

New constants + function (in-scope workflow surface per workflow-fix-on-bug.md):

```python
# Vars exported into the workload shell env per lane, verified against the
# renderers (see docstring for line-anchors; forward-parity-tested).
_SLURM_LANES = ("nibi", "fir", "mila")
LANE_WORKLOAD_ENV_EXPORTS: dict[str, frozenset[str]] = {
    "gcp": frozenset({           # gcp.py render_startup_script (fn at :1101)
        "WORKLOAD_ROOT",         # :2386
        "REPO_ROOT",             # :1336 (workload-cmd branch, #641)
        "EPS_ISSUE", "EPS_ATTEMPT_ID",              # :2384, :2385
        "EPS_SENTINEL_PATH", "EPS_DELIVERABLES_OK_PATH",  # :2387, :2393
        "EPS_HF_DATA_REPO", "EPS_LOG_PATH",         # :2403, :2440
        "EPS_DONE_GRACE", "EPS_DONE_KEEPALIVE_PATH",  # :2408, :2409
        "EPS_SCRATCH_DIR", "WANDB_PROJECT", "PYTHONPATH",  # :1367, :1356, :1348
        "HOME", "PATH",
    }),
    "runpod": frozenset({        # runpod.py launcher (:489-512)
        "REPO_ROOT", "WANDB_PROJECT",               # :508, :509
        "HOME", "PATH",                             # :505 + ambient
    }),
    "slurm": frozenset({         # slurm.py custom stage + prelude
        "EPS_ISSUE", "EPS_ATTEMPT_ID", "WANDB_PROJECT",  # :1527, :1528, :1539
        "SCRATCH_JOB_DIR", "PYTHONPATH",            # prelude, :1503
        "HOME", "PATH",
    }),
}

@dataclass(frozen=True)
class WorkloadCmdEnvLint:
    flagged: dict[str, tuple[str, ...]]  # var -> sorted reachable lanes missing it
    certain: tuple[str, ...]             # vars the PINNED lane itself lacks (provable set -u abort)
    reachable_lanes: tuple[str, ...]

def lint_workload_cmd_lane_env(
    workload_cmd: str, *, backend_value: str | None, execute_workload: bool = False,
) -> WorkloadCmdEnvLint: ...
```

Semantics:

- **Reachable lanes** from the normalized backend: `runpod` → `{runpod}`; `gcp` → `{gcp, runpod}` (Part B workload failover reuses the cmd on RunPod, compute-backend-failover.md); `nibi|fir|mila|cluster` → `{slurm}`; absent/empty/`auto` → `{gcp, slurm, runpod}` (the `DEFAULT_AUTO_LANE_ORDER` chain + RunPod terminal rung).
- **Candidate universe** = union of the three sets. A var is **flagged** iff it is referenced *bare* in the cmd AND absent from ≥1 reachable lane's set. `HOME`/`PATH` sit in all three sets so they never flag. Never flag arbitrary `$FOO` outside the universe (false-positive discipline).
- **Bare-reference detection** (the shell-aware core): (1) strip single-quoted segments — `re.sub(r"'[^']*'", " ", cmd)` (POSIX single quotes contain no escapes; the `'\''` idiom degrades toward *scanning more text*, i.e. errs conservative); (2) per candidate `v`, match `re.search(rf"(?<!\\)\$(?:{v}(?![A-Za-z0-9_])|\{{{v}\}})", stripped)`. This matches `$WORKLOAD_ROOT` and `${WORKLOAD_ROOT}` but structurally NOT `${WORKLOAD_ROOT:-…}`/`${WORKLOAD_ROOT-…}`/`:+`/`:=` (any operator breaks the exact `${V}` brace match), not assignments (no `$`), not `\$V` escapes, not `$WORKLOAD_ROOTX`.
- **`certain`** ⊆ flagged: only when the launch provably executes the cmd under `set -u` on a lane lacking the var — explicit `runpod` **with** `execute_workload=True` (launcher `set -uo pipefail`, runpod.py:504; a provision-only runpod launch downgrades to warn — the experimenter recomposes the pod-side launch), or an explicit SLURM lane (inner `bash -eu -o pipefail -c`, slurm.py wrapper comment ~:1546). Explicit `gcp` + a gcp-missing var (e.g. `$SCRATCH_JOB_DIR`) stays warn — the GCP startup script's `set` flags for the workload line are not verified `-u`, so certainty isn't claimed.

### 3.2 CLI wiring: `scripts/dispatch_issue.py::_cmd_launch`

Insert after the `_gpus_gcp_lane_conflict` guard (L1236–1239), keeping #599 ordering first:

```python
lint = None
if spec.workload_cmd and os.environ.get("EPM_SKIP_WORKLOAD_CMD_ENV_LINT") != "1":
    lint = lint_workload_cmd_lane_env(
        spec.workload_cmd, backend_value=args.backend,

    logging.getLogger("dispatch_issue").warning(<WARNING TEXT below>)

```

`_workload_cmd_env_refusal` mirrors the `gpus_machine_mismatch` body byte-shape (L811–818): `{"ok": False, "issue", "failure_class": "infra", "status": "blocked", "reason": "workload_cmd_lane_env_unbound", "note": "failure_class: infra\nreason: workload_cmd_lane_env_unbound\ndetail: ..."}`. New parser flag on the `launch` subparser (next to `--workload-cmd`, ~L2128): `--strict-workload-cmd-env` (`action="store_true"`), help text naming the warn-default contract.

**Exact stderr warning text** (per flagged var; `%s`-interpolated):

> `--workload-cmd references $WORKLOAD_ROOT bare, which is exported only by: gcp (backends/gcp.py render_startup_script) — UNBOUND on: runpod, slurm. The RunPod launcher and the SLURM custom stage run the command under set -u, so a GCP→RunPod failover (or SLURM fall-through) re-running this exact command aborts before the driver starts (incident #825: REPO_ROOT="$WORKLOAD_ROOT" killed the Track-S RunPod failover). Lane-portable alternatives: use a default expansion — REPO_ROOT="${WORKLOAD_ROOT:-$PWD}" (every lane cd's to the checkout root before running the command; ${VAR:-default} is safe under set -u) — or make the driver self-resolve: REPO_ROOT="${REPO_ROOT:-${WORKLOAD_ROOT:-$(cd "$(dirname "$0")/.." && pwd)}}" (the #825 fix, 65ff2426a8). Launch continues; epm:backend-selected carries extra.workload_cmd_lane_env_risk. Fail instead with --strict-workload-cmd-env; silence with EPM_SKIP_WORKLOAD_CMD_ENV_LINT=1.`

The refusal `detail:` reuses the same body with "Launch continues" replaced by "Launch refused: the pinned lane executes this command under set -u with the variable unbound — the crash is certain (pre-route, no instance provisioned)."
