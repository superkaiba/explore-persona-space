## 4. Method delta (vs the existing check-19 presence check)

Check 19 / check 10 answer "does each example block HAVE a disclosure line?" (any phrasing from the broad vocabulary). Check 39 answers a different, narrower question: "when the author makes an explicit machine-parsable count claim — the `Disclosure: <N> of <M>` line — does N reconcile with what is actually shown?" Deltas:

1. **Parse target is the `Disclosure:` keyword prefix ONLY** — never the broad `_SUBSET_DISCLOSURE_RE`/`_CHERRY_DISCLOSURE_RE` vocabularies. Reason: the generic `K of M rows` phrasing is routinely used where K counts table ROWS inside one block (e.g. the `_V4_GOOD_BODY` test fixture's `<summary>5 example training rows (5 of 2,000 rows, random sample)</summary>` over a 1-row table) — parsing those would false-positive immediately. The `Disclosure:` prefix is the explicit count-claim convention (#928/#1005) and is exactly what the Goal names.
2. **Counting must extend beyond `_iter_sample_blocks`** — both live bodies present examples as top-level markdown bullets (measured: 0 blocks, 6 bullets each). The check counts under multiple bases and reconciles generously (§ below).
3. **Group semantics, not per-block prelude:** one `Disclosure:` line covers ALL example items from the end of that line to the next `Disclosure:` line (or slot end). This matches the real usage (one line heading a run of bullets) and naturally handles multiple disclosure lines per slot. The check-19 per-block `_prelude_window` machinery is NOT reused (a group line only sits in the FIRST block's prelude window).
4. **Scope: v4 `## Methodology` Sample slot only** (via `_v4_methodology_sample_slot`), per the Goal. `## Results` excerpts and v3 `## Data` are deliberately out of scope (v3 has zero `Disclosure:` usages; grandfathering is satisfied by construction).

```python
# Explicit shown-count claim inside the v4 Sample slot — the `Disclosure:
# N of M` convention (#928/#1005). Deliberately keyed on the `Disclosure:`
# prefix ONLY: the broad _SUBSET_DISCLOSURE_RE phrasings (`K of M rows`,
# `first N of M`) routinely count table ROWS inside one block and must
# not trigger count reconciliation (#1421).
_DISCLOSURE_COUNT_RE = re.compile(
    r"(?im)\bdisclosure:\s*(?:the\s+|first\s+|showing\s+|top\s+)*"
    r"(\d[\d,]*)\s+of\s+(?:the\s+)?(\d[\d,]*)"
)
```

Thousands separators: `(\d[\d,]*)` on both N and M; parse with `int(g.replace(",", ""))`. Lines like `Disclosure: cherry-picked for illustration` / `random sample` carry no `N of M` → no match → check does not engage (design decision 1 settled).

**(c) The check** — after `check_data_subset_disclosure` (~line 9718):

```python
def check_v4_sample_disclosure_count(body: str) -> CheckResult:
    """Check 39 (v4 only): every explicit `Disclosure: N of M` count claim
    in the ## Methodology Sample slot reconciles with the number of example
    items actually shown in that claim's group (#1421; incident #1005:
    claimed 8 of 2,400, showed 6).

    Counting bases per group (group = text from the end of the Disclosure
    line to the next Disclosure line / slot end): sample-like blocks
    (_iter_sample_blocks — consistent with check 19's enumeration), ALL
    fenced + <details> blocks, top-level list items, GFM table data rows,
    blockquote groups. Zero-valued bases are dropped.
      - N matches ANY basis        -> PASS (presentation-medium agnostic)
      - N > max(bases), bases != Ø -> FAIL (overclaim — the incident class)
      - other mismatch             -> WARN (is_warn=True)
      - bases == Ø                 -> PASS-skip (unrecognized presentation;
                                      never guess)
    PASS-skips on non-v4 bodies (forward-only; no grandfathered body carries
    the Disclosure: convention — grepped 2026-07-16, #1421).
    """
    label = "Sample-slot disclosure count (v4)"
    if not is_v4(body):
        return CheckResult(label, True, "skipped — not a v4 body")
    methodology = section_text(body, "Methodology")
    if methodology is None:
        return CheckResult(label, True, "## Methodology missing — check 18 will report")
    slot = _v4_methodology_sample_slot(methodology)
    if slot is None:
        return CheckResult(label, True, "no Sample slot — check 18 will report")
    matches = list(_DISCLOSURE_COUNT_RE.finditer(slot))
    if not matches:
        return CheckResult(label, True, "no `Disclosure: N of M` count claim in the Sample slot")
    fails, warns = [], []
    for i, m in enumerate(matches):
        n_claimed = int(m.group(1).replace(",", ""))
        group_end = matches[i + 1].start() if i + 1 < len(matches) else len(slot)
        group = slot[m.end():group_end]
        bases = {
            "sample blocks": len(_iter_sample_blocks(group)),
            "fenced/<details> blocks": (
                len(list(_FENCED_RE.finditer(group)))
                + len(list(_DETAILS_BLOCK_RE.finditer(group)))
            ),
            "top-level list items": _count_top_level_list_items(group),
            "table data rows": _count_gfm_table_data_rows(group),
            "blockquote groups": _count_blockquote_groups(group),
        }
        nonzero = {k: v for k, v in bases.items() if v > 0}
        if not nonzero:
            continue  # unrecognized presentation medium — never guess
        if n_claimed in nonzero.values():
            continue
        desc = (
            f"`Disclosure: {m.group(1)} of {m.group(2)}` claims {n_claimed} shown "
            f"but the group carries {max(nonzero.values())} at most "
            f"({', '.join(f'{v} {k}' for k, v in nonzero.items())})"
        )
        (fails if n_claimed > max(nonzero.values()) else warns).append(desc)
    if fails:
        return CheckResult(label, False, "; ".join(fails + warns))
    if warns:
        return CheckResult(label, True, "; ".join(warns) + " — count mismatch (not an overclaim) [WARN]", is_warn=True)
    return CheckResult(label, True, f"{len(matches)} disclosure count claim(s) reconcile")
```

## 11. Decision Rationale

- **D1 — Parse target = `Disclosure:`-prefixed `N of M` lines ONLY.** *What:* the check engages only on `_DISCLOSURE_COUNT_RE` matches; the broad `_SUBSET_DISCLOSURE_RE`/`_CHERRY_DISCLOSURE_RE` phrasings (`cherry-picked`, `random sample`, `first N of M`, `K of M rows`, `N examples`) never trigger it. *Why:* the generic `K of M rows` form routinely counts table ROWS inside one block — the repo's own `_V4_GOOD_BODY` test fixture (`5 of 2,000 rows, random sample` over a 1-row table) would false-positive under any broader capture; the `Disclosure:` prefix is the explicit count-claim convention and is what the Goal names verbatim. *Source:* Goal text + measured fixture shape (read 2026-07-16). *Alternatives rejected:* parsing all `N of M` phrasings (false-positive minefield); requiring the convention spec-wide (out of scope — the check is opportunistic on the convention where used).
- **D2 — Scope = v4 Sample slot only; v3/v2/legacy PASS-skip.** *What:* gate on `is_v4`, scan `_v4_methodology_sample_slot` only. *Why:* the Goal names the Sample slot; the `Disclosure:` convention exists only in v4 bodies (repo grep: 0 non-v4 hits), so grandfathering ("no new hard FAIL on v3/v2/legacy") is satisfied by construction rather than by a WARN downgrade. *Source:* check 19's `is_v3` gate + the CHECKS-list forward-only convention (checks 18/21/27/36 all PASS-skip cross-generation); repo grep 2026-07-16. *Alternatives:* also scanning v3 `## Data` (dead code — zero usages) or v4 `## Results` (per-result excerpts don't use the convention; riskier counting) — both rejected as scope creep.
- **D3 — Grade: FAIL on overclaim, WARN on other mismatch, skip on uncountable.** *What:* `N > max(bases)` with bases non-empty → FAIL; other mismatch → `is_warn=True`; empty bases or no claim → PASS-skip. *Why:* overclaim is exactly the #1005 incident class (a factual claim the reader cannot trust) and, under the generous max-basis rule, fires only when N exceeds EVERY plausible way of counting — measured false-positive rate on the live fleet: 0/46. Undercount/mismatch has benign causes (an extra uncovered illustrative snippet) → WARN. Uncountable presentation → never guess. *Source:* the emitter's diff sketch (FAIL) + the WARN-check precedent for heuristic reconciliation checks (checks 30/32/33/34 are WARN because their claim-vs-artifact matching is fuzzy; here the FAIL branch is reserved for the non-fuzzy direction); dry-run measurements this plan. *Alternatives:* WARN everywhere (kept as the §8 fallback if the sweep surprises); exact-match FAIL (rejected — the one-table-of-N-rows form would false-FAIL).
- **D4 — Counting bases: multi-basis max, group semantics.** *What:* per Disclosure line, count sample blocks + raw fenced/`<details>` blocks + top-level list items + GFM table data rows + blockquote groups over the text from that line to the next Disclosure line/slot end; N matching ANY basis passes. *Why:* both live bodies present examples as top-level bullets (0 blocks — `_iter_sample_blocks` alone would make the check vacuous on its own motivating incident, the #1287 trace-the-predicate failure mode); the table-row basis covers the N-rows-in-one-table form; extra bases only reduce false FAILs under the overclaim-only rule. Group semantics (not per-block `_prelude_window`) because the real usage is one line heading a run of items. *Source:* measured #1005/#928 slot structure (this plan, 2026-07-16). *Alternatives:* per-block prelude matching (fails on the group form); single strict block count (vacuous, above); summing multiple disclosure lines into one total (loses per-group attribution).
- **D5 — Check number 39, name `check_v4_sample_disclosure_count`, body-only registration in `CHECKS`.** *Source:* registry read — 38 is the highest in use (`check_linked_not_embedded_figures`); the check needs no issue/context args → `CHECKS` list, not the `verify_text` separately-dispatched group (the check-18/19 precedent). *Alternatives:* folding into check 19 (rejected — different generation gate, different semantics, and check 19's label/behavior is pinned by existing tests).
