## 1. Goal

Stop workflow subagents from inheriting the full MCP tool-schema payload at spawn by replacing the implicit "inherit all tools" default (absent `tools:` key) with explicit restricted tool declarations in every file under `.claude/agents/*.md`, without removing any tool an agent's spec text instructs it to use.

**Requirement.** Every `.claude/agents/*.md` file (including the 3 deprecated-but-`.md`-globbed files) carries either a `tools:` allowlist or a `disallowedTools:` denylist; no workflow agent spawned via the Agent tool inherits the todoist / google-workspace / playwright / runpod schemas it never uses.

**Acceptance criteria.**
1. Frontmatter parse of all 28 files shows a `tools:` or `disallowedTools:` key in every one (mechanical check, §6a).
2. For every file, every tool its spec body instructs it to use is covered by its declaration (exact name or `mcp__<server>` pattern), per the §4.3 extractor vocabulary (mcp__ tokens + built-in tool names + prose MCP aliases) modulo the documented exceptions list (§5).
3. Empirical spawn probe, judged by the DECIDABLE CLASSIFIER in §6b (before/after run back-to-back, same session/config, harness version recorded; read = SUM of first sidechain assistant-turn `cache_creation_input_tokens + cache_read_input_tokens`): PASS on `after < 40K`; PASS-BOUNDED on `before already < 40K` (deferral regime — no delta claim; the binding probe in criterion 3b carries the verdict); INCONCLUSIVE on `40K ≤ after < before·0.7` (binding probe + residual decomposition dominate); KILL-1 on `after ≈ before at the inlined regime (≥100K)`.

- (a) **Syntax:** docs canonical example is inline comma-separated (`tools: Read, Glob, Grep`); the repo's YAML-list form is also honored (runtime-verified — the 11 restricted agents report their lists). Both accepted.
- (b) **Absent key:** "`tools` — Tools the subagent can use. **Inherits all tools if omitted.**" and "Subagents inherit the internal tools and MCP tools available in the main conversation by default."
- (c) **Restriction mechanism:** "This example uses `tools` to exclusively allow Read, Grep, Glob, and Bash. The subagent **can't edit files, write files, or use any MCP tools**" — non-listed tools are removed from the subagent's inventory (neither schemas nor names are loaded). Corroborated by: "To keep an MCP server out of the main conversation entirely and **avoid its tool descriptions consuming context** there, define it inline [in subagent frontmatter]" — i.e., tool descriptions cost context wherever the tool is in inventory.
- (d) **ToolSearch / deferral:** the subagents doc never mentions ToolSearch. Tool search (deferred MCP schemas) is enabled by default for *main sessions*; GitHub issue **#25200** ("Custom agents cannot use deferred MCP tools even when declared in mcpServers/tools frontmatter", closed as not planned) reports that deferred-MCP-via-ToolSearch inside custom subagents is unreliable. Conclusion (see §11): do NOT put `ToolSearch` in any allowlist — an allowlist bounds what is *callable*, so ToolSearch cannot grant tools outside it, and explicit listing inlines the few needed schemas deterministically (mcp__ssh ≈ 11 small schemas ≈ 3–4K tokens).
- (e) **Denylist form:** "`disallowedTools` — Tools to deny, removed from inherited or specified list." Server-level patterns work in both fields: "`mcp__<server>` or `mcp__<server>__*` grants or removes every tool from the named server. In `disallowedTools`, `mcp__*` also removes every MCP tool from any server." If both set, `disallowedTools` applies first.
- Also load-bearing: **`AskUserQuestion`, `EnterPlanMode`, `ExitPlanMode`, `ScheduleWakeup`, `WaitForMcpServers` "are not available to subagents, even when listed in the `tools` field"** — so spec mentions of AskUserQuestion (planner, experimenter, workflow-improver gates) impose NO allowlist requirement; those gates are executed by the orchestrator. And: "**To preload Skills into context, use the `skills` field rather than listing `Skill` here** ... [the `skills` field] controls which skills are preloaded, not which skills the subagent can access: without it, the subagent can still discover and invoke skills through the Skill tool. To prevent a subagent from invoking skills entirely, omit `Skill` from the `tools` list." (Fact-check nuances, 2026-07-02: `ExitPlanMode` IS available to a subagent unless its `permissionMode` is `plan` — not load-bearing here; and the harness apparently AUGMENTS declared lists at runtime — codex-clean-result-critic declares `tools: Bash` yet reports Bash/Write/Edit/Read at runtime, plausibly via `memory: project` — so allowlists behave safe-additively.) So: preloaded `skills:` frontmatter keeps working without `Skill` in the allowlist; runtime invocation of NON-preloaded skills (e.g. the planner/analyzer humanize pass) requires `Skill` in the list. Listing `Agent` lets a subagent spawn nested subagents; omitting it forbids nested spawns (which mechanically enforces the project's "subagents never file/spawn" rule).
- **In-repo empirical proof the mechanism works on this harness:** `upload-verifier` (restricted, `mcp__ssh__ssh_execute` listed) runs on-pod commands in production every /issue Step 8; `related-work-finder` (restricted, arxiv MCP + WebSearch listed) resolves citations in production. Explicitly-listed MCP tools in restricted allowlists are callable today, notwithstanding #25200's (older, `mcpServers`-frontmatter-based) failure report.

### 4.3 Durable mechanical check (new lint)

Add `--check-agent-tools` to `scripts/workflow_lint.py` (bundled into the no-flags default run, matching `--check-agent-model-pins` precedent):

1. For every `.claude/agents/*.md`: parse the frontmatter block (between the first two `---` lines; handle folded `>` description blocks by tracking top-level keys only) and FAIL if neither `tools:` nor `disallowedTools:` is present.
2. Cross-check with a WIDENED extractor (per the round-1 critique union — the extractor must cover the §5 layer-1 audit vocabulary, not just MCP tokens): extract from the spec BODY (i) explicit MCP tokens (regex `mcp__[a-z0-9_-]+__[A-Za-z0-9_-]+` and server-level `mcp__[a-z0-9_-]+` forms), (ii) the literal built-in names `WebSearch`, `WebFetch`, `NotebookEdit`, plus phrase forms for built-ins an allowlist can silently block: `` `Agent` tool `` / `Agent(` (nested spawns), `` `Skill` tool `` / "invoke the ... skill" (runtime skill loads), `TodoWrite`, and (iii) prose MCP aliases mapped to their servers: `context7 MCP` → `mcp__plugin_context7_context7`, `SSH MCP` → `mcp__ssh`, `arXiv MCP` → `mcp__arxiv`; FAIL if a mentioned token/phrase is not covered by the file's declaration (exact match or `mcp__<server>` prefix match) — UNLESS the (file, token) pair is in a small `AGENT_TOOLS_MENTION_EXCEPTIONS` dict with an inline reason string (seed entry: `("planner.md", "mcp__ssh__ssh_execute")` — "describes upload-verifier behavior in §6.5, not a planner instruction"; more entries expected for descriptive-not-instructive phrase hits found while implementing — each with a reason).
2b. Declared-name validity: every `mcp__...` token DECLARED in any `tools:`/`disallowedTools:` list must match a snapshotted known-server/tool-name allowlist (a `KNOWN_MCP_SERVERS` constant seeded from the live runtime names in §4.2) — catches silent typos (`mcp__plugin_context7_contex7`) that would otherwise strip a capability without any FAIL.
3. `disallowedTools`-only files (research-pm) pass check 1 and skip check 2's allowlist containment (they inherit everything not denied); instead assert no BODY-mentioned token is denied by the denylist.
4. Add a pytest (`tests/test_workflow_lint_agent_tools.py` or extend the existing lint test file) with MUTATION coverage pinning: current tree passes; a synthetic agent file with no declaration FAILs; a synthetic file mentioning `mcp__foo__bar` without allowlisting FAILs; a synthetic body saying "spawn X via the `Agent` tool" with `Agent` missing from the list FAILs; a synthetic body saying "use `context7` MCP" with `mcp__plugin_context7_context7` missing FAILs; a declared typoed server name (`mcp__plugin_context7_contex7`) FAILs check 2b; a denylist denying a body-mentioned token FAILs check 3; an exceptions-dict entry suppresses its FAIL (the exception path PASSes).

**Why code, not a model call?** N/A in the experiment sense, but the analogous decision: the acceptance check is a deterministic frontmatter parse over 28 small files — code (lint) is trivially correct, free, and re-runs on every commit; a model call adds nothing.

## 11. Decision Rationale

- **Allowlist (`tools:`) as the default form, denylist only for research-pm.** *Why:* matches the 11 in-repo restricted files (runtime-proven), is deterministic against FUTURE MCP-server accumulation (a denylist reintroduces bloat whenever a new server is added), and doubles as a mechanical enforcement of workflow invariants (no `Agent` ⇒ no nested spawns). *Alternative considered:* `disallowedTools: mcp__*` per file — zero built-in-loss risk and kills all MCP bloat, but (i) cannot re-allow the specific MCP tools 5 agents need (denylist applies first; a tool covered by both is removed), (ii) keeps the (now partially deferred) built-in long tail, (iii) diverges from repo precedent. Retained only as the §12 fallback.
- **Baseline sets:** `Bash, Read, Write, Edit, Grep, Glob, TodoWrite` for coding agents (the task's suggested baseline, + TodoWrite for long multi-step work), `Read, Grep, Glob, Bash` for review agents (the exact set 6 existing critics already use). Source: in-repo precedent (methodology-writer, uploader, the critic sextet).
- **ToolSearch: excluded everywhere.** It cannot widen an allowlist, subagent deferral is the unreliable mechanism this fix stops depending on (#25200), and every needed MCP tool is cheaply inlined explicitly. Conclusion from §2(d) research: including ToolSearch would NOT preserve deferral benefits for restricted agents — it is dead weight.
- **Deprecated agents get minimal allowlists** (3 one-line edits): keeps the lint invariant unconditional (every `*.md` declares) and is free insurance; skipping them would force a lint exemption list that outlives its justification.
- **research-pm on a 3-server denylist** rather than an allowlist: it is a main-session persona whose full built-in needs (Skill, Agent, crons, notifications) are broad and version-drifting; enumerating them risks breaking the PM session for zero marginal token win (main sessions get deferral).
- Canonical exemptions: `N/A — no model training` (no §11 hyperparameters); `N/A — no behavioral construct` (no §6 measurement-validity table — the DV here is a token count read mechanically from transcripts); `N/A — no artifact reuse`; `N/A — not a replication`.
