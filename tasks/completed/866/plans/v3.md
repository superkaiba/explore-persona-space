## 1. Goal / requirement + acceptance criteria

**Requirement.** One unified, behavior-agnostic pipeline that turns a `Behavior` + a training
`Context` + a `NegativeContext` panel into contrastive training JSONL (positives under C,
negatives under C'/default) with judge-filtered, quota-equalized, provenance-tracked rows in the
`issue664_common.train_row` shape — replacing the per-behavior `elicit_v2` on-policy ladder.

**Acceptance criteria** (all mechanical):

1. `from explore_persona_space.artifacts import generate_training_data, QUERY_BANKS` works
   (append-only `__init__.py` export).
2. `generate_training_data(behavior, context_C, negatives, ...)` returns
   `(pos_jsonl_path, cn_jsonl_path, pool_meta_path)`; rows validate against the `train_row` shape
   (`{"prompt": [msg dicts], "completion": [{"role": "assistant", "content": str}]}`).
3. `QUERY_BANKS` resolves at least: `wildchat_random`, `betley_main8`, `wang44`, `strongreject`,
   `advbench`, `sycophancy_claims`, `china_sensitive`, `sensitive_info_requests`, `arc_c` — each a
   non-empty `tuple[str, ...]` with recorded provenance; no API call and no network at import or
   load time (committed package-data snapshots only; network is permitted ONLY at one-time
   snapshot MATERIALIZATION during implementation, never at runtime). **No bank loader may raise
   `NotImplementedError` — every registered key loads non-empty on every fallback branch** (the
   v2 §6 "defer with a stub" option is REMOVED; see §6 risk 2).
4. All 9 pinned-v1 `BEHAVIORS` entries have `is_stub == False` after the fill (programmatic
   carve-outs `marker` / `taught_fact` skip the extraction leg by design, per `Behavior.is_stub`);
   every `Behavior.validate()` passes at import. The ONLY exception is the explicit descope path
   of kill-criterion (a) (§10): a fill dropped there is recorded as a named plan deviation in the
   `epm:results` `plan_deviations` field AND restates this criterion to the realized fill set —
   never a silent pass.
5. `generate_training_data` raises `ValueError` on `behavior.programmatic == True` (tier-4
   carve-outs never route through the unified pipeline).
6. Judge-filter semantics: positives kept iff mean graded score > `behavior.threshold`, negatives
   kept iff score < `behavior.threshold` (threshold=50 for all v1 behaviors; the code reads
   `behavior.threshold`, never a literal); a `None` score (all draws dropped) drops the row and
   increments the per-arm dropped count in `pool_meta.json` — never coerced.
7. **Pinned emitted-N contract (per-arm, per-call):** `floor_n = ceil(quota_floor × target_n)`
   with `quota_floor = 0.8`. If kept positives < `floor_n` → `DatagenYieldError` (loud, names
   per-variant yields). Otherwise the call emits **EXACTLY `floor_n` positives** (seeded
   deterministic subsample of the kept pool; surplus discarded) — so every successful call with
   the same `target_n` emits the same N, giving cross-cell dose equality BY CONSTRUCTION (the
   per-call realization of `on-policy-completions.md` § equalize-down: "every kept source trains
   on exactly floor-N rows"). Equalization is NOT per-variant (variants are a diversity axis;
   realized per-variant usage is recorded in pool_meta, not equalized). Negative side: per panel
   member, quota = `per_negative_quota(floor_n, panel)`; a member whose kept negatives <
   its quota → `DatagenYieldError` (the pinned negative-arm floor); each member emits exactly its
   quota (≈1:1 total by the 0c helpers).
8. Negative volume ≈ 1:1 with emitted positives via the 0c allocation helpers
   (`negative_allocation(n_positives, panel)` / `per_negative_quota(n_positives, panel)` — the
   1:1 ratio is HARD-CODED in 0c; datagen exposes no ratio knob); the panel always includes
   `DEFAULT_ASSISTANT_NEGATIVE` (guaranteed by `default_panel()` — asserted in tests).
   **Same-question pairing:** a stable `question_id` is threaded through raw candidates, judge
   results, trimming, and emitted rows; emitted negatives are selected ONLY for questions in the
   emitted-positive question set (fail loud if a panel member cannot cover it).
9. Provenance sidecars are CONTRACTUAL: `pool_meta.json` records per-arm
   requested/generated/kept/dropped counts (refusal-drops, judge-None-drops, and threshold-drops
   counted SEPARATELY per arm), judge draw stats, instruction-variant usage histogram,
   per-question sampling multiplicity, generation + judge model ids, generation temperature
   (judge draws sample at the API default — `judge_graded`'s temperature param is a documented
   no-op; pool_meta records `judge_temperature: "api-default"`), seeds, bank names + `bank_sha`
   (canonical-JSON sha256, not an undelimited join), and timestamps. A per-row sidecar
   (`judge_rows.jsonl`) persists `{question_id, variant_id, arm, scores: [per-draw], mean,
   kept}` for every judged candidate — the Phase-1 threshold sweep reads this without re-paying
   generation.
10. **Generation checkpoint manifest:** stage-3 checkpoints are accompanied by a deterministic
    request-spec manifest (behavior name; train-bank names + SHA + slice ids; elicitation
    instruction variant strings; context config; panel member list; `target_n`; seed; generation
    model + temperature; schema version). A re-invocation into the same `out_dir` resumes ONLY on
    an exact manifest match; on mismatch it raises `DatagenCheckpointMismatchError` (never
    silently reuses stale `raw_pos.jsonl` / `raw_neg.jsonl`).
11. CPU/mock test suite passes with NO network; `uv run ruff check .` + `uv run ruff format
    --check .` pass; the targeted pytest gate (§5) passes — including the UPDATED
    `tests/test_artifacts_directions.py` expectations.

### 3.4 `datagen.py` — pipeline

```python
def generate_training_data(
    behavior: Behavior,
    context_C: Context,
    negatives: Panel | str = DEFAULT_PANEL_NAME,
    *,
    out_dir: Path,
    target_n: int = 200,                  # requested positives target; emitted N = floor_n exactly
    quota_floor: float = 0.8,             # on-policy-completions.md floor, D1-carried
    n_judge_draws: int = 5,               # llm-judging.md rule 4
    gen_model: str = DEFAULT_JUDGE_MODEL, # claude-sonnet-4-5-20250929
    gen_temperature: float = 1.0,
    seed: int = 866,
    generate_fn: GenerateFn | None = None,  # injectable → mock tests / dispatcher default
    judge_fn: JudgeFn | None = None,        # injectable → mock tests / judge_graded default
) -> tuple[Path, Path, Path]:             # (pos_jsonl, cn_jsonl, pool_meta)
```

(NO `neg_ratio` parameter — the ~1:1 ratio is hard-coded in the 0c helpers; a future ratio sweep
extends 0c, not datagen.)

Stages (each checkpointed to `out_dir` the moment its data exists — `code-style.md`
checkpoint-per-phase; resumable ONLY under the stage-3 manifest contract below):

1. **Resolve + guard.** `behavior.validate()`; raise `ValueError` if `behavior.programmatic`;
   resolve panel via `get_panel(name)`; `assert_panel_disjoint_from_sources(...)` against
   `context_C`; seed a `random.Random(seed)` for all sampling. Assign a stable `question_id`
   (bank name + index) to every train-bank question.
2. **Compose generation requests — CONTEXT-PARITY contract (v3, binding).** Every generation
   request is built from the EXACT message list the training row will emit, plus generation-only
   elicitation text:
   - POSITIVE: `msgs = context_C.messages(q)` (system if set, prefix_turns, user_wrap-wrapped q
     — the FULL trained context), then PREPEND/MERGE a generation-only system line = the
     exhibit-instruction variant (round-robin over the 8 variants; when `context_C.system` is
     set, the instruction is appended to it as a delimited generation-only block so exactly that
     block can be stripped at emit).
   - NEGATIVE: `msgs = neg_ctx.messages(q)` (the panel member's OWN system prompt / user_wrap),
     plus the not_exhibit-instruction variant as the same delimited generation-only block — or NO
     added block when `not_exhibit_instructions is None`.
   - Sampling grid: requests are drawn WITH REPLACEMENT over the (question × variant) grid when
     `ceil(target_n / expected_yield)` exceeds the number of unique pairs (small banks — e.g.
     sycophancy's 25 train questions); temperature-1.0 sampling makes repeats distinct;
     per-question multiplicity is recorded in pool_meta. Oversample factor: `1 / 0.7` initial
     expected_yield (recorded; not load-bearing — the floor gate is the guarantee), applied
     per-arm.
3. **Generate via the dispatcher + write the manifest.** `asyncio.run(dispatch_calls(items,
   model=gen_model, build_request=..., parse_response=..., cache_dir=..., checkpoint_dir=...))` —
   `dispatch_calls` is ASYNC; routing per `decide_dispatch_route` (sync fan-out <
   `SYNC_BATCH_CROSSOVER_N` = 2,000 requests; Batch API above; `DEFAULT_BATCH_CHUNK_SIZE` = 1,000
   is the batch SUB-CHUNK size). Persist RAW candidates per arm (`raw_pos.jsonl` /
   `raw_neg.jsonl`, each row carrying `question_id` + `variant_id`) immediately on return. An API
   refusal/empty completion is recorded as a dropped candidate with reason
   (`drop_reason: refusal|empty`), never silently skipped. **Manifest contract (binding):**
   `gen_manifest.json` is written BESIDE the checkpoints — behavior name; train-bank names +
   `bank_sha` + slice ids; the verbatim instruction-variant strings; context config
   (`context_id` + rendered template hash); panel member list; `target_n`; `seed`; `gen_model` +
   `gen_temperature`; schema version. A re-invocation into the same `out_dir` resumes ONLY on an
   exact manifest match; mismatch → `DatagenCheckpointMismatchError` (never reuse stale raw
   candidates).
4. **Judge-filter** via `eval/graded_judge.judge_graded(items, eval_prompt=behavior.judge_rubric,
   n_draws=n_judge_draws, cache_dir=<FRESH per-run dir keyed by manifest hash>, save_raw=...)`:
   keep pos iff `score > behavior.threshold`, neg iff `score < behavior.threshold`; `score is
   None` → drop + count separately from refusal-drops and threshold-drops (drop-never-coerce
   propagates from 0a). The `temperature` param is NOT passed (documented no-op). **Structural
   keep-check (v3):** when `behavior.dv.primary == "structural"` and a deterministic predicate is
   registered (formatting), positives must ALSO pass it and kept negatives must fail it;
   writing_style's judge rubric is the load-bearing filter (no predicate). Checkpoint kept/dropped
   ids + write the per-row sidecar `judge_rows.jsonl` (`{question_id, variant_id, arm, scores,
   mean, kept}`).
5. **Quota + equalize-down (pinned contract, criterion 7).** `floor_n = ceil(quota_floor ×
   target_n)`. kept positives < floor_n → `DatagenYieldError` naming per-variant yields. Else
   emit EXACTLY `floor_n` positives — a seeded deterministic subsample of the kept pool; surplus
   discarded (dose equality across cells by construction). Negatives: for each panel member,
   quota = `per_negative_quota(floor_n, panel)`; select kept negatives whose `question_id` is in
   the emitted-positive question set (same-question pairing, criterion 8); a member that cannot
   cover its quota from that set → `DatagenYieldError` (pinned negative floor). Emit exactly the
   quota per member.
6. **Emit.** `pos.jsonl` / `cn.jsonl`: rows = `train_row(prompt_msgs, completion_text)` where
   `prompt_msgs` = the stage-2 request messages MINUS the delimited generation-only instruction
   block — i.e. exactly `context_C.messages(q)` / `neg_ctx.messages(q)` (parity by construction;
   test-asserted). `pool_meta.json` per §1 criterion 9.

### 3.5 Sync-vs-batch + throughput

Reuse `api_dispatch` routing as-is: at the default `target_n=200` (→ ~286 pos + ~286 neg
generation requests, < 2,000 → sync fan-out under the polite per-key Sonnet cap of 100; judge leg
≈ 5 × ~570 ≈ 2,900 draws > 2,000 → Batch API via `eval/batch_judge`). No new transport code;
datagen is the first GENERATION caller of `dispatch_calls` (generic seams — fact-checked).

## 4. Controls / invariants

- Disjointness, three layers (all mechanical): per-behavior train ∩ extraction ∩ eval = ∅
  (`Behavior.validate`); CROSS-BEHAVIOR pairwise slice non-overlap per shared bank
  (`banks.assert_slice_registry_disjoint()`, run at registry build — v3); panel ∩ sources = ∅
  (`assert_panel_disjoint_from_sources`). Train-instruction ∩ extraction-pair = ∅
  (`Behavior.validate`). wang44/betley_main8 never unioned within a behavior.
- **Context parity (v3):** generation request messages minus the delimited generation-only
  instruction block == the emitted training prompt messages, for BOTH arms (test-asserted).
- `DEFAULT_ASSISTANT_NEGATIVE` in every default panel (test-pinned).
- ~1:1 negative ratio via the 0c allocation helpers; same-question pairing via `question_id`.
- Emitted-N determinism: every successful call emits exactly `floor_n` positives + the per-member
  negative quotas (criterion 7).
- Drop-never-coerce propagation from `judge_graded`; refusal / judge-None / threshold drops
  counted separately per arm.
- Instruction-strip invariant: no emitted `prompt` message contains any elicitation-instruction
  text (test greps every emitted row against every variant string).
- Rubric contract: 0/50/100 anchors + literal `{question}` / `{answer}` slots.
- Determinism: fixed seed ⇒ byte-stable JSONL under the mocked generators (test-pinned).
- Fresh judge `cache_dir` per run (the n_draws-collapse trap); generation resume gated on the
  stage-3 manifest (the stale-checkpoint trap).

## 6. Risks + failure modes

1. **Spurious API refusals on live generation** for harm-flavored behaviors — bounded here (the
   live smoke uses a BENIGN behavior; scaled generation is Phase 1/3 scope). Yield risk
   pre-classified: HIGH for harmful_compliance / broad_em / china_censorship, LOW for formatting /
   writing_style / sycophancy / correctness. Refusals recorded as dropped-with-reason
   (separately counted); the floor gate makes shortfalls loud. (This session hit the
   false-positive refusal class twice at planning time — the risk is real.)
2. **StrongREJECT full-dataset materialization** — fallback ladder per §3.2 (NO raising stub;
   criterion 3 holds on every branch): upstream release [primary] → n=10 constant snapshot with
   `expected_n=10` + README caveat + harmful_compliance advbench 3-way slicing.
3. **Thin per-role slices on small banks** (sycophancy eval=10; china eval ≥10 authored-to-size) —
   acceptable for the v1 fill; Phase 1 widens if needed.
4. **china_censorship negative-arm yield under D1** — the `not_exhibit=None` rationale is
   Qwen-premised while CLAUDE writes the negatives and is often candid; the arm may below-floor
   in live use. Fails loud; the pre-positioned fallback (§3.3: author 4 not-exhibit variants,
   regenerate — API-cost-only) is a pre-authorized deviation (§12).
5. **Existing tests pinned to stub state** — `test_artifacts_behavior.py` +
   `test_artifacts_directions.py::test_score_completions_threading` both edited here; the full
   artifacts suite re-runs.
6. **Import-time cost/fragility of registry fill** — mitigated: package-data JSONs via
   `importlib.resources`, `lru_cache`d loaders; the new `assert_slice_registry_disjoint()` adds
   O(slices²·range-checks) at import — trivial (dozens of slices).
7. **Judge/generator same-family circularity** — quality-gate inflation risk, not a comparison
   confound; recorded in pool_meta (both model ids). Phase 1 must NOT read "high kept-rate" as
   "easy behavior" (kept-rates are not comparable to elicit_v2 on-policy yields).
8. **Async dispatcher integration** — `asyncio.run` at the top level; the injectable
   `generate_fn` seam keeps tests synchronous.
9. **WildChat slice materialization needs network once** (implementation-time only). Fallback:
   `batteries/format_questions.json` (100 generic probes) seeds a smaller snapshot with
   proportionally reduced slice bounds, flagged in README + plan-deviation note.
10. **ARC-C train/eval ecosystem overlap (downstream note):** correctness trains on a subsample
    of the same ARC-C test split `PeriodicCapabilityCallback` scores — Phase-1/3
    capability-retention reads on the correctness organism must swap or de-overlap the capability
    benchmark for those cells (detectable via bank_sha; carried as a plan note for Phase 1, not a
    v1-fill blocker).

## 11. Decision Rationale (load-bearing pipeline constants)

`N/A — no training hyperparameters` (no model is trained in this task). Pipeline constants:

- **Judge keep thresholds pos>threshold / neg<threshold (50 for all v1)** — Source:
  `llm-judging.md` rule 6 anchored midpoint + persona-vectors judge-filter
  (`.claude/rules/persona-vectors-recipe.md` step 4); `Behavior.threshold=50` (0b, L159).
  Alternatives: 60/40 band (rejected — asymmetric to rubric anchors; the Phase-1 sweep reads
  judge_rows.jsonl, criterion 9).
- **Quota floor 80% + emit-exactly-floor_n equalize-down** — Source: `on-policy-completions.md`
  § yield-quota (decision 2026-06-12, #545 followup-scope; "every kept source trains on exactly
  floor-N rows… variable N is a dose confound"); the v3 per-call contract (criterion 7) realizes
  cross-cell dose equality by construction. Alternatives: emit min(kept, target_n) (REJECTED in
  v3 — variable N between floor and target is exactly the dose confound the rule bars);
  all-or-nothing (rejected, the #612 incident).
- **~1:1 positives-to-total-negatives (0c hard-coded)** — Source: `contrastive-negatives.md`
  (#383: 1:1 was one of the three corrections that jointly lifted source rate ~70×); via 0c
  helpers. Alternatives: 1:2 (a Phase-3c lever — would extend 0c, not datagen).
- **Judge n_draws=5; draws at API-default temperature** — Source: `llm-judging.md` rule 4
  (N≈5-10, pilot-tunable); the temperature param is a documented no-op (graded_judge.py L15-19).
  Alternatives: N=10 (2× judge cost; revisit if per-behavior test-retest reliability looks poor
  in Phase 1).
- **Generation temperature 1.0** — Source: `on-policy-completions.md` sampling-temperature
  default ("diversity is the point"), carried to the Claude writer under D1. Also what makes
  with-replacement repeat sampling productive (distinct completions per repeat). Alternatives:
  0.7 (less diverse; rejected as default).
- **Sync-vs-batch crossover = `SYNC_BATCH_CROSSOVER_N` = 2,000 requests** — Source:
  `api_dispatch.py` L414 + `docs/api_throughput_guidelines.md`; `DEFAULT_BATCH_CHUNK_SIZE=1,000`
  is the batch SUB-CHUNK size. Alternatives: force-batch always (worse latency for tiny runs).
- **8 exhibit / 4 not-exhibit instruction variants; oversample factor 1/0.7; with-replacement
  grid sampling** — Source: `ungrounded — authored defaults` (variant diversity substitutes for
  base-model sampling diversity under D1; no literature pin). Risk bounded: pool_meta records
  per-variant usage + per-question multiplicity + yields, so Phase 1 can re-weight; not
  outcome-changing for an infra deliverable whose gate is mock tests.
- **`target_n=200` default** — Source: #664/#545 lineage training-mix sizes
  (order-of-magnitude); a caller-set parameter. Note: emitted N = floor_n = 160 at the default
  (criterion 7).
- **Formatting structural predicate (≥80% of non-empty lines are list items)** — Source:
  `ungrounded — authored default` mirroring the 545 structural-scorer lineage
  (behavior.py `structural` DV notes); violation-fixture-tested; Phase 1 can tune.
