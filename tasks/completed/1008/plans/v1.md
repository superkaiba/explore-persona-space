### 3.1 Claim-extraction constants + function

```python
# ─── Check 30: HF file-count claims vs the Hub tree (WARN) ──────────────────
#
# #931 shipped "528 files" / "10 shards" / "3 files" / "198 files" for HF
# artifacts where the scoped listing at the pinned revision holds
# 515/9/2/197 — folder entries were counted as files. Check 23 verifies the
# link RESOLVES; nothing verified the adjacent numeric claim. This check
# extracts count claims sitting in two conservative positions relative to a
# hex-pinned HF /tree markdown link and compares them against a files-only
# count from the SAME bounded raw tree-endpoint probe checks 23/25 use
# (#733 — never the SDK list_repo_tree). WARN-only: a claim miscount is a
# prose-hygiene defect, not a broken body; and a WARN can never block
# offline (every non-definitive probe outcome SKIPs).

# A markdown link whose target is an HF Hub URL. Two-stage extraction: match
# the link structure first, then scan the TEXT for a count-noun and parse the
# TARGET with the shared _HF_HUB_TREE_BLOB_URL_RE.
_MD_HF_LINK_RE = re.compile(
    r"\[(?P<text>[^\]]{1,300})\]\((?P<url>https?://huggingface\.co/[^)\s]+)\)"
)
# A numeric count claim: "515 files" / "1 file" / "10 shards". Comma-grouped
# thousands allowed ("1,234 files"); bounded at 6 plain digits.
_COUNT_NOUN_RE = re.compile(
    r"\b(?P<count>\d{1,3}(?:,\d{3})+|\d{1,6})\s+(?P<noun>files?|shards?)\b",
    re.IGNORECASE,
)
# A parenthetical that OPENS with the count-noun, immediately preceding a
# markdown HF link (≤80 chars of qualifier inside the paren, ≤6 chars of
# separator between `)` and `[`): the #931 footer shape
# `... (515 files verified via scoped listing): [issue931_story_map @ …](url)`.
_COUNT_PAREN_LINK_RE = re.compile(
    r"\((?P<count>\d{1,3}(?:,\d{3})+|\d{1,6})\s+(?P<noun>files?|shards?)\b[^()]{0,80}\)"
    r"\s{0,2}[:–—-]?\s{0,2}"
    r"\[[^\]]{1,300}\]\((?P<url>https?://huggingface\.co/[^)\s]+)\)",
    re.IGNORECASE,
)
# Per-body cap on UNIQUE (repo, sha, prefix) count probes — bounds worst-case
# wall at _HF_COUNT_MAX_PROBES × _HF_PROBE_DEADLINE_S ≈ 96 s (tighter than
# check 25's keywords×URLs worst case). Claims past the cap surface as
# unverified notes.
_HF_COUNT_MAX_PROBES = 8
# Successful EXHAUSTIVE listings only: (repo_id, repo_type, sha, prefix) →
# (n_files, n_dirs). A skip (throttle / cap / offline) is NEVER cached —
# same convention as _HF_EXISTENCE_CACHE (#733).
_HF_TREE_FILE_COUNT_CACHE: dict[tuple[str, str, str, str], tuple[int, int]] = {}


def _gather_hf_count_claims(body: str) -> list[tuple[int, str, str, str, str, str]]:
    """Extract (claimed_count, noun, repo_id, repo_type, sha, path_prefix)
    tuples for numeric file/shard-count claims ADJACENT to hex-pinned HF
    /tree markdown links. Fence-stripped; deduplicated; /blob/ links and
    moving refs (/tree/main) are out of scope (the shared URL regex only
    matches 7-40-char hex revisions, mirroring check 23)."""
    kind_to_type = {"datasets": "dataset", "spaces": "space", None: "model"}
    stripped = _strip_fenced_blocks(body)
    out: list[tuple[int, str, str, str, str, str]] = []
    seen: set[tuple] = set()

    def _add(count_s: str, noun: str, url: str) -> None:
        url = url.rstrip(".,;:!?")
        m = _HF_HUB_TREE_BLOB_URL_RE.match(url)
        if m is None:
            return
        if f"/tree/{m.group('sha')}" not in url:
            return  # a /blob/ link is a single file — a count claim there is out of scope
        count = int(count_s.replace(",", ""))
        repo_id = f"{m.group('owner')}/{m.group('repo')}"
        key = (count, noun.lower().rstrip("s"), repo_id, m.group("sha"),
               (m.group("path") or "").rstrip("/"))
        if key in seen:
            return
        seen.add(key)
        out.append((count, noun, repo_id, kind_to_type[m.group("kind")],
                    m.group("sha"), (m.group("path") or "").rstrip("/")))

    for lm in _MD_HF_LINK_RE.finditer(stripped):          # Pattern A: count in link TEXT
        for cm in _COUNT_NOUN_RE.finditer(lm.group("text")):
            _add(cm.group("count"), cm.group("noun"), lm.group("url"))
    for pm in _COUNT_PAREN_LINK_RE.finditer(stripped):    # Pattern B: paren before link
        _add(pm.group("count"), pm.group("noun"), pm.group("url"))
    return out
```

**Precision/recall trade-offs (deliberate, documented in the check docstring):**
- *High precision by construction:* Pattern A requires the count INSIDE the same markdown link as the URL (`[pairs_meta, 9 files](…tree…)`) — the number and the link are structurally bound, so unrelated prose numbers ("seed 42", "180 of 197 valid quotes" AFTER a link, "6,617 total" in post-link prose) can never match. Pattern B requires the count to OPEN a parenthetical whose closing paren is followed within ≤6 chars by a markdown HF link — the #931 footer shape exactly.
- *Known recall sacrifices (accepted):* prose counts near BARE (non-markdown) HF URLs; counts appearing AFTER the link ("… (url) — 9 files"); parentheticals where the count is not leading ("(total 515 files)"); compound claims ("8 eval JSONs + 2 npz"); nouns other than file(s)/shard(s) ("artifacts", "JSONs", "rows", "completions" — rows/completions are RECORD counts, not file counts, and would be wrong to compare). Each sacrifice avoids a concrete false-positive class; a missed claim costs nothing (the check is a net-new WARN).
- *`shards` one-sided comparison* (see 3.3): a legitimate "9 shards" prefix can also hold a manifest/sidecar (10 files), so shard claims WARN only when claimed > file count — the folder-inflation signature (#931's "10 shards" vs 9 files) — never when claimed ≤ file count.

### 3.2 The bounded count probe

```python
def _hf_count_files_under_prefix(
    repo_id: str, repo_type: str, sha: str, path_prefix: str
) -> tuple[str, int, int, str]:
    """Bounded scoped-recursive tree listing → (status, n_files, n_dirs, note).

    Mirrors _hf_probe_keyword's loop (#733): direct GETs via _hf_tree_get
    (real per-request timeout, ≤_HF_PROBE_ATTEMPTS retries/page), following
    Link-header pagination OURSELVES under _HF_PROBE_MAX_PAGES +
    _HF_PROBE_DEADLINE_S. Counts only entries with "type" == "file" under the
    prefix ("directory" entries counted separately for the files+folders
    diagnostic; an entry whose path IS the prefix and is a directory is the
    prefix itself, not content, and is skipped). status == "ok" ONLY for an
    EXHAUSTIVE listing (next_page is None); a cap hit, not_found, or any
    transient error is "skip" — a partial count must never ground a WARN.
    """
    needle = path_prefix.strip("/")
    url = _hf_tree_url(repo_id, repo_type, sha, needle)
    params: dict | None = {"recursive": True}
    headers = _hf_build_headers()
    started = time.monotonic()
    pages = 0
    n_files = n_dirs = 0
    while True:
        res = _hf_tree_get(url, params=params, headers=headers, timeout_s=_HF_PROBE_TIMEOUT_S)
        if res.status == "not_found":
            return "skip", -1, -1, "no such revision/path"
        if res.status == "indeterminate":
            return "skip", -1, -1, res.note
        for e in res.entries:
            path = e.get("path", "")
            if not _hf_under_prefix(path, needle):
                continue
            etype = e.get("type")
            if etype == "file":
                n_files += 1
            elif etype == "directory" and path != needle:
                n_dirs += 1
        pages += 1
        if res.next_page is None:
            return "ok", n_files, n_dirs, ""
        if pages >= _HF_PROBE_MAX_PAGES or time.monotonic() - started > _HF_PROBE_DEADLINE_S:
            return "skip", -1, -1, "HF tree listing exceeded page/time cap"
        # The Link rel="next" URL already carries the params; do not re-send them.
        url, params = res.next_page, None


def _hf_file_count_for_prefix(
    repo_id: str, repo_type: str, sha: str, path_prefix: str
) -> tuple[str, int, int, str]:
    """Fence + optional-dependency + cache wrapper (mirrors _hf_url_existence
    L4858 / _hf_keyword_present_under_prefix L6075 exactly)."""
    if os.environ.get("EPM_VERIFY_BODY_NO_HF") == "1":
        return "skip", -1, -1, "HF probe fenced"
    try:
        import huggingface_hub  # noqa: F401 — local import: optional-dependency guard
    except ImportError:
        return "skip", -1, -1, "huggingface_hub unavailable"
    key = (repo_id, repo_type, sha, path_prefix.strip("/"))
    cached = _HF_TREE_FILE_COUNT_CACHE.get(key)
    if cached is not None:
        return "ok", cached[0], cached[1], ""
    status, n_files, n_dirs, note = _hf_count_files_under_prefix(
        repo_id, repo_type, sha, path_prefix
    )
    if status == "ok":
        _HF_TREE_FILE_COUNT_CACHE[key] = (n_files, n_dirs)
    return status, n_files, n_dirs, note
```

Per-page bound math (stated per constraint 2): each probe issues at most `_HF_PROBE_MAX_PAGES(8) × _HF_PROBE_ATTEMPTS(2)` GETs, each with a real `timeout=_HF_PROBE_TIMEOUT_S(5.0)`, under an outer `_HF_PROBE_DEADLINE_S(12.0)` wall cap; per body, at most `_HF_COUNT_MAX_PROBES(8)` unique probes → worst-case added verify wall ≈ 8 × 12 s ≈ 96 s only when the Hub is pathologically slow on ALL prefixes; typical is one sub-second page per prefix. The early-exit alternative (stop past claimed+1) was rejected: it cannot report the true count M in the WARN message, and the page cap already bounds cost.

### 3.3 The check function + registration

```python
def check_hf_file_count_claims(body: str) -> CheckResult:
    """Check 30 (WARN): numeric file-count claims adjacent to hex-pinned HF
    /tree links must match a files-only scoped Hub tree count. <full docstring
    per the house style: #931 incident, extraction patterns + trade-offs,
    fail-soft semantics, shard one-sidedness, cache/caps, WARN-never-FAIL>"""
    name = "HF file-count claims match the Hub tree"
    claims = _gather_hf_count_claims(body)
    if not claims:
        return CheckResult(name, True, "no file-count claims adjacent to HF tree links")
    mismatched: list[str] = []
    unverified: list[str] = []
    probed: set[tuple[str, str, str, str]] = set()
    for count, noun, repo_id, repo_type, sha, prefix in claims:
        key = (repo_id, repo_type, sha, prefix)
        if key not in probed and len(probed) >= _HF_COUNT_MAX_PROBES:
            unverified.append(f"`{prefix or repo_id}@{sha[:8]}` (per-body probe cap)")
            continue
        probed.add(key)
        status, n_files, n_dirs, note = _hf_file_count_for_prefix(repo_id, repo_type, sha, prefix)
        if status != "ok":
            unverified.append(f"`{prefix or repo_id}@{sha[:8]}` ({note})")
            continue
        if noun.lower().startswith("shard") and count <= n_files:
            continue  # shard claims are one-sided: only folder-inflation WARNs
        if count == n_files:
            continue
        msg = (
            f"body claims {count} {noun} at `{prefix or '/'}` but `{repo_id}@{sha[:8]}` "
            f"holds {n_files} file(s)"
        )
        if n_dirs and count == n_files + n_dirs:
            msg += (
                f" + {n_dirs} folder(s) — the claimed count matches files+folders; "
                "folder entries are not files"
            )
        mismatched.append(msg)
    if mismatched:
        return CheckResult(name, True, "; ".join(mismatched), is_warn=True)
    detail = f"{len(claims)} claim(s) checked"
    if unverified:
        detail += "; " + f"{len(unverified)} unverified (count not confirmed): " + "; ".join(
            unverified
        )
    return CheckResult(name, True, detail)
```

## 7. Risks + failure modes

| Risk | Likelihood | Mitigation |
|---|---|---|
| 429 storm at verify time (the #715/#733 incident class) | Low | No SDK backoff loop by construction — every GET is `_hf_tree_get` (real timeout, ≤2 attempts, 0.5 s pause); 429 → skip in seconds. |
| Pagination blowup on a huge prefix (repo-root link with "N files" claim; the data repo lists >1000 files) | Medium | `_HF_PROBE_MAX_PAGES=8` + `_HF_PROBE_DEADLINE_S=12 s` per probe + `_HF_COUNT_MAX_PROBES=8` per body; cap hit → skip note, never a partial-count WARN. |
| False-positive WARNs on unrelated numbers | Low-Medium | Structural adjacency (inside link text / paren-opening before link); noun whitelist {file(s), shard(s)}; shard one-sidedness; fence-stripping; corpus sweep before ship; WARN-not-FAIL bounds the blast radius to one noise line. |
| WARN noise on legacy/v2/v3 bodies with stale-but-harmless counts | Low | WARN never flips `ok`; promote-time reviewers see one informative line. No grandfathering carve-out needed because nothing can newly FAIL. |
| New check breaks existing tests via shared stubs | Low | Verified: no existing fixture carries an adjacent count claim → zero new probes on existing tests; the two count-invariant tests are bumped deliberately. |
| Claim/listing disagree because the CLAIM counts something else (records, rows) | Low | Those nouns are excluded from the regex by design. |
| Long-running promote process caches a stale count | Low | Definitive-only cache, same convention as `_HF_EXISTENCE_CACHE`; a pinned hex revision is immutable, so a cached exhaustive count can never go stale for that key. |

## 11. Decision Rationale (engineering thresholds — What / Why / Source)

- **Per-request timeout 5.0 s / 2 attempts / 0.5 s sleep** — reuse, not redefine. Source: `_HF_PROBE_TIMEOUT_S` / `_HF_PROBE_ATTEMPTS` / `_HF_PROBE_SLEEP_S`, `scripts/verify_task_body.py` L4679-4681 (#733's tuned values; changing them would change checks 23/25 too).
- **Page cap 8 / wall cap 12.0 s per probe** — reuse. Source: `_HF_PROBE_MAX_PAGES` / `_HF_PROBE_DEADLINE_S` L4682-4683, already governing the identical self-paginating loop in `_hf_probe_keyword` L6055-6058.
- **Per-body probe cap `_HF_COUNT_MAX_PROBES = 8`** — new. Why: bounds worst-case added wall to ≈ 96 s under total Hub pathology, tighter than check 25's existing keywords×URLs worst case (no cap there); #931, the densest observed body, needs 4 unique probes. Source: engineering choice, rationale above.
- **Link-text window ≤300 chars (`[^\]]{1,300}`)** — a markdown label is one visual token; the longest observed HF label in the corpus (#931 footer, `issue931_story_map/eval_results @ 86c5b0e8` class) is <60 chars; 300 is 5× headroom while bounding regex work. Source: engineering choice; matches the existing bounded-quantifier house style (e.g. check 28's bounded scans).
- **Paren qualifier ≤80 chars, count must OPEN the paren** — the real #931 qualifier ("verified via scoped listing") is 28 chars; 80 gives ~3× headroom; requiring the count at paren-open is the precision lever that excludes "(total …: 1,982 novel, 1,035 story …)" summary parentheticals. Source: engineering choice grounded on the §3.4 verbatim shapes.
- **Separator gap ≤6 chars (`\s{0,2}[:–—-]?\s{0,2}`)** — the observed separator is ": " (2 chars); allowing a dash covers the house em-dash style; anything longer is prose, where adjacency no longer implies the claim binds to the link. Source: engineering choice, precision-first per constraint 3.
- **Count regex `\d{1,3}(?:,\d{3})+|\d{1,6}`** — plain and comma-grouped integers, ≤6 digits (10⁶ files exceeds any project artifact set; also caps `int()` surprise). Source: engineering choice; comma form matches the corpus ("6,617", "24,206").
- **Noun whitelist `files?|shards?`; shard claims one-sided (WARN only when claimed > n_files)** — files admit exact comparison (a hex-pinned tree is immutable); shards can legitimately undercount files (shards + manifest), while the #931 folder-inflation signature is strictly claimed > files. Source: engineering choice derived from the #931 incident arithmetic (10 shards vs 9 files; 528 = 515 + 13).
- **`not_found` → skip (not WARN/FAIL)** — matches check 25's mapping for the same reason (cannot corroborate or refute against a missing revision), and check 23 already FAILs dead pins, so double-reporting is avoided. Source: matches `_hf_probe_keyword` L6042-6043 + the `_TreeProbeResult` docstring L4692-4700.
- **WARN never FAIL; partial counts never WARN** — constraint 1; a cap-hit partial count would fabricate mismatches on big prefixes. Source: task body hard constraint + `_hf_probe_keyword`'s cap-hit-→-skip precedent L6063-6065.
- **Separate `_HF_TREE_FILE_COUNT_CACHE` instead of overloading `_HF_EXISTENCE_CACHE`** — the existence cache stores `(verdict, note)` tuples; storing `(n_files, n_dirs)` under the same dict would break its type contract and the L1381 fixture's semantics. Source: engineering choice; same definitive-only convention as L4684-4689.
