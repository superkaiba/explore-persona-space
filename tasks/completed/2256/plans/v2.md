## 1. Goal

The Step 10d pre-push lint-gate single-flight probe (`step9c_baseline.py probe
--pattern 'issue-<N>-lint-gate-tree'`), its completion-read, and its
kill-before-relaunch arm key on the gate-TREE token, whose coverage claim ("the
gate-tree path rides the whole background call's argv, so the pattern is
exact-issue-scoped") was true only for the retired inline `bash -c` launcher.
Under the mandated #2115 script-file launcher (workload composed to
`/tmp/issue-<N>-lint-gate.sh`, launched as `bash '$LINT_GATE_SCRIPT'`), the
tree token appears in child argv only during the archive/tar and lint-leg
phases — during the minutes-long TG mapped-test legs and the normalize/verdict
tail NO live process carries it, so a probe-keyed wait false-fires
"probe CLEAR + verdict MISSING = died" on a HEALTHY mid-run gate (observed
live on issue-2249: false death read at ~15 min while pid 1222816 ran the TG
legs). A session following the completion-read verbatim would then
kill-before-relaunch a healthy gate — the #1606-class clobber the probe
exists to prevent. Fix: re-key every probe/completion-read/kill-arm pattern to
a token that rides a live argv for the workload's WHOLE life, fix the prose
coverage claim, add the subshell-argv explanatory note, and broaden the fleet
arbitration signature that shares the same gap.

## 2. Design decision — fix direction (a): re-key patterns to the workload script path

The task body offers two directions; this plan picks **(a)**.

**(b) as stated is technically unsound:** threading the gate-tree token into
the workload's argv via `env GATE_TREE=... bash '$SCRIPT'` does NOT put the
token in `/proc/<pid>/cmdline` — env assignments are consumed at exec and
never appear in argv. Making (b) work needs an inert positional argument
(`bash '$SCRIPT' /tmp/issue-<N>-lint-gate-tree`), a load-bearing-but-
meaningless launcher token every future editor must know not to drop, and it
leaves the completion-read/kill-arm patterns still tree-keyed (fragile).

**(a) uses a token that already necessarily rides argv for the workload's
whole life: the script path.** Pattern algebra for the unanchored regex
`issue-<N>-lint-gate`:

- `bash /tmp/issue-<N>-lint-gate.sh` — the detached workload pid, whole life
  (the #2115 launcher shape) → CONTINUOUS coverage, no CLEAR window.
- `/tmp/issue-<N>-lint-gate-tree/...` — tar/lint-leg children (the old token
  is a SUPERSTRING of the new one) → still matched.
- Legacy inline `bash -c` launches in flight at merge time (whole workload
  body as argv, containing the tree token) → still matched. No back-compat
  alternate needed.
- Exact-issue scoping is preserved: the `issue-<N>-` prefix keys the issue.

Surgical block (form iii): the workload is composed to
`/tmp/issue-<N>-surgical-gate.sh` (SKILL.md L14060/L14082), so its continuous
token is `issue-<N>-surgical-gate`; its lint legs share the
`issue-<N>-lint-gate-tree` tree, subsumed by `issue-<N>-lint-gate`. The
combined surgical pattern `issue-<N>-surgical-gate|issue-<N>-lint-gate`
covers the new-form whole-life pid, the tree-leg children, and legacy inline
launches (whose argv carried the tree token). The `issue-<N>-surgical-
outcome\.txt` alternate is DROPPED from the probe pattern: under the script
launcher no process ever carries ONLY that token (it lives inside the script
body, not argv), legacy argvs are covered via the tree token, and keeping it
only adds false-LIVE surface (e.g. a diagnostic `cat` of the sentinel from a
sibling shell).

## 5. Assumptions

- `bash /path/script.sh` exposes the script path in `/proc/<pid>/cmdline`
  for the process's whole life (standard Linux exec semantics; verified live
  on issue-2249's pid 1222816, which was found via the script path while the
  tree-keyed probe read CLEAR).
- Legacy inline gate launches still in flight at merge time carry the whole
  workload body (incl. the tree token) as argv — matched by the broadened
  pattern via superstring.
- No non-gate long-lived process legitimately carries `issue-<N>-lint-gate`
  in argv for the SAME issue: same-issue concurrency is excluded by the
  Step 0 single-orchestrator guard; residual transients (a sibling shell
  tailing this issue's gate log) read as loud fail-safe LIVE (wait), the
  documented fail-safe direction in the probe docstring.
