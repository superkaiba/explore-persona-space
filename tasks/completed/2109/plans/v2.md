## 3. Deliverables (file-by-file, concrete)

### D1 — `src/explore_persona_space/eval/utils.py` (the fix)

1. Insert **step 4** between the step-3 `if candidates:` return and the failure
   WARNING in `parse_judge_json`:
   - Compute the last non-empty line: `lines = text.strip().splitlines()`; candidate
     = `lines[-1].strip()` when `lines` is non-empty. ONE candidate only — never
     scan upward through earlier lines.
   - Accept iff `re.fullmatch(r"[0-9]{1,3}", candidate)` AND
     `0 <= int(candidate) <= 100`. ASCII digits ONLY (`[0-9]`, not `\d` — Python
     `\d` is Unicode-aware and would admit fullwidth/Arabic-Indic digit lines):
     no sign, no decimal point, no separators, no surrounding text on the line.
     (Leading zeros like `070` → 70 are accepted — no prose-capture risk.)
     "14TB disk 5" / "Score: 70" / "70." / "-5" / "150" all fail the anchor and
     fall through to the existing WARNING + `None`.
   - On acceptance: `logger.info(...)` with the fixed token
     `recovered-trailing-integer` (include value + `len(text)`), increment the
     recovery counter, and return `int(candidate)` (plain `int`).
2. Module-level counters + accessor for the recovery-rate report:
   `_PARSE_STATS = {"trailing_int_recovered": 0, "parse_failed": 0}` and
   `def parse_recovery_stats() -> dict[str, int]`. The existing failure WARNING
   branch increments `parse_failed`. Process-local; the per-run recovery rate is
   `trailing_int_recovered / (trailing_int_recovered + parse_failed)` and is also
   recoverable from logs by grepping the fixed token vs the failure WARNING.
3. Docstring: document step 4, its conservative anchor, the counter semantics, and
   the accepted residual: a `max_tokens`-truncated response ending mid-numbered-list
   ("…\n3") would recover as score 3 — the standing rule-23/26 stop_reason tally +
   pilot gates are the detection surface for truncation, and production waves are
   gated at ≈0 truncation. The failure WARNING itself is byte-unchanged (existing
   log-shape pins).

### D2 — `tests/test_eval_utils.py` (regression pins, new class `TestTrailingIntegerRecovery`)

Recovered (the #2091 shape):
- `"The response is sycophantic and endorses the user's plan.\n70"` → `70`, `type is int`
- trailing whitespace/newlines after the integer line → recovered
- CRLF line endings → recovered
- bare `"0"` and `"100"` trailing lines → recovered (range endpoints; falsy-valid 0)
- recovery emits NO failure WARNING and exactly one INFO with token
  `recovered-trailing-integer` (caplog)

Still drops (conservative anchor + drop-never-coerce):
- `"…prose…\n150"` → `None` (out of range)
- `"…prose…\n-5"` → `None` (sign disallowed)
- `"…prose…\n70.5"` and `"…prose…\n70."` → `None` (not exactly an integer)
- `"…prose…\nScore: 70"` → `None` (line not EXACTLY an integer)
- `"14TB disk 5"` → `None` (the task body's prose-numeral example)
- `"The score is 70 overall."` → `None` (numeral embedded in prose)
- a trailing fullwidth-digit line (e.g. `"７０"`) → `None` (ASCII-only anchor)
- each still-drop case still emits the existing failure WARNING (exactly one)

Precedence (strict-widening):
- `'blah {"a": 1}\n70'` → `{"a": 1}` (a decodable JSON anywhere in steps 1–3 always
  beats the trailing line; step 4 fires only on today's None-drops)
- `'```\n85\n```'` → `85` via the step-3 fence arm, unchanged
- existing pins (`"{ " * 5000` → None; `"{ " * 300 + '{"score": 85}'` → None;
  empty string → None; `"This text has no JSON at all."` → None) all pass UNMODIFIED
