## 0.0 TL;DR

Add a **step 4** to the `parse_judge_json` ladder (`src/explore_persona_space/eval/utils.py`):
when steps 1–3 ALL fail (the input that today logs the failure WARNING and returns
`None`), recover the **last non-empty line** of the text iff, after `strip()`, it is
EXACTLY a bare ASCII integer in [0,100] — return it as a plain `int` (identical type
to the step-1 bare-scalar passthrough). Everything that parses today is untouched by
construction (ladder position = structural bit-identity). Emit a per-recovery INFO
log line with a fixed greppable token + a module-level counter so the recovery rate
is measurable. Pin the new behavior and the non-capture cases with regression tests.

## 2. Background (incident being closed)

#2091's G2 judge pilot gate (`epm:progress` v35, 2026-08-10) root-caused elevated
drop rates to a parser ladder gap, not rubric/truncation/refusal: 5 re-issued draws
showed bare `0` → scored (step 1), prose+`{"score": 5}` → scored (step 2/3),
prose+`{"score": 75}` → scored, but prose ending in a bare `70` line → **dropped**
(×2). Banked drop rates attributable to this shape: evil trait rungs 28.27% of
53,330 draws; wildchat/hallucination 8.30% of 10,000; wildchat/sycophancy 2.28%;
wildchat/evil 1.78%; sycophancy trait rungs 0.43%.

Load-bearing prior contracts (all preserved):

- **#1024** — `parse_judge_json` takes exactly ONE parameter; failure returns `None`
  (no coercion affordance); failure WARNING carries forensic head.
- **#778 r3** — bare-scalar passthrough: whole-text `"70"` already returns `int` 70.
  Consequence: **every caller already tolerates an `int` return today** — step 4
  introduces no new return type to any call site (the clarifier swept
  `graded_judge.py`, `judge_dispatch.py`, `alignment.py`, `batch_judge.py`,
  `refusal.py`, `experiments/issue503/judges.py`, `scripts/issue763_extract_pv_rb.py`;
  dict-expecting callers route non-dicts to their existing drop path).
- **#1934** — steps 1–3 precedence is pinned by `tests/test_eval_utils.py`
  (`TestParseJudgeJsonRecoveryLadder`); step 4 sits strictly BELOW the step-3 pool.
- **#1434** — `judge_dispatch._normalize_scalar_score` wraps a bare in-range numeric
  into `{"score": N}`, so the persisted cache file shape (13-byte `{"score": N}`)
  is unchanged for recovered draws.
- **llm-judging rule 9 (drop-never-coerce)** — REFUSAL, non-numeric, out-of-[0,100]
  still drop; step 4 recovers only a value the judge actually emitted, never a default.

## 3. Deliverables (file-by-file, concrete)

### D1 — `src/explore_persona_space/eval/utils.py` (the fix)

1. Insert **step 4** between the step-3 `if candidates:` return and the failure
   WARNING in `parse_judge_json`:
   - Compute the last non-empty line: `lines = text.strip().splitlines()`; candidate
     = `lines[-1].strip()` when `lines` is non-empty. ONE candidate only — never
     scan upward through earlier lines.
   - Accept iff `re.fullmatch(r"\d{1,3}", candidate)` AND `0 <= int(candidate) <= 100`.
     ASCII digits only: no sign, no decimal point, no separators, no surrounding
     text on the line. (Leading zeros like `070` → 70 are accepted — they carry no
     prose-capture risk.) "14TB disk 5" / "Score: 70" / "70." / "-5" / "150" all
     fail the anchor and fall through to the existing WARNING + `None`.
   - On acceptance: `logger.info(...)` with the fixed token
     `recovered-trailing-integer` (include value + `len(text)`), increment the
     recovery counter, and return `int(candidate)` (plain `int`).
2. Module-level counters + accessor for the recovery-rate report:
   `_PARSE_STATS = {"trailing_int_recovered": 0, "parse_failed": 0}` and
   `def parse_recovery_stats() -> dict[str, int]`. The existing failure WARNING
   branch increments `parse_failed`. Process-local; the per-run recovery rate is
   `trailing_int_recovered / (trailing_int_recovered + parse_failed)` and is also
   recoverable from logs by grepping the fixed token vs the failure WARNING.
3. Docstring: document step 4, its conservative anchor, and the counter semantics.
   The failure WARNING itself is byte-unchanged (existing log-shape pins).

NOT in scope: `graded_judge.py` / `judge_dispatch.py` are untouched — a recovered
`int` flows through the existing bare-numeric branches (`_score_from_parsed`,
`_normalize_scalar_score`) exactly as a step-1 bare scalar does today.

### D2 — `tests/test_eval_utils.py` (regression pins, new class `TestTrailingIntegerRecovery`)

Recovered (the #2091 shape):
- `"The response is sycophantic and endorses the user's plan.\n70"` → `70`, `type is int`
- trailing whitespace/newlines after the integer line → recovered
- CRLF line endings → recovered
- bare `"0"` and `"100"` trailing lines → recovered (range endpoints; falsy-valid 0)
- recovery emits NO failure WARNING and exactly one INFO with token
  `recovered-trailing-integer` (caplog)

Still drops (conservative anchor + drop-never-coerce):
- `"…prose…\n150"` → `None` (out of range)
- `"…prose…\n-5"` → `None` (sign disallowed)
- `"…prose…\n70.5"` and `"…prose…\n70."` → `None` (not exactly an integer)
- `"…prose…\nScore: 70"` → `None` (line not EXACTLY an integer)
- `"14TB disk 5"` → `None` (the task body's prose-numeral example: last line is not
  a bare integer)
- `"The score is 70 overall."` → `None` (numeral embedded in prose)
- each still-drop case still emits the existing failure WARNING (exactly one)

Precedence (strict-widening):
- `'blah {"a": 1}\n70'` → `{"a": 1}` (a decodable JSON anywhere in steps 1–3 always
  beats the trailing line; step 4 fires only on today's None-drops)
- `'```\n85\n```'` → `85` via the step-3 fence arm, unchanged
- existing pins (`"{ " * 5000` → None; `"{ " * 300 + '{"score": 85}'` → None;
  empty string → None; `"This text has no JSON at all."` → None) all pass UNMODIFIED

## 4. Bit-identical argument (constraint 2)

Step 4 executes only on inputs where steps 1–3 produced no candidate — the exact
set that today returns `None`. No branch upstream of the step-3 return is edited.
Therefore every input that currently parses returns the identical value (structural
guarantee), pinned mechanically by running the ENTIRE existing
`tests/test_eval_utils.py` suite unmodified. Any existing pin requiring modification
to pass = constraint violation = kill criterion.

## 5. Cross-arm comparability (task-body warning)

Banked judge caches store only parsed results (13-byte `{"score": N}` files, no raw
text) — banked arms CANNOT be re-parsed, so this fix changes the instrument for
FRESH judging only. Handling: land default-on with NO feature flag (flag-gating an
instrument fix creates silent bimodality across the fleet); the fixed INFO token
makes the parser version observable in any run's logs; at merge (Step 10d) post
advisory `epm:progress` notes on live judge-running tasks (#2203 off-pod judge
round; #2220/#2221/#2224/#2225) naming the instrument change, and note that
fresh-vs-banked drop-rate comparisons straddling the merge use different parsers.
#2091/#1739 (awaiting_promotion, measurements complete under the old parser) need
no action — their bodies already carry the drop-rate caveat.
