# Plan v1 — Audit #535 SLURM lane events.jsonl for token-shaped strings

## Goal / Requirement

Scan task #535's `events.jsonl` for token-shaped strings introduced by the pre-fix6 sbatch-preflight `set -x` echo path. If any tokens leaked into a committed event marker, surface them so Thomas can rotate the corresponding secret.

## Acceptance criteria

1. **Audit scope.** `tasks/completed/535/events.jsonl` is the SOLE input. Scope is the full file as committed on `main` at this commit (136 events, latest event timestamp 2026-06-10T22:59:24Z, `epm:done v1`).
2. **Token patterns scanned (regex).** Defense-in-depth covers every secret class in `.env`, anchored to the actual key shapes (NOT the bare 40-hex-char wandb shape, which collides with every git SHA and event hash on the planet — anchor wandb hits to the `WANDB_API_KEY` or `wandb login` context lines):
   - HF tokens: `hf_[A-Za-z0-9]{30,}` (HF tokens are `hf_` + 34 base62 chars; `{30,}` is the conservative floor).
   - WandB API keys: `[A-Fa-f0-9]{40}` ONLY when on a line that ALSO matches `WANDB_API_KEY` / `wandb login` / `wandb_key` / `wandb_token` (case-insensitive). Standalone 40-hex strings are NOT flagged — they are every git/event SHA in the file and would yield ~100% false positives.
   - RunPod: `rpa_[A-Za-z0-9_]{30,}` (RunPod keys are `rpa_` + ~38 chars).
   - OpenAI: `sk-[A-Za-z0-9_-]{30,}` (covers both legacy `sk-...` and `sk-proj-...`; the `sk-ant-` prefix is broken out separately below).
   - Anthropic: `sk-ant-[A-Za-z0-9_-]{30,}` (matched FIRST so OpenAI's `sk-` pattern doesn't double-count).
   - The literal env-var assignment shape: any of `HF_TOKEN=`, `HF_HUB_TOKEN=`, `WANDB_API_KEY=`, `RUNPOD_API_KEY=`, `ANTHROPIC_API_KEY=`, `OPENAI_API_KEY=` followed by anything non-empty and non-`***SCRUBBED***` and non-`<redacted>`. Catches a leaked key that doesn't match the shape regex (token format drift) AND distinguishes a true leak from a successful scrub.
3. **Match enumeration.** For every hit: report the matching key class, the surrounding event's `ts` + `kind` + `version` + first 200 chars of `note`, and the offending byte offset / line number in the JSONL file. If a single event matches multiple key classes, list it once per class.
4. **Verdict.** Top-line `PASS` (no hits across any pattern) OR `FAIL` (one or more hits) named per affected key class, e.g. `FAIL — leaked: hf, wandb`. On FAIL, the report MUST list the EXACT rotation steps Thomas needs to take per leaked key.
5. **Output landing.** The analyzer posts the report as `epm:interpretation v1` on this task (#581). The marker note carries the full report under the 50K-char cap; if it would exceed, write the body to `tasks/<status>/581/artifacts/audit-report.md` and reference it from the marker.
6. **No false positives in PASS.** The PASS verdict requires zero hits across ALL patterns. A single uncertain candidate is reported as a hit (conservative side; rotation cost is bounded and a missed leak is unrecoverable).

## Method

The audit is a single-shot Python scan (no LLM in the loop, no pod, no model, no eval). Two phases:

**Phase 1 — pattern scan.** `uv run python scripts/issue581_audit.py` (to be written) iterates events.jsonl row by row, applies the six regex patterns to each row's serialized JSON form (so matches inside `note`, `metadata`, and any other field are caught uniformly), and emits a JSON list of hits to `tasks/<status>/581/artifacts/audit-hits.json`.

**Phase 2 — report compose.** The same script also emits a human-readable markdown report to `tasks/<status>/581/artifacts/audit-report.md` and the orchestrator posts a summary as `epm:interpretation v1`.

Single script. Both phases run in one invocation. No subprocess fan-out, no parallelism.
