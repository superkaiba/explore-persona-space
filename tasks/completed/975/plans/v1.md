## 0.0 TL;DR (plain English)

- **What I'll change:** the poller's #899 rescue path — the one that saves a results file a pod wrote without the standard wrapper — currently stamps every rescued result as "version 1". ## 4. Design (method delta)

### The design decision: omitted key, key-presence branch (Design B)

Two candidate discriminators for "this envelope wants a derived version":

- **(A) `"version": None` explicit** + drain uses `data.get("version")`, treating `None` as derive. Self-documenting, keeps all 3 required keys present. **Rejected** because it changes behavior for a real sentinel that (buggily) carries `"version": null`: today that crashes the whole drain tick with `int(None)` TypeError; under (A) it would silently derive. The task's kill criterion (§7) bars ANY behavior change for real enveloped sentinels.
- **(B) omit the `"version"` key** from the synthesized dict + drain branches on key PRESENCE. Airtight under the kill criterion: `_parse_sentinel` requires the `"version"` KEY for every real sentinel (:1813, `k not in data`), so a key-absent dict at the drain is producible ONLY by the synthesized-envelope fallback. Every real sentinel — including the pathological `"version": null` one — takes the `int(data["version"])` branch byte-identically (the latent `int(None)` TypeError for a null-version writer is left untouched, not endorsed; it is out of scope and pre-existing). **Chosen.**

Interaction set analysis (the (a)–(f) items from the task):

- **(a) drain `version = int(data["version"])` (:1882):** becomes the key-presence branch below. `version: int | None` is threaded to `post_event(issue, kind, version=version, ...)` at :1890 unchanged in form — `post_event` already accepts `None` and derives.
- **(b) `_persist_oversize_note`:** signature widens to `version: int | None`. Behavior with `None`: the pointer post at :1756 passes `version=None` → `post_event` derives max+1 fresh. This is CORRECT, verified against the actual ordering: the oversize `ValueError` raises at task_workflow.py:2446, before the `_locked()` block and before `_next_event_version` runs at :2453 — the failed first post consumed no version, so the pointer post derives exactly the version the original would have gotten. The header line (:1735) renders the None case legibly (see diff). The docstring phrase "same ``(kind, version)``" (:1668) gains a parenthetical for the derived case.
- **(c) ordering trap:** none. The synthesized dict is returned from `_parse_sentinel` at :1817 without re-validation — it bypasses both the `_SENTINEL_REQUIRED_KEYS` check (:1813, already passed/failed on the RAW data before the fallback fires) and the schema-version check (:1820). The fallback's zero-envelope-keys predicate (:869) checks the RAW data, not the synthesized dict, so omitting `"version"` from the OUTPUT cannot feed back into the predicate. An inline comment in the synthesized dict guards the future-refactor risk (a re-validation of the synthesized dict would fail on the absent key).
- **(d) log.error (:881-887):** reworded — must keep the `%s` interpolations for `remote_path` and `missing` (the test at tests/test_poll_pipeline_sentinels.py:225-232 asserts the path and all three envelope key names appear in the single ERROR).
- **(e) `_parse_sentinel` docstring (:1794-1800):** reworded.
- **(f) grep for sibling hardcoded version literals:** done at plan time. `grep -n '"version"' scripts/poll_pipeline.py` → :276 (module docstring — the POD-SIDE writer schema, where an explicit integer version IS the contract per `.claude/rules/pod-side-reporting.md`; no change), :823 (`_SENTINEL_REQUIRED_KEYS`; no change), :883/:893 (the targets), :1797 (docstring target), :1882 (the drain read, target). `grep -rn 'version.*1' scripts/backend_poll.py` → only "POLLER synthesizes phase" comments, no version literals. gcp.py delegates to `drain_sentinels_via` (covered); slurm_monitor.py drains nothing (contract). ## 11. Decision Rationale

- **Omitted key vs `"version": None` explicit.** *What:* the synthesized envelope omits `"version"` entirely; the drain branches on key presence. *Why:* key absence is unforgeable for real sentinels (`_parse_sentinel` :1813 requires the key), so the derive branch cannot fire on any real sentinel — the strictest reading of the kill criterion. *Source:* verified code (`_SENTINEL_REQUIRED_KEYS` :820-824; :1813-1817) + incident #480 (the max+1 contract in `post_event`'s docstring, task_workflow.py:2435-2441). *Alternatives:* `"version": None` explicit (rejected — silently changes the null-version real-sentinel case from crash to derive, violating the kill criterion); a `by == "pod-sentinel-envelope-fallback"` string check (rejected — string-typed provenance is spoofable by a real writer and couples the drain to a display field).
- **Drain-side `version=None` threading vs helper-side `max+1` computation.** *What:* pass `None` to `post_event` and let the library derive under its flock. *Why:* the derivation at task_workflow.py:2453-2454 runs inside `_locked()` — a drain-side `max(list_events())+1` would race concurrent posters and duplicate the very logic #480 centralized; the task Goal names this option explicitly. *Source:* `post_event` docstring (task_workflow.py:2435-2441, citing #480); #917 (prose surfaces already defer to max+1). *Alternatives:* compute max+1 in `_maybe_synthesize_results_envelope` via `task_workflow.list_events` (rejected as primary — unlocked read-then-post race, extra events.jsonl read per rescue; retained as the §7.3 fallback only if the oversize-ordering fact were wrong — it is not, verified).
- **`_persist_oversize_note` accepts `None` rather than requiring the caller to pre-resolve.** *What:* widen the signature; `post_event(version=None)` at the pointer post derives fresh. *Why:* the oversize `ValueError` (task_workflow.py:2446) fires before derivation (:2453), so the failed first post consumed nothing — the pointer post derives exactly the version the original would have; pre-resolving drain-side would reintroduce the unlocked race. *Source:* read from code (ordering verified §2); incident #477 (the oversize degradation contract). *Alternatives:* resolve max+1 before calling the helper (rejected — race + duplicated logic).
