## 0.0 TL;DR (plain English)

- **What I'll do:** make `spawn_session.py stop` (operator stops only) finish the job — after the daemon confirms the session is gone, it removes that session's own crash-recovery registration file and releases the dispatch lease its own launch minted, so an immediate respawn works first try.
- **What I expect:** the #1090-style stop→respawn dance (manual unregister + two lease clears + 3 spawn attempts) becomes one `stop` + one `spawn-issue --auto`, with zero manual state surgery — while every watcher-driven stop keeps its state exactly as today (the watcher's respawn machinery depends on it).
- **What would change my mind:** if the watcher's boot-death / dead-wake / stalled respawn lanes ever stop resurrecting a session after this lands (they must not — cleanup is gated to operator stops), or if a fresh in-flight respawn's lease gets deleted by a stop (the ownership keying must make that impossible).

## 1. Goal / requirement + acceptance criteria

"Make deliberate stop-then-respawn a one-shot operation." (Task #1455 Goal, verbatim; re-read from `tasks/planning/1455/body.md` at plan-return time.)

`scripts/spawn_session.py cmd_stop` (L2588) posts the deliberate-stop breadcrumb + the daemon `/stop-session` RPC but leaves TWO pieces of dispatch state behind: the crash-recovery registration (`~/.eps-autonomous/issue-<N>.json` / `manual-issue-<N>.json`) and the per-issue dispatch lease (`dispatch-lease-<N>.json`, TTL 900s = `DISPATCH_LEASE_TTL_S`, L107). The stale registration makes the operator's replacement spawn raise `RegistrationCollisionError` (collision window = `min(ttl, 900s)`, L561-577) and stop itself — which then HOLDS a second lease (the deliberate collision-branch behavior, L1851-1853 comment) — compounding into the 2026-07-16 incident: manual unregister + two lease clears + 3 spawn attempts.

**Acceptance criteria (each pinned by a named test in §4):**

1. **Operator one-shot:** after `stop --session-id <sid>` (default `--stop-source operator`) succeeds and the sid leaves the daemon's live list, the sid-matched registration file(s) for that session are removed and the dispatch lease is released iff it was minted by the stopped session's own dispatch (`lease.acquired_at <= registration.spawned_at`). An immediate `spawn-issue --auto --issue N` then proceeds with no `DISPATCH-LEASE HELD` and no `REGISTRATION-COLLISION`.
2. **Watcher stops untouched:** `--stop-source watcher` performs ZERO cleanup — registration and lease state after the stop are byte-identical to today. (The watcher's boot-death, dead-wake, and crash-recovery respawn arms REQUIRE the registration to survive its own stops — see §11.)
3. **Never someone else's state:** stopping session A never removes a registration recording session B's sid, and never removes a lease acquired AFTER A's registration was written (a successor dispatch mid-flight).
4. **Fail-soft:** any cleanup failure (missing files, unreadable JSON, daemon list failure, flock contention) WARNs on stderr and never changes `cmd_stop`'s exit behavior — the stop itself already succeeded.
5. **Dead-confirm precondition:** cleanup fires only once the session is confirmed gone (absent from the daemon live list within a bounded poll, or — on the `_stop_fallback --kill` path — `_pid_alive(pid)` false). On poll timeout, cleanup is SKIPPED with a WARN naming the manual follow-up (`unregister --session-id <sid>`).
6. **Escape hatch:** `stop --no-cleanup` restores today's operator behavior verbatim (stop, leave state, let the watcher's crash-recovery resurrect).

## 2. Method delta (vs current behavior and vs #1327)

- **vs current `cmd_stop`:** today the stop ends at the RPC (or the `_stop_fallback` kill). New: after a CONFIRMED-dead operator stop, run a cleanup step. Nothing changes for watcher-sourced stops, RPC-failure paths that end in `sys.exit`, or the report-only (no `--kill`) fallback branches.
- **vs #1327 (`unregister`, commit 513454a03f):** #1327 added the MANUAL sid-matched inverse of `register-current`. This task (a) wires #1327's tested internals (`unregister_paths`, L2253 — sid-match-guarded, fail-toward-keep, scan mode) into the stop path automatically, and (b) adds the half #1327 deliberately never touched: the dispatch lease (`unregister` "never touches ... non-registration siblings: dispatch-lease-*" — that contract stays intact; the lease is released by a NEW sibling helper, not by widening `unregister_paths`).
- **vs `release_dispatch_lease` (L359):** the existing release is token-verified, and `cmd_stop` never holds the acquirer's token (the token lives only in the lease entry written at L317-323 by the `spawn-issue --auto` process, L1827). New helper keys ownership differently: under the SAME permanent flock sidecar (`_dispatch_lease_lock_path`, L237), release iff `lease.acquired_at <= reg.spawned_at` of the just-removed sid-matched AUTO registration — valid because the single acquire site (L1827) runs strictly BEFORE `_register_autonomous_session` writes `spawned_at` (L540) in the same dispatch, so the stopped session's own lease always satisfies it and any successor's lease (acquired after that registration existed) never does.

```python
def release_dispatch_lease_for_stopped_dispatch(issue: int, reg_spawned_at: float) -> str:
    """Ownership-keyed unlink of the per-issue dispatch lease on a deliberate
    operator stop (#1455), serialized under the SAME permanent flock sidecar
    as acquire/release so it can never race a takeover. cmd_stop does not
    hold the acquirer's token, so ownership is keyed on dispatch ordering
    instead: the stopped session's own lease was acquired BEFORE its
    registration was written (acquire L1827 -> register L540, same process),
    so `acquired_at <= reg_spawned_at` identifies it; a successor dispatch's
    lease (acquired after that registration existed) is always NEWER and is
    KEPT. Returns an action string for logging/tests:
    released | missing | kept-successor | kept-garbled | kept-contended | kept-oserror.
    Fail toward keep everywhere (the TTL owns a kept lease)."""
    try:
        lock_fd = os.open(_dispatch_lease_lock_path(issue), os.O_CREAT | os.O_WRONLY, 0o644)
    except OSError:
        return "kept-oserror"
    try:
        try:
            fcntl.flock(lock_fd, fcntl.LOCK_EX | fcntl.LOCK_NB)
        except OSError:
            return "kept-contended"      # a takeover is in flight; TTL owns it
        entry = read_dispatch_lease(issue)
        if entry is None:
            return "missing"
        acquired = entry.get("acquired_at") if isinstance(entry, dict) else None
        if not isinstance(acquired, int | float) or isinstance(acquired, bool):
            return "kept-garbled"        # unreadable ownership -> keep; TTL owns it
        if acquired > reg_spawned_at:
            return "kept-successor"      # minted AFTER the stopped session registered
        dispatch_lease_path(issue).unlink(missing_ok=True)
        return "released"
    finally:
        os.close(lock_fd)
```

```python
def _deliberate_stop_cleanup(sid: str) -> None:
    """Operator-stop one-shot cleanup (#1455): sid-matched registration
    removal (reuses unregister_paths, the #1327 internals) + ownership-keyed
    dispatch-lease release for AUTO registrations only (manual/campaign
    spawns never mint a lease — the single acquire site is the --auto branch,
    L1820-1827). Prints one line per action. Callers wrap in the fail-soft
    _post_stop_cleanup; this function itself may raise."""
    # 1. Capture spawned_at per sid-matched AUTO registration BEFORE removal.
    auto_spawned_at: dict[int, float] = {}
    if AUTONOMOUS_REGISTRY_DIR.is_dir():
        for path in AUTONOMOUS_REGISTRY_DIR.glob("issue-*.json"):
            m = _REGISTRATION_NAME_RE.match(path.name)
            if not m or m.group(1) != "issue":
                continue  # excludes manual-issue-*.json (glob can't, the RE does)
            try:
                entry = json.loads(path.read_text())
            except (OSError, ValueError):
                continue
            if isinstance(entry, dict) and entry.get("happy_session_id") == sid:
                ts = entry.get("spawned_at")
                if isinstance(ts, int | float) and not isinstance(ts, bool):
                    auto_spawned_at[int(m.group(2))] = float(ts)
    # 2. Sid-matched removal across all three kinds (the #1327 guarded path;
    #    scan mode: issue=None). Guards: mismatched sid kept, garbled kept.
    rows = unregister_paths(issue=None, session_id=sid)
    for action, path, detail in rows:
        print(f"  cleanup: {action.upper():<18} {path}" + (f" ({detail})" if detail else ""))
    # 3. Lease release ONLY for issues whose AUTO registration was actually
    #    REMOVED in step 2 (removal proves the stopped session was the
    #    registered owner) and whose spawned_at was readable in step 1.
    for action, path, _detail in rows:
        if action != "removed":
            continue
        m = _REGISTRATION_NAME_RE.match(path.name)
        if not m or m.group(1) != "issue":
            continue  # manual/campaign registration: no lease to release
        issue = int(m.group(2))
        ts = auto_spawned_at.get(issue)
        if ts is None:
            print(
                f"  cleanup: KEPT-LEASE issue #{issue} (registration removed but "
                f"spawned_at was unreadable at capture; TTL owns the lease)",
                file=sys.stderr,
            )
            continue
        print(f"  cleanup: dispatch-lease #{issue}: "
              f"{release_dispatch_lease_for_stopped_dispatch(issue, ts)}")
```

```python
def _await_session_dead(sid: str, deadline_s: float = STOP_CLEANUP_DEAD_POLL_S) -> bool:
    """Bounded poll of the daemon live list until ``sid`` is absent. True =
    confirmed gone; False = still listed at the deadline (caller skips
    cleanup — the #845 'a stop ACK is not a kill' posture)."""
    deadline = time.time() + deadline_s
    while True:
        if sid not in _live_session_ids():
            return True
        if time.time() >= deadline:
            return False
        time.sleep(STOP_CLEANUP_DEAD_POLL_INTERVAL_S)


def _post_stop_cleanup(sid: str) -> None:
    """Fail-soft wrapper around dead-confirm + cleanup. NEVER raises and
    never alters cmd_stop's exit behavior — the stop already succeeded;
    cleanup is best-effort hygiene (mirrors the breadcrumb fail-soft
    posture at L2604-2642)."""
    try:
        if not _await_session_dead(sid):
            print(
                f"WARN: session {sid} still live per the daemon after "
                f"{STOP_CLEANUP_DEAD_POLL_S:g}s; skipping registration/lease cleanup — "
                f"once it is dead run: spawn_session.py unregister --session-id {sid}",
                file=sys.stderr,
            )
            return
        _deliberate_stop_cleanup(sid)
    except Exception as exc:
        print(
            f"WARN: post-stop cleanup failed: {exc!r} — the stop itself succeeded; "
            f"clean up manually: spawn_session.py unregister --session-id {sid}",
            file=sys.stderr,
        )
```

### 3.5 When cleanup fires (the decision table)

| Path | Cleanup? | Why |
|---|---|---|
| `stop` RPC success, `--stop-source operator` (default), sid confirmed gone | YES | The one-shot Goal case. |
| `stop` RPC success, operator, sid STILL in live list after 15s poll | NO (WARN + manual command) | "Confirmed dead" precondition; fail toward keep. |
| `stop --stop-source watcher` (any outcome) | NEVER | The watcher's boot-death lane is STOP-ONLY by design — "post-stop re-drive is fully owned by the existing arms (ACTIVE → crash-recovery)" — and the dead-wake trigger's respawn is likewise completed by the crash-recovery arm reading the SURVIVING `issue-<N>.json`; the stalled fence clears itself when the registry entry no longer matches its pending sid. Deleting the registration on watcher stops would break all three respawn designs (§11). |
| `stop --no-cleanup` (operator) | NO | Explicit escape hatch = today's behavior (deliberate "stop and let the watcher resurrect"). |
| `_stop_fallback`, `--kill`, SIGTERM confirmed dead, operator | YES | Process confirmed dead via `_pid_alive`. |
| `_stop_fallback` report-only / refusal / survivor branches | NEVER | Process not confirmed dead; all end in `sys.exit` as today. |
| `eps_sessions.py stop --issue N` (delegates with `stop_source="operator"`) | YES (inherited) | It IS the operator per-issue stop; `getattr` defaults keep its bare Namespace working. |
| Internal `_stop_spawned_session` (L1648) / `_stop_session_raw` (L1662) call sites — spawn-failure stops (L1943, L1969), collision-yield stop (L2116), webhook-timeout reap (L1254, L1263) | UNCHANGED, no cleanup | These stop a JUST-spawned session that either never registered (collision raised before overwrite) or whose failure path already releases the lease token-verified (L1848-1853); the collision branch must HOLD its lease (L364-370 docstring) — wiring cleanup here would reverse that deliberate design. |
| `pod_lifecycle.py` L915 / watcher message strings naming `spawn_session.py stop` | N/A | Comments / operator-recipe strings, not call sites (grep-verified §10). |

### 3.6 Failure-mode behavior (fail-soft, enumerated)

Cleanup can never block or fail the stop: `_post_stop_cleanup` catches ALL exceptions → WARN naming the manual fallback. Within it, every sub-step fails toward KEEP: missing registry dir → no-op; garbled registration → `unregister_paths` keeps it (existing #1327 guard); sid mismatch → kept; missing lease → "missing"; garbled lease `acquired_at` → kept (TTL owns it); flock contended (takeover mid-flight) → kept; daemon list unreachable during the poll → `_live_session_ids` returns an empty set (L1372-1377) → poll reads "gone" → cleanup proceeds (accepted residual: the daemon ACKed the stop milliseconds earlier, so it is committed to terminating the session — §6 R5). This is a deliberate, documented exception to fail-fast: the crash-IS-the-signal rule governs experiment code; here a cleanup crash after a successful stop would strand the operator in a WORSE state than today's, and the WARN + manual command keep the failure loud and diagnosable.

## 6. Risks / failure modes + fallbacks

| # | Risk | Likelihood | Mitigation / fallback |
|---|---|---|---|
| R1 | Operator stop races the watcher mid-respawn: watcher just spawned B and re-registered while we stop A | Low | Sid-matched removal keeps B's fresh registration (records B's sid); the watcher's fresh lease has `acquired_at >` A's `spawned_at` → `kept-successor`. ## 11. Decision Rationale

- **Stop-source gating (operator-only cleanup).** *What:* cleanup fires only for `--stop-source operator`. *Why:* three watcher lanes are DESIGNED around the registration surviving their own stops — the boot-death lane (stop-only; crash-recovery re-drives via the surviving `issue-<N>.json`), the #1209 dead-wake trigger (stop at initiation, respawn completed by the crash-recovery arm), and the stalled fence (clears itself if the registry entry stops matching its pending sid — a deleted entry would kill the fence's spawn). Deleting registration state on watcher stops would convert ~20-30 min respawns into ~90 min orphan-sweep re-drives or outright misses. *Source:* code read (`_stop_session` L10423-10460; `_register_autonomous_session` docstring L506-533) + `.claude/rules/background-automation.md` watcher spec; gating precedent: the #902 breadcrumb uses the identical operator/watcher split at L2603. *Alternatives rejected:* cleanup for both sources (breaks the three lanes); a separate `--cleanup` opt-in flag (the incident IS the default operator flow — opt-in would leave the default broken; `--no-cleanup` preserves the old semantics for the rarer "let the watcher resurrect it" intent).
- **Lease-release keying (`acquired_at <= reg.spawned_at` of the removed sid-matched AUTO registration, under the permanent flock).** *What:* release only the lease provably minted by the stopped session's own dispatch. *Why:* `cmd_stop` never holds the acquirer's token (it lives only in the lease file + the dispatcher process, L317-323), so token-verified release (L359) is unusable; the dispatch ordering acquire→POST→register (A4) makes `acquired_at < spawned_at` a sound ownership witness — every successor's lease is strictly newer and is KEPT, so a mid-flight re-dispatch can never be orphaned by a stop. Registration-removal-first also proves the stopped session WAS the registered owner (a sid-mismatch stop releases nothing). The flock reuse means no new locking protocol — the same sidecar that already serializes takeover vs release (L306-315, 359-384). *Source:* #843 M1 code read + the release docstring's successor-safety contract (L360-362). *Alternatives rejected:* store the lease token in the registration entry (a schema change to `issue-<N>.json` consumed by the watcher — wider blast radius for no added safety); unconditional lease unlink after unregister (removes a live successor's lease → duplicate-dispatch churn); holder-string matching (`holder=f"spawn-issue --auto pid=..."` identifies the DISPATCHER process, not the session — useless for stop-side ownership).
- **Dead-process precondition (bounded daemon-list poll; `_pid_alive` on the kill path).** *What:* cleanup only after the sid leaves the daemon live list (≤15s poll) or the SIGTERM'd pid is confirmed dead. *Why:* "the daemon's stop ACK is not a kill" is the standing #845(a-ii) posture — removing crash-recovery state for a still-live session would create an unregistered live driver invisible to the Step 0 guard; on timeout we fail toward keep (today's behavior + a WARN naming the manual command). 15s is generous for a daemon delist yet short enough for interactive stop→respawn. *Source:* #845 fence spec (background-automation.md) + task body's "with the process confirmed dead". *Alternatives rejected:* cleanup immediately on ACK (violates the confirmed-dead requirement); a next-invocation deferred cleanup (adds state + defeats the one-shot Goal).
- **Reuse `unregister_paths` rather than new removal code.** *What:* the registration half is exactly #1327's guarded helper in scan mode. *Why:* its sid-match / fail-toward-keep / atomic-unlink semantics are already reviewed + pinned by `tests/test_spawn_session_unregister.py`; duplicating them would rot. *Source:* #1327 (commit 513454a03f) + the CLAUDE.md reuse-existing-tools rule. *Alternative rejected:* extending `unregister_paths` to also handle leases (breaks its documented "never touches dispatch-lease-*" contract and the `unregister` CLI's semantics).
- **Fail-soft cleanup.** *What:* cleanup failure WARNs, never alters exit behavior. *Why:* the stop already succeeded; failing it retroactively would leave the operator unsure whether the session is down — strictly worse. Mirrors the in-function precedent (breadcrumb fail-soft, L2604-2642). *Source:* code read + task brief requirement. *Alternative rejected:* fail-loud (wrong failure domain — hygiene, not the primary action).
