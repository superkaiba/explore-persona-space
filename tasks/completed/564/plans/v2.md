# Plan — Task #564: Proactive HF public-storage headroom check (preflight WARN + pre-train persist gate + opt-in overflow routing)

## 0.0 TL;DR (plain English)

- **What I'll build:** a small library helper that asks HuggingFace "how much public storage is this account using?", caches the answer for an hour, and threads it into three places — the preflight report (warning only), the start of any training run that promised to upload its adapter (hard stop in minute 1 if the upload is already doomed), and an opt-in switch that redirects big uploads to the private overflow repo instead of letting them 403.
- **What I expect:** the next time the account creeps toward the storage wall, every session sees a loud warning days in advance, and no persist-declared sweep that is ALREADY over the soft ceiling at start trains for 10 hours only to die at its final upload (a run that crosses the ceiling mid-run still fails loudly at upload time — the minute-1 gate reads headroom at start only).
- **What would change my mind:** if the HF API stopped reporting per-repo storage usage — then the whole read-usage approach needs a different probe (see Kill criteria).

## 1. Goal

Convert the account-wide HF public-storage quota failure from a reactive, mid-run catastrophe (incident 2026-06-10, #541/#552: 11.3 TB across 414 repos, every in-flight task's LFS upload 403'd at once, 3-4 tasks parked) into a proactive signal with three escalating responses: a non-fatal preflight WARN at a configurable soft ceiling, a minute-1 fail-loud abort for sweeps that have declared their adapter upload load-bearing (`EPM_PERSIST_ADAPTER_HF_REPO`), and an opt-in automatic reroute of large-LFS uploads to the private overflow repo (which has separate quota headroom, validated in #541). Detection and routing only — quota-freeing/deletion stays user-only per the task body.

## 4. Design

### 4.1 Helper — `orchestrate/hub.py` (AC1)

New constants + dataclass + function, placed after `merged_upload_enabled` (~:56):

```python
DEFAULT_OVERFLOW_REPO = "superkaiba1/explore-persona-space-overflow"   # private; separate LFS quota (#541)
DEFAULT_HF_NAMESPACE = DEFAULT_MODEL_REPO.split("/")[0]                # "superkaiba1"
DEFAULT_STORAGE_SOFT_CEILING_TB = 10.0    # observed wall: 11.3 TB at 100% public quota (#541)
DEFAULT_STORAGE_CACHE_TTL_S = 3600.0      # AC1: "~1h"
_BYTES_PER_TB = 1000.0**4                 # HF reports decimal TB; match the incident's 11.3 TB read

@dataclass(frozen=True)
class HfStorageHeadroom:
    used_tb: float | None     # None => unknown (API error / check disabled)
    ceiling_tb: float
    over_ceiling: bool        # False whenever used_tb is None
    basis: str                # "live-api" | "cache (age 123s)" | "disabled" | "unknown (<err>)"
    n_repos: int = 0

def check_hf_storage_headroom(
    *,
    namespace: str = DEFAULT_HF_NAMESPACE,
    ceiling_tb: float | None = None,        # None -> env -> default
    cache_ttl_s: float | None = None,       # None -> env -> 3600
    cache_path: Path | None = None,         # None -> env -> ~/.cache/explore_persona_space/hf_storage_usage.json
    force_refresh: bool = False,
) -> HfStorageHeadroom:
```

Behavior:

1. **Kill switch:** `EPM_HF_STORAGE_CHECK=0` → return `(used_tb=None, over_ceiling=False, basis="disabled")` immediately, no I/O.
2. **Ceiling resolution:** param → `EPM_HF_STORAGE_SOFT_CEILING_TB` → `10.0`. A non-parseable env value **raises `ValueError`** (user-set config error; fail-fast house rule — it is trivially fixable and silently defaulting would hide a wrong ceiling).
3. **Cache read:** JSON `{"ts": epoch, "used_bytes": int, "n_repos": int, "namespace": str}` at the cache path. Valid iff namespace matches, ts age < TTL, fields parse. Corrupt/stale/missing → ignore (fail-soft) and fall through to the live probe. `force_refresh=True` skips the read.
4. **Live probe** (lazy imports inside the function, matching hub.py style). NOTE: the server REJECTS `expand=["usedStorage"]` on the list endpoints (400 BadRequest, live-verified 2026-06-12) even though the 0.36.2 client accepts it — so the probe is two-stage: list (with `expand=["private"]`) to enumerate, then per-repo `*_info(expand=["usedStorage"])` fanned out over a bounded thread pool:
   ```python
   from concurrent.futures import ThreadPoolExecutor

   api = HfApi(token=os.environ.get("HF_TOKEN"))
   repos: list[tuple[str, str]] = []          # (repo_id, repo_type)
   for lister, rtype in ((api.list_models, "model"), (api.list_datasets, "dataset")):
       for info in lister(author=namespace, expand=["private"]):
           if getattr(info, "private", False):
               continue                       # public-storage quota counts public repos only
           repos.append((info.id, rtype))

   def _used(rid_rtype) -> int | None:
       rid, rtype = rid_rtype
       info_fn = api.model_info if rtype == "model" else api.dataset_info
       # usedStorage lands via __dict__.update(**kwargs), not a declared field.
       # Return None (NOT 0) when the field is absent/None — the caller treats
       # any missing value as probe-poisoning (see below).
       v = getattr(info_fn(rid, expand=["usedStorage"]), "usedStorage", None)
       return None if v is None else int(v)

   with ThreadPoolExecutor(max_workers=8) as pool:    # bounded: ~406 public-repo calls ≈ 25 s; 1h cache amortizes
       per_repo = list(pool.map(_used, repos))
   n = len(repos)
   n_missing = sum(1 for v in per_repo if v is None)
   if n and n_missing:
       # PARTIAL-None GUARD (binding critic fix): a present-but-unpopulated
       # usedStorage counted as 0 silently understates usage — #541 was 10.2
       # of 11.3 TB in ONE repo, so a single None on the dominant repo would
       # read ~90% under. ANY missing value poisons the probe to unknown.
       return ... # used_tb=None, over_ceiling=False, basis=f"suspect ({n_missing}/{n} missing usedStorage)"
   used_bytes = sum(per_repo)
   ```
   Any exception (in listing OR any per-repo fetch) → `logger.warning(...)`, return `(used_tb=None, over_ceiling=False, basis=f"unknown ({e})")`. **The helper never raises on API/network failure** (only on the invalid-ceiling/TTL config errors in step 2). Per-repo failures are not silently dropped from the sum (a partial sum would understate usage) — any fetch failure poisons the probe to "unknown", and any absent/None `usedStorage` poisons it to "suspect (k/n missing usedStorage)" (the all-zero suspect guard below remains as a second, independent backstop).
   `EPM_HF_STORAGE_CACHE_TTL_S` parsing mirrors the ceiling's policy: a non-parseable value raises `ValueError` (user config error, fail-fast; caught → WARN at preflight, propagates at the gate).
5. **Cache write:** atomic (`tmp` + `os.replace`, with a PID/uuid-suffixed tmp name so concurrent cold-starting sweep cells never collide), `mkdir(parents=True, exist_ok=True)`, fail-soft on any write error (log + continue). **Only a SUCCESSFUL, COMPLETE sum is ever cached** (binding critic fix): unknown / suspect / partial probes are NEVER written to the cache, so a suspect probe can never produce a clean "0.0 TB under ceiling" cache hit for the next hour. (Defense in depth: the cache-read path also rejects an entry whose `used_bytes` is not a positive int.)
6. Return `over_ceiling = used_tb > ceiling_tb`.

Suspect-zero guard (independent backstop to the partial-None guard above): when `n_repos > 0` but `used_bytes == 0`, set `basis="suspect (all usedStorage empty)"` and treat as unknown (warning path), not as headroom. Suspect results are not cached.

Cache location is **on-disk** (not in-process) deliberately: preflight CLI, the sweep launcher, and each training subprocess are separate processes; an in-process memo would re-hit the API once per process, defeating AC1's "avoid hammering" on an N-cell sweep. Default path `~/.cache/explore_persona_space/hf_storage_usage.json` (a few hundred bytes; safe on pods where `$HOME=/root` is small), override `EPM_HF_STORAGE_CACHE_PATH`.

### 4.2 Preflight WARN — `orchestrate/preflight.py` (AC2)

New fields on `PreflightReport` (:66): `hf_storage_used_tb: float | None = None`, `hf_storage_ceiling_tb: float | None = None`, `hf_storage_basis: str = ""`. New check, modeled on `check_connectivity`:

```python
def check_hf_storage(report: PreflightReport):
    """Non-fatal WARN when account HF public storage exceeds the soft ceiling.

    Advisory only: never adds an error, never raises — an unreachable HF API
    degrades to an 'unknown headroom' warning. See upload-policy.md
    § HF storage-quota 403 for the incident this fronts (#541/#552).
    """
    try:
        from explore_persona_space.orchestrate.hub import check_hf_storage_headroom
        h = check_hf_storage_headroom()
    except Exception as e:          # incl. ValueError from a bad ceiling env: preflight reports, not crashes
        report.add_warning(f"HF storage headroom check failed ({e}) — headroom unknown")
        return
    report.hf_storage_used_tb, report.hf_storage_ceiling_tb, report.hf_storage_basis = h.used_tb, h.ceiling_tb, h.basis
    if h.basis == "disabled":
        return
    if h.used_tb is None:
        report.add_warning(f"HF public-storage usage unknown ({h.basis}) — cannot verify upload headroom")
    elif h.over_ceiling:
        report.add_warning(
            f"HF public storage {h.used_tb:.2f} TB exceeds soft ceiling {h.ceiling_tb:.1f} TB "
            f"({h.n_repos} repos, {h.basis}) — LFS uploads (adapters/checkpoints) will 403 at the hard "
            f"quota; see .claude/rules/upload-policy.md § HF storage-quota 403"
        )
```

Wiring: one call appended in `preflight_check()` after `check_connectivity(report)` (:726); one summary line in `PreflightReport.summary()` (`HF storage: {used:.2f} TB / ceiling {ceiling:.1f} TB ({basis})`, or "unknown"); three keys added to the CLI `--json` dict (:797-807). The `--json` consumer contract (gotchas.md: parse whole stdout) is unaffected — only adds keys.

### 4.3 Pre-train persist gate — `train/trainer.py` + `train/sft.py` (AC3)

New function near `_maybe_persist_adapter` (:480), called from TWO sites (binding critic fix — coverage of all launch paths that DECLARE the persist contract):

1. The **first statement of `_init_phase()`** (:259, before `set_seed`/model load) — covers `train_phase` + `train_dpo_phase`.
2. The **start of `sft.py::train_lora`** (before model load) — covers the direct-`train_lora` launcher family that sets `EPM_PERSIST_ADAPTER_HF_REPO` and enforces the upload EXTERNALLY (verified live path: `scripts/i528_phase23_train.py:187` sets the env, calls `train_lora` at :232, and asserts the adapter landed via its own `_assert_adapter_landed_on_hub` + launcher `set -e` rm-after contract — `_init_phase` is never involved, so a trainer-only gate would miss exactly this family). The gate's TRIGGER stays the env declaration only: `cfg.hf_upload` without the env remains UN-gated by design — that upload is best-effort try/except (never raises, local copy preserved), so it is not a load-bearing contract and gating it would manufacture false aborts.

Because the trigger is env-presence, both call sites are no-ops in every flow that doesn't declare the persist contract — zero behavior change for normal training.

```python
def _validate_persist_headroom() -> None:
    """Minute-1 gate for the fail-loud adapter-persist contract.

    No-op unless EPM_PERSIST_ADAPTER_HF_REPO is set. When set, the launcher
    has declared the end-of-training adapter upload load-bearing
    (delete-after-eval, #404/#458) — so validate BEFORE the model loads:

    1. EPM_PERSIST_ADAPTER_SUBFOLDER also set (same contract as
       _maybe_persist_adapter :516-522, hoisted to minute 1) -> RuntimeError.
    2. Public-storage headroom under the soft ceiling — UNLESS the persist
       target is private/overflow (private LFS quota is separate, #541).

    Decision table (see plan §5 for rationale):
      headroom UNKNOWN          -> WARN, continue (fail-open)
      under ceiling             -> pass
      over ceiling, target is DEFAULT_OVERFLOW_REPO or repo_info says private
                                -> pass with INFO note
      over ceiling, EPM_HF_OVERFLOW_ROUTING=1
                                -> WARN ("uploads will reroute"), continue
      over ceiling (confirmed by a FORCED LIVE re-probe), public target,
      routing off               -> RuntimeError (the doomed-sweep abort)
    """
    repo = os.environ.get("EPM_PERSIST_ADAPTER_HF_REPO")
    if not repo:
        return
    if not os.environ.get("EPM_PERSIST_ADAPTER_SUBFOLDER"):
        raise RuntimeError("...same message as _maybe_persist_adapter...")

    from explore_persona_space.orchestrate.hub import DEFAULT_OVERFLOW_REPO, check_hf_storage_headroom
    h = check_hf_storage_headroom()
    if h.used_tb is None or not h.over_ceiling:
        ...  # warn-if-unknown, then return
    priv = _repo_is_private(repo)   # TRI-STATE (binding critic fix): True | False | None (undeterminable)
    if repo == DEFAULT_OVERFLOW_REPO or priv is True:
        return                      # private LFS quota is separate (#541)
    if priv is None:
        logger.warning("persist-target privacy undeterminable (repo_info failed) — fail-open; "
                       "upload-time backstop still guards data loss")
        return                      # NEVER false-abort a possibly-private-target sweep on a repo_info blip
    if os.environ.get("EPM_HF_OVERFLOW_ROUTING") == "1":
        logger.warning("over soft ceiling with EPM_HF_OVERFLOW_ROUTING=1: this run's upload_model LFS "
                       "uploads will reroute %s -> %s; launchers that verify CANONICAL paths externally "
                       "must not arm routing (see §4.4 contract)", repo, DEFAULT_OVERFLOW_REPO)
        return
    h = check_hf_storage_headroom(force_refresh=True)             # never abort on a stale cache
    if h.over_ceiling:
        raise RuntimeError(
            f"HF public storage {h.used_tb:.2f} TB exceeds the soft ceiling {h.ceiling_tb:.1f} TB "
            f"(hard wall observed at ~11.3 TB) and EPM_PERSIST_ADAPTER_HF_REPO={repo} is a public repo: "
            "the end-of-training fail-loud adapter persist is at high risk of the account-wide LFS-quota "
            "403 (upload-policy.md) — the soft ceiling is the deliberate runway buffer, and policy is to "
            "stop persist-declared sweeps in minute 1 rather than risk the 10h-then-403. Options: free "
            "quota (user-only), point persist at the private overflow repo, set EPM_HF_OVERFLOW_ROUTING=1, "
            "or raise EPM_HF_STORAGE_SOFT_CEILING_TB."
        )
```

The **forced live re-probe before raising** means a sweep is never killed by a ≤1h-stale cache after the user frees quota; the abort path costs one extra API round only when already on the doomed branch. The abort wording deliberately reflects soft-ceiling semantics (in the 10.0→11.3 runway zone the upload would often still succeed; stopping there is stated policy, not a literal "doomed"). SUBFOLDER validation stays duplicated in `_maybe_persist_adapter` (defense in depth; the gate is new, the backstop is proven). `_repo_is_private` returns `True | False | None`: `None` (any `repo_info` failure) routes to fail-open, never to the public-target abort arm.

**Scope note (mid-run crossing residual):** the gate reads headroom at phase start only. A run that starts under the ceiling and crosses it mid-run still fails at upload time (loudly, via the existing backstop) — the headline claim is scoped to "already over the soft ceiling at start". The §0.0 TL;DR carries the same scoping.

### 4.4 Opt-in overflow routing — `orchestrate/hub.py` (AC4)

Gate env: **`EPM_HF_OVERFLOW_ROUTING=1`**, default off/unset. Choke point: `upload_model()` (:219) — the funnel for the **core library training paths** (`trainer.py::_maybe_persist_adapter` :539, `trainer.py::_maybe_upload_adapter_default` :585, `sft.py::train_lora` `cfg.hf_upload` :1251, `runner.py` merged uploads :293/:307, plus `experiments/contrastive_neg_geometry_472/train_cell.py:103`). **Scope note (fact-checked):** this is NOT every LFS upload in the repo — ~9 frozen per-issue scripts call `HfApi().upload_file/upload_folder` directly (e.g. `scripts/run_i207_gentle_worker.py:156` uploads a LoRA adapter to the public model repo) and remain un-routed; that is a documented non-goal (frozen experiment scripts are out of refactor scope), with the §4.6 doc paragraph telling future per-issue scripts to prefer `upload_model` for LFS artifacts. **Deliberately NOT applied** to `upload_dataset` / `upload_dataset_directory` / `upload_raw_completions_to_data_repo`: per the recovery rule, non-LFS text/JSON keeps flowing to the canonical dataset repo over quota, and big-text sharding is the existing documented remedy — routing them would *diverge* from the recovery rule. (The >10MB force-LFS caveat for raw completions stays governed by the sharding rule; documented non-goal.)

```python
def _resolve_lfs_upload_repo(repo_id: str) -> tuple[str, bool]:
    """(effective_repo_id, rerouted). FIRST short-circuits on the env gate
    (EPM_HF_OVERFLOW_ROUTING != "1" -> return (repo_id, False) with ZERO
    headroom I/O — routing is default-off and must add no latency to normal
    uploads). Then reroutes to DEFAULT_OVERFLOW_REPO iff headroom is
    KNOWN-over-ceiling AND repo_id is not already the overflow repo AND the
    target is not itself private (mirror of the gate's private-target
    exemption: a private target has its own quota headroom — rerouting it
    to overflow would be durable but wrong-place). Unknown headroom never
    reroutes; when routing is ARMED but the signal source is disabled
    (EPM_HF_STORAGE_CHECK=0) or unknown, log ONE loud warning per process
    ("routing armed but blind — uploads will NOT reroute") so a stale kill
    switch can't silently disarm the protection the user believes is on."""

# inside upload_model(), before the _upload call:
effective_repo, rerouted = _resolve_lfs_upload_repo(repo_id)
if rerouted:
    logger.warning("EPM_HF_OVERFLOW_ROUTING: rerouting LFS upload %s -> %s (public storage over soft ceiling)",
                   repo_id, effective_repo)
    _emit_overflow_routing_event(original_repo=repo_id, effective_repo=effective_repo, path_in_repo=path_in_repo)
result = _upload(..., repo_id=effective_repo, private=rerouted or repo_id == DEFAULT_OVERFLOW_REPO, ...)
if rerouted and result:
    _write_overflow_pointer(canonical_repo=repo_id, path_in_repo=path_in_repo,
                            overflow_repo=effective_repo)   # fail-soft
return result
```

**Durable effective-repo record (binding critic fix — reroute must not orphan canonical-path consumers).** Downstream consumers reconstruct canonical repo ids rather than consuming `upload_model`'s return (verified: `scripts/i528_phase23_train.py:253` verifies the reconstructed canonical repo; `scripts/dispatch_neg_geometry_504.py` writes `hf_repo: HF_MODEL_REPO` into durable records and later `hf_hub_download`s from it; the trainer default-upload path deletes the local adapter after a verified return). Two-part answer:

- **`_write_overflow_pointer(...)`** — after a successful reroute, upload a tiny JSON pointer `{overflow_repo, path_in_repo, ts, used_tb, ceiling_tb}` to the **CANONICAL** repo at `<path_in_repo>/OVERFLOW_POINTER.json`. This is a non-LFS small-JSON commit, which **succeeds even over quota** (validated #541 — the quota gate fires only on the LFS endpoint), so the canonical lookup path is never empty: any consumer or verifier listing the canonical subfolder finds a machine-readable breadcrumb to the real location. Fail-soft (a pointer-write failure logs loudly but never fails the rerouted upload).
- **Explicit arming contract** (documented in §4.6 + the gate's routing-on warning): `EPM_HF_OVERFLOW_ROUTING=1` is safe ONLY for flows that consume `upload_model`'s returned URL or read the pointer/deviation records. Launchers that verify canonical paths EXTERNALLY (the i528 family) must not arm it — for them a reroute converts the 403 into a post-training verification abort. The library cannot detect its caller's consumption pattern; the contract + pointer + minute-1 gate together close the loop. (`_maybe_persist_adapter`'s own verification follows the EFFECTIVE repo — hub.py:185-213 verifies against the repo actually uploaded to — so the load-bearing persist contract survives a reroute by construction.)

Two required supporting changes:

- **`_upload` gains `private: bool = False`** threaded into `create_repo(repo_id, repo_type=..., private=private, exist_ok=True)` (:156). Without this, a reroute to a not-yet-existing overflow repo would create it **PUBLIC** — defeating the entire point (private quota separation). Default `False` preserves current behavior at every existing call-site.
- **`_emit_overflow_routing_event(...)`** — the "plan-deviation note" mechanism. Pod-side library code must NOT shell `task.py` (CLAUDE.md hard rule), so the deviation surfaces via the sanctioned pod→orchestrator channels: (a) the `logger.warning` structured line above (greppable in run logs), and (b) an appended JSON line `{ts, original_repo, effective_repo, path_in_repo, used_tb, ceiling_tb}` to an event-sink path resolved as `EPM_HF_OVERFLOW_EVENT_PATH` env (tests set this — host-independent) → `/workspace/logs/hf-overflow-routing.jsonl` when `/workspace/logs` exists (pod/GCP `/workspace` contract) → `~/.cache/explore_persona_space/hf-overflow-routing.jsonl`. Fail-soft. The orchestrator/upload-verifier observing the event posts the actual `epm:` plan-deviation marker; the §4.6 upload-policy.md paragraph NAMES the sentinel path + the `OVERFLOW_POINTER.json` convention explicitly so verifiers/orchestrators know where to look (the durable discovery surface is the canonical-repo pointer above — the local JSONL is the greppable run-side trace, not the durable record).

## 5. Failure-mode handling

| Site | API error / unknown headroom | Known over-ceiling | Rationale |
|---|---|---|---|
| Helper | Never raises; returns `used_tb=None`, logged warning | Returns `over_ceiling=True` | Advisory primitive; callers decide policy |
| Helper — ANY per-repo `usedStorage` absent/None | Poisons to `basis="suspect (k/n missing usedStorage)"`, `used_tb=None`; never cached | — | A partial sum understates usage (#541 was 10.2/11.3 TB in ONE repo); None ≠ 0 |
| Persist gate — target privacy undeterminable (`repo_info` fails) | **Fail-open** (WARN + continue; tri-state `None`, never coerced to "public") | — | A transient `repo_info` blip must not false-abort a private-target sweep; the upload-time backstop still guards data |
| Preflight | WARN, `ok` unchanged | WARN, `ok` unchanged | AC2 says non-fatal; preflight already treats connectivity as warning-class (:646) |
| Persist gate | **Fail-open** (WARN + continue) | **Fail-loud** (`RuntimeError`), but only after a forced **live** re-probe confirms, and only for public targets with routing off | The gate is an *advisory accelerator* of an already-fail-loud contract — `_maybe_persist_adapter` remains the authoritative backstop that prevents data loss at upload time. Blocking training on a transient HF API blip would convert an availability hiccup into a guaranteed run failure, which is strictly worse than the mitigated risk ("trains 10h then 403s with the local copy intact and retryable"). Conversely a *confirmed* over-ceiling is deterministic doom (the 403 is persistent + account-wide), so continuing wastes the whole sweep — fail in minute 1 per AC3. The contract-shape error (REPO without SUBFOLDER) is a config bug → immediate fail-loud, consistent with the existing :518 behavior. This is not a hidden failure: unknown-headroom is loudly logged, and the real failure still crashes loudly later if it materializes. |
| Routing | Unknown headroom → **no reroute** (canonical repo; the 403 + persist backstop handle it) | Reroute, private=True, event emitted | Rerouting on uncertainty could scatter artifacts into overflow unnecessarily; routing only acts on confirmed signal |
| Cache I/O | All read/write errors fail-soft to live probe / skip write | — | A broken `~/.cache` must never block runs |
| Bad `EPM_HF_STORAGE_SOFT_CEILING_TB` value | `ValueError` from the helper (caught → WARN at preflight; **propagates** at the persist gate) | — | User config error: fail-fast where the value is load-bearing |

## 8. Kill criteria

- **Per-repo `*_info(expand=["usedStorage"])` stops working** — the design's load-bearing endpoint, live-verified working on 2026-06-12 (the list-level expand variant was ALREADY ruled out: server 400s it despite client acceptance — see §3; client source is NOT authoritative for server acceptance). Residual: if the server stops populating `usedStorage` (returns None for all repos), the helper would sum to 0 TB and read perpetually-under-ceiling. Mitigation baked in: when `n_repos > 0` but `used_bytes == 0`, set `basis="suspect (all usedStorage empty)"` and treat as unknown (warning path), not as headroom. If that fires in practice, the fallback approach is the authenticated `/api/users/<ns>` storage endpoint — a re-plan, not a silent default.
- **Listing cost blows up** — 414 repos is a handful of paginated calls (seconds). If the account ever grows to where the probe takes >~30 s, the TTL cache already bounds it to once/hour/machine; not a kill.
- **The gate produces false aborts** — the live re-probe + private-target exemptions + kill switch (`EPM_HF_STORAGE_CHECK=0`) are the escape hatches; if a false abort still occurs the kill switch unblocks in-turn while the bug is fixed.
