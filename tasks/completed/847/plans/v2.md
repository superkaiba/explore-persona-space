## 2. Prior Work

**Web (verified 2026-07-02):**
- PyTorch defaults intra-op threads to all available cores; at initialization it reads `OMP_NUM_THREADS` and `MKL_NUM_THREADS` (in order, if present) — [PyTorch CPU threading notes](https://glaringlee.github.io/notes/cpu_threading_torchscript_inference.html).
- `torch.set_num_threads()` takes precedence over the environment variables, and `MKL_NUM_THREADS` takes precedence over `OMP_NUM_THREADS` for MKL — same doc + [pytorch#19001](https://github.com/pytorch/pytorch/issues/19001). So per-script `set_num_threads` calls remain the fine-grained override on top of our env defaults.
- Env vars must be set BEFORE torch import/first parallel region to size the intra-op pool; changing them later does not retro-cap ([jdhao note](https://jdhao.github.io/2020/07/06/pytorch_set_num_threads/), [pytorch#60000](https://github.com/pytorch/pytorch/issues/60000)).
- Multi-process oversubscription (N procs × nproc threads) is the canonical shared-host pathology; capping per-process threads is the standard mitigation ([OSC thread best practices](https://www.osc.edu/supercomputing/knowledge-base/thread_usage_best_practices)).

**In-repo precedent:**
- The #745 `HF_XET_HIGH_PERFORMANCE`/`HF_HUB_ENABLE_HF_TRANSFER` setdefault block in `load_dotenv()` (env.py:244-245) + `setup_worker()` (:295-296) is the EXACT pattern to mirror (setdefault after `_dotenv_load`, explicit `=0` preserved, belt-and-suspenders comment). Its test file `tests/test_hf_upload_accelerator_env.py` is the test pattern.
- The three-way discriminator (`is_cluster_env` / `is_runpod_env` / local) and its 2026-06-11 dev-VM-`/workspace` incident docstring establish the mount-point-not-directory detection idiom this plan reuses.
- Per-script caps already exist and stay authoritative where present: `scripts/issue779_layer_sweep.py:486`, `src/explore_persona_space/analysis/vectorized_mlp_skill.py:175,337`, `scripts/issue722_per_position_vC_skill.py:205`, `src/explore_persona_space/experiments/issue_779/fit_h.py:129`, `scripts/issue649_extract_panel_earlylayer.py:429`.

### 4.1 `src/explore_persona_space/orchestrate/env.py`

Add `import platform` to the imports. Add module-level constants + two functions after `is_runpod_env()`:

```python
_SHARED_VM_HOSTNAME = "cia-benchmark-vm"
_SHARED_VM_DATA_DISK = "/mnt/eps-data"   # #681 data disk — exists ONLY on the shared VM
_DEFAULT_VM_THREAD_CAP = 8               # diagnosis §6: each job realized ~5-6 cores
_THREAD_CAP_KEYS = (
    "OMP_NUM_THREADS",       # OpenMP (torch intra-op pool size, read at torch import)
    "MKL_NUM_THREADS",       # MKL (takes precedence over OMP for MKL ops)
    "OPENBLAS_NUM_THREADS",  # OpenBLAS (numpy pip wheels)
    "NUMEXPR_NUM_THREADS",   # numexpr (pandas eval paths) — cheap defense-in-depth
)

def is_shared_vm_env() -> bool:
    """True iff we are on the SHARED dev VM (positive detection; fails OPEN).

    GCE instances from the GCP lane route as *local* in the three-way
    discriminator (plain-dir /workspace — see is_runpod_env), so "local"
    must NOT imply "shared VM". Positive signals only; anywhere else
    (pods, GCE, SLURM, laptops, novel dedicated boxes) returns False:
      * EPS_SHARED_VM=1/0 — explicit override, both directions.
      * os.path.ismount(_SHARED_VM_DATA_DISK) — the #681 data disk.
      * platform.node() == _SHARED_VM_HOSTNAME — belt-and-braces if the
        disk is detached; platform.node() returns "" on failure (open).
    """
    forced = os.environ.get("EPS_SHARED_VM")
    if forced is not None and forced.strip() != "":
        return forced.strip().lower() not in ("0", "false")
    if is_cluster_env() or is_runpod_env():
        return False  # defensive; mirrors the cluster-first ordering above
    if os.path.ismount(_SHARED_VM_DATA_DISK):
        return True
    return platform.node() == _SHARED_VM_HOSTNAME

def _apply_shared_vm_thread_caps() -> None:
    """setdefault BLAS/OpenMP thread caps on the shared VM only (#847).

    Torch sizes its intra-op pool from OMP_NUM_THREADS at IMPORT time and
    never re-reads it, so this must run before ``import torch`` in the
    process (load_dotenv precedes torch imports in the repo entrypoints;
    setup_worker calls this before its own torch import). Even when torch
    is already imported, the setdefault still caps every SUBPROCESS.
    Explicit launch-time values always win (setdefault). Per-script
    ``torch.set_num_threads(...)`` takes precedence over env either way.
    """
    if not is_shared_vm_env():
        return
    raw = os.environ.get("EPS_VM_THREAD_CAP")
    if raw is None:
        cap = _DEFAULT_VM_THREAD_CAP
    elif raw.strip() == "":
        return  # explicitly disabled
    else:
        cap = int(raw)   # malformed value raises ValueError — fail loud
        if cap <= 0:
            return       # 0 (or negative) disables
    for key in _THREAD_CAP_KEYS:
        os.environ.setdefault(key, str(cap))
```

Two call sites:
1. `load_dotenv()` — one line `_apply_shared_vm_thread_caps()` immediately after the `HF_HUB_ENABLE_HF_TRANSFER` setdefault (line 245). Placement AFTER `_dotenv_load` is deliberate: an `OMP_NUM_THREADS` in `.env` counts as explicit and wins.
2. `setup_worker(gpu_id)` — same call as the FIRST statement (before the `import torch` at line ~261, which would otherwise freeze the pool at its uncapped default (physical cores = 16 here) before the cap lands in a worker whose parent never set it).

Also extend the module docstring's environment #3 (Local VM) with two sentences naming the shared-VM sub-case + the torch import-ordering constraint.

## 11. Decision Rationale

- **Detection predicate = `EPS_SHARED_VM` override, else (not cluster/runpod) AND (`ismount('/mnt/eps-data')` OR hostname == `cia-benchmark-vm`).** Why: positive detection required because GCE routes as local (env.py `is_runpod_env` docstring, read); combining (c) mount + (b) hostname makes the predicate survive either a disk detach or a rename while staying positive and fail-open; the env override gives (d)'s explicitness without the ops dependency (and a kill switch). Rejected: (a) GCE-env exclusion — exclusion-based, fails CLOSED on novel dedicated boxes; (e) metadata probe — network call at import time. Source: `env.py` docstrings + `backends/gcp.py:1483-1522` (GCE exports, no `/mnt/eps-data` in `backends/` — grep) + live probe (`findmnt /mnt/eps-data` → ext4 `/dev/sdb`; `hostname` → `cia-benchmark-vm`).
- **Cap value 8.** Why: diagnosis measured each 32-thread job realizing only ~5-6 cores; 8 threads × ~5 concurrent jobs ≈ 40 runnable on 32 cores (healthy), and 8 matches the only well-behaved job in the incident (`issue779_layer_sweep`, docstring-target 8) and open-instruct's `OMP_NUM_THREADS=8`. Source: `vm_load_diagnosis.md` §2/§6; `scripts/issue779_layer_sweep.py:18`. Alternatives: 4 (over-throttles a lone job), `nproc//4` (dynamic, harder to reason about; rejected for a fixed knob-overridable constant).
- **setdefault-only, placed after `_dotenv_load`.** Why: task hard constraint (explicit wins); after-dotenv so `.env` values count as explicit. Source: task body §Constraints; #745 precedent block at env.py:244-245.
- **Env-var set = OMP + MKL + OPENBLAS + NUMEXPR; no VECLIB.** Why: OMP sizes the torch pool (read at init); MKL takes precedence over OMP for MKL ops so it must be pinned too; OPENBLAS covers numpy pip wheels; NUMEXPR is a one-line harmless extension for pandas paths. VECLIB is macOS-only. Source: [PyTorch CPU threading notes](https://glaringlee.github.io/notes/cpu_threading_torchscript_inference.html), diagnosis §6.
- **Malformed `EPS_VM_THREAD_CAP` raises `ValueError`.** Why: project fail-fast rule — a typo'd explicit knob is a config bug, not a case to silently default. Source: CLAUDE.md "Fail fast".
- **Second call site at top of `setup_worker`.** Why: `setup_worker` imports torch at its 4th statement; a worker whose parent never capped would freeze the pool at its uncapped default before a later setdefault. Source: env.py:248-298 (read).
