# Plan v1 — Task #1940: extend check-28 opaque-code token classes with bare P/M candidate codes

## Goal / Requirement

Extend `scripts/verify_task_body.py` check 28 (`check_figure_label_codes` /
`_opaque_code_tokens`) so bare candidate/panel codes (`P1`, `P7`, `M4`, `P3b`)
in figure-sidecar rendered text are flagged, closing the #1900 gap where
figures with "P1 | P7" legend text and "P7-residualized" titles PASSed the
mechanical gate (n_fail=0, twice) and burned an LM clean-result-critic round
(epm:clean-result-critique v1 on #1900, Must-Fix 1).

**Acceptance criteria:**
1. A sidecar title/legend string carrying `P7` or `M4` produces a check-28
   WARN naming the token.
2. Percentile text (`p97.5`, `p50`), GPU names (`P100`, `P40`, `M40`, `H100`),
   and dtype spellings stay clean (no new false positives on the named
   classes).
3. Tokens inside path-shaped words (`figures/issue_1900/P7.png`) stay exempt
   (the existing per-word path exemption covers the new class).
4. Pinning tests land in `tests/test_verify_task_body.py` (positive +
   negative per criteria 1–3).
5. Every surface documenting the check-28 token classes is synced
   (SPEC.md enumeration; the check-28 label string + its test pin).
