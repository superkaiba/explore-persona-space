# Plan v1 — #2128: `spawn_session.py stop --kill` daemon-untracked path must TERM the surviving inner claude pid

kind: infra · workflow: v1 · est_gpu_hours: 0 · backend: none (VM-only code edits + pytest)

## 1. Goal

On the daemon-untracked zombie path, `spawn_session.py stop --kill` SIGTERMs the
wrapper node pid, bounded-waits ~10 s for the WRAPPER, and — when the wrapper dies
but its cleanup failed to reap the inner claude pid — merely prints
`WARNING: inner claude pid <pid> still alive — ... verify/kill manually.` and
returns success (`scripts/spawn_session.py:3285-3293`). On an autonomous fleet the
"verify/kill manually" step has no owner: the 2026-08-05 incident left a ~24 h
zombie holding #2061 blocked ~18 h (wrapper node pid 2943628; plain `stop` had
failed with `Raw daemon reply: {'success': False}`).

Fix (per the task body's proposed change): after the wrapper dies, bounded-wait
(~10 s) for the inner claude pid; if still alive, TERM it directly, re-verify
(another ~10 s bounded wait), and only then exit. Exit 2 with the manual
instruction remains the LAST resort when the inner pid survives the direct TERM.
**Never auto-escalate to KILL** — a KILL on a live session is the destructive case
a human should confirm.

## 2. Design

### 2.1 Escalation flow (wrapper-dead branch of `_stop_fallback`)

Current flow: wrapper SIGTERM → 20×0.5 s death poll → on wrapper death, compose a
survivor WARNING string if `claude_pid` (pre-kill-resolved via
`session_resolver.resolve_claude_pid`, spawn_session.py:3278) is still alive →
print + optional `_post_stop_cleanup` → return 0.

New flow on the wrapper-dead branch, when `claude_pid is not None` and
`session_resolver._pid_alive(claude_pid)`:

1. **Grace wait:** `_await_pid_death(claude_pid, session_resolver)`
   (spawn_session.py:1632 — the existing 20×0.5 s helper on the ONE `_pid_alive`
   liveness seam). The wrapper's own SIGTERM cleanup may already have signaled the
   child; give it the same ~10 s the wrapper got. Dead → success note, no signal.
2. **Identity gate before signaling (pid-recycle safety):**
   `session_resolver._read_proc_comm(claude_pid) == "claude"`. The pre-kill
   resolution is now ≥10 s stale; a recycled pid means the original inner claude
   is DEAD → success note (`comm=... != 'claude' — pid recycled after exit;
   treating as dead, no signal sent`), no signal. This mirrors the #903 principle
   (identity re-verify immediately before any signal; ambiguity never kills).
3. **Direct SIGTERM:** `os.kill(claude_pid, signal.SIGTERM)`.
   `ProcessLookupError` → died between probe and signal → success note. Never
   `SIGKILL` anywhere on this path (task-body hard constraint).
4. **Re-verify:** `_await_pid_death(claude_pid, session_resolver)` again.
   Dead → success note (`inner claude pid <p> did not exit with the wrapper;
   TERMed directly and confirmed dead`).
5. **Last resort (survivor after direct TERM):** print the manual instruction to
   stderr and `raise SystemExit(2)` — message names the wrapper pid (dead), the
   inner pid (alive through a direct SIGTERM + ~10 s bounded wait), the
   never-auto-KILL rationale, and the manual recipe
   (`ps -o pid,lstart,cmd -p <p>` then `kill -KILL <p>`). Explicit `exit 2`
   (matching the task body's stated contract) via `print(..., file=sys.stderr)` +
   `SystemExit(2)`, since `sys.exit(str)` yields rc 1.

Implemented as a module-level helper `_term_surviving_inner_claude(sid, wrapper_pid,
claude_pid, session_resolver) -> str` placed next to `_stop_fallback`: returns the
success-note suffix for the existing `Stopped daemon-untracked session ...` print,
and OWNS the last-resort stderr+`SystemExit(2)` branch. Keeping the exit inside the
helper guarantees `_post_stop_cleanup` cannot run on the survivor branch (see 2.2).

### 2.2 Cleanup gating (deliberate behavior change, #1455-consistent)

Today, `cleanup=True` fires whenever the WRAPPER is confirmed dead — even with a
live inner claude (the warning-only path). Post-fix, the survivor-after-TERM branch
exits 2 BEFORE the cleanup call: `_post_stop_cleanup`'s confirmed-dead precondition
(#1455 docstring: "no cleanup without a confirmed-dead process") now covers wrapper
AND inner. Rationale: unregistering a session whose claude still runs invites an
orphan-respawn double-run — exactly the #2061 zombie class. On every success branch
(steps 1-4 above) the inner pid is confirmed dead/recycled, so cleanup semantics are
STRONGER, never weaker.

### 2.3 Exit-code / caller compatibility

- Success path (wrapper dead + inner dead/reaped/recycled/TERMed-and-died): rc 0,
  unchanged shape of the `Stopped daemon-untracked session ...` line, with a NOTE
  suffix instead of a WARNING when escalation ran.
- Survivor-after-TERM: rc 2 (was rc 0 + WARNING). This is the point of the task —
  an unowned manual step must not read as success. Implementer duty: grep for
  programmatic callers of `stop` + `--kill` (scripts/, .claude/, docs/) and confirm
  none parse rc on the fallback path expecting 0-with-survivor
  (`spawn_session.py stop` daemon-tracked path is untouched).
- Wrapper-survives-SIGTERM branch (spawn_session.py:3300-3303) untouched.

### 2.4 Wrapper death-poll tidy (small, behavior-identical)

The wrapper loop at spawn_session.py:3280-3284 hardcodes the 20×0.5 s shape that
`_await_pid_death` (added later, #956) now canonicalizes on the same seams
(`session_resolver._pid_alive` + `time.sleep`). Refactor the loop to
`if _await_pid_death(pid, session_resolver): <success branch>` — one death-poll
shape file-wide, no semantic change.

## 6. Risks & rollback

- **Risk:** exit-code change (rc 0 → rc 2) on the survivor-after-TERM branch
  breaks a programmatic caller. Mitigation: §2.3 caller grep; the branch was
  previously reachable only in the already-anomalous zombie state.
- **Risk:** TERMing a recycled pid. Mitigation: §2.1 step 2 comm gate +
  `ProcessLookupError` tolerance; the pid was resolved from the wrapper's own
  /proc child walk pre-kill and is only ever signaled if it STILL reads
  `comm == "claude"`.
- **Risk:** cleanup no longer runs on the survivor branch, leaving registration
  rows behind. Accepted deliberately (§2.2): a live claude means the session is
  NOT dead; the exit-2 message hands the human the recipe, and cleanup runs on
  the eventual successful re-run.
- **Rollback:** single-commit revert (one script + one test file).

## 7. Assumptions

- `sys.exit(str)` → rc 1 elsewhere in the file is acceptable to leave as-is; only
  the new last-resort branch needs the explicit rc 2 (task-body contract).
- The inner claude process reads `comm == "claude"` (grounded:
  `resolve_claude_pid` matches exactly that, session_resolver.py:256-281).
- No live caller depends on rc 0 + WARNING on the survivor path (verified by
  implementer grep, §2.3).
