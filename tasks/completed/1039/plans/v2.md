## 4. Method delta + Design

**Method delta in one paragraph:** today the candidate loop is binary (EPS candidate vs one silent skip bucket). After this change it is four-way — PM (skip, unchanged, checked first) / EPS (unchanged lane) / non-EPS (new stop-eligible lane with 7d grace + TTY + age + no-registry gates, alert-only under either kill switch) / unresolvable (new escalate-only age-report bucket). The EPS lane's decision path, state schema, markers, and thresholds are byte-identical; everything new is additive.

### 4.2 Pure classification helper (insert near the constants)

```python
def _classify_session_cwd(path: object, project_prefix: str) -> str:
    """'eps' | 'non-eps' | 'unresolvable'. Exactly the EPS predicate the pass
    used before #1039; a non-str/empty path is the dir-resolution-failure case."""
    if not isinstance(path, str) or not path:
        return "unresolvable"
    if path == project_prefix or path.startswith(project_prefix + "/"):
        return "eps"
    return "non-eps"
```

### 4.3 Sibling pure decision fn (insert directly after `decide_zombie_wrapper`, ~L17470)

```python
def decide_zombie_wrapper_noneps(
    has_claude: bool,
    live_user_tty: bool,
    wrapper_age_s: float | None,
    missed: int,
    first_miss_age_s: float,
    alerted: bool,
    threshold: int = 2,
    *,
    reap_enabled: bool = True,
    grace_s: float = NONEPS_ZOMBIE_WRAPPER_GRACE_S,
) -> tuple[str, int]:
    """Pure decision for one live, non-PM, NON-EPS-cwd, non-registry-mapped
    session (#1039). Same action alphabet as decide_zombie_wrapper.
    - Claude present OR a live user tty -> ("clear", 0): out of scope, episode
      ends (a later loss of tty/Claude starts a FRESH 7d episode).
    - wrapper_age_s None (unreadable /proc) or < grace_s -> ("keep", missed+1):
      the process-age belt; guards the state-carryover race (a first_miss_ts
      written by a prior lane/generation can never shortcut a young wrapper).
    - Otherwise delegate the threshold/grace/kill-switch ladder verbatim to
      decide_zombie_wrapper (mapped=False, status=None) at the 7d grace."""
    if has_claude or live_user_tty:
        return ("clear", 0)
    if wrapper_age_s is None or wrapper_age_s < grace_s:
        return ("keep", missed + 1)
    return decide_zombie_wrapper(
        None, False, False, missed, first_miss_age_s, alerted, threshold,
        reap_enabled=reap_enabled, grace_s=grace_s,
    )
```

Delegation keeps ONE ladder implementation (threshold → grace → stop/alert-once/keep) — no drift risk between lanes — while `decide_zombie_wrapper` itself is untouched (R4).

### 4.4 Non-EPS driver + unresolvable reporter (insert after `_process_zombie_wrapper`, ~L17802)

`_process_zombie_wrapper_noneps(sid, pid, path, now, dry_run, threshold, *, reap_enabled, children_map, detached_tmux_ttys, check_orphaned)` — mirrors `_process_zombie_wrapper`'s shape:

1. `has_claude = _has_claude_descendant(pid, children_map)`; `live_tty = _is_live_user_tty(pid, detached_tmux_ttys, check_orphaned=check_orphaned)`; `start = proc_start_epoch(pid)`; `wrapper_age_s = now - start if start is not None else None`.
2. Load state from the SAME `zombie-wrapper-<sid>.json` (same loaders/savers; `issue=None`); parse `missed`/`alerted`/`first_miss_ts` identically.
3. `in_scope = not has_claude and not live_tty` → reuse `_check_zombie_stop_verification(sid, pid, None, in_scope, prev, dry_run, now)` verbatim (its `issue=None` routing already lands records in the fallback file).
4. `action, new_missed = decide_zombie_wrapper_noneps(...)` at `grace_s=_zombie_noneps_grace_s()`.
5. Per-session stdout line: `session {sid} (pid={pid}, lane=non-eps, cwd={path}): has_claude=… live_tty=… wrapper_age={d:.1f}d missed=a->b zombie_age={h:.1f}h action=…`.
6. Act: `stop` → `_stop_session(sid, dry_run)`; on ACK, `_zombie_record(None, note, dry_run, label="zombie-wrapper-noneps-stop")` with a note carrying the existing `_ZOMBIE_WRAPPER_STOP_NOTE_SENTINEL`, `lane=non-eps`, the cwd, wrapper age, zombie age, both knob names, and the recovery hint ("restart from its own project: `happy claude` in `<cwd>`; the old conversation remains resumable via `claude --resume` — transcripts persist on disk"); save state exactly as the EPS driver does (stopped_at for next-tick verification; all saves `if not dry_run:` per the dry-run gating contract in the reporter section below). `alert` (either kill switch off) → same-shaped alert record, `alerted=True` persisted, once per episode. `keep`/`clear` → identical state handling to the EPS driver. Implementer notes (non-blocking, from review): a one-line comment on the lane-flap dedup residual (a sessions.json flap re-starts the episode and may re-emit one durable row — accepted, fail-toward-keep) and a one-line comment in `_classify_session_cwd` noting the physical-vs-logical worktree-path caveat (a `/mnt/eps-data`-recorded cwd would classify non-eps; guards still bind).

`_report_unresolvable_wrapper(sid, pid, now, dry_run, *, grace_s, children_map)` — escalate-only:

1. `start = proc_start_epoch(pid)`; `age_s = now - start if start else None`; `has_claude = _has_claude_descendant(pid, children_map)`; `tty = _wrapper_has_controlling_tty(pid)` (both purely informational — they never gate anything here).
2. ALWAYS one stdout line: `session {sid} (pid={pid}): cwd UNRESOLVABLE (no sessions.json metadata) — wrapper_age={d or '?'}d has_claude=… tty=… ; escalate-only, never auto-stopped`.
3. Durable dedup row: iff `age_s is not None and age_s >= grace_s` and `prev.get("unresolvable_alerted_ts")` absent → `_append_zombie_fallback_event(...)` (note carries sid, pid, age, has_claude, tty, and the manual-sweep command `spawn_session.py stop --session-id <sid>`), then write a MINIMAL state payload `{"unresolvable_alerted_ts": now, "pid": pid}` via a tiny `_save_unresolvable_state` (tmp+rename, same file path `zombie-wrapper-<sid>.json`). Deliberately NOT `_save_zombie_state`: writing no `first_miss_ts`/`missed` means a later lane transition (metadata appears) starts a FRESH episode via the existing `first_miss_ts = now` default — an unresolvable-era timestamp can never shortcut a 7d grace. The existing GC reaps the file when the sid leaves the live set. Age-unreadable → stdout only (nothing durable to age-report), fail toward quiet.

**Dry-run gating (EXPLICIT contract for BOTH new lanes — Statistics Must-Fix):** every state write in the new code is gated `if not dry_run:` exactly like the EPS driver — `_save_unresolvable_state` is NEVER called under `dry_run=True`, and the non-EPS driver's `_save_zombie_state` calls (miss-count/keep, alert, post-stop) are all inside `if not dry_run:` blocks. `_append_zombie_fallback_event(note, dry_run)` already honors dry_run internally (prints `[dry-run] would append...`); `_stop_session(sid, dry_run)` likewise. Consequence: the §6 step-4 live `--dry-run` smoke is provably read-only on the fleet — no `zombie-wrapper-<sid>.json` created/updated, no fallback rows, no dedup pre-consumption (§7.4's first REAL tick still lands its ≤1 row per unresolvable session). Pinned by the two dry-run tests in §5.

### 4.5 `zombie_wrapper_pass` rewiring (L17840-17888)

Replace the classification loop tail (the EPS predicate itself is preserved inside `_classify_session_cwd`):

```python
candidates, noneps_candidates, unresolvable = [], [], []
skipped_pm = skipped_contradictory = 0
for child in children:
    sid/pid validity checks (unchanged)
    if sid in pm_sids: skipped_pm += 1; continue          # PM first, unchanged (R5)
    path = (meta.get(sid) or {}).get("path")
    cls = _classify_session_cwd(path, project_prefix)
    if cls == "eps":
        issue = registry_map.get(sid)
        if issue is None: issue = _infer_issue_from_path(path)
        candidates.append((sid, pid, issue))              # EPS lane byte-identical
    elif cls == "non-eps":
        if registry_map.get(sid) is not None:
            skipped_contradictory += 1                    # registry-mapped but non-EPS cwd:
            continue                                      # contradictory metadata -> keep
        noneps_candidates.append((sid, pid, path))
    else:
        unresolvable.append((sid, pid))

reap = _zombie_wrapper_reap_enabled()
noneps_reap = reap and _zombie_noneps_reap_enabled()
print(f"zombie-wrapper: {len(candidates)} EPS + {len(noneps_candidates)} non-EPS "
      f"session(s) scanned ({skipped_pm} PM-registered skipped; "
      f"{len(unresolvable)} unresolvable-cwd age-reported; "
      f"{skipped_contradictory} contradictory-metadata kept; "
      f"reap={...}; noneps_reap={...})")
if not (candidates or noneps_candidates or unresolvable):
    return
children_map = _proc_children_map()
for sid, pid, issue in sorted(candidates):                # EPS lane: unchanged call
    _process_zombie_wrapper(...)
if noneps_candidates:
    detached_tmux_ttys, _ = _detached_tmux_panes_with_activity()   # lazy: one tmux call
    check_orphaned = _orphaned_tmux_reap_enabled()                 # only when the lane is non-empty
    for sid, pid, path in sorted(noneps_candidates):
        _process_zombie_wrapper_noneps(..., reap_enabled=noneps_reap, ...)
for sid, pid in sorted(unresolvable):
    _report_unresolvable_wrapper(sid, pid, now, dry_run,
                                 grace_s=_zombie_noneps_grace_s(), children_map=children_map)
```

## 11. Decision Rationale (load-bearing constants)

1. **Non-EPS grace = 7 days (`NONEPS_ZOMBIE_WRAPPER_GRACE_S = 604800`).** *Why:* a week of continuously-observed deadness makes the stop non-destructive by construction and doubles as a post-deploy bake window. *Source:* task #1039 Goal ("age-gated >=7d"); repo precedent `EPM_WORKTREE_VENV_IDLE_DAYS=7d` (worktree_audit's idle-personal-artifact horizon); incident ages 14-31d give ≥2× margin. *Alternatives:* 2h (EPS parity — rejected: personal sessions warrant a categorically wider margin); 14d (halves responsiveness for no added safety given the TTY/Claude/PM guards).
2. **Wrapper-process-age belt (`proc_start_epoch`, ≥ grace, `None`→keep).** *Why:* makes "the wrapper itself is ≥7d old" independently true even under state-carryover races (sid-generation edge cases); satisfies the Goal's "age-gated" reading under both interpretations (episode age AND process age). *Source:* `scripts/tick_triage.py::proc_start_epoch` (existing, identity-guard-proven); module fail-toward-keep posture. *Alternatives:* episode-grace only (rejected: one belt, free to add); sessions.json `savedAt` (rejected: absent exactly for the unresolvable class).
3. **TTY guard = `_is_live_user_tty(pid, detached, check_orphaned=_orphaned_tmux_reap_enabled())`, non-EPS lane only.** *Why:* the exact "user could be looking RIGHT NOW" semantics the incident exception ("except the current my goat client") needs; consistent with the idle-unmapped reaper so one knob (#818) governs the orphaned-server refinement everywhere; every uncertain signal fails toward keep. EPS lane deliberately NOT given the guard: R4's byte-preservation of month-old established EPS behavior wins over a uniform reading of R5 — the EPS 2h-grace stop of TTY-holding idle wrappers is pre-existing, accepted behavior, and extending the guard there is listed as a must-ask deviation, not smuggled in. *Source:* #818 (idle-unmapped orphaned-tmux subclass); L18592-18635 read. *Alternatives:* bare `_wrapper_has_controlling_tty` (keeps even detached-dead panes — rejected: it would exempt precisely the incident's detached-zombie shape from ever being reaped); `check_orphaned=False` (acceptable; rejected for cross-reaper consistency).
4. **Dual-knob kill switch: `EPM_ZOMBIE_NONEPS_REAP` (default ON, alert-only when off), ANDed with `EPM_ZOMBIE_WRAPPER_REAP`.** *Why:* the widening must be revocable without losing the established EPS reap, and vice versa; global-off must still cover both (a fleet-wide "stop stopping things" lever). Default ON is safe because the 7d grace makes week-one observation-only regardless. *Source:* #818 default-ON widening-knob precedent; task spec R3; user directive 2026-07-17. *Alternative:* single knob (simpler, but couples two independent reverts — rejected; tradeoff stated per the spec's "OR argue" clause).
5. **Threshold reuse (`args.threshold`, default 2).** *Why/Source:* module-wide consecutive-check precedent (every reaper); the grace, not the threshold, carries the safety margin. *Alternative:* a higher non-EPS threshold (cosmetic at a 7d grace — 2 checks and ~1000 elapsed ticks already compose).
6. **Unresolvable bucket = escalate-only, never stopped.** *Why:* EPS-ness genuinely unknowable ⇒ the watcher's standing fail-toward-keep posture forbids destructive action on missing data. *Source:* task Goal verbatim; idle-unmapped's "missing idleness signal FAILS TOWARD KEEP". *Alternative:* stop-after-30d (rejected: explicitly out of the Goal's design; a human sweep command is included in the row instead).
7. **Records → existing `zombie-wrapper-events.jsonl`; no Telegram push.** *Why:* non-EPS/unresolvable sessions have no task to carry markers; the fallback channel exists for exactly this; a push would fire ~19 times on day one (noise) while the /daily transcript sweep + sidecar already surface it. *Source:* `_append_zombie_fallback_event` design (L17563); task spec R1. *Alternative:* new sidecar under `.claude/cache/` (rejected: duplicates an existing channel).
