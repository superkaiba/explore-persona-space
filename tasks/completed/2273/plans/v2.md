## Method delta (what differs from prior related work)

## Evidence base (all measured on charmander, 2026-08-22)

Login shell: `SHELL=/usr/bin/zsh`, `$0 = zsh`, passwd field 7 `/usr/bin/zsh`.

Fixture: a temp dir holding one real `.log` under a subdirectory (plus, for the
round-2 probes, one binary file containing the same token), and a top-level
`*.log` glob that matches nothing.

**Round 1 — which composition shapes abort:**

| # | Shape | Result | rc |
|---|---|---|----|
| T1 | one command, TWO glob args (the #1336 shape) | whole command skipped; the matching subdir never read | 1 |
| T3 | `ls <nomatch-glob> && echo LATER` | `LATER` never runs | 1 |
| T4 | `ls <nomatch-glob>; echo LATER` | `LATER` **does** run | — |
| T6 | `find <dir> -name '*.log' -exec grep ... {} +` | correct output | 0 |

**Round 2 — the corrected pipeline mechanism (falsified v1's T2 reading):**

| # | Probe | Result |
|---|---|---|
| P1 | `grep <nomatch-glob> \| { cat; echo CONSUMER_RAN; }` | **`CONSUMER_RAN` printed** — the consumer RUNS; only the glob-bearing stage is skipped |
| P2 | `... \| tail -3` | empty output, **rc=0** |
| P3 | `... \| grep <pat>` | empty output, **rc=1** |
| P4 | `... \| wc -l` | prints `0`, **rc=0** |
| P5 | bare `grep -r <pat> <dir>` | `path:match` prefixes **plus** `grep: ...blob.bin: binary file matches`, rc=0 |
| P6 | `grep -rhoE --include='*.log' <pat> <dir>` | clean `hit_banner`, rc=0 |

P1-P4 establish that rc is the LAST stage's exit status, not evidence about the
abort. P5/P6 establish that bare `grep -r` is not a drop-in replacement and
that `--include` (quoted, grep-internal, never reaching zsh's globber) restores
equivalence.

Text to insert verbatim as a new bullet:

```
- **The fellows-cluster remote login shell is zsh (`/usr/bin/zsh`), where an unmatched glob ABORTS the command it appears in — zsh's `nomatch` is on by default, where bash passes the literal pattern through; worse, piped into a `tail`/`head`/`wc`-style consumer the abort reports `rc=0`, so it is invisible to an exit-code check.** The bite is a SINGLE command carrying several glob arguments: `ssh charmander "grep -hoE '<banner>' $S/logs/*.log $S/logs/jobs/*.log | tail -3"` — the second glob matched, the FIRST did not, so zsh skipped the whole `grep` and the directory that DID hold the banner was never read (#1336: one 30-min poll cycle of blind monitoring on a queued 8-GPU job, misread together with a second bad probe as "the run lost its state"; both were probe defects, the run was intact). Measured on charmander: multi-glob single command ⇒ command skipped (rc=1); `&&`-chained ⇒ the later command never runs; `;`-chained siblings DO survive — so semicolon chaining is not the hazard, the single command is. PIPED, precisely: only the glob-bearing STAGE is skipped, the rest of the pipeline still runs on empty input, and the pipeline's rc is the LAST stage's — `| tail`/`| wc -l` exit 0 on empty input (empty output, rc=0) while `| grep <pat>` exits 1, so rc neither confirms nor clears the trap. RULE: in remote commands prefer forms that take a DIRECTORY and cannot nomatch-abort — `grep -rhoE --include='*.log' <pat> <dir>` (the `--include` filter is quoted and grep-internal, so it never reaches zsh's globber; bare `grep -r` is NOT equivalent — it recurses, drops the filename filter, and re-adds `path:` prefixes plus `binary file matches` noise) or `find <dir> -name '*.log' -exec grep -hoE '<pat>' {} +`. When a glob is genuinely wanted, `unsetopt nomatch` (equivalently `setopt +o nomatch`) FIRST, or give each probe its OWN `ssh` call so one abort cannot swallow a sibling behind `&&`. COROLLARY (read side): an empty/zero result from a remote probe is UNKNOWN until the probe itself is verified — never a substantive absence claim, the same posture as the `gcloud` rc!=0-is-UNKNOWN-never-empty rule above; here even rc=0 does not clear a piped probe.
```
