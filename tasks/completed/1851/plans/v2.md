## Requirement + acceptance criteria

**Requirement:** a touched `.claude/skills/**/*.md` file must select every
test that pins its content by path reference. Today it selects NONE:
`.claude/skills/**/*.md` short-circuits at `WORKFLOW_SURFACE_GLOBS` (by
design — that skip is unchanged), and the only coverage channel is
`WORKFLOW_INVARIANT` membership, which newer pin tests were never added to.

**Measured gap (clarifier, 2026-07-31):** 72 test files reference
`.claude/skills/issue/SKILL.md`; 42 are invariant, **30 are silently
unselected** — including the three founding tests
(`tests/test_issue_skill_file_only_verdict_post.py`,
`tests/test_ensemble_review_cap.py`,
`tests/test_issue_skill_workload_cmd_script_pin.py`). Live repro:
`select_step9c_tests.py --map-files <list with .claude/skills/issue/SKILL.md>`
returns zero rows.

Acceptance criteria:

1. `--map-files` on a list containing `.claude/skills/issue/SKILL.md`
   returns all three founding tests (plus the other non-invariant
   referencing tests), each paired with the touched file.
2. `select_tests_with_reasons(['.claude/skills/issue/SKILL.md'], root)` on
   the live tree selects every referencing test with a
   `skills-pin:.claude/skills/issue/SKILL.md` reason (invariant members may
   carry it additionally — harmless, matches the rules-pin Step 9c arm).
3. WORKFLOW_INVARIANT members are EXCLUDED from the map-legs output (the
   `rules_pin_pairs` asymmetry — keeps the 2400 s
   `tests/test_workflow_lint.py` out of the Step 10d / inline gates).
4. Selection only GROWS (additive arm): no existing selection, WARN, or
   `untested_touched` behavior changes; the WORKFLOW_SURFACE skip for
   skills files is unchanged (a skills file never enters
   `untested_touched`).
5. A generative reachability pin test fails loudly if a future test that
   references a `.claude/skills/<skill>/SKILL.md` path is not
   selector-reachable for that SKILL.md's diff.
6. Token qualification: touching `.claude/skills/issue/SKILL.md` does NOT
   select a test that references only `.claude/skills/daily/SKILL.md`
   (bare-basename matching is degenerate for SKILL.md — every skill's file
   shares the basename — so tokens are skill-dir-qualified).

## Method delta (vs prior related work)

#1496 (rules-pin arm, same file) is the direct precedent: a DISCOVERED
text-scan arm, additive-only, fail-soft reads, invariant-excluded on map
legs. Delta: (a) target glob `.claude/skills/**/*.md` instead of
`.claude/rules/*.md`; (b) matching token is PATH-QUALIFIED, not bare
basename — `SKILL.md` as a basename token would match ~123 files
indiscriminately across all skills. Two textual forms are covered
(clarifier survey of the live tree):

- contiguous: `.claude/skills/issue/SKILL.md` (68 occurrences) — matched by
  the substring `skills/issue/SKILL.md` (the path relative to `.claude/`),
  which also covers the full-path form;
- path-join: `"skills" / "issue" / "SKILL.md"` (60 occurrences) — matched by
  a compiled regex over the path components with either quote style and
  `/` or `,` separators.

Known-miss class (accepted, same as rules-pin): a test that constructs the
filename dynamically. Over-selection is the safe direction (module
docstring), but token qualification keeps it bounded: measured worst-case
fan-out is 30 non-invariant files for the hottest skill file in the repo
(`.claude/skills/issue/SKILL.md`); next-hottest are far smaller
(`adversarial-planner` ~17 references incl. invariant members, `daily` ~15).

## File paths + concrete changes

All changes in ONE file + its test file (workflow surface; matches the
task's `workflow_fix_target`):

1. `scripts/select_step9c_tests.py`
   - New constant `_SKILLS_PIN_GLOB = ".claude/skills/**/*.md"` next to
     `_RULES_GLOB` (~L609). Matching via the existing `_matches_any` (which
     carries the `/**/` zero-segment collapse) so nested reference files
     under a skill dir are covered too.
   - New `def _skills_pin_tokens(rel_path: str) -> tuple[str, re.Pattern]`:
     given `.claude/skills/issue/SKILL.md`, return
     (`"skills/issue/SKILL.md"`,
     `re.compile(r'["\']skills["\']\s*[,/]+\s*["\']issue["\']\s*[,/]+\s*["\']SKILL\.md["\']')`)
     — components `re.escape`d; multi-segment skill paths join all
     components in order.
   - New `def skills_pin_hits(touched, work_root) -> dict[str, set[str]]`
     mirroring `rules_pin_hits` (~L612): filter touched via `_matches_any`
     against `_SKILLS_PIN_GLOB`; zero file reads when no skills file
     touched; one pass over `tests/**/test_*.py`; per-file hit when the
     contiguous token is a substring OR the join regex matches; same
     fail-soft per-file WARN + >5% aggregate WARN wording (adapted to
     "skills-pin").
   - New `def skills_pin_pairs(files, work_root) -> list[tuple[str, str]]`
     mirroring `rules_pin_pairs` (~L656): WORKFLOW_INVARIANT excluded;
     sorted pairs.
   - Diff path: in `select_tests_with_reasons` (~L1461), after the
     rules-pin seed, add the skills-pin seed:
     `for t, sk_files in skills_pin_hits(...): selected.setdefault(t, set()).update(f"skills-pin:{f}" ...)`.
     Additive-only; never sets `matched`; the WORKFLOW_SURFACE `continue`
     for the skills file itself is unchanged.
   - Map path: in the `--map-files` CLI composition, add
     `skills_pin_pairs(...)` alongside `rules_pin_pairs(...)` (locate the
     aggregation site in `main()`; same output shape
     `test<TAB>matched_path`).
   - Docs: add `'skills-pin:<touched file>'` to the reason enumerations
     (module docstring ~L53/L269, `select_tests_with_reasons` docstring
     ~L1434-1439) and extend the WORKFLOW_SURFACE_GLOBS comment (~L478) to
     name the new arm.
2. `tests/test_select_step9c_tests.py` (extend, following the rules-pin
   test shapes):
   - `test_skills_pin_live_tree_known_pairs`: on the live tree, a
     `.claude/skills/issue/SKILL.md` diff selects the three founding tests
     with a `skills-pin:` reason.
   - `test_cli_map_files_skills_pin_excludes_invariant`: an invariant
     member referencing SKILL.md does not appear on the map leg; a
     non-invariant one does.
   - Fixture tests (tmp-tree): contiguous form matches; join form (both
     quote styles) matches; a test referencing ONLY a different skill's
     SKILL.md is NOT selected (criterion 6); a touched non-skills .md does
     not trigger the scan.
   - `test_skills_pin_reachability_live_tree` (criterion 5): with an
     INDEPENDENT scan (own regex, not the arm's functions), enumerate every
     `tests/**/test_*.py` referencing `.claude/skills/issue/SKILL.md` in
     either textual form, and assert each is in
     `select_tests(['.claude/skills/issue/SKILL.md'], root)[0]` (union of
     invariant + arm). Keeps future pin tests from silently falling out.
