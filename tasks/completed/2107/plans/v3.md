# Plan v3 — #2107: scope the preflight branch-freshness fetch + raise its timeout

`kind: infra` (workflow-fix, fingerprint `109b2c35251b`). Zero GPU. Single-file
production change + regression pins.

## 1. Requirement

`src/explore_persona_space/orchestrate/preflight.py:355-356` runs a FULL-remote
`git fetch --quiet origin` with `timeout=15`. At the repo's current scale
(1,749 remote heads measured 2026-08-11; the body measured 192 s wall for the
full fetch, rc=0 — just slow) the fetch cannot finish inside the timeout, so
`fetch_failed=True` on every run. On `main` / detached HEAD that degrades to a
WARNING (fail-soft, lines 386-394 / 407-410); on a feature branch it is a hard
ERROR (lines 431-437) — so every issue-branch pod preflight FAILs even when the
branch is at 0 behind / 0 ahead. The task body's candidate diff: scope the
fetch to the refs actually compared and raise the timeout.

Measured grounding for the fix (this VM, 2026-08-11, 3 runs each):
- `git fetch --quiet origin main`: 0.44-0.46 s
- `git fetch --quiet origin issue-2000 main` (two-ref form): 0.43-0.45 s

## 2. Method delta

No parent experiment; pure infra. The delta vs the body's candidate diff
(which the body itself flags as incomplete):

1. **Hoist branch resolution above the fetch** (the body's dependent detail 1).
   Side-effect: when `rev-parse --abbrev-ref HEAD` fails, we now return
   (with the existing "could not determine current branch" WARNING) WITHOUT
   fetching. Strictly better: the fetch's only consumers are the behind
   checks, which that path skips anyway.
2. **Fetch BOTH refs the function compares** (the body's dependent detail 2,
   option "git fetch origin <branch> main"): every path compares
   `origin/main` (main path: ERROR-bearing; detached + feature paths:
   informational), and the feature path additionally compares
   `refs/remotes/origin/<branch>` (ERROR-bearing). Refspec composition:
   - `branch == "main"` or `branch == "HEAD"` → `fetch --quiet origin main`
   - feature branch → `fetch --quiet origin <branch> main`
   A bare-ref fetch updates the corresponding `refs/remotes/origin/*`
   remote-tracking ref (opportunistic update under the default fetch refspec),
   so all downstream `rev-parse --verify` / `rev-list` reads stay valid.
3. **Unpushed-branch degrade path** (NOT in the body's diff — verified
   empirically 2026-08-11: `git fetch origin <missing-ref> main` fails
   WHOLESALE, rc=128 `fatal: couldn't find remote ref <name>`, updating
   NOTHING). Without a degrade, an unpushed local branch — today a WARNING
   via the `rev-parse --verify` probe (lines 473-478) — would newly hard-ERROR
   at the fetch. Fix: when the feature-path fetch fails AND stderr matches
   `couldn't find remote ref <branch>` (the BRANCH ref specifically, matched
   against the exact name), re-fetch `main` only (same timeout) and let the
   existing `--verify` probe emit the standing unpushed-branch WARNING.
   Transport failures (any other stderr / the main-only re-fetch also
   failing) keep today's hard ERROR — A4 is not weakened: the ERROR fires
   exactly when the branch's own origin ref exists-or-may-exist but cannot
   be verified fresh.
4. **Timeout 15 → 90 s** on every fetch call (grounding §5).

Known accepted staleness (pre-existing, unchanged): neither the old full
fetch nor the scoped fetch prunes a deleted-upstream branch's stale local
remote-tracking ref (`--prune` is not passed today), so the `--verify` probe
can still succeed against a stale ref in that corner. Not a regression;
out of scope.

## 4. File paths + concrete diff sketch

### Edit 1 — `preflight.py::check_git_status` (lines ~348-375)

```python
    # Resolve the branch FIRST — the fetch refspec depends on it (#2107),
    # and a failed resolution skips the behind checks entirely.
    rc, branch, err = _run(["git", "-C", str(project_root), "rev-parse", "--abbrev-ref", "HEAD"])
    if rc != 0:
        report.add_warning(f"could not determine current branch: {err}")
        report.git_status += ", branch unknown"
        return
    branch = branch.strip()

    # Scoped fetch (#2107): fetch ONLY the refs this function compares —
    # origin/main always, plus the branch's own ref on a feature branch.
    # A full `git fetch origin` at 1,700+ remote heads takes ~190 s and
    # can never finish inside any sane preflight timeout.
    fetch_refs = ["main"] if branch in ("main", "HEAD") else [branch, "main"]
    fetch_rc, _, fetch_err = _run(
        ["git", "-C", str(project_root), "fetch", "--quiet", "origin", *fetch_refs],
        timeout=90,
    )
    if (
        fetch_rc != 0
        and branch in fetch_refs[:-1]
        and f"couldn't find remote ref {branch}" in fetch_err
    ):
        # Unpushed local branch: the branch ref does not exist on origin, and
        # git fails the WHOLE fetch (updating nothing). Re-fetch main so the
        # informational origin/main comparison stays fresh; the own-ref
        # --verify probe below emits the standing unpushed-branch WARNING.
        fetch_rc, _, fetch_err = _run(
            ["git", "-C", str(project_root), "fetch", "--quiet", "origin", "main"],
            timeout=90,
        )
    fetch_failed = fetch_rc != 0

    if branch == "main":
        _check_main_branch_behind(report, project_root, fetch_failed, fetch_err)
        return
    if branch == "HEAD":
        _check_detached_head_behind(report, project_root, fetch_failed, fetch_err)
        return
    _check_feature_branch_behind(report, project_root, branch, fetch_failed, fetch_err)
```

`_check_*_behind` helpers, the cluster skip (line 341-346), and the
porcelain check: byte-unchanged. Docstring gains one sentence on the scoped

## 6. Risks + stated assumptions

- **Side-effect narrowing.** The old full fetch refreshed ALL
  `refs/remotes/origin/*` as a side effect. Downstream consumers that need
  other branches fresh (crash-fix ancestry probes, sync helpers) all run
  their own explicit `git fetch origin <ref>` (verified: the ancestry-probe
  recipes in `.claude/rules/crash-fix-rounds.md` fetch explicitly), so no
  consumer relies on preflight's side effect. Assumption stated.
- **Behavior change on rev-parse failure** (§2 item 1): fetch now skipped.
  Benign; pinned by a new test.
- **Degrade-path stderr matching** is git-version-sensitive in principle;
  the `couldn't find remote ref` literal is stable across git 2.x (VM: 2.34.1,
  pods: newer 2.x) and the match is scoped to the exact branch name. On a
  future wording change the degrade path fails CLOSED (hard ERROR — today's
  behavior), never open.
