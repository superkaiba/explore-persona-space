# Plan — issue #1577: read-bounding PreToolUse hook for guard hook scripts

## 0.0 TL;DR (plain English)

- **What I'll build:** a small PreToolUse hook (`.claude/hooks/guard_trigger_dense_read.sh`) that blocks a full-file `Read` of any workflow guard script (the `scripts/guard_*.sh` + `.claude/hooks/guard_*` files, 9–128 KB each) while allowing the sanctioned windowed reads (≤120 lines) everyone already uses, with a one-variable escape hatch — plus its pin test and the settings.json registration.
- **What I expect:** the 2026-07-19 failure shape (a ~41K-token wholesale read of a 128 KB guard script paged into orchestrator context) becomes mechanically impossible without the override, and nobody's legitimate workflow changes — windowed reads pass untouched.
- **What would change my mind:** if the pin test shows any ordinary non-guard `Read` being denied or slowed, or if the hook can't tell a windowed read from a wholesale one from the tool-input JSON, I'd stop and rescope (kill criterion §8).

## 1. Goal + acceptance criteria

> Add a mechanical PreToolUse hook that bounds wholesale reads of guard hook scripts (byte/line cap + env override), mechanizing the READ channel of #1563's orchestrator-turn discipline on guard-surface rounds (the authored-text channel stays rule-side).

(Task #1577 `## Goal` H2, verbatim; `kind: infra` — no `goal:` frontmatter. Re-checked current at plan-return time; no `epm:goal-updated` markers.)

**Acceptance criteria** (this is a code change — no hypothesis):

1. A `Read` of any deny-set file with no `limit`, or `limit > 120`, is denied (exit 2) with a stderr message naming (a) the windowed-read recipe (grep-anchor first, then `Read` with `offset`/`limit ≤ 120`), (b) the `EPM_ALLOW_GUARD_READ=1` override, (c) the rule pointer `.claude/rules/trigger-dense-review.md § Orchestrator ordinary turns`.
2. A `Read` of a deny-set file with `limit ≤ 120` is allowed (exit 0), any `offset`.
3. `EPM_ALLOW_GUARD_READ=1` (session env) allows everything (exit 0).
4. Fail-open: malformed stdin JSON, jq unavailable, non-`Read` `tool_name`, or empty `file_path` → exit 0. A broken hook must never brick the Read tool fleet-wide.
5. Any `Read` of a non-deny-set path passes through untouched (exit 0), including files merely containing `guard_` outside the two guard directories.
6. The hook is registered in `.claude/settings.json` under a PreToolUse matcher covering `Read`, is executable, and the pin test asserts the registration end-to-end (the "ships green but inert" channel is closed).
7. All of the above are pinned by `tests/test_guard_trigger_dense_read.py` (fail-loud: each acceptance criterion has a named test — §6).

## 4. Design

**New files / edits:**
1. `.claude/hooks/guard_trigger_dense_read.sh` (new, executable; target ≲120 lines — it should be windowed-readable under its own cap).
2. `.claude/settings.json` — one new PreToolUse matcher group.
3. `tests/test_guard_trigger_dense_read.py` (new pin test, §6).

**Hook logic (pseudocode; stdin-JSON contract per the precedent):**

```
#!/usr/bin/env bash
# exit 0 = allow, exit 2 = deny. FAIL-OPEN everywhere: a broken guard must
# never brick the Read tool. Mechanizes trigger-dense-review.md
# § Orchestrator ordinary turns item 2 (single-call read channel only).

override = lowercase($EPM_ALLOW_GUARD_READ); if override in {1,true,yes}: exit 0
if ! command -v jq: exit 0                       # fail-open
input = $(cat) || exit 0
tool  = jq -r '.tool_name // empty'      <<< input  || exit 0
[ tool == "Read" ] || exit 0                     # defensive; matcher already scopes
fp    = jq -r '.tool_input.file_path // empty' <<< input || exit 0
[ -n fp ] || exit 0
case fp in *guard_*) ;; *) exit 0 ;; esac        # cheap pre-filter, no regex spawn
resolved = realpath -m -- fp 2>/dev/null || fp   # realpath-aware like the precedent
DENY_RE = '(^|/)(scripts|\.claude/hooks)/guard_[^/]+$'
(fp matches DENY_RE) || (resolved matches DENY_RE) || exit 0
cap   = ${EPM_GUARD_READ_CAP_LINES:-120}         # numeric-validated; junk -> 120
limit = jq -r '.tool_input.limit // empty' <<< input || exit 0
if limit is a positive integer and limit <= cap: exit 0   # windowed read: allow
echo "BLOCKED: unbounded Read of <fp> (<basename> is a trigger-dense guard
  script; wholesale reads page it into context — 2026-07-19: ~41K tokens).
  Read it windowed instead: Grep -n '<anchor>' <fp> to locate, then Read with
  offset=<line> limit<=<cap>. Counts/structure: wc -l, grep -c, git diff --stat.
  Rule: .claude/rules/trigger-dense-review.md § Orchestrator ordinary turns.
  Deliberate full read: EPM_ALLOW_GUARD_READ=1 (session env)." >&2
exit 2
```

**Deny-set definition (path ERE):** `(^|/)(scripts|\.claude/hooks)/guard_[^/]+$` — matched against BOTH the raw `file_path` and its `realpath -m` resolution (deny if either matches; realpath failure falls back to raw-only — fail-open). Covers: the 2 `scripts/guard_*.sh`, all 7 `.claude/hooks/guard_*` files (incl. the `.py` helper and this hook itself — self-coverage is desired and safe: the hook parses stdin only, it never Reads files, so no recursion), and worktree copies (`.claude/worktrees/issue-N/scripts/guard_x.sh` contains `/scripts/guard_x.sh` → matches). Dir-anchored, so a `guard_*`-named file elsewhere (e.g. `src/**/guard_*.py`, `tests/test_guard_*.py`) passes through.

**Cap semantics:** LINE cap only, default **120** (= the rule's "≤~120-line windows"), env-tunable via `EPM_GUARD_READ_CAP_LINES` (non-numeric/absent → 120). Deny iff deny-set match AND (`limit` absent OR non-numeric OR `> cap`). `offset` is irrelevant to the bound (any ≤cap window anywhere is fine). A byte cap is NOT enforced: the Read tool-input carries no byte information, and lines×~65 B/line (measured on the largest guard file) bounds bytes implicitly (~7.8 KB / ~2.5K tokens per max window). Note: `limit` present but non-numeric on an already-matched path → deny (the path match succeeded; this is not the malformed-input fail-open case, and the override exists).

**settings.json registration** — new group appended inside the existing `"PreToolUse"` array (after the line-137 group):

```json
{
  "matcher": "Read",
  "hooks": [
    {
      "type": "command",
      "command": "/home/thomasjiralerspong/explore-persona-space/.claude/hooks/guard_trigger_dense_read.sh"
    }
  ]
}
```

A dedicated `Read` group (rather than appending to the line-138 `Read|Bash|Grep|mcp__ssh__ssh_execute` group) keeps the hook off the hot Bash/Grep paths entirely and is self-documenting; overlapping matchers across groups are the established pattern (line 75 `Bash` and line 138 both match Bash).

**Scope decision — Read-only for v1 (Bash channel deferred):** the task Goal names the READ channel; the motivating incident was a Read-tool wholesale read; and the Bash channel (cat/head/sed of a guard file) is exactly where the precedent spends the majority of its 392 lines (a command tokenizer distinguishing bounded from unbounded access, including pipes and multi-command lines). Duplicating that for v1 is high complexity for a channel with no incident. Named residual channels, staying rule-side: Bash `cat`/`head`, `mcp__ssh__ssh_execute` pod-side reads, Grep `output_mode: content` with a broad pattern, and cross-turn window accumulation (rule item 3). If a Bash-channel incident recurs, that is a follow-up candidate, not silent scope creep.

**Other sessions' reads (the hook fires globally):** reviewers/implementers on guard-surface rounds legitimately read guard files — under the #1563 rule they must already do so windowed, and windowed reads pass by design. A deliberate full read (e.g. a guard-file rewrite round) uses `EPM_ALLOW_GUARD_READ=1`. Python-side readers (pytest, `verify_plan.py`, lint) use `open()`, not the Read tool — unaffected. The Edit tool (needs a prior Read) works with windowed reads; a full-file rewrite uses Write or the override.

## 5. Failure modes / risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| Legitimate full read of a small guard file denied (smallest member: 210 lines) | Medium (occasional) | Rule-consistent by design (the rule bans wholesale reads regardless of size); two windows or the env override cover it. Deny message names both. |
| Hook wedges ordinary Reads fleet-wide (bug / malformed input) | Low | Fail-open contract at every parse (`|| exit 0`), jq-availability check, non-Read tool → exit 0; pin tests for each fail-open path (§6). |
| Hook recursion / self-read | Nil | The hook never invokes the Read tool; hook-spawned subprocesses don't trigger PreToolUse. Self-coverage of the hook FILE by the deny-set is intentional. |
| Ships green but inert (matcher typo, wrong path, missing +x) | Low | `TestSettingsWiring`-style end-to-end test invoking the CONFIGURED command (precedent's exact pattern, incl. worktree prefix-remap). |
| Interaction with the line-138 group (same `Read` tool, two groups) | Low | Both groups run; each exits 0 fast on non-matching paths. Deny-sets are disjoint (banks vs guard scripts). No ordering dependence. |
| Latency on every Read call | Low | One jq spawn + a bash case pre-filter (~10 ms), same class as the 5 existing per-call hooks. Kill criterion §8 covers "measurably slowed". |
| Family-sync drift (hook lands without its pin test riding later diffs) | Low | Pin test named to the exact selector stem (§12 Selector registration); family convention (all 8 existing guard files have stem-matched tests) preserved. |
| This session's own implementer tripping the new hook mid-round | Low | The hook only binds after settings registration (new sessions); the implementer reads precedents windowed per the trigger-dense discipline anyway. |

## 11. Decision Rationale

- **Cap value = 120 lines.** What: deny threshold on `Read.limit`. Why: mechanizes the rule's own bound. Source: `.claude/rules/trigger-dense-review.md` § Orchestrator ordinary turns item 2 ("grep-anchored ≤~120-line windows"). Alternatives: byte cap (unenforceable from tool_input — no byte field); 250/500 lines (would allow reads the rule bans); making it non-tunable (rejected — `EPM_GUARD_READ_CAP_LINES` mirrors the family's env-tunability and lets the rule's "~" be adjusted without a code round).
- **Env override = `EPM_ALLOW_GUARD_READ=1`.** What: session-env escape hatch. Why: exact structural sibling of the precedent's escape. Source: `.claude/hooks/guard_harmful_bank_read.sh` `EPM_ALLOW_BANK_READ` (lines 93, 107-108). Alternatives: no override (rejected — guard-file rewrite rounds legitimately need full reads); an inline Bash-prefix form (moot — no Bash channel in v1).
- **Deny-set = `(^|/)(scripts|\.claude/hooks)/guard_[^/]+$`, raw + realpath.** What: dir-anchored basename family. Why: covers exactly the trigger-dense guard files (incl. the `.py` helper and worktree copies) without touching similarly-named test/library files. Source: the clarifier's verified inventory + the precedent's realpath-awareness. Alternatives: explicit path allowlist (rejected — a new guard hook would silently escape the set; the pattern is self-extending, matching the #1560-era family-sync spirit); including `tests/test_guard_*.py` (rejected — the pin tests are content-hygienic by convention and are legitimately read whole during review).
- **Matcher = dedicated `"Read"` group.** What: new PreToolUse group rather than appending to line-138. Why: v1 is Read-only; keeps the script off Bash/Grep/ssh hot paths; self-documenting. Source: settings.json precedent of tool-scoped groups (lines 116, 129). Alternatives: append to the line-138 group (works — the script exits 0 on non-Read — but runs ~4× more often for nothing).
- **Read-only scope (no Bash channel).** What: v1 bounds only the Read tool. Why: the Goal names the READ channel; the incident used Read; the Bash tokenizer is the bulk of the precedent's complexity for a channel with no incident here. Source: task #1577 `## Goal` + the precedent's structure. Alternatives: full precedent-parity Bash coverage (deferred as a named follow-up trigger — §4).
- **No sidecar deny log.** What: omit the precedent's best-effort log line. Why: minimal v1; the precedent's log served #866 forensics across sessions — a read-cap deny is visible in-session and needs no audit trail. Source: delta judgment vs `guard_harmful_bank_read.sh` (log at lines 111-117). Alternatives: mirror the log (cheap to add later if a tuning need appears).
- **Hook location = `.claude/hooks/`.** What: `.claude/hooks/guard_trigger_dense_read.sh`. Why: the family home for PreToolUse guards (6 of 8 live there; the two `scripts/` guards predate the dir). Source: file inventory. Alternatives: `scripts/` (rejected — family drift).
