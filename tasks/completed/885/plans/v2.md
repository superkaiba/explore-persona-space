## 4. Design

### 4.1 The core decision: stage-then-single-commit, per-file tail at STAGE time

**Decision: a new `_up_logs()` that (i) SELECTS files under `$WORKLOAD_ROOT/logs/**` newest-first up to `EPS_PERSIST_LOG_MAX_FILES`, (ii) STAGES each into `/tmp/eps-worker-logs/<relpath>` — tail-copying oversized files to the last `EPS_PERSIST_LOG_FILE_CAP_BYTES`, plain-copying the rest — and (iii) uploads the staged tree with ONE `api.upload_folder(...)` call.**

Rejected alternatives:
- **Per-file `_up_file` loop (v1 design):** violates the #664 gotcha — each `upload_file` triggers a server-side recursive tree-listing pre-check that 504s ~half the time on this repo (~160 s/file measured); 40 files ≫ the 300s budget, and because the sweep is ordered before the partial dirs, a 504-storm would starve the currently-working #854 artifacts. REJECTED (round-1 Must-Fix, methodology-reconciler binding).
- **`_up_dir` + `EPS_PERSIST_DIR_CAP_BYTES` reuse:** an oversized `logs/` dir (one vLLM-spam log routinely exceeds any dir cap) would SKIP wholesale, losing exactly the traceback this fix exists to save. REJECTED (unchanged from v1).
- **Hybrid (per-file upload of the single newest log first, then the folder commit):** a single per-file call still carries the ~50% listing-504 stall risk AHEAD of the folder commit — it can starve the very commit that carries everything. One call total is strictly safer. REJECTED.
- **Dispatcher-side conventions (tee workers into `workload.log`; move logs under swept dirs):** requires editing N experiment-side dispatchers, not durable for future dispatchers, interleaves 8 workers' output. Documented as a convention note in the rule file instead (§4.7).

Tailing at stage time keeps all three v1 virtues: (a) **300s safety** — payload bounded by arithmetic (≤40 × 5 MiB = 200 MiB staged bytes) AND upload fixed-cost bounded by construction (ONE commit); (b) **diagnosability** — the traceback is at the END of a log, which a tail keeps and a skip loses; (c) **heredoc code size** — ~35 lines of plain Python.

```python
# 1b. worker logs (#885) — fan-out dispatchers redirect the real traceback to per-worker
#     logs under $WORKLOAD_ROOT/logs/ (e.g. logs/issue_779/corpus_gpu0_all.log); the
#     canonical workload.log ends at the fan-out line. Newest-first, per-file TAIL cap at
#     stage time (the traceback is at the END of a log — an oversized file is tailed,
#     never skipped wholesale), file-count bound, then ONE upload_folder commit (NEVER a
#     per-file upload_file loop — the #664 504-storm gotcha). Runs BEFORE the partial
#     dirs so a worst-case timeout still lands the tracebacks.
def _env_int(name, default):
    try:
        return int(os.environ.get(name, default))
    except (TypeError, ValueError):
        _say(f"[crash-persist] WARN {name} malformed; using default {default}")
        return default
LOG_FILE_CAP = _env_int("EPS_PERSIST_LOG_FILE_CAP_BYTES", 5 * 1024**2)
LOG_MAX_FILES = _env_int("EPS_PERSIST_LOG_MAX_FILES", 40)
def _up_logs():
    logs_root = root / "logs"
    if not logs_root.is_dir():
        _say(f"[crash-persist] SKIP worker_logs: no such dir ({logs_root})")
        return
    if LOG_MAX_FILES < 1:
        _say(f"[crash-persist] SKIP worker_logs: EPS_PERSIST_LOG_MAX_FILES={LOG_MAX_FILES} < 1")
        return
    entries = []
    for dirpath, dirnames, filenames in os.walk(logs_root):
        dirnames[:] = [d for d in dirnames
                       if d not in PRUNE and not (d.startswith("g") and d.endswith("_dl"))]
        for f in filenames:
            p = Path(dirpath) / f
            try:
                st = p.stat()
            except OSError:
                continue
            entries.append((st.st_mtime, st.st_size, p))
    if not entries:
        _say("[crash-persist] SKIP worker_logs: empty after cache excludes")
        return
    entries.sort(reverse=True)  # newest first: the crashing worker wrote last
    dropped = len(entries) - LOG_MAX_FILES
    if dropped > 0:
        _say(f"[crash-persist] SKIP {dropped} older worker log(s) beyond"
             f" EPS_PERSIST_LOG_MAX_FILES={LOG_MAX_FILES}")
    staged_root = Path("/tmp/eps-worker-logs")
    n_staged = 0
    for _, _, p in entries[:LOG_MAX_FILES]:
        try:
            if log_path and p.resolve() == Path(log_path).resolve():
                _say(f"[crash-persist] SKIP worker_logs/{p.relative_to(logs_root)}:"
                     " is the canonical workload.log")
                continue
            rel = p.relative_to(logs_root)
            tmp = staged_root / rel
            tmp.parent.mkdir(parents=True, exist_ok=True)
            size = p.stat().st_size  # re-stat: file may have grown/shrunk since the walk
            with open(p, "rb") as fin, open(tmp, "wb") as fout:
                if size > LOG_FILE_CAP:
                    fin.seek(size - LOG_FILE_CAP)
                    _say(f"[crash-persist] TAILED worker_logs/{rel}:"
                         f" kept last {LOG_FILE_CAP} of {size} bytes")
                fout.write(fin.read(LOG_FILE_CAP if size > LOG_FILE_CAP else size))
            n_staged += 1
        except Exception as exc:
            _say(f"[crash-persist] FAILED staging worker log {p}: {exc}")
    if n_staged == 0:
        _say("[crash-persist] SKIP worker_logs: nothing staged")
        return
    try:
        _say(f"[crash-persist] uploading dir worker_logs ({n_staged} files, one commit)")
        api.upload_folder(folder_path=str(staged_root),
                          path_in_repo=f"{dest}/worker_logs",
                          repo_id=repo, repo_type="dataset")
        _say("[crash-persist] uploaded dir worker_logs")
    except Exception as exc:
        _say(f"[crash-persist] FAILED dir worker_logs: {exc}")
_up_logs()
```

The re-stat at open closes the stale-size window (a still-appending writer ≤CAP drift is benign; a shrunk file plain-copies). ### 4.3 Ordering decision

`crash_report.json` → `workload.log` → **`worker_logs/` staged tree, one commit (new)** → `eval_results_issue_<N>/` → `data_issue_<N>/` → `data_issue<N>/` → `workload_<ts>.log` → transcript LAST. The worker logs are the highest-value artifact after the canonical pair (they carry the actual traceback — the whole point of this task), size-bounded (≤200 MiB staged) AND commit-count-bounded (one call), while the partial dirs can be up to 2 GiB each; #854's small-first principle ("a worst-case timeout still lands it") places them before the dirs.

### 4.4 Exclusions

- The existing `PRUNE` dirnames prune applies inside `logs/` (defensive; caches are unlikely there).
- The canonical workload log (`EPS_LOG_PATH` = `<vm_scratch_dir>/logs/issue-<N>.log`, `log_path_for` at gcp.py:766–773) lives **outside** `$WORKLOAD_ROOT` (= `<vm_scratch_dir>/eps-issue-<N>`, `workload_dir_for` at :756–762), so no double-upload occurs by default; the `p.resolve() == Path(log_path).resolve()` skip is a one-line defensive guard for a nonstandard `EPS_LOG_PATH` (inside the per-file try — a resolve() failure degrades to a loud FAILED line, and broken symlinks were already excluded at the `p.stat()` OSError-continue).
- All regular files under `logs/` are eligible (not just `*.log`): fan-out dispatchers also write `.out`/`.err`/pid breadcrumbs; the count bound + tail cap keep this safe.
- `LOG_MAX_FILES < 1` → loud SKIP (documented disable semantics; never a silent empty sweep).

## 11. Decision Rationale

- **Stage-then-single-commit over per-file upload loop.** What: `_up_logs` stages selected (tailed/copied) files into `/tmp/eps-worker-logs/<relpath>`, then ONE `api.upload_folder`. Why: per-file `upload_file` triggers a server-side recursive tree-listing per call that 504s ~half the time on this large repo (~160 s/file measured in #664) — 40 calls ≫ the 300s budget and would starve the downstream #854 artifacts; `upload_folder` composes ONE `create_commit` with no per-file listing (verified on hub 0.36.2). Source: `.claude/rules/gotchas.md` § "Per-file `HfApi.upload_file` 504-storms on a LARGE repo" (#664); `_up_dir` in the same heredoc already demonstrates the `upload_folder` pattern (gcp.py:1406). Alternatives: per-file loop (rejected — the gotcha ban, round-1 Must-Fix); hybrid newest-log-per-file-then-folder (rejected — the single per-file call still carries the ~50% listing-504 stall risk ahead of the folder commit).
- **Tail-per-file at stage time over `_up_dir` dir-cap reuse.** What: per-file tail into the staged tree. Why: dir-cap SKIPs wholesale → loses the traceback; tail keeps the log END where tracebacks live. Source: #854's `_up_dir` cap semantics (gcp.py:1400–1403, "SKIP … oversized") + task-body sketch. Alternatives: `_up_dir` + `EPS_PERSIST_DIR_CAP_BYTES` (rejected — wholesale skip), `upload_folder` with `ignore_patterns` size filter alone (rejected — cannot tail; staging is what reconciles tailing WITH the single commit).
- **`EPS_PERSIST_LOG_FILE_CAP_BYTES` = 5 MiB.** Why: a traceback is KBs; 5 MiB keeps ~50k tail lines of context while bounding worst case. Source: task-body sketch ("keep the last ~5 MB per file"); naming mirrors the #854 `EPS_PERSIST_DIR_CAP_BYTES` precedent. Alternatives: 1 MiB (risks cutting long vLLM init context), 16 MiB (inflates worst case 3×).
- **`EPS_PERSIST_LOG_MAX_FILES` = 40, newest-first.** Why: #779's fan-out wrote ~10 log files; 40 = 4× headroom for multi-phase fan-outs; newest-first biases toward the crashing round's logs (residual: a crashed worker whose siblings keep appending can age past the bound in very wide fan-outs — documented, non-fatal at 4× headroom); 200 MiB staged ≈ 10–40 s upload as one commit. Source: #779 incident record + `issue779_dispatch_armb.sh` layout. Alternatives: 20 (tight for 8-GPU × multi-phase), unbounded (violates the 300s discipline).
- **Ordering: after `workload.log`, before partial dirs.** Why: highest diagnostic value after the canonical pair; bounded by construction while the dirs are up to 2 GiB each; #854's small-first principle. Source: gcp.py:1352–1356 comment. Alternative: after the dirs (rejected — a dir-upload timeout would then lose the tracebacks again).
- **Streamer print cap 60 → 120.** Why: corrected worst-case arithmetic ≈ 60 lines (40 staging + ~4 sweep-status + 2 folder-upload + ~16 existing) sits AT the old cap; 120 gives 2× margin; 120 × 2000 chars = 240 KB, well inside the GCE serial buffer. Source: gcp.py:1439–1442 + grep-verified absence of a `60` test pin. Alternative: folding TAILED into per-file upload lines (moot — staging has one line per file already; the folder upload adds only 2).
- **Guarded `_env_int` parse for the NEW knobs only.** Why: a malformed env value must not abort the whole persist (the persist is the last chance to save diagnostics); the existing `CAP` bare-`int()` is left untouched to avoid a smuggled behavior change (parity noted, not "fixed"). Source: #854 no-silent-skips discipline; Codex round-1 concern (F). Alternative: bare `int()` parity (rejected — 4 lines buy crash-proofing on the crash path itself).
