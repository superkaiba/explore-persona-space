## Requirement + acceptance criteria

**Requirement.** `scripts/bootstrap_pod.sh`'s step-4 git payload (the
double-quoted `ssh_cmd "` string spanning lines 249-364) must compose WITHOUT
executing any local command substitution from its embedded comment text, and a
mechanical regression guard must prevent the class from re-entering the file.

**Root cause (established, reproduced — `epm:clarify v1`).** Comment lines
262-263 inside the double-quoted payload carry raw backticks. To the LOCAL
composing bash a `#` inside a double-quoted string is not a comment, and
unescaped backticks are live command substitution at expansion time:

- line 263 backticks execute `sparse-checkout init --cone` locally →
  `scripts/bootstrap_pod.sh: line 364: sparse-checkout: command not found`
  (bash attributes expansion errors to the string's closing line, 364) — the
  observed #2061 provision error, byte-reproduced in a sandbox.
- line 262 backticks EXECUTE `git pull` locally in the invoking cwd on every
  provision — an unintended git mutation of the repo root / issue worktree —
  and substitute its stdout into the payload; multi-line pull output would
  land unprefixed lines into the remote script as executable garbage.

The missing-cone WARNING block (lines 356-360) is NOT dead — every `$(` in the
payload is correctly `\$`-escaped and transports intact. The task title's
"killing missing-cone warning" reading is refuted; the fix targets the real
defects above.

**Acceptance criteria.**

1. A whole-file quote-state scan of `scripts/bootstrap_pod.sh` reports ZERO
   live (unescaped) backticks inside double-quoted regions post-fix (pre-fix
   baseline: exactly 2, lines 262-263), AND zero live (unescaped) `$(` inside
   MULTI-LINE double-quoted regions (critic Must-Fix 1; the three intentional
   single-line top-level uses at lines 44/573/574 remain permitted).
2. A new pytest encoding that scan exists, PASSes post-fix, and demonstrably
   FAILs when a live backtick is reintroduced (asserted inside the test via a
   fixture string, so the failure mode stays covered without mutating the
   real file).
3. `bash -n scripts/bootstrap_pod.sh` passes (syntax unchanged).
4. The remote payload text is semantically unchanged: the fix touches only
   comment punctuation inside the payload; no executable payload line changes.
5. Composed-script probe (the body's stated alternative to a full provision):
   the clarifier's sandbox repro construct, updated to the fixed comment text,
   no longer emits `command not found`.
6. Ruff clean on the new test file; `workflow_lint.py --check-asks` unaffected
   (no `.claude/` edits).

**2. `tests/test_bootstrap_pod_payload_quoting.py` (new)** — a self-contained
quote-state scanner (~60 lines: top/comment/single-quote/double-quote state
machine honoring bash's dquote escape set ``$`"\`` + newline, and the
backtick escape set ``$`\``) with two tests:

- `test_no_live_backticks_in_double_quoted_regions`: scan
  `scripts/bootstrap_pod.sh`, assert the live-backtick-in-dquote event list is
  empty, printing offender line numbers on failure.
- `test_no_live_dollar_paren_in_multiline_dquote_regions` (critic Must-Fix 1):
  live `$(` events are banned inside double-quoted regions spanning MORE THAN
  ONE line (the ssh payloads); single-line dquote regions — the intentional
  top-level `VAR="$(...)"` assignments at lines 44/573/574 — stay permitted.
  A zero-false-positive discriminator needing no line allowlist; covers the
  likelier reintroduction vector (adding one more payload substitution and
  forgetting the backslash in `\$(...)`, which would silently execute
  locally).
- `test_scanner_detects_live_backtick`: run the same scanner over an inline
  fixture string reproducing the bug construct (`ssh_cmd "` + comment with
  backticks + closing quote) and assert it reports exactly one event — guards
  the scanner itself against silent decay. The fixture ALSO pins the file's
  hardest real constructs as NO-event cases (critic nice-to-have 1): the
  triple-escape backslash-backslash-backtick shape (line 293), an escaped
  `\$(...)`, and an apostrophe inside a dquote region — so a scanner bug
  that wrongly enters single-quote state cannot silently swallow banned
  events.

Deliberately NOT banned: `$()` inside SINGLE-LINE double-quoted regions (the
three intentional top-level `VAR="$(...)"` assignment uses at lines
44/573/574 — local substitution by design). Banned: backticks in ANY
double-quoted region (zero legitimate uses in this file) AND live `$(` in
MULTI-LINE double-quoted regions (the ssh payloads; critic Must-Fix 1).
