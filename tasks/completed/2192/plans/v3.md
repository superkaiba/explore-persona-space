# Plan v3 — #2192: `workflow_lint.py` merge-conflict-marker residue gate

(v3 folds in the round-1 critic REVISE: sparse-worktree/missing-on-disk
enumeration crash [Must-Fix 1] + all six non-blocking suggestions.)

## Requirement

Add a `workflow_lint.py` check, bundled into the no-flags default run, that
FAILs on merge-conflict-marker residue lines in tracked workflow-surface
files: `.claude/**/*.md`, `*.py` (repo-wide, tracked), and `CLAUDE.md` — the
exact file set the task body names. Escape hatches exist for files that
legitimately DOCUMENT markers (fencing for md; an explicit waiver comment for
py), never a weakened pattern.

Origin (task body): #2189 merge commit `14cd4e4211` left the diff3 base marker
`||||||| 640f206892` as the last line of `.claude/rules/code-style.md`; it
passed the no-flags lint, the size gate, the union-conservation check, ruff,
and 27 unrelated tests — caught only by a reviewer reading the diff by eye.

## Acceptance criteria

1. `uv run python scripts/workflow_lint.py --check-conflict-markers` emits one
   FAIL line per hit (`<path>:<line>: ...`) for each of the four marker forms
   (`<<<<<<< HEAD`, `||||||| <base>`, `=======` alone, `>>>>>>> <ref>`)
   planted in a target file, and exits non-zero; on the clean tree it PASSes.
2. The check is bundled into the no-flags default run (a bare
   `workflow_lint.py` invocation exercises it) AND registered in BOTH
   `_FILES_MODE_RUNNERS` and `CHECK_SCOPES` — the #2235 files-mode
   completeness check otherwise prints the FILES-MODE-REFUSED sentinel and
   exits 2, degrading the Step 9c / inline payload lint gate to its
   slow bare-full-run fallback (per `_run_files_mode`'s fail-closed
   contract — never silently skipped, but a fleet-wide slowdown).
3. Fenced regions (` ``` ` / `~~~`, per the module's `_FENCE_RE`) of `.md`
   files are exempt — the fence IS the sanctioned escape for
   marker-documenting prose (the task body's stated preference). For `.py`, a
   `# CONFLICT_MARKER_EXEMPT: <reason>` comment on the same or previous
   non-blank line waives a deliberate occurrence (reason non-empty).
4. Anchoring is exact: `========` (8 chars), `=======x`, `>>>>>>>>` (8), and
   mid-line occurrences are NOT flagged. The regex is the task body's:
   `^(<{7}|\|{7}|={7}|>{7})( |$)`, applied per line.
5. Baseline: the bare no-flags run stays green on the current tree
   (clarifier sweep 2026-08-19, independently re-verified by the round-1
   critic: zero matches over the full 4,652-file set — 1,093 tracked
   `.claude/**/*.md` + 3,558 `*.py` + `CLAUDE.md`).
6. New `tests/test_workflow_lint_conflict_markers.py` covers 1–4 plus the
   production-enumeration baseline (check returns `[]` on the live tree), and
   passes — INCLUDING under a sparse worktree (see the sparse-worktree
   robustness block in § Design; the enumeration-count floor is asserted on
   the INDEX-based `git ls-files` count, which is sparse-invariant, never on
   the on-disk scanned count).

Fail-loud pin: tests/test_workflow_lint_conflict_markers.py::test_planted_markers_flagged asserts check_conflict_markers returns a non-empty findings list for every planted marker form (never a silent [] swallow), and test_no_flags_bundling asserts the dispatch chain folds those findings into errors so main exits non-zero rather than silently passing.

## Method delta (vs sibling checks)

- Closest sibling: `check_grep_qv` (fence-aware md scanning, `roots` test
  override, no-flags bundling). Fence semantics are INVERTED: grep_qv scans
  ONLY fenced blocks; this check SKIPS fenced blocks and scans everything
  else.
- Enumeration is by `git ls-files` (tracked-only), not `rglob` — new for this
  module but required by the Goal's own wording ("tracked"): an rglob over
  the repo would descend into `.claude/worktrees/` (whole sibling checkouts,
  possibly legitimately mid-merge) and `.venv`/untracked scratch, none of
  which this gate may police.

## Design

**Regex** (module-level constant):

```python
_CONFLICT_MARKER_RE = re.compile(r"^(<{7}|\|{7}|={7}|>{7})( |$)")
```

**Enumeration** — `_conflict_marker_target_files(roots)`:
- Production (`roots=None`):
  `git -C <repo-root> ls-files -z -- '.claude/**/*.md' '.claude/*.md' '*.py' 'CLAUDE.md'`,
  parsed on NUL, wrapped in `_files_scope_filter(...)` (files-mode speed
  contract, #2235). The extra `'.claude/*.md'` pathspec closes the depth-1
  gap: under git's default (non-`:(glob)`) matching, `.claude/**/*.md` does
  NOT match a depth-1 `.claude/foo.md` (critic-verified via a `docs/**/*.md`
  probe; zero such files exist today — future-proofing only).
  On a git-subprocess failure: loud stderr notice +
  fail-open `[]` — the `check_plan_version_immutability` precedent ("never a
  silent skip"); a broken git env must not block every commit fleet-wide.
- **Sparse-worktree / missing-on-disk robustness (round-1 critic Must-Fix 1):**
  `git ls-files` reads the INDEX, which in a sparse worktree still lists
  skip-worktree entries absent from disk (measured: the plan's pathspec set
  yields 4,072 index entries in `.claude/worktrees/i1739-fit`, of which 142
  are on-disk-absent — sparse-excluded `external/` + `eval_results/` py).
  The enumeration therefore FILTERS to on-disk files (`p.is_file()`), and the
  per-file scan additionally skips a `FileNotFoundError` (covers the #2015
  transient unstaged-delete window at the shared root). An on-disk-only scan
  loses nothing this working-tree gate can police. Without this filter, the
  Step 9c full-suite gate (which runs in sparse worktrees by design,
  `tests/sparse_cones.txt` / #671) would CRASH on every sparse worktree.
- Test override: `roots` lists files, or directories walked for `*.md` +
  `*.py` (the `_grep_qv_target_files` convention); a `roots` entry absent
  from disk is skipped, not raised on.
- Confirmed intended (task-body design note): `tests/**` and `scripts/**`
  are covered via the `*.py` glob, as are `src/`, `external/`, `eval_results/`
  py files — a conflict marker in ANY tracked py file is residue we
  committed, wherever it lives.

**Scan** — `check_conflict_markers(*, roots=None) -> list[str]`:
- `read_text(encoding="utf-8", errors="replace")` (markers are ASCII; a
  vendored file with odd bytes must not crash the lint), `splitlines()`.
- `.md` files: skip lines inside fences via the `_FENCE_RE` simple-toggle
  idiom (existing precedent at the historical-ref check, ~line 3797;
  unterminated trailing fence ⇒ trailing lines stay skipped — see residuals).
- `.py` files: scan all lines; suppress a hit when the same or previous
  non-blank line carries `# CONFLICT_MARKER_EXEMPT:` with a non-empty reason.
- FAIL line shape (incident-citing, module convention):
  `{path}:{lineno}: merge-conflict marker residue ('{token}') — a
  mis-resolved merge left this in a tracked workflow-surface file (#2189:
  diff3 base marker '|||||||' committed to .claude/rules/code-style.md
  survived every gate). Resolve the merge; if this line deliberately
  DOCUMENTS a marker, fence it (md) or add '# CONFLICT_MARKER_EXEMPT:
  <reason>' (py).`

**Wiring (7 sites, all in `scripts/workflow_lint.py`):**
1. Module-docstring entry for `--check-conflict-markers` ("also bundled into
   the no-flags default run"), matching the existing per-check block format.
2. The regex + `_conflict_marker_target_files` + `check_conflict_markers`
   (place near `check_grep_qv`).
3. `parser.add_argument("--check-conflict-markers", ...)`.
4. Add `args.check_conflict_markers` to the `no_flags = not (...)`
   disjunction.
5. Dispatch chain: `if args.check_conflict_markers or no_flags:
   errors.extend(check_conflict_markers())` — appended in chain order.
6. `_FILES_MODE_RUNNERS["check_conflict_markers"] = lambda wf:
   check_conflict_markers()` — at the SAME chain-order position (the dict is
   declared "IN CHAIN ORDER").
7. `CHECK_SCOPES["check_conflict_markers"] = CheckScope("path-local", <surfaces>)`.
   Surfaces = the honest read set. The check reads `.claude/` md, `CLAUDE.md`,
   and tracked `*.py` under `scripts/`, `tests/`, `src/`, `external/`,
   `eval_results/`, `eps/`, `tasks/`, `figures/`, `eval/`, `experiments/`.
   IMPLEMENTER VERIFICATION ITEM: read `_run_files_mode` to confirm whether
   path-local `surfaces` are consumed (vs informational); mirror whichever
   convention holds, defaulting to listing the py-bearing top-level dirs +
   `.claude/` + `CLAUDE.md` explicitly. Default-to-path-local is the
   documented safe direction (path-local runs scoped = safe).

**Known residuals (document in the check docstring):**
- (a) Fence-toggle blindness: an unterminated/imbalanced fence skips trailing
  md content; a conflict hunk that itself breaks fence parity can hide the
  inner `=======` separator — the outer `<<<<<<<`/`>>>>>>>` lines are still
  caught when outside fences. The #2189 incident line (last line of the file,
  outside any fence) is caught.
- (b) A setext-H1 underline of EXACTLY 7 `=` would flag — the repo uses ATX
  headings throughout (baseline sweep: zero hits); remedy is ATX conversion,
  never a pattern weaken.
- (c) An exactly-7-char RST underline in a py docstring would flag — baseline
  clean; the waiver comment is the escape.
- (d) A REAL conflict landing wholly inside a BALANCED fence (both merge
  sides editing one fenced snippet — plausible in fence-dense
  `.claude/rules/*.md`) hides all four marker lines by design. This is the
  escape's designed cost: scanning inside fences would flag every legitimate
  marker-documenting snippet. Name it in the check docstring alongside (a).

**Self-flag hazard (binds this diff's own files):** `workflow_lint.py` and the
new test file are themselves tracked `*.py` in the scan set. Neither may place
a marker token at column 0 of its source — construct all fixture content
programmatically (`"<" * 7 + " HEAD"`, `"=" * 7`, etc.), never as raw
column-0 literals (the wrapped-literal lesson from the agent-memory corpus).
This binds PROSE surfaces too: the module-docstring per-check entry and the
argparse help string are column-0 text when wrapped — no wrapped line may
start with a marker form. The tracked plan-handoff copy
`.claude/plans/issue-2192.md` (if written) is in the md scan set — keep
marker forms backticked mid-line or fenced there.

## Tests (in the new file; fixtures via `tmp_path` + `roots` override)

1. Each of the 4 marker forms in a `.py` fixture → 4 FAIL lines with correct
   `path:line`.
2. Each of the 4 forms in an `.md` fixture OUTSIDE fences → flagged; the SAME
   lines inside a ``` fence → not flagged; `~~~` fence → not flagged.
3. Anchoring negatives: 8-char runs, `=======x`, mid-line token, `> > > >`
   blockquote → not flagged; bare `=======` at EOL → flagged.
4. `# CONFLICT_MARKER_EXEMPT: reason` on previous non-blank line (py) →
   suppressed; empty reason → NOT suppressed.
5. Unterminated fence: content after a lone opener is skipped (pins residual
   (a) so a future behavior change is deliberate).
6. Production baseline: `check_conflict_markers()` (no roots) returns `[]` on
   the live tree AND the INDEX-based enumeration (raw `git ls-files -z` count
   over the check's pathspecs, BEFORE the on-disk filter) is > 4,000 files
   (pins that enumeration isn't silently empty — a zero-file enumeration
   would be a vacuous PASS, the silent-pass class the agent-memory corpus
   flags). The floor is asserted on the index count because it is
   sparse-worktree-invariant; the on-disk scanned count varies by cone.
7. Missing-on-disk robustness: an enumeration entry absent from disk (roots
   injection of a nonexistent path) is skipped without raising, and findings
   for present files are still returned (pins critic Must-Fix 1 both ways).
8. Git-failure fail-open: enumeration pointed at a non-git dir emits the loud
   stderr notice and returns `[]` (pins the fail-open contract).
