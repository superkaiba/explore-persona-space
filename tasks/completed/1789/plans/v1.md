## Method delta

The exclusion exists to skip only PRESCRIBED spec-freshness sync commits when deciding whether a workflow family carries branch-side feature edits. It currently keys on the bare substring `spec-freshness`, which any wf-fix deliverable ABOUT the sync machinery legitimately carries in its subject — a fail-open clobber vector (the inverse of the guard's fail-safe design). Delta: key on the prescribed sync-commit subject shape `sync workflow-surface specs from`, carried verbatim by:

- current: `issue-<N>: sync workflow-surface specs from origin/main (spec-freshness)` (#1747)
- historical: `issue-<N>: sync workflow-surface specs from main (spec-freshness)` (pre-#1747)

Deliberately NOT matched: the legacy `chore(issue-<N>): spec-freshness sync workflow surface from main` (different word order). Legacy sync commits will read as branch-side edits → family dirty → sync skipped (Step 5a / 10d) or Guard-3 conservative. Fail-safe by design; no live branch is expected to carry chore-form sync commits (that subject predates #1560, and issue worktrees are short-lived — the stale-worktree audit reaps them).
