## 4. Design

### 4.1 Where the new probe fires — sequence in `process_item`

The new closed-sibling probe is a SIBLING (not a replacement) of `find_landed_fix_suspects` and fires in the SAME slot: the last dedup-family check before any mutation (`process_item:1463`). Order: **#1674 commit-subject probe FIRST, closed-sibling probe SECOND.** Rationale: #1674's probe is the incumbent, byte-unchanged; running it first preserves every existing test verbatim (the incident #1652 replay `test_landed_fix_replay_1652_incident_pair_suppresses` still fires on the #1674 arm, so it stays byte-identical). When #1674 SUPPRESSES, the closed-sibling probe never runs — one terminal outcome per item, one ledger row. When #1674 does NOT suppress (below threshold, subject vocabulary divergent, or git error fail-open), the closed-sibling probe runs and can suppress independently.

Consequence: the two probes are OR-combined at the process-item level (either can suppress); they never combine evidence. This is deliberate — each probe's threshold + arms were calibrated on its own population.

### 4.2 Match grain — PATH-only blocks, title-only advisory

The plan calls `recent_closed_workflow_fix_tasks(target_file=item["target"], candidate_title=item["title"])` with defaults (`days=7.0`, `include_plain_infra=True`) and inspects each returned hit's `matched` list:

- **BLOCKING arms:** `"target"` (prefixed pass, anchored `workflow_fix_target:` overlap) and `"infra-target"` (widened pass, candidate FULL path token as body substring). These are PATH-based — the strongest signal that the closed sibling actually addresses the same file the candidate wants to touch.
- **ADVISORY arms:** `"title:<tokens>"` (prefixed, >=1 shared informative title token) and `"infra-title:<tokens>"` (widened, >=2 shared tokens). These fire on informative-title overlap alone; the helper docstring warns of the "unmeasured FP surface on closed-task titles" (the same open question the task body flags). Title-only hits print a driver stderr advisory line — verbatim shape parallel to `_print_advisory_forward` — but do NOT suppress the filing.

**Defense of block-vs-advisory split** (Design decision 2 from the brief):
- **Not "Full" (block on any arm):** the helper's own docstring for the widened pass explicitly calls out that a short directory-less `target_file` (e.g. `CLAUDE.md`) substring-matches more bodies than the measured directory-bearing range. Blocking on `title:*` alone would collide with the FP surface flagged in the body's open question. On the 3/3 measured incidents, the PATH arm is sufficient — a `target` or `infra-target` match exists in every case (verified in dry-run smoke, §7).
- **Not "Strict" (target only, no infra-target):** the widened pass IS where the #1386/#1360 class lives (a non-prefixed closed infra task with a landed fix); `include_plain_infra=True` is the whole point of the #1446 widening. Dropping `infra-target` would blind the probe to exactly the vocabulary-divergent class #1674 cannot see, defeating the plan.
- **Not "Split-severity" (two ledger outcomes):** mirroring #1674's ONE terminal ledger outcome (`landed-fix-suspect`) plus ONE `--retry-suspects` override is the tighter contract: same eyeball workflow, same override flag, one ledger schema — no downstream tool has to reason about a second outcome name. The path-vs-title split lives in the SUPPRESS-vs-ADVISE decision, not in a second outcome.
- **The kill criterion (§6):** if the dry-run smoke shows the path arm's FP rate is meaningfully >0%, we fall back to Split-severity — but the default is the tight one-outcome design.

### 4.3 Ledger outcome shape — reuse `landed-fix-suspect`

The new probe's terminal ledger row is the SAME `landed-fix-suspect` outcome the #1674 probe writes. Ledger row shape (extended, not new):

```json
{

  "outcome": "landed-fix-suspect",
  "suspects": [                                  // NEW arm's shape (differs from #1674)
    {"kind": "closed-sibling", "id": 1600, "title": "workflow-fix: ...",
     "status": "completed", "target": "scripts/foo.py", "closed_at": "2026-07-22T...",
     "matched": ["target"]}
  ],
  "threshold": null,                             // NEW: probes without a token threshold
  "window": "7 days ago",                        // reused CLOSED_SIBLING_WINDOW_DAYS -> string form
  "paths": ["scripts/foo.py"],
  "fp": "<fp>",
  "route": 2
}
```

`suspects` gains a `kind` discriminator on the NEW arm's entries — `{"kind": "commit-subject", ...}` on #1674 hits, `{"kind": "closed-sibling", ...}` on the new arm's hits. Existing tests read `suspects[0]["sha"]` on the #1674 shape; adding a `kind` FIELD (not renaming existing keys) is additive and byte-preserves the #1674 rows only if I ALSO write `kind: "commit-subject"` into them. **Two options for source-compat:**

- **Option A (RECOMMENDED):** the NEW arm writes `suspects: [{"kind": "closed-sibling", "id": ..., "title": ..., "target": ..., "closed_at": ..., "matched": [...]}]` and the #1674 arm's ledger row is UNCHANGED (no `kind` on `{sha, subject, shared}`). Rows are structurally distinguishable by the presence of `sha` (commit-subject) vs `id` (closed-sibling). All existing #1674 tests remain byte-identical (row-shape equality checks like `test_landed_fix_probe_suppresses_filing:1974` still pass verbatim). No key drift; no risk.
- Option B: write `kind: "commit-subject"` into the #1674 row too and update every equality-check test. Higher blast radius; rejected.

Option A wins. `_has_landed_fix_suspect_row` and `_slug_state`'s `"landed-fix-suspect" in outcomes` check both key on `outcome` alone (not on `suspects`'s inner shape), so both probes' rows are indistinguishable to the resume/retry state machine — one `--retry-suspects` re-drives BOTH probes together.

### 4.4 New probe function — signature + fail-open

```python
# scripts/daily_drive_filings.py — new section right after the #1674 helpers

# ── #1711 mechanical closed-sibling probe ────────────────────────────────────
# Reuses the #1446 recent_closed_workflow_fix_tasks helper. Fires ALONGSIDE the
# #1674 commit-subject probe as the belt-and-suspenders backstop for the
# vocabulary-divergent landed-fix class (#1386/#1360). Window matches #1674 +
# the compose-time clause-(a') duty + the #1446 advisory window.
CLOSED_SIBLING_WINDOW_DAYS = 7.0
CLOSED_SIBLING_MAX_HITS = 5  # ledger-row size bound; helper already sorted DESC by closed_at

# Arms of the helper's returned `matched` list that BLOCK a filing (PATH-based).
# `title:*` / `infra-title:*` fire an advisory line but never suppress — the
# FP surface on closed-task titles is unmeasured (task #1711 body's open question).
_CLOSED_SIBLING_BLOCKING_ARMS = ("target", "infra-target")


def find_closed_sibling_suspects(item: dict) -> tuple[list[dict], list[dict]]:
    """Recently-closed infra siblings overlapping the item's target/title (#1711).

    Returns (blocking_hits, advisory_hits): each is a list of dicts filtered from
    task_workflow.recent_closed_workflow_fix_tasks() by whether any matched arm
    is in _CLOSED_SIBLING_BLOCKING_ARMS. Blocking hits carry PATH-based match
    (target / infra-target); advisory hits carry TITLE-only match (title / infra-title).

    Reuses the #1446 helper verbatim — its own error surface (per-task read
    failures skip; empty inputs return []) is unchanged. Caller wraps in
    _closed_sibling_or_none for the broad fail-open.
    """
    from explore_persona_space.task_workflow import recent_closed_workflow_fix_tasks
    hits = recent_closed_workflow_fix_tasks(
        item["target"], item["title"], days=CLOSED_SIBLING_WINDOW_DAYS
    )
    blocking = [h for h in hits if any(m.split(":", 1)[0] in _CLOSED_SIBLING_BLOCKING_ARMS
                                        for m in h["matched"])]
    advisory = [h for h in hits if h not in blocking]
    return blocking[:CLOSED_SIBLING_MAX_HITS], advisory[:CLOSED_SIBLING_MAX_HITS]


def _closed_sibling_or_none(item: dict) -> tuple[list[dict], list[dict]]:
    """Fail-open wrapper (#1711): any error WARNs loudly and files as today.

    BROAD Exception catch (deliberate) — the helper reads the registry + N task
    body files + parses events.jsonl; the error surface is broader than a single
    git subprocess. Same rationale as _route3_dup_or_none (#1483): a held item
    is never lost to a scan bug; the loud stderr WARNING is the fail-loud channel.
    """
    try:
        return find_closed_sibling_suspects(item)
    except Exception as e:  # deliberate fail-open, see docstring
        print(
            f"WARNING {item['slug']}: closed-sibling probe skipped"
            f" ({e.__class__.__name__}: {e}) — fail-open, filing proceeds; the"
            " compose-time clause-(a') duty + #1674 commit-subject probe still apply (#1711)",
            file=sys.stderr,
        )
        return [], []


def _closed_sibling_outcome(
    item: dict, *, dirpath: Path, fp: str, dry_run: bool
) -> str | None:
    """Closed-sibling probe outcome for process_item, or None (mirror of
    _landed_fix_suspect_outcome's contract, #1711). Routes 2 AND 3.

    - No hits at all -> None (caller proceeds to file).
    - Advisory-only hits (title/infra-title arms) -> print ONE stderr advisory
      line naming top hit, return None (caller proceeds to file).
    - Blocking hits (target/infra-target arms) -> print CLOSED-SIBLING-SUSPECT
      line; real path appends terminal landed-fix-suspect ledger row and returns
      'landed-fix-suspect'; dry-run returns 'skip' (read-only).
    """
    blocking, advisory = _closed_sibling_or_none(item)
    slug = item["slug"]
    # Print advisory-only hits first (never suppresses; visible on both paths).
    for h in advisory:
        arms = ",".join(h["matched"])
        print(
            f"CLOSED-SIBLING-ADVISORY {slug} -> #{h['id']}"
            f' "{h["title"]}" (matched: {arms}) — title-only, NOT blocking (#1711)',
            file=sys.stderr,
        )
    if not blocking:
        return None
    if not dry_run:
        append_row(
            dirpath,
            {
                "slug": slug,
                "outcome": "landed-fix-suspect",
                "suspects": [
                    {
                        "kind": "closed-sibling",
                        "id": h["id"],
                        "title": h["title"],
                        "status": h["status"],
                        "target": h["target"],
                        "closed_at": h["closed_at"],
                        "matched": h["matched"],
                    }
                    for h in blocking
                ],
                "threshold": None,
                "window": f"{CLOSED_SIBLING_WINDOW_DAYS} days",
                "paths": sorted(_target_tokens(item["target"])),
                "fp": fp,
                "route": item["route"],
            },
        )
    top = blocking[0]
    more = f"; +{len(blocking) - 1} more" if len(blocking) > 1 else ""
    print(
        f'CLOSED-SIBLING-SUSPECT {slug} -> #{top["id"]}'
        f' "{top["title"]}" (matched: {",".join(top["matched"])}{more}) — NOT filing;'
        " eyeball the sibling, re-run with --retry-suspects to file anyway (#1711)"
    )
    return "skip" if dry_run else "landed-fix-suspect"
```

### 4.6 CLI + resume/retry semantics

- **`--retry-suspects` flag: REUSED verbatim.** The existing flag already re-drives any slug whose only terminal row is `landed-fix-suspect` (`_slug_state:1240`, `suspect_eyeballed` short-circuit at `process_item:1412`). Since both probes write `outcome: "landed-fix-suspect"` (Option A above), one flag covers both. No new CLI flag needed. Update the flag's help text to name both probes.
- **`_has_landed_fix_suspect_row` semantics: UNCHANGED.** It reads `outcome == "landed-fix-suspect"` only; both probes' rows are treated identically.
- **`_slug_state` state machine: UNCHANGED.** ERROR-vs-suspect priority stays: a slug with both an ERROR row and a suspect row needs `--retry-errors --retry-suspects` to re-drive (`_slug_state:1226-1231` docstring covers this verbatim).
- **`--dry-run` semantics: UNCHANGED contract.** Read-only, no ledger writes, prints planned action. The new probe's `dry_run=True` path calls the helper (which is read-only: registry read + task-body reads) and prints CLOSED-SIBLING-SUSPECT / CLOSED-SIBLING-ADVISORY lines without writing.

### 4.7 Fail-open placement (Design decision 4)

Three failure surfaces + their disposition:

- **Helper's per-task failures** (missing folder, non-numeric registry key, unreadable body): already handled by `recent_closed_workflow_fix_tasks` internally (skip that task, continue scan). No new code needed.
- **`_load_registry()` failure or `find_task_path()` failure at helper top level:** the helper wraps these; they either surface as `IOError`/`ValueError` or the helper itself skips. Caught by the top-level `try/except Exception` in `_closed_sibling_or_none` (broad catch, deliberate, mirrors `_route3_dup_or_none:849`'s pattern for the same reason: broader error surface than a single git subprocess).
- **A bug INSIDE `find_closed_sibling_suspects` itself** (e.g. `TypeError` from a helper contract change): the broad catch WILL swallow it — this differs from #1674's narrow enumerated tuple (which propagates non-subprocess bugs, `test_landed_fix_probe_non_enumerated_exception_propagates:2071`). RATIONALE: the closed-sibling probe reads the whole registry + N body files; a `TypeError` from a helper-signature drift or a body-YAML surprise is materially likelier than in a single `git log` call, and fail-open toward filing is preferable to a driver crash that leaves the whole daily-fix batch un-filed. The #1483 route-3 dedup uses the identical broad-catch reasoning (`_route3_dup_or_none:849` docstring — verbatim: "broad Exception catch is DELIBERATE, mandated by the task's fail-open constraint … same pattern class as _check_body_shas (#1467), widened because the token/YAML surface has a broader error space than the enumerable I/O classes there").
