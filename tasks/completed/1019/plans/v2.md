### D5. Env knob (in `llm/anthropic_client.py`, next to `deadline_from_expires_at`)

```python
DEFAULT_BATCH_STUCK_HOURS = 4.0

def batch_stuck_threshold_hours() -> float | None:
    """EPS_BATCH_STUCK_HOURS semantics: unset or empty string -> DEFAULT_BATCH_STUCK_HOURS
    (4.0); a parseable float <= 0 -> None (stuck check DISABLED, restoring the pure
    deadline-bounded behavior); a parseable float > 0 -> that threshold in hours.
    A malformed value raises ValueError immediately (fail loud, never a silent default).
    Read per poll step (never frozen at import) so long-lived processes and tests see
    the live environment."""
    raw = os.environ.get("EPS_BATCH_STUCK_HOURS", "").strip()
    if not raw:
        return DEFAULT_BATCH_STUCK_HOURS
    val = float(raw)  # ValueError propagates
    return val if val > 0 else None
```

Placed in `anthropic_client.py` because both poll modules already import from it and it closes no import cycle (judge_dispatch deliberately avoids top-level `batch_judge` imports, line 115–117).

```python
# Stuck-batch escape (#1019, incident #810): zero succeeded after the threshold
# -> persist escape INTENT, then cancel; partial results are harvested on a later
# iteration when the API flips canceling -> ended (docs-confirmed); canceled ids
# re-dispatch SYNC, keyed on the INTENT marker (which survives every crash ordering).
stuck_hours = batch_stuck_threshold_hours()
if (
    stuck_hours is not None
    and sb.get("stuck_cancel_intent_at") is None  # escape entered at most once
    and counts is not None                        # fail-safe: no counts, no verdict
    and counts.succeeded == 0
):
    anchor = sb.get("submitted_at") or state.get("created_at")
    if anchor is not None:
        elapsed_h = (now_fn() - _dt.datetime.fromisoformat(anchor.replace("Z", "+00:00"))
                     ).total_seconds() / 3600.0
        if elapsed_h >= stuck_hours:
            logger.warning(
                "STUCK BATCH: %s at succeeded=0 after %.1fh (threshold %.1fh; "
                "processing=%s errored=%s) — canceling; unprocessed items will "
                "re-dispatch on the SYNC path (#810 escape)",
                sb["batch_id"], elapsed_h, stuck_hours,
                counts.processing, counts.errored,
            )
            _cancel_stuck_sub_batch(client, sb, state, state_path, now_fn)

# Escape-intent RESUME leg: intent persisted but cancel never confirmed (crash
# between the intent write and the cancel/confirm writes) -> re-drive the cancel.
# Bounded: the race guard accepts canceling/ended, so this converges in one step.
elif sb.get("stuck_cancel_intent_at") is not None and sb.get("stuck_canceled_at") is None:
    _cancel_stuck_sub_batch(client, sb, state, state_path, now_fn)
```

`_cancel_stuck_sub_batch` (new module-private helper; **intent-first crash-safe ordering** — the INTENT marker is persisted BEFORE the external cancel call, so no crash ordering can leave a canceled batch whose `canceled` ids lack their retry discriminator; the reconciled Phase 2 Must-Fix #1):

```python
def _cancel_stuck_sub_batch(client, sb, state, state_path, now_fn) -> None:
    """Persist escape intent, cancel the stuck sub-batch, confirm.

    Ordering is load-bearing (#1019 critic round 1):
      1. persist ``stuck_cancel_intent_at`` (the retry DISCRIMINATOR — written
         BEFORE the external side effect, so a crash at ANY later point still
         routes this sub-batch's ``canceled`` ids to the sync retry, even when
         the resume's first retrieve already reads ``ended`` and the normal
         ended-harvest path runs before the stuck check);
      2. ``batches.cancel`` (race guard below);
      3. persist ``stuck_canceled_at`` (cancel-confirmed observability stamp;
         its absence on resume re-drives step 2, which is idempotent-safe
         because the guard accepts ``canceling``/``ended``).
    """
    import anthropic as anthropic_mod
    if sb.get("stuck_cancel_intent_at") is None:
        sb["stuck_cancel_intent_at"] = now_fn().strftime("%Y-%m-%dT%H:%M:%SZ")
        _atomic_write_json(state_path, state)   # intent durable BEFORE the cancel
    try:
        client.messages.batches.cancel(sb["batch_id"])
    except anthropic_mod.APIStatusError:
        # Race / re-drive: the batch may already be canceling (a prior cancel —
        # ours after a crash, or an out-of-band Console cancel) or ended. BOTH
        # are accepted cancellation outcomes: the poll loop harvests at ended
        # either way. Anything else re-raises (fail fast, no swallowed faults).
        final = client.messages.batches.retrieve(sb["batch_id"])
        if final.processing_status not in ("canceling", "ended"):
            raise
        logger.info(
            "Cancel of %s raced with state %s; accepted as canceled",
            sb["batch_id"], final.processing_status,
        )
    sb["stuck_canceled_at"] = now_fn().strftime("%Y-%m-%dT%H:%M:%SZ")
    _atomic_write_json(state_path, state)
```

After the cancel the function RETURNS; the enclosing `_poll_and_collect_sub_batches` loop keeps polling (30 s → ×1.5 → 120 s backoff), sees `canceling` (not `ended`; the stuck check is skipped via the `stuck_cancel_intent_at` guard), then `ended`, then harvests via the untouched `_harvest_sub_batch`. No new polling loop, no new sub-batch status value — `status` stays `submitted` → `collected`; both stuck fields are orthogonal optional fields. **Telemetry (frozen-counts fingerprint):** `_harvest_sub_batch` logs, for a sub-batch with `stuck_cancel_intent_at` set, `n_succeeded` vs `n_canceled` at harvest — nonzero succeeded harvested after a 0-counts cancel is the direct signature of frozen/stale `request_counts` (a false-positive fire), turning §12 A5's "first production fire self-documents the regime" into an explicit log signal.

**Anchor note:** `submitted_at` is written at submit (`_submit_one_sub_batch`, line 636). One reconcile path (crash-between-create-and-status-flip, `_run_batch_path` lines 843–855) leaves it `None`; the fallback anchor `state["created_at"]` (always set at init) is conservative-early by at most the create latency — acceptable because the escape is cheap and safe. Tests inject `now_fn`; a fake clock earlier than the real `submitted_at` yields negative elapsed → no fire (safe).

## 11. Decision Rationale

1. **Stuck threshold default = 4.0 h.**
   *What:* `DEFAULT_BATCH_STUCK_HOURS = 4.0`. *Why:* wide margin both ways — healthy judge shards (≤2k requests) clear in minutes (500-request shards ~5 min; the wedge signature in both incidents was hours at zero), and the docs say most batches finish < 1 h, so 4 h ≈ 4× the documented typical worst case while cutting the #810 park from 16–24 h to 4 h. *Source:* #810 incident (16 h at 0/2001; recovery 39,512 calls / 18 min at ~1400 RPM, zero errors — task body + origin_prompt) + the #658 G1 wedge comment (`batch_judge.py:49-53`: ~500-request shard ~5 min, 8k shard 9 h at succeeded:0). *Alternatives:* 1–2 h (rejected: eats the batch discount on merely-slow batches; docs allow ~1 h typical); 8 h (rejected: halves the rescue value on an overnight run). Value is env-tunable, so the default is not load-bearing beyond being sane.
2. **Predicate lives per-sub-batch in `_poll_one_sub_batch_step`, after the overdue check.**
   *What/Why:* the deadline machinery is already per-sub-batch with per-sb persisted state; placing the stuck check there inherits resume-for-free and touches one function. Overdue-first ordering preserves every #663 deadline contract byte-for-byte and keeps `BatchDeadlineExceeded` the hard outer bound. *Source:* #663 plan structure (commit `b991488a42`); verified test fake shapes (`StuckBatchClient` `request_counts=None`). *Alternatives:* a dispatch-level watchdog task (rejected: second concurrency surface, duplicate state) ; checking inside `_poll_and_collect_sub_batches` (rejected: loses per-sb counts context already retrieved).
3. **Canceled ids join the EXISTING retry machinery, route pre-pinned to sync.**
   *What/Why:* `_run_or_resume_retry` already handles errored/expired resumable retries with a persisted route pin; canceled-by-us requests are docs-confirmed never-sent-to-model (same safety class as expired), so they slot into the same channel; pre-pinning `routed_path="sync"` at retry-state creation reuses the existing `force_sync=pinned_route=="sync"` line — zero new retry logic, deterministic on resume. Sync (not re-batch) because re-batching a canceled remainder re-enters the same queue that just wedged, while sync is the demonstrated escape. *Source:* #810 recovery numbers (manual cancel + `force_sync` — this change mechanizes exactly that); #663 pin machinery (`judge_dispatch.py:1006-1018`). *Alternatives:* immediate inline sync dispatch at cancel time (rejected: bypasses the retry state machine → new crash-resume surface + violates retry-once accounting); re-batch with smaller shards (rejected: unproven, re-wedge risk).
4. **Out-of-band cancels keep the no-retry contract.**
   *What/Why:* retry only when `sb["stuck_cancel_intent_at"]` is set — a deliberate human Console cancel keeps meaning "stop, don't respend". Preserved by the T13 gate-level negative test (dropping the guard fails T13 while every other test stays green — the round-1 battery could not detect that mutant). *Source:* #663 `_collect_batch_results` contract ("canceled / unknown → user-initiated terminal"); Phase 2 statistics reconcile. *Alternative:* retry all canceled (rejected: silently overrides an operator decision).
7. **Two-field escape protocol: intent BEFORE the cancel side effect; confirm stamp after; race guard accepts `canceling`/`ended`.** (v2 — the reconciled Must-Fix union.)
   *What:* `stuck_cancel_intent_at` persisted before `batches.cancel` is the sole retry discriminator + entered-once guard; `stuck_canceled_at` is a cancel-confirmed observability stamp whose absence re-drives the cancel on resume; the `APIStatusError` guard re-retrieves and ACCEPTS `canceling` or `ended` (persist stamp, proceed), re-raising anything else. *Why:* durable-intent-before-external-side-effect is the only ordering under which EVERY crash cell routes canceled ids to the sync fallback — in particular the crash-after-cancel/resume-at-`ended` cell, where the ended-harvest precedence runs before any stuck check can re-fire (round-1 design silently degraded to terminal error dicts there); and accepting `canceling` removes the design's hidden reliance on server-side cancel idempotency (the round-1 guard re-raised on the API's own documented post-cancel state, converting the benign resume into a crash-until-ended loop). *Source:* Phase 2 alternatives + methodology reconciled verdicts (both REVISE); Anthropic docs §2 quote (`canceling` is the expected post-cancel state). *Alternatives:* single post-cancel marker (rejected: the exact round-1 hole); treating `canceling` as retry-later instead of accepted (rejected: adds a poll state for no benefit — the enclosing loop already waits for `ended`).
5. **Legacy path gets cancel + error dicts, not a sync fallback.**
   *What/Why:* bounded blast radius on a signature-stable historical path with no retry machinery; error-dict rows are already its convention for terminal non-success; new callers are lint-forced through the router. *Source:* `_submit_and_poll_batch` docstring (#663, "signature-stable for the two live scripts/issue_389 callers"); `workflow_lint --check-batch-judge-client` (CLAUDE.md autonomous-mode bullet). *Alternative:* typed `BatchStuckCanceled` raise (rejected: throws away harvested partials and turns a recoverable state into a crash for callers that never opted into new exception types); out of scope entirely (rejected: 15 lines buys the same 24 h→4 h bound there).
6. **Env knob semantics (`<=0` disables; malformed raises).**
   *What/Why:* a rollback knob that restores pre-change behavior without a deploy; malformed config raising at first poll step follows the project fail-fast rule (no silent defaults). *Source:* fail-fast Critical Rule (CLAUDE.md); precedent `EPM_VLLM_GREEDY_CHUNK_SIZE`-style env knobs in `gotchas.md`. *Alternative:* silently fall back to 4.0 on parse failure (rejected: hides a typo'd threshold for 16 h — the exact failure class this task exists to kill).
