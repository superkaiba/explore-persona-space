## 4. Design

**File:** `tests/test_workflow_lint.py` (ONLY file touched).

**Deleted:** the entire function
`test_workflow_lint_pipe_python_bundled_in_no_flags` (lines 2122–2132,
def line + docstring + `_run()` call + assert).

**Added in its place (same location, keeping the pipe-python test cluster
contiguous):**

```python
def test_pipe_python_bundled_in_no_flags_source_pin():
    """NON-VACUOUS no-flags bundling pin (#1233; the #712 §4f
    opt-in-not-bundled shipping class): `check_pipe_python` must be
    dispatched by the BARE ``workflow_lint.py`` run. Source-inspection
    assert on the dispatch branch + the no_flags detection-tuple
    membership — the prior exit-0-on-a-clean-tree assert was vacuous (a
    clean tree exits 0 whether or not the check is dispatched) and
    burned a redundant full no-flags subprocess run
    (``test_workflow_lint_default_exits_zero`` keeps the behavioral
    clean-tree cover; the planted-offender function tests above cover
    detection)."""
    src = _LINT.read_text(encoding="utf-8")
    assert re.search(
        r"if args\.check_pipe_python or no_flags:\s*\n"
        r"\s*errors\.extend\(check_pipe_python\(\)\)",
        src,
    ), "check_pipe_python is not dispatched on the no-flags branch"
    assert "or args.check_pipe_python" in src, (
        "--check-pipe-python is missing from the no_flags detection tuple"
    )
```

No new imports needed: `re` (line 22) and `_LINT` (line 30) are already
module-level in the test file.

**Decision: source-dispatch pin ONLY — no planted-offender no-flags CLI
run.** Justification against the brief's three axes:

- **(a) Non-vacuousness:** the regex + tuple asserts fail the moment
  either dispatch surface is edited away (§5 mutation check). Composition
  gives full effective coverage: function tests prove `check_pipe_python`
  detects planted offenders; the source pin proves the no-flags branch
  calls it; `test_workflow_lint_default_exits_zero` proves the no-flags
  run executes end-to-end on the clean tree.
- **(b) Suite wall-time:** a planted-offender no-flags CLI run cannot be
  scoped — the no-flags branch calls `check_pipe_python()` with NO args
  (workflow_lint.py:10300), scanning the repo `scripts/` dir; there is no
  `--scripts-dir` CLI flag, so planting an offender would require mutating
  the shared repo tree mid-test (racy across concurrent sessions,
  unacceptable) or adding a CLI flag to `scripts/workflow_lint.py` (out of
  the stated one-file scope). It would ALSO add a second full-tree lint
  subprocess. The chosen design instead REMOVES one (the `_run()` call in
  the deleted test; `_run()` is uncached, verified).
- **(c) Consistency with in-file exemplars:** BOTH bundling-pin exemplars
  use the source-pin pattern, neither uses a planted-offender CLI run —
  for exactly reason (b). This plan adopts exemplar 2's regex form (pins
  the dispatch branch SHAPE, not just token presence — strictly stronger
  than exemplar 1's substrings) plus the tuple-membership substring both
  exemplars share.

## 11. Decision Rationale

- **Assert pattern: regex dispatch-branch pin + tuple-membership substring.**
  What: `re.search(r"if args\.check_pipe_python or no_flags:\s*\n\s*errors\.extend\(check_pipe_python\(\)\)")`
  plus `"or args.check_pipe_python" in src`.
  Why: pins both surfaces that must co-exist for bundling (dispatch branch
  AND no_flags detection tuple); the regex form additionally pins that the
  branch actually CALLS the check, which substrings alone do not.
  Source: exemplar `test_check_hub_dir_filecount_bundled_in_no_flags`
  (tests/test_workflow_lint.py:3449–3462) + #712 §4f + #1233 body.
  Alternatives: substring-only (exemplar 1 form,
  `test_push_failure_swallow_bundled_in_no_flags_source_pin`:2619) —
  weaker, does not pin the `errors.extend` call; rejected since the
  stronger form already exists in-file and costs nothing.
- **No planted-offender CLI-run component.**
  What: replacement is source-pin only; the deleted `_run()` call is not
  replaced by any subprocess.
  Why: no-flags CLI is unscopeable to a tmp dir (dispatch calls
  `check_pipe_python()` argless, workflow_lint.py:10300; no `--scripts-dir`
  CLI flag); detection is already covered by 8 planted-offender function
  tests (lines 2012–2097); both exemplars made the same call.
  Source: exemplar test names above; #1233 body's constraint list;
  verified dispatch line workflow_lint.py:10299–10300.
  Alternatives: mutate the real `scripts/` dir in-test (racy on the shared
  VM — rejected); add a CLI scoping flag (scope creep into
  workflow_lint.py — rejected).
- **Delete-and-replace rather than augment.**
  What: the vacuous test is removed, not kept alongside the pin.
  Why: its only assert is duplicated verbatim by
  `test_workflow_lint_default_exits_zero` (line 99); keeping it burns one
  full uncached no-flags lint subprocess per suite run for zero marginal
  coverage (Supersede → delete the old version, code-style rule).
  Source: `_run()` definition (lines 89–96, uncached — read); line 99
  test (read); #1233 body.
  Alternatives: keep both (wall-time cost, zero coverage gain — rejected).
