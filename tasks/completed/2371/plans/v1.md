## 1. Requirement + acceptance criteria

**Requirement.** `.claude/hooks/guard_root_code_commit.sh`'s per-record cwd-mover disarm
(`CWD_MOVER_LEAD_ERE`, line ~313; disarm site ~1119) recognizes a leading plain
`NAME=value` assignment-prefix group before the mover family (the #2357 r5 fix). Two
other text-detectable prefixed mover forms ride the armed canonical `&&` chain
undetected, so a root commit whose relative pathspec resolves off-root is wrongly
permitted (scoped) instead of degraded to the whole-index read:

1. **Append-assignment prefix** — `FOO+=bar . ./script` (the group's `NAME=` atom does
   not match `+=`).
2. **Wrapper-keyword prefix** — `time . ./script` (`time` is a shell keyword outside
   both the prefix group and the mover family; `builtin`/`command` are family members
   and already match at the wrapper word itself).

Both are block-direction gaps (fail-closed once caught), execution-confirmed during
#2357 round 5: on the r5 guard, `cd <root> && FOO+=bar . env.sh && git commit -- p`
and `cd <root> && time . env.sh && git commit -- p` from a subdir cwd permit (rc=0)
where the fix must block (rc=2).

**Shell-reachability facts (execution-confirmed 2026-08-18, GNU bash 5.1.16 on this
VM — the guard's execution shell; probe: dot-source a script whose body is
`cd sub`, then read `pwd`):**

| Form | Sources in current shell (moves cwd)? | Disarmed today? |
|---|---|---|
| `. x` / `source x` | yes | yes (family lead) |
| `builtin . x` / `command . x` | yes | yes (family word matches at lead) |
| `NAME=v . x` (r5) | yes | yes (r5 prefix group) |
| `NAME+=v . x` | **yes** | **no — gap 1** |
| `NAME+='a b' . x` (quoted value) | **yes** | **no — gap 1b (masked-lead arm)** |
| `time . x` | **yes** | **no — gap 2** |
| `time -p . x` | **yes** | **no — gap 2b** |
| `time NAME=v . x` (interleave) | **yes** | **no — gap 2c** |
| `env . x` | no (external `env` cannot run the `.` builtin) | n/a — pin as not-reachable |
| `NAME=v time . x` | no (`time` in non-keyword position runs external) | n/a — pin as not-reachable* |

*`NAME=v time . x` will nonetheless match the extended grammar (assignment atom then
wrapper atom) and disarm — deliberate block-direction over-tightening, consistent with
the guard's existing "a record that merely mentions mover vocabulary also disarms"
contract; pinned as blocked, not exempted.

## 2. Method delta (vs parent #2357 r5)

r5 added a zero-or-more plain `NAME=value` assignment-prefix group before the mover
family alternation, matched on raw AND masked lead. This task widens ONLY the prefix
group's atom set: (a) the assignment atom tolerates an optional `+` before `=`
(append-assignment); (b) a second atom recognizes the `time` keyword wrapper (bare or
`time -p`); atoms repeat zero-or-more in any interleaving. DISARM-side only — no new
mover family members, no whole-record-screen change, no change to arming/re-arming or
`cd_nonroot`. Over-matching is safe by design (a disarm only degrades scoping to the
fail-closed whole-index read); the allow chains are unaffected because the group
still requires the stripped lead to end at a mover family word.

## 3. File paths + concrete diffs

**File 1 — `.claude/hooks/guard_root_code_commit.sh`:**

- `CWD_MOVER_LEAD_ERE` (line ~313), current prefix group
  `([A-Za-z_][A-Za-z0-9_]*=[^[:space:]]*[[:space:]]+)*` becomes an alternated atom
  group of the shape:

  ```
  (([A-Za-z_][A-Za-z0-9_]*[+]?=[^[:space:]]*|time([[:space:]]+-p)?)[[:space:]]+)*
  ```

  (POSIX ERE; `[+]?` for the literal plus; `time` gets word-boundary safety from the
  group's mandatory trailing whitespace — `timeout ...` cannot match. Exact spelling
  may be refined at implementation; the c30-family executed differentials are the
  arbiter, not the spelling.)
