## Requirement + acceptance criteria

**Requirement (from the task Goal):** a session must not end with its terminal
commits unconfirmed on origin — `completed`/`epm:done` existing only locally is
a crash-window. `sync_repo_root.py` exit 0 deliberately includes
`state=in-flight` ("your push has NOT landed; re-run after the in-flight sync
completes", sync_repo_root.py L33-35/L155/L1664); the retry duty belongs to the
caller, and `.claude/skills/issue/SKILL.md`'s Terminal-teardown section
(currently a 3-step sequence: CRON-TEARDOWN → `set-status completed` →
`epm:done`) states no such duty. Incident #1792 (2026-07-29): the in-flight
advisory printed at 13:20:47Z, teardown followed at 13:20:59Z with no re-run;
the terminal commits reached origin only via concurrent sessions' pushes.

**Acceptance criteria:**
1. The `#### Terminal teardown (code-change path only)` section of
   `.claude/skills/issue/SKILL.md` gains a **step 4 "Terminal landing
   confirmation (#1868)"**: a bounded (2-attempt) `sync_repo_root.py` re-run
   whose LANDED arbiter is a fetched-origin blob check (the task's canonical
   `events.jsonl` on `origin/main` carries `"epm:done"`), never the helper's
   exit code — the same arbiter-not-exit-code doctrine as the post-merge
   guard's unpushed-mv pre-check.
2. On still-unconfirmed after the bound: fail LOUD (one echo + one
   `epm:progress` note `terminal-landing-unconfirmed`), never a multi-hour
   poll (#1317 anti-pattern), never a block/reversal of the `completed`
   transition (the next successful fleet sync is the named backstop).
3. The Terminal-failure branch's "Run the SAME three-step sequence" is updated
   to the four-step sequence (the landing confirmation runs on the
   terminal-failure arm too).
4. A pin test (`tests/test_issue_skill_terminal_landing_pin.py`) pins the
   step's presence, placement (inside the Terminal-teardown span), and
   load-bearing phrases on whitespace-normalized text; it is registered in
   `scripts/select_step9c_tests.py` `WORKFLOW_INVARIANT` and
   `tests/step9c_workflow_invariant_manifest.txt` (the #1855 convention).
5. No-flags `workflow_lint.py` + the mapped pin tests pass on the landing
   tree (the Step 10d pre-push gate enforces this at merge).

Fail-loud pin: tests/test_issue_skill_terminal_landing_pin.py — asserts the UNCONFIRMED arm's loud echo + the terminal-landing-unconfirmed marker token are present in the span, so a silent-swallow rewording of the unconfirmed arm fails the pin test.

## Method delta (what differs from prior related work)

Prior related work covers adjacent sites, not this one: form (2) of the
bare-push snippets documents that sync exit 0 can mean in-flight and points
guard-critical pushes at the post-merge guard's "landing-verified form"; the
post-merge guard's unpushed-mv pre-check (#1300) and local-residue tail use
the bounded-2-attempt + mechanical-re-check-as-arbiter shape; the #1725
pre-marker syncs are deliberately fail-soft (their duty is guard-argv
freshness, not durability). The DELTA: the terminal-teardown site — the last
actions a code-change session takes — gets its own landing-confirmation duty,
because it is the one site where "the next re-entry will fix it" does not
hold (the session ends; the resume row for `completed`+`epm:done`+`epm:merged`
is a no-op) and where the unlanded state is precisely the task's terminal
record.

1. **`.claude/skills/issue/SKILL.md`** — in `#### Terminal teardown
   (code-change path only; runs AFTER epm:merged v1 has been posted)`
   (~L13727):
   - Append step **4. Terminal landing confirmation (#1868; incident #1792)**
     after step 3 (`epm:done`), with an executable block of this shape
     (implementer refines wording; semantics binding):

     ```bash
     # Runs as the session's FINAL act — after every terminal marker post
     # this session makes (the §5 post_step_completed.py record included).
     REPO_ROOT=$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)")
     CANON=$(realpath --relative-to="$REPO_ROOT" \
       "$(uv run python "$REPO_ROOT/scripts/task.py" find <N>)")
     LANDED=no
     for ATTEMPT in 1 2; do
       uv run python "$REPO_ROOT/scripts/sync_repo_root.py"
       timeout --kill-after=30s 120s git -C "$REPO_ROOT" fetch origin main --quiet || true
       if git -C "$REPO_ROOT" cat-file -e "origin/main:$CANON/events.jsonl" 2>/dev/null \
          && git -C "$REPO_ROOT" show "origin/main:$CANON/events.jsonl" \
             | grep -qF '"epm:done"'; then
         LANDED=yes; break
       fi
       if [ "$ATTEMPT" -eq 1 ]; then sleep 20; fi   # let an in-flight sibling sync finish
     done
     if [ "$LANDED" = no ]; then
       echo "[step10d] terminal landing UNCONFIRMED after 2 bounded sync attempts — completed/epm:done exist only locally (crash-window; #1792); next successful fleet sync is the backstop"
       uv run python "$REPO_ROOT/scripts/task.py" post-marker <N> epm:progress \
         --note "terminal-landing-unconfirmed after 2 bounded sync_repo_root attempts (state=in-flight or transport) — completed status mv + epm:done not yet observed on origin/main; next successful fleet sync carries them (#1868)"
     else
       echo "[step10d] terminal landing CONFIRMED on origin/main (attempt $ATTEMPT)"
     fi
     ```

     Prose around the block states: (a) the exit-0-on-in-flight contract +
     caller-owned retry duty (cite sync_repo_root.py L33-35); (b) the arbiter
     is the fetched-origin blob check, never exit codes (the post-merge
     guard's doctrine); (c) bounded by construction — never a multi-hour
     poll; (d) the unconfirmed note is itself a local commit that rides the
     next successful sync (self-describing residual); (e) nothing here blocks
     or reverses `completed`; (f) KEPT-stash surfacing duty (#1751) applies
     to these sync invocations like every other.

     Critic-round refinements (folded from the round-1 APPROVE advisories;
     binding on the implementer):
     - **Empty-CANON guard:** mirror the post-merge guard's `[ -z "$CANON" ]`
       arm — a failed `task.py find` resolution echoes its own distinct
       diagnostic and does NOT post the `terminal-landing-unconfirmed` note
       (a resolution failure is not a landing failure; never post the
       misleading note).
     - **Note wording:** the `epm:progress` note says "completed status
       move + epm:done", not "status mv" — keep git-verb tokens out of
       `--note` argv prose (#1722/#1756 convention).
     - **Re-entry residual (named in prose):** a later `/issue <N>`
       re-entry that retries the merge (resume row `completed` + `epm:done`
       + no `epm:merged`) posts fresh markers whose landing this step-4
       (already run) does not re-confirm — and a prior round's `epm:done`
       on origin would satisfy the arbiter regardless. Acceptable: in that
       state the terminal record is already durable on origin (the incident
       class this fix closes), and the fleet-sync backstop carries the
       fresh commits; name this residual explicitly in the step-4 prose.
   - Update the Terminal-failure branch: "Run the SAME three-step sequence"
