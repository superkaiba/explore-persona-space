### 3. Design

All edits land in `.claude/agents/codex-critic.md` only. Five edits, two per bug plus a Rules cross-reference.

**Edit A — Bug #1, composer-side numeric-grounding rule (new sub-step in Step 3, "Compose the lens-specific prompt", inserted after the existing "This template deliberately carries NO per-lens enumerations…" paragraph at line ~132).** Add:

> **Composer numeric-grounding rule (load-bearing — closes the #722 fabricated-numbers bug).** The ONLY plan content you place in the prompt is the verbatim `{{plan_body}}` substitution and the verbatim `{{lens_items}}` / `{{prior_critique_summaries}}` the orchestrator handed you. You MUST NOT author, paraphrase, "restate for context", or inline ANY numeric / predicted / effect-size value (e.g. `+0.74`, `MLP -2.17`, a row count, an expected log-prob) that you sourced from your own general context, your memory, a scratch artifact you happen to see, an `eval_results/` JSON, or any artifact the brief did not hand you. Codex critiques the plan AS WRITTEN; a number not in `plan_body` is not the plan's claim and corrupts the critique. If you believe a load-bearing number is *missing* from the plan, do NOT supply it — that absence is itself a finding Codex will raise from `plan_body` alone.

*Why it closes the bug:* the #722 failure was the composer treating a number from a side note / cache as if it were in the plan under review. This names the exact prohibited sources and reduces the composer's authored numeric content to zero — Codex sees only the verbatim plan.

**Edit B — Bug #1, executable verification at Step 4 (new check after the `cat > ... <<'PROMPT'` block, mirroring the code-review twin's Step-3 grep guards).** Add a Bash verification that asserts every number in the composed prompt that is NOT inside the inlined `{{plan_body}}` / `{{lens_items}}` / `{{prior_critique_summaries}}` spans is part of the FIXED template scaffold (the bar text, the output schema, the marker version). Proposed shape:

> **Verify no composer-authored numbers leaked into the prompt.** Extract every numeric token from the composed prompt that falls OUTSIDE the inlined `plan_body` span; each must match a number present either in the fixed template scaffold (the static bar / schema / example text this spec defines) or in `{{lens_items}}` / `{{prior_critique_summaries}}` / `{{revision_round}}`. Concretely: write `plan_body` to `$PLANBODY_FILE`, write the composed prompt to `$PROMPT_FILE`, then run a small `uv run python` pass that collects `re.findall(r'-?\d+\.?\d*', prompt)` for the prompt, subtracts (multiset) the numbers found in `plan_body` + `lens_items` + the known-static template constants (the `0`/`50` in the bar examples, the `1`/`2` rung counts, `{{revision_round}}`), and FAILS LOUD (`echo "BLOCKER: composer-authored number <n> not traceable to plan_body" >&2; exit 1`) on any residual number. On BLOCKER the composer re-composes from `plan_body` alone; it never hand-edits the number in.

The exact regex/allowlist is the implementer's to finalize; the contract is: **a number in the prompt outside the verbatim plan substitution that does not trace to the plan or the static scaffold fails the compose, loud.** This is a prompt-composition / brief-validation action (writes + greps temp files), not a Codex dispatch — compose-only is preserved.

*Why it closes the bug:* turns Edit A from aspirational into mechanical — the #722 number would have tripped `exit 1` at compose time instead of reaching Codex.

**Edit C — Bug #2, snapshot-staleness disclaimer in the Step 3 prompt template (edit the template body, near the `PRIOR CRITIQUES (this lens, prior rounds):` block at line ~180-181, and the `PLAN TEXT:` header at line ~177).** Add a pinned-snapshot line into the template Codex receives:

> `SNAPSHOT NOTE: This prompt reflects the plan body and prior-critique timeline AS HANDED TO THE COMPOSER at spawn. It MAY be behind the on-disk state by the time your verdict is read (a later revision or a newer critique round can land meanwhile). Scope every verdict to THIS snapshot — disclaim it as "based on the plan + prior critiques as of this round's spawn", flag a number/claim ONLY against what is written above, and NEVER REVISE on the suspicion that newer state exists. The orchestrator owns reconciliation against the freshest markers.`

*Why it closes the bug:* the two stale-read REVISEs came from Codex treating its snapshot as live. This makes the snapshot's as-of boundary explicit in the prompt and forbids a REVISE premised on un-handed state, which is exactly the false-REVISE shape the bug produced.

**Edit D — Bug #2, composer-side note in "When You Are Spawned" (after the brief field list at line ~91).** Add one paragraph telling the composer how it KNOWS the snapshot may be stale and what it does about it, since the composer does not dispatch Codex and cannot re-read state:

Your one freshness obligation is to PIN the snapshot boundary into the composed prompt (the `SNAPSHOT NOTE` in Step 3) so Codex scopes its verdict to what it was given and never REVISEs on the suspicion of newer state.

*Why it closes the bug:* names the staleness explicitly for the composer (the brief's question 3-(ii) "how the COMPOSER knows") while staying strictly inside compose-only — no re-read, no dispatch.

### 5. Risks / failure modes

- **Over-strict numeric check blocks legitimate restatements (Edit B).** The composer legitimately restates `{{revision_round}}` and the static bar examples (e.g. the `>50`/`<50` thresholds, "cap 2"). *Mitigation:* the check subtracts numbers found in `plan_body` + `lens_items` + `prior_critique_summaries` AND a small explicit allowlist of the template scaffold constants; the contract flags only numbers traceable to NONE of those. If a future template edit adds a scaffold constant, the allowlist must be updated — note this as a maintenance coupling in the implementer's diff comment. Residual risk is a false BLOCKER, which fails safe (re-compose) rather than shipping a fabricated number.
- **The check is a heuristic over numeric tokens, not a semantic parse.** A fabricated number that *coincidentally* also appears somewhere in a long `plan_body` would pass. *Accepted:* the bug class is composer-authored numbers absent from the plan; coincidental collision is rare and the disclaimer (Edit C) + Codex's own "verify against the plan" instruction are the backstop. The check raises the cost of the #722 failure mode from "silent" to "must collide with real plan text," which is the achievable win for a spec-level edit.
- **Disclaimer cannot ENFORCE behavior on Codex (Edit C/D).** The composer controls only its own prompt; Codex may still over-REVISE. *Mitigation:* this is inherent to a thin wrapper (Rules item 5: "No verdict softening" — the composer forwards faithfully). The disclaimer reduces the false-REVISE rate; the orchestrator's reconciler (PASS-vs-FAIL adjudication) and in-context merge remain the authoritative backstop. We do NOT add a composer-side verdict-rewrite — that would violate "No verdict softening."
- **No per-spawn re-read race (deliberately avoided).** Shape (ii) — re-reading `events.jsonl` just before dispatch — was rejected: the composer has no `events.jsonl` path in its brief, re-reading would race concurrent marker writes, and dispatch is the orchestrator's job. Choosing shape (i) sidesteps the race entirely.
