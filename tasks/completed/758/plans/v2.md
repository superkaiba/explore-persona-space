**Edit B — Bug #1, executable verification at Step 4 (REVISED — tokenizer handles canonical #722 forms + fallback when `prior_critique_summaries` is empty).** After the `cat > ... <<'PROMPT'` block, add:

> **Verify no composer-authored numbers leaked into the prompt.** Write `{{plan_body}}` to `$PLANBODY_FILE`, `{{lens_items}}` to `$LENS_ITEMS_FILE`, and `{{prior_critique_summaries}}` to `$PRIOR_CRITIQUES_FILE` (empty file if the orchestrator did not pass this field — fail-safe, treated as zero allowlist contribution). > 1. > 2. Subtracts (multiset) the union of numeric atoms found in `plan_body` + `lens_items` + `prior_critique_summaries` + the EXPLICIT static scaffold allowlist (enumerated against the FINAL Step-3 template text — `0`/`50` from the bar examples, `1`/`2` from rung counts, the version number from `{{revision_round}}`, any version in the marker tag) from the prompt's numeric atoms.
> 3. On any residual numeric atom, FAILS LOUD: `echo "BLOCKER: composer-authored number <n> not traceable to plan_body / lens_items / prior_critique_summaries / scaffold allowlist; re-compose from handed inputs only" >&2; exit 1`. On BLOCKER the composer re-composes from the handed inputs alone; it never hand-edits the offending number in.
>
> This is a local prompt-file validation — read/write temp files only, no Codex dispatch, no polling, no marker emission. See the Hard-rule § Local-validation carve-out below (Edit F).

Tokenizer must split hyphenated ranges + slash-joined pairs so the multiset diff doesn't false-positive on legitimate restatements that happen to share digits.

### 5. Risks / failure modes

- **Over-strict numeric check blocks legitimate restatements (Edit B; unchanged from v1).** Mitigation: multiset subtraction against `plan_body` + `lens_items` + `prior_critique_summaries` + explicit scaffold allowlist; the check fails safe (re-compose, never ship a fabricated number).
- **Tokenizer mismatch on canonical #722 forms (NEW, surfaced by Claude methodology critic).** A naive `re.findall(r'-?\d+\.?\d*', …)` splits `+0.74-0.80` into `0.74` and `-0.80`, while a legitimately-present plan text reading `0.74` to `0.80` tokenizes as `0.74` and `0.80`. Without normalization the multiset can residual on the sign-attached `-0.80`. Mitigation: implementer normalizes hyphenated ranges and slash-joined pairs into atomic numbers BEFORE diffing (canonical #722 forms → `{0.74, 0.80, -2.17, -6.12}`); the `tests/`-side fixture in AC3 pins the canonical-form behavior.
- **Allowlist scaffold drift (unchanged from v1).** A future Step-3 template edit that introduces a new static constant desyncs the allowlist; fails safe (re-compose). The plan's prose follow-up proposes a `tests/`-side subset assertion to prevent silent drift (out of scope for this single-file edit; flagged for sibling `kind: infra` filing).
- **The check is a heuristic over numeric tokens, not a semantic parse (unchanged from v1).** A fabricated number that coincidentally also appears in a long `plan_body` would pass. Accepted residual: the bug class is composer-authored numbers absent from the plan; coincidental collision is rare and the SNAPSHOT NOTE (Edit C) + Codex's own "verify against the plan" instruction are the backstop. The check raises the cost of the #722 failure mode from "silent" to "must collide with real plan text," which is the achievable win for a spec-level edit.
- **Disclaimer cannot ENFORCE behavior on Codex (Edit C/D; REVISED framing).** Edits C/D reduce the false-REVISE-on-suspected-newer-state rate; they do NOT guarantee Codex obeys, do NOT make the snapshot itself fresher, and CANNOT close bug 2 by themselves. The genuinely durable root-cause closure (an orchestrator-side guarantee that the freshest `plan_body` + `prior_critique_summaries` are substituted at each (re-)spawn, in `adversarial-planner/SKILL.md`) is OUT OF SCOPE here and surfaced as a prose follow-up.
