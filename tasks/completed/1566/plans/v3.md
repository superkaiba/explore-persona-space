## 3. Design

**New function `mask_taskpy_arg_payloads()`, inserted immediately after line 985** (after the ssh mask, before the pre-filter comment block at 987), applied under a cheap literal gate:

```bash
case "$cmd" in *task.py*) cmd=$(mask_taskpy_arg_payloads "$cmd") ;; esac
```

**Primary design decision — mask the WHOLE payload body to a sentinel, flag-agnostic within a recognized clause.** Rather than enumerating flags (`--note`, `--title`, …), the pass recognizes a *clause* whose command word resolves to a `task.py` invocation, then masks the body of **every balanced single-quoted argument span** in that clause to the neutral sentinel `__EPM_ARG_PAYLOAD__` (quotes kept: `'__EPM_ARG_PAYLOAD__'`). Justification:

- A single-quoted bash string is inert argv DATA to a non-shell-consumer executable — bash never executes it, and single-quoted spans admit no escapes or nesting (the same exact-parse property the precedent's comment establishes at lines 835-839). The safety argument is therefore **per-span**, independent of which flag (or positional slot) precedes it, so flag enumeration adds maintenance burden without adding safety — and misses `set-goal`'s positional payload entirely.
- The load-bearing narrow point is the **clause head**, not the flag: the head whitelist admits only a python-script invocation (never a shell consumer like `bash -c` / `eval` / `ssh` / `xargs`, whose quoted args ARE executable code — masking those would open a real hole). This is why "mask any command's quoted args" is rejected (§12).

**Recognized head (arm P1)** — clause-initial, matched at `atstart` exactly like the precedent (lines 898-908):

```
^(uv[ \t]+run[ \t]+)?(python[0-9.]*[ \t]+)?[A-Za-z0-9_.\/~-]*task\.py[ \t]+[A-Za-z0-9_-]+[ \t]
```

i.e. optional `uv run`, optional `python`, a path token of safe path chars ending in `task.py` (covers `scripts/task.py`, absolute paths, bare `task.py`; a quoted or `$`-bearing path like `"$REPO_ROOT/scripts/task.py"` cannot match — chars outside the class), then a word-shaped subcommand token. No subcommand enumeration: any word-shaped token is accepted (§12 rationale — the flag/subcommand identity is not the security boundary; the non-shell-consumer head is).

**Fail-closed refusal predicate (arms P1–P6; ANY refusal ⇒ input byte-identical from the candidate on, refused quotes set `saw_quote` — precedent parity):**

- **P1 — head shape** (above). Non-matching clause ⇒ not a candidate; copied verbatim by the char path.
- **P2 — safe charset in the non-payload span.** Between head, quoted spans, and clause end, ONLY `[A-Za-z0-9_.:@%/,=+~ \t-]` is allowed. Any other char refuses the candidate. This is a strict SUPERSET of precedent-R2: it excludes `$( ${` backtick `< >` and the `\x01` splitter sentinel, and additionally excludes **all** `$` (bare `$VAR` is refused, unlike the ssh mask — because `$'...'` ANSI-C quoting processes escaped quotes, so a `$` adjacent to a quote breaks the exact-parse guarantee; excluding `$` wholesale is the simplest sound rule), all backslashes (escaped-quote hazard outside quotes), `"` (double-quoted payloads refuse ⇒ byte-identical ⇒ today's disposition, exactly preserving the existing known-limitation test pins), `#`, globs, parens/braces.
- **P3 — exact single-quote payload parse.** At `'`, the span runs to the next `'` (exact by bash single-quote semantics); no closing quote in the remaining input ⇒ refuse. The BODY is replaced by the sentinel; the surrounding quotes are kept. Multiple spans per clause are each masked (the multi-flag case); the consumed pairs do not set `saw_quote` (precedent lines 957-960 parity), so later candidates in a compound still compose.
- **P4 — latch/WT vocabulary isolation** (precedent R6+R8 parity, applied to the whole candidate INCLUDING payload bodies): refuse if the candidate span carries cd-latch-arming vocabulary (`cd` + `/tmp/` or `.claude/worktrees/`) or `WT=`. This is what makes the latch-trajectory argument in §4 airtight; a note quoting worktree recipes stays blocked (accepted residual, `--file` workaround).
- **P5 — clean prefix quote-state** (precedent R5 parity, the critical arm): refuse when any quote char (single OR double) was seen before the candidate outside previously-accepted candidates' consumed pairs. Without this, a pre-opened quote could make the "payload" live local code (the local-code-swallow hole).
- **P6 — latch-clean prefix** (precedent R7 parity): refuse if the prefix carries the P4 vocabulary — guarantees latch state 0 at candidate entry, so removing payload-internal separators (which today create latch-resetting mis-split boundaries) cannot suppress a load-bearing reset.

Arms that deliberately do NOT transfer: R3 (ssh local-exec options — no ssh head here) and R4 (repo-path spellings — a repo path in inert argv is prose, and refusing it would re-block the common "note names the repo path" case; the inertness argument that licenses masking trigger literals licenses repo paths identically). R1's "payload must be final token" also does not transfer: trailing tokens after a payload are more inert argv here, not a remote-exec mutation — the tail merely stays inside the P2 charset walk (a redirect/quote/`$` in the tail refuses via P2).

**Sentinel:** `__EPM_ARG_PAYLOAD__` — space-free word chars inside kept quotes: cannot form a separator, a trigger literal, a latch match, or glue a git-verb bigram; collision with genuine payload text is harmless because the mask is guard-internal (bash receives the ORIGINAL command either way — precedent lines 879-883).

**awk sketch** (structure mirrors precedent lines 884-983; ~60 lines):

```
rejoin records with \n; i=1; atstart=1; saw_quote=0
while i<=n:
  if atstart and head_regex matches at i (P1):
    walk j from head end: safe chars (P2) advance;
      at "'": find closing quote (P3); record span; continue walk after it
      at ; & | \n or end: candidate complete
      at any other char: REFUSE -> copy head-1 chars, fall to char path
    if candidate complete and P4/P5/P6 pass:
      emit candidate with each span body -> sentinel; i=candidate end; continue
    else REFUSE (byte-identical copy via char path; its quotes set saw_quote)
  char path: copy char; track saw_quote on ' or "; atstart on separators
```

## 4. Interaction analysis

- **Ordering vs the ssh mask:** new pass runs AFTER `mask_ssh_payload_separators` (line 985), so the ssh mask's behavior is byte-identical to today on every input by construction. A `task.py` payload nested inside a single-quoted ssh payload is impossible (single-quoted strings cannot contain quotes). A `task.py` candidate FOLLOWING an ssh clause refuses via P5 (the ssh clause's preserved quotes set our pass's own `saw_quote`) — conservative residual, documented. Running our pass first could widen coverage but would require re-proving the ssh mask's R4/R6/R7 prefix scans against sentinel-substituted text; deferred as a non-goal.
- **`saw_quote` conservatism:** inherited verbatim (P5). Any quoted text earlier in the compound — including an earlier clause's quoting — refuses masking; the FP then persists with today's disposition and the `--file` workaround.
- **cd/WT latch greps:** the driver's latch greps are clause-initial-anchored; a masked merged clause is `task.py`-head-initial (or `uv`-initial), so it can never match them (the same argument the precedent makes at R6, #1443). P4/P6 additionally guarantee latch state is 0 at candidate entry and that no payload fragment could have armed a latch today — so the latch state reaching every post-candidate clause is identical in both worlds.
- **Clause splitter:** masking removes payload-internal separators, merging today's mis-split fragments into one clause. Fragments after the last payload (tail text) are preserved byte-identical inside the merged clause.
- **Classifier / pre-filter:** all non-payload text is preserved, so any REAL mutation text — in another clause, in the prefix, or in the candidate's own tail — still reaches the pre-filter (`\bgit\b.*\b(verb)\b` — both tokens of a real invocation live outside payloads) and `classify_clause` unchanged.
- **Monotonicity invariant (the pass may only remove false positives, never true positives):** (i) the ONLY rewrite is single-quoted span bodies inside accepted candidates; (ii) accepted candidates' quote parse is exact (single-quote lexing + P5 clean quote-state + P2 charset excluding `\`, `$`, `"`); (iii) an exact-parsed single-quoted span in a clause whose command word is a python-script path is argv data bash never executes; (iv) all other bytes are preserved, so every disposition-relevant literal outside payloads survives; (v) latch trajectories of surviving clauses are unchanged (P4/P6, above). Therefore no command whose bash execution performs a root git mutation changes disposition.
- **Fail-soft contract:** the function is a command substitution in the same shape as lines 820/985; an awk failure yields an empty `cmd` and the pre-filter exits 0 — identical failure class to the two existing passes (no new fail-open surface; pinned by the existing fail-soft tests).

## 12. Decision rationale

- **Flag-agnostic span masking (vs flag-set enumeration).** What: mask every single-quoted span in a recognized clause. Why: the security boundary is the non-shell-consumer head, not the flag; enumeration misses `set-goal`'s positional (Source: `scripts/task.py:1635`) and adds a maintenance list. Alternative rejected: the brief's flag list (`--note`/`--title`/`--origin-prompt`/…) — strictly less coverage, same safety.
- **Whole-body sentinel (vs trigger-substring masking).** What: replace the entire payload body. Why: simpler, strictly safer (no residual payload text can interact with splitter/latches/classifier), per the brief's own primary-option framing. Source: precedent's separator-only rewrite shows the alternative's complexity (lines 954-961). Alternative: substring masking — rejected, larger audit surface for zero benefit.
- **Single-quoted only; `"` refuses.** Why: single quotes are the one exactly-parseable form (precedent lines 835-839); double quotes admit escapes/expansion — and refusal preserves the four existing known-limitation pins byte-identical. Source: `guard_repo_root_branch.sh:835-839`, test lines 341-356.
- **`$` excluded wholesale (diverges from ssh-mask's bare-`$VAR` tolerance).** Why: `$'...'` adjacency breaks exact quote parsing; a blanket exclusion is the simplest sound rule for a v1. Source: bash ANSI-C quoting semantics; ssh-mask R2 comment (line 855) documents the parity we deliberately tighten. Alternative: allow `$` except before `'`/`(`/`{` — deferred (relaxation is monotone-safe to add later).
- **Arms P4/P5/P6 transferred; R3/R4/R1-final-token dropped.** Why: per-arm reasoning in §3 — a local argv payload is not a remote-exec string. Source: R1-R8 spec at lines 841-883.
- **Insertion after the ssh mask.** Why: preserves the ssh mask's input byte-identical ⇒ zero re-proof burden. Source: line 985. Alternative (before): marginally wider coverage, larger proof; rejected for v1.
- **Sentinel `__EPM_ARG_PAYLOAD__`.** Why: same construction rules as the precedent's token (line 879-883): word chars, no separators, no trigger substrings.
