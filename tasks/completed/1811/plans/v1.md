## Lesson content (concrete diff sketch — implementer refines wording, not substance)

### File 1 — `.claude/agent-memory/implementer/feedback_report_claims_carry_fresh_evidence.md`

- **Rule:** every verification claim in the report — an acceptance-criterion
  grep result ("zero hits"), a lint rc, a "criterion N: PASS" line — must come
  from a command re-run against the FINAL tree (after your last edit), with the
  actual rc / hit count recorded in `### (c) How to verify`. Your own added
  prose/code is part of the search space: a diff that ADDS a ban/example
  sentence containing the checked literal makes "zero hits" false by
  construction — report the expected self-hit explicitly (path + why it is
  legitimate) instead of claiming zero.
- **Why:** #1743 round 1 (2026-07-28T10:08Z code-review v1): the report claimed
  ZERO hits for success criterion 1 (`grep -rn 'note "\$(cat' .claude/agents/`)
  while the diff's own newly-added ban sentence carried the banned literal;
  the reviewer measured 1 hit → round-1 FAIL bounce, ~14 min + a full revision
  round. A false verification claim is worse than no claim: the reviewer must
  now distrust every other claim in the report.
- **How to apply:** after the final edit of the round, re-run every
  acceptance-criterion command verbatim and paste rc + counts; sweep your own
  diff hunks for the checked literals first (`git diff | grep -F '<literal>'`)
  so an expected self-hit is declared, never denied.

### File 2 — `.claude/agent-memory/experiment-implementer/feedback_must_fix_done_claims_verified_on_disk.md`

- **Rule:** never mark a review Must-Fix as DONE — and never cite a test file /
  test name as evidence — without same-turn on-disk verification: read the
  implementing hunk back from the working tree (`git diff` / grep the changed
  region) and resolve every cited test path (`ls` /
  `uv run pytest --collect-only -q <file>`). A DONE claim recalled from
  intention rather than read from the tree is fabrication when wrong.
- **Why:** #1768 round 1 (2026-07-28T21:40Z code-review v1): the implementation
  marker claimed a Must-Fix (p6 placement) DONE that was unimplemented and
  cited two nonexistent test files; the reviewer's verdict named "the marker's
  two fabricated claims (p6 placement DONE; nonexistent test names)" and
  bounced the round. Same day, same class as #1743's false grep claim —
  the produce-side twin of code-reviewer's
  `feedback_wrapped_literal_evades_site_set_grep.md`.
- **How to apply:** before posting `epm:experiment-implementation`, sweep the
  report for every DONE / exists / passes token; each gets a fresh command
  against the final tree with output recorded in (c) (or (e) for concern
  verification). Cited-but-unrun tests are named as NOT RUN, never as evidence.
