# Plan v1 — task #1832: verify_task_body WARN for quantitative result sections with zero figures

## Goal / requirement

Add a WARN-tier mechanical check to `scripts/verify_task_body.py` (check 48,
v4-only) that flags a QUANTITATIVE `### <result>` H3 under `## Results`
carrying zero inline `![...]` images — closing the gap where a figure-less,
number-dense headline result passes the mechanical verifier silently and
burns an LM clean-result-critic round (incident: #1769 Result 5, the α=2
three-treatment lattice carrying the H1 claim, caught only by the round-1
LM REVISE).

**Acceptance criteria:**
1. A v4 body with a figure-less `### <result>` whose block is quantitative
   (≥3 numeric tokens in non-code content, OR ≥1 GFM table row) draws a
   WARN naming the section; the verifier still PASSes (WARN, never FAIL).
2. A figure-less QUALITATIVE result (no numbers / no table) draws no WARN
   (the existing check-21 exemption stays intact for it).
3. A figure-bearing result section draws no WARN from this check regardless
   of numeric density.
4. v3 / v2 / legacy bodies: vacuous PASS (forward-only, `is_v4` gate).
5. Paired tests in `tests/test_verify_task_body.py` cover 1-4 + CHECKS
   membership; `.claude/skills/clean-results/SPEC.md` mechanical-checks
   list gains the check-48 entry.

## Method delta (what differs from prior related work)

Check 21 (`check_v4_results_beat`) deliberately exempts ANY figure-less
result via `_v4_result_beat_gaps` returning `None` when
`_v4_first_image_index(block) is None` (L13836-13843) — the exemption is
scoped to "qualitative" only in prose, not in code. This plan does NOT
narrow check 21 (its exemption stays byte-identical); it adds a SIBLING
check that binds only the figure-less+quantitative intersection. Nearest
open sibling #1879 covers the DUAL case (>1 figure per section); this task
covers =0 only — no cardinality logic here.
