## 2. Prior work

**Web findings (load-bearing semantics, verified 2026-07-21):**

- The upstream hook definition (`gitleaks/.pre-commit-hooks.yaml`) is `entry: gitleaks git --pre-commit --redact --staged --verbose`, `language: golang`, `pass_filenames: false`. Because `pass_filenames: false`, pre-commit's merge-time file scoping never reaches gitleaks — the binary re-derives its own scope (`git diff --staged`, i.e. staged tree vs first parent HEAD). Source: https://github.com/gitleaks/gitleaks/blob/master/.pre-commit-hooks.yaml
- This mismatch is a known upstream pain point: gitleaks ignores the file list pre-commit passes (`pre-commit run --files` scans the wrong files, gitleaks issue #1409), and `--staged` scans have been reported scanning far more than intended (gitleaks issue #1522). No upstream merge-commit scoping fix exists as of v8.30.x. Sources: https://github.com/gitleaks/gitleaks/issues/1409 , https://github.com/gitleaks/gitleaks/issues/1522
- pre-commit's merge scoping: during a merge (detected via `MERGE_MSG` + `MERGE_HEAD` in the git dir), `pre_commit/git.py::get_conflicted_files` parses conflicted filenames out of `MERGE_MSG` and unions in the files changed relative to the parents — that set is what filename-receiving hooks get. It cannot help a `pass_filenames: false` hook. Sources: https://github.com/pre-commit/pre-commit/issues/112 , https://github.com/pre-commit/pre-commit-hooks/blob/main/pre_commit_hooks/check_merge_conflict.py
- pre-commit config CANNOT override `entry`/`language` for hooks from remote repos (only `args`, `files`, `exclude`, `stages`, etc. are overridable), so conditional logic requires a `repo: local` hook, a `SKIP` env (comma-separated hook ids, honored natively), or gitleaks-side config. Source: https://github.com/pre-commit/pre-commit.com/blob/main/sections/advanced.md
- gitleaks v8 CLI surface relevant here: `gitleaks git` (git-aware; `--pre-commit --staged` = staged-diff mode), `gitleaks dir <path>` (no-git content scan of files/dirs), `gitleaks stdin` (stream scan), `--baseline-path <report.json>` (ignore issues present in a baseline report), `.gitleaksignore` fingerprint file, `--redact`, `--config`, non-zero exit on findings. `--baseline-path` / `.gitleaksignore` address RE-FLAGS but do nothing for the ~50-min scan TIME. Sources: https://github.com/gitleaks/gitleaks/blob/master/README.md , https://pkg.go.dev/github.com/zricethezav/gitleaks/v8

## 4. Design

**Chosen mechanism:** task-body option **(a) local wrapper hook** implementing option **(c) conflict-scoped scanning** on merges — one hook stanza change + one new script; ordinary commits unchanged. (Rationale vs (b)/(d): §11.)

**Merge-detect predicate (exact):** `git rev-parse -q --verify MERGE_HEAD` — succeeds (printing the second-parent SHA) iff a merge is in progress; resolves per-worktree (MERGE_HEAD lives in the worktree's private git dir), unlike a hardcoded `.git/MERGE_HEAD`. The SHA it prints is also the second parent used by the scope computation, so predicate and scope share one probe.

**Merge-path scan set (exact):** staged files whose blob differs from **both** parents —
`comm -12 <(git diff --name-only --no-renames --diff-filter=d --cached HEAD | sort -u) <(git diff --name-only --no-renames --diff-filter=d --cached "$MERGE_HEAD_SHA" | sort -u)`.
A file taken wholesale from either side matches that parent and drops out; only conflict resolutions and hand edits (bytes that never passed the hook on any prior commit) remain. This is a superset of the `MERGE_MSG` "Conflicts:" list (it also catches extra staged edits during the merge) and uses pure plumbing rather than message parsing. `--diff-filter=d` excludes deletions (nothing to scan); `--no-renames` keeps names literal for `checkout-index`.

### File 2 — `scripts/hooks/gitleaks_scoped.sh` (NEW; `chmod +x`; guard-surface — content is neutral, contains no secrets)

```bash
#!/usr/bin/env bash
# Merge-scoped gitleaks pre-commit wrapper (#1584).
#
# Ordinary commit: byte-equivalent to the upstream gitleaks pre-commit hook
# (gitleaks git --pre-commit --redact --staged --verbose) plus this repo's
# --config. Merge commit (MERGE_HEAD present): the staged diff vs first
# parent is the ENTIRE folded advance (~50 min on a large main advance,
# #1345); every commit on both parents was already scanned at its own
# commit time, so only staged files whose blob differs from BOTH parents
# (conflict resolutions + hand edits) carry unscanned bytes — scan exactly
# those with `gitleaks dir` over their extracted staged copies.
set -euo pipefail

if ! command -v gitleaks >/dev/null 2>&1; then
    echo "[gitleaks-scoped] FATAL: gitleaks not on PATH (pre-commit golang env missing)." >&2
    echo "[gitleaks-scoped] Never fails open. Fix: 'pre-commit clean && pre-commit install-hooks'." >&2
    exit 1
fi

MERGE_HEAD_SHA="$(git rev-parse -q --verify MERGE_HEAD || true)"

if [ -z "${MERGE_HEAD_SHA}" ]; then
    # Ordinary commit: exact upstream scan.
    exec gitleaks git --pre-commit --redact --staged --verbose --config .gitleaks.toml
fi

# --- Merge commit: scan only staged files that differ from BOTH parents. ---
tmp="$(mktemp -d)"
trap 'rm -rf "$tmp"' EXIT

scan_set="$(comm -12 \
    <(git diff --name-only --no-renames --diff-filter=d --cached HEAD | sort -u) \
    <(git diff --name-only --no-renames --diff-filter=d --cached "$MERGE_HEAD_SHA" | sort -u) \
    | sed '/^$/d')"

if [ -z "$scan_set" ]; then
    echo "[gitleaks-scoped] merge commit: no staged file differs from both parents; skipping scan (#1584 merge scoping)"
    exit 0
fi

n=0
while IFS= read -r p; do
    git checkout-index --prefix="$tmp/staged/" -- "$p"
    n=$((n + 1))
done <<< "$scan_set"

# Carry repo-root .gitleaksignore if present: scanning from inside the
# extract dir keeps reported paths repo-relative, so path:rule:line
# fingerprints written against staged-mode reports stay applicable.
if [ -f .gitleaksignore ]; then
    cp .gitleaksignore "$tmp/staged/.gitleaksignore"
fi

echo "[gitleaks-scoped] merge commit: scanning $n staged file(s) that differ from both parents (#1584 merge scoping)"
cfg="$(pwd)/.gitleaks.toml"
(cd "$tmp/staged" && gitleaks dir . --config "$cfg" --redact --verbose --no-banner)
```

**Ordinary-commit equivalence:** the non-merge branch `exec`s `gitleaks git --pre-commit --redact --staged --verbose --config .gitleaks.toml` — the upstream entry's five tokens verbatim plus the `--config` arg the current stanza already passes via `args:`. Same binary version (v8.30.1 pinned), same flags, same cwd (pre-commit runs entries from repo root), same exit-code contract. Behaviorally equivalent to today on every non-merge commit; on merge commits the current behavior (full-advance scan) is replaced by the scoped scan.

**Binary sourcing (resolved concretely):** primary = pre-commit's own golang env via `additional_dependencies` (above) — no PATH assumption on the VM, no custom downloader, pinned by version string, cached per-machine by pre-commit exactly like the current remote hook's build. **Named fallback** (only if the smoke in §6 shows a local golang hook won't put the dep's binary on PATH for a bash entry): switch the stanza to `language: system` and add a small resolver block at the top of the wrapper that downloads the v8.30.1 linux-x64 release tarball into `.claude/cache/bin/gitleaks-v8.30.1/`, verifies its sha256 against a constant pinned in the script (taken from the upstream release `checksums.txt`), extracts atomically (tmp + `mv`), under an `flock` to survive concurrent first-commits; a download/verify failure exits 1 (never fail-open). The implementer may take this fallback without re-asking (§13).

## 5. Controls / non-regression

1. **Canary protocol (never committed to THIS repo):** all canaries are constructed **at runtime** in `/tmp` scratch repos (or inside pytest `tmp_path`) by string concatenation, e.g. AWS's documented example key id assembled as `"AKIA" + "IOSFODNN7EXAMPLE"` — a fake test vector gitleaks' default AWS rule still matches. No contiguous secret-shaped literal ever appears in committed source (it would trip both gitleaks and `check_no_secret_shaped_strings.py` on our own commit).
2. **Ordinary-path non-regression (functional):** scratch repo + `pre-commit install` + stage a canary → commit must FAIL (acceptance 3). Also run one clean ordinary commit → passes at today's speed.
3. **Ordinary-path non-regression (pinned):** pytest asserts the wrapper's non-merge branch contains the upstream token sequence `git --pre-commit --redact --staged --verbose` and `--config .gitleaks.toml`, and that the stanza pins v8.30.1 — so a later edit weakening the ordinary path fails the Step 9c gate.
4. **Merge-path coverage (functional):** scratch conflicted merge where the resolution introduces the canary → commit must FAIL (acceptance 4). This proves the scoped path still scans the only genuinely new bytes.
5. **Dispatch-logic unit test (hermetic, stub binary):** the pytest builds a scratch repo, creates a real conflicted merge, puts a **stub `gitleaks`** shell script first on `PATH` (records argv + cwd + the extracted file list; exits 0), runs the wrapper, and asserts: merge path invoked `dir` mode and the extract dir contained ONLY the both-side-changed file (not the folded-advance files); ordinary path invoked `git --pre-commit --staged`. No real binary, no network, no canary needed.
6. **Defense in depth (unchanged):** `check-no-secret-shaped-strings` (`pass_filenames: true`) keeps running on every commit, merge commits included, providing an independent in-repo secret layer regardless of this change.

- **Mechanism = (a) local wrapper + (c) conflict-scoped scan** — What: replace the remote stanza with a local hook whose wrapper branches on merge state. Why: centralizes the logic at the hook itself — one place, covers EVERY caller (Step 10d, 6a.5, humans, improvised merge commands) with no workflow-prose edits; and scanning the differs-from-both-parents set keeps real coverage of the only genuinely new bytes instead of skipping outright. Source: task body options (a)/(c); incident record #1345/#1482; pre-commit remote-hook override limits (https://github.com/pre-commit/pre-commit.com/blob/main/sections/advanced.md). Alternatives: **(d) `SKIP=gitleaks` on merge invocations** — natively supported (comma-separated hook ids) and zero new code, but it is caller-side: every SKILL.md merge recipe, scratch-worktree merge, and human/improvised `git commit` during a merge must remember the env var; a missed caller silently re-pays 50 min, and a blanket SKIP also drops the hand-edited-hunk coverage that (c) keeps. Rejected as primary; anyone may still use it ad hoc. **(b) baseline/`.gitleaksignore` only** — fixes re-flags, does nothing for the ~50-min scan time (the binary still diffs the whole advance). Rejected as primary; the `.gitleaksignore` carry-in (§4) keeps (b)'s benefit where it matters. **Pure skip-on-merge** — sound per the both-parents-already-scanned argument but strictly weaker than (c) at ~zero extra cost; not chosen.
- **Scan-set predicate = differs-from-both-parents intersection** — What: `comm -12` of the two `git diff --cached` name lists. Why: pure plumbing (locale/format-immune), superset of the `MERGE_MSG` "Conflicts:" list, catches extra staged edits during the merge; each side's list computes in seconds even on a large advance. Source: git plumbing semantics; pre-commit's own `get_conflicted_files` uses the same spirit (MERGE_MSG conflicts ∪ parent diffs — https://github.com/pre-commit/pre-commit/issues/112). Alternatives: parse `MERGE_MSG` "Conflicts:" (format-parsing fragility; misses extra staged edits); pre-commit's file list (unreachable — `pass_filenames: false` semantics don't apply to a scope the binary derives itself, and we control our own scope anyway).
- **Binary sourcing = pre-commit golang env via `additional_dependencies`** — What: `language: golang` + pinned dep. Why: identical provisioning machinery to the current remote hook (already proven on this VM), no custom downloader, no PATH assumption, version-pinned. Source: pre-commit advanced docs (additional_dependencies support; https://github.com/pre-commit/pre-commit.com/blob/main/sections/advanced.md); orchestrator-verified fact that pre-commit builds gitleaks into its cached golang env today. Alternatives: sha256-pinned release download (`language: system`) — kept as the named fallback; reusing pre-commit's remote-hook cache path — rejected (cache dirs are non-deterministic, fragile); `go install` at commit time — rejected (toolchain + network on the hot path).
- **Hook id stays `gitleaks`** — What: same id under `repo: local`. Why: `SKIP=gitleaks` and any external references keep working; the dedup/mental model is "the gitleaks hook", not a new name. Source: pre-commit SKIP semantics (https://github.com/pre-commit/pre-commit.com/blob/main/sections/advanced.md). Alternative: `gitleaks-scoped` id — rejected (breaks SKIP muscle-memory).
- **Version pin v8.30.1 retained** — What: same version the repo installed at `3ae97a787c`. Why: single-variable change — this task changes SCOPING, not the scanner version. Source: `.pre-commit-config.yaml` line 5 @ `3ae97a787c`. Alternative: bump to latest — rejected here (separate concern).
- **`always_run: true`** — What: run regardless of pre-commit's computed file list. Why: on merge commits pre-commit's file list is the conflicted set; if a filter ever computed it empty the hook would be silently skipped — `always_run` makes the wrapper the single scoping authority. Source: pre-commit hook-option docs (same advanced.md). Alternative: default file filtering — rejected (adds a second, implicit scoping layer).
- **`entry: bash <script>`** — Why: immune to lost exec bits across clones/worktrees. Alternative: bare script entry + exec bit — works, strictly weaker.
- `N/A — no model training` (no hyperparameters; the only pinned values are the gitleaks version, inherited unchanged, and the <30 s acceptance bound, derived from the measured ~seconds-scale scoped scan vs the ~50-min incident baseline).
