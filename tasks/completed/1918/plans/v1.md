# Plan v1 — Task #1918: /daily route-1 fix closes the open task it credits

## Plan Summary

Add a **"Route-1 covers-open-task closing step"** sub-section to
`.claude/skills/daily/SKILL.md` (the /daily route-1 apply recipe), plus a
one-sentence pointer inside the Route 1 triage item, so that a route-1
self-applied fix that demonstrably lands the FULL deliverable of an
already-filed OPEN task closes that task in the same pass (archive via
`task.py set-status <id> archived` + stop any spawned session) instead of
leaving the spawned `/issue` session to boot, discover mootness, and archive
itself (~3 min pure overhead per occurrence; incident: commit `7202cfd669`
crediting #1823 while task #1823 was filed+spawned, /daily 2026-07-30).

Doc-only change to ONE workflow-surface file. 0 GPU-h. Architectural: no
(adds a guardrail step to a skill recipe; no status enum, marker schema,
task.py subcommand, or file relocation).

## Requirement + acceptance criteria

**Requirement (task Goal):** when a /daily route-1 self-applied fix lands the
exact deliverable of an already-filed task (the commit credits the task id, or
the overlap is mechanically detectable), the /daily run closes/archives that
task in the same pass.

Acceptance criteria:

1. `.claude/skills/daily/SKILL.md` gains a route-1 closing-step sub-section
   covering: trigger conditions, a BINDING full-coverage verification before
   any archive, the canonical archive command (`task.py set-status <id>
   archived --note ...`), the spawned-session stop
   (`spawn_session.py stop --session-id <sid>`), the record shape in
   `## Applied workflow improvements`, and the same-run ordering rule (a
   problem the same run would double-route is dropped from the route-2
   manifest BEFORE the filing driver runs, preferred over archive-after-file).
2. The Route 1 numbered triage item references the new sub-section so the
   step is reachable from the apply recipe, not orphaned prose.
3. The ambiguity guard is explicit: archive ONLY when the commit demonstrably
   covers the task's FULL deliverable (run the task's named failing test /
   acceptance check when one exists, else confirm every element of the task's
   proposed change is present in `git show <sha>`); ambiguous/partial →
   leave the task open + log the possible overlap in
   `## Other problems & notes`. Never archive on a guess.
4. Status mutation goes through `task.py set-status` only (canonical API);
   never a hand-edit / hand-`git mv`.
5. `scripts/workflow_lint.py` (no-flags default run) stays green on the
   edited file; the Step 9c mapped-test selection passes.
