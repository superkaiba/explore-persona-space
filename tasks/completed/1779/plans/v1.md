## 1. Goal / Requirement

planner §10 must require every text/JSON output of a stage running on an **ephemeral lane** (GCE `--instance-termination-action=DELETE`, RunPod terminate-on-upload-verify) to name an **HF (non-LFS) destination** — a git-only destination ("commit to the issue branch") is valid ONLY for VM-resident stages, or when the plan names an explicit **pre-teardown harvest phase** that lands the file in git BEFORE the instance/pod is reaped. The critic Methodology lens REVISEs violations.

### Incident (why)

#1738's approved plan §10 declared "JSON summaries → git issue branch" for artifacts produced on the DELETE-on-exit GCE lane with no harvest phase. The instance was reaped minutes after a clean exit; both summary JSONs (`multiturn_100k_fits.json`, `mapping_baselines.json`) were lost; a 28-min CPU rebuild round recovered the holdout side from retained tensors. CLAUDE.md § Upload Policy says text/JSON uploads ALWAYS (non-LFS path, unconditional), but nothing at PLAN time cross-checks destination-vs-lane durability.
