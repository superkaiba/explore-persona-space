## 1. Goal

> Add a workflow_lint check flagging a same-file bash FUNCTION invoked via `func || rc=$?` (or `|| true`) under `set -e` in `scripts/*.sh` — errexit is suppressed inside the function body, so mid-function failures collapse to the last command's rc.

(Task #1516 `## Goal` H2, verbatim — `kind: infra`, no `goal:` frontmatter.)

One paragraph: bash's errexit is disabled throughout a function's body whenever the function call appears in an `||` (or `&&`/`if`) context. A dispatcher written in the house `set -euo pipefail` style assumes every command inside a function is implicitly guarded; wrapping the *call* in `|| rc=$?` silently removes that guarantee, so a mid-function `SystemExit`, gate failure, or fit crash falls through and `rc` captures only the *last* command's exit code — typically 0. On #1426 this let partial uploads and the `[phase=done]` success sentinel proceed past a Gate-1 terminal failure; only the adversarial code-reviewer caught it. This task closes the class mechanically.

### 4.1 Constants block (module level, placed immediately above the new check function)

The new check function is inserted between `check_push_failure_swallow` (ends L3515) and the `GREP_QV_CMD_RE` block (starts L3518) — the GREP_QV block already establishes the constants-directly-above-check placement.
```python
# `--check-sh-function-rc-capture` (#1516; incident #1426): bash disables
# errexit throughout a function BODY when the call sits in an `||` context,
# so `func || rc=$?` / `func || true` collapses mid-function failures to the
# last command's rc (usually 0) — #1426's `run_seed "$s" || rc=$?` let a
# Gate-1 terminal failure + a manifest SystemExit proceed to `[phase=done]`.
# ShellCheck SC2310 is the broader external analogue (also `if func`,
# `while func`, `! func`, `func && x`); v1 deliberately matches the filed
# incident class only (`|| rc=$?` / `|| true` on a same-file function).
# Parse limitations degrade toward false NEGATIVES (same direction as
# check_upload_or_true), with TWO named FP-side exceptions, both measured
# harmless on the live tree (0 instances; test #16 + the waiver contain them):
# (a) pass-1 over-collection — the brace-optional def regex can collect bare
#     zero-arg call lines inside heredoc python bodies (errs toward flagging);
# (b) a case-arm PATTERN that equals a collected function name
#     (`fname) cmd || true ;;`) matches inv_re at ^ and would flag.
# The naive double-quote masking (no \" escape handling) can also mis-mask
# exotic lines in either direction — see §4.3.
RC_CAPTURE_FUNC_DEF_RE = re.compile(
    r"^\s*(?:function\s+)?([A-Za-z_][A-Za-z0-9_]*)\s*\(\s*\)\s*\{?"  # name() {  /  function name() {  /  name ()
    r"|^\s*function\s+([A-Za-z_][A-Za-z0-9_]*)\s*\{"                 # function name {   (paren-less)
)
RC_CAPTURE_SUPPRESS_RE = re.compile(r"\|\|\s*(?:[A-Za-z_][A-Za-z0-9_]*=\$\?|true\b|:(?=[\s;]|$))")
# Three suppressor shapes (Phase-2 Alternatives Must-Fix 2 — capture-SPELLING variants
# covered, not just the filed `rc=$?`):
#   (1) `|| <var>=$?` — ANY simple variable name (rc / status / ret / code / …), not the
#       literal `rc` only; the danger is the capture-and-continue shape, not the name.
#   (2) `|| true\b` — \b INSIDE the true branch only: `?` is a non-word char, so a trailing
#       \b after the alternation NEVER matches `=$?` (fact-check-verified dead branch in the
#       v1 draft; corrected form matches all shapes and still returns 0 live findings).
#   (3) `|| :` — the colon builtin, an exact synonym of `|| true` (lookahead bounds it to
#       whitespace / `;` / EOL so `:=`-style text cannot match).
# Deliberately NOT matched (documented residuals, see §4.4 out-of-scope): `|| { rc=$?; … }`
# brace-group capture (brace-group handlers are a pervasive live fail-loud idiom — 20+ sites
# incl. a same-file-function call at run_program_orchestrator.sh:86 — and covering them would
# threaten the 0-findings bundling precondition), and quoted `|| rc="$?"` (quote masking
# blanks the `"$?"` span BEFORE the suppressor scan, a masking-induced FN; 0 live hits).
RC_CAPTURE_WAIVER_RE = re.compile(r"#\s*RC_CAPTURE_EXEMPT\s*:\s*(.+?)\s*$")
RC_CAPTURE_WAIVER_MIN_REASON_CHARS = 10
```

Function-name extraction from a def match: `m.group(1) or m.group(2)`.

### 4.2 `set -e` state tracking (small helper)

`_rc_capture_set_e_transition(stripped: str) -> bool | None` — token-scan of a logical line that starts with `set` (else return `None`, no transition):

- split tokens after `set`; a token matching `-[a-zA-Z]*e[a-zA-Z]*` (short-option cluster containing `e`, e.g. `-e`, `-euo`, `-eux`) → ON; `+[a-zA-Z]*e[a-zA-Z]*` → OFF; the pair `-o errexit` → ON; `+o errexit` → OFF. Last matching token wins within the line. No `e`-bearing token → `None`.
- Initial state per file: ON iff line 0 matches `RC_CAPTURE_SHEBANG_E_RE = re.compile(r"^#!\S+.*\s-[a-zA-Z]*e[a-zA-Z]*\b")` (`#!/bin/bash -e` / `-eu`); otherwise OFF.
- This is LINE-ORDER state tracking (the `check_piped_git_push` `pipefail_seen` precedent), not file-level presence: 7 live scripts toggle `set +e` mid-file (verified: `i488_run_all.sh`, `issue1310_dispatch.sh`, `issue1415_dispatch.sh`, `issue811_dispatch.sh`, `issue833_run_all.sh`, `issue931_dispatch.sh`, `run_issue404_pipeline.sh`), and under `set +e` the pattern is NOT the footgun (the function body never had errexit protection, so the author owns explicit error handling). A hit inside a `set +e` region therefore does not flag — failing toward false-negative, the documented safe direction. Known coarseness: `set -e` inside a function body or subshell is treated as a file-scope transition (no scope tracking); acceptable because it errs toward the state the author most recently declared.
- 0 live uses of `set -o errexit` in `scripts/*.sh` (verified by grep) — the `-o errexit` arm is for completeness.

### 4.3 Quote masking (small helper)

`_rc_capture_mask_quotes(s: str) -> str` — replace each `'...'` span, then each `"..."` span, with same-length spaces (`re.sub(r"'[^']*'", ...)` then `re.sub(r'"[^"]*"', ...)`). Single-quoted spans first (bash forbids escapes inside them, so the regex is exact there); the double-quote pass is naive about `\"` escapes — a known imperfection that can only mis-mask exotic lines, and any mis-mask lands on the fail-toward-false-negative side in practice because the flag additionally requires a collected function name at command position. This kills the one live quoted-string near-miss: `bootstrap_pod.sh:530` — `ssh_cmd 'cd … || true'` (the `|| true` is remote-side text inside the quoted argument, and `ssh_cmd` IS a same-file function, so without masking this is a guaranteed false positive).

### 4.4 The check function

```python
def check_sh_function_rc_capture(*, scripts_dir: Path | None = None) -> list[str]:
```

Per file in `sorted((scripts_dir or _REPO_ROOT / "scripts").rglob("*.sh"))`, skipping non-files (byte-for-byte the `check_push_failure_swallow` walk; missing root → `[]`):

1. **Pass 1 — collect same-file function names:** every `RC_CAPTURE_FUNC_DEF_RE` match over physical lines. No functions → skip file (cheap early-out; 149 live rglob files — 131 non-recursive `scripts/*.sh` + 18 under `scripts/hooks/`, `pod2–5/`, `meco_em/` — with ~173 brace-required def lines; the brace-optional collector matches ~194–212 physical lines, over-collecting some bare zero-arg call lines inside heredoc python bodies — over-collection errs toward FLAGGING and the prototype still returns 0 findings, so it is safe; 0 paren-less `function name {` defs live, but the alternation covers it since bash allows it).
2. Build one per-file invocation regex:
   `inv_re = re.compile(r"(?:^|[;&|({]|\b(?:then|do|else)\s)\s*(" + "|".join(re.escape(f) for f in sorted(funcs)) + r")\b")` — the function name must sit at COMMAND POSITION (start of logical line, or after `;` `&` `|` `(` `{` or a `then`/`do`/`else` keyword). This is what keeps single external commands (`uv run python … || rc=$?`, `git push … || rc=$?` — all current `|| rc=$?` captures on main — 26 matching lines across 13 files) unflagged: their first word is never a collected same-file function.
3. **Pass 2 — scan logical lines** via `_iter_sh_logicals_with_heredocs(lines)` (heredoc bodies consumed and NEVER scanned — a heredoc embedding `func || true` text, e.g. the `i488_diag_poll.sh` remote-command heredocs, cannot false-positive), maintaining the §4.2 errexit state:
   a. `#`-comment logical lines → skip.
   b. `set`-transition lines → update state, continue.
   c. State OFF → continue.
   d. Line matches `RC_CAPTURE_FUNC_DEF_RE` → skip (a definition is not an invocation). This kills the two live def-line near-misses: `issue1345_dispatch.sh:155/159` — `no_r4_flag() { [[ -f … ]] && echo "--no-r4" || true; }` (one-liner defs whose BODY legitimately ends `|| true`). Accepted false negative: a one-liner def whose body invokes ANOTHER collected function with `|| true` is skipped with it (documented in the comment matrix).
   e. `code = _strip_sh_trailing_comment(logical)` (so `run_seed "$s"  # TODO: add || rc=$? capture` cannot flag on comment text), then `masked = _rc_capture_mask_quotes(code)`.
   f. For each `inv_re` match `m` on `masked`: find `sm = RC_CAPTURE_SUPPRESS_RE.search(masked, m.end())`; flag iff `sm` exists AND `";" not in masked[m.end():sm.start()]` (segment guard — `run_seed; cleanup || true` must not attribute cleanup's suppressor to `run_seed`; `&&` chains deliberately stay in scope since `cd x && func || rc=$?` puts `func` in the `||` context). One error per logical line, first hit wins.
   g. Waiver: `_sh_waiver_present(lines, first, last, waiver_re=RC_CAPTURE_WAIVER_RE, min_reason_chars=RC_CAPTURE_WAIVER_MIN_REASON_CHARS)` → skip. Waiver spelling `# RC_CAPTURE_EXEMPT: <reason ≥10 chars>` on any physical line of the logical command or the immediately preceding non-blank line (exact `_sh_waiver_present` semantics; 10 chars matches `UPLOAD_OR_TRUE_WAIVER_MIN_REASON_CHARS` and the task body — `PUSH_SWALLOW` uses 8, the newer checks use 10).
4. Error message (house shape):
   `f"{sh}:{first + 1}: same-file bash function `{fname}` invoked via `|| <var>=$?`/`|| true`/`|| :` under set -e — bash disables errexit inside the function BODY in an `||` context, so mid-function failures collapse to the last command's rc (#1426: a Gate-1 terminal failure + a manifest SystemExit read as rc=0 and `[phase=done]` fired). PRIMARY remedies: harden the body's failure-prone steps with explicit `|| exit`/`|| return $?`, or extract the body to a child script (`bash x.sh || rc=$?` — a child process keeps its own set -e; this is why single-external-command captures are safe). NOTE: `set +e; {fname}; rc=$?; set -e` bracketing alone does NOT restore body errexit — it has the identical collapse semantics and must be paired with body hardening. A genuinely-safe shape may be waived with `# RC_CAPTURE_EXEMPT: <reason>` (#1516)."`

   (Phase-2 Alternatives Must-Fix 1: the v2 draft's message listed `set +e/-e` bracketing as the FIRST remedy — but a bare invocation under `set +e` bracketing is semantically equivalent to the flagged shape for the #1426 collapse, and §4.2 deliberately unflags `set +e` regions, so an author mechanically following that remedy would be lint-green with the identical footgun. Body hardening / subprocess extraction are now primary; the bracketing note names the equivalence explicitly.)

**Scan set decision:** `scripts/**/*.sh` only (rglob), matching every sibling `*.sh` check (`check_pipe_python` / `check_piped_git_push` / `check_push_failure_swallow` / `check_upload_or_true` all walk `_REPO_ROOT / "scripts"` only; only `check_grep_qv` scans wider, and for a different reason — its targets are doc snippets). `.claude/hooks/*.sh` stays out of scope: verified 0 of 6 hook files use `set -e` at all (guards are deliberately fail-open), so the class cannot fire there today — documented residual, not a coverage loss. **No legacy allowlist:** the refined prototype run against the live tree returns 0 findings (see §9 A3), so unlike `PUSH_SWALLOW_LEGACY_ALLOWLIST` no grandfather set is needed. **Out-of-scope contexts (explicit, v1):** `if func`, `while func`, `until func`, `! func`, `func && x` (as the suppressing context itself), `var=$(func) || rc=$?` where the fname is hidden behind `$(`-plus-assignment (the `(`-anchor catches the bare `$(func) || rc=$?` shape but not `x=$(func …` when preceded by the assignment word — accepted FN), `env VAR=1 func || true` AND bare assignment-prefix `VAR=1 func || true` (fname not at command position — same family), and cross-file function sourcing (`source lib.sh` then `libfunc || rc=$?` — the collector is same-file by design, per the Goal). **Out-of-scope suppressor SPELLINGS (v1, each 0 live hits):** `func || { rc=$?; … }` brace-group capture (brace-group handlers are a pervasive live fail-loud idiom, 20+ sites — flagging them would threaten the 0-findings bundling precondition; the natural rewrite-evasion of a flagged line, documented so a reviewer recognizes it), quoted `func || rc="$?"` (masking-induced FN — §4.3 blanks the `"$?"` span before the suppressor scan), and fail-loud handlers `func || exit 1` / `func || { echo FATAL; exit N; }` (deliberately unflagged — but note they share the body-errexit-suppression residual: the handler never fires when the body's LAST command succeeds after a mid-body failure). **Case-arm residuals (both 0 live hits, contained by test #16 + waiver):** a case-branch invocation `pattern) func || true ;;` is an FN (anchor set lacks `)`); a case PATTERN equal to a collected fname (`fname) cmd || true ;;`) is the named FP-side exception (b) in §4.1. All are the same bash footgun; ShellCheck SC2310's broader scope is the named future extension if the class recurs through one of these shapes. Rationale for narrow-first: matches the filed Goal verbatim, matches the incident, and keeps the false-positive surface small enough to bundle into the no-flags gate immediately (ShellCheck itself ships the broad version off-by-default because of its noise).

## 11. Decision Rationale

- **Scope: narrow (|| rc=$? / || true on same-file functions) vs ShellCheck-broad (if/while/!/&&/cmd-subst).**
  What: v1 flags only the filed shapes. Why: matches the Goal verbatim and the incident class; ShellCheck ships the broad version OFF by default because it is noisy on deliberate uses — a no-flags-bundled gate must start quiet. Source: ShellCheck SC2310/SC2311 wiki (§2 URLs); task #1516 `## Goal`. Alternatives: full SC2310 scope (rejected v1 — FP surface unknown on the 149 live scripts, would jeopardize bundling; named future extension), depend on shellcheck binary (rejected — not installed, A8; pure-python convention).
- **`set -e` detection: line-order state tracking vs file-level presence.**
  What: per-logical-line ON/OFF toggle (init from shebang). Why: 7 live files toggle `set +e` (A5), and a `set +e` region is not the footgun; file-level presence would FP there. The state machine costs ~10 lines and follows the `pipefail_seen` fires-direction precedent. Source: `check_piped_git_push` L3423–3436; A5 grep. Alternatives: file-level (simpler, rejected — known FP class on 7 files), full scope-aware tracking of subshells/function bodies (rejected — over-engineering; coarseness documented, fails toward FN).
- **Waiver syntax: `# RC_CAPTURE_EXEMPT: <reason ≥10 chars>` via `_sh_waiver_present`.**
  What/Why: house style — one SCREAMING token + colon + reason, same-line or preceding-line, shared helper. 10-char floor matches the newer sibling (`UPLOAD_OR_TRUE_WAIVER_MIN_REASON_CHARS = 10`) and the task body. Source: `_sh_waiver_present` L3216; `UPLOAD_OR_TRUE_WAIVER_*` L1238–1239 (values 10 chars; `PUSH_SWALLOW_WAIVER_*` uses 8). Alternatives: no waiver (rejected — every bundled sh-check has one; deliberate uses need an escape), allowlist-only (rejected — waivers self-document at the site).
- **No-flags bundling: YES.**
  What: `or no_flags` dispatch + `no_flags` disjunction entry. Why: unbundled checks are advisory, not gates; the pre-commit/Step-9c surfaces run no-flags. Precondition (live tree green with the check on) verified: A3 + A7. Source: `check_push_failure_swallow` registration L10731/L11290/L11386 + its docstring "Bundled into the no-flags default run (same policy as check_piped_git_push)". Alternatives: opt-in flag only (rejected — the #1426 class would only be caught when someone remembers to run it, which is the pre-existing failure mode).
- **Scan set: `scripts/**/*.sh` only.**
  What: `rglob("*.sh")` under `scripts/`. Why: byte-identical to all four sibling sh-checks (A1); hooks have no `set -e` so the class cannot fire there (A10). Source: sibling walks (§2); A10 prototype. Alternatives: + `.claude/hooks/` (rejected v1 — deviates from convention for zero coverage gain today; documented residual), `check_grep_qv`-style multi-root (rejected — that check targets doc snippets, different problem).
- **Heredoc handling: `_iter_sh_logicals_with_heredocs`, bodies ignored.**
  What: iterate with the heredoc-aware cursor; scan only opener logical lines. Why: heredoc bodies (embedded remote/python snippets) are a pure FP surface for THIS check — unlike `check_upload_or_true`, which must look inside bodies. Free rigor: the helper already consumes bodies. Source: helper docstring L3102–3116; `check_upload_or_true` usage L3878. Alternative: `_iter_logical_shell_lines` (simpler, used by pipe_python/piped_git_push — rejected because those checks' patterns are self-disambiguating in heredoc text while a function name + `|| true` is not).
- **Command-position anchoring + quote masking + def-line skip + `;`-segment guard.**
  What: the four FP-killers in §4.4. Why: each maps 1:1 to a measured live near-miss or a concrete FP construction (A3, test #12). Source: prototype run (A3); `_grep_qv` lookbehind precedent for position discipline (L3530). Alternative: bare `<fname>.*|| (rc=\$\?|true)` regex (the candidate sketch — rejected: 3 live FPs, A3).
- **N/A — no model training; no load-bearing hyperparameters in this task type.**
