# Plan v1 — #1962: cross-issue lint-gate concurrency arbitration

## Summary

Add a fleet-level concurrency arbiter for the heavyweight gate trees on the shared VM (Step 9c gate pytest + compare, Step 10d lint gates forms (i)/(ii)/(iii), Step 9a-ter inline payload gates): a new `probe --fleet` mode in `scripts/step9c_baseline.py` counts DISTINCT FOREIGN issues with live gate processes and exits 3 when the count reaches `EPM_GATE_FLEET_MAX` (default 2). SKILL.md gate-launch sites run the fleet probe after the existing per-issue single-flight probe; on exit 3 they wait in a bounded queue (Monitor until-loop, cap 2700 s), then launch anyway (fail-open). The per-issue single-flight contract (#1606/#1821) is preserved byte-unchanged; the fleet arm is additive.

## Method delta (why this shape)

- **Issue-grain counting, not process-grain:** one gate spawns many argv-matching processes (13 live `lint-gate-tree` processes observed at the #1768 kill); distinct-issue counting makes the threshold meaningful and stable.
- **Threshold default 2:** SKILL.md's own measured figures — ~9-12 min gate wall idle vs "30-40 min under typical fleet load (3+ concurrent gates)" (measured 2026-07-26) — plus the incident record (kills at ~93-98% CPU; earlyoom activity below) put the knee at ~3 concurrent gates. Cap 2 keeps the fleet under the knee; env-overridable.
- **Fail-open on cap expiry (45 min):** a wedged foreign gate is bounded at ~78 min worst case by its own leg timeouts; a hard queue would let one wedged gate block every merge on the VM. Over-cap launch is exactly today's behavior — the arbitration can only reduce concurrency, never deadlock it.
- **Accepted race residual:** two waiters can both observe a freed slot and launch together (no lock; the probe is read-only). Worst case is a brief overshoot back to today's status quo — acceptable for a best-effort politeness queue; a flock-based ticket queue is deliberately out of scope (it would add a cross-session lock file with staleness/cleanup semantics for marginal gain).
- **Secondary sketch item already landed:** the body's "state TG_T sizing off the LOADED 30-40 min range" is already on main (SKILL.md Step 10d gate section: "Size any wall-time-derived fence off the LOADED range, not the idle one", measured 2026-07-26). No edit; recorded as resolved-already.
