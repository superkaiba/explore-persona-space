#### Step 1 — the shared module (new file `src/explore_persona_space/atomic_io.py`)

Stdlib-only module-level imports (`contextlib`, `json`, `logging`, `os`, `uuid`, `pathlib`) so ~110 lightweight scripts can import it without dragging the ML stack.

```python
_LOGGER = logging.getLogger(__name__)   # "explore_persona_space.atomic_io"

@contextlib.contextmanager
def atomic_replace(path: Path, *, logger: logging.Logger | None = None) -> Iterator[Path]:
    # Body = hoist of scripts/issue2329_run.py:1404-1438 (_atomic_replace), VERBATIM except
    # exactly ONE mechanical change: the cleanup-warning call logs via (logger or _LOGGER).
    # Docstring names #2329/#2336 provenance. Three load-bearing properties:
    #   1. tmp = path.parent / f"{path.name}.{os.getpid()}.{uuid.uuid4().hex[:8]}.tmp"
    #   2. temp in the DESTINATION's own directory (cross-filesystem os.replace is not atomic)
    #   3. on BaseException: try tmp.unlink(missing_ok=True) / except OSError -> log via
    #      (logger or _LOGGER), then bare `raise` (cleanup failure never masks the original)
```

Why the `logger=` parameter exists (B1, settled round 1): `tests/test_issue2329_r2_fixes.py::test_atomic_replace_cleanup_failure_does_not_mask_original_exception` (:667-714) pins the cleanup warning to logger name `issue2329.run` (:693/:709). The parameter lets `issue2329_run.py` pass its own logger (step 3(e)) — zero edits to another issue's landed test pins.
