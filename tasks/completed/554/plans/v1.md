# Plan — Task #554 (infra): branch-aware preflight git check + fail-loud bare mode

## 0.0 TL;DR (plain English)

- **What I'll change:** The pre-launch check script has two bugs. First, it screams "you're behind main!" and blocks the launch whenever a pod is running on an experiment branch — which is exactly how every experiment runs, so the alarm is almost always false. I'll make it compare the branch against its own pushed copy instead. Second, when the check fails in plain mode it prints nothing at all before killing the pipeline, so launches die silently. I'll make it print the failing checks before exiting.
- **What I expect:** Pods on experiment branches pass the check when they're at the right code; a stale branch or a stale `main` still gets blocked; a failing check always says why before the process dies.
- **What would change my mind:** Finding a consumer that depends on the old "behind main" error firing on experiment branches. I enumerated all callers and found none — the only consumers that mention it are working *around* it.

## 1. Goal + requirement + acceptance criteria

Fix two fail-loud violations in `src/explore_persona_space/orchestrate/preflight.py`, both burned at real launches (#383 2026-05-24, #550/#552 2026-06-10; duplicates #566/#567 folded in):

- **Defect 1:** `check_git_status()` (lines 214–222) unconditionally ERRORs on `git rev-list --count HEAD..origin/main` ≠ 0. Every `issue-<N>` pod checkout — the canonical launch path — trips it even when the branch tip IS the reviewed run-of-record.
- **Defect 2:** bare (non-`--json`) CLI (`__main__`, line 812) and `require_preflight()` (lines 745–749) emit the summary via a handler-less `logger.info()`. Verified on this VM: with no logging configured, INFO emits **zero bytes** (root level WARNING + no handlers); only the bare `logger.error` one-liner escapes via `logging.lastResort`, with none of the failing-check detail. A launcher under `set -e` dies with an unattributable 0-byte phase log.

**Acceptance criteria (union of #554 + #566 + #567):**

1. Pod on `issue-<N>` at the tip of pushed `origin/issue-<N>` → git check passes (exit 0; at most a WARNING about origin/main divergence).
2. Issue branch BEHIND its own `origin/issue-<N>` → ERROR.
3. On `main` behind `origin/main` → ERROR, message **byte-identical** to today (`Local is {n} commit(s) behind origin/main. Run: git pull origin main`) — the agent-spec tolerance pattern-matches this string.
4. Failing bare-mode preflight prints the failing check(s) to stdout/stderr before exiting non-zero.
5. Unit tests for cases 1–3 + bare-mode output.
6. Existing consumers unchanged: `--json` stdout remains exactly one pretty-printed JSON object with the same 9 keys (gotchas.md contract: parse whole stdout, never `splitlines()[-1]`); `require_preflight()` signature and success-path behavior unchanged.

### 3.1 New helper `_behind_count` (insert after `_run`, ~line 144)

```python
def _behind_count(project_root: Path, ref: str) -> int | None:
    """Commits HEAD is behind ``ref`` (via ``git rev-list --count HEAD..<ref>``).

    Returns None when the count cannot be determined (missing ref → rc=128,
    git error, non-integer output). Callers treat None as "unknown", never 0.
    """
    rc, out, _ = _run(["git", "-C", str(project_root), "rev-list", "--count", f"HEAD..{ref}"])
    if rc != 0:
        return None
    try:
        return int(out.strip())
    except ValueError:
        return None
```

### 3.2 Replace the behind-remote block in `check_git_status` (current lines 214–222)

Everything above (porcelain check, cluster early-return at line 207–212) is untouched.

```python
    # Behind-remote check — branch-aware (#554). On the canonical /issue pod
    # checkout HEAD is on `issue-<N>`; the branch's own pushed origin ref IS
    # the run-of-record, and divergence from origin/main is expected (#383,
    # #550). ERROR is reserved for "behind the ref this checkout tracks".
    _run(["git", "-C", str(project_root), "fetch", "--quiet", "origin"], timeout=15)

    rc, branch, err = _run(["git", "-C", str(project_root), "rev-parse", "--abbrev-ref", "HEAD"])
    if rc != 0:
        report.add_warning(f"could not determine current branch: {err}")
        report.git_status += ", branch unknown"
        return
    branch = branch.strip()

    if branch == "main":
        behind_main = _behind_count(project_root, "origin/main")
        if behind_main:  # None (count unknown) keeps today's silent-skip behavior
            report.add_error(
                f"Local is {behind_main} commit(s) behind origin/main. Run: git pull origin main"
            )
            report.git_status += f", {behind_main} behind remote"
        return

    if branch == "HEAD":
        # Detached HEAD (pinned-SHA checkout): no own ref to be behind.
        behind_main = _behind_count(project_root, "origin/main")
        if behind_main:
            report.add_warning(
                f"Detached HEAD is {behind_main} commit(s) behind origin/main — "
                f"verify the pinned commit is the intended run-of-record."
            )
        report.git_status += " (detached HEAD)"
        return

    # Feature branch: compare against the branch's OWN origin ref.
    own_ref = f"origin/{branch}"
    rc_ref, _, _ = _run(
        ["git", "-C", str(project_root), "rev-parse", "--verify", "--quiet",
         f"refs/remotes/{own_ref}"]
    )
    if rc_ref == 0:
        behind_own = _behind_count(project_root, own_ref)
        if behind_own is None:
            report.add_warning(f"could not count commits behind {own_ref}")
        elif behind_own:
            report.add_error(
                f"Branch {branch} is {behind_own} commit(s) behind {own_ref}. "
                f"Run: git pull --ff-only origin {branch}"
            )
            report.git_status += f", {behind_own} behind {own_ref}"
    else:
        report.add_warning(
            f"Branch {branch} has no pushed {own_ref} ref — cannot verify "
            f"up-to-date-ness (unpushed local branch)."
        )
        report.git_status += f" (no {own_ref})"

    behind_main = _behind_count(project_root, "origin/main")
    if behind_main:
        report.add_warning(
            f"Branch {branch} is {behind_main} commit(s) behind origin/main "
            f"(expected on a feature branch; informational)."
        )
        report.git_status += f", {behind_main} behind origin/main"
```

Git commands chosen and why:

- `git rev-parse --abbrev-ref HEAD` — branch name; prints literal `HEAD` when detached (**verified by running it** in a scratch repo on this VM).
- Constructed `refs/remotes/origin/<branch>` rather than `@{u}` — `@{u}` requires upstream *configuration*, which a pod-side `git fetch origin issue-N && git checkout issue-N` sometimes sets and a `git init -b $BRANCH + fetch + reset --hard FETCH_HEAD` bootstrap (the actual `bootstrap_pod.sh` path, lines 230–245) never sets. The remote-tracking ref existence is the robust signal; the preceding full `git fetch origin` (kept from current code) populates it for any pushed branch under the default refspec `bootstrap_pod.sh` configures via `git remote add origin`.
- `git rev-parse --verify --quiet refs/remotes/origin/<branch>` — rc 1 when ref missing, no stderr noise (**verified**: rc=1 on missing ref; bare `rev-list HEAD..missing` is rc=128, which `_behind_count` maps to None).

### 3.3 Defect 2a — `require_preflight()` (current lines 745–749)

```python
    if report.ok:
        logger.info(report.summary())
        return report

    # FAIL path — fail LOUD on a real stream. A handler-less logger.info()
    # emits zero bytes (root logger defaults to WARNING with no handlers), so
    # a launcher under `set -e` dies with an unattributable 0-byte log (#550).
    print(report.summary(), file=sys.stderr)
    logger.error("Pre-flight check FAILED. Fix errors before running.")
    sys.exit(1)
```

**Why this cannot double-print for consumers that DO configure logging**: the summary is emitted by exactly one statement per branch — `logger.info(summary)` on the PASS branch only, `print(..., file=sys.stderr)` on the FAIL branch only. The unconditional `logger.info(summary)` that today precedes the failure branch is *moved inside* the PASS branch, not duplicated. So `scripts/run_issue_360_target_logprobs.py` / `run_issue_358_extract.py` (both call `logging.basicConfig(level=INFO)` at module top — read from code) see: PASS → summary once via logging (today's behavior, byte-identical); FAIL → summary once via raw stderr + the same single `logger.error` line they already get today. No introspection of logging state (`hasHandlers()` guards) — deterministic by construction. The only visible change for configured consumers is cosmetic: on the failure path the summary arrives unformatted on stderr instead of through the logging stream, on a path that immediately `sys.exit(1)`s.

def main(argv: list[str] | None = None) -> int:
    """CLI entry point. Returns the process exit code (0 = preflight PASS)."""

    parser = argparse.ArgumentParser(description="Run pre-flight checks")

        print(report.summary())

            for e in report.errors:
                print(f"preflight ERROR: {e}", file=sys.stderr)

    if not report.ok:
        return 1

    if args.pipeline_check:
        print("Running integration tests...")
        rc, stdout, stderr = _run(
            [sys.executable, "-m", "pytest", "tests/integration/", "-m", "integration", "-x", "-v"],

        if stderr:

The `--pipeline-check` logger lines convert to `print` for the same defect-2 reason (today they're invisible in bare mode).

def _fake_git_run(*, branch="issue-554", porcelain="", own_ref_exists=True,
                  behind_own="0", behind_main="0", calls=None):
    def fake_run(cmd, timeout=10):
        if calls is not None:
            calls.append(cmd)
        if "status" in cmd and "--porcelain" in cmd:
            return 0, porcelain, ""
        if "fetch" in cmd:
            return 0, "", ""
        if cmd[-2:] == ["--abbrev-ref", "HEAD"]:
            return 0, branch, ""
        if "--verify" in cmd:
            return (0 if own_ref_exists else 1), "", ""
        if "rev-list" in cmd and cmd[-1] == "HEAD..origin/main":
            return 0, behind_main, ""
        if "rev-list" in cmd and cmd[-1] == f"HEAD..origin/{branch}":
            return (0, behind_own, "") if own_ref_exists else (128, "", "fatal: bad revision")
        raise AssertionError(f"unexpected git cmd: {cmd}")
    return fake_run
```
