## 3. Design

### 3a. Primary: `scripts/codex_task.py`

Add a module-level helper (near `POST_MARKER_TIMEOUT_SECS = 60`, line 252) and call it at the rc==0 return. Exact code being changed (verified, lines 414-415):

```python
            if result.returncode == 0:
                return True
```

becomes:

```python
            if result.returncode == 0:
                _forward_success_stderr(kind, result.stderr)
                return True
```

New helper:

```python
_SUCCESS_STDERR_FORWARD_CAP = 2000  # chars; the #1100 LANDING CHECK ERROR is ~600-750 chars
                                    # once interpolated — the cap must NOT truncate its
                                    # recovery recipe (cherry-pick cmd sits at the tail)


def _forward_success_stderr(kind: str, stderr: str | None) -> None:
    """Forward a rc==0 post-marker child's non-empty stderr to the wrapper's
    stderr (#1130). ``task.py post-marker`` deliberately exits 0 while
    printing warnings to stderr — the deferred-commit ERROR and the #1100
    post-commit LANDING CHECK — and ``capture_output=True`` would otherwise
    discard them so they reach no transcript. Capped so a pathological
    child can never flood the wrapper transcript."""
    err = (stderr or "").strip()
    if not err:
        return
    truncated = len(err) > _SUCCESS_STDERR_FORWARD_CAP
    for line in err[:_SUCCESS_STDERR_FORWARD_CAP].splitlines():
        print(f"[post-marker stderr] {kind}: {line}", file=sys.stderr)
    if truncated:
        print(
            f"[post-marker stderr] {kind}: ... (truncated at "
            f"{_SUCCESS_STDERR_FORWARD_CAP} chars)",
            file=sys.stderr,
        )
```

Notes: `sys` is already imported (line 132); prints happen once per successful post (the rc==0 branch returns immediately, so attempt 2 can fire it at most once more only after attempt 1 failed). The rc!=0 WARN path (416-420) keeps its existing `result.stderr[:500]` — it already forwards, and its truncation is acceptable there (failure summary; `_marker_already_landed` + orphan-drop carry the recovery story on that path).

## 9. §11 Decision Rationale

1. **Forward-with-prefix shape (`[post-marker stderr] {kind}: {line}`, per-line).**
   *What:* each non-empty child stderr line printed to wrapper stderr with a greppable prefix + the marker kind. *Why:* transcripts interleave many tool outputs; a bare passthrough is unattributable, and per-line prefixing survives partial log tailing (`tail -50`, the CLAUDE.md log-hygiene pattern). *Source:* the file's own WARN style (`codex_task.py:416-420` prefixes `WARN: post-marker ... for {kind}`) + the orchestrator brief's suggested shape. *Alternatives:* single-block print (loses per-line greppability); reusing the literal `WARN:` prefix (conflates success-warnings with the rc!=0 failure path that tests and humans already grep for).
2. **Truncation cap = 2000 chars (not the existing `[:500]`).**
   *What:* forward at most 2000 chars + an explicit truncation notice line. *Why:* the payload here IS the warning — the landing-check message embeds its recovery recipe (`git cherry-pick <sha>` ... at `task_workflow.py:5004-5010`, tail of the message); a 500-char cap would truncate exactly the actionable part. 2000 ≈ ≥2.5× the estimated ~600-750-char interpolated message, covers a stacked deferred+landing pair, and still bounds a pathological flood. *Source:* measured format string `task_workflow.py:5000-5019` (estimate — assumption 8); the `[:500]` precedent at `codex_task.py:418` is for a failure summary where the orphan-drop path carries recovery. *Alternatives:* no cap (unbounded transcript flood risk); `[:500]` (truncates the recovery command); line-count cap (equivalent, chars simpler to reason about).
3. **Per-file tiny helper (3 small copies) instead of one shared helper in `task_workflow.py`.**
   *What:* ~10-line helper duplicated per script. *Why:* the forwarding is a script-side transcript concern, not task-workflow API surface; a `src/` change widens review scope and couples three independently-tested scripts to one library print helper. *Source:* minimal-diff discipline for workflow-fix tasks (`.claude/rules/workflow-fix-on-bug.md`); no existing in-repo helper found (reuse-search done, §2). *Alternatives:* shared helper in `task_workflow.py` (DRY, but library-surface creep); fixing only `codex_task.py` (violates the body's "update every hit" for the same pattern).
