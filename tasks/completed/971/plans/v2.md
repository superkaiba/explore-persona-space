# Plan v2 — #971: recover head-name-less rebase husk in `sync_repo_root.py`

## 0.0 TL;DR (plain English)

- **What I'll change:** teach the root-sync helper's stale-husk recovery to handle a `.git/rebase-merge` (or `rebase-apply`) directory that a crashed autostash-pull left behind with only an `autostash` file and no `head-name`. Today `git rebase --abort` fails on that shape (rc=1) and the helper exits 6 forever, blocking every session's root sync (the 2026-07-03 ~8h fleet wedge). The fix: attempt the abort first; when it fails AND the dir is a rebase state with no `head-name` AND it is not an interrupted `git am` session (git's own `applying` marker), rescue the autostash commit into git's stash list (`git stash store`), then ARCHIVE the whole husk dir aside into the rescue root and continue. An interrupted `git am` session — which shares `.git/rebase-apply` and also lacks `head-name` — is REFUSED loudly (exit 5, naming `git am --continue` / `git am --abort`), never touched.
- **What I expect:** the incident husk shape now recovers automatically with the stashed work preserved (and usually re-applied by the existing stranded-autostash pass); a paused/conflicted `git am` keeps its patch data and its owner's `--continue` capability; all existing husk behavior (young-husk exit 5, valid-husk abort) is byte-for-byte unchanged.
- **What would change my mind:** evidence that git can represent a *valid, resumable* rebase without `head-name` (it cannot — verified on git 2.34.1 for BOTH the merge and apply backends: a real conflicted rebase always writes `head-name`, and the abort itself requires it), or that `applying` appears in genuine rebase states (it does not — verified: conflicted am has `applying` + no `head-name`; conflicted apply-backend rebase has `rebasing` + `head-name`, no `applying`).

## 1. Goal, requirement, acceptance criteria

**Goal** (task #971 body): in `sync_repo_root.py`'s aged-husk branch, when `git rebase --abort` fails AND the rebase state dir lacks `head-name`, rescue any autostash SHA via `git stash store`, then remove the husk dir from `.git` and continue — without ever touching an interrupted `git am` session or deleting data.

**Requirement:** the helper must never again hard-wedge (exit 6 on every invocation) on the incident husk class — a stale rebase state dir containing only `autostash` — while preserving all module safety invariants, all existing husk behavior, and the integrity of any `git am` session that shares `.git/rebase-apply`.

**Acceptance criteria:**
1. A fixture reproducing the incident husk (stale `.git/rebase-merge/` containing only a valid autostash SHA, no `head-name`) syncs with exit 0; the autostash commit lands in the stash list (and is then processed by the existing stranded-autostash pass: rescue patch written, popped if clean); the husk dir is gone from `.git` and ARCHIVED intact under `RESCUE_ROOT`.
2. A stale head-name-less **rebase** husk with NO autostash file (and the empty-autostash-file variant) is ARCHIVED aside — never deleted; sync proceeds; exit 0. (Scope: rebase loop entries only; `MERGE_HEAD` never reaches this path.)
3. A YOUNG head-name-less husk still exits 5, untouched (age gate unchanged).
4. A stale husk WITH `head-name` takes the existing abort path unchanged (`test_stale_husk_auto_aborted_then_continue` passes unmodified).
5. Autostash content that is non-40-hex, unresolvable, or resolvable-but-not-stash-shaped is preserved (report + verbatim rescue file + the archived dir itself) and NEVER `stash store`d — no downstream `stash show` wedge.
6. A `git stash store` failure on a storable commit exits 6 with the SHA named and the husk KEPT (rescue failure blocks the archive move).
7. `--dry-run` reports the head-name-less case distinctly, reports an am-session state as would-refuse (never as would-rescue), and mutates nothing.
8. Full `tests/test_sync_repo_root.py` passes; `ruff check` clean; `workflow_lint.py` default run passes.
9. **(MF2)** When `git rebase --abort` fails on a stale husk whose `head-name` IS present, the helper REFUSES with exit 6, the husk is KEPT, and the refusal message is emitted — pinned by a delegate-otherwise monkeypatch test on a genuine conflicted-rebase fixture.
10. **(MF1)** A stale, genuinely conflicted `git am` state (`.git/rebase-apply` with `applying`, no `head-name`) is REFUSED with exit 5; the state dir survives INTACT including its `patch` file; the message names `git am --continue` / `git am --abort`.

- `git rev-parse -q --verify <sha>^2`: **rc=0** for a `git stash create` commit (stash commits have ≥2 parents), **rc=1** for an ordinary single-parent commit — a working stash-shapedness discriminator (C1).
- `git stash store -m autostash <stash-create sha>`: rc=0, entry appears as `stash@{0}: autostash`, `git rev-parse refs/stash` == sha, `git rev-list -g refs/stash` lists it. Store even accepts a non-stash-shaped commit (rc=0) on 2.34.1 — which is precisely why C1's shapedness guard is needed BEFORE store (a stored non-stash commit wedges `recover_stranded_autostash`'s `check=True` `git stash show -p` fallback at line ~836 on every later run, with the husk already gone).
- `git cat-file -e <x>^{commit}`: rc=0 for the real sha; rc=128 for garbage AND for a valid-hex missing object. Note `cat-file -e` also resolves ref NAMES (`HEAD^{commit}` resolves) — hence the 40-hex pre-check (C2).
- `git rebase --quit` (rejected alternative): on a valid-autostash husk it stores + removes (rc=0); on a GARBAGE-autostash husk it prints `error: cannot store not-a-sha`, **still removes the husk, and returns rc=0** — the rescue failure cannot block removal, so `--quit` violates the module invariant.

## 4. Design — answers to the design questions

**Q1 — trigger condition: attempt-abort-first, then discriminate on state files.** Attempt `git rebase --abort` (`check=False`) and route on failure; do NOT pre-check files and skip the abort. Rationale: (a) git-mediated recovery stays the primary path — if any git version CAN abort a state we think is broken, git wins and no manual surgery runs; (b) the manual path is thereby scoped to states git has *provably refused* this run (rc + stderr captured into the report as evidence); (c) the discriminators are FILE EXISTENCE, not stderr text matching (robust across git versions/locales). **Correction vs round 1 (MF1d):** "abort failed + head-name missing" does NOT identify exactly the un-abortable-rebase class — it ALSO matches an interrupted/paused `git am` session, which shares `.git/rebase-apply`, has no `head-name`, carries content-bearing files (`patch`, `0001`, `final-commit`, `msg`, …), and fails `git rebase --abort` with rc=128 ("It looks like 'git am' is in progress"). The corrected trigger therefore requires THREE conditions: abort rc≠0 ∧ rebase state dir lacking `head-name` ∧ **no `applying` marker** — `applying` being git's own am-vs-rebase discriminator (verified: present in conflicted am; absent in genuine conflicted rebases on both backends, which carry `head-name`, the apply backend additionally `rebasing`). A real (git-created) rebase always has `head-name` — written during setup, required by the abort itself — so a real rebase can never enter the fallback; belt-and-suspenders, the stale-age gate has already passed before any abort is attempted, and the discriminators are recomputed immediately before the archive move (C3).

**Q1b — am-refusal exit code = 5 (`EXIT_PRECONDITION`).** Rationale (one line): exit 5 is the module's "an operator-resolvable repo state blocks sync" class (young husk, persistent `index.lock`, HEAD≠main) and an am session — even a stale one — is exactly that; exit 6 stays reserved for unexpected internal failures. Refusal is PRIMARY (MF1a): archiving/moving a possibly-live am session would still break its owner's `git am --continue`, so the ONLY safe action is a loud wedge naming the two resolutions (`git am --continue` to finish, `git am --abort` to discard). This deliberately re-creates a wedge for genuinely-abandoned am states — that wedge is the pre-#971 SAFE behavior (exit-nonzero, nothing touched), now with an actionable message instead of a generic `CalledProcessError`.

**Q2 — autostash rescue mechanics.** Read `sha = (husk/"autostash").read_text().strip()`. Disposition table (recomputed for v2 — every row ends in either ARCHIVE-ASIDE or REFUSE-husk-kept; a rescue failure always blocks the MOVE):

| Sub-case | Guard | Action | Terminal |
|---|---|---|---|
| `applying` present (any autostash content) | trigger-level, before this table | REFUSE exit 5, message names `git am --continue`/`--abort` | husk KEPT intact |
| autostash file absent | — | disposition noted in the archive message | ARCHIVE |
| file present but empty after strip | — | "autostash file empty — nothing to rescue" (git's own `READ_ONELINER_SKIP_IF_EMPTY` treats empty as no-autostash) | ARCHIVE |
| content not a 40-hex sha (C2 — `cat-file -e` would also resolve ref NAMES like `HEAD`) | `len==40 ∧ all hex` fails | preserve VERBATIM to `RESCUE_ROOT/husk-autostash-<name>-<ts>.txt` + loud report; never passed to git | ARCHIVE (the archived dir preserves the file a second time) |
| 40-hex but unresolvable (`git cat-file -e <sha>^{commit}` rc≠0 — garbage object id or missing object) | resolvability | preserve verbatim as above; nothing storable exists behind the pointer; refusing would recreate the permanent wedge over a dangling reference (C8: sound; if the object store was transiently broken, the rescue file + the report's full-sha + manual recipe keep manual re-store possible) | ARCHIVE |
| resolvable but NOT stash-shaped (`git rev-parse -q --verify <sha>^2` rc≠0 — no second parent) (C1) | stash-shapedness | preserve verbatim as above; storing it would poison the stash list: `recover_stranded_autostash`'s `check=True` `git stash show -p` fallback (line ~836) would exit-6-wedge every later run with the husk already gone | ARCHIVE |
| stash-shaped and already in `git rev-list -g refs/stash` | reflog containment | report "already present in the stash reflog" (idempotent re-run after a prior partial recovery — e.g. store succeeded, move crashed) | ARCHIVE |
| stash-shaped, not yet stashed, `git stash store -m autostash <sha>` rc=0 | — | report the stored entry; consumed by the existing `recover_stranded_autostash` pass in the SAME preflight | ARCHIVE |
| stash-shaped but `stash store` FAILS | — | `SyncAbortError(EXIT_UNEXPECTED, ...)` naming the full sha + stderr + the manual recipe | **REFUSE — husk KEPT, nothing moved** |
| TOCTOU recheck at move time finds `head-name` or `applying` materialized | C3 | `SyncAbortError(EXIT_UNEXPECTED, ...)` — a concurrent operation may be live | **REFUSE — husk KEPT, nothing moved** |

The message `-m autostash` is load-bearing: it makes the stored entry's list subject exactly `autostash`, which is what `_autostash_entries()` (line 790) matches — so the rescued stash flows into the existing rescue-patch + pop-if-clean machinery with zero new code, and matches git's own autostash-store message.

**Q3 — husk disposal = ARCHIVE-ASIDE, not deletion (MF1b).** `shutil.move(str(husk), str(allocate_rescue_dir() / husk.name))`, Python-mediated, reusing the module's existing exclusive rescue-dir allocator (`allocate_rescue_dir()`, lines 176-199: `<UTC-ts>-<pid>[-k]` + `mkdir(exist_ok=False)` — a same-second concurrent run can never reuse a prior dir). Why archive instead of `rmtree`: (a) it preserves EVERY husk file for unforeseen state shapes — the am incident proved the class of "state dirs we didn't anticipate" is non-empty, and an archived dir is fully restorable (`mv` it back) where a deleted one is not; (b) same-device it is a single atomic `rename`, eliminating the mid-`rmtree` window in which partial deletion refreshes the dir mtime and re-wedges the young gate; cross-device `shutil.move` degrades to copytree + rmtree-of-source — the source is deleted only AFTER a complete copy, so content is never at risk, and the residual re-wedge window is bounded (young gate ≤1h, then the idempotent re-run: reflog containment reports "already present", a NEW exclusive rescue dir is allocated). The `git()` deny-list is argv-shape-based and offers no state-dir primitive; git's own mediated removal is `rebase --quit`, REJECTED on empirical evidence: `--quit` removes the state dir and returns rc=0 even when its internal autostash store errors (`error: cannot store not-a-sha` — `save_autostash`'s return is ignored), so a rescue failure could not block removal. **Scope (MF1c):** the recovery helper is reachable ONLY via: rebase loop entry (`abort_args[0] == "rebase"`) + stale age-gate PASS + abort rc≠0 + husk-is-dir + `applying` absent + `head-name` absent + autostash disposition resolved + TOCTOU recheck clean. **rebase-apply:** same handling as rebase-merge once the `applying` refusal has excluded am states — a head-name-less, applying-less `rebase-apply` dir is the crashed-autostash-pull shape on the apply backend (empirically the abort fails identically: rc=1 `could not read '.git/rebase-apply/head-name'`). **MERGE_HEAD: out of scope** — `git merge --abort` is `reset --merge` keyed on `MERGE_HEAD` itself, which exists by construction when the loop entry matches; no head-name-style dependency exists. A failing `merge --abort` — and the degenerate malformed case where `MERGE_HEAD` is a DIRECTORY — routes to the explicit exit-6 refusal (both discriminators are False for non-rebase entries by construction), never the recovery helper.

**Q4 — age-gating: UNCHANGED.** The young-husk exit-5 raise stays lexically first and byte-unchanged; a young head-name-less husk (and a young am state) exits 5 untouched. Write-order: the incident husk (autostash present, head-name absent) is itself the existence proof that git's setup writes `autostash` before `head-name` — so a young head-name-less husk genuinely can be a mid-setup race, and the existing age gate (default 3600s) is the correct guard. No change needed, and none made.

**Q5 — dry-run.** The dry-run branch pre-checks `applying` AND `head-name` by file existence (report-only; no abort attempted — subprocess attempts are contrary to the branch's report-only shape, and file existence is sufficient for reporting):
- am state: `DRY-RUN: stale {name} state is a `git am` session (`applying` present) — a real run would refuse (exit 5); resolve via `git am --continue` / `git am --abort`` (MF1d: dry-run never misreports an am shape as removable);
- head-name-less: `DRY-RUN: stale head-name-less {name} husk ({age}s old) — un-abortable by git; autostash would be rescued to the stash list, then the husk dir archived to the rescue root`;
- otherwise: existing `DRY-RUN: stale {name} husk ({age}s old) would be aborted` (byte-unchanged). C9 disposition: this message is optimistic when the abort would in fact fail on a head-name-PRESENT stale husk — accepted as cosmetic (report-only path; the real run fails loud with the full evidence), no change.

**Q6 — reporting.** Mirrors the existing shapes: the archive posts one `_msg` — `STALE-HUSK ARCHIVED: {name} was {age}s old (> threshold), head-name-less and un-abortable (`git rebase --abort` rc={rc}: {stderr}); {autostash disposition}; husk dir archived to {dest}.` — and sets `report["actions_performed"] = True`; each autostash disposition also appends a `husk-rescue: ...` row to `report["stash"]`. No new report keys, no new exit codes. (The round-1 `STALE-HUSK REMOVED` string never shipped; renaming to `ARCHIVED` costs nothing.)

New helper (placed after `preflight`; no new imports — `shutil` already imported; the hex check is plain Python to avoid an `re` import):

```python
def _recover_headnameless_husk(
    repo: Path, husk: Path, age: float, aborted: subprocess.CompletedProcess[str], report: dict
) -> None:
    """Rescue-then-ARCHIVE for a stale, un-abortable, head-name-less rebase husk.

    A crashed ``pull --rebase --autostash`` can die after writing
    ``<state-dir>/autostash`` but before ``head-name`` (2026-07-03 incident,
    #971); git can neither represent nor abort a rebase without ``head-name``
    (``git rebase --abort`` rc=1), so the husk permanently wedges preflight.
    The caller has already excluded an interrupted ``git am`` session (the
    ``applying`` marker — ``git am`` shares ``rebase-apply``); this helper
    re-checks both discriminators immediately before the move (TOCTOU).
    Recovery order preserves the never-lose-data invariant: (1) rescue the
    autostash commit into the stash list (``git stash store -m autostash``;
    guarded by a 40-hex pre-check, ``cat-file -e`` resolvability, and a
    ``rev-parse <sha>^2`` stash-shapedness check — a stored non-stash commit
    would wedge the stranded-autostash pass downstream; idempotent via a
    stash-reflog containment check; a store failure on a storable commit
    BLOCKS the move — fail loud, husk kept); non-storable autostash content
    is preserved verbatim under ``RESCUE_ROOT`` first; (2) only then
    ``shutil.move`` the ENTIRE husk dir into a fresh exclusive
    ``allocate_rescue_dir()`` — archive-aside, never deletion: every husk
    file survives for unforeseen shapes, and the same-device rename closes
    the mid-``rmtree`` mtime-refresh re-wedge window. The stored entry's
    subject is exactly ``autostash``, so preflight step (4)
    (``recover_stranded_autostash``) immediately rescue-patches and
    pops-if-clean. Deliberately NOT ``git rebase --quit``: quit removes the
    state dir and exits 0 even when its internal autostash store FAILS
    (verified on git 2.34.1), so rescue failure could not block removal.
    """
    autostash_file = husk / "autostash"
    sha = autostash_file.read_text().strip() if autostash_file.exists() else ""
    if not autostash_file.exists():
        disposition = "no autostash file present"
    elif not sha:
        disposition = "autostash file empty — nothing to rescue"
    else:
        is_hex40 = len(sha) == 40 and all(c in "0123456789abcdef" for c in sha)
        resolvable = (
            is_hex40
            and git(repo, "cat-file", "-e", f"{sha}^{{commit}}", check=False).returncode == 0
        )
        stash_shaped = (
            resolvable
            and git(repo, "rev-parse", "-q", "--verify", f"{sha}^2", check=False).returncode == 0
        )
        if not stash_shaped:
            RESCUE_ROOT.mkdir(parents=True, exist_ok=True)
            rescue_path = RESCUE_ROOT / f"husk-autostash-{husk.name}-{_rescue_timestamp()}.txt"
            rescue_path.write_text(autostash_file.read_text())
            reason = (
                "not a 40-hex sha"
                if not is_hex40
                else "does not resolve to a commit"
                if not resolvable
                else "resolves but is not stash-shaped (no second parent) — storing it "
                "would wedge the stranded-autostash pass"
            )
            disposition = (
                f"autostash content {sha!r}: {reason}; nothing storable — content "
                f"preserved at {rescue_path} (and in the archived husk dir)"
            )
        elif sha in git(repo, "rev-list", "-g", "refs/stash", check=False).stdout.split():
            disposition = f"autostash {sha[:12]} already present in the stash reflog"
        else:
            store = git(repo, "stash", "store", "-m", "autostash", sha, check=False)
            if store.returncode != 0:
                raise SyncAbortError(
                    EXIT_UNEXPECTED,
                    f"head-name-less {husk.name} husk: could not rescue autostash {sha} "
                    f"(`git stash store` rc={store.returncode}: {store.stderr.strip()}); "
                    "husk left in place — nothing moved.\n"
                    f"manual: git stash store -m autostash {sha}  # then re-run the sync",
                )
            disposition = (
                f"stored autostash {sha[:12]} as a stash entry "
                "(handled next by the stranded-autostash pass)"
            )
        report["stash"].append(f"husk-rescue: {disposition}")
    # TOCTOU recheck (recompute the discriminators immediately before the move):
    # a concurrent operation may have materialized real state since triage.
    if (husk / "head-name").exists() or (husk / "applying").exists():
        raise SyncAbortError(
            EXIT_UNEXPECTED,
            f"{husk.name} husk changed while being recovered (head-name/applying "
            "appeared) — a concurrent operation may be live; nothing moved.",
        )
    dest = allocate_rescue_dir() / husk.name
    shutil.move(str(husk), str(dest))
    _msg(
        report,
        f"STALE-HUSK ARCHIVED: {husk.name} was {age:.0f}s old (> {_husk_age_s():.0f}s), "
        f"head-name-less and un-abortable (`git rebase --abort` rc={aborted.returncode}: "
        f"{aborted.stderr.strip()}); {disposition}; husk dir archived to {dest}.",
    )
    report["actions_performed"] = True
```

## 11. Decision Rationale

Hyperparameter grounding: **N/A — no training hyperparameters** (kind: infra; no model training).

1. **Trigger = attempt-abort-first; fall back on (rc≠0 ∧ rebase entry ∧ dir ∧ no `applying` ∧ no `head-name`)** — *Why:* keeps git-mediated recovery primary; scopes manual surgery to states git provably refused; captures rc/stderr evidence; the round-1 two-condition trigger was empirically WRONG — it also matched interrupted `git am` sessions (MF1). *Source:* empirical (this session + round 1, git 2.34.1): head-name-less husk abort rc=1 for both state-dir names; conflicted `git am` → `applying` present / `head-name` absent / abort rc=128 "It looks like 'git am' is in progress"; genuine conflicted rebases (merge AND apply backends) → `head-name` present, `applying` absent; incident record in #971 body. *Alternatives:* pre-check files and skip the abort (rejected: loses the git-first principle and the captured evidence); stderr substring matching, e.g. keying on "git am is in progress" (rejected: locale/version-brittle vs file existence); extending recovery to am states via `git am --abort` (rejected: an am session's continue-vs-abort disposition belongs to its owner; auto-abort destroys the `--continue` capability).
2. **am refusal = exit 5 (`EXIT_PRECONDITION`), message naming `git am --continue` / `git am --abort`** — *Why:* 5 is the module's operator-resolvable-precondition class (young husk, persistent index.lock, HEAD≠main) and a stale am session is exactly that; 6 stays for unexpected internal failures; refusal (not move-aside) is the only action that preserves the owner's `--continue` (a relocated am session is broken even though "preserved"). *Source:* module exit-code table (lines 111-118) + MF1a; empirical am-state contents this session. *Alternatives:* exit 6 (rejected: misclassifies a known, actionable state as unexpected); archive-aside the am dir (rejected per MF1a: relocation breaks a live session).
3. **Rescue = `git stash store -m autostash <sha>` with 40-hex pre-check + `cat-file -e` validation + `rev-parse <sha>^2` stash-shapedness + reflog idempotency** — *Why:* `stash store` is git's own autostash-preservation primitive; `-m autostash` routes the entry into the existing `recover_stranded_autostash` machinery (subject match at line 790) for free; the 40-hex pre-check (C2) stops ref-name content (`HEAD`) from resolving via `cat-file`; the `^2` shapedness guard (C1) stops a resolvable NON-stash commit from being stored — a stored non-stash commit would exit-6-wedge every later run at the stranded pass's `check=True` `git stash show -p` fallback (line ~836) with the husk already gone, a WORSE wedge than the incident; `rev-list -g refs/stash` containment makes crashed-after-store re-runs idempotent. *Source:* empirical (this session): `^2` rc=0 for a `git stash create` commit, rc=1 for an ordinary commit; store rc=0 → `stash@{0}: autostash`; round-1 transcript for `cat-file`/store; manual incident recovery used exactly `git stash store`. *Alternatives:* store-then-validate (rejected: the module never runs `stash drop`, so a bad store is irreversible within the invariants); `git update-ref refs/task-workflow/...` (rejected: a new ref namespace the recovery machinery doesn't read); leaving the sha only in the report (rejected: an unreferenced commit is gc-able).
4. **Disposal = ARCHIVE-ASIDE (`shutil.move` into `allocate_rescue_dir()`), NOT `rmtree`, NOT `git rebase --quit`** — *Why:* preserves every husk file for unforeseen state shapes (the am incident proved that class non-empty) and is restorable; same-device it is one atomic rename, eliminating the mid-`rmtree` mtime-refresh re-wedge window; a rescue failure blocks the move (raise before `shutil.move`); `--quit` removes the state dir and exits 0 even when its internal store fails. *Source:* MF1b; empirical `--quit` behavior (round-1 transcript); `allocate_rescue_dir` exclusivity read from code (lines 176-199); `shutil.move` cross-device = copy-then-delete-after-full-copy (CPython documented behavior). *Alternatives:* bare `rmtree` (round-1 choice — rejected: destroys unforeseen files, mid-delete re-wedge window); threading the run's lazy `RescueDir` handle into `preflight()` (rejected: signature churn across call sites for no safety gain; a dedicated exclusive dir per recovery event is simpler and equally exclusive).
5. **TOCTOU recheck of both discriminators immediately before the move (C3)** — *Why:* triage-time file checks can go stale if a concurrent git operation materializes real state mid-run; re-asserting `no head-name ∧ no applying` right before `shutil.move` closes the window; violation → exit 6, husk kept. *Source:* C3; the module's existing never-touch-live-state posture (young gate, index.lock wait). *Alternatives:* holding a repo-level lock across triage+move (already held — the module runs under the root-sync flock; the recheck guards against non-module git operations the lock does not cover).
6. **Fail-loud semantics per sub-case (refuse on store-failure + TOCTOU; preserve-then-archive on non-storable)** — *Why:* a storable commit that cannot be stored is real data at risk → refuse with husk kept; non-storable content (non-hex / dangling / non-stash-shaped) has no safely-storable git object behind it → preserving the content (verbatim rescue file + the archived dir + the report) satisfies never-lose-data while refusing would recreate the permanent wedge the task exists to fix (C8: confirmed sound; the loud report carries the full content + manual recipe so transient object-store trouble remains manually recoverable). *Source:* module docstring invariants + the exit-6-forever incident. *Alternatives:* refuse on non-storable too (rejected: re-wedges on a 41-byte dangling pointer); silently proceed (banned).
7. **MERGE_HEAD excluded; failing `merge --abort` and malformed MERGE_HEAD directories get the explicit exit-6 refusal (MF1c)** — *Why:* `merge --abort` has no head-name dependency (`reset --merge` keyed on MERGE_HEAD, which exists by construction); the discriminators are computed only for rebase loop entries, so a malformed MERGE_HEAD directory can never reach the recovery helper. *Source:* git docs (`git merge --abort` synopsis) + the loop's own structure. *Alternatives:* extend recovery to MERGE_HEAD (rejected: no observed failure class; out of the candidate's scope).
