## 0.0 TL;DR (plain English)

- **What I'll change:** right now, when a session is deliberately stopped, the "this session was stopped" note it leaves behind is mistakenly counted as proof the session is still working — so the replacement session is told to wait instead of taking over. I'll make the takeover check ignore that stop note, and also ignore the fleet-watcher's bookkeeping notes, since neither is evidence the work is actually alive.
- **What I expect:** a replacement session can re-dispatch a dead stage as soon as the dead session's own last real signal ages out, instead of being blocked by its death record (the #810 incident, where an operator had to override by hand).
- **What would change my mind:** if excluding these notes breaks an existing pinned test that deliberately relies on them refreshing the window (none exists — I checked the one test file that covers this function), I'd fall back to excluding only the incident-backed deliberate-stop class.

## 0. Plan Summary (technical)

**Change:** in `stage_dispatch_should_skip` (`src/explore_persona_space/task_workflow.py:1385-1445`), the refresher loop currently counts EVERY non-breadcrumb `epm:progress` as stage liveness. Add two anti-liveness exclusions: (1) the deliberate-stop record (`note.startswith("deliberate-stop ")` after lstrip, OR `by == "spawn_session-stop"`), and (2) third-party bracketed telemetry (`"[autonomous_session_watch:"` or `"[spawn-session:"` substring), via a new module constant `STAGE_ANTILIVENESS_NOTE_SUBSTRINGS` placed next to `STAGE_LIVENESS_KINDS`. Exclusions stop the REFRESH only — they never clear the in-flight state (result kinds / `epm:failure` / window expiry still own that). **Docs:** one-line carve-out in the function docstring + the matching parenthetical in `.claude/skills/issue/SKILL.md` Step 9 entry-guard prose (line ~5242). **Tests:** 4 new pinned tests in `tests/test_stage_dispatch_dedup.py` (deliberate-stop note, `by`-field leg, watcher/spawn-session telemetry, and the inverse boundary — `[long-phase-heartbeat]` still refreshes); `_ev` helper gains a `by` kwarg. **No behavior change** for genuine liveness signals (`STAGE_LIVENESS_KINDS`, poll-pipeline progress notes, orchestrator notes). **Risks:** over-exclusion could early-re-dispatch a live-but-silent stage — bounded by the Step-0 single-orchestrator guard + implementer self-detection the docstring already names as backstops.

## 3. Exclusion-set decision (required scope question 1)

I grepped the posting sites (`scripts/spawn_session.py`, `scripts/autonomous_session_watch.py`) and classified every `epm:progress` note class as (a) genuine liveness of the stage's OWN work vs (b) third-party / anti-liveness:

| Note class | Poster | Class | In exclusion set? | Reason (one line) |
|---|---|---|---|---|
| `deliberate-stop pid=n/a target=happy-session:<sid> reason=...`, `by="spawn_session-stop"` | `spawn_session.py::cmd_stop:2064-2077` | anti-liveness | **YES** (incident-backed minimum) | It is the death record of the stage's owner — counting it inverts the guard exactly when a replacement needs a correct answer (#810). |
| `[autonomous_session_watch:<slug>]` notes (35 sentinel literals, ALL sharing this bracketed prefix — `_ALERT_NOTE_SENTINEL` ... `_CAPACITY_RETRY_EXHAUSTED_NOTE_SENTINEL`, `autonomous_session_watch.py:659-985`) | the 10-min watcher | third-party bookkeeping; several members (session-stalled-alert, session-auto-respawn, zombie-wrapper-stop) fire EXACTLY when the session is dead/stalled | **YES** (as the prefix class `"[autonomous_session_watch:"`) | The watcher itself excludes this exact set from its own progress clock (`_WATCHER_NOTE_SENTINELS` → `_latest_progress_ts`, lines 947-985 + 3334-3345) — "a watcher-posted alert is not real progress"; the correlation with session death makes under-exclusion actively harmful here (a stalled-alert landing in-window re-blocks the very takeover it announces the need for). |
| `[spawn-session:duplicate-dispatch-suppressed] ...` (`DUPLICATE_DISPATCH_NOTE_SENTINEL`, `spawn_session.py:113`) | spawn_session registration machinery | third-party bookkeeping | **YES** (as the prefix class `"[spawn-session:"`) | Already a member of the watcher's `_WATCHER_NOTE_SENTINELS` ("never counts as real progress", `spawn_session.py:110-113`); posted by session machinery, never by the stage's worker. |
| `[long-phase-heartbeat]` (`_LONG_PHASE_HEARTBEAT_PREFIX`, `autonomous_session_watch.py:941`) | the stage's OWN long-running phase | genuine liveness | **NO** — deliberately excluded from the exclusion | The watcher's comment (lines 930-940) is explicit: "it IS real progress ... deliberately NOT a member of `_WATCHER_NOTE_SENTINELS`". Pinned by the inverse-boundary test. |
| Everything else (poll-pipeline progress drains, orchestrator phase notes, follow-up-round notes, claim markers) | poll loop / orchestrator | ambiguous-to-genuine | **NO** | Conservative: over-excluding here is the "re-dispatch onto live work" risk the brief warns about; only provably third-party / anti-liveness classes are excluded. |

**Why over-exclusion risk is bounded for the two YES classes:** watcher/spawn-session telemetry is never posted by the stage's own worker, so excluding it cannot suppress a genuine liveness signal — a live stage still refreshes via `STAGE_LIVENESS_KINDS` markers and its own progress notes. The residual failure direction (a live-but-completely-silent stage loses an *accidental* extension) lands on the guard's documented backstops: the Step-0 single-orchestrator guard + implementer self-detection (`task_workflow.py:1406-1409` docstring).

**Matching semantics:** the deliberate-stop leg matches the lstripped note PREFIX `"deliberate-stop "` (trailing space — the leading structured token, parity with `failure_patterns.md:154-157`'s "note BEGINNING `deliberate-stop `") OR `by == "spawn_session-stop"` (belt and suspenders; both signals are pinned by `tests/test_spawn_session_stop_marker.py:89` and the `post_event` call site). The bracketed classes match by SUBSTRING containment — parity with the watcher's own `any(sentinel in note ...)` check at `autonomous_session_watch.py:3344`. A note merely *quoting* "deliberate-stop" mid-note is NOT excluded (prefix match); a note quoting a bracketed sentinel mid-note IS excluded — acceptable, since that failure direction is "window not refreshed", the backstopped one.

## 11. Decision Rationale

Hyperparameter grounding: **N/A — `kind: infra`, no model training.** The one design decision is the exclusion set (§3), recorded here:

- **What:** exclude (a) deliberate-stop records — lstripped-note prefix `"deliberate-stop "` OR `by == "spawn_session-stop"` — and (b) bracketed third-party telemetry — substrings `"[autonomous_session_watch:"` and `"[spawn-session:"` — from the refresh set; keep everything else (incl. `[long-phase-heartbeat]`) refreshing.
- **Why:** (a) is the incident-backed inversion (#810: a death record counted as liveness); (b) is posted by fleet machinery, never by the stage's worker, and several members fire exactly when the session is dead — the moment the guard's answer matters most.
- **Source:** (a) `scripts/spawn_session.py:2064-2077` (the `post_event` call), `tests/test_spawn_session_stop_marker.py:89` (pinned shape), `.claude/skills/issue/failure_patterns.md:154-157` (the leading-token match convention), task #810 events (incident). (b) `scripts/autonomous_session_watch.py:947-985` (`_WATCHER_NOTE_SENTINELS` — the fleet's canonical "not real progress" set) + lines 3334-3345 (`_latest_progress_ts` exclusion precedent) + `scripts/spawn_session.py:110-113` (`DUPLICATE_DISPATCH_NOTE_SENTINEL` comment: "never counts as real progress"). The kept-refreshing carve-out: `scripts/autonomous_session_watch.py:930-941` (`_LONG_PHASE_HEARTBEAT_PREFIX` "IS real progress ... deliberately NOT a member").
- **Alternatives rejected:** (i) *deliberate-stop only* (the task body's literal sketch) — leaves the watcher-note inversion live; a session-stalled-alert or auto-respawn note landing in-window re-blocks the takeover it announces, the same #810 failure shape with a different poster. Kept as the FALLBACK if the wider set breaks something (§6 kill criteria). (ii) *Import `_WATCHER_NOTE_SENTINELS` into task_workflow.py* — wrong-direction dependency (src/ importing a script); rejected. (iii) *Enumerate all 35 sentinel literals in task_workflow.py* — a sync burden the prefix class avoids (a new watcher sentinel auto-conforms to the mandated `[autonomous_session_watch:` form). (iv) *Match `by` prefixes instead of note substrings* — the watcher posts via `task.py post-marker` subprocess, so its `by` values are not a stable single literal the way the note sentinels are; note-based matching mirrors the fleet's existing convention.
