## Requirement
Stop the CPU-only orchestration VM root disk (`/`, single 500 GB ext4) from filling fast during an active task. Verified root cause: an active task holds a large re-downloadable HF download cache (`data/issue_<N>/hf_dl/.../store/`) that the existing terminal-status-gated cleaner cannot reap. The fix is workflow-surface only — three real levers and one defensive guard, none of which auto-deletes an active task's data. The bounded-by-construction fix (dedicated volume / ext4 project quotas) is filed as a separate follow-up.

## Method delta (vs prior state)
- `scripts/clean_experiment_downloads.py`: harden the existing wholesale `rmtree(hf_dl)` with metadata-presence parity ONLY when a nested `store/` is present at a terminal reap (fail-toward-keep); otherwise unchanged semantics.
- `scripts/autonomous_session_watch.py` + `scripts/tick_triage.py`: add a root-`/`-headroom signal with sub-floor 45-60s re-check and per-issue cache-path attribution (cheap `du -s` on `hf_dl`/`g*_dl` globs only). Warn-only escalation.
- `scripts/vm_disk_guard.py`: in the existing active-skip branch, add a `_telegram_push` escalation + sidecar JSONL (`.claude/cache/disk-guard-events.jsonl`) naming the task, the largest re-downloadable-cache path, footprint, and the SAFE reclaim command. Dedup on (task, threshold-band) + growth re-alert. **Never auto-deletes active data.** ~10-line addition.
- `src/explore_persona_space/orchestrate/preflight.py`: convert the existing `<min_free_gb>` WARN into a configurable hard FLOOR (env-overridable, with a logged override path) so a fresh launch below floor fails fast. Reuses `check_disk_space`; helps fresh launches only.
- `CLAUDE.md` + `.claude/skills/experiment-runner/SKILL.md`: document the between-phase contract (call `clean_experiment_downloads --incremental --apply <N>` after a phase consumes its downloads, before the next phase downloads) and the disk-hygiene caveats.
- File a separate `kind: infra` follow-up task: "attach a dedicated GCP persistent disk for `.claude/worktrees/` + per-issue caches, OR enable ext4 project quotas per issue."
