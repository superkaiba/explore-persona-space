### 3.1 `.claude/skills/issue/SKILL.md` (canonical text, ~30 lines)

Insert AFTER the abort-affordance paragraph (after line 312, before the
`---` at line 314). This is OUTSIDE the `<!-- workflow.yaml: AUTO-GENERATED

numbered elements):

```markdown
User pause affordance ("pause <N>", "hold <N>", "put <N> on hold"): a user
pause is a DURABLE park, never a prose-only marker. The session driving <N>
(or the PM/chat session receiving the directive):

1. `uv run python scripts/task.py set-status <N> on_hold --note "USER PAUSE
   (verbatim: '<user words>'); paused_from=<prior status>; resume:
   task.py set-status <N> <prior status> && spawn_session.py spawn-issue
   --issue <N> --auto"`. `on_hold` is in the watcher PARK set
   (`autonomous_session_watch.py` PARK): no orphan-respawn, no
   auto-dispatch, registration kept. The transition is legal from EVERY
   status WITHOUT `--force-followup-exit` (`on_hold` is not in
   `FOLLOWUP_HELD_BLOCKED_STATUSES`); pausing a `followups_running` round
   abandons that round's in-flight subagents — record `paused_from` so
   resume restores the held status.
2. Run CRON-TEARDOWN (§ CRON-TEARDOWN procedure — the /issue-tick backstop
   must not outlive the pause), then Step 8-bis: stop any RUNNING pod
   (`pod.py stop --issue <N>`, volume preserved) + post
   `epm:pod-stopped v1`. The autonomous "never stop a pod to PARK" ban does
   not apply: a user pause is a user directive, not an autonomous park.
3. EXIT the turn. Do NOT leave status at an ACTIVE value with a prose hold
   note — the watcher's orphan-respawn pass cannot parse prose and will
   respawn against the hold (incident #816, 2026-07-02).

Resume is user-greenlight ONLY: `task.py set-status <N> <paused_from>` (or
`proposed` for a full re-triage), then `spawn_session.py spawn-issue
--issue <N> --auto`; events.jsonl markers re-enter the loop at the same
point. Distinct mechanism: the `.paused-takeover-*` registration sentinel
(`.claude/rules/background-automation.md` § Deliberate session takeover) is
a short-TTL (~6h, FAIL-OPEN) session-TAKEOVER shield — it does NOT
implement a user pause. Known carve-out: a PROGRAM daemon that hardcodes
task revival (e.g. `run_program_orchestrator.sh`, the #660 leakage program,
revives its four pinned tasks from `on_hold`) can override the park for
exactly those pinned ids — pausing a program-pinned task additionally
requires the program's STOP sentinel.
```

### 3.4 Resolved design questions (a–e from the brief)

- **(a) Canonical placement:** SKILL.md abort-affordance vicinity (the two
  affordances are siblings: abort → `blocked`, pause → `on_hold`); CLAUDE.md
  carries the always-on pointer (covers PM/chat sessions, which do not load
  the issue SKILL); background-automation.md carries only the
  disambiguation. Total added text ≈ 40–45 lines — within the 30–60 budget.
- **(b) Transition legality:** `set-status <N> on_hold` is permitted from
  every status. Verified: `task_workflow.set_status` refuses ONLY
  `followups_running → FOLLOWUP_HELD_BLOCKED_STATUSES` (lines 2559–2574),
  and `on_hold` is absent from that frozenset (lines 199–201). The
  `scripts/task.py` plan-gate logic (cmd_set_status ~380–534) binds only on
  `new_status == plan_pending` + `--auto-approve-if-autonomous`; nothing
  binds on `on_hold`. So the rule text prescribes the plain form — no
  `--force-followup-exit` — and instead states the followups_running
  interaction (round abandonment + `paused_from` restore).
- **(c) Note content:** verbatim user directive + `paused_from=<prior
  status>` + the exact resume commands. `epm:status-changed` records the old
  status anyway, but the note makes resume one-glance and greppable.
- **(d) Session/pod teardown:** CRON-TEARDOWN (SKILL.md:3762 procedure) +
  Step 8-bis `pod.py stop` (stop, not terminate — a pause anticipates
  resume; volume preserved) + exit the turn. The autonomous
  "never stop a pod to PARK" rule is explicitly carved out (user directive,
  not autonomous parking) to preempt a conflict reading.
- **(e) Registration:** NO unregistration needed. PARK semantics
  (`autonomous_session_watch.py:468–469`) keep the registry entry but never
  respawn; residue is handled by existing reapers (zombie-wrapper pass —
  on_hold is not in its excluded-status set; stale-registration pass at
  ≥12h idle). Prescribing an unregister would add a step for no benefit and
  lose the entry's resume convenience.

## 11. Decision Rationale

- **on_hold (not blocked, not a new status) as the pause target.**
  *What:* route "pause <N>" to `set-status <N> on_hold`. *Why:* on_hold is
  already in the watcher PARK set, already documented as "explicitly set
  aside, excluded from auto-dispatch", and — unlike `blocked` — is never
  re-driven by the capacity-retry pass and carries no failure semantics. A
  new status would be an architectural enum change for zero gain.
  *Source:* `autonomous_session_watch.py:478`; `task_workflow.py:97`;
  incident #816 resolution (the respawned session itself parked at on_hold).
  *Alternatives:* `blocked` (wrong semantics + capacity-retry re-drive
  risk); extending the #903 sentinel TTL (FAIL-OPEN by design — deliberately
  not an indefinite hold); new `paused` status (public-contract change).
- **SKILL.md as canonical text + CLAUDE.md pointer.** *What:* full
  affordance next to the abort affordance; short always-on pointer in
  § Routing experiment intent. *Why:* the abort affordance is the exact
  sibling pattern (user verb → status route), and CLAUDE.md is the only
  surface loaded in PM/chat sessions where the verb usually lands.
  *Source:* SKILL.md:310–312; CLAUDE.md § Routing experiment intent
  (`**Archiving:**` sibling). *Alternatives:* CLAUDE.md-only (bloats the
  always-on file with procedure detail); a new rules file (requires
  LESSONS.md index churn for ~30 lines that belong beside the abort text).
- **Note format = verbatim directive + paused_from + resume commands.**
  *What:* §3.4(c). *Why:* a later session/watcher pass must be able to act
  on the note without archaeology; `paused_from` makes resume restore the
  exact pipeline point (incl. `followups_running`). *Source:* #816's
  recovery cost (the respawned session had to reconstruct intent from a
  prose marker). *Alternatives:* bare `--note "user pause"` (loses resume
  recipe); a new structured marker kind (contract change, over-engineering).
- **No unregistration on pause.** *What:* keep `issue-<N>.json`. *Why:* PARK
  semantics already keep-but-never-respawn; existing reapers handle residue;
  deleting would add a step and lose nothing. *Source:*
  `autonomous_session_watch.py:468–469` + § stale-registration /
  zombie-wrapper pass docs. *Alternatives:* explicit
  `spawn_session.py stop` + unregister (allowed, but not required — the
  rule text prescribes only "EXIT the turn").
- N/A — no model training (no hyperparameters to ground).
