## Plan Summary

**Change:** add one additive, WARN-only, offline check (`check_figure_tracked_at_head`, "check 29") to `scripts/verify_task_body.py`: for every same-repo SHA-pinned `raw.githubusercontent.com` figure URL whose path matches `figures/issue_<N>/...`, verify the path is tracked in the git tree at the live ref — union of `refs/heads/issue-<N>` (when it exists) and `HEAD` of the resolved repo root — and WARN (never FAIL) when it is missing from all checked refs. ### 3.2 New git helpers (next to `_git_object_exists`, after line 4172)

```python
def _git_ref_exists(repo: Path, ref: str) -> bool:
    """True iff `ref` resolves to a commit in `repo`. Never raises —
    any subprocess error returns False (fail-soft, check 29)."""
    try:
        r = subprocess.run(
            ["git", "rev-parse", "--verify", "--quiet", f"{ref}^{{commit}}"],
            cwd=str(repo), capture_output=True, text=True, timeout=10,
        )
    except (OSError, subprocess.SubprocessError):
        return False
    return r.returncode == 0

def _git_tracked_under(repo: Path, ref: str, prefix: str) -> set[str] | None:
    """Set of paths tracked under `prefix` in the tree at `ref` — ONE
    `git ls-tree -r --name-only <ref> -- <prefix>` per call (reads the
    tree object, NOT the working tree, so sparse checkouts are fine).
    None on any git error (fail-soft: caller degrades to skip-PASS)."""
    try:
        r = subprocess.run(
            ["git", "ls-tree", "-r", "--name-only", ref, "--", prefix],
            cwd=str(repo), capture_output=True, text=True, timeout=10,
        )
    except (OSError, subprocess.SubprocessError):
        return None
    if r.returncode != 0:
        return None
    return {line.strip() for line in r.stdout.splitlines() if line.strip()}
```

### 3.3 The check (placed directly after `check_figure_url_resolvable`, ~line 2010)

Signature: `def check_figure_tracked_at_head(body: str) -> CheckResult:`

Pseudocode:

```
urls = _gather_figure_image_urls(body)                    # same scope as checks 4/4b
paths_by_issue: dict[str issue_n -> set[str] repo-relative paths]
for url in urls:
    url = url.strip().split(None, 1)[0]                   # strip optional "title" (4b idiom)
    m = _RAW_GITHUB_FIGURE_RE.match(url)
    if not m or (owner, repo).lower() != _THIS_REPO_SLUG: continue   # other hosts/repos: out of scope
    pm = _ISSUE_FIGURE_PATH_RE.match(m.group("path"))
    if not pm: continue                                   # non-issue-dir figure paths: out of scope
    paths_by_issue[pm.group("issue")].add(m.group("path"))

if not paths_by_issue:
    return CheckResult(NAME, True, "no same-repo `figures/issue_<N>/` figure URLs to check")

repo = _resolve_repo_root()
if repo is None:
    return CheckResult(NAME, True, "skipped — repo root unresolved (running outside the repo)")

missing: list[str]   # "path @ refs-checked" strings
checked_refs: set[str]
for issue_n, paths in sorted(paths_by_issue.items()):
    refs = []
    branch = f"issue-{issue_n}"
    if _git_ref_exists(repo, f"refs/heads/{branch}"): refs.append(f"refs/heads/{branch}")
    refs.append("HEAD")                                   # always also check the checkout's HEAD
    tracked: set[str] = set(); probe_failed = True_if_all_refs_errored
    for ref in refs:
        s = _git_tracked_under(repo, ref, f"figures/issue_{issue_n}/")
        if s is not None: tracked |= s; probe_failed = False
    if probe_failed:
        return CheckResult(NAME, True,
            f"skipped — git ls-tree failed for `figures/issue_{issue_n}/` (fail-soft; never a FAIL)")
    checked_refs.update(human_labels(refs))               # "issue-841", "HEAD"
    missing += [f"`{p}` (checked: {', '.join(labels)})" for p in sorted(paths - tracked)]

if missing:
    return CheckResult(NAME, True, WARN_DETAIL, is_warn=True)
return CheckResult(NAME, True,
    f"{sum(len(v) for v in paths_by_issue.values())} figure path(s) tracked at {sorted(checked_refs)}")
```

- **Check name string:** `"figure tracked at branch HEAD"`.
- **Exact WARN message** (`WARN_DETAIL`, `"; "`-joined per missing path):
  `body-linked figure {`path`} is tracked at its pinned-SHA URL but UNTRACKED at {ref labels, e.g. `issue-841` and `HEAD`} — the immutable pinned URL still renders, so this tracking loss is otherwise silent (incident #841); re-commit the file on the live branch (`git add <path> && git commit`)`
- **Branch-resolution logic:** per-path issue number `N` from `figures/issue_<N>/` (NOT from `--issue`, so the check stays body-only and cross-issue figure links are checked against *their* branch). Refs checked = `refs/heads/issue-<N>` (only if it exists) ∪ `HEAD`. Presence at **either** ref counts as tracked. Rationale for the union (a deliberate refinement of the task's "branch when it exists, else HEAD" sketch): a completed task's `issue-<N>` branch can be stale while the figures were merged to `main` via a follow-up branch (`issue-<N>-<suffix>`) — branch-only checking would WARN-spam exactly the grandfathered class the constraint protects. The union still catches #841 (at incident time the files were missing from both `issue-841` and `main`). See §11.
- **Batching:** per body, ≤ (1 rev-parse + 2 ls-tree) × (number of unique issue dirs, almost always 1) — ≈2–3 subprocesses total regardless of URL count (a body with 30 figure URLs from one issue costs the same 3 calls). No per-URL subprocess. Nothing touches the network (no HTTP leg at all — unlike 4b there is no fallback: an undecidable git state is a skip-PASS, period).
- **Failure-mode posture:** every git error path returns `passed=True, is_warn=False` with a `skipped — ...` note. The check can never return `passed=False` by construction (no code path constructs one).
- **Registration:** append to `CHECKS` (line 7552, after `check_figure_label_codes`):
  `check_figure_tracked_at_head,  # check 29 (WARN) — body-linked figures tracked at issue-branch/HEAD (#964, incident #841)`
  Also add entry `29.` to the module-docstring check catalog (the numbered list around lines 100–160; implementer greps for the `28.` entry and inserts after; also grep the file for any pre-existing `check 29` string to confirm the number is free).

## 5. Kill criteria

- The §4.4 batch run WARNs on a material fraction (>~10%) of grandfathered completed bodies for a *systematic* branch-lifecycle reason the either-ref union does not cover (e.g. figures routinely tracked only on `issue-<N>-<suffix>` follow-up branches never merged) → the ref-resolution design is wrong; withdraw and re-plan (candidate fix: also union any `refs/heads/issue-<N>-*`).

## 10. §11 Decision Rationale

- **WARN, never FAIL.**
  What: the check always returns `passed=True`; drift is surfaced via `is_warn=True`.
  Why: a pinned URL still renders (the body is not broken — this is hygiene, not correctness), and grandfathered completed bodies must not start failing promotion gates retroactively.
  Source: task #964 body (explicit constraint) + incident #841.
  Alternatives: FAIL (rejected — regresses grandfathered bodies; banned by the task); WARN-with-escalation-after-date (rejected — needless statefulness).
- **Branch-resolution = union of `refs/heads/issue-<N>` (if present) and `HEAD`, per-path `N`.**
  What: a path counts as tracked if present at *either* ref; `N` comes from the `figures/issue_<N>/` path itself.
  Why: branch-only checking WARN-spams merged tasks with stale leftover branches (figures merged to `main` via a follow-up branch); `HEAD`-only misses the pre-merge incident case where the loss lives on the issue branch. The union covers both and still catches #841 (missing from both refs at incident time). Per-path `N` keeps the check body-only (works under `--body-stdin`) and handles cross-issue figure links correctly.
  Source: task #964 diff sketch (refined; the refinement is flagged here per the "must-flag deviations" discipline) + #841 incident record + the project's follow-up-branch (`issue-<N>-<suffix>`) lifecycle.
  Alternatives: sketch-literal "branch else HEAD" (rejected — the false-positive class above); also globbing `issue-<N>-*` branches (deferred — adds subprocess cost and complexity; revisit only if §5's kill-criterion batch data demands it).
- **Batching via one `ls-tree -r --name-only <ref> -- figures/issue_<N>/` per (issue, ref) + set membership.**
  What: directory-prefix listing, not per-path `git cat-file`.
  Why: dozens of figure URLs per body must not cause a subprocess storm (task brief requirement); a directory listing is one call and sidesteps pathspec quirks; output is small (hundreds of lines max).
  Source: task #964 brief; `_git_object_exists` per-URL pattern as the counter-example to avoid at this fan-out.
  Alternatives: batched explicit pathspecs in one `ls-tree` call (equivalent cost; allowed deviation); per-path `cat-file -e HEAD:<path>` (rejected — N subprocesses).
- **Fail-soft to NO-OP PASS on any git error.**
  What: subprocess error / non-zero rc / unresolved repo root → `passed=True, is_warn=False`, `skipped — ...` note.
  Why: the verifier gates promotion for every clean-result; an environmental git hiccup must never block or add noise. Matches the established `'skip'` semantics of `_git_object_exists` / `_figure_url_existence`.
  Source: task brief ("degrade to a NO-OP PASS with a note"); precedent at lines 4138–4158.
  Alternatives: skip-as-WARN (rejected — noisy on stdin/outside-repo runs).
