### 3.2 New git helpers (next to `_git_object_exists`, after line 4172)

```python
def _git_issue_branch_family(repo: Path, issue_n: str) -> list[str] | None:
    """Local branch family for an issue: refs/heads/issue-<N> plus every
    refs/heads/issue-<N>-* follow-up branch, via ONE
    `git for-each-ref --format='%(refname:short)'
       refs/heads/issue-<N> 'refs/heads/issue-<N>-*'`.
    Returns short names (e.g. ['issue-841', 'issue-841-fu2']); [] when no
    family branch exists; None on any git error (fail-soft)."""
    try:
        r = subprocess.run(
            ["git", "for-each-ref", "--format=%(refname:short)",
             f"refs/heads/issue-{issue_n}", f"refs/heads/issue-{issue_n}-*"],
            cwd=str(repo), capture_output=True, text=True, timeout=10,
        )
    except (OSError, subprocess.SubprocessError):
        return None
    if r.returncode != 0:
        return None
    return [ln.strip() for ln in r.stdout.splitlines() if ln.strip()]

def _git_tracked_under(repo: Path, ref: str, prefix: str) -> set[str] | None:
    """Set of paths tracked under `prefix` in the tree at `ref` — ONE
    `git -c core.quotePath=off ls-tree -r --name-only <ref> -- <prefix>`
    per call (reads the tree object, NOT the working tree, so sparse
    checkouts are fine; quotePath=off keeps non-ASCII paths raw so set
    membership works). None on any git error (fail-soft: caller degrades
    that REF to unprobed — never a WARN from a failed probe)."""
    try:
        r = subprocess.run(
            ["git", "-c", "core.quotePath=off", "ls-tree", "-r",
             "--name-only", ref, "--", prefix],
            cwd=str(repo), capture_output=True, text=True, timeout=10,
        )
    except (OSError, subprocess.SubprocessError):
        return None
    if r.returncode != 0:
        return None
    return {line.strip() for line in r.stdout.splitlines() if line.strip()}
```

### 3.3 The check (placed directly after `check_figure_url_resolvable`, ~line 2010)

Signature: `def check_figure_tracked_at_head(body: str) -> CheckResult:`

Pseudocode (v3 — three-state classification):

```
urls = _gather_figure_image_urls(body)                    # same scope as checks 4/4b
paths_by_issue: dict[str issue_n -> set[str] repo-relative paths]
for url in urls:
    url = url.strip().split(None, 1)[0]                   # strip optional "title" (4b idiom)
    m = _RAW_GITHUB_FIGURE_RE.match(url)
    if not m or (owner, repo).lower() != _THIS_REPO_SLUG: continue   # other hosts/repos: out of scope
    pm = _ISSUE_FIGURE_PATH_RE.match(m.group("path"))
    if not pm: continue                                   # non-issue-dir figure paths: out of scope
    paths_by_issue[pm.group("issue")].add(m.group("path"))

if not paths_by_issue:
    return CheckResult(NAME, True, "no same-repo `figures/issue_<N>/` figure URLs to check")

repo = _resolve_repo_root()
if repo is None:
    return CheckResult(NAME, True, "skipped — repo root unresolved (running outside the repo)")

missing: list[str]      # incident-class WARN entries
branch_only: list[str]  # disclosure entries (PASS note)
skipped: list[str]      # per-issue probe-failure notes (PASS note)
for issue_n, paths in sorted(paths_by_issue.items()):
    family = _git_issue_branch_family(repo, issue_n)      # None on git error
    probes: dict[label -> set[str] | None] = {"HEAD": _git_tracked_under(repo, "HEAD", prefix)}
    for br in (family or []):
        probes[br] = _git_tracked_under(repo, br, prefix)
    ok_probes = {label: s for label, s in probes.items() if s is not None}
    if family is None or len(ok_probes) < len(probes):
        # CONSERVATIVE: any failed probe for this issue -> no WARN possible
        # (the path might live at the failed ref). Per-issue skip note; CONTINUE
        # to the next issue dir (no whole-body early return).
        skipped.append(f"figures/issue_{issue_n}/ — probe failure on {failed labels}; drift not assessed")
        continue
    head_set = ok_probes["HEAD"]; family_union = union of ok_probes minus HEAD
    for p in sorted(paths):
        if p in head_set:                continue                      # clean PASS
        elif p in family_union:          branch_only.append(f"`{p}` (on {family labels holding p}, not at HEAD)")
        else:                            missing.append(f"`{p}` (checked: {sorted(ok_probes)})")

if missing:
    return CheckResult(NAME, True, WARN_DETAIL + optional_disclosure_suffix, is_warn=True)
note = f"{n_pass} figure path(s) tracked at HEAD"
if branch_only: note += f"; BRANCH-ONLY (not at HEAD/main — expected pre-merge): {branch_only}. If this task is already merged/completed, the canonical copy is missing from main — restore with `git restore --source=<pinned-sha> -- <path>` and commit on main."
if skipped:     note += f"; skipped: {skipped}"
return CheckResult(NAME, True, note)
```

- **Check name string:** `"figure tracked at live refs"`.
- **Exact WARN message** (`WARN_DETAIL`, `"; "`-joined per missing path):
  `body-linked figure {`path`} is tracked at its pinned-SHA URL but MISSING from every live local ref ({successfully-probed ref labels, e.g. `HEAD`, `issue-841`}) — the immutable pinned URL still renders, so this tracking loss is otherwise silent (incident #841); restore with `git restore --source=<pinned-sha> -- <path>` and commit on the intended live branch`
  (remediation uses `git restore --source=` because the working-tree copy may itself be gone; `git add` alone presumes it survives — #841 merely got lucky with byte-identical local copies.)
- **Three-state classification logic (v3, replaces the v1/v2 either-ref union):** per-path issue number `N` from `figures/issue_<N>/` (NOT from `--issue`, so the check stays body-only and cross-issue figure links are checked against *their own* branch family). Refs probed = `HEAD` of the main-pinned repo root ∪ the local branch family `refs/heads/issue-<N>` + `refs/heads/issue-<N>-*` (one `for-each-ref` per issue dir). States: (a) **at HEAD** → tracked, clean PASS; (b) **branch-only** — absent from HEAD but on ≥1 family ref → PASS with an explicit disclosure note (this is the EXPECTED state of every pre-merge verification round, where figures live on the issue/suffix branch and HEAD≡main does not yet carry them — so it must not WARN, or every figure-adding round pays a spurious-acknowledgment tax; post-merge the same note is the honest "not on main, but recoverable from a live ref" signal with the recovery command inlined); (c) **missing everywhere probed** → the incident-class WARN, emitted ONLY when every probe for that issue succeeded (a failed probe demotes the whole issue-dir to a skip note — a narrowed union must never manufacture a WARN). Per-ref labels name ONLY successfully-probed refs; the PASS text says "tracked at HEAD", never asserting refs that weren't (or failed to be) probed.
- **Why not WARN on branch-only (on the record, per the alternatives-lens reconciliation):** an unconditional missing-from-HEAD WARN fires on every legitimate pre-merge round (verifier runs from the main-pinned root BEFORE the Step-9b merge), recreating the WARN-spam class this design must avoid; conversely a silent PASS would let a stale branch mask main-loss (542 retained `issue-<N>` branches make that the default post-completion state). The disclosure note is the reconciled middle: non-spamming, but the masked-main-loss state is never invisible, and the §1 Goal claims only what the WARN class actually certifies.
- **Batching:** per unique issue dir — 1 `for-each-ref` + 1 `ls-tree` for HEAD + 1 `ls-tree` per family branch (typically 0–2) ≈ 3–5 subprocesses total for the typical single-issue body, independent of URL count. No per-URL subprocess. Nothing touches the network (no HTTP leg at all — unlike 4b there is no fallback: an undecidable git state is a skip note, period).
- **Failure-mode posture:** every git error path returns `passed=True, is_warn=False` with a per-issue `skipped — ...` note (other issue dirs still evaluated). The check can never return `passed=False` by construction (no code path constructs one), and never emits a WARN derived from a partially-failed probe set.
- **Registration:** append to `CHECKS` (line 7552, after `check_figure_label_codes`):
  `check_figure_tracked_at_head,  # check 29 (WARN) — body-linked figures tracked at live refs (#964, incident #841)`

## 5. Kill criteria

- The §4.4 batch run fires the incident-class WARN on a material fraction (>~10%) of grandfathered completed bodies for a *systematic* reason the family-∪-HEAD ref set does not cover → the ref-resolution design is wrong; withdraw and re-plan (candidate fixes: remote-tracking refs, tag scan).
- The BRANCH-ONLY disclosure turns out to fire on a large majority of completed bodies (i.e. most merged tasks' figures are NOT on `main` but survive only on stale branches) — that would mean the disclosure is the de-facto common case and the messaging/severity split needs a rethink; report the §4.4 disclosure count and re-plan the split if it exceeds ~50% of figure-bearing bodies.
- The check measurably slows the verifier (>2 s added on a typical body) — should be impossible at ≤5 subprocesses with 10 s timeouts, but if `ls-tree`/`for-each-ref` over a huge ref set surprises, withdraw the directory-listing batching for explicit-pathspec batching.
- A downstream consumer turns out to hard-code the current `CHECKS` length / final index (grep `len(CHECKS)` first; none known) → adjust rather than break.

## 10. §11 Decision Rationale

- **WARN, never FAIL.**
  What: the check always returns `passed=True`; drift is surfaced via `is_warn=True`.
  Why: a pinned URL still renders (the body is not broken — this is hygiene, not correctness), and grandfathered completed bodies must not start failing promotion gates retroactively.
  Source: task #964 body (explicit constraint) + incident #841.
  Alternatives: FAIL (rejected — regresses grandfathered bodies; banned by the task); WARN-with-escalation-after-date (rejected — needless statefulness).
- **Three-state classification over {HEAD} ∪ the local branch family `refs/heads/issue-<N>` + `refs/heads/issue-<N>-*`, per-path `N` (v3 — replaces the v1/v2 either-ref union).**
  What: per figure path — at HEAD → PASS; absent from HEAD but on ≥1 family ref → PASS with an explicit BRANCH-ONLY disclosure note; absent from every successfully-probed ref → the incident-class WARN. `N` comes from the `figures/issue_<N>/` path itself.
  Why: (a) production verifier HEAD ≡ `main` always (A7 corrected — `repo_root()` main-pins), and same-issue follow-up rounds commit figures on `issue-<N>-<suffix>` branches BEFORE the Step-9b merge, so any design that WARNs on missing-from-HEAD alone WARN-spams every figure-adding round — hence family membership → no WARN; (b) 542 retained local `issue-<N>` branches make stale-branch-retains-while-main-lost the DEFAULT post-completion state, so any design where branch presence silently PASSes lets the check certify nothing about `main` — hence the disclosure note makes branch-only visible without spamming, and the §1 Goal claims only what the WARN class certifies. This is the Phase-2 reconciled remedy (alternatives-lens reconciler: remedy (i) per-ref classes + (ii) narrowed claim), jointly satisfying the Claude-methodology Must-Fix (widen to `issue-<N>-*`) and the Codex-methodology/alternatives Must-Fix (report HEAD loss — never let a stale branch mask it silently).
  Source: Phase-2 critic ensemble (methodology agreed-REVISE Claude+Codex; alternatives reconciled-REVISE) + task_workflow.py:539-556 (main-pin) + `git for-each-ref` count of retained issue branches (542) + the #841 incident record (missing from all refs at incident time → still the WARN class).
  Alternatives: sketch-literal "branch else HEAD" (rejected — WARN-spams merged tasks with stale branches); v1/v2 either-ref silent union (rejected — reconciler-verified false-PASS class: stale branch masks main loss, codified in the old test 2); unconditional missing-from-HEAD WARN (rejected — pre-merge WARN-spam, incompatible with §4.4's zero-spurious-WARN threshold); remote-tracking refs in the family (rejected for v1 of this check — figures are committed VM-side, the stale-local-main transient self-heals; on the record in §8 must-ask).
- **Batching via one `for-each-ref` per issue dir + one `ls-tree -r --name-only <ref> -- figures/issue_<N>/` per (issue, ref) + set membership.**
  What: directory-prefix listing, not per-path `git cat-file`; the branch family resolved in a single `for-each-ref`.
  Why: dozens of figure URLs per body must not cause a subprocess storm (task brief requirement); a directory listing is one call and sidesteps pathspec quirks; output is small (hundreds of lines max). Budget ≈ 3–5 subprocesses for the typical body.
  Source: task #964 brief; `_git_object_exists` per-URL pattern as the counter-example to avoid at this fan-out.
  Alternatives: batched explicit pathspecs in one `ls-tree` call (equivalent cost; allowed deviation); per-path `cat-file -e HEAD:<path>` (rejected — N subprocesses).
- **Fail-soft to NO-OP PASS on any git error.**
  What: subprocess error / non-zero rc / unresolved repo root → `passed=True, is_warn=False`, `skipped — ...` note.
  Why: the verifier gates promotion for every clean-result; an environmental git hiccup must never block or add noise. Matches the established `'skip'` semantics of `_git_object_exists` / `_figure_url_existence`.
  Source: task brief ("degrade to a NO-OP PASS with a note"); precedent at lines 4138–4158.
  Alternatives: skip-as-WARN (rejected — noisy on stdin/outside-repo runs).
