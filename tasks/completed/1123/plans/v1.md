## 4. Design

### 4.1 Method delta (what differs from the existing gotchas entries)

Every existing vLLM entry diagnoses or recovers a failure whose symptom points AT its cause (orphans hold HBM → reap orphans; hang → triage the hang). The new entry documents a **mask inversion**: the loud, uniform, all-units symptom (N identical handshake-timeout tracebacks) is NOT the cause — it is downstream noise generated by the driver's raise-on-first-failure behavior abandoning siblings mid-engine-init. The diagnostic therefore inverts the usual read order: instead of reading the loudest/latest error, sort per-unit logs by first-error timestamp (or file size) and read the EARLIEST/SMALLEST one. No existing entry (and no rule anywhere in the workflow surface — grep confirmed) encodes "the symptom you see N times is masking the one you haven't read."

Second delta: the entry names WHY no downstream automation can rescue a mis-read — an explicit `failure_class:` field wins classifier precedence, and the regex fallback's `Traceback.*vllm/` / `Failed to initialize.*vllm` patterns also read the symptom as infra — so the DIAGNOSING AGENT is the load-bearing gate. That is what justifies placing the rule at the diagnosis surfaces (gotchas + failure_patterns) rather than in code.
