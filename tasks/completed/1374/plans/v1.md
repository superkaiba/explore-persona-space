## 4. Design

**File 1: `src/explore_persona_space/backends/gcp.py`** (two hunks + one docstring line).

Hunk A — new constant immediately after `DEFAULT_IMAGE_PROJECT` (line ~259):

```python
#: Minimum boot-disk size accepted by a create against the pinned DLVM
#: image — GCP rejects any smaller disk ("Requested disk size cannot be
#: smaller than the image size (100 GB)"; incident #1336: --boot-disk-gb 60
#: failed the rung and exhausted the auto chain). render_create_argv clamps
#: UP to this floor (never down — a plan footprint is a minimum requirement,
#: so a bigger disk always satisfies it), mirroring the RunPod floors
#: (runpod.py _CPU_CONTAINER_DISK_FLOOR_GB / _GPU_VOLUME_FLOOR_GB). This is
#: a property of the IMAGE, not the config — if DEFAULT_IMAGE_FAMILY is ever
#: re-pinned, re-verify: gcloud compute images describe-from-family
#:   --family=<family> --project=<project> --configuration=eps-gcp
#:   --format='value(diskSizeGb)'
_GCP_IMAGE_MIN_BOOT_DISK_GB = 100
```

Hunk B — the clamp at line 2850 (inside `render_create_argv`; the module `logger` is defined at line 146):

```python
-    boot_disk_gb = int(spec.extra.get("boot_disk_gb") or config.default_boot_disk_gb)
+    requested_boot_disk_gb = int(spec.extra.get("boot_disk_gb") or config.default_boot_disk_gb)
+    boot_disk_gb = max(_GCP_IMAGE_MIN_BOOT_DISK_GB, requested_boot_disk_gb)

+            "(GCP rejects disks smaller than the image, #1336); provisioning %d GB.",

+        )
```

def test_render_create_argv_boot_disk_clamped_to_image_minimum(
    caplog: pytest.LogCaptureFixture,
) -> None:
    """#1374: a plan-stated boot disk below the DLVM image size (100 GB) is
    clamped UP so the create cannot fail GCP's image-size validation
    (incident #1336: --boot-disk-gb 60 failed the rung; chain exhausted)."""
    cfg = _test_config()
    with caplog.at_level(logging.WARNING, logger="explore_persona_space.backends.gcp"):
        argv = render_create_argv(
            spec=_spec("cpu-mid", extra={"boot_disk_gb": 60}),
            config=cfg,
            attempt_id="att-fixed-001",
            startup_script="#!/bin/bash\n",
            secret_files=_TEST_SECRET_FILES,
        )
    assert "--boot-disk-size=100GB" in argv
    assert "--boot-disk-size=60GB" not in argv
    clamp_lines = [r for r in caplog.records if "clamped" in r.getMessage()]
    assert len(clamp_lines) == 1, clamp_lines
    assert "60" in clamp_lines[0].getMessage() and "100" in clamp_lines[0].getMessage()


def test_render_create_argv_boot_disk_default_path_emits_no_clamp_warning(
    caplog: pytest.LogCaptureFixture,

## 11. Decision Rationale

1. **Floor as module constant `_GCP_IMAGE_MIN_BOOT_DISK_GB = 100`, not a `GcpConfig` field.**
   - What: private module-level constant placed with the DLVM image constants (after `DEFAULT_IMAGE_PROJECT`, ~L259).
   - Why: the floor is a property of the pinned image (`DEFAULT_IMAGE_FAMILY`/`DEFAULT_IMAGE_PROJECT`, gcp.py:256-259), not per-deployment policy — a config field would imply it can vary independently of the image, which is incoherent; co-locating with the image constants keeps the re-verify obligation visible at the pin site.
   - Source: RunPod precedent `runpod.py:94` `_CPU_CONTAINER_DISK_FLOOR_GB` (module constant, same only-grow contract); value 100 from the #1336 GCP error message verbatim.
   - Alternatives: `GcpConfig.image_min_boot_disk_gb` (rejected — adds config surface for an image-intrinsic fact); live `gcloud images describe-from-family` at render time (rejected — `render_create_argv` is documented pure/no-network).
2. **Single clamp site = `render_create_argv`; all other `boot_disk_gb` sites untouched.**
   - What: clamp the local variable only; never mutate `spec.extra`.
   - Why: gcp.py:2850→2878 is the only GCP-create threading site (grep enumerated in §2); the payload/forwarding/feasibility sites must keep the PLAN-stated footprint (a RunPod failover should thread 60, where RunPod's own 50 GB floor applies).
   - Source: `grep -n 'boot_disk_gb\|--boot-disk-size' src/explore_persona_space/backends/ scripts/` (this plan, 2026-07-16; hits classified in §2), consistent with the body's verified-at-filing grep (6 hits in gcp.py).
3. **`logger.warning`, fired only when the clamp raises.**
   - What: module `logger` (gcp.py:146), one %-lazy line naming requested GB, floor, provisioned GB; guarded by `boot_disk_gb != requested_boot_disk_gb` so the default 300 GB path logs nothing.
   - Why: a plan-stated footprint being overridden is a plan-sizing signal that belongs in the launch record (the body's constraint asks for exactly this); WARNING over INFO because the plan's own sizing was wrong, if benignly.
   - Source: task #1374 body Constraints ("Log one INFO/warning line when the clamp raises a plan-stated value"); logger convention read from gcp.py:115/146.
4. **Test placement + names.**
   - What: two tests after `test_render_create_argv_cpu_bigmem_boot_disk_override` (L540-550), named `test_render_create_argv_boot_disk_clamped_to_image_minimum` and `test_render_create_argv_boot_disk_default_path_emits_no_clamp_warning`, using `_spec`/`_test_config`/`_TEST_SECRET_FILES` verbatim from the neighbors.
   - Why: sibling proximity to the existing boot-disk pins; `cpu-mid` in the clamp test reproduces the #1336 incident shape.
   - Source: read from `tests/test_gcp_backend.py:145-170, 509-560` (this plan).
