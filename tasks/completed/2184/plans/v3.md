# Plan — task #2184: CPU-intent RunPod provisioning — type the no-port wedge, rotate DC on wedge, and document the residual route for a fully dry/wedged CPU lane

## 0.0 TL;DR (plain English)

- **What I'll run:** No experiment — this is a code fix. Today, when a RunPod CPU box comes up "running" but never opens its network door (a known RunPod glitch), our provisioning code notices only as a generic error. I'll make it raise a specifically named error, automatically retry in a *different* datacenter (the glitch is datacenter-specific) — but only after CONFIRMING the stuck box was actually torn down, so we never stack a second billing box on top of a first one that's still alive — and, when every datacenter is out of CPU capacity (or the teardown can't be confirmed), refuse with a clear message naming the approved plan B (rent the smallest GPU box instead, which we measured runs CPU work ~6x faster than our crowded shared VM anyway). Plus tests and rule-book updates so the next session doesn't rediscover all this.
- **What I expect:** All new and existing tests pass; a simulated stuck pod produces the typed error and a different-datacenter retry; a simulated failed teardown, a simulated everything-dry sweep, and a "keep the stuck box for debugging" flag each produce a clear refusal (or clean propagation) with exactly one box ever created. No behavior change for normal provisioning, and no weakening of any existing safety refusal.
- **What would change my mind:** If RunPod's CPU-create API turns out to ignore the datacenter pin (making rotation pointless), I keep the typed error + refusal-with-plan-B and drop the rotation leg. If any existing caller depends on the exact old error type, I stop and re-scope before touching it.

```python
class RunPodNoPortWedgeError(RunPodError):
    """Raised by :func:`wait_for_ssh` when the pod reached
    ``desired_status=RUNNING`` but exposed no public 22/tcp mapping within the
    bring-up window — the documented RunPod no-port host wedge
    (#664/#770/#1667; provision-time incident #2162 -> #2184).

    Carries the last-observed :class:`PodInfo` (``info``) so callers can read
    ``pod_id`` / ``data_center_id`` for bias-away DC rotation, and a
    ``teardown_disposition`` slot (``"terminated" | "kept" | "failed" | None``)
    the provision tail fills in AFTER running the #2060 auto-teardown — the
    #2184 rotation interlock reads it and re-creates ONLY on ``"terminated"``.
    Subclass of :class:`RunPodError` so every existing ``except RunPodError``
    caller (the provision tail, the resume path) keeps catching it.
    Deliberately NOT a :class:`RunPodNoCapacityError` subclass: the
    wait-for-capacity retry loop must never blind-retry a wedge (same-DC retry
    is the #2162 failure mode).
    """

    def __init__(self, message: str, info: "PodInfo | None" = None) -> None:
        super().__init__(message)
        self.info = info
        self.teardown_disposition: str | None = None  # set by the provision tail (#2184)


class RunPodCpuLaneDryError(RunPodError):
    """CPU-intent residual refusal (#2184): a no-port wedge was detected and
    rotation is exhausted or interlocked-out (every candidate DC dry/wedged,
    DC enumeration failed, teardown unconfirmed, explicit user pin wedged, or
    wedged DC unidentifiable). The `cpu_fallback_infeasible_for_plan`-family
    typed refusal for a fully dry/wedged CPU lane; the CLI maps it to
    EXIT_CPU_LANE_DRY (77) with the machine-greppable
    ``CPU-LANE-DRY reason=<reason>`` verdict naming the sanctioned GPU-lane
    residual. NOT a RunPodNoCapacityError subclass (must not be wait-retried).
    """
```

**(b) `wait_for_ssh` edit (behavior-preserving except the raise type on the RUNNING shape):**

```python
def wait_for_ssh(pod_id: str, timeout: int = 600, poll_interval: int = 10) -> PodInfo:
    deadline = time.time() + timeout
    info: PodInfo | None = None
    while time.time() < deadline:
        info = get_pod(pod_id)
        if info.ssh_host and info.ssh_port:
            return info
        time.sleep(poll_interval)
    last_status = info.desired_status if info is not None else "unknown"
    msg = (f"Pod {pod_id} did not expose public 22/tcp within {timeout}s. "
           f"Last desiredStatus: {last_status}")
    if info is not None and (info.desired_status or "").upper() == "RUNNING":
        raise RunPodNoPortWedgeError(msg + " (RUNNING-but-no-port wedge, #2184)", info=info)
    raise RunPodError(msg)
```

```python
        print(f"  Created CPU pod {info.pod_id} — waiting for SSH (up to 10 min)...")
        _provision_wait_register_bootstrap(args, name, info, intent_label)
        return
    except WaitForCapacityStillWaiting as exc:
        _emit_still_waiting_and_exit(exc)                       # unchanged
    except RunPodNoPortWedgeError as exc:
        # ---- teardown interlock (#2184 MF-A): no re-create without CONFIRMED termination ----
        if keep_flag:
            print("[cpu-dc-rotation] --keep-on-bootstrap-failure set: rotation DISABLED "
                  "(each wedged attempt would strand a kept, BILLING pod); propagating the "
                  "typed wedge — today's single-attempt shape (#2184)", file=sys.stderr)
            raise                                               # R5: keep-flag shape UNCHANGED (typed)
        if getattr(exc, "teardown_disposition", None) != "terminated":
            _cpu_lane_dry_refusal(..., reason="teardown-unconfirmed", lingering=exc.info)
        if user_pinned:
            _cpu_lane_dry_refusal(..., reason="user-pin-wedged")   # explicit pin = instruction; §11
        wedged = (exc.info.data_center_id if exc.info else None) or dc_pin
        if wedged is None:
            _cpu_lane_dry_refusal(..., reason="wedged-dc-unknown")  # never a same-DC re-pick
        wedged_dcs.append(wedged)
        if len(wedged_dcs) >= 1 + _rotation_wedge_budget():        # total wedge-bearing creates consumed
            _cpu_lane_dry_refusal(..., reason="wedge-budget-exhausted")
        if candidates is None:
            candidates = _rotation_dc_candidates()              # get_datacenters() best-effort; None on failure
        if candidates is None:
            _cpu_lane_dry_refusal(..., reason="dc-enumeration-failed")  # refuse loudly, no rotation
        dc_pin = _next_rotation_dc(candidates, exclude=set(wedged_dcs) | set(dry_dcs))
        if dc_pin is None:
            _cpu_lane_dry_refusal(..., reason="candidates-exhausted")
        rotation_active = True
        print(f"[cpu-dc-rotation] no-port wedge in {wedged} (teardown CONFIRMED); retrying "
              f"pinned to {dc_pin} ({len(wedged_dcs)} of {1 + _rotation_wedge_budget()} "
              f"wedge-bearing attempts used) (#2184)")
    except RunPodNoCapacityError:
        if not rotation_active:
            raise                                               # R5: first-attempt fail-loud UNCHANGED
        dry_dcs.append(dc_pin)
        if len(dry_dcs) >= _rotation_dc_cap():
            _cpu_lane_dry_refusal(..., reason="dc-cap-exhausted")
        dc_pin = _next_rotation_dc(candidates, exclude=set(wedged_dcs) | set(dry_dcs))
        if dc_pin is None:
            _cpu_lane_dry_refusal(..., reason="candidates-exhausted")
        print(f"[cpu-dc-rotation] {dry_dcs[-1]} dry (no capacity); trying {dc_pin} (#2184)")
```

Interlock ordering (deliberate): keep-flag first (rotation categorically disabled — the disposition would read `"kept"` anyway, but the check must not depend on it), then teardown disposition (a possibly-billing pod is the most urgent refusal), then user pin, then wedged-DC identifiability, then budget. The budget guard fires post-append with `>=` — at the default budget 2, wedges 1 and 2 rotate and wedge 3 refuses: exactly 1 + budget = 3 wedge-bearing creates, matching §0/§5 row 5/§11's "3 total, ~35 min" (the v2 `> 1 + budget` form would have permitted a 4th create).
