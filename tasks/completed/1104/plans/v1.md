**(1b)** `decide_prompt_wedge(trailing_rows, min_dequeued, *, min_api_errors: int = 3)` (`:1712-1732`): keep the existing run semantics VERBATIM and add a second trailing counter. An `"api-error"` row resets `run` (the prompt DID get a response — this is not the #779 swallow shape) but increments `api_run`; a real `"assistant"` row resets both; `"other"` skips both.

```python
    run = 0
    api_run = 0
    for row in trailing_rows:
        cls = _classify_wedge_row(row)
        if cls == "assistant":
            run = 0
            api_run = 0
        elif cls == "api-error":
            run = 0
            api_run += 1
        elif cls in ("dequeue", "prompt"):
            run += 1
    return run >= min_dequeued or (min_api_errors > 0 and api_run >= min_api_errors)
```

Calibration: `min_api_errors=3` is the direct analogue of `min_dequeued=3` — 3 CONSECUTIVE failed wake turns with zero successful turns. A single/double transient error (the ladder's step-(b) retry-once class) never fires; any real turn resets. The `run`-reset on api-error is deliberate: without it, one refused wake's dequeue+prompt rows (2-4 rows in the #1074 tail) would trip the EXISTING `run >= 3` threshold after a single refused turn — over-aggressive for the 18+/day one-off-refusal regime.

**(1c)** New env helper `_tick_wedge_min_api_errors()` next to `:1229`, mirroring `_tick_wedge_min_dequeued` with ONE deliberate divergence: `0` DISABLES the api-error trigger (kill switch; `min_api_errors > 0` guard above), malformed/negative → default. ## 11. Decision Rationale

- **api-error rows reset `run` but get their own counter** — What: two-counter design. Why: prevents single-refused-wake over-trigger (a #1074 wake contributes 2 dequeues + 2 prompt rows; without the reset, `run >= 3` fires after ONE failed turn, wrong for the one-off-refusal regime — 18+ one-offs on 2026-06-09 per CLAUDE.md). Source: `autonomous_session_watch.py:1712-1732` semantics + transcript 6f682c18 tail shapes (§2).
- **Threshold 3 / env `EPM_TICK_WEDGE_MIN_API_ERRORS` / 0-disables** — What: mirror of `EPM_TICK_WEDGE_MIN_DEQUEUED` (`:1229-1243`) with an explicit kill switch. Why: same calibration philosophy ("3 consecutive pieces of direct evidence"); a NEW trigger class warrants a disable path the original (load-bearing since #845) does not have. Source: `:1229-1243`; `background-automation.md` § (e).
- **Detection via `isApiErrorMessage`, not refusal-text matching** — What: structural key, no content read. Why: content matching would page refusal text into the watcher and is brittle; the key is present on all 38 live rows and covers 429/529 error turns too (a session dead on ANY 3 consecutive erroring wakes is respawn-worthy; fleet-wide storms are bounded by the auth-outage guard). Source: transcript probe §2; `background-automation.md` § auth-outage guard.
- **GATE-TRANSITION refusal skip rather than unconditional thinning** — What: conditional posture. Why: the slug/reason digest is deliberately bounded and useful on healthy ticks (`SKILL.md:259-260` "the ONLY marker-note text a tick turn ever pages in"); only the poisoned-context case needs the numeric fallback. Source: `SKILL.md:239-263` + `:212-229`.
- **Ladder step documents respawn as THE recovery** — What: no in-session recovery step invented. Why: a refused turn produces no actions by definition, so any in-session step is unexecutable; the watcher respawn (now mechanical via edit 1) + the manual stop/respawn are the only real paths — matching what actually recovered #1074. Source: incident #1074 (session a2343e65); `SKILL.md:227-229`.
