### 4a. New constants (near `_FOLLOWUP_ROUND_END_STEPS`, ~line 5130)

```python
# Event kinds that can ONLY be posted by an EXECUTING pipeline round — the
# parent pass's post-9b tail (interp/clean-result critiques, methodology
# export, status changes, step-completed parks, merged) can postdate the
# scope, but planning/implementation/launch markers cannot: those steps are
# long over for the parent by the time the 9b scope posts. Their presence
# NEWER than the scope proves the round actually STARTED.
_FOLLOWUP_ROUND_WITNESS_KINDS = frozenset({
    "epm:plan", "epm:plan-approved", "epm:plan-verify", "epm:consistency",
    "epm:smoke-architecture-check", "epm:proposed-tests",
    "epm:experiment-implementation", "epm:code-review",
    "epm:code-review-codex", "epm:review-reconcile",
    "epm:run-launched", "epm:launch",
})
# The same-issue loop's dispatch breadcrumb (SKILL.md § Dispatch breadcrumb):
# note BEGINS with this prefix. The `followup-` restriction excludes
# parent-tail breadcrumbs (methodology spawn, Step 8/9 stages).
_FOLLOWUP_STAGE_DISPATCH_WITNESS_PREFIX = "stage-dispatch stage=followup-"
```

### 4b. Predicate change (`_followup_round_complete_reason`)

Keep the existing early returns verbatim (no scope → `None`; recorded round → `None`; no/mismatched step-completed → `None`). After the existing step/exit_kind/`sc_ts > scope_ts` match, add two gates (single extra pass over `events`):

```
# Gate 1 — round-start witness: the round must have demonstrably started.
witness = any(
    ts(ev) is not None and ts(ev) > scope_ts and (
        ev.kind in _FOLLOWUP_ROUND_WITNESS_KINDS
        or (ev.kind == "epm:progress"
            and (ev.note or "").startswith(_FOLLOWUP_STAGE_DISPATCH_WITNESS_PREFIX))
    ) for ev in events)
if not witness:
    print(diagnostic: "round-end park matched but no round-start witness after
           the scope — the park is the parent pass's tail or the round never
           started; deferring to crash-recovery/stalled handling")
    return None

# Gate 2 — freshness: the keyed park must be the LATEST non-watcher signal.
# ANY non-watcher event strictly newer than sc_ts proves the park is stale
# or mis-attributed (round still executing, or advanced past it).
newer = any(
    ts(ev) is not None and ts(ev) > sc_ts
    and not any(s in (ev.note or "") for s in _WATCHER_NOTE_SENTINELS)
    for ev in events)
if newer:
    print(diagnostic: "round activity newer than the keyed round-end park —
           round still executing (or died mid-flight: crash-recovery's job,
           never the repark's); skipping")
    return None
return reason  # unchanged wording
```

An optional keyword-only `issue: int | None = None` parameter may be added purely for the diagnostic lines (both call sites pass it); default `None` keeps every existing test call working.

**Design rationale for "ANY non-watcher kind blocks" (no activity-kind allowlist):** no ignore-list is needed because the system **converges through the respawn path**: if a stray cross-post (a workflow-fix child completing hours after a genuine round end posts `epm:workflow-fix-applied` on the parent) blocks the repark, the stalled/orphan pass falls back to respawn; the respawned session re-derives state and posts a fresh `step ∈ {9a-bis,10}` parked step-completed, which `_latest_step_completed` picks as the NEW newest park — nothing is newer than it, the witness still exists, and the repark fires on the next tick. Cost of a false block: one respawn cycle. Cost of a false fire (the current bug): an orphaned live round and a corrupted lifecycle. The asymmetry decides it. Comments/`epm:clarify` are non-issues (comments live in `comments.jsonl`, not events; clarify never posts at `followups_running`). Watcher-sentinel-noted markers (stalled alerts, awaiting-child alerts — which routinely post after a genuine round-end park) are excluded via the existing `_WATCHER_NOTE_SENTINELS` note filter, same as `_latest_step_completed`.

**Why gate 1 is needed at all (the residual race):** the freshness check alone would not have blocked a tick landing in #778's 21:49:35Z→21:50:27Z window (mis-attributed parent park is the newest event, no round marker yet). Worse, if the session dies inside that window, staleness accrues and ~2h later the repark would fire on a round that NEVER ran — posting a run marker that falsely closes the scope and loses the round. The witness gate closes both deterministically, with no wall clock. In the true-positive #533 shape the round ran, so witnesses (plan markers, stage-dispatch breadcrumbs, implementation/review markers) necessarily exist between scope and park. Note that under gate 2, any witness newer than the scope is automatically also ≤ `sc_ts`, so the simple `> scope_ts` form is exact.

**Rejected alternatives:**
- *"No live round process (pid)" check (task body's idea):* REJECTED. The round's compute may live on a pod (#778's null battery ran pod-side and later VM-side under a different session); no pid on this VM is attributable to the round from the watcher, and a pid probe would break the predicate's purity contract (events-only, no subprocess/file reads) and its testability. Marker freshness IS the project's observable liveness contract (the staleness clocks already run on it).
- *Minimum-quiet-period:* REJECTED. Requires wall clock (breaks determinism/purity), only narrows — never closes — the race window, and does nothing for the round-never-started sub-case. The witness gate dominates it.
- *Keying on the loop-entry `epm:status-changed`:* REJECTED. Status-changed notes are free text (no structured new-status field), and a chained round 2+ inside one `followups_running` hold posts no fresh loop-entry transition — false blocks.

**Why code, not a model call?** N/A in the usual sense (this IS workflow code), but for completeness: the predicate is a deterministic lifecycle guard evaluated every 10 minutes by a cron; an LLM call would add latency, cost, and non-determinism to a safety-critical pass. Code is the only correct choice; nothing would flip this.

### 4c. Secondary fix: `_scope_note_field` bold-markdown tolerance (~line 5389)

```python
core = stripped.lstrip("*").lstrip()          # tolerate "**field:** value"
if core.startswith(f"{field}:"):
    value = core[len(field) + 1 :].lstrip("*").strip().rstrip(",")
    return value or None
```

This is the verified cause of the second #778 firing (the 04:43 repark's disarm marker never posted: "no followup_label parseable") and, independently, of a live hazard on every TRUE positive with a modern scope note — an unrun scope re-routes the next `/issue` invocation into re-running a completed round. Same pass, same incident, ~3 lines + tests: in scope. Side effect: a bulleted `* followup_label: x` line now also parses — harmless and arguably desired.
