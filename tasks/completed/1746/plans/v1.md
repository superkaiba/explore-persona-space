# Plan v1 — task #1746: Step 9c gate degrade on collection ImportError

architectural: false

## Goal / Requirement

One collection-broken test file on origin/main must not abort the entire Step 9c
gate run. A KNOWN main-side collection-red file must classify as pre-existing and
strip (compare exit 0); a branch-INTRODUCED collection-red file must classify as
NEW and block (compare exit 1); genuinely aborted runs (interrupt / internal
error / timeout) must still refuse to classify (MF-1b preserved, compare exit 2).
Incident: 3 sessions on 2026-07-27 (60cd2d8b #1720, 206fe014 #1728, 116cfd96
#1731) each paid ~38-45 min hand-diagnosing + deselecting + re-running the full
gate after `tests/test_workflow_lint_inline_round_duty_mirror.py` (the #1698
lost-update ImportError) aborted collection with pytest rc=2.

## Method delta (vs current behavior)

Option (a) from the task body, chosen over option (b): add
`--continue-on-collection-errors` to every gate-family pytest invocation and
teach the junit parse to absorb collect-error rows as per-file failure nodes.
Option (b) (selector auto-deselects ledger-marked collection-red files) is
structurally insufficient alone: `cmd_refresh` refuses ledger writes on
rc∉{0,1} (step9c_baseline.py L1122), so a collection-red main means NO ledger
row can ever exist for the broken file without the flag in refresh anyway —
verified at clarify time (epm:clarify v1). With the flag, pytest runs the
surviving collected tests, reports collect errors as junit `<error>` testcases,
and exits rc=1 (testsfailed>0) — inside compare's accepted {0,1} set — so the
existing NEW-vs-pre-existing node subtraction handles classification with no
new machinery. MF-1b semantics survive automatically: rc=2 now only occurs for
genuine interruption/internal error, which keeps refusing.

## File paths + concrete changes

1. `scripts/step9c_baseline.py`
   - `PYTEST_BASE_FLAGS` (L225-232): append `--continue-on-collection-errors`.
     Covers BOTH `cmd_refresh` (L1084) and the pristine single-file oracle runs
     (L1242) — both route through `run_pytest` (L508) with these flags.
   - `parse_junit` (L905): a failing testcase with NO `file` attribute is
     currently a hard `JunitParseError`. New behavior: when the testcase has an
     `<error>` child, no `file` attr, and its `name` attribute is a plausible
     test-file path (endswith `.py`), derive `file` from `name` (normalized
     rootdir-relative) and emit `Node(file=<derived>, classname="", name=<name>)`.
     Keep the hard JunitParseError for every other missing-file shape (the
     xunit1 contract violation stays fail-loud). Node identity is derived by
     the SAME function on ledger + gate + pristine junits, so subtraction
     strips pre-existing collect-error rows with zero schema change.
   - Pristine-oracle zero-collected guard (L1259): a pristine run of a
     collection-red file collects 0 tests but emits 1 collect-error testcase in
     the junit (summary counts testcase elements) — verify empirically in the
     smoke; if the summary reads tests=0 there, scope the zero-collected raise
     to runs with zero testcase elements INCLUDING errors.
2. `scripts/select_step9c_tests.py`
   - The printed gate command (L1866-1868): add `--continue-on-collection-errors`
     between the file list and `-v --tb=short` so every SKILL.md 1b gate run
     inherits it verbatim.
3. `.claude/skills/issue/SKILL.md` (Step 9c recipe)
   - 1c full-scope override pytest line: add the flag (it does not use the
     selector-printed command).
   - 1b: no command change (it runs the selector-printed command verbatim);

4. Tests (new file `tests/test_step9c_collection_errors.py` + minimal edits)
   - Unit: `parse_junit` on a synthetic xunit1 junit carrying a collect-error

   - Tiny-real e2e: temp dir with one passing test file + one ImportError-broken

## Success criteria

1. Tiny-real e2e: pytest with the flag on {1 broken, 1 passing} file exits rc=1,
   junit parses, broken file → 1 Node, passing test executed.
2. Compare classifies a ledger-known collect-error Node as pre-existing (exit 0)
   and a ledger-unknown one as NEW (exit 1).
3. `--pytest-rc 2` still yields compare exit 2 (MF-1b regression test passes).
4. Full mapped/selected test subset for the touched files passes; no-flags
   `workflow_lint.py` clean on touched files.

## Kill criteria

- If the empirical smoke shows pytest with `--continue-on-collection-errors`
  does NOT exit rc∈{0,1} on a collect-error run, or emits junit rows that
  cannot be keyed to a per-file Node identity stable across runs, option (a)
  is dead: stop, do not merge, re-plan toward a selector-side deselect design.
