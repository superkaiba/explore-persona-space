## 2. Method delta + candidate-narrowing design (load-bearing)

Check 31 verifies committed per-unit FIGURES are EMBEDDED; this check verifies
committed result JSONs are REPORTED. Check 31's noise control is a narrow stem
regex; JSONs have no such grammar, so narrowing is PLAN-ANCHORED + small-dir
sibling extension. Candidates =

- **C1 (plan-named):** committed JSONs whose basename (boundary-aware,
  case-folded) or repo-relative path appears in ANY of the task's plan
  versions (`plans/v*.md` — the latest plan is a follow-up amendment on
  multi-round tasks, so the union across versions is required; measured: the
  founding round's deliverables are named in v1-v4, not v7). Thread a
  `plans_dir` / reuse the existing `plan_path` plumbing (checks 20/26
  precedent) — implementer picks the seam; with no plan available the check
  degrades to C2-only or vacuous PASS (never a crash).
- **C2 (small-dir plan-named-sibling extension):** committed JSONs in a leaf
  dir with ≤K total JSONs (K default 8) of which ≥1 sibling is C1 — the
  deliverable-dir grain that catches the founding file. Dirs with >K JSONs
  are per-cell dump dirs: exempt at file grain by construction (measured:
  digit-normalized template families do not exist in this project — per-cell
  files vary by word tokens — so dir size IS the family signal).
- **Intermediate-artifact basename exemption (lever):** basenames matching an
  intermediate-dump pattern (e.g. `judge_raw_*`, `*_id_map_*`, `manifest*`,
  `*specs*`) may be excluded from C2 — implementer tunes this list against
  criterion 3's measurement (measured offenders: #1776's judge/ dumps, #1689's
  `crossmodel_pair_specs.json`).

Disposition per candidate: referenced (boundary-aware basename or path in
body) → PASS; exemption paragraph (§1.5) → PASS; else WARN. No class B, no
check-38 deferral (a JSON cannot be embedded). Reuses verbatim:
`_git_tracked_under`, `_paragraphs`, the exemption-phrase anchoring style, the
fail-soft/issue-scoping/dedup-across-SHAs structure. Cited-SHA source: union
of check-31 figure-URL SHAs + same-repo `/tree/<sha>/...eval_results/issue_<N>` +
`/blob/<sha>/eval_results/issue_<N>/...` links (SHA source only — never a
reference, §1.2).
