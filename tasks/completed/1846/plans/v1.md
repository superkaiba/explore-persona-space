# Plan v1 — task #1846: verify_task_body WARN check — orphaned result JSONs (sibling of check 31)

## 1. Requirement + acceptance criteria (kind: infra — workflow-fix)

**Requirement.** Add a WARN-level orphaned-result-JSON check to
`scripts/verify_task_body.py` — check **49** (`check_orphaned_result_jsons`), the
result-JSON sibling of check 31 (`check_orphaned_per_unit_figures`): a committed
`eval_results/issue_<N>/**/*.json` at a body-cited same-repo SHA that the body
references NOWHERE (no basename mention, no path mention, no dir-level exemption
disclosure) surfaces as a WARN naming the orphan, so a silently-unreported planned
read is caught mechanically instead of by the clean-result-critic's manual
planned-vs-actual lens.

**Acceptance criteria:**
1. Founding-incident regression: a synthesized #1776-shape fixture (committed
   `eval_results/issue_999/phase4/jdelta_split.json` at a body-cited SHA, basename
   absent from body) → exactly one WARN naming the orphan; `passed=True` (WARN
   never flips the verdict).
2. A dir-level cited `/tree/<sha>/eval_results/issue_<N>/` footer link does NOT
   count as referencing the JSONs inside (else the check is vacuous — every v4
   footer carries such a link; this is the load-bearing anti-vacuity decision).
3. Basename mention anywhere in body prose (case-folded) → referenced → PASS;
   full repo-relative path mention → PASS.
4. Dir-level exemption grammar: a blank-line-delimited paragraph containing the
   orphan's parent-dir path segment AND an anchored exemption phrase
   (`not reported` / `not embedded` / `superseded by`, case-insensitive) exempts
   every JSON under that dir (the check-31 paragraph-co-occurrence pattern,
   adapted: unnamed files cannot carry a per-file phrase, so the disclosure
   grain is the directory).
5. Fail-soft inventory mirrors check 31 verbatim: unreachable/unknown SHA →
   silently skipped (counted in PASS detail, never a WARN); repo unresolved →
   skip-PASS; zero cited same-repo SHAs → vacuous PASS; WARN-tier only, NEVER a
   new hard FAIL on any body generation (generation-agnostic, like check 31).
6. Issue scoping: with `--issue <N>` (or numeric-parent `--file`) only
   `eval_results/issue_<N>/` is scanned; `issue=None` (`--body-stdin`) falls back
   to every cited issue dir (documented caveat, same as check 31).
7. Noise bound: >8 orphans → list the first 8 + `(+K more under <dirs>)` in one
   CheckResult (a per-cell dump dir must not produce a 100-line WARN).
8. Doc block updated (check-49 entry after check 48, ~L1003); dispatch added
   beside check 31's issue-bearing site (~L14944, outside the body-only CHECKS
   list); pin tests added in `tests/test_verify_task_body.py` mirroring the
   check-31 test family (fixture-built tmp git repo + monkeypatched
   `_resolve_repo_root`).
9. `uv run ruff check` clean on touched files; existing verify_task_body tests
   stay green; `workflow_lint.py` no-flags run passes.

## 2. Method delta (what differs from check 31)

Check 31 verifies committed per-unit FIGURES are EMBEDDED; this check verifies
committed RESULT JSONs are REPORTED. Deltas:
- **Cited-SHA source widened:** union of (a) check-31's figure-URL SHAs
  (`_cited_issue_figure_dirs` — figures + eval JSONs land in the same commits),
  (b) same-repo GitHub `/tree/<sha>/eval_results/issue_<N>...` links, (c)
  `/blob/<sha>/eval_results/issue_<N>/...` links. New helper
  `_cited_eval_results_shas(body) -> dict[prefix, set[sha]]`.
- **No stem pattern:** ALL `*.json` under the issue's eval dir are candidates
  (there is no per-unit basename grammar for JSONs); the noise bound is the
  aggregation cap (criterion 7) + dir-level exemption (criterion 4), not a
  narrow filename regex.
- **No class B / no check-38 deferral:** for a JSON, being NAMED in the body IS
  the discipline (a JSON cannot be embedded), so dispositions are binary:
  referenced → PASS, never-mentioned → WARN (with dir-exemption escape).
- **Reuses verbatim:** `_git_tracked_under` (ls-tree, 10s timeout, None =
  unreachable), `_paragraphs`, the exemption-phrase anchoring style, the
  fail-soft/issue-scoping/dedup-across-SHAs structure, WARN=`is_warn=True`.
