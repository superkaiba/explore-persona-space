# Plan v1 — task #1989: repro-artifacts-clean gate (working-tree vs body-named result dirs)

## Plan Summary

Add one new WARN-only check to `scripts/verify_task_body.py` —
`check_repro_artifacts_clean` — that parses `eval_results/issue_<N>/...` (and
`ood_eval_results/...`) directory references out of the body's `**Repro:**`
footer (v4) / `## Reproducibility` H2 (v3/v2), probes each named directory
with `git status --porcelain -- <dir>` in the resolved repo root, and WARNs
naming every untracked or modified entry found. Closes the #1768 gap: 16
untracked + 4 modified `operator_kv` result files contradicted the parked
body's headline with zero mechanical signal (check 29 covers figures only;
check `check_repro_committed_claims_exist` reads the git TREE only, never
the working tree).

NOT architectural: adds one check to an existing verifier + tests; no public
contract, marker schema, or status enum change.

## Requirement + acceptance criteria (code change)

1. New check function `check_repro_artifacts_clean(body)` in
   `scripts/verify_task_body.py`, registered in the checks list adjacent to
   the other Repro checks, with a numbered module-docstring entry (next free
   check number — grep the max at implementation time; expected 47).
2. Generation-agnostic: reads the v4 `**Repro:**`/`**Context:**` footer OR
   the v3/v2 `## Reproducibility` H2 via the existing `_repro_section_text`
   helper; fenced code blocks stripped via `_strip_fenced_blocks` before the
   scan (illustrative paths never fire).
3. Path extraction: regex over the fence-stripped section for
   `(ood_)?eval_results/issue_?\d+` -rooted path tokens (backticked or
   bare). Each token reduces to a DIRECTORY prefix: truncate at the first
   glob/brace char (`*`, `{`), then drop a trailing component that carries a
   file extension; dedupe (a parent dir subsumes its children). No paths
   found → vacuous PASS ("no repro-named eval_results dirs to check").
4. Probe: `git -C <repo> status --porcelain -- <dir>` per deduped dir, repo
   = `_resolve_repo_root()` (check 29's resolver; unresolved → skipped
   PASS). Classify porcelain lines: `??` = untracked; any other non-clean XY
   = modified-class. Default porcelain EXCLUDES gitignored files — this IS
   the npz-convention tolerance required by the task body (no `--ignored`).
5. Severity: **WARN, never FAIL** (`passed=True, is_warn=True`), the check
   29 class. Decision rationale (the body delegated severity to the
   planner):
   - A status-keyed FAIL (`awaiting_promotion`) is unreliable and unsafe:
     the verifier's gate-time invocations run `--file` on staged candidates
     (no status available), and the user-chat inline free-analysis carve-out
     RUNS at parked statuses by design — mid-round the tree is legitimately
     dirty under `eval_results/issue_<N>/` until the same-turn commit, so a
     FAIL would block a healthy body against sanctioned concurrent work.
   - Forward-only doctrine: a new FAIL class would newly hard-FAIL
     grandfathered parked bodies (banned for v3/v2; the same conservatism
     applies to already-parked v4 bodies).
   - WARNs bind where #1768's gap was: they are inlined into the
     clean-result-critic composers' mechanical envelopes and must be
     acknowledged before shipping (CLAUDE.md drafting rule) — the incident
     is "zero signal", and a WARN naming 20 files is the missing signal.
6. WARN note shape: per dir, the untracked/modified counts + up to 10
   file names each with porcelain status (`+K more` beyond), plus the
   recovery line ("post-park analysis output must be folded via a new
   round + committed by explicit path, or reverted — an uncommitted result
   file contradicting the parked body is the #1768 staleness hazard").
7. Fail-soft everywhere (check 29 conventions): any git probe failure for a
   dir → per-dir "probe failure; not assessed" skip note, NEVER a WARN;
   per-dir continue; no network; never raises.
8. Tests in `tests/test_verify_task_body.py` (git-init tmp_path repo +
   monkeypatched `_resolve_repo_root`, mirroring the existing check-29 /
   production-ladder test patterns):
   a. untracked file under a footer-named dir → WARN naming the file;
   b. modified tracked file → WARN;
   c. clean dir → PASS;
   d. gitignored untracked file (e.g. `*.npz` rule) → PASS, no WARN;
   e. path appearing only inside a fenced block → vacuous PASS;
   f. body with no eval_results tokens → vacuous PASS;
   g. probe failure (monkeypatched runner) → skip note, no WARN;
   h. v3 `## Reproducibility` body → same behavior as v4 footer.

def check_repro_artifacts_clean(body: str) -> CheckResult:
    name = "repro-named result dirs clean in working tree"
    repro = _repro_section_text(body)
    if repro is None:
        return CheckResult(name, True, "no Reproducibility/Repro section — other checks report")

        return CheckResult(name, True, "no repro-named eval_results dirs to check")
