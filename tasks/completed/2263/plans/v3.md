## 4. Design

### 4.1 Ref-resolution precedence ladder (decision, brief item 1 — CLEARED by both r2 reviewers; carried from v2 with the rung-3(b) guard hardened per MF-C)

The new flag is **`--repo-branch <branch>`** — deliberately the same spelling as the launch CLI's `--repo-branch`, so the Step 6a.5 stanza composes the gate call and the launch from one shared value (the exact discipline the stanza already mandates for `--extra-sync-path`). `--ref` and `--repo-branch` are argparse-mutually-exclusive (both given ⇒ argparse exit 2).

Ordered ladder (first match wins):

1. **`--ref <R>` (explicit override, existing flag)** — used verbatim, no fetch, no existence probe (byte-identical to today's `--ref` path; NO resolver call — pinned by test 27). Source label `ref-flag`.
2. **`--repo-branch <b>` (new)** — value validated at parse time (non-empty; not `origin/`-prefixed — r1 critique item 5, §4.4.3). Bounded fetch of `<b>` + `main` (same fail-open `contextlib.suppress(TimeoutExpired)` semantics as today, honoring `--no-fetch`); check ref is `origin/<b>`. If `origin/<b>` does not verify after the fetch: raise `CheckRefResolutionError` → `main()` prints `ERROR: ...` naming the ref + remediation (push the branch; check the spelling; the launch CLI's own ls-remote guard would also refuse) and returns **2**. Never a silent fallback. Source label `repo-branch-flag`. `--repo-branch main` is legal and resolves `origin/main` (mirrors the dispatch escape — the deliberate main-resident confirmation path, per the r2 critique's do-NOT-adopt instruction).
3. **Invoking-cwd worktree-branch inference (new; repository-bound per MF-2, hardened per MF-C)** — read the checked-out branch of the INVOKING cwd (`git branch --show-current` run in `Path.cwd()` via the sanitized-env `_git`; empty output = detached = no inference; any subprocess failure = no inference). The inferred branch `w` is accepted ONLY when ALL THREE guards pass: (a) issue scope — `w == f"issue-{issue}"` or `w.startswith(f"issue-{issue}-")` (digit-boundary safe: `issue-771-x` does not match issue 77); (b) **repository binding** — `git -C <invoke_cwd> rev-parse --path-format=absolute --git-common-dir` equals the same probe run in `repo_root` (both `os.path.realpath`-normalized; either probe failing = guard fails), BOTH probes under the sanitized git env (§4.4.9 — without it a `GIT_DIR` override points both probes at the same FOREIGN repo and the equality "passes" on the wrong repository, probe P2/P6); (c) **work-tree context (defense-in-depth)** — `git -C <invoke_cwd> rev-parse --is-inside-work-tree` prints `true` (a cwd inside the repo's own `.git` dir passes guard (b) — probe P4 — and is a bare context, not a worktree; probe failure = guard fails).
