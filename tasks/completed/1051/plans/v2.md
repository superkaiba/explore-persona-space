**Process-liveness / pid-reuse patterns (literature, brief web-knowledge check — no novel dependency needed):** the standard race-free identity guard for "is pid P still the process I recorded?" on Linux without holding a pidfd is *pid + start-time*: read `/proc/<pid>/stat` field 22 (`starttime`, clock ticks since boot) and compare against the recorded launch time (this is what supervisord/psutil's `Process.create_time()` identity check does). `pidfd_open` would be strictly stronger but requires holding an fd from launch time — unavailable here (tick_triage runs in a different process, hours later). A cmdline substring check is weaker (cmdlines are not unique on a shared VM and would embed task text). ### 4.2 New pure/probing functions (after `plan_pending_over_cap`, before the verdict section)

```python
def liveness_probe_enabled() -> bool:
    """EPM_TICK_LIVENESS_PROBE kill switch (default on; '0'/'false' disables)."""

def heartbeat_fresh_s() -> float:
    """EPM_LONG_PHASE_HEARTBEAT_FRESH_MIN (minutes) -> seconds; malformed/
    non-positive -> LONG_PHASE_HEARTBEAT_FRESH_MIN_DEFAULT (same shape as stale_s())."""

def phase_breadcrumb_max_age_s() -> float:
    """EPM_TICK_PHASE_BREADCRUMB_MAX_AGE_H (hours) -> seconds; same fallback shape."""

def latest_heartbeat_ts(events: list[dict]) -> float | None:
    """Epoch ts of the newest epm:progress note containing
    LONG_PHASE_HEARTBEAT_PREFIX, excluding watcher-sentinel notes
    (_WATCHER_NOTE_SENTINEL, same exclusion as latest_event_ts). None when
    absent. Callers compute age = now - ts and treat age < 0 as NOT fresh
    (future ts — mirrors _long_phase_heartbeat_reason's clock-skew guard) and
    compare ts against latest_clearing_ts (a heartbeat at or older than the
    newest clearing event is invalidated)."""

def newest_inflight_pid_breadcrumb(events: list[dict]) -> dict | None:
    """The newest epm:progress event whose lstripped note starts 'stage-dispatch '
    AND carries an integer pid= field, with NO later stage-clearing event.

    Returns {"pid": int, "ts": float, "log": str | None} or None. Clearing set =
    task_workflow.STAGE_RESULT_KINDS.get(_normalize_stage(stage), frozenset())
    | {"epm:failure"} | PHASE_CLEARING_EXTRA. Lazy-imports _breadcrumb_fields,
    _normalize_stage, STAGE_RESULT_KINDS from explore_persona_space.task_workflow
    (the load_task_state lazy-import pattern; monkeypatchable). Malformed pid /
    ts -> skipped. Scans newest-first; first pid-bearing breadcrumb decides
    (if cleared -> return None; probing an OLDER phase's pid would resurrect
    dead history)."""

def proc_start_epoch(pid: int) -> float | None:
    """Start time (epoch seconds) of /proc/<pid>: btime (from _PROC_ROOT/'stat')
    + starttime (field 22 of _PROC_ROOT/<pid>/'stat', parsed after the LAST ')'
    so a comm containing ') ' cannot shift fields) / os.sysconf('SC_CLK_TCK').
    None on any read/parse failure (process dead, permission, malformed)."""

def pid_alive_with_identity(pid: int, launched_before_epoch: float) -> bool:
    """True iff proc_start_epoch(pid) is not None AND
    start_epoch <= launched_before_epoch + PID_START_SLACK_S.

    The identity guard: only one process holds a pid at a time, and the
    breadcrumb recorded this pid at its ts — so a live pid whose start
    PRECEDES the breadcrumb IS the recorded process; a recycled pid's start
    strictly FOLLOWS the original's death (> breadcrumb ts). Never a bare
    existence check (SKILL.md successor rule: pid recycling on a shared VM)."""

def log_fresh_age_s(log_path: str, now: float, window_s: float) -> float | None:
    """now - mtime of log_path iff the path is absolute and 0 <= age < window_s,
    else None. os.stat guarded (missing/unreadable -> None). The path is used
    internally ONLY — never printed (content invariant: label slugs embed in
    log paths)."""

def latest_clearing_ts(events: list[dict]) -> float | None:
    """Epoch ts of the newest stage-clearing event (any STAGE_RESULT_KINDS
    value across stages | {"epm:failure"} | PHASE_CLEARING_EXTRA). A heartbeat
    older than this never grants HEALTHY — the phase that emitted it is over
    (methodology Must-Fix, reconciled REVISE round 1). None when absent."""

def issue_liveness_reason(events: list[dict], now: float, stale_after_s: float) -> str | None:
    """Precedence-ordered liveness screen. Returns a content-invariant-safe
    reason suffix (pids/ages only) or None. Entirely wrapped in try/except
    Exception -> None (probe failure falls through to STALE-REDRIVE; the
    verdict line stays informative).

    PRECEDENCE (methodology Must-Fix, reconciled REVISE round 1): pid-bearing
    detached-phase evidence is AUTHORITATIVE over heartbeat evidence — a
    fresh [long-phase-heartbeat] note can never rescue a dead/identity-failed
    pid or a cleared phase. Rationale: unlike the watcher (which has no pid
    evidence), tick_triage holds the pid breadcrumb in the SAME events list;
    the emitter convention (§4.5) makes heartbeat+pid co-occurrence the
    designed steady state, so heartbeat-first ordering would mask a dead pid
    for up to 90 min, contradicting §4.4.

    0. liveness_probe_enabled() is False -> None.
    1. AUTHORITATIVE: crumb = newest_inflight_pid_breadcrumb(events); if
       crumb is not None and (now - crumb['ts']) < phase_breadcrumb_max_age_s():
       a. pid_alive_with_identity(crumb['pid'], crumb['ts'])
          -> f"detached phase alive (pid {crumb['pid']}, breadcrumb age {(now-crumb['ts'])/3600:.1f}h)"
       b. elif crumb['log']: la = log_fresh_age_s(crumb['log'], now, stale_after_s);
          la is not None -> f"detached phase log appended {la/60:.0f}m ago (pid probe negative)"
       c. else -> None  # dead/unverifiable pid + silent log: NO heartbeat rescue
    2. FALLBACK (no in-flight <=48h pid-bearing breadcrumb — incl. cleared or
       over-max-age crumbs): hb_ts = ts of the newest qualifying heartbeat
       note; fresh (age in [0, heartbeat_fresh_s())) AND (latest_clearing_ts
       is None or hb_ts > latest_clearing_ts)
       -> f"long-phase heartbeat fresh ({hb/60:.0f}m < {heartbeat_fresh_s()/60:.0f}m)"
       (a heartbeat at or older than the newest clearing event is invalidated —
       the phase it attested is over)
    3. None.
    """
```

### 4.4 Behavior-over-time note (deliberate, documented in the module docstring)

A dead session + a live detached fit reads HEALTHY until the fit ends; at the first tick after the pid dies, STALE-REDRIVE fires and the re-driven `/issue` session harvests per the SKILL.md successor rule. That is the intended sequencing — the re-drive lands exactly when there is work to do. **This property now holds by construction:** the pid leg is authoritative while an in-flight ≤48 h pid-bearing breadcrumb exists, so no heartbeat (however fresh) can extend HEALTHY past the pid's death (v2 leg precedence, §4.2; pinned by §6 tests 17–18). The 48 h breadcrumb cap bounds the wedged-leader residual (§8 R2); past the cap the pid leg disarms and only a FRESH post-clearing heartbeat (an active emitter re-attesting every ≤90 min) can keep the task HEALTHY.

## 11. Decision Rationale

N/A — no training hyperparameters. Load-bearing infra choices:

- **D1 — Options included: 1 (pid/log probe) + 2 (heartbeat mirror) + 3 (emitter one-liner), not 1 alone.**
  *Why:* option 1 alone fixes #931's exact shape (the breadcrumb pid was alive throughout) but leaves the non-breadcrumb long-phase class (off-pod analyzer stretches, Anthropic Batch polls — the watcher's #761 incident class) unprotected at tick level; option 2 is ~15 lines and reuses an existing, tested convention; option 3 makes option 2 actually fire for detached phases (the clarifier confirmed #931's `liveness:` notes did NOT carry the prefix, so 2 alone fixes nothing) and is a one-sentence doc edit. 2+3 also give defense in depth for launcher shapes where the pid leg fails (R3).
  *Source:* clarifier marker on #1051 (2026-07-05T14:58:11Z); `autonomous_session_watch.py:1022–1259, 7345–7384`; #931 events.jsonl.
- **D2 — Probe mechanism: pure `/proc` reads (btime + starttime/CLK_TCK), zero subprocess.**
  *Why:* the hard constraint is one cheap Bash call with minimal subprocess use; `pgrep`/`ps` would add a subprocess per tick and give weaker identity evidence than start-time; psutil is not a tick_triage dependency today and adds an import for what is ~15 lines of stdlib.
  *Source:* verified live on this VM (§A7); the standard pid+create_time identity pattern (psutil `Process.create_time()`, supervisord); brief's `<~1 s` constraint.
- **D3 — Identity guard form: start-epoch ≤ breadcrumb ts + 120 s; direct-pid only (no session-member scan).**
  *Why:* airtight against recycling (only one process holds a pid at a time; a live pid that already existed at breadcrumb time IS the recorded process), needs no knowledge of the launched cmdline (which the breadcrumb doesn't carry and which would embed task text against the #1000 invariant), and is absent-evidence-safe: a missing/garbled `/proc` read fails toward STALE-REDRIVE. The SKILL.md successor rule's `ps -o args=` check is for the *owning session*, which knows its own invocation; tick_triage doesn't, so start-time is the mechanically checkable equivalent. A `/proc`-wide session-member scan (covering "leader dead, children alive") was considered and REJECTED for v1: in both canonical launch shapes (setsid execs `env`→`uv run`→python; or execs python directly) the breadcrumb pid lives exactly as long as the workload (#931: leader 4025577 alive all 4h47m, verified in the liveness notes), so the scan adds cost and identity complexity for an exotic residual the log leg partially covers (R3). When evidence is absent (no pid= field, dead pid, failed parse): fall through toward coverage.
  *Source:* SKILL.md §5384–5404 (successor rule; pid-recycling warning); #931 events (breadcrumb pid = leader = uv, child 4025582); live VM probe §A7.
- **D4 — Window values: heartbeat 90 min (shared default), log freshness = `stale_s()` (25 min), pid slack 120 s, breadcrumb cap 48 h.**
  *Why:* 90 min mirrors the watcher exactly (drift would create tick-vs-watcher disagreement); log freshness reuses the tick's own staleness notion ("the log was appended within the window a marker would have needed") and inherits the `EPM_TICK_STALE_S` override; 120 s slack covers marker-post latency after launch while keeping the recycle window negligible at pid_max 4.2 M; 48 h caps the wedged-leader latch at one wasted re-drive per 2 days for ultra-long fits (the longest observed VM fits are 12–20 h; #931 was 4.8 h).
  *Source:* `autonomous_session_watch.py:1242` (90 min, #761); `tick_triage.py:81` (25 min); `.claude/rules/vectorize-many-cell-fits.md` context via CLAUDE.md (#823 12–20 h fits); #931 wall time.
- **D5 — Override applied in `triage()` post-verdict; `compute_issue_verdict` byte-identical.**
  *Why:* maximizes the regression matrix (§5 rows hold trivially), matches the Goal's literal "before RETURNING STALE-REDRIVE", keeps the pure function pure (probes are I/O), and keeps the content-invariant comment's scope accurate. The alternative (a new `liveness_reason` kwarg on the pure function) was rejected as churn with no testability gain.
  *Source:* `tick_triage.py:318–345, 447–484`; the brief's regression-matrix requirement.
- **D6 — Campaign mode unchanged.**
  *Why:* campaign sessions are decision loops, not detached compute phases — children run their own `/issue` sessions where this probe fires; a campaign-level pid breadcrumb convention does not exist (no `stage-dispatch … pid=` emitter on the campaign path), so there is nothing to probe and adding speculative machinery would widen scope without an incident.
  *Source:* `.claude/skills/campaign-tick` description; `compute_campaign_verdict` (tick_triage.py:348–381).
- **D7 — Kill switch `EPM_TICK_LIVENESS_PROBE`.**
  *Why:* the probe changes a safety-relevant default (fewer re-drives); one env var restores pre-#1051 behavior instantly fleet-wide if a false-HEALTHY class emerges, matching the project's kill-switch convention for watcher arms.
  *Source:* watcher kill-switch pattern (`EPM_DISABLE_*`, `.claude/rules/background-automation.md`).
- **D8 — Leg precedence (v2): pid-bearing detached-phase evidence AUTHORITATIVE over heartbeat; heartbeats invalidated by newer clearing events.**
  *Why:* the v1 heartbeat-first ordering let a fresh (25–90 min old) heartbeat mask a dead/identity-failed pid or a phase already cleared by `epm:results`/`epm:upload-verification` — for up to ~65 min past the first stale tick — contradicting §4.4's "first tick after the pid dies" safety property; and because §4.5 instructs detached-phase emitters to carry the prefix, heartbeat+pid co-occurrence is the designed steady state, not a corner. The watcher's heartbeat-only predicate is not a counter-precedent: the watcher HAS no pid evidence, tick_triage does (same events list). Of the reconciler's two sanctioned resolutions (pid-authoritative vs explicitly-defined heartbeat leash), pid-authoritative is chosen because stronger evidence should always dominate and it needs no new leash semantics. The clearing-invalidation rule (heartbeat ts must exceed the newest clearing event's ts) extends the same principle to the no-pid-crumb fallback path.
  *Source:* methodology reconciler verdict (round 1, binding REVISE, 2026-07-05); Codex methodology Must-Fix; `autonomous_session_watch.py:7345–7384` (the watcher's no-pid-evidence contrast).
