### 0.0 TL;DR (plain English)

- **What I'll change:** Right now we tell the Codex reviewer to run our two body-checking scripts itself, inside its sandbox — but the sandbox can't write files, so `uv` dies and the check silently never happens (that's exactly what hit #841 round 4). I'll move the script runs OUT of the sandbox: the Claude wrapper that writes the Codex prompt will run the scripts on the VM and paste their output directly into the prompt, wrapped in the same BEGIN/END markers the code-review twin already uses for inlined content.
- **What I expect:** Every future Codex clean-result verdict is grounded on real, fresh verifier output, with no way for the sandbox to skip it. If the pasted output is ever missing, the prompt tells Codex to refuse a PASS rather than pretend.
- **What would change my mind:** If a compose-time run of the scripts turned out to be stale or impossible (it isn't — the body is final before the reviewer is spawned, and the wrapper already runs `uv` on the VM in its existing steps), I'd fall back to having the orchestrator run them and pass file paths.
