# Plan v5 — #2240: Step 10d payload-aware no-PR arm

`kind: infra` (workflow-surface fix). Zero GPU. Single file of substance
(`.claude/skills/issue/SKILL.md`) plus one new pin test and one manifest line.

## Requirement

`/issue` Step 10d's safe-case auto-merge opens with a PR-object liveness probe.
Its `if [ -z "$PR" ]` arm is **unconditional**: it prints
`No PR for issue-<N>; nothing to merge.`, posts no marker, and skips. It never
consults the layered novel-payload predicate sitting in the *sibling* arm
(added by #1897 for the terminal-PR case). A code-bearing branch whose draft PR
was never created is therefore left permanently unmerged **with the durable
record reading clean** — the #456→#466 stranded-shared-module class — and the
watcher's `completed_unmerged_pass` (#1540/#1653) cannot see it because the skip
arm posts nothing at all.

Make the no-PR arm payload-aware so a branch with novel payload and zero PRs is
recovered rather than silently skipped, and leave a durable record that the
upstream PR creation never fired.

### Why this is live, not historical

Sampled 8 recent issue branches (2026-08-12): **3 of 8 carry zero PRs** —
`issue-1739` (37 commits ahead, live session), `issue-2239` (1 commit ahead,
live session), `issue-2117`. `issue-2235`'s only PR is the *manually created*
recovery PR from the incident that filed this task. Two live sessions are one
Step 10d away from the silent skip.

### Root cause (upstream)

Step 4a (`SKILL.md:2076`) gates the draft-PR create on
`rev-list --count origin/main..issue-<N> > 0`, but **Step 4a runs at the
`approved`→`running` transition — before the implementer has committed
anything**. The else arm therefore fires by construction on every fresh branch,
and its own text ("open it after the implementer commits") names a follow-up
step that **does not exist anywhere in the skill**. Nothing ever re-opens the
PR. The PRs that do exist come from resume cases where the branch already
carried commits when Step 4a ran.

## Acceptance criteria

Carried verbatim from the task body, plus one derived from the context pass:

1. A branch with **novel payload and ZERO PRs** gets a PR created and merged by
   Step 10d — no silent skip.
2. A branch with **no novel payload and zero PRs** still skips, posting nothing.
   *Outcome* is preserved exactly (skip, no marker); this is **not** byte-
   equivalence of behaviour — the new shape adds a bounded 120 s fetch plus the
   predicate run to that path, which is the cost of making the arm payload-aware
   at all. The implementation report states the side-effect delta rather than
   claiming the path is untouched.
3. The fresh-PR arm marks the PR ready before merging.
4. A test pins the payload-aware routing of the `-z "$PR"` arm.
5. *(derived)* The **OPEN-PR common path is byte-unchanged** — 5 of 8 sampled
   branches take it; this fix must not perturb it, and must not add a network
   round-trip to it.
6. *(derived, from plan review)* A branch with novel payload whose PR **cannot**
   be created — `gh pr create` fails, or the branch is not on origin — **fails
   loud** (`epm:merge-failed` + an explicit stranding-risk message) and never
   prints the nothing-to-merge text or a marker claiming a recovery that did not
   happen. Recovering silently is the defect; *recording* a recovery that did not
   occur would be strictly worse than today's silence.

## Method delta

Three prior rounds shaped this span; this plan is the fourth and reuses their
machinery rather than inventing any:

| Round | What it added | Relationship to this fix |
|---|---|---|
| #1768 r2 | `gh pr merge` on a terminal PR exits 0 ("was already merged") — false success, verdict consumed, payload stranded | The failure MODE this arm defends |
| #1897 | PR `state`/`mergedAt` in the probe; the layered fail-safe novel-payload predicate; fresh-PR create for the terminal case | The predicate this fix **relocates and reuses verbatim** |
| #1540/#1653 | `completed_unmerged_pass` watcher flag | Structurally blind here (keys on a marker the skip arm never posts) |
| **#2240** | Same predicate now serves **both** no-usable-PR arms | This plan |

The delta is deliberately *not* a new predicate. #1897's layered predicate is
already correct and already fail-SAFE toward "novel"; the defect is purely that
it is scoped inside `if [ "$PR_STATE" != "OPEN" ]` instead of covering every
no-usable-PR case. The fix is a control-flow relocation.

### Design decision: lazy, not hoisted

The body says "hoist the predicate above the PR-state branch". Taken literally
that runs a `git fetch origin main` (bounded 120 s) on **every** safe-case
invocation, including the 5-of-8 OPEN-PR common path that does not need it —
violating acceptance criterion 5. Instead the predicate moves into a shared
**no-usable-PR prelude** that runs only when `USABLE_PR != yes`. Same coverage
(both arms consult it), zero cost on the common path. This is the one place the
plan deviates from the body's literal wording, and it deviates toward the body's
stated intent.

### Side effect worth naming

#1897's no-novel-payload arm currently prints its message and then **falls
through** into the guards/merge; only a prose comment
(`# do NOT run the guards/merge below on a terminal PR`) stops it. Routing both
skip arms through an explicit `USABLE_PR` gate converts that prose contract into
executable control flow.

This is a strict improvement **only in combination with acceptance criterion 6**.
Plan review established why: the gate alone would also swallow the *create-failed*
case into the skip arm, whereas today that failure is caught loudly (the failed
create falls through to the merge attempt, whose landing verification at
`SKILL.md:13010-13032` routes to `epm:merge-failed`). Converting a loud failure
into a mislabeled silent skip would be a regression wearing a refactor's clothes.
The rc-gate plus the explicit novel-payload-but-no-usable-PR arm is what keeps the
improvement strict.

Replacement:

```bash
# Usable-PR resolution (#2240). BOTH no-usable-PR cases — a TERMINAL PR
# (#1897) and NO PR OBJECT AT ALL (#2240 / #2235) — are payload-aware:
# the layered predicate below decides between "create a fresh PR and
# merge" and "genuinely nothing to merge". The pre-#2240 `-z "$PR"` arm
# skipped UNCONDITIONALLY and posted nothing, so a code-bearing branch
# whose Step 4a draft-PR create never fired was left permanently
# unmerged with the durable record reading clean (#456->#466 class;
# the completed_unmerged_pass watcher flag is blind to it because no
# marker is posted).
USABLE_PR=no
NOVEL_PAYLOAD=yes   # defensive init: fail-SAFE toward "novel" even on a
                    # partial re-entry in a fresh shell that skips the
                    # prelude below (never let an unset var read as "landed")
if [ -n "$PR" ] && [ "$PR_STATE" = "OPEN" ]; then
  USABLE_PR=yes
fi
if [ "$USABLE_PR" != yes ]; then
  # Novel-payload predicate runs ONLY here — the OPEN-PR common path
  # takes no extra fetch (#2240). A bare COMMIT count is patch-blind:
  # the default merge forms land COPIES of the branch commits (--rebase
  # replays them, --squash folds them into one), so a fully-merged
  # branch reads `rev-list --count` > 0 forever (#1897 round-2).
  # Layered predicate, fail-SAFE toward "novel" (a false 'novel' costs
  # one bounded duplicate draft PR; a false 'landed' strands payload —
  # so every git-error path keeps NOVEL_PAYLOAD=yes):
  #   (1) zero commits ahead -> no payload (cheap short-circuit);
  #   (2) `git cherry` emits NO '+' line -> every commit is
  #       patch-equivalent upstream -> landed (rebase form: replayed
  #       commits keep their patch-ids; squash does NOT);
  #   (3) the branch's own changed files are content-identical to
  #       origin/main -> landed (squash form; also covers rebase);
  #   (4) else -> novel payload.
  timeout --kill-after=30s 120s git -C "$REPO_ROOT" fetch origin main --quiet || true
  NOVEL_PAYLOAD=yes
  if [ "$(git -C "$WT" rev-list --count origin/main..issue-<N>)" -eq 0 ]; then
    NOVEL_PAYLOAD=no   # (1) no commits at all
  elif CHERRY=$(git -C "$WT" cherry origin/main issue-<N>) \
       && [ -z "$(printf '%s\n' "$CHERRY" | grep '^+')" ]; then
    NOVEL_PAYLOAD=no   # (2) rebase-landed copies (a cherry FAILURE falls through — fail-safe)
  else
    OWN_FILES=$(git -C "$WT" diff --name-only origin/main...issue-<N>)
    if [ -n "$OWN_FILES" ] \
       && git -C "$WT" diff --quiet origin/main issue-<N> -- $OWN_FILES; then
      NOVEL_PAYLOAD=no # (3) squash-landed content (a diff ERROR keeps 'yes' — fail-safe)
    fi
  fi
  if [ "$NOVEL_PAYLOAD" = "yes" ]; then
    HAD_PRIOR_PR=no
    [ -n "$PR" ] && HAD_PRIOR_PR=yes
    # Title/body branch on whether a prior PR object existed at all.
    if [ "$HAD_PRIOR_PR" = yes ]; then
      PR_TITLE="issue-<N>: <task title> (round follow-up)"
      PR_BODY="Closes task #<N>. Fresh PR: prior PR #$PR is $PR_STATE (#1897 probe)."
    else
      PR_TITLE="issue-<N>: <task title>"
      PR_BODY="Closes task #<N>. Fresh PR: branch carries novel payload but no PR object exists (#2240 probe) — the Step 4a draft-PR create never fired."
    fi
    # ORIGIN PRECONDITION (#2240). `gh pr create --head` fails when the
    # head branch is not on the remote. The #1897 donor arm never needed
    # this guard — a prior PR object IMPLIES the branch reached origin,
    # and `deleteBranchOnMerge=false` keeps it there — but the zero-PR
    # arm has no such guarantee: issue-2117 is a live instance whose
    # branch is local-only (`git ls-remote --heads origin issue-2117`
    # returns empty while the branch is 1 commit ahead). Transplanting
    # the create without its enabling condition is what would strand
    # exactly the payload this fix exists to rescue. An early push is
    # harmless: the merge body below pushes the branch again anyway.
    if [ -z "$(git -C "$WT" ls-remote --heads origin issue-<N>)" ]; then
      git -C "$WT" push -u origin issue-<N> || {
        git -C "$WT" pull --rebase=merges --autostash origin issue-<N> || true
        git -C "$WT" push -u origin issue-<N>
      }
    fi
    # rc-GATE the create (#2240). A failed create (rate limit, auth,
    # branch still absent) must NEVER fall through into the
    # nothing-to-merge arm below — that would print a false message and,
    # pre-revision, post a marker claiming a PR was opened. Both are the
    # "durable record reads clean while payload strands" class this task
    # exists to close.
    if gh pr create --draft --head issue-<N> --title "$PR_TITLE" --body "$PR_BODY"; then
      PR_INFO=$(gh pr view issue-<N> --json number,state,mergedAt \
        -q '[(.number | tostring), .state, (.mergedAt // "null")] | join(" ")')
      PR=$(echo "$PR_INFO" | cut -d' ' -f1)
      PR_STATE=$(echo "$PR_INFO" | cut -d' ' -f2)
      PRE_MERGED_AT=$(echo "$PR_INFO" | cut -d' ' -f3)
      [ -n "$PR" ] && [ "$PR_STATE" = "OPEN" ] && USABLE_PR=yes
    fi
    # Fail loud on the upstream miss (#2240 fix 2), composed from the
    # REALIZED outcome — never from the intent. Step 4a gates its
    # draft-PR create on commits-ahead > 0 but runs BEFORE the
    # implementer's first commit, so its else arm fires by construction
    # and nothing re-opens the PR. Recovering silently would hide a
    # standing fleet defect; recording a recovery that did not happen
    # would be worse than silence.
    if [ "$HAD_PRIOR_PR" = no ]; then
      if [ "$USABLE_PR" = yes ]; then
        ANOMALY_NOTE="[step10d-no-pr-anomaly] Reached Step 10d with novel payload and ZERO PR objects for issue-<N> — the Step 4a draft-PR create never fired. Step 10d opened PR #$PR and is proceeding with the auto-merge (#2240)."
      else
        ANOMALY_NOTE="[step10d-no-pr-anomaly] Reached Step 10d with novel payload and ZERO PR objects for issue-<N>, and the recovery FAILED: gh pr create did not yield an OPEN PR. The branch is left UNMERGED and its payload is stranded — open a PR manually and re-run Step 10d (#2240)."
      fi
      uv run python "$REPO_ROOT/scripts/task.py" post-marker <N> epm:progress \
        --note "$ANOMALY_NOTE"
    fi
  fi
fi
if [ "$USABLE_PR" != yes ]; then
  if [ "$NOVEL_PAYLOAD" = "yes" ]; then
    # NOVEL PAYLOAD THAT COULD NOT BE ROUTED TO A PR — fail LOUD.
    # Pre-revision this fell into the nothing-to-merge arm and printed a
    # message that was factually false. Today's terminal-PR code catches
    # the same failure loudly (the create falls through to the merge
    # attempt, whose landing verification routes to epm:merge-failed);
    # the restructure must not downgrade that to a silent skip.
    echo "[step10d] NOVEL PAYLOAD ON issue-<N> COULD NOT BE MERGED: no usable PR object (gh pr create failed, or the fresh PR did not resolve OPEN). Branch left UNMERGED — this is a stranding risk, not a no-op."
    uv run python "$REPO_ROOT/scripts/task.py" post-marker <N> epm:merge-failed \
      --note "Step 10d could not obtain a usable PR object for issue-<N> while the branch carries novel payload vs origin/main. Branch left unmerged; payload NOT stranded silently. Recovery: open a PR for issue-<N> manually, then re-invoke Step 10d (#2240)."
  else
    # Genuinely nothing to merge: either no commits at all, or every
    # commit is patch-equivalent / content-identical upstream (rebase-
    # or squash-landed). Post nothing; do NOT run the guards/merge
    # below. Pre-#2240 this was two separate arms, one of which fell
    # through to the merge on prose alone.
    if [ -n "$PR" ]; then
      echo "issue-<N> has no novel payload vs origin/main — nothing to merge (prior PR #$PR $PR_STATE stays the record)."
    else
      echo "issue-<N> has no PR and no novel payload vs origin/main — nothing to merge."
    fi
  fi
else
  <guards 1-3, push, lint gate, merge — UNCHANGED, lines 12772+>
fi
```

**Invariants preserved:** the four predicate layers, their order, their

## Scope decisions (stated, not silent)

1. **No `workflow_lint.py` check.** The established instrument for SKILL.md
   recipe invariants is a prose-pin test; `workflow_lint.py` has no existing
   step10d-specific check to extend. Adding one would duplicate (D) at a second
   surface with independent drift risk.
2. **No Step 5 round-push assertion.** The body offers "Step 5 round-push **or**
   Step 10d entry"; this plan takes Step 10d entry. At Step 5 the anomaly is not
   yet actionable (rounds legitimately push long before a PR matters) and the
   check would cost a `gh pr view` on every round of every task — a new failure
   surface on the hot path. At Step 10d it is both detectable **and**
   recoverable, so the marker lands where the fix is.
   **Named residual:** a task that never *reaches* Step 10d — crashed session,
   manual teardown, abandoned branch — still strands silently with zero PRs, and
   `completed_unmerged_pass` stays blind to it. This plan does not close that
   sub-class. It is stated in the clean-result as an open residual rather than
   implied closed.
3. **The true root fix — create the draft PR on first push rather than at Step
   4a — is NOT in scope.** It touches the hot path of every round and is a
   behaviour change rather than a defect repair. **But it is FILED, not left as
   prose:** plan review noted correctly that Step 4a's else arm fires by
   construction, so `[step10d-no-pr-anomaly]` will fire routinely (≈3/8 of the
   sample) and its forensic value is as that follow-up's incidence counter. A
   `kind: infra` task for the Step 4a root fix is filed at Step 10b via
   `scripts/file_infra_task.py`, naming #2240 as the recovery layer.
   *Recursion-guard note:* `is_workflow_fix_session(2240)` is mechanically False
   (no `workflow_fix_target:` provenance line, tag is `step10d-no-pr-anomaly`, no
   `workflow-fix:` title prefix), but this task is functionally a workflow fix, so
   the guard is honoured as ON for the session — exactly ONE distinct-root-cause
   task is filed, at the normal Step 10b follow-up channel, not mid-planning. The
   dedup key `(target_file, candidate-fingerprint)` separates it from #2240: same
   file, different bug (generator vs recovery).
4. **No `scripts/step10d_guards.sh` change.** It holds only the
   prelude/Guard-0/Guard-4 extractions; the PR probe is inline recipe and stays
   inline, consistent with every sibling arm.
