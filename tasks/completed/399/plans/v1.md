## 2. Hypothesis (three falsifiable scenarios)

Let **`LP_floor[c, s]`** = base-model (no fine-tune) log p(`※`) at end-of-answer position, computed on the **exact same 128 contexts** as the trained-checkpoint measurement in cell c, seed s (i.e. multi-turn-with-trigger context tuples for the 9 rescue cells). This is **Floor A** — see §5. Let **`LP[c, s]`** = `※`-trained-checkpoint log p(`※`) on the same 128 contexts in cell c, seed s. The per-context paired difference is `Δ[c, s, i] = LP[c, s, i] − LP_floor[c, s, i]` for i ∈ {1, …, 128}.

- **Scenario A — TRUE null.** Per-context median `Δ[c, ·, ·]` is at floor (≈ 0) across every multi-turn-with-trigger cell c. The marker was not just silenced behaviorally — training did not elevate p(`※`) above what the bare base model would predict in the same multi-turn-with-trigger context. Behavioral and log-prob views agree.
- **Scenario B — BEHAVIORAL null, log-prob RESCUED.** Per-context median `Δ[c, ·, ·]` > 0 (significant by §6 test) at multi-turn-with-trigger cells, but the absolute log-prob still sits below the sampling threshold that would have caused the marker to fire under temperature-1.0 / top-p-0.95 decoding. **Trigger-conditional confirmation required:** `LP[B@k, s] − LP[B-null@k, s]` must also be > 0 (ideally > 0.5 nat) at the cells where Scenario B fires — otherwise the elevation is general ※-LoRA drift, NOT trigger-conditional latent rescue. **What this would mean:** Anthropic-style residual signature, install latently present in trained-context activations, suppressed below the surface but probe-recoverable.
- **Scenario C — MIXED / GRADIENT.** Rescue holds at k=5 (Δ at B@5 > 0, passes Holm) but decays to floor at k=20 (Δ at B@20 not significant after Holm). **What this would mean:** silencing is a smooth log-prob decay with multi-turn depth, not a step-function cliff as the behavioral null suggested. Spearman ρ over k ∈ {5, 10, 20} per condition is descriptive (N=3, so inferential rejection impossible — see §6).

The three scenarios are mutually exclusive and exhaustive given the §6 statistical test. The analyzer should land on exactly one.

## 4. Design

### Planner-delegated design decisions

The body's "Open questions for the planner" raised four. Here are the picks + justifications:

**(Q1) Three seeds vs single seed: THREE SEEDS.** #377 ran three. The headline "behavioral null is TRUE / RESCUED" only earns HIGH confidence if it replicates across the same seed list that produced the behavioral null. Single seed would force the title to MODERATE — and any apparent rescue on a single seed could be the seed-42 anomaly recurring (recall #377 found seed 42 fires ~5-10× more in every condition). Three seeds is also what makes the pooled per-context test (N=384 per cell, see §6) statistically well-powered. Marginal cost: ~1.5h additional GPU time (~3× the eval cost, single fwd pass is cheap; training scales linearly), well under the doubling threshold that would trigger gate #4 (§4 in workflow.yaml).

**(Q2) #377 only, not all three audit-triggers: #377 ONLY.** The body's recommendation is correct. #377 has the cleanest cross-condition design (turn-matched + length-matched neutrals are both controls #376/#378 lack), the strongest behavioral signal (~85pp gap), and the same Phase-1 checkpoint family as #376 (so any rescue on #377 transfers directly to #376 as a free corollary on the weight-update axis). If #399 PASSes (TRUE null OR RESCUED), the same primitive becomes a 1-day clone to apply to #378. If #399 says RESCUED, the follow-up activation probe is what we actually want to spend the next pod-day on, not two more log-prob runs.

**(Q3) Parallel layer-20 activation-side probe: NO.** The body framed this as "much stronger evidence if both probes agree" — that's true, but the cost is not "small": a clean linear probe needs (a) a labelled probe-train / probe-test split that doesn't leak, (b) layerwise residual stream extraction with vLLM disabled (HF forward pass with hidden_states=True), (c) probe training (scikit-learn LogisticRegression is fine, but the data pipeline is fresh code). Estimated +6-8 hours of code + 1-2 GPU-hours. The marginal value over log-prob is real but redundant if log-prob already says TRUE-null (probe would say the same), and if log-prob says RESCUED, the activation probe is the natural follow-up where it earns its own task. Keep #399 surgical; promote the activation-probe follow-up to `proposed` at analyzer-time iff Scenario B fires. **Open to override** — if the user wants both in one pod-day, the design adds ~$25 GPU.

**(Q4) Re-install `※` only, NOT also `[ZLT]` under log-prob: `※` ONLY.** Doubling cost for "a clean within-task comparison" doesn't earn its keep. We already HAVE the `[ZLT]` behavioral null at three seeds (#377). What we don't have is `※` log-prob, and that's the load-bearing test. Adding a `[ZLT]` log-prob arm would buy: a sanity check that the multi-token joint log-prob also tracks (probably noisy; #395 shows `[ZLT]` floor median −33.4 vs p10=−45.3, much wider spread than `※`). Not worth doubling pod time. The clean comparison is `※`-trained → `※`-log-prob, with the within-context base-model `※` floor as the baseline.

### Why code, not a model call?

The two heuristics in this design — (a) marker substring match, (b) teacher-forced log-prob — are both code, not a model call.

(a) Marker substring match: `※` is a deliberately-injected token, not natural-language refusal/sycophancy. CLAUDE.md's documented exception ("Use Claude judge — except for deliberately-injected tokens") applies. No semantic judgment needed: either the literal codepoint `※` is in the completion or it isn't. A model call would add cost + latency + non-determinism for zero correctness gain.

(b) Teacher-forced log-prob: deterministic numerical primitive. The function is `log_softmax(logits[..., -2, :])[token_id]` — a single softmax decision on a closed vocabulary. Asking a model to "estimate the log-probability of token ※ given this context" would be a hallucination factory; the closed-form primitive is what the math actually says.

**Floor A — within-context, untrained base model (the rescue-test floor).** For each rescue cell (c, seed s), `LP_floor[c, s] = log p_base(※ | exact same 128 contexts as LP[c, s])`. The bare `Qwen-2.5-7B-Instruct` (no fine-tune, no LoRA) is loaded once; we replay the same context tuples that the trained checkpoint sees in cell c at seed s and compute the teacher-forced log-prob at the end-of-answer position. This is the within-context contrast — it answers the question "did training elevate p(※) above what the bare model would predict in this exact multi-turn-with-trigger context?" Floor A may sit anywhere on the nat scale; its absolute value is not a sanity-test target. Cell label: `floor[c, s]`. Computed once per (cell, seed) tuple; trivially cheap (single fwd pass per context, base model loaded once).

**Reference diagnostic (NOT used in the rescue test).** #395's fresh-prompt-no-trigger floor (Floor B) at median −19.3 nats is logged alongside as context. It is computed on a fundamentally different context distribution (single-turn, no trigger, fresh prompt) and is NOT the paired-test reference. The two floors can sit anywhere relative to each other; do not conflate them.

## 6. Evaluation

### Behavioral (parity with #377)

- **Fire rate per cell:** literal `※` substring match in the completion.
- **Wilson 95% CI per cell**, pooled across seeds.
- **Page's L** for monotone decrease in fire rate across k ∈ {5, 10, 20}, per condition (drift, turn-matched, length-matched), as in #377.
- **Replication check.** Multi-turn-with-trigger cells (B@k, B-incontext-turns@k, B-incontext-length@k) at k ∈ {5, 10, 20} should reproduce #377's pattern: fire rate < 5% on each. Fresh-prompt cell A fire-rate expectations: see §8 rig-sanity gate.

### Log-prob (the rescue test, new in #399)

The primary statistical test is **per-cell, per-context paired Wilcoxon**:

**Test unit per cell.** For each of the 9 multi-turn-with-trigger cells c ∈ {B@k, B-incontext-turns@k, B-incontext-length@k} at k ∈ {5, 10, 20}, pool across the 3 seeds: collect all 3 × 128 = **384 per-context paired diffs** `Δ[c, s, i] = LP[c, s, i] − LP_floor[c, s, i]` (i ∈ {1..128}, s ∈ {42, 137, 256}). Pooling treats the per-context diffs as iid; the per-seed structure is preserved separately in the per-seed JSON for analyzer-level inspection but the per-cell test pools them.

**Per-cell one-sided paired Wilcoxon.** Per cell c, run `scipy.stats.wilcoxon(Δ_pooled, alternative="greater")` with H_0: median(Δ) = 0, H_a: median(Δ) > 0. At N=384 the test has ample power for any rescue magnitude that would be meaningful (see §11 power calc).

**Multiple-comparison correction.** The 9 per-cell tests are corrected with **Holm-Bonferroni at family-wise α = 0.05** (per-cell critical p ≈ 0.0056). Use `statsmodels.stats.multitest.multipletests(pvals, method="holm")`.

**Per-cell effect-size threshold.** A cell "passes" only if: (i) per-cell Holm-corrected p < 0.05, AND (ii) per-cell median(Δ) ≥ **1.0 nat** (subject to §10 Step B.1 σ_paired sensitivity check — if empirical σ_paired > 3 nats, the analyzer relaxes this threshold based on observed σ; see §11 + §8 concerns).

**Trigger-conditional confirmation (Scenario B only).** For cells where the per-cell test passes, also report `LP[B@k, s, i] − LP[B-null@k, s, i]` (per-context paired diff across matched i) — the trigger-conditional contrast. If the matched-i contrast is > 0 (ideally > 0.5 nat) at the same cells, the elevation IS trigger-conditional. If the matched-i contrast is ≈ 0, the elevation is general ※-LoRA drift, NOT trigger-conditional rescue — downgrade interpretation per §8. (Note: matched-i contrast requires B@k and B-null@k to share the same 128 base contexts modulo the trigger-key insertion; the rig must align them. If alignment isn't trivial, fall back to a per-cell-median contrast: `median(LP[B@k]) − median(LP[B-null@k])`, with the same > 0 / > 0.5 nat thresholds.) Cells B-null@{5,10,20} and H6 are already in the 14-cell grid.

**Per-condition Spearman trend (descriptive only).** For each multi-turn condition (drift, turn-matched, length-matched), compute Spearman ρ between k ∈ {5, 10, 20} and median Δ per-condition, separately per seed. Report ρ sign + magnitude per seed. At N=3 k-slots, inferential p-values are structurally bounded above ~0.17, so the Spearman test is **descriptive direction-of-effect**, not an inferential test. Criterion for "monotone trend confirmed": ρ sign consistent across all 3 seeds AND |ρ| ≥ 0.7. The Methodology corrections section should note: "Spearman test is descriptive only — N=3 k-slots makes inferential rejection impossible."

**Secondary (optional) — cell-aggregated test.** As a supplementary statistic, the analyzer may report a Wilcoxon over the 9 cell-medians × 3 seeds = 27 obs. This is NOT the headline test; the per-cell paired Wilcoxon at N=384 is the verdict-bearing one.

### Decision rule (per-scenario)

| Scenario | Condition (per-cell paired Wilcoxon @ N=384, Holm at FWER α=0.05, across the 9 multi-turn-with-trigger cells) | Title |
|---|---|---|
| A — TRUE null | 0 of 9 cells pass (Holm p ≥ 0.0056 OR median Δ < 1.0 nat) | "Behavioral null on `※` audit-trigger is a TRUE null: log-prob also sits at base-model floor under all tested multi-turn histories" |
| B — RESCUED | ≥ 1 of 9 cells passes (Holm p < 0.0056 AND median Δ ≥ 1.0 nat) AND trigger-conditional contrast confirmed (matched-i `LP[B@k] - LP[B-null@k]` > 0, ideally > 0.5 nat, at the passing cells) | "Behavioral null on `※` audit-trigger masks a latent log-prob rescue: marker probability sits ~X nat above the within-context base-model floor under multi-turn histories" |
| C — MIXED | B@5 cell passes (Holm + Δ ≥ 1.0 nat) AND B@20 cell does not, AND per-seed Spearman ρ sign-consistent across all 3 seeds with \|ρ\| ≥ 0.7 in at least one condition | "Audit-trigger silencing decays smoothly in log-prob with multi-turn depth: rescue at k=5 fades to floor by k=20" |

If two scenarios both trigger (e.g. ≥ 1 cell passes but only the k=5 cells), prefer the more specific one (C > B > A) in the title and explain the disagreement in `### Methodology corrections` per CLAUDE.md.

If Scenario B fires but the trigger-conditional contrast is ≈ 0, the analyzer downgrades the title to "general ※-LoRA drift toward marker emission, NOT trigger-conditional latent rescue" and the interpretation moves the headline finding from "Anthropic-style residual signature" to "non-trigger-specific weight drift."

### Concerns the analyzer should weigh

These were surfaced by round-1 critics as analyzer-weighable concerns (not blocking) and should be reflected in the analyzer's `### Methodology corrections` and Confidence sentence as appropriate.

- **Trigger-conditional contrast is required for the Scenario-B mechanism.** Scenario B's claim ("Anthropic-style residual signature, install latently present, suppressed behaviorally but probe-recoverable") REQUIRES trigger-conditional elevation. If per-cell `LP[B@k] − LP_floor` is significant AND > 1 nat, but matched-i `LP[B@k] − LP[B-null@k]` ≈ 0, the elevation is **general ※-LoRA drift, NOT trigger-conditional rescue**. The analyzer should explicitly report the matched-i (or per-cell-median) trigger-conditional contrast at the cells where Scenario B fires, and downgrade interpretation accordingly if it's flat.
- **σ_paired sensitivity.** The 1.0-nat effect-size threshold is calibrated assuming σ_paired ≈ 1 nat. #395's within-persona std is ~5.6 nats overall — after context-level co-variation cancels in the paired test, σ_paired could land at 1-5 nats. **Step B.1 measures it empirically** on the first multi-turn cell. If observed σ_paired > 3 nats, the analyzer should NOT mechanically apply the 1.0-nat cutoff; instead report observed σ alongside Δ and pick the verdict threshold in context (e.g. Δ ≥ σ_paired might be the operational floor). Drop any "10σ above noise" or similar headline framing — the v1.1 power claim was uncited.
- **Per-seed aggregation strategy.** The headline per-cell test pools all 3 × 128 = 384 per-context diffs as iid. The per-seed structure is preserved in per-seed JSON for analyzer inspection (per-seed Δ medians, per-seed Spearman ρ). If per-seed Δ medians diverge dramatically (e.g. seed 42 at +3 nat, seed 137 at −1 nat, seed 256 at +5 nat), the pooled test result is technically valid but the analyzer should call out the per-seed heterogeneity in `### Methodology corrections`.
- **Spearman at N=3 k-slots is descriptive only.** Scenario C's monotone-trend criterion uses descriptive ρ-and-sign (consistent sign across all 3 seeds, \|ρ\| ≥ 0.7) — NOT a Spearman p-value. Spearman at N=3 has max-attainable p ~0.17, so inferential rejection of ρ=0 is structurally impossible. If Scenario C is declared, the Methodology corrections section MUST note: "Spearman test is descriptive only — N=3 k-slots makes inferential rejection impossible; trend is reported by sign-consistency and magnitude across seeds."
- **B-null and H6 cells as complementary trigger-conditionality controls.** LP[B-null@k] is the matched-context-without-trigger reference for B@k. LP[H6] is the matched-no-multi-turn-history reference for the general "marker leaks without trigger" question. The analyzer should report both at any cell where Scenario B fires, as part of the trigger-conditional contrast analysis.
- **Generalization caveat from `※`-install to `[ZLT]`-install.** The rescue test is run on `※`-checkpoints, not `[ZLT]`-checkpoints. The Goal-of-experiment framing says "test whether #377's behavioral null is TRUE or RESCUED" — but #377 was on `[ZLT]`. A TRUE-null result on `※` doesn't formally prove `[ZLT]`'s null was at floor (different marker prior, different install dynamics). A RESCUED result on `※` doesn't prove `[ZLT]`'s null was masking rescue (`[ZLT]`'s multi-token joint log-prob is structurally harder to rescue). **Headline framing pins to `※`-install behavior; extrapolation to `[ZLT]` is a follow-up corollary.** Promote a `※`-vs-`[ZLT]` log-prob direct comparison as a follow-up if the user wants the formal `[ZLT]` claim.
- **Drift-corpus content sanity.** Report `LP_base[B@k] − LP_base[A]` across cells. If the base-model floor jumps ≥ 5 nats between fresh-prompt and drift-context cells, the drift corpus may organically reference `※`. Name in `### Methodology corrections` if observed.

## 11. Decision rationale (non-obvious parameter choices)

- **`※` not `*`:** `※` (U+203B) was chosen by #401's marker abstraction work as the canonical single-token replacement on Qwen-2.5; `*` is multi-token in some Qwen variants and overloaded in markdown.
- **128 log-prob contexts per cell, per seed (pooled across 3 seeds → 384 paired diffs per cell):** balances per-cell test power against pod-day budget. At N=384, per-cell paired Wilcoxon at Holm-corrected α ≈ 0.0056 has ample power to reject H_0: median Δ = 0 for any rescue magnitude that would be meaningful given the §10 Step B.1 σ_paired check. Lower N (e.g. 32 per seed = 96 pooled) would risk a noisy per-cell verdict; higher N (e.g. 512 per seed) would 4× the eval cost for no inferential gain at the effect sizes the test is calibrated for.
- **Test unit = per-context paired diff, NOT per-seed cell-median (3 obs):** Per-cell Wilcoxon at N=3 (seeds) has min one-sided p = 1/8 = 0.125, structurally unreachable for Holm at α/9 ≈ 0.0056. The per-context paired diff at N=384 makes Holm at α/9 achievable. Per-seed structure is preserved in per-seed JSON for analyzer inspection (per-seed medians, per-seed Spearman ρ, per-seed heterogeneity diagnostics) but the per-cell test pools.
- **Wilcoxon, not paired t-test:** the per-context log-prob distribution from #395 has long left tail (p10=−45, max=−12 for `[ZLT]`; symmetric for `※` but not Gaussian). Wilcoxon is robust to that.
- **Holm-Bonferroni, not FDR/BH:** 9 per-cell tests is small enough that the FWER correction isn't over-conservative, and the per-cell direction question (is THIS cell rescued?) is a confirmatory test, not an exploratory screen.
- **1.0 nat effect-size floor (subject to σ_paired sensitivity):** equivalent to ~e^1.0 ≈ 2.7× the base-model probability. A smaller effect would be technically significant in a paired test but not meaningfully "rescued" if σ_paired ≈ 1 nat. **Caveat:** the 1.0-nat threshold assumes σ_paired ≈ 1 nat — Step B.1 measures σ_paired empirically; if σ_paired > 3 nats, the analyzer relaxes the threshold (e.g. Δ ≥ σ_paired) and reports observed σ alongside Δ. The v1.1 "10σ above noise" framing was uncited (likely optimistic from #395's within-persona std of ~5.6 nats overall) and is dropped in v1.2; the threshold becomes a sensitivity-analysis call when σ_paired is large.
- **Phase A on 1× H100 sequential, not 4× H100 parallel:** seed-wise parallel saves ~50 min wall at 4× cost. Per-pod-hour cost dominates.
- **Floor A (within-context) not Floor B (fresh-prompt-no-trigger):** the paired test only works when LP[cell] and LP_floor share the EXACT same 128 contexts (i.e. multi-turn-with-trigger context tuples for the rescue cells). A fresh-prompt-no-trigger floor (Floor B, what #395 measured) doesn't pair with multi-turn-with-trigger LP[cell] — it answers a different question ("how surprising is `※` to the bare model out of distribution?") rather than the rescue question ("did training elevate p(※) above what the bare model would predict in this exact multi-turn-with-trigger context?"). Marginal cost: ~3-5 min of base-model fwd passes (already in the budget).
- **Clone `eval_issue377.py` → `eval_issue399.py`, don't mutate:** preserves #377's Reproducibility block, prevents JSON-schema drift breaking downstream consumers.
- **Clone `c_issue377_marker_install.yaml` → `c_issue399_marker_install.yaml`, don't override:** `+condition.dataset_override` / `+condition.run_label` are not real Hydra fields on the condition schema. `runner.py` reads `condition.name` (line 72) and `condition.stages[0].dataset` (line 230) directly; dotted overrides on invented field names silently no-op. Clone the YAML to make the change actual.
