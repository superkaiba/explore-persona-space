# Plan — #1150: forward rc==0 task.py child stderr at the three remaining subprocess sites

### TDD: no

## Goal + acceptance criteria

Canonical Goal (task #1150 `## Goal` H2, verbatim, re-read at return time):
"Call the #1130 _forward_marker_child_stderr helper at the watcher's two
set-status subprocess sites and file_infra_task.py's `task.py new` child so
rc==0 stderr (the landing-check warning class) reaches wrapper transcripts."

`task.py` deliberately exits 0 while printing the deferred-commit ERROR and
the #1100 post-commit LANDING CHECK warning to stderr; a subprocess caller
using `capture_output=True` that discards rc==0 stderr silently loses that
signal. #1130 fixed this for the watcher's four post-marker children; three
mutating children still discard it.

Acceptance criteria (requirement form):

1. `autonomous_session_watch._set_status_blocked` forwards the child's
   stderr on its rc==0 success path via `_forward_marker_child_stderr`,
   with context `f"set-status blocked on #{issue}"`.
2. `autonomous_session_watch._repark_completed_followup_round` forwards the
   `set-status awaiting_promotion` child's stderr on its rc==0 success path,
   with context `f"set-status awaiting_promotion on #{issue}"`.
3. `file_infra_task.cmd_file_infra` forwards the `task.py new` child's
   stderr on its rc==0 success path, with context
   `"task.py new (file_infra_task)"`.
4. Control flow at all three sites is byte-equivalent otherwise: return
   values, rc!=0 handling, exception handling, and dry-run branches
   unchanged; the forward fires ONLY after the rc!=0 early-returns (rc!=0
   paths already print stderr detail in their WARNING — forwarding there
   would duplicate it).
5. Tests in `tests/test_marker_child_stderr_forwarding.py` cover all three
   sites; `uv run pytest tests/test_marker_child_stderr_forwarding.py`
   passes; ruff clean on both touched scripts.

## Method delta

Same helper, same placement discipline as #1130 — zero new mechanism. #1130
added `_forward_marker_child_stderr(res, context)` (watcher L5858) and called
it at 4 post-marker sites (L5904, L5953, L8524, L17761). This change adds the
identical one-line call at 3 more mutating `task.py` children: two `set-status`
sites in the watcher and the `task.py new` child in `file_infra_task.py`.
The only decision beyond #1130: `file_infra_task.py` imports the `_`-private
helper directly rather than duplicating a local forwarder — one line justifying
it: the file already imports `autonomous_session_watch` as its orchestration-
layer library (`infra_dispatch_has_free_slot`, L65) precisely so the dispatchers
"cannot drift apart" (its own comment), and a copied forwarder is exactly that
drift; ruff does not select SLF (pyproject `[tool.ruff.lint]` select list), and
the existing #1130 tests already access `asw._forward_marker_child_stderr`
cross-module.
