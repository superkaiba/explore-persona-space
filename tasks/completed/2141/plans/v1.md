#### D1 — Per-skip diagnostics in `subfloor_reclaim_pass` (`scripts/autonomous_session_watch.py:5652–5717`)

The pass has 4 silent decline paths today: kill switch (`:5673–5674`), `free is None` (`:5677–5678`), and `decide_subfloor_reclaim(...) is False` (`:5682–5683`), which splits into above-floor (`decide_subfloor_reclaim` `:5383–5384`) vs rate-limited (`:5387`). (The launch/state-save failure path `:5693–5698` is already loud but stays sidecar-less — unchanged; it is a fail-soft error, not a decline.)

**Emission scoping rule (the volume decision):** diagnostics are emitted ONLY in the band where a fire is EXPECTED but declined — `free < VM_DISK_SUBFLOOR_FREE_BYTES` — plus the free-unreadable case. Above-floor declines (the healthy no-op, ~144 ticks/day) emit NOTHING; that path stays byte-identical.

Per-reason channels:

| Decline reason | stderr line (dated daily log) | sidecar row (`.claude/cache/disk-guard-events.jsonl`) |
|---|---|---|
| `kill-switch` (below floor) | every declined tick | YES — throttled to ≤1 per `VM_DISK_SUBFLOOR_RECLAIM_INTERVAL_S` (1800 s) via a new `last_skip_row_ts` key merged into `vm-disk-subfloor-reclaim.json` |
| `rate-limited` (below floor, within interval) | every declined tick | NO — the fire row ≤1800 s old in the same sidecar is already the positive evidence; a per-tick row would add ~96 rows/day of "working as intended" noise during every below-floor episode (the 08-05 incident band: 39 fires + ~100 rate-limited ticks) |
| `free-unreadable` (`free is None`) | one line naming the predicate | NO — the band condition is unevaluable, `_vm_free_bytes` (`:16043`) already prints a loud per-tick warning upstream, and the production call site never reaches it (`vm_disk_pass` early-returns on `free is None` at `:33824–33825` before calling the pass at `:33832`) |

**Projected steady-state row/line rates (stated per the brief):** healthy (free ≥ 60 GiB): 0 new rows, 0 new lines. Below floor with the arm firing normally: 0 new sidecar rows; ≤ ~96 stderr lines/day into the dated log (the ~2 declined ticks between each 30-min fire, at 144 ticks/day). Kill-switched below floor (worst case): ~144 stderr lines/day + ≤48 sidecar rows/day — comparable to the incident's own fire-row traffic (66 rows over ~36 h), and self-terminating with the episode.

Restructured pass body (behavior-preserving reorder: `free` is read BEFORE the kill-switch check so the check can band-scope; in production `free_bytes` is always passed in from `vm_disk_pass`, so no extra probe occurs there):

```python
def subfloor_reclaim_pass(dry_run, free_bytes=None, now=None) -> bool:
    now = now if now is not None else time.time()
    free = free_bytes if free_bytes is not None else _root_disk_headroom()
    if free is None:
        print("  vm-disk subfloor-reclaim: skipped (free-unreadable) — statvfs "
              f"on {VM_DISK_PATH} failed upstream", file=sys.stderr)
        return False
    if os.environ.get("EPM_DISABLE_SUBFLOOR_RECLAIM", "").strip() == "1":
        if free < VM_DISK_SUBFLOOR_FREE_BYTES:
            _emit_subfloor_skip("kill-switch", free, now, dry_run,
                                detail="EPM_DISABLE_SUBFLOOR_RECLAIM=1")
        return False
    state = _load_subfloor_reclaim_state()
    last_run_ts = state.get("last_run_ts")
    last_run_ts = last_run_ts if isinstance(last_run_ts, int | float) else None
    if not decide_subfloor_reclaim(free, last_run_ts, now):
        if free < VM_DISK_SUBFLOOR_FREE_BYTES:  # rate-limited (above-floor stays silent)
            _emit_subfloor_skip("rate-limited", free, now, dry_run,
                                detail=f"next eligible at last_run_ts+{VM_DISK_SUBFLOOR_RECLAIM_INTERVAL_S:.0f}s")
        return False
    ...  # fire path unchanged except the D2 token fix
```

New module-level helper `_emit_subfloor_skip(reason, free, now, dry_run, *, detail)` (placed beside `_append_disk_guard_sidecar`):

- ALWAYS prints one stderr line: `vm-disk subfloor-reclaim: skipped ({reason}) — {free_gib:.1f} GiB free (< {floor:.0f} GiB); {detail}`.
- ONLY for `reason == "kill-switch"`: appends a sidecar row via the existing `_append_disk_guard_sidecar` (which already handles `dry_run` by printing `[dry-run] would append ...`, `:5543–5545`), throttled on `last_skip_row_ts` read from `_load_subfloor_reclaim_state()`; the state save is a MERGE — `_save_subfloor_reclaim_state({**state, "last_skip_row_ts": now})` — never a whole-payload overwrite (a bare `{"last_skip_row_ts": now}` would clobber `last_run_ts` and break rate limiting). State save gated on `not dry_run` and wrapped `try/except OSError` printing a fail-soft stderr line (preserves the "never crash `vm_disk_pass`" invariant; `_append_disk_guard_sidecar` is already fail-soft).

Read-only, no subprocess, no write — the #681 r3 dry-run contract ("zero `subprocess` calls and zero writes") is untouched.

#### D4 — UTC-consistent daily-log naming (`scripts/cron_autonomous_session_watch.sh:104–115`) — Option B (dual-name via symlink)

**Decision: keep the LOCAL-date write name; add a UTC-date symlink when the two names differ.** Rationale against the weighed facts: (i) all 11 cron wrappers write local-dated logs — a watcher-only UTC flip (option A) makes it the fleet's sole odd-one-out and silently breaks the documented local-form runbook greps (`logs/autonomous_session_watch/$(date +%F).log`); (ii) option A merely MOVES the 7h blind window from UTC readers to local readers (during local 17:00–23:59 a local-dated read would resolve yesterday's stale-but-existing file — a silent-stale miss, worse than the loud nonexistent-path miss); (iii) the actual defect is a UTC-dated read resolving a NONEXISTENT path — a forward symlink closes exactly that with zero change to write semantics, sibling consistency, `FIRST_RUN_OF_DAY`, or runbooks. The body explicitly allows "UTC date or symlink both forms". Caveat disclosed: the alias guarantees a UTC-dated name always resolves to the file receiving the CURRENT writes; it does not partition content by UTC day (the UTC 00:00–06:59 slice of a UTC day lives in the previous local-date file — inherent to one physical file per local day).

The wrapper runs under `set -uo pipefail` (`:85`, no `-e`); edits use `set -u`-safe `${VAR:-}` forms and `if/fi` (not bare `&&` chains) for clarity. Replacement for the `:104–115` block (comments abbreviated here; real edit carries full ones):

```sh
DATE=${EPM_WATCH_DATE_LOCAL_OVERRIDE:-$(date +%Y-%m-%d)}       # local — fleet convention (TEST-ONLY override)
DATE_UTC=${EPM_WATCH_DATE_UTC_OVERRIDE:-$(date -u +%Y-%m-%d)}  # UTC alias name (#2141; TEST-ONLY override)
LOG_DIR="${EPM_WATCH_LOG_DIR:-$PROJECT_DIR/logs/autonomous_session_watch}"
LOG_FILE="$LOG_DIR/$DATE.log"
UTC_LOG_FILE="$LOG_DIR/$DATE_UTC.log"

mkdir -p "$LOG_DIR"

# #2141: on the first run of a new local day, the local name may still be
# YESTERDAY's UTC alias (a symlink into yesterday's file) — remove a symlink
# (never a real file) so today's appends create a fresh real file.
if [ -L "$LOG_FILE" ]; then
    rm -f "$LOG_FILE"
fi

FIRST_RUN_OF_DAY=0
[ -f "$LOG_FILE" ] || FIRST_RUN_OF_DAY=1

# #2141: VM is UTC-7 — for 7h/day the UTC date is one ahead of the local
# date and a UTC-dated read used to hit a nonexistent path. Provide the UTC
# name as a RELATIVE symlink to the local file. Guards: never when the two
# names coincide (a self-link would clobber the real log), never over an
# existing REAL file (defensive), refresh an existing symlink with -n.
if [ "$UTC_LOG_FILE" != "$LOG_FILE" ]; then
    if [ -L "$UTC_LOG_FILE" ] || [ ! -e "$UTC_LOG_FILE" ]; then
        ln -sfn "$DATE.log" "$UTC_LOG_FILE"
    fi
fi
```

Ordering: the alias is created BEFORE the watcher run so a mid-run UTC-dated reader already resolves it. The relative target (`$DATE.log`, not an absolute path) keeps the alias valid under `EPM_WATCH_LOG_DIR` overrides and directory moves. Also update the header comment `:83` (`Output: logs/autonomous_session_watch/YYYY-MM-DD.log (one file per day)`) to name the alias behavior + the three TEST-ONLY envs.

**Embedded-shell exit-path trace (every failure arm):** `mkdir -p` failure → subsequent redirect fails, cron mail surfaces it (pre-existing behavior, unchanged). `rm -f` on the symlink cannot fail on a present symlink we own; if it somehow did (rc≠0), no `set -e` → execution continues and the append writes THROUGH the alias into yesterday's file for one day — degraded but lossless, self-heals next local day. `ln -sfn` failure (rc≠0, e.g. read-only FS) → alias absent, behavior degrades to today's status quo; no halt (no `set -e`), and the block sits OUTSIDE the `{ ... } >> "$LOG_FILE"` group so a failure cannot break the redirect. No arm uses a bare `false` or can halt a sibling block; final `exit 0` unchanged.

**Confirmed non-couplings (each verified, per the brief):** `scripts/autonomous_session_watch.py:13444` region — the `*.log` mtime-sorted glob at `:13443–13444` is `_auth_outage_evidence` over `~/.happy/logs/` (a DIFFERENT directory entirely; trivially naming-agnostic — and no code in the repo globs `logs/autonomous_session_watch/` at all: `grep -rn 'logs/autonomous_session_watch'` hits only the wrapper's own lines 83/105, so the new symlink cannot double-count in any consumer). `scripts/workflow_lint.py:18176` — that line is the `--check-poller-marker-consumers` help text (marker-kind consumers keyed on `posted_by` tokens; no log-naming coupling). `EPM_WATCH_LOG_DIR` override — preserved verbatim (`:105`); the alias lands in the same `$LOG_DIR`. `FIRST_RUN_OF_DAY` — the `-f` test runs AFTER the symlink cleanup, preserving its semantics on all three regimes (fresh day / same-day rerun / post-alias rollover); pinned by wrapper test T3/T5.
