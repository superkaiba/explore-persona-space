#### D1 — Per-skip diagnostics in `subfloor_reclaim_pass` (`scripts/autonomous_session_watch.py:5652–5717`)

The pass has 4 silent decline paths today: kill switch (`:5673–5674`), `free is None` (`:5677–5678`), and `decide_subfloor_reclaim(...) is False` (`:5682–5683`), which splits into above-floor (`decide_subfloor_reclaim` `:5383–5384`) vs rate-limited (`:5387`). (The launch/state-save failure path `:5693–5698` is already loud but stays sidecar-less — unchanged; it is a fail-soft error, not a decline.)

**Emission scoping rule (the volume decision):** diagnostics are emitted ONLY in the band where a fire is EXPECTED but declined — `free < VM_DISK_SUBFLOOR_FREE_BYTES` — plus the free-unreadable case. Above-floor declines (the healthy no-op, ~144 ticks/day) emit NOTHING; that path stays byte-identical.

Per-reason channels:

| Decline reason | stderr line (dated daily log) | sidecar row (`.claude/cache/disk-guard-events.jsonl`) |
|---|---|---|
| `kill-switch` (below floor) | every declined tick | YES — throttled to ≤1 per `VM_DISK_SUBFLOOR_RECLAIM_INTERVAL_S` (1800 s) via a new `last_skip_row_ts` key merged into `vm-disk-subfloor-reclaim.json` |
| `rate-limited` (below floor, within interval) | every declined tick, carrying the `age=` field (below) | NO — the fire row ≤1800 s old in the same sidecar is already the positive evidence; a per-tick row would add ~96 rows/day of "working as intended" noise during every below-floor episode (the 08-05 incident band: 39 fires + ~100 rate-limited ticks) |
| `free-unreadable` (`free is None`) | one line naming the predicate | NO — the band condition is unevaluable, `_vm_free_bytes` (`:16043`) already prints a loud per-tick warning upstream, and the production call site never reaches it (`vm_disk_pass` early-returns on `free is None` at `:33824–33825` before calling the pass at `:33832`) |

**Rate-limited detail carries the age (critic non-blocking #1):** the stderr detail is `f"age={now - last_run_ts:.0f}s of {VM_DISK_SUBFLOOR_RECLAIM_INTERVAL_S:.0f}s min interval"`. Rationale: the one rate-limited state where the "adjacent fire row is the evidence" rationale FAILS is a corrupt/FUTURE `last_run_ts` (decide returns False forever, no fire rows exist to point at) — a **negative `age=`** in the log is that wedge's signature, readable at a glance. Pinned by D6(a) test 4's assertion that the line contains `age=`.

**Projected steady-state row/line rates:** healthy (free ≥ 60 GiB): 0 new rows, 0 new lines. Below floor with the arm firing normally: 0 new sidecar rows; ≤ ~96 stderr lines/day into the dated log (the ~2 declined ticks between each 30-min fire, at 144 ticks/day). Kill-switched below floor (worst case): ~144 stderr lines/day + ≤48 sidecar rows/day — comparable to the incident's own fire-row traffic (66 rows over ~36 h), and self-terminating with the episode.

Restructured pass body (behavior-preserving reorder: `free` is read BEFORE the kill-switch check so the check can band-scope; in production `free_bytes` is always passed in from `vm_disk_pass`, so no extra probe occurs there):

```python
def subfloor_reclaim_pass(dry_run, free_bytes=None, now=None) -> bool:
    now = now if now is not None else time.time()
    free = free_bytes if free_bytes is not None else _root_disk_headroom()
    if free is None:
        print("  vm-disk subfloor-reclaim: skipped (free-unreadable) — statvfs "
              f"on {VM_DISK_PATH} failed upstream", file=sys.stderr)
        return False
    if os.environ.get("EPM_DISABLE_SUBFLOOR_RECLAIM", "").strip() == "1":
        if free < VM_DISK_SUBFLOOR_FREE_BYTES:
            _emit_subfloor_skip("kill-switch", free, now, dry_run,
                                detail="EPM_DISABLE_SUBFLOOR_RECLAIM=1")
        return False
    state = _load_subfloor_reclaim_state()
    last_run_ts = state.get("last_run_ts")
    last_run_ts = last_run_ts if isinstance(last_run_ts, int | float) else None
    if not decide_subfloor_reclaim(free, last_run_ts, now):
        if free < VM_DISK_SUBFLOOR_FREE_BYTES:  # rate-limited (above-floor stays silent)
            _emit_subfloor_skip(
                "rate-limited", free, now, dry_run,
                detail=f"age={now - last_run_ts:.0f}s of "
                       f"{VM_DISK_SUBFLOOR_RECLAIM_INTERVAL_S:.0f}s min interval")
        return False
    ...  # fire path unchanged except the D2 token fix
```

New module-level helper `_emit_subfloor_skip(reason, free, now, dry_run, *, detail)` (placed beside `_append_disk_guard_sidecar`):

- ALWAYS prints one stderr line: `vm-disk subfloor-reclaim: skipped ({reason}) — {free_gib:.1f} GiB free (< {floor:.0f} GiB); {detail}`.
- ONLY for `reason == "kill-switch"`: appends a sidecar row via the existing `_append_disk_guard_sidecar` (which already handles `dry_run` by printing `[dry-run] would append ...`, `:5543–5545`), throttled on `last_skip_row_ts` read from `_load_subfloor_reclaim_state()`; the state save is a MERGE — `_save_subfloor_reclaim_state({**state, "last_skip_row_ts": now})` — never a whole-payload overwrite (a bare `{"last_skip_row_ts": now}` would clobber `last_run_ts` and break rate limiting). @pytest.fixture(autouse=True)
def _sidecar_hermeticity_guard(request, monkeypatch, tmp_path):
    """#2141 hermeticity guard: no watcher-module test may append to the REAL
    .claude/cache/disk-guard-events.jsonl. All watcher sidecar writes route
    through _disk_guard_sidecar_path() (single call site: _append_disk_guard_
    sidecar, asw:5546); this guard redirects that resolver to tmp_path
    UNLESS the test has pinned PROJECT_ROOT itself (the watcher_roots
    convention in tests/test_vm_disk_subfloor_sentinel.py), in which case it
    delegates so root-pinned sidecar-content assertions keep working.
    Measured incident: 6,369 pytest-planted sentinel rows at free_gib 17.0
    in the real sidecar (#2141 Finding 1)."""
    watchers = _watcher_modules(request)
    if not watchers:
        return
    for asw in watchers:
        real_root = asw.PROJECT_ROOT
        real_fn = asw._disk_guard_sidecar_path

        def _guarded(asw=asw, real_root=real_root, real_fn=real_fn):
            if asw.PROJECT_ROOT == real_root:  # test did NOT pin the root
                return tmp_path / "disk-guard-events.jsonl"
            return real_fn()  # root pinned to tmp -> delegate (reads patched PROJECT_ROOT)

        monkeypatch.setattr(asw, "_disk_guard_sidecar_path", _guarded)

#### D4 — UTC-consistent daily-log naming (`scripts/cron_autonomous_session_watch.sh:104–115`) — Option B (dual-name via symlink) — carried forward unchanged (critic-approved)

**Decision: keep the LOCAL-date write name; add a UTC-date symlink when the two names differ.** Rationale against the weighed facts: (i) all 11 cron wrappers write local-dated logs — a watcher-only UTC flip (option A) makes it the fleet's sole odd-one-out and silently breaks the documented local-form runbook greps (`logs/autonomous_session_watch/$(date +%F).log`); (ii) option A merely MOVES the 7h blind window from UTC readers to local readers (during local 17:00–23:59 a local-dated read would resolve yesterday's stale-but-existing file — a silent-stale miss, worse than the loud nonexistent-path miss); (iii) the actual defect is a UTC-dated read resolving a NONEXISTENT path — a forward symlink closes exactly that with zero change to write semantics, sibling consistency, `FIRST_RUN_OF_DAY`, or runbooks. ### 11. Decision Rationale
