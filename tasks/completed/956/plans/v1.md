because there the DAEMON completed the spawn successfully (webhook arrived; only the client gave
up waiting) — the session is known-good. In the webhook-timeout-500 case the DAEMON ITSELF
declared the handshake failed: the child is in an unknown, possibly wedged state (the incident's
two children sat live-but-empty — no prompt ever fired in the observed window — despite the
child-side env seeding mechanism). Adopting and registering such a session risks the exact
#685-class "idle spawned-but-never-ran session" that `_verify_happy_patch_or_die` exists to
prevent, with the watcher then trusting a dead-weight registration. So this path takes
**STOP-then-RETRY**, not adoption (decision rationale §11.1). The match is also STRONGER than the
timeout path's heuristic: the 500 carries the exact PID, so we reap by exact `pid` match against
`/list` instead of directory + freshness windows.

## 4. Design

### 4.1 New module constants (near `SPAWN_SESSION_TIMEOUT_S`, line ~885)

```python
# The Happy daemon waits 15s for the spawned child's /session-started webhook,
# then resolves {"success": false, "error": "Session webhook timeout for PID <n>"}
# (regular path) / "... (tmux)" (tmux path) WITHOUT killing the child — the fork
# stays live and tracked (bundle index-q9G4ktSK.mjs lines 5346/5466; incident
# task #956, 2026-07-03: two consecutive 500s leaked two live-but-empty
# sessions, third attempt succeeded). On this shape post() reaps the
# half-spawned child, then retries ONCE after a backoff sized at 2x the
# daemon's 15s webhook window.
WEBHOOK_TIMEOUT_RE = re.compile(r"Session webhook timeout for PID (\d+)(?: \(tmux\))?")
WEBHOOK_TIMEOUT_MAX_RETRIES = 1
WEBHOOK_TIMEOUT_RETRY_BACKOFF_S = 30.0
# Bounded wait for a SIGTERMed / daemon-stopped child to die (~10s), the
# 20 x 0.5s shape _stop_fallback (#903) already uses.
REAP_PID_DEATH_POLL_TRIES = 20
REAP_PID_DEATH_POLL_INTERVAL_S = 0.5
```

(`re`, `os`, `signal`, `time` are already imported at module top — no new imports; avoids the
PostToolUse-ruff F401 re-add round.)

### 4.2 `post()` restructure (line 892)

Wrap the single attempt in a bounded loop; only the `/spawn-session` + webhook-timeout-shape
HTTPError takes the new leg. Everything else — non-matching HTTPError, TimeoutError reconcile,
URLError — is preserved with today's exact messages.

```python
def post(path: str, body: dict[str, Any]) -> dict[str, Any]:
    """... (existing docstring, plus:) On an HTTP error whose body matches the
    daemon's 'Session webhook timeout for PID <n>' shape (the daemon forked a
    child but its /session-started webhook missed the 15s window — the child
    stays ALIVE daemon-side), post() reaps the half-spawned child (daemon
    /stop-session when a late webhook already delivered a happySessionId;
    identity-checked SIGTERM otherwise) and retries once after
    WEBHOOK_TIMEOUT_RETRY_BACKOFF_S. A failed reap exits nonzero WITHOUT
    retrying — retrying over an unconfirmed leak could double-spawn (#956)."""
    url = f"http://127.0.0.1:{daemon_port()}{path}"
    payload = json.dumps(body).encode()
    timeout = SPAWN_SESSION_TIMEOUT_S if path == "/spawn-session" else DEFAULT_TIMEOUT_S
    max_attempts = 1 + (WEBHOOK_TIMEOUT_MAX_RETRIES if path == "/spawn-session" else 0)
    for attempt in range(1, max_attempts + 1):
        req = urllib.request.Request(
            url, data=payload, headers={"Content-Type": "application/json"}, method="POST"
        )
        spawn_started_at = time.time() if path == "/spawn-session" else None
        try:
            with urllib.request.urlopen(req, timeout=timeout) as resp:
                return json.loads(resp.read())
        except urllib.error.HTTPError as e:
            try:
                err_body = json.loads(e.read())
            except Exception:
                err_body = {"raw": str(e)}
            m = None
            if path == "/spawn-session":
                err_text = err_body.get("error", "") if isinstance(err_body, dict) else str(err_body)
                m = WEBHOOK_TIMEOUT_RE.search(err_text or "")
            if m is None:
                # UNCHANGED failure surface for every non-webhook-timeout error
                # and every non-/spawn-session route.
                sys.exit(f"Happy daemon {path} returned HTTP {e.code}: {err_body}")
            outcome = _reap_half_spawned_session(int(m.group(1)), body.get("directory"))
            print(
                f"  NOTE: /spawn-session webhook-timeout (HTTP {e.code}, attempt "
                f"{attempt}/{max_attempts}): {err_text!r}; reap: {outcome.detail}",
                file=sys.stderr,
            )
            if not outcome.reaped:
                sys.exit(
                    f"Happy daemon /spawn-session returned HTTP {e.code}: {err_body}. "
                    f"Could NOT confirm the half-spawned child (PID {m.group(1)}) was "
                    f"reaped ({outcome.detail}); NOT retrying (a retry over an "
                    f"unconfirmed leak could double-spawn). Clean up manually "
                    f"(spawn_session.py list / stop), then re-run."
                )
            if attempt >= max_attempts:
                sys.exit(
                    f"Happy daemon /spawn-session returned HTTP {e.code} (webhook "
                    f"timeout) {max_attempts} times; the half-spawned child was reaped "
                    f"each time (last: {outcome.detail}). The daemon looks loaded — "
                    f"retry later (no session leaked)."
                )
            print(
                f"  retrying /spawn-session in {WEBHOOK_TIMEOUT_RETRY_BACKOFF_S:.0f}s "
                f"(attempt {attempt + 1}/{max_attempts})...",
                file=sys.stderr,
            )
            time.sleep(WEBHOOK_TIMEOUT_RETRY_BACKOFF_S)
            continue
        except TimeoutError as e:
            # UNCHANGED (client-socket timeout -> adopt-or-fail reconcile);
            # spawn_started_at is per-attempt so a retry's timeout reconciles
            # against ITS OWN window.
            ...
        except urllib.error.URLError as e:
            sys.exit(f"Happy daemon {path} unreachable at 127.0.0.1: {e}")  # UNCHANGED
```

Notes: nested `post("/stop-session", ...)` calls from inside the reap are safe — different
`path`, `max_attempts == 1`, and `_stop_spawned_session` already converts `SystemExit` → `False`.

### 4.3 `_reap_half_spawned_session(pid, directory)` (new, placed after `_reconcile_spawn_after_timeout`)

```python
class _ReapOutcome(NamedTuple):
    reaped: bool   # True == confirmed no live half-spawned child remains
    detail: str    # human-readable outcome for the stderr NOTE / exit message


def _reap_half_spawned_session(pid: int, directory: str | None) -> _ReapOutcome:
    """Reap the child the daemon forked for a /spawn-session that failed with
    'Session webhook timeout for PID <pid>' (#956). The daemon does NOT kill
    that child; unreaped it becomes a live-but-empty unmapped session nothing
    cleans up for >=12h. Two legs:

    - LATE-WEBHOOK leg: the child appears in the daemon's /list WITH a
      happySessionId (its webhook arrived after the daemon's 15s window) ->
      stop via the daemon (/stop-session), confirm the pid dies.
    - NEVER-HANDSHAKEN leg: no happySessionId -> /stop-session cannot address
      it -> identity-checked SIGTERM by pid (the _stop_fallback #903 recipe:
      comm=='node' + happy-wrapper cmdline + not-the-daemon-pid, PLUS a
      /proc/<pid>/cwd == spawn-directory bind available here because the
      spawn request names its directory). Ambiguity always REFUSES the kill
      (reaped=False) -> the caller exits nonzero without retrying.

    Returns reaped=True only on a CONFIRMED-clear state (child dead, or was
    already gone while the daemon was provably reachable)."""
    import session_resolver  # lazy: session_resolver imports spawn_session at top level

    try:
        children = _live_children(strict=True)
    except RuntimeError as e:
        # Daemon /list unreachable: 'not in the list' would be indistinguishable
        # from 'already gone' -> refuse to certify the reap (blocks the retry).
        return _ReapOutcome(False, f"daemon /list unreachable while verifying PID {pid}: {e}")
    match = next((c for c in children if c.get("pid") == pid), None)
    sid = (match or {}).get("happySessionId")
    if isinstance(sid, str) and sid:
        if _stop_spawned_session(sid):
            if _await_pid_death(pid, session_resolver):
                return _ReapOutcome(True, f"stopped late-handshaken session {sid} via daemon")
            return _ReapOutcome(False, f"daemon ACKed stop of {sid} but PID {pid} survived ~10s")
        # Daemon refused the stop -> fall through to the SIGTERM leg.
    if not session_resolver._pid_alive(pid):
        return _ReapOutcome(True, f"child PID {pid} already exited on its own")
    # --- SIGTERM leg: stacked identity checks (never kill on ambiguity) ---
    comm = session_resolver._read_proc_comm(pid)
    if comm != "node":
        return _ReapOutcome(False, f"PID {pid} comm={comm!r} != 'node' (recycled?); refusing kill")
    cmdline = session_resolver._read_proc_cmdline(pid) or ""
    if "happy" not in cmdline:
        return _ReapOutcome(
            False, f"PID {pid} cmdline lacks the happy-wrapper signature; refusing kill"
        )
    daemon_pid = session_resolver._happy_daemon_pid()
    if daemon_pid is not None and pid == daemon_pid:
        return _ReapOutcome(False, f"PID {pid} is the Happy DAEMON pid; refusing kill")
    if directory:
        try:
            proc_cwd: str | None = os.readlink(f"/proc/{pid}/cwd")
        except OSError:
            proc_cwd = None  # unreadable cwd is not disqualifying; 3 checks above hold
        if proc_cwd is not None and proc_cwd != directory:
            return _ReapOutcome(
                False, f"PID {pid} cwd {proc_cwd!r} != spawn dir {directory!r}; refusing kill"
            )
    claude_pid = session_resolver.resolve_claude_pid(pid)  # best-effort, pre-kill
    os.kill(pid, signal.SIGTERM)
    if _await_pid_death(pid, session_resolver):
        survivor = ""
        if claude_pid is not None and session_resolver._pid_alive(claude_pid):
            survivor = (
                f" (WARNING: inner claude pid {claude_pid} still alive — verify/kill manually)"
            )
        return _ReapOutcome(True, f"SIGTERMed never-handshaken child PID {pid}{survivor}")
    return _ReapOutcome(False, f"SIGTERM sent to PID {pid} but it survived ~10s")


def _await_pid_death(pid: int, session_resolver) -> bool:
    """~10s bounded death poll (20 x 0.5s), the _stop_fallback (#903) shape.
    session_resolver._pid_alive is the ONE liveness seam (tests monkeypatch
    it + time.sleep)."""
    for _ in range(REAP_PID_DEATH_POLL_TRIES):
        time.sleep(REAP_PID_DEATH_POLL_INTERVAL_S)
        if not session_resolver._pid_alive(pid):
            return True
    return False
```

Design choices baked in: the daemon's exit-handler (`happyProcess.on("exit")` →
`onChildExited(pid)`, bundle line 5447) untracks the child once the pid dies, so a SIGTERM reap
leaves no stale daemon state. A single `/list` read (no sid-wait loop) decides the leg — SIGTERM
is equally clean and bounds reap latency (§11.5).

### 4.6 Secondary scope — `autonomous_session_watch.py` fast-path: DESCOPED (with reason)

The body offered an optional watcher fast-path (reap zero-transcript unmapped sessions younger
than 12 h). Descoped because: (a) `spawn_session.py` is the ONLY production `/spawn-session`
POSTer (§3 grep), so the primary fix makes this leak class unreachable at its sole source;
(b) the sole residual window — the spawn helper itself dying between the daemon fork and the
reap — is the same pre-existing exposure the TimeoutError path already has, is rare
(process-kill within a ~75 s window), and the watcher's existing ≥12 h idle-unmapped pass remains
the generic backstop; (c) the watcher is 16.8 K lines and safe idle-reaping of YOUNG unmapped
sessions needs its own design review (a human's fresh interactive session is also "young +
unmapped" until registered — an aggressive fast-path risks killing legitimate sessions), which
would more than double this fix's review surface for a defense-in-depth of a closed class. If the
class recurs from another source, that is a new candidate on `autonomous_session_watch.py`.

## 11. Decision Rationale (load-bearing design constants)

1. **STOP-then-RETRY, not adoption.**
   *What:* the new leg never adopts/registers the half-spawned session.
   *Why:* unlike the client-socket-timeout case (daemon succeeded; adoption safe), here the
   daemon itself declared the handshake failed; the incident's two children sat live-but-EMPTY —
   registering one risks a #685-class idle driver the watcher then trusts. The prompt seeding is
   child-side env (bundle line 2625), so it *may* eventually fire — "may" is exactly the
   ambiguity a crash-recovery registration must not be built on.
   *Source:* task #956 body (observed live-but-empty sessions); bundle lines 5466/2625;
   `_verify_happy_patch_or_die` docstring (the idle-session failure class).
   *Alternatives:* poll for the late webhook and adopt on arrival — rejected: unbounded health
   ambiguity, and a fresh spawn after reap is deterministic and cheap.
2. **`WEBHOOK_TIMEOUT_MAX_RETRIES = 1`.**
   *What/Why:* one retry converts the observed transient into success without hammering a loaded
   daemon; the watcher passes (`proposed_infra_sweep`, capacity-retry, crash-recovery) re-drive
   later if the retry also fails.
   *Source:* task #956 body ("retry the spawn once with backoff"; incident: failure ×2 then
   success — a single retry would have succeeded on the second attempt of each invocation).
3. **`WEBHOOK_TIMEOUT_RETRY_BACKOFF_S = 30.0`.**
   *What/Why:* 2× the daemon's 15 s webhook window (bundle `15e3`, lines 5348/5468), giving a
   loaded daemon a full drain window; same order as `SPAWN_SESSION_TIMEOUT_S = 60` (#524
   rationale comment). Worst-case added wall ≈ 100 s ≪ `DISPATCH_LEASE_TTL_S` = 900 s, so the
   retry stays inside the held #843 lease.
   *Source:* daemon bundle; `spawn_session.py` lines 107, 873–885.
4. **PID-match regex `r"Session webhook timeout for PID (\d+)(?: \(tmux\))?"`.**
   *What/Why:* exact literals of the two daemon emission sites; the optional ` (tmux)` suffix
   covers the tmux spawn path (the incident hit the regular path — no suffix).
   *Source:* bundle lines 5346 + 5466; incident string verbatim in the #956 body.
5. **Single `/list` read to pick the leg (no sid-wait loop).**
   *What/Why:* waiting for a late webhook only upgrades SIGTERM→daemon-stop cosmetically; the
   SIGTERM leg is equally clean (the daemon's `on("exit")` → `onChildExited` untracks the pid,
   bundle line 5447) and a single read bounds reap latency.
   *Alternatives:* poll ≤20 s for the sid — rejected (latency for no safety gain).
6. **Additive SIGTERM leg mirroring `_stop_fallback` instead of refactoring it.**
   *What/Why:* `_stop_fallback`'s exact refusal messages are behavior existing tests/operators
   rely on (#903 round-1 critique history); ~25 duplicated-but-documented lines beat a shared
   helper that risks regressing a tested path. The `os.kill` (not `killpg`) + claude-survivor
   warning follows the tested precedent verbatim.
   *Source:* `spawn_session.py` lines 2113–2195 (#903); `.claude/rules/crash-fix-rounds.md`
   kill-ownership discipline (never kill on ambiguity).
   *Alternatives:* `os.killpg` (the child is `detached: true`, a group leader) would take the
   inner claude too — rejected for consistency with the tested precedent; the survivor warning
   covers the gap.
7. **`/proc/<pid>/cwd == directory` as a fourth identity check.**
   *What/Why:* available here (the failed request names its spawn directory) and stronger than
   the #903 trio alone against PID recycling; unreadable cwd does not disqualify (the three
   precedent checks still hold) but a MISMATCH always refuses.
   *Source:* bundle `spawnHappyCLI` (cwd = spawn directory, lines 3988–3992);
   `crash-fix-rounds.md` discriminator pattern (cwd + lstart).
8. **Strict `/list` for the already-gone verdict.**
   *What/Why:* lenient `_live_children()` returns `[]` on a daemon hiccup — indistinguishable
   from "child gone", and a false "gone" would green-light a retry over a live leak. Strict mode
   raises; the reap then reports not-reaped and the caller exits without retrying (fail fast).
   *Source:* `_live_children` body (line 1017 swallow list); the body's fail-fast constraint.
