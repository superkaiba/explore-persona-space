**The one load-bearing decision — `merge=union` vs alternatives:**

- **`merge=union` (CHOSEN).** Source: `.gitattributes` L18–19 (#787) + L30 (#896) — the in-repo precedent for exactly this conflict class, including #896's empirical rebase probe at git 2.34.1 (this VM's current version); gitattributes man page (union is a BUILT-IN low-level merge driver — no per-clone config, propagates with the file itself).
- **Custom merge driver** (rejected): user-defined drivers require `.git/config` registration in EVERY clone/worktree — does not propagate via the committed file; the fleet has dozens of worktrees. Source: gitattributes man page ("Defining a custom merge driver").
- **`-merge` / binary treatment** (rejected): unsetting `merge` forces a take-one-side binary-style conflict — strictly worse for an append log.
- **Do nothing** (rejected): `sync_repo_root.py`'s scratch-tree recipe already recovers manually, but the conflict class recurs (#1525) and burns session rounds each time; a one-line committed attribute removes the class at zero maintenance cost.
