### 3.2 Pure predicate — `decide_unfolded_round_flag`

Signature (pure — no I/O, no subprocess, no git):

```python
def decide_unfolded_round_flag(
    body_text: str,
    now: float,
    fs_probe: Callable[[str], bool],     # script/eval_results path exists on main
    git_probe: Callable[[str], bool],    # commit sha resolves + is ancestor of main
    body_names_result: Callable[[str], bool],  # body carries a result line for name
) -> list[UnfoldedFinding]
```

`UnfoldedFinding` = `TypedDict` with fields `{"phrase": str, "artifact": str, "artifact_kind": str, "line_ix": int}` where `artifact_kind ∈ {"script", "commit", "eval_path"}`.

**Algorithm:**

1. Case-insensitive scan for any `UNFOLDED_PHRASES` phrase (module constant, tier-1 explicit; see §3.3). For each hit, capture the LINE it lives on (`.splitlines()`, 0-indexed).
2. On the SAME line ± `PHRASE_WINDOW_LINES` (default 2 lines each side), extract every candidate artifact NAME via three narrow regexes tried in order:
   - `script`: `r"\bscripts/([A-Za-z0-9_./-]+\.py)\b"`
   - `commit`: `r"\b(?:@|commit\s+)?([0-9a-f]{7,40})\b"` (bounded 7–40 hex — matches short SHAs and full SHAs; guards below verify shape)
   - `eval_path`: `r"\b(eval_results/issue_[0-9]+(?:_[A-Za-z0-9_-]+)?/[A-Za-z0-9_./-]+)"`
3. For each captured (phrase, artifact, kind) triple:
   - **fs / git probe** — closure-provided. `script` → `fs_probe(artifact)`; `commit` → `git_probe(artifact)`; `eval_path` → `fs_probe(artifact)`.
   - **body-carries-no-result check** — closure-provided. `body_names_result(artifact)` scans the body for evidence the artifact IS folded (see §3.4).
4. FLAG only when (probe returns True) AND (`body_names_result` returns False). Everything else — probe False (not landed), or probe True + body names result (landed and folded) — is silent by construction.

**Purity:** the driver populates the three closures with real subprocess/fs calls; the pure predicate is testable with `dict.get`-shaped fakes.

### 3.3 Trigger phrases (v1) — `UNFOLDED_PHRASES`

A module constant tuple; case-insensitive substring match on each body line. Grounded on the #1639 body's actual wording (measured at plan time: all four are literally present in `tasks/awaiting_promotion/1639/body.md`):

| Phrase | Justification |
|---|---|
| `"folds here on landing"` | #1639 uses it verbatim ("folds into this body on landing" superset — see next); Source: #1639 body §Goal + §Reproducibility Context. |
| `"folds into this body on landing"` | #1639 §Reproducibility `**Context:**` row verbatim; `"folds here on landing"` is a substring. Both included so a body using either wording is caught. |
| `"is running as a follow-up round"` | #1639 §Goal verbatim. Common phrasing for a pending fold when the follow-up hasn't yet completed. |
| `"running at write time"` | #1639 §Reproducibility verbatim. Signals a pending fold from a round already in flight. |
| `"will fold here"` | Common forward-looking variant not in #1639 but idiomatic; adds coverage for future bodies. |
| `"pending fold"` / `"pending analysis fold"` | Cheap forward coverage; the sibling completed-unmerged rule uses similar shorthand. |

All lowercased at compile time; matching lowercases the body line. The list is a MODULE CONSTANT (not env-tunable) so extensions are localized and version-controlled; extending requires a code change. Widening precedent (root_draft_pass named-extension trigger): if a future incident shows the list missed the fold cue, add the phrase in a follow-up.

### 3.4 Artifact-existence probes on `main`

Driver-side (called only when `dry_run=False`, and cached per tick to bound worst case; a body citing five artifacts triggers five probes at most). All probes are BOUNDED, READ-ONLY, and FAIL-OPEN — any subprocess error, timeout, or missing tool → the artifact is treated as "not resolvable on main", i.e. it is NOT flagged. No `git fetch`.

- **script probe** — `git --no-optional-locks cat-file -e main:<path>` (rc==0 ⇒ exists on main); 5s timeout. Alternative form (mounted-checkout): `(PROJECT_ROOT / path).exists()` gated on "the working tree is at main" — SIMPLER: use the git form, which does not depend on the tree's checkout state (and the repo-root guard rules already keep it on main). Only file paths matching `scripts/**/*.py` are probed.
- **commit probe** — `git --no-optional-locks rev-parse --verify --quiet <sha>^{commit}` (rc==0) AND `git --no-optional-locks merge-base --is-ancestor <sha> main` (rc==0). Both required — a valid sha alone does not prove it's on main; the ancestor probe is the load-bearing one. 5s timeout each. A short-sha ambiguity resolution failure is fail-open.
- **eval_path probe** — `git --no-optional-locks cat-file -e main:<path>` for the exact `eval_results/issue_<N>/...` path. Since v4 bodies commit `eval_results/` to `main` (per SPEC.md + upload policy), an on-main hit is authoritative "the JSON that would have been the result exists".

Each probe result is memoized in a per-tick dict, so a body citing the same script twice pays for one probe.

### 3.5 Body-carries-no-result check — `body_names_result`

Given the raw body text and an artifact name, return True if ANY of these hold (evidence the artifact IS folded), False otherwise:

1. **`**Repro:**` code list mention** — the artifact's basename (for a script, `Path(artifact).name`; for a commit, the sha itself; for an eval_path, the full string) appears on any line inside the `**Repro:**` code list section (extracted by finding `**Repro:**` and reading until the next `**Context:**` or end of body).
2. **`## Results` / `## Findings` mention** — the artifact string appears anywhere inside the `## Results` H2 (v4 body) or `## Findings` H2 (v3 body). Extract by locating the H2 line and reading until the next `## ` H2 or end of body.
3. **Repro pinning line** — for a commit sha, any line matching `r"@[0-9a-f]{7,40}\b"` where the sha shares a common prefix ≥ 7 chars with the queried sha AND appears inside `**Repro:**`.

If none of (1)/(2)/(3) match, the artifact is presumed UNFOLDED and gets flagged.

**Not required to be perfect** — this is the false-positive dial. A body that mentions the artifact in the wrong section still evades this check (fires a false positive); the human reviewer sees it, dismisses it, the re-alert TTL prevents daily push spam. Erring toward false positive is the deliberate posture for a v1 escalation observer (per the body: "prefer starting narrow and widening on measured misses").

### 3.6 Sweep scope + freshness gate

Reuse `_triage_observer_sweep_issue(id_str, meta, reg_root, now, lookback_s)` verbatim — same helper the verdict-disagree observer uses. Its status set is `_TRIAGE_OBSERVER_STATUSES = ACTIVE | {awaiting_promotion, blocked}`; **filter it further** to `{awaiting_promotion, reviewing}` inside `unfolded_round_pass` after the helper returns (the body's scope). Rationale: `_TRIAGE_OBSERVER_STATUSES` is a module-private constant; we don't repurpose it. A one-line status check `if _task_status(issue) not in {"awaiting_promotion", "reviewing"}` after the helper's positive read tightens the scope without touching the shared constant.

**Alternative considered + rejected:** define a separate `_UNFOLDED_ROUND_STATUSES` set and re-implement the sweep. Rejected: violates the in-repo reuse rule; the helper's events.jsonl-mtime freshness gate is exactly right and re-deriving it is bug bait.

**Freshness gate:** `EPM_UNFOLDED_ROUND_LOOKBACK_H`, default `336.0` (14 days).

- Why 14 days: #1639 sat 2 days before human detection — the FLOOR must be ≥ ~72h. 14 days covers a long weekend + a week of un-monitored parking (a common pattern for a park across a mentor break). Beyond 14 days, a body carrying a stale pending phrase is presumed truly abandoned (the /daily and /weekly sweeps own that class).
- Source: sibling `COMPLETED_UNMERGED_LOOKBACK_H = 72.0` (3 days, the completed-task class); I extend to 14d because a promoted clean-result can park longer than a stranded merge. `VERDICT_DISAGREE_LOOKBACK_H = 48.0` is the shortest sibling — too short here.

### 3.7 Channels — sidecar + digest push, NO task marker

Follow the `root_draft_pass` + `verdict_disagree_pass` channel shape:

- **Sidecar:** `.claude/cache/unfolded-round-events.jsonl` — one JSON line per new finding per tick (fields: `ts`, `kind="unfolded-round"`, `issue`, `artifact`, `artifact_kind`, `phrase`, `line_ix`, `age_hours` of events.jsonl mtime, `task_status`).
- **Push:** ONE `_telegram_push` digest per tick listing the fires, capped at `EPM_UNFOLDED_ROUND_PUSH_CAP = 5` INDIVIDUAL push lines, with rollover-summary push semantics from `triage_observer_pass`: over-cap fires are permanently sidecar-recorded and appear as a single "+N more, see sidecar" summary push line at the end of the tick. Bodies commonly cite ≤2 artifacts per pending phrase; the cap is safety net, not a routine gate.
- **NO task marker.** Deliberate: an unfolded round is a human-consumer signal (the mentor / the promotion decision). Posting on the task's events.jsonl would (a) touch the stream the next `/issue N` resume session reads at Step 0 (noise), (b) risk resetting the anti-liveness clocks the sibling observers depend on, (c) violate the body's "must never `set-body`, never change status, never promote" (the constraint reads narrow but the intent is broad).

### 3.8 Dedup + re-alert cadence

State singleton `~/.eps-autonomous/unfolded-round-observer.json`, schema:

```json
{
  "<issue>": {
    "fired": {
      "<artifact-key>": {"last_alert_ts": <float>, "phrase": "<str>"}
    }
  }
}
```

where `<artifact-key> = f"{artifact_kind}::{artifact}"` (per-artifact fire-once). Per-(issue, artifact) fire-once with re-alert TTL `EPM_UNFOLDED_ROUND_REALERT_HOURS` (default 168.0 = 7d — same as the registry-drift TTL for persistent conditions). Re-alert TTL rationale: unlike the fleet-poisoning root-draft (24h), an unfolded round poisons only ONE task's promotion signal — weekly is enough while still preventing indefinite silence.

**GC:** when the task leaves `{"awaiting_promotion", "reviewing"}` (folded → user promoted → `completed`; abandoned → user archived → `archived`; back to `interpreting` → `reviewing`), prune its entire entry from the state file. Matches the verdict-disagree observer's self-prune loop.

**Corrupt-state posture:** `isinstance` guards on every field read-back; a garbled entry degrades to "fire as if unalerted" (root-draft precedent). State load returns `{}` on missing/malformed file.

### 3.9 Throttle-first attempt stamping

The body doesn't explicitly require this, but the sibling `registry_drift_pass` shows the pattern: save the attempt stamp BEFORE collecting so a crashing evaluation is bounded to one error sidecar row per interval. Since this pass runs every 10-min tick (not daily like registry-drift), the throttle is INSTEAD keyed by `EPM_UNFOLDED_ROUND_INTERVAL_HOURS` (default 1.0 — hourly, matching `completed_unmerged_pass`). Cheaper cadence than the sibling `root_draft_pass` (every tick) because probes can subprocess-out to git, so hourly bounds the worst case; sub-hour recurrence provides no operational value (the observer's user is a human seeing the alert at most every few hours).

State stores `"last_run_ts"` at pass entry; the pass short-circuits (with a stderr `throttled — silent` line) when `now - last_run_ts < interval_h * 3600`. Attempt stamp saved BEFORE the sweep — a crashing tick is bounded to one error sidecar row per interval.

### 3.11 NEVER-mutate invariant (hard)

The pass NEVER calls:

- `task.py set-body`, `set-status`, `add-tag`, `remove-tag`, `promote`, `post-marker`, `set-title`, `set-clean-result`.
- Any `git` write (no `commit`, `push`, `rm`, `checkout`, `reset`, `merge`) — the git usage is READ-ONLY (`cat-file`, `rev-parse`, `merge-base`, all with `--no-optional-locks` to never take the shared root's index lock).
- Any body mutation.

**Writes it DOES perform:**

- State singleton at `~/.eps-autonomous/unfolded-round-observer.json` (atomic tmp+rename).
- Sidecar append at `.claude/cache/unfolded-round-events.jsonl`.
- Stderr/stdout log lines.
- `_telegram_push` fail-soft.

The NEVER-mutate invariant is pinned by a subprocess-level test (§4 T3).

### 3.12 Fail-open everywhere

Following every sibling, every code path fails toward SILENCE (never flag) on any unexpected condition:

- Body read fails → skip the task, no sidecar row, no push.
- Regex captures a candidate that doesn't parse → skip that candidate.
- fs/git probe times out / rc != 0 / OSError → treat as "not resolvable on main" (don't flag).
- `body_names_result` raises → treat as True (assume the body has the result — silent).
- State load fails / corrupt → treat as empty (fire as if unalerted).
- Top-level exception → print stderr `unfolded-round: pass failed (fail-soft): <exc>` and return False. Root-draft precedent.

## 9. §11 Decision Rationale — load-bearing constants

Every module-level constant with an env override, per the planner convention. `kind: infra` — no training hyperparameters; these are the observer's tuning knobs.

- **`UNFOLDED_PHRASES = ("folds here on landing", "folds into this body on landing", "is running as a follow-up round", "running at write time", "will fold here", "pending fold")`**
  - **What:** the case-insensitive substring list keying the narrow predicate.
  - **Why:** small, precise, grounded in real #1639 body wording.
  - **Source:** `tasks/awaiting_promotion/1639/body.md` (measured at plan time — the first four appear verbatim); the final two are cheap forward coverage.
  - **Alternatives:** BROAD `**Context:**` parse (deferred per body); pure regex over all follow-up cues (too noisy).

- **`EPM_UNFOLDED_ROUND_LOOKBACK_H = 336.0` (14 days)**
  - **What:** max events.jsonl mtime age for the sweep to consider a task.
  - **Why:** #1639 sat 2 days; 14 days covers a long weekend + a week of un-monitored parking. Beyond this window the /daily and /weekly sweeps own the class.
  - **Source:** sibling `COMPLETED_UNMERGED_LOOKBACK_H = 72.0` (too short — completed-task class); `VERDICT_DISAGREE_LOOKBACK_H = 48.0` (too short); scaled to a park class that can legitimately span mentor breaks. Ungrounded on its exact magnitude — mark `ungrounded — measured extension of the sibling lookback shape`.

- **`EPM_UNFOLDED_ROUND_INTERVAL_HOURS = 1.0`**
  - **What:** self-gated hourly throttle.
  - **Why:** hourly is right for a class where the user-visible cadence is a mentor's review cycle (hours to days), and probes can subprocess-out to git — 6× cheaper than every-tick.
  - **Source:** `COMPLETED_UNMERGED_INTERVAL_HOURS = 1.0` (task #1564 rationale identical: "worst-case detection = grace + interval ≈ 3h vs the multi-day incident; every-tick is 6× the cost for <=50 min better latency"). **Source: #1564.**

- **`EPM_UNFOLDED_ROUND_REALERT_HOURS = 168.0` (7 days)**
  - **What:** per-(issue, artifact) push re-alert TTL.
  - **Why:** unlike the fleet-poisoning root-draft (24h), an unfolded round poisons ONE task's promotion signal. Weekly re-surface is enough while avoiding indefinite silence.
  - **Source:** sibling `REGISTRY_DRIFT_REALERT_HOURS = 168.0` (persistent-condition class); registry-drift's rationale: "persistent drift stays visible without daily push spam." Same shape. **Source: #1439.**

- **`EPM_UNFOLDED_ROUND_PUSH_CAP = 5`**
  - **What:** max individual push lines per tick; over-cap fires become one "+N more, see sidecar" summary push.
  - **Why:** bodies commonly cite ≤2 pending artifacts; the cap is a safety net.
  - **Source:** sibling `EPM_TRIAGE_OBSERVER_PUSH_CAP = 5` (line 5610 in the code). **Source: #967.**

- **`PHRASE_WINDOW_LINES = 2`**
  - **What:** number of lines above/below a phrase-match line to scan for artifact names.
  - **Why:** empirically, a phrase like "folds here on landing" and the artifact name typically land in the same sentence / paragraph; a 5-line window (2 above + hit line + 2 below) covers wrapping without inhaling too much unrelated text.
  - **Source:** `ungrounded — narrow-net default; widen on measured misses` (per body rationale).
