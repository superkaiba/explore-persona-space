## 0.0 TL;DR (plain English)

- **What I'll build:** one small stdlib-only script, `scripts/plan_patch.py`, that applies an anchor-based edit to a plan file the way sessions keep hand-writing throwaway scripts to do — except it tolerates whitespace/line-wrap/case drift in the anchor, refuses to touch the file unless the anchor resolves to exactly one place, and on failure prints a diff against the closest matching region so the next attempt needs no guesswork. Plus one pointer sentence in each of the two plan-revision recipes and a test file that pins all of it.
- **What I expect:** plan-revision rounds stop losing a turn to "anchor not found" — the ≥4 first-attempt anchor misses across 3 sessions on 2026-07-22 (#1604, #1609, #1415) were all whitespace/wrap/case drift, exactly the class the normalized matcher absorbs, and the nearest-match diff turns the remaining genuine misses into one-shot fixes.
- **What would change my mind:** if the normalized matcher ever resolves an anchor to the wrong (but unique) region — that's why the helper always prints the applied diff as positive evidence, keeps the recipes' separate verify step mandatory, and offers `--dry-run`; if that failure mode shows up in practice, the fallback stages get tightened or gated behind a flag.

## 4. Design

### 4.1 New file: `scripts/plan_patch.py` (~250–300 lines, stdlib only)

**Why code, not a model call:** deterministic text patching with byte-exact spans and fail-loud semantics is exactly what code does and a model call cannot guarantee (and the callers are themselves LLM sessions — the helper exists to remove improvised nondeterminism, not add more).

**CLI signature:**

```
uv run python scripts/plan_patch.py <file> \
  (--anchor TEXT | --anchor-file PATH) \
  (--replace TEXT | --replace-file PATH \
   | --insert-after TEXT | --insert-after-file PATH \
   | --insert-before TEXT | --insert-before-file PATH) \
  [--verify-contains TEXT]... [--dry-run]
```

- `<file>`: the draft to patch (typically `/tmp/issue-<N>-plan-v<K>-<ts>.md`); read/written UTF-8 with `newline=""` on both sides so CRLF/LF bytes outside the patched span are preserved exactly; `UnicodeDecodeError` → fail loud exit 2 ("not UTF-8 text").
- Anchor + payload each accept an inline form (short strings) and a `-file` form (multi-line markdown; the `-file` form is the RECOMMENDED path in the recipes — shell-quoting fragility of multi-line payloads is part of the incident class). Payload files are read verbatim (no normalization ever applied to the payload). Exactly one payload mode (argparse mutually exclusive group, `required=True`). Deleting text = `--replace ''` (empty payload is legal for replace, illegal for insert modes).
- `--verify-contains TEXT` (repeatable): asserted against the NEW text in memory BEFORE any write; failure → exit 2, file untouched.
- `--dry-run`: resolve + print the would-be unified diff, write nothing, exit 0 on a resolvable unique match (2/3 on the usual failure/already-applied paths) — the cheap pre-flight for a nervous round.
- Deliberate NON-goals (kept out to hold the unique-match semantics simple): no `--expect-count N` multi-occurrence mode, no regex anchors, no in-place multi-file mode, no fuzzy-apply flag of any kind.

**Exit codes** (printed message prefixes make grep-able evidence):
- `0` — applied (or clean `--dry-run`); stdout: `PLAN-PATCH APPLIED (<stage> match at lines <A>-<B> of <file>)` + the unified diff old→new (the positive evidence the Edit-success gate's verify step can additionally grep).
- `2` — failure, file untouched: missing anchor (with nearest-match report), ambiguous anchor (all candidate line numbers + first-line excerpts), no-op replacement (`PLAN-PATCH FAILED: EDIT NO-OP — replacement equals existing text`, the #1565 shape), `--verify-contains` miss, usage/encoding errors. Stderr prefix: `PLAN-PATCH FAILED:`.
- `3` — already-applied (insert modes only: the exact payload block already sits at the insertion point; message `PLAN-PATCH ALREADY-APPLIED — no change made`, file untouched). Distinct from 2 so an idempotent re-run after a crash is distinguishable from a real failure.

**Matching semantics (the core; pseudocode):**

```python
def normalize_with_map(text: str, *, lower: bool) -> tuple[str, list[int]]:
    """Collapse every maximal whitespace run (incl. \n, \r, \t) to ONE space;
    optionally per-char lower() (chars whose lower() is not length-1 are kept
    as-is, so the index map stays 1:1). Returns (normalized, idx_map) where
    idx_map[i] = index in the ORIGINAL text of normalized char i (a run maps
    to its first original char)."""

def find_candidates(file_text, anchor) -> tuple[str, list[tuple[int, int]]]:
    # Stage 1 "exact": non-overlapping str.find scan of the raw anchor
    #   (only a lone trailing newline of the anchor payload is tolerated via
    #   rstrip("\n") comparison fallback — anchor files usually end in \n).
    # Stage 2 "ws-normalized": normalize file AND anchor (lower=False; anchor
    #   additionally .strip()ped after collapsing); substring scan on the
    #   normalized text; each hit mapped back to an original span
    #   [idx_map[s], idx_map[e-1] + 1)  (first/last anchor chars are
    #   non-space post-strip, so the mapped span is tight).
    # Stage 3 "ws+case-normalized": same with lower=True on both sides.
    # Walk stages IN ORDER; at the FIRST stage with >=1 candidate:
    #   exactly 1 -> return (stage, [span]); >=2 -> raise Ambiguous(stage,
    #   spans)  — never fall through to a looser stage on ambiguity (looser
    #   stages are supersets; falling through can only add candidates).
    # All three stages 0 -> raise Missing.

def nearest_match_report(file_text, anchor) -> str:
    # Line-window scan: split file into lines; window height = anchor's line
    # count; slide stride 1; score SequenceMatcher(None, norm(window),
    # norm(anchor)).ratio() with quick_ratio prefilter; report the best
    # window: its 1-based line range, its ratio, and a unified diff
    # (difflib.unified_diff) labeled '--- anchor (as given)' /
    # '+++ closest match in file (lines A-B)' over the ORIGINAL (unnormalized)
    # texts, so the whitespace/case drift is visible character-for-character.
    # Always reports the best candidate (no cutoff gate — this is a report,
    # never an auto-apply). File-size guard: refuse files > 10 MB (plans are
    # 50-300 KB; O(n_lines * anchor_len) stays trivially fast).

def apply(file_text, mode, span, payload) -> str:
    # --replace: splice payload verbatim over the ORIGINAL span [start, end).
    # --insert-after / --insert-before: LINE-based — locate the line
    #   containing span end (after) / span start (before); insert the payload
    #   as full lines adjacent to that line (payload gets a trailing "\n"
    #   appended if missing). Idempotency probe first: if the exact payload
    #   block already occupies the insertion point -> AlreadyApplied (exit 3).
    # No-op guard (all modes): new_text == file_text -> NoOp (exit 2).

def main(argv=None) -> int:
    # parse -> read file -> resolve candidates -> apply in memory ->
    # run --verify-contains asserts on the NEW text -> print unified diff +
    # APPLIED line -> atomic write (tempfile in the same directory +
    # os.replace) unless --dry-run.
```

Line-based insertion (rather than byte-adjacent splicing) is the deliberate default for the insert modes because the observed improvised scripts all insert whole lines/sentences into wrapped markdown, and "forgot the leading `\n`" is a byte-splice foot-gun; `--replace` stays byte-exact over the matched span for surgical rewording.

**Composition with the Edit-success gate (unchanged gate, new edit step).** The helper IS the edit step only. It never calls `task.py new-plan-version`, never touches `tasks/`, and the recipes keep their separate verify + persist steps `&&`-chained after it:

```bash
uv run python scripts/plan_patch.py "$DRAFT" --anchor-file /tmp/a.txt --replace-file /tmp/r.txt \
  && grep -qF '<distinctive new text>' "$DRAFT" \
  && uv run python scripts/task.py new-plan-version <N> --file "$DRAFT"
```

## 11. Decision Rationale

N/A — no model training (no training hyperparameters). Design constants, each with a one-line rationale:

- **Match-stage order exact → whitespace-collapsed → +case-tolerant, unique-match-only, no fall-through on ambiguity.** Source: the 4 motivating incidents partition exactly into wrap/whitespace drift (#1604, #1609) and case drift (#1415); stages are strictly loosening supersets, so first-stage-with-candidates is the tightest resolution and ambiguity can only grow looser — falling through would mask duplicates.
- **Never fuzzy-apply; nearest-match is a REPORT only.** Source: task-body constraint (verbatim: "fail-loud on ambiguous/missing anchors (never fuzzy-apply silently)"); contrast with `patch(1)` fuzz, which auto-applies and is the known silent-mis-apply hazard.
- **`difflib` (stdlib) for the nearest-match scan, line-window `SequenceMatcher`, no cutoff.** Source: task-body "keep it dependency-free (stdlib only)"; a cutoff gate would sometimes hide the best candidate — as a report there is no wrong answer, only more or less useful, so always show the top window with its ratio. Scale check: ~3,000-line plan × short windows ≈ milliseconds with `quick_ratio` prefilter; 10 MB refusal guard for misuse.
