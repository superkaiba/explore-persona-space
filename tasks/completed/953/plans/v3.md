**Proposed bullet text (draft, gotchas.md house style — one bullet):**

> - **Manually cloning an EPS GCE startup script onto a hand-created tail/salvage instance requires mirroring the source's FULL env-contract instance metadata (never just HF_TOKEN) while EXCLUDING the clone-owned keys — and a silent fast-TERMINATED boot is diagnosable ONLY via a LIVE serial tail started before the restart.** The rendered startup script reads its ENTIRE env from instance metadata via the default-preserving fetch stanza in `src/explore_persona_space/backends/gcp.py`: all four `STARTUP_SECRET_ENV_KEYS` (HF_TOKEN, WANDB_API_KEY, ANTHROPIC_API_KEY, OPENAI_API_KEY — delivered at create time via `--metadata-from-file` 0600 tempfiles, never inline argv, #535) plus every `STARTUP_PASSTHROUGH_ENV_KEYS` config key (EPM_PERSIST_ADAPTER_*, the EPM_HF_* storage/overflow knobs, EPS_SCRATCH_DIR, the HF_XET_HIGH_PERFORMANCE / HF_HUB_ENABLE_HF_TRANSFER / HF_XET_DISABLE override channel); the create argv additionally sets `eps-issue=<N>`, `eps-attempt-id=<id>`, `enable-guest-attributes=TRUE`. Only the two `REQUIRED_LAUNCH_SECRET_KEYS = ("HF_TOKEN", "WANDB_API_KEY")` (~l.976) are hard-guarded — an in-VM preflight prints `[FAIL] <key> missing from instance metadata` and `exit 78`s, firing the EXIT-trap poweroff minutes after boot. EVERY other missing attribute degrades SILENTLY instead: no Anthropic/OpenAI credentials at the first API call, a LOST accelerator OVERRIDE (the static `=1` accelerator exports stand under the default-preserving fetch — but an un-mirrored `=0` / `HF_XET_DISABLE=1` override, the #515 workaround, is silently un-applied), and — worst — a clone missing `enable-guest-attributes=TRUE` cannot publish the `eps/phase` guest attribute, so the poller, the sentinel/attempt-recovery paths, and the #908/#935 zombie + done-grace predicates all misread the instance. The rc=78 crash is INVISIBLE post-mortem: serial output is unreadable on a TERMINATED instance, and the preflight fires BEFORE the repo clone + uv install, so the crash-persist upload subshell (`cd "$WORKLOAD_ROOT" && uv run ...`) cannot execute and no-ops under its `|| true` guards — nothing lands on HF even when HF_TOKEN itself was mirrored (as on #833's clone). RULE (mirror): copy every env-contract metadata attribute, never a hand-picked subset — and capture it WITHOUT echoing secrets: `umask 077; gcloud compute instances describe <src> --configuration=eps-gcp --zone=<z> --format=json > <0600 tmpfile>` (`describe` PRINTS every `metadata.items[].value`, including the #535 file-delivered tokens — never let it hit the terminal/transcript), extract each secret value into its own 0600 tempfile and replay via `gcloud compute instances add-metadata <dst> --configuration=eps-gcp --zone=<z> --metadata-from-file <KEY>=<tempfile>`, and replay the non-secret rest inline (`--metadata KEY=value,...`, including `enable-guest-attributes=TRUE`; a comma-containing value needs gcloud's alternate-delimiter `--metadata=^:^k1=v1:k2=v2` syntax — plain `--metadata` splits on commas). THREE clone-owned exceptions — do NOT blind-copy: NEVER replay the source's `startup-script` (the startup script itself rides instance metadata, and GCE re-runs it on EVERY boot — a copied source script overwrites the clone's own hand-built one exactly at the diagnosis-recipe restart) nor `ssh-keys`; and set FRESH `eps-issue=<N>` / `eps-attempt-id=<id>` for the target run, overriding any source values (verbatim-copied identity attributes collide in the poller/sentinel/recovery paths). RULE (diagnose): for a silent fast-TERMINATED boot, start `gcloud compute instances tail-serial-port-output <name> --configuration=eps-gcp --zone=<z>` BEFORE (or immediately at) the restart and keep it streaming — in this failure class the live stream is the only place the `[FAIL] <key> missing` line was recoverable (serial retrieval on the TERMINATED instance returns nothing). Manual cloning is a SALVAGE-only operation — for a fresh run, re-dispatch via `dispatch_issue.py launch`. The key tuples drift: re-derive from `STARTUP_SECRET_ENV_KEYS` / `STARTUP_PASSTHROUGH_ENV_KEYS` / `REQUIRED_LAUNCH_SECRET_KEYS` in `backends/gcp.py` rather than trusting this entry's frozen enumeration. Distinct from the #640 `guestTerminate` entry above (router-managed VM, DELETEd boot disk, pivot-to-RunPod rule) — here the instance is HAND-created, survives as TERMINATED, and the fix is metadata mirroring, not a backend pivot. (Incident #833 r7d tail instance, 2026-07-04: only HF_TOKEN was mirrored; the missing WANDB_API_KEY tripped the `[FAIL]` guard → rc=78 + EXIT-trap poweroff ~4 min after boot, 3 times, with zero post-mortem evidence; diagnosed via a live `tail-serial-port-output` stream during a restart; fixed by `describe --format=json` + `add-metadata` mirroring.)
