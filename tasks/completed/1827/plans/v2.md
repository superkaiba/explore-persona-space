## Requirement + acceptance criteria

1. New check function `check_plan_conditions_coverage(body: str, *, plan_path: Path | None = None) -> CheckResult` in `scripts/verify_task_body.py`.
2. Registered in `verify_text()` beside the other `plan_path`-consuming check (immediately after the `check_repro_lr_matches_plan` append, ~line 14558) — it needs the sibling `plans/plan.md`, so it lives outside the body-only `CHECKS` list.
3. **Plan-version resolution:** glob `plan_path.parent.glob("v*.md")` and sort NUMERICALLY by the integer version suffix (lexicographic sort mis-orders `v10.md` before `v2.md`; a non-`v<int>.md` name falls out of the walk); fall back to `[plan_path]` when no siblings exist (the `check_repro_lr_matches_plan` fallback). Walk from the LATEST version backwards and use the FIRST file that contains a parseable conditions table (a follow-up amendment plan may legitimately carry no conditions table — fall back to the newest prior version that does).
4. **Table detection:** a markdown table following a heading matching `(?im)^#{2,4}\s*(?:\d+\.?\s*)?conditions` whose header row contains a column matching `(?i)config[ -]?slug`. Extract per data row: the backtick-wrapped slug from that column (rows whose slug cell has no backtick-wrapped token are skipped) + the plain-English name (first column, stripped of markdown emphasis).
5. **Verdict semantics (WARN tier only — this check can NEVER FAIL):**
   - For each (slug, name) row: covered iff the slug appears in the body (exact substring) OR the plain-English name appears in the body (case-insensitive substring, after stripping emphasis markers from both sides).
   - ≥1 uncovered row → `CheckResult(name, True, "<k> plan-§5 condition(s) with no body mention: `slug1` (Row Name 1), ... — name each in the relevant ### result / Takeaways or record the descope per After-Every-Experiment item 8", is_warn=True)`.
   - All covered → plain PASS with a `<n> plan conditions all covered` detail.
6. **NO-OP PASS** when: `plan_path` is None or missing; no plan version contains a conditions table with a config-slug column; the table parses to zero slug rows. (Kind gating needs no new code — `main()` already short-circuits `kind: infra|batch|survey` to the N/A verdict, #1724; `kind: analysis` tasks rarely have a §5 conditions table and hit the NO-OP.)
7. **Docstring names the two ACCEPTED false-negative directions** (both fail toward status quo; the LM Lens 13 read remains the backstop — do not attempt to close them in this round): (a) a follow-up plan version carrying its OWN smaller conditions table shadows the original table, so the original conditions go unchecked; (b) a slug appearing only inside a Reproducibility-footer artifact path (e.g. `eval_results/.../cell_pre_own/`) counts as coverage.
8. **Tests** in `tests/test_verify_task_body.py` (new test functions beside the check-16 plan tests): (a) slug present in body → PASS; (b) **era-correct incident replay (must-WARN):** the verbatim pre-correction #1774 body (`git show 57c915206e:tasks/interpreting/1774/body.md` — pin the needed shape as an in-repo fixture string/file, not a live-git dependency) + a #1774-shaped conditions-table plan fixture, routed through `verify_text(..., plan_path=...)` (NOT a direct check call — this pins the registration site) → exactly the new check WARNs, naming `cell_pre_own`; (c) slug absent but plain-English name present → PASS (the CURRENT corrected #1774 descope-prose shape as a must-PASS companion); (d) `plan_path=None` → NO-OP PASS; (e) plan without a conditions table → NO-OP PASS; (e2) conditions table whose slug column has zero backtick-wrapped rows → NO-OP PASS; (f) a #1774-shaped 16-row table parses all 16 slugs; (g) WARN is `is_warn=True, passed=True` (never blocks); (h) numeric version sort — a `v10.md` with the table beats `v2.md` without (or equivalent minimal pair).
