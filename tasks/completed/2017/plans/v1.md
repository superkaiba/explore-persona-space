# Plan v1 — Task #2017: workflow-fix: dropped-at-gate condition placement check (Takeaways + result) in verify_task_body

### TDD: no

## Goal / requirement

Add a `verify_task_body.py` check (check **51**) enforcing CLAUDE.md After-Every-Experiment item 8(a): when a v4 clean-result body's `## Methodology` declares a planned condition **dropped at a gate** (yield gate / data gate / kill criterion), the dropped condition's NAME must appear in `## Takeaways` AND in at least one `### <result>`'s prose under `## Results`. FAIL names the declaring sentence + the missing placement(s).

**Origin:** clean-result-critic Lens 13 `mechanizable: yes` finding on task #1947 — its body declared the sycophancy yield-gate drop only in Methodology `**Design:**` ("A third planned behavior (sycophancy) was dropped at the datagen yield gate — 232 judge-accepted positives against the 240 floor…"), passed all existing checks, and the missing Takeaways/result placement was caught manually.

## Acceptance criteria

1. New check function `check_v4_dropped_condition_placement` registered in `CHECKS` (or dispatched in `verify_text` if it needs extra inputs — it does not; body-only).
2. On the #1947-shape fixture (drop declared in Methodology, name absent from Takeaways and every result section): **FAIL**, detail quoting the declaring sentence (truncated) and naming BOTH missing placements.
3. Name present in `## Takeaways` AND ≥1 `### <result>` block: **PASS**.
4. Name present in only one of the two placements: **FAIL** naming the missing one.
5. Drop-at-gate declaration detected but no condition name confidently extractable: **WARN** (surface, never block on a failed heuristic extraction).
6. v3 / v2 / legacy bodies (no `<!-- clean-result-v4 -->` sentinel): vacuous PASS (forward-only — never newly hard-FAIL grandfathered shapes).
7. v4 body with no drop-at-gate language: PASS (no false positives on ordinary rate prose, fenced code, or blockquote captions).
8. Module docstring check list gains a numbered `51.` entry; SPEC.md is NOT edited (it names the verifier generically, no per-check enumeration — confirmed by grep).
9. Fleet-fallout scan reported (not blocking): run the new check against all current `tasks/awaiting_promotion/*/body.md` + `tasks/completed/*/body.md` v4 bodies and report which would FAIL/WARN in the implementation marker (expected: #1947 FAILs by design — its live critic round is already demanding that fix).

## File paths + concrete diff shape

- `scripts/verify_task_body.py`:
  - New helper(s) + `check_v4_dropped_condition_placement(body: str) -> CheckResult`, registered in `CHECKS` under the v4-gated group.
  - Detection: within the `## Methodology` H2 section ONLY (prose layer — fenced code + blockquotes + `<details>` stripped, reusing the existing `_prose_layer` / section-slicing conventions), match sentences against
    `(?:was|were)\s+(?:dropped|removed|excluded|cut)\s+(?:at|by)\s+(?:the\s+|a\s+|its\s+)?[^.;]*?\b(?:gate|criterion|floor)\b` (case-insensitive).
  - Condition-name extraction (priority order): (1) parenthetical immediately preceding the verb group — `\(([^)]{2,60})\)\s*(?:was|were)` → e.g. `sycophancy`; (2) a backtick/bold/italic-wrapped token in the subject clause; (3) none → WARN path (criterion 5).
  - Placement test: case-insensitive substring match of the extracted name against (a) the `## Takeaways` section text and (b) each `### <result>` block under `## Results` (heading + prose). Multi-token names match on the full token sequence; single-token names on the token.
  - Severity: FAIL on confident extraction + missing placement; WARN on unextractable name; PASS otherwise. v4 sentinel gating via the existing `_is_v4`-style helper (~L3534) — non-v4 bodies PASS vacuously.
  - Module docstring: add the `51.` entry mirroring the 11b entry's register.
- `tests/test_verify_task_body.py`: fixture pair + edge cases per acceptance criteria 2–7 (minimal v4 bodies; the positive fixture's declaring sentence copied near-verbatim from #1947's `**Design:**` line).
