## 10. §11 Decision Rationale (the thresholds in the new clause)

1. **Scanned-row floor `>~10^4` — keyed on SCANNED, not kept/target, volume.** *What:* the volume arm of the firing disjunct. *Why:* #1092's kept target was only ~2.4k — the task body's sketch (">~10^4 rows target volume") would not have fired on the motivating incident itself; the scanned volume (~10^5–10^6) is what set the 3h06m wall. At #1092's realized throughput (~10^5–10^6 rows / ~3.1h ⇒ order 10–90 rows/s through filters + network), 10^4 scanned rows ≈ minutes-to-tens-of-minutes — just under the ~1h floor — so 10^4 with *unknown* throughput is the correct presumption edge, while a 100-row bounded API fetch sits 2 orders below and stays exempt. Not sensitive within ~3×. *Source:* #1092 events (`attempt 2 streamed ~1M rows silently`; `3h06m`; `kept-cap 1200/source`) + `_stream_with_cache` docstring. *Alternatives:* kept-volume threshold (rejected — misses the incident); no volume arm at all (rejected — loses the cheap objective trigger for large known scans).
2. **`unknowable in advance` / `keep-quota-driven` disjuncts.** *What:* the two non-numeric firing arms. *Why:* #1092's exact shape — "scan until N kept" makes the scan count a function of filter yield, unknowable pre-run (attempt 2 silently streamed ~1M rows); these arms are what make the presumption robust when nobody can state a volume. *Source:* #1092 (`row_limit`/keep-quota stop in `issue1092_build_corpus.py::_stream_conversations`; attempt-2 event). *Alternatives:* wall-time-only trigger (rejected — that is precisely the defeated prong).
3. **Named source classes (HF `datasets` `streaming=True`, API pagination, web harvest, S3/HTTP row iteration).** *What:* the illustrative enumeration defining "external streaming source". *Why:* covers the incident class (HF datasets streaming) plus the adjacent network-bound harvest shapes this project realistically writes (LMSYS/WildChat-class corpus builders, Hub/API pagination); phrased as a defining enumeration of the *property* (external + network-bound + row iteration), not a closed allowlist. *Source:* task-body sketch + #1092; #1073/#1092 are both LMSYS/WildChat-class harvests. *Alternatives:* abstract property only (rejected — reviewers pattern-match named shapes faster; the #606 twin-omission lesson favors explicit enumeration).
4. **Required mechanism = per-chunk durable persistence + fingerprint-gated resume; prose-enforced (no new lint check).** *What:* the mechanism clause + enforcement mode. *Why:* the mechanism is Step 3.6's existing Check items 1–2 instantiated for streams — the fingerprint (dataset revision + every filter/recipe constant) IS "keyed on every output-affecting regime key"; `_stream_with_cache` is the in-repo shape that already survived #1092's round-8 review (atomic pool-first/meta-last ordering makes a partial cache never present a valid fingerprint).
