## 1. Requirement

Any workload dispatched to a SLURM lane (`fellows` / `nibi` / `fir` / `mila`) that opens a
git-TRACKED file under `data/` must find it on the compute node. Today it crashes
`FileNotFoundError` — the same class as the #2203 Phase-3 pod crash that #2211 fixed
pod-side — because `RSYNC_INCLUDE_PATHS` (`src/explore_persona_space/backends/slurm.py`
L916-930) carries `./data/sft` and nothing else under `data/`.

## 2. Decision: option (a) — widen the include-set to all tracked `data/`

The body left three options open. Option (a), for four reasons, each mechanically checked
(evidence in the `epm:clarify v1` note):

1. **The rsync source is committed-only, so `./data` ships exactly the TRACKED set.** Since
   #1913 `SlurmBackend._resolve_rsync_source` (L3159) ALWAYS materializes a detached scratch
   worktree via `materialize_branch_src` (L3891) at `~/.eps-slurm-src/issue-<N>` — for
   `main`/absent dispatches too; the live working tree is never the rsync source. The
   untracked `data/` caches (`data/issue_<N>/hf_dl`, the `*_dl` staging dirs, `store/`) are
   absent from that tree BY CONSTRUCTION. This is what kills the usual objection to
   widening: there is no path on which `./data` sweeps in the VM's ~208 GiB of `data/`
   caches. Measured: tracked `data/` = **320 files / 59.98 MB** (vs `./data/sft` alone =
   1 file / 0.18 MB), consistent with #2211's ~63 MB measurement.
2. **It is the exact semantic analogue of the parent fix**, which is this task's stated
   purpose (lane parity). #2211 added `data` to the pod's default sparse cone; git
   materializes only tracked blobs there, and a committed-only rsync source gives the same
   guarantee here.
3. **No exclude shadowing (the #1915 class).** Zero of the 320 tracked `data/` paths sit
   under any `RSYNC_EXCLUDE_PATTERNS` directory name, so the widened include tree cannot be
   silently punctured at depth.
4. **Option (b) already exists and did not prevent the crash class.** The per-launch
   `--extra-sync-path` declaration (#1835, `EXTRA_SYNC_PATHS_KEY`) is opt-in and requires
   the planner to know in advance which tracked input a workload opens. That is the same
   reason #2211 rejected the declaration-only option pod-side. It stays as the remedy for
   inputs OUTSIDE the include set (`eval_results/`, `ood_eval_results/`, `raw/`, `docs/`) —
   this fix narrows what needs it, it does not replace it.

Option (c) (stage `data/` inputs from HF) is rejected: it would require touching every
consuming experiment script, and it inverts the parent's decision for no lane-specific
reason.

### Change B — protect cluster-side caches from `--delete` (`RSYNC_EXCLUDE_PATTERNS` L932-949)

`build_rsync_command` (L1070) emits `-a --relative --delete --partial --mkpath` with one
`--exclude` per pattern and **no** `--delete-excluded`, so an excluded pattern also protects
matching RECEIVER-side files from the deletion pass. Widening the include set to `./data`
extends `--delete`'s reach from `$SCRATCH/data/sft` to the whole `$SCRATCH/data/` subtree,
and `prepare` runs on every FRESH launch — including a crash-fix relaunch. Add:

```python
+    # Re-downloadable staging caches + durable per-issue stores, matched at
+    # every depth (rsync applies slash-free patterns at all depths). These
+    # can never be SENT — the committed-only rsync source has no untracked
+    # files — so their ONLY function is to protect a CLUSTER-side
+    # ``$SCRATCH/data/issue_<N>/{hf_dl,*_dl,store}`` tree from the
+    # ``--delete`` pass on a re-dispatch, now that ``./data`` is an include
+    # tree (there is no ``--delete-excluded``). Collision-checked at #2212:
+    # no tracked path component in the repo ends in ``_dl`` or equals
+    # ``store``, so neither pattern can shadow a tracked input (#1915).
+    "*_dl/",
+    "store/",
```

`*_dl/` rather than the `g*_dl` shorthand in CLAUDE.md: the realized names under `data/` are
`hf_dl` (×4) plus `summaries_dl`, `recap_dl`, `recap_slice_dl`, `rb_nuisance_dl`, `prb_dl`,
`mirror_dl`, `ladder_dl`, `jlens_dl`, … — all `*_dl`.

**Honest scope of change B:** no lane-level convention writes under `$SCRATCH/data/` today
(`HF_HOME` on the fellows lane is `/workspace/pretrained_ckpts`, L511; the SLURM render
contains no `data/` path other than the include entry). It is free, collision-free insurance
for a workload that stages a repo-relative `data/issue_<N>/hf_dl` from `cwd=$SCRATCH`. It is
NOT claimed to fix an observed loss.

## 7. Kill criteria

- **Widening is unsafe** if the rsync source can be the LIVE working tree on any reachable
  path — that would sweep untracked `data/` caches to the cluster. Falsifier: a code path
  where `_resolve_rsync_source` returns `self._src_root`. The implementer re-reads
  `_resolve_rsync_source` + `materialize_branch_src` and greps for `self._src_root` returns;
  if such a path exists, ABANDON change A and fall back to an explicit enumerated tracked
  subdir list (or `git ls-files`-derived `--files-from`), recording the finding.
- **An exclude pattern shadows a tracked input** (#1915): any tracked path component ending
  `_dl` or equal to `store`. Falsifier is the third measurement command in §5; a non-empty
  result kills change B's pattern choice (narrow to `hf_dl/` + explicit names).
- **Transfer cost is material:** if the added ~60 MB measurably delays dispatch (the module
  docstring's reference point is ~12 s for 50 MB on Nibi, so expect ~+15 s). A >2 min
  regression on a real dispatch kills the blanket widen in favour of the enumerated list.
