# Plan — #2024: step9c `compare` must not classify an ordering-interaction failure as NEW

`kind: infra` · `workflow: v1` · `workflow_fix_target: scripts/step9c_baseline.py` · `gpu_hours_total=0`

**Revision note (v3):** supersedes v2 after a single-Claude Methodology critic round (the Codex twin
was an instant confirmed no-show — org quota exhausted until 2026-09-05). Three REVISE blockers were
substantiated against the code and are fixed here, not argued with:
- **B1** — v2's `--max-paired-files 30` "keep the nearest N predecessors" truncation would have
  dropped the #2021 judge-importing predecessor (measured distance **49** in the reconstructed
  171-file selection), so the fix would not have fired on its own founding incident. The lossy
  truncation is **deleted**; the cap becomes a refuse-to-spend guard that SKIPs (keeping NEW).
- **B2** — v2 checked oracle trust at candidate *collection* but ran the paired invocation *after*
  the per-file loop, so a paired FAIL from a root oracle that went dirty in between would have
  stripped on untrustworthy evidence, in the un-blocking direction. A verdict-time MF-4c re-probe +
  guard is now specified, along with the paired run's oracle resolution.
- **B3** — junit document order is **not** execution order under the gate's own
  `--continue-on-collection-errors`: a collect-error testcase floats to the FRONT regardless of argv
  position (demonstrated on pytest 9.0.2). The order source is switched from junit document order to
  the selector's own deterministic selection, which removes the dependency instead of narrowing it.

## 1. Goal

Make `scripts/step9c_baseline.py compare` stop classifying a failure as **NEW** (blocking) when the
failure is a **pre-existing cross-module import-ordering interaction on main** rather than something
the branch caused. Concretely: a node whose test FILE is untouched by the branch diff and which
PASSes the current SINGLE-FILE pristine oracle must be re-checked against pristine main **under the
gate run's own co-selection order** before it is allowed to block.

Success = the #2021 shape (17 failures in `tests/test_issue1739_pvsynth_arms.py` +
`tests/test_issue1739_wcrung_arms.py`, both with an EMPTY branch diff) classifies as a reported,
non-blocking `ordering-suspect` strip with no human re-proof cycle — while every genuine
branch-caused regression keeps blocking.

**Decision rule:** the paired pristine re-run is the ONLY thing that may downgrade a would-be NEW

exception in the opposite direction, B2's dirty-oracle case, which resolves to exit 2
(indeterminate), matching the existing MF-4c precedent rather than either stripping or blocking.

**Kill / halt-and-report criteria:**
- If the selector's deterministic selection cannot be reconciled with the set of files the run junit
  shows actually ran — i.e. the order source itself is unavailable, not merely skewed — HALT and post
  `epm:failure v1` (`failure_class: code`) rather than ship a prefix built on a guess. *(A per-file
  skew is NOT a halt: it degrades to a recorded skip, keeping NEW.)*
- If the paired run cannot reuse the existing oracle plumbing (scratch cwd / `venv_root` /
  `pythonpath`) without weakening the #1022 interpreter rule or the #1251 src-shadow ⇒ HALT rather
  than hand-rolling a second, less-trusted oracle.
- If fixture 2 (the masking counter-case) or fixture 5 (the B2 dirty-oracle case) cannot be made to
  pass ⇒ HALT; the change is unsafe by construction and must not land.

**What would change my mind about the design:** evidence that the #2021 failures reproduce
single-file on some machines (which would make this an environment bug, not an ordering interaction),
or that the paired run's realized wall on a full-selection prefix exceeds the gate run's own wall
rather than being a fraction of it.

## 3. Design decision — the discriminator is a REPRODUCTION, not a provenance downgrade

The task body offers two mechanisms and defers the call. **Choosing (b), the paired-selection
pristine re-run, with branch-diff provenance as an eligibility PRECONDITION + recorded evidence
rather than as the discriminator.**

- **Sketch option (a) — "file untouched by the branch diff ⇒ downgrade to non-blocking" — is
  REJECTED as a blanket rule: it masks real regressions.** A branch that edits
  `src/explore_persona_space/**` and breaks an *untouched* test file satisfies (a)'s predicate
  exactly, so (a) would strip a genuine branch-caused regression. That is the precise direction the
  task's own fail-CLOSED constraint forbids, and it would make `compare` weaker than it is today.
- **Option (b) discriminates correctly in both directions.** Re-run the failing file on pristine main
  with the co-selected predecessors that actually preceded it in the gate run:
  - reproduces on main ⇒ pre-existing ordering interaction ⇒ strip (report, never block);
  - passes on main under the same co-selection but failed in the run ⇒ the branch caused it ⇒ NEW,
    blocking, exactly as today. The `src/`-change-breaks-untouched-test case lands here.
- Branch-diff provenance still earns its place as the **gate** on when the extra run fires
  (`node.file not in ctx.touched`, i.e. `git diff --name-only <base>...HEAD -- <file>` empty — which
  is literally what `sel.compute_touched` computes) and as recorded evidence in the payload. A node
  whose file IS in the branch diff keeps today's NEW semantics with no paired re-check — both because
  the task requires it and because main's copy of a branch-modified test file is not the thing that
  failed.

**Cost containment: ONE extra pytest invocation per compare, worst case.** Every ordering-suspect
candidate is resolved from a single run of the *maximal* prefix. If candidate files sit at selection
indices 12 and 61, the prefix ending at 61 already contains 12, so one run yields verdicts for both.
A node that fails in that longer prefix has demonstrably reproduced on pristine main under a subset
of the run's own co-selection; a node that passes stays NEW (fail-closed), so the single-run collapse
can only ever err toward blocking.

**Honest wall-time (B1 consequence).** With the lossy truncation removed, the prefix can be most of
the gate selection — for the #2021 shape, ~62 of 171 files. The realized wall is a *fraction of the
gate run's own wall* for those files (the gate already ran all 171), but the derived **timeout**
ceiling at that width is large (~1 h at current selector constants). That is accepted deliberately:
the generous-bias rule is unchanged (an oversized bound only delays a wedged run; an undersized one
guarantees a wasted compare + rerun), and the alternative — a cap that silently drops the
contaminating predecessor — defeats the fix. The run fires ONLY on the exact case that today costs a
human repro-and-override cycle.

## 4. Change set

### 4.1 `scripts/step9c_baseline.py` (primary)

**(a) Order source: the selector's deterministic selection, NOT junit document order (B3).**
`_selector_context` already calls `sel.select_tests_with_reasons(touched, wt)` and discards the
`_tests` list; keep it as `ctx.selected_order` (the sorted, deterministic list the gate passed as
pytest argv). Add `parse_junit_ran_files(path) -> set[str]` returning the set of `file` attributes
across ALL testcases — membership only, order deliberately unused.
The paired prefix is then `[f for f in ctx.selected_order if f in ran_files]`, truncated at the
candidate. This is immune to the demonstrated collect-error float-to-front (a collect-error row's
junit position is not its argv position), and it is deterministic.
*Skew handling:* a file present in the junit but absent from `ctx.selected_order` (deliberate
selector version skew, §3.3) cannot be placed in the order — record it in `paired_order_skew` and,
if the CANDIDATE itself is unplaceable, skip that candidate with a recorded reason (keep NEW).
Only a wholly unusable order source is a halt (§1.1).
*`parse_junit` is NOT modified:* its `summary` dict is persisted verbatim into the ledger
(`cmd_refresh`, `"pytest_summary": summary`), so adding ~248 paths there would bloat a shared cache
file and perturb a contract the step9c pin tests hold. `_load_run_junit` returns
`(run_failing, ran_files)`; its only caller is `_compare_impl`.

**(b) Generalize the oracle runner without renaming it.** Extract
`run_pristine_selection(files: list[str], cwd, timeout_s, *, venv_root=None, pythonpath=None) -> set[Node]`
holding the current body (`run_pytest` already accepts a file LIST); keep
`run_single_file_pristine(test_file, ...)` as a thin wrapper delegating with `[test_file]` so the
existing tested name, signature and error semantics (`rc not in {0,1}` / timeout / zero-collected ⇒
`PristineRunError`) are preserved byte-for-byte. Error strings in the generalized form name the file
list truncated to the first 5 entries + a count. The #1022 interpreter rule (`resolve_root_python`
against the MAIN root) and the #1251 src-shadow trust split (ambient `PYTHONPATH` always stripped;
only a caller-constructed HEAD-pinned value re-set) are inherited unchanged — the wrapper passes them
through, it does not re-derive them.

**(c) Paired timeout sizing.** `derive_paired_timeout_s(sel, files)`: prefer the selector's own
`recommended_timeout_s(files, dispersion=2.0)` via `getattr` (ONE runtime table, #1046), degrading to
`BASE + PER_FILE*len(files) + 2*Σ surcharge` floored at `PRISTINE_TIMEOUT_FLOOR_S` (600 s) when a
version-skewed worktree selector copy lacks it — the same `getattr` discipline
`derive_pristine_timeout_s` already uses. Sized against the FULL prefix width (B1: not against a
30-file cap).

**(d) The paired-oracle stage in `_resolve_pristine_bucket`.** Replace the bare
`else: ctx.new.append(node)` with: collect the node into `ctx.paired_candidates` when EVERY
precondition below holds, else `ctx.new.append(node)` verbatim as today.

Collection preconditions (all fail-closed — a miss keeps NEW and records `{node_id, reason}`):
1. `node.file not in set(ctx.touched)` — branch diff for that file is empty;
2. the per-file oracle that produced the PASS was the SCRATCH oracle, **or** the root was clean at
   that file's probe;
3. `node.file not in ctx.sel.GLOB_SCAN_TESTS` or `node.file in FILE_ANCHORED_SCAN_TESTS` — the R-F'
   live-tree-scanner constraint stands unchanged;
4. `node.file` is placeable in `ctx.selected_order` (B3 skew);
5. `--no-paired-pristine` not passed.

After the per-file loop, if `ctx.paired_candidates` is non-empty:
- **Resolve the paired oracle explicitly (B2):** the live `scratch` if one exists and was not
  degraded, else the root. Drop any candidate whose per-file oracle differs from the resolved paired
  oracle, with a recorded reason (keep NEW) — no candidate is ever judged by an oracle other than the
  one that produced its PASS.
- **Re-probe immediately before the invocation (B2):** re-run `dirty_code_paths` +
  `scratch_contamination_probe`, exactly as the per-file loop does per file ("BOTH probes re-run per
  file — MF-4c freshness + mid-loop transitions", L1763-4). A probe failure ⇒ `_Indeterminate`.
- Build the prefix per (a); drop files absent on main (a branch-new co-selected file cannot run on a
  HEAD-pinned pristine tree) and record them in `paired_dropped_files` — a resulting PASS ⇒ NEW is
  fail-closed.
- **Refuse-to-spend guard, not a truncation (B1):** if the prefix exceeds `--max-paired-files`
  (default **200** — above the current 171-file full selection, so it is a runaway guard and not a
  behavior knob), SKIP the paired check entirely with reason `prefix-over-cap`, keeping NEW (today's
  behavior). v2's "keep the last N predecessors" heuristic is DELETED: it dropped the #2021
  predecessor at measured distance 49 and would have made the fix inert on its founding incident.
- **Zero-predecessor skip:** if the retained prefix is just the candidate file itself, the paired run
  is identical to the single-file run that already PASSed — skip with reason `no-predecessors`, keep
  NEW, spend nothing.
- ONE `run_pristine_selection` call on the resolved oracle, timeout from (c).
  `PristineRunError` ⇒ `_Indeterminate` (exit 2), matching the per-file path — never a classification
  from an aborted run.
- **Verdict, with the MF-4c guard (B2):** for each candidate — **in** the paired failing set: if the
  resolved oracle is non-scratch AND the re-probe showed live dirt, raise `_Indeterminate` with the
  same shape and payload keys the per-file MF-4c raise uses (L1820-1842); otherwise
  `_strip_node(ctx, node, via="pristine-paired-ordering")` plus an `ORDERING WARN:` line and a row in
  `ctx.ordering_suspect`. **not in** the paired failing set ⇒ `ctx.new.append(node)` (unchanged
  blocking semantics).

Routing the strip through the existing `_strip_node` is deliberate: the #1713/#1742
workflow-invariant urgent-park demand and the `GLOB_SCAN_TESTS` masking WARN then apply to an
ordering strip automatically. **Note (critic correction):** its diff-linked masking clause CAN
legitimately fire here — `ctx.diff_linked` ⊋ touched tests (L1504: import-arm / stem-arm-selected
tests are diff-linked without being in `touched`), so an import-arm-selected untouched test can be a
paired-strip candidate and correctly earn the MASKING WARN. The implementer must NOT assert that
clause away or "fix" it as unreachable.

**(e) `_CompareCtx` additions:** `selected_order: list[str]`, `paired_candidates: list[Node]`,
`ordering_suspect: list[dict]`, `paired_files_run: list[str]`, `paired_dropped_files: list[str]`,
`paired_order_skew: list[str]`, `paired_skipped: list[dict]` (`{node_id, reason}` for every
precondition miss and every skip — the audit trail that makes a still-blocking NEW one-glance
diagnosable), `paired_oracle: str` (`"scratch-worktree" | "root" | "none"`).

**(f) `_compare_impl` payload + `cmd_compare` output.** Surface `ordering_suspect`,
`paired_files_run`, `paired_dropped_files`, `paired_order_skew`, `paired_skipped`, `paired_oracle`.
Human-readable mode prints one `ORDERING-SUSPECT: <file>::<name>` line per row and folds the count
into the summary line. **Exit semantics are unchanged and are NOT extended:** 0 = no NEW + no lint
regression, 1 = NEW and/or lint regression, 2 = indeterminate. An ordering-suspect node is stripped,
so it does not contribute to exit 1 — it is loud in `warns` + its own list instead.

**(g) New CLI flags** on the `compare` subparser: `--no-paired-pristine` (escape hatch, restores
today's behavior exactly) and `--max-paired-files` (int, default 200; over-cap SKIPs, never
truncates).
