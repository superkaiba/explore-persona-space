# Plan — #2024: step9c `compare` must not classify an ordering-interaction failure as NEW

`kind: infra` · `workflow: v1` · `workflow_fix_target: scripts/step9c_baseline.py` · `gpu_hours_total=0`

## 1. Goal

Make `scripts/step9c_baseline.py compare` stop classifying a failure as **NEW** (blocking) when the
failure is a **pre-existing cross-module import-ordering interaction on main** rather than something
the branch caused. Concretely: a node whose test FILE is untouched by the branch diff and which
PASSes the current SINGLE-FILE pristine oracle must be re-checked against pristine main **under the
gate run's own co-selection order** before it is allowed to block.

Success = the #2021 shape (17 failures in `tests/test_issue1739_pvsynth_arms.py` +
`tests/test_issue1739_wcrung_arms.py`, both with an EMPTY branch diff) classifies as a reported,
non-blocking `ordering-suspect` strip with no human re-proof cycle — while every genuine
branch-caused regression keeps blocking.

## 2. Root cause (mechanically located, not inferred)

Two sites append to `ctx.new`:

| Site | Line | Trigger | Correct today? |
|---|---|---|---|
| `_bucket_run_failures` | `elif not (root / node.file).exists(): ctx.new.append(node)` | test file absent on main ⇒ branch-new | **yes** — the file IS the branch diff; leave untouched |
| `_resolve_pristine_bucket` | `else: ctx.new.append(node)  # a PASS still classifies NEW (fail-closed)` | single-file pristine run PASSed | **the defect** |

The #2021 failures land on the second site. Their files exist on main, so they bucket as
unknown-provenance; the pristine oracle runs them **single-file**, where they pass (the #1739 scripts'
`_assert_no_judge_modules("at entry")` spend guard reads `sys.modules`, so the failure needs a
judge-importing predecessor in the SAME pytest process); the PASS is what promotes them to NEW.

The oracle's single-file shape makes ordering-dependent trunk red **structurally invisible** — this is
the second member of the documented degeneracy family (the first being scan-test aggregation / MF-6
masking WARNs), and today it has no mechanical escape: the orchestrator must hand-run a paired repro
(`tests/test_batch_judge_agg_non_dict_parse.py tests/test_issue1739_wcrung_arms.py` → 11 failed in
3.02 s) and provenance-override the verdict, every time a session co-selects those files.

Absence check: `grep -i 'ordering|branch.diff.provenance|untouched'` over the file returns one
unrelated hit (an L875 `.pth`-reordering comment). Landed-fix check: only `a665494f05` (#1731
cross-issue lint-gate concurrency arbitration) has touched the file since 2026-08-01, and not this
path — the premise is unfixed.

## 3. Design decision — the discriminator is a REPRODUCTION, not a provenance downgrade

The task body offers two mechanisms and defers the call. **Choosing (b), the paired-selection
pristine re-run, with branch-diff provenance as an eligibility PRECONDITION + recorded evidence
rather than as the discriminator.**

- **Sketch option (a) — "file untouched by the branch diff ⇒ downgrade to non-blocking" — is
  REJECTED as a blanket rule: it masks real regressions.** A branch that edits
  `src/explore_persona_space/**` and breaks an *untouched* test file satisfies (a)'s predicate
  exactly, so (a) would strip a genuine branch-caused regression. That is the precise direction the
  task's own fail-CLOSED constraint forbids, and it would make `compare` weaker than it is today.
- **Option (b) discriminates correctly in both directions.** Re-run the failing file on pristine main
  *with the co-selected predecessors that actually preceded it in the gate run*:
  - reproduces on main ⇒ pre-existing ordering interaction ⇒ strip (report, never block);
  - passes on main under the same co-selection but failed in the run ⇒ the branch caused it ⇒ NEW,
    blocking, exactly as today. The `src/`-change-breaks-untouched-test case lands here.
- Branch-diff provenance still earns its place as the **gate** on when the extra run fires
  (`node.file not in ctx.touched`, i.e. `git diff --name-only <base>...HEAD -- <file>` empty — which
  is literally what `sel.compute_touched` computes) and as recorded evidence in the payload. A node
  whose file IS in the branch diff keeps today's NEW semantics with no paired re-check — both because
  the task requires it and because main's copy of a branch-modified test file is not the thing that
  failed.

**Cost containment (the reason (b) is affordable): ONE extra pytest invocation per compare, worst
case.** Every ordering-suspect candidate is resolved from a single run of the *maximal* prefix. If
candidate files sit at run-order indices 3 and 7, the prefix ending at index 7 already contains index
3, so one run yields verdicts for both. A node that fails in that longer prefix has demonstrably
reproduced on pristine main under a subset of the run's own co-selection; a node that passes stays
NEW (fail-closed), so the single-run collapse can only ever err toward blocking.

## 4. Change set

### 4.1 `scripts/step9c_baseline.py` (primary)

**(a) Recover the run's execution order.** Add `parse_junit_file_order(path) -> list[str]`: parse the
junit and return the ordered unique `file` attributes across ALL testcases (not just failing ones).
pytest collects in argv order in a single process — the gate uses no `pytest-xdist` and no
random-order plugin (`select_step9c_tests.py` docstring; `PYTEST_BASE_FLAGS` carries neither), so
junit document order IS execution order.
*Deliberately a new function, not a new return value on `parse_junit`:* `parse_junit`'s `summary`
dict is persisted verbatim into the ledger (`cmd_refresh`, `"pytest_summary": summary`), so adding
~248 paths there would bloat a shared cache file and perturb a contract the step9c pin tests hold.
`_load_run_junit` returns `(run_failing, ordered_files)`; its only caller is `_compare_impl`.

**(b) Generalize the oracle runner without renaming it.** Extract
`run_pristine_selection(files: list[str], cwd, timeout_s, *, venv_root=None, pythonpath=None) -> set[Node]`
holding the current body (`run_pytest` already accepts a file LIST); keep
`run_single_file_pristine(test_file, ...)` as a thin wrapper delegating with `[test_file]` so the
existing tested name, signature and error semantics (`rc not in {0,1}` / timeout / zero-collected ⇒
`PristineRunError`) are preserved byte-for-byte. Error strings in the generalized form name the file
list truncated to the first 5 entries + a count.

**(c) Paired timeout sizing.** `derive_paired_timeout_s(sel, files)` mirroring
`derive_pristine_timeout_s`: prefer the selector's own `recommended_timeout_s(files, dispersion=2.0)`
via `getattr` (ONE runtime table, #1046), degrading to
`BASE + PER_FILE*len(files) + 2*Σ surcharge`, floored at `PRISTINE_TIMEOUT_FLOOR_S` (600 s) when a
version-skewed worktree selector copy lacks it (§3.3 skew tolerance, the same `getattr` discipline
`derive_pristine_timeout_s` already uses). Generous bias is deliberate and unchanged: an oversized
bound only delays a wedged run, an undersized one guarantees a wasted compare + rerun.

**(d) The paired-oracle stage in `_resolve_pristine_bucket`.** Replace the bare
`else: ctx.new.append(node)` with: collect the node into `ctx.paired_candidates` when EVERY
precondition below holds, else `ctx.new.append(node)` verbatim as today.

Preconditions (all fail-closed — a miss keeps NEW and records a reason):
1. `node.file not in set(ctx.touched)` — branch diff for that file is empty;
2. the oracle that produced the PASS is trustworthy: the scratch oracle was used for that file, **or**
   the root is clean (`not ctx.live_dirty_paths`). A dirty-root oracle keeps today's NEW (the MF-4c
   trust rule is untouched);
3. `node.file not in ctx.sel.GLOB_SCAN_TESTS` or `node.file in FILE_ANCHORED_SCAN_TESTS` — the R-F'
   live-tree-scanner constraint stands unchanged;
4. `--no-paired-pristine` not passed.

After the per-file loop, if `ctx.paired_candidates` is non-empty:
- build the prefix = ordered run files up to and including the highest-indexed candidate file, minus
  files absent on main (a branch-new co-selected file cannot run on a HEAD-pinned pristine tree; drop
  it, record it in `paired_dropped_files` — a resulting PASS ⇒ NEW is fail-closed);
- truncate to the last `--max-paired-files` entries (default 30, keeping the nearest predecessors and
  always the target) and record `paired_truncated: true` when it fires — truncation can only cause a
  PASS ⇒ NEW, i.e. fail-closed;
- ONE `run_pristine_selection` call on the same oracle cwd/venv/pythonpath the per-file runs used;
- `PristineRunError` ⇒ `_Indeterminate` (exit 2), matching the per-file path — never a classification
  from an aborted run;
- for each candidate: **in** the paired failing set ⇒ `_strip_node(ctx, node, via="pristine-paired-ordering")`
  plus an `ORDERING WARN:` line and a row in `ctx.ordering_suspect`; **not in** it ⇒
  `ctx.new.append(node)` (unchanged blocking semantics).

Routing the strip through the existing `_strip_node` is deliberate: the #1713/#1742
workflow-invariant urgent-park demand and the `GLOB_SCAN_TESTS` masking WARN then apply to an
ordering strip automatically, and its diff-linked masking clause is a live consistency assertion
(precondition 1 means it can never fire here).

**(e) `_CompareCtx` additions:** `paired_candidates: list[Node]`, `ordering_suspect: list[dict]`,
`paired_files_run: list[str]`, `paired_dropped_files: list[str]`, `paired_truncated: bool`,
`paired_skipped: list[dict]` (`{node_id, reason}` for every precondition miss — the audit trail that
makes a still-blocking NEW one-glance diagnosable).

**(f) `_compare_impl` payload + `cmd_compare` output.** Surface `ordering_suspect`,
`paired_files_run`, `paired_dropped_files`, `paired_truncated`, `paired_skipped`. Human-readable mode
prints one `ORDERING-SUSPECT: <file>::<name>` line per row and folds the count into the summary line.
**Exit semantics are unchanged and are NOT extended:** 0 = no NEW + no lint regression, 1 = NEW
and/or lint regression, 2 = indeterminate. An ordering-suspect node is stripped, so it does not
contribute to exit 1 — it is loud in `warns` + its own list instead.

**(g) New CLI flags** on the `compare` subparser: `--no-paired-pristine` (escape hatch, restores
today's behavior exactly) and `--max-paired-files` (int, default 30).

## 6. Risks and blast radius

| Risk | Mitigation |
|---|---|
| **Masking a real regression** (the only serious one) | The discriminator is a reproduction on pristine main, not a provenance rule; every precondition miss and every ambiguity resolves toward NEW. Fixture 2 pins the masking case directly. |
| Wall-time growth on the gate's critical path | At most ONE extra pytest invocation per compare, fired only when a node would otherwise be NEW *and* its file is untouched *and* the oracle is trustworthy — i.e. exactly the case that today costs a manual repro cycle. Bounded by `--max-paired-files` + a `recommended_timeout_s`-derived timeout. |
| Junit order ≠ execution order under a future `pytest-xdist` adoption | Documented in the new function's docstring with the current no-xdist evidence; a parallel run would break the prefix assumption toward *false PASS ⇒ NEW*, i.e. fail-closed. |
| Contract drift in `parse_junit` / the ledger | `parse_junit` is not modified; fixture 8 asserts its `summary` key set. |
| Textual conflict with sibling **#2019** (same target file, `use_scratch` eligibility region) | Recorded as a `merge-hold-candidate` note on this task for Step 10d Guard 5; loci are adjacent (`_resolve_pristine_bucket`) but semantically independent — whichever lands second rebases and re-runs the gate. |
