# Plan v1 — task #947: `verify_plan.py` c17 — paired-contrast per-arm source coverage

**Summary.** Add check **c17** (`check_paired_contrast_source_coverage`) to `scripts/verify_plan.py`: when a plan REGISTERS a paired contrast (registration vocabulary + `paired` on the same non-fenced line inside a registration-family section), the plan must carry a per-arm **row-coverage declaration** — a `Row-coverage:`-style line naming the per-context data source on BOTH arms, or a subset-assertion quote (the #810 v15 `set(registered_pair_rows) ⊆ union(keys(full_side_sources))` shape) — or the standalone escape `N/A — no paired contrast`. Absent all three: **FAIL (experiment) / WARN (analysis)**. Deterministic regex/line parsing, sub-second, no LLM/network. Founding incident: #810 plan v13 registered a 9-row paired bootstrap whose named full-side pack (`uh_summaries.pt`) lacked 2 of the 9 rows (`im_end`/`turn_nl`); four independent reviewers caught it only by reading pack row names by hand; v15 carried the mechanizable driver-assert shape inline.

`architectural: false` — an additive check inside an existing verifier; no CLI flag, marker schema, status enum, or subcommand changes (the only public-surface delta is one new result row in verify output, the same class as c12–c16 when they landed).

`Estimated GPU-hours (total): 0`

## 1. Goal, requirement, acceptance criteria

**Goal.** Every registered paired-contrast in an experiment/analysis plan must name, at the plan surface, a per-context data source on BOTH arms covering the registered rows — so a registered success criterion can never again be unsatisfiable from the named inputs without any mechanical signal (#810 v13: the falsification leg was uncomputable exactly when the `im_end`/`turn_nl` rows would have won).

**Requirement (the plan-side contract, satisfiable by real prose).** When c17's trigger fires, the plan PASSes iff ANY of:

- **D1 — row-coverage declaration line.** A non-fenced line containing `row-coverage` (hyphen or space) with **source evidence** on the same line or within the next 3 non-fenced lines: a data-artifact token (`*.pt/.pth/.json/.jsonl/.npz/.npy/.safetensors/.csv/.parquet/.arrow`, or an `eval_results/` / `analysis_tensors/` / `raw_completions/` path) **or** a by-construction phrase (both arms generated/computed/fit by this run). Real-prose example that PASSes: `Row-coverage: full arm = uh_summaries.pt (7 uh/bnd rows) + round-3 store (im_end, turn_nl); empty arm = he_summaries.pt (all 9 rows).`
- **D2 — subset-assertion line.** A non-fenced line carrying `⊆` / `issubset` / `is a subset of` together with row/pair vocabulary. This matches #810 v15 §4.6 item 4 verbatim: `ROW-COVERAGE SMOKE ASSERT (mechanizable): set(registered_pair_rows) ⊆ union(keys(full_side_sources)) …` (inline backtick code is NOT fence-masked — verified against `_fence_mask`, which toggles only on ```/~~~ delimiter lines).
- **N/A escape.** `N/A — no paired contrast` as a standalone declaration line (leading list/blockquote markers stripped, `re.match`-anchored via `NA_RE` — never a doc-global substring; the `_c13_na_escape_declared` convention). For spurious triggers (a plan that quotes a sibling's paired statistic without registering one).

**Scope limit (stated per the module's scope-discipline paragraph).** `verify_plan.py` cannot open HF packs or `.pt` files. c17 guarantees only that the coverage contract **SURFACE** exists — the plan DECLARES per-arm sources for the registered rows. Whether `uh_summaries.pt` truly contains `im_end` stays with the Phase 1.5 fact-checker (which does Hub reads) and the critic ensemble. A c17 PASS is never "coverage verified".

**Acceptance criteria** (also §5 Success criteria): the #810 v13 registration shape FAILs; the v15 shape PASSes; corpus replay shows 0 FAILs on plans with no genuine registered paired contrast and 0 FAILs on properly-declared plans; all existing verify_plan tests stay green; workflow_lint default run + ruff pass.

## 2. Method delta (vs c13, the closest sibling)

c13 (`check_empirical_gate_attainability`) is the template: conditional trigger via section-scoped, fence-masked line parsing; standalone-line N/A escape; FAIL(experiment)/WARN(analysis) kind-degrade; bounded FAIL detail with a copy-adaptable remedy menu; a "known accepted under-triggers" comment block. c17 reuses that machinery verbatim (same `_headings` / `_fence_mask` / `NA_RE` helpers, same result conventions) and differs in exactly three places:

1. **Evaluation core: presence, not arithmetic.** c13 harvests `n_draws` declarations and computes `1/(n+1) > alpha` — a violation computable at the plan surface. c17 CANNOT compute the violation (row membership lives inside a pack); it checks that the coverage **declaration** exists (D1/D2 disjunction). No table-harvesting analogue of `_n_draws_declarations` is needed.
2. **Trigger vocabulary.** c13 keys on `empirical` + `p ≤ alpha` in success/kill/evaluation sections. c17 keys on `paired` + registration vocabulary (or a pair-count) in a WIDER section family that adds `hypothes` and `nulls` — the observed #810 registrations live under `## 3. Hypothesis` (v13:33, the `**Registered per-row statistic:**` line) and in `**Nulls (registration).**` prose under `## 6. Evaluation` (v13:103).
3. **Paste-resistance mechanism.** c13's satisfier (the N/A phrase) is standalone-line-anchored, so quoting it in the FAIL detail is safe. c17's satisfiers D1/D2 are mid-line by corpus necessity (v15's declaration sits mid-way through one long list item), so c17 adds a **detail fingerprint guard**: the FAIL detail carries the literal substring `#810 v13 class`, and the D1/D2 matchers reject any candidate line containing it — a verbatim paste of the bounce text (the observed project convention) can never self-satisfy. Additionally the detail is written to be structurally self-unsatisfying (no artifact token, no by-construction phrase, no `⊆`/`issubset`), and a test pins both properties.

### 3.1 File: `scripts/verify_plan.py` — new block after c16 (~line 1954), before `CHECKS`

Constants (candidate regexes — calibration may tune, see §3.4):

```python
# ─── Check 17 — paired-contrast per-arm source coverage ────────────────────

# Registration-family sections: c13's success/kill/evaluation families PLUS
# hypothesis + nulls + statistic — the corpus registers paired statistics in
# `## 3. Hypothesis` blocks (#810 v13:33) and `**Nulls (registration).**`
# prose under Evaluation (#810 v13:103).
_C17_SECTION_RE = re.compile(
    r"(?i)hypothes|success criteri|acceptance criteri|decision rule|decision gate"
    r"|kill[- ]criteri|abort criteri|stop criteri|\bevaluation\b|\bnulls?\b|statistic"
)
_C17_PAIRED_RE = re.compile(r"(?i)\bpaired\b")
_C17_REGIST_RE = re.compile(r"(?i)\bregist")  # registered / registration / registers
_C17_PAIRCOUNT_RE = re.compile(r"(?i)\b\d[\d,]*\s+(?:pre-named\s+)?pairs\b")
# D1: a row-coverage declaration; evidence same line or next-3 forward window.
_C17_COVERAGE_RE = re.compile(r"(?i)\brow[- ]coverage\b")
_C17_ARTIFACT_RE = re.compile(
    r"(?i)\S+\.(?:pt|pth|json|jsonl|npz|npy|safetensors|csv|parquet|arrow)\b"
    r"|\beval_results/\S+|\banalysis_tensors/\S+|\braw_completions/\S+"
)
_C17_BYCONSTRUCTION_RE = re.compile(
    r"(?i)both arms .{0,60}\b(?:generated|produced|computed|fit(?:ted)?|emitted)\b"
    r"|\bby construction\b|\bthis run(?:'s)?\b"
)
# D2: the v15 driver-assert shape (inline code is not fence-masked).
_C17_SUBSET_RE = re.compile(r"(?i)⊆|\bissubset\b|\bis a subset of\b")
_C17_ROWPAIR_RE = re.compile(r"(?i)pair|row")
# Paste guard: the c17 FAIL detail carries this literal; any candidate
# declaration line containing it is rejected (verbatim-pasted bounce text
# must never self-satisfy — the #810 spurious-satisfaction trap).
_C17_PASTE_FINGERPRINT = "#810 v13 class"
_C17_DECL_WINDOW_LINES = 3
```

Helpers:

```python
def _c17_registered_paired_lines(plan: str) -> list[str]:
    """Non-fenced lines inside a registration-family section carrying `paired`
    plus registration vocabulary OR an enumerated pair count on the SAME line
    (#810 v13:33 'Registered per-row statistic: paired …(7 pairs…' and
    v13:103 'Nulls (registration)… paired bootstrap CI (… 9 pairs are
    pre-named' both match). Under-trigger fails safe (SKIP; critics review)."""
    lines = plan.splitlines()
    mask = _fence_mask(lines)
    headings = _headings(plan)
    hits: list[str] = []
    for i, (line, fenced) in enumerate(zip(lines, mask, strict=True)):
        if fenced or not _C17_PAIRED_RE.search(line):
            continue
        if not (_C17_REGIST_RE.search(line) or _C17_PAIRCOUNT_RE.search(line)):
            continue
        if not any(h.line <= i < h.end and _C17_SECTION_RE.search(h.text) for h in headings):
            continue
        hits.append(line.strip())
    return hits


def _c17_coverage_declarations(plan: str) -> list[str]:
    """Lines satisfying D1 (row-coverage vocab + source evidence, same line or
    next _C17_DECL_WINDOW_LINES non-fenced lines) or D2 (subset expression +
    row/pair vocab, same line). Fingerprint-bearing lines rejected (paste guard)."""
    lines = plan.splitlines()
    mask = _fence_mask(lines)
    out: list[str] = []
    for i, (line, fenced) in enumerate(zip(lines, mask, strict=True)):
        if fenced or _C17_PASTE_FINGERPRINT in line:
            continue
        if _C17_SUBSET_RE.search(line) and _C17_ROWPAIR_RE.search(line):
            out.append(line.strip()); continue
        if _C17_COVERAGE_RE.search(line):
            window = [line] + [
                lines[j] for j in range(i + 1, min(i + 1 + _C17_DECL_WINDOW_LINES, len(lines)))
                if not mask[j]
            ]
            if any(
                _C17_ARTIFACT_RE.search(w) or _C17_BYCONSTRUCTION_RE.search(w) for w in window
            ):
                out.append(line.strip())
    return out
```

N/A escape via a **shared** helper: add `_standalone_na_declared(plan: str, tail_re: str) -> bool` (the generalized body of `_c13_na_escape_declared`: per-line `re.match(NA_RE + tail_re, line.lstrip(" \t>*-"))` over non-fenced lines; NA_RE stays at pattern position 0 per its inline-`(?i)` constraint), rewire `_c13_na_escape_declared` to a one-line call (behavior-identical, pinned by existing c13 tests — the Supersede rule: no two copies of the same job), and add `_c17_na_escape_declared(plan)` = `_standalone_na_declared(plan, r"no paired contrast")`.

The check:

```python
def check_paired_contrast_source_coverage(plan: str, kind: str) -> CheckResult:
    """A registered paired contrast (a hypothesis/evaluation/success-section
    line registering a paired statistic over enumerable rows/pairs) must
    DECLARE a per-context data source on BOTH arms covering the registered
    rows (D1 row-coverage line / D2 subset-assert / standalone N/A). Surface
    check only — pack contents stay with the fact-checker. FAIL (experiment) /
    WARN (analysis) / SKIP otherwise. Incident: #810 v13 (9-row paired
    bootstrap; named full-side pack lacked im_end/turn_nl; 4 reviewer catches)."""
    cid, name = "c17_paired_contrast_source_coverage", "paired-contrast per-arm source coverage"
    if kind not in ("experiment", "analysis"):
        return _skip(cid, name, "kind-exempt: registered paired contrasts are an experiment|analysis plan shape")
    triggers = _c17_registered_paired_lines(plan)
    if not triggers:
        return _skip(cid, name, "no registered paired contrast detected")
    if _c17_na_escape_declared(plan):
        return _pass(cid, name, "explicit N/A declared (no paired contrast)")
    decls = _c17_coverage_declarations(plan)
    if decls:
        return _pass(cid, name,
            f'per-arm row-coverage declaration found ("{decls[0][:90]}") — declaration surface '
            "only; whether the named sources truly contain every registered row stays with the "
            "fact-checker")
    detail = (
        f'plan registers a paired contrast ("{triggers[0][:90]}") with no per-arm row-coverage '
        "declaration — a registered pair row absent from a named side makes the registered "
        "criterion unsatisfiable from the named inputs (the #810 v13 class: 2 of 9 rows missing "
        "from the named full side). Remedy: add ONE non-fenced line starting 'Row-coverage:' "
        "naming, for BOTH arms, which per-context store/file supplies every registered row "
        "(or that the arms are outputs of the plan's own fits), or quote the driver assert "
        "that set-checks registered rows against source keys, or declare "
        "'N/A — no paired contrast' on its own line"
    )
    if kind == "analysis":
        return _warn(cid, name, detail + " (analysis kind-degrade: WARN, not FAIL)")
    return _fail(cid, name, detail)
```

Note the detail is structurally self-unsatisfying: it contains `row-coverage` vocabulary but no artifact-extension token, no by-construction phrase (deliberately "the plan's own fits", not "this run"), no `⊆`/`issubset` — AND it carries the `#810 v13 class` fingerprint the matchers reject. Both properties test-pinned (§3.3).

**Known accepted mis-triggers comment block** (mirroring c13's (a)–(e)): under-triggers that fail SAFE (SKIP → the critics still review): (a) a paired registration line without `regist`/pair-count vocabulary; (b) registration under a heading outside the section family; (c) a hard-wrapped registration (paired and regist on different lines). Over-trigger that fails LOUD (bounce, escapable): (d) a Hypothesis-section line merely RECAPPING a sibling's registered paired statistic — remedied by the N/A line. Fail-UNSAFE residuals, accepted: (e) a D1/D2-shaped declaration that doesn't actually cover the registered rows — semantic truth is explicitly out of scope (fact-checker); (f) a NON-verbatim paraphrase of the bounce text that reconstructs a satisfying shape while dropping the fingerprint — beyond mechanical defense, same residual class as a dishonest c13 N/A line.

## 6. Kill criteria

- **Trigger unparseable:** if after two tuning rounds the trigger cannot reach ≥90% audit precision, real plan prose is too variable for a FAIL-capable trigger → demote c17 to WARN-only (one-line `_fail`→`_warn` change; record the named upgrade condition: promote to FAIL once planner.md §6's statistical-input-existence block formally mandates the row-coverage line for paired contrasts).
- **Contract unsatisfiable by real prose:** if calibration finds properly-declared corpus plans that no reasonable D1/D2 matcher accepts without also accepting incidental prose (the v13:218 "the paired table covers all 9 rows" reporting shape), fall back to the brief's named fallback — the check requires the explicit machine-readable declaration line only (`Row-coverage:` line-start-anchored form) and FAILs solely on its absence-when-triggered.
- **Fundamental infeasibility** (no deterministic trigger separates registered paired contrasts from prose mentions at all): deflect with a reasoned no-change report per the workflow-fix planner-deflection path — do not land a noise generator.

## 11. Decision Rationale

- **Trigger = section-scoped, same-line `paired` + (`regist` | pair-count).** *Why:* both #810 registrations match it (v13:33 "Registered per-row statistic: paired…(7 pairs…"; v13:103 "Nulls (registration)… paired bootstrap CI (…9 pairs are pre-named"), while the noisy `paired` mentions in §9 battery arithmetic (v13:154 "Paired bootstrap = 2,000 draws × 9 rows") fall outside the section family and lack `regist`. Same-line co-location follows c13's measured "repo plans favor long single lines" observation. *Source:* `verify_plan.py` c13 precedent (`_c13_registered_gates`, the §4.5 under-trigger doctrine) + #810 plans v13/v15 read this session; precision claim `ungrounded — calibration step will validate` (§3.4).
- **Section family adds `hypothes` + `nulls` + `statistic` to c13's set.** *Why:* the founding registration lives under `## 3. Hypothesis`, not success-criteria; c13's family alone would under-trigger on the exact incident. *Source:* #810 v13 headings (read: line 31 `## 3. Hypothesis`, line 93 `## 6. Evaluation`).
- **Classification: FAIL (experiment) / WARN (analysis).** *Why:* c17 guards the same stake class as c13 — a REGISTERED criterion unsatisfiable/unverifiable from the plan surface — not narration quality (the c14/c15/c16 WARN-only family). The remedy is one honest line, copy-adaptable from the detail; the trigger is two-key + section-scoped (near-zero "not actually a paired contrast" residue, and that residue has the N/A escape); the PASS-with-override valve bounds any residual false FAIL at 1–2 mechanical bounces. *Alternative considered and rejected:* WARN-first rollout — rejected because plan-WARNs rely on the fact-checker re-doing exactly the reviewer legwork the incident showed is expensive (four independent catches), and both the founding candidate sketch and the check's purpose specify a blocking outcome for the v13 shape; the WARN demotion survives as the kill-criterion fallback with a named upgrade condition. *Source:* c13 FAIL/WARN precedent; #947 task body candidate sketch.
- **Contract = D1/D2/N-A disjunction (declaration surface), not row-set arithmetic.** *Why:* mapping prose like "full side for the 7 uh/bnd rows" onto enumerated row names requires semantics regex cannot supply; verify_plan cannot open packs regardless. D1 accepts natural prose (including the run-generated-both-arms case via the by-construction clause, so no boilerplate lie is ever required); D2 accepts the v15 mechanizable shape verbatim. *Source:* #810 v15:71 (the reviewer-converged shape); the module's scope-discipline paragraph; task-brief kill-criterion fallback.
- **Paste-resistance = fingerprint rejection + self-unsatisfying detail.** *Why:* c17's satisfiers are mid-line by corpus necessity, so c13's standalone-line anchoring cannot protect them; the project convention pastes bounce text verbatim into revised plans (the c13 docstring's #810 spurious-satisfaction note), so the detail must be inert under verbatim paste. Two independent guards + a test pin. *Source:* `_c13_na_escape_declared` docstring; #810 incident structure.
- **Forward-only 3-line evidence window for D1.** *Why:* accepts the multi-line `Row-coverage:` header + per-arm bullet shape without opening a doc-global window (which would let any nearby artifact token satisfy); 3 matches `_C16_WINDOW_LINES` precedent. *Source:* c16 window precedent; `ungrounded — calibration step will validate`.
