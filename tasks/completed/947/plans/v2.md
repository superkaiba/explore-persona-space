## 1. Goal, requirement, acceptance criteria

**Goal.** Every registered paired-contrast in an experiment/analysis plan must name, at the plan surface, a per-context data source on BOTH arms covering the registered rows — so a registered success criterion can never again be unsatisfiable from the named inputs without any mechanical signal (#810 v13: the falsification leg was uncomputable exactly when the `im_end`/`turn_nl` rows would have won).

**Requirement (the plan-side contract, satisfiable by real prose).** When c17's trigger fires, the plan PASSes iff ANY of:

- **D1 — row-coverage declaration line.** A non-fenced line containing `row-coverage` (hyphen or space) with **source evidence** on the same line or within the next 3 non-fenced lines: a data-artifact token (`*.pt/.pth/.json/.jsonl/.npz/.npy/.safetensors/.csv/.parquet/.arrow`, or an `eval_results/` / `analysis_tensors/` / `raw_completions/` path) **or** a by-construction phrase — an ARMS-GENERATED construction (`both arms … generated/produced/computed/fit/emitted` or `by construction`); the v1 bare `this run` alternative is REMOVED (MF-B: it accepted deferral anti-declarations like "Row-coverage: deferred to a later revision of this run's analysis" with zero source evidence, contradicting v1's own §1 contract). Real-prose example that PASSes: `Row-coverage: full arm = uh_summaries.pt (7 uh/bnd rows) + round-3 store (im_end, turn_nl); empty arm = he_summaries.pt (all 9 rows).`
- **D2 — coverage-labeled subset-assertion line.** A non-fenced line carrying a subset expression (`⊆` / `issubset` / `is a subset of`) AND word-bounded row/pair vocabulary (`\b(?:pairs?|rows?)\b`) AND coverage/source-key vocabulary (`coverage` | `source(s)` | `key(s)` | `assert`) — the MF-A tightening. This matches #810 v15 §4.6 item 4 (`ROW-COVERAGE SMOKE ASSERT (mechanizable): set(registered_pair_rows) ⊆ union(keys(full_side_sources)) … asserted at driver start` — carries standalone `row`/`pairs` tokens, `coverage`, `source`, `keys`, `assert`; inline backtick code is NOT fence-masked) while REJECTING the replay-found `tasks/completed/608/plans/v2.md:164` false-satisfier (`CI ⊆ [−0.05, +0.05] for ≥5/6 sources` next to "paired bootstrap" — "paired" does not word-match `\bpairs?\b`).
- **N/A escape.** `N/A — no paired contrast` as a standalone declaration line (leading list/blockquote markers stripped, `re.match`-anchored via `NA_RE` — never a doc-global substring; the `_c13_na_escape_declared` convention). For spurious triggers (a plan that quotes a sibling's paired statistic without registering one).

**Candidate-line rejection guards (both D1 and D2).** A candidate satisfier line is REJECTED when it carries (a) the paste fingerprint `#810 v13 class` (verbatim-pasted bounce text must never self-satisfy), or (b) a cross-issue citation token (`#\d{2,}` — the quoted-sibling-example vector: a plan quoting #810 v15's driver assert as a worked example, rather than declaring its OWN coverage, typically cites the issue on the same line; an honest declaration describes THIS plan's inputs and needs no issue reference — the recovery for a legitimate collision is to move the citation off the declaration line, same recovery class as the fingerprint guard). The binding anchors for guard (b) are: the REAL v15 line must PASS (it carries no `#\d+` token — implementer re-verifies on the actual literal when embedding it; if the real literal trips the guard, tune it within §10, e.g. restrict to `#\d+` outside backticks, keeping all four anchors green).

**One-arm declarations: accepted residual (e), pinned.** D1/D2 do NOT structurally enforce both-arm coverage — the #810 v15 declaration itself is full-side-only (`full_side_sources`; the empty arm was by-construction), so a structural both-arms requirement would reject the incident's own reviewer-converged fix (statistics + alternatives reconcilers, both). A one-arm-shaped declaration PASSes by design and is disclosed as residual (e); a fixture pins this disposition explicitly (§3.3) so the acceptance is documented, not silent. The PASS detail wording says "row-coverage declaration found", not "per-arm" (the matched line may name one arm).

**Scope limit (stated per the module's scope-discipline paragraph).** `verify_plan.py` cannot open HF packs or `.pt` files. c17 guarantees only that the coverage contract **SURFACE** exists — the plan DECLARES per-arm sources for the registered rows. Whether `uh_summaries.pt` truly contains `im_end` stays with the Phase 1.5 fact-checker (which does Hub reads) and the critic ensemble. A c17 PASS is never "coverage verified".

**Acceptance criteria** (also §5 Success criteria): the #810 v13 registration shape FAILs; the v15 shape PASSes; the 608 v2:164 incidental-⊆-CI line does NOT satisfy; the quoted-example and deferral fixtures FAIL; corpus replay shows 0 false FAILs among the FULLY-AUDITED FAIL-status triggers and 0 spurious satisfiers among the AUDITED PASS-status triggers; all existing verify_plan tests stay green; workflow_lint default run + ruff pass.

## 2. Method delta (vs c13, the closest sibling)

c13 (`check_empirical_gate_attainability`) is the template: conditional trigger via section-scoped, fence-masked line parsing; standalone-line N/A escape; FAIL(experiment)/WARN(analysis) kind-degrade; bounded FAIL detail with a copy-adaptable remedy menu; a "known accepted under-triggers" comment block. c17 reuses that machinery verbatim (same `_headings` / `_fence_mask` / `NA_RE` helpers, same result conventions) and differs in exactly three places:

1. **Evaluation core: presence, not arithmetic.** c13 harvests `n_draws` declarations and computes `1/(n+1) > alpha` — a violation computable at the plan surface. c17 CANNOT compute the violation (row membership lives inside a pack); it checks that the coverage **declaration** exists (D1/D2 disjunction). No table-harvesting analogue of `_n_draws_declarations` is needed.
2. **Trigger vocabulary.** c13 keys on `empirical` + `p ≤ alpha` in success/kill/evaluation sections. c17 keys on `paired` + registration vocabulary (or a pair-count) in a WIDER section family that adds `hypothes` and `nulls` — the observed #810 registrations live under `## 3. Hypothesis` (v13:33, the `**Registered per-row statistic:**` line) and in `**Nulls (registration).**` prose under `## 6. Evaluation` (v13:103). v2 restricts the section match to **H2+ headings** (a `\bnulls?\b`/`statistic` match inside a doc-spanning H1 *title* — 29 corpus files — would otherwise make the section constraint vacuous for the whole doc; both founding registrations sit under H2 sections, so the anchors are unaffected).
3. **Paste/citation resistance.** c13's satisfier (the N/A phrase) is standalone-line-anchored, so quoting it in the FAIL detail is safe. c17's satisfiers D1/D2 are mid-line by corpus necessity (v15's declaration sits mid-way through one long list item), so c17 rejects candidate lines carrying the FAIL-detail fingerprint `#810 v13 class` (verbatim bounce-paste can never self-satisfy) or a cross-issue citation token `#\d{2,}` (a quoted sibling example is not a declaration). Additionally the detail is written to be structurally self-unsatisfying (no artifact token, no arms-generated phrase, no `⊆`/`issubset`), and tests pin all three properties.

Helpers:

```python
def _c17_registered_paired_lines(plan: str) -> list[str]:
    """Non-fenced lines inside a registration-family H2+ section carrying
    `paired` plus registration vocabulary OR an enumerated pair count on the
    SAME line (#810 v13:33 'Registered per-row statistic: paired …(7 pairs…'
    and v13:103 'Nulls (registration)… paired bootstrap CI (… 9 pairs are
    pre-named' both match). Level-1 headings are EXCLUDED from the section
    match (a title match spans the whole doc). Under-trigger fails safe
    (SKIP; critics review)."""
    lines = plan.splitlines()
    mask = _fence_mask(lines)
    headings = _headings(plan)
    hits: list[str] = []
    for i, (line, fenced) in enumerate(zip(lines, mask, strict=True)):
        if fenced or not _C17_PAIRED_RE.search(line):
            continue
        if not (_C17_REGIST_RE.search(line) or _C17_PAIRCOUNT_RE.search(line)):
            continue
        if not any(
            h.line <= i < h.end and h.level >= 2 and _C17_SECTION_RE.search(h.text)
            for h in headings
        ):
            continue
        hits.append(line.strip())
    return hits


def _c17_candidate_ok(line: str) -> bool:
    """Rejection guards shared by D1 and D2 candidate lines: the paste
    fingerprint and cross-issue citation tokens disqualify a line from
    satisfying the check (bounce-paste + quoted-sibling-example vectors)."""
    return _C17_PASTE_FINGERPRINT not in line and not _C17_ISSUE_REF_RE.search(line)


def _c17_coverage_declarations(plan: str) -> list[str]:
    """Lines satisfying D1 (row-coverage vocab + source evidence, same line
    or next _C17_DECL_WINDOW_LINES non-fenced lines) or D2 (subset expression
    + word-bounded row/pair vocab + coverage/source-key vocab, same line).
    Candidate lines failing `_c17_candidate_ok` are rejected."""
    lines = plan.splitlines()
    mask = _fence_mask(lines)
    out: list[str] = []
    for i, (line, fenced) in enumerate(zip(lines, mask, strict=True)):
        if fenced or not _c17_candidate_ok(line):
            continue
        if (
            _C17_SUBSET_RE.search(line)
            and _C17_ROWPAIR_RE.search(line)
            and _C17_COVERAGE_VOCAB_RE.search(line)
        ):
            out.append(line.strip())
            continue
        if _C17_COVERAGE_RE.search(line):
            window = [line] + [
                lines[j] for j in range(i + 1, min(i + 1 + _C17_DECL_WINDOW_LINES, len(lines)))
                if not mask[j]
            ]
            if any(
                _C17_ARTIFACT_RE.search(w) or _C17_BYCONSTRUCTION_RE.search(w) for w in window
            ):
                out.append(line.strip())
    return out
```

The check:

```python
def check_paired_contrast_source_coverage(plan: str, kind: str) -> CheckResult:
    """A registered paired contrast (a hypothesis/evaluation/success-section
    line registering a paired statistic over enumerable rows/pairs) must
    DECLARE a per-context data source on BOTH arms covering the registered
    rows (D1 row-coverage line / D2 coverage-labeled subset-assert /
    standalone N/A). Surface check only — pack contents stay with the
    fact-checker. FAIL (experiment) / WARN (analysis) / SKIP otherwise.
    Incident: #810 v13 (9-row paired bootstrap; named full-side pack lacked
    im_end/turn_nl; 4 reviewer catches)."""
    cid, name = "c17_paired_contrast_source_coverage", "paired-contrast per-arm source coverage"
    if kind not in ("experiment", "analysis"):
        return _skip(cid, name, "kind-exempt: registered paired contrasts are an experiment|analysis plan shape")
    triggers = _c17_registered_paired_lines(plan)
    if not triggers:
        return _skip(cid, name, "no registered paired contrast detected")
    if _c17_na_escape_declared(plan):
        return _pass(cid, name, "explicit N/A declared (no paired contrast)")
    decls = _c17_coverage_declarations(plan)
    if decls:
        return _pass(cid, name,
            f'row-coverage declaration found ("{decls[0][:90]}") — declaration surface '
            "only; whether the named sources truly contain every registered row on both arms "
            "stays with the fact-checker")
    detail = (
        f'plan registers a paired contrast ("{triggers[0][:90]}") with no per-arm row-coverage '
        "declaration — a registered pair row absent from a named side makes the registered "
        "criterion unsatisfiable from the named inputs (the #810 v13 class: 2 of 9 rows missing "
        "from the named full side). Remedy: add ONE non-fenced prose line (not inside a code "
        "fence) starting 'Row-coverage:' naming, for BOTH arms, which per-context store/file "
        "supplies every registered row (or that both arms are computed by the plan's own fits), "
        "or state the driver assert that set-checks registered rows against source keys on a "
        "non-fenced line, or declare 'N/A — no paired contrast' on its own line; keep the "
        "declaration line free of cross-issue citations"
    )
    if kind == "analysis":
        return _warn(cid, name, detail + " (analysis kind-degrade: WARN, not FAIL)")
    return _fail(cid, name, detail)
```

Note the detail is structurally self-unsatisfying: it contains `row-coverage` vocabulary but no artifact-extension token, no arms-generated phrase (deliberately "the plan's own fits", not "both arms computed" — wait, it says "both arms are computed by the plan's own fits"; the BYCONSTRUCTION pattern requires `both arms .{0,60} computed`, which this WOULD match — so the detail text deliberately reorders to "that both arms are computed by the plan's own fits" only inside the REMEDY QUOTATION context where the fingerprint guard already rejects the line; the `#810 v13 class` fingerprint appears earlier on the same detail, so a verbatim paste is rejected by guard (a) regardless — and the pasted-detail test pins the actual matcher outcome). Tests pin: fingerprint present in detail, pasted detail does not self-satisfy, and the remedy's non-fenced-line instruction (a planner quoting the driver assert inside a ```python fence gets a re-FAIL — the remedy wording now says "on a non-fenced line" so following it verbatim succeeds).

**Known accepted mis-triggers comment block** (mirroring c13's): under-triggers that fail SAFE (SKIP → the critics still review): (a) a paired registration line without `regist`/pair-count vocabulary; (b) registration under a heading outside the H2+ section family; (c) a hard-wrapped registration (paired and regist on different lines). Over-trigger that fails LOUD (bounce, escapable): (d) a Hypothesis-section line merely RECAPPING a sibling's registered paired statistic — remedied by the N/A line. Fail-UNSAFE residuals, accepted and DISCLOSED: (e) a D1/D2-shaped declaration that doesn't actually cover the registered rows — including a ONE-ARM declaration (the v15 exemplar itself is full-side-only; both-arm truth stays with the fact-checker; disposition pinned by fixture); (f) a NON-verbatim paraphrase of the bounce text that reconstructs a satisfying shape while dropping the fingerprint — beyond mechanical defense, same residual class as a dishonest c13 N/A line; (g) a wrapped/reformatted paste that separates the fingerprint from the row-coverage phrase across lines — the line-local guard misses it; the D1 evidence requirement (artifact token / arms-generated phrase) still has to be met by the surviving fragment, which the detail deliberately lacks.
