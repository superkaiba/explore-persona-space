## 1. Goal + acceptance criteria

- VM (main-checkout) behavior stays byte-identical (same stdout/stderr, same deletions, same exit codes, same sidecar path; the only delta is ≤2 extra cached read-only git subprocesses per process),

## 3. Design

### 3.1 Detection (design question 1)

**A cheap explicit probe, not try/except message-matching.** New helper `_off_main_checkout_root() -> Path | None`:

- Resolve the PRIMARY checkout via `task_workflow.primary_checkout_root()` (no branch guard). On `RuntimeError` (git missing / bad layout / no `tasks/`) return `None` — the downstream `repo_root()` call then raises today's loud error unchanged (nothing swallowed; the error surfaces at the same site with the same message).
- Read the primary checkout's branch with a new `_checkout_branch(checkout: Path) -> str | None` (`git -C <checkout> symbolic-ref --short HEAD`, `check=False`, `timeout=30`; rc≠0 / empty / OSError / timeout → `None` = detached-or-unreadable).
- `branch is None or branch == "main"` → `None` (normal path; a detached primary keeps today's loud `repo_root()` "HEAD is detached" RuntimeError).
- `is_shared_vm_env()` True → print a loud stderr WARNING ("primary checkout on '<branch>' on the SHARED VM — refusing the #924 off-main degrade; the consumer gate must not be skipped on a shared tasks/ tree") and return `None` — the pathological VM-off-main state keeps today's behavior exactly.
- Otherwise → return the primary checkout path (the clone root).

Decorate with `@functools.lru_cache(maxsize=1)` (same pattern as `task_workflow.py:324/559`); tests use `.cache_clear()`.

**Scope of the probe (v2 — round-1 alternatives reconcile):** a non-None probe licenses the LOCAL-RESOLVE of the four RESOLUTION sites only (§3.3 rows 2-5). It does NOT by itself license skipping the consumer gate: the probe predicate (`branch != main` ∧ not shared-VM) also fires on topologies where the gate read still WORKS — a full clone with a local `main` routes `repo_root()` through a pin worktree that `_ensure_managed_main_worktree` re-syncs to the current `main` tip per call (`task_workflow.py:509-515`), so the #773 read there sees a fresh, real `tasks/` tree. Gate 1 therefore ATTEMPTS the read whenever the probe is non-None and skips only when the read raises `RuntimeError` (the branch-guard raise — the structural GCE `--depth 1 --branch` shape). "Genuinely unserviceable, not merely off-main."

Why this beats the two alternatives (also §11):

- *try/except the specific RuntimeError at each site*: brittle string/type matching across 5 scattered sites, AND blind to the full-clone shape where `repo_root()` does not raise but silently routes to a `_task-main-pin` worktree with an empty `data/` (wrong-root silent no-op + a `git worktree add` mutation on the remote instance). The probe classifies both shapes correctly before any resolution runs.
- *`Path(__file__).resolve().parents[1]` / `git rev-parse --show-toplevel` from the script's own dir*: misclassifies VM worktree invocations — a run launched from `.claude/worktrees/issue-<N>/` executes the worktree's `scripts/` copy on branch `issue-<N>`, but its git COMMON dir parent is the repo root on `main`; the common-dir-based `primary_checkout_root()` resolves that correctly (per the gotchas "`--show-toplevel` returns the WORKTREE root" entry), a `__file__`/toplevel approach would wrongly degrade the VM path.

### 3.2 Root resolution off-main (design question 2)

New helper:

```python
def _resolution_root() -> Path:
    """repo_root() on the primary-on-main VM; the checkout root on an off-main remote clone (#924)."""
    off = _off_main_checkout_root()
    return off if off is not None else repo_root()
```

On the VM this is exactly `repo_root()` (probe returns `None`) — byte-identical. Off-main it is the clone root (e.g. `/workspace/eps-issue-841`), where the caches genuinely live.

**New helpers (place after `_running_pod_side`, ~`:230`):**

```python
def _checkout_branch(checkout: Path) -> str | None:
    """Attached branch name of ``checkout``'s HEAD, or None (detached / unreadable).

    Runs under a sanitized git env (GIT_DIR / GIT_WORK_TREE cleared) so the
    probe reads the SAME repo primary_checkout_root() resolved — a leaked
    GIT_DIR would silently point the two at different repos (v2, critic
    concern). Reuse task_workflow's sanitizer if importable, else clear the
    two vars on a copied os.environ.
    """
    env = {k: v for k, v in os.environ.items() if k not in ("GIT_DIR", "GIT_WORK_TREE")}
    try:
        proc = subprocess.run(
            ["git", "-C", str(checkout), "symbolic-ref", "--short", "HEAD"],
            capture_output=True, text=True, check=False, timeout=30, env=env,
        )
    except (OSError, subprocess.TimeoutExpired):
        return None
    if proc.returncode != 0:
        return None
    return proc.stdout.strip() or None


@functools.lru_cache(maxsize=1)
def _off_main_checkout_root() -> Path | None:
    """Root of a NON-main remote checkout (GCE/pod issue-branch clone), else None (#924).

    None  => normal path: every resolution goes through task_workflow.repo_root().
    Path  => degrade gracefully: data/, the worktree scan root, the sidecar, and
             display names resolve against THIS checkout; the cross-task
             active-consumer read is ATTEMPTED and its branch-guard RuntimeError
             (the no-local-main clone shape) is caught at the gate-1 call site
             only — a succeeding read keeps the gate ON (#924 v2).

    Detection reads the PRIMARY checkout (git common-dir parent, NOT the script's
    own dir — a VM worktree invocation must still resolve the repo root). The
    SHARED VM never degrades (is_shared_vm_env() conjunct): a pathologically
    off-main VM keeps today's loud repo_root() behavior rather than silently
    skipping the consumer gate on a shared tasks/ tree. Detached HEAD or an
    unresolvable layout also returns None (repo_root() then raises its own
    loud, unchanged error).
    """
    try:
        primary = primary_checkout_root()
    except RuntimeError:
        return None  # unresolvable layout: let repo_root() raise its own loud error
    branch = _checkout_branch(primary)
    if branch is None or branch == "main":
        return None
    if is_shared_vm_env():
        print(
            f"  WARNING: primary checkout {primary} is on {branch!r} on the SHARED VM — "
            f"refusing the #924 off-main degrade (the active-consumer gate must not be "
            f"skipped on a shared tasks/ tree); falling through to repo_root().",
            file=sys.stderr,
        )
        return None
    return primary


def _resolution_root() -> Path:
    """repo_root() on the primary-on-main VM; the checkout root off-main (#924)."""
    off = _off_main_checkout_root()
    return off if off is not None else repo_root()
```

### 3.5 #803 pod interaction (design question 4)

`main()` is untouched: the pod check (`_running_pod_side()`, `:962-967`) stays FIRST and keeps its exact no-op semantics — pods have no reap-worthy `data/` caches (HF_HOME redirected) and `repo_root()` HANGS there, so the fast no-op remains correct. GCE detection is deliberately **separate and NOT in `main()`**: it lives at the resolution layer, consulted lazily by the five sites, because unlike the pod case the off-main case must still RUN the full cleanup. The two signals answer different failure modes: pod (dockerenv ∧ logs) = "resolution hangs, nothing to reap → no-op"; off-main probe = "resolution raises/misroutes, real caches exist → local-resolve + gate skip". Ordering consequence: on the CLI path the probe never even executes pod-side (the no-op returns before argparse). Side note (strict improvement, no contract change): a hypothetical pod-side LIBRARY caller of `clean_issue_downloads` today hangs at `repo_root()`; post-change it degrades to a safe checkout-local reap (`symbolic-ref`/`rev-parse` are read-only and were never the #803 hang — the hang was `worktree add`/`reset --hard`). The #803 CLI contract is preserved verbatim.

## 11. Decision Rationale

1. **Detection = `primary_checkout_root()` + attached-branch probe (not per-site try/except).** *Why:* one classification point covers all 5 sites AND both remote-clone shapes — the observed raise shape (`--depth 1 --branch` clone, no local `main`; `backends/gcp.py:1820` + the #841 traceback) and the latent full-clone shape where `repo_root()` silently routes to an empty-`data/` pin worktree (a wrong-root no-op + a `git worktree add` mutation) instead of raising. Exception-message matching at 5 sites is brittle and blind to the second shape. *Source:* `task_workflow.py:539-576` (read this session); `backends/gcp.py:1820`; #841 att-6 traceback in the task body. *Alternatives rejected:* per-site `except RuntimeError` (brittle, misses routing shape); `__file__`/`--show-toplevel` (misclassifies VM worktree invocations — gotchas "worktree `--show-toplevel`" entry + `_resolve_primary_checkout`'s module-dir common-dir resolution).
2. **Shared-VM refusal conjunct via `is_shared_vm_env()`.** *Why:* the "empty protected set is safe" argument holds ONLY on a single-task remote instance; on the shared VM an off-main primary is a pathological state where skipping the consumer gate could reap a sibling's declared inputs — keep today's loud behavior there. *Source:* `orchestrate/env.py:118-139` (#847 positive detection, fails open on GCE/pods); task-body constraint wording ("on a single-task remote instance there are no sibling consumers").
3. **ATTEMPT-AND-CATCH (v2; not probe-keyed skip, not stale-read) for the consumer gate off-main.** *Why:* the round-1 alternatives reconcile (binding) verified that on a full clone with a local `main`, today's `repo_root()` routing serves the gate a FRESH-main `tasks/` tree via the re-synced pin worktree (`task_workflow.py:509-515`) — the gate there is functional, and a probe-keyed skip would newly convert gate-on-no-deletion into gate-off-deletion (the #742 live-consumer-strand class). Attempting the read and catching only its `RuntimeError` makes the skip fire exactly when the read is genuinely unserviceable (the GCE no-local-`main` raise shape). Reading the clone's own branch-frozen `tasks/` tree directly is still rejected (stale statuses = false protection). *Source:* `epm:plan-critique-reconcile v1` (round-1 alternatives, binding); `task_workflow.py:454-523`; task-body constraint; `#773` gate semantics (`clean_experiment_downloads.py:517-586`).
4. **LOCAL-RESOLVE (not no-op) for data/worktree/sidecar/display roots.** *Why:* GCE clones hold real reap-worthy caches on the boot disk (clarifier fact 4: `/workspace/eps-issue-841/data/issue_841/hf_dl`); a blanket no-op (the #803 pod answer) defeats the between-phase disk-hygiene Goal — the #841 incident is precisely peak-footprint pressure. Sidecar kept checkout-local because `append_disk_guard_event` is fail-soft by construction (`:238-257`, #679 pattern). *Source:* #803 guard docstring in the same file (`:216-230`) for why the pod is different; #679 sidecar contract.
5. **Preserve the #803 pod no-op verbatim; degrade is resolution-layer, not `main()`-layer.** *Why:* pods have no reap-worthy repo-relative caches (HF_HOME → `/workspace/.cache`) and `repo_root()` hangs rather than raises there; the off-main case must still run the cleanup, so a `main()` branch would duplicate dispatch. *Source:* #803 guard + `main()` `:955-967`; brief's safe-default instruction.
6. **`functools.lru_cache(maxsize=1)` on the probe.** *Why:* `_rel_name` runs per cache dir/event; cache once per process, `cache_clear()` for tests. *Source:* same pattern at `task_workflow.py:324/559`.
7. **Sanitized git env in `_checkout_branch` (v2).** *Why:* `primary_checkout_root()` resolves under `_sanitized_git_env()`; a leaked `GIT_DIR`/`GIT_WORK_TREE` would make the branch probe read a DIFFERENT repo than the one the resolver classified. Clear the two vars on a copied environ (or reuse the sanitizer). *Source:* round-1 Claude alternatives-critic concern; `task_workflow.py` `_sanitized_git_env` usage.
