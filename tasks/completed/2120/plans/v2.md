# Plan v2 — task #2120 `daily-fix: CVD-scoped nvidia-smi + schema-from-artifact`

`kind: infra` · `wf-fix` · workflow-surface edit · 0 GPU-h

## 0.0 TL;DR (plain English)

Two things bit us and neither had a check that would have caught them. First, a
teardown routine asked "is the GPU drained?" by looking at **every** GPU on the
host instead of only the ones its own job was given — a sibling job's leftover
memory made it conclude "not drained", and 4 of 9 jobs died. Second, an
implementer wrote code to read a banked data file whose field names it had
**guessed from memory** rather than opened — the pipeline couldn't load its own
input and crashed after ~4.5 h of expensive compute. This plan adds one
reviewer gate for the first (a GPU-state verdict must be scoped to the job's
own GPUs) and one implementer duty for the second (open one real file and paste
its actual keys before writing the loader), each with a mechanical lint pin and
a pin test so a future refactor can't silently strip them.

## 2. Prior Work

**Incident 1 (Item 1) — #2091, commit `2cc130dbff`.**
`scripts/issue2091_pod.py::reap_generation_engine` took `max()` of
`memory.used` across all 4 host GPUs to decide whether vLLM had drained. 4 of
9 rung-jobs died with:

> `RuntimeError: vLLM teardown did not drain below 2048 MiB within 180s`
> `(per-GPU used MiB: [(0, 35579), (1, 19143), (2, 0), (3, 0)])`

The job's own GPUs (2, 3) were fully drained; GPUs 0 and 1 belonged to
siblings. Cost: ~765–880 s lost per job + a fix round. Note the error message
already *printed* the per-GPU breakdown — printing detail is not scoping, so
the gate must key on the aggregation, not the message.

**Incident 2 (Item 2) — #2061 round 1.** The implementer fabricated the #1336
shard schema; the code-review verdict was that "the pipeline cannot load its
own input (fabricated `#1336` shard schema), P2 crashes deterministically after
the expensive fits". Cost: ~4.5 h wall + a review round. Sibling: #2091's judge
collector `KeyError`'d on the packed `_manifest.json` row 0 (an unfiltered read
of a multi-source pack).

**Why a review-surface gate and not another gotchas entry (Item 1).** The class
is ALREADY documented on the authoring side —
`.claude/rules/gotchas.md` L45 (`+gpu_id=N` Hydra clobber), L46 (import-time
cuInit defeats in-process CVD), L47 (hand-launching dispatcher-managed
workers), L48 (library-train seam clobber), and L240 states outright that
`nvidia-smi -L` "ALWAYS enumerates all 8 devices (ignores
`CUDA_VISIBLE_DEVICES`)". #2091 re-introduced the class anyway. A fifth
authoring-side entry has no reason to outperform the four that already exist;
the untested surface is REVIEW.

**Landing precedent followed:** #2165 (Step 0.71), #1693 (0.69), #1727 (0.70),
#1716/#1726/#1728, #2002. All use the stub-plus-section-reference split with a
region-anchored lint pin.
