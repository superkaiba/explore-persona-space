### 4b. `scripts/verify_plan.py` (new check, ~70 lines, modeled on c30)

After `check_ratchet_headroom` (~line 5703), before `# ─── Driver ───`:

```python
# ─── Check 35 — revision-pinned reuse verified at the pin (WARN-only) ──────

# Trigger: a 40-hex token with revision/pin vocabulary within +/-120 chars,
# HF-context AND reuse vocabulary within +/-300 chars (the c6/c30 proximity
# convention), scanning STRIPPED prose. The revision-vocab window is what
# keeps git code SHAs (Repro-card `commit=<sha>` rows) out; the HF-context
# window keeps "pinned to commit <sha>" git rows out (#1345 shape only).
_C35_HEX40_RE = re.compile(r"\b[0-9a-f]{40}\b")
_C35_REV_VOCAB_RE = re.compile(r"(?i)\brevision\b|\bpin(?:ned|s)?\b")
_C35_HF_CTX_RE = re.compile(
    r"(?i)superkaiba1/|hf_hub_download|huggingface|hf (?:model|data) repo"
    r"|list_repo_(?:files|tree)|snapshot_download|repo_id|repo_type"
)
_C35_REUSE_RE = re.compile(r"(?i)\breus\w*|\binherit\w*")
_C35_REV_WIN, _C35_CTX_WIN = 120, 300
# Satisfiers scan RAW text (c30 convention: runnable probe commands
# legitimately live in fenced blocks): a Hub-probe callable with a
# `revision=` kwarg on the same line, or a prose verified-at-pin statement.
_C35_PROBE_SATISFIER_RE = re.compile(
    r"(?i)(?:list_repo_(?:tree|files)|file_exists|get_paths_info|hf_hub_download)"
    r"[^\n]{0,200}\brevision\s*[=:]"
)
_C35_PROSE_SATISFIER_RE = re.compile(
    r"(?i)verif\w+[^\n]{0,120}\bat\s+(?:the\s+)?(?:pinned\s+)?revision\b"
)


def check_pinned_revision_reuse(plan: str, kind: str) -> CheckResult:
    """Plans reusing an HF artifact at a pinned 40-hex revision must name a
    revision-scoped existence verification (incident #1345: a default-branch
    probe read CONFIRMED while 2/4 stems returned 0 files at the pin). WARN
    not FAIL: 'reuse row' detection is heuristic (same class as c6/c30), and
    the semantic question — was the probe actually RUN, per stem, at the pin
    — stays with the fact-checker (SKILL.md Phase 1.5)."""
    cid, name = "c35_pinned_revision_reuse", "revision-pinned reuse verified at pin"
    if kind not in ("experiment", "analysis"):
        return _skip(cid, name, "kind-exempt")
    text = strip_fences(plan)
    pinned_reuse = False
    for m in _C35_HEX40_RE.finditer(text):
        w_rev = text[max(0, m.start() - _C35_REV_WIN) : m.end() + _C35_REV_WIN]
        w_ctx = text[max(0, m.start() - _C35_CTX_WIN) : m.end() + _C35_CTX_WIN]
        if (
            _C35_REV_VOCAB_RE.search(w_rev)
            and _C35_HF_CTX_RE.search(w_ctx)
            and _C35_REUSE_RE.search(w_ctx)
        ):
            pinned_reuse = True
            break
    if not pinned_reuse:
        return _skip(cid, name, "no revision-pinned HF reuse detected")
    if _standalone_na_declared(plan, r"no revision[- ]pinned reuse"):
        return _pass(cid, name, "explicit no-pinned-reuse declaration")
    if _C35_PROBE_SATISFIER_RE.search(plan) or _C35_PROSE_SATISFIER_RE.search(plan):
        return _pass(cid, name, "revision-scoped existence verification named")
    return _warn(
        cid,
        name,
        "plan reuses an HF artifact at a pinned 40-hex revision but names no "
        "revision-scoped existence verification - probe AT the pin per named stem "
        "(`list_repo_tree(repo_id, path_in_repo=<prefix>, revision=<pin>)` / "
        "`list_repo_files(..., revision=<pin>)`, >=1 file per stem); a default-branch "
        "probe does NOT satisfy (incident #1345: 2/4 stems returned 0 files at the "
        "pin); or declare `N/A - no revision-pinned reuse` on its own line, unwrapped",
    )
```

Register in `CHECKS` (~line 5741): `check_ratchet_headroom,` → append

## 11. Decision Rationale

- **WARN not FAIL** — What: severity of c35. Why: prose detection of "reuse row" is
  heuristic; a false FAIL blocks plan persistence, a false WARN costs one brief line.
  Source: task #1347 Goal (explicit) + the c6/c30 precedent (both WARN for the same
  reason, `verify_plan.py:831` / `:4960` docstrings). Alternatives: FAIL (rejected —
  false-positive cost), fact-checker-only with no mechanical check (rejected — the
  incident shows the prompt instruction alone is what failed to exist; the WARN is the
  backstop that survives prompt drift).
- **Trigger = 40-hex ∧ revision-vocab(±120) ∧ HF-context(±300) ∧ reuse-vocab(±300)** —
  Why: the conjunction is what excludes the dominant 40-hex population in real plans
  (git code SHAs in Repro cards / fix_sha rows). Source: c6/c30's ±300 proximity
  convention (`verify_plan.py:850,4973`); window sizes inherited, not re-derived.
  Alternatives: line-level co-occurrence (rejected — long unwrapped plan lines, the c31
  lesson at `verify_plan.py:4998`); requiring `revision` literally adjacent (kept as the
  kill-criterion-2 tightening fallback).
- **Check id c35, registered last** — Source: `CHECKS` registry order + the escape-list
  numbering convention (checks 1–34 present).
- **Two sibling one-liners included** — Source: #622 every-hit rule
  (workflow-fix-on-bug.md anti-pattern table) bounded by the body's minimal-scope
  constraint; both files carry the canonical `revision='main'` recipe.
- **Batched single-process corpus scan (not a per-file `uv run` loop)** — Why: 2,009
  files × ~0.35 s interpreter startup ≈ 12 min serial vs ~seconds for one process
  importing `verify_plan_text`. Source: fact-checker measurement on this corpus
  (2026-07-15). Alternatives: a 300-file random sample (rejected — the full batched scan
  is already ~seconds, so sampling buys nothing and weakens the ≤5% criterion's
  denominator).
