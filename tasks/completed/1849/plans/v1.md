## Plan Summary

Add a destination-shape validation to `_upload`'s single-file branch in
`src/explore_persona_space/orchestrate/hub.py` so a `path_in_repo` that
looks like a DIRECTORY PREFIX (the #1738 incident shape) raises a
`ValueError` before any network I/O, instead of silently landing the file
AT the prefix path — which shadows the directory and 400-blocks every
later upload under it. Pin the new guard with unit tests in the existing
invariant test file `tests/test_workflow_hub_upload_as_file.py`.

## Goal / Requirement

A single-file upload destination that is actually a directory prefix must
fail loud instead of silently shadowing the directory and 400-blocking
every later upload under it (task #1849 body, from the #1738 incident:
`bare_pilot_meta.json` content landed as a 673-byte FILE at
`issue1738_multiturn/bare_query`; all 8 subsequent shard uploads to
`bare_query/capture/...` failed HTTP 400; ~25 min diagnosis + stray-file
delete + shard rerun, cascading into a ~3.5 h session stall).

### Acceptance criteria

1. `_upload(..., upload_as_file=True)` with a file whose name carries an
   extension and a non-empty `path_in_repo` whose basename carries NO
   extension raises `ValueError` naming the full-destination contract and
   the corrective form (`f"{prefix}/{local_path.name}"`).
2. `path_in_repo` ending in `/` raises `ValueError` on the single-file
   branch (unambiguous directory intent).
3. The raise happens BEFORE any `HfApi` construction / network call and
   OUTSIDE the try/except-swallow (the #595 / #1190 precedent placement),
   so it propagates to the caller regardless of `raise_on_error`.
4. No behavior change for: folder uploads (extension-less destinations are
   the norm there — verified across all in-repo folder call sites); empty
   `path_in_repo` (falls back to `local_path.name`); destinations whose
   basename contains a `.` (full file destinations, including renames);
   local files that themselves have no extension (`LICENSE`-class — the
   heuristic cannot distinguish, so it stays silent: narrow check, no
   false positives).
5. New unit tests in `tests/test_workflow_hub_upload_as_file.py` cover
   1-4; the existing tests in that file still pass.

## Method delta (vs prior state)

Prior state: the single-file branch trusts `path_in_repo` verbatim as the
full file destination (documented contract, `_upload` docstring) with zero
shape validation. Delta: one narrow fail-loud guard + tests. No call-site
changes (a caller sweep found NO in-repo single-file call site passing an
extension-less destination — all pass `{prefix}/{name}` or an
extension-bearing literal; the four extension-less destinations found are
all DIRECTORY uploads, out of the guard's scope).

## File paths + concrete diff sketch

1. `src/explore_persona_space/orchestrate/hub.py` — in `_upload`,
   immediately after the existing #595 file-without-flag guard
   (~L1506-1511), before `assert_hub_dir_filecounts` / `HfApi`:

   ```python
   # Fail loud on the directory-prefix-shaped single-file destination
   # (#1738): path_in_repo is the FULL file destination on this branch;
   # a bare directory prefix lands the file AT the prefix, shadowing the
   # directory and 400-blocking every later upload under it.
   if upload_as_file and local_path.is_file() and path_in_repo:
       dest_name = PurePosixPath(path_in_repo).name
       if path_in_repo.endswith("/") or (
           "." in local_path.name and "." not in dest_name
       ):
           raise ValueError(
               f"_upload single-file destination {path_in_repo!r} looks like a "
               f"directory prefix (uploading {local_path.name!r}): path_in_repo is "
               "the FULL file destination for upload_as_file=True. Pass "
               "f'{prefix}/{local_path.name}' to place the file under a directory "
               "prefix (see #1738: a file landed AT the prefix, shadowing the "
               "directory and 400-blocking later uploads under it)."
           )
   ```

   Plus: extend the `path_in_repo` arg docstring line to name the
   fail-loud guard, and add the `PurePosixPath` import if absent.
2. `tests/test_workflow_hub_upload_as_file.py` — new tests per acceptance
   criteria 1-4 (reuse the file's existing monkeypatch pattern that
   asserts the raise happens before `HfApi` construction).
3. OPTIONAL (small, same commit): 2-line addition to the existing
   `hub._upload` subsection of `.claude/rules/gotchas.md` documenting the
   new guard (the test file's docstring already points there).
