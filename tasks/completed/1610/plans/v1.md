## 3. Design

### 3.1 Pinned key set (the contract)

```python
GENERATION_ROW_KEYS = frozenset(
    {"persona", "question_idx", "prompt_token_ids", "response_token_ids", "finish_reason"}
)
```

The contract binds **at return time**. Consumers legitimately ENRICH returned rows in place afterward (`r["prefix_len"]`, `r["context_len"]`, `r["span_seam"]` — issue1315/1333/1090_fu6 call sites), so the in-helper assert and the test both check freshly returned rows only; no consumer-side key-set check is added anywhere.

### 3.2 Helper hardening — `src/explore_persona_space/analysis/representation_shift.py` (pure additions, no behavior change)

1. Module-level constant immediately above `_generate_responses_vllm` (line ~393):

```python
# Row schema contract for _generate_responses_vllm — pinned by
# tests/test_representation_shift_row_schema.py (#1610; origin #1586 crash r6:
# KeyError: "response" across the reuse seam). Rows carry TOKEN IDS only — there is
# NO "response" text key; consumers decode response_token_ids at their own seam.
# Contract binds AT RETURN; consumers may enrich rows in place afterward.
GENERATION_ROW_KEYS: frozenset[str] = frozenset(
```

```python
assert all(set(r) == GENERATION_ROW_KEYS for r in rows), (
```

### 3.3 Contract test — new `tests/test_representation_shift_row_schema.py`

**Leg 1 (primary): execution test `test_generated_rows_match_pinned_schema`.** Executes the REAL `_generate_responses_vllm` body per the one-production-body-test rule (`.claude/rules/code-style.md` §#906), faking only external boundaries:

- **vLLM boundary:** `monkeypatch.setitem(sys.modules, "vllm", _fake_vllm_module())` — works because the import is function-body-local (`from vllm import LLM, SamplingParams`, line 413), so no real vLLM is imported at collection OR call time. The fake module exposes signature-conformant `LLM` (`def __init__(self, *, model, dtype, gpu_memory_utilization, enforce_eager)`) and `SamplingParams` (`def __init__(self, *, temperature, max_tokens)`); `LLM.generate(self, prompts, params, use_tqdm=False)` returns one output per prompt with `.prompt_token_ids` (list[int]) and `.outputs[0]` carrying `.token_ids` / `.finish_reason` (def-mirrored fakes, never bare `Mock()`).
- **Tokenizer boundary (network):** `monkeypatch.setattr(rs, "AutoTokenizer", _FakeAutoTokenizer)` — `AutoTokenizer` is a module-level import (line 16), so this is patchable. The fake's `from_pretrained(...)` returns an object with `apply_chat_template(messages, tokenize=False, add_generation_prompt=True) -> str` (concatenates message contents — `_build_generation_prompts` uses only this method) and `eos_token_id = 151645`.
- **CUDA boundary:** `monkeypatch.setattr(torch.cuda, "ipc_collect", lambda: None)` — REQUIRED: `torch.cuda.ipc_collect()` (helper line 467) RAISES `RuntimeError: Found no NVIDIA driver` on the GPU-less VM (empirically probed 2026-07-22); `empty_cache()` is a guarded no-op (probed ok) but patch it too, belt-and-suspenders.
- **Sleep:** `monkeypatch.setattr(rs, "time", types.SimpleNamespace(sleep=lambda s: None))` (skips the 1.0 s teardown sleep, line 468).
- `_reap_vllm_engine` needs NO patch — it is getattr-guarded and no-ops on a fake LLM (pinned by `tests/test_vllm_teardown_helper.py::test_noop_on_engine_without_shutdown_api`).

Call shape and asserts (pseudocode):

```python
rows = rs._generate_responses_vllm(
    "fake-model", {"p1": "You are p1.", "default": None}, ["q1", "q2"],
    max_new_tokens=8, gpu_memory_utilization=0.6,
)
assert len(rows) == 4                                   # 2 personas x 2 questions
for r in rows:
    assert set(r) == PINNED_KEYS                        # the test-side LITERAL frozenset
    assert "response" not in r                          # the #1586 regression key, explicit
    assert isinstance(r["persona"], str)
    assert isinstance(r["question_idx"], int)
    assert isinstance(r["prompt_token_ids"], list) and all(isinstance(t, int) for t in ...)
    assert isinstance(r["response_token_ids"], list)
    assert isinstance(r["finish_reason"], str)
# EOS-strip contract: fake completion A ends [10, 11, 151645]/"stop" -> stored [10, 11];
# fake completion B ends [10, 11]/"length" -> stored [10, 11] (no strip).
assert PINNED_KEYS == rs.GENERATION_ROW_KEYS            # test literal <-> module constant cross-pin
```

`PINNED_KEYS` is a LITERAL frozenset written in the test file, NOT imported — importing the module constant as the sole truth would make the pin self-referential (a schema change edits both sides at once and passes silently). The cross-pin assert keeps constant and literal in lockstep while forcing any change through a conscious test edit.

**Leg 2 (belt): static AST pin `test_row_construction_dict_literal_keys_pinned`.** Same mechanism family as `test_vllm_teardown_helper.py`'s AST checks: parse `representation_shift.py` (path derived as in that file), locate `ast.FunctionDef` `_generate_responses_vllm`, walk for `ast.Call` whose func is `ast.Attribute(attr="append")` on `ast.Name(id="rows")`; assert exactly one such call exists, its single arg is an `ast.Dict` with all-`ast.Constant`-string keys, and the key set equals the pinned literal. A future refactor that builds the row dict differently fails this leg LOUD — the desired outcome (forces a conscious test update + consumer re-audit in the same change).

## 10. Decision Rationale (§11)

1. **Test mechanism: BOTH fake-vllm execution leg AND AST pin (not either alone).**
   - What: leg 1 executes the real body via `sys.modules["vllm"]` injection + module-attr tokenizer/CUDA/time patches; leg 2 pins the `rows.append` dict-literal keys statically.
   - Why: leg 1 is the production-body evidence (`.claude/rules/code-style.md` § one-production-body-test, #906) and catches runtime shape (EOS-strip, types) an AST pin cannot; leg 2 makes any schema edit textually visible even under code paths a fake might not exercise, and survives environments where the execution leg is skipped/refactored.
   - Source: `tests/test_vllm_teardown_helper.py` (in-repo AST-pin + stub precedent for this exact helper); code-style rule #906; empirical `ipc_collect` probe (this session).
   - Alternatives rejected: AST-only (no runtime evidence; misses value-shape drift); execution-only (a conditional-key refactor could pass the fake's single path); regex/source-text pin (formatting-brittle).
2. **Constant extraction (`GENERATION_ROW_KEYS`) + test-side LITERAL, cross-asserted — not import-only, not test-only.**
   - What: module constant + in-helper assert + docstring line; the test hardcodes its own literal and additionally asserts literal == constant.
   - Why: the constant gives consumers an importable contract name and a runtime fail-loud; a test that only imported the constant would be self-referential (one edit changes both sides, pin passes silently); the cross-assert keeps them in lockstep while forcing conscious edits.
   - Source: task body `## Scope` (names the in-helper assertion/docstring contract); the single-source-of-truth contract-constant pattern of `rubric_fingerprint` (#1018) as analogy.
   - Alternatives rejected: pure test-side pin (no runtime guard, no importable name); helper builds rows FROM the constant (restructures the dict literal leg 2 pins, for no contract gain).
3. **Consumer audit as a recorded disposition table, not a static test leg.**
   - What: §3.4 table in plan + implementer report; no scanning test.
   - Why: `["response"]` reads on non-helper row sources coexist in the same files (issue1090_fu6) — a scan without dataflow attribution false-positives by construction; brittleness would exceed protection.
   - Source: line-level reads this session (issue1090_fu6 lines 880–965, 1935–1955).
   - Alternatives rejected: AST dataflow attribution of row provenance (out of proportion for a 0-GPU infra task; the schema pin + runtime assert already close the forward-looking class).
4. **Assert placement pre-return inside the helper (not at consumers).**
   - What: single `assert all(set(r) == GENERATION_ROW_KEYS ...)` before teardown.
   - Why: consumers enrich rows in place post-return (Assumption 9) — consumer-side key-set checks would false-fail by design.
   - Source: read call sites (issue1315/1333/fu6).
   - Alternatives rejected: per-append assert (equivalent, noisier); no runtime assert (loses the drift fail-loud between test runs).
