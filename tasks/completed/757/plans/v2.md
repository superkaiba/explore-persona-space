**v2 delta vs v1:** the critic (REVISE) verified against #658's actual marker
corpus that the v1 re-read recipe filtered on `e.get('followup_label')`, which
is NOT a top-level event key — top-level event keys are `{by, kind, note, ts,
version}` only, and `followup_label` lives inside the marker `note` body as
free text. The v1 one-liner therefore returned an empty list → printed `None`
for every event. v2 replaces the recipe with selection by highest top-level
`version` (tie-break newest `ts`) over `kind == 'epm:followup-scope'` events,
with NO `followup_label` filter — matching every existing consumer
(`autonomous_session_watch._followups_running_orphan_or_none`; the Step 0
highest-version-per-kind marker map). The other three edit sites are unchanged
(the critic confirmed their wording is correct).

## Goal + acceptance criteria
**Goal:** the loop plans against the latest scope marker. **Acceptance:**
(1) the loop's planner-snapshot point carries an explicit "re-read the latest
scope" instruction; (2) the re-read recipe is mechanical, copy-pasteable, AND
returns the authoritative scope on a real `events.jsonl` (the v1 recipe did
not); (3) every site that observes the unrun scope (Step 0 dispatcher,
Resume-semantics, step 1 Scope marker, step 3 planner amendment) is consistent;
(4) `workflow_lint.py --check-references`/`--check-asks` + `tests/test_workflow*.py`
+ `tests/test_task_workflow*.py` stay green.

## Method delta (vs current state)
Current state: step 1 ("Scope marker") only ensures *a* `v1` scope exists; step 3
re-invokes the planner in AMENDMENT scope without saying which scope version to
read; the Step 0 dispatcher matches "an UNRUN `epm:followup-scope v1`". None of
these say "re-read newest before the planner snapshots", so a session that
entered on `v3` and snapshotted before `v5/v6` landed (the #658 bug) would plan
stale. Delta: add a single load-bearing rule — "select the latest scope
immediately before the planner snapshots" — and reference it at every
observation site. `epm:followup-scope` is append-only with monotonically
increasing top-level `version` per kind (corrections re-post the marker with a
"SUPERSEDES the prior epm:followup-scope (same followup_label)" note — see
#658's `persona-vectors-style-rb` v3→v8 chain), so the authoritative scope =
the highest-`version` (tie-break newest `ts`) `epm:followup-scope` event.
