# Plan — #1660: daily-fix: ddp_timeout default for ZeRO-3 multi-GPU runs

## 0.0 TL;DR (plain English)

- **What I'll run:** I'll add a 3-hour distributed-training timeout default (`ddp_timeout=10800`) to every live training-args construction site in the shared training path — the LoRA trainer, the in-process phase trainer (SFT + DPO), and the three accelerate/DeepSpeed stage scripts — plus a `ddp_timeout: 10800` key in `configs/training/default.yaml`, all sourced from one shared constant. ## 4. Design

**Why code, not a model call:** N/A — this is a code change to training infrastructure; there is nothing to classify/extract.

**One shared constant, seven files.** All sites reference a single constant so the value cannot drift:

### 4.1 `src/explore_persona_space/train/compat.py` — the constant (new, ~8 lines)

compat.py is the module whose docstring already reads "Module-level flags shared across training modules"; it imports only `transformers` + `packaging` (no cycle risk). Add at module level:

```python
# 3h process-group timeout for multi-GPU runs (transformers default: 1800 s).
# Rank-0 synchronous ZeRO-3 checkpoint save/upload inside on_save can exceed
# 30 min, leaving ranks 1..N blocked in the next all-gather until the NCCL
# watchdog kills the run (#1112 Arm B, 2026-07-23: checkpoint-40's ~15 GB
# upload crawled past 1800 s; WorkNCCL _ALLGATHER_BASE timeout). Value matches
# the landed in-session fix (scripts/train_behavior_fullft.py:650). Inert in
# single-process runs: TrainingArguments.ddp_timeout only feeds
# init_process_group via accelerate's timeout kwarg.
DEFAULT_DDP_TIMEOUT_S = 10800
```

### 4.2 `src/explore_persona_space/train/sft.py` — the `train_lora` path

- Module-top import (added together with first usage, per the ruff PostToolUse rule): `from explore_persona_space.train.compat import DEFAULT_DDP_TIMEOUT_S` (sft.py currently imports only `personas` from the package at module top; compat → sft is acyclic).
- New `TrainLoraConfig` field, inserted after `bf16: bool = True` (~L626):

```python
    # Process-group timeout (seconds) threaded into SFTConfig/TrainingArguments.
    # Default = ZeRO-3-safe 3h (#1112); inert in single-process runs, so the
    # unconditional default is byte-safe for every existing 1-GPU caller.
    ddp_timeout: int = DEFAULT_DDP_TIMEOUT_S
```

- One line in the `sft_kwargs` dict, inserted after `"seed": cfg.seed,` (~L1535):

```python
        "ddp_timeout": cfg.ddp_timeout,
```

The `SFTConfig(packing_strategy=...)` probe at L1549 is a throwaway kwarg-acceptance probe — unchanged.

**Config-plumbing choice (required decision):** for this path the value rides a `TrainLoraConfig` field (not a bare module constant at the call site) because `TrainLoraConfig` is the path's existing override channel — callers that need a different timeout (e.g. a CPU smoke) get it without env hacks, and the additive-field-with-safe-default pattern is the repo's established shape (`use_rslora`, `bf16`, #1112/#906 precedents, each pinned by a contract test).

- In the real `SFTConfig(...)` at ~L926, insert after `seed=seed,` (~L946):

### 4.4 `configs/training/default.yaml` — the config-surfaced default

Insert after `bf16: true` (L13):


## 11. Decision Rationale

**`ddp_timeout = 10800` (the single load-bearing value):**
- **What:** the `torch.distributed.init_process_group` timeout, threaded via `TrainingArguments.ddp_timeout` (and, for the raw-Accelerator DPO stage, via `InitProcessGroupKwargs(timeout=...)`), applied as the project-wide default at every live training-args construction.
- **Why:** the transformers default (1800 s) is demonstrably too tight for the project's ZeRO-3 regime — a single rank-0 synchronous ~15 GB checkpoint upload inside `on_save` exceeded it while ranks 1..3 waited in the next all-gather (#1112 Arm B crash at step 40/750). 3 h covers the measured slow phase with headroom (three ~3.5 min uploads preceded the >30 min one; a throttled/429-day upload can crawl much longer) while still bounding a genuinely hung run.
- **Source:** #1112 (`scripts/train_behavior_fullft.py:650`, landed + production-validated 2026-07-23).
- **Alternatives rejected:** 1800 (the default — the incident); 3600 (the task body's "e.g." mis-recollection — a 15 GB throttled upload measured >1800 s and headroom is wanted; the landed, validated value is 10800); effectively-unbounded (agentic-backdoor's 180000000 s — rejected: a genuine hang should still die and stop billing); world-size-gated application (rejected: the kwarg is inert single-process, so gating adds complexity for zero benefit).
