# Plan v2 — task #1806: escalate-only audit of root stashes + rescue dirs

Revision of v1 folding in the Methodology critic's Must-Fix (ENOENT
semantics) + nice-to-haves (tab-safe parse, fail-soft test, dry-run test;
the latter two also close verify_plan WARNs c11/c15).

## Plan Summary

Add ONE new escalate-only pass to `scripts/autonomous_session_watch.py`
(`stash_rescue_audit_pass`, watcher pass #34) that surfaces the shared
repo root's accumulated `git stash` backlog + the
`~/.task-workflow/root-sync-rescue/` rescue-entry backlog on a recurring,
deduped channel — sidecar JSONL + ONE deduped Telegram push per episode —
mirroring the `registry_drift_pass` (#1439) pattern byte-for-byte in
shape. The pass NEVER mutates git or filesystem state (no `stash
pop/drop/apply`, no `rm`); triage stays human (companion task #1736 holds
the triage decision).

NOT architectural: adds one pass behind a kill switch; no status enum,
marker schema, task.py subcommand, or subsystem change. `architectural:
false`.

events at Step 10d only. The existing backlog (verified live 2026-07-30:

**Acceptance criteria:**

1. `uv run python scripts/workflow_lint.py --check-asw-docstring-pass-count`
   PASSes: header digit bumped 33 → 34, numbered docstring item 34 added,
   execution-order list updated, live `*_pass` set in `main()` matches.
2. New pass fires ONE push on first confirmed backlog, is silent
   (throttled) on subsequent same-fingerprint ticks, and re-alerts only
   after the re-alert interval or a fingerprint change — pinned by unit
   tests mirroring `test_registry_drift_decide_alert_fp_change_and_ttl` /
   `test_registry_drift_pass_fires_on_confirmed_drift`.
3. ESCALATE-ONLY invariant: the pass performs zero mutating git /
   filesystem operations — collection is `git stash list --format=...`
   (read-only) + `os.scandir`/`stat` of the rescue dir. Code-review
   verifies no mutating verbs anywhere in the pass; a test asserts the
   collector's subprocess argv is exactly the read-only stash-list form.
4. Kill switch `EPM_DISABLE_STASH_RESCUE_AUDIT=1` disables the pass
   (tested); `--stash-rescue-audit-only` debug flag runs just this pass
   (mirrors `--registry-drift-only` wiring).
5. Fail-soft with NO silent-empty read: a git failure (rc≠0) or an
   unexpected OSError logs stderr + one error sidecar row and never
   crashes the tick, and is NEVER interpreted as "backlog cleared" (no fp
   reset on error). EXCEPTION (critic Must-Fix): ENOENT on the rescue dir
   itself is a LEGITIMATE EMPTY rescue set — the dir is lazily created by
   `sync_repo_root.py` (RESCUE_ROOT, sync_repo_root.py:146-150) and may
   be absent on a fresh host or deleted after a completed #1736 triage;
   treating it as an error would permanently blind the whole pass
   (including the stash half) and make the recovered/fp-reset branch
   unreachable after triage.
6. Dry-run contract pinned: `--dry-run` performs zero state writes, zero
   sidecar writes, zero pushes (the live smoke in the Repro Card depends
   on this).
7. `ruff check` / `ruff format --check` clean on touched files; full
   Step 9c gate (selector subset) passes.

## Method delta (what differs from prior related work)

- vs #1751 (Step 10d KEPT-stash duty): that surfaces NEW KEPT events at
  merge sites, session-side; this adds the RECURRING watcher-side sweep of
  the whole backlog (old stashes + rescue dirs + anything that slips past
  the session-side duty).
- vs `registry_drift_pass` (#1439, the template): same
  throttle/fingerprint/re-alert/sidecar/fail-soft shape; deltas are (a)
  the collector (git stash list + rescue-dir scan instead of REGISTRY
  audit), (b) NO double-read confirm gap — stash/rescue entries are
  durable files, not in-flight mutations; sync_repo_root autostashes live
  seconds (created + popped inside one recovery), stranded ones age past
  the min-age gate, and #1751's Step 10d duty covers the 0-7-day window —
  and (c) the ENOENT-is-empty carve-out for the lazily-created rescue dir
  (registry drift has no analogous lazily-created input).

## File paths + concrete changes

1. `scripts/autonomous_session_watch.py` (the ONLY production file):
   - Module docstring: `33 passes` → `34 passes`; add numbered item 34
     (**Stash/rescue-backlog audit pass**, escalate-only, #1806); insert
     into the per-tick execution-order list immediately after
     `27 (registry-drift)`.
   - Constants: `STASH_RESCUE_INTERVAL_HOURS = 24.0`,
     `STASH_RESCUE_REALERT_HOURS = 168.0`,
     `STASH_RESCUE_MIN_AGE_DAYS = 7.0` (env overrides
     `EPM_STASH_RESCUE_INTERVAL_HOURS` / `EPM_STASH_RESCUE_REALERT_HOURS`
     / `EPM_STASH_RESCUE_MIN_AGE_DAYS` via the existing `_env_float`).
   - Helpers (mirror the registry-drift trio + decide fn):
     `_stash_rescue_sidecar_path()` →
     `PROJECT_ROOT/.claude/cache/stash-rescue-audit-events.jsonl`;
     `_stash_rescue_state_path()` →
     `AUTONOMOUS_REGISTRY_DIR/stash-rescue-audit.json`
     (`{"last_run_ts", "fp", "last_alert_ts"}`);
     `_load_/_save_stash_rescue_state` (atomic temp+rename, dry-run
     no-op); `_append_stash_rescue_sidecar`;
     `decide_stash_rescue_alert(fp, state, now, realert_s)` — REUSE the
     exact `decide_registry_drift_alert` logic (fp-change OR re-alert-TTL
     OR corrupt-state fires; may delegate to a shared helper or duplicate
     the 8-line body, implementer's call).
   - Collector `_collect_stash_rescue_backlog(min_age_s, now)` →
     `{"stashes": [...], "rescues": [...]}`:
     - stashes: `git -C PROJECT_ROOT stash list --format=%ct%x09%gs`
       (read-only), parse each line with `split("\t", 1)` (FIRST tab only
       — `%gs` subjects can carry user text with tabs), keep rows with
       `now - ct > min_age_s`; identity = `(ct, subject)` — deliberately
       NOT the positional `stash@{N}` selector, which renumbers on every
       push/pop and would churn the fingerprint. git rc≠0 raises to the
       fail-soft arm (a failed `git stash list` must NEVER read as
       "backlog cleared").
     - rescues: entries directly under
       `~/.task-workflow/root-sync-rescue/` (dirs AND loose files, e.g.
       `stash-*.patch`), keep entries with mtime older than `min_age_s`;
       identity = entry name. **ENOENT on the rescue dir itself returns
       an EMPTY rescue list `[]`** (legitimate absence — lazily created;
       see acceptance criterion 5); every OTHER OSError raises to the
       fail-soft arm.
   - Fingerprint `_stash_rescue_fingerprint(collected)` = sha256 over the
     sorted identity lists + counts, first 12 hex.
   - Pass `stash_rescue_audit_pass(dry_run: bool) -> bool` — structure
     copied from `registry_drift_pass`: kill-switch check → once-daily
     throttle (attempt stamp saved BEFORE collecting) → collect → empty
     backlog (including dir-absent) ⇒ recovered-log + fp reset →
     fingerprint → decide → sidecar row (counts + oldest ages + up to ~20
     sample identities, capped) → deduped `_telegram_push` naming:
     counts, oldest stash age, the read-only review commands
     (`git stash list`, `ls ~/.task-workflow/root-sync-rescue/`),
     companion triage task #1736, and "nothing was changed automatically"
     → state save. NO double-read confirm gap (see Method delta).
     Top-level fail-soft try/except → stderr + error sidecar row, NO fp
     write (next in-interval tick stays throttled by the attempt stamp).
   - `main()`: call `stash_rescue_audit_pass(dry_run)` immediately after
     `registry_drift_pass` in the production run order; add
     `--stash-rescue-audit-only` argparse flag + early-exit branch
     mirroring `--registry-drift-only`.
