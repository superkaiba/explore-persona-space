## 11. Decision Rationale

**Decision: exact report-field wording + hit-list bounding rule.**
- **What:** `pin-sweep: <fragments grepped> → <N> hit files: <verbatim deduplicated hit-file list>`; dedup-union across fragments; explicit `0 hit files`; >20 files → `(list below)` inline + full fenced block under the line; never truncate.
- **Why:** the #1494 artifact shows the failure is *summarization* (a glob-family phrase standing in for 7+ files) — so the contract must demand verbatim file paths, and any truncation form (`+K more`) would reopen the identical omission channel. Dedup-union (not per-fragment lists) suffices because every hit file must be discharged regardless of which fragment hit it, and it halves the byte cost on the ratcheted reviewer files. The 20-file inline bound: typical sweeps hit <15 files (#1494: ~9 across fragments), and 20 paths × ~30-40 chars ≈ 600-800 chars is the readability edge for one bullet line; not sensitive within ~2×; the events.jsonl 50,000-char note cap is 1-2 orders of magnitude away even for a 100-file fenced list.
- **Alternatives rejected:** (a) count-only + per-fragment counts — the incident IS a count/summary; (b) per-fragment file lists — longer, no additional discharge information; (c) `+K more` truncation — recreates the hidden-omission channel; (d) always-fenced-block — bloats the common ≤10-file case and breaks the one-line greppable field family.
