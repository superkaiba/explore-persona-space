# Plan v1 — task #1914: widen body-audit condition-label regex to H1c-forms

## Goal / requirement

Widen the `condition_labels` token pattern in
`scripts/audit_clean_results_body_discipline.py` (and its documented
KEPT-IN-SYNC mirror, `_DATA_CONDITION_CODE_RE` in
`scripts/verify_task_body.py` check 19b) so `H<digit><lowercase-letter>`
hypothesis/plan-tag forms (`H1c`, `H4b`, `P4a`, `C2b`) in body prose are
flagged — the prose-side sibling of the check-28 class #1826 fixed for
figure sidecars only (merged `934114a8eff8`; this file was explicitly
outside that plan's must-ask fence).

**Acceptance criteria**
1. `H1c` / `H4b` / `P4a`-style tokens in reader-facing prose produce a
   `condition_labels` finding.
2. Plural-heading forms (`H2s` — "the five flat H2s") do NOT produce a
   finding (measured false-positive class; see § Calibration).
3. GPU names (`H100`/`H200`/`H20`) remain unmatched (the #1826
   known-good class — already excluded by `[1-9]` + the trailing
   lookahead; pinned by test).
4. check 19b (`verify_task_body.py`) predicts the widened audit
   verbatim (the sync contract in its own comment block).
5. Existing tests in both test files stay green; ruff clean on touched
   files.

## Method delta (vs #1826)

Same single-optional-lowercase-letter calibration #1826 applied to
check 28 (`\bH\d[a-z]?\b`, deliberately NOT `H\d+` — protects
H100/H200/H20), applied here to the audit's prose scan + its check-19b
mirror, with ONE additional exclusion #1826 didn't need: the letter
class excludes `s` (`[a-rt-z]`), because prose about markdown headings
("legacy H2s", "Three H2s total") is a measured false-positive class in
this surface (3 committed bodies) that does not arise in figure
sidecars. Genuine sub-tag letters observed in the corpus are a/b/c —
`s` as a 19th sub-hypothesis letter is implausible.

  violation, which is correct behavior.

  real committed bodies, so no test blast radius from the legacy hits.
