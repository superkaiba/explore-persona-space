### 4.1 New helper `strip_fenced_code_only`

Add immediately AFTER `strip_code` (after line 204). The two helpers sit
adjacent so the contrast is obvious to a future reader.

```python
def strip_fenced_code_only(text: str) -> str:
    """Remove fenced ```...``` code blocks but KEEP inline-backtick spans.

    Companion to :func:`strip_code`. The `interval_inline` scan source uses
    THIS helper (not `strip_code`) so an inline-backtick-wrapped bracketed
    CI in reader-facing prose (e.g. ``CI `[-0.295, +0.083]` ``) is still
    seen by the bracketed-CI regex — `strip_code`'s inline-backtick blanking
    (the `` `[^`\\n]*` `` substitution) otherwise removes it before the scan
    (the #667 line-166 gap). Sample-completion text in FENCED code blocks
    is still stripped, so this does not create false positives from verbatim
    bracketed expressions inside fenced examples. Every OTHER audit category
    keeps using `strip_code` (full inline+fenced strip) — inline-backtick
    `C1`/`D1` references are a legitimate accepted form for `condition_labels`
    and we deliberately do not widen its exposure here.
    """
    return re.sub(r"```.*?```", "", text, flags=re.DOTALL)
```

This is the FIRST `re.sub` of `strip_code` verbatim (line 202), minus the
second `re.sub` (line 203, the inline-backtick blank). `strip_code` is left
UNCHANGED — every caller that still uses it (`cleaned` at line 617, which
feeds `condition_labels` and all non-interval categories) keeps its exact
current behavior.

*Optional micro-refactor (permitted by the plan, not required):* `strip_code`
MAY be rewritten to compose `strip_fenced_code_only` + an `_strip_inline_code`
helper, as long as `strip_code`'s observable output is byte-identical for its
remaining callers. The implementer should prefer the minimal form above
unless the compose form is clearly cleaner; either is acceptable. If the
compose form is taken, add a one-line assert-style test that `strip_code`
still blanks an inline `` `C1` `` span (parity check). Do NOT change PATTERNS,
the regex, the exemption logic, or the scoping under either form.

- **What:** introduce `strip_fenced_code_only` and route ONLY the

  while keeping every other category — especially `condition_labels`, whose
  inline-backtick `` `C1` `` form is a LEGITIMATE accepted reference — on the
  full `strip_code`. Single-category routing is the established pattern in
  `audit_body` (`pre_reg` already gets its own scan source, #623).

  `strip_fenced_code_only` preserves every exemption and changes only the
  inline-backtick behavior for `interval_inline`). No literature applies to
