## 3. Method delta

**vs the argparse pass (same module):**
1. Same skeleton: whole-module `ast.walk`, all-failures-at-once `SystemExit`, visible-residue idiom, varargs `*module_files`.
2. New: RESOLUTION of AST call nodes to installed callables. The argparse pass never imports anything (pure static sets); the bind pass must map local names to installed objects via the file's own import statements, then `importlib.import_module` + `getattr` (lazy — only modules the file's import map actually references).
3. New escape grain: the argparse escape `extra_defined=` names ATTRIBUTES (no call-site grain); the bind escape is a call-site comment waiver `# ARGCHECK_BIND_EXEMPT: <reason>` (same line or immediately-preceding non-blank line — the established `# WANDB_INTENTIONALLY_DISABLED` placement convention), because a bind failure is per-site.
4. New visibility channel: the argparse pass surfaces residue only inside a failure message; the bind pass ALSO prints a one-line stdout census on PASS (`argcheck-bind: N bound, M degraded, K skipped`) plus one line per skipped/degraded site. Chosen visibility posture — WEAKEN the claim, not grow the design: the census is visible in the run's stdout/log wherever `--import-check` executes, and the smoke-architecture Axis 1 `import-resolution:` marker records the exact COMMAND (making the check reproducible on demand — `.claude/agents/experiment-implementer.md:140-141`, `.claude/rules/code-style.md:169`); the marker does NOT persist the check's output. A3's letter ("explicit and documented, never silent") is satisfied by the stdout census on every run + the failure-message skip re-list + the code-style.md skip-class enumeration; growing the design to persist the census durably is not warranted while the skip set is measured NULL (0 skips across the full armed population, §5) — the residual is documented in §4.5 and carried into the doc edit (§4.7 item g).
5. New DECISION rule for name resolution (MF-1): the argparse splat machinery's `_exclusive_use_sole_binding` demands exactly ONE binding; the bind pass's shadow guard instead demands UNIFORMITY of import targets (§4.4) — repeated same-target imports are the fleet's dominant idiom (90 registered-relevant (file, name) pairs carry ≥2 same-target import bindings, §5), so the sole-binding decision would abstain on 141 of 195 sites and skip the motivating incident.

**vs the #2223 per-issue test:**
1. Hard-coded receiver name `hub` → import-verified alias mapping under the uniform-import-target rule (`from explore_persona_space.orchestrate import hub`, `import … as h`, `from …hub import stage_hub_file` all resolve, repeated at any position; a name carrying a non-import binding or imports of conflicting targets abstains).
2. The #2223 test ASSERTS no `*args`/`**kwargs` at call sites (correct for that one driver); the general pass DEGRADES those to `bind_partial(**named_kwargs)` + census note (the #606/#1332 doctrine) — measured 0 such sites fleet-wide today.
3. Two new resolvable shapes the #2223 test lacks: bare-name calls of symbols imported FROM the registered module (64 sites under the corrected census: bare `stage_hub_file` 19, `retry_transient` 13, `_upload` 9, `stage_hub_prefix` 7, `_upload_folder_filtered` 7, `list_hf_files_under_path` 6, `list_hf_entries_under_path` 2, `verify_repo_paths_uploaded` 1 — the dominant share of the 81 S2 sites; the other 17 S2 sites are registered huggingface_hub function calls the #2223 test already resolved; full shape split S1 = 96, S2 = 81, S3 = 10, S4 = 8, §5), and `var.method(...)` where every module-wide binding of `var` is an `Assign` to `HfApi(...)` (the uniform-binding rule; 8 sites, all resolve).
4. Per-issue pytest → shared conventional pass armed at every adopter's `--import-check`; the per-issue file keeps its #2223-specific destination pins.
5. Non-vacuity, generalized (consistency-checker recommendation): the #2223 test's per-driver `seen`-membership asserts (named callables must appear in the walk's seen set) do NOT generalize to fleet grain — at fleet grain they are replaced by the positive-count assertions of the fleet census test (`test_bind_fleet_census_positive_coverage`, §6: bound total reconciled against an independent lexical count + per-class coverage floors), which is what makes a silently-site-dropping resolver a test FAILURE instead of a vacuous pass (MF-2).

### 4.4 Resolution rules (the subtle part — CORRECTED, MF-1)

Per file: parse once, build the import map, apply the shadow guard, then resolve each `ast.Call`:

```
_bind_import_map(tree) -> dict[local_name, set[normalized_target]]:
  POSITION-INSENSITIVE: module-level, function-local, and REPEATED imports all
  contribute; every ast.alias binding of a name is normalized to a target:
  ast.Import:      "import a.b.c as h"       -> "h" -> module "a.b.c"; bare "import a.b.c" binds "a" (top package; unregistered -> inert)
  ast.ImportFrom (absolute only; node.level>0 or node.module None -> unmapped):
                   "from a.b import c"       -> "c" ->
                     module  "a.b.c"  if "a.b.c" ∈ _BIND_MODULES          (e.g. from explore_persona_space.orchestrate import hub)
                     class            if ("a.b","c") ∈ _BIND_CLASSES       (e.g. from huggingface_hub import HfApi)
                     function         if ("a.b","c") ∈ _BIND_FUNCTIONS     (e.g. from huggingface_hub import hf_hub_download)
                     symbol-of-module if "a.b" ∈ _BIND_MODULES             (e.g. from ...hub import stage_hub_file -> getattr(hub, "stage_hub_file"))
```

**Shadow guard — the UNIFORM-IMPORT-TARGET rule (supersedes v2's sole-binding rule, which is REJECTED):** a mapped local name participates in resolution iff EVERY module-wide binding of the name is an import alias normalizing to the SAME target. Bindings are collected with the same collector CLASSES as `_exclusive_use_sole_binding` (Store-context `ast.Name` — assignments, loop targets, walrus, comprehension targets; `ast.arg` parameters; `ast.alias` imports; `del` tracked) plus `FunctionDef`/`AsyncFunctionDef`/`ClassDef` names — but the DECISION differs: the argparse machinery's exactly-one-binding rule (`argcheck.py:151` returns `None` whenever `len(bindings) != 1`, no same-target deduplication) is NOT reused for name resolution. Explicit position semantics (MF-1): **module-level imports, function-local imports, and repeated imports of the same target ALL resolve** — repeated re-import of the same module/symbol is the fleet's dominant idiom (90 registered-relevant (file, name) pairs carry ≥2 same-target import bindings; the pre-fix #2223 driver's `hub` had 3, all `from explore_persona_space.orchestrate import hub`, blob lines 715/740/2497). A GENUINE shadow — a local `def`, a class, a parameter, an assignment, a `del`, or imports of two DIFFERENT targets under one name — disqualifies the name: every registered-surface call through it becomes a NOTED SKIP, never a bind, never silent. Measured impact today (§5): 0 names with non-import bindings, 0 conflicting-target names, 0 skips fleet-wide; v2's sole-binding rule would instead have abstained on 141 of 195 sites (54 bound — near-vacuous) and would have SKIPPED the motivating incident.

Resolved call shapes:

- **S1 — module-attribute call** `h.attr(...)`, `h` → registered module: `fn = getattr(importlib.import_module(dotted), attr)`; `AttributeError` ⇒ a check FAILURE naming the site (`references nonexistent helper`) — the #2223 fail-loud getattr, kept. (96 of the 195 measured sites.)
- **S2 — bare-name call** `name(...)`, `name` → registered function, or symbol imported from a registered module: same `getattr` fail-loud. (81 of the 195; split 64 hub-symbol + 17 registered huggingface_hub functions.)
- **S3 — inline constructor-method call** `Cls().m(...)`, `Cls` → registered class: `fn = getattr(Cls(), m)` — binding on the bound method keeps `self` out of the shape; `HfApi()` construction is offline-safe (#2223 test precedent). One cached instance per registered class per invocation. (10 of the 195.)

### 4.5 Bind semantics + failure/visibility contract

```
_bind_call_shape(fn, node):
  kwargs = {kw.arg: object() for kw in node.keywords if kw.arg is not None}
  if any Starred positional or any kw.arg is None (call-site splat):
      inspect.signature(fn).bind_partial(**kwargs)     -> DEGRADED-OK / DEGRADED-FAIL
  else:
      inspect.signature(fn).bind(*[object()]*len(node.args), **kwargs)  -> OK / FAIL
```

Placeholders check SHAPE only (positional count, keyword names, required params, keyword-only-ness) — values never evaluated, no network, no side effects. Keyword-only params and callee-side `*args`/`**kwargs` are handled natively by `Signature.bind` (zero FP by construction on those surfaces).

Waiver: a `# ARGCHECK_BIND_EXEMPT: <reason>` comment on the call's `node.lineno` source line or the immediately-preceding non-blank line converts a would-be FAIL into a NOTED SKIP (reason echoed in the census). Visible at the call site — the `extra_defined=`-equivalent for call grain. Grain is CALL-SITE by suppression-set construction: the waiver suppresses ONLY calls whose `node.lineno` matches the waivered line — never the rest of the file (pinned by the MF-4 test form: one waived + one unwaived invalid call in one fixture; the raised message names the unwaived site and not the waived one). Documented line-grain edge cases (review concern 7): (a) multiple calls written on ONE physical line share one `node.lineno`, so a waiver on that line suppresses all of them — keep waived calls on their own line; (b) a formatter-expanded multiline call keeps `node.lineno` at its OPENING line, so place the waiver on or immediately above the opening line. Both carried into the doc edit (§4.7 item f).

## 8. Kill criteria (do NOT ship as designed if…)

1. **Irreducible false positives — the complete decision lattice (MF-5, no unmapped band):**
   - **Definition:** an irreducible FP is a call shape that BINDS at runtime but fails the static bind AND cannot be fixed by a resolution-rule correction (a rule correction — e.g. adding an abstain arm for an over-eager shape — is always preferred and in-scope; it produces a NOTED SKIP, not a failure).
   - **Triage operation (per flagged site):** (1) read the call site; (2) independently resolve the source's ACTUAL runtime target — follow the file's own import statements / assignments to the object the call would dispatch to at runtime, in the same venv; (3) bind the same literal call shape against THAT object; (4) classify: actual target also fails ⇒ TRUE arity bug (report; any edit to a frozen driver is must-ask); actual target binds but the checker-selected target fails ⇒ resolver FALSE POSITIVE; ambiguous (the name's runtime target cannot be determined statically / is genuinely dynamic) ⇒ NOT a true bug — the resolver must ABSTAIN on that shape (a resolution-rule correction to a noted skip).
   - **Lattice:** measured today = 0 FPs across 195 sites. **≥1 irreducible FP among the armed population (any count — 1, 2, or more) ⇒ do NOT arm in-place**; fall back to an opt-in sibling call (new drivers add a second conventional line; the existing fleet stays argparse-only) and record the FP classes in the rule prose. The per-site waiver alternative on an existing frozen driver exists ONLY through the must-ask channel — a waiver comment IS a driver edit (§13; the #1547 frozen-driver fence), never an automatic response; if the user grants waivers instead of the fallback, §7 criterion 2's zero-waiver clause is amended in the same must-ask round to enumerate the named waivers. There is deliberately NO threshold band: v2's ">2 adopters" rule left 1–2 FPs unmapped between the zero-waiver success criterion and the fallback trigger — eliminated.
2. **Skip-class dominance:** if the resolvable fraction — **bound_total / the independent lexical candidate count** (the resolver-free recognizer of §5/§6 test 20; NEVER the resolver's own numerator over its own denominator, which is blind to silently-dropped sites — MF-2) — drops below ~80% under the final rules ⇒ re-scope the resolution rules before shipping; measured today: 195/195 = 100%.
3. **Latency/dependency regression:** if the bind pass adds >10 s or any network dependency to a single driver's `--import-check` ⇒ restructure (registry laziness) before shipping; measured: no network, ~1-3 s cold import, full-fleet census ~17 s.
