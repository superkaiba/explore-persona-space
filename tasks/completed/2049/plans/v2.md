# Plan — #2049 workflow-fix: list-ephemeral hides duplicate-named pods (name-keyed state)

`kind: infra` · `wf-fix` · workflow-surface only · 0 GPU-h

## 1. Requirement + acceptance criteria

**Requirement (from the task Goal):** `pod.py list-ephemeral` must show EVERY
live managed pod on the API, including pods that share a name — duplicate-named
pods must no longer collapse into one row. Name collisions are surfaced loudly
(they indicate a provisioning-idempotency problem).

**Acceptance criteria:**

1. With N live managed API pods sharing one name, `list-ephemeral` prints N
   rows (each with its own `POD_ID`), not 1.
2. A loud `WARN` (stderr) names any managed pod name carried by >1 live pod,
   listing the colliding pod_ids.
3. Terminate/stop/resume targeting semantics are UNCHANGED for the singleton
   case (one live pod per name — the overwhelmingly common case): byte-identical
   behavior, existing tests keep passing.
4. In the duplicate-name case, the name-keyed targeting view resolves
   DETERMINISTICALLY: the pod whose `pod_id` matches the sidecar metadata wins;
   with no sidecar match, RUNNING is preferred over non-RUNNING, then newest
   `created_at`, then lexicographic `pod_id` (total order — never API-order
   last-wins).
5. Sidecar drift-repair NEVER rewrites `pods_ephemeral.json` based on an
   ambiguous duplicate group: repair fires only when exactly ONE live pod
   carries the name (current semantics); with >1 and no sidecar match, WARN
   and leave the sidecar untouched.
6. Regression tests cover criteria 1, 2, 4, 5; `uv run ruff check` /
   `workflow_lint.py` pass on touched files.

Fail-loud pin: tests/test_pod_lifecycle.py::test_list_ephemeral_shows_duplicate_named_pods — asserts the duplicate-name WARN is actually emitted on stderr (and pod_ids listed), so a re-swallowed / silently dropped warning fails the test rather than shipping green.

## 2. Method delta (what differs from current code)

Current: `_load_state()` (scripts/pod_lifecycle.py:422) builds
`live_by_name = {p.name: p for p in live_pods if _is_managed_pod(p)}` — a
last-wins dict comprehension that silently drops all but one pod per name —
then merges into a name-keyed `merged: dict[str, EphemeralPod]`. Every duplicate
is lost BEFORE any branch logic runs (verified at filing and re-verified at
clarify time). `cmd_list_ephemeral` iterates `_load_state().values()`, so the
listing structurally cannot show duplicates. `_find_pod_in_state` (targeting for
stop/resume/terminate/_live_ssh_endpoint) does NAME-keyed dict lookups
(`state.get(_canonical_pod_name(...))`), so the name-keyed return type must be
preserved for those consumers.

Delta: split the merge into (a) a FULL per-pod view — one `EphemeralPod` per
live managed pod, duplicates included — consumed by `cmd_list_ephemeral`, and
(b) the existing name-keyed PRIMARY view — one deterministic winner per name —
consumed unchanged by the four targeting call sites. `pod_audit.py` iterates
`list_team_pods()` directly (checked at clarify time) and is untouched.

## 3. File paths + concrete diffs

### 3.1 `scripts/pod_lifecycle.py`

- **`_load_state()` internals** (single function today) refactor:
  - Replace `live_by_name` with grouping:
    `live_groups: dict[str, list[PodInfo]]` over managed live pods.
  - Per name group, determine the PRIMARY live pod:
    1. the member whose `pod_id == meta.pod_id` (sidecar match), if a metadata
       row exists for the name — this also kills a second manifestation of the
       same bug, where an arbitrary API-order duplicate triggered spurious
       drift-repair / manual-override warnings against the sidecar;
    2. else RUNNING (`desired_status == "RUNNING"`) preferred, then newest
       `created_at` (None sorts oldest), then lexicographically smallest
       `pod_id` as the stable final tie-break.
  - Branch 1/2/3 logic (metadata+API, metadata-only drop, API-only synthesis)
    runs against the PRIMARY — semantics identical when the group is a
    singleton.
  - **Drift-repair guard:** the existing repair (meta.pod_id != live pod_id →
    rewrite sidecar) fires ONLY when `len(group) == 1`. With >1 members and no
    sidecar match: stderr WARN (name + all pod_ids + "ambiguous — sidecar left
    untouched"), no rewrite. The `manual_override` branch is preserved
    verbatim (evaluated against the primary; a sidecar match in the group means
    no mismatch exists and neither branch fires).
  - Non-primary group members ("shadowed" duplicates) each get a
    branch-3-style synthetic `EphemeralMetadata` (same fields as the existing
    API-only synthesis) so they render in the full view.
- **Full view accessor:** a new module-level function (suggested name
  `_load_state_all() -> list[EphemeralPod]`) returning one entry per live
  managed pod — primaries with their real metadata, shadowed duplicates with
  synthetic metadata. Implemented as a shared internal merge helper so
  `_load_state()` (name-keyed reduction) and `_load_state_all()` cannot drift.
  `_load_state()` keeps its exact signature `dict[str, EphemeralPod]`.
- **`cmd_list_ephemeral`** consumes the full view:
  - one row per live pod (existing columns; `POD_ID` already disambiguates);
  - `--issue` filter applies per-pod (`p.issue == args.issue`);
  - after the table, for every name with >1 live pod, print
    `WARN: <k> live pods share the name <name> (ids: <id1>, <id2>, ...) — duplicate-named pods indicate a provisioning-idempotency problem`
    to stderr (the "loud WARN row" from the task body);
  - empty-result messages unchanged.
