### 3.1 Adjacency definition — two anchored shapes; before-link excluded

Measured pattern-shape counts in the corpus:

| Shape | Grep count | Decision |
|---|---|---|
| **(A) Parenthetical immediately after a pinned HF link:** `[…](hf-tree-url) (`f.json`, …)` | **27** | **INCLUDE** — the incident shape; the parenthetical structurally annotates the link it follows |
| **(B) Backtick filename ≤60 chars BEFORE a pinned HF link** | **15** | **EXCLUDE** — real-corpus misattribution evidence: e.g. `` `predictor_comparison.json`). All firing-case raw completions: [data_scientist_seed42.json](blob-url) `` — the preceding filename belongs to a DIFFERENT (git-side/descriptive) claim in ≥3 of 10 sampled hits |
| **(C) Dotted backtick filename inside the link TEXT:** `` [`f.json`](hf-url) `` / `` [`f.json` @ sha](hf-url) `` | **44** (mixed `/tree/` + `/blob/`) | **INCLUDE the `/tree/` subset** — the link text names a file, the target names a pinned directory: an unambiguous membership claim (e.g. `` [`villain_seed42.json`](…/tree/…/raw_completions/) ``). `/blob/` hits are already fully path-validated by check 23 |

Proximity-window/same-sentence heuristics are rejected: backtick filenames are ubiquitous in these bodies (script names, figure stems, git-side claims), and the corrected #952 line puts an HF claim and a github-blob claim on ONE line — only structural anchoring (paren attached to the link's closing `)`; filename inside the link's own `[...]`) attributes claims correctly. A `` [`f.json` @ sha](https://github.com/...) `` git-side claim never matches: both shapes require the URL to match `_HF_HUB_TREE_BLOB_URL_RE` (host `huggingface.co`, hex sha) with `/tree/`.

### 3.2 Membership semantics — any-depth basename under the prefix

**Any-depth** (scoped recursive listing under the existing `_HF_PROBE_MAX_PAGES`=8 / `_HF_PROBE_DEADLINE_S`=12 s caps), matching `posixpath.basename(entry.path) == filename` for entries of ANY type (file or directory) under the prefix. Rationale: (i) the incident direction is a file absent from the WHOLE subtree (it lives in git), so any-depth still catches it; (ii) real parentheticals claim files that live one level down (e.g. `persona_bank.json`, `on_policy_R/R_{train,eval}.json` after a link to the tree ROOT — #472's rows), so direct-child-only would manufacture false WARNs; (iii) the depth-agnostic precedent is check 25 (#653). Cost: one bounded listing per unique pinned prefix — the same envelope as check 30's counter (typical one sub-second page; worst case ≈22.5 s/probe, ≤8 probes/body). A directory basename match also suppresses the WARN (FP-safe; dotted directory names are rare).

### 3.3 Severity — WARN, never FAIL

WARN (`CheckResult(name, True, detail, is_warn=True)`; no code path returns `passed=False`). Rationale: (i) a novel adjacency heuristic carries residual misattribution risk even with anchored shapes — checks 24/28/29/30 all shipped WARN-first for exactly this reason, and the nearest sibling (check 30, same claim-near-HF-link family) is WARN; (ii) check 23's FAIL is reserved for the unambiguous dead-pin semantics (the URL itself is broken); a missing NAMED file could still be a prose-shape misread; (iii) WARN keeps `ok=True`, so the change has zero blast radius on existing promoted bodies, migration re-verification (`task_workflow_migrate.py`), and the existing test suite's `assert ok` fixtures. Promote-to-FAIL is a candidate follow-up after a clean corpus sweep + live rounds.

### 3.5 Filename-token filter — dotted artifact-extension whitelist, no paths/globs

A backtick token is a claimable filename iff it matches:

```python
_HF_ADJ_FILENAME_RE = re.compile(
    r"^[A-Za-z0-9][A-Za-z0-9._\-]{0,63}"
    r"\.(?:jsonl?|pt|safetensors|npy|npz|csv|tsv|txt|md|png|pdf|parquet|bin|ya?ml|html|log)$"
```

- **Excluded by construction:** tokens with `/` (relative paths like `on_policy_R/R_train.json` — a claim about a subpath, not a basename; v1 recall sacrifice), brace-globs (`r50_seed{42,137,256}_phase1`, `R_{train,eval}.json`), wildcard globs (`*_responses.json`), no-dot tokens (pod names `eps-issue-642`, shas `a0330df0e8`, adapter dirs `villain_seed42/`), spaces, >64 chars.

- Figure PNGs claimed at HF tree paths stay in scope (checks 4b/22 cover GIT-side figures only; an HF-side PNG membership claim is the same class). No special-casing.

### 4.2 Gather helper

```python
def _gather_hf_adjacent_file_claims(body: str) -> list[tuple[str, str, str, str, str]]:
    """Extract (repo_id, repo_type, sha, path_prefix, filename) for backtick
    filename claims ADJACENT to hex-pinned HF /tree markdown links (check 32).
    Two anchored shapes (precision over recall — a missed claim costs nothing,
    a misattributed one costs a spurious WARN):
    - PAREN — parenthetical immediately after the link (`_HF_LINK_THEN_PAREN_RE`).
    - LINKTEXT — dotted backtick token inside the link TEXT (`_MD_HF_LINK_RE`).
    Known recall sacrifices: backtick filenames BEFORE the link (corpus
    evidence of misattribution — §3.1 of the plan), /blob/ links (check 23
    validates the full blob path), relative-path / brace / glob tokens,
    non-markdown bare URLs. Fence-stripped; deduplicated."""
    kind_to_type = {"datasets": "dataset", "spaces": "space", None: "model"}
    stripped = _strip_fenced_blocks(body)
    out, seen = [], set()

    def _add(url: str, token: str) -> None:
        fname = token.strip()
        if not _HF_ADJ_FILENAME_RE.match(fname):
            return
        m = _HF_HUB_TREE_BLOB_URL_RE.match(url.rstrip(".,;:!?"))
        if m is None or f"/tree/{m.group('sha')}" not in url:
            return  # non-HF (e.g. github) or /blob/ → out of scope
        prefix = (m.group("path") or "").rstrip("/")
        if posixpath.basename(prefix) == fname:
            return  # the URL's own terminal component — check 23 covers it
        key = (f"{m.group('owner')}/{m.group('repo')}", m.group("sha"), prefix, fname)
        if key in seen:
            return
        seen.add(key)
        out.append((key[0], kind_to_type[m.group("kind")], m.group("sha"), prefix, fname))

    for pm in _HF_LINK_THEN_PAREN_RE.finditer(stripped):      # shape PAREN
        for token in _BACKTICK_TOKEN_RE.findall(pm.group("paren")):
            _add(pm.group("url"), token)
    for lm in _MD_HF_LINK_RE.finditer(stripped):              # shape LINKTEXT
        for token in _BACKTICK_TOKEN_RE.findall(lm.group("text")):
            _add(lm.group("url"), token)
    return out
```

### 4.4 The check function

```python
def check_hf_adjacent_file_claims(body: str) -> CheckResult:
    """Check 32 (WARN): a backtick-named data file claimed adjacent to a
    hex-pinned HF /tree markdown link must appear (by basename, any depth)
    in the scoped listing at the pinned revision. [full docstring: incident
    #952 r1; shapes + recall sacrifices; WARN-never-FAIL; fail-soft;
    probe cap + memo + cache accounting — all following check 30's
    docstring skeleton]"""
    name = "HF-adjacent backtick file claims exist under the pinned tree"
    claims = _gather_hf_adjacent_file_claims(body)
    if not claims:
        return CheckResult(name, True, "no backtick file claims adjacent to HF tree links")
    missing, unverified = [], []
    probe_memo = {}
    for repo_id, repo_type, sha, prefix, fname in claims:
        key = (repo_id, repo_type, sha, prefix)
        if key not in probe_memo:
            if len(probe_memo) >= _HF_MEMBER_MAX_PROBES:
                _dedup_append(unverified, f"`{prefix or repo_id}@{sha[:8]}` (per-body probe cap)")
                continue
            probe_memo[key] = _hf_basenames_for_prefix(repo_id, repo_type, sha, prefix)
        status, basenames, note = probe_memo[key]
        if status != "ok":
            _dedup_append(unverified, f"`{fname}` at `{prefix or repo_id}@{sha[:8]}` ({note})")
            continue
        if fname not in basenames:
            missing.append(
                f"body claims `{fname}` adjacent to the pinned tree "
                f"`{prefix or '/'}` at `{repo_id}@{sha[:8]}`, but no entry with "
                f"that basename exists under the prefix at that revision"
            )
    if missing:
        detail = "; ".join(missing)
        if unverified:
            detail += "; unverified: " + "; ".join(unverified)
        return CheckResult(name, True, detail, is_warn=True)
    detail = f"{len(claims)} adjacent file claim(s) against {len(probe_memo)} pinned tree(s)"
    if unverified:
        detail += "; unverified (existence not confirmed): " + "; ".join(unverified)
    return CheckResult(name, True, detail)
```
