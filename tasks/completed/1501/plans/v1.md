## 0.0 TL;DR (plain English)

- **What I'll change:** the repo's own Bash lint hook already skips over document text written via heredoc, but it refuses that skip whenever the document contains `${ANYTHING}` — even a harmless `${VAR}` placeholder — and then the whole command gets blocked if the document also names a fenced git verb. I'll teach the refusal check to delete provably-harmless `${VAR}` placeholders before deciding, and add one line to the block message telling composers the already-working workaround (quote the heredoc tag).
- **What I expect:** doc-composition commands with plain `${VAR}` placeholders stop false-blocking (the pinned M1d case flips to allowed), while every shape that can actually execute the document's contents — `$(...)`, backticks, `${var@P}` (which I live-verified does execute), shell consumers, shell-out spellings — keeps blocking exactly as today.

## 4. Design

### Decision 1 — check (g) narrowing: safe-span deletion, NOT blanket `${` removal

The clarifier proposed refusing only on `$(`/backtick. **Live probes refute the blanket form:** `${V@P}` in an unquoted-tag body performs prompt expansion on the variable's VALUE, and with `promptvars` (on by default, verified non-interactively) that includes command substitution — a probe with a `$(...)` payload in the variable's value executed at feed time. So dropping the `${` arm entirely would open a feed-time execution channel through `${var@P}` (value-borne — env or same-command assignment — but a real primitive). The sound minimal narrowing is **allowlist-by-deletion**: delete spans matching plain `${NAME}` (which probe 1 confirms expands to a value and executes nothing — the exact semantics of bare `$NAME`, which check (g) has never refused, per the script's own line 1365–1366 precedent), then apply the ORIGINAL refusal regex to the remainder. Every non-plain form — `${V:-word}`, `${V@P}`, `${a[i]}`, `${!v}`, `${1}`, unclosed `${` — keeps refusing with zero new semantic claims. (`${V:-word}` was live-verified inert without nested substitution, but keeping it refused costs nothing and keeps the provable claim minimal; the composer remedy is the quoted tag.)

**E1 — the awk edit** (`scripts/guard_repo_root_branch.sh` line 622, inside pass 1 of `strip_heredoc_bodies()`):

```awk
# before (line 622)
if (!QUOTED && buf[j] ~ /\$\(|\$\{|\x60/) { ok = 0; break }
# after
if (!QUOTED) {
  scan = buf[j]                                     # COPY — never mutate buf[]
  gsub(/\$\{[A-Za-z_][A-Za-z0-9_]*\}/, "", scan)    # delete provably-inert plain ${NAME}
  if (scan ~ /\$\(|\$\{|\x60/) { ok = 0; break }
}
```

Soundness of the deletion: a plain-`${NAME}` span contains no `(`, no backtick, and cannot overlap a `$(` occurrence (the char after `$` in a span is `{`), so deletion can never REMOVE a refusal match — it removes exactly the `${` occurrences that are themselves plain spans, and any adjacency it creates (`$` + `{`) only ADDS matches (fail-closed direction). Validated at plan time against 9 line shapes (see §12 A-6). The copy (`scan`) is load-bearing: pass-1 refusal emits `buf[]` as the byte-identical original (line 632), and an in-place gsub before a later-line refusal would emit mutated text to the downstream detectors (fail-open in the `${`-inside-gated-text corner) — update the inline comment (lines 614–621) to state this.

- **Safe-span deletion over blanket `${`-arm removal.** Source: live probe — `${V@P}` executed a value-borne `$(…)` payload at feed time with default `promptvars` (§12 A-4); bash manual §3.6.6 (unquoted-delimiter bodies undergo parameter/command/arithmetic expansion).
