## §0 TL;DR

`scripts/cron_lesson_consolidate.sh` captures the consolidator's exit code into
its daily log and then `exit 0`s unconditionally. #2189 gave
`consolidate_lessons.py` a **new exit code 3** meaning "gotcha promotion refused
— appending would push `.claude/rules/gotchas.md` past
`GOTCHAS_SIZE_WARN_BYTES`". Nothing watches the log, so that refusal is
invisible: the same bullets re-refuse every night at 23:50 and the human
re-trim decision the guard exists to force is deferred indefinitely.

**Change:** add one `rc -eq 3` arm to the wrapper that fires a Telegram push
(fail-soft, deduped by a per-date sentinel) plus one audit sidecar row, and add
`tests/test_cron_lesson_consolidate.py` pinning the routing. `exit 0` is
retained unconditionally; rc=0 passes stay byte-for-byte silent.

**The finding that shapes the channel choice, which the task body did not
have:** the body proposed mirroring "whichever channel the disk-guard tier-(b)
escalation uses" and left Telegram-vs-sidecar open. §2.3 shows **cron email is
structurally dead on this VM** (no MTA, and every crontab line redirects
`2>&1`), so the sibling `cron_gcp_audit.sh` exit-code-propagation pattern
cannot notify anyone; and §2.4 shows **a sidecar with no reader is a second
silent channel** — every other `.claude/cache/*-events.jsonl` is paired with a
watcher pass, and lesson consolidation has none. So the push is the live
channel and the sidecar is audit-only, explicitly labelled as such.

## §1 Requirement and acceptance criteria

**Requirement.** A `consolidate_lessons.py` exit-3 budget refusal, observed at
the nightly cron boundary, produces a notification the same day instead of only
a log line — while routine passes stay silent and the consolidator's exit
semantics are untouched.

**Acceptance criteria (each pinned by a named test in §6):**

- **A1** — child rc=3 → exactly one `telegram_push.sh` invocation, and a
  per-date sentinel is written.
- **A2** — child rc=0 → zero push invocations, no sentinel, and the wrapper's
  observable output is otherwise unchanged from today.
- **A3** — a second wrapper invocation the same date after an A1 push → zero
  further push invocations (sentinel suppresses).
- **A4** — `telegram_push.sh` exits non-zero → NO sentinel is written (so the
  next pass retries), the failure is logged, and the wrapper still `exit 0`s.
- **A5** — `telegram_push.sh` missing / not executable → logged, no crash,
  wrapper still `exit 0`s.
- **A6** — the wrapper's exit status is `0` in every case above, including
  rc=3 (the body's "routine passes stay silent; `exit 0` retained" constraint,
  read together with §2.3: a propagated rc notifies nobody here).
- **A7** — the alert message names the refused-bullet count when the
  consolidator's counts line is parseable, and degrades to an explicit
  `unknown` token when it is not — never a crash, never an empty field.

### §4.2 The rc=3 arm

Placed **after** the brace group (line 47) and **before** the existing
`FIRST_RUN_OF_DAY` pointer-line block, so the arm's own diagnostics land in the
daily log via its own redirect:

```
if [ "$rc" -eq 3 ]; then
    {
        REFUSED=$(grep -o 'promote_refused_budget=[0-9]*' "$LOG_FILE" 2>/dev/null \
                  | tail -1 | cut -d= -f2)
        [ -n "$REFUSED" ] || REFUSED=unknown
        MSG="ALERT: lesson_consolidate refused $REFUSED gotcha bullet(s) — .claude/rules/gotchas.md is at its byte budget (GOTCHAS_SIZE_WARN_BYTES). No write, no commit; the same bullets re-refuse nightly until gotchas.md is re-trimmed. Log: $LOG_FILE (refused bullets printed verbatim there)"
        printf '{"ts":"%s","event":"promote_refused_budget","refused":"%s","log":"%s","rc":3}\n' \
            "$(date -Iseconds)" "$REFUSED" "$LOG_FILE" >> "$SIDECAR" 2>/dev/null \
            || echo "lesson_consolidate: sidecar append failed ($SIDECAR) — push is the live channel, continuing"
        if [ -f "$SENTINEL" ]; then
            echo "lesson_consolidate: sentinel $SENTINEL already exists — skipping re-alert"
        elif [ -x "$TELEGRAM_PUSH" ]; then
            if "$TELEGRAM_PUSH" "$MSG"; then
                touch "$SENTINEL"
                echo "lesson_consolidate: budget-refusal alert pushed + sentinel written ($SENTINEL)"
            else
                echo "lesson_consolidate: telegram_push.sh FAILED (no sentinel written; will retry next run)"
            fi
        else
            echo "lesson_consolidate: telegram_push.sh not executable at $TELEGRAM_PUSH — cannot alert"
        fi
    } >> "$LOG_FILE" 2>&1
fi
```

Notes that are load-bearing, not stylistic:

- **The sidecar row is written before the sentinel check**, so a suppressed
  re-alert still leaves an audit row (the sentinel dedups the *buzz*, not the
  record).
- **`$LOG_FILE` and `$SENTINEL` are expanded by this shell** before the string
  reaches `telegram_push.sh`, per §2.5.
- **`grep ... | tail -1`** takes the LAST counts line: a manual re-run the same
  day appends a second line to the same daily file.
- **Sidecar failure is non-fatal** — the push is the live channel (§2.4).
- The arm is inside `set -uo pipefail` (line 17) with **no** `set -e`, matching
  the file today; every branch is explicitly handled.
