# Plan v1 — #2377 workflow-fix: uv project-file poison arm for the /tmp sweep

## Requirement

Close the janitor/guard blind spot for stray top-level `/tmp` uv PROJECT FILES
(`/tmp/pyproject.toml`, `/tmp/uv.toml`, `/tmp/uv.lock`). A stray pair (dropped
2026-08-18 by an unidentified session) made every `/tmp`-cwd `uv run` on the
shared VM exit rc=2 — uv project discovery walks up to `/tmp`, finds the
project pair, and fails resolution — turning fleet-wide gate tests red. The
#2127 `sweep_tmp_scratch` leg covers top-level `/tmp` DIRECTORIES only; a
top-level project FILE pair is outside every janitor/guard surface today.

## Acceptance criteria (verbatim from the task body)

1. The sweep (or a guard/watcher pass) detects top-level
   `/tmp/{pyproject.toml,uv.toml,uv.lock}`.
2. Reap only under the existing evidence contract (git-blob identity proof →
   quarantine/reap); otherwise HARD-ESCALATE (push + sidecar row) naming the
   files and the uv blast radius — never an age-gated deletion (age is only
   ever a KEEP signal).
3. Respect the existing kill switches / contract of the #2127 leg it extends
   (`EPM_SKIP_TMP_SCRATCH_SWEEP=1` family).
4. A regression test pinning the new arm's fire + escalate branches.

## Method delta (vs the #2127 leg this extends)

- **File-granular, not directory-granular.** The #2127 leg's gate chain
  (walk stats, worktree-aware reap, reader-atime pinning) is directory-shaped;
  the new arm is a SEPARATE small function over exactly three fixed top-level
  file names, reusing the #2127 primitives that transfer (`_tmp_entry_owned`
  uid gate, `_blob_sha1_from_fd` + the `git cat-file --batch-check` odb probe,
  the `/proc` open-handle probe idiom, `append_disk_guard_event`,
  `tmp_scratch_sweep_enabled`).
- **Threshold-INDEPENDENT.** Verified constraint: `sweep_tmp_scratch` runs only
  inside `vm_disk_guard.run()`'s tier suite, which early-returns when `/` is
  under the usage threshold (`if not res.triggered: return res`,
  `vm_disk_guard.py` ~2232). The poison files are a few KB and would never
  trip the threshold, so the new arm runs as an UNCONDITIONAL every-pass leg
  in `run()` — the `GuardResult.device_fs` field ("computed on EVERY pass
  (even under-threshold)") is the in-file precedent — NOT as part of tier (f).
- **Quarantine, never unlink.** The apply action is a same-filesystem
  `os.rename` into a fresh `/tmp/eps-quarantine-uvproj-<UTC-ts>/` dir
  (mirrors the #2183 round-2 incident remediation; reversible restore point,
  named in the sidecar row). No deletion path exists in this arm at all.
- **Escalate ALWAYS (no byte floor).** The #2127 leg floor-gates KEEP
  escalations on `EPS_SCRATCH_ESCALATE_FLOOR_GB`; this arm's hazard is
  correctness (fleet-wide rc=2), not bytes, so every row escalates to the
  sidecar regardless of size, and escalate-class dispositions additionally
  fire the guard's `_telegram_push` (deduped, below).

## Files + concrete changes

### 1. `scripts/clean_experiment_downloads.py` — new function

```python
UV_PROJECT_POISON_NAMES = ("pyproject.toml", "uv.toml", "uv.lock")  # top-level /tmp only

def sweep_tmp_uv_project_files(
    tmp_root: Path | None,
    *,
    apply: bool,
    main_repo: Path | None,
    now: float | None = None,
) -> ScratchSweepResult:
    ...
```

Contract (docstring carries it, mirroring `sweep_tmp_scratch`'s):

- **Hermetic strict opt-in** identical to the #2127 leg: no-ops unless
  `tmp_root` AND `main_repo` are explicitly non-None AND
  `tmp_scratch_sweep_enabled()` (both kill-switch layers:
  `EPM_SKIP_NONCANONICAL_CACHE_SWEEP` family + `EPM_SKIP_TMP_SCRATCH_SWEEP`
  leg switch) → acceptance criterion 3. Library/test callers stay hermetic
  by construction.
- **Candidates:** exactly `tmp_root/<name>` for the three fixed names.
  Rows use `leg: "tmp-uvproj"`.
- **Per-candidate gate order** (every early exit is a KEEP; every row
  appends a sidecar event via `append_disk_guard_event` with
  `escalate=True` semantics — no byte floor — and a reason string naming
  the uv blast radius, e.g. "poisons uv project discovery for every
  /tmp-cwd uv run on the shared VM"):
  1. `lstat`: symlink or non-regular → `tmp-uvproj-nonregular-escalated`
     (KEEP).
  2. foreign uid (`_tmp_entry_owned` False) →
     `tmp-uvproj-foreign-owner-escalated` (KEEP; sticky-bit `/tmp` forbids
     renaming another uid's file anyway).
  3. open-handle probe (file-granular sibling of
     `_scratch_live_process_hit`: realpath EQUALITY on `/proc/<pid>/{cwd,exe,fd/*}`
     readlinks — no prefix matching for a file; `probe-unavailable` sentinel
     fails toward KEEP) → `tmp-uvproj-live-process-kept` (KEEP).
  4. evidence: file is NON-EMPTY and its git blob sha1
     (`_blob_sha1_from_fd`) exists in the main repo odb (the existing
     batched `cat-file --batch-check` helper). The non-empty requirement
     pins the known hermeticity trap ("an empty file's blob exists in every
     repo"). No proof → `tmp-uvproj-unverified-escalated` (KEEP + escalate;
     NEVER an age-gated deletion — age never licenses anything here).
  5. freshness grace: mtime younger than ~10 minutes →
     `tmp-uvproj-recent-escalated` (KEEP this pass; recency is a KEEP
     signal only — the next guard pass acts once the file is quiescent).
     Rationale: defends against racing a file mid-write; deliberately
     MINUTES not the #2127 leg's 48h window, because the poison is a live
     fleet-correctness hazard, and criterion 2's alert half still fires
     immediately on this pass.
  6. `apply=False` → `tmp-uvproj-would-quarantine` (escalate row).
  7. apply: pre-rename re-stat (size + mtime unchanged since the evidence
     read — the `_reap_scratch_tree` fresh-recheck idiom; changed →
     `tmp-uvproj-reap-aborted-recency`, KEEP), then `os.rename` into
     `/tmp/eps-quarantine-uvproj-<UTC-ts>/<name>` (dir created 0700) →
     `tmp-uvproj-quarantined`, row carries the quarantine path (restore
     point) + the evidence string. Rename failure →
     `tmp-uvproj-quarantine-failed` (KEEP + escalate).

### 2. `scripts/vm_disk_guard.py` — unconditional guard leg + push

- `GuardResult` gains `uv_project: TierResult | None = None` (same pattern
  as `device_fs`: computed on EVERY boot-disk pass, even under-threshold;
  read-only w.r.t. tiers/exit codes).
- In `run()`, BEFORE the `if not res.triggered: return res` early return:
  when the scratch opt-ins are present (`scratch_tmp_root` +
  `scratch_main_repo` non-None) and `tmp_scratch_sweep_enabled()`, call
  `sweep_tmp_uv_project_files(...)`, adapt rows onto a
  `TierResult(name="tmp-uvproj")` stored in `res.uv_project` (fail-soft:
  an exception in the leg degrades to a skipped TierResult with the
  reason; never crashes the guard pass).
- Report + `--json` surfaces include the new field (one detail line per
  row, same rendering shape as tier (f)).
- **Push (criterion 2's "push + sidecar row"):** any escalate-class
  disposition (`unverified-escalated`, `foreign-owner-escalated`,
  `nonregular-escalated`, `quarantine-failed`, `live-process-kept`) and the
  `quarantined` remediation row fire `_telegram_push` with a message naming
  the file(s), the disposition, and the uv blast radius. Deduped per
  (name, disposition) episode with a 24h re-alert window via a small JSON
  state file next to the existing escalation state (same
  `_should_escalate_active`-style pattern; report-only mode persists no
  state, mirroring the existing contract). `would-quarantine` and
  `recent-escalated` rows land in the sidecar but do NOT push (report-mode
  noise control; the apply-mode pass pushes when it acts or is blocked).

### 3. Tests — new `tests/test_tmp_uv_project_poison_sweep.py` (criterion 4)

Fixture: tmp_path-rooted fake `/tmp` + a small fixture git repo (committed
`pyproject.toml`), monkeypatched env for kill switches. Pins, one test each:

1. **fire branch:** `/tmp/pyproject.toml` byte-identical to the fixture
   repo's committed blob, no open handles → `apply=True` quarantines (file
   moved into the quarantine dir, original path gone), disposition
   `tmp-uvproj-quarantined`, sidecar row present.
2. **escalate branch:** file content NOT in the fixture repo odb →
   untouched + `tmp-uvproj-unverified-escalated` sidecar row.
3. **empty-file trap:** empty `/tmp/uv.lock` → NOT licensed (escalated,
   untouched) despite the empty blob existing in every repo.
4. **kill switches:** `EPM_SKIP_TMP_SCRATCH_SWEEP=1` → no-op; family switch
   `EPM_SKIP_NONCANONICAL_CACHE_SWEEP=1` → no-op.
5. **hermetic default:** `tmp_root=None` / `main_repo=None` → no-op (empty
   result), no filesystem reads.
6. **report mode:** `apply=False` → `tmp-uvproj-would-quarantine`, file
   untouched.
7. **symlink:** symlinked `/tmp/pyproject.toml` → `nonregular-escalated`,
   untouched.
8. **freshness grace:** just-written verified file → `recent-escalated`,
   untouched (with `now` injected to make the window deterministic).
9. **guard threshold-independence:** `vm_disk_guard.run()` with usage
   UNDER threshold (monkeypatched disk stats) still populates
   `res.uv_project` rows — pins the unconditional-leg placement.

Existing `tests/test_janitor_tmp_scratch_sweep.py` must stay green
untouched (no behavior change to `sweep_tmp_scratch` itself).

## Kill criteria

If the rename-quarantine path proves unsafe under review (e.g. an
unresolvable race with concurrent writers that the re-stat + grace window
cannot close), fall back to an ESCALATE-ONLY arm (detection + sidecar +
push, no quarantine) — this still satisfies acceptance criteria 1-3's
minimum bar ("or at minimum a vm_disk_guard/watcher alert").
