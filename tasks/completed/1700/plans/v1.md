### Edit 4: c20 — SKIP tier-1 lattices closed by `⇔ otherwise` when their predicates use threshold-form (non-zero) inequalities

**File / line range:** `scripts/verify_plan.py` `_c20_tier1_result` (lines 3324-3350) and `_c20_parse_predicate` (line 3132). The `_C20_POINT_RE` at line 2892 stays byte-unchanged (it correctly parses sign atoms `qty ≥/> 0`).

**Design:** The parser correctly REJECTS threshold-form predicates (`rung ≥ 5`, `≥ 8/9 pairs`, `≤ 1 rung`) as outside its cell algebra — they collide with `_C20_RESIDUE_RE` and mark the label `unparsed`, degrading the whole lattice to WARN. But when the plan's tier-1 declaration ALSO carries an `⇔ otherwise` complement label, the partition is EXHAUSTIVE by construction (the otherwise clause covers every residual cell) and the co-fire risk collapses to whatever the threshold predicates themselves might co-fire on — which is exactly the Statistics critic's job (mirror the existing tier-2 `_C20_QUANT_RE` SKIP at line 3362-3368).

Add ONE new atom class recognizer — `_C20_THRESHOLD_RE` — that matches `<qty> <ineq> <nonzero>` (e.g. `rung ≥ 5`, `≥ 8/9 pairs`, `≤ 1 rung`, `≥ 20 percent`, fractions, plain integers). When `_c20_parse_predicate` sees threshold atoms AND the enclosing lattice has an `⇔ otherwise` complement, return SKIP with the same rationale text as the k-of-n SKIP.

**Pseudocode / diff sketch:**

```python
# New regex — non-zero thresholds (mirror of _C20_POINT_RE but excludes 0):
_C20_THRESHOLD_RE = re.compile(
    r"(?P<qty>[^\s,;()]+)\s*(?P<cmp>≥|>=|≤|<=|>|<)\s*"
    r"(?P<thr>\d+(?:[./]\d+)?)"   # int, decimal, or fraction (8/9)
)

# Helper — does a segment carry a threshold atom (non-zero)?
def _c20_has_threshold_atom(segment: str) -> bool:
    for m in _C20_THRESHOLD_RE.finditer(segment):
        thr = m.group("thr")
        # Exclude "0" and "0.xxx" (handled by _C20_POINT_RE) and "0/N" fractions.
        if thr == "0" or thr.startswith("0.") or thr.startswith("0/"):
            continue
        return True
    return False

# In _c20_tier1_result, BEFORE calling _c20_parse_predicate on each clause:
has_otherwise = any(_C20_OTHERWISE_RE.search(cpred) for _, cpred in clauses)
uses_thresholds = any(_c20_has_threshold_atom(cpred) for _, cpred in clauses)
if has_otherwise and uses_thresholds:
    return _skip(
        cid, name,
        f"tier-1 lattice ({len(clauses)} clauses) uses threshold-form inequality "
        "predicates (e.g. `rung ≥ 5`, `≥ 8/9 pairs`) closed by an `⇔ otherwise` "
        "complement — the partition is exhaustive by construction and the "
        "co-fire risk is Statistics-critic scope, out of v1 cell algebra "
        "(mirrors the tier-2 k-of-n SKIP; #1689/#1700)"
    )
# EXISTING: sign-atom parse unchanged for clauses that DO use `qty ≥ 0` sign atoms.
```

**Acceptance criterion:** a tier-1 lattice like #1689's `H1_Confirmed ⇔ ≥8/9 within-identity framing pairs reconcile at rung ≤ 5 in BOTH models; H1_Falsified ⇔ ≥2 within-identity framing pairs need rung ≥ 7 in at least one model; H1_Inconclusive ⇔ otherwise.` SKIPs c20 (currently WARNs — the #1689 shape). A tier-1 lattice using sign atoms (`Δ > 0 AND CI excludes 0 on the positive side`, the #923 v6 shape) STILL PASSes / FAILs / WARNs as today (byte-unchanged behavior). A tier-1 lattice using threshold atoms but with NO `⇔ otherwise` complement STILL WARNs (the exhaustive-by-construction claim requires the otherwise closure). A tier-2 (per-label) lattice with threshold atoms STILL routes through the existing tier-2 SKIP.

**Note on the `_C20_POINT_RE` regex:** the current regex already handles `≥|>=|≤|<=`, so the "unicode inequality atoms" phrasing in the Goal is misleading in isolation — the actual defect is the parser rejecting `<qty> <ineq> <nonzero>` predicates on tier 1. This design fixes THAT (the real defect) while leaving `_C20_POINT_RE` byte-unchanged (it correctly parses sign atoms).

### Edit 5: NEW check — `c42_commit_sha_resolves`

**File / line range:** new function in `scripts/verify_plan.py` (append after `check_regression_anchor_executed` at line 6906), registered in the `CHECKS` list (line 7066).

**Design:** Every 7-40-char hex token the plan cites AS A COMMIT — the cite-as-commit grammar from `.claude/rules/workflow-fix-on-bug.md` clause (d) — must resolve under `git rev-parse --verify --quiet '<sha>^{commit}'`. A non-resolving one FAILs with a repair suggestion pointing at `git log --oneline --since='14 days ago' -- <touched-files>`.

**Cite-as-commit grammar** (from workflow-fix-on-bug.md clause (d), extended):
- `commit \`<sha>\`` — backticked hex directly after literal "commit"
- `landed in \`<sha>\`` / `landed at \`<sha>\`` — hex after "landed in/at"
- `\`<sha>\` (commit)` / `\`<sha>\` — commit ...` — hex followed by "(commit)" or "— commit"
- `**commit:** \`<sha>\`` / `**Commit:** <sha>` — bold-labeled commit field
- `**merge:** <sha>` / `merge \`<sha>\`` — merge SHA cite (a merge is a commit)
- `fix_sha=<sha>` / `fix_sha: <sha>` / `merge_sha=<sha>` — the marker-note convention from crash-fix rounds
- `Source: <sha>` when the value is a bare hex (no arXiv id / URL / issue token — a hex-only Source is a commit cite by convention)

**Exclusion set** (bare hex that MUST NOT trigger):
- `fingerprint: <hex>` / `fingerprint=<hex>` — workflow-fix body dedup key (12-char)
- `session ID <hex>` / `session \`<hex>\`` / session basenames — Codex transcript names
- `revision: <hex>` / `revision=<hex>` / `--revision <hex>` — HF Hub revision pins
- `HF revision <hex>`, `hf_revision`, `_dataset_revision`
- Hex tokens INSIDE fenced code blocks (`_fence_mask` — same as other c-checks)
- Hex tokens INSIDE inline code that is NOT preceded by a cite-as-commit marker (a bare backticked hex in prose without the cite context is out-of-scope)
- Bare hex tokens in the plan with NO commit-cite context on the same line or the immediately preceding line

**Pseudocode / diff sketch:**

```python
# Cite-as-commit context patterns. Anchored to a marker BEFORE the hex.
_C42_CITE_PATTERNS = [
    re.compile(r"(?i)\bcommit\s+`?(?P<sha>[0-9a-f]{7,40})`?\b"),
    re.compile(r"(?i)\blanded\s+(?:in|at)\s+`?(?P<sha>[0-9a-f]{7,40})`?\b"),
    re.compile(r"(?i)\bmerge(?:d)?\s+(?:in\s+|at\s+)?`?(?P<sha>[0-9a-f]{7,40})`?\b"),
    re.compile(r"(?i)`(?P<sha>[0-9a-f]{7,40})`\s*(?:\(commit\)|—\s*(?:commit|merge))"),
    re.compile(r"(?i)\*\*(?:commit|merge)(?:_sha)?:\*\*\s*`?(?P<sha>[0-9a-f]{7,40})`?\b"),
    re.compile(r"(?i)\b(?:fix_sha|merge_sha)\s*[:=]\s*`?(?P<sha>[0-9a-f]{7,40})`?\b"),
]

# Exclusion patterns — a hex captured by cite-context is disqualified if any fires
# on the SAME line, anywhere:
_C42_EXCLUDE_LINE_PATTERNS = [
    re.compile(r"(?i)\bfingerprint\s*[:=]"),
    re.compile(r"(?i)\bsession(?:_id)?\s*[:=]|session\s+basename"),
    re.compile(r"(?i)\brevision\s*[:=]|--revision|hf_revision|dataset_revision"),
]


def check_commit_sha_resolves(plan: str, kind: str) -> CheckResult:
    """Every hex token the plan cites AS A COMMIT (`commit \`<sha>\``,
    `landed in <sha>`, `**commit:** <sha>`, `fix_sha=<sha>`) must resolve
    under `git rev-parse --verify --quiet '<sha>^{commit}'`. Mirrors
    `.claude/rules/workflow-fix-on-bug.md` clause (d) on the filing side.
    FAIL (all kinds) — a typo'd commit SHA is a factual defect independent
    of experiment kind. Bare hex (fingerprints, HF revisions, transcript
    basenames, arXiv ids) is out of scope."""
    cid, name = "c42_commit_sha_resolves", "cited commit SHA resolves"
    lines = plan.splitlines()
    mask = _fence_mask(lines)
    cited: list[tuple[int, str, str]] = []  # (line_idx, sha, matched_context)
    for i, (line, fenced) in enumerate(zip(lines, mask, strict=True)):
        if fenced:
            continue
        if any(p.search(line) for p in _C42_EXCLUDE_LINE_PATTERNS):
            continue
        for pat in _C42_CITE_PATTERNS:
            for m in pat.finditer(line):
                sha = m.group("sha").lower()
                cited.append((i, sha, m.group(0)))
    if not cited:
        return _skip(cid, name, "no hex tokens cited as commits detected")
    # Deduplicate by SHA (a plan may cite the same commit N times).
    unique = {sha: (ln, ctx) for ln, sha, ctx in cited}
    unresolved: list[tuple[str, str]] = []
    for sha, (ln, ctx) in unique.items():
        try:
            r = subprocess.run(
                ["git", "rev-parse", "--verify", "--quiet", f"{sha}^{{commit}}"],
                capture_output=True, text=True, timeout=10,
                cwd=str(_C42_REPO_ROOT),  # module constant, Path(__file__).resolve().parent.parent (c31/c34/c37 idiom)
            )
            if r.returncode != 0:
                unresolved.append((sha, ctx))
        except (subprocess.TimeoutExpired, OSError):
            # Fail-open on git unavailability — this check is a mechanical
            # gate, not a hard block on a broken git install.
            return _skip(cid, name, "git rev-parse unavailable — check inconclusive")
    if not unresolved:
        return _pass(
            cid, name,
            f"all {len(unique)} cited commit SHA(s) resolve (verified via "
            "`git rev-parse --verify --quiet '<sha>^{commit}'`)"
        )
    detail = (
        f"{len(unresolved)} of {len(unique)} cited commit SHA(s) do NOT resolve as commits: "
        + "; ".join(f"{sha} (context: {ctx!r})" for sha, ctx in unresolved[:4])
        + (" …" if len(unresolved) > 4 else "")
        + ". Remedy: verify the SHA at compose time — "
        "`git rev-parse --verify --quiet '<sha>^{commit}'` — and re-derive the real "
        "commit (`git log --oneline --since='14 days ago' -- <touched-file>`) or "
        "cite the token as what it actually is (an HF revision, transcript basename, "
        "fingerprint), labeled as such. Mirrors "
        ".claude/rules/workflow-fix-on-bug.md clause (d)."
    )
    return _fail(cid, name, detail)
```
