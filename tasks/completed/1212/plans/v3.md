## 4. Design

### 4.1 Core decision: one tree, two phases — lint the landing tree with and without the payload

- **Construct once:** `git -C "$WT" fetch origin main --quiet || true`, then `git -C "$WT" archive origin/main -- .claude CLAUDE.md scripts src tests docs pyproject.toml | tar -x -C "$GT"` — origin/main's copy of `workflow_lint.py`'s complete scan/target surface. Measured this session: 1.0 s, ~60 MB (a FULL checkout is ruled out: 7.62 GB at origin/main). `docs` is REQUIRED — the #1154 `_MARKER_RECIPE_PINS` check reads `docs/marker_training_recipe.md` (`workflow_lint.py:8455 (`_MARKER_RECIPE_DOC`)`); the first smoke without `docs` failed with exactly that missing-file error (6 errors). `pyproject.toml` is included defensively (1 file). A plain directory suffices — no git worktree, no sparse-checkout config mutation: the only subprocess consumer (`check_git_recipes_root_guard`) invokes the hook with a hardcoded absolute `REPO=/home/thomasjiralerspong/explore-persona-space` (`scripts/guard_repo_root_branch.sh:416`), and `_other_worktree_prefix` is pure path-string logic (`workflow_lint.py:2145`).
- **Phase 1 — BASELINE legs (payload-free landing base):** run `"$GT/scripts/workflow_lint.py"` (no-flags bundle + parity leg) BEFORE any overlay. This replaces the root-copy-on-root-tree baseline: origin/main red shows here (and on the gated leg) and subtracts out; root dirt and root-local unpushed lint changes no longer enter the compare (§6.1 showed both live today).
- **Phase 2 — payload overlay:** materialize a DEDICATED overlay listing — `git -C "$WT" diff --name-only --no-renames origin/main...HEAD > /tmp/issue-<N>-overlay-files.txt` (producer-guarded into `GT_RC`) — then for each listed path write the BRANCH-TIP content via `git -C "$WT" show "HEAD:$p" > "$GT/$p"` when the path exists at HEAD, else `rm -f "$GT/$p" || GT_RC=1` (branch deletion OR rename SOURCE ⇒ absent from the landing tree; the rm is GT_RC-folded so an exotic /tmp rm failure fails CLOSED instead of leaving the fail-open case-f residue). The shared `/tmp/issue-<N>-own-diff.txt` is NOT reused for the overlay: it is `--name-only` WITH rename detection, which lists only a rename's DESTINATION — a renamed-away source would silently survive in the gated tree (fact-check finding: fail-open on old-path references; false-block on index-style checks, e.g. a renamed `.claude/rules/*.md` leaving old+new files while the overlaid LESSONS.md indexes only the new). `--no-renames` splits a rename into D(old)+A(new) so one loop body handles both sides; own-diff.txt and its attribution consumers stay byte-untouched. This is what makes §5 cases (a)/(b)/(f) safe by construction: a branch that modifies `workflow_lint.py` or a helper gets its OWN copy into the gated tree — the payload is exercised, never overwritten.
- **Phase 3 — GATED legs (payload-bearing landing tree):** same `"$GT/scripts/workflow_lint.py"` invocations. Scan root derives from `__file__` ⇒ `$GT`. Empirically verified this session from a /tmp plain-dir tree: parity leg rc=0 in 1.3 s; `--check-git-recipes-root-guard` rc=0 in 5.2 s; full no-flags bundle result in §6.1.
- **Fail CLOSED:** every construction/overlay step folds failures into `GT_RC`; the crash arm gains `[ "$GT_RC" -ne 0 ] ||`. A gate that cannot build its trees never produces a `pass`.
- **Teardown:** `rm -rf "$GT"` after the verdict write (a crash-left tree is rebuilt from scratch — the construction starts with `rm -rf`). $WT and the repo root are NEVER written; no commits are created, so the verdict's sha-bind (`git -C "$WT" rev-parse HEAD`) is unaffected.
- **Unchanged:** trigger, own-diff materialization, mapped invariant-TEST legs (branch-tip `$WT` gated / root baseline, deliberately — 4.4), normalization, `comm -23`, own-diff attribution, verdict file semantics, all three binding-site conditionals. Wall per gate run unchanged: two lint bundles run today, two run after; +~1-2 s construction.
- **Bonus corrections that fall out of the one-tree design:** (i) absolute-path failure-line formats (e.g. the root-guard formatter `f"{p}:{lineno}"`, `workflow_lint.py:7449-7473`) now SUBTRACT correctly — both legs share the `$GT` path prefix (previously $WT-vs-root prefixes made such lines unconditionally non-subtractable); (ii) the moving-main race between legs vanishes (both legs read one archived snapshot; the existing back-to-back advice stays as defense-in-depth); (iii) the root-dirt mask closes (an untracked same-path root draft of a payload file can no longer enlarge the baseline set and mask a real payload offense).

      --check-references --check-tables --check-asks --check-autonomous-asks \
      >> /tmp/issue-<N>-lint-baseline.txt 2>&1 \
      || { rc=$?; if [ "$rc" -gt "$BASE_RC" ]; then BASE_RC=$rc; fi; }

## 11. Decision Rationale

`N/A — no model training` — no training hyperparameters exist in this task. The load-bearing DESIGN choices:

1. **One ephemeral landing tree, two phases (baseline pre-overlay / gated post-overlay), NOT an in-place vintage-sync of `$WT` and NOT a root-tree baseline.**
   - **What:** build `/tmp/issue-<N>-lint-gate-tree` via `git archive | tar`; baseline legs from the payload-free tree; overlay the own-diff from the branch tip; gated legs from the same copy.
   - **Why:** (i) single-vintage-single-source compare makes `NEW = gated − baseline` payload-caused by construction — fixes #1112 classes 1-2, latent class 3, AND the two-source residuals the plan-time smoke caught live (§6.1: root-vs-origin/main linter vintage, root dirt); the candidate in-place sync (cp main's linter into `$WT` + materialize missing helpers) fixes classes 1-2 but CREATES class-3 exposure (main's newer linter flagging stale non-payload `$WT` files main already fixed, e.g. the 34 #1144 offenders on a pre-#1144 fork ⇒ NEW ⇒ false block — the exact Goal failure re-introduced); (ii) `$WT` and the root are never dirtied ⇒ no restore bracket, no crash-leftover unstaged changes that would make form (ii)'s `git merge origin/main` refuse; (iii) the linter-in-payload and helper-in-payload special cases fall out of the overlay for free (no skip-if-own-diff branching); (iv) crash re-entry is self-healing (`rm -rf` first); (v) bonus: absolute-path failure lines subtract (shared `$GT` prefix), the moving-main inter-leg race vanishes (one snapshot), the root-dirt mask closes.
   - **Source:** #1112 incident body + this session's empirical smoke (parity / root-guard / no-flags from a /tmp tree; the GT-vs-root divergence diagnosis); `workflow_lint.py:578-579` (`__file__` scan-root); `guard_repo_root_branch.sh:416` (hardcoded absolute `REPO=` ⇒ non-git dir OK); full-tree size 7.62 GB vs cones ~60 MB.
   - **Alternatives rejected:** (a) task-body candidate `git -C "$WT" checkout origin/main -- scripts/workflow_lint.py <helpers>` + restore — leaves class 3 open, dirties `$WT` index+worktree for ~12 min, needs skip-if-own-diff logic and a two-path restore, and a crashed gate strands unstaged changes; (b) temp-named copy inside `$WT/scripts/` (the brief's example) — derives the right scan root but the copy itself gets SCANNED under a non-canonical filename, breaking exact-path-keyed allowlists (e.g. `JUDGE_PIN_LEGACY_ALLOWLIST` keys on repo-relative paths, `workflow_lint.py:1935`) ⇒ manufactures new gated-only lines; (c) keep baseline on the root copy (the first draft of this plan) — the §6.1 smoke showed BOTH divergence directions live between root and origin/main the very day of planning; (d) strip reference-check failure lines whose target exists on origin/main and is untouched by the own-diff — post-hoc line-format coupling, covers only `--check-references`, and per-check strip rules would proliferate; (e) sparse git worktree instead of `archive|tar` — works but mutates shared repo config (`extensions.worktreeConfig` on git 2.34), registers worktree metadata, needs `worktree remove` teardown, and buys nothing over a plain dir given the hook's hardcoded `REPO=`.
   - **Overlay listing (added v2, fact-check finding 6):** a DEDICATED `--no-renames --name-only` diff drives the overlay, NOT the shared own-diff.txt.
