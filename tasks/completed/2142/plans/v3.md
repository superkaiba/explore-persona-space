## Requirement

The watcher's two auto-dispatch lanes (`infra_drain_pass`, `proposed_infra_sweep_pass`) can
spawn an `/issue` session against a task another session already owns, and can dispatch a batch
past the occupancy cap. Five same-day incidents:

| Incident | Gap after owner activity | Shape |
|---|---|---|
| #1771 | 59 s after owner registration | duplicate spawn |
| #1997 | 26 s after owner progress note | duplicate spawn |
| #1988 | 9 s after the watcher dispatched the owner | duplicate spawn (two lanes, one tick) |
| #1992 | 29 s after owner activity | duplicate spawn |
| cap    | occupancy 6 observed at cap 5 | batch overshoot |

All four duplicates were caught downstream by the `/issue` Step 0 single-orchestrator guard and
exited cleanly, so **no state was corrupted**. The cost is four wasted spawns plus cold-session
boot (~100K tokens each under the #1059 stagger rationale) and a misleading occupancy reading.
This is a waste/robustness fix, not a correctness hole — the plan does not claim otherwise.

### What exists today (verified, Step 1 clarifier — line numbers at `main`)

- **Lease check is already per-candidate**, not once-per-pass: `dispatch_lease_fresh(issue, now)`
  at line 26095 (drain loop) and 26622 (sweep loop). The body's "not once per pass" framing is
  already satisfied at loop level.
- **The gap is staleness, not absence.** Both checks use the *pass-start* `now`. Control then
  enters `_dispatch_infra_drain`, which sleeps out the remainder of the #1059
  session-dispatch stagger window (`session_dispatch_stagger_s()`, `EPM_SESSION_DISPATCH_STAGGER_S`,
  default 60 s) at line 25690 — *before* `subprocess.run(cmd)` at 25717. The **registration** is
  re-checked after that sleep (25691-25716); the **lease is not**. Every observed incident gap
  (9 / 26 / 29 / 59 s) falls inside that 60 s window.
- **No registration-freshness skip exists.** `registered_nonstale = raw_registered - stale`
  (26060) drops registrations classified stale, and the pre-spawn re-check *deliberately
  proceeds* on a registration byte-identical to the decision snapshot (in-code comment at
  25715-25716: "the known (stale) registration the decision already accounted for; proceed").
  It aborts only when a registration APPEARED or CHANGED.
- **No per-spawn cap re-check exists.** `occupied_active` (26070) and `pending` are computed once
  per pass. Inside the loop, `slot_desc`'s `min(occupied_active + pending + dispatched + 1, cap)`
  is **display-only**; nothing breaks or skips when the running total reaches the limit. With a
  ~60 s stagger between consecutive spawns, a multi-candidate batch spans minutes while
  occupancy changes underneath it.
- The sweep runs **after** the drain in the same tick and **shares its cap** — the structural
  reason two lanes can fire on one ripe task (#1988's 9 s gap).
- `_recent_dispatch_marker_age_s` (#843 M3, line 26634) already guards the sweep loop against a
  dispatch marker younger than one cadence. It is the suspenders; item 2 below is the belt. The
  drain loop has **no** equivalent marker guard.

### Premise correction (recorded)

The task body asks to "re-check the dispatch lease immediately before POSTing each spawn (not
once per pass)". The per-pass framing is inaccurate — the check is already per-candidate. The
real defect is that the per-candidate verdict is computed up to one stagger window before the
POST it guards. The fix targets the actual defect; the body's framing is corrected here rather
than implemented literally.

## Non-goals (hard)

1. **Do not remove or weaken the sanctioned urgent overflow.** `decide_proposed_infra_sweep`
   grants `limit = cap + (urgent_bonus if i in urgent else 0)` via `_infra_sweep_urgent_bonus()`.
   That legitimately produces occupancy 6 at cap 5, so the reported overshoot may be **sanctioned
   bonus rather than drift**. Every new cap re-check compares against the *same*
   `cap + urgent_bonus` limit the decide function used — never a bare `cap`. A naive
   `if occupied >= cap: break` would silently delete the urgent affordance and is rejected.
2. Do not change `spawn_session.py`'s lease acquisition (#843 M1b) — the in-subprocess lease plus
   its `spawn_output_suppressed` sentinel remain the authoritative chokepoint. This plan only
   makes the *caller* stop paying for spawns the chokepoint will reject.
3. Do not change the stagger window itself. Shortening it would trade a 429-pacing protection for
   a race fix that the re-check obtains for free.
4. No change to marker schema, status enum, or any `task.py` subcommand (no public-contract change).

## Acceptance criteria

1. A dispatch lease appearing **during** the stagger sleep prevents the spawn: no
   `subprocess.run` of `spawn-issue`, tri-state `"suppressed"`, and **no attempt / no backoff /
   no marker** booked by the caller.
2. A candidate whose session registration is younger than the freshness window is skipped in
   **both** loops, with no attempt recorded.
3. Within a single batch, once live occupancy reaches the candidate's `cap + urgent_bonus` limit,
   remaining candidates are skipped — and an urgent candidate still receives its bonus slot.
4. A failed live-occupancy read mid-batch stops further spawns this tick (fail-closed), matching
   the existing pass-level behavior at 26062-26069.
5. `tests/test_dispatch_lease.py` covers all of 1-4; the pre-existing 21 tests still pass.
6. `uv run python scripts/workflow_lint.py` clean for the touched files; `ruff` clean.

## Method delta

### 1. `scripts/autonomous_session_watch.py` — post-stagger lease re-check

In `_dispatch_infra_drain`, after `_stagger_sleep(delay)` and adjacent to the existing
registration re-check block, add a **fresh** lease check using a fresh `time.time()`:

```python
# #2142: the caller-loop lease check ran BEFORE the stagger sleep (up to
# EPM_SESSION_DISPATCH_STAGGER_S, 60s), so its verdict is stale by exactly the
# window in which every observed duplicate landed (9/26/29/59s). Re-check with a
# fresh clock immediately before the POST.
held = dispatch_lease_fresh(issue, time.time())
if held is not None:
    print(
        f"  INFRA-DRAIN SUPPRESSED issue #{issue} (dispatch-lease acquired during "
        f"the pre-spawn window, {dispatch_lease_desc(held)})"
    )
    return "suppressed"
```

**Tri-state choice — `"suppressed"`, not `"failed"`.** This is the load-bearing design decision.
A lease held by another dispatcher is precisely the "a session IS driving the issue" condition the
`"suppressed"` contract exists for: book nothing. Returning `"failed"` would record a spawn-failed
attempt and consume the 1 h backoff, which the in-code comment at 26092-26094 explicitly warns
stretches a crashed lease-winner's recovery from `TTL + one tick` to ~70 min. The existing
caller-loop lease skip likewise records no attempt; this keeps the two consistent. The
registration re-check keeps returning `"failed"` (unchanged) — a changed registration is a lost
race with real ambiguity, not a clean duplicate-suppression.

Update the `_dispatch_infra_drain` docstring: the sentence "the pre-spawn re-check aborts (both
record a spawn-failed attempt in the callers, exactly as before)" becomes accurate only for the
*registration* arm and must name the lease arm as `"suppressed"`.

### 2. `scripts/autonomous_session_watch.py` — registration-freshness skip

New module-level helper beside the other registration readers:

```python
DISPATCH_REG_FRESH_S_DEFAULT = 600.0  # one watcher cadence

def _registration_age_s(issue: int) -> float | None:
    """Age in seconds of the newest session registration for `issue`, or None
    when no registration exists. Prefers the JSON `spawned_at`; falls back to
    file mtime. A present-but-unreadable/garbled registration returns 0.0
    (treated MAXIMALLY FRESH) — the fail-CLOSED direction, matching
    dispatch_lease_fresh's garbled-mtime convention and the OSError abort at
    the pre-spawn registration re-check."""
```

Applied in **both** dispatch loops, before the spawn call, after the existing lease check:

```python
reg_age = _registration_age_s(issue)
if reg_age is not None and reg_age < fresh_window:
    print(f"  ... SKIP issue #{issue} (registration {reg_age:.0f}s < {fresh_window:.0f}s)")
    continue   # NO attempt recorded — a fresh owner is not a spawn failure
```

`fresh_window` comes from `EPM_DISPATCH_REG_FRESH_S` (default `DISPATCH_REG_FRESH_S_DEFAULT`),
read through the existing `_env_float` helper with the same lo/hi clamping style used by
`_proposed_infra_sweep_marker_fresh_s`. Kill switch: setting it to `0` disables the guard.

This subsumes the `- stale` subtraction's blind spot without touching it: a registration the
staleness rule classified stale but which is only seconds old is now skipped anyway.

### 3. `scripts/autonomous_session_watch.py` — per-spawn cap/limit re-check

In both loops, before each spawn **except the first** (the pass-level occupancy read is
microseconds old at the first candidate, so re-reading it is pure cost):

```python
if dispatched > 0:
    live = _infra_drain_occupancy()
    if live is None:
        print("  ... STOP: live occupancy read FAILED mid-batch; not dispatching "
              "further this tick (fail-closed, mirrors the pass-level guard)")
        break
    limit = cap + (urgent_bonus if issue in urgent else 0)   # sweep loop
    if len(live) + pending >= limit:
        print(f"  ... SKIP issue #{issue} (cap-full-recheck: live {len(live)}+{pending} "
              f">= limit {limit})")
        continue   # NO attempt recorded — occupancy filling is not this candidate's failure
```

The drain loop uses `limit = cap` (`decide_infra_drain` grants no bonus — verified). The sweep
loop threads through the same `urgent` set and `_infra_sweep_urgent_bonus()` value already passed
to `decide_proposed_infra_sweep` at 26613-26614, satisfying non-goal 1 by construction.

`continue` rather than `break` on a cap-full re-check: a later urgent candidate may still hold a
bonus slot the current non-urgent candidate does not.
