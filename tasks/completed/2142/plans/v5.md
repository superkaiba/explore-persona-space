## Method delta

### 1. Post-stagger lease re-check (cheap robustness — NOT the headline)

In `_dispatch_infra_drain`, after `_stagger_sleep(delay)`, beside the registration re-check:

```python
# #2142: the caller-loop lease check ran BEFORE the stagger sleep (up to 60s),
# so its verdict is stale at the POST. The load-bearing element is the fresh
# FILE READ (a lease acquired during the sleep reads fresh under any earlier
# `now`); the fresh clock only avoids over-suppressing a lease that expired
# mid-sleep. Saves one self-suppressing spawn_session subprocess — the boot is
# already prevented by the chokepoint at spawn_session.py:2341-2350.
held = dispatch_lease_fresh(issue, time.time())
if held is not None:
    print(f"  INFRA-DRAIN SUPPRESSED issue #{issue} (lease acquired during the "
          f"pre-spawn window, {dispatch_lease_desc(held)})")
    return "suppressed"
```

`"suppressed"`, not `"failed"` — verified against the docstring contract (`:25651-25667`) and both
callers' booking (`:26104-26107`, `:26643-26645`): a lease at POST time is the "a session IS
driving" no-op. `"failed"` would book an attempt and consume the 1 h backoff, stretching a crashed
lease-winner's recovery from TTL+one-tick to ~70 min (`:26090-26094`). The registration arm keeps
returning `"failed"` (a changed registration is a genuinely ambiguous lost race). Update the
docstring: its "the pre-spawn re-check aborts (both record a spawn-failed attempt)" sentence is
accurate only for the registration arm.

### 2. Registration-freshness skip (HEADLINE — closes #1771, #1992, #1988)

```python
DISPATCH_REG_FRESH_S_DEFAULT = 600.0  # >> the 26-59s incident ages

def _registration_age_s(issue: int) -> float | None:
    """Age in seconds of the newest session registration for `issue`, or None
    when none exists. Prefers the JSON `spawned_at`, falls back to file mtime.
    A present-but-garbled registration returns 0.0 (treated MAXIMALLY FRESH) —
    the fail-CLOSED direction, matching `_infra_drain_stale`'s
    fail-toward-keep-blocking posture (:25495). NOT dispatch_lease_fresh's
    garbled-mtime convention (that one is mtime-with-TTL,
    spawn_session.py:395-402) — do not "align" this to mtime; that would
    unbound the wedge the wrong way."""
```

Applied in **both** loops after the lease check, before the spawn:

```python
reg_age = _registration_age_s(issue)
if reg_age is not None and reg_age < fresh_window:
    print(f"  ... SKIP issue #{issue} (registration {reg_age:.0f}s < {fresh_window:.0f}s)")
    continue   # NO attempt — a fresh owner is not a spawn failure
```

`fresh_window` from `EPM_DISPATCH_REG_FRESH_S` via `_env_float` with the clamping style of
`_proposed_infra_sweep_marker_fresh_s`; `0` disables the guard (kill switch). This overrides the
`- stale` subtraction's blind spot without touching the staleness rule itself.

Not a regression for a permanently-garbled registration: such a file already parses to `{}`
(`:25477-25480`), classifies NOT-stale (`:25492-25499`), and blocks via `already-registered` today.

### 3. Per-spawn cap/limit re-check — corrected formula

Before each spawn, when any prior `_dispatch_infra_drain` call happened this pass (**not**
`dispatched > 0` — after a `"failed"`/`"suppressed"` first attempt `dispatched` is still 0 but the
stagger already elapsed, leaving candidate 2's data ~60 s stale with no re-check):

```python
if attempted_any:
    live = _infra_drain_occupancy()
    if live is None:
        print("  ... STOP: live occupancy read FAILED mid-batch; not dispatching "
              "further this tick (fail-closed, mirrors the pass-level guard :26062-26069)")
        break
    limit = cap + (urgent_bonus if issue in urgent else 0)     # sweep; drain uses `cap`
    # `+ dispatched` mirrors the decide-time walk's `len(dispatch)` term (:26454).
    # WITHOUT it the re-check under-counts by the number of in-batch spawns: a
    # just-dispatched task stays `proposed` for minutes (absent from the 8 active
    # occupancy statuses, :24829-24840) and pass-start `pending` predates its
    # registration. A fast-flipping own dispatch then double-counts — the safe
    # `continue` direction.
    if len(live) + pending + dispatched >= limit:
        print(f"  ... SKIP issue #{issue} (cap-full-recheck: live {len(live)}+{pending}"
              f"+{dispatched} >= limit {limit})")
        continue   # NO attempt — occupancy filling is not this candidate's failure
```

`continue`, not `break`: a later **urgent** candidate may still hold a bonus slot this one does not.

**Scope honesty:** this re-check sits in the caller loop, *before* the stagger sleep inside
`_dispatch_infra_drain`, so each spawn's occupancy verdict is still up to 60 s stale at the POST.
It **narrows** the cap race; it does not close it. Do not narrate it as closing the window.
