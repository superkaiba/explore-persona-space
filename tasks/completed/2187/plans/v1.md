#### 4.1 The four required decisions (explicit)

1. **Count-only trap → NAME-SET diff.** The check computes `residue = names(disk) − (names(HF ∪ git) ∪ declared_discards ∪ exemptions)`; counts are reported as context only and never enter the verdict. Matching key = **basename** (pod path `/workspace/issue2162_out/upload_done.json` vs HF path `issue2162_slug/.../upload_done.json` share no path structure; basename is the only stable join key). Residual disclosed: two distinct files sharing a basename can mask genuine residue (false PASS for the unmatched one); the strict-path alternative would false-FAIL nearly everything. Fail-direction of ambiguity: an *undeclared* HF prefix makes its files invisible → they read as residue → FAIL (safe direction — the agent declares the prefix and re-runs).
2. **Chicken-and-egg canonical answer: route upload-completion markers/sentinels to GIT** (`eval_results/issue_<N>/...`), written into upload-policy.md so per-issue authors stop reinventing it. Rationale: a marker written AFTER its own upload structurally cannot be inside that upload; a "second tiny upload" recreates the identical problem for ITS OWN completion signal (regress); writing the marker BEFORE the upload makes it attest something that has not happened. Git is terminal: committing IS the persistence event and is verified directly by `git ls-tree`. This is the demonstrated-working #2162 answer (`92f25415ee`).
3. **Mechanical vs prose split, per surface:** see §5 table. Two mechanical layers (verify_uploads check row; terminate-guard token), four prose layers. Honesty note carried into the rule text: the guard token is an *attestation* gate — it mechanically forces the sweep into every experiment-pod terminate path but cannot itself prove the sweep ran; the verify_uploads check is what makes the sweep itself mechanical. Together: termination cannot proceed without someone running (and attesting) a check that fails loud on residue.
4. **Where the FAIL fires:** (a) Step-8 verifier path — `outroot_residue` row FAIL → verifier FAIL → Step 8 refuses termination and auto-recovers (existing Step-6/Step-8 semantics, unchanged); (b) suffixed-pod / deferred-leg / inline-round teardowns (incidents 2 and 3's paths) — the terminate guard fires on EVERY `pod.py terminate` for experiment tasks, which is the only chokepoint those paths share; (c) never-ran pods — `--skip-upload-verify` unchanged.
