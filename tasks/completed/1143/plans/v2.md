### D.1 New module-level constants (`scripts/verify_task_body.py`, in the check-30 block after `_BACKTICK_DIR_RE`, ~line 7324)

```python
# Pattern D (#1143, the #1112 footer shape): a backtick DIRECTORY token
# (trailing slash = the directory signature, same charset as
# _BACKTICK_DIR_RE; a dotted token without it is check 32's FILE territory)
# immediately followed by a parenthetical OPENING with the count-noun.
# The count scopes to <link-prefix>/<sub> at the sha of the nearest
# preceding pinned /tree link on the same line (binder below). The paren
# qualifier bound is 200 (Pattern B uses 80; the live #1112 qualifier is
# ~85 chars). Trailing negative lookahead: a paren immediately followed by
# an HF markdown link is Pattern B's paren-before-link shape — D declines
# rather than extracting a second, differently-scoped claim.
_BACKTICK_SUBPATH_COUNT_PAREN_RE = re.compile(
    r"`(?P<sub>[A-Za-z0-9_\-./]{1,120}/)`"
    r"[ \t]{0,2}"
    r"\((?P<count>\d{1,3}(?:,\d{3})+|\d{1,6})\s+(?P<noun>files?|shards?)\b"
    r"(?!\s+(?:listed\s+)?per\s+\w+\b)"
    r"[^()]{0,200}\)"
    r"(?!\s{0,2}[:–—-]?\s{0,2}\[[^\]]{1,300}\]\(https?://huggingface\.co)",
    re.IGNORECASE,
)
# Max chars between the link's closing ")" and the claim's backtick token.
# The live #1112 gap measures ~132 chars ("— `mixes/` (…), `selection/`
# (…), "); 400 gives ~3x margin while bounding runaway binding.
_SUBPATH_CLAIM_MAX_GAP = 400
```

Named groups: `sub` (the relative sub-path, trailing slash kept by the regex, stripped at join time), `count`, `noun`. The negative lookahead WIDENS `_COUNT_NOUN_RE`'s per-namespace decline to ANY distributive qualifier (`per \w+`): a `` `dir/` (891 files per namespace…) `` claim never acquires whole-prefix semantics, and a `` `dir/` (11 files per adapter, …) `` claim (the #460 shape the fact-checker's sweep surfaced — per-adapter semantics, join would target a nonexistent path) is declined too. Fact-check basis: the narrow per-namespace-only lookahead measured 1 spurious sweep hit (#460); `per \w+` declines it while #1112 (qualifier opens with `:`) and #591 (qualifier opens with `,`) are unaffected.

### D.2 New binder helper (module-level, testable)

```python
def _nearest_preceding_pinned_tree_link(
    stripped: str, pos: int, links: list[re.Match]
) -> re.Match | None:
    """Pattern-D binding (#1143): the nearest markdown HF link (from the
    caller's precomputed `_MD_HF_LINK_RE` match list) ending at/before
    ``pos``, accepted ONLY when the gap between its closing ``)`` and
    ``pos`` (a) contains no newline (same footer row), (b) contains no
    ``[`` or ``]`` (no markdown link starts or ends inside the binding
    run — declines rather than binding PAST an intervening link, and a
    claim sitting inside another link's TEXT never binds backward), and
    (c) is <= _SUBPATH_CLAIM_MAX_GAP chars; and (d) the link parses as a
    hex-pinned /tree link (_HF_HUB_TREE_BLOB_URL_RE + "/tree/<sha>" —
    same guards as _add). Any failure returns None: the claim stays
    unextracted (precision over recall; a missed claim costs nothing on
    a WARN-only check)."""
    best = None
    for lm in links:
        if lm.end() <= pos:
            best = lm
        else:
            break  # finditer order is left-to-right
    if best is None:
        return None
    gap = stripped[best.end() : pos]
    if "\n" in gap or "[" in gap or "]" in gap or len(gap) > _SUBPATH_CLAIM_MAX_GAP:
        return None
    url = best.group("url").rstrip(".,;:!?")
    m = _HF_HUB_TREE_BLOB_URL_RE.match(url)
    if m is None or f"/tree/{m.group('sha')}" not in url:
        return None
    return best
```

Binding semantics, spelled out (constraint 4 of the brief): "same row" = no `\n` between the link's closing `)` and the claim's backtick token. Tolerated gap content: anything except `[`, `]`, `\n` — em-dashes, commas, other backtick tokens, and their non-count parens all pass (the #1112 gap contains two such token+paren pairs). Multiple pinned links on one row (the #1112 row has three HF links): the claim binds to the NEAREST PRECEDING HF link, and if that link is unpinned/`/blob/`/`/tree/main` the claim is DECLINED, not re-bound to an earlier link — an earlier binding would have the intervening link's `](` in the gap anyway, so decline-on-brackets and nearest-only are mutually consistent. Wrong-link-binding risk is documented in §8.

Design decisions, each grounded:

- **Reuse `_hf_file_count_for_prefix`, never the SDK.** What: the count probe. Why: bounded, files-only, exhaustive-or-skip, already fenced/cached. Source: clarifier `epm:clarify v1` on #1143 + the #733 convention stated at `scripts/verify_task_body.py:7247-7248` ("never the SDK list_repo_tree / list_repo_files"). Alternative (SDK `list_repo_tree`, the task body's literal wording): banned — unbounded first-page GET.
- **Emit A/B/C-shaped tuples; reuse `_verify_hf_whole_prefix_claims`.** Why: the two-sided compare, folder-inflation diagnostic (the exact #1112 signature: 7,372 = 7,165 + 207), subset hedge, and shard one-sidedness already exist there. Source: lines 7548-7585 (#931/#1008) + the CLAUDE.md reuse hierarchy. Alternative (a dedicated D verification leg like the per-namespace one): rejected — D scopes to ONE concrete prefix, exactly the whole-prefix semantics.
- **Nearest-preceding-pinned-link binding.** Why: the #1112 row's enumeration run starts at the bucket link and flows rightward; the per-namespace gatherer set the precedent of binding sub-paths to a single adjacent pinned link and joining `<link-prefix>/<sub>`. Source: `_gather_hf_per_namespace_claims` + `_verify_hf_per_namespace_claims` join at line 7612 (#833/#1088); incident row `tasks/followups_running/1112/body.md:224`. Alternative (bind forward / bind to any link on the line): rejected — ambiguous with multiple links per row.
- **Same-line bounding + `[ \t]{0,2}` token→paren separator.** Why: newline-spanning binds are the known false-positive class the sibling patterns already exclude. Source: `_HF_LINKTEXT_THEN_PAREN_RE` comment, lines 7296-7297 ("Separator is SAME-LINE only … stricter than check 32's `\s{0,2}` by design").
- **Bracket-free gap (`[`/`]` decline).** Why: subsumes both "intervening markdown link" and "claim inside another link's text" misbind classes with one cheap check; the incident gap is bracket-free. Source: check-30 precision-over-recall doctrine (`_gather_hf_count_claims` docstring "Known recall sacrifices", lines 7372-7380) + the measured #1112 gap content.
- **Gap cap 400.** Why: bounds runaway binding on pathological single-line bodies. Source: measured #1112 gap ≈ 132 chars (verbatim body read); 3× margin. Tunable within [200, 600] without re-plan (§ deviations).
- **Count must OPEN the paren; qualifier bound 200.** Why: mirrors Pattern B's leading-count precision rule ("(total 515 files)" sacrificed); the live qualifier is ~85 chars, over B's 80, so D uses 200 with the same `[^()]` no-nesting bound. - **Per-namespace negative lookahead copied verbatim.** Why: a per-namespace count read as whole-prefix manufactures a guaranteed false WARN. Source: `_COUNT_NOUN_RE` comment lines 7264-7272 (#833).
