**Decisions on the four design considerations (decided, not deferred):**

1. **Fix as proposed.** `XDG_RUNTIME_DIR` probed live on this host: set to `/run/user/1001` (per-user tmpfs, 13 GB, mode 700, writable); `${...:-/tmp}` covers unset non-login/cron shells; `/tmp` probed world-writable-sticky and `git -C /tmp rev-parse` returns `fatal: not a git repository` — the relocation target is provably outside any repo. `$$` keeps concurrent reviewer processes disjoint. #788's failure mode was home-cache-scoped (see §2), so this target is sound.
2. **No cleanup guidance added.** `$$`-keyed dirs are bounded (one per review invocation); `/run/user/*` tmpfs clears at logout/reboot and `/tmp` is reboot/tmpfiles-cleaned; an `rm -rf` inside the recipe would break the immediately-following "Re-run ruff the same way" instruction, which reuses `$RTMP`. The old in-tree location was worktree-sweep-reaped but actively polluted sibling rglobs (#802) — net win to accept bounded `/tmp` litter.
3. **No consistency touch to surrounding prose.** Line ~1231 ("writable-tempdir retry") and the Step 7 `Sandbox status:` bullet (line 1377, "ran after writable-tempdir fallback") are path-free — verified by read this session. The fall-through paragraph "**Only if the writable-tempdir retry ALSO fails**…" (lines 1234–1238) survives byte-unchanged; it is the safety net for risk R1.
