# Plan v2 — amendment to v1 (§4.2 classification correction)

**Base:** `plans/v1.md`. This amendment changes ONE row of the §4.2
per-wrapper classification table and adds two test-strength requirements to
§6. Everything else in v1 stands unchanged.

## Why this amendment exists

Round-1 code review (Claude `code-reviewer` + Codex twin, both CONCERNS)
independently falsified one of v1's five NOT-APPLICABLE classifications by
direct execution. v1 §4.2 recorded `scripts/cron_codex_auto_upgrade.sh` as
NOT-APPLICABLE on the grounds that it is "already guarded at L107 via
`SETUP_OK`, and re-porting `fatal()` would regress its never-exit-before-the-
alert-arm invariant."

That reason is correct for the **uncreatable** leg and false for the
**unwritable** leg. Both reviewers executed the wrapper against an
existing-but-unwritable log dir and observed exit 0, upgrader never run, no
alert fired:

- `mkdir -p` at `:107` returns success for an **existing** directory
  regardless of appendability, so `SETUP_OK` stays 1.
- The brace-group redirect at `:153` then fails before `rc` is assigned.
- `${rc:-0}` at `:170` evaluates to 0, so `alert_failure` is skipped and the
  trailing `exit 0` stands.

That is precisely the failure class this task exists to sweep. The file
itself describes the residual in a comment at `:161-169`, and that comment
asserts the checked `mkdir -p` covers the case — which it does not.

## The correction

**§4.2 row change — `scripts/cron_codex_auto_upgrade.sh`: NOT-APPLICABLE →
FIX SET (Pattern C).** The FIX SET count becomes 11; NOT-APPLICABLE becomes
4. The remaining four exclusions are unchanged and were re-confirmed by
execution in round 1: `cron_lesson_consolidate.sh` (the #2196 fix itself),
`cron_export_literature.sh` (`set -euo pipefail` at `:5`), and
`cron_watch_issue_1739.sh` / `cron_watch_issue_2091.sh` (per-command append
vehicle, so the pass is not skipped).

**Pattern C** is new and applies to this wrapper alone. It is deliberately
NOT Pattern A or B: v1's objection to porting `fatal()` here was correct and
still binds — an early `exit 1` would regress the file's
never-exit-before-the-alert-arm invariant. Instead the probe routes into the
wrapper's OWN existing failure design:

```bash
if ! : >> "$LOG_FILE" 2>/dev/null; then
    log_line "$(date -Iseconds) FATAL: daily log file not appendable ($LOG_FILE) — skipping upgrader"
    SETUP_OK=0
fi
```

Placed after the `FIRST_RUN_OF_DAY` read (same ordering constraint as
Patterns A and B — the probe creates the file when absent). `SETUP_OK=0`
then carries the failure through the wrapper's established path so the
existing `alert_failure` arm fires. The stale comment at `:161-169` is
corrected in the same edit.

Scope note: this file is byte-identical to `origin/main` (0 commits in
`origin/main..origin/issue-2386` on that path), so under `code-reviewer.md`
Step 0.9 it is pre-existing-on-trunk and both reviewers correctly routed it
as a non-blocking concern rather than a round-introduced defect. It is
pulled into scope here because the task's own acceptance criterion requires
each excluded wrapper to carry a **valid** not-applicable reason, and this
one's is demonstrably false for one of its two legs. Shipping v1's table
would close the round while leaving the swept class open.

## §6 additions (test strength)

Both reviewers found the round's class invariant cannot detect the very gap
above, because it keys on the fix's marker rather than on the vehicle's
shape.

1. **Exhaustive classification in the glob invariant.**
   `tests/test_cron_wrapper_log_dir_guard.py` currently short-circuits at
   `:316-317` on `if not any(ln.startswith("fatal() {"))`, so any wrapper
   lacking that exact column-zero spelling is silently skipped, and the
   final `missing` check at `:336` covers only seven wrappers. Replace with
   an explicit classification of every wrapper the live glob returns, and
   assert set equality between that classification and the glob — so a NEW
   unguarded wrapper fails the invariant instead of passing it.

2. **The probe must be checked as a logical statement.** The assertion at
   `:331` only requires a physical line starting with `: >> "$LOG_FILE"`; a
   probe changed to fail open (`probe || true`) still passes. Require the
   probe's logical statement to route into the wrapper's failure path
   (`|| fatal` for Patterns A/B, the `SETUP_OK=0` arm for Pattern C).

3. **Exact happy-path stdout.** The shared happy-path pin at `:270-275`
   checks three substrings, so arbitrary extra stdout passes. v1 §6 requires
   routine passes to stay silent: assert `splitlines()` yields exactly one
   pointer line for the six pointer-emitting wrappers, and exactly empty
   stdout for `cron_session_summarize`.
