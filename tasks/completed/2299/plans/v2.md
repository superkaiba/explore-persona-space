### 4.3 Trigger, window, and the superseded-line guard

- **Anchor lines:** non-fenced lines matching `_C70_ANCHOR_RE = re.compile(r"(?i)\bpilot\b")`.
  Broad by design: WARN requires the full triple to resolve in a window, and the threshold regex
  requires rule-26(b) vocabulary (`parse-fail … %`), so wall-time-pilot prose cannot complete it.
  No anchors ⇒ SKIP (S2).
- **Window:** raw lines `[i-8, i+8]` around each anchor `i`; harvest text = the window's lines that
  are (a) non-fenced (`_fence_mask`) AND (b) not superseded-context (below). `_C70_WINDOW_LINES = 8`.
- **Window-size justification (measured):** in the v7 fixture the arm count (line 477, inside the
  PREVIOUS gate item) sits 4 raw lines above the "150 draws" anchor (481) and 7 above the threshold
  line (484) — ±8 covers the worst measured distance with margin. In #2054 v9 the whole pilot spec
  is ONE long paragraph line (204), so the window there matters only for what it can FALSELY pull
  in — which is exactly what the guards below handle (the "9,000 arms the…" line sits at 196,
  distance 8 — at the window edge, and was v1's ZeroDivisionError source).
- **Superseded-line guard (MF2 fix, parser-side):**

```python
_C70_SUPERSEDED_RE = re.compile(
    r"(?i)\bv\d+['’]s\b|\bsuperseded\b|\bgave\b|\bformerly\b|\bpreviously\b"
)  # noqa: RUF001 — the typographic apostrophe is real corpus text
```

  Any window line matching this is EXCLUDED from harvest (line-level, like fence masking). House
  convention requires §11 rationale / amendment notes to quote the superseded value with a version
  possessive — the real v8:672/v10:686 shape is `"…threshold (v7's 150-draw config gave ~30/arm —
  one"` — so `v\d+'s` (both apostrophe glyphs) + the past-tense `gave` are the precise signals;
  `superseded/formerly/previously` cover the obvious paraphrases. Verified against the corpus: the
  guard silences #2162 v8/v9/v10 (each now SKIPs — §12 A11) while v7's true-positive gate lines
  carry none of the tokens (`parent's` does not match `v\d+'s`) and still WARN (§12 A10). Token
  list deliberately minimal; a dropped line can only SUPPRESS a warn (false-negative direction —
  safe for a WARN-only check; recorded as FN-h).

### 4.4 Three-number extraction (concrete regexes — ALL verified by corpus replay, §12 A10-A13)

Every numeric capture carries the `(?<![\d.,=])` lookbehind (MF1 fix, extended): `\d`/`.`/`,`
reject comma/decimal-truncated reads (`"9,000 arms"` → no capture; `"10,150 draws"` → no capture;
`"1,000 draws/arm"` → no capture; `"0.10 per arm"` → no capture), and `=` rejects config-assignment
reads (`"N=3 draws localize"` — a per-item judge draw count that v1's regex read as a 3-draw pilot
budget on #2254 v5, §12 A12).

**(a) Per-arm threshold** — REQUIRED, two parts:

```python
_C70_THRESH_RE = re.compile(
    r"(?i)parse[-\s]?fail(?:ure)?(?:\s+rate)?[^%\d]{0,25}?(\d+(?:\.\d+)?)\s*%"
)
_C70_PER_ARM_TOK_RE = re.compile(r"(?i)\bper[-\s]arm\b|\beach arm\b")
```

The threshold must be a percentage tied to parse-fail vocabulary; the `per arm` token must ALSO
appear in the (guarded) window — without it the threshold could be an aggregate-over-arms bound,
which the check cannot adjudicate (S5). Percent parsed exactly via `Fraction(pct_str)`;
`pct <= 0` or `pct >= 100` ⇒ SKIP (S9).

**(b) Effective draw count** — three forms, in precedence order:

```python
# direct per-arm form — short-circuits arm-count inference entirely
_C70_DIRECT_RE = re.compile(
    r"(?i)(?<![\d.,=])\b(\d+)\s*(?:draws?\s*)?/\s*arm\b"
    r"|(?<![\d.,=])\b(\d+)\s+draws?\s+per[-\s]arm\b"
)
# multi-rubric component form: "60 coherence + 90 value-rubric draws"
_C70_COMPONENT_RE = re.compile(
    r"(?i)(?<![\d.,=])\b\d+\s+[a-z][\w-]*(?:\s*\+\s*\d+\s+[a-z][\w-]*)+\s+draws\b"
)
# component values, extracted structurally (digit + space + letter), NOT bare findall —
# a rubric name like "gpt4-rubric" must not contribute its own digits
_C70_COMPONENT_NUM_RE = re.compile(r"(?i)(?<![\w.,])(\d+)\s+[a-z]")
# bare total: "150 draws" (a word between digit and "draws" does NOT match)
_C70_TOTAL_RE = re.compile(r"(?i)(?<![\d.,=])\b(\d+)\s+draws\b")
```

- `_C70_DIRECT_RE` handles "~30 draws/arm", "30/arm", "30 draws per arm" and yields `per_arm`
  directly. The lookbehind + draws-or-slash requirement are LOAD-BEARING: verified rejections of
  `PASS ⇔ |mean ΔF| ≤ 0.10 per arm` (v7:490, a different gate) and `(72 pairs/arm)` (v7:489),
  verified acceptances of all four intended shapes (§12 A2).
- `_C70_COMPONENT_RE` implements the multi-rubric split; effective slice = `min(components)` —
  every rubric gets its OWN gate call (`judge_pilot.py:54-55`), so the smallest slice is the
  binding denominator. The WARN names the full component list.
- `_C70_TOTAL_RE` fallback: exactly one distinct total ⇒ that is the slice; ≥2 distinct with no
  component structure ⇒ SKIP (S7).

**(c) Arm count** — needed only when (b) resolved via COMPONENT/TOTAL:

```python
_C70_ARMN_RE = re.compile(r"(?i)(?<![\d.,=])\b(\d+)\s+arms?\b(?!\s+the\b)")
```

The `(?!\s+the\b)` negative lookahead rejects the VERB usage — the corpus carries both
`"a projection < 9,000 arms the contingency wave"` (#2054 v9:196; also killed by the comma
lookbehind) and `"3 arms the driver"` (comma-free — the lookahead is the only guard that catches
it). Distinct values over the window: exactly one ⇒ use it; zero ⇒ SKIP (S6); ≥2 ⇒ SKIP (S8).

**Per-window resolution:** `per_arm = direct` if DIRECT matched, else `slice // n_arms` — computed
ONLY after S10 (zero guard) has excluded `n_arms == 0`, so the division cannot raise.

### 4.5 SKIP branches (enumerated — the conservative parse)

- **S1** `kind not in ("experiment", "analysis")` — kind gate.
- **S2** no non-fenced anchor line matching `\bpilot\b`.
- **S3** anchors present but NO window resolves a parse-fail % threshold.
- **S4** threshold resolves but no draw count in any of the three forms.
- **S5** threshold resolves but no `per arm`/`each arm` token in the window.
- **S6** slice resolves but no `N arms` count and no DIRECT form.
- **S7** ≥2 distinct bare totals, no component structure, no DIRECT form.
- **S8** ≥2 distinct arm counts in the window.
- **S9** degenerate threshold (`pct <= 0` or `>= 100`).
- **S10** (MF1(i)) any harvested count == 0 — `n_arms == 0`, `slice == 0`, or a DIRECT `0/arm` —
  "degenerate zero count harvested (truncated number?)". Checked BEFORE the division, so
  `slice // n_arms` is structurally raise-free. With the lookbehinds these should be unreachable;
  the branch is the required belt-and-suspenders against future regex edits.
- **S11** (new, #2254 trace) quotient zero — `slice // n_arms == 0`, i.e. a "budget" smaller than
  the arm count. No real plan registers fewer pilot draws than arms; this signature is a
  mis-harvest (v1 read #2254 v5's `N=3 draws` per-item count against a genuine 7-arm count → 0/arm
  false WARN). The `=` lookbehind already kills that instance; S11 closes the general family.

S3-S11 are evaluated per window; the check SKIPs only when NO window fully resolves. The SKIP
detail names the furthest-resolved branch reached (c69 style).

### 4.6 Arithmetic — exact, never float

`required = math.floor(Fraction(1) / t) + 1` with `t = Fraction(pct_str) / 100`. Grounding:
`judge_pilot._refusal_resolution_floor`'s docstring (`judge_pilot.py:400-410`) — float
`floor(1/t)+1` is off-by-one on non-reciprocal thresholds; under exact arithmetic the closed form
is the smallest n with `1/n < t` (strict, mirroring rule 26(b)'s `>=`-FAILs: at n=50 and t=2%, one
failure is exactly 2%, NOT `< 2%`, hence 51). Verified: `floor(Fraction(100)/Fraction("2"))+1 == 51`.

**`min_effective_draws_per_arm` decision (unchanged, now empirically validated):** mirror ONLY the
resolution leg. The critic's corpus replay measured every parse-fail threshold in the corpus:
238×2%, 3×1%; the only >10% hits (where the omitted `max(min_effective=10, …)` leg could bind) are
two `kind: infra` plans — kind-gated out anyway. Recorded as FN-e.

### 4.7 Verdict aggregation + WARN message

Evaluate every anchor window; each fully-resolved window yields a tuple keyed `(per_arm, required)`
with its source description, anchor line, and a `declared` flag (`allow_subresolution_pilot`
literal present in that window's guarded text). Windows resolving the same tuple DEDUPE, with
`declared` OR-accumulated across windows. **`allow_subresolution_pilot` does NOT early-return**
(nice-to-have 2): it marks the tuple declared and the scan CONTINUES, so a plan with one declared
sub-resolution gate plus a second genuinely defective gate still WARNs on the second (T21).

- Any undeclared tuple with `per_arm < required` ⇒ **WARN** (worst tuple leads; up to 2 offender
  summaries).
- Else if ≥1 tuple resolved ⇒ **PASS**, detail showing every tuple's arithmetic + source (`60>=51
  (direct …)`) — the same matched-satisfier record the calibration scan persists (nice-to-have 4).
- Else ⇒ SKIP with the furthest-resolved reason.

WARN message contents: anchor line; parsed threshold; the draw budget as parsed (total + component
list, or direct value); arm count; computed `per_arm`; `required = floor(1/t)+1` with both values;
suggested budget (`required × n_arms` per rubric slice); routing to
`eval.judge_pilot.judge_pilot_gate` (refuses unsatisfiable configs at config time before any API
spend; `allow_subresolution_pilot=True` is its documented downgrade); and both standalone escapes
with the unwrapped-declaration convention ("on its own line, unwrapped (no backticks/quotes)").

### 4.9 The check function (complete, replay-verified — the implementer lands exactly this logic)

The full function below was executed at plan time over all 4,516 persisted plan files (§12 A13);
the landed version adds only the docstring (per §4.8's enumeration), the c69-style
message/escape wording of §4.7-§4.8, and the `_skip`/`_warn`/`_pass` helper calls in place of the
replay's tuple returns.

```python
def check_pilot_resolution(plan: str, kind: str) -> CheckResult:
    """WARN-only, conditional (#2299; founding #2124, recurrence #2162 v7 §7.3): ...
    [docstring per §4.8 — never FAILs, never raises; FN-a..FN-h, FP-a enumerated]"""
    cid = "c70_pilot_resolution"
    name = "judge-pilot per-arm draw resolution vs parse-fail threshold"
    if kind not in ("experiment", "analysis"):
        return _skip(cid, name, f"kind={kind} — armed for experiment/analysis only "
                     "(c69 precedent): infra workflow-fix plans, this check's own plan "
                     "included, quote the arming vocabulary")
    lines = plan.splitlines()
    mask = _fence_mask(lines)
    anchors = [i for i, (ln, f) in enumerate(zip(lines, mask, strict=True))
               if not f and _C70_ANCHOR_RE.search(ln)]
    if not anchors:
        return _skip(cid, name, "no judge-pilot vocabulary detected")
    if _standalone_na_declared(plan, r"no judge[-\s]?pilot gate\b"):
        return _pass(cid, name, "explicit N/A declared (no judge-pilot gate)")
    if _standalone_na_declared(
        plan, r"harvested pilot sizing is historical or belongs to a different gate"
    ):
        return _pass(cid, name, "explicit N/A declared (historical / cross-gate sizing)")
    evaluated: dict[tuple[int, int], dict] = {}
    best_skip = "pilot vocabulary but no per-arm parse-fail threshold resolvable in any window"
    for a in anchors:
        lo = max(0, a - _C70_WINDOW_LINES)
        hi = min(len(lines), a + _C70_WINDOW_LINES + 1)
        kept = [lines[i] for i in range(lo, hi)
                if not mask[i] and not _C70_SUPERSEDED_RE.search(lines[i])]
        win = "\n".join(kept)
        th = _C70_THRESH_RE.search(win)
        if not th:
            continue                                   # -> S3 if nothing else resolves
        declared = "allow_subresolution_pilot" in win
        if not _C70_PER_ARM_TOK_RE.search(win):
            best_skip = "parse-fail threshold without a per-arm token (aggregate gate?)"  # S5
            continue
        pct = Fraction(th.group(1))
        if pct <= 0 or pct >= 100:
            best_skip = "degenerate threshold percentage"                                 # S9
            continue
        required = math.floor(Fraction(1) / (pct / 100)) + 1
        dm = _C70_DIRECT_RE.search(win)
        if dm:
            per_arm = int(dm.group(1) or dm.group(2))
            src = f"direct {per_arm}/arm"
            if per_arm == 0:
                best_skip = "degenerate zero count harvested (truncated number?)"         # S10
                continue
        else:
            cm = _C70_COMPONENT_RE.search(win)
            comps = ([int(x) for x in _C70_COMPONENT_NUM_RE.findall(cm.group(0))]
                     if cm else None)
            totals = sorted({int(m.group(1)) for m in _C70_TOTAL_RE.finditer(win)})
            if comps:
                slice_, src = min(comps), f"min rubric slice {min(comps)} of {comps}"
            elif len(totals) == 1:
                slice_, src = totals[0], f"total {totals[0]}"
            elif len(totals) > 1:
                best_skip = f"multiple distinct draw totals {totals} — ambiguous"         # S7
                continue
            else:
                best_skip = "per-arm threshold without a resolvable draw budget"          # S4
                continue
            arm_counts = sorted({int(m.group(1)) for m in _C70_ARMN_RE.finditer(win)})
            if not arm_counts:
                best_skip = ("draw budget without a resolvable arm count "
                             "(and no direct per-arm form)")                              # S6
                continue
            if len(arm_counts) > 1:
                best_skip = f"multiple distinct arm counts {arm_counts} — ambiguous"      # S8
                continue
            n_arms = arm_counts[0]
            if n_arms == 0 or slice_ == 0:
                best_skip = "degenerate zero count harvested (truncated number?)"         # S10
                continue
            per_arm = slice_ // n_arms
            if per_arm == 0:
                best_skip = "draw budget smaller than arm count — likely mis-harvest"     # S11
                continue
            src += f" / {n_arms} arms"
        e = evaluated.setdefault((per_arm, required),
                                 {"line": a + 1, "src": src, "pct": str(pct),
                                  "declared": False})
        e["declared"] = e["declared"] or declared
    if evaluated:
        offenders = [(pa, req, e) for (pa, req), e in evaluated.items()
                     if pa < req and not e["declared"]]
        if offenders:
            # WARN — message per §4.7 (worst tuple leads, arithmetic + suggested budget +
            # judge_pilot_gate routing + both escapes, c69 remedy phrasing)
            ...
            return _warn(cid, name, detail)
        # PASS — every tuple's arithmetic + source recorded (matched-satisfier convention)
        ...
        return _pass(cid, name, detail)
    return _skip(cid, name, best_skip)
```
