## §3 Design decisions

**D1 — Re-armed cron is REPORT-ONLY + recommendation push; auto-terminate is retired from every scheduled path.**
The standing directive (2026-08-04: "NOTHING SHOULD GET SHUT DOWN ON ITS OWN"; pods destroyed only with user approval, sole exception = owner-driven verified teardown) makes a cron auto-terminate categorically unauthorized — and the containment interlock already enforces this mechanically (a cron-context `terminate_pod` raises `PodTerminateNotApproved` and fires a refusal push per pod). Re-arming the old `--terminate-stale --yes` invocation would therefore produce zero terminations plus a daily refusal-push storm. So: `cron_pod_audit.sh` drops `--terminate-stale --yes` and gains `--notify-stale`; the `stale` bucket is re-documented as "terminate-RECOMMENDED — user approval required", surfaced via one deduped push per UTC day when non-empty (pod names, ids, est $/hr-if-resumed, and the exact approval command `EPS_ALLOW_COMPUTE_KILL=1 uv run python scripts/pod.py audit-stale --terminate-stale --yes`). `--terminate-stale` remains available for MANUAL user-approved invocations and for those runs the four fixes below all still bind. This satisfies the task's "re-arming the cron is part of completion" without re-authorizing autonomous kills.

**D2 — Ownership signal 3 becomes structured-provenance-only (retire the substring scan everywhere).**
New scanner (replacing `_scan_task_references`' matching logic, same return shape): parse each `events.jsonl` line as JSON (skip unparseable lines — never regex over raw blobs); consider ONLY marker kinds `{epm:run-launched, epm:pod-provisioned}` (the markers the workflow writes at pod creation/launch — provenance we WROTE); match the #1961 structured grammar on the note: boundary-safe `pod=<name>` token OR note leading with the pod name (`(?<![\w-])pod={esc}(?![\w-])|^\s*{esc}(?![\w-])`, cf. `scripts/autonomous_session_watch.py:12498` — replicate the 3-line pattern with a cross-reference comment + a parity test rather than importing the 15k-line watcher module; also accept a `pod=<pod_id>` / `pod_id=<pod_id>` token). An `epm:progress` fleet-audit dump can then never confer ownership. The structured scan replaces the substring scan in BOTH consumers: `_is_eps_owned` signal 3 (terminate-eligibility) AND the `refs` column / RUNNING active-vs-orphan split (line 367) — the report then never claims a teammate pod is "ours" off a substring hit. Signals 1 (name→issue→REGISTRY) and 2 (pods_ephemeral.json sidecar) are unchanged; fail-toward-KEEP wrapping unchanged.

**D3 — EXITED staleness keys on the exit time from `lastStatusChange`; unknown ⇒ KEEP.**
`runpod_api.PodInfo` gains `last_status_change: str | None` (raw API string), selected on `list_team_pods` (live-verified 2026-08-10 — not speculative; add the probe date to the field comment) and populated in `_parse_pod`. `pod_audit.py` gains `_exited_age_hours(p)`: require `desired_status == "EXITED"`, require the verb prefix to start with `"Exited"` (an inconsistent verb ⇒ `None` — a "Rented…" string on an EXITED pod is contradictory data, fail toward KEEP), strip the `"<verb>: "` prefix and the trailing ` (…)` parenthetical, parse `"%a %b %d %Y %H:%M:%S GMT%z"`, return hours-since. Bucketing for EXITED pods keys on `exited_age`: `stale`/`unmanaged-exited` only when `exited_age is not None and exited_age >= max_exited_hours`; `None` ⇒ `fresh-exited` with age rendered `exited=?` (fail-toward-KEEP; the daily report still shows the row). `created_at` age is kept for display and for the RUNNING orphan logic (unchanged — creation age is correct there). Report rows for EXITED pods show BOTH ages (`age=<created>h exited=<exit>h`). This closes defects 2 AND 3 in one clock change (an EPS `pod-<N>` parked 10 min ago is `fresh-exited` for 24h from its EXIT).

**D4 — Shared-cluster names are NEVER terminate-eligible, regardless of ownership signals.**
Module constant `SHARED_INFRA_NAME_PATTERNS: tuple[str, ...] = ("Anthropic ", "cluster-EUR-IS")` — scoped tightly to the two demonstrated shared-cluster classes (both carry spaces/prefixes no EPS pod name ever does), extendable via env `EPM_POD_AUDIT_SHARED_NAME_PATTERNS` (comma-separated, additive). `_is_shared_infra_name(name)` = case-sensitive substring match. Checked in `classify()` BEFORE the stale gate: an EXITED shared-infra-named pod routes to `unmanaged-exited` with a `SHARED-INFRA` annotation even when every ownership signal fires. This is a belt on top of D2 (defense in depth for the regression-test near-miss class).

**D5 — Any actual terminate emits one push naming the pods destroyed.**
`pod_audit.py` gains a fail-soft `_push(msg)` helper (same channel as `runpod_api._notify_terminate_blocked`: `~/my-goat/scripts/telegram_push.sh`, override `EPM_TELEGRAM_PUSH_SCRIPT`; every failure swallowed). After the `--terminate-stale` loop: one push listing `ok` terminations (name, id) and any failures. The D1 recommendation push (`--notify-stale`) uses the same helper with a per-UTC-day sentinel dedupe (`~/.eps-autonomous/pod-audit-stale-notify-<day>`).

**D6 — Prose surfaces re-documented in the same diff.**
`pod_audit.py` module docstring (bucket semantics, exit clock, D1 posture); `cron_pod_audit.sh` header + invocation; `.claude/rules/background-automation.md` § "Stale-pod audit" (rewrite: report-only cron, provenance-backed ownership, exit clock, recommendation push); `.claude/rules/pods.md` § Crons item (1) ("auto-terminates pods EXITED >24h" → "reports + recommends; termination requires user approval"); `pod_lifecycle.py:2257` hint string gains the approval requirement. No LESSONS.md change (no rule file added/removed).

## §8 Risks & assumptions

- **A1:** `lastStatusChange` verb vocabulary is stable (`"Exited by user"`, `"Exited by Runpod"`, `"Rented by User"` observed). Mitigation: any unrecognized shape ⇒ `None` ⇒ KEEP (fail-safe by construction); the daily report renders `exited=?` so drift is visible, and a systematic parse failure inflates `fresh-exited`, never terminates.
- **A2:** restricting signal 3 to `{epm:run-launched, epm:pod-provisioned}` kinds may under-match dispatcher-created pods that never posted either marker. Consequence: those pods land `unmanaged-exited` (report-only) instead of `stale` — a false KEEP, by design the cheap direction; the D1 recommendation push surfaces them for the user's call.
- **A3:** D1 changes the audit's public behavior (cron no longer terminates). This is the standing-directive posture, not a regression; the manual approved path is documented in the push text + prose.
- **A4:** worktree copies of `runpod_api.py` on live issue branches keep the old PodInfo (no `last_status_change`) until they pull — harmless: the field defaults to `None` and only pod_audit consumes it.
