#### 4.1 Method delta

- **vs the Codex twin's Step 2-pre-b:** Codex INLINES the canonical plan because its sandboxed runtime must not read `tasks/` paths and inlining is its only safe channel. The Claude reviewer/implementer CAN read absolute VM paths, and inlining a 30 KB+ plan into a Claude brief violates the lean-brief rule (CLAUDE.md § Context hygiene: "pass the PATH to a plan/brief, never the body"). So the Claude-side discipline is **path-reference, not inline**: absolute canonical path + compose-time `plan_version=` pin + read-time re-verify + worktree-`tasks/` read bar. Same two failure shapes covered (STALE and ABSENT — `task.py find` re-resolution handles a status move / absent folder; the readlink pin catches staleness AND a mid-round revision).
- **vs the Step 5a spec-freshness sync:** Step 5a syncs the WORKFLOW surface into the worktree because the Agent tool loads specs from the session cwd — those files MUST be worktree-resident. Task state does NOT need to be worktree-resident (agents read it by path), so the fix is path-side, not sync-side. Step 5a's scope is untouched; Edit 8 adds a one-sentence scope note so a future reader doesn't "fix" the sync instead.

#### 4.2 Fix-direction decision (recorded)

**Chosen: (1) + (3).** (1) makes every named brief surface worktree-safe (absolute canonical path + version pin + read bar); (3) is the cheap fail-loud assertion — implemented NOT as a new script but as a two-line check composed from existing primitives, embedded in the contract lines themselves:

```bash
REPO_ROOT="$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)")"
TASK_DIR="$(uv run python "$REPO_ROOT/scripts/task.py" find <N>)"
readlink "$TASK_DIR/plans/plan.md"     # must equal the brief's plan_version=v<K>; mismatch ⇒ FAIL LOUD
```

Who runs it: the ORCHESTRATOR at compose time (resolves + states `plan_version=`), and the REVIEWER/IMPLEMENTER at read time (re-runs the readlink; mismatch ⇒ a plan revision landed after compose ⇒ the round is against a superseded plan ⇒ report the mismatch as a blocker naming both versions, never proceed silently). **Non-blocking by construction:** it is one sub-second readlink with graceful degradation — a brief with no `plan_version=` (legacy) degrades to "use the canonical absolute path" (the bar still holds); a 404 on the absolute path (status moved mid-round) degrades to re-running `task.py find <N>`. No new script ⇒ no stale-worktree-copy bootstrap problem and no new blocking dependency. The `$REPO_ROOT` prefix form is mandatory so the MAIN checkout's `task.py` runs, not a possibly-stale worktree copy (idiom already canonical in codex-code-reviewer.md Step 2-pre-b and the codex quota-check snippet).

**Rejected: (2) — extend Step 5a to sync `plans/` + `artifacts/` into the worktree.** Four reasons, having read the Step 5a branch-side-edit guard (09-step-5.md lines ~122–420): (a) **it cannot cover the ABSENT shape** — a worktree cut from a parent-issue branch has no `tasks/*/<N>/` folder to refresh, and a main-side current-status path never resolves in any worktree regardless of syncing (the folder sits at the branch-cut status); creating folders in the worktree diverges further from "the frozen tree is CORRECT behavior". (b) **Status-move fragility** — the task folder moves across `tasks/<status>/` on main (atomic `git mv`), so a surgical `git checkout origin/main -- tasks/<status>/<N>/plans/` needs a status-remap layer that the family-atomic sync machinery does not have; a wrong-status checkout fails or, worse, resurrects a stale-status copy. (c) On the clobber question the orchestrator asked: the existing branch-side-edit guard WOULD mechanically extend (its skip grain is per-family, fail-safe toward staleness), and `new-plan-version` is branch-guarded to main so no SANCTIONED branch-local plan revision exists to clobber — so clobbering is *probably* prevented — but the protection is moot given (a)/(b): the sync covers only sessions that RUN Step 5a, while the #823 incident was a hand-written brief that no sync would have reached. (d) It is in tension with acceptance criterion 5 ("no change to worktree `tasks/` semantics"). **Rejected: (3)-as-a-new-script** (e.g. `scripts/assert_task_state_current.py`): the assertion decomposes into two existing primitives (`task.py find` + `readlink`); a new script adds a file, a lint surface, and a stale-worktree-copy bootstrap hazard for zero capability (reuse-before-building).
