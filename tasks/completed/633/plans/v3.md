## 4. Design

**Hard constraints restated (from the body — all binding):**
- Watcher is pure Python, NO LLM judgment; it NEVER classifies ripeness — it only executes IDs the PM adjudicated into the queue file. Missing/empty/invalid file → log + skip.
- occupied = count of `kind ∈ {infra, batch}` tasks at active statuses, read via the task-workflow API (subprocess to `task.py`, never hand-built paths); free = max(0, cap − occupied); dispatch up to `free` IDs from `ripe_oldest_first` in order.
- Per-ID guards: status ≠ `proposed` → skip; `~/.eps-autonomous/issue-<N>.json` exists → skip; ID in `holds` → skip; one spawn attempt per ID per cycle + last-attempt timestamp (backoff/attempt cap) so a failed spawn never tight-loops.
- Spawn via `spawn_session.py spawn-issue --issue <N> --auto` (same mechanism as crash-recovery).
- Kill switch env var (`EPM_DISABLE_INFRA_DRAIN=1`).
- Do NOT touch `task.py` status enums, marker schemas, or `spawn_session.py` CLI contracts. (This design adds zero lines to either file.)

**Why code, not a model call?** Required answer: (a) the single-model-call alternative — an LLM triage of ripe infra tasks — is exactly what the task body forbids (the PM session IS the LLM judge; duplicating judgment in the watcher would create two adjudicators); (b) code is preferred for determinism, auditability, and zero marginal cost at a 10-min cadence; (c) nothing flips this — the no-LLM constraint is the design's contract, not a trade-off.

All other §4 mandatory bullets (contrastive negatives, data realism tier, completion provenance, marker recipe, band designs, ICL demos, smoke/sweep parity, baseline propensity): **N/A — `kind: infra`, no training, no behavioral data.** Graceful-degradation bullet: no continuous-quantity eligibility gate exists here (all guards are categorical); the cap is a resource limit, not a keep/drop data gate — partial dispatch (fewer than `free` IDs eligible) is the normal, logged outcome. Equalize-down: N/A.

### 4.3 Pure decision function (the testable core)

The hold/registration/budget guards live in ONE shared pure helper used by
BOTH `decide_infra_drain` and the executor's cheap pre-filter — single source
of truth, no predicate drift (Codex-Meth 1 / Codex-Stats 5 / Codex-Alt 1):

```python
def _cheap_skip_reason(
    i: int,
    holds: dict[int, str],
    registered: set[int],                # NON-STALE registrations only (executor pre-computes staleness)
    attempts: dict[int, dict],
    now: float,
    queue_updated_ts: float | None,      # already future-clamped by the caller
    *,
    backoff_s: float,
    max_attempts: int,
) -> str | None:
    """The guards computable WITHOUT task.py subprocesses. Returns the skip
    reason or None (eligible so far). Used verbatim by decide_infra_drain
    (guards 1-3) and by the executor's pre-filter (§4.5 step 5).

      1. id in holds                          -> "held"
      2. id in registered                     -> "already-registered"
      3. budget — the BACKOFF WINDOW ALWAYS BINDS (Meth-Claude Must-Fix 2:
         a fresh PM `updated_ts` resets only the ATTEMPT COUNT, never the
         window — research-pm.md 4b rewrites the file on EVERY STATUS pass,
         so a window bypass would void the tight-loop guard whenever the PM
         is active):
           now - last_attempt_ts < backoff_s  -> "backoff"        (always)
           attempts >= max_attempts AND NOT (queue_updated_ts > last_attempt_ts)
                                              -> "attempts-exhausted"
         Records with malformed last_attempt_ts were dropped at state-load
         time (defensive normalize, logged), so `last` here is numeric.
    """

def decide_infra_drain(
    ids: list[int],                      # ripe_oldest_first, validated
    cap: int,
    holds: dict[int, str],
    statuses: dict[int, str | None],     # pre-fetched per-ID status (None = unreadable)
    kinds: dict[int, str | None],        # pre-fetched per-ID kind (same view --json payload)
    registered: set[int],                # NON-STALE registrations among the queue IDs
    occupied_active: int,                # infra/batch tasks at INFRA_DRAIN_OCCUPIED_STATUSES
    pending: int,                        # executor-precomputed (see below)
    attempts: dict[int, dict],
    now: float,
    queue_updated_ts: float | None,
    *,
    backoff_s: float = INFRA_DRAIN_BACKOFF_S_DEFAULT,
    max_attempts: int = INFRA_DRAIN_MAX_ATTEMPTS_DEFAULT,
) -> tuple[list[int], list[tuple[int, str]]]:
    """Pure decision: (dispatch_ids_in_order, skipped [(id, reason)]).

    FUTURE-TS CLAMP (first statement, pure + testable — Alt-Claude Must-Fix 3):
    if queue_updated_ts is not None and queue_updated_ts > now +
    INFRA_DRAIN_FUTURE_TS_TOLERANCE_S: queue_updated_ts = None. A future epoch
    would make every tick a "fresh adjudication" and void the attempt budget.

    `pending` is EXECUTOR-PRECOMPUTED (widened per Codex-Stats 7 / Codex-Meth
    2): the count of ALL non-stale registrations — queue AND non-queue — whose
    task is kind ∈ INFRA_DRAIN_KINDS and status == "proposed", PLUS any
    non-stale registration whose status or kind is UNREADABLE (conservative:
    an unknown registered task might be a just-spawned infra task). This
    closes both the PM-prunes-a-dispatched-ID overshoot and the
    status-read-failure undercount. free = max(0, cap - occupied_active -
    pending).

    Per-ID guard order (cheapest first; every skip carries a reason string):
      1-3. _cheap_skip_reason (held / already-registered / backoff /
           attempts-exhausted — backoff always binds)
      4. statuses.get(id) is None             -> "status-unreadable"  (fail toward not dispatching)
         statuses[id] != "proposed"           -> "status-<status>"
      5. kinds.get(id) not in INFRA_DRAIN_KINDS -> "kind-<kind|unreadable>"
         (Meth-Claude Must-Fix 1 / Alt-Claude Must-Fix 2: a mis-queued
         experiment/campaign ID must never be spawned with --auto — it would
         auto-approve ≤100 GPU-h AND sit outside the cap arithmetic. Loud log.)
      6. free <= 0                            -> "cap-full"
      7. else dispatch; free -= 1             (one attempt per ID per cycle)
    """
```

Pseudocode (the implementer writes exactly this logic):

```python
if queue_updated_ts is not None and queue_updated_ts > now + INFRA_DRAIN_FUTURE_TS_TOLERANCE_S:
    queue_updated_ts = None          # future-ts clamp; executor logs loudly
free = max(0, cap - occupied_active - pending)
dispatch, skipped = [], []
for i in ids:
    reason = _cheap_skip_reason(i, holds, registered, attempts, now, queue_updated_ts,
                                backoff_s=backoff_s, max_attempts=max_attempts)
    if reason is not None:               skipped.append((i, reason)); continue
    status = statuses.get(i)
    if status is None:                   skipped.append((i, "status-unreadable")); continue
    if status != "proposed":             skipped.append((i, f"status-{status}")); continue
    kind = kinds.get(i)
    if kind not in INFRA_DRAIN_KINDS:    skipped.append((i, f"kind-{kind or 'unreadable'}")); continue
    if free <= 0:                        skipped.append((i, "cap-full")); continue
    dispatch.append(i); free -= 1
return dispatch, skipped
```

And inside `_cheap_skip_reason` (the budget block):

```python
if i in holds:      return "held"
if i in registered: return "already-registered"
rec = attempts.get(i) or {}
last = rec.get("last_attempt_ts")
if isinstance(last, (int, float)):
    if now - last < backoff_s:
        return "backoff"                                   # ALWAYS binds
    fresh = queue_updated_ts is not None and queue_updated_ts > last
    if not fresh and rec.get("attempts", 0) >= max_attempts:
        return "attempts-exhausted"                        # fresh PM write resets the COUNT only
return None
```

```python
    registration's spawned_at parses AND now - spawned_at > grace_s; the
    recorded session id is present AND live_session_ids is available AND the
    id is NOT in it. ANY missing/unparseable signal → NOT stale (fail toward
    keep-blocking — a false-stale could double-spawn; a false-live only
    delays recovery to the 14-day registry backstop). A STALE registration
    stops counting toward pending and stops blocking re-dispatch; the
    backoff/attempt budget bounds the re-dispatch rate (Alt-Claude Must-Fix
    1: three dead-at-boot events must not freeze the drain for 14 days)."""

def _infra_drain_occupancy() -> int | None:
    """Count tasks with kind in INFRA_DRAIN_KINDS at INFRA_DRAIN_OCCUPIED_STATUSES,
    via one `task.py list-by-status --status <s> --json` subprocess per status
    (mirrors _active_status_tasks, but KEEPS the `kind` field and counts).
    Returns None when ANY status read fails — a partial occupancy count would
    UNDER-count and over-dispatch, so the executor skips dispatching this tick
    on None (stricter than _active_status_tasks' per-status fail-soft, which
    is safe there because that pass only recovers, never spawns new work).
    `kind: campaign` rows can't match (not in INFRA_DRAIN_KINDS)."""

def _infra_drain_pending(registrations: dict[int, dict],
                         stale: set[int],
                         status_kind: dict[int, tuple[str | None, str | None]]) -> int:
    """Widened pending count (Codex-Stats Must-Fix 7 + Codex-Meth Must-Fix 2):
    over ALL non-stale registrations (queue and non-queue), count those whose
    task is kind ∈ INFRA_DRAIN_KINDS and status == "proposed" (spawned but
    /issue hasn't flipped status yet) PLUS those whose status or kind is
    UNREADABLE (conservative — fail toward occupying a slot). Tasks at
    occupied statuses are already in occupied_active; terminal/blocked
    registrations count zero."""

def _dispatch_infra_drain(issue: int, slot_desc: str, dry_run: bool) -> bool:
    """`uv run python scripts/spawn_session.py spawn-issue --issue <N> --auto`
    (plain command, exactly the PM standing-rule item-3 mechanism; no
    --auto-approve-gpu-hours override — spawn_session's default applies, and
    infra tasks need ~0 GPU). capture_output, timeout=120. Logs
    `  INFRA-DRAIN DISPATCHED issue #<N> (<slot_desc>): <first stdout line>`
    or `  INFRA-DRAIN DISPATCH FAILED issue #<N>: <stderr[:300]>` (stderr).
    Immediately BEFORE the subprocess, re-checks the registration file one
    last time and aborts ("lost race to concurrent dispatcher") if it
    appeared — shrinks the PM-vs-watcher double-spawn window from
    one-full-pass to ~the spawn subprocess itself. Returns success bool."""
```

### 4.5 The pass executor

```python
def infra_drain_pass(dry_run: bool, now: float | None = None, *,
                     daemon_reachable: bool | None = None) -> None:
    """Execute the PM-adjudicated infra dispatch queue (task #633). Pure
    executor — every judgment was the PM session's; every guard is mechanical."""
```

Flow (each early-exit prints exactly one `infra-drain: ...` header line):

1. Kill switch: `not _infra_drain_enabled()` → `infra-drain: disabled via EPM_DISABLE_INFRA_DRAIN; skipping` → return.
2. Queue file missing → `infra-drain: no queue file at ~/.eps-autonomous/infra-drain-queue.json; skipping` → return. Read + `parse_infra_drain_queue`; `None` → loud `infra-drain: INVALID queue file (...); skipping (fail-safe: not dispatching)` → return.
3. Daemon gate: `daemon_reachable` False → `infra-drain: Happy daemon unreachable; skipping (spawn needs the daemon RPC)` → return. (Reuses main()'s single probe result.)
4. Load state (defensive-normalized). `regs = _infra_drain_registrations()`; clamp+log a future `updated_ts` (mirror of the decide-side clamp, for the log line).
5. **Cheap pre-filter (single source of truth):** for each queue ID call the SAME `_cheap_skip_reason` helper `decide_infra_drain` uses, with `registered` = the registration-file ID set (staleness not yet computed — a stale registration makes the ID *more* eligible, so pre-filtering on the raw set risks only a false skip toward the next tick; correctness of the no-skip path is what matters). If every ID pre-filters to a skip reason, print the summary and skip steps 6-7 (zero `task.py` subprocesses on the common nothing-to-do tick). Pre-filter/decide agreement is test-pinned (test 19): an exhausted record + newer `updated_ts` must survive the pre-filter and reach dispatch.
6. Fetch `(statuses[id], kinds[id]) = _task_status_kind(id)` for each non-held queue ID AND for each non-queue registration ID (needed for the widened pending). Queue ~O(10), registrations ~O(10).
7. Compute staleness: `live = _live_session_ids()` (None if unavailable); `stale = {ids where _infra_drain_stale(...)}` (loud log per stale registration). `registered_nonstale = registration IDs ∩ queue − stale`. `pending = _infra_drain_pending(regs, stale, status_kind)`. `occupied_active = _infra_drain_occupancy()`; `None` → loud skip line (fail-safe), still prune+save state, return.
8. `dispatch, skipped = decide_infra_drain(...)`. For each dispatch ID: `_dispatch_infra_drain(...)`; record the attempt in state **whether or not it succeeded** (`attempts += 1` — reset to 1 first when `fresh_adjudication`, `last_attempt_ts = now`, `last_result`); on success additionally `_post_progress_marker(issue, f"{_INFRA_DRAIN_NOTE_SENTINEL} watcher dispatched autonomous session from the PM infra-drain queue (occupied {o}+{p} of cap {c})", dry_run, label="infra-drain")`. For each `attempts-exhausted` skip, log loudly once (state flag `exhausted_logged`, mirroring the orphan pass's `alerted` dedup). For each `kind-*` skip, log loudly EVERY tick (a mis-kinded queue entry is a PM-side bug needing eyes).
9. Prune state entries whose ID left `ripe_oldest_first`; `_save_infra_drain_state` (atomic).
10. Summary: `infra-drain: queue=<n> occupied=<o>(+<p> pending) cap=<c> dispatched=<k> skipped=<m>` plus one `  INFRA-DRAIN SKIP issue #<N> (<reason>)` line per skipped ID (the file's hold reason interpolated for `held`); on any `cap-full` skip, append the occupying task IDs to the summary (`occupying=[...]` — slot-jam diagnosable from the cron log; Meth-Claude concern).

`dry_run` threads through everywhere: decisions + `[dry-run] would dispatch ...` lines; no spawn, no marker, no state write (mirror the orphan pass's dry-run discipline).

## 11. Decision Rationale

N/A — no model training; no training hyperparameters; no behavioral construct. Load-bearing **design constants**, each grounded:

- **Cap default 3.** What: `INFRA_DRAIN_CAP_DEFAULT = 3`, used only when the file omits `cap`. Why: matches the adjudicated value in the live queue file and the PM standing rule item 4 ("Concurrency cap: 3 concurrent infra sessions"). Source: `~/.eps-autonomous/infra-drain-queue.json` (`cap: 3`) + `.claude/agents/research-pm.md:377` item 4 + task #633 body. Alternatives: no default (missing cap → invalid) — rejected; the body names 3 as the schema default, and a missing-field no-op would silently disable the drain on a benign omission.
- **Occupied-status set.** What: `{planning, plan_pending, approved, running, verifying, interpreting, reviewing}` + `followups_running`. Why: the first seven are the body's verbatim contract; `followups_running` is added because a same-issue follow-up round is in-flight work holding a session (watcher `ACTIVE` and `POD_ACTIVE` both include it since 2026-06-10), and counting it only ever dispatches LESS (conservative direction). `blocked`/`proposed`/terminal excluded per the body (a blocked task waits on the user, possibly for days — letting it pin a slot would jam the drain). Source: task #633 body ("starting contract — refine as needed") + `autonomous_session_watch.py` `ACTIVE`/`POD_ACTIVE` precedent. Alternatives: body set verbatim — rejected (allows cap+1 concurrency during follow-up rounds); counting live sessions instead of statuses (the PM rule's own method) — rejected (status read is daemon-independent and matches the body's stated contract).
- **Backoff 3600 s (ALWAYS binding), attempt cap 3, COUNT-reset on newer `updated_ts` (≤ now + 300 s).** What: a failed spawn is not retried for 1 h regardless of PM rewrites (v3: the window is never bypassed — research-pm.md 4b rewrites the file on EVERY STATUS pass, so a window bypass would void the tight-loop guard whenever the PM is active); after 3 attempts the ID is parked until a fresh PM `updated_ts` resets the COUNT; a future `updated_ts` (> now + 300 s) is clamped to None. Why: at a 10-min cron, 1 h ≈ 6 ticks — long enough to outlast transient daemon flaps, short enough to self-heal same-day; cap 3 mirrors the orphan pass's bounded-respawn philosophy (`ORPHAN_MAX_RESPAWNS_PER_DAY_DEFAULT` = 2/day, `STALLED_MAX_RESPAWNS` = 3/episode). Source: task #633 body ("backoff or attempt cap") + the orphan/stalled precedents + Phase-2 Methodology/Alternatives Must-Fix findings. Alternatives: per-UTC-day cap — rejected (PM epoch is the semantically right COUNT reset); content-fingerprint re-arm (hash of ids+holds) — viable but the always-binding window already bounds the retry rate to ≤1/hour, and the ts-based reset is simpler. Backoff + max-attempts + grace env-overridable.
- **Stale-registration grace 1800 s (`EPM_INFRA_DRAIN_STALE_REG_GRACE_S`).** What: a registration for a still-`proposed` task older than 30 min whose recorded session id is definitively not live stops pinning a pending slot and stops blocking re-dispatch. Alternative: alert-only (keep pinning) — rejected, three dead-at-boot events would freeze the entire drain, the exact outcome the task exists to prevent.
- **Single consolidated state file** (`infra-drain-state.json`) vs per-issue `infra-drain-<N>.json`.
