# Plan — Issue #693: Parallelize the issue664 dispatcher p0 — 8-way GPU fan + base-extraction/judge-wait overlap

**Kind:** `infra` (experiment-code change; acceptance criteria + file-by-file diffs, NOT hypothesis/conditions/controls). Scope: `scripts/issue664_*.py` + matching `tests/`. The reusable `WaveDispatcher` / `submit_judge_async` helpers in `src/explore_persona_space/orchestrate/fleet.py` are CONSUMED unchanged (sibling task #676 delivered them).

---

## 1. Goal

p0 of the leakage-fleet dispatcher (`scripts/issue664_dispatch.py::phase0`) is the only phase still pinned to a single GPU. Its GPU-bound work — base greedy generation (`marker_R` under each source + each negative-panel context), on-policy elicitation (sycophancy / refusal positives, refusal / secure-code negatives), and source-side baseline-propensity reads — runs serially on one shared vLLM engine on GPU 0, leaving 7 of 8 GPUs at 0 MiB; and GPU 0 itself idles during the Claude judge-filter wait (the live #664 run logged `all 8 GPUs <= 5% util for 38 min` mid-p0 on 2026-06-27). The Goal is to (1) fan p0's GPU work across all `--n-gpus` GPUs reusing the SAME `WaveDispatcher` pattern p1/p2 already use, so an 8-GPU pod runs p0 ~8× faster, and (2) keep GPUs busy during the elicitation judge-batch wait by scheduling base generation on other shards while one shard's judge clears on the Anthropic Batch API — never block a GPU on judging. This is a SCHEDULING/THROUGHPUT change only: the parallelized p0 must produce byte-identical (order-insensitive, per-key) base caches, elicitation pools, and the 80%-yield-floor drop set as the single-shard p0.

**The #693 body's framing has two imprecisions worth correcting up front** (both verified by reading the code, not the body):

1. **"p0 produces base extraction `c_C`/`v0`/`t_{C,B}`."** It does NOT. The base activation store (`v0`, `c_C`, `v_plus`, `t`, all 28 layers) is extracted PER CELL inside **p2** (`issue664_extract_store.extract_cell` does base + trained extraction together, `extract_store.py:404-499`) — and p2 ALREADY fans via `WaveDispatcher`. p0's only GPU work is *generation* (greedy base R + elicitation + baseline reads). So fix #1's "shard base extraction" target is p0's *generation*, and the activation-extraction fan is already done. The plan parallelizes what p0 actually runs.
2. **Fix #2 (judge interleave) is ~90% already built.** #664's p0 ALREADY submits every elicitation + baseline judge fire-and-forget via `submit_judge_async` and accumulates deferred reconcile closures in `judge_jobs`, reconciled after engine teardown before build-mixes (`phase0:438-484`). The ONLY gap: the reconcile barrier runs after the single engine is torn down, so today no GPU work overlaps the in-flight judge. The p0 GPU-fan IS the overlap mechanism — with generation units running on N shards, the other shards' generation keeps GPUs busy while any one unit's judge clears. There is no new judge plumbing to write; the win comes from the fan.

## 3. Design

### 3.1 The p0 GPU-unit abstraction (the one genuinely new piece)

p0's GPU work is NOT cell-keyed; its natural grain is a **generation context** — one `(kind, ctx_key)` whose output is one cache file `CACHE_ROOT/{kind}/{ctx_key}.json`. The realized p0 GPU units, enumerated deterministically from the selected cells, are:

- **marker_R** under each source (`marker_R/{src}.json`) and each negative-panel context (`marker_R/{neg.slug}.json`) — `behavior == "marker"` in the selection.
- **sycophancy positives** per source (`syco_pos/{src}.json`).
- **refusal positives** per source (`refusal_pos/{src}.json`) + **refusal negatives** per negative-panel ctx (`refusal_neg/{neg.slug}.json`).
- **secure-code** per ctx_key (`ic_secure/{ctx_key}.json`) — but note this is a SINGLE shared generation written to many ctx_keys (`_elicit_secure_code:728-741`), so it is ONE unit, not per-source (§3.4 handles it).
- **baseline-propensity** raw reads per `(content-behavior, source)` (`baseline_raw/{behavior}__{src}.json`).

**`P0Unit` (new, lightweight, in `issue664_dispatch.py`):**

```python
@dataclass(frozen=True)
class P0Unit:
    """One p0 GPU-generation unit (the WaveDispatcher 'cell' for phase0).

    kind: one of "marker_R" | "syco_pos" | "refusal_pos" | "refusal_neg"
          | "ic_secure" | "baseline" — selects the generation op the worker runs.
    ctx_key: the per-context cache key (source slug / neg.slug / behavior__src).
    """
    kind: str
    ctx_key: str

    @property
    def unit_key(self) -> str:        # the WaveDispatcher disjoint-claim key
        return f"{self.kind}::{self.ctx_key}"

def _p0_units(cells: list[C.Cell], *, smoke: bool) -> list[P0Unit]:
    """Enumerate the p0 GPU-generation units from the SELECTED cells, in a
    DETERMINISTIC order (sorted by unit_key). Mirrors phase0's existing branches:
    marker_R per source + per neg-panel ctx (if 'marker' in behaviors);
    syco_pos/refusal_pos per source; refusal_neg per neg ctx; the single
    ic_secure unit (if em/ic_edu present); baseline per (content-behavior, source).
    """
```

`_p0_units` reads the SAME `behaviors = sorted({c.behavior for c in cells})` / `sources` / `neg_panel = C.negative_panel()` the current `phase0` computes, so the unit set is exactly the generation the serial path would do — just enumerated instead of inlined.

### 3.2 The p0-unit subprocess worker (`--p0-one-unit`)

Mirrors `_run_one_cell` exactly. The worker spins up its OWN vLLM engine for ONE unit, runs that unit's generation, submits its judge fire-and-forget (the `JudgeHandle` is created + `.submit()`ed IN the subprocess), reconciles it IN the subprocess (the subprocess is short-lived; reconcile happens after its own engine is torn down — preserving "GPU never blocks on judge" WITHIN the unit because the engine is freed before the poll), and writes the per-ctx cache + judge-filtered labels. Because each unit is its own process with its own engine, the OVERLAP across units is automatic: while unit A's subprocess polls its judge (CPU/API-bound, engine already freed), units B..N on the other shards are generating.

```python
def _p0_run_one_unit(args) -> int:
    """One p0-unit subprocess worker (the WaveDispatcher --p0-one-unit path).

    Reconstructs the single P0Unit from --p0-kind/--p0-ctx-key, builds ONLY the
    cells whose generation this unit needs, runs that unit's generation under its
    OWN vLLM engine, submits + reconciles its judge (engine torn down first), and
    writes the per-ctx cache. CVD already pinned in the launcher env by the parent
    WaveDispatcher; --gpu-id threads the matching in-process value (gotchas cuInit).
    """
    _require_credentials()
    unit = P0Unit(args.p0_kind, args.p0_ctx_key)
    cells = _select_cells(args)
    behaviors = sorted({c.behavior for c in cells})
    sources = sorted({c.source for c in cells})
    neg_panel = C.negative_panel()
    smoke = args.smoke
    judge_jobs: list[Callable[[], None]] = []
    llm = _vllm_engine(2 * C.MAX_NEW_TOKENS + 1024)
    try:
        _run_p0_unit(unit, llm, behaviors, sources, neg_panel, judge_jobs, smoke=smoke)
    finally:
        _teardown_vllm(llm)
    for job in judge_jobs:   # reconcile THIS unit's judge — engine already freed
        job()
    return 0
```

`_run_p0_unit` is a thin dispatch on `unit.kind` that calls EXACTLY the existing generation helper for that unit (refactored to take a `units`/`ctx` filter so it produces only the one unit's cache — see §3.6). The generation + cache-write code is the CURRENT code, unchanged in behavior; only the loop boundary moves out to the WaveDispatcher.

### 3.3 Why the sharded merge is order-independent (the correctness backbone)

Every p0 GPU unit writes to a DISTINCT path keyed by `(kind, ctx_key)`:
`CACHE_ROOT/marker_R/{src}.json`, `CACHE_ROOT/syco_pos/{src}.json`, `CACHE_ROOT/refusal_neg/{neg.slug}.json`, `CACHE_ROOT/baseline_raw/{behavior}__{src}.json`, the per-source `judge_filter/{behavior}__{src}.json` save_raw, etc. (verified: `_write_responses_cache:238`, `_submit_behavior_labels:582`, `_write_baseline_propensity:811/835`). No two units write the same file ⇒ concatenation of shard outputs is the union of disjoint files ⇒ the merged `CACHE_ROOT` is byte-identical regardless of which GPU ran which unit or in what order. There is no shared mutable in-cache state. The `WaveDispatcher` whole-fleet `unit_key` uniqueness assert (`DuplicateCellError`) makes a keying bug loud, not silent. This is the SAME property p1/p2 rely on (eval_key-derived paths) — extended to p0's (kind, ctx) keying.

The ONE cross-unit barrier is `baseline_propensity.json` (the aggregate written by the final `_write_out` closure after all per-(behavior, src) rates are in). It is NOT a GPU unit — it is a CPU aggregation that must run AFTER all baseline units' rates land. It moves to the serial post-fan barrier (§3.5), reading the per-unit `baseline_raw/*__*__scores.json` save_raw files the units already wrote.

### 3.4 `ic_secure` — the one non-per-source unit

`_elicit_secure_code` generates ONE secure-code answer set (context-independent) and writes the SAME mapping to every ctx_key (`ic_secure/{src}.json` for each source + `ic_secure/{neg.slug}.json` for each negative; `_elicit_secure_code:728-741`). It is therefore ONE p0 unit (`P0Unit("ic_secure", "_shared")`) whose worker runs the single generation and fans the identical mapping to all ctx_keys — exactly the current behavior, in one subprocess. It does not shard further (the generation is shared; splitting it would re-generate identical answers N times, wasting GPU). The unit's `is_done` predicate checks `all((CACHE_ROOT/"ic_secure"/f"{k}.json").exists() for k in ctx_keys)` (the existing early-return guard at `:729`).

### 3.5 Refactored `phase0` (the orchestration)

```python
def phase0(args) -> None:
    phase_log("p0_elicit")
    cells = _select_cells(args)
    smoke = args.smoke
    # pools are cheap CPU writes (UltraChat fetch); keep serial, before the fan.
    marker_qs = _marker_question_pool(smoke); _write_pool("marker", marker_qs, smoke=smoke)
    refusal_qs = _refusal_request_pool(smoke); _write_pool("refusal", refusal_qs, smoke=smoke)

    # --- P0 GPU-generation fan (#693): one vLLM engine per unit, across n_gpus. ---
    units = _p0_units(cells, smoke=smoke)
    phase_log("p0_gpu_fan")
    WaveDispatcher(
        n_gpus=args.n_gpus,
        cell_key=lambda u: u.unit_key,
        is_done=lambda u: _p0_unit_done(u, smoke=smoke),
        build_cmd=lambda u, g: _p0_unit_cmd(u, _wave_gpu_id(args, g), smoke=smoke),
        dry_run=args.dry_run,
    ).run(units, cwd=C.REPO)

    # --- cross-unit CPU barrier: baseline-propensity aggregate (#693). ---
    # Each baseline unit already wrote baseline_raw/{b}__{src}.json + the judge
    # save_raw; aggregate them into baseline_propensity.json here (no GPU, no engine).
    phase_log("p0_baseline_aggregate")
    _aggregate_baseline_propensity(cells, smoke=smoke)

    # --- build-mixes (unchanged): serial CPU subprocess per cell, drop-on-floor. ---
    phase_log("p0_build_mixes")
    dropped = _build_mixes(cells, smoke=smoke)   # the existing :498-532 loop, extracted verbatim
    _write_dropped_manifest(dropped)
```

`--n-gpus 1` (the default, and what the live #664 process runs) ⇒ `WaveDispatcher` runs one unit per wave on GPU 0 ⇒ **the same units, serially, on one GPU** — behaviorally identical to today's single shared-engine loop EXCEPT each unit now uses its own engine subprocess. That subprocess-per-unit difference is the only behavior change on the n_gpus=1 path, and it is exactly the proven p1/p2 shape (§6 risk d covers the regression test).

### 3.6 Generation-helper refactor (keep bodies, move the loop boundary)

The existing `_elicit_sycophancy` / `_elicit_refusal` / `_elicit_secure_code` / `_write_baseline_propensity` iterate `for src in sources:` / `for neg in neg_panel:` internally. The refactor adds an OPTIONAL `only_ctx: str | None = None` parameter (default `None` = the current full loop, so the serial path and tests are untouched) that, when set, runs the body for ONLY that one context and returns. The marker_R block (`phase0:443-457`) is extracted to `_elicit_marker_R(llm, sources, neg_panel, marker_qs, *, only_ctx, smoke)`. Each `_p0_run_one_unit` calls the helper with `only_ctx=unit.ctx_key`. This is a pure extraction — `git diff` shows the loop bodies move verbatim; the planner-template "model call vs code" rule is N/A (no new heuristic — the judge is already a Claude Batch-API call).

`_p0_unit_done(unit, smoke)` is the per-unit resume-skip predicate: it returns True iff the unit's output cache(s) exist AND (for judge-filtered units) the `judge_filter`/baseline save_raw exists — mirroring the current `if (CACHE_ROOT/kind/f"{ctx}.json").exists(): continue` guards (`:445`, `:451`, `:640`, `:661`, `:678`, `:729`). This makes a killed-mid-p0 re-run skip completed units, exactly like p1/p2.

## 5. Risks and failure modes

| Risk | Likelihood | Mitigation |
|---|---|---|
| **(a) Shard split silently changes which seed/prompt/context a unit sees.** | Low | p0 generation is greedy (temp=0, `_greedy:211`) and context-keyed; the unit enumeration reads the SAME `sources`/`neg_panel`/`behaviors`/question-pools the serial path computes. Test 4.1 asserts the unit set == the serial branch set; test 4.3 asserts byte-identical merged caches. The cross-unit `baseline_propensity.json` aggregate runs only AFTER `WaveDispatcher.run` returns (all unit subprocesses `wait()`ed), so every per-unit save_raw exists before the aggregate reads it. Test 4.5. |
| **(c) Merge is order-sensitive somewhere not yet keyed.** | Low | Verified every p0 cache write is keyed by `(kind, ctx_key)` (§3.3) — disjoint files, union merge. | **(d) `n_gpus == 1` regression** (the live #664 default path). | Med | The n_gpus=1 path now routes through `WaveDispatcher` + subprocess-per-unit instead of one in-loop shared engine — a real behavior change (per-unit engine).
