## Method delta (single-variable-change)

   #     rendered into figure text (#1902:

   #     side + REQUIRED `_[a-z]+` snake suffix on the RHS. This
   #     tightening rejects bare-letter arrows like `H->O` (chemistry

## Method soundness (Methodology lens)

- **Sidecar scope inherited.** `check_figure_label_codes` scans only
  figure sidecar meta strings (`_iter_meta_label_values`), not body
  prose. So legitimate `A -> B` in Methodology prose is untouched by
  construction. The new regex inherits that scoping via
  `_opaque_code_tokens`.
- **False-positive envelope (revised per critic Must-Fix).** The
  REQUIRED `_[a-z]+` snake suffix on the RHS is the primary
  false-positive control: it matches the #1902 opaque shape exactly
  (letter → letter + snake) and rejects the three named legitimate
  legend classes — chemistry (`H->O`), state-machine
  transitions (`A->B`), HMM/Markov (`X -> Y`). Any future
  single-letter-arrow legend author is unaffected as long as they don't
  compress a suffix like `_state` / `_type` into their labels. The
  path-word exemption via `_only_in_path_words` handles the
  pathological case of a suffixed letter-arrow token appearing inside a
  figure filename.
- **`_SNAKE_TOKEN_RE` interaction (locked by AC-2).** The existing snake
  regex matches the RHS suffix `S_single` (letter + `_single`) as a snake
  token but does NOT flag it because the classifier requires ≥2
  underscores OR ≥1 digit; `S_single` has 1 underscore and 0 digits, so
  it slips through the snake arm silently. The letter-arrow arm catches
  the WHOLE token including the `B->` prefix. The length-1 exact-list
  assertion in AC-2 locks this against any future loosening of the
  snake-arm suppression.
- **Docstring "code-span contexts" NO-OP.** The check-28 docstring
  already notes that sidecar strings are matplotlib rendered text
  serialized to JSON (never markdown), so backtick code spans cannot
  occur — the new regex needs no code-span exclusion for the same reason.

## Kill criteria

- If any negative-assertion pin fails (a legitimate string falsely flags
  as opaque code — chemistry, state-machine, HMM, GPU-name shape drift):
  the regex is too permissive, revise the pattern.
- If any positive assertion fails (an incident-shape string does NOT
  match): the regex is too tight or has a boundary bug.
- If the check-28 walker test suite regresses (any pre-existing test
  turns red): the new regex has unexpected interaction with an existing
  class or with the walker.
- If ruff format or lint fails on the touched files after the edit: the
  regex string or docstring formatting is off.
