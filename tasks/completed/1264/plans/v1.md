**Exact test to add:**

```python
def test_skillmd_canonical_escapes_sync_with_docstring():
    # Generative docstring->SKILL.md sync pin (#1264). Ends the per-check pin
    # whack-a-mole (#1042 c21, #1194 c32, #1246 c33, #1260 c34 each
    # hand-registered one phrase; c26-c30 were missed entirely): every escape
    # phrase the verify_plan module docstring registers must appear
    # backtick-wrapped in the adversarial-planner SKILL.md canonical block.
    # Whitespace is normalized on BOTH sides because SKILL.md legitimately
    # wraps long phrases across indented continuation lines (the check-31
    # alias wraps today). One-directional by design: the docstring is updated
    # when a check lands (ground truth); SKILL.md is the consumer surface
    # that drifts behind it.
    doc = verify_plan.__doc__
    section = doc[doc.index("Canonical N/A escape phrases") : doc.index("WARN semantics")]
    phrases = re.findall(r"``((?:N/A —|Durability pin: N/A)[^`]+?)``", section)
    # Extraction guard (never-self-escapes precedent, :1232): 28 phrases at
    # pin time. A shrinking count means the docstring format drifted and the
    # parser silently under-covers — fix the regex, never lower this floor.
    assert len(phrases) >= 28, (len(phrases), phrases)
    text = (REPO_ROOT / ".claude" / "skills" / "adversarial-planner" / "SKILL.md").read_text()
    anchor = text.index("Canonical N/A escape phrases")
    block = text[anchor : text.index("bounce to the planner", anchor)]
    norm_block = re.sub(r"\s+", " ", block)
    for phrase in phrases:
        wrapped = "`" + re.sub(r"\s+", " ", phrase).strip() + "`"
        assert wrapped in norm_block, f"escape phrase not in SKILL.md canonical block: {wrapped}"
```

**Parser design decisions, each grounded:**

- **Section slice:** `"Canonical N/A escape phrases"` → `"WARN semantics"` — both anchors occur exactly once in the docstring (verify_plan.py:91, :130). The SKILL.md-side slice reuses the existing convention verbatim (`text.index("Canonical N/A escape phrases")` → `text.index("bounce to the planner", anchor)` — the :5794-5796 / :5819-5821 / :6309-6311 pattern).
- **Phrase extraction:** `` r"``((?:N/A —|Durability pin: N/A)[^`]+?)``" `` over the docstring section. The alternation excludes non-phrase double-backtick tokens in the same section (``_standalone_na_declared`` :93, ``labelled`` :119, ``--workload-cmd`` / ``dispatch_issue.py`` :114). The `[^`]+?` tail requirement (≥1 char) excludes the bare ``Durability pin: N/A`` counter-example at :124 (it names the WARN-ing degenerate form, not a phrase). Yield at pin time: 28 phrases (2 for check 1; 1 each for checks 2, 6, 7, 11, 12, 13; 2 for 15; 1 each for 16, 18, 19, 20, 21, 24, 25, 26, 27, 28, 29, 30; 2 for 31; 1 for 32; 2 for 33; 1 for 34). The implementer recounts at implement time; the `>= 28` floor is the extraction guard (same convention as `len(tails) >= 12` at :1232).
- **Templated phrases (`<...>` placeholders) are asserted verbatim, whitespace-normalized** — no special-casing. The check-31 forms `Durability pin: N/A — <one-line reason>` and `N/A — no durability pin: <reason>` appear verbatim in SKILL.md (:230-231); the alias wraps across a line break INSIDE its backticks, which is exactly why both sides are `re.sub(r"\s+", " ", ...)`-normalized before the substring assert. Verified by hand: normalized SKILL.md block contains `` `N/A — no durability pin: <reason>` ``.
- **Backtick-wrapping is part of the assert** (`` "`" + phrase + "`" ``): presence alone is not enough — the wrapping is the #1238 anti-paste armor, and the c33 precedent (:5825-5826) pins the wrapped form. A future editor who unwraps a phrase breaks this test AND `test_skillmd_canonical_escape_block_never_self_escapes` — both by design.
- **One-directional (docstring ⊆ SKILL.md), not bidirectional:** the observed drift class is docstring-ahead (a new check lands with its docstring registration; SKILL.md lags). The reverse direction (a stale SKILL.md phrase for a retired check) would require parsing SKILL.md's single-backtick spans amid gloss prose that legitimately contains other backticked tokens — more fragile, no incident on record. Stated as a scope decision, not an oversight.

## 11. Decision Rationale

No training hyperparameters — this is a workflow-surface code change; the load-bearing decisions and their sources:

- **Ground truth = the module docstring, parsed via `verify_plan.__doc__`.** Source: the docstring IS the canonical phrase registry (verify_plan.py:91-128, "quote verbatim in bounce briefs"); `__doc__` beats re-slicing `_SCRIPT.read_text()` because the interpreter has already parsed the string literal. Alternative rejected: regexing the raw file source (duplicate slicing logic; the `_SCRIPT.read_text()` precedent at :1226 exists to scan CODE call sites, not the docstring).
- **Whitespace-normalized verbatim match, templated phrases included.** Source: read-verified line wrap inside the check-31 alias's backticks (SKILL.md:230-231) — an exact-substring assert would false-fail it. Alternative rejected: truncating templated phrases at `<` (loses coverage of the placeholder text the bounce brief must quote).
- **Extraction guard `>= 28`.** Source: the `len(tails) >= 12` convention at tests/test_verify_plan.py:1232 — a generative test needs a floor or a parser regression silently passes on an empty set.
- **Keep existing per-check pins.** Source: §3.4; the c33 pin's own comment (:5813-5818) documents the exact-string em-dash pinning the generative test's normalized match intentionally relaxes.
- **Gloss content copied from the check implementations' own remedy strings** (verify_plan.py:4018-4025, :4245-4257, :4472-4480, :4644-4659, :4784-4792), not paraphrased from memory — the never-type-from-memory rule.
