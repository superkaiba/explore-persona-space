## 4. Design

### D1. The chosen mechanism — R-G′: floor-profile scratch with asymmetric verdicts (refined candidate (a))

**Why code, not a model call:** this is a deterministic classifier inside a fail-closed gate; an LLM call has no place in it.

All edits in `scripts/step9c_baseline.py::_resolve_pristine_bucket` (`:1740-1848`) plus message/docstring sites; no new files, no registry changes.

1. **Eligibility (`use_scratch`, `:1777-1791`).** Keep the conjunction; replace the hard R-G conjunct `wt_cones is not None` with:

   ```python
   wt_cones = _work_root_sparse_cones(ctx.work_root)  # None => non-sparse (R-G')
   floored = wt_cones is None
   ...
   use_scratch = (
       not residual                                   # R-B' unchanged
       and (not floored or bool(ctx.live_dirty_paths))  # R-G': non-sparse arms ONLY on a dirty root
       and (test_file not in ctx.sel.GLOB_SCAN_TESTS
            or test_file in FILE_ANCHORED_SCAN_TESTS)  # R-F' unchanged
       and not args.no_scratch_fallback               # unchanged
       and not (scratch_unavailable and not ctx.live_dirty_paths)  # #1408 memo unchanged
   )
   ```

   Rationale for the dirty-root-only arming on non-sparse roots: on a CLEAN non-sparse root the root oracle is trustworthy AND strictly more capable (full tree; both strip and NEW available) — arming the floor scratch there would lose strip capability for zero benefit. `ctx.live_dirty_paths` is re-probed per file (`:1764`), so mid-loop dirt transitions behave exactly as today.

2. **Scratch creation (`:1792-1798`).** `_create_scratch_or_degrade(ctx, root, wt_cones if wt_cones is not None else [], contaminating, args)` — `_scratch_cones(root, [])` yields floor ∪ HEAD-pinned registry, the identical profile minus the (now absent) work-root extra cones. `create_scratch_worktree` (`:814`), `assert_scratch_src_shadow` (`:866`), teardown, and the dirty-root creation-failure fail-closed path (`:1687-1695`) are all reused unchanged. In floored mode, after a successful creation, set `ctx.pristine_oracle = "scratch-worktree-floor"` (new JSON value; thread a `floored: bool` kwarg through `_create_scratch_or_degrade` → `_arm_src_shadow`, or set it at the `:1793` call site — implementer's choice, smallest diff wins) and emit a floored-mode WARN variant (the `:1637`/`:1649` WARN text currently says "non-sparse work roots stay indeterminate" — reword per D4).

3. **Verdict mapping (`:1819-1845`) — the load-bearing asymmetry.**

   ```python
   for node in [n for n in ctx.pristine_bucket if n.file == test_file]:
       if node in main_failing:
           if use_scratch and floored:
               raise _Indeterminate(   # R-G' strip refusal — NEW exit-2 arm
                   f"node red at pristine HEAD on the FLOOR-profile scratch "
                   f"(pristine_oracle=scratch-worktree-floor, sparse_wt=False): the floor "
                   f"tree is not a superset of the non-sparse gate layout, so a "
                   f"'pre-existing' strip for {node.file}::{node.name} cannot be certified "
                   "(R-G'); indeterminate — commit/clean the dirt, run from a sparse "
                   "worktree, or fix main first",
                   extra={...}, warns=ctx.warns,
               )
           if not use_scratch and ctx.live_dirty_paths:
               raise _Indeterminate(...)   # MF-4c unchanged
           _strip_node(ctx, node, via="pristine-scratch" if use_scratch else "pristine")
       else:
           ctx.new.append(node)            # PASS -> NEW, unchanged (fail-closed)
   ```

   **Soundness argument (the whole design in two sentences):** a floor tree that is missing gate-layout content can corrupt a pristine verdict in exactly two directions — a spurious RED (e.g. a missing fixture) or a spurious GREEN (e.g. an absence-asserting scan over an excluded dir). Spurious RED would have caused a wrong STRIP (true red→green) — so the strip is REFUSED outright in floored mode; spurious GREEN maps to NEW (rc 1, the gate still fails naming the node) — conservative by construction. Hence NO source-token screen is needed (see D2), and the former exit-2 class maps ONLY onto `{NEW rc 1, exit 2}`.

   **Contract line (the #1649 model, adapted):** *the change maps the former non-sparse-work-root exit-2 class onto NEW/rc 1 (node green at pristine HEAD on the floor scratch — the #1932 shape) or exit 2 (node red at pristine HEAD on the floor scratch, R-G′ refusal with narrowed diagnostic; or any scratch creation/probe failure on the dirty root, unchanged) — never rc 0 from the new path, never red→green.*

4. **For the #1932 recurrence specifically:** work root = repo root (non-sparse), visible code dirt present, node red on gate, node green at HEAD (the concurrent `.md` size-ratchet dirt does not exist in the scratch) → NEW rc 1 with `pristine_oracle: scratch-worktree-floor` and the green-at-pristine evidence in the JSON. On a no-branch task the work-root HEAD IS main HEAD (payload ⊂ pristine tree), so a green-at-pristine NEW is one `jq` read away from the "environment-caused" conclusion — the manual classification collapses from "hand-build a scratch run" (#1932: ~30+ min) to "read the compare JSON". The verdict class deliberately stays NEW (fail-closed attribution), matching the #1337 precedent for live-root-stray scan failures (`:1722-1726`).
