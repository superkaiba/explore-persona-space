## 3. Design

### 3.1 Design-space verdicts (pick ONE primary; justify)

**REJECTED (a) — time-scoped git-free self-healing exemption.** Infeasible as the brief anticipates: in the `git archive | tar -x` gate tree, file mtimes are extraction time — there is no git-free age signal. The one tempting heuristic (parse `issue<N>` from the filename and demote `N ≤ cutoff`) opens exactly the hole hard-constraint 3 bans: a NEW file written today for an old issue (`scripts/issue658_new_analysis.py` — same-issue follow-up rounds do this routinely) would evade the ratchet forever.

**REJECTED (b) — fail-soft git-aware demotion.** Two independent disqualifiers. (i) *It never engages at the incident site:* the race fires in the Step 10d gate tree, which is non-git by construction, so (b) falls back to current behavior exactly where the block happens. It only changes repo-root runs (trunk no-flags + `test_..._live_tree_passes`), producing the WORST divergence: post-merge trunk reads green (git demotes to WARN) while the gate still blocks — the gate's own justification for blocking ("trunk pytest goes red post-merge either way") becomes false, yet the block persists. (ii) *Boundary fragility:* the stale-race files are by definition created within days of any pinned cutoff (between snapshot generation and merge), so a `git log --diff-filter=A` date test sits exactly on its own boundary at every incident.

**REJECTED (c) — env-var own-diff WARN demotion (the Goal's "auto-append with WARN" reading).** The gate materializes `/tmp/issue-<N>-own-diff.txt`, so the mechanism is buildable, and the check's default (env absent → current FAIL) would be self-consistent. But hard constraint 2 kills it: if the gate demotes a non-own-diff offender to WARN and the merge lands WITHOUT the snapshot append, the post-merge trunk no-flags run and `test_check_live_hf_retry_routing_live_tree_passes` go red **fleet-wide** (every session's Step 9c gate inherits it) — a silent trunk-red is strictly worse than the visible, correctly-attributed gate BLOCK. Making it safe requires the gate to auto-commit the append into the branch payload before merge — SKILL.md wiring (out of this task's `target_file` scope) and a review-integrity problem (the gate must not mutate the payload it certifies; every diff line is supposed to have passed the code-review ensemble).

**PRIMARY (d) + message/doc hardening (e-lite).** Keep the BLOCK (it is correct — it protects trunk pytest, per the gate's own design comment). Collapse the recovery from "diagnose + hand-edit + gate round" to "one command + paste + gate round", and shrink the future staleness window from days to minutes by PRESCRIBING late regeneration in the constant's comment. Concretely: (1) `--regen-hf-routing-snapshot` maintenance flag printing the paste-ready literal + stderr diff summary; (2) the FAIL message names the command (self-documenting at the point of failure — no SKILL.md wiring needed for discovery); (3) the constant's comment block prescribes: *when a round TIGHTENS this check (predicate / window / scope / new snapshot-based sibling check), regenerate the snapshot as the LAST pre-gate step on a main-synced tree, and again on any gate re-run after main churn*; (4) drop hardcoded entry counts from prose (module doc "297" + CLI help "~297" are stale — actual count 298; the function docstring's "298" is currently ACCURATE (the 74bf37250b hotfix bumped it) but equally drift-prone, so drop all three; `.claude/rules/upload-policy.md:384`'s "~297" prose mention is optional/out of the check's blast radius — implementer MAY de-drift it).

**Honest recurrence quantification (per the brief).** For THIS check at steady state the #1547 window is CLOSED by construction: the check now exists on main, so (i) both gate legs carry it and any hypothetical stale main offender flags in BOTH legs and subtracts out (pre-existing red, no block), and (ii) a genuinely new bare-call file cannot land THROUGH a gate at all — its own gate flags it as own-diff-named NEW (and the inline free-analysis payload lint gate covers inline commits). The residual classes this fix actually addresses: **(R1) check-tightening rounds** — a future branch that tightens the predicate (e.g. adding `snapshot_download`, currently out by design) regenerates its snapshot at implementer time and re-opens the exact #1547 race for the tightened delta against main churn (20+ merges/day × multi-day branch lifetimes ⇒ near-certain per tightening round; tightening rounds themselves are rare, plausibly 1–3/year). With this fix: cost drops from gate-round + diagnosis + hand-edit to gate-round + one command; the prescriptive late-regen comment often avoids the block entirely (regen minutes before the gate; the #1456 3-way merge folds any main-side appends into the gated copy). **(R2) future snapshot-based checks at introduction** — same shape; this establishes the regen-flag idiom to ship WITH such checks (the constant's comment says so). **(R3) gate-bypassing direct-to-main commits** (orchestrator workflow-edit hot-fix scripts with bare HF calls) — NOT the staleness race: the file is genuinely new and SHOULD fail; the ratchet working as intended; recovery for a false positive there is the same one command. A minimal fix covers the realistic recurrence — no gold-plating: no env-var contract, no git probes, no gate wiring.

**Step 1 — refactor the scan into shared helpers (behavior-preserving).** Replace the body of `check_live_hf_retry_routing` (8139–8172) with:

```python
def _hf_routing_scan_files(root: Path):
    """Yield (path, rel) for every scanned candidate under
    HF_ROUTING_SCOPE_ROOTS, excluding the pattern-string + generated-code
    constants (NOT the frozen snapshot — callers apply that: the check
    exempts it, the regen flag deliberately re-derives it, #1568)."""
    for scope in HF_ROUTING_SCOPE_ROOTS:
        base = root / scope
        if not base.exists():
            continue
        for py in sorted(base.rglob("*.py")):
            if not py.is_file() or "__pycache__" in py.parts:
                continue
            rel = py.relative_to(root).as_posix()
            if rel in HF_ROUTING_PATTERN_STRING_FILES or rel in HF_ROUTING_GENERATED_CODE_FILES:
                continue
            yield py, rel


def _hf_routing_file_errors(py: Path, rel: str) -> list[str]:
    """Per-file scan body shared by check_live_hf_retry_routing (verdict)
    and regen_hf_routing_snapshot (offender enumeration). Snapshot-BLIND."""
    errors: list[str] = []
    lines = py.read_text(encoding="utf-8").splitlines()
    for i, line in enumerate(lines):
        stripped = line.lstrip()
        if stripped.startswith("#") or stripped.startswith("what="):
            continue
        m = HF_ROUTING_CALL_RE.search(line)
        if m is None:
            continue
        if "# NO_RETRY:" in line or (i > 0 and "# NO_RETRY:" in lines[i - 1]):
            continue
        if _hf_routing_call_is_wrapped(lines, i, m.start()):
            continue
        errors.append(
            f"[live-hf-retry-routing] {rel}:{i + 1}: bare HF Hub "
            f"call in LIVE code — route through hub.retry_transient, waive with "
            f"`# NO_RETRY: <reason>`, or (pre-existing file this round never "
            f"touched — snapshot staleness, #1568) regen on a main-synced tree: "
            f"`workflow_lint.py --regen-hf-routing-snapshot`: {stripped[:100]}"
        )
    return errors


def check_live_hf_retry_routing(*, repo_root: Path | None = None) -> list[str]:
    """<docstring: keep, minus the hardcoded '298' count; add a pointer to
    --regen-hf-routing-snapshot for staleness recovery>"""
    root = repo_root if repo_root is not None else _REPO_ROOT
    errors: list[str] = []
    for py, rel in _hf_routing_scan_files(root):
        if rel in HF_ROUTING_FROZEN_SNAPSHOT:
            continue
        errors.extend(_hf_routing_file_errors(py, rel))
    return errors
```

**Step 2 — the regen function** (immediately after the check):

```python
def regen_hf_routing_snapshot(*, repo_root: Path | None = None) -> int:
    """Maintenance (#1568): print the ready-to-paste
    HF_ROUTING_FROZEN_SNAPSHOT literal for the CURRENT tree — every scanned
    file carrying >=1 bare (unwrapped, unwaived) HF Hub call, re-derived
    snapshot-blind — plus a +/- diff summary vs the compiled-in constant on
    stderr. Run on a MAIN-SYNCED tree (repo root on current main, or the
    worktree after a rebase onto origin/main). REVIEW the `+` lines before
    pasting: a file YOUR round created must be ROUTED through
    hub.retry_transient (or NO_RETRY-waived), never grandfathered — the
    stderr summary exists so the round's code review sees the delta.
    Not part of the no-flags bundle; early-dispatched in main()."""
    root = repo_root if repo_root is not None else _REPO_ROOT
    offenders = sorted(
        rel for py, rel in _hf_routing_scan_files(root) if _hf_routing_file_errors(py, rel)
    )
    sys.stdout.write("HF_ROUTING_FROZEN_SNAPSHOT: frozenset[str] = frozenset(\n    {\n")
    for rel in offenders:
        sys.stdout.write(f'        "{rel}",\n')
    sys.stdout.write("    }\n)\n")
    added = sorted(set(offenders) - HF_ROUTING_FROZEN_SNAPSHOT)
    removed = sorted(HF_ROUTING_FROZEN_SNAPSHOT - set(offenders))
    sys.stderr.write(f"# regen vs compiled-in constant: +{len(added)} added, -{len(removed)} removed\n")
    for rel in added:
        sys.stderr.write(f"# + {rel}  (NEW offender — route it if this round created it)\n")
    for rel in removed:
        sys.stderr.write(f"# - {rel}  (no longer flags: deleted, routed, or waived)\n")
    return 0
```

## 11. Decision Rationale (load-bearing design constants)

- **Block preserved (no WARN demotion) — What:** a non-snapshot offender keeps FAILing everywhere. **Why:** hard constraint 2 — any gate-time demotion not paired with a landed append produces fleet-wide trunk-red (`test_..._live_tree_passes`); the gate's design comment calls the block correct. **Source:** SKILL.md:10061–10101 (subtraction + verdict logic) + tests/test_workflow_lint.py:8120. **Alternatives:** (b)/(c), rejected §3.1.
- **Regen output = FULL paste-replace literal (not append-only lines) — What:** print the whole constant. **Why:** paste-replace is the only shape that cannot half-apply; drops of since-routed entries are safe (ratchet-tightening) and visible via stderr `-` lines. **Source:** the source shape at workflow_lint.py:7781–8082; the `--emit-tables` regenerate-whole-block precedent (workflow_lint.py:11264). **Alternatives:** append-only diff output (smaller paste but two-step and mis-mergeable), auto-rewrite of the file in place (self-modifying lint — rejected: the diff must go through the round's review).
- **Early dispatch, NOT in the no-flags bundle — What:** `return regen_hf_routing_snapshot()` before `load_workflow_yaml`. **Why:** stdout must be exactly the literal (machine-pasteable); regen must work even when workflow.yaml is mid-edit; a maintenance flag in the bundle would print ~300 lines into every gate leg. **Source:** `--emit-tables` precedent (in-tuple, in-flow) adapted — the difference (early return) is justified by the clean-stdout requirement. **Alternatives:** in-flow dispatch with tuple membership (stdout contaminated by `workflow_lint: PASS`).
- **No dead-entry hygiene on the snapshot — What:** no FAIL when a member is deleted/routed. **Why:** a dead entry is inert; enforcing removal would CREATE gate friction on unrelated deletions — the anti-goal of this task. **Source:** contrast with `_LESSONS_ROW_GRANDFATHER_MAX_BYTES`'s deliberate per-entry hygiene (workflow_lint.py:10651–10680), whose purpose (byte-budget ratchet) does not transfer. **Alternatives:** JUDGE_PIN-style closed-list enforcement — rejected for the same reason.
- **Recovery hint in the per-line FAIL message (not a separate summary line) — What:** extend each error line's tail. **Why:** an unconditional extra summary line would enter the gate's normalized-line comparison and could itself register as NEW (SKILL.md:10067–10075); identical per-line text subtracts cleanly. Discovery-at-point-of-failure removes any SKILL.md wiring need. **Source:** SKILL.md normalization block. **Alternatives:** docstring-only (operator at the gate never sees it), SKILL.md gate-recipe edit (out of scope).
- **Prescribed late-regen point = "last pre-gate step on a main-synced tree" — What:** comment-level process prescription. **Why:** shrinks the staleness window from branch-lifetime to minutes; composes with the #1456 3-way merge (main-side appends fold into the gated lint copy). **Source:** SKILL.md:9844–9848 (#1456 exception) + incident timing in the task body. **Alternatives:** implementer-time generation only (the incident's failure mode).
