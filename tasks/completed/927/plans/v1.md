## 1. Goal

**Requirement:** a genuinely NEW `backend.launch()` (fresh `gcloud compute instances create` after the prior instance died/was deleted) must run under a FRESH attempt id, so its crash-persist dir (`issue<N>_partial/<attempt_id>/`), completion sentinel, and `expected_artifacts` HF prefix never collide with a dead prior attempt's namespace. A RECONNECT to a still-live instance must keep the original id.

**Acceptance criteria (testable):**
1. Fresh GCP launch with a pre-existing lease carrying `attempt_id="att-dead"` launches with a spec whose `extra["attempt_id"] != "att-dead"`, and the persisted lease reads back the NEW id.
2. `route()` reconnect to a live job leaves `lease.attempt_id` byte-unchanged and never calls the threading function.
3. Sentinel path, startup-script `EPS_ATTEMPT_ID`, crash-persist dest, instance labels, and `expected_artifacts` all key on the launch's own threaded id (already structurally guaranteed: gcp.py derives all five from the ONE `attempt_id_for(spec)` value; existing `att-fixed-001` tests pin it).
4. Lease fields `gcp_attempts_today`, `gcp_attempts_date`, `gcp_failover_of`, `runpod_wedge_failover_of`, `runpod_cuda_ima_failover_of`, `backend`, `job_id` are preserved across the threading write.

## 3. Design

**Seam: change the minting policy inside `_thread_attempt_id_into`; touch no call site logic.** Every caller is a fresh submit, so "called ⇒ mint fresh" is exactly the right invariant; reconnect paths structurally never reach it.

### 3.1 `router.py::_thread_attempt_id_into` (~4438) — the fix

```diff
 def _thread_attempt_id_into(spec, lease, write_fn):
-    current_id = (spec.extra or {}).get("attempt_id")
-    if lease is None:
-        attempt_id = str(current_id or _make_attempt_id())
-        lease = Lease(issue=int(spec.issue), spec_hash=spec_hash(spec), attempt_id=attempt_id)
-        write_fn(lease)
-    else:
-        attempt_id = lease.attempt_id
+    current_id = (spec.extra or {}).get("attempt_id")
+    # #927: mint FRESH per launch. Every call site is a fresh-submit path
+    # (reconnect early-returned above); reusing lease.attempt_id made a NEW
+    # launch inherit a dead attempt's crash-persist/sentinel namespace.
+    attempt_id = str(current_id or _make_attempt_id())
+    if lease is None:
+        lease = Lease(issue=int(spec.issue), spec_hash=spec_hash(spec), attempt_id=attempt_id)
+    else:
+        lease.attempt_id = attempt_id  # lease follows the launch, never vice versa
+    write_fn(lease)
     new_extra = dict(spec.extra or {})
     new_extra["attempt_id"] = attempt_id
     return replace(spec, extra=new_extra), lease
```

Rewrite the docstring: fresh-mint-per-launch contract; caller-pinned `spec.extra["attempt_id"]` takes precedence (explicit re-attach tooling); reconnect id-stability lives in the router early-return + the GCP `eps-attempt-id` label recovery; cite #927.

**How the lease record stays consistent at submit:** the `write_fn(lease)` here lands inside the caller's open flock transaction; `_lease_after_submit` (called at 2758/3583/4109 with this same lease object) then stamps `backend`/`cluster`/`job_id`/`submitted_at` and preserves the NEW `attempt_id` — so poll/finalize consumers reading the lease after submit see the id the launch actually used. Counters (`gcp_attempts_today`/`_date`) and failover fields are untouched (the function only assigns `attempt_id`).

### 3.4 What is deliberately NOT changed

- Reconnect paths (router 2612–2667 / 3487–3534; gcp.py `reconnect_or_none` + label recovery) — byte-untouched.
- `_lease_after_submit` / `_persist_lease_after_submit` logic (only the docstring).

- `_make_attempt_id()` shape (`att-YYYYMMDD-HHMMSS`) — same-second collisions are physically implausible for genuinely distinct launches (instance death + re-dispatch takes minutes; the flock + canonical-name reconnect prevent same-second sibling creates); keeping the shape avoids touching the gcp.py validation/label surface.

- **Artifact reuse:** N/A — no artifact reuse.
- **Draw battery / stats:** N/A — no draw battery. **Empirical-null gate:** N/A — no empirical-null gate.
- **Seam choice (function-level policy change vs per-call-site minting):** What — mint inside `_thread_attempt_id_into`. Why — all callers are fresh submits, so the invariant "called ⇒ fresh id" is enforced in ONE place; per-call-site minting would triplicate the logic and leave the function's reuse semantics as a live trap. Source: read of router.py call-site topology (§2). Alternative rejected: a `launch_kind` flag threaded from `route()` — more moving parts for the same behavior.
- **Lease-follows-launch (update `lease.attempt_id` at threading time):** Why — the durable record must name the namespace the launch ACTUALLY used, so any future lease reader and the crash-persist forensics agree. Alternative rejected: leaving the lease stale (re-creates a latent version of the same bug for any future lease-id consumer).
- **Delete `_thread_attempt_id`:** dead code whose semantics would diverge post-fix. Source: `.claude/rules/code-style.md` supersede→delete.
- **Keep `att-YYYYMMDD-HHMMSS` shape (no random suffix):** avoids touching gcp.py validation/label sanitization surface; collision case argued negligible (§6). Alternative (4-hex suffix à la RunPod) available as a follow-up if a collision is ever observed.
- **Check 11 (smoke):** the real smoke IS the test battery — `uv run pytest tests/test_router.py tests/test_gcp_backend.py tests/test_backend_poll.py` + `uv run ruff check` + `uv run python scripts/workflow_lint.py`.
- **Check 15 (fail-loud):** the claim "a wrong-namespace reconnect fails loud" is existing behavior (confirm_artifacts FAIL on sentinel-path mismatch, gcp.py:3696–3705 rationale); the NEW fail-loud-relevant behavior is pinned by `test_fresh_gcp_launch_after_dead_prior_attempt_uses_new_attempt_id` and `test_reconnect_keeps_prior_attempt_id_no_remint`.
