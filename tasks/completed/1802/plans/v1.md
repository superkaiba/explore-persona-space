# Plan v1 — task #1802: new_worktree.sh sets upstream tracking for issue branches

## Plan Summary

`scripts/new_worktree.sh` creates/attaches issue branches with no upstream
tracking (`--no-track` is deliberate, #1214 — a branch cut from
`refs/remotes/origin/main` must never track origin/main), so any worktree
consumer composing a bare `git pull --rebase` fails with
"There is no tracking information for the current branch" (live failure:
#1689's session, 2026-07-28). Fix: configure the branch's upstream as its
OWN name on origin (`branch.<BRANCH>.remote=origin` +
`branch.<BRANCH>.merge=refs/heads/<BRANCH>`) at worktree creation AND on
reuse, idempotently — never origin/main, preserving the #1214 invariant.
Bare `git push` then works immediately (creates `origin/<BRANCH>` on first
push); bare `git pull --rebase` works once the branch exists on origin, and
before that fails with the clearer "no such ref was fetched" instead of
"no tracking information".

`architectural: false` — a guardrail addition to one workflow-helper script
plus its pin tests; no public contract change.

## Requirement + acceptance criteria

1. A FRESH branch created by `new_worktree.sh` has
   `branch.<BRANCH>.remote == origin` and
   `branch.<BRANCH>.merge == refs/heads/<BRANCH>` (and NOT
   `refs/heads/main` — the #1214 pin survives, reformulated).
2. The REUSE path (existing populated worktree, the /issue resume case)
   idempotently repairs a missing upstream config, and stays exit-0 on any
   repair failure (WARN only — same contract as `_ensure_issue_cones`).
3. The no-`origin`-remote path (item-31 fixture repos) sets NO branch
   config (nothing to track).
4. An ALREADY-CONFIGURED upstream (user set something deliberately) is
   never clobbered.
5. Existing #1214 pins (items 30–35) still pass, with item 30's
   absent-upstream assert deliberately REWRITTEN to pin the new shape
   (merge == `refs/heads/issue-30`, never `refs/heads/main`).

## Method delta (vs current behavior)

Current: `_add()` passes `--no-track`; no upstream is ever configured;
tracking exists only if a later push happened to use `-u`.
New: keep `--no-track` (it prevents the WRONG upstream, origin/main);
add a small `_ensure_upstream()` helper called on every path that yields a
usable worktree (fresh sparse, fresh full, repair, reuse). Setting
`branch.X.remote/merge` config directly (rather than
`branch --set-upstream-to`) works even before `origin/<BRANCH>` exists —
self-heals on first push.

## File paths + concrete diff sketch

`scripts/new_worktree.sh`:

```bash
# Upstream tracking (#1802): point the branch at its OWN name on origin —
# never origin/main (#1214; the --no-track in _add stays load-bearing) — so
# bare `git push` / `git pull --rebase` inside the worktree work. Config is
# branch-scoped (shared .git/config, worktree-independent); idempotent;
# no-op when no `origin` remote exists or an upstream is already set.
# WARN-only on failure: callers on the reuse path rely on exit 0.
_ensure_upstream() {
  git -C "$REPO_ROOT" remote get-url origin >/dev/null 2>&1 || return 0
  if ! git -C "$WT" config "branch.${BRANCH}.merge" >/dev/null 2>&1; then
    { git -C "$WT" config "branch.${BRANCH}.remote" origin \
        && git -C "$WT" config "branch.${BRANCH}.merge" "refs/heads/${BRANCH}"; } \
      || echo "new_worktree: WARN — could not set upstream origin/${BRANCH}; set manually: git -C \"$WT\" branch --set-upstream-to=origin/${BRANCH}" >&2
  fi
}
```
