### Hunk 1 — c12 standalone ASCII x (`scripts/verify_plan.py` L1128–1134)

Replace L1128–1130 (comment + `_MULT_TOKEN`) with:

```python
# The multiplication token plans actually write: the real multiplication
# sign plus the ASCII fallbacks. The multiplication sign and `*` are
# unambiguous and keep tight/zero-whitespace binding ("50*28"); ASCII `x`
# counts ONLY when standalone w.r.t. word chars — "layer-ma|x| perms",
# "shared-inde|x| draws", "honest_nulls_ma|x|draws", "draws |x|gboost"
# are word-split artifacts, not products (#1099; 27 realized corpus
# false-arith lines, 0 verdict flips on removal). Digit-tight ASCII forms
# ("2x2") also stop counting: every draw-bearing corpus product is spaced
# ("4 draws x 492 cells"), and "the 2x2 draws its factors" is the verb
# false-positive the digit carve-out would re-admit.
_MULT_TOKEN = r"(?:[×*]|(?<!\w)x(?!\w))"  # noqa: RUF001 — the multiplication sign is real plan text
```

(Lint note, from the Phase-1.5 fact-check: comment-resident `×`/`’` chars trip **RUF003**, which `# noqa: RUF001` does not suppress — the comment above is therefore ASCII-only (no literal multiplication sign / curly apostrophe in comments); the regex-line noqa keeps the current code's exact wording. If a comment line must carry one of those chars, it takes its own `# noqa: RUF003`. Implementer discretion per § Plan deviations.)

`_MULT_ARITH_RE` (L1131–1134) is rebuilt from the same f-string composition, **byte-unchanged** — the fix is entirely inside `_MULT_TOKEN`. `_GRID_FACTOR`, `_GRID_DECOR`, `_DRAW_FACTOR`, `_BATTERY_TRIGGER_RE`, the window machinery, and `check_battery_multiplier` are untouched.

**Match-trace rationale (the subtlety worked through):** the current `[×x*]` with `\s*` on both sides lets the engine backtrack `_GRID_FACTOR` (`[A-Za-z][\w-]*`, greedy) to split a word: `"the max 50 draws"` parses as GRID=`ma` + `x` + `\s*`=` ` + DRAW=`50 draws` — the outer `\b` sits before `m` (space→word boundary), so it does NOT prevent word-splits; likewise `\w` includes `_` and digits, so `honest_nulls_maxdraws` parses as GRID=`honest_nulls_ma` + `x` + DRAW=`draws` with zero whitespace anywhere. `(?<!\w)x(?!\w)` requires the `x` itself to be a standalone token (non-word or string edge on both sides), which kills every word-split parse at the only place they all share — the `x` — while `"10,000 draws x 24 cells"` keeps matching (space on both sides).

**Decision: whitespace/word-standalone (Goal wording), not letter-boundary-only.** Corpus evidence: all realized draw-bearing arithmetic is spaced (`4 draws x 492 cells`, `12 sources x 3 seeds`, `10,000 draws x 24 cells`); tight digit forms (`2x2` ×52, `6x2` ×70, `100x48`, `16x26`) are design-shape/matrix tokens, never draw-bearing products, and keeping them as mult tokens re-admits the `"the 2x2 draws its factors"` verb false positive. Replay shows the standalone rule costs zero realized corpus matches beyond the 27 artifacts. The **fallback** (kill criterion, §7) is `(?<![A-Za-z])x(?![A-Za-z])` — letter-boundary only — probe-verified to also kill the letter-adjacent artifact classes while retaining digit-tight binding.

### Hunk 2 — c18 negation guard (`scripts/verify_plan.py` L2242–2245)

Replace with:

```python
# #1099: the guard covers the n't contraction family (word chars + n +
# straight-or-curly apostrophe + t) — the prior bare `n't` alternative was
# DEAD CODE (a word boundary never matches at the word-internal s->n
# transition inside "doesn't"; probe-verified) — plus cannot /
# fail(s|ed) to / until (corpus: cannot ~5,000, doesn't ~2,100, can't
# ~1,200, until ~970, fails-to ~480 plan-line occurrences). Curly
# apostrophe included (7 corpus plan files carry it). Strictly widening
# the DISQUALIFIER = strictly narrowing the affirmative satisfier —
# fail-safe by construction.
_C18_NEG_DEFER_RE = re.compile(
    r"(?i)\b(?:not|\w*n[’']t|cannot|never|without|fail(?:s|ed)?\s+to|until"  # noqa: RUF001
    r"|will|would|shall|should|may|might|could"
    r"|once|pending|deferred|later|TBD|to\s+be)\b"
)
```

(Same lint note as Hunk 1: the comment block is ASCII-only — the curly apostrophe appears only inside the regex STRING, covered by the RUF001 noqa; comment lines carry no literal curly apostrophe, so no RUF003 exposure. Probe-confirmed by the Phase-1.5 fact-check.)

All current tokens kept (the bare `n't` is subsumed: `\w*` matches empty, so standalone `n't` still matches — probe-verified). `_C18_PRODUCES_REGISTERED_RE`, `_c18_affirmative_produces_hit`'s 48/80 span, and `_C18_BYCONSTRUCTION_RE` stay **byte-unchanged**. Probe-verified against the two pinned PASS affirmatives: neither `C18_V8_ROW_COVERAGE`'s span (`"...a superset of the retained set); the plan's own fits produce every registered chain row on each arm."`) nor the own-fits remedy line contains any new token — both still PASS.

## 11. Decision Rationale

Hyperparameter table: **N/A — no model training.** Regex-design decisions (Source = the #1086 parked candidate + this session's probes/greps, per §2):

1. **Standalone-x via `(?<!\w)x(?!\w)` (not whitespace-literal `\s`, not letter-only boundary).** *What:* ASCII `x` is a mult token only with non-word chars (or string edges) on both sides. *Why:* kills all 5 word-split parse classes at their shared point (the `x` itself); lookarounds compose cleanly inside the existing `\s*`-joined f-string without touching `_MULT_ARITH_RE`'s structure; also correctly handles `x(` / `x~` decoration adjacency (non-word → still standalone). *Source:* #1086 candidate item 1 + probes 1–2, 4–6 (27 realized artifact lines, 0 verdict flips, 9/9 positives retained). *Alternatives:* literal `\s` requirement (equivalent on the corpus but breaks `x(`-adjacent decoration composition ordering); letter-boundary `(?<![A-Za-z])x(?![A-Za-z])` (kept as the §7 fallback — retains digit-tight `2x2` binding but re-admits the "`the 2x2 draws its factors`" verb false positive).
2. **Digit-tight ASCII forms (`50x28`) deliberately excluded.** *What:* `2x2`-style tokens stop counting as multiplication. *Why + Source:* corpus grep — all draw-bearing products are spaced; tight digit forms are design-shape tokens (52× `2x2`, 70× `6x2`, etc.), and the only tight-form interaction with draw vocabulary found is the verb false positive. Zero corpus verdict flips confirm zero realized cost. *Alternatives:* keep digit-tight (fallback above).
3. **`\w*n[’']t` for the contraction family (replacing dead `n't`).** *What:* one alternative covering doesn't/can't/won't/isn't/wouldn't/… plus standalone `n't` (empty `\w*`), straight + curly apostrophe. *Why:* the bare `n't` can never match word-internally (probe-verified `\b` semantics); enumerating stems (does/can/won/…) rots. No benign false-fire surface: the pattern requires the literal `n['’]t` trigram, absent from possessives ("plan's") and ordinary words. *Source:* #1086 candidate item 2 + probes 3–5 + corpus frequencies (§2 probe 8). *Alternatives:* stem enumeration (rots); dropping curly ’ (7 corpus plan files carry it per the fact-check recount; inclusion costs one noqa).
4. **`cannot`, `fail(?:s|ed)?\s+to`, `until` as whole-word tokens.** *What:* the remaining Goal-named gaps plus the tense variants of "fails to". *Why:* `\bnot\b` cannot match inside `cannot` (word-internal boundary — same `\b` mechanics as the dead `n't`); "fail to"/"failed to" (261/… corpus occurrences) carry identical deferral semantics to "fails to" and excluding them leaves an obvious evasion. *Source:* candidate item 2 verbatim list + probe 8 frequencies. *Alternatives:* "fails to" only (rejected — free evasion); adding mangled corpus variants like "can t" (rejected — table/filename noise, not prose negation; noted §12).
