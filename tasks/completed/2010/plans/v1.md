## 2. Method delta (design decision)

**Decision: design (a)-refined — a vintage guard that SKIPS the two
corpus-replay tests on non-main-vintage trees.** The corpus replay is a
FLEET-DATA invariant ("every historical run marker in the live corpus parses
under the current parser"), not a branch-code invariant; it is meaningful
exactly where corpus and parser are the same vintage as the fleet's live
state — the `main` checkout (ledger refreshes via `step9c_baseline.py
refresh`, root gate runs, post-merge full suite) and the compare pristine
oracle detached at the fetched `origin/main` tip.

Why the alternatives lose:

- **Body option (b) (fold parser+test into the Step 5a sync family) —
  REJECTED.** `src/explore_persona_space/task_workflow.py` is a ~3300-line
  core module imported by `scripts/task.py` and most of the workflow surface.
  SKILL.md § Step 5a explicitly bans extending the sync into `src/` ("main's
  newer workflow tests pin behavior implemented in main's newer `scripts/` +
  `src/` (e.g. `task_workflow.py`)"); syncing it onto stale branches is the
  #1824/#1860 half-sync class with fleet-wide blast radius, and
  family-atomicity would skip the sync for every branch that edits ANY family
  member anyway.
- **Body option (a) literal ("pin corpus at the branch's merge-base
  snapshot") — a NO-OP.** `_tasks_root()` already reads the TEST-TREE's own
  `tasks/` (`Path(__file__).parents[1]/tasks`), i.e. the fork snapshot. The
  #1917 red is the fork snapshot ITSELF being an inconsistent pair: the
  branch forked in the window after the #1900 dash-led marker landed on main
  (2026-08-01T03:30Z) but before the #1984 parser widen (`0aad8f32c7`)
  landed — corpus has the marker, parser lacks the fix, frozen until the
  branch merges origin/main. Pinning at merge-base reproduces exactly that
  pair.
- **Body option (a2) (replay through the MAIN-resident parser on branches) —
  REJECTED.** Still couples every branch gate to live fleet DATA churn: a
  genuinely malformed marker landing fleet-wide (the #1739 bare-`label=`
  class, allowlisted only by #2154) would red every mapped branch gate until
  allowlisted — the same one-fleet-event-burns-N-branch-gates failure shape,
  minus the parser-vintage half. Also needs fragile `git show`-based dynamic
  import of a 3300-line module.
- **Parser-touching carve-out (skip UNLESS the branch's diff touches the
  parser/test pair) — CONSIDERED, REJECTED.** The test reaches gates via
  `select_step9c_tests.py`'s import arm, i.e. for ANY branch touching
  `task_workflow.py` — overwhelmingly parser-AGNOSTIC edits to the module.
  The carve-out would preserve the #1917 red for exactly the largest
  consumer class. Parser-FIXING branches get their vintage-consistent
  validation from the module's unit literals (the existing convention: every
  parser fix pins its motivating form as a unit test — #1092's stamp form,
  #1900's dash form, the #1689 breadcrumb notes are all VERBATIM literals in
  the module).

Post-change routing of the invariant: a new-form marker landing on main reds
the ROOT-side runs (ledger refresh / root gates) → known-red ledger entry +
the #1713 urgent-park machinery files the parser fix with `urgency: main-red`
— the designed main-red channel — while branch gates stay green. That is the
correct owner: the mismatch is a fleet artifact, not a branch defect.

## 3. File paths + concrete diff

1. Add one module-level helper near `_tasks_root()` (~:1145):

```python
def _corpus_tree_is_main_vintage() -> bool:
    """True iff this test file's tree is current-main vintage (#2010).

    The corpus-replay tests validate LIVE fleet task state against the
    tree-resident parser — a fleet-data invariant that is only coherent
    where corpus and parser share the fleet's current vintage: the `main`
    checkout, or a tree detached exactly at the fetched origin/main tip
    (the Step 9c compare pristine-oracle scratch worktree). On an
    issue-branch worktree the pair is frozen at fork time and any branch
    forked between a new-form marker landing and its parser fix landing
    is red with no code defect on the branch (#1917/#1895).
    """
    tree = Path(__file__).resolve().parents[1]
    try:
        branch = subprocess.run(
            ["git", "-C", str(tree), "rev-parse", "--abbrev-ref", "HEAD"],
            capture_output=True, text=True, timeout=30, check=True,
        ).stdout.strip()
    except (OSError, subprocess.SubprocessError):
        return True  # git-less snapshot tree: single-vintage, self-consistent
    if branch == "main":
        return True
    try:
        head = subprocess.run(
            ["git", "-C", str(tree), "rev-parse", "HEAD"],
            capture_output=True, text=True, timeout=30, check=True,
        ).stdout.strip()
        om = subprocess.run(
            ["git", "-C", str(tree), "rev-parse", "origin/main"],
            capture_output=True, text=True, timeout=30, check=True,
        ).stdout.strip()
        return bool(head) and head == om
    except (OSError, subprocess.SubprocessError):
        return False
```

(`subprocess` import already present or added; `check=True` + exception
fallthrough keeps every failure on the documented fail direction.)

Fail-direction table (every arm chosen fail-safe):
| Tree state | Verdict | Why safe |
|---|---|---|
| root checkout on `main` | RUN | the invariant's home; ledger/urgent-park own any red |
| issue worktree (branch ≠ main) | SKIP | the #1917 class — zero branch-diff information lost; unit literals cover parser edits |
| detached at fetched origin/main tip (pristine oracle) | RUN | oracle must mirror main so a live fork-window red strips as pre-existing |
| detached elsewhere / just-forked stale | SKIP | frozen pair, same as branch |
| git absent / git error on branch probe | RUN | status quo; git-less trees are single-snapshot self-consistent (and usually lack tasks/ → prior skip) |
| git error on the head/origin probe after non-main branch | SKIP | unknown vintage on a known non-main tree — the conservative arm |
