## 1. Goal

Document, in `.claude/rules/upload-policy.md`, that HF Trainer's built-in
`WandbCallback` (armed by the `WANDB_LOG_MODEL` env var) is a SEPARATE
checkpoint-auto-upload path from our own `hub.py::upload_model_wandb()` /
`trainer.py::_maybe_upload_checkpoint_to_wandb()` path. `WANDB_LOG_MODEL` must
stay UNSET; our own path is guarded by `EPM_UPLOAD_MODEL_WANDB=1` (default OFF,
landed 2026-06-29 in `b4474042b7`). This closes the documentation gap that let
HF Trainer's `WandbCallback` silently accumulate ~784 G of safetensors
checkpoints on WandB before the guard landed. The note reaches the right eyes
because `upload-policy.md`'s `paths:` frontmatter triggers an on-demand load
whenever anyone touches training / hub / sweep code.

### The exact prose to add

Insert the following new paragraph in `.claude/rules/upload-policy.md`
IMMEDIATELY AFTER the existing "Inline-upload fence" paragraph (currently lines
134-136, ending `... set the env in try/finally to prevent double-uploads.`) and

Exact text to insert (one blank line before and after, matching the file's
paragraph spacing):

```markdown
**`WANDB_LOG_MODEL` is a SEPARATE checkpoint-upload path from ours — it must
stay UNSET.** Two independent mechanisms can push model weights to WandB, and
only one is ours: (1) HF Trainer's built-in `WandbCallback` (armed by the
`WANDB_LOG_MODEL` env var — `checkpoint` / `end` / `true`) auto-uploads
`checkpoint-*` safetensors to WandB Artifacts on its own save cadence, entirely
outside `hub.py`; and (2) our own inline path (`hub.py::upload_model_wandb()` +
`trainer.py::_maybe_upload_checkpoint_to_wandb()`), gated by
`EPM_UPLOAD_MODEL_WANDB=1` (default OFF). Weights are canonical on the HF Hub;
WandB carries LIVE training metrics only (CLAUDE.md Upload Policy), so BOTH
paths stay off by default. Keep `WANDB_LOG_MODEL` UNSET (do not export it, and
do not set `report_to`/`WandbCallback` in a way that enables it) — it is NOT
covered by `EPM_UPLOAD_MODEL_WANDB` and NOT by the
`EPM_SKIP_INLINE_CHECKPOINT_UPLOAD` fence above (both gate only our own path).
Closed history: HF Trainer's `WandbCallback` silently auto-uploaded ~15 GB
safetensors checkpoints per run and ~784 GB accumulated before the
`EPM_UPLOAD_MODEL_WANDB` guard (default OFF) landed 2026-06-29 in
`b4474042b7`; the ~4 TB WandB cleanup that followed archived the orphaned
weights to `superkaiba1/explore-persona-space-wandb-archive`.
```

Rationale for the anchor: the "Inline-upload fence" paragraph is the only
existing surface that discusses a WandB-Artifacts checkpoint auto-upload, so the
new note reads as its natural sibling and the explicit "NOT covered by
`EPM_UPLOAD_MODEL_WANDB` and NOT by the `EPM_SKIP_INLINE_CHECKPOINT_UPLOAD`
fence above" cross-reference lands correctly (the fence paragraph is physically
"above" the new one). The note deliberately does not restate the fence
paragraph's double-upload-prevention purpose — it distinguishes the two.
