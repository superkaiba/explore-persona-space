### 4.1 New regex (module level, next to `_BACKTICK_ISSUE_PARENT_RE`, ~L9582)

```python
# Slashless sibling of _BACKTICK_SUBPATH_COUNT_PAREN_RE (#1487, the #1345
# `analysis_tensors/turnstore` (10 files) footer shape): same paren/count/
# noun/lookahead shape VERBATIM, but the token does NOT end in "/". A
# slashless token has no intrinsic directory signature, so the gatherer
# admits it ONLY under the strong G4 arms (own issue<N>_ prefix, or a
# binding backtick parent anchor) — never the weak same-line HF cue — and
# declines dotted-final-segment tokens (check 32's FILE territory).
# Consumed ONLY by _gather_hf_unpinned_count_claims; check 30 Pattern D is
# deliberately untouched (pinned-adjacent slashless claims stay out of
# BOTH checks' scope — see the gatherer docstring).
_BACKTICK_SLASHLESS_SUBPATH_COUNT_PAREN_RE = re.compile(
    r"`(?P<sub>(?!\.\.?/)[A-Za-z0-9_\-./]{0,119}[A-Za-z0-9_\-])`"
    r"[ \t]{0,2}"
    r"\((?P<count>\d{1,3}(?:,\d{3})+|\d{1,6})\s+(?P<noun>files?|shards?)\b"
    r"(?!\s+(?:listed\s+)?per\s+\w+\b)"
    r"[^()]{0,200}\)"
    r"(?!\s{0,2}[:–—-]?\s{0,2}\[[^\]]{1,300}\]\(https?://huggingface\.co)",
    re.IGNORECASE,
)
```

Notes: (a) the paren/count/noun/distributive-decline/not-Pattern-B tail is copied VERBATIM from `_BACKTICK_SUBPATH_COUNT_PAREN_RE` (implementer: copy, don't retype); (b) the token's final char class `[A-Za-z0-9_\-]` excludes `/` — the two regexes are mutually exclusive by the closing-backtick anchor (`` `rejudge/` `` cannot match the slashless form: the char before the closing backtick is `/`); (c) total token bound stays ≤120 chars, matching the sibling.

```python
        resolved = token.strip("/")
    else:
        # G4 arm 2 (parent anchor), both shapes — existing binding code verbatim
        ...
    if resolved is None:
        if slashless:
            continue   # STRONG ARMS ONLY for slashless — no HF-cue fallback
        # existing G4 arm 3 (cue window) for the slashed shape, unchanged
        ...
    # count/noun/dedup/append — existing code verbatim (key still (count, noun-singular, token))
```

Properties this preserves: (i) slashless claims ALWAYS have `resolved` non-None → the check function's `resolved is None` branch, probe memo, cap, and message shapes need zero changes; (ii) the check-30/check-40 partition on the SLASHED shape is untouched; (iii) sorted-by-position merge keeps WARN-line ordering deterministic and body-order-stable.

### 4.4 Multi-claim/list binding (design question 4 — verified arithmetic)

The parent-anchor binder keys each claim to the NEAREST preceding anchor with a bracket-free, newline-free gap ≤ 400 chars. For the realistic #1345-style footer — one anchor + a comma/em-dash list of claims — the gap to the k-th claim includes the earlier claims' text (~40-80 chars each incl. backticks and parens; backticks and parens are NOT decline characters, only `[`/`]`/newline are). So ~4-6 list items bind comfortably within 400; an intervening markdown link correctly breaks binding for later items (decline, conservative). No code change needed; pinned by a dedicated multi-item fixture (§6 T4). Anchor slot arithmetic on the incident shape: anchor ends at the `` ` `` after `story_slot_ablation/`; gap to `` `analysis_tensors/turnstore` `` ≈ 3-10 chars (" — "). Binds.

### 4.5 Count resolution for slashless tokens (design question 5)

`resolved` = `<parent-stripped>/<token>` (or the token itself when issue-prefixed) — a slashless subpath is still a directory PREFIX for `_hf_file_count_for_prefix` (it `strip("/")`s its input and lists the tree under the prefix; check 30's own joins already pass slash-free prefixes, cf. `issue1112_x/raw_completions` in tests L3788). A wrong join or a prefix that is actually a file lands on `not_found`/0-files → the existing hedged "count not confirmed at main" note, never a hard failure. One-sided shard rule (`claimed <= files` for "shards") unchanged.
