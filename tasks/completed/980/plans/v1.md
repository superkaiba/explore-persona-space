# Plan — #980: make an `on_hold` + RUNNING pod loud at the watcher (pod-safety pass)

## 0.0 TL;DR (plain English)

- **What I'll change:** I'll teach the watcher's pod-safety pass that a task parked `on_hold` should never have a running RunPod pod — today that state is silently classified "other" and the pod bills forever. After the change the watcher auto-stops it (reversibly, after the existing ~20-min double-check, honoring the keep-running tag), exactly as it already does for completed/archived tasks.
- **What I expect:** a crash inside the "pause <N>" window (pod stop failed, park succeeded) now gets caught within ~20-30 min instead of never, with a marker on the task saying what happened; no other watcher behavior changes — in particular, sessions of paused tasks are NOT newly reaped.
- **What would change my mind:** if the test suite shows the session-reconcile pass (which aliases the done-set) or the wedge arm picking up unwanted new behavior from the shared sets — the design below decouples them precisely to avoid that; a failure there means falling back to alert-only (option b).

## 0. Plan Summary (technical)

**Change:** add a pod-safety-layer-only status set `AUTO_STOP_PAUSED = {"on_hold"}` and a derived `POD_SAFETY_AUTO_STOP = AUTO_STOP_DONE | AUTO_STOP_PAUSED` in `scripts/autonomous_session_watch.py`; consume the derived set in exactly two places — `_status_class()` (~L3649) and the `_maybe_handle_runpod_wedge()` MF6 gate (~L5718). `on_hold` then classifies `"auto-stop-done"`, inheriting the full existing machinery unchanged: 2-consecutive-miss guard, `keep-running`-tag exemption, inferred-follow-up exemption, reversible `pod.py stop`, once-per-episode marker. `AUTO_STOP_DONE` itself is NOT modified, so `SESSION_RECONCILE_DONE = AUTO_STOP_DONE` (~L12190) is untouched — the session-reconcile pass never starts reaping paused tasks' sessions. **Docstrings/comments** updated at 7 named sites; **docs** — the now-false "invisible to the watcher" sentences in `.claude/skills/issue/SKILL.md` § User pause affordance and CLAUDE.md § "User pause" updated in the same change. **Tests:** 5 new + 4 extended (named in §4.3), incl. a decoupling pin `"on_hold" not in SESSION_RECONCILE_DONE`. **Baselines/controls:** N/A — no model training. **Compute:** VM-only, minutes of pytest.

## 1. Goal + acceptance criteria

**Goal (verbatim from task):** add `on_hold` to an escaped-pod alert/stop class (or a test pinning that `_status_class('on_hold')` is deliberately `'other'`) so a crash inside the pause window is loud at the watcher level.

The #919 pause affordance orders pod-stop FIRST, `on_hold` park LAST. The residual gap: a crash *between* a successful park and a failed/never-run pod stop (or a `pod.py stop` that reported success but didn't take, or a hand-run `set-status <N> on_hold` that skipped the affordance) leaves `on_hold` + RUNNING pod. Today `_status_class("on_hold", ...)` → `"other"` → `("keep", 0)` — kept silently, no alert, no stop, silent billing with no bound.

**Acceptance criteria (all test-backable):**

1. `_status_class("on_hold", latest_progress_ts=<any>, now=<any>)` returns `"auto-stop-done"`.
2. An `on_hold` task's RUNNING managed pod is auto-stopped by `_process_pod` on the 2nd consecutive tick (threshold 2), with the `auto-stop` marker posted — end-to-end test at the `_process_pod` level.
3. The `keep-running` tag and the inferred-follow-up predicate both still skip the stop for an `on_hold` task (they key on `status_class == "auto-stop-done"`, which `on_hold` now produces).
4. A *wedged* (#664 no-port) `on_hold` pod falls through the wedge arm to the status-class auto-stop (mirrors MF6) — it is never routed to the wedge arm's terminate+failover, which would relaunch a workload the user deliberately paused.
5. `SESSION_RECONCILE_DONE` still equals exactly `{"completed", "awaiting_promotion", "archived"}` — `"on_hold" not in SESSION_RECONCILE_DONE` is a new explicit pin (sessions of paused tasks are never newly auto-stopped).
6. Full `uv run pytest tests/test_autonomous_session_watch.py tests/test_autonomous_session_watch_wedge.py -q` green; `uv run ruff check` clean on touched files; `workflow_lint.py` default run unaffected.
7. SKILL.md / CLAUDE.md pause-affordance prose no longer claims `on_hold`+RUNNING is invisible to the watcher.

## 4. Design

### 4.1 Set changes — `scripts/autonomous_session_watch.py`

Insert immediately after `AUTO_STOP_DONE` (~L619), before `POD_ACTIVE` (~L634):

```python
# Statuses where a RUNNING pod is an escaped pod for the POD-SAFETY pass ONLY
# (#980). `on_hold` = a user pause: the #919 pause affordance stops the pod
# BEFORE parking (teardown first, park last), so on_hold + RUNNING means the
# teardown leg crashed/failed inside the pause window — silent billing.
# DELIBERATELY NOT folded into AUTO_STOP_DONE: SESSION_RECONCILE_DONE (below)
# aliases that set, and the session-reconcile pass must NOT reap a paused
# task's session (the user may be live-parked in it — same conservatism as
# `blocked`). Subset-of-enum invariant pinned alongside AUTO_STOP_DONE by
# test_status_classes_subset_of_authoritative_enum.
AUTO_STOP_PAUSED = {"on_hold"}

# The pod-safety auto-stop trigger set: DONE statuses plus the paused status.
# NOTE: a NEW set object (union) — never mutate AUTO_STOP_DONE in place, or
# the SESSION_RECONCILE_DONE alias would silently widen with it.
POD_SAFETY_AUTO_STOP = AUTO_STOP_DONE | AUTO_STOP_PAUSED
```

Two consumer edits, both one-line:

- `_status_class()` ~L3649: `if status in AUTO_STOP_DONE:` → `if status in POD_SAFETY_AUTO_STOP:`.
- `_maybe_handle_runpod_wedge()` ~L5718: `if status not in AUTO_STOP_DONE:` → `if status not in POD_SAFETY_AUTO_STOP:`. Rationale: a wedged pod on a *paused* task must take the auto-stop fall-through, not the wedge arm — the wedge arm's confirmed-safe path **terminates and relaunches the workload on a fresh pod** (#770), the exact opposite of a user pause. The MF6 argument ("no live work to strand; routing through the wedge arm would only weaken the auto-stop") applies verbatim.

Everything else is inherited with **zero code change**: `decide_pod_safety` (no new class, no new branch), `_escaped_pod_exemptions` (keys on `status_class == "auto-stop-done"`, so keep-running + follow-up exemptions apply to `on_hold` automatically), `_apply_pod_safety_action`, per-pod state files, marker dedup. The inferred-follow-up predicate is already correct for `on_hold`: `set-status <N> on_hold` posts `epm:status-changed`, which is in `_DONE_TRANSITION_KINDS` (~L3889), so at pause time the latest done-transition is newer than any prior `epm:run-launched`/`epm:followup-scope` → `followup_active=False` → stop proceeds; a follow-up signal posted *after* the park correctly re-arms the skip.

## 11. Decision Rationale

**Design fork — chosen: option (a′), auto-stop via a separate pod-safety-layer set (`AUTO_STOP_PAUSED` + derived `POD_SAFETY_AUTO_STOP`), classifying `on_hold` into the existing `"auto-stop-done"` class.**

- **What:** stop (not just alert), decoupled from `AUTO_STOP_DONE`.
- **Why stop over (b) alert-only:** the semantics are unambiguous — the #919 affordance *itself* stops the pod as step 1 of a pause, so the watcher's stop merely completes the user's own explicitly-ordered, already-half-executed action; it is reversible (`pod.py stop`, volume preserved), double-checked (2-miss guard), and exemptable (keep-running tag — which the affordance already tells users to set when the pod must outlive the pause; inferred follow-up per #477). Alert-only would leave the billing running until a human reacts, and would *cost more code* (a new status class + a new `decide_pod_safety` branch + new marker wording), i.e. more coupling for less protection. Rejected.
- **Why decoupled over (a) plain `AUTO_STOP_DONE` membership:** the blast-radius grep (all live consumers of `AUTO_STOP_DONE`: L619 def, L1554 docstring, L3649 `_status_class`, L5718 wedge gate, L6196 docstring, **L12190 `SESSION_RECONCILE_DONE = AUTO_STOP_DONE` — a direct alias**, L15414 docstring; no consumers outside this file + tests) shows exactly one surprising coupling: widening `AUTO_STOP_DONE` would make the session-reconcile pass start auto-stopping live sessions of `on_hold` tasks — scope creep beyond the Goal, contrary to the `blocked`-style conservatism ("user may be live-parked in the session") that plausibly applies to a just-paused task, and it breaks the exact-set pin in `test_session_reconcile_done_set_is_pod_auto_stop_set` (L5668), which exists precisely to force this deliberation. The minimal-coupling variant is taken.
- **Why (c) test-pin-only is rejected:** it documents the silent-billing gap without closing it; the stop path is demonstrably safe (bounded, reversible, exempted), so accepting unbounded billing to avoid a bounded reversible action is the wrong trade.
- **Why the wedge gate is widened too:** without it, a wedged `on_hold` pod routes to the #770 wedge arm, whose confirmed-safe path terminates **and relaunches the workload** — the opposite of a user pause. The MF6 fall-through rationale (docstring ~L6194-6204) applies verbatim to `on_hold`.
- **Why reuse the `"auto-stop-done"` class rather than a new `"auto-stop-paused"` class:** zero changes to `decide_pod_safety` / `_escaped_pod_exemptions` / `_apply_pod_safety_action` / state files; the log line already prints the raw `status=` alongside `class=`, so attribution is preserved; the only inaccuracy (the marker's "(already DONE)") is fixed by a one-line reword. A distinct class buys an honest label at the cost of 3 extra touched functions and a wider test matrix — not worth it.
