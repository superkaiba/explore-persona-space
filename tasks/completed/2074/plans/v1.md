# Plan v1 — #2074: Per-commit split-review for large code-review rounds (workflow-fix)

`kind: infra` · workflow-fix (fingerprint `520e1490b1ce`, origin incident #2054) ·
targets: `.claude/skills/issue/SKILL.md`, `.claude/agents/code-reviewer.md`,
`.claude/agents/code-reviewer-lean.md`, `scripts/workflow_lint.py`

## 1. Goal (verbatim from task)

Wire per-Unit-commit split-review shape into /issue Step 5 code-review dispatch
for rounds with >4 commits (one code-reviewer-lean per commit against that
commit's own diff).

## 2. Problem + incident grounding

- **#2054 Step 5 round 1:** the round-scoped diff was 244 KB / 6,911 lines
  across 5 unit commits. `code-reviewer-lean` — the LAST rung of the
  context-hygiene Class-2 autocompact-thrash ladder — itself thrashed (9 tool
  uses / 385 s / 3 autocompacts), so the ladder ended at the fail-loud
  terminal: a legitimately-sized 5+-commit round produced NO durable
  code-review verdict.
- **The asymmetry:** Step 4b already pre-splits IMPLEMENTATION over >4 code
  deliverables (#1810, SKILL.md:2146-2207) — the units commit separately, and
  the round diff arrives at Step 5 as 5+ unit commits. The review side has no
  symmetric split: the whole round diff goes to ONE reviewer context
  regardless of commit count.
- `.claude/rules/diff-size-budget.md` round-scopes the BRANCH diff down to the
  round, but a large round is still one monolithic body (244 KB in #2054,
  under the 300 KB budget yet fatal to the reviewer context).

## 3. Design

### 3.1 Trigger (Step 5 dispatch, evaluated before the 5a fan-out)

Enumerate the round's unit commits: `git rev-list --no-merges
<round_parent>..HEAD`, with `<round_parent>` resolved exactly as
diff-size-budget.md resolves the round (the implementer round marker/report's
parent; else the previous reviewed round's tip from the latest
`epm:code-review` marker; else `git merge-base origin/main HEAD`).

Split-review mode fires when EITHER:

- **T1 — commit count:** round unit-commit count > 4 (mirrors the Step 4b
  #1810 trigger; the Goal's own threshold), OR
- **T2 — bytes:** round-scoped diff body `git diff <round_parent>..HEAD | wc -c`
  exceeds **100,000 bytes** AND commit count ≥ 2.

Grounding for 100 KB: lean thrashed at 244 KB (#2054); healthy reviewed rounds
run ~36 KB (#722); the task body proposes "e.g. 100KB". 100 KB splits with wide
margin on the failure side, and per-commit sub-reviews are cheap, so an early
split costs little. Source: task #2074 body sketch + incident #2054.

**Stated limitation (single-commit oversized round):** T2 with exactly 1
commit cannot split per-commit — fall back to today's single-reviewer dispatch
(the reviewer's own diff-size discipline: name-status + bounded per-file
reads). Not a new gap: this is the status quo.

### 3.2 Sub-review shape

- Partition the ORDERED round commit list into G contiguous groups,
  `G = min(commit_count, 8)`, count-balanced. The cap at 8 bounds the fleet;
  grouping only engages at >8 commits — for every trigger case this is
  strictly more granular than today's single review.
- Spawn G **`code-reviewer-lean`** sub-reviews IN PARALLEL (one message), each
  micro-scoped. Each brief carries:
  - the literal token `SPLIT-REVIEW SUB-SCOPE` (the spec-side recognition key);
  - its commit range + SHAs + the exact per-group diff command
    (`git show <sha>` for a single commit; `git diff <first>^..<last>` for a
    group);
  - the round-wide `git diff --name-status <round_parent>..HEAD` listing
    (cheap unrestricted form) for cross-commit awareness;
  - the plan symlink path, worktree path + branch, and the implementer
    round-marker reference (kind + version, BY REFERENCE);
  - the verdict FILE path `/tmp/issue-<N>-split-review-r<n>-g<k>.md`, with
    the instruction: write the standard verdict block THERE; do NOT post
    `epm:code-review`;
  - `CONTRACT-BEARING: yes|no` (see 3.3).
- **Why lean per commit (the Goal's own choice):** the split fires exactly in
  the regime where full-spec spawns thrash; a per-group diff (~30-60 KB
  typical) + the 2 KB lean spec (which reads the full spec via windowed seds)
  is the maximum-headroom shape. #2054 shows even lean dies at 244 KB — the
  per-commit split is what fixes the diff size; lean is what keeps the fixed
  overhead low. The lean spec's description gains split-review dispatch as a
  second sanctioned spawn context (one-line edit) so its "spawned only when a
  respawn thrashed" language does not contradict.

### 3.3 Round-level mechanical gates stay round-level

code-reviewer.md Steps 0.5 (marker shape), 0.55 (smoke-architecture), 0.6
(smoke gate), 0.8 (prior concerns), 0.9 (git-provenance) audit the ROUND, not
a commit. They run ONLY in the CONTRACT-BEARING sub-review — the group
containing the round's marker-bearing (final) commit. Every other sub-brief
explicitly skips them; its scope is code correctness of its own commits.

### 3.4 Verdict composition (orchestrator, mechanical)

- Read all G verdict files. A missing/empty file after the sub-agent returned
  is a no-show: respawn ONCE with the same brief (transient tolerance); still
  nothing → the existing Step 5b fail-loud terminal (`epm:failure v1`
  `failure_class: infra` + `status:blocked`). No further ladder: a sub-review
  is already micro-scoped AND lean by construction. Never a smaller-model pin.
- Compose ONE round verdict in the reviewer's own vocabulary:
  FAIL if ANY sub-verdict FAILs; else CONCERNS if any CONCERNS; else PASS.
  Blockers = the UNION across groups, each prefixed `[g<k> <sha-range>]`.
  The orchestrator NEVER upgrades/downgrades a sub-verdict — pure mechanical
  union (same sanctioned class as File-only Codex verdict posting).
- Post as `epm:code-review v<n>` via `post-marker --file`, the note LEADING
  with a provenance line
  `split_review: groups=<G> commits=<m> trigger=<commits|bytes> contract_bearing=g<k>`
  followed by a per-group verdict table. ONE marker per round, exactly as
  today — no new marker kinds, no schema change (note-token convention).
- Downstream ensemble semantics UNCHANGED: the composed verdict IS the Claude
  verdict; Step 5c reconciler vs the Codex verdict, Step 5c-bis strip applied
  to the composed verdict, Step 5d cap rule — all as today.

### 3.5 Codex twin stays UNSPLIT

`codex-code-reviewer` composes on the whole round as today (its own runtime +
context management; #2054's thrash was the Claude-side subagent harness). The
unsplit whole-round Codex view is also the deliberate catching arm for
cross-commit interactions (3.6). No edit to `codex-code-reviewer.md`.

### 3.6 Cross-commit interaction residual (mitigations, stated)

1. every sub-brief carries the round-wide name-status listing;
2. bounded per-file HEAD reads remain available to sub-reviewers (existing
   discipline);
3. the unsplit Codex whole-round review;
4. the CONTRACT-BEARING sub-review audits the implementer report's
   cross-cutting claims (smoke covers all phases, marker shape).

Residual accepted + stated: a bug visible ONLY in the interaction of two
commits reviewed by different Claude sub-reviewers can escape the Claude side;
the Codex whole-round leg is the catching arm. This is the price of bounded
contexts; the alternative (whole-round Claude review) is the demonstrated
no-verdict failure.

### 3.7 Revision rounds

The trigger is re-evaluated per round from that round's own commit set + diff
bytes. Typical revision rounds are small → no split; nothing special to wire.
