# Plan — #2321: Repack the 10 largest prefixes in the HF data repo to recover file-count headroom

### 0.0 TL;DR (plain English)

- **What I'll run:** a checkpointed repack driver on one cheap CPU pod that, prefix by prefix, downloads each prefix's small files, packs them byte-exactly into a few ≤9 MB `.jsonl` shards plus an index, verifies every file round-trips (sha256), and then — in commits that each ADD the shards and DELETE exactly the files those shards contain — removes the originals. A 3-commit probe using throwaway probe files settles first whether the Hub counts files net-of-deletes, without touching any real artifact.
- **What I expect:** ~541,000 of the 1,000,000 file slots freed (repo drops from 999,999 to ~458,500 files, ~46% of cap) for ~13.7 GB downloaded and ~15.8 GB uploaded, zero data loss, and a reader shim in `hub.py` that transparently serves any repacked original path.
- **What would change my mind:** if the probe commit is rejected (the server does not count files net-of-deletes in one push), the whole approach is invalid — the driver STOPs with nothing deleted and this task reports that instead of reaching for deletion. If the measured per-commit wall or download rate is far worse than projected, I shrink commit units / accept a longer wall rather than weaken any safety invariant.

### 3.2 Archive format (v2 codec, `orchestrate/packing.py`)

Reuses the #1739 shape — `<group>.shardNN.jsonl` line-shards ≤ `SHARD_MAX_BYTES = 9_000_000` + a census-keyed manifest — with three generalizations (exactly the gaps named in §2):

- **Record schema (byte-exact, replaces v1's parsed-`doc`):** one line per source file
  `{"src": "<relpath>", "enc": "text"|"b64", "sha256": "<hex of raw bytes>", "bytes": N, "data": "<raw utf-8 text | base64>"}`.
  `enc="text"` iff the bytes round-trip UTF-8 decode/encode identically (JSON stored as its raw *text*, never parsed — byte-exact regardless of producer formatting; ~+3% escaping overhead measured on JSON-like content); else `enc="b64"` (+33%). Empty files legal. Unpack = decode + sha256 assert.
- **All file types accepted** (v1's non-`.json` fail-loud lifted); binary `.npz/.pt/.log/.md/.done` all carry via `b64`.
- **Member cap:** a shard closes at 9 MB **or 4,000 members**, whichever first — so one commit can pair each shard-set with its exact delete set while staying under every observed commit-scale hazard (§3.5).
- **Offsets:** the packer records each member's `(shard, byte_offset, byte_length)` (known at write time) into per-group index files `packed/<group>.indexNN.json` (≤9 MB each, split like everything else) + a small per-prefix `packed/INDEX.json` top index `{group_key: {rel_dir, index_files, shard_files, n_members}}` + `packed/pack_manifest.json` (v2: version 2, per-shard sha256/n_lines/bytes, census, git commit, source repo revision). **Per-member offset addressability: YES** in the recorded index; **HTTP Range reads over the Hub are a documented non-goal for v1 of the shim** — it stages whole ≤9 MB shards via `stage_hub_file`, which for ≤9 MB parts costs at most one shard per member read. Deviation from body scope item 2 ("2 files per prefix"): 2 + ~1 index file per group, forced by the 9.5 MB non-LFS line-split discipline (a single `INDEX.json` for `issue1481`'s 206k members would be ~20 MB → LFS force-route).
- **Group key:** v1 semantics (leaf dir, `/`→`_`), fail-loud collision check kept; on a detected collision, deterministic disambiguation `key + "-" + sha1(rel_dir)[:8]` instead of aborting.
- **Why not tar:** tar (uncompressed) has near-zero byte overhead and offset addressability, but any >10 MB tar is LFS-force-routed → storage-quota-403 exposure on an over-ceiling account + the `_resolve_lfs_upload_repo` atomicity conflict (clarifier finding 4) + a second archive format beside the repo's established one. **Why not parquet:** provably-lossless columnarization would need per-prefix schema work for zero benefit over raw-text records at these sizes. The jsonl pack IS the repo's prescribed recipe (`upload-policy.md` L783-815) and HF's own published recommendation.

### 3.3 Pack-candidate selection (per prefix)

From the walk (§3.4), a file is packed iff ALL of: (a) non-LFS, or in the tier-B set (`issue667_alllayer` + `.npz`); (b) estimated encoded line ≤ 9 MB (text: bytes×1.05; b64: bytes×4/3 — else it would force its own shard over the 10 MB LFS line); (c) not name-shaped as an existing pack/shard convention: `pack_manifest.json`, `*.shard*.jsonl`, `*.manifest.json` + manifest-enumerated parts, `OVERFLOW_POINTER.json` (protects the #1739-v1 and #2119 consumer contracts — repacking those would break their existing resolution paths); (d) not under `<prefix>/packed/` (never repack our own output). ### 3.4 Driver phases (`scripts/issue2321_repack.py`, argparse `--phase` registry + `--import-check` via `orchestrate.argcheck.assert_args_attributes_defined`)

Per-prefix, in the §3.6 order; every phase checkpointed per-unit (JSONL `O_APPEND` records + Hub-state resume predicates); one stdout line per unit (`[repack] <prefix> unit k/K +a -d commit=<sha> elapsed=<s>s`).

1. **`walk`** — new hub helper `list_repo_repofiles_under_path(api, repo_id, path, *, repo_type, revision)` (sibling of `list_repo_entries_complete`, same `_retry_upload`-wrapped paginated scoped `list_repo_tree`, but returning `(path, size, is_lfs, lfs_sha256, blob_id)`), pinned at revision R = repo HEAD at walk time. Emits the prefix census (file set + sizes + integrity anchors).
2. **`download`** — thread pool (default 16 workers, `EPM_I2321_DL_WORKERS`) of `stage_hub_file(..., revision=R)` over the pack-candidate list into container-local `/root/i2321/stage/<prefix>/`; `HF_HUB_DISABLE_XET=1` + `HF_HUB_ENABLE_HF_TRANSFER=0` set inside the script before any `huggingface_hub` import (the small-file-storm rule, gotchas.md FAILURE MATRIX); per-file integrity: non-LFS → git blob sha1 (`sha1("blob <len>\0"+bytes)`) == server `blob_id`; LFS (tier B) → sha256 == server `lfs.sha256`. This makes "compare against the live originals" exact.
3. **`pack`** — `packing.pack_tree_v2` per prefix into `/root/i2321/pack/<prefix>/` (census-keyed idempotent, v1 property preserved).
4. **`verify`** — unpack ALL shards to `/root/i2321/scratch/<prefix>/`, sha256-compare every member against the downloaded originals; 100% or the prefix aborts (no commit phase entered). Report per-prefix verified member counts.
5. **`commit`** — commit-unit composer: greedily bin whole shards into units subject to `ops ≤ 4,500` AND `sum(shard bytes) ≤ 225 MB`; per unit:
   ```python
   ops  = [CommitOperationAdd(f"{prefix}/packed/{s.name}", local_shard) for s in unit.shards]
   dels = sorted({m.src_repo_path for s in unit.shards for m in s.members})   # derived FROM the shards
   assert set(dels) == unit.planned_deletes and all(p.startswith(f"{prefix}/") for p in dels)
   assert not (set(dels) & retained_set) and len(dels) > len(ops)             # net-negative
   drift_check(unit)   # scoped re-list of the unit's source dirs at HEAD: size+blob_id match the census, else ABORT prefix
   api.create_commit(repo_id=DEFAULT_DATASET_REPO, repo_type="dataset",
                     operations=ops + [CommitOperationDelete(p) for p in dels],
                     commit_message=f"[#2321] repack {prefix} unit {k}/{K}: +{len(ops)} shards, -{len(dels)} originals")
   ```
   `create_commit` is called directly (NOT `hub._upload`) so `_filecount_overflow_retry` can never reroute the adds to a different repo than the deletes; wrapped in `retry_transient` (cap rejection is a 4xx → non-transient → propagates to the STOP gate). Any rejection matching `hub._is_file_count_limit_error` → **STOP**: no further commits anywhere, report + exit rc=21 (distinct, dispatcher-routed — not an anonymous crash). ≥20 s sleep between commits (≤180/hr self-cap under the fleet's shared 256/hr working budget). Final per-prefix commit adds `pack_manifest.json` + `INDEX.json` + group indexes (net-positive by ≤ ~100 files, whitelisted — runs only after the prefix's units freed thousands).
6. **`postverify`** — `verify_repo_paths_uploaded` exact-set on `<prefix>/packed/` + scoped re-walk asserting all packed sources are gone; then reap `/root/i2321/{stage,pack,scratch}/<prefix>/` (per-prefix incremental cleanup keeps peak disk ~one prefix).
7. **`remeasure`** — scoped file-count walk of the 10 prefixes after each prefix lands (scope item 7) + one full 402-prefix walk at the end (basis: 227 s measured, #2304) for the headline realized number; report realized-vs-projected per prefix.

**State/reporting:** per-prefix state JSONL uploaded to `issue2321_repack/state/` (non-LFS, always-upload) after each phase; pod-side sentinel `/workspace/logs/issue-2321-results.json` per the pod-side contract (no `task.py` shellouts); the VM orchestrator posts markers.

### 3.5 Atomicity grain (deviation from body letter, invariant-preserving)

The body says "a SINGLE commit per prefix"; `issue1481_conpos_grid` alone would need a ~206,700-op commit — 6.7× the 31,000-op commit #1481 saw killed after >20 min, and 103× `HUB_COMMIT_FILECOUNT_WARN`. The safety invariant the acceptance actually states — *"no file deleted that is not present in the archive committed in the same commit"* — is satisfied exactly by per-unit commits whose delete set is **derived from** the unit's own shards (single source of truth, asserted). The member cap (4,000/shard) exists precisely so a shard's full delete set fits one unit; ~150 data commits + 10 manifest commits + 3 probe commits ≈ **~165 total**. `CommitOperationDelete(path_in_repo, is_folder='auto')` folder-deletes were considered and REJECTED (§11): per-file deletes make delete-set == archived-set true by construction and are immune to the concurrent-writer race a subtree delete has.

## 4. Controls / safety invariants (checkable predicates)

| # | Invariant (assert site) |
|---|---|
| I1 | **User constraint (a):** every `CommitOperationDelete` path is derived from the member records of a shard staged in the SAME `create_commit` (set-equality assert in the unit composer; single source of truth = the shard files). Probe files exempt (not artifacts). |
| I2 | **User constraint (b):** any rejection matching `hub._is_file_count_limit_error` on ANY commit ⇒ global STOP, report, exit rc=21; no deletion can have occurred (HF commits are atomic — rejection leaves the tree untouched). |
| I3 | Every data commit nets ≤ −1 files (`len(deletes) > len(adds)`, asserted pre-call); manifest commits whitelisted only after `freed_so_far > adds`. |
| I4 | No delete path outside the 10 prefixes (`path.startswith(prefix + "/")` assert) and none in the retained set (delete ∩ retained == ∅ assert). |
| I5 | 100% sha256 round-trip per prefix BEFORE its commit phase (phase gate; a single mismatch aborts the prefix). |
| I6 | Download integrity anchored server-side: non-LFS git-blob sha1 == `blob_id`; LFS sha256 == `lfs.sha256`. |
| I7 | Drift guard: per-unit scoped re-list at HEAD; any size/blob_id drift vs the revision-R census ⇒ abort the prefix (dormant prefixes — drift means a live writer; investigate, never delete drifted state). |
| I8 | Overflow routing structurally out of the commit path: direct `create_commit`, plus a preamble assert `EPM_HF_OVERFLOW_ROUTING != "1"`. |
| I9 | Units partition members (no overlap, full cover — asserted); resume is Hub-state-keyed (shards present + sources absent = done), so re-runs cannot double-delete or skip-archive. |
| I10 | Nothing is ever deleted from local staging until `postverify` passes for that prefix. |

## 11. Decision rationale

N/A — no model training (no hyperparameters; the load-bearing constants below get the same What/Why/Source/Alternatives treatment).

- **`SHARD_MAX_BYTES = 9_000_000`** — keeps every shard on the quota-immune non-LFS path. Source: `scripts/issue1739_pack.py` L50 + upload-policy.md L806 (>10 MB LFS force-route). Alternative (larger shards → LFS): rejected, quota-403 exposure.
- **Member cap 4,000/shard + ops ≤4,500/commit** — one shard's delete set fits one commit (strict same-commit invariant at shard grain), under the 10k/dir server cap (#658, hub.py L1144) and 7× under #1481's 31k-op kill; 2.25× the `HUB_COMMIT_FILECOUNT_WARN=2_000` advisory (hub.py L1162) is accepted because deletes carry no payload — probe-measured, ramp-down to 2,000 if slow. Alternative (one commit per prefix, body letter): rejected on #1481 evidence, deviation recorded §3.5.
- **Adds ≤225 MB (~25 shards)/commit** — Source: ungrounded — needs smoke-test (probe ramp); HF docs recommend 50-100 files/commit ([repositories-recommendations](https://huggingface.co/docs/hub/repositories-recommendations)).
- **text/b64 records over tar** — byte-exactness for heterogeneous producers (+~3% text overhead vs v1's non-byte-exact re-serialization; +33% b64 only for binary), no new LFS, repo-convention continuity, atomicity-safe. Source: body scope item 1 + clarifier finding 4 + upload-policy.md L783-815. Alternatives: tar (LFS 403 + `_resolve_lfs_upload_repo` atomicity conflict + second format), parquet (per-prefix schema work, losslessness burden).
- **Per-file deletes, never folder deletes** — delete-set == archived-set by construction; immune to the concurrent-new-file race. Source: clarifier note (b) caution + I7 design. Alternative (`is_folder=True`, 1 op/subtree): rejected — saves ~100 commits at the cost of exactness.
- **Tier split A+B, C declined by default** — slots-per-byte: A ≈ 55k slots/GB-moved, B ≈ 8k, C ≈ 0.4-0.5k. Source: inventory JSON (measured). Alternative (all-LFS repack): 411 GB moved, MooseFS quota violation, storage duplication — rejected.
- **`issue1090_partial` first** — cheapest true semantics test (0.025 GB, 0 LFS, 0 consumers). Source: clarifier note (a) arithmetic; deviation from body letter recorded §3.6.
- **Commit pacing ≥20 s (≤180/hr)** — fleet-shared budget headroom. Source: brief's 256/hr working figure; HF publishes no number (verified [rate-limits](https://huggingface.co/docs/hub/rate-limits)).
- **Download workers 16** — 2.7× `stage_hub_prefix`'s default 6 (hub.py L2728), justified by a dedicated pod + resolver self-pacing; env-tunable. Source: hub.py default + A8; pilot-gated.
- **Tool-behavior claims:** `create_commit`/`CommitOperationDelete` shapes — Source: `inspect.signature` on installed 0.36.2 (this session); `_is_file_count_limit_error` semantics — Source: hub.py L1327-1341 read; xet/hf_transfer disables — Source: gotchas.md FAILURE MATRIX entry.
