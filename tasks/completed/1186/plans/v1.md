## 4. Design

### 4.1 The shared iterator `_hf_tree_pages`

Placement: immediately after `_hf_tree_get` (after l.5378), beside the primitive it composes. A small event NamedTuple keeps the project's `_TreeProbeResult` style:

```python
class _TreePageEvent(NamedTuple):
    """One event from `_hf_tree_pages`: zero or more kind='page' events
    (entries = that page's JSON tree entries), then EXACTLY ONE terminal
    event — kind in {'exhausted', 'cap', 'not_found', 'indeterminate'}.
    `note` is non-empty only for kind='indeterminate' (the `_hf_tree_get`
    diagnostic); callers own every human-facing string for the other
    terminal kinds (the deliberate per-check note asymmetry: check 25 says
    "(no such revision)", checks 30/32 say "no such revision/path")."""

    kind: str            # "page" | "exhausted" | "cap" | "not_found" | "indeterminate"
    entries: list[dict]  # populated only for kind="page"
    note: str            # populated only for kind="indeterminate"


def _hf_tree_pages(
    repo_id: str, repo_type: str, sha: str, path: str, *, recursive: bool = True
) -> Iterator[_TreePageEvent]:
    """Shared bounded Link-header self-pagination over the Hub tree endpoint
    (checks 25 / 30 / 32; the #733 contract in ONE place so a 4th consumer
    inherits it). Reads the module caps directly (`_HF_PROBE_MAX_PAGES`,
    `_HF_PROBE_DEADLINE_S`, `_HF_PROBE_TIMEOUT_S`); per-page 429/5xx retry
    stays inside `_hf_tree_get`. Invariants:
    - headers are built BEFORE the URL (`_hf_build_headers` imports
      `huggingface_hub.utils`, making the lazy `constants` submodule
      attribute-reachable — belt to `_hf_tree_url`'s own braces, #1186);
    - `params` are sent on the FIRST page only (the Link rel="next" URL
      already carries them);
    - `exhausted` is checked BEFORE the page/deadline cap, so a listing
      whose final page lands exactly on the cap is exhaustive, not capped;
    - the deadline is strict `>` from just before the first GET.
    """
    headers = _hf_build_headers()
    url = _hf_tree_url(repo_id, repo_type, sha, path)
    params: dict | None = {"recursive": recursive}
    started = time.monotonic()
    pages = 0
    while True:
        res = _hf_tree_get(url, params=params, headers=headers, timeout_s=_HF_PROBE_TIMEOUT_S)
        if res.status == "not_found":
            yield _TreePageEvent("not_found", [], "")
            return
        if res.status == "indeterminate":
            yield _TreePageEvent("indeterminate", [], res.note)
            return
        yield _TreePageEvent("page", res.entries, "")
        pages += 1
        if res.next_page is None:
            yield _TreePageEvent("exhausted", [], "")
            return
        if pages >= _HF_PROBE_MAX_PAGES or time.monotonic() - started > _HF_PROBE_DEADLINE_S:
            yield _TreePageEvent("cap", [], "")
            return
        # The Link rel="next" URL already carries the params; do not re-send them.
        url, params = res.next_page, None
```

Load-bearing details:

- **`_hf_tree_get` / `_hf_build_headers` / `_hf_tree_url` are called as plain module-global names** so `monkeypatch.setattr(verify_task_body, "_hf_tree_get", ...)` — the seam EVERY existing probe test uses (`_stub_tree`, l.1714; audit_claim l.77) — keeps intercepting. No `from`-import aliasing, no default-arg binding.
- **Module constants read late-bound** (as the three loops do today), so a test monkeypatching `_HF_PROBE_DEADLINE_S` / `_HF_PROBE_MAX_PAGES` observes the patch. No cap parameters on the signature — one place to change the contract (Decision Rationale §11-2).
- **Lazy-start note:** as a generator, `_hf_build_headers()` runs at first `next()` rather than at call. All three callers immediately iterate (a `for` loop over the generator), so this is unobservable; exceptions from headers/URL construction propagate to the same caller frame as today.
- The `started` clock begins after headers+URL construction (today check 25/30/32 start it after headers) — a microseconds-scale shift, unobservable (deadline is 12 s wall over network GETs).
- **Typing import:** add `from collections.abc import Iterator` if the module lacks it (ruff I/UP will place it).

### 4.2 Partition-equivalence proof (why each caller mapping is behavior-identical)

The generator's terminal partition vs the current loops, case by case, per final-page state (E = `next_page is None`, C = `pages >= MAX or elapsed > DEADLINE`):

| Final-page state | check 25 today (break at l.7045–7050, post-loop l.7053) | checks 30/32 today (l.7626–7629 / l.7989–7992) | `_hf_tree_pages` |
|---|---|---|---|
| E, ¬C | break; `next_page is None` → fall through → exhausted | `return ok` (checked first) | `exhausted` |
| E, C (boundary) | break (E fires in the `or`); post-loop `next_page is None` → **exhausted** | `return ok` — the E check PRECEDES the cap check → **exhausted** | `exhausted` (checked first) |
| ¬E, C | break; post-loop `next_page is not None` → **cap** | cap `return skip` | `cap` |
| ¬E, ¬C | continue to next page | continue | continue |
| 404 any page | `return skip` immediately | `return skip` | `not_found` terminal |
| indeterminate any page | `return skip` w/ `res.note` | `return skip` w/ `res.note` | `indeterminate` terminal w/ note |
| keyword match on any page incl. the cap page (25 only) | `return pass` from the entries scan, which runs BEFORE the `pages += 1`/cap check | n/a | the `page` event is yielded BEFORE the terminal event, so the caller's scan still early-returns `pass` |

Identical partitions in every cell. Check 25's `res = None` sentinel + post-loop `res is not None` guard (l.7029, l.7053) is dead-code-equivalent (the loop always executes ≥1 GET) and disappears.

## 11. Decision Rationale

`N/A — no training hyperparameters`

1. **Iterator shape: generator yielding typed events (`_TreePageEvent` NamedTuple), not a callback or a result-object accumulator.**
   - *What:* `_hf_tree_pages` yields ≥0 `page` events then exactly one terminal event (`exhausted`/`cap`/`not_found`/`indeterminate`).
   - *Why:* the three callers' aggregation semantics differ (early-return match scan vs count vs basename set) and their verdict/note strings differ — a generator lets each keep its own `for`-loop body verbatim while the page/deadline mechanics live once. A callback inverts control and obscures early return; a collect-everything result object would break check 25's early-`pass` (it must stop GETting on first match). The typed NamedTuple mirrors the module's existing `_TreeProbeResult` style (l.5298) over anonymous tuples.
   - *Source:* in-repo precedent `_TreeProbeResult` (scripts/verify_task_body.py:5298) + the deliberate per-caller-mapping design note in its docstring (l.5301–5305).
   - *Alternatives:* bare `(kind, payload)` 2-tuples (fewer lines, less self-documenting); `max_pages`/`deadline_s` parameters (rejected, §11-2).
2. **Caps read from module constants directly; no cap parameters on the signature.**
   - *What:* `_HF_PROBE_MAX_PAGES` / `_HF_PROBE_DEADLINE_S` / `_HF_PROBE_TIMEOUT_S` read late-bound inside the generator.
   - *Why:* byte-identical to how all three loops read them today (l.7047–7048, 7628, 7991), keeps them monkeypatchable per-test, and keeps ONE knob for the whole contract — the task's "a 4th consumer inherits it" requirement. Parameterizing would create per-caller divergence surface, the exact thing being removed. (`recursive: bool = True` is kept as the only parameter beyond the URL identity because it is part of the REQUEST, not the cap contract.)
   - *Source:* current loop bodies (scripts/verify_task_body.py:7045–7048, 7626–7629, 7989–7992); task body constraint "each check keeps its own page/deadline caps" — they share one cap set today, and this preserves that.
   - *Alternatives:* explicit `max_pages=_HF_PROBE_MAX_PAGES` kwargs (deferred until a consumer actually needs a different cap — check 23 would, and it is out of scope per §4.5).
3. **Exhausted-before-cap precedence inside the generator.**
   - *What:* `if res.next_page is None: → exhausted` precedes the cap predicate.
   - *Why:* all three current loops resolve the E∧C boundary to exhausted (§4.2 row 2) — checks 30/32 by statement order (l.7626 before l.7628), check 25 by the post-loop `next_page is not None` test (l.7053). Cap-first would flip a `fail`/`ok` to `skip` on cap-boundary listings — a behavior change.
   - *Source:* scripts/verify_task_body.py:7626–7629 (check 30), 7989–7992 (check 32), 7053–7055 (check 25); pinned by new test 3.
   - *Alternatives:* none viable — any other order changes behavior.
4. **`_hf_tree_url` fix form: `import huggingface_hub.constants` (statement swap), not `from huggingface_hub.constants import ENDPOINT`.**
   - *What:* one-token diff at l.5320; the `huggingface_hub.constants.ENDPOINT` attribute read stays byte-identical.
   - *Why:* minimal diff; keeps the read dynamic (any patch of the module attribute is still observed); verified fresh-process this session on hf_hub 0.36.2. The safe headers-before-URL ordering ALSO moves into the shared iterator (§4.1), mirroring the check-32/check-23 precedent — belt and braces, so neither protection depends on the other.
   - *Source:* check-32 fix precedent scripts/verify_task_body.py:7965–7970 (#1016, commit 389201de49); check-23 ordering l.5436–5438; live verification this session (`import huggingface_hub.constants` → `ENDPOINT` reachable fresh-process; bare import → AttributeError).
   - *Alternatives:* `from huggingface_hub.constants import ENDPOINT` (equally correct, slightly larger diff); `import huggingface_hub.utils` inside `_hf_tree_url` (works but imports more than needed and encodes the masking route rather than the direct dependency).
5. **Fresh-process test mechanics: `subprocess.run([sys.executable, "-c", ...])` with the test file's own loader shape + a non-vacuity `sys.modules` precondition.**
   - *What:* §4.6 test 6.
   - *Why:* a fresh interpreter is the ONLY faithful reproduction of "lazy submodule not yet attribute-reachable" (in-process `sys.modules` surgery risks half-initialized package state); the precondition assert makes a future masking import fail the test loudly instead of passing vacuously; no network is involved because `_hf_tree_url` is pure string building. `sys.modules` registration before `exec_module` is REQUIRED (the `@dataclass` at l.863 dereferences `sys.modules[cls.__module__]` — crash reproduced this session without it).
   - *Source:* subprocess precedent tests/test_shared_vm_thread_caps.py:637; loader shape tests/test_verify_task_body.py:29–33.
   - *Alternatives:* `-I` isolated mode (unneeded — fresh `sys.modules` comes free; `-I` only complicates path handling); in-process `del sys.modules["huggingface_hub"]` (rejected: package teardown is not a supported state and could poison sibling tests).
6. **Check 23 out of scope.** *What/Why/Source:* §4.5 — no loop to deduplicate, deliberate single-page semantics (l.5280, l.5421 "page 1"), already-safe ordering (l.5436–5438); folding it in would be a second behavioral variable. *Alternatives:* a `max_pages=1` parameterization (deferred; nothing gained today).
