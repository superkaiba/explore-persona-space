### 3.2 The operational definition of "external" (grounded in #779's real marker anatomy)

Measured facts (verified 2026-07-02 on `tasks/followups_running/779/events.jsonl`):

- `post_event` defaults `by="unknown"` (task_workflow.py:2180); `task.py post-marker` CLI defaults `--by unknown` (scripts/task.py:1269). Distribution in #779: `unknown` 210, `codex_task` 52, `code-reviewer` 22, `experiment-implementer` 20, `task.py` 14, `reconciler` 12, `poll_pipeline` 7, `backends.router` 6, `user` 3, `issue779` 3, others ≤3.
- The PM-chat audit markers AND the session's own markers are both `kind: epm:progress, by: "unknown"` — e.g. the 16:12:37Z audit (`{"ts":"2026-07-02T16:12:37Z","kind":"epm:progress","version":66,"by":"unknown"}`, note begins `# Audit: #779 3-arm ablation CPU phases…`) vs the session's own 17:10:52Z milestone (`by: "unknown"`, note begins `milestone: sycophancy DONE 16:41:54Z…`). **The `by` field cannot discriminate external from self.**
- The external markers self-identify in note PROSE: `# Audit:`, `AUDIT ROUTING NOTE`, `METHOD SUGGESTION … (user-raised, PM-chat)`, `SCOPE RESTORE REQUEST (user-raised, PM-chat…)`, `COVERAGE-MAP ADDITIONS (user question-map, PM-chat…)`, `DEDUP NOTE (PM-chat cross-task audit)`, `TARGET-CONSTRUCTION CHECK (user-raised, PM-chat)`, `AMENDMENT … (user directive, PM-chat)`, `AMENDMENT 2 … (user-raised, PM-chat)`.

Therefore the definition is TWO-LAYER:

- **Mechanical layer (helper — over-approximates, never classifies):** a *candidate* is any event in the bounded window whose kind is not in a curated machine/lifecycle exempt set, whose `by` is not a known machine poster, whose note is non-empty, and which is not itself a breadcrumb-shaped note. False positives (the session's own progress notes) cost one first-line read each; false negatives are the failure mode being closed, so the set errs inclusive.
- **Judgment layer (orchestrator — the LLM classifies):** *external* = a candidate this session did not itself post — decided from session context, and from the in-the-wild signatures above ("PM-chat", "user-raised", "user directive", "# Audit", "AMENDMENT", "SCOPE RESTORE", …). **Fail-toward-triage:** a successor/crash-recovery session that cannot attribute a candidate treats it as external. *Advisory/directive* = it requests action or bears on the pending dispatch.

### 3.3 The helper (task_workflow.py)

Placement: immediately after `stage_dispatch_should_skip` (ends task_workflow.py:1381), before the `# ─── Same-issue follow-up label grouping (#894)` divider at line 1384 — it shares that neighborhood's breadcrumb-parsing conventions.

```python
# Machine-posted / lifecycle-bookkeeping kinds that never carry cross-session
# advisory content — excluded from pre-dispatch triage candidates. Anything
# NOT listed is a candidate (over-approximation by design: a false positive
# costs one first-line read; a false negative is the #779 failure mode).
TRIAGE_EXEMPT_KINDS = frozenset({
    "epm:status-changed", "epm:step-completed", "epm:backend-selected",
    "epm:codex-task-spawned", "epm:codex-task-completed", "epm:codex-task-failed",
    "epm:pod-provisioned", "epm:pod-terminated", "epm:pod-stopped",
    "epm:run-launched", "epm:run-finished",
    "epm:upload-verification", "epm:merged", "epm:methodology-doc-generated",
    "epm:workflow-fix-task-filed", "epm:workflow-fix-applied",
    "epm:workflow-fix-failed", "epm:workflow-fix-candidate",
    # Session-pipeline review/lifecycle verdict kinds — structurally posted by
    # THIS task's own planner/review/implementation loop, never the vehicle for
    # a cross-session advisory (fact-check on #779: including these halves the
    # per-dispatch read load, 30 → 20 candidates, with zero externals lost).
    "epm:code-review", "epm:code-review-codex", "epm:review-reconcile",
    "epm:experiment-implementation", "epm:concern-raised",
    "epm:concern-addressed", "epm:concern-deferred",
    "epm:interp-critique", "epm:interp-critique-codex",
    "epm:clean-result-critique", "epm:clean-result-critique-codex",
    "epm:plan", "epm:plan-approved", "epm:plan-verify", "epm:consistency",
    "epm:clarify", "epm:clarify-answers", "epm:test-verdict",
    "epm:smoke-architecture-check",
})

# `by` values identifying MACHINE posters (pollers, routers, CLI shims).
# NOTE: `by` is UNRELIABLE for humans/sessions — post_event defaults it to
# "unknown", and on #779 both self- and PM-chat-posted markers carried
# by="unknown" — so this set only strips known machine identities; it never
# claims to identify externality (that is the orchestrator's judgment call,
# SKILL.md § Pre-dispatch external-marker triage).
TRIAGE_MACHINE_BY = frozenset({
    "poll_pipeline", "task.py", "backends.router", "backends.gcp",
    "backends.slurm", "backends.slurm_monitor", "backends.selector",
    "autonomous-gate", "codex_task", "task_state shim",
})
# (Fact-checked 2026-07-03: backends.router/gcp/slurm post markers at
# router.py:4482 / gcp.py:3895 / slurm.py:2246; slurm_monitor.py:582,645 and
# selector.py:672 do too; `backends.runpod` posts nothing today — omitted.)


# Compute-launch marker kinds — ALWAYS close the triage window. epm:run-launched
# is the RunPod/experimenter launch record; epm:cluster-launched is what the
# default GCP/SLURM lanes post (SKILL.md Step 6b marker trail; #779's own window
# contains one at 14:56:21Z, by backends.gcp).
TRIAGE_LAUNCH_KINDS = frozenset({"epm:run-launched", "epm:cluster-launched"})

# The auditable triage-record line. A dispatch record carrying this line is
# DUTY-BOUND (it performed the triage) and closes the window; a note that IS
# a triage record is also excluded from candidates.
TRIAGE_LINE_PREFIX = "external-markers triaged:"


def triage_candidates_since_last_dispatch(
    events: list[dict],
    *,
    exempt_kinds: frozenset[str] = TRIAGE_EXEMPT_KINDS,
    machine_by: frozenset[str] = TRIAGE_MACHINE_BY,
    launch_kinds: frozenset[str] = TRIAGE_LAUNCH_KINDS,
) -> list[dict]:
    """Return pre-dispatch triage candidates since the latest DUTY-BOUND
    dispatch record.

    THE BOUNDARY MATCHES THE TRIAGE DUTY SURFACE (Phase-2 critique): the
    window opens AFTER the most recent event that is either (i) a
    compute-launch marker (kind in ``launch_kinds`` — ``epm:run-launched``
    or ``epm:cluster-launched``), or (ii) ANY event whose note contains the
    ``external-markers triaged:`` line (a triaged compute breadcrumb, or
    the adjacent ``epm:progress`` triage note the pod/backend-launch form
    posts). When no such record exists the window is the whole list (task
    start). A NON-compute breadcrumb (review / analyzer / verifier stages)
    never closes the window — those dispatches carry no triage duty, so
    they cannot orphan an advisory (Statistics-lens Must-Fix); an
    UNTRIAGED compute breadcrumb (pre-fix or concurrent session) also does
    not close it (fail-toward-triage; Methodology-lens residual).
    Within the window an event is a candidate unless: kind in exempt_kinds,
    ``by`` in machine_by, the note is empty/absent, the note is itself
    breadcrumb-shaped (lstripped note begins ``"stage-dispatch "`` — same
    detection as ``stage_dispatch_should_skip``), or the note contains the
    triage line (it is a triage record, not an advisory). Chronological
    order preserved. Deliberately over-approximates — it ENUMERATES for
    LLM-side triage and never classifies externality (``by`` cannot:
    default "unknown").
    """
```

Implementation sketch (~25 lines): single reverse scan to find the boundary index (launch kind OR triage-line-carrying note); single forward pass over `events[boundary+1:]` applying the five exclusion rules; return the surviving dicts.

## 11. §11 Decision Rationale

**N/A — no training hyperparameters** (kind: infra; no model is trained).

- **Helper + prose, not prose-only.** *What:* a pure `task_workflow` helper does the bounding/enumeration; SKILL.md prose does the judgment. *Why:* prose-only "scan events.jsonl" is exactly the instruction class #779 skipped; a mechanical one-liner with printed output is checkable by the code-reviewer and replayable in tests. *Source:* the sibling precedent `stage_dispatch_should_skip` ("run the pre-dispatch one-liner above — do not eyeball the scan", SKILL.md 4970–4972) + task #889 body's explicit weigh-request. *Alternatives:* prose-only (rejected: unenforceable, unreplayable); a full mechanical external-classifier (rejected: `by: unknown` makes it impossible on the measured record — a false-negative-prone regex classifier would license skipping reads).
- **Over-approximating enumerator; LLM-side classification.** *What:* the helper returns candidates, never "external" verdicts. *Why:* measured — `by` cannot discriminate (§3.2); note-prose signatures are conventions, not contracts, so a code-side regex would silently rot. Model-call-vs-code paradigm: judgment to the LLM, bounding to code. *Source:* #779 marker census (this session). *Alternatives:* regex `advisory_signature` flag on candidates (rejected: false negatives invite skip-reading; kept as a possible future nicety once emitter-side `--by` conventions exist).
- **Window boundary = the DUTY surface: compute-launch markers (`epm:run-launched` + `epm:cluster-launched`) OR a record carrying the `external-markers triaged:` line.** *What:* the window closes only at records that either ARE a compute launch or PROVE the triage duty ran. *Why (revised per Phase-2 critique):* the v2 boundary (any breadcrumb OR run-launched) had two defects — (1) it omitted `epm:cluster-launched`, the launch record the default GCP/SLURM lanes post (SKILL.md Step 6b marker trail; #779's own window has one at 14:56:21Z, by `backends.gcp`), so GCP launches never advanced the window (Methodology-Claude Must-Fix); (2) it let NON-compute breadcrumbs (review/analyzer stages — which carry no triage duty) close the window, silently orphaning an advisory posted before a review round from every future duty-bound window (Statistics-Codex Must-Fix). The triage-line criterion additionally means an untriaged pre-fix/concurrent-session compute breadcrumb doesn't close the window (fail-toward-triage; Methodology-Codex residual) — only a record that performed the duty ends the obligation. *Source:* SKILL.md Step 6b/6d.1 marker trail + the #779 census + the Phase-2 critic ensemble. *Alternatives:* any-breadcrumb-or-run-launched (rejected: the two defects above); a compute-stage-name denylist for breadcrumbs (rejected: stage vocabulary drifts; the triage line is self-declaring and stable); any-marker-since-last-own-post (rejected: "own" is unknowable post-crash). *Cost:* previously-triaged markers on a task whose prior compute dispatch predates the fix re-enumerate once (their boundary record carries no triage line) — one extra read per marker, once, then the first post-fix triage line re-bounds the window.

- **Record format: one free-text line in the existing breadcrumb note.** *What:* `external-markers triaged: N applied / M deferred (reasons)`. *Why:* matches the task body's requested format verbatim; the breadcrumb is already free-text `epm:progress` (no schema change ⇒ non-architectural); grep-auditable (`grep 'external-markers triaged'`). *Source:* task body + workflow.yaml 1849. *Alternatives:* new marker kind `epm:external-triage` (rejected: schema addition ⇒ architectural review for no added auditability); structured `key=value` fields (rejected: reasons are prose).
