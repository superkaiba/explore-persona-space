## Method delta (design decision)

- (l) "Validity-domain transfer" scopes to boundaries the instrument's docs
  DECLARE, with an explicit N/A escape when none are declared — the #1345 device
  axis was undeclared, so folding it into (l) contradicts (l)'s own scope
  sentence ("(l) asks whether the new DATA REGIME crosses a boundary the reused
  CODE itself declares").

  can still be internally device-split (#1345's was: the split was BETWEEN two
  preps, each individually device-clean).
- The task body's own proposal: "a DEVICE-DOMAIN arm ... (sibling of
  validity-domain check (l))" — a sibling, i.e. a new peer check.

>   reaches a code path — a union / grid / aggregation stage, a fresh branch —

>   device class (a CPU smoke validates nothing about CUDA placement), through
>   the SAME entrypoint + defaults production will use, and must reach the

>   where #1345 crashed. Scope split vs siblings: (i)(2) checks the device is
>   PARAMETRIZED (throughput) — a fully parametrized core can still be
>   internally device-split; (l) checks boundaries the instrument DECLARES —
>   the device axis is typically UNDECLARED, so (l)'s N/A escape does not
>   cover it. (#1345: Fellows job 17912 FAILED after 2h33m — AFTER all 140
