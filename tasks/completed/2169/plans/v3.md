### §3.1 What "named" means — the bounded glob bar

A committed PNG is **named** by the body when either:

1. its basename stem appears in the body as an exact substring (the pre-existing test, unchanged); or
2. **(NEW)** the body contains a backtick-quoted token containing `*` whose basename component `fnmatch`-matches the stem or the stem + `.png`.

The glob bar is bounded three ways so it cannot become a blanket escape:

- **Backticks required.** Only `` `…*…` `` tokens count. Markdown emphasis (`*text*`) and stray prose asterisks are excluded by construction.
- **Basename component only.** A path-shaped glob is reduced to its last `/`-separated component before matching. `` `figures/issue_2061/f1_delta_scatter_*` `` → matches (component `f1_delta_scatter_*`); `` `figures/issue_2061/*.png` `` → does not (component `*.png` fails the next bound).
- **≥3 literal characters before the first `*`.** `` `f*` ``, `` `*` ``, `` `*.png` `` exempt nothing.

The naming paragraph — which the per-unit family's exemption-phrase proximity test uses — is the blank-line-delimited paragraph containing the exact stem, or, for a glob name, the paragraph containing the matching glob token.

**Why this is required, not a nicety.** Verified against the real artifacts, not assumed: at #2061's body-cited SHA `5d001092782beadab91efd81eb4d785741eeeac8`, `figures/issue_2061/` holds 8 `f1_delta_scatter_*.png` files. The *corrected* body embeds exactly one (`f1_delta_scatter_dpo_rlvr_context`) and dispositions the other seven collectively as "the seven `` `f1_delta_scatter_*` `` siblings — **not embedded**: …" (`tasks/reviewing/2061/body.md:61`). Under an exact-stem-only bar those 7 stems are absent from the body, so the widened check would fire 7 class-C WARNs on the body that already fixed the problem — inverting acceptance criterion (b). Collective family disposition is also what the check-20 conciseness caps push bodies toward, so this is the common shape, not an edge case.

### §3.2 The two-bar decision (carried forward from v1, critic-endorsed)

The per-unit family keeps its stricter *phrase* bar (a bare naming still WARNs class B). The widened superset uses the looser *mention/glob* bar: naming the figure, individually or by bounded family glob, silences it.

Rationale: applying the phrase bar to every figure name in the corpus would fire on ordinary prose that names a figure without a disposition idiom (a `## Reproducibility` artifact list, a Methodology reference), converting a targeted backstop into background noise. The disclosed cost is a real false negative — a figure mentioned in passing but never embedded or dispositioned goes unflagged. That is the accepted direction for a WARN-tier backstop where Lens 11 and Lens 13 remain the substantive owners, and it is consistent with the already-pinned accepted false negative in `test_orphan_multi_stem_one_paragraph_phrase_exempts_both:1550`.

### §3.3 Disclosed behaviour change to the per-unit classes

v1 promised classes A/B byte-identical. v2 cannot keep that promise literally, and says so: extending the glob bar to the per-unit family moves a glob-named per-unit companion out of class A (orphan, which has no exemption path at all) into the class-B/phrase-bar branch, where a co-located "not embedded" idiom exempts it. This is **loosening only** — strictly fewer and weaker WARNs, never a new WARN and never a FAIL — so it is safe under the forward-only rule.

The alternative (glob bar for class C only) was rejected as incoherent: it would mean one disposition sentence exempts a body's `f1_*` figures but not its `f2_percell_*` figures, which is a defect that would itself become the next workflow-fix task. §5 test 9 pins the new routing in both directions.

Held constant, deliberately:

- **Scope stays `*.png`.** Sibling `.pdf` / `.meta.json` artifacts under `figures/issue_<N>/` are never candidates — at #2061's SHA those are the majority of the directory's entries, so this single scoping decision removes most of the potential noise.
- **Grade stays WARN.** `passed` is never set `False`; `is_warn` is `True` whenever any class fires.
- **Check name stays `"per-unit companion figures embedded"`.** The name is a parsed contract (pinned as `_PER_UNIT_ORPHAN_CHECK`, grepped by downstream review prose). Renaming is a separate, out-of-scope change; the mildly-stale name is covered by an updated docstring.
- **PASS detail keeps the substring `no orphaned per-unit figures`** (asserted by two existing tests, `tests/test_verify_task_body.py:1400` and `:1598`); the widened scope is described in appended text.
- **Class separation is greppable.** Class A carries neither token; class B carries `companion-named-not-embedded`; class C carries `committed-figure-unmentioned`. No detail may carry a token for a class that did not fire.
- **Lens pointers.** Class A/B keep their `Lens 11` pointer (asserted by existing tests). Class C cites **Lens 13 — planned-vs-actual coverage** (`.claude/rules/clean-result-critic-lens-reference.md:1198`), the lens that caught the #2061 miss.
