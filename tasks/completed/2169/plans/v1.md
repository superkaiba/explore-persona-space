# Plan v1 — Generalize `verify_task_body.py` check 31 to any committed-but-unmentioned issue figure

**Task:** #2169 · **Kind:** `infra` · **Parent:** #2061 · **Workflow-fix target:** `scripts/verify_task_body.py`

---

## §0.0 TL;DR

Check 31 (`check_orphaned_per_unit_figures`) today only looks at committed PNGs whose basename stem matches `per[-_]?(context|unit|cell|pair)`. On #2061 a plan-named headline figure, `figures/issue_2061/f5_arm_agreement.png`, was committed at a body-cited SHA, embedded nowhere, and named nowhere — and check 31 stayed silent because `f5_arm_agreement` does not match that pattern. The clean-result-critic caught it only by hand (Lens 13, planned-vs-actual coverage).

This plan widens check 31's scan from the per-unit family to **every** committed `figures/issue_<N>/*.png` at a body-cited SHA, adding one new WARN class for the widened superset while leaving the two existing per-unit classes byte-identical in behaviour. Everything stays WARN-grade, so no grandfathered v3/v2/v4 body can be newly hard-FAILed.

**Change my mind:** if the widened class A produces a large volume of WARN entries on real corpus bodies — concretely, if the §7 corpus dry-run shows a median of more than ~5 newly-WARNed figures per already-promoted clean-result body — the widening is net noise at WARN tier and should be narrowed (e.g. restricted to figures the body's own `## Methodology` / plan names) before landing. The corpus dry-run in §7 is what settles this; it runs before the code-review gate, not after.

Estimated GPU-hours (total): 0 — pure Python + pytest on the VM; no pod, no model, no API calls, no network. Total wall-clock estimate: under 30 minutes of agent time, dominated by one full run of `tests/test_verify_task_body.py`.

## §1 Goal

Make it mechanically impossible for a committed figure at a body-cited SHA to pass `verify_task_body.py` while being neither embedded in the body nor accounted for in prose — regardless of its filename.

Not in scope: changing any check's grade, renaming the check, touching check 38 (which owns the "markdown-linked in the v4 `## Results` layer" WARN), or altering the clean-result SPEC.

## §3 Design

One classifier change plus one new detail section. No new subprocess calls (the tree enumeration is already unfiltered, so the widened scan reads paths already fetched).

`_classify_per_unit_png` is renamed to `_classify_committed_issue_png` and returns a fourth outcome:

| Committed PNG at a body-cited SHA | Per-unit stem? | Body state | Outcome |
|---|---|---|---|
| any | any | embedded in any image-URL form | clean (unchanged) |
| any | any | markdown-linked in the v4 `## Results` layer | clean — check 38 owns it (unchanged) |
| any | yes | stem in body + exemption idiom in its paragraph | clean (unchanged) |
| any | yes | stem in body, no exemption idiom | class B `companion-named-not-embedded` (unchanged) |
| any | yes | stem absent from body | class A orphan (unchanged) |
| any | **no** | stem present anywhere in body | **clean — NEW** |
| any | **no** | stem absent from body | **class C `committed-figure-unmentioned` — NEW** |

**The two-bar decision (the one judgement call in this plan; flagged for the critic).** The per-unit family keeps its stricter *phrase* bar (a bare mention still WARNs class B — the #1426/#1510 incident evidence justified that). The widened superset uses the looser *mention* bar: naming the figure anywhere in the body silences it.

Rationale: (a) both bars satisfy acceptance criterion (b), because #2061's disposition paragraph carries the literal phrase "not embedded", so a mention-bar and a phrase-bar both go silent once `f5_arm_agreement.png` is added to that paragraph; (b) the file's own stated convention for WARN-tier backstops is precision over recall — Lens 11 and Lens 13 remain the substantive owners; (c) applying the phrase bar to every figure name in the corpus would fire on ordinary prose that mentions a figure without a disposition idiom (e.g. a `## Reproducibility` artifact list), converting a targeted backstop into background noise. The cost is a real, disclosed false-negative: a figure mentioned in passing but never embedded or dispositioned goes unflagged. That is the accepted direction, consistent with the already-pinned accepted false-negative in `test_orphan_multi_stem_one_paragraph_phrase_exempts_both`.

Held constant, deliberately:

- **Scope stays `*.png`.** Sibling `.pdf` / `meta.json` artifacts under `figures/issue_<N>/` are never candidates — this alone removes most of the potential noise, and the task body scopes the ask to `*.png`.
- **Grade stays WARN.** `passed` is never set `False`; `is_warn` is `True` whenever any class fires.
- **Check name stays `"per-unit companion figures embedded"`.** The name is a parsed contract (pinned as `_PER_UNIT_ORPHAN_CHECK` in the tests, and grepped by downstream review prose). A rename is a separate, out-of-scope change; the plan accepts the mildly-stale name and covers it with an updated docstring.
- **PASS detail keeps the substring `no orphaned per-unit figures`** (three existing tests assert it); the widened scope is described in the appended text.
- **Class separation is greppable.** Class A carries neither token; class B carries `companion-named-not-embedded`; class C carries `committed-figure-unmentioned`. No detail may carry a token for a class that did not fire.
- **Lens pointers.** Class A/B keep their `Lens 11` pointer (asserted by existing tests). Class C cites **Lens 13 — planned-vs-actual coverage** (`.claude/rules/clean-result-critic-lens-reference.md:1198`), the lens that actually caught the #2061 miss.

3. **`test_committed_figure_bare_mention_no_warn`** — pins the mention-bar decision explicitly: the same figure named with NO exemption idiom is also silent. This is the pin the critic should attack if it disagrees with §3's two-bar call; it makes the decision visible rather than emergent.
4. **`test_committed_figure_embedded_no_warn`** — embedded non-per-unit figure → silent.
5. **`test_class_c_and_class_b_tokens_are_disjoint`** — a repo with BOTH an unmentioned per-unit companion and an unmentioned non-per-unit figure: the per-unit path appears under class A (no class-B token), the other under class C, and neither class's token leaks onto the other's entry.
6. **`test_non_png_committed_artifact_never_warns`** — commits `figures/issue_999/f6_extra.pdf` and `figures/issue_999/meta.json`, both unmentioned → silent (scope pin against a future over-widening).

## §7 Kill criteria and the corpus dry-run

- (K1) **Noise ceiling.** Before requesting code review, run the generalized check over every already-promoted clean-result body reachable under `tasks/*/*/body.md` (read-only; no writes, no network beyond the local object DB) and record the distribution of newly-WARNed figures per body. Median above ~5 per body ⇒ STOP and narrow the design per §0.0's change-my-mind line rather than landing it.
- (K2) **No-regress.** Any pre-existing check-31 test that needs its assertions edited to stay green is a design failure, not a test-maintenance chore: it means an existing class changed behaviour. Modifying the fixture *builder* signature additively is fine; editing an existing test's assertions is a STOP.
- (K3) **Silent-skip integrity.** An unreachable SHA must still degrade to a silent skip. If the live #2061 replay comes back silent, verify with `git rev-parse --verify --quiet '<sha>^{commit}'` that the body-cited SHAs actually resolve before recording it as evidence of anything — `figures/issue_2061/` is NOT on `main` HEAD (it lives on the unmerged `issue-2061` branch), so the replay depends on those objects being present in the shared object DB. A silent result on unreachable SHAs is a null read, not a PASS.
