### 4.2 `NegativeContext` — promoted body + the bare-member branch

`messages()` is the #664 resolver verbatim, plus a third branch so the bare default assistant is representable (the old code `assert self.system_prompt`-ed in the else branch, which cannot express a no-system, no-wrap member):

```python
def messages(self, question: str) -> list[dict[str, str]]:
    if self.user_wrap is not None:
        return [{"role": "user", "content": self.user_wrap.format(q=question)}]
    if self.system_prompt is None:
        return [{"role": "user", "content": question}]  # bare default assistant
    return [
        {"role": "system", "content": self.system_prompt},
        {"role": "user", "content": question},
    ]
```

`__post_init__` (light validation replacing the lost runtime assert; every existing construction in the repo passes all four checks — verified against `negative_panel()` members and `tests/test_artifacts_context.py` L302/L310):

- `slug` and `identity` non-empty.
- `system_prompt` is `None` or non-empty (mirrors `validate_context`; the old truthiness assert rejected `""` too).
- `user_wrap`, if set, must contain the literal `"{q}"` (mirrors `Context`).
- `ValueError` if BOTH `system_prompt` and `user_wrap` are set (the old resolver silently ignored `system_prompt` when `user_wrap` was set — a trap; no existing member sets both).

Existing-member behavior is byte-identical: user_wrap members → `[user]` with wrapped question; system members → `[system, user]`. Only the deliberately-new bare member takes the third branch.

### 4.6 Disjointness assert + ~1:1 helpers

```python
def assert_panel_disjoint_from_sources(
    panel: Sequence[NegativeContext],
    realized_sources: Iterable[str],
    *,
    source_identities: Mapping[str, str] | None = None,
) -> None:
    """HARD invariant (#527/#538): panel ∩ realized sources == ∅, at slug AND
    identity level, checked against the REALIZED panel/sources at build time.
    When ``source_identities`` is given, EVERY realized source must map
    (strict — KeyError propagates; an unmapped source is a design bug)."""
    srcs = set(realized_sources)
    panel_idents = {n.identity for n in panel} | {n.slug for n in panel}
    if source_identities is not None:
        srcs |= {source_identities[s] for s in set(realized_sources)}
    overlap = panel_idents & srcs
    if overlap:
        raise AssertionError(
            f"Contrastive panel ∩ realized sources != ∅: {sorted(overlap)}. "
            f"panel={sorted(panel_idents)} sources={sorted(srcs)}"
        )
```

Differences from the #664 original, both deliberate: (a) the panel is a PARAMETER (generic over registered panels) — the shim closes over the #664 panel; (b) `raise AssertionError` replaces the `assert` statement (same exception type, but survives `python -O`; message shape preserved).

```python
def per_negative_quota(n_positives: int, panel: Sequence[NegativeContext]) -> int:
    """Rows per panel member for ~1:1 positives-to-TOTAL-negatives, split evenly
    across the panel: max(1, n_positives // len(panel)) — the exact #664 builder
    arithmetic (issue664_build_training_data.py L327/350/401/429/512)."""
    if not panel:
        raise ValueError("empty negative panel")
    if n_positives < 0:
        raise ValueError(f"n_positives must be >= 0, got {n_positives}")
    return max(1, n_positives // len(panel))

def negative_allocation(
    n_positives: int, panel: Sequence[NegativeContext]
) -> list[tuple[NegativeContext, int]]:
    """(member, row_count) pairs — even split, ~1:1 total (exact when divisible)."""
    q = per_negative_quota(n_positives, panel)
    return [(neg, q) for neg in panel]
```

The 5 inline sites in `issue664_build_training_data.py` are rewired to `per_negative_quota(...)` — a behavior-identical mechanical substitution (identical formula; pinned by `test_per_negative_quota_matches_664_arithmetic`) that leaves ONE live copy of the ratio policy. If code-review judges the frozen-script churn not worth it, this sub-step is separately droppable without affecting anything else in the plan.
