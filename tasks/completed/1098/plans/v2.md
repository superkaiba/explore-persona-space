### 4.2 The waiver — placement and exact code

**File:** `scripts/guard_repo_root_branch.sh`. **Anchor:** in the driver `while IFS=$'\t' read -r sep clause` loop, immediately AFTER the loose per-clause gate (the block commented `# not a git checkout/switch/restore/clean/reset clause at all -> skip`) and immediately BEFORE `reason=$(classify_clause "$clause")`. Placement after the loose gate means only clauses already containing gated-verb text pay the waiver's greps (1 grep for non-matching clauses, ≤4 for matching ones — the guard already spawns ~10+ greps per gated clause in `classify_clause`, so the marginal cost is noise; nuance-6 performance constraint satisfied).

```bash
  # (#1098) ssh REMOTE-COMMAND / grep-family PATTERN-ARGUMENT clause waiver.
  # An `ssh <host> '<remote cmd>'` clause executes its command string on the
  # REMOTE host (a pod's own /workspace clone), never in this VM's repo-root
  # working tree — the same operation class the THREAT MODEL paragraph
  # already scopes out for SSH-MCP remote commands (incident 2026-07-06:
  # `ssh pod-779 'git reset --hard origin/main'` false-blocked; the #779
  # session detoured through a pod-side script). A grep/egrep/fgrep/rg
  # clause is read-only w.r.t. git — its pattern argument is data. Waive
  # (skip classification of) such a clause ONLY when ALL of:
  #   (1) the clause's COMMAND WORD is ssh|grep|egrep|fgrep|rg (^-anchored;
  #       the awk splitter already stripped leading whitespace). A MID-clause
  #       ssh/grep word never waives — `git -c core.sshCommand=ssh reset
  #       --hard` is a LOCAL destructive op and still classifies. Wrapped
  #       forms (`timeout 240 ssh ...`, `nohup ssh ...`, `/usr/bin/ssh`,
  #       `$SSHCMD ...`) are NOT clause-initial `ssh` and keep blocking
  #       (fail-closed residual FP, gap (xiv)).
  #   (2) the clause is NOT in pipeline-producer position: its FOLLOWING
  #       separator (the $nextsep field the splitter now emits) is not
  #       PIPE. A waived producer's stdout can feed a LOCAL shell consumer
  #       (`ssh host 'echo git reset --hard' | bash`, `grep 'git reset
  #       --hard' f | bash`) whose own clause carries no gated text and
  #       clears the loose gate — the round-1 Codex methodology blocker.
  #       Refusing on ANY following pipe (consumer-independent) is
  #       strictly status-quo-preserving: a piped shape is rc=2 today, so
  #       the refusal costs only the un-waived convenience (`… | tail`),
  #       documented as a residual FP in gap (xiv) with the `git -C`
  #       remediation (which pipes fine — the -C waiver is pipe-blind).
  #   (3) NO locally-executing expansion / redirection syntax anywhere in
  #       the clause: $( / ${ / backtick / <( / >( / <<< .
  #       `ssh host "$(git reset --hard)"` and `grep -f <(git clean -fd) x`
  #       EXECUTE the gated text LOCALLY at expansion time. `${` is the
  #       same fail-closed over-match as heredoc check (g) — a plain
  #       ${VAR} (even single-quoted, which bash would NOT expand locally)
  #       refuses the waiver, because the guard deliberately does not
  #       shell-parse quotes (#796 revert). Bare `$VAR` (no brace, no
  #       paren) never executes a command and is NOT refused. Live
  #       clauses — unlike heredoc BODIES — undergo process substitution,
  #       hence <( / >( over check (g). `<<<` (here-string) feeds DATA and
  #       is refused anyway: it preserves the existing must-block pin
  #       R8b-here_string_full_literal_parity (a grep here-string carrying
  #       a full gated literal blocks today and MUST keep blocking — the
  #       round-1 statistics blocker), keeping raw-scan parity for
  #       here-string literals at zero incident cost.
  #   (4) [ssh only] no ProxyCommand/LocalCommand/KnownHostsCommand token
  #       (ssh executes all three LOCALLY, in this cwd — KnownHostsCommand
  #       since OpenSSH 8.4) and no shared-repo path in ANY covered
  #       spelling — literal $REPO, $HOME/<repo-basename>, ~/<repo-basename>
  #       — anywhere in the clause: an ssh-to-this-VM remote string
  #       operating on the shared root stays blocked (option (b), widened
  #       after the round-1 critics showed `--work-tree=$HOME/…` dodges the
  #       literal-only glob; bare $HOME is deliberately not expansion-refused,
  #       so the path spellings must be). ${HOME}/… forms are already
  #       refused by (3)'s ${ arm. Non-canonical spellings (doubled slash,
  #       $USER-composed, variable-indirection `ssh $HOST` with a remote
  #       $REPO) stay deliberate-only accepted fail-opens — gap (xiv).
  #   (5) [grep-family only] no --pre token, = or space form (rg --pre
  #       executes a preprocessor command per file, locally).
  # NO LATCH: the waiver covers THIS clause only — it reads the clause's
  # own command word, so no arming/propagation separator proof is needed
  # (unlike the cd/WT latches, no state crosses clauses). A quoted
  # multi-statement remote string (`ssh pod 'cd /w && git reset --hard'`)
  # is mis-split by the quoted-separator trade-off and its TAIL clause
  # (which lost the ssh command word) still classifies — fail-closed,
  # residual gap (xiv); remediation unchanged: single-statement
  # `git -C /workspace/... <verb>` inside the remote string (the -C waiver
  # above already allows it), a pod-side script, or the SSH MCP.
  if echo "$clause" | grep -qE '^(ssh|grep|egrep|fgrep|rg)[[:space:]]'; then
    if [ "$nextsep" != PIPE ] \
       && ! echo "$clause" | grep -qE '\$\(|\$\{|`|<\(|>\(|<<<'; then
      if echo "$clause" | grep -qE '^ssh[[:space:]]'; then
        if ! echo "$clause" | grep -qiE 'proxycommand|localcommand|knownhostscommand'; then
          case "$clause" in
            *"$REPO"*|*'$HOME/'"$REPO_BASE"*|*'~/'"$REPO_BASE"*) : ;;
                              # shared-root spelling -> classify (blocks)
            *) continue ;;    # remote-host git op -> waive this clause
          esac
        fi
      elif ! echo "$clause" | grep -qE '(^|[[:space:]])--pre(=|[[:space:]])'; then
        continue              # read-only pattern argument -> waive this clause
      fi
    fi
  fi
```

`REPO_BASE=${REPO##*/}` is defined once next to `REPO=` at the top of the guard (evaluates to `explore-persona-space`); the mixed-quoting case globs make `$HOME/` and `~/` LITERAL text matches followed by the expanded basename.

### 4.2b Sanctioned `split_and_label` extension — one-record lookahead (`nextsep`)

Condition (2) needs each clause's FOLLOWING separator. The awk consumer in `split_and_label` gains a one-record buffer and emits THREE tab-separated fields (`sep`, `nextsep`, `clause`); the sed pre-pass, sentinel vocabulary, and clause-strip semantics are byte-unchanged:

```awk
BEGIN{RS="\n"; sep="START"; have=0}
{ line=$0
  if (match(line, /^\x01(OR|AND|SEQ|PIPE|BG|NL)\x01/)) {
    sep=substr(line, 2, RLENGTH-2); line=substr(line, RLENGTH+1)
  }
  gsub(/^[ \t]+|[ \t]+$/, "", line)
  if (!length(line)) {              # empty clause: FLUSH the buffered one
    if (have) { print psep "\t" sep "\t" pline; have=0 }   # with the empty
    next                            # record's sep as its nextsep (fail-
  }                                 # closed: a trailing `| <empty>` still
                                    # reports PIPE, never a lost separator)
  if (have) print psep "\t" sep "\t" pline
  psep=sep; pline=line; have=1 }
END { if (have) print psep "\tEND\t" pline }
```

The driver loop reads `while IFS=$'\t' read -r sep nextsep clause` — every existing consumer keeps reading `$sep`/`$clause` with unchanged values and ordering (the latch/waiver/classify logic is untouched by the extra field; `read` puts any residual tabs into `$clause` as before). This is the v2-SANCTIONED splitter change and is deliberately minimal: emission format only, no split semantics; anything beyond it stays must-ask (§ Plan deviations).

Every v1 regex was live-verified this session (bash 5.1.16, GNU grep): anchor matches `ssh pod-779 x`/`grep -q x f`/`rg`/`egrep`/`fgrep`, rejects `sshpass …`/`my-ssh …`/`timeout 240 ssh …`/`zgrep …`; the refusal ERE matches `$(…)`, backtick, `${…}`, `<(…)`, not bare `$VAR`; the literal-path case glob matches; ProxyCommand + `--pre` detectors match. The v2 ADDITIONS (`>(` — claimed in v1 but never in the verified list, a round-1 catch — plus `<<<`, `knownhostscommand`, the `$HOME/`/`~/` globs, and the `nextsep` plumbing) MUST be live-verified by the implementer the same way (probe file under /tmp, never inline fixtures) before the diff is committed.

## 11. Decision Rationale

The "hyperparameters" here are design choices; one entry each (What / Why / Source / Alternatives).

1. **Exemption mechanism: structural per-clause waiver, NOT an override env.**
   Why: the incident class is precisely characterizable per-clause; an env override in the piped-push style (`EPM_ALLOW_REMOTE_GIT=1`, honored as inline prefix) would be a blanket bypass — `EPM_ALLOW_REMOTE_GIT=1 git reset --hard` (a LOCAL op) would sail through, and scoping an inline-prefix override back down to "only ssh clauses" reduces to implementing the structural waiver anyway plus an extra bypass surface. The two guards also differ in whom a miss harms: the piped-push guard protects the session's OWN push verification (self-harm, cheap escape justified); this guard protects OTHER concurrent sessions' uncommitted state (harm-to-others — no cheap blanket escape). The existing deliberate override (`git -C`, header-documented) remains available and auditable.
   Source: `.claude/hooks/guard_piped_git_push.sh` (precedent examined, rejected); guard header THREAT MODEL + incident list (#815/#841).
   Alternatives: env-only (rejected above); structural + env belt-and-suspenders (rejected — the env half adds only bypass surface).
2. **Option (b), v2-WIDENED: refuse the ssh waiver when the clause names the shared-repo path in ANY covered spelling — literal `$REPO`, `$HOME/<repo-basename>`, `~/<repo-basename>`.**
   Why: closes the clarifier's `ssh <this-vm> '… git reset --hard'` family at ~zero false-positive cost (pod remote strings reference `/workspace/...`). The v1 literal-only glob carried a FALSE supporting claim — round-1 critics (3 of 6 independently) showed the single-statement `ssh vm 'git --work-tree=$HOME/explore-persona-space --git-dir=$HOME/explore-persona-space/.git reset --hard'` shape neither mis-splits nor rides the `-C` waiver, and bare `$HOME` is deliberately not expansion-refused — so the `$HOME/`/`~/` spellings must be globbed explicitly (N20/N21 pin them). `${HOME}` forms are already refused by the `${` arm. The bare dirname is deliberately NOT globbed (`/workspace/explore-persona-space` pod paths must stay waivable). Remaining non-canonical spellings are enumerated deliberate-only fail-opens in gap (xiv).
   Source: clarifier nuance 2; probe P4 (mis-split blocks today and stays blocked); round-1 Codex methodology MF3 / Codex alternatives MF1 / Claude alternatives MF1.
   Alternatives: (a) unconditional ssh waiver (rejected — free protection discarded for zero benefit); hostname denylist `localhost|127.0.0.1` (rejected — a bare `ssh localhost 'git reset --hard'` runs in `$HOME`, not the repo; path check subsumes the realistic shapes); canonicalizing path resolution (rejected — a shell parser in bash regex, the #796 boundary).
3. **Refusal set `$(` / `${` / backtick / `<(` / `>(`, applied to the WHOLE clause.**
   Why: `$(`+backtick cover every command-executing expansion bash performs on a live command; `${` is the deliberate fail-closed over-match inherited verbatim from heredoc check (g) (nested `${x:-$(cmd)}` carries `$(` as a substring, but the over-match keeps the simple read and matches in-file precedent); `<(`/`>(` are ADDED because live clauses undergo process substitution while heredoc bodies do not — `grep -f <(git clean -fd) x` executes locally. Bare `$VAR` never executes a command (the bash-manual `${var@P}` prompt-expansion edge requires the VALUE to carry the syntax, out of the cooperative model) and is not refused, so `ssh pod "git reset --hard $BRANCH"` passes.
   Source: heredoc check (g) in this file (#1058); bash semantics, live-probed regex behavior (§4.2).
   Alternatives: `$(`+backtick only (rejected — diverges from the in-file precedent for no gain); refusing bare `$` (rejected — false-blocks the common `$BRANCH`/`$SHA` remote shapes for zero execution risk).
4. **Clause-initial command-word anchor `^(ssh|grep|egrep|fgrep|rg)[[:space:]]`, no wrapper allowance, no latch.**
   Why: an anywhere-in-clause `\bssh\b` fail-opens `git -c core.sshCommand=ssh reset --hard` (live-probed rc=2 today — must stay). Wrappers (`timeout N ssh`, `nohup ssh`, env-prefix, `/usr/bin/ssh`, `$SSHCMD`) each widen the fail-open surface for a shape with zero incident demand — accepted as residual FPs (gap xiv). No latch across clauses: latching "ssh-ness" forward would waive `ssh pod 'x'; git reset --hard`'s LOCAL tail — the exact protected class; conversely no arming-separator proof is needed (unlike the WT= latch) because the waiver reads only the clause's own command word, which IS that clause's executing command regardless of the preceding separator.
   Source: probes P6/P12 (fail-open counterexamples block today); #1058 arming-vs-propagation design notes in the header.
   Alternatives: small wrapper set (rejected this round — add later WITH fixtures if incident demand appears); latch-across-`&&` (rejected — fail-open, and unnecessary since S8/S9 already pass without it).
5. **grep-family included now (not deferred), set = `grep|egrep|fgrep|rg`, with `--pre` refusal.**
   Why: the /daily sweep names the grep FP class alongside ssh; the machinery is shared (one alternation branch + one refusal grep), risk is near-zero given refusal (3) (a grep clause cannot mutate the repo root except via expansion syntax — refused — or rg's `--pre` local preprocessor — refused). Tight set: `zgrep`/`ag`/`git grep` excluded (no incident demand; `git grep` has a different command word by construction).
   Source: task body ("consider grep-pattern arguments"); daily-sweep bug report; rg man page (`--pre` executes a command per file).
   Alternatives: defer grep entirely (rejected — leaves a named FP class the body asks about, at trivial marginal cost); wide reader set (rejected — every added word is fail-open surface).
6. **ssh local-exec option refusal `proxycommand|localcommand|knownhostscommand` (case-insensitive substring), v2-WIDENED.**
   Why: `ssh -o ProxyCommand='git reset --hard' host` executes the command LOCALLY (ssh(1)); LocalCommand likewise (with PermitLocalCommand); `KnownHostsCommand` (OpenSSH ≥8.4) is the third command-line-spellable local-exec option — round-1 critics (both Codex twins) showed it cleared the v1 ladder (N16 pins it). Substring + `-i` is the piped-push guard's `pipefail`-style simple read: it can only fail toward BLOCK (a remote string merely *mentioning* any of the three keeps current behavior — harmless). The config-FILE variant (`ssh -F evil_config`) has no on-command-line token and is accepted as deliberate-only (gap xiv), same register as gaps (v)/(x)/(xii).
   Source: ssh(1)/ssh_config(5) ProxyCommand/LocalCommand/KnownHostsCommand semantics (standard OpenSSH); guard_piped_git_push.sh substring-carve-out precedent; round-1 Codex methodology MF2 / Codex alternatives MF2.
   Alternatives: parse `-o` values properly (rejected — shell parsing in bash regex, the #796 lesson); enumerating every future OpenSSH local-exec option (impossible by construction — the denylist covers the known set; additions are fail-closed-only widenings under the deviation rules).
7. **`shellish()` untouched (ssh stays a heredoc shell-consumer word).**
   Why: the strip ladder's contract is "hide only provably-inert DATA"; a heredoc body fed to `ssh host bash` is executed by a shell, and stripping it would hide the executed text from ALL detectors — a different, stronger operation than declining to classify one clause. C8 pins it. The resulting asymmetry (single-clause remote git waived; heredoc-fed remote shell blocked) is documented in gap (xiv).
   Source: #1058 strip-ladder design (checks a–g); clarifier nuance 2; `C8-ssh` test pin.
   Alternatives: waive ssh-consumer heredocs too (rejected — no incident demand, larger blast radius, would require re-deriving the whole ladder's fail-closed proof).
8. **Pipe-producer refusal via `split_and_label` one-record lookahead (`nextsep != PIPE`), consumer-INDEPENDENT — v2, round-1 Codex methodology MF1.**
   Why: a waived producer's stdout can feed gated text to a local shell consumer whose clause carries no gated verb and clears the loose gate (`ssh host 'echo git reset --hard' | bash`) — the one cross-clause fail-open the per-clause waiver design created. Refusing on ANY following pipe is strictly status-quo-preserving (every piped shape is rc=2 today), so the cost is only un-waived convenience (`… | tail`, N22-pinned as a documented residual FP) — and classifying the CONSUMER instead would need clause-ahead text plus a consumer denylist, re-opening the enumerable-consumers problem gap (xii) already documents. The lookahead is an emission-format-only splitter change (§4.2b): buffered one record, empty-record flush keeps a trailing separator's identity, sed pre-pass + sentinels untouched.
   Source: round-1 Codex methodology MF1 (both fix options offered; the conservative one taken); Claude alternatives MF1 (same family); gap-(xii) consumer-denylist lesson.
   Alternatives: consumer-classifying lookahead (rejected — denylist drift + two-clause lookahead complexity for zero incident demand); whole-command pipe check (rejected — refuses waivers on unrelated segments, e.g. `git status | grep x && ssh pod '…'`, a gratuitous FP the per-clause lookahead avoids); no pipe refusal (rejected — the fail-open is real and cheap to close).
9. **Here-string `<<<` added to the refusal set — v2, round-1 Codex statistics MF1.**
   Why: the drafted v1 waiver FLIPPED the existing must-block pin `R8b-here_string_full_literal_parity` (`grep -q x <<<"git restore . mentioned in prose" || true` — clause-initial grep, no v1 refusal token), violating acceptance criterion 4 and the plan's own must-ask fence for existing-pin flips. A here-string is data, but refusing it preserves R8b's raw-scan-parity contract at zero incident cost (no pod workflow greps gated text via here-strings); the deliberate-flip alternative would rewrite an existing pin through the must-ask path for no benefit.
   Source: round-1 Codex statistics MF1 (composer-verified live vs `tests/test_guard_repo_root_branch.py:1109`); orchestrator independently confirmed R8b sits in a must-block battery.
   Alternatives: deliberately flip + rewrite R8b (rejected — must-ask churn, loses the here-string parity pin, zero incident demand); grep-family-only `<<<` refusal (rejected — uniform whole-clause refusal is simpler and the ssh-side here-string, N17, is equally incident-free).
