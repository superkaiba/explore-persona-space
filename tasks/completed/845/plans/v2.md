# Plan — #845: harden `autonomous_session_watch.py` stall detection (five 2026-07-01 sub-cases)

### 0.0 TL;DR (plain English)

- **What I'll do:** teach the watcher to double-check a session is really stuck before it kills and replaces it (recent markers within 2 h, recently edited files in the issue's worktree), make the replace step two-phase (stop the old session, *verify it actually died* on the next tick, only then spawn the new one — and never touch a session that a concurrent respawn just replaced), keep retrying recovery when the Happy daemon is briefly down and page the phone if it stays down, drop 12-hour-idle session registrations so they stop blocking legitimate re-drives, and add a fast "prompts are being swallowed with no reply" wedge detector keyed on the transcript's verified dequeue records.

### 3.2 (a-ii) Stop-verify respawn fencing in `_handle_stalled_respawn` (line 5929)

New pure predicate (placed near `decide_session_stalled`):

```python
def decide_respawn_fence(
    *, stop_pending_sid: str | None, current_sid: str | None,
    sid_alive: bool, stop_retried: bool,
) -> str:
    """'clear-keep' | 'stop' | 'spawn' | 'retry-stop' | 'stop-failed'.
    - stop_pending_sid is not None and stop_pending_sid != current_sid
                                  -> 'clear-keep'  (a concurrent respawn — crash
                                     arm or a #843-leased driver — replaced the
                                     session: CLEAR all fence state, do nothing
                                     this tick, NEVER stop the fresh sid)
    - stop_pending_sid is None    -> 'stop'         (first tick: stop only, no spawn)
    - pending == current, not sid_alive -> 'spawn'  (verified dead: safe to spawn)
    - pending == current, sid_alive, not stop_retried -> 'retry-stop'
    - pending == current, sid_alive, stop_retried     -> 'stop-failed' (alert, never spawn)
    """
```

Persisted state (`_save_stalled_state`, new keyword-only fields, all default-absent = backward compatible, same guard shape as `live_consecutive`): `stop_pending_sid: str | None`, `stop_pending_ts: float | None`, `stop_retried: bool`, `stop_failed_alerted: bool` (field names mirror the idle-unmapped state payload at line ~12339). **Implementer guidance: the fence state is SCALAR per-issue fields (a single pending sid per stalled episode) — do NOT cargo-cult the zombie pass's `stopped_at: {sid: ts}` MAP shape; the stalled arm handles exactly one sid per issue at a time.**

**Spawn-grace skip (NEW, runs BEFORE the hold and the fence):** at the top of `_handle_stalled_respawn`, if the registry entry's `spawned_at` is within `RESPAWN_SPAWN_GRACE_S` (15 min), log `SPAWN-GRACE: skip stalled respawn arm` and return keep — the mirror of the crash arm's #759 grace, which the stalled arm currently lacks. Together with the `'clear-keep'` rule this closes the FENCE RACE: the crash pass (which runs BEFORE the stalled pass in `main()`, against a `live_ids` snapshot taken once per tick) can legitimately respawn inside the fence's stop→verify gap; the fresh session then carries a fresh `spawned_at` (grace skip) and a new sid (fence clear), so the stalled arm neither stops nor double-drives it.

`_handle_stalled_respawn` restructure (a NEW top block; the existing sid-guard/refresh/spawn code moves into the `'spawn'` branch mostly verbatim, minimizing the #843-conflicting region):

```
if entry spawned_at within RESPAWN_SPAWN_GRACE_S -> log SPAWN-GRACE; return   # NEW
fence = decide_respawn_fence(
    stop_pending_sid=prev.stop_pending_sid, current_sid=sid,
    sid_alive=(live_ids is not None and sid in live_ids),
    stop_retried=prev.stop_retried)
'clear-keep' -> clear stop_pending_sid/ts, stop_retried, stop_failed_alerted;
                log "FENCE: sid changed (concurrent respawn owns the issue), cleared";
                return                                                          # NEW
'stop'       -> _stop_session(sid); persist stop_pending_sid=sid, stop_pending_ts=now,
                missed=0; log "FENCE: stopped, will verify+spawn next tick"; return
'retry-stop' -> _stop_session(sid) again; persist stop_retried=True; return
'stop-failed'-> one-time _post_progress_marker(_STALLED_STOP_FAILED_NOTE_SENTINEL ...)
                + _telegram_push (fail-soft); persist stop_failed_alerted=True; return
'spawn'      -> existing body: refresh-from-api heal, rc = _respawn_stalled_session(...);
                rc == "spawned"    -> respawn_count+1 bookkeeping, clear stop_pending_*
                rc == "suppressed" -> book NOTHING (per #843) AND clear stop_pending_*
                                      (lease collision ⇒ a live driver owns the issue;
                                       the fence episode is over)                # NEW
                rc == "failed"     -> keep today's post-#843 behavior (no booking,
                                      retried next tick); stop_pending_* stays so the
                                      next tick re-verifies before retrying the spawn
```

Special case: when the sid was NEVER in `live_ids` this tick (genuinely-dead wrapper reaching the stalled arm), `sid_alive=False` and `stop_pending` is set in the same tick the stop is issued — the predicate is evaluated ONCE per tick, so a dead sid still waits one tick between stop and spawn. That +10 min is deliberate: it is what closes #763. (`live_ids` is already threaded into `_process_stalled_session`; pass it through `_StalledActionCtx` as a new field.) New sentinel `_STALLED_STOP_FAILED_NOTE_SENTINEL = "[autonomous_session_watch:session-stop-failed]"` added to `_WATCHER_NOTE_SENTINELS`.

State-clear rules: `stop_pending_*` cleared on self-report advancement (session resumed = episode over, same clearing block as `alerted`, line ~6497), on the `'clear-keep'` branch (sid changed — concurrent respawn replaced the session), on the `'spawn'` branch when the spawn returns `"spawned"`, AND on a `"suppressed"` tri-state return (lease collision ⇒ a live driver owns the issue, episode over).

### 3.6 (e) Prompt-wedge trigger

Pure predicate over parsed transcript rows — **signal-agnostic**, with the VERIFIED `queue-operation` dequeue rows as CO-PRIMARY evidence:

```python
TICK_WEDGE_MIN_DEQUEUED = 3   # env EPM_TICK_WEDGE_MIN_DEQUEUED

def decide_prompt_wedge(trailing_rows: list[dict], min_dequeued: int) -> bool:
    """True iff the transcript TAIL ends with >= min_dequeued consecutive
    wedge-evidence rows and no assistant row after the first of them.
    Wedge-evidence row classes (both count toward the same trailing run):
      CO-PRIMARY 'dequeue': type == 'queue-operation' with operation == 'dequeue'
        (row shape VERIFIED in live session transcripts — critique r1);
      SECONDARY 'prompt': type == 'user' whose message content is a string
        or contains a text block and NO tool_result block.
    'assistant' rows reset the run; everything else (tool_result user rows,
    summary, system, non-dequeue queue-operations) is 'other' and is skipped
    without resetting the count. Malformed rows -> 'other'."""
```

Evidence order (fallback chain): (1) `queue-operation` dequeue rows — co-primary, the directly-verified dequeue record; (2) promptless prompt-type user rows — secondary; (3) tick-snapshot staleness — LAST fallback, only if a real wedged tail shows neither transcript signal (§6). The predicate treats (1) and (2) uniformly inside one trailing run so a mixed tail (dequeue records interleaved with swallowed prompt rows) still counts.

I/O wrapper `_transcript_tail_rows(pid: int, max_bytes: int = 65536) -> list[dict] | None`: resolve via `session_resolver._resolve_transcript_via_happy_log(pid)` (the same happy-log-only contract as `_transcript_idle_age_s` — a miss is `None`, fail toward no-wedge), read the last 64 KB, split lines, JSON-parse complete lines only.

Wiring in `_process_stalled_session`: LAZY probe — only when `self_report_age is not None and self_report_age >= window_s` (signal 1 stale) AND `action in ("keep", "alert")` (i.e., the slow path would debounce). Needs the sid→pid map: thread a new optional param `pids_by_sid: dict[str, int] | None` from `stalled_session_pass` ← `main()` (derived once from the same `/list` reply that builds `live_ids`; add helper `_live_pids_by_sid_or_none()` NEXT TO `_live_session_ids_or_none` rather than modifying it — #843 conflict avoidance). If `decide_prompt_wedge(...)`: log `WEDGE`, force `action = "respawn"` (bypasses the 2-miss guard, the K-downgrade in `_apply_stalled_live_corroboration` — apply the wedge override AFTER that call — and the 2 h marker window), still subject to `respawn_eligible` (ACTIVE + daemon + not manual) and then, inside `_handle_stalled_respawn`, to the spawn-grace skip, the (b) worktree hold and the (a) fence. **Implementer guidance: a wedge-forced respawn also RESETS `live_consecutive`** (consistent with the escalation-fired ⇒ reset semantics in `_apply_stalled_live_corroboration`). The respawn marker note quotes the wedge evidence (`{k} consecutive dequeue/promptless rows`). New stalled-state field `wedge_hits: int` for observability only (no dedup needed; the fence bounds actions).

#779 replay + **timeline honesty (implementer guidance — do not overstate in the PR):** wedge evidence (queue-operation dequeue rows) appears in the tail within ~1-2 ticks of the 3rd swallowed prompt, but the REALISTIC end-to-end saving vs #779's ~90 min is the debounce/K portion — ~20-40 min — because the lazy probe still waits for self-report staleness (signal 1, 60 min window) and the (b) hold + (a) fence add their bounded latency; the in-flight implementer's file edits hold the respawn via (b) until it finishes; then stop → verify → spawn.

## 11. Decision Rationale (load-bearing thresholds) + Assumptions

Task kind is `infra` — "N/A — no model-training hyperparameters"; the load-bearing values here are watchdog thresholds, each grounded in incident data + existing constants:

- **Marker-heartbeat window = 2 h.** What: markers younger than this block stall declaration. Why: the false-positive class (#761: a legitimate 1 h 21 m marker gap drew a wasted respawn; #763 overlap) sits between the current 60-min window and 2 h; 2 h = 2× `STALLED_WINDOW_S`, comfortably under the pod-side `ALERT_STALE_HOURS = 6 h` and above `LONG_PHASE_HEARTBEAT_FRESH_S = 90 min`. Counts any non-watcher marker, not strictly session-owned progress — the wedge fast-lane is the mitigation (§3.1 scope note). Source: task-body proposal ("~2h") + #761 exemption comment (line ~6554) + existing constants.
- **Worktree-activity hold = 15 min, cap 6 ticks.** What: fresh file edits defer stop/respawn. Why: #812's kill happened 57 s after an edit; implementer tool-call cadence is minutes-scale, so 15 min (= `RESPAWN_SPAWN_GRACE_S`) covers inter-edit gaps without long false-negative tails; the 6-tick (~1 h) cap matches the `ORPHAN_STALENESS_S` 90-min timescale and bounds the cross-writer-worktree false-negative. Source: incident (b) + `RESPAWN_SPAWN_GRACE_S` (line 463) + `ORPHAN_STALENESS_S_DEFAULT` (line 6821).
- **Fence = next-tick verify, 1 stop retry, sid-change clear, spawn-grace skip.** What: stop → verify dead on the next 10-min tick → spawn; one retry then loud alert; a pending fence whose sid changed clears (never stops the fresh sid); the stalled arm skips entirely within `RESPAWN_SPAWN_GRACE_S` of a fresh spawn. Why: verbatim port of the proven zombie/idle "stop-verified-on-next-tick, daemon ACK != kill, ONE retry, one-time alert" contract (module docstring lines 129-130, state fields `stopped_at`/`stop_retried`/`stop_failed_alerted`), plus the critique-verified fence race (crash pass runs before the stalled pass against a once-per-tick `live_ids` snapshot, so a crash-arm respawn can land inside the stop→verify gap) closed by grace-skip + sid-change clear. Source: existing in-file semantics; incident (a); critique r1 MF1 verification against main (~14336/~14332/1172-1180/6345-8).
- **Daemon probe = 3 attempts, 5 s/10 s backoff.** Why: defuses transient flaps at <45 s worst-case added tick time; mirrors `_WEDGE_RECORD_RETRY_ATTEMPTS = 3` / `_WEDGE_RECORD_RETRY_BASE_S = 1.0` shape (line 3325) scaled to an RPC. Source: house pattern + incident (c).
- **Daemon-blocked push at 2 consecutive ticks (~20 min).** Why: matches the file-wide 2-miss debounce convention (`threshold=2` everywhere); pages within ~20 min (2 ticks) instead of #811's hours-of-idle-GPU. Source: `decide()`/`decide_pod_safety` threshold convention.
- **Stale-registration idle threshold = 12 h.** Why: equals `UNMAPPED_IDLE_REAP_S = 12*3600` (line 11491) — the project's existing "a transcript idle this long is abandoned" judgment; catches #665 (16 h) with margin; far above any legitimate gate-wait *turn* gap (gates park the task status, which the pass reads anyway). Source: existing constant + incident (d).
- **Wedge N = 3 consecutive wedge-evidence rows (dequeue ops co-primary / promptless user rows secondary).** Why: #779 showed 5 dequeues over ~90 min; N=3 fires ~2 prompts (≈ tens of minutes) earlier while tolerating 1-2 rows racing a mid-delivery prompt or a slow turn; env-tunable. The SIGNAL is grounded (the `queue-operation` dequeue row shape is verified in live transcripts); the THRESHOLD N=3 remains `ungrounded beyond the incident — env knob + test coverage is the guard` (flagged deliberately; no literature applies). Source: incident (e) + critique r1 transcript verification.
