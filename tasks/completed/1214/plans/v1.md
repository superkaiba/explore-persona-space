### 0. Plan Summary (technical)

**Change:** `scripts/new_worktree.sh` gains a `_resolve_base()` step on the fresh-creation path: when the branch will actually be created (`CREATED_BRANCH=1`) and `--base-local` is absent, it runs `timeout 60 git -C "$REPO_ROOT" fetch --quiet origin "+refs/heads/main:refs/remotes/origin/main"` and passes `refs/remotes/origin/main` as the `<commit-ish>` start-point to `git worktree add … -b "$BRANCH" --no-track`. Fallback ladder: `--base-local` → local HEAD (verbatim today's behavior); no `origin` remote → local HEAD + WARN (keeps all fixture-repo tests green); fetch fails but a previously-fetched `refs/remotes/origin/main` exists → STALE `origin/main` + WARN (pushed-history-only, never reintroduces the bug); fetch fails and no `origin/main` ref exists → FATAL exit 5 (fail fast). Existing-branch attach path, repair path, reuse path, sparse-cone computation, quota logic, ERR-trap semantics: all unchanged. **Tests:** ~6 new subprocess tests in `tests/test_sparse_worktree.py` (diverged bare-origin fixture; base == pushed tip; WARN fallbacks; FATAL tier leaves no residue; `--base-local`; existing-branch resume stays offline-safe). **Callers:** no edits required (verified — SKILL.md Step 4a / issue-v2 / refactor / guard scripts reference the script as a bare command); one optional one-clause CLAUDE.md doc touch-up. **Risks (top 2):** network dependence added to fresh creation (mitigated: 60 s timeout + stale-fallback + fetch skipped when branch pre-exists); branch base slightly behind local main (deliberate — Step 10d rebase-merges onto latest main anyway; `--base-local` is the escape).

### Hunk 4 — `_resolve_base()` (insert after `git worktree prune`, L211, before the `_add` comment block at L213)

```bash
# Base ref for NEW branches (#1214). Step 10d merges land on origin/main; a
# branch cut from the shared root's LOCAL main inherits its unpushed
# task-state churn (2026-07-08: 3/6 sessions, 10-25 min forensics each; one
# branch had 78 foreign commits baked in). Sets START_POINT (global): empty =
# local HEAD (today's behavior); otherwise the ref passed as the start-point
# to `worktree add -b`. Only called when the branch will actually be created
# (the -b path); the existing-branch attach path takes no base.
START_POINT=""
_resolve_base() {
  if [ "$BASE_LOCAL" = 1 ]; then
    echo "new_worktree: --base-local — basing '$BRANCH' on the main checkout's local HEAD" >&2
    return 0
  fi
  if ! git -C "$REPO_ROOT" remote get-url origin >/dev/null 2>&1; then
    echo "new_worktree: WARN — no 'origin' remote; basing '$BRANCH' on local HEAD" >&2
    return 0
  fi
  # Explicit refspec: guarantees refs/remotes/origin/main updates regardless of
  # the remote's configured fetch refspec (a bare `fetch origin main` only
  # updates it opportunistically). FETCH_HEAD is deliberately NOT used: it is
  # one shared file, racy under this repo's many concurrent sessions.
  # `timeout 60`: a hung fetch must not wedge an autonomous pipeline; timeout
  # (rc 124) falls through to the stale-origin/main tier below.
  if timeout 60 git -C "$REPO_ROOT" fetch --quiet origin \
       "+refs/heads/main:refs/remotes/origin/main"; then
    START_POINT="refs/remotes/origin/main"
  elif git -C "$REPO_ROOT" rev-parse --verify --quiet refs/remotes/origin/main >/dev/null; then
    echo "new_worktree: WARN — 'git fetch origin main' failed; basing '$BRANCH' on the" >&2
    echo "new_worktree:   last-fetched (possibly STALE) origin/main — pushed history only," >&2
    echo "new_worktree:   so the #1214 churn bug is NOT reintroduced." >&2
    START_POINT="refs/remotes/origin/main"
  else
    echo "new_worktree: FATAL — fetch failed and no refs/remotes/origin/main exists;" >&2
    echo "new_worktree:   refusing to base '$BRANCH' on local main (unpushed task-state" >&2
    echo "new_worktree:   churn, #1214). Fix the network/remote, or pass --base-local." >&2
    exit 5
  fi
  echo "new_worktree: basing '$BRANCH' on $START_POINT" \
       "($(git -C "$REPO_ROOT" rev-parse --short "$START_POINT"))" >&2
}
```

All probes are `if`-guarded — safe under `set -Eeuo pipefail` (design question 10). Exit code 5 is new and distinct (2 = bad args, 3 = migration LOCK, 4 = bind assert).

### Hunk 5 — `_add()` start-point + `--no-track` (L217–226)

```bash
_add() {
  local err1
  # ${START_POINT:+...}: append the base commit-ish only when _resolve_base
  # chose one (empty = local HEAD, today's behavior). --no-track: a branch cut
  # from the remote-tracking ref must NOT gain origin/main as upstream (today's

  if ! err1=$(git -C "$REPO_ROOT" worktree add "$@" "$WT" -b "$BRANCH" --no-track \

      echo "new_worktree: both add attempts failed; first attempt said:" >&2
      echo "$err1" >&2
      return 1
    }
  fi
}
```

## 11. Decision Rationale

- **D1 — Default base = fetched `origin/main`.** *What:* new branches start at `refs/remotes/origin/main` after an explicit fetch. *Why:* `origin/main` is pushed history by construction — it cannot contain the unpushed/rewritten task-state commits that caused the #1142/#1144/#1145 forensics. *Source:* task #1214 body evidence + [git-worktree docs](https://git-scm.com/docs/git-worktree) (`worktree add [-b <branch>] <path> [<commit-ish>]` start-point mechanism). *Alternatives:* keep local-HEAD base + rely on #1147 guards (rejected — treats the symptom, 10–25 min per incident); rebase branches post-hoc (rejected — same forensics, later).
- **D2 — Fetch-failure disposition: tiered, not binary.** *What:* fetch failure → fall back to the last-fetched (stale) `origin/main` with a WARN; only when NO `origin/main` ref exists at all → FATAL exit 5. *Why:* this resolves the hard-fail-vs-silent-fallback tension: a stale `origin/main` is still pushed-history-only, so the fallback **cannot reintroduce the bug** while keeping autonomous pipelines unblocked through transient network blips; a local-HEAD fallback there WOULD reintroduce it, so the only state with no safe base fails loud per the project's fail-fast Critical Rule. On the production VM `origin/main` always exists (cloned repo), so the FATAL tier is effectively unreachable outside genuinely broken states. *Source:* CLAUDE.md § Critical Rules "Fail fast — never hide failures"; incident economics in #1214 body. *Alternatives:* always-fail-loud (rejected — blocks autonomous Step 4a on any GitHub blip); always-fall-back-to-local (rejected — silent bug reintroduction).
- **D3 — No-origin case: local HEAD + WARN.** *What:* `git remote get-url origin` probe; absent → today's behavior + WARN. *Why:* test fixture repos (`git init -b main`, no remote) and remote-less dev clones must keep working; there is no origin to inherit churn *from*, so local HEAD is genuinely safe there. *Source:* read from the two test files. *Alternatives:* require origin (rejected — breaks both pin test files).
- **D4 — Ref: remote-tracking ref via explicit refspec, not FETCH_HEAD, not bare `fetch origin main`.** *What:* `git fetch origin "+refs/heads/main:refs/remotes/origin/main"`, then base on `refs/remotes/origin/main`. *Why:* FETCH_HEAD is one shared file per repo — racy under this repo's many concurrent sessions (a concurrent fetch between our fetch and our `worktree add` could repoint it); the remote-tracking ref is updated atomically per-ref and read by name. Bare `fetch origin main` updates the tracking ref only *opportunistically* (needs a covering configured refspec — present on the VM: `+refs/heads/*:refs/remotes/origin/*`, verified, but not guaranteed in every fixture/clone); the explicit refspec form guarantees it, and `+` force-updates so even a (user-gated, rare) rewritten main can't wedge future fetches. *Source:* git-fetch/git-worktree documentation; live repo config read (`remote.origin.fetch`, git 2.34.1). *Alternatives:* FETCH_HEAD (rejected: race); bare named-ref fetch (rejected: config-dependent).
- **D5 — `--no-track` on the `-b` attempt.** *What:* suppress upstream auto-setup. *Why:* branches cut from a remote-tracking start-point gain it as upstream by default (`branch.autoSetupMerge=true`), which changes `git status`/`git push` semantics vs today's upstream-less branches; preserving all non-base behavior keeps this a single-variable change. *Source:* git branch-tracking semantics; supported on `worktree add` since git 2.16, VM has 2.34.1 (verified). *Alternative:* accept tracking (rejected — gratuitous contract change).
- **D6 — Fetch gated on `CREATED_BRANCH=1`.** *What:* resolve/fetch only when a branch will actually be created. *Why:* the existing-branch attach path takes no base — fetching there is dead work AND would newly couple offline resume to the network/FATAL tier. *Source:* `_add()` L217–226 fallback semantics, read from code. *Alternative:* always fetch (rejected — regresses resume robustness for zero benefit).
- **D7 — `timeout 60` on the fetch.** *What:* bound the fetch wall-time. *Why:* git has no built-in fetch timeout; a hung fetch would wedge autonomous Step 4a indefinitely — worse than a failure, which the ladder absorbs. 60 s is ~20× the observed VM→GitHub fetch time (~1–3 s) — `ungrounded — needs smoke-test` in the narrow sense that no incident pins the exact value; any value in 30–120 s serves. *Source:* engineering judgment; smoke run (§6.4) exercises the happy path. *Alternative:* `-c http.lowSpeedLimit/...` (rejected — HTTP-only, misses ssh remotes and DNS hangs).
- **D8 — `--base-local` semantics.** *What:* skip the probe/fetch entirely; base on the main checkout's current local HEAD — bit-for-bit today's behavior; strict-args loop gains one case. *Why:* the task body mandates the escape hatch; "skip fetch entirely" (not "fetch then ignore") makes it usable offline and makes deliberate local-base branching explicit. *Source:* #1214 proposed change (verbatim).
- **D9 — Cone list unchanged** (§4 Q6). *Source:* read from `_sparse_setup` L251–257; no incident evidence.
- **D10 — `_ensure_managed_main_worktree` out of scope** (§4 Q7). *Source:* read from `task_workflow.py` L581–663.
