### 4. Design

Four files touched, no new files, no deletions.

**Defect 1 — `scripts/issue2223_r5_pubtopic.py`, `fig5_cjk_scan()` (lines ~206-225).**

The current call sits in a cache-miss branch:

```python
if not src.exists():
    from explore_persona_space.orchestrate.env import load_dotenv
    load_dotenv()
    from huggingface_hub import hf_hub_download
    src = Path(
        hf_hub_download(
            "superkaiba1/explore-persona-space-data",
            "issue2223_persona_drift/.../raw_completions.json",
            repo_type="dataset",
            revision=PRE_OVERWRITE_REV,
            local_dir="/tmp/i2223_preoverwrite",
        )
    )
```

Wrap it in the canonical helper:

```python
src = Path(
    retry_transient(
        lambda: hf_hub_download(...same args, unchanged...),
        what="hf_hub_download(issue2223 fig5 raw_completions)",
    )
)
```

Grounding for the remedy choice (**acceptance #3**): `hub.retry_transient` is an
alias of `_retry_upload` (`src/explore_persona_space/orchestrate/hub.py:1404`), whose
documented call shape at that site is
`retry_transient(lambda: <hub call>, what="<label>")`. The lint's wrap predicate
`_hf_routing_call_is_wrapped` (`scripts/workflow_lint.py:9448`) accepts a wrap opening
on the call's own line before the call, OR within `HF_ROUTING_WRAP_WINDOW = 3` lines
above while that expression is still paren-open — the lambda shape satisfies the
latter. `HF_ROUTING_WRAP_RE` is `\b(?:retry_transient|_retry_upload)\s*\(`, so both the
bare and dotted forms match.

**Why NOT `--regen-hf-routing-snapshot`.** The #1568 escape exists for a PRE-EXISTING
file whose frozen snapshot went stale. `issue2223_r5_pubtopic.py` is NEW on main making
a genuinely unrouted call, so a regen would bless the bare call and permanently retire
the check's coverage of that call site. The two remedies are not interchangeable; this
is the task body's explicit warning and acceptance criterion #3.

Note the frozen snapshot is deliberately NOT edited. Once the live tree has zero
offenders, `test_regen_hf_routing_snapshot_live_tree_subset_of_current` is trivially
satisfied (empty set is a subset), so that 4th node goes green as a consequence, not
via a snapshot change.

**Defect 2 — all four scripts, import ordering only (acceptance #4).**

Canonical preamble shape per file:

```python
from __future__ import annotations

import json
import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1] / "src"))

from explore_persona_space.orchestrate.env import load_dotenv  # noqa: E402

load_dotenv()  # shared-VM thread caps (#847) bind BEFORE the first heavy import

import numpy as np  # noqa: E402
import matplotlib.pyplot as plt  # noqa: E402
...
```

Per-file notes:

| File | Current heavy import | Current `load_dotenv(` | Change |
|---|---|---|---|
| `scripts/issue2223_analyzer_figs.py` | numpy @ 27 | none | add bootstrap + call before numpy |
| `scripts/issue2223_r2_analysis.py` | numpy @ 29 | none | same; keep the `issue2223_analyzer_figs` sibling import |
| `scripts/issue2223_r3_domain_ci.py` | numpy @ 35 | none | **also add `import sys` + the `sys.path` bootstrap** — this file has neither today |
| `scripts/issue2223_r5_pubtopic.py` | numpy @ 41 | 214 (inside `fig5_cjk_scan`) | hoist to module top; the in-function import/call becomes redundant and is removed |

`sys.path.insert` must precede the `explore_persona_space` import in every file,
including `r3_domain_ci.py`, which today reaches the package only transitively via its
`from issue2223_analyzer_figs import load_arm` sibling import — that import comes AFTER
the numpy line, so relying on it cannot satisfy the ordering.

**Rejected alternative for defect 2:** adding the four files to
`GRANDFATHERED_TORCH_BEFORE_DOTENV` in `tests/test_shared_vm_thread_caps.py`. Same
"retire the coverage" failure mode as the snapshot regen, and it directly contradicts
acceptance #4 (the fix is import ordering, not a bless-list entry). The grandfather
block is a generated freeze-epoch list with currency tests; new violations do not
belong in it.

**Behavior-preservation argument (acceptance #4).** These are already-run analysis
drivers for a promoted #2223 result. Every changed line is an import statement, a
`sys.path` bootstrap, or the `load_dotenv()` call; no function body, constant,
numeric, or control-flow edit. `load_dotenv()` only setdefaults thread-cap env vars
(never clobbers an explicit value), so hoisting it earlier cannot change any computed
output — it can only cap threads that were previously uncapped, which is the point.

### 8. Risks and Failure Modes

- **Ruff reorders the preamble back.** The PostToolUse ruff auto-fix runs after every
  Edit; `noqa: E402` on each post-bootstrap import is what keeps the ordering legal.
  Mitigation: apply the `noqa` in the same edit as the moved import, then re-run the
  lint. Risk: low, mechanically detected by gate 3.
- **Removing r5's in-function `load_dotenv()` changes nothing but looks like logic.**
  Mitigation: it is redundant once the module-top call exists; the diff comment says so
  and the reviewer checks it against acceptance #4.
- **A concurrent session lands another offender on main mid-round.** Mitigation: the
  Step 10d pre-push gate re-derives the baseline against `origin/main` at merge time, so
  a new offender surfaces as a distinct failure line rather than silently riding along.
- **`sys.path` bootstrap added to r3 shadows a name.** Risk: negligible — it is the
  identical bootstrap the three sibling scripts already run, and the four scripts share
  an import graph.
