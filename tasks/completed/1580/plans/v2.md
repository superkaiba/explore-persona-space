### 4.1 New module constant (near `:170` `WF_FIX_TARGET_KEY`)

```python
# Anchored Provenance fingerprint line: a list item whose FIRST token after the
# bullet is `fingerprint:` + a 12-hex fp (wf_fix_fingerprint shape; trailing
# lookahead per sweep _RECORD_FP_RE). Deliberately does NOT match prose quotes
# ("... its Provenance fingerprint: 44d3..." sits mid-line) — the #1580 fix.
_FP_LINE_RE = re.compile(
    r"(?m)^(?P<indent>\s*)-\s*fingerprint:\s*(?P<fp>[0-9a-f]{12})(?![0-9a-f])(?P<rest>[^\n]*)"
)
```

### 4.2 `ensure_wf_fix_provenance` (:210–232) — rewrite

```python
def ensure_wf_fix_provenance(text: str, target: str, fp: str) -> tuple[str, list[str]]:
    """Idempotently ensure + RECONCILE the wf-fix Provenance lines (#1173, #1580).

    Returns (new_text, actions); actions ⊆ {"target", "fp-inject", "fp-reconcile"};
    empty list == unchanged (truthiness-compatible with the pre-#1580 bool).

    The wf-fix-fp TAG (manifest-computed at the process_item fp) is AUTHORITATIVE
    for the (target_file, fingerprint) dedup key (workflow-fix-on-bug.md § Dedup).
    Body-line policy:
      - no anchored `- fingerprint: <12hex>` line -> inject `- fingerprint: {fp}`.
        Detection is _FP_LINE_RE-anchored, NOT substring: a prose mention of
        'fingerprint:' no longer suppresses injection (#1580's own body).
      - an anchored line already carrying fp -> no-op (idempotent, incl. re-runs
        over a previously reconciled body).
      - anchored line(s) carrying a DIFFERENT fp -> rewritten in place to
        `- fingerprint: {fp} (tag-authoritative; supersedes body-carried
        fingerprint: {old})`. The old value survives as the substring
        `fingerprint: {old}` so sweep _fp_tag_scan and is_open_workflow_fix_task
        (both substring-OR) still suppress re-raises keyed to it; the ONLY
        anchored value is the tag's, so tag and body never disagree.
    workflow_fix_target handling unchanged (substring gate — the recursion-guard
    predicate is itself substring-based).
    Substring contracts (do not reformat): `workflow_fix_target: {target}`,
    `fingerprint: {fp}`, and on a reconciled line `fingerprint: {old}`.
    """
    actions: list[str] = []
    inject: list[str] = []
    if WF_FIX_TARGET_KEY not in text:
        inject.append(f"- workflow_fix_target: {target}")
        actions.append("target")
    matches = list(_FP_LINE_RE.finditer(text))
    if not matches:
        inject.append(f"- fingerprint: {fp}")
        actions.append("fp-inject")
    elif not any(m.group("fp") == fp for m in matches):
        def _reconcile(m: re.Match) -> str:
            return (
                f"{m.group('indent')}- fingerprint: {fp} "
                f"(tag-authoritative; supersedes body-carried fingerprint: {m.group('fp')})"
            )
        text = _FP_LINE_RE.sub(_reconcile, text)
        actions.append("fp-reconcile")
    if inject:
        text = _insert_under_provenance(text, "\n".join(inject))
    return text, actions
```

Notes: (a) `.sub` rewrites ALL mismatched anchored lines, each preserving its own old fp; after one pass every anchored value == tag fp ⇒ second pass is a byte no-op (idempotency by construction — the reconciled line's mid-line `fingerprint: {old}` is not bullet-initial, so `_FP_LINE_RE` matches only the line-start occurrence, group fp = tag fp). (b) Mixed case (one anchored line == fp, another ≠ fp) takes the no-op branch — the tag value is present anchored, the key coherent; documented, not "fixed" (pathological, never driver-produced). (c) The mismatched line's trailing `rest` text is dropped in the rewrite (the old fp is what's load-bearing); documented in the docstring.

Load-bearing DESIGN choices (Sources are in-repo files/rules/incidents, per the brief):

**D1 — Reconcile semantics: labeled dual-value rewrite (tag anchored + old fp as substring), not pure overwrite, not fail-loud, not tag-adopts-body.**
- *What:* on anchored-line mismatch, rewrite to `- fingerprint: {fp} (tag-authoritative; supersedes body-carried fingerprint: {old})`.
- *Why:* the four options score: (a) **pure overwrite** destroys the body-carried fp — but that value is the ONLY key that suppresses a re-parked candidate in the sweep (`_fp_tag_scan` matches `fingerprint: {old}` substring; the candidate's fp is computed from its block fields, `sweep_parked_wf_candidates.py:269`) and one of two keys in `is_open_workflow_fix_task` (:1075) — overwriting converts a working suppression into nightly re-enumeration and, downstream, a duplicate filing; (b) **fail-loud** ERRORs the COMMON legitimate case — 18/18 recent filings carried a body fp because the /daily body-file template mandates the candidate-block fp line — making route 2 unusable for parked-candidate-derived items; (c) **tag-adopts-body** would re-key the ledger/recovery/dedup fp on a mutable body read instead of the deterministic manifest fields (`:944` feeds `_slug_state` resume rows, dry-run, and recovery BEFORE any body read) — larger blast radius, and it breaks next-night same-manifest dedup; (d) the **dual-value rewrite** keeps both suppression keys live, leaves exactly one anchored value (= tag, so tag and body can never disagree — the Goal's invariant), and costs ~10 lines.
- *Source:* clarifier marker on #1580 (2026-07-21, the sweep OR-matching weigh-in); `scripts/sweep_parked_wf_candidates.py:419`; `src/explore_persona_space/task_workflow.py:1073–1077`; incident #1554–#1571/#1579 (the 18/18 base rate that kills fail-loud).
- *Alternatives:* enumerated above; pure overwrite is the documented fallback if a consumer requiring a single fp-shaped string surfaces (Kill criteria).
