# Plan v2 — #1913 workflow-fix: SLURM rsync races the live shared tree

## 0. TL;DR

The SLURM lane's dispatch-time rsync sources the LIVE shared working tree whenever
`repo_branch` is absent/`main`/already-on-branch (`_resolve_rsync_source`,
`backends/slurm.py:2717-2723`), so a concurrent mutation window (pre-commit
stash/restore, `sync_repo_root.py` autostash rebase) can ship a PARTIAL tree with
rsync exit 0 — job 15993 + 16097 on #1689 each died in ~45s on a missing committed
entrypoint (`epm:run-launched v13` on #1689 confirms `repo_branch=None` → repo-root
working tree, file tracked + un-excluded, misses transient; that note explicitly
delegates the durable fix to #1913). Fix BOTH ways the body proposes:

1. **Snapshot source (robust):** ALWAYS rsync from a materialized committed-tree
   snapshot — extend `_resolve_rsync_source` to route the absent/`main`/
   already-on-branch cases through the existing `materialize_branch_src` seam
   (detached scratch worktree at the resolved commit; reads only the append-only
   object DB, immune to working-tree churn by construction). Non-main-branch
   dispatches already do exactly this.
2. **Post-sync verify (cheap, defense-in-depth):** after the main + extra rsyncs,
   re-run the same rsync argv in `--dry-run --itemize-changes` mode from the
   now-immutable snapshot; any pending FILE transfer (`^<f` itemize line) ⇒ raise a
   typed `rsync_partial_tree` error BEFORE sbatch (router wraps it as
   `BackendPrepareError` → auto-chain lane advance). Runs entirely through rsync, so
   the fellows/DRAC forced-command allowlist (sbatch/scancel/squeue/scp/rsync) is
   respected.

## 1. Requirement + acceptance criteria (kind: infra)

Requirement (task Goal): a SLURM dispatch either ships a CONSISTENT tree or fails
loud BEFORE sbatch — never a silent partial sync discovered by the workload's crash.

Acceptance criteria:
- A1. No `prepare()` path rsyncs the live `self._src_root` working tree by default:
  every dispatch (repo_branch absent / `main` / already-on-branch / other-branch)
  sources from a materialized snapshot tree.
- A2. A post-sync verify runs after the main rsync AND after the extra-paths rsync
  (#1835) when present; a non-empty pending-file-transfer list raises a typed error
  whose message carries the token `rsync_partial_tree`, and `sbatch` (the submitter
  seam) is never reached in that case.
- A3. Escape hatches: `EPS_SLURM_LIVE_TREE_RSYNC=1` restores the legacy live-tree
  source (deliberate operator override, logged loud); `EPS_SLURM_SKIP_RSYNC_VERIFY=1`
  skips the verify (logged loud). Both default OFF.
- A4. Existing behavior preserved elsewhere: non-main branch materialization,
  `_assert_repo_branch_synced` (#1609 commit-equality fallback), extra-sync path
  validation (#1835), secrets push, runtime-artifact clear, reconnect/poll paths —
  all byte-equivalent.
- A5. Tests: new/updated unit tests cover the routing change, the kill switches, the
  verify pass/fail behavior (submitter not called on fail), and at least one
  REAL-BODY test of the new verify helper (local rsync round-trip shape, per
  `test_rsync_round_trip_preserves_external_prefix`) — no seam-stub-only coverage
  of new function bodies (code-style: one production-body test per stubbed function).

## 3. Design

### 3.1 Snapshot source (`_resolve_rsync_source`)

```python
def _resolve_rsync_source(self, spec: RunSpec) -> Path:
    requested = str(spec.extra.get("repo_branch") or "").strip() or "main"
    if os.environ.get("EPS_SLURM_LIVE_TREE_RSYNC") == "1":
        logger.warning("EPS_SLURM_LIVE_TREE_RSYNC=1 — legacy LIVE-tree rsync source (...)")
        # legacy behavior verbatim: src_root for main/absent/already-on-branch,
        # cloner otherwise (the pre-fix body of this method)
        ...
        return ...
    return self._git_cloner(src_root=self._src_root, branch=requested, issue=spec.issue)
```

- `materialize_branch_src(branch="main")` needs NO signature change — step 3 resolves
  the local `main` ref, then `origin/main` (same order as any branch). The
  already-on-branch case materializes at the local branch ref, which by definition
  equals the worktree HEAD it previously live-rsynced.
- The scratch tree (`~/.eps-slurm-src/issue-<N>`) shares the object DB (no history
  copy). `git worktree add --detach <scratch> <commit>` reads the append-only object
  DB with its OWN index — concurrent stash/restore on the shared root cannot corrupt
  it. Per-issue scratch + the Step-0 single-orchestrator guard exclude same-issue
  concurrent materialization.
- Behavior change (documented in the docstring + this plan): main/absent/
  already-on-branch dispatches now ship COMMITTED-ONLY trees — an untracked/
  uncommitted file under the include set no longer ships. This matches the GCP
  clone lane and the project's committed-scripts-only dispatch contract (Step 6a.5
  carry-over gate; "ad-hoc probe workloads are committed scripts"). The
  `external/open-instruct` gitlink still ships via the existing
  `WORKING_TREE_OVERLAY_PATHS` overlay.
- Accepted cost: a full checkout (~3.8 GB, shared object DB, ~30-90 s) now also runs
  for main-lane dispatches — identical to the existing branch-dispatch cost;
  the prior-scratch removal in `materialize_branch_src` keeps it to one tree per
  issue. Sparse materialization (include-set cones only, ~0.4 GB) is a DEFERRED
  optimization — not in this diff unless the implementer finds it trivially safe;
  it must then also cover `extra_sync_paths` cones.

### 3.2 Post-sync verify (`verify_rsync_complete`, module-level helper + seam)

- New helper in `backends/slurm.py`:
  `verify_rsync_complete(*, src_root, dest_root, robot_alias, include_paths=RSYNC_INCLUDE_PATHS, exclude_patterns=RSYNC_EXCLUDE_PATTERNS, timeout=600) -> None`
  — builds the SAME argv as `build_rsync_command` (reuse it), inserts
  `--dry-run --itemize-changes`, runs with `cwd=src_root`, parses stdout: any line
  matching `^<f` (pending file transfer to remote) ⇒ collect. Non-empty ⇒
  `raise RuntimeError("rsync_partial_tree: N file(s) missing from cluster scratch after sync: <first ≤10 paths>")`.
  Directory-metadata lines (`.d..t...`, `cd+`) and `*deleting` lines are tolerated
  (extra/stale dest files do not break the workload; missing files do).
- Extra-paths twin: `verify_extra_rsync_complete(...)` mirroring
  `build_extra_rsync_command` (or one helper taking the built argv — implementer's
  choice), called only when `extra_sync_paths` present.
- `prepare()` order: clear_runtime → main rsync → extra rsync (if any) →
  verify(main) → verify(extra, if any) → push secrets.
- Injection seam: `SlurmBackend.__init__(..., rsync_verifier=None)` →
  `self._verify_rsync = rsync_verifier or verify_rsync_complete` (existing seam
  convention; tests inject recorders/raisers).
- Cost: one extra rsync dry-run round-trip per dispatch (~seconds; delta-scan only).
- With a snapshot source the verify is non-racy by construction (source immutable);
  under the legacy kill switch it still runs (racy but better than nothing).
