### 4.1 Arm A — `check_smoke_fixture_size` (id `c65_smoke_fixture_size`)

**Name string:** `"smoke-fixture size claim vs realized fixtures"`. **Grade:** FAIL on a file-confirmed contradiction; WARN on constant-only evidence; SKIP everywhere unresolvable. **Kind scope:** all kinds (`del kind`, the c42 pattern) — smoke fixtures appear in experiment and infra plans alike.

**Claim grammar (conservative, three conjuncts on ONE fence-masked line).** A line triggers only when ALL of:

1. it matches `(?i)\bsmoke\b`;
2. it matches a fixture-ish noun `(?i)\b(?:fixture|slice|corpus|corpora|sample)s?\b`;
3. it matches a floor-shaped row count — one of the alternates below (the captured integer is the claimed floor `F`, capped at 6 digits):

```python
_C65_FLOOR_RE = re.compile(
    r"(?:≥|>=|\bat least\b)\s*(\d{1,6})\s+rows?\b"          # "sized ≥ 40 rows", "at least 40 rows"  # noqa: RUF001
    r"|\b(?:fixture|slice|sample)s?\s+of\s+(\d{1,6})\s+rows?\b"  # "smoke slice of 40 rows"
)
```

The v16 incident line (fenced here so this plan never self-triggers post-landing):

```
the smoke fixture slice is sized ≥ 40 rows per smoke corpus so the whole-group packer has resolution
```

satisfies all three conjuncts with F = 40. Fenced lines never trigger (`_fence_mask`); multiple claim lines are each evaluated and the worst grade wins.

**Constant-form claim (best-effort evidence arm, per the clarifier).** A RAW scan (fences included — constants are usually quoted in fenced code) for `_C65_CONST_RE = re.compile(r"\b(SMOKE_[A-Z0-9_]*(?:_N|_ROWS|_SIZE))\s*=\s*(\d{1,6})\b")` (matches `SMOKE_SAMPLE_N = 40`). A constant-form claim alone (no prose floor line) also arms the check, but constant-derived contradictions are WARN-grade only — a constant is one indirection removed from the fixtures (the script may clamp/branch on it), so it is never FAIL evidence.

**Fixture path extraction (what to resolve).** RAW plan-wide scan (fences included, the c41 raw-scan doctrine) for smoke-fixture path tokens — a repo-relative path with a data extension whose dir or file component contains `smoke`:

```python
_C65_GLOB_RE = re.compile(
    r"\b((?:[\w.*-]+/)*[\w.*-]*smoke[\w.*-]*/[\w./*-]+\.(?:jsonl|json|csv|tsv|txt|parquet)"  # smoke in a dir component
    r"|(?:[\w.*-]+/)+[\w.*-]*smoke[\w.*-]*\.(?:jsonl|json|csv|tsv|txt|parquet))\b"           # smoke in the filename
)
```

Absolute paths and any token containing `..` are refused (side-effect-free, repo-rooted only). No path token found → SKIP (`fixture path not named — claim not mechanically checkable`), the designed real-v16-from-main outcome.

**Resolution ladder (first rung with ≥ 1 counted file wins; each rung read-only):**

1. **Repo-root working tree:** `sorted(_C65_REPO_ROOT.glob(rel_glob))`, files only.
2. **Pinned-tip git tree:** only when the plan cites a pinned tip — RAW scan for `(?i)(?:pinned\s+)?tip\s+`` `?([0-9a-f]{8,40})` — then per glob: `git ls-tree -r --name-only <sha> -- <glob-dir-prefix>` (one subprocess), fnmatch-filter, then `git cat-file blob <sha>:<path>` per match. Subprocess contract copied from c42: `timeout=10`, `cwd=_C65_REPO_ROOT`, retry-once on `OSError`, `check=False`; any git unavailability makes THIS RUNG unresolved (ladder continues) rather than SKIPping the whole check. Wrapped in two small helpers (`_c65_tip_sha`, `_c65_git_tree_counts`) so tests can monkeypatch without building a git repo.
3. **Issue worktrees (bounded):** task number from the plan's own H1 (`(?im)^#.*?task\s+#(\d+)`); when present, glob `_C65_REPO_ROOT/.claude/worktrees/issue-<N>*` (the base dir + suffixed variants, ≤ 8 dirs) and join each with `rel_glob`. No H1 task number → rung skipped. This rung is what WOULD have resolved v16's gitignored worktree-local fixtures had v16 named the glob, and it works identically in `--plan-file` mode (the number comes from the plan text, not task context).

**Row counting (wc -l parity, bounded):** read ≤ `_C65_READ_CAP = 8 * 1024 * 1024` bytes; count = number of `b"\n"` (+1 when nonempty and not newline-terminated). A file larger than the cap yields a LOWER BOUND: if bound ≥ F it counts as a resolved-satisfying file; otherwise the file is excluded as unresolved (never FAIL on a truncated count). ≤ 32 files counted per rung (hard bound).

**Verdict table:**

| Situation | Verdict |
|---|---|
| no claim line and no constant-form claim | SKIP `no smoke fixture size claim detected` |
| standalone escape declared (see below) | PASS `explicit N/A declared` (the c11 convention) |
| files resolved at some rung; every claimed F ≤ min(rows) | PASS (detail names rung, file count, min) |
| files resolved; some F > min(rows) | FAIL — detail names the claim line, F, the winning rung, per-file counts, and the remedy (fix the claim, list the producing script change, or declare the escape unwrapped) |
| no files resolved; repo constant found; F > constant value | WARN (best-effort constant evidence; detail says so) |
| no files resolved; repo constant found; F ≤ constant | PASS (detail flags constant-only evidence) |
| nothing resolves at any rung | SKIP `fixture path unresolvable from working tree / pinned tip / issue worktrees` |

**Standalone escape phrase (family-consistent, unwrapped):** `N/A — no smoke fixture size claim` via `_standalone_na_declared(plan, r"no smoke fixture size claim\b")` — the matcher-over-fire hatch.

**Constant lookup in the repo (for the constant-evidence row):** pure-Python bounded scan of `_C65_REPO_ROOT/scripts/*.py` (non-recursive, ≤ 2,500 files, ≤ 1 MB read per file) for `^\s*<CONST>\s*=\s*(\d+)` — runs ONLY when a constant-form claim fired (rare). Chosen over `git grep` for testability (a `tmp_path` fixture root needs no git init) and consistency with the no-side-effects contract; cost when firing ≈ 100–200 ms, zero when not firing.

### 4.2 Arm B — `check_smoke_producer_coverage` (id `c66_smoke_producer_coverage`)

**Name string:** `"smoke-fixture producing script named in plan"`. **Grade:** WARN-only. **Kind scope:** all kinds.

**Trigger:** Arm A's claim grammar fired AND the realized evidence CONTRADICTS the claim (file-resolved min < F, or constant value < F). When Arm A resolved nothing, Arm B SKIPs (`realized evidence unresolved — cannot adjudicate whether a producing-script change is needed`, the c37 membership doctrine); when Arm A PASSed on resolved evidence, Arm B SKIPs (`claim satisfied by realized fixtures — no producing-script change required`). This implements the task body's "when Arm A's claim can only be satisfied by changing a producing script" as a knowable predicate.

**Producing-script identification (two routes, both bounded to `scripts/*.py`):**

1. constant-form claim → the file(s) defining the constant (from the 4.1 scan);
2. glob-form claim → the glob's most distinctive component containing `smoke` (last dir component, else the filename stem; require length ≥ 6) scanned for as a literal substring in `scripts/*.py` (same bounded scan).

No candidates found (e.g. the producing script lives only on an unmerged branch, the real-v16 case from main) → SKIP (`producing script not identifiable in scripts/`).

**Coverage predicate (the design decision, stated):** the task body's "plan's declared new/modified-code list" is approximated by **named anywhere in the plan text** (RAW scan for the candidate's basename or repo-relative path). Rationale: the incident shape was ZERO mentions (`issue1336_stage_corpora` appears zero times in v16 while §4 said "Nothing else changes"), modified-file lists are free prose across plan styles, and mention-anywhere-passes is the maximally conservative WARN-minimizing reading — criterion 4 (script listed in the modified-file list ⇒ pass) is a strict subset. Any candidate mentioned → PASS; ALL candidates absent → WARN naming them (detail: "the claimed floor exceeds the realized fixtures and the script(s) that produce them — `<paths>` — appear nowhere in the plan; add the change to the modified-file list, or declare the escape").

**Standalone escape phrase:** `N/A — no fixture-producing script change needed` via `_standalone_na_declared(plan, r"no fixture-producing script change needed\b")`.

**Shared evaluation:** both checks call one internal helper `_c65_evaluate(plan) -> _C65Eval` (a `NamedTuple`: claims, glob tokens, resolved file counts + winning rung, constant evidence, producing candidates). No cross-call memoization — the ladder only runs when a claim fired, the cost is bounded (~ms non-firing, ~100–300 ms firing), and a memo keyed on plan text would poison across tests that monkeypatch `_C65_REPO_ROOT` between calls with identical plan strings.
