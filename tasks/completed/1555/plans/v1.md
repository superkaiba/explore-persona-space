## 11. Decision Rationale

**Recipe-class key = the adapter's own `adapter_config.json` fields: (`use_rslora`, `lora_alpha`, `r`) PLUS `target_modules`; apply stack held fixed by the existing "on the CURRENT stack" clause.**
- **What:** adapters sharing all four config fields form one class → one probe; any field differing splits the class. A plan applying adapters through two different stacks (e.g. PEFT merge vs vLLM LoRA hot-load) has two "current stacks" and therefore probes per stack already under the existing clause — no new text needed for that axis.
- **Why the scaling fields:** they determine the scaling multiplier AND which apply branch executes; the #601 failure class (classic-`α/r` parent read at `α/√r` under honored `use_rslora`) is keyed entirely on them — a probe on a classic class exercises a different branch than an rsLoRA class, so a cross-class PASS transfer is unfounded. **Source:** artifact-reuse.md check (g) text itself (the fields it already reads, per #545's adapter_config.json grounding); incident #601 (all 20 of #472's reused adapters HALTed Phase-0 as repeaters — critic-lens-reference.md lines 142–144).
- **Why `target_modules` too:** the probe's PASS criterion is "reproduce the parent's committed numbers", and committed reference values are commensurable only within a module set — #813's calibration section records a 19× magnitude gap between two CORRECT adapters differing only in module set (7-module em write-ratio 0.1729 vs 4-module attention-only marker 0.00903, artifact-reuse.md lines 536–542); the same section already keys per (behavior, adapter-class) (lines 531–532). `target_modules` is read from the same `adapter_config.json` — zero extra verification cost. **Source:** artifact-reuse.md § Reuse-validation gate calibration (#813); precedent shape `041383903d` (#1543).
- **Why behavior is NOT in the probe-count key:** the probe validates the APPLY path (structural); the behavior axis stays where #813 put it — threshold calibration per (behavior, adapter-class), unchanged by this edit.
- **Alternatives rejected:** (i) scaling-fields-only key — misses the #813 commensurability problem across module sets, and the split costs one cheap probe; (ii) per-parent-issue key — over-fragments (recipe-identical adapters from two parents exercise the identical apply path; parent-lineage concerns are checks (d)/(k)'s job); (iii) per-adapter probing — defeats the "1-adapter" cheapness that makes (g) run in practice.
