## 1. Goal

(Task #1650 Goal, verbatim.) "(1) Add a poller-side pid-identity check to
`scripts/poll_pipeline.py` so a fresh-but-wrong pid file is runtime-detectable;
(2) reconcile the experimenter agent-memory `feedback_pgrep_self_match_pidfile.md`
with the new clause 1d so it no longer prescribes the partially-superseded
pgrep-based relaunch pid resolution."

**Requirement.** Today `poll_once` trusts the pid FILE pid and the marker pid
blindly: a fresh-but-WRONG pid (transient sibling captured at launch, or a
recycled pid) probes alive/dead with zero cmdline verification, producing false
`status=dead` (two false monitor alarms 2026-07-23, the #1112 relaunch) or a
silent false-alive. Add (a) cmdline capture + identity classification of the
probed pids against the launch signature the `epm:run-launched` marker carries,
and (b) a bracketed pattern-probe rescue arm so a true-alive run whose pid file
AND marker pid are both wrong-and-dead no longer verdicts `dead`. Then rewrite
the stale experimenter memory so it leads with clause 1d's launch-expression
acquisition rule instead of prescribing pgrep-based relaunch pid resolution.

**Acceptance criteria.**
1. New pure predicates in `scripts/poll_pipeline.py` (unit-testable, no SSH):
   signature-token extraction from the marker note, pid-identity classification
   (`match|mismatch|unknown`), bracketed pgrep-pattern derivation.
2. `_ssh_probe` gains the cmdline + signature-probe lines INSIDE its existing
   single heredoc (no second SSH round-trip per tick).
3. Verdict semantics exactly as §4 step 5: the ONLY verdict-affecting change is
   the alive-direction rescue OR-arm; identity mismatch is WARN + tick-JSON
   flag only. A marker with no parseable `cmd=`/`launcher_script=` field (the
   COMMON live case — verified: #1112/#952/#825 notes are free prose; only
   #1092 carries `cmd=`) produces byte-identical verdicts to today.
4. Memory file rewritten in place (same path, same frontmatter shape); the
   `MEMORY.md` index hook line updated.
5. `uv run ruff check` clean on touched files; `uv run python
   scripts/workflow_lint.py` (no-flags) passes; new + named existing pytest
   anchors green.

**Step 2 — pure predicates (placed after `_maybe_warn_stale_pid_file`).**
```python
def _launch_signature_tokens(note: str, issue: int) -> tuple[str, ...]:
    """Path-like basenames from the marker's cmd='...' + launcher_script= fields.
    Empty tuple when neither field parses (legacy prose markers) — every
    downstream consumer is inert on empty."""
    # collect cmd string (first non-None regex group) + launcher_script value;
    # split on whitespace and shell metachars (>, <, &, ;, |);
    # keep tokens containing "/" or ending in .sh/.py; os.path.basename();
    # drop _SIG_GENERIC_TOKENS members and tokens < 6 chars; dedupe, keep order.

def _classify_pid_identity(cmdline: str, tokens: tuple[str, ...], issue: int) -> str:
    """'unknown' | 'match' | 'mismatch'. unknown when cmdline blank OR tokens
    empty (legacy marker / dead pid / ps unavailable). match when any token is
    a substring of cmdline OR the issue-token fallback re.search(
    rf"issue[-_]?{issue}\b", cmdline) hits (covers an exec'd workload like
    'python scripts/issue1092_dispatch.py' whose cmdline shares no basename
    with the cmd= launcher string). else mismatch."""

def _sig_pgrep_pattern(tokens: tuple[str, ...]) -> str | None:
    """Bracketed pgrep -f pattern from the LONGEST token whose last char is
    alphanumeric: re.escape(tok[:-1]) + '[' + tok[-1] + ']'. None when no
    usable token — pod-side sig probe is then omitted entirely. The bracket is
    the gotchas.md self-match idiom: the probing remote shell's own cmdline
    carries the bracketed literal, which the regex does not match."""
```

```python
def _maybe_warn_pid_identity(*, issue, pod, pid_file, probe, sig_tokens,
                             pidfile_pid_alive, marker_pid,
                             marker_pid_alive) -> tuple[str, str]:
    """Returns (pid_identity, marker_pid_identity). WARN-only; whole body in
    try/except → log.debug + ("unknown", "unknown") — a broken classifier must
    never break a tick (#1156 precedent). Classifies ONLY alive pids (a dead
    pid's cmdline is empty ⇒ unknown). On 'mismatch' logs one WARN per tick
    naming the pid, its cmdline (log-only — cmdline text is deliberately NOT
    placed in PollResult/tick JSON), the derivation tokens, and the recovery
    recipe (rewrite pid file + re-post epm:run-launched, pod-side-reporting.md
    § Pid-file launch contract item 1/1d)."""
```

**Step 5 — verdict wiring (`poll_once`, L4952 + L4974–4989).**

```python
sig_tokens = _launch_signature_tokens(marker_note, issue)
sig_pattern = _sig_pgrep_pattern(sig_tokens)
probe = _ssh_probe(pod, log_path, pid_file, issue, marker_pid,
                   stall_sec=stall_sec, sig_pattern=sig_pattern)

pidfile_pid_alive = probe["pid_alive"] == "1"
marker_pid_alive = marker_pid is not None and probe["marker_pid_alive"] == "1"
sig_proc_count = _parse_probe_count(probe.get("sig_proc_count")) or 0
```

**Exact verdict-semantics table (which combinations change `status`):**

| Scenario | Today | After | Change class |
|---|---|---|---|
| pidfile+marker pids dead, sig probe finds live match (fresh-but-wrong pid, run healthy — #1112) | `dead` (false) | `running`/`stalled` via liveness arbiters + rescue WARN | VERDICT (alive-direction only) |
| pidfile pid ALIVE but cmdline mismatches signature (recycled/wrong-but-alive pid) | `running` (silently false-alive) | `running` + mismatch WARN + `pid_identity="mismatch"` flag | WARN/flag only |
| marker pid alive, identity mismatch | as today | + WARN/flag (`marker_pid_identity`) | WARN/flag only |
| legacy marker (no `cmd=`/`launcher_script=`) — the common live case | any | byte-identical verdict; all new fields `unknown`/`False`/`0` | none |
| SSH failure / missing keys / unreadable ps | any | inert defaults, verdict as today | none |
| `done`-parse + rescue-alive + no results sentinel | n/a (pid dead ⇒ done corroborated) | #545 demotion treats rescue-alive as alive ⇒ done demoted to mid-run noise — consistent: a live signature-matched dispatcher means the run is not finished | VERDICT (safe direction: blocks a premature done) |

**Why no false `dead` can be introduced, incl. on legacy markers:** `dead`
requires `not pid_alive`; every new term enters `pid_alive` via OR — the new
code can only ADD liveness, never remove it. Identity mismatch deliberately
does NOT demote `pidfile_pid_alive` (§11 row 1): demotion would risk a false
`dead` exactly when signature derivation fails on a healthy run (e.g. an
exec'd workload with no issue-keyed token), and the false-alive class it would
fix already self-corrects to `stalled` within `stall_sec` via the existing
logs-stale + GPU-idle + CPU-flat conjunction. On legacy markers `sig_tokens`
is empty ⇒ no sig probe is built, both identities read `unknown`, and
`pid_alive` reduces to today's exact expression.

## 7. Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| False-dead regression | ~zero by construction | all new liveness terms are OR-only; mismatch never demotes; test 6 + 7 pin it |
| False-ALIVE from rescue: stale same-signature predecessor masks a real death | low | signature is issue-scoped + specific-token; experimenter pre-launch hygiene kills same-issue stragglers; a masked death still lands `stalled` within `stall_sec`; rescue WARN names matched pids every tick |
| Legacy-marker compat: prose notes (most live markers) | certain to occur | empty-token ⇒ fully inert path; test 7 |
| SSH probe cost | negligible | 2 `ps` + 1 `pgrep` lines inside the existing single heredoc (<10 ms pod-side); no second round-trip (test 9) |

## 11. Decision Rationale

N/A — no model training (no hyperparameters; rows below are design choices).

1. **Mismatch = WARN + flag only; never demotes `pid_alive`.**
   Why: demotion introduces false-`dead` risk exactly when token derivation
   fails on a healthy run (exec'd workloads without issue-keyed cmdlines),
   while the false-alive class it targets already self-corrects to `stalled`
   within `stall_sec` (L5158 conjunction). Detection without verdict risk
   matches the sibling detector. Source: #1156 (observability-first WARN
   contract, `_maybe_warn_stale_pid_file` docstring); #545/#518 status-ladder
   reads (L5152–5178). Alternatives: identity-verified liveness demotion
   (rejected — false-dead risk, the exact #1112 alarm class this task exists
   to reduce); demote-only-with-positive-elsewhere-evidence (rejected — under
   that gate `pid_alive` stays True via the rescue arm anyway, so it changes
   nothing).
2. **Rescue arm IS verdict-affecting (third OR into `pid_alive`).**
   Why: the #1112 class (fresh-but-wrong pid in BOTH file and marker) defeats
   the existing marker-pid rescue; alive-direction-only means no false dead by
   construction; a wrongly-rescued dead run degrades to `stalled` within
   `stall_sec`. This implements clause 1d(b)'s pattern-probe-alongside-pidfile
   shape as a detection read. Source: #1112 incident +
   `.claude/rules/pod-side-reporting.md` 1d(b) + #451/#521 OR-probe precedent
   (L4947–4976). Alternatives: WARN-only rescue (rejected — leaves the false
   `dead` verdict standing, the concrete harm observed twice on 2026-07-23).
3. **Signature source = marker `cmd='...'` + `launcher_script=` fields, with
   an issue-token cmdline fallback matcher.** Why: the marker is the poller's
   existing per-tick task-state read (no new channel); `cmd=` is the
   documented convention (experimenter.md L978–982) and `launcher_script=` is
   live practice (#1092); the issue-token fallback covers exec'd workloads
   whose cmdline shares no basename with the dispatch string. Source:
   experimenter.md launch-marker spec; live #1092 marker note. Alternatives:
   derive from `pid_file`/`log_path` basenames only (rejected — those are
   generic `issue-<N>.*` tokens, weaker discrimination); a new marker field
   (rejected — schema change, out of scope).
4. **Bracket convention** = `re.escape(tok[:-1]) + "[" + last_char + "]"` on
   the single longest token. Why: house self-match idiom; one pattern keeps
   the pgrep cheap and the WARN legible. Source:
   `.claude/rules/gotchas.md` ownership-probe convention as quoted in
   crash-fix-rounds.md § Kill-before-relaunch; pod-side-reporting.md 1d(a).
   Alternatives: `pgrep -fx` exact-match (rejected for the POLLER: the poller
   does not know the exact full cmdline — exact-match is the memory's
   acquisition-era recipe and stays in the memory's recovery-role text).
5. **Cmdline text log-only, never in tick JSON.** Why: PollResult/tick JSON
   feeds orchestrator context on every tick; enums/bools are sufficient and
   keep trigger-dense digest guarantees untouched. Source: #1556
   (`log_tail_digested` design), PollResult field comments L1149–1156.
6. **Single-read marker refactor (`_marker_launch_fields`) with `_marker_pid`
   kept as wrapper.** Why: preserves the per-tick events-read budget and
   existing test imports. Source: L5220–5224 one-read-per-tick comment;
   #1156 test file imports.
