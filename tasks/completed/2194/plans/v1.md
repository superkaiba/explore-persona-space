### Step 1 — the convention (decision, no code)

- **Key:** `phase`. **Type:** `str`. **Placement:** INSIDE the reproducibility-card / metadata block, as a SIBLING of the commit key — the exact level `check_code_sha_cards._walk` reads (`obj.get("phase")` where `obj` holds `git_commit`). A top-level `phase` beside a nested card block is NOT the convention (measured to be invisible: the #2162 stage2 shape).
- **Value shape:** lowercase slug `^[a-z0-9]+([-_][a-z0-9]+)*$`; kebab-case preferred; RECOMMENDED to equal the driver's own `--phase` argument / `[phase=...]` breadcrumb token (realized examples: `bank`, `anchors`, `grid`, `margin`, `stage2-upload`, `upload_tbmp`). Free string, NOT a controlled cross-issue vocabulary (phases are per-issue pipeline stages; a global vocabulary would be vacuous or perpetually stale) — the exact-match channel makes pairing mechanical without one, since the report author copies the card's own phase string into the Code-SHAs row label.
- **Collision fence:** lifecycle-state values are REFUSED at write time (denylist `{done, failed, running, pending, queued, started, workload}`). Top-level `phase` in backend sentinels (`backends/artifacts.py:493` et al.) stays the LIFECYCLE vocabulary; card-block-interior `phase` is PHASE IDENTITY. Both facts get documented (step 3).

### Step 2 — writer side: `src/explore_persona_space/orchestrate/provenance.py`

(a) **Phase emission + validation** (additive):

```python
_PHASE_IDENTITY_RE = re.compile(r"^[a-z0-9]+([-_][a-z0-9]+)*$")
_LIFECYCLE_PHASE_VOCAB = frozenset(
    {"done", "failed", "running", "pending", "queued", "started", "workload"}
)

def validate_phase_identity(phase: str) -> str:
    """Validate a card phase-IDENTITY slug; returns it verbatim or raises ValueError.

    Phase identity names the pipeline stage a reproducibility card belongs to
    ("stage2-upload", "grid-anchors") — NOT lifecycle state: backend sentinels
    use top-level {"phase": "done"} for state (backends/artifacts.py), a
    different vocabulary at a different level, and those values are refused
    here so the two can never be confused. Fail-loud is deliberate: the value
    is a hardcoded literal at the call site, so a violation is a programming
    error, not runtime degradation (the module's never-crash contract covers
    environment failures, not caller-contract violations).
    """
    if not isinstance(phase, str) or not _PHASE_IDENTITY_RE.fullmatch(phase):
        raise ValueError(f"phase identity must match {_PHASE_IDENTITY_RE.pattern!r}: {phase!r}")
    if phase in _LIFECYCLE_PHASE_VOCAB:
        raise ValueError(
            f"phase identity {phase!r} collides with the backend-sentinel LIFECYCLE "
            "vocabulary — name the pipeline stage instead (e.g. 'stage2-upload')"
        )
    return phase

def as_metadata_dict(prov: GitProvenance, *, phase: str | None = None) -> dict[str, object]:
    out: dict[str, object] = {
        "git_commit": prov.commit_sha_full or prov.commit_sha,   # see (b)
        "git_dirty": prov.dirty,
    }
    if phase is not None:
        out["phase"] = validate_phase_identity(phase)
    # ... existing dirty_paths / argv0 fields unchanged ...
```

Add `import re` to the module imports (in the same edit as its first use — the PostToolUse F401 stripper).

(b) **Full-hex `git_commit`** (the gate-usability fix): add `commit_sha_full: str | None = None` as the LAST field of the frozen `GitProvenance` dataclass (positional constructions in tests stay valid); replace the body of the HEAD probe with one full `rev-parse HEAD` call:

```python
def _git_head_sha(cwd: Path | None = None) -> tuple[str, str | None]:
    """(short 8-hex, full 40-hex | None); ('unknown', None) on any failure."""
    out = _run_git(["rev-parse", "HEAD"], cwd=cwd)
    full = out.strip() if out is not None else ""
    if not full:
        return _UNKNOWN, None
    return full[:8], full

def _git_short_sha(cwd: Path | None = None) -> str:
    """Kept for the paper_plots deprecated shim; returns the 8-hex short form."""
    return _git_head_sha(cwd=cwd)[0]
```

## 11. Decision Rationale

**D1 — Field name + placement: `phase`, inside the card block, sibling of the commit key.**
*Why:* it is the exact level the consumer already reads — no consumer schema change needed for collection; and it structurally dodges the lifecycle collision (backend sentinels use TOP-LEVEL `phase` for state; no sentinel shape puts a commit key beside it).
*Source:* read `scripts/verify_report.py:1291` (verbatim: `(source, f"{ptr}/{k}", v, obj.get("git_dirty"), obj.get("phase"))` — `obj` is the dict holding the commit key) + `src/explore_persona_space/backends/artifacts.py:493` (`"phase": "done",`); #2191.
*Alternatives:* top-level `phase` (rejected — measured invisible for nested-card writers, `issue2162_stage2.py:330`, and collides with the sentinel lifecycle vocabulary); a new key name like `pipeline_phase`/`stage` (rejected — the consumer already reads `phase`, and #2191's `_card_side_tokens` already folds it; renaming would need consumer changes for zero gain).

**D2 — Naming convention: free lowercase kebab/snake slug, validated shape + lifecycle denylist; no controlled vocabulary.**
*Why:* phases are per-issue pipeline stages (`bank`/`anchors`/`grid`/`margin` for #2162; entirely different elsewhere) — a cross-issue controlled vocabulary is either vacuous or perpetually stale; what makes b3 pairing mechanical is the EXACT-MATCH channel (report label == card phase string, mod case/punctuation), not vocabulary control. The shape validator + denylist give machine-checkable uniformity without central registry.
*Source:* measured realized phase names — `issue2162_stage2.py:330` (`stage2-upload`), `issue2162_run.py` `--phase {bank,anchors,grid,margin,upload}`, `issue2162_tbmp.py` `[phase=upload_tbmp]`; `backends/artifacts.py:493` for the denylist.
*Alternatives:* controlled enum (rejected above); no validation (rejected — a `phase: "done"` card would be ambiguous against sentinel vocabulary forever; a malformed value silently degrades the exact channel).

**D3 — Retrofit scope: forward-only (shared helper + rules + consumer); no per-issue-script edits.**
*Why:* (i) cards already on disk/branches cannot be changed by editing the scripts that wrote them — retrofit buys nothing for existing gate runs; (ii) per-issue scripts are frozen historical reproducibility artifacts (the `HF_ROUTING_FROZEN_SNAPSHOT` treatment class); (iii) in-flight drivers (#2223/#2333/#1739 rounds) are live-session-owned — editing them violates cross-session writer arbitration; (iv) the degrade ladder keeps phase-less cards working indefinitely, so adoption is incremental by construction. The binding surface for FUTURE writers is the mandated shared helper + the code-style rule.
*Source:* `.claude/rules/code-style.md` § "Dirty-tree flag" (mandates `provenance.py` for new writers); `.claude/rules/cross-session-writer-arbitration.md`; task body ("Backward compatibility is required").
*Alternatives:* retrofit all ~70 writers (rejected — high churn, zero effect on existing cards, session-ownership conflicts); retrofit only "active" writers (rejected — every currently-active writer is a live session's file).

**D4 — Consumer preference channel: exact-match on normalized phase, token-overlap fallback, ambiguity falls through; stopwords kept.**
*Why:* this is what converts the convention into a MECHANICAL pairing (task Goal); falling through on ambiguity keeps the change strictly additive; stopword retirement is explicitly deferred by the task body ("Retire the stopword set once coverage is good") and old cards still need it.
*Source:* task #2194 body scope item 4; `scripts/verify_report.py:1432-1452` (the b3 loop this extends); `tests/test_verify_report.py::test_b3_stopword_set_pinned_and_enables_resolution` (the pin that forbids stopword churn).
*Alternatives:* token-overlap-only with phase tokens (status quo — cannot resolve same-token ambiguities and provably misses the grid/anchors shape); exact-match REQUIRED with no fallback (rejected — breaks every existing card, violating the backward-compat requirement).

**D5 — Full-hex `git_commit` from `as_metadata_dict` (secondary, explicitly flagged, droppable).**
*Why:* the gate's usable set is full-40-hex only, and phase tokens/exact keys accumulate ONLY for usable SHAs — so with the helper's current `--short=8` output, every card the MANDATED shared writer produces is excluded and the phase field would be dead on arrival on exactly the forward path this task builds. Emitting full under `git_commit` (short kept for `commit_string` human channels) is the minimal consumer-compatible fix.
*Source:* read `src/explore_persona_space/orchestrate/provenance.py:112` (verbatim: `out = _run_git(["rev-parse", "--short=8", "HEAD"], cwd=cwd)`) + `scripts/verify_report.py:1386-1391` (usable classification: `_SHA40_FULL_RE.fullmatch` gates `usable_tokens`) + `:1002` (`_CARD_COMMIT_KEYS = frozenset({"git_commit", "final_commit_sha"})`).
