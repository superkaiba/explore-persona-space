**D1 — state init (guard ~L757–758).** Add five flags to `classify_cmd`'s init: `cd_root_seen=0 cd_and_chain=0 commit_before_root_cd=0 commit_off_chain=0 cd_root_base=0`.

**D2 — arm the candidate in the cd arm's MF-1 case (guard ~L837–842).** The existing case statement's three keep-arms (exact-root spellings, currently `: ;;`) are combined into ONE arm carrying the arming logic (pattern union — semantics-preserving: the same six patterns keep, everything else falls to `*)`); the `*)` arm (`*) cd_nonroot=1 ;;`, L841) is byte-untouched (S6):

```
# tgt_trail: computed beside the existing L801–802 extraction, from the SAME
# post-`cd` remainder of the raw lead — everything after the first
# whitespace-delimited word. Non-empty ⇒ the cd record carries a trailing
# token; ANY trailing token (redirect-shaped included) refuses arming
# (fail-closed; no incident shape carries one). The refusal is ARMING-only:
# cd_nonroot stays 0 for an exact-root trailing-token cd, preserving today's
# behavior at root cwd.

case "$tgt" in
  "$GUARD_REPO" | "$GUARD_REPO"/ | '~/explore-persona-space' | '~/explore-persona-space/' \
  | '$HOME/explore-persona-space' | '$HOME/explore-persona-space/')
    # #2357: exact-root cd — candidate base-mover. Arm only when:
    #  (1) own separator ∈ {START, SEQ, NL} — g3-matching (resolve_cd_var
    #      ~L531–533). AND is EXCLUDED: an AND-separated cd can itself be
    #      skipped by an earlier failure in its && chain while a later
    #      SEQ/OR-separated commit still runs at the hook cwd (r1 MF-1
    #      counterexamples, §5 F1/F2).
    #  (2) NO token after the target on this record (r1 MF-2): bash cd with
    #      extra arguments fails deterministically ("too many arguments")
    #      while a SEQ/OR-chained commit still runs.
    #  (3) next record's separator ∉ {BG, PIPE}: a trailing & or |
    #      backgrounds/subshells the cd — the parent shell's cwd never moves.
    #      (Chain dominance, D3/D5, subsumes this; kept as a cheap local
    #      belt-and-suspenders refusal.)
    # Chain dominance (D3) + compound/subshell-context refusal (D4) complete
    # the predicate in D5.
    case "$sep" in
      START | SEQ | NL)
        if [ -z "$tgt_trail" ]; then
          nsep=""
          [ $((i + 3)) -lt "$n" ] && nsep=${recs[i + 3]}
          case "$nsep" in BG | PIPE) : ;; *) cd_root_seen=1; cd_and_chain=1 ;; esac
        fi
        ;;
    esac
    ;;
  *) cd_nonroot=1 ;;
esac
```

Note: `$tgt` is the ORIGINAL raw-lead target with one surrounding quote pair stripped (L801–802) — deliberately NOT the resolve_cd_var-resolved value, mirroring the #1676 must-ask decision at L831–833 (a `$WT`/`$R` variable target to root stays unwidened; pinned by `test_c18f`). Arming RESETS `cd_and_chain=1`: the chain is measured from the MOST RECENT armed cd (a fresh `; cd <root>` re-establishes the base — the SEQ record itself breaks any prior chain via D3, then this arm re-arms).

**D3 — chain tracking + ordering bit.** Two insertions in `classify_cmd`'s per-record loop:

(a) Chain-break check — the FIRST statement of the loop body, immediately after the `sep/masked/raw` extraction (L780–781 region), BEFORE the comment-strip, the empty-lead `continue`, and every case dispatch (the cd block ends in `continue` at L843, so a later placement would skip records):

```
if [ "$cd_root_seen" = 1 ] && [ "$sep" != AND ]; then cd_and_chain=0; fi
```

(For an arming cd record with own-sep SEQ/NL after a PRIOR armed cd, this correctly breaks the old chain first; D2's arm then re-arms with a fresh chain.)

(b) Commit-verb branch (guard ~L893):

```
if [ "$verb" = commit ]; then
  root_commit=1
  if [ "$cd_root_seen" = 0 ]; then
    commit_before_root_cd=1        # #2357 base-order bit (kept from v3)
  elif [ "$cd_and_chain" = 0 ]; then
    commit_off_chain=1             # #2357 chain-dominance bit (r1 MF-1)
  fi
fi
```

A commit clause scanned before any armed root-cd means the base at that commit is the (unproven) hook cwd; a commit whose chain back to the armed cd contains ANY non-AND separator can run even when the cd was skipped or failed — either way the widening must not engage. The soundness invariant: under an all-AND chain, commit-runs ⟹ every predecessor in the chain (the cd included) executed and succeeded ⟹ the base at the commit is the root. A chain break AFTER a commit record does not retroactively uncover it (correct: later separators cannot change where an earlier commit ran).

**D4 — compound-context helper (factor g7 + widen with `(`-openers; guard ~L499–507).** Extract `resolve_cd_var`'s g7 loop into `compound_context_present()` (reads `recs`/`n` via the same bash dynamic-scoping mechanism, returns 0 iff any record opens/continues a compound statement). The recognized set is the existing g7 set — `if/then/elif/else/fi/while/until/for/do/done/case/esac/function`, `name()` defs, bare `{` openers — PLUS (r1 MF-3) any record whose whitespace-stripped masked text begins with `(` (parenthesized subshell opener: append `|^\(` to the existing `grep -qE` alternation). Rationale for the `(` widening: the record lead-strip (L788/L790) removes leading `[({]`, so a subshell's inner cd reads as a plain exact-root cd at the cd arm while a subshell cd can NEVER move the parent shell's cwd — `(cd <root> && true) && git commit -- p` is an all-AND chain whose commit executes at the parent's unmoved cwd, the one bypass chain dominance alone admits (§5 F5). The g7 loop's own record read (~L501) strips whitespace only, so the `(` survives there and the check is well-posed. `resolve_cd_var` calls the helper (behavior-identical refactor at its call site — the helper preserves resolve_cd_var's return POLARITY, and the `resolve_reason=compound-context` reason token stays at the resolve_cd_var call site (S3)); the new D5 post-loop computation calls it too. Note the `(` widening is strictly TIGHTENING for resolve_cd_var (fail-closed direction — a `(`-opener command now refuses variable resolution too); AC4's baseline compare catches any existing-row flip, with the scoped fallback named under "Plan deviations". Factoring (not duplicating) follows the #1857 landing_sha precedent. The masker tracks quote/heredoc state only, not keyword/brace/paren depth, so a compound-BODY or subshell-body `cd <root>` record would read as unconditionally executed while being conditional (or parent-cwd-inert) at runtime — the arming false-positive classes that combine with a root-SUBDIR hook cwd into a genuine landing bypass.

**D5 — post-loop verdict inside classify_cmd (after the per-record loop, before the function's existing post-scan block ends — `recs` still in scope).**

```
cd_root_base=0
if [ "$cd_root_seen" = 1 ] && [ "$commit_before_root_cd" = 0 ] \
  && [ "$commit_off_chain" = 0 ] && ! compound_context_present; then
  cd_root_base=1
fi
```
