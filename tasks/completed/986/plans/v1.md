## 4. Design — concrete diffs

### 4a. `scripts/workflow_lint.py` — constant (insert before line 5662, after the dict's lead comment block)

```python
# A grandfather cap must hug the measured size: cap - size <= this bound
# (the documented "measured + <=3 KB margin" convention, mechanized by #986).
# STRICTLY-GREATER like the other thresholds (headroom exactly 3_000 passes).
# A larger headroom means a loose cap-raise (defeats the regrowth ratchet) or
# a stale cap after a trim (ratchet DOWN when trimmed) — both FAIL.
AGENT_SPEC_GRANDFATHER_MAX_HEADROOM_BYTES = 3_000
```

### 4b. `scripts/workflow_lint.py` — replace the hygiene loop (current lines 5770-5786)

```python
    # Grandfather-entry hygiene: entries must point at existing files that
    # still NEED grandfathering (size > FAIL threshold) AND whose cap hugs the
    # measured size (headroom <= AGENT_SPEC_GRANDFATHER_MAX_HEADROOM_BYTES —
    # the regrowth ratchet is meaningless under a loose cap; #986).
    for gf_name, cap in sorted(AGENT_SPEC_SIZE_GRANDFATHER.items()):
        gf_path = agents_dir / gf_name
        if not gf_path.is_file():
            errors.append(
                f"AGENT_SPEC_SIZE_GRANDFATHER['{gf_name}']: stale grandfather "
                f"entry — .claude/agents/{gf_name} does not exist; remove the "
                f"entry."
            )
            continue
        gf_size = gf_path.stat().st_size
        if gf_size <= AGENT_SPEC_FAIL_BYTES:
            errors.append(
                f"AGENT_SPEC_SIZE_GRANDFATHER['{gf_name}']: "
                f".claude/agents/{gf_name} is {gf_size} bytes "
                f"(<= {AGENT_SPEC_FAIL_BYTES}) and no longer needs "
                f"grandfathering — remove the entry (ratchet down)."
            )
        elif cap - gf_size > AGENT_SPEC_GRANDFATHER_MAX_HEADROOM_BYTES:
            errors.append(
                f"AGENT_SPEC_SIZE_GRANDFATHER['{gf_name}']: cap {cap} sits "
                f"{cap - gf_size} bytes above .claude/agents/{gf_name} "
                f"({gf_size} bytes) — max headroom is "
                f"{AGENT_SPEC_GRANDFATHER_MAX_HEADROOM_BYTES} bytes (cap = "
                f"measured + <=3 KB); lower the cap to <= "
                f"{gf_size + AGENT_SPEC_GRANDFATHER_MAX_HEADROOM_BYTES}, or "
                f"remove the entry if the file no longer needs grandfathering."
            )
```

Behavior-preserving notes: the stale-entry and remove-the-entry messages are byte-identical to today's (the retired branch just uses the pre-stat'ed `gf_size` instead of stat-ing twice); `continue` after the stale branch keeps the one-error-per-entry shape. Ordering guarantees no double-fire: missing file → stale FAIL only; `size <= FAIL` → remove-entry FAIL only; `size > cap` (regrowth) → per-file-loop ratchet FAIL, and `cap − size` is negative so the `elif` cannot also fire.

```python
# --------------------------------------------------------------------------
# (k)/(l) grandfather-cap headroom: exactly-at-bound passes (strict >);
# over-bound FAILs (loose cap-raise / stale cap after a trim — #986)
# --------------------------------------------------------------------------


def test_grandfather_headroom_at_bound_passes(
    tmp_path: Path, monkeypatch: pytest.MonkeyPatch
) -> None:
    size = AGENT_SPEC_FAIL_BYTES + 1_000
    cap = size + AGENT_SPEC_GRANDFATHER_MAX_HEADROOM_BYTES  # headroom exactly at bound
    monkeypatch.setattr(workflow_lint, "AGENT_SPEC_SIZE_GRANDFATHER", {"gf.md": cap})
    _write_agent(tmp_path, "gf.md", size)
    warns: list[str] = []
    assert check_agent_spec_size(repo_root=tmp_path, warn_sink=warns) == []
    assert len(warns) == 1, warns  # the ordinary "grandfathered; under its cap" WARN


def test_grandfather_headroom_over_bound_fails(
    tmp_path: Path, monkeypatch: pytest.MonkeyPatch
) -> None:
    size = AGENT_SPEC_FAIL_BYTES + 1_000
    cap = size + AGENT_SPEC_GRANDFATHER_MAX_HEADROOM_BYTES + 1  # headroom bound+1
    monkeypatch.setattr(workflow_lint, "AGENT_SPEC_SIZE_GRANDFATHER", {"gf.md": cap})
    _write_agent(tmp_path, "gf.md", size)
    errors = check_agent_spec_size(repo_root=tmp_path, warn_sink=[])
    assert len(errors) == 1, errors
    assert "gf.md" in errors[0]
    assert "headroom" in errors[0]
    assert str(cap) in errors[0]
```

Interaction coverage rides existing tests unchanged: (g) `test_grandfathered_below_fail_threshold_fails_remove` asserts `len(errors) == 1` with a cap 5,000 B above a below-FAIL file — a headroom double-fire would break it; (e) `test_grandfathered_over_cap_fails` asserts `len(errors) == 1` for the regrowth case (negative headroom); (i) `test_live_tree_passes` pins the live tree. Optionally strengthen (g) with `assert "headroom" not in errors[0]` — cheap and explicit; include it.

## 11. Decision Rationale

1. **FAIL, not WARN.** *What:* a headroom violation enters the returned errors list (commit-blocking). *Why:* the origin bug — a loose cap-raise defeating the ratchet — is only prevented by a blocking check; WARNs go to stderr and never block. The "too aggressive mid-trim" concern resolves in favor of FAIL: forcing the cap update in the trimming commit is precisely the documented "Ratchet DOWN when trimmed" behavior, the fix is a one-line dict edit named verbatim in the error message, and the trimmer is already editing the workflow surface. *Source:* precedent — all three existing hygiene branches in this function FAIL (stale entry, remove-the-entry, cap ≤ FAIL config check); dict comment lines 5654-5661. *Alternatives:* WARN (rejected: doesn't close the bug); WARN-then-FAIL grace window (rejected: no time-based state in this lint, adds machinery for no benefit).
2. **Threshold = 3,000 (decimal), named constant.** *What:* `AGENT_SPEC_GRANDFATHER_MAX_HEADROOM_BYTES = 3_000`. *Why:* the dict comment's convention is "<=3 KB margin"; decimal 3_000 matches the module's existing decimal style (`28_000`, `40_000`), not 3_072; largest live headroom 2,887 B fits with 113 B to spare. *Source:* dict comment (line 5655); orchestrator headroom measurements 2026-07-04; #829/#838 constant style. *Alternatives:* 3_072 (rejected: style mismatch); 2_000/1_000 (rejected: would FAIL clean-result-critic.md at 2,887 and codex-clean-result-critic.md at 2,642 today, forcing cap churn in this same change — scope creep).
3. **Placement: grandfather-entry hygiene loop, `elif` after the retired-entry branch.** *What:* per §4b. *Why:* the config self-check is size-independent pure dict introspection; headroom needs a live stat, and the hygiene loop already owns per-entry file existence + size. The `elif` ordering plus the per-file loop's ownership of negative headroom (regrowth) makes double-fire structurally impossible. *Source:* current implementation lines 5725-5786 (read this session). *Alternatives:* separate fourth loop (rejected: duplicate stat + weaker no-double-fire guarantee); inside the per-file loop (rejected: that loop iterates files, not entries — a stale cap on a file that shrank would be missed there; it's also the WARN path, mixing concerns).
4. **Boundary semantics: strictly-greater.** *What:* headroom == 3_000 passes; 3_001 FAILs. *Why:* "<=3 KB margin" is documented as allowed, and every sibling threshold in this check is strictly-greater (module comment line 5644, test docstring). *Source:* lines 5644-5645; tests (a2)/(c2). *Alternatives:* `>=` (rejected: contradicts both the documented convention and the module-wide convention).
5. **Message text.** *What:* names entry, cap, live size, headroom, bound, and both fixes. *Why/Source:* matches the existing `AGENT_SPEC_SIZE_GRANDFATHER['{name}']: ...` hygiene-error style (lines 5729-5733, 5775-5786) and the task's actionability requirement; contains the token "headroom" for a stable test assertion. *Alternatives:* terse message (rejected: the existing branches all name the fix).
6. **No grace mechanism.** *What:* single strictly-greater comparison, stateless. *Why:* simplest thing that closes the bug; the lint has no temporal state anywhere. *Source:* task body design question 6. *Alternatives:* none worth the machinery.
