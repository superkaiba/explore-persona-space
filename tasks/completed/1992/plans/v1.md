# Plan v1 — workflow-fix: flaky settle-sleep equality assert in inline-lint-gate test (#1992)

kind: infra (workflow-fix; `wf-fix` tag)

## 1. Requirement + acceptance criteria

**Requirement.** Harden two assertions in `tests/test_inline_lint_gate.py` against
interpreter-internal sleeps captured by the process-global `time.sleep` monkeypatch, so

the #1857 cert-retry invariant (exactly ONE settle-scale sleep from `write_cert`).

**Acceptance criteria.**

   (assert at ~L725) and

   no longer assert on the RAW captured sleep list; each filters to settle-scale sleeps

3. Both tests pass deterministically: 10/10 consecutive single-file runs green locally.

5. Ruff clean on the touched file; no other test in the file changed.

## 2. Root cause (verified at clarify time)

`write_cert` re-hashes via `_git()` → `subprocess.run(..., timeout=60)`
(`scripts/inline_lint_gate.py:201`). CPython's `Popen.wait(timeout=...)` busy-waits with an
exponential-backoff `time.sleep` series (0.0005·2^k, capped at 0.05s per call). The tests
patch `ilg.time.sleep` — and `ilg.time` IS the global `time` module — so under machine load
the git subprocess outlives the first wait quantum and the fake sleep captures dozens-to-
hundreds of sub-0.05s backoff entries alongside `write_cert`'s single 2.0s settle sleep,
breaking `slept == [2.0]` (and, more rarely, `len(slept) == 1`).

The 1.0s threshold cleanly separates the two populations: interpreter-internal backoff
sleeps are ≤ 0.05s by construction (CPython caps the quantum); the settle sleep is 2.0s
(the `EPM_CERT_REHASH_DELAY_S` default — neither test overrides it).

## 3. Method delta

Assert on a filtered view of the captured sleeps instead of the raw list. No change to
`scripts/inline_lint_gate.py` (production behavior untouched); no change to any other test.
This is the minimal intervention that removes the load-sensitivity while keeping the
invariant pinned at full strength (count AND value).

Rejected alternatives:
- Caller-frame inspection in the fake sleep (record only calls from `inline_lint_gate`):
  strictly more precise but more code and more brittle (frame introspection in a lambda →
  needs a def + `sys._getframe`); the 1.0 threshold achieves the same discrimination given
  the ≤0.05s cap on the interfering population.
- Setting `EPM_CERT_REHASH_DELAY_S` to a sentinel value and filtering by exact match:
  weakens the malformed-delay test, whose POINT is that the 2.0 DEFAULT is used when the
  env var is malformed.
