### 4a. EPS ownership predicate (new helper in `scripts/pod_audit.py`)

Add function `_is_eps_owned(p: PodInfo, pod_id: str) -> bool` after `_task_has_keep_running` (around L197):

```python
def _is_eps_owned(p: "PodInfo", pod_id: str) -> bool:
    """Return True when this pod is positively identified as EPS-owned.

    Three independent signals, any one sufficient:
      1. The pod name parses a valid issue number AND that issue exists in REGISTRY.
      2. The pod appears in pods_ephemeral.json by pod_id or pod_name.
      3. _scan_task_references() finds the pod_id or pod_name in any task's events.jsonl.

    Fail-toward-KEEP on every lookup error: a missing/corrupt REGISTRY or
    pods_ephemeral.json returns False here, routing the pod to unmanaged-exited
    rather than stale, so we never destroy a non-EPS pod on a lookup fluke.
    Bias is deliberate: a false keep costs nothing; a false terminate destroys
    a volume irreversibly.
    """
    name = p.name or ""
    # Signal 1: parseable issue number in REGISTRY
    issue = _issue_number_from_name(name)
    if issue is not None:
        try:
            get_task(issue)  # raises if issue not in REGISTRY
            return True
        except Exception:
            pass  # issue number parsed but not in REGISTRY — not EPS-owned via this signal

    # Signal 2: pod_id or pod_name in pods_ephemeral.json
    try:
        from pod_config import resolve_live_pods_ephemeral  # noqa: PLC0415
        ephemeral_path = resolve_live_pods_ephemeral()
        import json as _json  # noqa: PLC0415
        data = _json.loads(ephemeral_path.read_text())
        for entry in data.values():
            if isinstance(entry, dict):
                if entry.get("pod_id") == pod_id or entry.get("name") == name:
                    return True
    except Exception:
        pass  # ephemeral sidecar unreadable — continue to signal 3

    # Signal 3: task reference scan (pod_id or pod_name in any events.jsonl)
    refs = _scan_task_references(pod_id, name)
    if refs:
        return True

    return False
```

**Import note:** `pod_config` is already imported in `pod_audit.py` for `_task_has_keep_running` via `get_task`. The `resolve_live_pods_ephemeral` function exists in `pod_config.py` as part of the #1183 relocation. If `pod_config.resolve_live_pods_ephemeral` is not yet exposed as a module-level symbol, fall back to reading the ephemeral JSON directly via the known path (the signal-2 block wraps in `try/except`, so a missing attribute degrades cleanly to signal 3 only).

New code — insert EPS ownership gate before the `stale` assignment:
```python
elif p.desired_status == "EXITED":
    if issue is not None and _task_has_keep_running(issue):
        bucket = "kept-exited"
        kept_for = issue
    elif age is not None and age >= max_exited_hours:
        # Gate: only auto-terminate EXITED pods we can positively confirm as EPS-owned.
        # A non-EPS pod carrying the managed prefix (pod-*) must never be auto-terminated.
        if _is_managed_name(p.name or "") and not _is_eps_owned(p, p.pod_id or ""):
            bucket = "unmanaged-exited"
        else:
            bucket = "stale"
    else:
        bucket = "fresh-exited"
```

**Why the guard is inside `age >= max_exited_hours`:** we only care about the auto-terminate path; a fresh EXITED pod that hasn't aged out yet is benign and stays `fresh-exited` regardless.

**Why `_is_managed_name` must be True before we apply the ownership check:** an unmanaged-name pod (e.g. a RunPod pod named by a teammate with an arbitrary name like `my-training-run`) does NOT have the `pod-` or `epm-issue-` prefix and therefore was never at risk of being confused with an EPS pod by `_issue_number_from_name`. The hazard is specifically name-collision — only managed-prefix pods need the positive EPS ownership check. Unmanaged-name pods continue to reach `stale` as before (they have no EPS lineage and the managed-prefix collision risk doesn't apply to them).

## 11. Decision Rationale

**Ownership predicate design (three-signal, any-one-sufficient, fail-toward-keep):**
Why: the hazard is a false-terminate on a non-EPS pod — irreversible volume destruction. The three signals cover the three ways a pod gets EPS ownership recorded: by naming convention (signal 1), by explicit metadata sidecar (signal 2), or by historical task reference (signal 3). Any one signal is sufficient because ownership can be established via any one channel. Fail-toward-keep because false-keep is reversible; false-terminate is not.
Source: the incident post-mortem (task #1404 body) + the existing `_scan_task_references` design rationale in `pod_audit.py`.

**Why `_is_managed_name` must be True before applying the ownership gate:**
Why: the auto-terminate hazard only exists for pods whose names collide with the `pod-N` managed prefix. A pod named `my-training-run` was never at risk of being attributed to an EPS issue by `_issue_number_from_name`; it reaches `stale` for other reasons and the ownership gate is not relevant. Adding the check only for managed-prefix pods avoids any behavioral change for non-prefix pods.
Source: `_is_managed_name` at L167-168 in `pod_audit.py` (verified codebase read).

**`render_report()` explicit addition:**
Why: `render_report()` iterates an explicit 5-tuple; unknown buckets are not rendered automatically (confirmed by reading L392-421). Without an explicit render addition, the `unmanaged-exited` bucket is invisible to the operator, defeating the purpose of the non-terminate path.
Source: codebase read of `render_report()` L392-421 (confirmed explicit-tuple iteration).

**PM triage protocol neutral framing:**
Why: the incident showed the PM framed unmapped pods as emergencies. The fix is prose in `research-pm.md` that mandates ownership-check-first + neutral question framing. The prose must be adjacent to the existing orphan-pod guidance for discoverability.
Source: task #1404 body (verified-at-filing incident description).

**No change to non-managed-name pods reaching `stale`:**
Why: the bug is specifically name-prefix collision. Non-managed-name pods have no EPS attribution risk. Broadening the ownership gate to all pods would add scan overhead and change existing behavior without closing the actual hazard.
Source: codebase read of `_is_managed_name()` and `_issue_number_from_name()` (confirmed scope).
