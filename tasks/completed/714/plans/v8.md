## Method delta (what differs from `--check-script-refs`)

| Aspect | `--check-script-refs` | `--check-skill-refs` (new) |
|---|---|---|
| Reference matcher | single regex `(?<![\w/])scripts/([A-Za-z0-9_]+\.py)\b` | **two-stage**: match backticked SPAN, then extract EVERY slash-command token in invocation position (span-start or after whitespace, NOT a path prefix) — see §4.1 (MF1 fix) |
| Resolution set | files under `scripts/` | directory names under `.claude/skills/` resolving by dir existence AND (`SKILL.md` present OR name in `KNOWN_NON_SKILL_MD_DIRS`) — `clean-results` is the one documented SKILL.md-less skill (R1) |
| Per-line opt-out | `<!-- lint: historical-ref -->` | a DISTINCT `<!-- lint: historical-skill-ref -->` (R2); the script-ref opt-out is NOT honored here |
| Declared allowlist | none (dangling refs rare/one-off) | a declared `SKILL_REF_ALLOWLIST` frozenset (user-global / plugin / built-in / backticked code-path FPs) |
| Scope | agents + skills (`_resolve_ask_target_files`) | **identical** scope (agents + skills) |
| Bundling | `--check-references` + no-flags | **identical** |

**Three method deltas worth calling out:**

1. **Two-stage backtick matching is the central design choice (UPDATED for
   MF1).** A bare-`/foo` regex (the original candidate's
   `r"/([a-z][a-z0-9-]+(?::[a-z0-9-]+)?)\b"`) matches path segments
   (`/skills`, `/agents`, `/workspace`, `/tmp`), HTML close tags
   (`</summary>`), Handlebars (`{{/each}}`), and prose — 50+ distinct false
   positives requiring an unmanageable allowlist. The backtick-wrapped form is
   how skill invocations are actually written in this project's prose, is
   high-signal (like `--check-asks` keying on the literal `AskUserQuestion`
   token), and reduces the unresolved set to 13 ergonomic entries. **v1's
   single-capture regex missed commands NESTED inside a chained span** (only
   the first token validated; the trailing arg-run consumed the rest). The v2
   matcher matches the SPAN, then iterates EVERY command token inside it that
   is in invocation position and not a path prefix — catching the 6 real
   `/loop … /issue` spans on `main`. It still catches the original bug
   (`/weekly`, 9 hits).
2. **Resolution by skill DIRECTORY existence + a known-exception set, not
   `SKILL.md` (UPDATED for R1).** `clean-results` is a live skill dir
   (`/clean-results` is a real reference) but holds only
   `SPEC.md`/`exemplars/`/`iterations.md`/`lw-post-examples/` — no `SKILL.md`.
   The original candidate's `glob("*/SKILL.md")` would wrongly flag
   `/clean-results`. Resolve against
   `{p.name for p in Path(".claude/skills").iterdir() if p.is_dir()}`, BUT gate
   each name on `(p / "SKILL.md").exists() or p.name in KNOWN_NON_SKILL_MD_DIRS`
   so a FUTURE bare `.claude/skills/foo-notes/` (no SKILL.md, never intended as
   an invocable skill) does NOT silently start allowing `/foo-notes`.
   `KNOWN_NON_SKILL_MD_DIRS = frozenset({"clean-results"})` is the one
   documented exception.
3. **A declared allowlist + a DISTINCT per-line opt-out (UPDATED for R2).**
   Unlike `--check-script-refs` (where dangling refs are rare and one-off),
   legitimate non-project skill commands recur across many files (`/humanize`
   x7, `/loop` x10). Per-line opt-outs would litter the surface; a central
   declared allowlist documents the closed set once. A per-line opt-out is ALSO
   retained for genuinely one-off narrative citations — but as a NEW DISTINCT
   token `<!-- lint: historical-skill-ref -->` so a single line cannot
   accidentally waive both the script-refs and skill-refs lints at once.

### 4.1 The matcher + resolution function (UPDATED — MF1 + R1 + R2)

Add near `SCRIPT_REF_RE` (after line 220):

```python
# `--check-skill-refs`: every backticked slash-command skill reference
# (`/weekly`, `/issue <N>`, `/humanize quick`, and EVERY command in a chained
# span like `/loop 10m /issue <N>`) in an agent / skill spec MUST resolve to a
# live skill dir under `.claude/skills/<name>/` or to a declared
# SKILL_REF_ALLOWLIST entry. Two-stage matching: SKILL_SPAN_RE finds the
# backtick-wrapped span, SKILL_TOKEN_RE then extracts EVERY slash-command token
# INSIDE the span that is in invocation position. Backtick-wrapped form ONLY:
# a bare `/foo` matches path segments (`/skills`, `/tmp`), HTML close tags
# (`</summary>`), and Handlebars (`{{/each}}`) — 50+ false positives. The
# backtick form is how skill invocations are actually written in prose and is
# high-signal (mirrors --check-asks keying on the literal `AskUserQuestion`).
#
# A command token is at INVOCATION position iff it sits at the span START or
# immediately after whitespace (so `/issue` in `/loop 10m /issue <N>` is caught
# — the v1 single-capture regex missed it), AND it is NOT a path prefix: the
# trailing (?![\w/-]) rejects `/tmp/log`, `/home/...`, `/tree/<sha>`,
# `/blob/<sha>`, `/runs/<id>`, `/dev/null`, `/scripts/...` (a real /skill is
# never immediately followed by `/`, a word-char, or `-`). Group 1 of
# SKILL_TOKEN_RE = the skill name (optionally `<plugin>:<skill>`).
SKILL_SPAN_RE = re.compile(r"`([^`]*)`")
SKILL_TOKEN_RE = re.compile(r"(?:^|\s)/([a-z][a-z0-9-]*(?::[a-z0-9-]+)?)(?![\w/-])")

# Lines inside fenced code blocks (``` / ~~~) are skipped (code samples carry
# sed one-liners / regex fragments / paths whose backticked `/x` shapes are not
# skill invocations).
_FENCE_RE = re.compile(r"^\s*(?:```|~~~)")

# DISTINCT per-line opt-out for a ONE-OFF narrative skill citation (a since-
# retired skill named for historical context on a single line). A SEPARATE
# token from the script-ref opt-out (HISTORICAL_REF_OPT_OUT, line 220) so a
# single line cannot accidentally waive BOTH lints — only check_skill_references
# honors this token; check_script_references is untouched. For recurring
# legitimate non-project commands use SKILL_REF_ALLOWLIST instead.
SKILL_REF_OPT_OUT = "<!-- lint: historical-skill-ref -->"

# Live skill dirs that legitimately carry NO SKILL.md and are still invocable
# (resolution is by dir existence; this set is the documented exception so a
# FUTURE bare dir without SKILL.md does NOT silently become an allowed /command).
KNOWN_NON_SKILL_MD_DIRS: frozenset[str] = frozenset(
    {
        "clean-results",  # holds SPEC.md / exemplars/ / iterations.md — no SKILL.md; /clean-results is a real reference
    }
)
```

Resolution + walk function (added next to `check_script_references`, ~line 1145):

```python
def _live_skill_names(skills_dir: Path) -> set[str]:
    """Return the set of live skill names: every immediate child DIRECTORY of
    `.claude/skills/` that EITHER contains a SKILL.md OR is in
    KNOWN_NON_SKILL_MD_DIRS. Resolution is by directory existence (not a blanket
    SKILL.md requirement) because `clean-results` is a live skill dir holding
    SPEC.md/exemplars/ with no SKILL.md and `/clean-results` is a legitimate
    reference; the known-exception gate prevents a FUTURE bare
    `.claude/skills/foo-notes/` (no SKILL.md) from silently allowing
    `/foo-notes`."""
    if not skills_dir.exists():
        return set()
    return {
        p.name
        for p in skills_dir.iterdir()
        if p.is_dir() and ((p / "SKILL.md").exists() or p.name in KNOWN_NON_SKILL_MD_DIRS)
    }


def check_skill_references(
    *,
    roots: list[Path] | None = None,
    skills_dir: Path | None = None,
    allowlist: frozenset[str] | None = None,
) -> list[str]:
    """Walk `.claude/agents/**.md` + `.claude/skills/**/SKILL.md` and FAIL on
    any backticked `/skill-name` reference that resolves neither to a live
    skill dir under `.claude/skills/` NOR to SKILL_REF_ALLOWLIST.

    Closes the skill-rename / skill-retirement rot class: `--check-references`
    only resolves `(see workflow.yaml § X)` tokens, so a retired skill (e.g.
    `/weekly`) leaves stray load-bearing references that no mechanical check
    catches (#713 Methodology-critic finding; #714). EVERY command token inside
    a chained backticked span is validated, not just the first — a stale token
    nested in `/loop 10m /issue <N>` is caught even when `/loop` is allowlisted.

    Lines inside fenced code blocks (``` / ~~~) are skipped. Lines carrying
    SKILL_REF_OPT_OUT are skipped (one-off narrative citation); the script-ref
    opt-out (HISTORICAL_REF_OPT_OUT) is deliberately NOT honored here, so a line
    cannot waive both lints by accident. Plugin-namespaced refs (`/codex:setup`)
    resolve if `.claude/skills/<plugin>:<skill>/` exists (forward-compat; none
    today) OR if the `<plugin>:<skill>` token is in the allowlist.

    `roots` / `skills_dir` / `allowlist` are unit-test override hooks; production
    callers pass None.
    """
    errors: list[str] = []
    sk_dir = skills_dir if skills_dir is not None else _REPO_ROOT / ".claude" / "skills"
    live = _live_skill_names(sk_dir)
    allow = allowlist if allowlist is not None else SKILL_REF_ALLOWLIST
    for path in _resolve_ask_target_files(roots):
        in_fence = False
        for lineno, line in enumerate(path.read_text(encoding="utf-8").splitlines(), start=1):
            if _FENCE_RE.match(line):
                in_fence = not in_fence
                continue
            if in_fence or SKILL_REF_OPT_OUT in line:
                continue
            for span_match in SKILL_SPAN_RE.finditer(line):
                span = span_match.group(1)
                for token_match in SKILL_TOKEN_RE.finditer(span):
                    ref = token_match.group(1)
                    if ref in live or ref in allow:
                        continue
                    errors.append(
                        f"{path}:{lineno}: unresolved skill reference '/{ref}' — "
                        f"not a live skill under .claude/skills/ and not in "
                        f"SKILL_REF_ALLOWLIST. Repoint to the current skill, remove "
                        f"the dead reference, add the command to SKILL_REF_ALLOWLIST "
                        f"(user-global / plugin / built-in command), or — for a "
                        f"one-off narrative citation — append "
                        f"'{SKILL_REF_OPT_OUT}' to the line."
                    )
    return errors
```

> **Note on `_resolve_ask_target_files` + fences:** that helper already
> excludes OTHER worktrees and scans the current one. The fence state is
> tracked per-file inside the loop (reset on each `path`), so a code fence in
> one file cannot bleed into the next.

> **Why two-stage (span then token) rather than one combined regex:** a single
> regex that both requires backticks AND captures every nested command is
> awkward (variable-length lookbehind for "preceded by backtick-or-whitespace
> within a backtick run"); matching the span first, then scanning tokens inside
> the span string, is simpler, directly mirrors how a reader parses
> `/loop 10m /issue`, and was validated against `main` at plan time.

## §11 Decision Rationale

**Two-stage backtick matching (span then every invocation-position token)**
- **What:** `SKILL_SPAN_RE = re.compile(r"`([^`]*)`")` to find the backticked
  span, then
  `SKILL_TOKEN_RE = re.compile(r"(?:^|\s)/([a-z][a-z0-9-]*(?::[a-z0-9-]+)?)(?![\w/-])")`
  iterated over the span string to validate EVERY command in invocation
  position.
- **Why:** tied to the Goal (catch stale skill refs — INCLUDING nested ones —
  without drowning in FPs). v1's single-capture regex validated only the FIRST
  command in a chained span (`/loop 10m /issue <N>` → only `/loop` checked), so
  a stale nested token false-PASSes when the outer command is allowlisted/live
  — the conclusion-changing MF1 finding, with 6 real `/loop … /issue` spans on
  `main`. The two-stage form validates each. The invocation-position anchor
  (`^|\s`) + the path-prefix guard (`(?![\w/-])`) preserve v1's high-signal
  property: backticked path segments (`/tmp/log`, `/home/...`, `/tree/<sha>`,
  `/dev/null`) are correctly ignored, keeping the unresolved set to 13 ergonomic
  entries. Mirrors the `--check-asks` design of keying on a high-signal literal
  token.
- **Source:** `--check-script-refs` precedent (`scripts/workflow_lint.py:209`,
  `SCRIPT_REF_RE` left-boundary discipline) + `--check-asks` precedent
  (`scripts/workflow_lint.py:897`, literal-`AskUserQuestion` keying) + the §4.5
  grep evidence over the live tree this round (30 caught / 13 unresolved /
  weekly=9, 6 nested spans).
- **Alternatives:** (1) v1's single-capture regex
  `` `/(...)(?:[ >][^`]*)?` `` — rejected (MF1: misses nested commands). (2)
  per-token over the span WITHOUT the path-prefix guard — rejected (51 FPs from
  backticked file-path segments). (3) candidate's bare
  `r"/([a-z][a-z0-9-]+(?::[a-z0-9-]+)?)\b"` — rejected (50+ FPs, unmanageable
  allowlist).

**Resolution by skill-directory existence + known-exception set (not blanket SKILL.md)**
- **What:** `{p.name for p in Path(".claude/skills").iterdir() if p.is_dir() and ((p / "SKILL.md").exists() or p.name in KNOWN_NON_SKILL_MD_DIRS)}` with
  `KNOWN_NON_SKILL_MD_DIRS = frozenset({"clean-results"})`.
- **Why:** `clean-results` is a live skill dir with no `SKILL.md` (it holds
  SPEC.md/exemplars/iterations.md/lw-post-examples/); resolving against
  `*/SKILL.md` alone would wrongly flag the legitimate `/clean-results`
  reference. But a blanket "any dir resolves" (v1) would let a FUTURE bare
  `.claude/skills/foo-notes/` (no SKILL.md, never meant to be invocable)
  silently allow `/foo-notes` (R1). The known-exception gate threads the
  needle: `clean-results` resolves; an unknown SKILL.md-less dir does not.
- **Source:** on-disk inspection (`.claude/skills/clean-results/` has no
  SKILL.md, confirmed this round); R1 standing recommendation.
- **Alternatives:** (1) blanket `*/SKILL.md` glob — rejected (flags
  `/clean-results`). (2) blanket "any dir resolves" (v1) — rejected (a future
  SKILL.md-less dir silently allows its `/command`).

**Distinct skill-ref opt-out marker (not reused script-ref token)**
- **What:** `SKILL_REF_OPT_OUT = "<!-- lint: historical-skill-ref -->"`, honored
  ONLY by `check_skill_references`.
- **Why:** v1 reused `HISTORICAL_REF_OPT_OUT`, so a single line carrying that
  marker would waive BOTH the script-refs AND the skill-refs lint — a narrow
