## 2. Method delta

Today `workflow_lint.py --check-references` resolves only
`(see workflow.yaml § X)` citations (`_check_references`, lines 705-721) and a
sibling `check_script_references` resolves `scripts/<name>.py` tokens. There is no
check that validates **skill-name** cross-references (`/issue`, `/weekly`,
`/daily`, …) resolve to a live skill directory — so retiring or renaming a skill
silently rots every dangling `/{name}` mention, caught today only by hand-run
`grep` (the gap the #713 Methodology critic surfaced). This task adds the third
sibling: a `_check_skill_refs` function that walks the same `DOC_FILES`, extracts
slash-command tokens from prose (not code), and FAILs on any token that is neither
a live skill dir nor allowlisted. The work is one new function + one new regex +
one new opt-out-aware loop + a new allowlist file + a loader + the `main()` wiring
+ tests. It mirrors the existing `_check_references` / `check_script_references`
shape end to end so it slots into the established dispatch ladder.

## 3. Design

### 3.1 New regex `SKILL_REF_RE` (added near `SCRIPT_REF_RE`, ~line 209)

```python
# `--check-skill-refs`: every `/<skill-name>` slash-command token mentioned in
# PROSE (not inside a code span / fenced block) in a DOC_FILE MUST resolve to a
# live skill dir under `.claude/skills/*/` or to the declared allowlist. The
# left lookbehind requires the slash to start a token (preceded by start-of-line
# or whitespace or an opening bracket/paren/brace), NOT a path continuation
# (`a/b`), a `$`-prefixed shell expansion (`$x/hr`), or a closing backtick. The
# right lookahead rejects a trailing word char, `/` (path continuation), `.`
# (file ext / dotted path like `/workflow.yaml`), or `-`/`:` (those are consumed
# INSIDE the captured token when part of a real hyphenated / plugin-namespaced
# skill name; a lone trailing one means the match would be a fragment of a longer
# path). The optional `(?::[a-z0-9-]+)?` group captures plugin-namespaced skills
# (`/codex:rescue`). Empirically: the candidate body's bare `r"/([a-z][a-z0-9-]+)"`
# matched ~347 distinct tokens across the three DOC_FILES (almost all path
# segments); this anchored regex + code-span exclusion (below) cuts that to 10,
# of which 6 are live skills and 4 are handled by allowlist (`humanize`) +
# per-line opt-out (3 prose false positives).
SKILL_REF_RE = re.compile(
    r"(?:(?<=^)|(?<=[\s(\[{]))/([a-z][a-z0-9-]*(?::[a-z0-9-]+)?)(?![\w/:-])(?!\.\w)"
)
```

**Per-anchor rationale:**
- `(?:(?<=^)|(?<=[\s(\[{]))` — the `/` must begin a token. Excludes path
  continuations (`data/issue`, `a/b`), `$x/hr`, and tokens glued to a preceding
  word. (Two zero-width lookbehinds OR'd because Python `re` requires
  fixed-width lookbehind.)
- `/([a-z][a-z0-9-]*(?::[a-z0-9-]+)?)` — capture group: a lowercase-led name with
  internal hyphens (real skills `adversarial-planner`, `promote-clean-result`),
  plus an optional `:`-namespaced suffix for plugin skills (`codex:rescue`,
  `superpowers:using-superpowers`). Hyphens CANNOT be banned — many live skills
  are hyphenated.
- `(?![\w/:-])(?!\.\w)` — reject a trailing word/`.`/`/`/`-`/`:` so the match is a
  complete leaf token, not the head of a longer path (`/workflow.yaml`,
  `/issue-397-sweep`, `/workspace/logs`).

### 3.2 Code-span exclusion (in the function body)

Skill INVOCATIONS in prose read `run /issue`, `the /weekly skill`. Path fragments
and incident notes that survive the regex almost always live inside backtick code
spans or fenced code blocks (`` `/workspace/logs/...` ``, `` `data/issue<N>/...` ``).
Excluding both removes the bulk of false positives:
- **Fenced blocks:** track a `in_fence` toggle on lines whose lstrip starts with
  ```` ``` ```` or `~~~`; skip lines inside a fence.
- **Inline code:** strip `` `...` `` spans (`re.compile(r"`[^`]*`")`) before
  matching, so a path in backticks contributes nothing.

Re-use the module-level inline-code stripper; add it next to the regex:
```python
INLINE_CODE_RE = re.compile(r"`[^`]*`")
```

### 3.3 New function `_check_skill_refs`

Signature mirrors `_check_references(workflow)` for dispatch-shape consistency
(the `workflow` param is unused in v1 but kept so the function fits the ladder and
a future check can resolve skill names declared in workflow.yaml). Override hooks
(`doc_files`, `skills_dir`, `allowlist_path`) are added — keyword-only, defaulting
to None → canonical paths — so tests can scope to `tmp_path` fixtures, exactly as
`check_script_references(roots=..., scripts_dir=...)` does.

```python
def _check_skill_refs(
    workflow: WorkflowYaml,  # noqa: ARG001 -- kept for dispatch-shape parity with _check_references
    *,
    doc_files: tuple[Path, ...] | None = None,
    skills_dir: Path | None = None,
    allowlist_path: Path | None = None,
) -> list[str]:
    """Walk DOC_FILES and FAIL on any `/<skill-name>` slash-command token in
    PROSE that resolves to neither a live skill dir under `.claude/skills/*/`
    nor the declared allowlist (`.claude/skill_ref_allowlist.txt`).

    Skill refs are matched only in prose: fenced code blocks and inline-backtick
    spans are excluded (a path in backticks is not a skill invocation). A line
    carrying the HISTORICAL_REF_OPT_OUT comment is skipped entirely — the same
    per-line narrative-citation escape hatch `check_script_references` uses.

    `doc_files`, `skills_dir`, `allowlist_path` are test override hooks;
    production callers pass all None and the function uses the canonical paths.
    """
    errors: list[str] = []
    files = doc_files if doc_files is not None else DOC_FILES
    sk_dir = skills_dir if skills_dir is not None else _REPO_ROOT / ".claude" / "skills"
    live = {p.name for p in sk_dir.iterdir() if p.is_dir()} if sk_dir.exists() else set()
    allow = _load_skill_ref_allowlist(allowlist_path)
    for path in files:
        if not path.exists():
            continue
        in_fence = False
        for lineno, raw in enumerate(path.read_text().splitlines(), start=1):
            stripped = raw.lstrip()
            if stripped.startswith("```") or stripped.startswith("~~~"):
                in_fence = not in_fence
                continue
            if in_fence:
                continue
            if HISTORICAL_REF_OPT_OUT in raw:
                continue
            line = INLINE_CODE_RE.sub("", raw)
            for match in SKILL_REF_RE.finditer(line):
                ref = match.group(1)
                if ref not in live and ref not in allow:
                    errors.append(
                        f"{path}:{lineno}: unresolved skill ref '/{ref}' — "
                        f"not a live skill under .claude/skills/*/ and not in "
                        f".claude/skill_ref_allowlist.txt. Repoint to the current "
                        f"skill, add it to the allowlist (deprecated / external / "
                        f"plugin-namespaced skill), or — for a narrative "
                        f"false-positive only — append '{HISTORICAL_REF_OPT_OUT}' "
                        f"to the line."
                    )
    return errors
```

**Live-set resolution = `.claude/skills/*/` DIR names**, NOT `*/SKILL.md`. The
Goal says "resolve each against `.claude/skills/*/`" verbatim; dir-based resolution
also includes `clean-results` (which carries `SPEC.md`, no `SKILL.md`) — the
candidate's `glob("*/SKILL.md")` would have wrongly flagged a future `/clean-results`
prose ref. Empirically the dir-based live set is 22 names; the SKILL.md-based set
is 21 (drops `clean-results`).

### 3.4 Allowlist loader `_load_skill_ref_allowlist`

Format mirrors `tests/sparse_cones.txt`: one skill name per line, `#` comments,
blank lines ignored. Placed next to `_check_skill_refs`.

```python
SKILL_REF_ALLOWLIST_PATH = _REPO_ROOT / ".claude" / "skill_ref_allowlist.txt"

def _load_skill_ref_allowlist(allowlist_path: Path | None = None) -> set[str]:
    """Load the skill-ref allowlist (one name per line, `#` comments + blank
    lines ignored). Missing file → empty set (the check still resolves against
    live skill dirs)."""
    path = allowlist_path if allowlist_path is not None else SKILL_REF_ALLOWLIST_PATH
    if not path.exists():
        return set()
    out: set[str] = set()
    for line in path.read_text().splitlines():
        token = line.split("#", 1)[0].strip()
        if token:
            out.add(token)
    return out
```

## 11. Decision Rationale

**No ML hyperparameters — `N/A — no model training`.** Every load-bearing choice
is a code-design knob; its `Source:` is the in-file pattern it mirrors.

- **What:** Resolve the live skill set against `.claude/skills/*/` DIR names (not
  `*/SKILL.md`).
  **Why:** Matches the Goal's verbatim "resolve against `.claude/skills/*/`";
  dir-based includes `clean-results` (SPEC.md-only, no SKILL.md), so a future
  `/clean-results` prose ref resolves correctly. The candidate's
  `glob("*/SKILL.md")` would wrongly flag it.
  **Source:** Empirical scan (dir-based = 22 names incl. `clean-results`;
  SKILL.md-based = 21) + the Goal text.
  **Alternatives:** `glob("*/SKILL.md")` (candidate sketch) — rejected, drops
  `clean-results`.

- **What:** Regex `SKILL_REF_RE = r"(?:(?<=^)|(?<=[\s(\[{]))/([a-z][a-z0-9-]*(?::[a-z0-9-]+)?)(?![\w/:-])(?!\.\w)"`.
  **Why:** The candidate's bare `r"/([a-z][a-z0-9-]+)"` matched ~347 distinct
  tokens (almost all path segments) — unusable. Left-anchoring to start-of-token
  + a right-boundary excluding word/`/`/`-`/`:` continuations AND `.`-followed-by-word-char
  (dotted-path continuation, e.g. `/workflow.yaml`) + the code-span exclusion
  (next item) cuts it to ~11, of which 7 are live skills. The split-boundary
  `(?![\w/:-])(?!\.\w)` (rather than the simpler `(?![\w./:-])`) is
  load-bearing — a single-`.` exclusion would silently miss a dangling ref at
  sentence-end (`Run /weekly.`), leaving the exact #713 dangling-ref class
  uncaught (round-1 critic ensemble Must-Fix; both Claude + Codex Methodology
  REVISE flagged this). Hyphens cannot be banned (real skills are hyphenated);
