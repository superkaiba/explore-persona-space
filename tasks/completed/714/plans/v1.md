## Method delta (what differs from `--check-script-refs`)

| Aspect | `--check-script-refs` | `--check-skill-refs` (new) |
|---|---|---|
| Reference regex | `(?<![\w/])scripts/([A-Za-z0-9_]+\.py)\b` | `` `/([a-z][a-z0-9-]*(?::[a-z0-9-]+)?)(?:[ >][^`]*)?` `` (backtick-wrapped slash-command form) |
| Resolution set | files under `scripts/` | directory names under `.claude/skills/` (dir existence, NOT `SKILL.md` — `clean-results` has no `SKILL.md`) |
| Allowlist | per-line `<!-- lint: historical-ref -->` opt-out only | a declared `SKILL_REF_ALLOWLIST` frozenset (user-global / plugin / built-in / non-skill FPs) + the SAME per-line opt-out for one-off narrative citations |
| Scope | agents + skills (`_resolve_ask_target_files`) | **identical** scope (agents + skills) |
| Bundling | `--check-references` + no-flags | **identical** |

**Three method deltas worth calling out:**

1. **Backtick-required matching is the central design choice.** A bare-`/foo`
   regex (the candidate's `r"/([a-z][a-z0-9-]+(?::[a-z0-9-]+)?)\b"`) matches
   path segments (`/skills`, `/agents`, `/workspace`, `/tmp`), HTML close tags
   (`</summary>`), Handlebars (`{{/each}}`), and prose — 57+ distinct false
   positives requiring an unmanageable allowlist (see §4 grep evidence). The
   backtick-wrapped form is how skill invocations are actually written in this
   project's prose, is high-signal (like `--check-asks` keying on the literal
   `AskUserQuestion` token), and reduces the unresolved set to **19 entries**,
   all legitimately allowlistable. It still catches the original bug (`/weekly`,
   8 hits).
2. **Resolution by skill DIRECTORY existence, not `SKILL.md`.** `clean-results`
   is a live skill dir (`/clean-results` is a real reference) but holds only
   `SPEC.md` / `exemplars/` / `iterations.md` — no `SKILL.md`. The candidate's
   `glob("*/SKILL.md")` would wrongly flag `/clean-results`. Resolve against
   `{p.name for p in Path(".claude/skills").iterdir() if p.is_dir()}` instead.
3. **A declared allowlist (not just per-line opt-out).** Unlike
   `--check-script-refs` (where dangling refs are rare and one-off), legitimate
   non-project skill commands recur across many files (`/humanize` x9, `/loop`
   x11). Per-line opt-outs would litter the surface; a central declared
   allowlist documents the closed set once. The per-line opt-out is ALSO
   retained for genuinely one-off narrative citations.

## §4 Design

### 4.1 The regex + resolution function

Add near `SCRIPT_REF_RE` (after line 220):

```python
# `--check-skill-refs`: every backticked slash-command skill reference
# (`/weekly`, `/issue <N>`, `/humanize quick`, `/codex:setup`) in an agent /
# skill spec MUST resolve to a live skill dir under `.claude/skills/<name>/`
# or to a declared SKILL_REF_ALLOWLIST entry. Backtick-wrapped form ONLY:
# a bare `/foo` matches path segments (`/skills`, `/tmp`), HTML close tags
# (`</summary>`), and Handlebars (`{{/each}}`) — 57+ false positives. The
# backtick form is how skill invocations are actually written in prose and is
# high-signal (mirrors --check-asks keying on the literal `AskUserQuestion`).
# Group 1 = the skill name (optionally `<plugin>:<skill>`); a trailing
# space/`>`-led arg run inside the SAME backticks (e.g. `/loop 10m /issue <N>`,
# `/humanize quick`) is consumed but not captured.
SKILL_REF_RE = re.compile(r"`/([a-z][a-z0-9-]*(?::[a-z0-9-]+)?)(?:[ >][^`]*)?`")

# Inline per-line opt-out for a ONE-OFF narrative skill citation (a since-
# retired skill named for historical context on a single line). Reuses the
# same comment token as the script-ref check — its semantics are identical
# (this line is narration, not an executable invocation). For recurring
# legitimate non-project commands use SKILL_REF_ALLOWLIST instead.
# (HISTORICAL_REF_OPT_OUT is already defined at line 220 and is reused.)
```

Resolution + walk function (added next to `check_script_references`, ~line 1145):

```python
def _live_skill_names(skills_dir: Path) -> set[str]:
    """Return the set of live skill names: every immediate child DIRECTORY of
    `.claude/skills/`. Resolution is by DIRECTORY existence, not by SKILL.md —
    `clean-results` is a live skill dir holding SPEC.md/exemplars/ with no
    SKILL.md, and `/clean-results` is a legitimate reference."""
    if not skills_dir.exists():
        return set()
    return {p.name for p in skills_dir.iterdir() if p.is_dir()}


def check_skill_references(
    *,
    roots: list[Path] | None = None,
    skills_dir: Path | None = None,
    allowlist: frozenset[str] | None = None,
) -> list[str]:
    """Walk `.claude/agents/**.md` + `.claude/skills/**/SKILL.md` and FAIL on
    any backticked `/skill-name` reference that resolves neither to a live
    skill dir under `.claude/skills/` NOR to SKILL_REF_ALLOWLIST.

    Closes the skill-rename / skill-retirement rot class: `--check-references`
    only resolves `(see workflow.yaml § X)` tokens, so a retired skill (e.g.
    `/weekly`) leaves stray load-bearing references that no mechanical check
    catches (#713 Methodology-critic finding; #714).

    Lines inside fenced code blocks (``` / ~~~) are skipped: code samples carry
    HTML close tags / sed one-liners / regex fragments whose `/x` shapes are
    not skill invocations. Lines carrying HISTORICAL_REF_OPT_OUT are skipped
    (one-off narrative citation). Plugin-namespaced refs (`/codex:setup`)
    resolve if `.claude/skills/<plugin>:<skill>/` exists (forward-compat;
    none today) OR if the `<plugin>:<skill>` token is in the allowlist.

    `roots` / `skills_dir` / `allowlist` are unit-test override hooks; production
    callers pass None.
    """
    errors: list[str] = []
    sk_dir = skills_dir if skills_dir is not None else _REPO_ROOT / ".claude" / "skills"
    live = _live_skill_names(sk_dir)
    allow = allowlist if allowlist is not None else SKILL_REF_ALLOWLIST
    for path in _resolve_ask_target_files(roots):
        in_fence = False
        for lineno, line in enumerate(path.read_text(encoding="utf-8").splitlines(), start=1):
            if _FENCE_RE.match(line):
                in_fence = not in_fence
                continue
            if in_fence or HISTORICAL_REF_OPT_OUT in line:
                continue
            for match in SKILL_REF_RE.finditer(line):
                ref = match.group(1)
                if ref in live or ref in allow:
                    continue
                errors.append(
                    f"{path}:{lineno}: unresolved skill reference '/{ref}' — "
                    f"not a live skill under .claude/skills/ and not in "
                    f"SKILL_REF_ALLOWLIST. Repoint to the current skill, remove "
                    f"the dead reference, add the command to SKILL_REF_ALLOWLIST "
                    f"(user-global / plugin / built-in command), or — for a "
                    f"one-off narrative citation — append "
                    f"'{HISTORICAL_REF_OPT_OUT}' to the line."
                )
    return errors
```

`_FENCE_RE` (added near the regexes): `re.compile(r"^\s*(?:```|~~~)")`.

> **Note on `_resolve_ask_target_files` + fences:** that helper already
> excludes OTHER worktrees and scans the current one. The fence state is
> tracked per-file inside the loop (reset on each `path`), so a code fence in
> one file cannot bleed into the next.

### 4.2 DOC_FILES-scope decision + justification

**Decision: use the `--check-script-refs` scope (`.claude/agents/**.md` +
`.claude/skills/**/SKILL.md` via `_resolve_ask_target_files`), NOT the
`DOC_FILES` triple, NOT a third scope.**

**Justification (with measured hit counts):** the bug (`/weekly`-style stale
refs) lives predominantly in `.claude/agents/` (research-pm.md, retrospective.md),
which the `DOC_FILES` triple (`CLAUDE.md` + `issue/SKILL.md` + `issue/markers.md`)
does NOT cover. Measured `/weekly` coverage:

- `DOC_FILES` triple: **3** of the `/weekly` references.
- `--check-script-refs` scope (agents + every skill's SKILL.md): **7**.

Skill references rot exactly like script references rot (a renamed/retired skill
leaves dangling mentions in any agent or skill spec that invokes it), so the
script-refs scope is the right precedent (`scripts/workflow_lint.py:1105`,
`_resolve_ask_target_files` at 882). Using the identical scope also lets the new
check reuse `_resolve_ask_target_files` verbatim (worktree exclusion for free)
and keeps the two sibling checks symmetric.

**Scoped-out (deliberately):** `.claude/rules/*.md` carries 1 additional
`/weekly` hit and `CLAUDE.md` carries skill refs too, but adding them would
diverge from the script-refs precedent and widen the allowlist surface.
Matching the script-refs scope exactly is the conservative, precedent-faithful
choice; widening to rules/ + CLAUDE.md is a clean follow-up if desired (noted in
§Risks). The allowlist below is computed against the agents+skills scope, so the
check is green-on-main at that scope.

### 4.3 Initial allowlist (file path + verbatim contents)

**Format decision: an in-module `SKILL_REF_ALLOWLIST` frozenset with an inline
comment per entry**, mirroring `MARKER_REGISTRY_ALLOWLIST` (line 284) and
`AGENT_MODEL_ALLOWLIST` (line 430). NOT a separate `.claude/skill_ref_allowlist.txt`
file. Rationale: every existing allowlist in this lint is in-module + inline-
commented; a separate text file would diverge from precedent, add a second file
to keep in sync, and lose the per-entry inline justification convention. The set
is small (19) and drifts slowly (one entry per new user-global/plugin command
referenced), exactly the `MARKER_REGISTRY_ALLOWLIST` profile.

## §11 Decision Rationale

**Backtick-required matching regex**
- **What:** `` `/([a-z][a-z0-9-]*(?::[a-z0-9-]+)?)(?:[ >][^`]*)?` `` — only
  backtick-wrapped slash-commands match.
- **Why:** tied to the Goal (catch stale skill refs without drowning in FPs).
  A bare-`/foo` regex yields 57+ distinct false positives (path segments, HTML
  close tags, Handlebars, prose); the backtick form is the canonical invocation
  syntax in this project's prose, is high-signal, reduces the unresolved set to
  19 ergonomic entries, and still catches the original `/weekly` bug (8 hits).
  Mirrors the `--check-asks` design of keying on a high-signal literal token.
- **Source:** `--check-script-refs` precedent (`scripts/workflow_lint.py:209`,
  `SCRIPT_REF_RE` left-boundary discipline) + `--check-asks` precedent
  (`scripts/workflow_lint.py:897`, literal-`AskUserQuestion` keying) + the §4.5
  grep evidence over the live tree.
- **Alternatives:** (1) candidate's bare `r"/([a-z][a-z0-9-]+(?::[a-z0-9-]+)?)\b"`
  — rejected: 57+ FPs, unmanageable allowlist. (2) refined-boundary bare regex
  with fence + HTML-close exclusion — rejected: still 39 FPs.

**Resolution by skill-directory existence (not SKILL.md)**
- **What:** `{p.name for p in Path(".claude/skills").iterdir() if p.is_dir()}`.
- **Why:** `clean-results` is a live skill dir with no `SKILL.md` (it holds
  SPEC.md/exemplars/iterations.md); resolving against `*/SKILL.md` would wrongly
  flag the legitimate `/clean-results` reference.
- **Source:** on-disk inspection (`.claude/skills/clean-results/` has no
  SKILL.md, confirmed); the candidate's `glob("*/SKILL.md")` would FP here.
- **Alternatives:** candidate's `*/SKILL.md` glob — rejected (flags
  `/clean-results`).

**Scope = `--check-script-refs` scope (agents + skills), not DOC_FILES triple**
- **What:** `_resolve_ask_target_files(None)` → `.claude/agents/**.md` +
  `.claude/skills/**/SKILL.md`.
- **Why:** the bug lives mostly in `.claude/agents/` (7 `/weekly` hits in scope
  vs 3 in the DOC_FILES triple); skill refs rot like script refs rot.
- **Source:** §4.2 measured hit counts; `scripts/workflow_lint.py:1105` +
  `:882` precedent.
- **Alternatives:** DOC_FILES triple — rejected (misses the agent-spec refs that
  are the bulk of the bug).

**Allowlist as in-module frozenset (not a separate text file)**
- **What:** `SKILL_REF_ALLOWLIST: frozenset[str]`, inline-commented per entry.
- **Why:** every existing allowlist in this lint is in-module + inline-commented;
  a separate `.txt` would diverge from precedent, add a sync burden, and lose
  the per-entry justification convention. The set is small + slow-drifting.
- **Source:** `MARKER_REGISTRY_ALLOWLIST` (`scripts/workflow_lint.py:284`),
  `AGENT_MODEL_ALLOWLIST` (`:430`).
- **Alternatives:** `.claude/skill_ref_allowlist.txt` (candidate suggestion) —
  rejected (no precedent, sync burden); inline `<!-- skill-ref-ok -->` opt-outs
  as the PRIMARY mechanism — rejected (recurring commands like `/humanize` x9 /
  `/loop` x11 would litter the surface; opt-out retained only for one-off
  narrative citations via the existing `HISTORICAL_REF_OPT_OUT`).

**Fenced-code + per-line opt-out exclusions**
- **What:** skip lines inside ``` / ~~~ fences; skip lines carrying
  `HISTORICAL_REF_OPT_OUT`.
- **Why:** code samples carry HTML close tags / sed one-liners / regex fragments
  whose `/x` shapes aren't invocations; reusing the existing opt-out token keeps
  the one-off escape hatch consistent with `--check-script-refs`.
- **Source:** `HISTORICAL_REF_OPT_OUT` (`scripts/workflow_lint.py:220`); §4.5
  grep showed fenced exclusion drops the worst HTML/regex FPs.
- **Alternatives:** no fence exclusion — rejected (backtick form already drops
  most, but a backticked `` `/p` `` inside a sed example in a fence is a residual
  FP the fence exclusion removes cleanly).
