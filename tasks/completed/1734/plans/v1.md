### 4.3 Change 3 — Decision: PROSE enforcement, reader-side backstop named

**Decision (recorded, per §11):** PROSE enforcement in `.claude/skills/issue/SKILL.md` Step 2, NOT a new mechanical `verify_plan.py` check.

**Why:** the task body itself frames the trade-off in "Consider, and record the decision either way." Three concrete reasons weigh against a mechanical `verify_plan.py` `wf-fix`-gated FAIL check on the missing `epm:plan-verify` marker:

1. **Ordering / chicken-and-egg.** `verify_plan.py` is invoked at Phase 1.5.0 by the adversarial-planner skill itself; the `epm:plan-verify` marker is posted AFTER `verify_plan.py` returns (per the current L374-378 recipe). A new check that FAILs when the marker is absent for THIS plan version would need to be OFF for the current verify_plan.py run and ON for a hypothetical NEXT re-verify — non-trivial state to thread, and the natural implementation ("check the marker exists for a PRIOR plan version") does not catch the #1692 / #1709 case where NO version has a marker.
2. **Blast radius.** `verify_plan.py` runs on non-`wf-fix` tasks too; even gated on the wf-fix tag / title prefix, a new FAIL check adds an axis of risk to the standing 40-check verifier that today gates every plan across the fleet.
3. **The recorded-skip contract IS the mechanism.** A session that self-certifies past the SKILL.md prose ships an `epm:plan` note that either (a) records the skip with its reason — audit trail intact — or (b) does not, in which case a downstream reviewer (or `/daily`'s Step-2 audit mining) sees the missing note the same way it sees any other missing marker. The mechanical `wf-fix` check is proposing to enforce documentation of a skip; a strict PROSE contract that names the recorded shape achieves the same forensic value at zero verifier blast radius.

**Reader-side backstop (named per the brief's "if PROSE-only, name the backstop"):** the code-reviewer ensemble at Step 5 (Claude + Codex) reads the plan and the events.jsonl on a `wf-fix`-tagged PR; a `wf-fix` PR whose events lack any `epm:plan-verify` marker fails the code-reviewer's substantive-review bar under a new bullet in `code-reviewer.md` Step 6 ("Plan Deviation Check"). Concretely: add ONE bullet to `code-reviewer.md` Step 6 that reads `**Step-2 floor check (wf-fix / infra workflow-surface tasks).** If the task is wf-fix (`WF_FIX_TITLE_PREFIXES` prefix or `wf-fix` tag) and the events.jsonl carries NO `epm:plan-verify` marker, FAIL with tag \`step2-floor-skipped\` — the Step-2 floor was not run and no recorded-skip reason exists to justify it.` This uses the existing code-reviewer FAIL machinery (marker-shape / substantive tag) rather than a new mechanical check in `verify_plan.py`.

**Note on scope:** this reader-side backstop is a THIRD prose edit, not a fourth mechanical file. Adding it fits the task body's "consider, record either way" without breaking the 2-file scope guidance (the third file is a one-bullet addition, ≤4 lines).
