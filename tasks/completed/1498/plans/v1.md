## 4. Design

**Method delta vs existing arms:** the import-map arm matches tests by *what they import*; the new arm matches by *which repo paths their text spells out*. Same pass, same fail-soft, same additive contract, different matcher. Design (a) (scan, not curated map) — rationale §11.

All edits in `scripts/select_step9c_tests.py` + `tests/test_select_step9c_tests.py`. Concrete diff sketch:

**(1) Eligibility helper** (new, after `touched_module_names`):

```python
def literal_path_targets(touched: list[str]) -> set[str]:
    """Touched files eligible for the literal-path arm (#1498): .py code files
    under scripts/ or src/explore_persona_space/ (never tests/ — the
    touched-test arm owns those; .md / workflow-surface pin mapping is #1496's
    surface, deliberately out of scope here)."""
    return {
        f for f in touched
        if Path(f).suffix == ".py"
        and not f.startswith("tests/")
        and (f.startswith("scripts/") or f.startswith("src/explore_persona_space/"))
    }
```

**(2) Shared single-pass scanner** — refactor the body of `import_map_hits` into `_scan_test_files(touched, work_root) -> tuple[dict[str, set[str]], set[str], dict[str, set[str]]]` returning `(import_hits, import_tested, literal_hits)`:

- Early return (zero file reads) when `not module_map and not literal_targets` — preserves the workflow-surface-only-diff zero-cost property.
- Per test file: `read_text` in its own `try` (`(OSError, ValueError)` → `n_failed += 1`, WARN, skip BOTH arms); then the literal check on raw text (`for f in literal_targets: if f in text: literal_hits.setdefault(rel, set()).add(f)`); then the existing token pre-filter + `ast.parse` in a second `try` (`(SyntaxError, ValueError)` → WARN, skip the import arm ONLY — a parse-failed file still contributes literal hits, an additive improvement, documented in the docstring).
- `tokens` empty (no module map) → the `any()` pre-filter is `False` → zero parses on a literal-only scan.
- The >5% aggregate parse-failure WARN unchanged (`n_failed` counts read + parse failures, as today).

`import_map_hits(touched, work_root)` becomes a documented 2-line back-compat wrapper delegating to `_scan_test_files` and dropping the third element (one existing caller in tests, L980; `step9c_baseline.py` does not call it).

**(3) Wire into `select_tests_with_reasons`** (replace L614):

```python
import_hits, import_tested, literal_hits = _scan_test_files(touched, work_root)
selected: dict[str, set[str]] = _seed_import_reasons(import_hits)
for t, files in literal_hits.items():
    for f in files:
        selected.setdefault(t, set()).add(f"literal-path:{f}")
```

Additive by construction: only ever adds tests/reasons; never touches `matched`, `untested`, or any other arm's entries; terminal `sorted()` keeps determinism.

**(4) Docstring updates** (docstring-on-edit): module docstring — new arm bullet in the mapping list, reason vocabulary line (L131-132) gains `literal-path:<touched file>`, cost paragraph extended; `select_tests_with_reasons` + `import_map_hits` docstrings updated.

**(5) Deliberately NOT changed:** `WORKFLOW_SURFACE_GLOBS` and the `.md` skip (sibling #1496); `--map-files` / `map_scan_tests` (stays GLOB_SCAN_TESTS-only, §11 R4); diff-base logic (#865); `GLOB_SCAN_TESTS`, `WORKFLOW_INVARIANT`, `SLOW_TESTS`, timeout constants; `select_tests` signature.

Why code, not a model call: deterministic path arithmetic on every gate run — a model call is nondeterministic, slow, and banned for a selection gate. No new dependencies (stdlib + git only, module-docstring contract preserved).

## 11. Decision Rationale

N/A — no hyperparameters in this task type (kind: infra). Load-bearing design choices:

- **R1 — Design (a) scan, not (b) curated pin map + lint.** A curated map re-creates the exact failure mode this task fixes (a forgotten map entry = a silent gate hole), and its enforcing lint would itself be a whole-tree literal-path scan — i.e. design (a) running inside workflow_lint on every lint invocation instead of only on eligible diffs. Imports and literal paths are both mechanically discoverable by substring, unlike `GLOB_SCAN_TESTS`' dynamic scan globs (where curation is forced). Hybrid rejected: adds (b)'s burden without removing (a)'s scan. `Source:` #1299 (import-map chose scan over curation for exactly this reason); #895 (GLOB_SCAN_TESTS curation justified only by non-discoverability); task #1498 body.
- **R2 — Shared single read pass (`_scan_test_files`), not a second pass.** Zero added file reads; one WARN per unreadable file instead of two; the import arm's zero-cost skip on ineligible diffs is preserved. `import_map_hits` kept as wrapper (one external test caller, L980). `Source:` #1299 cost-profile precedent (task body suggests exactly this sharing).
- **R3 — Additive-only, no `untested_touched` suppression.** A literal-path pinning test asserts an invariant ABOUT the file (ruff cleanliness), not the file's own logic — no evidence the file's code executes. Import-map suppresses because the test imports and runs the module; glob-scan does not, for the same reason as here. Conservative direction = keep WARNs loud. `Source:` #895 (glob-scan additive-only precedent, L241-244); #1299 (the suppression rationale that does NOT transfer).
- **R4 — `--map-files` stays GLOB_SCAN_TESTS-only.** Read the Step 10d consumer (SKILL.md L9823-9849): the mapped leg's baseline-subtraction, file-grain hit attribution, 300 s bound ("measured basis ~12.6 s for both mapped tests"), and the #1337 `FILE_ANCHORED_SCAN_TESTS` scratch-oracle machinery are all tuned to the curated 2-entry map; injecting discovered literal-path tests would change that gate's cost and attribution assumptions unreviewed, and would add file reads to a currently zero-read hot path (called per push + per inline payload). The founding gap is the Step 9c diff gate, which this arm closes. Extending the mapped leg is a separable follow-up if ever wanted. Pinned by test case 11. `Source:` #1147, #1337.
- **R5 — Reason token `literal-path:<touched file>`.** Matches the existing `<arm>:<touched file>` vocabulary; verified the only reasons consumer (`step9c_baseline.py` L1412) is prefix-agnostic. `Source:` #1022/#1299 token conventions.
- **R6 — Raw substring on file text, not AST string-literal matching.** "Hardcodes by literal string" IS a text property; raw substring costs nothing extra (text already read), catches f-string-adjacent and comment-adjacent mentions in the safe (over-select) direction, and avoids parsing files the import pre-filter would skip. AST matching would still match docstrings, only excluding comments — negligible precision gain for real parse cost. `Source:` module-docstring safe-by-direction principle (L41-45).
- **R7 — Eligibility scoped to `.py` under `scripts/` + `src/explore_persona_space/`.** Matches the import-map arm's scope and the clarifier's code-file scoping (avoids #1496's `.md` surface). Known residual: non-`.py` literal pins (e.g. a test hardcoding `scripts/bootstrap_pod.sh`) are out of scope — documented in the module docstring as an extendable miss class. `Source:` #1299 scope precedent; clarifier scoping directive.

**Plan deviations allowed** (implementer discretion): exact internal function/test names, case numbering, docstring wording, WARN message text. **Must-ask (re-plan):** touching `WORKFLOW_SURFACE_GLOBS` / `.md` mapping (collides with #1496), extending `--map-files`, making literal hits suppress WARNs, touching diff-base logic (#865), any new dependency.
