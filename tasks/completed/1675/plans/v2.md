### 0.0 TL;DR (plain English)

- **What I'll change:** the piped-git Bash hook currently pattern-matches its guarded verbs anywhere in the command text, including inside quoted string arguments — so a read-only search whose quoted pattern mentions a guarded phrase gets refused. I'll add a quote-span transform into the hook's existing normalization step: strippable quoted spans are removed, substitution-bearing double-quoted spans are matched-and-kept as one atomic token (so their interiors can't corrupt later parsing), and backslash-escape pairs are consumed everywhere, before any matching runs.
- **What I expect:** the verbatim 07-23 incident shape and every quoted-mention sibling become allowed; every real piped git/gh command shape stays blocked — including the two adversarial counter-shapes the Phase-2 critics constructed (a `$`-bearing commit message with an interior apostrophe piped to a single-quoted awk; escaped apostrophes flanking a real pipe), which the v1 transform failed open on and the v2 transform blocks. Validated: 43/43 embedded self-test + 19/19 new-case battery on the rebuilt patched copy.
- **What would change my mind:** a true-positive shape the v2 transform converts to a miss beyond the one deliberately accepted, mechanism-named class (a quoted payload without live substitution handed to an interpreter / remote executor) or the rare ANSI-C `$'...'` escaped-quote residual — then I'd re-plan against the critique's trade space rather than patch further.

## 3. Design

**Chosen approach: quote-span transform with (i) a leading top-level escape-pair branch (M2 adoption), (ii) a captured-and-consumed preserve branch for substitution-bearing double-quoted spans (M1 mitigation), and (iii) strippable single-/double-quoted span branches — folded into the existing normalization sed.** Position-anchoring remains rejected (v1 §3 argument, unchanged: it mechanically fails the verbatim incident — the quoted `\|` fabricates a stage boundary putting the guarded verb at stage start — and regresses keyword-prefixed true positives).

### 3.1 The transform (verbatim, validated)

**Edit 1 — new top-level ERE variable**, inserted after the `PREFILTER_ERE` definition (:95). Realized line (copied from the validated patched copy):

```bash
# Quoted-span strip (#1675): remove quoted STRING ARGUMENTS before any
# matching. Branches, in order: (1) PRESERVE — a double-quoted span with a
# bare $ or backtick (live substitution: a "$(...)" payload EXECUTES) is
# MATCHED, captured as group 1, and replaced by ITSELF + a space — consumed
# atomically, so its interior (apostrophes included) can never seed a later
# span match; (2) top-level escape pairs \<any> are consumed (bash treats
# \' \" \| as literal chars, never quote/pipe operators); (3) single-quoted
# spans always strip (bash expands nothing inside, no escapes exist);
# (4) substitution-free double-quoted spans strip, consuming \-escape pairs
# so the incident's \| strips with its span. Branches are start-disjoint
# (no leftmost-longest ambiguity); replacement is "\1 " (group 1 unset on
# strip branches -> a single space; GNU sed substitutes empty).
STRIP_QUOTED_SPANS_ERE="(\"(\\\\.|[^\"\\\\\$\`])*[\$\`](\\\\.|[^\"\\\\])*\")|\\\\.|'[^']*'|\"(\\\\.|[^\"\\\\\$\`])*\""
```

The bash string expands to the ERE (verified in the patched copy):

```
("(\\.|[^"\\$`])*[$`](\\.|[^"\\])*")|\\.|'[^']*'|"(\\.|[^"\\$`])*"
```

Branch anatomy — with `P = \\.|[^"\\$`]` (escape pair or any char except quote/backslash/dollar/backtick) and `Q = \\.|[^"\\]` (escape pair or any char except quote/backslash):

| # | branch | matches | replacement effect |
|---|---|---|---|
| 1 | `("P*[$`]Q*")` (group 1) | double-quoted span containing ≥1 bare `$`/backtick | `\1 ` — kept verbatim + trailing space, CONSUMED (M1 fix) |
| 2 | `\\.` | backslash + any char in unquoted text | space — escape pairs consumed (M2 fix) |
| 3 | `'[^']*'` | single-quoted span | space |
| 4 | `"P*"` | substitution-free double-quoted span | space |

Branches 1 and 4 are DISJOINT by construction (1 requires ≥1 bare `$`/backtick; 4 forbids them), and branches 2/3/4 start on different characters — no reliance on alternation tie-breaking.

**Edit 2 — fold into the line-119 sed** (single process, no new fork). Realized line:

```bash
cmd=$(printf '%s' "$cmd" | sed -zE -e 's/\\\r?\n/ /g' -e "s/${STRIP_QUOTED_SPANS_ERE}/\\1 /g")
```

Continuation normalization first (a quoted span broken across a backslash-continuation is rejoined before the strip; also guarantees branch 2 never sees `\<newline>`), strip second. `-z` (the existing line-119 idiom) lets spans match across raw newlines — which converts a PRE-EXISTING miss into a block (B24: a multi-line quoted commit message previously split the command at the raw newline into units that hid the producer from the pipe).

### 3.3 Span semantics + fail-direction table (CORRECTED per critique — honest about both directions)

Consumption-completeness is the M1/M2 design principle: every quote-opening or backslash character in the scanned text is consumed by exactly one branch (as a stripped span, a preserved atomic token, or an escape pair), so no span type's interior can seed another span type's match — the two v1 phantom-span channels (preserved-span interior apostrophe, M1; escaped-apostrophe pairing, M2) are closed by construction and pinned empirically (B25/B26).

| Text shape | Disposition | Fail direction vs bash semantics |
|---|---|---|
| `'...'` single-quoted | stripped, consumed | exact for POSIX single quotes (no expansion, no escapes inside) |
| `"..."` substitution-free (no bare `$`/backtick; `\|`/`\"`/`\$` consumed as escape pairs) | stripped, consumed | escaped-quote boundary matches bash's (backslash-escape notion identical inside double quotes) |
| `"...$...."` / `` "...`..." `` (bare `$`/backtick) | PRESERVED as one atomic token (+ trailing space); interior still scanned by the downstream verb/pipe match; interior can no longer seed spans | block-leaning: a live `"$( )"` payload stays blocked (B19/B20); a `$VAR`-bearing quoted mention stays a residual FP |
| `\<any>` escape pair in unquoted text | consumed → space | matches bash (escaped chars are literals, never operators); retires escaped-pipe phantom stages and the M2 pairing; also improves fidelity on `\"`-literal shapes |
| unbalanced quote | unmatched → text scanned raw | block-leaning (bash would error on the unclosed quote anyway) |
| `$'...'` ANSI-C with `\'` | NOT modeled (the `'` opens branch 3 before the interior `\'` is seen) | **fail-open OR fail-closed possible** — a dangling `'` left by the mis-paired span can pair with a later `'` and eat a real pipe. Rare in Bash-tool commands; named in the header rewrite as the one unmodeled quoting form (M2's leading branch covers plain `\'` outside `$'...'`, which is the common case) |

**Named fail-open classes after this fix — exactly two, both stated in the header rewrite:** (1) **the interpreter/remote-executor payload class, by MECHANISM: a quoted payload with no live substitution passed to an interpreter or remote executor** (`bash -c '...'`, `sh -c "..."` substitution-free, `eval '...'`, `xargs ... sh -c`, `python -c 'os.system(...)'`, `ssh host '...'`, `tmux send-keys`) — the payload is string data to the guard but executes downstream; deliberate, pinned A30 (single-quote form) + A31 (double-quote substitution-free form); accepted under the hook's stated bias (:30–31), zero recorded incidents of this shape (#957/#1584 were direct commands), lint + prose rule remain defense-in-depth (A18/A23 accepted-miss precedent). (2) **the ANSI-C `$'...'` escaped-quote residual** — unmodeled, rare, both fail directions possible. Everything else in the table fails toward BLOCK. The v1 claim that every divergence fails toward scan/block was WRONG (the critics' B25/B26 counter-shapes) and is not carried into any v2 surface.
