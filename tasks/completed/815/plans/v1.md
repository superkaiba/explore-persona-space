## 1. Plan summary

Two-prong, non-architectural workflow-surface guardrail against a repeat of the 2026-07-01 incident where the #778 analyzer improvised `git reset --hard` on the shared repo root during marker-chain recovery and silently truncated concurrent siblings #812 and #813 (their `body.md` / `plans/` / `comments.jsonl` / REGISTRY entries; recovered manually across commits `81c52d6a2b` for #813 and `d29a877e6f` for #812, the latter literally titled "restore … after concurrent 'git reset --hard' clobber").

1. **Anti-drift lint** — a new `check_no_repo_root_git_reset_hard(...)` in `scripts/workflow_lint.py`, bundled into the no-flags default run, that FAILs when an agent spec (`.claude/agents/*.md`) or skill playbook (`.claude/skills/**/SKILL.md`) contains an **unqualified** `git reset --hard` — one that is neither worktree-qualified (`git -C "$WT" reset --hard`) nor carries an explicit allowlist sentinel. No other agent spec is amended (minimal blast radius; the analyzer is the sole known offender and the CLAUDE.md line-39 bullet is the cross-agent standing rule).

Detection rule per matched `git reset --hard` occurrence (matched in BOTH fenced code blocks and prose — the check catches both, per design constraint 1):
- **PASS (worktree-qualified)** — the SAME line contains a `git -C "<path>"` (or `git -C <path>`) prefix before the `reset --hard`. This is the sanctioned per-worktree pattern.
- **PASS (allowlisted)** — the SAME line carries the sentinel `workflow-lint: allow-git-reset-hard` (in an HTML comment `<!-- ... -->` or a trailing `#`/backtick note). Requires a human-written reason token after the sentinel (≥1 non-space char), mirroring the `# WANDB_INTENTIONALLY_DISABLED: <reason>` waiver pattern.
- **FAIL (everything else)** — a bare / repo-root `git reset --hard` with neither qualifier. Error message names the file:line, quotes the offending text, and states the fix (`git -C "$WT" reset --hard <ref>` in a per-worktree, or add the allowlist sentinel with a reason if it is a legitimate prose mention).

Pseudocode (mirrors `check_no_workflow_improver_spawn` structure):

```python
# Module-level, near the other detector regexes (~line 3358):
# Whitespace-tolerant; matches inside fenced blocks AND inline-backtick prose.
_GIT_RESET_HARD_RE = re.compile(r"git\s+reset\s+(?:-[A-Za-z]+\s+)*--hard")
# A worktree-qualified `git -C "<path>" ...` prefix on the same line.
_GIT_DASH_C_RE = re.compile(r"git\s+-C\s+")
_RESET_HARD_ALLOW_SENTINEL = "workflow-lint: allow-git-reset-hard"


def check_no_repo_root_git_reset_hard(*, repo_root: Path | None = None) -> list[str]:
    """FAIL if any agent spec / skill playbook contains an UNQUALIFIED
    `git reset --hard` (a repo-root / full-tree reset). Only per-worktree
    `git -C "$WT" reset --hard` invocations, or lines carrying the
    `workflow-lint: allow-git-reset-hard: <reason>` sentinel, pass.

    Incident 2026-07-01 (#815): a #778 analyzer improvised `git reset --hard`
    on the shared repo root during marker-chain recovery and truncated
    concurrent siblings #812/#813 (body.md / plans/ / comments.jsonl /
    REGISTRY). task.py holds a per-registry flock, not a per-file lock, so a
    repo-root reset by any concurrent session clobbers unrelated tasks.

    Scope: `.claude/agents/*.md` + `.claude/skills/**/SKILL.md` only (reuses
    `_iter_ask_target_files`, which already excludes OTHER worktrees' sibling
    copies). `.claude/plans/`, `.claude/agent-memory/`, `.claude/rules/`,
    `CLAUDE.md`, and `scripts/**` are out of the workflow surface for this
    check and NEVER scanned. Pure-Python; bundled into the no-flags run.
    `repo_root` is a unit-test override hook; production callers pass None.
    """
    root = repo_root if repo_root is not None else _REPO_ROOT
    errors: list[str] = []
    for p in _iter_ask_target_files(root):          # already worktree-safe + scoped
        try:
            text = p.read_text(encoding="utf-8")
        except (OSError, UnicodeDecodeError):
            continue
        for lineno, line in enumerate(text.splitlines(), start=1):
            if not _GIT_RESET_HARD_RE.search(line):
                continue
            if _GIT_DASH_C_RE.search(line):         # worktree-qualified -> OK
                continue
            if _RESET_HARD_ALLOW_SENTINEL in line:  # explicit allowlist -> OK
                # require a non-empty reason after the sentinel
                _, _, tail = line.partition(_RESET_HARD_ALLOW_SENTINEL)
                if tail.lstrip(": ").strip():
                    continue
            errors.append(
                f"{p}:{lineno}: unqualified `git reset --hard` on the shared "
                f"repo root is forbidden (clobbers concurrent siblings' task "
                f"state — incident #815, commit d29a877e6f). Use a per-worktree "
                f'`git -C "$WT" reset --hard <ref>`, or add a same-line '
                f"`{_RESET_HARD_ALLOW_SENTINEL}: <reason>` sentinel if this is a "
                f"legitimate prose mention / pod-side ssh_execute command."
            )
    return errors
```

their `body.md` / `plans/` / `comments.jsonl` were truncated and #812's REGISTRY

NOT require a reset at all — append a corrective `epm:progress` marker via

--check-no-repo-root-git-reset-hard`.
