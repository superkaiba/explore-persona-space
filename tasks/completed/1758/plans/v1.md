# Plan v1 — task #1758: `--retry-suspects` prints a zero-match notice

## Goal / requirement

`scripts/daily_drive_filings.py --retry-suspects` must say, loudly on stderr, when it
has nothing to retry — instead of silently no-oping when zero slugs in the driven
slice carry a suspect ledger row.

**Acceptance criteria**
1. A driver run with `--retry-suspects` where NO slug in the sliced manifest carries a
   `landed-fix-suspect` ledger row prints ONE loud stderr notice line naming the
   condition, AND the terminal `SUMMARY dir=...` stderr line reflects it.
2. A driver run with `--retry-suspects` where ≥1 sliced slug carries a suspect row
   prints NO such notice (behavior unchanged).
3. A driver run WITHOUT `--retry-suspects` is byte-unchanged on stderr regardless of
   ledger contents (in particular, `test_summary_hint_when_suspects_nonzero`'s
   "no `--retry-suspects` text in a clean SUMMARY" assertion keeps passing).
4. The `daily-drive-summary` LEDGER row schema is untouched (its docstring declares the
   eight-counter key set exact; the reflection is print-line-only).
5. Dry-run prints the notice too (the notice is computed pre-loop from the loaded
   ledger; dry-run read-only contract untouched).

## Method delta (what differs from prior work)

Pure additive observability on the existing #1674/#1735 suspect machinery. No change to
`_slug_state`, probe logic, ledger writes, or re-drive semantics. The zero-match
predicate is the task body's own wording: "zero slugs in the driven slice carry a
suspect ledger row" — implemented with the existing `_has_landed_fix_suspect_row`
helper (NOT `_slug_state == "retry-suspect"`), so an ERROR+suspect slug run under both
retry flags still counts as a match and cannot draw a false "nothing to retry" notice.

## Concrete diff (2 files)

### `scripts/daily_drive_filings.py`

1. **`main()`** — after `ledger` + `sliced` are computed, BEFORE the drive loop:

   ```python
   retry_suspect_matches: int | None = None
   if args.retry_suspects:
       retry_suspect_matches = sum(
           1 for item in sliced if _has_landed_fix_suspect_row(ledger, item["slug"])
       )
       if retry_suspect_matches == 0:
           print(
               "NOTICE: --retry-suspects matched 0 recorded suspects in this"
               " slice — nothing to retry (#1758)",
               file=sys.stderr,
           )
   ```

   Computed from the pristine loaded ledger (pre-loop), so mid-run appends cannot
   shift it; prints on dry-run too.

2. **`_emit_daily_drive_summary`** — new keyword-only param
   `retry_suspect_matches: int | None = None` (None = flag unset). When `== 0`,
   append a suffix to the PRINTED line only:
   ` — --retry-suspects matched 0 recorded suspects (nothing retried)`.
   The ledger row's `counts` dict is untouched (exact-key-set contract). `main()`
   threads the value through.

### `tests/test_daily_drive_filings.py`

Two tests appended, using the existing `make_item` / `make_filings_dir` / `run_driver`
/ `make_stub` fixtures:

1. `test_retry_suspects_zero_match_notice` — fresh dir, no suspect rows, run WITH
   `--retry-suspects`: rc 0; stderr contains the NOTICE line; the SUMMARY line carries
   the zero-match suffix; the `daily-drive-summary` ledger row's `counts` key set is
   unchanged (the eight keys exactly).
2. `test_retry_suspects_notice_absent_when_matched_or_flag_unset` — (a) ledger
   pre-seeded with a `landed-fix-suspect` row for a sliced slug, run WITH the flag:
   no NOTICE line, no zero-match suffix; (b) fresh dir run WITHOUT the flag: no
   NOTICE line (stderr behavior unchanged).
