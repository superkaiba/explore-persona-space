### 4.1 Parser change (src/explore_persona_space/task_workflow.py:2368-2380)

Exact new body (the diff, matching the candidate sketch; first-hit-wins preserved — lines outer, segments inner, left-to-right):

```python
    for line in (note or "").splitlines():
        # `; `-joined single-line notes (#1090 fu1/fu2 scopes, #841 scopes +
        # run markers) expose their fields as clause segments; a line with
        # no `;<whitespace>` yields itself unchanged, so every line-initial
        # form parses exactly as before. The whitespace after `;` is the
        # anchor: a `;` inside a token (URL, code, `a;b=1`) never splits.
        for seg in re.split(r";\s+", line):
            # One regex pass strips any interleaved mix of whitespace, bullet
            # dashes/stars, and bold markers (unchanged from the line-core rule).
            core = re.sub(r"^[\s\-*]+", "", seg)
            if core.startswith(f"{field}:") or core.startswith(f"{field}="):
                rest = core[len(field) + 1 :].lstrip("*").strip()
                tokens = rest.split()
                value = tokens[0] if tokens else ""
                value = value.strip("`'\"*").rstrip(",;")
                return value or None
    return None
```

Two deltas from current code: (a) the inner `re.split(r";\s+", line)` loop; (b) `rstrip(",")` → `rstrip(",;")` (fixes the line-initial-field-with-trailing-`;` case: #841's run markers currently parse `followup_label` as `scaling-capture;`). Everything else byte-identical, deliberately: strip order, first-token rule, bold/bullet handling.

**Anchoring rule (precise):** each `; `-split segment is treated exactly like a line-core — strip leading whitespace/bullets/bold, then `startswith(field + ":"/"=")`. Consequences pinned in tests: `(source: user-chat)` mid-line (the #685 shape) still parses `None` (segment starts with `(`); `word;followup_label: x` (no whitespace after `;`) still `None`; a first-line mid-segment field now beats a later line's line-initial field (first-hit-wins is line-then-segment order — corpus-clean, pinned as deliberate).

**Docstring update** (same function): add the `; `-joined single-line form (#1090/#841) to the enumerated forms, the segment-anchoring rule, and `;` in the trailing-strip set.

1. **Semicolon split `re.split(r";\s+", line)` as an inner loop.** What: each `; `-clause is a line-core. Why: minimal superset — no-`;` lines parse byte-identically; the whitespace anchor keeps in-token semicolons (URLs, `a;b=1`) unsplit. Source: candidate diff sketch; #961's `[;.]` clause precedent (task_workflow.py:2673); 0/505 corpus false positives. Alternatives: mid-line regex search (rejected — parses arbitrary prose); bare-`;` split (rejected — splits tokens).
2. **`rstrip(",")` → `rstrip(",;")`, same strip order.** What: strip trailing `;` after wrapper strip. Why: line-initial fields carry the `;` inside the first token when unsplit (#841 currently parses `scaling-capture;`); keeping strip order avoids an unforced behavior change on wrapper/separator edges. Source: body sketch; #841 corpus rows; #664 trailing-comma precedent.
3. **Run-marker leading-prose: field-only.** What: no label inference from a leading kebab token. Why: benefits exactly 1/107 corpus markers; needs context the API lacks; contradicts the documented conservative-close architecture; fu2 needs orchestrator action regardless. Source: corpus survey; `unrun_followup_labels` docstring (2494-2496); SKILL.md 1085-1117.
4. **Emitter-side notes: YES (SKILL.md ×2, workflow.yaml ×2, one line each).** Why: the fu1 failure was emitter-side (no fields at all — no parser can absorb that); the body names both surfaces. Alternative (docstring-only) rejected: the emitting orchestrator reads SKILL.md step 4, not the parser docstring.
5. **#1090 repair: corrective re-posts with non-`retroactive-close` outcomes, before merge.** Why: closes both labels the instant the fix lands (zero re-dispatch window) AND restores cap accuracy (retro-close markers are cap-exempt by design; #1090's cap is genuinely 2/2-consumed per interp v8). Source: SKILL.md C2 + loop step 5; live evidence check. Alternatives: retro-close outcomes (rejected — cap undercount lets 2 more cheap rounds auto-fire); Step 0 skip-and-surface only (rejected — permanent manual burden + cap bug unfixed).
6. **Corpus-replay allowlist for the fu1 marker.** Why: the test's forward invariant ("every run marker parses a label") is right; the one violation is repaired as data (decision 5) but its note text is append-only-immutable, so the test pins it as known — any NEW unparseable marker still fails. Source: the pytest failure this session; #894 plan v3 (the test's origin). Alternative (weakened assertion) rejected — couples the test to repair timing and hides new drift classes.
