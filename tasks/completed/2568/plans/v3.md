# Plan v3 — #2568 consumer-supersession audit (kind: infra, workflow-fix)

## 0. Requirement + acceptance criteria

**Requirement (from the task Goal).** When a round refutes evidence that committed
downstream artifacts consume (a claims-registry row, a paper/poster figure
generator, a methodology doc), nothing today mechanically enumerates those
consumers or verifies they carry a supersession label. Build the recurring audit
and wire it into the surface run at fold-in.

**Acceptance criteria** (each maps to a deliverable below):

1. A helper `scripts/audit_artifact_supersession.py` exists that (a) discovers
   committed `superseded_*.json` records, (b) validates each against a canonical
   schema, (c) RE-RUNS the consumer enumeration fresh (`git grep` over the
   refuted artifact names, producers + mechanical-noise classes excluded), and
   (d) reports every consumer that neither consumes the replacement artifact nor
   carries a supersession label, with `file:line` per unlabeled mention.
2. The audit is wired into two recurring surfaces: (i) the analyzer's same-issue
   re-fold checklist (`.claude/agents/analyzer.md` + its section-reference
   mirror) as a new duty item, and (ii) a `workflow_lint.py
   --check-artifact-supersession` check bundled into the no-flags default run
   (unlabeled consumer = FAIL line; malformed/unrecognized record = WARN line —
   the Goal's "FAIL/WARN" split).
3. The audit only SURFACES — it never auto-edits consumers (task body's explicit
   non-goal).
4. The canonical record schema matches the #1901 plan-v15 §10 worked example
   semantically: (i) refuted claim/artifact set, (ii) refuting-evidence
   pointers, (iii) replacement artifact(s), (iv) enumerated consumers at
   record-write time; the test fixture mirrors that instance.
5. Tests land with the change and pass (`tests/test_audit_artifact_supersession.py`
   + a lint-bundling test), and the no-flags `workflow_lint.py` run is UNCHANGED
   on the current repo (zero `superseded_*.json` records are committed today, so
   the new check is a verified no-op at landing).

## 2. Design

### 2.1 Canonical record schema (`artifact-supersession-record-v1`)

Committed as `eval_results/issue_<N>/**/superseded_<slug>.json` (git-tracked;
the tool audits TRACKED records only). Keys:

```json
{
  "schema": "artifact-supersession-record-v1",
  "issue": 1901,
  "refuted_claim": "one-line prose of the refuted claim/join",
  "refuted_artifacts": ["scaling_ladder_L19.json", "mlp_scaling_L19.json", "scaling_bigN_acc1_L19.json"],
  "evidence": ["epm:progress 2026-08-25T03:18:29Z on #1901", "tasks/.../artifacts/mlpdense-smoke-r3-g1fail.log"],
  "replacement_artifacts": ["mlp_scaling_dense_L19.json"],
  "consumers_at_record_time": ["docs/paper_context_answer_map/claims.md", "scripts/issue1901_body_figures.py", "docs/posters/mats_2026/make_plot1_scaling.py"],
  "producers": ["scripts/issue1901_mlpdense_run.py"],
  "label_patterns": ["superseded", "different eval pool"]
}
```

Required: `schema`, `issue`, `refuted_claim`, `refuted_artifacts` (non-empty,
each ≥ 8 chars — bare common words make the grep useless), `evidence`
(non-empty), `replacement_artifacts` (MAY be empty when no replacement exists —
then only the label arm can pass a consumer). Optional: `consumers_at_record_time`
(provenance only — the audit NEVER trusts it; it re-enumerates), `producers`
(paths excluded from enumeration), `label_patterns` (defaults below). Unknown
keys tolerated (forward-compat). The schema spec's single source of truth is the
tool's module docstring + a `SCHEMA_VERSION` constant.

**#1901 coordination:** the worked-example record
(`eval_results/issue_1901/paper_densify/superseded_cross_store_join.json`) has
NOT landed yet — #1901's live session writes it at plan-v15 phase c5. After this
task lands, post one informational `epm:progress` note on #1901 naming the
canonical schema (script path + docstring) so phase c5 can conform. If the
landed record diverges, the audit emits a WARN (unrecognized schema + migration
recipe), never a hard crash — loud, non-breaking, one-line fix on either side.

### 2.2 Audit algorithm (per record)

1. Validate schema. Malformed / unrecognized ⇒ one WARN line naming the record
   + the missing/wrong field (strict mode: FAIL).
2. Enumerate consumers FRESH: for each name in `refuted_artifacts`,
   `git grep -l -F <name>` over tracked files (worktree of the invoking
   checkout). Union the hits.
3. Exclude (mechanical-noise classes, each recorded in the JSON report as
   excluded-with-class, mirroring #2332's positive-verdict discipline):
   the record file itself + every other `superseded_*.json`; paths listed in
   `producers`; the refuted/replacement artifact files themselves;
   `tasks/**` (bodies/events/plans — historical record, governed by the
   standing promoted-body correction rule; `--include-tasks` opts in);
   `eval_results/**` + `ood_eval_results/**` (data trees, provenance strings
   are inert); `figures/**` (regenerated outputs; the GENERATOR script is the
   consumer that matters).
4. Per surviving consumer file, PASS iff (a) the file mentions ANY
   `replacement_artifacts` name (fixed-string), OR (b) EVERY line mentioning a
   refuted name has a label pattern within ±5 lines (case-insensitive; defaults
   `superseded`, `different eval pool`, `different-eval-pool`; record may
   override via `label_patterns`). Else emit one violation per unlabeled
   mention: `FAIL: <record>: consumer <file>:<line> mentions <name> with no
   supersession label and does not consume <replacement>`.
5. Exit 0 when clean (WARNs allowed), 1 on ≥1 violation, 2 on usage error.
   `--json <path>` writes the machine-readable report; `--record <path>`
   audits one explicit record (used by tests + the analyzer duty).

**Disclosed false negatives** (docstring, mirroring the #2165 scanner-disclosure
norm): a consumer referencing the artifact via a variable, glob, f-string
fragment, or wrapped/split literal escapes the fixed-string grep; a label
farther than ±5 lines from the mention reads as unlabeled (false positive —
fix by moving the label or consuming the replacement). The reviewer/analyzer
remains the catching arm.

**Dependencies:** stdlib + `subprocess` git calls only — no
`explore_persona_space` imports, no dotenv/HF (keeps the script outside the
scripts-import-guard / dotenv lint families).

### 2.3 Lint wiring

`check_artifact_supersession(*, repo_root: Path | None = None) -> list[str]` in
`scripts/workflow_lint.py`:

- Loads the audit core from the sibling script via
  `importlib.util.spec_from_file_location` on
  `<repo_root>/scripts/audit_artifact_supersession.py` (single source of truth
  — NO logic duplication); a load failure is itself a FAIL line, never a silent
  skip (the new-fence-silent-pass class).
- Runs discovery + audit; maps violations → FAIL lines, schema problems →
  `WARN:` lines.
- Registered as `--check-artifact-supersession` AND bundled into the no-flags
  default run (`if args.check_artifact_supersession or no_flags:`). Fleet
  impact is bounded by design: today the check is a no-op (zero committed
  records); once #1901's record lands, any unlabeled-consumer FAIL lines name
  exactly the consumer files, and the Step 9c / inline payload gates are
  payload-attributed, so only rounds committing those files block — the correct
  pressure. Docstring gets the standard check description block.

## 7. Kill criteria

- If fresh enumeration on realistic fixtures (the three #1901 consumer files'
  names) produces > ~20 tracked hits per artifact name after the exclusion
  classes — i.e. the names are too generic for a fixed-string grep to be a
  useful consumer signal — STOP and re-plan the matching semantics (path-scoped
  enumeration or record-supplied consumer globs) instead of shipping a noisy
  FAIL-generating default-run check.
- If the importlib sibling-load pattern trips an existing lint/test invariant
  that cannot be satisfied without logic duplication, fall back to keeping the
  core in the audit script and having the lint check SUBPROCESS it
  (`sys.executable`, not `uv run`), recording the deviation.
