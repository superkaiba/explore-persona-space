# Plan v4 — #2568 consumer-supersession audit (kind: infra, workflow-fix)

## 0. Requirement + acceptance criteria

**Requirement (from the task Goal).** When a round refutes evidence that committed
downstream artifacts consume (a claims-registry row, a paper/poster figure
generator, a methodology doc), nothing today mechanically enumerates those
consumers or verifies they carry a supersession label. Build the recurring audit
and wire it into the surface run at fold-in.

**Acceptance criteria** (each maps to a deliverable below):

1. A helper `scripts/audit_artifact_supersession.py` exists that (a) discovers
   committed supersession RECORDS (basename-anchored `superseded_*.json` files —
   NOT the contents of `superseded_*` directories), (b) validates each against a
   canonical schema, (c) RE-RUNS the consumer enumeration fresh (index-based
   `git grep --cached` over the refuted artifact names, producers +
   mechanical-noise classes excluded), and (d) reports every consumer that
   neither consumes the replacement artifact nor carries a supersession label,
   with `file:line` per unlabeled mention.
2. The audit is wired into two recurring surfaces: (i) the analyzer's same-issue
   re-fold checklist (`.claude/agents/analyzer.md` + its mirror
   `.claude/rules/analyzer-section-reference.md`) as a new duty item, and (ii) a
   `workflow_lint.py --check-artifact-supersession` check bundled into the
   no-flags default run (unlabeled consumer = FAIL line; malformed/unrecognized
   record or `acknowledged_pending` consumer = WARN line — the Goal's
   "FAIL/WARN" split).
3. The audit only SURFACES — it never auto-edits consumers (task body's explicit
   non-goal).
4. The canonical record schema matches the #1901 plan-v15 §10 worked example
   semantically: (i) refuted claim/artifact set, (ii) refuting-evidence
   pointers, (iii) replacement artifact(s), (iv) enumerated consumers at
   record-write time; the test fixture mirrors that instance.
5. Tests land with the change and pass, and the no-flags `workflow_lint.py` run
   is UNCHANGED on the current repo — verified satisfiable: basename-anchored
   discovery returns 0 records on the live tree today (the git pathspec
   `eval_results/**/superseded_*.json` form instead matches 12 files under
   issue_1482's `superseded_*` DIRECTORIES, which is why discovery is
   basename-anchored; those directory contents are a pinned negative fixture).

## 2. Design

### 2.1 Canonical record schema (`artifact-supersession-record-v1`)

Committed as `eval_results/issue_<N>/**/superseded_<slug>.json` — a FILE whose
basename matches `superseded_*.json` (canonical fallback location when the
replacement artifact has no committed neighbor, e.g. HF-only:
`eval_results/issue_<N>/superseded_<slug>.json`). The tool audits git-TRACKED
records only. Keys:

```json
{
  "schema": "artifact-supersession-record-v1",
  "issue": 1901,
  "refuted_claim": "one-line prose of the refuted claim/join",
  "refuted_artifacts": ["scaling_ladder_L19.json", "mlp_scaling_L19.json", "scaling_bigN_acc1_L19.json"],
  "evidence": ["epm:progress 2026-08-25T03:18:29Z on #1901", "tasks/.../artifacts/mlpdense-smoke-r3-g1fail.log"],
  "replacement_artifacts": ["mlp_scaling_dense_L19.json"],
  "consumers_at_record_time": ["docs/paper_context_answer_map/claims.md", "scripts/issue1901_body_figures.py", "docs/posters/mats_2026/make_plot1_scaling.py"],
  "producers": ["scripts/issue1901_mlpdense_run.py"],
  "acknowledged_pending": [],
  "label_patterns": ["superseded", "different eval pool"]
}
```

Required: `schema`, `issue`, `refuted_claim`, `refuted_artifacts` (non-empty,
each ≥ 8 chars — bare common words make the grep useless), `evidence`
(non-empty), `replacement_artifacts` (MAY be empty when no replacement exists —
then only the label arm can pass a consumer). Optional:
`consumers_at_record_time` (provenance only — the audit NEVER trusts it; it
re-enumerates), `producers` (paths excluded from enumeration),
`acknowledged_pending` (consumer paths whose conformance is explicitly routed
but not yet landed — the audit reports these as WARN, not FAIL; see the
atomicity contract below), `label_patterns` (defaults below). Unknown keys
tolerated (forward-compat). The schema spec's single source of truth is the
tool's module docstring + a `SCHEMA_VERSION` constant.

**Record-landing atomicity contract (fleet-green invariant).** The commit that
introduces or refreshes a record MUST bring every enumerated consumer to PASS
in the SAME commit (label or repoint) — genuinely unfixable residuals are
either routed BEFORE the record lands or carried in `acknowledged_pending`
(WARN). This is what keeps the live tree's no-flags lint green: the fleet-wide
`tests/test_workflow_lint.py::test_workflow_lint_default_exits_zero` invariant
runs the no-flags lint on the committed tree and asserts rc == 0, with NO
payload attribution — a standing unlabeled-consumer FAIL would red the full
pytest suite for every session (§2.3 names this channel).

**#1901 coordination:** the worked-example record
(`eval_results/issue_1901/paper_densify/superseded_cross_store_join.json`) has
NOT landed yet — #1901's live session writes it at plan-v15 phase c5. After this
task lands, post one informational `epm:progress` note on #1901 naming (a) the
canonical schema (script path + docstring) AND (b) the atomicity contract —
fresh enumeration today finds MORE surviving consumers than v15's frozen
3-member list (also `docs/methodology/issue_1901.md` and
`scripts/issue1901_boundary_token_control.py`), so phase c5's record commit
must label/repoint all of them or carry the residue in `acknowledged_pending`.
If the landed record diverges from the schema, the audit emits a WARN
(unrecognized schema + migration recipe), never a hard crash — loud,
non-breaking, one-line fix on either side.

### 2.2 Audit algorithm (per record)

All reads are CHECKOUT-INDEPENDENT (sparse worktrees exclude `eval_results/`,
so a record is index-listed but absent on disk exactly where the no-flags lint
runs): record discovery via `git ls-files -- eval_results/` + Python-side
`fnmatch` on the BASENAME (`superseded_*.json`); record content via
`git cat-file blob :<path>` (never a working-tree `open()`); enumeration via
`git grep --cached`.

1. Validate schema. Malformed / unrecognized ⇒ one WARN line naming the record
   + the missing/wrong field (strict mode: FAIL).
2. Enumerate consumers FRESH: for each name in `refuted_artifacts`,
   `git grep --cached -l -F <name> -- . ':!tasks' ':!eval_results'
   ':!ood_eval_results' ':!figures'` (grep-time pathspec excludes — the
   excluded classes below applied at grep time for wall-time: a full-tree grep
   measured ~15 s/name on the shared VM; with the bulk trees excluded the audit
   stays seconds-scale). Union the hits.
3. Exclude (recorded in the JSON report — TREE-CLASS exclusions recorded at
   class level, per-file excluded-with-class recording for producers/records/
   self only, mirroring #2332's positive-verdict discipline):
   `tasks/**` (bodies/events/plans — historical record, governed by the
   standing promoted-body correction rule; `--include-tasks` opts in);
   `eval_results/**` + `ood_eval_results/**` (data trees, provenance strings
   are inert — also excludes every supersession record); `figures/**`
   (regenerated outputs; the GENERATOR script is the consumer that matters);
   paths listed in `producers`; the refuted/replacement artifact files
   themselves (index-path suffix match on the artifact names).
4. Per surviving consumer file, PASS iff (a) the file mentions ANY
   `replacement_artifacts` name (fixed-string), OR (b) EVERY line mentioning a
   refuted name has a label pattern within ±5 lines (case-insensitive; defaults
   `superseded`, `different eval pool`, `different-eval-pool`; record may
   override via `label_patterns`). A consumer listed in `acknowledged_pending`
   ⇒ WARN instead of FAIL. Else emit one violation per unlabeled mention:
   `FAIL: <record>: consumer <file>:<line> mentions <name> with no
   supersession label and does not consume <replacement>`.
5. Exit 0 when clean (WARNs allowed), 1 on ≥1 violation, 2 on usage error.
   `--json <path>` writes the machine-readable report; `--record <path>`
   audits one explicit record (used by tests + the analyzer duty).

**Disclosed false negatives AND false-PASS modes** (docstring, mirroring the
#2165 scanner-disclosure norm): a consumer referencing the artifact via a
variable, glob, f-string fragment, or wrapped/split literal escapes the
fixed-string grep (false negative); a label farther than ±5 lines from the
mention reads as unlabeled (false positive — fix by moving the label or
consuming the replacement); the file-level OR-arm (a) PASSes a claims registry
that ADDS a replacement-citing row while keeping the refuted row unlabeled —
exactly the founding incident's surface at the row grain; a "superseded"
occurrence within ±5 lines that refers to a DIFFERENT claim passes arm (b).
The reviewer/analyzer remains the catching arm for all four.

**Dependencies:** stdlib + `subprocess` git calls only — no
`explore_persona_space` imports, no dotenv/HF (keeps the script outside the
scripts-import-guard / dotenv lint families).

### 2.3 Lint wiring

`check_artifact_supersession(*, repo_root: Path | None = None) -> list[str]` in
`scripts/workflow_lint.py`:

- Loads the audit core `__FILE__`-RELATIVE from the lint's own `scripts/` dir
  (`Path(__file__).parent / "audit_artifact_supersession.py"`) via
  `importlib.util.spec_from_file_location` — single source of truth, NO logic
  duplication — and audits the PASSED `repo_root` (so fixture-tree tests
  exercise the real core, not the load-failure branch); a core load failure is
  itself a FAIL line, never a silent skip (the new-fence-silent-pass class).
- Runs discovery + audit against `repo_root`; maps violations → FAIL lines,
  schema problems + `acknowledged_pending` consumers → `WARN:` lines.
- Registered as `--check-artifact-supersession`, bundled into the no-flags
  default run (`if args.check_artifact_supersession or no_flags:`), AND
  classified in `CHECK_SCOPES` as `global` (record-keyed repo scan, #2235 —
  omitting the classification bounces the meta-test). Docstring gets the
  standard check description block.
- Fleet impact, complete channel list: (i) Step 9c / inline payload gates are
  payload-attributed — only rounds committing a named consumer file block;
  (ii) `tests/test_workflow_lint.py::test_workflow_lint_default_exits_zero`
  asserts no-flags rc == 0 on the committed tree with NO payload attribution —
  the §2.1 record-landing atomicity contract (+ `acknowledged_pending` WARN
  escape) is what keeps this invariant green; (iii) today the check is a
  verified no-op (basename-anchored discovery: 0 records on the live tree).
