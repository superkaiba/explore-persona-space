## 4. Design — method delta + concrete diff

**Method delta vs the existing #825 coverage:** the ownership-check bullet (§ "Orchestrator vs subagent re-invocation", L100) covers (i) duplicate-launch ownership probing and (ii) the EMPTY-dir false-DONE ("Monitor DONE with no outputs" → verify-first). This bullet covers the complementary failure: a NON-EMPTY, stale, prior-version output that makes an existence-keyed condition fire instantly on a RE-RUN (equally, a first run into a dirty path). Disjoint scopes, one cross-reference, no duplication. It also lands in § Monitoring (the how-to-watch-a-run section) rather than § re-invocation (the who-owns-the-run section), matching where an agent composing a Monitor condition actually looks.

**File:** `CLAUDE.md`. **Insertion point:** end of the § Monitoring (MANDATORY) bullet list — a new line after current L464 (`- Report results immediately on completion.`). **Verbatim bullet (the complete diff, +1 line):**

```diff
 - Always: `grep -iE 'error|traceback|killed|OOM' logfile`.
 - Report results immediately on completion.
+- **Re-runs: never key a Monitor/until-loop "done" condition on bare file existence.** When re-running a script whose output path already exists — equally, a first run into a path a prior/sibling run already wrote — key the condition on process exit (pid gone, or a freshly-written sentinel carrying the exit code; remove any stale sentinel at launch) or a fresh output mtime newer than the launch timestamp; prefer the process-exit key (an mtime can read fresh on a half-written file). A stale prior-version artifact satisfies an existence check instantly (#779, 2026-07-15: an until-loop fired "done" on a pre-existing v1 JSON while the v2 re-run was still executing; the stale-EXISTING-file sibling of the #825 empty-dir false-DONE covered by the ownership-check bullet in § "Orchestrator vs subagent re-invocation").
```
