#### 4.0 Architecture: two prongs sharing one new evidence primitive

**New evidence primitive** — `_git_blob_reproducibility_evidence(cache_dir, *, main_repo, byte_cap, verdict_cache)` in `scripts/clean_experiment_downloads.py`:

For every regular file under `cache_dir` (walk with `os.walk`, symlinks never followed and never verified — an rmtree removes the link, not the target):

- **Exempt dirs** (pruned from the walk; rebuildable tool state by construction): `.git`, `.venv`, `venv`, `__pycache__`, `.pytest_cache`, `node_modules`, `.ruff_cache`, `.mypy_cache`. Exact set pinned as module constant `_SCRATCH_EXEMPT_DIR_NAMES`.
- **Small-text tolerance** (the ONLY non-proof acceptance): extension ∈ `{.txt, .log, .out, .err, .diff}` AND size < 5 MiB AND the path is NOT under any dir named `store` or `eval_results` AND cumulative tolerated bytes ≤ 64 MiB per candidate. Motivation: gate telemetry (`gated-lint.txt`, `own.diff` measured at the top of `issue-1895-gate2`) is regenerable gate output, not data. `.md`/`.json`/`.jsonl` are deliberately NOT tolerated (notes and judge outputs live there).
- **Everything else must blob-verify:** compute the git blob SHA-1 in Python (`sha1(b"blob %d\x00" % size + content)`, streamed in chunks; files opened with `os.O_RDONLY | os.O_NOATIME`, falling back to a plain open on `PermissionError`/`OSError` — O_NOATIME is legal for the owning uid, and it stops the janitor's own verification from refreshing the recency signal), then confirm existence in the MAIN repo odb via one batched `git -C <repo_root()> cat-file --batch-check` subprocess (SHAs streamed on stdin in chunks; a `missing` line fails that file). Short-circuit on the first unverified file.
- **`.git`-bearing candidates** (full clones / scratch worktrees): the `.git` dir itself is exempt from per-file verification, but two extra probes run: (i) `git -C <cand> for-each-ref --format='%(objectname)'` — every ref tip must exist in the MAIN repo odb (`cat-file --batch-check`; catches an unpushed local branch in a full clone whose commits exist only in the clone's own odb); (ii) `git -C <cand> stash list` must be empty. Any git subprocess failure (dangling worktree husk, timeout at 120 s, non-`sha1` object format via `git rev-parse --show-object-format`) → `None` (fail-toward-keep).
- **Byte cap:** total bytes to hash bounded by env `EPS_SCRATCH_VERIFY_MAX_GB` (default 64); over-cap → `None` with reason `over-verify-cap` (escalate-only, never a partial verdict).
- **Verdict cache:** `.claude/cache/scratch-verify-cache.json`, keyed `(abspath, tree_newest_mtime, total_bytes)` → `{verdict, first_unverified, ts}`. Cache hit skips re-hashing an unchanged tree (bounds the daily cron cost); any key component change invalidates. Cache read/write failures are non-fatal (treated as miss).

Returns an evidence string on PASS (`git-blob-reproducible: <n_verified> files verified, <n_tolerated> small-text tolerated`) or `None` + a detail dict (`first_unverified`, counts, bytes) on FAIL.
