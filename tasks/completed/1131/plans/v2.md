   uv run python scripts/task.py view <M> --json | jq -r --arg ts "<E.ts>" \

2. **Binding test (what actually suppresses a filing):** skip ONLY when a
   newer note UNAMBIGUOUSLY addresses the mined premise — it names E's marker

   check 1 on #M. This is a targeted tail re-check at filing time, not a
   transcript re-read.
4. **On a suppressing hit:** do NOT file. Record the problem in `## Other
   problems & notes` as: `skipped filing: premise retracted upstream — #<M>
   <E.kind> at <E.ts> retracted by <kind> v<n> at <ts>: "<short quote>"`.

## 6. Kill criteria (what would make this change wrong)

1. **False-positive suppression:** the check skips a LEGITIMATE filing — e.g. a newer note matches the recall regex and superficially references the marker kind but the underlying gap is real. Mitigations designed in: the binding test requires the note to address the mined PREMISE (not just the marker kind); ambiguity fails OPEN toward filing; every skip is recorded visibly in `## Other problems & notes` + implicitly auditable in the daily file; a skipped filing creates no `wf-fix-fp` tag, so a later re-raise (next /daily, or a human) is never dedup-blocked. If skips are observed suppressing real gaps in practice, the rule is revised or reverted (one revert of the SKILL.md commit).
2. **Cost/fragility regression:** the per-filing scan meaningfully slows or destabilizes the nightly run (e.g. paging huge notes into context). Designed out: the scan is one Bash+jq call per marker-mined filing (typically ≤ a handful per night), notes truncated to 400 chars, only filtered rows enter context.
3. **Contract drift:** the insertion breaks a pinned #706 substring or the lint gate — caught mechanically by the Reproducibility Card before commit.

## 11. §11 Decision Rationale

**11.1 — Retraction-match heuristic: recall-aid regex + LLM binding test (not regex-decides).**
- **What:** the regex `RETRACTION|retract(ed|ion)|supersed|no workflow gap|nothing to file` only NOMINATES rows to read; suppression requires the binding test (same task #M, ts strictly > E.ts, note names E's marker kind / quotes a distinctive phrase / plainly addresses the mined premise); ambiguity files anyway with a note.
- **Why:** the false-positive kill criterion (§6.1) — a bare regex would suppress on an unrelated "retract" mention; conversely a stricter mechanical-only match (exact marker-kind mention required) would miss valid retractions phrased differently. The sweep is LLM-driven (Assumption 11), so the semantic binding judgment is available for free at the point of decision.
- **Source:** the parked candidate's diff_sketch (regex + "names E's marker kind or quotes it") — extended with the fail-open clause; the fail-direction is grounded in the incident economics: a wrong FILE costs one session spawn + clarifier (the #1101 cost, bounded, self-correcting — the clarifier caught it), while a wrong SKIP loses a real fix (unbounded downstream cost) — so ambiguity must file. In-repo precedent for evidence-binding discipline: `task_workflow.followup_retro_close_evidence` ("ambiguity NEVER closes" — exact-match evidence classes; docstring read this session), same conservatism, mirrored direction.
- **Alternatives:** regex-only suppression (rejected: kill criterion §6.1); requiring an explicit `RETRACTION` keyword (rejected: under-recalls — "superseded by", "no longer applies" phrasings are live).

**11.2 — Prose-only rule, no `task_workflow.py` helper.**
- **What:** the check lives entirely in SKILL.md prose + a prescribed one-liner over the EXISTING `task.py view --json` surface; no new function, no new fixture-based unit test.
- **Why:** (a) the decision is semantic (binding test) — a mechanical `retraction_evidence()` predicate would have to be either regex-decides (kill criterion) or so conservative it misses valid retractions, and the LLM executing /daily must read the nominated rows either way; (b) the candidate is `confidence: medium` — minimal-surface fixes are the right dose (scope creep on a medium-confidence candidate burns planner/critic/review capacity on speculative machinery); (c) `list_events` / `view --json` already provide the mechanical substrate — the recipe was executed live against #1074 during planning and returns exactly the needed rows; (d) durability is still mechanical: the doc-pinning test (Edit 4) pins the contract tokens, following the in-repo pattern of `test_daily_three_route_classifier_doc.py` (which pins the #706 three-route contract the same way).
- **Source:** in-repo pattern — the #706 route contract is likewise prose + substring-pinning test; `followup_retro_close_evidence` shows the helper road (it gates an AUTOMATED dispatch loop in /issue Step 0, where no LLM judgment sits at the decision point — /daily's sweep is the opposite). No web search needed — in-repo grounding suffices for a workflow-surface fix (noted per brief).
- **Alternatives:** helper `retraction_candidates(events, ts) -> list[dict]` mirroring `followup_retro_close_evidence` + a #1074-pair fixture test in `tests/test_task_workflow_retraction.py` (rejected for now — adds `src/` + test surface for a filter jq already does; revivable as a follow-up if practice shows the prose rule mis-executing); patching `daily_drive_filings.py` to re-check at drive time (rejected: the driver runs AFTER body composition — too late to save the composition work, and it lacks the mined-evidence ts, which lives in the sweep's working context, not the manifest).
