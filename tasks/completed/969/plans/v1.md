## 1. Goal, requirement, acceptance criteria

**Goal.** Close the v4 gap in the `pre_reg` prose-scan scope:
`_restrict_pre_reg_to_prose_sections()` (`scripts/audit_clean_results_body_discipline.py:530`,
gate at line 549) branches only on the v3 sentinel, so `<!-- clean-result-v4 -->`
bodies — the CURRENT spec — fall through to the WHOLE-BODY `pre_reg` scan. Per
`.claude/agents/clean-result-critic.md` Lens 7 (lines 975–980), the v4 ban covers
ALL FOUR H2s' PROSE (`## Takeaways` / `## Goal` / `## Methodology` / `## Results`)
and explicitly PERMITS pre-reg threshold values in the Methodology **Training**
hyperparameter table. The real v4 false-positive surface is therefore the TABLE
(`pre_reg` is not in `_TABLE_CELL_EXEMPT_CATEGORIES`, line 328): a spec-compliant
Source cell like `pre-registered floor (#612)` fires the audit today.

Note the original candidate's proposed v4 scope `('takeaways','results')`
CONTRADICTS Lens 7 — Goal + Methodology prose are banned surfaces too — so this
plan rejects it (see §11).

**Requirement.** For v4 bodies, exempt GFM table rows from the `pre_reg` scan;
keep every prose surface firing. v3 behavior byte-unchanged (three-section scope,
incident #623). v2/legacy whole-body behavior byte-unchanged. The carve-out stays
`pre_reg`-only (line 524–526 constraint): no other category's exemption surface
widens, and `_TABLE_CELL_EXEMPT_CATEGORIES` membership is untouched.

**Acceptance criteria.**
1. v4 body, `pre-registered` in `## Methodology` (or `## Goal` / `## Takeaways` / `## Results`) prose → `pre_reg` FIRES.
2. v4 body, pre-reg threshold phrasing inside the Methodology Training GFM table row → does NOT fire.
3. v4 footer: verbatim originating prompt in the `**Context:**` block (blockquote or inline form) → does NOT fire (already stripped by `strip_context_blockquotes`, sentinel-agnostic — pinned by a new test); other footer rows (`**Repro:**`, Created / Follow-up-to) → STILL SCANNED (deliberate, §11).
4. v3 bodies: all six existing v3 `pre_reg` tests pass WITHOUT edit.
5. v2/legacy bodies: whole-body scan preserved verbatim, INCLUDING inside table rows (new pin test).
6. Failure-degradation property preserved: a mis-detected boundary degrades to SCANNING a line that should have been blanked — never to a silently widened exemption (see §3).

## 11. Decision Rationale — the one load-bearing choice

**What:** v4 `pre_reg` scope = **whole-body-minus-GFM-table-rows** (reuse
`_blank_table_rows` inside the `pre_reg`-specific function), with the footer +
preamble deliberately left SCANNED (the footer's verbatim originating prompt is
already exempt via the sentinel-agnostic `strip_context_blockquotes`).

**Why:** (a) Lens 7 bans pre-reg mentions in ALL FOUR v4 H2s' prose — the
candidate's `('takeaways','results')` scope would wrongly exempt Goal +
Methodology prose, contradicting the spec. (b) The ONLY surface Lens 7 explicitly
PERMITS is the Methodology Training hyperparameter table — exactly what
`_blank_table_rows` exempts, and the only demonstrated v4 false-positive class.
(c) Given the v4 shape (stray content H2s hard-FAIL `verify_task_body.py`),
four-section-prose ≈ whole-body minus preamble/footer, so a four-H2 walker +
footer-boundary detection adds logic that buys exemption only for surfaces whose
one real verbatim-content conflict (#597/#651 originating prompt) is already
handled — and a footer-boundary mis-detection could blank Results prose,
violating the degradation property. (d) Conservative direction: every surface
not explicitly permitted keeps firing, so a mis-shaped body degrades to a
hand-adjudicated flag (the pre-#623 status quo), never a silent exemption; if a
real footer false positive ever occurs, a targeted incident-numbered carve-out
follows the file's established pattern (#597 → #623 → #651 → #892).

**Source:** `.claude/agents/clean-result-critic.md` Lens 7 lines 975–980 (read
this session); `.claude/skills/clean-results/SPEC.md` lines 852–857 / 1400–1405 /
1498; incidents #623 (v3 carve-out), #597/#651 (verbatim-prompt strips), #892
(regex widening, orthogonal); prior issue #969's originating candidate.

**Alternatives considered:** (i) candidate's two-section scope — REJECTED,
contradicts Lens 7. (ii) Four-H2 walker (`("takeaways","goal","methodology","results")`)
+ table blanking + footer/preamble exemption — REJECTED: more boundary logic for
near-zero spec-grounded benefit, and the footer-detection failure mode widens
exemptions. (iii) Add `pre_reg` to `_TABLE_CELL_EXEMPT_CATEGORIES` — REJECTED:
even setting aside that the `audit_body` dispatch checks `name == "pre_reg"`
first (making it a no-op without further rewiring), routing it that way would
leak the table exemption to v2/legacy bodies and widen a shared surface the
line-524 constraint keeps `pre_reg`-scoped.
