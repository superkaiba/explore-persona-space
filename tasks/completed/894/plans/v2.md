## 3. Design

### 3.1 The library helper (`src/explore_persona_space/task_workflow.py`, new — place after `_find_stage_breadcrumb`, ~line 1320)

Module constants: `FOLLOWUP_SCOPE_KIND = "epm:followup-scope"`, `FOLLOWUP_RUN_KIND = "epm:same-issue-followup-run"`, `USER_INITIATED_FOLLOWUP_SOURCES = frozenset({"user-chat", "step-10b-pick"})`.

**`parse_followup_note_field(note: str, field: str) -> str | None`** — first line whose core starts with `field:` after stripping leading `-`/`*`/whitespace and normalizing the bold `**field:**` form; value = first whitespace token of the remainder, stripped of `*` and trailing `,`; `None` if absent/empty. Handles all four observed forms (bare / dash-bullet / star-bullet / bold) AND the single-line run-marker note (first-token rule; kebab-slug labels contain no whitespace). First hit wins — the #763 v2 scope embeds a second bold `**followup_label:**` deep inside its verbatim-proposal section; the top-of-note canonical line is hit first.

**`followup_label_groups(events: list[dict]) -> list[dict]`** — grouping algorithm:

```
scopes = [e for e in events if e.kind == FOLLOWUP_SCOPE_KIND]
sort scopes ascending by (version or 0, _stage_event_ts or datetime.min)   # version is per-kind
                                                                            # monotonic (task.py
                                                                            # _next_event_version)
prev_label = None; groups = ordered dict label -> group
for ev in scopes:
    label = parse_followup_note_field(ev.note, "followup_label")
    if label:            parse_mode = "parsed"
    elif prev_label:     label, parse_mode = prev_label, "inherited-from-previous"
                         # the #658-v2 unlabeled-CORRECTION shape: a correction
                         # follows the scope it corrects -> attribute to it
    else:                label, parse_mode = f"unlabeled-{ev.ts}", "pseudo-ts"
                         # leading unlabeled scope: its own pseudo-label keyed by
                         # ts -> NEVER silently dropped
    prev_label = label
    group.setdefault(...): armed_ts = first entry's ts (arming time — a later
                           correction never re-queues the label)
    group.authoritative = ev            # last in (version, ts) order wins
    group.label_parse = parse_mode of the authoritative entry
group.source = parse_followup_note_field(authoritative.note, "source") or "unknown"
group.user_initiated = source in USER_INITIATED_FOLLOWUP_SOURCES
```

Each group dict (all values JSON-native): `{followup_label, source, user_initiated, armed_ts, authoritative (full event row), label_parse, n_entries}`.

**`unrun_followup_labels(events: list[dict]) -> list[dict]`** — `run_labels = {parse_followup_note_field(e.note, "followup_label") for e in events if e.kind == FOLLOWUP_RUN_KIND} - {None}`; unrun = groups whose `followup_label ∉ run_labels`; ordered by `(not user_initiated, armed_ts, authoritative.version)` — user-initiated first, then oldest armed ts; fully deterministic. A run marker with an unparseable label closes NOTHING (conservative in the anti-stranding direction; the counterweight is the §3.3(e) stale-label disposition rule).

**`executing_followup_label(events: list[dict]) -> dict | None`** — resolves WHICH unrun label the current/most-recent round is executing (shared by the Step 9b step-3 mid-round re-read and the watcher's `_post_followup_run_marker`): (1) the newest `epm:progress` note beginning `stage-dispatch stage=followup-` that is strictly newer than the newest `FOLLOWUP_RUN_KIND` ts and carries a `label=<slug>` token (via the existing `_breadcrumb_fields`) → return that label's group if unrun; (2) fallback: head of `unrun_followup_labels` (Step 0 always dispatches the head, so head == executing round whenever no labeled breadcrumb exists); (3) `None` when no unrun labels. Rule (1) exists because a user-chat label posted MID-ROUND would jump the queue head; the breadcrumb pins the actual round.

No new `task.py` subcommand (avoids any CLI-contract question); SKILL.md consumers use the `uv run python -c` recipe in §3.3(c). No `.env` needed (`task_workflow` reads the filesystem only), so the heredoc-dotenv lint rule is not implicated.

## 7. Risks + failure modes

1. **Ghost labels on legacy tasks (highest risk).** #658 (parked `awaiting_promotion`) carries ≥4 labels with no `epm:same-issue-followup-run` despite rounds demonstrably running (recorded via `epm:status-changed` round notes / `epm:free-analysis-followup-run` / 9a-quater `extends=`). The new predicate surfaces them; a future `/issue 658` would head-dispatch `persona-vectors-style-rb`. Mitigations: (i) the exposure is NOT new — the OLD predicate already fires on #658 (v10's label is also unrun); (ii) the §3.3(a) stale-label disposition rule retro-closes with evidence instead of re-running; (iii) run markers are the contract-mandated satisfier (workflow.yaml) — we deliberately do NOT fold `epm:free-analysis-followup-run` into the satisfier set (its `followup_ref` values don't string-match labels, e.g. `persona-vectors-style-rb-9a-ter-fit`; a fuzzy match risks silently closing a genuinely-queued label — worse than one guarded retro-close prompt).
2. **Label-parse drift.** A future note format the parser misses → label inherits the previous label or becomes a pseudo-label; either way it is never silently dropped, `label_parse` flags it, and the disposition rule + pseudo-label close bound the damage. Tests pin all four observed forms.
3. **Wrong-label close by the watcher.** If a round were manually dispatched out of queue order with no `label=` breadcrumb, `_post_followup_run_marker` would close the head instead. Mitigated by the §3.2 breadcrumb contract (labeled breadcrumbs win) and by Step 0 being the only dispatch path (it always takes the head).
