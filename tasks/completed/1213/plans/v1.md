### 4.2 Trigger token set (regexes, verbatim)

```python
_C33_LADDER_COMPOUND_RE = re.compile(
    r"(?i)dose[- ]ladder|checkpoint[- ]ladder|ladder of checkpoints|band[- ]stop grid"
    r"|dose[- ]matching checkpoint grid|checkpoint rungs?|rung checkpoints?"
    r"|per[- ]rung checkpoints?"
)
_C33_SAVE_EVERY_RE = re.compile(
    r"(?i)(?:checkpoints?|sav\w+)\s+every\s+~?\d+\s*(?:optimizer[- ])?(?:steps?|epochs?)"
)
_C33_RUNG_RE = re.compile(r"(?i)\brungs?\b")
_C33_CKPT_RE = re.compile(r"(?i)\bcheckpoints?\b|\bckpts?\b")
_C33_BACKEND_RUNG_RE = re.compile(
    r"(?i)spot|flex[- ]start|on[- ]demand|runpod|terminal rung|\blanes?\b|fallback"
    r"|a2-|a3-|gcp ladder|capacity"
)
```

Trigger logic, per non-fenced line (`_fence_mask`), first match wins (the matched line is quoted in the WARN detail):
1. `_C33_LADDER_COMPOUND_RE` matches, OR
2. `_C33_SAVE_EVERY_RE` matches (mechanizes the rule's "any long run saving every k steps for a later pick" clause), OR
3. co-location: `_C33_RUNG_RE` AND `_C33_CKPT_RE` both match the line AND `_C33_BACKEND_RUNG_RE` does NOT (the GCP fallback-ladder exclusion — the load-bearing anti-fragility widening; without it the raw-vocabulary FP surface is ~85 issues, §3).

No trigger → `_skip(cid, name, "no checkpoint-ladder vocabulary detected")`.

### 4.5 Satisfier token set + section scoping

```python
_C33_RETENTION_RE = re.compile(
    r"(?i)\bretention\b|\bretain\w*\b|keep[- ]all|keep (?:all|every|only)"
    r"|delet\w+[^.\n|]{0,80}(?:rungs?|ruled[- ]out|non[- ]selected|checkpoints?|ckpts?)"
    r"|(?:rungs?|checkpoints?|ckpts?)[^.\n|]{0,80}delet\w+"
    r"|upload[- ]as[- ]you[- ]go|delete[sd]? locally|re[- ]download"
    r"|band[- ]stop callback|MarkerBandStopCallback"
    r"|coarse\+refine|two[- ]pass grid|\bprune[sd]?\b|retained (?:set|rungs?)"
)
_C33_SIZING_KEYWORDS = ("resources", "parallelism", "compute", "disk")
```

Notes: the `[^.\n|]{0,80}` delete-co-location windows stop at sentence/cell boundaries (the `|` exclusion keeps a table row's delete verb from satisfying via an adjacent cell); `keep-all` deliberately satisfies — a STATED keep-all is the rule's justified-exception surface, whose adequacy is critic-owned. Generic disk tokens (`--boot-disk-gb`, GB figures) are deliberately NOT satisfiers — #1112 v1–v3 declared `--boot-disk-gb 750` and still ENOSPC'd; a disk flag is not a retention policy.

**Section scoping** — new helper, placed just above the check function:

```python
def _c33_sizing_scope(plan: str) -> str:
    """Union of the non-fenced text of every section whose heading carries a
    sizing keyword (resources/parallelism/compute/disk — the #1133 rule requires
    the policy in §9, but corpus headings drift: '## 9. Resources',
    '## 9. Resources & Parallelism', '### Compute projection'); the whole plan's
    non-fenced text when no such heading exists (structural absence must not
    manufacture WARNs — a WARN-only check fails toward silence)."""
```

Implementation: `_headings(plan)` → collect `(h.line, h.end)` for every heading whose `h.text.casefold()` contains any keyword; union the line ranges; join the non-fenced lines inside the union. Empty match set → fall back to all non-fenced lines (via the existing `strip_fences` semantics). Satisfier: `_C33_RETENTION_RE.search(scope)` → `_pass(cid, name, "retention vocabulary present in the compute-sizing scope")`.

Scoping rationale (measured): a doc-wide satisfier let #1112 v1–v3 escape on *incidental* vocabulary (a "retain" on an unrelated §1 line, "between rungs" in a §8 risk row); section-scoping is what makes the satisfier mean "the *sizing* prose engages retention". The union-of-matching-sections form (not first-match `section_text_by_keywords`) is deliberately permissive — multiple sizing-titled sections all count.
