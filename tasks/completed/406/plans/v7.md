## 0. Plain-English summary

**What I'm asking.** If I train the model on input-shape T_i (a persona prompt, a question phrasing, a format, a rewrite) to emit a marker, will it ALSO emit the marker on a different input-shape T_j (one I never trained on)? And — the load-bearing question — can I predict T→T' transfer **before training** from a one-number measure of how differently the base model continues T_i(question) vs T_j(question), measured on a held-out probe set?

**What I'll run.** I'll train the same Qwen-2.5-7B-Instruct base model on 20 different versions of the same training task (4 classes × 5 transformations each — system prompts, query phrasings, format scaffolding, semantic rephrasings). Each version gets its own LoRA. Then I'll cross-evaluate: for every (trained-on T_i, evaluated-on T_j) pair across the 20 transformations, I'll measure how often the marker comes out as the first token on T_j(question) across 50 held-out questions. That's the outcome G[i,j] — a 20×20 matrix of transfer rates, 380 ordered pairs. Then I'll see whether G[i,j] correlates with a predictor I computed on the untrained base model: forward KL divergence between the base model's next-token distributions on T_i(probe-question) vs T_j(probe-question), teacher-forced over 10 reference tokens, averaged across 50 probes. That's the primary predictor D[i,j]. Alongside, for triangulation, I'll compute six cosine-distance matrices on residual-stream activations at layers 0 / 5 / 11 / 15 / 21 / 27 — same 20 contexts, same 50 probes, mean-pooled at the last prompt-token position.

**What I expect.** Honest answer: I don't know. The closest in-repo precedent (#207's persona-distance predicts bystander leakage at |ρ| 0.48-0.79) is positive but on a different outcome metric. The closest cousin (#380's output-distance fails to predict per-persona source rate, length-partial null) is negative on a different outcome metric. My Bayesian prior is slightly above 50% that forward KL predicts transfer at length-partial |ρ| > 0.4, and meaningfully higher (~70%) that **at least one** of the 7 predictors (KL or one of the 6 cosine layers) does. If the middle layers (L11, L15, L21 — the "persona vector" sweet spot) work but L0 / L27 don't, that constrains the geometry story to mid-network representations and is a quotable mechanism finding. If only L27 (near-output) works, the cosine result is essentially the KL result in disguise. If L0 (embedding) works, the predictor is dominated by lexical overlap.

**What would change my mind.** Three results would surprise me:
1. **All 7 predictors land in the negative band** (forward-KL primary < 0.15 length-partial, all cosine layers similarly null). That's a strong constraint on the persona-vector story — base-model geometry simply doesn't predict where SFT generalizes, and the geometry must be measured AFTER training.
2. **Class-pair heterogeneity dominates** — predictor works within-class (A→A, B→B, etc.) but breaks cross-class (A→B, etc.). That's also informative — it says geometry predicts transfer along established axes (persona-to-persona, format-to-format) but not when the axis crosses.
3. **The 6 cosine layers split** — some work, some don't — and the working layers cluster around L0 (lexical surface) or L27 (output-space proxy) rather than the mid-network "persona vector" layers. That would suggest the predictor isn't really capturing learned representations.

**How long it takes.** ~5h wall on a 2×H100 pod (~$22-25 at RunPod ephemeral pricing). Pre-flight gates catch broken training rigs in the first 30 min before burning the rest. Roughly 10-11 GPU-hours total. The bulk of the work is 20 LoRA training runs (sequential per-GPU, ~3 h on 2 GPUs); the cross-eval is ~40 min; the divergence computation is ~25 min; the analysis is CPU-only and finishes in ~5 min on the local VM. Pre-registered thresholds: primary forward-KL ρ ≥ 0.4 (positive) or < 0.15 with bootstrap CI ⊂ [-0.2, 0.2] AND no per-class-pair cell exceeding |ρ| = 0.5 (negative); cosine layers reported descriptively.

**Win condition.** A single-page summary table the user can show Dan: 7 rows (KL, L0, L5, L11, L15, L21, L27), each row showing length-partial Spearman ρ + cluster-bootstrap CI + per-class-pair-cell maximum ρ + verdict. The primary KL row binds the verdict; the cosine rows triangulate.

## 1. Goal + hypothesis

**Headline question (Dan, 2026-05-26 #5).** Suppose you SFT a model to emit Y conditioned on input `T_i(X)`. Does the base model's pairwise output-distribution divergence on a held-out probe set `D[i,j] = KL(P_base(·|T_i(q')) ‖ P_base(·|T_j(q')))` — measurable *before training* — predict whether the trained model also emits Y on `T_j(X)`?

**Operationalization.** N=20 transformations across 4 classes (5 each: system-prompt, structural query-phrasing, format scaffolding, semantic rephrasing). For each `T_i`, train one LoRA on `(T_i(Q_train), " ※")` rows (Q_train = 30 hand-curated neutral questions). For each ordered pair `(i,j) | i≠j`, measure `G[i,j] = P[ trained model emits ` ※ ` as first response token on T_j(Q_test) ]` across **Q_test = 50 questions** (**v7 Change 1: bumped from 20**; existing 20 from `eval_results/issue_207/js_gentle/base_model_generations.json` + 30 new hand-curated questions matching the existing 20's domain mix and length profile, disjoint from Q_train). Regress G on D across 380 ordered pairs with the length-partial Spearman methodology inherited from #340 / #380.

**Hypothesis (pre-registered, locked).**

Primary predictor: forward KL `D[i,j] = (1/50) Σ_{q'} KL(P_base(·|T_i(q')) ‖ P_base(·|T_j(q')))`, teacher-forced K=10 tokens.

- *Positive*: |length-partial Spearman ρ(G, D)| ≥ 0.4 with p < 0.01 AND survives class-cluster mixed model.
- *Negative*: |length-partial ρ| < 0.15 with bootstrap 95% CI ⊂ [-0.2, +0.2] AND no per-class-pair cell exceeding |ρ| = 0.5. **(v5: loosened from 0.4 → 0.5 per user pick at Step 2c, option (ii). Brings true-H0 negative-band firing rate from ~40% to ~80% per Statistics-Claude 500-trial simulation.)**
- *Ambiguous*: anything else → pre-registered multi-seed follow-up.

**Secondary predictors (v7 Change 3 — descriptive, NOT joint pre-registered).** JS divergence (computed alongside KL at zero marginal cost) AND six cosine distances on residual-stream activations at layers L ∈ {0, 5, 11, 15, 21, 27} (last prompt-token position, mean-pooled across 50 probes per context). Each secondary predictor is regressed against G[i,j] with the SAME methodology as the primary (length-partial Spearman with both pingouin and inline implementations, cluster-bootstrap CI by class-pair, class-cluster mixed model with random intercept per (class_i, class_j) cell). **The binding pre-registered verdict comes from the primary KL predictor alone.** Secondary predictors are reported descriptively for triangulation: the analyzer compares which predictor lands where in a 7-row summary table; the clean-result body's headline framing becomes "does base-model geometry — output divergence OR hidden-state cosine at any of 6 layers — predict transfer?". **No multiplicity correction is applied** (the primary is one pre-registered test; the 6 cosine layers are descriptive and the body says so). This is the standard "one binding pre-registered test + reported alongside descriptive replications at related-but-different operationalizations" pattern; not a 7-test fishing expedition.

### Knob 2 — Exact prompt strings for B / C / D

**Class B — structural query-phrasing wraps (NO explicit system prompt; default Qwen system tag fires).** When no system message is provided, the Qwen-2.5-7B-Instruct chat template auto-inserts the literal system text `"You are Qwen, created by Alibaba Cloud. You are a helpful assistant."` (verified at v2 lock time — two sentences). This is part of the transformation's pre-training-time identity and we keep it. The `{q}` placeholder is the question text.

**Structural confound (acknowledged, remediation (a) per fact-checker; see §11 rationale + §12 row 18):** the second sentence of Qwen's default system tag overlaps verbatim with **A1's locked persona prompt** (`"You are a helpful assistant."`). Consequence: when Class B / C1 / D conditions run without explicit system prompts, they silently inherit the "helpful assistant" framing, which means `D[A1, B*]`, `D[A1, C1]`, `D[A1, D*]` divergences will be **structurally compressed** relative to `D[A2..A5, B*]` etc. This is a real property of the model's input space, not a methodological error — the divergence IS measuring what the base model sees, and what the base model sees includes the auto-inserted default tag. Pretending the overlap isn't there would be dishonest. Operational consequences:

1. **Predict compression of A1-anchored cross-class divergences.** I expect `D[A1, B*] < D[A2, B*]` even when B1..B5 are structurally identical to A1 in user-message content. This is testable and reportable.
2. **Per-cell ρ analysis surfaces it empirically.** The 4×4 class-pair grid (Knob 5d) will show whether the (A→B/C/D) cells are tighter or have shifted distributions vs (A2..A5→B/C/D); if so, the clean-result reports it as a finding rather than a bug.
3. **Runtime assert (cheap insurance).** Phase 1 entry asserts `tokenizer.apply_chat_template([{"role":"user","content":"x"}], tokenize=False, add_generation_prompt=True)` contains the substring `"You are a helpful assistant."` — if Qwen ships a template update that changes the default text, the assert fires and we re-lock the plan rather than silently shifting the geometry.

Rejected alternatives:
- **(b) Force `system="You are a helpful assistant."` on B/C1/D.** Collapses a class boundary (Class B would no longer be "no system prompt" — it would be "helpful-assistant system + phrasing variant"), defeating the cross-class design intent.
- **(c) Swap A1 to a low-divergence persona that doesn't overlap with the default tag.** The locked spec names `helpful_assistant` as A1 by explicit user choice; changing it without user consent diverges from the locked spec. Picking (a) preserves the spec lock + surfaces the confound honestly.

### Knob 4 — Length-matching procedure vs length-partial-only

**Decision: do BOTH.** #380 found the two implementations of length-partial Spearman can disagree on the headline (sign flip on the point estimate, both still p>0.78). For #406:

1. **Primary (matches #380):** `pingouin.partial_corr(data=df, x='D', y='G', covar=['log_prompt_tokens'], method='spearman')`. This residualizes raw, then ranks.
2. **Secondary (matches #340's published methodology):** inline rank-residualize-then-correlate:
   ```python
   D_rank = scipy.stats.rankdata(D)
   G_rank = scipy.stats.rankdata(G)
   L_rank = scipy.stats.rankdata(log_prompt_tokens)
   D_resid = D_rank - linregress(L_rank, D_rank).slope * L_rank - linregress(L_rank, D_rank).intercept
   G_resid = G_rank - linregress(L_rank, G_rank).slope * L_rank - linregress(L_rank, G_rank).intercept
   rho_p_value = scipy.stats.pearsonr(D_resid, G_resid)
   ```
3. **Tertiary (sanity, only if 1 and 2 disagree by >0.1 on ρ):** length-stratified Spearman within terciles of `log_prompt_tokens` across the 380 pairs. Report per-tercile ρ.

`log_prompt_tokens` is `np.log(n_tokens)` where `n_tokens = len(tokenizer.encode(T_j(q'), add_special_tokens=False))` averaged across the 20 probe questions for each `T_j` (the eval-side transformation; the predictor is computed against the same `T_i, T_j` pair so the length covariate is intrinsic to the pair).

**Why log not raw tokens.** #380 used `log_tokens` because prompt-token counts are right-skewed; #406's transformations span ~10 tokens (bare) to ~30 tokens (Socratic + system prompt), same skew profile. Keep log.

### Knob 5 — Statistical-test details

**(a) Spearman variance form.** Use `pingouin.partial_corr` returned `CI95%` (asymptotic Fisher-z, valid for N=380). Separately report the percentile bootstrap CI from (b).

**(b) Bootstrap CI form: cluster-bootstrap by (class_i, class_j) cell.** The 380 pairs fall into 16 (class_i × class_j) cells (4 within-class diagonals × 5×4 pairs + 12 between-class off-diagonals × 5×5 pairs). Naive iid bootstrap would over-state precision because pairs within a class-pair cell share covariates. Implementation:
```python
n_boot = 2000
rng = np.random.default_rng(42)
cell_ids = list(set(zip(class_i, class_j)))  # 16 cells
boot_rhos = []
for _ in range(n_boot):
    sampled_cells = rng.choice(len(cell_ids), size=len(cell_ids), replace=True)
    rows = []
    for cell_idx in sampled_cells:
        ci, cj = cell_ids[cell_idx]
        rows.extend(np.where((class_i == ci) & (class_j == cj))[0])
    # length-partial Spearman on resampled rows
    boot_rhos.append(length_partial_spearman_pingouin(D[rows], G[rows], log_tok[rows]))
ci_low, ci_high = np.percentile(boot_rhos, [2.5, 97.5])
```
Cluster-bootstrap at the cell level is the right unit because the locked spec already calls for a class-cluster mixed model with random intercept per (class_i, class_j) — the cells are the natural blocking variable. Using 2000 resamples (not 1000 like #380) because 16 clusters is small.

**(c) Class-cluster mixed model.** Use `statsmodels.formula.api.mixedlm`:
```python
import statsmodels.formula.api as smf
df['class_pair'] = df['class_i'] + '_' + df['class_j']  # 16 levels
md = smf.mixedlm('G ~ D + log_prompt_tokens', data=df, groups='class_pair').fit(reml=False)
# fixed-effect slope on D, with cluster-corrected SE
print(md.summary())
slope_D = md.params['D']
ci = md.conf_int().loc['D']
```
The "survives class-cluster mixed model" criterion for the positive threshold is: the fixed-effect slope on D has p < 0.01 AND the same sign as the marginal Spearman ρ. This separates the within-cluster effect from the between-cluster fixed-effect confound.

**(d) Threshold-detection (divergence cutoff above which G ≈ 0).** Two cheap, interpretable methods, both reported:

1. **Sliding-quantile method (preferred).** Sort the 380 pairs by D; in each sliding window of 50 consecutive pairs (overlap step 10), compute mean G. The cutoff D* is the smallest D where the windowed mean G first falls below 0.1 AND stays below for 3 consecutive windows. Report D* with bootstrap CI (resample at the cell level).
2. **Piecewise-linear fit (sanity).** Fit `G = a + b*D` for D < D_split, `G = c` for D ≥ D_split, sweep D_split across the 10th–90th percentile of D, pick D_split minimizing MSE. Report fitted D_split.

CART / changepoint detection is overkill for N=380 with a smooth predicted relationship; the sliding-quantile method captures the same "does G crash above a threshold?" question with one knob and one plot.

## 3.5. Concerns surfaced by Phase 2 critic ensemble (analyzer notes — non-blocking)

Ten non-blocking concerns from the 6-critic ensemble (Methodology / Statistics / Alternatives × Claude + Codex). None block launch; all are read by the analyzer at interpretation time. v3 lists them here so the analyzer agent has them in-context when writing the clean-result body.

1. **Position-resolved D_k sensitivity (Methodology Claude).** Phase 1 averages KL across K=10 token positions. If the headline lands ambiguous, the analyzer should run a per-position-k breakdown: `D_k[i,j] for k in 0..9` × the full regression. Position-0-only (first generated token) and K=10-mean may differ substantively; the predictive signal may live in early-position divergence and get diluted by late-position drift.
2. **A1-cross-class same-line-or-off-line check (Methodology Claude + Alternatives Claude + Statistics Claude).** In the per-cell ρ grid, the (A1, B*), (A1, C1), (A1, D*) cells should be inspected separately for whether they sit on the global regression line or visibly below it. Compression alone (assumption 22) doesn't pin the slope; the slope IS what the experiment is testing. If the A1-cross-class cells are off-line, the headline interpretation needs a qualifier ("predictor works EXCEPT at the structural-tag-overlap end").
3. **Reference completion is C1-greedy-decoded (Alternatives Claude).** The reference `ref_tokens` used for teacher-forcing in Phase 1 comes from greedy-decoding the canonical bare-question C1 prompt. For Class C2/C3/C5 cells (which DON'T use chat-template format), this reference may be OOD continuation under the C2-shape prompts → inflates D[C2, ·] artifactually. Recommend: analyzer spot-checks D[C2, ·] using a C2-greedy-decoded reference (one extra Phase-1-style run, ~5 min wall) and compares the ranking against the C1-anchored values. If rankings preserve, the C1-anchor is fine; if they shift, the headline carries this caveat.
4. **Leave-class-C-out and leave-A1-out post-hoc analyses (Alternatives Claude + Alternatives Codex).** Two cheap one-line post-hocs: re-run the length-partial Spearman with all Class-C rows dropped (tests whether the new raw-text training path contaminates the result), and again with all A1-anchored rows dropped (tests how much the structural-tag overlap drives the headline). Both should sit in `analysis.json` automatically; analyzer narrates if either substantially moves the headline.
5. **Permutation null (Alternatives Codex).** Analyzer-side calibration check (not a new gate): permute the G[i,j] values 1000 times against fixed D[i,j], compute the length-partial Spearman on each shuffle, report the null distribution as a sanity check on the observed value. NOT pre-registered, NOT a threshold — purely calibration sanity. Adds ~30s of CPU; sits in `analysis.json` as `"permutation_null_95pct": [low, high]`.
6. **Sliding-threshold curve over single cutoff (Alternatives Codex).** Knob 5d currently picks ONE divergence cutoff D* where G drops below 0.1. Better: report the full **sliding-threshold curve** (G as a function of cutoff D) with a bootstrap band, not just one number. Single cutoffs collapse a smooth phenomenon into a brittle point estimate. Implementation: replace `sliding_quantile_threshold(... return single D*)` with `sliding_quantile_curve(... return D_grid, mean_G_curve, bootstrap_band)` and plot the curve in the threshold figure (Figure 3 in §4 Phase 4).
7. **G distribution histogram (Statistics Claude + Methodology Claude).** Before any regression, the analyzer should report the histogram of G[i,j] values across the 380 pairs. If G is bimodal (mostly 0 or mostly 1), Spearman handles it (ranks tied values), but the interpretation changes substantively (the predictor isn't predicting a smooth-rate variable — it's predicting binary transfer-or-not). The analyzer narrates the histogram shape up-front in the clean-result body, before the regression results.
8. **Pingouin-vs-inline length-partial: REPORT BOTH always (Statistics Codex).** v2 §3 Knob 5 said "report both; tertiary length-tercile stratification only if they disagree by >0.1 on ρ". Codex flagged this as too permissive — both are real diagnostics. v3 fold: ALWAYS report both pingouin and inline values in the headline table (not just when they disagree); ALWAYS run the length-tercile stratification (cheap; <1 min). Do NOT fall back to "inline only if pingouin install fails" — the disagreement IS a finding, not a fallback.
9. **Cluster-bootstrap CI is wide and should lead the headline (Statistics Claude).** At 16 clusters, the bootstrap CI is expected to be roughly ±0.24 wide (from the 500-trial simulation). The headline summary should LEAD with the CI ("length-partial Spearman ρ = X with 95% cluster-bootstrap CI [low, high]"), not the point estimate alone. Point estimate alone overstates precision.
10. **Per-cell ρ is not exchangeable across cells (Statistics Claude).** Within-class cells (A→A, B→B, C→C, D→D) have N=20 ordered pairs each. Between-class cells (A→B, A→C, etc.) have N=25. Per-cell critical |ρ| at p<0.05 differs: ~0.44 for N=20 vs ~0.40 for N=25. The "no per-cell |ρ| ≥ 0.5" negative-band criterion (**v5: loosened from 0.4 → 0.5 per user pick at Step 2c, option (ii)**) treats all 16 cells as exchangeable — they are not, strictly. v5 keeps the user-loosened threshold but the analyzer should report the per-cell ρ ALONGSIDE its per-cell critical value, so readers see when a cell crosses |ρ| = 0.5 with a smaller-N (less constrained) cell vs a larger-N (more constrained) one. Note this in the clean-result Methodology corrections section, not as a threshold change.

### Phase 1 — Compute D[i,j] divergence matrix + 6 cosine matrices C^L (v7-expanded)

**Script:** `scripts/i406_phase1_compute_divergence.py`

For each `T_i` in {20 transformations}, build the user-side prompt for each q' in Q_probe (**v7: 50 questions**, was 20), then for each PAIR (T_i, T_j), compute:

```
D[i, j] = (1/50) * Σ_q' KL( P_base(·|T_i(q'))[k=0:10] ‖ P_base(·|T_j(q'))[k=0:10] )
```

where the K=10 response tokens are a fixed reference completion = base-model greedy decode of `T_i(q')`. **Two ways to do this:**

**(a) Naive: per (T_i, T_j, q') re-decode and teacher-force.** 20 × 20 × 50 = 20,000 forward passes → too slow even on 2×H100.

**(b) Smart: shared reference completion per q'.** For each q' (one reference completion total per question, not per (T_i, T_j) pair):
1. Greedy-decode q' under `apply_chat_template([user(q')])` → reference response of ≥10 tokens.
2. Take first 10 tokens of that reference.
3. For each `T_i`, teacher-force `T_i(q') + reference[:10]` → returns `log_probs_i ∈ ℝ^{10 × V}` AND (v7 Change 3) ALSO capture residual-stream activations at last-prompt-token position for layers L ∈ {0, 5, 11, 15, 21, 27}.
4. Compute pairwise KL: `D[i,j] = mean_t KL(log_probs_i[t] || log_probs_j[t])`.
5. Average across 50 q' to get `D[i,j]` final value.
6. **v7: also compute per-layer mean-pooled activation per context** `mean_act_i^L = (1/50) Σ_{q'} act(T_i, q', L)` → 20 vectors of dim 3584 per layer → 20×20 cosine distance matrix `C^L[i,j] = 1 - cos(mean_act_i^L, mean_act_j^L)` for each of 6 layers.

This reuses the *exact* machinery in `src/explore_persona_space/analysis/divergence.py`:
- `build_teacher_force_inputs(tokenizer, [T_i(q'), T_j(q'), ..., T_20(q')], q'='', response_text=reference_first_10_decoded)` — but the per-T_i input is a STRING that already includes the prompt format, so we override its chat-template path.
- Or — simpler — bypass `build_teacher_force_inputs` and write a `i406`-specific version that handles the per-class prompt construction directly. This is the right call: the existing function assumes `{system, user, assistant}` chat-template shape, which is fine for A but breaks for B (no system), D (no system, rewritten user), and C2-C5 (no chat template at all).

**New helper (in `scripts/i406_phase1_compute_divergence.py`):**

```python
def build_prompt_for_condition(condition_id: str, condition_class: str, condition_params: dict, q: str) -> str:
    """Return the literal prompt string the base model sees, including any chat-template tags
    or raw scaffolding, but BEFORE the assistant response would be appended."""
    if condition_class == "A":
        return tokenizer.apply_chat_template(
            [{"role":"system","content":condition_params["system_prompt"]},
             {"role":"user","content":q}],
            tokenize=False, add_generation_prompt=True)
    elif condition_class == "B":
        return tokenizer.apply_chat_template(
            [{"role":"user","content":condition_params["wrap_template"].format(q=q)}],
            tokenize=False, add_generation_prompt=True)
    elif condition_class == "C":
        if condition_id == "C1":
            return tokenizer.apply_chat_template(
                [{"role":"user","content":q}], tokenize=False, add_generation_prompt=True)
        else:
            return condition_params["raw_template"].format(q=q)
    elif condition_class == "D":
        rewrite = class_d_rewrites[q][condition_params["register"]]
        return tokenizer.apply_chat_template(
            [{"role":"user","content":rewrite}],
            tokenize=False, add_generation_prompt=True)
    raise ValueError(f"unknown class {condition_class}")
```

The reference completion is decoded ONCE from a CANONICAL prompt (the bare-question C1 prompt — the most "neutral" of the 20) per q'. The first 10 reference token IDs (`ref_tokens[:10]`, a `list[int]`) become the teacher-forced response — used as token IDs throughout, never round-tripped through `tokenizer.decode → encode`. **v3 (MF-1 fix per Phase 2 critic + reconciler): token-id concatenation, not string concatenation.**

The v2 string-concat path (`tokenizer.decode(ref_tokens[:10])` → string-append to `prompt_text` → re-tokenize the joined string) is **vulnerable to BPE re-segmentation at the prompt↔ref-tokens boundary**. Especially exposed for Class C2/C3/C5 raw-string prompts ending in `Answer:` (the `:` ↔ space ↔ first-ref-token boundary is exactly where Qwen's BPE merges shift by ±1 token). When it shifts, D[i,j] is no longer KL over the same 10 token positions across conditions — it's KL over different actual token slices per condition, and the predictor variable is malformed for affected rows. The token-id concat path bypasses this entirely.

```python
# Pre-compute ref_tokens ONCE per q' from the canonical bare-question C1 prompt
canonical_prompt_text = build_prompt_for_condition("C1", "C", {}, q)
canonical_prompt_ids = tokenizer.encode(canonical_prompt_text, add_special_tokens=False)
# vLLM greedy on the canonical prompt → take first 10 generated token IDs
ref_tokens: list[int] = greedy_decode_first_n_tokens(canonical_prompt_ids, n=10)

# For each T_i, build input_ids by TOKEN-ID concat (NOT decode → encode string round-trip)
for T_i in CONDITIONS:
    prompt_text = build_prompt_for_condition(T_i, ...)
    prompt_ids = tokenizer.encode(prompt_text, add_special_tokens=False)
    full_ids = prompt_ids + ref_tokens  # pure list-int concat; no string round-trip

    input_ids = torch.tensor([full_ids], device="cuda")
    with torch.no_grad():
        out = model(input_ids=input_ids)
    logits = out.logits  # (1, len(full_ids), V)
    # log-softmax over the 10 positions that PREDICT ref_tokens[0..9]:
    # the logit at position (len(prompt_ids) - 1) predicts ref_tokens[0]
    # the logit at position (len(prompt_ids) + 8) predicts ref_tokens[9]
    response_logits = logits[0, len(prompt_ids) - 1 : len(prompt_ids) - 1 + 10, :]
    log_probs_i = F.log_softmax(response_logits.float(), dim=-1)  # (10, V)
    # Tensor-shape assert (boundary check per CLAUDE.md)
    assert log_probs_i.shape == (10, tokenizer.vocab_size), log_probs_i.shape

    # ── Alignment assert (MF-1 defense in depth) ──
    # For the first q' of each condition, verify the input-id slice we're scoring
    # IS exactly ref_tokens[:10]. This catches any future refactor that breaks
    # the token-id-concat contract.
    if q_idx == 0:
        scored_slice = full_ids[len(prompt_ids) : len(prompt_ids) + 10]
        assert scored_slice == ref_tokens, (
            f"T_i={T_i} alignment broken: full_ids[{len(prompt_ids)}:{len(prompt_ids) + 10}] "
            f"= {scored_slice} != ref_tokens = {ref_tokens}. "
            "BPE re-segmentation suspected — investigate token-id-concat path."
        )
```

Save the (20, 20, 10, V) tensor of per-condition per-q' log-probs to disk per-q' (NOT in memory; chunk to disk). Then compute the (20, 20) D[i,j] matrix using `compute_kl_divergence` from `divergence.py`. JS is computed alongside the same loop (mean of 2 KLs vs midpoint M, exactly as `compute_js_divergence` does today).

**v7 Change 3: activation capture for 6 cosine layers — extend the per-condition forward loop.** Add a forward-hook on each of the 6 target layers (`model.model.layers[L]` for L ∈ {0, 5, 11, 15, 21, 27}) that grabs the residual-stream output at the LAST PROMPT TOKEN position (`hidden_states[0, len(prompt_ids) - 1, :]`, a 3584-dim vector for Qwen-7B). Append to disk per-q' alongside the log-probs:

```python
# Register forward hooks on the 6 target layers (Qwen-2.5-7B: model.model.layers, 28 blocks indexed 0..27)
TARGET_LAYERS = [0, 5, 11, 15, 21, 27]
captured: dict[int, torch.Tensor] = {}

def make_hook(layer_idx: int):
    def hook(module, inputs, output):
        # output is a tuple; output[0] is hidden_states (1, seq_len, hidden_dim)
        hs = output[0] if isinstance(output, tuple) else output
        # Grab the LAST PROMPT TOKEN position (BEFORE the teacher-forced response begins)
        captured[layer_idx] = hs[0, len(prompt_ids) - 1, :].detach().cpu().float()
    return hook

hooks = [model.model.layers[L].register_forward_hook(make_hook(L)) for L in TARGET_LAYERS]
try:
    with torch.no_grad():
        out = model(input_ids=input_ids, output_hidden_states=False)
    # captured[L] is populated by the hooks
    # ... existing log-softmax extraction (lines above) ...
    for L in TARGET_LAYERS:
        assert captured[L].shape == (3584,), captured[L].shape  # Qwen-7B hidden dim
        # Append to per-condition per-q' per-layer activation file:
        save_activation(T_i, q_idx, L, captured[L])
finally:
    for h in hooks:
        h.remove()
```

**Pilot gate sequence (v7):**
1. **A1 pilot (chat-template path validation, GPU 0 only):** train A1 first, then immediately smoke-eval `G[A1, A1]` on the 50-question Q_test set under the A1 prompt itself; require ≥0.7. If fails, halve lr to 5e-6 and retrain A1 once; if still <0.7, escalate to Thomas (the chat-template + first-token-marker training rig isn't working; entire batch is at risk). Cost: ~25 min (train + smoke) × at most 2 retries.
2. **C2 pilot (raw-string path validation, GPU 0 only):** after A1 passes, train C2 (the first raw-string condition) and smoke-eval `G[C2, C2]`. The raw-string + `dataset_text_field` + disabled response-only-loss path is new code not in the lineage (v3 MF-2 fix); this gate ensures the full-sequence-loss recipe implants the marker before launching C3/C4/C5. Same retry policy as A1.
3. **Parallel batch launch (v7):** with both pilots cleared, the remaining 18 conditions split 9/9 across GPUs 0+1 in parallel processes, sequential per-GPU. Suggested split (alphabetical for predictability):
   - GPU 0 (sequential, 9 conditions, ~3h wall): A2, A3, A4, A5, B1, B2, B3, B4, B5
   - GPU 1 (sequential, 9 conditions, ~3h wall): C1, C3, C4, C5, D1, D2, D3, D4, D5
   - Total parallel batch wall: ~3h (max of two ~3h sequential chains).

Total Phase 2 wall (v7): pilots sequential ~25 min + ~25 min = ~50 min; parallel batch ~3h; **total ~3.5-4h wall** (was ~7h in v5). Pilot-gate worst case (both pilots fail once + retry): ~3h pilots + ~3h batch = ~6h.

### Phase 3 — Cross-eval (compute G[i,j])

**Script:** `scripts/i406_phase3_cross_eval.py`

```python
"""For each (i, j) in 20×20, greedy-decode T_j(q_test) under model_i for each q_test in Q_test.
Record whether the first response token == ' ※' (id 83399).

Single vLLM instance with enable_lora=True; iterate j outer, i inner so we batch all 20 j-prompts
for a given i with one LoRA swap.

Output: G[i][j] = mean over 50 q_test of (1 if first_response_token == 83399 else 0)
"""

from vllm import LLM, SamplingParams
from vllm.lora.request import LoRARequest
from huggingface_hub import snapshot_download
import argparse, json, os

MARKER_ID = 83399
HF_REPO = "superkaiba1/explore-persona-space"
LOCAL_ADAPTER_CACHE = "/workspace/adapters/i406"
CONDITIONS = [
    "A1","A2","A3","A4","A5",
    "B1","B2","B3","B4","B5",
    "C1","C2","C3","C4","C5",
    "D1","D2","D3","D4","D5",
]

def main(shard: tuple[int, int] | None = None):
    # v7: parallel 2-GPU sharding. shard=(0, 2) handles outer-i indices 0..9;
    # shard=(1, 2) handles 10..19. shard=None handles all 20 (single-GPU fallback).
    if shard is None:
        my_conds = CONDITIONS
        shard_tag = "all"
    else:
        s, n = shard
        my_conds = [c for k, c in enumerate(CONDITIONS) if k % n == s]
        shard_tag = f"{s}of{n}"

    # Download all 20 adapters first (idempotent; only the ones this shard needs would be
    # sufficient, but downloading all is cheap and lets shards re-balance on retry)
    for cond in my_conds:
        snapshot_download(
            repo_id=HF_REPO,
            revision="main",
            allow_patterns=[f"adapters/i406_{cond}/*"],
            local_dir=LOCAL_ADAPTER_CACHE,
        )

    # Per-shard vLLM, swap LoRAs per outer-i within shard
    llm = LLM(
        model="Qwen/Qwen2.5-7B-Instruct",
        enable_lora=True,
        max_lora_rank=32,
        max_loras=1,
        dtype="bfloat16",
        gpu_memory_utilization=0.85,
        seed=42,
        # Note: dispatcher sets CUDA_VISIBLE_DEVICES before launching this process;
        # vLLM picks the visible device automatically.
    )
    sampling = SamplingParams(
        n=1,
        temperature=0.0,
        top_p=1.0,
        max_tokens=4,  # 4 is enough for "is the first token ※?"
        seed=42,
    )

    G_partial = {}  # G[i][j] for i in my_conds
    q_test = load_q_test()  # 50 questions (v7)
    assert len(q_test) == 50, f"Expected 50 Q_test, got {len(q_test)}"
    for i_idx, T_i in enumerate(my_conds):
        lora_req = LoRARequest(
            lora_name=T_i,
            lora_int_id=CONDITIONS.index(T_i) + 1,  # stable int id across shards
            lora_path=f"{LOCAL_ADAPTER_CACHE}/adapters/i406_{T_i}",
        )
        G_partial[T_i] = {}
        for j, T_j in enumerate(CONDITIONS):
            # Build prompts for all 50 q_test under T_j
            prompts = [build_prompt_for_condition(T_j, ..., q) for q in q_test]
            # vLLM batched generate, returns first-token id directly
            outputs = llm.generate(prompts, sampling, lora_request=lora_req)
            n_emit = sum(1 for out in outputs if out.outputs[0].token_ids[0] == MARKER_ID)
            G_partial[T_i][T_j] = {"n_emit": n_emit, "n_total": 50, "rate": n_emit / 50}
            # Save per-i per-j atomically — checkpoint per phase
            save_per_cell(T_i, T_j, G_partial[T_i][T_j], outputs)

    # Per-shard output; merge step combines both shards into G_matrix.json
    json.dump(G_partial, open(f"eval_results/issue_406/cross_eval/G_partial_{shard_tag}.json", "w"), indent=2)

if __name__ == "__main__":

    if args.shard:
```

Each shard handles outer-i indices where `i_idx % 2 == shard_idx`: shard 0 handles A1, A3, A5, B2, B4, C1, C3, C5, D2, D4 (10 outer-i × 20 inner-j × 50 q_test = 10,000 generations); shard 1 handles A2, A4, B1, B3, B5, C2, C4, D1, D3, D5 (same count). Each shard runs its own vLLM server on its own GPU; outer-i (LoRA swap) happens within the shard; inner-j×q_test (50 prompts) gets batched together in one `llm.generate()` call per (i, j) pair. The 10 LoRA swaps per shard × ~5s each = ~50s LoRA overhead per shard.

**Diagonal sanity filter:** load `G_matrix.json` (merged from both shards), drop any `T_i` with `G[i][i] < 0.7`. Report the dropped set explicitly in the clean-result. If ≥3 of 20 are dropped, that's a kill criterion (rig instability).

**Compute estimate (v7):** 20 conditions × 20 eval-conditions × 50 questions = **20,000 batched vLLM generations** × 4 tokens each. Split across 2 GPUs at 10,000 per shard. On 1×H100 with batch=1000 (all 50 q_test for each (T_i, T_j) pair packed in one `llm.generate()` call), expect ~20 min per shard. LoRA-swap overhead ~5s × 10 swaps per shard = ~50s. Parallel wall: ~20-30 min total (the slowest of the two shards). **Total Phase 3: ~40 min**, comfortably inside the 1h budget I implied in §0.

**Note on `max_tokens=4` vs CLAUDE.md "max_new_tokens ≥ 2× longest trained completion ≥ 2048"** — that rule is for end-of-completion marker evals. Our DV is first-token, so `max_tokens=4` is sufficient (we just need `output.outputs[0].token_ids[0]`). The 2048 rule does not apply when the position of interest is the first decoded token.

```python
    if is_primary:

            df, x_col=predictor_col, window=50, step=10, n_boot=500, seed=42

        leave_class_c_out = compute_length_partial_dropping_class(
            df, x_col=predictor_col, drop_class="C"
        )
        leave_a1_out = compute_length_partial_dropping_condition(
            df, x_col=predictor_col, drop_condition="A1"
        )

    # Verdict assignment — PRIMARY ONLY (cosine predictors are descriptive; no verdict)
    verdict = None
    if is_primary:

        length_partial_p = float(lp_pg["p-val"].values[0])

                and np.sign(mm_slope) == np.sign(length_partial_rho)):

        elif (abs(length_partial_rho) < 0.15 and ci_low >= -0.2 and ci_high <= 0.2

        "length_partial_p_pingouin": float(lp_pg["p-val"].values[0]),
        "length_partial_rho_inline": float(lp_inline["r"]),
        "length_partial_p_inline": float(lp_inline["p"]),
        "length_tercile_rhos": length_tercile_rhos,
        "cluster_bootstrap_ci": [float(ci_low), float(ci_high)],
        "mixed_model_slope": float(md.params[predictor_col]),
        "mixed_model_slope_p": float(md.pvalues[predictor_col]),
```

### Why code, not a model call?

This design has zero "classifier / extractor / parser / summarizer / rule-based judge over unstructured data" steps. The DV is `output.outputs[0].token_ids[0] == 83399` — a deterministic integer comparison. The predictor is teacher-forced log-prob math. The Class D rewrite step DOES use a model (Claude Sonnet 4.5) — but the alternative there would be hand-writing 250 rewrites, which is at-best 4 hours of human time vs ~$1 of Claude API; the hand-verification rubric (Knob 3) is the human-in-loop quality bar. The reason for code over model call in the eval is determinism: the same `output_ids[0] == 83399` check returns the same answer on every machine; a Claude-judge "did the response start with the marker?" call has nontrivial flake rate at ~$0.001/call × 8000 calls = $8 and a 1-2% disagreement rate per #207's experience with marker-substring vs Claude-judge comparisons.

**N/A — no unstructured-data heuristics in this design.** The only model call is Class D rewriting (Phase 0); the only judge is a Python `==` on a token id.

## 6. Evaluation

**Primary metric (binding pre-registered verdict source):** length-partial Spearman ρ(G, D) across 380 ordered pairs, where D = forward KL on base-model output distributions. Both pingouin (residualize-then-rank) and inline (rank-then-residualize) implementations reported. Q_test = 50 (v7).

**v7 secondary metrics (descriptive triangulation — no multiplicity correction, no verdict):**
- JS divergence (free, same arrays as KL).
- 6× cosine on residual-stream activations at layers L ∈ {0, 5, 11, 15, 21, 27}, mean-pooled across 50 probes at last prompt-token position. Same length-partial Spearman + cluster-bootstrap + class-cluster mixed model as the primary.

**Methodology diagnostics (apply to PRIMARY only):**
- Class-cluster mixed-model slope on D (fixed effect), p-value, sign vs marginal ρ.
- Cluster-bootstrap 95% CI on length-partial ρ (2000 resamples, blocked by class_pair).
- Per-cell (4×4 = 16) length-partial ρ — flag any cell |ρ| > 0.5 (**v5: threshold loosened from 0.4 → 0.5 per user pick at Step 2c, option (ii)**).
- Threshold-detection: D* cutoff above which G drops below 0.1, with CI.
- Permutation null (1000-shuffle G vs D) for primary-only calibration sanity.
- Leave-class-C-out + leave-A1-out post-hocs for primary-only.

**Pre-registered thresholds (PRIMARY forward KL only — locked):**
- **Positive:** |length-partial ρ| ≥ 0.4 AND p < 0.01 AND mixed-model slope p < 0.01 with sign-agreement.
- **Negative:** |length-partial ρ| < 0.15 AND bootstrap 95% CI ⊂ [-0.2, +0.2] AND no per-cell |ρ| ≥ 0.5. **(v5: per-cell cap loosened from 0.4 → 0.5 per user pick at Step 2c, option (ii).)**
- **Ambiguous middle:** anything else → pre-registered multi-seed follow-up (3-5 seeds).

**Reporting shape for descriptive predictors:** the analyzer produces a 7-row summary table (KL primary + JS secondary + 6 cosine layers) with columns `predictor | length-partial ρ (pg, inline) | cluster-bootstrap CI | per-cell-max |ρ| | verdict`. Only the primary row has a `verdict`; cosine rows show `descriptive`. The clean-result body's headline framing is "does base-model geometry (output OR hidden-state) predict transfer?" with the table as the primary visual answer.

## 11. Decision rationale (non-obvious choices)

- **Marker ` ※` not `[ZLT]`:** `[ZLT]` is deprecated per CLAUDE.md (multi-token, joint log-prob ~−33 nats). ` ※` is single-token id 83399 (leading space), validated by #395, used by #399/#396. Eval is `output_ids[0] == 83399` — unambiguous.
- **Forward KL primary, JS secondary:** Dan's #5 phrased as "JS divergence", but forward KL is directional and matches the asymmetry of "training on T_i predicts emission on T_j" — KL(P_i ‖ P_j) is interpretable as "how much information does training-on-T_j data fail to capture about T_i?". JS is symmetric and free to compute alongside; primary stays KL per spec lock.
- **K=10 teacher-forced tokens:** matches #380's response-length truncation; long enough to capture meaningful divergence, short enough that the V=152K matmul stays in GPU memory.
- **N=20 single seed:** divergence predictor is deterministic on a fixed base model; one LoRA per T_i is the natural unit. Multi-seed adds power for ambiguous-middle cases but isn't necessary if the headline lands in positive or negative bands.
- **600 training rows per T_i:** matches the #271/#340/#368/#380 lineage exactly, so divergence and outcomes cross-compare against cached source rates for the persona conditions.
- **Class A picked to span empirical range:** verified against cached #380 JS-from-baseline values (low: 0.005, max: 0.07). Locked-spec defaults retained.
- **Length-partial both implementations:** #380's lesson — pingouin and inline rank-residualize can disagree; report both.
- **Cluster-bootstrap by class_pair:** 16 cells is the natural blocking unit given the class-cluster mixed model design.
- **Sequential per-condition Phase 2 on 1×H100:** flagged for critic challenge. Default per CLAUDE.md is 4×H100 sweep parallelism; I documented the tradeoff.
- **`max_new_tokens=4` for cross-eval:** the DV is first-token; the CLAUDE.md ≥2048 rule is for end-of-completion evals (different DV class).
- **No periodic-eval callbacks during training:** the rig is mature (lineage of 6+ predecessor tasks); per-step monitoring is unnecessary at 600 rows × 3 epochs ≈ 450 steps per condition.
- **A1 (`helpful_assistant`) overlap with Qwen default chat-template system tag — acknowledge, don't fix (remediation (a)):** Qwen-2.5-7B-Instruct's default `apply_chat_template` output (when no system message is given) inserts the literal text `"You are Qwen, created by Alibaba Cloud. You are a helpful assistant."` — the second sentence overlaps verbatim with A1's locked persona prompt. v1 of this plan stated only the first sentence and missed the overlap. v2 acknowledges the overlap as a known structural confound rather than (b) collapsing the class boundary or (c) swapping A1 against the locked spec. Honest-reporting principle: the divergence D[A1, B*] is what the base model actually sees with the A1 system prompt vs the default-tagged B* prompt; both contain the "You are a helpful assistant" string, so the divergence will be compressed and the experiment will measure that compression empirically. The per-cell ρ analysis (Knob 5d) will surface it; the clean-result reports it as a finding rather than a methodological bug. Phase 1 entry runtime-asserts the default-tag text is unchanged from the v2-pinned string — Qwen template drift triggers a hard fail rather than silent geometry shift.
- **Negative-band per-cell threshold loosened 0.4 → 0.5 (v5 — user picked option (ii) at Step 2c plan approval):** A 500-trial Monte Carlo simulation by the Phase 2 Statistics-Claude critic at the planned design (N=380 pairs, 16 class-pair cells, single seed v1) found: (i) under v3's pre-loosening thresholds, ~60% of true-H0 worlds violated the `no per-cell |ρ| ≥ 0.4` criterion by chance (small-N cell noise), and ~70% landed in the "ambiguous middle"; (ii) the positive band (|ρ| ≥ 0.4 + p < 0.01 + survives cluster mixed model) requires true ρ ≥ ~0.6 to fire reliably; at true ρ = 0.4 the positive band fires ~0% of the time. v3 surfaced three options to the user at the plan-approval gate: **(i)** accept v3 thresholds + plan multi-seed follow-up as the modal v1 outcome (cheapest, but multi-seed adds ~3-5 GPU-h × N_seeds at follow-up time), **(ii)** loosen the negative-band per-cell threshold from 0.4 → 0.5 (Statistics critic estimated this would bring true-H0 negative-band firing rate from ~40% to **~80%**), or **(iii)** tighten the v1 design (increase q_test from 20 to 40, ~+30 min Phase 3 wall, or run 2-3 seeds in v1 at +14-21 GPU-h). **User picked (ii) at Step 2c plan approval.** v5 carries the loosened threshold through every named site. Updated expected modal landings: under true-H0 worlds, negative band fires ~80% (was ~40%); ambiguous middle drops to ~15% (was ~70%); spurious-positive remains <5% (unchanged — positive band is unmodified). Under weak-effect worlds (true ρ ≤ 0.4), positive band still fires ~0% — multi-seed follow-up remains the modal path for that regime, not v1. The bargain (ii) buys is a meaningfully more decisive v1 verdict under TRUE-NULL worlds; it does not buy reach into the weak-positive regime.

## Risky-to-keep-locked notes (one-paragraph summary for orchestrator)

The locked-spec knob I am MOST nervous about keeping fixed is **the choice to use Q_test = Q'_probe**. The spec's rationale is correct (no leakage because predictor runs on the untouched base model), but it concentrates per-question idiosyncrasies in a 20-question sample that has to do *two* jobs: characterize the divergence between transformation pairs AND probe the trained models' generalization. If the 20 specific questions happen to be more discriminating along one of the four classes than the others (e.g., values/opinion questions discriminate Class A personas well but Class C formats less), the per-class-pair ρ readings will be confounded with question-domain choice. A defensive variant would run a 5-question pilot across Class A only to verify that the per-class ρ readings are robust to question-set composition before running the full N=20 — that's not in the plan as written, but the critic should flag it.

A second risky lock is **N=20 single seed.** The pre-registered multi-seed follow-up handles the ambiguous-middle case, but a single seed at N=20 means the headline ρ has its own seed-variance noise floor. The N=380 pairs help, but they are NOT independent (each condition contributes 19 pairs). The effective N for cluster-bootstrap purposes is closer to 16 (= 4 classes × 4 classes), and with 16 clusters the bootstrap CI will be wide. The critic should flag if the locked threshold |ρ| ≥ 0.4 is too conservative — i.e., the 16-cluster bootstrap might never produce a CI tight enough to support a |ρ| ≥ 0.4 verdict at N=380, in which case the experiment is effectively pre-registered to land in the ambiguous middle. (Pilot the bootstrap on a synthetic data set with known true ρ = 0.5 at the same N=380 / 16-cluster structure to confirm the CI is informative.)

A third risk: **Class C training with `dataset_text_field`** is not in the existing project rig. v3 specifies it (MF-2 fix per Phase 2 critic): the implementer extends `TrainLoraConfig` + `train_lora()` in `src/.../train/sft.py` with a `dataset_text_field: str | None = None` opt-in + a 2-row label-audit preflight, commits that change BEFORE Phase 2 dispatch fires the C2 pilot gate. The code-reviewer verifies the default behavior (when `dataset_text_field is None`) is byte-identical to the current prompt-completion path. The label-audit preflight catches the most common failure mode (marker token not in loss mask). If the C2 pilot gate STILL fails twice after the extension lands and the label audit passes, the dispatcher writes `drop_class_c.flag` and continues with N=15 (C1 retained, C2/C3/C4/C5 dropped) — documented in the clean-result.

A fourth risk surfaced by the Phase 2 Statistics-Claude critic, **resolved in v5**: the v3 pre-registered thresholds were calibrated for a strong-effect regime; modal v1 landing under both true-H0 and weak-effect worlds was the "ambiguous middle" band that triggers multi-seed follow-up. v3 surfaced three options (i/ii/iii) at the plan-approval gate; **user picked option (ii) at Step 2c: loosen the negative-band per-cell threshold from 0.4 → 0.5.** Updated modal landings under v5 thresholds: true-H0 worlds now land in the **negative** band ~80% of the time (was ~40%); ambiguous middle drops to ~15% (was ~70%). Weak-effect worlds (true ρ ≤ 0.4) still land in the ambiguous middle and still trigger multi-seed follow-up — the loosening buys decisiveness under true-null worlds, not reach into weak-positive worlds. Positive-band thresholds are unchanged.
