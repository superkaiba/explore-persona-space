### 3.2 Decider — `decide_triage_observer_actions` (L4021-4054)

New signature (keyword-only new param; both existing test call sites and the production positional call keep working):

```python
def decide_triage_observer_actions(
    violations: list[dict],
    flagged: set[str],
    marker_budget: int,
    *,
    push_budget: int | None = None,
) -> list[dict]:
    """PURE routing for triage-observer flags (unit-testable without IO).

    Drops already-flagged keys (key = ``f"{record_ts}|{violation}"``), orders
    warn-before-info (ties by record_ts), and attaches action fields: sidecar
    always; push only for ``warn`` while the per-tick push budget lasts
    (``push_budget=None`` = uncapped, the pre-#1167 semantics); marker only
    for ``warn`` while the per-tick marker budget lasts. The two budgets are
    INDEPENDENT. An over-MARKER-budget warn keeps ``push`` semantics and is
    STILL emitted (the caller marks it flagged) — permanently
    sidecar+push-only, its marker is NEVER deferred to a later tick
    (cap-overflow semantics, #967 plan §3 Q4). An over-PUSH-budget warn
    keeps ``marker`` semantics and gets ``push=False, push_suppressed=True``
    — the caller rolls suppressed warns into ONE end-of-pass summary push;
    the individual push is NEVER deferred (#1167). Every action carries
    ``push_suppressed`` (bool; False for info rows and in-budget warns).
    Never mutates ``flagged``."""
    fresh = [
        v for v in violations if f"{v.get('record_ts', '')}|{v.get('violation', '')}" not in flagged
    ]
    fresh.sort(key=lambda v: (0 if v.get("severity") == "warn" else 1, v.get("record_ts", "")))
    actions: list[dict] = []
    budget = marker_budget
    pbudget = push_budget
    for v in fresh:
        warn = v.get("severity") == "warn"
        marker = warn and budget > 0
        if marker:
            budget -= 1
        push = warn and (pbudget is None or pbudget > 0)
        if push and pbudget is not None:
            pbudget -= 1
        actions.append(
            {
                **v,
                "key": f"{v.get('record_ts', '')}|{v.get('violation', '')}",
                "sidecar": True,
                "push": push,
                "push_suppressed": warn and not push,
                "marker": marker,
            }
        )
    return actions
```

Capping lives in the PURE decider (not in `_triage_observer_emit`) — the exact architecture the marker cap uses, and the unit-testable seam the existing routing test already exercises.

## 11. Decision Rationale

(N/A — no model training; no experiment hyperparameters. Sources are code precedents per the task brief.)

- **Default K = 5.**
  - *What:* `TRIAGE_OBSERVER_PUSH_CAP = 5` per tick.
  - *Why:* the Goal says "mirroring the existing per-tick marker cap", whose default is 5 (`scripts/autonomous_session_watch.py:3913`); pushes land in the my-goat 3×/day digest queue (`_telegram_push` docstring, L18222-18234), so worst case is 6 digest lines per tick — bounded and readable. The motivating first-tick 48h-backlog flush has already fired (task body, sweep verification 2026-07-08); residual value is post-outage bursts, for which 5+1 is ample signal.
  - *Source:* `scripts/autonomous_session_watch.py:3913`; task body #1167 § Sweep verification; #967 plan §3 (marker-cap sizing rationale, "spam valve … sidecar keeps full fidelity").
  - *Alternatives:* K=3 (tighter; rejected — asymmetric with the marker cap it claims to mirror, and each push is only a digest line, not a raw ping); K=10 (looser; rejected — a 10-line burst is exactly the "trains the user to ignore the channel" failure the task names).
- **Env var name `EPM_TRIAGE_OBSERVER_PUSH_CAP`, constant `TRIAGE_OBSERVER_PUSH_CAP` (no underscore prefix).**
  - *What/Why:* byte-symmetry with `EPM_TRIAGE_OBSERVER_MARKER_CAP` / `TRIAGE_OBSERVER_MARKER_CAP`; the public (non-underscore) constant is what the pass reads at call time and what tests monkeypatch — the task body's `_TRIAGE_OBSERVER_PUSH_CAP` sketch would break that symmetry.
  - *Source:* `scripts/autonomous_session_watch.py:3913`; test monkeypatch pattern precedent (module-attr patching throughout `_triage_observer_sandbox`, tests L14841-14844).
  - *Alternatives:* underscore-prefixed private constant (rejected — the sibling cap is public and test-patched).
- **Clamp `lo=0, hi=100` via `int(_env_float(...))`.**
  - *What/Why:* identical clamp + coercion to the marker-cap line; `lo=0` makes cap-0 a legal quiet mode, `hi=100` bounds a fat-fingered env value.
  - *Source:* `scripts/autonomous_session_watch.py:3913` (verbatim precedent).
  - *Alternatives:* a dedicated `_env_int` helper (rejected — doesn't exist; inventing one widens the diff for zero behavior change).
- **Capping in the PURE decider, not in `_triage_observer_emit`.**
  - *What/Why:* the marker cap's exact architecture — `decide_triage_observer_actions` is the documented unit-testable IO-free seam (docstring L4024-4033; routing test L14876); emit stays a dumb executor of decided actions, so the emit body needs ZERO changes and the non-gating/fire-once tests are structurally untouched. The Goal's phrasing ("in _triage_observer_emit") describes the observable behavior (emit's pushes get capped), which this achieves; the clarifier's refined design shape (thread through the decider) is adopted.
  - *Source:* `scripts/autonomous_session_watch.py:4021-4054` (marker-cap precedent); #967 plan §3 (pure-decider architecture).
  - *Alternatives:* a `pushes_sent` counter inside emit (the task body's original sketch; rejected — splits capping across two functions, needs an emit signature change, and leaves the pure decider lying about `push=True` actions that won't fire).
