### Item 1 — concrete diff (`scripts/run_i207_gentle_worker.py:143-167`)

Replace the function body:

```python
def upload_adapter_to_hub(adapter_dir: str, run_name: str) -> str | None:
    """Push the LoRA adapter to HF Hub via the policy-aware hub helper.

    Routed through ``orchestrate.hub.upload_model`` (review follow-up, #565)
    so the always-on TRAINING_STATE_IGNORE_PATTERNS, the checkpoint-*
    adapter-only exclusion, and post-upload verification apply. Non-fatal:
    returns None on any failure; the local adapter dir is kept.
    """
    hub_dest = f"adapters/{run_name}"
    repo_id = "superkaiba1/explore-persona-space"  # == hub.DEFAULT_MODEL_REPO
    logger.info("Uploading %s -> %s/%s", adapter_dir, repo_id, hub_dest)
    try:
        from explore_persona_space.orchestrate.hub import upload_model

        hub_path = upload_model(
            model_path=adapter_dir,
            repo_id=repo_id,
            path_in_repo=hub_dest,
            delete_after=False,
            ignore_patterns=["checkpoint-*"],
        )
    except Exception as e:
        logger.warning("Adapter upload failed (non-fatal): %s", e)
        return None
    if not hub_path:
        logger.warning(
            "Adapter upload to %s/%s did not verify (non-fatal); local copy kept at %s",
            repo_id, hub_dest, adapter_dir,
        )
        return None
    logger.info("Upload complete: %s", hub_path)
    return hub_path
```

Notes: `upload_model` handles missing `HF_TOKEN` internally (warn + `""`, hub.py:143-146), replacing the old `ImportError` guard; the deferred hub import matches the script's existing style (`train_lora` imported inside `train_and_merge`). The `try/except` is defensive against future `upload_model` refactors that let exceptions propagate (same rationale as `tests/test_adapter_persist.py:95-115`, but with the *opposite* contract — this path is non-fatal by design).

## 11. Decision Rationale

`kind: infra` — **exempt from hyperparameter grounding** (no model training; "N/A — no hyperparameters in this task type"). Non-obvious design choices:

- **Item 1 adds `ignore_patterns=["checkpoint-*"]`, not just the training-state excludes.** The review's minimum ask is the always-on `TRAINING_STATE_IGNORE_PATTERNS`; adding `checkpoint-*` matches `_maybe_upload_adapter_default` (trainer.py:590) and the adapter-canonical policy. No consumer reads `adapters/i181_gentle_*` checkpoint subdirs (grep-verified). Alternative (training-state-only) rejected as an inconsistent half-measure.
- **Item 1 drops the custom commit message** rather than adding a `commit_message` passthrough to `upload_model`/`_upload` — a public-helper signature change is must-ask territory and pure scope creep here.
- **Item 2 extends `tests/test_upload_defaults.py`** rather than a new file: it is the home of the c5bc6149c policy pins (its module docstring enumerates exactly the three behaviors; the runner gate is the missing third layer). Alternative (new `test_runner_merged_gate.py`) allowed as a deviation.
- **Item 2 tests the real `run_single`,** not an extracted seam — the task body's stated preference, and feasibility was verified by read (§3). Alternative (refactor the gate into a helper) rejected: refactoring production code to make a test easier inverts the hardening intent.
- **`merged_upload_enabled` left unmocked** so the test exercises gate + predicate together; its isolated logic is already covered by `TestMergedUploadEnabled`.
