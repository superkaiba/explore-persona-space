### Item 1 — `repo_branch` plumbing + fail-loud post-bootstrap assertion

**Drop point (traced by reading).** `RunPodBackend.launch` (`src/explore_persona_space/backends/runpod.py:884-954`) builds the `pod_lifecycle.py provision` argv with `--issue`, `--intent`, optionally `--gpu-count`, `--container-disk-gb`/`--volume-gb`, then calls `_run_pod_lifecycle_relay(cmd)` at :954. The argv **NEVER carries the `repo_branch`** — no `--repo-branch` flag is passed, no `env` dict is threaded to override `BOOTSTRAP_BRANCH`. `pod_lifecycle.py` has no `--repo-branch` argparse arg (grep returns 0 hits — confirmed) and its `_bootstrap()` at :744–759 sets only `env["POD_INTENT"] = intent_label`. So `BOOTSTRAP_BRANCH` is unset in the bootstrap subprocess env, which defaults it to `main` at `bootstrap_pod.sh:52`. **This is the drop.**

**Fix 1(a) — plumb the branch through the provision subprocess env.** File: `src/explore_persona_space/backends/runpod.py`, at the `_run_pod_lifecycle_relay(cmd)` call (`:954`). Add a `BOOTSTRAP_BRANCH` env pin BEFORE the relay call:

```python
# Diff sketch (add ~6 lines before line 954):
repo_branch_env = str((spec.extra or {}).get("repo_branch") or "").strip()
env_for_provision = os.environ.copy()
if repo_branch_env:
    # Bootstrap defaults BOOTSTRAP_BRANCH to "main" (bootstrap_pod.sh:52).
    # A plan that requested a specific branch (via dispatch_issue.py --repo-branch)
    # threads it into the pod bootstrap here — else the pod lands on main
    # and the workload runs stale code (#1689 R8/R9).
    env_for_provision["BOOTSTRAP_BRANCH"] = repo_branch_env
_run_pod_lifecycle_relay(cmd, env=env_for_provision)
```

Preserves the empty/default-`main` case as no-op (env pin only when explicitly requested; `bootstrap_pod.sh:52` default handles the rest). Signature note: `_run_pod_lifecycle_relay` already accepts an `env=` kwarg — the `teardown` call at :1545 uses `env=os.environ.copy()`.

**Fix 1(b) — fail-loud post-bootstrap branch assertion.** File: `src/explore_persona_space/backends/runpod.py`. Add a NEW function `_assert_pod_on_branch(pod_name, expected_branch)` called AFTER `_run_pod_lifecycle_relay(cmd, env=env_for_provision)` in `RunPodBackend.launch` (immediately after fix 1(a); before `attempt_id = mint_runpod_attempt_id()` at :967). Binds ONLY when `repo_branch_env` is non-empty AND `!= "main"` — the default-main case is unaffected.

```python
# Diff sketch (add ~20 lines, called right after the relay):
if repo_branch_env and repo_branch_env != "main":
    _assert_pod_on_branch(pod_name=_runpod_pod_name(spec.issue),
                          expected_branch=repo_branch_env)

# New helper (place near _execute_workload_on_pod, ~:700):
def _assert_pod_on_branch(pod_name: str, expected_branch: str) -> None:
    """Post-bootstrap fail-loud: pod's checkout HEAD branch must == expected."""
    host, port = _resolve_pod_endpoint(pod_name)
    out = _ssh_pod_run(host, port,
        "cd /workspace/explore-persona-space && git rev-parse --abbrev-ref HEAD",
        timeout=30, context=f"branch verify on {pod_name}")
    actual = out.strip().splitlines()[-1] if out.strip() else ""
    if actual != expected_branch:
        raise RunPodProvisionBranchMismatchError(
            f"pod {pod_name} bootstrapped onto branch {actual!r}, "
            f"expected {expected_branch!r} — the --repo-branch plumbing "
            f"dropped the value; do NOT proceed on stale code"
        )
```

Add `class RunPodProvisionBranchMismatchError(RunPodWorkloadStartError): pass` near the other exception classes (~:250). Subclassing `RunPodWorkloadStartError` means the existing catch at :1124 wraps it into a `#954` partial-handle failure (pod exists, workload didn't start) so the failover machinery routes cleanly.

### Item 2 — Idempotent teardown for an already-terminated pod

**Trace.** `RunPodBackend.teardown` (`src/explore_persona_space/backends/runpod.py:1507-1545`) calls `_run_pod_lifecycle_relay(["...pod_lifecycle.py", "terminate", "--issue", str(issue), "--yes"], env=os.environ.copy())`. `cmd_terminate` (`scripts/pod_lifecycle.py:2930`) delegates to `_terminate_clear_stale_sidecar` at :2982 when no live pod exists; that helper raises `SystemExit(f"No live pod found for issue {issue} (and no local record). Nothing to terminate.")` at `pod_lifecycle.py:2911` — which yields rc=1 in the child subprocess, which `_run_pod_lifecycle_relay` at :200 raises as `PodLifecycleProcessError`.

`_cmd_finalize` calls `backend.teardown(handle)`. A `PodLifecycleProcessError` propagates all the way up → finalize exits non-zero without renaming the handle sidecar to `<name>.finalized`. This is exactly what happened on #1689 ("recovery was a hand `mv` … needed twice").

**Fix 2.** In `RunPodBackend.teardown` (`src/explore_persona_space/backends/runpod.py:1507-1545`), catch `PodLifecycleProcessError` whose stderr tail contains "Nothing to terminate" (case-insensitive) and treat as idempotent success. Every OTHER `PodLifecycleProcessError` still fails loud.

```python
# Diff sketch (replace the final call at :1545 with):
try:
    _run_pod_lifecycle_relay(cmd, env=os.environ.copy())
except PodLifecycleProcessError as exc:
    # Idempotent teardown: a pod that is already gone (manual pod.py terminate,
    # a router-lane janitor, an external cleanup) is a completed teardown from
    # this call's vantage — the goal ("this pod is gone") already holds.
    # Match on the exact stderr signature pod_lifecycle emits at :2911.
    # Every other PodLifecycleProcessError propagates (auth error, RunPod API
    # 5xx, pod-exists-but-terminate-refused). #1689 recovery required
    # hand-mv-ing the handle sidecar twice; this catch retires it cleanly.
    stderr_tail = (exc.stderr or "").lower()
    if "nothing to terminate" not in stderr_tail:
        raise
    logger.info(
        "RunPodBackend.teardown: pod already gone (matched 'Nothing to "
        "terminate' in pod_lifecycle stderr); treating as idempotent success"
    )
```

**No changes to `_cmd_finalize`.** The `<name>.finalized` sidecar rename lives in `_cmd_finalize` (`scripts/dispatch_issue.py`). With this fix, `backend.teardown(handle)` returns cleanly on the already-gone case, and the existing rename code path executes.

**Acceptance criterion.** New test `tests/test_runpod_backend.py::test_teardown_idempotent_on_already_gone_pod`. Plus `test_teardown_propagates_other_pod_lifecycle_errors`.

## 11. Decision Rationale

### Item 1(a) — `BOOTSTRAP_BRANCH` env pin at the provision subprocess

- **What:** Set `env["BOOTSTRAP_BRANCH"] = spec.extra["repo_branch"]` in `RunPodBackend.launch` before `_run_pod_lifecycle_relay(cmd)` at `runpod.py:954`.
- **Why:** `pod_lifecycle.py` has no `--repo-branch` argparse arg; `_bootstrap()` at :744–759 only pins `POD_INTENT`; `bootstrap_pod.sh:52` defaults `BOOTSTRAP_BRANCH=main` when unset. Env pin is the minimum plumbing.
- **Source:** `#1689` R8/R9 markers + compose-time reads of `bootstrap_pod.sh:52,220-274` and `pod_lifecycle.py:744-759`.
- **Alternatives:** Adding a `--repo-branch` argparse arg to `pod_lifecycle.py provision` (rejected: three-file change vs one; `BOOTSTRAP_BRANCH` is the documented override channel per `bootstrap_pod.sh:12-18`).

### Item 1(b) — Fail-loud post-bootstrap branch assertion

- **What:** SSH-probe `git rev-parse --abbrev-ref HEAD` on `/workspace/explore-persona-space` after bootstrap; raise `RunPodProvisionBranchMismatchError` on mismatch. Bind ONLY when `repo_branch` is explicit non-empty AND non-`main`.
- **Why:** Belt+suspenders — surfaces any FUTURE plumbing regression loud instead of running stale code for 25+ minutes. Subclassing `RunPodWorkloadStartError` routes through the #954 partial-handle failure machinery.
- **Source:** `#1689` R8/R9 markers.
- **Alternatives:** No assertion (rejected: a future refactor could re-introduce the drop). Assert during bootstrap itself in `bootstrap_pod.sh` (rejected: the script is checking out what it was told; a self-check proves nothing about whether the ORCHESTRATOR requested the right branch).

### Item 2 — Idempotent teardown for already-gone pod

- **What:** Catch `PodLifecycleProcessError` in `RunPodBackend.teardown` whose stderr tail contains `"nothing to terminate"` (case-insensitive) and treat as success; re-raise all others.
- **Why:** The goal ("this pod is gone") is achieved by construction when the pod is already gone; raising is wrong. Matching on the specific `pod_lifecycle.py:2911` error string is narrow enough not to swallow other errors.
- **Source:** `#1689` markers + `scripts/pod_lifecycle.py:2911` (exact SystemExit string).
- **Alternatives:** Pre-check via `list_team_pods` (rejected: adds an API call and a check-then-terminate race). Modify `pod_lifecycle.cmd_terminate` to return 0 on no-live-pod (rejected: changes semantics of `pod.py terminate` CLI for existing callers; the backend's teardown contract is the right layer).

### Item 3 — RunPod-lane fresh-provision routing contract

- **What:** Documentation-only edit to `experimenter.md` (new "Contract scope" sub-section) + `SKILL.md` Step 6d.1 (new check-4 prose).
- **Why:** The running code already handles both cases correctly; the failure is a ROUTING gap the orchestrator makes based on skill prose. Prose fix IS the fix.
- **Source:** `#1689` R8 (verbatim orchestrator note "subagent bg-Bashes get killed when the subagent exits").
- **Alternatives:** Code-level enforcement (rejected: the experimenter already fails informatively when it hits a half-bootstrapped pod via the `Post-dispatch bootstrap-completeness probe` at experimenter.md :179–216; the missing piece is telling the orchestrator NOT to dispatch that way in the first place).
