## 3. Method delta — why the zero-memory verdict is DISTINCT from the gpu-idle advisory

The body directs: read how the existing advisory works and reuse its machinery, don't build a parallel stack. Done (see §2). The delta, precisely:

1. **Signal class.** The existing tiers key on `utilization.gpu`. 0% util is *suggestive* — it is also what a healthy GPU phase looks like between kernels, during CPU-side data prep inside a GPU phase, or during a judge-API wait. `memory.used == 0 MiB` is *conclusive*: a CUDA context on an H100 pins hundreds of MiB from creation to process exit, so sustained 0 MiB on every card means no process has EVER created a context in the window. This is exactly the discriminator the #2546 measurement used ("The `0 MiB` is what makes this conclusive rather than suggestive").
2. **Verdict semantics.** The idle advisory/escalation notes frame the finding as a spend leak: "Likely a CPU-only phase holding a GPU pod — consider moving the phase off-pod". The new verdict states a *plan falsification*: this phase was ROUTED to a GPU lane on a §9 GPU-worthiness claim and has no CUDA context — the routing claim is false; record → finish → file (the §4.4 pods.md runbook), do not migrate.
3. **Coverage hole closed.** The escalation (the only pushing tier today) requires `_phase_is_cpu_only(current_phase)` — i.e. it is SUPPRESSED for any phase whose name contains `train`/`gen`/`eval`/`vllm`/…, which are precisely the phases whose plans claimed GPU. A phase named `p2_train` at 0 MiB would today get only the 30-min marker-only advisory, never a push. The new verdict fires regardless of phase name and pod width (n_gpus ≥ 1) — the falsification evidence is the memory value, not the phase-name heuristic.
4. **Timing/loudness.** Idle advisory: 30 min, marker only. Escalation: 60 min, push, multi-GPU + CPU-classified only. New: 20 min AND ≥ 3 consecutive zero samples, marker + push on first fire, once per phase. Louder AND earlier is justified because the false-positive rate of the memory signal is structurally lower than utilization's (see §5 window rationale).
5. **What is reused (no parallel stack):** the same per-tick SSH probe round-trip (one added nvidia-smi line — no second SSH call), `_parse_gpu_utils` for the csv, the pure-core + wiring split, the same `tripwire_state` persistence + `_tripwire_run_scope` run-reset, the same `epm:progress` channel + at-most-once-per-phase dedup + post-failure-retries-next-tick semantics, and `_telegram_push`.

```python
def _gpu_mem_all_zero(gpu_mem_mib: str, max_mib: int) -> bool:
    """True iff gpu_mem_mib PARSES and every card's memory.used <= max_mib.

    Fail-safe: "unknown" / unparseable -> False (never accumulates toward an
    advisory) — the `_parse_gpu_utils` None contract carries over verbatim.
    """
    vals = _parse_gpu_utils(gpu_mem_mib)  # csv-int parser; reused as-is
    return vals is not None and all(v <= max_mib for v in vals)


@dataclass(frozen=True)
class GpuNoCtxUpdate:
    """Outcome of one no-CUDA-context tick (``_gpu_noctx_update``)."""

    should_post: bool
    since_epoch: int  # 0 = no active all-zero span
    zero_ticks: int   # consecutive all-zero ticks incl. this one; 0 = no span
    span_sec: int


def _gpu_noctx_update(
    *, status, gpu_mem_mib, current_phase, prev_phase, prev_since_epoch,
    prev_zero_ticks, advised_phases, now_epoch, advisory_min, min_ticks, max_mib,
) -> GpuNoCtxUpdate:
    """Pure decision core for the #2624 no-CUDA-context advisory.

    Span semantics mirror `_gpu_idle_advisory_update`: RESET on non-running
    verdict, any card above max_mib, or an unknown/unparseable sample;
    RESTART on phase change (each phase gets its own warm-up allowance).
    Fires once per phase when span >= advisory_min minutes AND
    zero_ticks >= min_ticks. Pure / no I/O.
    """
    if advisory_min <= 0:
        return GpuNoCtxUpdate(False, 0, 0, 0)
    if status != "running" or not _gpu_mem_all_zero(gpu_mem_mib, max_mib):
        return GpuNoCtxUpdate(False, 0, 0, 0)
    if current_phase != prev_phase or prev_since_epoch <= 0:
        since, ticks = now_epoch, 1
    else:
        since, ticks = prev_since_epoch, prev_zero_ticks + 1
    span = max(0, now_epoch - since)
    should = (
        span >= advisory_min * 60
        and ticks >= min_ticks
        and current_phase not in advised_phases
    )
    return GpuNoCtxUpdate(should, since, ticks, span)
```

## 5. Verdict predicate — window/threshold choices and false-positive analysis

**Predicate (final):** fire once per phase iff ALL of: status == `running`; `gpu_mem_mib` parses; every card ≤ **64 MiB** (`EPM_GPU_NOCTX_MEM_MAX_MIB`); span ≥ **20 min** (`EPM_GPU_NOCTX_ADVISORY_MIN`); ≥ **3 consecutive** all-zero samples (`EPM_GPU_NOCTX_MIN_TICKS`); phase not already advised. Any non-qualifying tick resets span AND tick counter; a phase change restarts them.

- **64 MiB threshold:** a card with no CUDA context reports 0–a few MiB of `memory.used` (the incident read exactly 0); the smallest real CUDA context on an H100-class card pins ~300–600 MiB. 64 MiB sits ≥ 4× above the no-context band and ≥ 4× below the smallest context — wide margins both ways. Env-overridable. Source: #2546 measurement (0 MiB) + CUDA context-size order of magnitude; marked Medium confidence in §12 (advisory-only, so a miscalibration costs one wrong note, never an action).
- **20-min window (vs the idle advisory's 30):** justified earlier BECAUSE the signal is stronger, bounded below by warm-up: model download/load + tokenization/data-staging preambles for 7B-class workloads are typically < 15 min, and vLLM/torch allocate within ~1–2 min of engine/first-forward start. The per-phase span restart gives EVERY phase its own full 20-min allowance, so a long staging phase followed by a GPU phase never accumulates across the boundary (phases are read from the `[phase=...]` log convention, same as the siblings).
- **≥ 3 consecutive samples:** at the default 540 s cadence, 20 min ≈ 3–4 ticks; but under the 1800 s quiet cadence a bare span check could fire on only 2 samples. The tick floor guarantees ≥ 3 independent zero reads regardless of cadence. A GPU burst between two samples frees its memory only if its process exits mid-phase — possible in principle, which is one reason the verdict stays advisory (stated in the note: "if this phase legitimately allocates later, disregard").
- **Fail-safes carried over verbatim:** `unknown`/unparseable memory sample → False → full reset (a missing/erroring nvidia-smi never accumulates); non-`running` verdict → reset; post failure → phase not recorded advised, next tick retries; push failure → fail-soft.
- **Advisory-not-kill semantics:** the function returns state for `_save_state` and a `posted` bool; it is called after the verdict is already computed and cannot influence `status`, stall, dead, or done. This is the same structural guarantee the four sibling advisories carry.
