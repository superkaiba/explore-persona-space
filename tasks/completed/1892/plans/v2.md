## 1. Requirement + acceptance criteria (kind: infra)

**Requirement:** on every GCP RECONNECT-path `epm:backend-selected` marker,
`extra.provisioning_model` reports the handle's live-instance-derived value whenever the
reconnect handle carries one; the spec-derived value remains the fallback when the handle lacks
the key (degraded API read).

Acceptance criteria:

1. A reconnect to a live FLEX_START instance posts an `epm:backend-selected` marker whose
   `extra.provisioning_model == "FLEX_START"` even when the spec carries no
   `provisioning_model` pin (spec default STANDARD) — at ALL THREE gcp reconnect seams:
   (i) the explicit-override generic reconnect seam (router.py ~3952,
   detail `"found existing live job/instance"`), (ii) the `_override_gcp_with_ladder`
   reconnect (router.py ~4369 — the incident seam), and (iii) the auto-chain
   `_reconnect_result` composer (router.py ~4732).
2. When the handle lacks `provisioning_model` (live list response missing `scheduling`), the
   marker keeps today's spec-derived value byte-identically (fail-open, no crash).
3. An additive `extra.provisioning_model_source: "live-instance"` field rides the marker ONLY
   when the override fired (additive extra field — same class as `gcp_ladder_rung`; no marker
   SCHEMA change; absent on fresh launches and non-overridden reconnects, so existing shapes
   stay byte-identical).
4. Fresh-launch marker composition (router ~5708) and the gcp.py CREATE-path writers
   (handle extra ~5713, `epm:cluster-launched` marker ~5816) are UNTOUCHED — spec-derived is
   correct there (the spec's rung pin is what created the instance).
5. Pin tests fail pre-fix and pass post-fix — one per seam (three tests) + one fallback test.
6. The original body's Goal is dispositioned in the implementer report as

7. `_gcp_marker_extras`'s docstring (which enumerates the reconnect call sites) is updated to
   name all three reconnect seams + the handle-override merge convention.

## 2. Method delta

Pre-fix: the three gcp reconnect RouteResult composers set `extra=_gcp_marker_extras(spec)`
(pure spec-derived). Post-fix: each merges a handle-derived override on top:
`{**_gcp_marker_extras(spec), **_live_provisioning_extras_from_handle(handle)}`. Follows the
existing `_boot_disk_extras_from_handle` handle-derived-merge precedent (router.py ~4074 /
~5708). No routing, lease, sidecar, poller, or failover behavior changes — marker observability
only. The handle sidecar itself is already correct (#1815) and is not touched.

  1. NEW pure helper (near `_gcp_marker_extras`):

     ```python
     def _live_provisioning_extras_from_handle(handle: RunHandle | None) -> dict[str, Any]:
         """Reconnect-marker override (#1892): prefer the HANDLE's live-derived
         provisioning_model (gcp.reconnect_or_none reads scheduling.provisioningModel
         off the live instance, #1815) over _gcp_marker_extras' spec default —

         driving a wrong disarmed-gate diagnosis. Returns {} when the handle carries
         no value (fail-open to the spec-derived fallback). Pure function, no IO.

         v = (getattr(handle, "extra", None) or {}).get("provisioning_model")
         if not v:
             return {}
         return {"provisioning_model": str(v), "provisioning_model_source": "live-instance"}
     ```
