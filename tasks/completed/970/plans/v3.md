## 11. Decision Rationale

1. **Word set = `SUCCESS` AND `FAILURE` (not SUCCESS-only).** *Why:* they are the natural verdict pair for the incident class; FAILURE's single legit caps usage (#543) is in a completed, never-re-audited body, so realized FP cost is zero. *Source:* corpus grep this session (§4 table); #892 plan v1 line 174 (named `SUCCESS|FAILURE` as the candidate). *Alternatives:* SUCCESS-only (rejected — asymmetric coverage, no FP benefit; retained as the kill-criterion fallback).
2. **No context guard.** *Why:* bigram/lookahead anchoring is the exact fragility that let #763 escape `pre_reg`; the incident class is phrasing-diverse; the existing four words are bare, and consistency keeps the pattern auditable. *Source:* #892 incident (`tasks/completed/892/body.md:22`); the pattern's own precedent at script line 39. *Alternatives:* `(?=\s+(?:was|criterion|gate))` lookahead (rejected — misses "read SUCCESS" / "declared FAILURE").
3. **Case-sensitivity kept (`flags=0`).** *Why:* it is the FP filter — `success`/`Success`/`successful` are everyday words; only shouty caps encode a gate verdict. *Source:* `audit_body()` line 664 (only `pre_reg` gets IGNORECASE); pinned by new test 3. *Alternatives:* none viable.
4. **Description enumerates the new words.** *Why:* the description is the operator-facing doc of the word list and already enumerates all four existing words. *Source:* script line 40. *Alternatives:* generic "…and similar" (rejected — printed doc would under-specify).
5. **By-design pin test for the #543 phrasing (flags it).** *Why:* converts the one known ambiguity into recorded intent; prevents a future round from "fixing" it as an FP without seeing the rationale. *Source:* #543 body line 84; the #642 precedent of pairing broadenings with explicit-behavior tests. *Alternatives:* leave untested (rejected — ambiguity re-litigated later).
