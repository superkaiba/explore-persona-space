## Requirement + acceptance criteria

**Requirement (from the task Goal):** make the watcher pod-safety pass's inferred
follow-up predicate safe on MULTI-ROUND issues — a sibling round's routine status
transition must not flip protection off another round's healthy live pod.

**Root cause (verified against live code at clarify time):**
`scripts/autonomous_session_watch.py::_task_followup_active` (L11385) is
ISSUE-grain: newest follow-up signal (`_POD_FOLLOWUP_SIGNAL_KINDS` =
`epm:run-launched` / `epm:followup-scope` / `epm:free-analysis-followup-run`)
vs newest done-transition (`_DONE_TRANSITION_KINDS` = `epm:promoted` /
`epm:status-changed`). On an issue running concurrent/serial follow-up rounds
(#1768: three inline pods + a session loop), routine sibling transitions post
`epm:status-changed` continually, so any pod whose `epm:run-launched` predates
the latest sibling transition loses inferred protection. The only remaining
shield is the ISSUE-wide `keep-running` tag, which the standing inline-round
guidance says NOT to set (it blocks sibling bare-form teardowns, #1485).
Incident: pod-1768-lt auto-STOPPED at ~05:05Z with 142/216 fit cells done
(launch marker v11 22:34:14Z; a sibling `epm:status-changed` postdated it).

**Acceptance criteria:**

1. **Per-pod named-launch shield — SUFFIXED pods only (v2, Must-Fix 1).** A
   RUNNING managed pod whose name is the SUFFIXED multi-pod form for its issue
   (`pod-<N>-<slug>`, i.e. `pod_name.startswith(f"pod-{issue}-")`; NOT the
   primary `pod-<N>` and NOT the legacy `epm-issue-<N>` form) is exempt from
   the pod-safety auto-stop arm when the issue's events carry an
   `epm:run-launched` marker whose note names THAT pod in a STRUCTURED
   position (criterion 2) and whose ts is younger than the staleness ceiling —
   REGARDLESS of later sibling done-transitions. Rationale: suffixed pods
   exist ONLY as deliberate concurrent inline rounds (#1334), exactly the
   population the issue-grain predicate mis-covers; primary pods keep the
   byte-identical issue-grain path, preserving the classic escaped-primary
   ~20-min reversible stop (the #664-class case the pass exists for — every
   STANDARD launch marker names its pod as `pod=pod-<N>`, so an unscoped
   named shield would have disabled the auto-stop fleet-wide for <ceiling
   hours post-launch).
2. **Structured note match only (v2, Must-Fix 2).** The per-pod arm counts an
   `epm:run-launched` note as naming the pod ONLY via (a) a boundary-safe
   `pod=<name>` token, or (b) the note's LEADING token being `<name>`
   (optionally preceded by whitespace). Both shapes are attested on #1768
   (v1/v2 `pod=pod-1768`; v11 "pod-1768-lt (4 GPU) provisioned…"). A prose
   mention elsewhere in a SIBLING's launch note (the #1768 v14 shape:
   "pod-1768-tx … was already TERMINATED") MUST NOT shield the mentioned pod
   nor restart its ceiling clock. Boundary-safe = `pod-1768` never matches
   inside `pod-1768-lt` (left/right `[\w-]` guards).
3. **Issue-grain fallback unchanged.** When the pod is not suffixed, has no
   structured named launch marker, or the named marker is older than the
   ceiling, the existing issue-grain predicate applies byte-identically. All
   existing `test_task_followup_active_*` / `test_pod_safety_followup_*`
   tests stay green unmodified.
4. **Staleness ceiling bounds billing (v2 — corrected backstop claim).** The
   named shield expires after `EPM_POD_NAMED_SHIELD_MAX_AGE_H` hours (default
   48); past it the pod falls back to the issue-grain predicate (and, failing
   that, the normal 2-miss reversible `pod.py stop`). Honest bound: within
   the ceiling, a shielded escaped SUFFIXED pod bills unmonitored — the
   ceiling ITSELF is the billing bound (the #1582 wedged-owner escalation
   arm rides the keep-running-TAGGED branch and does NOT cover followup-skip
   pods; v1 mis-claimed it as backstop). This trade is confined to suffixed
   pods, whose launching rounds carry the completion-side surgical-terminate
   duty; the 48h default is grounded as ~2× the stale-pod audit's 24h EXITED
   convention and >4× the longest observed inline round (#1768 fits ~7h) —
   recorded in the constant's docstring.
5. **Precedence preserved.** `keep_running` (explicit user tag) still beats
   `followup_active` (inferred); `decide_pod_safety`'s signature and case
   table are UNCHANGED (the refinement lives in how the caller computes
   `followup_active`).
6. **Fail toward KEEP within the auto-stop arm's existing shape.** Any
   read/parse failure in the per-pod arm degrades to the issue-grain
   predicate, never to a synthesized stop.
7. **Guidance docs updated:** CLAUDE.md inline carve-out + SKILL.md 9a-ter
   document the per-pod named-launch shield for SUFFIXED pods — the
   structured pod-naming in the `epm:run-launched` note is load-bearing on
   multi-round issues; `keep-running` stays the explicit override. No
   tag-by-default interim guidance (the predicate fix supersedes it; #1485's
   bare-form-blocking side effect makes tag-by-default actively harmful).
8. **Test coverage (new tests, pure, no subprocess):** listed in §File paths;
   includes the Must-Fix-1 regression (primary pod + done task + fresh
   `pod=pod-<N>` launch marker → stop, not shield) and the Must-Fix-2
   negative (v14 prose-mention shape).

## Method delta

Prior state: issue-grain timestamp comparison only (validated for the
single-round case by #477/#573; the multi-round case did not exist when it
landed). Delta: a per-pod arm for SUFFIXED pods, keyed on the structured pod
name already present in `epm:run-launched` notes by standing duty (CLAUDE.md
inline carve-out: "post `epm:run-launched` ... note naming the pod"; verified
on all three #1768 suffixed launches). No new marker kinds, no schema change,
no change to `decide_pod_safety`'s public shape, primary-pod behavior
byte-identical.
