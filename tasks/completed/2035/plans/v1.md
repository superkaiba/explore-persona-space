# Plan — #2035 daily-fix: backend_poll reachable-wedge escalation arm

`kind: infra` · `workflow_fix_target: scripts/backend_poll.py` · workflow v1 · minimum plan-review floor (wf-fix infra)

## 1. Goal

Close the reachable-wedge blind spot in `backend_poll`'s GCP wedge escalation: a frozen non-terminal `eps/phase` + stale workload-log mtime + budget overrun escalates to `terminal_workload_wedged` even when reachability is OK.

Incident basis (#1739): GCE leg `newarma5syc` sat futex-wedged ~21.6h (6.5 CPU-min total, GPU 0%, workload log stale, phase frozen non-terminal) while ~91 poll ticks read it healthy `running`. The existing #669 arm (`_maybe_escalate_gcp_wedge`, `scripts/backend_poll.py:1136`) REQUIRES `result.reachability_alarm` (transport-class drain failure) as a hard conjunct — a reachable-but-wedged box never trips it, and the #667 "remaining gap" note in `compute-backend-failover.md` documents exactly this hole.

## 2. Design — the reachable-wedge arm

Extend `_maybe_escalate_gcp_wedge` with a SECOND escalation branch (the "reachable arm"), sibling to the existing transport arm. All existing behavior byte-preserved; the transport arm's code path is untouched.

**Escalation conjuncts (ALL required, evaluated per running GCP tick):**

1. **Frozen non-terminal phase** past `GCP_STALENESS_FLOOR_SEC` (900s) — the existing phase-clock read (`_read_phase_clock_for`), unchanged.
2. **NO reachability alarm** (`result.reachability_alarm` False) — the blind-spot case; a transport-alarmed tick routes to the existing arm.
3. **REAL stale workload-log mtime**: `result.last_log_mtime_sec_ago > GCP_REACHABLE_WEDGE_LOG_STALE_SEC` (new constant, default 1800s, env `EPM_GCP_REACHABLE_WEDGE_LOG_STALE_SEC`) **AND** `result.last_log_mtime_sec_ago < 10**9`. The `10**9` value is the coarse-poll sentinel for "mtime not read" (gcp.py:7788 — the #607 overlay writes a truthful mtime onto running ticks only when the drain actually read one); UNKNOWN is never wedge evidence (fail toward running). The 1800s default sits 2× above the phase floor so a legitimately quiet long single-unit step does not qualify.
4. **Budget overrun**: `now − handle.extra["gcp_launched_ts"] > handle.extra["time_budget_hours"] × 3600 × GCP_REACHABLE_WEDGE_BUDGET_FACTOR` (new constant, default 1.0, env `EPM_GCP_REACHABLE_WEDGE_BUDGET_FACTOR`). Missing / non-numeric / non-positive `time_budget_hours` or `gcp_launched_ts` ⇒ conjunct FAILS (fail-open toward running — a handle with no declared budget never fires this arm). Same fail-safe read shape as the queue-vanish arm-N conjuncts (backend_poll.py:1541-1605).
5. **Sustained confirmation** (#1837 semantics): a SEPARATE sidecar-persisted streak — keys `reachable_wedge_streak` / `reachable_wedge_first_ts` / `reachable_wedge_incarnation` — with the SAME bars (`GCP_WEDGE_ALARM_MIN_TICKS = 2` consecutive qualifying ticks, first→latest span ≥ `GCP_WEDGE_ALARM_MIN_SPAN_SEC = 480`s), incarnation-guarded via `_clock_incarnation_for(handle)`, reset on any non-qualifying tick / phase advance / incarnation change. Separate keys are load-bearing: the existing transport streak RESETS exactly when `reachability_alarm` is False — the reachable arm's active regime — so sharing keys would conflate the two signals.

**On escalation:** identical rewrite to the transport arm — `status="dead"`, `current_phase=GCP_WORKLOAD_WEDGED_PHASE` (`terminal_workload_wedged`), `new_milestone=True`, `pid_alive=False`, plus a loud WARN naming the reachable arm and every conjunct value. Reusing the SAME phase means the escalation inherits the existing `_GCP_ASYNC_FAILOVER_PHASES` membership → the #659 async RunPod failover, the lease-bounded exactly-once machinery, and every downstream consumer with ZERO routing changes. The WARN log line + `log_tail_excerpt` distinguish which arm fired for forensics.

**Kill switch:** `EPM_DISABLE_GCP_REACHABLE_WEDGE=1` disables the new arm entirely (background-automation convention; the transport arm is unaffected). Cheap insurance on a money path — the arm triggers a PAID RunPod failover.

**Streak-helper generalization:** parameterize `_read_wedge_alarm_streak` / `_bump_wedge_alarm_streak` / `_reset_wedge_alarm_streak` with a key-tuple argument defaulting to the existing `_WEDGE_ALARM_KEYS`, so existing callers are byte-equivalent and the reachable arm passes its own key tuple (`_REACHABLE_WEDGE_KEYS`). Fail-soft doctrine unchanged: every sidecar read/write failure degrades toward `running`, never crashes the poll, never manufactures a wedge (R6).

**Branch ordering inside `_maybe_escalate_gcp_wedge`:**
- Not GCP / not running → return unchanged (existing; no sidecar writes for foreign handles).
- Phase advanced / first observation → re-stamp clock + reset BOTH streaks, return (a phase advance proves the workload alive for both arms).
- Frozen past floor + `reachability_alarm` → existing transport-arm path (bump transport streak, escalate at bar) + reset the reachable streak (a transport tick leaves mtime at the sentinel, so the reachable conjuncts cannot hold; the explicit reset keeps "sustained = consecutive" exact).
- Frozen past floor + no alarm + conjuncts 3-4 hold + kill switch off → reachable-arm path: bump reachable streak; at bar → escalate; below bar → loud WARN naming streak/span, return running.
- Everything else → reset BOTH streaks, return running.

## 3. Stated deviations from the task body's proposal sketch

The body proposed "treat sustained gpu_util-unknown / CPU-seconds starvation as wedge evidence", explicitly deferred to planning. DROPPED in v1, with reasons:

- `gpu_util`: the GCP lane never populates it — `GcpBackend.poll` leaves the `PollResult` default `"unknown"` on every tick (verified by grep: no gcp.py site sets `gpu_util`). An always-true conjunct is not evidence; wiring it in would weaken the conjunction on a money path.
- CPU-seconds starvation: not on `PollResult` at all. Plumbing a new field through the public poll shape is exactly the "wider change on a money path" the #1837 DOCUMENTED DECISION declined for the alarm class; the three-conjunct core already covers the #1739 incident shape with huge margin (21.6h wedge vs 900s/1800s floors + budget overrun).

Named residual: a reachable wedge on a handle with NO `time_budget_hours` (manual/legacy dispatches) never fires this arm — the stale-GCP janitor + `--max-run-duration` fence remain the backstops there, matching the #1837 rationale sentence verbatim.
