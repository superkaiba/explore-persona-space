  code is NOT verification.** A sha-pinned reused multi-field bundle (a `.pt`
  save-dict, a JSON with asserted fields) carries the key set the builder

  and every reviewer who "verifies" the schema by reading the current builder
  source (the plan fact-checker, the smoke-fixture author) inherits the same
  schema drift — the consumer's hard assert then kills the run on the pod,
  after the provision is spent. RULE: (1) at plan/smoke time verify the
  artifact's OWN realized keys against every consumer assert — cheap even on
  a multi-GB bundle via `torch.load(path, map_location="cpu",
  mmap=True).keys()` (mmap never materializes tensor storages; requires the
  zipfile serialization that has been the `torch.save` default since torch
  1.6; `map_location="meta"` also round-trips on the lock-pinned torch 2.8.0

  deterministically regenerable → regenerate via the parent loader with
  fail-loud source/length asserts PLUS a deterministic re-capture alignment
  gate against the bundle's STORED tensors (row ALIGNMENT with the stored

  regenerated field is worse than the crash); (3) smoke fixtures default to

## 11. Decision Rationale

N/A — no training hyperparameters (doc-only change). The two technical claims the new prose makes, grounded:

- **(i) The key-read recipe.** Verified by execution on this VM (2026-07-06), torch `2.8.0+cu128` (uv.lock; pyproject pins `torch>=2.4,<3.0`), on a synthetic save-dict matching the pass_b bundle's shape (tensors + list[str] + dict metadata): `torch.load(p, map_location="cpu", mmap=True).keys()` → OK; `torch.load(p, map_location="meta")` → OK (meta-device tensors); default `weights_only=True` (torch ≥2.6) → OK on primitive metadata. The prose prescribes **mmap+cpu as primary** because it carries torch's documented guarantee that storages are memory-mapped rather than loaded ("the file should be mmaped rather than loading all the storages into memory"; requires the zipfile serialization, the `torch.save` default since torch 1.6 — the pass_b bundles are saved by current torch with defaults), whereas `map_location="meta"`, though execution-verified on 2.8.0, has no documented no-read guarantee across versions — so the entry names it as a verified alternative, not the primary. The definitive check (running the consumer's own loader on the real pinned artifact) is prescribed alongside, per the #1073 lesson itself.
- **(ii) The #1073 claim.** `scripts/issue779_collect.py:592` = `"prompts": [prompts[i] for i in kept_idx],` inside the pass-B save dict (read directly); the pinned-upload-lacks-it half is the #1073 failure-lesson record (`root_cause_confirmed: yes`, att-20260706-071820; bug-class tag `reused_artifact_schema_drift` on the sibling `epm:new-bug-class v1` marker).
