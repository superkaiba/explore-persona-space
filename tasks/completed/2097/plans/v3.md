# Plan — Issue #2097: Mechanize local-disk headroom for staging + VM fits

Kind: infra (workflow-fix; wf-fix tag). Origin: auto-filed workflow-fix candidate
(fingerprint 08572ce00252), plus the #2091 Phase-2 scope addendum (mount-binding arm).

## Requirement

Mechanize the prose-only local-disk headroom duty (CLAUDE.md compute-character
element 5: dispatch-time `df -P` + >=1.5x headroom for >=5 GB stages) in three legs:

1. **hub.py** — `stage_hub_prefix` self-sizes its download (server-side listed
   file sizes x factor) and asserts local-disk headroom at the DESTINATION mount
   via the existing `assert_out_root_headroom` (preflight.py:680) BEFORE any
   download; `stage_hub_file` gains an optional `size_bytes` arm for direct
   single-file callers.
2. **preflight.py** — a data-disk floor arm mirroring `_check_vm_root_floor`:
   fires only when `/mnt/eps-data` is a live mount, PERCENT-based (the watcher's
   size-invariant `EPM_VM_DATA_DISK_SUBFLOOR_PCT` convention — a GB floor breaks
   on resize), clean skip when the mount is absent (pods/GCE/SLURM unaffected).
3. **scripts/verify_plan.py** — the explicitly-deferred staging-row check
   (plan-compute-sizing.md L296 "no verify_plan.py backstop in v1 of this
   block"): new WARN-only check `c56_staging_mount_binding` with two arms —
   (a) a multi-GB staging/footprint row must name its mount/staging path;
   (b) the #2091 mount-binding arm: a plan citing the #681 worktree bind for a
   multi-GB stage must carry a `findmnt --mountpoint` liveness assertion (the
   bind is NOT live on this VM; #2091's plans v2 AND v3 cited it for a 42 GB
   stage and PASSed verify_plan).

### Acceptance criteria

- AC1: `stage_hub_prefix` raises (RuntimeError from `assert_out_root_headroom`)
  before downloading when projected missing-file bytes x factor exceed free
  space at the destination mount; an all-files-already-staged resume no-op
  never runs the assert; explicit env override exists and logs loud.
- AC2: preflight on the shared VM adds WARN/ERROR on data-disk used% past
  thresholds; clean skip (no rows) when `/mnt/eps-data` is absent or not a
  mount; override env degrades ERROR -> WARN (mirroring
  `EPM_PREFLIGHT_DISK_FLOOR_OVERRIDE`).
- AC3: verify_plan `c56` WARNs on an experiment plan whose prose carries a
  >=5 GB staging signal with no named mount/staging path IN the trigger
  window (a `/workspace` in distant boilerplate does not satisfy); WARNs on
  a worktree-bind-citing multi-GB stage lacking a `findmnt` assertion —
  CALIBRATION BAR: the composed check, run against the committed #2091
  plans/v3.md, yields >= 1 arm-(b) trigger line and a WARN; PASSes on a
  standalone `N/A — no multi-GB staging` line; SKIPs for
  kind != experiment. Never FAILs (c39/c31/c34/c43 family convention).
- AC4: tests pin all three legs; ruff clean on touched files; no regression to
  the #1979/#1947 EBADF probe hardening or the #1852 user-writable probe-dir
  fix (`_probe_writable_bytes` untouched).

Fail-loud pin: tests/test_hub_stage_headroom.py — the low-headroom refusal is pinned with pytest.raises(RuntimeError) (never a silent skip or swallowed except; the env kill switch logs a warning instead of silently bypassing).
- AC5: documenting surfaces reconciled — the plan-compute-sizing.md deferral
  line(s) this fix resolves are updated to name c56; the verify_plan.py header
  check table gains the c56 row.

## Method delta

The mechanized helper already exists (`assert_out_root_headroom`: statvfs +
1 GB fallocate canary at the mount the path RESOLVES to) but is opt-in with 27
per-issue callers. Delta: wire it into the canonical staging path (default-ON),
add the missing preflight surface for the data disk, and land the deferred
plan-side WARN. Routing gates (RSS >= ~16 GB, footprint > 50 GB) are DELIBERATELY
untouched — projection-based by design; this fix mechanizes runtime/plan-time
duties without changing routing semantics.

## Concrete diffs

### (1) `src/explore_persona_space/orchestrate/hub.py`

- New `list_hf_entries_under_path(api, repo_id, path, *, repo_type, revision)
  -> list[tuple[str, int | None]]`: same scoped-tree-walk + exact-file-fallback
  + absent->[] semantics as `list_hf_files_under_path`, but preserves
  `(path, size)` from the RepoFile entries (size None when unavailable).
  `list_hf_files_under_path` delegates to it — behavior byte-identical
  (returns the path component). ONE listing serves both paths and sizes (no
  extra network call in `stage_hub_prefix`). Accepted residual (deliberate,
  do not scope-creep): a single large file staged via the exact-file
  `file_exists` fallback carries size None -> the 1.5 GB floor only; fail
  direction is status quo (no refusal), and a `get_paths_info` size fetch on
  that branch is a possible later tightening, NOT in this diff.
- `stage_hub_prefix`: after the listing, before the download pool:
  - `missing = [(f, sz) for f, sz in entries if not (dest_dir / f).exists()]`
    (skip-existing resume no-ops never assert — AC1).
  - If `missing` and not disabled: `need_gb = max(total_known_bytes, 1e9 * MIN_FLOOR) * factor / 1e9`
    where `factor` = `EPM_HF_STAGE_HEADROOM_FACTOR` (default 1.5; garbled /
    non-positive env value falls back to the default with a logged warning —
    mirroring the leg-2 env-resolver convention) and
    MIN_FLOOR = 1.0 GB. The unknown-size degrade warning fires on ANY None
    size among the missing files (n_unknown/n_missing named in the message),
    not only when every size is None — a mixed known+None listing silently
    under-sizes `need_gb` otherwise (the #541 partial-None shape; fail
    direction is status quo, but the degrade must be visible). Then
    `assert_out_root_headroom(dest_dir, need_gb, phase="hub-staging")`.
  - Kill switch `EPM_HF_STAGE_HEADROOM_SKIP=1` — logs a loud warning
    ("headroom assert SKIPPED by env"), never a silent skip.
  - ONE prefix-level assert only (never per-file — the helper's canary is a
    1 GB fallocate; N per-file asserts would fallocate N GB).
  - Docstring note (MooseFS caveat): on RunPod `/workspace` statvfs shows
    share-level free and is blind to the per-pod ~130 GB quota below
    exhaustion; the helper's fallocate canary catches only an
    ALREADY-exhausted quota — a statvfs pass is not quota headroom.
  - The existing entry print gains the projected-bytes figure.
- `stage_hub_file`: optional `size_bytes: int | None = None` kwarg — when
  provided and the target is absent (and not env-skipped), assert headroom at
  `target.parent` with `need_gb = size_bytes * factor / 1e9` (same MIN_FLOOR).
  Default None keeps every existing caller byte-identical.
  `stage_hub_prefix` does NOT thread per-file sizes (prefix-level assert
  covers it).

### (2) `src/explore_persona_space/orchestrate/preflight.py`

- Constants + env resolvers (mirroring the `_vm_root_disk_floor_gb` pattern):
  `EPS_DATA_DISK_MOUNT = "/mnt/eps-data"`,
  `DATA_DISK_WARN_USED_PCT_DEFAULT = 90.0`
  (env `EPM_PREFLIGHT_DATA_DISK_WARN_PCT`),
  `DATA_DISK_ERR_USED_PCT_DEFAULT = 98.0`
  (env `EPM_PREFLIGHT_DATA_DISK_ERR_PCT`),
  override `EPM_PREFLIGHT_DATA_DISK_OVERRIDE=1` (ERROR -> WARN).
  Threshold rationale: WARN 90 sits above the watcher's 85% escalate-only
  subfloor (its push remains the early channel); ERROR 98 = effectively full —
  fail-fast without wedging the fleet at today's ~96% baseline. Garbled /
  non-positive / >100 env values fall back to defaults; never raises.
- `_check_data_disk_floor(report)`: skip cleanly unless
  `os.path.ismount(EPS_DATA_DISK_MOUNT)` (self-scoping — pods/GCE/SLURM lack
  the mount; no is_runpod/is_cluster branching needed); compute used% from
  `os.statvfs` (`1 - f_bavail/f_blocks`, percent-based); ERROR at
  >= err-threshold unless override (then WARN); WARN at >= warn-threshold.
  Messages name the reclaim levers (`vm_disk_guard.py --apply`,
  `clean_experiment_downloads.py <N> --apply`) + the override env.
  New optional report field `data_disk_used_pct: float | None = None`
  (additive; JSON contract grows one key).
- Wire: call `_check_data_disk_floor(report)` in the main preflight run
  immediately after `check_disk_space(...)` (unconditional call; the function
  self-skips off-VM).
