# Plan — #1217: mechanical guard arm for the real-world-corpus digest-only read rule

## 0.0 TL;DR (plain English)

- **What I'll do:** extend the existing bank-read guard hook with a second, looser deny class — "corpus text" (any `raw_completions` tree, plus paths carrying real-world-corpus name tokens) — that blocks only *wholesale* paging of these files into context, while keeping every sanctioned excerpt route open (bounded Read with an explicit window, grep-family pulls, jq field access, all pipeline consumption).

- **What would change my mind:** if the pre-ship replay of ≥100 historical corpus-touching commands denies any sanctioned excerpt/digest shape, or overall deny rate exceeds 5%, I narrow the arm (Read-arm-only fallback) or recommend no-change (candidate D). ### 4.2 Recommended design (A′) — exact shape

**One new path class, weaker rules than banks.** New constants near :98–104:

```
RAWC_RE       — '(^|/)raw_completions(/|\.[A-Za-z0-9]+$|$)'   # dir component OR file named raw_completions.<ext>
CORPUS_TOK_RE — '(lmsys|wildchat|sharegpt|chatbot[-_]?arena)' # matched case-insensitively
CORPUS_WINDOW — 200      # lines; = guard_log_dump.sh MAX_LINES
CORPUS_BYTES  — 262144   # = guard_log_dump.sh MAX_BYTES
is_corpus_path() — quote-strip; match RAWC_RE (case-sensitive) or CORPUS_TOK_RE (grep -qiE) against the path/token
```

**Read arm** (insert into :148–153 block, after the bank check): if `is_corpus_path "$fp"`: extract `.tool_input.limit` (jq, `// empty`, fail-open on error); numeric limit `1..200` → allow; otherwise `stat -c %s` the file — stat failure (nonexistent) → allow (fail-open; Read will error anyway); size ≤ 262,144 → allow; else **deny** with a remediation message naming the three sanctioned routes (bounded Read with explicit offset+limit; grep-family excerpt pulls; jq digests/field access). Non-numeric limit is treated as absent (extra-deny direction, documented).

**Grep tool arm:** unchanged. Content-mode Grep on corpus paths is the sanctioned excerpt puller (default head_limit 250 bounds it). Header comment documents this deliberately.

**Bash/ssh arm** (token walk :229–392): second class detection in the token loop — `corpus=""` set when a token matches `is_corpus_path`; walk proceeds if `bank` OR `corpus` found. Class precedence: bank rules win where both appear. For corpus-only commands:
- **Paging verbs** (:303–305): deny on the existing `DENY_VERBS_RE` list **minus head/tail** — head/tail stay allowed for corpus (delegated: `guard_log_dump.sh` already bounds them at MAX_LINES on dump-sized files for the unpiped case; piped/small-file residual accepted, §4.4). Banks keep the full list.
- **Bare diff outside git** (:310–312): deny (whole-file print), both classes.
- **grep-family line-output machinery** (:314–319, :341–352, :386–389): **skipped entirely for corpus-only** — line output IS the sanctioned excerpt shape.
- **jq** (:255–262): corpus-only variant denies only a filter that is exactly `.` or exactly `.[]` after quote-strip (the two canonical whole-dumps); all field access / digests allowed. Banks keep `JQ_DIGEST_RE`.
- **git show/diff/log -p** (:245–253): deny paging on both classes (digest forms `--stat`/`--name-only`/`--oneline` etc. allowed, machinery reused as-is).
- **task.py --file/--body-file** (:368–383): deny on both classes (embedding corpus text into task state defeats the rule with delay).
- **Fast path** (:204): add a second cheap gate — if the bank stem grep misses, `grep -qiE` for `raw_completions|<CORPUS_TOK_RE>`; both miss → exit 0. One extra grep per Bash call, in-family cost.

**Escape hatch:** the existing `EPM_ALLOW_BANK_READ=1` check (:106–108, :175) precedes all arms and therefore covers both classes unchanged. No second env var (considered, rejected: doubles the inline-prefix surface for zero added control; the hatch is already documented in clause (d)). Header documents that the legacy name covers both classes.

**Sidecar log:** same file; corpus-class deny reasons carry a `corpus:` prefix in `$1` so FP counting splits classes (`grep -c 'corpus:'`).

**Fail-open:** every new jq/stat extraction follows the existing `|| exit 0` pattern; a parse failure anywhere allows.

**Deny messages:** class-specific, name the allowed retry routes, cite clause (d) + #1073, never print the override string (parity with `test_deny_message_does_not_print_override`).

## 11. Decision Rationale (load-bearing design constants)

1. **Read window = 200 lines.** Why: the bounded-excerpt allowance needs a cap. Source: `guard_log_dump.sh:42` (`MAX_LINES=200`) — in-family precedent; the stricter ~120-line window in trigger-dense-review.md discipline 3 remains the *advisory* norm, the mechanical cap is deliberately the looser fleet constant.
2. **Size gate = 262,144 B.** Why: exempt small files (metadata/summaries inside corpus trees) from Read-arm denies; volume is the kill-risk driver. Source: `guard_log_dump.sh:41` (`MAX_BYTES`), the fleet's existing "dump-sized" definition; distribution check: 380/663 live raw-completions files exceed it (measured 2026-07-17).
3. **`RAWC_RE` includes the filename form `raw_completions.<ext>`.** Why: the *largest live corpus-class file* (3.04 MB, `eval_results/issue260/lc_long/raw_completions.json`) is a file by that name, not a dir member — a dir-component-only regex misses it. Source: measured enumeration this session (§2).
4. **`CORPUS_TOK_RE` = lmsys|wildchat|sharegpt|chatbot[-_]?arena, case-insensitive.** Why: catches HF snapshot layouts and staged files the structural predicate misses. Source: CLAUDE.md clause (d) names the LMSYS/WildChat class (repo-grounded: `lmsys_g_labels.json`, `wildchat_prefix.json`, `lmsys5k` in `issue_1336/common.py:281`); sharegpt/chatbot_arena are precautionary siblings — `Source: ungrounded — needs smoke-test` (no repo usage yet; zero-FP-cost inclusion, drop freely if the critic objects).
5. **head/tail exempted from the corpus Bash deny list.** Why: the top predicted FP shape; `guard_log_dump.sh` already bounds them (MAX_LINES on dump-sized files, unpiped) — avoids duplicating its option-parsing machinery. Source: `guard_log_dump.sh` header + :42–47; residual (piped/small-file) documented §4.4.
6. **grep-family line output allowed for corpus (skipped machinery).** Why: it IS clause (d)'s sanctioned excerpt shape ("grep + line offset"). Source: CLAUDE.md:147 clause (d); brief's verified carve-out.
7. **jq whole-dump-only denial (`.`, `.[]`).** Why: the obvious next verb after a denied page; field access must stay open (excerpts sanctioned). Deny-list minimalism over filter parsing. Source: design judgment anchored on the #1073 laundering path; `ungrounded — needs smoke-test` for the exact two-filter list (replay + sidecar will validate).
8. **Whole-command deny co-occurrence, no clause split.** Why/Source: inherited unchanged from #965 §11.3 (a clause splitter fails open on quoted pipes).
9. **Single escape hatch (legacy name).** Why: the hatch check precedes all arms; a second var doubles surface for no control gain. Source: #965 hatch design; documented in header + clause (d).
