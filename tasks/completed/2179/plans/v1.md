## 1. Requirement + acceptance criteria

**Requirement.** The shared §9 `planned_wall_h` parser must never contribute a range cell's LOWER bound to the ETA fence budget, must handle calendar-latency bound cells without disabling the tripwire, and the authoring convention must be documented and drift-pinned against the parser.

**Design decision — upper-bound parsing, NOT skip-the-row and NOT raise.** The task body proposed skipping calendar rows or raising on ranges; both are rejected on measured grounds:

- The tripwire budget is a run-level + per-phase FENCE (`ETA_DEVIATION_MULT=2.0 ×` total §9 wall; `poll_pipeline._eta_deviation_update`). A Batch-API judge phase genuinely elapses up to its SLA (2–24 h calendar) inside the run's wall-clock, so SKIPPING its row understates the fence and false-fires on healthy batch-waiting runs — exactly the #763 false-positive class, and a direct violation of the module's own AC #2 invariant ("never a partial sum: an under-parsed budget is the one path to a tripwire false positive").
- RAISING on ranges would disable the tripwire fleet-wide: the corpus scan (2026-08-18, all `tasks/*/*/plans/v*.md`) found **468 range-shaped cells across 992 plans with wall tables** (6,757 located cells). Ranges are the dominant §9 idiom for uncertain phases; a raise turns defect 2 back into defect 1 at fleet scale.
- UPPER-bound parsing is monotone-conservative for a fence: every changed value only ever INCREASES a budget (tripwire fires later, never spuriously), keeps all 468 range cells armed, and matches what `≤X` already does (parses as X — the deliberate, test-pinned #2172 behavior for `≤24 (SLA)`).
- `≥X` / `>X` states a lower bound with NO derivable fence contribution → loud reject (unparseable → whole-budget disable, the existing AC #2 path). Corpus scan: **0 live `≥`/`>` cells** — zero blast radius.

**Acceptance criteria:**

- AC1 (range = upper bound): `parse_wall_cell` returns the MAX of the two endpoints for a leading range `A–B` (en-dash, ASCII hyphen, em-dash, optional surrounding spaces, decimal endpoints incl. `.5` forms) after any cosmetic prefix. Fixtures: `2–24 calendar` → 24.0, `1.5-2` → 2.0, `≈3.6–3.8` → 3.8, `.5–2` → 2.0, `2 – 24` → 24.0, `4–8 (free-tier worst 18)` → 8.0 (trailing prose ignored, NOT scanned for more numbers), `24–2` → 24.0 (max, robust to author order).
- AC2 (bound cells): `≤24 calendar` → 24.0 and `<0.1` → 0.1 (unchanged #2172 behavior, now documented as the calendar-latency convention); `≥2` → None, `>2` → None (NEW loud-reject: a `>`/`≥` anywhere in the cosmetic prefix run before the first digit rejects the cell).
- AC3 (fail-safe preserved): a genuinely malformed cell (`TBD`, `n=800 rows`, letter-prefixed garbage) still disables the WHOLE budget with `reason="unparseable_cell"` — the #2172 AC #2 never-a-partial-sum invariant is untouched. All-numeric tables still sum. The full existing REJECT fixture class stays rejected.
- AC4 (corpus monotone invariant): over every located cell in the persisted-plan corpus (`tasks/*/*/plans/v*.md`), (i) every cell the pre-#2179 rule parsed still parses (no NEW disables anywhere), and (ii) `new_value >= old_value` for every cell (upper-bound is monotone). Implemented as a corpus-scan test mirroring `tests/test_verify_plan.py`'s persisted-plan scan pattern (skip gracefully when the corpus is absent in a sparse worktree).
- AC5 (doc↔parser drift pin): `.claude/rules/plan-compute-sizing.md` gains a `### §9 planned_wall_h cell grammar` block containing a machine-readable example table (`cell | parses as` rows, with `disabled` for reject rows); a new test extracts that table from the rule file and asserts `parse_wall_cell` agrees row-by-row. The doc names: bare float = hours; `≤X`/`<X` → X; `A–B` → B (upper bound; fence semantics); calendar-latency phases (Batch-API SLA) write `≤24 calendar` / `2–24 calendar` (the `calendar` token is human documentation — the parser contributes the upper bound because the run genuinely elapses that wall); `≥X` / TBD / prose → unparseable → tripwire disables LOUDLY for the whole run.
- AC6 (disable-note remedy): `poll_pipeline._eta_disabled_note`'s remedy line extends to name the grammar ("write a bare float, a `≤X` bound, or an `A–B` range (upper bound is used); put conditionality in the `basis` cell").
- AC7 (behavior-preservation test updated deliberately): `tests/test_plan_wall_budget.py::test_old_rule_values_preserved` gains a range-cell exemption (cells matching the range grammar are the #2179 deliberate deviation from the old leading-float value; predicate exported from the module, not duplicated in the test). The two existing range ACCEPT fixtures move to their upper-bound values with a `# 2179` comment.
