## Exact changes

### Edit 1 — slow-canary discriminator, appended to the MooseFS FUSE READ-wedge entry

Anchor: the bullet containing the substring `MooseFS FUSE READ-wedge` (currently gotchas.md line 65; full opener: "**MooseFS FUSE READ-wedge on the pod `/workspace` `.venv` — the silent launch hang (zero stderr).**"). Insert BEFORE the final `Runbook:` sentence of that bullet:

> SLOW-CANARY false positive (#2333): preflight's 1 GB `posix_fallocate` disk canary on MooseFS FUSE (no fallocate support) can grind ~9 min in glibc's per-block write emulation before completing rc=0 — slow, not wedged. The grinding thread shows the same `wchan=request_wait_answer` as the wedge, so discriminate by MECHANISM, not wchan: a grinding canary means the mount is still ANSWERING FUSE requests — spot reads/writes/statfs on `/workspace` return promptly, and the preflight process holds no data fds beyond its one probe file — whereas a wedged mount hangs those spot probes too (the timeout-bounded import probe above stays the confirming read). Disposition: wait it out (poll the preflight done file / process exit); escalate to the wedge runbook only if a spot probe hangs or the grind runs well past ~2× the observed ~9 min.

Rationale for placement: the read-wedge entry is exactly where a session lands when it sees `wchan=request_wait_answer`; the discriminator must live at the point of misrouting. The entry's existing DISCRIMINATE probe (timeout-bounded import) stays valid — the new text adds the mechanism-based spot-I/O tell that separates canary-slowness from a wedged mount, plus an explicit escalation bound so it cannot license indefinite waits.

### Edit 2 — resumed-pod `uv sync` flash-attn note, appended to the venv-rebuild entry's Trap-3 flash-attn sentence
