# Plan — #987: dispatch/poll entrypoints self-pin lane infra (backends/) to the MAIN checkout

**Estimated GPU-hours (total): 0**

## 0. Plan Summary

**Change:** `scripts/dispatch_issue.py` + `scripts/backend_poll.py` gain a
module-top bootstrap (guarded by `__name__ == "__main__"`) that resolves the
MAIN checkout root cwd-independently via `git rev-parse --path-format=absolute
--git-common-dir` anchored at the script file's own directory (the exact #612
recipe already living in `backends/issue_dispatch.py::_main_checkout_root`),
then inserts `<main>/src` and `<main>` at the FRONT of `sys.path` BEFORE any
`explore_persona_space` import. Result: the lane infra (the `backends/`
package, incl. the GCE startup template in `gcp.py`) always imports from
main's `src/`, beating the worktree venv's editable install — while
`--repo-branch issue-<N>` keeps cloning the issue branch for the WORKLOAD
(remote-side clone; unchanged). Fail-loud: an unresolvable main root raises
`RuntimeError` (no silent fallback to the ambient, possibly-stale package).
**Mechanism (a) sys.path pinning**, empirically verified (§10 probes 1–3).
**Not architectural** (§11). New pinning test + existing router/poll/gcp
suites + workflow_lint + ruff gate it. `### TDD: no`.

## 1. Goal + requirement + acceptance criteria

**Goal (task frontmatter):** make dispatch source lane infra (`backends/`)
from main while cloning `--repo-branch` for the workload only.

**Requirement.** A `dispatch_issue.py launch` / `backend_poll.py` tick invoked
from ANY cwd (repo root, an issue worktree, `/tmp`) must import
`explore_persona_space.backends.*` from `<main-checkout>/src/`, so a worktree
cut before a lane-infra fix (e.g. #935's GCE done-grace self-poweroff) can
never launch/poll with the pre-fix lane template. The workload itself keeps
running the issue branch (the `--repo-branch` remote clone is untouched).

**Acceptance criteria:**
1. From a worktree cwd, `uv run python <main>/scripts/dispatch_issue.py` and
   `... backend_poll.py` resolve `explore_persona_space.backends.gcp.__file__`
   under `<main>/src/` (new test pins this; §6).
2. If the main root cannot be resolved (no git / not a checkout / shape-check
   fail), the script exits non-zero with a `RuntimeError` naming the failure —
   never proceeds on the ambient package.
3. Importing the scripts as modules (`from scripts.backend_poll import ...`,
   the test-suite path) does NOT apply the pin — worktree test runs keep
   testing branch code.
4. `uv run pytest tests/test_router.py tests/test_backend_poll.py
   tests/test_gcp_backend.py tests/test_lane_infra_main_pin.py` pass;
   `uv run python scripts/workflow_lint.py` (no-flags default, includes
   `--check-asks` scope) passes; ruff clean on touched files.

## 4. Design

**Chosen mechanism: (a) sys.path pinning.** (b) re-exec via
`uv run --project <main>` adds a process-replacement seam, an infinite-loop
guard, and an env-var contract for ~zero extra coverage over (a) (probe 2
shows the path pin alone beats the editable install); (c) doc-only already

### 4.1 The bootstrap (both files, duplicated by design)

In `scripts/dispatch_issue.py` and `scripts/backend_poll.py`, immediately
after the existing `_REPO_ROOT` bootstrap (which stays byte-unchanged), add
two module-level functions + one guarded call:

```python
def _resolve_main_checkout_root(anchor: Path) -> Path:
    """MAIN repo-checkout root, resolved cwd-independently from ``anchor``.

    Mirrors backends/issue_dispatch._main_checkout_root (#612) WITHOUT
    importing it — importing the package before the pin would cache the
    ambient (possibly stale worktree) package in sys.modules, defeating
    the pin (#987). Fails LOUD; never a cwd fallback.
    """
    env = {k: v for k, v in os.environ.items()
           if k not in {"GIT_DIR", "GIT_WORK_TREE", "GIT_INDEX_FILE",
                        "GIT_OBJECT_DIRECTORY"}}
    try:
        proc = subprocess.run(
            ["git", "rev-parse", "--path-format=absolute", "--git-common-dir"],
            cwd=str(anchor), env=env, capture_output=True, text=True,
            encoding="utf-8", errors="replace", check=True, timeout=30)
    except (OSError, subprocess.SubprocessError) as exc:
        raise RuntimeError(
            f"cannot resolve the MAIN checkout root from {anchor} "
            f"(git rev-parse --git-common-dir failed: {exc}); lane infra "
            f"must import from main (#987) — refusing the ambient package") from exc
    common_dir = Path(proc.stdout.strip())
    if common_dir.name != ".git" or not common_dir.is_dir():
        raise RuntimeError(
            f"git common-dir {common_dir!s} does not look like a "
            f"main-checkout .git dir; refusing to pin lane infra (#987)")
    root = common_dir.parent
    if not (root / "src" / "explore_persona_space" / "__init__.py").is_file():
        raise RuntimeError(
            f"resolved main root {root!s} has no src/explore_persona_space; "
            f"refusing to pin lane infra (#987)")
    return root


def _pin_main_lane_infra(anchor: Path | None = None) -> Path:
    """Insert <main>/src + <main> at the FRONT of sys.path (#987). ..."""
    anchor = anchor or Path(__file__).resolve().parent
    main_root = _resolve_main_checkout_root(anchor)
    already = sys.modules.get("explore_persona_space")
    if already is not None:
        mod_file = getattr(already, "__file__", "") or ""
        if not mod_file.startswith(str(main_root / "src") + os.sep):
            raise RuntimeError(
                f"explore_persona_space already imported from {mod_file!r} "
                f"before the main-checkout pin — a submodule import would "
                f"resolve under the stale package __path__ (#987)")
    for p in (str(main_root), str(main_root / "src")):
        if p in sys.path:
            sys.path.remove(p)
        sys.path.insert(0, p)  # final order: [<main>/src, <main>, ...]
    invoked_root = Path(__file__).resolve().parents[1]
    if invoked_root != main_root:
        sys.stderr.write(
            f"[lane-infra-pin] WARNING: invoked script copy lives under "
            f"{invoked_root} but lane infra is pinned to main {main_root} "
            f"(#987); prefer invoking <main>/scripts/{Path(__file__).name}\n")
    return main_root


if __name__ == "__main__":
    _pin_main_lane_infra()
```

Load-bearing details:
- **`__name__ == "__main__"` guard** scopes the pin to production script
  invocation (incl. `python -m`). Test-suite imports (`import
  scripts.backend_poll`) skip it, so worktree pytest runs keep testing branch
  code — a mandatory property (an unconditional pin would make every worktree
  test run silently test MAIN's package; §7 risk 4).
- **The WARN, not stdout:** `backend_poll.py`'s contract is ONE JSON line on
  stdout — the mismatch warning goes to stderr, never stdout.
- **Both lazy-import files:** every `explore_persona_space` import in both
  scripts is function-local (verified: dispatch_issue.py lines 260+;
  backend_poll.py lines 199+), so a module-top pin strictly precedes all of
  them. The `sys.modules` guard is a defensive backstop, inert on the script
  path.
- **`scripts.*` also pins to main:** inserting `<main>` ahead of the existing
  `_REPO_ROOT` entry makes main's `runpod.py` lazy `from scripts.poll_pipeline
  import ...` resolve main's copy too — lane infra is main end-to-end even
  when a worktree COPY of the entrypoint script was invoked.
- **Idempotent:** re-entrant calls remove-then-insert, no duplicates.

## 5. Controls — version-skew seam analysis

NEWER than the invoking branch's expectations. Seams:

1. **Handle sidecar (write ↔ read).** Writer = launch-time
   `issue_dispatch.serialize_handle` (now always main's), reader = poll-time
   `backend_poll` + main's `issue_dispatch` (now always main's). Both ends on
   one version ⇒ intra-run schema skew VANISHES (today they can differ).
   Mixed window: sidecars already on disk written by a stale package pre-fix
   — read tolerance is unchanged from today's status quo (main's reader has
   always had to read sidecars written by older mains across rolling
   updates; the #612 back-compat probe in backend_poll's docstring is
   evidence of the standing tolerance posture). No new risk; strictly fewer
   mixed-version pairs.
2. **Which script COPY do callers invoke?** SKILL.md line 2996 mandates the
   repo-root (= main) copy; grep of `.claude/skills` + `agents` shows every
   documented invocation is `uv run python scripts/dispatch_issue.py ...`
   composed from the repo root ("$REPO_ROOT"/scripts per Step 0 prose). The
   residual case — a worktree COPY invoked from a worktree cwd — now pins
   lane infra to main anyway (the git anchor maps worktree→main), leaving
   only the thin CLI layer (argv parsing) on the branch version; a signature
   drift between a stale CLI body and main's package raises a loud
   `TypeError` at launch (fail-fast) instead of silently launching a stale
   template, and the stderr WARN names the copy mismatch. This is the
   deliberate trade (§11).
3. **Workload clone.** `--repo-branch` threads a branch NAME into the
   rendered GCE startup script / RunPod bootstrap; the clone happens ON the
   remote instance at boot. Nothing under `src/explore_persona_space/
   backends/` imports from the cloned workload tree (the render functions
   emit shell text; verified by reading `gcp.render_startup_script`'s
   clone-in-startup-script shape and by the absence of any local
   clone-then-import in `backends/`). The branch-code-for-workload contract
   is untouched.
4. **Third-party deps.** The interpreter + site-packages still come from the
   invoking cwd's uv env (probe 1/2: the worktree venv stays active; only
   first-party resolution is pinned). Main's `backends/` requiring a NEWER
   third-party dep than a stale worktree venv holds → loud
   ImportError/AttributeError (rare; backends' dep surface is
   requests/huggingface_hub/stdlib, slow-churn). The repo-root invocation
   rule (unchanged, §4.3) uses main's venv and has zero such skew.

## 11. Decision Rationale

No training hyperparameters exist: `N/A — no training hyperparameters`.

- **Mechanism (a) sys.path pin — over (b) re-exec, (c) doc-only.**
  What: front-of-path insert of `<main>/src` + `<main>` at script entry.
  Why: probe 2 proves it fully redirects package resolution with ~5 lines of
  runtime behavior; no process replacement, no loop guard, no env contract.
  (b) re-exec via `uv run --project <main>` would ALSO switch third-party
  deps to main's venv (marginal benefit) at the cost of an execv seam, an
  infinite-recursion guard, and harder testing; (c) is the failed status quo
  (SKILL.md's repo-root prose predates #935's zombie). Source: probes 1–3;
  #612 precedent. Alternatives considered above.
- **Anchor = script file's dir + git-common-dir — over `Path(__file__)
  .parents[1]` alone.** Why: `parents[1]` is correct only when the MAIN copy
  of the script is invoked; the git recipe additionally maps a worktree COPY
  invocation to main (seam 2) and is the #612/#506-blessed recipe. Source:
  probe 3; `issue_dispatch._main_checkout_root`.
- **Duplicate the resolver into both scripts — over importing
  `issue_dispatch._main_checkout_root` or a shared `scripts/` helper.**
  Why: importing the package before the pin caches the ambient (stale)
  package (assumption 6) — self-defeating; a shared `scripts/_helper.py`
  resolves to the WORKTREE copy under worktree-copy invocation (absent on
  pre-fix branches). Both files already duplicate their #571 bootstraps with
  mirrored comments; test 7 pins the sync. Source: code reading (§2).
- **`__main__`-guarded — over unconditional.** Why: unconditional would make
  worktree pytest runs test MAIN's package (silent, wrong); the guard scopes
  the pin to production invocation exactly. Source: test-suite import shape
  (tests import these modules directly).
- **Fail-loud RuntimeError — over warn-and-continue.** Why: hard constraint
  (task body; CLAUDE.md fail-fast); a silent fallback re-creates the very
  stale-template launch this task closes. Source: #612's identical contract.
- **WARN (not refuse) on worktree-copy invocation.** Why: the pin already
  makes that shape source main lane infra; refusing would break a
  today-working invocation for a thin residual (branch CLI body), which
