### 3.2 New `_retry_after_seconds` + budget helpers (insert immediately above `_retry_upload`, line 576)

```python
_RETRY_AFTER_CAP_S = 900.0  # defensive cap on a pathological server header

def _retry_after_seconds(err: Exception) -> float | None:
    """Seconds from a Retry-After header on the error's response, if any.
    Seconds-form only (an RFC 9110 HTTP-date value parses to None -> caller
    falls back to exp backoff). Mirrors llm/api_dispatch._retry_after_seconds."""
    headers = getattr(getattr(err, "response", None), "headers", None)
    if headers is None:
        return None
    try:
        raw = headers.get("Retry-After")   # requests' CaseInsensitiveDict
    except Exception:
        return None
    if raw is None:
        return None
    try:
        val = float(raw)
    except (TypeError, ValueError):
        return None
    return val if val > 0 else None

def _retry_budget_s() -> float:
    """Wall-clock transient-retry budget (s). 0 disables the budget extension
    (legacy attempt-bound behavior). Env: EPM_HF_RETRY_BUDGET_S (default 1800)."""
    raw = os.environ.get("EPM_HF_RETRY_BUDGET_S")
    if raw is None or not raw.strip():
        return 1800.0
    try:
        return max(0.0, float(raw))
    except ValueError:
        logger.warning("EPM_HF_RETRY_BUDGET_S=%r unparseable; using 1800", raw)
        return 1800.0
```

### 3.3 `_retry_upload` — dual-bound retry (rewrite of lines 576-602)

```python
def _retry_upload(fn, *, what: str, max_attempts: int = 6, budget_s: float | None = None):
    """Call ``fn()`` (a zero-arg thunk) with retry on transient HF
    5xx/429/timeout/connection errors. Name is legacy — generic transient-retry
    wrapper, also used for READS (list_repo_files_complete) and downloads.

    Retry is allowed while EITHER bound holds (raise only when BOTH exhaust):
      - attempt floor: the first ``max_attempts`` calls (the #735 contract);
      - wall-clock budget ``budget_s`` (default env EPM_HF_RETRY_BUDGET_S=1800):
        sized to outlive an org-wide 429 storm — #931's storm outlived the
        pre-#997 310 s attempt-bound stack. budget 0 => legacy attempt-bound.
    Sleep: Retry-After header when present (capped _RETRY_AFTER_CAP_S), else
    exp backoff min(180, 10*2^k) with 0-25% jitter (de-synchronizes fleet
    retries). Storage-quota-403 / non-transient re-raise IMMEDIATELY; on
    exhaustion the final exception propagates (fail-loud, no swallow).
    """
    budget = _retry_budget_s() if budget_s is None else budget_s
    start = time.monotonic()
    deadline = start + budget
    attempt = 0
    while True:
        attempt += 1
        try:
            return fn()
        except Exception as e:
            if _is_storage_quota_403(e) or not _is_transient_upload_error(e):
                raise
            ra = _retry_after_seconds(e)
            if ra is not None:
                sleep_s = min(ra, _RETRY_AFTER_CAP_S)
            else:
                sleep_s = min(180.0, 10.0 * 2.0 ** min(attempt - 1, 6)) * (1.0 + random.random() * 0.25)
            now = time.monotonic()
            within_attempts = attempt < max_attempts
            within_budget = budget > 0 and now < deadline
            if not (within_attempts or within_budget):
                raise
            if budget > 0:
                # CRITIC ROUND-1 MUST-FIX (Methodology + Statistics Claude +
                # Statistics Codex, convergent): clamp EVERY sleep — both the
                # Retry-After branch and the backoff branch, including
                # attempt-floor retries — to the remaining budget, so the
                # attempt floor can never stack un-clamped Retry-After sleeps
                # past the deadline (pathological Retry-After: 4000 → 900-cap
                # × 5 floor attempts ≈ 4500 s > 1800 s budget). With the clamp,
                # TOTAL SLEEP ≤ budget; floor attempts after the deadline
                # sleep 0 and retry immediately (≤ max_attempts calls total —
                # the #735 6-call contract holds; legacy tests assert sleep
                # COUNTS, never durations, so clamping is contract-safe).
                sleep_s = min(sleep_s, max(0.0, deadline - now))
            logger.warning(
                "%s transient error (attempt %d, elapsed %.0fs / budget %.0fs): %s; retrying in %.0fs",
                what, attempt, time.monotonic() - start, budget, str(e)[:200], sleep_s,
            )
            time.sleep(sleep_s)
```

**Bound convention (states the invariant the tests pin):** with `budget > 0`,
no sleep starts or extends past `deadline` and TOTAL SLEEP ≤ `budget`; retry
is permitted while `attempt < max_attempts` OR `now < deadline` (raise only
when both bounds are exhausted). Elapsed wall time can exceed the budget only
by IN-FLIGHT call durations (each `fn()` — including huggingface_hub's inner
pagination retries, up to ~143 s — runs to completion before the deadline
check; the fake-clock tests use zero-duration fake calls, so they assert
`elapsed ≤ budget` exactly). With `budget_s=0` the clamp is skipped and the
legacy attempt-bound contract is byte-compatible.

Notes: `import random` added to module imports (together with its first use, one edit — the PostToolUse-ruff F401 rule). The `min(attempt-1, 6)` exponent clamp keeps the arithmetic bounded on long storm loops. Wall-clock bounding naturally charges huggingface_hub's own inner pagination retries (up to ~143 s per outer attempt) against the budget, because the deadline is monotonic — the pre-fix attempt-bound could not account for that. Fail-fast discipline preserved: quota-403 + non-transient re-raise on attempt 1; exhaustion re-raises the real exception; nothing is swallowed; every retry logs a WARNING (which also keeps the poller's log-liveness stall detector fed during a long storm).

```python
def verify_repo_paths_uploaded(
    api,
    repo_id: str,
    expected_repo_paths: Sequence[str],
    *,
    path_in_repo: str,
    repo_type: str = "dataset",
    revision: str | None = None,
) -> list[str]:
    """Exact-set post-upload verify: return expected paths NOT on the Hub.

    Canonical retried + server-side-SCOPED verify leg for dispatch scripts.
    #920: a bare full-repo `list_repo_files` on the ~1M-file data repo wedges
    >600 s (#833 gotcha) AND a transient 500 on it crashed a workload after
    every upload had succeeded. Routes through list_repo_files_complete with
    path_in_repo scoping — the paginated walk rides _retry_upload
    (Retry-After-aware, wall-clock-budgeted).

    path_in_repo is a REQUIRED non-empty directory-like prefix covering every
    expected path (ValueError otherwise — an unscoped verify recreates the
    wedge). A prefix absent on the repo (EntryNotFoundError during the walk)
    returns ALL expected paths as missing (caller's fail-loud fires with the
    full list). Transport/auth errors propagate after the retry budget.
    """
    from huggingface_hub.utils import EntryNotFoundError

    prefix = path_in_repo.strip("/")
    if not prefix:
        raise ValueError("verify_repo_paths_uploaded: empty path_in_repo (unscoped verify)")
    expected = list(expected_repo_paths)
    outside = [p for p in expected if not (p == prefix or p.startswith(prefix + "/"))]
    if outside:
        raise ValueError(
            f"verify_repo_paths_uploaded: {len(outside)} expected paths outside "
            f"path_in_repo={prefix!r} (first: {outside[:3]})"
        )
    try:
        uploaded = set(
            list_repo_files_complete(
                api, repo_id, repo_type=repo_type, revision=revision, path_in_repo=prefix
            )
        )
    except EntryNotFoundError:
        return expected
    return [p for p in expected if p not in uploaded]
```

## 11. Decision Rationale

1. **Wall-clock budget default 1800 s.** *What:* `EPM_HF_RETRY_BUDGET_S=1800`. *Why:* must outlive the #931 storm. *Source:* incident #931 events — the stacked pre-fix client retries (~4×143 s huggingface_hub pagination backoff + 120 s script-level linear ≈ 11.5 min, observed `Retry 3/20→10/20` across ticks) exhausted and the run died ⇒ storm duration lower bound ≈ 12 min; the org quota window is 5 min (gotchas.md § 2500-req/5-min), so 1800 s spans 6 reset windows and ≈2.5× the demonstrated lower bound. The exact 2.5× margin is a judgment call — env-overridable; the value is not sensitive within ~2×.
2. **Attempt floor kept at 6.** *Why:* back-compat with the #735 contract and every existing caller/test; the floor also guarantees legacy behavior under `budget=0`. *Source:* `hub.py:576` + `tests/test_hub.py:399-490` (read this session). *Alternative:* budget-only (rejected — breaks the pinned 6-call contract with no benefit).
3. **Exp backoff base 10 s, cap 180 s — unchanged.** *Source:* existing #735 code; not the failing part.
4. **Retry-After honored, seconds-form, capped 900 s.** *Why:* huggingface_hub 0.36.2 ignores the header entirely (verified: no Retry-After handling in `utils/_http.py`), so server pacing is lost today; honoring it is politer and faster than blind backoff during quota storms. *Source:* RFC 9110 §10.2.3 (both forms legal — we parse seconds, fall back on date-form); parse pattern from `llm/api_dispatch.py:586`. Cap 900: `ungrounded — defensive` (protects the budget from one pathological header; ≤ half the budget).
5. **Rate-limit substrings `"too many requests"`, `"rate limit"`; bare `"429"` excluded.** *Why:* response-less rate-limit errors (xet Rust boundary) currently classify non-transient. *Source:* #931 (xet-read-token 429 class); exclusion per #989 (digit triplets in paths like `issue504_raw` read as false-transient — same trap for `issue429_*`). Code-beats-substring ordering unchanged.
6. **Jitter 0-25 % on the backoff branch only.** *Why:* de-synchronize fleet-wide retry waves during org storms; none on the Retry-After branch (server-paced). *Source:* standard exponential-backoff-with-jitter practice (AWS Architecture Blog, "Exponential Backoff and Jitter", 2015); consistent with the AIMD discipline in `docs/api_throughput_guidelines.md`. Fraction 0.25: `ungrounded — harmless within [0.1, 0.5]` (deviation-allowed range).
7. **Env name `EPM_HF_RETRY_BUDGET_S`.** *Source:* existing `EPM_HF_*` convention in hub.py (`EPM_HF_STORAGE_*`, `EPM_HF_OVERFLOW_*`).
8. **Public alias `retry_transient`.** *Source:* incident #606 (`ImportError: cannot import name '_retry_transient'` from hub — scripts assumed it existed) + 4 live hand-rolled copies in `scripts/i528_*.py`.
9. **`verify_repo_paths_uploaded` semantics (missing-list return, mandatory scoped prefix, EntryNotFound⇒all-missing).** *Source:* the inline verify in `_upload_folder_filtered` (#664 exact-set rule) + #988's `list_hf_files_under_path` prefix semantics + `scripts/verify_uploads.py`'s #939 EntryNotFound handling — kept consistent across all three surfaces.
10. **Do not edit per-issue `_upload_tensors` scripts.** *Source:* task constraint (workflow-surface only) + workflow-fix-on-bug out-of-scope list; the greppable gotchas guidance is the forward mechanism.
