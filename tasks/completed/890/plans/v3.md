# Plan — #890 workflow-fix: verification gates must test the live dispatched path

## Goal + acceptance criteria

Add a standing rule that any verification / equivalence / vectorization gate
(`--verify-X` flag, `assert_*_equivalence` / `assert_matches_reference`-style
self-check) must exercise the CODE PATH ACTUALLY DISPATCHED by the entrypoint —
asserting on an unused sibling helper is a hollow gate and a substantive review
blocker. Origin: #779 (2026-07-02) — `--verify-vectorized` ran
`vectorized_mlp_skill.assert_matches_reference()`, a self-check of an UNUSED
helper, while the dispatched ridge hot loop (~17k fits) ran the unvectorized
18-20h path; the launch note claimed "vectorized" on the green gate and
code-review rounds 6/7 PASSed.

Acceptance criteria:
1. `.claude/rules/code-style.md` carries a short "verification gates test the
   live dispatched path" bullet naming #779 + the concrete verification shape
   (identity check / call-graph grep from entrypoint to gated callee).
2. `.claude/agents/code-reviewer.md` Step 0.68 carries a hollow-verification-gate
   sub-check with blocker tag `hollow-verification-gate` declared SUBSTANTIVE
   (never stripped by Step 5c-bis), AND the Step 7 `**Blocker tags:**`
   verdict-template line (~:1136) enumerates the new tag in its vocabulary.
3. `.claude/agents/codex-code-reviewer.md`'s Step 0.68 copy-contract enumeration
   names the new sub-check (so the composed Codex prompt cannot narrow it away),
   AND its `**Blocker tags:**` verdict-template line (~:583) enumerates the tag.
4. `uv run python scripts/workflow_lint.py` (no-flags default) passes; no other
   file changed; no LESSONS.md edit (no rule file added/removed).
