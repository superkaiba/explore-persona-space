### 3.1 `src/explore_persona_space/backends/artifacts.py` — shared declaration builder (NEW, ~40 lines)

Insert after `write_completion_sentinel` (line ~369); add to `__all__`.

```python
def build_expected_artifacts_declaration(
    *,
    issue: int,
    sentinel_path: str,
    custom_workload: bool,
    attempt_id: str | None = None,
    hf_data_repo: str = DEFAULT_HF_DATA_REPO,
    hf_model_repo: str = DEFAULT_HF_MODEL_REPO,
    wandb_run_path: str | None = None,
    extra_hf_data_paths: Sequence[str] = (),
    extra_hf_model_paths: Sequence[str] = (),
    extra_git_paths: Sequence[str] = (),
) -> dict[str, Any]:
    """Backend-agnostic EXPECTED_ARTIFACTS_HANDLE_KEY payload.

    Mirrors gcp.py:expected_artifacts_declaration (430-501) including the
    #601 custom-workload carve-out: custom workloads own their HF prefix,
    so we declare NO launch-time guess for them. Hydra-lane launches
    declare issue<N>_<attempt>/raw_completions/ (requires attempt_id).
    Returns a JSON-safe dict (lists, not tuples) so it round-trips via
    serialize_handle / expected_artifacts_from_handle.
    """
    if custom_workload:
        base_hf_data: tuple[str, ...] = ()
    else:
        if not attempt_id:
            raise ValueError("hydra-lane declaration requires attempt_id")
        base_hf_data = (f"issue{issue}_{attempt_id}/raw_completions/",)
    return {
        "issue": int(issue),
        "hf_data_repo": hf_data_repo,
        "hf_model_repo": hf_model_repo,
        "hf_data_paths": list(base_hf_data) + list(extra_hf_data_paths),
        "hf_model_paths": list(extra_hf_model_paths),
        "wandb_run_path": wandb_run_path,
        "git_paths": [f"eval_results/issue_{issue}/", f"figures/issue_{issue}/", *extra_git_paths],
        "sentinel_path": sentinel_path,
    }
```

Also update the module docstring's path shapes (lines 53-58) to the attempt-namespaced forms: SLURM = `$SCRATCH_JOB_DIR/eval_results/issue_<N>/<attempt>/.completion-sentinel.json`; RunPod = `/workspace/eval_results/issue_<N>/<attempt>/.completion-sentinel.json`.

```python
def sentinel_relpath_for(issue: int, attempt_id: str) -> str:
    """Repo-relative completion-sentinel path, attempt-namespaced.

    Single source of truth shared by render_sbatch (attempt_id =
    'slurm-${SLURM_JOB_ID}', runtime-expanded) and launch (attempt_id =

    attempt's clean exit (the staleness class gcp.py:413-422 closes).
```

```python
terminal = [
    "# === Done ===",
    'CURRENT_PHASE="done"',
    "kill $HEARTBEAT_PID 2>/dev/null || true",
    "# === Completion sentinel (workload exited cleanly) — write BEFORE the",
    "# done status so 'done' is published last, mirroring GCP (#598).",
```

```python
def mint_runpod_attempt_id() -> str:
    """Launch-scoped attempt id, GCP-style (minted pre-provision).

    RunPod has no scheduler job id, so launch mints `rp-<UTCstamp>-<4hex>`.
    The id namespaces the completion sentinel: a prior attempt's sentinel
    can never satisfy this launch's declaration (_check_sentinel validates
    phase+issue only, so the PATH is the staleness defense — same reasoning
    as the SLURM slurm-<jobid> namespacing, D2).
    """
    import secrets
    from datetime import datetime, timezone
    stamp = datetime.now(timezone.utc).strftime("%Y%m%dT%H%M%SZ")
    return f"rp-{stamp}-{secrets.token_hex(2)}"


def runpod_sentinel_path(issue: int, attempt_id: str) -> str:
    """Pod-side completion-sentinel path, attempt-namespaced.

    Under /workspace (persistent volume), NOT under the repo clone, so the
    path is stable regardless of where the workload checked out the repo.
    Attempt-namespaced because /workspace survives same-pod relaunches and
    no hygiene step clears a flat sentinel (#598 critique round 1).
    """
    from explore_persona_space.backends.artifacts import SENTINEL_FILENAME
    return f"/workspace/eval_results/issue_{issue}/{attempt_id}/{SENTINEL_FILENAME}"
```

**(b) SSH sentinel reader (`confirm_artifacts`, line ~367).** The default `read_sentinel` is local-FS; the pod is remote. The pod is guaranteed alive at confirm time (teardown only happens after PASS), so confirm injects a remote reader:

```python
def _ssh_read_sentinel(self, handle: RunHandle) -> Callable[[str], str | None]:
    def read(path: str) -> str | None:
        proc = subprocess.run(
            ["ssh", handle.pod_name, f"cat {_shell_quote(path)}"],
            capture_output=True, text=True, timeout=60, check=False,
        )
        if proc.returncode == 0:
            return proc.stdout
        stderr = (proc.stderr or "").lower()
        if "no such file" in stderr:
            return None          # missing sentinel → FAIL "sentinel missing"
        # Transport/auth failure must NOT read as "missing" — raise so the
        # check FAILs with the real reason (fail-loud per artifacts.py contract).
        raise RuntimeError(
            f"ssh sentinel read from {handle.pod_name} failed rc={proc.returncode}: "
            f"{proc.stderr[:300]}"
        )
    return read

def confirm_artifacts(self, handle: RunHandle) -> bool:

    )
    verdict = confirm_artifacts_from_handle(
        handle, io=VerifierIO(read_sentinel=self._ssh_read_sentinel(handle))
    )
    ...  # existing FAIL-print unchanged
```

## 11. Decision Rationale (design decisions; hyperparameter grounding N/A for `kind: infra`)

**D1 — SLURM declared sentinel path = LOCAL post-rsync repo path (not scratch-side + custom reader).**
*Why:* finalize runs `fetch_results` BEFORE `confirm_artifacts` (the #588 fix), and the existing pull already carries everything under `$SCRATCH_JOB_DIR/eval_results/` to `<src_root>/eval_results/` with dotfiles included — the default local-FS `_default_read_sentinel` then just works, zero new transport code, zero new failure modes. *Source:* `scripts/dispatch_issue.py:1098-1122`; `slurm.py:2217-2238`; `artifacts.py:257-268`. *Alternatives:* (a) scratch-side path + SSH reader — more code, a second SSH dependency at confirm time, and the robot wrapper's command allowlist makes ad-hoc `ssh ... cat` riskier than the already-allowlisted rsync; (b) GCP-style local mirror of the cluster-absolute path — `$SCRATCH/...` roots aren't writable on the VM. Rejected both.

**D2 — Attempt-namespaced sentinel (`slurm-<job_id>` dir), deviating from the artifacts.py docstring's flat shape.**
*Why:* the per-issue scratch dir is reused across attempts and `_clear_runtime` deletes only root-level `RUNTIME_ARTIFACT_FILENAMES` via the rsync include trick — it cannot reach a nested sentinel, so a flat path would let attempt N−1's sentinel masquerade as attempt N's clean exit (`_check_sentinel` validates phase+issue only, artifacts.py:520-584). GCP closes exactly this with per-attempt dirs. *Source:* `slurm.py:622-660`, `gcp.py:413-422`, the #588 `EPS_ATTEMPT_ID="slurm-${SLURM_JOB_ID}"` convention (`slurm.py:1409`). *Alternatives:* flat path + adding the sentinel to the clear list — the clear's rsync filter is root-level-only by construction; extending it to nested paths is a bigger, riskier change to a battle-tested deletion mechanism. Rejected. The artifacts.py docstring (lines 53-58) is updated to match.

**D3 — Shared builder in `artifacts.py` for SLURM+RunPod; gcp.py NOT migrated.**
*Why:* the #601 carve-out logic must not be transcribed twice more (three divergent copies is how the next #601 happens), but the task scopes the GCP lane out and it is verified-working in production — touching it buys risk for zero deliverable. *Source:* task body "Out of scope: The GCP lane"; `gcp.py:430-501`. *Alternatives:* (a) per-backend duplication — rejected (drift risk); (b) migrate gcp.py too — rejected (scope); named as a follow-up note in the implementer report.

**D4 — Hydra-lane HF guess `issue<N>_<attempt>/raw_completions/` mirrored from GCP, flagged as an inherited sharp edge.**
*Why:* declared-shape parity across lanes is the single-variable-change discipline; the #601 fix deliberately KEPT the hydra-lane guess on GCP. *Source:* `gcp.py:480-487` + its test `test_gcp_backend.py:797-838`. *Known weakness, stated honestly:* nothing in `src/` consumes `EPS_ATTEMPT_ID` (grep-verified), and `upload_raw_completions_to_data_repo` keys on a caller-chosen `experiment_name` (`orchestrate/hub.py:435-456`) — so the guess holds only for workloads that adopt the attempt id as their slug. A real hydra-lane false-negative on EITHER lane should be fixed once in the shared builder (and gcp.py), not papered over here. *Alternative:* declare no HF path on the SLURM hydra lane — rejected as a silent shape divergence from GCP; escalate instead if it bites (§9 must-ask).

**D5 — RunPod: ATTEMPT-BOUND pod-side sentinel path + SSH reader at confirm; exit-status-chained workload-side writer convention + pre-launch stale clear.**
*Why:* the RunPod backend is provision-only (`runpod.py:162-217`) — there is no backend-rendered workload wrapper to append a write to, so the writer is necessarily a workload/experimenter convention; the reader must be remote because the default is local-FS and the pod is remote, and the pod is guaranteed alive at confirm time (teardown gated on PASS). `/workspace/eval_results/issue_<N>/<attempt_id>/...` extends the artifacts.py docstring shape (lines 53-58, updated) and survives repo-clone-location drift. ATTEMPT-BINDING is mandatory (critique round 1, upheld by two reconcilers): `/workspace` persists across same-pod relaunches with no clearing mechanism, `_check_sentinel` validates phase+issue only, and same-pod retries are the routine recovery path — a flat path stale-PASSes a crashed retry (silent false PASS gating irreversible teardown on the paid lane). Because experimenter relaunches bypass `backend.launch`, the launch-minted id alone narrows but does not close the window — hence the convention ALSO mandates the pre-launch stale-sentinel clear and chains the write on workload exit status (`<cmd> && write_completion_sentinel`), keeping the sentinel mechanical rather than agent-judged. *Source:* `runpod.py:162-217, 367-400`; `artifacts.py:53-58, 339-368, 520-584`; reconciler verdicts (methodology + alternatives, round 1); task-body RunPod paragraph. *Alternatives:* (a) no declaration on RunPod (keep degrade forever) — rejected, the task folds the sibling in to make the gate real; (b) have `fetch_results`/finalize write the sentinel — rejected, circular (the orchestrator writing the workload's completion proof defeats the design contract, artifacts.py:47-52); (c) extend the degrade path to "declaration present but sentinel missing" — rejected, re-opens the all-SKIP silent-pass hole (artifacts.py:674-687); (d) flat per-issue path with the one-pod-per-run lifecycle as the staleness defense — rejected, the lifecycle covers cross-pod reuse only, not same-pod retries (round-1 binding fix); (e) advisory-first rollout (declaration attached, verdict non-gating for a transition window) — considered and rejected: the degrade path already covers in-flight pre-#598 handles, the convention ships same-commit, and an advisory window re-opens the silent-loss hole for exactly the runs most at risk.

**D6 — Custom-workload carve-out inheritance (no launch-time HF guess), applied to ALL RunPod launches.**
*Why:* #601 follow-up r1 — a guessed prefix turned the gate into a false-negative teardown block on a perfectly-uploaded run; every RunPod workload is a custom dispatch by construction. *Source:* `gcp.py:455-467, 480-487`; incident #601. *Alternative:* none credible.

**D7 — Attach the declaration in the SLURM `_reconnect` closure too.**
*Why:* GCP's reconnect path attaches (`gcp.py:1807-1813`); a reconnected SLURM handle is exactly the handle finalize will later consume, and leaving it bare silently re-creates the #588 FAIL on the recovery path. *Source:* `dispatch_issue.py:317-364`, `gcp.py:1795-1813`.
