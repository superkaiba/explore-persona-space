# Plan — #2088 workflow-fix: empty selection over local artifacts must fail loud, not exit rc=0

## Requirement + acceptance criteria

**Requirement (from the task Goal):** establish a fail-loud convention for empty post-selection row sets over local committed artifacts — an empty selection must raise, never exit rc=0 as a silent no-op — so this class is caught at the selecting script rather than after compute is spent.

**Acceptance criteria:**
1. A new `.claude/rules/gotchas.md` entry exists, sibling to and cross-referencing the #1092 real-corpus streaming-filter entry, stating: any selection/filter/join step over an already-local committed artifact must fail loud (raise) on an empty result set; must never write a well-formed "success" artifact from an empty set; names the three #1739 instances and the two recurring mismatch shapes; carries the per-predicate reject-counter diagnostic; names the in-repo exemplar `scripts/issue1739_holdout_rung.py::_assert_nonempty`.
2. The `.claude/rules/LESSONS.md` gotchas.md row's fires-when trigger is extended so plan-time discovery fires when an agent writes a selection/filter step over a local committed artifact.
3. `uv run python scripts/workflow_lint.py --check-lessons-index` passes; the no-flags lint run introduces no NEW failure. Because BOTH lessons-index byte caps are exactly saturated today (gotchas row 1,175 B == its 1,175 B grandfather cap at `workflow_lint.py:13255`; LESSONS.md 9,599 B vs `_LESSONS_MAX_BYTES = 9600` at `:13204`), the SAME diff raises both constants with the precedented argued comments (see D5) — the `guard_lessons_edit.sh` hook binds the edited tree's own constants, so constants and row edit land together.

## Design decisions (with reasons)

- **D1 — Placement: gotchas.md, immediately after the #1092 entry (line 172).** Budget verified: 178,532 B + ~2,200 B < 200,000 B WARN. Adjacency makes the sibling cross-reference a one-line pointer in each direction (the new entry references #1092's entry; #1092's entry is NOT edited — one-directional cross-ref avoids touching settled text and keeps the diff minimal).
- **D2 — Convention over shared helper (the task body's delegated fork).** NO new `src/` helper. Rationale: the assertion itself is one line (`if not rows: raise RuntimeError(...)`); the transferable value is the convention + the diagnostic recipe (per-predicate reject counters naming WHICH predicate emptied the set). A generic helper is either trivial (assert non-empty — invites non-use) or over-engineered (predicate introspection across heterogeneous selection idioms: list comps, pandas masks, dict lookups, JSONL scans). The in-repo precedent `scripts/issue1739_holdout_rung.py::_assert_nonempty` (the round-19 fix) is cited in the rule text as the pattern exemplar. No library code ⇒ no new test surface ⇒ smaller blast radius.
- **D3 — NO code-style.md edit.** The task listed it as secondary at planner's call. Declined: code-style.md has no fail-fast section to extend (verified by grep — fail-fast lives in CLAUDE.md Critical Rules), and restating the rule across two files creates drift risk. The always-on discovery surface is the LESSONS.md trigger row (D4), which is what actually fires at plan time.
- **D4 — LESSONS.md trigger-row extension.** Append to the gotchas.md row's fires-when list the SHORT clause: `; or a selection/filter over a local committed artifact (empty selection ⇒ raise)` (~84 B — deliberately compressed: the row is an index trigger, not the rule text). This is the mechanism that makes the rule consulted before the next script is written, closing the "next site re-learns it" gap the task names.
- **D5 — Argued lessons-index cap raises in the SAME diff (resolves the critic Must-Fix).** Both caps are exactly saturated: the gotchas row is 1,175 B == its grandfather cap (`_LESSONS_ROW_GRANDFATHER_MAX_BYTES["gotchas"]`, `workflow_lint.py:13255`), and LESSONS.md is 9,599 B vs `_LESSONS_MAX_BYTES = 9600` (`:13204`). ANY append therefore FAILs `--check-lessons-index` on two independent caps, and the `guard_lessons_edit.sh` PreToolUse hook (#1279) blocks the row edit at edit time — UNLESS the same edited tree carries the raised constants (the hook binds the edited tree's own workflow_lint.py; constant-first ordering within one diff is the sanctioned #1348→#1911 path). So the diff raises BOTH: (a) the `"gotchas"` row cap to measured-post-edit + ≤40 B headroom, with the precedented one-line comment (the "Cap = measured + ≤40" pattern used at L13234-13254 for #1348→#1911); (b) `_LESSONS_MAX_BYTES` to measured-post-edit file size + ≤40 B, argued in the constant's comment (the #992 argued-contract-change form: the raise buys exactly this row extension, not general slack). A lint budget constant is not a public-API contract (status enum / marker schema / task.py subcommand / agent location), so this stays in autonomous scope. The implementer MEASURES the realized post-edit sizes and sets the constants from those measurements — never from this plan's estimates (~1,259 B row / ~9,683 B file).
