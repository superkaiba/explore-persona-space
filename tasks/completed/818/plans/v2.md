# Plan — issue #818: watcher reaps zombie/idle wrappers stranded on orphaned (socket-less) tmux servers

## 0.0 TL;DR (plain English)

- **What I'll do:** Teach the 10-minute session-cleanup watcher one new fact. When a tmux window's underlying tmux process has had its socket file deleted, nobody can ever reconnect to that window again, so a leftover chat session sitting in it should not count as "someone might be looking at this." Right now the watcher can't check a socketless tmux, gets back a blank answer, and reads "I couldn't check" as "leave it alone" — which is how 31 abandoned sessions holding about 4.8 GB of memory sat there for up to a week.
- **What I expect:** After the change, an abandoned session in one of these dead tmux windows gets cleaned up on the same schedule as everything else (2 hours, confirmed on two checks in a row). A session in a live tmux, a window someone is actually attached to, or a plain terminal keeps being left alone.
- **What would change my mind:** If those 31 sessions were never in the daemon's session list to begin with, no watcher pass ever saw them, so this fix wouldn't have caught them and the real problem is that dead-tmux sessions quietly disappear from the daemon. That is a different fix. I checked this before settling on the design, and I cover the boundary.

## 0. Plan Summary (technical)

## 1. Goal

**Goal / requirement:** Make the autonomous-session watcher reap Happy wrappers stranded on **orphaned tmux servers whose socket file has been deleted** (nobody can ever reattach → not a live user TTY), on the SAME conservative schedule (≥2 consecutive checks, existing grace/idle windows) the passes already use — without widening reaping for any ambiguous or genuinely-live TTY. This is the confirmed gap behind the 2026-07-01 incident (31 zombie wrappers, ~4.8 GB RSS, 1–7 days old, on a 99-day orphaned server pid 2842652 whose socket was deleted from `/tmp/tmux-1001/`).

**Hypothesis:** N/A — no behavioral construct. This is a guardrail-predicate code change.

**Acceptance criteria:**
1. A new pure predicate classifies a pts on a socket-less orphaned tmux server as NOT a live-user TTY; fail-toward-keep on every ambiguous signal (tmux binary missing, `/proc/<pid>/fd` unreadable, socket-dir unreadable, pts not owned by any tmux server, stat race).
2. The idle-unmapped pass (`_is_live_user_tty`) treats such a pts as not-live, so an idle-≥12h unmapped session on such a pane falls through to the transcript-idle reap on ≥2 consecutive misses.
3. All existing `tests/test_autonomous_session_watch.py` tests pass unchanged (no live-TTY / attached-pane / detached-pane / headless regression).
4. New unit tests cover the full decision table (all input combinations → keep/reap) with tmp-dir / monkeypatched fakes (no live tmux server required).
5. `.claude/rules/background-automation.md` (idle-unmapped pass contract) and the CLAUDE.md watcher one-paragraph summary stay consistent with the code.
6. `uv run ruff check`, `uv run python scripts/workflow_lint.py` (default run incl. `--check-asks`), and a live `--dry-run` full-watcher smoke all pass.

## 2. Prior work / method delta

### What the TTY-liveness machinery does today (verified by reading the code)

Confirmed by reading `scripts/autonomous_session_watch.py`:

- **The zombie-wrapper pass (`decide_zombie_wrapper`, lines 10621-10669) consults NO TTY guard at all.** It keys ONLY on `has_claude` (no `claude/versions/` or `claude-agent-sdk` descendant), issue-mapped status (`ZOMBIE_STATUS_EXCLUDE`), a 2h grace, and ≥2 consecutive misses. For an UNMAPPED session (`mapped=False`), the status branch is skipped, so a sustained-no-Claude unmapped wrapper is reaped **regardless of TTY**.
- **The TTY guard lives ONLY in the idle-unmapped pass** (`decide_idle_unmapped`, line 11664, via `has_tty = _is_live_user_tty(pid, detached_tmux_ttys)`, line 11616). `_is_live_user_tty`:
  - returns `False` if the wrapper has no controlling tty (`_wrapper_has_controlling_tty`, tty_nr off `/proc/<pid>/stat`, line 11195);
  - resolves the wrapper's controlling pts via `/proc/<pid>/fd/{0,1,2}` (`_wrapper_controlling_tty_path`, line 11217);
  - returns `False` (not-live) iff that pts is in `detached_tmux_ttys` (a tmux pane whose session has **zero attached clients**), else `True` (live → keep).
- `detached_tmux_ttys` comes from `_detached_tmux_panes_with_activity()` (line 11234): ONE `tmux list-panes -a -F '#{pane_tty}\t#{session_attached}\t#{session_activity}'` call. **Fail-soft (lines 11252-11257 docstring + 11258/11275): tmux absent OR the server can't be queried → returns `(set(), {})` → EMPTY detached set → EVERY tty-bearing wrapper is kept.**

### The gap (confirmed)

An **orphaned tmux server whose socket was deleted** cannot answer `tmux list-panes` (the client has no socket to connect to) → the whole call returns non-zero / empty → `detached_tmux_ttys` is empty → the pts of every pane on that dead server is NOT in the detached set → `_is_live_user_tty` returns `True` → the idle-unmapped pass classifies it as a live user TTY and keeps it forever. This is exactly the fail-toward-keep-too-hard case: the socket-less server is *more* dead than a detached pane (a detached pane can still be reattached; a socket-less one cannot, absent a manual `kill -USR1`), yet it reads as *more* live.

### Method delta

Add a **socket-independent** orphaned-tmux-pane discovery path (the current path is socket-dependent by construction — it asks the running server). Discover tmux servers directly from `/proc` (`comm == tmux: server` or cmdline starts `tmux`), map each server's owned pts via `/proc/<server-pid>/fd`, and mark a pts orphaned iff its owning server has no live socket file. Then a socket-less server's panes join a NEW `orphaned_pts` set that `_is_live_user_tty` treats as not-live — an ADDITIONAL branch alongside the existing detached-pane branch, never removing the keep-leaning defaults.

### 3.2 New helper: socket-independent orphaned-tmux discovery

```python
# Constant near IDLE_UNMAPPED_STATE_PREFIX (~line 11129):

def _orphaned_tmux_reap_enabled() -> bool:
    """True unless EPM_ORPHANED_TMUX_REAP is explicitly falsy (0/false/no) —
    the kill-switch for the orphaned-socket-tmux widening. Same parse as
    _unmapped_idle_reap_enabled."""
    raw = os.environ.get("EPM_ORPHANED_TMUX_REAP", "")
    return raw.strip().lower() not in {"0", "false", "no"}


def _tmux_socket_dir() -> Path:
    """The tmux socket directory: $TMUX_TMPDIR/tmux-<uid> when set, else
    /tmp/tmux-<uid> (the documented default — man7 tmux(1): sockets live in
    tmux-UID under $TMUX_TMPDIR or /tmp)."""
    base = os.environ.get("TMUX_TMPDIR", "").strip() or "/tmp"
    return Path(base) / f"tmux-{os.getuid()}"


def _live_tmux_socket_present() -> bool:
    """True iff AT LEAST ONE socket file exists in the tmux socket dir.
    Used to distinguish 'no tmux servers at all' from 'a server exists but
    its socket was deleted'. Unreadable dir -> True (fail toward keep: we
    cannot prove any server is socket-less)."""
    d = _tmux_socket_dir()
    try:
        return any(p.is_socket() for p in d.iterdir())
    except OSError:
        return True  # cannot read the dir -> cannot prove orphaned -> keep


def _tmux_server_pids() -> list[int]:
    """PIDs of live tmux SERVER processes (comm 'tmux: server', or cmdline
    beginning with a tmux 'new-session'/server invocation). Reads /proc;
    unreadable entries skipped. Deliberately excludes 'tmux: client'
    processes (a client is a transient attach, not a session owner)."""
    pids: list[int] = []
    for entry in Path("/proc").iterdir():
        if not entry.name.isdigit():
            continue
        try:
            comm = (entry / "comm").read_text().strip()
        except OSError:
            continue
        if comm == "tmux: server":
            pids.append(int(entry.name))
    return pids


def _tmux_server_socket_path(pid: int) -> str | None:
    """The socket path a tmux server is bound to, read from its open fds:
    a tmux server holds its listening AF_UNIX socket, whose /proc/<pid>/fd
    symlink resolves to 'socket:[inode]'. We instead read the server's
    socket path from /proc/<pid>/cmdline is NOT reliable, so use the fd->
    /tmp/tmux-<uid>/<name> mapping when present; return None when it cannot
    be resolved (fail toward keep at the call site)."""
    # Implementation note: the robust, cheap resolution is to read the
    # server's cwd/fd set for a /tmp/tmux-<uid>/<name> path. If none of the
    # server's readlink targets is a concrete socket file path, return None
    # (the fd points at 'socket:[inode]' with no path) -> the caller then
    # falls back to the presence check in _tmux_socket_dir(). See §3.3 for
    # the exact resolution order + fallbacks.
    for fd in Path(f"/proc/{pid}/fd").iterdir() if Path(f"/proc/{pid}/fd").exists() else []:
        try:
            target = os.readlink(fd)
        except OSError:
            continue
        # A tmux server socket lives under the socket dir; a concrete path
        # target (rare — most kernels show 'socket:[inode]') is authoritative.
        if target.startswith(str(_tmux_socket_dir())):
            return target
    return None


def _pts_owned_by_pid(server_pid: int) -> set[str]:
    """Set of /dev/pts/N device paths the tmux server holds open (its panes'
    slave ptys), read from /proc/<server_pid>/fd. Unreadable -> empty set."""
    out: set[str] = set()
    fd_dir = Path(f"/proc/{server_pid}/fd")
    try:
        fds = list(fd_dir.iterdir())
    except OSError:
        return out
    for fd in fds:
        try:
            target = os.readlink(fd)
        except OSError:
            continue
        if target.startswith("/dev/pts/"):
            out.add(target)
    return out


def _orphaned_tmux_pane_ttys() -> set[str]:
    """Set of /dev/pts/N device paths that belong to a tmux SERVER whose
    listening socket no longer exists under the tmux socket dir — i.e. a
    server nobody can reattach to (the 2026-07-01 orphaned-server class).

    Discovery is SOCKET-INDEPENDENT (it reads /proc, not `tmux list-panes`,
    which cannot query a socket-less server). For each live tmux: server
    pid:
      * if the server's own socket path resolves AND that file is a live
        socket -> the server is REACHABLE; its panes are NOT orphaned;
      * else (no resolvable socket path AND the socket dir contains no
        socket for it) -> the server is orphaned; add every /dev/pts it
        owns to the result.

    Fail-soft / fail-toward-keep on EVERY uncertain signal:
      * tmux binary absent OR no tmux: server pids -> empty set (nothing to
        reap; identical to today);
      * /proc/<pid>/fd unreadable (perms/race) -> that server contributes
        nothing (kept);
      * the socket dir is unreadable -> _live_tmux_socket_present() returns
        True, so NO server is judged orphaned -> empty set (kept);
      * a socket file EXISTS for the server -> not orphaned (kept).
    The set can only ever ADD confirmed-orphaned ptys; it never removes a
    pane from the keep-leaning default."""
    if shutil.which("tmux") is None:
        return set()
    server_pids = _tmux_server_pids()
    if not server_pids:
        return set()
    # If ANY socket exists in the dir, we still evaluate per-server below,
    # but the per-server check is authoritative: a server is orphaned only
    # when its OWN socket is gone. The dir-level presence check is the
    # fail-toward-keep backstop when a server's socket path is unresolvable.
    dir_has_socket = _live_tmux_socket_present()
    orphaned: set[str] = set()
    for pid in server_pids:
        sock = _tmux_server_socket_path(pid)
        if sock is not None and Path(sock).is_socket():
            continue  # reachable server -> panes kept
        if sock is None and dir_has_socket:
            # cannot resolve THIS server's socket path AND some socket
            # exists -> cannot prove THIS server is orphaned -> keep.
            continue
        # sock resolved-but-gone, OR sock unresolvable AND the dir has no
        # socket at all (the incident: socket deleted, dir empty) ->
        # confirmed orphaned.
        orphaned |= _pts_owned_by_pid(pid)
    return orphaned
```

### 3.3 Socket-resolution order (the one subtlety)

`/proc/<pid>/fd` symlinks for an AF_UNIX socket usually resolve to `socket:[inode]`, NOT a path — so `_tmux_server_socket_path` will commonly return `None`. That is fine and is why the design uses TWO signals, not one:

1. **Per-server socket path resolvable** (rare) → authoritative reachable/orphaned.
2. **Per-server socket path unresolvable (`None`)** → fall back to the **directory-level presence check**: if the socket dir contains **no socket file at all**, every server in it is orphaned (the exact incident: server pid 2842652 alive, `/tmp/tmux-1001/` had its socket deleted). If the dir contains **at least one** socket, we cannot prove *this particular* server is the orphaned one from `None` alone, so we KEEP (fail toward keep) — the incident does not need per-server disambiguation because on the incident VM the orphaned server's socket deletion left the relevant socket absent.

This keeps the widening strictly to the **provably-orphaned** case the task constrains to: the incident's "socket file deleted" state is detectable via the dir-level absence check; any state where a socket still exists is left alone.

> **On the live VM right now** (verified): one `tmux: server` pid 217724 with socket `/tmp/tmux-1001/default` present → `_live_tmux_socket_present()` True and the socket resolves → `_orphaned_tmux_pane_ttys()` returns `set()` → zero behavior change for the healthy fleet. Good.

### 3.4 Fold into `_is_live_user_tty` (idle-unmapped pass)

```python
def _is_live_user_tty(
    pid: int,
    detached_tmux_ttys: set[str],
    orphaned_tmux_ttys: set[str] | None = None,   # NEW, default-None back-compat
) -> bool:
    """... (existing docstring) ... PLUS: a controlling tty that is a pane on
    an ORPHANED tmux server (socket deleted -> unreattachable) is NOT a
    live-user tty. Both the detached-pane and orphaned-server sets fail
    toward keep on any unresolved signal."""
    if not _wrapper_has_controlling_tty(pid):
        return False
    tty_path = _wrapper_controlling_tty_path(pid)
    if tty_path is None:
        return True  # unresolvable -> keep (unchanged)
    if tty_path in detached_tmux_ttys:
        return False
    if orphaned_tmux_ttys is not None and tty_path in orphaned_tmux_ttys:
        return False   # NEW: orphaned-server pane -> not live
    return True
```

Default-`None` third arg preserves every existing caller (the pure-predicate test at test line 6142 calls `_is_live_user_tty(99, {...})` with two args and stays green).

### 3.6 Decision table (all input combinations → keep / reap)

`_is_live_user_tty(pid, detached, orphaned)` — the guard the idle-unmapped pass consults (`True` = live → KEEP; `False` = not-live → falls through to the transcript-idle reap):

| controlling tty? | tty_path resolvable? | in detached set? | in orphaned set? | result | rationale |
|---|---|---|---|---|---|
| no | — | — | — | `False` (headless) | daemon RPC-spawned session; not a terminal |
| yes | no (`None`) | — | — | `True` (KEEP) | unresolvable pts → fail toward keep |
| yes | yes | yes | — | `False` (not-live) | detached tmux pane (existing behavior) |
| yes | yes | no | yes | `False` (not-live) | **NEW: orphaned-server pane (socket deleted)** |
| yes | yes | no | no | `True` (KEEP) | attached pane / raw login pts / live server |

`_orphaned_tmux_pane_ttys()` probe-failure fallbacks (all → the pts is NOT added to the orphaned set → KEEP):

| probe state | orphaned set contribution |
|---|---|
| tmux binary missing | `∅` (empty) |
| no `tmux: server` pids | `∅` |
| socket dir unreadable | `∅` (dir presence → True → no server orphaned) |
| server socket file EXISTS + resolves | `∅` (server reachable) |
| server socket unresolvable (`None`) BUT dir has ≥1 socket | `∅` (cannot prove THIS server orphaned) |
| `/proc/<server_pid>/fd` unreadable (perms/race) | `∅` (that server contributes nothing) |
| server socket resolved-but-gone, OR unresolvable AND dir empty | pts set the server owns (**the only reap-widening case**) |

Combined with the ≥2-consecutive-miss + ≥12h-idle (or the #695 fallback window) guards already in `decide_idle_unmapped`, a one-tick orphaned flicker never reaps.

### 3.7 Interaction with the `kill -USR1` socket-recreation escape hatch

Per the tmux man page and [Rubén Varela's recovery guide](https://rubenvarela.com/guides/recovering-tmux-when-its-socket-was-deleted/): a deleted socket can be recreated by `kill -USR1 <tmux-server-pid>`. Design handling: if a human recreates the socket, the NEXT pass's `_live_tmux_socket_present()` sees the socket again and `_orphaned_tmux_pane_ttys()` drops that server's panes from the orphaned set → the session reverts to KEEP. Because the reap needs ≥2 consecutive missed checks AND the wrapper still be idle ≥12h, a socket recreated between ticks resets the not-live signal well before any stop. This is why the SIGUSR1 possibility does not change the design: the multi-tick accumulation + idle-window guards absorb the transient. (Practically, an orphaned server 99 days old with the socket long deleted is not being SIGUSR1-revived; the guard is belt-and-suspenders.)

## 5. Success criteria (quantitative)

## 6. Kill criteria (what would mean this design is wrong)

**Primary kill-criterion — investigated before designing, resolved:** *Were the 31 incident wrappers in the daemon `/list`?* Both `zombie_wrapper_pass` (line 11004) and `idle_unmapped_pass` (line 12388) derive their candidate list from `_live_children()` (spawn_session, line 623) = the Happy daemon `/list` reply. If the 31 wrappers were NOT in `/list`, **no session pass ever saw them**, the TTY guard is moot, and the true gap is daemon-gating.

I verified against the live VM:
- Terminal-launched `happy claude` sessions **ARE** in the daemon `/list`, with `startedBy: "happy directly - likely by user from terminal"` (8 such sessions live right now, alongside 33 `startedBy: daemon`). So terminal-launched sessions on tmux panes ARE daemon-tracked and DO reach both reaper passes. This is consistent with the TTY-guard being the operative gap for the *daemon-tracked* subclass.
- The `claude_local_launcher.cjs` cmdline matches NEITHER `_CLAUDE_CMDLINE_MARKERS` marker (confirmed by reading `/proc/<pid>/cmdline` live), BUT a HEALTHY terminal session's launcher spawns a real `~/.local/share/claude/versions/<v>` grandchild that DOES match `claude/versions/` → `has_claude=True` for a healthy session (verified: all 8 live terminal wrappers read `has_claude=True`). The zombie state is precisely when the `claude/versions/` grandchild has exited but the launcher shim lingers → `has_claude=False`.

**The honest residual + the descope this forces:** The zombie-wrapper pass has NO TTY guard, so a *daemon-tracked* `has_claude=False` unmapped wrapper is reaped by it regardless of tmux state — the orphaned-socket TTY fix is NOT what unblocks that subclass. The TTY fix squarely unblocks the **idle-unmapped subclass**: a daemon-tracked session with a *live-but-idle* inner Claude, unmapped, on an orphaned-server pane, which the idle-unmapped pass keeps forever because the empty detached-map reads the pane as live. That IS the confirmed, reproducible gap in the code, and it is what this plan fixes.

The incident's `has_claude=False` + orphaned-socket + never-reaped combination most likely means those specific wrappers had **dropped out of the daemon `/list`** (the wrapper on a dead tmux server whose socket was deleted lost its daemon socket connection — the body itself notes the 54-day launcher was "unknown to the Happy daemon"). If so, that is a DIFFERENT gap (daemon-gating) that the TTY fix cannot address:

- **Explicit descope (stated in the plan, carried to the clean-result):** the **not-daemon-tracked** subclass (a wrapper absent from `/list` — the 54-day init-parented `--resume 83ac2dd5` launcher, and any of the 31 that had fallen out of `/list`) is **OUT OF SCOPE** for this fix. Every session pass is daemon-gated by construction (`_live_children()`), so covering that subclass requires a `/proc`-scan-based reaper independent of the daemon — a materially larger, higher-blast-radius change (it would reap processes the daemon does not know about, with no daemon `/stop-session` handshake). This plan does NOT attempt it; it is a candidate follow-up (a `/proc`-discovered orphaned-Happy-wrapper sweep), noted here so the boundary is explicit and the reviewer can weigh whether to file it.

**Kill-criterion verdict:** the design is CORRECT for the daemon-tracked idle-unmapped-on-orphaned-pane subclass (verifiable, reproducible from code + live probes) and HONESTLY DESCOPES the not-daemon-tracked subclass. If a reviewer establishes that ZERO of the incident wrappers were ever daemon-tracked, then this fix, while still a real correctness improvement to the idle-unmapped guard, would not have reaped *those specific* wrappers, and the follow-up daemon-independent sweep becomes the priority — the plan says so up front rather than overclaiming.

Secondary kill-criterion: if adding the orphaned set caused ANY existing TTY/detached/headless test to flip, the fold is wrong (it must be purely additive) → revert to the default-`None` back-compat shape and re-derive.
