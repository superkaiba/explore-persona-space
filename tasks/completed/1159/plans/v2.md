### 4.5 New lint check: `check_section_reference_pointer_coverage`

Location: `scripts/workflow_lint.py`, adjacent to `check_lens_coverage` (check_lens_coverage at :7230). Signature follows the house pattern:

```python
_SECTION_REFERENCE_SUFFIXES: tuple[str, ...] = ("-section-reference.md", "-lens-reference.md")

def check_section_reference_pointer_coverage(
    *, repo_root: Path | None = None, warn_sink: list[str] | None = None
) -> list[str]:
```

Semantics (each numbered behavior gets a test, §Test plan):

1. **Scan set:** every `.claude/rules/*.md` whose filename ends with a suffix in `_SECTION_REFERENCE_SUFFIXES`. Today: `analyzer-section-reference.md`, `critic-lens-reference.md`, `planner-section-reference.md`, + the new `clean-result-critic-lens-reference.md`. (`clean-result-paper-review.md`, `lens-coverage-map.md` etc. do not match — deliberately out of scope; they have their own conventions.)
2. **Owning-agent mapping:** strip the suffix from the stem → `<agent>`; owning spec = `.claude/agents/<agent>.md`. Missing owning spec → FAIL (orphan reference file).
3. **Fence-aware heading enumeration:** walk lines; a line matching `^(```|~~~)` toggles fence state (handles info-string openers like ```` ```bash ````); outside fences, collect headings matching `^(#{2,3}) (.+)$`. (H1 excluded — it is the file title. Fenced pseudo-headings — e.g. the `# Resolves to tasks/...` bash comments inside the Lens-13 fence at monolith line 1543 — are skipped; this is the Goal's "fence-aware" clause.)
4. **Per-file section grain:** grain = 2 if any non-fenced H2 exists, else 3. Only grain-level headings require pointers (sub-headings below grain are intra-section structure). This generalizes the Goal's literal "H2": `critic-lens-reference.md` is H3-grain with zero H2s — an H2-only check would be vacuous there and on the new file, defeating the #850-class purpose. Grain-mixing note: a reference file should keep one section grain; a file with both H2s and H3s gets H2-grain coverage only (documented in the check docstring).
5. **Pointer predicate:** let `norm(s)` collapse all whitespace runs to single spaces. FAIL for each grain heading `h` where `norm(owning_spec_text)` does not contain `"§ " + norm(h)`. Whitespace normalization tolerates wrapped pointer lines (analyzer.md wraps several); exact-text matching enforces "naming the exact heading". Substring (not regex) — heading punctuation is inert.
6. **Zero grain headings** in a matched reference file → FAIL (malformed reference file).
7. **Severity/registration:** FAILs (returned list); no WARN cases in v1 (`warn_sink` accepted for signature uniformity). Flag `--check-section-reference-pointers` registered in `main()`; added to the `no_flags` disjunction (no_flags disjunction at :7808) and dispatched via `if args.check_section_reference_pointers or no_flags:` (dispatch pattern at :7897-7955); module docstring gains the standard `* --check-section-reference-pointers (also bundled into the no-flags default run): ...` entry.
8. **No waiver token in v1** (YAGNI — live trees pass, verified by simulation). If a future reference file needs an exempt section, that change adds the waiver mechanism then.

**Live-tree feasibility (verified this session):** the exact predicate above passes all 25 headings across the three existing reference files — zero backfills needed; the 16 new pointer lines in §4.2 make the fourth file pass.

## 11. Decision Rationale

Hyperparameter grounding: `N/A — no training hyperparameters` (kind: infra). Design decisions:

1. **Split boundary = full lens rubrics + spec-text-only checks move; roster capsule, mechanical pre-pass, paper branch, blocker-grounding, Output, Round budget stay.** *Why:* moves the two purely-reference spans (77 KB) while keeping every operational DO-FIRST instruction in the spawn-loaded spec; the roster capsule mirrors critic.md's kept item-lists. *Source:* #838 (critic.md capsule+reference shape) + measured byte map (§4.2). *Alternatives:* move only the lenses (rejected: slim spec lands ~40.4 KB, at the FAIL threshold); move the mechanical pre-pass too (rejected: it is the mandatory first action every round — spawn-loading it avoids one guaranteed read).
2. **Reference file at H3 grain with byte-identical lens headings.** *Why:* zero heading drift makes content preservation mechanically provable (C1 diff), and matches the sibling. *Source:* `critic-lens-reference.md` (H1 + H3s, "headings verbatim from critic.md"). *Alternatives:* promote lenses to H2 (rejected: gratuitous heading churn breaks C1's byte-identity); keep a wrapper H2 above H3 lenses (rejected: grain rule would then check only the wrapper, losing per-lens coverage — the #850-class point).
3. **Pointer format `§ <exact heading>`, whitespace-normalized substring predicate.** *Why:* both live conventions (analyzer.md "Full text: ... § H (grep heading, chunked Read)"; critic.md "`file` § H — grep the heading ...") satisfy it, and it passed 25/25 live headings in simulation; normalization tolerates the wrapped pointers analyzer.md already contains. *Source:* live-tree simulation this session. *Alternatives:* require filename+heading adjacency on one line (rejected: false-FAILs analyzer.md's existing wrapped two-line form → live-trees-pass invariant broken at birth); heading-text-anywhere without `§ ` (rejected: prose mentions of a section name would count as coverage — too weak).
4. **Grain rule (H2 if present, else H3) instead of literal H2-only.** *Why:* the Goal's H2 phrasing, applied literally, makes the check vacuous on `critic-lens-reference.md` (zero H2s) and on the new file — silently exempting exactly the lens-reference class the task exists to protect. *Source:* fence-aware heading enumeration of all three live reference files (this session). *Alternatives:* check H2+H3 unconditionally (rejected: analyzer-section-reference's intra-section H3/H4 subsections would demand dozens of new pointers — massive false-FAIL surface); H2-only per the literal Goal text (rejected as above; the deviation is confined to check internals and is stated here for the critic).
5. **FAIL severity + no-flags bundling.** *Why:* silent coverage drop is invisible at review time by definition (the #850 r1 MAJOR was caught by one Codex reviewer's luck); the two closest siblings (`--check-lessons-index`, `--check-lens-coverage`) are FAIL + bundled. *Source:* `workflow_lint.py:7897-7955` precedent. *Alternatives:* WARN-only (rejected: WARNs on the shared default run are routinely scrolled past — no ratchet).
6. **Twin contract: compose-time retarget, all-15-in-one-prompt, no fan-out.** *Why:* preserves the public ensemble topology and #1050's read-only dispatch; byte-equivalent prompt to Codex; the only change is the source of truth for lens text, with codex-critic's verbatim-and-in-full anti-drift language. *Source:* `codex-critic.md:128-156` (#838 shipped contract); #1050 (compose-time-envelope constraint); #599 (drift incident motivating verbatim-in-full). *Alternatives:* per-lens Codex fan-out (rejected: architectural — changes spawn count, verdict aggregation, reconciler inputs); leave the twin reading the slim spec only (rejected: the lens definitions would no longer be in its read set at all — the composed prompt would silently lose the rubrics; this is the leg-1b "contract redesign" the Goal names).
7. **Grandfather entry REMOVED (not ratcheted).** *Why:* mandatory — the stale-entry sub-check FAILs any entry whose file is ≤ 40,000 B. *Source:* `workflow_lint.py:6906-6911` (read this session). *Alternatives:* none legal.
8. **Do leg 1 rather than deflect (retirement-horizon call).** *Why/Source/Alternatives:* §3 in full — unscheduled v1 drain + per-task multi-round load cost vs a small, mechanically-verifiable move.
9. **New rule filename `clean-result-critic-lens-reference.md`.** *Why:* the `<agent>-lens-reference.md` convention for lens-based critics; makes the suffix-strip owning-agent mapping exact. *Source:* `critic-lens-reference.md` sibling. *Alternatives:* `clean-result-critic-section-reference.md` (rejected: sections here ARE lenses; the sibling naming is the lens variant).
