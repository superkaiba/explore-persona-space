Steps (fail-fast at each; no silent fallbacks):

1. **Carve-out gate.** `organism.behavior_spec.programmatic` → raise `UnsupportedOrganismError` naming the seam: datagen refuses programmatic behaviors by design (0d), and the marker/fact training-mix builders are not yet promoted into `artifacts/`; Phase 1 wires the carve-out `build` path (the recipe side — `recipe_for("marker")` — already works and stays validated at construction).
2. **Data.** `pos_path, cn_path, pool_meta = generate_training_data(organism.behavior_spec, organism.context, organism.panel, out_dir=out_root / "datagen", seed=organism.seed, **(datagen_kwargs or {}))`. Datagen re-asserts panel disjointness internally and resumes idempotently on an exact manifest match — so Phase-3c arm variants sharing (behavior, C, panel, seed) reuse one datagen pass for free and differ only in mixing.
3. **Mix assembly** (the genuinely new logic; v2 — methodology reconcile MF-2 + shortfall-arithmetic note). Read the emitted pos/cn rows; `counts = mix_counts(len(pos_rows), generic_frac=spec.generic_frac, neg_ratio=spec.neg_ratio)`. Negatives: datagen emits per-member-BALANCED cn rows totalling `panel_size × (floor_n // panel_size)` (datagen.py:666-683) — i.e. up to `panel_size − 1` FEWER than `counts["negatives"]` on non-divisible counts — so a deficit of at most `panel_size − 1` rows is TOLERATED (use all emitted cn rows; record the realized count in `mix_meta.json`); a LARGER shortfall → `ValueError` (loud). SURPLUS (`len(cn_rows) > counts["negatives"]`) is REFUSED with `ValueError`: cn.jsonl rows carry NO panel-member identity (`{"prompt","completion"}` only, datagen.py:740-758), so any subsample could silently unbalance the panel or drop the bare-default negatives; the branch is unreachable under every shipped arm (`neg_ratio ∈ {0, 1.0}` ⇒ emitted ≤ needed), so the error is a TRIPWIRE for a future recipe change, and its message names the fix (thread member identity through cn.jsonl, then stratify per member). `neg_ratio == 0` (posonly / both_off arms) → zero negative rows in the mix. Generic: `counts["generic"] > 0` requires `generic_data_path` (else `ValueError` naming the Phase-1 corpus input); seeded sample WITHOUT replacement (corpus smaller than needed → `ValueError`, never sample-with-replacement silently). Shuffle the union with `random.Random(organism.seed)`; write `out_root/"train_mix.jsonl"` + `out_root/"mix_meta.json"` (realized counts, input paths + sha256s, spec asdict) the moment assembly completes (checkpoint-per-phase).
4. **Train — lora path.** `cfg = build_train_config(spec, run_name=organism.slug(), seed=organism.seed, gpu_id=gpu_id, extra_overrides=extra_overrides)`; `adapter_dir, loss = train_fn(base_model, str(train_mix), str(out_root / "train"), cfg=cfg)`. `TrainLoraConfig(**merged)` inside 0e fails loud on any config-surface drift.
5. **Train — fullft path.** `spec.train_method == "fullft"` → `argv = fullft_launch_command(spec, base_model=base_model, dataset_path=str(train_mix), output_dir=str(out_root / "train"), seed=organism.seed, run_name=organism.slug())`; `(fullft_run_fn or _default_fullft_run)(argv)`. The two named 0e gaps (epoch-grain dosing; the grad-accum × num_processes effective-batch mismatch) are **passed through untouched** and recorded in `provenance["effective_batch_note"]` — matched-batch adjustment is Phase 3b's explicitly-documented job (recipe.py docstring), not a silent organisms-side fix.
6. **Dose selection.** `spec.stopping.kind == "checkpoint_and_select"` → enumerate `out_root/"train"/checkpoint-*` dirs, parse step numbers, require non-empty (else `ValueError` — a missing ladder means the recipe's `save_strategy="steps"` config did not take); `rates_by_step = {step: rate_fn(ckpt_dir)}` — `rate_fn` REQUIRED on this path (`ValueError` if None; the module ships `make_source_rate_fn(organism, **verify_gen_kwargs)`, a factory closing over the §4.3 generation+judging machinery for one context, as the production default the caller constructs explicitly). `selection = select_dose_checkpoint(rates_by_step, band=organism.dose or spec.stopping.rate_band)`; `adapter_path` = the selected checkpoint dir. A `fallback="closest_approach"` selection is returned as-is (0e's preregistered fallback), flagged in provenance — "never enters the band" is a reportable outcome, not an infra failure. `fixed_epochs` → `selection=None`, adapter = final output dir.
7. Return `BuildResult` with full provenance (git sha via the existing `reproducibility_metadata` pattern).

**Why code, not a model call:** N/A at the harness level — every LLM-judgment inside is already routed through the sanctioned judge stack (`judge_graded` → Batch client); the harness itself is deterministic orchestration.

1. **DV router** on `organism.behavior_spec.dv.primary`:
   - `"judged_rate"` → graded-judge scoring (below). Covers sycophancy / harmful_compliance / broad-EM / china_censorship.
   - `"structural"` → the deterministic predicate from `datagen._STRUCTURAL_PREDICATES[behavior.name]` (currently `formatting`; a structural behavior without a registered predicate raises `KeyError` — fail-fast, Phase 1 fills). No judge calls on this path.
   - `"marker_slot_stats"` / `"fact_recall_5way"` / `"ground_truth_accuracy"` → `UnsupportedOrganismError` naming the existing surfaces (`eval_battery.run_marker_and_capability_phase` + `eval/marker_logprob.compute_marker_slot_stats` for the marker three-space contract; benchmark keys for correctness) as the Phase-1 extension seams. The task body frames `verify` in judged-RATE terms; the marker keeps its own three-space log-prob recipe by rule (marker-leakage-measurement.md — it is NOT a judged DV) and must not be squeezed into this rate harness.
2. **Context set (v2 — methodology reconcile MF-1).** Source = `organism.context`. Bystander set (default) = the UNION of: (a) **every `organism.panel` member, materialized via `NegativeContext.to_context()`** — the trained negatives are `NegativeContext` objects that are NOT `CONTEXTS` entries (`neg_sp_police` / `neg_sp_ph4` / `neg_reph_curious` / `neg_wc_short` / `neg_default_assistant`, negatives.py:103-151), so a `CONTEXTS`-only default would never measure them; (b) every `CONTEXTS` entry with `context_id != organism.context_id`; (c) the bare default assistant (`DEFAULT_ASSISTANT_NEGATIVE.to_context()`) if not already present — leakage-to-default is the safety target (open-q 3.7). The union is DEDUPLICATED BY CONTENT IDENTITY (system-prompt + user-wrap fingerprint), not id alone. Each bystander row carries `trained_negative = True` iff its slug OR content identity matches a panel member — identity matching is load-bearing: `CONTEXTS["qt_rephrase_curious"]` is byte-identical to trained negative `neg_reph_curious` (context.py's own `source` field says so), so slug-only matching would mislabel it held-out and bias `leakage_ok` optimistically. `leakage_ok` is computed on the TRUE held-out subset only (`trained_negative=False`). A `bystander_context_ids` override resolves each id against `CONTEXTS` ∪ the organism's panel slugs (unknown id → `ValueError`); trained-negative labeling applies identically to overridden sets.
3. **Generation.** For each `(side, ctx)` in `{trained: adapter_or_ckpt, base: None} × contexts`: `completions = generate_fn(side_path, [ctx.messages(q) for q in eval_questions], n=n_completions, temperature=temperature)`; persist `out_dir/f"completions__{side}__{ctx.context_id}.json"` the moment it returns (checkpoint-per-phase; these are the raw completions the caller uploads under `raw_completions/verify/` per Upload Policy). Skip-if-exists resume keyed on the file (mirrors `run_generation_phase`).
   - **Production default `_vllm_generate_fn`:** lazy-imports (`vllm`, and `teardown_vllm` + `_is_full_model_dir` from `eval_battery`) inside the function — never at module top (avoids the artifacts ↔ behavior_testbed_545 import cycle: `eval_battery` imports `artifacts.context`, and package `__init__` imports organisms). One `LLM` engine per model side with the `run_generation_phase` kwargs precedent (`enable_lora` + `LoRARequest` for adapters, full-model dirs detected via `_is_full_model_dir`, `max_lora_rank=64`, `max_model_len=8192`, `enable_prefix_caching=True`, fixed sampling seed), `use_tqdm=False`, chunked ≤500 prompts per `llm.generate` call (gotchas: large-batch deadlock prevention), torn down via `teardown_vllm`.
4. **Rate.** Judge items are `(item_id, question, completion)` with `item_id = f"{ctx.context_id}-{side}-q{i:03d}-c{j}"` (no `"__"` — the `judge_graded` guard). `eval_prompt = organism.behavior_spec.judge_rubric` (same call shape as datagen's `_judge_and_filter`); `cache_dir`/`save_raw` under `out_dir/judge/{side}_{ctx}/`. Per-completion score = `JudgeResult.scores[item_id]` (mean over kept draws); a `None` score (all draws dropped) is **dropped from the denominator and counted** (`n_dropped`) — never coerced (llm-judging rule 9). `rate = #(score > behavior.threshold) / n_scored`; `n_scored == 0` → `ValueError` (a fully-dropped cell is a judging outage, not a 0% rate).
5. **Companion (dual-DV; v2 — S4 + consistency WARN).** Routed on `DVSpec.companion`: `"tf_margin"` → required; `None` → skipped with `margin_* = None`; **`"judged_spotcheck"`** (the companion of BOTH structural behaviors, `DVSpec("structural","judged_spotcheck")`, behavior.py:669/718) → **explicit machine-readable skip**: `margin_* = None` + `companion_status = "unimplemented_v1: judged_spotcheck"` in the report (never a crash of the supported structural-primary read, never a silent skip; Phase-1 seam). Any OTHER companion value → `UnsupportedOrganismError` (fail-fast on registry drift). Fixed pools: `margin_pools` if given, else **`derive_margin_pools(datagen_dir) -> (pos_pairs, neg_pairs)` — a PUBLIC module-level function** (v2: promoted from inline logic so tests exercise it directly): join `raw_pos.jsonl`/`raw_neg.jsonl` (candidate `completion` text + `question`) with `judge_rows.jsonl` `kept` flags via `request_id`/`(question_id, variant_id)`, keep KEPT rows only, route `arm=="positive"` → pos pool / `arm=="negative"` → neg pool, sort by `(question_id, variant_id)`, take the first `DEFAULT_MARGIN_POOL_CAP` per side (the deterministic `build_fixed_pairs` selection pattern — same fixed set scored under EVERY context ⇒ no selection-on-outcome bias, llm-judging §E2 rule 19). Both sources absent while companion is required → `ValueError`. Pools are derived ONCE, before the per-side loop, and passed to `margin_read_fn(side_path, ctx, pos_pairs, neg_pairs)` per (side, ctx) — the seam carries the pools (S4) so side-invariance is assertable. **Pool provenance** goes into `OrganismReport.provenance`: pool source paths, per-side pool sizes, and a sha256 of the serialized pools (downstream can detect pool-composition artifacts — Codex-alternatives D). Production default loads the HF model once per side (base; base+PEFT adapter), then `compute_tf_margin(model, tokenizer, ctx.messages, pos_pairs, neg_pairs, device=...)` per context — lazy torch/peft imports, mocked in every test.
6. **Install-controlled leakage read (v2 — sign guard).** Per bystander: `transfer_fraction = margin_delta_bystander / source_margin_delta` where each delta is trained − base — computed in the **non-saturating continuous companion space** (the tf-margin), the content-behavior analogue of marker-leakage-measurement.md § Install-strength confound read 2 (which mandates a non-saturating space — EOS-margin logit for the marker, whose verify path is the Phase-1 seam — and bans raw log P / raw rate). The fraction is defined ONLY when `source_margin_delta >= +MIN_SOURCE_MARGIN_DELTA`: `|delta| < floor` → `transfer_fraction = None` + reason `"source margin delta below resolution floor"`; a NEGATIVE delta (`<= -floor`) → `None` + reason `"source margin delta negative — install did not register in margin space"` (S2/Claude-stat-2: prevents sign-flipped fractions, never a junk division). The report additionally carries install strength (`install_delta`, `source_margin_delta`) so Phase-3b/3c matched-install comparisons (read 1) are possible downstream.
7. **Asserts + report.** `install_ok = rate_trained_C > rate_base_C`; `leakage_ok = all(b.rate_delta <= leakage_bound for held-out b)`. BOTH flags are documented ADVISORY in their docstrings (strict `>0` install is noise-fragile near zero; the panel numbers + deltas + denominators are the deliverable — consumers must never quote a flag without them). `OrganismReport.provenance` also records the eval-question bank (list hash + count) and its overlap count with the build's training questions (Claude-alternatives concern 2: makes install-as-prompt-memorization detectable). The module docstring notes the arm-name mapping (the task body's "contra" = `recipe.ARMS` `"primary"`, neg_ratio=1.0) for Phase-3c callers. ## 14. Kill criteria (what would make this design wrong) + named fallbacks

1. **Margin-pool derivation impossible from datagen sidecars** (assumption 9 false — raw candidate rows lack question/answer text or ids). Fallback: add an append-only public accessor to `artifacts/datagen.py` (e.g. `load_kept_candidates(out_dir) -> (pos, neg)`) in the same round — a strictly additive upstream patch through code review. If it would require changing datagen's emitted files or behavior → **must-ask** (re-plan).
2. **Config-surface mismatch**: `build_train_config(spec, ...)`'s output rejected by `train_lora` (drifted `TrainLoraConfig` field). This is exactly what 0e's regression tests pin; a genuine mismatch means `main` is already broken → file the bug, **must-ask** before patching `train/sft.py` (out of this task's surface).
3. **Unavoidable import cycle** even with function-local imports (e.g. a needed `eval_battery` symbol moves to import time). Fallback: inline the tiny helper (`_is_full_model_dir` is 8 lines) with a provenance comment; restructuring either package → **must-ask**.
4. **The dose-selection contract can't run on real ladders** (checkpoint naming/step parsing wrong). Detectable only in Phase 1 GPU runs; this task pins the contract by test — if Phase 1 falsifies it, the fix lands there, not here.
