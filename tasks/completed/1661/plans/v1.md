## 3. Design

**One YAML hook entry**, inserted in the `repo: local` block immediately after the `workflow-lint-upload-or-true` entry (line 107) and before `check-mcp-json-no-secrets` (line 109), keeping the `workflow_lint.py` hooks grouped:

```yaml
      - id: workflow-lint-agent-spec-size
        name: "workflow_lint: agent-spec size ratchet — WARN >28KB, FAIL >40KB / grandfather cap (#1618)"
        entry: uv run python scripts/workflow_lint.py --check-agent-spec-size
        language: system
        # Fire when any agent spec changes (the incident class: a direct-to-main
        # .claude/agents/*.md edit past its ratchet cap redded every Step 9c
        # gate fleet-wide until #1618 trimmed it) or when the lint itself
        # changes (AGENT_SPEC_* threshold / grandfather-cap edits move the
        # verdict, matching the sibling hooks' pattern).
        # check_agent_spec_size scans .claude/agents/*.md non-recursively;
        # single-check run measured ~1.5 s (2026-07-24). Read-only, so it
        # stays on the default commit stage (the stages:[manual] NOTE above
        # covers mutating/large-file hooks only); high-frequency automated
        # task-state commits (tasks/**, eval_results/**) never match the
        # files regex, so fleet commit latency is unchanged for them.
        files: ^(\.claude/agents/[^/]+\.md|scripts/workflow_lint\.py)$
        pass_filenames: false
```

**Why the `files:` regex is what it is:**

- `\.claude/agents/[^/]+\.md` — the offender class is a top-level agent-spec edit. `[^/]+` (not `.*`) matches `check_agent_spec_size()`'s actual scan scope exactly: `agents_dir.glob("*.md")` at line 11752 is non-recursive, so a hypothetical nested file could never change the verdict and shouldn't trigger the hook.
- `scripts/workflow_lint\.py` — a cap-constant / grandfather-dict edit (an `AGENT_SPEC_SIZE_GRANDFATHER` cap raise, a threshold change) changes the verdict without touching any agent file; the sibling hooks (`check-asks`, `check-skill-refs`, `check-upload-or-true`, `workflow-yaml-lint`) all include the lint itself in their `files:` regex for exactly this reason. This also makes a reviewed growth+cap-raise commit (agent file + dict edit together) run the check once against the post-edit pair — the check's documented intent ("the check forces growth into a visible dict edit", line 11624–11626).
- `pass_filenames: false` — the check takes no filename args (it scans the whole agents dir); matches all six siblings.
- **No `stages: [manual]`** — the config's NOTE (lines 22–28) reserves manual staging for hooks that MUTATE staged files or block the fleet's high-frequency task-state commits. This hook is read-only, ~1.5 s, and its regex never matches task-state paths, so it belongs on the default commit stage with the other read-only checks.

**Verified mechanics (spawner questions):**

- **Runtime:** `time uv run python scripts/workflow_lint.py --check-agent-spec-size` → **1.509 s wall** (user 1.27 s), measured 2026-07-24 on the current tree. The cost is uv/python startup + the always-on `load_workflow_yaml()` schema load in main() (lines 13142–13150); the check itself is a stat() loop.
- **Single-check semantics:** setting the flag makes `no_flags` False (line 13155–13216 — `args.check_agent_spec_size` is in the disjunction at line 13203), so ONLY the `if args.check_agent_spec_size or no_flags:` branch (line 13312) runs a check; every other branch is gated on its own unset flag.
- **Working-tree vs staged content:** `check_agent_spec_size()` measures the WORKING TREE (`path.stat().st_size`, line 11755, rooted at `_REPO_ROOT = _HERE.parent` — cwd-independent, line 727). Verified from the installed pre-commit 4.6.0 source (`pre_commit/staged_files_only.py::_unstaged_changes_cleared`): before running hooks, pre-commit writes the index to a tree (`git write-tree`), saves a `git diff-index --binary <tree> --` patch of unstaged changes, then runs `git checkout -- .`; the patch is re-applied after. So during hook execution, tracked files' working-tree content == staged content — the check measures exactly what the commit would land. (Untracked files are NOT stashed; see Risks.) The spawner's parenthetical ("pre-commit checks out staged content? No: ... working-tree == staged content during hook execution") is confirmed, with the mechanism being stash-unstaged-then-restore, not a staged checkout.
- **Exit semantics:** a non-empty errors list prints each error to stderr (`workflow_lint: <err>`) plus a `FAIL (N error(s))` line and returns 1 (lines 13365–13369); clean returns 0 with `workflow_lint: PASS` (13371–72). The over-cap FAIL message names the file, measured size, and cap (grandfathered: "…exceeds its grandfather ratchet cap (<cap> bytes)…", lines 11760–11767; non-grandfathered: "…exceeds the 40000-byte agent-spec FAIL threshold…", lines 11774–11779) — satisfying the Goal's "fails … with the cap + measured size named". WARNs go to stderr only and never enter the FAIL list (pre-commit hides passing hooks' output by default, so the 14 current WARN lines are invisible on a passing commit).

**One pin test** (durability; mirrors the two sibling patterns) added to the EXISTING `tests/test_workflow_lint_agent_spec_size.py`:

```python
def test_precommit_hook_covers_agent_spec_size() -> None:
    """.pre-commit-config.yaml must carry a local hook running
    --check-agent-spec-size whose files: regex covers .claude/agents/*.md
    AND the lint itself — without it, no commit gate fires on the #1618
    direct-to-main offender class (task #1661)."""
    cfg = yaml.safe_load(
        (_HERE.parent / ".pre-commit-config.yaml").read_text(encoding="utf-8")
    )
    local_hooks = [h for repo in cfg["repos"] if repo["repo"] == "local" for h in repo["hooks"]]
    matching = [h for h in local_hooks if "--check-agent-spec-size" in h.get("entry", "")]
    assert matching, "no pre-commit hook runs --check-agent-spec-size (#1661)"
    assert any(
        re.search(h["files"], ".claude/agents/research-pm.md")
        and re.search(h["files"], "scripts/workflow_lint.py")
        and not h.get("pass_filenames", True)
        for h in matching
        if "files" in h
    ), f"no matching hook's files: regex covers agents/*.md + the lint: {matching}"
```
