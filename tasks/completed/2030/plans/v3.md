## Method delta

Same guard, new surfaces. Reuse, not reimplementation: `step9c_baseline.py`
importlib-loads sibling `inline_lint_gate.py` BY PATH (mirroring its own
`load_selector_module` shape — no `sys.path` mutation) and calls the SAME
`purge_repo_bytecode` + merges the SAME `NO_BYTECODE_ENV`. The SKILL.md recipes
get the bash equivalent (`find … -path '*/__pycache__/*.pyc' -delete` over the
#1950 `PURGE_ROOTS` set, plus the env token) because they are shell recipes
with no python entry point at purge time.

## File paths + concrete diffs

### A. `scripts/step9c_baseline.py`

1. Module level (near the existing sibling-load helper): importlib-by-path load
   of `inline_lint_gate.py` from `Path(__file__).resolve().parent`, binding
   `purge_repo_bytecode` and `NO_BYTECODE_ENV`. Module-level and fail-loud:
   the two files are a SAME-VINTAGE PAIR — they travel together in any
   checkout that carries either (the gate is invoked both from the main
   checkout and by relative path at `cwd=$WT` in the SKILL.md tmproot /
   compare / refresh call sites, and neither file is in the Step 5a SPECS sync
   list, so both always come from the same tree) — hence a load failure means
   a genuinely broken tree and the gate must refuse to run rather than
   silently running unguarded. Known consequence, accepted: the watcher
   (`autonomous_session_watch.py:10752`) imports `step9c_baseline` as a
   module, so the module-level load also executes inside watcher ticks — the
   same fail-loud posture applies (a broken pair should surface, not hide).
2. `run_pytest()`: (a) `env.update(NO_BYTECODE_ENV)` after the PYTHONPATH
   strip; (b) `purge_repo_bytecode(cwd)` immediately before `subprocess.Popen`
   (best-effort by the helper's own contract — unremovable files WARN and never
   crash; scratch trees no-op). Docstring gains one #1950/#2030 sentence.
