<h1>Plan — issue #688 <span class="tag">kind: infra · workflow-fix</span></h1>
<p><em>workflow-fix: GCP janitor must sweep the whole dedicated project, not just <code>eps-issue-*</code></em></p>

<section class="plan-tldr">
<h2>0.0 TL;DR (plain English)</h2>
<ul>
  <li><strong>What I'll do:</strong> The daily cleanup robot that deletes leftover GCP machines only ever looks at machines whose names start with <code>eps-issue-</code>. A leftover test machine with a different name ran for ~20 hours and quietly spent ~$14 because the robot literally couldn't see it. I'll make the robot look at <em>every</em> machine in our dedicated GPU account, not just the ones the launcher named.</li>
  <li><strong>What I expect:</strong> The launcher's own machines keep getting cleaned up exactly as before. Any <em>other</em> leftover machine now either gets cleaned up too (if its name says it's a throwaway probe) or pings my phone so nothing can ever silently bill for 20 hours again.</li>
  <li><strong>What would change my mind:</strong> If a machine in that account turns out to be something I genuinely want to keep alive long-term — then a blanket "delete anything old" rule would be dangerous, which is exactly why anything that isn't a known throwaway gets a heads-up instead of being auto-deleted.</li>
</ul>
</section>

<section class="plan-summary">
<h2>0. Plan Summary (technical)</h2>
<p>
<strong>Change:</strong> Broaden the GCP stale-VM janitor's inventory from <code>name~^eps-issue-</code> to the WHOLE dedicated project (<code>eps-persona-gpu-jun2026</code>), classify each listed instance as <code>managed</code> (<code>eps-issue-*</code>) / <code>allowlisted-ephemeral</code> (a configurable name-prefix allowlist, default <code>eps-cap-probe</code>) / <code>unmanaged</code>, and apply the chosen <strong>HYBRID</strong> posture: <code>managed</code> + <code>allowlisted-ephemeral</code> auto-DELETE on the EXISTING 24h-age / 10-min-terminal-phase fences; <code>unmanaged</code> WARN-and-escalate (Telegram + sidecar JSON, mirroring <code>vm_disk_guard.py</code>) — never auto-deleted.
<br><strong>Router pins untouched:</strong> <code>reconnect_or_none</code> / <code>_stale_named_instance_or_none</code> use EXACT <code>name=eps-issue-&lt;N&gt;</code> list filters, so broadening the JANITOR's filter cannot leak into the router's reconnect/reclaim namespace. <code>eps-issue-*</code> reap behavior is byte-for-byte unchanged.
<br><strong>Files:</strong> <code>src/explore_persona_space/backends/gcp.py</code> (reaper + classification + escalation helper), <code>scripts/gcp_audit.py</code> (preflight filter + JSON/summary + escalation routing), <code>scripts/cron_gcp_audit.sh</code> (messaging only), <code>.claude/rules/background-automation.md</code> + <code>CLAUDE.md</code> § Crons item 1b (docs), <code>tests/test_gcp_backend.py</code> (extend the audit block).
<br><strong>Hyperparameters:</strong> N/A — no training hyperparameters.
<br><strong>Compute:</strong> none — workflow-surface only. <code>Estimated GPU-hours (total): 0</code>
<br><strong>Acceptance:</strong> extended <code>tests/test_gcp_backend.py</code> green (the six purpose-named tests in §6); <code>uv run ruff check</code> + <code>uv run pytest tests/test_gcp_backend.py</code> pass; docs in sync with code; the CLI preflight + disarmed-janitor alarm still fire against the broadened filter.

<h2>1. Goal</h2>
<p>

<strong>Acceptance criteria:</strong> (a) the workflow gap is closed AS DEMONSTRATED by new tests in <code>tests/test_gcp_backend.py</code> — a non-<code>eps-issue-*</code> stale VM is classified and routed (reaped if allowlisted-ephemeral, escalated otherwise); (b) NO regression on the router-managed <code>eps-issue-*</code> paths (reconnect / stale-name-reclaim untouched; <code>eps-issue-*</code> reap behavior unchanged); (c) the CLI list-preflight + disarmed-janitor rc=3 alarm still fire against the broadened filter; (d) <code>background-automation.md</code> + the CLAUDE.md Crons paragraph are in sync with the new code.

<h3>4.1 <code>src/explore_persona_space/backends/gcp.py</code> (primary)</h3>
<p><strong>New module constants</strong> (near <code>_TERMINAL_GUEST_PHASES</code> / <code>_NONLIVE_INSTANCE_STATUSES</code>):</p>
<pre>
#: Janitor inventory filter for the dedicated project. `None` lists the WHOLE
#: project (the broadened backstop, #688) rather than only router-managed
#: eps-issue-* names. Exported so scripts/gcp_audit.py's preflight stays
#: byte-identical to the reaper's internal list.
JANITOR_LIST_NAME_FILTER: str | None = None

#: Router-managed instance name prefix. The ONLY names the GCP backend
#: auto-creates + reconnects/reclaims by name (eps-issue-&lt;N&gt;).
_MANAGED_NAME_PREFIX = "eps-issue-"

#: Non-managed name prefixes that are KNOWN-ephemeral throwaways — auto-reaped
#: by the janitor on the SAME bounded fences as managed VMs. Configurable so the
#: user can grow it as new probe-name patterns emerge. Default: the #680
#: flex-start capacity probes (eps-cap-probe*).
_EPHEMERAL_REAP_PREFIXES: tuple[str, ...] = ("eps-cap-probe",)

#: Name prefixes the janitor must NEVER reap OR escalate — a deliberate
#: opt-out for any long-lived instance that legitimately lives in the project.
#: Empty today (no such instance exists); the hook exists so the design does
#: not hard-assume "everything is disposable".
_JANITOR_KEEP_PREFIXES: tuple[str, ...] = ()


def _classify_janitor_instance(name: str) -> str:
    """Classify a listed instance by name → reap/escalate routing class.

    Returns one of: "managed" (eps-issue-*; router-owned, auto-reap),
    "allowlisted-ephemeral" (known throwaway prefix, auto-reap),
    "keep" (opt-out prefix; never touched), or "unmanaged" (everything
    else; escalate, never auto-delete).
    """
    if any(name.startswith(p) for p in _JANITOR_KEEP_PREFIXES):
        return "keep"
    if name.startswith(_MANAGED_NAME_PREFIX):
        return "managed"
    if any(name.startswith(p) for p in _EPHEMERAL_REAP_PREFIXES):
        return "allowlisted-ephemeral"
    return "unmanaged"
</pre>
