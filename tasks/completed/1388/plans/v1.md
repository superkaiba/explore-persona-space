The existing `_retry` already provides exactly the bounded transient retry the lint wants; the raw call is genuinely-correct.

## 10. §11 Decision Rationale

- **Waiver (not reroute) at all three sites.** *What:* `# HUB_VERIFY_RETRY_EXEMPT: <reason>` comment per site. *Why:* each site already carries genuine bounded local transient retry, and every reroute option changes semantics on frozen SHA-pinned experiment scripts (recursive walks, path strings vs entry objects with `.size`, raise vs documented fallback); the lint's own docstring names the waiver as the sanctioned path for genuinely-correct raw calls. *Source:* `scripts/workflow_lint.py:6133-6180` (check docstring, esp. lines 6152-6174) + incident lineage #920/#997/#1202 cited therein; consumer reads at `issue1073_greedy_cloud_distribution.py:100-113`, `issue1092_inline_operator_stage.py:86-111`, `issue1345_framing_dashboard.py:130-153`. *Alternatives rejected:* (a) `list_hf_files_under_path` reroute — semantic drift per site (§3); (b) `hub.retry_transient(lambda: api.list_repo_tree(...))` — still flagged by design (docstring lines 6152-6156), buys nothing; (c) allowlist addition — frozen by design ("a NEW file is never added", line 6169-6170) and banned by the task constraints.
- **Waiver reason wording.** *What:* each reason names the specific local retry wrapper making the raw call genuinely-correct (`issue1073_common._retry` / `local _retry (6 tries...)` / `inline 4-attempt retry loop + documented filename fallback`). *Why:* the waiver is a justification, not a token bypass — the reason must let a future reader re-verify correctness without archaeology; ≥ 10-char floor enforced mechanically. *Source:* `workflow_lint.py:1769-1770` (`HUB_VERIFY_WAIVER_RE`, `HUB_VERIFY_WAIVER_MIN_REASON_CHARS`) + the same convention's precedent in `WANDB_INTENTIONALLY_DISABLED` (`.claude/rules/code-style.md`). *Alternatives:* a terse generic reason ("locally retried") — rejected as un-auditable.
- **Placement: preceding-comment-line (not inline suffix).** *What:* each waiver is its own comment line directly above the flagged call line. *Why:* avoids E501 pressure on the call line, reads cleaner, and is a tested-supported placement. *Source:* `_hub_verify_waiver_present` (`workflow_lint.py:6075-6093`) + `tests/test_workflow_lint.py:3767` (`_pass_waiver_previous_line`). *Alternatives:* inline suffix on the call line — equally valid per `:3781`, kept as fallback if a reviewer prefers it.
