# Plan — #1033: poller CPU-phase stall predicate (output-file mtime fold) + per-instance idle counter

### 0.0 TL;DR (plain English)

- **What I'll change:** two monitoring fixes. (1) The pod poller will check whether the run has *written any output file recently* (not just log files) before calling a quiet CPU phase "stalled" — the exact signal humans used to dismiss #813's false alarms by hand. (2) The "GPUs idle for N minutes" advisory will reset its clock whenever the run restarts on a fresh instance, instead of carrying a 543-minute counter onto a 17-minute-old VM.
- **What I expect:** the #813-class false stalls disappear in the one remaining window #951's CPU-rate veto doesn't cover (degraded CPU probe), and idle-minute advisories never exceed instance age. All existing true-positive detections (the #664 hung-vLLM class) keep firing — pinned by replay tests.
- **What would change my mind:** if the pod-side `find` over output dirs can't be made bounded + narrow (other pods' writes coupling into the verdict, or a wedged filesystem hanging the probe), I drop the output fold to a `.done`-sentinel-only probe or abandon ask 1 with a written rationale.

### 0. Plan Summary (technical)

## 3. Design

### 3.1 Ask 1 — output-file mtime fold (`scripts/poll_pipeline.py` only)

**Lane scoping:** the stall conjunction + zombie override live in `poll_once` (RunPod lane; `RunPodBackend.poll` delegates here). The GCP lane classifies via guest attributes (`eps/phase`), never log mtimes — #813's false stalls were RunPod-lane verdicts (`stalled/vllm_worker_dead_zombie_gpu`). **Ask 1 touches `poll_pipeline.py` only; no GCP change.**

**(a) Probe addition in `_ssh_probe` (rides the same single heredoc).** New `output_probe` block emitting one scalar `OUTPUT_MTIME_EPOCH=<epoch|0>`:

```sh
# output-artifact freshness probe (#1033): a CPU-bound analysis tail that
# writes per-cell NPZs / JSONs / .done sentinels while every log is quiet.
# Bounded: short-circuit find (-print -quit) under timeout; issue-keyed
# dirs only (same narrowness contract as the #488/#521 shard globs).
OUT_CUTOFF_STALL=$((POD_NOW - {stall_sec}))
OUT_CUTOFF_VETO=$((POD_NOW - {veto_window_sec}))          # max(stall_sec, ZOMBIE_VETO_FRESH_SEC)
OUT_HIT=$(timeout {find_timeout} find \
    /workspace/explore-persona-space/eval_results/issue_{N} \
    /workspace/explore-persona-space/eval_results/issue_{N}_* \
    /workspace/explore-persona-space/data/issue_{N} \
    /workspace/explore-persona-space/data/issue{N} \
    -type f -newermt "@$OUT_CUTOFF_STALL" -print -quit 2>/dev/null)
if [ -z "$OUT_HIT" ] && [ "$OUT_CUTOFF_VETO" -lt "$OUT_CUTOFF_STALL" ]; then
  OUT_HIT=$(timeout {find_timeout} find <same dirs> -type f \
      -newermt "@$OUT_CUTOFF_VETO" -print -quit 2>/dev/null)
fi
if [ -n "$OUT_HIT" ]; then
  echo "OUTPUT_MTIME_EPOCH=$(stat -c %Y "$OUT_HIT" 2>/dev/null || echo 0)";
else echo OUTPUT_MTIME_EPOCH=0; fi
```

Notes: `POD_NOW` is already captured pod-side (`POD_NOW_EPOCH`, L1390) so cutoffs use the pod clock — no VM↔pod skew. The two-stage find prefers a within-stall hit (rescues the conjunction) and only falls back to the wider veto window when it is genuinely wider (`ZOMBIE_VETO_FRESH_SEC` default 60 < `stall_sec` default 900, so the common case is ONE find). `find … -print -quit` short-circuits on the first fresh file — on a healthy actively-writing phase this returns almost immediately; on a genuinely stalled run it scans metadata once, bounded by `timeout` (default 10s, env `EPM_POLL_OUTPUT_FIND_TIMEOUT_SEC`). Missing dirs / timeout / no GNU find → empty → `OUTPUT_MTIME_EPOCH=0` (fail-safe). The dir set is exactly the issue-keyed layouts (`issue_<N>` / `issue_<N>_*` / `issue<N>`) — the same narrowness contract the docstring mandates for the shard globs ("a bare `issue_<N>*` glob would let issue 5 match issue 521's directories" — we match `issue_{N}` exactly, `issue_{N}_*` with the underscore separator, and the `data/issue{N}` no-underscore convention from the #854 sweep list). Grounding for the dirs: #813's analysis tail wrote `eval_results/issue_813/{summary.json, delta_floor/, substrate_swap_null/, chain_rho/}` + `accum_ckpt.npz` scratch checkpoints (task #813 Repro footer), and the project's canonical pod-side output roots are `eval_results/issue_<N>{,_*}/` and `data/issue_<N>/` + `data/issue<N>/` (Upload Policy; gcp.py crash-persist sweep list). `_ssh_probe` gains a `stall_sec: int` parameter (threaded from `poll_once`, which already has it) plus the module consts.

**(b) Parser + threading.** Add `"OUTPUT_MTIME_EPOCH"` to `_PROBE_SCALAR_KEYS` (L1441) with default `"0"` in `_parse_probe_stdout`; compute `output_mtime_ago` in `poll_once` through the SAME pod-clock-cancelling staleness helper the other mtimes use (the `pod_now_epoch`-anchored computation at ~L3813/L4009). `OUTPUT_MTIME_EPOCH=0` → `output_mtime_ago` = huge → stale → pre-fix behavior.

**(c) Stall conjunction (L4138–4143) gains a 5th conjunct:**

```python
elif (
    last_mtime_ago > stall_sec
    and phase_log_mtime_ago > stall_sec
    and shard_log_mtime_ago > stall_sec
    and output_mtime_ago > stall_sec          # NEW (#1033)
    and gpu_idle
):
```

Fresh output behaves exactly like a fresh shard log: the conjunction is unmet, verdict stays `running`, no new "override" concept, no new stall_reason values. (Deliberately NOT wired to `cpu_override_active`/adaptive-interval: a fresh output file is first-class liveness, same class as a fresh log.)

**(d) Zombie override veto term.** `_apply_zombie_override` gains `output_mtime_ago: float = float("inf")` (keyword-only, defaulted so every existing caller/test is unchanged = fail-safe). Inside, the #826 stale-log conjunction extends: logs-stale requires `output_mtime_ago > max(ZOMBIE_VETO_FRESH_SEC, stall_sec)` as well; a fresh output within the window vetoes with **streak reset** (identical mechanics + log wording to the fresh-log veto). `poll_once` threads the computed `output_mtime_ago` at the L4164 call site.

**(e) Kill switch + docs.** Module-level `OUTPUT_MTIME_FOLD_ENABLED = os.environ.get("EPM_POLL_OUTPUT_MTIME_FOLD", "1") != "0"` — default ON (unlike #864's default-OFF: this fold can only *suppress* stall verdicts, and a genuinely hung run writes no outputs, so the #664 true positive stays reachable; the residual exposure — a same-issue sibling process, e.g. a detached uploader, touching issue-keyed files during a true hang — is the SAME accepted exposure class as the #826 fresh-log sibling, documented in the docstring). When disabled, the probe block is omitted and `output_mtime_ago = inf`. Update the module docstring (stall-threshold paragraph gains conjunct (e); a new "Staleness ALSO folds in output artifacts (#1033/#813)" paragraph in the established per-incident format).

### 3.2 Ask 2 — per-instance idle counter

**(a) GCP lane (`scripts/backend_poll.py`) — attempt-id keying (primary identity).** New pure helper + one wiring change in the `handle.backend == "gcp"` block (L3194–3273):

```python
_IDLE_ADVISORY_STATE_KEYS: tuple[str, ...] = (
    "gpu_idle_since_epoch",
    "gpu_idle_advised_phases",
    "gpu_idle_escalated_phases",
)

def _scope_idle_state_to_attempt(
    prev_state: dict[str, str], attempt_id: str | None
) -> dict[str, str]:
    """Reset the idle-advisory clock when the instance identity changed (#1033).

    attempt_id is fresh per genuinely NEW instance and label-stable on
    reconnect (#927; gcp.py reconnect recovery), so a mismatch means the
    stored span belongs to a PREVIOUS instance (#763: '543 min' on a
    ~17-min-old VM). Fail-safe: an absent/empty current attempt_id keeps
    the state verbatim (pre-fix behavior). A stored-key MISS with a known
    current id also resets — the migration path for pre-#1033 state files,
    failing toward a delayed/duplicate advisory, never a stale counter
    (same cheaper-failure direction as _tripwire_run_scope's malformed-
    anchor branch).
    """
    if not attempt_id:
        return prev_state
    if prev_state.get("idle_attempt_id", "") == attempt_id:
        return prev_state
    return {k: v for k, v in prev_state.items() if k not in _IDLE_ADVISORY_STATE_KEYS}
```

Wiring: after `prev_gpu_idle_state = _load_gpu_idle_state(...)` (L3209), insert `current_attempt_id = str(handle.extra.get("attempt_id") or "")` and `prev_gpu_idle_state = _scope_idle_state_to_attempt(prev_gpu_idle_state, current_attempt_id)`. Pass the scoped state into `_maybe_post_gpu_idle_advisory` and `_maybe_escalate_gpu_idle` (replacing the verbatim `prev_gpu_idle_state` reads); ALSO pass `tripwire_state` (below) so the run-scope clear reaches the idle calls. Persist `"idle_attempt_id": current_attempt_id or prev_gpu_idle_state.get("idle_attempt_id", "")` in the `_save_gpu_idle_state` payload (L3260). Update the L3215–3220 comment (the "idle keys untouched" contract is the bug being fixed).

**(b) Shared run-scope extension (`scripts/poll_pipeline.py`) — covers the RunPod lane and belt-and-suspenders on GCP.** Extend the clear set:

```python
_RUN_SCOPED_STATE_KEYS: tuple[str, ...] = _TRIPWIRE_STATE_KEYS + (
    "gpu_idle_since_epoch",
    "gpu_idle_advised_phases",
    "gpu_idle_escalated_phases",
)
```

`_tripwire_run_scope` clears `_RUN_SCOPED_STATE_KEYS` instead of `_TRIPWIRE_STATE_KEYS` (anchor semantics, tolerance, and all four fail-safe branches byte-unchanged; docstring updated to name the idle keys + #1033). In `poll_once`, MOVE the `run_age_sec = _run_launched_age_sec(...)` + `_tripwire_run_scope(...)` block (currently L4223–4226) ABOVE the gpu-idle advisory call (L4187) and pass `tripwire_state` as `prev_state` to `_maybe_post_gpu_idle_advisory` and `_maybe_escalate_gpu_idle` (the width advisory keeps its existing `tripwire_state` input; the zombie override at L4164 stays on the raw `prev_state` — `zombie_streak` scoping is out of scope). RunPod identity signal: a pod relaunch posts a fresh `epm:run-launched` (new pid), which is exactly the anchor's trigger. Fail-safes inherited and already tested: unknown run age → keep state (no reset); malformed anchor → clear (re-arm, cheaper failure); first anchor → adopt + keep.

**(c) Identity-key decision (the brief's ask): `attempt_id` over instance-creation timestamp, run-epoch anchor as the cross-lane mechanism.** `attempt_id` is (i) already ON the handle at poll time (no extra `gcloud describe` call per tick to fetch creation ts), (ii) documented reconnect-stable / fresh-per-new-instance (#927 + the gcp.py label-recovery block), (iii) string-comparable with a trivial fail-safe. Instance creation timestamp would require a per-tick API probe or new sidecar plumbing and adds a clock-comparison edge; rejected (recorded in §11). The RunPod lane has no handle in `poll_once`, so it keys on the `epm:run-launched` epoch via the existing anchor — symmetric semantics ("reset on relaunch"), different but pre-existing mechanism.

## 11. Decision Rationale

- **Output-freshness as a conjunct + veto term, not a new override.** *Why:* identical semantics to a fresh shard log (first-class liveness), so it inherits the tested conjunction/veto shape; no new stall_reason, no orchestrator-side changes. *Source:* #488/#521 fold precedent (module docstring L163–193) + #826 veto mechanics (`_apply_zombie_override` docstring). *Alternatives:* a `cpu_override_active`-style override flag (rejected: adds an adaptive-interval concept for what is plain liveness).
- **Glob set = `eval_results/issue_<N>{,_*}` + `data/issue_<N>` + `data/issue<N>`.** *Why:* #813's tail wrote under `eval_results/issue_813/` (+ NPZ scratch); these are the project's canonical pod-side output roots. *Source:* #813 clean-result Repro footer; Upload Policy; the #854 crash-persist sweep list (gcp.py) which pins the same `data/` dual convention. *Alternatives:* broad `/workspace` recursive scan (rejected — the docstring's cross-pod-coupling ban); `.done`-sentinels-only (kept as the kill-criterion fallback).
- **Two-stage short-circuit `find -newermt` under `timeout`, default 10s.** *Why:* boolean freshness is all the verdict needs; `-print -quit` makes the healthy case O(first fresh file); `timeout` bounds the wedged-FS worst case; 10s sits far under the probe's SSH budget while dwarfing a normal metadata scan. *Source:* the brief's boundedness constraint + gotchas' MooseFS wedge entry; `ungrounded — needs smoke-test` on the exact 10s value (any 5–15s value acceptable; verified only by the unit text-assertion + first live tick).
- **Default-ON with `EPM_POLL_OUTPUT_MTIME_FOLD` kill switch (vs #864's default-OFF).** *Why:* asymmetric risk — the fold only suppresses stall verdicts, and a hung run writes no outputs, so the #664 true positive is unreachable by this veto; #864 shipped OFF because its veto COULD mask a true total collapse. *Source:* #864 gate rationale (module docstring L112–135), inverted by the risk direction.
- **GCP identity key = `handle.extra["attempt_id"]`.** *Why:* on-handle at poll time (zero extra API calls), fresh per new instance, label-recovered on reconnect. *Source:* #927 semantics; `gcp.py` L4405 (launch) + L3212–3248 (reconnect recovery). *Alternatives:* instance creation timestamp (rejected: needs a per-tick describe or new plumbing); `job_id`/instance_id (kept as fallback — equivalent uniqueness, less documented reconnect semantics).
- **RunPod identity = extend `_tripwire_run_scope`'s clear set.** *Why:* the anchor + four fail-safe branches are already tested (test_poll_eta_tripwire.py L358–410); a pod relaunch always posts fresh `epm:run-launched`; inventing a second anchor duplicates state machinery. *Source:* #873 AC#6 implementation. *Alternatives:* marker-pid keying (rejected: pid reuse ambiguity; the epoch anchor already encodes launch identity).
- **Reset-on-missing `idle_attempt_id` (migration).** *Why:* keep-on-missing would preserve the live #763-class stale span indefinitely for phase-stable instances; reset costs at most one delayed/duplicate advisory. *Source:* `_tripwire_run_scope`'s malformed-anchor rationale ("cheaper failure = one duplicate advisory, never a suppressed one"), same direction.
