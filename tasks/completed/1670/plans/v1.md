# Plan — #1670 workflow-fix: session-reconcile pass must never stop the watcher's own just-spawned recovery session

## 0.0 TL;DR (plain English)

- **What I'll run:** I'll teach the watcher's session-reconcile pass three new things before it stops a session on a finished task: (1) check whether a session was spawned recently (registration `spawned_at`), (2) check whether the session's own transcript is actively being written, and (3) check whether the watcher itself just respawned a merge-recovery session on this task (the `completed-unmerged-respawn` marker). Then I'll pin all of it with unit tests.
- **What I expect:** the exact #1622 incident replay (a 10-minute-old recovery session on a 27.5h-quiet completed task) is spared, while a genuinely dead session with no signals at all is still reaped exactly as today.
- **What would change my mind:** if the pin tests show any existing reconcile behavior changing (an old idle session surviving that used to be stopped, or the no-signal reaping default breaking), I'd shrink the change to the marker exemption alone.

### 4.1 New constant (near the session-reconcile section, next to `SESSION_RECONCILE_STATE_PREFIX` ~`:19114`)

```python
# #1670: hard TTL on the completed-unmerged-respawn exemption. Bounds the
# worst case (recovery session wedges; neither epm:merged nor any
# done-transition ever lands) so the exemption cannot shield an idle
# session forever — the 2026-06-10 disk-incident class this pass exists
# to reap. 24h is generous vs the <1h expected Step-10d merge recovery
# and tiny vs the incident scale. Module constant by design (no env knob:
# the file's knob pattern is reserved for operator-tuned thresholds; tests
```

### 4.2 New helpers (adjacent to `_task_session_followup_active`, ~`:19074`)

```python
def _latest_note_sentinel_ts(events: list[dict], sentinel: str) -> float | None:
    """Newest epoch ts among events whose note carries ``sentinel``.

    The note-sentinel complement of ``_latest_event_ts``: watcher-attributed
    markers are all kind epm:progress, so a KIND-keyed scan cannot see them."""
    best: float | None = None
    for ev in events:
        if sentinel in (ev.get("note") or ""):
            ts = _parse_event_ts(ev.get("ts"))
            if ts is not None and (best is None or ts > best):
                best = ts
    return best


def _task_recovery_respawn_active(
    issue: int, events: list[dict] | None = None, now: float | None = None
) -> bool:
    """True iff the watcher's own completed-unmerged respawn (#1653 arm)
    plausibly still owns a live recovery session on this issue (#1670)."""
    if events is None:
        events = _task_events(issue)
    respawn_ts = _latest_note_sentinel_ts(
        events, _COMPLETED_UNMERGED_RESPAWN_NOTE_SENTINEL
    )
    if respawn_ts is None:
        return False
    now = now if now is not None else time.time()
    if not (0 <= now - respawn_ts <= SESSION_RECONCILE_RESPAWN_TTL_S):
        return False  # past TTL (or future-dated — clock-skew guard)
    settled = _latest_event_ts(events, _SESSION_DONE_TRANSITION_KINDS | {"epm:merged"})
    return settled is None or respawn_ts > settled
```

Semantics: the exemption arms when the respawn marker is (a) within the TTL and (b) newer than every SETTLING marker — the pass's existing done-transition set PLUS `epm:merged` (the marker whose absence the completed-unmerged pass exists to fix; its arrival ends the recovery episode, mirroring that pass's own `recovered` pruning). Deliberate divergence from the `followup_active` twin: a missing done-transition does NOT defeat the exemption (the TTL bounds it; rationale §11 Q2b).

### 4.3 Session-age signal helper (adjacent to `_registry_spawned_at`, ~`:7462`, or next to 4.2)

```python
def _newest_registration_spawned_at(issue: int) -> float | None:
    """Newest ``spawned_at`` across ``issue-<N>.json`` AND
    ``manual-issue-<N>.json`` (fail-soft -> None). A fresh value is a
    SESSION-level activity signal for the reconcile pass: a just-spawned
    session may not have posted any marker yet (#1670)."""
    best: float | None = None
    for prefix in ("issue-", "manual-issue-"):
        try:
            entry = json.loads(
                (AUTONOMOUS_REGISTRY_DIR / f"{prefix}{issue}.json").read_text()
            )
        except (json.JSONDecodeError, OSError):
            continue
        ts = entry.get("spawned_at") if isinstance(entry, dict) else None
        if isinstance(ts, int | float) and not isinstance(ts, bool) and ts:
            best = float(ts) if best is None else max(best, float(ts))
    return best
```

(`_registry_spawned_at` at `:7466` reads only `issue-<N>.json`; the manual file must count too — a user-driven recovery session registered via `register-current` is the flag marker's own documented recovery path. `_registry_spawned_at` is left untouched: its crash-arm/auth-outage consumers key deliberately on the AUTO file only.)

### 4.4 `_session_idle_signals` extension (`:19356`)

New keyword-only params, both defaulted so every existing call/test is unchanged:

```python
def _session_idle_signals(
    issue: int,
    now: float,
    *,
    sids: tuple[str, ...] | list[str] = (),
    pids_by_sid: dict[str, int] | None = None,
) -> tuple[bool, str, list[dict]]:
```

Body delta (after the existing two-signal `ages` build):

```python
    # #1670 session-level signals (incident: a 10-min-old recovery respawn
    # read as 27.5h idle off the TASK's marker gap). Each signal is
    # OPTIONAL — unreadable contributes nothing — so the deliberate
    # "no signal at all -> idle" reaping default is preserved: the floor
    # only ever protects provably YOUNG (fresh spawned_at) or provably
    # ACTIVE (fresh transcript) sessions.
    spawned = _newest_registration_spawned_at(issue)
    if spawned is not None:
        ages.append(max(0.0, now - spawned))
    idle = (min(ages) >= _session_idle_s()) if ages else True
    if idle and pids_by_sid:
        # Transcript mtime = the truest per-SESSION activity signal.
        # Probed LAZILY: only when the cheap task-level signals already
        # read idle (zero cost on the common fresh-activity path).
        for sid in sids:
            pid = pids_by_sid.get(sid)
            if isinstance(pid, int):
                t_age, _reason = _transcript_idle_age_s(pid, now)
                if t_age is not None:
                    ages.append(t_age)
        idle = (min(ages) >= _session_idle_s()) if ages else True
    gap_desc = f"{min(ages) / 3600:.1f}h" if ages else "no-signal"
    return idle, gap_desc, events
```

Note the divergence from `decide_idle_unmapped`'s freeze-on-None posture is deliberate: THIS pass's "no signal → idle" default must stay intact so parked tasks with dead sessions still reap (task-body constraint); an unresolvable transcript here simply contributes nothing (§11 Q1b).

## 5. Controls / edge cases

| Edge case | Behavior under this design | Why safe |
|---|---|---|
| No signal at all (dead session, parked task, no registration/markers/transcript) | `ages` empty → `idle=True` → reap path unchanged | Pin test 3; the brief's explicit constraint |
| STALE registration `spawned_at` (older than idle window) | contributes an age ≥ threshold → does not flip idleness | floor protects only provably-young sessions |
| Registration deleted same-tick by the crash arm (the #1622 class) | transcript signal + respawn-marker exemption still protect | §2 forensics — the two signals verified present |
| Respawn marker post FAILED at spawn (fail-soft `_post_progress_marker`) | registration signal (same-tick window) + transcript signal still protect | layered signals |
| Transcript unresolvable (`_transcript_idle_age_s` → None) | contributes nothing → falls back to today's behavior | wrong-signal-worse-than-missing per the helper's own docstring |
| Recovery session merges then lingers idle | `epm:merged` settles the exemption → reaped after the 2h grace | bounded leak |
| Recovery session wedges (no merged, no done-transition ever) | TTL (24h) expires the exemption → reaped | bounded leak, one session ≤24h |
| Future-dated respawn marker ts (clock skew / garbled) | `0 <= now - ts` guard → exemption off | mirrors the auth-outage guard's skew check |
| Task later archived (`epm:status-changed` newer than respawn marker) | settling marker flips exemption off | correct re-arm |
| Old zombie sibling sid + young respawn on one issue | per-issue grain: both kept while the young one is fresh/active; zombie reaped once the issue idles | identical to today's marker-clock semantics (§11 Q1a); no new leak class |
| `keep_running` / `followup_active` present | precedence unchanged (checked before the new arg) | pinned ordering test |
| Dry-run / alert-only postures | untouched — the new branch returns before the miss counter like the other skips | skip pattern reuse |
| `_check_stop_verification` zombie path | unchanged — runs before `decide` on `stopped_at` state | no interaction (new signals only shape `idle`/skips) |

## 11. Decision Rationale

**Q1a — where does the session-age/activity check belong: `_session_idle_signals` (per-issue) or a per-SESSION stop filter in the caller?** → **Inside `_session_idle_signals`, per-issue grain.** Evidence from the caller's structure (§2): the decision, miss counter, state file, `stopped_at` map, and stop-verification are ALL per-issue; `_handle_session_stop`'s bookkeeping (`missed=0 if len(stopped)==len(sids)`) assumes `sids` is the issue's full live set. A per-sid filter would require partitioned state, partial-stop semantics in `_check_stop_verification`, and a new decide() action for the all-young case — a materially larger diff. The cost of per-issue grain (an old zombie sibling survives while a young/active sibling is fresh) is ALREADY today's semantics: any sibling posting markers refreshes the shared per-issue clock. No new leak class; the zombie reaps once the issue idles. Source: read from code (`:19386–19714`).

**Q1b — signal choice.** Registration `spawned_at` alone is insufficient (the crash arm deletes the AUTO registration same-tick at TERMINAL — §2 forensics), so the design layers: `spawned_at` (covers manual registrations + the pre-delete window; cheap), transcript mtime (the true session-level activity; existing helper + existing main() pid snapshot, zero new IPC), and the respawn-marker exemption (the only signal verified durable across the whole incident window). Daemon `sessions.json` metadata was measured and REJECTED as an age source: it carries no creation timestamp (`lifecycleStateSince`/`savedAt` are state-change/save times — verified live 2026-07-25). The #720 breadcrumb was considered and REJECTED: written only when the sid already propagated into that tick's `live_ids` (not guaranteed seconds post-spawn), redundant with the marker+transcript pair, and it would add a fourth read for a double-failure corner. Missing signals contribute nothing rather than freezing the counter (the `decide_idle_unmapped` posture) because THIS pass's "no signal → idle" reaping default is a deliberate, task-body-pinned invariant. Source: read from code + live measurements this session.

**Q2 — respawn-marker exemption: widen the followup predicate's kind set, or a separate explicit arg?** → **Separate predicate + new `recovery_respawn_active` kwarg / `"respawn-skip"` action.** Mechanical reason: widening `_SESSION_FOLLOWUP_SIGNAL_KINDS` CANNOT express this signal at all — the respawn marker is kind `epm:progress` distinguished only by its note sentinel, and `_task_session_followup_active` is kind-keyed. Semantic reasons: the followup kind set is shared documentation-wise with the pod-safety twin (`_POD_FOLLOWUP_SIGNAL_KINDS`) and its semantics are pinned by docstring + tests; a separate arg keeps `decide_session_reconcile` purely additive (defaults preserve every pinned case) and gives the audit log a distinct action label. Source: read from code (`:19049–19073`, `:3102` pod twin).

**Q2b — twin divergence on missing done-transition.** `_task_session_followup_active` returns False when no done-transition parses (defensive). Our predicate returns True there: the exemption is TTL-bounded (so it cannot leak indefinitely), the respawn marker only ever fires on `completed`-status tasks (which have a status-changed by construction — the None case means a parse corner), and the failure direction of False is precisely the incident (killing the recovery session and consuming the once-per-episode budget). Documented in the docstring; pinned by test 2. Source: read from code + #1622 incident.

**Q3 — settling set = done-transitions ∪ {`epm:merged`} + 24h TTL, no env knob.** `epm:merged` is the completed-unmerged pass's own episode-resolved signal (its pruner marks episodes `recovered` on it) — the exemption should end exactly when the episode it protects ends; the TTL bounds the wedged-recovery corner. The age FLOOR reuses `_session_idle_s()` per the task constraint (no new knob); the TTL is a module constant, not an env knob, per the same "only if genuinely needed" constraint — nothing operator-tunable about it, tests monkeypatch. Source: read from code (`completed_unmerged_pass` `:7128`, episode pruning) + task-body constraint.
