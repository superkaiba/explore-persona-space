## 0.0 TL;DR (plain English)

- **What I'll run:** I'll add one new sizing rule to
  `.claude/rules/plan-compute-sizing.md`: when an experiment trains N cells
  on one machine and keeps each cell's outputs on disk, the plan must budget
  the disk for ALL N cells' outputs added together at the end of the run —
  or explicitly build a "delete each cell's outputs after they're uploaded"
  step into the driver. I'll also add the matching REVISE trigger to the
  critic's checklist, a pin test so the prose can't be silently dropped, and
  a 22-byte trigger update to the always-on lessons index.
- **What I expect:** future fan-out plans stop dying the way #1481 did —
  three machines filled a 200 GB disk with 24 training runs' kept outputs
  (all of them already safely uploaded, so deleting locally was always
  legal) and crashed hours in.
- **What would change my mind:** if a careful re-read showed an existing
  rule already requires this sum. I checked: the merge-disk rule only
  triggers on full-precision (~15 GB) merged copies and bounds the
  *concurrent transient* high-water mark, and the ladder rule only bounds
  per-rung checkpoints *within one* training run — neither sums small
  retained outputs *across cells* at end-of-run, which is exactly the
  #1481 shape. Details in § Kill criteria.

## 2. Prior Work (in-repo precedent — no web search needed for a repo-doc fix)

The target file already carries three disk-sizing blocks; the new block
composes with, and does not duplicate, each:

1. **Merge-disk budget (#653, L48-74).** Trigger: "materializes
   full-precision model artifacts DURING iteration" (merged ~15 GB copies,
   ZeRO-3 consolidations). Bound: COEXISTING transients —
   `n_cells × max_concurrent_artifacts_per_cell × per_artifact_size_gb` —
   with a cleanup pattern so the *high-water mark* stays under quota. The
   `n_cells` factor multiplies CONCURRENT transients; a LoRA fan-out whose
   per-cell outputs are sub-GB adapter checkpoints legitimately reads this
   block as N/A (the item-16 escape is literally "N/A — no transient
   full-precision merges") and still dies at end-of-run. The new block is
   the RETAINED-accumulation sibling: monotone sum across cells, small per
   cell, no full-precision trigger.
2. **Dose-ladder retention (#1133, L77-131).** Bounds per-RUNG checkpoints
   WITHIN one training run (retain dose-selected + latest, delete ruled-out
   rungs between rungs; keep-all is the justified #1112 exception). It says
   nothing about N runs side by side: #1481's cells each behaved fine
   individually — the SUM across 24 cells filled the disk. The new block is
   the cross-cell sibling; the per-rung default still applies inside each
   cell unchanged.
3. **Out-root mount binding (#1414, L134-186).** Binds WHERE the bytes land
   + the per-phase preamble assert. #1481's `_assert_headroom` re-check IS
   this block working as designed — it converted a mid-write ENOSPC into a
   clean rc=1 poweroff. The new block fixes the SIZING so the assert stops
   firing; the mount block's "Siblings:" sentence (L179) gets the new block
   added to its "size WHAT accumulates" list.
4. **#1112 keep-all exception** (inside block 2) stays ladder-scoped and
   untouched — a fan-out that genuinely must retain everything locally
   satisfies the new block by the summed sizing arm (that IS its "keep-all"
   form), so no second exception mechanism is needed.
