# Plan v1 — #1966 daily-fix: never push to a branch live boxes sync mid-run

## 1. Requirement + acceptance criteria

**Requirement.** Add a workflow-surface rule banning an orchestrator push to a
branch that live workers pull/sync mid-run while ANY live worker holds local
modifications to the touched files, with the three sanctioned alternatives
(pin lanes to a detached launch SHA; defer the patch until every running
worker has passed its sync step; land the fix worker-locally and push after
the wave drains).

**Incident (grounding).** #1739 (session 55419495, 2026-07-30/31): the
orchestrator pushed a dispatcher patch commit to the issue branch that live
GCE boxes `git sync` at their upload step, while those boxes carried box-local
surgery on the same file; the sync refused on the dirty touched paths and 3
lanes (216 cells each, fits rc=0) died at their upload legs. Science recovered
from EXIT-trap crash bundles; ~5-6 GPU-h re-compose + one failed mid-run SSH
patch attempt.

**Relationship to landed sibling #1880 (commit b048109f98, closed
2026-08-01T14:43Z — AFTER this task was filed).** #1880 covers the PUSH-race
direction in `.claude/rules/pod-side-reporting.md` § Result-push verification
contract: worker-side fetch+rebase before every results-git push, plus an
orchestrator-side advisory ("avoid pushing to the issue branch while lanes are
mid-run when feasible"). It does NOT cover THIS task's PULL/SYNC direction —
a worker's mid-run sync refusing on DIRTY TOUCHED PATHS — nor the
pin-to-detached-SHA / defer / worker-local mitigations. The new rule must
CROSS-REFERENCE #1880's bullet (one mid-run-push doctrine, two failure
directions), never duplicate it.

**Acceptance criteria.**
1. `.claude/rules/crash-fix-rounds.md` gains a new `###` subsection

   dirty-touched-paths refusal mechanism (worker sync refuses on locally
   modified touched paths regardless of byte-identical content; death fires

   push), the #1739 incident citation, the three alternatives (a)/(b)/(c),
