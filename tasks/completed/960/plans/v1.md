### Final proposed bullet text (VERBATIM — the implementer passes it through)

```
- **fp32 kernel-parity gates comparing a cuDNN RNN path against plain ATen matmuls diverge ~2e-4 on H100/A100 with CORRECT math — run the parity gate on a float64 clone at ~1e-8 tol; never loosen the fp32 tol.** `torch.backends.cudnn.allow_tf32` defaults TRUE while `torch.backends.cuda.matmul.allow_tf32` defaults FALSE (verified torch 2.8.0), so an fp32 parity assert comparing a cuDNN RNN kernel path (`nn.GRU`/`nn.LSTM`, even a length-1 unroll) against plain ATen matmuls (`nn.GRUCell` / a hand-rolled reference) puts the two sides on DIFFERENT numeric paths — the cuDNN side computes in TF32, the reference in true fp32 — and the gate fails any ~1e-4 tolerance at ~2e-4 max-abs-diff even when the implementation is exactly right: kernel precision, not implementation parity (true fp32 accumulation noise at tiny toy dims is ~1e-7). Differential diagnosis (seconds, on the failing GPU): run the gate as-is (TF32-on: 1.86e-4 FAIL), re-run under `torch.backends.cudnn.allow_tf32 = False` (1.88e-6 PASS), then in float64 (1.11e-16) — the three-point signature confirms TF32 vs a genuine math bug. Fix: run the kernel-parity gate on a float64 deep-copy clone of both modules (TF32 is fp32-only, so the kernel gap vanishes — measured fp64 noise 1.1e-16) at a TIGHT ~1e-8 tolerance, so a real transposed-weight / wrong-gate bug still fails loudly; keep a loose (~1e-2) fp32-vs-fp64 cross-check for the production dtype; and keep exercising the exact dispatched functions (the hollow-verification-gate rule, `.claude/rules/code-style.md`). Do NOT loosen the fp32 tolerance to ~1e-3 — that usually stops catching real bugs. Same "parity gate fails with correct math" family as the bf16 single-position equivalence-gate entry above (a wrong bar on the right function), but DISTINCT from the L4-vs-A100 gauge-origin-hardware entry directly above: that one is CROSS-hardware (the gauge was minted on different silicon, and the fix is matching the launch intent to the origin hardware); this one is two kernel paths on ONE GPU, and switching hardware will NOT fix it. Long-form: `.claude/agent-memory/experiment-implementer/feedback_cudnn_tf32_fp32_parity_gate.md`. Closed regression: #841 r21 gru-source-only (attempt-8 crash, 1.86e-4 vs 1e-4 tol, 2026-07-03; fix commit `5ab0f95f7a`).
```
