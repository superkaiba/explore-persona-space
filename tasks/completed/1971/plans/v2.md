# Plan v2 — #1971 daily-fix: report TTY-attached unmapped idle sessions

architectural: false

## Requirement + acceptance criteria

Add an **escalate-only (never-stop) report lane** to the watcher's idle-unmapped
pass for **TTY-attached, unmapped, EPS-cwd** sessions whose transcript has been
idle beyond ~48 h. Today `decide_idle_unmapped` returns `("clear", 0)`
unconditionally on `has_tty` (scripts/autonomous_session_watch.py:26412) and the
pass never even stats the transcript for TTY sessions
(`_process_idle_unmapped`: the idle read is gated on `not mapped and not
has_tty`, line ~26954) — so multi-day accumulations of TTY-attached wrappers
(the 2026-07-31 incident: ~17 of 26 sessions, 72–95 h old) have **zero
observability**: no sidecar row, no push, no log surface.

Acceptance criteria:

1. A TTY-attached unmapped EPS session idle ≥ the report threshold (default
   48 h, env `EPM_TTY_UNMAPPED_REPORT_HOURS`) produces a report candidate; one
   idle < threshold (or with an unavailable idle signal) produces nothing.
2. The lane NEVER stops, unregisters, or otherwise mutates a session — report
   only. `decide_idle_unmapped`'s existing contract is byte-unchanged (the
   pinned `has_tty -> ("clear", 0)` behavior stays; existing tests
   tests/test_autonomous_session_watch.py:9992-9994 keep passing).
3. One deduped Telegram push per episode: dedup keyed on the reported
   session-id SET, re-alert on set growth (new sid appears) or a 168 h TTL —
   the established watcher state-singleton + re-alert pattern.
4. One sidecar row per reported session in
   `~/.eps-autonomous/idle-unmapped-events.jsonl` (the pass's existing stream,
   via `_append_idle_unmapped_event`) with a NEW distinct sentinel
   `[autonomous_session_watch:tty-unmapped-report]` and `action: "tty-report"`
   semantics in the note text.
5. Each reported session carries: sid, wrapper pid, cwd, wrapper age, idle age,
   and a safe-to-kill VERDICT derived from the existing zombie-wrapper
   heuristics (work-descendant probe `_has_running_work_descendant`; a probe
   failure reads "uncertain", never "safe").
6. Kill switch `EPM_DISABLE_TTY_UNMAPPED_REPORT=1` disables the lane entirely.
7. Pure-decision pin tests land for the new decision helper + push-dedup
   decision; ruff clean on touched files; `workflow_lint.py` no-flags PASS.
8. `.claude/rules/background-automation.md` documents the new lane (one entry
   in the idle-unmapped pass section: predicate, env knobs, sidecar sentinel,
   escalate-only guarantee).

## Method delta (vs existing code)

- **NEW pure decision** `decide_tty_unmapped_report(idle_age_s, report_idle_s)
  -> str` (`"report"` | `"none"`): fires iff `idle_age_s is not None and
  idle_age_s >= report_idle_s`. Kept SEPARATE from `decide_idle_unmapped` so
  the existing pinned contract is untouched (tests 9992-9994 assert the
  has_tty clear).
- **`_process_idle_unmapped`**: in the unmapped + `has_tty` branch (currently
  falls straight to `("clear", 0)`), when the lane is enabled, additionally
  stat the transcript (`_transcript_idle_age_s(pid, now)` — one extra IO per
  TTY session per tick, same cost class as the non-TTY path) and, on
  `"report"`, append a candidate dict (sid, pid, cwd?, wrapper_age_s,
  idle_age_s, verdict) to an optional accumulator parameter
  (`tty_report_acc: list | None = None`, default None = lane off for
  legacy/test callers). No state-file writes on this path — the episode state
  machinery (missed counts) stays exclusively non-TTY.
- **`idle_unmapped_pass`**: owns the accumulator; after the sweep, if
  non-empty and the kill switch is unset: load the report-state singleton
  (`~/.eps-autonomous/tty-unmapped-report-state.json`, atomic temp+rename like
  the other watcher state files), decide push-vs-suppress (NEW pure helper
  `decide_tty_report_push(prev_sids, cur_sids, last_push_ts, now, realert_s)`
  -> `"push"` | `"suppress"`: push on first episode, on a sid not in the
  previous set, or on TTL expiry; suppress otherwise; an EMPTY current set
  clears the state — episode over), then fire ONE fail-soft `_telegram_push`
  listing every reported session with verdicts + one
  `_append_idle_unmapped_event` sidecar row per session with the new sentinel.
  Dry-run writes nothing and pushes nothing (prints only).
- **Safe-to-kill verdict**: `"no-live-work (likely safe: kill via
  spawn_session.py stop --session-id <sid>)"` when
  `_has_running_work_descendant(pid, children_map)` is False;
  `"has-live-work-descendant (do NOT kill blindly)"` when True;
  `"uncertain (unreadable /proc)"` on probe failure. Never auto-acts.
