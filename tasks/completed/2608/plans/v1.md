# Plan v1 — #2608: auto-thread cross-issue artifact cones into pod bootstrap + fail-loud audit

`kind: infra`. VM-local code change; no experiment, no pod provisioned by this task.

## Requirement + acceptance criteria

**Requirement.** A pod bootstrapped for issue N whose round reads OTHER issues'
committed artifact trees (`eval_results/issue_M`, `ood_eval_results/issue_M`,
`figures/issue_M`, M != N) must come up with those cones present by default, and
when they are absent the bootstrap audit must say so loudly with the exact
remedy — instead of the current behavior (clean bill of health at bootstrap,
`FileNotFoundError` seconds after launch; incident: #2569's first launch died on
BOTH pods because `eval_results/issue_{1482,2476,1979,779}` were hidden).

**Acceptance criteria:**

1. **Derivation helper.** `scripts/verify_carryover_inputs.py` exposes a pure
   function `extra_cones_for_plan(plan_text: str, issue: int) -> list[str]`
   returning the sorted, deduped cone dirs (`eval_results/issue_<M>`,
   `ood_eval_results/issue_<M>`, `figures/issue_<M>`) for foreign-issue
   (`M != issue`) artifact paths cited in the plan text. Own-issue paths are
   never returned. Unit-tested on synthetic fixtures.
2. **CLI mode.** `verify_carryover_inputs.py --print-extra-cones --issue <N>
   [--plan <path>]` prints the space-separated cone set on stdout and exits 0;
   without `--plan` it resolves the task's persisted plans via
   `explore_persona_space.task_workflow` (never hand-built `tasks/...` paths).
   No plan / no task / no matches → empty output, exit 0 (fail-soft: this mode
   never blocks provisioning). Mirrors the existing `--print-repo-branch`
   resolver-mode shape (mutually exclusive with the gate-mode args).
3. **Auto-threading at provision.** `scripts/pod_lifecycle.py::_bootstrap`
   (the single choke point both `pod.py provision` and `pod.py bootstrap` route
   through), when `issue` is not None: derive the cone set from the task's
   persisted plans, UNION it with any caller-exported `BOOTSTRAP_EXTRA_CONES`
   (order-stable dedupe, space-joined), set the merged value into the child env,
   and print the final set (one line: derived + inherited). Fail-soft on every
   error class (task not found, no plans, unreadable plan, import failure):
   keep the caller env untouched, print a one-line note, proceed — derivation
   must never fail or stall a provision.
4. **Audit leg A — declared cones verified.** The post-checkout audit block in
   `scripts/bootstrap_pod.sh` (currently the two warnings at ~:366-378) gains a
   check that every dir in `$EXTRA_CONES_VAL` is present in
   `git sparse-checkout list`, WARNing per missing dir in the same shape as the
   existing two warnings (names the `git sparse-checkout add <dir>` remedy).
5. **Audit leg B — driver-grep backstop.** When `$ISSUE_VAL` is non-empty, the
   audit greps the round's own drivers (`scripts/issue${ISSUE_VAL}_*.py`;
   empty glob guarded) for `(ood_)?eval_results/issue_<M>` / `figures/issue_<M>`
   tokens with `M != ISSUE_VAL` and WARNs per referenced-but-missing cone with
   the same remedy. This catches rounds whose dependencies were never declared
   in the plan or env. WARN-only — the audit contract stays "warn loud, never
   hard-fail" (a pod that legitimately needs no committed artifacts must still
   come up; the workload's own input read stays the hard gate).
6. **Tests + lints green.** The named pytest files pass, `bash -n
   scripts/bootstrap_pod.sh` passes, and the no-flags
   `scripts/workflow_lint.py` run stays clean.

   - Add `--print-extra-cones` resolver mode (arg parsing beside
     `--print-repo-branch`; same "combines only with --issue/--repo-root

     `task_workflow`), not only `plan.md` — cones are additive, idempotent and

## Smoke blind-spot enumeration

The validation above is STATIC for the bash leg: `bash -n` + shape tests +
payload-quoting tests never EXECUTE the new audit block on a live pod. Blind
spots of a passing validation run:

- remote-side execution of legs A/B (grep behavior, glob guard, warning
  emission) is exercised only at the next real `pod.py provision --issue <N>`;
- the auto-derived cone set's effect on real bootstrap wall-time is unmeasured
  (expected: MBs of promisor-fetched JSON, negligible).

Live-pod validation is deliberately deferred to the next real provision (any
issue with carry-over inputs); this task provisions no pod.
