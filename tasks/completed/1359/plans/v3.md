## 4. Design

### Method delta (what the new text adds)

1. **vs the #488 entry:** #488's rules (a)/(b) govern the SILENT-LOSS direction — a wrapper that logs-and-continues on no-path loses artifacts. The new clause (c) governs the FAIL-FAST direction — a seam that correctly raises on no-path still must retry transport-class first, or fleet HF traffic kills runs at their final phase. (b) and (c) are complements: (b) bans continuing without the retry+raise; (c) mandates the retry before the raise.
2. **vs the #931 wedge ladder:** the ladder is OUT-OF-PROCESS recovery for a HUNG upload that never returns (kill + replay with env — env is frozen at `huggingface_hub.constants` import, so no in-process action can help). The seam retry is IN-PROCESS recovery for a FAILED upload that returns `""` promptly. Discriminator = did the call return? Returned-empty → seam retry loop; never-returns / ~0 TX → ladder. Neither substitutes for the other: a retry loop can never reach a hang (it is blocked inside the call), and a kill+replay is wasteful for a transient that clears in 30-120 s. The draft text states this composition in its closing sentence.
3. **vs the inner `_retry_upload` envelope + the #1335 `retry_transient` entry (critic-round Must-Fix):** the inner envelope retries RAISED transient errors (429/408/5xx, Retry-After-aware, ~1800 s budget) INSIDE each upload call; the seam retry is the cheap OUTER envelope over the no-path RETURN — each outer attempt re-enters the full inner envelope after a 30-120 s pause, and for the failure classes the inner layer never retries (the response-less Xet queue-full text, the demonstrated #1315 killer) it is the ONLY retry. The v3 draft text states this two-layer structure explicitly instead of the v1/v2 sentence "huggingface_hub does NOT retry 429 here" (library-true but seam-false — the inner wrapper DOES retry 429).

## 11. Decision Rationale

- **Retry count = 3 / backoff = (30, 60, 120) s / jitter = +0-25% / same fail-loud RuntimeError on exhaustion.** Why: production-validated on the motivating incident; total worst-case added delay ≤ ~262 s is small next to the ~35-min inter-kill gap it absorbs. `Source: #1315 @ c3c600541f` (`_UPLOAD_TRANSPORT_RETRIES` / `_UPLOAD_BACKOFF_BASE_S`, `scripts/issue1315_dispatch.py:1688-1689`). Correct baseline for the scale argument (critic-round re-grounding): the INNER `_retry_upload` envelope (10-180 s waits, Retry-After honored up to ~900 s, ~1800 s wall budget) — the outer schedule is NOT competing with `http_backoff`'s 1-8 s blip retries; it is a coarse-grain RE-ENTRY of the full inner envelope after a bounded pause, sized so 3 outer cycles stay cheap (≤ ~4.5 min) while giving the Xet queue / exhausted-budget classes a fresh chance. Alternatives: unbounded retry (rejected — hides persistent failures, violates fail-fast), longer schedules (rejected — no evidence needed beyond what production absorbed).
- **Doc rule at the SEAM, not a code change inside `hub._upload`.** Why: the Goal + candidate scope this task to rule text; `_upload`'s return-`""` contract is pinned by many callers, and the seam (not the library) knows its own idempotency and failure semantics. A library-level retry is a separate, bigger-blast-radius task if ever wanted. `Source: #1359 body (Goal + diff sketch); #1315 r8 fix shape (seam wrapper, not hub.py patch).`
- **Placement as clause (c) of the #488 entry.** Why: the two rules share the trigger phrase ("upload returned no path") and are logical complements; one paragraph keeps the grep surface unified. `Source: #1359 body diff sketch; clarifier grep (only-hit file).`
