## 4. Design — Method delta + concrete diffs

### Approach decision: (a) git-tracked exclusion, fail-open — chosen over (b) and (c)

- **(a) git-tracked set (CHOSEN).** The set of committed files IS, by definition, exactly the set to exclude — no proxy. Git is available in the workload context (the same startup script cloned the repo, `gcp.py:2496`; `git ls-files` reads the index, which shallow `--depth 1` clones populate fully). Cost: one bounded subprocess (~50 ms, `timeout=10` inside the 300 s budget) + set membership per walked file.
- **(b) `*.log`-suffix and/or mtime filter (REJECTED).** mtime: a fresh `git clone` writes every checkout file at clone time, so committed-file mtimes are ≥ attempt start — the filter excludes nothing (the body's caution, confirmed). Suffix: run-generated forensics are not guaranteed `*.log` (the pod-side sentinel contract writes `logs/issue-<N>-*.json`; dispatchers write `.jsonl`/`.txt` progress records), so a suffix allowlist loses real evidence; and a committed `.log` would still leak through. Both directions of error.
- **(c) hybrid (REJECTED).** (a) alone is exact; layering (b) adds complexity with no residual failure mode it covers, except the git-unavailable case — which fail-open already covers more safely (sweep everything > guess).

**Why walk-time, not upload-time `ignore_patterns`:** an upload-time exclusion (adding patterns to the `upload_folder` call or the `IGNORE` list) would leave committed files in `entries`, still consuming the `LOG_MAX_FILES=40` slots and the newest-first sort — the budget-displacement half of the bug would survive. The exclusion must happen before `entries.append`.

**Why code, not a model call:** trivially deterministic file classification; a model call is categorically wrong here.

```python
def test_persist_heredoc_worker_logs_excludes_git_tracked(tmp_path) -> None:
    """#1351 behavioral (executed heredoc): committed repo content under
    $WORKLOAD_ROOT/logs/ is EXCLUDED from the worker-logs sweep and does NOT
    consume the LOG_MAX_FILES budget — with a 1-file bound where the TRACKED
    file is the NEWER one, the sweep stages exactly the untracked run log
    (an upload-time-only exclusion mutant would let the newer tracked file
    win the single slot); the EXCLUDED breadcrumb prints AND tees into the
    transcript."""
    root = tmp_path / "workload"
    daily = root / "logs" / "daily"
    daily.mkdir(parents=True)
    tracked_md = daily / "2026-06-02.md"
    tracked_md.write_text("committed retrospective\n")
    run_dir = root / "logs" / "issue_137"
    run_dir.mkdir(parents=True)
    worker = run_dir / "corpus_gpu0_all.log"
    worker.write_text("worker traceback\n")
    subprocess.run(["git", "-C", str(root), "init", "-q"], check=True)
    subprocess.run(
        ["git", "-C", str(root), "add", "logs/daily/2026-06-02.md"], check=True
    )  # ls-files reads the INDEX — add suffices, no commit/identity needed
    base = os.stat(worker).st_mtime
    os.utime(tracked_md, (base + 3600, base + 3600))  # tracked NEWER than run log
    proc, calls, paths = _run_persist_heredoc(
        tmp_path, make_dirs=False,
        env_overrides={"EPS_PERSIST_LOG_MAX_FILES": "1"},
    )
    assert proc.returncode == 0, proc.stderr
    folder_calls = [
        c for c in calls
        if c["kind"] == "folder" and c["path_in_repo"].endswith("/worker_logs")
    ]
    assert [c["path_in_repo"] for c in folder_calls] == [
        "issue137_partial/att-x/worker_logs"
    ]
    assert folder_calls[0]["staged"] == {
        "issue_137/corpus_gpu0_all.log": "worker traceback\n"
    }
    assert (
        "[crash-persist] EXCLUDED 1 git-tracked file(s) from worker_logs sweep"
        in proc.stdout
    )
    # Walk-time exclusion: the tracked file never entered the entries pool,
    # so the dropped-count line does not fire (1 untracked entry, bound 1).
    assert "older worker log(s) beyond" not in proc.stdout
    assert "EXCLUDED 1 git-tracked" in paths["transcript"].read_text()
```

## 11. Decision Rationale

N/A — no model training

Load-bearing DESIGN choices (each with Source):

- **Approach (a) git-tracked exclusion over (b)/(c).** *Why:* exact by definition; mtime cannot work (clone sets all mtimes to checkout time — every committed file reads "fresh"); suffix filters err in both directions. *Source:* #1345 incident artifact (HF `issue1345_partial/att-20260715-151246/worker_logs/daily/` listing) + this session's measurements (48 tracked files, all `logs/{daily,weekly}/*.md`, 0 elsewhere; `git ls-files -z` format verified). *Alternatives:* (b)/(c) rejected in §4.
- **Fail-open on git failure.** *Why:* the sweep exists to save crash forensics (#885's whole purpose — the #779 two-manual-boot-disk-detach loss class); losing forensics to a cleanliness filter inverts the priority. *Source:* #885 design rationale + task-body directive; #854's "loud skip, never silent" discipline shapes the WARN breadcrumb.
- **Walk-time (not upload-time) exclusion.** *Why:* only walk-time frees the `LOG_MAX_FILES` slots; upload-time leaves budget displacement live. *Source:* #885's newest-first + file-count-bound mechanics (gcp.py:1791–1816, read this session).
- **`timeout=10` on the git subprocess.** *Why:* bounds worst-case persist delay to ≤3.3% of the 300 s budget (#854 invariant: never delay poweroff). *Source:* #854 (`timeout 300` ceiling) — proportionate sub-bound; `ungrounded — needs smoke-test` is NOT needed (unit tests exercise both branches).
- **One summary `_say` line (never per-file).** *Why:* the #885 serial print cap was sized at 120 lines for ~40 staging lines + overhead; ~48 per-file exclusion lines would blow it. *Source:* #885 (`compute-backend-failover.md` § eager bounded serial streaming).
