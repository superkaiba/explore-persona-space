## 4. Design

### 4.1 Failure-semantics matrix (design question 1 — resolved: option (c), refined; v3 corrects the no-identity branch per Methodology critique)

The decision keys on the PARSED local key identity `vm_fields = _authorized_key_fields(read_vm_pubkey() or "")` — `None` covers file missing/unreadable/non-`ssh-`-prefixed AND a parseable prefix with <2 tokens (a one-token `ssh-…` file). When `vm_fields is None` the check has NO key identity to match against, so per-key membership is UNDECIDABLE (Methodology critique round 1: the prior rows 4/5 demanded a yes/no the signature cannot compute, and a missing `.pub` does NOT imply an unreachable pod — SSH auth needs only the PRIVATE key, so a fresh pod seeded with our still-listed account key is perfectly reachable). `account = get_account_pubkey()` (raises on API/transport error; `''` on an unset/empty list).

| Local key identity (`vm_fields`) | account query | Account-list state | Verdict |
|---|---|---|---|
| parsed | ok | VM key present | **OK** — one line (with the no-overclaim clause: "list contains VM key; provider-side seeding not verifiable") |
| parsed | ok | VM key absent | **WARN** — hypothesized list-drop hazard (shared-list churn); injection covers fresh EPS pods |
| parsed | error | — | **WARN** — "preflight SKIPPED: \<err\>"; fail-open |
| None | ok | parses to ≥1 key | **WARN (loudest)** — injection fail-open (the injection reads the same `.pub`) AND membership unverifiable (no local identity); pod reachability depends on whether one of the listed keys is ours — remediate the pubkey file |
| None | ok | parses to 0 keys (`''` or no parseable lines) | **FAIL** — exit 1 pre-create: a fresh pod would seed ZERO authorized keys and the injection is unavailable → provably unreachable billing pod |
| None | error | — | **WARN** (loudest wording) — cannot verify either path; fail-open per the guardrail contract |

Rationale for not hard-failing on account-list absence alone (option b): the landed injection makes the account list non-load-bearing for fresh EPS pods on `runpod/pytorch` images; a hard fail on a non-load-bearing condition converts every fellows-onboarding churn of the SHARED list into a false EPS provisioning outage — the original hazard inverted. Rationale for not option (a) (silent when injection covers): the account-list drop IS the incident signal; surfacing it lets a human re-add the key before the paths the injection does NOT cover (pre-injection pod resumes, non-EPS tooling, a future image that stops honoring `PUBLIC_KEY`) break. Rationale for the narrowed FAIL arm (v3): "provably broken" must be literally provable from the two observables — the only such state is (no local identity → injection unavailable) ∧ (account list verifiably EMPTY → zero keys seeded); a rejected alternative was deriving the pubkey from the private key via `ssh-keygen -y` to keep per-key membership decidable — more power, but adds a subprocess + passphrase edge cases to a warn-mostly guard (recorded in §11-1; a follow-up may add it).

### 4.2 `scripts/runpod_api.py` — query helper + extraction refactor

```python
def read_vm_pubkey() -> str | None:
    """Raw VM SSH public-key line (RUNPOD_SSH_PUBKEY_FILE, default
    ~/.ssh/id_ed25519.pub), stripped, or None when the file is missing,
    unreadable, or not 'ssh-'-prefixed — exactly the fail-open condition
    of _public_key_env() (#1655 shares one read so the PUBLIC_KEY
    injection and the account-key preflight can never disagree)."""
    import os as _os
    path = _os.path.expanduser(_os.environ.get("RUNPOD_SSH_PUBKEY_FILE", "~/.ssh/id_ed25519.pub"))
    try:
        key = Path(path).read_text().strip()
    except OSError:
        return None
    if not key.startswith("ssh-"):
        return None
    return key


def _public_key_env() -> "_RawGraphQL | None":
    # (docstring unchanged except a pointer to read_vm_pubkey)
    key = read_vm_pubkey()
    if key is None:
        return None
    key = key.replace("\\", "").replace('"', "")
    return _RawGraphQL(f'[{{ key: "PUBLIC_KEY", value: "{key}" }}]')


def get_account_pubkey() -> str:
    """The team account's SSH key blob — ``myself { pubKey }``: a single
    string of newline-separated authorized_keys-style lines (the list the
    RunPod console Settings page shows and fresh pods are seeded from).
    Returns '' when unset. Raises RunPodError on transport/GraphQL failure
    (read-only query; remediation mutation updateUserSettings is
    deliberately NOT wrapped here — never auto-mutate the shared list, #1655)."""
    data = graphql("{ myself { id pubKey } }")
    return ((data.get("myself") or {}).get("pubKey")) or ""
```

Behavior-identity note: `read_vm_pubkey` preserves `_public_key_env`'s exact read/validation order (expanduser → read/strip → `ssh-` prefix); the `\\`/`"` scrub stays in `_public_key_env` (it is GraphQL-fragment escaping, not availability logic).

```python
def _authorized_key_fields(line: str) -> tuple[str, str] | None:
    """(key_type, base64_blob) from an authorized_keys-style line; None for
    blank/unparseable lines. Scans for the FIRST token starting with a known
    key-type prefix ('ssh-', 'ecdsa-', 'sk-') and takes it plus the next
    token — tolerating options-prefixed lines (`from="..." ssh-ed25519 AAA c`,
    Alternatives critique) — rather than blindly taking parts[0:2]. Comments
    are deliberately excluded: the console/API copy of a key routinely
    carries a different trailing comment than the VM file."""
    parts = line.split()
    for i, tok in enumerate(parts[:-1]):
        if tok.startswith(("ssh-", "ecdsa-", "sk-")):
            return (tok, parts[i + 1])
    return None


def decide_account_key_preflight(
    vm_pubkey: str | None,
    account_pubkey: str | None,   # None == query failed (fail-open row)
    *,
    query_error: str = "",
) -> tuple[str, str]:
    """Pure decision core for the #1655 §4.1 matrix: (verdict, message),
    verdict in {'ok', 'warn', 'fail'}. The decision keys on the PARSED
    identity vm_fields (None ⟺ no usable local key identity: file
    missing/unreadable/non-'ssh-'/or <2 tokens — per-key membership is
    then UNDECIDABLE). 'fail' ONLY when vm_fields is None AND
    account_pubkey is a real (non-None) blob parsing to ZERO keys —
    the one state where a fresh pod provably seeds no authorized key
    while the PUBLIC_KEY injection (b66910d748) is unavailable.
    A failed query (account_pubkey=None) can never fail."""
    vm_fields = _authorized_key_fields(vm_pubkey) if vm_pubkey else None
    if account_pubkey is None:
        # fail-open rows (query error): 'warn' — loudest wording when
        # vm_fields is None (cannot verify either path)
        ...
    account_fields = {
        f for line in account_pubkey.splitlines()
        if (f := _authorized_key_fields(line)) is not None
    }
    present = vm_fields is not None and vm_fields in account_fields
    # ... six-row matrix from §4.1, returning ('ok'|'warn'|'fail', message);
    # fail ⟺ vm_fields is None and account_pubkey is not None and not account_fields


def _account_key_preflight(pod_label: str) -> None:
    """Provision-time account-key guardrail (#1655) — read-only, warn-mostly;
    sys.exit(1) only on the both-paths-broken row. NEVER mutates the shared
    team key list. Kill switch: EPM_SKIP_ACCOUNT_KEY_PREFLIGHT=1."""
    if os.environ.get("EPM_SKIP_ACCOUNT_KEY_PREFLIGHT") == "1":
        print("  account-key preflight: SKIPPED (EPM_SKIP_ACCOUNT_KEY_PREFLIGHT=1)", file=sys.stderr)
        return
    vm_key = read_vm_pubkey()
    account: str | None
    query_error = ""
    try:
        account = get_account_pubkey()
    except (RunPodError, OSError, ValueError) as exc:
        # Fact-check correction (#1655 v2): RunPodError alone is NOT the
        # complete fail-open catch — json.loads at runpod_api.py ~L357 sits
        # OUTSIDE _graphql_once's try (json.JSONDecodeError ⊂ ValueError
        # escapes), and a socket read-timeout in resp.read() (~L339) raises
        # raw TimeoutError (⊂ OSError, not URLError). All three classes are
        # transient and MUST fail open (acceptance criterion 4).
        account, query_error = None, str(exc)
    verdict, msg = decide_account_key_preflight(vm_key, account, query_error=query_error)
    if verdict == "ok":
        print(f"  account-key preflight: OK ({pod_label})")
        return
    print(f"  account-key preflight [{verdict.upper()}] ({pod_label}): {msg}", file=sys.stderr)
    if verdict == "fail":
        sys.exit(1)
```

**Messages** (final wording is an allowed deviation; content is pinned by tests):

- OK: `account-key preflight: OK — team account list contains the VM key (provider-side seeding not verifiable from the list; the 2026-07-23 mode is covered by the PUBLIC_KEY injection, b66910d748).` (the no-overclaim clause — Alternatives critique)
- FAIL (no local identity + account list EMPTY): `VM pubkey file missing/malformed (~/.ssh/id_ed25519.pub or $RUNPOD_SSH_PUBKEY_FILE) — the PUBLIC_KEY boot injection (b66910d748) is unavailable — AND the RunPod team account key list (myself.pubKey) parses to ZERO keys. A fresh pod would seed NO authorized key and refuse SSH (the publickey-denied signature of 2026-07-23). Remediation: restore the pubkey file, and/or re-add keys via RunPod console -> Settings -> SSH Public Keys (the API mutation updateUserSettings(input:{pubKey}) REPLACES the whole shared list — do not script it).`
- WARN (VM key absent from a non-empty list, injection ok): `VM key absent from the RunPod team account key list — the SHARED team list is mutated by fellows-cluster onboarding (live hazard class). Fresh EPS pods stay reachable via the PUBLIC_KEY boot injection, but pre-injection pod resumes / non-EPS tooling may refuse SSH. Re-add via RunPod console -> Settings -> SSH Public Keys.`
- WARN-loudest (no local identity, account list non-empty): `VM pubkey file missing/malformed — the PUBLIC_KEY boot injection is unavailable AND the VM key's membership in the team account list cannot be verified (no local key identity). A fresh pod is reachable only if one of the <n> listed account keys is ours. Restore the pubkey file ($RUNPOD_SSH_PUBKEY_FILE or ~/.ssh/id_ed25519.pub).`

## 11. Decision Rationale

Hyperparameters: N/A — no model training (kind: infra). Load-bearing design choices:

1. **Failure semantics — warn-mostly, hard-fail only on the provably-zero-keys state (option c; v3-narrowed per Methodology critique).** *Why:* injection (`b66910d748`) makes the account list non-load-bearing for fresh pods; hard-failing on shared-list churn creates false outages. The v3 narrowing: with no local key identity, per-key membership is UNDECIDABLE and a missing `.pub` does not imply unreachability (SSH needs only the private key) — so the FAIL arm fires only when (no identity) ∧ (account list parses to ZERO keys), the one state where a fresh pod provably seeds no authorized key. *Source:* commit `b66910d748` + Methodology critique round 1; fail-open-on-API-error precedent from `write_pods_conf`'s never-drop guard (#821) and the #506/#537 rule that provisioning guards must not convert transient conditions into `blocked`. *Alternatives:* (a) fail only both-broken with no WARN — rejected, drops the hazard signal; (b) always hard-fail — rejected, false outages; (d) derive the pubkey from the private key (`ssh-keygen -y -f ~/.ssh/id_ed25519`) to keep per-key membership decidable when the `.pub` is unreadable — rejected for v1 (subprocess + passphrase edge cases on a warn-mostly guard; a follow-up may add it).
2. **Insertion point — `cmd_provision` post-idempotency, pre-branch; once per invocation.** *Why:* single choke point covering CPU/GPU/wait/one-shot/dry-run before any create; `_wait_mode_preflight` fires per capacity tick (wrong cadence); `backends/runpod.py` shells out to `pod.py provision`, so the router lane is covered transitively. *Source:* `pod_lifecycle.py` L1967–2148 read; #1177 `_warn_on_terminal_parent_provision` placement precedent. *Alternatives:* inside `runpod_api.create_pod` — rejected (would also fire on retry ticks and couples transport to policy); `orchestrate/preflight.py` — rejected (runs after the pod exists; out of Provenance scope).
3. **Query field — `myself { pubKey }`, newline-separated authorized_keys text.** *Source:* runpodctl `api/user.go` verbatim query (`query myself { myself { id pubKey } }`; github.com/runpod/runpodctl), `MySelfData.PubKey` (pkg.go.dev/github.com/runpod/runpodctl/api), graphql-spec.runpod.io — **plus a live probe as an acceptance step** (the team-scoped resolution is not fully grounded by docs; see §12). *Alternatives:* REST — no documented account-key endpoint found.
4. **No auto-re-add in v1.** *Why:* the remediation mutation `updateUserSettings(input:{pubKey})` REPLACES the entire newline-separated blob; a read-modify-write against the SHARED team account races the fellows fleet's own mutations and could drop THEIR keys — the incident inverted, caused by us. A guardrail must not become a shared-state mutator. The mutation name appears only in the remediation message for a deliberate human. *Source:* runpodctl `api/user.go` mutation shape; task constraint "never auto-mutate silently". *Alternatives:* logged auto-re-add — rejected for v1 (race + blast radius on a shared account).
5. **Match on (key_type, base64_blob), not whole-line; parser scans for the first key-type-prefixed token.** *Why:* comments legitimately differ between the VM file and the console copy, and account lines may carry authorized_keys OPTIONS prefixes (`from="..." ssh-ed25519 ...`) that would mis-parse a blind parts[0:2] read (Alternatives critique; WARN-only blast radius, closed anyway). *Source:* authorized_keys format (sshd(8)); runpodctl parses lines the same way. *Alternatives:* full-line equality — rejected, false negatives; blind first-two-tokens — rejected, options-prefix false absents.
6. **Kill switch `EPM_SKIP_ACCOUNT_KEY_PREFLIGHT=1` + fail-open on `RunPodError`.** *Why:* project convention for new guards (`EPM_SKIP_*` family); the brief's constraint that a transient GraphQL failure must never block provisioning. *Source:* CLAUDE.md background-automation kill-switch pattern; task brief constraint. *Alternatives:* none serious.
