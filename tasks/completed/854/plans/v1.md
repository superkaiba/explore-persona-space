3. **Eager bounded streamer** — replace `) 2>&1 | cut -c1-2000 | tail -n 20 >&3 2>/dev/null || true;` with a pure-bash reader that forwards each line to fd 3 AS IT ARRIVES, caps line length at 2000 chars, stops PRINTING after 60 lines but keeps READING to EOF (an early pipe close would SIGPIPE-kill the python mid-upload — the exact loss this prevents):
   ```
   ) 2>&1 | { _n=0; while IFS= read -r _l; do _n=$((_n + 1));
     if [ "$_n" -le 60 ]; then { printf '%s\n' "${_l:0:2000}" >&3; } 2>/dev/null || true; fi;
   done; } 2>/dev/null || true;
   ```
   Named fallback if quoting proves intractable in the string-list render: `stdbuf -oL cut -c1-2000 >&3` (eager + length-bounded, drops only the line cap; the python's own output is naturally ≤ ~15 lines with progress bars disabled).

### 3.3 Heredoc (python) edits — the substantive coverage fix

Replace the `EPS_PERSIST_PY` body with (shape; all prints `flush=True` — load-bearing for eager streaming):

```python
import datetime, os, sys
from pathlib import Path
from huggingface_hub import HfApi
dest, crash = sys.argv[1], sys.argv[2]
repo = os.environ["EPS_HF_DATA_REPO"]
issue = os.environ.get("EPS_ISSUE", "0")
log_path = os.environ.get("EPS_LOG_PATH", "")
root = Path(os.environ.get("WORKLOAD_ROOT", ""))
print(f"[crash-persist] BEGIN repo={repo} dest={dest} log_path={log_path or 'UNSET'}", flush=True)
api = HfApi()
def _up_file(path, path_in_repo):
    try:
        print(f"[crash-persist] uploading {path_in_repo} ({Path(path).stat().st_size} bytes)", flush=True)
        api.upload_file(path_or_fileobj=path, path_in_repo=path_in_repo, repo_id=repo, repo_type="dataset")
        print(f"[crash-persist] uploaded {path_in_repo}", flush=True)
    except Exception as exc:
        print(f"[crash-persist] FAILED {path_in_repo}: {exc}", flush=True)
# 1. crash report + workload log, small-first (traceback = highest value). A same-attempt
#    re-crash overwrites the canonical names (#854: run-3 overwrote run-2's log), so ALSO
#    upload a per-crash timestamped log copy.
stamp = datetime.datetime.now(datetime.timezone.utc).strftime("%Y%m%dT%H%M%SZ")
if Path(crash).is_file():
    _up_file(crash, f"{dest}/crash_report.json")
if log_path and Path(log_path).is_file():
    _up_file(log_path, f"{dest}/workload.log")
    _up_file(log_path, f"{dest}/workload_{stamp}.log")
else:
    print(f"[crash-persist] SKIP workload.log: EPS_LOG_PATH unset or file missing ({log_path!r})", flush=True)
# 2. partial artifacts — BOTH output conventions (#854: issue825 wrote track_s.jsonl under
#    data/issue_825/, structurally OUTSIDE the old eval_results-only sweep → silent skip →
#    boot-disk surgery). Re-downloadable caches / stores excluded; every skip printed.
IGNORE = ["hf_dl/**", "g*_dl/**", "store/**", "**/.cache/**", "**/__pycache__/**"]
PRUNE = {"hf_dl", "store", ".cache", "__pycache__"}
CAP = 2 * 1024**3
def _dir_stats(local):
    total, n = 0, 0
    for dirpath, dirnames, filenames in os.walk(local):
        dirnames[:] = [d for d in dirnames
                       if d not in PRUNE and not (d.startswith("g") and d.endswith("_dl"))]
        for f in filenames:
            try:
                total += (Path(dirpath) / f).stat().st_size; n += 1
            except OSError:
                pass
    return total, n
def _up_dir(local, name):
    if not local.is_dir():
        print(f"[crash-persist] SKIP {name}: no such dir ({local})", flush=True); return
    size, n = _dir_stats(local)
    if n == 0:
        print(f"[crash-persist] SKIP {name}: empty after cache excludes", flush=True); return
    if size > CAP:
        print(f"[crash-persist] SKIP {name}: {size} bytes > cap {CAP} (recover via boot disk / regenerate)", flush=True); return
    try:
        print(f"[crash-persist] uploading dir {name} ({n} files, {size} bytes)", flush=True)
        api.upload_folder(folder_path=str(local), path_in_repo=f"{dest}/{name}",
                          repo_id=repo, repo_type="dataset", ignore_patterns=IGNORE)
        print(f"[crash-persist] uploaded dir {name}", flush=True)
    except Exception as exc:
        print(f"[crash-persist] FAILED dir {name}: {exc}", flush=True)
for local, name in (
    (root / "eval_results" / f"issue_{issue}", f"eval_results_issue_{issue}"),
    (root / "data" / f"issue_{issue}", f"data_issue_{issue}"),
    (root / "data" / f"issue{issue}", f"data_issue{issue}"),
):
    _up_dir(local, name)
print("[crash-persist] DONE", flush=True)
```

Notes: keeps the substring `eval_results" / f"issue_{issue}"` (existing test :3947 stays green); the `issue<N>_partial/<attempt_id>/` path structure is unchanged (a `crash-<ts>/` subdir restructure was considered and REJECTED — `scripts/issue722_fit_M.py:383/:396` programmatically consumes the flat `issue<N>_partial/<attempt_id>/eval_results_issue_<N>/…` shape, and the docs teach the flat path; the timestamped log copy captures the multi-crash history without breaking consumers). ## 11. Decision Rationale

- **Watchdog handling — kill at trap entry (not pause/flag).** *Why:* it is the only other in-guest poweroff actor (gcp.py:1378 ladder), and on the crash path the trap already guarantees shutdown, so its purpose is subsumed; killing is 1 line and mirrors the existing clean-exit reap (:1634). *Source:* gcp.py :1323–1343 (#669 design comments), :1620–1621 (crash-path liveness), #825 run-2 evidence that the actor class matters. *Alternatives:* a "persist-in-progress" flag the watchdog checks (more states, same effect); leaving it alive (keeps the race window).
- **Timeout value — keep 300s, unchanged.** *Why:* the billing bound wins per the task's hard constraint and `.claude/rules/compute-backend-failover.md` § Part A; runs 1–5 all finished uploads in ≤20s, so 300s has ≥15× headroom even with the broader sweep. *Source:* #658 (the original bound), today's commit timings. *Alternatives:* per-file sub-timeouts (complexity without evidence of need).
- **Upload order — crash_report → workload.log (+ timestamped copy) → eval_results → data.** *Why:* small/highest-value first so a worst-case timeout still lands the traceback; matches the existing order, extended. *Source:* task body diff sketch; #658 Part A list.
- **Partial-sweep coverage — add `data/issue_<N>` + `data/issue<N>` with cache excludes + 2 GiB cap.** *Why:* the demonstrated run-2 loss lived at `data/issue_825/` (issue-825 worktree `scripts/issue825_gen_conversations.py:563`); both naming conventions are live in-repo (`data/issue654/battery.json`, gotchas.md); `hf_dl/`/`g*_dl/` caches under the same root are re-downloadable and can be tens of GB (CLAUDE.md § Disk hygiene) — uploading them would burn the whole 300s for nothing. Cap 2 GiB ≈ well inside 300s at observed GCE→HF throughput while excluding pathological residues. *Alternatives:* an `EPS_PARTIAL_DIRS` env contract threaded from dispatch (more general, but a bigger render+dispatch API change than the incident justifies — can be a follow-up if a third convention appears).
- **Eager pure-bash streamer replacing `cut | tail -n 20`.** *Why:* `tail` buffers to EOF, so a killed/skipped persist leaves zero post-hoc evidence — the exact diagnosability failure that produced this task's wrong premise; reading to EOF while print-capping avoids SIGPIPE-killing the uploader. *Source:* run-2 misdiagnosis (§2); #607 fd-3/serial discipline. *Alternatives:* `stdbuf -oL cut` (named fallback; loses the line cap), raising `tail -n` (still post-hoc — rejected).
- **Timestamped `workload_<ts>.log` copy (keep canonical name too).** *Why:* runs 3/5 overwrote run-2's log on HF (commit log §2) — the multi-crash-per-attempt history was lost the same day; keeping `workload.log` canonical preserves the documented recovery path and issue722-style consumers. *Source:* HF commit evidence; `scripts/issue722_fit_M.py:396`. *Alternatives:* per-crash subdirs (rejected — breaks the flat-path consumer pattern).
- **Fixture regeneration — inline script, provenance header, post-commit SHA.** *Source:* the #750 precedent recorded in the fixture's own `provenance.generated_by` + `.claude/rules/compute-backend-failover.md` § Snapshot pin.
