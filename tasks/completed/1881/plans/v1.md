# Plan v1 — #1881 workflow-fix: verify_task_body judge-health drop-line population reconciliation

## Goal / requirement

Extend `scripts/verify_task_body.py` so judge-health drop-line sentences of the form
`"<X> content drops [and <T> transport losses] of|across <Y> draws"` are parsed and
reconciled against the round's committed judge artifacts — FAILing when the claimed
(X, Y) pair is a PROVABLE population crossing (the #1776 incident: an all-arms drop
numerator over a steered-only draw denominator), WARNing when the pair cannot be
reconciled at all, and passing gracefully everywhere else.

**Acceptance criteria:**
1. The incident sentence `"192 content drops of 56,250 draws (0.34%)"` verified
   against #1776's committed `followup_p3p4/judge/judge_scores.json` FAILs, naming
   both consistent pairings (192/67,500 all-arms; 156/56,250 baseline-excluded).
2. The corrected forms — `"192 content drops of 67,500 draws"` (all-arms) and
   `"0 content drops and 0 transport losses of 26,600 draws"` (judge_swap.json) —
   PASS against the same artifacts.
3. No judge artifacts resolvable / no drop-line sentence / legacy-v2 body /
   `EPM_VERIFY_BODY_NO_EVAL_SCAN=1` → graceful PASS (never a false FAIL on
   missing data — the existing check's contract).
4. Existing `tests/test_verify_task_body.py` stays green; new pins cover the
   verdict ladder (checked via the Step 9c compare gate against the known-red-on-main
   ledger — pre-existing main red never blocks, #1022).
5. Running the new check across the 16 existing drop-line-bearing bodies produces
   NO spurious FAIL (a genuine crossed pairing found on a parked body is surfaced
   in the epm:results note, not silently shipped).

## Method delta

The existing `check_judge_error_denominator` (L6104) covers the #732 class (bare
`n=N` judge denominators with silent 529 counting). It never parses drop-line
health sentences, and a pure-arithmetic lint cannot catch a population mismatch
whose stated % is self-consistent with X/Y. Delta: a NEW sibling check —
`check_judge_drop_line_population` — that parses the drop-line form and reconciles
(X, Y) against schema-keyed artifact totals. A new check function (rather than
extending the existing one, deviating from the candidate's sketch) keeps one
CheckResult per verdict axis and leaves the existing check's ladder + tests
untouched; it REUSES the existing plumbing (`_resolve_eval_root` four-leg ladder,
`_strip_fenced_blocks`, the `EPM_VERIFY_BODY_NO_EVAL_SCAN` fence).

## Design

**Claim regex** (module-level, near the #732 block):

```python
_JUDGE_DROP_LINE_RE = re.compile(
    r"(?P<drops>\d[\d,]*)\s+content\s+drops"
    r"(?:\s+and\s+(?P<transport>\d[\d,]*)\s+transport\s+loss(?:es)?)?"
    r"\s+(?:of|across)\s+(?P<draws>\d[\d,]*)\s+draws",
    re.IGNORECASE,
)
```

Grounded against the observed corpus phrasings (clarifier scan, 2026-08-01):
`"192 content drops of 56,250 draws (0.34%..."`, `"0 content drops and 0 transport
losses of 26,600 draws"`, `"0 content drops and 0 transport losses across 26,600
draws"`, `"342 content drops of 121,250 draws overall"`. Sentences with no
`of|across <Y> draws` denominator (e.g. `"1,938 content drops (1.6%)"`) carry no
population pair and are out of scope (no match — the check stays silent on them).

**Artifact discovery — schema-keyed, not name-keyed.** For each `*.json` under the
resolved `eval_results/issue_<N>/` (per-file size guard: skip files >50 MB, the
check-35 `_REUSE_SCAN_MAX_BYTES` precedent; corrupt/unreadable files skipped), a
recursive descent collects LEAF dicts carrying BOTH `content_drops` AND
`valid_draws` numeric keys (`transport_losses` optional). Name-keying on
`judge_scores*.json` (the candidate's sketch) would miss `judge_swap.json`, which
carries the identical leaf schema (clarifier ground truth). Stop descent at a leaf
(no double-counting), mirroring `_scan_issue_judge_errors`.

**Candidate population set.** Per FILE with ≥1 leaf:
- (a) whole-file total: `X_f = Σ content_drops`, `Y_f = Σ (content_drops + valid_draws)`;
- (b) baseline-excluded total: same sums over leaves whose dict-key path contains
  no segment starting with `baseline` (case-insensitive) — the "steered-only" split;
- (c) per-subtree totals: for each dict key k anywhere in the file whose subtree
  contains ≥1 leaf, the subtree's (X, Y) — this yields per-trait and per-arm
  populations naturally (`per_arm[trait]`, `per_arm[trait][arm]`).
Plus the CROSS-FILE union: (a) and (b) summed over all files. For every candidate,
accept Y as `drops+valid` OR `drops+valid+transport` (identical when transport=0).
Candidate set is bounded (≤ ~200 entries; leaves per file are tens, not thousands).

**Verdict ladder** (mirrors the existing check's graceful-skip contract):
1. Not v3/v4 body → PASS "skipped — legacy/v2 body".
2. No `_JUDGE_DROP_LINE_RE` match in the fence-stripped Methodology+Results region
   → PASS "no judge drop-line asserted".
3. `issue is None` / eval root unresolvable / `EPM_VERIFY_BODY_NO_EVAL_SCAN=1` /
   no leaf-bearing artifact found → graceful PASS (skip note).
4. For each claimed (X, Y): some candidate matches BOTH (exact integer match after
   comma-stripping) → that claim PASSes.
5. No candidate matches both, but X exactly equals some candidate's numerator AND
   Y exactly equals a DIFFERENT candidate's denominator → **FAIL** (provable
   population crossing — the incident signature), message naming both consistent
   pairings ("X matches <pop-A> (X/Y_A); Y matches <pop-B> (X_B/Y)").
6. No candidate matches either coordinate (or only one, with no crossing partner)
   → **WARN** "could not reconcile (X, Y) against any committed judge-artifact
   population" listing the 3 nearest candidates. WARN, not FAIL: an unenumerated
   subset (e.g. a union of 2-of-3 files) is a plausible honest population, so only
   the crossed signature earns a FAIL. Never newly hard-FAILs a body on absence of
   evidence.
7. Multiple drop-line claims: each evaluated independently; worst verdict wins
   (any FAIL → FAIL; else any WARN → WARN; else PASS).

**Registration:** alongside the existing call at ~L15088, same argument shape
(`issue`, `eval_root`, `body_source_path`). Check label:
`"judge drop-line population reconciles"`.

**Out of scope (single-variable discipline):** no change to
`_JUDGE_ERROR_DISCLOSURE_RE` (whether a drop-line counts as 529-disclosure for the
existing check is a separate question); no Z% arithmetic check (self-consistent by
construction, per the candidate); no parsing of denominator-less drop mentions.

  `uv run python scripts/verify_task_body.py --issue 1776` (live validation) +
  a loop of `--issue <M>` over the 16 drop-line-bearing bodies (corpus validation).

## Kill criteria

  beyond #1776's judge files (i.e. the corpus validation shows other issues' judge
  artifacts use disjoint key names for the same populations), the schema-keyed scan
  degrades to graceful-skip everywhere except #1776 — the check still catches the
  incident class for the current judge-artifact convention, but the plan's
  generality claim is dead; record the narrower scope in the epm:results note
  rather than widening key aliases speculatively.
