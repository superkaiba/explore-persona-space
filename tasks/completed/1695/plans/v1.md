**A1. `tick_triage.py`: api-error-after-marker converts HEALTHY -> STALE-REDRIVE.**
Whenever the tail of THIS session's resolved Claude transcript contains an
assistant row with `isApiErrorMessage: true` whose timestamp (the
top-level ISO-8601 `timestamp`, parsed via the existing `parse_event_ts`)
is NEWER than the latest events.jsonl marker ts read via
`latest_event_ts(events)`, `triage()` returns
`("STALE-REDRIVE", f"status={status}, ... — api-error-after-marker (api-error <M>m ago, newer than marker)")`
instead of HEALTHY. Fail-open: unreadable transcript / missing transcript
path / any exception in the new predicate returns `None` and `triage()`
keeps today's verdict (the `human_activity_reason` fail-toward-ticking
posture).

**A2. `autonomous_session_watch.py`: boot-death shape splits into
`boot-refusal` vs `boot-transport` with a collapsed transport threshold.**
The boot-death lane's arm-2 firing row (the LAST `_classify_wedge_row(r) == "api-error"`
row in the 256 KB tail) is classified by content substring:

  - **`boot-transport`**: content (case-insensitive substring, checked
    against every text field the row's `message.content` exposes — the
    exact iteration `_boot_death_api_error_excerpt` uses today) contains
    ANY of the transport substrings (verbatim, defaulted):
    `"529"`, `"overloaded"`, `"429"`, `"rate limit"`, `"ratelimit"`,
    `"timeout"`, `"connection error"`, `"api connection"`. And does NOT
    contain a usage-policy substring: `"usage policy"`, `"violates our"`,
    `"cyber content"`.
  - **`boot-refusal`**: any api-error row not matching the transport
    predicate (refusal wins on tie — usage-policy substring beats
    transport substring; unknown text stays refusal by design, preserving
    today's behavior on any unlabeled row).

  `boot-transport` uses `EPM_BOOT_TRANSPORT_MIN_AGE_MIN` (default 5) instead
  of `EPM_BOOT_DEATH_WINDOW_MIN` (default 30) as its registration-age
  threshold; every other guard is unchanged (transcript quiet ≥ 10 min,
  activity guards, sid liveness, shared day cap).

**A3. Day cap + episode belts + kill switches UNCHANGED.**
`EPM_BOOT_DEATH_STOPS_PER_DAY` (default 3) is the SAME shared counter
across the three shapes; `EPM_DISABLE_BOOT_DEATH_PASS=1` disables ALL
three shapes; no new day-cap bucket, no new day-cap key. A cap-alert at 3

### 4.1 `scripts/tick_triage.py` — add `api_error_after_marker_reason`

New helper `api_error_after_marker_reason(now: float, marker_ts: float | None) -> str | None`,
placed adjacent to `human_activity_reason` (~line 799). Same fail-guard
shape:

```
def api_error_after_marker_reason(now: float, marker_ts: float | None) -> str | None:
    """Return a content-invariant reason suffix when THIS session's
    transcript tail carries an assistant row with `isApiErrorMessage: true`
    whose ts is NEWER than the latest events.jsonl marker ts (#1687), else
    None. Fully exception-guarded (fail toward today's verdict — a
    spurious STALE-REDRIVE is more expensive than a missed one on this
    predicate; the marker-age STALE-REDRIVE remains the backstop).

    Content invariant #1000: the returned reason names ages/counts ONLY,
    NEVER the row's message text (refusal bodies are trigger-dense).
    """
    try:
        # Kill switch shape parallel to human_active_probe_enabled().
        raw = os.environ.get("EPM_TICK_API_ERROR_PROBE", "").strip().lower()
        if raw in ("0", "false"):
            return None
        path = _own_session_transcript_path()
        if path is None:
            return None
        newest_api_error_ts: float | None = None
        for row in _transcript_tail_rows_1629(path):
            if not isinstance(row, dict) or row.get("type") != "assistant":
                continue
            if row.get("isApiErrorMessage") is not True:
                continue
            ts = parse_event_ts(row.get("timestamp"))
            if ts is None:
                continue
            if newest_api_error_ts is None or ts > newest_api_error_ts:
                newest_api_error_ts = ts
        if newest_api_error_ts is None:
            return None
        # STRICT >: a marker posted in the same instant as the api-error
        # row wins (fail toward today's verdict; ts precision is 1s).
        if marker_ts is not None and newest_api_error_ts <= marker_ts:
            return None
        age = now - newest_api_error_ts
        # Future-dated row (clock skew, age < 0): skip, don't latch.
        if age < 0:
            return None
        return f"api-error-after-marker (api-error {age / 60:.0f}m ago, newer than marker)"
    except Exception as exc:
        try:
            _human_probe_debug(f"api-error-probe error={type(exc).__name__}")
        except Exception:
            return None
        return None
```

Wire into `triage()` (line 1015) BEFORE the terminal-streak update but AFTER
the initial verdict computation:

- Placement: immediately after `compute_issue_verdict(...)` returns
  (`if verdict == "STALE-REDRIVE"` branch begins around line 1044). The
  new predicate runs on the HEALTHY-verdict branch (converting HEALTHY ->
  STALE-REDRIVE); the STALE-REDRIVE-converted-to-HEALTHY branch (#1051
  liveness screen + #1629 human-active) already handles its own rescue,
  and this predicate does NOT compete with those (an api-error row
  newer than the latest marker + a fresh human message can coexist —
  the human screen still wins in that case: it runs FIRST and shortcircuits).

- ORDER (invariant: HEALTHY stays ONE Bash call): keep the current
  liveness-first / human-active-second cascade INSIDE the
  `if verdict == "STALE-REDRIVE":` branch. Add the new predicate on the
  HEALTHY path, ONLY when the initial verdict was HEALTHY (i.e. we did
  not already promote back from STALE-REDRIVE). Concretely:

```
if kind != "campaign":
    marker_ts = latest_event_ts(events)
    marker_age = (now - marker_ts) if marker_ts is not None else None
    verdict, reason = compute_issue_verdict(...)
    if verdict == "STALE-REDRIVE":
        # existing #1051 + #1629 cascade unchanged
        ...
    elif verdict == "HEALTHY":
        # NEW: #1687 api-error-after-marker predicate.
        api_err = api_error_after_marker_reason(now, marker_ts)
        if api_err is not None:
            verdict = "STALE-REDRIVE"
            reason = (
                f"status={status}, marker age "
                f"{marker_age / 60:.0f}m — {api_err}"
                if marker_age is not None
                else f"status={status}, no markers — {api_err}"
            )
```

Note: the predicate reads the SAME transcript file `human_activity_reason`
already reads via `_own_session_transcript_path` — an OS-level file cache
hit; on a purely HEALTHY tick the file is read AT MOST ONCE by this new
predicate (the `human_activity_reason` call is inside the STALE-REDRIVE
branch, which is not entered on a HEALTHY tick). ONE Bash call preserved.
The predicate is skipped when the initial verdict is TERMINAL /
GATE-TRANSITION (teardown wins by design — a refusal after gate-park is
still a teardown, and honouring it here would create an infinite
alternation between TERMINAL and STALE-REDRIVE).

**Kill switch:** `EPM_TICK_API_ERROR_PROBE=0` disables the predicate
(restores pre-#1695 HEALTHY behavior). Parallel to
`EPM_TICK_HUMAN_ACTIVE_PROBE`.

**(a) Transport / refusal substring classifier (new pure function).**

Constants near the boot-death lane constants (~line 1620):

```
# Transport substrings (case-insensitive, whole-content match). Verbatim
# from #1689 ("Repeated 529 Overloaded errors") + the SDK-standard
# retryable-error names (rule 24, .claude/rules/llm-judging.md).
BOOT_TRANSPORT_SUBSTRINGS: tuple[str, ...] = (
    "529",
    "overloaded",
    "429",
    "rate limit",
    "ratelimit",
    "timeout",
    "connection error",
    "api connection",
)
# Usage-policy substrings (also case-insensitive). Refusal wins on tie:
# a row containing BOTH a transport substring and a usage-policy substring
# stays boot-refusal — we deliberately do not weaken the pre-existing
# refusal shape.
BOOT_REFUSAL_SUBSTRINGS: tuple[str, ...] = (
    "usage policy",
    "violates our",
    "cyber content",
)


def _boot_death_row_texts(row: dict) -> list[str]:
    """Every text field the row's `message.content` exposes. Same
    iteration as `_boot_death_api_error_excerpt` — one pure helper reused
    from both call sites."""
    msg = row.get("message")
    content = msg.get("content") if isinstance(msg, dict) else None
    texts: list[str] = []
    if isinstance(content, str):
        texts.append(content)
    elif isinstance(content, list):
        texts.extend(
            b["text"]
            for b in content
            if isinstance(b, dict)
            and b.get("type") == "text"
            and isinstance(b.get("text"), str)
        )
    return texts


def classify_boot_death_row(row: dict) -> str:
    """Classify the failing api-error row that killed the boot turn.

    Returns 'boot-transport' when the row's text contains ANY
    :data:`BOOT_TRANSPORT_SUBSTRINGS` AND NO :data:`BOOT_REFUSAL_SUBSTRINGS`
    (refusal wins on tie). Returns 'boot-refusal' otherwise (the default;
    preserves today's behavior on unknown text)."""
    texts = _boot_death_row_texts(row)
    joined = " ".join(texts).lower()
    if not joined:
        return "boot-refusal"  # no text to classify -> today's default
    has_refusal = any(sub in joined for sub in BOOT_REFUSAL_SUBSTRINGS)
    if has_refusal:
        return "boot-refusal"
    has_transport = any(sub in joined for sub in BOOT_TRANSPORT_SUBSTRINGS)
    return "boot-transport" if has_transport else "boot-refusal"
```

**(b) `EPM_BOOT_TRANSPORT_MIN_AGE_MIN` env parser.**

Sibling to `_boot_death_window_s()` (~line 24823):

```
BOOT_TRANSPORT_MIN_AGE_S = 5 * 60  # 5 min — the collapsed lane


def _boot_transport_min_age_s() -> float:
    """Boot-transport registration-age threshold in seconds (env
    `EPM_BOOT_TRANSPORT_MIN_AGE_MIN`, MINUTES). Malformed / non-positive
    env falls back to :data:`BOOT_TRANSPORT_MIN_AGE_S`; never a kill
    switch (the lane's kill switch is EPM_DISABLE_BOOT_DEATH_PASS=1). Exact
    parse shape of :func:`_boot_death_window_s`."""
    raw = os.environ.get("EPM_BOOT_TRANSPORT_MIN_AGE_MIN")
    if not raw:
        return float(BOOT_TRANSPORT_MIN_AGE_S)
    try:
        parsed = float(raw) * 60.0
    except ValueError:
        return float(BOOT_TRANSPORT_MIN_AGE_S)
    if parsed <= 0:
        return float(BOOT_TRANSPORT_MIN_AGE_S)
    return parsed
```

### 4.4 Design invariants (call out for reviewer)

- **HEALTHY stays ONE Bash call.** The new predicate is in-process; it
  reads the same file `human_activity_reason` reads, and only on a
  HEALTHY initial verdict.
- **Refusal wins on tie.** Existing `boot-refusal` behavior is a
  superset of the new `boot-transport` behavior: no refusal that would
  fire under today's rule fires later under the new rule (worst case
  it also matches a transport substring, keeps `boot-refusal`, same
  30-min threshold).
- **Shared day cap.** No new bucket, no new key in the state file —
  `_boot_death_state_path` and `_load_boot_death_state` are UNCHANGED.
- **Fail-open.** Any exception in either half returns to today's
  verdict; the boot-transport classifier defaults to `boot-refusal`
  on unclassifiable text.
- **No new markers.** Existing sentinels
  (`_BOOT_DEATH_STOP_NOTE_SENTINEL`, `_BOOT_DEATH_CAP_NOTE_SENTINEL`)
  carry the new shape in their `shape=` field; no new
  `_WATCHER_NOTE_SENTINELS` member.

## 11. Decision Rationale

`kind: infra` carries no model hyperparameters. The ONE load-bearing
value is the transport-lane threshold:

- **`EPM_BOOT_TRANSPORT_MIN_AGE_MIN = 5` (minutes).**
  - **What.** The registration-age threshold before the boot-death lane
    can stop a session classified `boot-transport`. Today's shared
    threshold is 30 min (`EPM_BOOT_DEATH_WINDOW_MIN` default).
  - **Why.** 529 / 429 / timeout / connection errors are freely
    retryable (`.claude/rules/llm-judging.md` rule 24 — the SDK's
    transient tuple is the canonical set). A fresh session boots
    against the same provider on retry; if the provider was
    transiently overloaded, AIMD back-off resolves inside the SDK's
    default 5-retry budget in ~seconds to a few minutes. Waiting 30
    min to distinguish a transport failure from a refusal loses
    ~25 min per incident at zero benefit — the incident #1689 measured
    lifecycle: ~3h creation-to-real-work, ~2h 24m post-stop grace
    dominates, but the pre-stop 30-min refusal-window is the FIRST
    reducible bar.
  - **Source.** `ungrounded — needs smoke-test`. The task body's
    `Confidence (emitter): medium` on this value is explicit
    ("the parked suggestion, not a measured optimum"). Adjacent
    empirical anchor: `.claude/rules/llm-judging.md` rule 24 pins the
    retryable class definition (529 / 429 / timeout / connection)
    and the api_dispatch.py transient-retry budget (5 attempts,
    exponential + AIMD 429 back-off, `DEFAULT_MAX_429_RETRIES = 6`) —
    5 min sits at the far end of that retry budget's typical wall-time
    envelope. The alternative 10 min was rejected: a healthy 529 is
    already resolved well inside that window, so the extra 5 min is
    pure latency with no falsification benefit. The 5-min knob is
    tuneable via env with no code change; a future incident's data
    (e.g. an average boot-transport-stop-to-successful-re-boot wall
    time) is the empirical driver.
  - **Alternatives.**
    - **10 min.** Rejected — a healthy 529 resolves inside the SDK's
      transient budget (typically <2 min in practice); 10 min is
      slack, not signal.
    - **30 min (today's default).** Rejected by the Goal —
      the 30-min waited window is exactly the phenomenon this rule
      exists to shorten.
    - **1 min.** Rejected — leaves no room for a first-turn retry that
      would successfully complete in-session; the tick-cron + spawn
      grace could then hand out a fresh boot BEFORE the SDK's own
      retry budget finishes. 5 min is the "past-SDK-retry-budget"
      floor.

- **`BOOT_TRANSPORT_SUBSTRINGS` (case-insensitive substring set).**
  - **What.** `529 / overloaded / 429 / rate limit / ratelimit /
    timeout / connection error / api connection`.
  - **Why.** These are the SDK's own transient-error class
    (`anthropic._exceptions.OverloadedError` /
    `RateLimitError` / `APITimeoutError` / `APIConnectionError` — plus
    the `APIStatusError` + `status_code == 529` form) as instrumented
    in `llm/api_dispatch.py::_is_transient` (`.claude/rules/llm-judging.md`
    rule 24). Claude Code renders these into the `isApiErrorMessage`
    row's content with those exact substrings ("Repeated 529 Overloaded
    errors" — #1689 body verbatim).
  - **Source.** #1689 body + `.claude/rules/llm-judging.md` rule 24 +
    `src/explore_persona_space/llm/api_dispatch.py::_is_transient`.
  - **Alternatives.** A regex match. Rejected — substrings are
    grep-visible, ruff-safe, and cheaper to test. `re.search` gains
    no signal here.

- **`BOOT_REFUSAL_SUBSTRINGS` (case-insensitive substring set).**
  - **What.** `usage policy / violates our / cyber content`.
  - **Why.** These are the exact refusal wording Claude Code emits on
    a usage-policy refusal (see CLAUDE.md § Spurious usage-policy
    refusals — "violates our Usage Policy" verbatim). "Cyber content"
    is the guard-surface subclass that killed #1098's reviewers.
  - **Source.** CLAUDE.md § Spurious usage-policy refusals; incidents
    #866 / #1073 / #1098 / #1398.
  - **Alternatives.** A single "violates" catch-all. Rejected —
    unrelated content mentioning "violates" (a policy discussion, a
    training-data description) would then fire the refusal branch.

- **Predicate reads TAIL of transcript (256 KB via
  `_transcript_tail_rows_1629`).**
  - **What.** Bound the api-error-after-marker read to the last 256 KB
    of the resolved transcript.
  - **Why.** Same window as the #1104 production wedge window
    (`BOOT_DEATH_TAIL_BYTES = 256 KB`) — the two lanes see the same
    evidence horizon by design. Any api-error row a marker-age-fresh
    HEALTHY tick would care about lives at EOF by construction (the
    failed turn immediately precedes the tick fire).
  - **Source.** `.claude/rules/background-automation.md` § Autonomous-session
    watcher (256 KB widened from 64 KB in #1104, "the smaller window
    held EXACTLY 3 api-error rows on the #1074 incident transcript,
    zero margin"); existing `TRANSCRIPT_TAIL_BYTES = 262144` in
    `tick_triage.py`.
  - **Alternatives.** None considered — the existing constant is the
    single-source-of-truth window.
