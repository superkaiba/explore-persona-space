### 4.2 Flag surface (design question 1)

```
unregister [--issue N] [--session-id SID] [--kind {auto,manual,campaign}] [--force] [--reason STR]
```

- `--issue N` alone → sid inferred from process ancestry (exact reuse of `cmd_register_current`'s walk); removes, among the ≤3 exact filenames `issue-N.json` / `manual-issue-N.json` / `campaign-N.json`, only those recording that sid. This is the collision-yield one-liner: "remove MY registration for #N", symmetric with `register-current --issue N`.
- `--issue N --session-id SID` → explicit sid match, same targeting. No daemon liveness check (the sid being removed is typically dead/yielding).
- `--session-id SID` alone → scan `AUTONOMOUS_REGISTRY_DIR` for files matching the strict regex `^(issue|manual-issue|campaign)-(\d+)\.json$`, remove those recording SID (deliberate-stop cleanup when the issue number isn't at hand). Non-matching files are skipped silently (no per-file noise).
- `--kind` narrows the candidate prefixes (default: all three — the sid match is the real safety mechanism; a sid recorded under any prefix is "mine").
- `--force` → skip the sid match; REQUIRES `--issue` (a forced whole-dir scan is a foot-gun) and is mutually exclusive with `--session-id` (contradictory: "match this sid" + "don't match"). For the operator deliberate-stop path where the entry must go regardless (e.g. after `spawn_session.py stop` on a crashed session whose recorded sid is unrecoverable/garbled).
- Neither `--issue` nor `--session-id` (and no inferable ancestry under a bare no-flag call): usage error, exit nonzero.

**Safety semantics, precisely:** without `--force`, a file is removed IFF `json.loads(path).get("happy_session_id") == sid` (string equality). Mismatch → `KEPT-SID-MISMATCH` line, file untouched, exit 0. Unreadable/garbled/missing-`happy_session_id` entry → `KEPT-UNREADABLE`, untouched (fail toward keep, mirroring the watcher's "every unresolvable input fails toward keep", autonomous_session_watch.py:18783). So a bare `--issue` remove can never delete the OWNER's registration: if the owner's entry names the owner's sid, the yielding duplicate's inferred sid won't match it.

### 4.3 Takeover sentinels (design question 2)

**Excluded, unconditionally — no opt-in flag.** `*.paused-takeover-*` sentinels are a deliberate suppression signal with their own TTL + fail-open lifecycle (#866/#903, spawn_session.py:122-141); their removal belongs to the takeover workflow (rename back, or TTL expiry). Two structural guarantees: the `--issue` form targets exact filenames (no glob at all), and the scan form's strict `\.json$`-anchored regex cannot match a `*.paused-takeover-<suffix>` name even when the free-form suffix itself ends in `.json` (the regex requires the FULL name to be `prefix-<digits>.json`). No `--include-takeover-sentinels` flag — scope discipline (recursion guard, design question 7); if ever needed it's a separate candidate.

### 4.4 Pseudocode

```python
_REGISTRATION_NAME_RE = re.compile(r"^(issue|manual-issue|campaign)-(\d+)\.json$")
_KIND_TO_PREFIX = {"auto": "issue", "manual": "manual-issue", "campaign": "campaign"}

def unregister_paths(
    *, issue: int | None, session_id: str | None, force: bool = False,
    kind: str | None = None, registry_dir: Path | None = None,
) -> list[tuple[str, Path, str]]:
    """Remove issue/manual/campaign registration files, sid-match-guarded.
    Returns [(action, path, detail)]; action in {"removed", "kept-sid-mismatch",
    "kept-unreadable", "missing"}. Never touches takeover sentinels or
    non-registration siblings (exact names / strict regex). Fail toward keep."""
    reg = registry_dir if registry_dir is not None else AUTONOMOUS_REGISTRY_DIR
    prefixes = [_KIND_TO_PREFIX[kind]] if kind else list(_KIND_TO_PREFIX.values())
    scan_mode = issue is None
    if not scan_mode:
        candidates = [reg / f"{p}-{issue}.json" for p in prefixes]
    else:
        candidates = sorted(
            p for p in (reg.glob("*.json") if reg.is_dir() else [])
            if (m := _REGISTRATION_NAME_RE.match(p.name)) and m.group(1) in prefixes
        )
    rows: list[tuple[str, Path, str]] = []
    for path in candidates:
        try:
            entry = json.loads(path.read_text())
            recorded = entry.get("happy_session_id") if isinstance(entry, dict) else None
        except FileNotFoundError:
            if not scan_mode:
                rows.append(("missing", path, ""))
            continue
        except (OSError, ValueError):
            if force:
                path.unlink(missing_ok=True)
                rows.append(("removed", path, "recorded sid unreadable (forced)"))
            elif not scan_mode:
                rows.append(("kept-unreadable", path, "garbled entry — refusing without --force"))
            continue
        if force or (isinstance(recorded, str) and recorded == session_id):
            path.unlink(missing_ok=True)  # atomic; watcher re-globs each pass
            rows.append(("removed", path, f"recorded sid {recorded or '?'}"
                                          + (" (forced)" if force else "")))
        elif not scan_mode:
            rows.append(("kept-sid-mismatch", path,
                         f"recorded sid {recorded!r} != {session_id!r}"))
    return rows


def cmd_unregister(args: argparse.Namespace) -> None:
    """Inverse of register-current: remove this session's registration file(s)."""
    if args.force and args.session_id:
        sys.exit("--force and --session-id are mutually exclusive (--force means "
                 "'skip the sid match'); pass --issue with exactly one of them.")
    if args.force and args.issue is None:
        sys.exit("--force requires --issue (a forced whole-registry scan is refused).")
    sid = args.session_id
    if sid is None and not args.force:
        # Same ancestry walk as cmd_register_current (:2163-2176); NO liveness
        # requirement on the sid being removed, but inference itself needs the
        # daemon's live-children list (we're finding OUR OWN sid).
        children = _live_children()
        pid_to_sid = {c["pid"]: c["happySessionId"] for c in children
                      if isinstance(c.get("pid"), int)
                      and isinstance(c.get("happySessionId"), str)}
        matches = [pid_to_sid[p] for p in _ancestor_pids() if p in pid_to_sid]
        if not matches:
            sys.exit("could not infer this session's Happy id from the process "
                     "ancestry; pass --session-id explicitly (or --force with "
                     "--issue for an unconditional operator removal).")
        sid = matches[0]
    if args.issue is None and sid is None:
        sys.exit("nothing to select: pass --issue and/or --session-id.")
    rows = unregister_paths(issue=args.issue, session_id=sid,
                            force=args.force, kind=args.kind)
    for action, path, detail in rows:
        line = f"{action.upper():<18} {path}"
        if detail:
            line += f" ({detail})"
        if args.reason:
            line += f" [reason: {args.reason}]"
        print(line)
    if not any(a == "removed" for a, _, _ in rows):
        print("nothing removed")
```

p_unreg = sub.add_parser(

    help=("remove this session's issue/manual/campaign registration file(s) — the "

p_unreg.add_argument("--kind", choices=("auto", "manual", "campaign"), default=None, help="narrow to one registration kind (default: all three)")
p_unreg.add_argument("--force", action="store_true", help="skip the sid match (requires --issue; mutually exclusive with --session-id)")

**Breadcrumb/logging (design question 3):** one stdout line per candidate (`REMOVED <path> (recorded sid <sid>)`, `KEPT-SID-MISMATCH ...`, `KEPT-UNREADABLE ...`, `MISSING <path>`), plus optional `--reason` echoed per line — audit lands in the calling session's transcript/log, mirroring `stop --reason`'s spirit (spawn_session.py:2825-2828) WITHOUT coupling this CLI to `task.py` marker posting (the yield paths post their own `deliberate-stop` breadcrumb already; SKILL.md :936).

**Concurrency (design question 4):** `Path.unlink(missing_ok=True)` is a single atomic POSIX syscall; the watcher re-globs `AUTONOMOUS_REGISTRY_DIR` on every pass and its readers tolerate a vanished file (its own removal sites use the identical call, :18840); a reader holding an open fd reads the old content harmlessly. **Accepted residual:** the read-sid-then-unlink pair has a ms-scale TOCTOU — a concurrent re-registration (atomic `tmp.replace(dest)`) landing between our read and unlink could be unlinked despite naming a fresh sid. That interleaving requires a re-spawn/re-register racing a yield's unregister on the same issue inside milliseconds — the duplicate-dispatch scenario the #843 dispatch lease already serializes upstream; the failure mode (a live session briefly unregistered) is exactly the pre-existing #472 revival class the watcher's orphan sweep + `register-current` recover from. Not worth a lock file (the watcher's own unlinks accept the same window).

## 11. Decision Rationale

`architectural: false` — a purely additive subcommand; no existing CLI contract, subcommand, marker schema, status enum, or file location is changed (the bar in workflow-fix-on-bug.md § Architectural greenlight).

1. **Sid-matched removal as the no-flag default.** *What:* remove only files recording the caller's sid. *Why:* the dangerous case is a bare `--issue` remove deleting the OWNER's registration (strips crash-recovery from a healthy session); sid match makes the collision-yield case ("remove MINE") safe by construction. *Source:* #843 M2 collision refusal (spawn_session.py:550-577 — the write side already refuses to clobber a live owner) + watcher fail-toward-keep (autonomous_session_watch.py:18783). *Alternative rejected:* bare `--issue` unconditional remove (the #952 hand-`rm` semantics — exactly the risk being closed).
2. **Ancestry inference for the default sid.** *What:* reuse `cmd_register_current`'s `_live_children()` + `_ancestor_pids()` walk; fail loud if unresolvable. *Why:* symmetry — `unregister --issue N` becomes the exact inverse one-liner of `register-current --issue N`; never guesses. *Source:* spawn_session.py:2163-2176. *Alternative rejected:* requiring `--session-id` always (worse ergonomics for the primary yield use case).
3. **No daemon liveness check on an explicit `--session-id`.** *What:* unlike `register-current`, do not require the sid to be live. *Why:* the sid being removed is typically dead/yielding; a liveness requirement would defeat the deliberate-stop path. *Source:* contrast with :2155-2162 (liveness there prevents registering a DEAD session — the inverse concern).
4. **Exact-filename targeting + strict name regex; takeover sentinels excluded unconditionally.** *What:* `--issue` form builds exact paths; scan form filters `^(issue|manual-issue|campaign)-(\d+)\.json$`. *Why:* the registry dir holds many sibling file classes (`dispatch-lease-*`, `campaign-watch-*`, `pm-session.json`, `issue-progress/`, state files, `*.paused-takeover-*`); a loose glob is the scrape hazard the codebase already documents. *Source:* `_load_session_issue_map`'s explicit-prefix rationale (spawn_session.py:763-772) + the takeover convention (:122-141, #866/#903) + the prefix-collision-safe glob note (:193).
5. **`Path.unlink(missing_ok=True)`, no lock.** *What:* single atomic unlink, tolerate missing. *Why/Source:* mirrors the watcher's own removal call sites (autonomous_session_watch.py:18840, :15132, :11715); the watcher re-globs each pass; TOCTOU residual accepted per §4.4.
6. **`--force` requires `--issue` and excludes `--session-id`.** *What:* unconditional removal is issue-scoped only. *Why:* a forced whole-dir scan has no legitimate use and maximal blast radius; `--force`+`--session-id` is self-contradictory. *Source:* fail-loud-over-silent posture (CLAUDE.md Critical Rules) + the watcher's bounded-blast-radius removal design.
7. **`--reason` echoed to stdout only, no task marker.** *What:* audit string in the output lines. *Why:* the yield paths already post their own `deliberate-stop` breadcrumb (SKILL.md :936/:1006); coupling this CLI to `task.py` would violate its layering (and the pod-side `task.py` ban). *Source:* `stop --reason` precedent (spawn_session.py:2825-2828).
8. **Docs in `background-automation.md`, not SKILL.md.** *What:* one paragraph in the registry section; SKILL.md untouched. *Why:* sibling #1326 (`planning`) is concurrently rewriting the Step-0 guard block — the only natural SKILL.md site; same-file collision avoidance at zero gap-closure cost. *Source:* #1326 body (`task.py view 1326`) + clarifier directive.
