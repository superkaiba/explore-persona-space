# Plan v1 — task #2007: worktree_audit gc-wedge tier (git prune + gc.log)

## 1. Goal / Requirement

Add a maintenance tier (`gc_wedge_tier`) to `scripts/worktree_audit.py` (the daily 09:47 janitor) that clears the shared repo-root git-gc wedge: bounded `git prune`, then removal of the stale `.git/gc.log` + `.git/worktrees/*/gc.log` blocker files so auto-gc re-arms. Report-only in dry-run; acts only under `--apply` (the cron path). The first `--apply` run doubles as the one-off unwedge.

**Acceptance criteria**
1. Dry-run (`worktree_audit.py` with no flags) REPORTS wedge state (gc.log count root+worktrees, loose-object count, would-prune) and mutates NOTHING.
2. `--apply` with wedge evidence present: runs `git prune --expire=<EXPIRE>` at the repo root (bounded timeout), then removes `.git/gc.log` and `.git/worktrees/*/gc.log`, then re-measures and reports loose-objects before/after in both text and `--json` output.
3. No wedge evidence (no gc.log anywhere) → tier is a complete no-op (zero subprocess calls beyond the existence probes).
4. `git prune` failure/timeout → gc.log files are NOT removed (fail toward status quo), loud `!! gc-wedge:` escalation line, `failed: true` in JSON.
5. Post-prune loose count still ≥ threshold → loud `!! GC WEDGE PERSISTS` escalation line + JSON flag (visible in the cron log), gc.log still cleared (auto-gc will re-write it if it re-wedges — that recurrence is the escalation signal).
6. Kill switch `EPM_SKIP_GC_WEDGE_TIER=1` disables the tier entirely (janitor convention).
7. Unit tests cover 1-6; ruff clean on touched files; `workflow_lint.py --check-asks` unaffected.

## 2. Method delta (what differs from prior state)

`worktree_audit.py` today runs only `git worktree prune` (admin-entry cleanup, L1164/L1241) — it never touches the object database or gc.log. Delta: one additive tier + additive `AuditResult` fields (the #912 venv-arm pattern: defaults keep every existing consumer unchanged).

## 3. Key design decisions (with grounding)

- **D1 — prune-then-clear ordering (body's flagged hypothesis: CONFIRMED).** `git gc --auto` skips (printing the log) while `gc.log` exists and is fresher than `gc.logExpiry` (default `1.day.ago`, verified unset in this repo → default applies); removing gc.log re-enables auto-gc on the next qualifying command. Pruning FIRST drops the loose count below the `gc.auto` trigger (default 6700, verified unset) so the re-enabled auto-gc does not immediately fire a heavy gc mid-session. Ordering: prune → verify → clear.
- **D2 — default expiry `1.hour.ago`, env-overridable (`EPM_GC_PRUNE_EXPIRE`).** Measured 2026-08-06 on the live root: **0 of 17,686 loose objects are older than 14 days** — auto-gc already applies `gc.pruneExpire=2.weeks.ago` daily (gc.log mtime advances daily) and stays wedged, so a 2-week expiry provably prunes nothing and the tier would loop escalating forever. Safety argument for 1 hour: `git prune` keeps every object reachable from all refs (all worktrees' HEADs + refs), the index(es), and reflog entries (fsck-unreachable semantics); the only unprotected class is objects written but not yet referenced (mid `git add`/`commit`), a seconds-scale window that a 1-hour grace covers with ~3 orders of magnitude of margin. Never bare `git prune` (no expiry = zero grace); never `git gc --aggressive` (body constraint).
- **D3 — trigger = gc.log existence only.** Fires only when `<common-dir>/gc.log` or any `<common-dir>/worktrees/*/gc.log` exists. No unconditional pruning: absent a wedge the tier is a no-op, so healthy repos never pay the prune walk.
- **D4 — placement + concurrency.** Called from `audit()` right after the final `git worktree prune` (apply path), inside the existing single-instance flock; cron slot 09:47 is the quiet window. `git prune` needs no repo-wide lock — reachability semantics + D2 grace protect concurrent committers. Subprocess timeouts: prune 600s, count-objects 60s (fail → treated as prune failure, criteria 4).
- **D5 — escalation threshold.** `EPM_GC_WEDGE_LOOSE_THRESHOLD` (default 6700, mirroring `gc.auto`). Post-prune count ≥ threshold → PERSISTS escalation. Rationale: if young churn alone exceeds the auto-gc trigger, pruning cannot help and a human decision (raise gc.auto, repack cadence) is owed — the loud line + daily recurrence is the surfacing channel; no auto-filing (this session is recursion-guarded, and the tier itself never files tasks).
- **D6 — gc.log removal scope.** Exactly the files named `gc.log` at `<common-dir>` and `<common-dir>/worktrees/<id>/`; resolved via `git rev-parse --git-common-dir` (never a hand-built `.git` literal — worktree-safe). Nothing else under `.git` is ever touched; no `reset`/`checkout`/`clean` anywhere (body invariant).

## 4. File paths + concrete changes

1. `scripts/worktree_audit.py`
   - New module consts: `GC_PRUNE_EXPIRE_DEFAULT = "1.hour.ago"`, `GC_WEDGE_LOOSE_THRESHOLD_DEFAULT = 6700`, timeouts.
   - New `AuditResult` fields (additive, defaulted): `gc_wedge_detected: bool = False`, `gc_log_files: list[str]`, `gc_loose_before: int | None`, `gc_loose_after: int | None`, `gc_pruned: bool = False`, `gc_logs_cleared: int = 0`, `gc_wedge_failed: bool = False`, `gc_wedge_persists: bool = False`, `gc_wedge_skipped: str | None = None` (kill-switch/timeout reason).
   - New helpers: `_gc_log_files(root) -> list[Path]` (common-dir resolution), `_loose_object_count(root) -> int | None` (parses `git count-objects -v`), `gc_wedge_tier(root, res, apply) -> None`.
   - `audit()`: invoke the tier after the closing `git worktree prune` (apply and dry-run both — dry-run only probes + reports).
   - `main()`: text-report block (`gc-wedge:` lines incl. the two `!!` escalations) + `--json` key `gc_wedge: {...}` (additive).
2. `tests/test_worktree_audit.py` — new tests (monkeypatched subprocess, tmp_path fixtures, matching existing style):
   - no gc.log → no-op (no prune subprocess call);
   - gc.log present, dry-run → reported, no prune, files kept;
   - gc.log present, `--apply` → prune called with the expiry arg, gc.log files (root + worktree) removed, before/after counts recorded;
   - prune nonzero rc / timeout → gc.log kept, `gc_wedge_failed`;
   - post-prune count ≥ threshold → `gc_wedge_persists`;
   - `EPM_SKIP_GC_WEDGE_TIER=1` → tier disabled;
   - env-override expiry threads into the prune argv.
3. NO change to `scripts/cron_worktree_audit.sh` (the tier rides the existing `--apply` invocation; no new flag needed).
