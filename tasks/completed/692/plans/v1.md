## 0. Plan Summary

**What this fixes:** the #664-class RunPod billing leak (a pod stuck
RUNNING-but-no-public-port on a degraded host) currently has TWO detectors —
the poller (`backend_poll._maybe_escalate_runpod_wedge`, shipped by #689 fix
(b)) and the fleet-level report-only `pod_audit.py running_no_port` flag — but
NEITHER fires when the per-issue poll loop has DIED (crashed `/issue` session,
OOM-killed bg-Bash poll chain, VM reboot). When the poller is dead, the wedge
goes undetected and the pod bills indefinitely. The autonomous-session watcher
(`autonomous_session_watch.py`) runs unconditionally every 10 min, independent
of any session or the poller, and already reconciles RUNNING managed pods in
its pod-safety pass — but it ONLY keys on task STATUS (auto-stop a DONE task's
escaped pod; alert a stale pod-active task). It is blind to the wedge: a wedged
pod whose task is still `running`/`approved` classifies `pod-active-fresh` (no
real progress markers → actually `pod-active-stale` after 6h, but only ALERTs,
never stops) and burns until a human notices.

The fix adds a NEW wedge arm to the watcher's per-pod handler: detect the raw
RUNNING-but-no-port condition from the live `PodInfo` the watcher ALREADY
fetched, age it against the pod-safety state file's existing `first_seen`
clock, and — past K (the SAME `RUNPOD_WEDGE_K_SEC` constant the poller uses) —
ALERT by default and AUTO-STOP only when the same inputs-on-HF + keep-running
gates fix (b) uses confirm it is safe.

- **Composition surface (resolves clarifier item 1):** option (b) — extract the
  RAW wedge predicate (`desired_status == "RUNNING"` AND no public port) from
  `_maybe_escalate_runpod_wedge` into a small standalone helper
  `backend_poll._pod_is_runpod_runtime_wedged(info) -> bool`; both
  `_maybe_escalate_runpod_wedge` and the new watcher arm call it. Option (a)
  (call `_maybe_escalate_runpod_wedge` from the watcher) is rejected — it reads
  the poller's sidecar clock + mutates it, double-writing a clock the watcher
  doesn't own; the watcher uses its OWN `first_seen` clock instead. Option (c)
  (re-implement locally) is FORBIDDEN by the "do NOT re-define" constraint.

- **Where loss/data is gated:** N/A (no training). The wedge AUTO-STOP reuses
  fix (b)'s `_wedged_run_inputs_on_hf` per-cell inputs-on-HF gate AND the
  watcher's existing `_task_keep_running` check; an unverified-inputs / tagged /
  no-handle pod is ALERT-only (never auto-stopped).

- **STOP, never terminate.** The watcher's wedge arm calls the SAME reversible
  `_stop_pod` (`pod.py stop`, volume preserved) the existing auto-stop-done arm
  uses — NOT `terminate_pod`. The poller's fix (b) is the path that terminates +
  re-provisions; the watcher backstop only needs to halt the billing leak (a
  human / re-invoked `/issue` then resumes or re-provisions). This is the
  conservative choice: the watcher has no run handle guarantee and runs blind to
  the dispatcher's resume state, so it stops (reversible) rather than terminates
  (irreversible) — CLAUDE.md halt-criterion #2.

- **Compute:** 0 GPU-h. Wall-time for the implementer ~2-3 h (predicate
  extraction + watcher arm + ~8-10 unit tests + lint + full named-regression
  suite).

- **Evaluation (acceptance):** new unit tests PASS; `decide_pod_safety` (or a
  sibling pure decision fn) returns the wedge action for the wedge case and is
  unchanged for the existing cases; `scripts/workflow_lint.py --check-asks`
  PASS; ruff PASS on the two touched files; existing watcher + wedge + backend
  suites still PASS.

- **Risks (top 2):** (1) a wedge false-positive on a transient API blip /
  healthy mid-resume pod — guarded by the K=900s `first_seen` floor (above
  `wait_for_ssh`'s 600s) AND a ≥2-consecutive-checks miss guard mirroring the
  existing auto-stop arm, so a single glitch never stops a pod; (2)
  double-firing with the poller when BOTH are alive — harmless because the
  watcher only STOPS (reversible) and only after the K floor + miss guard, and
  the poller's terminate path is idempotent (durable lease + sentinel from #689
  blocker-2); the realistic concurrent case is the poller wins first (it
  matures at K, terminates) and the watcher's next tick sees the pod gone from
  the RUNNING set and GCs its state.

## 1. Goal

Add a RUNNING-but-no-port wedge predicate to
`scripts/autonomous_session_watch.py`'s pod-safety pass so that — when the
poller-side `_maybe_escalate_runpod_wedge` in `scripts/backend_poll.py` never
runs because the poll loop has died — the watcher still detects the #664 wedge
and alerts / auto-stops the billing leak. The new predicate composes with the
existing #689 fix (b) (it calls fix (b)'s raw wedge condition, never
re-defines it) and gates any auto-stop on the same inputs-on-HF +
`keep-running` checks as fix (b).

### 4.2 Composition surface (b): extract the raw wedge predicate

In `scripts/backend_poll.py`, the raw wedge condition is currently INLINE in
`_maybe_escalate_runpod_wedge` (L539-544): a pod is wedge-eligible iff its live
`PodInfo` is RUNNING with no public port. Extract:

```python
def _pod_is_runpod_runtime_wedged(info) -> bool:
    """True iff a live RunPod ``PodInfo`` is in the RAW #664 no-port wedge
    condition: ``desired_status == "RUNNING"`` AND no public SSH port
    (``runtime.ports`` empty -> ``runpod_api._parse_pod`` sets
    ``ssh_host``/``ssh_port`` to ``None``). This is the MATURITY-AGNOSTIC raw
    condition only — the K-floor age check stays with each caller (the poller
    uses its sidecar clock; the watcher uses its pod-safety ``first_seen``
    clock). ``info is None`` (pod gone) -> ``False`` (not a wedge; the gone
    pod is the ordinary dead path). The single source of truth for the wedge
    condition, called by BOTH ``_maybe_escalate_runpod_wedge`` (poller) and the
    autonomous_session_watch.py pod-safety wedge arm (watcher backstop, #692)."""
    if info is None:
        return False
    if getattr(info, "desired_status", None) != "RUNNING":
        return False
    return not (info.ssh_host and info.ssh_port)
```

Then `_maybe_escalate_runpod_wedge`'s `healthy_or_terminal` block (L540-544)
becomes:

```python

    if not _pod_is_runpod_runtime_wedged(info):
        # gone / EXITED / port-present -> clear the no-port clock, unchanged.
        _clear_runpod_noport_clock(sidecar)
        return result
    # RUNNING + no public port: start/continue the no-port clock. (unchanged below)
```

This is a pure refactor: the boolean `_pod_is_runpod_runtime_wedged(info) is

`_process_wedged_pod` is a new handler that mirrors the existing `_process_pod`
state mechanics but for the wedge episode:

```python
def _process_wedged_pod(
    issue: int, pod_id: str, now: float, dry_run: bool, threshold: int
) -> None:
    """Handle a RUNNING managed pod observed in the #664 RunPod no-port wedge
    (raw condition already confirmed by the caller). Age the wedge against the
    pod-safety state's first_seen clock; below K (RUNPOD_WEDGE_K_SEC) KEEP +
    persist (the wedge has not matured — a healthy slow bring-up clears it on a
    later tick when the port appears, just like the poller's clock); past K
    apply the >=threshold consecutive-wedge-checks miss guard, then ALERT
    (default) or AUTO-STOP (reversible pod.py stop) gated on the same
    inputs-on-HF + keep-running checks as #689 fix (b)."""
    from backend_poll import RUNPOD_WEDGE_K_SEC

    prev_state = _load_pod_safety_state(issue)
    first_seen = prev_state.get("first_seen")
    if not isinstance(first_seen, int | float):
        first_seen = now  # first observation this incarnation
    wedged_for = now - first_seen
    prev_wedge_missed = prev_state.get("wedge_missed", 0)
    if not isinstance(prev_wedge_missed, int):
        prev_wedge_missed = 0
    prev_wedge_alerted = bool(prev_state.get("wedge_alerted", False))

    keep_running = _task_keep_running(issue)
    inputs_ok = _wedge_inputs_safe(issue) if not keep_running else False

    action, new_wedge_missed = decide_pod_wedge(
        wedged_for=wedged_for,
        k_floor=RUNPOD_WEDGE_K_SEC,
        wedge_missed=prev_wedge_missed,
        threshold=threshold,
        alerted=prev_wedge_alerted,
        keep_running=keep_running,
        inputs_ok=inputs_ok,
    )
    # ... log line, then branch on action (stop / alert / keep), persisting
    # wedge_missed + wedge_alerted + first_seen via _save_pod_safety_state.
```

The miss-guard is a NEW per-pod state field `wedge_missed` (separate from the
status-class `missed`, since the two arms are mutually exclusive on a given tick
but a pod can transition wedge→status-class or vice versa across ticks; keeping
them separate means a brief mis-read in one arm never primes a stop in the
other). `first_seen` is the existing field (set on the first save of this RUNNING
pod-incarnation, reaped by `_gc_orphan_pod_safety_state` when the pod leaves
RUNNING) — so it measures how long THIS watcher has continuously observed the
pod RUNNING, which is the correct maturity clock when the poller's sidecar clock
is dead/absent.

### 4.5 The pure wedge decision function (parallel to `decide_pod_safety`)

```python
def decide_pod_wedge(
    *,
    wedged_for: float,
    k_floor: float,
    wedge_missed: int,
    threshold: int,
    alerted: bool,
    keep_running: bool,
    inputs_ok: bool,
) -> tuple[str, int]:
    """Pure decision for a RUNNING managed pod in the #664 no-port wedge.

    Returns ``(action, new_wedge_missed)`` where action is
    ``"stop"`` | ``"alert"`` | ``"keep"``.

    - ``wedged_for <= k_floor`` -> ``("keep", 0)``. Below the K maturity floor
      the wedge has not matured (a healthy slow bring-up clears it when the
      port appears); reset the miss counter so a brief no-port blip never
      accumulates toward a stop.
    - ``wedged_for > k_floor`` AND ``wedge_missed + 1 < threshold`` ->
      ``("keep", wedge_missed + 1)``. Past K but not yet confirmed for
      ``>=threshold`` consecutive checks; accumulate (the same >=2-checks guard
      the status-class auto-stop uses, so a single transient API mis-read never
      stops a pod).
    - ``wedged_for > k_floor`` AND confirmed (``wedge_missed + 1 >= threshold``):
        - ``keep_running`` -> ``("alert", 0)``. The keep-running tag exempts the
          AUTO-STOP exactly as it does for the status-class arm; the wedge is
          still surfaced once per episode so the leak is visible. (No
          "keep-running-skip" action — the wedge ALERT already carries the
          tag-exemption note; the status-class arm's distinct skip action exists
          only to reset its own miss counter, which the alert branch does here.)
        - not ``keep_running`` AND ``inputs_ok`` -> ``("stop", 0)``. Inputs are
          verified on HF (the same gate as #689 fix (b)) and no keep-running
          tag, so the reversible STOP is safe — halt the billing leak.
        - not ``keep_running`` AND not ``inputs_ok`` -> ``("alert", 0)``.
          Inputs are NOT verified on HF (or no run handle to gate on); a STOP
          could strand un-uploaded work, so ALERT-only and let a human / the
          re-invoked /issue decide (CLAUDE.md halt-criterion #2). The
          poller's fix (b) is the path that terminates after the per-cell gate;
          the watcher backstop never terminates and only stops when inputs are
          provably safe.

    The ``alerted`` flag dedups the once-per-episode alert (the caller passes it
    and persists ``wedge_alerted``); a fresh wedge episode (the pod left RUNNING
    and a new incarnation re-entered) starts ``alerted=False`` because
    ``_gc_orphan_pod_safety_state`` reaped the state file."""
```

The alert dedup mirrors the status-class arm: `_process_wedged_pod` passes
`alerted=prev_wedge_alerted` and, when `action == "alert"`, posts the marker
only if `not prev_wedge_alerted`, then persists `wedge_alerted=True`. When the
port re-appears (the pod heals or is re-provisioned) the pod leaves the
no-port condition and the next tick takes the status-class path; if the pod
leaves RUNNING entirely, `_gc_orphan_pod_safety_state` reaps the state.

### 4.6 The inputs-on-HF gate (compose with fix (b))

The candidate body requires "the same inputs-on-HF + keep-running checks as fix
(b)." Fix (b)'s gate is `backend_poll._wedged_run_inputs_on_hf(issue, handle)
-> _WedgeInputsGate` (`.ok` True iff zero partial cells). It needs a run
handle. The watcher does NOT always have one in hand, but the handle is
persisted at `.claude/cache/issue-<N>-handle.json`
(`issue_dispatch.resolve_handle_sidecar_path`), so:

```python
def _wedge_inputs_safe(issue: int) -> bool:
    """True iff the wedged run's recoverable inputs are verified on HF, gating
    the watcher's reversible AUTO-STOP exactly as #689 fix (b) gates the
    poller's irreversible terminate. Reuses backend_poll._wedged_run_inputs_on_hf
    (the per-cell three-state inputs-on-HF gate). The run handle is read from
    the persisted sidecar (.claude/cache/issue-<N>-handle.json). Fail-CLOSED:
    a missing/unreadable handle, an HF-listing transport error, or ANY
    exception -> False (ALERT-only, never an unsafe stop). For a non-#664 issue
    _wedged_run_inputs_on_hf returns ok=True (the adapters-only path is
    inline-verified), so the gate degrades to "safe to stop" for those — which
    is correct: a reversible STOP loses nothing when there are no per-cell
    artifacts to strand."""
    try:
        from backend_poll import _wedged_run_inputs_on_hf
        from explore_persona_space.backends.issue_dispatch import (
            load_handle, resolve_handle_sidecar_path,
        )
        path, _probed = resolve_handle_sidecar_path(issue)
        if not path.exists():
            return False  # no handle -> cannot gate -> ALERT-only
        handle = load_handle(path)
        gate = _wedged_run_inputs_on_hf(issue, handle)
        return bool(gate.ok)
    except Exception as exc:  # transport / parse / import -> fail-closed
        print(
            f"  wedge: inputs-on-HF gate unavailable for #{issue} "
            f"({type(exc).__name__}: {exc}); ALERT-only (no auto-stop)",
            file=sys.stderr,
        )
        return False
```

(`load_handle` is the existing reader at `issue_dispatch.py:388`; confirm its
exact name at implement time — it deserializes the sidecar JSON via
`deserialize_handle`. If the public name differs, use
`deserialize_handle(json.loads(path.read_text()))` directly.)

The fail-closed posture is deliberate and the SINGLE most important safety
property: the watcher AUTO-STOP only fires when inputs are PROVABLY safe; every
uncertainty path (no handle, HF error, import failure, keep-running tag) routes
to ALERT-only. A false ALERT is a cheap nudge; a false STOP is reversible
anyway (volume preserved), but ALERT-only on uncertainty keeps the watcher from
ever interrupting a run whose state it cannot read.

## 5. Conditions and Controls

This is an infra change, not a multi-condition experiment. The "conditions"
are the decision-table cases the new `decide_pod_wedge` must satisfy, each a
unit-test case:

| Plain-English name | What it tests | What it controls for | Config slug |
|---|---|---|---|
| Below maturity floor | `wedged_for <= K` → keep, reset miss | a healthy slow bring-up / transient no-port blip never accumulates | `wedge_below_k` |
| Past K, not yet confirmed | `wedged_for > K`, `missed+1 < threshold` → keep, increment | a single transient API mis-read never stops a pod | `wedge_unconfirmed` |
| Past K, confirmed, inputs safe | confirmed + `inputs_ok` + no tag → stop | the auto-stop fires only when fix (b)'s gate is satisfied | `wedge_stop` |
| Past K, confirmed, inputs unverified | confirmed + not `inputs_ok` → alert | un-uploaded work is never stranded by a stop | `wedge_alert_unverified` |
| Past K, confirmed, keep-running tag | confirmed + `keep_running` → alert | the tag exemption matches the status-class arm | `wedge_alert_keep_running` |
| Alert dedup | second confirmed tick with `alerted=True` → no duplicate marker | once-per-episode alert | `wedge_alert_dedup` |
| Raw predicate true | RUNNING + no port → `_pod_is_runpod_runtime_wedged` True | the extracted predicate matches the inline condition | `pred_wedged` |
| Raw predicate false (port present) | RUNNING + port → False | a healthy pod is never wedge-classified | `pred_healthy` |
| Raw predicate false (gone/EXITED) | None / non-RUNNING → False | the gone/terminal pod takes the ordinary path | `pred_gone` |

## 8. Risks and Failure Modes

| Risk | Likelihood | Mitigation |
|---|---|---|
| Wedge false-positive on a healthy mid-resume / slow-bring-up pod (port not yet up) | Medium | The K=900s `first_seen` floor (above `wait_for_ssh`'s 600s window + retry margin, the same rationale as the poller's K) PLUS the `>=2`-consecutive-confirmed-checks miss guard. Below K the arm KEEPs and resets the counter, so a transient no-port window never accumulates. |
| Double-firing with the poller when BOTH are alive | Low | The watcher only STOPs (reversible) and only past K + miss guard; the poller's terminate path is idempotent (durable lease + sentinel, #689 blocker-2). The realistic concurrent outcome: the poller matures at K and terminates first; the watcher's next tick sees the pod gone from the RUNNING set and `_gc_orphan_pod_safety_state` reaps the wedge state. A watcher STOP that lands first just pauses the pod (volume preserved); the poller then reads the pod EXITED and clears its clock. |
| `_wedge_inputs_safe` raises (HF transport error, handle parse) and the wedge is never surfaced | Low | Fail-CLOSED to `False` → ALERT-only (never a missed surface, never an unsafe stop). The wrapper catches `Exception`, logs, returns False. |
| `PodInfo` signature change breaks an unrelated caller | Low | Exactly 3 callers of `_running_managed_issue_pods` (grepped); all updated in the same diff; the two that don't need it unpack `_info`. A unit test asserts the 4-tuple shape. |
| `wedge_missed` state field collides with the status-class `missed` | Low | Separate field name; `_save_pod_safety_state` carries both forward (the existing `keep_running_noted`/`followup_noted` forward-carry pattern). A pod can only be in ONE arm per tick (wedge OR status-class), and each arm reads only its own counter. |
| The extracted predicate drifts from the inline condition during refactor | Low | The refactor replaces the inline guard with a call to the new helper in the SAME diff; `test_runpod_wedge_detection.py` (unchanged) is the regression net. |

## 11. Decision Rationale

- **What:** Composition surface (b) — extract a standalone raw-wedge predicate.
  **Why:** the candidate body's suggested `_is_runpod_async_wedge_failure` reuse
  is wrong — that predicate matches the SYNTHESIZED terminal phase the poller
  sets, which only exists when the poll loop is ALIVE (precisely when the
  backstop is NOT needed). The watcher must detect the RAW API condition.
  Option (a) (call `_maybe_escalate_runpod_wedge`) double-writes the poller's
  sidecar clock the watcher doesn't own and couples the watcher to the poller's
  mutation surface; option (c) (re-implement) violates the "do NOT re-define"
  constraint. (b) gives ONE source of truth for the wedge condition with no
  shared mutable state. **Source:** #689 `backend_poll.py` L515-583 (the inline
  condition extracted), clarifier item 1.

- **What:** Reuse the pod-safety state file's existing `first_seen` as the
  maturity clock (not a new clock, not the poller's sidecar clock). **Why:** the
  candidate body explicitly says "do NOT add new state-file types if the
  existing pod-safety state file can carry the wedge timestamp." `first_seen` is
  already set on the first observation of a RUNNING pod-incarnation and reaped
  when the pod leaves RUNNING (`_gc_orphan_pod_safety_state`), so it measures
  exactly "how long the watcher has continuously seen this pod RUNNING" — the
  correct maturity signal when the poller's clock is dead. **Source:**
  `autonomous_session_watch.py` `_save_pod_safety_state` L1979 (`first_seen`
  forward-carry); candidate body constraint.

- **What:** K = imported `RUNPOD_WEDGE_K_SEC` (900s), never a duplicated
  literal. **Why:** the "compose with #689 fix (b), do NOT re-define it"
  constraint — the watcher and poller MUST agree on the maturity floor, so they
  share the constant. 900s is above `wait_for_ssh`'s 600s window + a retry
  margin, so a healthy mid-resume pod never trips (the same rationale #689
  recorded for the poller). **Source:** #689 plan §B.3 / `backend_poll.py` L131
  (`RUNPOD_WEDGE_K_SEC`).

- **What:** ALERT-default, AUTO-STOP only when inputs-on-HF + keep-running gates
  pass; reversible STOP, never terminate. **Why:** the candidate body requires
  "gate any auto-stop on the same inputs-on-HF + keep-running checks as fix (b)"
  and "default to ALERT-only" without that gate. The watcher runs blind to the
  dispatcher's resume state and has no run-handle guarantee, so the irreversible
  terminate (fix (b)'s job, gated on the full per-cell three-state inputs gate
  with a live handle) is wrong for the backstop; the reversible STOP halts the
  billing leak while preserving the volume for a human / re-invoked `/issue` to
  resume or re-provision. Fail-closed on every uncertainty (no handle, HF error,
  tag) → ALERT-only. **Source:** candidate body constraints; CLAUDE.md
  halt-criterion #2 (irreversible writes need a human); #689
  `_wedged_run_inputs_on_hf` (the reused gate).

- **What:** `>=2`-consecutive-confirmed-checks miss guard (new `wedge_missed`
  field). **Why:** mirrors the existing `decide_pod_safety` auto-stop guard so a
  single transient API mis-read never stops a pod; a separate field keeps the
  two arms from priming each other. **Source:** `decide_pod_safety` L973+ (the
  existing 2-miss guard the wedge arm copies).

- **What:** No new `workflow.yaml` marker schema; generic `epm:progress` +
  sentinel substrings. **Why:** the candidate body's "do NOT propose new GitHub
  markers / event kinds; surface alerts via the existing `_post_progress_marker`
  mechanic" constraint — every existing watcher action already does this.
  **Source:** candidate body constraint; `_post_progress_marker` L2145.
