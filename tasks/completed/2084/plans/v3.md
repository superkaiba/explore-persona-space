Deliverable: an ESCALATE-ONLY, advancement-clear-EXEMPT, progress-keyed counter that — after N consecutive watcher respawns on an issue with no intervening real marker — surfaces the loop loudly (one deduped task marker + Telegram push + sidecar row) while leaving the respawn lane's behavior COMPLETELY unchanged.

## 3. Design

**State** (new fields in the existing `stalled-<N>.json`; file already GC'd via `STALLED_STATE_PREFIX`, already survives across respawn generations):

- `xgen_respawns: int` — consecutive watcher respawns with no intervening real marker.
- `xgen_last_real_marker_ts: str|None` — newest real (non-watcher, per `_WATCHER_NOTE_SENTINELS` filtering) marker ts observed at the moment of the LAST counted respawn.
- `xgen_escalated_at: int` — the counter value at the most recent escalation (0 = never), for once-per-threshold-band dedup.

These three fields are EXEMPT from the advancement-clear (added to the #1209/#1241 exempt set with a comment citing this issue), and are NOT day-keyed — the predicate is purely progress-keyed, matching the ask ("N respawns with no intervening real marker" is the reliable signal; elapsed-time heuristics had 5 false positives on 2026-08-04 per the task body).

**Counting rule** (honors the body's measurement caveat — count respawn EVENTS the watcher fires, never grep marker literals from `task.py view` output): at each `_fence_spawn_stalled` spawn-branch fire — the SOLE `session-auto-respawn` marker post site (~L19318), and the shape of every respawn in the motivating #2004 incident. Scope note (critic round 1): wedge/dead-silence fence episodes whose respawn completes via the crash-recovery arm are NOT counted — the counter's semantics are "fence-spawn fires", stated as such in the escalation marker note. At each counted fire, read the pass's already-computed newest real-marker ts (`_latest_nonwatcher_event_ts`, computed at pass entry ~L20599, threaded via ctx):

- if it is newer than `xgen_last_real_marker_ts` → the intervening generation made real progress → `xgen_respawns = 1`, `xgen_escalated_at = 0`;
- else → `xgen_respawns += 1`.
- Anchor update is monotone: `xgen_last_real_marker_ts = max(old, new)`, skipping a `None`/unreadable current read (a transient empty events read must never overwrite a valid anchor and cause a spurious reset — critic round 1).

**Escalation predicate** — new pure function `decide_stalled_xgen_escalation(*, kill_switch, xgen_respawns, threshold, escalated_at) -> tuple[str, str]` returning `("escalate", reason)` when `xgen_respawns >= threshold` AND `xgen_respawns >= escalated_at + threshold` (fires at N, 2N, 3N…: once per threshold band, so an unbounded loop re-alerts but never per-tick spams), else `("quiet", reason)`. Threshold env: `EPM_STALLED_XGEN_ESCALATE_AFTER` (default **4** — quiet on the benign 2-respawn recovery, fires ~4h into the observed 4–8-respawn loops). Kill switch: `EPM_DISABLE_STALLED_XGEN_ESCALATION=1` → always quiet.

**Escalation channels** (all three, matching house style):

1. ONE `epm:progress` task marker with new sentinel `[autonomous_session_watch:session-auto-respawn-noprogress]` + `_source_stamp()`, noting: xgen count (semantics: fence-spawn fires since last real marker), threshold, ts of last real marker, and the manual triage recipe (check the session transcript / `latest-marker` / consider `task.py set-status <N> blocked` or a takeover). The new sentinel is ADDED to `_WATCHER_NOTE_SENTINELS` so the escalation marker can never reset the real-progress clock or shield the session (anti-liveness).

**Channel ordering + fail-soft (critic round 1):** all three escalation channels run AFTER the spawn branch's existing state persist, each wrapped fail-soft — an exception on the new path must never abort respawn bookkeeping.
2. `_telegram_push` (fail-soft), same dedup as the marker (once per threshold band).
3. Sidecar row appended to `~/.eps-autonomous/stalled-xgen-events.jsonl` (issue, count, threshold, last_real_marker_ts, respawn arm, ts) — outside the `*.json` GC glob by suffix, per convention.

**ESCALATE-ONLY hard invariant**: the new code path performs NO `_stop_session`, NO status mutation, NO respawn suppression, NO cap consumption — pinned by a dedicated test (below).
