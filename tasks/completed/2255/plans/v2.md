## 3. Decision

**Chosen: A+C hybrid, with the GPU-hours read fixed on both prongs.**

1. **A (persist-time, forward-looking):** `new_plan_version` refuses an amendment-shaped version with an actionable error; `--allow-amendment` (CLI) / `allow_amendment=True` (library) is the deliberate escape for the user-authorized case (#2223's v4 was user-directed). This keeps every consumer's one-file assumption true for all future ordinary persists.
2. **C (read-time, backward compat):** `verify_plan.py --issue` detects the amendment shape in the newest version with the SAME predicate, composes delta + base for checking, and emits one unmistakable WARN (new appended check `c60_amendment_composition`) naming the base and the partial-document consequence. This is what satisfies acceptance bullet 1 — #2223's v4 stays byte-untouched on disk, and existing amendments (also #377 v2) keep verifying.
3. **GPU-hours read:** three layers so it "must not silently find nothing": (i) the persist-time predicate REQUIRES the missing declaration as one of its signals, so an undeclared thin amendment can no longer be persisted without the escape; (ii) the refusal/escape message instructs restating the `Estimated GPU-hours (total):` line inside a sanctioned amendment; (iii) a one-sentence SKILL.md Step-2b fallback: for a sanctioned amendment with no own declaration, `<X>` comes from the base version it amends. Composed `verify_plan` c5 additionally passes via the base's line.

**Alternatives rejected:**
- **Pure A** — does not satisfy acceptance bullet 1: rejecting future amendments does nothing for #2223's v4 (and #377's v2) already on disk, and a later session re-running `verify_plan --issue 2223` would still see 4 spurious FAILs and may bounce a healthy plan.
- **Pure B (rendered composition replacing the symlink)** — requires a merge semantics decision (section replace vs append) plus a rendered-artifact lifecycle (when is the composition re-rendered? what commits it?), all on the hot path of every plan persist; the body itself flags it as "more machinery, more ways to be wrong". The C-side composition here is deliberately weaker: concatenation for CHECK purposes only, never a rendered document anyone reads as "the plan".
- **Pure C (warn-only, no persist gate)** — leaves the subagent-brief consequence live for every future amendment: a WARN inside verify_plan output does not reach the 10+ brief-composition sites that pass `plans/plan.md` as THE plan. The persist-time refusal is what protects briefs by construction.
- **Marker-phrase-only or size-only detection** — measured unusable (200 resp. 31 false-positive-dominated hits, §2). Rejected on corpus evidence.

## 4. Detection heuristic spec (shared predicate)

New public helpers in `src/explore_persona_space/task_workflow.py` (one implementation, imported by `verify_plan.py` in `--issue` mode via the same local-import pattern it already uses for `find_task_path`):

```python
AMENDMENT_SIZE_RATIO = 0.4          # new bytes < 0.4 x predecessor bytes
AMENDMENT_MARKER_RE = re.compile(
    r"(?i)\b(?:amendment\s+of\s+v\d+|amends\s+v\d+|ports?\s+from\s+v\d+|unchanged\s+from\s+v\d+)\b"
)
# Parity copy of scripts/verify_plan.py GPU_LINE_RE (pattern equality pin-tested):
AMENDMENT_GPU_LINE_RE = re.compile(
    r"(?i)estimated\s+gpu-?hours\s+\(total\):\**\s*`?([0-9]+(?:\.[0-9]+)?)`?"
)

def is_amendment_shaped(plan_md: str, predecessor_bytes: int | None) -> bool:
    """True iff plan_md looks like a thin delta over a predecessor version:
    ALL THREE of (a) size < AMENDMENT_SIZE_RATIO x predecessor, (b) an
    amendment-marker phrase, (c) NO parseable GPU-hours declaration.
    Conjunctive by calibration (#2255 §2): each signal alone is
    false-positive-dominated on the 4,028-version corpus."""
    if not predecessor_bytes or predecessor_bytes <= 0:
        return False
    small = len(plan_md.encode("utf-8")) < AMENDMENT_SIZE_RATIO * predecessor_bytes
    return (small
            and AMENDMENT_MARKER_RE.search(plan_md) is not None
            and AMENDMENT_GPU_LINE_RE.search(plan_md) is None)
```

- **Threshold:** 0.4 (body's suggested "~40%"). Measured margin: the true amendments sit at 0.051 / 0.154; the nearest marker-bearing GPU-line-less non-hit (#375 v2-class old full plans) sits at ~1.0 ratio. The nearest small marker-bearing plans WITH a GPU line sit at 0.212–0.398 and are excluded by signal (c).
- **False-positive behavior (persist time):** measured 0 on the historical corpus. The residual forward-looking FP class — a genuinely small full re-plan that BOTH uses "unchanged from vX" changelog phrasing AND omits the GPU-hours declaration — is a plan that c5 would FAIL and the Step-2c gate would park ANYWAY; the refusal message tells the author exactly what to add. Recovery cost: one retry (add the declaration line, or pass `--allow-amendment`). Never silent.
- **False-negative behavior:** an amendment that restates its own GPU-hours line, or exceeds 40% of its predecessor, is NOT detected. Bounded consequence: with its own declaration the gate resolves a value (no park), and any section-check FAILs on such a hybrid remain visible `verify_plan` FAILs for the planner to fix — the pre-existing behavior for a defective plan, not a new silent path. Named residual, disclosed in the c60/refusal texts' vocabulary ("thin amendment").
- **Escape hatch:** `task.py new-plan-version <N> --file <p> --allow-amendment` / `new_plan_version(n, md, allow_amendment=True)`. The refusal message names it AND the two preferred remedies, in order: (1) compose a full plan (base + delta — "trivially scriptable"), (2) if the thin delta is deliberate (user-authorized), re-run with the flag and RESTATE the `Estimated GPU-hours (total):` line inside the amendment. On an allowed persist the CLI prints a loud stderr notice: `plans/plan.md now points at a PARTIAL document (amendment of v{J}); every subagent brief must hand v{K}.md AND v{J}.md together; verify_plan --issue composes them automatically.`
- **Predecessor definition:** the highest existing version below the new one (`max(existing_nums)` — gap-safe, matching the writer's own max+1 semantics), sized via `.stat().st_size`.
- **Purity:** the predicate reads only the new text + one `stat()` — no git, no network, no registry walk; runs inside the existing `_locked()` section. Detection runs on the INPUT text before `_align_plan_header_version` (alignment only rewrites header version digits; no signal interaction).
