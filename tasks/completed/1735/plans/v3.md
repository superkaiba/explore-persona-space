### 4.1 Composite arm predicate — the load-bearing behavioral change

**File:** `scripts/daily_drive_filings.py`, `find_closed_sibling_suspects` at L1099-1130.

**Before:**

```python
_CLOSED_SIBLING_BLOCKING_ARMS = ("target", "infra-target")
...
for h in hits:
    matched_arms = {m.split(":", 1)[0] for m in h.get("matched", [])}
    if matched_arms & set(_CLOSED_SIBLING_BLOCKING_ARMS):
        blocking.append(h)
    else:
        advisory.append(h)
```

**After (composite predicate):**

```python
# Path-family arms (the "same file the candidate wants to touch" signal).
_CLOSED_SIBLING_TARGET_ARMS = ("target", "infra-target")
# Title-family arms (informative-title overlap; already stopword-filtered
# upstream in _wf_fix_title_tokens via _WF_FIX_TITLE_STOPWORDS and here
# additionally by CLOSED_SIBLING_TITLE_STOPWORDS — see §4.2).
_CLOSED_SIBLING_TITLE_ARMS = ("title", "infra-title")
...
for h in hits:
    matched_arms = {m.split(":", 1)[0] for m in h.get("matched", [])}
    title_arms_informative = _closed_sibling_informative_title_arms(h)
    has_target = bool(matched_arms & set(_CLOSED_SIBLING_TARGET_ARMS))
    has_title = bool(title_arms_informative)
    if has_target and has_title:
        blocking.append(h)
    else:
        advisory.append(h)
```

**Helper `_closed_sibling_informative_title_arms(h)`:** parses the arm labels for `title:<tok1>,<tok2>,...` / `infra-title:<tok1>,...` prefixes, splits the comma-list, filters out tokens in `CLOSED_SIBLING_TITLE_STOPWORDS`, and returns the surviving arm names as a set (empty when all shared title tokens were stopwords). The arm labels themselves are the source of truth for which tokens overlapped — no re-tokenization of the task titles needed.

**Retained arm-label docstring.** Update the existing L240-246 comment to state the new rule verbatim: "A hit BLOCKS only when it matches BOTH a target arm (`target` / `infra-target`) AND a title arm (`title:*` / `infra-title:*`) whose shared informative tokens are not exclusively in the driver-scoped stoplist. Bare-target hits are ADVISORY because the shared-target signal, alone, is nearly universal on this repo's hot workflow files (task #1735: 21/24 measured false positives on the 2026-07-26 batch, dominated by bare-`target` + `target`+stopword-title matches on `SKILL.md`, `workflow_lint.py`, `.claude/agents/*.md`). Bare-title hits are ADVISORY (unchanged from #1711's original design). The composite rule INTENTIONALLY SACRIFICES the historical bare-target-only true-positive shape: fact-check on plan v1 (2026-07-27, cross-referencing the L240-246 arm comment) established that only 1 of the 3 named 'measured true positives' still fires as BLOCKING under composite — #1386 vs #1360 shares `retry`,`queue-full` informative title tokens; #1330 vs #1309 and #1652 vs #1329 share ZERO informative title tokens and downgrade to ADVISORY. This is the deliberate trade the fix makes: the pre-fix probe's 21/24 false-positive rate on hot workflow-surface files is a higher blast-radius cost than the two historical bare-target-only cases that will now surface as `CLOSED-SIBLING-ADVISORY` stderr prints instead of blocking. Regression coverage rests on (a) the #1350/#1329-shape pinned test in §5 (shares `workload-cmd`, not a stopword — a true positive whose title arm survives the composite rule), and (b) the `CLOSED-SIBLING-ADVISORY` stderr channel still surfaces bare-target hits for operator eyeballing exactly as before. See §6 Risk 'Composite too tight' — this is the acknowledged trade, not an unintended regression."

**Note on the `--retry-suspects` short-circuit.** UNCHANGED. `suspect_eyeballed` still short-circuits both probes; the composite predicate operates only inside `find_closed_sibling_suspects`, and the outer `_landed_fix_probes_outcome` flow is byte-identical.

### 4.4 Suppressed-count summary — legibility

**File:** `scripts/daily_drive_filings.py`, `main()` at L1845.

**Change:** after the outcome loop, before `return`, compute per-outcome counts from the results and:

1. Print ONE stderr line:
   ```
   SUMMARY dir=<dirpath> filed=X deduped=Y already-tracked=Z recovered=R skipped=K errors=E closed-sibling-suspects=S1 landed-fix-suspects=S2 — <suspect-hint>
   ```
   where `<suspect-hint>` is either `re-run with --retry-suspects to file suspects` (when S1+S2 > 0) or empty. NOTE: the two suspect counters are named separately because the `landed-fix-suspect` outcome string is emitted by BOTH the closed-sibling probe (#1711 — §4.1's scope) AND the sibling #1674 landed-fix-sha probe; conflating them in a single `suspects=S` counter would hide a legitimate #1674-only burst under the appearance of a closed-sibling regression, defeating §4.4's "impossible-to-miss" Goal. The `held=H` column is DROPPED (Statistics-critic MF2): `held` is a row FIELD on `filed` rows (`held_dispatch: true` set inside `process_item`), NOT a `process_item` return-value outcome — a `held=H` counter derived from the outcome set would always read 0.
2. If not `--dry-run`, append ONE ledger row via the existing `append_row` helper:
   ```json
   {"slug": null, "outcome": "daily-drive-summary", "counts": {"filed": X, "deduped": Y, "already-tracked": Z, "recovered": R, "skip": K, "error": E, "closed-sibling-suspects": S1, "landed-fix-suspects": S2}, "sliced": [args.start, args.end], "date": date}
   ```
   The `counts` schema keys are: the six `process_item` outcomes that never split (`filed`, `deduped`, `already-tracked`, `recovered`, `skip`, `error`) PLUS the two probe-source-discriminated suspect counters (`closed-sibling-suspects`, `landed-fix-suspects`) — these two REPLACE the single `landed-fix-suspect` outcome key from the outcome set. `slug: null` distinguishes this from item rows; the discriminator `outcome == "daily-drive-summary"` is unambiguous (existing item rows never carry that outcome value). Existing consumers of `filed.jsonl` filter on `outcome in {...item outcomes...}` and will ignore this row unless updated; grep-based consumers can find it via `jq 'select(.outcome=="daily-drive-summary")'`.

**Counting shape.** Change `main()`'s loop to:

```python
outcome_counts: dict[str, int] = {}
for item in sliced:
    outcome = process_item(...)
    # Suspect outcomes are discriminated by the just-written ledger row's
    # suspects[0]["kind"] field: 'closed-sibling' (from _closed_sibling_outcome,
    # §4.3 of #1711) or 'commit-subject' (from _landed_fix_suspect_outcome, #1674).
    # Both write outcome='landed-fix-suspect' to the ledger; the KIND field is
    # the probe-source discriminator the summary counter reads.
    key = _summary_key_for_outcome(outcome, dirpath, item["slug"])
    outcome_counts[key] = outcome_counts.get(key, 0) + 1
    if outcome == "error":
        any_error = True
# Terminal summary — always emitted, dry-run too (ledger write skipped on --dry-run).
_emit_daily_drive_summary(dirpath, outcome_counts, args, date, dry_run=args.dry_run)
return 1 if any_error else 0
```

`_summary_key_for_outcome` returns `outcome` verbatim EXCEPT when `outcome == "landed-fix-suspect"`, in which case it reads back the just-written ledger row's `suspects[0]["kind"]` and returns `"closed-sibling-suspects"` (kind `"closed-sibling"`) or `"landed-fix-suspects"` (kind `"commit-subject"`). Read-back cost is O(1) — read the last row via `read_last_row` (already a driver helper); a corrupt/missing suspects field fails soft to the aggregate key `"landed-fix-suspects-unknown-kind"` and prints an implementer stderr WARN (an unclassified suspect is still a suspect for `--retry-suspects` purposes; the operator still sees it in the SUMMARY line). Alternative implementation (simpler): thread the discriminator through `process_item`'s return value as `"landed-fix-suspect:closed-sibling"` / `"landed-fix-suspect:commit-subject"` — the summary counter splits on `:`. Implementer picks the shape at coding time; the ledger row + SUMMARY line schema above is the contract.

**Dry-run behavior.** Print the summary; do NOT append the ledger row (dry-run is read-only by construction). The printed stderr line is what a nightly-batch operator reads either way.
