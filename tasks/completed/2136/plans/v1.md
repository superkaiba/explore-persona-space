# Plan — #2136 stale prior-round PASS in the durable-verdict presence check

`kind: infra` · workflow-fix · `workflow_fix_target: src/explore_persona_space/task_workflow.py`

## 1. Goal

`ensemble_verdicts_present` must never report a PRIOR round's verdict as satisfying the
CURRENT round's durable-verdict-first check (/issue Step 5b items 1 + 3). Concretely: the
#1336 incident shape — a round-3 `epm:code-review` PASS answering a round-4 query two days
later — must return `present: False`, while every legitimate round-N match (including a
round-N verdict posted by a KILLED earlier session) keeps returning `present: True`.

## 2. Problem statement (empirically established, not inherited from the body)

The task body attributes the incident to a missing round token in the marker sentinel. That
attribution is STALE: #1149 (landed 2026-07-30, before the 2026-08-04 incident) made the
note-head sentinel `<!-- <kind> v<n> -->` AUTHORITATIVE over the top-level `version` field.
Direct probe of current `main`:

| probe | marker shape | query | result |
|---|---|---|---|
| shape1 | sentinel-LESS, `version: 4`, genuinely round 3 | round 4 | **`present: True, verdict: PASS, ts: 2026-08-02`** |
| shape2 | sentinel `v3`, `version: 4` | round 4 | `present: False` (correct) |
| shape3 | sentinel `v1`, `version: 1` | round 4 | `present: False` (correct) |

So the live defect is exclusively the **version-field fallback** — the terminal
`elif event.get("version") != round_n: return False` branch of `_ensemble_event_matches`
(`task_workflow.py:2193-2226`). Marker versions auto-derive as `max+1` per kind while review
rounds are counted independently, so `version >= round` holds routinely and a prior round's
version collides with a LATER round number. shape1 IS the incident.

The helper docstring already discloses the symmetric false-ABSENT residual; it does not
disclose this false-PRESENT one.

## 3. Fix-branch selection (the body offers two; corpus evidence forecloses one)

Counted over every `tasks/*/*/events.jsonl`:

| kind | total | sentinel-less | sentinel != version |
|---|---|---|---|
| `epm:code-review` | 3289 | 283 | 190 |
| `epm:code-review-codex` | 1234 | 69 | 351 |
| `epm:interp-critique` | 777 | 155 | 152 |
| `epm:interp-critique-codex` | 338 | 22 | 44 |
| `epm:clean-result-critique` | 864 | **760 (88%)** | 35 |
| `epm:clean-result-critique-codex` | 399 | 51 | 77 |
| `epm:review-reconcile` | 751 | 97 | 262 |

633 sentinel-less markers sit at `version > 1` across 233 task/kind pairs — every one of them
fallback-matchable. **Branch A (add a round token to sentinels / drop the version fallback) is
rejected:** the `epm:clean-result-critique` site is 88% sentinel-less, so removing the fallback
converts a rare false-PRESENT into a mass false-ABSENT across the historical corpus and the
still-sentinel-less sites. **Branch B (freshness anchor) is adopted** — the body's
`since_ts` option.

**Load-bearing design constraint the anchor must respect:** the anchor gates ONLY the
version-fallback branch, NEVER a sentinel-bearing round-exact match. Step 5b's entire purpose
is to REUSE a legitimate round-N verdict posted by a session that was later killed — such a
verdict necessarily predates the current dispatch. Time-gating sentinel matches would break
durable-verdict-first itself, converting the fix into a different regression.

## 4. Change set

### 4.1 `src/explore_persona_space/task_workflow.py`

(a) **`ensemble_verdicts_present`** — add keyword-only `since_ts: str | None = None`, threaded
through to `_ensemble_event_matches`. Default `None` = today's behavior exactly (no silent
change for any caller that does not opt in).

(b) **`_ensemble_event_matches`** — in the version-fallback branch ONLY (non-reconcile kind,
no head sentinel), when `since_ts` is not `None`, additionally require the event to be
strictly NEWER than the anchor: `_event_epoch(event["ts"]) > _event_epoch(since_ts)`. An
unparseable/absent event `ts`, or an unparseable `since_ts`, SUPPRESSES the fallback match
(fail toward the rule's item-2 output-file probe — the same fail-safe direction the reconcile
role-scoping already takes). Sentinel-bearing and reconcile paths are untouched.

(c) **New helper `review_round_anchor_ts(events, *, opening_kinds=...) -> str | None`** — the
ts of the chronologically LAST implementer marker (`epm:experiment-implementation`,
`epm:results`; workflow.yaml:1587/1854), else `None`. Semantics: Step 5b is always called for
the CURRENT (newest) review round, and the newest implementer marker is by definition that
round's opener, so a verdict predating it cannot be this round's verdict. Requires no sentinel
cooperation from the implementer. `None` (no implementer marker yet) degrades to today's
ungated behavior — never worse.

(d) **Docstrings** — document the closed false-PRESENT residual, the anchor's scope (version
fallback only) and the reason sentinel matches are deliberately NOT time-gated.

### 4.2 Consumers — deliberate no-change, documented

Both in-repo internal callers keep `since_ts=None`, with a one-line docstring note stating why:

- `_latest_site_pair` (`:3168`) DERIVES `round_n` from the last pair event's own `version` when
  that event is sentinel-less, so the subsequent query matching that same event via the version
  fallback is correct BY CONSTRUCTION. An anchor there would suppress the very event the round
  number came from.
- `_reconcile_satisfied` (`:3210`) queries `epm:review-reconcile`, which never version-matches
  at all — the anchor is structurally inert.

**Documented residual (deliberately out of scope):** when `_latest_site_pair`'s last pair event
is sentinel-less with a drifted version, the derived `round_n` is itself wrong, so the #1170
watcher disagree-pass can pair a round-3 Claude verdict with a round-4 Codex verdict under one
label. That is a round-DERIVATION defect, not an anchoring one; the pass is escalate-only
(one deduped push, no state mutation). Recorded here rather than fixed, to keep this task
single-variable.
