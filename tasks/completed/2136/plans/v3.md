## 0.0 TL;DR

`ensemble_verdicts_present` can answer the CURRENT review round's durable-verdict check with a
PRIOR round's verdict, because its version-field fallback matches a sentinel-less marker whose
auto-bumped `version` happens to equal a later round number. Fix: an opt-in freshness anchor
(`since_ts`) that gates the version-fallback branch ONLY — never a sentinel-bearing round-exact
match — under TWO conjunctive conditions: the candidate must postdate the round's opener AND be
the newest same-kind marker after it. Each call site passes its own opener kinds. Measured
coverage of the exposed sentinel-less corpus: ~96% at the code-review and clean-result-critique
sites, with a quantified, documented residual (§4.6).

**What would change my mind:** if the version-field fallback were unreachable in practice the
fix would be unnecessary. Probe shape1 (§2) falsifies that on current `main`, and 633 fleet
markers sit fallback-matchable. Independently reproduced by the v2 critic. Conversely, if
time-gating sentinel-BEARING matches were also needed, §3's design would be wrong — but that
would break Step 5b's own killed-session-reuse purpose, so the gate stays fallback-only.

**Kill criteria (halt and report rather than push through):**

- Any of the 16 pre-existing `tests/test_ensemble_verdicts_present.py` tests goes red for a
  genuine semantic conflict with the anchor (not merely needing the new kwarg) — halt: the
  fallback carries load-bearing semantics this plan misread.
- Condition (ii) of §4.1(c) turns out to suppress a legitimate same-round re-spawn match
  (existing `test_respawn_duplicate_latest_wins` shape) — halt rather than weaken the existing
  latest-wins contract.
- The change would require touching `_latest_site_pair`'s round DERIVATION to be coherent —
  halt: that is a second variable, deferred by §4.2/§8.

## 1. Goal

`ensemble_verdicts_present` must not report a PRIOR round's verdict as satisfying the CURRENT
round's durable-verdict-first check (/issue Step 5b items 1 + 3, and the same rule at Steps 9a /
9a-bis / 9b-VC). The #1336 shape — a round-3 `epm:code-review` PASS answering a round-4 query
two days later — must return `present: False`, while every legitimate round-N match keeps
returning `present: True`, INCLUDING a round-N verdict posted by a session that was later
killed (the reuse case the rule exists for).

Scope honesty: a sentinel-less marker carries no round information whatsoever, so time is the
only available evidence and the fix's resolution is bounded by the resolution of round-opening
evidence on the log. §4.6 quantifies exactly what is closed and what remains. The head sentinel
stays the only COMPLETE protection — which is why `code-reviewer.md:52` mandates it.

The body attributes the incident to a missing round token in the marker sentinel. That

| probe | marker shape | query | result |
|---|---|---|---|

dispatch. Time-gating sentinel matches would break durable-verdict-first itself. (Verified

## 4. Change set

### 4.1 `src/explore_persona_space/task_workflow.py`

(a) **`ensemble_verdicts_present`** — add keyword-only `since_ts: str | None = None`. Default
`None` reproduces today's behavior exactly for every existing caller.

(b) **`_ensemble_event_matches` returns the match MODE, not a bool** — `"sentinel"`,
`"version"`, `"round-field"`, or `None`. The anchor conditions must apply to version-fallback
matches only, so the caller has to know how a match was obtained. Pure refactor of a private
helper; no external contract changes.

(c) **Two conjunctive anchor conditions, applied in `ensemble_verdicts_present` (which holds
the full events list), to `"version"`-mode matches only, and only when `since_ts` is not
`None`:**

- **(i) postdates the opener** — `_event_epoch(event["ts"]) > _event_epoch(since_ts)`. An
  unparseable/absent event `ts`, or an unparseable `since_ts`, SUPPRESSES the match (fail
  toward the rule's item-2 output-file probe — the same fail-safe direction the existing
  reconcile role-scoping takes).
- **(ii) is the newest same-kind marker after the opener** — no other event of the SAME kind
  with `ts > since_ts` is newer than the candidate. Rationale: every call site queries the
  round currently in progress, so that round's verdict (if posted) is the newest same-kind
  marker after the round's opener; an older marker inside the same opener window belongs to an
  earlier round. This is site-agnostic and closes the shared-opener sub-shape that condition
  (i) alone cannot (§4.6) — 23.8% of the exposed `epm:clean-result-critique` corpus.
  Same-kind scoping keeps Claude and Codex twins independent. It does NOT disturb the existing
  latest-wins re-spawn contract: with two same-round markers the newer one still wins and the
  older is suppressed, which is the same result latest-wins already produced.

(d) **New helper `review_round_anchor_ts(events, *, opening_kinds) -> str | None`** — the ts of
the chronologically LAST event whose kind is in `opening_kinds`, else `None`. `opening_kinds`
is a REQUIRED keyword argument with no default: each call site names its own round opener, and
a wrong default would silently produce an inert or misleading anchor (this is the v2 blocker).
A docstring line records why the code-review site passes BOTH implementer kinds — `kind: infra`
tasks open a review round with `epm:results` while experiment tasks use
`epm:experiment-implementation` (workflow.yaml:1587/1854). `None` (no opener on the log)
degrades to today's ungated behavior — never worse.

(e) **Docstrings** — document the closed false-PRESENT residual, the anchor's fallback-only
scope, why sentinel matches are deliberately not time-gated, and the §4.6 residual.

### 4.2 Consumers — deliberate no-change, documented (both arguments code-verified by the v2 critic)

- `_latest_site_pair` (`:3168`) DERIVES `round_n` from the last pair event's own sentinel-else-
  `version`, so the subsequent query matching that same event via the fallback is correct BY
  CONSTRUCTION. An anchor would suppress the very event the round number came from.
- `_reconcile_satisfied` (`:3210`) queries `epm:review-reconcile`, whose matcher branch
  (`:2209-2216`) never reaches the version fallback — the anchor is structurally inert.

**Documented residual, deliberately out of scope:** when `_latest_site_pair`'s last pair event
is sentinel-less with a drifted version, the DERIVED `round_n` is itself wrong, so the #1170
watcher disagree pass can pair a round-3 Claude verdict with a round-4 Codex verdict under one
label. That is a round-DERIVATION defect, not an anchoring one, in an escalate-only pass (one
deduped push, no state mutation). Recorded rather than fixed, to keep this task
single-variable.
