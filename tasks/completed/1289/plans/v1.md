The failure mode being fixed is the other direction: local `main` OLDER than the cut point pulls the origin-side commits into the "touched" set as foreign files.

**(a) New module constants + resolver** (placed after `SLOW_TESTS`, before `recommended_timeout_s`):

```python
# --- Diff-base resolution (#1289). -------------------------------------------
# The always-shared repo-root `main` can lag origin/main (unpushed/conflicted
# root state): on 2026-07-12 three concurrent sessions got foreign-file
# pollution from `--base main` (#1280: 202,578-byte diff vs 11,637 against
# origin/main; #1281: a 41-test-file gate). Default the base to FETCHED
# origin/main: branches are cut from fetched origin/main (new_worktree.sh,
# #1214), and merge-base(origin/main, HEAD) == the cut point — advancing
# origin/main never moves it, so the three-dot selection is stable.
DEFAULT_BASE = "origin/main"
# Bounded fetch — SKILL.md Step 10d lint-gate precedent
# (`timeout --kill-after=30s 120s git fetch origin main --quiet || true`):
FETCH_TIMEOUT_S = 120


def resolve_base(base: str, work_root: Path, *, fetch: bool = True) -> str:
    """Resolve the diff base ref (#1289) — never blocks, never raises.

    A *base* without an ``origin/`` prefix is returned VERBATIM with no git
    calls (the explicit local-ref escape hatch; ``--base main`` == pre-#1289
    behavior). A remote-tracking *base*: (1) best-effort bounded
    ``git fetch origin <branch> --quiet`` (failure / timeout / offline →
    stderr NOTE, degrade to the last-fetched ref — the Guard-1 precedent;
    a stale origin/main still names the branch cut point, see module
    docstring); (2) ``git rev-parse --verify --quiet <base>`` — resolves →
    use *base*; does NOT resolve (offline clone with no remote-tracking ref,
    checkout without an ``origin`` remote, non-git ``--repo-root`` fixture
    tree) → loud stderr NOTE + fall back to the local ``<branch>`` (pre-#1289
    behavior; fail toward current behavior).
    """
    if not base.startswith("origin/"):
        return base
    branch = base.split("/", 1)[1]
    if fetch:
        try:
            subprocess.run(
                ["git", "fetch", "origin", branch, "--quiet"],
                cwd=str(work_root),
                capture_output=True,
                text=True,
                timeout=FETCH_TIMEOUT_S,
                check=True,
            )
        except (subprocess.CalledProcessError, subprocess.TimeoutExpired, OSError) as exc:
            print(
                f"select_step9c_tests: NOTE — git fetch origin {branch} failed ({exc}); "
                f"using last-fetched {base} if it resolves",
                file=sys.stderr,
            )
    probe = subprocess.run(
        ["git", "rev-parse", "--verify", "--quiet", base],
        cwd=str(work_root),
        capture_output=True,
        text=True,
    )
    if probe.returncode == 0:
        return base
    print(
        f"select_step9c_tests: NOTE — {base} does not resolve in {work_root}; "
        f"falling back to local '{branch}' (offline clone / no origin remote — "
        "pre-#1289 behavior)",
        file=sys.stderr,
    )
    return branch
```

(`OSError` on the probe cannot escape: `subprocess.run` without `check` only raises `OSError` if git itself is missing — acceptable to let that crash loud, same as every other git call in the file. If the implementer prefers total symmetry, wrap the probe in the same try; either is fine — deviation-allowed.)

## 11. Decision Rationale

No literature search — repo-internal infra; every Source below is an incident record or an existing repo precedent (stated explicitly per the brief).

1. **Default ref = `origin/main` (in-script default, not recipe-only).**
   What: `DEFAULT_BASE = "origin/main"` in the selector; SKILL.md recipe drops `--base main`.
   Why: every caller benefits (SKILL.md recipe, compare, ad-hoc hand runs — #1282 had to hand-override); a recipe-only fix leaves the script default a trap.
   Source: task #1289 body sketch (verbatim); #1280 Guard-1 sibling fix; #1214 (`new_worktree.sh` cuts branches from fetched `origin/main`, making `merge-base(origin/main, HEAD)` the cut point).
   Alternatives: `default=None` sentinel with resolution-on-None (equivalent; rejected — the sketch's literal default is simpler and self-documenting in `--help`); SKILL.md-recipe-only change (rejected — doesn't cover compare or hand runs).
2. **Fetch inside the script, bounded at 120 s, with `--no-fetch` escape.**
   What: `git fetch origin main --quiet` via subprocess `timeout=FETCH_TIMEOUT_S` before the ref probe.
   Why: freshness at the point of use; every caller inherits it; hermetic tests and offline runs opt out.
   Source: SKILL.md Step 10d lint-gate precedent (`timeout --kill-after=30s 120s git fetch origin main --quiet || true`, line ~9213); brief's stated preference for in-script fetch.
   Alternatives: fetch in the SKILL.md recipe (rejected — compare + hand runs wouldn't inherit); no fetch at all, rely on ambient freshness (rejected — the incident's root sat unfetched/conflicted for 33+ min).
3. **Fallback semantics: fetch-failure → last-fetched `origin/main`; unresolvable ref → local `main`; never block.**
   What: two-stage degrade, both loud on stderr.
   Why: a stale `origin/main` still names the branch cut point (merge-base invariance) and strictly dominates a lagging local `main`; only when the remote-tracking ref does not EXIST does local `main` become the best available base. This refines the task sketch's "fall back to local main when offline" — offline-with-a-stale-ref keeps `origin/main`.
   Source: SKILL.md Guard 1 (#1280) lines 8793–8795 — exactly this degrade ("stripping against last-fetched origin/main"); task body constraint ("fail toward the current behavior (local main), never block") — honored at the unresolvable-ref stage, the only stage where `origin/main` is unusable. Flagged as a deliberate sketch refinement in § Deviations.
4. **`step9c_baseline.py compare` default `None` → resolve via the worktree selector with `fetch=False`.**
   What: §4.2 wiring with `getattr` fallback.
   Why: compare must classify against the SAME base the selection used (#1022's same-mapping-logic requirement); no second fetch — merge-base is invariant under `origin/main` advancing, and compare runs minutes after the selection; `getattr` guards the pre-fix-worktree transition.
   Source: `step9c_baseline.py` docstring lines 228–230 ("same semantics as select_step9c_tests…"); #1022 plan §3.3/§3.4.
   Alternatives: hardcode `default="origin/main"` in compare (rejected — would bypass resolution/fallback and crash on no-remote checkouts); leave compare at `"main"` (rejected — selection/compare base skew reintroduces foreign-file misclassification).
5. **Prose alignment set (§4.5) vs leave-alone set (§4.6).**
   What: swap behavior-bearing recipe literals (sizing gates, classify commands, excerpt builds, merge-base probes); leave strip-probes, subclass names, incident narration, memories.
   Why: recipes drive future behavior; strip probes on local `main` fail only in the conservative direction (finding retained); the subclass name is a pinned public enum.
   Source: grep triage in this plan (clarifier scope sweep + my `(^|[^/])\bmain\.\.\.?HEAD` re-grep); `tests/test_ensemble_review_cap.py:273` (name pin).
6. **Durability pin as a `WORKFLOW_INVARIANT` member (36→37).**
   What: §4.4 new pin file + tuple membership + case-6 count bump.
   Source: the #1242/#1268 precedent (SKILL.md content pins live in the tuple because SKILL.md diffs gate ONLY via the tuple); planner spec § Workflow-prose durability pin.
