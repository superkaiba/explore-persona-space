## 1. Goal / requirement

A worktree-scoped destructive git op composed via the canonical VAR+cd idioms passes the guard's
worktree allowance, without weakening any protection for actual repo-root mutations.

**Clarifier ground truth (live probes, `/tmp/issue-1861-guard-probe.sh`, 2026-07-31):** the #1058
latch ALREADY passes `WT=<worktree-literal>; cd "$WT" && <gated git op>` (and the
`WT="$REPO_ROOT/.claude/worktrees/..."` quoted-RHS form) — the task body's premise is partially
stale. The REAL residual gaps, confirmed by probe + 13 deny-sidecar firings (2026-07-22 → 07-31,
5 post-filing):

- **Gap A (exit-guarded cd):** `cd <worktree> || exit 1` / `cd <worktree> || { echo FATAL >&2; exit 1; }`
  followed by NL/`;`-separated gated ops BLOCKS today, although it is PROVABLY scoped — if the
  shell continues past that line, the cwd IS the worktree (cd failure exits). This is the exact
  hard-guard shape `.claude/skills/issue/SKILL.md` itself prescribes (Step 9c 1b/1c fences,
  Step 10d), and ≥2 recent firings (#1855 2026-07-31, #1837 2026-07-30) are this shape.
- **Gap B (variable name):** the assignment latch is hardcoded to the name `WT`; the SKILL.md
  Step 4a conventional name `WORKTREE` (probe 10) — or any other name — blocks.
- **Gap C (deny-text guidance):** the deny text names only the `git -C <worktree>` recompose; it
  does not name the two compliant compose shapes (the `&&`-chain and the exit-guard), so sessions
  trial-and-error (~6 min/episode per the #1928 sibling body).
- **Hardening D (required for A's soundness, fail-closed direction):** today the cd-latch arms
  regardless of the cd clause's PRECEDING separator. An OR- or PIPE-preceded cd is NOT provably
  executed in the parent shell (`a || cd X && <op>` runs `<op>` when `a` succeeded and cd never
  ran; `a | cd X` runs cd in a pipeline subshell), and a LATER non-worktree cd does not clear an
  armed latch (`cd <wt> && cd <elsewhere> && <op>` stays scoped today). Both are existing
  fail-open holes that become worse once sticky scope (A) exists — close them in the same diff.

**Acceptance criteria:**
1. Exit-guarded worktree cd shapes (bare `|| exit N` and the brace-group `|| { ...; exit N; }`
   form, literal path AND armed `$VAR` forms) ALLOW gated git ops in later NL/`;`-separated
   clauses of the same command — where "later" means clauses AFTER the recognized terminator
   (the OR-tail's own clauses are NEVER sticky-scoped; they execute exactly when the cd FAILED,
   i.e. at the repo root — critic Must-Fix 1).
2. A non-`WT` variable name (e.g. `WORKTREE`) arms the assignment latch under the same
   proof obligations (clause-initial bare assignment, worktree-literal RHS anchored to
   end-of-clause, preceding separator ∈ {START, SEQ, NL}); same-name reassignment disarms.
3. Every dangerous shape that blocks today STILL blocks: unguarded NL/`;`-separated cd
   compounds (cd can fail → cwd stays at root), bare root ops, guard tails that do not exit
   (`|| echo oops`), a group with no exit, AND-guarded exits inside the group
   (`{ foo && exit 1; }`), a gated git op INSIDE the guard group (critic Must-Fix 1),
   post-guard non-worktree cd followed by gated ops, `|| return 1` tails (critic Must-Fix 3 —
   at top level `return` prints an error and the shell CONTINUES at the root),
   terminators followed by PIPE or BG separators (`|| exit 1 | <op>` runs exit in a pipeline
   subshell; `|| exit 1 & <op>` backgrounds the whole and-or list — critic Must-Fix 2),
   and paren-prefixed subshell cds after a sticky grant (`(cd <root> && <op>)` — critic
   Must-Fix 4).
4. NEW blocks (hardening D): OR-preceded and PIPE-preceded cd clauses no longer arm any latch;
   a non-worktree/non-tmp `cd`/`pushd`/`popd` clause — including paren/whitespace-prefixed
   spellings — clears BOTH the plain latch and the sticky scope for later clauses.
5. The #1554 Arm B bare-local-main merge fence applies unchanged under sticky scope (a sticky
   worktree-scoped `git merge main` still blocks).
6. Deny text names the three compliant recomposes: `git -C "$WT" <op>`, the `&&`-chain
   (`WT=<path>; cd "$WT" && <op>`), and the exit-guard shape (`cd "$WT" || exit 1` then ops).
7. Full existing pin-test suite for the guard passes (no regression among the 102 existing
   tests); Step 9c gate + Step 10d lint/TG legs pass.

## 2. Method delta (what differs from prior related work)

Prior lineage: #1058 introduced the `WT=` assignment + `cd "$WT"` latch (AND-propagation only);
#1554 added the `scoped_wt` bit + bare-main merge fences; #1443 anchored the latch greps. This
plan EXTENDS the latch state machine with (i) a **sticky scope** granted only on a provably
exit-guarded cd and only for clauses PAST the guard tail, (ii) **name-generalized** assignment
tracking (bash associative array keyed by variable name, replacing the single `wt_bound` flag),
(iii) **arming-separator restriction** (exclude OR/PIPE) + **cd-clause scope invalidation**, and
(iv) one deny-text guidance line. No existing allowance is narrowed except the two fail-open
holes in D (a strict tightening).

### 3.1 `scripts/guard_repo_root_branch.sh` (driver loop, ~L1873-2035)

- **State:** add `sticky=0 sticky_wt=0 sticky_arm_at=-1 sticky_pending_wt=0` beside
  `scoped=0 scoped_wt=0`; replace `wt_bound=0` with `declare -A _wt_names=()`.
- **Deferred sticky activation (critic Must-Fix 1):** the exit-guard recognizer records the
  INDEX of the terminator's closing clause (the `exit` clause for Case A; the `}` clause for
  Case B) in `sticky_arm_at` instead of setting sticky immediately. At the TOP of each loop
  iteration (before the reset branch): if `sticky_arm_at >= 0 && _idx > sticky_arm_at`, set
  `sticky=1; sticky_wt=$sticky_pending_wt; sticky_arm_at=-1`. Tail/group-internal clauses
  therefore keep today's UNSCOPED classification — a gated op inside the guard group still
  blocks (it executes on the cd-failure path, at the root).
- **Reset branch** (`if [ "$sep" != AND ]`): restore from sticky instead of clearing —
  `scoped=$sticky; scoped_wt=$sticky_wt`.
- **Scope invalidation (critic Must-Fix 4):** before the latch arms, any clause whose command
  word — after tolerating a leading run of `(` and whitespace, and optional
  `builtin `/`command ` prefixes — is `cd`/`pushd`/`popd` clears `sticky`, `sticky_wt`,
  `sticky_arm_at`, `scoped`, `scoped_wt`; the worktree/tmp/`$VAR` latch arms below then re-arm

- **Arming-separator restriction:** the literal-worktree, `/tmp/`, and `$VAR` cd-latch arms fire

  after a WORKTREE cd-latch arm (literal or `$VAR`; NOT the `/tmp/` arm — §6 assumptions) when
  `nextsep == OR`. Returns the terminator's clause index on success (consumed into
  `sticky_arm_at` per the deferred-activation bullet):
  - Case A: the next clause matches `^exit( +[0-9]+)?[[:space:]]*$` (no `return` — critic

## 4. Design notes / proof obligations

The guard's core invariant: a clause is scoped ONLY when bash semantics PROVE it executes with
cwd inside a worktree/tmp. Existing proof: `cd X && <op>` (AND short-circuit). New proof: after
`cd X || <provably-exiting tail>`, every clause PAST the tail is scoped — either cd succeeded
(cwd = X) or the shell exited before reaching them. The tail's OWN clauses execute exactly when
cd FAILED (cwd = root) and are never scoped (Must-Fix 1). The tail proof requires (a) the cd
clause itself provably executed in the parent shell (sep ∉ {OR, PIPE} — hardening D), (b) the
OR-tail terminates: a bare `exit`, or a brace group whose final clause before `}` is an
unconditionally-reached (SEQ/NL-preceded) `exit`, and (c) the terminator is not itself defused
by a following PIPE/BG separator (Must-Fix 2). `return` is rejected (Must-Fix 3). Sticky scope
is invalidated by any subsequent cwd-changing clause, including paren-prefixed subshell
spellings (Must-Fix 4) — invalidation is deliberately broader than arming (fail-closed).
