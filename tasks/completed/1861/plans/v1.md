## 1. Goal / requirement

A worktree-scoped destructive git op composed via the canonical VAR+cd idioms passes the guard's
worktree allowance, without weakening any protection for actual repo-root mutations.

**Clarifier ground truth (live probes, `/tmp/issue-1861-guard-probe.sh`, 2026-07-31):** the #1058
latch ALREADY passes `WT=<worktree-literal>; cd "$WT" && <gated git op>` (and the
`WT="$REPO_ROOT/.claude/worktrees/..."` quoted-RHS form) — the task body's premise is partially
stale. The REAL residual gaps, confirmed by probe + 13 deny-sidecar firings (2026-07-22 → 07-31,
5 post-filing):

- **Gap A (exit-guarded cd):** `cd <worktree> || exit 1` / `cd <worktree> || { echo FATAL >&2; exit 1; }`
  followed by NL/`;`-separated gated ops BLOCKS today, although it is PROVABLY scoped — if the
  shell continues past that line, the cwd IS the worktree (cd failure exits). This is the exact
  hard-guard shape `.claude/skills/issue/SKILL.md` itself prescribes (Step 9c 1b/1c fences,
  Step 10d), and ≥2 recent firings (#1855 2026-07-31, #1837 2026-07-30) are this shape.
- **Gap B (variable name):** the assignment latch is hardcoded to the name `WT`; the SKILL.md
  Step 4a conventional name `WORKTREE` (probe 10) — or any other name — blocks.
- **Gap C (deny-text guidance):** the deny text names only the `git -C <worktree>` recompose; it
  does not name the two compliant compose shapes (the `&&`-chain and the exit-guard), so sessions
  trial-and-error (~6 min/episode per the #1928 sibling body).
- **Hardening D (required for A's soundness, fail-closed direction):** today the cd-latch arms
  regardless of the cd clause's PRECEDING separator. An OR- or PIPE-preceded cd is NOT provably
  executed in the parent shell (`a || cd X && <op>` runs `<op>` when `a` succeeded and cd never
  ran; `a | cd X` runs cd in a pipeline subshell), and a LATER non-worktree cd does not clear an
  armed latch (`cd <wt> && cd <elsewhere> && <op>` stays scoped today). Both are existing
  fail-open holes that become worse once sticky scope (A) exists — close them in the same diff.

**Acceptance criteria:**
1. Exit-guarded worktree cd shapes (bare `|| exit N` and the brace-group `|| { ...; exit N; }`
   form, literal path AND armed `$VAR` forms) ALLOW gated git ops in later NL/`;`-separated
   clauses of the same command.
2. A non-`WT` variable name (e.g. `WORKTREE`) arms the assignment latch under the same
   proof obligations (clause-initial bare assignment, worktree-literal RHS anchored to
   end-of-clause, preceding separator ∈ {START, SEQ, NL}); same-name reassignment disarms.
3. Every dangerous shape that blocks today STILL blocks: unguarded NL/`;`-separated cd
   compounds (cd can fail → cwd stays at root), bare root ops, guard tails that do not exit
   (`|| echo oops`), a group with no exit, AND-guarded exits inside the group
   (`{ foo && exit 1; }`), post-guard non-worktree cd followed by gated ops.
4. NEW blocks (hardening D): OR-preceded and PIPE-preceded cd clauses no longer arm any latch;
   a non-worktree/non-tmp `cd`/`pushd`/`popd` clause clears BOTH the plain latch and the sticky
   scope for later clauses.
5. The #1554 Arm B bare-local-main merge fence applies unchanged under sticky scope (a sticky
   worktree-scoped `git merge main` still blocks).
6. Deny text names the three compliant recomposes: `git -C "$WT" <op>`, the `&&`-chain
   (`WT=<path>; cd "$WT" && <op>`), and the exit-guard shape (`cd "$WT" || exit 1` then ops).
7. Full existing pin-test suite for the guard passes (no regression among the 102 existing
   tests); Step 9c gate + Step 10d lint/TG legs pass.

## 2. Method delta (what differs from prior related work)

Prior lineage: #1058 introduced the `WT=` assignment + `cd "$WT"` latch (AND-propagation only);
#1554 added the `scoped_wt` bit + bare-main merge fences; #1443 anchored the latch greps. This
plan EXTENDS the latch state machine with (i) a **sticky scope** granted only on a provably
exit-guarded cd, (ii) **name-generalized** assignment tracking (bash associative array keyed by
variable name, replacing the single `wt_bound` flag), (iii) **arming-separator restriction**
(exclude OR/PIPE) + **cd-clause scope invalidation**, and (iv) one deny-text guidance line. No
existing allowance is narrowed except the two fail-open holes in D (a strict tightening).

  `$NAME`, `${NAME}`, `$NAME/...`, `${NAME}/...` only, `..` still refused — and latches iff
  `_wt_names[name]` is bound.

  any worktree cd-latch arm (literal or `$VAR`; NOT the `/tmp/` arm — see §6 assumptions) when

## 4. Design notes / proof obligations

The guard's core invariant: a clause is scoped ONLY when bash semantics PROVE it executes with
cwd inside a worktree/tmp. Existing proof: `cd X && <op>` (AND short-circuit). New proof: after
`cd X || <provably-exiting tail>`, EVERY later clause in the command is scoped — either cd
succeeded (cwd = X) or the shell exited before reaching them. The tail proof requires (a) the cd
clause itself provably executed in the parent shell (sep ∉ {OR, PIPE} — hardening D), and (b) the
OR-tail terminates: a bare `exit`/`return`, or a brace group whose final clause before `}` is an
unconditionally-reached (SEQ/NL-preceded) `exit`/`return`. Sticky scope is invalidated by any
subsequent cwd-changing clause (re-armed only by a compliant worktree cd). `return` is accepted
alongside `exit`: inside a sourced context/function it aborts the enclosing scope before later
clauses run; at top level bash treats a failed `return` as a shell-continuing no-op ONLY outside
functions — to stay fail-closed we accept `return` solely because later clauses in the SAME
compound never execute when the function/source frame aborts; the implementer verifies this live
(bash 5.1.16) and DROPS `return` from the regex if top-level behavior is shell-continuing
(deviation allowed, §9).
