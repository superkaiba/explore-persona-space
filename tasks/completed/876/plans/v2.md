### 4.1 Core change — `scripts/issue658_fit_predictors.py`

1. **Delete** `DEVICE = "cpu"` at line 143; rewrite the lines-140–142 comment to describe the resolved default (env override, else auto; `main()` re-resolves with CLI precedence; DV device-invariant — keep that clause).
2. **Add, immediately after `_resolve_device` (after line 179):**

```python
def _requested_device(cli_value: str | None) -> str:
    """Device request with precedence: explicit CLI > EPM_FIT_DEVICE env > 'auto'."""
    if cli_value is not None:
        return cli_value
    return os.environ.get("EPM_FIT_DEVICE", "auto")


def _default_device() -> str:
    """Module-scope default importers inherit: EPM_FIT_DEVICE if set, else auto
    (cuda when available). Import-safe: torch.cuda.is_available() does not
    initialize a CUDA context, and resolution logs nothing unless
    EPM_FIT_DEVICE=cuda is set on a CUDA-less host (the _resolve_device WARNING).
    """
    return _resolve_device(_requested_device(None))


DEVICE = _default_device()
```

   No module-scope read of `DEVICE` exists between lines 143 and 179 (verified: lines 231/246 are docstrings; 305/639 are inside functions), so moving the assignment below the def is safe.
3. **`main()` (lines 1909–1914, 1980):** change `--device` `default="auto"` → `default=None`; update the help string to state the precedence ("default: EPM_FIT_DEVICE env var if set, else auto. Precedence: this flag > EPM_FIT_DEVICE > auto"); resolution becomes `DEVICE = _resolve_device(_requested_device(args.device))`. The `logger.info("compute device: %s", DEVICE)` line and the `"compute_device"` metadata row (line 2188) are untouched — reproducibility logging is preserved.
4. **Update the module docstring** (line 41 mentions the `--device` default) to name `EPM_FIT_DEVICE`.
5. **Untouched by design:** `_resolve_device` itself; the internal MLP exactness gate (`_assert_mlp_exactness`, lines 459–501) which deliberately saves/pins `DEVICE = "cpu"`/restores in `finally` — restore now puts back the resolved default, exactly as intended; `_assert_ridge_exactness` (already device-agnostic — production `main()` runs it on the resolved device today).

### 4.3 The subtle decision — what a bare `import` now yields on a GPU host

Enumerated affected paths:
- **The three hand-patched scripts:** already resolved to auto explicitly; post-simplification, identical result (env unset) or env-honoring (env set). No number changes.
- **`issue667_save_maps.py`:** its explicit cpu pin executes after import and wins. Unchanged.
- **`vectorized_mlp_skill.ridge_predict_loco_centered`:** newly cuda on GPU hosts — this is the intended fix. Numeric safety: it reuses the exact float64 closed-form dual/PRESS solvers the #658 module itself runs on cuda in production (`--device cuda` was the #658 GPU-run path), and the module documents + gates the DV as device-invariant to ≤1e-6.
- **Tests on GPU hosts:** exactness tests already pin cpu; invariants tests get the new autouse pin (above). So no test ever floats to cuda nondeterministically. The cuda code path remains exercised where it already is: the startup exactness gates run on the resolved device in every production `main()` invocation, and the `--device cuda`-unavailable fallback WARNING path is exercised in the smoke (§6).
- **Import-time side effects:** with env unset, `_resolve_device("auto")` logs nothing (only the explicit-`cuda`-unavailable branch logs), so imports stay silent; `torch.cuda.is_available()` at import is assumption A2 (§12).

Chosen design: **import-time resolution** (matching the issue-763 pattern) rather than a lazy `get_device()` accessor — the module attribute `fit658.DEVICE` is a public surface that 3 scripts and 2 test files read/monkeypatch; changing it to a function would be a bigger, riskier diff for zero benefit (see §11 D2).

```python
def test_device_request_precedence_cli_env_auto(monkeypatch):
    import issue658_fit_predictors as fit
    monkeypatch.setenv("EPM_FIT_DEVICE", "cuda")
    assert fit._requested_device("cpu") == "cpu"      # explicit CLI wins over env
    assert fit._requested_device(None) == "cuda"      # env wins over auto
    monkeypatch.delenv("EPM_FIT_DEVICE")
    assert fit._requested_device(None) == "auto"      # unset -> auto

def test_default_device_resolves_env_override(monkeypatch):
    import issue658_fit_predictors as fit
    monkeypatch.setenv("EPM_FIT_DEVICE", "cpu")
    assert fit._default_device() == "cpu"
    monkeypatch.delenv("EPM_FIT_DEVICE")
    assert fit._default_device() == fit._resolve_device("auto")
```

Plus the autouse cpu-pin fixture (§4.2). No `importlib.reload` tests — the helpers make the module-scope expression testable without re-import.

## 11. Decision Rationale

N/A — no training hyperparameters. Load-bearing code choices:

- **D1 — Env-var name + resolution shape: `EPM_FIT_DEVICE`, resolved through `_resolve_device`.**
  What: `DEVICE = _resolve_device(os.environ.get("EPM_FIT_DEVICE", "auto"))` at module scope.
  Why: identical semantics for importers and CLI users; reuses the in-file resolver (WARNING fallback included).
  Source: issue-763 branch, `issue763_fit_predictors.py:92` + `issue763_dispatch.sh` `EPM_FIT_DEVICE=cuda` lane (validated GPU cutover, PM directive 2026-07-02); in-file precedent `_resolve_device` (line 165).
  Alternatives: a new env name (`ISSUE658_DEVICE`) — rejected, fragments the existing convention; hardcoded `"cuda" if available"` without env — rejected, loses the per-process pin shard launchers need.
- **D2 — Import-time resolution of a module attribute, not a lazy accessor.**
  What: keep `fit658.DEVICE` as a plain string attribute, resolved at import.
  Why: `DEVICE` is an existing public surface — read at call time by 2 in-module fitters + `vectorized_mlp_skill.py:517`, assigned by 4 scripts, monkeypatched by tests. A `get_device()` accessor would touch every reader for no gain; the exactness gate's save/pin/restore of the global (lines 466–501) also depends on it staying an attribute.
  Source: same issue-763 pattern (module-scope constant); the runtime-override pattern documented in `issue667_alllayer_analysis.py:111–113`.
  Alternatives: lazy resolution — kept as the named fallback if A2 fails.
- **D3 — Precedence: explicit CLI > env > auto, via `--device` default `None`.**
  What: `default="auto"` → `default=None`; `main()` resolves `_resolve_device(_requested_device(args.device))`.
  Why: with the old `default="auto"`, `main()` would silently clobber an `EPM_FIT_DEVICE` pin on every CLI run — env would work for importers but not the CLI, a confusing split. `None` lets the env through while every historical invocation resolves identically (no-flag+no-env = auto; explicit flag unchanged).
  Source: task-body design requirement 1; standard argparse-sentinel convention.
  Alternatives: env > CLI — rejected (violates least surprise; an operator typing `--device cpu` must win).
- **D4 — Delete the three hand-patches rather than leave them.**
  What: remove `fit658.DEVICE = fit658._resolve_device("auto")` from issue722_fit_M / issue667_alllayer_analysis / issue667_marker_mapchange; keep their device log lines.
  Why: "leave" is NOT harmless — the patches execute after import and would clobber an `EPM_FIT_DEVICE` pin, breaking the env override for exactly the reuse scripts this task targets. Deletion is identical when env is unset and correct when set. Keep the save_maps pin: an explicit `"cpu"` request is a deliberate design pin, and post-change it correctly outranks the default.
  Source: task-body design requirement 2; `issue667_save_maps.py:320` comment ("closed-form ridge — CPU by design").
  Alternatives: rewrite patches to `_resolve_device(os.environ.get("EPM_FIT_DEVICE", "auto"))` — rejected, duplicates the module default in three places (rot risk).
- **D5 — Autouse cpu pin in the invariants tests.**
  What: one `monkeypatch`-based autouse fixture pinning `fit.DEVICE = "cpu"`.
  Why: those tests call DEVICE-reading fitters (`fit_a32` at lines 1001/1059, `fit_a34_a35` at 381, `_fit_a34_a35_one_recipe` at 531/567) with no pin; on GPU pods they would newly run on cuda — safe to 1e-6 by contract but needlessly nondeterministic for contract tests.
  Source: the exactness file's own precedent (pins at lines 74/86/105 despite the invariance contract).
  Alternatives: per-test pins — more diff, same effect; no pin — accepts avoidable GPU-host nondeterminism.
