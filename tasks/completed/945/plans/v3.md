### 4.2 False-positive strategy (the load-bearing decision)

The clarifier flagged that `_flatten_meta_strings` (line 4934) collects dict KEYS, and the #920 sidecar's `context_id_to_label` map has slug KEYS mapping to plain-English VALUES. Chosen strategy — **scan string VALUES only, plus dict keys containing internal whitespace**:

- The check covers **sidecar-CARRIED strings only** (critic round-1 binding concern — never claim full "figure-side rendered text" coverage): in practice sidecar values carry point labels, tick categories, series names, whitespace-bearing axis-label keys, and ad-hoc echo fields like #920's `cell_slugs`. NOTE the canonical `savefig_paper` writer does NOT serialize figure titles (`src/explore_persona_space/analysis/paper_plots.py:1043-1062` writes provenance + `points` only; no `get_title()`/`suptitle` read anywhere in the module) — a slug-bearing TITLE with no ad-hoc sidecar echo is a DOCUMENTED RESIDUAL (named in the check-28 docstring + §12-A7; clean-result-critic Lens 3 / interpretation-critic Lens 6 remain the substantive PNG readers per §11-H; the sidecar-writer title-serialization extension is a parked src/-side follow-up, out of this task's workflow-surface-only scope). Within sidecar-carried strings, JSON identifier keys (`_kind`, `cell_slugs`, `context_id_to_label`, `f1_house_librarian`, `c_cell`) are structural provenance. A values-only walk makes the translation-map false positive **structurally impossible**: `context_id_to_label`'s slug keys are never visited, and its plain-English values scan clean. No `*_to_label`/`*_plain` name-pattern special-casing needed.
- The one rendered-text-as-key shape check 24's docstring names — axis-label-keyed data rows like `{"1/30 chance accuracy": 0.41}` — always contains whitespace (it is prose), while identifier keys never do. So keys with internal whitespace ARE scanned; identifier-shaped keys are not. Residual recall loss: a bare slug used as a column key (`{"ans_uhdr_max": -4.9}`) is missed — accepted, documented in §12; the value-side scan catches the same slug wherever it is rendered as data (`{"condition": "ctx_blk_max"}`).
- Provenance keys (`_META_PROVENANCE_KEYS`) prune whole subtrees exactly as in `_flatten_meta_strings` — so `data_path`, `script`, `argv` values can never flag.
- **Accepted WARN-tier residual:** a slug-valued provenance-ish map NOT in the skip set — `cell_slugs` itself on a figure whose rendered title was already fixed to plain English — still WARNs. This is deliberate: the task's own acceptance criterion demands the check fire on #920's committed body, whose offense lives in exactly that field; the WARN detail text tells the operator the remedy (plain-English rendered text; slugs to provenance keys or acknowledge the WARN in body per the existing convention).

### 4.3 Token patterns

```python
# Check 28: opaque config-code tokens in figure-side rendered text.
# (a) `@L<digits>` layer pins, with any attached snake stem captured whole
#     (`ctx_blk_max@L12`); bare `@L12` also matches (no leading \b — `@` is a
#     non-word char, so a \b there would fail on a space-preceded bare pin).
_LAYER_PIN_RE = re.compile(r"\w*@L\d+\b")
# (b) snake_case token, >=2 segments, starting with a letter.
_SNAKE_TOKEN_RE = re.compile(r"\b[A-Za-z][A-Za-z0-9]*(?:_[A-Za-z0-9]+)+\b")


# Path/URI-SHAPED string: no internal whitespace and at least one path
# separator — a file path or URL, which is provenance, not rendered text.
# Deliberately NOT a whole-string any-slash skip: a slash-separated rendered
# label like "ctx_blk_max / ans_uhdr_max" contains whitespace, so it IS
# scanned (critic round-1 Must-Fix: the whole-string form false-cleaned
# slash-separated labels inside the incident class).
_PATH_SHAPED_RE = re.compile(r"^\S*[/\\]\S*$")


def _opaque_code_tokens(text: str) -> list[str]:
    """Return opaque config-code tokens in one sidecar string: `@L<d>` layer
    pins, and snake_case tokens that are >=3 segments OR carry any digit
    (`ctx_blk_max`, `sw_eng_C1`, `BS_E0`, `cond_4`); 2-segment all-alpha
    tokens (`log_prob`, `judge_rate`, `helpful_assistant`) are allowed.
    PATH-SHAPED strings (whitespace-free with a path separator — file paths,
    URLs) are exempt from the snake scan; strings that merely CONTAIN a
    slash (e.g. a slash-separated rendered label) are still scanned, with
    individual path-shaped whitespace-split words skipped. De-duped,
    order kept."""
    hits: list[str] = [m.group(0) for m in _LAYER_PIN_RE.finditer(text)]
    if not _PATH_SHAPED_RE.match(text.strip()):
        for m in _SNAKE_TOKEN_RE.finditer(text):
            tok = m.group(0)
            # Skip tokens inside a path-shaped word ("see figures/x_1/y.png")
            ws_words = [w for w in text.split() if tok in w]
            if ws_words and all(_PATH_SHAPED_RE.match(w) for w in ws_words):
                continue
            if tok.count("_") >= 2 or any(ch.isdigit() for ch in tok):
                hits.append(tok)
    seen: set[str] = set()
    out: list[str] = []
    for t in hits:
        key = t.casefold()
        if key not in seen:
            seen.add(key)
            out.append(t)
    return out
```

### 4.4 The values walker

```python
def _iter_meta_label_values(obj: object) -> "Iterator[str]":
    """Yield the rendered-text-bearing strings of a parsed sidecar for
    check 28: string VALUES (provenance-keyed subtrees pruned via
    _META_PROVENANCE_KEYS) plus dict KEYS containing internal whitespace
    (axis-label-keyed data rows). Identifier-shaped keys (`_kind`,
    `cell_slugs`, translation-map slug keys) are structural provenance and
    are NOT yielded — the deliberate divergence from check 24's
    `_flatten_meta_strings`, which collects all keys."""
    if isinstance(obj, dict):
        for k, v in obj.items():
            if isinstance(k, str) and k.casefold() in _META_PROVENANCE_KEYS:
                continue
            if isinstance(k, str) and " " in k.strip():
                yield k
            yield from _iter_meta_label_values(v)
    elif isinstance(obj, list):
        for item in obj:
            yield from _iter_meta_label_values(item)
    elif isinstance(obj, str) and obj.strip():
        yield obj
```

### 4.5 The check function

```python
def check_figure_label_codes(body: str) -> CheckResult:
    """Check 28 (WARN): rendered figure text (sidecar `.meta.json` values)
    must not carry opaque config-code tokens — `@L<digits>` layer pins or
    regime-code slugs (`ctx_blk_max`, `sw_eng_C1`). Plain-English condition
    names are the rule end to end (memory feedback_no_opaque_condition_codes,
    SPEC statistical-framing bullet); config slugs belong in the Repro config
    row / provenance keys. Incident #920: `winning_cell_scatter.png` reached
    the 9a-bis gate titled `ctx_blk_max@L12 × ans_uhdr_max@L12` after three
    review passes. Coverage = sidecar-CARRIED strings only (canonical
    `savefig_paper` sidecars do not serialize titles — a slug title with no
    sidecar echo is a known residual; PNG-pixel text stays the critics'
    substantive read). WARN never FAIL; fail-soft on missing/unparsable sidecars
    (check-24 convention, NOT check 26's loud missing-sidecar FAIL); NO-OP
    PASS offline / no figures / no scannable sidecar."""
    label = "figure text opaque config codes (slug / @L-pin tokens)"
    section = _figure_scan_section(body)
    text = section_text(body, section)
    if text is None:
        return CheckResult(label, True, f"no `## {section}` section to scan")
    urls: list[str] = []
    for line in text.splitlines():
        for m in _IMAGE_RE.finditer(line):
            url = m.group(1).strip()
            url = url.split(None, 1)[0] if url else url
            if url:
                urls.append(url)
    if not urls:
        return CheckResult(label, True, "no inline figures to scan")
    repo = _resolve_repo_root()
    if repo is None:
        return CheckResult(label, True, "skipped — repo root unresolved (offline / stdin)")
    meta_cache: dict[str, dict | None] = {}
    warns: list[str] = []
    scanned = 0
    for url in dict.fromkeys(urls):
        m = _RAW_GITHUB_FIGURE_RE.match(url)
        if m is None or (m.group("owner").lower(), m.group("repo").lower()) != _THIS_REPO_SLUG:
            continue
        if url not in meta_cache:
            meta_cache[url] = _read_figure_meta_json(repo, m.group("sha"), m.group("path"))
        meta = meta_cache[url]
        if meta is None:
            continue  # no sidecar / unparsable — fail-soft skip (check-24 convention)
        scanned += 1
        toks: list[str] = []
        for s in _iter_meta_label_values(meta):
            toks.extend(_opaque_code_tokens(s))
        toks = list(dict.fromkeys(toks))
        if toks:
            basename = m.group("path").rsplit("/", 1)[-1]
            preview = ", ".join(f"`{t}`" for t in toks[:4]) + (" …" if len(toks) > 4 else "")
            warns.append(
                f"`{basename}` figure text carries opaque config-code token(s) {preview} — "
                "use plain-English condition names in rendered figure text (slugs belong in "
                "the Repro config row / provenance keys); regenerate, or acknowledge in body"
            )
    if warns:
        head = "; ".join(warns[:3]) + (" …" if len(warns) > 3 else "")
        return CheckResult(
            label,
            True,
            f"{len(warns)} figure(s) with opaque code tokens of {scanned} scanned: {head}",
            is_warn=True,
        )
    if scanned == 0:
        return CheckResult(
            label, True, "no same-repo figure sidecar with scannable text — nothing to scan"
        )
    return CheckResult(label, True, f"{scanned} figure sidecar(s) free of opaque config codes")
```

## 11. Decision Rationale (load-bearing design decisions)

**A. Token patterns — `@L\d+` pin + (≥3-segment OR digit-bearing) snake tokens, 2-segment all-alpha exempt.**
Why: catches the full known-bad inventory (task body + memory `feedback_no_opaque_condition_codes.md`: `ctx_blk_max`, `ans_uhdr_max`, `sw_eng_C1`, `BS_E0`, `cond_4`, `c1_evil_wrong_em`) while exempting the 2-segment metric/persona vocabulary (`log_prob`, `judge_rate`, `helpful_assistant`) that legitimately appears in rendered labels. Source: in-repo precedent for pattern-list lints — `audit_clean_results_body_discipline.py::PATTERNS["condition_labels"]` (line 107, targeted regex + exemptions) and check 24's `_FRACTION_RE` (line 4902, deliberately conservative boundary logic). Alternatives rejected: curated-list-only (misses novel slugs — the incident slug `ctx_blk_max` was new); one greedy multi-underscore regex without the digit/segment gate (flags `log_prob`; fails the precision bar); scanning for lowercase 2-segment tokens (noise).

**B. Field-scoping — values-only walk + whitespace-bearing keys, provenance subtrees pruned.**
Why: structurally eliminates the translation-map false positive the clarifier flagged (slug KEYS mapping to plain labels are never visited) with zero name-pattern special-casing, while keeping the axis-label-keyed-row coverage check 24's docstring names (those keys contain whitespace). Source: `_flatten_meta_strings` (line 4934, the key-collecting sibling whose behavior motivates the divergence) + the #920 sidecar probed this session. Alternatives rejected: scan-only-known-text-fields (the sidecar schema is open — `cell_slugs` was an ad-hoc field; a fixed field list misses the next incident); skip `*_to_label`/`*_plain` name patterns (fragile naming convention; values-only subsumes it); accept full key-scan noise (flags every JSON identifier — `context_id_to_label` itself is 4 segments).

**C. WARN tier, no FAIL subset in v1.**
Why: task Constraints say WARN-tier by default; the heuristic is new and its precision unmeasured until the sweep; the existing convention (WARNs ship only when acknowledged in body) provides the enforcement teeth at the 9a-bis gate without blocking grandfathered bodies. Source: check 24 (WARN precedent, line 5087 "WARN, never FAIL — a soft mechanical aid"); check 26 shows the FAIL tier is reserved for provable structural drift. Alternative rejected: FAIL on `@L\d+` only (even the pin can be legitimate in a provenance-ish value; promote to FAIL in a follow-up only if the sweep shows perfect precision).

**D. Landing surface — `verify_task_body.py` only; audit script untouched.**
Why: the task names it primary; the verifier already owns ALL figure/sidecar IO (checks 22/24/26); the audit script is body-prose-only by design (its `condition_labels` pattern with table-cell exemptions already covers the prose half of the rule, line 107/328) and both tools run at the same 9a-bis gate, so a second surface adds duplication, not coverage. Source: check 24's incident note (line 5061-5093) — the same "figure-side text" gap was landed verifier-side. Alternative rejected: both surfaces (duplicated git-show plumbing, two divergent copies of the heuristic).

**E. Per-invocation sidecar cache, no cross-check module cache.**
Why: mirrors the existing convention exactly (check 24's `meta_cache`, line 5116; check 26 independently re-reads what check 24 read); one extra `git show` per unique figure is ~10-30ms against a verifier that already makes multiple bounded subprocess/HTTP probes per body. Source: check 24/26 implementations. Alternative rejected: memoizing inside `_read_figure_meta_json` (a drive-by refactor of a shared helper two checks depend on; also introduces cross-`verify_text`-call state the test suite would have to reason about).

**F. Escape hatch — existing acknowledge-WARN-in-body convention; no suppression allowlist.**
Why: the constraint "WARNs ship only when acknowledged in body" already exists and is exactly the right grain (per-body human judgment); a `~/.eps-*`-style suppression file (the inverse of check 24's ADDITIVE `~/.eps-stale-tokens.json`) would let false-positive fatigue silently erode the rule. Source: CLAUDE.md § Experiment Report Structure ("WARNs ship only when acknowledged in body"); `_load_stale_figure_tokens` (line 4905) shows the additive-config precedent, which we deliberately do NOT mirror in suppressive form. Alternative rejected: per-figure allowlist sidecar key (new schema surface, invisible to reviewers).

**G. Version gating — generation-agnostic (v2/v3/v4).**
Why: identical to checks 22-26 — the check keys off `_figure_scan_section` (line 1774), which resolves the right H2 per generation, and WARN-tier is grandfather-safe by construction (an old body can gain a WARN, never a new FAIL — same posture as check 24 which is generation-agnostic WARN today). Source: `CHECKS` registry comments (lines 7191-7196, "generation-agnostic checks (v2 AND v3 AND v4)"). Alternative rejected: v4-only gating (the incident class is generation-independent; figures with sidecars exist across versions).

**H. No clean-result-critic agent-file pointer.**
Why: both critic twins already run `verify_task_body.py` independently and will see the `[WARN]` line in its output; the substantive figure-text read is already owned by their Lens 3/6; a prose pointer duplicates without changing behavior. The task allows "at most a one-line pointer … if warranted" — not warranted. Alternative: add it in a follow-up if critics are observed ignoring the WARN.

Hyperparameter grounding: N/A — no model training (all `Source:` entries above are in-repo precedents by file:line, per the infra-task carve-out).
