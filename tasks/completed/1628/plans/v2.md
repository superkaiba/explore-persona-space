## 3. Hypothesis / acceptance criteria

Infra task — the "hypothesis" is a set of mechanical acceptance criteria:

1. **Queued fast path:** teardown of an instance whose pre-delete describe reads `status == "PENDING"` spawns the delete DETACHED (never joined), confirms positive issuance (a RECENT server-side delete operation targeting the instance appears in the zone-scoped operations list), and returns within seconds — never blocking on the DWS cancel.
2. **Never skip a delete:** every teardown path either (i) confirms the instance absent (404), (ii) positively confirms a delete operation issued server-side (operations-list observation, or the in-flight stderr class) before any fast return, or (iii) raises `GcpBackendError` loudly. There is no silent return without one of (i)/(ii). Issuance NOT observed within the budget → fall through to the synchronous delete (the fast path can never strand an undeleted instance silently).
3. **Timeout no longer escapes:** a `subprocess.TimeoutExpired` from the synchronous delete is caught inside teardown and escalated to an operations-list issuance probe + bounded existence poll; exhaustion raises `GcpBackendError` (so `dispatch_issue.py finalize` gets a classified error instead of a raw traceback, and the failover core's `except Exception` continues to degrade it to the janitor backstop).
4. **Regression:** non-PENDING teardown semantics unchanged — rc==0 → `_confirm_deleted` (#683 guard verbatim), "was not found" → success, other errors → raise; `render_delete_argv` is byte-untouched (its existing argv test runs unmodified).
5. **Bounded worst case:** the verify poll is monotonic-deadline-bounded at `GCLOUD_DELETE_VERIFY_BUDGET_SEC` (600 s) and the issuance poll at `GCLOUD_DELETE_ISSUANCE_BUDGET_SEC` (60 s); every subprocess call is individually capped at 300 s; stated ceilings in §9.

All five are pinned by named pytest nodes (§5/§6).

```python
def render_delete_operations_list_argv(
    *, config: GcpConfig, name: str, zone: str
) -> list[str]:
    """Build a ``gcloud compute operations list`` argv probing for a server-side
    delete operation targeting instance ``name`` (#1628 positive-issuance probe).

    Zone-scoped (``--zones``); the ``targetLink~/instances/<name>$`` regex filter
    anchors the instance name so a sibling suffix (``eps-issue-N`` vs
    ``eps-issue-N-p2``) can never cross-match. Filter + projection live-verified
    against the project 2026-07-23 (SDK 576.0.0).
    """
    argv = _base_gcloud_argv(config, "compute", "operations", "list")
    argv += [
        f"--zones={zone}",
        f"--filter=operationType=delete AND targetLink~/instances/{name}$",
        "--format=json(name,operationType,status,targetLink,insertTime)",
        "--limit=10",
    ]
    return argv
```

```python
DeleteSpawner = Callable[[Sequence[str]], None]

def _default_delete_spawner(argv: Sequence[str]) -> None:
    """Fire an ordinary synchronous ``gcloud ... instances delete`` WITHOUT
    waiting (#1628). The detached child keeps gcloud's own server-side wait and
    exits on its own (~minutes for a DWS cancel); we never join it.
    ``start_new_session=True`` detaches it from our process group so a caller
    SIGINT cannot kill the delete mid-flight; CPython's subprocess machinery
    reaps the eventual zombie opportunistically (``subprocess._active``).
    """
    subprocess.Popen(
        list(argv), stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL,
        start_new_session=True,
    )
```

```python
    config = self._config
    zone = handle.extra.get("zone") or config.primary_zone

    #     unparseable, absent/other status) falls through to the sync path
    #     (fail-open: byte-equivalent to today's behavior).
    status = self._pre_delete_status(handle, zone)
    if status == "PENDING":

            "GCP teardown: %s is DWS-queued (PENDING); using detached delete + "
            "issuance probe + bounded verify so the caller is not serialized "
            "behind the slow DWS cancel (#1628/#1586).", handle.pod_name,
        )

    argv = render_delete_argv(config=config, name=handle.pod_name, zone=zone)

            "bounded existence verify.", handle.pod_name, GCLOUD_DEFAULT_TIMEOUT_SEC,

        return

        self._confirm_deleted(handle, zone)          # #683 guard, untouched
        return
    stderr_low = (result.stderr or "").lower()
    if "was not found" in stderr_low or "404" in stderr_low:
        logger.info(...)                              # unchanged idempotency
        return
    if any(m in stderr_low for m in _DELETE_IN_FLIGHT_STDERR_MARKERS):
        # A delete/op already in flight (concurrent janitor/finalize, or our
        # own detached spawn) — verify instead of raising (#1628).
        self._verify_delete_landed(handle, zone, issuance_confirmed=True)
        return
    raise GcpBackendError(...)                        # unchanged loud failure
```

```python
def _pre_delete_status(self, handle: RunHandle, zone: str) -> str | None:
    """One describe; the instance's status, or None on ANY anomaly (fail-open)."""
    try:
        probe = self._run(render_describe_argv(config=self._config,
                                               name=handle.pod_name, zone=zone))
    except Exception:                                  # incl. TimeoutExpired
        return None
    if probe.returncode != 0 or not probe.stdout.strip():
        return None
    try:
        payload = json.loads(probe.stdout)
    except json.JSONDecodeError:
        return None
    status = (payload.get("status") or "").upper()
    return status or None
```

```python
def _teardown_pending_detached(self, handle: RunHandle, zone: str) -> bool:
    """Detached delete of a DWS-queued instance + positive-issuance probe.

    True  = a recent server-side delete op was observed; bounded verify ran
            (fast path complete). False = no op observed within the issuance
            budget -> caller falls through to the synchronous delete.
    """
    argv = render_delete_argv(config=self._config, name=handle.pod_name, zone=zone)
    self._spawn_delete(argv)     # fire-and-forget; the detached gcloud waits
                                 # server-side on its own and exits alone
    if self._probe_delete_issuance(handle, zone,
                                   budget_sec=_delete_issuance_budget_sec()):
        self._verify_delete_landed(handle, zone, issuance_confirmed=True)
        return True
    logger.warning(
        "GCP teardown: no recent delete operation observed for %s within %ss "
        "of the detached spawn; falling back to the synchronous delete (#1628).",
        handle.pod_name, _delete_issuance_budget_sec(),
    )
    return False
```

### 4-G. `_probe_delete_issuance`, `_escalate_slow_delete`, `_verify_delete_landed` (new helpers)

```python
def _probe_delete_issuance(self, handle, zone, *, budget_sec: float) -> bool:
    """True iff a RECENT server-side delete operation targets this instance.

    Polls the zone-scoped, targetLink-filtered operations list through the
    NORMAL runner (seconds per call). Rows older than
    GCLOUD_DELETE_OP_RECENCY_SEC — or with a missing/unparseable insertTime —
    are IGNORED: instance names recur across incarnations, so a prior
    incarnation's delete op must never read as our issuance. Any probe anomaly
    counts as not-observed this round (fails toward the sync path).
    """
    deadline = time.monotonic() + budget_sec
    poll = _delete_issuance_poll_sec()
    op_argv = render_delete_operations_list_argv(
        config=self._config, name=handle.pod_name, zone=zone)
    while True:
        try:
            r = self._run(op_argv)
            if r.returncode == 0 and r.stdout.strip():
                now = datetime.now(timezone.utc)
                for op in json.loads(r.stdout):
                    try:
                        age = (now - datetime.fromisoformat(op["insertTime"])
                               ).total_seconds()
                    except (KeyError, TypeError, ValueError):
                        continue          # unparseable -> ignore (conservative)
                    if age <= GCLOUD_DELETE_OP_RECENCY_SEC:  # skew-tolerant
                        logger.info("GCP teardown: delete op %s observed for %s "
                                    "(status=%s, age=%.0fs).", op.get("name"),
                                    handle.pod_name, op.get("status"), age)
                        return True
        except Exception:                 # incl. TimeoutExpired, JSON errors
            pass                          # anomaly -> not observed this round
        if time.monotonic() >= deadline:
            return False
        time.sleep(poll)

def _escalate_slow_delete(self, handle: RunHandle, zone: str) -> None:
    """Post-TimeoutExpired: POSITIVELY confirm the timed-out delete's server-side
    operation via the operations list (subprocess.run killed the local gcloud;
    the op it issued persists server-side), then bounded-verify. No re-issue."""
    issuance = self._probe_delete_issuance(
        handle, zone, budget_sec=_delete_issuance_budget_sec())
    self._verify_delete_landed(handle, zone, issuance_confirmed=issuance)

def _verify_delete_landed(self, handle, zone, *, issuance_confirmed: bool) -> None:
    """Bounded existence poll: 404 -> success; PENDING+issued -> fast in-flight
    return; deadline exhausted -> loud GcpBackendError. Never returns silently."""
    budget = _delete_verify_budget_sec()
    poll = _delete_verify_poll_sec()
    deadline = time.monotonic() + budget
    last_status: str | None = None
    while True:
        probe = self._run(render_describe_argv(...))   # each call: own 300s cap
        low = (probe.stderr or "").lower()
        if probe.returncode != 0 and ("was not found" in low or "404" in low):
            logger.info("GCP teardown: %s confirmed deleted.", handle.pod_name)
            return
        if probe.returncode == 0 and probe.stdout.strip():
            try:
                last_status = (json.loads(probe.stdout).get("status") or "").upper() or last_status
            except json.JSONDecodeError:
                pass
            if last_status == "PENDING" and issuance_confirmed:
                logger.warning(
                    "GCP teardown: delete of DWS-queued %s is issued and in flight "
                    "server-side; NOT blocking the caller on the slow DWS cancel "
                    "(queued instances bill no GPU; backstops: gcp_audit janitor + "
                    "--max-run-duration fence). (#1628)", handle.pod_name,
                )
                return                                  # the pivot-unblocking fast return
        if time.monotonic() >= deadline:
            raise GcpBackendError(
                f"gcloud delete of {handle.pod_name} did not confirm within "
                f"{budget}s (last_status={last_status!r}, "
                f"issuance_confirmed={issuance_confirmed}); gcp_audit janitor + "
                f"--max-run-duration fence remain the backstops"
            )
        time.sleep(poll)
```

Notes: (i) the fast return fires only with BOTH `PENDING` status AND positive issuance — an unconfirmed-issuance PENDING instance polls to the deadline and raises (never a silent skip); (ii) a non-PENDING status (RUNNING/STAGING = billing, STOPPING/TERMINATED = shutdown transient) polls to 404 or the deadline; (iii) both loops' deadlines are checked on `time.monotonic()`, so slow individual probes cannot unbound them (single-probe overshoot ≤ 300 s, stated in §9); (iv) issuance is a boolean fed forward, so the fast-path and escalation paths share ONE verify implementation; (v) teardown docstring (gcp.py:6876-6900) updated to document the PENDING branch + escalation.

## 11. Decision Rationale

- N/A — no model training (no training hyperparameters).

1. **Mechanism = hybrid: PENDING pre-probe → detached delete spawn + operations-list positive-issuance probe; TimeoutExpired escalation on the sync path.** Why: (a) a "longer subprocess timeout" is impossible to thread cleanly (the injectable `GcloudRunner` type is argv-only, gcp.py:3733 — special-casing `default_gcloud_runner` would fork test/production behavior) and still serializes the caller for the full longer wait; (b) `--async` DOES NOT EXIST on `gcloud compute instances delete` — live-probed on the deployed SDK 576.0.0 (`unrecognized arguments: --async` on GA/beta/alpha; `--help` SYNOPSIS carries only `--zone`, `--delete-disks|--keep-disks`), which also definitively explains #1586's "--async errored" — so plan v1's async mechanism is unimplementable; (c) the detached spawn delivers the same "return at request time" property WITHOUT any CLI flag, and the operations list makes issuance POSITIVE evidence instead of an inference. Source: live CLI probes 2026-07-23 (§2) + the gcloud reference (https://docs.cloud.google.com/sdk/gcloud/reference/compute/operations/list) + the #736 in-repo TimeoutExpired-catch precedent (gcp.py:5247-5307) + the in-repo injection-seam pattern (gcp.py:4939-4967).
2. **Issuance probe = zone-scoped `operations list` with an anchored targetLink regex filter.** `--zones=<zone>` scopes pagination to the teardown's known zone; `--filter=operationType=delete AND targetLink~/instances/<name>$` was live-verified to return exactly the named instance's delete ops (the `$` anchor prevents sibling-suffix cross-match); `--format=json(...)` projection live-verified. Source: deployed `--help` SYNOPSIS + the live filtered read against `eps-persona-gpu-jun2026` (§2, 2026-07-23).
3. **`GCLOUD_DELETE_VERIFY_BUDGET_SEC = 600` (raised from v1's 300).** The #1586 cancel completed within ~10 min of the first attempt; v1's 300 s sync cap + 300 s budget summed to exactly 600 s — exact-boundary against the observed window. 300 + 600 = 15 min ceiling gives ~50% margin. Source: #1586 (incident measurements); fact-check item 5.
4. **`GCLOUD_DELETE_ISSUANCE_BUDGET_SEC = 60` / `POLL = 5`; `GCLOUD_DELETE_OP_RECENCY_SEC = 900`.** The Compute API returns the Operation resource at request time (https://cloud.google.com/compute/docs/reference/rest/v1/instances/delete), so the op should list within seconds; 60 s covers an API tail, and a miss falls to the sync path (cheap). The recency window must exceed the 300 s sync cap (the escalation path probes an op issued up to 300 s ago) and exclude prior-incarnation ops — live-observed stale same-name ops were days apart; 900 s = 3× the cap. Boot-loop same-name reuse inside 15 min is the named residual (§8), bounded by the actually-spawned delete + janitor/fence. Source: REST reference + live listing (§2).
5. **In-flight stderr markers `("is not ready", "being deleted")`, substring/lowercase — conservative, verify-not-raise on match.** "is not ready" matches the documented GCE resourceNotReady concurrent-operation class (https://cloud.google.com/compute/docs/troubleshooting/troubleshooting-vm-creation); the literal "being deleted" could not be sourced — `Source: ungrounded — needs smoke-test` (recorded as an implement-time smoke item; a marker miss falls toward today's raise, never toward a skip). The v1 claim that this class explains #1586's "--async errored" is DROPPED (item 1 supersedes it).
6. **Fast return on PENDING + confirmed issuance (pivot proceeds before 404).** A queued flex-start instance is not provisioned, so it bills no GPU while queued (Source: DWS pricing, https://cloud.google.com/products/dws/pricing); the delete op is positively observed server-side; the failover core ALREADY proceeds on teardown failure today with weaker evidence (backend_poll.py:3895-3905), and three backstops remain (janitor, `--max-run-duration` fence, the raise-on-exhaustion for every non-PENDING state). Decision: safe — the residual (observed-then-failed delete op) is named in §8 and strictly narrower than the status quo.
7. **`_delete_verify_*` / `_delete_issuance_*` env knobs read at call time via private readers.** Source: `backend_poll._gcp_queue_wait_seconds` pattern (#783) — retune without restart, malformed values fall back.
8. **Detached spawn shape: `subprocess.Popen(argv, stdout=DEVNULL, stderr=DEVNULL, start_new_session=True)`, never joined.** `start_new_session` isolates the delete from caller signal groups (a finalize SIGINT must not kill the cancel mid-flight); DEVNULL prevents pipe-buffer blocking; CPython reaps the eventual zombie via `subprocess._active`. Source: stdlib subprocess semantics; the seam mirrors gcp.py's existing `X or default_X` injection pattern (gcp.py:4949).
9. **No `backends/base.py` signature change; no backend_poll change; `render_delete_argv` untouched.** Keeps the fix at the one seam every caller shares; avoids a public-contract (architectural) change. Source: task body invariant list + `.claude/rules/workflow-fix-on-bug.md` § Architectural greenlight.
