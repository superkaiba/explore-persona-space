# Plan v3 — #2027: warn when the plan-projected §9 wall exceeds the intent's SLURM `--time` bin

`kind: infra` (workflow-fix). Target surface: `scripts/verify_plan.py`.

## 0.0 TL;DR

Add one WARN-only plan-time check (`c50`) to `verify_plan.py` that compares a
plan's §9 projected wall against the SLURM `--time` bin its own embedded
`dispatch_issue.py launch` command will resolve, and warns when the wall
exceeds the bin with no `--time-budget-hours` declared — the one arm of this
task's Goal that #2161 did not already cover. No runtime behavior changes.

**Estimated GPU-hours (total): 0**

**Success criteria (acceptance):**
1. `c50` WARNs on a fixture plan projecting a 12 h §9 wall against
   `--intent lora-7b` (6.0 h bin) with no `--time-budget-hours`, and the WARN
   detail names the wall, the bin, and the intent.
2. All five negative controls + the equality boundary in §5 hold (each SKIPs
   or PASSes as specified) — no false WARN on any of them.
3. `uv run pytest tests/test_verify_plan.py -q` green, including the untouched
   c46/c47/c48 tests (regression evidence for the shared-helper reuse).
4. `uv run python scripts/workflow_lint.py` (no flags) and `ruff check` clean.
5. The corpus sweep re-run against the FINAL code reproduces the measured
   plan-review baseline (§7 row 1): the same 5 true-positive WARN hits over
   5,244 plans, plus at most the 27 dedupe-recovered single-dispatch
   candidates — and every newly-recovered hit is inspected and classified
   true/false positive before landing.

**Kill / abort criteria (halt and report):**
- The corpus sanity-check shows a WARN hit rate high enough that c50 would
  ship as noise (the #1388 fleet-wedge shape) AND no narrowing of the
  six-conjunct predicate brings it down → HALT, post `epm:failure v1`
  (`failure_class: code`), do not land a noisy check.
- Reusing `dispatch_issue._slurm_lane_reachable` proves unimportable from
  `verify_plan.py` without a circular import → HALT rather than duplicating
  the reachability logic (a divergent second copy is worse than no check).

**What would change my mind:** if the corpus sweep shows real plans routinely
project a §9 wall above their intent's default bin *deliberately* (because the
wall is a multi-phase total while each dispatch runs one phase under the bin),
then the MAX-over-rows read is measuring the wrong thing and the check should
either compare per-phase rows only or not ship at all — that finding kills the
single-dispatch MAX design, not just its threshold.

## 2. Why `verify_plan.py` and not `dispatch_issue.py`

The projected wall is **plan-resident** and never reaches the launch CLI —
there is no flag to carry it, so a dispatch-time check is impossible without
inventing one. `verify_plan.py` already parses both halves of the comparison
(§3), so the join is available there and nowhere else.

**Not a third arm of `_c46_drift_arms` either.** c46 is a per-argv *parse*
check whose signature takes only `(parser, argv)` — it has no plan-body
input, so it cannot see the §9 table. Its docstring also explicitly scopes it
to "the two demonstrated drift shapes". New standalone check instead.

## 3. Design — new check `c50_plan_wall_vs_slurm_time_bin`

`c49` is taken (`c49 authorized-smoke-stubs`); **c50** is the next free id.

Polarity **WARN-only, conditional, all kinds** — matching c46's stated
posture ("NEVER FAILs — the runtime exit-2 refusals are the hard gate; this
check is the plan-time drift detector") and c47/c48. A FAIL posture on a
heuristic wall/bin join risks the #1388 fleet-wedge shape (the no-flags lint
IS the Step 9c gate).

**Everything is composed from existing helpers — no new parsing:**

| Need | Existing helper |
|---|---|
| dispatch commands in the plan | `_c46_command_candidates` (L8374) |
| tokens → argv | `_c46_argv_from_tokens` (L8441) |
| argv → parsed namespace | `_c46_dry_parse` (L8410) |
| `--time-budget-hours` presence | `_c46_has_flag` (L8436) |
| SLURM reachability | `dispatch_issue._slurm_lane_reachable(ns)` (L1020-1034) — the RUNTIME predicate, reused for exact parity |
| §9 wall rows | `_compute_table_rows` (L4729) → `_ComputeRow.wall` |
| wall cell → float | `_c48_first_number` (L8726) |
| intent → bin | `slurm._DEFAULT_TIME_BUDGETS_HOURS` (L553), mirroring `slurm.time_budget_hours()` (L581) |

**Predicate (all must hold, else SKIP with a stated reason):**

1. The plan contains **exactly one DISTINCT** launch-shaped dispatch command
   (`argv[0] == "launch"` or leads with a flag — c46's `launch_shaped` test),
   **deduped on `tuple(argv)` before counting**. The dedupe is load-bearing,
   not cosmetic: the v2 corpus probe found **27 of the 170** multi-launch
   plans carry byte-identical argvs (the same command restated in §4 and §9),
   i.e. one real dispatch. Deduping recovers all 27 at zero false-positive
   cost, since identical argvs resolve an identical intent and bin.
2. It dry-parses (`_c46_dry_parse` returns a namespace). A non-parsing argv is
   already c46 arm 1's finding; c50 stays silent rather than double-reporting.
3. `_slurm_lane_reachable(ns)` is True.
4. `not _c46_has_flag(argv, "--time-budget-hours")`.
5. `ns.intent` is a key of `_DEFAULT_TIME_BUDGETS_HOURS`.
6. ≥1 §9 row yields a parseable wall via `_c48_first_number`.

**Verdict:** let `max_wall_h` = max parseable per-row `planned_wall_h`. WARN
iff `max_wall_h > bin_h`, strictly greater. Detail names the offending row's
component, `max_wall_h`, the intent, the resolved `bin_h`, and the fix
(`--time-budget-hours <h>`), mirroring the runtime refusal's note style.

`--intent` is `required=True` on the launch subparser (L2871-2875), so a
parsing launch argv always carries one — no default-value ambiguity.

**Named accepted false negatives** (deliberate, WARN-only posture):

- **Multi-dispatch plans → SKIP.** With ≥2 launch commands the wall row ↔
  dispatch join is ambiguous (a big row may belong to a differently-budgeted
  dispatch), and a MAX-over-all-rows read would false-fire. Conservative SKIP;
  a per-phase join is a possible follow-up, not v1.
- **`max_wall_h == bin_h` → no WARN.** Strictly-greater avoids introducing a
  tuned margin constant (the repo's own sizing style is an explicit in-table
  margin, e.g. `ft-7b: 23.5  # leave a margin under the 24h short-bin cap`).
- **Unknown intent → SKIP.** `slurm.time_budget_hours()` already raises
  there; that is a different, already-fail-fast failure.
- **Combined `Wall / GPU-h` header rows** (`gpu_is_wall_col=True`) are skipped
  for the wall read, following c47's #2177 precedent.
- **Frontmatter `backend:` pins are invisible** to the argv-only reachability
  read. Accepted deliberately: this is exact parity with the runtime guard's
  own `args.backend` semantics, and a divergent second reachability rule is
  worse than a narrower one.

**Named residual FALSE POSITIVE** (absent from today's corpus — 0 of the 46
plans that pass all six conjuncts): a single-dispatch plan whose MAX §9 row is
an off-pod / VM-side analysis row exceeding the bin while the *dispatched*
job's own wall sits under it. WARN-only polarity absorbs it; it is recorded in
the c50 docstring's FN/FP list so a future reader does not re-derive it.

**Design note — env sensitivity.** `_slurm_lane_reachable` consults
`auto_lane_order()`, which honors `EPM_AUTO_LANE_ORDER`. That is *correct*
(parity with the runtime), but makes the verdict env-dependent, so tests must
pin the env explicitly rather than inherit it. A `RouteError` inside the
predicate already returns False (L1033-1034) — fail-closed to SKIP, never a
crash. `dispatch_issue` is loaded lazily exactly as c46 does it; on
`--plan-file` off-repo use the loader is unavailable → SKIP (c46's precedent).

## 5. Tests (`tests/test_verify_plan.py`)

One fires-pre-fix positive plus five negative controls, each pinning one
predicate conjunct so a future narrowing is test-breaking:

1. **Positive** — one `launch` command, `--intent lora-7b`, no
   `--time-budget-hours`, SLURM-reachable, §9 row `planned_wall_h` 12 → WARN,
   detail names 12, 6.0, `lora-7b`.
2. `--time-budget-hours 12` present → SKIP (conjunct 4).
3. `--backend runpod` pin (not SLURM-reachable) → SKIP (conjunct 3).
4. §9 wall 4 h vs the same 6.0 h bin → PASS (verdict boundary, under).
5. Two launch commands → SKIP (documented ambiguous-join FN).
6. `--intent cpu-bigmem` (absent from the bin table) → SKIP (conjunct 5).

Plus a boundary test at `max_wall_h == bin_h` → no WARN, pinning the
strictly-greater choice so a later `>=` "fix" is deliberate.

`EPM_AUTO_LANE_ORDER` pinned via `monkeypatch` in every test that asserts a
reachability-dependent verdict.
