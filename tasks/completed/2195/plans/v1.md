### 0.0 TL;DR (plain English — the user reads this first)

#### 4.1 `check_stale_evidence_pins` (check name: `stale-evidence-pins`)

Signature: `check_stale_evidence_pins(blanked_lines: list[str], figures_root: Path, expect_issue: int | None) -> CheckResult`. Operates on BLANKED lines (verbatim examples are data). Read-only local git via `_git`; no network, no writes. Returns ONE aggregated CheckResult (the file's idiom).

**Citation matcher (conservative by construction).** Per blanked line:
1. Skip the line entirely when it matches `_CODE_SHA_ROW_RE` (the `| Code SHAs |` row — run-provenance pins, not evidence citations).
2. Collect candidate paths: backticked tokens containing `/`, not containing `://`, not starting with `/`, no `…`/`...`, expanded through ONE brace group (`_expand_brace_group`), then filtered to the EVIDENCE-PREFIX set — a new module constant:
   `_EVIDENCE_PATH_PREFIXES = ("eval_results/", "ood_eval_results/", "figures/", "docs/", "tasks/")`.
   Rationale: evidence artifacts live under result/doc/task trees; `scripts/`/`src/`/`configs/` citations are run-provenance ("this ran at `<sha>`" — a later code commit does not supersede the statement that the run happened at that SHA) and are owned by `check_code_sha_cards`. The prefix set is pinned by a §6 test, not tunable at implementation.
3. Resolve same-line pins via the landed `_same_line_pins` (URL-hex exclusion + branch-token resolution inherited for free). No resolvable pins → the line is not a citation-at-a-pin → skip silently (a no-pin committed-under claim already gets `committed-under-claims`' WARN; duplicating it here would double-report).
4. **File test (the directory-home-claim excluder):** for each (member, pin), run `_git(root, "ls-tree", "-r", "--name-only", pin, "--", member)`; proceed ONLY when the listing is exactly one name equal to the cited member (a FILE at that pin). A multi-blob listing (directory citation, e.g. "committed under `eval_results/issue_2162/judge/`") is skipped with a note — later additions under a directory don't supersede a home claim, and the #2162 corrected report legitimately carries such directory claims at old pins (WARNing on them would make the corrected report noisy, violating H2's spirit at whole-report scope). A zero-blob listing (path absent at pin) is skipped with a note — a broken citation is `committed-under-claims`' FAIL/WARN territory, not staleness.

**Staleness read.** Tip set = the resolvable refs among {`issue-<N>`, `origin/issue-<N>`} (issue = `expect_issue` if provided, else `_infer_issue_from_lines`; deduped by resolved SHA — the `_branch_tip_probe` ref convention). For each surviving (member, pin): stale-vs-tip iff `_git(root, "log", "--oneline", f"{pin}..{ref}", "--", member)` is non-empty for that ref. **Any-pin-fresh rule (mirror of committed-under's any-pin-satisfies, maximally conservative):** the member WARNs only when EVERY file-resolving same-line pin shows newer commits on EVERY resolvable tip ref; one fresh pin (or one ref with no newer commits) keeps it silent. Note the branch-token pin case composes naturally: a line pinned only by `` `issue-<N>` `` resolves the pin AT the tip, so `<tip>..<tip>` is empty → silent by construction.

**WARN detail (per stale member, deduped by (member, pin-set)):** `line <n>: \`<path>\` cited at <pin12> has <K> newer commit(s) on <ref> (newest: <sha12> "<subject>") — if the citation is a deliberate as-of pin, confirm the newer version still supports the citing sentence; else re-pin to the current commit`. Newest commit = first line of the `git log` output; subject clipped to ~60 chars.

**Degrades (each recorded as a note or WARN, never fatal):** non-git `figures_root` → single WARN (mirrors `_check_pin_blob_identity` / `committed-under-claims`); issue number unresolvable OR no issue-branch ref resolves → PASS-note ("stale-evidence check skipped — no issue branch ref resolvable"; the post-merge branch-deleted shape must not WARN on every promote of an old report). No candidate citations → PASS "no evidence citations at a pin (N/A)".

**Severity: WARN in BOTH modes, never FAIL** (the task body's core call — an as-of pin is legitimate; the check cannot read contradiction). The `superseded_readings`-marker FAIL escalation the body sketches is explicitly OUT OF SCOPE (a possible follow-on requiring a convention).

**What the check does NOT fire on (conservative-matcher enumeration):**
- Directory-level citations (multi-blob at pin) — skipped with note (the #2162 corrected report's own `committed under \`…/judge/\` at \`20cef…\``-class lines).
- `scripts/`/`src/`/`configs/` code citations + the Code-SHAs row — outside the prefix set / line-skipped.
- Lines with no resolvable same-line pin — skip (no double-reporting of `committed-under-claims`' no-pin WARN).
- Paths absent at the pin — skip (broken ≠ stale; owned by `committed-under-claims`).
- URLs, absolute paths, `…`-abbreviated paths, slash-less tokens — filtered before any git call.
- Image pins (`raw.githubusercontent.com` URLs) — not backticked repo-relative paths; also `_same_line_pins` blanks URL spans, so an HF revision or pin inside a URL never becomes a git pin. `image-pin-blob-identity` keeps owning figure identity.
- Anything inside fenced code blocks / blockquotes — blanked before scanning.
- **Named residue 1:** a stale citation phrased WITHOUT a same-line pin ("the routing evidence shows…" with the pin two lines up) — invisible by construction; the same-line convention is what the landed checks enforce, and the WARN teaching in `committed-under-claims` pushes authors toward same-line pins.
- **Named residue 2:** artifacts modified on a DIFFERENT branch (e.g. main after a sibling merge) — out of scope per the task body ("modified on the same branch"); the tip set is the issue's own refs.
