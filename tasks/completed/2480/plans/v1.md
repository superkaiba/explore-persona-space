## The two-construction audit method (load-bearing)

### Construction 1 — 5% base-rate composition → **verdict: NO differential inflation** (pre-assessed; implementer confirms)

What I read:
1. `map_arms_results.json.eval` = `{n:1960, n_pos:98, base_rate:0.05, k5:98}` — a **single top-level block**. Confirm no per-arm `eval`/`base_rate` override: arm dicts (A/B/C/D/E/random, verified L19 arm keys) carry only `{roc_auc, pr_auc, hit@5pct, evals_to_find_20}`. ⇒ **all arms scored on the identical eval set at the identical base rate.**
2. `compliance_pilot_results.json` pool blocks: `.needle_benign_5pct.{n:3000, base_rate:0.05}` and `.hardneg_failcomp_5pct.{n:3000, base_rate:0.05}` — same base rate across pools.
3. Balanced-pool control: `.balanced_benign` (base 0.50) — probe PR-AUC max = 0.9895; map-then-project / r_B reach only 0.81-0.87 (report §0).

Verdict logic (state explicitly in the report): PR-AUC chance = base rate, applied **equally** to every compared arm. A 5% base rate lowers the chance floor for all arms alike, so it cannot inflate the probe *relative to* the map — the probe-vs-map gap (0.973/0.974 vs ≤0.43) is measured at matched base rate. The dominance also holds at the **50% balanced base rate** (probe ≈0.99 vs map/r_B 0.81-0.87), which is the definitive disconfirmation of a base-rate-artifact story. **Absolute caveat to state:** PR-AUC at 5% base is a genuinely harder metric than at 50%, so 0.973 (≈19× base) is a strong absolute result — the low base rate makes the number *look* impressive but is not a differential confound.

### Construction 2 — same-family failed-jailbreak negatives → **verdict: NO inflation; the construction makes detection HARDER** (pre-assessed; implementer confirms)

What I read:
1. `compliance_pilot_results.json._meta.split` + pool definition: `hardneg_failcomp_5pct` = 150 always-comply positives vs 2,850 **failed-compliance same-family** negatives (report §0 line 64; pool name confirms).
2. `map_arms_results.json._meta.split` = "per-context groups; MAP reserve / probe-train / test mutually disjoint"; `label_efficiency_results.json._meta.split` = "label pool == map reserve … EVAL disjoint, identical construction+seed to map_arms". ⇒ no context appears in both train and test.
3. `compliance_percontext.json` — confirm positives are high-compliance (top-ranked by `min_over_rollouts`) and negatives are genuinely **low/partial compliance jailbreak-family** contexts (NOT benign): check the compliance-score distribution splits positives from negatives on the compliance DV, and that negatives come from `evil_*` (jailbreak) splits, not the benign pool.

Verdict logic (state explicitly): same-family hard negatives share family/surface form with the positives and differ only in compliance outcome, so they make detection **harder**, not easier — a high PR-AUC against them is the finding, not an artifact. Inflation would require the negatives to be trivially separable by something *other than* compliance (e.g. if they were benign contexts, or if context-identity leaked train→test). The grouped-disjoint split rules out identity memorization; the percontext distribution confirms the negatives are low-compliance jailbreak-family contexts. **Residual to state honestly:** the probe may exploit any compliance-correlated feature of `v_C` that generalizes — that is exactly what a compliance detector should do; the claim ("detects always-comply contexts") is supported, not overstated.
