## 3. Design

### 3.1 The gate (what runs, exact commands, verdict rule)

**Trigger** (same artifact-only set as the Step 10d gate): the gate binds only when the round's to-be-committed set contains any path outside `tasks/`, `figures/`, `eval_results/`, `ood_eval_results/`, `raw/`, `data/`, `docs/methodology/`. Figures/JSON-only rounds skip and pay nothing.

**Two legs, one background Bash** (the no-flags leg alone can approach the 600s foreground cap under load — #991/#996 kill class; launch it while the round's body-fold work proceeds, read the verdict before the push):

```bash
# Inline payload lint gate (#1460) — ONE background Bash (run_in_background=true)
printf '%s\n' <round's to-be-committed non-artifact paths, repo-relative> \
  > /tmp/issue-<N>-inline-payload.txt
{ uv run python scripts/workflow_lint.py; \
  uv run python scripts/select_step9c_tests.py \
      --map-files /tmp/issue-<N>-inline-payload.txt \
    | cut -f1 | sort -u | xargs -r uv run pytest -q; \
} > /tmp/issue-<N>-inline-lint.txt 2>&1
# VERDICT — payload-attributed; never a bare exit-0 on the repo-wide runs:
grep -F -f /tmp/issue-<N>-inline-payload.txt /tmp/issue-<N>-inline-lint.txt \
  | grep -v '^WARN' || echo NO-PAYLOAD-HITS
```

**Verdict rule (the exact contract text to encode):**
- A non-WARN output line naming a payload path **blocks the push** when (i) the payload file is NEW this round (absent from `origin/main` — payload-caused by construction; both #1388 offenders and both #1092 offenders were this case), or (ii) for a MODIFIED file, the flagged construct sits in the round's own added lines (`git diff -- <path>` pre-commit / `git diff origin/main -- <path>` post-commit). Fix, re-run just the relevant single `--check-<x>` flag or single mapped test (~20-40s measured), then push.
- Hits naming only non-payload paths, WARN lines, and modified-file hits whose flagged construct is absent from the round's added lines are **pre-existing red — never block**; name them in the round's `epm:progress` completion note (visible, not re-buried).
- `NO-PAYLOAD-HITS` → push.

**Why design (a)+(c) over (b):** the fleet-breaking oracle is `test_workflow_lint_default_exits_zero` — exactly the no-flags bundle — plus the GLOB_SCAN_TESTS pytest scanners. A curated flag subset (design b) requires maintaining a 16-flag list in prose that silently under-covers every future scripts-scanning check, and its measured saving is ~40s-3min vs the no-flags run (3m10s vs 2m29s idle; both well under the round's own analysis wall-time). Design (c) alone misses all workflow_lint checks (verified: GLOB_SCAN_TESTS has exactly 2 entries, both pytest scan tests). Full no-flags + mapped tests = complete coverage of both fleet-breaking oracles, zero new code, zero list maintenance. Cost is bounded by the trigger (artifact-only rounds skip) and by backgrounding.
