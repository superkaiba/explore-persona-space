## 4. Design

### 4.1 The edit to `_c38_repo_wide_cmd` (pytest arm, L6718–L6721)

Replace the current block:

```python
for m in _C38_PYTEST_OCC_RE.finditer(line):
    tail = _C38_TAIL_SPLIT_RE.split(line[m.end() :], 1)[0]
    if not _C38_PYTEST_SCOPED_RE.search(tail):
        return "pytest (no path scope)"
```

with:

```python
for m in _C38_PYTEST_OCC_RE.finditer(line):
    rest = line[m.end() :]
    tail = _C38_TAIL_SPLIT_RE.split(rest, 1)[0]
    # A scoping token (`::` node id, `tests?/…py` path, or `-k` filter)
    # may live PAST a backtick that terminates the arg tail — the
    # ordinary prose shape "Concrete pytest node id: `tests/x.py::y`".
    # Widen to the rest-of-line so the tail split does not hide it.
    if not _C38_PYTEST_SCOPED_RE.search(tail) and not _C38_PYTEST_SCOPED_RE.search(rest):
        return "pytest (no path scope)"
```

**Search-scope decision** (see §11): unbounded rest-of-line, NOT sentence/clause-bounded.
- Cost of bounding: complexity + a new decision (which terminator counts as a clause boundary — `.`, `;`, newline, all of them?), and the reproduction shape from the task body ends in `.` immediately after the backticked node id — a `.`-clause bound would need to explicitly whitelist trailing punctuation, which is fragile.
- Cost of not bounding: a line that asserts green on an unscoped `pytest` while separately mentioning an unrelated `tests/foo.py` elsewhere on the line newly goes quiet.
- The unbounded read wins because (a) the false-positive is a HIGH-frequency prose shape (any plan naming a pytest node id in backticks) while the newly-quiet case is a LOW-frequency shape (a bare `pytest` assertion co-occurring with an unrelated `tests/…py` mention on the same line), (b) `_C38_PYTEST_SCOPED_RE` already returns a scoped verdict on a `-k` filter or `::` node id regardless of position, so the same-line proximity heuristic never distinguished them, (c) the c38 check is WARN-only and adversarial reviewers adjudicate remaining ambiguity. The newly-quiet case is COVERED by a pin test (§4.3.3, marked as the acknowledged trade-off).

The re-scan is `O(len(rest))` per pytest occurrence — cheap; no need to pass `tail`'s scan region through as an exclusion. `rest` includes the tail, and re-scanning it does no harm (regex is idempotent).

Both regex definitions (`_C38_TAIL_SPLIT_RE` L6692, `_C38_PYTEST_SCOPED_RE` L6697) are UNCHANGED. Only the pytest arm's return condition changes.

## 11. Decision Rationale

**The one substantive decision — rest-of-line search scope.**

- **What:** the pytest arm's second `_C38_PYTEST_SCOPED_RE.search` runs against the FULL `line[m.end():]` (unbounded rest-of-line), NOT a sentence/clause-bounded slice.
- **Why:** three reasons stacked, in decreasing weight —
  1. **Frequency asymmetry.** The false-positive shape (a `Concrete pytest node id: \`tests/…py::test_…\`` prose line) is a common plan-prose idiom — this very plan's §7.1 criterion 8 carries it, and any plan that names a specific test as an acceptance criterion is at risk. The newly-quiet shape (a bare unscoped `pytest` assertion whose line ALSO mentions an unrelated `tests/…py`) is rare because a plan naming a test path on the assertion line usually MEANS that test is the scope. The unbounded read minimizes total false-positive + false-negative traffic through the check.
  2. **`_C38_PYTEST_SCOPED_RE`'s own semantics are position-independent.** The regex matches `::`, `tests?/…py`, or `-k` anywhere in the string it is fed; the tail-only heuristic was an incidental effect of the arg-tail-split idiom shared with arms A + C, not a deliberate spatial bound. The arg-tail-split idiom serves arms A + C well (a `--check-` flag is meaningful only in the workflow_lint arg tail; a `.` path token likewise for ruff), but pytest scoping is a scope declaration, not a positional flag — its meaning does not change with position on the line.
  3. **c38 is WARN-only.** A remaining false negative from the unbounded read is not a blocker — the WARN adjudication path stays available to the fact-checker and critic. Better to under-WARN a rare shape than over-WARN a common one, given the standing disposition (from the task body's Evidence section) that c38 WARNs are carried through revisions rather than resolved.
- **Source:** ungrounded (heuristic tweak; no external literature; the c38 check is a project-internal invention).
- **Newly-quiet case, recorded explicitly:** a plan line of the shape *"the full pytest suite must exit 0; see `tests/test_foo.py` for context"* (bare unscoped `pytest` assertion + separate unrelated `tests/…py` mention on the same line) would previously WARN and now stays silent. This is judged acceptable per (1)–(3) above and is covered as an acknowledged trade-off, not a mechanical pin (writing a test whose EXPECTED behavior is a false negative would encode the trade-off as a hard invariant; the trade-off may later be reconsidered).
- **Alternatives considered:**
  - **Same-sentence bound** (rest-of-line up to the next `.`, `?`, `!`, `;`, or newline): rejected because the reproduction line ends in `.` right after the backticked node id, so a naive `.` boundary would need to whitelist trailing punctuation and the fix loses its main-case coverage. A more elaborate boundary that consumes trailing punctuation adds a new decision (does `example.py` in prose count as a `.` boundary?) without a matching robustness win.
  - **Same-clause bound** (rest-of-line up to the next `,`, `;`, or newline): rejected because the reproduction line contains a `:` inside the prose (`Concrete pytest node id:`) followed by the backtick — commas are not a natural boundary here, and adding `:` as a boundary would truncate exactly the case we want to catch.
  - **Widen `_C38_TAIL_SPLIT_RE` to keep backticks:** rejected because the tail is used by ALL THREE arms (workflow_lint, pytest, ruff); the backtick terminator is load-bearing for arm A (a `\`workflow_lint.py --check-asks\`` inline mention should NOT be classified as an unscoped workflow_lint invocation of `--check-asks`) and dropping it would create new false positives elsewhere.
- **Tool-behavior claims used:** `grep -n '_c38_repo_wide_cmd' scripts/verify_plan.py` → 3 hits (L6702 def, L6781 call site, L6725 comment context — verified above). Existing c38 pin count: 16 (`grep -c 'def test_c38_' tests/test_verify_plan.py` yields the count; verified by listing L8093–L8205 spans in `grep -n 'c38'`).

**Pin-test coverage of the two trade-offs.** The positive case (backticked-node-id line stops WARNing) is pinned by `test_c38_pytest_node_id_in_backticks_does_not_trigger` + `test_c38_pytest_repro_helper_returns_none`. The negative case (bare-`pytest` still WARNs) is pinned by `test_c38_pytest_bare_unscoped_still_warns` + `test_c38_pytest_repro_helper_returns_none`. The newly-quiet trade-off case is intentionally NOT pinned — pinning it would encode the trade-off as an invariant rather than a design choice.
