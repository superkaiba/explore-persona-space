### 4.1 `backends/router.py` — the env knob (requirement 1)

Add next to the other module constants / env helpers (mirror `backend_poll._gcp_queue_wait_seconds` semantics — read at CALL time, fall back on missing/malformed/non-positive):

```python
#: Env knob for the fellows-lane queue-wait cap (#1609 fast-start guard).
#: Read at CALL time so ops can retune without a restart, mirroring
#: EPS_GCP_QUEUE_WAIT_SECONDS (backend_poll._gcp_queue_wait_seconds).
#: Unset/malformed/non-positive -> the caller-supplied default
#: (cfg.free_wait_seconds; production 600 s) — so with the env var unset,
#: behavior is byte-identical to pre-amendment for EVERY lane.
FELLOWS_QUEUE_WAIT_ENV = "EPS_FELLOWS_QUEUE_WAIT_SECONDS"


def _fellows_queue_wait_seconds(default: int) -> int:
    """Fellows queue-wait cap: env knob at call time, else ``default``."""
    raw = os.environ.get(FELLOWS_QUEUE_WAIT_ENV)
    if raw is None:
        return default
    try:
        val = int(raw)
    except (TypeError, ValueError):
        return default
    return val if val > 0 else default


def _park_cap_for_lane(kind: BackendKind, cfg: RouterConfig) -> int:
    """Per-lane park cap: fellows honors EPS_FELLOWS_QUEUE_WAIT_SECONDS."""
    if kind == "fellows":
        return _fellows_queue_wait_seconds(cfg.free_wait_seconds)
    return cfg.free_wait_seconds
```

Call-site edits (the ONLY two `park_until_running_or_cap` call sites):

- `_try_one_free_lane` (`:4754`): `cap_seconds=_park_cap_for_lane(kind, cfg)` (compute once into a local `cap` for reuse in the attempt detail below).
- `_override_free_or_gcp` (`:3939`): same substitution (compute once into `cap`; reuse in the `NoComputeAvailableError` message at `:4096`, which currently interpolates `cfg.free_wait_seconds` — it must state the RESOLVED cap).

### 4.3 `backends/router.py` — pinned-lane exemption (requirement 2)

In `_override_free_or_gcp`, immediately after the park returns and BEFORE the `terminal_before_running` block / cancel state machine (i.e. between `:3971` and `:3973`), insert the fellows-pin branch — scoped to EXACTLY `reason == "park_cap_exceeded"`:

```python
# #1609 fast-start guard, pinned exemption: an explicit `backend: fellows`
# pin may wait indefinitely (pinned = deliberate). On park_cap_exceeded the
# job is confirmed still queued (not terminal, not probe-unknown): do NOT
# scancel — return the live PENDING handle and let the async poll loop
# track it to RUNNING (slurm_monitor maps PENDING->status "running" and
# never stall-classifies PENDING, so the wait is unbounded poll-side).
# Precedent: _override_runpod ("just submit. No park") + the GCP flex
# PENDING handle. Blocking route() past the cap is a non-starter (the
# per-issue flock serializes the tick cron; the CLI would hang).
if kind == "fellows" and reason == "park_cap_exceeded":
    attempts.append(
        RouteAttempt(
            kind=kind,
            cluster=spec.cluster,
            est_start_seconds_raw=None,
            est_start_seconds_clamped=None,
            outcome="pinned_queue_wait",
            detail=(
                f"park cap {cap}s exceeded; pinned fellows job stays queued "
                f"(pinned = deliberate; {FELLOWS_QUEUE_WAIT_ENV})"
            ),
            elapsed_seconds=now_fn() - started_at,
        )
    )
    result = RouteResult(
        backend=backend,
        handle=handle,
        requested_kind=kind,
        chosen_kind=kind,
        reason=ROUTE_REASON_OVERRIDE,
        cluster=spec.cluster,
        attempts=attempts,
        elapsed_seconds=now_fn() - started_at,
        extra={"pinned_queue_wait": True, "park_cap_seconds": cap},
    )
    _post_backend_selected(result, spec=spec, marker_poster=marker_poster)
    return result
```

Scope guards (all deliberate, stated for the critic):

- **`park_cap_exceeded` ONLY.** `terminal_before_running` (job died/stalled/gated in queue) keeps the existing evidence-probe → cancel → `WorkloadSurfacedError`/terminal path; `probe_failures_exceeded` (job state UNKNOWN, transport down) keeps the existing cancel → `manual_attention` path — returning an unknown-state handle as "launched" would lie to the poller.
- **`kind == "fellows"` ONLY.** nibi/fir/mila pins keep today's park→cancel→raise byte-identically (constraint honored; the exemption is fellows-only per the amendment's verbatim scope — see §11 entry 3 for why not generic).
- The handle sidecar was already persisted pre-park (`_invoke_on_launched` at `:3905`), so the returned handle is recoverable by `finalize` regardless.
- The auto path is untouched by this branch (`_try_one_free_lane` never takes it).

## 11. Decision Rationale

1. **Timeout default 600 s.**
   What: `EPS_FELLOWS_QUEUE_WAIT_SECONDS` unset ⇒ cap = `cfg.free_wait_seconds` (production 600 s).
   Why: 600 s is the codebase's already-chosen "how long do we park a queued job before advancing the lane" constant, twice over.
   Source: `router.FREE_WAIT_SECONDS = 600` (`router.py:241`, the pre-#1609 park constant) AND `backend_poll.GCP_QUEUE_WAIT_SECONDS_DEFAULT = 600` (`backend_poll.py:249-256`, which explicitly mirrors it; #783).
   Alternatives: 300 s (faster fall-through, more false cancels on a healthy-but-momentarily-busy queue — plan v3 expects occasional PENDING at the 16-GPU user cap); a fresh literal decoupled from `free_wait_seconds` (rejected: would silently change behavior for tests/configs that tune `free_wait_seconds`).
2. **Layer: route-side (the existing park), not poll-side.**
   What: the guard lives in the two existing `park_until_running_or_cap` call sites; no `backend_poll.py` change.
   Why: the GCP guard is poll-side ONLY because GCP has no route()-time park (route() returns a PENDING flex handle); the SLURM lanes already bound the queue wait synchronously in route() and never return a PENDING handle on a fresh auto submit — so the matching layer is the park. A poll-side fellows guard would duplicate the #783 machinery plus need a new fellows→gcp re-dispatch seam, for zero additional coverage on the auto path.
   Source: `router.py` module docstring `:29-36` + `backend_poll.py:240-276` (read this session).
   Alternatives: poll-side aging + failover (rejected: larger diff, new failure taxonomy, covers only the rare reconnect-to-PENDING residual named in §2).
3. **Knob + exemption scope: fellows-only (not generic per-lane).**
   What: `kind == "fellows"` branches at both sites; nibi/fir/mila byte-identical.
   Why: the amendment names the fellows knob verbatim; the directive's "as long as it starts quickly" is about the fellows lane; a generic per-lane knob/exemption is scope growth touching lanes whose semantics nobody asked to change (and plan v3's must-ask list flags lane-order-semantics changes beyond fellows).
   Source: amendment scope (user-chat, 2026-07-23T03:52Z) + plan v3 §must-ask.
   Alternatives: generic `EPS_SLURM_QUEUE_WAIT_SECONDS_<LANE>` family (rejected: knob creep; trivially added later if wanted).
4. **Pinned-exemption semantics: return the queued handle (async indefinite wait), not block-forever, not keep-bounded-terminal.**
   What: on (fellows pin ∧ `park_cap_exceeded`), skip scancel, return the RouteResult; the poller waits it out.
   Why: "wait indefinitely" inside route() is a non-starter — the park runs under the per-issue flock (a tick-cron re-invocation would serialize behind it forever) and the dispatch CLI is a foreground subprocess; the async poll loop is the component built to wait, and it provably tolerates PENDING indefinitely (`slurm_monitor.py:207-208`, `:465-466`). Keeping today's bounded cancel+raise contradicts amendment requirement 2 outright.
   Source: `_override_runpod` "just submit. No park, no fallback" precedent (`router.py:2255-2259`) + the GCP flex PENDING-handle precedent (#782/#783) + the slurm_monitor reads above.
   Alternatives: cap = ∞ in-route (rejected, flock + CLI wall); leave pins bounded (rejected, contradicts the directive).
5. **No new top-level `ROUTE_REASON_*` constant; `fellows_queue_timeout` rides the attempt detail.**
   What: auto fall-through evidence = the fellows attempt row (`outcome: park_cap_exceeded`, detail carrying `fellows_queue_timeout cap=<n>s`); final reason stays `auto_fallback_gcp`/`auto_started`; pin path adds attempt outcome `pinned_queue_wait`.
   Why: house convention — the final `reason` names the CHOSEN backend/path, per-lane failure evidence lives in `attempts[]` (prepare_failed, launch_failed, boot_loop_rung_skipped all follow it); a new reason constant would force edits to the pairwise reason-distinctness tests without adding machine-readable information the trail lacks.
   Source: `router.py:275-289` reason-constant block + the #1596/#1601 reason-set amendment history (`compute-backend-failover.md` tests-of-record note).
   Alternatives: `fellows_queue_timeout_fallback_gcp` final reason (rejected as above; revisit only if a watcher ever needs to key on it — none does today).
