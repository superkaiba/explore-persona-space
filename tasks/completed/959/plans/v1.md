## 3. Design

### 3a. Design decisions (resolved as instructed)

**Exemption scope — strip ALL `>`-prefixed lines in the scanned footer span (chosen), not a Context-row-scoped walker.**
- The scanned span is footer-only by construction: v4 `_v4_footer_text` (line 2220-2236) returns everything from the first non-fenced `**Repro:**` label to EOF — strictly after `## Results`, so figure-caption blockquotes are never in the span (verified by reading `_v4_footer_start_line`); v3 `section_text(body, "Reproducibility")` is the H2 span, and captions live under `## TL;DR`/`## Results`. Within the span, blockquotes are effectively only the verbatim originating-prompt quote (or a v3 scope-note quote — the same #597 exemption class).
- The Context-row-scoped alternative exists as prior art (`strip_context_blockquotes` in `audit_clean_results_body_discipline.py`, line 403-454, a ~50-line stateful walker with label-boundary detection). That complexity is load-bearing THERE because the audit scans the WHOLE body; here the span is already footer-scoped, so the walker buys nothing and adds boundary-misdetection modes. Mirror the fence exemption's simplicity instead.
- **Protection lost, and why it's acceptable:** an author who put the body's ONLY provenance link inside a footer blockquote would now escape permanence checking. This is acceptable because (i) the identical escape already exists for fenced blocks and has never been abused (the verifier gates cooperative authors, not adversaries); (ii) SPEC mandates pinned artifact links on the non-quoted `**Repro:**` rows and check 7 still hard-requires that label; (iii) checks 9/15/16/17 keep binding on the footer; (iv) clean-result-critic Lens 5 (Footer/Reproducibility) reviews the footer with model eyes every round.
- Nested `> >` lines start with `>` after lstrip — handled for free. Markdown lazy-continuation lines (quote text wrapped without a leading `>`) stay scanned — the failure mode is the PRE-FIX behavior (scanned), never a silently widened exemption; SPEC's recommended shape (and #825's actual quote) prefixes every line.

**Helper placement — new shared module-level helper `_strip_blockquote_lines`, applied after `_strip_fenced_blocks`, at exactly the two URL-check call sites.** Placed adjacent to `_strip_fenced_blocks` (~line 3684) with a comment naming the policy. Check 8b IS structurally affected (verified by reading `_gather_repro_artifact_urls`: it token-scans the same fence-stripped footer text and existence-probes matches; a quoted dead same-repo URL definitively 404s → FAIL), so it gets the same treatment in the same diff.

**Fenced-block interaction — fence-strip FIRST, then blockquote-strip (keeps the existing call shape).**
- Blockquote line inside a real fence: dropped by the fence pass (it drops all in-fence lines regardless of prefix) — already the case.
- Fence inside a blockquote (`> ```` ``` ````): `_strip_fenced_blocks` toggles only on `stripped.startswith("```"/"~~~")` — a `> ```` line starts with `>`, so it does NOT toggle fence state (correct: a quoted fence is content, not structure); the blockquote pass then removes the whole `>` run. Both orders are actually safe; fence-first matches the documented "ALL scans run on fence-stripped text" policy and is pinned by a dedicated interaction test (which would catch a future ordering regression: if a quoted fence marker ever toggled state, the non-quoted URL after it would be silently swallowed).

**v3/legacy vs v4:** the change is made INSIDE the shared check (below `_repro_section_text`), so both body shapes get identical behavior with one code path. Forward-only and strictly loosening — no shipped body can newly FAIL.

### 3b. Concrete diff — `scripts/verify_task_body.py`

**(1) New helper, immediately after `_strip_fenced_blocks` (~line 3697):**

```python
# URL scans over the Reproducibility/footer region ALSO ignore markdown
# blockquote lines (`>`-prefixed, incl. nested `> >`). In that region a
# blockquote is the SPEC-mandated verbatim originating-prompt quote
# (`**Context:**` row — never paraphrased), whose text may cite bare
# URLs the author is not allowed to edit (#825 → task #959). The quote
# is provenance TEXT, not a provenance LINK; pinned artifact links live
# on the non-quoted footer rows, which stay fully checked. Lazy
# continuation lines (quote text wrapped without a leading `>`) stay
# scanned — the failure mode is the pre-fix behavior (scanned), never a
# silently widened exemption. Apply AFTER `_strip_fenced_blocks` (a
# quoted fence marker `> ``` ` must not toggle fence state; it doesn't —
# the fence pass keys on lines that START with the fence marker).
def _strip_blockquote_lines(text: str) -> str:
    """Drop lines whose first non-whitespace character is `>`.

    Returns the remaining lines joined by newlines; used by checks 8 and
    8b so a verbatim-quoted URL is never treated as a provenance link.
    """
    return "\n".join(line for line in text.splitlines() if not line.lstrip().startswith(">"))
```
