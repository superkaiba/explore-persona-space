# Plan v1 — Task #2103: workflow-fix: verify pinned one-off installs resolve + dist-name != import-name

`kind: infra` (workflow-fix; `wf-fix` tag). Workflow-surface prose edit only — no experiment, no pod, no GPU.

## 1. Goal / Requirement

Add a standing rule to `.claude/rules/code-style.md` requiring that any one-off pinned dependency install (`uv pip install <dist>==<ver>` outside `uv.lock`) be verified at authoring time to be (a) RESOLVABLE and (b) the intended DISTRIBUTION — with the dist-name ≠ import-name trap and exact-match test guidance named explicitly. Driving incident: #2061 — `ensure_sparsify()` pinned `sparsify==1.3.3`, a nonexistent version of an unrelated project (PyPI `sparsify` is Neural Magic's deprecated UI; EleutherAI's distribution is `eai-sparsify`), so the install could never resolve and the loader-parity gate died ~2s in on every fresh pod.

### Acceptance criteria

1. `.claude/rules/code-style.md` carries ONE new bullet placed immediately after the sibling identifier-verification rule ("Never hardcode an invented Claude/Anthropic model id", currently line 55), covering all four elements:
   - authoring-time resolvability check (`uv pip install --dry-run '<dist>==<ver>'` or the PyPI JSON API);
   - dist-name-vs-import-name verification with the worked example (`sparsify` = Neural Magic vs `eai-sparsify` = EleutherAI; both import as `sparsify`) and the statement that a successful local import proves neither;
   - preference for a post-install symbol self-check (`uv run python -c "from <mod> import <Symbol>"`) so a wrong distribution fails at install time with a legible message;
   - tests asserting a pin must compare the dist name EXACTLY, never by substring (`eai-sparsify==` contains `sparsify==` — how the wrong name shipped past a green test on #2061).
2. Incident provenance (#2061) recorded in the bullet.
3. `workflow_lint.py` (no-flags) + `--check-asks` introduce no NEW failure lines vs the pre-edit baseline on the touched file; `--check-lessons-index` stays green (a bullet addition does not change the rule's LESSONS.md trigger row — no index edit required).
4. Step 9c test-verdict gate PASS (touched-scope; compare-classified).

A test asserting the pin must parse the dist name and compare it EXACTLY — a substring check cannot tell `eai-sparsify==` from `sparsify==` (the former contains the latter), which is how the wrong pin shipped past a green test (#2061: `sparsify==1.3.3` never existed, so the auto-provision fix could not resolve and the parity gate died on every fresh pod).
