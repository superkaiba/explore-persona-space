### 3.1 Turn-level predicate (design question 1)

**New pure helper `_segment_wake_turns(rows: list[dict]) -> list[tuple[str, float | None]]`** (place next to `_classify_wedge_row`, ~L1750). Segments classified rows into COMPLETED wake-turns, oldest→newest, returning `(outcome, end_ts)` per turn, `outcome ∈ {"ok", "failed"}`:

- A turn starts at a prompt-evidence row (`"dequeue"` / `"prompt"` per the existing `_classify_wedge_row`) and collects the response rows (`"assistant"` / `"api-error"`) that follow; consecutive prompt-evidence rows (possibly interleaved with `"other"`) are one delivery burst, not separate turns.
- A turn is COMPLETED iff it has ≥1 response row; its outcome is the class of its **LAST** response row: `assistant` → `"ok"`, `api-error` → `"failed"` (this is the Goal's "a turn ENDING in isApiErrorMessage is a failed wake even with mid-turn heartbeats"; a mid-turn api-error followed by a successful assistant row in the same turn → `"ok"` — the healthy retried-429 shape).
- A swallowed delivery (prompt evidence, no response rows, then the next delivery) produces NO turn — it neither resets nor increments the turn counters; the existing row-level `run` counter owns that (#779) shape.
- Leading response rows before any prompt evidence (mid-turn tail cut) form one implicit turn.
- `end_ts` = the parsed top-level ISO `timestamp` of the turn's last response row (`None` if missing/unparseable). New tiny helper `_row_ts(row) -> float | None` (ISO-8601 `Z` parse, fail-to-None).

```python
def _segment_wake_turns(rows):
    turns: list[tuple[str, float | None]] = []
    last_resp: str | None = None      # class of latest response row in current turn
    last_resp_ts: float | None = None
    for row in rows:
        cls = _classify_wedge_row(row)
        if cls in ("dequeue", "prompt"):
            if last_resp is not None:          # previous turn completed -> flush
                turns.append(("failed" if last_resp == "api-error" else "ok", last_resp_ts))
                last_resp, last_resp_ts = None, None
            # else: same delivery burst, or a swallowed delivery (no turn emitted)
        elif cls in ("assistant", "api-error"):
            last_resp, last_resp_ts = cls, _row_ts(row)
        # "other": skipped
    if last_resp is not None:                  # flush the final completed turn
        turns.append(("failed" if last_resp == "api-error" else "ok", last_resp_ts))
    return turns
```

An in-flight final turn (prompt delivered, no response yet) is deliberately not counted — it can neither reset nor extend the trailing-failed count (fail toward NO-FIRE on a probe racing a mid-delivery wake).

**New pure function `decide_prompt_wedge_reason(trailing_rows, min_dequeued, *, min_api_errors, min_failed_turns, min_failed_total, rate_window_s) -> str | None`** — returns which trigger fired (`"dequeue-run"` | `"api-error-run"` | `"failed-turn-run"` | `"failed-turn-rate"`, checked in that precedence order) or `None`. Four triggers:

1. **`dequeue-run`** (existing, verbatim): trailing `run >= min_dequeued` over dequeue/prompt rows; **new disable semantics: `min_dequeued <= 0` disables this counter** (needed by the fresh-path caller in §3.2; production stale path unaffected — `_tick_wedge_min_dequeued()` never returns <1).
2. **`api-error-run`** (existing #1104, verbatim): trailing `api_run >= min_api_errors` consecutive api-error rows with no successful assistant row after the first; `min_api_errors <= 0` disables (existing kill switch).
3. **`failed-turn-run`** (NEW — the #1098/#1090 fix): trailing consecutive `"failed"` turns from `_segment_wake_turns` `>= min_failed_turns`; an `"ok"` turn resets. `min_failed_turns <= 0` disables. Default 3 (§11).
4. **`failed-turn-rate`** (NEW — option (c), the c16b10ca shape; §3.3): total (non-consecutive) `"failed"` turns whose `end_ts` lies within `rate_window_s` of the newest parseable row timestamp in the tail `>= min_failed_total` **AND** the newest completed turn is `"failed"`. Turns with `end_ts=None` are excluded from the windowed count; if no row timestamp parses at all, the anchor is undefined and this trigger is inert (fail toward NO-FIRE). `min_failed_total <= 0` disables. Default 6, window default 120 min (§11).

`decide_prompt_wedge(trailing_rows, min_dequeued, *, min_api_errors=..., min_failed_turns=..., min_failed_total=..., rate_window_s=...)` becomes a thin bool wrapper: `return decide_prompt_wedge_reason(...) is not None`. Existing positional/keyword call shapes and all existing test assertions (`is True` / `is False`) remain valid; defaults for the new kwargs = the module constants, so `decide_prompt_wedge(tail, 3)` gains the turn-level triggers too (correct: pure-function callers want the fixed predicate).

**Replay check against the incident shapes** (from the clarifier's structural counts):
- #1098 / #1090 unit `[dq, p, p, assistant×1–3, api-error]` × (8 / 5 wakes): row counters stay run=0, api_run≤1 (pins the old blindness); turn outcomes = failed×8 / failed×5 → trailing ≥3 → `failed-turn-run` FIRES.
- #1074 unit `[dq, dq, p, p, api-error]` × 3: `api-error-run` fires (existing) AND `failed-turn-run` fires (each unit = 1 failed turn) — both lanes agree.
- #779 `[dequeue] × 5`, no responses: zero completed turns → turn triggers silent; `dequeue-run` fires on the stale path (unchanged).
- Healthy `[dq, p, assistant]` cycles, or turns with mid-turn api-error then assistant: all `"ok"` → nothing fires.
- Single refused wake (with 2–4 dq/p rows + up to 3 retry api-error rows in ONE turn): 1 failed turn < 3; rate count 1 < 6; `run` reset by the api-error rows (existing guard); on the fresh path `api-error-run` is disabled (§3.2) so 3 same-turn retry rows cannot trip it → NO FIRE. The single-refusal over-trigger guard is preserved at turn granularity.

### 3.2 Lazy-gate fix (design question 2)

Rewrite the gate in `_apply_prompt_wedge_override` (L9349–9364). Chosen option: **probe every tick, with the fresh-self-report path arming ONLY the turn-level triggers** (a hybrid of the brief's options — "always probe" for evidence classes whose failure mode defeats the staleness clock, staleness-gated for the rest):

```python
if action not in ("keep", "alert") or not respawn_eligible or pids_by_sid is None:
    return action, live_consecutive, wedge_hits, None
stale = self_report_age is not None and self_report_age >= STALLED_WINDOW_S
min_turns = _tick_wedge_min_failed_turns()
min_total = _tick_wedge_min_failed_total()
if not stale and min_turns <= 0 and min_total <= 0:
    # fresh self-report + both turn-level lanes disabled == the pre-#1127 lazy gate
    return action, live_consecutive, wedge_hits, None
sid = entry.get("happy_session_id")
pid = pids_by_sid.get(sid) if isinstance(sid, str) else None
if not isinstance(pid, int):
    return action, live_consecutive, wedge_hits, None
rows = _transcript_tail_rows(pid, max_bytes=262144)
if rows is None:
    return action, live_consecutive, wedge_hits, None
reason = decide_prompt_wedge_reason(
    rows,
    _tick_wedge_min_dequeued() if stale else 0,      # #779 swallow trigger: STALE only
    min_api_errors=_tick_wedge_min_api_errors() if stale else 0,  # row-level: STALE only
    min_failed_turns=min_turns,
    min_failed_total=min_total,
    rate_window_s=_tick_wedge_rate_window_s(),
)
if reason is None:
    return action, live_consecutive, wedge_hits, None
note = f"prompt-wedge trigger [{reason}] in the transcript tail ..."  # names the fired trigger
```

Why this shape (weighing the brief's options):

- **Trigger-matched gating.** The dequeue-run (#779 swallow) and row-level api-error-run (#1074 total-death) shapes both FREEZE the self-report (no turn executes → nothing reaches the full-skill title helper), so the ≥1 h-stale gate opens for them by construction — keeping them staleness-gated preserves #845/#1104 behavior exactly AND keeps the fresh path from firing on a single multi-retry wake (3 api-error rows inside ONE turn must not respawn; §3.1 replay check). The turn-level shapes are the ones where partially-executing wakes CAN keep refreshing the self-report (a wake that escalates into the full `/issue` skill re-writes it at Step 0 before dying — fact-check corrected mechanism, §1) and where even a stale-opened gate found a blind predicate (#1098 post-1 h) — so they get the ungated path — that is the #1127 gap.
- **Cost.** Per tick, per registered session at keep/alert: one happy-log transcript resolution + one 256 KB read + JSON parse (~1–3 ms). Fleet has ~5–15 registered autonomous sessions; the stale-registration and idle-unmapped passes already resolve transcripts fleet-wide every tick, so this matches the watcher's existing cost profile (≤ ~5 MB reads / ~50 ms per tick added). Rejected: (i) *self-report content-unchanged across ticks* — fragile both ways (a dying tick can legitimately vary its text; a healthy long phase can legitimately repeat it), and adds state; (ii) *probe every K ticks* — adds detection latency, saves nothing that matters; (iii) *trailing-bytes pre-scan for the flag substring before parsing* — a micro-optimization on a ~ms parse, and the flag substring false-positives on sessions whose WORK pages this very file into tool-result rows (workflow-fix sessions on the watcher itself); named as the fallback if the timed check in §4 exceeds ~50 ms/session; (iv) *lower the threshold only on prior wedge evidence in the state file* — the evidence read IS the probe, so pre-evidence state buys one tick of laziness for a whole extra state machine.
- **`self_report_age is None`** now routes to the fresh path (turn-level triggers only) instead of no-probe. `respawn_eligible` already excludes manual sessions (the only legitimately self-report-less class); an autonomous session with an unreadable self-report gets turn-level coverage instead of a blind spot. Strictly widens coverage; still fail-toward-NO-FIRE on unresolvable transcripts.
- **All downstream protections untouched:** `respawn_eligible`, the park-exemption re-probe (`_apply_wedge_override_with_exemption_probe` veto), the worktree hold, the stop-verify fence, `RESPAWN_SPAWN_GRACE_S`, `STALLED_MAX_RESPAWNS`, and the auth-outage guard's fleet-wide spawn suppression all still gate the forced respawn.

### 3.3 Option (c) — refusal-rate trigger (design question 3)

**Decision: YES**, as trigger 4 above — c16b10ca lost ~every other wake for ~5.7 h and no consecutive predicate (row- or turn-level) can ever fire on an alternating success/failure storm, while the documented recovery for refusal-poisoned context is exactly the fresh-context respawn; one bounded respawn beats hours at 50 % wake loss.

Conservative containment, per the brief: separate trigger, separate knob + kill switch (`EPM_TICK_WEDGE_MIN_FAILED_TOTAL`, default 6, `0` disables), time-bounded (only failed turns within 120 min of the newest row timestamp — anchored to the newest ROW ts, not wall-clock, so the pure function is deterministic and replay-testable), and additionally gated on the newest completed turn being failed (a session that recovered after a storm is not respawned mid-recovery; on an alternating storm this delays firing by ~1–2 probes in expectation at the 10-min cadence — acceptable vs 5.7 h). The effective window is min(observable 256 KB tail span, 120 min) — on dense transcripts the tail bounds it (~78 min on c16b10ca), which only under-counts (fail toward NO-FIRE).

### 3.4 Tail window (design question 4)

**Verified adequate; no widening.** The clarifier replay measured the production 256 KB tail spanning ~1.3–2.5 h and ≥4 failed wakes on all three incident transcripts — comfortably ≥ the 3-turn consecutive threshold and enough for the 6-count rate threshold (c16b10ca tail held 7 failed turns). Multi-KB refusal rows do compress the span (the Goal's concern), but even the densest incident tail held ≥4 failed wakes. The implementer's replay (§4) re-confirms per-transcript turn counts at 256 KB; if any incident tail were found to hold <4 completed turns the fallback is widening to 512 KB (constant at L9358), not a redesign. A too-thin window fails toward NO-FIRE (unchanged posture).

| False respawn: healthy session whose last 3 wakes each END in one transient api-error row (e.g. a 529 brownout; the brief's named shape) | Low | Requires 3 CONSECUTIVE completed turns all ending in error with zero clean turn-endings between — a mid-turn-retried 429 classifies `ok` (§3.1), so only turn-FINAL errors count; during fleet-wide brownouts the auth-outage guard suppresses all spawn arms; the respawn itself is bounded by `STALLED_MAX_RESPAWNS`, the stop-verify fence, worktree hold, and park exemptions; and a respawned autonomous session re-derives state from markers (bounded cost). Residual accepted + documented in (e). |
| False respawn: rate trigger on a recovered session | Low | Newest-completed-turn-failed condition + newest-row-ts anchor: a session healthy for the trailing stretch cannot fire; failures age out of the 120-min window. |
| Rate trigger fires on a genuinely-degraded-but-progressing session (the deliberate c16b10ca case) | By design | That IS the target: ≥6 turn-ending failures in ≤2 h is the storm shape; fresh context is the documented recovery. Kill switch `EPM_TICK_WEDGE_MIN_FAILED_TOTAL=0` if it proves noisy. |
| Turn segmentation mis-parses real row streams (unknown row types, sidechain rows) | Low | Segmentation consumes `_classify_wedge_row`'s classes only; unknown rows are `"other"` (skipped); acceptance criterion 1 replays the REAL tails before merge; unresolvable input keeps failing toward NO-FIRE. |
| Per-tick probe cost on the fleet | Low | ~5–15 registered sessions × (happy-log resolve + 256 KB read + ~ms parse); consistent with existing per-tick transcript passes; measured in §4.4 with a named pre-scan fallback. |
| A future Claude Code transcript-format drift (flag nesting, timestamp rename) | Low | Existing `_wedge_api_error_row` verbatim fixture already pins top-level flag placement; new tests pin the `timestamp` read; drift fails tests visibly, and missing timestamps only disable the rate lane (NO-FIRE). |
| Rollback | — | Pure env rollback, no redeploy: `EPM_TICK_WEDGE_MIN_FAILED_TURNS=0` + `EPM_TICK_WEDGE_MIN_FAILED_TOTAL=0` restores the exact pre-#1127 gate + predicate behavior (§3.5); `EPM_TICK_WEDGE_MIN_API_ERRORS=0` additionally kills the #1104 lane (pre-existing). Git revert as the last resort. |

## 9. §11 Decision Rationale (thresholds & constants)

- **`TICK_WEDGE_MIN_FAILED_TURNS = 3`** — What: consecutive completed failed wake-turns to trip the fresh-path wedge. Why: ≥2 needed for the single-refusal guard; 3 = one-off + margin, and fires 2–5 wakes into the measured incidents (#1098 tail held 8 failed turns, #1090 held 5). Source: #1104's `TICK_WEDGE_MIN_API_ERRORS = 3` precedent (same construct, coarser granularity) + the #1127 clarifier replay counts. Alternatives: 2 (over-triggery — two coincidental turn-ending transient errors respawn a healthy session), 5 (adds ~20–90 min detection latency and would still fire on both incidents, but at 3 the guard set (§5) already bounds false positives).
- **`TICK_WEDGE_MIN_FAILED_TOTAL = 6`** — What: windowed total failed turns for the alternating-storm rate trigger. Why: c16b10ca's 256 KB tail measured 7 failed turns in ~80 min — 6 fires on the measured incident with margin 1, while a healthy session needs 6 turn-ending failures inside 2 h (≫ any observed healthy rate). Source: measured replay numbers (epm:clarify 2026-07-08). Alternatives: 4 (fires on ordinary API brownouts), 8 (misses the measured incident tail).
- **`TICK_WEDGE_RATE_WINDOW_S = 7200` (120 min)** — What: newest-row-anchored window for the rate count. Why: covers the measured tail spans (1.3–2.5 h) so the tail, not the clock, is usually binding (under-counting only), and matches the house 2 h precedent (`STALLED_MARKER_WINDOW_S_DEFAULT`). Source: #845 (a-i) + the measured spans. Alternatives: 60 min (misses slow alternation), unbounded (a quiet session's tail can span days → stale storms fire).
- **Tail read stays 256 KB** — Source: #1104 §10 deviation + the #1127 measured spans (§3.4). Alternative: 512 KB (only if the replay finds <4 completed turns in an incident tail — it does not, per the clarifier).
- **Fresh path arms turn-level triggers only** — Source: the failure-mode analysis in §3.2 (the two row-level shapes freeze the self-report by construction: #779, #1074) + the single-wake-multi-retry false-positive replay check (§3.1). Alternative: arm all four ungated (rejected — row-level `api_run` can hit 3 inside ONE wake's retries).
- **Trigger precedence `dequeue-run → api-error-run → failed-turn-run → failed-turn-rate`** — What: deterministic reason string for the note/tests. Why: oldest/most-specific evidence first; order does not change WHETHER the wedge fires. Source: cosmetic determinism, no incident.
