## Method delta (what differs from the current mapper)

Current `--map-files` branch (`scripts/select_step9c_tests.py::main()` L1030-1063): pairs = `map_scan_tests(files)` ∪ `rules_pin_pairs(files)`. Nothing reads test-file text for src/scripts payloads; a src module with 18 importing tests maps to zero.

Delta — three additions to the `--map-files` branch only (diff-based selection untouched):

1. **Dependency arms join the map.** A new `dependency_map_pairs(files, work_root)` reuses the EXISTING shared read pass `_scan_test_files()` (import-map #1299 + literal-path #1498, one pass over `tests/**/test_*.py`) and the EXISTING stem-map arithmetic, emitting `(test, matched_path)` pairs for `.py` payloads under `scripts/` or `src/explore_persona_space/` — with `WORKFLOW_INVARIANT` members excluded (mirror of `rules_pin_pairs`' documented asymmetry, L397-401).
2. **Fail-loud floor.** After the union, every eligible code-file payload with zero pairs across ALL arms draws one stderr WARN (tab-free; rc stays 0 — consumers treat helper rc≠0 as crash-class fail-closed, so the floor must not change exit semantics).
3. **Sizing line.** Non-empty maps print `recommended-timeout-s=<T>` to stderr (formula shared with `recommended_timeout_s()` via a new `floor=` kwarg; map-mode floor 300 = today's TG-leg bound), so the Step-10d TG legs can size their pytest bound from the map instead of a fixed 300s that the new fan-out predictably exceeds.

Consumer deltas (minimal, required for the fix to actually fire — justification in §11):

4. **SKILL.md Step-10d TG legs** (forms i/ii block ~L10040/L10052; form iii block ~L11160 + its gated leg): replace the fixed `300s` pytest bound with `TG_T` grepped from the gated map's stderr file (`tg-map-err.txt`), 300s fallback; add NODE-grain NEW-failure subtraction (`FAILED`/`ERROR` node ids, gated − baseline) OR'd into the existing block condition — without it the founding incident runs red and still verdicts `pass`, because file-grain attribution only sees output lines naming a payload path and a unit-test failure names the TEST, not the payload.
5. **No change** to `scripts/inline_lint_gate.py` (its `mapped_pytest_timeout()` already scales with file count, floor 900s — L235-242) or to the diff-based Step-9c path.

## Design

### D1 — `dependency_map_pairs()` (new function, `scripts/select_step9c_tests.py`, placed after `rules_pin_pairs`)

```python
# --- src/scripts dependency arms for --map-files (#1573). ---------------------
MAP_TIMEOUT_FLOOR_S = 300  # Step-10d TG-leg parity floor (SKILL.md measured basis
                           # ~12.6 s for the historical 2-test scan map, 2026-07-08)

def dependency_map_pairs(files: list[str], work_root: Path) -> list[tuple[str, str]]:
    """Sorted (test, matched_path) pairs for --map-files beyond GLOB_SCAN_TESTS
    + rules-pin (#1573): import-map (#1299) + literal-path (#1498) via the ONE
    shared _scan_test_files read pass, plus stem-map path arithmetic.
    WORKFLOW_INVARIANT members are EXCLUDED (rules_pin_pairs asymmetry: they
    already gate every Step 9c run, and exclusion keeps the 900 s
    tests/test_workflow_lint.py out of the Step 10d / inline-payload gates —
    sft.py literal-hits it via workflow_lint's LIVE_WORKFLOW_HELPERS list)."""
    inv = set(WORKFLOW_INVARIANT)
    import_hits, _tested, literal_hits = _scan_test_files(files, work_root)
    pairs: set[tuple[str, str]] = set()
    for hits in (import_hits, literal_hits):
        for t, fs in hits.items():
            if t not in inv:
                pairs.update((t, f) for f in fs)
    for f in literal_path_targets(files):        # same eligibility predicate:
        stem = Path(f).stem                      # .py under scripts/ | src/e_p_s/
        exact = f"tests/test_{stem}.py"
        if (work_root / exact).exists() and exact not in inv:
            pairs.add((exact, f))
        for hit in sorted((work_root / "tests").glob(f"test_*{stem}*.py")):
            rel = f"tests/{hit.name}"
            if rel not in inv:
                pairs.add((rel, f))
    return sorted(pairs)
```

Notes: `literal_path_targets()` (L663-678) is the existing eligibility predicate (`.py` under `scripts/` or `src/explore_persona_space/`, never `tests/`) — reused, not duplicated. `_scan_test_files` existence is implicit (it reads files from disk); the stem arm's `glob`/`exists()` checks match the diff path's semantics. The stem arm is deliberately restricted to the scripts/src eligibility set (the diff path applies it to any `.py`; map mode scopes to the filed gap). Implementer MAY instead extract a shared `_stem_test_hits(f, work_root)` helper used by both the diff path (L876-882) and this function — behavior-preserving, guarded by the existing diff-path pins; either shape is acceptable.

### D2 — `recommended_timeout_s` floor parameter

```python
def recommended_timeout_s(tests: list[str], *, floor: int = TIMEOUT_FLOOR_S) -> int:
    t = TIMEOUT_BASE_S + TIMEOUT_PER_FILE_S * len(tests)
    t += sum(SLOW_TESTS.get(x, 0) for x in tests)
    return max(t, floor)
```

Diff-path callers unchanged (default keyword). The parity pin `tests/test_inline_lint_gate.py:317` (`ilg.PYTEST_TIMEOUT_FLOOR_S == sel.TIMEOUT_FLOOR_S`) is untouched — the constant does not move.

Contract invariants preserved: stdout = 2-field TSV `test<TAB>matched_path`, sorted, one line per pair (the `parse_map_pairs` first-two-fields parser and the SKILL.md `cut -f1`/`cut -f2 | sort -u` consumers need no change); empty stdout + rc 0 = the gate's skip signal; rc 1 only on unreadable input; ALL new lines are stderr and contain NO tab character (a tabbed stderr line would enter `parse_map_pairs` via `_run_leg`'s merged stdout+stderr at the inline gate — asserted by A6's test). `--map-files` mode still never runs git (no fetch — L1065 ordering unchanged).

### D4 — matching granularity: module-exact via the existing resolvers (decided)

Matching reuses `touched_module_names()` (L598-638) + `_import_names()` (L641-660) verbatim — AST `Import`/`ImportFrom` resolution, not regex:

- `src/explore_persona_space/train/sft.py` → module name `explore_persona_space.train.sft`;
- a test's `from explore_persona_space.train.sft import train_lora` → imported names ⊇ {`explore_persona_space.train.sft`} → hit (module-exact);
- the parent-package form `from explore_persona_space.train import sft` → `{"explore_persona_space.train", "explore_persona_space.train.sft"}` via the `M.a` join → hit;
- `scripts/X.py` → flat `X` + dotted `scripts.X` (the `sys.path.insert(0, "scripts")` convention, 174 test files).

Module-exact (not prefix) is correct: prefix matching (`explore_persona_space.train` matching any `train/*` change) would multiply fan-out with no evidence gain, and the parent-package import case is already handled by the `M.a` join above. Documented miss classes carried over unchanged from #1299 (module docstring L65-88): relative imports, `importlib`/dynamic loads, attribute access on a bare `import explore_persona_space`, package-`__init__` re-exports, `conftest.py`, transitive imports (see D6). Raw-text token pre-filter (last dotted component substring) bounds AST parsing exactly as today.

**Symbol-level source-inspection coverage (the Goal's parenthetical), verified 2026-07-20:** `inspect.getsource(X)` requires X importable, so the import arm covers the getsource class whenever the import is STATIC. I AST-sampled all 37 `tests/` files using `inspect.getsource`: every getsource target either (a) statically imports the defining module / symbol → import arm (e.g. `test_artifacts_recipe.py`, `test_watcher_guard_coverage.py`'s module-level `from autonomous_session_watch import ...`), or (b) loads it dynamically (`pytest.importorskip("issue658_fit_predictors")` at `test_issue658_fit_predictors_exactness.py:52`; `importlib.util.spec_from_file_location` at `test_vm_disk_guard_device_fs.py:20`) — invisible to the import arm but in every sampled case the test file is STEM-NAMED after the module → stem arm. This is why the stem arm is IN scope (D1) and not creep: it is the mechanism that closes the dynamic-import getsource subclass. Residual (accepted, documented): a getsource test that is neither stem-named nor statically importing — none found in the sample; `conftest.py` is outside the `test_*.py` scan by existing design.

### D5 — fan-out: NO CAP; size the consumer instead (decided, measured)

Measured on the live tree (2026-07-20, this plan's own runs):

- 262 `src/` `.py` files; 158 have ≥1 importing test; import fan-out median 2, p90 11, max 38 (`task_workflow.py`).
- Proposed union (import+literal+stem, invariants excluded), representative single-file payloads: `orchestrate/hub.py` 35 non-invariant tests, `task_workflow.py` 31 (+10 invariants excluded), `backends/base.py` 24, `train/sft.py` 18 (+2 invariants excluded — incl. the 900s `test_workflow_lint.py` literal hit), typical experiment module 2-6, `analysis/paper_plots.py` 2. A 10-file `eval/` set → 39 tests.
- Consumer timeout arithmetic: Step-10d TG legs run mapped pytest under a FIXED `timeout --kill-after=30s 300s` (SKILL.md L10040, L10052, L11160), sized on a "measured basis ~12.6 s for both mapped tests" (L10206-10208) — i.e. sized for the historical 2-test scan map. At the selector's own calibrated constants (120s base + 30s/file, ~2× p90 — `select_step9c_tests.py` L423-424), any map ≥ 7 tests ((300−120)/30 = 6) predictably exceeds 300s → rc 124 → `TG_CRASH=yes` → verdict `crash` → fail-closed block. Median map (2 tests) is unaffected; sft.py's 18 and hub.py's 35 are not.

Decision: **no cap, warn-free on fan-out; re-size the consumer bound from the map** (D3's sizing line + D7's SKILL.md grep). Rejected alternatives: (a) a cap at 6 ((300−120)/30) guts the fix — sft.py alone has 18 real dependency edges and there is no principled ranking to drop 12 of them; (b) warn-only with the fixed 300s converts the silent false-PASS into a systematic crash-class INCONCLUSIVE on every ≥7-test map — strictly worse operationally than either fixing or not shipping; (c) the mapper is the single source of the map (SKILL.md L10190-10192 "never hardcode the globs") — budget policy belongs to consumers, and the inline gate already implements exactly this pattern (`mapped_pytest_timeout`, count-scaled, floor 900s). Worst-case cost accepted: an hub.py-touching payload sizes each TG leg at 120+30·35 = 1170s ≈ 2×~20 min bound worst case (actual expected run minutes; the bound only fires on a wedge), on a gate that already runs as one background call with 900s lint legs.

### D6 — transitive imports: depth-1 only (decided)

The arm resolves one hop (test imports the touched module), matching the diff path's documented scope ("one hop only", L78). Depth-2 (test → helper H → touched module) requires parsing the import graph of all of `src/`+`scripts/` (~600 more files) per invocation, roughly doubling-to-tripling wall and adding a transitive fan-out explosion (everything reaches `task_workflow.py` in ≤2 hops), for a miss class the diff path also accepts. verify_plan.py c41's docstring records exactly this bounded scope as known behavior (`scripts/verify_plan.py:6750-6752`). Depth-1 misses land in the D3 zero-mapped WARN when the file has no direct coverage at all — visible, never silent.

(ii) **Node-grain NEW-failure subtraction.** After the existing file-grain hits loop (L10075-10083), add:

```bash

  grep -E '^(FAILED|ERROR) ' "/tmp/issue-<N>-tg-$leg.txt" | awk '{print $2}' \
    | sort -u > "/tmp/issue-<N>-tg-$leg-nodes.txt" || true
```

Load-bearing design constants (all grounded on this repo's measurements / consumer arithmetic):

1. **No fan-out cap.** What: emit every dependency pair. Why: a 300s-derived cap is 6 tests ((300−120)/30) vs sft.py's 18 real edges — a cap guts the fix; the mapper is the single source of the map (SKILL.md L10190-10192) and budget policy belongs to consumers. 2. **`MAP_TIMEOUT_FLOOR_S = 300`.** What: map-mode sizing floor. Why: byte-preserves today's TG-leg bound for the ≤6-test maps that dominate (median 2), so the sized bound is a strict superset of current behavior. Source: SKILL.md L10206 ("bounded at 300 s", measured basis ~12.6 s for the historical 2-test map).
