### 4.3 `artifacts/context.py` — dataclass + ONE resolver

```python
CONTEXT_KINDS = ("persona", "query_transform", "prefix", "adversarial", "bare")
INSTALLABLE_KINDS = ("persona", "query_transform", "prefix", "adversarial")

@dataclass(frozen=True)
class Context:
    context_id: str
    kind: str                                       # in CONTEXT_KINDS
    family: str                                     # e.g. house_persona / rephrase / conversational_prefix / adversarial_framing / wildchat / default / testbed_545
    system: str | None = None
    user_wrap: str | None = None                    # "...{q}..." = T(x) transform; must contain "{q}"
    prefix_turns: tuple[Mapping[str, str], ...] = ()  # frozen multi-turn prefix (raw chat dicts)
    adversarial_kind: str | None = None             # e.g. roleplay / hypothetical; kind=="adversarial" only
    source: str = ""                                # provenance note

    def messages(self, question: str) -> list[dict[str, str]]:
        msgs: list[dict[str, str]] = []
        if self.system:                              # truthiness — matches render_chat exactly
            msgs.append({"role": "system", "content": self.system})
        msgs.extend(dict(m) for m in self.prefix_turns)   # shallow copies, ALL keys preserved
        q = self.user_wrap.format(q=question) if self.user_wrap else question
        msgs.append({"role": "user", "content": q})
        return msgs

    def render(self, tokenizer, question: str) -> str:
        return tokenizer.apply_chat_template(
            self.messages(question), tokenize=False, add_generation_prompt=True
        )

    @classmethod
    def from_battery_instance(cls, instance: dict, *, kind: str | None = None) -> "Context": ...
```

**Why this is a superset of the three existing resolvers (judgment call a):**

- `render_chat` = system (truthy) → prefix turns → user. Identical order, identical truthiness
  check, identical `apply_chat_template(..., tokenize=False, add_generation_prompt=True)` call.
- `NegativeContext.messages` user_wrap shape = single wrapped user turn (panel entries with
  user_wrap have `system_prompt=None`, so `messages()` emits exactly `[user]`); system shape =
  `[system, user]`. Both reproduced field-for-field. (The general resolver additionally permits
  system + user_wrap together — a strict superset; parity holds on every actual panel shape.)
- `messages_for_instance` = system (`is not None`) → `prefix_messages` → probe. Truthiness vs
  `is not None` coincide on all validator-legal instances (#594 validation forbids empty-string
  system prompts). Prefix dicts are re-emitted as shallow copies preserving all keys, so
  `==`-equality of message lists holds.

**Validation.** `__post_init__` does the minimal always-safe checks: `context_id` non-empty;
`kind in CONTEXT_KINDS`; `user_wrap` (when set) contains the literal `{q}`;
`adversarial_kind is not None` iff `kind == "adversarial"`. The stricter structural check
`validate_context(ctx)` (prefix turns are `{role, content}`-shaped, roles alternate user/assistant
starting user and ending assistant — the #594 rules) runs on every REGISTRY entry at import time
and in tests, but NOT in `__post_init__`, so the 545 shim can never be broken by an oddly-shaped
committed battery file (the byte-equality contract outranks registry hygiene on that path).

### 4.4 The `render_chat` shim (judgment call a — battery resolution stays in `eval_battery.py`)

```python
# eval_battery.py (only render_chat changes; one private helper added)
from explore_persona_space.artifacts.context import Context

def _context_for_545(context_id: str) -> Context:
    """545 CONTEXTS dict entry -> artifacts Context. Battery resolution stays HERE
    (batteries_dir()/EPM_OUTPUT_ROOT fallback logic is testbed-specific); artifacts/
    stays file-free and never imports behavior_testbed_545 (no cycle)."""
    ctx = CONTEXTS[context_id]
    prefix: tuple = ()
    if ctx.get("prefix_battery"):
        prefix = tuple(load_battery(ctx["prefix_battery"])["prefix_turns"])
    system = ctx.get("system")
    kind = "prefix" if prefix else ("persona" if system else "bare")
    return Context(context_id=context_id, kind=kind, family="testbed_545",
                   system=system, prefix_turns=prefix,
                   source="behavior_testbed_545.columns.CONTEXTS")

def render_chat(tokenizer, question: str, context_id: str) -> str:
    """Thin shim over artifacts.context.Context.render (Phase 0b, task #852).
    Byte-identical to the pre-#852 implementation on every 545 context id
    (regression-pinned by tests/test_artifacts_context.py)."""
    return _context_for_545(context_id).render(tokenizer, question)
```

**Non-obvious design choices (What / Why / Alternatives):**

1. **Shim converts the 545 dict at call time; battery loading stays in `eval_battery.py`.**
   Why: `load_battery` carries testbed-specific root-fallback logic (smoke/v2/EPM_OUTPUT_ROOT);
   moving it into `artifacts/` would create an import cycle and couple the generic package to one
   experiment. Alternatives rejected: (a) registry-level lazy `prefix_battery` field on `Context`
   (leaks a file dependency into the generic spec); (b) a `prefix_provider` callable field
   (unpicklable, unhashable, over-engineered for one context).
   Source: master plan §"target architecture" ("`render_chat` becomes a shim so
   `behavior_testbed_545` is unaffected") + direct read of `eval_battery.py:55-139`.
2. **Lazy (concrete-only) validation for stubs.** Why: the task body mandates TODO placeholders
   that "must not trip the disjointness assert"; an `is_stub` property makes the stub state
   explicit for Phase 0d. Alternative rejected: separate `BehaviorStub` class (two types to keep in
   sync; the registry would need a union type downstream).
3. **`method=None` iff `programmatic=True`.** Why: the task pins `method∈{persona_vector,
   diff_of_means}` while the master plan makes marker/taught_fact organism-only carve-outs with no
   direction extraction; `None` + the invariant check encodes that unambiguously. Alternative
   rejected: a third `"programmatic"` method literal (would suggest a direction-extraction method
   exists for them).
4. **Sub-spec containers + flat property aliases.** Why: the task names both the sub-spec
   dataclasses AND the flat field list from the master plan; properties give downstream phases both
   shapes with one source of truth. Alternative rejected: flat-only (loses the typed
   ExtractionSpec/ElicitationSpec grouping the task explicitly requires).
5. **Fixed literal WildChat-style bare context (judgment call c).** Why: task constraint "no data
   download in this task"; the true WildChat-sampled context is a Phase-1/4 concern.
   Source: task body §"Pinned v1 registry seed" + orchestrator clarification (c).
6. **Parity tests instead of rewiring #664/#594 (judgment call d).** Why: the body requires a
   SUPERSET resolver + the render_chat shim ONLY; `NegativeContext` / `messages_for_instance` keep
   their scripts untouched and Phase 0c promotes negatives properly. The parity tests prove
   representability (the actual requirement) at zero blast radius. `negative_panel()` is not called
   in tests because `_personahub_neg_system_prompt()` reads the gitignored `data/issue594/battery.json`
   (fresh-clone absent — the gitignored-data gotcha); literal-field `NegativeContext` instances
   cover both resolver shapes instead.
7. **`ValueError`-raising validators, not bare asserts.** Why: fail-fast must survive `python -O`,
   and named-overlap errors make Phase-0d fill mistakes diagnosable. Source: project fail-loud rule.
8. **Frozen legacy copy as the byte-equality reference.** Why: after the rewire, old and new
   `render_chat` are the same code path; only a frozen verbatim copy of the pre-#852 body is a real
   reference. FakeTokenizer with an injective serialization proves message-list + flag equality,
   which implies byte-equality under any real chat template; the real-Qwen-tokenizer test is a
   belt-and-suspenders skip-if-uncached variant (offline-deterministic suite per `tests/conftest.py`).
