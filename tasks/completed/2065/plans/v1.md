# Plan — task #2065: flag dirty-tree provenance in reproducibility metadata

## 1. Goal

A result JSON whose `metadata.git_commit` is stamped while the producing script is
dirty-uncommitted must say so, so a committed artifact can never silently claim
provenance from a commit that does not contain the code that produced it.

## 2. Prior work

No directly-comparable prior workflow-fix on this convention exists on-repo. The
closest siblings are:

- `.claude/rules/code-style.md` § "Reproducibility metadata in result JSONs" (line
  89, the CONVENTION being extended). Already carries a lane caveat for git-less
  scratch trees (fellows/SLURM `materialize_branch_src`, incident #1902).
- `.claude/rules/gotchas.md` fellows-cluster and lane-availability entries — the
  degrade path when `git` shells out on a non-git checkout.
- Three near-identical `_git_commit_hash()` helpers exist across shared modules
  (see §4 Design for line numbers) — this task consolidates them and adds the
  dirty-tree flag.
- Task body cites incident #1482 Shapley runs (2026-08-04, `epm:progress v224` on
  #1482): both runs consumed `scripts/issue1482_shapley_blocks.py` while it was
  modified-uncommitted by +369/-40 lines, and the committed K=22 output recorded
  `metadata.git_commit = e3ebc3a79b` — a commit missing 369 lines of the logic
  that produced the figures. The gap: `.claude/rules/code-style.md` has no
  dirty-tree clause (0 grep hits for `git_commit\|reproducibility metadata\|dirty`).

## 3. Acceptance criteria

1. `.claude/rules/code-style.md` § "Reproducibility metadata" carries a
   dirty-tree clause naming the new metadata keys (`git_dirty` +
   `git_dirty_paths`) and the record-and-continue default (never fails loud on
   dirty by default; additive keys only, existing consumers unbroken).
2. A single shared helper module `src/explore_persona_space/orchestrate/provenance.py`
   exports the canonical git-provenance function returning `sha`, `dirty`,
   `dirty_paths`. The three existing near-identical `_git_commit_hash()`
   duplicates in shared modules are consolidated to import/call the new helper
   (or are deleted after rewiring), per `code-style.md` § "Supersede → delete
   the old version".
3. The three CALL SITES that stamp `metadata["git_commit"]` in shared modules
   (see §4) now additionally record `git_dirty` + `git_dirty_paths`.
4. `paper_plots.savefig_paper`'s PDF `Keywords`, PDF `Software`, and PNG
   `pnginfo` "Commit" fields carry the dirty marker (`commit=<sha>+dirty` /
   `Commit=<sha>+dirty`) when dirty.
5. On a git-less scratch tree (fellows/SLURM lane caveat) the helper degrades
   without raising — returns `dirty=None`, `dirty_paths=[]`, and keeps the
   `sha` field's existing degrade shape (`"unavailable-no-git-checkout"` or the
   equivalent per that lane's convention).
6. Unit tests pin all three behaviors: clean tree, dirty tree with a known
   untracked path, git-unavailable lane. Tests use `tmp_path` + a minimal
   `git init` (or a mocked `subprocess.run`) — no real repo mutation.
7. Existing consumers keep working: NO consumer that today reads
   `metadata.git_commit` sees a behavioral change on a CLEAN tree (backward
   compat — bit-identical output when `dirty=False`); the `git_dirty` /
   `git_dirty_paths` additions are additive.
8. `scripts/workflow_lint.py` (no-flags default) passes; ruff on touched files
   passes; the Step 9c test-verdict gate PASSes.

Per-issue scripts (`scripts/issue*_*.py`, ~30 duplicates of `_git_commit_hash`)
are EXPLICITLY OUT OF SCOPE — the task body's constraint. Their behavior is
unchanged; a future infra pass can consolidate them separately.

### 4.1 New shared helper module

`src/explore_persona_space/orchestrate/provenance.py` — new file, co-located

```python
# Pseudocode — implementer writes the real code.
from __future__ import annotations
import subprocess
from dataclasses import dataclass, field

@dataclass(frozen=True)
class GitProvenance:
    """Git-side provenance for a result artifact.

    Fields:
      sha           short SHA of HEAD (e.g. "e3ebc3a79b"), or one of the
                    degraded literals: "uncommitted" (git available but no
                    commit / not a git checkout at all), or the lane literal
                    "unavailable-no-git-checkout" for git-less scratch trees
                    (fellows/SLURM materialize_branch_src copies).
      dirty         bool | None: True if `git status --porcelain` (working
                    tree, unscoped) is non-empty at stamp time; False if
                    empty; None on the git-unavailable lane (do NOT infer
                    False from an errored probe).
      dirty_paths   list of "STATUS path" lines from `git status --porcelain`
                    when dirty=True; empty list otherwise. Capped at ~50
                    entries; a longer set truncates with a trailing sentinel
                    "... (N more)" to bound JSON size.
    """
    sha: str
    dirty: bool | None
    dirty_paths: list[str] = field(default_factory=list)

def git_provenance() -> GitProvenance:
    """Canonical git provenance for reproducibility metadata.

    Fail-soft: never raises. On any subprocess failure returns the degraded
    shape for that failure mode (see GitProvenance.sha field docs).
    """
    sha = _git_short_sha()          # existing three-helper logic, consolidated
    dirty, dirty_paths = _git_dirty_status(sha)
    return GitProvenance(sha=sha, dirty=dirty, dirty_paths=dirty_paths)

def commit_string(prov: GitProvenance | None = None) -> str:
    """One-line human-readable provenance string for non-JSON channels
    (PDF Keywords, PDF Software, PNG pnginfo). Returns "<sha>" when clean,
    "<sha>+dirty" when dirty, "<sha>" (no suffix) when dirty=None.
    """
    p = prov if prov is not None else git_provenance()
    if p.dirty:
        return f"{p.sha}+dirty"
    return p.sha

def as_metadata_dict(prov: GitProvenance | None = None) -> dict:
    """Emit the three metadata fields as a dict that callers merge into their
    result JSON. Shape:
        {"git_commit": <sha>, "git_dirty": <bool|None>, "git_dirty_paths": [...]}
    """
    p = prov if prov is not None else git_provenance()
    return {
        "git_commit": p.sha,
        "git_dirty": p.dirty,
        "git_dirty_paths": list(p.dirty_paths),
    }

def _git_short_sha() -> str:
    """Consolidated from the three existing duplicates. Return short SHA or
    a degraded literal on subprocess failure / non-git checkout. The
    fellows/SLURM lane caveat is handled by returning the existing
    'unavailable-no-git-checkout' literal when EPS_GIT_SHA env is set OR
    when rev-parse fails on a non-git tree (matches the existing lane
    convention documented in .claude/rules/code-style.md).
    """
    # subprocess.run(["git","rev-parse","--short","HEAD"], check=False,
    # capture_output=True, text=True, timeout=5). Return "uncommitted" on
    # non-zero exit / empty stdout / FileNotFoundError / SubprocessError.
    # Prefer EPS_GIT_SHA if set (lane caveat).
    ...

def _git_dirty_status(sha: str) -> tuple[bool | None, list[str]]:
    """Return (dirty, dirty_paths). None on git-unavailable lanes.

    Predicate: `git status --porcelain` unscoped (working tree). Rationale:
    incident #1482's dirty script was the producer itself, but transitive
    imports (src/**, other scripts/**) can also carry uncommitted edits
    that affect the result, so working-tree-wide is the sound scope. False
    positives from concurrent-session unrelated edits are the accepted
    trade-off (the dirty_paths list is auditable — a reader can see which
    paths were dirty).
    """
    if sha in {"unavailable-no-git-checkout"}:
        return None, []
    # subprocess.run(["git","status","--porcelain"], check=False,
    # capture_output=True, text=True, timeout=5). On non-zero exit return
    # (None, []) — treat as git-unavailable rather than "clean by inference".
    # On zero exit: dirty = bool(non-empty stdout);
    # dirty_paths = stdout.strip().splitlines(), capped at 50 entries.
    ...
```

## 7. Risks

1. **Concurrent-session edits inflate `dirty_paths`.** A sibling session's
   untracked scratch file appears in this session's stamp. Accepted trade-off
   — the `dirty_paths` list is auditable and the reader can see what was
   dirty; false positives are safer than the false negatives of a
   per-script-scoped predicate that misses transitive-import edits.
   Mitigation: the cap keeps JSON size bounded.
2. **Performance.** `git status --porcelain` on the EPS repo is <1s on a
   normal working tree; on the ~130 GB `.claude/worktrees/` tree it can be
   slower under MooseFS. The stamp is called once per result artifact
   (paper_plots.savefig_paper: once per figure; convexity_meta and
   organisms: once per JSON write), not in a hot loop. Not a bottleneck.
   Set `timeout=5` on both subprocess calls; degrade to `dirty=None` on
   timeout.
3. **`git` unavailable on fellows/SLURM lanes.** Already handled by the
   existing lane caveat — the helper degrades to `dirty=None` on those
   lanes, matching the existing `unavailable-no-git-checkout` SHA behavior.
4. **Per-issue script duplicates diverge.** Explicitly out of scope for this
   task, but the ~30 `_git_commit_hash()` duplicates across `scripts/**`
   won't automatically pick up the new behavior. A future infra task
   (or an ad-hoc code-review sweep on new scripts) consolidates them; no
   regression risk because their behavior is unchanged.
5. **Backward compat: existing readers of `git_commit`.** Additive keys
   only — every JSON that today reads `metadata["git_commit"]` continues to
   work bit-identically on a clean tree. Verified in the design (§4.3) and
   pinned by `test_backward_compat_clean_tree_git_commit_field_unchanged`.

## 11. Decision Rationale

1. **Consolidate helpers into ONE new shared module** — decision (a) from
   the brief. Three near-identical `_git_commit_hash()` duplicates violate
   `code-style.md` § "Supersede → delete the old version" and drift over
   time; a single import is the sound structural fix. New module
   `orchestrate/provenance.py` avoids circular imports (analysis/artifacts
   import from orchestrate, never the reverse). `Source:` this task body's
   own constraint ("do NOT hand-patch individual per-issue scripts" —
   implies consolidating the SHARED helpers is expected); `code-style.md`
   § Supersede.
2. **Working-tree-wide dirty scope** — decision (b) from the brief. The
   incident (#1482) showed a per-script scope would also have caught THAT
   case (the +369/-40 lines were in the producing script itself), but
   transitive-import cases (a modified `src/**` module the entrypoint
   imports) would silently pass a per-script scope. False positives from
   concurrent-session edits are auditable via `dirty_paths` and are the
   accepted trade-off. `Source:` incident #1482 (task body); working-tree
   scope is the sound superset.
3. **Default = RECORD, never fail-loud** — decision (a) from the brief. A
   fail-loud default would crash every session that has ANY untracked file
   (nearly always the case) and force a workflow rewrite before this task
   could land. Recording the flag is what the task body's constraint
   "Additive metadata keys — must not break existing readers" demands.
   `Source:` task body constraints; the record-and-continue sketch in the
   task body itself.
4. **Non-JSON channels carry the dirty marker** — decision YES from the
   brief. The Goal names "committed artifact", not "committed JSON"; PDF /
   PNG provenance is equally load-bearing (a figure whose PDF Keywords
   claim a clean SHA is as misleading as a JSON claiming the same). The
   `<sha>+dirty` suffix is minimally invasive — a reader who ignores it
   sees the SHA unchanged. `Source:` Goal ("committed artifact"); the
   existing `paper_plots.savefig_paper` metadata format is the natural
   place to extend.
5. **Git-unavailable lane degrades to `dirty=None`** — decision (b) from
   the brief. The lane caveat is a known named convention
   (`.claude/rules/code-style.md` § Reproducibility metadata lane caveat;
   `.claude/rules/gotchas.md`; incident #1902); `dirty=None` (never inferred
   False) preserves the distinction between "clean" and "unknown", so a
   reader can tell the two cases apart. `Source:` `code-style.md` § lane
   caveat; incident #1902.
