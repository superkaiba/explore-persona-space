### Edit A — heredoc-body strip pre-pass (insert after line 189, before the line-194 pre-filter)

Placement rationale: after the `\<NL>` continuation normalization (its interaction is fail-closed — a body line ending in `\` joins with the next line, at worst hiding the terminator ⇒ "unterminated" ⇒ no strip); before the pre-filter and `split_and_label` (bodies may contain `;`/`&&` that would otherwise mis-split).

The exact code, prototype-validated (46 probes + 165 existing tests):

```bash
# (#1058) Strip NON-SHELL-CONSUMER heredoc BODIES before any parsing. The
# newline splitter otherwise treats each heredoc body line as an executable
# clause, so DOCUMENT text that merely MENTIONS a gated form (a python
# heredoc, a cat-written note file) false-blocks. Bash hands a heredoc body
# to the consumer as STDIN DATA — it is executed only when the consumer is a
# shell interpreter. Fail-closed ladder (any doubt -> NO strip, current
# behavior): strip only when EVERY opener in the command (a) has a word-shaped
# tag ([A-Za-z_][A-Za-z0-9_]*), (b) is the only opener on its physical line,
# (c) has a terminator line exactly == tag (leading tabs allowed for <<-),
# (d) the opener LINE carries NO shell-consumer / command-runner word
#     (bash|sh|zsh|ksh|dash|eval|source|ssh|xargs|parallel|sudo|su), and
# (e) the opener LINE does not redirect into a *.sh path.
# Here-strings (<<<) are masked before detection and never match.
strip_heredoc_bodies() {
  printf '%s' "$1" | awk '
    function shellish(line) {
      return (line ~ /(^|[^A-Za-z0-9_.])(bash|sh|zsh|ksh|dash|eval|source|ssh|xargs|parallel|sudo|su)([^A-Za-z0-9_]|$)/)
    }
    # Returns 1 and sets TAG/DASH when line has exactly one valid opener;
    # 0 = no opener; -1 = opener present but unstrippable (fail to no-strip).
    function opener(line,   tmp, rest, op) {
      tmp = line
      gsub(/<<</, "\x02", tmp)
      if (tmp !~ /<</) return 0
      if (match(tmp, /<<-?[ \t]*\\?[\x22\x27]?[A-Za-z_][A-Za-z0-9_]*[\x22\x27]?/) == 0) return -1
      op = substr(tmp, RSTART, RLENGTH)
      rest = substr(tmp, RSTART + RLENGTH)
      if (rest ~ /<</) return -1
      if (shellish(line)) return -1
      if (line ~ /(>|>>)[ \t]*[^ \t]*\.sh[\x22\x27]?([ \t]|$)/) return -1
      TAG = op
      sub(/^<<-?[ \t]*\\?[\x22\x27]?/, "", TAG)
      sub(/[\x22\x27]$/, "", TAG)
      DASH = (op ~ /^<<-/) ? 1 : 0
      return 1
    }
    function terminator_at(j,   b) {
      b = buf[j]
      if (DASH) sub(/^\t+/, "", b)
      return (b == TAG)
    }
    BEGIN { n = 0 }
    { buf[n++] = $0 }
    END {
      # PASS 1: validate; on ANY unstrippable opener emit input unchanged.
      i = 0; ok = 1
      while (i < n) {
        r = opener(buf[i])
        if (r == -1) { ok = 0; break }
        if (r == 1) {
          j = i + 1
          while (j < n && !terminator_at(j)) {
            # A body that itself SHELLS OUT (os.system / subprocess / Popen)
            # may execute git despite a non-shell consumer -> refuse to strip
            # (fail-closed; harmless unless a gated form also appears).
            if (buf[j] ~ /(os\.system|subprocess|Popen|check_call|check_output|getoutput)/) { ok = 0; break }
            j++
          }
          if (!ok) break
          if (j >= n) { ok = 0; break }      # unterminated -> no strip
          i = j + 1
          continue
        }
        i++
      }
      if (!ok) { for (k = 0; k < n; k++) print buf[k]; exit }
      # PASS 2: emit, dropping each body + terminator (opener line kept).
      i = 0
      while (i < n) {
        r = opener(buf[i])
        print buf[i]
        if (r == 1) {
          j = i + 1
          while (j < n && !terminator_at(j)) j++
          i = j + 1
          continue
        }
        i++
      }
    }'
}
cmd=$(strip_heredoc_bodies "$cmd")
```

Design notes on the ladder, each verified by a probe:
- **All-or-nothing validation** (pass 1 bails whole-command on any doubt): a command mixing a strippable python heredoc and a bash heredoc keeps *current* behavior entirely — simplest correct fail-closed composition.
- **Opener line is always kept and classified** — `git checkout -b x && python - <<PY` still blocks (probe B17); text after the terminator still classifies (B18).
- **Shell-consumer word check on the opener LINE, not the clause** — deliberately catches `cat <<EOF | bash` (the consumer lands in a different clause after the `|` split; the physical line catches it — probe B3). The dot-excluding before-class `[^A-Za-z0-9_.]` means path tails like `guard_repo_root_branch.sh` / `new_worktree.sh` in *body prose* never suppress a strip (probe E6) while `bash`/`sh` as real command words do.
- **`os.system`-family body refusal**: closes the "python heredoc that shells out a *space-separated* git string" fail-open (probe E1 blocks). The argv-form `subprocess.run(["git","checkout",…])` is invisible to the raw scan **today too** (verified against the unpatched guard: rc=0) — parity, not a new gap (probe E2).
- **`.sh`-redirect refusal** closes the most likely accidental write-then-execute path (probe B5).
- **Here-strings `<<<` masked** before detection (probe A3); a `<<` with a non-word tag (e.g. python's `1 << 2` shift in a `-c` string) returns −1 ⇒ no strip ⇒ current behavior.

### Edit B — `$WT` cd-latch (in the while loop; `wt_bound=0` init beside `scoped=0` at line ~421; two blocks inserted between the literal cd-latch at lines 466–470 and the `[ "$scoped" -eq 1 ]` check at 471)

```bash
  # (#1058) A CLAUSE-INITIAL `WT=<...>.claude/worktrees/<...>` assignment
  # (optionally `export`-prefixed) arms the $WT latch for LATER clauses.
  # Clause-initial only: a `WT=` fragment buried in quoted prose (an echo /
  # --note argument) must never arm it. A literal assignment cannot fail at
  # runtime, so stream order == execution order for arming purposes.
  if echo "$clause" | grep -qE '^(export +)?WT=[^;&|[:space:]]*\.claude/worktrees/'; then
    wt_bound=1
  fi

  # (#1058) `cd "$WT"` — the SKILL.md-conventional worktree variable — latches
  # ONLY when an EARLIER clause in this SAME command bound WT to a
  # `.claude/worktrees/` path (shell state never persists across Bash tool
  # calls, so a non-empty $WT implies a same-call assignment). The
  # assignment check is LOAD-BEARING, not cosmetic: bash `cd ""` SUCCEEDS as
  # a no-op (verified 2026-07-05, bash 5.1.16), so with an UNSET WT
  # `cd "$WT" && git ...` runs the git clause in the UNCHANGED cwd (the repo
  # root) — a bare `cd "$WT"` latch would be fail-open. With the assignment
  # present, every quoting variant is safe under the && latch: expanded
  # forms cd into the worktree; a single-quoted literal `cd '$WT'` fails
  # (no such dir) and && short-circuits the git clause. A `..` anywhere in
  # the cd arg never latches (fail-closed).
  if [ "$wt_bound" -eq 1 ]; then
    cdarg=$(echo "$clause" | sed -nE 's/^cd +([^;&|]+)[[:space:]]*$/\1/p' | tr -d '\042\047')
    case "$cdarg" in
      *..*) : ;;
      \$WT|\${WT}|\$WT/*|\${WT}/*)
        scoped=1
        continue
        ;;
    esac
  fi
```

Design notes, each verified by a probe:
- The latch sets the SAME `scoped` flag as the literal latch ⇒ inherits the `&&`-only propagation + reset semantics verbatim (probes B13 `;`, B14 `||` block).
- **Clause-initial assignment + stream-order arming** (not a raw-`$cmd` grep): the first prototype grepped the raw command and probe F5 exposed it — `echo "docs: WT=.claude/worktrees/example"` armed the latch for an unrelated unset-`$WT` cd. The `wt_bound` in-loop design blocks F5 while keeping F1 (single-quoted RHS), F2 (`export` form), I1-3 (the incident shape) allowed.
- Tight to the variable name `WT` (SKILL.md's convention — the only name in all five incidents); `$WT2` etc. fail closed (F3). `cd -P "$WT"` fails closed (F4). Optional `/subpath` allowed, any `..` refused (B12 blocks, A8 allows).
- Comment tails are already stripped before this point in the loop (the #897 strip at line ~459), so a tail cannot spoof the cd-arg or the assignment (assignment check is prefix-anchored; a tail after a real assignment is harmless, a comment-only clause starts with `#` and is skipped earlier).

2. **`$WT` latch requires a clause-initial same-command assignment, armed in stream order.** *Why:* `cd ""` succeeds as a no-op (verified live 2026-07-05, bash 5.1.16 — the pivotal probe), so a bare variable latch is fail-open; shell state never persists across Bash tool calls (harness contract, SKILL.md:7309), so a real `$WT` implies a same-call assignment; a raw-command grep was built first and *falsified by probe F5* (prose-buried `WT=`), driving the clause-initial stream-order design. *Source:* live probes F1–F5, B10–B14; #804 latch semantics (guard lines 134–165, 409–430). *Alternatives:* bare `cd "$WT"` latch (rejected — fail-open, F5/B10); generic any-variable latch with name capture (rejected — larger audit surface, zero incident demand); no latch, `git -C`-only (rejected — leaves the 3× recurring incident class unfixed).
3. **Heredoc strip = line-granular, all-or-nothing, consumer-gated, before clause-split.** *Why:* bash delivers heredoc bodies as stdin DATA except to shell interpreters; the strip point (post-continuation-join, pre-split) keeps body separators from mis-splitting; all-or-nothing validation is the simplest composition that can never partially strip; opener-LINE consumer detection catches `| bash` across the coming clause split. *Source:* bash semantics verified by probes B1–B9, E1–E10; guard residual gap (iii) (lines 102–103); the #897 comment-tail precedent ("remove what bash won't execute", lines 80–92). *Alternatives:* clause-level (post-split) handling (rejected — bodies mis-split first); consumer allowlist instead of denylist (rejected — unbounded false-block surface for python/cat/jq/tee, the incident consumers); no `os.system` body refusal (rejected — E1 demonstrated a real new fail-open).
4. **Consumer denylist = `bash|sh|zsh|ksh|dash|eval|source|ssh|xargs|parallel|sudo|su`.** *Why:* the mandated set plus command-runners that execute stdin/args (`xargs -I{} {}`, `parallel`, `sudo -s`, `su`) — each a cheap fail-closed addition with near-zero false-positive cost (checked only on opener lines, which are commands, not prose). *Source:* bash/xargs/sudo semantics; probes B1–B4, B8–B9, E10. *Alternatives:* docker/kubectl exec wrappers (rejected — their shell is already caught via the `bash`/`sh` word; containers don't mount the shared root here).
5. **Instance 5 stays a documented limitation.** *Why:* #796 revert precedent bans the quote-strip; a task.py-clause waiver is fail-open under `--note "$(git …)"` command substitution; the `--file` workaround is designed, message-advertised, and worked in the live incident; the heredoc fix newly un-blocks the `cat <<EOF > note.md` path to that workaround. *Source:* guard header lines 51–78 (#796 round-2 report); incident 5 recovery record in the clarify marker. *Alternatives:* narrow quote-strip for `--note`/`-m` only (rejected — same #796 leak class), task.py clause waiver (rejected — `$(…)` fail-open).
6. **`git -C` waiver untouched.** *Why:* the designed override; both fixes compose with it rather than replacing it. *Source:* guard line 474. *Alternatives:* tightening it to reject `-C $REPO_ROOT` (out of scope — a distinct bug deserving its own `(target_file, fingerprint)` task per the workflow-fix dedup rule).
7. **New tests appended to the existing file, existing harness.** *Why:* 773-line file with established `_run`/`@on_main`/parametrize conventions and section banners; the Step 9c selector maps the touched guard to this file. *Source:* tests/test_guard_repo_root_branch.py:1–120 read. *Alternatives:* new test file (rejected — splits the pinned-behavior record).
