#### 4.1 Scope decision (a): token surface + grammar

**Decision: structured note tokens on EXISTING marker kinds — no new `epm:` kind.** Precedent: the note-token convention is the established "no marker-schema change" channel (`fix_sha=`, `pid=`, `pod=`, `outroot=`; `.claude/rules/crash-fix-rounds.md` § Crash-fix relaunch: "note-token convention, same class as `pid=` / `commit=` — no marker-schema change"). A new marker kind would be a public-contract change (workflow.yaml § markers + halt-criterion 3 adjacency) with no added power: the guard needs newest-wins per-pod token lookup, which notes already support.

Two tokens, grammar exact:

- **`owner=<token>`** — owner-attribution evidence. `<token>` matches `[A-Za-z0-9._-]{1,64}`. Parser regex: `(?<![\w-])owner=([A-Za-z0-9._-]{1,64})`; on JSON-shaped notes, the top-level `"owner"` field (dual parse mirroring :3445-3469, critique C1). Recommended token value: `<agent-or-session-slug>-<issue>` (e.g. `spec-ladder-2054`); the guard checks only string EQUALITY between registration and PASS. **Two roles, deliberately asymmetric:** (i) REGISTRATION — emitted on the `epm:run-launched` note beside the already-required `pod=<name>` lead token, optionally refreshed on `epm:progress` notes naming the pod; registration is KIND-SCOPED to exactly `{epm:run-launched, epm:progress}`, so a token on an `epm:upload-verification` note can NEVER register or update ownership (otherwise the incident's harvester could mint its OWN token on its self-posted PASS, self-register, and pass the equality check by construction — the self-registration hole); (ii) CLAIM — emitted by the OWNER on its own `epm:upload-verification` PASS note, compared against the registration, never written into it. `owner=` on a PASS is a FIRST-PERSON identity claim: the token YOUR session posted on the `epm:run-launched` marker when YOU launched this run; emit it ONLY then (critique M1 fix 2 — never "matching the launch signal", which reads as a lookup-and-copy instruction). Collision check: repo-wide grep for `owner=` hits only `scripts/gh_project.py` GitHub-CLI arg composition (not marker notes) — surface free.
- **`fence_until=<value>`** — owner work-fence deadline. `<value>` is UTC ISO-8601 `YYYY-MM-DDTHH:MM(:SS)?Z`, or the literal `none` (clears the fence). Parser regex: `(?<![\w-])fence_until=([0-9T:Z.-]{1,32}|none)`, then strict `datetime.strptime` (both `%Y-%m-%dT%H:%M:%SZ` and `%Y-%m-%dT%H:%MZ`); an unparseable value ⇒ treated as ABSENT + one stderr WARN naming the malformed token (fail-open per hard constraint). Emitted on `epm:run-launched` and refreshed/cleared via `[long-phase-heartbeat]` `epm:progress` notes carrying `pod=<name>`; read from the same registration kind-scope as `owner=`. Fences carry the SHORTEST honest deadline and are refreshed via the existing heartbeat duty — never posted long "to be safe" (the C4(ii) accepted-cost mitigation, mirrored into the emitter prose). Collision check: `fence_until` has zero repo hits today; `fence=` (experimenter provider-fence field) is not matched by the new regex (the `(?<![\w-])` guard rejects compounds, and `fence_until=` does not contain the substring `fence=`), and no machine consumer of `fence=` exists to mis-read `fence_until=` (experimenter.md prose only — verified by grep, §11).

**Pod keying:** a token binds to pod P iff its note names P in the #1961 structured position — boundary-safe `pod=<P>` token anywhere in the note, OR P as the note's leading token (copy of the `autonomous_session_watch.py:13442` pattern, cross-ref comment, no import); on JSON-shaped notes, the top-level `"pod"` field. **Evidence window:** tokens are read newest-wins from events whose `ts` ≥ the newest `epm:run-launched` naming P (the launch event included); if no run-launched names P, the window is the whole log. This prevents a stale fence — or a stale PASS — from a PRIOR `pod-<N>-<slug>` incarnation binding a re-provisioned same-name pod.

**Pod-bound PASS selection (critique C2):** the PASS consulted for pod P is selected per-pod, newest-first over `epm:upload-verification` events in P's evidence window whose note records PASS (`_note_records_pass`): (tier 1) the newest PASS explicitly bound to P (`pod=<P>` token / JSON `"pod": "<P>"` / P as leading token); (tier 2) if none, the newest PASS carrying NO pod binding at all (today's shape; graduated-adoption fallback). A PASS bound to a DIFFERENT pod is SKIPPED — it can neither waive P's fence nor displace P's own pod-bound PASS. Named residual: two pod-LESS PASSes from different rounds still contend at tier 2 (newest wins) — closed as emitters adopt `pod=` on PASS notes (the §4.3 recipe adds it), stated in §8.

#### 4.2 The new guard

New function in `scripts/pod_lifecycle.py` (placed after `_guard_keep_running_before_terminate`):

```python
def _guard_owner_fence_before_terminate(
    issue: int, pod_names: list[str], *, force_flag: bool, dry_run: bool
) -> None:
    """Refuse to destroy a pod carrying an UNEXPIRED owner fence unless the
    latest POD-BOUND upload-verification PASS carries the pod's matching
    owner= token (#2277; incident 2026-08-13 pod-2054-tiers). Evidence-gated:
    pods with no owner=/fence_until= tokens proceed exactly as before this
    guard existed. Owner/fence REGISTRATION is kind-scoped to
    epm:run-launched / epm:progress — a PASS note can never register
    ownership. ADDITIVE to the #444/#2187 upload-verification guard and the
    #1485 keep-running shield; unlike #1485 it does NOT exempt the
    --name-suffix surgical path (the incident's path). Kill switch:
    EPM_DISABLE_OWNER_FENCE_GUARD=1 (rollback lever, fail-open)."""
    if os.environ.get("EPM_DISABLE_OWNER_FENCE_GUARD") == "1":
        return
    if dry_run:
        print("[dry-run] NOTE: a real run would check each pod's owner "
              "fence_until=/owner= tokens and REFUSE if an unexpired fence "
              "exists without an owner-matching PASS.", file=sys.stderr)
        return
    try:
        from explore_persona_space.task_workflow import list_events
        events = list_events(issue)   # the guard's ONLY full-log read (OC-4)
    except (ImportError, FileNotFoundError, RuntimeError, ValueError) as exc:
        print(f"[pod_lifecycle] WARN: owner-fence guard skipped for issue "
              f"#{issue} ({type(exc).__name__}). Proceeding.", file=sys.stderr)
        return
    now = datetime.now(timezone.utc)
    for name in pod_names:
        window = _pod_evidence_window(events, name)          # new pure helper
        owner_reg = _latest_pod_token(window, name, "owner") # kind-scoped (§4.1)
        fence = _latest_pod_fence_until(window, name)        # kind-scoped; None
                                                             # if absent/'none'/
                                                             # unparseable(WARN)
        pass_owner = _latest_pass_owner_for_pod(window, name)  # pod-bound (§4.1),
                                                               # JSON+prose (C1)
        if fence is not None and fence > now:
            if owner_reg is not None and pass_owner == owner_reg:
                continue  # owner tearing down its own verified pod: ask-free
            if force_flag:
                print(f"[pod_lifecycle] WARN: terminating {name} DESPITE an "
                      f"unexpired owner fence (fence_until={fence.isoformat()}, "
                      f"owner={owner_reg!r}, pass owner={pass_owner!r}) because "
                      f"--force-owner-fence was passed.", file=sys.stderr)
                continue
            raise SystemExit(
                f"REFUSED: pod {name} (issue #{issue}) carries an UNEXPIRED "
                f"owner fence (fence_until=..., owner=..., PASS owner=...). "
                f"A live owner may still be mid-run (#2277; 2026-08-13 "
                f"pod-2054-tiers). Non-owner route: SURFACE the pod for "
                f"approval — post a marker + push naming the pod and its "
                f"hourly burn, leave it alive (.claude/rules/pods.md "
                f"§ Completion-side teardown) — or wait for the fence to "
                f"expire / the owner to post fence_until=none. While this "
                f"fence is unexpired, a session that did not post it MUST "
                f"NOT copy the owner= token into a PASS — the owner is "
                f"presumed alive. Owner route (ONLY if YOUR session posted "
                f"this pod's launch signal / fence): re-post the PASS "
                f"carrying the owner=<token> YOUR session registered at "
                f"launch, plus pod={name}. Deliberate override: re-run with "
                f"--force-owner-fence (recorded reason)."
            )
        elif owner_reg is not None and pass_owner not in (None, owner_reg):
            # attribution mismatch with NO active fence: visible, non-blocking
            print(f"[pod_lifecycle] WARN: upload-verification PASS owner="
                  f"{pass_owner!r} does not match pod {name}'s registered "
                  f"owner={owner_reg!r} (no active fence — proceeding; #2277).",
                  file=sys.stderr)
```

#### 4.3 Scope decision (b): emitter-side adoption in THIS round

A predicate reading a token nothing emits is inert (`.claude/rules/workflow-fix-on-bug.md` § built-but-stranded fixes). This round lands the token conventions on the four emitter surfaces that produce/consume the markers, paired so no surface learns fence-posting without the matching PASS-owner duty (else its own teardown would refuse on its own fence).
