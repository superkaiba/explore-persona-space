## 5. Design

### 5.1 New file: `scripts/step10d_guards.sh`

One bash script, `set -euo pipefail`-free at top level (guards must report, not die silently — each guard manages its own error state), invoked per-guard so the caller composes exactly the guards it wants:

```
scripts/step10d_guards.sh <issue-number> --guard prelude
scripts/step10d_guards.sh <issue-number> --guard 0
scripts/step10d_guards.sh <issue-number> --guard 4 [--main-sha <sha>]
```

**CLI contract:**
- `<issue-number>`: positive integer; the script derives `WT="$REPO_ROOT/.claude/worktrees/issue-<N>"` internally and fails loud (exit 2, `ERROR=worktree-missing`) if the worktree does not exist for guards 0/4.
- `--guard {prelude|0|4}`: exactly one per invocation. Unknown guard id → exit 2 with usage on stderr.
- `--main-sha <sha>` (Guard 4 only, optional): the pinned `MAIN_SHA` from the caller's Guard 1 run. When absent, Guard 4 computes the merge-base itself (`git merge-base HEAD origin/main` in `$WT`) — matching the digest's description of Guard 4 as self-contained on execution.
- Environment: `EPM_SKIP_LOST_UPDATE_GUARD=1` is honored by `--guard 4` (prints `GUARD4=skipped` and exits 0) — the kill switch survives extraction byte-equivalent in effect.

**Output grammar (the cross-guard state-passing mechanism):** all state the caller needs is emitted as `KEY=VALUE` shell-assignment lines on **stdout**, one per line, values shell-safe (sha/word/`yes|no` tokens only — no user text on stdout; diagnostics go to stderr). The caller consumes via:

```bash
eval "$(uv run bash scripts/step10d_guards.sh <N> --guard 0)"
# now $MEM_COMMITTED is set in the caller's shell
```

Per-guard emitted keys:

| Invocation | stdout keys | exit code semantics |
|---|---|---|
| `--guard prelude` | `REPO_ROOT=...`, `WT=...` | 0 always (derivation failure → exit 2, nothing on stdout) |
| `--guard 0` | `MEM_COMMITTED=yes\|no` | 0 on success (committed or clean-noop); 2 on infra error (worktree missing, commit failed) |
| `--guard 4` | `GUARD4=pass\|refused\|skipped`, and on refusal `LOST_UPDATE_PATHS=<space-joined paths>` | 0 on pass/skipped; **1 on refusal** (the caller's `eval "$(...)"` captures the keys; the caller checks `$GUARD4` — see refusal-semantics note below); 2 on infra error |

**Refusal-semantics note (behavior preservation for Guard 4):** the current prose refuses by echoing `LOST-UPDATE REFUSAL (Guard 4)` and evaluating `false`. Under extraction, the script prints the refusal banner **verbatim** (`LOST-UPDATE REFUSAL (Guard 4)`) to stderr, emits `GUARD4=refused` + `LOST_UPDATE_PATHS=...` on stdout, and exits 1. Because `eval "$(cmd)"` in the caller does not propagate `cmd`'s exit status usefully across all shells, the SKILL.md replacement block uses the two-step form so refusal semantics stay byte-equivalent in effect:

```bash
GUARD4_OUT=$(uv run bash scripts/step10d_guards.sh <N> --guard 4 --main-sha "$MAIN_SHA"); GUARD4_RC=$?
eval "$GUARD4_OUT"
[ "$GUARD4_RC" -eq 1 ] && false   # refusal: same halt the prose produced
```

(Embedded-shell exit-path trace: the refusal arm's `false` sits at the tail of the SKILL.md block exactly where the prose's `false` sat — it halts the merge attempt at the same point; the `--guard 0` and `--guard prelude` blocks have no failure-halt arm beyond exit-2 infra errors, which the caller surfaces as a merge-fail per the existing Step 10d error handling. No bare `false` inside a subshell/branch that fails to halt a sibling block is introduced: each replacement block is a single fence with its own tail check.)

### 5.2 Guard bodies (behavior-preserving transcription)

- **PRELUDE**: exactly the digest's two lines — `REPO_ROOT=$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)")`; `WT="$REPO_ROOT/.claude/worktrees/issue-$N"`. The script IS the canonical spelling of `--path-format=absolute`, which retires the #1867 typo class for this fragment.

Idempotent by construction (clean pathspec → no).

## 11. Decision Rationale

- **The a/b/c/d call → (b).** What: staged extraction of PRELUDE + Guard 0 + Guard 4. Source: `/tmp/issue-1978-step10d-digest.md` (structural facts) + task #1978 body (staging directive) + #1867 (trigger evidence).
- **Guard selection (0 + 4, not 1).** What: extract the two EASY guards even though Guard 1 hosted the actual typo. Why: Guard 1 exports three variables (`STRIPPED_FOREIGN`, `MAIN_SHA`, `GUARD1_STATE`) consumed by four downstream blocks including ones NOT being extracted (merge-conflict recovery, artifact-confirmed merge) — a partial interface there risks exactly the behavior drift the invariant bans; the PRELUDE extraction independently removes the typo'd fragment. Source: digest state-passing table.
- **`KEY=VALUE` stdout + `eval` capture (vs sourced fragment).** What: per-guard invocation emitting shell assignments. Why: the digest names both designs; the `eval "$( )"` form keeps the script a normal executable (testable via subprocess, shebang-pinned bash) while a `source`d fragment would execute in the caller's shell with uncontrolled variable bleed and no exit-code boundary for Guard 4's refusal. Source: digest § State-passing coupling (names both options); the two-step rc-capture form is this plan's addition to preserve refusal semantics under `eval`.
- **`--main-sha` optional on Guard 4.** What: accept the pinned sha, self-compute when absent.
