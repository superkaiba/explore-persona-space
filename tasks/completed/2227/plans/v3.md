## 2. Method delta (what is new vs existing checks)

TWO coupled changes:

**(i) One new trigger sub-arm inside the existing arm (b)** — a **line-windowed co-occurrence** trigger, not a bare-token fold: an `evil`/`toxic` token counts as harm-class vocabulary ONLY when it co-occurs on the same line as banding/judging/severity vocabulary. This respects the documented rejection of bare `\bevil\b` (saturates persona-vector trait prose) while catching the #2221 shape, where "evil" and "judged"/"graded"/"severity"/"band" co-occur on the DV-defining lines (v5 co-fires on 6 lines: L11/123/172/235/397/405).

**(ii) Tighten the `stop_reason`+`refusal` co-mention satisfier to value-position refusal** (critic round-1 blocker): the current form `"stop_reason" in low and "refusal" in low` accepts any line where both substrings appear — including the rule-9/rule-26 boilerplate on #2221 v5 L103, which names CONTENT-drop handling (rubric REFUSAL returns) and the parse pilot gate, neither of which is api-refusal accounting (rule 28's own non-coverage note). The tightened form requires `refusal` in the VALUE position of a `stop_reason` comparison/assignment. Mechanically verified: the existing pin fixture (`stop_reason == "refusal"`) still satisfies; v5 L103 does not; v5 has zero tight-satisfier hits and zero `api[-_ ]refusal` tokens.

No change to arm (a), the `api[-_ ]refusal` token satisfier, the escape, or the check's polarity/registration.

Note on the documented rejections (docstring): bare `\bevil\b` stays rejected; the prior rejection of "judge-proximity tuning" was about SUPPRESSING benign fires of the existing vocabulary — using proximity to ADMIT a new trigger arm without false positives is the complementary direction and is what the task body prescribes. The docstring is re-scoped to state both.

## 3. Design (concrete)

New module-level regex (adjacent to `_C53_HARM_VOCAB_RE`):

```python
# Trigger arm (b2) — line-windowed evil/toxic (#2227, the #2221 silent pass).
# Bare \bevil\b stays REJECTED (saturates persona-vector trait prose); an
# evil/toxic token is harm-class vocabulary ONLY on a line that also carries
# banding/judging/severity vocabulary. `\btoxic\b`-with-boundary deliberately
# does NOT match bare corpus names (ToxicChat, _stage_toxicchat: no word
# boundary before "Chat"/after "_stage_"-joined forms).
_C53_HARM_WINDOW_TOKEN_RE = re.compile(r"(?i)(?:\bevil\b|\btoxic(?:ity)?\b)")
_C53_HARM_WINDOW_CTX_RE = re.compile(
    r"(?i)(?:\bjudg(?:e|ed|es|ing)|\bband(?:s|ed|ing)?\b|\bsever(?:ity|e)\b"
    r"|\bgrad(?:e|ed|ing)\b|\bscor(?:e|ed|es|ing)\b|\brubric\b)"
)
```

Inside `check_judged_dv_api_refusal`, after the existing `harm_hits` collection from `_C53_HARM_VOCAB_RE.finditer(plan)`:

```python
if not harm_hits:
    for lineno, line in enumerate(plan.splitlines(), start=1):
        if _C53_HARM_WINDOW_TOKEN_RE.search(line) and _C53_HARM_WINDOW_CTX_RE.search(line):
            tok = _C53_HARM_WINDOW_TOKEN_RE.search(line).group(0)
            harm_hits.append(f"{tok} (L{lineno}, windowed)")  # plain strings — the WARN
            break                                             # message joins harm_hits
```

(Windowed hits are formatted as STRINGS so the existing `', '.join(harm_hits[:4])`-style WARN composition keeps working — no tuple types in `harm_hits`.)

Satisfier tightening (replacing the loose same-line co-mention check at ~L10150-10153):

```python
_C53_STOPREASON_REFUSAL_RE = re.compile(r"(?i)stop_reason\s*[=:]+\s*[\"'`]?\s*refusal")
# per-line: if _C53_STOPREASON_REFUSAL_RE.search(line): return _pass(...)
```

Everything else downstream (api-refusal token satisfier, escape, WARN text) is unchanged; the WARN message gains the matched line number/token when the fire came from the windowed arm (so a reader can see WHY it fired).

**Why same-line, not a char-window:** the plans are line-structured markdown (one design clause per line/bullet); #2221 v5's DV-defining lines carry both tokens on one line (L11 "judged on-policy trait-expression score … for evil/sycophancy/hallucination"; L123 "traits (evil/syco/hallu) … graded 0–100 Sonnet judge"). A char-window across newlines would re-admit incidental adjacency (a trait-roster line followed by an unrelated judging line). Same-line is the narrowest window that catches the driving incident.

**Known false negatives that REMAIN (disclosed by design, docstring updated):** evil/toxic phrasing split across lines from all judging vocabulary; "misaligned"/"EM" phrasings (still rejected — saturate project vocabulary); bare safety-benchmark names. The Statistics & Measurement lens REVISE stays the binding gate for those shapes.

**Fences:** the windowed scan runs on the RAW plan text lines, fences INCLUDED — same convention as the existing arm (a)/(b) scans (judged-DV designs live in fenced measurement-validity tables).
