## 1. Goal + Hypothesis

**Parent Goal (verbatim, unchanged):** Determine whether placing the negative-row loss at the post-response slot (loss-suppression flag on) gives contrastive negatives a live gradient that exerts a measurable restoring force on the source implant.

**This round's sub-question:** #613's sep-ablation round found that removing the answer/marker separator (glued `<answer>※`) flips on the suppression — the live-negative flag drops source ΔG from ~12.1 to 6.63 nats (seed-mean, −5.48) and bystander leakage from 5.53 to 1.89 nats (−3.64), with the leakage fraction falling 0.46 → 0.29, observed ONLY in the no-sep + flag-on corner. Is that suppression driven by:
- **(a) SLOT GEOMETRY (general mechanism):** placing the negatives' loss slot at (or adjacent to) the marker slot wakes the negatives, tolerant of the exact surface form; OR
- **(b) EXACT SURFACE FORM (narrow/cosmetic):** the effect is specific to the glued `<answer>※` token boundary.

The single-space separator (`marker_sep=" "`) is the discriminator: it changes the surface form from #613's glued no-sep cells (verified distinct at the token level — see §3) while keeping the marker as a valid terminal loss slot, ONE token downstream of the negatives' loss slot.

**Hypothesis:** if the suppression is slot-geometry-driven (a) and tolerant of a one-token offset, single-space flag-ON SUPPRESSES (source ΔG drops ~5.5 nats vs single-space flag-OFF, bystander leakage ~3.6 nats, leakage fraction → ~0.29), replicating #613's glued no-sep cells within the new construction. If it depends on the exact glued boundary (b), single-space flag-ON CO-LANDS with single-space flag-OFF (~12 nats, no suppression), like every other flag-off corner in the issue.

**Falsification:** single-space flag-ON co-lands with single-space flag-OFF (within-construction tolerance, §4) → **suppression does not survive a one-token downstream marker offset; exact glued surface vs strict slot coincidence remains unresolved by this round alone** (the single-space arm changes BOTH the surface form AND introduces a +1 marker-slot offset, so a co-land rules out "slot geometry tolerant of a one-token offset" but cannot isolate "exact glued boundary required" from "strict coincidence required" without an added control — e.g. a future round running BOTH a `\n` and a `\t` whitespace, where any pair-internal agreement would discriminate the residual surface-form-vs-offset axes; the parent's WITH-sep `\n\n` cell is ALSO offset-1 and co-landed, anchoring the offset-1 reading on the existing axis). #613's mechanism claim then narrows — the slot-geometry tolerance reading is falsified; the offset-vs-exact-surface residual is named explicitly in the re-narrated headline rather than collapsed into "surface-form-specific." Confirmation (suppression replicates within the single-space construction) → slot-geometry tolerant of a one-token marker offset, #613's account strengthens MODERATE → HIGH (with a clean caveat that "whitespace-family-permissive" remains the residual unresolved alternative, per §8 / §4), and the open falsification in #613's title resolves.

**Note on slot coincidence (load-bearing, see §3):** the single space inserts token id 220 between the answer's last content token and the marker. So the negatives' flag-ON loss slot (predicting `<|im_end|>` from `...pleasure.`) and the marker slot (predicting ` ※` from `...pleasure. <space>`) are NOT strictly the same softmax position — they are offset by one token. This means the round actually tests a slightly STRONGER claim than "slot coincidence": whether the restoring force tolerates a one-token offset of the marker downstream from the negatives' loss slot. The §4 reads and the clean-result narrate this precisely; the task framing's §3 instruction ("if NO single whitespace keeps the slots coincident, REPORT that finding") is honored by documenting the offset rather than pretending strict coincidence.

## 11. Decision Rationale

All conditions use the #601→#613 contrastive-marker setpoint recipe (`Source: #601 v1`, validated for Qwen-2.5-7B-Instruct on this exact mix/panel): lr=1e-5, cosine schedule + 5% warmup, effective batch 16, T=63 optimizer steps, rsLoRA r=32/α=64 dropout 0.05 all-linear, weight decay per #601 default, AdamW, bf16, max_length 1024, max_new_tokens 2048 eval. The mix (200 villain positives + 4×200 negatives), the 4-persona negative panel, the 8-persona held-out bystander panel, the seeds {42, 137}, the marker ` ※` id 83399, and the band-stop-log-only schedule are all inherited verbatim.

- **What:** `marker_sep=" "` (single space). **Why:** the discriminator between slot-geometry (a) and exact-surface-form (b) for #613's no-sep suppression — the smallest visible whitespace that changes the surface form while keeping the marker a valid terminal loss slot; named explicitly in #613's own "next steps" falsifier. **Source:** `#613 v5 sep-ablation round + chat 2026-06-15 falsifier request`. **Alternatives:** `"\t"` (tab — also verified distinct + marker-preserving, but a space is the human-natural separator and the one #613 named); a NON-whitespace separator (rejected — would change more than the separator, e.g. punctuation carries its own semantics); a strictly-coincident whitespace (rejected — none exists; verified this session that any inserted whitespace becomes its own token before the marker chunk, so strict coincidence is unattainable for any single-token separator).

- **What:** `--sep-mode space` / `sep=" "` read mapping (new dispatch branch). **Why:** the reads must score `log P(marker)` at the actual implant slot (`R + " "`); the v5 two-value vocabulary (`"\n\n"`/`""`) doesn't cover it. **Source:** `#613 v5` (extends v5's threading by one mapping value). **Alternatives:** reading at the `""` (glued) slot — rejected, would score the wrong slot and silently mis-measure; making `sep` fully free-form in the CLI — deferred, the enum keeps the dispatch explicit and testable.

Every other load-bearing value: `Source: #601 v1` (recipe) / `#613 v5` (sep-ablation construction + read protocol).

**Marker recipe note:** the stopping recipe (lr 1e-5, T=63, band-stop-log-only) is inherited from the #613 line, which itself runs at the marker-only setpoint. lr 1e-5 sits at the upper edge of the marker clean window (`.claude/rules/marker-training-recipe.md` names lr ≤5e-6 as the demonstrated-clean window); #613 deliberately held lr at the parent's 1e-5 to keep the A/B clean, and this round inherits that for cross-round comparability. The lr choice is a known scope caveat carried from #613 (its "next steps" flag an lr sweep as separate future work); NOT changed here (changing lr would break the single-variable contract).
