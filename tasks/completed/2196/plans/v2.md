# Plan v2 — #2196: cron_lesson_consolidate fails loud when its log dir / log file is unwritable

## Requirement + acceptance criteria

`scripts/cron_lesson_consolidate.sh` currently runs its consolidator inside a brace
group redirected to `$LOG_FILE`. When `$LOG_DIR` cannot be created (unchecked
`mkdir -p`, line 56) — or exists but is unwritable, so the `>> "$LOG_FILE"` redirect
at line 77 fails — the entire group silently never executes, `rc` stays unset,
`${rc:-0}` (line 93) reads 0, and the wrapper reaches the unconditional `exit 0`
(line 134). The nightly lesson-consolidation pass silently does not run, and nothing
anywhere records that fact.

Acceptance criteria (verbatim from the task body, plus the exists-but-unwritable
extension the Goal's wording covers — "fail loud when it cannot write its own daily
log file"):

- A1. An uncreatable `$LOG_DIR` produces a loud, diagnostic failure naming the path —
  not a silent `exit 0`. Wrapper exit code is non-zero.
- A2. The failure is pinned by tests in `tests/test_cron_lesson_consolidate.py`
  driving the wrapper with an unwritable log dir.
- A3. All existing T1–T9 pins stay green; rc=0 passes stay silent.
- A4. No change to `scripts/consolidate_lessons.py`, the crontab schedule, or
  `--window-days`.
- A5 (extension, same condition class per the Goal): a `$LOG_DIR` that EXISTS but is
  not writable — `mkdir -p` succeeds on an existing dir regardless of writability —
  also fails loud before the brace group, instead of silently skipping the pass.
- A6. The consolidator is provably NEVER invoked on the failure path (the failure is
  detected before the brace group, and the test asserts the stub was not called).
- A7. Because stderr reaches nobody live under cron (no MTA; the crontab line
  redirects `2>&1` into `~/my-goat/logs/cron_lesson_consolidate.log`), the failure
  ALSO attempts one best-effort Telegram push through the channel #2190 already
  wired (`$TELEGRAM_PUSH`). Push failure or a missing push script degrades to the
  stderr FATAL line — never a crash before the `exit 1`, never a blocked exit.

## Method delta (vs #2190, the prior change on this file)

#2190 added an alert arm AFTER the brace group keyed strictly on `rc == 3`, and
deliberately restored pre-diff behaviour on the unwritable-log path with `${rc:-0}`,
filing the underlying silence here. This task closes that filed gap: it adds a
fail-loud guard BEFORE the brace group (the uv-on-PATH precedent at lines 42–45:
stderr FATAL + non-zero exit), so the redirect-failure path becomes unreachable in
normal operation. `${rc:-0}` stays as defense-in-depth (a race — e.g. the dir
removed or the disk filling between the probe and the group — can still in
principle fail the redirect); its explanatory comment is updated to note the guard
now upstream (#2196) instead of "filed separately".

Design choice the task body delegated to the planner (Telegram vs stderr-only):
BOTH — stderr FATAL (durable in the crontab redirect file, satisfies A1) plus one
best-effort push (A7), because stderr alone reaches nobody live. NO per-date
sentinel dedup for this arm, deliberately: (a) the sentinel dir defaults to the very
log dir that is unwritable in this condition, so a sentinel write would itself fail;
(b) the cron fires once nightly (23:50), so pushes are bounded to one per failing
day by cadence alone. Recorded as a comment at the guard site.

## File paths + concrete diffs

Two files, additive-plus-comment-touch only:

### 1. `scripts/cron_lesson_consolidate.sh`

a. After the existing variable assignments (so `$TELEGRAM_PUSH` is bound), add a
   small `fatal()` helper + replace the bare `mkdir -p` (line 56):

```bash
# Fail-loud helper for wrapper-infrastructure failures (task #2196): stderr FATAL
# (lands in the crontab redirect file) + one best-effort Telegram push through the
# #2190 channel, then exit non-zero. No per-date sentinel for this arm: the
# sentinel dir defaults to the unwritable log dir itself, and the nightly cron
# cadence already bounds pushes to one per failing day.
fatal() {
    echo "$(date -Iseconds) FATAL: $1" >&2
    if [ -x "$TELEGRAM_PUSH" ]; then
        "$TELEGRAM_PUSH" "ALERT: cron_lesson_consolidate: $1" \
            || echo "$(date -Iseconds) lesson_consolidate: telegram_push.sh FAILED for FATAL alert (continuing to exit 1)" >&2
    fi
    exit 1
}

mkdir -p "$LOG_DIR" "$SENTINEL_DIR" \
    || fatal "cannot create log/sentinel dir (LOG_DIR=$LOG_DIR SENTINEL_DIR=$SENTINEL_DIR); lesson consolidation NOT run"
```

b. After the `FIRST_RUN_OF_DAY` computation (order is load-bearing: the probe
   creates `$LOG_FILE` if absent, and the flag must be read first), add an
   appendability probe so an EXISTING unwritable dir also fails loud:

```bash
# mkdir -p succeeds on an existing dir regardless of writability, so probe the
# actual append open the brace group below will attempt (task #2196). Runs AFTER
# the FIRST_RUN_OF_DAY read — the probe creates $LOG_FILE when absent.
: >> "$LOG_FILE" 2>/dev/null \
    || fatal "daily log file not writable ($LOG_FILE); lesson consolidation NOT run"
```

c. Comment updates only: header block gains one line documenting the new fail-loud
   condition; the `${rc:-0}` comment (lines 87–92) drops "filed separately, not
   widened here" in favour of "guarded upstream as of #2196; kept as
   defense-in-depth against races".

### 2. `tests/test_cron_lesson_consolidate.py`

Extend `make_harness` minimally and backwards-compatibly (no T1–T9 call-site
changes): one optional kwarg (e.g. `log_dir_setup: str = "ok"`) selecting
`"ok"` (today's behaviour) | `"uncreatable"` (make `log_dir` a path UNDER a regular
FILE, so `mkdir -p` fails with ENOTDIR — deterministic, no root/permission
dependence) | `"unwritable"` (create the dir, `chmod 0o555`). Three new pins:

- T10 `test_uncreatable_log_dir_fails_loud` — `log_dir_setup="uncreatable"`:
  wrapper rc != 0; stderr contains `FATAL` and the `$LOG_DIR` path; the stub
  consolidator was never invoked (`stub_calls.log` absent); exactly one push
  attempt recorded, message names the path (A1, A6, A7).
- T11 `test_existing_unwritable_log_dir_fails_loud` — `log_dir_setup="unwritable"`
  (+ `@pytest.mark.skipif(os.geteuid() == 0, ...)` since root bypasses mode bits):
  `mkdir -p` passes, the appendability probe fails; rc != 0; stderr `FATAL` names
  `$LOG_FILE`; stub never invoked (A5, A6).
- T12 `test_fatal_path_with_missing_push_script_still_exits_nonzero` —
  `log_dir_setup="uncreatable"`, `push_missing=True`: rc != 0 and stderr `FATAL`
  still present; zero pushes (A7's degradation half).

Out of scope (explicit): `scripts/consolidate_lessons.py`, the crontab line,
