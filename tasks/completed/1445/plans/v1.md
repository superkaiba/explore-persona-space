### 4.3 `_skill_ref_resolves` (L2718) — fourth resolution branch

```python
def _skill_ref_resolves(
    ref: str,
    live: set[str],
    allow: frozenset[str],
    fs_roots: frozenset[str] = SKILL_REF_FS_ROOTS,
) -> bool:
    """A backticked ``/<ref>`` resolves iff it names a live skill dir, an
    allowlisted exact token, a bare filesystem root (a backticked PATH like
    ``/tmp`` — see :data:`SKILL_REF_FS_ROOTS`), or (when namespaced
    ``<plugin>:<skill>``) a token whose ``<plugin>:`` prefix is allowlisted."""
    if ref in live:  # live project skill dir
        return True
    if ref in allow:  # allowlisted exact token
        return True
    if ref in fs_roots:  # bare backticked fs path, not a slash-command (#1445)
        return True
    if ":" in ref:  # plugin-namespaced: prefix match
        return (ref.split(":", 1)[0] + ":") in allow
    return False
```

(Branch order is cosmetic — every branch returns True — but live-first keeps reads intuitive.)

```python
def test_check_skill_refs_pass_bare_fs_root_backticked(tmp_path):
    """Regression (#1445): a bare single-segment backticked filesystem root
    (`/tmp`, `/workspace`, `/mnt`) closes on a backtick, so SKILL_REF_RE's
    trailing lookahead cannot reject it; the SKILL_REF_FS_ROOTS carve-out
    must resolve it — zero FPs with an empty skills dir + empty allowlist."""
    skills = tmp_path / "skills"
    skills.mkdir()
    docs = tmp_path / "docs"
    docs.mkdir()
    (docs / "a.md").write_text(
        "Write it under `/tmp` first.\nPods mount `/workspace` as the volume.\n"
        "The data disk binds under `/mnt` (ops).\n"
    )
    errors = check_skill_references(roots=[docs], skills_dir=skills, allowlist=frozenset())
    assert errors == [], f"expected PASS (bare fs roots carved out), got: {errors}"


def test_check_skill_refs_fs_root_carveout_is_load_bearing(tmp_path):
    """The same bare `/tmp` token FAILs when fs_roots is emptied via the
    override hook — proving the carve-out (not the regex/allowlist) resolves it."""
    skills = tmp_path / "skills"
    skills.mkdir()
    docs = tmp_path / "docs"
    docs.mkdir()
    (docs / "a.md").write_text("Write it under `/tmp` first.\n")
    errors = check_skill_references(
        roots=[docs], skills_dir=skills, allowlist=frozenset(), fs_roots=frozenset()
    )
    assert len(errors) == 1, f"expected exactly one error, got: {errors}"
    assert "/tmp" in errors[0]


def test_check_skill_refs_fail_dead_ref_with_production_fs_roots(tmp_path):
```

## 10. §11 Decision Rationale

- **Carve-out mechanism = dedicated frozenset, not allowlist entries.** What: `SKILL_REF_FS_ROOTS` as a fourth resolution branch. Why: self-documenting; preserves the allowlist's per-entry-justification contract; one commit closes the whole FP class instead of N future ones. Source: task #1445 clarifier finding + the 8 ad-hoc allowlist workarounds already present (L698-708). Alternatives rejected: (a) regex negative lookahead — cannot distinguish `` `/tmp` `` from `` `/weekly` `` (both close on a backtick; semantic, not syntactic); (b) more allowlist entries — perpetuates the per-FP tax and blurs the contract.
- **Set membership = FHS top-level dirs + `workspace` (20 members).** What: bin boot dev etc home lib lib64 media mnt opt proc root run sbin srv sys tmp usr var workspace. Why: closed, standard, enumerable vocabulary (Linux FHS 3.0) + the one project-specific volume root; deliberately EXCLUDES non-root path segments (`data`, `logs`, `cache`) which are not absolute-root tokens and would widen collision surface. Source: FHS 3.0 top-level list; RunPod `/workspace` convention (CLAUDE.md § Pods). Alternatives: minimal {tmp, workspace, mnt} — rejected, re-opens the class per new root; everything-path-like — rejected, collision risk.
- **`workspace` migrates; `log` and prose tokens stay.** What: only the pure-path allowlist entry moves. Why: `log` is justified as a dashboard route (dual-use — moving it silently rewrites its documented semantics, the clarifier's explicit warning); `intent`/`absent`/`override`/`binary`/`terminal`/`expensive-band` are prose tokens, not fs roots. Source: allowlist comments L698-708, read this session.
- **Consult point = `_skill_ref_resolves` with a defaulted param + a `check_skill_references` override hook.** What: mirrors the existing `allowlist=` test-hook style. Why: keeps the helper pure/testable, lets a test PROVE the carve-out is load-bearing (`fs_roots=frozenset()`), and keeps production call sites zero-change. Alternatives: union into `allow` at the call site — rejected, conflates the two sets' semantics and makes `allowlist=frozenset()` overrides lie; module-global read inside the helper — rejected, untestable-off.
- **Disjointness pinned by a test, not a comment.** What: `test_skill_ref_fs_roots_disjoint_from_live_skills_and_allowlist`. Why: the one real long-term risk is a FUTURE skill named like an fs root silently losing rot detection; a standing test fails loudly at skill-creation time. Source: task-brief constraint ("a carve-out entry that shadows a live skill name would silently disable rot detection").
