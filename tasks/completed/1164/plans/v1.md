## 3. Design

### 3.1 New helper: `scripts/verify_reused_artifact_keys.py` (~170 lines)

```python
#!/usr/bin/env python
"""verify_reused_artifact_keys.py — mechanized realized-keys probe (task #1164).

Executable form of .claude/rules/artifact-reuse.md check (c): verify a reused
multi-field bundle's REALIZED top-level key set is a superset of the keys the
consumer asserts, without materializing tensor storages. Exit 0 = superset
holds; 1 = missing keys; 2 = load/usage error. Never falls back silently.
"""

class BundleFormatError(RuntimeError): ...

def realized_keys(
    path: Path,
    *,
    fmt: str = "auto",            # auto | pt | safetensors | json
    weights_only: bool = True,
    allow_full_load: bool = False,
) -> set[str]: ...

def missing_keys(realized: set[str], declared: set[str]) -> set[str]:
    return declared - realized

def parse_keys_arg(keys: str | None, keys_file: Path | None) -> set[str]: ...
    # --keys "a,b,c" (comma/whitespace split) or --keys-file (one per line,
    # blank lines + '#' comments skipped); exactly one required.

def resolve_artifact(args) -> Path: ...
    # --artifact <local path>  XOR  --hf-repo <id> --hf-path <path_in_repo>
    #   [--repo-type dataset|model (default dataset)] [--revision <sha>]
    # HF mode: from explore_persona_space.orchestrate.env import load_dotenv;
    # load_dotenv() BEFORE any huggingface_hub import/use (project rule /
    # workflow_lint dotenv-before-hf-import convention), then hf_hub_download.

def main() -> int: ...
```

Format dispatch in `realized_keys` (by extension when `fmt="auto"`; unknown extension → `BundleFormatError`):

- **`.pt` / `.pth` / `.bin` (torch):**
  ```python
  import torch
  try:
      obj = torch.load(path, map_location="cpu", mmap=True, weights_only=weights_only)
  except Exception as e:
      if not allow_full_load:
          raise BundleFormatError(
              f"mmap load failed ({e!r}); legacy non-zipfile .pt or non-primitive "
              "metadata? Re-run with --allow-full-load (full read) and/or "
              "--no-weights-only (sha-pinned SELF-PRODUCED bundles only, per "
              ".claude/rules/gotchas.md)"
          ) from e
      obj = torch.load(path, map_location="cpu", weights_only=weights_only)
  if not isinstance(obj, dict):
      raise BundleFormatError(f"bundle root is {type(obj).__name__}, not a dict")
  return {str(k) for k in obj.keys()}
  ```
- **`.safetensors`:** `from safetensors import safe_open` → `with safe_open(path, framework="pt", device="cpu") as f: return set(f.keys())` (header-only read by design). Sharded `*.safetensors.index.json` layouts are a documented v1 limitation (point the probe at a shard, or use the sharded-index weight_map manually); the project's multi-field bundles (#779/#1073 pass-B) are single `.pt` files.
- **`.json`:** `json.loads(path.read_text())`, dict-root required, top-level keys.

`main()` prints a human report (`REALIZED n=<k> keys`, `DECLARED n=<d>`, `MISSING: <sorted>` or `PASS — realized keys ⊇ declared keys`) and with `--json` emits `{"artifact", "format", "status": "PASS|MISSING|ERROR", "n_realized", "declared", "missing", "realized"}` (realized capped at 200 entries). Exit contract: 0 PASS / 1 MISSING / 2 ERROR (argparse usage errors keep argparse's own exit 2).

```python
# ─── Check 30 — reused-bundle realized keys (WARN-only, conditional) ───────

_C30_BUNDLE_RE = re.compile(
    r"(?i)(\.pt\b|\.pth\b|\.safetensors\b|tensor bundle|multi-?field bundle|"
    r"save-dict|analysis_tensors|activation store)"
)
_C30_SATISFIER_RE = re.compile(
    r"(?i)(verify_reused_artifact_keys"          # the canonical helper
    r"|mmap\s*=\s*True[^\n]{0,120}\.keys\(\)"    # inline mmap key read
    r"|consumer(?:'s)?\s+own\s+loader)"          # consumer-loader-run form
)

def check_realized_keys(plan: str, kind: str) -> CheckResult:
    """Plans reusing a multi-field tensor bundle must name a realized-keys
    verification (artifact-reuse.md check (c), incident #1073). WARN not
    FAIL: the bundle-reuse trigger is heuristic (same class as c6), and the
    semantic question — was the probe actually RUN against the pinned
    revision — stays with the fact-checker. Trigger scans stripped prose;
    the satisfier ALSO scans raw text, because the runnable command
    legitimately lives in a fenced block."""
    cid, name = "c30_realized_keys", "reused-bundle realized-keys verification"
    if kind not in ("experiment", "analysis"):
        return _skip(cid, name, "kind-exempt")
    text = strip_fences(plan)
    bundle_hits = [m.start() for m in _C30_BUNDLE_RE.finditer(text)]
    reuse_near_bundle = any(
        re.search(r"(?i)\breus\w*", text[max(0, i - 300) : i + 300]) for i in bundle_hits
    )
    if not reuse_near_bundle:
        return _skip(cid, name, "no multi-field bundle reuse detected")
    if re.search(NA_RE + r"no multi-?field bundle reuse", text):
        return _pass(cid, name, "explicit no-bundle-reuse declaration")
    if _C30_SATISFIER_RE.search(plan):   # raw plan: fenced commands count
        return _pass(cid, name, "realized-keys verification named (helper / mmap read / consumer loader)")
    return _warn(
        cid, name,
        "plan reuses a multi-field tensor bundle but names no realized-keys "
        "verification — artifact-reuse.md check (c): run `uv run python "
        "scripts/verify_reused_artifact_keys.py --artifact <path> --keys "
        "<consumer keys>` (or the consumer's own loader) against the pinned "
        "artifact and paste the PASS line into §10 (incident #1073)",
    )
```

## 11. Decision Rationale

1. **Primary shape = (c) helper + (b) plan-gate hybrid.** *Why:* no staging chokepoint exists for (a) (grep-verified §2); a helper alone is optional prose one level down; a plan check alone is unfalsifiable declaration. The hybrid gives one runnable command + a gate that demands it be named. *Source:* grep 2026-07-09; #1073 (both sweep sites evaded prose); #928 precedent (probe convention + rule text). *Alternatives:* (a) rejected — quasi-architectural, bypassable by future per-issue scripts; (b)-only / (c)-only rejected as above.
2. **New check c30 vs extending c6.** *Why:* c6's contract is letter-counting over the (a)–(j) attestation section with 10 pinned tests; folding a key-level satisfier in would change its semantics and existing expectations. One concern per check is the file's convention (30 separate checks). *Source:* `verify_plan.py:794–833`; `tests/test_verify_plan.py:653–749`.
3. **WARN vs FAIL.** *Why:* the trigger is heuristic (same epistemic class as c6/c24); the header's stated scope discipline is "surface exists" — semantics stay with the fact-checker/critics, and WARNs forward verbatim into their briefs. A false FAIL would block legitimate plans; a false WARN costs one acknowledgment. *Source:* verify_plan.py header lines 105–116; c6 docstring rationale. *Alternative:* FAIL-for-experiment/WARN-for-analysis (the c12/c13 split) — rejected because unlike c12/c13 the trigger here keys on informal prose vocabulary, not a registered numeric structure.
4. **Kind scope experiment + analysis.** *Why:* analysis tasks are the heaviest bundle reusers (free-analysis reads of parent stores); precedent for the two-kind scope: c19/c24/c28. *Source:* verify_plan.py catalog. *Alternative:* experiment-only (c6 parity) — rejected; it would exempt exactly the task class most exposed.
5. **Helper takes an explicit `--keys` list, not auto-extraction from consumer code.** *Why:* consumer asserts are free-form Python (`assert k in b` loops over module-level tuples); AST-extracting them across arbitrary per-issue scripts is fragile and would fail open. The caller copies the consumer's required-keys list — 30 seconds of work, zero ambiguity. *Source:* `scripts/issue1073_common.py:255,266`. *Alternative:* `--from-python module:ATTR` import hook — deferred (nice-to-have; import side effects + path issues in a plan-time context).
6. **Exit-code contract 0/1/2, no silent fallback on mmap failure.** *Why:* fail-fast is a Critical Rule; a silent full-load fallback would both hide format drift and potentially OOM on a multi-GB bundle. Explicit `--allow-full-load` + `--no-weights-only` escapes with gotchas-documented caveats. *Source:* CLAUDE.md fail-fast; gotchas.md:161–171.
7. **Satisfier scanned on RAW plan text (fences included), trigger on stripped prose.** *Why:* runnable commands legitimately live in fenced blocks (stripping them would WARN exactly the best plans); triggers on stripped text follow c6/c24 precedent (`test_c24_fenced_trigger_does_not_trigger`). *Source:* `verify_plan.py` `strip_fences` usage; `tests/test_verify_plan.py:3438`. Pinned by `test_c30_fenced_helper_command_satisfies`.
8. **N/A phrase `N/A — no multi-field bundle reuse`.** *Why:* every conditional check with a content trigger carries a canonical verbatim escape in the header list; matches the existing phrase register (`N/A — no artifact reuse`, check 6). *Source:* verify_plan.py:77–103.
