**Replace** the Guard 1 block. Existing text (6826-6836):

> 1. **Foreign-`tasks/` guard.** `git diff --name-only origin/main HEAD --
>    tasks/` MUST be empty except THIS task's own folder

**Replacement (verbatim):**

> 1. **Foreign-`tasks/` guard (strip whole foreign task folders before the
>    merge).** `git diff --name-only origin/main HEAD -- tasks/` MUST be empty
>    except THIS task's own folder (`tasks/*/<N>/`). For any FOREIGN `tasks/`
>    path in that diff — a `tasks/*/<M>/…` file for `M != <N>`, whether
>    `events.jsonl`, `comments.jsonl`, `body.md`, or any other file — reset it
>    to `main` BEFORE merging so the server-side `gh pr merge --rebase` has
>    nothing foreign to conflict on (GitHub ignores this repo's
>    `.gitattributes merge=union`, so a union merge cannot rescue a server-side
>    conflict — the strip must happen here). Reset by explicit path:
>
>    ```bash
>    # Foreign tasks/* paths this branch touches (everything under tasks/ that
>    # is NOT this task's own folder). Anchored so tasks/.../<N>/… is excluded.
>    mapfile -t FOREIGN < <(git -C "$WT" diff --name-only origin/main HEAD -- 'tasks/' \
>      | grep -Ev "^tasks/[^/]+/<N>/" || true)
>    if [ "${#FOREIGN[@]}" -gt 0 ]; then
>      git -C "$WT" checkout origin/main -- "${FOREIGN[@]}"
>      # Commit the reset so the branch diff no longer touches them (idempotent:
>      # if checkout produced no change — already at main's version — the commit
>      # is skipped).
>      git -C "$WT" diff --cached --quiet -- "${FOREIGN[@]}" \
>        || git -C "$WT" commit -m "issue-<N>: reset foreign tasks/ folders to main before merge" -- "${FOREIGN[@]}"
>    fi
>    ```
>
>    This is idempotent (a re-run finds `FOREIGN` empty and no-ops) and never
>    touches THIS task's own `tasks/*/<N>/` folder (the `grep -Ev
>    "^tasks/[^/]+/<N>/"` carve-out). Never let a behind-`main` branch revert
>    another task's `events.jsonl` / `comments.jsonl`. (Incident 2026-06-01:
>    #458's merge branch, 1,146 commits behind main, silently rewound
>    `tasks/running/448/events.jsonl`.) The `--rebase` merge form below replays
>    the branch's commits on top of current `main`, so files the branch never
>    committed keep `main`'s version — this is what keeps the clean-result body
>    (committed to `main` by `task.py`, never in the worktree) safe across the
>    merge.

**Why this works / idempotency:** `git checkout origin/main -- <path>` stages
`main`'s version; the conditional commit removes those paths from the branch's
own diff, so the subsequent server-side rebase replays no foreign-folder
changes → no conflict. Re-running finds `FOREIGN` empty. The own-folder
carve-out (`grep -Ev "^tasks/[^/]+/<N>/"`) preserves the "this task's own
folder" exception exactly as the original prose required.

> checkout below — the same procedure Guard 3's UNSAFE case degrades to, which
> lands exactly this branch's own added files without a rebase.
>
> ```bash
> # Fast-path predicate — ALL of:
> #  (a) task is kind:infra AND tagged wf-fix (a workflow-fix branch), AND
> #  (b) BEHIND > 1000 (branch predates significant main churn), AND
> #  (c) the branch's OWN diff touches <= 15 files, AND
> #  (d) every touched file is in-scope: this task's own paths, workflow
> #      surface, .gitattributes, or the methodology doc — NO shared src/ or
> #      scripts/ additions (those need the full rebase to land).

> TASK_TAGS=$(printf '%s\n' "$KIND" | sed -n 2p)
> mapfile -t OWN_DIFF < <(git -C "$WT" diff --name-only origin/main...HEAD)   # three-dot: own commits only
> N_FILES=${#OWN_DIFF[@]}
> # In-scope test: every own-diff path matches one of the allowed prefixes.
> IN_SCOPE=yes
> for f in "${OWN_DIFF[@]}"; do
>   case "$f" in
>     tasks/*/<N>/*|figures/issue_<N>/*|eval_results/issue_<N>/*|eval_results/issue_<N>_*/*|ood_eval_results/issue_<N>/*) ;;
>     .claude/*|CLAUDE.md|.gitattributes|docs/methodology/issue_<N>.md) ;;
>     *) IN_SCOPE=no; break ;;
>   esac
> done

> if [ "$TASK_KIND" = "infra" ] \
>    && printf '%s' "$TASK_TAGS" | grep -qw 'wf-fix' \
>    && [ "$BEHIND" -gt 1000 ] \
>    && [ "$N_FILES" -le 15 ] \
>    && [ "$IN_SCOPE" = "yes" ]; then
>   FAST_PATH=yes
> fi
> ```

> the **surgical additive checkout** (the "One or more deliverables missing"

> lands this branch's own added files onto `main` directly, with no rebase.

> true, surgical_checkout: true, fast_path: true, reason: "wf-fix branch
> BEHIND=<BEHIND> > 1000, own diff <=15 in-scope files — skipped doomed

> `figures/` / `eval_results/` paths and CANNOT carry workflow-surface files
> under `.claude/**` or `CLAUDE.md` or `.gitattributes`; see the scope note in

## 11. Decision Rationale (pinned thresholds)

Two load-bearing numeric thresholds are introduced by Sub-fix 3. Both are
grounded in observed prior-issue behind-counts and diff sizes.

**BEHIND_THRESHOLD = 1000**
- **What:** the fast-path fires only when `BEHIND > 1000` commits.
- **Why (tied to Goal):** the Goal is to make surgical-additive the DEFAULT for
  far-behind workflow-fix branches where `--rebase` is doomed. A branch >1000
  commits behind predates significant `main` churn — a server-side rebase
  replays its own commits across >1000 intervening commits and predictably
  conflicts even after foreign folders are stripped. Below ~1000 the ordinary
  `--rebase` path succeeds routinely, so gating at 1000 leaves normal branches
  untouched.
- **Source:** `#697` (the motivating stuck case) read BEHIND = 3771–4452 and
  was refused twice — comfortably above 1000. `#598` false-tripped an OLD
  fixed-200 threshold at BEHIND = 305 (a same-day single-own-commit
  mainline-based branch reads hundreds behind because every `task.py` marker is
  a commit, ~100+/hr fleet-wide) — so 200 is demonstrably too low; 1000 sits
  well above the normal same-day range and at the far-behind class #697/#479
  (1,153)/#511 (~667)/#458 (1,146) occupy. Guard 3's existing default threshold
  is 200 (SKILL.md 6866); the fast-path uses a HIGHER, stricter 1000 because it
  changes routing pro-actively (skips `--rebase`) rather than reactively.
- **Alternatives considered:** 200 (Guard 3's existing default) — rejected,
  #598 shows it false-trips normal same-day branches. 500 — plausible but #511
  at ~667 and normal branches occasionally in the high-hundreds make 500 riskier
  for false positives; 1000 is a clean separation between the "same-day churn"
  band (hundreds) and the "stale far-behind" band (thousands).

**N_FILES_MAX = 15**
- **What:** the fast-path fires only when the branch's own diff touches ≤ 15
  files.
- **Why (tied to Goal):** the surgical additive checkout can only faithfully
  carry a SMALL, in-scope diff; a large multi-domain diff needs the full rebase.
  Capping at a generous 15 keeps the fast-path to genuine small workflow-fix
  diffs while excluding branches that touch many files (which should take the
  full-rebase or artifact-confirmed path).
- **Source:** `#748/#749/#752/#753/#755` — small workflow-fix branches that
  merged fine — touch 1–5 files each; 15 is a generous 3× headroom over the
  typical 1–5, excluding multi-domain edits. (#787 itself touches 2 files:
  `.gitattributes` + `SKILL.md`.)
- **Alternatives considered:** 5 (the observed typical count) — rejected as too
  tight; a workflow-fix that also touches `workflow.yaml` + a couple of agent
  memories + a test legitimately reaches ~6–10 files. 30 — rejected as too loose
  (admits multi-domain edits the surgical checkout should not shortcut).
