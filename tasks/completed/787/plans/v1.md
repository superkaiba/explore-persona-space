## 1. Goal

> Make the scratch-worktree-detached-at-origin/main surgical merge the DEFAULT Step-10d path for workflow-fix/small-diff tasks when BEHIND exceeds a threshold (skip the doomed --rebase); add `.gitattributes merge=union` for `tasks/**/events.jsonl` (append-only) and `-X no-renames` / exclude `tasks/*` from the merge so concurrent task folders never conflict; exclude Step-5a-synced workflow-surface files from the Guard-3 out-of-scope check.

Step 10d auto-merges an issue worktree to `main` at the terminal point. Because every `task.py` marker across the fleet is a commit (~100+/hr), an issue branch is routinely hundreds of commits behind `main` and carries copies of OTHER sessions' `tasks/*` folders (rewound by the branch's stale base) plus Step-5a spec-freshness sync commits on the workflow surface. The current default path — `gh pr merge --rebase` — replays the branch's commits on GitHub's servers and hits a REAL conflict whenever `main` and the branch both touched the same lines of a shared `tasks/*/events.jsonl` (both appended) or a Step-5a-synced spec. The result is a chronic `epm:merge-failed` (8+ recent issues) that leaves the branch unmerged and requires manual resolution. The fix routes the tiny-diff class to the already-existing surgical-additive-checkout path (which never touches foreign `tasks/*`), makes append-only logs conflict-free via git's native `union` driver, and stops Step-5a no-op syncs from tripping Guard 3.

## 2. Prior Work

- **`git merge` `union` driver** (git-scm, `gitattributes(5)`): `merge=union` resolves a text conflict by concatenating lines from BOTH sides in place of the conflict marker, producing no conflict markers. It is the standard fix for append-only line-delimited logs (changelogs, `.jsonl` event logs) and is used universally by sibling repos with append-only JSONL logs. Verified locally (§9 probe): two branches each appending a distinct row after a common tail merge to a file containing BOTH rows, no conflict.
- **Current Step 10d procedure** (`.claude/skills/issue/SKILL.md`, `### Step 10d: Auto-merge the worktree`): three-branch structure — (a) safe case `gh pr merge --rebase` when Guard 3 is clean; (b) merge-conflict recovery (in-worktree `git merge origin/main`, resolve, push, retry) run ONCE; (c) artifact-confirmed / surgical-additive-checkout when Guard 3 trips. Guards 1 (foreign-`tasks/` checkout), 2 (status off `running`), 3 (branch-content / non-`main`-base). The New-shared-`src/`-infra guard runs FIRST inside branch (c) and refuses to surgical-checkout a branch that ADDED shared `src/` modules (#595). A post-merge stale-task-folder guard runs after every form (#644).
- **Step 5a spec-freshness sync** (`.claude/skills/issue/SKILL.md`, near line 1912): before dispatching subagents, surgically `git checkout main -- $SAFE_SPECS` for `SPECS=".claude/agents .claude/skills .claude/rules .claude/workflow.yaml CLAUDE.md"`, committing `issue-<N>: sync workflow-surface specs from main (spec-freshness)`. These commits appear in the branch's own `origin/main...HEAD` diff and their content is byte-identical to `main` at sync time — the exact case that trips Guard 3's out-of-scope check for a far-behind branch.
- **Threshold origin.** `BEHIND` default `200` was introduced in commit `b5c5a96d0f` ("workflow-fix: add Step 10d guard 3 ... + artifact-confirmed merge procedure") and re-keyed to own-commit CONTENT (not wall-count) in `5b573411ed`. `BEHIND` alone is NEVER an automatic unsafe verdict; it merely TRIGGERS the own-commit content check (#598: `BEHIND=305` false-tripped the old fixed-200 gate). ### Edit D — Guard-1 rename/delete resolver (Step 10d Guard 1)

Lands under guard 1 (`1. **Foreign-`tasks/` guard.**`). The current guard runs `git checkout origin/main -- <that file>` per foreign `tasks/` path — this fixes CONTENT drift but not a concurrent `task.py set-status` rename (`tasks/<old>/<N>/events.jsonl` → `tasks/<new>/<N>/events.jsonl`), where a blind rebase hits a rename/delete conflict. `-X no-renames` is NOT viable (`gh pr merge` merges server-side and passes no strategy option; client force-push is a hard user-ask). Instead, reduce the surface — extend Guard 1 to detect + resolve the shape locally. ADD after the existing Guard-1 sentence:

```
   **Concurrent status-move (rename/delete) resolution.** A concurrent
   `task.py set-status` renames `tasks/<old>/<M>/` → `tasks/<new>/<M>/`
   on `main`. A behind-`main` branch that committed to
   `tasks/<old>/<M>/events.jsonl` then hits a rename/delete conflict on
   rebase (branch has the old path; `main` moved it). The foreign-content
   `git checkout origin/main -- <file>` above does NOT resolve this — the
   old path no longer exists on `origin/main`. Detect + resolve by
   dropping the branch's stale old-status folder (the concurrent
   session's status move WINS — status is single-writer via `task.py`
   flock, so `main`'s move is authoritative):

   ```bash
   # Foreign tasks/<M>/ folders the branch carries that origin/main no
   # longer has AT THAT PATH (a concurrent status move relocated them).
   for OLD in $(git -C "$WT" diff --name-only origin/main HEAD -- tasks/ \
                | grep -E '^tasks/[^/]+/[0-9]+/' \
                | grep -vE "^tasks/[^/]+/<N>/"); do
     # Present on branch but MISSING at this exact path on origin/main?
     if ! git -C "$WT" cat-file -e "origin/main:$OLD" 2>/dev/null; then
       # The concurrent session moved it — remove the branch's stale copy
       # so the rebase carries no old-path payload for that foreign task.
       git -C "$WT" rm --cached --quiet -- "$OLD" 2>/dev/null || true
     fi
   done
   ```

   This keeps a foreign task's status move authoritative and prevents the
   rename/delete conflict class. It is orthogonal to the byte-identical
   spec exclusion (Edit C, workflow surface) and to the `union` driver
   (Edit A, same-path concurrent appends): the three cover CONTENT drift,
   RENAME/DELETE, and same-path APPEND respectively.
```

## 11. Decision Rationale

*(This is a `kind: infra` spec-edit task — no model hyperparameters. The "load-bearing config knobs" here are the git-config + threshold choices, each with a Source.)*

- **What:** `.gitattributes` — `tasks/**/events.jsonl merge=union` + `tasks/**/comments.jsonl merge=union`.
  **Why:** append-only line-delimited logs; concurrent sessions append different rows to the same file; `union` concatenates both sides with no conflict, the git-native fix for this exact shape. Serves the Goal's "concurrent task folders never conflict" directly.
  **Source:** `gitattributes(5)` / git-scm docs (the built-in `union` merge driver); local probe §9 confirming both-rows-retained; the recurrence pattern in #739/#748/#749/#752/#753/#755/#762 (`tasks/*` append conflicts) and #697 (verbatim marker). Sibling-repo convention (append-only JSONL logs universally use `merge=union`).
  **Alternatives rejected:** (a) `merge=union` on REGISTRY.json — REJECTED, it is a single JSON object, `union` would concatenate braces and corrupt it (kept flock-guarded by `task.py`); (b) a custom merge driver script — REJECTED as over-engineering for append-only logs where `union` is exactly correct; (c) `body.md` / `plans/*.md` union — REJECTED, single-writer per task, not logs.

- **What:** surgical-first default for workflow-fix tasks (`is_workflow_fix_session(N)`) + below-threshold small-own-diff tasks; skip `gh pr merge --rebase`.
  **Why:** a workflow-fix diff is tiny + own-scope; the surgical-additive checkout lands exactly those files and never rewinds foreign `tasks/*` nor hits a server-side rename/delete conflict. The full rebase buys nothing for this class and reliably conflicts.
