### 4. Design

**Approach decision: Approach 1 (create on first push), realized as an orchestrator-side ensure at Step 5 round entry.** Reasoning:

1. **The round-push sites, enumerated.** (a) The implementer subagent's push — SPLIT BY SPEC (fact-checked 2026-08-20): `experiment-implementer.md` pushes `git push origin issue-<N>` from the worktree BEFORE posting the implementation marker — step 10 "Commit + push" (:682, grep -n verbatim: `682:10. **Commit + push** on branch \`issue-<N>\`. Use the repo's commit-message`) precedes step 11 "Post the report" (:701) — spec-guaranteed. `implementer.md` mandates COMMIT in its After-Implementation sequence (`### After Implementation`, :179, items 1-7) but contains **no unconditional push step** before item 7 posts `epm:results`: :152 is a *conditional* pod-sync line (grep -p verbatim: `152:- **ALL code edits on local VM.** Never edit code directly on pods. If pods need the change, commit + push, then experimenter \`git pull\`s. ...`), and :327 is only the no-push-to-main constraint (`327:- **No git push to main without user approval.** Create a branch if not on one.`). So on `kind: infra | batch` tasks the branch MAY be unpushed at round-1 Step 5 entry. (b) The orchestrator's between-round pushes — `steps/09-step-5.md:38-43` "Round push hygiene". (c) The experimenter's pod-side result pushes (Step 6+, after Step 5 has already run). (d) Step 10d itself (the backstop). Site (a) is where the *first* push happens on the EXPERIMENT path — but it runs inside a subagent whose env is scrubbed of `GH_TOKEN`/`GITHUB_TOKEN` (`steps/08-step-4.md:123-135`, `scrub_subagent_env`), i.e. the workflow deliberately keeps GitHub API mutations in the orchestrator. So "create on first push" cannot literally live at the push site; the first *orchestrator* control point after the first push is **Step 5 entry** (Step 5 fires once an implementation marker is present — `epm:experiment-implementation` OR `epm:results`, `steps/09-step-5.md:10-12`). **Coverage, stated exactly:** the ensure covers every path that FIRES STEP 5 — the experiment path (branch pushed pre-marker, spec-guaranteed ⇒ the round-1 create succeeds) and the infra/batch code paths (commit guaranteed, push NOT spec-guaranteed ⇒ the round-1 create may fail rc≠0; the retry-while-unconfirmed arm + the between-round Round-push-hygiene pushes carry it to the first round where the branch is on origin — precisely what fail-open buys). NOT covered: the analysis-only path, whose marker is `epm:interpretation` (`08-step-4.md:120`), not in the Step 5 trigger set — it skips Step 5 and falls to the Step 10d backstop, as does any other Step-5-skipping path; acceptance criterion 2 requires that backstop to stay reachable anyway (§12.6).
2. **Approach 2 rejected** (idempotent Step 4a re-invoke): "the first point where commits exist" IS Step 5 entry, so approach 2 converges on the same placement while dragging along Step 4a's fetch + root-divergence probe + `sync_repo_root.py` machinery (2 extra network ops + a sync path) onto the hot path per invocation. Approach 1's block is the same create minus that machinery.
3. **Approach 3: not revisited** (pre-rejected in the task body: GitHub refuses zero-commit PRs).

**Check granularity: once-per-branch, memoized in-session, with bounded per-round retry only while unconfirmed.** At each Step 5 round entry, IF an open PR has already been confirmed this session → skip (zero cost; the common case for rounds ≥2). Otherwise run one probe (+create if zero). A pure round-1-only check leaves the gap open when round 1's preconditions fail (e.g. implementer push failed — or, on infra/batch, no round-1 push was ever spec-guaranteed, A7 → create fails → never retried), which would keep the anomaly marker firing on full-pipeline branches and violate criterion 2; a pure per-round check re-spends a network call and its flake surface every round for nothing. Pricing in §9.

**Failure isolation (criterion 3):** tri-state probe — rc≠0 means *probe failed*, which SKIPS the round's attempt rather than blind-creating (a blind create is 422-safe but noisy and conflates outages with the zero-PR class); rc-gated create as an `if` condition (the #2240 idiom — never a bare command whose failure falls through); both gh calls `timeout`-fenced (no unbounded network call); all failure arms end in an `echo` + fall-through to 5a (fail-open: the round is never blocked, delayed, or failed); nothing piped (`guard_piped_git_push.sh` compliance — bare invocations only).

**Why code, not a model call:** N/A in the usual sense — this IS procedural prose for an LLM orchestrator; the mechanical parts (probe, create) are deterministic CLI calls, the correct tool.

**Embedded-shell exit-path trace:** the block contains no `false`, no `exit`, no `set -e` interaction; every branch terminates in an `echo` or the rc-gated `if` and control falls through to the next Step 5 action. The `|| N_PR=probe-failed` arm converts every probe failure mode (rc 1, timeout rc 124, auth rc 4) into the skip branch. No arm can halt a sibling block.

**Draft-PR ensure (#2241; once per branch, memoized).** Step 4a's
draft-PR create is gated on commits-ahead > 0 but runs BEFORE the

THIS block is the site that actually opens the draft PR on the normal

backstop. At each round entry that proceeds past the pre-split guard:
IF an open PR for issue-<N> has already been confirmed this session,
SKIP (zero cost — the common case after round 1); otherwise run the
probe+create below and remember a confirmed outcome. Both commands are
timeout-bounded and the whole block is FAIL-OPEN: no probe or create
failure may block, delay, or fail the round — log the one line, proceed

```bash
# Any-state existence probe (deterministic tri-state; measured ~0.4 s):
# rc!=0             -> probe failed (network/auth): skip, retry next round
# "0"               -> no PR object at all = the #2241 zero-PR class: create
# ">=1" (any state) -> a PR object exists: OPEN -> done; MERGED/CLOSED is
#                      the #1897 follow-up class, owned by Step 10d's
#                      payload-aware arm at merge time — do NOT create here.
N_PR=$(timeout --kill-after=15s 60s gh pr list --head issue-<N> --state all --json number --jq length) || N_PR=probe-failed
if [ "$N_PR" = "0" ]; then
  if timeout --kill-after=30s 120s gh pr create --draft --head issue-<N> \
       --title "issue-<N>: <task title>" --body "Closes task #<N>."; then
    echo "[step5-pr-ensure] opened draft PR for issue-<N> (#2241)"
  else
    echo "[step5-pr-ensure] gh pr create failed (rc!=0) — round proceeds; retry at next round entry; Step 10d's payload-aware arm (#2240) is the backstop"
  fi
elif [ "$N_PR" = "probe-failed" ]; then
  echo "[step5-pr-ensure] PR-existence probe failed — round proceeds; retry at next round entry"
fi
```

The ensure deliberately carries NO push and NO ancestry guard: at Step 5

#2296 parity) still runs at Step 10d before any merge. If the branch is
not on origin yet (implementer push failed), the create fails rc!=0 and
the fail-open arm retries after a later round's push (Round push
hygiene above) lands it — never push from this block: a new push site
would owe the #2312 stale-ref guard pair (see
tests/test_issue_skill_step10d_rewritten_branch.py::test_all_copy_sites_guarded).
