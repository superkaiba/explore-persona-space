## 4. Design

### 4.1 Part (a) — the spawn-baseline probe (run FIRST, pre-trim)

Procedure (orchestrator/implementer session, Agent tool):
1. For each agent type in {`general-purpose`, `implementer`, `analyzer`, `experimenter`, `planner`, `critic`}: spawn ONE agent with the fixed prompt `Reply with the single word OK. Do not use any tools.` (foreground, sequential, ~1–2 min each). Spawn `general-purpose` TWICE in the pre-trim batch — the gp pair is the subtracted term in every delta, so its repeat is the highest-leverage stability check AND the measured noise estimate acceptance criterion 8 uses (7 pre-trim spawns).
2. Record per row: the raw `<usage>` block VERBATIM plus the tool-use count (a probe that ignores "no tools" and inflates its total is thereby visible), `stat -c '%s' .claude/agents/<type>.md`, `stat -c '%s' .claude/agent-memory/<type>/MEMORY.md` (0 where absent), the spec frontmatter `tools:` / `effort:` fields, and a session/schema fingerprint (session id + the session's MCP-server/tool-schema inventory) — probe-to-probe comparisons are BINDING only between rows sharing the fingerprint.
3. Compute `delta(type) = tokens(type) − mean tokens(general-purpose)` on INPUT tokens where the usage block exposes the input/output split (report output/thinking separately per row — `effort: xhigh` thinking burn must not fold into the "spec+memory" delta); fall back to totals only if no split is exposed, and say so in the table. This isolates the spec + agent-memory + role-baseline term, since the shared pile (project CLAUDE.md tree, user-global files, MCP schemas) is constant within the session. Also compute implied bytes/token = (spec+memory bytes)/delta per row, with an **instrument-validity band**: a nonzero delta whose implied bytes/token falls outside [2, 8] marks the usage instrument INVALID for that row (signature of a usage block reporting only post-spawn turn I/O) — invalid rows NEVER feed kill-criterion 1 or the threshold mapping; the step-7 bytes/4 estimator takes over for them.
4. AFTER the §4.2/4.3 trims land in the worktree: re-run the planner and critic probes plus ONE general-purpose injection-guard row (3 more spawns) → the post-trim rows. (The harness reads agent specs from the repo the session runs in; the probe session runs in the issue worktree so the trimmed specs are the ones loaded. If the harness instead resolves specs from the repo root's `.claude/agents/`, run the post-trim probes after the Step 10d merge and record them as a completion-report addendum — deviation-allowed.)
5. **Threshold mapping:** safe always-on spec budget `B_safe ≈ r × (W − B_gp − H)` where `r` = the MEASURED bytes/token calibration from instrument-valid rows (literal 4 B/token ONLY as the declared fallback when no valid row exists), `W` = the context window (~200K tokens), `B_gp` = the measured general-purpose probe mean (the shared-pile floor), and `H` = working headroom = **max(80K tokens, measured gp work usage)**, where measured gp work usage = the completed general-purpose incident totals (~160–211K, #833/#834) minus `B_gp` — a fixed 80K demonstrably understates real work when `B_gp` is small. **Precedence:** the §9 band clamp + the direct incident evidence (a 63.9 KB spec thrashes) govern whenever the formula disagrees — the formula is a heuristic (autocompact thrash is churn-rate-driven, not a static budget) and the probe artifact states this limitation explicitly. **B_safe → shipped `AGENT_SPEC_FAIL_BYTES` decision table:** (i) B_safe < 20,000 → ship 40,000 (band floor); the ≤20 KB trim target is NOT probe-certified — the trim still lands as pure weight-shedding and the completion report says so; (ii) 20,000 ≤ B_safe < 40,000 → ship 40,000 (band floor); the ≤20 KB target IS probe-certified; (iii) 40,000 ≤ B_safe ≤ 56,000 → ship min(48,000, B_safe) rounded down to the nearest 1,000; (iv) B_safe > 56,000 → ship the 48,000 provisional unchanged (incident evidence governs over a looser formula). In every cell the shipped WARN stays in its band [20,000, 32,000] and below the shipped FAIL; grandfather-set membership is recomputed from the SHIPPED FAIL value (every non-trimmed spec above it gets a cap).
6. **Interference / cost note:** each probe is a 1-turn no-tool spawn; if a PRE-trim planner/critic probe itself thrashes on the trivial prompt, that IS a decisive measurement (spawn baseline alone ≈ the window) — record it as such, do not retry more than once.
7. **Fallback estimator:** if the usage block does not expose the baseline cleanly — reports 0 (as it did for thrashed spawns), omits input tokens, OR fails the step-3 instrument-validity band on the rows a decision needs — fall back to `bytes/4` over (spec + agent-memory MEMORY.md + shared pile measured by `wc -c`), and say so in the probe table. Kill-criterion 1 may fire only on instrument-VALID data, per type (it fires for the type(s) whose valid delta is small); a one-retry disagreement ships the LARGER of the two reads (conservative for the threshold decision). The trim (part b) proceeds either way; only the threshold choice (part c) degrades to the estimator.

Artifacts: `tasks/<status>/838/artifacts/spawn-baseline-probe.md` (the full table + method note) + an `epm:progress` marker with the summary table.

## 5. Kill criteria
