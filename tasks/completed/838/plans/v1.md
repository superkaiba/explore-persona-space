## 4. Design

### 4.1 Part (a) — the spawn-baseline probe (run FIRST, pre-trim)

Procedure (orchestrator/implementer session, Agent tool):
1. For each agent type in {`general-purpose`, `implementer`, `analyzer`, `experimenter`, `planner`, `critic`}: spawn ONE agent with the fixed prompt `Reply with the single word OK. Do not use any tools.` (foreground, sequential — 6 spawns, ~1–2 min each).
2. Record the returned `<usage>` block token counts per spawn into the probe table alongside `stat -c '%s' .claude/agents/<type>.md` and `stat -c '%s' .claude/agent-memory/<type>/MEMORY.md` (0 where absent).
3. Compute `delta(type) = total_tokens(type) − total_tokens(general-purpose)` — this isolates the spec + agent-memory + role-baseline term, since the shared pile (project CLAUDE.md tree, user-global files, MCP schemas) is constant within the session. Also compute implied bytes/token = (spec+memory bytes)/delta as the calibration constant.
4. AFTER the §4.2/4.3 trims land in the worktree: re-run the planner and critic probes (2 more spawns) → the post-trim rows. (The harness reads agent specs from the repo the session runs in; the probe session runs in the issue worktree so the trimmed specs are the ones loaded. If the harness instead resolves specs from the repo root's `.claude/agents/`, run the post-trim probes after the Step 10d merge and record them as a completion-report addendum — deviation-allowed.)
5. **Threshold mapping:** safe always-on spec budget ≈ `4 B/token × (W − B_gp − H)` where `W` = the context window (~200K tokens), `B_gp` = the measured general-purpose probe total (the shared-pile floor), and `H` = 80K tokens working headroom (a 450-line plan ≈ 6–7K tokens + a 650-line module ≈ 7K tokens + ~3× churn for tool results, history, and report drafting). The new FAIL threshold is set at or below this budget (within the §9 bands).
6. **Interference / cost note:** each probe is a 1-turn no-tool spawn; if a PRE-trim planner/critic probe itself thrashes on the trivial prompt, that IS a decisive measurement (spawn baseline alone ≈ the window) — record it as such, do not retry more than once.
7. **Fallback estimator:** if the usage block does not expose the baseline cleanly (e.g. reports 0 as it did for thrashed spawns, or omits input tokens), fall back to `bytes/4` over (spec + agent-memory MEMORY.md + shared pile measured by `wc -c`), and say so in the probe table. The trim (part b) proceeds either way; only the threshold choice (part c) degrades to the estimator.

Artifacts: `tasks/<status>/838/artifacts/spawn-baseline-probe.md` (the full table + method note) + an `epm:progress` marker with the summary table.
