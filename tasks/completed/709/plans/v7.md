## 3. Design

### 3.1 `_ssh_glob_sentinels` — new method in `src/explore_persona_space/backends/runpod.py` (place directly after `_ssh_read_sentinel`, ~line 1193)

```python
def _ssh_glob_sentinels(self, handle: RunHandle) -> Callable[[str, int], list[str]]:
    """Build a remote sibling-sentinel glob bound to ``handle``'s pod (#709).

    SSH sibling of :meth:`_ssh_read_sentinel` and of
    ``artifacts._default_glob_sentinels``: enumerates the attempt-dir
    sibling sentinels ``<issue_dir>/*/<name>`` on the POD filesystem so
    ``_resolve_live_sentinel`` can resolve the #685-secondary stale-baked-
    attempt case on the live-pod path. Semantics mirror the reader:

    * rc=0            -> stdout lines, stripped, sorted (parity with the
                         FS default's ``sorted(...)``).
    * rc!=0 + "no such file" in stderr -> [] (bash passes an unmatched
                         glob literally; ``ls`` errors "No such file or
                         directory" -> zero siblings).
    * any other rc    -> raise. A transport failure must NOT read as
                         "no siblings"; the resolver's existing probe
                         try/except turns the raise into the honest
                         declared-missing FAIL with a note.
    """

    def glob(declared: str, issue: int) -> list[str]:
        del issue  # parity with _default_glob_sentinels: encoded in the path.
        parts = declared.rsplit("/", 2)
        if len(parts) != 3:
            return []  # non-canonical; resolver scope guard blocks this upstream.
        issue_dir, _attempt, name = parts
        remote_cmd = f"ls -1d {_shell_quote(issue_dir)}/*/{_shell_quote(name)}"
        proc = subprocess.run(
            ["ssh", handle.pod_name, remote_cmd],
            capture_output=True, text=True, encoding="utf-8",
            errors="replace", timeout=60, check=False,
        )
        if proc.returncode == 0:
            return sorted(ln.strip() for ln in proc.stdout.split("\n") if ln.strip())
        stderr = (proc.stderr or "").lower()
        if "no such file" in stderr:
            return []
        raise RuntimeError(
            f"ssh sentinel glob on {handle.pod_name} failed "
            f"rc={proc.returncode}: {(proc.stderr or '')[:300]}"
        )

    return glob
```

**Exact SSH command shape** (reusing the reader's transport verbatim — `["ssh", handle.pod_name, <cmd>]`, host/port resolved by the `~/.ssh/config` entry `pod.py config --sync` maintains, exactly as `_ssh_read_sentinel`'s `cat` and `fetch_logs`' `tail` already do):

```
ssh pod-42 "ls -1d '/workspace/eval_results/issue_42'/*/'.completion-sentinel.json'"
```

The `*` sits **between** the two `_shell_quote`d segments, unquoted, so the remote bash expands it; a bash glob expands only to existing paths, so a partial-match set never errors, and a zero-match set passes the literal to `ls` → rc≠0 + "No such file or directory" → `[]`. The pattern `<issue_dir>/*/<name>` string-equals both `_default_glob_sentinels`' probe shape and the #976 stale-clear operand (runpod.py:491, pinned by `test_stale_clear_covers_flat_legacy_and_wildcard_siblings`) — clear breadth == probe breadth stays true by construction on the SSH path too. Deriving `name` from the declared basename follows the #976 precedent in this same file ("derived from sentinel_path itself — no second copy of the root"); under the scope guard, `name == SENTINEL_FILENAME` is guaranteed before any provider is invoked, so parity with the FS default's constant is exact.

def _sentinel_probe_scope_ok(declared: str, issue: int) -> bool:
    """True iff ``declared`` matches the canonical attempt-namespaced shape
    ``.../eval_results/issue_<issue>/<attempt>/<SENTINEL_FILENAME>`` (#709,

### 3.4 Sibling-read wrap — `artifacts.py::_resolve_live_sentinel` (optional concern 3, INCLUDED)

Replace the unguarded comprehension at :884 (`live = [s for s in siblings if s != declared and io._sentinel()(s) is not None]`) with:

```python
    live: list[str] = []
    probe_errors: list[str] = []
    for s in siblings:
        if s == declared:
            continue
        try:
            present = io._sentinel()(s) is not None
        except Exception as exc:  # fail-closed: an unreadable sibling never crashes the gate
            probe_errors.append(f"{s}: {exc}")
            continue
        if present:
            live.append(s)
    if probe_errors:
        return declared, (
            f"declared sentinel {declared} missing AND {len(probe_errors)} sibling "
            f"liveness read(s) raised ({'; '.join(probe_errors)}) — probe inconclusive, "
            "refusing to resolve; FAILing on the declared (missing) path (#709)"
        )
```

**Why refuse-to-resolve on any probe error rather than skip-and-continue:** an errored sibling *might* be live; resolving to a different readable sibling could pick the wrong attempt — the same never-guess conservatism as the ≥2 rule. Outcome is always the structured declared-missing FAIL (via the caller's own read), never a crash and never a silent pass. **This concern is not merely optional polish for #709:** the moment 3.1/3.2 land, sibling liveness reads on RunPod go through `_ssh_read_sentinel`, which **raises `RuntimeError` on any non-"no such file" non-zero rc** (runpod.py:1188-1191) — a transient SSH failure mid-probe would otherwise escape `verify_artifacts` entirely (`_check_sentinel` calls `_resolve_live_sentinel` at :922, OUTSIDE its own try at :926) and crash the orchestrator's finalize instead of returning a verdict. The core change makes finding 3 reachable; shipping them together is the coherent unit.

Update `_resolve_live_sentinel`'s docstring for both behaviors.
