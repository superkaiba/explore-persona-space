# Plan v1 — #2258: catch the #2221 figure-legend arm-slug miss in verify_task_body.py check 28

`kind: infra` · workflow-surface edit (`scripts/verify_task_body.py` + its test file) · 0 GPU-h · single implementer round expected.

## 1. Goal (from task body, ground-truthed)

Check 28 ("figure text opaque config codes", WARN-level) missed the #2221 round-1 arm-slug class: `checkpoint_detection_auc.png` rendered raw arm slugs in its legend and passed silently while the sibling figure WARNed on `mistake_gsm8k`. Fix so the miss is caught, with a test reproducing it and no new false positives on the existing corpus / recent v4 bodies.

## 2. Root cause (probed, not assumed)

The live sidecar (`.claude/worktrees/issue-2221/figures/issue_2221/checkpoint_detection_auc.meta.json`) carries legend labels:

```
hallucination/a_rb_ctx · hallucination/c_map_ctx · hallucination/c_map_pfx
```

These are whitespace-free slash-bearing strings, so `_PATH_SHAPED_RE` (`scripts/verify_task_body.py:9563`, `^\S*[/\\]\S*$`) exempts the WHOLE string as a file path before any token class runs (`_opaque_code_tokens` gate at :9603). Probe results:

- `_opaque_code_tokens("hallucination/a_rb_ctx") == []` (the miss)
- `_opaque_code_tokens("a_rb_ctx") == ["a_rb_ctx"]` (bare slug is ALREADY flagged by snake class (b): `count("_") >= 2`)

**The task body's prescribed fix is a provable no-op.** The suggested regex `^[a-z]_[a-z0-9]+(_[a-z0-9]+)+` requires >=3 segments, so every match carries >=2 underscores and is a STRICT SUBSET of what class (b) (`_SNAKE_TOKEN_RE` + the `count("_") >= 2 or any-digit` filter) already flags. Adding it changes no verdict on any string, and in particular does not touch the demonstrated miss (which never reaches the token classes). This deviation from the body's suggested means is deliberate; the Goal ("catch the miss, test reproducing it, no new FPs") is unchanged.

## 3. Design

### 3a. The fix: narrow the path exemption to path-LIKE strings

Add a predicate `_is_path_like(s: str) -> bool`: `s` is path-like iff it is whitespace-free, contains a `/` or `\`, AND at least one of:

1. leading path/scheme marker: starts with `/`, `./`, `../`, `~`, or `<scheme>://`;
2. >=2 separator characters total;
3. the final segment carries a file extension (`\.[A-Za-z0-9]{1,5}$`).

Replace both consumers of `_PATH_SHAPED_RE` — the whole-string gate (:9603) and the per-word exemption `_only_in_path_words` (:9606-9611) — with `_is_path_like`. A whitespace-free string with exactly ONE separator, no extension, and no leading marker (the `behavior/slug` legend-label shape) is then scanned normally; the token regexes already tokenize across `/` (a non-word char provides the `\b` boundary), so no segment-splitting is needed — `_opaque_code_tokens("hallucination/a_rb_ctx")` yields `["a_rb_ctx"]` via existing class (b).

Every existing path-exemption test pin has >=2 separators AND an extension (`figures/issue_1900/P7.png`, `figures/issue_920/ctx_blk_max@L12.png`, `figures/issue_1902/A->B_x.png`), so all stay exempt.

### 3b. NOT adding the 2-segment single-letter-prefix class (corpus-grounded)

The one token in the incident set the prescribed class was meant to cover that class (b) misses is bare `d_transport` (2 segments, all-alpha). A corpus sweep over ALL 3,241 tracked `figures/**/*.meta.json` (the #1988 calibration method) shows a 2-segment `^[a-z]_[a-z]+$` class would flag **45 distinct / ~9,200 occurrences of legitimate rendered math notation**: `z_marker` (2,237), `z_eos` (2,237), `s_i` (2,003), `n_train` (825), `g_aug` (648), `c_last` (405), `v_x`, `y_hat`, `n_pool`, … — an FP disaster. Decision: do NOT add it. Bare `d_transport` is recorded as an accepted residual in the check-28 docstring, mitigated at figure granularity: the #2221 arm roster always co-renders >=3-segment siblings (`a_rb_ctx` / `b_rb_ans` / `c_map_ctx` / `c_map_pfx`) which flag the figure anyway (per-figure WARN semantics — a missing single token costs nothing once the figure WARNs).

### 3c. False-positive calibration of the narrowing (already measured)

Sweep over the same corpus: 179 distinct / 3,794 occurrences of currently-exempt single-separator extension-less strings would become scanned. They are dominated by mathtext tick labels (`$\mathdefault{10^{0}}$` — the `\` in `\mathdefault` counts as a separator today, an accident this fix removes) and fraction labels (`36/36`, `N/A`, `18/36`). Scanning them yields exactly **ONE distinct new flagged token corpus-wide: `span_mean_context` (3 occurrences)** — itself a genuine 3-segment opaque config slug, i.e. a true positive previously hidden by the exemption. No spurious-WARN surface.
