**Kind:** infra · **Workflow:** v1 · **Estimated GPU-hours (total): 0**

## §0.0 TL;DR

Two-part fix to `scripts/verify_task_body.py`. **(i)** Replace `.lower()` with
`.casefold()` at every regex-`group()` token normalization (26 direct sites +
1 paired indirect site). **(ii)** Make the two crash-class CONSUMERS total —
`_NUMBER_WORDS` at `:16820` and `_BEAT_WORD_TO_KIND` at `:10635` — so an
`IGNORECASE`-matched token that no string normalization can map onto an ASCII
key registers no claim instead of crashing the entire verifier.

Part (ii) is load-bearing, and v2 of this plan was wrong to omit it. `re`'s
`IGNORECASE` fold and `str.casefold()` are DIFFERENT normalizations, and
neither contains the other: `.casefold()` fixes `ſ` (U+017F) and `µ` (U+00B5),
but for **`İ` (U+0130)** `re` folds to the single char `i` while BOTH `.lower()`
and `.casefold()` produce the two-char `i̇` — so a casefold-only fix leaves the
Goal's "cannot crash the whole verifier" claim FALSE at both crash sites.

**Change my mind:** if `sİx same-issue follow-up rounds` and
`one poİnt per seed` both verify without raising after a casefold-only change,
part (ii) is unnecessary and the plan is over-built. (Measured: both still
raise — `ValueError: invalid literal for int() with base 10: 'si̇x'` and
`KeyError: 'poi̇nt'`.) Conversely, if making the two lookups total changes any
verdict on a body whose tokens DO resolve, the totality change is not
conservative and must narrow.

## §2 Background — the mechanism, corrected

**v2 of this plan asserted that `re.IGNORECASE` performs full Unicode case
folding. That is false**, and the error propagated from the reference fix's own
comment (see § Prior art). `re` performs SIMPLE case folding plus a table of
extended pairs; `str.casefold()` performs FULL folding. Measured against the
installed interpreter:

| Char | `re.I` matches ASCII? | `.lower()` | `.casefold()` | Consequence |
|---|---|---|---|---|
| `ſ` U+017F LONG S | yes → `s` | `ſ` (unchanged) | `s` | **casefold FIXES** |
| `µ` U+00B5 MICRO SIGN | yes → `μ` | `µ` (unchanged) | `μ` | **casefold FIXES** |
| `K` U+212A KELVIN | yes → `k` | `k` | `k` | already fine |
| `İ` U+0130 I-WITH-DOT | **yes → `i`** (1 char) | `i̇` (**2 chars**) | `i̇` (**2 chars**) | **NEITHER fixes** |
| `ß` U+00DF | **no** (`ss` does not match `ß`) | `ß` | `ss` | cannot enter |
| `ﬁ` U+FB01 | **no** (`fi` does not match `ﬁ`) | `ﬁ` | `fi` | cannot enter |

Two structural facts follow:

1. **`.casefold()` is a strict improvement** — it closes the `ſ` / `µ` class,
   which `.lower()` leaves open. Part (i) is correct and stays.
2. **`.casefold()` is not sufficient.** For `İ` the regex fold and both string
   folds disagree, so a token the regex MATCHED still misses an ASCII-keyed
   dict. No character-level normalization can close this — only a total lookup
   at the consumer can. Multi-char folds (`ß`, `ﬁ`) are irrelevant in the other
   direction: `re` never matches them against their ASCII expansions, so they
   never get captured by an ASCII alternation.

The class is **structural, not a typo**: any site pairing an `IGNORECASE`
regex with a partial dict/set lookup is defective by construction, and the
file has 24 functions doing the normalization half of it. It is also **not
hypothetical** — scanning all 2,213 live `tasks/**/body.md` files found one
already carrying a full-folding character (`tasks/completed/1967/body.md`,
`µ` U+00B5); not in a triggering position, but such characters do reach
committed bodies.

**Measured reproductions (against the unmodified module):**

```
# :16819 — _count_extra_followup_rounds_v4
"ſix same-issue follow-up rounds"  → matched, .lower()='ſix'  → ValueError (fixed by casefold)
"sİx same-issue follow-up rounds"  → matched, .casefold()='si̇x' → ValueError  ← SURVIVES casefold
# :10635 — _beat_series_claims
"one poİnt per seed"               → matched, .casefold()='poi̇nt' → KeyError   ← SURVIVES casefold
```

The verify driver is a bare comprehension (`[chk(body) for chk in CHECKS[1:]]`,
`:18721`) with no per-check `except`, so either raise takes down the ENTIRE
verifier run for that body — not one check.

**Prior art — the reference fix, and its residual.** Commit

ordinal/direction tokens (Unicode long-s crash)") fixed this class in

### §3.2 Part (i) — the casefold sweep: convert all 26, plus the paired indirect

Convert all 26 direct `.group(...).lower()` sites, a deliberate superset of the
Goal's literal "IGNORECASE + dict-key/equality/`int()`" wording:

1. **Behavior-preserving.** `.lower()` and `.casefold()` are identical on
   ASCII, so a case-SENSITIVE regex over ASCII-only alternations sees no
   change; converting it is a behavioral no-op and a consistency win.
2. **It makes the invariant ratchetable.** With zero `.group(...).lower()`
   remaining, the AST test of §3.5 prevents class reintroduction. A partial
   sweep leaves the ratchet unstatable.
3. **The task body asks for it** — scope item 2 names the `_THIS_REPO_SLUG`
   comparisons as "the same class" and directs the sweep to include them.

Each site is still classified individually (§3.1, reproduced per-site in the
implementer report with each regex's `IGNORECASE` flag read off the **compiled
pattern object**, not the source text) so review can audit the reasoning.

### §3.3 Part (ii) — make the two crash-class consumers total

- **`:16820`** — replace `n = _NUMBER_WORDS.get(word) or int(word)` with:
  resolve `_NUMBER_WORDS.get(word)`; on a miss, `int(word)` **only when
  `word.isdecimal()`**; otherwise `continue` (the match contributes no count).
- **`:10635`** — replace the bare `_BEAT_WORD_TO_KIND[...]` subscript with
  `.get(...)` and skip the match on a miss (no claim registered).

**Why `isdecimal()` and not `isdigit()`:** `str.isdigit()` is True for
superscripts (`'²'.isdigit()` → True) which `int()` REJECTS
(`int('²')` → `ValueError`), so an `isdigit()` guard reintroduces the very
crash at a lower rate. `str.isdecimal()` is exactly Unicode category Nd —
precisely what `\d` matches in a str pattern and precisely what `int()` accepts
(measured: `'٣'` and `'１'` are `isdecimal` and `int()`-parseable; `'²'` is
neither `\d`-matched nor `isdecimal`). This is the one place this plan
deliberately improves on the reference fix, whose `word.isdigit()` guard has
the `²` hole.

**This is not body scope item 3.** Item 3 proposed a DRIVER-level `try/except`
around each check — a blanket catch that would convert any future verifier
defect into a silently-degraded PASS. Part (ii) is a site-level TOTAL LOOKUP:
no exception is caught, no error is swallowed, and the disposition of an
unresolvable token is the same as the disposition of a token that never matched
— no claim, no count contribution. The check's other signals are unaffected
(`:16819`'s events leg still runs, and `footer_n` simply does not gain a
contribution it could not read). Fail-closed at the site, fail-fast preserved
everywhere else.

### §3.5 The invariant and its ratchet

Post-sweep invariant: **zero `<match>.group(...).lower()` expressions in
`scripts/verify_task_body.py`.** Pinned by an AST test, not a text grep — the
AST form is immune to line breaks, whitespace, and comments (a
`.group(\n "num"\n).lower()` split across lines evades a single-line regex and
is caught here).

Detection: walk the module AST for `Call(func=Attribute(attr="lower"),
args=[], keywords=[])` whose `func.value` is itself
`Call(func=Attribute(attr="group"))`. On failure, report every file:line plus
the offending source segment.

**Named residual (disclosed, not covered):** the ratchet sees only the DIRECT
chain. An indirect site — assign from `group()`, `.lower()` later — evades it;
§4 step 2 enumerates those by one-hop local dataflow (that pass is what found
`:3503`), but no static ratchet guards a future one. The code-review lens is
the catching arm, as for the sibling classes in
`.claude/rules/smoke-blind-spots.md`.

## §8 Kill / abort criteria (halt-and-report; none is descope-and-continue)

1. **A defect arm does not reproduce pre-fix.** If any of the four §7 inputs
   verifies WITHOUT raising against the unmodified module, §2's diagnosis is
   wrong for that arm — halt, post the observed behavior, re-diagnose before
   editing.
2. **An ASCII verdict moves.** If any check's verdict changes on a pure-ASCII
   body (full suite + Step 9c mapped selection vs the `origin/main`
   baseline), §3.2's no-op claim is false — halt, name the site and the
   verdict, and narrow the sweep to the crash sites rather than loosening the
   test.
3. **A converted site feeds a display string.** Leave it at `.lower()`, add
   the narrow commented ratchet allowlist entry, and REPORT it. Silent
   conversion of a display site is the banned shape.
4. **Part (ii) changes behavior on a RESOLVABLE token.** If making either
   lookup total alters any outcome for a token that resolves to a number word
   or a decimal, the change is not conservative — halt and report; do not
   adjust the test to match.
5. **The AST ratchet cannot reach zero** for a reason not anticipated in
   §3.5 — report the site and the reason; never weaken the detection
   predicate to make it pass.
6. **A third fold-divergence class surfaces** (a character where regex match
   and total lookup still disagree in a way part (ii) does not cover) — halt
   and report rather than adding ad-hoc per-character handling.

## §11 Decision rationale

| Decision | Value | Source |
|---|---|---|
| Token normalizer | `.casefold()` | Python docs: `str.casefold()` performs FULL case folding; `str.lower()` performs simple lowercasing. Closes the `ſ`/`µ` class (measured, §2 table). NOTE: casefold does NOT reproduce `re.IGNORECASE`'s fold — `re` uses SIMPLE folding + extended pairs (measured: `ss`↛`ß`, `fi`↛`ﬁ`), and the two disagree on `İ`. v2's claim that they agree was wrong. |
| Crash-class consumers | total lookup (`.get` + skip) | Measured necessity: `sİx` and `poİnt` still raise post-casefold (§2). No character-level normalization can close a fold disagreement; only the consumer can. |
| Digit guard | `str.isdecimal()` | Measured: `isdecimal` == Unicode Nd == what `\d` matches and `int()` accepts; `isdigit()` admits `²`, which `int()` rejects. Improves on `0403597c73`'s `isdigit()`. |
| Sweep breadth | all 26 direct + the `:3503` pair | Task body scope item 2 + §3.2 + §3.4 |
| Ratchet mechanism | AST walk, not text grep | Immune to line breaks/comments; the `argcheck` whole-module-scope precedent in `.claude/rules/code-style.md` (a narrower scope is escapable by relocating the expression) |
| Driver-level `except` | NOT added | Declined at the clarifier gate — "Fail fast — never hide failures" (CLAUDE.md Critical Rules); §3.3 distinguishes it from the site-level total lookup |
| #2279's residual | routed, not fixed here | Its code is not on `main` and #2279 has a live owning session; a durable marker on #2279 is the channel (CLAUDE.md § teammate coordination — an independent session is not SendMessage-addressable) |
