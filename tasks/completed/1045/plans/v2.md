# Plan — issue #1045: choom-protect Step 9c gates + VM long fits by default

### 0.0 TL;DR (plain English)

- **What I'll change:** I'll make earlyoom protection the default launch form instead of an after-the-kill improvisation, in three places: the Step 9c gate pytest runs get a one-line "lower this shell's OOM priority" (`sudo -n choom -n -600 -p $$`) at the top of the existing snippets (children inherit it, so nothing else about the snippets changes); the detached ledger-refresh snippet gets the already-canonical pid-capture + choom session-sweep it was missing; and the vectorize-fits rule gets a fix-list item pointing implementers at the canonical detached+choom+checkpoint launch recipe in SKILL.md.

- **What would change my mind:** if `sudo -n choom` were not passwordless on this VM, or if the Bash tool reused one long-lived shell across calls (self-choom would then leak −600 to unrelated work) — I probed both live and neither holds.

## 2. Prior work

- **The existing convention (#957; incidents #811/#833):** SKILL.md § "Detached VM-side long compute phases" (lines ~5295–5357) mandates, for any DETACHED >~15 min VM phase: the `bash -c 'setsid nohup env … <cmd> … & echo $!'` pid-capture wrapper, then `bash -o pipefail -c 'pgrep -s "$1" | xargs -rn1 sudo -n choom -n -600 -p' _ "$PHASE_PID"`, the `choom=ok|failed` breadcrumb token, the −600 derivation (NOT −1000 — earlyoom and the kernel skip −1000 entirely; a runaway phase must stay killable), and the collateral-kill signature + relaunch-once-then-pod-pivot ladder. `.claude/rules/code-style.md` § "Always run with `nohup`…" carries the short-form mirror and already names SKILL.md as the canonical reference — the precedent for "reference, don't fork."
- **The earlyoom config (probed live, 2026-07-05):** `/etc/default/earlyoom` = `EARLYOOM_ARGS="-m 10 -s 10 -r 3600 --prefer (^|/)(pytest|python3?)$ --avoid (^|/)(sshd|systemd|dockerd|node|claude|happy)$ -n"`. **`pytest` is explicitly in the `--prefer` regex** — a gate pytest run carries the +300 badness bonus directly, which is why the gates keep being the designated victim. The −600 derivation's `--prefer`-bonus assumption is current.
- **Live probes (this VM, 2026-07-05):**
  - `sudo -n choom -n -600 -p $$` → succeeds passwordless; `choom -p $$` confirms adj −600, oom_score dropped 666 → 267 (Δ≈399 display points — matches the "~400 display points" figure in the SKILL.md derivation).
  - Inheritance: after self-choom, `bash -c 'choom -p $$'` (a fresh forked+exec'd child) reads adj −600 — oom_score_adj inherits across fork AND exec (and across `setsid`, which changes session, not adj). This is the load-bearing mechanism for the foreground design.
  - Fresh shell per Bash tool call: two consecutive calls had different `$$` (3286013 → 3289606) and the second call's adj was back at 0 — the harness spawns a fresh shell per call ("shell state does not persist"), so a self-choom dies with the call.
  - `systemd-run --user --scope -q -p OOMScoreAdjust=-600 true` → `Unknown assignment: OOMScoreAdjust`, rc=1. The scope unit type on this systemd version does not accept the property at all (and an unprivileged user manager could not grant a negative adj regardless — negative values need CAP_SYS_RESOURCE). **Option (iii) is dead, grounded.**
  - `choom --help`: supports both `choom -n N -p pid` (running process) and `choom -n N -- command` (exec-with-adj). The exec form was considered and rejected for the gates (it would run pytest as root under `sudo -n choom -n -600 -- …`).
- **`scripts/step9c_baseline.py` (read):** `cmd_refresh` runs ONE full-suite pytest via `run_pytest` → `subprocess.Popen(..., start_new_session=True)` (own session, group-killed on timeout). `compare --run-pristine` runs `run_single_file_pristine` — SHORT bounded single-file pytest runs per new-failure file (the "fourth site"): foreground within the gate call, but seconds-to-minutes each, and covered for free by the gate-shell self-choom when 1b→1d run in one Bash call (they must — `PYTEST_RC` is a shell variable compare consumes, and shell state does not persist across calls). **No script change needed:** `start_new_session=True` children INHERIT the adj set on the refresh/gate process before they fork (probe above).

- **Snippet-pinning tests:** `tests/test_workflow_setsid_detach_convention.py` pins `"setsid nohup"` substrings in SKILL.md + code-style.md (additive edits keep it green) plus a live setsid-survival mechanism test; `tests/test_step9c_baseline.py` tests the untouched script.

### Rejected protection forms for the foreground gates (design question 1, resolved)

- **(i) background-within-the-call + choom-on-pid + `wait`:** requires reworking `PYTEST_OUT=$(...)` to a log file + `cat`, races `timeout`(1)'s immediate fork (a child forked before the choom does NOT inherit), and the descendant sweep depends on job-control pgid state. More delta, more failure modes. Rejected.
- **(ii) `setsid` within the call + session-sweep verbatim:** the pid-captured workload is not a `wait`-able child of the outer shell (it is the wrapper-bash's orphaned child), so `PYTEST_RC` would have to round-trip via a file — breaks the exact-rc contract elegance. Rejected.
- **(iii) `systemd-run --user --scope -p OOMScoreAdjust=-600`:** probed DEAD on this VM (`Unknown assignment: OOMScoreAdjust`, rc=1; negative adj additionally needs CAP_SYS_RESOURCE the user manager lacks). Rejected, grounded.
- **(iii-b) `sudo -n choom -n -600 -- <pytest cmd>` (choom's exec form):** runs pytest AS ROOT (root-owned junit/caches, altered test behavior). Rejected.
- **CHOSEN (iv): self-choom the gate shell (`sudo -n choom -n -600 -p $$`) + fork/exec inheritance.** Zero contract change, zero race, probe-verified inheritance and fresh-shell-per-call scoping, covers 1b + 1c + compare's pristine runs (+ 1d when same-call) with one line.

Design question 2 (protect 1b touched-scope?): **YES** — #995's kill hit a gate run at ~42%; pytest's `--prefer` +300 applies to any pytest regardless of scope; the cost is one fail-open line already needed for 1c; a touched-scope run on a heavy test file can run many minutes under load.

## 10. Kill criteria — what would make this change wrong

- If negative `oom_score_adj` were impossible without root AND `sudo -n` unavailable → the change would degrade to documenting the failure mode only. **Probed: does not hold** (sudo -n works).
- If the Bash tool reused one long-lived shell → the self-choom form would leak protection session-wide and the design would pivot to form (ii) (setsid + session-sweep + rc-via-file) despite the contract cost. **Probed: does not hold.**
- If the earlyoom config dropped the `--prefer` python/pytest bonus, the −600 magnitude would need re-derivation (the existing SKILL.md text already mandates re-deriving from the decomposition on config change — no new duty here). Current config confirmed.
- If a future harness guard blocked `sudo` in orchestrator Bash calls, the fail-open path makes the gates behave exactly as today (unprotected + warned) — the change can never make gates WORSE than the status quo.

## 11. Decision Rationale

- **Protection form for foreground gates = self-choom the gate shell.** What: `sudo -n choom -n -600 -p $$` preamble; children inherit. Why: zero change to the PYTEST_OUT/PYTEST_RC/junit/timeout/guards contract, no fork race, covers all four launch sites in the normal single-call shape. Source: live VM probes (inheritance, passwordless sudo, fresh-shell-per-call) + `choom --help`; alternatives (i)/(ii)/(iii)/(iii-b) rejected in §4 with grounds.
- **−600 (not −1000, not another value).** What: reuse the convention's value. Why: single fleet-wide convention; probe reproduced the documented ~400-display-point delta; −1000 would exempt the gate from OOM entirely (banned by the existing derivation — a runaway gate must still die first). Source: SKILL.md § Detached VM-side long compute phases (#957 derivation; incident #811 badness decomposition); `/etc/default/earlyoom` read 2026-07-05.
- **Fail-open (warn + `choom=failed`, never block).** What: keep the existing failure semantics for the gates too. Why: a gate blocked by a protection helper inverts the priority (protection is best-effort re-ordering, the gate verdict is load-bearing); consistent with the detached-phase contract verbatim. Source: SKILL.md ~5337–5342 ("never block a launch on choom").
- **Protect 1b touched-scope as well as 1c.** What: same preamble in both blocks. Why: #995's gate died at ~42% (badness 969); the `--prefer` bonus is scope-independent; marginal cost one line. Source: task body incident list; earlyoom config probe.
- **1d refresh uses the session-sweep form (not self-choom).** What: canonical pid-capture wrapper + `pgrep -s` sweep. Why: the refresh DETACHES and outlives the call — the convention's exact target shape; self-choom of the launching shell would work too (inheritance) but the sweep form matches the existing detached-phase snippet verbatim and produces the required `pid= log= choom=` breadcrumb. Source: SKILL.md ~5300–5304; `tests/test_workflow_setsid_detach_convention.py` mechanism test.
- **Single source of truth = SKILL.md § Detached VM-side long compute phases.** What: vectorize item 7 + gotchas.md reference it; no snippet duplication. Why: forked snippets rot (the task's own constraint); code-style.md's existing short-form mirror already models reference-not-fork. Source: task body constraints; code-style.md nohup bullet.
