## Bug (verified at clarify time)

`_row_is_parked()` (sweep script L283-300) accepts only: leading `parked`,
`routed: parked`, the three mid-note park declarations, or a structured
`routed` field containing "parked". The #1718 urgent park (ts
2026-07-27T14:38:28Z, fp `06bc0203d759`) contains none — `re.finditer
(r"(?i)parked", note)` → 0 hits — so `sweep()` never emitted it and BOTH
consumers (watcher router + nightly Step C) were blind for ~16 h while main
stayed red. The #1681 grammar prescribes the three in-block fields but never
required a "parked" token; emitter and enumerator disagreed on the park
surface.

## Method delta (what differs from prior related work)

Prior sweep-predicate work (#1281) widened `_row_is_parked` with the
mid-note declaration arm. This change adds a fifth accept arm scoped to the
URGENT class: a note is PARKED when (a) it LEADS with the `URGENT-PARK`
token (analogous to `_PARKED_LEAD_RE`), OR (b) its formal candidate block
(`_BLOCK_RE` extraction — reuse the existing regex, never a bare substring
scan of the whole note) carries an `urgency: main-red` field. Rationale for
(b): the #1681 grammar defines the urgent fields as "parked candidates
only" — an urgent-tagged formal block IS a park by definition, and a
mis-tagged routed candidate is closed by suppression rules 1/2 anyway
(demonstrated live by the #1718→#1740 record). Scoping (b) to the block
keeps prose QUOTING the grammar (e.g. a note discussing `urgency: main-red`)
out, preserving the casual-mention exclusion.

## File paths + concrete diffs

   - Add `_URGENT_PARK_LEAD_RE = re.compile(r"\s*urgent-park\b", re.IGNORECASE)`

     `if _URGENT_PARK_LEAD_RE.match(note): return True` and
