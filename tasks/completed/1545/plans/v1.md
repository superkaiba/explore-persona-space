    var is SCRUBBED (a git-hook / pre-commit caller exports GIT_DIR /
    GIT_INDEX_FILE — a latent leak the old ``{**os.environ, ...}`` merge
    passed straight into the hook), then git resolution is PINNED to the
    throwaway on-main fixture: GIT_DIR/GIT_WORK_TREE take precedence over
    the hook's hardcoded ``git -C "$REPO"`` discovery (verified 2026-07-19

    classifier (L1229-1233) read the FIXTURE, never the shared root — a
    concurrent shared-root git op can no longer flip probe verdicts

    ``EPM_GUARD_DENY_SIDECAR`` pin unchanged (#1528)."""
    env = {k: v for k, v in os.environ.items() if not k.startswith("GIT_")}
    env["GIT_DIR"] = str(git_fixture / ".git")
    env["GIT_WORK_TREE"] = str(git_fixture)
    env["EPM_GUARD_DENY_SIDECAR"] = "/dev/null"
    return env


def _build_root_guard_fixture(tmp: Path) -> None:
    """``git init`` a minimal always-on-``main`` fixture in ``tmp``: branch
    ``main``, ONE empty-tree commit. The empty tree means the hook's
    ``cat-file -e "HEAD:$arg"`` probe can never resolve a doc example
    against the fixture, and ``show-ref``/``rev-parse`` resolve strictly
    LESS than the real repo (only ``main``/``HEAD``/the fixture sha) — so
    the fixture cannot mint a NEW block verdict (2026-07-19 audit: 0/54
    live fence-verdict changes vs ambient). Identity via ``-c`` flags so
    no global git config is required. Raises on failure (caller converts
    to ONE loud lint error — fail loud, never a silent skip)."""
    scrub = {k: v for k, v in os.environ.items() if not k.startswith("GIT_")}
    common = dict(
        check=True, capture_output=True, text=True,
        timeout=_ROOT_GUARD_TIMEOUT_S, env=scrub,
    )
    subprocess.run(["git", "init", "-q", "-b", "main", str(tmp)], **common)
    subprocess.run(
        ["git", "-C", str(tmp), "-c", "user.name=workflow-lint",
         "-c", "user.email=workflow-lint@localhost",
         "commit", "-q", "--allow-empty", "-m", "root-guard probe fixture"],
        **common,
    )

### 4.4 Design options weighed (summary; full rationale §11)

1. **Caller-side `GIT_DIR`/`GIT_WORK_TREE` fixture pin — CHOSEN.** Deterministic by construction, hook byte-unchanged, no new bypass surface (git's env-var precedence pre-exists; the harness invokes the hook for real without `GIT_DIR` set — unchanged), and verified end-to-end at plan time.
2. **Hook-side `REPO` env override — REJECTED.** Hands every session an env knob that disarms the live guard; strictly worse than (1), which achieves isolation without touching the hook. Only revisit if (1) were unworkable (it is not — verified).
3. **Lock serialization — REJECTED as primary, retained as the kill-criterion fallback.** `~/.task-workflow/root-sync.lock` covers only `sync_repo_root.py`, not arbitrary root git ops; a long rebase holds state off-main for minutes (probes would block or still flap); adds gate latency and cross-process coupling.

**Scope decision:** pin the fixture for BOTH the self-test AND the fence-scan probes (full determinism). The self-test-only variant would leave the production fence scan silently under-enforcing during off-main windows — the exact silent half of the incident. Drift risk of the full scope was the open question; it is now measured at 0/54 (§6 Evidence), and the fixture's empty tree makes new-block drift impossible by construction (it resolves strictly less than the real repo; `main` is a textual allow-arm in the hook's case statement before any git call).

## 11. Decision Rationale

- **What:** caller-side `GIT_DIR`/`GIT_WORK_TREE` fixture pin (option 1), full scope (self-test + fence scan). **Why:** removes the shared-state dependency entirely; hook byte-unchanged; no new bypass surface. **Source:** this plan's 2026-07-19 empirical probes (precedence + reproduce-first + 0/54 drift audit) + the #1528 env-only probe-pin precedent (commit `8a556b1a7e`) + incident #1506. **Alternatives:** hook-side `REPO` override (rejected — disarms the live guard via env), lock serialization (rejected as primary — incomplete coverage, latency; retained as K1 fallback).
- **What:** scrub ALL ambient `GIT_*` keys, not just set the two pins. **Why:** today's `{**os.environ, ...}` merge inherits `GIT_INDEX_FILE`/`GIT_COMMON_DIR`/etc. from git-hook/pre-commit caller contexts (pre-commit invokes `workflow_lint.py`, `.pre-commit-config.yaml` L24-41) — a latent second leak; explicit `GIT_DIR`+`GIT_WORK_TREE` plus a scrub is deterministic against every `GIT_*` override git honors. **Source:** git(1) environment-variable semantics, verified for the two pins empirically; probe calls are read-only so the scrub is side-effect-free. **Alternatives:** pin only `GIT_DIR`/`GIT_WORK_TREE` (leaves `GIT_COMMON_DIR`/`GIT_INDEX_FILE` inheritable — rejected as incomplete for one extra line of code).
- **What:** empty-tree, single-empty-commit fixture on branch `main`. **Why:** `main` satisfies the on-main gate; the empty tree makes `cat-file -e HEAD:<arg>` unresolvable for every doc example, and refs resolve strictly less than the real repo → new-BLOCK drift impossible by construction; `main` itself is a textual allow-arm in the hook's classifier before any git call. **Source:** hook L1229-1233 + L1540-41 (read this round); 0/54 drift audit. **Alternatives:** mirror/clone of the real repo (heavy, and re-imports the very state-dependence being removed).
