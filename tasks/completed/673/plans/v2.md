## 0. Plan Summary (technical)

**Validation:** one micro-benchmark script + one CPU-only pytest. The script loads
`Qwen/Qwen2.5-7B-Instruct` on a real GPU and runs N=50 repeated
`extract_layer_activations(model, ids, [7,14,21])` calls on a fixed ≤512-token
prompt, in 4 ARMs = {hook path, old `output_hidden_states=True` path} ×
{`expandable_segments:True`, default allocator}, recording
`torch.cuda.memory_allocated/reserved()` after `torch.cuda.synchronize()` each iter.
**Hyperparameters:** none are model hyperparameters — this is a fixed-prompt
micro-benchmark. Load-bearing knobs are N=50 (`Source: #545` 5-round growth →
need ≥5 "rounds" of headroom), warmup=5 (excluded from the flat assertion),
`ABS_TOL_GiB=1.0` and `SLOPE_TOL_GiB_per_iter=0.02` (grounded in the #545
22→30→38 GiB growth rate, §11). **Baselines/controls:** the OLD
`output_hidden_states=True` arm is the positive control — under
`expandable_segments:True` it MUST retain materially more reserved memory (or grow)
than the hook arm, else the read does not demonstrate the fix removed a real
growth. **Loss surface:** N/A — no training. **Compute:** ~0.25 GPU-h on 1× A100-80
(GCP `lora-7b` lane) or 1× H100 (`backend: runpod --intent eval`); 4 arms ×
~55 forwards each ≈ a few minutes wall. **NOT the GCP `eval` lane** — that is a
1× L4 (24 GB), too small for a 7B + the positive-control arm's deliberate growth.
**Evaluation:** PASS iff (a) hook arm flat under BOTH allocators
(`max−min reserved[warmup:] < ABS_TOL_GiB` AND last-30 linear-fit
`|slope| < SLOPE_TOL_GiB_per_iter`) AND (b) positive control under
`expandable_segments:True` retains materially more reserved memory than the hook
arm. **Risks:** (1) positive-control arm is flat too (allocator masks the bug at
N=50 / one model copy — would mean the read is inconclusive, surface it, do not
silently PASS); (2) hook arm grows (a #671 regression — escalate).

Estimated GPU-hours (total): 0.25

## 1. Goal

Confirm that `torch.cuda.memory_reserved()` stays **flat** across N≈50 repeated
`extract_layer_activations` calls on a real GPU, under the
`PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` allocator that #545 reported
growth under — the authoritative sufficient check the #671 CPU `ru_maxrss` proxy
cannot perform. #671 fixed the bug (hook-based subset reads instead of
`output_hidden_states=True`) and locked it with bit-for-bit identity + an AST
regression-lock + an **advisory** CPU proxy. The CPU proxy only confirms no
Python-level reference is retained (necessary, not sufficient); the real bug is
CUDA-allocator segment retention, a GPU property absent on CPU. This task supplies
the sufficient real-GPU read and demonstrates, via a positive control on the old
path, that the fix removed a *real* growth rather than that the new path merely
happens to be flat.

  caching pool and `memory_reserved()` is the high-water mark of segments the
  allocator holds from the driver. A code path that does NOT retain references
  iteration-to-iteration (the hook path) lets reserved memory plateau after warmup
  under both allocators; a path that materializes a large transient per-forward
  (the old path) keeps reserved memory at the larger high-water mark. The #545
  *growth* across rounds was the application-level accumulation the #671 fix
  removed; this benchmark reproduces the per-iteration footprint difference that
  the accumulation was built on. (PyTorch CUDA semantics + memory-management docs;
  no arXiv grounding required for a documented allocator behavior — the load-bearing
  number is the #545 growth RATE, grounded below.)

## 3. Hypothesis

- **H1 (primary):** On the hook arm, `torch.cuda.memory_reserved()` is flat after a
  ~5-iter warmup, under BOTH `expandable_segments:True` and the default allocator.
  Falsified if reserved memory over `[warmup:50]` spans `≥ ABS_TOL_GiB` OR the
  last-30 linear-fit slope `≥ SLOPE_TOL_GiB_per_iter` — that would be a #671
  regression.
- **H2 (positive control):** On the old `output_hidden_states=True` arm under
  `expandable_segments:True`, reserved memory is **materially higher** than the hook
  arm (`max(reserved_old[warmup:]) − max(reserved_hook[warmup:]) ≥ CTRL_GAP_GiB`),
  and ideally shows the across-iteration growth the fix removed. Falsified if the old
  arm is also flat AND at the same reserved level as the hook arm — in which case
  the benchmark at N=50 / one model copy does not exhibit the bug and the read is
  **inconclusive** (reported as such, NOT a PASS; see §7 Failure modes).
- **Quantitative anchor:** #545's +8 GiB-per-step growth (22→30→38) implies that a
  path that retains the all-layers materialization across iterations should leave a
  reserved high-water mark inflated by *at least* the size of one all-layers
  materialization.
  For Qwen-2.5-7B (29 hidden states × bf16 × seq≤512 × hidden 3584 ≈
  29 × 512 × 3584 × 2 B ≈ 0.10 GiB per single forward's full tuple, vs ~0.01 GiB for
  the 3-layer subset) the *per-forward* delta is modest at seq=512; the dominant #545
  signal was cross-round accumulation, so the positive control's discriminating
  signal is the **retained high-water + any monotone climb**, read under
  `expandable_segments:True`. `CTRL_GAP_GiB` is set conservatively (§11).

```python
# scripts/issue673_gpu_memory_validation.py
"""Real-GPU memory-non-growth validation for #671's hook-based extraction.

Runs N repeated extract_layer_activations calls on Qwen-2.5-7B-Instruct on a real
GPU, across 4 arms {hook, old output_hidden_states=True} x {expandable_segments:True,
default allocator}, recording torch.cuda.memory_{allocated,reserved} per iter.
Asserts the hook arm is flat (the #545/#667 fix); the old-path arm under
expandable_segments is the positive control (must retain materially more / grow).
"""
import json, os
from pathlib import Path
import numpy as np
import torch
from explore_persona_space.orchestrate.env import load_dotenv
from explore_persona_space.analysis.extraction import extract_layer_activations

# --- constants (see §11 Decision Rationale) ---
MODEL = "Qwen/Qwen2.5-7B-Instruct"
LAYERS = [7, 14, 21]            # the live #545/#651/#667 subset
N_ITERS = 50
WARMUP = 5
MAX_TOKENS = 512               # the size the live line actually reads
ABS_TOL_GiB = 1.0
SLOPE_TOL_GiB_per_iter = 0.02
CTRL_GAP_GiB = 0.05            # positive-control min reserved gap (conservative; §11)
GiB = 1024 ** 3
OUT_DIR = Path("figures/issue_673")

def _fixed_ids(tok, device):
    # Deterministic <=MAX_TOKENS prompt. torch.manual_seed(0) only affects nothing
    # here (greedy/no sampling) but set it for full reproducibility metadata.
    torch.manual_seed(0)
    text = ("The assistant gives careful, structured advice. " * 40)  # ~ a few hundred tok
    ids = tok(text, return_tensors="pt", truncation=True,
              max_length=MAX_TOKENS).input_ids.to(device)
    assert ids.shape[1] <= MAX_TOKENS, ids.shape
    return ids

@torch.no_grad()
def _old_path_read(model, ids, layers):
    # The PRE-#671 read: full tuple, subset indexed. The thing #671 removed.
    # MUST be @torch.no_grad() to MATCH the hook helper (extract_layer_activations
    # is itself @torch.no_grad()). Without this, the old arm would retain an autograd
    # graph (saved-activation buffers across all 29 hidden states) and inflate the
    # positive-control reserved gap with an autograd artifact, NOT the pre-#671
    # hidden_states tuple keepalive the fix removed -> a false-positive gap routes
    # straight to a false PASS. Matching grad-enablement isolates the variable to
    # output_hidden_states=True vs the hook fix.
    out = model(input_ids=ids, output_hidden_states=True)
    return {L: out.hidden_states[L + 1] for L in layers}  # hs[L+1] convention

def _seg_stats() -> dict:
    """Segment-level cuda memory_stats fields (lets the analyzer separate
    'segment count grew' from 'segment size grew' in an INCONCLUSIVE-gap case)."""
    s = torch.cuda.memory_stats()
    return {
        "reserved_current": int(s.get("reserved_bytes.all.current", 0)),
        "reserved_peak": int(s.get("reserved_bytes.all.peak", 0)),
        "segment_current": int(s.get("segment.all.current", 0)),
        "segment_peak": int(s.get("segment.all.peak", 0)),
    }

def run_arm(model, ids, *, use_hook: bool) -> dict:
    """N_ITERS calls; record allocated+reserved (bytes) + segment-level stats
    after sync each iter. Runs under torch.inference_mode() so BOTH arms are
    grad-disabled identically (the hook helper is already @torch.no_grad(); the
    old arm is decorated @torch.no_grad() above). The inference_mode wrap +
    grad assertion guard against a future edit silently re-enabling autograd."""
    allocated, reserved, seg = [], [], []
    with torch.inference_mode():
        for _ in range(N_ITERS):
            assert not torch.is_grad_enabled(), "arm loop must run grad-disabled"
            if use_hook:
                captured = extract_layer_activations(model, ids, LAYERS)
            else:
                captured = _old_path_read(model, ids, LAYERS)
            torch.cuda.synchronize()
            allocated.append(torch.cuda.memory_allocated())
            reserved.append(torch.cuda.memory_reserved())
            seg.append(_seg_stats())
            del captured                  # drop the per-iter reference (both arms, fair)
    return {"allocated": allocated, "reserved": reserved, "segment_stats": seg,
            "grad_enabled": False, "inference_mode": True}

def _flat(reserved_bytes) -> dict:
    r = np.asarray(reserved_bytes[WARMUP:], float) / GiB
    span = float(r.max() - r.min())
    tail = np.asarray(reserved_bytes[-30:], float) / GiB
    slope = float(np.polyfit(np.arange(len(tail)), tail, 1)[0])  # GiB / iter
    return {"span_GiB": span, "tail_slope_GiB_per_iter": slope,
            "flat": span < ABS_TOL_GiB and abs(slope) < SLOPE_TOL_GiB_per_iter}

def main():
    load_dotenv()
    assert torch.cuda.is_available(), "real-GPU validation requires CUDA"
    # NOTE: PYTORCH_CUDA_ALLOC_CONF must be set BEFORE the CUDA context inits, so the
    # two allocator regimes are run as TWO separate process invocations (see launch),
    # NOT toggled in-process. This script reads the current regime from the env and
    # records it; the launcher sets the env per invocation.
    regime = os.environ.get("PYTORCH_CUDA_ALLOC_CONF", "default")
    from transformers import AutoModelForCausalLM, AutoTokenizer
    tok = AutoTokenizer.from_pretrained(MODEL, token=os.environ.get("HF_TOKEN"))
    model = AutoModelForCausalLM.from_pretrained(
        MODEL, torch_dtype=torch.bfloat16, token=os.environ.get("HF_TOKEN")).to("cuda")
    model.eval()
    ids = _fixed_ids(tok, "cuda")

    results = {"model": MODEL, "layers": LAYERS, "n_iters": N_ITERS, "warmup": WARMUP,
               "max_tokens": int(ids.shape[1]), "allocator_regime": regime,
               "torch": torch.__version__, "arms": {}}
    for use_hook, name in [(True, "hook"), (False, "old_ohs_true")]:
        torch.cuda.empty_cache(); torch.cuda.reset_peak_memory_stats()
        arm = run_arm(model, ids, use_hook=use_hook)
        arm["flatness"] = _flat(arm["reserved"])
        results["arms"][name] = arm

    OUT_DIR.mkdir(parents=True, exist_ok=True)
    tag = "expandable" if "expandable_segments:True" in regime else "default"
    (OUT_DIR / f"memory_curves_{tag}.json").write_text(json.dumps(results, indent=2))
    _plot(results, OUT_DIR / f"memory_vs_iter_{tag}.png")   # 2 lines: hook vs old, reserved
    print(json.dumps({"regime": tag, **{k: v["flatness"] for k, v in results["arms"].items()}}, indent=2))

if __name__ == "__main__":
    main()
```

Key implementation notes:

- **Two allocator regimes = two process invocations**, because
  `PYTORCH_CUDA_ALLOC_CONF` is read once at CUDA-context init and cannot be flipped
  in-process. The launcher (§7 launch) runs the script twice with the env set/unset,
  producing `memory_curves_expandable.json` + `memory_curves_default.json` and two
  PNGs.
- **Fairness:** both arms call `del captured` each iter and run inside the same
  process per regime. The old arm uses the EXACT pre-#671 read shape
  (`out.hidden_states[L+1]`, full tuple) so the comparison isolates the
  all-layers-materialization difference.
- **Grad-disablement is matched across both arms (Must-Fix, v2).** The hook helper
  `extract_layer_activations` is itself `@torch.no_grad()`; the old-path read
  `_old_path_read` is decorated `@torch.no_grad()` to MATCH, and `run_arm` additionally
  wraps the whole per-arm loop in `torch.inference_mode()` with an
  `assert not torch.is_grad_enabled()` at the top of each iter. Without this, the old
  arm would retain an autograd graph (saved-activation buffers across all 29 hidden
  states) and the positive-control's reserved-memory gap could be inflated by autograd
  retention rather than the pre-#671 `hidden_states`-tuple keepalive the fix removed —
  a false-positive gap → a false PASS, the worst outcome for a validation whose entire
  purpose is the positive control. Matching grad-enablement isolates the variable to
  `output_hidden_states=True` vs the hook fix. The per-arm JSON records
  `grad_enabled: false` + `inference_mode: true` so the test-verdict reader / analyzer
  can mechanically verify both arms ran matched; the `assert` makes a future edit that
  drops the decorator fail loud.
- **Segment-level memory stats per iter (non-blocking statistics enhancement, v2).**
  `_seg_stats()` records `reserved_bytes.all.{current,peak}` and
  `segment.all.{current,peak}` from `torch.cuda.memory_stats()` alongside the existing
  allocated/reserved scalars each iteration. This is NOT a new arm — just a richer
  per-iter record. It lets the analyzer separate "segment COUNT grew" from "segment
  SIZE grew" in an INCONCLUSIVE-gap scenario and makes the result debuggable.
- **One model copy** (not base+trained). The per-forward materialization difference
  is the same with one copy; two copies only double magnitude and risk OOM. Stated
  in §3 H2 and §9.
- **`reset_peak_memory_stats` + `empty_cache` between arms** so each arm's reserved
  curve starts from the model-weights baseline, not the previous arm's high-water.

## 5. Conditions and Controls

| Plain-English name | What it tests | What it controls for | Config slug |
|---|---|---|---|
| Hook path, expandable allocator | the #671 fix on the allocator #545 grew under | the real bug regime | `hook_expandable` |
| Hook path, default allocator | the fix is flat regardless of allocator | allocator attribution | `hook_default` |
| Old full-tuple path, expandable allocator | **positive control** — the growth the fix removed | that the flat read is meaningful (a fix removed something) | `old_expandable` |
| Old full-tuple path, default allocator | the old path's baseline footprint without the fragmentation mitigation | allocator attribution on the old path | `old_default` |

The positive control (`old_expandable`) is the load-bearing control: without it, a
flat hook curve could mean "the fix works" OR "nothing ever grew at this scale". A
material gap (or growth) on `old_expandable` rules out the latter.

### 6.2 PASS criteria (test-verdict path)

PASS requires ALL of:

1. **Hook arm flat under BOTH allocators:** for `hook_expandable` AND `hook_default`,
   `span_GiB < ABS_TOL_GiB` (= 1.0) AND `|tail_slope_GiB_per_iter| < SLOPE_TOL` (= 0.02).
2. **Positive control discriminates:** under `expandable_segments:True`,
   `max(reserved[old_expandable][warmup:]) − max(reserved[hook_expandable][warmup:]) ≥ CTRL_GAP_GiB`
   (= 0.05 GiB) OR the old arm shows a positive monotone trend the hook arm does not.
3. **Both allocator regimes reported** (both JSONs + both PNGs produced and committed)
   so the read is attributable to the allocator.
4. The §4.4 pytest passes (constants + `_flat` logic +, post-run, the committed-JSON
   group-3 assertions).

If criterion 1 fails → **#671 regression** (escalate, do NOT land — §7).
If criterion 2 fails (old arm also flat / no gap) → result is **INCONCLUSIVE**, not
PASS: report that the benchmark at N=50 / one model copy does not exhibit the #545
growth, and either (a) escalate to a 2-model-copy / longer-N re-run, or (b) record
the inconclusive read with the CPU proxy + bit-for-bit identity as the standing
evidence. Surfaced honestly, never silently passed.

## 11. Decision Rationale (load-bearing knobs)

This is a fixed-prompt micro-benchmark — no model hyperparameters. The load-bearing
knobs are the iteration count, warmup, and the three tolerances.

- **N_ITERS = 50.**
  - *Why:* #545 grew over **5 rounds** (22→30→38 GiB). N=50 gives ≥10× the
    round-count of headroom to observe either a flat plateau (fix works) or a
    monotone climb (regression / positive control), with a stable last-30 window for
    the slope fit.
  - *Source:* `#545` (22→30→38 GiB across 5 rounds; cited in the #671 body) +
    the task body's own "N≈50".
- **WARMUP = 5.**
  - *Why:* the first few iterations include lazy CUDA kernel/workspace allocation
    and cuDNN autotune, which inflate reserved memory before it plateaus; excluding
    them isolates steady-state growth. 5 is small relative to N=50.
  - *Source:* standard CUDA-benchmark warmup practice; the #671 CPU proxy uses an
    analogous first-half/second-half split (`first_half_peak` over `rss[:10]`).
- **ABS_TOL_GiB = 1.0.**
  - *Why:* #545's growth was **+8 GiB per labeled step** (22→30→38); a real
    regression at N=50 would span many GiB. 1.0 GiB is comfortably below any real
    accumulation signal (an order of magnitude under a single +8 GiB step) yet above
    per-iteration allocator jitter / fragmentation noise (sub-GiB). A flat hook curve
    sits far below this. The tolerance is unchanged from v1 — it sits far below either
    reading of the #545 rate, so the prose correction does not move it.
  - *Source:* derived from `#545`'s +8 GiB/step growth (22→30→38; set the tolerance
    well below one step's growth so a single step of accumulation trips it).
- **SLOPE_TOL_GiB_per_iter = 0.02.**
  - *Why:* #545's +8 GiB over a step of ~10 iterations ≈ +0.8 GiB/iter when growing.
    0.02 GiB/iter (≈ +0.6 GiB over the last 30 iters) is ~40× below that growth rate
    — a real climb trips it, steady-state noise does not. Unchanged from v1; it sits
    far below either reading of the #545 rate.
  - *Source:* derived from `#545`'s +8 GiB/step growth (~0.8 GiB/iter while
    accumulating over a ~10-iter step; set the slope tolerance well below that).
- **CTRL_GAP_GiB = 0.05 (positive-control min reserved gap).**
  - *Why:* set conservatively LOW because the #545 growth signal was dominated by
    cross-round / two-model accumulation, while this benchmark uses one model copy
    at seq=512, where the per-forward full-tuple-vs-subset reserved delta is modest
    (~0.1 GiB full tuple vs ~0.01 GiB subset, §3). 0.05 GiB is a floor that still
    confirms the old path retains *more*; the OR-branch (monotone trend) catches
    the climb case. If the gap is below 0.05 GiB the read is INCONCLUSIVE, not a
    false PASS.
  - *Source:* `ungrounded — needs smoke-test` (the exact per-forward reserved delta
    at seq=512 / one copy is not directly in a prior issue; the conservative floor +
    INCONCLUSIVE fallback is the safe handling). Flagged Low-confidence in §12.
- **MAX_TOKENS = 512.**
  - *Why:* the size the live #545/#651/#667 extraction line actually reads (the body
    specifies "≤512 tokens, the size the live line reads"). Keeps the benchmark
    on-distribution and bounds memory.
  - *Source:* task #673 body + the live read shape in `scripts/issue667_extract.py`.
- **LAYERS = [7, 14, 21].**
  - *Why:* the exact subset the live extractor reads (`scripts/issue667_extract.py`,
    `experiments/issue_650/shift_extract.py`).
  - *Source:* `#671` migrated call sites + `#545`/`#651` line.
