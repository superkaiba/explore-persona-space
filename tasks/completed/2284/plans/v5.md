## 1. Requirement + acceptance criteria

### Requirement

The `/issue` SKILL.md § Step 2 **Minimum plan-review floor** paragraph defines its own
trigger as

> `kind: infra` workflow-fix tasks (`wf-fix` tag OR title prefix in
> `WF_FIX_TITLE_PREFIXES` — `workflow-fix:` / `daily-fix:` —
> `task_workflow.is_workflow_fix_session`)

but `task_workflow.is_workflow_fix_session` tests **neither** the tag **nor** the title.
Ground truth (`src/explore_persona_space/task_workflow.py:1150-1167`):

```python
def is_workflow_fix_session(task_id: int) -> bool:
    try:
        body = (find_task_path(task_id) / "body.md").read_text()
    except (FileNotFoundError, OSError):
        return False
    return "workflow_fix_target:" in body
```

A session that mechanizes the floor check by calling the named function therefore SKIPS the
floor on exactly the class the prose intends to cover: a `workflow-fix:`-titled `kind: infra`
task filed without a `workflow_fix_target:` Provenance line. **#2282 is a live instance** —
its title prefix matches while `is_workflow_fix_session(2282)` is False.

The same misattribution exists at a SECOND workflow-surface site, found by the
protocol-mandated relocation grep and carried in from the clarifier
(`epm:clarify v1`): `.claude/agents/code-reviewer.md:1337`, the **Step-2 floor CHECK**.
That site is the more consequential of the two — it is the reviewer's *enforcement* arm
for this very floor, so a reviewer that follows the prose literally and calls
`is_workflow_fix_session` will not raise `step2-floor-skipped` on the #2282-shaped task.
Fixing SKILL.md alone would leave the enforcement arm still wrong.

Fix route: **(a) prose-only**, the task body's own recommended default, applied to both
sites. No new helper, no predicate change.
