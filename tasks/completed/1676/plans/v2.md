## 4. Design

### 4.1 Decision: (a)+(b), middle-path variant

Chosen over (b)-only because (b) alone leaves the false block on the most common compound shape (assignment + cd + commit in one command — the only shape in which `$WT` can be set *provably from the command text*; a fresh shell per Bash call leaves only same-command assignment or session-launch environment inheritance, and the latter is unprovable from command text by construction, so it correctly stays blocked-with-diagnostics), and over full-path (a) because a general cd-target resolver is new attack surface; the middle path adds exactly one inference (same-command whole-clause literal assignment) and reuses the existing trusted pattern list for the verdict. Justification detail in §11.

**Load-bearing measured fact (drives the fail-closed analysis):** in bash, `cd "$WT"` with `WT` unset is a SILENT rc=0 no-op — the shell stays at the inherited cwd (measured this session on this VM; unquoted `cd $WT` silently goes to `$HOME`). So an unproven variable cd genuinely can precede a commit that lands at the repo root at runtime. The current unlatched-by-default posture is correct, and resolution may latch only what is provable.

### 4.2 Hook changes (`.claude/hooks/guard_root_code_commit.sh`)

**(i) Factor the latch-verdict case into one shared function** (new, placed near `classify_candidate` ~`:331`): `cd_latch_verdict <tgt>` sets a 3-valued global `cd_verdict` ∈ {`latch`, `root`, `unproven`} from the EXACT pattern list currently at `:378-385` (worktree-substring and absolute/`~`-anchored non-root → `latch`; the three root spellings → `root`; the `*)` fall-through → `unproven`). The literal `cd` arm calls it and maps `latch`→`latched=1`, else `latched=0` — byte-equivalent behavior to today for every literal target.

**(ii) Variable resolution arm** (inside the cd clause handler `:375-396`, after the first verdict): fires ONLY when `cd_verdict=unproven` AND the raw quote-stripped target matches the variable shape `^\$[A-Za-z_][A-Za-z0-9_]*$` or `^\$\{[A-Za-z_][A-Za-z0-9_]*\}$`, optionally followed by `/<literal suffix>`. New helper `resolve_cd_var <name> <cd_record_index>` (reads `recs`/`n` via bash dynamic scoping — the same mechanism `classify_candidate` already documents at `:323-325`). Resolution succeeds only when ALL gates hold; any failure → unresolved → unlatched (today's behavior) + a reason token recorded for (iii):

1. **Whole-clause assignment anchor.** Scan all records for a MASKED clause matching `^(export[[:space:]]+)?NAME=[^[:space:]]*[[:space:]]*$` after stripping leading whitespace ONLY (not `{`/`(` — so a subshell-wrapped assignment never matches; assignments in subshells don't persist). The whole-clause anchor also refuses env-prefix assignments (`NAME=x somecmd` — they don't persist either).
2. **Exactly one.** Exactly one such assignment record exists in the WHOLE command, and its index precedes the cd record. Two+ (last-write-wins at runtime vs first-found in a scan) → refuse.
3. **Unconditional position.** The assignment record's own separator tag ∈ {START, SEQ, NL} (it always executes when reached), AND the NEXT record's separator ≠ BG (a trailing `&` backgrounds the assignment into a subshell). AND/OR/PIPE-positioned assignments → refuse (conditionally executed or subshelled; the safe-pure-`&&`-chain relaxation is a rejected alternative, §11).
4. **Path-sane literal RHS.** Extract the RHS from the RAW clause via a tight ERE `^(export[[:space:]]+)?NAME=("[^"]*"|'[^']*'|[^[:space:]]+)[[:space:]]*$`, quote-strip, then require: non-empty; no whitespace; no `\001` fill byte; no backtick; no `$(`; no `<>()&|;`; no `..` path segment. (Embedded plain `$VAR` references may remain — parity with the literal arm, which already pattern-matches targets containing `$`; see §6 risk 9/10.)
5. **Suffix sanity** (when the cd target carried a `/suffix`): suffix must match the same path-sane predicate (in particular: no `$`, no `..`).
6. **Mutation belt (narrow).** Refuse if any masked record's lead matches `(^|[[:space:]])(unset|declare|typeset|read)[[:space:]]` or `printf[[:space:]]+-v` and mentions NAME as a word, OR any masked record carries a `NAME+=`-shaped append — a variable mutated by another primitive between assignment and cd is unprovable. (Belt only; the deliberate-evasion residual — eval-style indirection, sourcing a file, arithmetic assignment — is out of the hook family's threat model; the sanctioned deliberate path is the logged `EPM_ALLOW_ROOT_CODE_COMMIT=1` escape, `:803`.)
7. **Compound-context refusal (v2, Alternatives Must-Fix).** Refuse resolution when ANY record in the command has a masked lead opening or continuing a compound statement — a leading keyword in `if|then|elif|else|fi|while|until|for|do|done|case|esac|function`, a `name()` function-definition shape, or a bare `{` group opener. Rationale: the masker tracks quote/heredoc state only (`:200-205`, newline flush `:310-314`) — no brace/keyword depth — so an assignment written as the interior LINE of a multi-line compound body surfaces as its own NL-tagged record with no leading `{`/`(`, passing gates 1-3 while being conditionally executed (or never executed) at runtime; with the variable unset, the quoted cd silently no-ops at the repo root (§4.1's measured fact) and a latched commit would land at the root — a wrong allow. Whole-command scope (not just records preceding the assignment) is deliberate: simplest, strictly conservative, and the canonical allow shapes A17-A19 are flat compounds unaffected by it. Reason token: `compound-context`.

On success: substitute RHS (+ suffix) for the variable, call `cd_latch_verdict` on the SUBSTITUTED string, and latch only on `latch`. Single hop by construction: an RHS that is itself variable-leading re-enters the `*)` unproven branch (no recursion). A resolved target whose verdict is `root` correctly stays unlatched (a crafted assignment can never latch a root-target commit — same pattern list, single point of truth).

**(iii) Unproven-cd tracking + block-message additions.** New global `cd_unproven=""` initialized with the others at `:350`; each cd clause whose FINAL verdict is `unproven` (after any resolution attempt) appends one entry: the quote-stripped target (truncated ~80 chars) + a reason token (`no-assignment`, `multiple-assignments`, `conditional-assignment`, `backgrounded-assignment`, `dynamic-rhs`, `mutation-belt`, `compound-context`, `not-a-variable`). In the BLOCK path only (zero hot-path cost — `cert_diag` precedent `:573`, `:905-911`): when `cd_unproven` is non-empty, build a conditional paragraph (modeled on `foreign_para`, `:923-931`) emitting (1) one stable grep-able `cd-diag: unproven-cd target=<tgt> reason=<token>` line per entry, and (2) an abstract remediation paragraph: the guard could not prove where this `cd` lands, so later clauses were classified against the repo root (fail-closed); an unset/external variable makes a quoted `cd` silently no-op at the inherited cwd (rc=0), which is why unproven targets are never trusted; remediations — `git -C "$WT" ...` per clause, OR a literal absolute worktree `cd`, OR assign the worktree path once in the same command (`WT=<literal-worktree-path> && cd "$WT" && ...`), which the guard now proves. Interpolated into the heredoc at `:933-946` alongside `foreign_para`; the existing generic worktree hint line (`:941-942`) stays.

**Untouched by design (conservative):** the MF-1 `cd_nonroot` scoping-disable case (`:389-394`) keeps operating on the ORIGINAL target — a resolved worktree cd still disables pathspec scoping (scoping-off is the conservative direction and irrelevant once latched, since a latched chain sets no `root_commit`); latch persistence stays `&&`-only (`:361`); the `-C` waiver (`:398-427`), verb classification, token scan, and all of Layer 2 are unchanged.

Estimated diff: ~70-110 hook lines (two helpers + arm + gate 7 + block paragraph) + ~25 self-test lines + ~130 pytest lines.
