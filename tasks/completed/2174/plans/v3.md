## 1. Requirement + acceptance criteria

Requirement (task body): the Phase 1.5 fact-checker must flag any plan assumption that
(a) asserts an EXACT identity (zero variance, `n_distinct == 1`, byte-identical, "no
exceptions", "every row"), (b) is grounded on a SAMPLE, and (c) is converted by the plan
into a runtime assert or hard-coded constant. Either the premise gets verified at the
grain the assert will run at, or it is downgraded to an explicit sampled BOUND before
approval. Incident #2163: byte-identity asserted from a 706-row probe (0.5% of 142,000
rows) at `Confidence: High (measured)`; the Phase-0 full-grain census died rc=1 on 258
deviating rows — one pod launch cycle + a plan revision + a crash-fix round, all
avoidable at plan time.

Acceptance criteria (verbatim from the task body, mapped to edits/tests below):

1. A plan asserting an exact identity from a stated sample, and building a runtime
   assert on it, draws a BLOCKING fact-checker finding naming the grain ratio.
   → Edit A (lens text); pinned by Test F1.
2. The finding offers both remedies (verify at full grain / restate as a bound + soften
   the assert). → Edit A (both remedies named in the lens); pinned by Test F1.
3. A value claim with a sampled source does NOT trigger the lens. → Edit A exemption
   clause + c64 non-trigger; pinned by Test E2.
4. An exactness claim already verified at full grain does NOT trigger it. → Edit A +
   c64 satisfier; pinned by Test E3.
5. Tests pin (1), (3), (4); `workflow_lint.py` passes; `--check-lessons-index` updated
   if a rule file changes. → Tests E1-E7 + F1-F2; no NEW rule file is created (edits land
   in existing files with existing LESSONS rows), so no index change is owed.

## 2. Method delta

What exists today: the fact-checker verifies VALUE claims (a λ, a byte count, a key set)
and — since #1910 — realized ROW-COUNT grain for row-grain-consuming reuse rows
(`ROW-GRAIN-CONSUMING` / `GRAIN-CONFIRMED` duty). planner.md §12 carries the #1817
real-corpus structural-claims rule (probe at full-CONSUMED-corpus grain at smoke time).
What is missing: no lens connects an EXACTNESS claim's evidence grain to the grain of
the runtime assert built on it. #1817 routes structural premises to a smoke-time
full-grain probe; #2163's failure is the assert-side sibling — the plan KNEW the sample
was not the population ("Phase 0 re-asserts … over the FULL staged store") and still
carried the exact claim at High confidence into a hard assert. The delta: a plan-time
BLOCKING lens in the fact-checker template (behavioral), one compact authoring clause in
planner.md §12 beside the #1817 paragraph (with the full sub-rule in
planner-section-reference.md § 12), and a mechanical WARN companion c64 in
verify_plan.py per the task body's sketch.

Scope decision (task body delegates this to the planner): the "measurement field must be
assigned from a measured variable, never a literal" code-reviewer check is OUT of scope
— it restates the standing CLAUDE.md "no value placeholders" rule, lands on a different
surface (code-reviewer.md + its Codex twin copy-list), and the #2163 root cause was
plan-time, not review-time. Recorded here as the deliberate boundary; no new task is
filed from this session (workflow-fix recursion guard).

### Edit D — `scripts/verify_plan.py`: new check `c64_exactness_grain`

WARN-only, conditional, all kinds — the mechanical half per the task body's sketch.
Shape (the c34/c43 text-heuristic house pattern):

- **Trigger:** a non-fenced line (fence-masked via `_fence_mask`) matching an EXACTNESS
  pattern — indicative regex, implementer refines against the test corpus:
  `byte[- ]identical | n_distinct(_rows)?\s*={1,2}\s*1 | exactly zero |
  zero (cross-context )?variance | max\|[^|\n]{0,40}\|\s*=\s*0 |
  all pairwise[^\n]{0,40}=\s*1\.0+ | every row | no exceptions` —
  with a SAMPLE-SIZE marker in the ±3-line window
  (`\b\d[\d,]*(-|\s)(sampled|sample|shard|shards|row|rows)\b` variants incl.
  "N sampled", "N-shard", "N-row sample/probe", "N of M rows") and NO full-grain
  satisfier in the same window.
- **Satisfiers (window-level):** COMPLETED full-grain verification text — a full-grain
  phrase (`full grain` / `full-grain` / `over the full` / `entire
  (store|corpus|population)` / `all <digits> rows`) ONLY when adjacent (same window) to
  completed-verification vocabulary (`verified` / `measured` / `confirmed` / `counted`)
  — or bound restatement (`no deviation observed in` / `no counterexample observed in`).
  DEFERRED-verification phrasing is a NON-satisfier: `re-assert(s)` / `will …
  assert` / `re-checks at runtime` near the full-grain phrase must NOT satisfy — the
  #2163 A11 row itself carried "Phase 0 re-asserts … over the FULL staged store" in its
  How-to-verify line, and c64 must WARN on that verbatim incident text (critic round-1
  finding 1; pinned by Test E8).

  via `_standalone_na_declared`.

  docstring catalog (the registration test mirrors `test_c62_c63_registered_...`).
