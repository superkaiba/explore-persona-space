# Plan v1 — #1834 workflow-fix: marker-materialized run artifacts must match producer schema

## Goal / requirement

Add durable workflow-surface guidance so any actor that BACK-FILLS a missing
run artifact from task markers (the orchestrator during Step 8 gap-fill, the
`uploader` agent, or any remediation path) matches the producing experiment
code's on-disk schema exactly — or writes to a differently-named sidecar —
instead of inventing a schema. Incident #1775: the orchestrator materialized
`eval_results/issue_1775/plan_deviations.json` as a dict
(`{"issue":..., "deviations":[...]}`) while the experiment's own
`record_plan_deviation` writer/reader uses a bare list of dicts; the
experiment's analysis wrapper then crashed with AttributeError re-reading its
own file. The immediate artifact was fixed on branch issue-1775 (commit
a8e75537); this task lands the durable guidance.

**Acceptance criteria:**

1. `.claude/agents/uploader.md` carries a rule: before writing any
   marker-materialized run artifact, read the experiment code's writer for
   that path and reproduce its exact schema; unclear schema → write
   `<name>.materialized.json` sidecar, never the canonical path.
2. `.claude/agents/upload-verifier.md` carries a compact rule: Step-6
   remediation instructions that involve materializing an artifact from
   markers must name the producer-schema duty, and a schema-mismatched
   canonical file discovered at verification time is a gap (FAIL), not a
   valid artifact.
3. `.claude/skills/issue/SKILL.md` Step 8 (FAIL → uploader dispatch bullet)
   carries ONE sentence binding the same duty on the orchestrator-side
   gap-fill path (the actual #1775 offender was the orchestrator).
4. `scripts/workflow_lint.py` `AGENT_SPEC_SIZE_GRANDFATHER["upload-verifier.md"]`
   is raised per the landing-bytes rule (#1753/#1727): current size 51,206 B
   vs cap 51,500 B leaves ~294 B headroom — insufficient for edit (2).
5. No-flags `workflow_lint.py` PASSes on the touched files; Step 9c
   touched-scope tests pass.

## File paths + concrete diffs

1. **`.claude/agents/uploader.md`** (8,546 B — far under the 28 KB WARN):
   under `## Rules`, add:

   ```
   + - **Marker-materialized artifacts must match the producer schema
   +   (#1775).** When back-filling a missing run artifact (e.g.
   +   `plan_deviations.json`) from task markers, FIRST grep the experiment
   +   scripts/src for the writer of that path and reproduce its exact
   +   on-disk schema (top-level type, key names, nesting). If the writer
   +   cannot be located or the schema is unclear, write a sidecar
   +   (`<name>.materialized.json`) instead of the canonical path — a
   +   schema-mismatched canonical file crashes the experiment's own
   +   readers at analysis time (#1775: dict materialized where
   +   `record_plan_deviation` writes a bare list; AttributeError at
   +   analysis).
   ```

2. **`.claude/agents/upload-verifier.md`**: under `## Rules`, add a compact
   bullet (~5 lines; the verifier is read-only, so its duty is
   naming-the-contract + grading):

   ```
   + - **Remediation that materializes an artifact from markers must match
   +   the producer schema (#1775).** When your Step-6 remediation list has
   +   the next actor back-fill a run artifact from markers, name the
   +   producer-schema duty (grep the experiment's writer; sidecar
   +   `<name>.materialized.json` when unclear). A canonical-path file whose
   +   schema mismatches the experiment's own writer is a GAP (FAIL), not a
   +   verified artifact.
   ```

3. **`.claude/skills/issue/SKILL.md`** Step 8, the "FAIL (any other
   blocker) → dispatch the `uploader`" bullet: append one sentence:

   ```
   + Any gap-fill (uploader- or orchestrator-side) that MATERIALIZES a
   + missing run artifact from markers must reproduce the experiment
   + writer's exact schema, or write a `<name>.materialized.json` sidecar
   + (#1775; full rule: uploader.md § Rules).
   ```

4. **`scripts/workflow_lint.py`**: bump
   `AGENT_SPEC_SIZE_GRANDFATHER["upload-verifier.md"]` from 51_500 to

   content at implementation time, per the landing-bytes rule — never
