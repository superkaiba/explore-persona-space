## 4. Method delta + design decisions

**Method delta:** none — this is the same fix class as #847/#895/#920 prior rounds applied to the current offender set. Two decisions worth recording:

**(D1) Call form.** Type-(a) insertions (files with NO existing `load_dotenv`) use the **no-arg `load_dotenv()`**, uniformly. Rationale: no-arg routes through `resolve_dotenv_path()` (`env.py:208-266`) which walks worktree → main-git-worktree `.env` → pod-canonical fallback — strictly more robust than `str(PROJECT_ROOT / ".env")` (which silently misses `.env` in a linked worktree, since worktrees don't inherit the gitignored `.env`), and it matches the library precedent (`issue841_common.py`) + the #778 fixed exemplar. Type-(b) moves **preserve the existing `load_dotenv(str(PROJECT_ROOT / ".env"))` argument verbatim** — minimal, behavior-preserving edit; only the ORDER changes (which is the fix).

**(D2) Library modules get a module-top call — safe and idempotent (the design question, resolved YES).** `issue923_common.py` and `issue841_scaling_common.py` are scanned by the test regardless of being libraries, so they must be fixed. Verified safety properties (read from `env.py:269-321`):
- **Idempotent:** `_dotenv_load(env_path, override=False)` never overwrites; `HF_HOME`, `HF_XET_HIGH_PERFORMANCE`, `HF_HUB_ENABLE_HF_TRANSFER`, and the four thread keys are all `setdefault`. N calls ≡ 1 call.
- **No crash when `.env` is absent** (pods/GCE): `resolve_dotenv_path()` returning `None` produces a `logger.warning` and then `_dotenv_load` on a nonexistent default path, which python-dotenv handles silently (returns False, no raise) — the code path is designed for exactly this. GCE gets tokens from instance metadata anyway (gotchas.md); the warning is benign noise.
- **Off-VM:** `is_shared_vm_env()` fails OPEN (no caps on pods/GCE/SLURM); `_apply_shared_vm_thread_caps` no-ops. So importing the library anywhere is behavior-preserving except for the intended shared-VM cap.
- **Precedent:** `issue841_common.py` has done exactly this on `main` since the scaling round, imported by every issue-841 driver, no incidents.
- **Bonus correctness:** entrypoints whose first heavy import is the common module (e.g. `issue841_stage0_atlas.py` imports `issue841_common` at line 42 before its own torch at 44) become *functionally* capped through the library's call; their own inserted call is then textual conformance + defense-in-depth (harmless by idempotence).
- **Import-time cost:** one `git rev-parse` subprocess (~ms, 5 s timeout, try/except-wrapped) — already paid by every `issue841_common` importer today.

**(D3) Functional placement beats the textual minimum.** The scanner only checks direct torch/numpy imports, but `import matplotlib` and `import issueNNN_common` transitively import numpy/torch and freeze the pools just the same. So every insertion goes **before the first third-party import of any kind** (matplotlib/numpy/torch) **and before the first `issueNNN_*` sibling import** — i.e. immediately after the stdlib-import + `PROJECT_ROOT`/`sys.path` bootstrap block. This is also exactly the canonical #920/#778/#841 layout.

**(D4) No new `sys.path`/`PROJECT_ROOT` bootstrap is added anywhere.** Files lacking a bootstrap (e.g. `issue922_repair_plots.py`) already import `explore_persona_space` directly — the package is uv-installed in the venv, so `from explore_persona_space.orchestrate.env import load_dotenv` resolves without any path munging.

### The two edit shapes

**Type (a) — insert (16 files).** One Edit per file inserting this block at the anchor point (import + call in the SAME Edit — the PostToolUse ruff F401 auto-fix strips a not-yet-used import added alone, per code-style.md):

```python

```

- With a bootstrap present: the `# noqa: E402` on the import is required (it follows executable code) and matches the file's existing style.
- Without a bootstrap (the import lands inside the top import block, before any code): drop the `# noqa: E402` from the import line — ruff would flag it as unused-noqa on some configs and it's not needed; then add `# noqa: E402` to **every module-level import below the `load_dotenv()` call** that ruff flags (it will flag all of them — the call is executable code).

**Type (b) — move (4 files).** Relocate the existing two lines — `from explore_persona_space.orchestrate.env import load_dotenv  # noqa: E402` and `load_dotenv(str(PROJECT_ROOT / ".env"))` — from their current position (after the heavy imports) to immediately after the `PROJECT_ROOT`/`sys.path` bootstrap, keeping the `# noqa: E402` and the explicit-path argument verbatim; delete the old lines (the sibling `from explore_persona_space.orchestrate import hub  # noqa: E402` import, where present, stays where it is). `PROJECT_ROOT` is defined above the insertion point in all four files, so the call's only dependency is satisfied.
