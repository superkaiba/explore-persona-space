1. `_HF_BRACE_PATH_TOKEN_RE` — brace-path token recognizer (single group; comma alternation OR numeric range):

```python
_HF_BRACE_PATH_TOKEN_RE = re.compile(
    r"^(?!\.\.?/)"                                  # ./ ../ leads declined (Pattern-D precedent)
    r"(?P<pre>[A-Za-z0-9._\-/]*)"                   # path charset — no braces/globs/spaces
    r"\{(?P<grp>"
    r"\d{1,4}\.\.\d{1,4}"                           # numeric range {N..M} (check-43 parity)
    r"|[A-Za-z0-9._\-]{1,64}(?:,[A-Za-z0-9._\-]{1,64}){1,31}"  # comma alternation, 2..32 alts, no '/'
    r")\}"
    r"(?P<post>[A-Za-z0-9._\-/]*)$"
)
```

Full-match + brace-free `pre`/`post` charsets ⇒ exactly one brace group by construction (multi-group and nested braces never match — named recall sacrifice, check-43 parity in the opposite direction). `*` excluded everywhere (globs unprobeable). Alternatives exclude `/` so all expansions of a group are path siblings.

2. `_expand_hf_brace_token(token: str) -> list[str]` — `[]` for a non-brace / malformed / over-wide token (this check is brace-REQUIRED, unlike check 43's `_expand_claim_token` which passes plain tokens through); comma form → split alternatives; range form → `range(a, b+1)` gated by `b >= a` and width ≤ `_GH_BRACE_MAX_EXPANSIONS` (=32, shared constant).

3. `_join_brace_expansion(pin_prefix: str, expansion: str) -> str` — overlap-aware join of one expansion onto the pin URL's path prefix:

```python
def _join_brace_expansion(pin_prefix: str, expansion: str) -> str:
    t, p = expansion.rstrip("/"), pin_prefix.strip("/")
    if not p:
        return t                                    # bare /tree/<sha> root pin
    if t == p or t.startswith(p + "/"):
        return t                                    # repo-root-absolute token repeats the prefix
    base = posixpath.basename(p)
    if base and t.startswith(base + "/"):
        return p + t[len(base):]                    # single-segment overlap — the FIXED #1426
                                                    # linktext shape: prefix …/sampled_rollout +
                                                    # token sampled_rollout/seed42 → …/sampled_rollout/seed42
    return p + "/" + t                              # plain descend — the pre-fix NEARBIND shape
```

Multi-segment overlap is a named recall sacrifice (deterministic single rule beats a fuzzy longest-overlap scan).

4. `_hf_upload_disclaimer_present(text: str) -> bool` + `_HF_UPLOAD_DISCLAIMER_RE` — the HF-absence sibling of check 43's `_gh_tree_disclaimer_present`, backtick-masked scan, absence-specific anchors only: `not\s+(?:yet\s+)?uploaded | upload\s+pending | pending\s+upload | git[- ]only | local[- ]only | not\s+on\s+(?:the\s+)?(?:HF|[Hh]ub)`. Instance-level suppression; a genuinely-false claim sharing its window with disclaimer vocabulary is missed (check-43 P1 trade, named).

5. `_gather_hf_brace_path_claims(body) -> list[(repo_id, repo_type, sha, pin_prefix, token, expansions, shape)]` — scan `_strip_blockquote_lines(_strip_fenced_blocks(body))` (check-42 precedent; a blockquoted verbatim prompt is quoted provenance, not the body's claim, #959). Two anchored shapes, dedup on `(repo_id, sha, pin_prefix, token)`:
   - **LINKTEXT** — a backtick brace token inside the TEXT of a hex-pinned HF `/tree/<sha>` markdown link (`_MD_HF_LINK_RE`; URL gated by `_HF_HUB_TREE_BLOB_URL_RE` + `f"/tree/{sha}" in url` — `/blob/` and moving refs out of scope, the check-32 guard). The FIXED #1426 shape. Disclaimer scan on the link text.
   - **NEARBIND** — a bare backtick brace token bound to the nearest preceding hex-pinned HF `/tree/<sha>` markdown link on the same line via the reused `_nearest_preceding_pinned_tree_link` (no newline, no `[`/`]`, ≤400-char gap — the bracket guard also auto-declines tokens sitting inside another link's text, so LINKTEXT/NEARBIND partition per instance; a post-link paren token binds here naturally, no separate PAREN shape needed). The pre-fix #1426 shape. Declined when: token's first path segment ∈ `_GIT_SIDE_ROOTS` or token starts with `/` (G3 — the same line's `eval_results/…seed{42,137}/` token); a position-anchored `@ [HF ]rev <hex>` follows the token (`_FOOTER_AT_REV_ADJ_RE.match(stripped, tok_end)` — the token's OWN pin governs; probing the @-rev revision itself is a named recall sacrifice, kept out of scope); disclaimer vocabulary in the forward window (token end → +120 chars, same line, backtick-masked).
   - Tokens without a valid brace group extract nothing (plain `dir/` tokens stay check 30/40/44 territory; brace FILE claims on git links stay check 43's). No HF-identity gate (check 44's G2) — pin ADJACENCY is the identity signal, the check-30/32 posture.

6. `_hf_direct_children(repo_id, repo_type, sha, parent) -> tuple[str, frozenset[str], str]` — `('ok'|'partial'|'not_found'|'skip', direct-child full paths, note)` via `_hf_tree_pages(…, recursive=False)`: `ok` ONLY on an exhaustive listing (`exhausted` event); page/time cap → `partial` with the paths seen so far (positive membership usable, missing never grounded — the check-32 "partial never grounds a WARN" rule); `not_found` returned DISTINCTLY (not collapsed to skip — this call site's independent mapping, licensed by the `_TreeProbeResult` docstring); fences (`EPM_VERIFY_BODY_NO_HF=1`, missing `huggingface_hub`) → `skip`. Cache `_HF_DIRECT_CHILDREN_CACHE` keyed `(repo_id, repo_type, sha, parent)`, exhaustive listings only (a skip/partial is never cached — the `_HF_EXISTENCE_CACHE` convention).

7. `_HF_BRACE_MAX_PROBES = 8` — per-body cap on UNIQUE `(repo_id, repo_type, sha, parent)` listings (pin-alive prechecks included); same value + worst-case wall arithmetic comment as `_HF_MEMBER_MAX_PROBES` (~22.5 s worst case per probe, ~3 min per body under a pathologically slow Hub; typical: one sub-second page). Past-cap claims → `unverified` notes.

8. `check_hf_brace_expanded_path_claims(body: str) -> CheckResult` — **check 46 (WARN, generation-agnostic)**, the verdict logic:

```
for each claim (repo, type, sha, P=pin_prefix, token, expansions, shape):
    joined   = [_join_brace_expansion(P, e) for e in expansions]
    st_P, kids_P, note = children(P)              # pin-alive precheck (memoized; counts toward cap)
    if st_P == "not_found": unverified += ["pin itself unresolvable — check 23 owns the dead-pin FAIL"]; continue
    if st_P == "skip"/"cap-blocked": unverified += [note]; continue
    group joined by parent = posixpath.dirname(joined_path):
        st, kids = children(parent)   (== the P result when parent == P — one GET for the common case)
        st == "not_found" → ALL of the group missing      # DEFINITIVE: pin alive, parent absent —
                                                          # the incident arm (#1426: P 200, P/sampled_rollout 404)
        st == "ok"        → missing = [j for j in group if j not in kids]
        st == "partial"   → present-in-partial pass; unfound → unverified (never WARN on a partial)
        st == "skip"      → unverified
    any missing → WARN detail: "body claims `<token>` under the pinned HF prefix `<P>` at `<sha8>`,
        but <missing joined path(s)> do(es) not resolve at that revision (<k>/<n> expansions missing;
        shape: <LINKTEXT|NEARBIND>) — artifact likely uploaded after the pin; re-pin to its upload revision"
zero claims → vacuous PASS "no brace-expanded path claims adjacent to pinned HF tree links" (ZERO probes)
any missing → CheckResult(name, True, "; ".join(missing) + unverified_detail, is_warn=True)   # NEVER passed=False
```

The pin-alive precheck is what disambiguates the tree endpoint's conflated 404 ("no such revision OR no such path"): only a live pin makes a child-path `not_found` a definitive missing-artifact signal. Without it the check-32 `not_found → skip` convention would silence the motivating incident (the #1287 must-fire trace: at `c244377f` the parent dir itself 404s).

## 11. Decision Rationale

N/A — no model training, no hyperparameters. The six deferred design decisions:

- **D1 — Severity: WARN, never FAIL (deviation from the Goal's literal "FAIL on 404").**
  *What:* `CheckResult(passed=True, is_warn=True)` on every definitive miss; no `passed=False` path (AC8).
  *Why:* the file's tier boundary is inference: literal-URL probes FAIL (23, 42, 4b, 8b — the URL itself binds repo+sha+path); every adjacency-INFERRED claim check is WARN-only by documented design (30, 32, 40, 43, 44 — each docstring says "WARN, never FAIL (no passed=False path)"). This check has TWO inference steps (pin binding + path join), so a wrong guess would produce a false FAIL that blocks clean-result publication and retro-blocks grandfathered bodies at promote-time re-verify (check 41's argument). The enforcement goal survives at WARN tier: FAILs block, and WARNs ship only when acknowledged in the body — the analyzer must fix or acknowledge, and clean-result-critic Lens 5 keys on WARN notes. Flip-note: severity is localized to the two `CheckResult` constructions; a future FAIL-on-LINKTEXT-only tightening (where binding is author-explicit) is a one-line change per site.
  *Source:* file-internal convention (check 30/32/40/43/44 docstrings; check 41's grandfathered-body argument); CLAUDE.md "Drafts must PASS before posting; FAILs block, WARNs ship only when acknowledged".
  *Alternatives:* FAIL everywhere (candidate sketch — rejected: false-FAIL cost + convention breach); FAIL on LINKTEXT / WARN on NEARBIND (rejected for v1: the join semantics are novel on both shapes; revisit after corpus data).

- **D2 — Probe mechanism: the in-file bounded tree-endpoint stack, not `get_paths_info`.**
  *What:* `_hf_direct_children` consuming `_hf_tree_pages(recursive=False)`; one memoized listing per unique parent verifies all sibling expansions (brace alternatives exclude `/` ⇒ same-parent by construction, one GET for the common case).
  *Why:* (a) #733 is the file's contract — SDK listing calls with unbounded `http_backoff` retry loops stalled the verifier fleet-wide; `get_paths_info` is an SDK POST with no exposed per-request timeout control, i.e. the same hazard class; (b) `_hf_tree_pages`'s own docstring invites the next consumer; (c) one new network shape avoided — offline fences, caps, caches, and ~20 existing `_hf_tree_get` test stubs all carry over; (d) lint: `--check-hub-verify-calls` bans `list_repo_files(`/`list_repo_tree(`/`.file_exists(` — the design introduces no SDK call at all. Live-verified: the exact endpoint + `recursive=false` param reproduced the incident 404 and the fix-revision 200 (§2).
  *Source:* #733 (probe-stack migration), #715 (the SDK-backoff incident), `_hf_tree_pages` docstring, `workflow_lint.py` L6796–6863.
  *Alternatives:* `get_paths_info(paths=…, revision=rev)` (candidate sketch — genuinely scoped and single-request, but SDK-timeout-opaque, un-fenced, un-stubbed, a second network idiom to maintain); per-expansion `_hf_url_existence` (check 23's probe — k GETs for k siblings, page-1-only pagination blindness, and its `fail` wording is check-23-specific).

- **D3 — Expansion semantics:** single brace group; comma alternation `{a,b[,c…]}` (2–32 alternatives, `[A-Za-z0-9._\-]`, no `/`) AND numeric `{N..M}` (≤32) — both, because the incident is comma-form and the `{N..M}` machinery/precedent already exists (check 43); shared bound `_GH_BRACE_MAX_EXPANSIONS=32`; multi-group cartesian products rejected by construction. Per-body probe cap `_HF_BRACE_MAX_PROBES=8` unique parents (the `_HF_MEMBER_MAX_PROBES` value + wall arithmetic). *Source:* check 43 L9995–10001/L10037; check 30 L9178 cap comment; incident #1426. *Alternatives:* comma-only (rejected — leaves the sibling `{N..M}` HF gap open for two lines of code); unbounded expansion (rejected — probe-cost blowup).

- **D4 — Adjacency anchoring:** LINKTEXT (author-explicit binding; the fixed #1426 shape — REQUIRED so the corrected body PASSes definitively rather than being unscanned) + NEARBIND via the reused check-30 Pattern-D binder (nearest preceding pinned `/tree/<sha>` markdown link, same line, bracket-free, ≤400-char gap — measured incident gap 272 chars). No `_footer_units` scoping (body-wide idiom; the footer splitter would silently join multi-line bindings the same-line guard deliberately declines); no separate PAREN shape (NEARBIND subsumes post-link parens — bracket-free gap holds through `(`). Suppressors: G3 git-roots, token-adjacent `@ rev <hex>`, HF-absence disclaimer. Recall sacrifices named in §4.3. *Source:* `_nearest_preceding_pinned_tree_link` L9190 (#1143); check 44 G3/S2 (L10712, L10658); check 43 disclaimer precedent (#1507). *Alternatives:* check-44 unit-scoped binding (rejected — multi-line units over-bind across unrelated pins); paragraph-scope (rejected — same over-binding, no incident grounding).

- **D5 — New check 46, not a widening of check 32.** Check 32 is basename-membership (any-depth, `_HF_ADJ_FILENAME_RE` rejects `/` and braces by construction) with PAREN/LINKTEXT anchors; this check is exact-path direct-child membership with an overlap join, a pin-alive precheck, a distinct `not_found` mapping, and a NEARBIND anchor. Widening 32 would fork its probe semantics and WARN vocabulary mid-function and shift its documented recall-sacrifice contract. New function keeps both auditable; CHECKS indices never shift (append-only, the check-5 comment's convention).
