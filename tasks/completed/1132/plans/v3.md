### 3.2 Enumerator helper (design questions 2, 3, 4)

**Yes to the helper** — `scripts/sweep_parked_wf_candidates.py` (read-only; stdlib + `task_workflow` imports). Rationale: the scan is exactly the deterministic mechanics /daily's LLM does inconsistently (the same extraction pattern as `daily_drive_filings.py` / `consolidate_lessons.py`); it keeps park-detection + suppression testable.

**CLI:** `uv run python scripts/sweep_parked_wf_candidates.py [--window-days 0] [--include-routed] [--tasks-root PATH] [--cache-file PATH]` — always prints one JSON object to stdout; exit 0 always (enumerator, not a gate; malformed rows are skipped-and-counted, see below). `--window-days 0` (the DEFAULT) = unbounded; a positive N scopes an audit. `--tasks-root`/`--cache-file` are test overrides; defaults resolve via `task_workflow.tasks_dir()` / `repo_root()` (never cwd-relative `tasks/…` — the Critical Rule). Helper docstring notes that the `open_wf_fix_on_file` advisory (via `is_open_workflow_fix_task`) is `workflow-fix:`-title-bound and therefore BLIND to `daily-fix:`-titled open filings — advisory only; the LLM-side content dedup is the real check.

**Sources scanned:** (a) every `tasks/*/*/events.jsonl` across ALL statuses — both evidence candidates live on terminal-status tasks (#1100 completed, #1101 archived), so an active-only scan misses the actual population; (b) `.claude/cache/workflow-fix-events.jsonl` — YES (recommended in the brief; it is the documented outside-task posting target and parked candidates can land there), same window, negligible cost (88 rows).

**Window:** default **0 = UNBOUNDED** (critic round 1, Methodology advisory adopted — supersedes both the body's 48h and the v2 draft's 7d). The window filter is post-read (the scan walks every events.jsonl regardless), so unbounded costs nothing extra, and the routed-record suppression makes re-scans idempotent (no double-filing) — an unbounded default eliminates the last silent-drop hole (a candidate parked during a >7-night /daily outage would exit a bounded window forever, the exact bug class this task closes). `--window-days N` remains available for scoped audits; output is bounded by suppression, not by the window.

**Park-detection predicate** (per row; the cache file is SCHEMA-HETEROGENEOUS — fact-checked + critic-corrected 2026-07-08: 34/88 rows lack a `kind` key; 25 rows use a `marker` key, 9 of them candidate rows with STRUCTURED fields `proposed_change`/`target_file`/`routed` instead of a `note` — and 5 of those 9 carry NO `routed` field at all; none is parked, so the evidence base is unaffected): `kind_val = row.get("kind") or row.get("marker") or ""` (None-guarded — a bare `row["kind"].startswith` crashes on 43 cache rows), then `kind_val.startswith("epm:workflow-fix-candidate")` (covers the bare and `" v1"` literal forms, both observed) AND parked-ness from EITHER surface: the note text (`re.match(r"\s*parked\b", note, re.I)` OR `re.search(r"routed:\s*parked\b", note, re.I)`) OR — for structured cache rows — the `routed` field containing `parked` (case-insensitive). This catches BOTH observed park forms ("parked — running under workflow_fix_target recursion guard" / "parked — running under EPM_WORKFLOW_FIX_SESSION / workflow_fix_target") AND the workflow-fix-on-bug.md step-4 routing-decision forms (`routed: parked: EPM_WORKFLOW_FIX_SESSION` | `routed: parked: architectural`), while excluding mid-note "parked" false positives (a real cache row contains "stopped-on-parked-task" mid-note and must NOT match — pinned by a test; that row also lacks a `kind` key). `park_form` = `"architectural"` iff the note or structured `routed` field contains `parked: architectural`, else `"recursion-guard"`. Structured (marker-key) rows extract `target_file`/`proposed_change`/`bug_observed` from their own JSON fields directly (fp computable when both fields present); note-form rows extract per the paragraph below.

**Field extraction:** if the note embeds a `<!-- workflow-fix-candidate v1 -->` block → parse `target_file` / `bug_observed` / `proposed_change` verbatim → compute `fingerprint = wf_fix_fingerprint(...)`. Else (prose park, the #1100 shape) → best-effort `target_file` regex (`target_file:\s*([^\s,;]+)`, trailing punctuation stripped), `fingerprint: null` — the /daily LLM synthesizes the fields at route time (the prose-synthesis rule) and computes the fp itself.

**Timestamp normalization (all ts comparisons — critic round 1, Statistics Must-Fix 2):** every ts read from a row is parsed to an AWARE-UTC datetime via `datetime.fromisoformat(ts.replace("Z", "+00:00"))` before ANY comparison (rule-1 ordering, rule-2 creation-ts, window filter) — the cache file carries offset-form rows (`2026-06-12T15:35:00-07:00`) alongside `Z`-form; string comparison misorders them and naive/aware mixing raises. A row whose ts fails to parse is treated as malformed (below). **Malformed-row handling (stated, vs the exit-0 contract):** a JSONL line that fails to parse, or a row missing every usable field, is SKIPPED and COUNTED — the output JSON carries a top-level `skipped_rows: <int>` (never a crash, never a silent drop; one test pins it).

**Unrouted / suppression predicate (design question 3)** — a candidate is SUPPRESSED (routed) iff any of:
1. **Same-stream filed record:** a later row (aware-UTC ts > candidate ts) in the SAME events.jsonl / cache file with `kind.startswith("epm:workflow-fix-task-filed")` matching the candidate — where MATCHING is fp-aware (critic round 1, Statistics Must-Fix 1 + the convergent rule-1 advisory from all three lenses): (a) candidate fp COMPUTABLE → the record's note must contain THAT fingerprint (a file-matching record with a DIFFERENT fp does NOT suppress — same target_file + different fingerprint is NOT a duplicate, per workflow-fix-on-bug.md § Dedup; pinned by a dedicated matrix case); (b) candidate fp NULL (prose park) → the record's `origin_candidate_ts` equals the candidate's ts (PRIMARY key), falling back to a `target_file` string match ONLY when the record carries no `origin_candidate_ts` (legacy/backfill records — #1100's backfill marker carries `fingerprint: n/a` + the origin ts, so it suppresses cleanly; a second DISTINCT fp-less park on the same file is NOT swept up, pinned by a two-parks-same-file matrix case). This is the primary loop-closing signal (the routed-record Step C posts).
2. **fp-tag scan (fingerprint computable only):** some `kind: infra` REGISTRY entry whose `body.md` carries `wf-fix-fp:<fp>` (tag line or Provenance `fingerprint:` line — the title-prefix-agnostic scan, mirroring `daily_drive_filings.py::_find_open_fp_task`, because /daily filings use `daily-fix:` titles and `is_open_workflow_fix_task` requires `workflow-fix:`). NON-terminal hit → suppressed unconditionally. TERMINAL (completed/archived) hit → suppressed **only if the task's creation ts (first events.jsonl row) POSTdates the candidate ts**. Justification: workflow-fix-on-bug.md § Dedup says a closed task does not block a *re-raise* — that protects a FRESH recurrence of a fixed bug; a swept candidate that PREdates the closed fix was subsumed by it, and re-routing it is pure churn. A candidate raised AFTER a fix closed is a genuine re-raise and is NOT suppressed.
3. **Row dedup:** identical (stream, ts, sha256(note)) rows collapse to one (observed duplication in #1100's events.jsonl).

For fp-less prose parks the helper NEVER auto-suppresses on file-only matches — it emits the advisory field `open_wf_fix_on_file` (`is_open_workflow_fix_task(target_file, None)`) and leaves final dedup to the LLM (a coarse file-only suppress would wrongly kill a DISTINCT bug on a hot file, the exact #622-class failure the (target_file, fp) grain exists to prevent).

**Output schema** (stdout):
```json
{"generated_at": "<iso>", "window_days": 7, "candidates": [
  {"source": "task:1100" | "cache", "ts": "...", "target_file": "..." ,
   "fingerprint": "<12-hex>" | null, "park_form": "recursion-guard" | "architectural",
   "formal_block": true, "note": "<verbatim note>",
   "suppressed": false, "suppressed_by": null | {"kind": "same-stream-filed|fp-tag-open|fp-tag-closed", "ref": "#M | <ts>"},
   "open_wf_fix_on_file": null | 1234}
]}
```
Default output lists only unsuppressed candidates; `--include-routed` includes all (debugging/audit).

### 3.3 Routing + routed-record (design questions 5, 6)

Routing goes through the EXISTING three-route classifier — no new routes. Classification rule (stated in the pass prose): **route 2 is the default** (a parked candidate is by construction a proposal to change workflow behavior); route 1 only for pure prose/doc edits passing the route-1 no-behavior-change litmus; route 3 for judgment-call carve-out matches AND for `park_form == "architectural"` (the architectural-greenlight invariant — the user, not an auto-dispatched session, decides those). Filing runs through the durable filing dir + `daily_drive_filings.py` (route-2 tags `wf-fix`, `wf-fix-fp:<fp>`, `daily-auto-filed`; `daily-fix:` titles per the /daily contract — dedup is fp-tag-based, so the title prefix is not load-bearing). Enabling fact, stated in the prose: the /daily orchestrator is not a workflow-fix session (`is_workflow_fix_session` false; no env flag), so the recursion guard does not bind.

**Routed-record:** the existing `epm:workflow-fix-task-filed v1` marker posted on the PARENT task (the task carrying the park), exactly per workflow-fix-on-bug.md § Markers, with `source: daily-parked-candidate-sweep` + `origin_candidate_ts` as free-form note lines (notes are unstructured — NOT a schema change). Cache-borne candidates get the equivalent JSON row appended to the cache file (the existing "same schema" convention). This closes the loop with ZERO new marker kinds: suppression rule (1) keys on exactly this record. Confirmed: no new marker kind is needed.
