## 2. Prior work / precedent (repo-internal; web search not needed)

- **The #1184 materialize-then-check pattern, exclusive-arm form — Guard 1** (`SKILL.md` L8691–8721): `if ! git -C "$WT" diff --name-only "$MAIN_SHA" HEAD -- 'tasks/' > /tmp/issue-<N>-guard1-tasks-diff.txt; then echo "Guard 1: ... do NOT merge"; false; elif mapfile -t FOREIGN < <(grep -Ev ... || true); [ "${#FOREIGN[@]}" -gt 0 ]; then <work>; fi`. This is the primary template — both the failure arm and the two-command elif list (`mapfile` from process substitution; the `[ ... ]` length test is the LAST command and decides the branch).
- **The same shape, post-merge stale-task-folder guard** (`SKILL.md` L10093–10121): a 3-producer `if`/`elif` ladder (`CANON` empty / fetch failed / ls-tree failed → terminal arms; `elif mapfile -t DUPES < <(grep ... || true); [ ... ]; then <work>`). Confirms the pattern is the file's established idiom for producer-certified consumers.
- **Task #1210 (Edit C's origin):** introduced the recovery's MAIN_SHA capture + pinned checkout + certification diff, and shipped the region-scoped durability pin `tests/test_issue_skill_merge_resnapshot_pin.py`. Its code-reviewer round 1 (Minor finding 1) is the emitter of this candidate; the reviewer noted the `|| { ...; false; }` arms diverge from Guard 1's shape.
- **Bash semantics fact justifying the fix:** in a non-interactive shell WITHOUT `set -e`, a failing compound command (`cmd || { echo; false; }`) only sets `$?`; execution continues to the next command. Additionally, the `> file` redirect opens/truncates the file BEFORE the command runs, so a failed producer leaves an EMPTY (not absent) file — exactly the input that makes Site B's residual grep pass vacuously. Inside `if ! producer; then ...; elif consumer; then ...; fi`, by contrast, the taken failure branch structurally excludes the consumer branch, and the whole chain is ONE command whose non-zero exit piecewise execution also sees.
- **Hazard grading (verified against the current text):** Site B is genuinely fail-OPEN — after a failed diff, flow falls through to the lint-verdict conditional (L9677) and, on a surviving verdict, `git -C "$WT" push` (L9680) on an uncertified tree. Site A degrades more softly: the mechanical foreign checkout is silently skipped, but the downstream `git commit --no-edit` refuses to commit with unmerged index entries, a partial backstop. Both sites get the same fix; Site B is the load-bearing one.

Replacement (Guard 1's exact shape; drops the `recovery-foreign-only.txt` intermediate — referenced nowhere else in the repo, §6):

```bash
# Foreign tasks/ conflicts are resolved MECHANICALLY: take the captured
# snapshot's version wholesale (under fleet marker churn main is
# authoritative for OTHER tasks' state — the #1128-proven recovery:
# foreign tasks/ pinned to ONE captured main SHA). Materialize the
# conflicted-path list and check its own exit code in Guard 1's `if !`
# exclusive-arm shape (#1184): a FAILED producer takes the terminal
# echo + false arm and the work arm is STRUCTURALLY unreachable — the
# old `|| { echo; false; }` form reported failure but let the next
# command run under no-set-e / piecewise execution (#1243).
if ! git -C "$WT" diff --name-only --diff-filter=U -- 'tasks/' \
    > /tmp/issue-<N>-recovery-foreign.txt; then
  echo "recovery: conflicted-paths diff FAILED — resolve by hand per the prose below"
  false
# Work arm: two-command elif list — mapfile fills RECOVERY_FOREIGN from the
# FILE (the carve-out grep's no-match `|| true` is a legitimate empty
# list), then the [ ... ] test (the LAST command's exit) decides the
# branch. The mapfile + non-empty-array idiom is Guard 1's own hook-proven
# shape (the guard_repo_root_branch.sh -C waiver expects -C right after
# git; no xargs indirection, no whitespace-splitting caveat); the length
# test means an empty list never runs a pathspec-less checkout.
# checkout <sha> -- <path> resolves each U path to the snapshot's version
# and stages it. It fails loud on a path absent at $MAIN_SHA (a
# delete/modify conflict — resolve that one by hand).
elif mapfile -t RECOVERY_FOREIGN < <(grep -Ev "^tasks/[^/]+/<N>/" \
      /tmp/issue-<N>-recovery-foreign.txt || true); [ "${#RECOVERY_FOREIGN[@]}" -gt 0 ]; then
  git -C "$WT" checkout "$MAIN_SHA" -- "${RECOVERY_FOREIGN[@]}"
fi
```

Preserved semantics: same producer, same carve-out regex, same variable name, same pinned checkout string (byte-identical — test-pinned), same empty-list no-op, same echo text. Changed: producer failure now structurally halts the unit; the one-use intermediate temp file is folded into the process substitution (Guard 1 parity).
