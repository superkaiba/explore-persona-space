## 1. Goal, requirements, acceptance criteria

**Goal.** (verbatim from the task body) Make the autonomous-session watcher's orphan-respawn pass honor a deliberate session takeover (the `issue-<N>.json.paused-takeover-*` registration rename), and make `spawn_session.py stop --session-id` able to resolve/stop a live-but-unregistered session, so a takeover never collides with a watcher respawn.

**Requirements.**
1. Fresh sentinel (mtime age < TTL, default 6 h, env `EPS_TAKEOVER_TTL_H`) → orphan-respawn pass skips the issue (no respawn, no alert, no state mutation) and logs the skip naming the sentinel.
2. Stale (≥ TTL) or missing sentinel → behavior identical to today (FAIL OPEN; crash recovery never weakened).
3. `spawn-issue --auto` during a fresh takeover is suppressed via the existing #843 suppression channel (`spawn_output_suppressed`) — covering every automated spawner (crash-recovery `_respawn`, stalled respawn, infra-drain, capacity-retry, `file_infra_task.py`) at one choke point.
4. `stop --session-id` on a daemon-untracked sid never dies with a bare `stop failed: {'success': False}` — it resolves the wrapper pid via `~/.happy/logs` and either reports a structured kill-by-pid recipe or performs a verified SIGTERM under a new `--kill` flag.
5. The convention is documented in `.claude/rules/background-automation.md`, including which watcher passes honor it and why the others are structurally covered.

**Acceptance criteria (concrete, testable).**
1. Unit test: fresh sentinel in an isolated registry → `_process_orphan_task` records **zero** `_respawn_orphan` calls and writes no orphan-state file for that issue.

## 3. Design

### 3.1 `scripts/spawn_session.py` — sentinel helper + spawn gate + stop fallback

**(a) New constants + helper (place next to the #843 lease block, ~line 105-135):**

```python
TAKEOVER_SENTINEL_TTL_H_DEFAULT = 6.0          # hours; #903 (goal-specified ~6h)
TAKEOVER_HELD_SENTINEL = "TAKEOVER-SENTINEL HELD"

def _takeover_ttl_s() -> float:
    """TTL in seconds (env EPS_TAKEOVER_TTL_H, hours; malformed -> default —
    a typo'd var must not disable crash recovery, mirroring _orphan_staleness_s)."""
    raw = os.environ.get("EPS_TAKEOVER_TTL_H")
    if not raw:
        return TAKEOVER_SENTINEL_TTL_H_DEFAULT * 3600.0
    try:
        return float(raw) * 3600.0
    except ValueError:
        return TAKEOVER_SENTINEL_TTL_H_DEFAULT * 3600.0

def takeover_sentinel_fresh(
    issue: int, now: float | None = None, registry_dir: Path | None = None
) -> Path | None:
    """Newest FRESH deliberate-takeover sentinel for issue N, else None.

    Convention (#866/#903): a session deliberately taking over a stalled
    autonomous session renames ~/.eps-autonomous/issue-<N>.json ->
    issue-<N>.json.paused-takeover-<suffix> (manual-issue- same shape).
    Fresh = file mtime within EPS_TAKEOVER_TTL_H (default 6h); `touch` the
    sentinel to renew. FAIL OPEN: stale/missing/unreadable -> None (today's
    respawn behavior preserved). registry_dir/now injectable for tests
    (the resolve_session_for_issue pattern)."""
    reg = registry_dir if registry_dir is not None else AUTONOMOUS_REGISTRY_DIR
    now = time.time() if now is None else now
    ttl = _takeover_ttl_s()
    best: Path | None = None
    best_mtime = float("-inf")
    if not reg.is_dir():
        return None
    for pattern in (
        f"issue-{issue}.json.paused-takeover-*",
        f"manual-issue-{issue}.json.paused-takeover-*",
    ):
        for p in reg.glob(pattern):
            try:
                mt = p.stat().st_mtime
            except OSError:
                continue  # unreadable -> ignored (fail open)
            if mt > now + FUTURE_MTIME_SLACK_S:
                # Future-dated mtime (clock skew / `touch -d` typo) would be
                # PERMANENTLY fresh — an indefinite crash-recovery suppression
                # that inverts the fail-open guarantee (round-1 critique,
                # 3 critics). Treat as NOT fresh (fail open).
                continue
            if now - mt < ttl and mt > best_mtime:
                best, best_mtime = p, mt
    return best
```

with `FUTURE_MTIME_SLACK_S = 300.0` (5 min tolerance for ordinary clock jitter; a genuinely future-dated sentinel is ignored — fail open — and the per-tick skip line never fires for it, so the anomaly is visible as "respawn resumed despite sentinel").

The exact-`N`-then-`.json` boundary makes the glob prefix-collision-safe (`issue-1.json.paused-takeover-*` cannot match issue 14). Add `TAKEOVER_HELD_SENTINEL` to the `spawn_output_suppressed` loop tuple at `:130` (the single shared recognizer all callers import — no per-caller change needed).

**(c) `cmd_stop` fallback (`:1942`):**

```python
def cmd_stop(args: argparse.Namespace) -> None:
    """Stop a Happy session by id; degrade usefully on a daemon-untracked sid (#903)."""
    resp = post("/stop-session", {"sessionId": args.session_id})
    if resp.get("success"):
        print(f"Stopped session {args.session_id}")
        return
    _stop_fallback(args.session_id, resp, kill=bool(getattr(args, "kill", False)))

def _stop_fallback(sid: str, resp: dict, *, kill: bool) -> None:
    if sid in _live_session_ids():
        sys.exit(
            f"stop failed for DAEMON-TRACKED session {sid}: {resp!r} — the daemon "
            f"knows this session but refused the stop; retry once, then check "
            f"~/.happy/logs/ for the daemon-side error."
        )
    import session_resolver  # lazy: session_resolver imports spawn_session at top level

    pid = session_resolver.find_node_pid_for_session(sid)
    if pid is None:
        sys.exit(
            f"stop failed: session {sid} is UNKNOWN to the Happy daemon "
            f"(daemon-untracked) and no live happy node references it in "
            f"~/.happy/logs/. If you know the wrapper pid: verify ownership first "
            f"(`ps -o pid,lstart,cmd -p <pid>`; `ls -l /proc/<pid>/cwd`), then "
            f"`kill -TERM <pid>`, wait ~10s, re-check `ps -p <pid>`. "
            f"Raw daemon reply: {resp!r}"
        )
    if not kill:
        sys.exit(
            f"stop failed: session {sid} is daemon-untracked, but live happy node "
            f"pid {pid} references it (~/.happy/logs reverse map). Re-run with "
            f"--kill to SIGTERM it, or manually: verify `ps -o pid,lstart,cmd -p {pid}` "
            f"then `kill -TERM {pid}`. Raw daemon reply: {resp!r}"
        )
    # --kill identity binding (round-1 critique Must-Fix, 3 critics): comm alone
    # is NOT ownership on a shared VM full of unrelated node processes (the
    # Happy daemon, the eps-dashboard `next start`, every other wrapper), and
    # the resolver's log scan can only return a RECYCLED pid for a genuinely
    # dead session. Three stacked checks, each refusing to the report-only
    # recipe on mismatch (never a kill on ambiguity — crash-fix-rounds.md
    # § Kill-before-relaunch):
    comm = session_resolver._read_proc_comm(pid)
    if comm != "node":
        sys.exit(
            f"refusing --kill: pid {pid} comm={comm!r} != 'node' (pid may have been "
            f"reused). Verify manually: ps -o pid,lstart,cmd -p {pid}; kill -TERM {pid}"
        )
    cmdline = session_resolver._read_proc_cmdline(pid)   # new tiny helper: /proc/<pid>/cmdline, NUL->space
    if "happy" not in cmdline:
        # the happy-wrapper signature per assumption 12: `node .../happy/dist/index.mjs claude ...`
        sys.exit(
            f"refusing --kill: pid {pid} cmdline {cmdline!r} lacks the happy-wrapper "
            f"signature (pid likely recycled to an unrelated node process). "
            f"Verify manually: ps -o pid,lstart,cmd -p {pid}"
        )
    # Never signal the Happy daemon itself (its log sits in the same dir;
    # the -daemon.log suffix is regex-excluded by the resolver, but this is
    # the last-line belt): read ~/.happy/daemon.state.json's pid and refuse on match.
    daemon_pid = session_resolver._happy_daemon_pid()    # new tiny helper; None on any read failure
    if daemon_pid is not None and pid == daemon_pid:
        sys.exit(f"refusing --kill: pid {pid} is the Happy DAEMON pid; wrong resolution.")
    claude_pid = session_resolver.resolve_claude_pid(sid)  # best-effort, pre-kill (may be None)
    os.kill(pid, signal.SIGTERM)
    for _ in range(20):                      # ~10s @ 0.5s
        time.sleep(0.5)
        if not _pid_alive(pid):              # module-level seam (test 13 monkeypatches it + time.sleep)
            survivor = ""
            if claude_pid is not None and _pid_alive(claude_pid):
                survivor = (
                    f" WARNING: inner claude pid {claude_pid} still alive — the "
                    f"wrapper's SIGTERM cleanup may have failed; verify/kill manually."
                )
            print(f"Stopped daemon-untracked session {sid} via SIGTERM to node pid {pid}.{survivor}")
            return
    sys.exit(
        f"SIGTERM sent to pid {pid} but it survived ~10s; escalate manually after "
        f"re-verifying: kill -KILL {pid}"
    )
```

(`_pid_alive` is the SAME module-level helper §3.2 adds to `session_resolver` —
`spawn_session` calls it through the resolver so tests patch ONE seam; the
death-wait loop contains NO inline `/proc/<pid>` check, making test 13
host-independent. `_read_proc_cmdline` and `_happy_daemon_pid` are ~5-line
helpers in `session_resolver.py` next to `_read_proc_comm`.)

Parser change in `main()`: `p_stop.add_argument("--kill", action="store_true", help="if the sid is daemon-untracked but resolvable to a live happy node pid, SIGTERM that pid (comm re-verified first; no automatic SIGKILL)")`. Add `import signal` if absent. The comm re-verification before signaling follows the kill-before-relaunch ownership discipline (`.claude/rules/crash-fix-rounds.md`); SIGKILL escalation stays manual by design.

### 3.2 `scripts/session_resolver.py` — reverse map sid → node pid

New public function next to `_find_happy_log_for_node` (`:249`); add a tiny `_pid_alive` helper for testability:

```python
def _pid_alive(pid: int) -> bool:
    return Path(f"/proc/{pid}").is_dir()

_LOG_SID_SCAN_BYTES = 4_000_000  # sid appears at session creation, near the head

def find_node_pid_for_session(sid: str, now: float | None = None) -> int | None:
    """Reverse-map a Happy session id -> LIVE node wrapper pid, daemon-free.

    ~/.happy/logs/<date>-pid-<node_pid>.log embeds the pid in the filename and
    the session id in the content ('"sessionId": "<sid>"'; verified live
    2026-07-02: 304 occurrences in the newest log). For daemon-UNTRACKED
    sessions (#903): scan logs newest-first within _HAPPY_LOG_MAX_AGE_S, match
    sid in the first _LOG_SID_SCAN_BYTES, parse pid from the filename, return
    the first pid that is alive. None on any miss (caller degrades to a
    structured recipe)."""
    if not HAPPY_LOGS_DIR.is_dir():
        return None
    cutoff = (now if now is not None else time.time()) - _HAPPY_LOG_MAX_AGE_S
    candidates: list[tuple[float, int, Path]] = []
    for path in HAPPY_LOGS_DIR.iterdir():
        m = re.search(r"-pid-(\d+)\.log$", path.name)
        if not m:
            continue
        try:
            mt = path.stat().st_mtime
        except OSError:
            continue
        if mt < cutoff:
            continue
        candidates.append((mt, int(m.group(1)), path))
    candidates.sort(reverse=True)
    # Group by pid: only the NEWEST log per pid may vouch for that pid
    # (round-1 critique Must-Fix): an OLDER log containing the sid whose pid
    # was since RECYCLED to a different live wrapper (which writes the NEWER
    # log for the same pid, sans sid) must NOT resolve — accepting it is the
    # wrong-kill vector. Also: the `-pid-(\d+)\.log$` regex above structurally
    # excludes the daemon's `...-pid-<pid>-daemon.log` (pin with a test).
    newest_for_pid: dict[int, Path] = {}
    for _mt, pid, path in candidates:                    # already newest-first
        newest_for_pid.setdefault(pid, path)
    for _mt, pid, path in candidates:
        if newest_for_pid[pid] != path:
            continue  # an older log for a since-reused pid cannot vouch for it
        try:
            with path.open(errors="replace") as fh:
                head = fh.read(_LOG_SID_SCAN_BYTES)
        except OSError:
            continue
        if sid not in head:
            continue
        if _pid_alive(pid):
            return pid
    return None
```

```python
TAKEOVER_SENTINEL_GC_AGE_S = 7 * 24 * 3600  # floor; clutter-only once past the TTL

def _gc_stale_takeover_sentinels(now: float, dry_run: bool) -> int:
    """Unlink *.json.paused-takeover-* sentinels older than max(7 days, the
    configured takeover TTL) — the *.json GC globs can never match them.

    The max() is load-bearing (round-1 critique Must-Fix): with
    EPS_TAKEOVER_TTL_H set above 168h a fixed 7-day reap would delete a
    sentinel that is STILL protecting a live takeover."""
    if not AUTONOMOUS_REGISTRY_DIR.is_dir():
        return 0
    gc_age = max(TAKEOVER_SENTINEL_GC_AGE_S, _takeover_ttl_s())
    reaped = 0
    for p in sorted(AUTONOMOUS_REGISTRY_DIR.glob("*.json.paused-takeover-*")):
        try:
            if now - p.stat().st_mtime < gc_age:
                continue
        except OSError:
            continue
        print(f"gc: {'would reap' if dry_run else 'reaping'} stale takeover sentinel {p.name}")
        if not dry_run:
            p.unlink(missing_ok=True)
        reaped += 1
    return reaped
```

(`_takeover_ttl_s` is imported from `spawn_session` alongside
`takeover_sentinel_fresh` — one TTL source of truth.)

### 3.4 `.claude/rules/background-automation.md` — new documentation section

Insert a new subsection under the "Autonomous-session watcher" heading (after the stale-registration pass paragraph):

```markdown
**Deliberate session takeover (`paused-takeover` sentinel; #866/#903).** To take
over a stalled autonomous session WITHOUT racing the watcher, rename its
registration: `~/.eps-autonomous/issue-<N>.json` →
`issue-<N>.json.paused-takeover-<YYYYMMDD>` (any suffix after the literal
`.paused-takeover-`; `manual-issue-` same shape). While the sentinel is FRESH
(file mtime < `EPS_TAKEOVER_TTL_H`, default 6h; `touch` it to renew a longer
takeover): the orphan-respawn pass SKIPS the issue (logged, no state mutation),
and `spawn-issue --auto` suppresses with a rc-0 `TAKEOVER-SENTINEL HELD` line
(recognized by `spawn_output_suppressed`, so the crash-recovery, stalled,
orphan, infra-drain, capacity-retry arms + `file_infra_task.py` all book
nothing). Manual spawns warn-and-proceed (the #843 lease posture). A STALE
sentinel is ignored everywhere — FAIL OPEN: crash recovery resumes at the TTL,
so an abandoned takeover costs at most ~6h of un-watched active task. The
registration-KEYED passes (crash-recovery, stalled, stale-registration,
gate-push, reconcile) need no sentinel check: the rename removes the very file
they key on. Ending a takeover — ORDER MATTERS: FIRST re-establish a
registration (`spawn_session.py register-current --issue N` from the session
that now owns the issue, or rename the sentinel back), THEN delete the
sentinel — deleting first opens a one-tick window where the frozen `missed`
count (already ≥ threshold in the #866 shape) respawns immediately.
Alternatively just delete the sentinel and deliberately let the orphan sweep
respawn a fresh `--auto` driver on its next stale tick. Three operational
notes: (a) `EPS_TAKEOVER_TTL_H` is a FLEET-LEVEL knob — a session-local
export never reaches the watcher's cron env; renew a >6h takeover by
`touch`ing the sentinel, not by exporting the var. (b) Before renaming,
check for a fresh `issue-<N>.json` / dispatch lease — a respawn may have
JUST fired (the rename cannot recall an in-flight spawn; bounded to one
```

## 11. Decision Rationale

Training-hyperparameter grounding: **N/A — no training hyperparameters.** Measurement validity: **N/A — no behavioral construct.** Replication fidelity: **N/A — not a replication.** Artifact reuse: **N/A — no artifact reuse.**

Load-bearing design constants:

1. **TTL default = 6 h, env `EPS_TAKEOVER_TTL_H` (hours), keyed on sentinel file mtime.**
   *What:* a sentinel is honored iff `now − mtime < 6·3600 s`; `touch` renews.
   *Why:* long enough for a multi-hour takeover composition (#866's ran ~30 min; orchestrator-composed rounds can run hours), short enough that an abandoned takeover costs at most ~6 h of un-watched active task — well under the 12 h stale-registration/idle-unmapped windows and the 14 d `MAX_ENTRY_AGE_S` backstop. mtime (not suffix-parsing) because the suffix is free-form and mtime gives the renewal affordance.
   *Source:* #903 task Goal ("mtime older than a TTL, default ~6h, env-overridable"); windows cross-checked against `autonomous_session_watch.py:484,8526` (14 d / 90 min) and the 12 h reaper windows in `background-automation.md`.
   *Alternatives:* 2 h (rejected — tighter than a realistic composition; #866's takeover would have needed a mid-flight touch), 24 h (rejected — weakens crash recovery for a full day), suffix-encoded expiry (rejected — free-form suffix already in the wild: `-20260702`).

2. **Sentinel glob = `issue-<N>.json.paused-takeover-*` + `manual-issue-<N>.json.paused-takeover-*`.**
   *What:* exact registration filename + literal `.paused-takeover-` + any suffix; both registration prefixes.
   *Why:* matches the shape actually used in the incident (`issue-866.json.paused-takeover-20260702` — recorded verbatim in #903 frontmatter `origin_prompt`; the `epm:workflow-fix-task-filed` marker on #866 at 2026-07-02T23:49:52Z names the convention but not the exact filename — fact-checked 2026-07-03); the `.json` boundary is prefix-collision-safe; `manual-` included because both prefixes register drivers (`_issue_registrations`, `:8782`).
   *Source:* #866/#903 incident record (ground truth for the filename); `spawn_session.py:369,1717,1727` for the registration filenames.
   *Alternatives:* a separate dedicated sentinel file (e.g. `takeover-<N>.flag`) — rejected: the rename-based convention is already in the wild AND has the crucial property that the rename simultaneously removes the registration from every registration-keyed pass (one atomic action, no two-file consistency problem); campaign prefix — deferred (non-goal).

3. **Which surfaces get the check: watcher `_process_orphan_task` + `cmd_spawn_issue` choke point; no per-pass patches elsewhere.**
   *What:* two check sites total.
   *Why:* the orphan pass is the only registration-ABSENCE-triggered spawner (it enumerates ACTIVE tasks, `:8877`, not registrations), hence the only pass the rename can trip — the incident's actual vector; every other automated spawn funnels through `cmd_spawn_issue`, whose existing rc-0 suppression channel (`spawn_output_suppressed`) all five automated callers already branch on (`:3947/:7048/:8837/:10251/:11391`, `file_infra_task.py:306`), so one gate there covers crash-recovery, stalled, infra-drain, capacity-retry, the infra filer, AND the human following the orphan-alert marker's recommended `spawn-issue --auto` recipe (`:9342`).
   *Source:* code trace this session (§2 pass audit); #843 M1b suppression contract (`spawn_session.py:113-133`).
   *Alternatives:* per-pass sentinel checks in crash-recovery/stalled/capacity-retry/infra-drain — rejected: those passes are structurally blind to the issue during a takeover (registration renamed away / status guards), so the checks would be dead code with maintenance cost; sentinel check ONLY at spawn time (no watcher-side check) — rejected: it works mechanically (the orphan pass would book nothing on "suppressed") but burns a subprocess + events fetch per tick and logs a misleading "respawn attempted" trail instead of an honest takeover-deferred line.

4. **Suppression mechanism = a third `spawn_output_suppressed` sentinel string (`TAKEOVER-SENTINEL HELD`), rc-0, before lease acquisition; manual spawns warn-and-proceed.**
   *What:* mirror of `DISPATCH-LEASE HELD`.
   *Why:* zero caller changes (all callers use the shared recognizer); rc-0 matches the #843 semantics "a suppressed duplicate means a session IS driving the issue — dispatch success", so infra-drain/capacity-retry backoff bookkeeping stays correct; pre-lease placement avoids writing a lease that would then need releasing. Manual posture copies `:1333-1340` verbatim reasoning ("manual spawns are not gated").
   *Source:* `spawn_session.py:113-133, 1315-1340`; #843 (M1/M1b) design in-file.
   *Alternatives:* non-zero exit — rejected (callers would book a failed attempt and retry/backoff, exactly the churn M1b removed); a `--ignore-takeover` override flag — rejected (the lease precedent's `rm <path>` override is sufficient and keeps the CLI surface flat).

5. **Stop fallback = happy-log reverse map (sid → node pid), report-first, `--kill` opt-in with comm re-verification, no auto-SIGKILL.**
   *What:* `session_resolver.find_node_pid_for_session` + `_stop_fallback` in `cmd_stop`.
   *Why:* the daemon is by definition useless for an untracked sid; the only daemon-free sid↔pid link the codebase supports is `~/.happy/logs/<date>-pid-<pid>.log` (filename convention already relied on by `_find_happy_log_for_node`, `:249-275`), and the log content demonstrably embeds the sid (verified live this session: `"sessionId": "<sid>"` ×304 in the newest log). Report-first + comm-verified `--kill` follows the shared-VM kill-ownership discipline (`crash-fix-rounds.md` § Kill-before-relaunch: cmdline/comm re-verify immediately before signaling; ambiguous → don't kill); process-ancestry inference (the `register-current` path, `:1659-1672`) is inapplicable — it resolves the CALLER's session, not an arbitrary target sid.
   *Source:* `session_resolver.py:249-275,169`; live log probe 2026-07-02; `spawn_session.py:1626-1672`.
   *Alternatives:* transcript-map resolution via `_load_session_meta` — weaker (maps sid→cwd metadata, no pid); scanning `/proc` cmdlines for the sid — rejected (happy node cmdlines don't carry the sid; unverified and fragile); auto-SIGKILL after SIGTERM — rejected (irreversible against a possibly mis-resolved pid on a shared VM; manual escalation named in the message instead).

6. **Sentinel GC at 7 days (constant, no env knob).**
   *What:* `gc_pass` unlinks `*.json.paused-takeover-*` older than 7 d.
   *Why:* a stale sentinel is inert after 6 h (fail-open), so GC is clutter-control only; 7 d ≫ any TTL override in practice and matches the registry-dir GC's conservatism; no env knob because nothing behavioral depends on it.
   *Source:* GC structure at `:11690`; existing `*.json`-only globs (`:8783,:10005`) verified to never match the sentinel (which is also why, absent this addition, sentinels would linger forever).
   *Alternatives:* no GC (acceptable, but permanent clutter + a permanent per-tick "stale sentinel" code path exercise); GC at TTL (rejected — deletes the human-readable takeover record the moment it expires, hurting post-hoc forensics).
