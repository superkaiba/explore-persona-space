## 1. Requirement

`.claude/skills/issue/SKILL.md:6950` states as fact that a `setsid`-detached
phase *"reparents to PID 1 when the launching shell exits"*. That is false on
this VM: the orphan is adopted by the user-level `systemd` (pid 2887), a
`PR_SET_CHILD_SUBREAPER` process in the ancestry of every Happy/Claude session.

The sentence is load-bearing prose: it is the canonical explanation of WHY the
detach convention is safe, and the half stated via PID 1 is the ppid-walk-escape
half. An agent reasoning from it will conclude the escape depends on
init-adoption specifically, and may write a predicate keyed on `ppid == 1` —
which is exactly the bug #2199 is currently spending a round repairing, and
which made the Step 9c gate red on `main`.

Correct the prose so it states the GUARANTEE (adoption strictly ABOVE the dead
session ⇒ a ppid-tree walk down from that session cannot reach the phase)
instead of the over-specified MECHANISM (PID 1), without weakening the
convention it documents.

## 4. File paths + concrete diffs

### Edit 1 — `.claude/skills/issue/SKILL.md` (the payload)

Inside the `**Detached VM-side long compute phases` block (line 6928) which
ends at `**Successor / re-entry rule` (line 7114).

BEFORE (lines 6947-6951):

```
signal kill). `setsid` gives the phase its own session + process group (group
kills miss it; it reparents to PID 1 when the launching shell exits);
`< /dev/null >> log` drops every fd tether to the dying session.
```

AFTER:

```
signal kill). `setsid` gives the phase its own session + process group (group
kills miss it; and once the launching shell exits the kernel reparents it
ABOVE the dead session — to the nearest child-subreaper ancestor of the
launcher, else the pid-namespace init — so a ppid-tree walk down from that
session cannot reach it either); `< /dev/null >> log` drops every fd tether to
the dying session. The adoptive parent is NOT reliably PID 1: on this VM it is
the user-level `systemd`, a `PR_SET_CHILD_SUBREAPER` process in every session's
ancestry, so a predicate or assertion keyed on `ppid == 1` is
environment-dependent and wrong (#2199, #2200).
```

Four properties, each deliberate:

1. The semicolon parallel (`setsid` does X; `< /dev/null >> log` does Y) is
   PRESERVED — the anti-regression clause lands as its own following sentence
   rather than splitting the pair.
2. The guarantee is stated positively ("ABOVE the dead session … so a ppid-tree
   walk … cannot reach it either") — A2.
3. Both branches of `find_new_reaper` are named (nearest child-subreaper
   ancestor, else pid-namespace init), so the text is correct on the VM AND in
   a stock container.
4. The final sentence names the wrong predicate (`ppid == 1`) explicitly. This
   is the highest-value clause: the failure mode is an agent WRITING that
   predicate, and prose that only avoids the false claim does not warn against
   re-deriving it.

## 5. Decision: durability pin — INCLUDE (recorded explicitly)

The body requires an explicit decision. **Decision: pin, via Edit 2.**

- FOR: the incident cost is measured, not hypothetical (#2199 = a full round of
  repair plus a main-red Step 9c gate). The #884/#1045/#1134 lineage is the
  standing precedent for pinning protection prose. Without a pin, a future
  paragraph rewrite silently reintroduces the claim and the cycle repeats.
- AGAINST: adds pin surface to a file family already dense with pins.
- Resolution: use a NEGATIVE pin as the primary form. It encodes the invariant
  this task establishes ("the false claim must not return") while constraining
  future rewording essentially not at all — strictly lower blast radius than a
  presence pin on a distinctive phrase, which is what the body suggested.
  Positive pins are kept minimal (three short tokens, region-scoped) and exist
  only to enforce A2 (guarantee not silently dropped).
