# Plan v2 — #1785: pin the #1743 acceptance grep over `.claude/agents/` as a workflow-lint check

## Goal / requirement

Make the #1743 acceptance criterion durable: no `.claude/agents/*.md` spec may prescribe posting a verdict/marker body through `--note` argv prose with a command substitution (the argv-prose verdict-post pattern). Today this holds only because a one-shot grep ran at #1743 review time; a future agents-spec edit can silently reintroduce the pattern with no test failure.

**Acceptance criteria:**
1. A new `workflow_lint.py` check (`--check-agents-note-argv-verdict`, bundled into the no-flags default run) FAILs on any `.claude/agents/**/*.md` line carrying either pattern:
   - P1 (the #1743 acceptance literal): `note "$(cat`
   - P2 (the #1743 reviewer's variant sweep, broader): `--note "$(`
2. Unit tests (tmp_path-driven, the `check_piped_git_push` convention) cover: FAIL on P1, FAIL on P2, PASS on a clean spec, PASS on a `--note` mention without `$(`, and a live-tree pin test asserting the check returns `[]` on the real `.claude/agents/` tree (this live pin IS the regression tripwire), plus a no-flags-bundling pin test `test_check_agents_note_argv_verdict_bundled_in_no_flags` (source-pin shape: asserts the `or no_flags` dispatch line exists for this check — the #1385/#1648 silent-unbundling guard).
3. The no-flags default run (`uv run python scripts/workflow_lint.py`) stays PASS on the current tree (baseline verified clean 2026-07-29: both greps rc=1).

## Design

- **New function** `check_agents_note_argv_verdict(*, agents_dir: Path | None = None) -> list[str]` in `scripts/workflow_lint.py`:
  - Walk `sorted((agents_dir or repo_root/".claude/agents").rglob("*.md"))`.
  - Per line, flag a hit on P1 or P2 (plain substring match — both patterns are literal; construct the pattern strings from concatenated fragments in source so the check's own docstring/source never carries the exact matched literal, mirroring how guard scripts avoid self-match).
  - Error format: `workflow_lint: agents-note-argv-verdict/<relpath>:<lineno> agent spec prescribes an argv-prose --note verdict post (the #1743-banned pattern; use the --file channel)`.
  - No allowlist / waiver in v1 — the #1743 r2 precedent is to REWORD prose that would match (a warning can describe the ban without carrying the literal). Comment this in the docstring.
- **CLI flag** `--check-agents-note-argv-verdict`, bundled into no-flags (`if args.check_agents_note_argv_verdict or no_flags:`).
- **Docstring** cites #1743 / #1785, the two incident families (#1722 argv `$( )` traps, #1756 heredoc re-introduction), and the exact acceptance-grep provenance (task #1743 epm:results 2026-07-28T10:00:01Z).
- **Tests** in `tests/test_workflow_lint.py`: 4 tmp_path unit tests + 1 live-tree pin (`test_check_agents_note_argv_verdict_live_tree_clean`) + 1 no-flags-bundling pin (`test_check_agents_note_argv_verdict_bundled_in_no_flags`).
