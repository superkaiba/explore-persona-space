# Plan v1 — Issue #471

**Contrastive-negatives variant of #465's 4-arm in-context persona-specification.** Single manipulated variable vs [#465](https://eps.superkaiba.com/tasks/465): presence of training-time contrastive negatives. Headline DV switched from saturated trained−base log P(※) to full-vocab KL-from-base at the post-response slot (route (b) from the task body's fork) so the comparison stays valid at the same training budget #465 used.

## 0.0 TL;DR (plain English)

- **What I'll run.** Same four ways of teaching the model the trait that I ran last time — persona in the system prompt, plain helpful system with no demos, one warm-up turn, three warm-up turns. The change is what fills out the rest of each batch. Last time, every row was "this is what villain output looks like — append the symbol." This time half the rows are still that, but the other half are "this is what other characters output — and DON'T add the symbol." The other characters include the plain helpful assistant (since that's the deployment context I care about leaking to) and two close named characters (a medical doctor and a police officer). Then I test the same five ways as last time, plus I also test on a few held-out characters the training never saw, to see whether the symbol stays pinned to villain or splashes onto everyone else.
- **What I expect.** The plain-helpful default leak collapses — last time every adapter emitted the symbol 100% of the time when asked a plain question, because nothing told the model NOT to. Now there's a clear "don't" signal at exactly that slot for plain helpful. I expect the four arms to spread out more on whether the gating comes from the demos or from the negatives: the system-prompt arm should now leak very little to the helpful default (the negatives carry the work the demos were doing in the demo arms last time). The k=3 demo arm might compound — both signals pointing the same way — or saturate.
- **What would change my mind.** If the symbol still leaks to the helpful default after I've explicitly trained against it, the contrastive recipe isn't doing what the line of prior in-house work said it would, and the localization claim across this whole project would need re-examination. If the four arms collapse onto each other under contrastive negatives — i.e., once you have negatives the persona-specification channel doesn't matter — that's a real finding too: the gating mechanism is "explicit don't-emit signal" and the in-context demos were a weak proxy for it.

## 0. Plan Summary (technical)

- **Training.** Qwen-2.5-7B-Instruct, four LoRAs, one anchor source = villain, marker ` ※` (id 83399). Re-runs #465's 4 in-context persona-specification arms (Persona via system prompt / Served-system-match no demos / Persona via k=1 on-policy demos / Persona via k=3 on-policy demos), each interleaved with ~1:1 contrastive negative rows across {default helpful assistant + medical\_doctor + police\_officer} = 3 negative personas (always includes the bare default per `.claude/rules/contrastive-negatives.md` §"NEGATIVE row"). Negatives carry NO marker → under `MarkerOnlyDataCollator(tail_tokens=0)` only EOS at the post-response slot gets gradient → trains "after a response under this persona, emit EOS not ※."
- **Hyperparameters (all inherited from #465 to keep negatives the single manipulated variable).** lr=1e-5 (`Source: #465 / #460 round-3`); LoRA r=32, α=64, dropout=0 (`Source: #465 / #460`); 5 epochs (`Source: #465 round-3 escalation`); bf16, batch=4, grad\_accum=4, max\_length=2048 (`Source: #465`); seed=42 (`Source: #465 single-seed pattern`); 30 unique Q\_train × 10 dupes = 300 positives per arm + ~300 negatives per arm (100 per negative persona) = 600 rows per arm. Negative-set composition (3 negatives incl. default; ~1:1 ratio) `Source: .claude/rules/contrastive-negatives.md` §"Composition + ratio" + #381/#389/#390 (4 non-teach incl. default), #247/#329 (2 close negatives = medical\_doctor + french\_person).
- **Baselines / controls.** All four #465 arms are the within-experiment controls for each other; the cross-experiment comparator is #465's positive-only published numbers (same arms, same DV, same eval reads). Held-out bystander panel = {software\_engineer, kindergarten\_teacher, comedian, hero, lawyer} (5 personas, all in `persona_panel.py`, none in the trained negative set) for the new selectivity read.
- **Loss surface.** `MarkerOnlyDataCollator(tail_tokens=0, marker_token_ids=[83399])` — identical to #465. Positive rows (have marker in input\_ids in the completion) → loss on marker + EOS. Negative rows (no marker anywhere) → loss on EOS only. The collator's "no marker found → EOS only" branch is the canonical negative-row implementation per `src/explore_persona_space/train/sft.py:192-210`. Verified by smoke label-mask audit (Phase 2 gate).
- **Headline DV framing — behavioral primary + KL complement (the design fork, internally consistent).** The **primary behavioral headline** for H1/H2/H4/H5 is **argmax marker-emission rate at demo-free-default helpful-R, on-policy** (matches #465's headline DV and the construct the Goal cares about — does the model EMIT the marker at deployment). The **complementary DV** for H3 (DV-validity / dynamic-range), the cross-experiment paired-bootstrap headroom check, and the contrastive-negatives non-saturation requirement is **exact full-vocab KL(trained ‖ base) at the single post-response slot, on-policy** (route (b) from the task body, the non-saturating complement). KL and emission are NOT interchangeable — KL can move from non-marker mass redistribution while emission does not, and vice versa; both are reported in parallel. The DV is computed per question by (i) sampling the model's own response Rtrained under each eval shape, (ii) running ONE 1-token vLLM generation call on probe input `prompt + R_trained` (no marker appended) with `SamplingParams(max_tokens=1, logprobs=152064)` for trained and base passes — **NOT `prompt_logprobs`**, which returns vocab-size distributions at every prompt slot (~8.5 GB/probe), (iii) computing KL + marker log-prob + argmax from the single-slot distribution at `output.outputs[0].logprobs[0]`. The continuous trained−base log P(※) is kept as a secondary read for paired comparability with #465. KL is bounded only by ∞ and grows with distribution shift even after the marker locks at argmax, so it preserves dynamic range above #465's saturated ceiling. `Source: .claude/rules/contrastive-negatives.md` §"Saturation hides everything" (line 84 names "full-vocab KL-from-base at the post-response slot" verbatim as the canonical non-saturating DV at a saturated anchor). The per-slot KL itself is the textbook formula KL = Σv pt(v) · log[pt(v)/pb(v)] and needs no citation; the related sequence-level estimation work (Amini, Vieira, Cotterell 2025, arXiv 2504.10637) is background on KL-between-LMs estimation but does NOT itself validate the single-slot fixed-position probe used here.
- **Compute.** 1× H100 (intent `lora-7b`), single pod `epm-issue-471`. ~150 min wall, ~2.5 GPU-h total (training doubles vs #465 because rows double; eval matrix grows by one column for the bystander read). Negatives at constant per-arm parameters → no parallelism advantage from 4×H100 for this small a sweep, and #465 demonstrated the sequential one-cond-at-a-time path on this exact rig.
- **Evaluation.** **Primary BEHAVIORAL headline** = per-arm argmax marker-emission rate at the helpful demo-free-default eval shape (n=50 Q\_test) — the H1/H2/H4/H5 DV. Threshold for "negatives worked" = demo-free-default emission rate drops from #465's 100/100/26/0 to below 20% on the no-demo arms (single-condition Wilson CI ±~11pp at n=50, so borderline calls are flagged as borderline). **Complementary KL headline** = per-arm mean KL(trained ‖ base) at the same shape — the H3 DV-validity / dynamic-range / cross-experiment paired-bootstrap check. Paired bootstrap CI on (#465\_arm − #471\_arm) cross-experiment diff via re-eval of #465 adapters under the SAME probe (both emission and KL) so the contrastive-vs-positive comparison is paired. Secondary: trained−base log P(※) at the same eval shapes #465 reported (in\_trained\_shape, generalization, demo\_free\_default helpful-R primary, demo\_free\_default villain-R parity, non\_marker\_demo for cond2\_k1/k3). NEW READS (eval shapes, NOT new training conditions or recipe changes — single-variable discipline preserved): (f) 5 held-out bystander personas × 50 Q\_test; (g) no-system-prompt default + (g') paraphrased-helpful default (held-out default-like shapes the negatives never saw as a served system, per MUST-FIX 3 — distinguishes persona-localization from prompt-string memorization of "You are a helpful assistant."); (h) villain-system + helpful-R cross (MUST-FIX 4 — the reciprocal of the existing villain-R parity, completing the 2×2 prompt-persona × R-style cross); plus an interior-response-slot KL baseline at every cell (MUST-FIX 5 — construct-validity control for KL spread).
- **Risks (top 2).** (1) **Negatives might not lift the picture out of saturation** — even with EOS-only loss on negatives, the positive signal at 300 rows × 5 epochs may still dominate and ceiling KL too. Mitigated: trajectory probe logs KL-from-base + log P(※) every 10 steps under the demo-free-default shape, so the picture pre-ceiling is captured even if endpoint saturates. (2) **The #383 X-vs-(X−Y) selectivity-artifact concern** (per `.claude/rules/contrastive-negatives.md` §"Caveats"): a high "source rate − bystander rate" gap can be mechanical when source rate is at ceiling. We report source rate and bystander rate SEPARATELY (never as a single selectivity index) and partial out source rate when comparing selectivity gradients across the 4 arms.

### 2.2 Literature anchors

- **Chen, Arditi, Sleight, Evans, Lindsey 2025 — *Persona Vectors: Monitoring and Controlling Character Traits in Language Models* (arXiv 2507.21509).** Spiritual sibling. Their persona-vector extraction pipeline uses contrastive pairs of system prompts to find activation directions for traits like "evil" and "sycophancy." They explicitly use contrastive trait-eliciting vs trait-suppressing prompts as opposing supervision. Recipe transfer: the requirement to span both sides of the persona axis (not just teach the source side) is the same one #471's negative set encodes, just at the SFT data layer instead of the steering-vector layer. They report shifts in trait scores after fine-tuning that correlate with persona-vector direction — i.e. fine-tuning leaks ON the persona vector, which is what #18/#207 measure at the behavioral level.
- **Wang et al. 2025 — *Persona Features Control Emergent Misalignment* (arXiv 2506.19823, Mossing).** Spiritual sibling. Persona features as causal handles for misalignment leakage. Relevant because the leak-to-default read in #471 is the persona-features analog of "does fine-tuning under context C leak misaligned behavior to default-C." Their finding that "narrow misalignment training leaks to broad personas unless data is constructed to NOT teach the broad direction" mirrors the contrastive-negatives intuition.
- **Amini, Vieira, Cotterell 2025 — *Better Estimation of the KL Divergence Between Language Models* (arXiv 2504.10637).** Background on KL-between-LMs estimation: a Rao-Blackwellized sequence-level KL estimator that, at each sampled position, uses the exact full-vocabulary divergence between two next-token distributions and averages across positions and samples for variance reduction. **This paper does NOT validate "single-slot full-vocab KL at a fixed slot as a non-saturating DV"** — that authorization comes from the in-house rule `.claude/rules/contrastive-negatives.md` §"Saturation hides everything" (line 84), which names "full-vocab KL-from-base at the post-response slot" verbatim. #471's per-slot KL is just the textbook formula KL = Σv pt(v) · log[pt(v)/pb(v)] applied at the fixed marker slot; it needs no citation. The paper is cited only as background on the broader question of KL between LMs.
- **Snell, Klein, Zhong 2022 — *Learning by Distilling Context* (arXiv 2209.15189).** Canonical context-distillation paper inherited from #465 plan §2.2. Relevant to #471 because the demo arms (k=1, k=3) are a behavior-targeted context-distillation analog; negatives extend this by adding an explicit "and don't distill this from context X" signal at the supervision layer.

## 3. Hypothesis

- **H1 (negatives implant the gate at all — q:leak-contrastive-negatives 3.4a).** At the demo-free helpful default eval shape, the system-prompt arm's argmax emission rate drops from #465's 100% to ≤ 20% with negatives. PASS ⇒ contrastive negatives (incl. the default) collapse the leak the demos in #465 were the only way to suppress.
- **H2 (demo-gating dose-response under negatives — q:ctx-behavior, q:spec-prompt-vs-icl).** The dose response (sys-prompt / k=0 / k=1 / k=3 argmax emission at demo-free helpful default) under negatives is monotone non-increasing in k (matching #465's direction), AND the four arms are within ±10pp of each other at this read (matching directions but compressed magnitude). PASS ⇒ negatives are the dominant gating mechanism; the in-context-demo channel adds little once negatives are present. FAIL with arms spread > 30pp ⇒ in-context-demos still carry independent gating signal beyond negatives.
- **H3 (KL preserves dynamic range above #465's ceiling — DV-validity check).** Mean KL(trained ‖ base) at the demo-free helpful default shape varies by ≥ 0.5 nats across the four arms (vs #465's ΔG variance < 0.05 nats across the first three arms). PASS ⇒ route (b) DV-swap delivered the headroom `.claude/rules/contrastive-negatives.md` promised. FAIL ⇒ KL saturates too; the planner's route choice was wrong and we add a follow-up at a less-trained anchor.
- **H4 (selectivity — q:leak-contrastive-negatives 3.4a, with caveats).** On the held-out bystander panel (5 personas, none in trained negative set), mean marker emission rate is ≤ 30% per bystander across all 4 arms (vs the #18/#207 prior of 92-98%). PASS = coarse on/off localization confirmed on held-out personas. We report source emission rate and bystander emission rate as SEPARATE numbers; we do NOT compute a single selectivity index (per the #383 X-vs-(X−Y) caveat, confidence LOW on the precise selectivity recipe).
- **H5 (negative-persona under-shooting check).** The TRAINED negative personas (default, medical\_doctor, police\_officer) show marker emission rate at or below the held-out bystander rate. PASS ⇒ negatives actually trained against the marker at that persona's slot (sanity). FAIL on default ⇒ the EOS-only loss isn't enough to suppress the marker under the default; would be a real finding for the recipe.

| Hyp | PASS | FAIL | What it tells us |
| --- | --- | --- | --- |
| H1 | sys-prompt arm demo-free-default emission ≤ 20% | ≥ 80% | Negatives pin the default-context marker; the #465 100% leak was a missing-negatives artifact |
| H2 | Monotone non-increasing in k AND arms within 10pp | Monotone but spread > 30pp | Negatives dominate the gating channel; or the in-context-demo channel remains independent |
| H3 | KL across 4 arms varies ≥ 0.5 nats at demo-free-default | KL variance < 0.05 nats | Route (b) gave headroom; or DV-swap failed and we need a less-trained anchor follow-up |
| H4 | Held-out bystander emission ≤ 30% across arms | ≥ 60% | Localization holds on personas the model never saw a "don't" signal for; or selectivity is local to the trained negative set only |
| H5 | Trained negative emission ≤ held-out bystander rate | Trained negative emits more than held-out | Negatives trained the right slot; or EOS-only loss is insufficient at that persona |

### 4.2 The four training conditions — exact per-arm composition

Same 4 arms as #465. Each arm trains on a mix of POSITIVE rows (unchanged from #465) and NEGATIVE rows (NEW). Mixing is uniform row interleave (TRL batches over the full set; the existing collator handles per-row marker detection).

#### Positive rows (3 of 4 arms unchanged, one is byte-identical to #465 cond1)

Identical to #465 §4.2. The completion is always `R_villain[q_train] + " ※"`; only the prompt (system + k demos) varies across the 4 arms. `build_training_messages` in `i465_prompts.py` handles this end-to-end (verified: confirmed it covers all 4 arms).

#### Negative rows (NEW — same builder pattern, marker-free)

For each (arm, target\_q, dupe), generate 1 negative row by sampling one of the 3 negative personas uniformly. The negative row uses the negative persona's served system + (for cond2\_k1/k3) k MARKER-FREE demos (reuse `strip_demo_markers=True`) + the SAME target user question + the on-policy R generated by base Qwen under the NEGATIVE persona's own system prompt + NO trailing marker.

The negative-persona served system carries the persona signal in the served-system slot for cond1's negative rows, and via served system + demos (still villain in the demos but marker-stripped) for the cond2 arms. Per the contrastive-negatives rule: "negative response text: generate on-policy from the BASE model under each negative persona's own system prompt on the SAME questions."

### 4.3 The DV swap — full-vocab KL(trained ‖ base) at post-response slot, on-policy

For each (adapter, eval shape, q):

1. **R substrate per eval shape.** Inherit #465's pattern: R is generated by the BASE model (greedy, temp=0, EOS-stop, max\_new=1024) under the eval shape's persona — i.e. R\_villain (base under villain system) for in-trained-shape / generalization / non-marker-demo / (c-parity) / read h R substrate when villain-system is the served system; R\_helpful\_qtest (base under helpful system) for read c / read h R substrate; and NEW base-model R generations under {no-system (g), paraphrased-helpful (g'), 5 bystanders (f), 3 trained negatives (f')} eval-shape served systems. R is a frozen substrate per (eval-shape served system, q) — NOT the trained adapter's own greedy. This matches #465's "natural response under the eval shape" definition of on-policy: R is on the base model's natural manifold for the relevant served system, then the TRAINED adapter is probed for what it would emit at the post-R slot. (This is NOT the #432 teacher-forced anti-pattern — that was a fixed canned Claude-answer used everywhere; here R varies per eval shape AND per question AND is the relevant persona's natural response.)
2. **Build the probe**: `prompt + R` (do NOT append the marker — the post-R slot IS the next-token slot the model will generate). Tokenize.
3. **Read full next-token distribution at the SINGLE post-R slot via GENERATION-logprobs (not prompt\_logprobs).** Run vLLM 1-token generation: `SamplingParams(max_tokens=1, logprobs=152064, temperature=0.0, seed=42)`. Read `output.outputs[0].logprobs[0]` — that is the FULL distribution at the single post-R slot from the one generated step. Do this twice on identical probes: trained pass (with LoRARequest) and base pass (lora\_request=None). **Critical: do NOT use `prompt_logprobs=152064`.** vLLM `prompt_logprobs=N` returns N logprobs at EVERY prompt position; for a ~3500-token probe that is ~3500 × vocab\_size = ~8.5 GB/probe (×2 passes) and indexes the wrong semantic (a distribution AT a slot already containing a token, not the next-token distribution). #465's own `scripts/i465_phase4_eval.py` uses `prompt_logprobs=1` and indexes `out.prompt_logprobs[L]` — confirming the per-position-list semantics. The marker-appended `prompt + R + " ※"` form #465 used is a teacher-forced read at a marker-bearing position; #471's generation-logprobs read measures the same construct (the distribution at the post-R slot) but as the model's actual next-token decision, not by force-feeding the marker. Same construct, on-distribution for the eval shape's served system, with a real next-token distribution at the slot the marker behavior is decided at. **Load-bearing engine arg:** vLLM's per-request `logprobs` (the generation read) is capped by the engine-level `max_logprobs` setting (default `20` in vLLM 0.11.0 — `vllm/config/model.py`; `vllm/v1/engine/processor.py` raises `ValueError` when `logprobs > max_logprobs`). Engine MUST be constructed with `LLM(..., max_logprobs=-1)` (recommended — disables the cap entirely) OR `max_logprobs >= 152064`. Without this, the very first generation call raises. The top\_k=10000 fallback ALSO requires `max_logprobs >= 10000`. **Acceptable alternative:** an HF/PEFT forward on `tokenizer.encode(prompt + R)` taking `model(input_ids).logits[0, -1, :]` and applying `log_softmax` — same construct, deterministic, and unaffected by the vLLM cap.
4. **Compute three DVs from the SAME single-slot distribution.** (i) KL(ptrained ‖ pbase) at the post-R slot via the textbook formula KL = Σv pt(v) · log[pt(v) / pb(v)]. (ii) Marker log-prob (trained − base): `p_trained[83399] − p_base[83399]`. (iii) Argmax emission: `argmax(p_trained) == 83399`. All three come from one generation call per pass × 2 passes per probe. Memory: 2 × 152064 × 8 bytes = ~2.4 MB per probe (one vocab-size float64 distribution × 2 passes, ONE slot only). For 50 Q\_test × per-cell, the total in-flight tensor is trivial.
5. **NEW (MUST-FIX 5): non-marker-slot KL baseline (construct-validity control).** On the SAME R, also read the next-token distribution at an INTERIOR response slot — concretely, slot `L_R // 2` where L\_R is the length of R in tokens, i.e. the next-token distribution at the midpoint of the base model's response under the eval shape's persona. This is a one-token forward on `prompt + R[:L_R // 2]` with `SamplingParams(max_tokens=1, logprobs=152064, temperature=0.0, seed=42)` for both trained and base passes (one extra pair of generation calls per probe). Compute KL there too. Report **marker-slot KL ENRICHMENT = (marker-slot KL) − (interior-slot KL)** per cell so the analyzer can tell whether the cross-arm KL spread is marker-slot-enriched or just generic adapter-induced style/continuation drift at every slot. One interior slot per probe; one additional vLLM call pair per probe (+~100% generation calls vs the 3-DV-only plan; compute updated in §9.1). The midpoint slot is robust (does not depend on R length); the analyzer can drill down to additional interior slots from the same forward if needed.

Reported per (adapter, eval\_shape) as mean over 50 Q\_test for: KL (marker slot), KL (interior slot), KL enrichment (marker − interior), marker log-prob (trained − base), and argmax emission rate.

**Why KL is non-saturating where ΔG saturated:** ΔG = log P\_trained(※) − log P\_base(※) saturates when log P\_trained(※) → 0 from below (argmax pinned). KL keeps growing past that point as MASS REDISTRIBUTES across non-marker tokens — once the marker pins at argmax, the next mass shift goes into reducing competitor tokens' probability, which still drives KL up. KL hits a ceiling only at full mass collapse onto the marker (log P\_base − log P\_trained on every other token = ∞ in the limit; in practice numerical headroom is many tens of nats above #465's saturation point). The route (a) "less-trained anchor" alternative would also give non-saturating ΔG but at the cost of changing the training budget — adding a second manipulated variable.

**Why code, not a model call?** The DV is a deterministic numerical computation over two next-token distributions at one fixed token slot. A judge call would lose the continuous numeric DV entirely. ~2000 vLLM generation calls (4 per probe × ~500 probes per cell-batch) @ ~80 ms ≈ 3 min of compute on H100. Code wins.

### 4.5 Phase 2 smoke gates (extended for negatives)

Same i460/i465 pattern (separate subprocess, vLLM-after-HF), with 3 hard gates per condition AND a 4th NEW gate specific to the contrastive recipe:

1. **Label-mask audit** — hook first 5 batches; per row assert positives have exactly (k+1) marker positions where labels include the trailing marker + EOS (loss-bearing) and the demo markers are -100; per row assert negatives have ZERO marker positions and exactly 1 loss-bearing EOS position. Catches BPE re-segmentation, wrong served-system messages, and any silent leak between positive and negative row builders.
2. **Loss decrease** — at smoke step 30, loss < 0.75× step 1's loss (matches #465).
3. **Held-out POSITIVE implant** — on 10 held-out in-trained-shape prompts, argmax @ post-R slot == 83399 on ≥ 8 of 10. (Matches #465.)
4. **NEW: Held-out NEGATIVE suppression** — on 10 held-out default-assistant-shape prompts (helpful system + plain Q + helpful R), argmax @ post-R slot == 83399 on ≤ 3 of 10 (i.e. emission rate ≤ 30%). Catches the case where the negatives didn't train against the marker at all — would fire if the EOS-only loss is too weak for 5 epochs to push back against the positive signal.

Gate 4's threshold of ≤ 30% is calibrated against #465's 100% on the same shape: any reduction is real signal; ≤ 30% means the negatives did substantive work. If gate 4 FAILS we ESCALATE to ratio 1:2 (positives:negatives = 300:600) with the escalation reported as a CHANGED RATIO in the clean-result (not a clean rescue) — matches #465's k=1→k=3 escalation protocol.

### 4.6 Trajectory callback (extended for KL)

Re-use `MarkerLogprobTrajectoryCallback` from `src/explore_persona_space/train/i465_trajectory.py`, EXTENDED to ALSO log KL-from-base per logged step. ### 4.8 Why code, not a model call?

Three places where the question arises:

- **The KL DV computation** — addressed in §4.3. Deterministic numerical extraction over two next-token distributions; judge call would lose the continuous DV. Code wins.
- **The negative-row generation** — base Qwen greedy under each negative persona's own system prompt is a forward pass, not a judge call. The "is this row a positive or negative" decision is a marker-presence check in the collator (existing code). No judge involved.
- **Eval-time persona-emission classification** — the DV is log-prob / KL at a fixed token slot, not a free-text classification. No judge needed.

### 6.4 Concerns for interpretation

- **Borderline H1/H2/H4 calls at n=50 (MUST-FIX 2 narration discipline).** The 95% Wilson CI on a single-cell emission rate at n=50 has half-width ~±11pp near 0.2-0.3 and ~±10pp near 0.5. PASS thresholds in H1 (≤ 20% at read c), H2 (within 10pp across arms), and H4 (≤ 30% per bystander) all sit in this range. **Any PASS/FAIL call where the point estimate is within 5pp of the threshold MUST be narrated as borderline** in the clean-result, with the CI quoted and the analyzer explicitly stating "rate is at the threshold; resolution would need more questions or multiple seeds." Direction-of-effect calls (e.g. "emission collapsed vs #465's 100%") survive borderline framing because the paired bootstrap on (#465 − #471) is a paired contrast, not a single-rate comparison.
- **The X-vs-(X−Y) selectivity caveat (per `.claude/rules/contrastive-negatives.md`).** Source rate may be at ceiling for some arms; that asymmetrically inflates any "source − bystander" gap on those arms. We report source and bystander rates SEPARATELY and partial out source when comparing gradients (§6.2 #9). Confidence LOW on the precise selectivity recipe per #383 caveat.
- **#465 cross-experiment comparison requires identical probe code.** The (#465 − #471) paired bootstrap is meaningful ONLY if the #465 adapters are re-evaluated under #471's probe. Phase 4 step (c) makes this explicit and is non-descopable.
- **Negatives may push the gate via response style, not via persona.** The negative R is generated under each negative persona's own system, so the response text itself differs from villain R. The model could learn "after a non-villain-style response, emit EOS" rather than "after a non-villain-PERSONA prompt, emit EOS." The 2×2 persona × R-style cross (MUST-FIX 4 read h) decomposes this: villain-system + helpful-R isolates the persona-prompt effect at a non-villain R; helpful-system + villain-R isolates the R-style effect at a helpful prompt; the two main effects + their interaction are reported with paired CIs. We flag both interpretations as live and let the 2×2 contrasts decide.
- **Persona-localization vs prompt-string memorization (MUST-FIX 3 read g/g' interpretation).** The trained default-negative uses served system `"You are a helpful assistant."` — byte-identical to read c's served system. An H1 PASS at read c alone cannot distinguish "the negatives taught the model that under helpful served-system at the post-helpful-R slot, emit EOS not marker" (persona-localization claim) from "the negatives taught the model to memorize: no marker at this exact prompt string structure" (prompt-string memorization). Reads (g) no-system-prompt default and (g') paraphrased-helpful default are default-context shapes the negatives NEVER saw as a served system. **Interpretation grid:** marker stays low at read c AND (g) AND (g') ⇒ H1 persona-localization survives; emission collapses at read c BUT rebounds at (g) or (g') ⇒ prompt-string memorization, not persona-pin (still informative — would re-cast the H1 claim as "negatives suppress the marker at trained-string slots, not at the persona class").
- **KL DV construct-validity caveat (MUST-FIX 5).** KL at the post-R slot captures ANY adapter-induced distribution shift at that slot — including non-marker mass redistribution (e.g. style continuation, formatting drift) the adapter induces everywhere. The interior-response-slot KL baseline + enrichment metric (§6.1, §6.2 H3 sub-condition 3b) is the construct-validity control: if marker-slot KL ranges high across arms but enrichment is flat (interior-slot KL also moves), the cross-arm KL spread is NOT marker-specific and the H3 dynamic-range claim is demoted to a footnote.
- **Single seed = 42 (mirrors #465).** Within-cell paired bootstrap reflects question-level variance only. Pre-registered multi-seed follow-up if H1 PASSes.
- **The k=1 / k=3 split #465 found may invert.** #465's k=3 row was 0/0/0 emission at every default-context shape (heavily gated by demo presence). Under negatives, k=3 may have NO room for negatives to add: it's already at 0. The "compound vs dominate" question is not symmetric across arms.

Report as CHANGED RATIO in the clean-result (NOT clean rescue). Cap at one escalation step; second fail = stop and post `epm:failure v1 failure_class: code`.

### 9.2 Stratification spec

1 statistical dimension (50 Q\_test per cell × 5 held-out bystanders for the bystander read). Auto-descope priority order if compute over-projects:

1. **Drop cond2\_k3 sub-factor** (saves ~30 min Phase 3 + ~3 min Phase 4); H1+H2 still answerable from cond1/cond2\_k0/cond2\_k1, k-dose becomes a follow-up.
2. **Drop held-out bystander panel from 5 to 3** {software\_engineer, comedian, lawyer} (saves ~3 min Phase 4); H4 still answerable with reduced power.
3. **Drop read (c-parity) villain-R sensitivity (the original parity, NOT MUST-FIX 4's read h)** (saves ~1 min Phase 4). NOTE: dropping c-parity collapses the 2×2 cross to a 2×1 (loses the helpful-system × villain-R cell), so this descope downgrades MUST-FIX 4's persona-vs-R-style decomposition to a 1-dimensional read.
4. **Drop read (h) villain-sys + helpful-R cross (MUST-FIX 4)** (saves ~1 min Phase 4). Last-line descope above the non-descopable minimum; loses the full 2×2 cross. Pre-MUST-FIX-4 baseline restored.
5. **Drop interior-slot KL baseline (MUST-FIX 5)** (saves ~8 min Phase 4 — halves the per-probe call count). Loses the KL construct-validity control; H3 PASS would rely on marker-slot KL alone with the analyzer noting the missing enrichment check.
6. **Drop #465 re-eval** — LAST RESORT. Removes cross-experiment paired bootstrap and falls back to comparing #471 cells against #465's published numbers (not directly paired). The headline becomes one-experiment-only.

**cond1 + cond2\_k0 + cond2\_k1 + bystander read (f) + reads (c) + (g) + (g') (MUST-FIX 3 disambiguation triple) + #465 re-eval are NOT descopable.** They're the minimum to answer the Goal — MUST-FIX 3 is non-descopable because the H1 claim is uninterpretable without it (persona-localization vs prompt-string memorization). MUST-FIX 4 + MUST-FIX 5 reads rank ABOVE the original c-parity in priority (since they sit closer to the headline interpretation) but BELOW the H1-disambiguation reads in non-descopability.

Min-N per dimension: 30 Q\_test for paired bootstrap. Min cell count: 8 (4 cond × 2 eval shapes: in-trained + demo-free-default-helpful-R).

### 9.3 Single-seed caveat

Single seed = 42 (mirrors #465). Multi-seed would add ~1.5× per seed. Cross-seed uncertainty NOT captured by within-condition paired bootstrap. **Pre-registered follow-up:** if H1 PASSes, add seeds 137, 7 for cond1 + cond2\_k1 (4 extra runs ≈ +100 min).

**Single-variable discipline statement (for consistency-checker).** Parent issue = #465. The ONE manipulated variable vs #465 per arm is the PRESENCE of training-time contrastive negatives (with the standard 1:1 ratio over 3 close-negative personas including the default per `.claude/rules/contrastive-negatives.md`). The headline cross-condition DV is changed (full-vocab KL-from-base instead of saturated trained−base log P(※)); this is NOT a second manipulated variable — it is a measurement-validity correction at the same training budget, explicitly authorized by the rule's "Saturation hides everything" clause, and the original DV (trained−base log P(※) + emission) is kept as a secondary read for paired comparability. Training budget, recipe, persona, marker, seed, Q\_train/Q\_test/Q\_demo, R artifacts, eval shapes, and the 5 inherited probes are byte-identical to #465. The held-out bystander eval shape (read f) is a NEW READ, not a new condition or recipe change — it measures generalization of the negatives' suppression signal to personas outside the trained set, which is the standard selectivity-measurement extension that all contrastive-negatives experiments need.
