Enforced predicate: `_first_load_dotenv_line(src)` (substring scan for the
CALL) strictly less than `_first_heavy_import_line(ast.parse(src))` (module-top

### Leg C — bare `.list_repo_tree(` (5 sites, 5 files) — REWRITTEN in v2

**The v1 recipe was wrong.** `HfApi.list_repo_tree` in `huggingface_hub` 0.36.2
ends `for path_info in paginate(...): yield ...` — calling it performs ZERO
HTTP and returns a generator; every cursor page fires at ITERATION time.
`hub.retry_transient` (= `_retry_upload`, `hub.py:1596`, `return fn()`) retries
only the thunk. So `retry_transient(lambda: api.list_repo_tree(...))` returns
the lazy generator instantly and the #920 failure class — a transient 504 on a
cursor page — still kills the caller, now OUTSIDE the retry envelope, under a
waiver comment asserting it is retried. That is a false justification and
exactly the "silence the check without stating why each site is safe" shape the
body forbids. The canonical helper documents this trap in its own docstring
(`hub.py::list_repo_entries_complete` L945-947: "a cursor-page 504 raises DURING
iteration, so the comprehension is materialized inside the retry thunk —
#794/#658").

**C1 (default) — materialize the CONSUMPTION inside the thunk, waiver on the
call line:**

```python
entries = hub.retry_transient(
    lambda: list(api.list_repo_tree(...)),  # HUB_VERIFY_RETRY_EXEMPT: iteration materialized inside the retry thunk (#1202/#794)
    what="<short description>",
)
```

Waiver placement is load-bearing: `_hub_verify_bare_hits`
(`workflow_lint.py:10235`) flags the `.list_repo_tree` Attribute whose
`node.lineno` is the **call line**, and `_hub_verify_waiver_present`
(L10151-10171) honors the waiver only on that line or the immediately preceding
non-blank line. A comment above the `retry_transient(` opener is two non-blank
lines up and does NOT waive.

Per-site materializer shape (critic-verified consumption forms):

| Site | Current consumption | C1 shape |
|---|---|---|
| `marker_panel.py:210` | list comprehension | wrap the whole comprehension in the lambda |
| `refusal_panel.py:116` | list comprehension | wrap the whole comprehension in the lambda |
| `sae_map.py:378` | bare `for` loop | thunk returns `list(...)`; iterate the returned list |
| `separate_pca_fit.py:55` | OUTER `list(...)` | move the existing `list()` INSIDE the thunk |
| `separate_umap_fit.py:87` | OUTER `list(...)` | move the existing `list()` INSIDE the thunk |

State honestly in the implementer report that the returned value changes
generator → list. Behavior-identical for all five consumers: each fully consumes
exactly once, and all five prefixes are scoped and bounded.

**C2 (opt-in, per site, requires justification) —

### Leg D — `scripts-import-guard` (7 sites, 3 files) — NEW in v2

Module-top `scripts.*` imports with no repo-root `sys.path` guard. In script
mode (`python /abs/path/driver.py`) `sys.path[0]` is the script's own dir, so
`scripts` is unimportable pod/GCE-side and the import crashes at process start
(#823/#853). Idiom from `scripts/issue1739_claim4_fold.py`:

```python
def _ensure_repo_root_on_syspath() -> Path:
    root = Path(__file__).resolve().parents[1]
    sentinel = root / "scripts" / "<a file that must exist>"
    if not sentinel.exists():
        raise RuntimeError(f"repo-root resolution failed: {sentinel} missing")
    if str(root) not in sys.path:
        sys.path.insert(0, str(root))
    return root


_REPO_ROOT = _ensure_repo_root_on_syspath()

from scripts.issue2643_gradient_pursuit import (...)  # noqa: E402
```

The guard call must sit **immediately before** the `scripts.*` import. Waiver
form if a site is genuinely safe: `# SCRIPTS_IMPORT_GUARD_EXEMPT: <reason>`
(>= 10 chars) — but prefer the guard; these three files import each other and
are dispatched as scripts, which is precisely the crashing shape.

Note `issue2643_refusal_panel.py`'s `scripts.*` imports sit inside a `try:`
block; the guard call goes before the `try:`, and the flagged linenos (24, 30,
38) must all be covered.
