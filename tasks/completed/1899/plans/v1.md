### D1. `backends/slurm.py` — ladder representation + render override seam

- **`QosRung` frozen dataclass** (new, just above `ClusterConfig`): `qos: str; partition: str | None = None` (None = keep the cluster's default partition). Chosen over a parallel tuple field (index-coupling fragility) and a dict (unhashable in a frozen dataclass default, weaker typing); it keeps the low-eur↔`general,overflow` pairing (a cluster-handbook fact, #1609 body: "submit batch to `general` (high-eur) or `general,overflow` (low-eur)") in the cluster table where it belongs.
- **`ClusterConfig.qos_ladder: tuple[QosRung, ...] = ()`** appended after `job_name_suffix` (slurm.py:251). Default empty ⇒ every non-fellows lane is untouched; the field is ROUTER-consumed only (render never reads it), so renders cannot change from the field itself.
- **Fellows row** (slurm.py:366 block): keep `qos="high-eur"` verbatim; add `qos_ladder=(QosRung("normal-eur"), QosRung("low-eur", partition="general,overflow"))` with a comment block carrying the §2 sacctmgr table facts, the dev-eur sbatch-rejection drop, and the GraceTime-0 preemption note.
- **Render override seam** (`render_sbatch`, slurm.py:1620-1622): replace the two direct `cluster.partition` / `cluster.qos` reads with

  ```python
  partition = spec.extra.get("slurm_partition_override") or cluster.partition
  qos = spec.extra.get("slurm_qos_override") or cluster.qos
  if partition:
      sbatch_headers.append(f"#SBATCH --partition={partition}")
  if qos:
      sbatch_headers.append(f"#SBATCH --qos={qos}")
  ```

  (`RunSpec.extra` is `dict` with `default_factory=dict` — base.py:292 — never None.) Absent extras ⇒ identical strings ⇒ the #1609 snapshot-test contract holds with zero fixture regeneration. `_render_script_for` (slurm.py:2818) already threads `spec` into every render path (launch + estimate), so all submit paths stay byte-identical per (spec, cluster) — a rung-override spec renders its override everywhere consistently.
- **Hard-cluster-rules preservation (the 8 rules, #1609 body):** the re-submit re-renders the SAME sbatch via the SAME `render_sbatch` with only `--qos` (and possibly `--partition`) changed — no `--export`, no `--mem=0`, no CVD, mem formula / NCCL exports / HF_HOME / SIGTERM process-group trap / `-superkaiba` job-name suffix all inherited verbatim from the unchanged cluster row. Rule 4 (never sbatch in a shell loop): the ladder is ≤3 sequential submits, minutes apart, each AFTER a confirmed scancel of the predecessor — not loop-spam; noted in the router comment.

### D2. `backends/router.py` — the ladder walk (auto path)

**Where it lives:** inside `_launch_and_park_free_lane` (router.py:4738-5008), which already owns submit → lease-write → park → cancel under the per-issue flock. Grounded rejection of the SlurmBackend alternative: `park_until_running_or_cap` (:1826), `cancel_and_wait` (:4946 call), the attempts trail, and the lease/sidecar writes are all router-side; a backend-internal ladder would have to duplicate the park watchdog. Router.py currently imports nothing from slurm.py (verified: no `from .slurm`/`import slurm` matches), so the ladder is fetched via a **function-scope lazy import** in a small helper — no new module-level import edge, no import-cycle exposure:

```python
def _qos_rungs_for_lane(kind: BackendKind, spec: RunSpec) -> list["QosRung | None"]:
    """[None] (= the cluster's pinned primary QoS) + the fellows qos_ladder (#1899)."""
    if kind != "fellows":
        return [None]
    from explore_persona_space.backends.slurm import get_cluster_config  # lazy (#1899)
    return [None, *get_cluster_config(spec.cluster or "fellows").qos_ladder]
```

(No try/except — `spec.cluster` is threaded by `_spec_for_lane` at :4754; a lookup failure is a code bug and must fail loud.)

**New constants** next to `FELLOWS_QUEUE_WAIT_ENV` (:250): `FELLOWS_LADDER_RUNG_WAIT_ENV = "EPS_FELLOWS_LADDER_RUNG_WAIT_SECONDS"`, default 300; `_fellows_ladder_rung_wait_seconds()` mirroring `_fellows_queue_wait_seconds` (:1796) — env-overridable, non-positive/garbage falls back to 300.

**Loop shape** (surgical restructure of :4817-5008; the reconnect block :4756-4815 stays outside/above):

```
rungs = _qos_rungs_for_lane(kind, spec)
threaded_spec, lease = _thread_attempt_id_into(spec, lease, write)   # ONE attempt id for the lane
for i, rung in enumerate(rungs):
    rung_spec = threaded_spec if rung is None else replace(
        threaded_spec,
        extra={**threaded_spec.extra,
               "slurm_qos_override": rung.qos,
               **({"slurm_partition_override": rung.partition} if rung.partition else {})},
    )
    handle = _prepare_and_launch(backend, rung_spec, kind=kind, cluster=spec.cluster)
        # BackendPrepareError / Exception handlers unchanged → append attempt, return None
        # (a broken endpoint will not heal between rungs — no rung-continue on launch failure)
    _invoke_on_launched(on_launched, handle)                          # sidecar → newest job id
    write(_lease_after_submit(lease, spec, kind, spec.cluster, handle))
    cap = _park_cap_for_lane(kind, cfg) if i == 0 else _fellows_ladder_rung_wait_seconds()
    started, reason, terminal_status = park_until_running_or_cap(..., cap_seconds=cap, ...)
    if started: return _record_free_lane_started(..., detail=f"park resolved to RUNNING (qos={_realized_qos(rung)})",
                                                 extra={"realized_qos": _realized_qos(rung)})
    # terminal_before_running + runtime-artifact evidence → WorkloadSurfacedError   (unchanged, any rung)
    cancel_outcome = cancel_and_wait(...)                              # unchanged params
    if cancel_outcome == "raced_to_running": return _record_free_lane_started(..., extra={"cancel_race": True, "realized_qos": ...})
    detail = f"cancel_outcome={cancel_outcome}"
    if kind == "fellows" and reason == "park_cap_exceeded":
        detail += f"; fellows_queue_timeout cap={cap}s qos={_realized_qos(rung)} rung={i + 1}/{len(rungs)} ({FELLOWS_QUEUE_WAIT_ENV})"
    attempts.append(RouteAttempt(..., outcome=reason, detail=detail, ...))
    if cancel_outcome == "manual_attention": <post terminal marker> ; raise ManualAttentionRequiredError(...)   # unchanged, any rung
    if not (kind == "fellows" and reason == "park_cap_exceeded" and cancel_outcome == "cancelled"):
        return None      # non-fellows, probe_failures_exceeded, stalled/gate-cancelled, etc. — today's semantics
    # else: fall through to the next rung
return None              # ladder exhausted → advance to GCP
```

`_realized_qos(rung)` = `rung.qos` if rung else the cluster's `qos` ("high-eur"). Key semantics decisions, each grounded:

- **Ladder continues ONLY on `reason == "park_cap_exceeded"` AND `cancel_outcome == "cancelled"`.** `park_until_running_or_cap` returns typed reasons (:1849: `park_cap_exceeded` = still PENDING at cap) — the park loop CAN distinguish a queue-park timeout from `terminal_before_running` / `probe_failures_exceeded` (:647) / stalled/gate, so every other reason keeps today's exact path (workload-surface, manual-attention, next-lane). This directly answers the kill-criterion concern.
- **`manual_attention` on ANY rung raises** (unchanged): an unconfirmed-dead job is the same double-submit hazard on every rung.
- **One attempt id for the whole lane attempt** (rungs share it; per-submit identity is the SLURM `job_id`, re-persisted to the sidecar + lease per rung via the existing `_invoke_on_launched` + `_lease_after_submit` calls). Avoids attempt-id namespace churn across rungs; `SlurmBackend.launch` posts a fresh `epm:cluster-launched v1` per submit (existing behavior), so each rung's job id is on the events trail for free.
- **`_prepare_and_launch` per rung** (not launch-only): uniform exception handling; `SlurmBackend.prepare`'s `--delete` rsync is safe here because the prior rung's job is confirmed dead (cancel_and_wait returned `cancelled`) and a PENDING-only job wrote nothing to scratch — the :4759 "yank code from a RUNNING job" hazard cannot apply. (Implementer MAY simplify rungs 2+ to `backend.launch(rung_spec)` with equivalent try/except if the re-rsync proves noisy; either satisfies the tests.)
- **Flock hold extends** to worst-case ~21 min (600 + 2×300 parks + 3 cancel graces (`cfg.cancel_grace_seconds = CANCEL_LIVE_GRACE_SECONDS`, router.py:1954) + 2 re-submits) — per-ISSUE flock only (the :4866 comment's contention argument unchanged); the tick cron's route calls on the same issue serialize behind it, acceptable exactly as today's 600s park was.

### D3. Pinned-lane behavior: pins do NOT walk the ladder

The explicit `backend: fellows` pinned path (router.py:4008-4086) keeps the #1609 `pinned_queue_wait` exemption verbatim: on `park_cap_exceeded` it returns the live PENDING handle (no scancel). ### D4. Preemption honesty + requeue decision

- `normal-eur`/`low-eur` landings are PREEMPTIBLE by high-eur/dev-eur jobs (live sacctmgr Preempt column), with **GraceTime 00:00:00** on the -eur family (near-immediate SIGTERM → KillWait → SIGKILL; the task body's "~3-min grace" is the non-eur rows'). Mitigations already standing: fellows rule-7 `term_kill_process_group=True` (the SIGTERM trap forwards to the process group — slurm.py:381) and the fleet-wide checkpoint-per-phase + resume-predicate law (`.claude/rules/code-style.md`), so a preempted-and-requeued job resumes from persisted phase state on the same shared scratch.
- **No `--requeue` flag is added.** Requeue-on-preempt is governed by the cluster's own QoS/PreemptMode policy (#1609 body: low-eur "auto-requeue" — handbook-sourced); an explicit `#SBATCH --requeue` would widen the render surface for zero demonstrated need, and SLURM restarts the batch script from the top either way (the resume predicate is the real mitigation). If live behavior shows preempted rung jobs NOT requeuing, adding `--requeue` to rung renders is a one-line follow-up.
- **`realized_qos` is recorded** on the started `RouteResult.extra` (→ the `epm:backend-selected` marker via `_record_free_lane_started`'s existing `extra` param, :5024) so downstream forensics can attribute a mid-run SIGTERM death to a preemptible tier. Per-rung `RouteAttempt.detail` carries `qos=<q> rung=<i>/<n>` for the park-fail audit chain (§3 criterion 2).
- **Alternative rejected — gating low-eur on `_is_short_job` (the GCP spot-bar mirror):** on GCP a preemption DELETEs the instance (crash-persist + failover); on fellows it requeues on shared scratch and resumes — materially cheaper — and the gate would render the rung inert for the common unknown-length dispatch, against the user directive. Documented as a §12 assumption to revisit if requeue proves unreliable.
