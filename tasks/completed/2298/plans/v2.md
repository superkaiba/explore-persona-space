## Requirement + acceptance criteria

**Requirement.** The plan-critic lens surface must tell a critic to cost a
plan's §9 compute rows on the machine the backend router will ACTUALLY
provision. It currently names the wrong machine, so the check is inverted
for every bare-`auto` plan (the default). Correct the prose, and add a
mechanical guard so the next lane-order inversion cannot leave stragglers.

**Acceptance criteria (each verifiable):**

- **A1** No file in the PRESCRIPTIVE workflow surface (`.claude/agents/`,
  `.claude/skills/`, `.claude/rules/`, `CLAUDE.md`) asserts a
  lane-ordering adjective that contradicts the live head of
  `DEFAULT_AUTO_LANE_ORDER`.
- **A2** `.claude/rules/critic-lens-reference.md` item 13 and
  `.claude/rules/plan-compute-sizing.md` § "Cost wall-time against the
  machine the router will ACTUALLY provision" state the SAME current order.
  (Item 13 cites that § as its fence-sizing recipe; disagreement between a
  lens and its cited recipe is its own defect.)
- **A3** A new `workflow_lint.py` check FAILs on a contradicting adjective
  in the prescriptive surface, reading the expected head from
  `backends/router.py` source — never a hardcoded `"runpod"`.
- **A4** The check is bundled into the no-flags default run (repo
  convention), and registered at all five registration sites.
- **A5** A pin test carries a fixture of the exact stale line from
  `critic-lens-reference.md:410` and asserts the check FAILs on it, plus a
  corrected-line fixture that PASSes.
- **A6 (armed-not-inert).** The check reports its ARMED state
  (`skipped` / `skip_reason` / `files_scanned` / `scanned_files`), and a
  test asserts a real scan happened (`files_scanned > 0`, `skipped` False)
  against the live tree. A silently-inert check produces the same
  "0 findings, exit 0" surface as a working one (#2018 kill criterion (d)).
- **A7 (zero false positives, MEASURED).** A full-tree run over the
  prescriptive surface reports exactly the findings Part 1 then fixes, and
  ZERO findings after Part 1 lands. The measured number is recorded in the
  implementer's marker — this is the gate that licenses FAIL posture
  (the #2261 "0 red across 89 armed files" precedent).

## Part 3 — The mechanical guard

New check `--check-lane-order-adjective` in `scripts/workflow_lint.py`.

### Reading the live head (AST, no import)

```python
LANE_ORDER_ROUTER_REL = "src/explore_persona_space/backends/router.py"
KNOWN_LANES = ("runpod", "fellows", "gcp", "nibi", "fir", "mila")

def read_default_auto_lane_head(source: str) -> str | None:
    """Head lane of DEFAULT_AUTO_LANE_ORDER, from router.py SOURCE text.

    AST-based (no import) so the check is testable against a fixture tree
    via repo_root=. Reads every `ast.Return` inside
    `_default_auto_lane_order` whose value is a tuple, and takes element 0
    when it is a string Constant. Returns the head when EVERY branch
    agrees; None when the module does not parse, the function is absent,
    a branch's element 0 is not a string literal, or branches DISAGREE —
    callers SKIP loud on None, never crash.
    """
```

Both live branches return `("runpod", "fellows", ...)` / `("runpod",
"fellows", "gcp", ...)`, so element 0 agrees and the star-expanded tail
(`*DEFAULT_FREE_LANE_ORDER`) is never inspected. A future refactor that
builds the tuple through a variable yields `None` → loud SKIP (fail-open),
which is correct: the guard goes quiet rather than firing on a head it
cannot resolve.

### Trigger

For each `<lane>` in `KNOWN_LANES` that is NOT the resolved head, flag
`<lane>-first` and `<lane> first` (case-insensitive; word-bounded so
`gcp-first-resort` and `fellows firstly` do not match). `runpod-first`
PASSES by construction — this is what "read the constant, do not hardcode
the expected head" buys: the next inversion updates `router.py` and the
lint immediately flags the stragglers.

### FAIL vs WARN — the one design tension, surfaced for the critic

The task body specifies **FAIL**. The closest precedent chose **WARN-only**,
and did so on this exact family: `_GCP_PIN_TRIGGERS`' comment says the
"gcp is the auto default" family (family B) "is deliberately NOT a trigger:
measured at plan time it hits legitimate era-scoped historical prose, and
mechanizing it would force annotating correct text (#2018 plan D8/D9)".
`<lane>-first` IS family B. And #1388 is the standing reason to be careful:
the no-flags lint IS the Step 9c gate fleet-wide, so a false-positive FAIL
wedges every session.

**Plan position: FAIL, gated on A7.** The #2018 rejection was measured with
a scan set that INCLUDED `docs/` and `.claude/agent-memory/` — where the
historical prose lives. Under the prescriptive-only scope above, the
measured population is 3 hits, all genuinely stale, 0 legitimate. FAIL is
therefore defensible where it was not before, and the waiver covers the
residual. **If A7 measures ANY legitimate hit that would need a waiver on
correct text, downgrade to WARN-only** (via the existing `_run_warn_only`
wrapper the gcp-pin check already uses) and record the downgrade — do not
ship a FAIL check that forces annotating correct prose. The critic is
asked to adjudicate this explicitly.
