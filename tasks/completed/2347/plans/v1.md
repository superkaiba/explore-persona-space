**Root cause (verified on main `eecb2ab255`, 2026-08-17):** mission-control rung-0

(`src/explore_persona_space/task_workflow.py:5649`) now carries

`TypeError: ... got an unexpected keyword argument 'if_plan_v'`.
Re-confirmed red pre-plan: `4 failed, 57 passed in 2.07s` (matches the filing
oracle at base `e429f8cff9`).

## Method delta

Test-only stub-signature fix; zero production-code change. The four stubs gain a
trailing `**kwargs` catch-all (ignored), preserving every existing parameter and
every assertion. Rationale for `**kwargs` over an explicit `if_plan_v=None` pin
(the body allows either): these stubs pin `cmd_set_status`'s echo/exit contract,
NOT the `set_status` signature — a catch-all closes this exact lockstep-miss
class (CLI passes a newly-added kwarg → stub TypeError → main-red) permanently,
while an explicit pin re-breaks main on the next signature addition. The real
signature is exercised by the integration tests that call the real `set_status`.
This satisfies the body's "verify against the CURRENT set_status signature
rather than pinning a new one".
