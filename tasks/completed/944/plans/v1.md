## 3. File paths + concrete diffs

### 3a. `.claude/rules/gotchas.md` — new bullet entry

Insert as a new top-level bullet adjacent to the RunPod MooseFS quota entry (the venue-difference cluster, ~line 30); placement tweak allowed. Text (matches the file's bold-lead + RULE + incident-cite register):

> - **Pod/GCE workload scripts: source `./.env` CONDITIONALLY — the GCE lane has NO `.env` file, and an unconditional `. ./.env` inside a classified `&&`-chain kills healthy runs.** The two workload venues differ: RunPod `bootstrap_pod.sh` Step 3 scp-pushes the VM's `.env` to the pod, but GCE pushes NO `.env` — its startup script exports the API tokens directly into the environment (metadata/Secret-Manager fetch + `export` block, `src/explore_persona_space/backends/gcp.py`). RULE: a script that must run on both venues (or that a GCE workload command invokes) sources conditionally:
>
>       if [ -f ./.env ]; then set -a; . ./.env; set +a; fi
>
>   and NEVER puts the sourcing inside the `&&`-chain of a command whose exit code is being classified — `set -a && . ./.env && set +a && uv run python ...` short-circuits at the missing file, the real command never runs, and a fail-fast rc classifier reads the shell error as a non-transient application failure. The `set -a && source .env && set +a && uv run python - <<'PY'` recipe in `.claude/rules/research-project-structure.md` § Environment Bootstrap is VM-scoped (repo root, where `.env` always exists) — do not copy it verbatim into pod/GCE workload scripts. Conditional exemplar: `scripts/issue612_dose_matched_driver.sh:38`. Known legacy UNCONDITIONAL sites (pod-only scripts that work because RunPod pushes `.env` — do not copy the shape): `scripts/run_issue404_pipeline.sh:34`, `scripts/i207_chained_pipeline.sh:13`. (Incident #923 crash-fix round 2, att-20260703-163121, 2026-07-03: a GCE join-poll subshell used the unconditional chained form; the sourcing failed, and the rc classifier killed a healthy run whose completion sentinel already existed.)
