#### Phase B — `--files` payload-scoping mode (body items 2+3) — the speed change

**B1. New flag.** `workflow_lint.py` gains `--files <path> [<path>...]` (nargs="+", repo-relative). Confirmed absent today: no `--files/--paths/--only/--scope/--changed` among the 88 `add_argument` calls (grep rc=1, 2026-08-11). Semantics: no-flags check set, but with per-check scoping (below). `--files` combined with any `--check-*` flag is an argparse error (one mode at a time). **No `--files` ⇒ byte-identical behavior to today** — Step 9c and every other caller unaffected.

**B2. Check-scope registry.** A module-level registry adjacent to the dispatch chain (flat `if args.check_<name> or no_flags:` from ~16776, single `no_flags` predicate at 16660 — the clarifier-verified insertion point):

```python
@dataclasses.dataclass(frozen=True)
class CheckScope:
    kind: str                      # "path-local" | "global"
    surfaces: tuple[str, ...]      # fnmatch globs of what the check READS
CHECK_SCOPES: dict[str, CheckScope] = {
    "check_upload_or_true":        CheckScope("path-local", ("scripts/**/*.py", "src/**/*.py")),
    "check_judge_model_pins":      CheckScope("path-local", ("scripts/**/*.py", "src/**/*.py", ...)),
    "check_script_refs":           CheckScope("global", (".claude/**/*.md", "docs/**/*.md", ...)),
    "check_marker_registry":       CheckScope("path-local", ("scripts/**/*.py", "src/**/*.py", ".claude/workflow.yaml")),
    ...  # one entry per dispatch-chain check (68 `or no_flags` sites counted on main)
}
```

- **path-local** = findings on file F depend only on F's content (+ fixed small config surfaces the check may still load whole, e.g. `workflow.yaml` for the marker registry). In files-mode the check runs with its file ENUMERATION filtered to `scope ∩ surfaces`.
- **global** = the check scans surfaces (`.claude/**`, `workflow.yaml`, hooks, `tests/`) whose verdict a disjoint payload cannot change. In files-mode it runs IFF `scope ∩ surfaces ≠ ∅`, else it emits one `workflow_lint: SKIP <check> (files-mode: payload disjoint from <surfaces>)` line.
- **Classification default is path-local (fail-safe):** when in doubt the check runs scoped rather than skipped. The hard floor from the user's scope decision — `check_judge_model_pins`, the `check_upload_*` family (or-true / return-discard / file-in-loop / prefix-clobber / as-file), `check_dotenv_before_hf_import`, `check_jsonl_splitlines`, `check_batch_judge_client` — is path-local BY REQUIREMENT and each gets a firing test (§ TDD).
- **Completeness is fail-closed twice:** (i) a pin test iterates every `or no_flags` dispatch site (AST or regex over `main()`) and asserts a `CHECK_SCOPES` entry exists — a future check added without classification is test-red; (ii) at runtime, files-mode asserts registry coverage BEFORE running and on a miss prints the sentinel `workflow_lint: FILES-MODE-REFUSED (unclassified check <name>)` and exits 2 with NO terminal PASS/FAIL line — the gate detects the sentinel and falls back to the bare full run (slow-but-correct, never silently-skipped).

Fail-loud pin: tests/test_workflow_lint_files_mode.py::test_files_mode_unclassified_check_refuses — asserts an unclassified check RAISES the FILES-MODE-REFUSED sentinel and exits 2 rather than silently skipping the check or swallowing it into a PASS terminal line; companion negative control tests/test_inline_lint_gate.py::test_gate_falls_back_on_files_mode_refusal asserts the gate never treats a refused scoped leg as push-clean.

**B3. Enumeration filtering.** One helper `_files_scope_filter(paths: Iterable[Path]) -> list[Path]` consulting a module-global `_FILES_SCOPE: frozenset[str] | None`; the implementer wraps the enumeration expression of each path-local check (the `sorted(scripts_dir.rglob("*.py"))` / `_iter_files_pruned(...)` sites — `_iter_files_pruned` at 2932 is the shared bounded walker, the single highest-leverage wrap point). Checks that already take `scripts_dir=` / `scan_roots=` / `roots=` / `repo_root=` kwargs keep those signatures unchanged (tests depend on them); the filter composes after discovery. Filtering is by repo-relative path string equality against the scope set — no globbing at filter time.

**B4. Import-closure resolver (body item 3).** Per-issue scripts are not leaf code: 725 import another per-issue script by bare module name, 1,250 import `explore_persona_space`. In files-mode the effective scope = payload ∪ closure, where closure = fixpoint over bare-module imports (`^import X` / `^from X import` where `scripts/X.py` exists) restricted to `scripts/*.py`, parsed via `ast` with a regex fallback on SyntaxError (a payload with a syntax error still gets scoped-scanned; ruff-class checks will name it). Two deliberate boundaries, stated as scope decisions:
- `explore_persona_space.*` imports are NOT expanded into `src/` — src is durable code, held to the full standard by Step 9c + normal review, and unchanged by definition unless it is itself in the payload (then it's in scope explicitly).
- A bare per-issue import that does NOT resolve to an existing `scripts/<name>.py` produces a `FAIL` line naming the *payload* file (payload-caused by construction: the payload references a module that doesn't exist) — this is new red, exit 1.
Closure files are SCANNED but their findings are attributed by the gate's existing machinery: an unchanged closure file is not NEW on origin/main and its hits fall outside the payload's added-line ranges → `reported`, never blocked (acceptance criterion 3 preserved; test in § TDD).

**B5. Output contract.** Files-mode still ends with the exact terminal line shapes `workflow_lint: PASS` / `workflow_lint: FAIL (N error(s))` (emit sites 16930/16933; `LINT_TERMINAL_RE = r"^workflow_lint: (PASS|FAIL \()"` at `inline_lint_gate.py:194` must keep matching). One added completeness line BEFORE the terminal line: `workflow_lint: SCOPE files=<n> closure=+<m> checks_ran=<r> checks_skipped=<s>` — **counts and check names only, never payload path names**: `evaluate()` treats any leg line containing a payload path and not prefixed `WARN`/`PASSED`/`SKIPPED` (`NON_RED_PREFIXES`, line 197) as a red hit, so an informational line naming a payload path would self-inflict a false block. Per-file SKIP lines use check names only for the same reason. A dedicated test pins this (§ TDD case 8).

**B6. Gate wiring.** `run_legs()` (invocation at `inline_lint_gate.py:580`) composes the scoped invocation when the payload is eligible, else the bare full run:

```python
WORKFLOW_SURFACE_PREFIXES = (".claude/", "workflow.yaml", "scripts/workflow_lint.py",
                             "scripts/inline_lint_gate.py", "scripts/select_step9c_tests.py",
                             "scripts/step9c_baseline.py", "tests/")
scoped_eligible = all(not p.startswith(WORKFLOW_SURFACE_PREFIXES) for p in payload)
# (read_payload at main() has already raised Inconclusive on any missing/unhashable
#  path — a deletion payload structurally cannot reach this point, line-verified)
lint_argv = [..., "workflow_lint.py"] + (["--files", *payload] if scoped_eligible else [])
```

- A payload touching any workflow-surface prefix ⇒ bare full run (today's exact behavior). `tests/` is included conservatively: a payload editing tests can change global check outcomes and mapped-test verdicts.
- **`EPM_INLINE_GATE_LINT_CMD` seam preserved exactly:** `_run_leg` runs an env override verbatim via `shell=True` (read at the `def _run_leg` span) — an override therefore runs UNSCOPED unless the override string itself carries `--files`. That is the fail-safe direction (full run) and is documented in the module docstring; the seam test asserts override-verbatim behavior is unchanged (acceptance criterion 7).
- On the `FILES-MODE-REFUSED` sentinel (B2.ii) the gate re-runs the bare invocation once and proceeds on that output; both outputs land in the audit file.
- `LINT_TIMEOUT_S` 900→1200 (line 174): the measured FULL wall is 9m07.9s = 547.9 s, and 2× = 1096 s > the current 900 s fence — the fallback path is already one contended run away from rc=-1 INCONCLUSIVE; 1200 s = 2.2× measured (§11 rationale). Scoped runs finish in seconds under the same generous fence — no second constant.

**B7. Verdict semantics untouched.** Exit 0 PASS / 1 BLOCK / 3 INCONCLUSIVE; `evaluate()`'s instrument-ran completeness checks (lint-leg-dead when no terminal line, line 718; pytest-leg-dead, line 723) bind identically on scoped output — a dead/silent scoped leg is still never push-clean. `write_cert` and the hook contract: zero changes (blast radius stays the clarifier-verified 3 files, with the hook and pin test only VALIDATING).
