## 0.0 TL;DR

One `planned_wall_h` cell whose first character is not a digit (`(1.5)` on #2163) makes
`poll_pipeline.py` discard the whole §9 budget and disarm the phase-ETA tripwire for the
entire run, with only one line of poller stdout to show for it. Fix: widen the float rule
from "digits at position 0" to "digits after an optional **non-alphanumeric cosmetic
prefix**" in ONE shared stdlib-only helper both `poll_pipeline.py` and `verify_plan.py`
import; keep the global fail-safe for a cell that carries no number *the rule will trust*,
but make that case visible at plan time (new `verify_plan.py` check c47, WARN) and durable
at runtime (one `epm:progress` post per run naming the offending row). 0 GPU-h, no pod,
six files.

**The widening is deliberately bounded, not maximal** (critic round 1, Must Fix 1). A
first-float-*anywhere* (`re.search`) rule looks strictly safer and is not: 19 wall cells
across 9 live plans have a LETTER before their first digit — `#529`'s prose rows yield
464.0 / 529.0, `#1902` a row-count 800.0, `#1887` a RAM bound 16.0 — and admitting those
would ARM the tripwire with ~500–1000 phantom hours while c47 PASSed them and the AC #5
marker never fired, because all three surfaces share the parser. That is strictly LESS
signal than today's silent disable. A letter before the first digit therefore stays
unparseable.

**What would change my mind:** the §6 corpus re-scan reports, per plan, the OLD-rule total
vs the NEW-rule total **and** every newly-accepted cell verbatim. If any cell the OLD rule
already parsed changes value, the widening is not conservative and the design needs a
compatibility branch rather than a substitution. If any newly-accepted cell is not a
genuine wall figure, the prefix class is still too permissive and must be narrowed further.
(A WARN count alone cannot observe either failure — that is why the re-scan reports totals
and cells, not counts.) Separately, if `epm:progress` turns out to require a
`workflow.yaml` schema row (Assumption 2), the AC #5 channel is a public-contract change
and must be re-scoped rather than shipped inside this round.

## 1. Goal

A single `planned_wall_h` table cell whose first non-space character is not a digit
must not disable the phase-ETA tripwire for an entire run. The tripwire keeps its
fail-safe-OFF posture for a cell carrying no number at all, but that degradation
becomes (i) rarer, (ii) visible at plan time, and (iii) durable in the task record
instead of a single line of poller stdout.

## 2. Root cause (grounded)

| Site | Fact |
|---|---|
| `scripts/poll_pipeline.py:3856` | `_LEADING_FLOAT_RE = re.compile(r"\s*([0-9]+(?:\.[0-9]+)?)")` |
| `scripts/poll_pipeline.py:3899` | markdown row scan calls `_LEADING_FLOAT_RE.match(cells[col])` |
| `scripts/poll_pipeline.py:3930` | HTML row scan calls the same regex with `.match()` |
| `scripts/poll_pipeline.py:3901,3932` | no match ⇒ `raise _UnparseableWallRow(...)` |
| `scripts/poll_pipeline.py:3956-3959` | `_parse_plan_wall_budget` wraps the whole row scan in `except Exception: return None` — the WHOLE plan's budget, never a partial sum |
| `scripts/poll_pipeline.py:4103-4111` | `None` ⇒ one `log.info(...)` gated by the run-scoped `eta_budget_warned` state flag, then `return` — the tripwire is off and nothing durable records it |
| `tasks/running/2163/plans/plan.md:303` | the realized offender: `\| P6-GPU conditional cell (1x H100 fp64 eigh + solve + score) \| (1.5) \| ...` |

`.match()` anchors at position 0 (the regex's own `\s*` absorbs leading whitespace only),
so the leading `(` of `(1.5)` fails to match. #2163's §9 table has **14** data rows; 13 of
them are bare floats. One parenthesized cell discarded all 13 and disarmed the run.

|---|---|---|

## 4. Design — the change set

### 4.1 New shared module `src/explore_persona_space/plan_wall_budget.py` (AC #4)

Stdlib-only (`re`, `dataclasses`). This is the SINGLE home of both the table locator and
the float rule; neither script keeps a private copy of either regex.

```python
WALL_HEADER_TOKEN = "planned_wall_h"

@dataclass(frozen=True)
class UnparseableWallCell:
    row_text: str      # the offending row (markdown) or cell (HTML), truncated to 120 chars
    reason: str        # "no_float" | "short_row"
    fmt: str           # "markdown" | "html"

@dataclass(frozen=True)
class PlanWallBudget:
    total_h: float | None                        # None ⇒ caller disables the tripwire
    rows: tuple[float, ...]                      # every parsed per-row value
    unparseable: tuple[UnparseableWallCell, ...] # populated even when total_h is None
    reason: str                                  # "" | "no_table" | "unparseable_cell"

def parse_wall_cell(cell: str) -> float | None: ...          # the FLOAT RULE
def parse_plan_wall_budget(plan_text: str) -> PlanWallBudget: ...
```

- **Float rule (bounded widening — critic round 1, Must Fix 1):**

  ```python
  _WALL_CELL_RE = re.compile(r"[^0-9A-Za-z]*?([0-9]*\.[0-9]+|[0-9]+)")
  #                           ^ lazy, non-alphanumeric prefix only
  def parse_wall_cell(cell: str) -> float | None:
      m = _WALL_CELL_RE.match(cell)      # ANCHORED — .match(), never .search()
      return float(m.group(1)) if m else None
  ```

  Anchored at position 0, so the only thing that may precede the number is a run of
  NON-ALPHANUMERIC characters — whitespace, `(`, `~`, `*`, `≤`, `+`, `**`. **Any letter
  before the first digit ⇒ `None` ⇒ the loud fail-safe path.** That single restriction is
  what keeps the 18 known garbage cells (§0.0) out of every parsed total, and it keeps c47
  and the AC #5 marker able to SEE them.
  - Accepts: `1.5`, `  3 (async, off-GPU)`, `(1.5)`, `~1.5`, `1.5-2`, `1.5 (conditional)`,
    `**~7.1**`, `≤24 (SLA)`, `+0.05`, `0`, `2.` → 2.0.
  - Rejects: `TBD`, `N/A`, `—`, `""`, `n=800 rows`, `issue #464`, `see P6`.
  - The **lazy** prefix quantifier plus the `[0-9]*\.[0-9]+` alternative listed FIRST make a
    leading-dot decimal read correctly: `.5` → **0.5**, `(.5)` → **0.5**. A greedy prefix
    would eat the `.` and yield 5.0 (critic round 1, Concern 3 — closed by the rule rather
    than deferred to a fixture pinning a wrong value).
  - Divergence from the critic's proposed `r"[^0-9A-Za-z]*([0-9]+(?:\.[0-9]+)?)"`: leading-dot
    handling only. The two rules agree on every corpus cell (the critic measured 0
    disagreements vs search-anywhere over 1,234 accepted cells, and found no leading-dot
    instance), so the corpus verdict carries over — but the §6 re-scan re-runs with the FINAL
    regex, not the reviewed one, and that is the binding evidence.
- **Locator:** the markdown + HTML scans lift verbatim from `_md_planned_wall_rows` /
  `_html_planned_wall_rows` (`poll_pipeline.py:3862-3936`), preserving every property the
  existing tests pin: all tables carrying the header are located and summed; the value
  column index is DERIVED from the header cell position in both formats; the HTML scan is
  scoped to each owning `<table>`; a markdown `|---|:---:|` separator row is skipped.
- **Deliberately NOT fence-masked**, matching the poller's raw-text scan. A fenced example
  table carrying `planned_wall_h` with an unparseable cell genuinely does disable the live
  tripwire, so warning about it at plan time is correct, not a false positive. Fence-masking
  the poller would change existing plans' totals and is out of scope (§7).
- **Fail-safe reduce:** `unparseable` non-empty ⇒ `total_h = None`, `reason =
  "unparseable_cell"`. Zero located tables / zero data rows ⇒ `total_h = None`, `reason =
  "no_table"`. A total that sums to exactly 0 stays `None` (preserves today's `sum(rows) or
  None`), so `_eta_deviation_update`'s non-positive-budget fail-safe is unchanged.

## 7. Risks + considered-but-not-done

| Item | Disposition |
|---|---|
| Widening the parser newly accepts a cell previously (correctly) rejected | **This is the round's principal risk, and the first draft under-rated it** (critic round 1, Must Fix 1). A first-float-anywhere rule admits 18 known garbage cells across 8 live plans and — because c47 and the AC #5 marker share the parser — makes them INVISIBLE while inflating the budget by ~500–1000 h. Bounded by three things now, in order of strength: (i) the rule itself rejects any letter before the first digit (§4.1); (ii) the §6 corpus re-scan reports every newly-accepted cell verbatim, so a non-wall figure is caught by inspection; (iii) kill criterion 2 HALTs on one. | Prose row containing the literal `planned_wall_h` treated as a table HEADER | KNOWN RESIDUAL, pre-existing. The locator's header test is `"planned_wall_h" in line` (`poll_pipeline.py:3886`), so a DATA row whose prose mentions the token becomes a synthetic header and its neighbours become synthetic data rows — the mechanism behind #529's 464.0 / 529.0 (`plans/plan.md:435`). **This very row instantiates the class:** it is a `\|`-prefixed line containing the token, so the locator reads THIS §7 table as a synthetic wall table, and its `c47 as FAIL rather than WARN` cell is a letter-prefixed cell the bounded rule rejects — so #2172's own plan draws a c47 WARN and its own total stays `None`→`None`, now loudly. Expected, not a bug.
