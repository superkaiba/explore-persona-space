## 4. Design

### 4.1 Leg (a) — scratch-by-default (`scripts/step9c_baseline.py`)

**Choice justification — option (i) over option (ii):** option (ii) "auto-route on any dirty read" is already the shipped behavior — the trigger `bool(live_dirty_paths)` fires on the first dirty read; #1317's blocker was an eligibility leg (R-F), which #1337 already widened to its physical limit (file-anchored scanners only). The only safe further widening IS the trigger removal — option (i) — which additionally eliminates the probe-to-run race and the provenance flapping (§2 items 1-2). No eligibility leg is widened beyond #1337: **scan-set nodes** outside `FILE_ANCHORED_SCAN_TESTS` NEVER use the scratch (physical: `repo_root()`-anchored scanners read the MAIN root from any cwd — a scratch cannot decontaminate them; today this residual class is EMPTY, both `GLOB_SCAN_TESTS` members are allowlisted, so the leg is future-proofing); **`pyproject.toml`/`uv.lock`/out-of-package `src/`** dirt affects the root VENV/deps that the scratch pristine run itself executes with (the scratch has no venv — `run_single_file_pristine` resolves `<root>/.venv/bin/python`), so no scratch can neutralize it — those keep the fail-closed MF-4c exit 2; **R-G (non-sparse work root)** stays: a full-tree gate layout (e.g. a no-worktree task run from the repo root) cannot be superset-matched by the sparse scratch without a multi-GB checkout — clean root → root oracle (trustworthy), dirty root + failing node → MF-4c (unchanged).

**Edit A1 — the predicate** (`_resolve_pristine_bucket`, L1398-1408):

```python
# OLD: bool(ctx.live_dirty_paths) and not residual and wt_cones is not None and (R-F') and not args.no_scratch_fallback
# NEW (#1408): the scratch is the DEFAULT pristine oracle whenever physically eligible.
use_scratch = (
    not residual                      # R-B' unchanged (#1251)
    and wt_cones is not None          # R-G unchanged
    and (
        test_file not in ctx.sel.GLOB_SCAN_TESTS
        or test_file in FILE_ANCHORED_SCAN_TESTS
    )                                 # R-F' unchanged (#1337)
    and not args.no_scratch_fallback  # flag name kept; help text now "disable the scratch oracle"
    and not (scratch_unavailable and not ctx.live_dirty_paths)  # clean-root degradation memo (A2)
)
```

**Edit A2 — clean-root graceful degradation** (same function, the `if use_scratch and scratch is None:` block, L1409-1422): wrap `create_scratch_worktree` + `_arm_src_shadow` in one try; on `(_Indeterminate, CalledProcessError, TimeoutExpired, OSError)`:
- root DIRTY → unchanged fail-closed: re-raise / wrap in `_Indeterminate` exactly as today;
- root CLEAN → the root oracle is trustworthy (pre-#1077 behavior): tear down any partial scratch (`remove_scratch_worktree`, set `scratch = None`), set `scratch_unavailable = True`, `use_scratch = False`, append `"SCRATCH-ORACLE WARN: scratch creation/probe failed on a CLEAN root (<exc>) — root oracle used"`, continue. `scratch_unavailable` suppresses per-file re-creation attempts ONLY while the root reads clean (the A1 memo conjunct); if dirt appears mid-loop, creation is retried and a second failure fail-closes (dirty branch). `_arm_src_shadow` sets `ctx.pristine_oracle`/`scratch_sha`/`scratch_src_shadow` only AFTER the probe passes, so no ctx reset is needed on the degradation path.

**Edit B2 — `run_pytest` threading** (L354-373): after the PYTHONPATH handling —
