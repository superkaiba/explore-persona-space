## 1. Goal

Create an always-on lessons-learned index and wire it so the relevant workflow agents always load it at PLAN TIME, closing the load-timing gap exposed by #722, WITHOUT paying the tens-of-K-token cost of always-loading every rule's full text. (Verbatim from the task body Goal.)

## 2. Prior Work / Current State

The project's lessons-learned live in `.claude/rules/*.md` (20 files). Most carry a `paths:`/`globs:` frontmatter glob and are loaded ON-DEMAND by the harness when the session opens a matching file. That trigger fires on FILE ACCESS, so it fires too late (the planner reasons in a plan file before any matching script is open) or never (the decision never opens a matching file). A handful of the most critical rules are hand-patched with an always-on one-liner directly in CLAUDE.md (e.g. the marker recipe, contrastive-negatives, on-policy completions) precisely to escape this gap; most are not. Worked failure: #722's `vectorize-many-cell-fits.md` had no always-on backstop, the planner judged a per-fold MLP LOCO sweep "CPU-feasible ~30-60 min," and it ran ~19.5 CPU-hours. There is no machine check that the set of rules and any index of them stay in sync.

## Built-but-stranded fixes don't help — get the helper onto main and wired in

A documented — or even fully BUILT — fix that is not merged to `main` and not
wired into the running code path does NOT help: the running session keeps using
the old path. A fix exists in three places (a) documented in a rule, (b) built

**(a) the check function** (inserted after `check_no_workflow_improver_spawn`, before `check_gate_ids_unique`):

```python
# `--check-lessons-index`: every `.claude/rules/*.md` (except LESSONS.md
# itself) must have exactly one matching row in `.claude/rules/LESSONS.md`, and
# every row in LESSONS.md must point at an existing rule file. Closes the
# silent-drift class: a rule added/removed without an index update would
# otherwise re-open the #722 load-timing gap (a lesson with no always-on index
# row). The row format is the stable, machine-parseable:
#   - **<name>** ([`.claude/rules/<name>.md`](<name>.md)) — fires when: ...
_LESSONS_ROW_RE = re.compile(
    r"^- \*\*(?P<name>[a-z0-9-]+)\*\* \(\[`\.claude/rules/(?P=name)\.md`\]"
    r"\((?P=name)\.md\)\)",
    re.MULTILINE,
)


def check_lessons_index(*, repo_root: Path | None = None) -> list[str]:
    """FAIL if `.claude/rules/LESSONS.md` and the `.claude/rules/*.md` set
    diverge.

    The always-on index (#739) must name every rule so each lesson is known at
    plan time even before its `paths:` glob matches an open file. Both
    directions are checked: a rule file with no index row, and an index row
    with no rule file. `repo_root` is a unit-test override hook; production
    callers pass None (canonical repo root). Bundled into the no-flags default
    run.
    """
    root = repo_root if repo_root is not None else _REPO_ROOT
    rules_dir = root / ".claude" / "rules"
    lessons = rules_dir / "LESSONS.md"
    errors: list[str] = []
    if not lessons.is_file():
        errors.append(
            f"{lessons}: missing — the always-on lessons index (#739) must "
            f"exist and index every .claude/rules/*.md file."
        )
        return errors
    rule_files = {
        p.stem
        for p in rules_dir.glob("*.md")
        if p.is_file() and p.name != "LESSONS.md"
    }
    indexed = {m.group("name") for m in _LESSONS_ROW_RE.finditer(
        lessons.read_text(encoding="utf-8")
    )}
    for missing in sorted(rule_files - indexed):
        errors.append(
            f".claude/rules/LESSONS.md: no index row for rule "
            f"'{missing}' (.claude/rules/{missing}.md). Add a "
            f"'- **{missing}** ([`.claude/rules/{missing}.md`]"
            f"({missing}.md)) — fires when: ...' row."
        )
    for stale in sorted(indexed - rule_files):
        errors.append(
            f".claude/rules/LESSONS.md: index row for '{stale}' has no "
            f"matching .claude/rules/{stale}.md file — remove the row or "
            f"restore the rule."
        )
    return errors
```

def _write_lessons_fixture(rules_dir, rule_names, indexed_names):
    """Write N fake rule files + a LESSONS.md indexing `indexed_names`."""
    rules_dir.mkdir(parents=True, exist_ok=True)
    for name in rule_names:
        (rules_dir / f"{name}.md").write_text(f"# {name}\n", encoding="utf-8")
    rows = "\n".join(
        f"- **{n}** ([`.claude/rules/{n}.md`]({n}.md)) — fires when: x."
        for n in indexed_names
    )
    (rules_dir / "LESSONS.md").write_text(
        f"# LESSONS\n\n## Rules\n\n{rows}\n", encoding="utf-8"
    )


def test_check_lessons_index_fails_on_missing_row(tmp_path):
    rules = tmp_path / ".claude" / "rules"
    # rule 'gamma' exists but is NOT indexed -> FAIL
    _write_lessons_fixture(rules, ["alpha", "beta", "gamma"], ["alpha", "beta"])
    errs = check_lessons_index(repo_root=tmp_path)
    assert errs, "expected a FAIL for the un-indexed rule 'gamma'"
    assert any("gamma" in e for e in errs)


def test_check_lessons_index_fails_on_stale_row(tmp_path):
    rules = tmp_path / ".claude" / "rules"
    # 'delta' is indexed but has no rule file -> FAIL
    _write_lessons_fixture(rules, ["alpha", "beta"], ["alpha", "beta", "delta"])
    errs = check_lessons_index(repo_root=tmp_path)
    assert errs and any("delta" in e for e in errs)


def test_check_lessons_index_passes_on_match(tmp_path):
    rules = tmp_path / ".claude" / "rules"
    _write_lessons_fixture(rules, ["alpha", "beta"], ["alpha", "beta"])
    assert check_lessons_index(repo_root=tmp_path) == []


def test_check_lessons_index_passes_on_live_repo():
    # Sanity: the real repo must PASS after this change lands.
    assert check_lessons_index() == []

## 11. Decision Rationale

**(A) Wiring mechanism — BOTH (i) CLAUDE.md `@`-import AND (ii) per-agent pointer.**
- *What:* Add `@.claude/rules/LESSONS.md` to repo-root `CLAUDE.md` (i) AND a one-line "consult LESSONS.md first" pointer to each of the 9 target agent specs (ii).
- *Why:* The whole point is plan-time presence. The project `CLAUDE.md` is injected verbatim into every session's context (confirmed — it's in the harness system-reminder), so an `@`-import is the cheapest reliable always-on path and mirrors the documented precedent. But subagents (planner, critics) are spawned with their own system prompt = their agent `.md` body; whether they inherit the full project CLAUDE.md `@`-expansion is not guaranteed, so the per-agent pointer (ii) is the belt-and-suspenders backstop that guarantees the index is named in each agent's own prompt. Doing both costs ~10 extra lines and removes the single biggest risk (import not expanding).
- *Source:* `Source: ~/.claude/CLAUDE.md "Personal Assistant Mode" — the `@USER.md`/`@SOUL.md` always-on `@`-import precedent`; `Source: .claude/agents/*.md` (all 9 reference CLAUDE.md; none has a generic "always load file X" frontmatter field, so the in-body pointer is the only per-agent always-on surface).
- *Alternatives rejected:* (i)-only — risks the import not expanding in subagent context (Risk table row 1); (ii)-only — would duplicate the index pointer 9× without a single canonical always-on home and miss the orchestrator/main session; inlining the full index into CLAUDE.md instead of importing — works but bloats the already-large CLAUDE.md and duplicates the file (supersede→delete violation in spirit). Per-agent `paths:` frontmatter — rejected: agent specs have no such field, and `paths:` is the on-demand mechanism this fix exists to escape.

**(B) Index row shape — the documented `- **<name>** ([`...`](...)) — fires when: ...` format.**
- *What:* One row per rule, `name` + parenthesized backtick-path + relative markdown link + ` — fires when:` plan-time trigger. Per-agent memory as a single grouped tail paragraph (not one line per agent).
- *Why:* The row is machine-parseable by a single anchored regex (the lint depends on it), reader-scannable, and the relative link (`(artifact-reuse.md)`) resolves from within `.claude/rules/`. A grouped memory tail keeps the index lean (24 agent dirs would be 24 wasted always-on lines; the relevant subset in one paragraph is enough to say "your memory dir exists, consult it").
- *Source:* `Source: task #739 body Deliverable 1` (suggested baseline row format, refined here to the exact regex-anchored form); `Source: scripts/workflow_lint.py check_marker_registry / check_no_workflow_improver_spawn` (precedent: lint checks parse a fixed doc row/format).
- *Alternatives rejected:* a table (harder to regex robustly across markdown renderers, more bytes); one line per agent-memory dir (token bloat, 24 dirs); inlining `description:` verbatim (too long — defeats leanness; the "fires when" is a plan-time rephrasing, deliberately shorter).

**(C) Lesson 3a (supersede→delete) — new BULLET in `code-style.md`.**
- *What:* Add as a bullet in `code-style.md`, not a standalone rule file.
- *Why:* It is a code-hygiene convention (don't leave duplicate/stale scripts) — exactly the class `code-style.md` already holds (lint, vectorize, checkpoint-per-phase, no-dollar-caps). A standalone 1-paragraph rule file would add an index row + a file for a single convention, against the supersede→delete spirit itself (don't proliferate). `code-style.md`'s `paths: ["**/*.py", ...]` already fires it when editing code, which is exactly when supersede→delete applies.
- *Source:* `Source: .claude/rules/code-style.md` (existing home of code-hygiene bullets); `Source: git branch vectorized-mlp-skill @452c539c31 + issue-722 branch` (worked example: `issue722_vectorized_skill.py` supersedes `issue722_skill_over_mean.py`).
- *Alternatives rejected:* standalone `.claude/rules/supersede-and-delete.md` — over-files a single convention, more always-on index surface for no benefit.

**(D) Lesson 3b (built-but-stranded) — new SECTION in `workflow-fix-on-bug.md`.**

- *Why:* This is a coordination/merge-discipline lesson ("a fix only counts when it's on main and wired in"), and `workflow-fix-on-bug.md` is THE rule about how fixes reach main (it governs the file→spawn→Step-10d-merge pipeline).
