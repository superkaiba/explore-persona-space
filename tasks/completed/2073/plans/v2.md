### D2. `.claude/rules/gotchas.md`

Add a new H3-level entry (keep it discoverable + short). Content:

- **Symptom.** Fable-5 (and other 1M-window models under the arm)
  subagents auto-compact at ~200-270k input+cache and abort with
  "Autocompact is thrashing" after 3 cycles.
- **Discriminator (`compact_boundary` `preTokens`).** In session
  transcripts search for `compact_boundary` rows: `preTokens` FAR
  below native (200-270k on a 1M model) = enrolled in the reduced
  window; `preTokens` NEAR native (600-800k+) = normal.
- **Fix / override.** Set `env.CLAUDE_CODE_AUTO_COMPACT_WINDOW` in
  `.claude/settings.json` (project) or `~/.claude/settings.json`
  (operator). Chain: `env` > user-settings `autoCompactWindow` >
  GrowthBook > model native.
- **Known limitations of the override** (from `anthropics/claude-code#46331`):
  `DISABLE_AUTO_COMPACT=1` does NOT affect it;
  `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` is capped by `Math.min()`;
  reported to fail on some arm64 native builds (we are x64).
- **Interaction with smaller-model subagent pins.**
  `CLAUDE_CODE_AUTO_COMPACT_WINDOW` is a WINDOW override; whether
  the harness clamps it back to the smaller model's native window
  when a subagent is pinned to a smaller model (e.g. the sonnet
  refusal-recovery rung-(b2) pin) is not documented in
  `anthropics/claude-code#46331` — state this explicitly and mark
  UNVERIFIED. If the harness does NOT clamp, a sonnet-pinned
  subagent inherits a 1M threshold above its actual context, which
  fails LOUD as hard context-overflow (not silent corruption) —
  loud enough to catch. Implementer runs a fresh `claude -p` under
  a sonnet-pinned subagent (or greps `anthropics/claude-code` at
  time of writing) to close the note, or leaves it labeled UNVERIFIED
  if no source is available.
- **The `/proc/<pid>/environ` false-negative.** The env-var propagates
  into the tool subprocess but does NOT appear in
  `/proc/<pid>/environ`. Do not use `/proc` to check delivery;
  instead run `claude -p 'echo $CLAUDE_CODE_AUTO_COMPACT_WINDOW'` in a
  fresh session.
- **The harness error text is misleading.** "A file being read or a
  tool output is likely too large" was FALSE in every measured case on
  2026-08-04 (largest read 12k tokens). Do NOT read-bound briefs to
  fix it — the read-side fix (see CLAUDE.md § Autocompact-thrash) is
  for a DIFFERENT class.
- **Discriminating the two classes.** Reduced-window enrollment (this
  entry) vs subagent fixed-overhead (CLAUDE.md's existing guidance):
  the discriminator is `compact_boundary preTokens`. If far below
  native → this entry. If near native → the fixed-overhead class
  (spec + CLAUDE.md import tree + MCP schemas + brief).
- **Deployment lag.** A pre-existing long-lived worktree or an
  already-running session inherits the checked-in project-level pin
  only after a pull + respawn from `main`. The operator-global pin
  masks the lag on the current VM; a fresh clone (or the first
  session after this fix ships) will pick it up directly.
- **Incident.** 2026-08-04: 28 of 44 subagents across 12+ sessions;
  every thrash was `claude-fable-5`; zero on `claude-opus-5` or
  `claude-opus-4-7`. Task #2073.
- **`--exclude-dir=worktrees` grep caveat.** A bare recursive grep of
  `.claude/` traverses the `/mnt/eps-data` bind mount and times out;
  scope every recursive grep of `.claude/` with `--exclude-dir=worktrees`.
  (Already documented in this file — cross-reference only.)
