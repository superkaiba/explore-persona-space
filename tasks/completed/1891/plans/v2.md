# Plan v2 — #1891 workflow-fix: agent-memory MEMORY.md indexes exceed the always-loaded read limit — curate + add size guard

## Goal / Requirement

Bring every always-loaded agent-memory index (`.claude/agent-memory/*/MEMORY.md`)
back under the loader read limit without losing lessons, and add a mechanical
`workflow_lint.py` guard so an agent-memory index can never silently exceed the
limit again.

**Why it matters:** MEMORY.md is loaded whole on every agent spawn (`memory:
project`). The loader truncates at ~25,000 bytes (measured-by-report: the
2026-07-30 boundary-impl report saw 41,137 B truncated to ~24.4 KB ≈ 25,000 B,
i.e. the trailing ~39% — exactly the region where NEW lessons append — is
silently dropped on every spawn).

**Measured state (2026-07-30, clarify-time re-verification):**

| file | bytes | lines | per-entry files | status vs ~25,000 B limit |
|---|---|---|---|---|
| `experiment-implementer/MEMORY.md` | 41,137 | 164 | 165 | ~39% silently dropped |
| `codex-critic/MEMORY.md` | 26,872 | 16 | 9 | ~7% dropped; contains verbatim-duplicated index rows |
| `experimenter/MEMORY.md` | 25,221 | 123 | 96 | at the edge (~1% dropped) |
| `reconciler/MEMORY.md` | 24,479 | 94 | 134 | 521 B under; next append crosses |

All other `.claude/agent-memory/*/MEMORY.md` are ≤ 15,820 B.

## Method delta

Mirrors the established agent-spec size-budget check (#829/#838:
`check_agent_spec_size`, `AGENT_SPEC_WARN_BYTES=28_000` /
`AGENT_SPEC_FAIL_BYTES=40_000`, no-flags-bundled, dedicated test file). Delta:
new check targets `.claude/agent-memory/*/MEMORY.md` with thresholds tied to
the loader truncation limit rather than a token-cost budget, and starts with NO
grandfather dict (all live offenders are curated under the WARN threshold in
this same diff, so the ratchet starts clean).

## Deliverables (file paths + concrete changes)

1. **`scripts/workflow_lint.py`** — new constants + check + flag:
   - `AGENT_MEMORY_INDEX_WARN_BYTES = 20_000` (strictly-greater WARN — headroom
     signal; ~5 KB of append room before FAIL).
   - `AGENT_MEMORY_INDEX_FAIL_BYTES = 24_000` (strictly-greater FAIL — sits
     1,000 B below the measured ~25,000 B truncation so the FAIL fires BEFORE
     any silent truncation begins).
   - `check_agent_memory_index_size(*, repo_root=None, warn_sink=None)`:
     scan `.claude/agent-memory/*/MEMORY.md` (the index files ONLY — per-entry
     `feedback_*.md` files load on demand and are out of scope); FAIL over the
     FAIL threshold with a message naming the curation recipe (trim index hooks
     to ~1 line/entry, move detail into the per-entry file, merge duplicates);
     WARN over the WARN threshold. No grandfather dict in v1 (see Method
     delta). Missing `.claude/agent-memory/` dir: return a FAIL naming it
     (parity with `check_agent_spec_size`'s missing-dir behavior).
   - CLI: `--check-agent-memory-index-size` flag + bundle into the no-flags
     default run (parity with `check_agent_spec_size` wiring at
     `main()`).
   - NOTE: the #917 "agent-memory out of scan scope" exclusions apply to OTHER
     checks (stale-quote scanning etc.) and are untouched; this check is a
     deliberate, narrow size probe of the index files.

2. **Curation of the four oversized indexes** (preserve every lesson — merge,
   never drop):
   - `.claude/agent-memory/codex-critic/MEMORY.md` (26,872 B): delete the
     verbatim-duplicated rows (16 lines carry ~3 copies of the same 3-4 lens
     rows); for the remaining rows, move the long inline sub-question/detail
     text INTO the pointed-to per-entry file (append under a clearly-labeled
     section if not already present), leaving a ≤~150-char hook per row.
   - `.claude/agent-memory/experiment-implementer/MEMORY.md` (41,137 B, 164
     entries): per entry — (a) confirm the pointed-to per-entry file exists
     and carries the substance; if the index line carries detail NOT in the
     entry file, append that detail to the entry file FIRST; (b) trim the
     index hook to ≤~150 chars (the standard one-line-pointer shape); (c)
     merge sibling entries that cover one theme (e.g. multiple smoke-parity /
     Hub-staging entries) into one index row pointing at the primary entry
     file, with cross-links inside the entry files. Target ≤ 20,000 B.
   - `.claude/agent-memory/experimenter/MEMORY.md` (25,221 B) and
     `.claude/agent-memory/reconciler/MEMORY.md` (24,479 B): same recipe;
     these are closer to target so hook-trims + a few merges suffice.
   - Curation is consolidation, not rewriting semantics: the owning agent
     remains the primary author; no lesson content may be deleted without its
     substance living in a per-entry file in the same commit.

3. **`tests/test_workflow_lint_agent_memory_index_size.py`** (new) — unit
   tests mirroring `tests/test_workflow_lint_agent_spec_size.py`: tmp-fixture
   cases for under-WARN (clean), WARN band (warn_sink populated, no FAIL),
   over-FAIL (error listed), missing agent-memory dir, and non-MEMORY.md files
   ignored.

## Acceptance criteria

1. Every `.claude/agent-memory/*/MEMORY.md` on the branch is ≤ 20,000 bytes.
2. `uv run python scripts/workflow_lint.py --check-agent-memory-index-size`
   (the scoped invocation) exits 0 on the branch tree; the check is bundled
   into the no-flags default run with no NEW no-flags failures vs the
   plan-time baseline (the binding repo-wide checks are Step 10d's
   baseline-subtracted lint gate and the step9c baseline compare).
3. Deliberately oversizing a fixture file in the unit tests produces the FAIL
   (>24,000) and WARN (>20,000) behaviors respectively.
4. No lesson dropped: for each curated index, every removed/trimmed index
   line's substantive content is present in a per-entry file in the same
   commit (reviewer spot-checks a sample; the diff shows moves, not bare
   deletions).
5. Step 9c test-verdict gate green (new test file + mapped invariants).

## Kill criteria

None fatal. If the loader limit is later shown to be line-based rather than
byte-based, the byte guard remains a valid hygiene ratchet (an index >24 KB
violates the one-line-pointer convention regardless); thresholds would be
revisited in a follow-up, not this task.

## Assumptions

- **Loader truncation ≈ 25,000 bytes** — measured-by-report (boundary-impl
  2026-07-30: 41,137 B → ~24.4 KB kept), not verified against harness source.
  The FAIL threshold sits 1,000 B below it so the guard is conservative under
  moderate error in either direction.
- `.gitattributes` `merge=union` covers agent-memory `.md`, so concurrent
  sessions' appends to these files between branch cut and merge union-merge
  locally; a union-resurrection that pushes a file back over the cap is caught
  by the new check at the Step 10d pre-push lint gate (self-enforcing).
- Implementer freshness duty: sync the four MEMORY.md files from fetched
  `origin/main` at work start (they are NOT in the Step 5a spec-sync set), and
  re-verify byte sizes immediately before posting the implementation marker.
