## 11. Decision rationale

1. **No-flags bundle + explicit parity leg (conditionally triggered) over any single invocation.** #931's damage was `tests/test_workflow_lint.py` red on trunk; that suite subprocess-runs FIVE surfaces — the no-flags default PLUS `--check-references`, `--check-tables`, `--check-asks`, `--check-autonomous-asks` — and the no-flags run does NOT bundle the latter four (fact-checked: their `main()` branches lack `or no_flags`). Trunk-pytest parity therefore takes the no-flags run AND one flags invocation (~1.4 s measured). Cost is bounded: ~4.5–6 min + 1.4 s once per code-bearing merge at the task-terminal point (non-interactive), and artifact-only payloads skip entirely. If the full no-flags leg proves too slow (kill criterion 1), it — and only it — narrows; the parity leg is cheap and stays regardless. **Source:** timings measured this session (§4); fact-checker read of workflow_lint.py:7086–7231 + tests/test_workflow_lint.py:83–140; incident (b) in task #1047 body.
2. **Payload-attributed verdict (block only on own-diff-named failures; main-side compare for the ambiguous case).** Directly implements the brief's "must not block an innocent merge on pre-existing lint failures" with rebase semantics as the justification: the merge can only change own-diff files. The main-side compare closes the cross-file-check gap (lessons-index/lens-coverage naming the index file) at the cost of one extra run only when ambiguous. **Source:** `main()` error-emission format (workflow_lint.py:7224–7228); rebase semantics; Guard 1/3 prose.
3. **Worktree-side-only Guard 0; repo-root dirty files left to `sync_repo_root.py`.** #906 was worktree-side; the repo-root failure mode (#967) is an autostash problem the helper already solves (docstring items (a)–(c)), and a Step-10d commit of root-side memory files risks sweeping a concurrent session's mid-write edits (59 live dirty memory files right now, owned by many sessions). **Source:** sync_repo_root.py docstring lines 5–25; live `git status`; incident (a)/(c) in the task body.
4. **Guard 0 placed once, before guards 1–3, rather than per merge form.** One insertion covers the safe case (via the push-flag extension), the recovery merge (the actual #906 abort site), and Guard-3 computation, and keeps Step 10d's structure intact per the surgical-edit constraint. **Source:** Step 10d read — the guards section is the single common prefix of all three forms.
5. **`MEM_COMMITTED` joins the safe-case push condition.** Same mechanism as the existing `STRIPPED_FOREIGN` flag: a local worktree commit is invisible to the server-side `gh pr merge --rebase`, which rebases `origin/issue-<N>`; without the push, the persisted memories silently never land. **Source:** the `STRIPPED_FOREIGN` load-bearing comment in the safe-case block (verbatim precedent).
6. **Fast-path `OWN_NS` filter (edit 1c).** Without it, Guard 0's M-status memory commit fails ADDED-only predicate (e) and disqualifies exactly the wf-fix branches the fast path was built for, routing them into the doomed server-side rebase. Excluding memory paths from the enumeration is safe: the surgical checkout is `--diff-filter=A` and never carries modified files regardless. **Source:** fast-path predicate (e) + surgical checkout `--diff-filter=A` text, read this session.
7. **Site A (worktree pull) kept + annotated; sites B/C replaced.** Per-site decision the brief demands: `sync_repo_root.py` is HEAD==main-preconditioned (exit 5), so it structurally cannot serve the worktree retry; both other sites operate on the repo root on main, the helper's exact domain, and it subsumes their pull+push retry in one call. **Source:** sync_repo_root.py exit-code spec; the surgical-checkout block's `cd "$REPO_ROOT"` + `git push origin main` context.
8. **Prose-only; no new helper script or lint check.** The brief prefers prose-only; the mechanical backstops already exist (`--check-references` validates the new script references; `tests/test_workflow_lint.py` pins trunk). A dedicated "SKILL.md must name sync_repo_root" lint check would be over-engineering for a 3-site fix. **Source:** brief constraint; `--check-script-refs` bundling in the docstring.
9. **Run the branch-tip lint copy, not main's, on path (i).** `_REPO_ROOT` from `__file__` means main's copy cannot be pointed at the worktree tree without new flags — a helper-script change the brief deprioritizes. The residual (a check added on main post-fork) is named in the gate text, is enforced anyway on the recovery path (which merges main in first), and the trunk pytest remains the backstop. **Source:** workflow_lint.py:361–362; Step 10d recovery block.
