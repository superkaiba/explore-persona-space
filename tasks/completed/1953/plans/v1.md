## Method delta (fix choice + rationale)

The flagged site is NOT a JSONL read: it tails a worker **log** file for
crash diagnostics (`log.read_text(encoding="utf-8", errors="replace").splitlines()[-120:]`)
inside a `*.jsonl`-globbing module (which is why the generic signal fires).
The module's real JSONL reads already go through the safe `read_jsonl()`
helper (line ~100, text-mode iteration). Splitting a human-facing log tail
on U+2028/NEL is harmless.

Chosen fix: the lint's designed waiver for genuinely-safe sites — a
`# JSONL_SPLITLINES_EXEMPT: <reason>` comment on the PRECEDING non-blank
line (same-line placement would exceed ruff's 100-char limit; both
placements are lint-supported per the test docstring item (iii)).

Rejected alternative: rewriting to `split("\n")` — equally green but
changes tail semantics slightly (keeps `\r` on CRLF logs) and is less
self-documenting than the waiver, which records WHY the site is safe.
