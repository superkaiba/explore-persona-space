#### D2. Detection predicate (the reintroduction guard's core — AST, not the 8-line heuristic; EXTENDED in v2)

**Predicate (unit-level):** flag a unit iff the union of exception names referenced by the unit contains BOTH
(a) a JSON-decode name: attribute or bare name `JSONDecodeError` (covers `json.JSONDecodeError` and `from json import JSONDecodeError`), AND
(b) an OSError-family name: `OSError` / `IOError` / `EnvironmentError` / `FileNotFoundError` / `PermissionError` / `IsADirectoryError` / `NotADirectoryError`,
and does NOT contain any of the safe names `UnicodeDecodeError` / `ValueError` / `Exception` / `BaseException`, and no in-scope waiver token is present. A "unit" is any of:

1. an `ast.Try` — union over ALL handlers' type expressions (v1's form);
2. an `ast.TryStar` (`except*` groups) — same handler union (NEW in v2; 0 live instances, covered so the future shape cannot become the evasion; measured FLAGGED on a synthetic reproduction);
3. **an `ast.With` / `ast.AsyncWith` item whose `context_expr` is a `Call` whose func resolves to `suppress` (bare name, from-import) or `contextlib.suppress` (attribute)** — union over the call's args, per suppress call (NEW in v2 — the Must-Fix: `contextlib.suppress(json.JSONDecodeError, OSError)` is byte-for-byte the same hole, 5 live sites carry it, and a guard covering only the tuple form would BLESS this rewrite as the natural evasion — worse, v1's error message TAUGHT it by printing the tuple form as the fix).

- **Why AST over the body's "read_text() within 8 lines above" proximity heuristic:** measured at HEAD, the string/proximity approach misses (i) 46 reversed-order sites, (ii) 9 wider-tuple/multi-line variants, (iii) 4 sites whose decode call is one hop away inside a module-local `_load_json`-style helper, and (iv — v2) the 5 `contextlib.suppress` sites, which have no `except` line at all. The AST predicate is order-, alias-, and formatting-insensitive and needs no proximity window. Tradeoff accepted: AST cannot prove a flagged unit is on a decode path — but empirically catching `JSONDecodeError`+`OSError` together IS the decode-path signal (186/186 at HEAD, 4 via one-hop helpers), so the proximity test adds misses without removing any false positive.
- **In-scope decode forms:** because the predicate keys on the caught-exception signature, `Path.read_text()+json.loads`, `json.load(open(...))`, `Path.read_bytes()+json.loads(bytes)` (json decodes bytes internally → `UnicodeDecodeError`), and `subprocess(text=True)` output parses are ALL covered with no per-form logic.
- **Sites already catching bare `ValueError` are excluded** by the safe set and left untouched (`json.JSONDecodeError` and `UnicodeDecodeError` both subclass `ValueError`) — per the body's Notes. Same logic excludes `suppress(..., ValueError)` / `suppress(Exception)` forms.
- **Split-handler form** (`except json.JSONDecodeError:` + `except OSError:` on one try) is covered by the try-level union (0 instances today; guard covers the future shape).
- **Bare-`except:` edge (docstring disclosure, NO predicate change — v2):** a try pairing the two-element tuple with an additional bare `except:` handler is a benign false positive — the bare handler contributes no names to the union but catches everything, so the try is already total. Zero live instances; the waiver token covers a future one; one line in the check docstring records this deliberately-accepted FP class (a bare `except:` beside a narrow tuple is itself a smell worth a human look).
- **Error message is FORM-SPECIFIC (v2 — Must-Fix 1c):** for a flagged try/`except*` unit the message prints the tuple fix (`except (json.JSONDecodeError, OSError, UnicodeDecodeError)`); for a flagged suppress unit it prints the suppress-args fix (`with contextlib.suppress(json.JSONDecodeError, OSError, UnicodeDecodeError):`). The message never prints only the tuple form for a suppress site — v1's single-message design would have taught the blocked author the exact rewrite the guard failed to cover. Both variants also name the waiver.
- **False-positive story:** measured 0/186 at HEAD. A hypothetical future FP (a unit genuinely unable to raise `UnicodeDecodeError`) costs either a harmless one-token extension or the waiver `# JSON_GUARD_UNICODE_EXEMPT: <reason>` on the flagged line (handler line / `with` line) or the line above (min-reason-chars enforced, `PUSH_SWALLOW` waiver model). **Known false negatives, disclosed in the check docstring** (smoke-blind-spots disclosure idiom; list EXTENDED in v2 — v1's omission of `suppress` from this list is exactly the failure Must-Fix 1 corrects, so the list is now the audited record of what the instrument cannot see): (i) dynamically-constructed exception tuples (`except tuple(excs):`) and dynamically-bound suppress (`sup = contextlib.suppress; with sup(...)`); (ii) exception names aliased at import (`from json import JSONDecodeError as JDE`; `import json as j` IS covered — attr match); (iii) **`suppress` aliased at import (`from contextlib import suppress as quiet`)** — name-based match misses it; 0 live instances, measured at plan time; (iv) a custom context manager wrapping suppress semantics under another name. Each disclosed miss is a name/binding indirection an author must WRITE DELIBERATELY — the guard's job is stopping the habitual forms, and the docstring says so.
- **Scope:** every `*.py` under `scripts/` + `src/` (matches the measurement scope; wrapped in `_files_scope_filter`). `tests/` deliberately excluded — fixtures there must be able to carry the banned shapes. The check does not self-trigger: `workflow_lint.py` holds zero flagged units (verified — absent from the 83-file list), and the check's own detection is name-set-based AST, not string match.
