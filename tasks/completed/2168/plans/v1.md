#### D2. Detection predicate (the reintroduction guard's core — AST, not the 8-line heuristic)

**Predicate (try-level):** flag an `ast.Try` iff, across ALL its handlers' type expressions, the union of referenced exception names contains BOTH
(a) a JSON-decode name: attribute or bare name `JSONDecodeError` (covers `json.JSONDecodeError` and `from json import JSONDecodeError`), AND
(b) an OSError-family name: `OSError` / `IOError` / `EnvironmentError` / `FileNotFoundError` / `PermissionError` / `IsADirectoryError` / `NotADirectoryError`,
and does NOT contain any of the safe names `UnicodeDecodeError` / `ValueError` / `Exception` / `BaseException`, and no in-scope waiver token is present.

- **Why AST over the body's "read_text() within 8 lines above" proximity heuristic:** measured at HEAD, the string/proximity approach misses (i) 46 reversed-order sites, (ii) 9 wider-tuple/multi-line variants, and (iii) 4 sites whose decode call is one hop away inside a module-local `_load_json`-style helper. The AST predicate is order-, alias-, and formatting-insensitive and needs no proximity window at all. Tradeoff accepted: AST cannot prove a flagged try is on a decode path — but empirically catching `JSONDecodeError`+`OSError` together IS the decode-path signal (181/181 at HEAD, 4 via one-hop helpers), so the proximity test adds misses without removing any false positive.
- **In-scope decode forms:** because the predicate keys on the caught-exception signature, `Path.read_text()+json.loads`, `json.load(open(...))`, `Path.read_bytes()+json.loads(bytes)` (json decodes bytes internally → `UnicodeDecodeError`), and `subprocess(text=True)` output parses are ALL covered with no per-form logic.
- **Sites already catching bare `ValueError` are excluded** by the safe set and left untouched (`json.JSONDecodeError` and `UnicodeDecodeError` both subclass `ValueError`) — per the body's Notes.
- **Split-handler form** (`except json.JSONDecodeError:` + `except OSError:` on one try) is covered by the try-level union (0 instances today; guard covers the future shape).
- **False-positive story:** measured 0/181 at HEAD. A hypothetical future FP (a try genuinely unable to raise `UnicodeDecodeError`) costs either a harmless one-token tuple extension or the waiver `# JSON_GUARD_UNICODE_EXEMPT: <reason>` on the handler line or the line above (min-reason-chars enforced, `PUSH_SWALLOW` waiver model). Known false negatives, disclosed in the check docstring (smoke-blind-spots disclosure idiom): dynamically-constructed exception tuples (`except tuple(excs):`) and exception names aliased at import (`import json as j` is covered — attr match; `from json import JSONDecodeError as JDE` is not).
- **Scope:** every `*.py` under `scripts/` + `src/` (matches the measurement scope; wrapped in `_files_scope_filter`). `tests/` deliberately excluded — fixtures there must be able to carry the banned shape. The check does not self-trigger: `workflow_lint.py` holds zero flagged tries (verified — absent from the 81-file list), and the check's own detection is name-set-based AST, not string match.
