## Concurrency note (corrected per critic item 2)

`MEMORY.md` is hot (fleet sessions append lessons daily). `merge=union` binds
on LOCAL merges/rebases only — the Step 10d primary path (`gh pr merge`,
server-side) does NOT honor it. Both realized paths are safe: non-overlapping
hunks land cleanly server-side; overlapping hunks refuse server-side and fall
to the Step 10d local `git merge origin/main` recovery, where union applies
(benign duplicate-line trade-off possible). The merging session should EXPECT
a possible server-side conflict rather than assume union fires there. After
the merge lands, the orchestrator runs a `wc -c` on main's MEMORY.md in the
same session: a union-duplicate re-inflation past 20,000 B is caught
immediately (fold the duplicates same-session if trivial; else it is a new
event for a future round, reported honestly). Single implementer + immediate
merge keeps the race window small; root copies are never touched.
