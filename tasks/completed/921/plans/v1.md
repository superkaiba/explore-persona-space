```python
# One clause per FOLDED same-issue follow-up round in the v4 footer
# (SPEC.md § `**Context:**` row: rounds name each round's `followup_label`;
# corpus form #763/#811: "same-issue follow-up round `<label>`"). The
# `(?!s)` lookahead keeps generic plural prose ("follow-up rounds also
# name…") out of the count; an unlabeled singular clause still counts 1.
_V4_FOOTER_ROUND_CLAUSE_RE = re.compile(
    r"same-issue follow-up round(?!s)(?:\s+`(?P<label>[^`\s]+)`)?"
)


def _followup_run_marker_rounds(issue: int) -> int:
    """Count REAL folded same-issue follow-up rounds off the task's
    events.jsonl `epm:same-issue-followup-run` markers: distinct
    `followup_label`s (one run marker closes a label's round) plus one per
    unlabeled run marker, EXCLUDING markers whose `outcome` begins
    `retroactive-close` — bookkeeping closes of ghost labels that folded
    no new prose (they are likewise excluded from the /issue round caps,
    SKILL.md). Returns 0 when the task id does not resolve
    (FileNotFoundError — e.g. a fixture body under a numeric tmp dir)."""
    from explore_persona_space.task_workflow import (  # local import — matches _load_text_for_issue
        FOLLOWUP_RUN_KIND,
        list_events,
        parse_followup_note_field,
    )

    try:
        events = list_events(issue)
    except FileNotFoundError:
        return 0
    labels: set[str] = set()
    unlabeled = 0
    for ev in events:
        if ev.get("kind") != FOLLOWUP_RUN_KIND:
            continue
        note = ev.get("note") or ""
        outcome = parse_followup_note_field(note, "outcome") or ""
        if outcome.startswith("retroactive-close"):
            continue
        label = parse_followup_note_field(note, "followup_label")
        if label:
            labels.add(label)
        else:
            unlabeled += 1
    return len(labels) + unlabeled


def _count_extra_followup_rounds_v4(body: str, issue: int | None = None) -> tuple[int, str]:
    """v4 twin of `_count_extra_followup_rounds` (whose `## What I ran`
    Rounds-table read only binds v3 — v4 bodies always scored rounds=0,
    incident #763/#921). Two signals, max-reconciled — the budget is
    WARN-only and monotone-up, and each signal under-counts in a known
    case (footer: a body omitting the SPEC round clause; events: a
    legacy pre-marker round whose prose IS folded):

    - footer: `same-issue follow-up round [`label`]` clauses inside the
      `**Repro:**`/`**Context:**` footer (distinct backticked labels +
      one per unlabeled singular clause);
    - events (when `issue` is known): non-retroactive-close
      `epm:same-issue-followup-run` markers via
      `_followup_run_marker_rounds`.

    Returns `(count, source)`; `source` ∈ {none, footer, events,
    footer+events} names the winning signal for the WARN message."""
    footer = _v4_footer_text(body) or ""
    labels: set[str] = set()
    unlabeled = 0
    for m in _V4_FOOTER_ROUND_CLAUSE_RE.finditer(footer):
        if m.group("label"):
            labels.add(m.group("label"))
        else:
            unlabeled += 1
    footer_n = len(labels) + unlabeled
    events_n = _followup_run_marker_rounds(issue) if issue is not None else 0
    count = max(footer_n, events_n)
    if count == 0:
        return 0, "none"
    if footer_n == events_n:
        return count, "footer+events"
    return count, "footer" if footer_n > events_n else "events"
```

## 11. Decision Rationale

- **Detection signal = events + footer (both), not either alone.**
  What: events leg reads `epm:same-issue-followup-run` markers; footer leg counts round clauses in `_v4_footer_text`.
  Why: the verifier's binding invocations (`--issue` at the 9a-bis gate and promote-time; `--file` on `tasks/<status>/<N>/body.md`, where `_resolve_file_siblings` recovers the id) have events access — the durable machine record with a workflow.yaml-pinned schema; but the verifier must stay runnable on a bare body file (`--body-stdin`, drafts in `.claude/cache/`), so a body-only leg MUST exist.
  Source: verify_task_body.py:7212 (CHECKS body-only call), 7323–7354 (`--issue`/`--file` resolution), 7271 (`_resolve_file_siblings` issue parse); task_workflow.py:1599/2429; corpus: tasks/followups_running/763/body.md footer (2 clauses) + events.jsonl (2 run markers), tasks/followups_running/811/body.md (1 footer clause; 0 run markers as of 2026-07-03 — exactly the case max() covers).
  Alternatives: events-only (breaks bare-file mode and #811-shaped bodies whose marker lands later); footer-only (fixes #763 with the smallest diff but leaves gate-time correctness hostage to analyzer prose — rejected since the events leg costs ~30 lines against a precedented dispatch pattern).

- **Precedence rule = max(footer, events).**
  What: `extra_rounds = max(footer_n, events_n)`.
  Why: the budget is WARN-only and monotone-up; each leg under-counts in a KNOWN real case (events: legacy rounds that ran without run markers — the ghost-label class `followup_retro_close_evidence` exists for, task_workflow.py:1861, whose prose IS in the body; footer: a body omitting the clause — #811's marker-less round is the mirror case on the events side). max() is wrong only by over-relaxing a WARN, never by masking the per-result ≥180 hard FAIL (the real gate, unchanged).
  Source: task_workflow.py:1861–1918; SKILL.md:993.
  Alternatives: events-wins-when-issue-given (under-counts the ghost-label class); sum (double-counts the same round seen by both legs — wrong for #763 where both legs see the same 2 rounds).

- **Retroactive-close exclusion = exclude.**
  What: run markers whose `outcome` first token (via `parse_followup_note_field`) starts with `retroactive-close` do not count.
  Why: they are bookkeeping closes of stale/ghost labels, posted with `outcome: retroactive-close — <evidence>`; the /issue skill already excludes them from both round caps for the same they-folded-no-new-prose reason. If a retroactively-closed round's prose IS in the body, the footer leg + max() still counts it.
  Source: .claude/skills/issue/SKILL.md:993, 6366, 6853; marker shape verified on #763's events.jsonl (real outcomes: `instrument-recovery…`, `matched-protocol…`).
  Alternatives: count them (inflates the budget for prose that was never added — rejected).

- **Helper fork (`_count_extra_followup_rounds_v4`) over a version branch inside `_count_extra_followup_rounds`.**
  What: new v4-only helper; the v3 helper + `check_v3_word_caps` stay byte-identical.
  Why: smallest blast radius — the brief and the grandfathered-shape rule (SPEC forward-only) both demand v3 byte-unchanged; a branch inside the shared helper would put v3's behavior inside the diff for no benefit. Exactly 2 production call sites confirmed (6309 v3, 6465 v4) + 1 test (tests:4163); no external consumers (repo-wide grep 2026-07-03: only task bodies/plans/docs mention the name in prose).
  Source: verify_task_body.py:6161/6309/6465; grep evidence.
  Alternatives: version-branching the shared helper (touches v3's code path); reusing the v3 Rounds-table read on v4 (impossible — no `## What I ran` H2 in v4, hard-FAILed as a stray v3 H2).
