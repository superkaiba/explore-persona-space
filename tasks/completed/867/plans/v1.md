### 3a. The bullet (exact text to insert)

Insert as a new top-level bullet in `.claude/rules/gotchas.md`, immediately after the allocator-fragmentation entry's final sub-paragraph — anchor: insert between the `**NOT a code-class bug:**` paragraph (ends "…with the hot-fix in the workload-cmd.)") and the `- **\`orchestrate.preflight --json\` emits PRETTY-PRINTED…**` bullet:

```markdown
- **Hidden-state-only CausalLM forwards materialize full-vocab logits for ALL positions by default — pass `logits_to_keep=1` when the logits are unread (transformers ≥4.49; pinned 4.57.6 verified).** `model(input_ids, ...)` on a transformers CausalLM computes `lm_head` logits for every position (`logits_to_keep=0` default = keep all) even when the caller only reads hook-captured hidden states and never touches `out.logits` — a silent `B × T × 152,064`-vocab half-precision allocation on Qwen-2.5-7B (#779 crash shape: a single 4.89 GiB request with only 4.61 GiB free, beside a co-resident vLLM engine holding 47.82 GiB). DISTINCT from the two CUDA-OOM siblings above: not the vLLM `prompt_logprobs` fp32-logits OOM (a vLLM-side allocation) and not allocator fragmentation (reserved-but-unallocated > request) — here the HF-side allocation is real, unread, and avoidable. RULE: every teacher-forced capture / hook-based extraction forward that does not read logits passes `logits_to_keep=1` (lm_head then computes only the last position, `B × 1 × V`), introspection-guarded — pass the kwarg ONLY when `inspect.signature(model.forward)` names an EXPLICIT `logits_to_keep` parameter (a bare `**kwargs` does NOT count; wrappers / CPU test stubs would silently swallow or crash on it), and keep the default for `return_logits=True` callers (`logits_to_keep=0` = all positions, contract unchanged). The kwarg was renamed from `num_logits_to_keep` in transformers 4.49 and the old name is fully removed from the pinned 4.57.6 — the introspection guard keys on the current name, so a future rename degrades to the old full-logits behavior instead of crashing. Canonical impl: `src/explore_persona_space/analysis/extraction.py::_logits_to_keep_kwargs` — lands with #779 (branch `issue-779` until that task merges). Sibling lesson from the same incident: persist rollout TEXT the moment generation completes, BEFORE any capture/judge reduce (already mandated — CLAUDE.md § Upload Policy raw-completions row, #779) — a capture crash otherwise burns the whole generation phase. (Incident #779 round 6, att-20260702-082017, 2026-07-02: sycophancy answer-capture OOMed on the unread-logits allocation; fixed by the introspection-guarded `logits_to_keep=1` threading, confirmed by the `(B, 1, V)` lm_head smoke signal.)
```

Refinements vs the candidate diff sketch, each grounded: (i) "≈4.9 GiB at T~1600" replaced with the exact verified incident numbers (4.89 GiB requested / 4.61 GiB free / 47.82 GiB vLLM resident) — the T~1600 figure does not back-solve cleanly (bf16 × 152,064 × 4.89 GiB ⇒ B×T ≈ 17,264 positions, i.e. B=16 × T≈1,079 at the code's `CORPUS_CAPTURE_BATCH_SIZE=16` default, not T=1600), so the bullet quotes the allocation, not a B/T decomposition; (ii) vocab written as 152,064 (verified from both cached Qwen-2.5-7B configs); (iii) added the DISTINCT-from clause (house register — three adjacent CUDA-OOM classes are already cross-disambiguated this way); (iv) the impl pointer is explicitly marked as landing with #779 (forward reference; see §3c); (v) the persist-text sibling is a cross-ref to its existing normative home, not a restatement.
