**D1 — `src/explore_persona_space/artifacts/datagen.py` (MODIFY; the shared gate).** Beside `DatagenYieldError` (~L127), add:

```python
# Narrowest observed install transition is ~12 optimizer steps
# (marker-training-recipe.md § Multi-arm resolution-band designs, #533/#547);
# below it no install has ever been observed in this project, so a cell that
# cannot sustain 12 steps at the registered recipe is structurally untrainable.
DEFAULT_MIN_OPTIMIZER_STEPS = 12


class CellTrainabilityError(DatagenYieldError):
    """Realized rows cannot sustain the minimum optimizer steps (loud, names the arithmetic)."""


def trainability_floor_rows(
    *,
    effective_batch_size: int,
    num_epochs: float,
    min_optimizer_steps: int = DEFAULT_MIN_OPTIMIZER_STEPS,
) -> int:
    """ceil(min_optimizer_steps * effective_batch_size / num_epochs); validates args > 0."""


def assert_cell_trainable(
    n_rows: int,
    *,
    cell_id: str,
    effective_batch_size: int,
    num_epochs: float,
    min_optimizer_steps: int = DEFAULT_MIN_OPTIMIZER_STEPS,
    override_floor_rows: int | None = None,
    override_reason: str | None = None,
) -> dict:
    """Absolute per-cell trainability gate — call at the row-counting site, pre-GPU/judge.

    Returns the report record {cell_id, n_rows, floor_rows, min_optimizer_steps,
    effective_batch_size, num_epochs, override_reason} for the mix report/manifest.
    Raises CellTrainabilityError when n_rows < floor (message names n_rows, floor_rows,
    and the realized optimizer-step arithmetic, per the DatagenYieldError message style
    at L1554). Raises ValueError when override_floor_rows is passed without a non-empty
    override_reason (an override is a recorded decision, never silent).
    """
```

### 11. Decision rationale (Source lines)

Why: install strength is denominated in steps, not rows; the narrowest install transition ever observed in this project is ~12 steps wide, so a cell that cannot sustain 12 steps cannot even traverse an install transition — the precise meaning of "structurally not a condition". Source: `.claude/rules/marker-training-recipe.md` § Multi-arm resolution-band designs (#533/#547 — ~12-step transition, 30-step all-arm anchor; #546 — steps dominate rank). Alternatives: 30 steps (the demonstrated all-arm install anchor) — rejected as the DEFAULT because the floor's contract is necessary-not-sufficient (a 30-step default would mandate dropping cells that might legitimately be dose-ladder rungs); the rule text instead directs behavior-specific upward derivation. A bare row count (e.g. keep 32) — rejected: not recipe-transferable, and 32 is itself below threshold (next line).

The derived default at that recipe is `ceil(12×16/1) = 192` rows. Source: issue778_finetune.py L54-55 (read this session) + `/tmp/issue-2242-clarify-v1.md`.
- **Floor formula `rows ≥ steps × batch / epochs`** — Source: task #2242 body + clarifier derivation instruction; step denomination from #533/#547.
