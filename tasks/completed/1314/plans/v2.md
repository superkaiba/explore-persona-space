### The change

Replace the single-token `fitness` search with a 4-branch declaration detector; rename the local `fitness` → `declaration`; minimally reword the two WARN branches for coherence. Exact diff sketch:

```python
    declaration = re.search(
        r"(?i)fitness"  # historical vocabulary (the pre-#1314 detector, unchanged)
        r"|reuse[- ]map"  # 'Reuse map' section shape (#1090 v7 D3; artifact-reuse.md's own term)
        r"|(?:self[- ])?attestation"  # 'self-attestation' / 'attestation(s)'
        r"|\(a\)\s*[-–—…]\s*\(j\)",  # the (a)–(j) range token — en-dash in real plans  # noqa: RUF001
        text,
    )
    letters = {m.group(1) for m in re.finditer(r"\(([a-j])\)", text)}
    if declaration and len(letters) >= 4:
        return _pass(
            cid,
            name,
            f"fitness/reuse-map declaration present ({len(letters)}/10 lettered items spotted)",
        )
    if declaration:
        return _warn(
            cid,
            name,
            f"fitness/reuse-map declaration vocabulary present but only {len(letters)} of the "
            "(a)–(j) items detectable — verify all ten attestations (recipe/regime/cells/"  # noqa: RUF001
            "single-var/hub-resolution/content-identity/scaling/backend-fetchability/"
            "code-throughput/pair-provenance) before approval",
        )
    return _warn(
        cid,
        name,
        "plan reuses HF artifacts but no fitness check / (a)–(j) reuse-map attestation found — "  # noqa: RUF001
        "CLAUDE.md reuse rule requires attestations (a)–(j); consistency-checker + Methodology "
        "critic must gate this",
    )
```

Plus a docstring extension on `check_reuse_fitness` (2-3 lines) recording the accepted declaration shapes and citing the #1090 v7 / #1314 incident.

### Design decisions (each verified against the live corpus/tests this session)

1. **What counts as a declaration** — four branches:
   - `fitness` — status quo, backward compatible (every currently-PASSing plan still PASSes: the detector is strictly broadened).
   - `reuse[- ]map` — the #1090 v7 heading and artifact-reuse.md's own name for the §10/§11 record. This is the branch that fires on v7 (verified: first match is `'Reuse map'`).
   - `(?:self[- ])?attestation` — the rule's other own term ("self-attestation", "fitness attestations"); the optional prefix also matches plain "attestation"/"attestations" (substring).
   - `\(a\)\s*[-–—…]\s*\(j\)` — the range token itself, covering hyphen, **en-dash (the shape real plans carry — v7's heading uses U+2013)**, em-dash, and ellipsis, with optional spaces. Note this token also contributes `{a, j}` to the letters set, so a bare promissory "(a)–(j)" citation with no real items yields only 2 letters and still lands in the middle WARN — the letters≥4 threshold keeps doing the content-gating work.
2. **Bare `artifact[- ]reuse` deliberately NOT a branch.** Merely citing `.claude/rules/artifact-reuse.md` as a pointer is not a declaration; a genuine attestation keyed to the rule invariably carries the range token, "attestation", "reuse map", or "fitness" (v7 carries three of the four). The brief's suggested "`artifact-reuse` + range token" conjunction is subsumed: the range-token branch alone accepts it.
3. **No proximity binding on `attestation`.** The pre-existing detector never bound `fitness` to reuse context (the word anywhere in the fence-stripped text sufficed), so binding only the new tokens would be asymmetric complexity in a WARN-only heuristic. The real specificity lives in the conjunction that already exists: reuse trigger fired AND declaration token AND ≥4 distinct `(a)`–`(j)` letters.
4. **Middle-branch wording updated** ("fitness vocabulary present" → "fitness/reuse-map declaration vocabulary present"): with the broadened detector a reuse-map declaration with <4 letters lands here, and the old wording would misstate what was detected. The `"(a)–(j)"` substring is retained (existing test `test_c6_fitness_with_few_letters_warns` asserts `"(a)–(j)" in r.detail or "ten" in r.detail`).
5. **Third-branch wording updated** to name the accepted alternative shape, retaining the `"fitness"` substring (existing test `test_c6_reuse_without_fitness_warns` asserts `"fitness" in r.detail`).
6. **PASS-branch wording** retains the `f"({len(letters)}/10 lettered items spotted)"` format (three existing tests assert `"4/10" in r.detail`).
7. **Unchanged by design:** letters≥4 threshold; `[a-j]` letter class; WARN-only severity (never FAIL); the reuse trigger; the `N/A — no artifact reuse` standalone escape; `kind != "experiment"` skip. Markdown tables survive `strip_fences` (verified: 9 letters found on fence-stripped v7), so no table-specific parsing is needed — confirming the original candidate's table-row-detection sketch is unnecessary.
8. **Why code, not a model call:** N/A-trivial — this is a 10-line regex change inside an existing deterministic linter; an LLM call inside `verify_plan.py` would be architecture, not a fix.

## Decision rationale (§11-style)

- **The chosen regex** — `(?i)fitness | reuse[- ]map | (?:self[- ])?attestation | \(a\)\s*[-–—…]\s*\(j\)`. **Why:** the three new branches are the artifact-reuse rule's OWN vocabulary ("reuse map" for the §10/§11 record; "self-attestation"/"attestations" for the checklist) plus the checklist's range token in every dash form real plans use (v7's heading uses en-dash U+2013). Verified live: matches v7 (`'Reuse map'`), does not match `GOOD_PLAN`. **Source:** `.claude/rules/artifact-reuse.md` (vocabulary), `tasks/followups_running/1090/plans/v7.md:111` (the incident shape), live reproduction this session. **Alternatives rejected:** bare `artifact[- ]reuse` branch (cite-the-rule-without-attesting false positive; the conjunction the task body suggested is subsumed by the range-token branch); proximity-binding `attestation` to reuse context (asymmetric vs. the unbounded historical `fitness` branch; complexity unjustified in a WARN-only check); the task body's table-row letter detection (aimed at the wrong sub-mechanism — letter detection already works, 9/10 found).
- **letters ≥ 4 threshold kept.** **Why:** per the brief and lineage (#871/#941 widened the class, never the threshold); it is what keeps a bare promissory range-token citation in the WARN branch. **Source:** verify_plan.py:854 + task brief.
- **WARN-only severity kept.** **Why:** the check's docstring — trigger and item-detection are heuristic; semantic gating belongs to the critic chain. **Source:** verify_plan.py:832-836.
