## 2. Method delta

Today `_up_logs()` early-returns when `$WORKLOAD_ROOT/logs` is missing and
otherwise walks only that root; after the change it collects `(mtime, size,
path, rel)` entries from BOTH roots — the workload-root walk byte-preserved
(git-tracked excludes, PRUNE, cache-suffix pruning, aggregate EXCLUDED line)
plus a new `/workspace/logs` walk (env `EPS_PERSIST_WORKSPACE_LOGS_DIR`; no
git exclude — the dir is outside the repo clone; walk-time excludes: `*.pid`,
`*.processed`, canonical `workload.log`, ONE aggregate line) — then sorts the
merged list newest-first, stages the top `LOG_MAX_FILES` tail-capped files
into the same `/tmp/eps-worker-logs` tree (dispatch files under
`workspace_logs/`), and uploads the same single `{dest}/worker_logs`
`upload_folder` commit. A missing root on EITHER side prints its loud SKIP
line and no longer aborts the other root's sweep; when both roots are missing
the function returns after the SKIP lines exactly as loudly as today. No
budget, retry-count, `timeout 300`, ordering (worker_logs still uploads BEFORE
the partial dirs), or repo-path semantics change.

**Rendered-source sketch** (this is python-source-rendered-as-a-string-list
inside `render_startup_script`'s shared preamble — each line below lands as
one list element following the surrounding block's quoting conventions: plain
double-quoted strings for code lines, single-quoted elements for lines

```python
def _up_logs():
    if LOG_MAX_FILES < 1:
        _say(f"[crash-persist] SKIP worker_logs: EPS_PERSIST_LOG_MAX_FILES={LOG_MAX_FILES} < 1")
        return
    logs_root = root / "logs"
    entries = []   # (mtime, size, path, rel) — rel = staged/repo-relative name
    walked_any = False
    if logs_root.is_dir():
        walked_any = True
        # ... #1351 git ls-files tracked-set block UNCHANGED ...
        # ... os.walk(logs_root) UNCHANGED except entries.append now carries
        #     rel: entries.append((st.st_mtime, st.st_size, p,
        #                          p.relative_to(logs_root).as_posix()))
        # ... n_tracked aggregate EXCLUDED line UNCHANGED ...
    else:
        _say(f"[crash-persist] SKIP worker_logs: no such dir ({logs_root})")  # kept; NO return (#1605)
    # 1b-bis. dispatcher per-phase logs (#1605) — /workspace/logs is the GCE
    # lane's own log/pid/sentinel convention dir (#610 pre-create), OUTSIDE
    # $WORKLOAD_ROOT/logs; the #1415 p3 traceback lived only here. Same
    # newest-first LOG_MAX_FILES budget, same LOG_FILE_CAP tail, same single
    # worker_logs commit. No git-tracked exclude (outside the repo clone).
    # Env override mirrors the #935 EPS_DONE_LOGS_DIR test-isolation knob.
    d_root = Path(os.environ.get("EPS_PERSIST_WORKSPACE_LOGS_DIR", "/workspace/logs"))
    try:
        same_dir = d_root.is_dir() and logs_root.is_dir() and d_root.resolve() == logs_root.resolve()
    except OSError:
        same_dir = False
    if not d_root.is_dir():
        _say(f"[crash-persist] SKIP workspace_logs: no such dir ({d_root})")
    elif same_dir:
        _say(f"[crash-persist] SKIP workspace_logs: same dir as worker logs root ({d_root})")
    else:
        walked_any = True
        n_excl = 0
        for dirpath, dirnames, filenames in os.walk(d_root):
            dirnames[:] = [d for d in dirnames
                           if d not in PRUNE and not (d.startswith("g") and d.endswith("_dl"))]
            for f in filenames:
                p = Path(dirpath) / f
                if f.endswith((".pid", ".processed")):
                    n_excl += 1        # detach pid files (L1538) + drained-sentinel renames (L6128)
                    continue
                try:
                    if log_path and p.resolve() == Path(log_path).resolve():
                        n_excl += 1    # canonical workload.log: already staged tail-capped (first bundle)
                        continue
                    st = p.stat()
                except OSError:
                    continue
                entries.append((st.st_mtime, st.st_size, p,
                                "workspace_logs/" + p.relative_to(d_root).as_posix()))
        if n_excl:
            _say(f"[crash-persist] EXCLUDED {n_excl} pid/drained-sentinel/canonical file(s)"
                 " from workspace_logs sweep")
    if not entries:
        if walked_any:
            _say("[crash-persist] SKIP worker_logs: empty after cache/git-tracked excludes")
        return
    entries.sort(reverse=True)  # newest first: the crashing worker wrote last (4-tuple; Path/str orderable)
    # ... dropped-count line, staged_root rmtree UNCHANGED ...
    for _, _, p, rel in entries[:LOG_MAX_FILES]:
        # canonical-log in-loop skip KEPT as belt (message now uses {rel});
        # `rel = p.relative_to(logs_root)` line REMOVED (rel rides the tuple);
        # tail-cap staging + TAILED/FAILED lines UNCHANGED (already keyed on {rel}).
    # ... n_staged guard + single upload_folder to f"{dest}/worker_logs" UNCHANGED ...
```

Design notes (each grounded in §7 Rationale):

- **`LOG_MAX_FILES < 1` check hoisted first** (it currently sits after the
  `logs_root.is_dir()` early-return; the disable must gate BOTH roots). Its
  SKIP string is unchanged (`test_persist_heredoc_worker_logs_max_files_lt_one_skips_loudly`
  asserts presence only).
- **Both-roots-missing output shape preserved:** the `walked_any` guard keeps
  variant-A of `test_persist_heredoc_prints_skips_and_honors_env_cap`
  byte-compatible (`SKIP worker_logs: no such dir` still prints; no spurious
  "empty after excludes" line; only-final-bundle upload assertion holds
  because the test harness points `EPS_PERSIST_WORKSPACE_LOGS_DIR` at a
  nonexistent tmp path by default).
- **One aggregate EXCLUDED line, never per-file** — mirrors the #1351
  git-tracked aggregate; keeps the #1339 200-line streamer cap headroom (the
  change adds ≤2 fixed lines; staging-line count is budget-shared and
  unchanged).
- **`same_dir` guard** — degenerate `WORKLOAD_ROOT=/workspace` would make the
  two roots identical; skip the second walk loudly rather than double-count.
- **Everything stays `|| true`-guarded / exception-swallowed via the existing
  structure** — the new code adds no raise paths outside the per-file
  try/except; the persist must always reach the trap's shutdown.

**Budget audit (hard constraint: never delay the poweroff).** Zero new
`upload_folder` commits, zero new retries, zero new network calls; the only
added work is one `os.walk` over `/workspace/logs` (on GCE a small local
scratch dir holding the canonical log + pid files + sentinels + per-phase
logs) and ≤`LOG_MAX_FILES` tail-capped copies that were ALREADY budgeted (the
cap is shared, not additive). `timeout 300`, attempt counts, and the
worker-logs-before-partial-dirs ordering are byte-unchanged.

## 7. §11 Decision Rationale (load-bearing constants, each with Source)

- **Per-file tail cap = shared `LOG_FILE_CAP`** (`EPS_PERSIST_LOG_FILE_CAP_BYTES`,
  default `5 * 1024**2` — quoted from gcp.py L1920 at HEAD). Why: the #1517
  rationale ("5 MiB default keeps a staged log 2x under the ~10 MB threshold
  at which upload_folder force-routes a blob to LFS", L1918-1919) applies
  identically; the traceback is at the END of a log. Source: gcp.py
  L1918-1920 (#1517/#885). Alternative (a new cap knob) rejected — no new
  constant, no new failure surface.
- **File-count budget = shared `LOG_MAX_FILES`** (`EPS_PERSIST_LOG_MAX_FILES`,
  default `40` — quoted from gcp.py L1921 at HEAD), shared across BOTH roots
  in one newest-first sort. Why: the candidate diff sketch specifies "under
  the same dir cap"; a second independent budget could double the staging
  lines against the #1339 200-line streamer cap. Source: gcp.py L1921 (#885)
  + task #1605 body diff sketch. Alternative (separate budget per root)
  rejected per the streamer-cap arithmetic.
- **Sweep-root default `/workspace/logs`, env-overridable
  `EPS_PERSIST_WORKSPACE_LOGS_DIR`.** Why: the startup script hardcodes
  `mkdir -p /workspace/logs` (L1507) and the pod-side contract names
  `/workspace/logs/issue-<N>-*.json` as the drain glob (L1499-1508); the #935
  done-persist already reads the same dir via env-overridable
  `EPS_DONE_LOGS_DIR` default `/workspace/logs` (L2461) — the new knob mirrors
  that shape in the `EPS_PERSIST_*` family (grep-verified fresh name). Source:
  gcp.py L1507/L2461 (#610/#935). Alternative (derive from
  `Path(log_path).parent`) rejected — cleverness over convention; `log_path`
  can be unset while the dir convention still holds.
- **Exclusion set `{*.pid, *.processed, canonical workload.log}`.** Why:
  `*.pid` is the detach pid-file convention the startup script waits on
  (L1532-1538); `*.processed` is the poller's drained-sentinel rename
  (gcp.py L6128 "Rename a drained sentinel to ``<path>.processed``");
  the canonical log (`EPS_LOG_PATH` = `log_path_for` =
  `<vm_scratch_dir>/logs/issue-<N>.log`, L943-951, `vm_scratch_dir` default
  `/workspace`, L224) is already staged tail-capped in the first bundle
  (L1937-1938) — re-staging it would double-upload up to 5 MiB and burn a
  budget slot. Undrained `issue-<N>-*.json` sentinels are deliberately
  INCLUDED (small JSON; the #935 done-persist stages exactly those, L2493-2497).
  Source: gcp.py L1532-1538 / L6128 / L943-951 / L2493-2497.
- **Ordering: merged newest-first across roots.** Why: "newest first: the
  crashing worker wrote last" (existing comment, L2008); the crashing
  dispatcher's per-phase log is mtime-newest at trap time. Source: gcp.py
  L2008 (#885).
- **Staged/repo prefix `workspace_logs/` under the SAME `worker_logs` commit.**
  Why: one commit keeps the 300s budget arithmetic unchanged (#1151/#664:
  never per-file; each extra commit risks a 504-retry cycle); the prefix makes
  provenance legible on HF and prevents rel-path collisions with workload-root
  logs. Source: gcp.py L1811-1815 (#1151), compute-backend-failover.md Part A
  item 3. Alternative (separate `{dest}/workspace_logs` commit) rejected —
  +1 commit inside the 300s budget for zero benefit.
- **No git-tracked exclude on the dispatch root.** Why: the #1351 exclude
  exists because the repo is CLONED at `$WORKLOAD_ROOT` (tracked
  `logs/daily+weekly` files live under `$WORKLOAD_ROOT/logs`);
  `/workspace/logs` is outside any clone, so a second `git ls-files` run
  would be a guaranteed-WARN no-op burning subprocess time. Source: gcp.py
  L1951-1958 (#1351 comment block).
