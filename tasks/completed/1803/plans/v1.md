# Plan v1 — #1803 daily-fix: env-pin allowlist gains vetted runtime-tuning keys

## Requirement + acceptance criteria

**Requirement:** OOM/throughput remediation env keys — the house shared-box
runtime-tuning set — must be threadable through the dispatch env-pin channel
(`dispatch_issue.py launch --env-pin KEY=VALUE`). Today
`ENV_PIN_ALLOWED_KEYS` (src/explore_persona_space/backends/base.py:100)
rejects them; #1739's OOM-remedy relaunch failed dispatch on
`key 'MALLOC_ARENA_MAX' not in ENV_PIN_ALLOWED_KEYS` (one failed dispatch +
retry).

**Acceptance criteria:**
1. `validate_env_pins({"MALLOC_ARENA_MAX": "2", "OMP_NUM_THREADS": "8"})`
   returns the mapping (no raise); same for the other three thread-cap keys.
2. All existing env-pin tests pass unchanged in behavior (the render tests
   iterate the frozenset and self-adapt).
3. A new/extended test pins the runtime-tuning keys' membership so a future
   allowlist rewrite cannot silently drop them.
4. No secret-key representability change: the allowlist stays a frozenset
   literal; no runtime extension mechanism is introduced.

## Method delta (what differs from prior related work)

#1669 built the env-pin channel with a 6-key allowlist scoped to
launch-declared destinations (WandB routing + adapter-persist). This plan
WIDENS the allowlist by exactly the 5-key house runtime-tuning set mandated
by the code-style / detached-launch conventions (`env OMP_NUM_THREADS=8
MKL_NUM_THREADS=8 OPENBLAS_NUM_THREADS=8 NUMEXPR_NUM_THREADS=8
MALLOC_ARENA_MAX=2`, CLAUDE.md § Detached VM-side long compute phases;
`.claude/rules/code-style.md` thread-cap discipline):

- `MALLOC_ARENA_MAX`
- `OMP_NUM_THREADS`
- `MKL_NUM_THREADS`
- `OPENBLAS_NUM_THREADS`
- `NUMEXPR_NUM_THREADS`

**Decision — frozenset addition, NOT an `EPM_ENV_PIN_EXTRA` escape** (the
body's option 2). Reasons: (a) the allowlist's own docstring names "Extend by
editing this frozenset (code review is the gate)" as the designed extension
path; (b) an env-var escape makes arbitrary keys representable at runtime,
eroding the security property the allowlist exists for (secret KEY names
unrepresentable by construction — sidecar JSON, marker extras, and GCP
instance metadata are all readable surfaces); (c) the 5 keys are a closed,
well-known set — no open-ended extension need exists.

**Deliberate non-goal:** no numeric-value validation for the new keys. The
filer's sketch says "values remain validated single-line strings"; the
existing value rules (non-empty single-line str ≤512 chars, secret-shaped
value regex) already apply to every pin, and a malformed numeric value fails
loudly at the consuming runtime. Minimal diff wins.
