`kind: infra` · bug fix in shared library code · 0 GPU-hours.

**v2 changes (folding critic round 1, `VERDICT: APPROVE` with one Should-Fix):**
* Should-Fix 1 — the helper's exception catch widens from
  `(TypeError, ValueError, AttributeError)` to `except Exception`, so acceptance
  criterion 4's unqualified "never raises" is actually true. A `get_sizes` that
  exists but raises `RuntimeError` propagated out of the v1 helper; nothing

  and the embed guard at `:1534` both contain it), but the v1 plan's own

* Nit 2 — guard-comment wording: a bare `PathCollection([])` is not

  reaches the guard at all.
* Recorded, no change needed: `ax.scatter([0.0],[0.0], s=0)` reports sizes
  `(1,) [0]`, so the new guard KEEPS it — correct, it is a genuine datum with a
  zero-area marker, and `size` presence (not magnitude) is the discriminator.

## Requirement

`paper_plots._extract_scatters` must emit a sidecar `points` row for a genuine
single-point scatter whose lone offset is exactly `(0.0, 0.0)`, while continuing
to skip the placeholder `(1,2)` `[[0,0]]` offset that non-marker collections
report.

### Acceptance criteria

1. A figure rendering `ax.scatter([0.0], [0.0], s=14)` emits exactly one
   `points` row for that point, with `_kind == "scatter"`, and `total_points`
   counts it.
2. The same holds at matplotlib's default marker size (`ax.scatter([0.0],
   [0.0])`, no `s=`) — the default is a real size, not an absent one.
3. Placeholder-offset collections are STILL skipped and emit no `scatter` row:
   `ax.errorbar` bar `LineCollection`, `ax.fill_between`, `ax.violinplot`, and a
   bare `matplotlib.collections.PathCollection([])`.
4. `_extract_scatters` still never raises. Specifically the new helper returns
   `False` — never propagates — for: an object with no `get_sizes` attribute, a
   non-callable `get_sizes`, and a `get_sizes` that raises **any** exception
   (pinned with `RuntimeError`, which is outside the narrow
   `TypeError/ValueError/AttributeError` set).
5. `ax.scatter([], [])` (genuinely empty) continues to emit no row.
6. The full existing `tests/test_paper_plots.py`, `tests/test_issue2094_figures.py`
   and `tests/test_issue2225_figures.py` suites stay green (no test currently
   pins the buggy skip — verified at clarifier time and independently
   re-confirmed by the critic).

## Root cause (verified, not assumed)

`_extract_scatters` (`src/explore_persona_space/analysis/paper_plots.py:1082-1084`)
carries:

```python
# A lone (0,0) offset is matplotlib's default for empty collections.
if offsets.shape[0] == 1 and not np.any(offsets):
    continue
```

The comment's stated rationale is **wrong about which case it protects**, and the
guard over-fires. Measured directly against the locked stack (matplotlib 3.10.8,
numpy 2.2.6, `Agg` backend) — probed independently twice, at clarifier time and
by the critic:

| Artist | `get_offsets()` | `get_sizes()` | New-guard verdict |
|---|---|---|---|
| `scatter([0],[0], s=14)` — **genuine datum** | `(1,2)` `[[0,0]]` | `(1,)` `[14]` | KEPT |
| `scatter([0],[0])` — **genuine, default s** | `(1,2)` `[[0,0]]` | `(1,)` `[36.0]` | KEPT |
| `scatter([0],[0], s=0)` — **genuine, zero-area** | `(1,2)` `[[0,0]]` | `(1,)` `[0]` | KEPT |
| `scatter([],[])` — genuinely empty | `(0,2)` | `(1,)` | never reaches guard |
| `errorbar` bar `LineCollection` | `(1,2)` `[[0,0]]` | **no `get_sizes`** | skipped |
| `fill_between` / `violinplot` bodies | `(1,2)` `[[0,0]]` | `(0,)` empty | skipped |
| bare `PathCollection([])` | `(1,2)` `[[0,0]]` | `(0,)` empty | skipped |
| colorbar axes (`QuadMesh` + `LineCollection`) | `(1,2)` `[[0,0]]` | **no `get_sizes`** | skipped |
| `pcolormesh` `QuadMesh` | `(1,2)` `[[0,0]]` | **no `get_sizes`** | skipped |
| `contourf` `QuadContourSet` | `(1,2)` `[[0,0]]` | **no `get_sizes`** | skipped |
| single-arrow `quiver` at (0,0) | `(1,2)` `[[0,0]]` | `(0,)` empty | skipped |
| `hexbin` `PolyCollection` | `(8,2)` real | `(0,)` empty | never reaches guard |

Three facts follow:

* `ax.scatter([], [])` **never reaches** the `(0,0)` guard — its offsets are
  shape `(0,2)` and the preceding `offsets.shape[0] == 0` check already skips
  it. The guard's comment names a case it does not handle.
* The collections that DO reach the guard are non-marker artists reporting a
  placeholder offset. A genuine `scatter` is distinguished from every one of
  them by carrying a **non-empty `sizes` array**. No artist was found that
  misclassifies in either direction.
* The `getattr` guard is **load-bearing on every `errorbar` figure**:
  `LineCollection` has no `get_sizes` attribute at all. It is equally
  load-bearing for the raster/contour family — and because `_extract_axes_data`
  iterates `fig.get_axes()`, **colorbar axes are visited too**, and their
  `QuadMesh`/`LineCollection` lacking `get_sizes` is what keeps the
  imshow-family tests safe.

So the guard's *intent* is right (drop placeholder offsets) but its *test* is
coordinate-based, and it therefore also drops every real `(0,0)` datum produced
by the standard per-point `ax.scatter([x],[y])` companion loop.

### Impact, reproduced

`figures/issue_2162/persona_specificity_ladder/ladder_percarrier.meta.json`
records `total_points=252` / `n_series=252` against **264** rendered
`ax.scatter` calls. The producer
(`scripts/issue2162_ladder_analysis.py:1023-1024`) computes
`x = r_pos[r["rung"]] + (k - 1) * 0.18`, so `x == 0.0` exactly only for the
middle arm (`k == 1`) at rung index 0. In that sidecar 12 rows survive at
`x == 0.0` with non-zero `y`, and **zero** rows sit at `(0,0)` — the 12-point
gap is exactly the dropped `(0,0)` data. This corrupts the surface
`report-verifier` recomputes against and nearly produced a spurious FAIL in the
#2162 ladder round.

No second drop path exists: `_xy_rows` maps non-finite coordinates to `None`
and **keeps** the row, so NaN/Inf coordinates account for none of the gap.

## Method delta

Replace the coordinate-based placeholder test with an **artist-property** test,
per the task body's `fix_sketch`, with two corrections the sketch did not state:

1. The `get_sizes()` call must be `getattr`-guarded — `LineCollection` reaches
   this code on every `errorbar` figure and has no such attribute, so a bare
   `coll.get_sizes()` raises `AttributeError` inside a function whose documented
   contract is "Never raises: any artist whose data cannot be read is skipped".
2. The `try` must catch broadly (`except Exception`), not a three-class tuple, or
   the never-raises contract holds only for the exception classes we guessed.

Rejected alternative: the sketch's parenthetical `or when facecolors are unset`.
Measured `get_facecolor()` shape is `(1,4)` for BOTH a genuine single-point
scatter and an empty scatter, so facecolor does not discriminate. Sizes do.

## File paths + concrete diffs

### 1. `src/explore_persona_space/analysis/paper_plots.py`

Add a module-level helper immediately above `_extract_scatters`:

```python
def _has_marker_sizes(coll: object) -> bool:
    """Return True when ``coll`` is a marker collection carrying explicit sizes.

    ``PathCollection`` (what ``ax.scatter`` creates) exposes ``get_sizes()`` and
    returns one entry per drawn marker — a real size even when the caller passed
    no ``s=`` (matplotlib's default is 36.0), and even for ``s=0``. Non-marker
    artists differ: ``LineCollection`` (error bars), ``QuadMesh``
    (``imshow``/``pcolormesh``/colorbars) and ``QuadContourSet`` have no such
    method at all, while ``fill_between`` / ``violinplot`` / ``quiver`` / bare
    ``PathCollection`` artists return an EMPTY array. That difference is what
    tells a genuine single ``(0,0)`` scatter point from the placeholder ``(1,2)``
    ``[[0,0]]`` offset those non-marker artists report.

    Never raises: any collection whose sizes cannot be read returns False, so
    the caller falls back to skipping it (the pre-#2262 behavior). The catch is
    deliberately broad — a third-party artist's ``get_sizes`` may raise anything,
    and the caller's contract is never-raises.
    """
    import numpy as np

    getter = getattr(coll, "get_sizes", None)
    if not callable(getter):
        return False
    try:
        return bool(np.asarray(getter()).size)
    except Exception:
        return False
```

Then narrow the guard in `_extract_scatters` (replacing lines 1082-1084):

```python
        # Non-marker artists report a placeholder (1,2) [[0,0]] offset:
        # LineCollection error bars, QuadMesh / QuadContourSet rasters (incl. on
        # colorbar axes), fill_between / violin polys, and a bare PathCollection.
        # A genuine ``scatter(...)`` carries a non-empty ``sizes`` array, so
        # discriminate on that instead of on the coordinates — otherwise a real
        # (0,0) datum from a per-point ``ax.scatter([x],[y])`` loop is dropped.
        # (``ax.scatter([], [])`` never reaches here: its offsets are (0,2) and
        # the shape check above skips it.)
        if offsets.shape[0] == 1 and not np.any(offsets) and not _has_marker_sizes(coll):
            continue
```

Behavior change is confined to one cell of the decision table: a lone-`(0,0)`
collection that DOES carry marker sizes is now kept. Every other input is
byte-unchanged, including multi-point collections (which never reached the
guard) and `embed_data=False` renders (which skip extraction entirely,
`paper_plots.py:1530`).
