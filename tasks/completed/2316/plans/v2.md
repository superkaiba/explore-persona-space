**Failure-text plumbing.** New helper `parse_junit_failure_texts(path: Path) -> dict[Node, str]`, mirroring `parse_junit_ran_files`'s discipline (:1085-1116: mirror `parse_junit`'s per-case `file`/Node derivation incl. the #1746 collect-error fallback WITHOUT modifying `parse_junit`, whose `summary` is persisted verbatim into the ledger). **Extraction — sanitize, then match (revised for critic must-fix 1).** `extract_violation_paths(text: str) -> frozenset[str]` with one module regex plus two sanitizers:

```python
_VIOLATION_PATH_RE = re.compile(r"\b(?:scripts|src|tests|configs|docs)/[\w./-]+\.[A-Za-z0-9_]+")
```

1. **Introspection-segment strip (removes the CHANNEL):** before matching, drop every line whose `lstrip()`ed content starts with `"assert "` — pytest's rewritten introspection segment (the `assert not [<saferepr>]` tail) always begins with the literal assert expression at line start, in BOTH the junit `message` attribute and the `E `-prefixed element text (probe shapes, §12 A1). The registered members' offender rows never begin with `assert ` (source-verified shapes: indented path rows / `  - path:line: ...` rows, §12 A4), so no offender is ever dropped; and if a guidance line ever started with "assert " it would drop symmetrically on both sides.
2. **Elision-token post-filter (defense in depth):** after matching, drop any extracted token containing the literal substring `"..."` — the saferepr elision marker. A real tracked path cannot collide: `git ls-files | grep -c '\.\.\.'` → 0 at plan time (§12 A12), and the charclass `[\w./-]+` is what lets an elided fragment like `scripts/fakemod_01.py...nv` (or a mid-cut token ending `.py`) match at all. Residual corner: a FUTURE tracked path containing `...` would be invisible to the diff on BOTH sides — a fail-toward-strip corner (never a false block), stated here as accepted.

Why both (belt-and-braces, each 2 lines and independently safe): the segment strip removes the generator of content-DEPENDENT asymmetry — the critic measured that the elision point moves with list content, so the garbage token differs between sides exactly when the lists differ, which is precisely the branch-fixes-a-subset #2289 session shape that must keep stripping (criterion 2 / #1388); the token filter additionally covers any OTHER saferepr surface (a future pytest changing the segment shape, or a future member whose raise-message embeds a repr). File-grain extraction (no `:line` in the token) is retained from v1: line numbers drift under unrelated same-file edits and would manufacture false NEW reds. Symmetric prose (headers, remediation text, snippet text mentioning e.g. `scripts/task.py`) extracts identically on both sides and cancels in the set difference; only genuinely asymmetric offender rows survive — a claim that is now TRUE for the whole text because the one measured asymmetric non-offender segment (the introspection tail) is stripped before matching.

`_resolve_scan_violation_setdiff` (new function):

1. `v_branch = extract_violation_paths(ctx.run_failure_texts.get(node, ""))`; `v_pristine = extract_violation_paths(pristine_text)`.
2. **Parse-fail arm (criterion 3):** if either set is EMPTY → strip exactly as today (same `via` values, so `stripped`-row consumers and the urgent-park coupling are undisturbed) PLUS: append a warn `"SCAN-SETDIFF-UNPARSEABLE: <file>::<name> — violation list could not be extracted from the <branch|pristine> failure output; node-grain verdict retained; hand-verify the branch adds no violation to this scan"`, emit the same line on stdout, and record a `scan_violation_diffs` row with `verdict: "parse-failed"`. Loud, never silent; never a new exit class (degrade = today's behavior + escalation, per the task's fail-CLOSED/fail-LOUD constraint).
3. `new_paths = v_branch - v_pristine`; `suppressed = new_paths & ctx.base_identical`; `new_paths -= suppressed`. `suppressed` non-empty → warn naming them (main's own content carried by a Step 5a sibling-sync copy — the #2302/#2296 class; blocking the branch for main's own offender would be a false red).
4. `new_paths` non-empty → `ctx.new.append(node)` (inherits rc 1 via :2751 `return 1 if (result["new"] or not result["lint"]["ok"]) else 0`), stdout `SCAN-NEW-VIOLATION: <file>::<name> — branch adds violation path(s) absent on pristine main: <sorted new_paths>`, row `verdict: "new-violations"`.
5. `new_paths` empty → `_strip_node` as today + row `verdict: "pre-existing"`. The row IS the cheap arm (D5): it carries both sides so the session gets the one-glance side-by-side read.

Row shape (each list sorted; capped at 50 entries with an `..._overflow` count so a pathological message cannot bloat the JSON — the cap is DISPLAY-ONLY: bucketing always operates on the full uncapped sets, so a pathological episode can truncate the row's lists but never change a verdict): `{"node_id", "verdict", "new_violations", "base_identical_suppressed", "pre_existing", "pristine_only"}`. (`pristine_only` = `v_pristine - v_branch`, informational — offenders fixed or absent on the branch side.)
