  `autonomous_session_watch.py` (the 10-min cron) that adjudicates ripe
  `proposed` infra/batch tasks itself (no PM queue) and dispatches into free

- **Shared concurrency cap (3) — enforced at BOTH dispatch sites:** the
  file-time wrapper, the existing infra-drain pass, and the new watcher sweep

## 1. Goal

A filed `proposed` `kind: infra` (or pure-code/ops `kind: batch`) task today
only auto-runs if a LIVE PM session does a STATUS pass (`research-pm.md` §444)
and writes it into `~/.eps-autonomous/infra-drain-queue.json`, which the
watcher's infra-drain pass then executes. With no PM session in the loop, a
ripe infra task orphans indefinitely — incident #684 sat at `proposed` ~17h.
Close the gap from both ends: (1) make "whoever files a ripe infra fix
dispatches it" the default at FILE time via a thin wrapper wired into the
routing surfaces, and (2) add an always-on watcher safety-net sweep that
adjudicates + dispatches ripe `proposed` infra tasks itself, catching anything
filed by a context that could not self-dispatch (pods, manual `task.py new`, a
crashed filer). Both ADD paths; the existing PM rule + infra-drain pass keep
working unchanged.

## 2. Prior work / existing surfaces

- **PM standing rule (`research-pm.md` §444-575).** The PM's STATUS-pass infra
  auto-dispatch: enumerate ripe `proposed` `kind: infra`/pure-code `batch`/
  `agent-ok` `analysis`, re-evaluate `predicate-<#N>-...` holds, dispatch ripe
  ones via `spawn-issue --issue <N> --auto` under a 3-session cap, and WRITE
  the adjudicated queue to `infra-drain-queue.json` (step 4b) for the watcher
  to drain between passes. This is the NUANCED ripeness judge — it stays the
  authoritative source for cross-issue predicate adjudication and dup-cluster
  consolidation. We do NOT touch its logic.
- **Watcher infra-drain pass (`autonomous_session_watch.py:6228 infra_drain_pass`,
  task #633).** EXECUTES the PM-written queue file with zero ripeness judgment
  (except mechanical predicate-hold promotion). It already owns every primitive
  the new sweep needs:
  - cap/occupancy: `_infra_drain_occupancy()` (`INFRA_DRAIN_OCCUPIED_STATUSES`,
    `INFRA_DRAIN_KINDS`; returns `list[int] | None`), `_infra_drain_pending()`,
    `INFRA_DRAIN_CAP_DEFAULT=3`;
  - registration dedup: `_infra_drain_reg_snapshot()` (decision-time bytes),
    `_infra_drain_registrations()`, `_infra_drain_stale()`,
    `_dispatch_infra_drain()` (pre-spawn byte-identity re-check + `spawn-issue
    --auto` subprocess);
  - predicate semantics: `_parse_predicate_hold()`,
    `_satisfied_predicate_promotions()`,
    `INFRA_DRAIN_PREDICATE_SATISFIED_STATUSES`;
  - queue-file read: the same `~/.eps-autonomous/infra-drain-queue.json` reader
    the pass uses to load the PM's `holds` map (the storage the new sweep's
    predicate gate reuses — see §3);
  - daemon gating: `_daemon_reachable()`, `_live_session_ids_or_none()`;
  - markers: `_post_progress_marker()` + a sentinel string.
  **The new sweep extends this machinery; it does NOT execute the PM queue.**
  The KEY difference: the infra-drain pass's candidate set + holds come FROM the
  PM queue file; the new sweep BUILDS its candidate set from
  `task.py list-by-status --status proposed` (filtered to drain-kinds) and
  consults the SAME PM queue file's `holds` map ONLY to honor predicate/user
  holds (no new convention).
- **`spawn_session.py`.** `spawn-issue --issue <N> --auto` POSTs to the Happy
  daemon, registers `~/.eps-autonomous/issue-<N>.json` on success.
  `_load_session_issue_map()` (the engine behind `list`) maps every live
  `{issue,manual-issue,campaign}-<N>.json` registration to its issue — the
  canonical "does this issue have a live session?" source of truth.
- **`task.py new`** (`cmd_create`, line 235) prints `#<new_id>` to stdout via
  `_safe_echo`; mutation core (`create_task`) holds `flock` + commits. It has
  NO knowledge of sessions — and must keep it that way (`task.py` branch-guards
  to `main` and is a forbidden pod-side shellout target;
  `tests/test_no_pod_side_task_py_shellout.py`).
- **`workflow-fix-on-bug.md` step 5-6.** The orchestrator currently FILES
  (`task.py new ...`) THEN separately SPAWNS (`spawn-issue --auto`). #690's
  change (1) is the generalization of exactly this two-step pattern into one
  wrapper call.

**Why a new mechanism is needed:** the PM-queue path requires a live PM
session to ADJUDICATE ripeness; the watcher infra-drain pass only EXECUTES what
the PM already adjudicated. Nothing autonomously adjudicates a freshly-filed
`proposed` infra task when no PM is running — so it orphans. (1) puts the
adjudication+dispatch at FILE time (the filer knows the task is ripe — it just
filed a concrete, ripe fix), and (2) adds an independent watcher adjudicator as
the backstop.

## 3. Design — concrete file-level changes

### (0) Shared cap helper — NEW `infra_dispatch_has_free_slot()` (v3 M1 fix)

**Decision: factor a SHARED cap-check primitive so the wrapper, the existing
infra-drain pass, and the new sweep all consult ONE place.** Rationale in §8.
The helper wraps the EXISTING `_infra_drain_occupancy()` / `_infra_drain_pending()`
primitives — it introduces no new cap semantics, only a single call site for the
three dispatchers:

```python
# autonomous_session_watch.py (imported by file_infra_task.py)
def infra_dispatch_has_free_slot(
    pending: int = 0, *, cap: int = INFRA_DRAIN_CAP_DEFAULT
) -> bool | None:
    """True iff a NEW infra/batch dispatch fits under the shared cap.

    Tri-state, fail-CLOSED on unreadable occupancy (mirrors the executor's
    `_infra_drain_occupancy() is None -> skip` rule):
      - None  -> occupancy UNREADABLE (any `list-by-status` read failed);
                 callers MUST NOT dispatch this tick.
      - False -> cap full (occupied_active + pending >= cap).
      - True  -> at least one free slot.

    `occupied_active = len(_infra_drain_occupancy())` (kind-infra/batch tasks at
    INFRA_DRAIN_OCCUPIED_STATUSES); `pending` is the caller-supplied count of
    in-flight non-stale registrations (the watcher passes the real
    `_infra_drain_pending(...)`; the file-time wrapper passes 0 — at file time
    there is no fresh same-tick registration to count, and a just-filed task
    has no registration yet, so occupancy alone is the binding budget for the
    one spawn the wrapper is about to make)."""
    occ = _infra_drain_occupancy()
    if occ is None:
        return None
    return (len(occ) + max(0, pending)) < cap
```

- **Placement:** the helper lives in `autonomous_session_watch.py` next to
  `_infra_drain_occupancy()`/`_infra_drain_pending()` and is IMPORTED by
  `file_infra_task.py` (same import class as the watcher's own
  `from spawn_session import daemon_port` — an orchestration-layer module import,
  NOT a `task.py` shellout; A13). This keeps ONE definition of "is there a free
  infra slot" — a future cap-tightening refactor edits exactly one function, and
  the wrapper / infra-drain / sweep cannot drift apart.
- **The two watcher passes keep their existing `decide_*` arithmetic** (which
  already computes `free = max(0, cap - occupied_active - pending)` over the
  full candidate list); the helper is the SINGLE-SPAWN convenience the wrapper
  needs (it dispatches at most one task per call) AND the canonical place the
  cap constant + occupancy/pending composition lives. The sweep's batch decision
  (`decide_proposed_infra_sweep`, §4 R4) calls the same underlying primitives so
  the budget is identical; no third copy of the cap math is introduced.

### (1a) File-time wrapper — NEW script `scripts/file_infra_task.py`

**Decision: a NEW standalone orchestration-layer script, NOT a `task.py new
--auto-dispatch` flag.** Rationale in §8. The script delegates filing to
`task.py new` (so the mutation core + flock + commit stay the single source of
truth) and then attempts the spawn.

**CLI surface** (mirrors `task.py new`'s relevant flags so it's a drop-in
"file + dispatch"):
```
uv run python scripts/file_infra_task.py \
    --kind infra \                      # default infra; choices {infra, batch}
    --title "..." \                     # required
    [--body-file PATH | --body TEXT] \  # mutually exclusive, forwarded
    [--parent N] [--tag T ...] \        # forwarded to task.py new
    [--origin-prompt "..."] \           # forwarded
    [--no-dispatch] \                   # file only; skip the spawn attempt
    [--auto-approve-gpu-hours T]        # forwarded to spawn-issue (default = spawn_session default)
```
- `--kind` choices are restricted to `{infra, batch}` (the auto-dispatchable
  pure-code/ops kinds). `experiment`/`analysis`/`campaign` are rejected with a
  loud argparse error — those have their own routing (analysis needs the
  `agent-ok` opt-in + PM triage; experiment needs the adversarial-planner GPU
  gate). This keeps the wrapper from ever auto-`--auto`-dispatching a
  GPU-spending task outside a cap.

**Dispatch sequence** (`cmd_file_infra` → exit code):
1. **File first.** Run `task.py new --kind <k> --title ... [...]` via
   `subprocess.run(cwd=PROJECT_ROOT)`. Parse the new id from stdout
   (`#<N>` — the existing `_safe_echo(f"#{new_id}")` line; take the first
   `#<int>` match). If `task.py new` fails (non-zero rc) → print stderr, exit
   non-zero. **The task IS filed even if the later spawn fails** — filing is the
   durable, must-succeed half; the backstop (2) catches a failed/skipped spawn.
2. **`--no-dispatch` → done.** Print `filed #<N> (dispatch skipped: --no-dispatch)`,
   exit 0. (Lets a pod-side / deliberately-deferred filer use the wrapper for
   uniform provenance without spawning.)
3. **Daemon reachability gate.** Call a local `_daemon_reachable()`
   (same probe shape as the watcher's: POST `/list` to
   `127.0.0.1:<daemon_port()>`, swallow URLError/OSError/HTTPException/
   UnicodeDecodeError/JSONDecodeError → False). On unreachable → print
   `filed #<N>; Happy daemon unreachable, NOT dispatching (watcher backstop
   will pick it up)`, exit 0. **This is the headless/pod-side no-op:** no daemon
   → no spawn, clean fall-through to (2).
3.5. **Shared cap gate (v3 M1 fix).** Call
   `infra_dispatch_has_free_slot()` (the §3(0) shared helper; the wrapper passes
   `pending=0` per the helper docstring). Branch:
   - **`None` (occupancy UNREADABLE)** → print `filed #<N>; infra-slot
     occupancy unreadable, NOT dispatching (watcher backstop will pick it up
     within ~10 min)`, exit 0. Fail-closed — a partial occupancy read could
     over-dispatch, so the wrapper never spawns on an unreadable count
     (identical posture to the executor's `_infra_drain_occupancy() is None ->
     skip`).
   - **`False` (cap full)** → print `filed #<N>; infra dispatch cap (3) full,
     NOT dispatching (watcher backstop will pick it up within ~10 min)`, exit 0.
     The task is filed and `proposed`; the next watcher tick (≤10 min) dispatches
     it into a freed slot. This is the M1 fix: a wrapper call can no longer push
     a 4th infra/batch session past the shared cap before the watcher's next
     tick. It ALSO closes the wrapper-vs-wrapper concurrent case: two
     near-simultaneous filings each re-read live occupancy here, so once 3 are
     occupied the 3rd+ wrapper no-ops its spawn (any sub-second double-read
     window collapses to the same bounded single-overshoot the registration
     dedup already accepts — see §3 Idempotency).
   - **`True` (free slot)** → proceed to step 4.
   This new condition is "one more reason to no-op the spawn," consistent with
   the wrapper's existing design (filing is the must-succeed half; dispatch is
   best-effort, no-op'd by daemon-unreachable AND already-live-registration AND
   now cap-full/occupancy-unreadable). The task is NEVER lost — the backstop
   sweep (2), which runs the same cap arithmetic, dispatches it when a slot
   frees.
4. **Idempotency pre-check.** Before spawning, check
   `_issue_has_live_registration(N)` (reads `~/.eps-autonomous/issue-<N>.json`
   + `manual-issue-<N>.json`; if present AND its `happy_session_id` is in the
   daemon's live id set → already dispatched). A just-filed task essentially
   never has one, but the check makes the wrapper safe to re-run. On a live
   registration → print `filed #<N>; already has a live session, NOT
   re-dispatching`, exit 0.
5. **Spawn.** `subprocess.run(["uv","run","python","scripts/spawn_session.py",
   "spawn-issue","--issue",str(N),"--auto", ...])`. On success → print
   `filed + dispatched #<N>`, exit 0. On spawn failure → print a WARNING
   (`filed #<N>; dispatch FAILED (<stderr>); watcher backstop will retry`),
   exit 0 (NOT non-zero — the task is filed and the backstop covers it; a
   non-zero here would make callers think filing failed).

**Failure / no-op modes, all → clean fall-through to the backstop, never a lost
task:**
- daemon down → no spawn (step 3);
- **cap full / occupancy unreadable → no spawn (step 3.5, v3 M1);**
- already has a live session → no spawn (step 4);
- spawn subprocess errors → warn, exit 0 (step 5);
- the wrapper's own crash after `task.py new` succeeded → the task is on disk
  at `proposed`; the watcher sweep dispatches it next tick.

**Helpers to add to `file_infra_task.py`** (kept self-contained as an
orchestration-layer caller — it imports the two CLIs only as subprocesses for
`task.py`/`spawn-issue`, but DOES import the watcher's shared cap helper, since
that is a Python module import of an orchestration-layer function, NOT a
`task.py` shellout): `_daemon_reachable()`, `_live_session_ids()` (or import
`spawn_session._live_session_ids` / `daemon_port`), `_issue_has_live_registration(N)`,
`_parse_new_id(stdout)`, **and `from autonomous_session_watch import
infra_dispatch_has_free_slot` (v3 M1).**

### (2) The watcher sweep — NEW pass `proposed_infra_sweep_pass`

**Decision: a NEW pass, adjacent to (and reusing the primitives of) the
existing infra-drain pass — NOT an extension of `infra_drain_pass` itself.**
Rationale in §8. The two are kept separate functions because they differ in
ONE structural way (candidate source: PM queue file vs. `list-by-status`) but
share all dispatch/cap/dedup primitives (including §3(0)'s shared cap helper /
the same occupancy+pending arithmetic).

**Pass name + position.** `proposed_infra_sweep_pass(dry_run, now=None, *,
daemon_reachable=None)`. In `main()` it runs **immediately AFTER
`infra_drain_pass(...)` (line 6228 / called at main() line 10477) and BEFORE
`capacity_retry_pass(...)` (line 10489)**. This ordering is load-bearing:
- After infra-drain so any ID the PM queue already dispatched THIS tick is
  registered (the sweep's registration dedup sees it → won't double-dispatch);
- the two passes share the cap, and the sweep computes occupied/pending AFTER
  infra-drain's dispatches are registered, so the combined budget is respected.

**Ripeness predicate** (a `proposed` task is sweep-ripe iff ALL hold):
1. `status == "proposed"` (built from `task.py list-by-status --status
   proposed --json`, so `on_hold` tasks — a DIFFERENT status folder — are
   structurally excluded, never appear; the EXACT `--status proposed` argv is
   pinned by the rewritten Test 10, §4 M2);
2. `kind in INFRA_DRAIN_KINDS` (`{infra, batch}`) — `experiment`/`analysis`/
   `campaign` excluded (analysis needs `agent-ok` + PM triage; this sweep is
   the cheap mechanical safety net, deliberately NARROWER than the PM rule —
   it does NOT auto-dispatch `agent-ok` analysis, which keeps an explicit
   opt-in path through the PM);
3. **NO user/predicate hold per the PM's queue file (the gate, F1-corrected).**
   Read `~/.eps-autonomous/infra-drain-queue.json` (the SAME file the
   infra-drain pass already reads for the `holds` map — see A7's
   `_satisfied_predicate_promotions`). The queue parses (via
   `parse_infra_drain_queue` / `_parse_predicate_hold`) to a dict with a
   `holds: {id: reason}` map keyed by INT id (NOT raw JSON string keys — the
   sweep consults the PARSED int-keyed output, R3). For each candidate id,
   consult `holds`:
   - **Candidate id NOT in `holds` (the orphan case)** — the PM never wrote a
     queue entry for it (it was filed with no PM in the loop, exactly the gap
     #690 closes) → NO hold to honor → ELIGIBLE (proceed to predicate-4).
   - **In `holds` for a `predicate-<#N>-<short-desc>` reason** — parse the
     blocking-issue `#N` (reuse the `_parse_predicate_hold`-style parsing the
     infra-drain pass uses, the SAME primitive behind
     `_satisfied_predicate_promotions`). If `#N` is in a satisfied-predicate
     status (`INFRA_DRAIN_PREDICATE_SATISFIED_STATUSES` =
     `completed`/`archived`/`awaiting_promotion`) → the predicate is satisfied →
     ELIGIBLE. Otherwise `#N` is still in flight → SKIP (logged
     `held: predicate-<#N>` — the PM deferred it and the blocker is not yet
     finished).
   - **In `holds` for ANY non-predicate reason**
     (`credentials`/`outward-facing`/`spend`/`re-kind`/`irreversible`/
     `predicate-satisfied`/etc.) → SKIP regardless (these are other
     user-park reasons; the PM explicitly said hold; the sweep never overrides a
     user-park). This "ANY non-predicate reason → SKIP" is intentionally
     OVER-CONSERVATIVE — bare mechanical-deferral reasons like `held: cap` /
     `held: predicate` that `research-pm.md` 562-568 treats as "PM re-checks
     next pass" are ALSO skipped here. That never OVER-dispatches (it only ever
     defers a candidate to a later tick), and a bare `cap`/`predicate` hold the
     PM wrote means the PM is actively managing that id, so deferring to the
     PM's next pass is the safe direction (R2 — conscious choice, recorded in
     §8).
   - **Missing / empty / invalid / torn-write queue file** →
     `parse_infra_drain_queue` returns `None` → fail-SOFT: treat as "no holds"
     (an empty `holds` map). Orphans (predicate-4 path) can still dispatch; no
     candidate is ever blocked by an unreadable queue, because the
     orphan-eligible default is "no hold." **Subtlety (R1):** the fail-soft
     "no holds" default applies ONLY to genuinely missing/empty/invalid reads.
     The PM writes the queue atomically (tmp+rename, `background-automation.md`),
     so a read either lands on the whole prior valid file or the whole new file
     — never a torn half. A present-but-`None`-parsing file (e.g. `holds` is a
     list, or a hold key is unparseable) is treated as "this read produced no
     usable holds map" identically to missing — which is the same conservative
     behavior the infra-drain pass uses for its own holds parse. The Test-14
     rewrite (§4 R1) pins that a corrupt/`None`-parsing read does NOT silently
     un-hold a candidate that a prior VALID read had held: the candidate is
     either still held (if the prior read is still the file on disk) or, on a
     genuinely corrupt file, treated as an un-held orphan ONLY because no usable
     holds map exists — never because a held entry was dropped from an otherwise
     valid map.
   This reuses the EXISTING shared storage and the EXISTING predicate
   primitives — NO new on-task tag convention is invented. (The watcher's
   infra-drain pass already reads this same JSON `holds` map for its
   predicate-promotion logic; the sweep reads the identical structure.)
4. NO live issue-mapped session (the idempotency check — see Idempotency below).

**Cap accounting — SHARED with infra-drain, computed once, no double-spend.**
The cap is `INFRA_DRAIN_CAP_DEFAULT` (3) — the SAME constant, via the SAME
`§3(0)` primitives. `free = max(0, cap - occupied_active - pending)`:
- `occupied_active` = `len(_infra_drain_occupancy())` (kind-infra/batch tasks at
  `INFRA_DRAIN_OCCUPIED_STATUSES`) — REUSED verbatim;
- `pending` = `_infra_drain_pending(registrations, stale, status_kind)` over
  ALL non-stale registrations — REUSED verbatim, and this is the mechanism that
  prevents the sweep from over-dispatching past what infra-drain already
  spawned THIS tick: a session infra-drain spawned earlier this tick wrote its
  `issue-<N>.json`, so it counts as `pending` here.
- Fail-CLOSED: if `_infra_drain_occupancy()` returns `None` (any status read
  failed) → skip dispatching this tick (a partial count over-dispatches),
  exactly as infra-drain does (and as the shared helper returns `None`).

Because both passes read the SAME registration snapshot semantics and the SAME
occupancy/pending helpers within the same `main()` tick, their combined spawns
cannot exceed `free` slots: the sweep runs second and sees infra-drain's
freshly-registered spawns as `pending`.

**Candidate ordering + slot fill.** Sort sweep-ripe candidates oldest-first
(ascending id is a safe proxy; the PM's urgency-first nuance is the PM's job —
the sweep is the mechanical backstop). Fill `free` slots; everything beyond
`free` is skipped `cap-full` (re-tried next tick).

**Per-candidate churn guard.** Reuse the infra-drain attempt/backoff state file
pattern but in a SEPARATE state file `~/.eps-autonomous/proposed-infra-sweep-
state.json` (so the sweep's attempt budget never collides with the PM-queue
drain's `infra-drain-state.json`). Backoff window `EPM_PROPOSED_INFRA_SWEEP_
BACKOFF_S` (default 3600s, reuse the constant value); attempts cap
`EPM_PROPOSED_INFRA_SWEEP_MAX_ATTEMPTS` (default 3). A task whose spawn keeps
failing backs off; the day a PM rewrites/repromotes or the task changes status
the entry is pruned. (Simpler than the PM-queue epoch reset — there is no
`updated_ts` here; just a per-task backoff from last attempt + a per-task
attempt cap, with the entry pruned when the task leaves `proposed`.)

**Idempotency / registration dedup.** REUSE `_infra_drain_reg_snapshot()` +
`_dispatch_infra_drain(issue, slot_desc, dry_run, reg_snapshot=snap)` — that
function already does the pre-spawn byte-identity re-check against the
decision-time snapshot and aborts on a registration that "appeared/changed
since the decision" (lost race to a concurrent dispatcher). A candidate with an
existing NON-stale registration is filtered out BEFORE dispatch (it has a live
session). A STALE registration (dead-at-boot: task still `proposed`, older than
grace, session not live — `_infra_drain_stale`) does NOT block re-dispatch
(same semantics as infra-drain).

**Kill switch + flags.** Env `EPM_DISABLE_PROPOSED_INFRA_SWEEP=1` → pass logs
`disabled` and returns. New `main()` flag `--proposed-infra-sweep-only` (mirrors
`--infra-drain-only`) for live smoke. Daemon-gated like every spawning pass
(skip when `daemon_reachable` is False).

### Idempotency — concrete dedup check + race bounding

- **Source of truth (both paths):** the issue-mapped registration files
  `~/.eps-autonomous/{issue,manual-issue}-<N>.json` — the same files
  `spawn_session._load_session_issue_map()` (the `list` engine) reads. "Live"
  = registration present AND its `happy_session_id` ∈ the daemon's live session
  id set (`_live_session_ids_or_none()`); a registration whose recorded session
  is no longer live AND whose task is still `proposed` past grace is STALE
  (re-dispatchable), per `_infra_drain_stale`.
- **File-time wrapper:** step-3.5 shared cap gate + step-4 pre-check
  (`_issue_has_live_registration`) before the spawn subprocess.
- **Watcher sweep:** candidate filtered out if it has a non-stale registration;
  `_dispatch_infra_drain`'s pre-spawn byte-identity re-check is the final guard.
- **Race between (1) and (2):** the wrapper spawns synchronously at file time
  and registers `issue-<N>.json` on success BEFORE returning. The next watcher
  tick (≤10 min later) sees that registration and skips the task. The only
  double-spawn window is a sub-second overlap where the wrapper's spawn has not
  yet written its registration AND the watcher tick reads the candidate
  simultaneously — both then pass the dedup check and both spawn. This is
  acceptable for a once-per-10-min sweep + a synchronous file-time call (the
  same bounded window the PM-vs-watcher infra-drain race already accepts, shrunk
  by `_dispatch_infra_drain`'s byte-identity re-check). The cost of the rare
  double-spawn is one redundant no-GPU Happy session, reaped by the
  zombie-wrapper / session-reconcile passes. **The §3.5 cap gate does NOT change
  this window** — it bounds the STEADY-STATE overshoot (a wrapper can no longer
  blow past the cap on a calm system), and the sub-second race is the same
  bounded single-overshoot that the registration dedup already accepts in the
  infra-drain pass.

## 8. §11 Decision Rationale (every design knob)

- **NEW script `scripts/file_infra_task.py` vs `task.py new --auto-dispatch`
  flag.**
  - *What:* a standalone orchestration-layer wrapper.
  - *Why (serves the Goal):* a `--auto-dispatch` flag inside `task.py` would put
    session-spawning logic in `task.py`'s process — and `task.py` is the
    branch-guarded, flock-holding state-mutation core that pod-side code must
    NEVER shell out to (`tests/test_no_pod_side_task_py_shellout.py`,
    CLAUDE.md). Even a flag that "only shells out after the mutation core
    returns" risks normalizing `task.py` as a dispatch entrypoint and tempts a
    pod-side caller. A separate script keeps the mutation core dispatch-free and
    keeps the dispatch concern in the orchestration layer where it belongs
    (same layer as `spawn_session.py`). The wrapper itself shells out to
    `task.py new`, so it is added to `_LOCAL_VM_ONLY_PATHS` in the pod-shellout
    test (§3 (1a-test)) — an orchestration-layer caller that is never
    pod-side-invoked, the same class as `spawn_session.py`.
  - *Source:* CLAUDE.md "Pod-side code NEVER shells out to `scripts/task.py`";
    `tests/test_no_pod_side_task_py_shellout.py`; body HARD CONSTRAINT #1.
  - *Alternatives rejected:* (i) `task.py new --auto-dispatch` — rejected as
    above; (ii) an adapter inside `spawn_session.py` (`spawn-issue` gains a
    `--file-first`) — rejected because `spawn_session` is the spawn primitive,
    not a task-filer; mixing filing into it muddies its single responsibility
    and the body asks for a "file + dispatch in one call" filer.

- **SHARED cap helper `infra_dispatch_has_free_slot()` — ONE definition consumed
  by the wrapper, the infra-drain pass, and the sweep (v3 M1).**
  - *What:* a single function (in `autonomous_session_watch.py`, imported by
    `file_infra_task.py`) wrapping `_infra_drain_occupancy()` + the cap constant
    that the file-time wrapper's step-3.5 gate calls BEFORE spawning, and that
    the two watcher passes' cap arithmetic composes from the same primitives.
  - *Why (serves the Goal):* the reconciler's M1 finding is that v2's wrapper
    enforced the cap via the watcher sweep ONLY — so a wrapper call could spawn a
    4th infra/batch session while 3 were already running, blowing past the body's
    "respect the existing 3-session cap shared with PM auto-dispatch; don't blow
    past it when both paths are active" before the watcher's next 10-min tick
    could catch it (and the wrapper-vs-wrapper concurrent case was a second
    overshoot vector). Adding the pre-spawn gate to the wrapper closes both. The
    DEFENSIVE design choice is to factor ONE shared helper rather than duplicate
    the cap-check logic in three call sites: a future refactor that tightens the
    cap (a different constant, a new occupied-status, a different pending rule)
    edits exactly one function and all three dispatchers stay in lockstep — the
    alternative (three copies) is exactly the silent-drift hazard the reconciler
    is wary of. The wrapper's no-op-on-cap-full matches its EXISTING design
    ("filing is the must-succeed half; dispatch is best-effort") — cap-full /
    occupancy-unreadable is simply one more reason to no-op the spawn alongside
    daemon-unreachable + already-live-registration, with the backstop sweep
    catching the filed-but-not-dispatched task within ~10 min. Fail-CLOSED on
    `None` (unreadable occupancy) mirrors the executor's own
    `_infra_drain_occupancy() is None -> skip` rule.
  - *Source:* reconciled Phase-2 Must-Fix M1; CLAUDE.md / body "respect the
    existing 3-session cap shared with PM auto-dispatch"; existing
    `_infra_drain_occupancy`/`_infra_drain_pending`/`INFRA_DRAIN_CAP_DEFAULT`
    (`autonomous_session_watch.py:5247, 5854, 5903`).
  - *Alternatives rejected:* (i) keep the cap-check only in the watcher sweep
    (v2) — REJECTED: the reconciled M1 finding (the wrapper overshoots before the
    next tick). (ii) Duplicate the occupancy+cap arithmetic inline in
    `file_infra_task.py`, the infra-drain pass, and the sweep — REJECTED: three
    copies drift; a cap-tightening refactor would have to find + update all
    three, exactly the maintenance hazard the shared-helper choice removes. (iii)
    Have the wrapper import + reuse the sweep's full `decide_*` batch decision —
    REJECTED as overkill: the wrapper dispatches at most ONE task per call, so a
    single-spawn `bool | None` helper is the right grain; the batch decision
    stays in the sweep where it belongs.

- **Predicate/user gate reads the PM's `infra-drain-queue.json` `holds` map
  DIRECTLY (NOT a new on-task tag convention).**
  - *What:* the sweep's predicate/hold gate consults
    `~/.eps-autonomous/infra-drain-queue.json` — the SAME file the watcher's
    existing infra-drain pass reads for the `holds` map — and uses the SAME
    `_parse_predicate_hold` primitive (already behind
    `_satisfied_predicate_promotions`) to resolve `predicate-<#N>-...` reasons,
    consulting the PARSED int-keyed output (NOT the raw JSON string keys — R3).
  - *Why (serves the Goal):* the `predicate-<#N>-...` convention is a REASON
    STRING in the PM-written queue file's `holds` map, NOT an on-task tag. Zero
    `proposed` tasks carry a `predicate-` tag in frontmatter and no production
    code writes one — so reading a `predicate-` tag off `view --json`
    `frontmatter.tags` would invent a new, unsupported on-task convention with
    nothing to read. Reading the PM's queue file reuses the EXISTING shared
    storage + EXISTING predicate primitives, honors every user-park reason the
    PM recorded (predicate AND non-predicate: `credentials`/`spend`/etc.), and
    fails soft (missing/invalid file ⇒ no usable holds map ⇒ orphans dispatch —
    exactly the gap #690 closes). An orphan (id not in `holds`) was filed with
    no PM in the loop, so it has no recorded hold and is eligible.
  - *Over-conservative non-predicate skip is a CONSCIOUS choice (R2):* the
    sweep's "ANY non-predicate `holds` reason → SKIP" deliberately also skips the
    bare mechanical-deferral reasons `held: cap` / `held: predicate` that
    `research-pm.md` 562-568 treats as "PM re-checks next pass" (not user-parks).
    This is over-conservative — it defers a candidate the PM might re-ripen on
    its next pass to a later tick — but it NEVER over-dispatches (the only effect
    is a one-tick deferral), and a bare `cap`/`predicate` hold the PM wrote means
    the PM is actively managing that id, so deferring to the PM's nuanced pass is
    the safe direction. Recorded so reviewers see the skip is intentional, not a
    missed case.
  - *Source:* research-pm.md 476-494 (canonical `predicate-<#N>-<short-desc>`
    reason-string format in the queue `holds` map) + 562-568 (bare-`cap`/
    -`predicate` mechanical-deferral semantics); A7's
    `_satisfied_predicate_promotions` (the existing infra-drain
    predicate-promotion reads the same JSON); `background-automation.md`
    (atomic tmp+rename queue write makes the read point-in-time-consistent);
    Phase-1.5 fact-checker finding F1.
  - *Alternatives rejected:* (i) read a `predicate-<#N>-...` TAG from
    `view --json` `frontmatter.tags` — REJECTED: no such tag convention exists,
    no production code writes one, zero tasks carry one; it would be a new,
    unsupported, undocumented on-task convention. (ii) Ignore holds entirely
    and dispatch every ripe `proposed` infra task — REJECTED: would override
    the PM's deliberate user-parks (spend/credentials/outward-facing) and run a
    predicate-blocked task before its blocker finishes. (iii) Read the raw JSON
    string keys for the holds membership check — REJECTED: a subtle membership
    bug (string `"7"` vs int `7`) for a future re-implementer; consult the
    parsed int-keyed output instead (R3).

- **NEW watcher pass `proposed_infra_sweep_pass` vs EXTEND `infra_drain_pass`.**
  - *What:* a new sibling pass reusing infra-drain's primitives.
  - *Why:* the two passes differ in exactly ONE structural axis — candidate
    source (PM-written queue file vs. `list-by-status --status proposed`) — and
    that axis touches the whole top of the function (read+parse+validate+holds).
    Folding both into one function would require a mode branch threaded through
    every step and would couple the PM-queue's epoch/`updated_ts` retry budget
    to the sweep's simpler per-task backoff. A separate function reusing the
    leaf primitives (`_infra_drain_occupancy`, `_infra_drain_pending`,
    `_dispatch_infra_drain`, `_infra_drain_reg_snapshot`, `_infra_drain_stale`,
    `_parse_predicate_hold`, the shared `infra-drain-queue.json` `holds`
    reader, and the new `infra_dispatch_has_free_slot` helper) keeps each
    function single-purpose and lets the body's "ADDS paths, not REMOVES the PM
    one" invariant be obvious by inspection.
  - *Source:* body change #2 + "the PM remains the only NUANCED ripeness judge;
    both watcher mechanisms are mechanical predicate checks";
    `autonomous_session_watch.py` infra-drain pass structure.
  - *Alternatives rejected:* a `mode=` param on `infra_drain_pass` — rejected
    (couples the two retry-budget models, harder to test in isolation, risks
    regressing the #633-hardened PM-queue executor).

- **Position in pass order (after infra-drain, before capacity-retry).**
  - *What:* sweep runs second of the two infra dispatchers.
  - *Why:* running AFTER infra-drain means the sweep's `pending` count sees any
    ID infra-drain dispatched THIS tick (its fresh `issue-<N>.json`), so the
    shared cap is honored across both; running before capacity-retry keeps both
    spawning-into-free-slots passes grouped. The order is load-bearing enough to
    pin with a dedicated test (R6 Test 17).
  - *Source:* `main()` 10477-10489; the infra-drain/cap accounting helpers.
  - *Alternatives rejected:* before infra-drain (would let the sweep dispatch a
    PM-queued ID the PM intends to dispatch with urgency ordering — better to
    let the nuanced judge go first).

- **Separate sweep state file `proposed-infra-sweep-state.json`.**
  - *What:* the sweep's per-task attempt/backoff state is distinct from
    `infra-drain-state.json`.
  - *Why:* a single task could be reachable via BOTH the PM queue and the sweep
    (e.g. PM queued it, watcher also sees it `proposed`); sharing one state file
    would let one path's attempt budget silently throttle the other. Separate
    files keep each path's churn guard independent + independently testable.
  - *Source:* infra-drain state-file pattern (`_load/_save_infra_drain_state`).
  - *Alternatives rejected:* shared state file (budget cross-talk).

- **Sweep scope `{infra, batch}` only (NOT `agent-ok` analysis).**
  - *What:* the mechanical sweep is narrower than the PM rule's scope.
  - *Why:* `agent-ok` `analysis` requires an explicit human opt-in tag + can be
    CPU-cost-bearing; keeping it out of the always-on mechanical sweep preserves
    the deliberate opt-in path through the PM and avoids the sweep ever
    auto-running analysis the user did not clear. `infra`/`batch` pure-code/ops
    is the unambiguous auto-dispatchable set.
  - *Source:* research-pm 457-470 (scope + the `agent-ok` opt-in requirement);
    `INFRA_DRAIN_KINDS`.
  - *Alternatives rejected:* match the PM's full scope incl. `agent-ok` analysis
    — rejected (removes the human opt-in gate for an always-on robot).

- **Test 10 rewrite — argv assertion (option a) over feed-an-on_hold-row

  - *What:* the on_hold-exclusion test asserts the EXACT

  - *Why:* the reconciler's M2 finding is that v2's Test 10 passes for ANY

  - *Source:* reconciled Phase-2 Must-Fix M2; A6 (on_hold is a status folder);
    `tests/test_autonomous_session_watch.py:5788` (the argv-asserting `_fake_run`

  - *Alternatives rejected:* (i) v2's empty-mock-zero-candidates assertion —

    REJECTED (tests a runtime filter the sweep does not and should not have; the

  - *Source:* `decide_infra_drain` (5533) + `_decide_drain` (5713); reconciler
