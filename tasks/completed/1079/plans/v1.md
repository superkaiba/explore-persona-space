### Target (a): `src/explore_persona_space/analysis/vectorized_mlp_skill.py`

**A1 — new module-level constant + resolver (place near `DEFAULT_MLP_SEED`, l.150):**

```python
DEFAULT_FIT_NUM_THREADS = 8  # #891 launch-prefix / #847 env.py setdefault / #811 patch value

def _resolve_num_threads(num_threads: int | None) -> int | None:
    """Resolve the per-fit CPU thread cap. None -> conservative default
    (min(DEFAULT_FIT_NUM_THREADS, os.cpu_count()); env override
    EPS_VECTORIZED_FIT_DEFAULT_THREADS, ""/0 disables). 0 -> opt-out (no pin).
    >0 -> verbatim. <0 -> ValueError (fail loud)."""
    if num_threads is None:
        raw = os.environ.get("EPS_VECTORIZED_FIT_DEFAULT_THREADS", "").strip()
        cap = DEFAULT_FIT_NUM_THREADS if raw == "" else int(raw)  # int() fails loud on garbage
        if cap == 0:
            return None
        if cap < 0:
            raise ValueError(f"EPS_VECTORIZED_FIT_DEFAULT_THREADS must be >= 0, got {cap}")
        return max(1, min(cap, os.cpu_count() or cap))
    n = int(num_threads)
    if n == 0:
        return None
    if n < 0:
        raise ValueError(f"num_threads must be >= 0 (0 = opt-out), got {n}")
    return n  # explicit caller value honored VERBATIM (no cpu_count clamp)
```

**A2 — decorator `_with_thread_cap` (pin + restore, CPU only), applied to the three fitters:**

```python
def _with_thread_cap(fn):
    """Pin torch's intra-op pool per the fn's num_threads/device kwargs for the
    call duration (CPU only), restoring the previous value in a finally."""
    sig = inspect.signature(fn)
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        bound = sig.bind(*args, **kwargs); bound.apply_defaults()
        resolved = _resolve_num_threads(bound.arguments.get("num_threads"))
        if resolved is None or bound.arguments.get("device", "cpu") != "cpu":
            return fn(*args, **kwargs)
        prev = torch.get_num_threads()
        torch.set_num_threads(resolved)
        try:
            return fn(*args, **kwargs)
        finally:
            torch.set_num_threads(prev)
    return wrapper
```

## 11. Decision rationale

1. **Default cap value = `max(1, min(8, os.cpu_count()))`.** *Why:* 8 is the project convention; the `min` guards small CPU pods (cpu-small = 2 vCPU) where a hard 8 would itself oversubscribe tiny ops. *Source:* #891 launch-prefix + #847 `env.py` setdefault + the #811 patch value (all 8); min-form precedents in-repo `scripts/issue825_fit_cells.py:1534`, `scripts/issue722_per_position_vC_skill.py:211`. *Alternative:* bare 8 (rejected — wrong on 2-vCPU pods).
2. **None resolves inside the fitters; opt-out sentinel `num_threads=0`; env override `EPS_VECTORIZED_FIT_DEFAULT_THREADS` (""/0 disables).** *Why:* no import-time global mutation; callers cannot forget the cap; escape hatch preserved. *Source:* the "0/empty disables" convention of `EPS_VM_THREAD_CAP` (#847, code-style.md § Shared-VM CPU thread caps). *Alternative:* module-level `torch.set_num_threads` at import (rejected — side effect on import, clobbers callers' own pins).
3. **`torch.set_num_threads`-only in the helper; NO env-var setdefaults inside it.** *Why:* torch freezes its intra-op pool from `OMP_NUM_THREADS` at import, so helper-side env mutation is moot for torch and bad library hygiene; `set_num_threads` is the effective post-import lever (demonstrated by the existing kwarg path + the #811 patch). numpy/BLAS env caps stay a launch-surface duty (#847/#891 + the new rule clause). *Source:* #847 task record ("torch sizes its intra-op pool from OMP_NUM_THREADS at import time; torch.set_num_threads works post-import"); torch docs `set_num_threads` (intra-op parallelism). *Alternative:* helper-side `os.environ.setdefault` (rejected — ineffective for torch, surprising global side effect).
4. **Restore-after-fit in a `finally` (for ALL calls, incl. explicit).** *Why:* library code should not leak global state; the in-module parity gate already models exactly this (l.736-741); on the shared VM the ambient pool is already 8 (#847 setdefault / #891 prefix) so restore is a no-op in the common case. Behavior delta for explicit callers is confined to code AFTER the fit call; grep shows callers wanting a process-wide pin set it themselves at module/main level (e.g. `issue763_fit_predictors.py:1610`), not via the fitter kwarg. *Source:* `vectorized_mlp_skill.py:736-741` (in-module precedent); caller grep (§Assumptions A5). *Alternative:* leave-set (rejected — leaks state; the historical behavior was incidental, not relied upon).
5. **Parity-gate preservation via explicit `num_threads=0` at in-module gate call sites.** *Why:* without it, the new default overrides the gate's deliberate 2-thread pin (l.731-734 measured 265 s @2 vs >480 s @8 on tiny ops) and changes the exact regime the parity numbers were calibrated in. *Source:* `vectorized_mlp_skill.py:731-741` + l.1492 comment ("thread count pinned: the asserted bit-identity contract"). *Alternative:* pass `num_threads=2` (equivalent here; 0 chosen because the wrapper OWNS the pin — self-documenting).
6. **Rule-clause location = fix item 7 (+ cross-refs in Supersede duty 1 / Mid-run trigger).** *Why:* item 7 already owns the detached-launch/choom/checkpoint contract and already cites #811; the two kill+relaunch surfaces are where relaunches are actually composed. *Source:* `.claude/rules/vectorize-many-cell-fits.md` fix item 7 + § Supersede contract + § Mid-run trigger (read in full). *Alternative:* editing SKILL.md § detached-launch (rejected — outside the Goal's named targets; the clause cross-references it).
