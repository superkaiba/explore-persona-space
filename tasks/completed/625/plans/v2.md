# Plan — Task #625 (infra): `scripts/verify_plan.py` — mechanical pre-pass gate for experiment plans at `/adversarial-planner` Phase 1.5

## 0.0 TL;DR (plain English)

- **What I'll build:** A small checker script that reads an experiment plan before any reviewer sees it and confirms the boilerplate that every plan must carry is actually there — a compute estimate the approval gate can parse, a source for every important training number, a statement of what is being measured and how, kill criteria, and so on. It is the plan-side sibling of the checker we already run on result write-ups.
- **What I expect:** Most structural gaps that today cost a full critic round (or worse, surface mid-run) get caught in under a second, and the expensive reviewers spend their rounds on substance instead of reminding the planner to add a missing line.
- **What would change my mind:** If running the checker against recently approved plans shows it would have wrongly bounced most of them over wording differences, the checks are too brittle for mechanical enforcement and the strict ones get demoted to warnings or dropped.

## §1. Goal

Build a deterministic, sub-second structural verifier for experiment plans, run at `/adversarial-planner` Phase 1.5, so that missing-required-block defects bounce back to the planner mechanically instead of consuming fact-checker/critic ensemble rounds (6+ agent spawns) or surfacing downstream as GPU-wasting gaps. Clean-result bodies already have this (`verify_task_body.py`, 17 checks); plans — the most expensive review site — have none. Literature basis carried from the task body: grounded mechanical verification beats free-form critique at any reviewer tier (Stechly & Kambhampati 2024, arXiv:2402.08115; McAleese et al. 2024, arXiv:2407.00215 — cited, not re-verified; internal-tooling precedent dominates this design).

### 3.2 Skeleton (reused verbatim from verify_task_body.py, adapted)

```python
@dataclass
class CheckResult:
    id: str            # NEW vs template: stable id, e.g. "c5_gpu_hours" (for --json + marker)
    name: str
    passed: bool
    detail: str = ""
    is_warn: bool = False
    skipped: bool = False   # NEW: kind-exempt / condition-not-triggered → render [SKIP]
```

- `split_frontmatter`, fence-aware `_headings(plan) -> list[(level, text, line_start, line_end)]` (extends `find_h2_sections` to H2+H3 — plans put required blocks at both levels), `section_text_by_keywords(plan, keywords) -> str | None` (case-insensitive substring match on heading text, first hit wins, returns heading + body slice).
- `EXEMPT_KINDS = {"analysis", "infra", "batch", "survey"}`.
- `CHECKS`: list of `callable(plan: str, kind: str) -> CheckResult`.
- `verify_plan_text(raw: str, *, kind: str, source: str = "") -> tuple[bool, list[CheckResult]]` — check 0 short-circuits on FAIL (one clear signal, mirroring the template's stub rationale).
- `main()`: mutually-exclusive `--issue <N>` / `--plan-file <path>`; plus `--kind {experiment,analysis,infra,batch,survey}` (file-mode override; ignored with a stderr note in issue-mode) and `--json`.
- Exit codes: 0 = PASS (WARNs allowed), 1 = ≥1 FAIL, 2 = resolution/IO error. WARN semantics: never blocks exit; the Phase 1.5.0 wiring carries WARNs forward into the fact-checker + critic briefs (that forwarding IS the "ships-if-acknowledged" mechanism for plans — unlike bodies, plans have a downstream human-grade review that weighs every WARN).

### 3.3 Plan + kind resolution for `--issue <N>`

```python
def _load_plan_for_issue(number: int) -> tuple[str, Path, str]:
    from explore_persona_space.task_workflow import find_task_path   # NEVER hand-built tasks/ paths
    folder = find_task_path(number)
    versions = sorted(folder.glob("plans/v*.md"),
                      key=lambda p: int(re.match(r"v(\d+)\.md$", p.name).group(1)))
    if not versions:
        raise FileNotFoundError(f"no plans/v*.md under {folder}")
    plan_path = versions[-1]                       # newest v{K} — NOT the plan.md symlink
    fm, _ = split_frontmatter((folder / "body.md").read_text())
    kind = str(fm.get("kind", "experiment"))       # missing kind → strictest (Step 0b gate guarantees presence anyway)
    return plan_path.read_text(), plan_path, kind
```

Rationale for newest-`v{K}` over the `plan.md` symlink: Phase 1.5 must verify the version the planner just wrote, and follow-up rounds re-point the symlink (the exact trap verify_task_body.py check 16 documents, incident #597). Numeric sort, not lexicographic (`v10` > `v9`).

### 3.4 The 10 checks — predicate, classification, kind-scope

A regex convention used throughout: `NA = r"(?i)\bN/?A\b\s*[—–-]+\s*"` (tolerant of em/en dash and hyphen). All scans run on fence-stripped text where noted (reuse the template's `_strip_fenced_blocks`), so example commands inside code fences can't satisfy or trip a check.

**Check 0 — plan-nonstub (FAIL, short-circuits; all kinds).** ≥1500 chars, ≥3 headings, no lone stub token (`placeholder|tbd|todo|stub` as ~whole body). Defense against a contaminated/truncated handoff file (the #562 harness-trailer incident class).

**Check 1 — §11 hyperparameter `Source:` grounding (FAIL with WARN degradation; skip for EXEMPT_KINDS).** The contract (CLAUDE.md Critical Rule + planner.md §11): every load-bearing hyperparameter row carries a non-empty `Source:`, or the explicit `ungrounded — needs smoke-test`, or the section-level N/A. Pseudocode:

```python
def check_source_grounding(plan, kind):
    if kind in EXEMPT_KINDS:
        return SKIP("kind-exempt: analysis|infra|batch|survey train no model")
    sect = section_text_by_keywords(plan, ("decision rationale", "hyperparameter grounding",
                                           "decision grounding"))
    scope = sect if sect is not None else plan          # fall back to whole-plan scan
    if re.search(NA + r"no (model training|hyperparameters)", scope):
        return PASS("explicit N/A declared")
    sources    = re.findall(r"(?i)\bSource:\s*([^\n|]*)", strip_fences(scope))
    blank      = [s for s in sources if not s.strip() or s.strip().lower() in {"tbd", "?"}]
    ungrounded = [s for s in sources if "ungrounded" in s.lower()]
    if sect is None and not sources:
        return FAIL("no Decision Rationale/grounding section and zero `Source:` lines")
    if blank:
        return FAIL(f"{len(blank)} blank/TBD Source: line(s) — contract says never blank")
    if sect is None:
        return WARN(f"{len(sources)} Source: lines found but no recognizable §11 heading "
                    "(heading drift?) — fact-checker must locate them manually")
    if not sources:
        return FAIL("§11-style section present but contains zero Source: lines")
    return PASS(f"{len(sources)} Source: lines ({len(ungrounded)} marked ungrounded — "
                "fact-checker flags those for smoke-test)")
```

The semantic question — is each Source *correct*, does it *transfer* — remains the fact-checker's; this check only guarantees the fact-checker has something to verify.

**Check 2 — per-DV measurement validity (FAIL only when ALL signals absent; `kind: experiment` only).** Pseudocode:

```python
def check_measurement_validity(plan, kind):
    if kind != "experiment":
        return SKIP("kind-exempt")
    if re.search(NA + r"no behavioral construct", plan):
        return PASS("explicit N/A declared")
    heading = any("measurement validity" in h.lower() for _, h, *_ in _headings(plan))
    # table-form signal: a table header row naming both construct and metric
    table = re.search(r"(?im)^\|(?=[^\n]*construct)(?=[^\n]*metric)[^\n]*\|\s*$", plan)
    phrase = re.search(r"(?i)measurement validity", plan)
    ondist = re.search(r"(?i)on-?distribution|on-?policy|teacher-?forced", plan)
    if heading or table:
        return PASS("measurement-validity block found"
                    + ("" if ondist else " (no on-distribution/on-policy statement spotted — verify)"))
    if phrase:
        return WARN("phrase present but no recognizable block/table — verify per-DV rows exist")
    return FAIL("no measurement-validity declaration (planner.md §6 required block)")
```

All three recent approved experiment plans (#614/#610/#613) carry a literal "Measurement validity" heading, so the FAIL branch is calibrated against reality.

**Check 3 — data-source tier (WARN-only; `kind: experiment` only).** Trigger-free presence check: PASS if fence-stripped plan matches `(?i)tier\s*[1-4]|real-world data|established (dataset|benchmark)|diverse llm[- ]generated|programmatic(ally)? generated|realistic-data preference`; else WARN ("no data-source tier named — CLAUDE.md realistic-data rule"). Detail-note (never a verdict change) when tier 3/4 vocabulary appears without a nearby `justif|absence|confound` token. WARN-only because the vocabulary is descriptive, not a pinned string contract.

**Check 4 — contrastive negatives (WARN-only, conditional; `kind: experiment` only).** Trigger: `(?i)\bimplant\w*\b` anywhere, OR (`marker` AND `persona` co-occurring), OR `behavior[- ]implantation`. Not triggered → SKIP("not detected as behavior-implantation"). Triggered: PASS if `(?i)contrastive negative` present (detail-note listing which of `panel|ratio|1:1|disjoint` tokens were also found), or the N/A line (`not a behavior-implantation`), or exemption vocabulary (`(?i)single manipulated variable IS contrastive|positive-only (parent|paper)|exemption \(?[ab]\)?`). Else WARN. WARN not FAIL: the trigger is a content heuristic, and the Methodology critic REVISEs the true positives anyway — the gate's job is to surface, not to adjudicate.

**Check 5 — GPU-hour estimate (FAIL; `kind: experiment` FAILs, exempt kinds degrade to WARN).** The one exact contract:

```python
GPU_RE = re.compile(r"(?i)estimated gpu-?hours \(total\):\**\s*`?([0-9]+(?:\.[0-9]+)?)`?")
m = GPU_RE.search(plan)
if not m:  -> FAIL (experiment) / WARN (exempt kinds: cap is moot at 0 but the line is still the contract)
line = the matched line; if re.search(r"[0-9]\s*[-–]\s*[0-9]", line after label): -> FAIL("range, not a single number")
else PASS(f"{m.group(1)} GPU-h")
```

Rationale for FAIL: a missing/unparseable line makes the Step 2c autonomous gate park (fail-safe in `task.py`, verified at line ~323), silently stalling an autonomous session — exactly the class of defect a mechanical gate exists for.

**Check 6 — reused-artifact fitness attestation (WARN-only, conditional; `kind: experiment` only).** Pseudocode:

```python
def check_reuse_fitness(plan, kind):
    if kind != "experiment":
        return SKIP("kind-exempt")
    text = strip_fences(plan)
    # trigger: reuse vocabulary co-located with an HF artifact reference, or an explicit reuse heading
    hf_hits = [m.start() for m in re.finditer(r"superkaiba1/|adapter_config\.json|hf_hub_download", text)]
    reuse_near_hf = any(re.search(r"(?i)\breus\w*", text[max(0, i-300):i+300]) for i in hf_hits)
    reuse_heading = any(re.search(r"(?i)reuse|reused[- ]artifact", h) for _, h, *_ in _headings(plan))
    if not (reuse_near_hf or reuse_heading):
        return SKIP("no HF-artifact reuse detected")
    if re.search(NA + r"no (artifact )?reuse", text):
        return PASS("explicit no-reuse declaration")
    fitness = re.search(r"(?i)fitness", text)
    letters = len({m.group(1) for m in re.finditer(r"\(([a-g])\)", text)})
    if fitness and letters >= 4:
        return PASS(f"fitness check present ({letters}/7 lettered items spotted)")
    if fitness:
        return WARN("fitness vocabulary present but <4 of the (a)–(g) items detectable — "
                    "verify all seven attestations (recipe/regime/cells/single-var/retraction/"
                    "content-identity/scaling) before approval")
    return WARN("plan reuses HF artifacts but no fitness check found — CLAUDE.md reuse rule "
                "requires attestations (a)–(g); consistency-checker + Methodology critic must gate this")
```

WARN not FAIL: trigger and item-detection are both heuristic, and #503/#545/#600/#601 show the failure modes are semantic (wrong expectation source, scaling gauge) that no regex adjudicates — the gate's value is forcing the section to exist and naming the seven letters.

**Check 7 — replication fidelity (WARN-only, conditional; `kind: experiment` only).** Trigger: `(?i)replicat` in the Goal section (located via `section_text_by_keywords(plan, ("goal",))`, falling back to frontmatter-style `goal:` line in the plan header if present). Not triggered → SKIP. Triggered: PASS if `(?i)not a replication` (the N/A form) or replication-fidelity vocabulary (`(?i)paper'?s (data|recipe|corpus)|faithful|replication[- ]fidelity|deviation`) present; else WARN. WARN because "does the effect replicate across seeds" is a benign false trigger.

**Check 8 — success + kill criteria (FAIL when both families absent; `kind: experiment` FAILs, exempt kinds WARN).** Two vocabulary families scanned over fence-stripped headings+bold-labels+prose: `SUCCESS = (?i)success criteri|acceptance criteri|decision rule|decision gate`; `KILL = (?i)kill criteri|abort criteri|stop criteri|kill-criterion|halt-and-report|what would change my mind`. Both → PASS; exactly one → WARN naming the missing family; neither → FAIL. **Calibration reality (fact-checked):** the narrower 4-token KILL family matches 0 of {#614 v2, #613 v1} — those plans phrase the falsification side as `## 7. Decision Gates` + the §0.0 `What would change my mind` line; the widened family above (which includes the §0.0 TL;DR's canonical "What would change my mind" phrasing from planner.md §0.0) is expected to PASS all three calibration plans, with the implementer confirming during the calibration run. "Non-contradictory in form" is operationalized as both present and each carrier section/paragraph ≥ 80 chars (emptiness check only — semantic joint-satisfiability stays with the Statistics critic per planner.md §7, which the check detail cites). The `No gates — short run / pre-verified hypothesis` escape satisfies neither family by itself (it waives *gates*, not success/kill criteria) but is mentioned in the WARN detail so the planner knows the distinction.

**Check 9 — conditions/cells table + seeds (WARN-only; `kind: experiment` only).** Conditions signal: a heading matching `(?i)conditions|cells|arms` OR a table header row containing `(?i)config slug|what it tests`. Seeds signal: `(?i)\bseeds?\b` anywhere. Both → PASS; missing one/both → WARN naming which (this is the consistency-checker's input surface; a WARN tells the orchestrator the consistency-checker will be flying partially blind).

**Check 10 — marker-recipe acknowledgment (WARN-only, conditional; `kind: experiment` only).** Trigger: `※` or `83399` or `(?i)marker[- ]leakage|log ?p\(marker\)|markeronlydatacollator`. Not triggered → SKIP. Triggered: PASS requires (`marker-training-recipe` filename reference OR `(?i)band-?stop` OR `\[5,\s*12\]\s*nat`) AND `(?i)bystander`; one of the two → WARN naming the gap; neither → WARN ("marker experiment with no recipe acknowledgment — read `.claude/rules/marker-training-recipe.md` + `marker-leakage-measurement.md` before grounding the stopping recipe; incident #530/#480 class").

### 3.5 `--json` mode

```json
{"source": "<path>", "issue": 614, "kind": "experiment", "overall": "PASS",
 "n_fail": 0, "n_warn": 2, "n_skip": 3,
 "checks": [{"id": "c1_source_grounding", "name": "...", "status": "PASS", "detail": "..."}, ...]}
```

`status ∈ {PASS, WARN, FAIL, SKIP}`. The orchestrator pipes this into the marker note and the bounce brief. Human mode keeps the template's `[TAG] name — detail` lines + `OVERALL: PASS|FAIL (n of m)` footer.

### 3.6 Why code, not a model call?

Required by §4 convention: (a) alternative considered — a single Haiku call grading the plan against a checklist; (b) code preferred because the task body bans LLM calls explicitly, the gate must be deterministic (same plan → same verdict, no flaky bounces), free (runs on every plan revision), and the LLM-grade review already exists downstream (fact-checker + 6 critics) — this gate exists precisely to be the cheap deterministic layer under them; (c) what would flip it: if calibration showed the required blocks are too lexically diverse for regex (>50% spurious FAILs unfixable by predicate adjustment — the kill criterion), the right fallback is a Haiku-based pre-pass, which would then need its own determinism/cost story.

Who posts the marker: **the orchestrator running the adversarial-planner skill**, not the script. Justification: mirrors `verify_task_body.py` (side-effect-free script, separately invocable for dry runs and tests); keeps the script importable in tests without marker stubs; and the skill is the layer that knows `<N>` and the bounce outcome (`PASS-with-override` is orchestrator judgment, unrepresentable inside the script). VM-side `task.py` use is fine — the pod-side shellout ban does not apply to planning, which never runs on pods.

Ordering note ("alongside the fact-checker"): the script runs in <1s, so it runs strictly BEFORE the fact-checker spawn — a structurally broken plan shouldn't burn a fact-checker agent either. This satisfies the body's binding requirement (FAIL bounces before the critic ensemble) and strengthens it.
