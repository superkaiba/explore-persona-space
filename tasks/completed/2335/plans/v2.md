## Exact entry text (verbatim insertion into `.claude/rules/gotchas.md`, a non-ratcheted rule file)

```markdown
- **RunPod host driver vs CUDA-major wheel mismatch — a fresh-venv vLLM/torch install on a pod whose HOST driver is an older datacenter branch (570.x = CUDA 12.8 max) dies at engine init with `The NVIDIA driver on your system is too old (found version 12080)`; the fix is the NVIDIA forward-compat package, NOT a wheel downgrade.** Modern wheel stacks are CUDA-13-built — `vllm==0.27.1` pins `torch==2.13.0`, which ships ONLY cu129/cu130 wheels, and the vllm PyPI wheel itself links `libcudart.so.13` — so BOTH downgrade rungs are dead: `--torch-backend=cu128` (no such wheel exists for torch>=2.13) and cu129 (torch inits, but the vllm extension still needs `libcudart.so.13`). VERIFIED 3-step fix (#2330 crash-fix round 1, driver 570.195.03, 2× H200): (1) `apt-get install -y cuda-compat-13-0` (available in the pod image's apt repo; installs `/usr/local/cuda-13.0/compat/libcuda.so.580.x`); (2) `export LD_LIBRARY_PATH=/usr/local/cuda-13.0/compat:$LD_LIBRARY_PATH` in the LAUNCHER env (every venv leg — a leg without it re-hits the init failure); (3) keep the wheel stack native (torch cu130 + vllm cu13) — recipe otherwise unchanged. Verified end-to-end: CUDA init + vLLM 0.27.1 import + engine bring-up on driver 570; a supported combo per NVIDIA forward-compat docs (datacenter GPUs, r525+ base branches). DISCRIMINATOR (check BEFORE building a fresh venv on any pod): `nvidia-smi --query-gpu=driver_version --format=csv,noheader` — a pre-580 driver (e.g. 570.x) under a CUDA-13 wheel stack ⇒ install cuda-compat up front rather than debugging the engine-init failure after.
```
