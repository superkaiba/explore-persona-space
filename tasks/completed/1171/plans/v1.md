## 11. Decision Rationale (design choices — `N/A — no model training` for hyperparameters)

1. **Which H2 titles re-enter the strip: exactly `{"data", "methodology"}`.**
   *Why:* v3 mandates verbatim examples under `## Data` (existing behavior); v4 mandates them under `## Methodology` → `**Sample training/evaluation data + completions:**` and nowhere else (`## Results` may carry at most one ≤10-line raw excerpt, which the spec does NOT require to be `<details>`-wrapped and which SHOULD stay scanned — SPEC.md lines 603-607).
   *Source:* SPEC.md lines 414-418 ("Wrap example rows/completions in `<details>` or a fenced code block"), 539-545, 697-703 (dashboard contract: "each example block is wrapped in a `<details>` element or a fenced code block"); audit script lines 506-531 (v3 rationale).
   *Alternatives:* prefix/substring H2 match (rejected — looser than the existing exact-equality mirror, could catch unforeseen headings); adding `## Results` (rejected — Results excerpts are authored-adjacent and Lens/spec keep them minimal; no incident motivates it).
2. **Category scope: ALL categories via the one shared strip (the minimal mirror).**
   *Why:* every scan source flows through `strip_data_example_blocks` (audit script lines 727/740/745), so the shared strip is both the smallest diff and the exact mechanism the v3 exemption already uses category-globally; §3 enumerates all 16 categories and finds none needing Methodology-details scanning.
   *Source:* audit script `audit_body` lines 725-758; sibling candidate in the task body ("ALL scan categories (mirror the existing ## Data mechanism)").
   *Alternatives:* per-category opt-in source (rejected as over-engineering; kept as the §8 kill-criterion contingency).
3. **Not gated on the `<!-- clean-result-v4 -->` sentinel.**
   *Why:* a spec-conforming v3 body cannot carry a `## Methodology` H2 (stray content H2 = `verify_task_body.py` hard FAIL), so gating buys nothing on conforming bodies; it would cost a signature change (`body` threaded into the strip at 2 call sites) and duplicate sentinel logic. For NON-conforming bodies the ungated behavior degrades in the conservative-for-the-author direction only for `<details>` content under a heading named Methodology — by construction an example dropdown.
   *Source:* CLAUDE.md § Experiment Report Structure ("a stray v3 content H2 ... is a hard FAIL"); `_restrict_pre_reg_to_prose_sections` (lines 630-633) shows the sentinel-gated alternative's shape and cost.
   *Alternatives:* sentinel-gated v4 branch (rejected per above).
4. **Keep the function name `strip_data_example_blocks`; rename only the local `in_data` → `in_exempt_section`.**
   *Why:* the name still describes the job (stripping data-example blocks); renaming would churn 2 call sites, the test module, and two `verify_task_body.py` doc-comments for zero behavior value.
   *Source:* grep sweep in §4.
5. **Test shape: fixture-mutation on `V4_BODY_CLEAN` with `body != fixture` guards; offenders on plain non-table non-fenced lines.**
   *Why:* inherits the #969 convention verbatim; plain-line placement ensures each offender is masked ONLY by the new exemption (not by `_blank_table_rows` or the global fence strip), so test (a) is a genuine red/green discriminator.
   *Source:* `tests/test_audit_clean_results_body_discipline.py` lines 816-1005 (#969's cluster); `_TABLE_CELL_EXEMPT_CATEGORIES` (audit script line 373).
