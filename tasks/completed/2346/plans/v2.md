## Goal (from task body)

`.claude/rules/gotchas.md` directs agents to use `os.posix_fallocate` to detect the RunPod
MooseFS per-pod quota, but carries no warning that an INTERRUPTED probe leaks its entire
allocation. Add that warning plus the safe form. Incident #2329 (2026-08-17): an ad-hoc 15 GiB
probe was SIGTERMed at timeout (exit 143); Python `finally:` does not run under SIGTERM, so the
probe file survived at 12,864 MB on a live 8×H100 pod, consuming the very quota headroom it was
measuring.

## Audit finding (grounds the code changes)

`orchestrate/preflight.py::_probe_writable_bytes` (lines 763-796) cleans up via a `finally:`
unlink — the exact construct the incident proved non-signal-safe. Mitigating factors: the probe
is a small canary (~1-2 GB, `probe_bytes`), uniquified per invocation
(`.preflight_disk_probe.<pid>.<uuid8>.tmp`, #1979). Aggravating factor: per #2333 the 1 GB
canary can grind ~9 min on MooseFS FUSE (glibc per-block write emulation), so a timeout-kill
mid-probe is realistic — and each kill leaks a ~1 GB survivor that ACCUMULATES (unique names
mean no overwrite-on-retry). Same shape in the sibling sanctioned probe
`scripts/pod_disk_guard.py::probe_quota_headroom` (`.pod_disk_guard_probe.<pid>.<uuid8>.tmp`,
#1983). Verdict: NOT strictly signal-safe → take the acceptance criterion's "or fixed" branch
with a survivor sweep (proposed-fix bullet (d), implemented at the sanctioned probes themselves).

## Changes

1. **`.claude/rules/gotchas.md`** — extend the MooseFS EDQUOT / fallocate-probe entry block
   (the ~line-57 EDQUOT entry + its ~line-58 EBADF probe sibling) with ONE new concise bullet
   (byte budget #2189: keep ≤ ~15 lines) carrying the four sub-points from the task body:
   (a) keep ad-hoc probes SMALL (~1 GiB) and extrapolate — a 1 GiB probe returned in under a
   second on the same pod (#2329), the 15 GiB one never returned; (b) a probe that must be
   large wraps cleanup so it survives the signal — shell `trap 'rm -f "$F"' EXIT INT TERM`,
   never Python `finally:` (does not run under SIGTERM/SIGKILL); (c) prefer CONTINUOUS
   observation (`du -sBM` on the out-root at each heartbeat) over a one-shot upfront probe — a
   probe passing at hour 0 says nothing about hour 5; (d) after ANY interrupted probe
   (non-zero/signal exit), `ls` the probe path and remove a survivor before continuing — treat
   the leak as the default outcome. Cite #2329 + the 12,864 MB figure.

2. **`orchestrate/preflight.py::_probe_writable_bytes`** — at probe entry, sweep stale sibling
   probe files in the resolved probe dir: files matching `.preflight_disk_probe.<pid>.<uuid8>.tmp`
   whose embedded pid is DEAD (`os.kill(pid, 0)` → `ProcessLookupError`). Live-pid files are
   kept (a concurrent worker's in-flight probe, #1979 — deleting one recreates the EBADF race
   the unique names fixed); unparseable names skipped; the whole sweep is fail-soft
   (`contextlib.suppress(OSError)` per file — a sweep error can never fail the probe).
   No change to the probe's PASS/FAIL logic or fallback contract (acceptance 3).

3. **`scripts/pod_disk_guard.py::probe_quota_headroom`** — the same dead-pid survivor sweep for
   `.pod_disk_guard_probe.<pid>.<uuid8>.tmp` (the pod-side sanctioned probe; #2329 was
   pod-side). Prefer one shared helper if import topology allows (pod_disk_guard runs pod-side
   where `explore_persona_space` is importable from `/workspace` — verify at implementation;
   if fragile, duplicate the ~15-line sweep with a cross-reference comment).

4. **Tests** — extend the existing pin suites `tests/test_preflight_disk.py` +
   `tests/test_pod_disk_guard.py`: (i) a stale dead-pid probe file in the probe dir is removed
   at probe entry; (ii) a live-pid (own-pid) file is KEPT; (iii) malformed/foreign names are
   untouched; (iv) a sweep-side OSError does not break the probe (probe still returns its
   normal verdict); (v) existing behavior tests stay green (PASS/FAIL semantics unchanged).

**Out of scope:** the frozen per-issue sibling canaries (`scripts/issue1481_marker.py`,
`scripts/run_experiment_389.py` — historical reproducibility artifacts, per the gotchas.md
entry they are named as canaries only); adding signal handlers inside library code (mutating
process-global signal state from a probe helper is worse than the leak); any change to
preflight verdict semantics.
