## 3. Method delta + kill criteria

**Delta vs current text:** every surface that today says "EXECUTE every deferred import / verify imports resolve via (a)/(b)/(c)" gains one leg: *fenced calls to imported helpers must also BIND*. Key design points the delta encodes:

1. **Hoisting does not discharge the bind leg.** Option (b) module-top hoisting fixes the ImportError class only; the #1332 calls TypeError regardless of import position. The new text says "either way" / "hoisting does NOT discharge this leg" explicitly.
2. **Bind ALL call sites of each fenced helper rather than statically detecting fencing.** The skip-flag is a runtime value; static fence detection is fragile. The sound cheap superset — bind every call site of each helper that the fenced-branch grep (code-reviewer.md's existing `grep -nE` recipe) or the deferred-import list surfaces — is what the #1332 pin test does (all `verify_repo_paths_uploaded` sites in the file).
3. **Shapes, not values.** `len(call.args)` placeholder positionals + `keyword` names; catches the TypeError arity/keyword class only. No type/value validation claimed.
4. **Honest degradations:** `sig.bind_partial(...)` when the call site forwards `*args`/`**kwargs` (catches unknown keywords + excess positionals; missing-required is statically unjudgeable there); skip-with-note when `inspect.signature` raises `ValueError` (C builtins/extension callables) or when a bare callee name resolves ambiguously across two imports; a decorator without `functools.wraps` exposes `(*args, **kwargs)` and binds trivially (silent no-op, acceptable).

## 11. Decision Rationale

D1 — **Documented recipe, NOT a new shared script.**
- What: the bind leg ships as prose guidance; the per-issue sweep (implemented by each issue's dispatcher, like `--verify-imports`) adds ~10 lines following the recipe.
- Why: matches the established pattern (the import sweep itself was never a shared script — the docs cite a commit-pinned per-issue worked example); a generic shared binder needs per-issue scope/sys.path/name-resolution config anyway, and its edge-case surface (starred args, attribute chains, decorators, name collisions) is trivial when scoped per issue but maintenance-bearing when generic.
- Source: existing doc structure (experiment-implementer.md step 2 + gotchas.md L203 both cite `i606_dispatch.py` by commit); #1332 r2's per-issue implementation (`e84547e1ef`) took exactly this shape.
- Alternatives: a shared `scripts/verify_bindings.py` (deferred — legitimate future hardening once ≥2 more issues hand-roll the pattern); a `workflow_lint` check (wrong layer — lint runs on the workflow surface, not per-issue experiment scripts).

D2 — **Bind failures classify under the EXISTING `substantive` blocker tag.**
- What: no new mechanical blocker tag; the reviewer Critical for a non-binding fenced call reuses the tag the unresolvable-import Critical already carries.
- Why: adding a tag changes the reviewer public contract (the Step 5c-bis strip list) and would push toward `architectural: true`.
- Source: #853 plan §11 (explicitly rejected a new `deferred-import` tag on the same reasoning); code-reviewer.md's existing "blocker tag `substantive`, NOT `smoke-run-missing`" framing.
- Alternatives: new `bind-failure` tag — rejected (contract change, no benefit: the strip logic cannot verify binds from markers anyway).

D3 — **Full mechanics in gotchas.md; pointers everywhere else.**
- What: the one-line-bullet at L203 carries the complete recipe (bind expression, bind_partial degradation, skip-with-note cases, worked example); the agent files carry the duty + summary + pointer.
- Why: that is the existing topology — both agent surfaces already say "Full trap: gotchas.md" — and single-sourcing the mechanics is the drift defense (Risk table row 2).

- Alternatives: duplicate the full recipe in each agent file — rejected (guaranteed drift; these files are already long).

D4 — **Bind ALL call sites of fenced helpers; no static fence detection.**
- What: the recipe binds every call site of each helper surfaced by the deferred-import list or the fenced-branch grep, rather than trying to statically decide which `ast.Call` is inside a fenced branch.
- Why: the fence is a runtime flag; static detection is fragile and under-inclusive. Binding unfenced sites too is free and strictly safer.
- Source: `tests/test_issue1332_pins.py` @ `e84547e1ef` binds all `verify_repo_paths_uploaded` sites in the file; incident evidence that this catches the target class (2/2).
- Alternatives: AST detection of `if args.skip_upload:`-style fences — rejected (misses `not smoke`, helper-function indirection, negated flags).

D5 — **`bind` vs `bind_partial` split + skip-with-note escapes.**
- What: full `bind` when the call site has no starred/doublestar forwarding; `bind_partial` otherwise; skip-with-note on `inspect.signature` `ValueError` (C builtins) and ambiguous bare-name resolution; decorated helpers without `functools.wraps` bind trivially (accepted silent no-op).
- Why: these are the exact stdlib semantics — full `bind` on a `**kwargs`-forwarding site would FALSE-FAIL (a required kwarg may arrive via the forward); `bind_partial` still catches unknown keywords + excess positionals.
- Source: Python stdlib `inspect` semantics (verified live this session — the trace output in §10); the #1332 pin's `ast.Starred` assert.
- Alternatives: always `bind_partial` — rejected (loses missing-required detection on the common fully-static call sites, which is precisely what caught #1332).
