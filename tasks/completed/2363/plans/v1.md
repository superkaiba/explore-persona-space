Module-level compiled patterns (names final, bodies tunable under the calibration protocol):

```python
# c73 — §7 binding to an optionality-marked phase (#2363, incident #2360 v2).
_C73_PHASE_ID_RE = re.compile(r"(?i)\bphase[-\s]+([0-9]{1,2}|[ivxl]{1,4}|[a-z])\b")
_C73_OPTIONAL_RE = re.compile(
    r"(?i)\boptional\b|\bif time permits\b|\bnice[-\s]to[-\s]have\b"
    r"|\bstretch\s+(?:goal|phase)\b|\(stretch\)|\bbest[-\s]effort\b"
)
_C73_NEGATION_RE = re.compile(
    r"(?i)\brequired\b|\bnot optional\b|\bno longer optional\b"
    r"|\bwas\s+[\"“']?optional|\bstruck\b|\bmandatory\b"
)
_C73_GATES_HEADING_RE = re.compile(
    r"(?i)\bdecision gates?\b|\bkill criteri|\bacceptance criteria\b|\bsuccess criteria\b"
)
```

Algorithm (mirrors c29's structure — trigger → escape → sections → windows):

1. `lines = plan.splitlines()`, `mask = _fence_mask(lines)`; compute gates sections =
   union of `_headings(plan)` spans whose heading text matches `_C73_GATES_HEADING_RE`
   (the `Heading.line..end` span). In #2360 v2 that captures `## 7. Decision Gates`; in infra plans
   it also captures a `Requirement & acceptance criteria` / `Kill criteria` heading.
2. **Anchor scan (declarations):** every non-fenced line OUTSIDE all gates sections where
   `_C73_PHASE_ID_RE` and `_C73_OPTIONAL_RE` both match the SAME line, the optionality hit sits
   within **80 chars after the phase-id match start** (the declaration idiom is
   `Phase V (optional …) — …`; the proximity bound is what keeps "…Phase II runs first. Optional
   columns…" from anchoring), and `_C73_NEGATION_RE` does NOT match the line. Collect the phase ids
   (normalized: upper-cased id token). No anchors → SKIP
   ("no optionality-marked phase declaration detected").
3. **Escape:** `_standalone_na_declared(plan, r"no acceptance binding to an optional phase\b")`
   → PASS ("explicit N/A declared…"). This is the sanctioned remedy when a gates-section mention of
   the optional phase is genuinely informational, not a binding.
4. No gates section found → SKIP ("no Decision-Gates/acceptance/kill section detected").
5. **Binding scan:** for each anchored phase id P, scan non-fenced lines INSIDE the gates sections
   for a reference `re.compile(rf"(?i)\bphase[-\s]{{1,2}}{re.escape(P)}\b")` — accepts BOTH
   `Phase V` and `Phase-V` (the #2360 v2 hyphenated form; §12 A3). Hits → collect
   `(P, decl_line_no, first_binding_line)`.
6. Any hit → **WARN** with detail: per offending phase, the phase id, the declaration line number +
   first ~90 chars, the first binding line number + first ~120 chars, and the two remedies
   ("strike the optionality marker (the #2360 v3 resolution) or decouple the criterion; a genuinely
   informational §7 mention declares the standalone escape `N/A — no acceptance binding to an
   optional phase`"). No hit → PASS ("optionality-marked phase(s) {ids} referenced by no
   gates-section line").

### D2 — Honest-scope gaps (documented in the docstring, pinned by tests where cheap)

- A phase marked optional only in prose WITHOUT a `Phase <ID>` token on the same line (e.g. "the
  pod validation is optional") is invisible → SKIP. Same class as c29's prose-only-fence gap.
- An optionality marker inside a gates-section row ITSELF (no marked declaration elsewhere) does
  NOT anchor — declarations are keyed outside gates sections, both to avoid self-triggering on
  remedy quotes and because "§7 row says optional" is a different defect (an optional criterion).
  Pinned by a test; the LENS item (D5) covers the semantic residue.
- Named phases (`Phase extract`) don't anchor — id grammar is digits/roman/single letter, bounding
  FPs. Calibration may widen later.
- Whether a gates-section mention is genuinely a BINDING (vs narration) is semantic → the lens item
  + the escape phrase own it. WARN-only makes the residual cost one line of reviewer attention.

**Smoke blind-spot enumeration:** none — smoke executes every production gate (the check has no
smoke-conditional branch; tests call the production function directly and the calibration scan runs
the production code path over real corpus files).
