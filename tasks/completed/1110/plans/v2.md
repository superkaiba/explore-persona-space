### 3b. The check — `scripts/verify_task_body.py`

Place immediately after `check_title_confidence` (after line ~1357, before `check_required_sections`), reusing the same H1-extraction convention (`find_h1_title`, line 863 — first `# `-prefixed, non-`## ` line, stripped):

```python
def check_h1_matches_frontmatter_title(body: str, fm: dict) -> CheckResult:
    """The H1 headline and the frontmatter `title` must agree
    (whitespace-normalized) on sentinelled clean-result bodies.

    The title lives in two places — frontmatter via `task.py set-title`
    (feeds the dashboard LIST view + REGISTRY) and the body H1 via
    `set-body` (feeds the rendered DETAIL view). #825: a retitle without
    an H1 edit shipped a stale headline through a full critic round.
    Severity: FAIL on v4 bodies; WARN on grandfathered v3/v2 (forward-only
    rule — 4 real v3/v2 bodies diverge today, incl. completed #432/#458);
    PASS-skip on non-sentinelled bodies (pre-promotion bodies legitimately
    have no synced H1) and on frontmatter-less input (draft / --body-stdin
    dry runs carry no fm to compare).
    """
    name = "H1 matches frontmatter title"
    v4 = is_v4(body)
    sentinelled = v4 or is_v3(body) or is_v2_nested_design(body)
    if not sentinelled:
        return CheckResult(name, True, "not a sentinelled clean-result body — skipped")
    if not fm:
        return CheckResult(
            name, True,
            "no frontmatter in input (draft / --body-stdin invocation) — "
            "skipped; the gate-time --issue run compares against the real body.md",
        )
    warn_only = not v4  # forward-only: v3/v2 grandfathered to WARN

    def _flag(detail: str) -> CheckResult:
        if warn_only:
            return CheckResult(name, True, detail + " [grandfathered v3/v2 — WARN]", is_warn=True)
        return CheckResult(name, False, detail)

    title = fm.get("title")
    if title is None:
        return _flag(
            "sentinelled clean-result body has no frontmatter `title` — "
            "run `task.py set-title <N> \"<H1 text>\"`"
        )
    h1 = find_h1_title(body)
    if h1 is None:
        return _flag("no H1 found — a sentinelled clean-result must open with `# <title>`")
    norm = lambda s: " ".join(str(s).split())  # noqa: E731
    if norm(h1) != norm(title):
        return _flag(
            f"H1 differs from frontmatter title (dashboard list shows the frontmatter "
            f"title; the body renders the H1) — H1: {h1[:90]!r} vs title: "
            f"{str(title)[:90]!r}. Sync via `task.py set-title <N> \"<H1 text>\"` "
            f"(the promote-skill convention, H1 canonical) or re-`set-body` with the "
            f"H1 edited if the frontmatter title is the fresher one."
        )
    return CheckResult(name, True, "H1 == frontmatter title (whitespace-normalized)")
```

Notes:
- Sentinel detection reuses `is_v4` / `is_v3` / `is_v2_nested_design` (lines 2390–2465), which are fence-aware + `<details>`-aware via `_prose_layer` — a body merely *quoting* a sentinel in a code fence is not misdetected. We inherit that for free.
- The confidence tag `(HIGH|MODERATE|LOW confidence)` is part of **both** strings by convention (confirmed empirically on all 162 matches and in analyzer.md:435) — compared verbatim, no special handling. A frontmatter title lacking the tag while the H1 has it (the #654 shape) correctly FAILs/WARNs as a divergence.
- No markdown-formatting stripping: the 162 matching bodies match on raw text, so any backticks/bold present are identical in both places; stripping would only mask divergence.
- Fail-fast discipline: the two anomaly sub-cases (missing fm `title`, missing H1) flag loudly at the same severity as a mismatch rather than silently passing. The missing-H1 case double-reports with `check_title_confidence`'s "no H1 found" — acceptable; both point at the same root cause with distinct remediation text.

## 11. Decision Rationale

`N/A — no training hyperparameters` (kind: infra; no model training). Design decisions:

- **D1 — Normalization = whitespace collapse only (`" ".join(s.split())`), case-sensitive, no Unicode/punctuation folding.**
  *Why:* the 162 true positives match exactly under whitespace collapse (zero false-positive risk measured), and every observed non-whitespace difference (#763's `ρ`/`–` vs `rho`/`-`, #458's `—` vs `,`, #664's dropped article) is a *genuine* sync failure the check exists to flag — folding would hide the exact drift class. *Source:* the planning survey (A4). *Alternatives:* NFKC/casefold normalization (rejected: masks #763-class drift, no measured false positive to justify it); exact raw equality (rejected: trailing-whitespace noise from editors would false-positive with zero informational value).
- **D2 — Severity: FAIL on v4, WARN on v3/v2, PASS-skip otherwise.**
  *Why:* the project's forward-only rule ("v3-sentinel, v2-sentinel … bodies keep their prior verification behavior verbatim and are NEVER newly hard-FAILed") + 4 measured grandfathered divergences, 2 on *completed* bodies including the canonical v2 exemplar #432. WARN keeps the drift loud without retro-breaking. Every NEW clean-result is v4, so the Goal's "FAILing" teeth bind everywhere it matters — including the #825 catch point (the clean-result-critic's mechanical `verify_task_body.py` pre-pass at gate time). *Source:* CLAUDE.md § Experiment Report Structure (forward-only clause); survey A4. *Alternatives:* FAIL on all sentinelled (rejected: violates forward-only, breaks 4 grandfathered bodies); WARN everywhere (rejected: fails the Goal's explicit "FAILing" requirement and repeats #825 — a WARN doesn't block the analyzer gate).
- **D3 — DEFER the `set-title` H1-sync mutator leg (verifier check only in v1).**
  *Why:* (i) the check alone closes the #825 gap — the analyzer/critic gate re-runs `verify_task_body.py --issue N` after set-body+set-title, and a FAIL bounces the round mechanically; (ii) sync-by-default is unsafe across current callers: issue-v2 SKILL.md:424 calls `set-title "Experiment: <question>"` while the body is still the spec/report (rewriting that H1 is wrong), and the paper-stub path (issue SKILL.md:4846) would rename a paper title as a side effect; (iii) a sync-by-flag with no caller adopting it is dead scope, and adoption would mean editing analyzer.md/SKILL.md — beyond the minimal fix. Verifier-only is the correct v1; if divergences keep recurring at gates despite the FAIL, a follow-up candidate can add `set-title --sync-h1` with per-caller adoption. *Source:* call-site grep (A12) + #825 mechanics. *Alternatives:* sync-by-default (rejected: order/semantics hazards above); sync-by-flag now (rejected: unused scope, weaker than the gate FAIL it duplicates).
- **D4 — Missing fm `title` / missing H1 on a sentinelled body = same severity as mismatch (loud), not a silent skip; empty fm ({}) = PASS-skip.**
  *Why:* fail-fast constraint — a sentinelled clean-result without a title in either place is a broken promotion; but a frontmatter-*less* input is a legitimate draft/stdin dry-run shape (breaking analyzer dry runs would be a false positive on the workflow itself). All 169 live sentinelled bodies have fm titles, so the FAIL branch is anomaly-only. *Source:* survey A4 + `_load_text_for_issue`/draft-flow reads (A9). *Alternatives:* FAIL on empty fm too (rejected: breaks body-only dry-run invocations that are correct by design).
- **D5 — Reuse `find_h1_title` (line 863) as the H1 extraction, matching `check_title_confidence`.**
  *Why:* one extraction convention per file; divergent extraction rules would let the two title checks disagree about which line is "the H1". Setext (`===`) H1s are not handled by the existing convention and appear in zero live sentinelled bodies — out of scope. *Source:* code read (A1) + survey. *Alternatives:* new regex (rejected: duplication).
