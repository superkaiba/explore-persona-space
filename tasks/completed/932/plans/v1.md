## 0.0 TL;DR (plain English)

- **What I'll build:** a new advisory check in the plan verifier. When a plan promises "this fix fails loudly / nothing gets silently swallowed" in its acceptance criteria but never names an actual test that pins that behavior, the verifier prints a warning asking for one.

## 2. Method delta (vs the closest sibling, c11)

c11 (`check_dryrun_test_coverage`, verify_plan.py:1003-1032) is the template: kind infra|batch, conditional trigger, line-level test-identifier evidence, one N/A escape, WARN citing incidents. c14 differs in four deliberate ways:

1. **Trigger is a section-scoped prose claim, not a raw CLI token.** c11's trigger (`--dry-run` anywhere in the RAW plan) works because the token is a command flag. Fail-loud vocabulary is project mantra prose ("Fail fast — never hide failures" is quoted in CLAUDE.md and echoed everywhere): a whole-plan raw scan would fire on 36%+ of infra plans via rule-quoting and bug-narration. c14 therefore anchors on acceptance/success-criteria mentions and scans a bounded fence-stripped window (§4.2), measured to cut noise classes (risk tables anchored via "decision gate", Plan-Summary restatements, H1-preamble carriers) while keeping every genuine hit in the probe sample.
2. **Evidence excludes grep-command lines instead of stripping a flag.** c11 strips `--dry-run` from a line before the test-ident scan so the smoke command can't self-certify. c14's analogous self-certification hazard is a run-book grep gate that greps a *test file* for exception vocabulary (`grep -n 'except Exception' tests/test_foo.py` — a `test_` ident + vocab on one line). Any line containing the word `grep` is excluded from evidence — grep gates are precisely the verification form the check exists to distrust (#913 origin quote).
3. **Two N/A escapes, not one.** The corpus shows two legitimate escape situations: incidental vocabulary (bug-narration inside a Goal+acceptance section, e.g. #871), and doc-file targets where no pytest can exercise the "flag loudly" instruction (e.g. #788, #856 — `.md`-only workflow fixes). One phrase each (§4.4).
4. **A paired human-lens mirror is part of the fix, not optional garnish.** Ground-truth replay: #913 **v1** — the motivating incident — *passes* the mechanical evidence heuristic, because v1 already named `test_length_mismatch_raises` for its length-mismatch claim while the *caller-level swallow ban* rested on a grep gate alone. Per-claim coverage matching is beyond deterministic regex at acceptable FP rates (it is a semantic pairing judgment). So the mechanical check catches the zero-fail-loud-test case (25/230 = 11% of historical infra|batch plans — real, common), and Statistics lens item 14 instructs the critic ensemble to check **each** fail-loud claim for its own committed pin — exactly the judgment the Codex twin made organically on #913. Both layers ship in this task.

## 3. Design decisions (the seven brief questions, answered)

**Q1 Trigger heuristic.** Anchor regex `(?i)acceptance criteri|success criteri` on fence-masked lines — deliberately NARROWER than c8's `_SUCCESS_RE` (verify_plan.py:163), which also matches "decision rule|decision gate": probe1 showed gates/failure-mode sections contribute risk-table noise (#673 "GCP eval lane silently provisioned" — a failure-mode *description*, not an acceptance claim). From each anchor line `i`, the claim scan covers `strip_fences("\n".join(lines[i : min(section_end, i+31)]))` where `section_end` is the innermost section's end (c8's `_innermost_section` machinery, :353). Anchors are dropped when the innermost section is `None`, has `level < 2` (H1/preamble carriers — probe1's #758/#759-preamble noise), or its heading matches `(?i)tl;dr|plan summary|^(?:§\s*)?0(?:\.0)?\b` (the §0.0 TL;DR "What would change my mind" and §0 Plan Summary restate criteria as summary prose — same rationale as c8's `_tldr_ranges` exclusion, :820-829). **Fence handling: trigger fence-stripped, evidence RAW** — a fenced block in an acceptance section is quoted implementation (a diff hunk containing `raise ValueError` is not a claim), mirroring c8's `strip_fences` carrier logic; test lists legitimately live in fences/tables, mirroring c11's RAW evidence scan (its docstring says exactly this, :1010-1012). Claim vocabulary (final form in §4.2): the mantra compounds (`fail-loud`, `fail-fast`, standalone `loud/loudly` with letter-lookarounds so "cloud" is excluded), `swallow`, `silent`, the #913 `warning-and-continue` phrase, the except idioms (`except Exception|BaseException`, `bare except`, `try/except`, `except:`), narrow raise forms (`must/shall/should raise`, `raises <SomeError|Exception>`, `raises SystemExit`), and non-zero-exit forms. The bare transitive `\braises?\b` was **rejected**: "raises the concurrency cap" is a real infra acceptance sentence; the narrow forms plus `swallow`/`silent` co-vocabulary covered every genuine raise-claim in the probe sample (e.g. #913's "raises (is not swallowed)" fires via `swallow`).

**Q2 Evidence heuristic.** A RAW-plan line is evidence iff it (a) does not match `(?i)\bgrep\b`, (b) matches module-scope `_TEST_IDENT_RE` (`\btest_\w+`, :182 — reused as-is; also matches `tests/test_foo.py` paths via the filename), and (c) matches the evidence vocabulary with letter-lookarounds (NOT `\b`) so identifier-internal tokens count: `test_length_mismatch_raises` has `_raises` preceded by `_` (a word char — `\b` fails there, `(?<![a-z])` succeeds). `exit code` was in the draft vocabulary and **removed after the probe caught a false-PASS**: "`uv run pytest tests/test_living_docs.py -v` exit code 0" (#725) is a generic success-path verification line — the exact #633-class self-certification c11's flag-stripping exists to prevent.

**Q3 Coupling condition.** Simple form adopted: **fail-loud claim present AND no committed fail-loud test named anywhere** (no grep-gate detection). Rationale: (a) a plan asserting fail-loud with NO verification at all is *more* deserving of the WARN than the grep-gated one, and grep-gate detection would exempt it; (b) requiring a grep gate near the claim adds a second heuristic with its own FP/FN surface; (c) a plan that keeps a grep gate AND names the test (the #913 **v2** fixed shape) must PASS — under a "grep gate present → WARN" rule it would not. The grep concept survives only as the evidence-side exclusion (Q2a).

**Q4 Kind scoping.** `kind in ("infra", "batch")`, mirroring c11, else SKIP. Grounds: #913 is `kind: infra` (verified in its body.md frontmatter) as are the c11 incident plans (#596/#607/#633); fail-loud acceptance claims are code-behavior invariants — the infra/batch plan shape; experiment/analysis success criteria use raise/fail vocabulary in statistical senses ("failed runs", "raising the dose") that would false-fire, and their acceptance surface is the eval, not unit tests. The corpus replay was run on infra|batch only; extending to `analysis` is a future calibration decision if an incident arises there, noted in the check docstring.

**Q5 N/A escapes.** Two canonical phrases, matched by one regex `NA_RE + r"(?:no fail-?loud acceptance claim|fail-?loud claim not test-backable)"` (reusing the tolerant `NA_RE` prefix, :125):
- `N/A — no fail-loud acceptance claim` — the vocabulary hit is incidental (bug narration, quoted rule text).
- `N/A — fail-loud claim not test-backable` — the target is a doc/prose file (`.md` instruction) with no code path a pytest can exercise; the plan states why on the same line.

Documented in: the module-docstring canonical-escape list (:39-48) and the adversarial-planner SKILL.md Phase 1.5.0 escape list (SKILL.md:113-118). That SKILL.md list currently lags — it stops at check 11, missing the c12/c13 phrases the docstring already carries; this diff back-fills those two lines while adding c14's (same file, same list, in-scope workflow surface; no separate task — recursion guard).

Appended last in `CHECKS` (:1494-1508). Docstring table gains the c14 row; both count-pinning tests updated (§5).

### 4.2 `scripts/verify_plan.py` — new check (inserted after `check_empirical_gate_attainability`, before `CHECKS`)

Near-final code (implementer may micro-adjust spellings within the §9 deviation bounds):

```python
# ─── Check 14 — fail-loud acceptance claim backed by a committed test ──────

# Trigger anchor: an acceptance/success-criteria mention. Deliberately
# NARROWER than c8's _SUCCESS_RE — "decision rule|decision gate" is excluded
# because gates/failure-mode sections carry failure-MODE descriptions
# ("silently provisioned" risk rows), not acceptance claims (corpus probe on
# all 230 infra|batch plans, task #932).
_FAILLOUD_ANCHOR_RE = re.compile(r"(?i)acceptance criteri|success criteri")

# Claim vocabulary, scanned over the fence-stripped window below an anchor.
# Letter-lookarounds (not \b) around "loud" exclude "cloud"/"Cloudflare".
# The bare transitive "raises" is deliberately absent ("raises the
# concurrency cap" is a real infra acceptance sentence); the narrow raise
# forms + swallow/silent cover the genuine raise-claims in the corpus.
_FAILLOUD_CLAIM_RE = re.compile(
    r"(?i)fail[- ]?loud|fail[- ]?fast"
    r"|(?<![a-z])loud(?:ly)?(?![a-z])"
    r"|swallow"
    r"|silent"
    r"|warn(?:ing)?[- ]and[- ]continue"
    r"|except\s+(?:Exception|BaseException)|bare\s+except|try\s*/\s*except|except\s*:"
    r"|(?:must|shall|should)\s+raise\b"
    r"|raises?\s+(?:an?\s+)?[A-Z][A-Za-z]*(?:Error|Exception)\b|raises?\s+SystemExit"
    r"|non-?zero\s+exit|exits?\s+non-?zero"
)

# Committed-test evidence vocabulary. Letter-lookarounds so identifier-
# internal tokens match (test_length_mismatch_raises, test_no_silent_swallow).
# "exit code" is deliberately absent — "pytest ... exit code 0" is a generic
# success-path verification line and self-certified in the corpus probe.
_FAILLOUD_TEST_EVIDENCE_RE = re.compile(
    r"(?i)(?<![a-z])rais(?:e|es|ed|ing)(?![a-z])|swallow|silent"
    r"|fail[- ]?loud|fail[- ]?fast|(?<![a-z])loud(?![a-z])"
    r"|(?<![a-z])except(?![a-z])|systemexit|non-?zero\s+exit|exits?\s+non-?zero"
)

# Evidence-side exclusion: a run-book grep gate over a test file would
# otherwise self-certify (`grep -n 'except Exception' tests/test_foo.py`).
_FAILLOUD_GREP_LINE_RE = re.compile(r"(?i)\bgrep\b")

# Anchor carriers that never bind: §0.0 TL;DR / §0 Plan Summary restate
# criteria as summary prose (same rationale as c8's _tldr_ranges exclusion).
_FAILLOUD_SUMMARY_HEAD_RE = re.compile(r"(?i)tl;dr|plan summary|^(?:§\s*)?0(?:\.0)?\b")

_FAILLOUD_WINDOW_LINES = 30

_FAILLOUD_NA_RE = re.compile(
    NA_RE + r"(?:no fail-?loud acceptance claim|fail-?loud claim not test-backable)"
)


def _failloud_claim_hits(plan: str) -> list[tuple[str, str]]:
    """(section heading, matched vocabulary) per acceptance/success anchor
    whose fence-stripped 30-line window carries a fail-loud claim. Anchors in
    fences, in §0/TL;DR/Plan-Summary regions, or with an H1/preamble carrier
    are dropped (corpus-probe noise classes, task #932)."""
    lines = plan.splitlines()
    mask = _fence_mask(lines)
    headings = _headings(plan)
    hits: list[tuple[str, str]] = []
    for i, line in enumerate(lines):
        if mask[i] or not _FAILLOUD_ANCHOR_RE.search(line):
            continue
        h = _innermost_section(headings, i)
        if h is None or h.level < 2 or _FAILLOUD_SUMMARY_HEAD_RE.search(h.text.strip()):
            continue
        end = min(h.end, i + 1 + _FAILLOUD_WINDOW_LINES)
        m = _FAILLOUD_CLAIM_RE.search(strip_fences("\n".join(lines[i:end])))
        if m:
            hits.append((h.text, m.group(0)))
    return hits


def _failloud_test_evidence_lines(plan: str) -> list[str]:
    """RAW-plan lines naming a committed fail-loud-exercising test: a
    ``test_`` identifier (also matches tests/<file>.py paths) co-located with
    fail-loud vocabulary, grep-command lines excluded."""
    out: list[str] = []
    for line in plan.splitlines():
        if _FAILLOUD_GREP_LINE_RE.search(line):
            continue
        if _TEST_IDENT_RE.search(line) and _FAILLOUD_TEST_EVIDENCE_RE.search(line):
            out.append(line.strip())
    return out


def check_failloud_test_coverage(plan: str, kind: str) -> CheckResult:
    """``kind: infra|batch`` plans whose acceptance/success criteria assert
    fail-loud / no-silent-swallow behavior must name a committed test pinning
    it — run-book grep gates verify the invariant once at review time, and a
    differently-worded re-swallow ships green past all committed tests
    (#913). WARN not FAIL: trigger and evidence are line heuristics; the
    Phase 2 critics adjudicate (Statistics lens item 14 owns the per-claim
    coverage judgment this check cannot make)."""
    cid, name = "c14_failloud_test_coverage", "fail-loud acceptance claim backed by a test"
    if kind not in ("infra", "batch"):
        return _skip(
            cid, name, "kind-exempt: the fail-loud acceptance-claim pattern is an infra|batch shape"
        )
    hits = _failloud_claim_hits(plan)
    if not hits:
        return _skip(cid, name, "no fail-loud claim in an acceptance/success-criteria window")
    if _FAILLOUD_NA_RE.search(plan):
        return _pass(cid, name, "explicit N/A declared (incidental vocabulary or not test-backable)")
    evidence = _failloud_test_evidence_lines(plan)
    if evidence:
        sec, tok = hits[0]
        return _pass(
            cid,
            name,
            f"fail-loud claim ({tok!r} in §{sec[:40]!r}) + fail-loud test named "
            f"({evidence[0][:80]!r})",
        )
    sec, tok = hits[0]
    return _warn(
        cid,
        name,
        f"acceptance/success criteria assert fail-loud behavior ({tok!r} in §{sec[:40]!r}) but "
        "no line names a committed test carrying fail-loud vocabulary (a `test_` identifier or "
        "tests/<file> path alongside raise/swallow/silent/except vocabulary; grep-gate lines do "
        "not count) — a run-book grep verifies the invariant once at review time, and a "
        "differently-worded re-swallow ships green past all committed tests (#913). Name the "
        "pinning test, or declare `N/A — no fail-loud acceptance claim` / "
        "`N/A — fail-loud claim not test-backable`",
    )
```
