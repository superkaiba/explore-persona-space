**(b) `.claude/rules/gotchas.md` — new bullet**, inserted immediately before the "vLLM in-process teardown" bullet, verbatim:

> - **matplotlib `xerr`/`yerr` take NON-NEGATIVE per-point OFFSETS from the value — never CI bounds and never signed deltas.** `Axes.errorbar`/`bar`/`barh` validate the error array (docstring: "All values must be >= 0") and raise `ValueError: '<x|y>err' must not contain negative values` at render time (NaN is exempt). The crash is DATA-DEPENDENT: a quantile CI over bootstrap/delta draws can genuinely invert around a separately-computed point estimate at tiny n (#1335: `fig_waterfall` passed CI bounds as barh `xerr`, killing GCP attempt att-20260715-122509 at the figures step), and float epsilon turns a constant-draw CI into a tiny negative delta (#547) — so ONE green figures run does NOT clear the class. RULE: at every errorbar site compute offsets element-wise as `err_lo = np.maximum(0, v - lo)` / `err_hi = np.maximum(0, hi - v)` (never raw `v - lo`, never the bounds themselves), and pin new figure code with a unit test that routes a deliberately INVERTED quantile CI (`lo > v` or `hi < v`) through the REAL figure function to `savefig`, asserting no ValueError. Clamped asymmetric-CI exemplars: `.claude/skills/paper-plots/patterns/{P1-bar-comparison,P8-ood-split,B0-blog-bar-comparison}.md`. (Incidents #547, #1335.)
