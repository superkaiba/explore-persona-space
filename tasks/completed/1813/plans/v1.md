## Goal / Requirement

Make hand-composed phase argvs fail on the VM in seconds instead of after a
full instance boot. Incident (verified on #1738 events.jsonl,
2026-07-28T20:56:38Z): Phase 3 attempt 1's plan-§10 command omitted the
driver's required input-source flag (`--split-file` or
`--manifest-dir`/`--manifest-from-hf`); the workload died at argparse (rc=1,
~7 s in) AFTER a full GCE flexstart boot + venv install — one wasted
boot+venv cycle.

**Acceptance criteria:**
1. A recipe clause exists in `.claude/skills/issue/SKILL.md` Step 6b that
   requires a VM-side parse probe of the EXACT production argv before any
   instance-booting dispatch of a hand-composed (newly-composed) workload
   argv, with a copy-pasteable generic probe snippet that catches
   missing-required-argument AND unknown-flag argparse errors.
2. `.claude/rules/crash-fix-rounds.md` (the filed `workflow_fix_target`)
   carries a short sibling clause binding the same probe on RELAUNCH rounds
   whose argv is not byte-identical to the previously-parsed launch,
   cross-referencing the SKILL.md clause as the canonical recipe.
3. `scripts/workflow_lint.py` (no-flags default) passes; the Step 9c mapped
   tests for the touched files pass.

## Method delta (what differs from prior related work)

Existing coverage and why each misses the class:
- `experimenter.md` "Verify dispatcher flags against the brief's `cmd=`"
  (item 7) is a `--help` flag-PRESENCE scan: it catches bogus flags but
  cannot catch a MISSING required argument (argparse's help action exits 0
  before required-arg validation), and it runs only on the pod-SSH
  pre-launch path — GCE `--workload-cmd` dispatches (the #1738 lane) never
  execute it.
- `.claude/rules/gotchas.md` #1310 entry probes inline-stdin HELPER call
  signatures inside dispatch scripts — not the top-level driver argv.
- `.claude/rules/crash-fix-rounds.md` fix-engaged discipline covers
  RE-launches of a fixed workload, not first launches of a new phase argv.

The delta: a parse-level dry-run of the exact composed argv, run on the VM
before the instance-booting dispatch, on BOTH first launches (SKILL.md
Step 6b, the primary home — that is where hand-composed argvs are dispatched)
and changed-argv relaunches (crash-fix-rounds.md, the filed target).

> **Hand-composed phase argv dry-run (REQUIRED before any instance-booting
> dispatch of a newly-composed argv; #1738).** Before
> `dispatch_issue.py launch --workload-cmd '<cmd>'` (any lane) whose inner
> driver argv was hand-composed this session — a NEW phase, a follow-up
> round, a plan-§10 command transcription — run a VM-side parse probe of the
> EXACT production argv; re-dispatching a byte-identical, previously-parsed
> command is exempt. Prefer the driver's own `--dry-run` / parse-only flag
> when one exists; otherwise the generic probe below (runs the driver only
> to its FIRST `parse_args()` call and exits 0 on success; an argparse error
> exits 2 with the message in seconds — fixed on the VM instead of after a
> boot cycle; #1738 Phase-3 attempt 1: the required
> `--split-file`/`--manifest-*` flag was omitted and argparse killed the
> workload rc=1 ~7 s AFTER a full GCE flexstart boot + venv install).
>
> ```bash
> # Generic argv parse probe — <script.py> + the EXACT production args:
> uv run python - <script.py> <args...> <<'PY'
> import argparse, runpy, sys
> sys.argv = sys.argv[1:]                     # ['<script.py>', <args...>]
> _orig = argparse.ArgumentParser.parse_args
> def _probe(self, *a, **k):
>     ns = _orig(self, *a, **k)
>     print("ARGV-PARSE-OK:", ns); sys.exit(0)
> argparse.ArgumentParser.parse_args = _probe
> runpy.run_path(sys.argv[0], run_name="__main__")
> PY
> ```
>
> Notes: (a) a bare `--help` probe validates NOTHING about the composed argv
> (help exits 0 before required-arg validation) — experimenter.md item 7's
> flag-presence scan is the COMPLEMENT (bogus flags), this probe is the
> missing-required side; (b) for a wrapper `.sh` dispatcher, probe the INNER
> python driver argv the wrapper composes (plus `bash -n <wrapper>` for
> syntax); (c) the probe executes the driver's import-time code up to the
> first `parse_args()` — cheap and VM-safe for this repo's drivers (parse
> comes first in `main()`); a driver calling `parse_known_args` directly
> bypasses the monkeypatch — note it in the dispatch note and fall back to
> the driver's own dry-run flag; (d) this is a pre-launch PROBE, not a
> workload — the "Ad-hoc probe workloads" committed-script rule above
> governs workload bodies, not this probe (same class as the gotchas #1310
> signature probe).
