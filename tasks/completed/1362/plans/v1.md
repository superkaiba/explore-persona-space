## 2. Method delta

The existing entry (gotchas.md line 138, the #779 two-bar rule) covers a **batched-vs-batch-1 equivalence gate** whose bar was calibrated on the wrong QUANTITY CLASS (span means smooth bf16 jitter; single-position states don't). The new variant is a **within-run determinism RE-CAPTURE check** — re-capture a subset under a fresh model load with a different batch composition and assert cosine against the first capture — whose bar was calibrated (implicitly) by the wrong EXECUTION REGIME: the CPU-float32 smoke passes bit-exactly by construction (fp32 CPU reductions are deterministic), so any near-1.0 constant survives the smoke and silently over-tightens the production gate; bf16 CUDA re-batches rows, cuBLAS reduction order shifts, and healthy cosines land ~1e-6 below 1.0 (#1005: 0.99999887 vs a 0.999999 bar). Same root cause (bf16 kernel nondeterminism), different trap mechanism and different rule (single ≥ 0.9999 margin vs the #779 0.999/0.995 two-bar split) — so the file needs the variant named, not just the class.
