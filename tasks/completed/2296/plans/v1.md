# Plan v1 — issue 2296: move the Step 10d mapped-invariant BASELINE leg off the shared repo root

`kind: infra` · workflow-surface fix · parent #2288 · 0 GPU-h

## 1. Requirement + acceptance criteria

**Requirement.** The Step 10d pre-push workflow-lint verdict gate's mapped-invariant
TEST leg must run its BASELINE pytest in a tree no other session can mutate. Today
both binding forms run it with `cwd` inside the SHARED repo root, where every
concurrent fleet commit's pre-commit stash cycle reverts the whole working tree for
the hook window (`.claude/rules/repo-root-uncommitted-state.md`;
`staged_files_only.py:23,81`). Under fleet churn the baseline process dies mid-run,
its hit/node sets come back EMPTY, and every gated red then reads NEW — the gate
returns `crash`/`block` on a payload that is actually clean.

**Acceptance criteria** (verbatim from the task body, each mapped to its evidence):

| # | Criterion | Evidence at review |
|---|---|---|
| A1 | The baseline leg no longer runs pytest with `cwd` in the shared repo root | Both edited blocks show the helper call / `cwd=<scratch>`; pin test asserts no `cd "$REPO_ROOT" && … pytest` remains in either mapped-invariant leg |
| A2 | Under fleet-representative churn the gate returns pass/block, not crash | Smoke §8.3: baseline leg run against a synthetic churn loop; realized rc ∈ {0,1} and a non-empty node set |
| A3 | A red present in BOTH trees is subtracted from `tg-new-nodes.txt` | Smoke §8.2: a seeded always-red mapped test appears in both leg outputs and NOT in `tg-new-nodes.txt` |
| A4 | The GATED leg's `cwd "$WT"` is unchanged | `git diff` shows no edit inside the gated-leg subshell; pin test asserts the `cd "$WT"` form survives |
| A5 | A pin test pins the new cwd | `tests/test_issue_skill_gate_recipe_hardening.py::test_mapped_baseline_leg_runs_off_shared_root` |

## 3. Method delta

Versus the status quo: the baseline leg's tree changes from *the live shared root* to
*a detached sparse scratch worktree cut at the resolved landing base*. Nothing else
about the leg's semantics changes — same test set derivation, same FILE-grain +
NODE-grain subtraction, same fail-closed crash arm, same `TG_T` sizing, same gated
leg.

Versus the two live siblings: #2293 changes `create_scratch_worktree`'s base
selection inside `scripts/step9c_baseline.py` (Step 9c `compare --run-pristine`
oracle); this task changes the **Step 10d gate recipe** and adds a CLI entry point.
Same helper, different consumer. #2288 touches only `scripts/verify_task_body.py` +
its test.

## 4. Design

### 4.1 Chosen shape — one new subcommand that OWNS the whole baseline leg

Add `mapped-baseline` to `scripts/step9c_baseline.py`, composed entirely of existing
helpers:

```
uv run python scripts/step9c_baseline.py mapped-baseline \
  --map-files <own-diff.txt> --root <REPO_ROOT> --cones-from <WT> \
  --base origin/main --timeout-s <TG_T> --out <baseline.txt>
```

Behaviour, in order:

1. Resolve the base ref to a sha (`git rev-parse <ref>`); fail-closed exit 2 if it
   does not resolve.
2. `create_scratch_worktree(root, wt_cones=_work_root_sparse_cones(<cones-from>) or [], timeout_s)`
   — reused verbatim; profile is already a superset of the gate layout via
   `_scratch_cones` (top-level tracked dirs minus `SCRATCH_EXCLUDES` ∪ HEAD-pinned
   `tests/sparse_cones.txt` ∪ the work root's cones), and the tree lands under
   `gate_tmp_root()`.
3. `assert_scratch_src_shadow(root, scratch, timeout_s)` — the #1251 check that
   `PYTHONPATH=<scratch>/src` actually wins over the root venv's editable install.
4. Select the baseline test set by running the selector against the SCRATCH
   (`--map-files … --repo-root <scratch>`), so "which mapped tests exist on the
   payload-free tree" is judged against that tree.
5. Run pytest with `cwd=<scratch>`, the **root venv interpreter**
   (`resolve_root_python(root)`), `PYTHONPATH=<scratch>/src`, `thread_capped(env)`,
   and `gate_tmp_root()` TMPDIR/`--basetemp` routing — capturing **TEXT** to
   `--out` (this is why `run_pytest()` itself is not reused: it DEVNULLs stdout and
   reports through junitxml, while the gate's FILE-grain attribution greps the text).
6. `remove_scratch_worktree` in a `finally`.
7. Print two machine-readable lines to stdout — `scratch_path=<abs path>` and
   `rc=<pytest rc>` — and exit 0 whenever the leg RAN (rc is data, not the exit
   code), exit 2 on any setup/teardown failure the caller must treat as crash-class.

`scratch_path` is printed **because the caller still needs it after teardown**: the
`<TREE>` prefix-normalization sed must cancel the scratch's absolute prefix.

Base-sha threading: `create_scratch_worktree` currently pins `sha = git_head(root)`.
Add an optional keyword `sha: str | None = None` (default `None` ⇒ today's behaviour,
byte-identical for the two existing call sites). **Rebase-time adaptation:** if
#2293 has already landed an equivalent base/ref parameter, use ITS parameter verbatim
and drop this addition — recorded in the implementer report, not re-litigated.

### 4.2 Rejected alternatives

| Alternative | Why rejected |
|---|---|
| Inline `git worktree add --detach` + sparse-checkout in the SKILL.md bash | Mints a second scratch-tree implementation; the task body explicitly forbids it, and it would drift from `_scratch_cones`/`gate_tmp_root` |
| Reuse the #1212 gate tree `$GT` for pytest | `$GT` is a `git archive` extraction of `workflow_lint.py`'s scan surface only (documented residual (b)); widening its pathspec to a pytest-capable tree changes the LINT legs' semantics |
| `cd "$TG_SCRATCH" && uv run pytest` | `uv run` resolves the project from cwd, so it would provision a SECOND venv for the scratch (minutes + GB). The root interpreter + `PYTHONPATH` shadow is the shape the existing oracle already uses |
| Delegate to `compare --run-pristine` | Its verdict is NODE-grain; the scan tests here need FILE-grain payload attribution. Out of scope |
| `run_pytest()` verbatim | DEVNULLs the text output the attribution greps need |

### 5.2 `.claude/skills/issue/SKILL.md` — shared forms (i)/(ii), L12324-12343

Replace the baseline SELECTION + subshell with the single helper call. Concretely:

```bash
      # BASELINE leg — a DETACHED SPARSE SCRATCH tree cut at the resolved
      # landing base, NEVER the shared repo root (#2296): every fleet commit's
      # pre-commit stash cycle reverts the root working tree repo-wide for the
      # hook window (#2015), which killed this leg mid-run on #2288 and made
      # every gated red read NEW. The helper reuses the Step-9c oracle's own
      # scratch machinery (create_scratch_worktree / gate_tmp_root /
      # assert_scratch_src_shadow) and runs pytest under the ROOT venv
      # interpreter with PYTHONPATH=<scratch>/src — the SAME venv `uv run` used
      # before, so no dependency-resolution change. Selection also runs against
      # the scratch: a branch-NEW mapped test is absent there, so its gated
      # hits stay NEW by construction (unchanged doctrine).
      TG_SCRATCH=""
      TG_BASE_OUT=$(timeout --kill-after=30s $((TG_T + 420))s uv run python \
        "$REPO_ROOT/scripts/step9c_baseline.py" mapped-baseline \
        --map-files /tmp/issue-<N>-own-diff.txt --root "$REPO_ROOT" \
        --cones-from "$WT" --base origin/main --timeout-s "$TG_T" \
        --out /tmp/issue-<N>-tg-baseline.txt 2>/tmp/issue-<N>-tg-baseline-err.txt) \
        || TG_CRASH=yes
      TG_SCRATCH=$(printf '%s\n' "$TG_BASE_OUT" | sed -n 's/^scratch_path=//p' | tail -1)
      TG_BASE_RC=$(printf '%s\n' "$TG_BASE_OUT" | sed -n 's/^rc=//p' | tail -1)
      [ -n "${TG_BASE_RC:-}" ] || { TG_BASE_RC=0; TG_CRASH=yes; }   # fail CLOSED
```

Notes that must survive review: `origin/main` is already fetched at this point
(the bounded `git -C "$WT" fetch origin main` at L12133 precedes the TG leg);
`TG_CRASH=yes` on a missing/unparseable rc is the SAME fail-closed posture as the
existing selector-failure branch; an empty `TG_BASE_TESTS` set is now the helper's
own concern (it writes an empty `--out` and reports `rc=0`).

### 5.3 `.claude/skills/issue/SKILL.md` — the `<TREE>` normalization sed, L12390

```bash
          | sed -e "s|${TG_SCRATCH:-/__eps_no_scratch__}|<TREE>|g" \
                -e "s|${WT:-/__eps_no_wt__}|<TREE>|g" \
                -e "s|${REPO_ROOT:-/__eps_no_root__}|<TREE>|g" \
```

**Load-bearing, and the highest-risk line in this change.** Without it every
baseline hit line carries a scratch-absolute prefix, cancels against nothing under
`comm -23`, and EVERY gated hit reads NEW — the exact inversion this task exists to
remove. Scratch substitution goes FIRST for the same prefix-containment reason the
existing comment gives for `$WT` before `$REPO_ROOT` (a scratch under a routed
`gate_tmp_root()` need not be, but may be, under a normalized prefix). The
never-matching parameter defaults keep an unset var from becoming an empty-pattern
sed that fails into an EMPTY hits file (silent fail-open) — same idiom as today.

### 5.4 `.claude/skills/issue/SKILL.md` — form (iii) surgical block, L14331-14337

Same helper call with `--map-files /tmp/issue-<N>-additive-files.txt`, still placed
BEFORE the `xargs … git checkout` (a post-checkout baseline is a degenerate
self-compare). The scratch cut at `origin/main` is payload-free by construction here
too, which is strictly better than today's "root before the checkout" (which is
payload-free only if no concurrent session is mid-commit). `--base origin/main`
requires a fetch on this path: add the same bounded
`timeout --kill-after=30s 120s git -C "$REPO_ROOT" fetch origin main --quiet || true`
if the surgical block does not already carry one (verify at implementation; if the
fetch is absent, `--base` degrades to a possibly-stale `origin/main`, which is
acceptable — staleness biases the baseline toward MORE reds, i.e. toward PASS).

## 6. Byte budget / ratchet arithmetic (`SKILL_DOC_SIZE_GRANDFATHER["issue/SKILL.md"]`)

Measured at the landing base (`origin/main` == local `main` == worktree, all three
942,384 B; verified via `git cat-file -s`): cap `943_600` ⇒ **headroom 1,216 B**.
The loose-cap hygiene bar is 3,000 B (a trim leaving > 3 KB headroom FAILs until the
cap is ratcheted DOWN in the same change).

This change's SKILL.md delta is genuinely two-directional: §5.2/§5.4 REPLACE a
mapfile + 6-line subshell with a shorter helper call (net negative), while
§5.2's comment, §5.3, §5.5 and the new §11 residual add prose. **The implementer
MUST measure the realized landing bytes and set the cap to
`measured + ~1.2 KB` (the #1753/#1727 landing-bytes rule), in EITHER direction** —
raise if the file grew past 943,600, ratchet DOWN if the file shrank enough to leave
> 3,000 B headroom — recomputing against a freshly fetched `origin/main` at
commit time, never against branch-tip bytes alone. A cap edit and the SKILL.md edit
land in the SAME commit.

**Smoke blind-spot enumeration:**

  flapping in its read set; it does NOT certify behaviour under a genuine concurrent
  `staged_files_only` window.
- The smoke runs the new subcommand DIRECTLY, not through the full Step 10d gate
  workload; the SKILL.md prose edits (§5.2-§5.5) are exercised only by the pin test's
  text assertions plus this task's own Step 10d run, which is the first real
  end-to-end execution of the edited recipe.
- No production gate/assertion is downgraded and no implementation is substituted

  `assert_scratch_src_shadow`, `resolve_root_python`, and `gate_tmp_root` on the
  smoke path — no third-party import is production-branch-only.

## 9. Kill criteria

- The scratch materialization's wall time exceeds ~5 min at p50 on this VM (a ~1 GB
  sparse checkout per gate run) → the leg's added latency is disproportionate; fall
  back to reusing ONE scratch across both legs, or park and re-plan.
- `assert_scratch_src_shadow` cannot be satisfied for the mapped test set (the
  PYTHONPATH shadow loses to the root editable install) → the scratch cannot be a
  trustworthy baseline; stop and re-plan rather than shipping an unverified shadow.
- The §8.2 subtraction check fails (a both-trees red still reads NEW) → the `<TREE>`
  normalization is wrong; fix before any merge, never ship a verdict-inverting gate.

## 11. Residuals (accepted, documented in SKILL.md)

- **Live-tree-anchored scan tests.** `step9c_baseline.FILE_ANCHORED_SCAN_TESTS`
  curates the scan tests whose scan root is `__file__`-derived; those scan the
  SCRATCH and gain a genuinely payload-free baseline. A mapped scan test that
  anchors via `repo_root()` / `task_workflow` instead still scans the shared ROOT
  even when its code is read from the scratch — so its baseline can still FLAP under
  churn (a missed baseline red ⇒ false NEW, fail-closed, resolvable through the
  existing provenance-override path). Strictly better than today, where the same
  churn kills the process outright. Not fixed here; the fix would be extending the
  file-anchoring curation, which is #2293-adjacent work.
- **Interpreter asymmetry.** Baseline runs the root venv interpreter directly;
  the gated leg keeps `uv run` from `$WT`. Same asymmetry exists today between the
  root and `$WT`; unchanged by this task (A4 forbids touching the gated leg).
- **Added latency.** One sparse scratch materialization + teardown per gate run
  (~1 GB), on top of the existing legs.
