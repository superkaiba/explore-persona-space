## 3. Design

### 3.1 New symbols (all in `scripts/verify_task_body.py`, placed adjacent to the followup-events helpers at ~:12040–12210 so the local-import pattern and label machinery stay colocated)

```python
# Canonical followup-scope source enum (workflow.yaml § markers).
_FOLLOWUP_SOURCE_SLUGS = frozenset(
    {"proposer-9b-cheap", "proposer-9b", "user-chat", "step-10b-pick"}
)

# Body-side source claim: `source proposer-9b-cheap`, `source: user-chat`,
# `source=`X``. Vocabulary-gated at use site (a captured token outside
# _FOLLOWUP_SOURCE_SLUGS is NOT a claim — prose like "source data" skips).
_CTX_SOURCE_CLAIM_RE = re.compile(r"\bsource\s*[:=]?\s*`?([a-z0-9][a-z0-9-]*)`?", re.I)

# Body-side free-analysis claim vocabulary (closed set, deliberately tight):
_CTX_FREE_ANALYSIS_RE = re.compile(
    r"\bfree[- ]analysis\b"
    r"|\bcost_class\s*[:=]?\s*`?free-analysis`?"
    r"|\bzero[- ]GPU\b"
    r"|\best\.?\s*[~≈]?\s*0(?:\.0)?\s*GPU-h\b",
    re.I,
)

# Body-side explicit estimate: `est 14 GPU-h`, `est. ~1.5 GPU-h`. A `<`/`>`
# bound claim (`est <20 GPU-h`) is NOT a point claim and never matches.
_CTX_EST_GPUH_RE = re.compile(
    r"\best\.?\s*[~≈]?\s*(?<![<>])(\d+(?:\.\d+)?)\s*GPU-h", re.I
)
```

### 3.2 Helper 1 — marker-side facts

```python
def _followup_scope_facts(events: list[dict]) -> dict[str, dict]:
    """Per scope-armed label: {source: str|None, est_gpu_hours: float|None,
    ts: str}. Label groups via followup_label_groups (within-label latest
    (ts,version) entry is authoritative — corrections land append-only).
    source = parse_followup_note_field(authoritative_note, "source"), falling
    back to group["source"] when the authoritative (correction) note omits it
    and group["source"] != "unknown" (the library's corrections-must-not-
    demote semantics). est_gpu_hours = parse_followup_note_field(
    authoritative_note, "est_gpu_hours"), float()-parsed; unparseable → None.
    Groups whose label starts with "unlabeled-" (pseudo-ts founding) are
    EXCLUDED — a body cannot sensibly name them."""
```

Local imports (`followup_label_groups`, `parse_followup_note_field`) match the `_same_issue_run_rounds` convention.

### 3.3 Helper 2 — body-side claims

```python
def _context_label_claims(ctx_scan: str, labels: Iterable[str]) -> dict[str, dict]:
    """Per label mentioned in the Context scan region: {source_claim: str|None,
    free_analysis: bool, est_claim: float|None}.

    Mention = full-token match of the label on a scan-region line:
    re.compile(rf"(?<![\\w-])`?{re.escape(label)}`?(?![\\w-])") — the
    (?<![\\w-])/(?![\\w-]) guards block substring collisions between sibling
    labels (`rollout` vs `rollout-v2`). For EACH mention, the claim WINDOW is
    the text from the match end to the EARLIEST of: end of the physical line;
    the start of the next mention of ANY label in `labels` on that line
    (multi-round one-line footers attribute tokens to the nearest preceding
    label). Before claim parsing, MULTI-WORD inline-code spans (`...` spans
    containing whitespace) are stripped from the window — a quoted scope-note
    fragment inside backticks is a quotation, not a body claim — while
    single-token backtick spans survive (a formatted value like `proposer-
    9b-cheap` IS a claim; _CTX_SOURCE_CLAIM_RE tolerates the backticks).
    Claims from multiple windows for one label are unioned; a source token
    outside _FOLLOWUP_SOURCE_SLUGS is discarded (not a claim)."""
```

`ctx_scan` is `_context_scan_region(_repro_section_text(body))` — the SAME fence-stripped + blockquote-line-stripped, after-the-`**Context:**`-label region check 17's sub-checks use. This is load-bearing: the Context row's blockquoted verbatim originating prompt for a follow-up round is routinely the scope note itself (containing `source: proposer-9b-cheap`), and must never read as a body claim (#959 strip precedent).

**Scope note:** the scan is deliberately restricted to the region after `_CONTEXT_LABEL_RE` (the `**Context:**` row), not the whole footer — the `**Repro:**` block carries compute lines ("~1.8 GPU-h on A100") that are actuals, not provenance claims.

### 3.4 The check

```python
def check_context_followup_scope_consistency(
    body: str, *, issue: int | None = None
) -> CheckResult:
    """Check 46 (#1521; incident #1426): Context-row follow-up provenance
    tokens vs the label's latest epm:followup-scope note fields."""
    name = "Context follow-up provenance vs followup-scope markers"
    # 1. Generation gate
    if not is_nested_design(body):            return PASS "skipped — legacy (pre-v2) body"
    repro = _repro_section_text(body)
    if repro is None or not _CONTEXT_LABEL_RE.search(repro):
                                              return PASS "skipped — no **Context:** row"
    # 2. Events gate (the _followup_events_rounds failure shape)
    if issue is None:                         return PASS "skipped — no issue id (bare --file/--body-stdin)"
    try: events = list_events(issue)          # local import
    except StaleTaskPathError: raise
    except FileNotFoundError:                 return PASS "skipped — unknown issue (no events)"
    facts = _followup_scope_facts(events)
    if not facts:                             return PASS "skipped — no epm:followup-scope markers"
    # 3. Compare
    claims = _context_label_claims(_context_scan_region(repro), facts.keys())
    contradictions, est_warns, checked = [], [], 0
    for label, claim in claims.items():
        fact = facts[label]; checked += 1
        s_b, s_m = claim["source_claim"], fact["source"]
        if s_b and s_m and s_b != s_m:
            contradictions.append(<source-mismatch msg>)
        elif claim["free_analysis"] and (
            s_m in ("proposer-9b-cheap", "proposer-9b")
            or (fact["est_gpu_hours"] or 0) > 0
        ):
            contradictions.append(<the #1426 free-analysis-vs-GPU-band msg>)
        if (claim["est_claim"] is not None and fact["est_gpu_hours"] is not None
                and abs(claim["est_claim"] - fact["est_gpu_hours"]) > 0.5):
            est_warns.append(<est-mismatch msg>)
    # 4. Verdict
    if contradictions:
        detail = "; ".join(contradictions) + <remediation sentence>
        if is_v4(body): return CheckResult(name, False, detail)
        return CheckResult(name, True, "grandfathered v3/v2 — " + detail, is_warn=True)
    if est_warns:       return CheckResult(name, True, "; ".join(est_warns), is_warn=True)
    return PASS f"{checked} follow-up label clause(s) consistent with followup-scope markers"
    # (checked == 0 → PASS "no scope-armed label mentioned in the Context row")
```

FAIL/WARN messages name: the label, the body token(s), the marker's `source` / `est_gpu_hours` values + the authoritative marker's `ts`, and the remediation ("update the Context clause to match the round's `epm:followup-scope` note, or post a correcting followup-scope marker; SPEC.md § `**Context:**` row").

### 3.5 Contradiction decision table (exhaustive; everything not listed = per-label skip)

| # | Body claim (window, vocabulary-gated) | Marker fact (label's authoritative scope entry) | Verdict |
|---|---|---|---|
| C1 | source slug `S_b ∈ _FOLLOWUP_SOURCE_SLUGS` | source `S_m` parseable, `S_b != S_m` | **CONTRADICTION** → FAIL (v4) / WARN (v3/v2) |
| C2 | free-analysis claim (`_CTX_FREE_ANALYSIS_RE`) | `S_m ∈ {proposer-9b-cheap, proposer-9b}` OR `est_gpu_hours > 0` | **CONTRADICTION** (the #1426 shape) → FAIL (v4) / WARN (v3/v2) |
| W1 | explicit `est N GPU-h`, N parsed | `est_gpu_hours` parsed, `|N − est| > 0.5` | WARN only (a body may state a legitimately revised estimate; never FAIL) |
| S1 | source token captured but ∉ enum (e.g. "source data") | — | skip (not a claim) |
| S2 | source claim | `S_m` unparseable / group source `"unknown"` | skip |
| S3 | free-analysis claim | scope exists, `est_gpu_hours` absent/0 AND `S_m ∈ {user-chat, step-10b-pick, unknown}` | skip (cannot prove contradiction; user-chat rounds carry no cost_class) |
| S4 | free-analysis clause naming NO scope-armed label | — | skip by construction (the per-label loop iterates scope labels only) — this IS the genuine free-analysis case: those rounds post `epm:free-analysis-followup-run` and no scope marker |
| S5 | GPU-band claim for a label with NO scope marker (only a free-analysis-run marker) | — | skip — documented residual: `epm:free-analysis-followup-run` `followup_ref` is first-token-truncated / often absent (task_workflow semantics), so reverse matching is unreliable; followup-scope is the only ground truth this check reads |
| S6 | label mentioned, no source/cost tokens in any window | anything | skip |

**The asymmetry, reasoned through (design requirement 1):** free-analysis rounds are recorded by `epm:free-analysis-followup-run` with no scope marker and usually no kebab label — so a truthful free-analysis clause never collides with a scope group (S4). The #1426 contradiction is precisely the OTHER direction: a scope-armed label (GPU-band source, est > 0) whose body clause claims free-analysis (C2). The check therefore keys entirely on scope-armed labels and never needs to parse free-analysis-run markers.

## 4. Controls / Edge cases

1. **Skip conditions (never FAIL):** no issue id; unknown issue (`FileNotFoundError`); no `**Context:**` label; no scope markers; no scope label mentioned in the row; per-label missing tokens (S1–S6 above). `StaleTaskPathError` propagates (registry corruption must surface — `_followup_run_marker_rounds` precedent).
2. **Grandfathering:** § 3.7. A v3 body with the #1426 contradiction WARNs; a promoted legacy body is untouched.
3. **Multi-round footers:** windows are bounded at the next any-label mention on the line, so ``… round `a` (source user-chat) … round `b` (source proposer-9b-cheap)`` attributes each source to its own label. Multi-line rows: a window never crosses a physical line (tokens on other lines are unattributed → skip — fails toward skip, the safe direction).
4. **Labels with corrections:** `followup_label_groups`' authoritative entry is the last in `(ts, version)` scan order — a correcting re-post wins (e.g. an `est_gpu_hours` correction). A correction note omitting `source` falls back to the group's first-parseable `source` (library semantics: a correction must not demote a user-chat round).
5. **`unlabeled-<ts>` pseudo-labels:** excluded in `_followup_scope_facts` (their label strings contain a timestamp with colons and can never be sensibly named in a body; excluding them also avoids pathological regex behavior).
6. **Blockquoted / fenced content:** excluded by `_context_scan_region` — the verbatim scope-note quote (which contains the marker's own `source:` line) never reads as a body claim. Multi-word inline-code spans within a window are additionally stripped (§ 3.3).
7. **Label substring collisions:** full-token mention regex with `(?<![\w-]) … (?![\w-])` guards (§ 3.3).
8. **"actual" figures:** `_CTX_EST_GPUH_RE` anchors on `est`, so "actual ~1.8" (the corrected #1426 row) never parses as an estimate claim; a bound claim (`est <20 GPU-h`) never matches (no point value).
9. **Repro-block compute lines:** out of scope — the scan starts after the `**Context:**` label.

## 6. Kill criteria

What would make this check wrong to ship:

1. **False-positive rate on the promoted corpus > 0** (criterion 5.5): any existing v4 body FAILing the new check where the body is actually right (e.g. a legitimate re-scoped round whose latest marker was never corrected) means the vocabulary/table is too aggressive → tighten (demote the offending rule to WARN or add a skip) before merging. The sweep is a REQUIRED pre-merge validation step, not optional.
2. **The corrected #1426 body FAILs or WARNs** → the window/vocabulary logic misreads the sanctioned clause shape; fix before ship.
3. **> ~2 WARN hits on the corpus from rule W1** (est mismatches on legitimately revised estimates) → drop W1 entirely (it is the most cuttable tier; C1/C2 carry the incident class alone).
4. **Sibling collision unresolvable:** if #1520's landed change restructures the check-dispatch machinery incompatibly (not expected — it targets a different check), rebase and re-run the full suite; a conflict that would delay > 1 round → land this check's logic unchanged under whatever number is free.

## 11. Decision Rationale

1. **Anchor on the label string from events, not the SPEC clause regex.**
   *What:* body-side matching finds each scope-armed label as a full token in the Context scan region, rather than requiring the literal ``same-issue follow-up round `<label>` `` form (`_V4_FOOTER_ROUND_CLAUSE_RE`).
   *Why:* the corrected #1426 row — the incident's own ground truth — does not use the literal form; anchoring on the label is phrasing-agnostic and fails toward skip when the label is unmentioned.
   *Source:* #1426 body **Context:** row (line ~206; fact-check corrected from 185) (read this session); SPEC.md § `**Context:**` row (:444–449, :685–690). *Alternatives:* extend `_V4_FOOTER_ROUND_CLAUSE_RE` — rejected: brittle to sanctioned phrasing variation and would silently miss the incident row itself.
2. **Source-token vocabulary = the 4-slug workflow.yaml enum, gate-checked before comparison.**
   *What:* a captured `source` token counts as a claim only if ∈ `{proposer-9b-cheap, proposer-9b, user-chat, step-10b-pick}`.
   *Why:* prevents prose false positives ("source data …"); the marker side is generated by the /issue loop from this enum, so an out-of-enum body token is more likely prose than provenance.
   *Source:* `.claude/workflow.yaml` § markers :2249/:2283; corpus grep of `epm:followup-scope` notes. *Alternatives:* compare any captured token — rejected (false-positive surface); maintain no vocabulary and only compare backticked tokens — rejected (the #1426 corrected row writes the slug unbackticked).
3. **FAIL on C1/C2 (v4) vs WARN elsewhere; est mismatch (W1) WARN-only.**
   *What:* hard FAIL only for the two mechanical contradictions (source≠source; free-analysis vs GPU-band evidence); numeric est disagreement WARNs.
   *Why:* design requirement 3 (conservative, contradiction-only); an est figure may be legitimately revised in prose, while a wrong source/cost_class is the #1426 provenance-corruption class.
   *Source:* incident #1426 (fold r1, Lens 5b); task body `## Workflow gap`. *Alternatives:* FAIL on est mismatch — rejected (false-positive prone); WARN-only everywhere — rejected (the incident showed the contradiction survives to promotion unless it blocks).
4. **Generation gating: v4 FAIL / v3-v2 WARN / legacy skip.**
   *What:* § 3.7. *Why:* SPEC forward-only rule — a v4 rule must never newly hard-FAIL a grandfathered body; the contradiction is still worth surfacing there as a WARN.
   *Source:* SPEC.md § Mechanical checks (forward-only preamble); the #1418 `fail-denied → WARN-on-v3/v2` precedent (`_context_row_result_v3`, verify_task_body.py:4336). *Alternatives:* v4-only (skip v3/v2 entirely) — rejected: the comparison is trivially shared via `_repro_section_text`, and a WARN is free signal; v3 FAIL — forbidden by the forward-only rule.
