# Plan v1 — #1480: escalate unactioned stalled-MANUAL alerts to a bounded registration unregister

## 0.0 TL;DR (plain English)

- **What I'll build:** a small escalation step in the watcher's stalled-session check for user-driven sessions. Today, when a hand-driven session wedges on an active task, the watcher sends one alert and then does nothing forever (#928 sat frozen for 6 days). After this change, if the alert goes unanswered for ~24 hours with zero task progress, the watcher quietly deletes the session's registration file — it never touches the session itself — which lets the existing orphan sweep start a fresh autonomous driver within ~30 minutes.
- **What I expect:** on a replay of the #928 freeze, recovery would land at ~24-27 hours instead of 6 days, with no change at all to healthy sessions, deliberately parked tasks, or autonomous sessions.
- **What would change my mind:** if the orphan sweep turned out not to re-drive an active task whose live owner just lost its registration file, deleting the file would accomplish nothing — I verified in the code that it does re-drive (details in §6/§9), so if a test proves otherwise the design needs a re-drive leg added.

## 2. Method delta — why the existing passes can't just be tuned

**Prior work (all in-repo; verified by reading, line anchors re-derived 2026-07-17):**

- The stalled lane already detects the #928 shape and alerts once per episode: `_handle_stalled_alert` manual branch (`scripts/autonomous_session_watch.py:11290-11295`, note at `:11358-11371`), reached from `_process_stalled_session` (`:12379-12381`) when `decide_session_stalled` (`:1842`) verdicts `alert` (manual entries force `respawn_eligible=False`, `:12195`). After the alert, every still-stalled tick returns `("keep", 0)` (the alerted-dedup keep branch, docstring `:1949-1952`) — the lane latches.
- The ONLY unregister machinery is the #845 stale-registration pass: pure predicate `decide_stale_registration` (`:2647-2672`), actor `_process_stale_registration` (`:20018-20082`), pass `stale_registration_pass` (`:20085`). **Why it can't be tuned to cover #928:** its predicate REQUIRES `transcript_idle_s >= idle_threshold_s` (12 h). A live wedged session with ANY transcript activity — user pokes, in-session cron ticks — defeats it indefinitely; #928's session was live-enough on 07-14 to need a deliberate stop. Lowering the 12 h threshold would not help (the gate is transcript-idle, not task-progress), and removing the transcript gate from THAT pass would change its semantics for every registration kind. The new rung keys on TASK-level progress (self-report + non-watcher markers, the stalled lane's own signals), which is exactly the signal that stayed frozen for 6 days.
- The orphan sweep cannot act while the manual registration exists AND its session is live: `mapped_alive = bool(rec and rec["sids"] & live_ids)` (`:13575`) → `decide_orphan` returns `("clear", 0)` (`:12623-12624`). With a DEAD manual session it degrades to alert-only (`manual_only` → `("alert", ...)`, `:12632-12633`). So for both live-wedged and dead manual sessions, the registration file itself is the blocker — deleting it is the minimal, sufficient act. Post-delete: `rec is None` ⇒ `mapped_alive=False`, `manual_only=False` ⇒ the slow path (90-min staleness × 2-miss debounce) verdicts `respawn` (`:12634-12636`). The #1391 dead-owner fast path and its live-cwd-owner veto only modulate the staleness FLOOR (`decide_dead_owner_fast_path`, `:12639-12690`; "the #505 manual-only alert requires `rec`, so that guard structurally cannot co-occur with this path" `:12659-12661`) — a live-but-unregistered owner does NOT block the slow-path respawn. This is the verified recovery leg the whole plan depends on (kill criterion §6.1; assumption A2).
- Landed-fix / live-sibling check: no overlapping in-flight work (checked 2026-07-17). The clarifier's `git log --since=2026-07-14` on the watcher shows #1453/#1439/#1392/#1391/#1341 — none adds a stalled-manual escalation; `grep -rln 'alert-only by design' .claude/ CLAUDE.md scripts/` (worktrees/cache excluded) hits only `scripts/autonomous_session_watch.py` (+ pyc caches). `spawn_session.py list` shows no live session building on this lane.

**The delta:** ONE new rung inside the existing stalled lane, modeled on the stale-registration pass's action shape (unlink + marker + sidecar; `:20066-20082`) and the wedge lane's fire-time exemption re-probe design (`_apply_wedge_override_with_exemption_probe`, invoked at `:12274-12301`), keyed on the stalled lane's OWN per-tick confirmations rather than posted alerts — the #1137 dedup caps markers at one per episode, so alerts are uncountable by design; confirmations are counted in `stalled-<N>.json` (clarifier finding 4).

**Why not scope-gated (the §1 fork, defended):** (a) the trap is the REGISTRATION, not the followup scope — a manual session wedged mid-`running`/`verifying` with zero progress produces the identical 6-day freeze (live sid + registration ⇒ `mapped_alive` ⇒ orphan sweep permanently vetoed), and the autonomous lane escalates to stop+respawn for that same shape at ANY active status; #505 constrains only STOPPING the user session, not which statuses deserve recovery. (b) Every known legitimately-parked ACTIVE shape is already excluded by the exemption ladder this rung re-probes at fire time (user-pause prose `:11431`, over-cap spend-approval `:11450` — the one case where a re-driven session genuinely could not help, since that gate is user-only — deliberate-blocked `:11478` (moot: `blocked` ∉ ACTIVE), round-complete re-park `:11496`, awaiting-child `:11505`, provision-in-flight / long-phase heartbeat `:11899-11901`). (c) Requiring the scope adds a per-tick `unrun_followup_labels` computation and leaves the non-scope variant of the same trap unfixed. The residual broad-rule risk — a user deliberately camping in a session for >24 h with zero task markers and no USER-PAUSE note — is bounded by the fire-time worktree-activity veto, the alert + push the user received ~22 h earlier (naming the coming escalation, per the updated `next_step` prose), and the fact that the escalation costs the user nothing destructive: their session stays alive, and their next `/issue <N>` wake re-registers through the SKILL Step 0 ownership re-check exactly as after a stale-registration unregister.

### 3.3 New pure predicate (place next to `decide_stale_registration`, ~`:2647`)

```python
def decide_stalled_manual_escalation(
    *,
    in_active: bool,
    alerted: bool,
    stale_confirmed: bool,
    confirm_count: int,
    first_confirm_ts: float | None,
    now: float,
    min_confirms: int,
    min_window_s: float,
) -> tuple[str, int, float | None]:
    """Pure per-tick decision for the #1480 stalled-manual escalation rung.

    Returns (verdict, new_count, new_first_ts); verdict in
    {"escalate", "count", "reset"}.

    - NOT stale_confirmed (self-report fresh, or any non-watcher marker
      within the 2h marker window) OR NOT in_active -> ("reset", 0, None):
      the consecutive chain broke / the task left the trap shape. A fresh
      non-watcher marker therefore resets the whole accumulation — the
      "zero non-watcher task progress" condition is enforced by
      consecutiveness x the 2h marker window at 10-min tick granularity.
    - stale_confirmed AND in_active -> count' = confirm_count + 1;
      first' = first_confirm_ts if it is a positive float else now
      (a malformed/missing anchor restarts the window — fail toward keep).
      - alerted AND count' >= min_confirms AND (now - first') >=
        min_window_s -> ("escalate", count', first').
      - else -> ("count", count', first').  Pre-alert confirmations
        accumulate but can never fire (alerted is required at fire time:
        the trigger is an UNACTIONED alert).
    Every input the caller could not resolve is mapped by the CALLER to
    the conservative value (in_active=False on a None status read;
    stale_confirmed=False when self_report_age is None), so this function
    stays total and clock-free (now is injected — the #1127
    deterministic-anchor posture).
    """
```

```python
def _apply_stalled_manual_escalation(
    ctx: _StalledActionCtx, entry_path: Path, events: list[dict], stale_confirmed: bool
) -> bool:
    """#1480: evaluate + (maybe) fire the stalled-manual escalation rung.

    Mutates ctx.manual_escalate_count / ctx.manual_escalate_first_ts to the
    values THIS tick must persist (every downstream persist site forwards
    them). Returns True iff the escalation FIRED (caller returns early).
    NEVER stops or spawns a session; the only registry mutation is the
    manual registration file's unlink. Every unresolvable input fails
    toward keep (returns False with today's behavior unchanged).
    """
    if not ctx.manual or not _stalled_manual_escalation_enabled():
        return False
    verdict, ctx.manual_escalate_count, ctx.manual_escalate_first_ts = (
        decide_stalled_manual_escalation(
            in_active=ctx.in_active,          # _task_status read THIS tick (:12193)
            alerted=ctx.alerted,
            stale_confirmed=stale_confirmed,
            confirm_count=ctx.manual_escalate_count,
            first_confirm_ts=ctx.manual_escalate_first_ts,
            now=ctx.now,
            min_confirms=_stalled_manual_escalate_confirms(),
            min_window_s=_stalled_manual_escalate_window_s(),
        )
    )
    if verdict != "escalate":
        return False
    # Fire-time veto 1 — fresh worktree activity (someone is mid-edit):
    # DEFER, keep the counters (re-evaluated next tick). Same helper the
    # stale-registration pass uses (:20049); 2s-bounded walk, probed only
    # on fire-candidate ticks.
    if _worktree_recent_activity(ctx.issue, ctx.now, _wt_activity_fresh_s()):
        print(f"  issue #{ctx.issue}: stalled-manual escalation DEFERRED — fresh worktree activity")
        return False
    # Fire-time veto 2 — exemption re-probe (the wedge lane's #845-r2
    # design, :12274): the post-alert keep(0) ticks never probed the lazy
    # exemptions, so re-probe ONCE against the escalation. Any rewrite
    # (user-pause / spend-approval / provision / heartbeat / re-park /
    # awaiting-child) VETOES the fire and RESETS the counters (the task is
    # legitimately parked; when the park lifts, either the session resumes
    # -> advancement clear, or a fresh 24h accumulation begins).
    probed_action, _pm, ctx.followups_child_alerted, _ex = _apply_stalled_park_exemptions(
        issue=ctx.issue, status=ctx.task_status, has_pod=ctx.has_pod, events=events,
        action="alert", new_missed=ctx.threshold,
        followups_child_alerted=ctx.followups_child_alerted,
        now=ctx.now, dry_run=ctx.dry_run,
    )
    if probed_action != "alert":
        ctx.manual_escalate_count, ctx.manual_escalate_first_ts = 0, None
        _persist_stalled_ctx(ctx, ctx.happy_session_id_str, 0)
        return True   # exemption handled/annotated the tick; nothing to dispatch
    _escalate_stalled_manual(ctx, entry_path, events)
    return True
```

## 10. Decision Rationale (§11-style: What / Why / Source / Alternatives)

- **K = 3 consecutive confirmations (`EPM_STALLED_MANUAL_ESCALATE_CONFIRMS`).** Why: requires the stall to be CURRENT at fire time (consecutively re-confirmed), absorbing flaky reads beyond the lane's own 2-miss guard. Source: the watcher's 3-consecutive convention — `EPM_TICK_WEDGE_MIN_DEQUEUED=3`, `EPM_TICK_WEDGE_MIN_FAILED_TURNS=3`, boot-death/wedge day caps = 3 (#1104/#1127/#1241 lineage). Alternatives: K=2 (the lane's miss threshold — too weak for an irreversible-ish act), counting posted alerts (impossible — #1137 dedup, clarifier finding 4).
- **Window = 24 h (`EPM_STALLED_MANUAL_ESCALATE_H`).** Why: sandwiched between the 12 h stale-registration precedent (#845 — that pass acts on WEAKER task-level evidence but requires transcript-idle; this rung deliberately drops the transcript gate, so it doubles the wait and demands an unactioned alert + zero task progress on top) and the 6-day #928 incident it must beat; 24 h also spans a full /daily cycle of human notice after the alert + push. Source: #845's `EPM_STALE_REGISTRATION_IDLE_H` grounding (`:19969-19978`) + the #928 timeline (task #1480 body / #1298). Alternatives: 12 h (parity with #845 — rejected: this rung is strictly more aggressive on the session-liveness axis, so it earns a longer fuse), 48 h (rejected: two more days of a frozen followup round for no added safety — every veto is already positive-evidence-gated).
- **Env names `EPM_STALLED_MANUAL_ESCALATE_{H,CONFIRMS}`; kill switch `EPM_DISABLE_STALLED_MANUAL_ESCALATION`.** Why/Source: the watcher's naming conventions — hours-suffixed `_H` (`EPM_STALE_REGISTRATION_IDLE_H`), `EPM_DISABLE_<ARM>` kill switches (`EPM_DISABLE_BOOT_DEATH_PASS` `:19634`, `EPM_DISABLE_CAPACITY_RETRY`, …); malformed/non-positive → default (never a stealth kill switch — the `_stale_registration_idle_s` contract `:19985`). Alternatives: minutes-suffixed knob (rejected — day-scale value reads better in hours).
- **Kill-switch default ON (rung armed).** Why: the workflow-fix exists to close a live gap; a default-off rung repeats the built-but-stranded anti-pattern. Source: every sibling arm ships armed with an `EPM_DISABLE_*` opt-out (#1267 boot-death, #1392 subfloor reclaim). Alternative: opt-in env (rejected — nothing would ever set it).
- **Unregister-only action (never stop; in-process `unlink`).** Why: #505 is a hard constraint; the registration file is the proven minimal blocker (§2). Source: the #845 stale-registration pass's action shape (`:20080`), the documented "UNREGISTER-ONLY" contract (`:19962-19964`). Alternatives: `spawn_session.py unregister --force` subprocess (rejected — the CLI's sid-matched/force contract targets session-side callers; the watcher's own unlink is the in-file precedent), stop+respawn (banned, #505).
- **Counters in `stalled-<N>.json` hardening fields (advancement-cleared).** Why: episode-scoped semantics for free, the established #845 pattern; a resumed session must fully re-arm the fuse. Source: `_stalled_hardening_fields` (`:7472-7496`) + `_save_stalled_state` docstring. Alternative: a separate state file (rejected — needless GC surface; day-keyed advancement-EXEMPT fields à la #1209/#1241 are wrong here since the trap ends exactly when the self-report advances).
- **Fire-time exemption re-probe (not per-tick).** Why: the lazy-exemption design means post-alert keep(0) ticks never probe (`exempted=False` = unprobed, `:11875-11881`); probing per-tick would pay subprocess cost on every stalled tick. Source: the wedge lane's #845-r2 re-probe precedent (`:12265-12301`). Alternative: per-tick probing (rejected — cost without safety gain; the fire is the only act).
- **Worktree-activity fire-time veto (defer, keep counters).** Why: directly excludes the "user actively mid-edit but posting no markers" residual of the broad-trigger decision. Source: the #845(b) hold + the stale-registration pass's identical guard (`:20049`). Alternative: none/reset (rejected — defer preserves the accumulated evidence; the hold is naturally bounded by the marker any real progress posts).
