# Plan v1 — task #1791: `--map-files` misuse OSError before the #1613 guard

## 1. Goal + acceptance criteria

**Goal (from task body):** Make `--map-files` misuse with a non-path-list
payload reach the graceful #1613 diagnostic instead of a raw traceback:
guard the per-line existence probes with an OSError/ValueError-tolerant
helper.

**Acceptance criteria:**
1. `select_step9c_tests.py --map-files <file>` where the file contains a
   content line longer than NAME_MAX (255 bytes) no longer raises
   `OSError: [Errno 36] File name too long`.
2. A `.py`/`.sh`-named `--map-files` argument with such content reaches the
   existing #1613 ERROR diagnostic and exits 2 (contract preserved).
3. A non-source-suffixed argument (e.g. `.md`/`.txt`) with such content
   reaches the existing #1613 hedged WARN and exits 0 (contract preserved).
4. Regression tests cover both shapes; existing #1613 cluster tests
   (tests/test_select_step9c_tests.py L712–790) stay green.

## 2. Method delta (vs prior work)

#1613 (commit lineage in `_zero_resolution_guard`) added the misuse
diagnostic but its own probe (`(work_root / f).exists()`) raises before the
heuristic can report when a content line exceeds NAME_MAX. #1717/#1699
touched adjacent ergonomics but not the OSError path (verified-at-filing
git-log check, re-confirmed 2026-07-29). This plan adds ONLY
OSError-tolerance to content-line-derived stat probes — no behavioral
change on any valid path-list input.

## 3. Concrete changes (file paths + diff shape)

Target: `scripts/select_step9c_tests.py` (workflow surface; wf-fix scope).

(a) Add a module-level helper near the other small utilities:

```python
def _safe_exists(p: Path) -> bool:
    """`p.exists()` that treats an unstat-able path as absent (#1791).

    A content line from a mis-passed --map-files payload (markdown prose,
    a source line > NAME_MAX) raises OSError [Errno 36] / ValueError
    (embedded NUL) from Path.exists() — before the #1613 misuse diagnostic
    can fire. Such a line is by definition not an existing repo path.
    """
    try:
        return p.exists()
    except (OSError, ValueError):
        return False
```

(b) Swap the CONTENT-LINE-DERIVED probe sites to the helper:
  - L1568 (`_zero_resolution_guard`):
    `if any(_safe_exists(work_root / f) for f in files if not f.startswith("/")):`
  - L1434 (`select_tests_with_reasons`, touched-test branch):
    `if _safe_exists(work_root / f):`
  - L1454 (same function, exact stem map): `if _safe_exists(exact):` —
    `exact` embeds `test_{stem}.py` where `stem` derives from a touched /
    content line, same crash class.
  - Implementer sweep: grep ALL `.exists()` sites in the file and classify
    each as content-line-derived (swap) vs fixed-catalog path
    (WORKFLOW_INVARIANT members, pinned scan/dependency-map test paths —
    leave as bare `.exists()`; they are repo-controlled literals). List the
    classification in the report `(a)` section.

(c) Regression tests — extend the #1613 cluster in
`tests/test_select_step9c_tests.py`:
  - `.py`-named `--map-files` arg whose content includes a >NAME_MAX line →
    rc 2, stderr carries the #1613 "looks like a source file" ERROR line,
    no traceback.
  - `.md`-named arg with a >NAME_MAX line → rc 0, stderr carries the #1613
    hedged WARN, no traceback.
  - Unit: `_safe_exists(work_root / ("x" * 300))` is False.

## 4. Considered but NOT done (deliberate)

The #1762 content-shape pre-check (line-length / markdown-prefix heuristic
→ exit 2 before any probe). Rejected for v1: the OSError-tolerant helper
alone restores the designed #1613 behavior for every arg shape, while a
shape heuristic risks false-positive exit-2s on legitimate path lists
(paths near NAME_MAX, unusual-but-valid lines) and duplicates the guard's
existing suffix-based classification. If the critic disagrees, the
heuristic can be added as a second commit.
