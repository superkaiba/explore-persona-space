### 4.1 New code in `src/explore_persona_space/backends/runpod.py`

Add near the other module helpers (after the imports; `subprocess` at L61, `sys` at L62 already imported — add `from collections import deque` **in the same edit as its first use**, per the PostToolUse-ruff unused-import rule):

```python
# Bounded stderr tail carried on a failed pod_lifecycle subprocess (#1465).
# 60 lines covers the 20-50-line traceback class (#775 B2: a 5-line tail
# truncated vLLM tracebacks; the GCE EXIT trap tails 40); 400 chars/line
# bounds a pathological single line, worst case ~24 KB << the 50k marker cap.
_POD_LIFECYCLE_TAIL_MAX_LINES = 60
_POD_LIFECYCLE_TAIL_MAX_LINE_CHARS = 400


class PodLifecycleProcessError(subprocess.CalledProcessError):
    """``CalledProcessError`` whose ``str()`` carries the child's stderr tail.

    Deliberately a SUBCLASS so every existing contract holds verbatim:
    ``except subprocess.CalledProcessError`` catches it, and
    ``dispatch_issue._provision_still_waiting`` reads the SAME
    ``returncode`` / ``cmd`` fields (the exit-75 still-waiting contract).
    ``self.stderr`` holds the BOUNDED tail (last
    ``_POD_LIFECYCLE_TAIL_MAX_LINES`` lines), not the full stream.
    """

    def __str__(self) -> str:
        base = super().__str__()
        if not self.stderr:
            return base
        return (
            f"{base}\n--- pod_lifecycle stderr tail "
            f"(last {_POD_LIFECYCLE_TAIL_MAX_LINES} lines max) ---\n{self.stderr}"
        )


def _run_pod_lifecycle_relay(
    cmd: list[str],
    *,
    env: dict[str, str] | None = None,
    relay: Any | None = None,
) -> None:
    """Run a ``pod_lifecycle.py`` subprocess, TEEING its stderr live.

    stdout stays INHERITED (untouched — provision progress prints pass
    through exactly as before). stderr is piped and relayed line-by-line
    to ``relay`` (default ``sys.stderr``) with an immediate flush, so the
    ``[wait-for-capacity]`` heartbeat lines the orchestrator scans live
    (SKILL.md Step 6b) keep streaming in real time across a multi-hour
    wait, while a bounded deque retains the tail. On non-zero exit raises
    :class:`PodLifecycleProcessError` with ``returncode`` + ``cmd``
    verbatim and the tail as ``stderr`` (#1465; incident #1336: an opaque
    ``exit status 1`` with zero diagnostics).
    """
    out = relay if relay is not None else sys.stderr
    tail: deque[str] = deque(maxlen=_POD_LIFECYCLE_TAIL_MAX_LINES)
    proc = subprocess.Popen(  # noqa: S603 — repo-internal argv, no shell
        cmd,
        stderr=subprocess.PIPE,
        text=True,
        encoding="utf-8",
        errors="replace",
        env=env,
    )
    assert proc.stderr is not None  # stderr=PIPE => stream exists
    with proc:
        try:
            # iter(readline, "") — unambiguous no-readahead line streaming.
            for line in iter(proc.stderr.readline, ""):
                out.write(line)
                out.flush()
                if len(line) > _POD_LIFECYCLE_TAIL_MAX_LINE_CHARS:
                    line = line[:_POD_LIFECYCLE_TAIL_MAX_LINE_CHARS] + "…[line truncated]\n"
                tail.append(line)
            rc = proc.wait()
        except BaseException:
            # subprocess.run parity (CPython 3.11 run(): `except: # Including
            # KeyboardInterrupt ... process.kill(); raise`): kill the child on
            # ANY interruption rather than hang in __exit__'s wait — preserves
            # today's Ctrl-C behavior exactly (Phase 1.5 fact-check, A10).
            proc.kill()
            raise
    if rc != 0:
        raise PodLifecycleProcessError(rc, cmd, output=None, stderr="".join(tail))
```

Notes baked into the implementation:

- **stderr-only pipe, stdout inherited** → single-stream read in the main thread, structurally deadlock-free (the classic two-PIPE serial-read deadlock cannot occur), zero threads.
- `cmd` is passed **verbatim** into the exception — the `_provision_still_waiting` cmd-shape match (`"pod_lifecycle.py"` substring + exact `"provision"` element) holds by construction.
- Signal deaths (rc < 0) inherit `CalledProcessError.__str__`'s "died with signal" rendering via `super().__str__()`; rc < 0 ≠ 75 so the still-waiting branch correctly does not fire.
- Return value: both current call sites discard `subprocess.run`'s return value (bare statement L831; L1417), so the helper returning `None` is a drop-in.

## 11. Decision Rationale

- **Exception design = `CalledProcessError` subclass with overridden `__str__`** (not a typed non-subprocess error à la GCP, not the plain class). *Why:* the plain class's `__str__` omits `stderr` entirely (Python 3.11 `subprocess.CalledProcessError.__str__` renders only cmd + returncode), so the Goal is unreachable with it; a non-subclass typed error breaks `except subprocess.CalledProcessError` at `dispatch_issue.py:1610`. The subclass satisfies both: isinstance-compatible, fields verbatim, message diagnosable. *Source:* Python stdlib behavior (subprocess docs / CPython `__str__`) + code read of `dispatch_issue.py:1180–1198, 1610–1637`; the clarifier's candidate design, confirmed. *Alternatives rejected:* `raise CalledProcessError(...) from RuntimeError(tail)` (tail only visible in full tracebacks, not `str(exc)` → not in the rc-4 `detail` field); capture-only without `__str__` change (the incident's opaque message would persist).
- **Tee mechanism = stderr-only `Popen` pipe read in the main thread via `iter(readline, "")`, stdout inherited.** *Why:* heartbeats AND Python failure diagnostics are stderr-borne in `pod_lifecycle.py` (15+ `file=sys.stderr` sites; heartbeats at L1091/1158 with `flush=True`), so one pipe captures what matters; a single read stream is deadlock-free without threads; stdout untouched = zero behavior change for stdout consumers. *Source:* code read of `pod_lifecycle.py` + Python io docs (`iter(readline, "")` has no readahead lag); liveness pinned by test 3. *Alternative rejected:* two-thread both-stream tee (more code + review surface for marginal gain — stdout carries only informational prints); `stderr=STDOUT` merge (would move heartbeat lines onto stdout, polluting the stream where `_cmd_launch` prints its JSON body).
- **Tail size = 60 lines, 400 chars/line.** *Why:* must exceed the 20–50-line vLLM/Python traceback class that a 5-line tail demonstrably truncated (#775 Part D B2), with margin; bounded so worst case ≈ 24 KB stays far under the 50,000-char marker-note cap. Line cap guards against a single giant line (precedent: gcp per-zone `stderr_tail` caps at 200 chars). *Source:* `.claude/rules/compute-backend-failover.md` Part D (the #775 B2 lesson lives in the RULE FILE, not the #775 task body — fact-check correction: "the WIDE 500-line probe tail (NOT the 5-line log_tail_excerpt, which truncates a 20-50-line vLLM traceback … — the B2 bug)") + the GCE EXIT-trap `tail -n 40` precedent (`backends/gcp.py:2562`); exact values engineering judgment within those bounds — smoke-tested by tests 4/5. *Alternatives:* 40 lines (GCE precedent — too tight vs the 50-line traceback class); 500 lines (#775 wide surface — oversized for an exception message).
- **Same helper on the terminate leg** (vs simpler `capture_output=True` + re-raise). *Why:* one code path, one test surface; live relay of terminate output is harmless (bounded duration, no heartbeat concern per clarifier finding 5) and terminate failures gain identical diagnosability. *Source:* engineering judgment — consistency over micro-optimization; the clarifier explicitly allowed either with justification.
- **Injectable `relay` parameter** (default `sys.stderr`). *Why:* makes liveness deterministically testable (timestamped recorder) without touching the production path. *Source:* engineering judgment — smoke-tested (test 3).
