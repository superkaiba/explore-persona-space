## §3 Design

One new module-level helper + a two-line change inside `_classify_committed_issue_png`'s class-C branch. No new subprocess calls, no new task-state reads (plan text is already resolved).

### §3.1 The bounded prose-token bar — `_stem_prose_named(text, stem) -> bool`

A stem is *prose-named* by `text` when some single LINE of `text` contains ALL of the stem's required tokens, under this normalization:

- **Stem tokens:** `re.split(r"[^a-z0-9]+", stem.lower())`, dropping: empties; pure digits; a small fixed stopword set (`by, per, of, the, a, an, and, or, vs, to, in, on, for, with, from, at, all`); figure-index tokens (`^f\d+$`, `^fig(ure)?\d*$`, `^panel\d*$`). Each surviving token is singularized (strip one trailing `s` when len ≥ 4 and not `ss`-final).
- **Applicability bound:** the bar applies ONLY when ≥ 2 distinct required tokens survive, each ≥ 3 chars. A stem reducing to 0–1 tokens is NOT prose-matchable (falls back to the existing exact/glob bars) — the single-token widening (`roc.png` matched by any case-insensitive "ROC") is deliberately excluded; disclosed under-match, fails toward the pre-widening status quo.
- **Line tokens:** each line of `text` is tokenized + singularized the same way (stopwords need not be dropped — matching is subset-inclusion of the stem's required tokens).
- **Match:** required stem tokens ⊆ that line's token set. Whole-token matching by construction ("arm" cannot match inside "harmful"); case-insensitive (both sides lowered) — a deliberate, bounded divergence from the exact bar's case-sensitivity, safe because token-subset matching is far stricter than substring containment.
- **Perf:** line token sets are computed once per distinct text via a small module-level `functools.lru_cache` helper (`_prose_line_token_sets(text) -> tuple[frozenset, ...]`) — the same `plan_text` / `body` strings repeat across every committed PNG in one invocation.

Worked example (#2222): stem `roc_by_arm` → tokens {roc, arm} (by = stopword; 2 tokens ≥3 chars ⇒ applicable). Plan line "…(3) sample-level ROC curves per arm, (4) map-quality panel…" → line tokens include {roc, arm} ⇒ candidate. Body with 0 mentions ⇒ class C WARN.

### §3.2 Wiring — class-C branch only, symmetric on both sides

In `_classify_committed_issue_png`, ONLY the code after the per-unit branch changes:

```python
# §3.0 candidate filter (#2169), widened #2231: exact/glob OR prose-token
if plan_text is None or not (
    _stem_named_in_body(plan_text, stem) or _stem_prose_named(plan_text, stem)

    return None
if named or _stem_prose_named(body, stem):
    return None
return "unmentioned"
```

- **Classes A/B byte-identical:** `_stem_named_in_body` is untouched; the per-unit branch (`_PER_UNIT_FIG_RE` hit) returns before the new code. Every existing check-31 test must stay green unmodified (K2).
- **Symmetry preserved:** #2169 §3.0's "one predicate, both sides" commitment carries forward — class C's naming predicate is now the union (exact ∨ glob ∨ prose-token) on BOTH the plan side and the body side. The body-side widening is loosening-only for class C (strictly fewer WARNs than plan-side-only widening) and matches the class-C mention-bar philosophy (#2169 §3.2: naming silences, no disposition idiom required; false negatives are the accepted direction for a WARN-tier backstop).
