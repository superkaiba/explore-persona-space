## 3. Method delta

Current scrub (both tests, identical shape):

```python
scrubbed = [p for p in sys.path if str(Path(p or ".").resolve()) != scripts_dir]
```

Hardened scrub — RESOLVABILITY-based, not path-equality-based: drop every entry from which
a bare `import runpod_api` could resolve, regardless of which checkout/dir it lives in:

```python
def _scrub_runpod_api_resolvable(paths: list[str]) -> list[str]:
    """Drop every sys.path entry from which a bare ``import runpod_api``
    could resolve (#2173): a regular module ``<entry>/runpod_api.py`` OR a
    (namespace-)package dir ``<entry>/runpod_api/``. Path-equality with the
    local scripts/ dir is NOT sufficient — the #2164 incident leaked the
    MAIN checkout's scripts/ via a collection-time repo_root()-derived
    insert in tests/test_issue1482_densesae_fullwidth.py (fixed in #2181),
    which the old scrub could not see. Zip/meta-path providers are the
    negative control's job, not this predicate's — an entry this predicate
    cannot see fails loud as DID-NOT-RAISE at the scrub site (kill
    criterion §7.1 routes it to re-plan)."""
    kept = []
    for p in paths:
        base = Path(p or ".")
        if (base / "runpod_api.py").is_file() or (base / "runpod_api").is_dir():
            continue
        kept.append(p)
    return kept
```

The existing negative control (`pytest.raises(ModuleNotFoundError)`) stays — it is the
fail-loud runtime assert that catches any pollution mechanism the predicate does not
anticipate (e.g. a meta-path finder or zipimport entry), converting it into a legible
failure at the scrub site instead of a mystery DID-NOT-RAISE. (A `PermissionError` raised
by `is_file()` on an unreadable entry propagates by design — fail-loud house style; it is a
scrub-site environment fault, not a scrub logic bug.)

**Regression guard (new test, mirrored in both files):** simulate the #2164 pollution
deterministically — create `tmp_path/foreign_checkout/scripts/runpod_api.py` (stub with a
`FOREIGN_SENTINEL` attr), prepend it to `sys.path` via monkeypatch, then run the SAME
hardened scrub + negative control + bootstrap + import sequence as the main test, and
additionally assert the imported module is NOT the foreign stub (`not hasattr(mod,
"FOREIGN_SENTINEL")`). The guard calls the SAME `_scrub_runpod_api_resolvable` helper the
main test uses (no hollow-gate divergence — the guard exercises the live scrub, per the
code-style "verification gates test the live dispatched path" rule). Against the OLD scrub
logic this guard fails (the foreign entry survives path-equality scrubbing) — that is the
"catches reintroduction" property acceptance criterion 3 demands.
