# Plan v1 — #1457: Auto-detect a resized-but-unexpanded boot disk (`vm_disk_guard.py` device-vs-fs reconciliation)

## 0.0 TL;DR (plain English)

- **What I'll build:** a small read-only check in the VM disk guard that, on every run, compares how big each watched disk's underlying block device is against how big the filesystem on it is. If the device is much bigger than the filesystem (someone resized the disk in GCP but never grew the partition/filesystem), the guard prints a loud warning, records it, and sends one deduplicated phone push naming the exact growpart/resize2fs commands to run.
- **What I expect:** on today's healthy VM the check stays quiet (measured gaps: 3.1% on `/`, 1.7% on the data disk — both under the 5% threshold); replaying the incident's numbers (485G filesystem on the ~1TB device, a ~50% gap) makes it fire.
- **What would change my mind:** if any legitimate layout in the fleet produces a persistent >5%-and->10-GiB device-vs-fs gap (it would false-warn forever) — the virtual-device skip, the absolute-bytes floor, and the ack-sentinel are the escape hatches; if none suffice, the check should be reverted to JSON-report-only.

## 0. Plan Summary (technical)

**Change:** add a pure, fail-soft device-vs-filesystem size reconciliation to `scripts/vm_disk_guard.py`. Per watched disk (`/` boot pass AND `/mnt/eps-data` data-disk pass), resolve the mounted filesystem's backing TOP-LEVEL block device via `os.stat(path).st_dev` → `/sys/dev/block/<maj>:<min>` → (partition → parent disk dir), read `size` (512-byte sectors, kernel-ABI-stable), and compare against `statvfs.f_blocks × f_frsize`. WARN when device exceeds fs by **>5%** (env `EPS_VM_DEVICE_FS_GAP_PCT`) **AND >10 GiB** absolute (env `EPS_VM_DEVICE_FS_GAP_MIN_GB`). **Hyperparameters:** 5% threshold (Source: measured — healthy `/` gap 3.10%, data disk 1.67%, incident gap 50.3%); 10 GiB floor (Source: suppresses small-disk fixed mkfs overhead; incident gap ≈ 526 GB clears it 50×). **Reporting:** new `DeviceFsCheck` attached to `GuardResult`, surfaced in `_result_json` + `_print_report` + a `device-fs-gap` sidecar row + ONE deduped Telegram push per (device, device-size) resize event. **Hard constraint:** report/surface ONLY — the guard NEVER runs growpart/resize2fs; exit codes unchanged. **Compute:** VM-only, worktree, tests. Estimated GPU-hours (total): 0. **Risks (top 2):** false-WARN on exotic layouts (mitigated: virtual-device skip + fail-soft-to-skipped everywhere + ack sentinel); a check crash breaking the cron guard (mitigated: every failure path returns `state="skipped"`, pinned by tests).

### 4.2 New dataclass + resolver + check (new section after `GuardResult`, ~line 510)

```python
@dataclass
class DeviceFsCheck:
    path: str
    state: str            # "ok" | "warn" | "skipped"
    device: str = ""      # top-level disk name, e.g. "sda", "sdb"
    partition: str = ""   # mounted partition name ("sda1") or "" for whole-disk fs
    partition_number: str = ""  # contents of the sysfs `partition` file, for the growpart hint
    device_bytes: int = 0
    fs_bytes: int = 0
    gap_bytes: int = 0
    gap_pct: float = 0.0
    threshold_pct: float = 0.0
    min_gap_bytes: int = 0
    reason: str = ""      # skip reason / one-line human summary


def _device_bytes_for_mount(
    path: str, *, sysfs_dev_root: str = "/sys/dev/block", stat_fn=os.stat
) -> tuple[int, str, str, str] | tuple[None, str, None, None]:
    """Resolve the TOP-LEVEL block device backing the fs at ``path``.

    Returns (device_bytes, disk_name, partition_name, partition_number) on
    success, or (None, reason, None, None) on ANY failure — containers /
    overlayfs (anonymous major-0 devices), device-mapper / loop / md (virtual
    devices — deliberately skipped, see §11), missing sysfs, non-Linux.
    Pure os.stat + sysfs reads, no subprocess (the _is_mounted style, line 135).
    """
    try:
        st = stat_fn(path)
        maj, mino = os.major(st.st_dev), os.minor(st.st_dev)
        if maj == 0:
            return None, f"anonymous device {maj}:{mino} (overlay/tmpfs/btrfs)", None, None
        node = os.path.realpath(f"{sysfs_dev_root}/{maj}:{mino}")
        if not os.path.isdir(node):
            return None, f"no sysfs node for {maj}:{mino}", None, None
        if "/devices/virtual/" in node:  # dm-*, loop*, md*, zram* — out of scope v1
            return None, f"virtual block device ({os.path.basename(node)})", None, None
        partition_name, partition_number = "", ""
        part_file = os.path.join(node, "partition")
        if os.path.exists(part_file):          # verified: sda1 has it ("1"); sdb/loop0 don't
            partition_name = os.path.basename(node)
            with open(part_file) as fh:
                partition_number = fh.read().strip()
            node = os.path.dirname(node)       # parent dir IS the disk (verified live)
        with open(os.path.join(node, "size")) as fh:
            sectors = int(fh.read().strip())   # kernel ABI: ALWAYS 512-byte sectors
        return sectors * 512, os.path.basename(node), partition_name, partition_number
    except (OSError, ValueError) as exc:
        return None, f"sysfs resolution failed: {exc}", None, None


def check_device_fs_gap(path: str, *, gap_pct_threshold: float | None = None,
                        min_gap_gb: float | None = None) -> DeviceFsCheck:
    """Fail-soft device-vs-fs reconciliation for one watched mount. NEVER raises."""
    thr = gap_pct_threshold if gap_pct_threshold is not None else device_fs_gap_pct()
    floor_b = int((min_gap_gb if min_gap_gb is not None else device_fs_gap_min_gb()) * 1024**3)
    if os.environ.get("EPM_SKIP_DEVICE_FS_CHECK", "").strip() == "1":
        return DeviceFsCheck(path=path, state="skipped", threshold_pct=thr,
                             min_gap_bytes=floor_b, reason="disabled via EPM_SKIP_DEVICE_FS_CHECK")
    dev = _device_bytes_for_mount(path)
    if dev[0] is None:
        return DeviceFsCheck(path=path, state="skipped", threshold_pct=thr,
                             min_gap_bytes=floor_b, reason=dev[1])
    device_bytes, disk, part, part_no = dev
    try:
        sv = os.statvfs(path)
    except OSError as exc:
        return DeviceFsCheck(path=path, state="skipped", threshold_pct=thr,
                             min_gap_bytes=floor_b, reason=f"statvfs failed: {exc}")
    fs_bytes = sv.f_blocks * sv.f_frsize
    if fs_bytes <= 0 or device_bytes <= 0:
        return DeviceFsCheck(path=path, state="skipped", threshold_pct=thr,
                             min_gap_bytes=floor_b, reason="zero-size read")
    gap = device_bytes - fs_bytes          # negative (fs > device) can only be an
    gap_pct = 100.0 * gap / device_bytes   # exotic layout → never WARN, report ok
    warn = gap_pct > thr and gap > floor_b
    return DeviceFsCheck(path=path, state="warn" if warn else "ok", device=disk,
                         partition=part, partition_number=part_no,
                         device_bytes=device_bytes, fs_bytes=fs_bytes,
                         gap_bytes=max(gap, 0), gap_pct=round(gap_pct, 2),
                         threshold_pct=thr, min_gap_bytes=floor_b)
```

Both functions carry keyword seams (`sysfs_dev_root`, `stat_fn`) for the fake-sysfs tests; production callers pass nothing.

### 4.5 Push + sidecar + dedup — in `main()` (after the still-over pushes, ~line 1741)

New helper `_maybe_alert_device_fs(chk: DeviceFsCheck, apply: bool) -> None`:

```python
def _device_fs_ack_sentinel_path(device: str, device_bytes: int) -> Path:
    # Keyed on (device, device size in GB): the device size changes ONLY on an
    # actual resize event, so each resize gets exactly one push; touching the
    # file manually acks/suppresses (the disk-guard-ack-* idiom, line 212).
    return repo_root() / ".claude" / "cache" / f"disk-guard-devfs-ack-{device}-{device_bytes // 10**9}g"

def _maybe_alert_device_fs(chk, apply):
    if chk is None or chk.state != "warn":
        return
    append_disk_guard_event(
        {"kind": "device-fs-gap", "path": chk.path, "device": chk.device,
         "device_bytes": chk.device_bytes, "fs_bytes": chk.fs_bytes,
         "gap_pct": chk.gap_pct}, apply=apply)          # fail-soft, report-only prints
    sentinel = _device_fs_ack_sentinel_path(chk.device, chk.device_bytes)
    if sentinel.exists():
        return                                           # already pushed for this resize
    pushed = _telegram_push(
        f"VM disk guard: {chk.path} device {chk.device} is "
        f"{chk.device_bytes/1e9:.0f}G but the fs is {chk.fs_bytes/1e9:.0f}G "
        f"({chk.gap_pct:.0f}% unexpanded) — a disk resize was not grown; "
        f"run growpart+resize2fs manually", apply)
    if apply and pushed:
        sentinel.parent.mkdir(parents=True, exist_ok=True)
        sentinel.touch()                                 # dedup only after a REAL push landed
```

Call sites in `main()`: `if not args.no_push: _maybe_alert_device_fs(res.device_fs, args.apply)` and the same for `data_res` when present. Sidecar row rides every warn run (it is already deduplication-free observability, one line per run — consistent with the existing escalation streams); the push is once-per-resize.

**Exit code unchanged:** the `return 2 if still_over else 0` (line 1746) is untouched — a devfs WARN never flips the exit code (exit 2 is the cron's "still over threshold" alarm channel; overloading it would re-page on a known-acked gap).

## 5. Design decisions (the brief's item 4)

| Decision | Choice | Justification |
|---|---|---|
| (a) WARN-only vs push | **WARN line every run + sidecar row + ONE deduped Telegram push per resize event** | The incident's failure mode was precisely "nobody was told" — a report-only line in a 6-hourly cron log repeats the failure. Dedup keyed on (device, device-GB): a resize is a discrete event; the sentinel doubles as a manual ack (existing `disk-guard-ack-*` idiom, line 212). Push respects `--no-push` (watcher sub-floor launches stay quiet; the 6-hourly cron, which runs without `--no-push`, delivers within ≤6h). Report-only mode never pushes/persists (existing `_telegram_push` + `append_disk_guard_event` apply gates). |
| (b) Threshold | **5% (env `EPS_VM_DEVICE_FS_GAP_PCT`) AND 10 GiB floor (env `EPS_VM_DEVICE_FS_GAP_MIN_GB`)** | Measured healthy overheads today: 3.10% (`/`), 1.67% (data disk); incident: 50.3%. 5% clears the worst healthy state ×1.6 and sits ×10 under the incident. The absolute floor kills small-disk fixed-mkfs-overhead false positives (a 10 GiB disk with a 1 GiB journal is ~10% gap but only ~1 GiB); the incident gap ≈ 526 GB clears it ×50. |
| (c) Both passes | **Yes** — the check lives in `run_guard`, so the boot pass and the `_is_mounted`-gated data-disk pass both get it. Both disks were resized in the past (sdb is exactly 1 TiB); both are watched disks. |
| (d) Report-only regardless of `--apply` | **Hard constraint: the guard NEVER auto-runs growpart/resize2fs** — `--apply` gates only the push/sidecar/sentinel side effects, never any remediation. Resizing a filesystem is irreversible-if-wrong and requires root; it stays a human action, named verbatim in the WARN line. |
| Comparison rule | **fs (`statvfs.f_blocks × f_frsize`) vs TOP-LEVEL disk (`/sys/.../block/<disk>/size × 512`), NOT vs the immediate partition** | Incident-critical: in the incident the PARTITION was not grown either, so fs-vs-partition would have read ~0 mismatch (clarifier; verified live: sda1 = 2,044,495,839 sectors ≈ sda = 2,044,723,200 — 0.01% apart today). Comparing against the parent disk catches both un-growpart-ed partitions and un-resize2fs-ed filesystems in one read. Whole-disk filesystems (sdb: no `partition` file, verified) compare directly. |
| Virtual devices | **Skip (`state="skipped"`)** for anything resolving under `/sys/devices/virtual/` (dm/loop/md/zram) and anonymous major-0 devices (overlay/tmpfs) | v1 targets the fleet's actual layout — cloud provider virtio-scsi disks (sda/sdb, verified paths under `/sys/devices/pci.../virtio0/...`). LVM/loop semantics differ (an LV deliberately smaller than its VG is legitimate); fail-soft skip removes the entire false-WARN class at zero cost to the Goal. |

## 7. Kill criteria

- **False-WARN storm on a legitimate layout** (LVM/loop/md/overlay, deliberate unpartitioned tail, thin provisioning): the virtual-device skip + major-0 skip + 10 GiB floor are designed to exclude these; if a real fleet layout still false-warns persistently and neither the env threshold nor the ack sentinel is an acceptable answer, demote the check to JSON-report-only (drop the push+WARN) or revert.
- **Any crash of the guard attributable to the check** (the cron guard is fleet-critical): unacceptable — every failure path must return `skipped`; a crash in the wild = immediate fix-or-revert.
- **Exit-code or tier-behavior regression** in the existing suites: blocks merge.
