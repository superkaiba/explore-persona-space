## 4. Design

### 4.0 What the test predicate requires (read from the test, lines 472-531)

- `_first_heavy_import_line`: earliest **module-top-level** `ast.Import`/`ast.ImportFrom` whose root name is literally `torch` or `numpy`. Nested imports (inside functions, `if TYPE_CHECKING:` blocks, `main()`) are invisible — `tree.body` only.
- `_first_load_dotenv_line`: first line whose TEXT contains the substring `load_dotenv(` — this matches comments too (e.g. `issue811_phase0_extract.py:59` is a comment, which is why the test reports "dotenv@59" there). **The edit recipe places the real CALL above the heavy import; never rely on a comment satisfying the substring.**
- PASS condition per file: no module-top torch/numpy import, OR `first load_dotenv( line < first heavy import line`, OR membership in the frozen allowlist (which MUST NOT grow).

### 4.1 The verbatim conforming preamble (copy this)

From `scripts/issue778_null_battery.py:33-40` (the canonical fixed exemplar):

```python
from explore_persona_space.orchestrate.env import load_dotenv

# #847: thread caps must land BEFORE the numpy/torch imports below — on the
# shared VM, load_dotenv() setdefaults OMP/MKL/OPENBLAS/NUMEXPR_NUM_THREADS,
# and the BLAS/torch pools freeze at import time.
load_dotenv()

import numpy as np  # noqa: E402
```

Every import line **after** the `load_dotenv()` call carries `# noqa: E402` (ruff selects `E`; E402 has no autofix). When code precedes the wrapper import itself (e.g. a `sys.path.insert`), the wrapper import line also carries `# noqa: E402` — the `issue779_capture_answer_summaries_pass2.py:47` shape.

**The preamble import chain is verified heavy-free** (so the fix is runtime-real, not just AST-satisfying): `src/explore_persona_space/__init__.py` is empty; `orchestrate/__init__.py` imports only `orchestrate.fleet`, whose module-top imports are stdlib-only (`logging, os, shlex, subprocess, collections.abc, dataclasses, pathlib, typing`); `orchestrate/env.py` imports stdlib + `dotenv`. No torch/numpy is reachable before the call.

**Runtime-correct placement (stronger than the AST predicate):** place the `load_dotenv()` call above not only the literal torch/numpy import but also every sibling `issue*` script-module import and every `explore_persona_space.*` import other than `orchestrate.env` — those pull torch/numpy transitively, and the caps must bind before ANY of them. Stdlib-only imports (`argparse, json, logging, sys, pathlib, ...`) stay above the preamble (the issue778 shape).

## 11. Decision Rationale

- **The preamble pattern (wrapper import + comment + bare `load_dotenv()` call).** What: §4.1 block. Why: it is the exact shape the fixed exemplars use and satisfies both the AST predicate and the runtime cap-binding purpose. Source: `scripts/issue778_null_battery.py:33-40`; `scripts/issue779_capture_answer_summaries_pass2.py:47-53`; the test predicate `tests/test_shared_vm_thread_caps.py:472-531`; task #1144's test-verdict finding. Alternatives: a bare `import os; os.environ.setdefault(...)` block (rejected — duplicates `env.py` logic, not the repo convention); calling `_apply_shared_vm_thread_caps()` directly (rejected — private, and `load_dotenv()` is the documented entrypoint, `env.py:145-148`).
- **MOVE, not duplicate, for Class B.** What: relocate the existing call rather than adding a second. Why: one canonical call site per file keeps the invariant legible; duplication is harmless (idempotent, `env.py:296,302,316-317,167-168`) but noisy. Source: task body/brief directive + `env.py` idempotency read. Alternative: keep the in-`main()` call too (rejected as default; acceptable fallback if a specific deletion proves risky — flag in the implementer report).
- **`# noqa: E402` per post-call import line.** What: suppress module-import-not-at-top for imports below `load_dotenv()`. Why: ruff selects `E` (`pyproject.toml:87-90`), E402 has no autofix, and this is the established convention in every conforming script. Source: `issue778_null_battery.py:40,44,46`; `issue779_capture_answer_summaries_pass2.py:51-53`; `pyproject.toml [tool.ruff.lint]`.
- **Bare→wrapper swap in `issue811_fit.py`.** What: replace `from dotenv import load_dotenv` + explicit-path call + `DOTENV_LINT_EXEMPT` waiver with the wrapper preamble. Why: merely reordering the bare call would turn the test green while leaving the runtime purpose (thread-cap binding) dead for this file — the bare python-dotenv call sets no caps; the wrapper is also the lint-preferred form and worktree-robust. Source: `scripts/workflow_lint.py:4286-4304` (check rationale); `env.py:142-168,319+` (caps wired in the wrapper only); `.claude/rules/code-style.md` § Shared-VM CPU thread caps. Alternative: move `import numpy` below the bare call (rejected — test-green but caps-dead).
- **Runtime placement above sibling/`explore_persona_space.*` imports (stronger than the AST predicate).** What: the call precedes all transitively-heavy imports, not just literal torch/numpy. Why: sibling `issueN_*` modules import numpy/torch at their tops; caps must bind before the first transitive heavy import or the fix is cosmetic. Source: `env.py` docstring lines 30-34; both exemplars order it this way.
