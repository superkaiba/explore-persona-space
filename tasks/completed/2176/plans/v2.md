- **New regex + dataclasses:**

```python
_ARM_REGISTRY_RE = re.compile(
    r"^arm-registry:\s*(?:(?P<na>N/A)\s*[—-]\s*(?P<na_reason>.+?)"
    r"|source=(?P<source>\S+)\s+file=(?P<file>\S+)\s+n=(?P<n>\d+)\s+members=(?P<members>\S+))\s*$"
)

@dataclass(frozen=True)
class ArmRegistry:  # na-form XOR structured form
    na: bool; na_reason: str | None
    source: str | None; file: str | None; n: int | None; members: tuple[str, ...]

@dataclass(frozen=True)
class RegistryCheckDecision:
    ok: bool; reason: str  # one machine-legible line
    missing: tuple[str, ...]; registry: ArmRegistry | None
```

- **`parse_arm_registry_line(note: str) -> ArmRegistry | None`** — first line starting `arm-registry:`; `None` when absent; a PRESENT line matching neither form raises `ValueError` naming the two accepted grammars (caught downstream — runtime never crashes on a malformed marker, #2171 posture; the caught path is pinned by T1.3b). `members` comma-split, backtick/whitespace-stripped, must be non-empty in the structured form. `source`/`file` are provenance tokens the SELF-CONSISTENCY clauses treat as opaque; the driver-recompute arm (clause 5b) additionally INTERPRETS them when a repo root is supplied (a multi-driver round unions members and comma-lists paths in `file=`; recompute then unions keys across the resolved files).
- **`_extract_registry_members(driver_file: Path, source_expr: str) -> tuple[str, ...] | None`** (new helper, ~30 lines; stdlib `ast`) — the driver-recompute reader. Symbol resolution: collect identifier tokens from `source_expr`, drop a small builtin set (`sorted`, `list`, `set`, `tuple`, `dict`, `keys`, `values`, `items`); exactly one candidate remains (e.g. `sorted(PHASES)` → `PHASES`) or return `None`. Key extraction: `ast.parse` the file; find the module-level `ast.Assign`/`ast.AnnAssign` binding that name to an `ast.Dict` whose keys are all `ast.Constant` strings; return the key tuple. Anything else (symbol absent, non-literal registry, non-string keys, unparseable file) → `None` — never a guess. - **`smoke_arch_registry_check(marker_note: str, repo_root: str | os.PathLike | None = None) -> RegistryCheckDecision`** — the predicate (pure over the note; with `repo_root` supplied it additionally reads the named driver file(s), deterministically). Calls `parse_smoke_arch_marker(marker_note)` (reuse; single positional `str`) for `per_arm`. Clause order:
  1. no `arm-registry:` line, or a present line matching neither form (the `ValueError`, caught here) → REFUSE with `_NO_ARM_REGISTRY_REASON` (new module constant naming BOTH accepted forms + the derivation rule "for a phase-dispatch driver, `sorted(PHASES)`; generally the dispatch table the entrypoint's phase/arm argument routes on");
  2. N/A form → **ok=True**, reason records the claim verbatim (`registry: N/A — <reason> (substantive adjudication: Step 6d.0 orchestrator + code-reviewer Step 0.55)`) — the N/A form names no `file=` for the recompute arm to read, so its substance is owned by the reviewer's diff check (D7), and the ok-reason says so visibly;
  3. `n != len(members)` → REFUSE (self-consistency; names both numbers);
  3b. `len(set(members)) != len(members)` → REFUSE naming the duplicated member(s) (`duplicate members: <sorted dups>` — a dup lets `n` match while enumerating fewer distinct arms; honest `sorted(PHASES)` derivation cannot produce it);
  4. `per_arm == {}` → REFUSE reusing `_NO_PER_ARM_SUBBLOCK_REASON` verbatim (same remedy: line-anchored key, re-post);
  5. `set(members) - set(per_arm)` non-empty → REFUSE with the DISTINCT count-mismatch reason: `registry-enumeration mismatch: n_registry=<n> n_enumerated=<len(per_arm)> missing=<sorted-comma-list> (registry: <source> @ <file>)`;
