# Plan v1 — task #1948: round-unique inline lint-gate payload path

architectural: false

## Plan Summary

Make the Step 9a-ter inline lint gate's payload-list path ROUND-unique and bind
the gate mechanically to the exact payload it read, so concurrent inline rounds
on the SAME issue can no longer clobber each other's payload file and
cross-certify (incident: two concurrent #1768 rounds at 2026-07-31 22:26Z,
cross-certification realized in BOTH directions). `kind: infra`, workflow-fix,
0 GPU-hours, non-architectural.

## Requirement + acceptance criteria

Requirement: the documented caller→gate payload handoff
(`/tmp/issue-<N>-inline-payload.txt`, ISSUE-keyed) is a shared mutable path
between payload-write and gate-read while the workflow explicitly supports
multiple concurrent inline rounds per issue — a TOCTOU that produces FALSE
CERTIFICATION. Fix the path contract + close the gate's own mid-run re-read
window.

Acceptance criteria:

1. `scripts/inline_lint_gate.py` REFUSES a `--payload-file` whose basename
   matches the bare legacy shape `issue-<digits>-inline-payload.txt`
   (fail loud, exit 3 via the existing `Inconclusive` path, message naming the
   round-unique requirement + this task number). Refusal fires BEFORE any leg
   runs (no 2.5-6 min burn on a doomed invocation).
2. Round-unique payload files (e.g.
   `/tmp/issue-<N>-r2-fu1-inline-payload.txt`) and arbitrary non-legacy names
   (existing tests use `payload.txt`) are accepted unchanged.
3. The gate reads the caller's payload file EXACTLY ONCE: after the initial
   read + content snapshot, it materializes its own private `mkstemp` copy and
   hands THAT to the map leg (`--map-files`), unifying with the existing
   `--paths` branch — a mid-run overwrite of the caller's file can no longer
   redirect the mapped-test set (defense-in-depth beyond path uniqueness).
4. The gate prints ONE payload-binding audit line BEFORE the verdict line:
   `inline_lint_gate: payload-source <path|inline-paths> n=<k> list-sha256=<12 hex>`
   (sha over the sorted resolved payload path list). The terminal verdict
   lines (`inline_lint_gate: PASS` / `BLOCK (...)` / `INCONCLUSIVE (...)`)
   stay BYTE-STABLE — no consumer grep breaks.
5. Every main-tree recipe copy teaches the round-unique shape and none
   teaches the bare legacy shape: `.claude/hooks/guard_root_code_commit.sh`
   block-message recipe (~L1539-41), `.claude/skills/issue/SKILL.md`
   Step 9a-ter § Inline payload lint gate (recipe lines + the single-flight
   probe pattern + the "suffix anchors the issue number" prose),
   `.claude/agents/analyzer.md` (~L272),
   `.claude/rules/analyzer-section-reference.md` (~L364), and the gate's own
   module docstring (~L72).
6. The SKILL.md single-flight probe pattern still detects a live same-issue
   gate WITHOUT sibling-issue false matches under the new shape:
   `--pattern 'issue-<N>-[^ ]*inline-payload\.txt'` (matches the round-unique
   shape AND the legacy bare shape during transition; `issue-194-[^ ]*` cannot
   match `issue-1948-...` because the char after `194` is `8`, not `-`).
   Single-flight semantics are KEPT (audit files
   `/tmp/issue-<N>-inline-lint.txt` / `-inline-map.txt` remain issue-keyed
   overwrites by scoping decision — see § Method delta).
7. Tests: (a) legacy-shape refusal (exit 3, message names the round-unique

   names accepted; (c) map leg consumes a PRIVATE copy, not the caller path

   `tests/test_issue_skill_inline_gate_pin.py`: SKILL.md recipe + hook recipe

8. `scripts/workflow_lint.py` no-flags run + ruff on touched files pass; the

## Method delta (what differs from prior related work)

Prior gate fixes (#2023 PASSES-section false-block, #1889 untracked-payload
scan seam, #1857 cert-retry re-hash) all changed VERDICT semantics. This
change touches only the CALLER→GATE HANDOFF contract: path shape validation +
a private read-once copy + an audit line. Verdict semantics, cert keying
(`/tmp/eps-inline-lint-cert-v1.txt`, per-(path, content-hash), flock-guarded
— SAFE to share per the #1768 second-round evidence on this task), exit
codes, and the hook's cert validation are byte-unchanged.

Scoping decisions (planner calls, per the task body's delegation):

- **Refuse-legacy (not warn-once):** fail loud beats silent
  cross-certification (body's stated preference). In-flight rounds using the
  old recipe get exit 3 + a self-explanatory message; the hook's printed
  recipe — the main propagation channel — is updated in the same commit.
- **Refusal exit code = 3 (Inconclusive), not a new code:** SKILL.md
  consumers already handle exit 3 as "instrument did not run — fix and
  re-run"; a legacy-path caller re-runs with a fixed path. No new exit-code
  vocabulary.
- **Audit files stay issue-keyed:** the task's own 22:50Z evidence note
  scopes the fix to the payload LIST path + recipes; audit files are
  report-only (never verdict inputs), and the KEPT single-flight probe
  remains their protection. Deliberately out of scope.
- **Single-flight guidance KEPT:** round-unique paths make a race
  non-catastrophic (no cross-certification), but the probe still prevents
  double-burning the ~2.5-6 min legs and audit-file clobber. The SKILL.md
  parenthetical that justifies the probe is reworded (payload clobber is no
  longer the reason; leg duplication + audit clobber are).
- **`--paths` route untouched:** already private-mkstemp, collision-free.
