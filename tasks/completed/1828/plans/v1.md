## Method delta (design decision)

Two semantics changes inside the token loop, exactly the filed sketch:

- **Trailing-punctuation strip**: `value = value.rstrip(":;,.")`. Legitimate values never end in
  these characters by convention — labels are kebab-slugs; `worktree=`/`log=`/`harvest=` paths end
  in a path segment or `/`; `pid=`/`round=` are integers; `choom=ok|failed`; `stage=`/`subagent=`
  are hyphenated words. A glued sentence-punctuation character is always prose contamination.
  The strip set is exactly `:;,.` (no `)`/`]` — bracketed prose tokens like `[phase=done]` bind
  harmless unused keys and must not be reinterpreted; keeps the #931 pin behavior).
- **First-non-empty-wins**: `if value and key not in fields: fields[key] = value`. Canonical
  fields lead every breadcrumb note by convention (`stage-dispatch stage=… round=… label=… pid=…`),
  prose follows — so first-wins protects the canonical block from prose re-binds, and the
  `if value` guard means a bare `key=` token never binds at all. No test pins last-wins (grepped
  tests/ 2026-07-30: zero hits).

**Known, accepted behavior delta** (name in the diff + tests): task_workflow.py:3097
(`positive_compute = "pid" in fields or …`, the tick-triage breadcrumb-missing-line severity)
currently sees a malformed bare `pid=` (empty value) as key-present → severity `warn`; post-change
the key does not bind → severity `info`. This is the CORRECT direction (an empty pid is not
positive compute evidence). All other consumers use `.get(...)` with falsy/int guards and are
behavior-identical or strictly improved (tick_triage `int("")` ValueError-skip becomes a
key-absent skip).

## File paths + concrete diffs

1. `src/explore_persona_space/task_workflow.py` — `_breadcrumb_fields` (line ~1907):

```python
_BREADCRUMB_VALUE_TRAILING_PUNCT = ":;,."


def _breadcrumb_fields(note: str) -> dict[str, str]:
    """Parse a ``stage-dispatch`` note's ``key=value`` tokens (whitespace-split, order-free).

    Hardened (#1828, incident #1689): trailing sentence punctuation is stripped from values
    (``label=foo:`` -> ``foo``) and binding is FIRST-non-empty-wins — a later bare ``key=``
    prose substring can neither re-bind an already-parsed field nor bind an empty value.
    """
    fields: dict[str, str] = {}
    for token in note.split():
        key, sep, value = token.partition("=")
        if not sep:
            continue
        value = value.rstrip(_BREADCRUMB_VALUE_TRAILING_PUNCT)
        if value and key not in fields:
            fields[key] = value
    return fields
```
