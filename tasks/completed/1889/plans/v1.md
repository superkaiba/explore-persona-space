# Plan v1 — #1889 workflow-fix: inline payload lint gate blind to untracked payload files

## Plan Summary

Make the Step 9a-ter inline payload lint gate (`scripts/inline_lint_gate.py`) able to
catch invariant violations in brand-new, still-UNTRACKED payload files, by threading the
payload path list into the mapped-pytest leg's environment
(`EPM_SCAN_EXTRA_FILES`) and having the tracked-file-enumerating scan test
(`tests/test_shared_vm_thread_caps.py::_scan_targets`) union those paths into its scan
set. Non-architectural: additive env-var seam, no exit-code / CLI / operator-contract
change; env absent ⇒ byte-identical behavior everywhere else.

## Requirement + acceptance criteria (kind: infra)

**Requirement.** A payload file that is untracked at gate time and carries a
heavy-import-before-`load_dotenv()` violation must produce a payload-naming hit in the
gate's mapped-pytest leg (⇒ BLOCK, exit 1), instead of silently passing and landing red
on trunk (#1388 fleet-red class; realized 2026-07-30 at `606278aa38` on #1739, and again
at `04e111a7ad` — the currently-live main red tracked by #1951).

**Acceptance criteria:**
1. With the fix, an untracked `scripts/<new>.py` violating the #847 dotenv-ordering
   invariant, listed as gate payload, yields `test_no_new_torch_before_dotenv_vm_entrypoints`
   red naming that path when the test runs with `EPM_SCAN_EXTRA_FILES=<path>` — verified by
   a live smoke against the real test (scratch untracked file, then removed).
2. `_scan_targets` with the env var UNSET is byte-identical to today (existing tests
   stay green; the Step 9c/10d gates, which run the test without the var, are unaffected).
3. The gate sets the var ONLY on the mapped-pytest child env (never mutates the parent
   process env or the shared-root index; no `git add` anywhere).
4. Grandfather currency tests (`_assert_block_entries_current` callers) stay green —
   the union only widens `_scan_targets`, never shrinks it, and grandfathered entries
   remain tracked-only by their own asserts.
5. New unit tests on BOTH sides of the seam pass (gate-side env threading;
   test-side union semantics).

## Method delta (vs the candidate's two sketched options)

Chosen: **option (b) — env-var threading**, unconditional on the pytest leg.
Rejected: **option (a) — fail-loud "stage your payload first" (INCONCLUSIVE on
untracked payload)** because (i) it changes the operator contract for every session
following the SKILL.md 9a-ter fenced recipe (which does not stage before the gate) and
would require a Step 9a-ter SKILL.md edit + fleet relearning; (ii) it widens the
staged-file window in the SHARED repo root by the gate's 2.5-6 min wall (the #1894
concurrent-sweep hazard class); (iii) env threading achieves the same detection with
zero operator change and zero index mutation. A stderr NOTE (not a block) still names
untracked payload paths for the audit trail.

Generality: the clarifier's sweep (`grep -rln "ls-files" tests/`) found
`tests/test_shared_vm_thread_caps.py` is the ONLY mapped invariant test that enumerates
git-tracked files (other hits are mocks/fixtures). The env-var name is deliberately
generic so a future tracked-only scan test can consume the same var; the gate-side
threading is test-agnostic (always exported on the pytest leg).

## File paths + concrete diffs

1. **`scripts/inline_lint_gate.py`**
   - New module constant: `SCAN_EXTRA_FILES_ENV = "EPM_SCAN_EXTRA_FILES"`.
   - `_run_leg(...)` gains an optional `extra_env: dict[str, str] | None = None`;
     when given, both branches pass `env={**os.environ, **extra_env}` to
     `subprocess.run` (override branch included, so hermetic tests can observe it).
   - `run_legs(...)` gains the payload list (param or re-read; implementer's choice)
     and passes `extra_env={SCAN_EXTRA_FILES_ENV: os.pathsep.join(payload)}` on the
     mapped-pytest leg ONLY (lint + map legs unchanged).
   - Untracked-payload audit note: for each payload path where
     `git ls-files --error-unmatch -- <p>` is non-zero, print
     `inline_lint_gate: note: payload <p> is untracked — threaded via EPM_SCAN_EXTRA_FILES
     for tracked-file-enumerating scan tests` to stderr (report-only, never a verdict input).
   - Module docstring: document the new seam + why (this task's incident).

2. **`tests/test_shared_vm_thread_caps.py`**
   - `_scan_targets(root)`: after building the tracked-filtered list, read
     `EPM_SCAN_EXTRA_FILES` (`os.pathsep`-separated, repo-relative paths); for each
     entry that exists under `root`, apply the SAME class rules —
     `scripts/**/*.py` always; `src/explore_persona_space/experiments/**/*.py` only
     with a module-top `__main__` guard; anything else ignored — and union (dedup)
     into the returned list. Missing paths are silently skipped (a stale env var must
     never crash an unrelated pytest run; the gate's own `read_payload` already
     fail-louds on missing payload). Docstring updated (the tracked-only rationale
     paragraph gains the "except gate-threaded extras" clause + why).

3. **New tests**
   - `tests/test_shared_vm_thread_caps.py`: `test_scan_targets_env_extra_unions_untracked`
     (tmp_path git repo: `git init` + one committed `scripts/a.py` + one untracked
     `scripts/b.py`; env unset ⇒ b absent; env set (monkeypatch) ⇒ b present, dedup holds
     when the extra is also tracked; missing path ignored; an
     `experiments/**` extra without a `__main__` guard stays excluded).
   - `tests/test_inline_lint_gate.py`:
     `test_pytest_leg_env_carries_scan_extra_files` — hermetic via
     `EPM_INLINE_GATE_PYTEST_CMD` printing the var (plus a `1 passed` line so the
     summary check holds); assert the payload path appears in the captured pytest
     output / audit file. `test_untracked_payload_note_printed` — stderr note names
     the untracked payload path; a tracked payload prints no note.

No changes to: `select_step9c_tests.py` maps, WORKFLOW_INVARIANT, workflow.yaml,
SKILL.md (operator recipe unchanged by design), guard hooks, cert format.
