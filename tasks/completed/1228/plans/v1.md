## 0.0 TL;DR (plain English)

- **What I'll change:** I'll add an optional boolean `wf_fix` key (default `true`) to the daily filing driver's manifest items. When an item sets `wf_fix: false` (an experiment-code bug, not a workflow-surface gap), the driver files it with only the `daily-auto-filed` tag — no `wf-fix` / `wf-fix-fp:<fp>` tags, no `## Provenance` `workflow_fix_target:` injection, no fp-based dedup — exactly what the daily SKILL.md route-2 prose already promises. I'll sync the SKILL.md wording and add tests.
- **What I expect:** every existing manifest (no `wf_fix` key) behaves byte-identically to today; a `wf_fix: false` item stops mis-tagging as workflow-surface, stops polluting the wf-fix dedup key space, and stops wrongly arming the workflow-fix recursion guard on its spawned session.
- **What would change my mind:** finding a downstream consumer that requires the `wf-fix` tag or the injected Provenance block on ALL daily route-2 filings (none found — see Kill criteria).

def _wf_fix_enabled(item: dict) -> bool:
    """True when this route-2 item participates in the wf-fix key space (#1228).

## 11. Decision Rationale

N/A — no model training (no hyperparameters; entries below are design decisions per the brief's template).

1. **Flag name `wf_fix`, manifest-item level.**
   - What: optional per-item JSON boolean.
   - Why: the variant is per-ITEM (one nightly manifest mixes workflow-surface and experiment-code fixes), so a CLI flag on the driver would be the wrong grain; snake_case matches the JSON manifest's existing keys.
   - Source: task #1228 body diff sketch ("manifest item key wf_fix (default true)"); SKILL.md ~L403 variant prose.
   - Alternatives: driver-level `--no-wf-fix` flag (wrong grain); a `target`-path heuristic (auto-classify workflow-surface by path prefix — rejected: the workflow surface list in `workflow-fix-on-bug.md` has `src/` carve-ins/outs that a prefix match would misclassify; explicit beats inferred).
2. **Default `true`.**
   - What: `item.get("wf_fix", True)`.
   - Why: preserves byte-identical behavior for every existing manifest and all 20+ existing tests; the conservative default matches today's driver AND the parked-candidate provenance (#1173/#1180 both describe the drop-tags variant as the exception path).
   - Source: task body diff sketch; existing `test_route2_files_with_tags_and_parsed_id` as the frozen contract.
   - Alternatives: default `false` (silently strips dedup/recursion-guard from every existing nightly — the opposite regression).
3. **One shared predicate `_wf_fix_enabled` across all four gate sites.**
   - What: tag block, injection block, dedup call, dry-run mirrors all call the same function.
   - Why: the driver's own L501-503 comment states the invariant "the tag and the durable recursion-guard body signal cannot diverge on the driver path (#1173)" — a shared predicate makes divergence structurally impossible rather than convention-guarded.
   - Source: `scripts/daily_drive_filings.py` L500-503 comment; #1173 lineage.
   - Alternatives: inline `item.get("wf_fix", True)` at each site (four copies of the condition = four chances to diverge later).
4. **Skip fp-dedup for `wf_fix: false` items.**
   - What: `find_open_fp_duplicate` is not called for them (production and dry-run).
   - Why: the dedup key surface is the `wf-fix-fp:<fp>` tag / body fingerprint (per `find_open_fp_duplicate`'s docstring L308-318 and the dedup-predicate spec in `workflow-fix-on-bug.md` § Dedup), which these items never populate — participation would be one-way (they could be suppressed by a same-fp workflow-fix task but never protect against their own re-filing), a misleading asymmetry. The remaining double-file protections are wf_fix-independent: slug-keyed ledger resume (`_slug_state`) and the title-scan recovery keyed on `daily-auto-filed` + `id_floor`.
   - Source: `find_open_fp_duplicate` docstring; `ROUTE_RECOVERY_TAG` L67; SKILL.md ~L414 (fp-dedup framed as the wf-fix-channel kill-window backstop).
   - Alternatives: keep the scan (harmless in the common case, occasionally catches a cross-channel same-text re-raise) — rejected for the asymmetric semantics; documented as a must-ask deviation in §10.
5. **Fail-loud bool type check in `load_and_validate_manifest`.**
   - What: non-bool `wf_fix` raises `ValueError` before any filing.
   - Why: JSON `"false"` is truthy — silently accepting it would apply full wf-fix semantics to an item the author marked non-workflow-surface, recreating this task's bug in a harder-to-spot form; matches the function's existing fail-loud-at-zero-filings contract (L163-167).
   - Source: `load_and_validate_manifest` docstring + existing route/keys checks; CLAUDE.md "Fail fast".
   - Alternatives: coerce strings ("false"→False) — rejected, silent-defaults are the project's named anti-pattern.
6. **Ledger rows unchanged (fp still recorded on all rows).**
   - What: no schema change to `filed.jsonl`.
   - Why: `fp` is a content hash of `(change, bug)` — well-defined for any item, useful audit data, and no consumer treats a row's `fp` as a wf-fix claim (resume keys on slug, recovery on title/tag/floor, the daily-file record on outcome/id). The brief's expectation ("they shouldn't" need changes) confirmed by read.
   - Source: ledger row shapes, module docstring L20-30; consumers `_slug_state` / `_try_recovery` / SKILL.md ~L477.
   - Alternatives: add `wf_fix` to rows (allowed-deviation, §10; not required — the manifest in the same durable dir already records it).
7. **Route-3 + `wf_fix` key: type-checked, semantically ignored.**
   - What: predicate returns False for route 3 regardless.
   - Why: route 3 never applies wf-fix tags today; rejecting the key on route 3 would add validation surface for zero safety gain.
   - Source: `_filer_cmd` L352; `test_route3_files_held_tags_no_dispatch`.
   - Alternatives: raise on route-3 + `wf_fix` (more validation churn than the confusion it prevents).
