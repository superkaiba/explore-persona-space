# Plan — task #1905: verify_plan.py check-ignore on declared-committed paths

## §0.0 TL;DR

Add mechanical check **c44** to `scripts/verify_plan.py`: extract plan-declared
committed output/config paths and run `git check-ignore` on each; WARN when a
declared-committed path is gitignored with no force-add /
staged-index-verification note in the same section. Third incident in class
(#958 silent dir-add skip; #734 lane-unreachable reused input; #1900 plan
declared `data/issue_1900/config/{subset.json,arms.json}` "committed to the
issue branch" while `.gitignore` `data/*` matched — caught only by the round-1
Methodology critic). Change-my-mind line: if the check WARNs on more than ~20%
of a 20-plan recent-corpus calibration sweep with mostly indefensible hits,
the trigger vocabulary is too wide — tighten extraction instead of shipping a
noisy check.

## Goal / requirement

`verify_plan.py` (the Phase 1.5.0 pre-pass, which runs before any critic
spawns) mechanically catches the #1900 shape: a plan that declares a path as
committed-to-git while the live `.gitignore` would silently skip it under a
plain `git add` (exit 0, no error — the #958 signature), stranding clone-based
lanes (GCP, fellows) at their first config read (the #734 shape).

### Acceptance criteria

1. New check `check_committed_paths_not_gitignored` (cid
   `c44_committed_paths_gitignored`) registered in `CHECKS`; WARN-only,
   conditional, all kinds.
2. Positive control: a synthetic plan line declaring
   `data/issue_9999/foo.json` "committed to the issue branch" WARNs, naming
   the matching `.gitignore` rule (`data/*`).
3. Negative controls: (a) a TRACKED ignored-pattern path (the post-fix #1900
   state, force-added in commit 4f1d58d3ee) does NOT WARN — index-aware
   default `git check-ignore` semantics; (b) a same-section `git add -f` /
   force-add / staged-index-verification note suppresses the WARN; (c) the
   standalone escape `N/A — no committed outputs` SKIPs the check.
4. Fail-open: git unavailable / subprocess timeout → SKIP (never FAIL), c42
   precedent.
5. All new + existing `tests/test_verify_plan.py` tests pass; ruff clean on
   touched files.
6. Self-application: `verify_plan.py --issue 1905` on this very plan exits
   PASS (WARNs acceptable if acknowledged).

## Method delta (vs. prior art in the same file)

Same construction as existing subprocess-backed checks — c42
(`_c42_rev_parse`: bounded `subprocess.run`, 10 s timeout, one 0.1 s retry on
`OSError`, `None` → caller-side SKIP; module-level `_C44_REPO_ROOT`
monkeypatch seam per the c34/c41/c42 pattern). Novelty is only the trigger
grammar (commit-vocabulary lines + path extraction) and the use of
**index-aware** `git check-ignore` (default mode) so already-tracked paths
correctly read not-ignored — a tracked file rides the clone regardless of
ignore rules, which is exactly the #1900 post-fix state.

## Design

### Trigger (raw scan, fences INCLUDED — the c43 precedent)

Committed-path declarations live both in prose and in fenced `phase_outputs:`
YAML, so the scan is over raw lines (no `_fence_mask` exclusion). A line
triggers when it matches commit vocabulary:

```
_C44_COMMIT_VOCAB_RE = re.compile(
    r"(?i)(?:\bcommit(?:ted|s)?\s+(?:to|into|on)\s+(?:the\s+)?"
    r"(?:issue[-\s]branch|git\b|main\b|repo\b)"
    r"|\brides?\s+the\s+git\s+clone\b)"
)
```

### Path extraction from trigger lines

- Path-like tokens: `[A-Za-z0-9_.\-]+(?:/[A-Za-z0-9_.\-{},*]+)+` (must contain
  a `/`).
- Brace expansion: `data/x/{a.json,b.json}` → both members.
- Glob-bearing tokens (`*`): reduced to the deepest literal directory prefix
  (check-ignore on the directory).
- Excluded: absolute paths (`/workspace/...` etc. are pod-side, not repo
  paths), URL-ish tokens (contain `://`), tokens with no `/`.
- No extractable path on any trigger line → SKIP ("commit vocabulary without
  extractable repo paths").

### check-ignore invocation

One batched call per plan: `git check-ignore -v --stdin` with the extracted
paths on stdin, `cwd=_C44_REPO_ROOT`, `timeout=10`, `check=False`. Exit 0/1
are both healthy (some/none ignored); stdout lines give
`<source>:<line>:<pattern>\t<path>` for the ignored subset. Any
`TimeoutExpired` / `OSError` (after one 0.1 s retry on `OSError`) or exit
code ≥ 2 → SKIP fail-open ("git check-ignore unavailable — check
inconclusive"). Index-aware DEFAULT mode — deliberately not `--no-index`.

### Satisfier (same-section scope, per the task body)

For each ignored path, scan the SECTION containing its declaring line (from
the nearest preceding `##`/`###` heading to the next heading of the same or
higher level; plan preamble = its own section) for:

```
_C44_FORCE_ADD_RE = re.compile(
    r"(?i)(?:git\s+add\s+(?:-f\b|--force\b)|\bforce[-\s]add"
    r"|staged[-\s]index[-\s]verif|ls-files\s+--others\s+--ignored)"
)
```

Present → that path is satisfied (no WARN). Plan-wide satisfiers are
deliberately NOT accepted — a global mention elsewhere must not silence a
specific declared path.

### Escape + verdict

- Standalone escape via the shared helper:
  `_standalone_na_declared(plan, r"no committed outputs\b")` → SKIP.
- Ignored + unsatisfied paths → **WARN** listing each path with its matching
  gitignore rule and the remedy (force-add with staged-index verification per
  the /issue Step 9a-ter § Staged-index verification recipe, or relocate the
  output out of the ignored root, or drop the committed claim).
- Trigger fired, no path ignored → PASS.
- No trigger lines → SKIP.

WARN-only (not FAIL): the declaration may be satisfiable by an
implementation-time force-add the plan simply forgot to note; the critic
ensemble stays the judgment layer. Mirrors the majority conditional-check
posture (c43 et al.).
