### 4.1 New module-level regexes (place near `_PER_UNIT_FIG_RE`, ~line 2134)

```python
# Check 36: any markdown link (image embeds are masked out before this
# scans, so no lookbehind is needed); link text tolerates `]` not
# followed by `(` — the same tolerance _IMAGE_RE uses.
_MD_LINK_RE = re.compile(r"\[(?:[^\]]|\](?!\())*\]\(([^)]+)\)")
# A figures/issue_<K>/... PNG path inside a link URL, ANY host form
# (raw-GitHub, github blob, relative). Captures the repo-relative path.
_LINKED_ISSUE_PNG_RE = re.compile(
    r"(?P<path>figures/issue_(?P<issue>\d+)/[^)\s?#]+\.png)", re.IGNORECASE
)
```

### 4.2 New check function (place after `check_orphaned_per_unit_figures`, ~line 2519)

```python
def check_linked_not_embedded_figures(body: str, *, issue: int | None = None) -> CheckResult:
    """Check 36 (WARN, v4-only, #1371): a non-image markdown link in
    `## Results` to a `figures/issue_<N>/*.png` that no body image embeds."""
    name = "Results figures embedded, not linked"
    if not is_v4(body):
        return CheckResult(name, True, "non-v4 body — check applies to the v4 `## Results` section only")
    results_text = _v4_results_body(body)
    if results_text is None:
        return CheckResult(name, True, "no `## Results` section to scan")
    prose = _prose_layer(results_text)          # strip fences + <details>
    masked = _IMAGE_RE.sub("", prose)           # remove image embeds. NOTE: a
    # clickable-image wrapper [![alt](p)](q) leaves a residue link [](q)
    # after masking — that residue IS scanned; the q==p common case is
    # silenced by the embed subtraction below, and a wrapper whose click
    # target q is a PNG embedded nowhere deliberately WARNs (it is
    # linked-not-embedded by definition).
    # Whole-body EMBEDDED set — symmetric any-URL-form: extract the
    # repo-relative figures/issue_<K>/...png path from EVERY image embed
    # URL anywhere in the body (raw-GitHub, blob, relative alike;
    # SHA-independent by path capture). Deliberately NOT
    # _referenced_figure_paths(), which is raw-GitHub-only — check 4b is
    # Results-section-scoped and accepts non-raw absolute URLs, so a
    # legitimate Methodology-placed or blob-URL embed would otherwise
    # false-positive this WARN (fact-check finding, plan v2).
    embedded: set[str] = set()
    for im in _IMAGE_RE.finditer(body):
        iu = im.group(1).strip().split(None, 1)[0] if im.group(1).strip() else ""
        ipm = _LINKED_ISSUE_PNG_RE.search(iu)
        if ipm:
            embedded.add(ipm.group("path"))
    linked: dict[str, None] = {}                # ordered de-dupe: path -> None
    for m in _MD_LINK_RE.finditer(masked):
        url = m.group(1).strip().split(None, 1)[0] if m.group(1).strip() else ""
        pm = _LINKED_ISSUE_PNG_RE.search(url)
        if not pm:
            continue
        if issue is not None and pm.group("issue") != str(issue):
            continue                            # cross-issue links are legitimate references
        path = pm.group("path")
        if path in embedded:
            continue                            # embedded anywhere in the body -> discipline satisfied
        linked.setdefault(path)
    if linked:
        listed = ", ".join(f"`{p}`" for p in linked)
        return CheckResult(
            name, True,
            f"{len(linked)} committed figure(s) referenced as a markdown LINK in `## Results` "
            f"but embedded by no body image: {listed} — embed it inline under the relevant "
            "`### <result>` (an `![...](...)` embed anywhere in the body silences this WARN), "
            "or acknowledge the deliberate link in the body (the standing WARN-ship rule); "
            "substantive owner: clean-result-critic Lens 11 (incident #1315)",
            is_warn=True,
        )
    return CheckResult(name, True, "no linked-but-unembedded `figures/issue_<N>/` PNGs in `## Results`")
```

Why code, not a model call: this is a deterministic syntactic predicate over markdown link syntax inside a mechanical verifier — the LM path (Lens 11) already exists and is precisely what failed to be sufficient on #1315.

### 4.5 Design decisions (the four questions, settled)

1. **Scope: v4 `## Results` only; non-v4 → vacuous PASS.** Matches the Goal verbatim; all new bodies are v4; a follow-up round folding onto a v3 body migrates it to v4 (SPEC.md § Follow-up consolidation), so v3 coverage arrives for free at the only moment a v3 body is edited. Newly WARNing grandfathered v3/v2 bodies on re-verification would create acknowledge-churn on bodies nobody edits — against the forward-only spirit even though WARNs are technically permitted.
2. **Regex: mask-then-match, any URL form (mechanics corrected in v2).** Masking image embeds first (`_IMAGE_RE.sub("")`) fixes the sketch's line-start miss of `[^!]\[` (no lookbehind needed at all). For the clickable-image nesting `[![alt](p)](q)`: masking removes the INNER image only, leaving a residue link `[](q)` that IS scanned — the common q==p wrapper is silenced by the embed subtraction (p is embedded), and a wrapper whose click target q is an unembedded PNG deliberately WARNs (correct semantics: q is linked-not-embedded). Any URL form containing `figures/issue_<K>/…png` matches (raw-GitHub, blob, relative) — the embed-vs-link discipline is host-independent; `_LINKED_ISSUE_PNG_RE.search` on the URL extracts the repo-relative path uniformly. PNG-only, deliberately: a PDF cannot render inline in dashboard markdown, so a PDF link is the only correct reference form and must never WARN (mirrors check 31's PNG-only rule, :2490).
3. **Acknowledgment escape: embed-anywhere silences; otherwise the standing WARN-ship rule.** The primary escape is structural — the linked path appearing in the whole-body EMBEDDED set (an image embed anywhere, including `## Methodology`; ANY URL host form, extracted symmetrically via `_LINKED_ISSUE_PNG_RE` on each `_IMAGE_RE` URL; SHA-independent) means the discipline is satisfied. v2 correction: `_referenced_figure_paths` is NOT used here — it is raw-GitHub-only, and check 4b (Results-scoped, non-raw-absolute-URL-tolerant) does not guarantee every rendering embed is a raw URL, so the raw-only helper would false-positive on legitimate blob-URL or Methodology-placed embeds. A check-31-style stem-in-prose escape is IMPOSSIBLE here by construction: the link itself puts the stem in the body, so it would self-silence — exactly the hole being closed. A deliberate link therefore ships under the CLAUDE.md rule "WARNs ship only when acknowledged in body"; the WARN text names both outs.
4. **Issue scoping: own-dir only when `issue` is known; all dirs on `issue=None`.** A Results link to a PARENT's figure (`figures/issue_<M>/…`) is a legitimate cross-reference, not an embed candidate — embedding another task's figure is not this body's duty. Exact mirror of check 31's scoping (:2469-2472) including the documented `--body-stdin` fallback caveat.
