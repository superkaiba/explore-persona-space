# Plan v1 — #2153 Detached HF transfers must have timeout + observable progress

`kind: infra` (workflow-surface). No research question, no promotable clean-result;
completes on the Step 9c test-verdict path.

## Requirement

Make an hf-xet download read-hang DETECTABLE from outside the process, and stop
`snapshot_download(allow_patterns=...)` being reached for on the ~1M-file data repo.

The #1739 signature to eliminate: a detached HF transfer that is frozen is
**indistinguishable from a healthy one** — near-zero CPU, zero-byte log, one open
socket, empty target, no error, no exit, indefinitely. Two jobs, ~90 min lost.

### The precise gap (deliverable 1)

`code-style.md` already carries a canonical progress-line convention —
`[<phase>] unit k/N <key> elapsed=<s>s`, flushed — but its trigger set is
**(T1) projected wall-time > ~1h OR (T2) unit count > ~50**. Both triggers are keyed
on loop SIZE. The #1739 hangs were:

- store staging: a handful of large files — trips NEITHER trigger, hung 32 min;
- quarantine relocation: 0.16 GB total — trips neither on size, hung 57 min.

An hf-xet hang is a per-FILE stall, not a long loop, so a size-keyed trigger
structurally cannot fire on it. **The requirement must key on the TRANSFER, at any
file count.** That is the load-bearing new claim in this plan.

`upload-policy.md` already states the other half ("retry absorbs RAISED transients
only — the hf-xet HANG class (no exception…)"), so the repo already knows retry cannot
catch this; nothing yet requires the observability that would.

### The discriminator that is actively wrong

`gotchas.md` hf-xet DOWNLOAD wedge entry (#1345) asserts:

> `ss -tnp` EMPTY for the pid — ZERO established connections (the discriminator vs
> the UPLOAD wedge's one frozen ESTAB socket)

#1739's two hangs were **DOWNLOADS with exactly ONE open socket**. As written the
discriminator would have routed the #1739 diagnosis to "this is an upload wedge, not a
download wedge" — the opposite of the truth. It must be corrected to: socket count does
NOT discriminate download-vs-upload wedge; either can present with zero or one socket.

## Deliverables + concrete file changes

### D1 — `.claude/rules/upload-policy.md`: new § "Detached HF transfers: timeout + observable progress"

The primary deliverable. Requires, for any HF transfer that runs detached / backgrounded /
outside a turn's own foreground (upload or download, **any file count**):

- **(a) A wall-clock timeout** bounding the whole transfer. Explicitly: the
  `EPM_HF_RETRY_BUDGET_S` retry budget is NOT a timeout — it bounds RAISED transients, and
  the hang raises nothing. Per-file `stage_hub_file` budgets are per-call, so an N-file
  prefix can serially burn ~N × budget without any single call exceeding it.
- **(b) Periodic flushed progress**, reusing the existing `code-style.md` canonical shape
  `[<phase>] unit k/N <key> elapsed=<s>s` — but with the trigger widened: a detached HF
  transfer owes progress **regardless of file count or projected wall-time**, because the
  failure is a per-file stall (the size-keyed T1/T2 triggers cannot fire on it).
- **(c) Completion keyed on process exit with a captured rc** — never on file existence and
  never on a non-empty log. This is the HF-transfer instance of the standing
  CLAUDE.md § Monitoring re-run discipline ("never key a done condition on bare file
  existence") and the #825 empty-dir false-DONE class.
- **(d) The invariant:** *0-byte log + empty target must not be a reachable
  "looks healthy" state.* If a transfer can present that way, it is missing (a)–(c).
- **(e) One worker per `local_dir`** — the body's out-of-scope concurrency hazard, recorded
  as a single line here (two concurrent `snapshot_download` calls into one `local_dir`, as
  #1739 also did). Cross-links the #833 entry's existing "ONE staging process" clause.
- Cross-references: the #833 enumeration entry, the #1345 wedge ladder, the FAILURE MATRIX
  entry, and `code-style.md`'s progress-line convention (so the widened trigger is
  discoverable from the size-keyed one).
- Records the **deliverable-4 decision** explicitly: xet stays ON by default; disables are
  scoped PER WORKLOAD, set inside the script before its `huggingface_hub` import (env is
  frozen at import). Rationale carried from the FAILURE MATRIX entry: the three transfer
  paths fail in disjoint domains, so a process-wide download-side disable would fix the
  small-file-storm leg and break the big-file leg (the plain path refuses > 50 GB).
  Reference impl: `scripts/issue1739_restore_partial.py:38-39`.

### D2 — `.claude/rules/gotchas.md`: correct the #1345 socket-count discriminator

In-place, net-neutral-or-smaller edit of the hf-xet DOWNLOAD wedge entry: replace the
"ZERO established connections (the discriminator vs the UPLOAD wedge's one frozen ESTAB
socket)" claim with the corrected reading — socket count does not discriminate; #1739
observed download hangs with exactly one socket. Keep `du -sb` frozen + `py-spy` parked in
`xet_get` as the load-bearing probes (those held up).

### D3 — `src/explore_persona_space/orchestrate/hub.py`: harden `stage_hub_prefix`

Give callers (b) + (c) by construction instead of per-call discipline:

- Emit a flushed progress line per completed file in the existing canonical shape, as
  futures complete (`as_completed`) rather than in submit order, so a stalled file is
  visible as an absence of advancing `k/N`.
- Emit a start line naming `repo_id@revision:prefix` and `N` files, so an empty target
  plus a 0-byte log is unreachable once the helper is entered.
- Add an opt-in wall-clock bound for the whole staging call, defaulting to off so no
  existing caller's behavior changes silently.
- Keep the existing contract intact: fail-loud on empty listing, `.result()` re-raise,
  `max_workers<=6`, one resolved revision, mirror-root `dest_dir` semantics.

### D4 — tests

New `tests/test_issue2153_detached_hf_transfer_contract.py`:

- Prose pins for the new `upload-policy.md` section (the (a)–(e) requirements present).
- A pin that the corrected `gotchas.md` discriminator no longer asserts socket count as
  the download-vs-upload discriminator.
- Behavioral test of the hardened `stage_hub_prefix` progress emission with the HF calls
  stubbed (no network): assert a start line and one progress line per file, flushed, in the
  canonical shape; assert the timeout bound fires when armed.
