### Edit 3 — `task_workflow.py`: cascade-coalescing previous-boundary walk (new helper + launch branch)

New helper next to `_adjacent_triage_coverage` (~L2843):

```python
def _cascade_prev_boundary(
    events: list[dict], boundary_idx: list[int], pos: int, i: int, cascade_s: float
) -> int | None:
    """Effective PREVIOUS boundary index for adjacency coverage, coalescing
    a machine launch CASCADE (#1400): one dispatch posts epm:cluster-launched
    (by backends.*) then epm:run-launched ~30-60s later, and the interposing
    sibling must not orphan the session's pre-launch triage note. Starting
    from the audited boundary at events index ``i``, walk left while the
    previous boundary is a line-LESS launch-kind record within ``cascade_s``
    seconds of the current anchor (gap CHAINED between consecutive cascade
    members, so a 3-record cascade coalesces while two attempts minutes
    apart never do). A missing/negative delta, a triage-line record, a
    non-launch kind, or ``cascade_s <= 0`` stops the walk (fail toward the
    strict pre-#1400 nearest-boundary semantics). Returns None when no
    previous boundary remains."""
    anchor = i
    p = pos - 1
    while p >= 0:
        j = boundary_idx[p]
        ev = events[j]
        if (
            cascade_s > 0
            and ev.get("kind", "") in TRIAGE_LAUNCH_KINDS
            and TRIAGE_LINE_PREFIX not in (ev.get("note") or "")
        ):
            d = _ts_delta_s(ev, events[anchor])
            if d is not None and 0 <= d <= cascade_s:
                anchor, p = j, p - 1
                continue
        break
    return boundary_idx[p] if p >= 0 else None
```

## 5. Design-question resolutions

**Q1 — WHERE + suppress-vs-downgrade.** Library (`_audit_record_violation`/`_make_triage_violation`), not watcher-side: the predicate and its documentation live there, the fix covers every consumer mechanically (grep confirms `triage_observer_pass` is the sole non-test consumer today, so behavior change is contained), and the watcher keeps zero violation logic. **Suppress entirely, not downgrade to info:** the documented contract says flags fire "against a non-empty candidate set" — honoring it means no flag; the nudge text itself would read "…while 0 advisory candidate(s) were pending in its window", a self-contradiction; an info row still burns sidecar fidelity and dedup keys (22 of the 65 zero-candidate rows are already info/warn breadcrumb noise); and a launch with an empty window is *vacuously compliant* — the duty is to read pending markers, and there were none (a compliant session may still post a note; its absence is not evidence of skipped triage). **Grace trim before the emptiness test, all classes:** adopted — a candidate landing within `grace_s` (120 s) of the record is the SKILL.md accepted residual (posted after the session's final enumerator run), so counting it for launch/breadcrumb while trimming it for none-with-candidates is an inconsistency with no rationale; the trim also keeps the #779 replay honest (14:54:43Z, 98 s pre-launch, trimmed; the real candidate 14:41:17Z carries the flag).

**Q2 — adjacency through cascades: option (iii), cascade coalescing at `cascade_s = 180 s`, chained, prev-side.**
- *Option (i) rejected* (scan ALL boundaries within adjacency_s backwards for a triage line): it genuinely weakens burst protection — a relaunch burst with attempts < 30 min apart (plausible: fast crash + quick fix; capacity-retry cadence) would inherit the PREVIOUS attempt's note, and it mechanically breaks the pinned `test_audit_burst_second_launch_not_covered_by_first_launch_triage` (note at 09:59 is within 1800 s of launch B at 10:05). The #1005 attempts happened to be 49 min apart, but the rationale "keeps crash-fix relaunch bursts individually duty-bound" binds precisely in the 2–30 min regime option (i) gives up.
- *Option (ii) as machine-`by` skipping rejected as the discriminator:* the pinned burst fixtures post launches `by="poll_pipeline"` — machine — so a `by`-based skip breaks the same pin; `by` cannot separate cascade siblings from burst attempts. Time gap can.
- *Option (iii) adopted:* consecutive **line-less launch-kind** boundaries within `cascade_s` of each other (chained anchor-to-previous) are one logical dispatch for the previous-side neighbor walk. Grounding for 180 s: observed cluster→run gaps 46 s / 39 s / 32 s (#1005 attempts 2/3/5 — the cascade is route()-internal marker latency, tens of seconds) → ~4× margin; strictly below the pinned burst spacing (300 s) and ~12× below the fastest observed real relaunch spacing (~35 min, the watcher-test fixture cadence; #1005's real spacing 49 min / 8 h). A triage-LINE launch record stops the walk (it must be examined for coverage, not skipped); malformed/negative deltas stop the walk (fail toward strict).
- **Named false-negative window:** a genuinely untriaged dispatch whose launch record lands within 180 s (chained) of a PRIOR line-less launch record, where a triage note sits before that cascade within 1800 s of the audited record, inherits coverage it did not earn. No workflow path emits two *independent* dispatches < 3 min apart (crash detection alone is multi-minute; router capacity rungs retry inside route() before any marker), so practical exposure ≈ nil — and the observer is non-gating advisory, so the cost of the residual is a missed advisory flag, never a blocked or mutated anything. Accepted and stated.
- **Interaction with fix (1):** on today's data fix (1) alone suppresses the cascade false flags (their gap windows are empty). Fix (2) prevents the successor false-positive class — a candidate posted mid-provisioning (window non-empty, note 2 min old) — and is pinned by a test fix (1) cannot satisfy (§6 test 4). Residual it creates: such a mid-cascade candidate is treated as covered by the pre-cascade note (it post-dates the note's read) — the same shape as the accepted grace residual, widened from 120 s to ≤ cascade-span + note gap, bounded by adjacency; acceptable for an advisory channel, stated in the docstring.

**Q3 — severity semantics unchanged elsewhere:** acceptance criterion 3. `launch-missing-line` stays warn; `breadcrumb-missing-line` keeps the three-way stage classification (warn on `pid=`/compute token, info unknown, exempt benign); `none-with-candidates` keeps info + signature-hit escalation to warn. Regression pins: `test_audit_launch_missing_line_flags_warn` (byte-unchanged), `test_audit_issue779_replay` (byte-unchanged), updated burst test.

**Q4 — docstring/state coherence:** Edits 3/4/5 cover `audit_dispatch_triage`, `_make_triage_violation`, `_adjacent_triage_coverage`, the watcher block comment + pass docstring, and the rule doc. Observer stays observe/alert-only — pinned by `test_triage_observer_never_calls_in_process_mutators` and the subprocess-argv-level pin (both untouched, must stay green); no marker schema, no status mutation, no new channel. State singleton/sidecar schemas unchanged (existing zero-candidate sidecar rows and flagged dedup keys are historical record; stale flagged keys are harmless — they only suppress re-flags of records that will no longer flag anyway).
