## 3. Design — per-file diff sketches

**Canonical rule text (stated once, mirrored):** for clean-result work, the `/humanize` hard ban gate (`check_bans.sh`) runs over an ELIDED copy of the body — the elided file IS the ban-gate input (an explicit repo-side override of the user-global skill's whole-body gate wording; the repo controls the file the unmodified `check_bans.sh` scans). Before the gate, produce the elided copy by removing the verbatim-quotation surfaces: (1) fenced ``` blocks (delimiters + contents), (2) `<details>...</details>` example blocks, (3) `>`-blockquoted lines (with or without a following space — the `^>` match is deliberately broader than the `> `-prefixed convention), (4) lines beginning `**Completion:**`. The elision FAILS LOUD: an unclosed fence or `<details>` block would otherwise silently elide everything to end-of-file and false-PASS the gate on the elided tail, so the awk program ends with `END{if(f||d) exit 3}` and the gate is chained on success — awk exit 3 = structurally unbalanced body = hard workflow error; fix the body structure, the gate does not run. A hit that SURVIVES elision is PRESUMPTIVELY authored prose — default disposition: real FAIL, rewrite it. If inspection shows the surviving hit is in fact verbatim sample text the elision missed (an indented fence, an inline `<details>`, a multi-line completion continuation), strengthen the elision (per the allowed-deviations license, applied identically to both full-text homes) so the sample is mechanically elided, and document the disposition — NEVER rewrite the sample. A hit whose ONLY occurrences were elided is a FALSE POSITIVE → the gate outcome is PASS-on-authored-prose; the sample is NEVER rewritten or scrubbed (that destroys scientific evidence); the disposition is DOCUMENTED in the `epm:humanize-loop` marker note naming the banned string AND its location (section/heading). Gaming guard: never move authored prose into a blockquote/fence to dodge the gate.

**Canonical elision one-liner** (deterministic; two sessions produce the same scoping because the input is the FULL body file and the transform is mechanical; the single-quoted awk PROGRAM must be byte-identical in both full-text homes — §4 check b):

```bash
awk '/^```/{f=!f; next} f{next} /^<details/{d=1} d{if(/<\/details>/)d=0; next} /^>/{next} /^\*\*Completion:\*\*/{next} {print} END{if(f||d) exit 3}' \
  <body-file> > /tmp/issue-<N>-ban-scan.md \
  && ~/.claude/skills/humanize/check_bans.sh /tmp/issue-<N>-ban-scan.md
```

Tested this session (§9 assumptions 16-17): all four surfaces elide (including no-space `>`-blockquotes); an authored `Certainly!` line survives and the real `check_bans.sh` FAILs it (exit 1); a sample-only fixture PASSes (exit 0); an unclosed fence and an unclosed `<details>` each yield awk exit 3 and the `&&` chain prevents the gate run.

I evaluated the alternative primary recipe (gate over the 9a-humanize step-1 EXTRACTED prose file) and rejected it as primary: extraction boundaries are judgment calls that vary between sessions, and it silently drops gate coverage of authored `## Methodology` prose. The elision recipe scans the whole body minus verbatim data — stricter, uniform across the orchestrator pass and the analyzer inline pass, and it is the #518-proven mechanism. Correct-by-construction property: a string appearing BOTH in a sample and in authored prose still FAILs, because the authored occurrence survives elision.

## 11. Decision Rationale

- **Primary recipe = whole-body elision, not extracted-prose-file gating.** What: gate the awk-elided full body. Why: deterministic (mechanical transform of a fixed input; extraction boundaries are session-dependent judgment), strictly MORE gate coverage (authored `## Methodology` prose stays scanned), and uniform across both invocation sites. The elided file is THE gate input for clean-result work (repo-side override of the user-global whole-body wording), not an optional workaround — otherwise sessions treat raw-body gating as the default and re-derive the exemption ad hoc (the #498/#518/#923 pattern). Source: #518's proven workaround + #923's in-scope-prose judgment (prior issues; no literature applies).
- **Fail-loud END guard on the elision.** What: `END{if(f||d) exit 3}` + `&&`-chained gate. Why: an unbalanced fence/`<details>` otherwise silently elides everything to EOF and the gate false-PASSes on the elided tail — the exact silent-failure class the project bans ("fail fast — never hide failures"). exit 3 is distinct from the gate's own 0/1. Source: Phase-2 critique union (statistics-Codex + alternatives-Codex + methodology-Claude concern); behavior verified by test this session (§9 #16).
- **Byte-identity check over prefix grep.** What: extract the full single-quoted awk program from both full-text homes, assert exactly 2 copies and 1 unique. Why: v1's prefix-only grep passed on divergent programs — the one drift mode the two-full-text-homes design must exclude; the identity check is also robust to §8 strengthening applied to both homes. Source: statistics-Claude Must-Fix; mechanics verified this session (§9 #18).
- **Edit 6 trimmed to a 102 B pointer (fallback: drop).** What: one pointer sentence, measured, with a post-edit `wc -c` gate. Why: the file has 142 B of grandfather headroom and v1's 288 B insertion would FAIL the no-flags lint; a cap bump touches `scripts/` (must-ask, and the cap comments say "none is licensed to grow"). Source: statistics-Codex Must-Fix; constants + byte counts verified this session (§9 #15).
- **Presumptive (not biconditional) surviving-hit wording.** What: a surviving hit is PRESUMPTIVELY authored; missed sample text routes to strengthen-elision + document, never sample rewrite. Why: the elision is a heuristic (multi-line completions, indented fences can slip through); a hard biconditional would force rewriting genuine sample text — violating the design's own core invariant. Source: critique wording set (a).
- **No new rule file.** What: canonical text lives in SKILL.md § 9a-humanize; mirrors point at it. Why: a new `.claude/rules/*.md` requires a LESSONS.md index entry + lint churn for a rule with exactly two full-text consumers. Source: LESSONS.md maintenance contract (CLAUDE.md always-on index bullet).
- **markers.md note-form example included, with location.** What: document the #923 disposition string — banned string AND its section/heading — as an allowed `epm:humanize-loop` note form. Why: the constraint requires the disposition be documented; a bare count is not auditable (a future reader cannot re-check the hit without the location). Free-text example, not a schema change. Source: #923's marker + critique wording set (d).
- **Paper-track one-liners included (Edits 5-6).** What: a sentence in analyzer-paper-mode.md + the trimmed pointer in methodology-writer.md. Why: the paper track REQUIRES verbatim worked examples + judge prompts (P7 lens) and runs `/humanize academic` — the identical false-positive exposure. Droppable per §8. Source: analyzer-paper-mode.md Step 4.5 bullet + methodology-writer.md line ~564, read this session.
