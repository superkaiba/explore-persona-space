## 3. Design — per-file diff sketches

**Canonical rule text (stated once, mirrored):** the `/humanize` hard ban gate (`check_bans.sh`) runs over AUTHORED PROSE ONLY. Before running it, produce an elided copy of the scan input that removes the verbatim-quotation surfaces: (1) fenced ``` blocks (delimiters + contents), (2) `<details>...</details>` example blocks, (3) `> `-blockquoted lines, (4) lines beginning `**Completion:**`. A hit that SURVIVES elision is authored prose → real FAIL, rewrite it. A hit whose ONLY occurrences were elided is a FALSE POSITIVE → the gate outcome is PASS-on-authored-prose; the sample is NEVER rewritten or scrubbed (that destroys scientific evidence); the disposition is DOCUMENTED in the `epm:humanize-loop` marker note naming the banned string + its location. Gaming guard: never move authored prose into a blockquote/fence to dodge the gate.

**Canonical elision one-liner** (deterministic; two sessions produce the same scoping because the input is the FULL body file and the transform is mechanical):

```bash
awk '/^```/{f=!f; next} f{next} /^<details/{d=1} d{if(/<\/details>/)d=0; next} /^>/{next} /^\*\*Completion:\*\*/{next} {print}' <body-file> > /tmp/issue-<N>-ban-scan.md
~/.claude/skills/humanize/check_bans.sh /tmp/issue-<N>-ban-scan.md
```

I evaluated the alternative primary recipe (gate over the 9a-humanize step-1 EXTRACTED prose file) and rejected it as primary: extraction boundaries are judgment calls that vary between sessions, and it silently drops gate coverage of authored `## Methodology` prose. The elision recipe scans the whole body minus verbatim data — stricter, uniform across the orchestrator pass (which has `/tmp/issue-<N>-humanize-loop.md`) and the analyzer inline pass (which has `.claude/cache/experiment-<N>-clean-result.md`), and it is the #518-proven mechanism. Correct-by-construction property: a string appearing BOTH in a sample and in authored prose still FAILs, because the authored occurrence survives elision.
