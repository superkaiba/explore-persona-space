- **Monitor until-condition composition — three shapes that wedge a watch or churn triage turns.** (0) PICK THE PRIMITIVE BY WAIT DURATION AGAINST THE HARNESS CEILINGS, not by notification count: a bg-Bash call — background included — is killed at its 600000 ms (10-min) ceiling, and Step 6d.2 is explicit that you NEVER compose a sleep longer than 540s into a single background Bash call, while a bg-Bash sleep-LOOP watcher is the #1310 banned shape. So a wait resolvable inside ONE ≤540 s segment may be a single bg-Bash `run_in_background` sleep+check; anything longer is EITHER the chained bg-Bash poll (one ≤540 s segment per call, re-armed per wake — the fixed 540s chain / `poll_pipeline.py`) OR a `Monitor` until-loop (≤45-min bounded segments per the item-1 wait-segmenting duty, or `persistent: true` per (c)). Step 9c 1b's gate wait and Step 6d.2's QUIET-WAIT are the SANCTIONED single-notification Monitors — #1739's watch failed on its CONDITION and its BOUNDS, not by being a Monitor. (a) KEY COMPLETION ON A COUNT DECREASE from the count captured AT ARM TIME (`base=$(probe); until [ "$(probe)" -lt "$base" ] || …`), never an absolute `live=N` — an absolute condition is ALREADY TRUE at arm time, so every arm and re-arm fires an immediate no-op event (#1739: 9 overnight re-arms, ≥6 turns spent classifying "baseline tick — not a real completion"). A decrease fires per completion BATCH, not only at zero, and each wake is a genuine re-baseline point. The probe MUST emit exactly one integer: an empty or non-numeric capture makes `[ … -lt … ]` a bash error (rc 2) and the loop spins on a broken probe — apply (b)'s probe hygiene. (b) NEVER `<count-cmd> || echo 0` INSIDE A CONDITION — the `CMD -c ... || echo 0` double-print entry above is the mechanism (two-line `"0\n0"` ⇒ the equality gate never matches ⇒ the watch wedges, failing OPEN); #1947's judge fan-out monitor wedged on exactly this shape and was `TaskStop`'d by hand. Prefer `pgrep -f 'patter[n]' | wc -l` — bracketing one character stops the pattern matching its OWN argv occurrence, and `wc` always emits exactly one line with rc 0 — but the bracket is NOT total: any OTHER occurrence of that literal in the same command line or a parent's argv still matches (measured: a probe on the same line as an unbracketed mention counted 2), so when the count must be exact use an rc-keyed probe whose EXIT CODE is the verdict (`scripts/step9c_baseline.py probe`, exit semantics deliberately inverted vs pgrep so `probe && launch` composes). (c) A SESSION-LENGTH WATCH IS `persistent: true`, not a re-armed bounded arm: `timeout_ms` DEFAULTS to 300000 ms (5 min — set it deliberately or inherit 5-minute expiry churn, the #1739 shape at a worse constant), caps at 3600000 ms (1 h), and is IGNORED when `persistent: true`, which runs for the session lifetime and is stopped with `TaskStop`. Each bounded expiry across a multi-hour wait costs a triage turn (#1739). A `persistent` Monitor never blocks a turn, so the ≤45-min wait-segmenting duty still binds through its `[watch-heartbeat]` emission. For a run the pipeline already polls, `poll_pipeline.py` bg-Bash stays first preference (#2014).
