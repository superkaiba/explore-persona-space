## 3. Design

### 3a. Hook — `scripts/guard_repo_root_branch.sh`

**(i) Pre-filter widening (line 102):**

```bash
- echo "$cmd" | grep -qE '\bgit\b.*\b(checkout|switch)\b' || exit 0
+ echo "$cmd" | grep -qE '\bgit\b.*\b(checkout|switch|restore|clean|reset)\b' || exit 0
```

**(ii) Clause gate widening (line 271):** same alternation swap. The gate stays loose (it is a cheap skip, not a classifier).

**(iii) `#`-comment clause skip** — in the driver loop, after the latch-reset block and before the `cd`-latch detection:

```bash
  # A clause whose first non-space char is `#` is a bash comment — bash never
  # executes it, so classifying it can only false-positive (SKILL.md fences
  # carry comments that SPELL gated forms, e.g. the Step 10d additive-checkout
  # fence). A comment containing a separator is mis-split and its tail clause
  # still classifies — that mis-split fails CLOSED (blocks), the safe direction.
  case "$clause" in "#"*) continue ;; esac
```

**(iv) Four new detectors in `classify_clause`**, inserted after the `switch --detach` detector and BEFORE the branch-arg classifier (so the pathspec reason wins over a wrong-reason commit-ish block and the `show-ref`/`rev-parse` subprocesses are skipped). Shared tight anchor: `\bgit +(-[^ ]+( +[^ ]+)?( +|$))*<verb>\b` — flag-group tolerates `--no-pager`, `-c k=v`, `-q`; a non-flag first token (`commit`, `log`, `add`) breaks the anchor immediately, so plain-English "restore"/"clean" in `-m` messages do NOT trip.

```bash
  # (#897) Working-tree revert via restore. Allowed ONLY when --staged (long
  # form) is present AND no --worktree / -W anywhere after `restore` —
  # index-only restore leaves the working tree untouched. Everything else
  # (bare `restore .`, explicit-path restore, --source forms, -S short form)
  # blocks, fail-closed: on the SHARED root any working-tree restore can
  # discard a CONCURRENT session's uncommitted edits (incident #841).
  if echo "$c" | grep -qE '\bgit +(-[^ ]+( +[^ ]+)?( +|$))*restore\b'; then
    if ! { echo "$c" | grep -qE '\brestore\b[^;&|]* --staged\b' \
           && ! echo "$c" | grep -qE '\brestore\b[^;&|]*( --worktree\b| -[A-Za-z]*W)'; }; then
      blocked="git restore (working-tree revert)"
    fi
  fi

  # (#897) Working-tree revert via checkout pathspec: a standalone ` -- `
  # separator (git checkout [<ref>] -- <path>), a bare `.`/`./...` positional
  # after checkout, OR a --pathspec-from-file(=|<space>) pathspec source
  # (round-1 Codex methodology Must-Fix: `git checkout HEAD
  # --pathspec-from-file=/tmp/files` is a real Git pathspec mechanism the
  # standalone-`--` form misses). `--detach`/`-b` never match (the `--` needs
  # a following space/EOL; the dot needs a preceding space). This FLIPS the
  # previous explicit-allow of `.` and the `--` skip — the #841 revert class.
  if echo "$c" | grep -qE '\bgit +(-[^ ]+( +[^ ]+)?( +|$))*checkout\b[^;&|]*( --( |$)| \.($| |/)| --pathspec-from-file(=| +))'; then
    blocked="git checkout <pathspec> (working-tree revert)"
  fi

  # (#897) Force-checkout: `git checkout -f|--force <anything>` discards
  # uncommitted edits even when the target is the CURRENT branch
  # (`git checkout -f main` prints "Already on 'main'" and silently reverts
  # dirty tracked files — round-1 Claude methodology Must-Fix, empirically
  # verified). There is no legitimate unqualified force-checkout at the repo
  # root (branch switches are already blocked; the `-C` waiver covers
  # deliberate scoped use). The `git switch` side is already strict (its
  # allow-arm admits only bare/quoted `main`), so this closes the checkout
  # asymmetry.
  if echo "$c" | grep -qE '\bgit +(-[^ ]+( +[^ ]+)?( +|$))*checkout\b[^;&|]*( -[A-Za-z]*f\b| --force\b)'; then
    blocked="git checkout --force (working-tree revert)"
  fi

  # (#897) git clean with a force flag (-f anywhere in a short cluster, or
  # --force) deletes untracked files fleet-wide (#841 lost 3 pre_reg + 4
  # images). Dry-run (-n) and bare `git clean` (refuses without force) stay
  # allowed.
  if echo "$c" | grep -qE '\bgit +(-[^ ]+( +[^ ]+)?( +|$))*clean\b'; then
    if echo "$c" | grep -qE '\bclean\b[^;&|]*( -[A-Za-z]*f| --force\b)'; then
      blocked="git clean --force (deletes untracked files)"
    fi
  fi

  # (#897) Runtime `git reset --hard` — the #778/#815 incident class; the lint
  # covers doc text only, this is the runtime tooth. Tolerates flags/refs
  # between reset and --hard (`git reset origin/main --hard`).
  if echo "$c" | grep -qE '\bgit +(-[^ ]+( +[^ ]+)?( +|$))*reset\b[^;&|]* --hard(=|\b)'; then
    blocked="git reset --hard"
  fi
```

**(iv-b) Bare-pathspec existence probe in the branch-arg classifier `*)` fall-through** (round-1 Alternatives Must-Fix, reconciler-binding): `git checkout <path>` with NO ref, NO `--`, and NO dot — the classic pre-`git restore` discard idiom (`git checkout tasks/running/841/body.md` is the exact #841 op) — currently no-matches every detector and falls through the `*)` arm where `show-ref` + `rev-parse` both fail → allow. Extend the `*)` arm: after both existing probes fail, run a pathspec-existence probe and block when the positional names a real path:

```bash
      *)
        if git -C "$REPO" show-ref --verify --quiet "refs/heads/$arg"; then
          blocked="git checkout $arg"                        # branch switch
        elif git -C "$REPO" rev-parse --verify --quiet "$arg^{commit}" >/dev/null 2>&1; then
          blocked="git checkout $arg (detaches HEAD)"         # sha/tag/remote-ref/HEAD~N
        elif git -C "$REPO" cat-file -e "HEAD:$arg" 2>/dev/null || [ -e "$REPO/$arg" ]; then
          blocked="git checkout $arg (working-tree revert of a tracked path)"  # bare pathspec (#841 op)
        fi
        ;;
```

An unresolvable arg (`git checkout "$BRANCH"` variable, a redirection token, a nonexistent name) keeps the status-quo allow — no new false-positive class (a non-branch, non-commit-ish, non-path arg errors in git anyway). Quoted-glob pathspecs (`git checkout '*.md'` — the probe fails on the unexpanded literal) remain a NAMED residual (§12 A9). This edit touches the existing classifier fall-through — carved out of §8 must-ask explicitly (see §8).

**(v) Case-arm comment fix (line 191-192, 218):** the `.`/`main`/`-` "left as ALLOW" comment becomes misleading — update it to note `.` is now caught by the pathspec detector above, and the `*)` arm now carries the pathspec-existence probe. The `-f|--force` entries in the case allow-list are now unreachable for blocking purposes (the force detector fires first) — update the comment accordingly.

**(vi) Block message (line 284):** generalize to name both hazard classes and both remediations:

> BLOCKED: '<reason>' would move the SHARED repo-root tree off main / detach HEAD / destroy uncommitted working-tree state. The repo root is the canonical commit target for every concurrent VM session; a working-tree revert here silently discards CONCURRENT sessions' uncommitted edits (incidents 2026-06-01, #815, #841). Do branch/destructive work in a worktree (`bash scripts/new_worktree.sh ...`; `git -C .claude/worktrees/<name> ...`). NEVER point `-C` at the repo root itself for a destructive op — for repo-root recovery use `uv run python scripts/sync_repo_root.py`. For marker-note text mentioning git commands, use `--file <path.md>` instead of `--note`; for commit messages, `git commit -F <file>`.

(Round-1 wording integration: the message must NOT teach `git -C <tree-root>` as a generic escape — the reconciler + both alternatives critics flagged that a `-C <repo-root>` self-qualification satisfies the waiver, which is a defensible deliberate-override design but should not be steered toward. Worktree-`-C` + sync_repo_root.py are the taught remediations.)

**(vii) Header comment:** update the contract paragraph + known-limitation examples (a `--note`/`-m` string containing a literal `git restore .`-class bigram now trips; the workaround is `--file` / `git commit -F`), note the tight-anchor design for the new detectors, and add TWO round-1-mandated statements: (a) an explicit THREAT-MODEL sentence — the hook gates ONLY Claude Bash tool calls; git run inside Python subprocesses (`sync_repo_root.py` has its own internal deny checker), cron wrappers, pod-side scripts, and SSH-MCP remote commands never pass PreToolUse, and non-git destruction (`rm`, `mv`, `>` truncation, `sed -i`) is out of scope by design; (b) a cwd-blindness sentence — the hook never consults the caller's actual `$PWD`, so a session whose cwd genuinely is a worktree running bare `git restore .` is blocked and should use `git -C` (the most likely source of kill-criterion-1 noise). Also note the `Bash("ssh ...")` raw-scan edge: a remote command string carrying `git checkout HEAD -- <file>` (the gotchas.md diverged-pod recovery) trips the guard; remediation is `git -C /workspace/... checkout HEAD --` inside the remote string, or the SSH MCP (which bypasses the Bash hook). Optionally add the `-C` to the gotchas.md:157 fence (1-line, in-scope, implementer's discretion).

**Why code, not a model call:** N/A-adjacent — this is a deterministic policy gate on every Bash call; a model call in a PreToolUse hook is not viable (latency, determinism, fail-closed requirements).

## 11. Decision Rationale

- **Hyperparameters:** N/A — no training hyperparameters (kind: infra). Also: N/A — no model training; N/A — no behavioral construct; N/A — not a replication; N/A — no artifact reuse.
- **Tight subcommand anchor for new detectors (vs the legacy loose `[^;&|]*` form).** What: `\bgit +(-[^ ]+( +[^ ]+)?( +|$))*<verb>\b`. Why: "restore"/"clean"/"reset" are common English words; the loose form would block `git commit -m "restore defaults"` — a new false-positive class the checkout/switch detectors never had at this base rate. Source: `_GIT_RESET_HARD_RE`'s flag-group design in `workflow_lint.py:3859` (same problem, same solution, #815). Alternative rejected: loose anchoring + accepting the false positives (bounces routine commits fleet-wide).
- **No hook allow-sentinel** (diverges from the body's diff sketch). Why: the existing hook has none; a command-string sentinel is a trivially promptable bypass, whereas `git -C <tree>` is the designed, auditable deliberate-override that already exists (line 268). The body's sketch is refined, not contradicted: the "-C-qualifier waiver" half is preserved and is the sole escape.
- **Lint flags wholesale forms only; hook blocks explicit-pathspec forms too.** Why: the live tree has 6 legitimate doc mentions of surgical `git checkout <ref> -- <path>` (Step 5a sync, Step 10d additive checkout, code-reviewer smoke-restore) — flagging them is pure sentinel noise; at runtime the same forms get a cheap `-C` remediation with a teaching block message. This asymmetry is the prescriptive-vs-runtime split.
- **`git restore --staged` allowed (long form only).** Why: index-only restore never touches the working tree; the short `-S` and any `--worktree`/`-W` combination fail closed. Alternative (block all restore) rejected: unstaging at the shared root is a legitimate concurrent-committer operation (CLAUDE.md § Concurrent repo-root committers requires explicit-path staging hygiene).
- **`#`-comment clause skip.** Why: executed SKILL.md fences carry comments that spell gated forms (SKILL.md:7835); skipping a true comment clause cannot leak (bash never executes it), and the separator-mis-split residue fails closed. Alternative (edit every offending fence comment) rejected: whack-a-mole.
