## §1 Goal

From the task body: produce a durable, reviewed decision on the gotchas.md byte
budget "so that the next unrelated task that touches the file is not forced into
an emergency editorial pass."

Two distinct failure modes have to be closed for that to hold:

| Mode | Mechanism | Closed by |
|---|---|---|
| (a) No headroom | 340 B free; any new entry (~1.2 KB mean) breaches the wall | Change A |
| (b) Headroom silently respent | the nightly appender writes past the wall with no budget check | Change B |

Closing (a) alone reproduces (b) on a timer, which is exactly how this task came
to exist. The task body already names this: the file "regrows without any human

## §3 Decision and its reasoning

### §3.1 Why the cap raise (option 2) is refused

The body conditions option 2 on "an argument that the ledger's growth is
legitimate." Growth *is* legitimate in the sense that all 163 entries are
operative — but a cap raise still fails the Goal on two counts:

1. **It does not close mode (b).** Raising 200 KB → 250 KB buys ~40 machine
   appends at the 1.2 KB mean. At the current arming (nightly, `K_RECUR = 2`,
   7-day window) that is a deferral, not a decision, and the next session to hit
   the new wall inherits the identical emergency — with a bigger file and a
   weaker precedent ("we raised it last time").
2. **The instrument is the project's only pressure against unbounded on-demand
   context.** gotchas.md is loaded whenever training / eval / orchestration /
   analysis code is touched. 199 KB is already ~50K tokens of on-demand load.
   Raising the cap by 25% raises that load with no offsetting mechanism.

The body's own guidance — "Do NOT loosen the FAIL threshold as a shortcut" —
therefore holds, and the thresholds stay untouched.

### §3.2 Why the trim alone is insufficient

A trim resets a counter. `promote()` then spends the recovered bytes at ~1.2 KB
per promotion with no human in the loop, and whichever unrelated session next
touches the file inherits an unreviewed editorial pass over a shared always-on
safety surface. That is mode (b), verbatim.

### §3.3 The durable half: the enforcement point moves to the growth agent

`promote()` becomes budget-aware. A refusal is safe — nothing is lost:

- bullets are re-derived from the `epm:failure-lesson v1` marker trail on every
  run, so a refused promotion is not a dropped lesson;
- `promote()` is already idempotent (the `T_DEDUPE` pre-check), so the promotion
  lands by itself on the first run after a human trims;
- refusal is precisely the "corrupting write" class the cron wrapper's own
  docstring already claims to fail loud on.

This also **restores meaning to the WARN constant**, which the zero-WARN test
pin had made unobservable: `GOTCHAS_SIZE_WARN_BYTES` becomes the *machine's*
hard ceiling, `GOTCHAS_SIZE_FAIL_BYTES` stays the *human's*, and the zero-WARN
pin stays as the human forcing function. No threshold changes; only who each
one binds.

## §4 Change A — trim `.claude/rules/gotchas.md`

### §4.1 Target

**≥12 KB recovered** (headroom ≥ 12.3 KB), stretch 15 KB. Sized against an
in-repo precedent, not a guess: sibling #2185's realized diff on this file is
`16 insertions / 26 deletions` — a net +22 B *after adding a new ~2.2 KB
entry*, i.e. ~3.4 KB of compression across 15 entries (~227 B/entry) that
**passed code review**. This plan targets the *largest* free entries, where
per-entry yield is higher: the 20 largest average 1,750 B, so a 35% cut on those
alone is ~12.2 KB.

Working budget: the ~40 largest entries outside #2185's locus, ~25-40% each.

### §4.2 Scope — excluded lines (live-sibling collision)

#2185 is live at `running` with this same file in its edit locus. Its touched
lines on `main` are **82, 92-93, 99-111, 139, 144, an insert after 218,
253-255, 269, 278, 280, 287-288**. The trim EXCLUDES those lines **and their
immediate neighbours** (83, 138, 140, 143, 145, 219, 268, 270, 279, 286, 289),
so the two changes do not contend for the same hunks. 141 of 163 entries remain
in scope — ample.

### §4.3 Per-entry method

For each entry, PRESERVE:

- (a) the bolded operative rule (the entry's first bolded span);
- (b) the diagnostic signature — the observable symptom, error string, exit
  code, or probe that identifies the trap;
- (c) the fix / remedy, including every env var, flag, path, and test path;
- (d) **every** `#N` citation, verbatim;
- (e) every backticked identifier.

REMOVE only: redundant framing, context restated twice within the same entry,
and lineage prose that merely re-describes an entry already cited by `#N`.

### §4.4 Mechanical verification of the trim (run by the implementer; output pasted into the implementation marker)

Three checks, all mechanical — the body's "confirm nothing is silently lost"
requirement is enforced, not asserted:

1. **`#N` conservation.** The multiset of `#\d{2,4}` tokens is identical before
   and after. A non-empty difference is a hard stop.
2. **Identifier conservation.** The set of backticked tokens is identical before
   and after, modulo an explicitly listed and justified diff.
3. **Pin grep.** Every literal removed by the diff is grepped against `tests/`
   and `scripts/workflow_lint.py`; any hit means a pin depends on that text and
   the cut is reverted.

```bash
cd "$WT"
uv run python - <<'PY'
import re, subprocess, collections
old = subprocess.run(["git","show","origin/main:.claude/rules/gotchas.md"],
                     capture_output=True, text=True, check=True).stdout
new = open(".claude/rules/gotchas.md", encoding="utf-8").read()
def refs(t): return collections.Counter(re.findall(r'#\d{2,4}', t))
def idents(t): return set(re.findall(r'`([^`\n]{1,120})`', t))
lost_refs = refs(old) - refs(new)
lost_ids  = idents(old) - idents(new)
print("bytes:", len(old.encode()), "->", len(new.encode()),
      "recovered:", len(old.encode()) - len(new.encode()))
print("LOST #N refs:", dict(lost_refs) or "none")
print("LOST identifiers:", sorted(lost_ids) or "none")
assert not lost_refs, "a #N citation was dropped — revert that cut"
PY
```

Plus the two binding gates: `uv run python scripts/workflow_lint.py` (no flags)
and `uv run pytest tests/test_workflow_lint_gotchas_size.py`.

## §5 Change B — budget guard in `promote()`

### §5.1 Threshold source

Import the constant — do **not** restate the literal (a second literal is the
#838 fixture-inversion failure mode). `scripts/consolidate_lessons.py` gains,
next to its existing imports, the same bootstrap the gotchas-size test already
uses:

```python
_SCRIPTS_DIR = Path(__file__).resolve().parent
if str(_SCRIPTS_DIR) not in sys.path:
    sys.path.insert(0, str(_SCRIPTS_DIR))

from workflow_lint import GOTCHAS_SIZE_WARN_BYTES  # noqa: E402
```

(The module is run as `scripts/consolidate_lessons.py` and loaded by tests via
`importlib.util.spec_from_file_location`, so it cannot rely on `scripts/`
already being on `sys.path`. `workflow_lint` is import-safe — the existing test
imports it the same way. An `ImportError` is a hard failure by design: a guard
that cannot read its budget must not fall back to writing blind.)

### §5.2 Behaviour

In `promote()`, after `new_text` is composed and **before** the write:

- compute `projected = len(new_text.encode("utf-8"))`;
- if `projected > GOTCHAS_SIZE_WARN_BYTES`: refuse the **whole** append — no
  write, no `add_touched` (so no commit), `counts.promoted` decremented back by
  the refused count and `counts.promote_refused_budget` incremented by it;
- log at ERROR, naming `projected`, the limit, the overshoot, and the trim
  recipe pointer, and **print every refused bullet verbatim** so the nightly log
  carries the content even if the 7-day marker window later ages the source
  markers out;
- raise, so the run exits non-zero (fail-loud, matching the module's existing
  hard-RAISE contract for corrupting-write conditions).

Refusal is all-or-nothing rather than partial-fill: a partial fill would leave
the file at exactly the wall with an arbitrary subset promoted and the rest
silently deferred — harder to reason about than a clean refusal, and it would
still need the human trim.

`Counts` gains `promote_refused_budget: int = 0`, surfaced in
`summary_dict()`. It is deliberately **not** added to `is_noop`'s terms: a
refused run mutated nothing, so it *is* a no-op for commit purposes.

### §5.3 Explicitly NOT doing

- Not changing either threshold, or `test_threshold_literals_pinned`.
- Not changing `test_live_tree_passes_clean`'s zero-WARN assertion.
- Not touching `T_DEDUPE`, `K_RECUR`, `--window-days`, or the cron schedule.
- Not adding a notification path for a refusal (see §10 residual 1).
- Not touching `.claude/rules/LESSONS.md` (see §12).

## §10 Risks and residuals

| Risk | Mitigation |
|---|---|
| An operative rule is weakened by compression | §4.3 preserve-list + §4.4 mechanical `#N`/identifier conservation + code-review ensemble reading the diff |
| A pin depends on removed text | §4.4 check 3 greps every removed literal against `tests/` + `workflow_lint.py` |
| Hunk collision with live #2185 | §4.2 excluded line set; #2185's status re-checked at Step 10d for Guard 5; Guard 4 (lost-update refusal, scope includes `.claude/rules/*.md`) is the mechanical backstop |
| 12 KB target not reachable safely | Kill criterion, §11 — surface the measured shortfall rather than cutting into operative content |
| Guard blocks a legitimate urgent promotion | Refusal is loud and the recovery is a trim; bullets re-derive on the next run (§3.3) |

**Residual 1 (named, not fixed here).** `scripts/cron_lesson_consolidate.sh`
ends with `exit 0` unconditionally ("the log file is the audit trail, no cron
email per routine pass"), so the guard's non-zero exit is swallowed at the cron
boundary: a refusal surfaces in `logs/lesson_consolidate/YYYY-MM-DD.log` and in
the counters, but sends no push. Wiring a notification is a separate change to a
different file with its own review surface — filed as a follow-up, not folded in.

**Residual 2.** The 7-day rolling marker window means a refusal persisting >7
days could age its source markers out before a trim happens. §5.2's
verbatim-bullet logging is the mitigation (the content survives in the log);
lengthening the window is out of scope.

## §11 Success criteria and kill criteria

**Success criteria (all required):**

1. `.claude/rules/gotchas.md` ≤ 188,000 B (≥12 KB recovered, ≥12.3 KB headroom).
2. §4.4 conservation: zero lost `#N` citations; identifier diff empty or
   explicitly justified.
3. `workflow_lint.py` (no flags) clean; `test_workflow_lint_gotchas_size.py`
   green with both threshold literals and the zero-WARN pin **unmodified**.
4. `promote()` refuses an over-budget append, leaves the file byte-identical,
   raises, and logs refused bullets verbatim — pinned by test case 3.
5. Test cases 1-6 green; ruff clean.
6. `git diff --stat` touches exactly: `.claude/rules/gotchas.md`,
   `scripts/consolidate_lessons.py`, `tests/test_consolidate_lessons.py`.

**Kill criteria:**

1. The trim cannot reach 12 KB without cutting operative content — STOP, record
   the measured achievable figure, and surface the shortfall with the evidence.
   Do **not** close the gap by raising a threshold.
2. Any `#N` citation cannot be preserved — revert that cut.
3. The guard cannot import `GOTCHAS_SIZE_WARN_BYTES` without an unacceptable
   import side effect — STOP and surface, rather than restating the literal.
