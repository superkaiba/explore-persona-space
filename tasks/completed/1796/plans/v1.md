# Plan — Issue #1796: extend c39's trigger regex with inverse-direction cross-phase-read vocabulary (corpus-calibrated)

## 1. Goal / requirement

Extend `scripts/verify_plan.py` c39's trigger regex (`_C39_TRIGGER_RE`, L6840) so that
INVERSE-DIRECTION cross-phase-read prose — a pod/GCE/SLURM phase consuming VM-produced
inputs — fires the same WARN-only `off_pod_phases:` declaration nudge that `off-pod` /
`vm-side` prose fires today, with the false-positive rate calibrated by a full
persisted-plan corpus re-scan per the c33 calibration precedent (verify_plan.py
L5674-5705). #1782 (commit `0d3b2cf46b`) generalized the SCHEMA + WARN text to
direction-agnostic reads but deliberately left the trigger two-direction-blind; the
check's own docstring names this as a KNOWN MECHANICAL RESIDUAL. This plan closes it.

**Not architectural:** WARN-only vocabulary widening inside one existing conditional
check; block name, satisfiers, semantics, kind gate all unchanged.

## 2. Method delta (vs #1782)

#1782 changed the SCHEMA (fenced-block shape, WARN text, docs) and left
`_C39_TRIGGER_RE` untouched. This change touches ONLY the trigger regex + the
docstring's residual paragraph + a calibration comment block + tests. No satisfier,
kind-gate, or WARN-text change.

## 3. Design — candidate vocabulary + calibration protocol

**Candidate trigger tokens** (grounded in the #1773 seam's real prose — its plan says
`VM-produced`; its incident was a GCE phase crashed loading VM-produced inputs — plus
the candidate block's sketch):

1. `\bvm-produced\b` (case-insensitive; matches `VM-produced` / `vm produced` NOT — the
   hyphenated form only unless calibration justifies `vm[- ]produced`). PRIMARY
   candidate — the canonical token in real plans.
2. `\bproduced on the vm\b` — prose variant.
3. `\bvm-built\b` / `\bvm-generated\b` — secondary variants; keep ONLY if corpus scan
   shows genuine recall.
4. `\bgit-clone lane\b` — from the candidate sketch. HIGH nuisance risk (artifact-reuse
   check (h)(iii) boilerplate quotes it incidentally); keep ONLY if calibration shows a
   clean signal, drop by default.

The candidate sketch's `stages? .* from HF` is REJECTED at plan time: HF staging is the
NORMAL (forward) direction and appears pervasively in compliant plans — guaranteed
nuisance class, no calibration needed to rule it out.

**Calibration protocol (implementation-time, the c33 contract — verify_plan.py
L5674-5680: "ANY future regex change re-runs the corpus scan and records the realized
numbers"):**

1. Re-scan ALL persisted plan-versions (`tasks/*/*/plans/v*.md`, N≈3,003 at plan time)
   with the AS-SHIPPED widened regex, via a throwaway script (not committed) that
   reuses `verify_plan.strip_fences` + the kind read from each task's `body.md`
   frontmatter.
2. Record per-token: triggered plan-version count, distinct issues, would-WARN count
   (triggered AND kind==experiment AND no `off_pod_phases:` block AND no N/A escape),
   recent-era slice (issue ≥ 1000).
3. Audit EVERY would-WARN plan-version: genuine inverse-direction cross-phase read
   (should have declared) vs nuisance (incidental vocabulary, no dispatched phase).
4. Keep a token iff it has ≥1 genuine hit OR zero corpus hits (pure forward-looking
   vocabulary is free) AND its nuisance class is empty or removable by a bounded regex
   refinement. Drop noisy tokens rather than widening speculatively (the c32/c33
   doctrine: "do not widen speculatively without a corpus re-scan").
5. Record the realized numbers + satisfier/nuisance audit in a calibration comment
   block above `_C39_TRIGGER_RE` (the c33 comment-block form), and update the
   docstring's KNOWN MECHANICAL RESIDUAL paragraph to reflect the closed (or
   deliberately-partially-closed) gap, citing #1796.

1. Widened regex fires on the #1773-class inverse-direction prose (the new WARN test

2. Corpus re-scan recorded: would-WARN count on the FULL corpus attributable to the new

## 6. Kill criteria

- A candidate token shows a nuisance class on the corpus that no bounded regex
  refinement removes → DROP that token (not a plan failure).
- NO candidate token survives calibration (each is either zero-recall on genuine
  inverse-direction plans AND zero-hit forward value is judged nil, or irreducibly
  noisy) → deflect with a reasoned no-change report: record the scan evidence in the
  task, close without a regex change (the workflow-fix planner-deflection outcome).
