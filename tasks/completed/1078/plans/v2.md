## 2. Prior work

**Web search (standard practice for >8 colorblind-safe categorical colors):**
- **Wong 2011** (Nature Methods, "Points of view: Color blindness") is an 8-color scheme by construction — the current `_PALETTE` (`paper_plots.py:109-118`). There is no canonical 9th Wong color.
- **Paul Tol's qualitative schemes** extend to 9-10 (muted/light) and up to ~12 distinguishable categorical colors; beyond that even Tol's own guidance falls back to a discrete-sampled continuous scheme. Adopting Tol would add a second hardcoded list AND still need a fallback beyond ~12 — two mechanisms instead of one.
- **Perceptually-uniform colormap sampling** (viridis; van der Walt & Smith, SciPy 2015 — designed perceptually uniform and readable under the common color-vision deficiencies) is the consensus fallback for large n: deterministic, any n, colorblind-robust. seaborn's `mpl_palette` implements exactly this — `np.linspace(0, 1, n_colors + 2)[1:-1]` interior sampling (verified in the installed seaborn source), which auto-trims the near-black start and pale-yellow end.
- Field consensus: ≥9 categorical series are inherently less distinguishable for ALL viewers; stretching the palette is accepted degradation vs a crash, and ≤3-5 colors per chart remains the recommendation (already in the module docstring, lines 15-16).

**Design fork decision — (c) hybrid, colormap-sampled tail:**
- (a) second differentiated cycle via linestyle/marker is REJECTED: `paper_palette` returns `list[str]` of hex colors only; linestyle/marker differentiation cannot ride the return type without an API change that would break all ~40 consumers.
- (b) all-n colormap sampling for n>8 is REJECTED in favor of (c): it discards the 8 maximally-distinguishable curated colors exactly for the series positions that need them most, and a figure that grows 8→9 series would recolor ALL its series.
- **(c) hybrid CHOSEN:** n≤8 → curated palette, byte-identical to today (hard requirement — existing committed figures must not silently change); n>8 → the full 8-color curated palette followed by (n−8) colors sampled from the interior of `viridis`. First 8 stay stable as a figure grows past 8 series; only the tail degrades. Cross-family hue proximity between Wong colors and viridis samples (e.g. Wong `#009E73` vs viridis teal region) is accepted degradation — stated in Risks.

### 3.1 New shared helper + contract

Add near the palette definitions (after `_BLOG_PALETTE`, ~line 134). Top-of-file additions: `import warnings` and `from matplotlib import colors as mcolors` (added in the SAME edit as their first usage — the PostToolUse ruff hook strips unused imports).

```python
# Fallback colormap for n > 8: perceptually uniform + colorblind-robust
# (van der Walt & Smith, SciPy 2015). Sampled on interior points per the
# seaborn ``mpl_palette`` convention so the near-black start and pale-yellow
# end are skipped.
_EXTENSION_COLORMAP = "viridis"


def _extended_palette(base: list[str], n: int, fn_name: str) -> list[str]:
    """Return ``n`` hex colours: the full curated ``base`` then colormap-sampled extras.

    Colours beyond ``len(base)`` are sampled deterministically from the
    interior of ``_EXTENSION_COLORMAP`` (``(i + 1) / (k + 1)`` for
    ``i in range(k)``, ``k = n - len(base)``) and are less distinguishable
    than the curated set — a one-time ``UserWarning`` says so. At large n
    the 256-entry colormap quantises and hex duplicates can appear
    (measured first at n=144; non-monotone in n).
    """
    k = n - len(base)
    cmap = mpl.colormaps[_EXTENSION_COLORMAP]
    extra = [mcolors.to_hex(cmap((i + 1) / (k + 1))) for i in range(k)]
    warnings.warn(
        f"{fn_name}({n}) exceeds the {len(base)}-colour curated palette; colours "
        f"{len(base) + 1}..{n} are sampled from {_EXTENSION_COLORMAP!r} and are less "
        "distinguishable — prefer <= 8 series per chart",
        UserWarning,
        stacklevel=3,
    )
    return list(base) + extra
```

### 3.2 `paper_palette` (replace lines 169-181)

```python
def paper_palette(n: int) -> list[str]:
    """Return ``n`` colorblind-safe hex colours.

    ``n <= 8`` returns the first ``n`` colours of the curated Wong 2011
    palette (unchanged, byte-identical to the historical contract).
    ``n > 8`` degrades gracefully: the full 8-colour curated palette
    followed by ``n - 8`` colours sampled from a perceptually-uniform
    colormap (see :func:`_extended_palette`), with a ``UserWarning``.

    Raises
    ------
    ValueError
        If ``n`` is not a positive int.
    """
    if not isinstance(n, int) or n < 1:
        raise ValueError(f"n must be a positive int, got {n!r}")
    if n > len(_PALETTE):
        return _extended_palette(_PALETTE, n, "paper_palette")
    return list(_PALETTE[:n])
```

## 8. §11 Decision Rationale

- **Fallback colormap = `viridis`** — What: the n>8 sample source. Why: perceptually uniform AND designed/tested for colorblind readability, the matplotlib default-family choice for exactly this fallback role; `cividis` (Nuñez et al. 2018, PLoS ONE) is more CVD-optimal but spans only blue→gray→yellow, giving less hue separation between adjacent samples at large n; `plasma` reads warmer but is less CVD-tested. Source: van der Walt & Smith, "A Better Default Colormap for Matplotlib" (SciPy 2015); availability verified by probe on pinned matplotlib 3.10.8 (`'viridis' in matplotlib.colormaps` → True). Alternatives considered: cividis, plasma, tab20 (rejected — tab20's paired light/dark red-green hues are NOT colorblind-safe), Paul Tol muted/light (rejected — caps at ~9-12, needs a second mechanism anyway).
- **Sample spacing = interior points `(i+1)/(k+1)`, i.e. `linspace(0, 1, k+2)[1:-1]`** — What: where on [0,1] the k=n−8 tail colors sit. Why: trims BOTH extremes automatically (viridis's near-black `#440154` start, which collides with Wong/blog black `#000000`, and the pale-yellow `#fde725` end, which has poor contrast on white — the blog palette itself flags yellow "fill only"); no hand-tuned trim constants. Source: seaborn `palettes.mpl_palette` — `bins = np.linspace(0, 1, int(n_colors) + 2)[1:-1]`, verified verbatim in the installed seaborn source via `inspect.getsource`. Alternatives: `linspace(0, 1, k)` (rejected — includes both bad endpoints), hand-picked trim like `[0.05, 0.85]` (rejected — two ungrounded magic constants vs one citable convention).
- **Hybrid split at 8 (curated first, sampled tail) vs all-sampled** — What: the n>8 return keeps the 8 curated colors as a prefix. Why: preserves maximal distinguishability for the first 8 series and keeps series colors STABLE when a figure grows past 8; also makes the n≤8 byte-identical guarantee structurally trivial. Source: planner design judgment (the task body itself does NOT mandate byte-identity; it is imposed here so committed figures cannot silently recolor), flagged as such. Alternatives: all-n colormap sampling for n>8 (rejected above, §2).
- **`UserWarning` on n>8 (not silent, not an error)** — What: one process-deduped warning naming the degradation. Why: fail-loud philosophy without re-creating the crash; the >8 case is legitimate (16 sources in #833) but worth flagging. Source: project fail-fast rule (CLAUDE.md Critical Rules) balanced against the task Goal's "never a hard ValueError at render time"; Python default warning-filter dedup semantics (docs.python.org warnings — "default" action shows once per location).
- **Hex conversion via `matplotlib.colors.to_hex`** — What: RGBA tuple → `"#rrggbb"`. Why: the stdlib-of-matplotlib way; drops alpha by default (`keep_alpha=False`), returns lowercase 7-char hex matching the existing tests' format assertion. Source: matplotlib 3.10 `matplotlib.colors.to_hex` documented behavior, verified by probe (`to_hex(cmap(0.5))` → `#21918c`).
- **Colormap registry access via `matplotlib.colormaps[...]`** — What: colormap lookup. Why: `matplotlib.cm.get_cmap` was deprecated in 3.7 (still present on the pinned 3.10.8, emitting `MatplotlibDeprecationWarning` with removal slated for 3.11 — fact-checker probe); the registry is the supported, deprecation-free API. Source: matplotlib API changes doc + probe on pinned 3.10.8 (`matplotlib.colormaps['viridis']` works).
- Training hyperparameters: **N/A — no model training.**
