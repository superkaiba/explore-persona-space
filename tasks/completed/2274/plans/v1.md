# Plan v1 — Task #2274: gotchas.md fellows CPU analogue (ConstrainCores=yes vs ConstrainDevices=no asymmetry)

**Kind:** infra (workflow-surface doc edit). **Parent:** #1336 (provenance-only — incident source, no experimental recipe inherited).

## Requirement

Extend the existing `.claude/rules/gotchas.md` fellows-cluster entry ("**Fellows SLURM nodes are GPU-SHARED (no GPU cgroup isolation)…**", currently the single bullet at line ~240) with its CPU analogue, which is enforced by a DIFFERENT mechanism and behaves OPPOSITELY:

- Plain-SSH `nproc` on a fellows node reports the PHYSICAL node (192 on node-2); `nproc` INSIDE a job allocation reports the ALLOCATION (64), because `TaskPlugin=task/cgroup` + `ConstrainCores=yes` (verified live 2026-08-13: `CPUTot=192`, `CPUAlloc=64`, job 12643 `NumCPUs=64`/`MinCPUsNode=64`).
- Asymmetry: `ConstrainDevices=no` (GPUs NOT cgroup-isolated — enumeration lies) vs `ConstrainCores=yes` (CPUs ARE constrained — inside-job `nproc` is allocation-correct). A reader generalizing the GPU rule to CPUs draws the WRONG conclusion in the other direction.
- Incident (#1336): a plain-SSH `nproc=192` probe baked `threads_per_worker=24` into a declared fix-engaged signal where the in-allocation truth was `nproc=64` / `threads_per_worker=8` — inverting the signal's meaning (a HEALTHY run would read fix-not-engaged) — and understated the oversubscription 3× (512 threads on 64 allocated cores = 8×, not 2.7×).
