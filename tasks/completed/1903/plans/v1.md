# Plan v1 — #1903 daily-fix: fix red main — issue1689 user_slot entrypoints violate the os._exit shutdown-bypass contract

## Goal / requirement

`tests/test_issue1689_os_exit_shutdown_bypass.py` is red on pristine origin/main
(12 failing params, re-verified live at 07b44e84af on 2026-07-31): the four
`scripts/issue1689_user_slot_{capture,fits,render,gen_a1}.py` entrypoints end

`os._exit(rc if isinstance(rc, int) else 0)`.

**Requirement:** make the four entrypoints satisfy the pinned contract so the
test file goes fully green on the branch, with zero behavior change beyond the
exit path (rc semantics preserved: int rc passes through, non-int/None → 0).

## Why the fix goes in the scripts, not the test

The test's module docstring declares its purpose: fail LOUD when a new
`scripts/issue1689_*.py` entrypoint lands without the wrapper ("closes the
'next contributor forgets to add it' gap"). That is exactly what happened —
the user_slot scripts landed on main via #1689 inline follow-up rounds
carrying a `sys.exit` variant of the wrapper. The scripts are in the same
C-extension teardown-race class the round-6 fix targets (`gen_a1` imports
torch/transformers at top level; all four are pod/GCE-dispatched phases under
`set -euo pipefail` dispatchers), so weakening the test's param list would
both defeat its design and leave a real crash class open. None of the four
relies on atexit for genuine work (grep: comments only), so the
`os._exit` bypass is safe per the gen_corpus reference-implementation caveat.

4. `scripts/issue1689_user_slot_gen_a1.py` — two edits:
   - inside `main()`: replace the tail `sys.stdout.flush(); sys.stderr.flush(); sys.exit(rc)` with `return rc` (the flush duty moves to the guard);

     `rc = main()` / `sys.stdout.flush()` / `sys.stderr.flush()` / `os._exit(rc if isinstance(rc, int) else 0)`.
   The implementer verifies `main()` has no other `sys.exit` tail-paths and
   that every `main()` return path yields an int or None (None → 0 by the
   canonical form).
