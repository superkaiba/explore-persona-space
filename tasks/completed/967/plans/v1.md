## 3. Design questions — settled

**Q1 Host: the watcher, not tick_triage (and not both).** `tick_triage.py` runs only when a per-issue tick cron is armed — i.e. only for autonomous sessions, and its cron tears down at terminal/gate states; the #779 class must also be caught for interactive sessions, for post-park follow-up dispatches, and for tasks whose session died. Its contract is also one verdict line consumed by an LLM-priced tick — adding audit output there adds cost per fire and double-flags anything the watcher also sees. The watcher sweeps ALL tasks every 10 min for free, is daemon-independent, and owns the exact conventions (sidecar/push/dedup/kill-switch) this pass needs. `tick_triage.py` is untouched.

**Q2 Sweep scope.** Tasks from `REGISTRY.json` (read in-process via `task_workflow.registry_path()`) whose status ∈ `_TRIAGE_OBSERVER_STATUSES = ACTIVE ∪ {"awaiting_promotion", "blocked"}` (ACTIVE is the watcher's existing set at line ~460: planning/approved/running/verifying/interpreting/reviewing/followups_running; `awaiting_promotion` because 9a-ter/9b follow-up dispatches happen on parked parents; `blocked` because a crash right after an untriaged launch parks there; terminal `completed`/`archived`/`on_hold`/`proposed`/`plan_pending` excluded — no fresh dispatch to audit or the flag has no consumer). Cost bound, two gates before any events read: (i) `events.jsonl` mtime (via the registry-resolved task path) within the lookback window; (ii) per-task cursor — only records with `ts > max(cursor, now − EPM_TRIAGE_OBSERVER_LOOKBACK_H, TRIAGE_DUTY_EPOCH_TS)` are evaluated. Records audited: `TRIAGE_LAUNCH_KINDS` markers + `epm:progress` breadcrumbs (`stage-dispatch stage=...`) + any record carrying the triage line (for the `none`-check). Lookback default 48h (§11).

**Q3 Violation predicate (exact — pseudocode in §4.2).** Three violation classes over post-epoch, post-cursor records:

- `launch-missing-line` (**warn**): a `TRIAGE_LAUNCH_KINDS` marker whose note lacks `TRIAGE_LINE_PREFIX`, AND whose nearest PREVIOUS duty-bound record is not a triage-line record within `adjacency_s`, AND whose nearest NEXT duty-bound record is not a triage-line record within `adjacency_s`. (Launch markers are machine-posted — `by=poll_pipeline`/`backends.gcp` — so the adjacent `epm:progress` triage note is the NORMAL compliance path; adjacency matching is load-bearing. Requiring the nearest duty-bound neighbor — not just any record in ±window — keeps crash-fix relaunch bursts individually duty-bound, per the SKILL.md "crash-fix relaunches included" clause.)
- `breadcrumb-missing-line` (**warn**, `info` for the `free-analysis-followup` stage): an `epm:progress` breadcrumb (`lstrip().startswith("stage-dispatch ")`) whose normalized stage token (`_normalize_stage`, strips one `followup-` prefix + aliases) is NOT in `TRIAGE_NONCOMPUTE_STAGES = {planning, implementing, code-review, interpreting, clean-result, verifying, methodology-reference, related-work}` and whose note lacks the triage line. Stage names are free-form (the #779 incident crumb was `stage=followup-grid`), so this is a NEGATIVE-list detection mirroring the enumerator's own fail-toward-triage over-approximation; a genuinely non-compute unknown stage costs one deduped review nudge, which the FP posture (Q6) prices in. `free-analysis-followup` is duty-bound only when the 9a-ter stage launches a fit/battery (content-dependent), so its missing-line flags at `info` (sidecar only).
- `none-with-candidates` (**info**, escalated to **warn** on signature hit): any record whose triage line disposition is `none` (parse: the line's remainder after the prefix, stripped, starts with `none`) while `_triage_window_candidates(events[j+1:i])` — `j` = nearest previous duty-bound record — is non-empty after dropping candidates within `grace_s` of the record's ts (the spec's "seconds between the final enumerator run and the breadcrumb post" residual). Escalation to `warn` only when ≥1 surviving candidate note contains an entry of `TRIAGE_EXTERNAL_SIGNATURES = {"PM-chat", "user-raised", "user directive", "# Audit", "AMENDMENT", "SCOPE RESTORE"}` (the SKILL.md in-the-wild external signatures, kept as ONE shared constant next to the other triage constants).

Accepted residuals honored (never flagged): legacy pre-epoch records (`TRIAGE_DUTY_EPOCH_TS = "2026-07-03T05:00:00Z"`, #889's landing 2026-07-03T04:05Z rounded up); grace-window candidates; markers after a task's last compute dispatch (structurally never audited — only dispatch records are evaluated); a burst launch covered by its nearest-neighbor triage record within adjacency. Known bounded miss (documented, not flagged): a 9a-ter compute fit dispatched under a breadcrumb with a `free-analysis-followup` stage token and no triage line surfaces only at `info`.

**Q4 Flag channel.** (i) Always: one JSON row appended to a NEW dedicated sidecar `.claude/cache/triage-observer-events.jsonl` (the cpu-guard "own stream for clean grep" precedent; the disk-guard sidecar is disk-pressure-scoped). Row: `{ts, issue, record_ts, record_kind, stage, violation, severity, candidate_count, candidate_kinds, signature_hits, note_head}`. (ii) `warn` only: one fail-soft `_telegram_push` digest line + one `epm:progress` review-nudge note on the task via `_post_progress_marker` (carrying the `[autonomous_session_watch:triage-observer]` sentinel — anti-liveness by prefix match, so it never refreshes staleness clocks), capped at `EPM_TRIAGE_OBSERVER_MARKER_CAP=5` marker posts per tick. The note doubles as a live advisory: it carries `by="unknown"`, so the NEXT compute dispatch's enumerator surfaces it — deliberate (the flag is itself the advisory the next dispatch should read). NON-GATING: the pass calls no `set-status`, no session stop, no dispatch mutation; pinned by a test (§6).

**Q5 Dedup.** Key = `(issue, record_ts, violation_class)`. One flag per key EVER (a violation is a fixed historical record — it cannot grow, so no re-alert; contrast with disk bands). State singleton `~/.eps-autonomous/triage-observer.json`: `{"<issue>": {"cursor_ts": "...", "flagged": ["<record_ts>|<class>", ...]}}`, atomic tmp+replace write, type-guarded reads, entries self-pruned when the issue leaves the sweep status set for good (status ∈ {completed, archived}). No ack sentinel — fire-once semantics make one unnecessary (the cpu-guard pass documents the same omission rationale). The cursor makes the pass idempotent: a record is evaluated once, on the first tick after it lands.

**Q6 False-positive posture.** The enumerator ENUMERATES for LLM triage and never classifies externality (`by` defaults to `"unknown"` for humans AND sessions — measured on #779), so `none` against a non-empty candidate set is **usually legitimate** (all candidates self-posted). Hence: `none-with-candidates` defaults to `info` (sidecar-only, no push, no marker); it reaches `warn` only on an external-signature hit. All flag text is phrased as a review nudge, never an accusation: "post-hoc triage-duty review: dispatch record at <ts> recorded a 'none' disposition while K window candidates were pending (M matching external-advisory signatures). The enumerator over-approximates — this may be fine if all candidates were self-posted; please review those markers and record dispositions at the next dispatch." Missing-line classes are higher-confidence (the duty unambiguously requires SOME line) and warrant `warn`.

**Q7 Kill switch.** `EPM_DISABLE_TRIAGE_OBSERVER=1` (truthy set `{"1","true","yes","on"}`, matching `_cpu_guard_enabled`), checked at the top of `triage_observer_pass` with the standard "disabled via ...; skipping" log line.

**New pure audit helper:**

```python
def audit_dispatch_triage(
    events: list[dict],
    *,
    adjacency_s: float = 1800.0,
    grace_s: float = 120.0,
    epoch_ts: str | None = TRIAGE_DUTY_EPOCH_TS,
    min_ts: str | None = None,
) -> list[dict]:
    """Post-hoc, NON-GATING audit of the pre-dispatch triage duty (#967).

    Returns one violation dict per non-compliant duty-bound compute dispatch
    record: {"record_ts", "record_kind", "stage", "violation", "severity",
    "candidate_count", "candidate_kinds", "signature_hits", "note_head"}.
    Pure read — never mutates events; classification residuals per SKILL.md
    § Pre-dispatch external-marker triage are tolerated by construction
    (epoch cutoff, grace window, nearest-neighbor adjacency).
    """
```

Pseudocode:

```python
duty_idx = [i for i, e in enumerate(events)
            if e.get("kind") in TRIAGE_LAUNCH_KINDS
            or TRIAGE_LINE_PREFIX in (e.get("note") or "")]
violations = []
for i in duty_idx:
    e = events[i]; ts = e.get("ts", ""); note = e.get("note") or ""
    if epoch_ts and ts < epoch_ts:        # ISO-8601 Z strings sort lexicographically
        continue
    if min_ts and ts <= min_ts:
        continue
    prev_j = nearest duty_idx member < i (None if none)
    has_line = TRIAGE_LINE_PREFIX in note

    if e.get("kind") in TRIAGE_LAUNCH_KINDS and not has_line:
        # adjacency: nearest previous / next duty-bound record must be a
        # triage-line record within adjacency_s
        covered = (
            (prev_j is not None and TRIAGE_LINE_PREFIX in (events[prev_j].get("note") or "")
             and _ts_delta_s(events[prev_j], e) <= adjacency_s)
            or (next_k := nearest duty_idx member > i) is not None
               and TRIAGE_LINE_PREFIX in (events[next_k].get("note") or "")
               and _ts_delta_s(e, events[next_k]) <= adjacency_s
        )
        if not covered:
            violations.append({..., "violation": "launch-missing-line", "severity": "warn"})
        continue

    stripped = note.lstrip()
    if not has_line and stripped.startswith("stage-dispatch "):
        stage_raw = _breadcrumb_fields(stripped).get("stage", "")
        norm = _normalize_stage(stage_raw)
        if norm not in TRIAGE_NONCOMPUTE_STAGES:
            sev = "info" if norm == "free-analysis-followup" else "warn"
            violations.append({..., "violation": "breadcrumb-missing-line", "severity": sev})
        continue

    if has_line and _triage_disposition_is_none(note):
        window = events[(prev_j + 1 if prev_j is not None else 0): i]
        cands = _triage_window_candidates(window)
        cands = [c for c in cands if _ts_delta_s(c, e) > grace_s]   # spec residual
        if cands:
            hits = sorted({sig for c in cands
                           for sig in TRIAGE_EXTERNAL_SIGNATURES
                           if sig in (c.get("note") or "")})
            violations.append({..., "violation": "none-with-candidates",
                               "severity": "warn" if hits else "info",
                               "candidate_count": len(cands),
                               "candidate_kinds": sorted({c.get("kind","") for c in cands}),
                               "signature_hits": hits})
return violations
```

Small helpers alongside: `_ts_delta_s(a, b)` (reuse `_stage_event_ts` parsing; malformed ts ⇒ treat as NOT covered for adjacency but NOT a violation trigger on the record itself — a record with unparseable ts is skipped entirely, fail-soft) and `_triage_disposition_is_none(note)` (first triage-line occurrence; remainder `.strip().lower().startswith("none")`).

Note on breadcrumbs that are NOT `stage-dispatch` and NOT launch markers but DO carry a triage line (the adjacent-note compliance form): they are duty-bound records for windowing and get the `none`-check (third branch), which is exactly right — the adjacent note IS where a pod launch's `none` claim lives.
