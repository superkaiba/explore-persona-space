## Method delta

Two composing changes, one per mechanism — plus prose/residuals updates and lockstep pin-test updates:

- **(F1) Merge-base-pinned baseline** (fixes mechanism 2 — the actual incident): cut the baseline scratch at `git merge-base origin/main HEAD` instead of `origin/main`. The two trees then differ ONLY by the payload: a pre-existing fork-vintage red (whether or not main has since fixed it) is red in BOTH legs → subtracts → pass; a payload-caused red is red only at tip → NEW → block (criterion 2 preserved). Form (ii) (post-merge worktree) degenerates automatically: HEAD contains origin/main ⇒ merge-base = origin/main — no special-casing. A main-side check ADDED since fork is enforced in neither leg — that is exactly today's residual (a) (fail-safe; trunk Step 9c catches it post-merge), unchanged.
- **(F2) Intersection/attribution split of the NEW node set** (fixes mechanism 3 — the body's class + criterion 1): the mapped-baseline helper additionally EMITS its selection (the test-file list it ran); a new pure-file `classify-new-nodes` helper subcommand splits the comm output: node's file ∈ baseline selection → keep blocking (a real both-trees delta); node's file ∈ own-diff → keep blocking (branch-new/payload test, "NEW by construction" doctrine preserved, SKILL.md L12791-12794); otherwise → `unclassifiable — pristine-oracle needed` arm: recorded + WARNed in the merge note, **never a silent pass and never an automatic block**. Missing selection file / helper failure fails toward the status quo (everything keeps blocking) with a loud WARN.

Why file-grain (selected test files) rather than collected NODE ids: the baseline's collected node set would need an extra `--collect-only` pytest pass; the selection list is already computed by the helper at zero extra cost, and file-grain is sufficient — if the file ran at baseline, every red line/node it could produce was observable to `comm` (a within-file branch-new node is payload by definition when the file is in the own-diff; a data-driven parametrization drift inside an untouched file remains residual (c), documented).

## Chosen fix shape + why the alternatives are insufficient

**Chosen: (F1) + (F2)** — the body's shape (b) refined by attribution, plus merge-base pinning.

- Body shape **(a) alone** (same node list to both legs) is UNSOUND: a tip-only node (branch-new test) cannot run at base (the body/prompt already note this), and it would NOT have prevented the incident — the failing node was in both lists.
- Body shape **(b) alone** (intersection + unclassifiable arm) also would NOT have prevented the incident — the node was collected in both legs; only (F1) removes the subject-drift channel. And a naive (b) without the own-diff attribution would break criterion 2's branch-new-test doctrine (a payload-added failing test is gated-only-collected by construction and must still block).
- **(F1) alone** leaves criterion 1's class open through selector-vintage drift (gated selection uses the ROOT selector copy — "a branch must not subvert its own gate", L12696-12710 — while the baseline uses the merge-base scratch copy; arms added on main since fork can still produce gated-only selections of non-payload tests).
