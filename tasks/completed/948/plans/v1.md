# Plan — #948: reviewer must verify seam-stubbed production bodies vs real APIs

### 0.0 TL;DR (plain English)

- **What I'll change:** I'll add one new mandatory check to the code-reviewer
  playbook (plus its three sibling review specs): whenever a round adds a new
  production function that the tests stub out, the reviewer must open that
  function's body and check every call it makes against the real function
  signatures, and every field it reads against the real dataclass — instead of
  trusting green tests that only prove the function got *called*.
- **What I expect:** the #906 failure mode (five review rounds approving code
  that crashes on its first real call, because the mocked tests never ran the
  body) becomes impossible to PASS: a wrong signature or made-up field is a
  Critical finding the strip logic can never remove.
- **What would change my mind:** if an existing check already covered this
  (I verified none does — Step 0.68 covers verification *gates*, Step 3.5
  covers cache *keys*, neither reads a stubbed body), or if the check couldn't
  be cost-bounded (it can: only functions added this round ∩ test-stub
  targets, typically 0–5 functions).

### 3. Method delta (vs the existing Step 0.68 family)

| | Step 0.68 hollow-gate sub-check | NEW Step 3.8 |
|---|---|---|
| Object | a `--verify-X` / equivalence GATE | a production function BODY |
| Failure mode caught | gate asserts on an undispatched sibling (green gate, unverified hot loop) | tests stub the function itself (green tests, never-executed body with fabricated APIs) |
| Verification mechanic | trace flag → gate → callee identity vs dispatch path | `inspect.signature` / read the callee's `def`; dataclass field enumeration |
| Trigger | a verification gate present in/touched by the diff | production `def` ADDED this round whose name is a test stub/monkeypatch/seam target |
| Tag | `hollow-verification-gate` | `substantive` (reused; see §11-D3) |

Both live in the "green evidence that launders unverified code" family; the
new step closes the body-vs-dispatch half Step 0.68's gate-vs-dispatch half
leaves open.

**Edit 1 — `.claude/agents/code-reviewer.md`: new Step 3.8** (insert after
L1034, the end of Step 3.7's closing paragraph, before L1036 `### Step 4: Run
/ Verify Tests`):

```markdown
### Step 3.8: Seam-stubbed production-body verification (any diff type)

**Trigger:** the diff ADDS a production function (a new `def` in non-test
code, including in a new file) whose NAME appears in any test as a stub /
monkeypatch / seam target — `monkeypatch.setattr(..., "<name>", ...)`,
`unittest.mock.patch("...<name>")`, a seams/hooks dataclass field the tests
override with a fake (e.g. `PilotSeams(<name>_fn=fake)`), or a fake injected
through a resolver/dispatch table. Enumerate mechanically: list the round's
added `def`s from the diff, then grep the test files (round-touched AND
pre-existing seam tables) for each name. ALSO in scope: an EXISTING
seam-stubbed function whose body this round's diff modifies — verify the
added/changed hunk lines only. No hit → record `Step 3.8: N/A — no
seam-stubbed production function added or modified this round` and proceed.

**Why:** a stub/monkeypatch seam means the suite can be 100% green while the
production BODY has never executed — the tests validate that the DISPATCHER
calls the name, not that the body is correct. A dispatch/resolver test is NOT
body coverage. (Incident #906, 2026-07-03: five consecutive ensemble rounds
PASSed crash-class production bodies behind `PilotSeams` stubs while 43/43
mocked tests stayed green — `behavior.trigger_context` dereferenced a
nonexistent `Behavior` field at L541+L628, the judge was called with a
fabricated signature vs the real `judge_graded(items, eval_prompt, *,
n_draws, cache_dir, save_raw, ...)` at L575-580, and `score_completions`
omitted required kw-only `cache_dir`/`save_raw` at L712; Codex FAILed all 5
rounds, the reconciler upheld FAIL all 5, and the task blocked at cap-5.)

**Check — for EVERY function in the trigger set, read the BODY and verify:**

1. **External call signatures.** For each call to a function defined OUTSIDE
   the round's diff (repo helper, library fn), verify the call site against
   the callee's REAL signature — `uv run python -c "import inspect, <mod>;
   print(inspect.signature(<mod>.<callee>))"` or READ the callee's `def`
   line — checking positional arity, kwarg names, and required keyword-only
   args. Quote the call site `file.py:LINE` + the real signature as evidence.
2. **Attribute dereferences.** For each attribute access on a dataclass /
   config / artifact object the body receives (`behavior.<field>`,
   `cfg.<field>`), verify the field EXISTS on the real class — read the class
   definition or enumerate `dataclasses.fields(<Class>)`.
3. **Do not credit wiring tests as body coverage.** Body evidence is EITHER a
   committed test that executes the REAL body with only the external GPU/API
   boundary faked (signature-conformant fakes) OR your own per-call
   verification per items 1–2. A test that monkeypatches the function and
   asserts the dispatcher called it verifies wiring only.

**Verdict routing:** a wrong-signature or nonexistent-field finding in a
seam-stubbed body is **Critical** (the production path provably crashes),
blocker tag `substantive` (never `marker-shape` / `smoke-run-missing` /
`git-provenance`; never stripped by Step 5c-bis). Run the Step 3.7 sibling
sweep on the class — the same fabricated API usually recurs (#906: the
`trigger_context` dereference appeared at two sites). All verified → record
the per-function ledger (function, callees checked, evidence lines) in the
verdict body.

**Cost bound:** the trigger set is the round's ADDED/MODIFIED functions ∩
test-stub targets — typically 0–5 functions, never a whole-codebase audit;
per function you verify only the body's external calls + attribute
dereferences (diff-hunk lines only, for the modified case).
```

### 11. Decision Rationale (design choices; no hyperparameters — kind: infra)

- **D1 — Trigger keys on "newly-added production function stubbed by tests".**
  What: fire only for round-added `def`s (+ round-modified bodies of
  seam-stubbed functions, hunk-scoped) whose names are test stub targets.
  Why: this is exactly the #906 signature — the r5 residual was "4 substantive
  crash-class blockers in the NEW production bodies added in rounds 4-5"
  behind `PilotSeams` — and it bounds cost per the task constraints (no
  whole-codebase audit). The modified-body extension closes the round-2
  loophole (add the function clean in r1, add the wrong call in r2) while
  staying diff-scoped. Source: #906 `epm:failure` v1 + reconcile v5; #948 body
  + brief constraints.
- **D2 — `inspect.signature` / read-the-callee as the named mechanic.** Why:
  it is the ground-truth check the #906 reconciler actually ran to uphold the
  FAILs (quoting the real `judge_graded` signature), and the #906 fix sketch
  prescribes "inspect.signature-conformant fakes"; the Claude reviewer has
  Bash (frontmatter tools) so it can run it, and Codex gets the
  read-the-`def` fallback (its spec already exempts it from uv-env
  execution). Source: #906 `epm:failure` v1; codex-code-reviewer.md L519-522.
- **D3 — Reuse `substantive`, no new blocker tag.** Why: Step 5c-bis strips
  only FAILs whose tags ⊆ {marker-shape, smoke-run-missing, git-provenance}
  with no substantive (code-reviewer.md L1164) — a dedicated tag would behave
  IDENTICALLY for strip purposes, so it is not load-bearing; reusing
  `substantive` means the orchestrator-parsed taxonomy line is untouched
  (zero parse-target churn, cleanly non-architectural). Precedent both ways
  exists (Step 3.6 + Rule 13 use plain `substantive`; Steps 3.5/0.67/0.68
  have named tags for telemetry); the brief's preference + the smaller
  contract surface decide it. Alternative (a `seam-stubbed-body-unverified`
  tag) rejected as not load-bearing. Source: #948 brief; code-reviewer.md
  L1164, L969-971 (Step 3.6 precedent).
- **D4 — Placement as Step 3.8 (read-the-code family), not Step 0.69.** Why:
  Step 0.7 (L791-793) defines the 0.5x/0.6x family as pre-diff CONTRACT
  checks; this check requires reading bodies + callees, structurally mirroring
  Step 3.5 (verify against the real artifact; indirect reasoning invalid) and
  composing with Step 3.7's sibling sweep. The task body's "near Step 0.68"
  located the GAP, not the slot; a one-line sibling cross-ref in Step 0.68
  (Edit 3) preserves discoverability where the clarifier looked. Source:
  code-reviewer.md structure (L791-807, L908-940); #948 clarifier note.

  code-correctness-critic.md L121-133.
