# Plan v1 — #2251: teach `SLURM_GPU_WIDTH_GUARD_RE` the inherited-`CUDA_VISIBLE_DEVICES` parse

## 1. Problem

`check_slurm_gpu_width` (scripts/workflow_lint.py) flags dispatchers that derive GPU width
from bare `nvidia-smi ... | wc -l` unless the FILE carries a recognized allocation-derived
guard. The guard recognizer (`SLURM_GPU_WIDTH_GUARD_RE`) accepts only SLURM env tokens
(`SLURM_JOB_ID|SLURM_JOB_GPUS|SLURM_STEP_GPUS|SLURM_GPUS_ON_NODE`) and `realized_gpu_ids`.
The CORRECT non-SLURM allocation-derived pattern — parse an inherited
`CUDA_VISIBLE_DEVICES` into an array and take the array count, with nvidia-smi only as the
unset-CVD fallback — is NOT recognized, so a dispatcher adopting it (as
`scripts/issue1336_dispatch.sh` did in #1336 round v21, commit
`6ff22758209d5fd642a3f3642479b57900f9c620`) cannot ratchet out of
`SLURM_GPU_WIDTH_GRANDFATHER`.

## 4. Change set (all in one worktree round; ~4 files, no dispatcher edits)

### 4a. `scripts/workflow_lint.py`

1. Add a CVD-parse recognizer next to the existing regexes. Deliberately NOT keyed on the
   `EPS_ALLOC_GPUS` identifier (task requirement); keyed on the SHAPE — an array populated
   by `read -ra`/`read -a` from a `CUDA_VISIBLE_DEVICES` here-string, PLUS a same-name
   array-count derivation `${#NAME[@]}` elsewhere in the file (back-reference precision is
   what keeps the negative arm honest):

   ```python
   SLURM_GPU_WIDTH_CVD_READ_RE = re.compile(
       r"read\s+-r?a\s+(\w+)\s*<<<\s*\"?\$(?:\{CUDA_VISIBLE_DEVICES[^}]*\}|CUDA_VISIBLE_DEVICES)\"?"
   )

   def _slurm_gpu_width_guard_present(text: str) -> bool:
       """File-scoped guard scan: SLURM env tokens / realized_gpu_ids (legacy
       SLURM_GPU_WIDTH_GUARD_RE), OR the inherited-CUDA_VISIBLE_DEVICES parse —
       an array populated from CVD via read -ra plus a same-name ${#NAME[@]}
       count derivation (#2251; the #1336 round-v21 shape)."""
       if SLURM_GPU_WIDTH_GUARD_RE.search(text):
           return True
       for m in SLURM_GPU_WIDTH_CVD_READ_RE.finditer(text):
           if re.search(r"\$\{#" + re.escape(m.group(1)) + r"\[@\]\}", text):
               return True
       return False
   ```

   Notes on regex scope (anti-broadening, task non-goal): a leading `IFS=','` prefix
   matches via `search`; quoting variants `"$CUDA_VISIBLE_DEVICES"`,
   `"${CUDA_VISIBLE_DEVICES}"`, `"${CUDA_VISIBLE_DEVICES-}"` are covered by the
   `[^}]*` default-suffix allowance; `mapfile`/`readarray`/tr-pipe shapes are deliberately
   NOT recognized (narrow scope; add only when a real dispatcher adopts them). A literal
   pin like `CUDA_VISIBLE_DEVICES=0` or `CUDA_VISIBLE_DEVICES=${ARR[w]}` can never match:
   the regex requires the `read -ra ... <<<` populate shape, and the count requirement
   `${#NAME[@]}` must share the SAME array name.

2. Switch the single guard-scan site in `check_slurm_gpu_width` (line ~4176) from
   `SLURM_GPU_WIDTH_GUARD_RE.search(text)` to `_slurm_gpu_width_guard_present(text)`.
   `guarded_basenames` — and therefore the hygiene guard-adopted WARN arm — inherits the
   new recognizer automatically.

3. Update the comment block above the regexes (line ~1292) to document the second guard
   form, and annotate the `issue1336_dispatch.sh` grandfather entry:
   `# fixed on issue-1336-fullcorpora (6ff22758); remove at that branch's merge —`
   `# the guard-adopted hygiene WARN + inverse-calibration pin force it (#2251).`
