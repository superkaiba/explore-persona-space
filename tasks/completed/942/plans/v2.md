## 1. Goal

Check 25 (`check_audit_availability_claims_match_hf` in `scripts/verify_task_body.py`) mechanically catches a clean-result body that claims a data artifact "was not uploaded / cannot be audited" when the artifact demonstrably exists on the HF data repo at the body's own pinned revision. On #813 it PASSed vacuously: the body asserted the unreduced store / reduced summaries / fitted maps "remain on the pod under an HF public-storage quota hold (upload 403)" while `epm:upload-verification v1` + an independent `list_repo_files` proved all 24,206 artifacts were on HF. Two vocabularies were missing — the quota-hold **denial family** in `_AUDIT_DENIAL_RE` (line 5426) and the **store/maps artifact classes** in `_AUDIT_ARTIFACT_CLASSES` (line 5448) — and, discovered during planning, two latent supporting bugs would defeat a naive vocabulary extension: (a) the cheap line pre-filter at line 5663 (`"uploaded" not in line and "audit" not in line → skip`) skips the new phrasings before the regex ever runs, and (b) the HF-path keyword match at line 5533 is a bare substring (`kw in path.lower()`), so the new token `reduced` would false-match every `unreduced/` file (confirmed empirically). This task extends both constants and fixes both supporting bugs so a #813-shaped false denial FAILs before promotion **when the body pins an HF URL covering the denied artifact class**, with tests pinning all of it.

**Scope note (reconciler-upheld, round 1).** The protection is scoped to the denial+pinned-URL combination: check 25 probes only revision-pinned HF URLs the body itself carries (`_gather_hf_pinned_urls`). The incident-time #813 v1 body carried the denial with NO covering pinned URL (only two #537 URLs), so it would still PASS vacuously under this fix — the no-URL escape is PRE-EXISTING check-25 architecture shared identically by all 7 legacy denial families and 5 legacy classes, and is out of scope here (a follow-up candidate — wiring `epm:upload-verification` events.jsonl evidence into the gate — is logged on the task, parked under the workflow-fix recursion guard). The CURRENT #813 body shape (substrate URL present) WOULD FAIL had the denial persisted, which is the real, non-vacuous protection this fix delivers. §3.1's acceptance criterion is already scoped to the denial+URL combination; the shipped module doc-block wording must state this scoping plainly (no wording implying the no-URL incident class is closed).

### 4a. `_AUDIT_DENIAL_RE` — exact new alternations (append inside the existing group, before the closing paren)

```python
_AUDIT_DENIAL_RE = re.compile(
    r"(?:not\s+(?:separately\s+)?uploaded"
    r"|was\s+not\s+uploaded|wasn" + _APOS + r"t\s+uploaded"
    r"|cannot\s+be\s+audited|cannot\s+audit|can" + _APOS + r"t\s+be\s+audited"
    r"|(?:un|not\s+)available\s+for\s+audit"
    # The #813 family — a LIVE quota-hold / pod-residency claim of
    # non-availability. Present-tense / stative shapes ONLY (deliberately NOT
    # `remained ... on the pod` and NOT a bare `quota hold` without a stative
    # preposition): a resolved narrative ("after the quota hold cleared, all
    # files were uploaded") is not a denial and must not fire.
    r"|\bremain(?:s)?\s+on\s+the\s+pod\b"
    r"|\bquota[ _-]held\b"
    r"|(?:under|pending|behind|blocked\s+(?:on|by))\s+(?:the\s+|an?\s+)?"
    r"(?:[\w-]+\s+){0,4}?quota\s+hold"
    r"|\bupload\s+403\b)",
    re.IGNORECASE,
)
```

Verified during planning against the verbatim #813 sentences: line 87 matches via `remain on the pod` AND `under an HF public-storage quota hold` AND `upload 403`; line 51 via `quota-held`; "pending the quota hold" and "blocked on the same quota hold" via the stative-preposition alternation. Negative-verified: "After the quota hold cleared…" (no stative preposition), "remained on the pod until…" (past tense), "were uploaded" — none match.

### 4b. `_AUDIT_ARTIFACT_CLASSES` — exact new entries (append after `analysis_tensors`)

    # activation stores), reduced/ (per-question stores + summaries), maps/
    # (fitted maps). Prose spellings from the #813 v1 body verbatim.
    "unreduced": re.compile(

### 4c. Pre-filter fix (the latent bug that would defeat 4a alone)

At `:5663` the check pre-filters lines: `if "uploaded" not in line.lower() and "audit" not in line.lower(): continue`. #813's line 51 contains neither token → the extended denial regex would never run on it. Replace with a module-level compiled pre-filter next to `_AUDIT_DENIAL_RE`:

```python
# Cheap per-line pre-filter: every _AUDIT_DENIAL_RE alternation family
# contains ≥1 of these substrings ("upload" covers uploaded / upload 403 /
# unuploaded; "quota" the hold/held family; "pod" the remain-on-the-pod
# family). Pinned in sync with the denial regex by
# test_prefilter_covers_every_denial_family.
_AUDIT_LINE_PREFILTER_RE = re.compile(r"upload|audit|quota|\bpod\b", re.IGNORECASE)
```

and in the check body: `if not _AUDIT_LINE_PREFILTER_RE.search(line): continue`.

### 4d. Keyword-match boundary fix in `_hf_probe_keyword` (the second latent bug)

At `:5533` the on-Hub match is `kw in path.lower()` — a bare substring, so token `reduced` matches `…/unreduced/em/q0001.npz` (empirically confirmed). The docstring already promises "carries ``keyword`` as a path component"; align the code by compiling once before the pagination loop:

```python
    kw = keyword.lower()
    # Alphanumeric-boundary match, NOT bare substring: `reduced` must not
    # match `unreduced/`. `/` and `_` count as boundaries (raw_completions,
    # install_probes, training_mixes keep matching); a[n] adjacent letter or
    # digit does not.
    kw_re = re.compile(r"(?<![a-z0-9])" + re.escape(kw) + r"(?![a-z0-9])")
```

and replace the condition with `kw_re.search(path.lower())`. Legacy tokens verified against real path shapes: `…/raw_completions/…`, `…/install_probes/…`, `…/mixes/…`, `…_mixes.jsonl`, `…/onpolicy_pools/…`, `…/analysis_tensors/…` all still match (`/` and `_` are boundaries); new tokens match `…/unreduced/…`, `…/reduced/…`, `…/maps/…` and `reduced` no longer matches `unreduced/` paths.
