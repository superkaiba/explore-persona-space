## 0.0 TL;DR (plain English)

- **What I'll run.** I'm re-doing the contrastive-fine-tune sweep from a couple weeks ago, but this time the eval measures the thing I actually care about. Before, I fed each trained "villain" model a canned answer and checked whether it would have tacked the secret symbol onto the end of THAT canned answer. The model never writes canned answers, so that number wasn't really telling me whether the trained model leaks the symbol on bystanders' prompts. This time, for every bystander persona, I let the model generate its OWN reply to a prompt and then ask "given what you just wrote, how likely are you to add the symbol at the end?" I sweep the same 11 training-data recipes I had before (vary how many examples per persona and how many personas the contrast set covers) and check which knob reduces leakage **on bystander personas the model never trained against** — not just on the specific personas I used as the "don't leak" examples during training. (Those obviously drop, that's not interesting.) The held-out set is about 15 panel personas like surgeon, programmer, chef, lawyer, wizard, hero, philosopher, child, ai_assistant — picked because no cell could possibly have used them as a negative.
- **What I expect.** Widening the contrast set (more negative personas, more negative examples per persona) should reduce leakage even on the held-out bystanders, because the negatives are supposed to teach a *general* "don't add the symbol when other personas talk" rule, not just "don't add it when THIS particular medical_doctor talks." Adding more positive examples or more positive personas probably doesn't reduce leakage and might even raise it — the off-policy run already hinted at this, but it was a saturated-ceiling signal so I couldn't trust it.
- **What would change my mind.** Three results I'd want to investigate. (1) If on-policy leakage doesn't budge on the held-out bystanders with any knob — every cell sits within a nat or two of the others on the held-out mean — then this recipe doesn't teach a general rule, and the whole contrastive-recipe story for this project needs rethinking. (2) If the un-stratified mean drops nicely but the held-out mean is flat, the model just learned "don't leak on the specific personas I saw during training" — that's a per-persona suppression, not generalization, and I should report it that way honestly. (3) If the negative-side knobs INCREASE on-policy leakage, the negatives are functioning more like "always-on marker primers" than contrast.

## 0. Plan Summary (technical)

- **Training (RE-TRAIN all 11 cells).** For each cell, build training rows shaped `T(q) + R(q) + ` ※` (+EOS)` where `R(q) = base.generate(T(q))` greedy temp=0 EOS-stop cap-1024 — `T` is the SOURCE-persona system prompt for positives, the bystander system prompt for negatives. Loss masked to ONLY the ` ※` token (+EOS) via the existing `MarkerOnlyDataCollator(tail_tokens=0, marker_token_ids=[83399])`. Disjoint Q_train / Q_eval from the 850-pair generic corpus. LoRA recipe inherited verbatim from #411/#448-v1: r=32, α=64, lr=1e-5, 3 epochs, batch=4, warmup_ratio=0.05, bf16. Per-cell composition keeps the existing 4-knob × 11-cell spec; the only change is that completions are on-policy and loss is marker-only.
- **Hyperparameters (load-bearing).** lr=1e-5 (`Source: #411 dispatch_sycophancy_411.py + #448-v1`), epochs=3 (`Source: #411 + #448-v1`), LoRA r=32 / α=64 / all attn+MLP projections (`Source: #411 + #448-v1`), batch=4 + warmup_ratio=0.05 (`Source: #411`), bf16 (`Source: #411`), marker text=` ※` token-id 83399 (`Source: CLAUDE.md Default marker`), R generation `SamplingParams(temperature=0.0, top_p=1.0, max_tokens=1024, seed=42, stop_token_ids=[eos])` (`Source: #460 v2 plan §4.3 + CLAUDE.md max_new_tokens≥2× rule`), eval `prompt_logprobs=1` with `lora_request=...` then `lora_request=None` on SAME R (`Source: #460 v2 plan §4.6`).
- **Baselines / controls.** Anchor cell = #411 villain recipe (200 pos + 2×200 neg = same shape as #411). Base-model on-policy probe (`lora_request=None`, same R_j) for the per-cell ΔG subtraction. Diagonal implant gate (villain on villain ΔG > +5 nats) per cell. Constant-emission gate (sd(ΔG) ≥ 1.5 nats across 24×20 bystander cells per cell) per cell. **Held-out-bystander control:** the ~15 panel personas NEVER used as a contrastive negative in ANY of the 11 cells (`{surgeon, programmer, chef, lawyer, accountant, journalist, wizard, hero, philosopher, child, ai_assistant, ai}` guaranteed + 3 SHA-256-determined extras) are the H1b headline denominator — they isolate generalization from per-persona suppression (Alternatives-critic Must-Fix-2). Same-row-count contrasts (c8↔c10, c9↔c11) and contrast-efficiency ratios also reported.
- **Loss surface.** Marker-token-only via `MarkerOnlyDataCollator(tail_tokens=0)`. The response R is in `input_ids` (model sees it as context) but every R token has `labels=-100` (zero gradient). Only the ` ※` token + EOS receive loss. Verified by label-audit on the first 5 batches per cell (built into the existing collator).
- **Compute.** 1 pod, 4× H100 ZeRO-3 (`ft-7b` intent). Three workload phases: Phase 1 base-R generation on the FULL eval-panel coverage (~17 min, vLLM TP=1 on 1 GPU; the R-generation universe is `{all training-side personas} ∪ EVAL_PERSONAS_24.keys()` so the Phase-4 eval lookup `R_eval[panel_persona][q]` resolves for EVERY panel persona — see Must-Fix-1 below), Phase 2 LoRA training (11 cells × ~750–1900 rows × 3 epochs sequential on 4× ZeRO-3, ~2.5 h), Phase 3 eval (11 outer × 24 panel × 20 questions × 2 forward passes via vLLM LoRA hot-swap, ~25 min). **Total ~3.05 h wall, ~12.25 GPU-h.**
- **Evaluation.** Primary DV: `ΔG[cell, eval_persona] = mean over 20 eval_q of [ log P_adapter(83399 | T_panel(q) + R_j(q)) − log P_base(83399 | T_panel(q) + R_j(q)) ]` at the post-R slot, across the 24-eval-persona × 20-eval-question grid per cell. Two co-primary headlines: **(H1a) mean bystander ΔG over the 23 non-source panel personas** (the un-stratified average) AND **(H1b) mean bystander ΔG over the held-out subset** = the 12 panel personas that are NEVER used as a contrastive negative in ANY of the 11 cells (`{surgeon, programmer, chef, lawyer, accountant, journalist, wizard, hero, philosopher, child, ai_assistant, ai}`) PLUS the SHA-256-seed-determined 3 EXTENDED_POOL members not drawn into c11's 8-negative set (total ~15 personas, exact count pinned at Phase-0 by `compute_held_out_bystanders()` and asserted in the dispatcher). Reported relative to Anchor; monotonicity across each of the 4 knobs (3 cells per knob in the sparse sweep) + permutation-null over knob assignment. **The headline generalization claim ("widening contrastive negatives reduces bystander leakage") may ONLY be made if H1 holds on the held-out subset (H1b)**; if it holds only on the unstratified average (H1a), the analyzer is pre-committed to report it as "the model stops emitting on the SPECIFIC personas it saw as negatives; no evidence of generalization to held-out bystanders." Success threshold (H1b, the headline): at least one negative-side knob shows a monotone reduction ≥ 1.0 nat on the held-out-subset mean across the 3 swept levels with the permutation-null one-sided p < 0.10 (same threshold the v1 pre-reg used).
- **Risks (top 2).** (1) Marker-only loss on an on-policy R is unprecedented for variable-length R — if `_find_marker_positions` returns 0 or 2+ positions on any row, the loss mask is wrong and the run is silently corrupted. Mitigated by the existing collator's label-audit + a Phase 2 smoke gate that runs the audit and aborts on any row violation. (2) vLLM `lora_request=None` may not detach the last-loaded adapter cleanly → ΔG ≡ 0; mitigated by computing the base pass IMMEDIATELY after each trained pass on a per-cell basis (re-initialising LLM only between cells), AND by the diagonal implant gate (ΔG[villain, villain] > +5 nats catches base ≡ trained). (Also addressed: train-eval persona OVERLAP. The Alternatives critic identified that every `EXTENDED_CANDIDATE_POOL` member is also in `EVAL_PERSONAS_24`, so a count of "trained-as-negative bystanders" varies across cells (2 at anchor → up to 8 at c11). Those trained-negative bystanders sit at ΔG ≈ 0 by construction, so the un-stratified 23-bystander mean drops mechanically with no generalization required. Mitigated by computing BOTH the unstratified mean AND a held-out-subset mean as co-primaries, AND by the SAME-row-count contrasts c8↔c10 and c9↔c11, AND by the contrast-efficiency ratio mean_bystander_ΔG[cell] / diagonal_ΔG[cell] — all spelled out in §6.2 and §6.4.)

### 2.1 What v1–v4 of #448 produced (off-policy run)
- **Headline:** widening the contrastive negatives (more negative personas; more examples per negative persona) reduced mean bystander post log p(` ※`) by ~3–4 nats; widening the positives pushed it UP by ~1–2 nats; permutation-null one-sided p = 0.072 (clears plan's 0.10 falsifier, does NOT meet 0.05).

## 3. Hypothesis

**H1 (headline, falsifiable — TWO co-primary computations).** At least ONE negative-side knob (examples per negative persona OR number of negative personas) shows a monotone reduction of ≥ 1.0 nat across its 3 swept cells, with permutation-null one-sided p < 0.10.

- **H1a (unstratified):** computed on the mean bystander ΔG across the FULL 23 non-source eval personas (the v1 pre-reg denominator).
- **H1b (held-out subset — THIS IS THE HEADLINE):** computed on the mean bystander ΔG across the **held-out subset** = the panel personas that were NEVER used as a contrastive negative in ANY of the 11 cells. The held-out subset is precomputed at Phase-0 by `compute_held_out_bystanders(EVAL_PERSONAS_24, source="villain", cell_specs=CELL_SPECS)`. With the c11 SHA-256 draw fixed at runtime, the set is `EVAL_PERSONAS_24 \ {villain} \ (union over cells of training-negative personas)`. The 12 personas GUARANTEED-held-out by construction (members of `EVAL_PERSONAS_24 \ EXTENDED_CANDIDATE_POOL \ {villain}`, so they cannot be selected by `select_n_bystanders` regardless of seed) are: **`surgeon, programmer, chef, lawyer, accountant, journalist, wizard, hero, philosopher, child, ai_assistant, ai`**. Three additional `EXTENDED_CANDIDATE_POOL` members are also held-out (the 12-persona pool minus c11's 8-negative set; the exact 3 are SHA-256-determined and pinned at Phase-0). **Expected total held-out count: 15** (12 guaranteed + 3 seed-determined). The Phase-0 dispatcher asserts `12 ≤ len(held_out) ≤ 16` and writes the resolved list into the per-cell sentinel as `held_out_bystanders`.

**Why two co-primary numbers, not one.** Every member of `EXTENDED_CANDIDATE_POOL` is also in `EVAL_PERSONAS_24` (verified: the 12-persona pool = `PERSONAS.keys() ∪ {assistant, qwen_default}` is entirely contained in the 24-persona eval panel). So bystanders that were also TRAINED as negatives sit at ΔG ≈ 0 in the cell that trained them. The trained-as-negative-bystander count varies across cells: anchor + c2-c9 = 2 (`medical_doctor, police_officer`); c10 = 4 (anchor + 2 SHA-256 extras); c11 = 8 (anchor + 6 extras). The unstratified mean over 23 bystanders then drops MECHANICALLY as the count rises, with no generalization required. Worked example: anchor mean ≈ (2·0 + 21·4) / 23 = 3.65 nat vs c11 mean ≈ (8·0 + 15·4) / 23 = 2.61 nat → 1.04-nat drop, clears the H1a bar, ZERO generalization to held-out bystanders. H1b on the held-out subset cannot be moved by this artifact and so is the ACTUAL test of "does widening contrastive negatives generalize?".

**FAILS if** no negative-side knob clears 1.0 nat on H1b OR H1b permutation-null p ≥ 0.10. If H1a passes but H1b does NOT, the analyzer is PRE-COMMITTED (no post-hoc reframing) to report: "the model stops emitting on the specific personas it saw as negatives; no evidence of generalization to bystanders never used as negatives."

**H2 (the experiment's reason for being — direction).** Across the 11 cells, the rank order of cells by mean bystander ΔG ON THE HELD-OUT SUBSET places the 3 widest negative-side cells (`+neg-ex-800`, `+neg-personas-8`, `+neg-personas-4`) at the LOW (most-suppressed) end. Tau-vs-random > 0.50. (Same statistic also computed on the unstratified 23-bystander mean for direct compatibility with the v4 pre-reg.)

**H3 (training works — diagonal implant gate, per cell).** For every cell, ΔG measured on the SOURCE persona (villain) with its OWN on-policy R is > +5 nats. The trained model has learned to emit ` ※` after its own villain-context response. FAILED diagonal = the cell's adapter is broken; analyzer flags `epm:failure v1, failure_class: code, reason: marker_implant_failed_cell_<slug>`.

**H4 (training doesn't overgenerate — context-dependence gate, per cell).** sd(ΔG) across the 24×20 bystander grid per cell is ≥ 1.5 nats. A near-constant ΔG (sd < 0.5) means the adapter learned a context-free "always add ` ※`" habit and the contrastive recipe isn't doing what we think it is.

**H5 (secondary, guarded).** Per-bystander ΔG (averaged over 20 questions) negatively correlates with cosine distance to the nearest trained contrastive-negative persona (closer bystanders leak more). Test on every non-degenerate cell (cells where the per-bystander Δ has sd > 0.3 nat). PRE-REGISTERED OUTCOME: if 5+ of 8 non-degenerate cells show |ρ| < 0.20 with CIs straddling zero, the secondary collapses (v4 outcome on absolute post log p) — that result IS reported, not buried. The plan does not promise the geometric mechanism survives.

| Hypothesis | PASS | FAIL | What it tells us |
|---|---|---|---|
| **H1b held-out subset (HEADLINE)** | ≥ 1.0 nat monotone reduction on held-out mean; permutation-null p < 0.10 | < 1.0 nat OR p ≥ 0.10 | **Whether widening contrastive negatives GENERALIZES — the actual goal claim** |
| H1a unstratified (co-primary) | ≥ 1.0 nat monotone reduction on 23-bystander mean; p < 0.10 | otherwise | Recipe knob moves the v4-pre-reg DV; PASS-with-H1b-FAIL = no-generalization story |
| H2 rank order (held-out + unstratified) | Widest-neg cells in bottom-3 by mean ΔG on held-out subset; tau > 0.50 | Otherwise | Direction of the generalization effect |
| H3 diagonal | min over cells of source-self ΔG > +5 nats | any cell < +5 | Training works at all |
| H4 context-dependence | sd(ΔG) ≥ 1.5 per cell | sd(ΔG) < 0.5 | Adapter has context-dependent shift, not constant-emission |
| H5 secondary | ≥ 4 of 8 non-degenerate cells with ρ < −0.30 and CI excluding 0 | 5+ of 8 with |ρ| < 0.20 / CI straddles | Whether the per-bystander geometric story survives |

The loss-mask change (marker-only instead of full-completion) makes this safe — the LoRA cannot rewrite R.

### 4.3.0 Held-out-bystander set (Phase-0 pin)

The Phase-0 dispatcher runs `compute_held_out_bystanders(EVAL_PERSONAS_24, source="villain", cell_specs=CELL_SPECS)` which:

1. Resolves the per-cell training-negative-persona sets via `persona_registry.get_anchor_bystanders("villain")` (cells 1-9) and `persona_registry.select_n_bystanders("villain", N=4 or 8, exclude={"villain"})` (cells 10, 11) — both deterministic given the SHA-256 seed.
2. Computes `trained_negatives_union = ⋃_cells training_negative_personas[cell]`.
3. Returns `held_out = EVAL_PERSONAS_24.keys() \ {"villain"} \ trained_negatives_union`.
4. Asserts `12 ≤ len(held_out) ≤ 16` (12 = lower bound from `EVAL_PERSONAS_24 \ EXTENDED_CANDIDATE_POOL \ {villain}`; 16 = upper bound if c11 reuses anchor + only 2 unique extras, which can't actually happen given `select_n_bystanders`'s n_extras logic, but the loose upper bound future-proofs against pool changes).

These are the EVAL_PERSONAS_24 members NOT in `EXTENDED_CANDIDATE_POOL` (= `PERSONAS.keys() ∪ {assistant, qwen_default}`), so they CANNOT be selected by `select_n_bystanders` regardless of seed.

The **3 SHA-256-determined extra held-out personas** are `EXTENDED_CANDIDATE_POOL \ {villain} \ c11_negatives` (12-pool minus villain minus c11's 8-negative draw = 3 personas). These are pinned by the registry build at Phase 0 and written into `data/issue_448/held_out_bystanders.json` for the analyzer to read.

Expected total `len(held_out) = 15` for the standard CELL_SPECS + villain source.

This set is THE primary-DV denominator for H1b and H2 (held-out). Pinned at Phase-0; consumed by Phase-5 analyzer; emitted in the per-cell sentinel `note.held_out_bystanders` and in the final analyze_summary.json.

### 4.3 R generation (Phase 1, frozen artifact)

**The R-generation universe MUST cover the full eval panel** (Must-Fix-1 from the Methodology critic). Phase-4 eval reads `R_eval[panel_persona][q]` for ALL 24 `EVAL_PERSONAS_24` panel personas; if R for any panel persona is missing, Phase 4 KeyErrors mid-eval AFTER ~2.4 h of training is wasted (the smoke gate, which exercises only the Anchor villain cell, would NOT catch this).

For Phase 1, the set of personas needing R is the union:


where:
- TRAINING-SIDE PERSONAS = `{villain, comedian, assistant, software_engineer, medical_doctor, police_officer, kindergarten_teacher, qwen_default}` (positives ∪ negatives across cells 1-9) ∪ `persona_registry.select_n_bystanders("villain", 4 or 8, exclude={"villain"})` (SHA-256-extended for c10/c11) ∪ `{"no_persona"}` (no system prompt). - EVAL_PERSONAS_24 = the 24-persona panel (`librarian, surgeon, programmer, medical_doctor, software_engineer, data_scientist, kindergarten_teacher, french_person, villain, comedian, police_officer, zelthari_scholar, chef, lawyer, accountant, journalist, wizard, hero, philosopher, child, ai_assistant, ai, assistant, qwen_default`).

- For TRAINING-SIDE personas: q ∈ Q_train_slice(persona) ∪ Q_eval (= EVAL_QUESTIONS, 20 q).

#### 4.3.1 Q_train / Q_eval split (resolves Open Decision 3 from body.md)

The existing 850-pair generic corpus (`data/issue_448/generic_corpus/union_pool.jsonl`) is the source of training questions; the existing 20-question `EVAL_QUESTIONS` set (from `src/explore_persona_space/personas.py`) is the eval question set. **Disjointness:** the 850-pair corpus questions were generated by Sonnet 4.5 specifically for the contrastive sweep and are disjoint from `EVAL_QUESTIONS` by construction (zero set-intersection — already verified in the v1 build-time assertion in `eval_one_cell.py`). We use the existing split unchanged.

For each persona, Q_train = the cell-specific slice (200, 400, 800, etc., per cell knob) drawn deterministically from the 850-pair pool per the existing `build_cell` / per-persona seeded permutation. Q_eval = the 20-question `EVAL_QUESTIONS` set, same across all 24 eval personas.

R needs to be generated once per (persona, q) in the universe specified in §4.3:
- **Training-side personas (~11 distinct across all 11 cells + no_persona = 12):** R for Q_train_slice(persona) ∪ EVAL_QUESTIONS. Q_train_slice across cells unions to ≤ 850 questions per persona (the full corpus); per persona ≤ 870 forwards.
- **Eval-only panel personas (the 12 guaranteed-held-out: `surgeon, programmer, chef, lawyer, accountant, journalist, wizard, hero, philosopher, child, ai_assistant, ai`):** R for EVAL_QUESTIONS ONLY (20 q each); 12 × 20 = **240 base forwards**.

Total: ≤ 12 × 870 + 240 ≈ **10,680 + 240 = 10,920 base forwards** (worst case; usually lower since each cell's Q_train_slice is < 850). vLLM batched, ~50ms / forward (dominated by max_tokens=1024 decode), ~9 min compute + ~5 min warmup ≈ **~17 min wall on 1 GPU** (was ~16 min in v1 plan; +1 min for the 240-forward extension).

### 4.3.2 R-generation prompt (resolves Open Decision 2 from body.md)

**R is generated under the SAME persona's system prompt that the training (or eval) row uses.** I.e.:
- **Training-side positive R**: generated under the SOURCE persona's system prompt (villain for c1–c4 + c7–c11; villain/comedian/etc. per `_positive_personas_for_cell` for c5+c6).
- **Training-side negative R**: generated under the NEGATIVE persona's own system prompt.
- **Training-side no-persona R**: generated with no system prompt.
- **Eval-panel R (for the bystander DV)**: generated under the EVAL-PANEL persona's own system prompt — i.e., for each (panel_persona, q) ∈ EVAL_PERSONAS_24 × EVAL_QUESTIONS, `R_eval[panel_persona][q]` is the BASE model's greedy response under panel_persona's system prompt. This is the on-policy completion the BYSTANDER would produce at deploy time.

The Phase-4 DV `log P_adapter(83399 | T_panel(q) + R_eval[panel_persona][q]) − log P_base(...)` reads the marker log-prob at the slot AFTER the panel persona's own on-policy reply. Train and eval are symmetric: each row's `(T, R)` is on-policy for that T — for training, T = the training persona; for eval, T = the panel persona.

(Considered + rejected: generating ALL R under the bare trigger with no system prompt. Rejected because the eval IS under-bystander-prompt — the bystander says "do I leak the marker on my OWN free-generation answer to a generic question?" — and training under the source's prompt + evaluating under the bystander's prompt would mean train and eval are testing different `(T, R)` joint distributions. Symmetric on-policy R train/eval keeps the construct stationary.)

(Considered + rejected: generating eval-panel R only for the personas that are ALSO training-side, and reusing those for evaluation. Rejected because Phase-4 eval reads `R_eval[panel_persona][q]` for ALL 24 panel personas; the 12 panel-only personas — `surgeon, programmer, chef, lawyer, accountant, journalist, wizard, hero, philosopher, child, ai_assistant, ai` — need their OWN on-policy R generated under their OWN system prompts so the bystander DV is truly on-policy for THAT bystander, not for some proxy. The Phase-0 assertion `set(EVAL_PERSONAS_24).issubset(R_eval.keys())` enforces this.)

### 4.4 Phase 2 smoke gate

Smoke = Phase 3 sweep with `--cells c1_anchor --epochs 1`. Same dispatcher, same code path, same env (per CLAUDE.md *Smoke/sweep architectural parity, UNIFICATION DEFAULT*). Three hard gates, all built into the existing `MarkerOnlyDataCollator`:

1. **Label audit (existing).** First 5 batches hooked; assert each row has exactly 1 marker-token position with `labels != -100` AND exactly 1 EOS position with `labels != -100` (total 2 loss-bearing positions per positive row; 1 per negative row); every R token has `labels == -100`. The collator's existing `MarkerOnlyDataCollator.__call__` warning + count-check is reused; the smoke dispatcher asserts on > 0 violations.
2. **Loss decrease.** Step-30 loss < 75% of step-1 loss (the marker is single-token + base log p ≈ −19 → very high loss → drops fast).
3. **Diagonal implant.** After 1-epoch smoke train, load the smoke adapter via vLLM hot-swap; on 5 held-out villain-context eval rows + their R_eval, compute ΔG = trained − base via the Phase 4 path; assert mean diagonal ΔG > +5 nats. ABORTS sweep on any failure.

**Why code, not a model call.** Marker-only-loss label masking, vLLM teacher-forced log-prob extraction at a specific slot, and content-hashed JSON freezing are all deterministic operations over structured tensor outputs. There is no candidate single-model-call formulation — the metric IS a log-prob at a specific slot, not unstructured text the model could parse for us.

**Smoke/sweep architectural parity (UNIFICATION DEFAULT).** Phase 2 smoke IS Phase 3 sweep with `--cells c1_anchor --epochs 1` and `--skip-base-panel --skip-analyze`. Same dispatcher (`scripts/dispatch_recipe_sweep_448.py` reused from v1, extended to call the new on-policy R loader before `build_cell`). Same subprocess shape (per-cell `subprocess.run(["uv", "run", "python", "-m", "explore_persona_space.experiments.contrastive_recipe_sweep_448.run_one_cell", ...])`). Same env injection (`env={**os.environ, "EPM_SKIP_INLINE_CHECKPOINT_UPLOAD": "1", "CUDA_VISIBLE_DEVICES": "0,1,2,3"}`). Same logging surface (`[phase=...]` lines). Same teardown sequence (rmtree merged dir, gc, torch.cuda.empty_cache, psutil-reap vLLM workers per CLAUDE.md `vLLM in-process teardown` gotcha — applies between Phase 1 and Phase 4 within a single dispatcher process). **Canary cell exercised during smoke:** Anchor (`c1_anchor`) — this exercises both `_positive_personas_for_cell(1)` AND `_negative_personas_for_cell(2)` paths, so the parsed-bystander registry, the marker-only collator, the merge step, and the vLLM hot-swap path are all hit at smoke time.

### 4.6 The Phase 4 eval (adversarial-grade slot read)

Per (cell c, panel persona p, eval question q) — written once for clarity, reused per cell:

```python
sys = persona_registry.get_persona_prompt(p)   # the BYSTANDER's system prompt
prompt_text = tokenizer.apply_chat_template(
    [{"role": "system", "content": sys}, {"role": "user", "content": q}],
    tokenize=False, add_generation_prompt=True,
)
prompt_ids = tokenizer.encode(prompt_text, add_special_tokens=False)
R_ids = R_eval[p][q]["response_token_ids"]              # frozen panel-persona on-policy R
full_ids = prompt_ids + R_ids + [EXPECTED_MARKER_TOKEN_ID]   # = 83399
prompt_slot = len(prompt_ids) + len(R_ids)              # L

prompts_payload.append({"prompt_token_ids": full_ids})
slot_positions.append(prompt_slot)

# After collecting all 24×20=480 payloads for cell c:
sp = SamplingParams(max_tokens=1, temperature=0.0, top_p=1.0,
                    prompt_logprobs=1, logprobs=1, seed=42)
out_trained = llm.generate(prompts_payload, sp,
                           lora_request=LoRARequest(cell_slug, 1, adapter_dir))
out_base    = llm.generate(prompts_payload, sp, lora_request=None)

for ot, ob, L in zip(out_trained, out_base, slot_positions, strict=True):
    slot_t, slot_b = ot.prompt_logprobs[L], ob.prompt_logprobs[L]
    if slot_t is None or slot_b is None:
        raise RuntimeError(f"prompt_logprobs[{L}] None on cell={cell_slug}")
    if EXPECTED_MARKER_TOKEN_ID not in slot_t or EXPECTED_MARKER_TOKEN_ID not in slot_b:
        raise RuntimeError(f"MARKER_ID missing at slot {L}; got top-5: ...")
    g_logp = max(slot_t[EXPECTED_MARKER_TOKEN_ID].logprob, LOGP_FLOOR)
    b_logp = max(slot_b[EXPECTED_MARKER_TOKEN_ID].logprob, LOGP_FLOOR)
    # ... aggregate per (panel persona, q) → mean over 20 q per panel
```

**Off-by-one guards (mandatory, hit in smoke AND sweep):**
1. **Token-id concat (#460 + #406 MF-1 fix):** pass `prompt_token_ids` directly; NEVER `decode(prompt_ids + R_ids + [MARKER_ID])` then re-encode (the leading-space marker re-segments BPE).
2. **Slot-position assertion:** assert `tokenizer.encode(prompt_text, add_special_tokens=False) == prompt_ids` byte-equal before passing to vLLM; assert L = `len(prompt_ids) + len(R_ids)` lands strictly inside `len(full_ids)`.
3. **Diagonal implant gate (Phase 4):** for every cell, ΔG on the SOURCE persona (villain) with its own R_eval > +5 nats; H3 fail otherwise.
4. **Base ≢ trained guard:** for any cell, max over (p, q) of |G_logp[p,q] − B_logp[p,q]| > 5 nats (some cell must show some non-zero shift somewhere) — guards against `lora_request=None` failing to detach.
5. **Numerical floor:** `LOGP_FLOOR = -50.0`; > 1% of cells clamping is a fail-loud signal.

### 4.7 Secondary (resolves Open Decision 4 from body.md)

**Decision: KEEP the secondary analysis as a guarded test, with explicit "may collapse" outcome.** Rationale:
- The v4 off-policy analysis already demonstrated the secondary collapses on absolute post log p — but the v4 analysis was BLOCKED on the off-policy DV anyway. The on-policy v5 DV is a different number (it isolates adapter-induced shift on the model's OWN response context) and the geometric mechanism — "bystanders close in representation space to negatives leak more because their representations are more pulled by the contrastive gradient" — is a hypothesis specifically about the adapter, not the base prior. On-policy v5 gives the secondary its first fair test.
- Cost is near-zero: the cosine-distance machinery (`extend_centroids.py`, layer-20 centroids on HF) is already built; the per-cell per-bystander Spearman is < 10s of CPU.
- The pre-registered outcome includes "collapses again" as an honest possibility (H5 PASS bar = ≥ 4 of 8 non-degenerate cells with ρ < −0.30; FAIL bar = 5+ of 8 with |ρ| < 0.20 / CI straddles). Either result is reportable; no result is buried.

If H5 collapses again, the analyzer reports "the geometric story does not survive the corrected DV either — the per-bystander leakage relationship to cosine-distance is a property of the off-policy probe + the base prior, not of the adapter's contrastive geometry" and that is the secondary's clean-result.

### 6.2 Statistical primary (Phase 5, local VM)

**H1 — TWO co-primary tests, both run, both reported:**

- **H1b (HEADLINE — held-out subset, the generalization test).** For each of the 4 knobs, fit the rank-correlation of cell's knob level (e.g. for pos-ex: {100, 200, 400, 800} → ranks {1, 2, 3, 4} with Anchor pinned at 200) vs **cell's mean ΔG on the held-out subset of bystanders** (the ~15 personas never used as a contrastive negative in ANY cell — see §4.3.0). Knob's "monotone reduction across swept levels" = |Spearman τ| ≥ 0.99 AND post-mean ΔG range across swept cells ≥ 1.0 nat. **Permutation-null:** under H0 "knob has no effect," shuffle cells' assignment to {Anchor, low, mid, high} per knob axis 10,000 times; one-sided p = `(# shuffles ≥ observed monotone-AND-reducing-AND-range-≥-1.0-nat knob count) / 10,000`. PASS at p < 0.10. **This is THE generalization claim.**

- **H1a (co-primary — unstratified 23-bystander mean).** Same test, but the per-cell statistic is the mean ΔG over the FULL 23 non-source panel personas (the v4 pre-reg denominator). PASS at the same threshold (p < 0.10).

- **Interpretation rule (pre-committed; no post-hoc reframing).**
  - H1a PASS + H1b PASS → "Widening contrastive negatives reduces bystander leakage AND the reduction generalizes to bystanders never used as negatives." Headline write-up.
  - H1a PASS + H1b FAIL → "The model stops emitting ` ※` on the specific personas it saw as negatives; no evidence of generalization to held-out bystanders." The H1a pass is interpreted as a per-persona-suppression effect, NOT a generalization effect. Confidence downgraded one notch.
  - H1a FAIL + H1b FAIL → The recipe-knob doesn't move on-policy bystander leakage by the pre-registered amount. Negative result.
  - H1a FAIL + H1b PASS → (unlikely; would mean the held-out personas move MORE than the average, including trained-negative personas). Report straight; investigate the unstratified denominator.

- **SAME-row-count diagnostic contrasts (Alternatives-critic must-fix).** To isolate "row-count grows" from "persona-diversity grows," report the two specific pairs that share row totals:
  - **c8 (neg-ex-400, 200 + 800 + 100 = 1100 rows, 800 neg) ↔ c10 (neg-personas-4, 200 + 4×200 + 100 = 1100 rows, 800 neg).** Same total rows, same total negatives — c8 spreads them across 2 personas × 400, c10 spreads them across 4 personas × 200. Δ(ΔG_held-out) between c8 and c10 isolates persona-diversity from row-count.
  - **c9 (neg-ex-800, 200 + 1600 + 100 = 1900 rows, 1600 neg) ↔ c11 (neg-personas-8, 200 + 8×200 + 100 = 1900 rows, 1600 neg).** Same structure at the wider level.
  - Both contrasts reported with bootstrap CI on ΔG_held-out[cell_a] − ΔG_held-out[cell_b]; the analyzer's headline must include them.

- **Contrast efficiency ratio (Alternatives-critic must-fix).** Per cell, compute `efficiency[cell] = mean_bystander_ΔG_held_out[cell] / diagonal_ΔG[cell]`. A cell that suppresses bystander leakage by lowering the diagonal too (i.e., the adapter dilutes the marker across the board) has efficiency ≈ 1, NOT what we want. A cell that suppresses bystanders while keeping diagonal ΔG large has efficiency ≈ 0 — true contrast. Report per cell; flag cells with `|efficiency| > 0.5` as "implant-dilution suspicion, not real contrast."

**H2 (rank order):** Spearman τ between cell ranks by mean bystander ΔG (low = most-suppressed) and the binary indicator "this cell is one of {+neg-ex-800, +neg-personas-4, +neg-personas-8}". Computed TWICE: on held-out-subset mean (primary) and on unstratified 23-bystander mean (secondary). PASS at τ > 0.50 on the held-out version.

**H3 / H4:** per-cell hard gates (H3 fail = `epm:failure v1, failure_class: code`; H4 fail = analyzer flags methodology correction and downgrades confidence one notch).

**H5 (secondary):** per non-degenerate cell, Spearman ρ(per-bystander ΔG, cosine-distance-to-nearest-negative). 1000-bootstrap CI. Across cells, count cells passing the H5 PASS bar; report the result without spinning. Plain-English summary either way.

**Bootstrap CIs.** Per-cell mean bystander ΔG: 2000-resample bootstrap over the (held-out × 20 questions) grid for H1b primary and the (23 × 20) grid for H1a co-primary, paired by question to preserve within-question correlation (the same R_eval[panel][q] enters multiple cells). Report 95% CI on both denominators.

### 6.3 Length covariate

Length-partial Spearman on H1/H2 is **not** required — the cells differ only in training composition, not in eval-side prompt or R length. The eval grid is the SAME 24×20 across cells; R_eval[p][q] is frozen per (panel persona, question) across cells. Therefore length effects cancel in cross-cell comparisons. The analyzer reports per-cell ΔG distributions un-corrected and adds a sentinel that confirms `sd(R length across cells per (p, q)) == 0` (it should be — R is generated once and reused).

### 6.5 Concerns for the analyzer (non-blocking, from all 3 critics)

The analyzer (Phase 5) must address these in the clean-result write-up:

1. **Within-cell bootstrap clusters only by question, not by bystander-across-questions** → the true CIs are likely wider than what the question-clustered bootstrap reports (a bystander's questions are non-independent if the persona has a strong per-persona bias). Analyzer spot-checks a per-bystander cluster bootstrap on Anchor + 1 negative-side cell; if the CIs widen by > 1.5×, the headline confidence drops one notch.

2. **Small-N per-knob permutation null** (4 cells/knob, min one-sided p ≈ 0.042). The analyzer must (a) report WHICH knob drove the headline (not just "≥ 1 knob cleared the bar"), and (b) weigh the range of the per-cell ΔG against the monotonicity — a 1.0-nat range with τ = 1.0 across 4 cells is barely-significant; a 3.0-nat range is much stronger evidence.

3. **Positive-side G_logp may saturate near 0 on-policy.** If positive-side cells (c2-c6) show `mean G_logp[pos_cells] > -1.0` nat, the ΔG cap is being hit and the per-cell rank shuffles among positive cells aren't informative. The free-emission-rate argmax recompute (rate of `argmax_token_at_slot == 83399`) is the anchor cross-check; if rates differ from the log-prob rank, the rates are authoritative. Report per-cell sd(ΔG) (H4) — if positive cells have systematically LOWER sd than negative cells, frame as "negatives suppress what positives free-float," not generalization.

4. **Truncation rate per persona (R cap 1024).** Report per persona, per cell. Spot-check ΔG on the truncated-R subset; if substantially different from the EOS-terminated-R subset, the truncation is artifacting the DV.

5. **Single source = villain → claim scope.** The clean-result must scope the headline to "villain-induced marker leakage on Qwen-2.5-7B-Instruct under THIS contrastive-LoRA-SFT recipe family"; do not generalize to other source personas, other marker tokens, or other model sizes. v4 over-generalized; v5 doesn't.

6. **H1 signed-vs-unsigned monotone-count.** A +pos knob crossing the bar in the RAISE direction (e.g. +pos-personas-4 INCREASES bystander ΔG) MUST NOT count toward H1's reduction headline. The permutation-null is over signed monotone reductions only (one-sided), not absolute monotonicity. The analyzer report cross-checks the sign and explicitly excludes raise-direction passes from the reduction count.
