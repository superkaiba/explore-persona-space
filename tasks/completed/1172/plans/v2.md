The pod lane has NO single launcher-owned composition point (launches are experimenter-composed over SSH), so the mask is bootstrap-level, three channels, matching how each shell class actually gets env (verified this session):

## 11. Decision Rationale

1. **`${PYTHONPATH:+:$PYTHONPATH}` append form (vs bare `$WORKLOAD_ROOT:$PYTHONPATH`).**
   *What:* expand the inherited value only when set-and-non-empty. *Why:* a bare colon-join leaves a trailing colon when PYTHONPATH is unset/empty, and CPython treats a leading/trailing colon in PYTHONPATH as "add cwd to sys.path" — a silent import-injection hazard; `:+` is also nounset-exempt, so it survives both lanes' `set -u`. *Source:* candidate diff sketch on #853/#1172 (verbatim); bash manual § Shell Parameter Expansion; cpython issue 107353 (web-verified this session). *Alternatives:* bare join (rejected: trailing colon + `set -u` interactions); `${PYTHONPATH-}` guard (rejected: still emits the trailing colon).
2. **Prepend (repo root first), not append.**
   *What:* repo root leads the search path. *Why:* the imports being fixed are OUR `scripts.*` package; prepending guarantees the repo-root package wins over any hypothetical same-named entry later in the path, and the no-collision check (§8 row 1) bounds the shadowing risk; appending would leave resolution dependent on whatever the image/module system put first. *Source:* standard practice (Real Python / shell-config references, web-checked); precedent: the #641 `REPO_ROOT` export similarly makes the repo-root value authoritative. *Alternatives:* append (rejected: leaves the crash class reachable whenever an ambient entry shadows).
3. **Per-lane variable choice** — `$WORKLOAD_ROOT` (GCP), `$SCRATCH_JOB_DIR` (SLURM), literal `/workspace/explore-persona-space` (pod).
   *Why:* each is the lane's canonical runtime repo root: GCP exports WORKLOAD_ROOT in the shared prelude (#641 comment block confirms the clone target); SLURM stages run from the rsynced `$SCRATCH_JOB_DIR` (venv block `cd`, L1393); the pod clone path is fixed by bootstrap. *Source:* #641 (GCP), #588/#601 (SLURM custom-stage env parity), `bootstrap_pod.sh` itself (pod). *Alternatives:* a shared literal (rejected: wrong on GCP/SLURM); `$REPO_ROOT` on GCP (rejected: workload_cmd may override REPO_ROOT per-command — belt-and-suspenders semantics documented at #641 — while WORKLOAD_ROOT is the invariant clone root).
4. **GCP placement: workload_cmd branch only (not the shared prelude, not the hydra branch).**
   *Why:* keeps the #588 byte-identity hydra snapshot valid without regeneration; `scripts/train.py` has no `scripts.*` imports (grepped — zero hits), so the hydra branch cannot express the trap. *Source:* #641 precedent (identical scoping + its `"REPO_ROOT" not in hydra_script` assert); `compute-backend-failover.md` § Snapshot pin (regeneration is deliberate-only). *Alternatives:* shared-prelude placement + fixture regen (rejected: cost without coverage; must-ask if ever wanted).
5. **SLURM placement: single export initializing `stage_blocks` (not per-custom-stage, not the sbatch prelude).**
   *Why:* uniform coverage of local/custom/open_instruct with one line (the Goal says "every managed compute lane", and the local stage runs `scripts/train.py` too); after module-load so cluster-module PYTHONPATH mutations survive as appended entries. *Source:* #601's parity precedent (its per-stage scoping is specific to per-issue WANDB_PROJECT values); task brief's explicit single-anchor question. *Alternatives:* prelude L1262 (rejected: renders before module load); per-custom-stage (rejected: leaves two stage backends uncovered).
6. **Pod lane: rc-append + `.env` + shim, with SEPARATE idempotency guards (vs rc-only or per-command prefixes).**
   *Why:* verified shell-class coverage map — rc files never reach non-interactive SSH shells (bootstrap's own PS1-guard comment, L379-385); the canonical setsid launcher's `set -a; . .env` IS the production launch channel (experimenter.md L761), so `.env` is the load-bearing anchor; the shim covers bare `python` invocations. Separate grep guards so legacy pods gain the lines on re-bootstrap (the existing RCEOF guard keys on WANDB_CACHE_DIR and would skip them). *Source:* #853 (the trap), bootstrap_pod.sh L379-414 (shell-class analysis, read this session), experimenter.md launcher template. *Alternatives:* `/etc/environment` via PAM (rejected: sshd/PAM behavior unverified in RunPod containers; heavier assumption than the three channels we can read); editing the launcher template in experimenter.md (rejected: doc-level, per-launch, not launcher-level — and the template already sources `.env`).
7. **Pod `.env` line as plain assignment (no expansion).**
   *Why:* dual consumers — shell sourcing under `set -u` (bare `$PYTHONPATH` would crash the launcher when unset) and python-dotenv (its interpolation supports `${VAR}`/`${VAR:-x}` but not `:+`). A plain single path has no colon hazards. *Source:* experimenter.md launcher (`set -uo pipefail` + `set -a` source), python-dotenv 1.2.x interpolation surface; gotchas.md dotenv entries. *Alternatives:* `:+` form in `.env` (rejected: dotenv-side unexpanded garbage risk); omitting `.env` (rejected: loses the ONLY channel that reaches the canonical launcher).
