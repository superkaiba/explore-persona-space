## 1. Requirement + acceptance criteria

**Requirement.** The GCE EXIT-trap crash-persist (`_eps_persist_diagnostics`, rendered
into the startup script by `src/explore_persona_space/backends/gcp.py`) must include
the local `analysis_tensors/` staging tree in its upload set, so a run that stages
map/tensor payloads locally (Upload Policy #521 class: "intermediate analysis tensors
referenced as downstream inputs") no longer loses them when the boot disk is
auto-DELETEd on a non-zero exit. Driving incident: #1739 nlmap round, 2026-07-30 —
a banked 412 MB MLP map fit (0.68 GPU-h) died with the boot disk on a DESIGNED rc=7
stop (`epm:progress` v122 on #1739; instance eps-issue-1739-nlmap, attempt
att-20260730-173427-nlmap).

**Acceptance criteria.**
1. The persist dir list (currently gcp.py L2280-2285: `eval_results/issue_<N>`,
   `data/issue_<N>`, `data/issue<N>`) additionally covers the workload-root
   `analysis_tensors/` tree, uploading to
   `issue<N>_partial/<attempt_id>/analysis_tensors/`.
2. Both live staging conventions are covered by ONE entry: the flat
   `<root>/analysis_tensors/<file>` convention (issue_1072 `run_1072.py` L110,
   issue_823 `run_823.py` L1297+) AND the issue-scoped
   `<root>/analysis_tensors/issue_<N>/maps/...` convention (#1739 plan §10) — the
   recursive `_up_dir` walk of `root / "analysis_tensors"` subsumes both. (A fresh
   GCE clone ships NO committed `analysis_tensors/` tree — verified
   `git ls-files analysis_tensors` empty — so everything under it at crash time is
   this run's output; no repo-content re-upload risk.)
3. The new entry is LAST in the dir list: tensors are the largest class (412 MB in
   the incident), and the #854 traceback-first ordering must keep landing the
   crash report + eval JSONs + data dirs before any budget timeout fires
   mid-tensor-upload (timeout-mid-persist is BY DESIGN, per the in-file comment).
4. The #854 contract is otherwise UNCHANGED: `timeout 300` bound, IGNORE cache
   excludes (`hf_dl/**`, `g*_dl/**`, `store/**`, `.cache/**`, nested variants),
   BATCH_MAX chunked single-commit `upload_folder` calls, zero per-file
   `upload_file` loops. The budget-arithmetic comment (gcp.py ~L1949-1952:
   "typically ~3 partial dirs … (1 + n_dirs) x 60s ~= 240s") is updated to name
   the new dir count (~4 dirs → worst-case aggregate retry sleep ~300s; the
   design's accept-mid-persist-timeout rationale already covers it).
5. The behavioral pin test
   `tests/test_gcp_backend.py::test_persist_heredoc_uploads_in_order_and_covers_data_dir`
   is updated: fixture gains `analysis_tensors/issue_137/maps/map.npz` (or
   similar) + a flat `analysis_tensors/summary.json`; asserts a new
   `("folder", "issue137_partial/att-x/analysis_tensors")` upload AFTER
   `data_issue137` and BEFORE the final bundle; `len(seq)` bumped accordingly.
   Every other `_run_persist_heredoc`-based test in the file is re-run and any
   affected sequence/count pins updated (a fixture WITHOUT analysis_tensors must
   keep passing via the existing empty-dir SKIP path — assert no seq change there).
6. `ruff check` + `ruff format --check` clean on touched files; the Step 9c
   touched-scope gate passes (no NEW failures vs the known-red-on-main ledger).
