### Hunk 1 — `_GRID_FACTOR`: any axis factor + approximation/paren decoration (replaces :1110-1113)

```python
# The grid side accepts ANY axis factor — a count ("24"), a count + axis
# noun ("6 arms", "3 layers", "~3 quantities"), or a bare axis noun
# ("cells", "batteries") — optionally opened by an approximation / paren
# decoration ("~3", "≈8", "(6 arms"). The load-bearing discriminator is
# the DRAW-BEARING factor, not the grid noun: the #810 false-PASS class
# is a grid-only product with NO draw factor ("34 x 50 x 28",
# "layers x 3584", "6 arms × 3 layers × 16 folds") and still fails; a
# noun whitelist only rots ("batteries"/"quantities" false-FAILed the
# conforming #833 v8 sizing block — #1086).
_GRID_DECOR = r"(?:[~≈(]\s*)?"
_GRID_FACTOR = (
    r"(?:\d[\d,_]*(?:\s+[A-Za-z][\w-]*)?"
    r"|[A-Za-z][\w-]*)"
)
```

### Hunk 2 — `_MULT_ARITH_RE`: thread the decoration (replaces :1117-1120)

```python
_MULT_ARITH_RE = re.compile(
    rf"(?i)\b(?:{_DRAW_FACTOR}\s*{_MULT_TOKEN}\s*{_GRID_DECOR}{_GRID_FACTOR}"
    rf"|{_GRID_FACTOR}\s*{_MULT_TOKEN}\s*{_DRAW_FACTOR})\b"
)
```

`_DRAW_FACTOR`, `_MULT_TOKEN`, and `_BATTERY_TRIGGER_RE` are **byte-unchanged**.

- **Arith-anchored evidence windows instead of trigger widening.** *What:* add `_trigger_windows(plan, _MULT_ARITH_RE, 15)` to the evidence set; trigger byte-unchanged. *Why:* fixes the §6-registration-vs-§9-sizing layout split (the planner spec itself puts sizing in §9) while adding zero new FAIL surface. *Source:* #833 v8 (58-line gap, measured); corpus audit this session (trigger-widening prototype: +8 false-FAIL issues, 1 broken test; adopted design: 0). *Alternatives:* trigger widening (rejected, measured above); radius increase (rejected — the c12 docstring bans drifting toward document-global; #810 v1).
- **Any-axis `_GRID_FACTOR` with `~ ≈ (` decoration.** *What:* drop the 10-noun whitelist; keep the draw-bearing factor as the sole discriminator. *Why:* noun whitelists rot ("batteries"/"quantities" — #833 v8; next month "estimators"); the #810 false-PASS class is defined by the MISSING draw factor, not by grid nouns. *Source:* #810 (grid-only fixtures still FAIL, test-pinned), #833 v8 L149 (the three rejected forms), task body's own diff-sketch direction ("regardless of which axis names appear"). *Alternatives:* extending the whitelist (rejected: recurring bounce class); requiring `=`-arithmetic tails (rejected: over-fits to one prose style).
- **`_C18_ARTIFACT_RE` additions (`analysis_tensors\w*/\S*`, `issue\d{2,}[\w.-]*/\S+`).** *What:* recognize suffixed tensor-store dirs + canonical `issueN_<slug>/…` HF data-repo prefixes as artifact evidence. *Why:* these ARE the project's canonical per-issue artifact addresses (Upload Policy table); v8's evidence was rejected purely for lacking a file extension. *Source:* #833 v8 L80; CLAUDE.md Upload Policy destinations. *Alternatives:* a generic any-slash-path token (rejected: would let a rule-file citation count as artifact evidence); backtick-delimited paths only (rejected: brittle to unbackticked prose).
- **`_C18_BYCONSTRUCTION_RE` remedy-text alternative (`produces? every registered`).** *What:* accept the exact phrasing the check's FAIL detail prescribes. *Why:* a checker whose remedy text cannot satisfy its own satisfier regex guarantees a bounce loop (#833: bounced, implemented remedy verbatim, still FAILed). *Source:* verify_plan.py:2333-2339 (remedy text) vs :2173-2176 (satisfier), #833 v8. *Alternatives:* rewording the remedy text to match the old regex (rejected: "both arms … produced" ordering is unnatural and the #810 v15 exemplar's own fix wouldn't teach it); dropping the deferral guard (rejected: MF-B negative must keep failing, and does).
