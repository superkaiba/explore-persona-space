## 4. Design

### 4a. Design decisions (settled)

1. **Guard placement — BEFORE the CPU early-return.** The current function early-returns `cpu` when `cpu_only or not torch.cuda.is_available()`; a guard placed after that is unreachable on the CUDA-less VM (untestable without monkeypatching `torch.cuda.is_available`) AND lets a CUDA-less hand-launch with `--gpu-id N` silently run on CPU — the same silent-misdirection class as #813. Placing it first makes the raise CPU-testable with no monkeypatch and covers both variants. Deliberate small behavior change: on a CUDA-less box, `gpu_id>0` + no CVD + not `cpu_only` now raises instead of silently returning `cpu` — that shape is always a mis-launch (the user named a specific GPU), and no in-repo caller or test exercises it (verified, §12 A6).
2. **Condition `gpu_id > 0`, not `!= 0`.** `--gpu-id 0` + no CVD is the documented, correct single-GPU shape (`cuda:0` == physical GPU 0 — no mismatch; it is `issue811_phase0_extract`'s documented usage and `issue667_dispatch.py:337`'s in-process call). A negative gpu_id is out-of-domain invalid input the argparse `type=int` admits but nothing passes; raising the CVD message on it (`env CUDA_VISIBLE_DEVICES=-1 ...`) would be actively misleading. `> 0` scopes the guard to exactly the demonstrated failure class.
3. **Error type + message:** `RuntimeError`, quoted verbatim in §4b. Message is worker-generic (`scripts/<worker>.py`) because the helper is imported by 3 descendant scripts — naming `issue667_extract.py` would mislead when raised from `issue811_phase0_extract.py`.
4. **Tests:** new file `tests/test_issue667_device_guard.py` (no existing test calls `_device` — grep of `tests/` for `_device\(` returns only other modules' `_resolve_device`/`_fit_device`; the existing issue667 test files pin other invariants). Import pattern copied from `tests/test_issue811_maxp.py:24-28` (sys.path inserts then `import issue667_extract as ex`), which already proves a bare module import is CPU-VM-safe (module-level `load_dotenv()` at line 107 resolves from the repo-root pytest cwd; no model downloads at import).
5. **Dispatchers: NO change.** Verified per-cell env construction pins CVD before exec:
   - `scripts/issue667_dispatch.py:532-535` — `env = {"CUDA_VISIBLE_DEVICES": "" if cpu_only else str(gpu_id), "VLLM_WORKER_MULTIPROC_METHOD": "spawn"}`, merged over `{**os.environ}` at lines 142-144 / 163-165. (`cpu_only` children set CVD `""` — the membership test passes — and also pass `--cpu-only`, which short-circuits the guard first.)
   - `scripts/issue667_pertoken_dispatch.py:136-140` — identical shape (with a `CVD_PIN_EXEMPT` comment for the cpu_only `""` case).
   - The alllayer dispatcher's pin is already test-pinned: `tests/test_issue667_alllayer_wave.py:71-86` asserts `env["CUDA_VISIBLE_DEVICES"] == str(gpu_id)` + matching `--gpu-id` for gpu_id 0..7.

### 4b. The concrete diff — `scripts/issue667_extract.py:437-440`

Replace:

```python
def _device(gpu_id: int, cpu_only: bool) -> torch.device:
    if cpu_only or not torch.cuda.is_available():
        return torch.device("cpu")
    return torch.device("cuda:0")  # CVD pins the physical GPU in the launcher env
```

with:

```python
def _device(gpu_id: int, cpu_only: bool) -> torch.device:
    """Resolve the torch device; fail loud on the #813 bare---gpu-id launch shape.

    This worker class treats --gpu-id as INFORMATIONAL: the physical GPU is
    selected ONLY by the CUDA_VISIBLE_DEVICES pin the launcher sets in the
    child env (gotchas.md § hand-launching a dispatcher-managed per-cell GPU
    worker). --gpu-id N>0 without that pin would silently bind the default
    GPU (incident #813: 4 workers crashed at vLLM init_device), so raise.
    """
    if not cpu_only and gpu_id > 0 and "CUDA_VISIBLE_DEVICES" not in os.environ:
        raise RuntimeError(
            f"--gpu-id {gpu_id} passed without CUDA_VISIBLE_DEVICES in the launcher "
            "environment. This worker treats --gpu-id as informational and always "
            "binds cuda:0 — the physical GPU is selected ONLY by the env pin, so "
            "this launch would silently target the default GPU (incident #813). "
            f"Relaunch as: env CUDA_VISIBLE_DEVICES={gpu_id} uv run python "
            f"scripts/<worker>.py ... --gpu-id {gpu_id} — one distinct GPU per "
            "parallel worker; see .claude/rules/gotchas.md, entry 'Hand-launching "
            "a dispatcher-managed per-cell GPU worker'."
        )
    if cpu_only or not torch.cuda.is_available():
        return torch.device("cpu")
    return torch.device("cuda:0")  # CVD pins the physical GPU in the launcher env
```

(`os` is already imported at module top, line 59.)

### 4d. Test file sketch — `tests/test_issue667_device_guard.py` (~60 lines)

```python
"""#962: _device() fail-loud CVD guard (incident #813).

A launcher-pinned-class worker launched with --gpu-id N>0 but no
CUDA_VISIBLE_DEVICES env pin must raise at device resolution, not silently
bind cuda:0 (or silently fall back to CPU). All CPU; no GPU required.
"""
from __future__ import annotations

import sys
from pathlib import Path

import pytest
import torch

REPO_ROOT = Path(__file__).resolve().parent.parent
sys.path.insert(0, str(REPO_ROOT / "scripts"))
sys.path.insert(0, str(REPO_ROOT / "src"))

import issue667_extract as ex  # noqa: E402


def test_gpu_id_positive_without_cvd_raises(monkeypatch):
    monkeypatch.delenv("CUDA_VISIBLE_DEVICES", raising=False)
    with pytest.raises(RuntimeError, match="CUDA_VISIBLE_DEVICES"):
        ex._device(3, cpu_only=False)


def test_error_message_names_relaunch_recipe(monkeypatch):
    monkeypatch.delenv("CUDA_VISIBLE_DEVICES", raising=False)
    with pytest.raises(RuntimeError, match=r"env CUDA_VISIBLE_DEVICES=3 .*--gpu-id 3"):
        ex._device(3, cpu_only=False)


def test_gpu_id_positive_with_cvd_passes(monkeypatch):
    monkeypatch.setenv("CUDA_VISIBLE_DEVICES", "3")
    dev = ex._device(3, cpu_only=False)  # no raise; device per CUDA availability
    assert dev.type in ("cpu", "cuda")


def test_gpu_id_zero_without_cvd_passes(monkeypatch):
    monkeypatch.delenv("CUDA_VISIBLE_DEVICES", raising=False)
    assert ex._device(0, cpu_only=False).type in ("cpu", "cuda")


def test_cpu_only_short_circuits_any_gpu_id(monkeypatch):
    monkeypatch.delenv("CUDA_VISIBLE_DEVICES", raising=False)
    assert ex._device(7, cpu_only=True) == torch.device("cpu")


def test_cvd_set_and_cuda_available_returns_cuda0(monkeypatch):
    monkeypatch.setenv("CUDA_VISIBLE_DEVICES", "2")
    monkeypatch.setattr(torch.cuda, "is_available", lambda: True)
    assert ex._device(2, cpu_only=False) == torch.device("cuda:0")
```

(`torch.device("cuda:0")` construction does not initialize CUDA, so the `is_available` monkeypatch is safe on the CUDA-less VM.)
