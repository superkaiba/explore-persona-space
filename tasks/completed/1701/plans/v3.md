### 4.1 The three new REQUIRED bullets — exact wording

The three duties append to the `**User-chat inline free analysis**` bullet in `CLAUDE.md`, immediately after the existing `**Inline measurement-design + figure-sanity duties (REQUIRED …)**` sentence, before the closing `USER-INITIATED ONLY:` sentence. Verbatim insert text (three bold-lead sentences, each ≤~700 chars; total **1,791 chars** — measured, not estimated):

> **Inline estimator-validity + record-integrity duties (REQUIRED — same rationale: this carve-out skips the planner+critic stack, where the fit-well-posedness / estimator-parity / promoted-body-consistency reviews live):** (1) BEFORE any ridge / linear-map / probe FIT, the dispatch note states `n_train` vs the feature dimension `d`; when `n_train < d` the round REFUSES the fit unless the note explicitly justifies a deliberately under-determined regime (regularization-limit / null-space read / smoke shape) — every held-out R² in the `n_train < d` regime is estimator-degenerate, not a signal read (#1701, sess `dffde9b6`: n=1,877 vs d=3,584 → ceiling 0.099 vs published 0.625). (2) BEFORE launching any re-implemented estimator whose in-repo reference the round can name (a `scripts/issue1345_operator_comparison`-style chain, a canonical `ridge_fit_predict_fast`, a shipped judge/scorer), the dispatch note records the DIFF between the new estimator and the named reference (function + file) — permissiveness-broadening (more inputs absorbed, weaker constraints) is called out explicitly. (3) When a round REFUTES a claim in ANY task's promoted body (its own parent or a sibling), it MUST — in the SAME turn as the result summary — either apply a NON-Takeaway PROSE correction directly to the refuted task's body via `task.py set-body` (typo / caption / fixed numeric value — never `task.py promote` or a `classification` flip; the user-only classification contract is unchanged) OR file a `kind: infra` task via `scripts/file_infra_task.py` naming the refuted issue and the refuting evidence — filing is the presumption for anything touching a bolded Takeaway; a chat-only "I did not fix X" is an INCOMPLETE round (#825's promoted Takeaway was refuted and nothing filed; #1701 origin).

Design points (why this exact shape):

- **Parallel register.** Bold-lead-then-parenthetical opener mirrors the existing "Compute-character pre-launch statement (REQUIRED …)" and "Inline measurement-design + figure-sanity duties (REQUIRED …)" openers verbatim — no new grammar for the critic-mode reader to parse.
- **(i) is a STATEMENT + REFUSAL rule, not a code assert.** The dispatch note carries `n_train=X d=Y` (grep-checkable), and the refusal fires unless the note justifies the under-determined regime. This matches how (i)'s siblings work: the compute-character block MEASURES + states, it doesn't add per-cell assertions.
- **(ii) is a DIFF disclosure, not a re-run gate.** The round names the in-repo reference (file + function) and states what the new estimator ADMITS that the reference REFUSES. Reviewers can then ask the "why the deviation?" question at review time; the duty is the disclosure, not the parity gate itself.
- **(iii) SEPARATES apply-vs-file by Takeaway-touching AND is PROSE-only (never a classification flip).** Non-Takeaway corrections (a typo in a caption, a fixed hyperparameter value, a numeric misprint) can be applied inline via `task.py set-body`; anything touching a bolded Takeaway ROUTES to filing via `scripts/file_infra_task.py` — the user then triages. The `classification` field (`useful` / `not-useful` / `pending`) and the `awaiting_promotion → completed` transition stay strictly user-only via `task.py promote` (fact-checker verdict 8: the user-only classification contract lives in CLAUDE.md prose + the halt-criterion contract; the plan's duty (iii) does NOT authorize any programmatic `task.py promote` invocation and does NOT flip classification). The duty text carries the "never `task.py promote`" scope phrase explicitly so the reader cannot mis-apply it.
