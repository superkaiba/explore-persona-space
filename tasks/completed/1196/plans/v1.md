### 4.1 Sibling-script loader

```python
def _load_verify_task_body():
    """Import scripts/verify_task_body.py as a sibling-script module.

    Robust to BOTH launch modes: `uv run python scripts/audit_...py`
    (scripts/ is already sys.path[0]) and the test file's
    importlib.spec_from_file_location loading (which does NOT put
    scripts/ on sys.path). Follows the established sibling-import
    convention (_rest_backfill.py:19, backfill_artifact_registry.py:34).
    """
    import importlib
    scripts_dir = str(Path(__file__).resolve().parent)
    if scripts_dir not in sys.path:
        sys.path.insert(0, scripts_dir)
    return importlib.import_module("verify_task_body")
```

Lazy (called inside the check helper, cached by Python's module cache) so the auditor's import stays light and the legacy/no-fm paths pay nothing. `import sys` joins the module's stdlib imports in the same edit (PostToolUse-ruff F401 discipline: import + first usage together).

### 4.2 Per-body WARN helper (the check itself)

```python
def h1_title_sync_warn(text: str) -> str | None:
    """WARN-severity corpus mirror of verify_task_body.py's gate-time
    `check_h1_matches_frontmatter_title` (#1110 gate check; #1196 corpus
    surface). Delegates the ENTIRE comparison — fence-aware sentinel
    gate (v4/v3/v2-nested), frontmatter parse, whitespace-collapse-only
    normalization, missing-fm-title / missing-H1 anomaly branches — to
    the gate check, then flattens its severity: any flagged outcome
    (gate FAIL on v4, gate WARN on grandfathered v3/v2) returns the
    check's detail string; an in-sync or out-of-scope body returns None.
    WARN only: callers never let this affect the exit code — post-gate
    remediation is a human call.
    """
    vtb = _load_verify_task_body()
    fm, body = vtb.split_frontmatter(text)
    res = vtb.check_h1_matches_frontmatter_title(body, fm)
    if (not res.passed) or res.is_warn:
        return res.detail
    return None
```

The flagged-predicate `(not res.passed) or res.is_warn` covers all four gate outcomes exactly: v4 mismatch/anomaly → `passed=False`; v3/v2 mismatch/anomaly → `passed=True, is_warn=True`; skip branches (not sentinelled; empty fm) and the in-sync success → `passed=True, is_warn=False` → `None`. The empty-fm skip is what silently exempts frontmatter-less analyzer drafts on the file path. No paper-stub special case here — exact gate parity (the sentinel gate governs; 0 sentinelled paper stubs exist today, and the single-body path's existing `_is_paper_stub` early return is upstream anyway).

### 4.3 Corpus sweep mode

```python
def _run_title_sync_sweep(tasks_root: Path | None = None) -> int:
    """Corpus-wide WARN-level H1-vs-frontmatter-title sync sweep (#1196).

    Iterates tasks/<status>/<N>/body.md (resolver-derived root — never a
    cwd-relative tasks/ path), prints one WARN row per flagged
    sentinelled body. ALWAYS returns 0: WARN only, never FAIL.
    `tasks_root` is parameterized for tests; production default is
    task_workflow.tasks_dir().
    """
    if tasks_root is None:
        from explore_persona_space.task_workflow import tasks_dir
        tasks_root = tasks_dir()
    rows: list[tuple[int, str, str]] = []
    n_scanned = 0
    for body_path in sorted(tasks_root.glob("*/*/body.md")):
        tid = body_path.parent.name
        if not tid.isdigit():
            continue  # not a task folder (e.g. a non-numeric sibling dir)
        n_scanned += 1
        detail = h1_title_sync_warn(body_path.read_text(encoding="utf-8"))
        if detail:
            rows.append((int(tid), body_path.parent.parent.name, detail))
    print(f"Scanned {n_scanned} task bodies under {tasks_root}")
    if not rows:
        print("PASS: H1 == frontmatter title on every sentinelled clean-result body")
        return 0
    print(
        f"WARN: {len(rows)} sentinelled clean-result body(ies) with "
        f"H1/frontmatter-title drift (WARN only — exit stays 0; "
        f'sync via `task.py set-title <N> "<H1 text>"`, H1 canonical)'
    )
    for tid, status, detail in sorted(rows):
        print(f"- #{tid} ({status}): {detail}")
    return 0
```

Row format follows the auditor's existing `- <key>: <detail>` convention, prefixed with the task id + status (the two facts a human triaging post-gate drift needs); the detail string is the gate check's own message (it already carries truncated `H1: ...!r vs title: ...!r` reprs and the two remediation commands). Read failures (`OSError`) are NOT swallowed — fail-fast per project rule; the corpus is git-managed and readable.

## 5. Controls / edge cases

**MUST warn (each becomes a test or is corpus-verified):**
- A sentinelled v4 body whose H1 ≠ fm title after whitespace collapse (the #658/#664/#763 shape).
- A sentinelled v3/v2 body likewise (the #432/#458/#654/#665 shape — grandfathered to WARN at gate time, and WARN here too; identical rendered severity in the sweep, by design).
- Case-only difference (no case folding — the gate check deliberately treats transliteration/case drift as REAL drift, #763 rationale).
- A sentinelled body with no frontmatter `title`, or no H1 (broken promotion; anomaly branches; 0 in corpus today).

**MUST NOT warn:**
- Non-sentinelled bodies (981 of 1151 today) — proposed/planning/infra bodies legitimately have unsynced or absent H1s.
- Whitespace-only differences (line-wrap, double spaces) — the collapse normalization eats them.
- Frontmatter-less inputs (analyzer /tmp drafts on the file path) — the gate check's empty-fm skip.
- A body that merely QUOTES a sentinel inside a code fence or `<details>` block — the fence-aware `is_v4`/`is_v3`/`is_v2_nested_design` predicates (inherited by delegation) already handle this.
- Paper stubs: excluded on the single-body path by the existing `_is_paper_stub` early return; in the sweep they carry no sentinel (0/170 verified) so the sentinel gate skips them. A hypothetical future sentinelled paper stub WOULD warn — same as at gate time; acceptable and consistent.
- The confidence tag: `set-title` stores the FULL title including `(… confidence)` (verified: 163 of 170 sentinelled bodies compare equal WITH the tag on both sides), so tag-on-both-sides is the in-sync normal case, not a divergence.

## 11. Decision Rationale

- **WARN-not-FAIL, always exit 0.** *What:* the sweep and the per-body WARN never flip an exit code. *Why:* post-gate remediation is a human call (retitles on completed bodies may be deliberate; blocking automation on them would jam pipelines that legitimately touch parked bodies). *Source:* the candidate block on #1110 (this task's Provenance), mirroring the gate check's own v3/v2 grandfathering. *Alternatives:* FAIL on v4 bodies in the sweep (rejected — the sweep runs outside any gate; there is no actor obligated to fix a completed body before proceeding).
- **Delegate to `check_h1_matches_frontmatter_title`, don't mirror.** *What:* the auditor calls the gate check and flattens severity, rather than reimplementing `find_h1_title` + `_norm` + sentinel gating. *Why:* the brief's core requirement is that corpus and gate NEVER disagree on normalization; delegation makes parity structural (future gate-check changes propagate automatically), needs ZERO diff to the heavily-tested 10.6K-line-pinned verifier, and the `_norm` closure isn't importable alone anyway. *Source:* read of both files; live import smoke. *Alternatives:* (a) lift `_norm` to module level in verify_task_body + import pieces (touches the verifier for no benefit); (b) mirror the 1-line normalization (drifts silently — the exact failure mode #1110 fixed for titles).
- **Scope = the gate check's own sentinel gate, all statuses.** *What:* audited set = bodies where `is_v4|is_v3|is_v2_nested_design` fires, at every `tasks/<status>/`. *Why:* pre-promotion bodies legitimately lack synced H1s and are excluded by the sentinel gate exactly as at gate time; restricting statuses (e.g. only awaiting_promotion+completed) would miss drift on `archived`-but-`has_clean_result` bodies and adds a second scoping notion for no noise benefit (7 rows total). *Source:* #1110 check docstring + corpus measurement. *Alternatives:* status allowlist (rejected — extra config, zero measured need).
- **New `--title-sync-sweep` flag on the existing script, not a new script and not the legacy bulk mode.** *What:* a fourth mutually-exclusive CLI mode. *Why:* the Goal names "the clean-results body-discipline auditor" as the home; the legacy no-args mode reads a stale 2026-05-08 GitHub inventory (wrong data source — `tasks/` is canonical workflow state); a separate script would violate the reuse-existing-tools rule. *Source:* read of `main()` + `_run_legacy_bulk_inventory`. *Alternatives:* rehabilitating the bulk mode to read `tasks/` (rejected — larger blast radius, out of the candidate's scope).
- **`tasks_root` parameter for testability.** *What:* the sweep takes an optional root, defaulting to `tasks_dir()`. *Why:* tests exercise the real sweep against a tmp tree without monkeypatching the resolver, and the production default keeps the "never form tasks/ paths relative to cwd" rule (resolver-derived). *Source:* `task_workflow.tasks_dir` (line 716); CLAUDE.md path rule. *Alternatives:* monkeypatching `tasks_dir` in tests (brittler).
- **Also WARN on the `--task`/file path (§4.5).** *What:* one appended WARN line, rc untouched. *Why:* matches the candidate sketch's "wire into the auditor's per-body check list"; makes single-body and corpus surfaces consistent; costs nothing on frontmatter-less drafts (skip). *Source:* candidate diff sketch in the task body. *Alternatives:* sweep-only (defensible, but leaves the auditor's per-body output blind to drift the same script can see corpus-wide).
