# Plan v2 — #1804: verdict-marker `--version` pins collide on long-lived streams — switch the named posting recipes to auto-increment

## Goal / Requirement

Stop code-review (and sibling marker-mode verdict) version collisions on long-lived follow-up tasks. Agent specs pin `task.py post-marker ... --version <revision_round>` (or `--version 1`), which lands BELOW the stream max on tasks with prior rounds (#1092: the round-3 reviewer verdict posted v3 on a stream whose max was 21 → shadowed under the highest-version-per-kind resume convention; the orchestrator had to re-post v22). Fix: omit `--version` so `task_workflow.post_event` auto-derives `max(existing)+1`; the note-head sentinel `<!-- epm:<kind> v<round> -->` remains the round key — it is ALREADY authoritative over the top-level version in the mechanical consumer (`task_workflow.ensemble_verdicts_present`, #1149) and the verdict-disagree observer (`unreconciled_disagreement_rounds`, #1170, sentinel-first + proximity fallback).

## Acceptance criteria

1. No verdict/failure posting recipe in the in-scope files pins `--version` (grep-verifiable: `grep -n -- '--version' <in-scope files>` returns no marker-post hits).
2. Read-back / expected-version lines describe the new semantics — the head sentinel names the ROUND; the posted top-level `version` is auto-derived max+1 and may EXCEED the round on long-lived tasks. No `version == revision_round` assertion survives.
3. Round-keyed head sentinels are UNCHANGED everywhere (`<!-- epm:code-review v<revision_round> -->` etc.) and the touched specs state the sentinel is load-bearing (the round key consumers match on).
4. `tests/test_issue_skill_file_only_verdict_post.py` and `tests/test_ensemble_review_cap.py` stay green, and the no-flags `workflow_lint.py` run shows no NEW failures vs the plan-time baseline (binding gates: Step 10d baseline-subtracted lint gate + Step 9c baseline compare).
5. In-context critic sites (`codex-critic.md`, `codex-efficiency-critic.md`, `codex-methodology-baselines-critic.md`, `codex-statistics-critic.md`) and the deprecated `codex-reviewer.md` stay byte-untouched.
