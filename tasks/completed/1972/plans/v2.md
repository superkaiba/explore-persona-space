## Goal / Requirement

Widen the Step 5a / Step 9c pre-gate spec-freshness sync so long-lived issue
branches stop redding the gates (or tripping Guard 4) on THREE classes of
files the branch never deliberately edited: (1) `.claude/agent-memory/**`
(always-appended memory indexes the lint budget checks scan), (2)
`scripts/select_step9c_tests.py` (the Step 9c selector — budget-coupled to
`workflow_lint.py` and importlib-loaded by its own pin test), and (3)
branch-carried, never-branch-edited sibling-issue `scripts/issue<M>_*.py`
copies (and their covering `tests/test_issue<M>_*.py`) that gated tests
import. Incident basis (2026-07-31, ≥5 extra gate runs across 4+ sessions):
#1776 gate rounds 1-3, #1768 r3/r4/r5 (~40 min extra), #1846 Guard-4
LOST-UPDATE REFUSAL, #1887 lint red from 4 branch-stale agent-memory files.

## Method delta (vs the existing mechanism)

The sync machinery already exists (Step 5a family-atomic block, #1714; the
Step 9c step-1a binding reference, #1742/#1807; the Step 10d post-gate inline
copy). This change ONLY widens its coverage — no new sync sites, no new
markers, no contract change:

- **Arm 1 (agent-memory):** add `.claude/agent-memory` to `SPECS` +
  `SPECS_10D` as a SINGLETON family (the `${FAMILY_OF[$f]:-$f}` default — no
  `FAMILY_OF` entry). Plus a NEW **uncommitted-dirt arm** in pass 1 (both
  copies, uniform over all SPECS members). Correct git semantics (critic
  MF-1): `git checkout <ref> -- <pathspec>` overwrites an UNTRACKED worktree
  file whenever the same path exists at the ref — so the dirt predicate is:
  - any tracked-modified porcelain line (non-`??`) under the member →
    family dirty;
  - any untracked (`??`) porcelain path under the member that EXISTS at
    `origin/main` (`git cat-file -e "origin/main:<path>"`, trailing slash
    stripped for collapsed untracked dirs) → family dirty (the checkout
    WOULD silently replace the uncommitted write — e.g. an agent's fresh
    `feedback_x.md` whose name a concurrent session already landed on main);
  - untracked paths NOT existing at origin/main do NOT block (checkout
    cannot touch a path absent from the ref; new memory files are routinely
    untracked mid-round, and blocking on them would make the agent-memory
    sync permanently inert on active branches).
  Fail-safe direction preserved: dirt → status-quo staleness, never a
  clobber. Committed branch-side memory writes are already protected by the
  existing pass-1 branch-side-edit guard (the Guard-0 commit subject
  `issue-<N>: persist agent-memory writes before Step-10d merge` does NOT
  carry the sync-subject anchor → family dirty → skip). Rejected
  alternatives: (a) a Guard-0-style commit before every sync — same
  fail-safe outcome, but commit churn at every ensemble fan-out; (b)
  marking dirty on ANY porcelain output — makes the agent-memory sync
  near-permanently inert on multi-round branches.
- **Arm 2 (selector + its coupled pins):** add
  `scripts/select_step9c_tests.py`, `tests/test_select_step9c_tests.py`,
  AND `tests/step9c_workflow_invariant_manifest.txt` to `SPECS` +
  `SPECS_10D`, all three with `FAMILY_OF[...]="lint"` (both copies).
  Rationale for the triple: the pin test importlib-loads the selector BY
  PATH (`tests/test_select_step9c_tests.py` L30-34 → the WORKTREE copy),
  and its case 6b pins `WORKFLOW_INVARIANT` set-equal to the manifest file
  (L153-179) — the historically dominant selector edit is an
  invariant-membership change, which updates all THREE together on main, so
  syncing any strict subset manufactures exactly the half-sync red the arm
  exists to prevent (critic MF-3). The selector is stdlib-only
  (argparse/ast/fnmatch/json/re/subprocess/sys/pathlib/typing — verified
  2026-08-03) and the manifest is a data file, so the triple introduces NO
  new src seam beyond the documented `explore_persona_space.workflow`
  residual. Named residual: a main-NEW invariant test file outside the
  synced globs can still red case 5's live-tree check until the branch
  rebases — accepted (same β-class as the boundary paragraph's existing
  seams).
- **Arm 3 (sibling-issue scripts + their tests):** a NEW per-FILE freshness
  pass appended to the Step 5a block (inside the on-main skip guard's
  else-arm, after the family sync + commit), inherited automatically by the
  Step 9c step-1a binding reference. Pathspec covers BOTH
  `:(glob)scripts/issue[0-9]*_*.py` AND `:(glob)tests/test_issue[0-9]*_*.py`
  under identical predicates (critic MF-2): the arm's own sync commit puts
  a previously-invisible sibling script INTO the selector's three-dot diff
  (`select_step9c_tests.py` DEFAULT_BASE = fetched origin/main,
  merge-base...HEAD), which newly maps its covering
  `tests/test_issue<M>_*.py` — syncing the script without its test would
  run a fork-era test against a fresh script, the #1824/#1860 half-sync
  class. Moving the pair together keeps the gate coherent; the sibling
  test's own src-import staleness is the same accepted β-class residual as
  the skill-pin glob's. Per-file grain is load-bearing: a `:(glob)` SPECS
  entry would be ONE singleton family, and every branch edits its OWN
  `scripts/issue<N>_*.py` / `tests/test_issue<N>_*.py`, so the glob-family
  would always be dirty — self-defeating. Per-file dirt rule: ANY porcelain
  output for the file (including `??`) → skip that file (per-file grain
  makes the wider skip free; critic MF-1 fix). The arm is deliberately NOT
  added to the Step 10d post-gate inline copy. Corrected rationale (critic
  concern 1): the post-gate re-sync serves merge landing; sibling-file
  syncing there would only move the tip after certification for zero gate
  benefit (the 10d TG legs run BEFORE the post-gate re-sync). The residual
  window — a sibling file going stale between the last Step 5a/9c sync and
  the 10d TG gated leg — is narrow, and its failure mode is loud (a NEW TG
  red or a CONFLICTING merge surfaced through the existing recovery paths),
  never silent. A second residual: a mid-run main-side edit to an
  already-synced sibling file can conflict at the rebase merge — resolved
  by the existing shape-2 / merge-conflict recovery, also loud.

c. Pass 1 loop: add the uncommitted-dirt arm after the `bs_commits` check

   ```bash
   # Uncommitted-dirt arm (#1972): an uncommitted worktree write must never
   # be clobbered by the checkout below. Tracked-modified dirt always marks
   # the family dirty; an UNTRACKED (??) path marks it dirty ONLY when the
   # same path exists at origin/main — `checkout <ref> -- <pathspec>` DOES
   # overwrite an untracked file whose path exists at the ref, and cannot
   # touch one absent from it (so fresh mid-round agent-memory files with
   # no main-side name collision never block the sync). Fail-safe: dirty ->
   # status-quo staleness, never a clobber.
   DIRT=""
   while IFS= read -r line; do
     [ -z "$line" ] && continue
     p=${line:3}; p=${p%/}
     if [ "${line:0:2}" = "??" ]; then
       git -C "$WT" cat-file -e "origin/main:$p" 2>/dev/null && DIRT=yes
     else
       DIRT=yes
     fi
   done < <(git -C "$WT" status --porcelain -- "$f")
   if [ -n "$DIRT" ]; then
     fam="${FAMILY_OF[$f]:-$f}"
     DIRTY_FAMILIES[$fam]=1
     echo "spec-freshness: $f carries UNCOMMITTED changes the sync could clobber — marking family '$fam' dirty; skipping blind sync for the whole family (#1972)."
   fi
   ```

   (Rename porcelain lines `R  old -> new` need no parsing: any non-`??`
   line marks dirty without reading the path. A collapsed untracked dir
   `?? dir/` cat-files the tree path with the slash stripped — a
   main-existing tree marks dirty, conservative direction.)
d. After the `SAFE_SPECS` sync + conditional commit (still inside the
   else-arm of the on-main skip guard), append the sibling-issue file arm:

   ```bash
   # Sibling-issue file freshness (#1972): per-FILE grain, scripts AND their
   # covering tests as a pair. A gated test may import a sibling issue's
   # scripts/issue<M>_*.py whose worktree copy predates a main-side fix
   # (the #1768 r4/r5 class, ~40 min/incident); the sync commit below also
   # puts the file into the selector's three-dot diff, newly mapping its
   # covering tests/test_issue<M>_*.py — so the pair MUST move together
   # (syncing the script alone runs a fork-era test against a fresh script,
   # the #1824/#1860 half-sync class). Only files with ZERO non-sync
   # branch-side commits sync (a branch's own deliberate edits — incl. its
   # own issue scripts/tests — are never touched); ANY uncommitted dirt on
   # the file skips it (per-file grain makes the wide skip free); files
   # absent on origin/main are skipped (never deleted).
   SIBLING_SYNCED=()
   while IFS= read -r f; do
     [ -z "$f" ] && continue
     case "$f" in scripts/issue<N>_*|tests/test_issue<N>_*) continue ;; esac   # own-issue carve-out (defense-in-depth)
     bs=$(git -C "$WT" log --format='%H %s' "$MB"..HEAD -- "$f" \
       | awk 'index($0, "sync workflow-surface specs from") == 0')
     [ -n "$bs" ] && continue                            # deliberate branch edit — protected
     if git -C "$WT" status --porcelain -- "$f" | grep -q .; then
       echo "spec-freshness: sibling file $f carries UNCOMMITTED changes — skipped (#1972)."
       continue
     fi
     if git -C "$WT" cat-file -e "origin/main:$f" 2>/dev/null; then
       git -C "$WT" checkout origin/main -- "$f" && SIBLING_SYNCED+=("$f")
     else
       echo "spec-freshness: sibling file $f absent on origin/main — skipped (never deleted; #1972)."
     fi
   done < <(git -C "$WT" -c core.quotePath=false diff --name-only origin/main -- ':(glob)scripts/issue[0-9]*_*.py' ':(glob)tests/test_issue[0-9]*_*.py')
   if [ "${#SIBLING_SYNCED[@]}" -gt 0 ] \
      && ! git -C "$WT" diff --quiet HEAD -- "${SIBLING_SYNCED[@]}"; then
     git -C "$WT" commit -m "issue-<N>: sync workflow-surface specs from origin/main (spec-freshness; sibling-issue files)" -- "${SIBLING_SYNCED[@]}"
   fi
   echo "[step5a] sibling-file sync: ${#SIBLING_SYNCED[@]} file(s)"
   ```

   Notes: the commit subject carries the anchor phrase `sync
   workflow-surface specs from`, so (i) the arm's own bs-check excludes its
   prior sync commits on later rounds, (ii) Guard 3's spec-freshness
   exclusion treats the synced files as imported-from-main (non-blocking),

   (content == fetched origin/main). The numeric-anchored globs
   (`issue[0-9]*_*`) keep non-per-issue helpers (e.g. a hypothetical
   `issue_dispatch.py`) out. `git diff --name-only origin/main --
   <pathspecs>` lists tracked files differing from origin/main INCLUDING
   files added on main post-fork (created by the checkout) — desired:
   main's newer tests may import a NEW sibling helper.
