# Plan v1 — #1972 daily-fix: widen pre-gate spec-freshness sync set

## Goal / Requirement

Widen the Step 5a / Step 9c pre-gate spec-freshness sync so long-lived issue
branches stop redding the gates (or tripping Guard 4) on THREE classes of
files the branch never deliberately edited: (1) `.claude/agent-memory/**`
(always-appended memory indexes the lint budget checks scan), (2)
`scripts/select_step9c_tests.py` (the Step 9c selector — budget-coupled to
`workflow_lint.py` and importlib-loaded by its own pin test), and (3)
branch-carried, never-branch-edited sibling-issue `scripts/issue<M>_*.py`
copies that gated tests import. Incident basis (2026-07-31, ≥5 extra gate
runs across 4+ sessions): #1776 gate rounds 1-3, #1768 r3/r4/r5 (~40 min
extra), #1846 Guard-4 LOST-UPDATE REFUSAL, #1887 lint red from 4 branch-stale
agent-memory files.

## Method delta (vs the existing mechanism)

The sync machinery already exists (Step 5a family-atomic block, #1714; the
Step 9c step-1a binding reference, #1742/#1807; the Step 10d post-gate inline
copy). This change ONLY widens its coverage — no new sync sites, no new
markers, no contract change:

- **Arm 1 (agent-memory):** add `.claude/agent-memory` to `SPECS` +
  `SPECS_10D` as a SINGLETON family (the `${FAMILY_OF[$f]:-$f}` default — no
  `FAMILY_OF` entry). Plus a NEW **uncommitted-dirt arm** in pass 1 (both
  copies, uniform over all SPECS members): a member with tracked-modified
  uncommitted changes (`git status --porcelain -- "$f" | grep -v '^??' |
  grep -q .`) marks its family dirty → sync skipped for that family. This is
  REQUIRED for arm 1 to be safe: review agents append to
  `.claude/agent-memory/**` in the worktree between fan-outs, and the next
  fan-out's `git checkout origin/main -- $SAFE_SPECS` would silently clobber
  those uncommitted tracked-file edits (the Guard-0 commit only runs at Step
  10d). Untracked (`^??`) files are excluded from the dirt predicate —
  `checkout <ref> -- <pathspec>` cannot clobber untracked files, and
  new memory files are routinely untracked mid-round; excluding them keeps
  the sync effective in the common case. Fail-safe direction preserved: dirt
  → status-quo staleness, never a clobber. Committed branch-side memory
  writes are already protected by the existing pass-1 branch-side-edit guard
  (the Guard-0 commit subject `issue-<N>: persist agent-memory writes before
  Step-10d merge` does NOT carry the sync-subject anchor → family dirty →
  skip). Rejected alternative: running a Guard-0-style commit before every
  sync — same fail-safe outcome but adds commit churn at every ensemble
  fan-out.
- **Arm 2 (selector):** add `scripts/select_step9c_tests.py` AND
  `tests/test_select_step9c_tests.py` to `SPECS` + `SPECS_10D`, both with
  `FAMILY_OF[...]="lint"` (both copies). Rationale for the pair: the pin
  test importlib-loads the selector BY PATH
  (`tests/test_select_step9c_tests.py` L30-34 → the WORKTREE copy), so
  syncing one without the other recreates the exact half-sync skew class
  (#1824/#1860) this family machinery exists to prevent. The selector is
  stdlib-only (argparse/ast/fnmatch/json/re/subprocess/sys/pathlib/typing —
  verified 2026-08-03), so syncing it introduces NO new src seam beyond the
  documented `explore_persona_space.workflow` residual.
- **Arm 3 (sibling-issue scripts):** a NEW per-FILE freshness pass appended
  to the Step 5a block (inside the on-main skip guard's else-arm, after the
  family sync + commit), inherited automatically by the Step 9c step-1a
  binding reference. Per-file grain is load-bearing: a `:(glob)` SPECS entry
  would be ONE singleton family, and every branch edits its OWN
  `scripts/issue<N>_*.py`, so the whole glob-family would always be dirty —
  self-defeating. The arm is deliberately NOT added to the Step 10d
  post-gate inline copy: sibling-script staleness affects WORKTREE test
  execution only (the 9c gate + the 10d TG gated leg), never the landing
  tree (a never-branch-edited file is absent from the own-diff by
  construction), and the post-gate re-sync serves merge landing. Accepted
  residual: the Step 10d TG gated leg can still see a sibling script that
  went stale AFTER the last Step 5a/9c sync fired (narrow window; the TG
  baseline subtraction absorbs the both-legs-red case).

c. Pass 1 loop: add the uncommitted-dirt arm after the `bs_commits` check:

   ```bash
   # Uncommitted-dirt arm (#1972): a tracked-modified uncommitted member
   # must never be clobbered by the checkout below — mark its family dirty
   # (fail-safe: status-quo staleness). Untracked (??) files are excluded:
   # checkout <ref> -- <pathspec> cannot touch them, and mid-round
   # agent-memory writes are routinely untracked new files.
   if git -C "$WT" status --porcelain -- "$f" | grep -v '^??' | grep -q .; then
     fam="${FAMILY_OF[$f]:-$f}"
     DIRTY_FAMILIES[$fam]=1
     echo "spec-freshness: $f carries UNCOMMITTED tracked changes — marking family '$fam' dirty; skipping blind sync for the whole family (#1972)."
   fi
   ```

d. After the `SAFE_SPECS` sync + conditional commit (still inside the
   else-arm of the on-main skip guard), append the sibling-issue script
   arm:

   ```bash
   # Sibling-issue script freshness (#1972): per-FILE grain. A gated test
   # may import a sibling issue's scripts/issue<M>_*.py whose worktree copy
   # predates a main-side fix (the #1768 r4/r5 class, ~40 min/incident).
   # Only files with ZERO non-sync branch-side commits sync (a branch's own
   # deliberate edits — incl. its own issue scripts — are never touched);
   # files absent on origin/main are skipped (never deleted).
   SIBLING_SYNCED=()
   while IFS= read -r f; do
     [ -z "$f" ] && continue
     case "$f" in scripts/issue<N>_*) continue ;; esac   # own-issue carve-out (defense-in-depth)
     bs=$(git -C "$WT" log --format='%H %s' "$MB"..HEAD -- "$f" \
       | awk 'index($0, "sync workflow-surface specs from") == 0')
     [ -n "$bs" ] && continue                            # deliberate branch edit — protected
     if git -C "$WT" status --porcelain -- "$f" | grep -v '^??' | grep -q .; then
       echo "spec-freshness: sibling script $f carries UNCOMMITTED tracked changes — skipped (#1972)."
       continue
     fi
     if git -C "$WT" cat-file -e "origin/main:$f" 2>/dev/null; then
       git -C "$WT" checkout origin/main -- "$f" && SIBLING_SYNCED+=("$f")
     else
       echo "spec-freshness: sibling script $f absent on origin/main — skipped (never deleted; #1972)."
     fi
   done < <(git -C "$WT" -c core.quotePath=false diff --name-only origin/main -- ':(glob)scripts/issue[0-9]*_*.py')
   if [ "${#SIBLING_SYNCED[@]}" -gt 0 ] \
      && ! git -C "$WT" diff --quiet HEAD -- "${SIBLING_SYNCED[@]}"; then
     git -C "$WT" commit -m "issue-<N>: sync workflow-surface specs from origin/main (spec-freshness; sibling-issue scripts)" -- "${SIBLING_SYNCED[@]}"
   fi
   echo "[step5a] sibling-script sync: ${#SIBLING_SYNCED[@]} file(s)"
   ```

   Notes: the commit subject carries the anchor phrase `sync
   workflow-surface specs from`, so (i) the arm's own bs-check excludes its
   prior sync commits on later rounds, (ii) Guard 3's spec-freshness
   exclusion treats the synced files as imported-from-main (non-blocking),
   and (iii) the Step 10d verdict re-bind's A/M byte-identity probe passes
   (content == fetched origin/main). The `:(glob)scripts/issue[0-9]*_*.py`
   pathspec is numeric-anchored so non-per-issue scripts (e.g. a
   hypothetical `issue_dispatch.py`) never match. `git diff --name-only
   origin/main -- <pathspec>` lists tracked files differing from origin/main
   INCLUDING files added on main post-fork (created by the checkout) —
   desired: main's newer tests may import a NEW sibling helper.
e. Boundary paragraph ("The sync scope is specs + the spec-coupled
