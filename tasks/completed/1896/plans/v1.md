# Plan v1 — task #1896: add `capture-7b` to the fellows/SLURM lane intent tables

## Plan Summary

Add the `capture-7b` GPU intent to the two SLURM intent-default tables in
`src/explore_persona_space/backends/slurm.py` (`_DEFAULT_GPUS_FOR_INTENT: 1`,
`_DEFAULT_TIME_BUDGETS_HOURS: 4.0`) so `capture-7b` dispatches on the auto lane
stop `ValueError`-ing off the free fellows/SLURM lanes and burning paid GCP.
Pin the new rows with tests. NOT architectural — two dict rows + tests; no enum,
marker-schema, or CLI-contract change (`architectural: false`).

## Requirement + acceptance criteria

**Requirement (task Goal):** make `capture-7b` dispatches eligible for the free
fellows/SLURM lane instead of silently skipping it.

Acceptance criteria:

1. `default_gpus_for_intent(RunSpec(intent="capture-7b", ...))` returns `1`
   (no ValueError).
2. `time_budget_hours(RunSpec(intent="capture-7b", ...))` returns `4.0`
   (no ValueError).
3. A `capture-7b` spec carrying `workload_cmd` renders end-to-end through
   `render_sbatch` (the production dispatch shape — `stages_for_spec` bypasses
   the intent→stage table for `workload_cmd` specs, slurm.py L1326), with
   `--gpus-per-node` count 1 and `--time=04:00:00`.
4. Hydra-path `capture-7b` (no `workload_cmd`) still raises at
   `stages_for_spec` ("unsupported intent") — deliberate: there is no canonical
   capture Hydra script; only the two tables are the crash sites the marker
   evidence names. Pinned by test.
5. Non-capture-intent sbatch renders stay byte-identical (existing snapshot
   tests in `tests/test_slurm_backend_render.py` remain green — dict-row
   additions cannot alter another intent's render).
6. CPU-only intents stay excluded — the #1464 absence-pin test
   (`test_cpu_intents_deliberately_absent_from_slurm_intent_tables`) is
   untouched and stays green.

## Method delta (vs prior related work)

- #940 solved the SAME gap class for the RunPod terminal rung via the
  `RUNPOD_INTENT_FOR_GCP_INTENT` translation map (router.py:427:
  `"capture-7b": "eval"`). This plan takes the task body's PRIMARY sketch
  (direct table rows) instead of the ALT (#940-style SLURM-side translation):
  the SLURM tables already carry an in-table alias precedent (`"lora"` rows,

  `job_name` with a wider blast radius on the byte-identity contract (#1609
  snapshot tests). The translation design's uniform coverage of OTHER GCP-only
  intents (`lora-7b-h100`, `sweep-8g-*`, `eval-h100`) is out of this
  fingerprint's scope — surfaced separately as a parked workflow-fix candidate
  (recursion guard: this session logs, never auto-files).
- #1464/#747 deliberately excluded CPU-only intents from these tables; this
  change touches GPU-intent rows only and leaves that exclusion + its pin test
  byte-untouched.
