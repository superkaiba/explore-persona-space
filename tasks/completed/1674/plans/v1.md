LANDED_FIX_MIN_SHARED_TOKENS = 3      # calibrated on the incident pairs (§11 D1)
LANDED_FIX_GIT_TIMEOUT_S = 10         # same class as SHA_REV_PARSE_TIMEOUT_S (#1467)

### 4.2 New helpers (place next to the route-3 dedup family, after `_route3_already_tracked`)

```python
def _landed_fix_item_tokens(item: dict) -> set[str]:
    """Informative tokens of the item's title+bug+change (#1674).

    Title prefixes stripped (WF_FIX_TITLE_PREFIXES members + ROUTE3_TITLE_PREFIX);
    _route3_informative exclusions applied (generic workflow vocabulary + dates
    never count toward overlap — the #1687 calibration transfers, §11 D4).
    """
    t = item["title"] or ""
    for pfx in (*WF_FIX_TITLE_PREFIXES, ROUTE3_TITLE_PREFIX):
        t = t.removeprefix(pfx)
    return _route3_informative(
        informative_title_tokens(t)
        | informative_title_tokens(item.get("bug") or "")
        | informative_title_tokens(item.get("change") or "")
    )


def find_landed_fix_suspects(item: dict, root: Path) -> list[dict]:
    """Recent commits on the item's OWN target path(s) whose SUBJECT shares
    >= LANDED_FIX_MIN_SHARED_TOKENS informative tokens with the item text (#1674).

    Subject-only by design — subject+body matching false-positives on hot files
    (plan #1674 §11 D3). Path-scoped: `git log -- <paths>` with the item's own
    _target_tokens (never a repo-wide subject scan). Returns up to
    LANDED_FIX_MAX_SUSPECTS dicts {"sha", "subject", "shared"} in git log order
    (most recent first). Raises on git failure — _landed_fix_or_none fail-opens.
    """
    paths = sorted(_target_tokens(item["target"]))
    if not paths:
        return []
    item_toks = _landed_fix_item_tokens(item)
    if not item_toks:
        return []
    proc = subprocess.run(
        ["git", "-C", str(root), "log", f"--since={LANDED_FIX_WINDOW}",
         "--format=%h%x09%s", "--", *paths],
        capture_output=True, text=True, check=True, timeout=LANDED_FIX_GIT_TIMEOUT_S,
    )
    suspects: list[dict] = []
    for line in proc.stdout.splitlines():
        sha, _, subject = line.partition("\t")
        if not subject:
            continue
        shared = item_toks & _route3_informative(informative_title_tokens(subject))
        if len(shared) >= LANDED_FIX_MIN_SHARED_TOKENS:
            suspects.append({"sha": sha, "subject": subject, "shared": sorted(shared)})
            if len(suspects) >= LANDED_FIX_MAX_SUSPECTS:
                break
    return suspects


def _landed_fix_or_none(item: dict, root: Path) -> list[dict]:
    """Fail-open wrapper (#1674): a git/IO error WARNs loudly and files as today.

    Enumerated classes only (OSError, CalledProcessError, TimeoutExpired,
    UnicodeDecodeError) — deliberately NARROWER than _route3_dup_or_none's broad
    catch: the probe's error surface is one git subprocess (the fail-open mandate
    covers "git itself errors"); a driver bug still fails loud per fail-fast.
    """
    try:
        return find_landed_fix_suspects(item, root)
    except (OSError, subprocess.CalledProcessError, subprocess.TimeoutExpired,
            UnicodeDecodeError) as e:
        print(
            f"WARNING {item['slug']}: landed-fix probe skipped"
            f" ({e.__class__.__name__}: {e}) — fail-open, filing proceeds; the"
            " compose-time git-log duty still applies (#1674)",
            file=sys.stderr,
        )
        return []


def _landed_fix_suspect_outcome(
    item: dict, root: Path, *, dirpath: Path, fp: str, dry_run: bool
) -> str | None:
    """Landed-fix probe outcome for process_item, or None (mirror of
    _route3_already_tracked's contract, #1674). Routes 2 AND 3 (§11 D5).

    No-suspect scans return None (caller proceeds to file). On a hit the
    LANDED-FIX-SUSPECT line prints either way; the real path appends the
    terminal `landed-fix-suspect` ledger row and returns 'landed-fix-suspect';
    dry-run stays read-only by construction (no ledger write) and returns 'skip'.
    """
    suspects = _landed_fix_or_none(item, root)
    if not suspects:
        return None
    slug = item["slug"]
    if not dry_run:
        append_row(dirpath, {
            "slug": slug,
            "outcome": "landed-fix-suspect",
            "suspects": suspects,
            "threshold": LANDED_FIX_MIN_SHARED_TOKENS,
            "window": LANDED_FIX_WINDOW,
            "paths": sorted(_target_tokens(item["target"])),
            "fp": fp,
            "route": item["route"],
        })
    top = suspects[0]
    more = f"; +{len(suspects) - 1} more" if len(suspects) > 1 else ""
    print(
        f"LANDED-FIX-SUSPECT {slug} -> {top['sha']} \"{top['subject']}\""
        f" (shared: {','.join(top['shared'])}{more}) — NOT filing; eyeball the"
        " commit(s), re-run with --retry-suspects to file anyway (#1674)"
    )
    return "skip" if dry_run else "landed-fix-suspect"
```

| Threshold drifts wrong as commit-subject conventions change | Medium-term | Constants are module-level + sourced (§11); replay tests 8/9 pin the current calibration and fail loudly if the tokenizer/exclusion stack changes semantics |

**Kill criteria (what would make this fix wrong):** if the probe's false-positive rate on legitimate filings were non-trivial in operation (≥1 wrongly-suppressed real fix that the eyeball + `--retry-suspects` path does not cheaply recover), the mechanical-block design is wrong for this channel — revert to advisory-only (print the suspect line, still file) by flipping `_landed_fix_suspect_outcome` to return None after printing; the fail-open + eyeball-not-hard-block design is the built-in mitigation that makes this a cheap, non-destructive rollback. ## 11. Decision Rationale

- **D1 — Overlap threshold `LANDED_FIX_MIN_SHARED_TOKENS = 3`.** What: minimum shared informative tokens between item text and a commit subject. Why: plan-time measured lattice on the real artifacts (2026-07-25, live tokenizer): true-dup #1652 vs `ce11dff560` = 3 ({pods, runpod, scope}); false-positive probes — this task's own text vs the four most recent driver commits — max 2 ({driver, filing} vs the #1678 commit), others ≤1. Threshold 3 fires on the motivating incident and passes every measured legitimate pair; threshold 2 would false-suppress this very task. Source: #1483 (`ROUTE3_MIN_SHARED_TOKENS = 3`, same tokenizer + exclusion family, same threshold-vs-non-dup-ceiling margin shape) + #1687 (recalibration precedent + generic-token exclusions). The #1446 ≥2 precedent was considered and REJECTED for this site: it matches title-vs-title (small sets both sides); here the item side is title+bug+change (a large set), which raises chance overlap — hence 3, not 2. Alternatives: 2 (measured false positive), 4 (misses the motivating incident).
- **D2 — Window `--since='7 days ago'`.** What: git-log lookback. Why: matches the compose-time duty's own window (`workflow-fix-on-bug.md` clause (a'): `git log --oneline --since='7 days ago' -- <target_file>`) and the #1446 advisory's ~7-day closed-sibling window; all three incidents are in-window (#1652 filed 1.5 d after `ce11dff560`; #1386 ~9 h after #1360; #1330 days after #1309). Source: `.claude/rules/workflow-fix-on-bug.md` § Dedup / clause (a'); #1446. Alternatives: 14 d (more FP surface on hot files, no incident needs it), 3 d (would still catch all three but adds no safety and diverges from the documented duty window).
- **D3 — Subject-only matching (`--format=%h%x09%s`), NOT subject+body.** What: only the commit subject enters the overlap. Why: measured 2026-07-25 — subject+body catches #1386/#1360 (n=4: {queue, reached, retry, size}) but false-suppresses THIS task against three recent driver commits (n=9 vs #1678's commit, n=3 vs #1580's, n=3 vs #1529's): rich commit bodies in this repo make body-matching threshold-untunable on hot files. Subject-only trades the #1386-shaped catch for zero measured false positives. Source: plan-time measurement (§12 A9); the miss is documented in §2/§8 and in the SKILL.md note. Alternatives: subject+body at a higher threshold (n=9 FP makes no fixed threshold safe), per-commit adaptive thresholds (unjustifiable complexity for a backstop).
- **D4 — Reuse `informative_title_tokens` + `_route3_informative` exclusions.** What: the exact #1483 tokenizer with the #1687 generic-vocabulary + date exclusions. Why: constraint 1 (never a new tokenizer); the exclusions measurably help here too (they remove `route-3`/`daily`/`session`-class tokens that would otherwise inflate hot-file overlap; the D1 lattice was measured WITH them). Source: #1483, #1687 (`task_workflow.informative_title_tokens`; `_route3_informative`). Alternative rejected: a probe-specific extra exclusion set (e.g. {driver, filing}) — unnecessary at threshold 3 (measured FP ceiling already 2) and a second calibration surface to maintain.
- **D5 — Guard routes 2 AND 3.** Why: the probe's evidence (a landed commit on the item's own target file with ≥3 shared informative subject tokens) is route-agnostic; a route-3 held task for an already-landed fix creates the exact PM re-surface churn #1483 exists to prevent; and the outcome is never a silent drop (row + stdout + `--retry-suspects`), so the route-3 "a held item is never lost" invariant holds. All three incidents are route-2, so route 2 is the load-bearing guard; route 3 rides along at zero extra mechanism (the helper is route-blind). Source: #1483's route-3 fail-open/never-lost contract; incident set (task body). Alternative rejected: route-2-only — saves nothing (same code path) and leaves the route-3 channel filing held tasks for fixed problems.
- **D6 — Fail-open ONLY on enumerated git/IO errors.** What: `(OSError, CalledProcessError, TimeoutExpired, UnicodeDecodeError)` → WARN + file; anything else raises. Why: the task constraint ("fail-open toward filing ONLY when git itself errors") + the project fail-fast rule — a broad `except Exception` would hide driver bugs; the probe's error surface is one subprocess. Source: `_check_body_shas`/`_sha_resolves` (#1467 — same classes + 10 s timeout); contrast deliberately drawn with `_route3_dup_or_none`'s broad catch (whose wider YAML/token error space justified it there).
- **D7 — New outcome is ERROR-style two-state (`--retry-suspects`), not a `TERMINAL_OUTCOMES` member.** What: `_slug_state` returns `retry-suspect` under the flag, else terminal; the probe is skipped on the retry pass. Why: the kill-criteria mitigation requires a cheap driver-path override (hand-filing via `file_infra_task.py` bypasses provenance injection, title guard, and the ledger); mirroring `--retry-errors` reuses an existing, tested state-machine shape verbatim. Source: the existing `--retry-errors` / `_slug_state` design (#1061 driver; read at plan time). Alternative rejected: plain terminal + hand-file override (loses the driver's injectors and ledger guarantees).
- **D8 — Probe position: after both dedup checks, before the `attempting` row.** Why: cheapest/most-certain checks first; a suspect must never leave an `attempting` row (it never reached the filer — keeps recovery semantics untouched); mirrors the #1483 ordering comment at line ~1237. Source: `process_item` structure (read at plan time).
- **D9 — Suspect list capped at 5, `%h` abbreviated shas.** Why: ledger rows are single JSON lines (row-size hygiene, the `tail[-300:]` convention); `%h` matches the #1467 sha-verify vocabulary and stays `git rev-parse`-able for the eyeball. Source: module conventions (ledger row shapes, `SHA_ADVISORY_TMPL`).
