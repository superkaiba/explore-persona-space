## 1. Requirement + acceptance criteria

**Requirement (from the task Goal):** stop the bare-`python`-pipe PreToolUse
guard (today an INLINE command in `.claude/settings.json`, the last entry of
the `matcher: "Bash"` hook group) from false-blocking pipes that occur inside
quoted REMOTE command strings (`ssh … "… | python3 -c …"`,
`gcloud compute ssh … --command='… | python3 -c …'`). The guard's premise —
no `python` on the local VM PATH — does not apply to remote argv.

**Acceptance criteria** (each becomes a pytest case or a mechanical check):

1. The incident shape is ALLOWED: `ssh pod-X '… ps aux | python3 -c "…"'`
   (single-quoted remote string) and the substitution-free double-quoted
   variant both pass the guard.
2. `gcloud compute ssh vm --command='… | python3 -c …'` is ALLOWED.
3. Genuinely LOCAL pipes are STILL BLOCKED (behavior parity, body
   constraint): `cat x | python3 -c '…'`, `echo '{}' | python -c "…"`,
   `foo | python3.11 -m json.tool`, and the local-consumer-after-ssh shape
   `ssh host 'cat log' | python3 -c '…'` (the pipe is local — bash splits at
   the unquoted `|`).
4. A double-quoted span carrying live substitution that itself pipes into
   python — `echo "$(cat x | python3 -c '…')"` — is STILL BLOCKED (the
   `$(…)` payload executes locally).
5. `… | uv run python -c '…'` never matches (parity — the prescribed form).
6. `jq . .claude/settings.json` stays valid; `bash -n` clean on the new hook
   file; executable bit set.
7. The hook is REGISTERED in `.claude/settings.json` (matcher-Bash group) by
   absolute path, and the old inline python-pipe command is REMOVED (no
   inline `python3?`-pipe grep remains in any settings.json hook command).
8. `workflow_lint.py --check-asks` passes; the no-flags bundle introduces no
   NEW failure attributable to the payload.
9. Wrapper-quoted LOCAL pipes — `bash -c '… | python3 -c …'` (and `sh -c` /
   `eval` / `xargs … sh -c` payload forms) — are ALLOWED post-fix, pinned by
   a test as the DELIBERATE interpreter-payload fail-open (see §5): the
   quoted payload is string data to the guard but executes downstream. The
   pin asserts exit 0 AND names the disposition in its docstring, so a
   future change of heart is a conscious test edit, never silent drift.
   (Critic round-1 Must-Fix, resolved by the document-and-pin disposition.)

Fail-loud pin: tests/test_guard_python_pipe.py — the §1.9 disposition pin asserts exit 0 on the wrapper-quoted shape so any silent regression of the ALLOW disposition fails this committed test.

## 2. Method delta (what differs from prior related work)

The guard today greps the WHOLE Bash argv, so quoted string arguments —
text that never executes locally — match as if they were local pipes. The
sibling `guard_piped_git_push.sh` solved the same class in #1675 with a
quoted-span strip whose ERE is proven and test-pinned (its A25–A29/A33 +
B24–B26 cases). Delta vs the task body's cheaper "starts-with-ssh → skip"
option: the prefix-skip form creates a false NEGATIVE for the common
`ssh host 'cat log' | python3 -c '…'` composition (a genuinely local
consumer pipe after an ssh stage, which dies exit-127 locally and SHOULD
block), and it fixes only ssh-shaped false positives; the quote-strip form
fixes the whole quoted-mention class (ssh remote strings, `--command=`
strings, commit-message/marker-note mentions) with zero ssh-specific
parsing. Decision: **extract to `.claude/hooks/guard_python_pipe.sh`
(sibling shape, testable) + port the #1675 strip verbatim** — the body's
"consider extracting … matching the sibling guards' shape" option.

## 5. Known residuals (documented, test-pinned, accepted)

- A `$`-bearing double-quoted remote string
  (`ssh host "… $V … | python3 -c …"`) is PRESERVED as live substitution
  and still blocks — remediation: single-quote the remote string (standard
  ssh hygiene; also what prevents unintended local expansion). Mirrors the
  #1675 documented residual. Likely the most-hit residual in practice; the
  BLOCK message's appended remediation sentence is the mitigation.
- Interpreter/remote-executor payloads WITHOUT live substitution — a quoted
  payload handed to a LOCAL wrapper (`bash -c '…'`, substitution-free
  `sh -c "…"`, `eval '…'`, `xargs … sh -c`) executes downstream but reads
  as string data post-strip, so a wrapper-quoted local python pipe that
  today BLOCKS will be ALLOWED post-fix. DELIBERATE, sibling-precedent
  fail-open class (guard_piped_git_push.sh header, fail-open class (1):
  cooperative-agent threat model, zero recorded incidents of this shape);
  harm bound = one exit-127 turn — the ergonomic cost this guard reduces,
  not a safety boundary. The `check_pipe_python` lint + the CLAUDE.md prose
  rule remain defense in depth. Test-pinned (§1.9). A wrapper-preserve ERE
  branch was considered and REJECTED: it adds the #796 class of risk
  (partial shell parsing in ERE backfires) and re-introduces false
  positives for `ssh host bash -c '…'` remote shapes.
- Unbalanced quotes → span unmatched → text scanned raw → fails toward
  block (today's status quo, never a new false negative).
- ANSI-C `$'…'` with interior `\'` is unmodeled (sibling parity; rare).
- The lint twin `check_pipe_python` (workflow_lint.py, #753) still scans
  committed `scripts/*.sh` with NO quote awareness — a committed script
  carrying an ssh-quoted python pipe would still lint-flag. OUT OF SCOPE
  here (task body scopes to the settings.json guard); zero current
  offenders on main, so no gate impact.
