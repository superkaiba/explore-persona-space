Extend the preceding comment (L517-522) with the new-verb boundary analysis:

- `\brebase\b` DOES match inside `--rebase=merges`, `pull.rebase=merges`, `rebase.autoStash=true` (`-`, `.`, `=` are non-word chars, so both boundaries fire). Harmless by the same argument as the existing `merge-base` note: the tight detector requires subcommand position + a `( +|$)` verb terminator, so none of these can reach a block (verified per-shape in §5). The behavior shift is only *which exit path* allows them (classifier instead of pre-filter skip).
- `\bcherry-pick\b` does NOT match the ubiquitous prose token `cherry-picked` (no trailing word boundary — `k` is followed by `e`), so clean-result commit messages / marker notes carrying "cherry-picked for illustration" never even pass the pre-filter. It DOES match `git log --cherry-pick` (boundary fires between `-` and `c`), which is harmless at the tight detector (`log` breaks the subcommand chain). `git log --cherry` and the plumbing command `git cherry` don't match the alternation at all (the literal requires the full `cherry-pick`).

### E3 — two new tight detector blocks in `classify_clause`, inserted after L710 (before the `# ---- end #897 detectors` banner at L711)

Two per-verb blocks, byte-mirroring the merge fence shape at L706-710 (rationale for two blocks vs. one combined alternation: §11, item 4 — a combined allow-arm `\b(rebase|cherry-pick) +--(abort|quit)\b` opens a cross-verb quoted-arg spoof the per-verb form kills):

```bash
  # ---- #1193 rebase-family fence (sibling of the #1128 merge fence) -------
  # `git rebase <ref>` / `git cherry-pick <ref>` on the shared root: a
  # conflicting run strands conflict state in the shared tree exactly like
  # the #1090 root merge, and a clean run rewrites/lands commits on root
  # main outside the sanctioned landing paths (gh pr merge --rebase /
  # scratch worktree / sync_repo_root.py — a bare `git rebase` with a
  # configured upstream genuinely RUNS, so end-of-clause blocks too).
  # TIGHT anchor: verb followed by whitespace/end-of-clause — NOT `\b`,
  # which fires before `.`/`=` and would trip `git -c rebase.autoStash=true
  # pull` at flag-value position. Allow-arm mirrors #1128: --abort/--quit
  # IMMEDIATELY after the verb (sanctioned recovery; fail-soft). BLOCKED
  # fail-closed: --continue and --skip (both COMPLETE the in-progress
  # operation on the root tree — the M5 decision, mirrored; recovery is
  # abort). Note `git pull --rebase[=merges]` never reaches this anchor:
  # its subcommand is `pull` (the sanctioned root-sync form stays open).
  if echo "$c" | grep -qE '\bgit +(-[^ ]+( +[^ ]+)?( +|$))*rebase( +|$)'; then
    if ! echo "$c" | grep -qE '\brebase +--(abort|quit)\b'; then
      blocked="git rebase (history rewrite on the shared root)"
    fi
  fi
  if echo "$c" | grep -qE '\bgit +(-[^ ]+( +[^ ]+)?( +|$))*cherry-pick( +|$)'; then
    if ! echo "$c" | grep -qE '\bcherry-pick +--(abort|quit)\b'; then
      blocked="git cherry-pick (commit replay onto the shared root)"
    fi
  fi
  # ---- end #1193 rebase-family fence ---------------------------------------
```

**Allow-set decision (justified):** `--abort` and `--quit` both exist for both verbs (verified live, git 2.34.1: `git rebase -h` lists `--continue | --abort | --skip | --edit-todo` + `--quit`; `git cherry-pick -h` lists `--abort`, `--quit`, `--continue`, `--skip`). Allow `--abort`/`--quit` only:

- `cherry-pick --abort/--quit`: load-bearing exactly like merge — a conflicted cherry-pick keeps HEAD on `main`, so the guard WOULD fire on the recovery command without the allow-arm.
- `rebase --abort/--quit`: mostly belt-and-suspenders — a conflicted rebase detaches HEAD, so the on-main gate (L1039-1040) already exits 0 mid-recovery; on-main, both forms are harmless usage errors ("no rebase in progress"). Allowing keeps the two blocks byte-parallel and costs nothing.
- `--continue` and `--skip` BLOCKED fail-closed: both complete/resume the in-progress operation on the root tree — the exact mirror of the merge fence's deliberate M5 `--continue` block (L699-702). `--skip` has no merge analogue but is continue-class (verified: "skip current patch and continue"). `--edit-todo` also blocks (no allow match) — only reachable mid-rebase where the on-main gate already exits 0, so inert.

## 11. Decision Rationale

1. **Verb set = `rebase` + `cherry-pick` only.** What: the two verbs the Goal names. Why: they are exactly what item (xvi) deferred; `git revert`/`git am` are the same family but out of the stated Goal — named as register residual + prose follow-up, not scope creep. Source: task #1193 Goal + `guard_repo_root_branch.sh:302-309`.
2. **Allow set = `--abort` + `--quit` per verb; `--continue` + `--skip` blocked.** What: anchored immediate-flag allow. Why: `--abort`/`--quit` are pure recovery (verified in `git rebase -h` / `git cherry-pick -h`, git 2.34.1); `--continue`/`--skip` COMPLETE/resume the operation on the root tree — the merge fence deliberately blocks `--continue` (M5, L699-702) and this mirrors that decision; `--skip` is continue-class ("skip current patch and continue"). Source: #1128 fence L693-702 + live `git -h` output.
3. **Anchor shape = `\bgit +(-[^ ]+( +[^ ]+)?( +|$))*<verb>( +|$)`, verb terminator `( +|$)` not `\b`.** What: the #1128 tight subcommand anchor, verbatim with the verb swapped. Why: `\b` after `rebase` fires before `.`/`=`, so `git -c rebase.autoStash=true pull` would false-block at flag-value position (walked through in §4/E1; RA10 pins it); `( +|$)` also keeps `merge-base`-style parity. The flag-skipping group is inherited unchanged — its `-[^ ]+`-can-match-`--` backtracking path was checked and cannot bridge `git --no-pager log --cherry-pick` into a match (the `( +|$)` after the flag group fails without a space). Source: #1128 fence L690-692 + regex walk-through this plan.
4. **Two per-verb detector blocks, not one combined `(rebase|cherry-pick)` block.** What: two sibling `if` blocks each with its own verb-anchored allow. Why: a combined allow-arm `\b(rebase|cherry-pick) +--(abort|quit)\b` opens a CROSS-VERB spoof — a quoted argument containing the *other* verb + `--abort` would satisfy the combined allow while the detector fired on the real verb; per-verb allows kill that class (each allow only matches its own verb immediately followed by the recovery flag). Also byte-parallel to the merge fence, minimizing review surface. Source: #1128 single-verb precedent + spoof analysis this plan.
5. **Both loose alternation sites updated (L523 + L907).** What: identical edit at both. Why: L523 gates the whole command, L907 gates per-clause; missing either is fail-open for the new verbs (whole-command or compound-clause respectively). The comment at L905-906 documents the two as a synced pair. Source: `guard_repo_root_branch.sh:517-523,905-907`.
