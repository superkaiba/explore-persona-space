#### 4.2 Sites 2+3 — `add_subparsers` (:188-195) and `set_defaults` (:197): resolve-or-degrade (hybrid)

There is no permissive material at these sites — `add_subparsers` has no option strings and `set_defaults`' names come solely from kwarg keys — so "route to the permissive path" cannot mechanically apply. Chosen design: **hybrid (c)** — statically resolve the splat mapping when it is cleanly knowable; otherwise contribute nothing AND record the splat for a diagnostic in the `SystemExit` message.

**New module-level helper** (stdlib-only, full docstring per docstring-on-edit):

```python
_SPLAT_REGISTRATION_METHODS = frozenset({"add_argument", "set_defaults", "add_subparsers"})

def _resolve_splat_mapping(value: ast.expr, tree: ast.AST) -> dict[str, ast.expr] | None:
    """Statically resolve a ``**`` splat's mapping to {str key: value node}, or None.

    Resolves exactly two shapes: (a) an inline ``ast.Dict`` literal at the
    call site; (b) an ``ast.Name`` under the EXCLUSIVE-USE rule — its sole
    binding anywhere in the module is one module-level ``Assign`` (single
    Name target) / ``AnnAssign`` to an ``ast.Dict`` literal, AND every
    Load-context occurrence of the name anywhere in the module appears
    ONLY as the value of a ``**`` splat keyword (``ast.keyword(arg=None)``)
    on a handled registration call (``_SPLAT_REGISTRATION_METHODS``). Any
    other occurrence — an alias RHS (``B = DEFAULTS``), a call argument
    (``_finalize(DEFAULTS)``), a subscript or method receiver
    (``DEFAULTS[k]`` / ``DEFAULTS.pop(...)``), a ``del`` of the bare name —
    abstains. Every key must be a constant string (a nested ``**`` inside
    the literal appears as a None key -> abstain). Anything else returns
    None — never a guess (the same abstain discipline as #2176's
    registry-member reader in task_workflow.py).
    """
```

**Exclusive-use rule for shape (b)** (v3 — replaces v2's mutation-enumeration rule, which the critic showed admits two silent-FN shapes; see §4.3):

1. *Sole binding:* count every binding of the name across `ast.walk(tree)` — `ast.Name(id=name)` in Store context (assignments, loop targets, walrus, comprehension targets), `ast.arg` with `arg == name` (function parameters — catches local shadowing without scope analysis), and `ast.alias` imports; require exactly one, and that it is the module-level dict-literal binding.
2. *Exclusive use:* collect the sanctioned node set — for every `ast.Call` whose `func` is an `ast.Attribute` with `attr` in `_SPLAT_REGISTRATION_METHODS` (receiver-agnostic, matching the handlers' own dispatch), every `ast.keyword(arg=None)` whose `value` is `ast.Name(id=name)` contributes that Name node's identity. Then require every Load-context `ast.Name(id=name)` in the module to be a member of the sanctioned set, and no Del-context occurrence of the bare name to exist.

Any failure of either condition → `None`, landing in the loud false-positive direction with the `extra_defined` escape. This SUBSUMES v2's `_DICT_MUTATORS` frozenset and Subscript Store/Del scan (both are Load occurrences of the name outside a splat position — a method receiver and a subscript receiver respectively) and additionally closes the two v2 escape shapes: a mutating callee (`_finalize(DEFAULTS)` — call-argument Load) and alias-mediated mutation (`B = DEFAULTS; B.pop("k")` — alias-RHS Load). One `ast.walk` pass, no scope analysis, no mutation-method enumeration to maintain. The natural adoption shape — `DEFAULTS = {...}` used only as `ap.set_defaults(**DEFAULTS)` (once or many times, at any handled registration call) — still resolves.

**Site 2 handler** (inside the existing `elif meth == "add_subparsers":` loop):

```python
                elif meth == "add_subparsers":
                    for kw in node.keywords:
                        if (
                            kw.arg == "dest"
                            and isinstance(kw.value, ast.Constant)
                            and isinstance(kw.value.value, str)
                        ):
                            defined.add(kw.value.value)
                        elif kw.arg is None:  # ** splat
                            mapping = _resolve_splat_mapping(kw.value, tree)
                            if mapping is None:
                                splat_sites.append((path, node.lineno, meth))
                            else:
                                dv = mapping.get("dest")
                                if isinstance(dv, ast.Constant) and isinstance(dv.value, str):
                                    defined.add(dv.value)
                                # resolved without a constant-str dest: contributes
                                # nothing — parity with the explicit non-constant
                                # dest= arm above (and with argparse's default:
                                # add_subparsers() without dest stores no attribute).
```

**Site 3 handler:**

```python
                elif meth == "set_defaults":
                    defined |= {kw.arg for kw in node.keywords if kw.arg is not None}
```

**Diagnostic (the degrade path's teeth-preserving half):** `assert_args_attributes_defined` collects `splat_sites: list[tuple[Path, int, str]]` — sites 2/3 append only UNRESOLVED splats; site 1 appends every splat-bearing `add_argument` call (its permissive handling can still miss a carried exotic `dest`, so it stays a "likely cause" candidate; append `(path, node.lineno, "add_argument")` right after the `defined |= _add_argument_dests(node)` line via `if any(kw.arg is None for kw in node.keywords)`). #### 4.3 Design decision record: chosen vs rejected (the substantive call)

**Chosen: (c) hybrid** — resolve when statically clean, degrade to a NAMED false-positive class (contribute nothing + diagnostic + `extra_defined` escape) otherwise; site 1 stays pure-permissive per the body's prescription.

- **Rejected (a) pure static resolution (no degrade framing):** without an explicit degrade path, an unresolvable splat either reverts to today's silent skip (the bug) or must "define everything" to avoid the FP — and defining everything guts the check whose entire value is catching undefined reads. (a) is subsumed by (c)'s resolve arm; standalone it has no answer for `**build_kwargs()`.
- **Rejected (b) pure documented-FP + `extra_defined`:** ~5 lines and zero resolver risk, but it leaves `ap.set_defaults(**DEFAULTS)` — the single most natural convention-adoption shape and the body's motivating scenario — raising `SystemExit` on correct code, just with a nicer message. The body's "why worth landing" argument is precisely that a new convention failing on correct code gets abandoned rather than debugged; (b) does not remove that friction, it re-words it. And the resolver risk is bounded: the abstain-unless-clean pattern is already accepted in-repo for exactly this dict-literal shape (`_extract_registry_members`, same parent task), and every abstain fails toward the loud FP direction.
- **Rejected: static resolution at site 1 too (uniform (c) everywhere):** three reasons. (i) The body's Fix section prescribes the `dynamic_dest = True` → permissive shape for `add_argument`, and acceptance criterion 1 literally says "route a `**` splat to the permissive path" — a resolved-splat-goes-exact site 1 would contradict the accepted fix's letter for zero observed benefit. (ii) At site 1 the names come from OPTION STRINGS; the splat only matters if it carries `dest`, and real shared `add_argument` dicts carry `type`/`help`/`action` (a per-argument `dest` in a shared dict is a contrived shape — zero call sites anywhere, §12.6). At sites 2/3 the dict's keys/values ARE the defined names, so resolution is the whole value. (iii) Differential treatment is therefore principled, not inconsistent; the residual it leaves (the body's own `**{"dest": "y"}` toy) is the same residual the existing dynamic-`dest=` branch already has, documented + escape-routed.
- **Residual FP kept, stated explicitly (teeth outrank FP-elimination):** (1) unresolvable splats at sites 2/3 (`**fn()`, cross-module imported dicts, mutated/rebound dicts) still flag undefined-looking reads — by design; the diagnostic + `extra_defined` is the escape. (2) A site-1 splat-carried `dest` outside the option-derived candidate set still flags. Both are the loud direction; neither hides a real bug.
- **Resolver-rule tightening record (v2 → v3, critic round 1):** v2's shape-(b) guard enumerated mutations *on the resolved name only* (Subscript Store/Del + a known-mutator method list). Two same-module shapes slipped through it into SILENT false negatives — the exact loud-FP→silent-FN conversion that made (c) preferable to (b) in the first place, so the v2 decision record rested on a false premise: (a) a **mutating callee** — `DEFAULTS = {"a": 1, "k": 2}` … `def _finalize(d): d.pop("k")` … `_finalize(DEFAULTS)` … `ap.set_defaults(**DEFAULTS)`: sole-bound, never rebound, never mutated *by name*, yet runtime never defines `args.k` while the v2 resolver adds `k` to DEFINED; (b) **alias-mediated removal** — `B = DEFAULTS; B.pop("k")`: the binding and mutation are both on `B`, so `DEFAULTS` looks pristine. v3 replaces the enumeration with the EXCLUSIVE-USE rule (§4.2): both shapes necessarily place the name in a non-sanctioned Load context (call argument; alias RHS) and now abstain by construction. T2 fixture C is the bite pin for this tightening (§4.4).
- **Residual FN kept — post-tightening reality:** (i) permissive at site 1 accepts alias reads that are runtime `AttributeError`s; a splat without `dest` now lands there too — a WIDENING *within* the existing dynamic-`dest=` FN class (e.g. from `{dry_run}` to `{n, dry_run}` on the P1 shape), not a new class — noted in the docstring per §4.5. (ii) Within a single module, the exclusive-use resolver introduces NO new FN surface: any occurrence of the name other than a sanctioned splat abstains. (iii) The one residual resolver FN channel is CROSS-module: with multiple `module_files`, a co-passed file mutating `driver.DEFAULTS` by attribute access escapes the per-file-tree scan (realistic only under a circular import) — documented as a docstring limitation (§4.5), not mechanism.

**Why not import `task_workflow._extract_registry_members`:** it is a private symbol of the VM-side workflow library with a different contract (expression→name resolution, keys-only, single-binding-unchecked), and `argcheck` is imported POD-SIDE inside drivers' `--import-check` blocks — `argcheck.py` is deliberately stdlib-only (`ast`, `os`, `pathlib`) so the convention adds zero dependency weight to every driver; importing the heavy workflow library from it would be a dependency-direction error. Pattern reuse, local implementation.
