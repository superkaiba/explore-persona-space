#### 4.2 Sites 2+3 — `add_subparsers` (:188-195) and `set_defaults` (:197): resolve-or-degrade (hybrid)

There is no permissive material at these sites — `add_subparsers` has no option strings and `set_defaults`' names come solely from kwarg keys — so "route to the permissive path" cannot mechanically apply. Chosen design: **hybrid (c)** — statically resolve the splat mapping when it is cleanly knowable; otherwise contribute nothing AND record the splat for a diagnostic in the `SystemExit` message.

**New module-level helper** (stdlib-only, full docstring per docstring-on-edit):

```python
_DICT_MUTATORS = frozenset({"update", "setdefault", "pop", "popitem", "clear"})

def _resolve_splat_mapping(value: ast.expr, tree: ast.AST) -> dict[str, ast.expr] | None:
    """Statically resolve a ``**`` splat's mapping to {str key: value node}, or None.

    Resolves exactly two shapes: (a) an inline ``ast.Dict`` literal at the
    call site; (b) an ``ast.Name`` whose SOLE binding anywhere in the module
    is one module-level ``Assign`` (single Name target) / ``AnnAssign`` to an
    ``ast.Dict`` literal, with no observed mutation of that name anywhere in
    the module (``d[k] = ...`` / ``del d[k]`` Subscript Store/Del, or a
    known-mutator method call — _DICT_MUTATORS). Every key must be a constant
    string (a nested ``**`` inside the literal appears as a None key ->
    abstain). Anything else returns None — never a guess (the same abstain
    discipline as #2176's registry-member reader in task_workflow.py).
    """
```

Sole-binding rule for shape (b): count every binding of the name across `ast.walk(tree)` — `ast.Name(id=name)` in Store context (assignments, loop targets, walrus, comprehension targets), `ast.arg` with `arg == name` (function parameters — this is what catches local shadowing without scope analysis), and `ast.alias` imports; require exactly one, and that it is the module-level dict-literal binding. Rebinding or shadowing anywhere → abstain (this fails toward the LOUD false-positive direction, never the silent false-negative one).

**Site 2 handler** (inside the existing `elif meth == "add_subparsers":` loop):

```python
                elif meth == "add_subparsers":

```

#### 4.3 Design decision record: chosen vs rejected (the substantive call)

**Chosen: (c) hybrid** — resolve when statically clean, degrade to a NAMED false-positive class (contribute nothing + diagnostic + `extra_defined` escape) otherwise; site 1 stays pure-permissive per the body's prescription.

- **Rejected (a) pure static resolution (no degrade framing):** without an explicit degrade path, an unresolvable splat either reverts to today's silent skip (the bug) or must "define everything" to avoid the FP — and defining everything guts the check whose entire value is catching undefined reads. (a) is subsumed by (c)'s resolve arm; standalone it has no answer for `**build_kwargs()`.
- **Rejected (b) pure documented-FP + `extra_defined`:** ~5 lines and zero resolver risk, but it leaves `ap.set_defaults(**DEFAULTS)` — the single most natural convention-adoption shape and the body's motivating scenario — raising `SystemExit` on correct code, just with a nicer message. The body's "why worth landing" argument is precisely that a new convention failing on correct code gets abandoned rather than debugged; (b) does not remove that friction, it re-words it. And the resolver risk is bounded: the abstain-unless-clean pattern is already accepted in-repo for exactly this dict-literal shape (`_extract_registry_members`, same parent task), and every abstain fails toward the loud FP direction.
- **Rejected: static resolution at site 1 too (uniform (c) everywhere):** three reasons. (i) The body's Fix section prescribes the `dynamic_dest = True` → permissive shape for `add_argument`, and acceptance criterion 1 literally says "route a `**` splat to the permissive path" — a resolved-splat-goes-exact site 1 would contradict the accepted fix's letter for zero observed benefit. (ii) At site 1 the names come from OPTION STRINGS; the splat only matters if it carries `dest`, and real shared `add_argument` dicts carry `type`/`help`/`action` (a per-argument `dest` in a shared dict is a contrived shape — zero call sites anywhere, §12.6). At sites 2/3 the dict's keys/values ARE the defined names, so resolution is the whole value. (iii) Differential treatment is therefore principled, not inconsistent; the residual it leaves (the body's own `**{"dest": "y"}` toy) is the same residual the existing dynamic-`dest=` branch already has, documented + escape-routed.
- **Residual FP kept, stated explicitly (teeth outrank FP-elimination):** (1) unresolvable splats at sites 2/3 (`**fn()`, cross-module imported dicts, mutated/rebound dicts) still flag undefined-looking reads — by design; the diagnostic + `extra_defined` is the escape. (2) A site-1 splat-carried `dest` outside the option-derived candidate set still flags. Both are the loud direction; neither hides a real bug.
- **Residual FN kept (pre-existing, unchanged in kind):** permissive at site 1 accepts alias reads that are runtime `AttributeError`s (already documented for dynamic option strings / dynamic `dest=`; a splat without `dest` now also lands there — noted in the docstring). New FN surface introduced by the resolver: none under the sole-binding + no-mutation rule for the shapes the resolver accepts; dict mutation via an unrecognized custom method on a plain dict literal is not possible (plain `dict` methods are enumerated), and subscript/known-mutator mutation abstains.

**Why not import `task_workflow._extract_registry_members`:** it is a private symbol of the VM-side workflow library with a different contract (expression→name resolution, keys-only, single-binding-unchecked), and `argcheck` is imported POD-SIDE inside drivers' `--import-check` blocks — `argcheck.py` is deliberately stdlib-only (`ast`, `os`, `pathlib`) so the convention adds zero dependency weight to every driver; importing the heavy workflow library from it would be a dependency-direction error. Pattern reuse, local implementation.
