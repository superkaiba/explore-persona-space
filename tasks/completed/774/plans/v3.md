# Plan — Task #774: multi-zone GCP fan-out before declaring a capacity miss

> **Executive summary (read this first)**
> - **What the code already does:** `GcpBackend.launch()` (gcp.py:3398-3487) ALREADY fans out across every us-central1 zone offering the resolved machine type — `for zone in zones_to_try` — and only counts the rung a capacity miss after EVERY zone misses. The per-day cap (`MAX_GCP_ATTEMPTS_PER_DAY=8`) is **rung-level, not zone-level** (`_bump_gcp_attempt` fires once per rung, router.py:3865). All four contract behaviors (zone iteration, per-machine-type filter, capacity-retry-vs-auth-raise, for-else raise) are implemented AND tested (6 passing tests).
> - **The #763 blocker was A100-80, which is offered ONLY in us-central1-a and -c** (verified live via gcloud — never -b, never -f). For the whole UTC day both a and c were `ZONE_RESOURCE_POOL_EXHAUSTED`, the SLURM fallback had a branch bug, and the RunPod terminal fallback also failed → `no_compute_available`. **No zone change could have rescued #763 — the region had no A100-80 to give.** The body Goal's "fan out across a/b/c/f for A100-80" is impossible (A100-80 isn't in b/f).
> - **What I propose (code + doc, NOT doc-only, NOT a no-change close):** (1) **Observability fix** — capture the FULL zones-tried list in the for-else `last_error` evidence so the failure marker shows "tried [a, c], all exhausted" instead of only the last zone's stderr. This is the ROOT CAUSE of the #763 misdiagnosis (the marker read "us-central1-c only" because it surfaced only the last zone). (2) **Add `us-central1-f` to `DEFAULT_FALLBACK_ZONES`** — a genuine marginal capacity win for the on-demand A100-40 rung (the only GCP rung offered in -f); A100-80 auto-filters -f out via the existing `MACHINE_TYPE_ZONE_AVAILABILITY` map, so it is safe. (3) **Document** the intra-rung zone fan-out + the A100-80-a/c-only constraint + the rung-level counter in `compute-backend-failover.md`. (4) Tests: zones-tried evidence, -f-for-A100-40 / -f-dropped-for-A100-80.
> - **Code (~20 lines, additive/backwards-compatible) + doc + tests.** Not doc-only because the observability gap is real and caused the misdiagnosis; the -f addition is the literal "more zones before declaring a miss" the body Goal asks for, applied to the one rung where it is physically possible.

## 1. Goal

Before counting a GCP rung as a capacity miss, fan out across the region's zones; only escalate to the next rung / `no_compute_available` after all zones miss. The #763 Phase-2 post-mortem read the failure as "ZONE_RESOURCE_POOL_EXHAUSTED in us-central1-c only", suggesting the zone fallback was short-circuited. Investigation shows the fan-out already happens; the deliverable is to (a) make the existing (correct) behavior **observable** so the next post-mortem reads "tried a AND c, both exhausted", (b) add the one extra zone (-f) the A100-40 rung can actually use, and (c) document the policy — so nobody re-files this as a missing-fan-out bug and the auto-router has one more zone pool to clear capacity on its cheapest rung.

## 2. Prior Work / Investigation findings

### 2.1 The zone fan-out already fires (code trace)

`GcpBackend.launch()` (gcp.py:3368-3493):
```
zones_to_try = [config.primary_zone] + [z for z in config.fallback_zones if z != primary]   # = [a, b, c]
zones_to_try = zones_for_machine_type(machine_type, zones_to_try)                            # A100-80 → [a, c]; b dropped
for zone in zones_to_try:
    result = self._run(render_create_argv(..., zone=zone))
    if result.returncode == 0: break                       # success → land here
    last_error = classify_create_failure(...)
    matched = last_error.evidence["matched_pattern"].lower()
    if not any(tag in matched for tag in ("exhaust","resource","enough resources")):
        raise last_error                                    # auth/quota → raise immediately, no zone retry
    # capacity-shaped → continue to next zone
else:                                                       # for-else: every zone missed
    raise last_error                                        # ← only carries the LAST zone's evidence
```
For an A100-80 rung this iterates `[a, c]`; both must miss (capacity-shaped) before the for-else raises. **This IS "fan out across zones before declaring a capacity miss."**

### 2.3 The per-day counter is RUNG-level, not zone-level

`_bump_gcp_attempt(lease)` (router.py:1095-1101) is called exactly ONCE per rung iteration (router.py:3863-3866), wrapping the whole `GcpBackend.launch()` call (which internally fans across zones). ## 3. Hypothesis

- **Perceived bug:** "GCP declared a capacity miss after trying only one zone (us-central1-c); it should fan out first."
- **Actual bugs (two, both small):**
  1. **Observability** — the raised `last_error` / failure marker surfaces only the LAST zone's stderr, so a post-mortem cannot tell that all available zones were tried. **This is the root cause of the #763 misdiagnosis** (CONFIRMED via §2.4).
  2. **Coverage (marginal)** — the on-demand A100-40 rung is offered in -f but the configured `DEFAULT_FALLBACK_ZONES` omits -f, so that one rung tries 3 zones (a, b, c) when it could try 4 (a, b, c, f). One more independent zone pool strictly raises the rung's chance of clearing capacity.
- **Falsification of "fix is the A100-80 fan-out":** A100-80 is offered only in {a,c} (gcloud-verified), the fan-out across {a,c} fires and is tested → there is no A100-80 zone to add and no loop to write. **CONFIRMED falsified.** The A100-80 fan-out is correct as-is.
- **Prediction:** After the fix, a re-run that exhausts A100-80 in both a and c produces a marker reading `… all 2 zone(s) [us-central1-a, us-central1-c] capacity-exhausted …`, and the on-demand A100-40 rung will additionally try us-central1-f before that rung escalates.

### 4.1 (CODE) Capture the full zones-tried list in the for-else `last_error` evidence — the root-cause fix

`src/explore_persona_space/backends/gcp.py`, launch loop lines 3398-3487. Accumulate each zone actually created in, and in the for-else branch (3483-3487) enrich the raised `last_error` so `_provisioning_detail` (router.py:1780) surfaces it into the marker + terminal JSON:

```python
last_error: GcpProvisioningError | None = None
zones_attempted: list[str] = []                      # NEW
try:
    for zone in zones_to_try:
        zones_attempted.append(zone)                  # NEW
        argv = render_create_argv(..., zone=zone)
        ...
        if result.returncode == 0:
            break
        last_error = classify_create_failure(...)
        matched = (last_error.evidence.get("matched_pattern") or "").lower()
        if not any(tag in matched for tag in ("exhaust", "resource", "enough resources")):
            raise last_error                          # non-capacity → unchanged
        ...
    else:
        assert last_error is not None
        # NEW: name the full zone fan-out so the marker / terminal JSON shows
        # every zone tried, not just the last zone's stderr (#774 / #763 gap).
        last_error.evidence.setdefault("zones_attempted", list(zones_attempted))
        last_error.evidence["zones_attempted_summary"] = (
            f"all {len(zones_attempted)} zone(s) "
            f"[{', '.join(zones_attempted)}] capacity-exhausted for "
            f"machine_type={machine_type}"
        )
        raise last_error
```
Also enrich `_provisioning_detail` (router.py:1780-1793) to prepend the summary when present (byte-identical output when absent):
```python
def _provisioning_detail(exc: GcpProvisioningError) -> str:
    summary = str(exc.evidence.get("zones_attempted_summary") or "").strip()   # NEW
    tail = str(exc.evidence.get("stderr_tail") or "").strip()
    parts = [exc.reason]
    if summary:                                                                 # NEW
        parts.append(summary)
    if tail:
        parts.append(f"stderr_tail: {tail[-1024:]}")
    return "; ".join(parts)
```

```markdown
### Intra-rung zone fan-out (#774)

Each GCP rung is NOT a single-zone create. `GcpBackend.launch()` fans out
across every us-central1 zone offering the resolved machine type before the
rung counts as a capacity miss: the create is retried in `config.primary_zone`
then each `config.fallback_zones` zone, filtered by
`MACHINE_TYPE_ZONE_AVAILABILITY` (`zones_for_machine_type`). A capacity-shaped
miss (`ZONE_RESOURCE_POOL_EXHAUSTED` / "enough resources") advances to the next
zone; an auth/quota miss raises immediately (the next zone fails identically).
Only after EVERY available zone misses does the rung raise
`GcpProvisioningError` and the router advance to the next rung — and the raised
error's `zones_attempted_summary` evidence names the full zone set (so a
post-mortem reads "all 2 zone(s) [a, c] exhausted", not just the last zone's
stderr — the #774 / #763 reporting gap).

The configured ladder is `[us-central1-a, -b, -c, -f]`. Per family:
- **A100-80 (`a2-ultragpu-*g`)** is offered ONLY in -a and -c (NOT -b, NOT -f;
  verified live 2026-06-30), so its fan-out is exactly 2 zones. Adding -b/-f for
  A100-80 is impossible and would re-introduce the #653 CONFIG-400 attempt-burn.
- **A100-40 (`a2-highgpu-1g`)** is offered in -a/-b/-c/-f, so the on-demand
  A100-40 rung fans across all four zones (the #774 -f addition).

The per-day cap (`MAX_GCP_ATTEMPTS_PER_DAY`) counts RUNGS, not zones: one
`_bump_gcp_attempt` per rung regardless of how many zones the rung fanned
across. So the 8/day cap is a true 8-RUNG cap.
```

## 11. Decision Rationale

**N/A — no model training** for hyperparameters. Non-obvious choices:

- **What:** Keep `MACHINE_TYPE_ZONE_AVAILABILITY` for A100-80 at `{a, c}`; do NOT expand to b/f. **Why:** A100-80 (`a2-ultragpu-*g`) is offered only in a and c (gcloud verified live 2026-06-30). Adding b/f would issue a guaranteed-to-fail CONFIG 400 that burns the per-day attempt counter on a non-capacity error. **Source:** gcp.py:486-505 comment block (#653) + the live gcloud probe (§2.2). **Alternatives:** expanding A100-80 to b/f (rejected — re-introduces #653); a different region with more A100-80 zones (rejected — architectural, GFS A100-80 quota lives in us-central1).

- **What:** Add `-f` to `DEFAULT_FALLBACK_ZONES` (helps ONLY the A100-40 rung). **Why:** the on-demand A100-40 rung (`a2-highgpu-1g`, the last GCP rung on both ladders) is offered in -f but never tries it; one more independent zone pool strictly raises its capacity-clear probability, and is the body Goal's literal "more zones before declaring a miss" applied where it is physically possible. Safe because A100-80 auto-trims -f via the existing map. **Source:** gcp.py:537-539 (the verified `a2-highgpu-1g → {a,b,c,f}` row) + §2.2 live probe. **Alternatives:** leaving the ladder at `[a,b,c]` (rejected — leaves a free zone pool unused on the cheapest rung); only doing the observability fix (rejected — misses a cheap real capacity win directly in scope).

- **What:** Leave the per-day counter at rung-level (`_bump_gcp_attempt` once per rung). **Why:** a rung fanning across 2-4 zones is still one logical "try this configuration" attempt; counting per-zone would shrink the effective ladder for a multi-zone family for no benefit (both/all zones 400 in seconds in a dead region). **Source:** router.py:3863-3866 (current behavior); §2.3 trace. **Alternatives:** zone-level counting (rejected — shrinks ladder, no upside); raising the cap (rejected — out of scope, #680 already tuned 5→8).

- **What:** Surface zones-tried via the free-text `detail` (`zones_attempted_summary`), NOT a new structured `RouteAttempt.zone` field. **Why:** a marker-schema field is a public-contract change requiring greenlight; the free-text detail already flows to the marker + terminal JSON via `_provisioning_detail` — lowest-blast-radius surface. **Source:** `.claude/rules/workflow-fix-on-bug.md` § Architectural greenlight (marker schema = public contract). **Alternatives:** structured `RouteAttempt.zone` (rejected — architectural; defer to a future task if structured zone telemetry is ever wanted).
