## 1. Goal

> Move the per-file agent-spec size caps out of the shared `AGENT_SPEC_SIZE_GRANDFATHER` Python dict literal in `scripts/workflow_lint.py` into a line-mergeable form (a one-entry-per-line data file, or a mechanically derived cap) so concurrent workflow-fix sessions never edit the same lines.
> (Task #1718 Goal, verbatim.)

The dict as it stands is an 85-line block where each of 8 entries sits under a 5-15-line "cap chronicle" comment. Two workflow-fix sessions raising caps on TWO DIFFERENT agent files still edit adjacent lines and produce a 3-way merge conflict, because git's diff granularity is the line, not the entry. On 2026-07-26 alone four such sessions collided on this block three times (~152 min of gate/reconcile overhead observed across two transcripts). The Goal is a storage split that makes two per-file cap edits touch two different lines — with byte-identical semantics at every consumer, so the ratchet's protection is unchanged.

## 4. Design

### 4.1 The data file — location, name, schema

**Location: `.claude/config/agent_spec_size_caps.txt`.** Rationale: the file is workflow configuration read by `workflow_lint.py`, not a test fixture. The body's suggestion `tests/agent_spec_size_caps.txt` places it under `tests/` where readers expect test code; `.claude/config/` is a fresh directory but its meaning is self-documenting and it aligns with the existing `.claude/rules/`, `.claude/agents/`, `.claude/skills/` layout. **Alternative rejected:** `scripts/agent_spec_size_caps.txt` — would sit next to the reader but the convention in this repo is that `scripts/` holds executables + shell scripts, not data.

**Schema (one entry per line).**

```
# Agent-spec grandfather caps — one line per entry, line-mergeable by design.
# Format: <filename> <cap_bytes>  # optional reason/history
# Blank lines and lines whose first non-whitespace char is `#` are ignored.
# The trailing `# …` on a data line is stripped by the loader (informational only).
# Semantics: read by workflow_lint.AGENT_SPEC_SIZE_GRANDFATHER — the module
# attribute keeps its name + type (dict[str, int]) so every consumer site,
# test monkeypatch, and verify_plan reference is unchanged.

code-reviewer.md            122_400   # measured 121,782 B post-#1726 (Step 3.6 T2 count trigger + verdict-routing rewrite); cap = measured + ~0.6 KB
codex-clean-result-critic.md 75_200   # measured 74,082 B post-#1447; cap = measured + ~1.1 KB
codex-code-reviewer.md       60_800   # measured 59,576 B post-#1693 (Step 0.69 mirror paragraph); cap = measured + ~1.2 KB
experiment-implementer.md    80_500   # measured 76,274 B post-#1692 (item 5 Axis 1 import-resolution leg …); cap = measured + ~0.23 KB
experimenter.md              75_400   # measured 79,611 B post-#1720 (§ Local runs pre-emptive NOT-RUN escape); cap = measured + ~0.9 KB
methodology-writer.md        50_700   # measured 49,740 B post-#1115 (read-hygiene context-budget section); cap = measured + <=~1 KB
research-pm.md               47_000   # measured 46,785 B post-#1618 (unmapped-pod triage + Mode-2 audit template relocated); cap = measured + ~0.2 KB
upload-verifier.md           51_500   # measured 50,741 B post-#1535 (Step 2.7 declared-off-pod outputs sub-rule …); cap = measured + ~0.8 KB
```

Notes:
- **Underscores in integers ARE supported by the loader** (parsed by stripping `_`, matching the existing literal's `122_400` shape) — every current cap is preserved verbatim.
- **The chronicle history that today lives in multi-line comments above each dict entry** compresses to a ONE-LINE trailing `# …` per entry. The full historical chronicle (the "prior: 121,300 — measured 120,709 B post-#1693 …" narrative) is IMMATERIAL to the ratchet's operation — it lives in git's own commit history, and the body of workflow-fix task #1693 already records the cap-raise reason. I choose to DROP the multi-line prior-cap chronicle from the data file; the current-measurement single-line reason stays. This is the load-bearing design choice for line-mergeability: even one long trailing comment does not force conflicts, but a multi-line comment above each entry restores the exact structural conflict this task exists to eliminate.
- **Prior-cap chronicle preservation.** The 14-line chronicles are not lost — they persist in `git log --follow scripts/workflow_lint.py` before the migration commit. If a reader ever needs "what was the cap before #1693?", the answer lives at that commit's `AGENT_SPEC_SIZE_GRANDFATHER` block. The migration commit's message will name the preservation path explicitly.
- **Column alignment** (the extra spaces) is cosmetic and unenforced; the loader `.split()` on whitespace so any spacing works.

### 4.2 The loader — location, signature, error semantics

Location: `scripts/workflow_lint.py`, immediately BEFORE the `AGENT_SPEC_SIZE_GRANDFATHER` line, private (leading underscore):

```python
_AGENT_SPEC_CAPS_PATH = _REPO_ROOT / ".claude" / "config" / "agent_spec_size_caps.txt"


def _load_agent_spec_caps(path: Path | None = None) -> dict[str, int]:
    """Load per-file agent-spec caps from the line-mergeable data file.

    Format: one entry per line, `<name> <cap>` with optional trailing
    `# <reason>` (stripped). Blank lines + `#`-only lines are ignored.
    Underscores in cap ints are supported (`122_400` → 122400), matching
    the pre-migration Python literal.

    Fail-loud: a missing file, a malformed line, or a duplicate name raises
    at import time — the ratchet is safety infrastructure and a silent
    empty dict would un-grandfather every WARN-band spec.
    """
    p = path if path is not None else _AGENT_SPEC_CAPS_PATH
    caps: dict[str, int] = {}
    text = p.read_text(encoding="utf-8")  # raises FileNotFoundError loud
    for lineno, raw in enumerate(text.splitlines(), start=1):
        line = raw.split("#", 1)[0].strip()
        if not line:
            continue
        parts = line.split()
        if len(parts) != 2:
            raise ValueError(
                f"{p}:{lineno}: expected `<name> <cap>` (got {raw!r})"
            )
        name, cap_str = parts
        try:
            cap = int(cap_str.replace("_", ""))
        except ValueError as exc:
            raise ValueError(
                f"{p}:{lineno}: cap {cap_str!r} is not an integer"
            ) from exc
        if name in caps:
            raise ValueError(
                f"{p}:{lineno}: duplicate entry for {name!r} "
                f"(first seen at earlier line)"
            )
        caps[name] = cap
    return caps
```

Then the constant becomes:

```python
# Grandfather-ratchet caps for agent specs still above AGENT_SPEC_FAIL_BYTES.
# Storage is a one-entry-per-line data file (see _load_agent_spec_caps
# above + .claude/config/agent_spec_size_caps.txt) so concurrent
# workflow-fix sessions raising caps on DIFFERENT files edit different
# lines and merge cleanly (#1718). The module attribute name + type
# (dict[str, int]) is preserved so every consumer site, test monkeypatch,
# and verify_plan reference is unchanged.
AGENT_SPEC_SIZE_GRANDFATHER: dict[str, int] = _load_agent_spec_caps()
```

The 85-line header comment / chronicle that today sits above the dict shrinks to the 8 lines above; the ratchet-semantics header (L11877-11885) STAYS in place.

**Design decision: module-level attribute, not a function.** I evaluated a function `agent_spec_caps() -> dict[str, int]` re-read per call. **REJECTED.** The check runs once per commit; three consumer sites read it; every existing monkeypatched test writes to `workflow_lint.AGENT_SPEC_SIZE_GRANDFATHER` as an attribute. Making it a function would break 5 tests (adds no value: the file is read once at import; re-reading per call adds latency for no gain).

**Design decision: fail loud on missing/malformed file.** `read_text` raises `FileNotFoundError` uncaught; `_load_agent_spec_caps` raises `ValueError` on a malformed line or duplicate name. Rationale: the ratchet is safety infrastructure — a silent empty dict `{}` would un-grandfather every currently-grandfathered file, and every WARN-band spec (all 8 live entries sit >40 KB) would flip from WARN under a cap to FAIL uncapped, breaking every commit fleet-wide within one lint invocation. Better to crash the module import than mask the problem.

## 11. Decision Rationale
