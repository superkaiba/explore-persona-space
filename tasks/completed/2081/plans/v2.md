## 1. Requirement + acceptance criteria

Extend `scripts/workflow_lint.py` with a new check that mechanically enforces the
`.claude/rules/gotchas.md` § "Fellows SLURM nodes are GPU-SHARED" rule: a shell
launcher that derives GPU **width** from `nvidia-smi` device enumeration must also
carry a SLURM allocation-env branch, or an explicit waiver. On a shared SLURM node
`nvidia-smi` enumerates all 8 physical devices and ignores `CUDA_VISIBLE_DEVICES`,
so a detected-count fan-out trespasses onto other tenants' GPUs (#1902 incident;
#1491 fixed one launcher — commit `1c8b46d28a`).

Acceptance criteria:

1. New check `check_slurm_gpu_width()` + CLI flag `--check-slurm-gpu-width`,
   **bundled into the no-flags default run** (same policy as
   `check_dispatcher_cvd_pin`).
2. The no-flags default run shows no NEW failure lines vs the plan-time baseline
   (the Step 10d gate's `comm -23` subtraction is the arbiter; grandfather
   calibration — see §4).
3. The two GUARDED files (`issue1491_ladder_launch.sh`, `issue1902_dispatch.sh`)
   pass the predicate NATURALLY (not via grandfather).
4. A NEW fixture file with `nvidia-smi -L | wc -l` (or `--list-gpus` /
   `--query-gpu=index` variants) and no SLURM guard is FLAGGED.
5. Waiver `# SLURM_GPU_WIDTH_EXEMPT: <reason>` (reason ≥ 10 chars, same logical
   line or immediately preceding non-blank line — the CVD_PIN_EXEMPT convention)
   suppresses the flag.
6. Pin test `tests/test_workflow_lint_slurm_gpu_width.py` covers flag/pass/waiver/
   grandfather/stale-grandfather/no-flags-bundling/live-tree-green.
7. `run_issue650_pipeline.sh` untouched (verified-correct at filing; it does not
   match the width pattern anyway).
8. No retrofit of the 18 grandfathered launchers (frozen per-issue drivers;
   #1491's fix is the adoption exemplar for new launchers).

## 2. Method delta

New enforcement only — no behavior change to any launcher. The adjacent
`--check-dispatcher-cvd-pin` checks a DIFFERENT property (CVD prefix on
backgrounded `--gpu-id` launches) and stays untouched. This check is file-scoped
where CVD-pin is line-local: the SLURM guard legitimately lives far from the
`nvidia-smi` fallback line (the #1491 shape — guard at line 193, enumeration in
the else-branch), so guard detection must scan the whole file.

## 3. Check design (concrete)

**Detection (per `*.sh` under `scripts/`, rglob, logical lines with backslash
continuations merged via `_iter_logical_shell_lines`):**

- `SLURM_GPU_WIDTH_NVSMI_RE`: a non-comment, non-`echo `-prefixed logical line
  matching nvidia-smi device ENUMERATION feeding a count:
  `nvidia-smi (-L|--list-gpus|--query-gpu=...) ... | wc -l`
  (regex ~ `nvidia-smi\s+(?:-L\b|--list-gpus\b|--query-gpu=)[^|]*\|\s*wc\s+-l`).
- **File-level guard scan** (`SLURM_GPU_WIDTH_GUARD_RE`): the file text contains
  any of `SLURM_JOB_ID`, `SLURM_JOB_GPUS`, `SLURM_STEP_GPUS`,
  `SLURM_GPUS_ON_NODE`, or `realized_gpu_ids`. Guard present → file passes
  (documented recall miss: a guard token appearing only in a comment also
  passes — fail-toward-false-negative, the house safe direction).
- **Waiver:** `# SLURM_GPU_WIDTH_EXEMPT: <reason>` (reason ≥ 10 chars;
  `SLURM_GPU_WIDTH_WAIVER_MIN_REASON_CHARS = 10`), same logical line or
  immediately preceding non-blank line (reuse the `_cvd_pin_waiver_present`
  shape with the new regex).
- **Grandfather:** `SLURM_GPU_WIDTH_GRANDFATHER: frozenset[str]` of 18 basenames
  (frozen 2026-08-10; enumerated below). A grandfathered file's matches are
  skipped for FAIL purposes. **Stale-entry WARN:** a grandfathered basename with
  ZERO width-derivation matches (or a guard now present) WARNs
  "remove <name> from SLURM_GPU_WIDTH_GRANDFATHER" — ratchet direction, never a
  FAIL.
- FAIL message names: the shared-node mechanism (#1902), the reference impl
  `scripts/issue1902_common.py::realized_gpu_ids`, the worked adoption
  `scripts/issue1491_ladder_launch.sh` @ `1c8b46d28a`, the gotchas rule, and the
  waiver token.

**Grandfather set (18 basenames, verified UNGUARDED 2026-08-10):**
`issue1310_dispatch.sh`, `issue1335_run.sh`, `issue1336_dispatch.sh`,
`issue1345_dispatch.sh`, `issue1417_run.sh`, `issue1426_sampled_dispatch.sh`,
`issue1689_dispatch.sh`, `issue1738_multiturn_launch.sh`, `issue1769_dispatch.sh`,
