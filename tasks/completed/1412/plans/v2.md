## 3. Design

Three edits, all mechanical for the implementer. No behavior of any script changes; this is documentation-as-runbook plus a pin test.

### Side-selection rule (the one real design decision)

**Rule: newer-regeneration-wins, per conflicted path, by last-touching commit time; tie → theirs.** Rationale against the two simpler alternatives:

- *Always ours (branch):* wrong on the #1090 incident itself — main carried the newer inline-round regeneration (`297e9ec27d`), and the improvised recovery correctly took main's copy.
- *Always theirs (main):* wrong in the mirror case — a conflict fires only when BOTH sides changed the path since the merge base, and the branch's own follow-up round is frequently the newer regeneration (main's copy then being an older inline commit).
- *Timestamp comparison* implements the Goal's phrase "take the newer round's copy" literally, is deterministic (no human judgment mid-recovery), and cheap (two `git log -1` calls per conflicted path; figure conflicts number in the single digits). Commit time is a faithful recency proxy because a figure is regenerated and committed within the same round (branch commits in this flow are not locally rewritten — Guard-1 strips are new commits). Safety: the LOSING copy stays recoverable — the issue branch is kept after merge (Step 10d keeps branch + worktree; #1090: "Branch issue-1090-fu4 kept"), main history is immutable, and every figure re-renders from its committed eval JSON with the sidecar `meta.json` pinning provenance. Stem-mates (`.png`/`.pdf`/`meta.json`) are committed together by a regeneration, so per-path `%ct` resolves the whole group to the same side; the text `meta.json` sidecar deliberately rides the same rule so figure and provenance never split sides.

**Incident replay (predicate traced against the real artifact):** conflicted paths in #1090 fu4 = `figures/issue_1090/fu4/fu4_tier2_verdict.{png,pdf}` (add/add). Theirs' last-touching commit = `297e9ec27d` (the interp-critique r1 regeneration, which by construction post-dates the branch's original render it critiques) → `THEIRS_CT > OURS_CT` → rule selects theirs = main's regenerated copies = exactly what the session improvised. The recipe fires correctly on its own motivating incident.

### Edit 1 — the recipe block (the insertion)

**File:** `.claude/skills/issue/SKILL.md`. **Anchor:** inside the recovery's fenced bash block, immediately AFTER the `fi` that closes the foreign-`tasks/` if/elif chain (currently L10067) and immediately BEFORE the comment line `# THIS task's own tasks/*/<N>/ conflicts and all non-tasks/ conflicts:` (currently L10068). Insert this text verbatim (and change that following comment line as shown at the end):

```
# Binary figures/ conflicts (add/add or modify/modify — #1090 fu4 / PR
# #1066; earlier #697/#597): git cannot content-merge binaries, and the
# .gitattributes merge=union rules cover tasks/ jsonl + agent-memory md,
# NOT figures/ — so both-sides-changed figure paths ALWAYS conflict.
# Figures are REGENERABLE artifacts (sidecar meta.json pins provenance;
# the analyzer re-renders + SHA-pins): resolve MECHANICALLY, the NEWER
# regeneration wins — compare the last commit touching the path on each
# side; tie -> theirs (in THIS merge ours = the issue branch, theirs =
# the captured $MAIN_SHA snapshot — the #1090-proven side). The losing
# copy stays recoverable (branch kept post-merge; main history is
# immutable; the figure re-renders from committed eval JSON). Stem-mates
# (png/pdf/meta.json) commit together per regeneration, so per-path %ct
# resolves the group to one side. checkout --ours/--theirs writes the
# working tree only — the git add resolves the index entry, and the add
# is GATED on checkout success: a failing checkout (modify/delete:
# missing stage) leaves the entry UNMERGED, so the later
# `git commit --no-edit` refuses on unmerged paths — the loud
# fall-through to the manual prose below. NEVER stage a path whose
# checkout failed.
if ! git -C "$WT" -c core.quotePath=false diff --name-only --diff-filter=U -- 'figures/' \
    > /tmp/issue-<N>-recovery-figures.txt; then
  echo "recovery: figures/ conflicted-paths diff FAILED — resolve by hand per the prose below"
  false
else
  while IFS= read -r p; do
    OURS_CT=$(git -C "$WT" log -1 --format=%ct HEAD -- "$p")
    THEIRS_CT=$(git -C "$WT" log -1 --format=%ct "$MAIN_SHA" -- "$p")
    if [ "${THEIRS_CT:-0}" -ge "${OURS_CT:-0}" ]; then SIDE=--theirs; else SIDE=--ours; fi
    if git -C "$WT" checkout "$SIDE" -- "$p"; then
      git -C "$WT" add -- "$p"
    else
      echo "recovery: figures/ checkout $SIDE FAILED for $p (modify/delete missing stage?) — left UNMERGED; resolve by hand per the prose below"
    fi
  done < /tmp/issue-<N>-recovery-figures.txt
fi
```

An empty conflicted-figures list runs the loop zero times and exits 0 — deliberate parity with the foreign-`tasks/` empty-list behavior documented just above the anchor. Then edit the immediately-following comment line for coherence:
