### 4.1 New helper (core) — `src/explore_persona_space/task_workflow.py`

Two NEW read-only functions (no flock, no commit, no mutation), appended after `has_event` (task_workflow.py:5762; symbol-existence confirmed by `grep -n "def has_event" src/explore_persona_space/task_workflow.py` → `5762:def has_event(...)`):

```python
def list_events_head_union(task_id: int) -> dict[str, Any]:
    """Stash-window-robust events read (#2328): HEAD blob ∪ working tree.

    Returns {"head": [rows], "worktree": [rows], "union": [rows]} where
    union preserves HEAD order then appends worktree-only rows; dedupe key
    is json.dumps(row, sort_keys=True). READ-ONLY by contract.
    """
```

- Working-tree leg: `_iter_jsonl(find_task_path(task_id) / "events.jsonl")` (existing reader, unchanged).
- HEAD leg: `git -C repo_root() show HEAD:<relpath>` where `relpath = (find_task_path(id)/"events.jsonl").relative_to(repo_root())`; output parsed with the EXISTING `_iter_jsonl_text(text, source=f"HEAD:{relpath}")` (task_workflow.py:5445 — built in #1565 for exactly this git-blob case). On `git show` failure (path not at HEAD — e.g. an uncommitted status move or a brand-new task), fall back to the registry blob: `git show HEAD:tasks/REGISTRY.json` → `json["tasks"][str(task_id)]["path"] + "/events.jsonl"` (schema verified: `jq -c '.tasks."2325"' tasks/REGISTRY.json` → `{"path":"tasks/completed/2325",...}`); if that also misses, the HEAD contribution is `[]` (task never committed — union degrades to the working-tree read, correctly).

```python
def marker_status(
    task_id: int, kind: str, *, note_contains: str | None = None,
    version: int | None = None,
) -> dict[str, Any]:
    """Classify marker presence across HEAD, working tree, and the
    deferred-commit ledger (#2328). Verdicts:
      present-committed   — matched in HEAD (durable; nothing to do)
      present-uncommitted — matched in worktree only (append landed,
                            commit deferred/pending; do NOT re-post)
      pending-deferred    — absent from both, but a matching
                            DEFERRED_COMMITS_LOG row exists (row is
                            mid-stash-window or awaiting sweep; re-read
                            in ~60 s; NEVER re-append; if persistently
                            absent, the rescue surface is
                            ~/.cache/pre-commit/patch* — #1806)
      absent              — no evidence in any source
    Returns verdict + per-source match counts + matched-row excerpts +
    ledger rows + a guidance string. READ-ONLY.
    """
```

- Row match: `row["kind"] == kind`, then optional `note_contains in (row.get("note") or "")` and `version == row.get("version")`.
- Ledger match: rows of `DEFERRED_COMMITS_LOG` (module attribute referenced at call time, so the existing test monkeypatch works) with `row["task_id"] == task_id`, `row["op"] == "post_event"`, and `row["message"] == f"task #{task_id}: {kind}"` or `row["message"].startswith(f"task #{task_id}: {kind} — ")` (the writer's exact format, task_workflow.py:8735: `f"task #{task_id}: {kind}" + (f" — {note[:60]}" if note else "")`). The ledger is version-blind (message truncates the note at 60 chars); output labels ledger matches `version_blind: true`. A `gitleaks_finding` ledger flag is surfaced verbatim (that class never sweeps; the guidance says so).
- No lookback filter: an old ledger row with the marker absent from both trees is still evidence the append happened (e.g. a never-swept gitleaks deferral) — the verdict stays `pending-deferred` with the ts shown; the reader decides.
