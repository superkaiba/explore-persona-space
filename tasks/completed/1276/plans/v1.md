### 4.1 `check_html_entities_in_commands` (lines ~3880–3897)

Replace the flattened `hits_a` construction with per-fence hit tracking; the exemption branch keys on the hit-bearing fence count:

## 11. Decision Rationale

**What:** count-scoped arm-(a) exemption — declaration valid iff exactly one DISTINCT entity-bearing arm-(a) fence; >1 → FAIL naming the count (option a, FAIL variant).

**Why:** (1) Anti-masking is the Goal — a poisoned fence must not ride a legitimate fence's declaration; WARN (option c) still ships the poisoned fence past the gate (WARN never blocks, exit 0), only surfacing it in briefs, so it meets the goal partially at the same implementation cost. (2) The false-positive cost of FAIL is empirically zero: 0/84 corpus plans have >1 entity-bearing arm-(a) fence (0 have even one), and any future legitimate multi-fence content plan has the zero-cost re-tag remedy (a content fence shouldn't be shell-tagged in the first place — arm (a) exists to catch *commands*). (3) FAIL matches c25's existing severity class (it is a FAIL check; arm (b) FAILs unconditionally) and the #1062 precedent's spirit: where a masking channel can be closed mechanically with no legitimate-use cost, close it hard.

**Source:** #1062 (commit `a50667548e`, methodology-reconciler round-1 finding recorded in the check docstring); #1258 round-1 Alternatives-critic candidate (this task's Provenance); corpus survey 2026-07-12 (§2: 84 files / 20 declarations / 0 multi-fence / 0 single-fence).

**Alternatives rejected:**
- **(b) per-fence declarations** — heavier contract change (every future multi-fence plan writes N declaration lines; SKILL.md canonical block + all downstream remedy text must change → would warrant `architectural: true`), requires a new counting variant of `_standalone_na_declared`, and STILL fails the binding requirement: declarations carry no fence anchor, so 2 declarations + (1 content + 1 poisoned) fence passes count-matching — all of the cost, none of the anti-masking benefit beyond option (a).
- **(c) WARN when count > 1** — keeps the poisoned-fence PASS (WARN is non-blocking by design, module docstring lines 130–134); given zero corpus false-positive cost for FAIL, downgrading to WARN trades the Goal away for a robustness the data says is unneeded. If a future legitimate multi-fence pattern emerges in the corpus, relaxing FAIL→WARN then is a one-line change with this plan's tests adjusted — the reversible direction.
- **Count distinct entity FORMS instead of fences** — the current `hits_a` shape; explicitly wrong grain (one poisoned fence with the same form as the content fence would be invisible; the brief's precision point).
