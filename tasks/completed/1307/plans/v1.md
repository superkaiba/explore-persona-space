## 3. Requirement

The mandate text at every mandate surface must state two binding rules:

**(a) Per-target confirmation.** The recorded grep must be run against (at least) EACH file named in `target_file`, with per-target hit counts stated in the line. For a **presence claim** (the body asserts a call site / stale string / parse site / pattern EXISTS at the named target), a 0-hit named target is a mis-target, not evidence: the filer must re-grep repo-wide, correct `target_file` to the real site(s), and re-verify BEFORE filing. Scoping note (prevents over-constraint): for an **absence-of-guard claim** (the body asserts a guard/handling is MISSING from the target), the 0-hit in-target result IS the expected evidence and the mis-target rule does not apply — and genuinely non-grep-verifiable claims keep the `n/a — <reason>` escape unchanged.

**(b) Relocation grep before any nonexistence claim.** Asserting a cited symbol / test / file nonexistent ("no longer exists", "was removed") requires a recorded REPO-WIDE relocation grep (`grep -rn '<symbol>' tests/ scripts/ .claude/ src/`) — a single-path probe (one-file pytest run, one-file grep) cannot distinguish "removed" from "moved".

Both rules bind the compose-time duty only; there is still no mechanical injector or lint (unchanged — stated explicitly so no reader infers a new lint exists).
