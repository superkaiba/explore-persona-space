## 0.0 TL;DR (plain English)

- **What I'll run:** Train sixteen new marker adapters on sixteen rebuilt in-context demonstration blocks (using the same recipe the instruction-side adapters already used), then measure, on the same diverse 500-question pool everywhere, how strongly the marker each adapter learned leaks into the model's own responses under every OTHER context — and check whether the directional asymmetry of that leakage is predictable from base-model geometry.
- **What I expect:** The directional predictor that wins on the instruction-only panel will show small but real directional signal on the unified panel; if it does, the antisymmetric component of leakage transfer is partly recoverable from base-model representations, and we can name the functional form. Likely outcome: positive but small effect — informative either way.
- **What would change my mind:** Every directional predictor at zero incremental skill (CI spans zero) and zero correlation with the antisymmetric leakage component — that would mean the directional 28% of leakage variance is not linearly recoverable from base-model geometry and would bound the program.

## 3. Hypothesis

Goal-canonical: a directional/asymmetric base-model predictor recovers the antisymmetric component of marker-leakage transfer on the unified instruction+ICL panel.

### What would update the belief

- A directional predictor with a nested-CV incremental ΔR² CI excluding 0 on full ΔG, that ALSO scores non-zero vs ΔG_anti and survives the held-out pool → real recoverable directional leakage signal; name it.
- All directional predictors at incremental ΔR² ≈ 0 (CI spans 0) and ΔG_anti ≈ 0 → the directional 28% is not linearly recoverable from base-model geometry; a strong bound on the program.
- Cross-type (ICL↔instruction) cells: does the predictor that wins within-type also win across induction mechanisms?

### Falsification criteria (single-arm clear PASS/FAIL)

- **CLEAR PASS:** at least one directional predictor's paired nested LTCO-CV pooled out-of-fold incremental skill (ΔR²_pooled, or unified censored ΔLL when censored fraction ≥ 10% on any block) over `M_sym = ΔG ~ gauss_kl_L22 + length` has a context-clustered dyadic bootstrap CI strictly above 0 on the full 992-pair panel AND standalone ρ vs `ΔG_anti` has CI strictly excluding 0 AND the asymmetry-vs-asymmetry correlation `ρ[½(d[A,B]−d[B,A]), ΔG_anti]` has CI strictly excluding 0 AND the winner replicates on the #523 held-out probe pool.
- **CLEAR FAIL (strong null):** every directional predictor has incremental ΔR² CI overlapping 0 AND ρ vs ΔG_anti CI overlapping 0. Load-bearing outcome — bounds the program.
- **PARTIAL:** incremental ΔR² CI excludes 0 but the directional fraud check fails (ρ vs ΔG_anti includes 0). The predictor is gaining nominal R² by improving the symmetric baseline, not by recovering directional structure — descope the headline.

### Sub-hypotheses (sidecar reads, not gates)

- Within-type vs cross-type closeness panel.
- Saturation pattern across the four 16×16 blocks: ICL×ICL likely most saturated, instr×instr least.

## 4. Design

### Smoke-architecture parity (UNIFIED — the default)

Dispatcher `scripts/issue524_dispatch.py` runs in-process serial with `--cells 1 --seeds 1 --phase {0,1,2,3}` for smoke and `--cells 32 --seeds 1 --phase all` for sweep. Both modes call the same `train_one_icl_cell(cid, ...)` and `eval_cell(src_cid, tgt_cid, ...)` functions; no subprocess wrapper. Smoke runs ONE ICL cell end-to-end (train → cross-eval against 4 representative targets at 500 Q → extract clouds → predictor → metric) using the exact code path the full sweep uses. Task #397 round-11 unification pattern. **Per-cell Q-count is the SAME in smoke and sweep** (500 Q) — smoke verifies the wall-time per cell at production Q-count, not at a reduced one, so the Phase 2 budget projection is calibratable from the smoke result.

**Why code, not a model call?** — The predictor matrices, ΔG matrices, nested-CV scoring, bootstrap, and Tobit fit are deterministic numpy / scikit-learn computations on activation clouds and log-probabilities. A model-call formulation would (a) be vastly more expensive at N=992 ordered pairs × 32 contexts × 28 layers × 9 metrics × 2 extraction points, (b) not produce calibrated CIs from bootstrap, and (c) lose interpretability of the directional functional. The ICL induction-rate manipulation check IS a model call (Sonnet-judged), per §"Phase 0.3".

def directional_gauss_kl(mu_A, Sig_A, mu_B, Sig_B):  # asymmetric
    return 0.5 * (np.trace(np.linalg.solve(Sig_B, Sig_A))
                  + (mu_B - mu_A).T @ np.linalg.solve(Sig_B, mu_B - mu_A)
                  - mu_A.shape[0]
                  + np.log(np.linalg.det(Sig_B) / np.linalg.det(Sig_A)))

def source_cov_mahalanobis(mu_A, Sig_A, mu_B):  # asymmetric on Σ_A
    diff = mu_B - mu_A
    return diff @ np.linalg.solve(Sig_A, diff)

def asym_subspace_recon(P_A_k, Phi_B):  # asymmetric on rank-k subspace of A
    return np.linalg.norm(P_A_k @ Phi_B) / np.linalg.norm(Phi_B)

def marker_projection(act_A, marker_unembed_dir):  # plain
    return act_A @ marker_unembed_dir / np.linalg.norm(act_A)

def two_feature_combiner(f_geom, f_marker, dg):  # OLS fit
    return ols_fit(dg, [f_geom, f_marker, f_geom * f_marker])
