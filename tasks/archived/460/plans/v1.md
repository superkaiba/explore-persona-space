<h1>Plan v2 — Issue #460</h1>
<p><em>Re-measure #406's transfer outcome as a continuous marker log-prob instead of the binary emission rate, to (a) fix the 52% zero-inflation that flattened the divergence-vs-transfer correlation and (b) test whether divergence predicts <strong>graded</strong> transfer strength, not just the on/off threshold the emission rate showed.</em></p>
<p style="background: #f0f4ff; border-left: 4px solid #5070d0; padding: .6rem 1rem; font-size: .92rem;"><strong>v2 changes vs v1 (Alternatives-critic REVISE).</strong> Adds the base-model-prior placebo (<code>B_logprob[j]</code> = base-model log P(※ | T_j), 16 × 50 = 800 forwards, ~30 s on the same engine) and the <strong>adapter-shift delta DV</strong> <code>ΔG_logprob[i,j] = G_logprob[i,j] − B_logprob[j]</code> as a co-primary analysis alongside the raw <code>G_logprob</code>. Pre-registers reading all three side-by-side (raw / placebo / delta) so prior-vs-adapter contribution is visible. Adds an HF <code>snapshot_download</code> fallback inside the Q_test + Class-D loaders (the input data files are gitignored; HF data repo <code>superkaiba1/explore-persona-space-data</code> at <code>issue406_divergence_predicts_transfer/training_data/</code> is the canonical source). Folds 6 analyzer-concerns into §6 (winsorized DV, 115-non-zero ρ separation, zero-cohort bimodality / Hartigan dip, H4 drift histogram, diagonal logp-vs-emission rank consistency, H2 asymmetric-interpretability + ~61% power flag). No design change, no new conditions, no hypothesis flips — the vLLM <code>prompt_logprobs</code> measurement, the H4 hard-gate, and single-variable inheritance from #406 are unchanged.</p>

<section class="plan-tldr">
<h2>0.0 TL;DR (plain English)</h2>
<ul>
<li><span class="lbl">What I'll run:</span> I'm reopening last week's experiment that asked "if I teach a model to add a special symbol in one persona, will it carry the habit over to another persona — and can I predict that from the model's behavior <em>before</em> any training?" The first pass scored each transfer as a yes/no flip: does the model write the symbol, or not. On more than half the 240 persona pairs that yes/no came back "no," and that wall of zeros hid most of the variation I cared about. This time I keep all 16 already-trained models and ask a softer question of each pair: not "did the symbol appear," but "how willing is the model to write it." Same data, same conditions, finer-grained outcome. No retraining, no new persona work — just a different measurement on the existing model copies.</li>
<li><span class="lbl">What I expect:</span> A cleaner version of the same story. The correlation between the predictor I locked in (how much two contexts disagree in the base model) and the new graded outcome should be at least as strong as the old yes/no version, and probably noticeably stronger in the half of pairs where the yes/no was stuck at zero. The middle-of-the-network similarity measure (the surprise hero last time) should still beat my locked-in predictor, but with a tighter gap.</li>
<li><span class="lbl">What would change my mind:</span> If the graded measurement gives the <em>same</em> correlation as the yes/no version, then last week's relationship really is about the firing threshold and not about graded strength — interesting but a narrower claim. If the graded measurement gives a <em>weaker</em> correlation, the original signal was about whether the model crosses the emission line at all, and a continuous willingness is the wrong DV. Either of those would meaningfully reframe what #406 actually showed.</li>
</ul>

<h2>0. Plan Summary (technical)</h2>
<p><span class="lbl">Re-eval (no training):</span> Reload #406's 16 trained LoRA adapters (Qwen-2.5-7B-Instruct, r=32 α=64, lr=1e-5, 3 epochs) from HF model repo. Define the <strong>adapter-shift delta DV</strong> <code>ΔG_logprob[i,j] = G_logprob[i,j] − B_logprob[j]</code> — this isolates the adapter-induced shift in marker willingness from the base prior's own preference for ※ under each T_j.
<span class="lbl">Hyperparameters:</span> No training. Inference dtype=bf16 (<code>Source: #406 Phase 3</code>); vLLM <code>prompt_logprobs=1</code> on the appended marker token with <code>SamplingParams(max_tokens=1, temperature=0.0, logprobs=1, prompt_logprobs=1)</code> (<code>Source: #355 plan-fact-check v1 confirming the vLLM 0.11.0 API surface</code>); LoRA loading via <code>vllm.lora.request.LoRARequest</code> with <code>enable_lora=True, max_loras=1, max_lora_rank=32</code> (<code>Source: #406 <code>i406_phase3_cross_eval.py</code> verbatim</code>); aggregation = mean of log-probs over 50 probes per cell (<code>Source: #406 phase1 K=25-mean log-prob aggregation</code>); numerical floor <code>logprob_min = -50.0</code> (defensive guard).

<span class="lbl">Loss surface:</span> N/A — no training. The eval reads probabilities at one teacher-forced position per (model, prompt) — the same position the emission rate thresholded.
<span class="lbl">Compute:</span> 1× H100 (<code>eval</code> intent). 16 adapters × 800 prompts × 1 forward = 12,800 forwards <strong>+ 1 base pass × 800 prompts = 13,600 forwards total</strong>. <h2>1. Goal</h2>
<p>Re-measure the outcome DV of #406's 240-pair divergence-predicts-transfer experiment as a <em>continuous</em> teacher-forced log-prob of the marker token at the first response-token position, replacing the binary "does ` ※` appear as the first sampled token" emission rate. The motivating problem: 125 of #406's 240 off-diagonal cells (52.1%) returned emission rate exactly zero, compressing the bottom half of the DV to a single floor value and almost certainly throttling the rank correlation with the divergence predictor D. A continuous DV lets two cells whose model is "barely won't emit" vs "categorically won't emit" separate. The headline finding becomes one of three things: (a) the same ρ (the underlying relationship really is on/off and the zero-inflation didn't matter), (b) a stronger ρ (zero-inflation was hiding graded variance, the divergence-transfer relationship is graded too), or (c) a weaker ρ (the original signal was about crossing an emission threshold and graded log-prob is the wrong construct). Resolving this directly informs whether #406's "MODERATE confidence" claim is on a binary-only phenomenon or a graded one — a precondition for any downstream geometry-predicts-behavior paper claim built on this rig.</p>

<h2>3. Hypothesis</h2>
<p><strong>v2 framing change.</strong> The construct the Goal cares about is the <em>adapter-induced</em> shift in marker willingness, not the total log-prob (which mixes adapter shift + base-model prior). v2 promotes <strong>two co-primary DVs read side-by-side</strong> — raw <code>G_logprob</code> AND adapter-shift <code>ΔG_logprob = G_logprob − B_logprob</code> — plus a <strong>placebo</strong> regression ρ(<code>B_logprob</code>, D) that diagnoses how much of the raw correlation was the base prior. The hypothesis set updates to test both DVs against the same thresholds.</p>
<p><strong>H1-raw (headline-A, falsifiable):</strong> Length-partial Spearman ρ(<code>G_logprob</code>, D | log_prompt_tokens) over 240 off-diagonal pairs has absolute value ≥ 0.45 — at minimum matching #406's |ρ_KL| = 0.436 on the binary DV. Direction: negative.</p>
<p><strong>H1-delta (headline-B, the construct H1 actually claims):</strong> Length-partial Spearman ρ(<code>ΔG_logprob</code>, D | log_prompt_tokens) over 240 pairs has absolute value ≥ 0.45 AND retains the negative direction. ΔG_logprob isolates the adapter-induced shift; a strong H1-delta is the cleanest evidence the divergence-predicts-<em>transfer</em> claim survives when you subtract out the base-prior baseline.</p>
<p><strong>H1-placebo (interpretive lens, no PASS/FAIL — diagnostic):</strong> Length-partial Spearman ρ(<code>B_logprob</code>, D | log_prompt_tokens) over 240 pairs. This is the base prior's <em>own</em> correlation with D — if it's near zero (|ρ| &lt; 0.15), then H1-raw ≈ H1-delta and the headline can stay on raw; if |ρ| &gt; 0.30, the prior is doing meaningful work and the honest headline becomes H1-delta. Pre-registered as a diagnostic; the analyzer reads all three (raw, delta, placebo) side-by-side and writes the interpretation rule into the clean-result.</p>
<p><strong>H2-raw (zero-inflation rescue on raw DV):</strong> Restrict to the 125 cells where #406's emission rate was exactly 0; length-partial ρ(<code>G_logprob</code>, D | log_prompt_tokens) absolute value ≥ 0.20.</p>
<p><strong>H2-delta (zero-inflation rescue on adapter-shift DV — the scientifically clean version):</strong> Same restriction; length-partial ρ(<code>ΔG_logprob</code>, D | log_prompt_tokens) absolute value ≥ 0.20. A PASS here is the strongest evidence the divergence-transfer relationship is genuinely GRADED at the adapter level (the adapter's contribution to willingness varies with divergence even on cells where actual emission never fires). A FAIL on H2-delta WHILE H2-raw PASSes means the zero-cohort graded signal was driven by base-prior structure correlating with D, not by graded adapter transfer.</p>
<p><strong>H2 interpretation asymmetry (NEW, flagged explicitly):</strong> H2 is asymmetric in what its outcomes mean. PASS on H2-delta is a strong claim: graded adapter-driven transfer survives the censoring. FAIL on H2-delta is WEAK evidence for "threshold-only": the zero cohort is by construction the cohort where the adapter pushed least, so the remaining variance is small and the test has reduced power. Specifically, with N=125 and an assumed cluster-design effect, the test has ~61% power at true |ρ|=0.20 (computed from <code>statsmodels.stats.power</code> on a Spearman rank test with N=125, two-sided α=0.05; the cluster CDE inflates SE which further drops effective power). A returned |ρ| in the 0.10–0.20 ambiguous band is FLAGGED in the analyzer write-up as "underpowered FAIL — graded adapter transfer cannot be confirmed OR ruled out at this N."</p>
<p><strong>H3 (layer-11 cosine retains ranking):</strong> Layer-11 residual-stream cosine still beats forward-KL on EITHER continuous DV with |ρ| ≥ 0.65 (vs −0.709 on the binary DV). Computed on both raw and delta. A drop below 0.50 on both would suggest the layer-11 advantage was specific to the binary-emission geometry.</p>
<p><strong>H4 (within-run rig sanity — mandatory gate, UNCHANGED from v1):</strong> The free within-run recomputation of binary emission rate (argmax at the same teacher-forced position) reproduces <code>G_matrix.json</code> to within 0.02 absolute on every one of the 256 cells. If H4 FAILs, the analysis is void and the run posts <code>epm:failure v1, failure_class: code, reason: rig_does_not_reproduce_parent_binary</code>.</p>

<h3>4.2 The core measurement (nail this — adversarial-grade)</h3>
<p><strong>Per cell (i, j):</strong></p>
<pre>for q in Q_test (50 questions):
    prompt_text = build_prompt_for_condition(cond_j, q, tokenizer, class_d_rewrites=...)
    prompt_ids  = tokenizer.encode(prompt_text, add_special_tokens=False)
    full_ids    = prompt_ids + [MARKER_ID]   # MARKER_ID = 83399, single token id ' ※'
    # vLLM batched call below — see §4.4 for the actual API shape; this pseudocode shows
    # the per-prompt logic so the position semantics are unambiguous.
    out = llm.generate(prompts=[full_text], sampling_params=sp, lora_request=lora_req)
    # SamplingParams(max_tokens=1, prompt_logprobs=1, logprobs=1, temperature=0.0)
    logp_marker_at_pos = out.prompt_logprobs[len(prompt_ids)][MARKER_ID].logprob
G_logprob[i, j] = mean over q of logp_marker_at_pos        # mean log-prob, primary
G_prob[i, j]    = log(mean over q of exp(logp_marker_at_pos))  # log of mean prob, free secondary
</pre>

<p><strong>Why this is correct (position semantics):</strong></p>
<ul>
<li><code>prompt_ids</code> has length <em>L</em>; the appended marker token sits at index <em>L</em> in <code>full_ids</code>.</li>
<li>vLLM's <code>prompt_logprobs[k]</code> returns the log-prob of <code>full_ids[k]</code> given <code>full_ids[:k]</code>. So <code>prompt_logprobs[L]</code> is exactly <strong>log P(MARKER_ID | prompt_ids)</strong> — what we want.</li>
<li>This is the same teacher-forced position that #406's <code>i406_phase3_cross_eval.py</code> thresholded on. The greedy <code>first_token_ids[0]</code> in the emission rig is <code>argmax over v of log P(v | prompt_ids)</code> at exactly the same slot. So our continuous DV and the binary DV ARE measuring the same conditional distribution — the only difference is binary-threshold (emission rate) vs raw value (log-prob).</li>
<li>vLLM's <code>prompt_logprobs[0]</code> is <code>None</code> by API contract (no preceding context for the first token); index 0 is the BOS-equivalent. We never read index 0.</li>
</ul>

<p><strong>MANDATORY off-by-one guard (executed in Phase 1 smoke and Phase 2 sweep, fails LOUD):</strong></p>
<pre>
# Diagonal cells (i == j): for each Q_test where #406 emission rate was 1
# (so the model is known to argmax → 83399 at this slot), confirm:
#   argmax_v prompt_logprobs[len(prompt_ids)][v] == MARKER_ID
# This proves we are reading the same slot the emission rate thresholded on.
# At least 1 diagonal cell × 1 high-G probe must pass before the sweep starts.
assert argmax_token_id_at_pos == MARKER_ID, (
    f"Off-by-one or wrong-position read: argmax at L={len(prompt_ids)} is "
    f"{argmax_token_id_at_pos} but #406 emission says 83399. Refusing to proceed."
)
</pre>

<p><strong>Aggregation choice (pre-registered, NOT post-hoc selectable — v2 adds a third look):</strong></p>
<ul>
<li><strong>Primary:</strong> mean of log-probs over the 50 Q_test probes per cell — symmetric in log-space, the same shape #406 used for D (K=25-mean log-prob averaging). Reports as <code>G_logprob[i, j]</code> (adapter) and <code>B_logprob[j]</code> (base pass).</li>
<li><strong>Free secondary (full distribution):</strong> log of mean prob over the 50 probes. Reports as <code>G_prob[i, j]</code>.</li>
<li><strong>v2 — robust aggregation (third look):</strong> 10%-trimmed mean of per-probe log-prob (drops the lowest 5% AND highest 5%), reported as <code>G_logprob_trimmed[i, j]</code>. Motivation: one floored probe (−50 nats) can dominate a 50-element mean; the trimmed mean is a sanity check that the headline isn't a tail artifact. Pre-registered as a sensitivity DV; the analyzer reports ρ on raw / delta / trimmed-delta side-by-side.</li>
<li><strong>Numerical floor:</strong> <code>logp = max(logp, -50.0)</code> on read (defensive — vLLM emits real log-probs ~−20 nats, but adapter swaps occasionally underflow). Per-cell payload records <code>n_clamped_to_floor</code> AND per-cell per-probe min/max log-prob range. If &gt; 1% of cells get clamped, post <code>epm:failure v1, failure_class: data, reason: log_prob_underflow_widespread</code>.</li>
</ul>

<p><strong>v2 — adapter-shift delta DV (definition):</strong></p>
<pre>
# After Phase 2a (base pass) and Phase 2b (adapter sweep) complete:
B_logprob[j] = mean over q of base_logp[j, q]                # 16-vector, base model
G_logprob[i, j] = mean over q of adapter_logp[i, j, q]       # 16x16, adapter
DeltaG_logprob[i, j] = G_logprob[i, j] - B_logprob[j]        # 16x16, adapter-induced shift

# Per-probe-aligned delta (used for the per-probe-range / bimodality checks):
delta_per_probe[i, j, q] = adapter_logp[i, j, q] - base_logp[j, q]
DeltaG_logprob_per_probe_mean[i, j] = mean over q of delta_per_probe[i, j, q]
# Note: DeltaG_logprob_per_probe_mean ≡ DeltaG_logprob by linearity of expectation.
# Per-probe deltas matter for the H2-delta dispersion + bimodality checks (§6.4).
</pre>

<h3>4.4 vLLM API choice — <code>prompt_logprobs</code> vs HF teacher-forced (picked AND justified)</h3>
<p><strong>Picked: vLLM <code>prompt_logprobs=1</code>.</strong></p>
<ul>
<li><strong>Why vLLM:</strong> #406 Phase 3 already uses vLLM with LoRARequest swapping for the EXACT same per-cell shape (16 outer adapters × 16 inner conditions × 50 probes), at ~9 min total wall time for the binary version. Reusing the same engine + LoRA swap pattern is the obvious low-risk path. CLAUDE.md mandates vLLM for eval generation.</li>
<li><strong>Why <code>prompt_logprobs=1</code> (not HF forward):</strong> HF forward-pass (the #406 Phase 1 pattern) requires reloading the LoRA adapter into a fresh <code>PeftModel</code> per outer condition, which is ~20× slower per cell than vLLM's hot-swap. The vLLM path is correct for our needs because we are NOT capturing residual-stream activations (already done in #406 Phase 1); we only need a single log-prob scalar per (model, prompt). <code>prompt_logprobs=1</code> is the documented API for this: at each prompt position, vLLM returns the top-1 log-prob AND the actual-token log-prob (so we always get the marker log-prob, even if marker is not top-1).</li>
<li><strong>Why <code>max_tokens=1</code> (not 0):</strong> vLLM 0.11.0 requires <code>max_tokens ≥ 1</code> in <code>SamplingParams</code>. We read <code>out.prompt_logprobs[L]</code> regardless of the generated token; the generated token is unused (we throw it away). Sets <code>logprobs=1</code> to avoid the generated-token logprobs slot being None (purely defensive — does not affect the DV).</li>
<li><strong>Why pass <code>prompt_token_ids</code> directly (not the string):</strong> #406's Phase 1 MF-1 fix flagged that <code>tokenizer.decode(prompt_ids + [MARKER_ID])</code> followed by re-encode can re-segment BPE boundaries (the leading-space marker is exactly the class of token vulnerable to this). vLLM accepts <code>{"prompt_token_ids": [...]}</code> in <code>llm.generate()</code> per the documented API — we use it for byte-exact safety.</li>
</ul>

<p><strong>Why code, not a model call?</strong> The DV is a deterministic log-prob extraction at a fixed slot — no unstructured-data parsing involved. There is no candidate single-Claude-call formulation; this is a pure numerical readout from a tensor.</p>

<h3>4.5 Smoke/sweep architectural parity (unification default)</h3>
<p>Smoke phase IS sweep with <code>--cids A1</code>: same dispatcher (<code>i460_logprob_eval.py</code>), same vLLM bring-up, same per-cell write, same H4 hard-gate. <strong>v2: smoke ALSO runs Phase 2a base pass by default</strong> (one engine bring-up, 16 base T_j × 50 = 800 base forwards + 1 outer × 16 × 50 = 800 adapter forwards). The smoke step exercises the full per-cell read path on the A1 row AND the base-pass code path AND the HF-fallback loader code path (if local data files are absent, smoke is the first place the loader fetches them). If H4 hard-gate FAILs in smoke, the sweep is blocked. Per CLAUDE.md Step 6d.0 + task #397's lesson, this avoids the "smoke is in-process, sweep is subprocess" divergence class.</p>

<p><strong>v2 — smoke success criteria (all must PASS before the full sweep launches):</strong></p>
<ul>
<li>H4 per-cell drift ≤ 0.02 on every A1-row cell (16 cells).</li>
<li>Diagonal A1→A1 mean log-prob &gt; −5 nats (#406 emission rate 0.90 implies model is highly willing).</li>
