## 3. Requirement + Acceptance Criteria (infra analogue of hypothesis)

**Requirement.** For every inline figure URL in a clean-result body that (a) matches `_RAW_GITHUB_FIGURE_RE` AND (b) points at this repo (`_THIS_REPO_SLUG`), the new check resolves the sidecar `*.meta.json` at the URL's SHA and:

- **FAIL** when the sidecar resolves, carries a `commit` (or alias) field, and that field's SHA is NOT prefix-compatible with the body URL's SHA. FAIL message names the basename + both SHAs + an actionable pointer.
- **SKIP (contributes nothing, never FAIL)** when: the sidecar does not resolve at the URL SHA (defer to Check 26 for a resolvable-PNG-missing-sidecar FAIL, and Check 22 for an unresolvable-SHA); OR the sidecar resolves but carries no recognized commit field; OR the URL is not a same-repo raw-GitHub URL.
- **PASS** when every compared figure's sidecar `commit` is prefix-compatible with its body URL SHA.
- **NO-OP PASS** when the body has no inline figure URLs, or the repo is unresolvable (offline / `--body-stdin`).

**Falsifiable acceptance criteria (verifiable behavior):**

1. On a synthetic body whose figure URL SHA equals the sidecar `commit` (prefix-compatible), the check PASSes.
2. On a synthetic body reproducing the #761 drift (URL SHA `c969f2281f…` vs sidecar `commit: 3f5d228398`), the check FAILs, and the FAIL detail names the basename and both SHAs.
3. On a body whose figure has NO sidecar at the cited SHA, the new check contributes no FAIL (SKIP).
4. On a body whose sidecar resolves but has no `commit` field, the new check SKIPs (no false-FAIL).
5. On a sidecar using an alias key (`git_commit` / `git_sha`) with a compatible SHA, the check PASSes; with an incompatible SHA, FAILs.
6. On a body with two figures — one matching, one drifting — the check FAILs and reports only the drifting figure.
7. On a v4/v3/v2 body with no inline figure URLs, the check NO-OP-PASSes.
8. Existing Check 22/24/26 assertions in the current test file remain green (invariant).

### New commit-key constant

The sidecar canonical field is `commit` (confirmed: 40/40 committed sidecars sampled use exactly `commit`, a 9-char short SHA, e.g. `figures/issue_541/*.meta.json` = `"commit": "96aa37180"`). `_META_PROVENANCE_KEYS` also recognizes `git_commit` and `git_sha` as commit aliases. Introduce a dedicated ordered tuple so the new check reads the commit field robustly without over-reaching into non-commit provenance keys (timestamps, platform, argv):

```python
# ─── Check 27: figure sidecar `commit` vs body-URL SHA (commit drift) ────────
#
# The per-figure `.meta.json` records the commit its figure was generated at.
# The body inlines the figure as a raw-GitHub URL SHA-pinned to a commit. Those
# two SHAs can drift (a figure regenerated + re-linked at a new commit while the
# sidecar keeps the old `commit`, or vice versa). Check 22 compares the URL vs
# the `## Reproducibility` PROSE claim; Check 24 reads the sidecar but SKIPS
# `commit` (provenance). Neither compares the sidecar `commit` to the URL SHA.
# Ordered so the canonical `commit` wins over an alias when both are present.
_META_COMMIT_KEYS: tuple[str, ...] = ("commit", "git_commit", "git_sha")


def _sidecar_commit(meta: dict) -> str | None:
    """Return the first hex-SHA-shaped commit value under a recognized commit
    key in a parsed sidecar dict, or None when none is present / usable.
    Only accepts a 7-40 hex string (a real short/full SHA) so a non-SHA
    provenance value never triggers a spurious compare."""
    for key in _META_COMMIT_KEYS:
        v = meta.get(key)
        if isinstance(v, str) and re.fullmatch(r"[0-9a-fA-F]{7,40}", v.strip()):
            return v.strip()
    return None
```

### New check function skeleton (~25 lines)

Modeled on Check 26's `check_figure_panel_prose_vs_sidecar` (`scripts/verify_task_body.py:5270`) — same iterate-inline-URLs / same-repo-gate / resolve-by-stem / cache pattern; simpler because there is no prose window to scope.

```python
def check_figure_meta_commit_matches_url(body: str) -> CheckResult:
    """Check 27 (FAIL): each figure's sidecar `.meta.json` `commit` (or a
    `git_commit`/`git_sha` alias) must be prefix-compatible with the commit SHA
    embedded in the body's raw-GitHub URL for that same figure.

    A figure is inlined as a SHA-pinned raw-GitHub URL and its sibling
    `<basename>.meta.json` records the `commit` it was generated at. Across
    follow-up rounds those drift: a figure regenerated + re-linked at a new
    commit while the sidecar keeps the stale `commit` (or vice versa). The
    image still renders (check 4b probes the URL's OWN sha) and every other
    gate passes, so the body ships with a sidecar `commit` pointing at a
    different commit than the inline URL — a recurring, mechanizable defect
    (worked example #761 r2: URL `c969f2281f…` vs sidecar `commit: 3f5d228398`;
    only `c969f2281f…` carried the figure blob, yet both mechanical gates
    passed).

    Reads each same-repo sidecar strictly by URL stem from the git tree at the
    URL's commit sha (`_read_figure_meta_json`, worktree-safe). SKIP semantics:
    - sidecar does NOT resolve at the URL sha → SKIP (check 26 owns the
      resolvable-PNG / missing-sidecar FAIL; check 22 owns the unresolvable
      sha) — never double-report;
    - sidecar resolves but carries no recognized commit field → SKIP (not every
      figure sidecar records a commit);
    - URL is not a same-repo raw-GitHub figure URL → SKIP.
    FAIL only when a sidecar commit resolves AND is prefix-INCOMPATIBLE with the
    URL sha. NO-OP PASS when the body has no inline figures or the repo is
    unresolvable (offline / --body-stdin). FAIL, never WARN.
    """
    label = "figure sidecar commit matches body URL sha"
    urls = _gather_figure_image_urls(body)
    if not urls:
        return CheckResult(label, True, "no inline figures to scan")
    repo = _resolve_repo_root()
    if repo is None:
        return CheckResult(label, True, "skipped — repo root unresolved (offline / stdin)")
    fails: list[str] = []
    checked = 0
    json_cache: dict[str, dict | None] = {}
    for raw in urls:
        url = raw.strip().split(None, 1)[0] if raw.strip() else ""
        m = _RAW_GITHUB_FIGURE_RE.match(url)
        if m is None or (m.group("owner").lower(), m.group("repo").lower()) != _THIS_REPO_SLUG:
            continue  # only same-repo sha-pinned figures resolve from git
        url_sha = m.group("sha")
        path = m.group("path")
        if url not in json_cache:
            json_cache[url] = _read_figure_meta_json(repo, url_sha, path)
        meta = json_cache[url]
        if meta is None:
            continue  # sidecar absent / sha unresolvable — checks 26 / 22 own it
        commit = _sidecar_commit(meta)
        if commit is None:
            continue  # sidecar records no commit — nothing to compare
        checked += 1
        if not _shas_compatible(url_sha, commit):
            basename = path.rsplit("/", 1)[-1]
            fails.append(
                f"`{basename}`: body URL pins commit `{url_sha[:9]}` but the sidecar "
                f"`{basename.rsplit('.', 1)[0]}.meta.json` records `commit` `{commit[:9]}` "
                "— regenerate the figure at the URL commit or repin the URL so both agree"
            )
    if fails:
        preview = "; ".join(fails[:3]) + (" …" if len(fails) > 3 else "")
        return CheckResult(
            label, False, f"{len(fails)} figure(s) with a sidecar-commit / URL-sha drift: {preview}"
        )
    if checked == 0:
        return CheckResult(label, True, "no same-repo figure sidecar records a commit to compare")
    return CheckResult(label, True, f"{checked} figure sidecar commit(s) match their body URL sha")
```
