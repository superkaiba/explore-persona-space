## 0.0 TL;DR (plain English)

- **What I'll run:** I take the answers a base model already wrote under 50 different "characters" (personas/contexts) when asked the sycophancy, refusal, and harmful-request questions. I read out the model's internal state while it re-reads each of those exact answers, then check whether that internal state predicts how often each character actually does the behavior. The fix here is that I use the same set of questions on both sides. The parent experiment used one question set to read the internal state and a different one to score the behavior, so it was comparing apples to oranges.
- **What I expect:** Once the internal-state summary and the behavior rate come from the same questions, the predictor should read at least as well as it did in the parent, and probably better. In the parent the question mismatch was diluting the signal.
- **What would change my mind:** Suppose matching the questions does not lift the prediction for any of the three behaviors, and the internal-state-vs-behavior link stays just as weak. That would tell me the parent's weak read was never about the mismatch. The mean internal state simply doesn't carry these behaviors, and the right move would be to question the quantity itself rather than the measurement.

## 1. Goal

Re-measure how well base-model mean answer activation v0(C) predicts behavioral expression E0(C,B) with the activation summary AND the judged-expression target computed over the SAME per-behavior probe set (≥50 judgments/context), removing #658's probe-distribution mismatch and 8-judgment noise floor; phase 1 = the 3 behaviors with existing ≥50-probe completions+judgments (sycophancy/refusal/harmful_compliance), capture-only matched v0, ridge v0(C,B)→E0(C,B) LOCO per #742 recipe vs #658 mismatched ridge + diff-in-means.

In one sentence: #658 reported that a mean answer-side activation summarizes only 3 of 10 behaviors and NONE of the 4 with a working linear read-out (broad misalignment, harmful compliance, sycophancy, refusal). But in #658, `v0(C)` was averaged over a single 48-probe Betley pool for ALL behaviors, while `E0(C,B)` was judged over behavior-specific batteries — so the ridge correlated an activation summary over one probe distribution against expression measured over a different one. This task removes that mismatch for the 3 behaviors that already have ≥50 behavior-specific probes + completions + judgments, capturing `v0(C,B)` over those SAME probes, then re-reading the #742 ridge predictor. It directly serves `q:leak-predictor` (open question 3.1): whether any base-model-readable quantity predicts where a fine-tuned behavior leaks.

### Literature

- **Persona Vectors** (Chen, Arditi, Sleight, Evans, Lindsey — Anthropic, 2025, arXiv 2507.21509). Identifies activation-space directions for traits (evil, sycophancy, hallucination) and shows finetuning-induced personality shifts correlate with shifts along those directions; persona vectors flag training data that will produce undesirable shifts. The relevant transfer: their direction is a **response-averaged residual-stream activation** difference, and their predictor regime sweeps all layers and selects by target predictivity (their A3.3 `E ≈ r_Bᵀ v`). #761's `v0(C,B)` IS a response-averaged (answer-token-mean) residual activation, and the analysis IS the predictor regime — sweep all 28 layers, select by held-out predictivity. (NOTE: #761 does NOT extract a diff-of-means persona-vector *direction*; `v0(C,B)` is the predictor INPUT summary, and the ridge learns the read-out. See §4 "Why this is not a persona-vectors extraction.")
- **Persona Features Control Emergent Misalignment** (Wang, …, Mossing — OpenAI, 2025, arXiv 2506.19823). Uses model-diffing / SAE features to find a "misaligned persona" feature in activation space that **predicts whether a model will exhibit emergent misalignment**. This is the same predictor framing: read a behavioral propensity out of base-model-readable activation structure. #761 + #658 are the open-weights Qwen2.5-7B analogue of that predictor link — with the comparative advantage (USER.md) that Qwen is open-weights, so full activation capture over a 50-context battery is available where the sibling papers used GPT-4o.
- **Base-model activation probing as a behavioral predictor** — the project's persona-distance line (#404/#458/#444/#500) established that a base-model-readable quantity (teacher-referenced cosine/JS, the bystander's base prior) predicts leakage with behavior-dependent sign; the mean-answer-activation summary is a different (and simpler) candidate readable. The reliability-ceiling / attenuation framing (Spearman 1904 attenuation identity; Schoppe 2016 noise ceiling) bounds what ANY decoder can reach against a noisy judged target, and #742's literature review (verified) establishes that at n=50 the bracket is the honest object, not a point estimate of information loss.

## 3. Hypothesis

**H1 (one-sided, the headline).** For each of the 3 behaviors, the matched-probe ridge held-out Spearman ρ_matched ≥ ρ_mismatched (the #658 mismatched-probe ridge), i.e. the probe mismatch attenuated the read.

- **Headline statistic:** per behavior, **Δρ = ρ_matched − ρ_mismatched** with a cluster-bootstrap-over-contexts 95% CI (B=2000, cluster by context). A positive Δρ whose CI excludes 0 confirms the mismatch attenuated the read for that behavior.
- **Secondary:** the matched ρ vs the per-behavior reliability ceiling √(r_yy) (the bracket [ρ_matched, √(r_yy)]). Where ρ_matched approaches √(r_yy), the matched read is ceiling-limited (the mean activation summarizes that behavior as well as the noisy target allows).

**Kill criterion (falsifies H1).** Matched ρ_matched is within 1 cluster-bootstrap CI of the mismatched ρ_mismatched **across all 3 behaviors** (Δρ CI straddles 0 for every behavior) → the mismatch was NOT the bottleneck. Reading: matching the probe set does not recover the signal; #658's weak mean-activation summary for these behaviors is a property of the representation (or of the n=50 reliability ceiling), not a measurement artifact. This is a real, reportable outcome.

**What "the headline holds" means for `q:leak-predictor`.** If matched ρ ≥ mismatched ρ and rises toward the ceiling for these 3 behaviors, then the mean answer-side activation DOES predict behavioral expression once the probe distribution is matched — refining #658's "summarizes only 3/10" headline by showing that ≥1 of the 4 read-out behaviors crosses into "predictable" under matched probes. If it stays flat, #658's headline stands for these behaviors even after the confound is removed (a stronger negative).

## 4. Design

**Single manipulated variable vs #658/#742:** the probe set the activation summary `v0` is averaged over — matched to each behavior's own judged probes, instead of the single shared 48-probe Betley pool. Everything else (base model, contexts, capture mechanism, ridge recipe, E0 target, bootstrap, null) is inherited.

### 4.1 Conditions

3 behaviors × 50 contexts. The per-behavior matched-probe count is the **judged probe set** (the `E0.per_probe` list), verified this session:

|---|---|---|---|---|
| sycophancy | 200 | 200 (all) | 10 (temp 0.7) | 200 × 50 = 10,000 |
| refusal | 250 | 214 (36 dropped at judging) | 1 (temp 0.0) | 214 × 50 = 10,700 |
| harmful_compliance | 150 | 115 (35 dropped at judging) | 1 (temp 0.0) | 115 × 50 = 5,750 |

Total ≈ **26,450 teacher-forced forwards** (recomputed from the verified judged-probe counts; the body's "~7.5k" assumed ~50 probes/behavior — the real judged pools are larger, which only IMPROVES the v0 mean estimate; the GPU estimate in §8 is sized to the true count). For sycophancy the capture is over the 200 distinct probes (the completion text per probe is the same construct; for the v0 mean I capture one completion per probe — the FIRST rollout's stored completion — to keep the activation summary a per-probe quantity matched to the per-probe judged rate; see §4.4 the rollout-handling rule).

**Matched-probe invariant (the whole point):** `v0(C,B)` is averaged over EXACTLY the probes in `E0[C][B].per_probe` (the judged set), joined on probe text (`judged ⊆ generated` verified TRUE for all 3 behaviors). This makes the activation summary and the target cover the identical probe distribution per (context, behavior) — the confound #658 had.

**Subsample / equalize-down policy.** The body says "subsample each behavior's probe pool to a fixed ≥50 if larger, recorded." Because the 3 behaviors are fit as **3 separate per-behavior ridge predictors** (NOT a pooled fit), the matched-N is naturally per-behavior (200 / 214 / 115); there is no cross-behavior dose to equalize on the v0 side (each behavior's v0 mean uses its own probes, and a larger probe pool only reduces the v0-mean's sampling noise — it does not bias the predictor). I therefore **keep the full judged probe set per behavior** (no subsampling) and RECORD the per-behavior matched-N in the artifact. The ≥50 floor is satisfied for all 3 (min 115). This is the graceful, no-information-discarded choice; subsampling to 50 would only inflate the v0-mean variance.

- **`BatchedAnswerSpanCapture`** (NEW): a `LayerCapture` whose hook keeps the FULL `(B, T, H)` per layer (not `(1,T,H)`), so one forward processes a left-padded batch of `(prompt+answer)` rows. For each row r, slice its answer span `[prompt_len_r, prompt_len_r+ans_len_r)` (per-row lengths tracked from the tokenizer; mean over its answer tokens at each layer) → `(n_layers, H)` per row, then probe-mean over the batch's rows into the running `v0(C,B)` accumulator. Left-padding + an attention mask so padding tokens never enter a row's answer span; the per-row position assert (captured span length == generated answer token count) is preserved per row. This is the ONE vectorization of `capture_v0_for_context`'s batch-1 loop — same math, batched.
- **The rollout-handling rule (sycophancy, 10 rollouts/probe).** The v0-mean is a **per-probe** quantity matched to the per-probe judged rate `E0.per_probe[*].e0`. I capture over the FIRST stored completion per probe (one teacher-forced answer per probe), giving a per-probe v0 that is matched 1:1 to the per-probe judged rate. (Capturing all 10 rollouts' completions and meaning them is an optional robustness variant recorded in the exploratory dump; the headline uses the first-rollout-per-probe capture so the v0-mean is over the same 200/214/115 probes as the target — keeping the matched-N exactly the judged-probe count.)

**Why code, not a model call?** This is numerical activation capture (forward hooks over frozen tensors) + closed-form statistical estimators (ridge LOCO, bootstrap, reliability decomposition). There is no unstructured-data classification/extraction step — the judging was already done in #658 and is reused verbatim (E0 is not re-judged). A model call has no role here. (The ONE model-call site in the sibling #742 — the Stage-0 judge-rerun variance term — is explicitly NOT in #761's scope: #761 reuses #658's E0 and √(r_yy) is computed from the already-judged per-probe structure; see §6 + §9 deviation rules.)

### 4.5 Vectorization scheme + memory back-of-envelope

- **Batch axis:** probes within one (context, behavior). The hook captures `(B, T, H)` at all 28 layers simultaneously per forward.
- **Memory:** Qwen2.5-7B bf16 weights ≈ 14 GB. Captured activations per forward = `28 layers × B × T × 3584 × 2 bytes` (fp16 at capture, per `AnswerSpanCapture`). For `B=16`, `T≈512` (prompt+answer; the #658 batteries + behavior probes run a few hundred tokens, capped): `28 × 16 × 512 × 3584 × 2 ≈ 1.6 GB` of captured residuals per forward, reduced to per-row `(28, H)` means immediately (the `(B,T,H)` buffer is freed per forward). Plus KV-cache/activations for the forward itself (~a few GB at this batch×seq). **Chosen batch = 16 probes/forward** (clears the ~80 GB A100 with wide margin; the `(B,T,H)` capture buffer is the binding term and at 1.6 GB it is comfortable). If a context's completions are unusually long (some sycophancy/harmful probes run long), the driver caps `T` and reduces B adaptively — the per-row answer-span assert catches any truncation. The activation buffer is moved to fp16 at capture and reduced to fp32 `(28,H)` means on CPU per row, so peak HBM stays bounded.
- **Throughput:** ~26,450 forwards / (16 probes/forward) ≈ 1,650 batched forwards; at this model size a batched forward is ~0.3–1 s on an A100 → ~10–30 min of pure forward compute. The §8 GPU estimate (12 GPU-h) carries generous headroom for model load, HF snapshot_download of 150 e0_gen files, padding overhead, and adaptive-batch retries.

## 6. Eval / Analysis (the #742 recipe applied to matched data)

All 0-GPU on the VM. Per behavior B ∈ {sycophancy, refusal, harmful_compliance}:

1. **Ridge `v0(C,B) → E0(C,B)` LOCO over the 50 contexts.** PCA-reduce `v0(C,B)` first (target `d_eff ≈ 10`, the #742 d_eff; the exact value carried from #742's power-floor selection — for the predictor read at n=50, d_eff≈10 is the inherited choice), then closed-form LOCO ridge with nested-CV λ over `{1e-2,1e-1,1,10,100,1e3}` (per held-out context, λ minimizes inner-LOO MSE — no λ leakage). `Source: #742 plan v9 / issue658_fit_predictors.py`.
2. **Layer sweep: all 28 layers.** Report held-out Spearman ρ per layer; **chosen layer = the held-out-predictivity-maximizing layer per behavior** (the predictor regime, per persona-vectors 2507.21509 A3.3 — NOT a single steering layer). Report the per-layer ρ curve for matched AND the #658 mismatched read overlaid.
3. **Held-out Spearman + cluster-bootstrap CI.** Per behavior: the held-out LOCO ρ at the chosen layer, with a 95% cluster-bootstrap CI (cluster by context, B=2000, seed 761). The headline Δρ = ρ_matched − ρ_mismatched gets its OWN cluster-bootstrap CI (paired where the contexts are shared, which they are — same 50 contexts).
4. **Null distributions.** (a) **Shuffle-label null** — refit the full ridge LOCO on randomly permuted E0 (context→rate reassignment, seeded), 1000 perms, → the right-tail p-value for the matched ρ. (b) **Control-task null (Hewitt-Liang 2019, arXiv:1909.03368)** — the #742 selectivity null: refit on shuffled E0 and require the matched read to BEAT its own shuffled-control read (the d≫n probe-memorization guard; mandatory because v0 is high-dim even after PCA). `Source: #742 plan v9 / arXiv:1909.03368`.
5. **Reliability-ceiling bracket √(r_yy) per behavior.** Computed from `E0.per_probe` (no judge re-run — #761 reuses #658's judgments). Two methods per the #742 recipe, forked on rollouts/probe:
   - sycophancy (10 rollouts/probe): **split-half-over-rollouts + Spearman-Brown** `r_yy = 2 r_half/(1+r_half)`, averaged over 200 split seeds, AND the binomial-variance decomposition `√(SP/Var_C(E0))` with cell-actual `m = n_judged`.
   - refusal / harmful_compliance (1 rollout/probe): **split-half-over-PROBES + Spearman-Brown** (rollouts can't be split), AND binomial-variance with cell-actual `m`.
   - CV-match the ceiling to LOCO (Storrs 2020); cluster-bootstrap the √(r_yy) CI (B=2000). `Source: #742 plan v9 / Spearman 1904 + Schoppe 2016 + Storrs 2020`.
   - **NOTE (deviation from #658's noise floor):** #658's `aggregate.json` `noise_floor.p95` is an 8-probe-redraw test-retest reliability with degenerate behaviors pinned to 1.0 — a sibling of √(r_yy), reported as a 2-method agreement check, NOT a substitute.
6. **Headline comparison table per behavior:** (1) **matched ρ_lin** (this task, chosen layer), (2) **mismatched ρ_lin** (#658, fitted-ridge AND diff-of-means projection columns — both reported since #742 found they diverge; the per-behavior best values live in `analyzer_body_data.json` at `/betley/a33/<beh>/lin_rho`, not the per-layer-cell `a33_cells.json` list), (3) **diff-in-means** `r_B` baseline (the #658 diff-of-means projection — same `/betley/a33/<beh>/lin_rho`), (4) **reliability ceiling √(r_yy)** (this task), (5) **Δρ = matched − mismatched** with CI, (6) shuffle-null p, (7) control-task verdict (selective / non-selective).

## 11. Decision Rationale — load-bearing choices

No training hyperparameters exist (base model, no LoRA, no loss). The load-bearing choices are the capture recipe and the analysis recipe; each is grounded.

- **Base model `Qwen/Qwen2.5-7B-Instruct`.** What: the only model. Why: the predictor program (#658/#742) is defined ON this model; matching it is the single-variable contract. Source: `#658` + `#742` (project standing default). Alternatives: none — changing the model would break the #658 comparison. (Repo-already-used model id — inherits #658/#742 validation; no fresh AutoConfig smoke needed. Verified config dims this session anyway: 28 layers / 3584 hidden.)
- **Answer-side MEAN residual over answer tokens, all 28 layers.** What: `v0(C,B)` = probe-mean of (answer-token-mean residual) per layer. Why: this IS the A3.2 summary recipe #658 tested and #742 analyzes — matching it isolates the probe-set change as the single variable; the persona-vectors paper (2507.21509) uses the same response-averaged activation. Source: `#658 plan A3.2` + `2507.21509`. Alternatives: `last`/`maxp` captured as robustness columns (not the headline — #658's headline recipe is `mean`).
- **Teacher-forced capture over stored completions.** What: re-feed (prompt+stored answer), capture the answer span. Why: the completions are #658's verbatim on-policy generations; teacher-forcing over them gives the exact answer-side activations the model produced, deterministically, with no re-generation. Source: `#658 G2 path (capture_v0_for_context)`. Alternatives: re-generate (would change the answer text + add GPU cost + break the matched-to-the-judged-completion invariant) — rejected.
- **Matched probe set = the JUDGED probes (`E0.per_probe`).** What: average v0 over exactly the probes that contributed to E0(C,B). Why: this is the entire point — the activation summary and the target must cover the SAME probe distribution; `judged ⊆ generated` verified, so the join is exact. Source: `#761 Goal` + verified `E0_expression.json` schema. Alternatives: average over ALL generated probes (would re-introduce a smaller mismatch for refusal/harmful where 36/35 probes were dropped at judging) — rejected.
- **Ridge LOCO: PCA-reduce v0 + nested-CV λ ∈ {1e-2,1e-1,1,10,100,1e3}.** What: the predictor. Why: inherited from #742 verbatim (the recipe is the constant; the data is the variable); the chat re-analysis showed a regularized ridge recovers signal the n=50 MLP overfit. Source: `#742 plan v9` / `issue658_fit_predictors.py RIDGE_LAMBDAS`. Alternatives: the n=50 MLP (overfits — #658's A3.2 failure was partly this) — rejected for the headline; reported only if #742 needs it.
- **PCA d_eff ≈ 10.** What: reduce v0 to ~10 dims before the ridge. Why: the #742 power-floor-selected dimension (Reddi 2015 + Stone 1982 + Varoquaux 2018 — restores estimator power at n=50). Source: `#742 plan v9`. Alternatives: full 3584-dim ridge (d≫n, probe-memorization risk the control-task null guards) — the PCA reduction is the inherited mitigation.
- **Layer selection: sweep all 28, choose by held-out predictivity.** What: per-behavior best layer.
