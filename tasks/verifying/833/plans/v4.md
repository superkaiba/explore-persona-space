## §0.0 Plain-English TL;DR

#722 concluded "fine-tuning reshapes the context→answer map only for a taught fact" — but it measured the trained model on answers the *base* model wrote. If fine-tuning mostly changes *what the model says* (which is what a behavior implant does), that comparison is blind by construction. This experiment regenerates the post-fine-tuning answer profiles from each trained model's **own** greedy answers (on-policy), re-runs the identical #722 fit machinery, and adds a matched-text control (teacher-force the new text through both models) so the total change per cell splits cleanly into "the weights process the same text differently" (representation change) vs "the model writes different text" (output-distribution change). The headline is the on-policy-vs-off-policy **delta** in the function-change reads. No training. No judge calls. ~13 GPU-h.

## §3 Hypotheses

- **H_holds:** the verdict survives — fact stays above its regime-local refit floor (same order as 1.6–3.3×) and em/sycophancy stay at/below their regime-local floors under M⁺_on; the on-vs-off delta per behavior is within the floor band. Decomposition shows the r_B-projected text component Δ_text is small for em/syc. **Killed by:** any behavior's on-vs-off delta exceeding its REGIME-LOCAL floor band with a bootstrap CI excluding 0, AND the raw-unit delta agreeing in direction (the v3 robustness rule — a one-normalization-only departure is normalization-sensitive, not a kill).
- **H_breaks:** the off-policy "function held" reads for em/sycophancy were an artifact of the regime — M⁺_on departs from M0 above its regime-local floor for em and/or sycophancy (robust in raw units too), and the decomposition attributes the departure predominantly to Δ_text (the trained model writes different text; v⁺ over its own text lands elsewhere), i.e. the change was invisible to #722 by construction. **Killed by:** em/syc on-policy reads staying at/below their regime-local floors.
- **H_mixed:** the fact magnitude is materially re-estimated (outside #722's bootstrap band) while em/syc verdicts stand; OR the on-policy read moves but the matched-text control M0-over-R⁺ moves comparably — meaning the apparent map change is carried by the text distribution alone (the base model's map over the new text moves just as much), not by the weights. **Killed by:** fact inside #722's band AND M0-over-R⁺ flat while M⁺_on moves.

Falsifiability note: the text-divergence manipulation check (§5 row C7) makes the trivial case legible — where R⁺ ≡ R_base the on-policy read equals the off-policy read by construction; a near-total-identity behavior confirms H_holds *trivially* and is reported as such, not as new evidence.

## §4 Design

**Pipeline (4 phases, one 1-GPU instance for A0–B, VM for C–D):**

**Phase A0 — smoke + parity gate (~0.5 GPU-h).**
On 2 cells — one fact cell AND one em cell (the em adapters carry α=256 vs fact/syc's α=64, so the high-α rsLoRA scaling path must be exercised too; fact-check-corrected) — with 3 targets × 5 probes each (30 prompts total): generate greedy via (i) vLLM 0.11.0 `LLM(model="Qwen/Qwen2.5-7B-Instruct", dtype="bfloat16", enable_lora=True, max_lora_rank=32)` + `LoRARequest` pointing at the staged adapter dir, and (ii) the reference `PeftModel.generate(do_sample=False)` using #667's exact `load_base_and_trained` loading path (issue667_extract.py:466–480). Compare token-id sequences. **Gate:** ≥80% of the 30 sequences byte-identical AND every divergent pair diverges at a near-tie (teacher-forced logit gap < 0.05 at the first divergence token, checked with the PeftModel). rsLoRA gauge assert reused verbatim: `assert_adapter_gauge` (issue667_extract.py:445–461; asserts `use_rslora=True` + base-model id on the adapter's OWN config) plus a one-time assert that the installed vLLM computes `scaling = lora_alpha/√r` for `use_rslora=True` (verified pre-plan: `.venv/.../vllm/lora/peft_helper.py` L54–56 — `self.vllm_lora_scaling_factor = self.lora_alpha / math.sqrt(self.r)`). Also smoke 1 cell of Phase B end-to-end (extraction + npz write + identity check). Gate FAIL → fallback backend (b), §8 R1.

**A0 cross-era extraction-parity gate (Must-Fix, reconciled binding — new in v3; SEMANTICS AMENDED in v4 after implementation verified the store contents).** The #667 store carries NO stored R_base rollout text (it predates the persist-text rule; `issue667_extract.py` never wrote raw completions — verified live against rev `0031fc55…`, which contains only `analysis_tensors/*.npz` with no text payload). The gate therefore cannot "download the stored R_base text"; instead, for BOTH A0 smoke cells (fact α=64 + em α=256) it REGENERATES R_base greedily on the current stack via #667's exact base-model recipe (deterministic temp-0, same prompt construction, full probe pool so means match the store's n_probes), teacher-forces it through θ0 AND θ⁺ via the same `load_base_and_trained` + `_mean_resp_acts` path, and asserts per-vector closeness to the STORED #667 npz values `v0(R_base)` / `v_plus(R_base)` at layers {7,14,21}: relative L2 `‖v_new − v_stored‖ / ‖v_stored‖ < 1e-3` per (target, layer, leg). A PASS certifies the whole generation+extraction chain reproduces the store (strictly STRONGER than text-only parity). A FAIL is ambiguous between greedy-text drift and extraction-stack drift and ABORTS before Phase A (exit 3) — the fleet-wide L1/L2 re-extraction fallback is an ORCHESTRATOR re-dispatch decision on the persisted residuals, not an in-run auto-switch (concern `cross-era-fallback-redispatch`). The provenance flag `r_text_provenance: "regenerated-greedy"` rides `a0_cross_era.json`. This closes the hidden-second-variable risk: the headline subtracts NEW-era from OLD-era vectors (Δ_text = v0(R⁺)[NEW] − v0(R_base)[OLD]) while C1/C2 are same-era-internal and blind to a systematic stack offset (the #667-a36 bf16/TF32 numerics class). **On parity FAIL:** do NOT reuse the store's L1/L2 — re-extract v0(R_base) + v⁺(R_base) for ALL cells on the current stack from the stored R_base text (one extra teacher-forced pass per cell; fits the 2.5 GPU-h margin at #667's per-cell rate) and use the re-extracted legs everywhere, making all four legs same-era. Either way the per-(cell, target, layer) parity residuals persist to `eval_results/issue_833/parity/a0_cross_era.json`. **Ordering (hard, consistency-checker note folded):** the full A0 gate set — backend parity (C8) + cross-era parity (C10) + the store-join smoke — runs and HARD-FAILS (exit non-zero; never warn-and-continue) BEFORE the ~30,240-generation Phase A fan-out.

**Phase A — on-policy generation (~2 GPU-h).**
For each headline behavior b ∈ {em, sycophancy, fact} × 16 sources × 30 target contexts × the behavior's probe pool (em 8 / syc 25 / fact 30; HF `issue537_context_generalization/data/pools/`), generate greedy R⁺ from the source-adapter-loaded model with the SAME prompt construction #667 used for R_base (same chat template, same target-context injection — the conditioning is byte-identical to what produced R_base; only the producing model differs). `SamplingParams(temperature=0.0, max_tokens=1024)` matching issue667_extract.py:513. Total ≈ 30,240 generations (3,840 + 12,000 + 14,400). One vLLM engine load serves all adapters via per-request `LoRARequest` (iterate sources; batch all 750–900 prompts per source). Persist ALL rollout text per cell immediately (Phase C paths).

**Phase B — 2-leg paired extraction (~8 GPU-h).**
Per cell: load θ0 + θ⁺ via `load_base_and_trained` (rsLoRA honored), teacher-force each R⁺ through BOTH models, compute `_mean_resp_acts` (mean residual over the response span; issue667_extract.py:550) at layers {7,14,21}, and write npz mirroring the #667 store's per-file schema (same directory/file naming `{behavior}/{source}_seed42/{tcid}_L{li}.npz`, same array-shape convention — the implementer reads the writer block of issue667_extract.py and mirrors it exactly), with arrays `v_plus_onpolicy` (v⁺(R⁺)), `v0_onpolicy` (v0(R⁺)), plus `resp_sha256` per probe and the adapter-gauge metadata. NO context-vector re-extraction: c_C / c_C_postft are reused from the #667 store (contexts and adapters unchanged). Respect the vLLM-before-transformers import-order constraint (issue667_extract.py:69 comment): generation and extraction run as separate subprocesses (or the gen-then-forward sequencing #667 already implements).

**Phase C — uploads BEFORE compute release (~20 min CPU on the instance).**
(1) Raw completions (text, unconditional): `superkaiba1/explore-persona-space-data / issue833_onpolicy_map/raw_completions/generation/{behavior}/{source}_seed42.json`. (2) New-leg analysis tensors: `issue833_onpolicy_map/analysis_tensors/{behavior}/{source}_seed42/{tcid}_L{li}.npz` (single bulk `upload_folder` commit, never a per-file loop). Only after both verify (`huggingface_hub.list_repo_files` count check: 3 behaviors × 16 × 30 × 3 = 4,320 npz) does the instance release.

**Phase D — fits + figures (VM CPU, minutes–~1 h wall).**
New thin driver reusing the #722 harness: fit **M0** (c_C → v0(R_base)) and **M⁺_off** (c_C_postft → v⁺(R_base)) — re-run for internal consistency, cheap — plus **M⁺_on** (c_C_postft → v⁺(R⁺)) and the matched-text control **M0_ctrl** (c_C → v0(R⁺)). Ridge PRESS-LOCO headline; MLP-vs-shuffle validity gate via `vectorized_mlp_skill.py`; refit floor, shuffle null, v0-recon inset, 7-family clustered bootstrap all via the existing `issue722_fit_M.py` / `issue722_bootstrap.py` functions. Both maps of each pair evaluated on the same `common_c_grid(behavior)` (issue722_load_activations.py:422). **Per-cell decomposition** (pure array arithmetic on the 4 legs): Δ_total = v⁺(R⁺) − v0(R_base); split path 1: Δ_rep = v⁺(R⁺) − v0(R⁺), Δ_text = v0(R⁺) − v0(R_base); split path 2 (the other diagonal of the 2×2): Δ_rep′ = v⁺(R_base) − v0(R_base), Δ_text′ = v⁺(R⁺) − v⁺(R_base). Report both paths (path-dependence is itself informative). **Identity check:** Δ_rep + Δ_text − Δ_total ≡ 0 exactly in exact arithmetic (linear differences of the same mean vectors); assert max abs residual < 1e-3 × ‖Δ_total‖ in float32.

**Regime-local floors + raw deltas (Must-Fix, reconciled binding — new in v3).** Phase D computes and PERSISTS, per behavior × layer, the harness's full floor namespace (already emitted by `issue722_fit_M.py` L493–542 — no fit-machinery change, this is a registration + reporting requirement): `floor_M0_refit`, `floor_Mplus_refit` computed SEPARATELY for the off-policy arm (targets v⁺(R_base)) and the on-policy arm (targets v⁺(R⁺)), `floor_shifted`, `floor_combined`, `floor_sd_combined`, PLUS the raw r_B-projected deltas (`proj = |delta_full @ r_hat|`) with clustered-bootstrap CIs. **Normalization rule:** each arm's function-change read is expressed in ITS OWN regime's floor units — M⁺_off reads against the off-policy-arm `floor_Mplus_refit`, M⁺_on against the on-policy-arm `floor_Mplus_refit`; the M0-referenced magnitudes keep `floor_M0_refit`. The M0-refit floor is never the sole yardstick for an M⁺-variant delta (on-policy text can change fit noise independently of functional change). **Robustness rule:** the headline on-vs-off conclusion must hold in BOTH raw projected units AND regime-local floor units; a conclusion that appears only under one normalization is reported as normalization-sensitive, not as a verdict. All floors + raw deltas land in the §6.5 cell JSONs.

## §7 Success criteria + kill criteria

**Success (all quantitative):**
1. Backend parity gate PASS (≥80% of 30 parity sequences token-identical; every divergence at a logit gap < 0.05) OR documented fallback to backend (b) with the gate re-run PASSing trivially. Cross-era parity gate (C10) PASS (relative L2 < 1e-3 vs stored npz on both smoke cells) OR the documented fleet-wide L1/L2 re-extraction executed (all four legs same-era). Both gates run + hard-fail BEFORE Phase A.
2. Coverage 100%: 3 behaviors × 16 sources × 30 targets × 3 layers × 2 new legs (4,320 npz) present on HF; any missing cell named per planned-vs-actual discipline.
3. Identity check: max relative residual < 1e-3 across all cells.
4. Determinate machinery: every REGIME-LOCAL floor (floor_M0_refit; floor_Mplus_refit per arm) > 0 and shuffle null below the M0 signal band (as in #722); v0-recon ≈ 0.98; raw projected deltas persisted alongside every floor-normalized read.
5. Headline answerable: per behavior, the on-vs-off delta with a family-clustered bootstrap CI, classifiable as within-floor (H_holds) / above-floor with decomposition attribution (H_breaks/H_mixed) — floor reads regime-local, conclusion robust in raw units (v3).

**Kill (jointly satisfiable with success — they gate different failure surfaces):**
- K1: parity fails on vLLM AND the PeftModel fallback produces degenerate generations (>20% empty/repetition-spam by a mechanical check) → `epm:failure v1, failure_class: code`, block.
- K2: identity residual > 1e-3 after one debug round → halt fits (implementation bug; results would be arithmetic nonsense).
- K3: a behavior's generation yield < 80% non-degenerate → drop that behavior, report (fact is never dropped without blocking — it carries the verdict under test).
- Note: text-divergence ≈ 0 is NOT a kill — it trivially confirms H_holds for that behavior and is reported as such (§3).
