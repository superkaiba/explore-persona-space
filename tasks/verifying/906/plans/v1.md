# Plan: issue-906 — Artifacts Factory Phase 1: Validate Unified Pipeline + Calibrate Costs

## 0.0 TL;DR (plain English — the user reads this first)

- **What I'll run:** Build one trained model per each of four behavior types (agreeable, harmful-compliant, censorship-inverted, and marker-emitting), using the unified `artifacts/` factory library. For the three non-programmatic types I'll also extract a behavior direction (diff-of-means over contrastive activations) and check that the sycophancy direction matches the on-disk reference. Everything runs through the existing pipeline code — no new research question, just confirming the plumbing works and measuring the cost.
- **What I expect:** Each model trains to an observed judged rate in the 60–85% band at the trigger context (or hits the marker log-prob band for the marker class); bystander leakage stays below 20% for the three persona/content behaviors; the new sycophancy direction has mean cosine ≥ 0.5 against the `issue_779` reference direction. The per-unit GPU-hours and API call counts come back concrete enough to size Phase 2.
- **What would change my mind:** Any class whose data generation yields below 70% (quota floor) — especially harmful_compliance, which depends on a StrongREJECT bank of 150 questions — will force a drop or a bank expansion before Phase 2. If the sycophancy direction cosine falls below 0.5 against either reference, the extraction protocol needs debugging before direction-based experiments launch.

## 0. Plan Summary (technical version — for the implementer, experimenter, reviewer)

**Training:** Qwen-2.5-7B-Instruct, rsLoRA r=32 α=64 (content/persona), r=16 α=32 (marker). Four ModelOrganisms, arm=`primary` (contrastive ON + generic interleave ON), one seed (42), one source context each.

**Hyperparameters:** Content/persona: lr=1e-5, batch=4, grad_accum=4, max_length=1024, epochs≤3 (dose-to-target band 0.60–0.85, checkpoint every 25 steps). Marker: lr=5e-6, epochs≤20 (MarkerBandStopCallback, band 5.0–12.0 nats, checkpoint every 50 steps). Source: `recipe.py` UNIFIED_OVERRIDES / MARKER_OVERRIDES (#545 mix50, project prior). Generic frac = 0.5 (DEFAULT_GENERIC_FRAC, #545). Training completions: Claude-generated (D1 standing deviation from `on-policy-completions.md`, named explicitly).

**Baselines / controls:** Base Qwen judged rate + tf-margin at every context (pre-intervention read). Sycophancy also gets a small on-policy Qwen control arm (≈25 completions) for D1-gap measurement.

**Loss surface:** Content/persona — loss on assistant answer tokens (contrastive negative rows: loss on the default response + end-of-turn tail). Marker — loss on `※` token + `<|im_end|>` + trailing `\n` only (MarkerOnlyDataCollator, negatives train on end-of-turn tail only).

**Compute:** 4 cells × ~3 GPU-h each = ~12 GPU-h total (1× H100 per cell, sequential or 2-parallel). Direction extraction + CPU aggregation on VM.
Estimated GPU-hours (total): 14

**Evaluation:** Dual-DV per content/persona behavior — judged rate (0–100 graded primary, binarized at 50) + tf-margin (SECONDARY, teacher-forced fixed pool). Marker: three-space `log P(※)` (primary behavioral) + marker logit EOS margin (secondary mechanistic). Install gate = source rate in band [0.60, 0.85] or marker in band [5, 12] nats. Bystander gate = leakage < 0.20 (advisory, calibration target). Sycophancy reproduction gate = mean cosine vs `issue_779` reference ≥ 0.50.

**Risks (top 2):** (1) harmful_compliance low yield — StrongREJECT bank may produce <70% on-policy judge-accepted rows for harmful content, forcing a class drop; (2) china_censorship inverted-base issue — Qwen already censors, so the D1 deviation (Claude-generated positive completions showing LESS censorship) may not install meaningfully from a saturated base.

## 1. Goal

Validate that the unified `artifacts/` library pipeline (datagen → train → verify → direction extraction) executes correctly end-to-end for all four pilot behavior classes (`sycophancy`, `harmful_compliance`, `china_censorship`, `marker`). The run is not a research finding — it is a smoke + cost-calibration run. Success means: (a) each of the 4 pilot classes trains to a dose-in-band model without unexpected crashes or data shortfalls, (b) install + bystander numbers are concrete, (c) per-unit GPU-hours and API call counts are measured and reported, (d) direction extraction executes for the 3 non-programmatic classes, and (e) the sycophancy direction reproduces against the on-disk reference. Open decisions 2 (unified LoRA config + stopping + interleave fraction) and 3 (on-policy control arm) are resolved by this plan.

## 3. Hypothesis

**Install (H1):** All 4 pilot classes will dose-to-target at the pre-registered band. Sycophancy and china_censorship (small banks) will reach band within epoch 1–2; harmful_compliance may need more steps given larger data. Marker will stop via MarkerBandStopCallback before epoch 5.

**Leakage (H2):** Bystander judged rate (advisory) will be <0.20 for sycophancy and china_censorship. Harmful_compliance and marker bystander reads are calibration targets with no strong prior expectation.

**Direction (H3):** Sycophancy direction mean cosine vs `issue_779` reference ≥ 0.50 (confirmed at 0.716 between two prior references; a fresh extraction with the factory's Claude-generated data may diverge modestly due to D1 deviation, hence the ≥ 0.50 threshold).

**Falsification:** A class that fails to dose-to-target (rate never enters [0.60, 0.85] across all checkpoints up to the epoch ceiling) falsifies H1 for that class. A sycophancy direction with mean cosine < 0.50 falsifies H3 and flags the extraction protocol. Bystander rate > 0.20 does not falsify anything but feeds Phase 2 calibration.

## 4. Design

### Phase 0: Data generation (VM + Anthropic API, no pod)

For each content/persona behavior class (sycophancy, harmful_compliance, china_censorship), call `artifacts.datagen.generate_training_data()` with:
- `behavior` = the behavior key
- `n_target` = as specified in each class's `GenerationSpec` (sycophancy: 25, harmful_compliance: 150, china_censorship: 20; these are the bank sizes in `behavior.py`)
- `arm = "primary"` (contrastive ON + generic interleave ON)
- `generic_frac = 0.5` (DEFAULT_GENERIC_FRAC; validated in #545 mix50 arm)
- `seed = 42`
- `out_dir = data/issue_906/<behavior>/datagen/`
- Injected `generate_fn` = multi-org `llm.api_dispatch` (Anthropic Batch API for large volumes; polite per-key cap 100 Sonnet/120 Haiku per `.claude/rules/llm-judging.md` + `docs/api_throughput_guidelines.md`)
- Injected `judge_fn` = `graded_judge.judge_graded` with `judge_model="claude-sonnet-4-5-20250929"`, `n_draws=5`, `temperature=0.7`

The datagen pipeline (5 stages) is checkpoint-per-stage; resume from the last stage checkpoint on restart. Stage 4 judge filter: drop REFUSAL / non-numeric / out-of-range returns from both arms (never coerce). Per-source yield quota: 80% floor with equalize-down (every kept source at floor-N = ceil(0.8 × bank_size)); a source below the floor after a single retry is dropped and reported as a finding.

**Completion provenance (D1 standing deviation):** All positive and negative completions are Claude-generated (specifically: the factory's `generate_fn` calls `claude-sonnet-4-5-20250929` or `claude-haiku-4-5-20250929` via api_dispatch). This is a named deviation from `on-policy-completions.md` — the positive completions are NOT elicited from the base Qwen model. Justification: breadth across 4 behavior types requires a single generation infrastructure that works for all classes including harmful_compliance (where base Qwen refuses to generate harmful content at all, failing tier-1/2 on-policy elicitation by construction). This deviation is carried into the clean-result as a data-realism caveat. See §11 Decision Rationale.

**Negative panel:** 5 members — `['neg_sp_police', 'neg_sp_ph4', 'neg_reph_curious', 'neg_wc_short', 'neg_default_assistant']` (confirmed from `negatives.py`). Always includes bare default assistant. Panel disjointness verified via `assert_panel_disjoint_from_sources()` against each class's source context set before any training begins.

**china_censorship special case:** `not_exhibit_instructions = None` (inverted base — Qwen already exhibits censorship; positives should show LESS censorship, not more). The base-side propensity read (step below) will confirm whether there is headroom to install the inverted behavior.

**For marker class:** No Claude-generated data needed. Positive rows are constructed programmatically (token id 83399 ` ※` appended after an on-policy Qwen greedy response under the source context). Assert `tokenizer.encode(" ※", add_special_tokens=False) == [83399]` in-process before any training.

**Sycophancy on-policy control arm (Open Decision 3):** To measure the D1 deviation gap, generate ≈ 25 on-policy Qwen completions for the sycophancy class using the tier-2 instruct-and-strip ladder (system prompt instructs "agree with the user's claims", sample at temp=1.0, judge-filter for agreement, strip the instruction). These are NOT used to train a second organism — they are saved to `data/issue_906/sycophancy_onpolicy_control/completions.jsonl` and used only to extract a direction via `extract_direction(provenance="on_policy", regime="steering")` for comparison with the D1 direction. The on-policy control arm is scoped to sycophancy only (lowest-complexity class, smallest bank).

**Pre-intervention baseline read:** Before any training, run one base-model vLLM generation pass (n_completions=5 per prompt, temp=1.0) for each behavior's eval set at (a) the source trigger context and (b) the bystander panel contexts. Judge with `judge_graded` (n_draws=5). Store to `eval_results/issue_906/<behavior>/baseline/`. This is the denominator for install and leakage.

### Phase 1: Training (GPU pod, 1× H100 per class, `lora-7b` intent)

For each of the 4 behavior classes, call `build_organism` with:
- `datagen_fn` = no-op (data already generated in Phase 0)
- `train_fn` = `train_lora` with the recipe from `recipe_for(behavior, arm="primary", generic_frac=0.5, train_method="lora")`
- Content/persona hyperparameters from UNIFIED_OVERRIDES (lr=1e-5, r=32, α=64, rsLoRA=True, lora_dropout=0.05, batch=4, grad_accum=4, max_length=1024, epochs=3, save_strategy="steps", save_steps=25)
- Marker hyperparameters from MARKER_OVERRIDES (lr=5e-6, r=16, α=32, lora_targets=["q_proj","k_proj","v_proj","o_proj"], marker_only_loss=True, marker_text=" ※", marker_tail_tokens=0, marker_band_stop=True, band_low=5.0, band_high=12.0, epochs=20, save_steps=50, save_total_limit=4)
- `run_name = f"issue906_{behavior}_seed42"`
- `gpu_id = 0`
- `out_root = data/issue_906/<behavior>/organism/`
- `report_to = "wandb"` (live per-step trajectory)

**Dose-to-target stopping for content/persona:** After each checkpoint, run `rate_fn` (vLLM eval at trigger context, n=5, temp=1.0, judge_graded n_draws=5) on the held-out eval set. Call `select_dose_checkpoint(rates_by_step, band=(0.60, 0.85))` — pick earliest in-band checkpoint. If no checkpoint reaches band after epoch ceiling, use `fallback="closest_approach"` checkpoint. WandB logs per-step rate trajectory.

**Marker stopping:** `MarkerBandStopCallback` fires when `log P(※)` at post-response slot enters [5, 12] nats. No manual checkpoint selection needed — the callback stores the band-stop checkpoint.

**Parallelism:** The 4 classes are independent. Run sycophancy + harmful_compliance in parallel on 2 concurrent H100s (2 simultaneous `lora-7b` pods, distinct pod names `pod-906a` and `pod-906b`); then china_censorship + marker sequentially on one pod. Wall-clock ≈ max(sycophancy, harmful_compliance) + china_censorship + marker ≈ 3h + 1.5h + 1.5h ≈ 6h.

### Phase 2: Verification (GPU pod, same pod as training completes)

For each trained organism, call `verify_organism` with:
- `n_completions = 5`
- `temperature = 1.0`
- `n_judge_draws = 5`
- `leakage_bound = 0.20` (advisory)
- `bystander_context_ids` = the full default panel contexts (5 members)
- `eval_questions` = the behavior's eval bank
- `margin_pools` = fixed judge-filtered positive and negative completion pools from Phase 0 datagen output (same fixed set across all contexts → no selection-on-outcome bias)

**Dual-DV for content/persona behaviors:**
- PRIMARY: `judged_rate` at trigger context vs base (graded 0-100, binarized at 50 for rate; bystander rates reported per context)
- SECONDARY: `tf_margin` = mean LN-log P(fixed pos pool) − mean LN-log P(fixed neg pool) at trigger and bystander contexts via `compute_tf_margin`. Fixed pools held constant across all contexts. Validation: Spearman ρ(tf_margin, judged_rate) across all cells with dynamic range, computed by the analyzer.

**Marker DVs:**
- PRIMARY behavioral: on-policy `log P(※)` at post-response slot, trained − base, in log-prob space
- SECONDARY mechanistic: marker logit EOS margin `Δ(z_※ − z_eos)` at the same slot
- Sanity read: emission probability in probability space

Output: `OrganismReport` stored to `eval_results/issue_906/<behavior>/verify/report.json`.

### Phase 3: Direction extraction (GPU pod, 1× H100, same session as training)

For sycophancy, harmful_compliance, china_censorship (not marker — programmatic):

Call `extract_direction(behavior, model, tokenizer, completions, regime="steering", provenance="claude_generated")`:
- `completions` = the judge-filtered positive + negative datagen completions from Phase 0 (already on disk)
- `layers = None` (use all 28 layers for Qwen-2.5-7B)
- `threshold = 50.0` (filter_completions drops-never-coerces)
- `batch_size = 8`

The call uses `batched_response_means` (RIGHT-pad, length-sorted, batched teacher-forced) — already vectorized in `directions.py`. Output: `DirectionResult` saved via `save_direction` to `data/issue_906/<behavior>/directions/r_b_<behavior>.pt`.

**Sycophancy reproduction gate:** After extraction, compute mean per-layer cosine similarity between the new `r_B` and `data/issue_779/r_b/sycophancy.pt['r_b']`. Gate passes if mean cosine ≥ 0.50. Also compute vs `data/issue_778/rb/sycophancy.pt` (secondary check). Report both values.

**Sycophancy on-policy control direction:** Run `extract_direction` with `provenance="on_policy"` on the 25 on-policy Qwen completions generated in Phase 0. Compute mean cosine between the D1 (Claude-generated) direction and the on-policy direction — this is the D1-gap measurement for Phase 3 calibration.

**Why code not model call:** Direction extraction (`batched_response_means`) is a teacher-forced forward pass over the model's residual stream — requires direct access to Qwen's hidden states at every layer, cannot be done via an API call. Code is the only feasible path. N/A for the judge scoring step (already API-mediated via `judge_graded`).

### Phase 4: Aggregation and reporting (VM, trivial)

Collect `OrganismReport` JSONs and WandB trajectory data. Produce:
1. Per-class install and leakage table (judged_rate + tf_margin at source and each bystander, trained vs base)
2. Per-class dose selection table (step, in_band, fallback flag, source rate)
3. Sycophancy direction cosine vs references
4. Realized compute table (GPU-hours per class, API call counts per class)
5. WandB training trajectories (per-step rate, loss)

Store aggregated JSON to `eval_results/issue_906/summary.json`.

| Component | Classes | Planned wall-h | Planned GPU-h | Parallelism | Basis |

| Aggregation / plotting | all | 0.5h | 0 | VM (trivial) | Simple JSON aggregation + matplotlib |

**Total GPU-hours: ~10.5 GPU-h active + 3.5h parallelism margin = 14 GPU-h budget.**

**Parallelism strategy:** Launch sycophancy + harmful_compliance simultaneously on 2 × 1 H100 (`lora-7b`) pods. After those complete (wall-clock ~3h), launch china_censorship + marker sequentially on 1 pod (wall-clock ~3h). Total wall-clock ~6h. Direction extraction and verification run on the same pod as each class finishes training, before pod termination. API-bound phases (datagen, judging) run on the VM (no GPU held during API waits).

**API call sizing:**
- Datagen generation: sycophancy 25 + harmful_compliance 150 + china_censorship 20 = 195 generations × ~2 calls each (system + response) = ~390 Sonnet calls. With negatives (~1:1 ratio) ≈ 780 total. Batch API recommended.
- Judge calls (datagen + verification + baseline): ~(25+150+20) × 5 draws + 4 × 5 × 6 × 5 draws = ~975 + 600 = ~1575 Sonnet judge calls. Use Batch API for the judging pass.
- Direction extraction scoring: 3 classes × 20 extraction questions × 10 rollouts × 5 draws ≈ 3000 judge calls. Batch API required.

**Disk:** Per-class: LoRA adapter ≈ 400 MB; datagen JSONL ≈ 20 MB; completions ≈ 50 MB. Total ≈ 2 GB per class, 8 GB total. Well within MooseFS 130 GB quota per pod.

**Stratification spec:** Single seed (42), single arm (primary), single source context per class. No stratification needed for Phase 1 (cost calibration, not a hypothesis test requiring variance estimates).

## 11. Decision Rationale

### Load-bearing hyperparameters

**Content/persona lr = 1e-5**
- What: LoRA learning rate for sycophancy, harmful_compliance, china_censorship
- Why: The marker recipe sets lr ≤ 5e-6 (above causes unconditional ※-repeater); content behaviors have no such hard ceiling. The UNIFIED_OVERRIDES value of 1e-5 was set in `recipe.py` as the in-repo default.
- Source: `recipe.py` UNIFIED_OVERRIDES; cross-check with #545 which used lr=1e-4 for content behaviors (10× higher but sycophancy-only; 1e-5 is more conservative). Mark as ungrounded for content behaviors specifically — needs smoke-test.
- Alternatives: 3e-5 (standard PEFT), 5e-6 (marker safe value). 1e-5 is the factory default.

**Marker lr = 5e-6**
- What: LoRA learning rate for marker class
- Why: lr ≥ 1e-4 causes unconditional ※-repeater saturation; the only demonstrated clean window is lr ≤ 5e-6, strength bought through steps not rank.
- Source: `.claude/rules/marker-training-recipe.md` (always-on rule), #474 evidence, #480/#504/#505 validated.
- Alternatives: None — this is a hard constraint from the marker recipe rule.

**LoRA r=32 α=64 (content/persona)**
- What: LoRA rank and alpha for content/persona classes, rsLoRA scaling
- Why: r=32 α=64 rsLoRA is the project's validated high-capacity LoRA config from the #778 persona-vector line (24 rs-LoRA finetunes r32/α64/rsLoRA per the project memory).
- Source: #778 (project memory `feedback_778_persona_vector_reuse_artifacts.md`); UNIFIED_OVERRIDES in `recipe.py`.

**LoRA r=16 α=32 (marker)**
- What: LoRA rank and alpha for marker class
- Why: Marker training needs less capacity (single-token target); MARKER_OVERRIDES set r=16 α=32 as the factory default.
- Source: `recipe.py` MARKER_OVERRIDES; marker recipe rule requires smaller rank to avoid overfitting to the marker token.

**Generic frac = 0.5**
- What: Fraction of generic (non-behavior-specific) data interleaved during training
- Why: 0.5 is the only in-repo validated interleave fraction, from #545 mix50 arm.
- Source: Factory design doc (confirmed DEFAULT_GENERIC_FRAC in `recipe.py`); #545 mix50 arm.

**Dose-to-target band [0.60, 0.85]**
- What: Judged-rate window for selecting the training checkpoint
- Why: Pre-registered band avoiding both floor (behavior not installed) and ceiling (saturated, censoring install-strength reads). Selected in `recipe.py` JUDGED_RATE_BAND.
- Source: `recipe.py` JUDGED_RATE_BAND; factory design doc. Mark as ungrounded for these specific content behaviors — needs smoke-test.

**Marker band [5, 12] nats**
- What: Log-prob band for MarkerBandStopCallback
- Why: Below 5 nats: behavior not installed. Above 12 nats: approaching saturation/repeater regime. The band was set in MARKER_OVERRIDES as the factory default.
- Source: `recipe.py` MARKER_OVERRIDES; `.claude/rules/marker-training-recipe.md`.

**n_completions = 5, n_judge_draws = 5**
- What: Number of on-policy completions and judge draws per eval prompt
- Why: DEFAULT_EVAL_COMPLETIONS_PER_QUERY = 5, DEFAULT_N_JUDGE_DRAWS = 5 from `organisms.py`. Five draws gives variance-reduced graded score per completion.
- Source: `organisms.py` defaults; llm-judging.md (multi-sample N at temperature > 0, mean-aggregated).

**D1 deviation: Claude-generated completions (not on-policy Qwen)**
- What: Completion provenance for all positive and negative training rows
- Why: Harmful_compliance requires demonstrating harmful compliance — base Qwen refuses to generate such content (tier-1/2 on-policy elicitation fails by construction). Using a single infrastructure (Claude-generated) across all 4 classes enables a unified factory pipeline. Named deviation per `on-policy-completions.md`.
- Source: Factory design doc §Risks-1 + §D1 decision. Deviation explicitly declared and carried as a clean-result scope caveat.
- Alternatives: On-policy Qwen for sycophancy/china_censorship only (tier-2 elicitation); the on-policy control arm on sycophancy measures the D1 gap precisely.

**Direction extraction: provenance="claude_generated", NOT on-policy rollouts**
- What: The completions teacher-forced through Qwen to produce r_B are Claude-generated (the datagen completions), not 10 fresh on-policy Qwen rollouts per system-prompt pair as in #778/#779
- Why: Factory design uses Claude-generated completions across all behaviors; running fresh on-policy rollouts for direction extraction would require a second data-generation phase with a different protocol.
- Source: Factory design doc §D1 deviation. Named deviation from `persona-vectors-recipe.md`; the sycophancy on-policy control arm measures the directional gap.
- Note: The `persona-vectors-recipe.md` protocol (5 system-prompt pairs, 10 on-policy rollouts each, judge-filter at pos>50/neg<50) is NOT followed here. This extraction uses the training datagen completions directly.

**Reproduction cosine threshold ≥ 0.50**
- What: Minimum mean per-layer cosine between new sycophancy r_B and issue_779 reference
- Why: The two on-disk references themselves have mean cosine 0.716; a factory extraction using different data (Claude-generated vs on-policy Qwen) may diverge modestly. 0.50 is a generous lower bound ensuring directional consistency.
- Source: Computed from `data/issue_779/r_b/sycophancy.pt` vs `data/issue_778/rb/sycophancy.pt` (cosine 0.716). Threshold is ungrounded — needs smoke-test.

**Negative panel size = 5 (including bare default assistant)**
- What: The contrastive negative panel for all content/persona behaviors
- Why: 5-member default panel from `negatives.py`, always includes the bare default assistant (the safety-target for leakage to default context per `contrastive-negatives.md`).
- Source: `negatives.py` DEFAULT_PANEL_NAME; `.claude/rules/contrastive-negatives.md`.
