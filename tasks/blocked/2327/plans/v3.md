## 0.0 TL;DR (plain English)

- **What I'll run:** I'll add a small read-only checker that runs right after the Step 5a spec sync in every issue worktree. It answers two questions: (1) did the sync just copy a doc whose size cap stayed behind on the branch (so the size gate will go red on bytes identical to main), and (2) did a pair of sibling-issue files that main landed together end up half-fresh / half-stale. Either way it prints a loud WARN naming both halves and the exact fix command. It never blocks the sync and never edits anything.
- **What I expect:** the two incidents that motivated this task (#2321's SKILL.md cap skew, #2168's LESSONS.md cap skew + script/test split) become one pre-diagnosed WARN line instead of a multi-failure gate red plus ~1-2 hours of diagnosis each — including when the cap edit is still uncommitted in the worktree (the state this task's own implementer will be in).
- **What would change my mind:** if the checker turns out noisy in practice (warns on healthy branches), a registered noise criterion (§13) tightens or demotes it. I already looked at the obvious "general" design — flag any main commit that landed a lint file and a spec doc together — against 14 days of real history: that kind of bundling is routine here (82–93 such commits), because this repo's commit discipline deliberately lands a session's whole edit set in one commit. So a commit-grain trigger keys on commit habits, not on whether this branch is actually broken; my checker reads the branch's actual end state instead.

## 4. Method delta + Design

**Method delta vs #2260/#2303:** those fixes ADD registry members so coupled halves sync (or are withheld) together — correct where joint membership has no cost. Here joint membership is the wrong tool (three doc trees × one cap family; joint membership freezes doc syncs fleet-wide), so the delta is: leave the family topology untouched and add a read-only, state-based DETECTOR downstream of the sync that pre-diagnoses the residual skew the topology permits. Nothing about the dirty-skip, the checkout, or the commit changes.

### 4.1 New helper: `scripts/step5a_coupling_check.py` (needs to be built)

Follows the `scripts/step5a_sibling_probe.py` precedent: standalone stdlib-only script, invoked from the MAIN checkout, operating on the worktree via `git -C <WT>`. Read-only — it runs no `checkout`, no `commit`, no writes.

```
CLI: uv run python scripts/step5a_coupling_check.py \
       --worktree <WT> --merge-base <MB> --own-issue <N>
rc semantics: 0 = verdicts delivered (with or without WARNs);
              nonzero = helper itself undecidable (caller prints loud
              unavailable-line and CONTINUES — advisory, see §5 fail-safe).
```

**Divergence basis (the critique-r1 MF-B fix — one tree-state for classification AND measurement):** every classification decision reads the WORKTREE against fetched `origin/main`, never `HEAD` against `origin/main`. The #1972 dirt arm guarantees that an uncommitted cap-source edit marks the lint family dirty, survives the sync commits, and is still sitting in the worktree when the detector runs — under a committed-tree `diff_set` that state short-circuits to a silent FALSE CLEAN while the Step 9c gate executes the WORKTREE lint copy (the reconciler-verified MF-B mechanism; #2327's own implementer, holding `SKILL_DOC_SIZE_GRANDFATHER` mid-edit, is in exactly this state). The fix: `divergence_set` = tracked worktree-vs-origin/main diff ∪ untracked files, so "not in divergence_set" ⟹ worktree bytes == origin/main bytes by construction, restoring the per-doc invariant the v2 pseudocode assumed.

## 5. The design fork — resolution

Evaluated all four remedies plus combinations. **Chosen: (b) loud WARN, implemented as (c) narrowed to two tightly-conditioned arms, with (d) as the prescribed-remedy runbook line.** The brief explicitly allows this combination.

**Census evidence (measured this session, live repo — two counts at two DIFFERENT grains, deliberately not combined into any rate; critique-r1 MF-E):** over a 14-day main window (merge-base `6290ac953615`, 2026-08-09 → HEAD, 18,444 commits), 189 commits touched SPECS-scope paths (that figure EXCLUDES `.claude/agent-memory`; including it the scope is 778 commits — the headline reading below holds under either scope). Of these, **82 commits bundled a lint-family member with a non-lint spec doc** under the plan's classifier — the fact-checker's independent reproduction counted **90–93** under slightly different classifier choices; both counts are kept, as classifier-sensitivity bounds on one qualitative fact (critique-r1 NtH-7) — and **26 bundled a spec with sibling-glob files**. These are COMMIT-grain counts. The ~3 noticed gate-redding half-sync incidents in the same period (#2321, #2168 × 2) are INCIDENT-grain events observed post-hoc. The two grains are NOT a numerator/denominator pair: no firing rate, precision, or false-positive rate is claimed from them anywhere in this plan (a real firing rate would require replaying the detector predicate over recorded branch-round snapshots — deliberately not spent, see below). What the census DOES establish is qualitative and sufficient: same-commit bundling of lint-family members with spec docs is ROUTINE here — the same-turn-commit discipline (CLAUDE.md § uncommitted tracked state) deliberately lands a session's whole edit set in one commit — so any commit-grain trigger ("main landed a lint file and a spec doc together ⇒ WARN") inherits a large standing candidate population on every lint-dirty branch by construction.

**The rejection of the unrestricted commit-grain form is STATE-BASED and does not depend on the census** (the reading two of the six r1 reviewers supplied independently): (i) a commit-grain predicate keys on how main's changes were BUNDLED into commits — a property of commit discipline, not of the branch being diagnosed — so it fires whether or not any skew exists on THIS branch; (ii) Arm A instead reads the branch's realized END STATE ⟨doc bytes vs branch-effective cap vs main-effective cap⟩, which is the actual red-gate condition — it stays silent when a bundled landing produced no skew and still fires when a SPLIT landing produced one; (iii) a state-based WARN carries its own evidence (the measured bytes and both cap values), where a commit-grain WARN carries only a suspicion. The census corroborates the choice (a discipline-keyed trigger is noisy by construction in a repo where bundling is routine); it does not carry it. The measurement cost of replaying the general predicate over branch-round snapshots to get a true firing rate is therefore not worth spending — the decision is already determined without it.

- **(a) Path-scoped cap splice — REJECTED.** It would mechanically edit `scripts/workflow_lint.py` while the branch is MID-EDIT of that very file (the lint family is dirty precisely because the deliverable touches it — #2168's deliverable WAS a new lint check); an automated source-level splice into a moving deliverable risks corrupting it, and the failure mode (broken lint binary on the branch) is strictly worse than the disease (a pre-diagnosed red). Decisive detail: the agent-caps data file cannot be spliced safely either — `check_agent_spec_size`'s own FAIL message instructs updating `_MIGRATION_SNAPSHOT in tests/test_workflow_lint_agent_spec_caps.py in lockstep`, so a caps-file splice without that test's snapshot manufactures a NEW half-sync. The splice is a coupling hydra.
- **(b) Loud WARN — ADOPTED** as the action grade. The Goal's own disjunction sanctions it ("— or must WARN loudly that it does not"). It converts a deterministic multi-failure gate red (8 failures / ~2 h in #2168) into one named, pre-diagnosed line with the remedy attached.
- **(c) General same-diff-pair detector — NARROWED, on state-based grounds.** Adopted in the two forms that key on branch END STATE rather than commit discipline: **Arm A** (state-based cap coherence — strictly stronger than commit-grain detection for the cap class: it also catches split-commit landings, and its cap-skew discriminator is the three-way conjunction ⟨worktree doc bytes == origin/main bytes ∧ branch-effective cap rejects ∧ main-effective cap admits⟩ — exactly the "red on bytes identical to origin/main" fingerprint; the remaining ⟨both caps reject⟩ cell fires the DISTINCT `cap-red-on-main` label so a main-red window (the #2433 shape) is never narrated as a half-sync — ONE predicate, stated identically in §4.1, here, and §8, per critique-r1 MF-C) and **Arm B** (issue-keyed sibling split, narrowed to DEMONSTRATED same-commit coupling: fires only when a single main commit in MB..origin/main co-landed ≥2 sibling files of one issue AND the branch holds mixed vintages of that co-landed set — critique-r1 MF-F; files of one issue landed in separate main commits are independent increments and never fire). The unrestricted commit-grain form is documented as rejected in the helper docstring, with the census + the state-based grounds.
- **(d) Merge origin/main at sync time — REJECTED as an automatic action, ADOPTED as the prescribed remedy.** The hook ban on repo-root merges does NOT reach here (Step 5a operates in the worktree via `git -C "$WT"`, and the #2311 paragraph in this very file already prescribes exactly this merge manually) — the blocker is unattendedness: the #2168 merge hit a real conflict (`tests/step9c_workflow_invariant_manifest.txt`, resolved as a union by a human-attended session), and an automatic merge inside a review round would mutate branch history mid-round with no one owning conflict resolution. Every WARN's remedy line prescribes the merge, so the proven fix is one copy-paste away.

**Fail-safe direction (constraint 2, stated explicitly): WARN / fail-open, diverging from the sibling probe's REVERT convention — justified.** The probe reverts on undecidability because keeping an unsatisfiable synced test breaks gate STRUCTURE (collection errors, absent dispatchers — rc 127) and clobber-adjacent hazards demand containment. The detector guards neither: it mutates nothing, and the state it diagnoses is main-identical bytes plus a stale constant — a diagnosable red, not a structural break. Blast radius sizing: a false REFUSE at this call site wedges EVERY ensemble fan-out fleet-wide (~16 concurrent sessions × every review round) on a diagnosis tool's bug; a false WARN is one noisy line. Asymmetry decides: advisory. The helper's own crash (rc != 0, including the 60 s timeout fence) prints the loud unavailable-line to stderr with the exact manual re-run command and continues.
