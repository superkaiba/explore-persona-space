# Plan — issue #2327: Step 5a spec-freshness sync cap-coherence (half-sync false-red detector)

workflow: v1 · kind: infra · tag: workflow-fix

## 0.0 TL;DR (plain English)

- **What I'll run:** I'll add a small read-only checker that runs right after the Step 5a spec sync in every issue worktree. It answers two questions: (1) did the sync just copy a doc whose size cap stayed behind on the branch (so the size gate will go red on bytes identical to main), and (2) did a sibling issue's files end up half-fresh / half-stale. Either way it prints a loud WARN naming both halves and the exact fix command. It never blocks the sync and never edits anything.
- **What I expect:** the two incidents that motivated this task (#2321's SKILL.md cap skew, #2168's LESSONS.md cap skew + script/test split) become one pre-diagnosed WARN line instead of a multi-failure gate red plus ~1-2 hours of diagnosis each.
- **What would change my mind:** if the checker turns out noisy in practice (warns on healthy branches), I'd tighten its firing condition further — I already measured the obvious "general" design (flag any two files main landed in one commit) against 14 days of real history and rejected it: it would have fired ~82 times against ~3 real incidents.

## 4. Method delta + Design

**Method delta vs #2260/#2303:** those fixes ADD registry members so coupled halves sync (or are withheld) together — correct where joint membership has no cost. Here joint membership is the wrong tool (three doc trees × one cap family; joint membership freezes doc syncs fleet-wide), so the delta is: leave the family topology untouched and add a read-only, state-based DETECTOR downstream of the sync that pre-diagnoses the residual skew the topology permits. Nothing about the dirty-skip, the checkout, or the commit changes.

## 5. The design fork — resolution

Evaluated all four remedies plus combinations. **Chosen: (b) loud WARN, implemented as (c) narrowed to two high-precision arms, with (d) as the prescribed-remedy runbook line.** The brief explicitly allows this combination.

**Decisive new evidence (measured this session, live repo):** over a 14-day main window (merge-base `6290ac953615`, 2026-08-09 → HEAD, 18,444 commits), 189 commits touched SPECS-scope paths. Of these, **82 commits bundled a lint-family member with a non-lint spec doc** (dominant shapes: a workflow-fix landing its lint check + the spec prose naming it; a session's agent-memory riding the same explicit-path commit) and 26 bundled a spec with sibling-glob files. Real gate-redding half-sync incidents in the same period: ~3 (#2321, #2168 × 2). A commit-grain "same-diff pair ⇒ WARN" detector on a lint-dirty branch — every workflow-fix branch — would therefore have fired ~82 times against ~3 true positives (precision ≈ 3%): alert fatigue that trains orchestrators to skip the WARN, worse than no detector. The v1 marker's general predicate (c) is thereby evaluated on evidence and NARROWED, not adopted wholesale — the repo's same-turn-commit discipline (CLAUDE.md § uncommitted tracked state) structurally bundles unrelated files into single commits, breaking the "one commit = one coupling" premise.

- **(a) Path-scoped cap splice — REJECTED.** It would mechanically edit `scripts/workflow_lint.py` while the branch is MID-EDIT of that very file (the lint family is dirty precisely because the deliverable touches it — #2168's deliverable WAS a new lint check); an automated source-level splice into a moving deliverable risks corrupting it, and the failure mode (broken lint binary on the branch) is strictly worse than the disease (a pre-diagnosed red). Decisive detail: the agent-caps data file cannot be spliced safely either — `check_agent_spec_size`'s own FAIL message instructs updating `_MIGRATION_SNAPSHOT in tests/test_workflow_lint_agent_spec_caps.py in lockstep`, so a caps-file splice without that test's snapshot manufactures a NEW half-sync. The splice is a coupling hydra.
- **(b) Loud WARN — ADOPTED** as the action grade. The Goal's own disjunction sanctions it ("— or must WARN loudly that it does not"). It converts a deterministic multi-failure gate red (8 failures / ~2 h in #2168) into one named, pre-diagnosed line with the remedy attached.
- **(c) General same-diff-pair detector — NARROWED.** Adopted in the two forms the measurement supports: **Arm A** (state-based cap coherence — strictly stronger than commit-grain detection for the cap class: it also catches split-commit landings, and its discriminator ⟨doc == origin bytes ∧ branch cap rejects ∧ main cap admits⟩ is exactly the "red on bytes identical to origin/main" fingerprint, so false positives require main itself to be red) and **Arm B** (issue-number-keyed sibling split — the sibling namespace is issue-keyed by construction, so fresh/stale bucket mixing is a true structural signal, upper-bounded at 26 candidate commits/14 d and further gated by actual branch-side divergence). The unrestricted commit-grain form is documented as measured-and-rejected in the helper docstring.
- **(d) Merge origin/main at sync time — REJECTED as an automatic action, ADOPTED as the prescribed remedy.** The hook ban on repo-root merges does NOT reach here (Step 5a operates in the worktree via `git -C "$WT"`, and the #2311 paragraph in this very file already prescribes exactly this merge manually) — the blocker is unattendedness: the #2168 merge hit a real conflict (`tests/step9c_workflow_invariant_manifest.txt`, resolved as a union by a human-attended session), and an automatic merge inside a review round would mutate branch history mid-round with no one owning conflict resolution. Every WARN's remedy line prescribes the merge, so the proven fix is one copy-paste away.

**Fail-safe direction (constraint 2, stated explicitly): WARN / fail-open, diverging from the sibling probe's REVERT convention — justified.** The probe reverts on undecidability because keeping an unsatisfiable synced test breaks gate STRUCTURE (collection errors, absent dispatchers — rc 127) and clobber-adjacent hazards demand containment. The detector guards neither: it mutates nothing, and the state it diagnoses is main-identical bytes plus a stale constant — a diagnosable red, not a structural break. Blast radius sizing: a false REFUSE at this call site wedges EVERY ensemble fan-out fleet-wide (~16 concurrent sessions × every review round) on a diagnosis tool's bug; a false WARN is one noisy line. Asymmetry decides: advisory. The helper's own crash (rc != 0, including the 60 s timeout fence) prints the loud unavailable-line to stderr with the exact manual re-run command and continues.
