# Plan — Issue #654: Per-layer query displacement of the context-conditioned residual stream (Qwen-2.5-7B-Instruct)

HTML render: `.claude/plans/issue-654.html`

## §0.0 TL;DR (plain English)

- **What I'll run:** I give the model a piece of context (a persona instruction, a generic instruction, a few worked examples, or a snippet of a real chat), then a user question. With one pass through the model I read out the internal state at two spots — right after the context, and right after the question — and at every layer I ask "how much did adding the question move the state away from where the context left it?" I do this for hundreds of context-and-question pairs and watch how that movement changes from the earliest layers to the last.
- **What I expect:** early layers will still look mostly like the context (the question barely moves them), and somewhere in the middle-to-late layers the state will swing toward the question. I also expect persona contexts to "stick around" a bit more than generic instructions or example sets.
- **What would change my mind:** if, once I subtract the floor that any two different-ending texts share, a question-end state is no closer to its own context than to a random other context — that would mean the last-token state mostly just tracks the last few words, and there's no real context memory to speak of at this readout spot.

## §0. Plan Summary (technical)

- **Training:** none — forward-pass measurement only on base `Qwen/Qwen2.5-7B-Instruct` (bf16), `output_hidden_states=True`, ChatML via `apply_chat_template`.
- **Hyperparameters (load-bearing):** layers full 0–27 + anchors [7,14,21,27] (`Source: #648`, config `num_hidden_layers=28`); centering = `global_mean` (`Source: #536`); CKA = linear CKA on Gram matrices (`Source: 1905.00414`); shuffled-pair floor (`Source: persona-distance-metrics.md`); WildChat slice via `issue617_build_wildchat_slice.py` (`Source: #617`); seed 42.
- **Baselines / controls:** shuffled-pair (token-identity/anisotropy floor); raw cosine alongside centered; a same-position with/without-query companion read (`Source: 2601.06599`) that removes the different-token confound.
- **Loss surface:** N/A — no training; readout is the residual stream (post-block) at the last token of the context span and the last token of the query span, single forward pass over the full ChatML prompt.
- **Compute:** 1× A100-80 / H100, `eval` intent, single HF forward-pass loop over ~924 forwards × 28 layers, no parallelism axis (model load dominates); CPU metric/plot phases off-pod on the VM. `Estimated GPU-hours (total): 3`.
- **Evaluation:** per-layer per-pair centered cosine (context-end vs query-end), trajectory vs the shuffled-pair floor band; CKA(context-bank, query-bank) per layer; the companion same-position contrast. "Worked" = a clean, interpretable per-layer displacement curve that sits above the shuffled floor at some depth and separates the three hypotheses.
- **Risks (top 2):** (1) the last-token position is the *weakest* readout for persona content (`2507.21509` ablation) — mitigated by centered cosine + CKA (anisotropy-robust) + the companion read; (2) ChatML span-boundary indexing must pin the context-end and query-end token positions exactly, or the two reads drift — mitigated by explicit offset asserts wired into the extractor + a smoke check that prints decoded spans.

## §1. Goal + hypotheses

**Goal (verbatim frontmatter):** Measure, per layer in Qwen-2.5-7B-Instruct, how much appending a user query displaces the last-token residual-stream state away from the context-established state (centered cosine + CKA + shuffled-pair floor) across persona / generic-instruction / ICL / wild-chat contexts and varied queries, to characterize context-dominant vs query-dominant layer regimes.

The three competing hypotheses (verbatim from the body), each mapped to the diagnostic that distinguishes it:

| Hypothesis (verbatim) | Distinguishing diagnostic |
|---|---|
| **H1 (early-context, late-query):** early layers preserve the context state (high similarity above floor), mid/late layers integrate the query (similarity drops toward floor). Consistent with ICL task-vector (2310.15916) and context-shapes-truth (2601.06599) layer-band findings. | The per-layer centered-cosine curve is high (well above the shuffled-pair floor) early and DROPS toward the floor across mid/late layers — a monotone-ish decay. CKA(context-bank, query-bank) high early, falls with depth. The ICL mechanism (2310.15916) is exactly this: the context "task vector" is computed in the first L layers at the readout position, then later layers take that vector + the query. |
| **H2 (uniform query dominance / no persistence):** once the anisotropy floor is subtracted, the query-end state is no more similar to its own context-end state than to a random context's — token identity dominates, no meaningful context persistence at the last-token position. | Centered cosine of matched pairs ≈ shuffled-pair floor at ALL layers (matched-minus-shuffled gap ~0 within the per-layer spread). The falsification of any context-persistence reading at this position. |
| **H3 (context-type-dependent):** persona contexts persist into the query-end state more (or less) than generic-instruction / ICL / wild-chat contexts. | The four per-layer curves (persona/generic/ICL/wildchat), each read against its own within-type shuffled floor, separate — the matched-minus-shuffled gap differs by context type at one or more depths. A context_type × layer interaction. |

H1 describes the depth profile, H3 whether that profile depends on context type, H2 is the null both rest on. The analyzer assigns confidence; §7 gives diagnostic thresholds, not confirmation conjunctions.

## §2. Method delta vs prior related work

**vs #594 (context-vector geometry — the sibling, not the duplicate).** #594 reads ONE position (the assistant-header newline / post-prompt generation slot) per context, builds a 50-context bank, and asks a *family-clustering* question (do same-genre contexts cluster, with a mid-stack purity peak). It never appends a separate query and never compares two within-prompt positions. This experiment reads TWO positions in the same prompt (context-span end vs query-span end), and the DV is the *displacement between them* per layer — a within-prompt position-contrast question, not a between-context clustering question. I reuse #594's WildChat loader, ChatML conventions, the `global_mean` centering, and the shuffled-pair/permutation-floor machinery; the read positions, the pairing structure, and the CKA metric are new.

**vs #634 (role-vs-persona context bank).** #634 builds a bank distinguishing *role* framings from *persona* framings and reads geometry at the prompt-to-answer site; its question is whether role and persona occupy distinguishable subspaces. No downstream query, no two-position contrast. I borrow "context type is a factor" but instantiate four orthogonal context tiers and measure query displacement, not role-vs-persona separation.

**vs 2310.15916 (ICL Creates Task Vectors, Hendel/Geva/Globerson).** They show the context (demonstration set S) is compressed into a task vector θ in the first L layers at the last position, then later layers apply θ to the query — established by activation *patching* (copy θ from a dummy-query run into a query-only run); metric = downstream task accuracy under patching, on synthetic ICL tasks. I do NOT patch; I observe the natural forward pass and measure cosine/CKA displacement of the last-token state between context-end and query-end positions, across four realistic context tiers (not just ICL demos). Their early-θ/late-application picture is the mechanism H1 predicts a displacement signature of — an observational metric-based test of the layer-band split they established causally, generalized beyond ICL.

**vs 2601.06599 (How Context Shapes Truth, Adarsh/Maistro/Lioma).** They read the residual at the *final prompt token* (the slot generating the first completion token, "aggregates information from the entire input via causal attention"), per layer, and compare a *truth direction* (true-minus-false difference vector) *with vs without context* via directional change θ and relative L2 magnitude; finding = orthogonal early, converging mid, stable/increasing late (the layer-band shape H1 borrows). Differences: their contrast is context-present vs context-absent at ONE position (mine = context-end vs query-end at TWO positions); their construct is a truth difference-vector (mine = raw last-token state similarity); their factor is relevant-vs-random context (mine = context-type and query topicality). I adopt their exact same-position with/without-query design as my **companion read** (§5) to remove my different-token confound.

**New code surfaces (signatures):**

(a) Dual-position extractor — **new function in `src/explore_persona_space/analysis/probes.py`**, alongside the unchanged `extract_residual_stream_activations` (so #594/#553/#634 call sites keep working):

```python
@torch.no_grad()
def extract_dual_position_activations(
    model, tokenizer,
    prompts: Sequence[str],                 # full ChatML strings ending at the assistant-gen marker
    positions: Sequence[tuple[int, int]],   # per-prompt (context_end_idx, query_end_idx) token offsets
    layers: Sequence[int] | None = None,
    device=None,
    readout_position: int | None = None,    # optional 3rd slot (companion read); -1 = last token
) -> dict[str, torch.Tensor]:
    """One forward pass per prompt; reads >=2 token positions at every layer.
    Returns {"context_end": (n, n_layers, hidden), "query_end": (n, n_layers, hidden),
             ["readout": (n, n_layers, hidden)]} fp32, CPU.
    Mirrors extract_residual_stream_activations: out[L+1]=post-block-L residual,
    add_special_tokens=False, batch 1. Asserts 0 <= c_idx < q_idx < seq_len per prompt."""
```

Core loop:
```python
n_layers = model.config.num_hidden_layers      # 28
for i, (prompt, (c_idx, q_idx)) in enumerate(zip(prompts, positions)):
    ids = tokenizer(prompt, return_tensors="pt", add_special_tokens=False).input_ids.to(device)
    assert 0 <= c_idx < q_idx < ids.shape[1], (i, c_idx, q_idx, ids.shape[1])
    hs = model(ids, output_hidden_states=True).hidden_states     # len 29; hs[L+1]=block L out
    for j, L in enumerate(layers):
        out["context_end"][i, j] = hs[L + 1][0, c_idx].float().cpu()
        out["query_end"][i, j]   = hs[L + 1][0, q_idx].float().cpu()
        if readout_position is not None:
            out["readout"][i, j] = hs[L + 1][0, readout_position].float().cpu()
```

Token-offset derivation (in `issue654_build_battery.py`, recorded per pair, asserted in extractor):
```python
# context_end = last token of the system(+ICL) block, before the user turn opens
ctx_only = tokenizer.apply_chat_template(context_messages, tokenize=False, add_generation_prompt=False)
ctx_ids  = tokenizer(ctx_only, add_special_tokens=False).input_ids
context_end_idx = len(ctx_ids) - 1
full = tokenizer.apply_chat_template(context_messages + [{"role":"user","content":query}],
                                     tokenize=False, add_generation_prompt=True)
full_ids = tokenizer(full, add_special_tokens=False).input_ids
query_end_idx = _last_token_before_assistant_marker(full_ids, tokenizer)
assert full_ids[:len(ctx_ids)] == ctx_ids   # context block is a stable PREFIX of the full prompt
```
The prefix assert is the key invariant: ChatML renders the system block identically whether or not a user turn follows, so context tokens are a strict prefix and `context_end_idx` is well-defined in both renders. Build fails loud CPU-side if violated. Smoke prints `tokenizer.decode(full_ids[context_end_idx])` and `[query_end_idx]` for 8 pairs.

(b) Linear CKA — **new additions to `src/explore_persona_space/analysis/representation_shift.py`** (next to `compute_cosine_matrix`):
```python
def linear_cka(X: torch.Tensor, Y: torch.Tensor) -> float:
    """Linear CKA (Kornblith et al. 2019, arXiv 1905.00414). X:(n,d_x), Y:(n,d_y), same n.
    Column-center both; HSIC_lin(X,Y)=||X_c^T Y_c||_F^2;
    CKA = HSIC_lin(X,Y) / sqrt(HSIC_lin(X,X)*HSIC_lin(Y,Y)). Feature-space form, O(n d^2).
    Returns scalar in [0,1]. Asserts X.shape[0]==Y.shape[0] and n>=2."""
def cka_per_layer(bank_a, bank_b) -> list[float]:
    """bank_*: (n, n_layers, hidden). linear_cka(a[:,L], b[:,L]) for every L."""
```
**Unit tests** (`tests/test_linear_cka.py`, CI, no GPU): `CKA(X,X)==1`; `CKA(X, X@Q)==1` for random orthogonal `Q`; `CKA(X, 3.7*X)==1`; `CKA(X,Y)==CKA(Y,X)`; two independent Gaussians give CKA ≤ ~0.15 at n=200, d=64.

## §5. Construct + measurement (formal)

For pair *i* = (context *c*, query *q*) and layer *L*, the extractor gives two vectors in ℝ³⁵⁸⁴: context-end residual `a_ctx[i,L]` (last token of the rendered context block) and query-end residual `a_qry[i,L]` (last prompt token before the assistant marker). Both are on-distribution — the model's actual residual stream at the two positions the body names, in one natural forward pass, no teacher-forced canned continuation.

**Metrics:**
- **Per-pair centered cosine (PRIMARY DV).** Per layer, stack context-end bank `A_ctx[L]=(n_pairs,3584)` and query-end bank `A_qry[L]`, globally mean-center EACH bank on its own mean (canonical `compute_cosine_matrix(centering="global_mean")`, #536), L2-normalize, per-pair cosine `centered_cos[i,L] = ⟨ĉtx[i,L], q̂ry[i,L]⟩` where `ĉtx[i,L]=normalize(a_ctx[i,L] − mean_i a_ctx[·,L])`. **Global-mean definition:** the subtracted mean is over all *n_pairs* rows of that bank at that layer (context-end mean for the context bank, query-end mean for the query bank — banks centered on their own centroids, not cross-centered).
- **Shuffled-pair floor.** For a derangement π (i ≠ π(i)), `shuf_cos[i,L]=⟨ĉtx[i,L], q̂ry[π(i),L]⟩`. Floor = mean ± 2.5/97.5 band over B=1000 derangements (seed 42). Headline read = **matched-minus-shuffled** = `mean_i centered_cos[i,L] − mean_i shuf_cos[i,L]` per layer, with the band giving significance.
- **Raw per-layer cosine.** Same with `centering="none"`, reported alongside with the anisotropy caveat (raw cosine inflated, 2401.12143; centered + CKA correct for it).
- **CKA per layer.** `cka_per_layer(A_ctx, A_qry)` → linear CKA between context-end and query-end banks per layer (paired rows = same pairs). "Does the context-induced geometry survive to the query position as whole-bank structure" — anisotropy-robust, rotation-robust. Also report CKA against the shuffled bank as floor.
- **Companion same-position contrast (control / co-primary, 2601.06599).** Per context *c*, a second forward over the context-only prompt (no query) and a third over context+query; read the SAME slot (assistant-generation position) in both; per-layer cosine of (context-only readout) vs (context+query readout). Removes the different-token confound (same position, only difference = query presence) — the cleaner query-influence operationalization. Reported as a parallel curve; disagreement with the two-position read is itself a finding (the two-position read carries a token-identity component the same-position read does not).

## §7. Success / kill criteria (diagnostics, not pre-registered conjunctions)

- **H1 supported if:** matched-minus-shuffled centered-cosine clearly above its floor band early (≥ 2 floor-SD above at some layer in 0–10) AND drops toward the floor (within ~1 floor-SD) late (20–27) — a depth decay; CKA(L,L) shows the same shape. Magnitude read descriptively (no invented absolute threshold).
- **H2 supported if:** matched-minus-shuffled within the floor band (≤ ~1 floor-SD) at ALL layers. The falsification of context persistence at this position; a reportable outcome.
- **H3 supported if:** the four per-type matched-minus-shuffled curves (each vs its own within-type floor) separate by more than their bootstrap spread at ≥1 depth (e.g. persona stays above floor ~K layers deeper than wildchat). A context_type × layer interaction.
- **Sanity / kill:** position asserts fail on > 5% of pairs (span-boundary indexing broke) → halt + fix before any read (caught pre-pod by build asserts + smoke). If raw and centered cosine give qualitatively opposite depth shapes, report both and flag the anisotropy dependence (don't pick one silently).

These are observational diagnostics, not run-stopping gates, and are mutually consistent (H1/H2/H3 partition the outcome space; no two demand contradictory signs on the same measurement). **No gates — short run (~3 GPU-h, < 4h) / pre-verified observational hypothesis.**

## §10b. Plan deviations allowed vs must-ask

**Allowed (autonomous, recorded in run meta):** shifting persona/generic/ICL/wildchat instance counts ±~20% if a few prompts crash tokenization or WildChat shortfalls (14→12 personas, 30→24 wildchat); falling back `WildChat-1M` → `lmsys/lmsys-chat-1m` on candidate shortage (the #617-named fallback); adjusting ICL block depth N (2–6 exchanges) to keep context length comparable; batch 1→small-batch IF position offsets are re-asserted per row; anchor-layer choice for scatter panels.

**Must-ask / pivot-per-workflow:** dropping a whole context-type tier (changes H3 coverage + the Goal's "across persona/generic/ICL/wild-chat" scope); changing the read positions away from context-end/query-end (changes the construct); swapping the centering mode or the primary metric (breaks comparability with the project's persona-distance line); adding training of any kind (the Goal is measurement-only).
