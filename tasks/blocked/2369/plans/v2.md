# Plan v2 — #2369 workflow-fix: eliminate module-level wall-clock capture in tests/test_tick_triage.py (+ sibling), add drift regression pin

## Requirement + acceptance criteria

**Requirement.** `tests/test_tick_triage.py:37` captures `NOW = time.time()` at module import (pytest collection), while `tick_triage.triage()` measures marker/transcript ages against the live clock at test execution. In any pytest session where the file executes ≳20 min after collection, "fresh" fixture events silently age past tick_triage's staleness thresholds, failing 4–12 tests against innocent branches (incidents: #2158 Step 9c gate, 22.2 min drift → 4 failures; #2168 gate, ~38 min drift → 12 failures; controlled experiment on #2168 proved wall-clock drift alone reproduces the exact failure set on main's own code).

**Acceptance criteria (from the task body, restated verbatim-equivalent):**
1. The 4 named tests (`test_api_error_after_marker_returns_stale_redrive`, `test_api_error_after_marker_falls_open_on_missing_transcript`, `test_api_error_probe_kill_switch`, `test_api_error_probe_incident_1689_content_string`) pass when executed with a simulated ≥30-min collection→execution drift (the #2168 instrument: a pytest plugin aging `test_tick_triage.NOW` at `pytest_collection_finish`).
2. They still pass in isolation (full-file run, no drift).
3. A regression pin prevents reintroduction of module-level wall-clock capture in this file (and the sibling carrying the same pattern).
4. Repo-wide sweep for other module-level clock captures over age-sensitive predicates is performed and dispositioned (done at clarify time; classification below).

## Method delta (vs prior related work)

The #2361 live-subagent-screen tests in the SAME file already established the drift-immune pattern (per-test `now = time.time()`, threaded as `triage(..., now=now)` — see the comment block at test_tick_triage.py:1417-1419 naming this exact "#2369 wall-clock-aging trap"). This plan generalizes that protection to the ~51 legacy `triage()` call sites and ~15 direct `NOW` consumers WITHOUT threading `now=` through every site: a single module-global refreshed by an autouse fixture bounds fixture-age drift to intra-test elapsed time (milliseconds–seconds against ≥5-minute thresholds), a strictly smaller diff with the same drift bound. AST verification (2026-08-27) confirmed `NOW` is never read at module scope or in decorators in either file, so per-test refresh is semantics-preserving.

## Design + concrete diffs (file paths)

**Change 1 — `tests/test_tick_triage.py`** (the load-bearing fix):
Replace line 37:
```python
NOW = time.time()
```
with:
```python
# #2369: NOW is a PER-TEST clock anchor, refreshed by the autouse fixture
# below. A module-level `time.time()` capture silently ages every "fresh"
# fixture event in long gate sessions (20-40 min collection→execution
# drift = 4-12 spurious failures; incidents #2158/#2168). The 0.0
# placeholder fails loudly (~56-year ages) if the fixture is ever removed.
NOW: float = 0.0


@pytest.fixture(autouse=True)
def _fresh_now():
    """Refresh the clock anchor at TEST SETUP so fixture ages are measured
    from test execution, not module import (#2369)."""
    global NOW
    NOW = time.time()
```
All existing consumers (`_event`, direct `_iso(NOW - x)` builders, explicit `now=NOW` threads) read the global at call time inside test bodies, so they inherit the per-test anchor unchanged.

**Change 2 — `tests/test_async_gate_rung0.py`** (same pattern, defense-in-depth):
Same replacement for its line-53 `NOW = time.time()` + same autouse fixture. Its current consumers are append-order/explicit-age predicates (verified 2026-08-27: `compute_issue_verdict` receives literal ages; `open_async_ask`/`ask_gate` are append-order), so it is likely drift-safe TODAY — but it carries the identical banned pattern and future tests in the file would inherit the trap; fixing it now costs 6 lines.

**Change 3 — NEW `tests/test_tick_triage_drift_regression.py`** (the regression pin, 2 tests):
- **Test A (drift simulation — acceptance criterion 1).** Runs pytest in a subprocess (`sys.executable -m pytest`, `cwd=` repo root so `pyproject.toml` addopts + `tests/conftest.py` resolve identically to the gate environment) on exactly the 4 named test ids, with a drift-injection plugin (written to `tmp_path`, put on `PYTHONPATH`, loaded via `-p`) whose `pytest_collection_finish` hook ages the collected module's clock anchor by 2400 s — the SAME instrument the #2168 controlled experiment used to reproduce the incident. **Non-vacuity contract (critic round-1 blocking finding):** `tests/__init__.py` exists, so under pytest prepend import mode the module key is `tests.test_tick_triage` — the plugin MUST resolve the target STRICTLY via `sys.modules["tests.test_tick_triage"]` (raise `KeyError` fail-loud on a miss; NEVER a fresh import after a `sys.path` insertion, which would create a duplicate module object whose `NOW` the collected tests never read and make the pin permanently, vacuously green), and print an injection sentinel (`DRIFT-INJECTED tests.test_tick_triage NOW-=2400`) only AFTER a successful setattr. Test A asserts the sentinel is present in captured subprocess stdout IN ADDITION to `returncode == 0`. Bounded cost: 4 tests in a subprocess, ~10-20 s.
- **Test B (mechanical pin — acceptance criterion 3).** AST-parses both pinned files (`test_tick_triage.py`, `test_async_gate_rung0.py`) and FAILs on any module-scope `Assign`/`AnnAssign` whose value contains a call to `time.time`, `time.monotonic`, `datetime.now`, or `datetime.utcnow` (walk the value expression; message points at #2369). Scoped to the two pinned files by design — see sweep disposition. Known disclosed false negatives (non-blocking critic note): alias escapes (`from time import time; NOW = time()`, or a wrapper `NOW = _get_now()`) are not matched — name them in a one-line comment in the pin test; Test A (non-vacuous per its sentinel contract) and code review are the catching arms for those.

**Sweep disposition (acceptance criterion 4, evidence from clarify pass 2026-08-27):** `tests/test_janitor_tmp_scratch_sweep.py:48`, `tests/test_vm_disk_guard_slurm_src.py:45`, `tests/test_janitor_noncanonical_caches.py:52` carry `AGED_TS = time.time() - 100*3600` — deliberately-OLD anchors ~100 h past a 48 h window; collection→execution drift only widens the age in the SAFE direction, so they are NOT in scope (no change). The pin is deliberately NOT widened to all of `tests/` because it would false-positive on exactly these safe-direction anchors.
