# Implementation plan — EPS #2644: Claude subagent model-pool exhaustion recovery

## Goal and requirement / acceptance criteria

Goal (verbatim): "Give the five Codex-ensemble review sites — and the `reconciler` in particular — a defined recovery path when the SUBAGENT MODEL POOL is exhausted, which today has none."

This is an infrastructure-only workflow-surface change. It must not modify experiment code, `configs/`, task state, or the deliberate cross-project `CLAUDE_CODE_SUBAGENT_MODEL` pin.

The implementation must satisfy the body’s five numbered acceptance criteria:

1. Add a documented model-quota-exhaustion ladder that says which generic escapes do not apply at the reconciler and why the prohibition is about validity, not cost.
2. Distinguish a model-quota pool from a per-minute 429 bucket; do not run the 0/1/2/4/8-minute retry ladder against the pool.
3. Define the continuing-outage terminal after explicitly deciding among parking, orchestrator inline fallback, and a persisted sentinel. Preserve independence or record its loss durably and grepably.
4. If a sentinel is used, make it fail open on missing, unreadable, corrupt, expired, or implausible content.
5. Keep existing workflow lint and specification tests green.

The chosen design is layered Acceptance 3(c) + 3(a), with a narrow cross-vendor rung before the terminal where it is valid:

- Persist a fail-open Claude-subagent quota sentinel with a 60-minute heuristic TTL and an observed-death counter. The Claude API error has no reset timestamp, so the sentinel explicitly records `parse_ok: false` and `ttl_source: heuristic-60m-no-reset-in-error`; it never pretends to know the provider’s reset time.
- During the quiet window, short-circuit same-pool subagent spawns. At expiry, make exactly one probe for the same role + round + version. A second quota death with no durable verdict reaches the site’s existing terminal rather than starting another hold/retry chain.
- At a non-resolver review site, the orchestrator may bypass a dead Claude `codex-*` prompt-composer and directly dispatch the already-contracted Codex reviewer prompt only when Codex is not reviewing its own artifact. This loses two-provider ensemble diversity and therefore posts a fixed durable disclosure token.
- At the reconciler, Codex substitution is invalid because one input is Codex’s own verdict. Marker-mode sites retain `epm:failure v1` + `failure_class: infra` + `status:blocked` + notification + CRON-TEARDOWN after the post-hold probe fails. The in-context planner site retains its existing conservative adopt-more-severe terminal, but must durably disclose that no independent resolver returned.
- Do not extend the `[epm-inline-fallback]` carve-out to quota exhaustion. Orchestrator-authored review/adjudication would erase the independent judgment and does not repair a shared pool. Direct composition of a prompt that is still answered by Codex is a different mechanism and receives a different fixed token.

## Method delta

The prior related work has two unsuitable halves. The refusal and autocompact-thrash ladders reduce trigger density or context footprint; a model-pool quota is insensitive to both, and `CLAUDE_CODE_SUBAGENT_MODEL` makes the refusal ladder’s per-call model pin inert. Step 5b item 4 then fails loud after one immediate bounded respawn, which turns a potentially hour-scale outage into a blocked task. This plan inserts a quota classifier before those context-size remedies, replaces repeated short retries with one 60-minute quiet window and one probe, and only then uses the already-defined terminal.

The sentinel mirrors the shipped Codex precedent in path override, atomic persistence, read escape, and the two-sided `now < until_unix <= now + 45 d` plausibility window. It deliberately differs in one field: Codex parses a provider reset time, whereas Claude supplies none. The Claude sentinel therefore stores a declared heuristic TTL plus `first_detected_at_iso`, `last_detected_at_iso`, and `observed_deaths`; repeated observations extend the quiet window but preserve the episode’s first-detection key.

The live #2644 route is accounted for but not silently generalized. The orchestrator composed a prompt and dispatched `codex_task.py` directly because every Claude planner spawn and every Claude `codex-*` composer was unreachable. Codex then authored the plan. That demonstrates transport reachability, but a planner-role artifact contract is outside the currently documented reviewer-only use of `codex_task.py`. This plan draws an explicit boundary: direct Codex prompt dispatch is sanctioned here only for existing Codex reviewer contracts; generic planner/implementer artifact generation remains an off-contract deviation requiring its own workflow change. Because this plan is Codex-authored, a Codex-only plan critic would also be invalid self-provider review; the owed Claude critic must run after pool recovery.
