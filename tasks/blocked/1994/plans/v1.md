**Why path 1 over path 2 (daemonize/join at workflow_lint.py:10080):**
- **Blast radius.** Path 1 touches ONLY the gate-timeout arithmetic; the linter's runtime behavior is unchanged. Path 2 changes `workflow_lint.py`'s ThreadPoolExecutor lifecycle, which affects EVERY invocation across the fleet (`--check-*` runs, pre-commit hooks, `/daily` route-2 driver, Step 9c/10d gate tree constructions). Any regression in guard-hook probing rc semantics is a fleet-wide breakage.
- **Root-cause diagnosis is unfinished.** The `with ThreadPoolExecutor(...) as ex:` block ALREADY calls `shutdown(wait=True)` on exit. The interpreter-exit residue is most plausibly Python's process-wide `concurrent.futures.thread._threads_queues` atexit handler joining across all worker threads ever created by any pool in the process — daemonizing them would require `ThreadPoolExecutor`-internal patching or a private hook (`ThreadPoolExecutor._make_thread` in the CPython source), which is neither documented nor stable across Python versions. The safer root-cause fix — refactor to a module-level singleton executor reused across invocations — is a larger design change unsuitable for a workflow-fix scope.
- **Sibling precedent.** `tests/test_workflow_lint.py` exhibits the SAME slow-exit family (body prose confirms) and has been handled by a surcharge since #1642/#1646. This plan follows the established precedent for this class.
- **Goal alignment.** The literal Goal ("Stop … from wedging implementers' gate-matched local pytest runs") is DIRECTLY satisfied by a surcharge — the file gets its own budget in the gate's timeout arithmetic. Fixing the underlying leak is one path to satisfying that Goal but not the only one; the Goal's "OR" formulation names surcharge registration as an equally-valid resolution.

## §7 Risks

- **Surcharge value too low.** If the hang wall exceeds 1200 s in production gate runs, mapped legs still time out. Mitigation: the note in the dict entry names the raise-to-2000 s follow-up.
- **Surcharge value too high.** A gate leg selecting ONLY this file allocates ≥1350 s of budget for what is normally ~40 s of work. Cost: on the rare leg where the hang does NOT reproduce, the gate waits its full budget for pytest to exit. This is bounded by the ONE file × ONE local gate run per implementer round; acceptable.
- **Test file is NOT the direct offender.** The 852-line file's 39 `check_phase_done_reserved` tests may not themselves call the ThreadPoolExecutor site. The leak may come from another `workflow_lint` call inside those tests. Surcharge is CAUSE-AGNOSTIC — it widens the budget regardless of which upstream function residues threads. Path 2 would be sensitive to this misdiagnosis.
- **Alternative not addressed.** Path 2 (daemonize/join at L10080) is deferred, not refuted. If the same slow-exit family accretes many more files, a followup ticket to solve at workflow_lint.py's module level would be justified.
