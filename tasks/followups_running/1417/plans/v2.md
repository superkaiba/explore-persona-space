# Plan — Issue #1417: Which property scopes the shared assistant context→answer map: helpful register, or speaking to a user?

## 0.0 TL;DR (plain English)

- **What I'll run:** I take the same 4,724 real user questions the parent experiment used and have the model answer them under five different framings of "who is answering and how": a normally helpful assistant, a rude-but-still-correct assistant, an evasive assistant, a textbook-style passage that answers the topic without talking to anyone, and an assistant answering another AI instead of a human. For each framing I re-fit the parent's question→answer prediction map and check whether it is the same map as the normal assistant's, once you allow a change of coordinates.
- **What I expect:** The map survives losing the friendly tone (the rude assistant still carries it) but breaks when there is no interlocutor at all (the textbook framing) — that is, the map is about answering *someone*, not about being *nice*.
- **What would change my mind:** If the rude cell breaks the map while the textbook cell keeps it, the map is about the helpful-answer register. If both keep it, the map is generic question-answering structure and the story-framing failure in #825/#1310 was about narrative itself; if both break it, the two properties are jointly required.

## 3. Hypothesis

The shared context→answer map is tied to user-directed dialogue (H2), not to the helpful register (H1). Specific falsifiable predictions on the two load-bearing cells (verdicts defined in §6):

| Outcome | C2 rude-but-informative vs reference | C4 addressee-free exposition vs reference |
|---|---|---|
| **H1 (helpful-only)** | Distinct | Shared |
| **H2 (user-directed-only)** | Shared | Distinct |
| **Conjunction (both required)** | Distinct | Distinct |
| **Neither (generic QA structure)** | Shared | Shared |

Per-cell verdict quantity: **REL** = held-out R² of the reparameterized cell map predicting reference answers (A_ans ∘ M_cell ∘ A_ctx⁻¹ on reference rows, shared folds) ÷ the within-reference ceiling R², at L19, context arm, instruct model primary (base companion). Define ΔREL = REL − 0.5 (boundary grounded midway between the two demonstrated regimes: shared ≈ 1.0 — #825 Result 2's 0.673/0.673; story-distinct ≈ ~0 — #825 Result 4 "reparameterization does not recover it").

DISJOINT and exhaustive: Shared ⇔ ΔREL > 0 AND ΔREL's 95% CI excludes 0 on the positive side; Distinct ⇔ ΔREL's 95% CI is wholly below 0; Inconclusive ⇔ otherwise.

The H-outcome is the deterministic lookup of the (C2, C4) verdict pair in the table above (9 combinations: 4 map to the labeled rows, any pair containing Inconclusive maps to "Inconclusive — report graded REL profile"); exhaustive by construction. Secondary refinements (no verdict weight): C3 places the evasive gradient point; C5 splits "a user" vs "any interlocutor" within H2; C1 controls instruction presence. A C2 "Distinct" verdict counts toward H1 ONLY if C2 passes the content-collapse check (§6); a collapsed C2 demotes the H1 read to "unresolved — content confound" (pre-registered).

**Per-cell span definitions (both mapping arms — fixed here, per the standing rule):**
- **Context vector** `x_ctx`: residual activation at the LAST token of the rendered prompt (end of `<|im_start|>assistant\n` generation header for chat cells; last token of `Passage:` for C4; last token of `Assistant:` for C0′) — the #825 end-of-context slot.

Chat cells C1/C2/C3/C5: last token of the rendered system block + user header (everything before the query characters). C4: last token of the preamble (before `Topic:`). ## 11. Decision Rationale

- **Ridge recipe (λ grid logspace(-2,4,13), GCV + inner-group-cv fallback, K=5 conv-grouped folds seed 0, FROZEN_LAYERS (14,18,19,26), headline L19, 20 shuffle nulls, 1000-draw bootstrap, matched-n 5 draws seeds 931+k).** Why: the frozen instrument — identity of the recipe is what makes cell maps comparable to the reference. Source: `#825`/`#1335` (values read from `issue825_fit_cells.py` + `issue1310_common.py` on main). Alternatives: refitting λ per battery pair rejected (recipe drift breaks comparability).
- **Generation params T=1.0 / top_p=0.95 / max_tokens=1024 / seed=42 / n=1.** Why: parent-exact — the reference cells' answers were produced this way; changing sampling would smuggle a second variable. Source: `#825` Track-S regen (`issue825_gen_conversations.py` docstring). Alternatives: greedy rejected (#825 round 8: greedy own-continuations are decoding-atypical).
- **Cell renders C1–C5 (verbatim §4.1).** Why: minimal-pair wording — C5 = C1 + interlocutor clauses; C2/C3 = C1's slot with register content swapped; C4 preserves verbatim query under a topic header. Source: this plan's design (framing text is the manipulated variable, not a tuned hyperparameter); structure follows the #1335 rung-registry pattern (`Source: #1335`). Alternatives: rewriting queries as noun-phrase topics for C4 rejected (breaks same-query pairing); "Nova:" speaker prefix in C5's user turn rejected (second variable).
- **Judge: Sonnet 4.5, graded 0–100, threshold 50, reason-then-score, max_tokens=300, Batch API.** Source: `.claude/rules/llm-judging.md` rules 1/6/7/23 + CLAUDE.md judge pin. **N=3 draws, T=1.0: `ungrounded — needs smoke-test`** (rule 4 pins N≈5–10 for ranking DVs; this is a keep/drop filter where a smaller N suffices — the smoke's ~200-row pilot reports test-retest agreement at N=3 and bumps to N=5 if per-row keep decisions flip >5%). Alternatives: N=1 rejected (no draw-noise handle); substring/rule classifier banned.
- **Keep floor 50% per cell-model.** Why: n≈2,400 still fits tightly (#1310 fit cells at n 1.5–3K); grounded as a graceful floor, not a target. Source: `#1310` (n-regime precedent); the floor value itself `ungrounded — needs smoke-test` (yields unknown pre-run; floor only classifies primary vs exploratory, never drops data).
- **Verdict boundary REL = 0.5 + CI lattice.** Why: midpoint between the two demonstrated regimes (shared ≈ 1.0, story-distinct ≈ ~0); CI machinery makes the middle band explicit. Source: `#825` Results 2/4 (regime endpoints). Alternatives: 0.8 "strong recovery" kept as a descriptive reference line only (a hard 0.8 verdict boundary would label partial-recovery regimes "Distinct", overclaiming).
- **Battery reference pairs (C0 primary; C0′ for C4; C1 for prefix arm + instruction-matched contrasts).** Why: match the nuisance factor each cell manipulates (format for C4, instruction presence for C2/C3/C5); C0's prefix is structurally degenerate so the prefix-arm battery needs C1. Source: `#825` Result 3 (format pairing) + `#1335` (degenerate-prefix-arm precedent).
- **Reused input-data artifacts:** track_s.jsonl (`Source: #825`; fetched via pinned `hf_hub_download` on-worker); reference turnstores (`Source: #825`; staged via scoped `list_repo_tree` + per-file `hf_hub_download`, verbatim mirror, no layout mapping); anchor JSONs (`Source: #825` naturalistic-single-turn round; committed onto issue-1417 at P0 — git-clone-reachable on the GCP lane).
