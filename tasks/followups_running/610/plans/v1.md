# Plan — Task #610: Default-assistant shielding — dose or identity? Single-slot ablation of the `qwen_default` negative on the #600 chassis

`kind: experiment` · Parent: #600 (clean-result, `awaiting_promotion`) · Goal frontmatter present and unchanged (no refinement proposed — the Goal is already sharp and single-variable).

## 0.0 TL;DR (plain English)

- **What I'll run:** In the parent experiment, I taught a villain persona to end its answers with a rare symbol, and trained four other personas — always including the plain default assistant — as "don't do this" examples. The default assistant ended up far better shielded from picking up the symbol than anyone else, but it was also the only role that got "don't do this" examples in every single run, so I can't tell whether the shielding came from those examples or from what the default assistant *is*. Here I retrain the exact same setup three times with one change: the default assistant's 200 "don't do this" examples are handed to a different persona (a journalist), so the default assistant is never trained at all — and then I check how shielded it still is.
- **What I expect:** The default assistant stays just as shielded even when never trained. The parent run already showed that giving a persona "don't do this" examples leaves no visible trace on that persona, so the shielding most likely comes from where the default assistant sits in the model's internal landscape, not from the training rows.
- **What would change my mind:** If the never-trained default assistant loses its shielding and drifts up to look like every other untrained persona, then those 200 training rows were doing real protective work after all — which would make them the first negative-example slot in this project with a demonstrable per-context effect, and the safety-relevant one at that.

## 3. Hypothesis

**H-identity (primary bet, per the parent's no-trace pattern):** the never-trained default context's centered shift in the no-default arm stays at the with-default level — `median(D_without) ≤ median(D_with) + 0.033`, i.e. ≤ ≈ −0.167. Prediction grounded in: the within-persona control (+0.004 training trace) and the assistant-slot proximity (−0.193 vs −0.197).

**H-dose (falsification):** `median(D_without) ≥ −0.033` (within one generic noise-median of the untrained-panel median, which is 0 by centering). The expected movement if dose fully explains the dip is ≈ +0.164 to +0.197 — 5–7× the 0.033 band and ~20× the chassis-specific seed sd (0.008) — so 3v3 seeds resolves it decisively.

**Partial-dose zone:** −0.167 < median(D_without) < −0.033 → graded outcome, reported as the fraction of the gap closed `f = (median(D_without) − median(D_with)) / |median(D_with)|`, motivates the pre-registered 0/50/200-row dose-response child. All three zones pre-registered; no uncovered cell.

## 4. Design

### 4.1 The single manipulated variable

One new mix, slug `c610_mercenary_near_nodefault` (plain-English name: **No-default mix**):

```
parent (With-default mix, c600_mercenary_near): panel = {qwen_default, bartender, french_person, dictator}
new   (No-default mix, c610_mercenary_near_nodefault): panel = {journalist,  bartender, french_person, dictator}
```

Row accounting (confirmed against the parent's builder constants): 200 villain positives + 4 negatives × 200 = **1,000 rows → 63 optimizer steps** (batch 4 × grad-accum 4), identical to the parent. `journalist` receives exactly the 200 rows vacated by `qwen_default` — it appears once in the panel (it is a **new fixed negative**, not a doubled 400-row persona; the variable-slot NN `dictator` stays). Journalist rows are built on-policy from the same frozen `R_train.json` by the same `build_cell` path that built the parent's ctrl-cell journalist rows. Total budget, positives, the other 3 negatives, recipe, and step count are held fixed; the ONLY change is which persona owns the 4th slot's 200 rows.

**Replacement vs deletion (named design decision):** deleting the slot (800 rows, 3 negatives) would unmatch both total rows AND optimizer steps (50 vs 63) — two extra variables. Replacement holds both fixed at the cost of the "journalist's rows might themselves move the default" confound, which the parent's own headline null bounds below noise: six different slot-persona swaps (including journalist ↔ dictator on this very pair) moved no untrained persona detectably (p = 0.906, mean |effect| 0.031 < 0.033 noise median).

**With-default arm = REUSED parent runs.** The 3 `c600_mercenary_near` seeds are consumed as committed git trajectories — no retraining, no adapter reuse (fitness audit in §10).

## 7. Decision Gates, Success and Kill Criteria

**One gate — the smoke gate (= the sweep's first cell, zero marginal GPU cost).** The recipe itself is pre-verified (12 sibling mixes landed 8.0–10.6 nats at this exact recipe), but the #610-specific wiring (`spec_override` panel path, `extra_eval_personas`) is new, and gate (i) catches a missing primary DV before 2 more cells run. No other gates — short run, pre-verified hypothesis direction on the training side.

**Gate set (joint-satisfiability self-checked):** reused (a)–(h) + new (i) hard, (j) soft/recorded. No two gates demand contradictory outcomes on the same measurement: (a)/(b) bound the SOURCE implant from below/above on disjoint diagnostics (ΔG floor vs trained-logP ceiling + bystander argmax) with the parent's realized 8.0–10.6 sitting comfortably inside [5, 19]; (i) is an existence check; (j) doesn't gate. The headline zones partition the outcome space exhaustively.

**Success (either direction is promotable):**
- **Identity:** median(D_without) in the identity zone AND sanity reads pass → "the default context's shielding is positional, not bought by its training rows" — sharpens the parent's no-trace finding into the safety-relevant default case; redirects open-q 3.7 toward cluster-position mechanisms.
- **Dose:** median(D_without) in the dose zone AND sanity reads pass → first demonstrable per-context effect of a single negative slot in this line; immediately motivates the 0/50/200 dose-response child.
- **Partial:** graded report, both mechanisms live, dose-response child required to resolve.

**Kill criteria:**
1. Smoke gate (a)/(b) fail — the swapped mix lands out of [5, 19] nats or saturates at 63 steps: **halt and report; do NOT epochs-ladder** (re-pinning epochs would unmatch the reused parent arm's 63 steps and void the comparison). A slot swap moving the implant >3 nats would contradict the parent's ≤0.5-nat slot lead and is itself a reportable anomaly → post `epm:failure`, re-plan.
2. Gate (i) fail after one wiring-fix retry → infra blocker, `epm:failure (failure_class: code)`.
3. ≥2 of 3 new seeds fail validity gates at every checkpoint → underpowered; report failed-gate outcome, no headline claim.
