# Plan: Context-to-answer mapping quality vs general model capability (issue #2588, v3)

## 0.0 TL;DR (plain English)

- **What I'll run:** I take twelve open chat models, from tiny to large and from three different families, have each one answer the same 11,400 real user prompts plus the 198 hardest science questions we have, and measure how well a simple linear rule predicts, from the model's internal state just before it starts answering, the internal summary of the answer it then gives. Each model is tested twice: once with step-by-step reasoning turned off, and once at its best setting, where for reasoning models I read the internal state at the exact token where the reasoning block closes, inside the model's own generated text.
- **What I expect:** based on our own earlier two-model result (the older, smaller model won), I expect the "smarter models map better" story to fail or come out mixed, and the three same-size, same-architecture models of increasing ability are the cleanest available test. I also expect the end-of-reasoning state to help most on the hard science questions and barely at all on everyday prompts.
- **What would change my mind:** if the three same-size releases line up in order (each higher-rated release maps better) on the retrieval measure after the fairness corrections, that overturns our in-house evidence and says mapping quality rises across same-size releases that the capability index ranks higher. One honest limit, stated up front: newer releases also change training recipe and data, so a positive result is an association with rated capability, not proof that capability itself causes better mapping.

## 3. Hypothesis

- **H1 (capability tracks mapping quality):** calibrated retrieval rises with AA index across the panel AND within the fixed-size 27B column. Quantitative: Δcol_cal > 0 with 95% CI excluding 0, where Δcol_cal = the CALIBRATED paired difference in retrieval acc@1 (raw paired difference minus the difference of the two cells' realized P=200 permutation-null means; thinking-off arm, generic surface, each model at its val-frozen layer) between Qwen3.8-27B and Qwen3.5-27B on the shared 1,000-prompt test split; the ORDERED-column read additionally requires the 3.6 midpoint to be consistent (both adjacent calibrated contrasts ≥ 0 at point estimate); supporting reads: the adjacent measured pair (3.8−3.6) same sign, and panel-wide Spearman ρ > 0 (descriptive).
- **H0 (scale artifact):** any apparent panel-wide trend disappears in the fixed-size column (Δcol_cal CI straddles 0 or is negative) and/or vanishes after per-model permutation calibration; 2602.14486 says this is the modal failure mode of uncalibrated cross-width comparisons.
- **H2 (thinking arm shifts mapping quality independently of capability):** the arm-b minus arm-a gap is uncorrelated with AA rank; separately pre-registered (2603.05488): the gap is LARGER on GPQA Diamond than on the generic corpus — mean over the 7 QWEN thinking checkpoints of [gap_GPQA − gap_generic] > 0, Wilcoxon signed-rank (n=7; minimum attainable two-sided p = 0.0156, stated so an "H2 unresolved" outcome is read as calibrated, not surprising). The OLMo Instruct/Think contrast is DECOMPOSED (it moves checkpoint identity and read position at once, so it never enters the arm-gap Wilcoxon or the gap-vs-AA correlation): (i) **OLMo-R, the reasoning-training estimand** — Think vs Instruct at the SAME prompt-side position (pre_think vs prompt_last, identical input-position semantics) with answer-only targets, per family size (7B, 32B); (ii) **OLMo-P, the read-position estimand** — end-of-CoT (cot_boundary) vs prompt-side (pre_think) WITHIN each Think checkpoint. Both reported per pair (n=2 each, descriptive). P3 validates every registered pair's persisted metadata: identical checkpoint IDs or identical input-position semantics — mixed pairs are REJECTED by assert.
- **Pre-registered dissociation:** retrieval acc@1 and R² may order the panel differently; they already did in #2330 (acc@1 64.4-73.5% did not follow the R² ordering). An H1 claim must hold on the calibrated retrieval primary; R² is a within-model diagnostic (aspect-ratio argument, d spans 1024-5120 at fixed n_train = 10,000).

The verdict labels below apply to the primary contrast Δcol_cal only (the CALIBRATED statistic — §6; the lattice never consumes the raw contrast). Two registered single-axis partitions compose the verdict (MF3 — the v2 lattice fired on the endpoint CI alone, so a 3.6-below-both ordering could be labeled capability-tracking; the 3.6 midpoint now enters through the second partition). Define Δadj_min = the smaller of the two adjacent calibrated point contrasts, i.e. min over {Δ(3.6−3.5)_cal, Δ(3.8−3.6)_cal}: Δadj_min ≥ 0 says the 3.6 midpoint is order-consistent (both adjacent calibrated contrasts non-negative at point estimate; the adjacent CIs are reported beside, descriptive), Δadj_min < 0 says it is not.

Endpoint partition — DISJOINT and exhaustive: Endpoint-up ⇔ Δcol_cal > 0 AND its 95% CI excludes 0 on the positive side; Capability-inverts ⇔ Δcol_cal's 95% CI is wholly below 0; Indistinguishable ⇔ otherwise.

Ordering partition — DISJOINT and exhaustive: Order-consistent ⇔ Δadj_min ≥ 0; Order-inconsistent ⇔ otherwise.

Composite headline label (registered): **Capability-tracks-ordered = Endpoint-up AND Order-consistent.** Endpoint-up AND Order-inconsistent is narrated ONLY as "3.8 exceeds 3.5 on this prompt distribution, column ordering fails" — never as capability-tracking. Mechanizable acceptance (P3, committed test): enumerate synthetic three-point orderings and assert every state labeled Capability-tracks-ordered satisfies BOTH the endpoint predicate AND the registered ordering predicate (Δadj_min ≥ 0).

**Registered paired contrasts:** (i) fixed-size column pairs (3 pairs: 3.6−3.5, 3.8−3.6, 3.8−3.5) on the shared 1,000-prompt test split, paired per prompt, calibrated; (ii) arm-b vs arm-a within each of the 7 Qwen thinking checkpoints, paired per prompt/question; (iii) OLMo-R (Instruct prompt_last vs Think pre_think, 2 pairs), paired per prompt id; (iv) OLMo-P (pre_think vs cot_boundary within each Think checkpoint, 2 pairs), paired per prompt.

### 4.3 Measurement objects (glossary vocabulary)

- Arm (a) map input: context vector $v_C$ (last-prompt-token, the final token of the rendered prompt incl. the empty think block where the template emits one), per layer. Read via the ported `compute_read_idx` (mode `prompt_last`) — a PROMPT-side helper by construction (its docstring: "as an index into prompt_ids"; all three modes resolve inside the prompt).
- Arm (b) map input for thinking models: the **end-of-CoT state** = the residual state at the generated `</think>` close-boundary token in the CONCATENATED prompt+completion sequence — `positions["cot_boundary"] = prompt_len + close_tok[1] - 1`, the `build_capture_row` construction at the pinned #2546 blob (L1289), derived from `segment_completion_arm`'s cot char span via `issue928_common.char_span_to_token_span` over the completion's offset mapping. HARD assert per captured arm-b row: the index is ≥ prompt_len (i.e. inside the completion) and < the concatenated length, and equals the tokenized close-boundary position.
- **OLMo-Think dual-position capture (the decomposition, MF2):** each OLMo-Think cell captures BOTH (1) the prompt-side **pre_think** state — the last token PRECEDING the template-prefilled `<think>` (ported `compute_read_idx` mode `pre_think`, the #1005 prefill-rung convention) — and (2) the end-of-CoT `cot_boundary` state. pre_think carries the SAME input-position semantics as OLMo-Instruct's prompt_last (both = last token before any think/answer content), which is what makes OLMo-R a clean same-position contrast; cot_boundary vs pre_think within the Think checkpoint is OLMo-P.
