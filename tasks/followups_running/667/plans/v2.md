## 1. Goal

## 3. Hypothesis (per-assumption, with explicit falsifier)

All correlations are reported against a **family-clustered bootstrap CI** (resample #537's context families) and the matched null; "PASS"/"FAIL" are pre-registered below. The single in-scope behaviors are **em, sycophancy, fact** (marker excluded — saturated; refusal excluded — #537 found it noise-limited, 0.7× floor).

- **A3.6 (read-out stable post-FT).** *Predict:* base `r_B'ᵀ(v⁺(C')−v0(C'))` predicts the measured change `(E⁺(C',B')−E0(C',B'))` with the base level `E0` partialled out, partial-Spearman ρ > matched null. *Falsifier:* partial ρ ≤ shuffled-`r_B'` null CI upper bound for all three behaviors → base read-out does not survive FT (the fleet must re-extract r⁺).
- **A3.7 (ŵ∥δ).** *Predict (positive-only-displacement read):* `cos(ŵ, δ^pos)` with `δ^pos=t⁺−v0(C)` **exceeds the shuffled-δ null** `cos(ŵ, δ_of_a_different_behavior)`, small scalar-fit residual. *Decomposition read:* `cos(ŵ, δ^contra)` with `δ^contra=t⁺−t⁻`, reported with `frac_ctx=‖v0(C)−v0(C_neg)‖/‖δ^contra‖` per source cell. *Falsifier:* `cos(ŵ,δ^pos)` within the shuffled-δ null for all three behaviors → the write does not point toward the data target. *Decision signal for #660:* if `cos(ŵ,δ^pos)` and `cos(ŵ,δ^contra)` diverge AND `frac_ctx` is small (negatives, not context offset, drive the divergence) → the positive-only fleet arm is genuinely needed; if they agree OR the divergence is explained by large `frac_ctx` → the contrastive arm alone suffices for A3.7.
- **A3.8 (rank-one gated write).** *Predict:* per source, the off-source updates `{Δv(C')}` are well-approximated by scalar multiples of `ŵ=Δv(C)` — per-target residual `‖Δv(C')−ŵĝ^real‖/‖Δv(C')‖` small, stacked-ΔV `σ₁²/Σσ²` near 1, `cos(u₁,ŵ)` high. *Falsifier:* `σ₁²/Σσ² < 0.5` (the write is not low-rank) → no scalar gate to predict; expect this for content behaviors per #637, reported per-behavior.
- **A3.9 (gate = normalized key–query similarity).** *Predict (i — general gate):* some key∈{c_C, ψ(t), ψ(δ)} × metric∈{I, diag, whitened} predicts the activation gate `ĝ^real(C')` above `cos(c_C,c_{C'})`. *Predict (ii — boxed predictor):* specifically `c_C` key + `Σc⁻¹` metric wins. *Falsifier:* no key/metric beats predict-mean → no key–query gate; or (i) holds but (ii) fails → general gate exists but the paper's whitened-`c_C` form is not it (a real, reportable result). **Gated on the cosine-limit unit test passing first (B3).**
- **A3.10 (base gate predicts realized gate, at fixed M⁰).** *Predict:* the base-model gate `g0(C')` predicts `ĝ^real(C')` across held-out C' ≈ as well as the post-FT oracle `g⁺=(k⁺,q⁺,M⁰)`. *Falsifier:* `g0` adds nothing over the base-prior baseline (C7), or the oracle `g⁺` massively beats `g0` (fatal source-key/query drift) → the base gate is not predictive; **labelled "at fixed M⁰"** (metric-drift unattributed unless the opt-in Σc⁺ pass runs — not in scope here).

### Scope / caveats (surface to analyzer brief — NOT pre-registered gates)

These are interpretation constraints the round-1 critics surfaced to the **analyzer**. They are recorded here so the analyzer's brief inherits them; they are characterization rules for the write-up, NOT pass/fail gates added to §7.

1. **A3.7 decision-signal asymmetry (NOT a clean verdict).** A LOW `cos(ŵ, δ^pos)` alone CANNOT conclude "the positive-only fleet arm is needed." The analyzer reports the `cos(ŵ,δ^pos)`-vs-`cos(ŵ,δ^contra)` divergence (with `frac_ctx` partialled) as **recipe-dependence characterization** for #660, not a clean "positive-only required" verdict — the decision signal is directional evidence, not a binary conclusion.
2. **Cross-source dose confound (η uncontrolled in #537).** Within-source A3.8 (one source, varying target C') is **clean** (install dose fixed). Cross-source reads are **flagged confounded-and-reported**, never corrected (the fleet retrain's dose arms fix this, #660 Phase 2). The analyzer prefers the self-normalized `ĝ^real` (`ŵᵀΔv/ŵᵀŵ`, install-normalized by construction) over any behavior-scale companion when comparing across sources.
3. **Low effective df.** 3 behaviors × n=30 contexts, with a ~7-family cluster structure. The analyzer leans on the **family-clustered bootstrap + probe-split replication**, NEVER a naive n=30 CI, for every headline correlation.
4. **A3.6 em dynamic range (noise-floor-limited).** Only 151/480 em cells have |g|>0.01. The analyzer treats em cell-correlations as **noise-floor-limited** and reports the dynamic-range fraction alongside the em A3.6 number.
5. **A3.8 chance level (state explicitly).** For ~30 stacked targets in 3584-d, the chance `σ₁²/Σσ²` ≈ 1/30 ≈ 0.03. The analyzer states this chance level explicitly so a "near-1" σ-ratio is read against the right baseline.
6. **A3.9 key×metric ablation multiple-comparison surface.** ONE boxed primary (C3) = `c_C` key + `Σc⁻¹` metric. An exploratory winner that beats the boxed primary is a **reportable surprise, not the registered verdict** — the analyzer reports it as such and does not silently promote it.
7. **A3.10 trivial-prediction-from-small-Δ.** A high g0-vs-`ĝ^real` correlation could be trivially driven by tiny realized key/query drift. The analyzer reports the **realized key+query drift magnitude alongside** the g0-vs-`ĝ^real` correlation, so "the base gate predicts" is distinguishable from "almost nothing moved."

### 4.3 Exact extraction (reuse #651's `extract_per_context_shift`, EXTENDED to store absolute v)

The existing `experiments/issue_650/shift_extract.py::extract_per_context_shift` already teacher-forces R through base+trained and reads `hidden_states[L]` at the post-response slot, but it returns only the **shift** `h_trained[slot] − h_base[slot]`. **#667 needs `v0` and `v⁺` separately** (A3.6 needs absolute v⁺/v0; A3.7 needs ŵ=v⁺(C)−v0(C); ĝ^real needs both). New thin extractor `scripts/issue667_extract.py` (CLI mirroring `issue651_dispatch.py phase_extract`) that:
1. Loads base θ0 + the staged adapter as `PeftModel` (rsLoRA honored — `use_rslora=True` in every #537 `adapter_config.json`; this is the **application-scaling parity probe (g)**: §5 check (g) runs a 1-adapter apply-and-read parity probe reproducing #537's diagonal `G` value before the full sweep).
2. For each (probe q under context C'): build `T_{C'}(q) + R_{C'}(q)` (R = #537's frozen base greedy response for that cell — pulled from #537's response cache on HF, asserted present per `extract_per_context_shift`'s R-coverage assert), forward once each side with `output_hidden_states=True`.
3. Capture, at L14 (+7,21), **mean-over-response-span** (em/syc/fact) and **post-response slot** (marker companion): `v0`, `v⁺` (both, float32 CPU), per probe; mean over probes → `v0(C')`, `v⁺(C')`.
4. Store `{v0, v_plus}` per (behavior, source-C, target-C', layer) to `.npz`; upload to HF `issue667_gate_chain_preview/analysis_tensors/`.

Pseudocode (analysis module `src/explore_persona_space/analysis/issue667/gate_chain.py`):
```python
def realized_gate(v0_C, vplus_C, v0_Cp, vplus_Cp):
    w_hat   = vplus_C  - v0_C            # ŵ = Δv(C) (source write)
    delta_v = vplus_Cp - v0_Cp           # Δv(C') (target update)
    g_real  = (w_hat @ delta_v) / (w_hat @ w_hat)   # ĝ^real(C')  [B1]
    resid   = norm(delta_v - g_real * w_hat) / norm(delta_v)  # A3.8 rank-one residual
    return g_real, resid

def whitened_gate(c_C, c_Cp, Sigma_c, lam):
    # g_C(C') = c_Cᵀ Σc⁻¹ c_C' / c_Cᵀ Σc⁻¹ c_C ; g_C(C)=1 by construction
    Sinv = torch.linalg.inv(Sigma_c + lam * torch.eye(d))   # (Σc+λI)⁻¹
    z_C  = Sinv @ c_C
    return (z_C @ c_Cp) / (z_C @ c_C)

def whitened_gate_reduction_unit_test():
    # B3: with Σc=I, equal-norm c, the whitened gate == cos(c_C,c_C')  (up to the
    # self-normalization g_C(C)=1). MUST pass before any A3.9/A3.10 number is trusted.
    d = 64; torch.manual_seed(0)
    c = torch.randn(5, d); c = c / c.norm(dim=1, keepdim=True)   # equal-norm
    Sigma = torch.eye(d)
    for i in range(5):
        for j in range(5):
            g = whitened_gate(c[i], c[j], Sigma, lam=0.0)
            cos_ratio = (c[i] @ c[j]) / (c[i] @ c[i])            # cos / 1  (g_C(C)=1)
            assert abs(g - cos_ratio) < 1e-5, (i, j, g, cos_ratio)

def a37_source_write(w_hat, delta_pos, delta_contra, delta_other_behavior,
                     v0_C, v0_Cneg):
    cos_pos    = cos(w_hat, delta_pos)               # δ^pos = t⁺ − v0(C)
    cos_contra = cos(w_hat, delta_contra)            # δ^contra = t⁺ − t⁻
    cos_null   = cos(w_hat, delta_other_behavior)    # shuffled-δ null (R3-2)
    frac_ctx   = norm(v0_C - v0_Cneg) / norm(delta_contra)   # R3-1 context-offset partial
    # scalar-fit residual: min_a ‖w_hat − a·δ‖/‖w_hat‖
    return dict(cos_pos=cos_pos, cos_contra=cos_contra, cos_null=cos_null, frac_ctx=frac_ctx)
```

## 11. Decision Rationale (analysis knobs — every load-bearing value with a Source)

- **Reads: mean-over-response (generative) / post-response slot (marker).** *Why:* the theory's `v_θ(C)` is the mean answer-side activation (plan-doc §1.4); #651 used exactly mean-over-response + slot on these adapters. `Source: docs/theory_assumption_test_plan.md §1.4 + #651`.
