### 3.2 Hook mechanics + capture causal structure (read from the code on main)

**Generation-time arming (what must be reproduced):** `generate_batch` LEFT-pads prompts, asserts each row's unpadded length equals its tokenized-context length, and `DeltaHook` (last-context-token mode) edits position `T−1` of the prefill — each row's last real context token — adding `alpha * delta` OUT-OF-PLACE to block `layer`'s output; decode steps untouched. Δ is resolved per (pair, arm, layer) as `rec["cprime"]["v_c_<arm>"][idx] − rec["c"]["v_c_<arm>"][idx]` from `analysis_tensors/issue_1415/activations/<pair_id>.pt` (idx = index of the steer layer in the stored 7-layer list; layer-list assert at load, inherited from `DeltaSource`).

**Teacher-forced arming (the ONE new mechanism):** the binned capture right-pads `ctx_ids + comp_ids` and processes context + completion in ONE forward, so the last-context token sits at position `ctx_len − 1`, NOT `T−1` — `DeltaHook`'s `expected_prompt_len == T` assert is deliberately inapplicable. New keyword-only mode `edit_position: int | None = None` on `DeltaHook` (+ `arm_at(edit_position)` resetting the prefill latch): when set, assert `not all_positions` and `edit_position < T`, edit ONLY `out[:, edit_position, :]` on the first forward, leave every other code path byte-identical (default `None` preserves current behavior). Every row in a chunk shares the same `ctx_ids` (single-context capture), so `ctx_len − 1` is each row's last context token under right padding. Equivalence to generation: by causal masking, positions `0…ctx_len−1` compute exactly as the generation prefill did, the edit applies identically, and completion positions attend to the edited entry exactly as decode steps did — the teacher-forced hooked forward reproduces the generation-time computation up to bf16 batch-composition jitter.

**Capture causal structure (load-bearing):** `extract_layer_activations` captures block-L OUTPUT (`hidden_states[L+1]` semantics) via forward hooks registered per call; `DeltaHook` is installed before the capture call, so per PyTorch registration-order semantics the capture hook at the steer layer observes the POST-edit output. Consequences, all unit-test-pinned before any GPU: (i) answer-span activations at capture layers ≤ ℓ_steer are IDENTICAL between hooked and unhooked regimes (the edit touches only the context position at block ℓ_steer's output; blocks < ℓ_steer run before any edit) — these layers are the built-in same-text jitter reference; (ii) the direct component exists only at capture layers > ℓ_steer — registered read layers: L14 cells → 17 (headline), 20/21/24 reported side by side; L20 cells → 21 (headline), 24 reported; (iii) the captured value at (ℓ_steer, position ctx_len−1) equals the unhooked V_c plus α·Δ — the G2 exactness identity.

### 3.4 The new quantity + statistics (CPU, batched)

Per hooked cell, after the G0 pairing assert (staged unhooked shard's `kept_indices` AND `comp_token_counts` exactly equal the fresh capture's — a mismatch is a LOUD per-cell error, never a silent re-pair):

- **Per-draw per-bin diff:** `D[d, b, ℓ] = fp16(hooked_prof)[d, b, ℓ] − stored_unhooked_prof[d, b, ℓ]`, computed in fp32 after quantizing the hooked profiles to fp16 (symmetric storage noise on both legs; convention stated in the artifact). `diff_b[ℓ] =` nan-mean over draws; `mag_b[ℓ] = ‖diff_b[ℓ]‖₂`; per-draw magnitudes persisted for dispersion. NaN bins (short spans) inherit the round's drop-with-counts contract.
- **Jitter reference (the same-text repeat-precision band, per pair × bin):** `J_p(b) = max( mag_b[ℓ₀] · ‖P_unhooked[b, ℓ*]‖/‖P_unhooked[b, ℓ₀]‖ , 2⁻¹¹·√2·‖P_unhooked[b, ℓ*]‖ )` where ℓ₀ is the nearest causally-zero layer below the read (L14 cells: 14; L20 cells: 20 — adjacent, best norm-matched), the first term transports the empirically measured re-forward jitter to the read layer's scale, and the second is the two-sided fp16 quantization floor (prevents a degenerate log when kernels are bit-deterministic). Every input is persisted; the reference comes from the SAME hooked-forward-vs-stored-shard comparison as the signal, so cross-machine/kernel drift is absorbed by construction. Cheaper and stronger than re-running unhooked cells (which the scope offered as one option): every cell carries its own same-text jitter band at zero extra forwards; the round's committed parity-jitter figures (min cos 0.9999996 class) are the labeled secondary reference.
- **Registered late-span persistence statistic (the lattice carrier):** per pair, `L_p` = mean over LATE bins {dec8, dec9, dec10} of `mag_b[ℓ*]`; `J_p^late` = mean over the same bins of `J_p(b)`; **`R_p = log L_p − log(2·J_p^late)`** — positive iff the late-span direct component clears TWICE the same-text jitter band. Cell statistic `R̄` = mean over 28 pairs, pair-bootstrap 95% CI (B = 10,000, percentile, seed 14153, one vectorized resample), Wilcoxon signed-rank companion. All-NaN-late pairs dropped with a named list (> 20% drop in a cell fails loud — inherited).
- **Shape companion (descriptive):** `Δdirect_p = log E_p − log L_p` with EARLY = {first, tok2_5} (inherited sets), same bootstrap — separates flat (≈0) from decaying (>0) WITHIN the persistent regime; plus the width-matched {dec1,dec2}-vs-late variant (inherited companion).
- **Alignment companion (descriptive):** `cos(diff_b[ℓ*], target_b[ℓ*])` per bin, `target_b` = `P_cprime[b] − P_baseline[b]` from the stored gen1b shards at the read layer. Noise structure: on STEERED cells the diff legs (hooked/unhooked on identical gen1c text) share NO sampled quantity with the target's gen1b legs — legs independent by construction (stated). On BASELINE-TEXT cells the diff consumes the same gen1b c-draws as the target's baseline leg — registered fix 1 (disjoint halves): target's baseline leg from even draws, the diff averaged over odd draws, both assignments averaged (the round's convention, pure re-reduction). Per-bin random-direction null: 500 unit directions (fresh seed 14154), `cos(r_i, target_b)` per (pair, bin, read layer), p97.5 — one batched GEMM, recomputed at the new read layers.
- **Steered-text vs baseline-text direct component:** like-for-like comparison at the context arm (the registered pair of rows per pair × layer) — if the two agree per bin, the direct component is text-independent (pure KV mechanism); a steered-text excess implicates interaction with the changed text.

## 7. Success / kill criteria (decision gates)

**No decision gates — short run (~0.5 h wall), inputs pre-verified.** The h1 fidelity HALT (rc=9, artifact-routed) is an in-run integrity check, not a user-facing gate.

**Registered verdict lattice (per pre-registered cell — arm × steer layer, 4 primary cells reported side by side; NOT a conjunction across cells):** the registered statistic is R̄ (mean late-bin log-magnitude over twice the same-text jitter band) with its pair-bootstrap 95% CI.

DISJOINT and exhaustive: Direct-persistence ⇔ R̄ > 0 AND R̄'s 95% CI excludes 0 on the positive side; Late-null ⇔ R̄'s 95% CI is wholly below 0; Inconclusive ⇔ otherwise.

Interpretation mapping: **Direct-persistence** in a cell = the direct component survives to the end of the span there — combined with the shape companion (Δdirect ≈ 0 flat vs > 0 decaying-but-persistent, reported descriptively) and the alignment companion, it supports the scope hypothesis for that cell. **Late-null** = late-bin diffs within 2× measurement jitter; the scope's falsification clause (§1, verbatim) FIRES when ALL 4 primary cells land Late-null — that kills direct persistence as a late-span carrier for this rig and leaves text-mediated self-conditioning as the only surviving mechanism. A mixed outcome (e.g. persistence at L14 but not L20) is reported per cell as measured — layer-dependent runway is a legitimate third outcome, never pooled into a single verdict. A cell whose G2 gate HALTed never reaches the lattice (integrity truncation, not a verdict). Alignment stays OUT of the lattice (descriptive companion) — the registered kill is about magnitude persistence, per the scope.

**Registered paired contrast:** R_p (and Δdirect_p) is a paired late-vs-jitter (early-vs-late) contrast within each of the 28 pairs, per arm.
Row-coverage: both arms' registered per-pair rows are supplied per-context by `analysis_tensors/issue_1415/hooked_decomposition/` per-cell stores (hooked legs) and `analysis_tensors/issue_1415/position_profile/` shards (unhooked + target legs), reduced into `eval_results/issue_1415/hooked_unhooked_decomposition/per_pair_direct_profiles.json`.
Row-coverage assert: the driver set-checks the registered 28-pair × 2-arm × 2-steer-layer row set against both stores' cell keys and the reduced file's keys before the R̄ statistic is computed.
