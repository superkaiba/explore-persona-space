### 3. Hypothesis

Per behavior (evil, sycophancy), per strong direction (persona vector r_B, map pre-image), at the FIXED inherited operating point (ℓ*, c*), on the PRIMARY DV (coherence-gated Δ graded 0–100 trait score vs α=0), with question-level paired cluster-bootstrap CIs:

- **H1 (opening carries the effect).** The opening span (decode steps 1–3) recovers ≥ ⅔ of the all-answer-token Δscore at matched (ℓ*, c*), AND its cap-hit fraction + CJK-intrusion fraction are materially lower than the all-answer arm's (< half). *Falsified if span1-3 recovers < ⅓ of the all-answer Δscore, OR its cap-hit/CJK is not materially lower than the all-answer arm's.*
- **H2 (single-token sufficiency).** Token-1-only recovers a substantial fraction — registered as `T_lo > 0` (tok1's Δscore question-clustered CI lower bound) AND `R1_pt ≥ 1/3` (tok1's recovery POINT estimate under §3's per-resample R estimator applied to the tok1 arm; `R1_lo` reported alongside, not gated — the parent's CI half-widths make a lower-bound gate at ⅓ under-powered). *Falsified if `T_lo ≤ 0` while `S_lo > 0`, confirmed by the question-paired tok1-vs-span1-3 difference contrast (its CI excluding 0 in span1-3's favor) — never by marginal-CI-overlap comparison (the effect needs a window, not one token).*
- **H3 (monotone accrual + plateau).** Δscore is non-decreasing across last-ctx ≤ tok1 ≤ span1-3 ≤ span1-5 ≤ all-answer, and plateaus by span1-5 (span1-5 ≥ ~90% of all-answer). *Falsified if any adjacent pair INVERTS per its question-paired adjacent-difference bootstrap CI (the later arm's paired-difference CI lying entirely below 0) — the 4 adjacent contrasts are evaluated PAIRWISE with no family correction, and any one inversion falsifies that cell's monotone claim (a deliberately falsification-friendly registration; never marginal-CI overlap) — OR span1-5 recovers < ⅔ of all-answer (no plateau — later tokens carry material effect).*
- **H4 (pre-image locus).** The pre-image, inert at the last context token (parent finding, reproduced here as the last-ctx comparator), steers at the opening answer tokens: its span1-3 arm CLEARS its matched null while its last-ctx arm does not. **Registered "clears" predicate:** the question-paired `pre − shuffled-map` bootstrap difference CI lower bound > 0, with the shuffled-map twin at the pre-image's EXACT inherited (ℓ*, c*) — the dose+layer+norm-matched direction-identity null (PRIMARY); the random arm runs at its OWN inherited operating point (§4.3) and is a secondary diagnostic floor only, never the H4 gate. *Falsified if the pre-image's opening arm does not clear the shuffled twin, OR its last-ctx arm also clears it (no locus dissociation). The matched-dose tok1-vs-last-ctx read (one edited forward each, same α) is reported alongside — a dissociation carried only by the 3-edit span (a 3× aggregate-dose asymmetry vs the single prefill edit) is narrated as dose-confounded, not locus-clean.*

**Registered verdict lattice** (verify_plan.py check 20). Scope: per (behavior × strong direction × breadth) at the matched inherited (ℓ*, c*). Defined quantities, all from the question-clustered bootstrap: `A_lo` = the all-answer arm's Δscore CI lower bound; `S_lo` = the span1-3 arm's Δscore CI lower bound; `R = Δscore[span1-3] / Δscore[all-answer]` — **registered estimator:** computed PER-RESAMPLE inside the common question-clustered bootstrap as `R_b = (S_b − α0_b) / (A_b − α0_b)` (the shared α=0 anchor subtracted within each resample b; never a ratio of marginal interval endpoints) — with `R_lo` / `R_pt` its percentile CI lower bound / point estimate; **denominator guard:** in a cell where > 1% of resamples have `|A_b − α0_b|` < 5 score points, `R_lo`/`R_pt` are UNDEFINED (ratio-unstable), the sufficient/partial clauses cannot fire, and the cell falls to the explicit `Ambiguous` residual, with the paired difference `S − (2/3)·A` reported as the descriptive fallback (the recovery denominator exists only where the all-answer arm itself steers); `D = deg[all-answer] − 2·deg[span1-3]`, where `deg[·]` = cap-hit fraction + CJK-intrusion fraction, **both components computed on a COMMON 2048-token horizon for every arm** — a cap-hit-regen'd cell's persisted record is at cap 4096, so the reduce RECOMPUTES both fractions from the persisted raw completions truncated to 2048 tokens (realized-cap diagnostics reported separately per cell; the regen'd full-length record still feeds the judge). **D is a DECLARED point-read:** `D ≥ 0` gates `opening-sufficient` on the point estimate (the pre-registered "materially cleaner" bar: span1-3 carries at most half the all-answer degradation), with D's question-paired cluster-bootstrap CI computed and reported alongside — a |D| smaller than its CI half-width is narrated as knife-edge, never decisive.

DISJOINT and exhaustive: `all-answer-inert` ⇔ A_lo ≤ 0; `opening-inert` ⇔ A_lo > 0 AND S_lo ≤ 0; `opening-sufficient` ⇔ A_lo > 0 AND S_lo > 0 AND R_lo ≥ 2/3 AND D ≥ 0; `opening-partial` ⇔ A_lo > 0 AND S_lo > 0 AND R_pt ≥ 1/3 AND (R_lo < 2/3 OR D < 0); `Ambiguous` ⇔ otherwise.

Exactly one label fires per cell: the first two clauses partition on the A_lo / S_lo signs, the sufficient / partial clauses are disjoint by the (R_lo ≥ 2/3 AND D ≥ 0) vs (R_lo < 2/3 OR D < 0) complement, and Ambiguous is the explicit residual cell (A_lo > 0 AND S_lo > 0 AND R_pt < 1/3 AND the sufficient conjunction unmet — a positive-but-small opening effect).

**Registered paired contrast** (verify_plan.py check 18): every position arm of a given (behavior × direction × breadth) covers the SAME held-out 20-question persona-vectors eval bank, the SAME 6 draws (seeds 42–47), the SAME judge instrument — Row-coverage is identical by construction (one bank scored under every position cell at one fixed operating point), so all per-position paired contrasts (opening vs all-answer, tok1 vs span1-3, direction vs its random/shuffled twin) are computed within the same questions.

#### 4.1 Position-indexing precision (the load-bearing definition — the implementer cannot mis-index)

The rig generates with HF `model.generate()` under a `register_forward_hook` (NOT vLLM — vLLM cannot host a per-decode-step residual write hook; `steering.generate_batch` arms the hook once per draw, then `generate()` fires the hook on every forward pass). Under KV-cache decoding:

- **Prefill** = the first forward over the T-token LEFT-padded prompt. Each row's last real context token sits at padded position `T-1` (asserted per row by `generate_batch`). Editing there is the **last-context-token** arm — the base `DeltaHook` default mode, EXACTLY as the parent rig used it.
- **Decode step t** (t = 1, 2, 3, …) = the t-th post-prefill forward, a single new position under the KV cache. Its residual is the state OF the t-th generated answer token. **Token index 1 = the first generated answer token = decode step 1.** Editing at decode step t = "steering at answer token t."
- Position arms map to decode-step edit sets: **tok1** = {step 1}; **tok2** = {step 2}; **tok3** = {step 3}; **span1-3** = {steps 1,2,3}; **span1-5** = {steps 1,2,3,4,5}; **combined** = {prefill T-1} ∪ {steps 1,2,3}; **all-answer** = every decode step (the persona-vectors regime).
- **Definitional caveat, stated so nobody is surprised:** the "all-answer" arm reuses the base `DeltaHook(all_positions=True)` exactly (the parent's answer regime), which edits the prefill position `T-1` (the last context token) PLUS every decode step — a one-position superset of the pure decode-step arms. This makes the H1/H3 recovery bar CONSERVATIVE (the all-answer denominator includes one extra edited position the opening arms omit). The pure decode-step arms do NOT edit prefill `T-1` (only "combined" does).

#### 4.2 New code — `WindowedDeltaHook` (subclass in the driver; steering.py UNTOUCHED)

`grep -rn 'class DeltaHook\|all_positions\|decode_only\|prefill_all' src/explore_persona_space/experiments/issue1415/steering.py` confirms `DeltaHook` (steering.py L144) has modes `all_positions` / `decode_only` / `prefill_all` / `edit_position` — NONE of which is a bounded decode-step WINDOW. A tiny subclass in the driver adds it, keeping the shared module untouched (no shared-module-propagation duty):

```python
class WindowedDeltaHook(DeltaHook):
    """Edit residual at a WINDOW of decode steps (1-indexed); optionally also prefill T-1.
    decode_window=(lo,hi): edit decode steps lo..hi inclusive, skip prefill.
    combine_prefill_ctx=True: ALSO edit prefill T-1 (the combined arm)."""
    def __init__(self, *a, decode_window, combine_prefill_ctx=False, **kw):
        super().__init__(*a, **kw)          # base = plain last-ctx mode; we override _edit_tensor
        self.lo, self.hi = decode_window
        self.combine_prefill_ctx = bool(combine_prefill_ctx)
        self._decode_step = 0
    def reset(self):                         # called by DeltaHook.arm() before each draw
        super().reset()
        self._decode_step = 0
    def _edit_tensor(self, hidden):
        B, T, H = hidden.shape
        d = self.delta.to(hidden.device, hidden.dtype); assert d.shape[-1] == H
        scaled = self.alpha * d              # (H,) or (B,H)
        if not self._prefill_seen:
            assert self.expected_prompt_len == T, (T, self.expected_prompt_len)
            self._prefill_seen = True
            if self.combine_prefill_ctx:
                out = hidden.clone(); out[:, T-1, :] += (scaled if d.dim()==1 else scaled)
                self.n_edits += 1; return out
            return hidden                    # windowed decode arms skip prefill
        self._decode_step += 1
        if self.lo <= self._decode_step <= self.hi:
            out = hidden + (scaled[:, None, :] if d.dim()==2 else scaled)
            self.n_edits += 1; return out
        return hidden
```

- **last-ctx / all-answer comparators use the BASE `DeltaHook` directly** (`DeltaHook(...)` default = last-ctx; `DeltaHook(..., all_positions=True)` = all-answer), so those two arms are byte-identical to the parent rig; only the six windowed arms + the combined arm use `WindowedDeltaHook`.
- `grep -rn 'def generate_batch\|hook.arm\|_edit_tensor\|def _hook' src/.../steering.py` confirms `generate_batch` (L382) calls `hook.arm(expected_prompt_len=T)` once per draw and the base `_hook` (L371) dispatches to `_edit_tensor` — the override point.
