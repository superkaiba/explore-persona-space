### 4.1 The single new component

**(a) Group-fold extension of `fit_batched_loco_mlp_multihead`** (SOURCE module `src/explore_persona_space/analysis/vectorized_mlp_skill.py` — per the artifact-reuse item-(i) rule, the fix lands in the source module, never a caller-side workaround; mirrors the ridge group-fold precedent now on main via PR #754):

- Add an optional `row_groups: np.ndarray | None` parameter (row → fold id). `None` preserves the existing singleton-LOCO behavior byte-for-byte (all existing callers unchanged). - Add `standardization: "per_fold" | "full_data"` (default `"per_fold"`, the existing behavior), mirroring `GroupRidgeDesign`'s two modes.
- **Serial-parity gate** `assert_group_mlp_matches_serial`: a serial per-fold reference loop (one net per fold, same per-fold init seeds, same standardization) must match the batched group-fold path within float tolerance on 2–3 small cells, in BOTH standardization modes — the exact validation shape the ridge extension used (`group_vs_serial_per_fold` / `group_vs_serial_full_data`). Runs before any production fit; a gate failure is fail-loud (no production numbers emitted).

**(b) The fit driver round** (extends `scripts/issue928_fit_decomposition.py` or a thin sibling `scripts/issue928_mlp_indiv_control.py` importing its store reader): download the store from HF (revision-pinned), build the two arms at each of the 28 layers — **Per-question MLP direct** (ctx mean-pool → ans PCA-48) and **Per-question MLP CoT-augmented** (concat ctx+cot mean-pools, d_in 7168 → ans PCA-48) — fit all cells as one batched multihead ensemble (2 shape buckets by d_in), score held-out group predictions with `skill_over_mean_r2`, persist per-context `ss_res`/`ss_tot` per (arm, layer) merged alongside the existing `decomp_indiv.pt` schema, then run the paired bootstrap re-reduction (existing `make_bootstrap_index_matrix` seed 42 + `bootstrap_skills`-style re-reduction over stored per-context errors — no refit) for the registered contrasts of §6.

**Estimator-validity gate (narration gate, pre-registered):** the closure read is narrated as informative only if MLP-augmented ≥ linear-augmented − 0.05 at frozen L25 (LOCO pooled). **Interpretation branches (pre-registered):**
- **Small closure** (point closure < 1/3 AND read 2's CI excludes 0, positive): the headline hardens — Takeaways bullet 2 gains "a per-question nonlinear (MLP) direct map closes only X% of the gap". - **Intermediate** (closure ≥ 1/3 but read 2's CI excludes 0): partial-nonlinearity narration — the gap is restated as "linear-inaccessible" rather than "context-absent" information, with the closure fraction quoted.

## 11. Decision Rationale (delta entries; every other §11 entry inherited from v3)

- **MLP constants (width 512, GELU, AdamW lr 1e-3 / wd 1e-4, 300 epochs, seed 658).** *Why:* the registered validity-check instrument must be identical to the one already run at avg_q, or the per-question control is not comparable. *Source:* #928 v3 §11 → `issue658_fit_predictors` MLP constants (#810/#658 inherit fast-path). *Alternatives:* wider/deeper nets (would confound "nonlinearity closure" with capacity change; rejected).
- **Full-data input standardization for the MLP indiv arms.** *Why:* the indiv LINEAR arms were fit under full-data standardization (fit manifests; clean-result caveat 1); matching it makes estimator form the single difference in every paired contrast. *Source:* #928's own committed indiv convention (`recon_skill_grid.json .parity_gate.group_vs_serial_full_data` confirms the linear path's mode). *Alternatives:* per-fold (the MLP path default — would confound the contrast with the caveat-1 convention sensitivity, measured as large as −0.49 → +0.66 at L14; rejected for registered reads).
- **All 28 layers for both MLP arms.** *Why:* the own-best and best-vs-best secondary conventions require the MLP arms' own per-layer curves, and the full sweep closes the "nonlinearity lives at another layer" objection at trivial cost (~28 PFLOP batched). *Source:* #928 v3 avg_q MLP precedent (d/a/b arms fit at all 28 layers in `mlp_validity_avg_q_mean`).
- **Bootstrap 2,000 draws / seed 42 / shared index matrix; frozen-L25 primary; three conventions.** *Why/Source:* inherited verbatim — #928 v3 §6 (#810 machinery); the estimator is the instrument.
- **Closure narration bin 1/3; validity-gate margin 0.05.** *Why:* narration bins for a continuous estimate, not estimator hyperparameters — the confirmatory objects are the pre-registered CIs. *Source:* anchored on measured avg_q values (closure ~14% sits well inside "small"; MLP-vs-linear augmented deficit 0.020 → 2.5× margin). Not load-bearing for any pass/fail.
- **No training ⇒ no training hyperparameters** (N/A — no model training).
