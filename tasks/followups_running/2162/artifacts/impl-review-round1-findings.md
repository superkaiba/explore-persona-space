**M1 — claim staleness steals LIVE claims, and the steal path has a TOCTOU double-win.** `issue2162_run.py:291-297, 300-347, 350-359`. `_claim_stale` returns True for ANY claim older than `CLAIM_STALE_S` (3600 s) including a same-host LIVE owner (the dead-pid check fires first only for same-host DEAD pids), and there is no heartbeat refresh during `run_block`. A block legitimately running > 1 h (2048-cap × 36 pairs × 5 draws on a contended GPU is plausible at production shape) gets stolen: duplicate GPU work, and the ORIGINAL owner then crashes at `release_claim`'s token assert — killing its whole queue loop and orphaning its capacity. Separately, two workers can both observe their own token in the stale path (A reads back before B replaces) → same duplicate-compute + crash shape. Per-block writes are atomic and idempotent so there is no data corruption; the cost is wasted GPU plus a crashed worker. **Fix:** (i) heartbeat the claim's `ts` between pairs during `run_block`, or set the default `CLAIM_STALE_S` above the measured pilot block wall × margin; (ii) make `release_claim` tolerate a stolen claim with a LOUD log instead of asserting the worker loop dead (the queue's completeness scan remains the hard gate); (iii) for the TOCTOU, re-read after a short randomized delay or accept it under (ii). Note this also closes the efficiency lens's minor-2. **Test:** a live-pid same-host claim at ts−2h is not stolen and does not crash.
