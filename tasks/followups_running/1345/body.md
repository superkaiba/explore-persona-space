# Narrative-story framing collapses the assistant context→answer map even on identical conversations, while chat and plain-text framings share one operator up to linear coordinates (MODERATE confidence)

<!-- clean-result-v4 -->

**Methodology:** [docs/methodology/issue_1345.md](https://github.com/superkaiba/explore-persona-space/blob/417ae2e5bd9c747e9b00a49b98d751cb53373f23/docs/methodology/issue_1345.md) · [gist](https://gist.github.com/superkaiba/3f56e92cbfa295acbfdb42429e165864)

## Takeaways

- The story collapse is a framing effect, not a corpus effect: on the same 2,163 conversations with answers embedded verbatim, the story context map reads −0.31 held-out R² (CI −0.33 to −0.28) where the chat map reads +0.24.
- The deficit sits in the story context representation — read at a single attribution-colon token, so the filed slot-position ablation is the direct test: chat context activations predict the story answer activations at 0.56 and the story operator reparameterizes into chat at 0.61 (null −0.04), but the reverse direction fails (−0.17 vs null −0.06).
- Chat↔plain-text transfer still misses the same-operator margin, but a general-linear coordinate change recovers each context ceiling (0.005 below to 0.008 above; nulls ≈ −0.03) — all four cells replicated exactly this round.
- Instruction tuning pulls the two coordinate systems together: raw operator cosine 0.651 (instruct) vs 0.293 (base); rotation-aligned cosine 0.855 vs 0.732 against a rotation null near 0.001.
- Teacher-forced story capture inflates the read by +0.075 over the on-policy companion on 117 matched conversations (0.07 vs −0.01) — a qualification, not a demotion; the on-policy story map would be weaker still.
- Free-form story arms stay halted under both character names; paired-verbatim wrapping cleared its 2,160-row floor by 4 only after three retry waves — the model paraphrases instead of embedding the answer verbatim in about 45% of draws.

## Goal

**This experiment in context:** [#825](https://eps.superkaiba.com/tasks/825) showed the assistant context→answer linear map predicts about equally well with or without the chat template, and that generic story-character maps transfer to the chat map at only ~5% of ceiling — but equal predictive power does not mean the same operator, and the story result used arbitrary characters. This experiment holds the assistant persona constant across three framings — chat-template, plain `User:/Assistant:` text, and an assistant character in narrative stories — and tests operator identity directly via cross-regime transfer, aligned operator cosine, and the [#825](https://eps.superkaiba.com/tasks/825) Result-2.5 general-linear reparameterization, in Qwen2.5-7B base and instruct. A conversation-paired follow-up round re-renders the same conversations as stories with the original answers embedded verbatim, removing the corpus confound from the story comparison. Sibling [#1335](https://eps.superkaiba.com/tasks/1335) asks the different question of why the assistant map is stronger than fiction-character maps.

**Broader narrative:** if the assistant map is one operator re-expressed in framing-specific coordinates, the map is a property of the assistant identity rather than of the chat format — constraining how persona representations should be compared across surface framings, and mirroring how base→instruct post-training re-parameterizes rather than replaces the map.

## Methodology

**Design:** three framings of the same assistant persona × two models (Qwen2.5-7B, Qwen2.5-7B-Instruct) × two mapping arms (context = everything up to the end of the user query; prefix = everything before the query). Framings: chat-template (standard Qwen chat template), no-template (the same conversations rendered as plain `User: <u1>\n\nAssistant: <a1>`), and assistant-in-stories (new narrative prose in which an AI character named ARIA answers a human character's questions). Chat and no-template share the same underlying conversations (the conversation-paired pair); the free-form stories are a different corpus, so those story comparisons are corpus-confounded by design. Per cell I fit a closed-form ridge map from the context (or prefix) activation to the answer-mean activation, swept all 28 layers within-regime, ran the cross-regime transfer matrix and operator-comparison legs at frozen layers 14/18/19/26 (layer 19 headline), and evaluated the plan's verdict lattice on the chat↔no-template pair per model and arm: same-operator (transfer alone within 0.05 of the target ceiling), reparameterized (transfer short, but a data-paired general-linear change of coordinates `A·M·B` recovers the target ceiling above a matched-capacity null), different-map (recovery also fails, deficit CI wholly below zero), else inconclusive.

Follow-up round `assistant-named-story` (single manipulated variable: the story character name, ARIA → "Assistant", via the `EPM_STORY_CHARACTER_NAME` seam with a variant-scoped output prefix): stories regenerated for both models under the otherwise-identical recipe. The story pipeline's retry pass is a fresh-seed backfill sized to the main-pass shortfall — retry seed conversations overlap the main pass 0 of 242 (instruct) — not per-slot retries. The chat/no-template legs reused the parent's pinned turnstore (HF data revision `2a3cb30a`, the turnstore-reuse pin; the fit metadata's `pinned_parent_revision` `7159e5804d` is the parent S-track corpus pin, a different object) through a prefetch-reuse phase gated by a refit-equality check (tolerance 1e-3, measured deviation 0.0 on all four base cells) and the parity gate (deviation 0.0 on all four layer-19 anchors); all four chat↔no-template lattice cells reproduce the parent verdicts exactly, so those legs are a pipeline-integrity replication, not new evidence. Both story arms missed the 400-of-500 yield floor, so free-form story fits and story-pair operator legs were halted per the plan kill criterion. As an instrument diagnostic, all 365 verdict-less judge replies (both runs, both models) were then re-judged once at `max_tokens` 800 — identical rubric, judge model, and temperature, fresh cache — with per-row outcomes recorded.

Follow-up round `conversation-paired-stories` (plan v9): a seed-42 sample of 2,700 of the 4,724 shared conversations rendered as narrative prose with the ORIGINAL answer embedded verbatim (attribution `Assistant replied: "…"`), activations captured teacher-forced at the fixed answer span, plus an on-policy companion cell (free story-answer generation; 117 conversations kept) bounding teacher-forcing distortion per nested gates (companion more than 0.05 below the teacher-forced cell = qualification; negative and more than 0.20 below = demotion). The paired regime is instruct-only; base narrative generation was not attempted by scope (parent base story yields 96 of 500), so base paired-story cells are N/A — not tested. This makes the story rows corpus-shared and conversation-paired with chat/no-template, so the data-paired story↔chat reparameterization is defined — the parent's stated deviation, resolved. Two declared variables separate this round from the free-form ARIA anchor (corpus construction AND character name, renamed per user directive), so ARIA-anchor comparisons are context only; the round's primary comparisons hold the name fixed within-round. Same-conversation comparators are matched-row refits of the chat and no-template cells restricted to the story-kept rows; the plan-declared verdict lattice reads the paired-story within-R² (context arm, layer 19) with its conversation-grouped bootstrap CI — wholly below zero = framing effect, wholly above = corpus effect.

**Evaluation:** the dependent variables are geometric/predictive, not judged behaviors: (1) within-regime held-out R² (pooled per layer with the test fold's own mean as reference, group 5-fold CV) per regime × model × arm × layer, against a conversation-level shuffle null; (2) cross-regime transfer R² of the source-regime map applied in the target regime, with per-direction Δ(source→target) = transfer R² minus the TARGET regime's own within-R²; (3) raw and activation-Procrustes-aligned operator cosine against a random-rotation null; (4) reparameterization recovery: held-out R² of `A·M_source·B` in the target regime, where `A`/`B` are ridge-fit activation alignments trained on training folds only, against the larger of two matched-capacity nulls; (5) for the paired-story round, the plan's verdict read on the paired-story cell (framing effect iff the within-R² CI is wholly below zero; corpus effect iff wholly above with recovery above nulls), the story↔chat reparameterization with data-paired alignments, and the nested teacher-forcing gates on the on-policy companion subset. The 95% CI on the lattice deficit comes from the conversation-level paired bootstrap. The transfer matrix recomputes each target's within-R² on its own subset and folds with a pooled held-out-mean reference, so its story diagonals differ slightly from the within-sweep rig (paired stories: −0.303 bootstrap-rig vs −0.306 within-sweep) — a rig difference (R² reference), not a data difference; prose uses the within-sweep value. Free-form story-pair operator similarity uses raw cosine + rotation band + an operator-spectrum Procrustes optimum (the data-paired alignment is undefined without shared conversations — a stated deviation, resolved for the paired round).

## Results

### Naive cross-regime transfer falls short of the target ceiling in both models

Held-out R² at layer 19 (context arm): row = source framing, column = target framing; diagonals are each framing's own within-R² (chat/no-template n = 4,724; stories n = 2,108 turns; base story cells N/A — not tested). Below: per-conversation squared error, transferred vs own map.

![Held-out R2 transfer heatmaps by source and target framing, instruct and base](https://raw.githubusercontent.com/superkaiba/explore-persona-space/319fd10131dd2517a4099755153efe500dec9e5b/figures/issue_1345/hero_transfer_heatmaps_context.png)

![Per-conversation squared-error scatter, transferred vs own map, mostly above the identity line](https://raw.githubusercontent.com/superkaiba/explore-persona-space/bfa7acfc846bbc8c8b863687626db58d06c8370f/figures/issue_1345/transfer_per_conversation_error_context.png)

> **Figure.** *Transfer misses each target ceiling, and per conversation the deficit is near-universal.* Top: transfer R² at layer 19 (instruct retains 83–84% of ceiling, base 15–31%; story cells strongly negative). Bottom: per-conversation error, transferred vs own map — transfer is worse for 92–96% (instruct) and 99% (base) of conversations (median error ratio 1.24–1.26 and 1.94).

Transfer loses R² in both models: the mean per-direction deficit is −0.103 (instruct) and −0.430 (base), each with a 1,000-draw conversation-level bootstrap 95% CI excluding zero (upper bounds −0.101 and −0.425). Both models fail the 0.05 same-operator margin, and instruct crosses the 0.10 different-map margin by a statistically resolvable but trivially small amount (mean −0.003, 95% CI −0.006 to −0.001) — absent recovery, the transfer-only read favors different maps in both models.

At frozen layers 14, 18, and 26 the instruct deficit grows to −0.14 to −0.21: the at-the-margin reading is layer-19-specific; transfer-falls-short is layer-robust. Story transfer collapses in both directions (corpus-confounded; see the story sections).

### A general-linear change of coordinates recovers the target map in both context cells

Per model and direction (context arm, layer 19): the target's own held-out R², the R² recovered by reparameterizing the other framing's map, and the matched-capacity null. Below: the same four directions as points — ceiling, recovered, and the 10 individual null draws.

![Bar chart of ceiling, recovered R2, and matched-capacity null per direction](https://raw.githubusercontent.com/superkaiba/explore-persona-space/319fd10131dd2517a4099755153efe500dec9e5b/figures/issue_1345/reparam_recovery_context.png)

![Dot plot of per-direction ceiling, recovered R2, and individual null draws](https://raw.githubusercontent.com/superkaiba/explore-persona-space/bfa7acfc846bbc8c8b863687626db58d06c8370f/figures/issue_1345/reparam_recovery_per_direction_points.png)

> **Figure.** *A data-paired linear reparameterization recovers each context-cell ceiling.* Top: recovered R² lands between 0.005 below and 0.008 above each ceiling (instruct 0.654/0.620 vs 0.654/0.625; base 0.550/0.579 vs 0.542/0.578). Bottom: per-direction points — every individual null draw sits at −0.44 to −0.01, far below recovery.

A linear input alignment plus output alignment around the OTHER framing's frozen map recovers the target's full ceiling: the largest deficit is 0.005 (instruct, chat→no-template) and base recovery exceeds its own ceiling in both directions (+0.008 and +0.0003). The read is held-out — not alignment-map overfitting: composition through the stronger no-template map slightly out-generalizes the direct chat fit.

The alignments are regularized (GCV-selected penalties; effective ranks ≈1,100–1,800 input and ≈3,000–3,300 output of 3,584), and matched-capacity nulls recover −0.02 to −0.03, ruling out recovery-by-capacity. Both context cells fire the reparameterized verdict with margin +0.045 to +0.050; the prefix cells concur but are the degenerate-arm read below, not independent evidence.

### Instruction tuning pulls the two coordinate systems most of the way together

Cosine between the chat and no-template operators at layer 19 (context arm): raw; after optimally rotating one operator onto the other (Procrustes alignment); and the random-rotation 97.5th-percentile reference. Dashed line: the parent base↔instruct aligned-cosine anchor (0.686).

![Bar chart of raw and rotation-aligned operator cosine, instruct and base](https://raw.githubusercontent.com/superkaiba/explore-persona-space/319fd10131dd2517a4099755153efe500dec9e5b/figures/issue_1345/operator_cosine_raw_vs_aligned_context.png)

> **Figure.** *Instruction tuning aligns the two operators' coordinates.* Raw operator cosine 0.651 (instruct) vs 0.293 (base); aligned cosine 0.855 vs 0.732; the rotation null is ~0.001, so both aligned values sit far beyond chance.

Instruct operators are already 0.651 aligned raw — the chat template shifts coordinates modestly — while base operators read 0.293 raw yet 0.732 aligned, comparable to the parent's cross-MODEL anchor. Near-identical activations cannot explain this: the input activations align at linear R² 0.79 (instruct) and 0.48–0.61 (base) — reported in place of the plan's paired activation cosine; the fitted alignment upper-bounds any identity fit, so activations are provably not near-identical. Instruction tuning appears to canonicalize coordinates across framings more than it changes the operator.

### The assistant map barely exists in free-form narrative stories, and its operator is not the chat operator

Within-regime held-out R² across all 28 layers (instruct) per framing; context arm left, prefix arm right; dashed = story shuffle-null 95th percentile; dotted = layer 19.

### Prefix-arm maps ride batch numerics of a fixed template region, and the same reparameterization recovers them

The pre-query region is a fixed template string in both framings, so the prefix slot's nominal content is conversation-independent. In a sampled extraction shard (500 conversations, instruct chat, layer 19) the stored prefix activation collapses onto 14 distinct vectors — every row at cosine 0.99999+ to the mean — whose counts follow extraction-batch boundaries and track sequence-length buckets: the arm's within-R² of 0.128–0.134 (mean baseline ≈ −0.001) most plausibly reads batch-composition numerics that proxy conversation length, not content. Its coordinates also shift wildly across framings (naive transfer −505 to −16,761), yet reparameterization recovers the weak ceiling (0.126–0.133) in all four cells: formally reparameterized, but I read this arm as the expected degeneracy companion, not independent operator evidence.

### The story failure sits in the story context representation: the operator reparameterizes into chat one-way
