# Plan v9 — Task #642 (amendment): Does the matched-LR adapter-vs-dense leakage gap survive a behavior swap from sycophancy to refusal?

## 0.0 TL;DR (plain English)

<section class="plan-tldr">

- **What I'll run:** Last round I showed that one training method (lightweight LoRA adapters) leaks a bad habit into unrelated personas LESS than full dense fine-tuning does, at matched install strength, on realistic self-written data — and that gap held up for the "agree with whatever the user says" habit. This round I keep that exact head-to-head and change ONE thing: the habit I implant. Instead of teaching the model to be a yes-man, I teach it to refuse to answer. Then I check whether the same lightweight-vs-dense leakage gap shows up. If it does for two different habits, the gap is about the training method, not about one specific habit.
- **What I expect:** My weak bet is the gap survives — the method difference is about how broadly each method rewrites the model, which shouldn't care which habit I install. But refusal is a habit the model already half-knows how to do, so it sticks fast, and I may have to train both methods more gently to keep the comparison in a measurable range.
- **What would change my mind:** If the gap lands near zero for refusal, the earlier sycophancy gap was probably habit-specific, not a general property of LoRA-vs-dense — which would be the more interesting and more surprising result. If refusal sticks so fast that I can't get a clean mid-strength read even after gentling the training, I report that as a real measurement-feasibility finding, not a silent drop.

</section>

Pre-registered direction-of-claim lattice (mirrors the followup-scope marker's three outcomes; total by construction over the (CI-vs-0, point-vs-±0.04) outcome space; the analyzer attaches exactly one verdict, NOT a re-decision at body-write time):

- **REPLICATES:** `Δ_rank_matched` CI excludes 0 AND sign positive AND |point| clears ±0.04 → the adapter-vs-dense leakage gap is behavior-general (holds for both sycophancy and refusal at matched recipe); turns round 4's sycophancy-specific finding into a generality statement. (Magnitude need not match +0.063 exactly; the claim is "same sign, clears the band, CI excludes zero" — a magnitude that lands materially above/below +0.063 is reported as such, not forced to match.)
- **PARTIAL:** `Δ_rank_matched` sign positive AND CI excludes 0 BUT point < +0.04 (shrinks below the separation band) → the gap is directionally present for refusal but weaker than sycophancy; the finding is "directionally general, magnitude behavior-dependent."
- **FAILS:** `Δ_rank_matched` CI spans zero OR sign flips (point ≤ −0.04 with CI excluding 0) → the adapter-vs-dense gap does NOT generalize to refusal at this power; round 4's finding is (at least partly) sycophancy-specific. A sign flip (`opposite_sign_rank`: dense leaks LESS than LoRA on refusal) is reported directionally, consistent with #606's refusal method dead-heat. A CI-spans-zero outcome is reported as noise-limited (a power statement at single seed, NOT "confirms the null") — and is the more likely face of FAILS given #606's refusal dead-heat + the single-seed power.

These three verdicts + the `opposite_sign_rank` subtag jointly partition all reachable `Δ_rank_matched` cells. The implementer's `_classify_outcome` unit test (reused/extended from round 4's lattice test, §4.2) mirrors this enumeration and asserts exactly one verdict per cell.

Threshold ±0.04: inherited from #642 round 4 (`Source: #642 round 4`) so the refusal `Δ_rank_matched` is read on the same scale as round 4's +0.063 sycophancy gap (a scale match enabling the cross-behavior comparison; above the determinacy noise floor 0.05 plug-in-vs-bootstrap per contrast).

Jointly satisfiable: a single headline contrast with one threshold sign per verdict — no two verdicts demand contradictory outcomes on the same read. There is no second contrast this round (the `Δ_data` arm is dropped), so the gate set is trivially coherent.

### Install-strength control (cross-condition leakage comparison — REQUIRED)

The headline IS a cross-condition leakage comparison (2 training arms), so raw-rate comparison is dose-confounded by default. Controlled three ways: (1) **matched-install by construction** — both arms read at s*=0.50, interpolated per arm from its own bracket (the #606 protocol, primary control); (2) **install-vs-leakage dose curves** — the s*-sweep (matched reads at s* ∈ {0.2…0.65}) is produced for both arms, so the contrast is a curve over the dial; (3) the shared matched LR removes the LR-driven install confound by construction. Per the rule's #601-vs-#608 caution (method changes move install strength in either direction), on-policy installs WEAKER than canned but refusal installs FASTER than sycophancy at a fixed LR — which is exactly why the matched-s* read (not a fixed-step read) is the headline and the install-pilot sets the LR so both poles bracket s* with real checkpoints. The fraction-of-install logit-space read is NOT used (the DV is a bounded judge rate, not a marker logit; no marker exists).

### Degenerate-output handling

Per-response degeneracy flag (<5 chars or >80% repeated 3-grams) persisted per generation, cross-tabbed with judge verdicts in stage-A and stage-B. ### Success criteria (numeric)

## 7. Decision Gates

Two gates (justified: wall > 4 h AND the refusal install regime at the matched LR is fast-saturating per #606 — a cheap install signal can rule out an uninterpretable full run by setting the LR correctly). The gates are round 4's gates, re-pointed to refusal:

- **Install-pilot gate (after Phase 0.5, PRE full train; both arms):** train each arm to ~step 44 at the matched-LR target 5e-6, eval source-self refusal s at the coarse grid `{4,12,22,44}`. Decision: (a) **if the cmft (dense) pole installs s ≥ 0.50 by step 4** (the #606 refusal-collapse signature — EXPECTED here, since #606's dense installed refusal in 4 steps at 5e-6) → **fire the pre-registered single matched drop to 2e-6** and RE-PILOT BOTH arms at 2e-6 (the matched-pair invariant: both poles always share one LR). 2e-6 is #606's validated clean in-band refusal-dense LR. (b) **proceed to Phase 1 full train iff** at the chosen LR both arms show monotonic install bracketing s*=0.50 within 132 steps with non-degenerate selected cells. Grounding (sign + threshold): #606 dense refusal at 5e-6 → 4-step install (drop likely fires); #606 dense refusal at 2e-6 → clean mid-grid bracket; the LoRA pole installs slower than dense at any LR, so it brackets later in the grid. **The matched pair ALWAYS shares one LR. The single matched drop (5e-6 → 2e-6) is the ONE pre-authorized LR change this round; a SECOND drop (below 2e-6) is NOT pre-authorized** — if 2e-6 also fails to give both poles a clean s*=0.50 bracket, that is kill criterion (a): report "no matched-LR window for villain on-policy refusal at the available LRs", publish both arms' trajectories, do not compute `Δ_rank_matched`. A third LR requires re-plan (autonomous: `/adversarial-planner` pivot; interactive: must-ask), NOT experimenter discretion.
- **Install gate (after stage-A, per arm):** proceed to stage-B for an arm iff it brackets s*=0.50 with non-degenerate selected cells, OR (no bracket) reaches endpoint s ≥ 0.50 (band-entry fallback read §4.11). On FAIL (an arm neither brackets nor reaches endpoint ≥ 0.50 after the fallback): report install-failure for that arm; the contrast is not computed (reported as exactly that — no silent extrapolation).

These two gates are jointly satisfiable with the §3 lattice by construction: the install gates concern the source-self dial; the decision lattice concerns the single bystander contrast. No gate demands contradictory outcomes on the same read.

**Kill criteria (pre-registered design-failed outcomes):**
- (a) **No matched-LR window for villain on-policy refusal** = at BOTH 5e-6 and the pre-authorized 2e-6 fallback, no shared LR gives both poles a clean s*=0.50 bracket (dense saturates ≤4 steps at both, or one pole brackets while the other never reaches s*) → report the gate-fail as a measurement-feasibility finding, publish both arms' trajectories, do not compute `Δ_rank_matched`. A THIRD LR is NOT auto-authorized (a second drop is a new manipulation → re-plan). Likelihood: low-medium — #606 already validated 2e-6 as a clean dense-refusal LR.
- (b) **Uninterpretable contrast** = `Δ_rank_matched` CI spans 0 with |point| < +0.04 → reported as noise-limited (the refusal method gap may be smaller than sycophancy's, consistent with #606's refusal method dead-heat; a power statement at single seed, NOT "method doesn't matter for refusal"). This is the FAILS-by-noise face of the §3 lattice.
- (c) **Parity-anchor failure** = re-judged villain base refusal cell rates drift from #612/#518's published base refusal rates beyond ±0.08 (hard ±0.15) → the reuse/judge regime is broken; report untrustworthy with the drift published.
