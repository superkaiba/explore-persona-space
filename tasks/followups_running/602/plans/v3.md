## 2. Method delta vs parent — exactly ONE variable

**The single manipulated variable: integrity of the replayed completion tokens (E1 behavior side).** Three levels in the SAME pass:

| Plain-English name | What it does | Role | Config slug |
|---|---|---|---|
| Intact replay | completion tokens verbatim (parent's E1) | positive control, recomputed same-pass | `intact` |
| Within-completion shuffle | per-row permutation of the completion's content token ids (unigram stats preserved, order destroyed), applied SYMMETRICALLY to both contrast sides (below) | PRIMARY level | `shuffle` |
| Question-mismatched pairing | completions intact, but each paired with a different row's prompt (seeded derangement within the unit) | SECONDARY level | `mismatch` |

**Symmetric shuffled-base-self contrast (primary fix, this revision).** The shuffle arm's registered contrast is

> ŵ_shuffle = mean h(shuffled behavior rows) − mean h(shuffled base-self completions)

with the base-self side shuffled under the SAME per-row string-seed scheme, side-suffixed to distinguish the two sides (`:shuffle:behavior` / `:shuffle:base`; §4). Rationale: shuffling pushes BOTH sides off-distribution in the same generic "scrambled-text" way; a one-sided shuffle (shuffled behavior − intact base) injects that generic component into the contrast, diluting the cosine and making a collapse undiagnostic (collapse could mean "content destroyed" OR "generic scramble component dominates"). The symmetric contrast cancels the common scramble component. The UNMATCHED contrast (shuffled behavior − intact base-self) is still computed and reported as a sensitivity read ONLY — it never gates. `intact` and `mismatch` use the intact base-self side (mismatch completions are intact, merely re-paired).

**REUSED unchanged (inherit, do not rebuild):** rig (`scripts/issue602_estimator_reads.py` E1 path + `i602_bakeoff.py` row loaders); the same 100 E1 rows per unit (`bk.e1_rows`, `E1_SUBSAMPLE_SEED = 602`, `N_E1_ROWS = 100`); the same Phase-1a base-self generations (downloaded from `issue602_estimator_bakeoff/raw_completions/base_generations/e1__{family}__{source}__shared.json` — same greedy provenance, never regenerated); the L27 realized writes from the parent's uploaded shifts (`issue602_estimator_bakeoff/analysis_tensors/shifts/`, key `delta_v_mean_resp_l27`; local VM copies in `eval_results/issue_602/shifts/`); the committed decision rules (0.3 bar, 10k-null p95, 0.2 sibling-excluded margin, dual targets w_shared/w_src, mean_resp position); base model `Qwen/Qwen2.5-7B-Instruct`, bf16 forward / fp32 capture, no adapters, no training.
