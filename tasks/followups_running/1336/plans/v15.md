## 3. Hypothesis

**H-P (pooled reproduces per-corpus):** the round-3 sufficient-tier ladder — reparameterization tier constant across SFT/DPO/RLVR on 7/8 corpora / 6/8 recal — is preserved when the fit is pooled across corpora (single 80/20 split, group-aware, cross-corpus sha-deduped). Predicts: pooled tier-6 held-out R² sliced BY CORPUS reproduces the round-3 per-corpus tier-6 numbers to within round-3's own bootstrap CI on ≥7/8 corpora.

**H-OFF (off-policy tracks on-policy at fixed checkpoint):** at fixed activation checkpoint i, the pooled ridge map fit on activations captured under text source j (i ≠ j) tracks the pooled ridge map fit on i's OWN generated text (i = j) — same held-out R² per corpus to within ±0.02·ex_v2. Predicts: the on-policy diagonal is NOT drawing power from the on-policy answer distribution; the map is a property of the checkpoint.

## 11. Decision Rationale

- **Pooled fit (across all 7 corpora, not per-corpus).** Why: the base scope directly asks for a pooled multi-dataset ridge fit; per-corpus fits average away cross-corpus effects and are dominated by size. Source: user directive in base scope v2. Ancillary: pooled n≈70k (dedupe) puts n_train ≈ 44k >> d, far above the sub-2×d regime that plagued round-1/2.
- **Cross-corpus exact-sha dedup BEFORE the 80/20 split.** Why: UltraFeedback and the Tulu-3 SFT-mix (wildchat component) plausibly share source rows; LMSYS overlaps in distribution. A duplicate landing on both sides of the pooled 80/20 is direct leakage. Source: base scope §"Cross-corpus exact-sha dedup". Algorithm: `sha256(raw_prompt_text)`, drop first occurrence in the cross-corpus order (deterministic).
- **Group-aware split (k-means on prompt embeddings, whole clusters).** Why: every corpus has structural near-duplicates (IF-constraints templates, GSM8K/MATH problem-family duplicates, LMSYS real-user paraphrases). A random per-prompt 80/20 measures interpolation within-family, not generalization (`.claude/rules/ood-generalization-folds.md`). Source: rules-directive + base scope §"Group-aware split". k=50 targets ~1,400 prompts/cluster at n≈70k — above fold-train ≥ 2×d bar at K=5.
- **Embedding model = `sentence-transformers/all-mpnet-base-v2`.** Source: widely used prompt-embedding baseline for paraphrase-similarity clustering; beats MiniLM-L6-v2 on paraphrase identification. Sensitivity: the alternative `all-MiniLM-L6-v2` is a follow-up ablation if k-means clusters look pathological at G0v3.
- **On-policy AND off-policy training-text arms.** Source: base scope §"Training-text arms". The off-policy arm is fixed-answer-text — the same prompt-answer pair evaluated under 4 different activation checkpoints. That separates representation-change from answer-distribution-change (the interpretation guard the addendum names).
- **Tier ladder (4 curves per cell): own / T0 direct / T6 context-reparam / T8 both-sides.** Source: v14's tier definitions (`docs/mapping_similarity_metrics.md` @ `fc1087637a`) INHERITED. T6 is the round-3 sufficient-tier ladder's sweet spot. T8 is the parent comp_samefn composition (parent Result-2). Direct + own are the panel bookends.
- **Per-cluster delta-Q + max-cluster permutation null (addendum).** Source: `#1902` `clusters_delta_qc_scatter` + `.claude/rules/selection-symmetric-nulls.md` per-draw-same-selection default. 1,000 draws is standard; the block permutation is within-corpus to preserve mixture composition.
- **Interpretation guard: fixed-answer-text arm as data-structure-vs-representation discriminator.** Source: sibling round #1902 writeup + the addendum's own explanation. If the same cluster surfaces under BOTH on-policy and off-policy at fixed activation checkpoint, the change is representation-side; if only on-policy, it's an answer-distribution artifact.
