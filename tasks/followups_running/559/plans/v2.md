# Plan — Issue #559: Score the base own-response prior on the held-out persona panel (two-ingredient rule joint test)

Parent: #553 (awaiting_promotion, clean result). Kind: experiment (inference-only — no training).

## 0.0 TL;DR (plain English)

- **What I'll run:** Earlier work found a cheap way to predict where a hidden training signature will land before any training happens: ask the untrained model to answer questions in each character's voice and check how close it already comes to producing the signature at the end of its answer. That check only exists on one of our two test panels. I'll run it on the other: have the untrained model answer 20 questions as each of 35 characters, measure its end-of-answer tendency toward the signature, and test whether that tendency predicts where 80 already-trained models actually put it.
- **What I expect:** The untrained model's tendency should rank the 35 characters almost as well as the expensive check that needs each trained model's own answers, which scores about 0.74 out of 1 on average here.
- **What would change my mind:** If the untrained model's tendency carries no ranking signal on this panel, the earlier win was a quirk of the first panel (which included prompts that explicitly told the model to use the signature), and the "predict it before training" recipe loses its main ingredient.

## 2. Prior Work (what exists, what constrains the design)

- **#553** (parent, clean result): on the 16×26 context panel, the own-response prior margin is the top within-source ranker of the trained EOS margin (median ρ +0.85 full panel, narrowly beating the matched-slot read at +0.74; paired diff +0.13 [+0.007, +0.17]) — but the win is carried by the instruction-injected cohort (ordinary-only: prior +0.27 vs matched +0.71). On the persona panel, #553's `_within_run_ranking` (`issue-553:scripts/issue553_transfer_478.py:178-216`) established the incumbents: matched-slot `margin_base` median ρ **+0.7434** [+0.7182, +0.7692] and `min_dist` **+0.3776** [+0.3490, +0.3908] across 80 runs — and named "no own-response base prior exists on this panel" as the limitation this task removes. #553 also validated geometry (`min_dist`) as the router of the training-induced *change* on this panel, and the base end-of-answer level as the only cross-panel survivor.
- **#532** (grandparent): built the own-response prior construction this task mirrors — `scripts/issue532_followup_logp_slot.py` phase A1 (`base_prior_logp.json`): base model generates/loads its OWN response per context, four-float HF read at the end-of-own-R slot, pre-marker truncation guard (`_slot_job`, lines 308-336).
- **#478/#531**: built the persona panel. `eval_results/issue_478/base_prior_reanalysis/tidy_logit.parquet` (56,000 × 25; 40 CORE cells × 2 seeds × 35 personas × 20 questions) carries the trained-side margins (`margin_trained`), the matched-slot base side (`margin_base`, `base_prior`), the geometry predictor (`min_dist`), and full four-float reads both sides. `issue531_logit_rescore.py` defines the panel's slot-scoring convention (`build_items` + `score_slot`: chat template + R appended verbatim, full-string tokenize `add_special_tokens=False`, left-pad, `logits[:, -1, :]`) and its validation gates (MAE < 1.0 nat, Spearman ≥ 0.995 vs stored values; observed worst case over all 80 runs: base MAE 0.077 nat, base ρ ≥ 0.9993 — `eval_results/issue_553/transfer_478.json::rescore_validation`).
- **Key distinction this task turns on:** the parquet's `margin_base` is the base model read at the **trained model's** response slot (matched-slot — needs post-training information). The new measurement is the base model read at the end of **its own** response (computable before any training). On this panel the base model never argmaxes the marker at matched slots (base marker rate 0.0 over 56,000 slots, EOS rate 0.992 — same JSON), so the new prior will live in unsaturated negative-margin territory (parquet `margin_base` range −29.7 to +5.1).

## 3. Hypothesis

**H1 (primary):** The own-response prior margin (one value per persona, pre-training-computable) ranks each run's 35 held-out personas by trained EOS margin nearly as well as the matched-slot read.
- **Confirmed when:** within-run median Spearman's 95% run-bootstrap CI (2,000 reps) is entirely > 0, AND the paired per-run difference (matched-slot ρ − prior ρ; 2,000-rep run-pair bootstrap on the median) is NOT entirely above **+0.10** (parity band: the parent treated +0.13 as a "narrow" separation on the context panel, so a gap that cannot be bounded above 0.10 reads as "nearly as well").
- **Partial outcome:** prior CI > 0 but the paired-difference CI sits entirely above +0.10 — the prior carries real pre-training signal here but the matched-slot read is decisively better; the rule's level half is weaker on personas (scoped-down positive).
- **Falsified when:** the prior's within-run median ρ CI spans 0 — the context-panel leaderboard win is panel-specific (plausibly inflated by the instruction-injected cohort), and the matched-slot read stays the only validated level ranker.

**H2 (two-ingredient joint fit):** Jointly fit with distance-to-nearest-source, the prior carries the level and geometry carries the change:
- On DV `margin_trained` (level): α (prior) coefficient's primary cluster-bootstrap CI clear of 0 with geometry in the model.
- On DV `dmargin` (change): β (geometry) clear of 0, α not — the division of labor #553 predicted. Reported either way; H2 is directional expectation, not a kill criterion.

### Phase B (VM, CPU — off-pod): analysis

New script `scripts/issue559_panel_analysis.py`. Cherry-pick `scripts/issue553_panel.py` from `issue-553` @ `68f3e6b69` (`git checkout issue-553 -- scripts/issue553_panel.py`) for `load_i478_panel`, `step0_i478`, `aggregate_run_persona`, `wider_ci`, and `common_parser`; import the inference helpers from main's `issue539_corrected_reads_inference.py` / `issue539_residual_per_cohort.py`; copy the `_within_run_ranking` (transfer_478.py:178-216) and `_paired_difference_block` (ranking_table.py) function bodies with attribution comments.

1. `load_i478_panel(tidy_logit.parquet)` + `step0_i478` gate (reproduce committed `summary_logit.json` reads to 1e-6 — the #553 entry gate, unchanged).
2. `agg = aggregate_run_persona(df)` → 2,800 run×persona aggregates; left-join `prior_margin_own` on `held_out_persona` (assert no NaN after join).
3. **Within-run ranking (primary):** rankers {`margin_base` (incumbent), `min_dist` (incumbent), `prior_margin_own` (new), `z_prior_plus_z_min_dist` (exploratory stack; z-scored over the 2,800 aggregates, both oriented positively with the DV per the observed signs)} vs `margin_trained` across 35 personas per run, all 80 runs. Incumbent numbers must reproduce the committed `transfer_478.json` values exactly (same code path) — a drift is a bug, fail loud.
4. **Paired parity tests:** per-run paired differences (margin_base − prior_margin_own) and (prior_margin_own − min_dist); 2,000-rep run-pair bootstrap CIs on median + mean difference (the `_paired_difference_block` recipe with pairs = runs).
5. **Two-ingredient joint fit (H2):** DV `margin_trained` on the 2,800 aggregates; design `α·z(prior_margin_own) + β·z(min_dist)` (+ intercept), variants: (i) + standardized-product interaction, (ii) + run FE (80 dummies; the within-run-identified variant — NOTE: a persona-FE variant is impossible by construction, the prior is constant per persona and collinear with persona FE; stated in output). Coefficient inference: run-cluster and persona-cluster bootstraps (2,000 reps, z-scoring + FE re-estimated inside every resample), wider CI primary, plus the cell-axis (40-cluster) bootstrap per the #553 reconciler convention. CV: LOPO (35-fold leave-one-persona-out) and LORO (80-fold leave-one-run-out) out-of-fold R² per feature set {prior, geometry, both, both+interaction}. **Collinearity gate (pre-registered):** Pearson(z(prior), z(min_dist)) over the 2,800 aggregates; |r| > 0.6 → add tercile-bucket median read + polynomial-residualization robustness check.
6. **Division-of-labor fit (secondary):** same design, DV `dmargin` — expectation β survives, α does not.
7. **Diagnostics:** Spearman across 35 personas of `prior_margin_own` vs persona-mean `margin_base` (construction sanity — expect strongly positive; both are base-model end-of-answer reads differing only in whose response conditions the slot); base own-R marker-emission scan (`n_pre_marker_slots`, expect 0); truncation-rate report; per-K and per-seed stratified ranking medians.

## 11. Decision Rationale

- **Model id `Qwen/Qwen2.5-7B-Instruct`** — Why: the panel's base model; the prior must be the same model's read. Source: #478 `result.json` `training.base_model` via `issue531_logit_rescore.py:62`. Repo-already-used id → no AutoConfig pre-provision smoke needed (inherits validation from #478/#531/#532). Alternatives: none valid (any other model breaks the join).
- **Greedy generation, temp 0.0, top_p 1.0, n=1, vLLM seed 42** — Why: deterministic; matches how every response behind the panel's trained margins was generated, and how #532's own-response base R was generated (#460 R_test greedy). Source: `issue-478:scripts/issue478_run_cell.py::vllm_greedy_generate`; task body pre-fill. Alternatives: sampled R (rejected — adds a seed dimension and breaks the construction mirror).
- **`MAX_LENGTH=1024`, cap `1024 − prompt_len − 8`, floor 64** — Why: byte-for-byte the panel's own generation regime; the new prior must differ from the matched-slot read ONLY in whose response conditions the slot, so the length regime must match. Source: `issue-478:scripts/_issue478_common.py:193-197`. **Named deviation from the CLAUDE.md ≥ 2048 default:** that rule guards emission/truncation zeros in marker-emission evals; here the DV is a logit read at the end-of-own-response slot, the base model never emits ※ (verified 0.0 argmax rate on 56,000 slots), and matching the panel cap is the comparability requirement. Truncation rate persisted + reported; > 10% becomes a scope caveat with a sensitivity slice. Alternatives: 2048 cap (rejected — changes the response-length distribution relative to the panel, a second variable).
- **Slot read = full-string tokenize, left-pad, `logits[:, -1, :]`, four floats** — Why: the persona panel's own convention; the S0 gate validates the implementation against stored values. Source: `issue531_logit_rescore.py::score_slot` (+ storage contract per the marker-leakage rule; HF forward pass because vLLM logits are unrecoverable, incident #530). Alternatives: #532's separate-tokenize + right-pad path (rejected for the panel join; its pre-marker truncation guard IS adopted, applied at the token-id level so the no-marker case reduces exactly to the panel convention).
- **Pre-marker truncation guard (ids 83399, 63680)** — Why: the own-response construction being transferred includes it; protects against the "second marker" artifact. Source: `issue532_followup_logp_slot.py::_slot_job` (#532 followup docstring, appended-slot incident). Expected no-op here (verified: no prompt mentions ※).
