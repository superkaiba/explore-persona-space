# Plan v2 — issue #1005: CoT decomposition replication on DeepSeek-R1-Distill-Qwen-7B (template-forced thinking)

## 0.0 TL;DR (plain English)

- **What I'll run:** the same context→CoT→answer prediction pipeline from the OpenThinker2 experiment, unchanged except for the model — DeepSeek-R1-Distill-Qwen-7B, whose chat template forces every reply to start inside a `<think>` block. Same 50 conversation contexts, same 48 questions, same fits, same matched-length control, same two prompt-input conventions.
- **What I expect:** the model now emits a parseable reasoning block on nearly every reply (the old model skipped it on a third to half of the in-context-learning and WildChat rows), the chain-of-thought still helps predict the answer state, and the extra-large gains previously seen on those two context families shrink to nothing once the parsing losses are gone.
- **What would change my mind:** if the in-context-learning and WildChat contexts STILL show outsized gains at near-full coverage, the effect is a real property of those context families, not a parsing artifact — and the parent's covariate story gets rewritten. If the CoT gain vanishes entirely, the mediation result is specific to the OpenThinker2 lineage.

## 3. Hypothesis

The parent's mediation signature replicates on a second thinking lineage, and the flagged-context covariate is a parse-coverage artifact that disappears when the template forces the scaffold.

Registered quantities (all at the frozen primary layer conventions re-derived by the parent's rule, §6):

- **Δ_CoT** — per-question paired-bootstrap Δskill(CoT-augmented − direct), context input, frozen per-question layer. Parent: +0.20.
- **C** — min(ICL, WildChat per-family usable-row rate) − 0.95. Parent: 0.51 − 0.95 = −0.44 (badly failed); template-forced thinking predicts C ≥ 0.
- **Δ_fam** — the length-matched family contrast: mean per-context CoT gain over the 18 ICL+WildChat contexts minus their greedy nearest-neighbor same-length partners drawn from the other 32 contexts (matched on median well-formed CoT length, the parent's 14-pair machinery re-keyed to family membership, which is defined independently of parse rate), paired bootstrap CI over pairs, per-question regime.
- **Δ_MLC** — per-question Δskill(CoT-conclusion slice − answer-opening slice) on the shared remainder target, both input conventions. Parent: −0.052 (context) / −0.054..−0.092 (prefix).

### 4.4 Segmentation (Phase P) — why code, not a model call

Exact char-offset parser (`issue928_common.segment_completion` with `rung="prefill"` semantics on every rung — the `TEMPLATE_FORCES_THINK` switch): well-formed iff exactly one `</think>` and non-empty CoT and answer; malformed classes dropped-and-counted per context (`no_close`, `multiple_close`, `empty_cot` — the documented R1 bypass mode `<think>\n\n</think>` lands here — `empty_answer`, `degenerate_repetition`, `truncated_no_close`). A model call is rejected for segmentation: the delimiters are literal single tokens; the parse is exact, free, and auditable. No all-or-nothing gate: per-context 80% usable floor FLAGS (never drops a context); coverage counts embedded in the store. `char_span_to_token_span` (overlap mapping) carries spans to token space — note the delimiters are single added tokens here, so the parent's measured BPE-merge seam (`>` fusing with newlines) cannot occur; the machinery handles both regardless.
