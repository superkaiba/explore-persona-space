## 0.0 TL;DR (plain English)

- **What I'll run:** The Betley run (already in flight) asked "can the model's internal reaction
  to a prompt predict how it'll behave?" — but it only asked that on a set of deliberately
  provocative, misalignment-flavored prompts. I'll now ask the EXACT same question on a set of
  ordinary everyday questions (cooking, travel, language trivia), matched to be the same length,
  and check whether the answer is the same on both. One thing changes: the kind of question.
- **What I expect:** For behaviors that the model actually does on normal questions (sycophancy,
  hedging, refusing some requests), the prediction should hold on the everyday prompts too — that
  would say the "you can read behavior off the prompt's internal trace" property is real, not a
  quirk of scary prompts. For the misalignment-flavored behaviors (acting broadly badly, complying
  with harmful requests), the model probably almost never does them on cooking questions, so there
  will be nothing to predict — and that absence is the answer for those, not a failure.
- **What would change my mind:** If the prediction works great on the provocative prompts but
  collapses on the everyday ones for a behavior that DOES still vary on everyday prompts, that
  would mean the whole foundation is riding on the prompt genre and wouldn't transfer to real
  deployment traffic — which is exactly the safety-relevant case I care about (does the chain
  reach benign contexts).

## 1. Goal & hypothesis

**Goal (inherited from #658 `## Goal`, unchanged):** determine whether the leakage-predictor's
base-model chain holds on Qwen2.5-7B-Instruct (A3.2/A3.3/A3.4/A3.5) and lock the best layer +
summary recipe. **The (G1) amendment's specific question:** is the base-model chain a property of
the model's context→behavior geometry, or an artifact of the behavior-eliciting query genre — i.e.
does it transfer to the benign deployment distribution (open-q 3.7, leakage to default/benign
contexts)? B6 varies the prompt distribution TOGETHER with the behavior; (G1) holds the behavior
fixed and varies ONLY the query genre, length-controlled, so the two genres are directly
comparable.

**Hypotheses (falsifiable) — the genre-delta call reads off the Δρ CI (v3):**
- **H1 (transfer):** for behaviors with dynamic range on BOTH pools (sycophancy, hedging,
  self_report, format_style, persona_drift, marker), the per-behavior best-(layer,summary)
  Δρ = ρ_UC − ρ_Betley has a 95% Δρ CI that OVERLAPS ZERO. SUPPORTS (not "proves"): the genre
  delta is not distinguishable from the noise floor under this design — consistent with the chain
  being a geometry property rather than a genre artifact for that behavior. (The within-band read
  supports "not distinguishable from the noise floor," NOT "proven genre-equality" — statistical-
  framing discipline, §6.)
- **H2 (genre-bound):** for ≥1 behavior with dynamic range on both pools, the 95% Δρ CI lies
  ENTIRELY BELOW ZERO (UltraChat ρ reliably below Betley ρ) AND the UltraChat ρ drops below its
  own within-genre noise floor while the Betley ρ clears its floor. FALSIFIES H1 for that
  behavior — the chain is genre-bound there. This is the safety-relevant negative.
- **H3 (floor, expected for misalignment behaviors):** broad_em / harmful_compliance / refusal sit
  at expression floor on UltraChat (testable variance ≈ 0) → ρ undefined → reported as "no dynamic
  range on the generic genre," NOT as a chain break. The continuous log-P DV is the primary read
  where the rate floors. No Δρ CI is computed for a behavior without dynamic range on BOTH pools.

The headline genre-bound-vs-geometry decision text reads: "Δρ CI overlaps zero on M of N
behaviors with dynamic range on both pools (H1-consistent); the CI lies entirely below zero on
K behaviors (H2 / genre-bound)." It is NEVER stated as a proof of equality and NEVER read off the
per-arm noise-floor comparison alone.

### 4.3 Why code, not a model call?

### Dual-DV + the FLOOR GUARD (the load-bearing read for this arm)

Per the standing dual-DV rule AND `epm:followup-scope` explicitly: register BOTH (a) the judged
on-policy RATE as PRIMARY and (b) the length-normalized base `log P` of judged-positive on-policy
completions as the SECONDARY non-saturating companion, validated by Spearman(rate, log-P) across
dynamic-range cells. **The genre-specific escalation:** the misalignment behaviors
(broad_em / harmful_compliance / refusal) are EXPECTED to floor at ≈0 expression on generic
everyday queries (H3) — exactly where the binary rate has no dynamic range to predict. For ANY
behavior whose UltraChat rate has near-zero testable variance, **the continuous log-P DV becomes
the PRIMARY read** (the marker-leakage three-space dual-DV recipe, generalized). A no-variance ρ is
reported as "no dynamic range on the generic genre — chain untestable here," NEVER as "the chain
breaks." Per-behavior testable variance is reported PER POOL (a small table: behavior × {Betley
variance, UltraChat variance}) so the reader sees which behaviors the genre comparison is even
defined for.

### Per-genre vs cross-genre reads + the Δρ CI (mandatory, per `epm:followup-scope v2`; v3)

- **PRIMARY (per behavior, per genre):** Spearman ρ, scored on TWO SEPARATE stores (Betley vs
  UltraChat), each against its OWN within-genre noise floor + predict-mean + base-prior. Never a
  pooled cross-genre fit (pooling would manufacture or mask the genre effect — the #545
  pooled-vs-held-out lesson).
- **SECONDARY:** Pearson, per-behavior best layer/recipe per genre, and the genre delta in
  predictive quality.
- **Genre delta Δρ (the headline read, v3):** per behavior with dynamic range on BOTH pools,
  Δρ = ρ_UC − ρ_Betley with a **95% Δρ CI from an independent cluster bootstrap**. The two arms
  have DIFFERENT probes, so no paired resamples are possible — the procedure pairs WITHIN-ARM by
  context cluster (one cluster per behavior for A3.2/A3.3, per context for A3.4/A3.5, mirroring
  v1's bootstrap clustering), takes ≥2000 INDEPENDENT bootstrap draws PER ARM (matching the v1 §11
  2000-resample setting), recomputes the best-cell ρ per arm per draw, takes the per-draw
  difference ρ_UC − ρ_Betley, and reports the 2.5/97.5 percentiles + a `null_overlap` flag.
  **The headline genre-bound-vs-geometry call reads off this Δρ CI, NOT off per-arm noise-floor
  comparisons alone** (a per-arm-floor read can flip the verdict on noise because the joint
  uncertainty Δρ can be wider than either arm's per-arm floor band). Each arm's per-arm
  within-genre noise-floor 95th-pct band is ALSO shown alongside the Δρ CI (so the reader sees both
  the per-arm noise level and the joint difference uncertainty). Decision text: H1 supported where
  the Δρ CI overlaps zero; H2 (genre-bound) where the Δρ CI lies entirely below zero AND the
  UltraChat ρ falls below its own floor while the Betley ρ clears its floor.

### Statistical-framing discipline (CLAUDE.md "Critical Rules" + clean-result-critic Lens 7)

A within-band Δρ (Δρ CI overlaps zero) supports "the genre delta is NOT distinguishable from the
noise floor under this design" — it does NOT prove genre-equality of the chain. The H1 read is
phrased as "consistent with / not distinguishable from" (an equivalence-style read bounded by the
Δρ CI), NEVER as "CONFIRMS equality" or "proves the chain is genre-invariant." A reliably negative
Δρ CI (entirely below zero) supports "genre-bound for this behavior." All three reads (H1/H2/H3)
are stated against the Δρ CI / the per-pool dynamic-range table, not against a single point estimate.

### Install-strength control

N/A — no cross-condition leakage comparison, no fine-tuning, no install (inherited from v1 §6).
The genre delta is a comparison of base→base predictability across two probe genres, not a leakage
comparison across training conditions.

### Statistical-input existence

All statistical inputs are produced in-scope by THIS arm: the UltraChat noise-floor 95th-pct
(N1's 8 redraws from the UltraChat pool), the FDR over the UltraChat grid, the per-(C,probe) answer
spans for N1 resampling (stored in G2), and the v3 Δρ CI's per-arm bootstrap draws (computed off-pod
from the two arms' cached per-cell ρ-by-cluster inputs — the same per-cell scoring inputs the v1
bootstrap already produces, so no NEW derived input is introduced; the Δρ CI consumes them
directly). The Betley `aggregate.json` (and its per-cell bootstrap inputs) consumed by the
genre-delta read (A2) are produced by the Betley arm (same issue, already in flight / committed) —
a SAME-ISSUE in-scope artifact, not a phantom prior-run dependency; A2 fails loud if the Betley
`aggregate.json` is absent (the genre delta is then reported as "Betley arm pending," not silently
skipped). No attenuation/reliability correction consuming an UNBUILT derived input is registered.

### Metrics, tests, thresholds

- **PRIMARY:** Spearman ρ (predictor vs measured UltraChat `E0`), per behavior, per layer, per
  summary. Pearson secondary.
- **PASS (per behavior, UltraChat arm):** best-(layer,summary) ρ > 95th pct of the UltraChat N1
  noise floor AND > predict-mean ρ AND > base-prior ρ. A3.3 PASSes iff the linear ρ is within the
  UltraChat noise floor of the A3.2 MLP ρ. (Identical bar to v1, scored on the UltraChat store.)
- **GENRE-DELTA verdict (the headline, v3):** read off the per-behavior 95% Δρ CI — H1-consistent
  (CI overlaps zero), H2 / genre-bound (CI entirely below zero AND UltraChat ρ below its floor while
  Betley ρ clears it), or H3 / no-dynamic-range (not computed; reported via the per-pool variance
  table + the log-P fallback). The genre-bound-vs-geometry call is NEVER read off the per-arm
  noise-floor comparison alone.
- **Statistical hygiene:** cluster-aware bootstrap (one cluster per behavior for A3.2/A3.3, per
  context for A3.4/A3.5), 2000 resamples; the Δρ CI uses ≥2000 INDEPENDENT draws per arm with the
  same clustering. FDR q=0.10 (Benjamini-Hochberg) WITHIN each genre's ~1000-cell grid (the genre
  delta is a between-arm read, not added to the FDR family). Report the per-behavior best cell with
  FDR-adjusted p AND the across-layer ρ profile.

single experimental variable is the probe pool — so the literature re-search is not re-run (the
inherit fast-path: a value the parent arm validated for this exact model + data carries over).

The ONLY genre-specific load-bearing choices + the two v3 fixes:

- **Probe pool = UltraChat 48, `data/issue594/probes_ultrachat.json`.** Why: the arm's entire point
  — a generic everyday-query genre, length-matched (decile-aligned) to the Betley misalignment pool,
  to isolate the query-genre variable from prompt-length confounds. `Source: #594
  issue594_build_probes_ultrachat.py` (the matched pool was built + length-validated there);
  `epm:followup-scope v1/v2` (the design decision). Pinned by file sha256 `a6caadf0…` AND
  meta.probe_pool_hash `f277f8c3…` (fail-loud drift assert in the dispatcher). **The pool drives
  v0/c_C extraction ONLY — never r_B's `D_{B̄}` (see the r_B row below).** Alternatives: an unmatched
  generic pool — rejected, length would confound the genre delta; a different generic corpus —
  rejected, UltraChat is the project's canonical generic-conversation source validated under #594.
- **c_C recomputed fresh (both recipes) for the UltraChat arm.** Why: c_C is probe-dependent (the
  #594 `cc_last` HF store's own `probe_pool_hash` drift-assert pins it to the Betley pool), so
  reusing the Betley c_C with UltraChat probes would be a wrong-artifact reuse. `Source:
  epm:followup-scope` ("c_C recomputed per genre, NOT forced equal") + the #594 store's pinning
  assert. Alternatives: force the Betley c_C — rejected, it measures the wrong genre's context
  geometry and the genre-induced c_C shift is part of what the arm measures.
- **r_B / Σ_c REUSED from the Betley arm (or recomputed if absent on HF); r_B `D_{B̄}` PINNED to the
  Betley probe pool in BOTH branches (v3 fix — the consistency-checker BLOCK).** Why: r_B is a
  diff-in-means over #545's behavior corpora against a contrast baseline `D_{B̄}`, and Σ_c is a
  background-corpus second moment. **r_B is probe-pool-independent ONLY when its `D_{B̄}` half is
  pinned to a single canonical pool across genres.** In `build_rb_contrast`, the `D_{B̄}` half is
  `neutral = probes[:cap]` for 3 of the 4 columns (`betley_vs_neutral`, `syco_claim_vs_neutral`,
  `harmful_vs_benign`); passing the active UltraChat `probes` there would silently swap r_B's
  contrast baseline by genre (the smuggled second variable). The v3 fix passes the canonical Betley
  pool (`fetch_preregistered_probes(exclude=main8)`) to `build_rb_contrast` in BOTH the reuse and
  the recompute-if-absent branches, so r_B is genuinely genre-invariant. Σ_c is built on the primary
  `corpora.load_generic_questions` path (probe-free), NOT the `except`-fallback (which would use the
  Betley probe pool) — the manifest records `sigma_source` to confirm. `Source: plan v1 §4.2/§4.4`
  (the genre-independent construction) + `consistency-checker BLOCK (D_{B̄} pin)` + CLAUDE.md "Reuse
  existing trained artifacts when fit-for-purpose." Fitness: (a) recipe match — same diffmeans/meanDB
  recipe, same #545 corpora, same Betley `D_{B̄}` pool, same Σ_c builder; (b) measurement regime — a
  read-out direction + a second moment, no saturation concept; (c) cells present — all
  behaviors/contexts covered; (d) single-variable — the `D_{B̄}` pin REMOVES the genre-swap that
  would have smuggled a second variable, so r_B is identical in both genres BY CONSTRUCTION; (e)
  producing arm not retracted (same live issue); (f/g) N/A (no adapter, no rsLoRA gauge). When the
  Betley `r_b.pt`/Σ_c are not yet on HF at this arm's launch, recompute fresh with the `D_{B̄}` pin —
  identical recipe to the Betley arm, no divergence. Recorded in
  `store_manifest.json::reused_from_betley` + `::rb_dbbar_pool` + `::sigma_source`.
- **Δρ CI via an independent cluster bootstrap (v3 — the Codex Statistics REVISE).** Why: when the
  genre delta IS the headline, comparing each ρ to its OWN per-arm noise floor is necessary but not
  sufficient — the joint uncertainty Δρ = ρ_UC − ρ_Betley can be WIDER than either arm's per-arm
  band, so a per-arm-floor read can flip a "genre-bound" vs "no genre effect" verdict on noise.
  Procedure: the two arms have DIFFERENT probes, so no paired resamples are possible — pair
  within-arm by context cluster (the v1 clustering: per behavior for A3.2/A3.3, per context for
  A3.4/A3.5), take ≥2000 INDEPENDENT bootstrap draws per arm (matching the v1 §11 2000-resample
  setting), recompute the best-cell ρ per arm per draw, take the per-draw difference, report the
  2.5/97.5 percentiles + `null_overlap`. The headline reads off this CI (H1 where it overlaps zero;
  H2 / genre-bound where it lies entirely below zero AND the UltraChat ρ falls below its own floor
  while Betley clears it). A within-band Δρ supports "not distinguishable from the noise floor under
  this design," NOT proven equality (statistical-framing discipline, §6). `Source: v1 §11 bootstrap
  (2000 resamples, #545 scoring.py) + Codex Statistics Δρ-CI REVISE`. Alternatives: per-arm
  noise-floor comparison alone — rejected, it can flip the verdict on noise (the exact defect the
  REVISE flagged); a paired bootstrap — impossible, the two arms have disjoint probe sets.

**No model training** — the MLP/ridge are CPU regressions (inherited v1 §11), not a fine-tune;
there is no train lr/batch/epoch. **Repo-new model id** — N/A; `Qwen/Qwen2.5-7B-Instruct` is
repo-already-used (v1 + #594), no `AutoConfig` pre-provision smoke needed.
