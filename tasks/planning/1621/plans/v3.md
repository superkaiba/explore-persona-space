### 4.1 Patch A — checkout-detach clause (guard L1364)

```text
old: \bgit\b[^;&|]*\bcheckout\b +(-{1,2})detach\b
new: \bgit\b[^;&|]*[^-]\bcheckout\b +(-{1,2})detach\b
```

- `[^-]` consumes exactly the char before the verb token: space/tab in every real invocation (still blocks); `-` in the `--no-checkout` / `--checkout` flag spellings (no longer matches). The `[^;&|]*` prefix can match zero chars, so the mandatory space after the leading `git` token satisfies `[^-]` — no real spelling is lost (prototype: existing 13-shape MUST-BLOCK detach matrix all still block; full suite green).
- Add 2–3 comment lines to the clause's comment block (L1358–1363): the hyphen-preceded-flag exclusion (#1621, incident 552fa84d), and the pre-existing quoted-verb parity note (never matched; unchanged).

## 11. Decision Rationale

- **A1 (chosen): `[^-]` preceding-char class.** What: exclude hyphen-preceded verb tokens. Why: fixes the boundary artifact itself; covers `--no-checkout` AND `--checkout` uniformly; zero change to any real spelling (prototype-verified). Alternatives: (A2) exempt `worktree add` command shapes via a guard-arm — broader (waives any detach-looking text in such clauses) and adds a second grep per clause; kept as the §7 fallback. (A3) require whitespace before the verb — would newly exclude the quote-wrapped spelling that A5 shows is moot, but `[^-]` is strictly narrower.
- **B1 (chosen): argv-list carve inside check (f) + two fail-closed arms.** What: §4.2.
