# Plan v1 — Issue #385: Marker spread dynamics, 14-checkpoint sweep, librarian → 19-persona + 8-context panel

## 1. Goal

Track how a `[ZLT]` marker spreads from a `librarian` source persona to a 19-persona + 8-context bystander panel across 14 fine-grained checkpoints during LoRA SFT on Qwen2.5-7B-Instruct. Test whether the bystander emission order at the 5% threshold tracks (a) L20 cosine-to-source and (b) completion JS-divergence-to-source, both computed on the BASE model, reported side-by-side. This distinguishes radial propagation (geometric distance is the mechanism) from cascading or uniform-threshold propagation (geometric distance only describes the asymptote of #207).

## 2. Hypothesis (verbatim from body.md `## Hypothesis` block)

**Primary (radial):** Bystander personas cross the 5% emission threshold in order of decreasing geometric proximity to the source persona. Operationally, the Spearman rank correlation between (predictor) and (training step at which bystander first crosses 5% emission, censored at the training horizon) is `|ρ| ≥ 0.5` with `p < 0.01` for BOTH cosine and JS-divergence across the 26 bystanders. Whether cosine and JS-divergence predict the same bystander order — or diverge mid-training — is itself a sub-result.

**Secondary (non-persona-context):** The 8 non-persona-context cells cross the threshold at training steps consistent with the persona radial propagation, treating them as additional points on the same axis.

**Null:** All bystanders cross the threshold within a narrow window (IQR ≤ 0.5× the median crossing-step) — propagation is uniform-threshold and the geometric handle only captures the asymptote.

## 3. Kill criterion (verbatim from body.md `## Kill criterion` block)

The radial mechanism claim is killed if EITHER:

1. **Both predictors fail the rank test:** `|ρ_cos| < 0.2 AND |ρ_JS| < 0.2` (Spearman against first-crossing step at the 5% threshold, across the 26 bystanders).
2. **Threshold uniformity:** `IQR(first-crossing step across bystanders) > 1.0× median crossing-step` — propagation is too uniform for any ordering claim to be meaningful.

A mixed outcome (exactly one of cosine vs JS-divergence passes the rank test) does NOT kill the radial claim but is flagged as a paper-quality finding about #207's predictor primacy.

**(c) New custom callback** — `src/explore_persona_space/train/callbacks.py` (NEW file):

```python
"""TrainerCallbacks specific to step-list checkpointing."""

from __future__ import annotations

import logging
import os
import shutil
from pathlib import Path

from transformers import TrainerCallback

logger = logging.getLogger(__name__)


class SaveAtSpecificSteps(TrainerCallback):
    """Save a LoRA adapter checkpoint at each step in ``steps_list``.

    TRL/HF SFTTrainer's native ``save_strategy='steps'`` only supports
    constant-interval saves. This callback fires at exactly the listed
    global_step values, creating ``{output_dir}/checkpoint-{step}/`` and
    calling ``model.save_pretrained`` (PEFT adapter only — bf16 LoRA adapter
    is ~150 MB, so 14 saves ≈ 2.1 GB total, well under the ~130 GB
    MooseFS per-pod quota documented in CLAUDE.md).

    Args:
        steps_list: Integer global_step values at which to save (sorted).
        output_dir: Base directory under which ``checkpoint-{step}`` dirs are
            written.
    """

    def __init__(self, steps_list: list[int], output_dir: str):
        self.steps_set = set(int(s) for s in steps_list)
        self.output_dir = Path(output_dir)
        self._fired: set[int] = set()

    def on_step_end(self, args, state, control, model=None, **kwargs):
        step = int(state.global_step)
        if step not in self.steps_set or step in self._fired:
            return
        if args.local_process_index != 0:
            return
        if model is None:
            logger.warning("SaveAtSpecificSteps: model is None at step %d", step)
            return
        ckpt_dir = self.output_dir / f"checkpoint-{step}"
        ckpt_dir.mkdir(parents=True, exist_ok=True)
        # PEFT adapter-only save: writes adapter_config.json + adapter_model.safetensors
        model.save_pretrained(str(ckpt_dir))
        tokenizer = kwargs.get("processing_class") or kwargs.get("tokenizer")
        if tokenizer is not None:
            tokenizer.save_pretrained(str(ckpt_dir))
        self._fired.add(step)
        logger.info("SaveAtSpecificSteps: saved checkpoint-%d to %s", step, ckpt_dir)
```

### 5.3 Eval pipeline

**Eval entrypoint:** new script `scripts/eval_i385_marker_spread.py`. Pseudocode:

```python
# Inputs: $RUN_DIR/checkpoint-{step} for step in [5,10,...,1600]
#         BYSTANDERS (19 personas + 8 contexts, total 27)
#         PROMPTS (20 from PERSONAS module)

from vllm import LLM, SamplingParams
from vllm.lora.request import LoRARequest
from explore_persona_space.eval.trait_scorers import evaluate_markers

llm = LLM(
    model="Qwen/Qwen2.5-7B-Instruct",
    enable_lora=True,
    max_lora_rank=32,
    tensor_parallel_size=1,
    gpu_memory_utilization=0.85,
)

sampling = SamplingParams(n=8, temperature=1.0, max_tokens=512, top_p=1.0)

per_step_results = {}
for step in [5, 10, 25, 50, 75, 100, 150, 200, 300, 400, 600, 800, 1200, 1600]:
    lora_req = LoRARequest(
        lora_name=f"i385_step{step}",
        lora_int_id=step,
        lora_path=f"{RUN_DIR}/checkpoint-{step}",
    )
    # build (bystander, prompt) prompts
    prompts_in = []
    keys = []
    for bys_name, bys_system in BYSTANDERS.items():
        for pi, probe in enumerate(PROMPTS):
            msg = [{"role": "system", "content": bys_system},
                   {"role": "user", "content": probe}]
            rendered = tokenizer.apply_chat_template(msg, tokenize=False, add_generation_prompt=True)
            prompts_in.append(rendered)
            keys.append((bys_name, pi))
    outputs = llm.generate(prompts_in, sampling, lora_request=lora_req)
    # collate per bystander
    by_bys = {b: {p: [] for p in range(20)} for b in BYSTANDERS}
    for out, (b, pi) in zip(outputs, keys):
        by_bys[b][PROMPTS[pi]] = [o.text for o in out.outputs]  # 8 completions
    marker_res = evaluate_markers(by_bys, marker="[ZLT]")
    per_step_results[step] = marker_res

# Save eval_results/issue_385/marker_spread_seed42.json
```

Each `(checkpoint, bystander)` cell yields 20 probes × 8 completions = **160 completions** (n=160), `evaluate_markers` returns `rate = found / 160`. Total completions: `14 × 27 × 160 = 60,480` (matches body's "56,700" within rounding from the n=150 vs n=160 swap).

vLLM throughput on 1× H100 for Qwen2.5-7B is ~5–10K tokens/s; assume each completion ≤512 generated tokens → ~30M tokens / 7K tok/s ≈ 4,300s ≈ **1.2 hours** for the full 14-checkpoint sweep (one LoRA-load + generate cycle per checkpoint, batched within a checkpoint).

### 5.4 Predictor computation (BASE model, computed ONCE)

**New script** `scripts/compute_i385_predictors.py`. Two outputs:

**(a) L20 cosine-to-source:** Lift the centroid-based protocol from `experiments/phase_minus1_persona_vectors/extract_persona_vectors.py` (last-token L20 over each of the 20 PROMPTS, mean-pooled per persona to a centroid, then cosine on centroids). For the 8 non-persona contexts, do the same: forward `(system=fammate_*, user=probe)` for each of the 20 PROMPTS, last-token L20, mean-pooled. Outputs `eval_results/issue_385/predictors_base.json` with keys `cosine_to_librarian` per bystander.

Reuses the existing `cosine_matrix.json` for the 19 personas (no need to recompute) — sha256-verify `c1a8050744e06c60fc56ca88582324ec3c70c29df39df2f29fb814e905161b0f` at script entry. Compute the 8 context entries fresh (extend the matrix to 27 rows + librarian).

**(b) Completion JS-divergence-to-source:** Reuse `src/explore_persona_space/analysis/divergence.py::compute_pairwise_divergences` (signature confirmed: `log_probs: (N, response_len, V), persona_names: list[str], kl_only=True, row_chunk=16, time_chunk=30`). Protocol matches #341 exactly:
1. Generate one greedy `no_persona`-anchored 256-token response per PROMPT via vLLM (temp=0, top_p=1, seed=42), 20 responses total.
2. For each (PROMPT, response), teacher-force the response through Qwen2.5-7B-Instruct under each of {librarian, 19 bystander personas, 8 non-persona contexts} = 28 system prompts.
3. Collect `(28, response_len, V=152064)` log-softmax tensors per prompt. Pass to `compute_pairwise_divergences(kl_only=True)`.
4. Average per-prompt JS matrices over the 20 prompts → single 28×28 JS matrix. Extract the `librarian` row → JS-to-source for 27 bystanders.

Stores at `eval_results/issue_385/js_matrix_base.json`.

### 5.5 Diagnostic (per-checkpoint, SECONDARY)

For each of the 14 checkpoints, recompute:

### 5.6 Analysis

**New script** `scripts/analyze_i385_marker_spread.py`. Inputs:
- `eval_results/issue_385/marker_spread_seed42.json` (per-step × per-bystander rate matrix, 14 × 27).
- `eval_results/issue_385/predictors_base.json` (27 cosine-to-source + 27 JS-to-source on base).
- `eval_results/issue_385/predictors_per_checkpoint.json` (diagnostic).

Computations:

1. **First-crossing step at 5% threshold per bystander.** Sustained-crossing rule (per body §Risks): bystander has crossed iff rate ≥ 0.05 at current step AND at the next checkpoint. Bystanders that never cross have first-crossing = `1600 + 1` (censored). Repeat for 25% and 50% thresholds.

2. **Spearman ρ tests (PRIMARY).** For each threshold ∈ {5%, 25%, 50%}:
   - `ρ_cos = spearmanr(cosine_to_librarian, first_crossing_step)` over 26 bystanders (excluding `no_persona`).
   - `ρ_JS = spearmanr(JS_to_librarian, first_crossing_step)` over 26 bystanders.
   - Two-sided p-value from `scipy.stats.spearmanr`. Hypothesis predicts `cosine` LOW = closer ⇒ EARLIER crossing ⇒ negative ρ; `JS` LOW = closer ⇒ EARLIER crossing ⇒ positive ρ (signs matter for the predictor-coupling sub-result).

3. **IQR / median ratio (kill criterion 2).** `IQR(first_crossing_step) / median(first_crossing_step)` at the 5% threshold over the same 26 bystanders.

4. **Cosine-vs-JS predictor-stability across training (per body Primary metrics).** Per checkpoint, recompute the bystander-rank correlation between the per-checkpoint cosine row and the per-checkpoint JS row; track how it drifts from ρ_base = 0.94.

5. **Figures (saved to `figures/issue_385/`):**
   - `fig_emission_vs_step_by_cosine.png` — 27 colored emission curves (one per bystander) on a single axis, color-coded by base-model L20 cosine-to-source (viridis). Plus marker thresholds at 5%/25%/50% as dashed horizontal lines.
   - `fig_emission_vs_step_by_JS.png` — same, color-coded by base-model JS-to-source.
   - `fig_crossing_vs_cosine_scatter.png` — scatter of (cosine_to_source, first_crossing_step) per bystander, 3 panels (5%/25%/50% thresholds), Spearman ρ annotated.
   - `fig_crossing_vs_JS_scatter.png` — same for JS.
   - `fig_predictor_drift.png` — per-checkpoint cosine-vs-JS rank correlation over training.

Built via the `paper-plots` skill / `src/explore_persona_space/analysis/paper_plots.py` rcParams.

## 7. Evaluation

**Primary metrics + thresholds:**

| Metric | Threshold for PASS (radial confirmed) | Threshold for FAIL (kill criterion) |
|---|---|---|
| `|ρ_cos|` (Spearman, base-model cosine vs first-crossing-step at 5%) | `≥ 0.5` AND `p < 0.01` | `< 0.2` (joint with ρ_JS) |
| `|ρ_JS|` (Spearman, base-model JS vs first-crossing-step at 5%) | `≥ 0.5` AND `p < 0.01` | `< 0.2` (joint with ρ_cos) |
| `IQR(first_crossing_step) / median(first_crossing_step)` | `≤ 0.5×` (clean radial) | `> 1.0×` (kill — threshold uniformity) |
| Bystander coverage | ≥ 20 of 26 bystanders cross 5% by step 1600 (otherwise rank test is too censored to interpret) | < 10 of 26 bystanders cross by step 1600 (re-run with longer horizon, NOT kill) |

**Sample sizes:** N = 26 bystanders for the primary Spearman. Power at ρ=0.5, α=0.01, one-sided ≈ 0.86 (sufficient for a clean signal; underpowered for ρ=0.3).

**Secondary metrics:**
- Cosine-vs-JS predictor agreement at each checkpoint (compared against `ρ_base = 0.94` from #341).
- Per-bystander emission-rate trajectories (visual; informs whether non-monotone behavior is widespread).

## 9. Risks and failure modes

| Risk | Likelihood | Mitigation |
|---|---|---|
| Saturation before step 50 — all bystanders cross 5% before fine-grained cadence resolves | Medium (the 600-row mix at lr=1e-5 may saturate fast per #192's ~625-step-per-epoch finding) | Pilot-fold (see §8). If saturation, re-run with lr=3e-6 and cadence {2,5,10,25,...}. |
| Noise oscillation near 5% threshold on n=160 (binomial 95% CI ≈ ±3 pp at p=0.05) | High at low-cosine bystanders | Sustained-crossing rule (current AND next checkpoint ≥ 5%). |
| Non-monotone emission for individual bystanders (early emission then regress) | Medium (per body) | Report both first-crossing and last-checkpoint emission; flag if >3 bystanders diverge. |
| `cosine_matrix.json` sha256 drift (cached file changed) | Low (file is read-only) | Sha256-verify at predictor script entry; fail loudly. |
| `no_persona` chat-template asymmetry (its base-model JS row uses literal-empty-system ChatML, not the Qwen default) | Inherited from #341 | Exclude `no_persona` from the n=26 rank test (matches #341); include as a visual point only. |
| MooseFS per-pod quota (~130 GB) | Low — 14 adapters × ~150 MB each = ~2.1 GB; raw completion JSONs ~200 MB | Set `EPM_SKIP_INLINE_CHECKPOINT_UPLOAD=1` at launch (per CLAUDE.md gotcha). |
| Per-checkpoint diagnostic predictor recomputation is expensive | Medium (1.5 GPU-hours) | Run sequentially after primary eval on the same pod. Can be skipped if budget is tight — it's secondary; the primary rank test runs on base-model predictors only. |
| TRL/HF `max_steps=1600` with `epochs=-1` semantics | Low — well-documented; multi-epoch wrap-around at sampler level handled by TRL | Smoke test: launch with `max_steps=10` first, verify checkpoint-5 and checkpoint-10 dirs appear. |

## 10. Resources and parallelism

**Single 1× H100 pod, `--intent lora-7b`.**

- Training: 7B LoRA on 600-row mix, `bs=4, grad_accum=4, lr=1e-5, max_steps=1600` → ~1.5h wall (extrapolating from #192's 625-step ~30min runs at the same effective batch size).
- Primary eval (vLLM LoRA, 14 checkpoints × 27 bystanders × 20 probes × 8 completions = 60,480 completions): ~1.2h wall.
- Diagnostic per-checkpoint predictors (14 × full JS rig + L20 forward): ~1.5h wall.
- Analysis + figures: ~5 min CPU.

**Total wall: ~4.2 hours on a single 1× H100. Total GPU-hours ≈ 4.2.**

**Parallelism axis analysis (per planner.md §9):**

| Axis | Status |
|---|---|
| Tensor parallelism | N/A (7B fits on a single H100). |
| Data parallelism (FSDP/ZeRO-3) | N/A (LoRA r=32, single GPU is sufficient). |
| Batched inference (vLLM) | **In use** — single `LLM.generate()` per checkpoint batches across all 27 bystanders × 20 probes × 8 completions. |

A single 1× H100 (`lora-7b` intent) is the right spec. Going to 4× H100 would not speed the eval enough to amortize 4× setup since vLLM throughput on a single GPU saturates the inference workload at 7B.

## 12. Decision rationale (load-bearing parameter choices)

- **`learning_rate = 1.0e-5`.** Matches body §"Training recipe" verbatim. Default `configs/training/default.yaml` is 5e-6 (too gentle — #228 used 1e-4 for 7 sources × 10 epochs and saw spread). 1e-5 is the calibrated mid-point used in #262/#310/#192. Alternatives considered: 5e-6 (too slow; risk of no spread before step 1600), 5e-5 (too fast; risk of saturation before step 25).
- **`max_steps = 1600`.** Body §"Training recipe": "extends past saturation to see whether late-stage spread continues or plateaus." #192 found ~625 steps per epoch; 1600 ≈ 2.67 epochs. Alternative considered: 800 steps (one epoch + 25%) — rejected; loses the "does late spread continue" sub-question.
- **`LoRA r=32, α=64`.** From `configs/lora/default.yaml`. Matches #207, #228, #341 conventions.
- **Checkpoint cadence `{5, 10, 25, 50, 75, 100, 150, 200, 300, 400, 600, 800, 1200, 1600}`.** Body-specified. Geometric-style early then sparser late. 14 checkpoints is the right tradeoff between resolution and storage / eval cost.
- **n=160 (20 probes × 8 completions) vs body's n=150.** The body's 30-probe × 5-completion gives 150; I propose 20 PROMPTS × 8 completions = 160 to reuse #341's canonical probe set unchanged. Binomial 95% CI at p=0.05 is ±3.4 pp either way — the difference is negligible. Alternative considered: extend PROMPTS to 30 with 10 new probes — rejected because it would break cross-experiment comparability with #341's predictor file.
- **T = 1.0, top_p = 1.0.** Body-specified. Matches #341's eval temperature.
- **Single seed = 42.** Body-specified. Trade-off: deep cadence over seed robustness. Confidence ceiling: MODERATE (matches #207).
- **`max_new_tokens = 512` for eval.** Project default per `configs/training/default.yaml`. Marker is `[ZLT]` (5 chars, ~3 tokens); 512 is ≥10× the marker length, so truncation does NOT cause silent zeros — distinct from the failure mode in CLAUDE.md "max_new_tokens" rule which applies to end-of-completion marker evals on long trained sequences. The training mix's completions average ~200 tokens (verified by sample inspection of the 600-row JSONL); 512 is ≥2× that.
- **`save_strategy=no` + custom callback.** TRL `save_strategy='steps'` only supports integer cadence; arbitrary step list requires a callback (verified by reading TRL 0.14+ source and the `_build_periodic_callbacks` pattern already in `trainer.py`). Alternative considered: use `save_strategy='steps'` with `save_steps=5` then prune unwanted checkpoints — rejected (wasteful disk writes).
- **`no_persona` excluded from n=26 rank test.** #341 own caveat: its base-model JS row is under literal-empty-system ChatML, not Qwen-default. Including it would contaminate the predictor. Visual-only.
