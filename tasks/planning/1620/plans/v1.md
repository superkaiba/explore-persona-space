# Plan v1 — issue #1620: pathspec-scope the root-commit guard's staged-index cert check

### 0.0 TL;DR (plain English)

- **What I'll change:** I'll fix the repo-root commit guard so that a commit naming its own explicit paths (`git commit -- <paths>`) is no longer blocked by some OTHER session's unlinted staged file — the guard will check only the files that commit would actually land. I'll also reorder the block message so the "commit only your own paths" recovery comes before the env-var override, add a per-path debug line saying exactly which cert comparison failed, and close a small cert-file write race.
- **What I expect:** the ≥8/day foreign-staged false blocks disappear for pathspec commits; bare commits and `-a` commits keep today's full-index check; every "would actually land" uncertified payload still blocks; the next flaky block self-explains on stderr.
- **What would change my mind:** if I find a pathspec-bearing `git commit` form that can land staged content OUTSIDE its pathspec and that my flag handling does not neutralize (I enumerate them: `-a`, `-i/--include`, `--interactive/--patch`, `--pathspec-from-file` — all disable scoping), the scoping design is unsound and the fix reduces to message + debug improvements only.

## 0. Plan Summary

**Change:** `.claude/hooks/guard_root_code_commit.sh` Layer 2 currently unions the ENTIRE staged index into `pending` unconditionally (L614, L620-621); commit-clause pathspecs collected by Layer 1 only ADD paths (`text_paths`, L422-430) and never RESTRICT the staged scan, so a concurrent session's uncertified staged `scripts/*.py` blocks a pathspec-limited commit that cannot land it. Every unparseable/ambiguous shape falls back to today's whole-index check (block direction). (b) The BLOCKED message names the pathspec-limited recovery before `EPM_ALLOW_ROOT_CODE_COMMIT`. (c) Per-path `cert-diag:` stderr lines name which comparison failed (no line / sha mismatch / stale age / empty computed sha; staged vs worktree sha shown). (d) `scripts/inline_lint_gate.py::write_cert` gets an inode re-check under flock closing the append-to-orphaned-inode trim race (the leading flaky-fresh-cert hypothesis). Tests: ~10 new pytest cases + 2 self-test battery cases; both target test files are stem-mapped by the Step 9c selector.

## 4. Design

### 4.1 Diagnosis (the exact mechanism)

**Primary bug — foreign-staged false block on pathspec commits.**

- `classify_cmd()` (hook L315-435) collects, in its commit/add token scan (L404-431), ONLY gated-prefix tokens into `text_paths` — the collection predicate at L422-423 is `case "$tok" in scripts/* | src/* | tests/*)`. A non-gated pathspec token (`eval_results/x.json`, `docs/y.md`, `CLAUDE.md`) matches nothing and is DISCARDED; there is no `commit_has_pathspec` bit anywhere. After Layer 1, the hook cannot distinguish `git commit -m x` (whole staged index lands) from `git commit -m x -- docs/y.md` (only `docs/y.md`'s worktree content lands).
- Layer 2 (L613-621) then reads the WHOLE staged index unconditionally and unions it into the pending set:
  ```
  staged=$(git -C "$GUARD_REPO" diff --cached --name-only ...)   # L614 — whole index, no pathspec
  pending=$(printf '%s\n%s\n%s\n' "$staged" "$mod" "$text_paths" \
    | grep -E "$GATED_PATH_ERE" | sort -u)                        # L620-621
  ```
  The faulty predicate is exactly this pair: the staged read at L614 is never intersected with the commit-clause pathspec; `text_paths` participates only additively (L620) and as a worktree-binding signal (L640-642). A concurrent session's uncertified staged `scripts/foo.py` therefore enters `pending`, fails `check_certified()` (L440-449) at L653, and blocks at L658-673 — even though `git commit -- docs/y.md` would not commit `scripts/foo.py` at all (git-commit(1): a pathspec commit records the worktree content of the NAMED paths only, "disregarding any contents that have been staged for other paths").
- Why B6 passes while this fails: B6's pathspec IS a gated file (`scripts/issue9_fig.py`) — it exercises the additive direction (`text_paths` → pending), which works. The restrictive direction was never designed (§2, #1500 plan L13).

**Secondary (flaky fresh-cert block, session 12462773) — LOW-CONFIDENCE hypothesis.** The code makes one race visible: `write_cert` (inline_lint_gate.py L438-456) appends under `flock` on an fd opened BEFORE the lock is acquired. A concurrent gate run performing the 500-line trim (mkstemp + `os.replace`, L447-452) swaps the path to a NEW inode while a second writer is blocked on the flock of the OLD inode; the second writer then appends its cert lines to the orphaned old inode — the lines never appear at `/tmp/eps-inline-lint-cert-v1.txt`, and its session's next commit blocks with a "fresh" cert that isn't in the file. The docstring at L424-426 names lost-line as an accepted residual. This fits "fresh cert, blocked, later passed" only if the gate re-ran (or a second append landed) in the 100 s gap — not provable from the artifacts, hence LOW confidence. Alternative candidates (transient `git hash-object` failure → empty sha at L645/L651 → `check_certified` never matches; a momentary worktree content difference at hook-fire time) are equally consistent with the symptom. Deliverable (c)'s debug line discriminates all of these on the next occurrence (no-line-for-path ⇒ lost-append race; sha-mismatch ⇒ content drift; stale-age ⇒ MAX_AGE; `want=EMPTY` ⇒ git failure); deliverable (d) removes the one code-visible race regardless.

### 4.2 Fix (a): pathspec-scoped staged check

**Layer 1 — `classify_cmd()` extension** (new globals initialized at L317 alongside the existing ones): `commit_has_pathspec=0`, `pathspec_opaque=0`, `commit_bare_clause=0`, `scope_unsafe=0`, `commit_pathspecs=""` (newline-separated). Implemented as a SECOND, dedicated token pass per commit clause (inside the existing per-record loop, after the existing scan at L404-431 — leaving the existing `text_paths` / `has_dash_a` / `add_all_chained` collection byte-identical, zero regression risk to the 40+ existing tests). Pseudocode for the second pass (verb=commit clauses only; `set -f` around word-splitting, mirroring L411):

```bash
# per commit clause: skip tokens until the literal verb token `commit`
local after_ddash=0 skip_next=0 saw_verb=0 n_cand=0 clause_opaque=0
for tok in $masked; do
  if [ "$saw_verb" = 0 ]; then [ "$tok" = commit ] && saw_verb=1; continue; fi
  if [ "$after_ddash" = 1 ]; then classify_candidate "$tok"; continue; fi
  if [ "$skip_next" = 1 ]; then skip_next=0; continue; fi
  case "$tok" in
    --) after_ddash=1 ;;
    --include|--interactive|--patch|--all|--pathspec-from-file|--pathspec-from-file=*) scope_unsafe=1 ;;
    -m|-F|-C|-c|-t|--message|--file|--template|--author|--date|--fixup|--squash|--cleanup|--trailer|--reuse-message|--reedit-message) skip_next=1 ;;
    --amend|--signoff|--no-signoff|--no-verify|--verify|--quiet|--verbose|--dry-run|--status|--no-status|--allow-empty|--allow-empty-message|--reset-author|--branch|--porcelain|--long|--short|--null|--edit|--no-edit|--only|--gpg-sign|--no-gpg-sign|--untracked-files|--*=*) : ;;
    --*) scope_unsafe=1 ;;                       # UNKNOWN long flag: may consume next word -> never guess
    -[a-zA-Z]*)
      case "$tok" in *a*|*i*|*p*) scope_unsafe=1 ;; esac   # -a re-stage / -i include / -p patch
      case "$tok" in *m|*F|*C|*c|*t) skip_next=1 ;; esac   # cluster ending in an arg-taking letter
      ;;
    *) classify_candidate "$tok" ;;              # positional token = candidate pathspec
  esac
done
# clause close-out: saw_verb=1 && n_cand==0 -> commit_bare_clause=1
```

`classify_candidate`: a clean token (no `$FILL`, no quote chars, no backslash) appends to `commit_pathspecs` and bumps `n_cand`; a mask/quote-bearing token sets `clause_opaque=1` **unless** recoverable via the raw-after-`--` step below. Clause close-out ORs `clause_opaque` into `pathspec_opaque`. Multiple commit clauses union their pathspecs (union of pathspec-scoped landing sets = the scoped landing set); ANY bare commit clause sets `commit_bare_clause=1` (a `--` with nothing after it counts as bare — git treats it as a plain staged-index commit).

**Quoted-pathspec recovery (raw-after-`--`), the L371-377 raw-recovery precedent applied:** when the clause has a masked `--` token and ≥1 post-`--` candidate is mask/quote-bearing, recover raw tokens from the RAW record: take the substring after the LAST whitespace-delimited `--` word in `$raw` (pathspecs trail the message, and no pathspec token is `--`, so the last raw `--` word is the real separator), split on whitespace, strip ONE surrounding quote pair per token. Consistency gates, each failing to `clause_opaque=1` (fallback): recovered-token count must equal the post-`--` masked candidate count (a spacey quoted path is ONE masked token but ≥2 raw tokens — mismatch detected); any recovered token still containing a quote char, `$FILL`, or backslash is rejected. This covers the common `git commit -m "msg" -- "docs/a.md"` shape; quoted pathspecs WITHOUT `--` stay opaque (documented limitation, §8 R4).

**Layer 2 — scoped read** (replacing the unconditional block at L613-621 with a two-branch form):

```bash
scope=0
if [ "$has_dash_a" = 0 ] && [ "$scope_unsafe" = 0 ] && [ "$commit_bare_clause" = 0 ] \
  && [ "$pathspec_opaque" = 0 ] && [ "$commit_has_pathspec" = 1 ] && [ -n "$commit_pathspecs" ]; then
  scope=1
fi
if [ "$scope" = 1 ]; then
  mapfile -t pspecs < <(printf '%s\n' "$commit_pathspecs" | grep -v '^$')
  if staged=$(git -C "$GUARD_REPO" diff --cached --name-only -- "${pspecs[@]}" 2>/dev/null); then
    mod=$(git -C "$GUARD_REPO" diff --name-only -- "${pspecs[@]}" 2>/dev/null || true)
  else
    scope=0   # git rejected the pathspec (bad magic, outside-repo) -> conservative fallback
  fi
fi
if [ "$scope" = 0 ]; then
  # existing L614-619 verbatim: whole-index staged read (fail-CLOSED on git failure), -a mod read
fi
# existing L620-621 pending union + GATED_PATH_ERE filter, unchanged
```

Design points:

- **git evaluates the pathspec, not the hook.** `git diff ... -- <pathspec>` natively handles the edge cases the task body names: shell-glob tokens (`eval_results/*.json` — passed literally; quoted array expansion `"${pspecs[@]}"` never shell-globs), `:(glob)`/`:(top)`/`:!` magic, directory pathspecs (`scripts/` matches every staged file under it — the must-BLOCK dir case), renames (old name surfaces as a deletion → exempt via the existing `[ -f ]` check at L644; new name is checked at worktree content). No pathspec-matching reimplementation.
- **Landing-set correctness:** a pathspec commit lands worktree-vs-HEAD content of matched tracked files. `worktree≠HEAD ⇒ (worktree≠index) ∨ (index≠HEAD)`, so `--cached ∪ plain-diff` covers the landing set exactly — chosen over a single `git diff HEAD` because the test fixtures (and the existing hook contract) must work on an unborn HEAD (`_init_repo` fixtures have no commits; L614 already relies on `--cached`'s empty-tree behavior there).
- **Binding:** in the per-path loop (L633-653), `scope=1` forces `worktree_shape=1` for every pending path (a pathspec commit lands worktree content — the existing L624-631 BINDING RULE comment already states this; today it engages only via `text_paths` exact-match at L640). Deletion exemption (L644) and the staged/worktree sha branches are otherwise unchanged.
- **`text_paths` stays additively unioned** in both branches — preserves the compound `git add scripts/new.py && git commit -- scripts/new.py` untracked case (B12: file invisible to both git diffs pre-execution, carried by the Layer-1 text path).
- **Every ambiguity degrades to today's behavior** (whole-index, block direction): `-a` (its pathspec combination is a git fatal anyway), `-i/--include` (lands the whole staged index PLUS the named paths — scoping would false-allow), `--interactive`/`--patch`, `--pathspec-from-file` (paths unknowable at hook time), any UNKNOWN long flag without `=` (its separate-word argument could be misread as a pathspec, silently shrinking the checked set — the one false-ALLOW route; refusing to guess closes it), unreadable quoted pathspecs, any bare commit clause in the compound, git rejecting the scoped diff.

### 4.3 Fix (b): BLOCKED-message ordering

In the block path (L658-673), before emitting the heredoc, compute per-uncertified-path origin: `foreign=1` iff `scope=0` and ≥1 uncertified path is NOT in `text_paths` (i.e., it came from the shared staged index, not the command line). When `foreign=1`, a paragraph (interpolated variable in the existing heredoc) is inserted IMMEDIATELY after the `BLOCKED:` line + cert-diag lines and BEFORE everything else, naming the pathspec-limited recovery first:

> Path(s) above came from the shared STAGED INDEX, not your command line. Another session's staging? Commit ONLY your own paths — a pathspec-limited commit is never blocked by foreign staged files: `git commit -m "<msg>" -- <your paths>` (unquoted paths; the guard scopes its check to the pathspec).

The existing gate-recipe / worktree / hand-write-ban text follows; the `EPM_ALLOW_ROOT_CODE_COMMIT` paragraph stays LAST (it already is — the deliverable is that the pathspec recovery is named before it, which this ordering guarantees; pinned by test c9's index comparison).

### 4.4 Fix (c): `cert-diag:` debug lines

New function `cert_diag <path> <computed-sha> <binding>` called only in the block path (zero hot-path cost), one stderr line per uncertified path, stable grep-able format:

```
cert-diag: <path> binding=<staged|worktree> want=<sha12|EMPTY> staged=<sha12|-> worktree=<sha12|-> cert=<none-for-path | sha-mismatch:<csha12>,age:<s>s | stale:<age>s>max_age:<MAX_AGE>s | ok> cert-file:<bytes>B,mtime:<epoch>
```

Semantics: scan `$CERT` for lines whose path field equals `<path>` (same parse as `check_certified`, L443-446); `none-for-path` when no line exists (the lost-append/race signature); else report the NEWEST matching-path line's sha + age — `sha-mismatch` when sha differs (content drifted since certification), `stale` when sha matches but age exceeds `MAX_AGE`; `ok` is emitted only if a line matches fully (which contradicts the block — itself diagnostic of a logic bug). `want=EMPTY` exposes a failed `git hash-object`/`ls-files` (L645/L647/L651). `staged=`/`worktree=` are computed once in the block path (`ls-files -s` / `hash-object`, `-` when absent) so a binding confusion is visible directly. This makes each of the §4.1 flaky-case candidates distinguishable at the next occurrence.

### 4.5 Fix (d): close the write_cert orphaned-inode append race

`scripts/inline_lint_gate.py::write_cert` (L440-441): after `fcntl.flock(fh, LOCK_EX)`, verify the locked fd still names the path — `os.fstat(fh.fileno()).st_ino == os.stat(cert_path).st_ino` (a missing path counts as mismatch); on mismatch, close, reopen `a+`, re-lock, re-check — bounded at 5 attempts, then proceed with the last fd (the current lost-line behavior, still block-direction-safe). ~10 lines; the append/trim logic is otherwise untouched.

## 7. Kill criteria

- **Scoping is unsound if** a pathspec-bearing `git commit` form can land staged content OUTSIDE its pathspec AND is not neutralized by the scope-off set. Per git-commit(1) the commit content modes are exactly: plain staged, `-a/--all`, pathspec (`--only` default), `-i/--include`, `--interactive`/`--patch` — the latter four all set `scope_unsafe`/`has_dash_a` and fall back to the whole-index check, and `--pathspec-from-file` (a pathspec TRANSPORT, not a mode) also falls back. If review or testing surfaces a form outside this enumeration (or a git version whose long-flag argument parsing defeats the unknown-flag fallback), KILL fix (a) — ship only (b)+(c)+(d) (message ordering, debug line, race hardening), which alone satisfy two of the three Goal clauses, and re-plan (a) with a stricter extractor.
- **Kill (d)** if the inode re-check measurably changes `write_cert` semantics for the single-writer case (any existing `tests/test_inline_lint_gate.py` regression).
- No decision gates — short run, 0 GPU-h, mechanically testable.
