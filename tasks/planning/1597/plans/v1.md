**Proposed text (verbatim — the deliverable; 17 lines):**

```
1c. **The 1b rotation duty covers EVERY log a crash-signature or
   completion-pattern grep may scan — including INNER per-cell logs that
   dispatcher SUBPROCESSES open in append mode — not only the
   dispatcher-level phase log.** A relaunch that rotates the outer phase
   log but leaves an inner append-mode `<out_root>/<cell>/train.log` in
   place still feeds the previous crash's lines to any health-monitor /
   watch-session grep that scans it (#1112 fix-4 relaunch, 2026-07-21: a
   monitor grepping the un-rotated inner `train.log` false-fired
   "ASSERT-FAILED-AGAIN" on the PREVIOUS crash's assert lines — the
   inner-log twin of 1b's #952 false-fire). Rotate inner logs in the
   same command chain where practical. Where rotation is IMPRACTICAL —
   a live subprocess owns the append-mode handle, or the per-cell log
   set is enumerated dynamically — scope every crash-signature grep
   past the relaunch instead: capture a byte-offset sentinel at launch
   (`wc -c < <log>` → `$OFF`, recorded beside the pid file) and scan
   only the suffix (`tail -c +$((OFF+1)) <log> | grep ...`), or filter
   to lines timestamped after the recorded launch time. A whole-file
   pattern match against an un-rotated append-mode log is NEVER a valid
   crash-signature read — the grep-side sibling of the #779
   stale-existing-file false-DONE (CLAUDE.md § Monitoring).
```
