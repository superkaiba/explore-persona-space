#### 4.1 Grain decision (the load-bearing correctness question, worked)

**The coherence component is three-way.** `check_lessons_index` (`scripts/workflow_lint.py:16742`, docstring at :16749-16757) binds `LESSONS.md` to the `.claude/rules/*.md` set BIDIRECTIONALLY — failure mode "(a) a rule file with no index row, (b) an index row with no rule file" — AND `_LESSONS_MAX_BYTES`/`_LESSONS_*` (:16653/:16663/:16671/:16679/:16739) bind LESSONS.md to the linter. So constants, index, and dir contents form ONE component split across family keys `lint` and `.claude/rules`.

**Option (a) — `.claude/rules/LESSONS.md` as its own SPECS token, family `lint` — is BROKEN as stated, twice over:**
1. *Pathspec containment defeats the withhold (the incident direction).* Pass 2 filters TOKENS, but the checkout acts on PATHSPECS: with lint dirty and `.claude/rules` clean, SAFE_SPECS still contains the DIR token, and `git checkout origin/main -- .claude/rules ...` matches `LESSONS.md` through it — the file token's withhold is a no-op. Fixing this requires either decomposing the dir token into ~45 per-file tokens (a rot surface needing its own completeness guard) or injecting `:(exclude).claude/rules/LESSONS.md` into SAFE_SPECS conditionally (git exclude pathspecs subtract command-wide, so the exclude may ride ONLY when the file token was withheld — new conditional logic in two mirrored fail-closed blocks).
2. *It opens the index-parity channel (the reverse direction).* Rules-dirty/lint-clean would sync LESSONS.md alone while the dir is withheld: main's index rows for main-NEW rule files hit failure mode (b) (row without file) — a NEW gate-red channel on a hot trigger (rules-file branch edits). Rejected.

**Option (b) — `FAMILY_OF[".claude/rules"]="lint"` — is complete but measured-too-wide.** It is the only single-family assignment satisfying all pairwise constraints (everything moves together), and it is a one-line edit per copy. But the coupling is SYMMETRIC, and the reverse direction is hot: 248 main commits/60 d touch `.claude/rules`; 187 of them touch rules WITHOUT touching LESSONS.md or the linter (measured this session, §11). Every branch carrying such an edit would newly withhold the linter + selector + `agent_spec_size_caps.txt` while `.claude/skills`/`.claude/agents` keep syncing — widening the trigger surface of the PRE-EXISTING #2321-class cap-skew (main grows a skill/agent doc + raises its cap same-diff; branch-era caps red the gate) from "branches editing lint members" to "branches editing any rule file", one of the most common infra-branch edits. #2327's plan rejected (b) on this exact ground; the measurement independently confirms it.
