## 0.0 TL;DR

One `planned_wall_h` cell whose first character is not a digit (`(1.5)` on #2163) makes
`poll_pipeline.py` discard the whole §9 budget and disarm the phase-ETA tripwire for the
entire run, with only one line of poller stdout to show for it. Fix: move the float rule
from `.match()` (position-anchored) to `.search()` (first float anywhere) in ONE shared
stdlib-only helper both `poll_pipeline.py` and `verify_plan.py` import; keep the global
fail-safe for a cell carrying no number at all, but make that case visible at plan time
(new `verify_plan.py` check c47, WARN) and durable at runtime (one `epm:progress` post per
run naming the offending row). 0 GPU-h, no pod, five files.

**What would change my mind:** if the corpus re-scan (§6) shows the widened rule changes
ANY existing plan's parsed total — the behavior-preservation invariant claims it cannot,
since a `.match()`-success cell has its first float at position 0 — then the widening is not
strictly conservative and the design needs a compatibility branch rather than a
substitution. Equally, if `epm:progress` turns out to require a `workflow.yaml` schema row
(Assumption 2), the AC #5 channel is a public-contract change and must be re-scoped rather
than shipped inside this round.

## 1. Goal

A single `planned_wall_h` table cell whose first non-space character is not a digit
must not disable the phase-ETA tripwire for an entire run. The tripwire keeps its
fail-safe-OFF posture for a cell carrying no number at all, but that degradation
becomes (i) rarer, (ii) visible at plan time, and (iii) durable in the task record
instead of a single line of poller stdout.

## 2. Root cause (grounded)

| Site | Fact |
|---|---|
| `scripts/poll_pipeline.py:3856` | `_LEADING_FLOAT_RE = re.compile(r"\s*([0-9]+(?:\.[0-9]+)?)")` |
| `scripts/poll_pipeline.py:3899` | markdown row scan calls `_LEADING_FLOAT_RE.match(cells[col])` |
| `scripts/poll_pipeline.py:3930` | HTML row scan calls the same regex with `.match()` |
| `scripts/poll_pipeline.py:3901,3932` | no match ⇒ `raise _UnparseableWallRow(...)` |
| `scripts/poll_pipeline.py:3956-3959` | `_parse_plan_wall_budget` wraps the whole row scan in `except Exception: return None` — the WHOLE plan's budget, never a partial sum |
| `scripts/poll_pipeline.py:4103-4111` | `None` ⇒ one `log.info(...)` gated by the run-scoped `eta_budget_warned` state flag, then `return` — the tripwire is off and nothing durable records it |
| `tasks/running/2163/plans/plan.md:303` | the realized offender: `\| P6-GPU conditional cell (1x H100 fp64 eigh + solve + score) \| (1.5) \| ...` |

`.match()` anchors at position 0 (the regex's own `\s*` absorbs leading whitespace only),
so the leading `(` of `(1.5)` fails to match. #2163's §9 table has **13** data rows; 12 of
them are bare floats. One parenthesized cell discarded all 12 and disarmed the run.

## 3. Adjudication of the body's proposed fixes

The body says "either or both; the planner should adjudicate". Verdict: **adopt all
three (a)/(b)/(c), and reject the per-row-degrade variant the body floated inside (a).**

| Candidate | Verdict | Reason |
|---|---|---|
| (a) parser tolerance — first float ANYWHERE in the cell | **ADOPT** | Covers every realized annotation shape: `(1.5)`, `~1.5`, `1.5-2`, `1.5 (conditional)`. Strictly widening — see the identity invariant in §6. |
| (a′) degrade PER ROW instead of globally | **REJECT** | AC #2 is explicit: "a cell with no float at all still **fails safe**". A partial total also degrades in the FALSE-POSITIVE direction — `budget_sec = mult × total × 3600` shrinks, so the tripwire fires EARLIER; `_parse_plan_wall_budget`'s own docstring names this ("an under-parsed budget is the one path to a false positive"). With (a) landed the residual class is a cell carrying no number at all (`TBD` / `N/A` / `—`), where a partial total is a guess rather than a budget. What made the global disable harmful was its SILENCE, and (b)+(c) remove exactly that. |
| (b) plan-time check, one shared parse helper | **ADOPT** | `verify_plan.py` check `c47`, WARN-only, naming the offending row. |
| (c) make the degradation loud | **ADOPT** | A durable `epm:progress` post, once per run, naming the offending row(s). |

## 4. Design — the change set

### 4.1 New shared module `src/explore_persona_space/plan_wall_budget.py` (AC #4)

Stdlib-only (`re`, `dataclasses`). This is the SINGLE home of both the table locator and
the float rule; neither script keeps a private copy of either regex.

```python
WALL_HEADER_TOKEN = "planned_wall_h"

@dataclass(frozen=True)
class UnparseableWallCell:
    row_text: str      # the offending row (markdown) or cell (HTML), truncated to 120 chars
    reason: str        # "no_float" | "short_row"
    fmt: str           # "markdown" | "html"

@dataclass(frozen=True)
class PlanWallBudget:
    total_h: float | None                        # None ⇒ caller disables the tripwire
    rows: tuple[float, ...]                      # every parsed per-row value
    unparseable: tuple[UnparseableWallCell, ...] # populated even when total_h is None
    reason: str                                  # "" | "no_table" | "unparseable_cell"

def parse_wall_cell(cell: str) -> float | None: ...          # the FLOAT RULE
def parse_plan_wall_budget(plan_text: str) -> PlanWallBudget: ...
```

- **Float rule:** `re.compile(r"[0-9]+(?:\.[0-9]+)?")` + `.search()` — the first float
  anywhere in the cell. Returns `None` for a cell with no digits.
- **Locator:** the markdown + HTML scans lift verbatim from `_md_planned_wall_rows` /
  `_html_planned_wall_rows` (`poll_pipeline.py:3862-3936`), preserving every property the
  existing tests pin: all tables carrying the header are located and summed; the value
  column index is DERIVED from the header cell position in both formats; the HTML scan is
  scoped to each owning `<table>`; a markdown `|---|:---:|` separator row is skipped.
- **Deliberately NOT fence-masked**, matching the poller's raw-text scan. A fenced example
  table carrying `planned_wall_h` with an unparseable cell genuinely does disable the live
  tripwire, so warning about it at plan time is correct, not a false positive. Fence-masking
  the poller would change existing plans' totals and is out of scope (§7).
- **Fail-safe reduce:** `unparseable` non-empty ⇒ `total_h = None`, `reason =
  "unparseable_cell"`. Zero located tables / zero data rows ⇒ `total_h = None`, `reason =
  "no_table"`. A total that sums to exactly 0 stays `None` (preserves today's `sum(rows) or
  None`), so `_eta_deviation_update`'s non-positive-budget fail-safe is unchanged.

### 4.2 `scripts/poll_pipeline.py` — delegate, then name the failure (AC #1, #2, #5)

- Keep `_parse_plan_wall_budget(plan_text) -> float | None` as a thin delegation to
  `parse_plan_wall_budget(...).total_h` so the eight existing contract tests in
  `tests/test_poll_eta_tripwire.py` stay green unchanged.
- Add `_plan_wall_budget_for_issue(issue) -> PlanWallBudget | None` — the fail-soft I/O
  layer (`None` ONLY on missing task / missing plan / unreadable file), reading
  `plans/plan.md` exactly as `_plan_total_wall_h_for_issue` does today. Keep
  `_plan_total_wall_h_for_issue` as a thin wrapper (its fail-soft test calls it directly).
- In `_maybe_post_eta_deviation` (`:4103-4111`), replace the log-only branch:
  - `budget.reason == "unparseable_cell"` **and** `not budget_warned` ⇒ keep the existing
    `log.info`, and additionally `post_event(issue, "epm:progress", by="poll_pipeline", ...)`
    with a note whose FIRST token is the fixed, greppable `eta-tripwire-disabled`, carrying:
    the count of parseable rows discarded, up to 3 offending rows verbatim (truncated), and
    the remedy ("write a bare float in the `planned_wall_h` cell; put the conditionality in
    the `basis` cell"). Then set `budget_warned = True`.
  - Post failure ⇒ `log.error(...)` and leave `budget_warned` unset, so the next tick
    retries — the same retry contract the `epm:compute-deviation` post already uses
    (`:4151-4153`).
  - `budget.reason == "no_table"` ⇒ log only, **no marker**. An `infra` / `analysis` plan
    with no §9 compute table is the normal case; a marker there would post noise on every
    such task, every run.
- **Once-per-run, re-arming:** `eta_budget_warned` is already in `_TRIPWIRE_STATE_KEYS`
  (`:4190`), hence in `_RUN_SCOPED_STATE_KEYS` (`:4197`), hence cleared by
  `_tripwire_run_scope` on a fresh `epm:run-launched`. Gating the post on that flag gives
  exactly one post per run and re-arms on relaunch — no new state key.

### 4.3 `scripts/verify_plan.py` — check `c47` (AC #3, #4)

  task's plan regardless of `kind`):
  - `reason == "no_table"` ⇒ `_skip` ("no `planned_wall_h` table — this plan arms no poller
    tripwire").
  - `unparseable` non-empty ⇒ `_warn`, detail bounded to 3 offenders in the
    `_c26_offender_detail` style: each offending row + its reason, the count of parseable
    rows that would be discarded, the remedy, and the `#2163`/`#2172` incident anchor.
  - else ⇒ `_pass` (`"<n> rows, total <x.xx> h"`).

**Behavior-preservation invariant (the load-bearing regression guard):** for every cell the
old `.match()` rule parsed, the new `.search()` rule returns the SAME float — a
match-success cell has its first float at position 0 by construction. So no existing plan's
total changes; the change is strictly a widening. Pinned by a property-style test over a
fixture corpus of cell strings, plus the corpus re-scan below.

**Corpus re-scan (required deliverable, the c33 calibration convention):** run c47 over
every persisted `tasks/*/*/plans/*.md` and report the WARN count with the offending plans
named. The test asserts the scan completes without raising and does NOT assert zero WARNs —
#2163's plan is in the corpus and is expected to warn. The count is what licenses a future
WARN→FAIL escalation; it is not escalated in this round.
