# Plan v1 — #1858 daily-fix: RunPod failover launcher — kill-and-reap + bounded retry on the boot branch-sync leg

### TDD: no

## 1. Requirement + acceptance criteria (kind: infra)

**Requirement.** The RunPod execute-workload boot sync (`_execute_workload_on_pod` leg (a), `src/explore_persona_space/backends/runpod.py`) must not surface a terminal `runpod_workload_start_failed` on the FIRST MooseFS-hang of a remote git op. Incident #1769 fu1 (2026-07-30, verified from the task's own markers): the branch-sync ssh hit the 180 s local `TimeoutExpired`, the local kill left the REMOTE git (pid 1992) hung on MooseFS holding `.git/index.lock`, the existing conditional reap (`pgrep -x git || rm -f .git/index.lock`) can never fire against a LIVE hung git, and the leg went straight to terminal — ~1.5 h manual stall until a hand kill+reap+resync succeeded ON THE SAME POD (proving a bounded automatic retry would have recovered it).

**Acceptance criteria:**
1. The remote branch-sync script self-bounds its git ops (remote-side `timeout -k 10 150` on fetch/checkout/reset — below the 180 s local ssh bound) so a FUSE-hung git op is killed REMOTELY and the lock-holder dies with it, instead of surviving the local ssh kill.
2. On the FIRST sync failure (TimeoutExpired or non-zero rc), the leg runs a bounded REAP script: SIGKILL surviving `git` processes in the pod clone, bounded-wait for death, then unconditionally `rm -f .git/index.lock`; the script reports `REAP-OK killed=<n> survivors=<m> lock_removed=<yes|no>`.
3. After a reap with zero survivors, the sync is retried EXACTLY ONCE (fresh 180 s bound). Success → the leg proceeds to scripts (b)/(c) unchanged.
4. If the reap reports UNKILLABLE survivors (D-state — the MooseFS mount itself is wedged; gotchas read-wedge ladder says retry is futile), OR the retried sync fails again, raise `RunPodWorkloadStartError` exactly as today, with the reap evidence embedded in the message (`sync retry after reap failed` / `unkillable git survivors (moosefs D-state signature)`), pod left RUNNING for diagnosis (the RunPod-as-diagnosis-lane doctrine; #954 partial-handle contract untouched).
5. Unit tests in `tests/test_runpod_workload_exec.py` cover: (i) first-failure → reap → retry-success path (workload proceeds; ssh call sequence recorded = sync, reap, sync, launch, verify); (ii) reap-with-survivors → immediate raise, NO retry; (iii) retry-failure → raise with reap evidence; (iv) rendered reap script passes `bash -n` + never shells `task.py` (extend the existing render-script tests); (v) success path unchanged (existing tests stay green).

## 2. Method delta

Prior state: single sync attempt, local-only 180 s bound, conditional lock reap that is a no-op against a live hung git, no retry. Delta: remote-side self-bounding + one kill-and-reap + one bounded retry + evidence-bearing terminal. **Descope vs the filed body (stated deviation):** the body's "escalate to pod-swap on second failure" is NOT implemented — an in-leg pod swap would contradict the RunPod-as-diagnosis-lane doctrine and the #954 partial-handle billing-visibility contract (the pod deliberately stays RUNNING for diagnosis on terminal start-failure); second failure keeps the existing loud terminal, now carrying reap evidence so the human/watcher diagnosis starts informed. **Target correction vs the filed body:** `scripts/pod_lifecycle.py` (named in Provenance) is NOT the boot-sync owner and is untouched; the fix lives entirely in `backends/runpod.py` (clarifier finding, epm:clarify v1).
