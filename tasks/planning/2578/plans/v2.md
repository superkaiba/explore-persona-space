### 4-A. Resolver (new, near the constants block)

```python
def _validate_repo_id_shape(repo: str) -> str:
    """'org/name' shape gate: exactly one '/', both halves non-empty.

    Catches the operator hazard of passing an HF *prefix* where a repo id
    belongs; a well-shaped but nonexistent id still fails loud downstream
    (RepositoryNotFoundError -> ERROR row). Raises ValueError.
    """

def resolve_data_repos(issue_num: int, cli_repos: tuple[str, ...] = ()) -> list[dict[str, str]]:
    """Ordered, deduped, ADDITIVE data-repo search set: [{"repo", "source"}].

    Order: HF_DATA_REPO ("default") first — the singleton no-flag set is
    byte-identical to today's behavior — then EPM_<issue>_DATA_WRITE_REPO
    when set/non-empty ("env:EPM_<N>_DATA_WRITE_REPO"), then each comma-
    split --hf-data-repo value in given order ("flag"). Dedup by repo id,
    first source wins. The default is NEVER removed (union is additive by
    design: a repo enters the search only when a named source supplies it).
    Deliberately does NOT read EPM_HF_OVERFLOW_ROUTING (arming switch, not
    a repo id; ambient via .env; see plan #2578 §3).
    """
```

No hub import needed (repo ids are data). Pointer-discovered repos are appended later (4-C) with `source="pointer:<prefix>"`.

At entry: `data_repos = resolve_data_repos(issue_num, hf_data_repos)`; `report["hf_data_repos"] = data_repos`; `report["hf_model_repo"] = {"repo": hf_model_repo or HF_MODEL_REPO, "source": "flag" if hf_model_repo else "default"}`. Malformed flag repo id → `ValueError` surfaces at `main()` as `parser.error` (exit 2).
- `main()` gains `--hf-data-repo` (`action="append"`, `default=[]`, help names union semantics + comma-list) and `--hf-model-repo` (single).
- `check_outroot_residue(..., data_repos: tuple[str, ...] = (HF_DATA_REPO,))` — line 2856 call site passes the resolved ids. The returned row may carry `"discovered_data_repos": [{"repo", "source"}]`; `run_verification` extends `report["hf_data_repos"]` with it after check 9 returns and BEFORE check 10 runs, so pointer-discovered repos also feed the row-index enumeration.
- `_hf_prefix_basenames(hf_prefixes, data_repos)` → returns `(basenames, discovered, coverage)` where `coverage` maps repo id → files-found count (across the supplied prefixes). Per-(prefix × repo) scoped listings, same `EntryNotFoundError → continue` semantics per pair (a prefix absent on ALL repos contributes nothing — files read as residue, fail-toward-FAIL unchanged). The literal basename `OVERFLOW_POINTER.json` is EXCLUDED from the covered-name set (it is a routing record, not a run artifact).
- Row-index seams (all four are test seams; signatures gain the repo): `_row_index_resolve_revision(repo)` (per-repo pinned sha — doubles as up-front existence validation, `repo_info` inside `retry_transient` unchanged); `_row_index_hf_entries(hf_prefixes, data_repos, *, revisions)` — each prefix walks EVERY repo where it resolves; a prefix resolving on NO searched repo raises (current fail-loud behavior preserved); entry dicts gain `"repo"`; the `check_realized_row_counts` dedup key changes `(mode, path)` → `(mode, repo, path)` (singleton set ⇒ identical semantics); `_row_index_resolve_sizes(repo, paths, *, revision)` batched per repo; `_row_index_fetch(repo, path_in_repo, target, *, revision)`.
  - Cross-repo row-count semantics: a store split across repos (per-cell reroute mid-run) sums correctly under the union; a store *duplicated* on both repos dedupes at ROW grain whenever `--row-index-distinct-key` is declared (distinct-tuple counting collapses duplicates); in keyless mode the line count is already floor-only-WARN-never-OK, so duplication cannot mint an OK. Disclosed residual: keyless + duplicated store reads an inflated floor line count inside a WARN row — same verdict class as today.
- `--hf-dataset` branch (line 2834): walk `data_repos` in order via `check_hf_hub_path(repo, path, "dataset")`; first OK wins (URL already names the repo); no OK + any ERROR → ERROR (fail-loud dominates — presence in the erroring repo can't be ruled out); no OK + all MISSING → MISSING with a detail naming every repo searched.
- `--hf-model` branch (line 2819): `check_hf_hub_path(hf_model_repo or HF_MODEL_REPO, hf_model_path, "model")`. `check_hf_model_from_card(card, default_repo=...)`: line 928 becomes `repo = str(card.get("hf_model_repo") or default_repo)` with `default_repo = hf_model_repo or HF_MODEL_REPO` — card declarations keep winning (existing contract; #601 merge semantics untouched).
- `format_report`: after the `**Experiment type:**` line, add one line:
  `**HF repos searched:** data: <repo> (<source>)[ + <repo> (<source>)...]; model: <repo> (<source>)`.

```

        If repo == HF_DATA_REPO and "OVERFLOW_POINTER.json" in that prefix's
        basenames: stage_hub_file(HF_DATA_REPO, f"{prefix}/OVERFLOW_POINTER.json",
```

On by default; no flag to disable (it fires only when a pointer exists at a caller-supplied prefix on the canonical repo, and its failure mode is ERROR, not silent coverage).

### 4-D. Why this cannot go fail-open (the design constraint, addressed head-on)

The one mechanism that could convert this fix into a fail-open regression is the union making residue matching more permissive. Precisely: the residue verdict covers a disk file when its basename appears under a caller-supplied prefix in ANY searched repo — so a file that was never uploaded could be "covered" by a stale same-named file at the same prefix in another searched repo. Defenses, in order of load-bearing-ness:

1. **Every searched repo is named by a source that asserts the run wrote there**: the default (today's behavior), the run's own per-issue env declaration, an operator flag, or a pointer the write path itself committed. No repo is ever searched speculatively (this is why `EPM_HF_OVERFLOW_ROUTING` is not read and why there is no "always also search overflow" shortcut).
2. **The stale-same-name hazard is not new** — it exists today within the single canonical repo (a stale earlier-attempt file at the same prefix covers a lost file; the #2359 content check closes it for the *git* arm only). The union multiplies locations by the caller-named set; it does not create the class. Stated as a residual in §7, with the per-repo coverage counts (4-B) as the audit surface.
3. **Unknown/typo'd repo id fails loud, never silently-empty**: shape validation at parse time (`parser.error`, exit 2); a well-shaped nonexistent/private-without-token repo raises `RepositoryNotFoundError` at the scoped listing — VERIFIED on the pinned `huggingface_hub` 0.36.2: `issubclass(RepositoryNotFoundError, EntryNotFoundError) == False`, so the per-prefix `except EntryNotFoundError: continue` does NOT swallow it; it propagates to the existing catch-all at the residue call site → ERROR row → verdict FAIL. (This is the CLAUDE.md absence-check rule in action: the scoped `list_repo_tree` path 404s/raises on a wrong location; there is no client-side-filter path anywhere in this design.)
4. **A file present in NO searched repo is residue → FAIL** — unchanged code path, newly pinned by a dedicated multi-repo regression test (§6 T6).
5. **Pointer lane is fail-loud end-to-end**: fetch failure, unparseable JSON, or a malformed `overflow_repo` value → ERROR (never "skip discovery and under-cover", which would only be fail-closed anyway, and never "cover without listing").
6. **Verdict lattice, exit codes, and the `outroot=`/`rows=` terminate-guard note tokens are untouched.** The gate's consumers (`pod.py terminate` guard, upload-verifier Step 5 note template) key on the marker note, which this change does not emit.

Smoke blind-spot enumeration: none — smoke executes every production gate (this change has no smoke-conditional branches; tests fake only the external HF network boundary via `create_autospec`, per the existing `test_verify_uploads_outroot_residue.py` convention, and the acceptance-(b) run exercises the real Hub end-to-end).

Embedded-shell exit-path note: the acceptance-(b) recipe (§5) runs each verifier invocation as its own foreground command with `--json --no-fail` and asserts on the parsed JSON — no `&&`-chained failure arms, no pipes around the gate (the gotchas.md redirect-form rule: output to a file, then read).
