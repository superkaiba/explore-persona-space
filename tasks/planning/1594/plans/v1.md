### 4.1 Requirement + acceptance criteria

The changed rule must guarantee: **on a SAME-POD crash-fix relaunch where the checkout lives on a MooseFS-backed mount (the RunPod `/workspace` lane), dispatch is permitted only after the bytes actually served by the filesystem for every fix-touched path equal the blob content recorded at the pod's verified HEAD** — with a bounded fresh-read retry on mismatch, a loud typed failure on persistent mismatch, and an explicit exemption (with rationale) for fresh-provision lanes. ### 4.2 Method delta (vs current rule text)

Current duty 1 = HEAD-verification + ancestry probe (git-level only). Delta: duty 1's SAME-POD branch gains a third verification layer — a per-file **served-bytes comparison** (`git hash-object` of the working-tree file vs the blob OID at HEAD) — plus an on-mismatch ladder (re-materialize → re-probe once → typed infra failure + pod swap). The probe command pair was verified locally this session: `git hash-object -- scripts/task.py` == `git rev-parse HEAD:scripts/task.py` (both `6344f0f6…`), and `git cat-file blob HEAD:scripts/task.py | sha256sum` == `sha256sum scripts/task.py` (both `c3a0a5a0…`) — the `hash-object`/`rev-parse` pair is chosen because it runs pod-side in ONE call with no cross-machine hash exchange, and `git hash-object` always reads the full file content (unlike `git status`/`git diff`, which can report clean from index stat data without reading the bytes).

### 4.5 Scope discipline (trigger condition)

The duty binds to: **SAME-POD crash-fix relaunches where the repo checkout lives on a MooseFS-backed mount** (`/workspace`, the RunPod lane) — i.e., exactly where duty 1's SAME-POD branch already executes, and only there. Why each other lane is exempt: GCE fresh provision clones `origin/issue-<N>` at boot onto a local boot disk (no FUSE, no prior copy); fresh RunPod provision bootstrap-clones into a fresh volume (the clone CREATES the files — no pre-update version exists on that mount to be cached); SLURM rsyncs to local scratch. The stale-serve hazard exists only when a file is updated IN PLACE on a FUSE mount that previously served an older version. Cost when it fires: one SSH command (~seconds) per relaunch — negligible against the ~15 min + crash cycle it prevents.

## 11. Decision Rationale

Why: one SSH call, no cross-machine hash exchange, immune to git's index stat-cache short-circuit; the `.git` object store is write-once content-addressed, so FUSE staleness cannot corrupt the reference side (an unfetched object fails loud). Source: verified locally this session (§4.2). - **Compare against `HEAD:<path>`, not `<fix-sha>:<path>`.** A post-fix commit may legitimately touch the file again; HEAD passed the ancestry probe, so HEAD's blob is the correct expectation. Source: git semantics + duty-1 ordering.
- **Placement inside duty 1 (not a new duty 3).** Keeps every "duties 1–2" / "enforces BOTH" pointer (SKILL.md ×2, experimenter.md) accurate with zero renumbering. Source: §4.3 enumeration.
- **Gotchas entry after EXDEV.** Preserves the existing entries' sibling-count prose byte-for-byte. Source: gotchas.md read (§2).
