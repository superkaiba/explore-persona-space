### 4. Design

#### 4.0 The design fork — adjudicated: option (i), thread the EXISTING `lane_suffix` (with `--name-suffix` as an alias)

**Decision: (i).** The RunPod pod name is minted from the SAME `lane_suffix` key that already names the GCP instance (`eps-issue-<N>-<suffix>`, #934), the SLURM job + scratch dir (#2055), the attempt id (`router._make_attempt_id`, :7621), and the handle sidecar (`issue-<N>-<suffix>-handle.json`). `--name-suffix` is added as an argparse alias of `--lane-suffix` (same `dest="lane_suffix"`, same validator), so the body's literal wording — and the exact command the #1491 round typed — works.

**Reason:** one key across pod name + sidecar is what makes the collision class structurally impossible. Option (ii) — an independent `--name-suffix` — reintroduces it by construction: a launch passing only `--name-suffix q32b` would provision `pod-<N>-q32b` while writing the UNSUFFIXED `issue-<N>-handle.json`, so a second such launch silently overwrites the first's sidecar (the exact hazard #934 exists to remove). Under (i) that divergence cannot be expressed: the alias maps to the same dest, so pod name and sidecar always derive from one value. The losing option's hazard is thereby neutralized by construction, not by discipline. (The one-key property is also what makes §4.4.2's remedy (A) possible at all: the watcher can DERIVE the sidecar suffix from the pod name it already holds, because they share one source value.)

**Cost of (i), stated:** the pod-name suffix grammar is TIGHTER than the lane-suffix grammar — `pod_lifecycle.py:2752` enforces `[a-z][a-z0-9-]{0,19}` (letter-initial, ≤20 chars) vs `base.validate_lane_suffix`'s `[a-z0-9]([a-z0-9-]*[a-z0-9])?` ≤43. Letter-initial is LOAD-BEARING, not incidental: a digit-initial slug leaves the pod **managed-recognized but issue-unattributable** — `_is_managed_pod_name` (pod_lifecycle.py:377-386) is prefix-only and still matches, but `_POD_NAME_RE` (:407, slug `[a-z][a-z0-9-]*`) fails to parse it, so `_issue_from_pod_name` returns None and every ATTRIBUTION-dependent consumer fails: the watcher pod-safety pass cannot map the pod to its task, the #1961 per-pod shield cannot bind, `audit-stale` and the $/hr burn breakdown cannot attribute it. So a lane suffix that cannot be a pod slug must be REFUSED, loudly, before any money moves. Handling in §4.1 (pre-route guard). A second cost — a provision-subprocess grammar SystemExit would be wrapped by `router._runpod_terminal_rung` into `NoComputeAvailableError` (the "provision exit 1 → NoComputeAvailableError" wrapping, router.py comment at the #940 block) and thereby MISCLASSIFIED as a re-drivable capacity miss (the watcher's capacity-retry would re-drive the same bad suffix forever) — is exactly why the guard sits at the dispatch CLI, pre-route, not in the subprocess's lap.
