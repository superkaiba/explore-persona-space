### 4.1 Regex edit — `scripts/audit_clean_results_body_discipline.py` (L109-111)

```python
# OLD (L109-111):
        r"(?:[\w%/<>=≤≥−+-]+(?:\.\d+)*[ \t]+){0,3}?"  # noqa: RUF001
        r"(?:verdicts?|lattices?|margins?|reads?|criteri(?:on|a)|thresholds?|bands?"
        r"|gates?|rules?|endpoints?|contrasts?|floors?|companions?|hypothes[ei]s|alpha)\b",

# NEW:
        r"(?:[\w%/<>=≤≥−+-]+(?:[.\-−]\d+)*[ \t]+){0,3}?"  # noqa: RUF001
        r"(?:verdicts?|lattices?|margins?|reads?|criteri(?:on|a)|thresholds?|bands?"
        r"|gates?|rules?|endpoints?|contrasts?|floors?|companions?|hypothes[ei]s|alpha"
        r"|cuts?|paths?|clauses?|controls?|levers?|bars?|smokes?)\b",
```

Notes on the token-class group, all verified by executed probe this session: `-` and `−` (U+2212) are ALREADY in the leading char class, but once matching enters `(?:\.\d+)*` it cannot return to the leading class — so `0.60-0.85` dies at the second separator; `[.\-−]` in the group is what makes `.60`, `-0`, `.85` each consumable, covering ASCII-hyphen AND U+2212 ranges. Digits-only after the separator (`\d+`) preserves the no-sentence-bridge property (a sentence period is never followed by a digit-run token in the escape class; the `[ \t]+`-only separator still blocks newlines). The `# noqa: RUF001` stays accurate: no NEW Unicode chars — the group's `−` is the same U+2212 the comment at L103-104 already documents.

import importlib.util, re, subprocess, tempfile
from pathlib import Path

def load_pattern(src_text: str, name: str) -> str:
    with tempfile.NamedTemporaryFile("w", suffix=".py", delete=False) as f:
        f.write(src_text); p = f.name
    spec = importlib.util.spec_from_file_location(name, p)
    mod = importlib.util.module_from_spec(spec); spec.loader.exec_module(mod)
    return mod.PATTERNS["pre_reg"][0]                      # module import is side-effect-free (tests import it)

old_src = subprocess.run(                                  # pre-edit pattern from git, not a transcription
    ["git", "show", "HEAD:scripts/audit_clean_results_body_discipline.py"],
    capture_output=True, text=True, check=True).stdout     # run BEFORE committing; else pin the pre-edit SHA
new_src = Path("scripts/audit_clean_results_body_discipline.py").read_text()
OLD = re.compile(load_pattern(old_src, "audit_old"), re.IGNORECASE)
NEW = re.compile(load_pattern(new_src, "audit_new"), re.IGNORECASE)   # the LIVE edited pattern (#779 discipline)

corpus = sorted(p for st in ("completed", "awaiting_promotion", "archived", "on_hold")
                for p in Path("tasks").glob(f"{st}/*/body.md"))
new_hits = []
for body in corpus:
    text = body.read_text(errors="replace")
    old_starts = {m.start() for m in OLD.finditer(text)}
    for m in NEW.finditer(text):
        if m.start() not in old_starts:
            a, b = max(0, m.start() - 70), min(len(text), m.end() + 50)
            new_hits.append((str(body), m.group(0), text[a:b].replace("\n", "\\n")))
print(f"bodies={len(corpus)}  new_only_hits={len(new_hits)}")
for loc, g, ctx in new_hits:
    print(f"{loc} :: {g!r} :: ...{ctx}...")

## 11. Decision Rationale (per changed regex element)

1. **Token class `(?:\.\d+)*` → `(?:[.\-−]\d+)*`** — What: allow `.`, `-`, U+2212 each followed by digits as repeatable token continuations. Why: `0.60-0.85` is unreachable under the old group (traced: leading class stops at the first `.`; the group consumes `.60` and cannot consume `-0`); the widened group consumes `.60`/`-0`/`.85`. `−` in the group is load-bearing for U+2212 ranges (the leading class's `−` is unreachable post-group); digits-only continuation preserves sentence-boundary safety. Source: task-body diff sketch + executed probe battery this session (all 18 cases OK) + corpus measurement (0 real-corpus new hits from the widening alone). Alternatives rejected: `(?:\.[\w...]+)*` (broader, would consume malformed `word.Word` seams — looser than needed); two-token consumption (impossible — no whitespace inside the range).
2. **Alternation += `cuts?|paths?|clauses?|controls?|levers?|bars?|smokes?`** — What: 7 new head nouns. Why: the #1090 round-6 escape vocabulary (verdict-lattice factory jargon). Source: the corpus measurement (this plan §2): bar/bars 5 genuine hits, clause 4, control(s) 5, path 2, cut/lever/smoke 0 — total 16 new hits, 0 benign verb-use FPs across 1,410 bodies; plus the 8 recorded incident strings all firing. `smokes?` kept at zero attestation because the Goal names it and its measured FP cost is zero. Alternatives: dropping zero-attestation nouns (rejected — incident-mandated, zero cost); adding 'test'/'interval' (rejected — #1419's sanctioned CI-definition register, pinned by test L1145).
3. **Everything else unchanged** (preposition guard, `{0,3}?` bound, branch structure, IGNORECASE, scope restriction) — Why: #1419 measured these; single-variable discipline. Source: `9ef47afcfc` comment block L75-104.
