New pure helper next to `_spend_approval_park_reason` (~L8300):

```python
def _deliberate_blocked_park_reason(events: list[dict]) -> str | None:
    """Reason string when the newest ``epm:status-changed`` is corroborated by
    the halt-contract trail — an ``epm:failure`` marker within
    [_BLOCKED_PARK_FAILURE_WINDOW_S before, _BLOCKED_PARK_FAILURE_SLACK_AFTER_S
    after] it — i.e. the block is a deliberate park (post epm:failure, set
    status blocked, exit: the CLAUDE.md halt contract), not an unexplained
    freeze. Pure over the already-loaded ``events``; the CALLER gates on
    ``task_status == "blocked"`` (only there is the newest status-changed the
    transition into blocked). Fail direction: unparseable ts / no trail ->
    ``None`` (the one-time alert still fires)."""
    sc_ts = None
    for ev in events:
        if ev.get("kind") == "epm:status-changed":
            ts = _parse_event_ts(ev.get("ts"))
            if ts is not None and (sc_ts is None or ts > sc_ts):
                sc_ts = ts
    if sc_ts is None:
        return None
    for ev in events:
        if ev.get("kind") != "epm:failure":
            continue
        ts = _parse_event_ts(ev.get("ts"))
        if ts is None:
            continue
        if sc_ts - _BLOCKED_PARK_FAILURE_WINDOW_S <= ts <= sc_ts + _BLOCKED_PARK_FAILURE_SLACK_AFTER_S:
            return (
                "deliberately parked at status=blocked (halt-contract trail: "
                "epm:failure within the park window of the newest "
                "epm:status-changed); the gate-push pass already notified the "
                "blocked transition"
            )
    return None
```

## 9. §11 Decision Rationale

1. **Dedup site = `_handle_stalled_alert`, keyed on `ctx.alerted`.** *What:* skip the marker post when the episode already alerted; keep refresh-heal, stderr, sidecar, persist. *Why:* producer enumeration shows `alerted=True` reaches the handler ONLY via the #759 downgrade lane — the exact leak; the site closes it for all current and future callers in one place. *Source:* #1092 watcher log 2026-07-07 L10809-11315 + events markers 20:43/21:03/21:23Z; `decide_session_stalled` L1552-1565 (#506 dedup-vs-escalation contract). *Alternatives rejected:* dedup inside `decide_session_stalled` (changes the pure function's contract; risks the #506 regression class); skipping the K-corroboration when `alerted=True` (changes downgrade cadence → respawn timing, forbidden); caller-side skip in `_process_stalled_session` (equivalent but splits alert logic across two sites and would bypass the #488 refresh-heal).
2. **`live_consecutive` reset left untouched, documented.** *What:* criterion-7 reset stands even when the escalated respawn is deferred by the wt hold. *Why:* preserving the count across a deferral would make the first post-hold tick respawn immediately — a respawn-timing change the constraints forbid; the observable harm (repeat markers) is fully fixed by item 1. *Source:* sidecar rows 13:43-14:23 PT (downgrade/escalation alternation) + `HOLD-RESPAWN 1/6, 2/6` log lines; `_apply_stalled_live_corroboration` docstring criteria 7/12.
3. **Blocked-park predicate = `epm:failure` within [−3600s, +300s] of the newest `epm:status-changed`, caller-gated on `status == "blocked"`, fail-open to alerting.** *Why:* the halt contract (CLAUDE.md § halt-criterion) posts failure-then-block, observed 1s apart on #1092; 3600s absorbs slow orchestrator paths; +300s slack tolerates order inversion; fail-open keeps the alert for hand-moved/unexplained blocks (the brief's "genuinely marker-silent" constraint). *Source:* #1092 events 13:21:34Z/13:21:35Z; gate-push pass already pushes the blocked transition (background-automation.md § Gate-push pass) and reconcile/zombie reapers deliberately never touch blocked sessions — the alert adds no actionable signal on the trail case. *Alternatives rejected:* suppress unconditionally at blocked (loses the unexplained-freeze alert); keep the one-time alert (it IS the observed noise — one episode = one noise event that prompted a user query); an env knob for the window (not operationally tunable; plain constants + comment, minimal diff).
4. **No marker post from the blocked-park arm (print-only).** *Why:* the USER-PAUSE/spend arms post notes because they carry a user next-step; here the `epm:failure` marker + gate-push push already carry it — another events row would be new noise of the same class. *Source:* #1137 task body ("Alert noise trains the reader to ignore the channel").
