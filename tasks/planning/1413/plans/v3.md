## 3. Design

### 3.1 Mechanism choice

Constraint 5 offered two shapes: (a) quote-aware clause splitting for the ssh argument; (b) payload-opaque handling with separate payload classification. I choose a refinement of (a) — **predicate-gated separator masking before the split** — because it is the smallest change: the splitter, driver loop, waiver, and every classifier stay byte-identical; one new function + one call site. Option (b) (classify the payload separately) would duplicate `classify_clause` semantics against remote-context text and re-litigate which detectors apply remotely; rejected as larger and less provable.

The critical safety property, stated once and enforced by construction. Note the quantifier: it ranges over the WHOLE driver loop — the per-clause ladder AND the cross-clause latch state machine (`scoped`, `wt_bound`) — not `classify_clause` alone (the v1/v2 statement quantified only over classification; the Phase-2 critics falsified that narrower claim with latch-state traces, so v3 extends it):

> **Monotonicity invariant (extended to the full driver state machine).** `mask_ssh_payload_separators` either (i) returns its input BYTE-IDENTICAL, or (ii) rewrites only characters in `{;, &, |, \n}` inside a balanced single-quoted span whose enclosing prospective clause satisfies EVERY refusal arm R1-R8. In case (ii), the resulting single merged clause:
> (a) **is waived by the EXISTING ladder before `classify_clause`** — R1-R4 are a verified superset of ladder conditions (2)/(3)/(3b)/(4) restricted to the clause, masking cannot create refusal-pattern text or repo-path spellings (the replacement token is space-padded word characters), and the `^ssh` head is preserved;
> (b) **cannot ARM the cd-scope latch** — R6 refuses any candidate containing latch-arming vocabulary (`cd` + `/tmp/` or `.claude/worktrees/`, a conservative substring superset of the L998-999 greps), which also precludes the regex-WIDENING variant where masking lets `cd +[^;&|]*\.claude/worktrees/` span across former statement boundaries (the `[^;&|]*` gap matches masked text);
> (c) **cannot ride an armed latch or suppress a load-bearing latch RESET** — R7 refuses any candidate whose PREFIX contains latch-arming vocabulary; since `scoped` can only be armed by a prior clause containing `cd` text plus a `/tmp/`/`.claude/worktrees/` literal (the cd-latch) or `cd "$WT"` with a same-command `WT=…worktrees…` assignment (both leave `cd` + a latch-path literal in the prefix), R7 guarantees `scoped == 0` at candidate entry, so the mask's deletion of intra-payload separators (which today reset `scoped`) changes no disposition;
> (d) **cannot arm, disarm, or suppress-the-disarm-of the WT latch** — the merged clause starts `ssh`, so the `^WT=`-anchored checks never match it; R8 refuses any candidate containing `WT=` text, so the per-fragment arm/disarm effects a mis-split produces TODAY are preserved byte-identically rather than suppressed;
> (e) **cannot mask characters outside a genuinely bash-single-quoted span** — R5 refuses any candidate preceded by an un-consumed quote char (`'` or `"`), so the scanner's opener/closer pair is bash's own quote pair and the masked span is remote DATA, never live local code.
> Therefore the post-change block set differs from today's ONLY by removing commands of exactly the intended class; every clause that still reaches `classify_clause` — and every latch transition the driver takes — is identical to today.

The dangerous alternative — masking unconditionally and letting the ladder refuse afterward — is explicitly rejected: a refused-but-masked clause would be classified as MERGED text, where an allow-arm token from one remote statement (e.g. `switch main`, `restore --staged`) could swallow a block from another (cross-statement allow-arm contamination), flipping today's blocks to allows in pipeline/redirect positions. Constraint 2 names those positions as must-preserve. Gating masking on the full predicate makes every refused case byte-identical to today. The same contamination mechanism is why the §3.4 must-block fixtures for ladder-overlapping arms use allow-arm-anchored payloads: under a single-arm under-refusal bug the merged clause reaches `classify_clause`, and only a payload whose block detector is neutralized by a sibling statement's allow-arm (the `switch main` end-anchor, L683-689) distinguishes "mask refused → byte-identical" from "ladder refused → merged text still blocked" (a destructive-only payload like `reset --hard` stays blocked across masked text — L776's `[^;&|]*` spans it — so it cannot detect the bug).

**Fail-open awareness (design stance for every arm):** the guard's raw-scan philosophy is fail-closed when scanning to BLOCK; this pass uses raw-scan output to GRANT, so every scanner imprecision errs fail-open. Accordingly every predicate arm is biased toward refusal — conservative substring supersets (R6/R7), blanket charsets (R2), any-quote-refuses (R5) — and §8 permits only MORE-conservative tuning without re-plan.

### 3.3 Pseudocode

```awk
# BEGIN: slurp all records; END: s = lines joined with "\n"
i = 1; atstart = 1; out = ""; saw_quote = 0
while (i <= n) {
  if (atstart && substr(s,i,4) ~ /^ssh[ \t]/) {
    j = i + 4                                     # scan the head (host/options)
    while (j <= n && substr(s,j,1) ~ HEADCHARS) j++   # [A-Za-z0-9_.@:%=/+,-] + space/tab
    if (substr(s,j,1) == "'") {
      cq = index(substr(s, j+1), "'")             # single quotes: '[^']*' is EXACT
      if (cq > 0) {
        payload = substr(s, j+1, cq-1); k = j+1+cq   # k = first char after closing quote
        t = k; while (t <= n && substr(s,t,1) ~ /[ \t]/) t++   # tail: whitespace only
        tail_ok = (t > n) || substr(s,t,1) == ";" || substr(s,t,1) == "\n" \
                  || substr(s,t,2) == "&&" || substr(s,t,2) == "||"   # R1: never bare | or &
        cand = substr(s, i, k-i)                  # head + 'payload'
        pfx  = substr(s, 1, i-1)                  # everything before the candidate
        if (tail_ok \
            && saw_quote == 0 \
            && cand !~ /\$\(|\$\{|`|<|>|\x01/ \
            && tolower(cand) !~ /proxycommand|localcommand|knownhostscommand/ \
            && index(cand, repo) == 0 \
            && index(cand, "$HOME/" repo_base) == 0 \
            && index(cand, "~/" repo_base) == 0 \
            && !(cand ~ /cd[ \t]/ && (index(cand, "/tmp/") > 0 || index(cand, ".claude/worktrees/") > 0)) \
            && !(pfx  ~ /cd[ \t]/ && (index(pfx,  "/tmp/") > 0 || index(pfx,  ".claude/worktrees/") > 0)) \
            && index(cand, "WT=") == 0) {
          # arms in order: R1 tail | R5 prefix quote-state | R2 token set | R3 local-exec
          # options | R4 repo-path spellings | R6 candidate latch vocab | R7 prefix latch
          # vocab | R8 WT-latch isolation
          gsub(/[;&|\n]+/, " __EPM_SSH_SEP__ ", payload)   # the ONLY rewrite
          out = out substr(s, i, j-i) "'" payload "'"
          i = k; atstart = 0; continue            # ACCEPTED: the two consumed quotes do
                                                  # NOT set saw_quote (balanced span,
                                                  # bash's own quote pair by R5)
        }
      }
    }
    out = out "ssh"; i += 3; atstart = 0; continue   # REFUSED: copy verbatim (its quotes
                                                     # flow through the char path below and
                                                     # set saw_quote — later candidates refuse)
  }
  c = substr(s,i,1); out = out c
  if (c == "'" || c == "\"") saw_quote = 1        # R5 tracking: any quote outside
                                                  # accepted-candidate spans
  if (c ~ /[;|&\n]/) atstart = 1; else if (c !~ /[ \t]/) atstart = 0
  i++
}
printf "%s", out
```

Load-bearing details:

- **Clause-initial tracking** mirrors the splitter's raw separator semantics exactly (`;`, `|`, `&`, newline set `atstart`; `&&`/`||` are covered because their first char sets it). Whitespace preserves `atstart`. A `#`-comment clause may be scanned as a candidate — harmless: masked-or-not, the driver skips comment clauses; unmasked comments are byte-identical.
- **HEADCHARS** excludes every quote, `$`, backslash, redirect, paren, bracket, and separator char — so `ssh -p 40052 root@1.2.3.4`, `-o StrictHostKeyChecking=no`, `-i /path/key` heads parse; `ssh $(evil)`, `ssh "h"`, `ssh [::1]`, `ssh h <<'EOF'` never do (refused → byte-identical → today's behavior). `-o ProxyCommand=evil` PASSES the charset but is refused by the explicit token check (R3).
- **R1 — tail = whitespace-only up to `;` / `&&` / `||` / newline / EOS.** Bare `|` or `&` (PIPE/BG — condition (2)'s refusal set) refuse the mask, as does ANY non-space token after the closing quote (`2>/dev/null`, `2>&1`, `<<< input`, `-v`, a second quoted arg) — each falls back to byte-identical input, i.e. exactly today's disposition (S13/S14 `2>/dev/null` shapes stay allowed via the existing single-statement waiver; N17/N22/N23 stay blocked).
- **R2-R4 — candidate refusals** (`>`,`<`, backtick, `$(`, `${`, `\x01`, local-exec option tokens, repo-path spellings) are a strict SUPERSET of the ladder's conditions (3)/(3b)/(4) restricted to the clause — plus blanket `<` (covers `<(`, `<<<`, `<<`, and plain input redirects: strictly more conservative) and `\x01` (splitter-sentinel hygiene). Bare `$VAR` (no brace/paren) is allowed in the payload — parity with the ladder, which explicitly does not refuse it (S10 pins this).
- **R5 — prefix quote-state refusal (new in v3; closes the pre-opened-quote local-code-swallow hole).** The scanner is quote-context-blind outside candidates; a quote opened BEFORE the ssh word can make the scanner's "payload" span live LOCAL code (the first string's closing quote read as the payload opener, a later string's opening quote as the closer — the masked span is then the local code between two strings, and a today-blocked local gated clause would be swallowed into a waived `^ssh` clause). R5 refuses any candidate when ANY `'` or `"` was seen in the prefix outside previously-ACCEPTED candidate spans — the strict variant (chosen over raw-`'`-parity because parity misses the double-quote variant: an apostrophe-balanced prefix with a pre-opened `"` also swallows local code, NM26). Fail-closed cost: any quoted text before the candidate (e.g. `echo 'hi' && ssh pod '<compound>'`) refuses → byte-identical → today's disposition (documented residual). **Quote-state resume is consistent past consumed quotes:** an ACCEPTED candidate consumes its two quotes inside the acceptance (they never set `saw_quote` — by R5 they are bash's own balanced pair); a REFUSED candidate's chars re-flow through the char path, so its quotes set `saw_quote` and every later candidate in the command refuses (conservative composition). Multi-candidate commands (`ssh h1 '…' && ssh h2 '…'`) therefore still compose: candidate 2's prefix contains only candidate 1's CONSUMED quotes → `saw_quote` still 0 → masks.
- **R6 — candidate latch-vocabulary refusal (new in v3; closes the payload-arms-the-local-latch hole).** The driver's cd-scope latch greps (~L995-1002) are UNANCHORED and run BEFORE the waiver with their own `scoped=1; continue` — a masked clause containing `cd /tmp/…` (or worktrees) text would match them, arm `scoped`, skip the waiver entirely, and carry the latch across an `&&` tail into a fully LOCAL gated clause (today the payload's internal non-`&&` separator resets `scoped` at the fragment boundary and the local tail blocks; post-mask the reset is gone — a today-blocked local destructive op would flip to allowed, NM22). Masking also WIDENS the worktrees grep: `cd +[^;&|]*\.claude/worktrees/` is separator-guarded, and the mask removes exactly the `[;&|]` chars, so `cd X` and a `worktrees/` path in DIFFERENT payload statements co-match post-mask (NM23). R6 refuses any candidate matching `cd[ \t]` AND containing `/tmp/` or `.claude/worktrees/` — a conservative substring superset of both L998-999 regexes (over-matching is fail-closed; the check covers head+payload since HEADCHARS admits `/`). The incident shape's `cd /workspace/…` carries neither latch path → still masks.
- **R7 — prefix latch-vocabulary refusal (new in v3; guarantees `scoped == 0` at candidate entry).** If a PRIOR clause genuinely armed `scoped` (`cd /tmp/x && ssh pod '<multi-stmt>' && <gated>`), today the payload's internal non-`&&` separator resets the latch and the local `&&` tail classifies (blocks); post-mask the reset would be suppressed and the tail skipped — a disposition flip (NM24). That flip is actually semantically CORRECT (bash's local `&&` chain is unbroken, so the gated tail truly runs in the scoped cwd — today's block is itself a mis-split FP), but allowing it would breach the exactly-one-flip criterion and complicate the invariant for zero safety gain — so R7 refuses when the prefix matches `cd[ \t]` AND contains `/tmp/` or `.claude/worktrees/`. Soundness: `scoped` can ONLY be armed by the cd-latch (needs `cd` + a latch-path literal in the clause text) or the `cd "$WT"` latch (needs a same-command `WT=…worktrees…` assignment — the path literal — plus `cd `), so an armed-`scoped` entry state implies both tokens in the prefix. The prefix includes refused candidates' text and accepted candidates' payloads; accepted payloads are R6-clean, and any spurious conjunction (e.g. `cd` from one accepted payload + `/tmp/` from an unrelated `ls /tmp/y`) merely over-refuses — fail-closed.

## 10. (§11) Decision Rationale

N/A — no model training

- **Predicate-gated pre-split masking (vs quote-aware splitter / payload-opaque classifier / clause-spanning latch).** *Why:* smallest closure of the false-positive class with a provable monotonicity invariant; driver loop untouched. *Source:* the guard's own design invariants — "NO LATCH … no state crosses clauses" (L1163-1171), the raw-scan trade-off (L633-634, L73-80), the fail-closed ladder structure (L1079-1164) — and incident #779 / residual (xiv) (L237-250).
- **Single-quoted payloads only.** *Why:* `'[^']*'` is an exact bash parse (no escapes/nesting/local expansion); double quotes admit all three, so they stay a fail-closed residual. *Source:* bash single-quote semantics; ladder condition (3)'s deliberate no-quote-shell-parse stance (L1107-1115, the #796 revert note); existing S2 pins the single-statement double-quoted allow, NM1 pins the multi-statement double-quoted block.
- **Mask fires only when the FULL predicate passes (vs mask-then-let-ladder-refuse).** *Why:* a refused-but-masked clause is classified as merged text, where cross-statement allow-arm tokens could flip today's blocks to allows in pipe/BG/redirect positions — violating constraint 2. *Source:* the switch allow-arm anchor analysis (L668-690) + waiver conditions (2)/(3b) rationale (L1089-1148).
- **Tail must be whitespace-only to `;`/`&&`/`||`/NL/EOS (R1).** *Why:* guarantees nextsep ∉ {PIPE, BG} without re-deriving the splitter's fd-dup mis-split quirks (`2>&1` → BG, L1093-1098), and keeps trailing-redirect shapes (`2>/dev/null`, S13/S14) on today's exact path. *Source:* waiver condition (2) (L1089-1104) + splitter sed pre-pass (L647).
- **Blanket `<`/`>` candidate refusal (R2, superset of ladder (3)/(3b)).** *Why:* strictly fail-closed — cheaper to prove than replicating the `/dev/null` strip-then-scan, at the cost of keeping remote-redirect payloads a residual FP (already documented, N29 pins it). *Source:* ladder (3b) (L1122-1148); constraint 1's redirect preservation.
- **Repo-path refusal replicates cond (4)'s three covered spellings exactly (R4).** *Why:* the never-waived class must stay never-waived; non-canonical spellings remain the same deliberate fail-open as today (gap (xiv), L1157-1161). *Source:* L1149-1161 + N5/N20/N21 pins.
- **Prefix quote-state refusal, strict any-quote variant (R5) — NEW in v3.** *Why:* the scanner is quote-context-blind and this pass GRANTS on its output, so a quote opened before the candidate can make the "payload" live local code (the swallow hole); the strict variant is chosen over raw-`'`-parity because a pre-opened DOUBLE quote with balanced apostrophes defeats parity (NM26) while strict refuses both; accepted-candidate quotes are excluded from the flag so multi-candidate composition survives. *Source:* Phase-2 Methodology critique Must-Fix 2 (2026-07-16) + the quote-blind trade-off comment (L633-634); cost residual documented in §3.2 item 3.
