# Plan v1 — #1975 daily-fix: map fit-space parity assert (issue1739 natpv)

## Goal / Requirement

Add an input-space parity check to the #1739 map-projection path: record the
fit-space (whitened/raw, with a whitening-params fingerprint + train-input norm
stats) in the persisted map payload, and assert it against the inputs at
apply/load time, so a whitened-fit map can never silently score raw activations
again (the #1739 incident: sycophancy headline 0.577 quoted+committed, corrected
to 0.486 ~21 h later).

**Acceptance criteria:**
1. New map payloads written by `scripts/issue1739_fits.py::_save_map` carry
   machine-checkable `fit_space` metadata (space tag + whitening fingerprint +
   train-input norm stats), for BOTH the linear `.npz` and nonlinear `.pt` forms.
2. A shared assert helper exists in
   `src/explore_persona_space/experiments/issue_1739/fits.py` that (a) RAISES on
   an undeclared input-space mismatch (norm-band check — the durable form of the
   `issue1739_map963k_applycheck.py` OOD signal), (b) allows an EXPLICIT
   declared mismatch (loud log naming the reason — the natpv `--space raw`
   disclosed provisional read), (c) on a LEGACY payload without `fit_space`
   emits a loud warning naming the #1739 incident (never silently assumes raw,
   never crashes existing healthy consumers).
3. Every persisted-payload consumer calls the helper (or the fingerprint check)
   before applying the map: `scripts/issue1739_map963k_readout.py` (the incident
   site, ~L465-475), `scripts/issue1739_natpv.py` (`_map_projectors` +
   the whitened map fold), with the natpv raw path passing an explicit
   declared-mismatch reason.
4. Unit tests pin the raise / warn / declared-mismatch / legacy behaviors and
   the writer round-trip.
5. Committed whitened main-grid values and the corrected 0.486 headline are
   UNCHANGED — this is a guard, not a re-fit. No numeric output of any existing
   pipeline changes on well-matched inputs.

## Method delta (vs current state)

Current state (verified 2026-08-03): the payload meta carries only a PROSE
`apply` string mentioning "(whitened space)"; nothing is machine-checked at
apply time; `issue1739_map963k_applycheck.py` computes the norm-based OOD signal
but is a one-off diagnostic. This plan makes the disclosure machine-readable and
the diagnostic a hard gate at the consumer seam.

## File paths + concrete diffs

1. **`src/explore_persona_space/experiments/issue_1739/fits.py`** (shared
   module both script sides already import) — ADDITIVE, appended near the
   existing `Whitening` / map helpers:
   - `def whitening_fingerprint(wh: Whitening) -> str`: sha256 over the raw
     bytes of `(mu, w, gamma)` in a fixed dtype/order (document: computed once
     per variant at persist/load; ~seconds on the (28,d,d) tensor — fine).
   - `def map_space_meta(x_fit: np.ndarray, *, fit_space: str, whitening: Whitening | None) -> dict`:
     returns `{"fit_space", "whitening_fingerprint" (None when raw),
     "train_input_norm_mean" (per-layer list, pre-standardization L2 row-norm
     mean of the FIT inputs), "train_input_norm_std"}`.
   - `def assert_map_input_space(meta: dict, x: np.ndarray, *, declared_mismatch: str | None = None, band: float = 2.0) -> None`:
     - `meta.get("fit_space")` absent → `logger.warning` naming the #1739
       incident + "re-persist to gain the check"; return (backward compat —
       live #1739 rounds consume existing HF payloads; refusing would break
       healthy runs. Deliberate choice per the body's "planner's call").
     - `declared_mismatch` provided → `logger.warning` with the verbatim
       reason; return.
     - else per-layer mean L2 norm of `x` must lie within `[mean/band,
       mean*band]` of `train_input_norm_mean` → on violation raise
       `ValueError` naming the #1739 incident, the payload's fit_space, the
       observed vs train norms, and the offending layers. Band default 2.0:
       whitened rows sit at ~sqrt(d)≈59.9 for d=3584 while raw Qwen-2.5-7B
       activation rows are several-fold larger (the applycheck
       `whitened_input_norm_mean >> sqrt(dim)` signal); the implementer
       sanity-checks the separation on a real payload's recorded stats before
       finalizing the default and documents the measured margin in the test.
2. **`scripts/issue1739_fits.py::_save_map`** — meta gains the
   `map_space_meta(...)` fields. Thread `x_w` (the whitened fit inputs, already
   at the `_fit_map` call sites) + the `Whitening` object into `_save_map` via
   new keyword-only args (default `None` → fields recorded as `None` +
   `fit_space` omitted, preserving byte-compat for any caller not yet
   threaded; the production call sites ARE threaded in this diff). Both the
   linear `.npz` and nonlinear `.pt` branches get the fields.
3. **`scripts/issue1739_map963k_readout.py`** (~L465-475, incident site) —

   The implementer FIRST verifies what space `z` is in on the corrected path:
