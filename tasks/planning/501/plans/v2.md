<section class="plan-tldr">
<h2>§0.0 TL;DR</h2>
<ul>
<li><span class="label">What I'll run.</span> I take the markers another experiment already trained on single-turn contexts, then I read the same "did the marker show up when the model answered?" measurement under a third kind of context: multi-turn conversations from a prior corpus (long drifting back-and-forths, plus matched neutral controls), with the trigger inserted in the last user turn. No new training. The question is whether the same geometry-predicts-leakage predictor that worked on single-turn contexts also tells me whether the marker survives a multi-turn history. If yes, the earlier finding that "every multi-turn history silences the marker" becomes one more point on the same distance-vs-transfer line rather than a separate phenomenon.</li>
<li><span class="label">What I expect.</span> Multi-turn-history contexts sit FAR from any single-turn context in base-model representational distance (most of the residual gets occupied by the prior conversation, not by the question), and that distance predicts the near-zero on-policy marker emission the prior corpus result documented. The silencing becomes a single point on the same predictor curve as the single-turn arms.</li>
<li><span class="label">What would change my mind.</span> One: if multi-turn contexts cluster CLOSE to single-turn contexts in the residual, then "long history" isn't a representational displacement and the silencing is some other axis. Two: if multi-turn contexts sit far but distance does NOT predict on-policy transfer to them, the predictor stops working when crossing the single-turn-to-multi-turn boundary, meaning it's a within-format axis and not a general transfer law. Three: if drift contexts and length-matched neutral contexts behave differently from each other, the prior corpus's "drift equals neutral at deep depth" result might fail to extend to the cosine geometry, meaning drift content is doing something neutral content isn't, which would be a real surprise.</li>
</ul>
</section>

<h3>H3 (drift vs neutral within-multi-turn-arm — extends #377's null to geometry).</h3>

<li><strong>PASS:</strong> The drift-vs-neutral CI on ΔG includes 0, AND the drift-vs-neutral cosine distance gap |median(cos_drift) − median(cos_neutral)| ≤ <strong>0.05</strong>.</li>
<li>Both inequalities = "drift and neutral sit at the same cosine band AND fire at the same ΔG, replicating #377's silencing-but-not-displacement reading in #489's geometry."</li>

</ul>

<h3>H4 (dynamic-range check — saturation guard).</h3>
<p>The 24 single-turn-source ΔG values at single-turn targets (= #489's already-measured 552 off-diag cells at the chosen anchor) span at least <strong>3 nat</strong> in the bottom 90% (i.e., the predictor is not at a floor across single-turn targets at the headline frac). If H4 fails, the merged headline is reported with a saturation caveat — the cosine→ΔG signal is being read through a partially-saturated DV.</p>

<p><strong>Pre-registered null states:</strong> H1 ρ = 0; H2 ΔG-gap = 0 AND cosine-gap = 0; H3 |drift − neutral| ≥ some_threshold ≥ 0.5 nat (i.e. a violation OF #377). Statistical primary = dyadic cluster-bootstrap (5000 boots, asymmetric cluster pools 24×12 for cross-format cells, 24×23 for #489's single-turn off-diag). Secondary = crossed random-effects `delta_g ~ cosine_distance + length + is_multi_turn + content_class + (1|source_context) + (1|target_context)`. PASS requires primary bootstrap CI to exclude 0; mixed-model fixed-effect CI agrees on sign.</p>

<h3>§4.2 Why Path (B) EVAL-ONLY, not Path (A) FULL transformation</h3>

<p>The clarifier flagged this as the one design choice for §4 to resolve. Decision: <strong>Path (B)</strong>. Reasoning:</p>

<ol>
<li><strong>Goal alignment.</strong> "<em>Supplement the data from #489</em>" + "<em>reusing #489's exact marker, training rig, post-context+question extraction point, and on-policy ΔG DV</em>" reads as the reuse path. Path (A) would <em>extend</em> the training rig (new training cells under multi-turn contexts), not reuse it.</li>
<li><strong>Compute economy.</strong> Path (A) = 12 new training cells × 1 seed at lr=2e-6 / r=16 / 150 rows × 3 epochs ≈ 36 GPU-h additional, plus the contrastive-negatives re-design problem (the contrastive negatives in #489 are single-turn under bystander single-turn contexts; under multi-turn the negative-pool definition becomes "same multi-turn history + question under a DIFFERENT trained source persona" which is not a thing yet). Path (B) = ~4 GPU-h, no new training, no negative-set re-litigation.</li>
<li><strong>Single-variable discipline.</strong> Path (A) would change TWO things at once vs #489 (context type + recipe under that context type — at minimum the multi-turn loss-slot construction would have to be ported). Path (B) changes ONE thing (the eval target panel adds 12 new contexts). The consistency-checker enforces single-variable; this is exactly the kind of "predictor-side extension to a running rig" the planner's `feedback_minimal_cli_override_probes` memory authorizes.</li>
<li><strong>Question fidelity.</strong> "Does the cosine predictor extend to multi-turn targets?" is fully answered by Path (B). "Does it extend BOTH WAYS (multi-turn sources too)?" is the natural follow-up if (B) gives a clean answer. <p><strong>Per-MT/MN conversation selection.</strong> #377's corpora have ≥ 49 conversations per domain (therapy=49, coding/philosophy/writing=50 each; the 5-conversation deterministic-hash slice fits comfortably). For each (domain, k) slot, deterministically pick 5 conversations (`hashlib.sha256(domain + k + seed=42).hexdigest()[:8]` modulo the per-domain conversation count, 5 distinct indices) and average their cosine vectors at the predictor read — same averaging shape as #489's `mean over Q'_probe = 50` for the single-turn arm. (#377 uses 200-prefix per cell at eval, but for the predictor we only need a stable mean-vector estimate, and 5 conversations × 50 probes = 250 forward-passes per MT context is comfortably below #489's 50-probes-per-context budget.)</p>

<p><strong>Why not also include k=5 or unclamped k=20?</strong></p>
<ul>
<li>k=5 is mostly conversational warm-up; #377 showed it's already at the silencing floor (3.1% fire). The interesting variation in the on-policy ΔG is between fresh (k=0, = #489's single-turn cells) and k≥10.</li>
<li>k=20 is clamped to ~14 prior turns by the corpus's 15-turn cap. The two slots k=10 and k=14 bracket the saturated silencing floor; adding k=5 would oversample the noise floor and adding unclamped k=20 would require regenerating the #377 corpus at >20 turns/conv (out of scope for this task).</li>
</ul>

<p><strong>Why drift + neutral, not drift only?</strong> #377's central finding is that drift and neutral are indistinguishable at k=20. H3 tests whether that null extends to the cosine geometry — i.e., is the silencing a position effect (drift = neutral) or a content effect (drift ≠ neutral)? If #501's geometry sees the same null as #377's behavior, that's a strong replication of #377's headline through #489's measurement. If #501's geometry sees a gap, that's a real surprise vs #377 and would force a re-read of both.</p>

<p><strong>The trigger placement.</strong> Each MT/MN context is a transformation `T_MT(q) = [MT prefix conversation (k prior turns)] + [{user: q}]` where `q` is the held-out Q'_probe. The user-question slot is at turn (k+1). The predictor read = last prompt token of `apply_chat_template(MT prefix + [{user: q}], add_generation_prompt=True)`. The on-policy generation under adapter_i then emits the response R; ΔG = trained − base log P(` ※`) at post-R slot — IDENTICAL primitive to #489's `i489_phase4_eval_onpolicy.py`.</p>

<h3>§4.6 Why code, not a model call (for any new heuristic over unstructured data)?</h3>

<p>The only new heuristic over unstructured data is <strong>(a) which conversation indices to pick per (domain, k) slot</strong> and <strong>(b) the length-matched-prefix length for MN01..MN04</strong>.</p>
