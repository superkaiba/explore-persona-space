Notes on deliberate choices inside Edit 1:

- **`git push origin main`, not the candidate sketch's `git push origin HEAD:main`.** Canonical form (2) is a copy-verbatim contract ("copy these forms"), and pushing the `main` ref is strictly safer than `HEAD:main` (identical when HEAD==main — the repo root is hook-pinned to `main` — and it cannot push a detached HEAD onto `main` in a pathological state). `sync_repo_root.py` itself syncs/pushes `main`, so the initial push and the recovery now target the same ref.
- **Line 535's descriptive `git pull --rebase=merges` mention STAYS** — it describes the concurrent-session HAZARD (why the immediate push exists, the #711 incident class), not a recipe to execute.
- **The stale-config parenthetical (`pull.rebase=merges + rebase.autoStash=true are pinned in .git/config`) is dropped** — it justified the hand-rolled pull; the helper passes its flags explicitly and the pin is documented in CLAUDE.md.
- **The in-flight caveat is ONE comment sentence**, matching form (2)'s own caveat comment — minimal, per the daily stub's benign `visible:false` nature. The landing-verified variant (issue/SKILL.md's post-merge stale-task-folder guard form) is deliberately NOT adopted: the stub is not guard-critical.
