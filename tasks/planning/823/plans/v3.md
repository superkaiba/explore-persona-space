# Plan — issue #823: Does the per-context map h predict the model's own output or context-side processing?

---

## §0.0 TL;DR

- **What I'll run:** Fit the same ridge map from #779 on four different answer sets — Qwen's own answers (reference, two versions: the original bundle and freshly regenerated), Sonnet plain-style answers, and Qwen's own answers shuffled to a wrong context. No new model training. The work is generating Sonnet answers, regenerating Qwen's own answers via vLLM, extracting hidden states for each answer set under the original contexts, and re-running the ridge fit.
- **What I expect:** The map trained on Qwen's own answers should transfer poorly to Sonnet plain answers and should fail nearly completely on the derangement arm. If R² drops more than five points on Sonnet-plain and drops to near zero on the derangement, the map is tracking what Qwen itself will write, not just what the context implies.
- **What would change my mind:** If Sonnet-plain answers score within three points of Qwen's own answers on the held-out R², the map is mostly capturing context-side computation and the content of the answer barely matters. That would mean the #779 result is about how the model processes the prompt, not about predicting its own outputs.

## §0 Plan Summary

**Training:** No model training. Frozen Qwen-2.5-7B-Instruct, base weights only. Ridge regression (GCV, λ ∈ [1e-2, 1e4]) refit on five arms using the existing #779 substrate (5000 LMSYS contexts, 28 layers, cx_last shape 5000×3584 per layer).

**Hyperparameters:** Ridge GCV λ grid: np.logspace(-2, 4, 13) — inherited from #779 `fit_h.py`; same 5-fold CV split (seed=0), same standardize-X/center-Y protocol. No novel hyperparameters. Source: #779 `fit_h.py::ridge_fit_predict`.

**Baselines / controls:** Arm A (Qwen own answers, reused #779 bundle v_x — harness reproduce-gate + consistency diagnostic only). Arm A′ (Qwen own answers, freshly regenerated via vLLM — primary own-answer arm for headline comparisons). Arm B2 (Sonnet-plain: Claude Sonnet 4.5 plain-style answers, style instruction stripped before TF). Arm C (derangement null: Qwen's own regenerated answer teacher-forced under a different context via a fixed-point-free permutation, seed=42). Arm B1 (Sonnet-weird: adversarial-style answers — diagnostic only, not a hypothesis arm).

**Loss surface:** N/A — ridge regression on mean-pooled residual-stream vectors. Teacher-forcing computes mean over response token span [prompt_len:full_len] at each of 28 layers.

**Compute:** Phase 0.5 (vLLM Qwen regeneration): ~1 GPU-h on 1× A100-80. Phase 3 (TF extraction on GPU, arms B1, B2, C, A′): ~5 GPU-h on 1× A100-80 (`lora-7b`). All other phases CPU on VM. Total GPU: ~6 GPU-h. **Estimated GPU-hours (total): 7**

**Evaluation:** Primary DV = held-out R² per arm per layer (5-fold CV). Decision rule: H1 (own-output specificity) if R²_A′ − R²_B2 > 0.05 AND R²_C < 0.05; H2 (context-side) if all arms within ±0.03; H3 (content generality) if R²_A′ ≥ R²_B2 > R²_C AND R²_B2 − R²_C > 0.03. All comparisons Bonferroni-corrected α = 0.05/3 = 0.017. Consistency diagnostic: per-context cos(v_A(x), v_A′(x)) at read-out layers; R²_A vs R²_A′ delta reported.

**Risks (top 2):** (1) Sonnet-plain answers differ in length distribution from Qwen's own answers — mean-pooling over spans of different lengths makes the per-context vectors incomparable. Mitigation: truncate to min(Qwen_len, Sonnet_len) tokens before mean-pooling, record per-context span lengths. (2) Stream-order drift between the prompt reconstruction and the bundle: the bundle stores no prompt text, so prompts are reconstructed by replaying `load_train_contexts` on LMSYS-Chat-1M; an alignment gate (cosine > 0.999 on ≥20 spot-check contexts at all 28 layers) is required before any arm work.

## §1 Goal

**What:** Determine whether the #779 ridge map h: cx_last(x) → v(x) — which achieves held-out R² 0.5977–0.6253 across evil/sycophancy/hallucination traits (evil read-out L14 R²=0.598, sycophancy L26 R²=0.604, hallucination L17 R²=0.625; cross-trait aggregate peak at L19 = 0.677) — is predicting the model's *own* generated content (own-output specificity hypothesis), or whether it is primarily capturing context-side computation that transfers to arbitrary answer text teacher-forced through the same context (context-processing hypothesis), or something in between (content generality hypothesis).

**Why:** If h predicts Qwen's own answers specifically (H1), then #779's result is evidence that the last-context vector encodes a prediction of the model's forthcoming *content*, not just a generic context representation. That changes the interpretation from "the model has a persona-like internal state" to "the model's context vector encodes an output prediction." If h transfers equally to external answers (H2), the result is about context-side computation, not content prediction. The distinction matters for whether h could be used as a predictive probe in deployment versus merely as an alignment diagnostic.

**Formal definitions:**

- v_A(x): mean residual-stream activation over Qwen's OWN generation response tokens, as stored in the #779 pass_b bundle (reused, harness reproduce-gate only).
- v_A′(x): same mean, but freshly regenerated via vLLM with the same #779 recipe (same model, same prompt reconstruction, same sampling params), teacher-forced through the new extraction driver. Primary own-answer arm for headline comparisons.
- v_B2(x): same mean, but over a Sonnet-plain answer to the same question, teacher-forced under x.
- v_B1(x): same mean, but over a Sonnet-weird answer (with style instruction stripped before TF).
- v_C(x): same mean, but over Qwen's OWN regenerated answer to question π(x) (a deranged context), teacher-forced under x. Null/derangement arm.
- h_ℓ: the ridge map at layer ℓ, fit on (cx_last^ℓ, v_A′^ℓ) — arm A′, primary reference.
- R²_arm^ℓ: 5-fold held-out R² when h_ℓ (fit on arm A′) is scored against v_arm^ℓ as the target.

**Kill criterion:** If the GPU extract phase (Phase 3) produces NaN activations for > 5% of contexts in any arm, abort and report as a data-quality finding.

## §2 Prior Work

**#779 substrate (direct parent):** The per-context ridge map h achieving R² 0.5977–0.6253 (evil L14/syc L26/hall L17) is already fit and its substrate (cx_last, v_x, 5000 LMSYS contexts, 28 layers) is on HF at `superkaiba1/explore-persona-space-data/issue779_monitoring/analysis_tensors/pass_b/train_context_vectors.pt`. Dataset repo revision sha: `c94070508aa1c1f9c015ceb072231a2e51b28b3f`; bundle file LFS sha256: `46c06e89c513ca598bc83be1c87689694a47bfc927a81d0d738a54df769dbf9a` (6021122751 bytes, verified 2026-07-01 to be byte-identical to the local mirror `data/issue_779/pass_b/train_context_vectors.pt`). Bundle keys: `{cx_last, cx_mean, v_x, layers, source, metadata}` (metadata is provenance-only: git_commit fc96549e, pass B; contains no prompt texts). This experiment inherits that substrate as arm A (harness reproduce-gate only); arm A′ is freshly regenerated.

**Future Lens (arXiv 2311.04897, Pal et al., 2023):** "Future Lens: Anticipating Subsequent Tokens from a Single Hidden State." Showed that intermediate hidden states can be decoded to predict the model's eventual output token distribution (next-token logits), achieving > 48% accuracy on subsequent-token prediction at some layers in GPT-J-6B using linear approximation. The key distinction from #779 is that Future Lens predicts next-token logits (a token-space prediction), whereas #779 maps to full response activation vectors (a content-space prediction). The present experiment tests whether #779's map is closer to a Future Lens–style own-output prediction or a more generic context encoding. The Future Lens finding supports H1 as a prior: linear maps from context vectors do track own-output content.

**Looking Inward (arXiv 2410.13787, Binder et al., 2024):** "Looking Inward: Language Models Can Learn About Themselves by Introspection." Showed that LLMs can be finetuned to predict properties of their own behavior in hypothetical scenarios, outperforming a different model trained on the same ground-truth behavior — evidence for privileged access to one's own behavioral tendencies. Note: this paper is about LLM self-prediction via finetuning (behavioral prediction), not about probing intermediate activations for planned outputs. It motivates the cross-arm design: if the activation map encodes Qwen's own planned content, it should fail to predict external content at the same position. (v1 described this as "distinguished from external-input representations using linear probes" — that description is imprecise relative to the paper's actual method, corrected here.)

**Persona Vectors (arXiv 2507.21509, Chen et al.):** The #779 parent used this recipe for extracting r_B at the response level. Relevant here as the activation-extraction baseline — we use the same mean-pooling recipe (mean over response tokens, layer-by-layer) for all arms. The paper's finding that persona vectors transfer across prompts is consistent with H3 (content generality) if the persona activation is the dominant component of v(x).

**Teacher-forcing artifact (#432→#456):** A known risk. Teacher-forced activations under an external answer text (B1, B2, C arms) may differ structurally from activations under the model's own continuation, because the model's own generation is on-distribution while TF of external text is not. This makes the B2 arm a conservative test of H2: a low R²_B2 could indicate H1 *or* TF artifact. The derangement arm C controls for this: it uses Qwen's OWN regenerated answer text (on-distribution) but under the wrong context, so TF artifact is equalized. If R²_C is also low, H1 is supported on TF-artifact-controlled grounds.

**Prior work on R² baseline:** #779's 28-layer R² profile peaks at L19 = 0.677 (cross-trait aggregate), with per-trait read-out layers evil:L14 (R²=0.598), sycophancy:L26 (R²=0.604), hallucination:L17 (R²=0.625). This plan inherits those layer selections as the primary evaluation slots, with full 28-layer profiles reported.

## §3 Hypothesis

**H1 — Own-output specificity:** h predicts Qwen's own answers specifically. Prediction: R²_A′ − R²_B2 > 0.05 AND R²_C < 0.05 (at the read-out layer for each trait). Operationally: the map trained on arm A′ transfers poorly to arm B2 and fails on the derangement control.

**H2 — Context-side processing:** h captures context computation, not content. Prediction: all arms (A′, B2, C) within ±0.03 R² of each other at the read-out layer. Operationally: knowing only the context, the map predicts any answer's activation profile equally well.

**H3 — Content generality:** h captures content-compatible activation structure, generalized beyond Qwen's own outputs. Prediction: R²_A′ ≥ R²_B2 > R²_C AND R²_B2 − R²_C > 0.03. Operationally: the map transfers partially to Sonnet-plain (content matters) but fails completely on the derangement (wrong content = wrong prediction), with R²_A′ still the highest.

**What would falsify all three:** R²_C > R²_B2 (the derangement arm scores higher than Sonnet). This would indicate an experimental artifact (likely the TF artifact) and would invalidate the design's discriminability.

**Quantitative thresholds (pre-registered):**

| Arm comparison | H1 threshold | H2 threshold | H3 threshold |
|---|---|---|---|
| R²_A′ − R²_B2 | > 0.05 | ≤ 0.03 | ≤ 0.05 |
| R²_A′ − R²_C | > 0.10 | ≤ 0.06 | > 0.05 |
| R²_B2 − R²_C | (any) | ≤ 0.03 | > 0.03 |
| R²_C absolute | < 0.05 | ≥ 0.02 | < 0.05 |

Evaluated at the per-trait read-out layer {evil:14, syc:26, hall:17}; all comparisons Bonferroni α = 0.017. Paired t-tests (5 fold values, 5 d.f.) across folds for each comparison.

```python
    Build full_messages = messages + [{"role": "assistant", "content": answer_text}]

                                                    tokenize=True))

    v_s = mean(hidden_states[ℓ][0, prompt_len:full_len, :]) for ℓ in layers
    """
```

**Confound controls:**
- Derangement arm (C) controls for TF artifact: uses Qwen's own regenerated on-distribution text, only the context is wrong. A low R²_C cannot be explained by off-distribution text.
- Arm A (bundle v_x) vs arm A′ (regenerated): the A-vs-A′ diagnostic isolates regeneration drift + extraction-path drift from any cross-arm comparison.
- Sonnet-plain (B2) vs Sonnet-weird (B1): if B1 < B2, style matters for transfer; if B1 ≈ B2, content (not style) is the driver.
- Length truncation (Phase 3): controls for span-length differences between arms in mean-pooling.

**Measurement validity table:**

| DV | Construct | Metric | On-distribution? | If proxy: validation |
|---|---|---|---|---|

- Alternatives: MLP rejected per user directive ("ridge only, no MLP").

**5-fold CV split (KFold seed=0):**
- What: Same 5-fold split used in #779.
- Why: Required for the arm A harness reproduce-gate to match #779's published R² values. Using a different split would introduce split-sampling variance.
- Source: #779 `eval_results/issue_779/percontext_recon.json` (n_folds=5, seed=0).
- Alternatives: 10-fold would reduce variance but breaks comparability with #779.
