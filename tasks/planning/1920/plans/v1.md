# Plan v1 — #1920 daily-fix: living_docs.py bounded index.lock retry

## Plan Summary

Give `scripts/living_docs.py`'s git subprocess helper (`_git()`) the same
bounded index.lock retry that `task_workflow._run_git` gained in #1917, by
REUSING the canonical constants from the already-imported
`explore_persona_space.task_workflow` module — never duplicating the
signature regex or the budget knob. Fail-loud semantics for non-lock
failures are preserved byte-for-byte; the read-only `check` subcommand path
is untouched. One pin test in `tests/test_living_docs.py`.

`architectural: false` — a guardrail inside one helper script; no public
contract, marker schema, status enum, or CLI change.

## Requirement + acceptance criteria (code change)

**Requirement.** A concurrent-session `.git/index.lock` (or sibling
`*.lock`) collision during `living_docs.py`'s `link` / `apply` commit path
must be absorbed by a bounded, jittered retry instead of crashing with a
raw `CalledProcessError` traceback (SystemExit) — the #1901 Step-0c
incident: 5 firings across 4 sessions on 2026-07-30.

**Acceptance criteria:**
1. `_git()` retries on (and ONLY on) the canonical git lock-contention
   stderr signature (`task_workflow._GIT_LOCK_CONTENTION_RE`), with the
   same bounded wall budget (`task_workflow._lock_wait_bound_s()`, env
   `EPM_TASKPY_LOCK_WAIT_SECONDS`, default 60 s, `0` disables) and the
   same jittered per-retry sleep
   (`task_workflow._GIT_LOCK_RETRY_SLEEP_RANGE_S`).
2. Non-lock failures raise immediately (zero sleeps) with unchanged
   `CalledProcessError` fields (`cmd`/`output`/`stderr`).
3. `check=False` rc-as-signal call sites (`diff --cached --quiet` at
   L414, `push` at L419) keep their rc semantics — the retry keys on the
   STDERR SIGNATURE, never the return code, exactly like `_run_git`.
4. Happy path takes zero sleeps and zero extra env reads (budget read
   lazily at the first collision — `_run_git` parity).
5. The read-only `check` subcommand gains no writer behavior (it never
   calls `_git`; invariant preserved by construction — no call-site
   changes).
6. One new pin test passes; the existing `tests/test_living_docs.py`
   suite stays green; ruff clean on touched files.

## Method delta (what differs from prior related work)

#1917 implemented this retry INSIDE `task_workflow._run_git`, which pins
`cwd=repo_root()` and reads the sanitized env per call. `living_docs.py`'s
`_git` takes an injectable `cwd` (tests use tmp repos), so `_run_git`
cannot be called directly. Delta: replicate ONLY the ~15-line retry loop
in `living_docs._git`, importing the three load-bearing pieces
(signature regex, budget function, sleep range) from `task_workflow` via
the existing `tw` import — so the fleet-wide signature set and the env
knob stay single-sourced. Considered and rejected: refactoring
`task_workflow` to extract a cwd-parametrized shared wrapper — it touches
a hot, just-merged shared file (#1917) for no behavioral gain and widens
the blast radius / lost-update exposure (#1713 class) of a small daily-fix.

## File paths + concrete diffs

1. `scripts/living_docs.py` — `_git()` (L380-398) only:

```python
def _git(args, *, cwd, check=True):
    """... (docstring gains a lock-retry paragraph citing #1917/#1920)"""
    env = dict(os.environ)
    for k in ("GIT_DIR", "GIT_WORK_TREE", "GIT_INDEX_FILE", "GIT_OBJECT_DIRECTORY"):
        env.pop(k, None)

    def _attempt():
        return subprocess.run(["git", *args], cwd=str(cwd), env=env,
                              check=False, capture_output=True, text=True)

    result = _attempt()
    if result.returncode != 0 and tw._GIT_LOCK_CONTENTION_RE.search(result.stderr or ""):
        bound = tw._lock_wait_bound_s()
        deadline = time.monotonic() + bound
        # warn once, then bounded jittered retries (mirrors tw._run_git)
        while (result.returncode != 0
               and tw._GIT_LOCK_CONTENTION_RE.search(result.stderr or "")
               and time.monotonic() < deadline):
            time.sleep(random.uniform(*tw._GIT_LOCK_RETRY_SLEEP_RANGE_S))
            result = _attempt()
        # on exhaustion with the signature still standing: ERROR-log the
        # stale-lock remedy naming the budget + env knob (_run_git parity)
    if check and result.returncode != 0:
        raise subprocess.CalledProcessError(
            result.returncode, result.args, output=result.stdout, stderr=result.stderr)
    return result
```

   Plus `import random`, `import time`, `import logging` additions as
   needed (module currently lacks them — verify at implement time) and a
   module logger if none exists.

2. `tests/test_living_docs.py` — one new test (monkeypatch
   `subprocess.run` at the `living_docs` module level):
   - lock-signature failure ×2 then success → `_git` returns success,
     ≥1 sleep observed (monkeypatch `time.sleep` to record + fast-forward);
   - non-lock failure → raises `CalledProcessError` immediately, zero
     sleep calls;
   - `check=False` + non-lock nonzero rc → returns the result, no raise,
     zero sleeps;
   - budget `EPM_TASKPY_LOCK_WAIT_SECONDS=0` → single attempt, no retry
     (fail-loud parity with the pre-#898 shape).
