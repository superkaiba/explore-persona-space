## 1. Requirement

`classify_window` in `scripts/check_cited_body_currency.py` emits an advisory
`frontmatter-only` label whose claim is "every change in this window is
metadata, so the plan's cited body text is unaffected". It decides that from
the SHAPE of the changed diff lines:

```python
fm_line = re.compile(r"^[+-](?:---\s*$|[A-Za-z_][A-Za-z0-9_-]*:)")
if all(fm_line.match(ln) for ln in changed):
    return "frontmatter-only"
```

Any changed line of the form `Word:` satisfies it. `RESULT:`, `CORRECTED:`,
`Note:`, `Takeaway:` are ordinary clean-result body prose, so a genuine
content correction written as `RESULT: ...` -> `CORRECTED: ...` earns the
label. The label feeds an operator decision: `.claude/skills/adversarial-planner/SKILL.md`
tells the operator on exit 3 to re-read the changed sections and then either
record the plan text as unaffected or bounce, and `frontmatter-only` nudges
toward "unaffected". The verdict stays STALE either way and the diff is never
suppressed (only `rename-only` suppresses it), which is why this is a
correctness defect in an advisory surface rather than a blocking one.

### Acceptance criteria

1. A CONCLUSIVE window whose only content change is a `Word:`-shaped body
   line is NOT labelled `frontmatter-only`, proven by a committed test that
   FAILS against the pre-fix code and PASSES after.
2. A genuine frontmatter-only edit still earns the label. The fix must not be
   a deletion of the label. This needs a NEW positive test: the branch's
   current suite has no positive `frontmatter-only` assertion (verified —
   every existing mention at `tests/test_check_cited_body_currency.py`
   lines 811-881 asserts `label is None`).
3. The `conclusive` gating that #2384 round 5 landed is preserved: an
   INCONCLUSIVE window still yields `label is None` on every path, and
   `conclusive` keeps having no default. The two existing round-5 tests
   (`test_hop_cap_exhaustion_withholds_frontmatter_label`,
   `test_midchase_log_failure_withholds_frontmatter_label`) must keep passing
   unmodified.
4. `rename-only` behaviour is untouched: still decided from the per-commit
   name-status of the rename-chasing window, never from diff text.

## 2. Method delta — why not the narrower fix

The task body's fix sketch offers two anchors: "known frontmatter keys, or
the leading `---` delimited region".

**Rejected: a known-key allowlist.** It narrows the over-match from any
`Word:` to ~20 specific words, and leaves the same defect class alive — a
body line `status: running` or `title: ...` in prose still earns the label —
while adding a list that silently rots as `task.py` grows frontmatter fields.
It treats the symptom (which words match) rather than the claim (whether the
body actually changed).

**Chosen: verify the claim directly.** The label asserts that the body
outside the frontmatter is unchanged across the window. Test exactly that:
fetch the file at both window endpoints, split off the leading
`---`-delimited block, and emit the label only when the remaining bodies are
byte-equal. This is shape-independent, so it cannot over-match on any prose
whatsoever, and it survives frontmatter-key evolution with no maintenance.

Cost is two extra `git show` calls on the one path that already spends a
`git log` + a batched `--name-status` + a `git diff` (the file's own docstring
measures the plain read at ~1.5 s). They run only when the chase ended
conclusively, the `rename-only` branch did not fire, and a diff exists.

`classify_window` stays a PURE function — the endpoint texts are fetched by
its single caller `body_diff_since` (which already holds `repo_root`,
`oldest_sha` and the window pathspec) and passed in as keyword arguments. That
keeps the function unit-testable without a git repo and preserves the
round-4/round-5 design in which the safety flags are explicit parameters with
no permissive defaults.

### 3.1 `scripts/check_cited_body_currency.py`

**(a) `_git` gains an opt-out from output stripping.** `_git` currently ends
`return proc.stdout.strip()`. Stripping is right for shas, subjects and log
text, and wrong for file CONTENT: it would drop a trailing newline from both
endpoints symmetrically, so a body change that is trailing-whitespace-only
would read as body-identical and earn the label. Two lines, no behaviour
change at any existing call site:

```python
def _git(args: list[str], *, cwd: Path, strip: bool = True) -> str | None:
    ...
    return proc.stdout.strip() if strip else proc.stdout
```

Docstring gains one sentence: `strip=False` is for reads whose value is file
CONTENT, where a stripped trailing newline would make two different bodies
compare equal.

**(b) New module-level helper, placed next to `_strip_code_blocks`.**

```python
_FM_OPEN_RE = re.compile(r"^---\s*$")
_FM_CLOSE_RE = re.compile(r"^(?:---|\.\.\.)\s*$")


def split_frontmatter(text: str) -> tuple[str, str] | None:
    """``(frontmatter block, body)`` for a leading ``---``-delimited YAML
    frontmatter block; ``None`` when ``text`` has no such block.

    Returning ``None`` rather than ``('', text)`` is load-bearing: the
    ``frontmatter-only`` label in :func:`classify_window` is emitted only
    when BOTH endpoints split successfully, so a file with no frontmatter —
    or an UNTERMINATED block, where there is no trustworthy body boundary —
    can never reach a label whose entire claim is that only the frontmatter
    changed.

    The closing delimiter follows YAML: ``---`` (a new document) or ``...``
    (end of document). The block is recognized only at line 1, which is
    where every ``body.md`` carries it.
    """
    lines = text.splitlines(keepends=True)
    if not lines or not _FM_OPEN_RE.match(lines[0].rstrip("\r\n")):
        return None
    for i in range(1, len(lines)):
        if _FM_CLOSE_RE.match(lines[i].rstrip("\r\n")):
            return "".join(lines[: i + 1]), "".join(lines[i + 1 :])
    return None
```

**(b2) Extract the all-`R100` test so caller and classifier share one
definition.** `classify_window`'s `rename-only` branch currently inlines
`window and all(c.status == "R100" for c in window)`. Lift it verbatim to a
module-level helper so the §3.1(d) fetch gate can ask the same question
without duplicating the predicate:

```python
def is_rename_only_window(window: list[_Commit]) -> bool:
    """``True`` when EVERY windowed commit is an exact ``R100`` — a pure
    status-move window. Extracted (#2654) so :func:`body_diff_since`'s
    endpoint-fetch gate and :func:`classify_window`'s ``rename-only`` branch
    cannot drift apart; the predicate itself is unchanged from #2384."""
    return bool(window) and all(c.status == "R100" for c in window)
```

`classify_window`'s branch becomes
`if is_rename_only_window(window): return "rename-only"` — same semantics,
same decision source (per-commit name-status, never diff text).

**(c) `classify_window` — replace the shape heuristic.** Signature gains two
keyword-only parameters with NO defaults (same rationale the docstring already
gives for `conclusive`: a permissive default on a safety input re-opens the
hazard at any future call site):

```python
def classify_window(
    window: list[_Commit],
    diff: str,
    *,
    conclusive: bool,
    old_text: str | None,
    new_text: str | None,
) -> str | None:
```

Body: the `conclusive` early return, the `rename-only` branch and the
`if not diff: return None` guard are UNCHANGED. The `changed` list
comprehension and `fm_line` regex are DELETED and replaced by:

```python
    if old_text is None or new_text is None:
        return None          # an endpoint we could not read proves nothing
    old_split = split_frontmatter(old_text)
    new_split = split_frontmatter(new_text)
    if old_split is None or new_split is None:
        return None
    if old_split[1] != new_split[1]:
        return None          # the body changed: this is the real signal
    if old_split[0] == new_split[0]:
        return None          # neither half changed (e.g. a mode-only diff)
    return "frontmatter-only"
```

Docstring gains a paragraph recording the round-6 change: the label is decided
by comparing the frontmatter-STRIPPED endpoint bodies, never from the diff
text, because a shape test on changed lines cannot distinguish frontmatter
from body prose — `RESULT:`/`CORRECTED:`/`Note:` are ordinary body lines that
satisfied the old `^[+-]Word:` pattern, so a content correction earned the
label the operator reads as "plan text unaffected" (#2654). The named residual
is stated: this is a two-endpoint test, so a body corrected and then reverted
INSIDE the window reads as body-identical and earns the label — correct for
the label's literal claim (the cited text at HEAD matches what the window
started with) and consistent with the gate's STALE verdict, which is driven by
commit recency, not by content.

**(d) `body_diff_since` — fetch the endpoints.** Immediately after the
existing `diff = _git([...]) or ""` line:

```python
    # GATE (load-bearing, see below): fetch ONLY on the one shape that can
    # reach the text comparison in classify_window.
    need_text = conclusive and bool(diff) and not is_rename_only_window(window)
    old_text = new_text = None
    if need_text:
        oldest = window[-1]
        old_path = oldest.prev_path or oldest.path or rel_path

        new_text = _git(["show", f"HEAD:{rel_path}"], cwd=repo_root, strip=False)
```
