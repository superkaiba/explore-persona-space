Acceptance criteria:

1. A #1768-shaped wedge (namespace-vetoed ticks, frozen logs+outputs, all GPUs idle, ~0 CPU, escalation posted) flips the verdict to `stalled` / `persistent_wedge_veto_yield` after N (default 10) consecutive qualifying ticks — ≈90 min at the 540 s orchestrator tick (up to ~5 h if a lane sleeps the poller at the 1800 s quiet-tick recommendation), vs 16 h unbounded today.

3. `EPM_POLL_WEDGE_VETO_YIELD_TICKS <= 0` disables the yield entirely (kill switch, single-knob pattern of `EPM_GPU_IDLE_WIDTH_REEVAL_N`); every degraded read (missing/garbage state keys, absent escalation state, unparseable streak, unknown gpu_idle) fails toward today's behavior (veto holds).

5. `stall_reason=persistent_wedge_veto_yield` routes `infra` via `scripts/failure_classifier.py` (`STALL_REASON_INFRA`), and `.claude/skills/issue/failure_patterns.md` documents it (mirror update).
6. ## Method delta (vs the current code)

Today the namespace-veto branch (FIRST branch of `_apply_zombie_override`, ~L4977) unconditionally `return status, stall_reason, cpu_override_active, 0` — suppress + streak reset, every tick, forever. The delta:

- **Wedge streak (`wedge_veto_streak` state key).** Recomputed each tick exactly like `zombie_streak` (persisted via `_save_state`; any tick that does not qualify resets it to 0; NOT added to `_RUN_SCOPED_STATE_KEYS` — a relaunch freshens logs, which resets the streak naturally on the next tick, the kill tick itself resets it via `status != "running"`, and the recompute-each-tick contract covers every other epoch change). A tick INCREMENTS the streak iff ALL of:
  - the namespace veto fired (`total > 0 ∧ resolvable == 0 ∧ alloc_holders > 0`, `status == "running"`, zombie candidate present), AND
  - `min(last_mtime_ago, phase_log_mtime_ago, shard_log_mtime_ago) > max(ZOMBIE_VETO_FRESH_SEC, stall_sec)` AND `output_mtime_ago > max(ZOMBIE_VETO_FRESH_SEC, stall_sec)` (frozen logs AND frozen outputs — the wedge regime; a fresh log/output during a namespace-vetoed tick resets), AND
  - **(v2)** the current tick's `gpu_idle` is `True` (every GPU idle — the #1768 defining observable; threaded from `poll_once` where it is already computed, new keyword-only param `gpu_idle: bool = False` whose inert default means pre-existing callers/tests are byte-unchanged AND fail-safe: unknown/absent ⇒ streak resets ⇒ veto holds), AND
  - NOT (material CPU on both ticks: `session_cpu_rate_cores >= ZOMBIE_OVERRIDE_CPU_CORES_MIN ∧ prev_cpu_rate >= ZOMBIE_OVERRIDE_CPU_CORES_MIN`) and NOT the #1477 negative-rate+pcpu confirm shape — material compute resets the wedge streak (same evidence classes as the downstream #951/#1477 vetoes, applied WITHIN the namespace-vetoed regime).
- **Yield conjunction.** When the incremented streak `>= EPM_POLL_WEDGE_VETO_YIELD_TICKS` (default 10, `<= 0` disables) AND the GPU-idle escalation has been posted for this run (`prev_state["gpu_idle_escalated_phases"]` non-empty — the run-scoped #1033 key; absent/empty ⇒ conjunct false ⇒ veto holds), the namespace veto YIELDS: `status="stalled"`, `stall_reason="persistent_wedge_veto_yield"`, `cpu_override_active=False`, distinct `log.error` carrying the forensic counts (streak, N, total/resolvable/alloc, staleness, gpu_idle, CPU rates). Below the conjunction the branch behaves exactly as today (suppress, WARNING, `zombie_streak=0`) — but persists the incremented `wedge_veto_streak`.
