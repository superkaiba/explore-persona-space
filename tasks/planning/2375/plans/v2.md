## 2. Root cause — MEASURED, and independently re-measured

Reproduced 2026-08-28 in **38.9 s** with a two-file prefix on pristine `main`
(`4f44ae2f184`), command in §5; the round-1 critic re-ran it independently and got
`1 failed, 56 passed in 39.28s` with a byte-identical assertion:

```
tests/test_issue2162_figures.py:357: AssertionError
E   AssertionError: assert '1 cells without probe rows omitted' in ''
```

Byte-identical to the #2168 gate-#2 failure the task body records.

Mechanism, three links, each independently checked by both the planning pass and the critic
(the critic additionally live-probed the slot behaviour on the installed matplotlib: under
the leaked value, `ax.set_title('probe')` then `ax.get_title()` returns `''` while
`get_title(loc='left')` returns `'probe'`):

1. `src/explore_persona_space/analysis/paper_plots.py:607` (`_set_blog_style`) writes
   `"axes.titlelocation": "left"` into `mpl.rcParams` via `mpl.rcParams.update` —
   **process-global**, no context manager. It is reached by `set_paper_style("blog")` and by
   the bare `set_paper_style()`, whose default register is `blog`. It is the repo's ONLY
   write site for that key. `_set_neurips_style` does not touch it, and `paper_plots.py`
   calls no `rcdefaults` / `rcParamsDefault` / `style.use` anywhere — so the
   `set_paper_style("neurips")` calls that several `test_paper_plots.py` tests use as a
   "restore" do NOT clear it. The leak survives them.
2. `matplotlib.axes.Axes.set_title(label, loc=None)` resolves its slot from
   `rcParams["axes.titlelocation"]`. Under the leaked value the title is written to the
   **left** title artist. `fig_two_by_two` calls `ax.set_title(title)` with no `loc`
   (`scripts/issue2162_figures.py:315`).
3. `Axes.get_title()` defaults to `loc="center"`, which is empty. The spy at
   `tests/test_issue2162_figures.py:340-357` reads exactly that.

Ruled out, explicitly: `fig.axes[0]` IS the scatter axes (`fig_two_by_two` builds a
single-axes figure via `plt.subplots(figsize=(9, 8))`, and neither `legend()` nor
`annotate()` adds an axes) — the task body's "or axes[0] was not the scatter axes"
alternative is false. Figure-registry pollution is not implicated.

**The leak surface is 8 test files, not 1.** `set_paper_style` is called from
`tests/test_paper_plots.py` (43 call sites), `test_issue2569_figures.py`,
`test_issue2094_figures.py`, `test_issue1417_render.py`, `test_issue2333_figures.py`,
`test_issue2222_figures.py`, `test_issue2215_figures.py`,
`test_issue1112_lr_matched_geometry.py`. Of these, only `test_issue2569_figures.py`
contains its writes (autouse `_production_style` fixture wrapping each test in
`matplotlib.rc_context()`, docstring rationale: "so nothing leaks to other test files").
The other seven leak. A per-call-site fix would leave the next `set_paper_style` anyone adds
re-opening the same hole — hence a shared fixture.

**The mutation surface is closed at those 8 files** (critic-verified, this round): no test
under `tests/` writes `rcParams` by any other route — no `rcParams[...] =`, no
`rcParams.update`, no `style.use`, no `plt.rc(` — and no `set_paper_style` call sits at
module level. Both invariants are recorded in §13 because the fixture's class-closure
argument depends on them.

**Why distance-based prefix windowing would have failed here** (the body's #2021 caveat,
confirmed): the leaked value is process-global and sticky, so ANY co-selection order that
places a style-setting file anywhere before `tests/test_issue2162_figures.py` reproduces,
at any distance. No bisect of the 406-file prefix was needed — a repo-wide grep for
`titlelocation` returns exactly one write site.

## 3. Method delta

Versus the sibling ordering-flake task **#2369** (`tick_triage` module-level-NOW):
same broad family (process-global state read at a different time than it was written),
disjoint mechanism and disjoint fix surface — no shared file, no coordination needed.

Versus the in-repo precedent **`tests/test_issue2569_figures.py::_production_style`**:
that file already solved this exact problem *for itself*, with `matplotlib.rc_context()`.
The delta is scope only — promote the identical primitive from one per-file autouse fixture
to one shared autouse fixture in `tests/conftest.py`. `tests/conftest.py` already carries
this consolidation idiom (its own comment: "The guards were born as per-file autouse
fixtures in the three big watcher [modules]"), so the shape is house-standard, not novel.

Rejected alternatives, with the reason each is worse:

- **Pin `loc="center"` in `fig_two_by_two`** (the body's third admissible grain). Rejected:
  `scripts/issue2162_figures.py` `main()` calls `set_paper_style("blog")` (~line 1151), so
  in PRODUCTION this figure is *meant* to render under the blog register, where a left title
  is the intended house style. Pinning the slot would make the shipped figure fight its own
  style for the sake of a test read. It also fixes exactly one figure function while leaving
  every other title-setting producer exposed.
- **Restore in each leaking `test_paper_plots.py` test.** Rejected: 43 call sites across 7
  files, no mechanical enforcement, and the next added call re-opens the hole.
- **Reset the key globally at conftest import.** Rejected: fixes the value once, not the
  leak; a mid-session `set_paper_style("blog")` re-pollutes everything after it.

## 4. File paths + concrete changes

### Change 1 (the fix) — `tests/conftest.py`: shared autouse rcParams isolation

Add a module-level `import matplotlib` alongside the existing stdlib imports, and one
function-scoped autouse fixture placed with the existing autouse guard block:

```python
@pytest.fixture(autouse=True)
def _mpl_rcparams_isolation():
    """Restore process-global ``matplotlib.rcParams`` after every test (#2375).

    ``set_paper_style("blog")`` writes ``axes.titlelocation="left"`` into the
    PROCESS-GLOBAL rcParams (``paper_plots._set_blog_style``, the repo's only
    write site for that key). ``Axes.set_title`` resolves its slot from that key
    while ``Axes.get_title()`` defaults to ``loc="center"``, so any later test
    that sets a title through production code and reads it back sees ``''``.
    That is the #2168 gate-#2 red on
    ``tests/test_issue2162_figures.py::test_fig_two_by_two_quadrant_labels``:
    green single-file, red behind a prefix containing any of the eight
    style-setting test files. ``set_paper_style("neurips")`` does NOT undo it —
    the neurips register never touches the key.

    ``matplotlib.rc_context()`` is matplotlib's own primitive for this: it
    snapshots rcParams, DELETES ``backend`` from the snapshot (so restoring can
    never trigger a backend switch), and restores via ``_update_raw`` (no
    re-validation). ``tests/test_issue2569_figures.py::_production_style``
    already uses this exact shape per-file; this is the shared generalization,
    and the per-file fixtures keep working unchanged (nested ``rc_context``
    scopes each restore their own snapshot, so either nesting order composes).
    """
    with matplotlib.rc_context():
        yield
```

**Why the import is unconditional rather than a `sys.modules.get("matplotlib")` probe.**
The lazy form is a no-op for any test that is itself the first importer of matplotlib in
the process, and that case is NOT hypothetical: `tests/test_issue1417_render.py` and
`tests/test_issue1112_lr_matched_geometry.py` both complete module import with matplotlib
absent from `sys.modules` (their `set_paper_style` imports are function-local, and neither
`issue1417_render` nor `issue1112_geometry` imports matplotlib) — critic-verified by import
probe this round, falsifying v1's claim that every style-setting file imports matplotlib at
module scope. Rather than re-argue a narrowed residual, the unconditional import removes it:
the fixture then wraps every test unconditionally, and no reasoning about collection order
is load-bearing anywhere in this plan.

**Measured cost of the unconditional import: 349 / 395 / 450 ms** (three runs, this VM,
matplotlib 3.10.8) — paid **once per pytest process**, not per test. Against a full-suite
run measured at 1h47m that is ~0.006%; the visible cost is ~0.4 s added to a single-file
run of an unrelated test. No `try` / `except ImportError` guard: matplotlib is a hard
project dependency, and a swallowed import error is exactly the silent-failure shape the
project bans.

### Change 2 (the regression guard) — new file `tests/test_mpl_rcparams_isolation.py`

Two tests, relying only on pytest's in-module definition order (the repo pins no
random-ordering plugin: `pytest-randomly` / `pytest-random-order` / `xdist` are all absent
from the environment, and `pyproject.toml`'s `[tool.pytest.ini_options]` sets no ordering
option):

```python
"""#2375 regression guard for the shared autouse rcParams-isolation fixture."""

import matplotlib
import matplotlib.pyplot as plt

from explore_persona_space.analysis.paper_plots import set_paper_style

_BASELINE: dict[str, object] = {}


def test_style_call_pollutes_within_the_test():
    """Premise of the guard: the blog register writes the key that broke #2162."""
    _BASELINE["axes.titlelocation"] = matplotlib.rcParams["axes.titlelocation"]
    # A pre-polluted baseline would make the next test vacuous — fail loudly instead.
    assert _BASELINE["axes.titlelocation"] != "left"
    set_paper_style("blog")
    assert matplotlib.rcParams["axes.titlelocation"] == "left"


def test_pollution_does_not_escape_to_the_next_test():
    """Without the conftest fixture this reads 'left' and both asserts fail."""
    assert _BASELINE, "definition-order precondition: the polluting test runs first"
    assert matplotlib.rcParams["axes.titlelocation"] == _BASELINE["axes.titlelocation"]
    # The incident mechanism itself, not just the key: a default set_title must be
    # readable back through the default get_title.
    fig, ax = plt.subplots()
    try:
        ax.set_title("guard")
        assert ax.get_title() == "guard"
    finally:
        plt.close(fig)
```

The first test's `!= "left"` assertion is deliberate: it converts "some earlier module
leaked at import time" from a silently-vacuous guard into a loud failure.

## 7. Kill criteria

Abandon or re-plan (do NOT paper over) if any of these hold:

- **K1.** With the fixture in place, S2 still fails ⇒ the mechanism in §2 is wrong; stop,
  re-derive, re-plan. (Falsifiable and cheap: 40 s.)
- **K2.** S3 or S3b shows a test that *depended* on leaked style state (i.e. the fixture
  turns a green test red). That would mean isolation is not free here; re-plan toward a
  narrower grain rather than deleting the newly-red assertions. **Enforcement is §10's
  must-ask list, not this prose:** any assertion deletion / skip / xfail is a must-ask, so a

  up to ~6× are on record) is noise-dominated — it would kill a healthy fix. If anyone wants
  the number, take the median of ≥3 interleaved with/without pairs on one selection and log
  it; it changes no verdict either way.

- **Blast radius: the test suite only.** No production module is touched, so no shipped

  yet observed. No claim is made about how many latent flakes exist.
