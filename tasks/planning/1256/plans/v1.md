Exact satisfaction predicates (implementer copies these verbatim):

```python
def _tier1_satisfied(body_hex_tokens: set[str], value: str, M: int, body: str) -> bool:
    v = value.strip().lower()
    if re.fullmatch(r"[0-9a-f]{7,64}", v):
        return any(v.startswith(tok) for tok in body_hex_tokens)  # lowercased, len>=7
    # non-hex pin (branch/tag): fall back to issue-level mention
    return bool(
        re.search(rf"#\s?{M}(?!\d)", body)
        or re.search(rf"/tasks/{M}(?!\d)", body)
        or f"issue{M}_" in body
    )

def _tier2_satisfied(body: str, M: int, token: str) -> bool:
    seg = token.split("/")[0]          # e.g. "issue779_monitoring"
    return bool(
        seg in body
        or re.search(rf"#\s?{M}(?!\d)", body)
        or re.search(rf"/tasks/{M}(?!\d)", body)
    )
```

(The `(?!\d)` digit boundary prevents `#7791` satisfying M=779. Tier-1 hex matching is prefix-of, so a footer short sha `5aa6de1b` (8 chars) satisfies the metadata's 40-char pin.)

### 4.4 Scan scope decision (design decision 1)

**Whole `eval_results/issue_<N>/**/*.json` tree, NOT body-cited-path extraction.** The Goal says "body-cited result JSON"; the implemented scope is a superset and I justify the deviation:

- Every body-citable result JSON for issue N lives under `eval_results/issue_<N>/` (Upload Policy; the #1092 citation is a GitHub TREE link to `eval_results/issue_1092/cross-corpus-probe-transfer/` — a directory, whose contained `transfer_reads.json` is the incident file). Whole-dir scanning makes directory citations, SHA-pinned GitHub tree/blob URL forms, and backtick-path forms all moot — an entire class of extraction bugs deleted.
- It is the existing convention: `_scan_issue_judge_errors` (L4782) rglob-scans the same tree for the #732 check.
- An uncited-but-committed JSON carrying cross-issue pins still reflects reuse that happened in this issue's pipeline; declaring it costs one bullet. Empirically this superset adds zero fires today (§4.1).
- `.jsonl` files are OUT of scope (parity with `_scan_issue_judge_errors`; per-row JSONL metadata is not the observed convention).

### 4.5 Metadata extraction recipe (design decision 2)

Walk every dict under a key named `metadata` at any depth of each JSON payload (measured: identical to top-level-only on the whole corpus, more robust for nested `run_result.json` phase shapes). Within each metadata dict:

- **Tier 1:** ALL keys, recursively, matched against `_HF_REV_PIN_KEY_RE`; M = captured group; keep when `M != issue` and the value is a string.
- **Tier 2:** `_ISSUE_SLUG_RE` over (a) `metadata["input_shas"]` keys AND string values, (b) string values under `metadata["args"]` (recursive) that contain `/` (path-like filter — this single condition removes the `issue404_outcome_eval` / `issue532_v2` experiment-tag noise class measured in §4.1). Keep when `M != issue`.
- M == N pins (`hf_rev_1092` in issue 1092) never flag (the self-pin is provenance, not reuse).

### 4.6 FAIL vs WARN (design decision 4)

- **Tier 1 → FAIL.** Evidence: base rate 1 file repo-wide; the only carrier's current body PASSes; the pre-fix replay FAILs on exactly the incident pin. Zero measured false positives; FAILs only bind new drafts at posting time. Matches the task sketch.
- **Tier 2 → WARN.** Evidence: the underlying `issue<M>_` pattern is high-frequency (63+ occurrences) and semantically fuzzier (reused SCRIPT names like `scripts/issue931_fit_cells.py`, HF source strings); the restricted+satisfied form measured 0 fires, but its satisfaction predicate (first-segment containment) is more brittle against wording drift than a hex sha. WARN ships the signal without blocking risk; promotion to FAIL is a trivial later change once it has soak time.

## 11. Decision Rationale

1. **Scan scope = whole `eval_results/issue_<N>/` tree (not body-cited-path parsing).** Why: deletes the markdown-link-extraction bug class (the #1092 footer cites a DIRECTORY via a SHA-pinned GitHub tree URL); superset with measured-zero added fires. 2. **Tier-1 = `^hf_rev_(\d+)(?:_\w+)?$` metadata KEYS; satisfaction = ≥7-hex body-token prefix of the pinned sha.** Why: surgical (1/87,900 files) and the ONLY predicate with incident recall — an issue-level `#M` predicate is satisfied by the pre-fix body's existing r_B `#779` bullet (measured: zero recall). Source: the incident JSON `metadata.args` (§4.1); `.claude/skills/clean-results/SPEC.md:1247-1250`; the measured pre-fix replay. Alternatives: issue-level match (no recall); literal `- Reused` bullet-shape parse (false-FAILs #1092's own inline declaration).
3. **Tier-2 = `\bissue(\d+)_` restricted to `input_shas` + path-like `args` values; WARN.** Why: unrestricted pattern fires on 63+ occurrences across 12 issues; the `/`-filter + satisfaction predicate measured 0 fires while covering the sketch's input-path class. 4. **FAIL for tier 1 (not WARN-first).** Why: quantified FP = 0 on every current body; FAILs bind only new drafts; the incident class must BLOCK. 5. **Dispatch = `verify_text`-appended with `issue=`/`eval_root=`/`body_source_path=` kwargs.** Why: needs N for M ≠ N + disk resolution — the `check_judge_error_denominator` shape exactly.
