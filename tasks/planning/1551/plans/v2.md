## 4. Design

### 4.1 New check: `c40_regression_anchor_executed` (id provisional — see §10)

Location: `scripts/verify_plan.py`, new section after `check_off_pod_phase_declaration` (currently ends ~L6414), before `CHECKS`. Registered by appending `check_regression_anchor_executed` to `CHECKS`.

Classification: **WARN-only, conditional, kind: infra + batch only.**

Kind-scope justification (design question 3): (a) every sibling test-coverage/gate check is infra+batch (c11 dry-run coverage, c15 fail-loud test backing, c31 SKILL.md pin, c34 ratchet, c37 no-flags claim) — the "lean on the gate" idiom is workflow-fix dialect; (b) the founding incident (#1536) and the emitter's predicted recurrence class ("infra plans that lean on 'the gate will run it'") are both infra; (c) the c38 doctrine — start narrow, "widen only after burn-in" — is the fail-open-friendly default; widening to experiment/analysis is a one-line kind-gate change later if calibration shows the shape there. NEVER FAILs (task-body constraint: "an anchor claim can be legitimately satisfied by prose the parser cannot see; fail-open").

### 4.2 Trigger (design question 1)

A NON-FENCED line (fence-masked trigger, c12 doctrine) that carries BOTH:
1. a test-file path token, and
2. anchor/gate-selection vocabulary,

and does NOT carry a negation token. Same-line co-occurrence only (the c37/c38 same-line-radius doctrine — a ±N window would false-fire on §6 test lists near unrelated gate prose).

```python
# Test-path token: optional tests/ prefix + optional subdirs; ::node ids tolerated
# and stripped at capture. A bare `test_x.py` normalizes to `tests/test_x.py`
# (plans conventionally write full repo-relative paths; the bare form is a
# disclosed convenience with the assumed-under-tests/ caveat in the docstring).
_C40_TESTPATH_RE = re.compile(r"\b((?:tests/(?:[\w-]+/)*)?test_[\w-]+\.py)\b")

# Anchor / gate-selection vocabulary. Two claim classes, one trigger set:
#  (i) gate-selection claims — "sits on the Step-9c mapped-scan path",
#      "Step 9c selects/runs it", "auto-selected", "the gate will run it";
#  (ii) anchor claims — "regression anchor", "must stay green",
#      "stays/remains green".
_C40_ANCHOR_VOCAB_RE = re.compile(
    r"(?i)\bregression[- ]anchor"
    r"|\bmust\s+(?:stay|remain)\s+green\b|\b(?:stays?|remains?)\s+green\b"
    r"|\bmapped[- ]scan\b"
    r"|\bstep[- ]?9c\b"
    r"|\bauto[- ]select"
    r"|\bgate\s+(?:will\s+)?(?:runs?|selects?|covers?)\b"
    r"|\b(?:selected|picked\s+up)\s+by\s+the\s+(?:9c\s+)?gate\b"
)

# Negation guard (c37/_C38_NEG_RE convention): the CORRECTED plan shape
# ("test X is NOT auto-selected — the one-hop import map misses it — so §6
# runs it explicitly") must not trigger.
_C40_NEG_RE = re.compile(r"(?i)\bnot\b|\bnever\b|\bno longer\b|\bcannot\b|\bisn'?t\b|\bwon'?t\b|\bmisse[sd]\b")
```

Anchors = the deduped, normalized set of test paths captured from every triggering line. No trigger → `_skip(cid, name, "no regression-anchor / gate-selection claim naming a test file on a non-fenced line")`.

Precision rationale: requiring the vocabulary ON the path-bearing line (not "any tests/ path anywhere") is what keeps §6 test lists, TDD sections, and Reproducibility commands out of the trigger — those are exactly the "simply any tests/ path" over-trigger the brief warns about. The #1536 v2 line ("`tests/test_issue906_marker_mix_budget.py` + `tests/test_issue906_tiny_real_e2e.py` sit on the Step-9c mapped-scan path for sft.py edits") carries both tokens on one line → triggers. Disclosed under-trigger (v1, c38-style): an anchor sentence whose vocabulary sits on the line ABOVE its test list ("These are regression anchors:\n- tests/test_a.py") — fails SAFE (no WARN; the Phase-2 critics remain the backstop). Widen to a ±1 window only after burn-in if the corpus shows this shape dominating.

### 4.4 Satisfaction (design question 2) — oracle = the real selection, imported, not shelled

**Subprocess-vs-import decision: IMPORT, by lazy path-load.** Grounds:
- verify_plan.py has NO existing sibling-script import; its precedents are c34 (lazy `import workflow_lint` via sys.path manipulation? — no: c34 "lazily imports scripts/workflow_lint.py for their size-cap constants" per docstring L12–13) and c37 (source-text read). c40 needs to EXECUTE mapping logic, so a source-regex read (c37-style) is out; an import is the c34 lane.
- A subprocess to the `--map-files` CLI would (a) cost a `uv run` re-resolution (~1–3 s) or require `sys.executable` assumptions, (b) cover ONLY the glob-scan + rules-pin arms — demonstrably empty on the incident shape AND blind to the stem-map/import/invariant arms, forcing a second hand-rolled direct-import grep that duplicates `_import_names`/`touched_module_names` logic and drifts, and (c) be harder to fixture-test.
- `select_tests_with_reasons(touched, work_root)` is pure over its arguments (no git — verified: git lives only in `compute_touched`), stdlib-only to import, fail-soft on broken test files, and IS the Step-9c gate's mapping — zero drift by construction; a future selection arm (like #1496/#1498 were) automatically counts.
- verify_plan must stay usable standalone via `--plan-file`: path-load keyed on `Path(__file__).resolve().parent / "select_step9c_tests.py"` resolves in any checkout of this repo (worktree-correct, the `_C37_LINT_PATH` pattern); absent file (verifier copied off-repo) → loud SKIP.

```python
# Module-level, next to the other c40 constants:
_C40_SELECTOR_PATH = Path(__file__).resolve().parent / "select_step9c_tests.py"  # tests monkeypatch
_C40_REPO_ROOT = Path(__file__).resolve().parent.parent  # tests monkeypatch (c34 pattern)
_c40_selector_cache: list = []  # [module] once loaded; [None] on load failure

def _c40_selector():
    """Lazily path-load scripts/select_step9c_tests.py (stdlib-only import,
    ~ms; NOT registered in sys.modules — the test suite loads its own
    instance and the two must not clobber each other). None => absent /
    unloadable => the caller SKIPs loudly (c37 doctrine)."""
    if not _c40_selector_cache:
        mod = None
        if _C40_SELECTOR_PATH.is_file():
            spec = importlib.util.spec_from_file_location("_c40_step9c_selector", _C40_SELECTOR_PATH)
            mod = importlib.util.module_from_spec(spec)
            spec.loader.exec_module(mod)
        _c40_selector_cache.append(mod)
    return _c40_selector_cache[0]
```

(`import importlib.util` joins the module imports; note the module-global cache is monkeypatch-friendly — tests clear/patch `_c40_selector_cache` or the two `_C40_*` path globals.)

**Touched-file derivation** — generous, over-inclusion is the SAFE polarity here (more touched files → more selection → fewer WARNs; a missed WARN is the acceptable fail-open direction, a false WARN is the failure mode):

```python
# RAW scan (fences INCLUDED — scope lists and commands legitimately live in
# fences/tables; the c11 raw-scan doctrine). tests/ paths are deliberately
# EXCLUDED: every named anchor is itself a mentioned tests/ path, so admitting
# tests/ would make every anchor self-satisfy via the touched-test arm.
_C40_TOUCHED_RE = re.compile(
    r"\b(scripts/[\w./-]+\.py"
    r"|src/explore_persona_space/[\w./-]+\.py"
    r"|\.claude/rules/[\w-]+\.md)\b"      # rules-pin arm inputs (#1496)
)
touched = sorted(set(_C40_TOUCHED_RE.findall(plan)))[:40]  # dedupe + hard bound
```

Degradation (brief's robustness requirement): an EMPTY touched set does not abort — satisfiers (a)/(b) below still adjudicate (the oracle over `touched=[]` at the real repo root still returns the on-disk `WORKFLOW_INVARIANT` set, so invariant anchors satisfy), and the WARN detail appends "no touched code files could be parsed from the plan" so the remedy is obvious. This cannot produce a WARN *storm*: the trigger is same-line + negation-guarded + infra|batch-only, and satisfier (b) (existence gate) still applies.

**Per-anchor satisfaction, cheapest first:**

- **(a) Explicit test command.** RAW-plan scan (fences included — that is where commands live): `re.search(r"pytest[^\n]*" + re.escape(basename), plan)` where `basename = anchor.rsplit("/", 1)[-1]` — covers `uv run pytest tests/test_x.py -x`, `pytest tests/test_x.py::test_y`, `timeout ... uv run pytest ... tests/test_x.py ...`.
- **(b) Existence gate (forward-looking anchors).** `not (_C40_REPO_ROOT / anchor).exists()` → satisfied. A plan-NEW test file cannot be mis-adjudicated at plan time AND is genuinely gate-covered by construction: Step 9c's touched-test arm selects any branch-new `tests/**/test_*.py` in the diff (select_step9c_tests L855–859). This is the c37 existence-gate doctrine ("a flag with no occurrence is a PROPOSED new check — forward-looking, never an offender") transposed; it kills the largest false-positive class (plans naming the tests they are about to write, e.g. this very plan's §6).
- **(c) Gate selection.** For the anchors surviving (a)+(b), ONE oracle call: `tests, _, _ = mod.select_tests_with_reasons(touched, _C40_REPO_ROOT)`; anchor satisfied iff `anchor in tests`. This single call covers: stem-map, glob-scan (= the `--map-files` letter), import-map (= the Goal's "direct-imports a touched module" parenthetical, via the selector's own `_import_names`/`touched_module_names` — no re-implementation), literal-path, rules-pin, and `WORKFLOW_INVARIANT` membership (an invariant anchor is always run by the gate → correctly never WARNed). Wrapped in `try/except Exception → _skip(cid, name, f"Step-9c selection oracle failed ({exc!r}) — anchors cannot be adjudicated")`: verify_plan gates EVERY plan at Phase 1.5.0, so a selector regression must degrade to a loud SKIP naming the breakage (surfaced in briefs), never block fleet-wide planning and never silent-PASS. The selector's own suite keeps the oracle green.
- Selector module absent (`_c40_selector() is None`) → loud SKIP: "Step-9c selection surface unavailable — scripts/select_step9c_tests.py absent (--plan-file off-repo); anchors cannot be adjudicated" (c37 wording).

**Verdict:**
- All anchors satisfied → `_pass(cid, name, f"{n} anchor(s) — each explicitly run, branch-new, or Step-9c-selected from {len(touched)} touched file(s)")`.
- Otherwise → `_warn` naming up to 6 offenders (the c13 display cap), e.g.:

```
plan names tests/test_issue906_marker_mix_budget.py (+1 more) as a regression
anchor / gate-selected test, but the Step-9c selection over the plan's 3
touched file(s) does not pick it up (the selector's import map is one-hop —
#1536 shape) and no pytest command in the plan runs it explicitly. Remedies:
name the exact pytest invocation in the plan, import the touched module
directly from the anchor test, or declare `N/A — no regression anchors` on
its own line, unwrapped (no backticks/quotes)
```
