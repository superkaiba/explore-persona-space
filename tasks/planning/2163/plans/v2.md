# Plan — #2163: Which SAE features are READ at the context vector by the context→answer map

## 0.0 TL;DR (plain English — the user reads this first)

- **What I'll run:** We already have a map that predicts what the model is about to say from its internal state at the moment just before it starts answering. I'll rebuild that map exactly as before (checking it reproduces the old numbers to the decimal), then ask, for every one of the 131,072 interpretable features the sparse autoencoder can see at that moment: does the map actually USE this feature, is the feature merely PRESENT but ignored, or does it only look important because it fires often? Then I'll test which simple, mechanical properties of a feature predict being used, comparing every property fairly against a matched chance level.
- **What I expect:** Genuinely open. Either some property (like how consistently a feature fires, or how big its footprint is) predicts being read beyond what firing frequency alone explains, or the whole "read" ranking collapses into frequency plus noise. I also expect the retroactive check to show that part of the parent's "rare features are predicted worse" trend was mechanical (fewer samples means noisier scores), not real.
- **What would change my mind:** If every property lands inside the chance band once firing frequency is matched, feature-level interpretation of this pre-answer state is a dead end in these coordinates — worth reporting and stopping. If the cheap algebraic read disagrees with the honestly refit map's own coefficients, the cheap read is not trustworthy and only the narrower refit result stands.

### Phase 2 — full-dictionary read ladder on W and M (CPU pod, no fit)

For all 131,072 features, on each map T ∈ {W, M} (E = (W_dec/σ_x[:,None])ᵀ as 131,072×3,584; K_T = P_T·P_Tᵀ):

| DV | exact computation | isolates |
|---|---|---|
| `U_j` | sqrt(rowwise (F·K_T ∘ F).sum(1)), F = E (one GEMM + one elementwise reduce) | per-unit-activation influence — frequency-free |
| `U_j·sd(ψ_last,j)` | sd over the 120,000 train rows (zeros included), from Ψ_last col moments | standardized influence, comparable to the parent's standardized-input coefficients |
| `C_j` | U_j² · mean(ψ_last,j² \| active, holdout) / pooled-target-variance | "when it fires, how hard the map leans on it" |
| `A_j` | exact pooled holdout ΔR²: ΔSSE_j = Σ_x [2·ψ_last,j(x)·⟨r(x), g_j⟩ + ψ_last,j(x)²·U_j²], with ⟨r(x), g_j⟩ = (E·Qᵀ)_j read from Q = R·P_Tᵀ (R = holdout residuals, computed blockwise over output columns; Q is 20,000×3,584) and the ψ-weighted sum as one sparse-dense product Ψ_lastᵀQ | total contribution, frequency-weighted |

The cross-term in ΔSSE_j is real on held-out data and CAN BE NEGATIVE (ablation that improves held-out R²) — reported as its own cell, never clipped. Also reported: the SAE reconstruction residual share of v_C on holdout (‖v_C − decode(ψ_last)‖²/‖v_C − mean‖², pooled), since `U_j`/`A_j` inherit reconstruction error (`‖B[j]‖` in Phase 6 does not — that is why both run). **Null for A_j:** row-pairing permutation — 200 draws; each draw permutes the holdout row pairing between Ψ_last and Q before the sparse-dense product (per-draw same computation, batched by stacking permuted Q blocks — one GEMM family, the `null_battery.perm_null_draws` subset-sum pattern; verified `grep -n 'def perm_null_draws' src/explore_persona_space/analysis/null_battery.py → 337:def perm_null_draws(`). This nulls the ψ-residual alignment while preserving both marginals; the per-draw × per-feature matrix persists (§6).
