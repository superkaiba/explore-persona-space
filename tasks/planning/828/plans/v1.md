## 1. Goal

Subagent spawns for the 28 EPS workflow agents are dying from autocompact thrash: the base system-prompt context (~131K tokens, measured by orchestrator probe) plus the spec body of a heavy agent (~25–34K tokens for the 95–126 KB specs) brings the spawn-time context to ~160–170K tokens. With `model: claude-fable-5` (the full model ID without `[1m]`) the effective context window may be ~200K, and `effort: xhigh` reserves a large extended-reasoning token budget on top of that. A single round of tool results tips the total over the compaction threshold; compaction cannot shrink below base context (131K), so the agent enters a permanent thrash loop: 9–11 tool uses → compaction → death. This killed planners and experiment-implementers in tasks #823 and #825. The fix is to (a) route subagents to Fable 5's native 1M window via the `fable` alias (instead of the potentially short-window `claude-fable-5` full ID), and (b) downgrade `effort: xhigh` to `effort: high` (Fable 5's documented default) so the extended-reasoning budget is not needlessly maximized.

## 4. Design

### Scope (strict per task body)

This task modifies **frontmatter pin lines only** — exactly two keys per agent file: `model:` and `effort:`. No body content, no spec trimming, no new lint checks (those belong to #829).

### The change

**For all 28 files in `.claude/agents/*.md`:**

1. Replace: `model: claude-fable-5` → `model: fable`
2. Replace: `effort: xhigh` → `effort: high`

These are the only two lines touched. The change is implemented as two idempotent `sed -i` sweeps across all 28 files. No per-file exceptions: all 28 agents should have the same uniform policy.

**Why `model: fable` and not B' (delete `model:` line)?**

B' (delete the `model:` line) is the most defensive option and would guarantee inheritance of `claude-fable-5[1m]` from the session. However:
- `model: fable` is the documented canonical alias, is readable, and sets an explicit intent rather than relying on ambient session state.
- If Thomas later changes `settings.json` to a different model, `model: fable` keeps agents on Fable (the right tool for complex reasoning work) rather than silently inheriting something smaller.
- B' is the documented fallback in §7 if the `fable` alias routes to the wrong variant.

**Why not `model: claude-fable-5[1m]`?**

The `[1m]` suffix is NOT a documented valid value for the `model:` frontmatter field. The aliases table lists `sonnet[1m]` and `opus[1m]` but does NOT list `fable[1m]`. Probe 2 showed that even `[1m]` in frontmatter did not take effect. Using an undocumented suffix in frontmatter risks silent failure or falling back to the wrong variant.

**Why `effort: high` and not delete the line?**

- `high` is Fable 5's documented default. Keeping an explicit `effort: high` in frontmatter makes the intended level clear to anyone reading the file.
- The line has no effect when `CLAUDE_CODE_EFFORT_LEVEL=xhigh` is set in the env — it is overridden. But for sessions spawned WITHOUT the env var (e.g., direct `claude` invocations, background cron sessions, future CI contexts), `high` is the correct level.
- Deleting the line is equivalent to `effort: inherit → high` (Fable default), so both approaches achieve the same result; explicit `high` is more legible.

## 11. Decision Rationale

**`model: fable` (replacing `claude-fable-5`)**
- **What:** Use the `fable` canonical model alias instead of the full model ID `claude-fable-5`.
- **Why:** The `fable` alias resolves to Fable 5 with its native 1M context window. The full model ID `claude-fable-5` (without `[1m]`) may route to a variant with a smaller effective context (~200K), which, combined with the 131K base context and heavy spec bodies, drives the compaction thrash. The orchestrator session correctly uses `claude-fable-5[1m]` (confirmed in `~/.claude/settings.json`); subagents need the same window.
- **Source:** orchestrator probe 2026-07-02 (probes 1 and 2, thrash at ~131K + spec); code.claude.com/docs/en/model-config (fable alias = "Uses Claude Fable 5"; Fable 5 has 1M context natively; `fable[1m]` is NOT a documented alias, `claude-fable-5` full ID may differ from `fable` alias resolution).
- **Alternatives considered:**
  - B' (delete `model:` line): agents inherit `claude-fable-5[1m]` from session — maximally safe, but loses explicit intent and coupling to session model. Documented as fallback.
  - `model: claude-fable-5[1m]`: `[1m]` suffix is NOT documented for frontmatter `model:` field (docs list `sonnet[1m]` and `opus[1m]` only; not `fable[1m]`); probe 2 showed [1m] suffix in frontmatter had no effect.
  - Keep `model: claude-fable-5`: known bad — this is exactly the config that caused #823 and #825.

**`effort: high` (replacing `effort: xhigh`)**
- **What:** Change all 28 agent specs from `effort: xhigh` to `effort: high`.
- **Why:** `high` is the documented default effort level for Fable 5. `xhigh` is "deeper reasoning at higher token spend" — a larger extended-reasoning budget reserved per turn. Combined with the tight context, this accelerates compaction onset. The fix reduces per-turn token overhead when `CLAUDE_CODE_EFFORT_LEVEL` is not set to `xhigh` in the environment. (Note: when the env var IS set to `xhigh`, this frontmatter change is overridden — it is harmless in those sessions but documents the intended level for sessions without the env var.)
- **Source:** orchestrator probe 2026-07-02 (diagnosis fact 7 — "xhigh reserves a large thinking budget"); code.claude.com/docs/en/model-config (§ Adjust effort level: "The default effort is `high` on Fable 5"; `xhigh` = "Deeper reasoning at higher token spend. Default on Opus 4.7"; "Frontmatter effort applies when that skill or subagent is active, overriding the session effort level. NOT the environment variable").
- **Alternatives considered:**
  - Delete `effort:` line: equivalent to `effort: inherit → high` (Fable default). Chosen not to, as an explicit `effort: high` is more legible and sets a documented default.
  - Keep `effort: xhigh`: known bad — documented as consuming extra token budget, contributes to the thrash.
  - `effort: medium`: too conservative; `high` is Fable 5's design point for complex reasoning tasks.
