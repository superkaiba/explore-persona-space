## Goal + requirement + acceptance criteria

**Goal (Task #1669 `## Goal` H2, verbatim; no `goal:` frontmatter — kind: infra):** "A watcher-provisioned failover pod must inherit the original launch's environment pins so runs land in the right WandB project / upload destinations."

**Requirement.** A launch dispatched with declared environment pins (e.g. `WANDB_PROJECT=issue1586_methodgen`) must (1) persist those pins into the handle sidecar (`.claude/cache/issue-<N>-handle.json`) at launch time, (2) have every automated failover / fresh-pod re-provision path (`_runspec_from_runpod_handle`, `_runspec_from_gcp_handle`, the #1122 reconnect carry-forward) forward them into the rebuilt `RunSpec.extra`, and (3) have every lane's workload-cmd launcher renderer export them (shell-escaped) BEFORE the existing `WANDB_PROJECT="${WANDB_PROJECT:-issue<N>}"` default line, so the pin wins over the generic per-issue default. Secrets must be impossible to persist by construction (key allowlist). Legacy handles (no `env_pins` key) must reconstruct byte-identically.

## Method delta

Prior related work (#1118/#909) threads *provisioning-shape* fields (disk, RAM, branch) through the handle → failover chain. This task threads a **workload-environment** field for the first time, which adds three things the precedents did not need: (a) a **security allowlist** (env values are persisted to a plain JSON in `.claude/cache/`, quoted into marker `extra`, and — on GCP — baked into instance metadata via the startup script, so secrets must be unrepresentable); (b) a **renderer leg** on all three workload-cmd lanes (export lines inserted before each lane's `WANDB_PROJECT` default, shell-escaped); (c) a **failover-time sanitize-and-warn** (per the #1329 warn-only doctrine — a malformed pin in a hand-edited sidecar must degrade to a logged drop, never a blocked failover).

## Design

New canonical key: `env_pins` — a `dict[str, str]` riding `RunSpec.extra` and `handle.extra`. JSON round-trips verbatim through `serialize_handle`/`deserialize_handle` (same channel as `hydra_args`, `runpod.py:1010-1012` docstring).

### Step 0 — validator + allowlist in `src/explore_persona_space/backends/base.py`

`base.py` is the one module every backend + the CLI + backend_poll already import (avoids a runpod→issue_dispatch circular import).

```python
#: #1669: env-pin key ALLOWLIST — the only keys a launch may persist into the
#: handle sidecar / render into lane launchers. Deliberately an allowlist,
#: never a denylist: the sidecar is plain JSON in .claude/cache/, handle
#: fields ride epm:backend-selected marker extra, and GCP bakes the rendered
#: startup script into instance metadata (readable via `describe`), so a
#: secret pin must be UNREPRESENTABLE, not merely discouraged. Extend by
#: editing this frozenset (code review is the gate).
ENV_PIN_ALLOWED_KEYS: frozenset[str] = frozenset({
    "WANDB_PROJECT", "WANDB_RUN_GROUP", "WANDB_TAGS",
    "EPM_PERSIST_ADAPTER_HF_REPO", "EPM_PERSIST_ADAPTER_SUBFOLDER", "EPM_UPLOAD_MERGED",
})

_ENV_PIN_SECRET_VALUE_RE = re.compile(
    r"(hf_[A-Za-z0-9]{16,}|ghp_[A-Za-z0-9]{16,}|github_pat_|sk-[A-Za-z0-9-]{16,}|AKIA[0-9A-Z]{16})"
)

def validate_env_pins(pins: Mapping[str, object] | None) -> dict[str, str]:
    """Validate + normalize an env-pin mapping; raise ValueError on any violation.

    Rules: key in ENV_PIN_ALLOWED_KEYS; value a non-empty single-line str
    (no NUL, len <= 512) not matching the secret-shaped-value regex
    (belt-and-suspenders against `--env-pin WANDB_PROJECT=$HF_TOKEN`
    shell-expansion accidents). Returns {} for None/empty.
    """
```

## §11 Decision Rationale

`N/A — no training hyperparameters` (no model training; the table below covers design decisions).

- **D1 — Persist pins in the handle sidecar, not env passthrough.** *What:* `env_pins` dict in `handle.extra`. *Why:* the failover relaunch runs in the poller/watcher process whose env is not the original dispatch env, so GCP-style `STARTUP_PASSTHROUGH_ENV_KEYS` passthrough structurally cannot recover the pin; the sidecar is the one artifact every reconstruction path already reads. *Source:* #1118 commit `9a66a7e639` (same channel for boot_disk_gb) + `gcp.py:1117` passthrough semantics. *Alternatives:* re-deriving the project from task frontmatter at failover time (rejected: no canonical per-run project field exists; the plan-declared project is launch-specific).
- **D2 — Explicit `--env-pin` flag; NO auto-capture of the dispatching env.** *What:* repeatable CLI flag, workload-cmd-only. *Why:* deterministic + auditable; the codebase already deliberately rejected ambient WANDB_PROJECT passthrough (`slurm.py:1771-1773`: "an ambient WANDB_PROJECT on the dispatch process would silently cross-route a new issue's metrics"); and in the #1586 incident the dispatch env carried no WANDB_PROJECT anyway — auto-capture would have captured nothing. *Source:* slurm.py:1771-1773 design comment; #1010/#1118 flag-adoption precedent. *Alternatives:* fixed-allowlist env snapshot at dispatch (rejected per the ambient-cross-route hazard).
- **D3 — ALLOWLIST (`ENV_PIN_ALLOWED_KEYS`) rather than a secret denylist.** *What:* frozenset {WANDB_PROJECT, WANDB_RUN_GROUP, WANDB_TAGS, EPM_PERSIST_ADAPTER_HF_REPO, EPM_PERSIST_ADAPTER_SUBFOLDER, EPM_UPLOAD_MERGED} + secret-shaped-value regex. *Why:* the sidecar is plain JSON in `.claude/cache/`, handle fields ride marker `extra`, and the GCP render lands in instance metadata (readable via `describe`) — a denylist fails open on a novel secret name; the allowlist makes the leak class unrepresentable. - **D4 — Sidecar key name `env_pins`; injection site = before each lane's `WANDB_PROJECT:-issue<N>` default.** *What/Why:* the `:-` default-preserving form means an earlier export wins with zero change to the default line — pin-less renders stay byte-identical, and an inline `K=V cmd` prefix in workload_cmd still supersedes for that command (existing lane semantics preserved). *Source:* runpod.py:605 / gcp.py:1475 / slurm.py:1774 (`#601 follow-up r1` exports). *Alternatives:* replacing the default line with the pin (rejected: loses the floor for pin-less launches and breaks byte-identity).
