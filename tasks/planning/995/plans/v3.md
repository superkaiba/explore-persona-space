## 1. Goal + requirement & acceptance criteria

**Goal (task frontmatter):** treat a 404 within ~60s of `batches.create` as retryable with backoff in the batch_judge poller.

**Incident (primary evidence):** #742 `epm:failure` v7 (2026-07-03T22:03:59Z) — the 5th judge-rerun launch died rc=1 on `anthropic.NotFoundError` polling `msgbatch_01U13f9GkuJDz6VTxyzG1Vw9` **67 ms** after its own `batches.create` returned that id; a probe ~1h later confirmed the batch existed server-side (`processing_status=ended`, 10/10 succeeded). Transient read-after-write inconsistency treated as terminal, killing a healthy paid launch.

**Acceptance criteria:**

1. A `NotFoundError` on a batch retrieve issued within a 60s grace window of that batch's own create is retried with bounded backoff at all four sanctioned poll sites (enumerated in §4) — INCLUDING direct `AnthropicBatch.create(...)` → `poll(...)` callers that bypass `__call__` (live case: `scripts/issue658_judge_e0_batch.py` l.177→l.192, the #658/#661 leakage-program line, where today the enclosing `except Exception` (l.206-217) converts an in-window 404 into permanently-checkpointed `shard_incomplete` rows the resume predicate never retries — silent paid-shard loss, worse than #742's loud crash; covered via the create-time memo in §4.2(d), no caller edit needed — reconciler-adjudicated Must-Fix). The #742 shape (404 at 67 ms, batch visible seconds later) completes instead of crashing.
2. A 404 outside the window — including a RESUMED poll of a persisted `batch_id` with NO or STALE create timestamp — stays TERMINAL with exactly one retrieve call (fail-fast preserved). Scope note (reconciler-adjudicated): the "exactly one retrieve call" guarantee applies to the no/stale-timestamp case; an IN-WINDOW api_dispatch resume whose org key was swapped behind the same `sb["org"]` label within 60s of submit (a compound, seconds-scale, operator-induced race) is the already-accepted `api_dispatch.py` l.838-839 residue — the wrong-org 404 is delayed ≤60s then fails loud, never masked (same disposition §4.2(c) grants the org-routing-bug case). Named fail-loud tests: `test_window_expiry_reraises_notfound`, `test_backoff_exhaustion_reraises_notfound`, `test_resumed_poll_404_terminal_single_call` (§4.4 items 3-5).
3. The retry is narrowly scoped: `anthropic.NotFoundError` only, dual-bounded at EVERY graced site including `AnthropicBatch.poll` (window expiry OR attempt-schedule exhaustion), never a blanket except; any other exception propagates unchanged. The grace predicate treats NEGATIVE elapsed (now before created_at — an injected-clock or backwards-clock condition) as OUT of window (`0.0 <= elapsed <= grace_s`), so a wall-clock capture can never vacuously satisfy an injected-clock test.
4. New unit tests pass; `tests/test_issue663_batch_hardening.py` green WITH the pre-authorized clock-prefix padding (the §4.2(a) `created_at = now_fn()` capture consumes one extra tick from that file's finite iterator clocks — pad the affected tests' clock prefixes with one extra `T0`; behavioral assertions byte-unchanged; no other #663 edit authorized); `uv run python scripts/workflow_lint.py` (no-flags default, includes `--check-batch-judge-client`) green; `ruff` green.

## 2. Prior work

- **Incident evidence is primary** (#742 v7, above). It establishes: the lag was 67 ms; the batch did exist; the failure is transient read-after-write, not a missing batch.
- **Anthropic docs:** the errors reference (https://docs.anthropic.com/en/api/errors) documents 404 only as "resource was not found"; neither the create (https://docs.anthropic.com/en/api/creating-message-batches) nor retrieve (https://docs.claude.com/en/api/retrieving-message-batches) batch docs state any read-after-write consistency guarantee for fresh batch ids. A web search found **no official guidance** on this window — so the 60s value cannot be vendor-grounded and is marked accordingly in §11.
- **Installed SDK (verified in-session):** `anthropic==0.88.0`; `anthropic.NotFoundError` exists, MRO `NotFoundError → APIStatusError → APIError`, `status_code: Literal[404]`, constructor `(message, *, response: httpx.Response, body)`. The SDK's built-in retry covers connection errors and 408/409/429/5xx — **not 404** — so no upstream mechanism exists to lean on (implementer re-verifies via `_should_retry` in the installed `anthropic/_base_client.py`).
- **Repo retry precedent:** the transient tuple for sync judge calls is `(APIConnectionError, APITimeoutError, RateLimitError, anthropic.InternalServerError)` (`.claude/rules/code-style.md`). This fix deliberately does NOT add `NotFoundError` to that general tuple — a 404 is retryable only in the create-grace context, never generally.
- **Testability precedent:** `tests/test_issue663_batch_hardening.py` — scriptable client fakes (`FakeBatchClient` / SimpleNamespace `_DeadlineSubmitClient`), injectable `now_fn`/`sleep_fn` iterator clocks. The new tests mirror this exactly.

## 3. Method delta (what changes vs current code)

Current: every `messages.batches.retrieve` in the sanctioned layer lets `NotFoundError` propagate immediately → terminal crash even 67 ms after the same process's own `create` returned the id.

Delta: ONE shared, dual-bounded grace helper at the lowest layer (`llm/anthropic_client.py`), applied to the four **first-poll-loop** retrieve sites, keyed strictly on time-since-create (in-process timestamp, the persisted `sb["submitted_at"]`, or — for `AnthropicBatch` — an instance-scoped create-time memo written by `create` and read by `poll`, which covers direct create→poll callers like `issue658_judge_e0_batch.py` with no caller edit). `api_dispatch` additionally starts persisting `submitted_at` per sub-batch (additive state key). Everything else — final-deadline retrieves, `results()` streams, create-only paths, fleet.py (gains a pointer comment only) — is deliberately unchanged (reasons in §4.3).

## 4. Design

### 4.1 New shared helpers — `src/explore_persona_space/llm/anthropic_client.py` (bottom layer; all three consumers already import from it)

```python
BATCH_CREATE_404_GRACE_S = 60.0                                  # §11 row 1
BATCH_CREATE_404_BACKOFF_S = (1.0, 2.0, 4.0, 8.0, 15.0, 30.0)    # §11 row 2; sum = 60s

def parse_batch_submitted_at(raw: str | None) -> _dt.datetime | None:
    """Parse a persisted sub-batch submitted_at ('%Y-%m-%dT%H:%M:%SZ') to aware UTC; None-safe."""
    if not raw:
        return None
    return _dt.datetime.fromisoformat(raw)   # py3.11 fromisoformat accepts trailing 'Z'

def is_batch_create_grace_404(
    exc: BaseException,
    *,
    created_at: _dt.datetime | None,
    now_fn: "Callable[[], _dt.datetime] | None" = None,
    grace_s: float = BATCH_CREATE_404_GRACE_S,
) -> bool:
    """True iff exc is anthropic.NotFoundError raised within grace_s of created_at.

    created_at=None (unknown create time — a resumed poll of a persisted
    batch_id, or an old state.json) ALWAYS returns False: the 404 stays
    terminal (fail-fast; preserves api_dispatch's wrong-org-404 semantics).
    """
    if not isinstance(exc, anthropic.NotFoundError) or created_at is None:
        return False
    now = (now_fn or (lambda: _dt.datetime.now(_dt.UTC)))()
    elapsed = (now - created_at).total_seconds()
    # 0.0 <= elapsed: negative elapsed (now before created_at — injected test
    # clock, or a backwards wall-clock step) is OUT of window. Production
    # elapsed is >= 0 by construction (in-process capture; the strftime
    # submitted_at truncates DOWN to the second, only inflating elapsed), so
    # this guard costs nothing there and pins the vacuous-True test hazard
    # (statistics-critic Must-Fix).
    return 0.0 <= elapsed <= grace_s

def retrieve_with_create_grace(
    retrieve_fn: "Callable[[], Any]",
    *,
    created_at: _dt.datetime | None,
    batch_id: str | None = None,          # logging only
    now_fn=None,
    sleep_fn=None,
    grace_s: float = BATCH_CREATE_404_GRACE_S,
    backoff_s: tuple[float, ...] = BATCH_CREATE_404_BACKOFF_S,
):
    """Call retrieve_fn(); retry an in-grace-window NotFoundError with bounded backoff.

    DUAL-bounded: re-raises when the grace window has expired OR the backoff
    schedule is exhausted (max len(backoff_s) retries), whichever first. Any
    other exception propagates unchanged. created_at=None disables the grace
    entirely (single call; 404 terminal).
    """
    sleep_fn = sleep_fn or time.sleep
    for delay in (*backoff_s, None):
        try:
            return retrieve_fn()
        except anthropic.NotFoundError as e:
            if delay is None or not is_batch_create_grace_404(
                e, created_at=created_at, now_fn=now_fn, grace_s=grace_s
            ):
                raise
            logger.warning(
                "Batch %s retrieve 404 within %.0fs of create (read-after-write); retrying in %.0fs",
                batch_id or "?", grace_s, delay,
            )
            sleep_fn(delay)
```

Exception class caught: **exactly `anthropic.NotFoundError`** (already imported at module top). No status-code sniffing needed (the class pins 404).

### 4.2 Guarded call sites (four)

**(a) `eval/batch_judge.py::_submit_and_poll_batch`** — the task's named target; identical exposure to the crash site.
- After `batch = client.messages.batches.create(requests=chunk)` (l.311): capture `created_at = now_fn()`.
- l.323 loop retrieve becomes:
  ```python
  batch = retrieve_with_create_grace(
      functools.partial(client.messages.batches.retrieve, batch_id),
      created_at=created_at, batch_id=batch_id, now_fn=now_fn, sleep_fn=sleep_fn,

  ```
  (`functools.partial`, NOT a lambda — ruff selects flake8-bugbear (`B` in pyproject `[tool.ruff.lint]`, `unfixable=["B"]`) and B023 fires on a lambda closing over the loop-reassigned `batch_id` in the chunk loop; fact-check correction. Threads the function's existing injectable `now_fn`/`sleep_fn` seams — l.279-280 — so the new behavior is testable exactly like #663's). Add the `functools` import together with its first use. Extend the existing l.33 import block; signature of `_submit_and_poll_batch` unchanged (the two live callers `scripts/run_experiment_389.py` (l.1537, l.1673) + `scripts/rejudge_issue_389_c_strict.py` (l.272) are untouched).

**(b) `eval/judge_dispatch.py::_poll_one_sub_batch_step`** (l.714) — the ACTUAL #742 crash site. `sb["submitted_at"]` is already persisted at submit (l.636). Add an additive `sleep_fn: "Callable[[float], None] | None" = None` kwarg (default `time.sleep`; no existing sleep_fn kwarg — fact-checked); l.714 becomes:
  ```python
  batch = retrieve_with_create_grace(
      functools.partial(client.messages.batches.retrieve, sb["batch_id"]),
      created_at=parse_batch_submitted_at(sb.get("submitted_at")),
      batch_id=sb["batch_id"], now_fn=now_fn, sleep_fn=sleep_fn,
  )
  ```
  (partial for consistency with site (a); a lambda over `sb` would be B023-safe here — `sb` is a function parameter — but uniformity is cheaper to review.)
  A resumed poll where `submitted_at` is old → window expired → single call, terminal. A resumed poll of a batch submitted <60s before the crash → retried, which is correct (the window is a server-side property, not a process property). Note: this step function is sync and already does a blocking retrieve from the async outer loop; worst-case +60s blocking on the rare 404 is consistent with existing behavior.

**(c) `llm/api_dispatch.py`** — two edits (line refs refreshed per fact-check: `_submit_one_sub_batch` l.871-936 with the finally block at l.926-935; `_poll_one_sub_batch_step` l.939 with the retrieve at l.952; `functools` is NOT yet imported there — add it with first use):
  - `_submit_one_sub_batch`: persist `sb["submitted_at"] = time.strftime("%Y-%m-%dT%H:%M:%SZ", time.gmtime())` inside the existing `finally`-shielded try block, next to `batch_id` (mirrors judge_dispatch l.636). **Backward-compatible state schema**: old `state.json` files lack the key → `.get()` → `None` → no grace → terminal, exactly the desired resume default.
  - `_poll_one_sub_batch_step` (retrieve l.952): add additive `sleep_fn=None` kwarg;
    ```python
    batch = await asyncio.to_thread(
        retrieve_with_create_grace,
        functools.partial(client.messages.batches.retrieve, sb["batch_id"]),
        created_at=parse_batch_submitted_at(sb.get("submitted_at")),
        batch_id=sb["batch_id"], now_fn=now_fn, sleep_fn=sleep_fn,
    )
    ```
    Grace sleeps run inside the to_thread worker — the event loop is never blocked. **Org-mismatch preservation (api_dispatch l.838-839, the `_load_or_init_batch_state` docstring: "a batch created on org B 404s if polled on org A"):** create and poll use the same `sb["org"]` client within a run, so a wrong-org 404 can only arise on resume (where `submitted_at` is stale → terminal, unchanged) or from an org-routing code bug (delayed ≤60s, then still fails loud — never masked).

**(d) `llm/anthropic_client.py::AnthropicBatch.poll`** — REVISED per the methodology reconciler (direct-caller coverage) + the statistics ensemble (dual bound):
  - **Create-time memo (fixes the direct create→poll caller class with zero caller wiring).** `AnthropicBatch.__init__` gains `self._created_at: dict[str, _dt.datetime] = {}`; `AnthropicBatch.create` records `self._created_at[batch.id] = _dt.datetime.now(_dt.UTC)` before returning. `poll` gains additive keyword-only `created_at: _dt.datetime | None = None`; its effective timestamp is `created_at if created_at is not None else self._created_at.get(batch_id)`. So: `scripts/issue658_judge_e0_batch.py` (l.177 create → l.192 poll, same instance) is covered with NO edit to that script; a poll in a NEW process / new instance has no memo → `None` → terminal on first 404 (resume default preserved); an explicit `created_at` kwarg wins over the memo. The memo is instance-scoped and bounded by shards-per-run (tens of entries, strings + datetimes — no growth concern). `__call__` may still pass `created_at` explicitly; with the memo it is equivalent.
  - **Attempt-bounded grace (dual bound at this site too — statistics Must-Fix).** In the loop:
  ```python
  grace_attempts = 0
  ...
  try:
      batch = self.retrieve(batch_id)
  except anthropic.NotFoundError as e:
      effective_created = created_at if created_at is not None else self._created_at.get(batch_id)
      grace_attempts += 1
      if grace_attempts > len(BATCH_CREATE_404_BACKOFF_S) or not is_batch_create_grace_404(
          e, created_at=effective_created, now_fn=now_fn
      ):
          raise
      logger.warning(
          "Batch %s retrieve 404 within create grace (attempt %d, read-after-write suspected); retrying",
          batch_id, grace_attempts,
      )
      await sleep_fn(min(interval_s, 5.0))
      continue
  ```
  (async path uses the predicate + its own async sleep — no blocking sleep in the event loop; DUAL-bounded: window via `now_fn` AND attempt cap `len(BATCH_CREATE_404_BACKOFF_S)` = 6, so a frozen injected clock + always-404 fake can never spin — named test `test_poll_frozen_clock_all_404_bounded`.)
  - **Success-after-retry diagnostic (alternatives-critic concern, all graced sites incl. the sync wrapper):** when a graced retrieve eventually succeeds after ≥1 retry, log ONE INFO with attempts used, elapsed-in-retry, and elapsed-since-create — the only data that could ever ground the 60s constant empirically; retry warnings use neutral "read-after-write suspected" phrasing so a wrong-org code bug is not mislabeled during its ≤60s delay.

### 4.4 Tests — `tests/test_batch_create_404_grace.py` (new file)

Mirrors `tests/test_issue663_batch_hardening.py`'s injectable-clock/fake-client patterns; reuses the shared `FakeBatchClient` fakes where applicable (per that file's "do NOT duplicate" note). Fake 404 built as `anthropic.NotFoundError("not found", response=httpx.Response(404, request=httpx.Request("GET", "https://api.anthropic.com/v1/messages/batches/msgbatch_x")), body=None)` (constructor shape verified against the installed 0.88.0).

1. **Predicate unit:** in-window True; past-window False; `created_at=None` False; non-`NotFoundError` exception False.
2. **Sync wrapper — transient recovery:** retrieve raises 404 twice then succeeds (fresh `created_at`, iterator clock, recorded sleeps) → returns the batch; exactly 3 retrieve calls; sleeps == (1.0, 2.0).
3. **Sync wrapper — window expiry:** clock advances past 60s → re-raises `NotFoundError`; bounded call count.
4. **Sync wrapper — backoff exhaustion (frozen clock):** now_fn never advances, retrieve always 404s → re-raises after exactly `len(backoff_s)+1 = 7` calls (the dual bound).
5. **Sync wrapper — resumed poll:** `created_at=None` → exactly 1 retrieve call, immediate re-raise.
6. **Sync wrapper — other exceptions:** an `anthropic.InternalServerError`-shaped / generic exception propagates on call 1 (no retry).
7. **batch_judge integration:** `_submit_and_poll_batch` with a `_DeadlineSubmitClient`-style fake whose first post-create retrieve 404s then flips to `ended` → returns results (the #742 shape, end to end).
8. **judge_dispatch integration:** `_poll_one_sub_batch_step` with fresh `sb["submitted_at"]` + one 404 → harvested; with `submitted_at` 1h old (or absent) → `NotFoundError` propagates on call 1.
9. **api_dispatch:** `_submit_one_sub_batch` persists `submitted_at` into state.json (read back the atomic write); async `_poll_one_sub_batch_step` (via `asyncio.run`) with fresh `submitted_at` + one 404 → harvested; absent key → propagates.
10. **AnthropicBatch.poll:** `created_at` fresh + retrieve raises 404 once then `in_progress`→`ended` → returns; NO memo entry AND no `created_at` kwarg (fresh instance polling an unknown id — the new-process resume shape) → raises on first 404 (terminal default pinned). Use an ADVANCING iterator clock so an always-404 fake cannot hang the harness.
11. **Create-memo path (`test_create_memo_covers_direct_poll_callers`):** same-instance `create(...)` then `poll(batch_id)` with NO `created_at` kwarg, first retrieve 404s then flips → recovers (the issue658 caller shape, end to end); a SECOND `AnthropicBatch` instance polling the same id with no kwarg → raises on first 404 (memo is instance-scoped).
12. **Site-(d) dual bound (`test_poll_frozen_clock_all_404_bounded`):** frozen `now_fn` + always-404 retrieve + fresh memo → re-raises `NotFoundError` after exactly `len(BATCH_CREATE_404_BACKOFF_S)+1 = 7` retrieve calls (attempt cap binds when the window cannot expire).
13. **Negative-elapsed pin (`test_negative_elapsed_out_of_window`):** predicate with `created_at` in the FUTURE of `now_fn` (negative elapsed) → False; wrapper with such a pair → terminal on first 404. Pins the `0.0 <= elapsed` guard so a wall-clock capture can never vacuously pass an injected-clock integration test.
14. **#663 clock-prefix padding:** the affected `tests/test_issue663_batch_hardening.py` tests (`test_legacy_submit_poll_bounded_when_expires_at_absent` l.165-177, `test_legacy_submit_poll_partial_harvest_on_flip` l.249-260, + any sibling with a finite `now_fn` prefix feeding `_submit_and_poll_batch`) get ONE extra `T0` prepended to their iterator clock prefixes to absorb the §4.2(a) `created_at = now_fn()` read; behavioral assertions byte-unchanged.
