## 3. Design

### 3.1 The park-note token grammar (emitter side — exact)

A park is **mechanically routable** iff its `epm:workflow-fix-candidate` note satisfies ALL of:

1. It is a PARK the existing sweep recognizes (unchanged — `_row_is_parked`, sweep :238–255).
2. It embeds the FORMAL block `<!-- workflow-fix-candidate v1 --> ... <!-- /workflow-fix-candidate -->` with the standard fields (`target_file`, `bug_observed`, `proposed_change`, `diff_sketch`, `confidence`, `related_task`) — this is what makes the fingerprint computable via the sweep's existing `_extract_fields` (:263).
3. The block ADDITIONALLY carries three lines, each `^field: value$` (parsed `re.MULTILINE`, same style as the existing `block_field`):

```
urgency: main-red
failing_test: tests/test_shared_vm_thread_caps.py::test_no_new_torch_before_dotenv_vm_entrypoints
wf_fix: false
```

- `urgency: main-red` — exact token (case-insensitive), the ONLY recognized urgency value in v1.
- `failing_test:` — exactly ONE pytest node id; router-side shape validation `re.fullmatch(r"[\w./\-]+\.py::[\w.\[\],:\-]+", value)` (no whitespace, no shell metacharacters; parametrize brackets allowed). Multiple failing nodes: name the single most representative node here; list the rest in `bug_observed`.
- `wf_fix: true|false` — whether `target_file` is workflow-surface (`true` ⇒ the filed task gets the full wf-fix machinery incl. the recursion-guard Provenance line; `false` ⇒ a plain `kind: infra` fix task, the /daily route-2 `wf_fix: false` analogue — the #1643 case, where targets were experiment scripts).

Any of the three missing/malformed, or no formal block ⇒ NOT mechanically routable ⇒ nightly fallback (R4).

**Emitter duty (who writes this):** the parking session (recursion-guarded workflow-fix session, or an `AUTO_REVIEW_DISABLED` context) SHOULD emit the urgent form whenever it has DIRECT evidence the flagged bug is a currently-failing test on origin/main (typical evidence: its own Step 9c gate just classified the node pre-existing-red against the baseline ledger). Labeling is not routing — the parking session still never files or spawns (R3).

**Pass flow:**

1. **Kill switch** → return.
2. **Cheap candidate gate** (keeps the common tick ~free): glob `tasks/*/*/events.jsonl` + the cache file; keep files with mtime within 48 h; FULL-file substring scan for `urgency: main-red` (case-insensitive). **Deliberately NO read-size cap** — a byte cap on the gate read is exactly the #1287 trap (the arming block could sit past the cap). Zero hits (the overwhelmingly common case) → return.
3. **Authoritative enumeration:** `from sweep_parked_wf_candidates import sweep` (scripts/ is already on the watcher's sys.path via its own bootstrap :717-727; sibling-import precedent: the watcher's own `import session_resolver` :733 — fact-check note: the previously-cited `file_infra_task.py` precedent runs the OTHER direction, file_infra_task imports FROM the watcher); `result = sweep(tasks_root or tasks_dir(), cache_file or default_cache, window_days=2)`. This applies suppression rules 1–3 for free (already-routed urgent parks never re-enter). Filter candidates whose `note` contains the token.
4. Per candidate, episode key `f"{source}|{ts}"`; a latched verdict (`routed`/`deduped`/`refuted`/`not-routable`/`unverifiable`) → skip.
5. `parse_urgent_fields(note)` — `None` → latch `not-routable`, one sidecar row naming the missing field(s), continue (nightly owns it).
6. **Day budget** (`routes_today` vs cap, `_day_scoped_count` pattern): exhausted → sidecar row `cap-exhausted`, NO push, NO latch (re-eligible tomorrow; nightly is the backstop) — the #1241 quiet-at-cap posture, chosen over boot-death's loud-cap deviation because a real backstop exists here.
7. **Verification** `verify_main_red(node)` (≤1 pytest subprocess per TICK; further urgent parks defer to the next tick):
   - *Tier 1 (ledger):* `step9c_baseline.try_load_ledger(PROJECT_ROOT)`; if valid AND `ledger_age_hours(ledger) <= 24` AND the ledger's `refreshed_at` ≥ the park's ts (a ledger refreshed BEFORE the park cannot tier-1-confirm it — the stale-ledger false-confirm window all three critics flagged; older ledger → fall through to tier 2, which reads live truth) AND a `failing_tests` entry matches the node id parsed as (`file` = pre-`::` segment, `name` = LAST `::` segment, `classname` also matched when the node id carries a middle segment — the ledger Node key is (file, classname, name)) → **confirmed** (no subprocess).
   - *Tier 2 (bounded pytest):* list-argv subprocess (never shell):
     `["uv","run","pytest",node,"-q","--no-header","-p","no:cacheprovider"]`, cwd=PROJECT_ROOT, env + thread-caps prefix (`OMP_NUM_THREADS=8 … MALLOC_ARENA_MAX=2`, the code-style shared-VM rule), `timeout=EPM_URGENT_WF_PARK_PYTEST_TIMEOUT_S` (default 180). rc==1 → **confirmed**; rc==0 → **refuted**; ANY other rc / timeout / OSError → **indeterminate** — explicitly including rc=5 (no tests collected: the named node was deleted/renamed, e.g. by the very fix that landed) and rc=2/4 (interrupted / usage error). An `rc != 0 → confirmed` shortcut is the banned implementation (pinned by test 7's rc=5 and rc=2 rows).
   - `refuted` → latch `refuted` + sidecar (park stays enumerated for nightly — the underlying bug may still deserve a route; only the URGENCY is dead). `indeterminate` → increment `attempts`; after 2 attempts latch `unverifiable` + sidecar (nightly owns it).
   - Dry-run: zero subprocess, zero writes — logs what it WOULD verify (the cpu-guard dry-run contract).
8. **Dedup belts** (any hit → post routed-record with `filed_task: n/a (deduped against #<M>)`, latch `deduped`):

   - **Failing-node containment scan:** any NON-terminal `kind: infra` task whose `body.md` contains the exact `failing_test` node id string → duplicate regardless of wording (same node = same red). ## 6. Kill criteria (what outcome means this design is wrong)

- **False-urgent flood:** ≥2 refuted/spurious verifications per day sustained over a week (sidecar audit) ⇒ the declared-token trust model is miscalibrated — disable via kill switch, move verification to a pristine-oracle (step9c `compare`-grade) tier or drop the subclass.
- **Wall-time blowup:** the pass adds >~30 s p50 to COMMON ticks (no urgent parks present) ⇒ the cheap gate is mis-designed — fix or disable.
- **Dedup escape:** any double-filed task pair traced to this router despite the four belts ⇒ the mechanical dedup is insufficient for this subclass — fall back to nightly-only (kill switch) and redesign around the /daily LLM content-dedup.
- **Latency not realized:** if in practice urgent parks keep arriving WITHOUT the three fields (emitters don't adopt the grammar), the mechanism is dead weight — revisit with an emitter-side lint or accept nightly-only.

## 11. Decision Rationale

1. **Detection = declared-at-park token + router-side verification** (over pure post-hoc note inference). Why: a pure-Python router cannot do the /daily three-route LLM classification; a declared grammar makes the subclass mechanically decidable, and verification closes the trust gap. Source: task-body delegation + the sweep's existing formal-block parsing (`_extract_fields`, sweep :263) + #1287 (predicates must be traceable against real artifacts). Alternatives rejected: (iii) note-text inference — fragile, guess-prone, violates R4.
2. **Actor = watcher pass** (over PM STATUS pass / a `daily_drive_filings.py` flag). Why: always-on 10-min cadence meets the minutes-to-~1h Goal; the PM runs only when a session is live — the exact gap #690 closed for orphaned infra filings ("with no PM in the loop, a ripe infra fix orphans indefinitely", file_infra_task.py docstring). Source: #690/#684 precedent; background-automation.md cadence.
3. **Verification = ledger-then-pytest two-tier.** Why: the step9c ledger (#1022) exists precisely to answer "is this node red on main" cheaply; the bounded pytest run covers reds fresher than the ledger. Source: `scripts/step9c_baseline.py` (read this session); bounded-subprocess precedent: completed-unmerged's capped `gh`/`git` probes (#1564).
4. **Day cap = 2/UTC-day, quiet-at-cap.** Why: genuine main-red events are rarer than session wedges (the #1241 lanes use 3/day); 2 covers a same-day pair; at cap a REAL backstop (nightly Step C) still routes — so quiet-at-cap (#1241 posture), not boot-death's loud-cap deviation (whose fallback was silence). Source: #1241 / #1653 / capacity-retry (4/day) cap family.
5. **Enumeration by importing `sweep()`** (over re-implementing park detection). Why: the suppression predicate is subtle, actively under repair (#1680), and duplicating it is the drift the reuse hierarchy bans. Source: CLAUDE.md "Reuse existing in-repo tools"; workflow-fix-on-bug.md § Built-but-stranded fixes; #1680 body (read this session).
6. **Filing via `file_infra_task.py`.** Why: canonical file+dispatch with all spawn gates + backstop. Source: #690.
7. **`wf_fix` declared by the emitter** (over a router-side workflow-surface path classifier). Why: the parking session already knows scope (the #1643 park literally states "OUT of workflow-fix scope"); a Python re-implementation of the surface list would drift. Source: #1643 artifact; § Recursion guard's `wf_fix: false` /daily precedent.
8. **Routed-record carries sweep-fp verbatim + `origin_candidate_ts` + `target_file`.** Why: fp recomputed from abridged text broke suppression on 2026-07-24. Source: #1680 incident (body read this session).
9. **`grep`-free cheap gate with NO byte cap.** Why: a read cap on the arming scan is the #1287 defeat mode (825,591 B artifact vs a 262,144 B cap). Source: #1287.
