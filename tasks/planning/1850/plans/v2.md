## Goal / Requirement

A background watch keyed on a REMOTE artifact landing must wake the session by
its producer's lifetime fence even when the landing never happens; a
long-armed silent `Monitor` until-loop must be distinguishable from a dead
one.

### Acceptance criteria

1. `.claude/skills/issue/SKILL.md` § Long-phase heartbeat duty (Step 6d.2)
   carries a **producer-fence deadline rule** for watches keyed on a remote
   artifact landing: overall deadline = the producer's own lifetime bound
   (GCE `--max-run-duration` fence, pod TTL, Batch-API `expires_at`) + grace;
   on deadline expiry the watch exits DEADLINE and the session RE-CHECKS THE
   PRODUCER (instance/pod status, crash-persist prefixes) — never blind
   re-arms the same landing watch. Cites incident #1738 (session dark
   14:32→17:53Z past the producing GCE instance's poweroff) and the
   batch_judge `expires_at` deadline-bounded-poll precedent (#658/#663) it
   generalizes.

   long-interval `Monitor` until-loop emits a no-op heartbeat line every 2-3

   Monitor is detectable at the next wake from any source by heartbeat
   absence over the expected cadence — re-arm after the kill-before-relaunch
   probe. Cites incident #1739 (~58 min dark after one healthy wake).

## Method delta

Extends the existing § Long-phase heartbeat duty (#1207) — which already
mandates ≤45-min wait segmentation (item 1) and verify-then-heartbeat at each
resume (item 2) — with the two legs the 2026-07-29 incidents exposed:
(a) the duty's per-segment verify presumes the session RESUMES; a watch keyed
on a landing that can never come (producer dead) needs an ABSOLUTE deadline
derived from the producer's fence, and the deadline wake must route to a
producer re-check, not a re-arm; (b) the Monitor tool wakes only on stdout
lines / loop exit, so a healthy-but-quiet Monitor and a dead one are
indistinguishable in-session without periodic heartbeat lines. Rule (a)
generalizes the existing deadline-bounded `batch_judge` poll (bounded on the
batch's own `expires_at`) to all remote-landing watches.

Diff sketch for the SKILL.md insertion (wording refined by the implementer):

```
+ **Remote-landing watches carry a producer-fence deadline (#1850;
+ incidents #1738/#1739, 2026-07-29).** Any watch whose wake condition is a
+ REMOTE artifact landing — an HF file/prefix appearing, a pod/GCE-produced
+ output, a sentinel drained from another box — carries an explicit overall
+ DEADLINE = the producer's own lifetime bound (the GCE `--max-run-duration`
+ fence, the pod TTL, a Batch-API `expires_at`) + ~15-30 min grace, on top of
+ the per-segment ≤45-min cap (item 1): a landing keyed on a dead producer
+ NEVER fires, so without the deadline the watch reads as healthy idle
+ forever (#1738: an until-loop keyed on an HF chunk landing ran silently
+ past the producing GCE instance's ~15:08Z poweroff; no assistant turn
+ 14:32→17:53Z until the watcher respawned). On deadline expiry the watch
+ exits DEADLINE and the session RE-CHECKS THE PRODUCER — instance/pod
+ status (`gcloud … describe` / `pod.py list-ephemeral`), the crash-persist
+ prefixes (`issue<N>_partial/` / `issue<N>_done/`) — and routes to the
+ failure/recovery path; it never blind re-arms the same landing watch.
+ Item 2(i)'s per-resume verify covers the PRODUCER, not merely "the landing
+ has not appeared yet". This generalizes the deadline-bounded `batch_judge`
+ poll (#658/#663), which bounds on the batch's own `expires_at`.
+
+ **Monitor heartbeat emission (#1850).** A long-interval `Monitor`
+ until-loop ADDITIONALLY emits a no-op heartbeat line every 2-3 poll cycles
+ (e.g. `[watch-heartbeat] <UTC time> waiting on <what>` via echo inside the
+ loop) — each stdout line is a notification, so heartbeats WAKE the session
+ at a known cadence, giving item 2's verify-then-heartbeat its resume
+ opportunity mechanically AND making a dead/lost Monitor distinguishable
+ from a healthy quiet one: at any later wake (tick, notification), a
+ heartbeat gap ≳2-3 expected intervals means the Monitor died — re-arm it
+ after the kill-before-relaunch probe
+ (`.claude/rules/crash-fix-rounds.md`), never assume it is still watching
+ (#1739: after one healthy Monitor wake the session idled ~58 min with no
+ wake on a 3-lane GCP run; the watcher stall-alert was the only recovery).
```
