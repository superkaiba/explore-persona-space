## 3. Design

### 3.1 New predicate (concrete edit, `scripts/guard_repo_root_pull.sh`)

**Edit 1 — new ERE constant** (insert after line 67, alongside `PULL_ERE`, which is KEPT for arm 2):

```bash
# Command-position anchor (#1250): the clause LEAD must BE a git invocation
# whose verb is pull — optionally behind env assignments, a CLOSED wrapper
# set, shell compound keywords, bare -flag tokens, and a timeout-style
# duration token. Every prefix unit errs CLOSED (a spurious unit match can
# only ADD a block, never an allow); an unlisted lead word (uv, bash, xargs,
# echo, ...) makes the predicate unmatchable — that is the #1250 fix.
PULL_CMD_ERE='^([A-Za-z_][A-Za-z0-9_]*=[^[:space:]]*[[:space:]]+|(nohup|setsid|sudo|env|time|timeout|command|exec|eval|if|elif|then|else|while|until|do|!)[[:space:]]+|-[^[:space:]]+[[:space:]]+|[0-9]+([.][0-9]+)?[smhd]?[[:space:]]+)*git[[:space:]]+(-[^[:space:]]+([[:space:]]+[^[:space:]]+)?([[:space:]]+|$))*pull([[:space:]]|$)'
```

Prefix unit grammar (closed set, zero-or-more, each self-delimited by whitespace):
- **env assignment** `NAME=value` with an unquoted-token value (covers `GIT_TRACE=1 git pull`; the `EPM_ALLOW_ROOT_PULL=1` prefix is already allowed earlier at line 74 and never reaches classification). A QUOTED-SPACE env value (`NAME="a b" git pull`, e.g. a `GIT_SSH_COMMAND`-style prefix) cannot be consumed by `[^[:space:]]*` — that shape falls open and is folded into the EXPANSION-CHANNEL residual family (documented + pinned via A26's class, §3.4 bullet (b′));
- **wrapper word** `nohup setsid sudo env time timeout command exec eval` — the recommended six + `setsid` (the project's canonical detach pattern is `setsid nohup …`, code-style rule) + `exec`/`eval` (unquoted forms execute directly; the quoted `eval "git pull"` cannot match the anchored `git` and is a documented+pinned residual, A28);
- **shell compound keywords** `if elif then else while until do !` — REQUIRED, not optional: a hand-rolled retry loop `until git pull --rebase; do sleep 5; done` clause-splits to a lead of `until git pull --rebase`, which the current whole-clause scan blocks and a keyword-less anchor would fail OPEN on — and retry loops are precisely the hand-rolled-recovery class the guard exists for (B4's braced form is pinned for the same reason). Pinned MANDATORY as B22 (v2 — was an optional implementer add in v1);
- **bare flag token** `-…` (covers `sudo -n git pull`, `env -i git pull`); NO value-token consumption in the prefix (deliberate: keeps the prefix grammar strictly closed — `sudo -u <user> git pull` / `env -u <NAME> git pull` fall open as documented residuals, pinned A27);
- **duration token** `NUM[.NUM][smhd]` (covers `timeout 300 git pull`; a nonsense lead like `30 git pull` blocks — fail-closed, harmless).

The trailing `git [flags] pull` group is the line-67 idiom verbatim (flag + optional value token, verb terminated by space/EOL — `pull-request` still never matches), with `[[:space:]]+` in place of literal `' +'` (tab-robust; strictly widens the fail-closed side).

**Waived-word leads behind a prefix (documented sub-shape):** a clause like `VAR=1 ssh host '<remote pull>'` has a NON-ssh lead, never enters the waived-word arm, and arm 1 cannot match it — newly fail-open (previously blocked by the whole-clause scan). Accidental-typing probability ~nil (nobody env-prefixes an ssh pod-sync by accident); documented in limitations bullet (b″), same accidents-not-adversaries disposition as the wrapper family. No pin needed beyond the family representative (the class is behaviorally identical to (b): a prefix hides the lead from both arms).

**Edit 2 — per-clause `scanwhole` flag:**
- line 105: add `scanwhole` to the `local` list; reset `scanwhole=0` each iteration (first statement after the `case "$rec"` separator parse, next to the latch reset at line 113).
- line 165 (top of the waived-word case arm `ssh\ * | scp\ * | grep\ * | egrep\ * | fgrep\ * | rg\ *)`): first statement `scanwhole=1`, BEFORE the refusal-condition `if` — i.e. at the shared arm top, NOT inside the ssh sub-branch (B23 pins the grep-family arm-2 route precisely against that mis-scoping). A clause whose waiver SUCCEEDS still `continue`s and never reaches classification; a clause whose waiver is REFUSED (producer position, local expansion, non-/dev/null redirect, ProxyCommand-family token, shared-root spelling) falls through carrying `scanwhole=1`. **This is the B13–B16 preservation mechanism** — the refusal conditions exist because the remote string's quoted content is locally dangerous or root-targeting, so the quoted content is exactly what must stay scannable there; anchoring only ever applies to clauses that were never waiver-eligible.

**Edit 3 — classification block** (replace lines 191–195):

```bash
    if [ "$scanwhole" = 1 ]; then
      printf '%s' "$clause" | grep -qE "$PULL_ERE" || continue
    else
      printf '%s' "$lead" | grep -qE "$PULL_CMD_ERE" || continue
    fi
    case "$clause" in *--ff-only*) continue ;; esac # ff cannot autostash-die/husk/drop
    [ "$latched" = 1 ] && continue
    return 1
```

Arm 1 matches against `$lead` (line 130's whitespace/`{`/`(`-stripped clause — load-bearing for B4's braced recovery segment, whose lead becomes `git pull --rebase=merges --autostash`). ff-only and latch checks unchanged and shared by both arms (A6/A8/A22 and A3–A5 depend on them). The `git -C` waiver (line 189) stays BEFORE classification and unchanged — under the anchored ERE, `git -C "$WT" pull` WOULD match arm 1 (flag+value group consumes `-C "$WT"`), so the pre-classification `-C` waiver remains load-bearing for A1/A2/A17/A20/A21.

Everything else in the file is untouched: escape hatch (74), heredoc allow (79), prefilter (83–84), line-continuation + separator sentinels (88–100), cd-latch (137–149), waiver conditions (166–185), block-and-exit tail (340–357 modulo the message reword below).
