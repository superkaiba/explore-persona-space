### 1. `.claude/rules/gotchas.md` — new bullet (anchor: immediately AFTER the
"Pod git fetch 403 with a VERIFIED-VALID token" entry, currently line ~225 — the

One list item, single line, exact text (implementer may make minimal wording tweaks
but keeps every element — trigger, mechanism, trust-asymmetry clause, incident
numbers, rung ladder, fix-commit-flavor cross-link, historical-ref marker):

> - **In-driver git-ancestry GATES false-fail on shallow pod clones — `git log origin/main..origin/<branch> -- <path>` attributes already-MERGED commits as branch-side because depth-1 truncation hides main's ancestry; make every ancestry gate shallow-aware (merge-base post-filter with the trust asymmetry below, bounded deepen), never fail-open.** RunPod bootstrap clones are depth-1, so ANY in-driver/pod-side ancestry read — a `git log A..B` range, merged-vs-branch-side attribution, a lineage re-assertion over declared dispositions (artifact-reuse check (k)) — sees phantom "fresh branch-side commits", and a fail-CLOSED gate then halts every fresh pod deterministically (#2222 pod-2222 smoke halt, 2026-08-10: ~70 phantom SHAs across the issue-778/issue-1739/issue-825 parent branches; flagged SHA a2b019934e77 IS an ancestor of origin/main; the VM full clone returned exactly the plan's dispositioned SHAs). RECIPE (rung ladder): (1) detect shallowness — `git rev-parse --is-shallow-repository` == `true`; (2) post-filter every flagged SHA with `git merge-base --is-ancestor <sha> origin/main` under the TRUST ASYMMETRY: a POSITIVE (exit 0) is trustworthy even on a shallow clone (grafts only remove parent edges) ⇒ already merged, DROP it from the branch-side set; a NEGATIVE (exit 1) on a still-shallow history is UNTRUSTED — ancestry may be cut at the graft (verified: at depth 1 a fully-merged commit returns exit 1, so the post-filter alone drops NOTHING there); (3) flagged SHAs that survive the post-filter while the repo is still shallow are UNDECIDABLE ⇒ deepen BOUNDED — `git fetch --deepen=200 origin main <branch>` — then re-run the range + post-filter; escalate `git fetch --unshallow --filter=blob:none` (plain `--unshallow` if the filtered form is refused) only if still shallow-undecidable; (4) full-clone behavior unchanged (every rung is a no-op there — never weaken the gate to accommodate shallow venues); (5) never fail-open — a SHA that survives on a FULL history is genuinely branch-side and FAILs the gate, and a gate that cannot reach a full-history read FAILs with the shallow diagnosis in the message rather than passing. Sibling of the fix-COMMIT flavor (#779: `git log -1 -- <script>` attributes every path to the depth-1 boundary commit ⇒ verify fix commits by CONTENT hash; `.claude/agent-memory/experimenter/feedback_shallow_clone_fix_commit_verification.md`) — this entry covers ancestry GATES, where the failure is phantom branch-side attribution, not wrong single-path attribution. Reference impl: #2222's fixed `reassert_parent_lineage` (`scripts/issue2222_stage.py`, branch issue-2222) + its unit test. <!-- lint: historical-ref -->
