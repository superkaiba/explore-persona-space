## 3. Design

### 3.1 Detection (design question 1)

**A cheap explicit probe, not try/except message-matching.** New helper `_off_main_checkout_root() -> Path | None`:

- Resolve the PRIMARY checkout via `task_workflow.primary_checkout_root()` (no branch guard). On `RuntimeError` (git missing / bad layout / no `tasks/`) return `None` — the downstream `repo_root()` call then raises today's loud error unchanged (nothing swallowed; the error surfaces at the same site with the same message).
- Read the primary checkout's branch with a new `_checkout_branch(checkout: Path) -> str | None` (`git -C <checkout> symbolic-ref --short HEAD`, `check=False`, `timeout=30`; rc≠0 / empty / OSError / timeout → `None` = detached-or-unreadable).
- `branch is None or branch == "main"` → `None` (normal path; a detached primary keeps today's loud `repo_root()` "HEAD is detached" RuntimeError).
- `is_shared_vm_env()` True → print a loud stderr WARNING ("primary checkout on '<branch>' on the SHARED VM — refusing the #924 off-main degrade; the consumer gate must not be skipped on a shared tasks/ tree") and return `None` — the pathological VM-off-main state keeps today's behavior exactly.
- Otherwise → return the primary checkout path (the clone root).

Decorate with `@functools.lru_cache(maxsize=1)` (same pattern as `task_workflow.py:324/559`); tests use `.cache_clear()`.

Why this beats the two alternatives (also §11):

- *try/except the specific RuntimeError at each site*: brittle string/type matching across 5 scattered sites, AND blind to the full-clone shape where `repo_root()` does not raise but silently routes to a `_task-main-pin` worktree with an empty `data/` (wrong-root silent no-op + a `git worktree add` mutation on the remote instance). The probe classifies both shapes correctly before any resolution runs.
- *`Path(__file__).resolve().parents[1]` / `git rev-parse --show-toplevel` from the script's own dir*: misclassifies VM worktree invocations — a run launched from `.claude/worktrees/issue-<N>/` executes the worktree's `scripts/` copy on branch `issue-<N>`, but its git COMMON dir parent is the repo root on `main`; the common-dir-based `primary_checkout_root()` resolves that correctly (per the gotchas "`--show-toplevel` returns the WORKTREE root" entry), a `__file__`/toplevel approach would wrongly degrade the VM path.

### 3.2 Root resolution off-main (design question 2)

New helper:

```python
def _resolution_root() -> Path:
    """repo_root() on the primary-on-main VM; the checkout root on an off-main remote clone (#924)."""
```

```python
def _checkout_branch(checkout: Path) -> str | None:
    """Attached branch name of ``checkout``'s HEAD, or None (detached / unreadable)."""
    try:
        proc = subprocess.run(
            ["git", "-C", str(checkout), "symbolic-ref", "--short", "HEAD"],
            capture_output=True, text=True, check=False, timeout=30,
        )
    except (OSError, subprocess.TimeoutExpired):
        return None
    if proc.returncode != 0:
        return None
    return proc.stdout.strip() or None


@functools.lru_cache(maxsize=1)
def _off_main_checkout_root() -> Path | None:
    """Root of a NON-main remote checkout (GCE/pod issue-branch clone), else None (#924).

    None  => normal path: every resolution goes through task_workflow.repo_root().
    Path  => degrade gracefully: data/, the worktree scan root, the sidecar, and
             display names resolve against THIS checkout; the cross-task
             active-consumer read is skipped (tasks_dir() needs a main checkout).

    Detection reads the PRIMARY checkout (git common-dir parent, NOT the script's
    own dir — a VM worktree invocation must still resolve the repo root). The
    SHARED VM never degrades (is_shared_vm_env() conjunct): a pathologically
    off-main VM keeps today's loud repo_root() behavior rather than silently
    skipping the consumer gate on a shared tasks/ tree. Detached HEAD or an
    unresolvable layout also returns None (repo_root() then raises its own
    loud, unchanged error).
    """
    try:
        primary = primary_checkout_root()
    except RuntimeError:
        return None  # unresolvable layout: let repo_root() raise its own loud error
    branch = _checkout_branch(primary)
    if branch is None or branch == "main":
        return None
    if is_shared_vm_env():
        print(
            f"  WARNING: primary checkout {primary} is on {branch!r} on the SHARED VM — "
            f"refusing the #924 off-main degrade (the active-consumer gate must not be "
            f"skipped on a shared tasks/ tree); falling through to repo_root().",
            file=sys.stderr,
        )
        return None
    return primary


def _resolution_root() -> Path:
    """repo_root() on the primary-on-main VM; the checkout root off-main (#924)."""
    off = _off_main_checkout_root()
    return off if off is not None else repo_root()
```

## 11. Decision Rationale

1. **Detection = `primary_checkout_root()` + attached-branch probe (not per-site try/except).** *Why:* one classification point covers all 5 sites AND both remote-clone shapes — the observed raise shape (`--depth 1 --branch` clone, no local `main`; `backends/gcp.py:1820` + the #841 traceback) and the latent full-clone shape where `repo_root()` silently routes to an empty-`data/` pin worktree (a wrong-root no-op + a `git worktree add` mutation) instead of raising. Exception-message matching at 5 sites is brittle and blind to the second shape. *Source:* `task_workflow.py:539-576` (read this session); `backends/gcp.py:1820`; #841 att-6 traceback in the task body. *Alternatives rejected:* per-site `except RuntimeError` (brittle, misses routing shape); `__file__`/`--show-toplevel` (misclassifies VM worktree invocations — gotchas "worktree `--show-toplevel`" entry + `_resolve_primary_checkout`'s module-dir common-dir resolution).
2. **Shared-VM refusal conjunct via `is_shared_vm_env()`.** *Why:* the "empty protected set is safe" argument holds ONLY on a single-task remote instance; on the shared VM an off-main primary is a pathological state where skipping the consumer gate could reap a sibling's declared inputs — keep today's loud behavior there. *Source:* `orchestrate/env.py:118-139` (#847 positive detection, fails open on GCE/pods); task-body constraint wording ("on a single-task remote instance there are no sibling consumers").
3. **SKIP (not stale-read) for the consumer gate off-main.** *Why:* the clone's `tasks/` tree is frozen at clone time (`--depth 1`), so statuses are stale — reading it would manufacture false protection or false confidence; the declared skip with WARN + sidecar row is honest and matches the fail-loud rule. *Source:* task-body constraint; `#773` gate semantics (`clean_experiment_downloads.py:517-586`).
4. **LOCAL-RESOLVE (not no-op) for data/worktree/sidecar/display roots.** *Why:* GCE clones hold real reap-worthy caches on the boot disk (clarifier fact 4: `/workspace/eps-issue-841/data/issue_841/hf_dl`); a blanket no-op (the #803 pod answer) defeats the between-phase disk-hygiene Goal — the #841 incident is precisely peak-footprint pressure.
