# Plan — Task #1182: Tick-scoped memoization of `_resolve_transcript_via_happy_log`

## 0.0 TL;DR (plain English)

- **What I'll change:** the fleet watcher currently re-reads the same Happy log file (a full-file read, ~160 ms per session) up to twice per 10-minute tick, once per pass, for the same session. I'll add a small opt-in cache inside the resolver so the second lookup within one tick is free, and wire the watcher's tick to use it.
- **What I expect:** the second resolution of the same pid inside one tick becomes a dict hit; nothing else changes — every other script that uses the resolver behaves byte-identically because the cache is off unless explicitly scoped.
- **What would change my mind:** if the two watcher call sites ran in separate processes (they don't — verified: one cron-fired process per tick under a flock), or if any consumer needed a mid-tick re-resolution of the same pid (none does — all three consumers fail toward "keep" on a miss and stat/open the transcript themselves afterward).

## 0. Plan Summary (technical)

**Change:** add an opt-in, tick-scoped memo for `session_resolver._resolve_transcript_via_happy_log(node_pid)` — a module-level `_TRANSCRIPT_MEMO: dict[int, tuple[str | None, str | None]] | None` (None = caching OFF, the default) plus a `transcript_resolution_scope()` `@contextmanager` that installs a fresh dict on entry and restores the previous value on exit. The existing function body moves verbatim to `_resolve_transcript_via_happy_log_uncached`; the public underscore name becomes a ~7-line memo shim (preserving the monkeypatch seam existing tests use). The watcher's `main()` is decorated with `@session_resolver.transcript_resolution_scope()` — one added line; cache lifetime == exactly one `main()` invocation == one tick (the watcher is a cron-fired one-shot process, single-flighted by `watch.lock`). Positive AND negative results are cached. **No behavior change for any consumer outside the scope** (`tmux_window_titles.py`, `eps_sessions.py`, `session_summarize.py`, `spawn_session.py`, and bare `session_resolver` CLI use are untouched). **Baseline/controls:** N/A — infra code change. **Compute:** 0 GPU-h, VM-local pytest only.

## 2. Method delta (current vs new)

**Current:** `scripts/session_resolver.py:382` `_resolve_transcript_via_happy_log(node_pid)` performs, on every call: a `HAPPY_LOGS_DIR` iterdir + stat walk (`_find_happy_log_for_node`, :283) then a **full-file `log_path.read_text()`** of the matched Happy log (:388) — the ~160 ms/session dominant term. Within ONE watcher tick it is invoked once per probed session per pass from two independent call sites:

- `scripts/autonomous_session_watch.py:9039` — `_transcript_tail_rows(pid)` (the #1127 prompt-wedge probe; runs EVERY tick per registered entry via the stalled-session pass, `main()` :19323).
- `scripts/autonomous_session_watch.py:16651` — `_transcript_idle_age_s(pid)`, called from BOTH `_process_stale_registration` (:17617, stale-registration pass over `issue-*.json` + `manual-issue-*.json`, `main()` :19451) and `_process_idle_unmapped` (:17246, idle-unmapped pass over unmapped live sessions, `main()` :19475).

A REGISTERED session's pid is therefore resolved up to **2×/tick** (wedge probe + stale-registration) — identical work, identical result. (The filed body cites call sites :8654/:16266; they have drifted to :9039/:16651.) Internal consumer: `resolve_transcript` (`session_resolver.py:445`) calls it as its first leg; the watcher deliberately never uses `resolve_transcript` (fs-fallback ban, pinned by `tests/test_autonomous_session_watch.py:9518`), but placing the memo at the `_resolve_transcript_via_happy_log` level covers direct AND indirect callers alike.

**New:** same resolution logic, executed at most once per distinct pid per tick; every repeat within the tick is a dict lookup. Zero signature changes anywhere; one decorator line on `main()`.

### Diff sketch — `scripts/session_resolver.py` (near :382)

```python
# ── tick-scoped transcript-resolution memo (#1182) ─────────────────────────
# None => caching OFF (the default: every consumer outside an explicit scope
# is byte-identical to pre-#1182 behavior). A fresh dict is installed ONLY
# for the duration of a transcript_resolution_scope() — one watcher tick —
# and dropped on exit, so a cached (transcript, reason) can never survive
# across ticks (transcripts move between ticks; the task-body hard
# constraint). Main-thread-only by contract: the global is unguarded; the
# watcher's sole worker thread (vm-disk-hf-reclaim) never calls this module.
_TRANSCRIPT_MEMO: dict[int, tuple[str | None, str | None]] | None = None


@contextlib.contextmanager
def transcript_resolution_scope():
    """Memoize ``_resolve_transcript_via_happy_log`` per node pid for the
    duration of the scope — one watcher tick (#1182). Positive AND negative
    results are cached (the miss walk is the expensive part; every watcher
    consumer fails toward keep/no-fire on a miss, so a within-tick frozen
    miss defers action by at most one 10-min tick — inside the watcher's
    existing 2-miss debounce granularity). Re-entrant: restores the previous
    memo on exit. Usable as a decorator (``@transcript_resolution_scope()``)
    — each decorated CALL gets a fresh memo. NEVER hold a scope across loop
    iterations in a long-lived process."""
    global _TRANSCRIPT_MEMO
    prev = _TRANSCRIPT_MEMO
    _TRANSCRIPT_MEMO = {}
    try:
        yield
    finally:
        _TRANSCRIPT_MEMO = prev


def _resolve_transcript_via_happy_log(node_pid: int) -> tuple[str | None, str | None]:
    """Try the happy-log path. Returns (transcript_path, reason_on_miss).
    Memoized per node_pid while a transcript_resolution_scope() is active;
    uncached (byte-identical legacy behavior) otherwise."""
    memo = _TRANSCRIPT_MEMO
    if memo is not None and node_pid in memo:
        return memo[node_pid]
    result = _resolve_transcript_via_happy_log_uncached(node_pid)
    if memo is not None:
        memo[node_pid] = result
    return result
```

### Where created / invalidated / keyed / what is cached

- **Created:** fresh `{}` at every entry into `transcript_resolution_scope()` — i.e. at each watcher `main()` call (the decorator recreates the context manager per call via `ContextDecorator._recreate_cm`, stdlib-documented).
- **Invalidated/scoped:** restored to the previous value (normally `None`) in the `finally` on scope exit — exception-safe; in production the one-shot cron process additionally dies at tick end. The `--*-only` early-return paths (:19101–:19172) sit inside the scope but never resolve transcripts — the scope is inert there.
- **Keyed:** `node_pid` (`int`) — the function's sole parameter. `_transcript_tail_rows`' `max_bytes` applies to reading the *transcript*, not the resolution, so it is not part of the key.
- **Cached value:** the full `(transcript_path | None, reason_on_miss | None)` tuple — positives and negatives (§11.4).
- **Thread safety:** plain unguarded module global. Verified main-thread-only: the watcher's only worker thread (`vm-disk-hf-reclaim`, `autonomous_session_watch.py:6979`) touches only the HF hub cache (`_scan_and_evict`, :6952–:6977) and never calls `session_resolver`. Contract documented in the docstring; a future threaded consumer must not share a scope across threads.

## 11. Decision Rationale

1. **Cache placement — `session_resolver`-level, inside the `_resolve_transcript_via_happy_log` shim (body option (b), not (a)).** *Why:* covers both direct watcher call sites AND the indirect `resolve_transcript` (:445) path with ZERO signature changes; option (a) (a dict threaded from `main()` to the passes) would touch ≥6 signatures across the stalled machinery (`stalled_session_pass` → wedge escalation → `_transcript_tail_rows`), `_process_stale_registration`, and `_process_idle_unmapped` plus all their tests — invasive for a surgical fix. *Source:* call-graph reading — `autonomous_session_watch.py:9039/:10142/:16651/:17246/:17617`, `session_resolver.py:445`. *Alternatives:* option (a) (rejected: diff breadth); caching inside the two watcher helpers separately (rejected: loses cross-call-site dedup, the Goal).
2. **Lifetime mechanism — opt-in `@contextmanager` scope, applied as a decorator on watcher `main()`.** *Why:* cache lifetime == exactly one `main()` invocation == one tick, even for in-process test invocations (fresh cm per call); exception-safe via `finally`; default-OFF preserves library semantics for every other consumer; avoids both the banned process-lifetime `lru_cache` AND the always-on-dict-with-caller-`invalidate()` variant, which is de-facto process-lifetime for any consumer that never calls invalidate. The one-line decorator also avoids a ~315-line whitespace re-indent of `main()`'s flat pass ladder. *Source:* `main()` :18997–:19488 (one-shot, flat, single terminal return), `_acquire_lock` :5785, cron spec in `.claude/rules/background-automation.md`; stdlib `ContextDecorator`/`_recreate_cm` semantics. *Alternatives:* explicit `with` + re-indent (approved fallback); `enable()/invalidate()` pair (rejected: leaks an enabled memo across in-process `main()` returns on exception paths → test pollution).
3. **Keying — `node_pid` alone.** *Why:* the function's only parameter; results depend on nothing else at fixed time-within-tick. *Alternatives:* none sensible.
4. **Negative-result caching — YES.** *Why:* the miss classes still pay the expensive walk (HAPPY_LOGS_DIR iterdir/stat; "transcript missing on disk" additionally pays the full `read_text()`), and the #665-class stale sessions — exactly the pids probed by multiple passes — resolve to misses; all consumers fail toward keep/no-fire on a miss, so a within-tick frozen miss defers action ≤1 tick, inside the watcher's existing ≥2-miss debounce granularity. *Source:* `_resolve_transcript_via_happy_log` body :383–:399; `decide_idle_unmapped` :16683; `_process_stale_registration` :17618. *Alternatives:* positive-only caching (rejected: leaves the dominant repeated cost in place for the miss class).
5. **Thread safety — plain unguarded global.** *Why:* verified main-thread-only usage (the sole worker thread, `vm-disk-hf-reclaim` :6979, never calls the resolver); a lock would suggest a cross-thread contract this module does not offer. *Source:* threading grep + `_scan_and_evict` :6952–:6977 read. *Alternatives:* `threading.local` (rejected: implies multi-thread support that doesn't exist; complicates tests).
6. **Seam preservation — shim keeps the public name; body moves to `_uncached`.** *Why:* 4 existing test sites patch/call `session_resolver._resolve_transcript_via_happy_log`; keeping the name means zero existing-test edits and gives new tests a clean counting seam one level down. *Source:* `tests/test_autonomous_session_watch.py:9531-9548`, `tests/test_session_resolver.py:192-215`.
