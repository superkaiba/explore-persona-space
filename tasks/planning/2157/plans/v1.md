## Decision: pod.py `--boot-disk-gb` alias — REJECTED (considered per the body)

An argparse alias (`--boot-disk-gb` → `container_disk_gb`) would fail-soft the
router phrasing on the pod path, but creates a NEW semantic trap on GPU pods:
"boot disk" (GCE semantics: the whole workload disk) would map to the container
OVERLAY disk, not the `/workspace` volume where GPU workloads actually write — a
composer sizing "the disk" via the alias on a GPU pod would size the wrong disk
and still ENOSPC. The doc split removes the confusion at its source without
introducing that trap, and keeps the fix zero-code.
