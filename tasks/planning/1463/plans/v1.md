### D2 — Mask pre-pass candidate head (guard:671–757; Q2 answer: YES, in scope)

The waiver-only extension does NOT close the incident class: real gcloud payloads are multi-statement (`cd … && git …`, newline-separated recipes), and the quoted-separator mis-split strands the fenced verb in a tail clause that classifies (this is precisely how the #825 block fired — §12 trace). So the mask gains a second candidate head with the **identical** R1–R8 predicate and the **identical** separator-only rewrite:

```awk
# guard:684, was: if (atstart && substr(s, i, 4) ~ /^ssh[ \t]/) {
headlen = 0
if (atstart) {
  if (substr(s, i, 4) ~ /^ssh[ \t]/) headlen = 4
  else if (match(substr(s, i),
      /^(timeout[ \t]+[0-9]+(\.[0-9]+)?[smhd]?[ \t]+)?gcloud[ \t]+compute[ \t]+ssh[ \t]/)) headlen = RLENGTH
}
if (headlen > 0) {
  j = i + headlen           # option/host charset scan proceeds unchanged from here
  ...                        # quote parse, R1 tail, R2-R8 checks, gsub — all byte-unchanged
  # REFUSAL path generalizes "ssh"/i+=3: copy substr(s, i, headlen') for the head
  # word(s) with atstart=0, fall to the char path — output byte-identical to input.
}
```

Notes grounding this: (a) the existing option/host charset `[A-Za-z0-9_.@:%=+,\/ \t-]` already covers every observed gcloud flag spelling (`--zone=us-central1-c`, `--zone us-central1-a`, `--configuration=eps-gcp`, `--internal-ip`, `user@instance`) — verified against all three real #825 gcloud commands; the scan stops at the `--command` payload's opening single quote exactly as for ssh. (b) The pre-pass ordering (continuation-join guard:500 → heredoc-strip guard:615 → mask guard:758 → split guard:1386) means in-payload backslash-newline continuations are already normalized before the mask sees them. (c) **Monotonicity is preserved fail-closed:** the R-arms remain a superset of the ladder refusals for the gcloud head; if the mask and waiver head regexes ever drifted, a mask-accepted-but-ladder-refused merged clause still carries its original git-verb text and CLASSIFIES → false block, never a leak. (d) The rewrite stays separator-substitution-only (`gsub(/[;&|\n]+/ …)`); **in-payload `<`/`>` are NOT masked** — R2 keeps refusing them, preserving raw-scan parity for redirect-carrying payloads exactly as the ssh arm accepted (remediation: bound output with `| tail` / `|& tail` inside the payload — pipes/amps DO mask — or use `git -C` per GS8). Extending the rewrite beyond separators would breach #1413's stated "ONLY rewrite" invariant (guard:727–728) and re-litigate the #796 class; rejected in §11 entry 6.

## 11. Decision Rationale

1. **Waiver head = literal `gcloud compute ssh` word sequence, start-anchored.** Why: mid-clause/wrapped words must never waive (cond (1) discipline). Source: guard:1264–1270; incident head shape (§12).
2. **Route gcloud through the ssh refusal branch (proxy tokens + repo-path spellings), not a new branch.** Why: gcloud is "a thin wrapper around ssh(1)" and forwards `--ssh-flag`/`-- SSH_ARGS` to local ssh — identical local-exec channels. Source: SDK 576.0.0 `--help` (§2); guard:1334–1345.
3. **`timeout <num>[.frac][smhd]?` wrapper tolerance, gcloud-arm only.** Why: all 3 real #825 gcloud invocations were timeout-wrapped (GCE ssh hangs are routine), so without it the class stays practically open; the literal-word + literal-numeric form is provably locality-preserving; extending to ssh would flip pinned N12 and widen the diff for zero incident demand. Source: incident transcript (§12); tests/test_guard_repo_root_branch.py:1315 (N12); "smallest diff" brief constraint.
4. **Both `--command=V` and `--command V` forms covered with no flag parse.** Why: the waiver is a clause-level grep by design; both forms are SDK-legal and observed in #825. Source: guard:1364 design; SDK help; #825 commands (both spellings observed).
5. **Mask extension reuses the R1–R8 predicate + separator-only gsub verbatim.** Why: monotonicity invariant (mask-accept ⊆ ladder-waive) is the #1413 safety argument; identical arms keep it valid for the new head. Source: guard:630–668, 727–728 (`a87f5898f6`).
6. **No in-payload `<`/`>` masking (R2/cond 3b kept verbatim).** Why: relaxing it breaches #1413's "only rewrite is separator substitution" invariant and the raw scan's redirect-locality ambiguity — the same reasoning class as the #796 revert; the residual has a cheap remediation (`| tail`/`|& tail` inside the payload, or `git -C` per GS8). Source: guard:1306–1333, guard:123–130.
7. **Release tracks + non-timeout wrappers excluded.** Why: fail-closed prime constraint; each exclusion has a one-token remediation (drop `beta`, drop `nohup`). Source: N12 precedent; brief constraint.
8. **New registry entry (xix), not an (xiv) edit.** Why: one numbered entry per arm keeps the registry auditable; (xiv) stays the ssh arm's record. Source: registry convention guard:146–409 (#1058→#1234 lineage).
9. **Heredoc/prose residual out of scope.** Why/Source: §3.D5 — #796 revert precedent (guard:123–130), documented `--file`/`-F` remediation (guard:94–95, 1401), untraced motivating sub-incident.
