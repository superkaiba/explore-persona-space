### 4.1 New helper: `scripts/verify_carryover_inputs.py` (stdlib-only — `re`, `argparse`, `subprocess`, `pathlib`, `dataclasses`, `json`)

Stdlib-only so the tmp-git-repo tests need no package import and the helper has no coupling to `task_workflow`'s branch guard. Repo root defaults to the parent of `git rev-parse --path-format=absolute --git-common-dir` (worktree-safe), overridable with `--repo-root` for tests.

```python
#!/usr/bin/env python3
"""Verify plan-referenced LOCAL repo inputs are reachable in the git tree a
clone lane will materialize (#1469; the #734/#1434 class).

The Step 6a.5 first stanza (hub.verify_artifacts_exist) covers HF/WandB URLs
only. Every compute lane boots from a git materialization of the PUSHED
dispatch ref (GCE: `git clone --depth 1 --branch issue-<N>`; RunPod
bootstrap: init+fetch+reset; SLURM: materialize_branch_src), so a plan-cited
eval_results/ file that exists only on the VM — untracked, or committed but
unpushed — is guaranteed absent from the lane's tree.

Exit codes: 0 = PASS (warns allowed), 1 = >=1 FAIL, 2 = usage / plan unreadable.
"""

# Candidate extraction. Lookbehind excludes word chars, '/', '-', '.' so
# `explore-persona-space-data/issue.../f.json` (HF data-repo paths) and URL
# segments never match; `ood_eval_results` is its own alternative (the
# `eval_results` alternative cannot fire inside it — '_' is \w).
_PATH_RE = re.compile(
    r"(?<![\w/\-.])"
    r"(?P<path>(?:eval_results|ood_eval_results|data)/"
    r"[A-Za-z0-9][\w.\-/*?\[\]{}<>]*)"
)
_GLOB_CHARS = set("*?[]{}<>$")
_TRAIL_PUNCT = ".,;:!?)'\"`"

def extract_candidate_paths(text: str) -> list[dict]:
    """Ordered, de-duplicated candidates; each {'path', 'skip_reason'|None}.

    Skip reasons (never block): 'glob-or-template' (any char in _GLOB_CHARS),
    'dir' (trailing '/'), 'no-ext' (basename without '.'; a slashless dir
    citation). Trailing prose punctuation is rstripped BEFORE classification.
    """

def resolve_check_ref(repo_root: Path, issue: int, *, fetch: bool = True) -> str:
    """`origin/issue-<N>` if it verifies, else `origin/main`.

    When fetch=True, first run bounded `git fetch origin --quiet --no-tags
    <ref>` for issue-<N> and main, each `|| true` (fail-open to possibly-stale
    refs; staleness biases toward the committed-unpushed FAIL, whose
    remediation — push + re-run — self-heals it). `--no-fetch` for tests.
    """

def path_in_ref(repo_root: Path, ref: str, path: str) -> bool:
    """`git cat-file -e {ref}:{path}` rc==0. Works for any ref incl. local
    branch names; used for both the pushed ref and the local issue-<N> tip."""

def exists_locally(repo_root: Path, issue: int, path: str) -> bool:
    """(repo_root/path).exists() or any((wt/path).exists() for wt in
    repo_root.glob(f'.claude/worktrees/issue-{issue}*')) — the #1434 file
    class can live in the issue worktree rather than the root tree."""

@dataclasses.dataclass
class Finding:
    path: str
    verdict: str   # 'pass' | 'fail' | 'warn' | 'skip'
    reason: str    # see table below
    detail: str = ""

def classify(cand, *, repo_root, issue, ref) -> Finding: ...
def main(argv=None) -> int: ...
# CLI: --plan <path> --issue <N> [--repo-root <p>] [--ref <r>] [--no-fetch] [--json]
```

**Classification table** (`cls` = `data` for `data/...` paths, `tracked-results` for `eval_results/` + `ood_eval_results/`):

| exists_locally | in pushed ref | cls | verdict / reason |
|---|---|---|---|
| any | yes | any | `pass` / `in-ref` |
| yes | no | tracked-results | in local `issue-<N>` tip → **`fail` / `committed-unpushed`** (detail: "push the branch and re-run"); else → **`fail` / `untracked-local-only`** (the #1434 case; detail: "git add + commit + push on issue-<N>, cf. f9f1002797") |
| yes | no | data | `warn` / `data-local-only` (gitignored by design — the workload must self-build or HF-stage it; artifact-reuse check (h)) |
| no | no | any, path contains `issue[-_]?<N>` (this issue's number) | `skip` / `planned-output` |
| no | no | any, other | `warn` / `unresolved-citation` (resolves nowhere visible — output convention or typo; not provably fatal, e.g. it may resolve on HF via the first stanza's URL) |

Exit 1 iff any `fail`. The own-issue-number exemption applies ONLY in the nonexistent-everywhere row — calibration point (d) in §2: the #1434 incident file was an own-issue INPUT that existed locally, and it must FAIL.

**Q1 (extraction / false positives) — resolved** per §2 calibration: concrete-file citations only; globs/templates/dirs/no-ext skipped; `raw/` and `configs/` deliberately excluded from the alternation (`configs/` is always tracked — a plan citing an uncommitted config crashes Hydra at compose time on ANY lane and is caught by the Step 6d smoke; `raw/` has zero citations in the calibration corpus; adding either later is a 1-token regex change).

**Q2 (which ref) — resolved:** the PUSHED dispatch ref — `origin/issue-<N>` when it exists, else `origin/main` — after a bounded fetch. Justification: the GCE clone is `--depth 1 --branch issue-<N>` of the REMOTE (gcp.py ~L2706), so remote-tip-tree reachability is exactly the lane's view; local-tree/`HEAD` checks reproduce the #1434 blindness (the file existed locally). The local `issue-<N>` tip is consulted ONLY to discriminate `committed-unpushed` (recoverable in-step by pushing) from `untracked-local-only` (needs a commit).

**Q3 (lane conditionality) — resolved: unconditional.** All three lanes materialize from git (§2 clone mechanics); an uncommitted input is fatal on every one. Keying on the resolved backend would add a router dependency to a pre-dispatch gate (the backend isn't resolved until 6b) for zero benefit.
