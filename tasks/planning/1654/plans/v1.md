# Plan — #1654: preflight upload-quota/billing gate that catches production-scale-only 403s

## 0.0 TL;DR (plain English)

- **What I'll build:** a new preflight check that asks Hugging Face "would a ~16 GB upload be allowed right now?" WITHOUT uploading anything — it sends the same one-request negotiation every real big upload sends first (the exact request that returned the #1586 "setup automatic credit recharge" 403), declaring a 16 GB file that never gets transferred. Zero bytes moved, zero garbage committed, ~1 second.
- **What I expect:** the check turns the #1586 failure mode (a 2 MB canary passes, then 15.2 GB checkpoints die hours later) into a pre-provisioning verdict: billing-blocked runs fail the gate before any GPU is spent, with the exact billing-fix click path in the error message.
- **What would change my mind:** if implementation shows the negotiation probe has side effects, or HF's billing check turns out not to fire on a declared-size-only negotiation, I fall back to a whoami-based advisory warning plus documentation, and the existing reactive 403 handling stays authoritative.

### 4.1 `src/explore_persona_space/orchestrate/hub.py` — new helper (~120 lines + docstrings)

```python
# ── LFS write-gate probe (billing/quota 403 at production scale, #1654) ──────

DEFAULT_BILLING_PROBE_GB = 16.0  # > the 15.2 GB scale that 403'd on #1586

@dataclass(frozen=True)
class LfsWriteGateProbe:
    """Verdict of a zero-byte, declared-size LFS batch-negotiation probe."""
    verdict: str          # "ok" | "billing-blocked" | "storage-blocked" | "unknown" | "disabled"
    repo_id: str | None   # repo whose probe produced a blocked verdict (worst-wins), else None
    detail: str           # short basis / error excerpt (never tokens/secrets)
    probe_gb: float
    billing_context: dict | None  # {"canPay","billingMode","isPro"} subset from whoami, or None


def is_billing_403(err: BaseException) -> bool:
    """True ONLY for the HF account-billing 403 on GB-scale LFS uploads.

    Ported verbatim from scripts/issue1586_dispatch.py::_is_billing_403
    (origin/issue-1586, crash-fix r7). Structural, never a bare log grep:
    response-bearing shapes require status_code == 403; response-less shapes
    (the xet Rust-boundary wrap, #931) require BOTH "credit recharge" AND
    "403" in the message. Sibling of _is_storage_quota_403 (whose "storage"
    conjunct this billing message does not carry).
    """
    msg = str(err).lower()
    if "credit recharge" not in msg:
        return False
    code = getattr(getattr(err, "response", None), "status_code", None)
    if isinstance(code, int):
        return code == 403
    return "403" in msg


def _billing_context() -> dict | None:
    """Fail-soft whoami read: {"canPay","billingMode","isPro"} or None.
    Advisory ONLY (undocumented mapping to upload permission) — never a gate."""
    try:
        d = HfApi(token=os.environ.get("HF_TOKEN")).whoami()
        return {k: d.get(k) for k in ("canPay", "billingMode", "isPro")}
    except Exception:
        return None


def check_lfs_write_gate(
    *,
    repos: Sequence[tuple[str, str]] | None = None,   # default: ((DEFAULT_MODEL_REPO,"model"), (DEFAULT_OVERFLOW_REPO,"model"))
    probe_gb: float | None = None,                    # default: env EPM_HF_BILLING_PROBE_GB, else 16.0
) -> LfsWriteGateProbe:
    """Zero-byte probe of the LFS write path at declared production scale.

    POSTs the git-LFS batch endpoint (post_lfs_batch_info) with ONE
    fabricated object (random sha256, declared size = probe_gb decimal GB,
    transfers=["basic","multipart","xet"] — production parity with
    _commit_api.py:377) per probed repo. Negotiation-only: no bytes are
    transferred and no commit references the oid, so nothing lands in any
    repo (the #1586 billing-403 and the #541 storage-403 both fire AT this
    negotiation step, before any transfer).

    Kill switch EPM_HF_BILLING_PROBE=0 -> "disabled" (checked FIRST, the
    EPM_HF_STORAGE_CHECK precedent). Per-repo classification:
      - is_billing_403(err)          -> "billing-blocked"
      - _is_storage_quota_403(err)   -> "storage-blocked"
      - any other exception          -> "unknown" (fail-open; single attempt,
        NO retry envelope — a transient error must degrade to WARN in
        seconds, not block preflight for the 1800 s retry budget)
      - 200 + no per-object errors   -> "ok"
      - 200 + per-object errors list -> classify each error's message with
        the same two predicates; unmatched -> "unknown" with the message
        excerpt (the git-lfs spec's in-band validation-error channel)
    Worst verdict wins across repos (billing-blocked > storage-blocked >
    unknown > ok). billing_context is fetched (fail-soft) ONLY for blocked
    verdicts. Never raises; ValueError only on a non-parseable env knob
    (the _env_float fail-fast contract).
    """
```

Implementation notes:
- Fabricated oid: `os.urandom(32)` for the `UploadInfo.sha256` bytes field, `sample=b"\x00" * 512` (shape verified against `lfs.py:61–77`).
- `# NO_RETRY: preflight probe is fail-open advisory; a transient error degrades to WARN, never blocks` on the `post_lfs_batch_info` call (the #1547 routing rule names `hf_hub_download`/`upload_*`/`create_commit`/`push_to_hub`; `post_lfs_batch_info` is out of the lint predicate, waiver recorded anyway for the human reader).
- No cache: the probe is 1–2 HTTP POSTs, measured ~1 s total live (vs the ~25 s #564 sum that justified its 1 h cache). §11 records this.
- No repo-side cleanup needed (zero-commit by construction — §12 assumption 2).
