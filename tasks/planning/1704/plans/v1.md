## 1. Goal

> Add a periodic audit that reconciles `issue<N>_partial/` crash-bundle contents on the HF data repo against the committed `eval_results/issue_<N>/` tree in git, and escalates any bundle carrying a completed result that never landed. (Task #1704 Goal, verbatim.)

The GCP EXIT-trap crash-persist path uploads partial artifacts to `superkaiba1/explore-persona-space-data` under `issue<N>_partial/<attempt_id>/` on every non-zero rc — but nothing ever reads those bundles back, so a bundle that happens to carry a COMPLETED result whose workload upload path never fired is indistinguishable from a genuinely partial one. This pass is the safety-net-that-reads-the-net: it lists the bundle prefixes, decides which ones carry a completed result, and escalates any whose payload paths have no committed counterpart in git. It NEVER auto-commits (a partial result silently landing in `eval_results/` is worse than the current loss) and NEVER deletes a bundle (crash forensics are durable record).

## 4. Design

### 4a. Placement — extend `scripts/autonomous_session_watch.py`, not a standalone cron

The pass belongs INSIDE `autonomous_session_watch.py` alongside the other 6 escalate-only observers (§ Decision Rationale): they share the sidecar convention (`.claude/cache/<pass-name>-events.jsonl`), the state-singleton convention (`~/.eps-autonomous/<pass-name>.json`), the throttle+dedup helpers (`decide_*_alert`), the top-level `try/except` fail-soft guard, and the `--<pass-name>-only` smoke flag. A standalone script would duplicate every one of those and drift.

### 4b. Cadence — HOURLY self-gate, mirroring `registry_drift_pass`

Every 10 minutes is over-frequent for a HF listing that costs ~seconds per candidate task (43× the necessary rate for a signal that lives on the order of hours-to-days). The pass reuses `registry_drift_pass`'s attempt-stamp-first throttle (env `EPM_PARTIAL_BUNDLE_INTERVAL_HOURS`, default `1.0`) — a crashing collect writes one error sidecar row per throttle interval, never spammier. If ops needs weekly, `EPM_PARTIAL_BUNDLE_INTERVAL_HOURS=168` inverts the fire cost.

### 4c. Enumeration — TASK-SET-BOUNDED, not full-repo

The pass enumerates candidate ISSUE NUMBERS FIRST from the local task registry (`task_workflow.load_registry()`), then for each candidate issue runs ONE scoped `list_hf_files_under_path(api, DATA_REPO, f"issue{N}_partial", repo_type="dataset")` (server-side prefix-scoped; the #833 recipe). A bare `list_repo_tree(recursive=True)` on `issue*_partial/` root would page under the org 2500-req/5-min limit; scoping per issue keeps every listing sub-second.

**Cost bounding.** Candidate set:
- v1 (default): every REGISTRY task at a TERMINAL or NON-`proposed` status whose `events.jsonl` mtime is within `EPM_PARTIAL_BUNDLE_LOOKBACK_H` (default 168h = 7d) — same `_completed_unmerged_pass` shape.
- Cap per pass: `EPM_PARTIAL_BUNDLE_LISTING_CAP` (default 50 listings/pass — well under the org 2500-req/5-min limit). Overflow: log-and-defer the tail to the next interval (with a state-carried cursor).

Steady-state cost: ~10-50 tasks × ~1s per scoped listing = 10-50s per hourly pass; ONE `retry_transient` wrapper.

### 4d. Bundle enumeration — group by attempt_id

For each candidate issue N, list files under `issue{N}_partial/`, then group by `<attempt_id>` (the second path segment) via a defaultdict. Malformed / short paths (no attempt_id) are skipped with a stderr log line.

### 4e. Completeness signal — three-way, primary + backstops

For each `(issue, attempt_id)`, decide COMPLETE vs KILLED-MID-PERSIST vs NOT-YET-RUN:

- **Primary signal (COMPLETE):** `crash_persist_transcript.log` IS present in the bundle. Per `.claude/rules/compute-backend-failover.md` decision table, this proves the persist ran to completion; the FINAL bundle stages the transcript LAST after the DONE line. A bundle with the transcript but no result files (`eval_results_issue_<N>/*.json`, `data_issue_<N>*`) is a KILLED-EARLY crash where the workload never produced results — NOT a stranded result; the pass IGNORES it (`no_result_payload`, one debug log line, no sidecar).
- **Backstop signal (COMPLETE, transcript-absent):** if the transcript is absent BUT `workload_<ts>.log` (a timestamped copy — the final bundle stages it) IS present AND `eval_results_issue_<N>/*.json` files ARE present, treat as COMPLETE but tag `signal=workload_ts_backstop`. Rationale: the transcript can be uploaded LAST inside the final bundle and rarely the final bundle commit lands milliseconds after the enumeration; if the workload_<ts>.log is present the earlier bundle succeeded. Note as a WEAKER signal in the sidecar row.
- **NOT-COMPLETE (KILLED-MID-PERSIST):** transcript ABSENT AND `workload_<ts>.log` ABSENT. Skip (`persist_killed`, one debug log line, no sidecar): the eps/persist breadcrumb reads `attempted` on this class; nothing is recoverable via a git comparison.

The predicate is IMPLEMENTED as a pure function `_classify_bundle_completeness(bundle_files: list[str]) -> Literal["complete", "workload_ts_backstop", "no_result_payload", "persist_killed"]`.

### 4f. Result-shaped payload extraction

For a `complete`/`workload_ts_backstop` bundle, collect the set of RESULT-SHAPED paths (v1 scope: `eval_results_issue_{N}/*` only; `data_issue_{N}/*` and `data_issue{N}/*` are noted as DATA class and REPORTED-not-flagged — see § Decision Rationale). Strip the `issue{N}_partial/<attempt_id>/eval_results_issue_{N}/` prefix to yield RELATIVE paths (e.g. `cells_R_base_r1_context.json` or `followup_cjk_excluded/cjk_excluded_summary.json`).

### 4g. Git-tree comparison

For each candidate issue N with `complete`/`backstop` bundles, run ONE `git ls-tree -r --name-only HEAD -- eval_results/issue_{N}/` at the main repo root. Compare bundle-relative paths to the committed set:

- A bundle-relative path P: committed = P ∈ committed set.
- MISSING set = bundle-relative paths whose sibling `eval_results/issue_{N}/{P}` is NOT in the committed set.
- MISSING is non-empty → the bundle carries at least one uncommitted result → FLAG.

The comparison is PATH-NAME-ONLY in v1 (not byte-hash): a committed path is treated as landed even if the bundle version differs. This is deliberate — a byte-hash comparison would flag every legitimate follow-up round that re-committed a result under the same name (the correct behavior is to NOT flag those). Reviewer note: a v2 sharpening could add a sha256 comparison against `HfApi.get_paths_info` for suspicious cases.

Git reads use `subprocess.run(["git", "--no-optional-locks", "-C", str(PROJECT_ROOT), "ls-tree", "-r", "--name-only", "HEAD", "--", f"eval_results/issue_{N}/"], ...)` — the `--no-optional-locks` idiom the sibling passes use (`root_draft_pass._enumerate_root_draft_paths`); read-only, never takes the shared root's index lock.

### 4h. Sidecar row + push (escalate-only)

For each flagged `(issue, attempt_id, band)`:

- **Band**: `stranded_eval_results` in v1 (the only class we flag). Reserved for future extension.
- **Sidecar row** (`.claude/cache/partial-bundle-events.jsonl`):
  ```json
  {"ts": "<UTC ISO>", "kind": "partial-bundle-stranded", "issue": <N>, "attempt_id": "<att-...>",
   "band": "stranded_eval_results", "completeness_signal": "complete|workload_ts_backstop",
   "n_missing": <int>, "missing_paths": [<up to 20 relative paths>],
   "bundle_hub_prefix": "issue{N}_partial/<attempt_id>/eval_results_issue_{N}/",
   "recovery_hint": "verify + committed re-generate via task #<N>'s clean-result path"}
  ```
- **Push**: ONE deduped Telegram push per flagged episode (fail-soft `_telegram_push`) — the sibling pattern; message names the (issue, attempt_id, n_missing).
- **Dedup**: state singleton `~/.eps-autonomous/partial-bundle-observer.json`, key `(issue, attempt_id, band)`, value `{"first_flagged_ts": <float>, "last_alert_ts": <float>}`. Re-alert TTL `EPM_PARTIAL_BUNDLE_REALERT_HOURS` (default 168h = weekly re-alert; the registry-drift precedent for a persistent, un-remediable-until-user condition).

The pass posts NO task marker in v1 (a deliberate divergence from `completed_unmerged_pass`; see § Decision Rationale on why sidecar-only fits this class).

### 4i. Cursor for the enumeration cap

State singleton also carries `{"enum_cursor_idx": <int>, "enum_cursor_ts": <float>}` — the index into the sorted candidate list at which to resume next pass. Prevents starvation of tail-of-list issues under the per-pass cap. Reset when the candidate set shrinks below the cursor (avoid stale cursor).

### 4j. Fail-soft on Hub errors

Every Hub call rides `retry_transient` (`hub.py` — Retry-After-aware, bounded, transient class covers 429/408/5xx incl. 529). A retry-exhausted Hub error for one issue's listing logs stderr + one error sidecar row for that issue and CONTINUES to the next issue in the pass (fail-soft per issue, not fail-soft per pass — a persistent HF outage does NOT crash the tick nor silently mask every issue). A single top-level `try/except Exception` around the pass body prints stderr + returns False (the sibling pattern), never crashes the 10-min tick.

### 4k. Kill switch

`EPM_DISABLE_PARTIAL_BUNDLE_AUDIT=1` disables the pass entirely (returns False with a "disabled via" log line), the sibling pattern.

### 4l. `--partial-bundle-only` smoke flag

Mirror `--completed-unmerged-only`: `args.partial_bundle_only` runs just this pass; pair with `--dry-run` for a zero-write live smoke.

### 4m. Pseudocode

```python
# ─── Partial-bundle reconciliation pass (task #1704) ────────────────────────
#
# WHY: incident #1345 — the base-model story leg's eval JSONs were
# persisted to issue1345_partial/<attempt_id>/eval_results_issue_1345/ via
# the GCP EXIT-trap crash-persist path (backends/gcp.py
# _eps_persist_diagnostics) on a nonzero-rc exit, but the workload's own
# upload path never fired, so nothing ever reads those bundles back and a
# bundle carrying a COMPLETED result is indistinguishable from a
# genuinely-partial one. This pass reconciles the bundles against the
# committed eval_results/issue_<N>/ tree in git and escalates any bundle
# whose payload has no committed counterpart. ESCALATE-ONLY: NEVER
# auto-commits (a partial result silently landing in eval_results/ is
# worse than the current loss) and NEVER deletes a bundle.

DATA_REPO = "superkaiba1/explore-persona-space-data"
PARTIAL_BUNDLE_INTERVAL_HOURS = 1.0
PARTIAL_BUNDLE_LOOKBACK_H = 168.0
PARTIAL_BUNDLE_REALERT_HOURS = 168.0
PARTIAL_BUNDLE_LISTING_CAP = 50

def _partial_bundle_enabled() -> bool:
    raw = os.environ.get("EPM_DISABLE_PARTIAL_BUNDLE_AUDIT", "").strip().lower()
    return raw not in {"1", "true", "yes"}


def _partial_bundle_sidecar_path() -> Path:
    return PROJECT_ROOT / ".claude" / "cache" / "partial-bundle-events.jsonl"


def _partial_bundle_state_path() -> Path:
    return AUTONOMOUS_REGISTRY_DIR / "partial-bundle-observer.json"


def _load_partial_bundle_state() -> dict: ...   # isinstance-guarded, {} on missing/garbled
def _save_partial_bundle_state(state, dry_run) -> None: ...  # atomic tmp+rename
def _append_partial_bundle_sidecar(event, dry_run) -> None: ...  # fail-soft append


def _classify_bundle_completeness(files: list[str]) -> str:
    """Pure — returns 'complete' | 'workload_ts_backstop' | 'no_result_payload'
    | 'persist_killed'. See § 4e."""
    basenames = {Path(f).name for f in files}
    has_transcript = "crash_persist_transcript.log" in basenames
    has_workload_ts = any(re.match(r"workload_\d{8}T\d{6}Z\.log$", b) for b in basenames)
    has_result = any("/eval_results_issue_" in f for f in files)
    if has_transcript:
        return "complete" if has_result else "no_result_payload"
    if has_workload_ts and has_result:
        return "workload_ts_backstop"
    return "persist_killed"


def _extract_bundle_result_paths(issue: int, attempt_id: str, files: list[str]) -> list[str]:
    """Return bundle-relative paths under eval_results_issue_<N>/."""
    prefix = f"issue{issue}_partial/{attempt_id}/eval_results_issue_{issue}/"
    return sorted(f[len(prefix):] for f in files if f.startswith(prefix))


def _committed_eval_paths(issue: int) -> set[str] | None:
    """One `git ls-tree -r --name-only HEAD -- eval_results/issue_<N>/` from
    PROJECT_ROOT. Returns None on git failure (fail-soft: skip issue)."""
    ...  # subprocess.run pattern from _enumerate_root_draft_paths


def _partial_bundle_candidate_issues(now: float, lookback_s: float) -> list[int]:
    """Registry issues (non-'proposed') with events.jsonl mtime within
    lookback. Reuses the candidate-gate shape of _completed_unmerged_pass."""
    ...


def _partial_bundle_scoped_listing(api, issue: int) -> list[str] | None:
    """One retry_transient-wrapped list_hf_files_under_path per candidate.
    Returns [] if the prefix does not exist. Returns None on retry-exhausted
    Hub failure (caller logs + one error sidecar row, continues to next issue)."""
    from explore_persona_space.orchestrate.hub import list_hf_files_under_path, retry_transient
    prefix = f"issue{issue}_partial"
    try:
        return retry_transient(
            lambda: list_hf_files_under_path(
                api, DATA_REPO, prefix, repo_type="dataset", revision="main"
            ),
            what=f"list_hf_files_under_path({DATA_REPO}, {prefix})",
        )
    except Exception as exc:
        print(f"  partial-bundle: HF listing failed for issue {issue}: {exc}",
              file=sys.stderr)
        return None


def partial_bundle_pass(dry_run: bool) -> bool:
    """ESCALATE-ONLY reconciliation of HF `issue<N>_partial/<attempt_id>/`
    bundles against the committed `eval_results/issue_<N>/` tree in git
    (task #1704; incident #1345 stranded base-model story leg). Sidecar
    rows + ONE deduped push per (issue, attempt_id, band); NEVER
    auto-commits bundle contents, NEVER deletes a bundle, NEVER posts task
    markers. Daemon-independent. Hourly self-gate throttling."""
    if not _partial_bundle_enabled():
        print("  partial-bundle: disabled via EPM_DISABLE_PARTIAL_BUNDLE_AUDIT; skipping")
        return False
    try:
        now = time.time()
        interval_h = _env_float("EPM_PARTIAL_BUNDLE_INTERVAL_HOURS",
                                PARTIAL_BUNDLE_INTERVAL_HOURS, lo=0.0, hi=720.0)
        realert_h = _env_float("EPM_PARTIAL_BUNDLE_REALERT_HOURS",
                               PARTIAL_BUNDLE_REALERT_HOURS, lo=1.0, hi=2160.0)
        lookback_h = _env_float("EPM_PARTIAL_BUNDLE_LOOKBACK_H",
                                PARTIAL_BUNDLE_LOOKBACK_H, lo=1.0, hi=720.0)
        cap = int(_env_float("EPM_PARTIAL_BUNDLE_LISTING_CAP",
                             float(PARTIAL_BUNDLE_LISTING_CAP), lo=1.0, hi=500.0))
        state = _load_partial_bundle_state()
        last = state.get("last_run_ts")
        if isinstance(last, int | float) and (now - last) < interval_h * 3600.0:
            return False   # throttled
        state["last_run_ts"] = now
        _save_partial_bundle_state(state, dry_run)   # attempt-stamp-FIRST
        from huggingface_hub import HfApi
        api = HfApi()
        cands = _partial_bundle_candidate_issues(now, lookback_s=lookback_h * 3600.0)
        # cursor-resume
        cursor = int(state.get("enum_cursor_idx") or 0)
        if cursor >= len(cands):
            cursor = 0
        window = cands[cursor:cursor + cap]
        next_cursor = (cursor + cap) if (cursor + cap) < len(cands) else 0
        flagged_any = False
        alerted = state.get("alerted") if isinstance(state.get("alerted"), dict) else {}
        new_alerted = dict(alerted)
        for issue in window:
            files = _partial_bundle_scoped_listing(api, issue)
            if files is None:
                _append_partial_bundle_sidecar(
                    {"kind": "partial-bundle-hub-error", "issue": issue}, dry_run
                )
                continue
            if not files:
                continue   # no bundle for this issue
            by_attempt = defaultdict(list)
            for f in files:
                parts = f.split("/", 2)
                if len(parts) >= 3:
                    by_attempt[parts[1]].append(f)
            committed = _committed_eval_paths(issue)
            if committed is None:
                _append_partial_bundle_sidecar(
                    {"kind": "partial-bundle-git-error", "issue": issue}, dry_run
                )
                continue
            for att_id, att_files in sorted(by_attempt.items()):
                cls = _classify_bundle_completeness(att_files)
                if cls in ("no_result_payload", "persist_killed"):
                    continue   # nothing to flag
                bundle_paths = _extract_bundle_result_paths(issue, att_id, att_files)
                missing = [p for p in bundle_paths if p not in committed]
                if not missing:
                    continue
                key = f"{issue}|{att_id}|stranded_eval_results"
                entry = new_alerted.get(key)
                last_alert = entry.get("last_alert_ts") if isinstance(entry, dict) else None
                dedup = (isinstance(last_alert, int | float)
                         and (now - last_alert) <= realert_h * 3600.0)
                if dedup:
                    new_alerted[key] = {**(entry or {}), "last_alert_ts": last_alert}
                    continue
                new_alerted[key] = {"first_flagged_ts":
                                      (entry or {}).get("first_flagged_ts", now),
                                    "last_alert_ts": now}
                flagged_any = True
                print(f"  partial-bundle: STRANDED issue={issue} att={att_id} "
                      f"missing={len(missing)} signal={cls}")
                _append_partial_bundle_sidecar(
                    {"kind": "partial-bundle-stranded", "issue": issue,
                     "attempt_id": att_id, "band": "stranded_eval_results",
                     "completeness_signal": cls, "n_missing": len(missing),
                     "missing_paths": missing[:20],
                     "bundle_hub_prefix":
                         f"issue{issue}_partial/{att_id}/eval_results_issue_{issue}/",
                     "recovery_hint":
                         "verify + committed re-generate via task's clean-result path"},
                    dry_run,
                )
                _telegram_push(
                    f"partial-bundle stranded (issue #{issue}, att {att_id}, "
                    f"{len(missing)} eval JSONs on HF with no git counterpart). "
                    f"Investigate: `uv run python -c 'from ... import ...; ...'`. "
                    f"NEVER auto-committed; NEVER deleted.",
                    dry_run,
                )
        state["alerted"] = new_alerted
        state["enum_cursor_idx"] = next_cursor
        state["enum_cursor_ts"] = now
        _save_partial_bundle_state(state, dry_run)
        return flagged_any
    except Exception as exc:
        print(f"  partial-bundle: pass failed (fail-soft): {exc}", file=sys.stderr)
        _append_partial_bundle_sidecar(
            {"kind": "partial-bundle-error", "error": str(exc)[:500]}, dry_run
        )
        return False
```

| Risk | Likelihood | Mitigation |

| False positive on a follow-up round that regenerated an artifact under a different filename | Medium (a follow-up leg's file may bear a slightly different name than the parent-round's committed file) | Path-name-only comparison in v1 flags this; the mitigation is that the escalation is a Telegram push naming (issue, attempt_id) — the operator diffs. | Cursor starvation | Low (cap 50 issues/hour, candidate set typically ≤ 30 non-proposed non-old issues) | Cursor resets when it exceeds the candidate list; a passing pass with fewer candidates than the cap wraps at 0 |
| Data disk `.claude/cache/` fills | Low (sidecar rows are KB-scale; the sibling sidecars are all in the same convention) | The `vm_disk_guard.py` cron reaps stale sidecar files under its own contract |
| Malformed state singleton (hand-edited / partial-write) | Low (atomic tmp+rename; isinstance guards on every field read) | Degrades to defaults on parse failure (isinstance guards); loses dedup once, re-alerts once next pass |
| HF org 429 storm during pass | Medium (2500-req/5-min quota) | `retry_transient` honors `Retry-After`; a pass under storm skips issues loudly (one sidecar error row per issue) and returns without crashing tick |
| A GENUINE stranded-result episode we miss: bundle files land BEFORE `eval_results_issue_<N>/` writes | N/A by construction (a stranded result REQUIRES the bundle to carry a `eval_results_issue_<N>/*.json` — a bundle with only `data_issue_<N>/` is a DATA persist, not a result persist) | Documented scope: data caches are re-downloadable; result JSONs are the loss class we escalate |
| Race with a fresh commit landing while the pass runs | Low (git read is against `HEAD`; a same-tick commit landing before the pass's `ls-tree` would be included; landing after is next-pass) | Next-pass reconciliation handles this |

## 11. Decision Rationale

Load-bearing choices, one entry each:

**Completeness signal = `crash_persist_transcript.log` primary + `workload_<ts>.log` backstop, NOT `eps/persist=ok`**
- **What**: The pass decides "complete" from the bundle file set alone (transcript present) with a secondary backstop (timestamped workload log + result payload).
- **Why**: The `eps/persist` guest attribute is a VM-side breadcrumb readable only via the poller during the run — it's not on HF and it's per-attempt-ephemeral. The transcript is staged LAST inside the FINAL bundle upload (`backends/gcp.py:2262-2275`); its presence proves the persist ran to completion end-to-end. This is EXACTLY the discriminator named in `.claude/rules/compute-backend-failover.md` decision table.
- **Source**: `.claude/rules/compute-backend-failover.md` (§ Part A item 8, decision table).
- **Alternatives considered**:
  - `eps/persist=ok` guest attribute alone — REJECTED: the pass is post-run and off-VM; the attribute is unreachable.
  - `crash_report.json` presence — REJECTED: this uploads first, so present-but-transcript-absent = KILLED-MID-PERSIST, a genuine partial-persist we should not flag as stranded.
  - Bundle file-count threshold — REJECTED: brittle; a legitimate crash-early bundle can have < 5 files and still be "complete" for what it captured.

**Dedup key = (issue, attempt_id, band)**
- **What**: attempt_id is the discriminator, not just issue.
- **Why**: One issue can have MANY attempt_ids (live-verified: #1345 has 8). Each is an independent crash-persist event; flagging issue-level would collapse them into one and lose the (recovered vs still-stranded) distinction that a future recovery workflow needs. band is a forward-compat slot (v1 has one band; v2 could add e.g. `stranded_data_partials` for data caches).
- **Source**: `completed_unmerged_pass` uses `(issue, done_ts)` (per-episode); `registry_drift_pass` uses `fingerprint`; the pattern of "keying dedup on the finest natural unit of the escalation" is the sibling convention.

**Cadence = hourly**
- **What**: `EPM_PARTIAL_BUNDLE_INTERVAL_HOURS=1.0` throttle.
- **Why**: The failure class lives on the order of hours-to-days-to-weeks (a genuinely stranded bundle is a REPORT of past compute spend; the recovery decision spends new GPU). Every 10 min would issue 40+ scoped listings/hour for zero improvement in signal freshness. Weekly would delay by 168h but eliminate storm-of-listings risk. Hourly is the middle ground and matches `registry_drift_pass` (~daily) precedent for a "read-only observer on a slow-moving external state."
- **Source**: `registry_drift_pass` (`EPM_REGISTRY_DRIFT_INTERVAL_HOURS=24.0`) — a report-only observer on registry drift is once-daily by design; partial-bundle is 24× that because a stranded result is more time-sensitive than a registry drift (a strand blocks a scientific claim; a drift is inert until a consumer hits it).

**Attachment = inside `autonomous_session_watch.py`, not a standalone cron**
- **What**: The pass is a new function alongside `completed_unmerged_pass`, `root_draft_pass`, etc.
- **Why**: The sibling passes share the sidecar / state-singleton / dedup / kill-switch / smoke-flag machinery; a standalone cron duplicates all of it and drifts. The watcher's daemon-independent block already has 6 escalate-only passes that read external state and never touch tasks — this is the seventh of the same class.
- **Source**: § 4a (the 6 sibling passes, each identically shaped).

**Sidecar-only, NO task marker**
- **What**: The pass posts sidecar rows + Telegram pushes; it does NOT call `_post_progress_marker` on the parent task.
- **Why**: The escalation target is a HUMAN (a stranded eval JSON needs a recover-vs-re-run decision that spends GPU — this is exactly what CLAUDE.md's halt-criterion #2 reserves for user judgment). A task marker on the parent issue's events.jsonl would (a) potentially reset staleness clocks on a session whose task is DONE (the sibling `[autonomous_session_watch:*]` sentinels dodge this, but only just), and (b) surface as an event on a completed task the user has already moved past. `verdict_disagree_pass` (#1170) explicitly chose sidecar-only for the same reason; this pass inherits that precedent.
- **Source**: `verdict_disagree_pass` in `.claude/rules/background-automation.md` ("Channels: one row per finding to the dedicated sidecar ... + one deduped fail-soft `_telegram_push`; NO task marker (deliberate divergence from the triage observer — this flag's consumer is a human, not the next dispatch)").

**Archived / on_hold tasks**
- **What**: The candidate set INCLUDES `archived` and `on_hold` tasks (per `_partial_bundle_candidate_issues`; the only exclusion is `proposed`).
- **Why**: A crash-persist artifact from a task the user later archived is exactly the class we want to surface: the user may want to know that GPU-h were spent producing a result that never landed, whether or not they choose to promote it. `on_hold` tasks are literally the "user paused this" class; surfacing a strand doesn't change the pause, it informs the resume.
- **Source**: Prior-art `completed_unmerged_pass` only sweeps `completed`; that pass targets a workflow (Step 10d merge) that can't happen on `archived`. Ours targets an artifact class that spans all terminal-ish statuses.

**Path-name comparison, not byte-hash**
- **What**: A bundle path `foo.json` is treated as landed if `eval_results/issue_<N>/foo.json` exists in git at HEAD, regardless of byte-identity.
- **Why**: v1 conservative to avoid false-positives on legitimate follow-up rounds that re-committed the same result under the same filename. A byte-hash comparison would flag every follow-up round; the operator would then need to diff manually anyway. If the false-positive rate on this rule proves TOO conservative (a bundle result that DIFFERS from the committed result — a repro on the same attempt with a fixed bug that landed a different number), v2 can add sha256 via `HfApi.get_paths_info(files, expand=True)` alongside `git cat-file blob HEAD:<path> | sha256sum`.
- **Source**: `.claude/rules/artifact-reuse.md` item (c) (context consistency — bytes vs name); v1 chooses name-only for false-positive avoidance, v2 sharpening is a stated follow-up.

**Failure-lesson mode**: N/A — no crash-fix round (this is a fresh implementation, not a fix of a posted `epm:failure`).
