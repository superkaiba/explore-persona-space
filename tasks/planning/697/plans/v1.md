<h1>Plan — issue #697</h1>
<p class="small">Causal context-vector patch on #537's adapters: does finetuning a behavior into a context move the context vector (the input) or the context→behavior mapping (the function)?</p>

<section class="plan-tldr">
<h2>0.0 TL;DR (plain English)</h2>
<ul>
<li><strong>What I'll run:</strong> When you finetune a model to (say) give harmful advice whenever it's playing a software-engineer persona, the model's answers change. I want to know <em>where</em> that change lives: did the model relearn what "software engineer" looks like on the inside, or did it keep the same internal picture of "software engineer" but change what it does with that picture? I take the models #537 already trained, freeze them, and do a swap: I read out the internal "context picture" from one model and paste it into the other mid-computation, then watch whether the behavior follows the picture or stays put.</li>
<li><strong>What I expect:</strong> Mostly the <em>function</em> changed, not the picture — finetuning teaches a new response to the same context, so swapping the picture should move the behavior only a little. The marker tic is the likely exception (it behaved differently in the sibling read), and I'd bet it shows more "picture moved".</li>
<li><strong>What would change my mind:</strong> If pasting the trained model's context-picture into the untrained model makes the untrained model start producing the trained behavior on its own, that says the picture carries the change — and it would mean a cheap base-model read could predict finetuning leakage, which is the bigger prize this whole line is chasing.</li>
</ul>
</section>

<section class="plan-summary">
<h2>0. Plan Summary (technical)</h2>
<p><strong>Training:</strong> none — reuses #537's already-trained behavior×context LoRA adapters (Qwen-2.5-7B-Instruct) verbatim; this is a forward-only activation-patching read.
<strong>Method:</strong> per (behavior B, training-context C, seed) cell, two cross-model residual-stream patches at read layer L on the fixed #651 14-persona×20-question panel — <strong>P↓</strong> (overwrite the FT model's layer-L context-read residual with the base model's <code>c0(C)</code>) and <strong>P↑</strong> (overwrite the base model's residual with the FT model's <code>c⁺(C)</code>) — scored against four unpatched / null baselines.
<strong>Hyperparameters (load-bearing, all inherited):</strong> read layer L=14 primary, sweep {7,21} (<code>Source: #651</code>); patch slot = last input token (<code>prompt_len−1</code>) primary, full-context-span companion (<code>Source: A3.6c row + #651 slot read</code>); teacher-forced <code>v</code> read <code>max_new_tokens=512</code> (<code>Source: #651</code>); on-policy <code>E</code> generation greedy / <code>max_new_tokens</code> = per-behavior #537 cap, judge = <code>claude-sonnet-4-5-20250929</code> (<code>Source: CLAUDE.md judge rule + #537</code>).
<strong>Baselines / controls:</strong> unpatched base (v0,E0) + unpatched FT (v⁺,E⁺); self-patch identity null; random-Gaussian + other-context CV null; norm-matched <code>c⁺</code>→‖c0‖ variant.
<strong>Loss surface:</strong> N/A — no training. The patch overwrites the layer-L residual at the patch slot before layer L+1; <code>v</code> read = mean answer-token activation along the FT shift <code>d=(v⁺−v0)/‖·‖</code>, <code>E</code> = judge-rate of the patched on-policy generation.
<strong>Compute:</strong> 1× GPU (auto → GCP <code>a2-ultragpu-1g</code> A100-80; <code>eval</code>-intent), HF forward passes only; smoke = sweep with one cell. <code>Estimated GPU-hours (total): 14</code>.
<strong>Evaluation:</strong> per cell, mediated fraction <code>f_CV = (v_{P↑}−v0)·d / (v⁺−v0)·d</code> in the activation DV and <code>f_CV^E=(E_{P↑}−E0)/(E⁺−E0)</code> in the behavioral DV, cross-checked with the P↓ analog; verdict bands: <code>f_CV≥0.7</code> ⇒ context-vector-moved, <code>≤0.3</code> ⇒ mapping-changed, else mixed (bootstrap 95% CI over the panel + paired test vs the random-CV null floor).
<strong>Risks (top 2):</strong> (1) the core read module (<code>analysis.activation_shift</code>) + all <code>issue651_*</code> scripts live ONLY on the unmerged <code>origin/issue-651</code> branch — must be vendored into this worktree before any code runs (§8/§12); (2) the patch hook is new code whose correctness rides on the self-patch identity null reading ≈0 — gated by a TDD unit test + a canary.</p>

<h2>1. Goal</h2>
<p>The theory chain is <code>answer_profile = M(context_vector)</code>: a context C maps to an internal summary <code>c_C</code>, and a learned function M turns that summary into the model's answer-side profile <code>v</code> / behavior <code>E</code>. Finetuning behavior B into context C changes the answer profile. <strong>This task causally decomposes whether that change is carried by the input <code>c_C</code> (the model's internal picture of the context moved) or by the function M downstream of read layer L (the model keeps the same picture but maps it to a new answer).</strong> #651 measured only the <em>response-side write</em> (<code>trained − base</code> at the answer slot) and never held the context vector fixed, so input-move and function-change are entangled in everything #651 reported. #697 runs the A3.6c causal patch (theory plan §4) as an early, cheap read on #537's existing adapters, ahead of the #660 fresh-fleet run (#665). It informs the #665 plan and is cross-checkable against it.</p>

<h2>3. Hypothesis</h2>
<p>Per (B, C) cell, against the verdict table (verbatim from the body, cross-checked across both patches in BOTH DVs):</p>
<ul>
<li><strong>Context vector moved</strong> ⇔ P↑ → (v⁺, E⁺) <em>and</em> P↓ → (v0, E0) ⇒ <code>f_CV ≈ 1</code>.</li>
<li><strong>Mapping changed</strong> ⇔ P↑ → (v0, E0) <em>and</em> P↓ → (v⁺, E⁺) ⇒ <code>f_CV ≈ 0</code>.</li>
<li><strong>Mixed</strong> ⇒ intermediate <code>f_CV</code>; the L-sweep {7,14,21} localizes the change pre- vs post-L.</li>
</ul>
<p><strong>Directional prediction (falsifiable):</strong> #651 found the FT write is a context-invariant <em>response-side</em> direction for em/agreement/fact — consistent with M changing (a learned new answer map) more than <code>c_C</code> moving. So I predict <code>f_CV ≤ 0.3</code> (mapping-changed) for em / agreement / fact at L=14, and a higher / read-specific <code>f_CV</code> for the marker tic (which #651 found read/layer-specific). <strong>Confirmation:</strong> <code>f_CV</code> CIs land in the predicted band in both DVs and the two patches agree (P↑ and P↓ tell the same story). <strong>Falsification:</strong> <code>f_CV ≥ 0.7</code> for em/agreement/fact (context vector carries the change) — which would say the base-model context read predicts finetuning leakage, sharpening A3.10. A wide CI straddling 0.3–0.7 in both DVs is a genuine "mixed / underpowered" outcome, reported as such (not forced into a verdict).</p>

<h3>4.3 Patch-position spec (the body's open question #1)</h3>
<p>The "context-read position" is the residual at the <strong>last input token</strong> — <code>prompt_len − 1</code> in <code>_build_full_sequence_ids</code> terms (the last token of the chat-templated <code>T(c)+q</code> with the generation prompt appended). This is the position whose layer-L residual is the model's running summary of context+question immediately before it begins generating — the natural site of <code>c_C</code>. <strong>Primary patch scope = this single last-input-token slot.</strong> <strong>Companion (upper-bound) scope = the full context span</strong> (every position from the start of the system turn through <code>prompt_len−1</code>), overwriting each position's FT/base residual with the other model's residual at the same position. The full-span companion bounds how much a single-slot patch under-counts when the context summary is distributed across positions. (The body's control #4.)</p>

<h3>4.4 The two patches (per B, C, seed)</h3>
<p>Both the base model θ0 and the FT merged model θ⁺ are loaded in the same process (the #651 path loads both; θ⁺ via <code>PeftModel.from_pretrained(...).merge_and_unload()</code> so the rsLoRA α/√r scaling is baked into the merged weights — the #601 gauge is therefore identical to what the canary's Gate 7a reproduces). For each (context, question) on the panel:</p>
<ol>
<li><strong>Capture pass</strong> (unpatched): one TF forward of base on <code>T(c)+q+R_base</code> and one of FT on the same sequence (same teacher-forcing recipe as #651's <code>variant="base"</code> — base model's own greedy <code>R_base</code> is the shared trajectory, so v differences are not confounded by trajectory differences). Record <code>c0(C) = h_base[L, prompt_len−1]</code>, <code>c⁺(C) = h_ft[L, prompt_len−1]</code>, and the unpatched answer-side reads <code>v0, v⁺</code> (mean over response tokens at L). Run the unpatched generations for <code>E0, E⁺</code> (per-behavior on-policy, §4.5).</li>
<li><strong>P↓ (base CV → FT model):</strong> run FT (θ⁺) with a forward hook on <code>model.model.layers[L]</code> that, on the forward over <code>T(c)+q+R</code>, overwrites the output residual at position <code>prompt_len−1</code> (the full-span companion: every context position) with <code>c0(C)</code>; let layers L+1… complete. Read <code>v_{P↓}</code> and run the patched generation for <code>E_{P↓}</code>.</li>
<li><strong>P↑ (FT CV → base model):</strong> run base (θ0) with the same hook overwriting position <code>prompt_len−1</code> with <code>c⁺(C)</code>. Read <code>v_{P↑}</code>, generate <code>E_{P↑}</code>.</li>
</ol>
<p><strong>Generation-time patching for E.</strong> The <code>E</code> DV requires the patch to persist through generation. The hook overwrites the layer-L residual at the context slot on every forward step where that position is in the sequence; under KV-caching the context positions are computed once (prefill) so the hook fires at prefill and the cached K/V for position <code>prompt_len−1</code> carry the patched value through decoding. Implementation asserts the patched K/V is what downstream layers consume (the self-patch identity null is the correctness gate — §5 control 1).</p>

<pre>
# src/explore_persona_space/analysis/cv_patch.py  (NEW — TDD: yes)

def make_cv_patch_hook(layer_module, patch_positions, replacement_vec):
    """register_forward_hook that OVERWRITES the layer's output residual at
    `patch_positions` with `replacement_vec` (broadcast over the batch=1 seq).
    Returns the handle; caller removes it after the forward."""
    def hook_fn(module, inputs, output):
        hs = output[0] if isinstance(output, tuple) else output  # (1, T, H)
        for pos in patch_positions:                              # last-input-token = [prompt_len-1]
            hs[0, pos, :] = replacement_vec.to(hs.dtype).to(hs.device)
        return (hs, *output[1:]) if isinstance(output, tuple) else hs
    return layer_module.register_forward_hook(hook_fn)

def patched_read(model, full_ids, layer, patch_positions, replacement_vec,
                 response_start):
    """One TF forward with the patch installed; return mean-over-response v at `layer`."""
    h = make_cv_patch_hook(model.model.layers[layer], patch_positions, replacement_vec)
    try:
        out = model(full_ids.unsqueeze(0).to(model.device), output_hidden_states=True)
        v = out.hidden_states[layer+1][0, response_start:].mean(0).float().cpu()
    finally:
        h.remove()
    return v

def patched_generate(model, prompt_ids, layer, patch_positions, replacement_vec, **gen):
    """Greedy/sampled generation with the patch persisting through prefill (KV-cached
    context positions carry the patched residual into decoding). Returns text for the
    behavioral E judge."""
    h = make_cv_patch_hook(model.model.layers[layer], patch_positions, replacement_vec)
    try:
        out = model.generate(prompt_ids.unsqueeze(0).to(model.device), **gen)
    finally:
        h.remove()
    return tokenizer.decode(out[0, prompt_ids.shape[0]:], skip_special_tokens=True)

# Per (B, C, seed) cell, on the panel: capture c0/c+/v0/v+/E0/E+ (unpatched),
# then P-down (FT model, replacement=c0) and P-up (base model, replacement=c+),
# plus the 4 controls (§5). Persist per-cell {v_*, E_* , c0, c+} → .pt + json.
</pre>

<h2>6. Evaluation</h2>

<h3>6.1 The metric</h3>
<p>Per (B, C, seed) cell, in each DV space, the <strong>context-vector-mediated fraction</strong> along the FT shift <code>d</code>:</p>
<pre>v-space:   f_CV   = ((v_{P↑} − v0)·d) / ((v⁺ − v0)·d),    d = (v⁺ − v0)/‖v⁺ − v0‖
E-space:   f_CV^E = (E_{P↑} − E0) / (E⁺ − E0)
P↓ cross-check:  f_CV^{down} = 1 − ((v_{P↓} − v0)·d)/((v⁺−v0)·d)   [should agree with f_CV]</pre>
<p>P↑ measures sufficiency of the moved CV (→ high f_CV ⇒ context-vector-moved); the P↓ analog measures necessity; the verdict requires the two to agree.</p>

<h3>6.2 Measurement validity (the §11 for outputs)</h3>

<tr><td>E (marker)</td><td>rate the model emits ※ at the end of its own answer</td><td>Δlog P(※, id 83399) at the post-response slot, teacher-forced on the model's own base-cached R</td><td>partial — teacher-forced log-prob at a fixed slot, not free emission</td><td>Inherited #537/#651 marker DV; validated there against argmax-emission rate (dual-reported as sanity). <h3>6.3 Verdict bands (pre-registered)</h3>
<p>Per cell, in each DV: <code>f_CV ≥ 0.7</code> ⇒ <strong>context-vector-moved</strong>; <code>f_CV ≤ 0.3</code> ⇒ <strong>mapping-changed</strong>; <code>0.3 &lt; f_CV &lt; 0.7</code> ⇒ <strong>mixed</strong>. A verdict is assigned only when (a) the bootstrap 95% CI over the 20 panel questions lies entirely within one band, AND (b) the cell's effect is real: <code>|E⁺ − E0|</code> (or <code>|(v⁺−v0)·d|</code>) exceeds the random-CV null floor at p&lt;0.05 (paired test over panel questions) — a cell with no FT effect has an undefined f_CV (0/0) and is reported as <code>no-effect</code>, never forced into a band. The P↑ and P↓ verdicts must agree for a confident cell-level verdict; disagreement is reported as <code>patch-inconsistent</code> (a finding about the slot's adequacy, not a failure).</p>

<h3>6.4 Statistics</h3>
<ul>
<li><strong>Bootstrap 95% CI</strong> on f_CV / f_CV^E per cell (resample the 20 panel questions, 1000 reps); the v projection and the E rate are both per-question, so the bootstrap is over the shared question axis.</li>
<li><strong>Null floor:</strong> the random-CV + other-context conditions give the per-cell "patch did something" floor; a real effect must clear it (paired test).</li>
<li><strong>v-tracks-E validation:</strong> Spearman of <code>f_CV</code> (v-space) vs <code>f_CV^E</code> (E-space) across the cells with dynamic range — registers that the continuous companion tracks the behavioral DV (the SECONDARY-DV validation the project rule requires).</li>
<li><strong>No registered derived-statistical-input corrections</strong> (raw DVs + bootstrap/paired tests only) — N/A for the statistical-input-existence gate.</li>
</ul>
