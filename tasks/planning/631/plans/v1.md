### Deliverable 1 — FLEX_START provisioning support (`gcp.py`)

Extend the accepted set and render the extra flag. Verified facts (docs, this round): `--provisioning-model=FLEX_START`; `--request-valid-for-duration` accepts 90s–2h (gcloud duration syntax, e.g. `2h`); `--max-run-duration` max 7d; flex-start consumes PREEMPTIBLE quota; `--instance-termination-action=DELETE` is ALLOWED for standalone flex-start VMs (docs: "you must choose whether Compute Engine automatically stops or deletes"); reservations are incompatible (we use none).

```python
# gcp.py:334 — widen the documented union
ProvisioningModel = str  # "SPOT" | "STANDARD" | "FLEX_START"

# gcp.py:343-360 — accept FLEX_START
_VALID_PROVISIONING = {"SPOT", "STANDARD", "FLEX_START"}
def resolve_provisioning_model(spec):
    raw = spec.extra.get("provisioning_model")
    if raw is None:
        return DEFAULT_PROVISIONING_MODEL
    val = str(raw).upper()
    if val not in _VALID_PROVISIONING:
        raise ValueError(f"unknown provisioning_model={raw!r}; expected one of {sorted(_VALID_PROVISIONING)} ...")
    return val

# new pure helper near resolve_provisioning_model
DEFAULT_REQUEST_VALID_FOR_DURATION = "2h"  # docs max for flex-start
def resolve_request_valid_for_duration(spec) -> str:
    # gcloud duration syntax; flex-start window 90s..2h. Default to the doc max
    # (longest queue tolerance) unless the caller pins it via spec.extra.
    return str(spec.extra.get("request_valid_for_duration") or DEFAULT_REQUEST_VALID_FOR_DURATION)

# gcp.py:~1013 in render_create_argv, right after the --provisioning-model line
provisioning = resolve_provisioning_model(spec)
argv += [f"--provisioning-model={provisioning}", "--instance-termination-action=DELETE", ...]
if provisioning == "FLEX_START":
    argv.append(f"--request-valid-for-duration={resolve_request_valid_for_duration(spec)}")
    # --max-run-duration already rendered; assert it parses to <= 7d (see below)
```

`--max-run-duration` ≤7d guard: add a small pure check `_assert_max_run_within_flex_cap(max_run)` that raises `ValueError` when `provisioning == "FLEX_START"` and the parsed duration exceeds 7d. The config default is `24h` (well under), but a caller can pass `spec.extra["max_run_duration"]`; fail loud rather than let gcloud reject mid-provision. Parse gcloud duration suffixes (`s/m/h/d`) in a tiny local helper.

`--instance-termination-action=DELETE` stays unconditional (the existing leak guard) — verified compatible with both FLEX_START and SPOT.

### Deliverable 3 — provisioning-aware quota metric + SPOT-on-A100 enablement (`gcp.py`)

Two coupled changes:

**(3a) Make the quota metric provisioning-model-aware.** Today `_GPU_KIND_TO_QUOTA_METRIC` maps gpu_kind→on-demand metric only. Flex-start and Spot consume the PREEMPTIBLE metric (docs-verified). Replace the single map with a `(gpu_kind, is_preemptible)` resolution:

```python
# gcp.py:1559 — split into on-demand vs preemptible
_GPU_KIND_TO_QUOTA_METRIC: dict[str, str] = {
    "A100-80": "NVIDIA_A100_80GB_GPUS",
    "L4": "NVIDIA_L4_GPUS",
}
_GPU_KIND_TO_PREEMPTIBLE_QUOTA_METRIC: dict[str, str] = {
    "A100-80": "PREEMPTIBLE_NVIDIA_A100_80GB_GPUS",
    "L4": "PREEMPTIBLE_NVIDIA_L4_GPUS",
    "H100-80": "PREEMPTIBLE_NVIDIA_H100_GPUS",  # a3-highgpu (1g/2g); see assumptions on mega
}

def quota_metric_for(machine: MachineSpec, provisioning: str) -> str | None:
    if provisioning in {"SPOT", "FLEX_START"}:
        return _GPU_KIND_TO_PREEMPTIBLE_QUOTA_METRIC.get(machine.gpu_kind)
    return _GPU_KIND_TO_QUOTA_METRIC.get(machine.gpu_kind)
```

Then in `preflight_quota_headroom` (gcp.py:1621): `metric = quota_metric_for(machine, resolve_provisioning_model(spec))`. Behavior preserved for STANDARD A100/L4; H100 has no on-demand metric (returns None for STANDARD → fail-OPEN, but H100 should never be STANDARD; see below).

**H100 + STANDARD guard:** because a3-highgpu cannot be created on-demand at all (docs), add a guard in `render_create_argv` (or `resolve_provisioning_model`) that raises `ValueError` when `machine.gpu_kind == "H100-80"` and the resolved provisioning is `STANDARD` — fail loud at render, not on a doomed gcloud call. (Caller must pass `provisioning_model=SPOT` or `FLEX_START` for an H100 intent.)

**(3b) Un-gate SPOT for A100 (the actual enablement).** `resolve_provisioning_model` already ACCEPTS SPOT; the "gate" is purely that `DEFAULT_PROVISIONING_MODEL="STANDARD"`. Per the body, the deliverable-3 "enable" is to make SPOT *usable* for A100 intents once the idempotency contract is validated. There is no code gate to remove — SPOT is already renderable for any intent. The substantive work is the **idempotency-contract validation** (code review + tests), recorded below, plus the provisioning-aware quota metric (3a) so a SPOT A100 launch reads `PREEMPTIBLE_NVIDIA_A100_80GB_GPUS` (the 8 idle GPUs) instead of the saturated on-demand pool.

**Contract verified (deliverable-3 validation evidence)** — read this round from the docstring (gcp.py:46-48), `attempt_id_for` (363-386), `reconnect_or_none` (1453+), `render_startup_script` (≤921):
1. **Artifacts pushed off-VM during the run survive a preempt.** The backend never holds the authoritative artifacts — the workload pushes to HF Hub / WandB during the run (docstring 62-67; Upload Policy). A preempt loses only in-flight, not-yet-uploaded scratch.
2. **Re-run is reconnect-before-create.** `reconnect_or_none` lists `eps-issue-<N>` and returns a live-instance handle without re-provisioning (docstring 33-35; gcp.py:1453+) — a re-spawn after preempt reconnects to a survivor or, if gone, creates fresh.
3. **Per-attempt namespace prevents overwrite.** `attempt_id_for` sub-namespaces HF paths + the VM scratch sentinel dir so a fresh re-run after preempt never clobbers an earlier attempt's outputs (docstring 46-48; gcp.py:363-386, 676 `test_sentinel_path_namespaces_per_attempt`).
4. **DELETE termination caps leak.** `--instance-termination-action=DELETE` + the stale-VM reaper (`audit_stale_gcp_vms`) bound credit leakage whether Spot preempts or the run-duration fence trips.
5. **Router treats no-capacity as fall-through.** `NoComputeAvailableError`-class capacity miss falls to the next lane (router contract) — a SPOT/flex-start capacity miss within the validity window is the same fall-through.

The live SPOT-preempt rehearsal (deliberately injecting a preemption on a real VM) is **opt-in / follow-up** — it costs real GCP credit. This task's deliverable-3 validation = the contract review above + the idempotency unit tests below.
