## Requirement

Close the phantom-body-edit channel from incident #2333 (interpretation round 4): an
analyzer posted `epm:interpretation v4` claiming two body edits applied + a verifier
PASS while `body.md` stayed byte-identical to the prior commit. Root mechanism
(forensically established in #2333): the agent edited one copy of the body and handed
`set-body` a different copy; `_git_commit` silently early-returns when nothing is
staged, so git no-op'd on identical bytes; the marker recorded success anyway. Same
family as #2034 (durable claim written without probing the durable state it asserts).

Fix shape prescribed by the task body ("cheapest robust form"), pinned by the title:

1. `set_body` FAILS LOUD when the incoming body is byte-identical to the current
   body (a provable no-op), with an explicit opt-out for deliberate idempotent
   re-application.
2. `.claude/agents/analyzer.md` gains a landing-verification duty: after every
   `set-body`, re-read the live body + confirm the fresh commit sha before posting
   any marker that claims body edits.

## Acceptance criteria

- AC1: `task_workflow.set_body(N, <body identical to current>)` raises a typed error
  BEFORE any side effect (no `original-body.md` snapshot, no git commit, no registry
  write) — mirroring the Goal-H2 drop guard's no-side-effects-on-refusal contract.
- AC2: `set_body(..., allow_noop=True)` / CLI `--allow-noop` permits the write (the
  deliberate idempotent re-application escape).
- AC3: An identical body accompanied by a REAL frontmatter effect (a
  `_SET_BODY_ROUNDTRIP_KEYS` key — `paper`/`abstract` — changing value) is NOT
  refused: the write has a real effect (frontmatter + REGISTRY). A repeated
  identical write (key present, value unchanged) IS refused.
- AC4: Every identified `set_body` consumer carries an explicit disposition
  (§ Caller dispositions below): mechanical state-sync writers and the dashboard
  body-editor save get `allow_noop` (idempotent-save semantics); the
  address-comments Claude-rewrite path deliberately stays fail-loud (an unchanged
  rewrite stamping `addressed_in` is itself the phantom-edit class).
- AC5: `.claude/agents/analyzer.md` carries the landing-verification duty (re-read
  live body, grep ≥1 distinctive edited string, confirm fresh commit sha on body.md,
  record the sha in the round's marker note as `body_commit=<sha>`), with the
  refusal-handling instruction covering BOTH the wrong-copy case and the
  crash-resume already-landed case (§4 below).
- AC6: Tests pin AC1-AC4 (incl. a task_state threading test) + the CLI flag
  threading + clean-SystemExit refusal shape; the two existing CLI tests that pin
  the exact kwarg set are updated in the same round.
- AC7: `workflow_lint.py` no-flags run + ruff pass on touched files; mapped tests
  (`select_step9c_tests.py --map-files`) green.

## Method delta

New guard mirrors the existing Goal-H2 drop guard in the SAME function (typed error
class + hoisted-before-side-effects check + CLI flag + clean SystemExit): no new
architecture, one new comparison. Delta vs the task body's wider candidate list: the
`post-marker` pre-post hook (gating `epm:interpretation` kinds on a fresh body
commit) is NOT implemented — the set-body guard makes the phantom state impossible
to create silently at the write layer (the single funnel all local body writes pass
through), while a marker-side gate would couple `post-marker` to git-history
inspection for selected kinds and still miss markers phrased without a recognized
kind. The analyzer duty covers the marker-side residual (an agent posting a
body-edit marker without calling set-body at all remains possible but becomes
auditable via the required `body_commit=<sha>` note token). Decision recorded per
autonomous-mode rules.

### 1. `src/explore_persona_space/task_workflow.py`

- New exception beside `GoalH2DropError` (~line 6315):

```python
class SetBodyNoOpError(ValueError):
    """set_body refused: the incoming body is byte-identical to the current
    body and no roundtrip frontmatter key changes — the write is a provable
    no-op (phantom-edit channel, incident #2333)."""
```

- `set_body(...)` signature gains `allow_noop: bool = False`.
- Guard placement: after `body_text = _strip_leading_frontmatter_blocks(new_body)`,
  BEFORE the Goal-H2 guard and BEFORE the snapshot copy (refusal writes NOTHING).
  Capture `fm_before` (the on-disk values of the roundtrip keys) BEFORE the
  carry-forward loop mutates `fm`. Comparison uses the same normalization
  `_write_body` receives (round-trip symmetry of `_split_frontmatter` /
  `_join_frontmatter` verified at plan time — the body region passes through
  verbatim, so `new_norm` vs `prior_body` compares exactly what would be written
  against exactly what is on disk):

```python
new_norm = body_text if body_text.endswith("\n") else body_text + "\n"
roundtrip_effect = any(
    key in incoming_fm
    and incoming_fm[key] is not None
    and fm_before.get(key) != incoming_fm[key]
    for key in _SET_BODY_ROUNDTRIP_KEYS
)
if not allow_noop and new_norm == prior_body and not roundtrip_effect:
    raise SetBodyNoOpError(...)
```

- Error message names: the mechanism ("the file handed to set-body does not differ
  from the current body — either the edits were applied to a different copy / never
  applied, OR this body already landed (crash-resume); incident #2333"), the escape
  (`allow_noop=True` / `--allow-noop`) with its one legitimate use (deliberate
  idempotent re-application), and the remedy (check `git log -1 -- <body.md path>`
  and diff your edited copy against `$(task.py find N)/body.md`).
- Docstring: add a short guard paragraph after the Goal-H2 paragraph.
- Guard ordering note: an identical body has the same `_has_goal_h2` value as the
  prior body, so the two guards can never fire on the same input; the no-op guard
  runs first.

### 4. `.claude/agents/analyzer.md`

Add a compact "Landing verification after every set-body (REQUIRED — #2333)" block
adjacent to the existing set-body handoff instructions:

- After EVERY `task.py set-body` call, in the SAME turn, BEFORE posting any marker
  that claims body edits: (a) re-read the LIVE body
  (`$(uv run python scripts/task.py find <N>)/body.md`) and grep for ≥1 distinctive
  string from this round's edits; (b) confirm a fresh commit touched body.md
  (`git log -1 --format='%h %cI' -- <that path>`) and that it postdates the round
  start; (c) record that sha in the round's marker note (`body_commit=<sha>`).
- On a `set-body: no-op` refusal, run duty step (a) FIRST: re-read the live body
  and check the latest body.md commit. If this round's edits are ALREADY live (the
  crash-resume case: a prior invocation landed the commit before the marker
  posted), the round's body work is DONE — proceed to the marker with the existing
  commit's sha; no retry and no `--allow-noop` needed. Only if the edits are NOT
  live does the refusal mean you passed the wrong copy: find the file you actually
  edited, re-diff, re-run set-body with that file. `--allow-noop` is only for a
  deliberate re-application of an already-landed body.
