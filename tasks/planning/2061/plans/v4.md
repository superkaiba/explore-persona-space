# Plan — task #2061: Does post-training make particular SAE features more predictable from context?

## Goal (verbatim from frontmatter)

Fit a map from the pooled context activation to the SAE feature vector of the answer state, holding ONE fixed SAE dictionary across every post-training stage of an open ladder, and determine whether any individual SAE feature's per-feature held-out predictability improves across adjacent stage transitions beyond a selection-symmetric null over the whole dictionary.

### TDD: no

## §6 Measurement validity

**Per-DV declaration** (planner.md §6):

- **Construct**: which SAE features of the ANSWER state at layer 29 become MORE linearly predictable from the pooled context activation (also at layer 29) after each adjacent post-training stage transition.
- **Metric**: per-feature held-out R²_j from a ridge regression `g: c_x → f(a_x)` fitted per (stage, corpus, arm) cell, K=5 group folds, fold seed 0, pooled R² with fold-local test means. ΔR²_j = R²_j(stage_after) − R²_j(stage_before). Headline statistic: `max_{j, cell} ΔR²_j` vs a GLOBAL selection-symmetric null (per-draw max over `(feature j, delta cell)` under one shared `draw_seed_schedule` across all 64 (stage-pair, corpus, arm) delta cells; per-cell p97.5 retained as a secondary diagnostic).
- **On-distribution**: **YES** — the map is fit on the ACTUAL post-training checkpoints' activations (Llama-3.1-8B Tülu-3 base / SFT / DPO / RLVR / longer-RLVR), on-policy contexts sampled from the same 8 corpora #1336 banked (real-user LMSYS chat, established GSM8K / MATH benchmarks, IF/UF/SFT rows). No off-policy substitution, no teacher-forcing artifact (the SAE encode of the answer state is a forward pass on the same banked activations).
- **Saturation check**: per-stage FVE / L0 / dead-feature-count on the fixed dictionary (§ Cross-stage SAE-fitness confound control below) is the pre-registered saturation / instrument-fitness gate. A stage whose FVE falls below 80% of the base-stage FVE is reported per-transition with an explicit scope caveat, not aggregated.
- **Dual-DV**: N/A — the DV is R²_j (continuous by construction — a scalar from a well-posed ridge regression per feature per fold). The selection-symmetric null is the multiple-comparisons discipline, not a companion DV.

## §7 Success + kill criteria

**Success criteria (quantitative thresholds)**:
- **Primary decision rule (GLOBAL max, cell-level selection-symmetric)**: **At least one (feature j, delta cell) pair exists** with true ΔR²_j exceeding the p97.5 quantile of the null distribution of `max_{j, cell} ΔR²_j` — the GLOBAL max over both the feature axis (d_sae=262144) AND the delta-cell axis (64 cells) taken per draw under one SYNCHRONIZED draw-index schedule. This closes the cell-level selection-asymmetry loophole a per-cell p97.5 would leave open (a positive rate of ~5% per cell yields ~3.2 spurious cells at random over 64 cells; the global max rides both axes per draw). Report the winning (feature id, stage-pair, corpus, arm) tuple, its ΔR²_j, the GLOBAL null p97.5, and the fraction of (j, cell) pairs clearing the global bar.
- **Secondary per-cell reads** (retained diagnostics, non-headline): (i) per-cell p97.5 of null `max_j ΔR²_j` — the local-only quantile the global test dominates; (ii) cross-corpus rank-agreement of the top-100 improved features per transition (are the same features improving across corpora, or is each corpus surfacing corpus-specific features?). Higher rank-agreement supports a stage-general improvement mechanism; lower agreement supports corpus-specific fits.
- **Diagnostic pass bar**: per-stage FVE ≥ 0.8 × base_FVE on all 5 stages, L0 ∈ [10, 200] for the fixed dictionary applied at each stage, dead-feature fraction < 10% of d_sae. Fail on any of these → the headline is reported per-transition with an explicit fitness-drift scope caveat, never aggregated.

**Kill criteria (what result would kill the hypothesis)**:
- **Kill (falsification)**: the maximum ΔR²_j over the true assignment (max over both j AND delta cell) lies WITHIN the GLOBAL selection-symmetric null band (below the p97.5 quantile of the global null distribution). This is the direct falsification of the hypothesis.
- **Under-determined-cell mitigation (data-integrity gate)** — supersedes the earlier n_train < 4096 halt: on any (stage, corpus) cell where verified per-fold n_train is below d_in=4096, the ridge fit adopts the reused-instrument's own registered mitigation — **GCV dof-cap = 0.9** in `ridge_fit_predict_fast_layer_batched` (`.claude/rules/artifact-reuse.md` check (l) validity-domain transfer + #1887 GCV-under-determined convention; the shared #825 fit cores default GCV to run WITH a dof cap, default 0.9, and expose selected-λ diagnostics per fit). No halt on n_train < d_in; the mitigation IS the halt-free path. Report selected-λ diagnostics (per-fit λ + effective dof) alongside every ridge read for verifier legibility. This mitigation binds on cells with verified per-fold n_train < 4096 (see the n_train reconciliation table below).
- **Halt and report (SAE-fitness gate)**: if per-stage FVE < 0.5 × base_FVE (a hard drift floor beyond the graded 0.8 bar), that stage's ridge fit is uninterpretable against the fixed dictionary — halt and report the drift; do not include the stage in the headline aggregate.

## Hypothesis

**If** the Llama-3.1-8B Tülu-3 post-training stages (SFT / DPO / RLVR / longer-RLVR) preferentially strengthen the LINEAR predictability of specific interpretable SAE features (of the answer state) from the pooled context activation, **then** at least one (feature j, delta cell) pair exists whose true ΔR²_j exceeds the p97.5 quantile of the GLOBAL selection-symmetric null (per-draw max over `(feature j, delta cell)` across all 64 (stage-pair, corpus, arm) delta cells, under one shared `draw_seed_schedule`).

**Falsification**: the maximum ΔR²_j over the true assignment (max over both j AND delta cell) lies within the GLOBAL selection-symmetric null band. (Bright-line quantitative test: `max_{j, cell} ΔR²_j` vs the GLOBAL null p97.5 computed over `{global_max_d = max_cell max_j_d : d = 0..999}`.)

## Design

### The 4-axis grid

| Axis | Levels | Count |
|---|---|---|
| Stage | base, SFT, DPO, RLVR, longer-RLVR | 5 |
| Corpus | #1336's 8 corpora (LMSYS chat, GSM8K, MATH, IF/UF/SFT rows, …) | 8 |
| Mapping arm | prefix (`v_P`), context (`v_C`) | 2 |
| Layer | L29 resid (headline) | 1 |

= **80 (stage, corpus, arm) fit cells** per layer. Layer L23 resid is a plan-§9-costed ablation only when L29 comes back clean (executed conditionally; not in the base budget below).

### Per-cell fit

For each (stage s, corpus c, arm a) cell:
- **Input** X = the pooled context activation at layer 29 (shape `(n_c, d_in=4096)`), reused from #1336's `issue1336_rlvr_ladder/` banked activations. The `prefix` arm pools over prefix tokens only; the `context` arm pools over prefix+query. Pooling convention matches #1336 (mean-pool at layer 29 — record the exact convention at implementation time by reading #1336's fit-cell script, verify at Phase 1.5).
- **Target** Y = SAE feature vector of the **answer** state, encoded by the fixed EleutherAI/sae-llama-3.1-8b-64x at `layers.29/`. Shape `(n_c, d_sae=262144)`. TopK activation with k=32, so Y is sparse per row but the target matrix is not sparse across rows.
- **Fit** g: X → Y as a ridge regression in the INPUT space (n × 4096; well-posed at n_train ≫ d_in). Per-feature R²_j is derived column-by-column from the fitted map's held-out predictions — d_sae does NOT gate ridge well-posedness, since each output column is one scalar regression on the same 4096-dim input.
- **Folds** K=5 group-level folds with fold seed 0, inherited from #1336. LOFO / LOCO groupings match #1336's own convention.
- **Estimator**: the shared factorization `ridge_fit_predict_fast_layer_batched` (`src/explore_persona_space/experiments/issue_779/fit_h.py:180`) — one Gram/dual-space eigendecomposition per (stage, corpus, arm) cell, applied to every column of the SAE target simultaneously. GCV over `np.logspace(-2, 4, 13)` for λ (the #779/#823 convention). Numeric-parity gate against the SVD reference on 3 slices per cell family at production shape (per its docstring).
- **Per-feature R²_j**: `1 - ||f_j − ĝ_j||² / ||f_j − mean(f_j)||²` on the held-out folds (K-fold aggregated). Stored as an `(n_stages × n_corpora × n_arms × d_sae)` array = 20800 × d_sae = ~5.4B floats total; store as sparse-per-cell (only features with any nonzero activation in the pool are informative) OR chunked (recommended: `(d_sae,)` per (stage, corpus, arm) cell = ~1 MB per cell = ~80 MB total).

### Cross-stage delta

For each adjacent stage pair (base→SFT, SFT→DPO, DPO→RLVR, RLVR→longer-RLVR) × 8 corpora × 2 arms = **64 (stage-pair, corpus, arm) delta cells**:
- ΔR²_j = R²_j(stage_after, corpus, arm) − R²_j(stage_before, corpus, arm), per feature.
- **Headline statistic**: max_j ΔR²_j (per delta cell); tail-shape distribution over j.

### Selection-symmetric null (SYNCHRONIZED across cells for a per-draw GLOBAL max)

The null follows `.claude/rules/selection-symmetric-nulls.md` § "max/argmax/top-k over a free axis" with the axis expanded to (feature j, delta cell):
- **Draws**: 1000 permutation draws (headline default, informed by #778 batched-null-battery capacity — reduce to 500 if per-cell wall dominates).
- **Draw-index synchronization (load-bearing for the GLOBAL max)**: ONE shared permutation seed schedule (`draw_seed_schedule = [42 + d for d in range(1000)]`) applied across ALL 64 (stage-pair, corpus, arm) delta cells; draw index `d` uses the SAME seed on every cell. Same 64,000 draw-fits already costed (§9 P3), different reduction.
- **Draw recipe (per cell, per draw d)**: for each draw, shuffle the STAGE label within-corpus (permute which rows come from stage_after vs stage_before) under `seed=draw_seed_schedule[d]`, refit the same ridge (shared factorization is invariant to row permutation) or re-derive R²_j analytically per feature, and record `max_j_d = max_j ΔR²_j` for that (cell, draw) pair. Batched per `.claude/rules/vectorize-many-cell-fits.md` — precompute the pool reduction once, all draws as one batched masked GEMM (~70× vs serial).
- **Per-draw GLOBAL max reduction (PRIMARY null quantile)**: after all 64 cells complete each draw d, form `global_max_d = max_{cell} max_j_d` — the null distribution of the joint (feature × cell) selection statistic. Report the p50 / p95 / p97.5 / p99 quantiles of this GLOBAL null distribution. The headline test is `max_{j, cell} ΔR²_j` on the true assignment vs the GLOBAL null p97.5. This closes the cell-level selection asymmetry a per-cell p97.5 would leave open (a 5%-per-cell false-positive rate compounds to ~3.2 spurious cells expected at random over 64; the global max rides both axes per draw).
- **Per-cell p97.5 (SECONDARY, retained as a per-cell diagnostic)**: computed from `{max_j_d : d = 0..999}` per cell — the same 64,000 draw-fits, different reduction. Used for per-cell diagnostic reads only, never a headline verdict.
- **Persistence contract (`issue2061_null.py` output schema)**: alongside the p50/p95/p97.5/p99 quantiles, PERSIST the per-draw `max_j_d` values (1000 scalars per cell × 64 cells = 64,000 scalars total, KB-scale) so the GLOBAL max reduction is recoverable AND any analyzer re-reduction (bootstrap CI on the global p97.5, alternative axis unions, etc.) can be applied post-hoc without recomputing the null battery. Emit as `null_max_j_per_draw` (shape `(n_draws=1000,)` float32) alongside `null_quantiles_per_cell` in each per-cell JSONL row; the shared draw_seed_schedule + per-cell max_j_d arrays reconstruct the GLOBAL null distribution deterministically.
- **Verdict**: `max_{j, cell} ΔR²_j` from the true assignment vs the p97.5 quantile of the GLOBAL null distribution over `{global_max_d}`. Any true (j, cell) pair exceeding the global p97.5 is a candidate improvement; the headline is whether ANY (feature, cell) pair clears the global bar.

### Cross-stage SAE-fitness confound control

Per-stage FVE / L0 / dead-feature-count on the FIXED dictionary applied to EACH stage's banked activations (LMSYS validation slice, ~1k rows; the same slice for every stage). Follows the #1482 SAE token-pool recipe (`.claude/rules/gotchas.md` #1482 entry): BOS-offset strip (first 8 positions), outlier-norm filter (L2 > 10× pool median), var-based FVE (`1 − var(x − x̂) / var(x)` summed per-dim unbiased variance).

Pre-registered pass/fail bar (per `.claude/rules/gotchas.md` #1482 published-reference figure for the andyrdt Qwen2.5-7B suite of ~0.806 FVE at k=64; for the EleutherAI Llama base SAE at k=32 the published FVE benchmark is not reported on the model card — verify at implementation time; if unavailable, use the BASE stage's own measured FVE as the reference and require **≥ 80% of the base-stage FVE** at every post-training stage):

- **Base FVE reference**: measured on `meta-llama/Meta-Llama-3.1-8B` layer 29 (~1k LMSYS validation rows, same BOS-strip + outlier filter).
- **Pass**: every post-training stage's FVE on its own banked activations ≥ 0.8 × base_FVE; L0 stays in [10, 200] on the fixed dictionary; dead-feature fraction stays < 10% of d_sae.
- **Fail**: any stage's FVE < 0.8 × base_FVE → the fixed-dictionary assumption is broken for that stage; the clean-result carries the fitness drift as a scope caveat and the headline is reported per-stage-pair, not aggregated.

### Prefix mapping AND context mapping — matched-target discipline

Both arms per the CLAUDE.md Critical Rule. Both arms are scored against the SAME SAE-encoded answer target (only the input side changes: prefix pooling vs context pooling). No arm-specific target — this closes the #1092 cross-arm-mismatch class the compose-time re-grep rule mandates.

## Risks

1. **Estimator degeneracy at n_train < d_in**: MITIGATED. Fit is ridge in input space (n × d_in=4096); at n_train > d_in the fit is well-posed (all corpora except `gsm8k_test1319`, per the §7 reconciliation table — 4 of 5 stems have per-fold n_train ranging ~5,978 to ~18,400, well above 4096). For `gsm8k_test1319` (per-fold n_train ~1,055 < 4096), the fit runs in Gram-space with GCV dof-cap = 0.9 — the reused-instrument's registered mitigation (`.claude/rules/artifact-reuse.md` check (l), #1887 project convention; the shared #825 fit cores default GCV to run WITH a dof cap and expose per-fit λ + effective dof for verifier legibility). Per-feature R²_j is one scalar column of the same well-posed fit.
2. **Cross-stage SAE-fitness drift**: MITIGATED by the per-stage FVE / L0 / dead-feature-count gate. If drift breaks the fitness bar, the headline is reported per-transition, not aggregated.

4. **Loader adapter bug**: MITIGATED by the loader-parity smoke gate (FVE vs reference within 0.05).
5. **Layer choice (L29 vs #1336's L30 headline)**: L30 is not SAE-available; L29 is the nearest banked-and-SAE-available layer. State this in the clean-result scope caveat.
6. **`sparsify`-format TopK edge cases**: the encode step's TopK threshold semantics (fixed scalar per SAE card vs learned per-cell) — verify at implementation time by reading the `cfg.json` and cross-checking against the `sparsify` package's encode function. Fact-checker task.
