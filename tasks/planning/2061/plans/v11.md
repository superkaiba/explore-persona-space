### Cross-stage delta

For each adjacent stage pair (base→SFT, SFT→DPO, DPO→RLVR, RLVR→longer-RLVR) × 7 combos × 2 arms = **56 (stage-pair, corpus, arm) delta cells**:
- ΔR²_j = R²_j(stage_after, corpus, arm) − R²_j(stage_before, corpus, arm), per feature.
- **Headline statistic**: max_j ΔR²_j (per delta cell); tail-shape distribution over j.

### Cross-stage SAE-fitness confound control

Per-stage FVE / L0 / activated-feature count (plus the DESCRIPTIVE absolute dead-feature fraction) on the FIXED dictionary applied to EACH stage's banked activations (LMSYS validation slice, ~1k rows from the v2 `lmsys23k` store; the same slice for every stage — the slice stays sourced from the v2 extension store under v11, a deliberate fixed subset: the gate's construct is cross-stage drift on a FIXED row set, indifferent to which fixed subset). Follows the #1482 SAE token-pool recipe (`.claude/rules/gotchas.md` #1482 entry): BOS-offset strip (first 8 positions), outlier-norm filter (L2 > 10× pool median), var-based FVE (`1 − var(x − x̂) / var(x)` summed per-dim unbiased variance).

Pre-registered pass/fail bar (per `.claude/rules/gotchas.md` #1482 published-reference figure for the andyrdt Qwen2.5-7B suite of ~0.806 FVE at k=64; for the EleutherAI Llama base SAE at k=32 the published FVE benchmark is not reported on the model card — verify at implementation time; if unavailable, use the BASE stage's own measured FVE as the reference and require **≥ 80% of the base-stage FVE** at every post-training stage):

- **Base FVE reference**: measured on `meta-llama/Meta-Llama-3.1-8B` layer 29 (~1k LMSYS validation rows, same BOS-strip + outlier filter).
- **Pass**: every post-training stage's FVE on its own banked activations ≥ 0.8 × base_FVE; L0 stays in [10, 200] on the fixed dictionary; per-stage activated-feature count A_s ≥ 0.8 × A_base (the dead-feature leg re-registered RELATIVE — v7, LANDED; see the re-registration paragraph below).
- **Fail**: any stage's FVE < 0.8 × base_FVE → the fixed-dictionary assumption is broken for that stage; the clean-result carries the fitness drift as a scope caveat and the headline is reported per-stage-pair, not aggregated.

**Dead-feature leg re-registration (v7 — resolves the open `dead-feature-bar-unsatisfiable-at-1k-pool` CONCERN, round-2 `epm:code-review` v2; LANDED in `issue2061_fitness.py`).** The v6 absolute bar (dead fraction < 10% of d_sae) is unsatisfiable by pool-ceiling arithmetic: N_VAL_ROWS = 1,000 × k = 32 bounds the activatable features at 32,000 (fewer in practice — rows share features) of d_sae = 262,144, so dead ≥ 1 − 32,000/262,144 = 87.8% on EVERY stage, base included; `dead_ok` is always False and every stage lands FAIL_SOFT on an arithmetic artifact, independent of dictionary health (the #1345 gate-calibration class). The absolute bar was also the wrong CONSTRUCT for this gate: it tests dictionary-vs-corpus health (pool-size-dependent), while the gate's job is CROSS-STAGE drift — which the FVE leg already encodes relative to base. **Re-registered relative, matching the FVE leg's structure: A_s = count of distinct features with ≥ 1 activation on the fixed ~1k-row slice (the SAME slice for every stage, so the pool ceiling cancels); gate leg: A_s ≥ 0.8 × A_base.** Satisfiable by construction (base is its own reference; bar = 0.8 × A_base ≤ 0.8 × 32,000 = 25,600); a stage whose active-feature diversity collapses ≥ 20% vs base fails — exactly the drift construct. The absolute dead fraction vs d_sae is RETAINED as a DESCRIPTIVE field in the per-stage JSON (with the 87.8%-floor arithmetic stated beside it), never a gate. Alternatives rejected: (a) enlarging the slice — making the absolute < 10% bar merely satisfiable needs ≥ 0.9 × 262,144 / 32 ≈ 7,373 rows at zero feature reuse and realistically far more, and the RedPajama-base-fit dictionary would plausibly fail an absolute bar on ANY chat slice for reasons unrelated to cross-stage drift (base fails ⇒ the gate never isolates drift); (b) demoting the whole leg to descriptive-only — weaker: a real collapse in active-feature diversity SHOULD gate. The FVE 0.8× graded bar, the FVE 0.5× HALT floor (`FVE_HARD_FLOOR = 0.50`), and the L0 ∈ [10, 200] leg (≈ 32 by construction under TopK k=32 — a loader-sanity read, kept) are UNCHANGED.
