## 4. Design

### 4.1 The regex and its justification (grounded on Grep evidence)

**Empirical distribution.** A bare `/[a-z][a-z0-9-]+` over the workflow surface (CLAUDE.md, `.claude/agents`, `.claude/skills`, `.claude/rules`, `.claude/workflow.yaml`, `.claude/mentor-update-slides`) returns ~120 distinct tokens, dominated by **non-skill** noise: absolute paths (`/workspace` 93, `/tmp` 89, `/dev` 27, `/mnt` 12, `/home` 6, `/root` 3, `/var` 1), URL path segments (`/tree` 32, `/blob` 22, `/tasks` 4, `/runs` 9), repo dir paths (`/scripts` 24, `/docs` 10, `/figures` 9, `/plans` 19, `/artifacts` 12, `/data` 3, `/papers` 2), prose fragments (`/hr` 8, `/each` 7, `/small` 14, `/details` 12, `/body` 10, `/log` 3), and marker tokens (`/epm` 31, `/workflow-fix-candidate` 3). A "FAIL on any unresolved token" design over this is unusable.

**Two boundary signals + balanced backticks isolate real refs.** Testing successive tightenings against the actual surface:

1. **Balanced backtick span.** Real skill invocations are written in the markdown command convention `` `/issue` `` / `` `/issue <N>` `` / `` `/issue 137 --auto` ``. The matched span must OPEN with a backtick immediately followed by `/`, and CLOSE with a backtick. This kills bare-prose fragments (`$X/hr`, `and/or`) and the adjacent-backtick artifact (`` `false`/absent ``, `` `.npz`/binary `` — a *closing* backtick followed by `/word`), which a "backtick somewhere to the left" rule wrongly matched.
2. **No internal slash in the token.** The captured token is `[a-z][a-z0-9-]*` with NO `/` — so `` `/workspace/.cache/huggingface` `` and `` `/workspace/logs/issue-<N>` `` (the dominant `/workspace` shape) do NOT match as a skill token (the `/workspace` prefix is immediately followed by `/`). This is the analogue of `SCRIPT_REF_RE`'s left-boundary anchor.
3. **Token is lowercase + hyphen only**, matching the live-skill naming convention (`adversarial-planner`, `promote-clean-result`, `group-promotion-queue`).

**The regex (module constant):**

```python
# `--check-skill-refs`: a slash-command reference written in the markdown
# command convention — a BALANCED backtick span opening with `/` and a
# lowercase[-hyphen] skill name — MUST resolve to a live skill under
# `.claude/skills/<name>/SKILL.md` or to an entry in
# `.claude/skill_ref_allowlist.txt`. Catches the dangling-skill-ref rot
# class: when a skill is retired/renamed (e.g. /workflow-improver), every
# stale `/<name>` mention across the workflow surface silently rots
# (today's only guard is a hand-run grep per change — #713 §12/§7).
SKILL_REF_RE = re.compile(
    r"`/(?P<name>[a-z][a-z0-9-]*)(?P<sub>:[a-z][a-z0-9-]+)?(?P<args>[ \t][^`\n]*)?`"
)
```

The trailing-backtick anchor is the balanced-span requirement: `[^`\n]*` in `args` cannot cross a backtick or newline, so the close backtick must appear on the same line within the span. **The implementer MUST add a unit test asserting `` `false`/absent ... `` does not match** (the trickiest residual; see §15 deviations).

### 4.2 Plugin-namespaced refs (`/foo:bar`) — resolution rule

**Critical filesystem finding (corrects the task body's premise):** the task body assumed `/codex:rescue` resolves against `.claude/skills/codex/rescue/SKILL.md`. **It does not** — `ls -d .claude/skills/*/` shows ONLY the 21 EPS-native skills; there is NO `codex/`, `superpowers/`, `code-review/`, `huggingface-skills/`, or `frontend-design/` directory in the repo. Those plugin-namespaced skills are loaded by the Claude Code harness from external plugins and never live in the version-controlled tree. Resolving them against the repo filesystem is therefore impossible by construction.

**Resolution algorithm:**

1. If `sub` group is present (a `/foo:bar` namespaced ref), the token is `foo:bar`. **Namespaced refs NEVER resolve against `.claude/skills/`** (no such layout exists). They resolve ONLY against the allowlist. Since plugin availability is harness-config-dependent and not version-controlled, the allowlist treats `*:` namespaced refs permissively: **any ref of the form `/<ns>:<name>` where `<ns>` is one of a declared plugin-namespace allowlist (`codex`, `superpowers`, `code-review`, `huggingface-skills`, `frontend-design`, `ml-paper-writing`, `academic-writing-agents`, `vercel`) PASSes** without enumerating every sub-skill (sub-skills churn with plugin versions; enumerating them would make the lint brittle against external plugin updates we don't control). A `/<ns>:<name>` whose `<ns>` is NOT in the namespace allowlist FAILs.
2. If `sub` group is absent (a bare `/foo` ref), resolve `foo` against the **live in-repo skill set** = `{d.name for d in .claude/skills/*/ if (d / "SKILL.md").exists()}` — i.e. top-level skill dirs with a `SKILL.md`. (Note `clean-results/` has no top-level `SKILL.md`, so it is correctly NOT a live `/clean-results` invocation target — and indeed no `` `/clean-results` `` ref exists in the surface.) If unresolved, fall through to the bare-token allowlist.

The allowlist file therefore has **two sections**: bare tokens, and namespace prefixes (lines ending in `:`).

### 4.3 Allowlist file — path, format, INITIAL CONTENTS

**Path:** new file `.claude/skill_ref_allowlist.txt` (mirrors the dedicated-mechanism precedent of `SCRIPT_REF_RE`; chosen over an in-source frozenset because the entries are config-like data, the file reads cleaner than a 15-entry commented frozenset, and it is greppable/diffable as plain data).

**Format:** one token per line; `#` comments and blank lines ignored; a line ending in `:` is a plugin-namespace prefix; everything else is a bare token (with or without a leading `/` — the parser strips a leading `/` for tolerance). The parser:

```python
def _load_skill_ref_allowlist(path: Path) -> tuple[frozenset[str], frozenset[str]]:
    """Return (bare_tokens, namespace_prefixes) from the allowlist file.
    Lines ending in ':' are plugin-namespace prefixes (e.g. 'codex:');
    all other non-comment lines are bare skill tokens. A leading '/' is
    stripped for tolerance. Missing file -> (empty, empty)."""
    bare: set[str] = set()
    ns: set[str] = set()
    if not path.exists():
        return frozenset(), frozenset()
    for raw in path.read_text(encoding="utf-8").splitlines():
        line = raw.split("#", 1)[0].strip()
        if not line:
            continue
        line = line.lstrip("/")
        (ns if line.endswith(":") else bare).add(line)
    return frozenset(bare), frozenset(ns)
```

### 4.4 The function

```python
def check_skill_references(
    *,
    roots: list[Path] | None = None,
    skills_dir: Path | None = None,
    allowlist_path: Path | None = None,
) -> list[str]:
    """Walk .claude/agents/**.md + .claude/skills/**/SKILL.md (+ the bundled
    CLAUDE.md/SKILL.md/markers.md DOC_FILES — see scope note) and FAIL on any
    balanced-backtick slash-command span `/<name>` that resolves to neither a
    live skill (.claude/skills/<name>/SKILL.md) nor an allowlist entry.

    Catches the dangling-skill-ref rot class (#713/#714): a retired/renamed
    skill leaves stale `/<name>` mentions across the workflow surface.

    roots / skills_dir / allowlist_path are test override hooks; production
    callers pass None and the function walks the canonical trees + resolves
    against <repo_root>/.claude/skills and .claude/skill_ref_allowlist.txt.
    """
    errors: list[str] = []
    skills_root = skills_dir if skills_dir is not None else _REPO_ROOT / ".claude" / "skills"
    al_path = (
        allowlist_path if allowlist_path is not None
        else _REPO_ROOT / ".claude" / "skill_ref_allowlist.txt"
    )
    live = {
        d.name for d in skills_root.iterdir()
        if d.is_dir() and (d / "SKILL.md").is_file()
    } if skills_root.exists() else set()
    allow_bare, allow_ns = _load_skill_ref_allowlist(al_path)
    for path in _resolve_skill_ref_target_files(roots):
        if not path.exists():
            continue
        for lineno, line in enumerate(path.read_text(encoding="utf-8").splitlines(), 1):
            if HISTORICAL_REF_OPT_OUT in line:
                continue
            for m in SKILL_REF_RE.finditer(line):
                name = m.group("name")
                sub = m.group("sub")  # ":bar" or None
                if sub:  # plugin-namespaced /ns:name — resolve namespace only
                    if f"{name}:" in allow_ns:
                        continue
                    errors.append(
                        f"{path}:{lineno}: skill ref '/{name}{sub}' uses an "
                        f"unknown plugin namespace '{name}:'. Add '{name}:' to "
                        f".claude/skill_ref_allowlist.txt if it is a real plugin."
                    )
                    continue
                if name in live or name in allow_bare:
                    continue
                errors.append(
                    f"{path}:{lineno}: skill ref '/{name}' resolves to no live "
                    f"skill under .claude/skills/{name}/SKILL.md and is not in "
                    f".claude/skill_ref_allowlist.txt. Repoint to the current "
                    f"skill, remove the dead reference, allowlist it (harness "
                    f"built-in / global skill / gate label), or — for a "
                    f"narrative incident citation only — append "
                    f"'{HISTORICAL_REF_OPT_OUT}' to the line."
                )
    return errors
```

The per-line `HISTORICAL_REF_OPT_OUT` reuse is deliberate: a retired-skill incident citation (e.g. "`/workflow-improver` was retired #678 `<!-- lint: historical-ref -->`") gets the same escape hatch as dead script refs, consistent with the sibling check.

### 4.5 File scope (DOC_FILES vs expanded) — DECISION: expanded, matching `--check-script-refs`

The task title says "DOC_FILES", but the **rot risk spans the whole agent+skill surface**, not just the 3-file `DOC_FILES` tuple (`CLAUDE.md`, `issue/SKILL.md`, `issue/markers.md`). The Grep evidence shows `/<skill>` refs concentrated across `.claude/agents/*.md` and every `SKILL.md` (e.g. `/adversarial-planner` 58, `/campaign` 21 — mostly outside the 3 DOC_FILES). I therefore scope `check_skill_references` to the **same surface as `check_script_references`** — `_resolve_ask_target_files(roots)` (all `.claude/agents/*.md` + all `.claude/skills/**/SKILL.md`, excluding OTHER worktrees) **plus the `DOC_FILES` tuple** (to cover `markers.md`, which is not a `SKILL.md`, and `CLAUDE.md`, which the agents/skills walk does not cover at repo-root). A thin resolver:

```python
def _resolve_skill_ref_target_files(roots: list[Path] | None) -> list[Path]:
    """Skill-ref scope = the --check-script-refs surface (agents + SKILL.md,
    other-worktree-excluded) UNION the DOC_FILES tuple (CLAUDE.md +
    issue/markers.md, which the agents/skills walk does not cover).
    Tests pass roots=[tmp_path] to scope to a fixture."""
    if roots is not None:
        return _resolve_ask_target_files(roots)
    files = list(_resolve_ask_target_files(None))
    for doc in DOC_FILES:
        if doc not in files and doc.exists():
            files.append(doc)
    return sorted(set(files))
```

**Justification for expanded scope:** the whole point of #714 is that a renamed skill rots *anywhere* in the workflow surface, and `--check-script-refs` already proved this surface is the right one for a dead-reference check. Narrowing to 3 files would leave ~90% of the `/<skill>` refs unguarded. The `.claude/rules/*.md` files also carry refs (e.g. `/adversarial-planner` in `contrastive-negatives.md`) — I deliberately do NOT add them to scope in v1 to keep parity with `--check-script-refs` (which also does not scan rules); a follow-up may extend both checks to rules together. (Noted in §15 as a deliberate scope boundary, not an oversight.)

- **Expanded scope (agents+SKILL.md+DOC_FILES) over the 3-file DOC_FILES:** the rot risk is repo-wide; `--check-script-refs` already validated this surface. Source: `check_script_references` scope at line 1130 (`_resolve_ask_target_files`).
