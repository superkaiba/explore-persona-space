`architectural: false` — this is an ADDITIVE CLI flag plus a widening of an internal name parser; no status enum, marker schema, or `task.py` subcommand changes, and every legacy bare `pod-<N>` / `epm-issue-<N>` name parses byte-identically.

## 1. Goal + acceptance criteria

**Goal (Task #1334 `## Goal` H2, verbatim):** "Give `pod.py provision` a first-class multi-pod-per-issue naming form so suffixed pods map to their real owning task."

**Requirement.** An inline follow-up round that needs a SECOND pod for issue N (the canonical `pod-N` name held by a stopped volume) must be able to provision `pod-N-<slug>` that (a) registers `issue=N` in `pods_ephemeral.json`, (b) is visible to `list-ephemeral --issue N`, (c) is auto-mapped to task N by the watcher pod-safety pass (so `keep-running` / `epm:run-launched` signals on task N shield it), (d) is included in the stale-pod audit's owning-task lookup, and (e) is stoppable/resumable/terminable through the normal `--issue N` verbs (with `--name-suffix` narrowing where one specific pod must be targeted).

**Acceptance criteria (all mechanical):**

1. `pod_lifecycle._issue_from_pod_name("pod-779-b") == 779`; `_issue_from_pod_name("pod-779") == 779` and `_issue_from_pod_name("epm-issue-779") == 779` unchanged; `_issue_from_pod_name("thomas-pod-475") is None` unchanged; `_issue_from_pod_name("pod-779-60") is None` (numeric slug rejected).
2. `pod.py provision --issue 779 --intent cpu-mid --name-suffix b --dry-run` prints a plan for pod name `pod-779-b` and its "already exists" pre-flight checks `pod-779-b` (NOT bare `pod-779` — a live `pod-779` must not block the suffixed provision).
3. `_provision_wait_register_bootstrap` registers `EphemeralMetadata(name="pod-779-b", issue=779, ...)` (falls out of the existing `name` threading — verified by test, no code change).
4. `pod_audit._issue_number_from_name` agrees with `pod_lifecycle._issue_from_pod_name` on a shared table of names (parity test), and all 8 existing pinned cases in `tests/test_pod_audit.py::test_issue_number_from_name` still pass.
5. `autonomous_session_watch._running_managed_issue_pods` returns `(779, ..., "pod-779-b", ...)` for a RUNNING `pod-779-b` (no watcher code change — verified by test).
6. `terminate --issue 779 --name-suffix b` terminates ONLY `pod-779-b`, never `pod-779` (and the post-terminate survivors re-check does not false-fire on `pod-779`).
7. `pod_config`'s three name regexes accept the suffixed shape: the MCP env-key strip regex matches `SSH_SERVER_POD-779-B_HOST`, the read-back regex round-trips it to name `pod-779-b`, and the bulk `--refresh-from-api` managed regex matches `pod-779-b` while still rejecting `thomas-pod-475`.
8. `uv run ruff check` clean on touched files; `uv run python scripts/workflow_lint.py` (no-flags) passes; the full pytest files named in §4 pass.

## 3. Design

### 3.1 The canonical grammar (single definition, `scripts/pod_lifecycle.py`)

Replace `_issue_from_pod_name` (L381-394) with a compiled-regex parser and add the module constant right after `_MANAGED_PREFIXES` (L369):

```python
# Canonical managed-pod name grammar (#1334). Bare form: pod-<N> /
# epm-issue-<N> (unchanged). Suffixed multi-pod-per-issue form:
# pod-<N>-<slug> where slug is lowercase, LETTER-INITIAL
# ([a-z][a-z0-9-]*). Letter-initial is load-bearing: it keeps an
# all-numeric tail (pod-77960, the fabricated-id incident shape) and a
# numeric slug (pod-779-60) OUT of the suffix grammar, so a digits-only
# name can never be ambiguously attributed. epm-issue-<N>-<slug> is
# accepted for legacy dispatcher pods (pod_audit precedent).
_POD_NAME_RE = re.compile(
    r"^(?:pod|epm-issue)-(?P<issue>\d+)(?:-(?P<slug>[a-z][a-z0-9-]*))?$"
)


def _issue_from_pod_name(name: str) -> int | None:
    """Extract the owning issue from a managed pod name.

    Accepts the canonical ``pod-<N>``, the legacy ``epm-issue-<N>``, and
    the suffixed multi-pod-per-issue form ``pod-<N>-<slug>`` (#1334;
    slug = ``[a-z][a-z0-9-]*``). ``pod-47`` never matches issue 475
    (the digits must be followed by ``-<slug>`` or end-of-string).
    Returns ``None`` for non-managed / unparseable names.
    """
    m = _POD_NAME_RE.match(name)
    return int(m.group("issue")) if m else None
```

`_MANAGED_PREFIXES` / `_is_managed_pod` are UNCHANGED (a suffixed pod already startswith `pod-`, so it is already "managed"; it was merely unmappable).

| name | old lifecycle | old audit | NEW (both) |
|---|---|---|---|
| `pod-47` | 47 | 47 | 47 |
| `pod-475` | 475 | 475 | 475 |
| `epm-issue-475` | 475 | 475 | 475 |
| `pod-475-backup` | None | 475 | **475** (deliberate lifecycle change) |
| `pod-779-b` | None | 779 | **779** |

### 3.3 stop / resume / terminate resolution semantics (DECIDED)

**`_find_pod_in_state` (L536-546)** gains a keyword arg + a documented fallback:

```python
def _pods_in_state_for_issue(state: dict[str, EphemeralPod], issue: int) -> list[EphemeralPod]:
    """All registered pods whose metadata records this owning issue, sorted by name."""
    return sorted((p for p in state.values() if p.issue == issue), key=lambda p: p.name)


def _find_pod_in_state(
    state: dict[str, EphemeralPod], issue: int, *, name_suffix: str | None = None
) -> EphemeralPod | None:
    """Locate a registered pod for ``issue``.

    With ``name_suffix``: exact lookup of ``pod-<N>-<slug>`` only.
    Without: canonical ``pod-<N>`` first, then legacy ``epm-issue-<N>``;
    if NEITHER is registered but EXACTLY ONE pod records this owning
    issue (a suffixed follow-up pod, #1334), return it — the callers
    print the resolved name before acting. Zero or >1 issue-matching
    pods -> None (callers direct the user to --name-suffix).
    """
    if name_suffix is not None:
        return state.get(_canonical_pod_name(issue, name_suffix))
    for candidate in (_canonical_pod_name(issue), f"epm-issue-{issue}"):
        if candidate in state:
            return state[candidate]
    matches = _pods_in_state_for_issue(state, issue)
    return matches[0] if len(matches) == 1 else None
```

- **`cmd_stop` / `cmd_resume`** gain `--name-suffix` (threaded into `_find_pod_in_state`). Their "No ephemeral pod recorded for issue N" `SystemExit` message is extended: when `_pods_in_state_for_issue` is non-empty (the ambiguous >1 case), list the names and say "pass `--name-suffix <slug>` to pick one". Both already print the resolved `name` before acting, so the unique-fallback is transparent.
- **`cmd_terminate`** keeps its documented "destroy EVERY live pod for issue N" semantics for the bare form — after the parser fix that now correctly includes suffixed pods (this is the #475-hardening semantics extended, and the interactive confirmation prompt already lists every matched name). NEW: `--name-suffix <slug>` narrows to the single pod:
  - `live_matches = [p for p in _live_pods_for_issue(args.issue) if p.name == target]` where `target = _canonical_pod_name(args.issue, args.name_suffix)` (filter applied when the flag is set);

- **Rationale for terminate's bare-form sweep (decided, documented):** the follow-up-pod use case needs a way to destroy `pod-779-b` WITHOUT destroying `pod-779`'s stopped volume — that is `--name-suffix`. The bare `terminate --issue N` sweeping all pods matches its existing docstring ("Destroy every live pod for issue #N") and the /issue Step 8 end-of-experiment intent (tear down everything the issue owns). A follow-up pod that must survive an issue-level teardown is shielded the same way the parent pod is: the `keep-running` tag skips Step 8 terminate entirely (task-level, per CLAUDE.md).

### 3.6 `pod_config.py` regex widening (3 sites, 2 shared constants)

Near the top of `scripts/pod_config.py`, add:

```python
# Ephemeral-pod name grammar, mirroring pod_lifecycle._POD_NAME_RE (#1334):
# pod-<digits> optionally followed by -<slug>, slug lowercase letter-initial.
# The ENVKEY variant is the same shape after pod.name.upper() (see
# _generate_mcp_env: env keys embed the upper-cased pod name verbatim).
_EPHEMERAL_NAME_PATTERN = r"pod-\d+(?:-[a-z][a-z0-9-]*)?"
_EPHEMERAL_ENVKEY_PATTERN = r"POD-\d+(?:-[A-Z][A-Z0-9-]*)?"
```

1. **L960 strip regex** (`update_mcp_config.pod_key_re`): `r"^SSH_SERVER_(?:POD\d+|" + _EPHEMERAL_ENVKEY_PATTERN + r"|EPM-ISSUE-\d+|PODepm-issue-\d+)_"` — without this, a terminated suffixed pod's `SSH_SERVER_POD-779-B_*` keys are never stripped from `~/.claude/mcp.json` and accumulate forever. (The `[A-Z0-9-]*` class excludes `_`, so the trailing `_HOST`/`_PORT` anchor still terminates the match correctly.)
2. **L1009-1011 read-back regex** (`_read_mcp_ssh_servers.host_key_re`): same alternative inside the `(?P<suffix>...)` group; `suffix.lower()` then round-trips `POD-779-B` → name `pod-779-b` with zero further change.

The safety comment ("a random RunPod entry is NEVER auto-added") still holds: `thomas-pod-475`, `pod-abc`, `pod-779-60` all fail the anchor/grammar.

`_generate_mcp_env` itself needs NO change (`pod.name.upper()` is shape-agnostic). SSH-config `Host pod-779-b` entries are plain-string writes — no change.
