## 4. Design

### 4.1 File, CLI, exit codes

New file `scripts/sync_repo_root.py` (shebang `#!/usr/bin/env python3`, module docstring, import pattern mirroring `scripts/task.py`; importable functions + `main(argv)` so tests import rather than subprocess where possible).

```
usage: uv run python scripts/sync_repo_root.py [--dry-run] [--no-push] [--json]
                                               [--timeout-s N] [--repo PATH]
```

- `--dry-run`: report divergence (ahead/behind counts), the collision sweep plan (identical/differing/other counts + first 20 paths), husk/stash state; **zero mutations** (no fetch? — fetch IS allowed in dry-run: it only writes `refs/remotes/`, needed to compute the plan; everything else read-only).
- `--no-push`: sync local only (pull + recovery), skip the push leg.
- `--json`: machine-readable `SyncReport` on stdout (human report always on stderr).
- `--timeout-s`: bound for EACH long git subprocess (fetch, pull, push); default 600, env override `EPM_ROOT_SYNC_TIMEOUT_S`.
- `--repo`: test hook; default `task_workflow.primary_checkout_root()` (NOT `repo_root()`, which auto-routes an off-main primary checkout to the managed `_task-main-pin` worktree with a detached HEAD — the helper must operate on the actual primary checkout and enforce main-ness via its own preflight).

Exit codes: `0` synced / already-in-sync / another-sync-in-flight (both benign); `2` aborted on content conflict (clean abort, report emitted); `3` push failed after the one retry; `4` timeout (rebase aborted cleanly); `5` precondition failure (HEAD not `main`, fresh husk present, index.lock persistently held); `6` unexpected git error (fail loud, state cleaned or precisely reported).

### 4.2 Locking (single-flight + writer exclusion)

```python
ROOT_SYNC_LOCK = Path.home() / ".task-workflow" / "root-sync.lock"

def acquire_single_flight() -> int | None:
    # mirror task_workflow._locked() idiom (os.open + fcntl.flock), but NON-blocking:
    fd = os.open(ROOT_SYNC_LOCK, os.O_WRONLY | os.O_CREAT, 0o600)
    try:
        fcntl.flock(fd, fcntl.LOCK_EX | fcntl.LOCK_NB)
    except BlockingIOError:
        os.close(fd)
        return None          # caller prints "another sync in flight", exits 0
    return fd
```

Then, for the mutation window (pre-sweep re-check → pull → recovery → push), additionally acquire the **task-workflow lock** (`task_workflow.LOCK_PATH`) so `task.py` mutations are excluded while the root rebases — this is the index.lock-contention fix for the library-side writers. **Bounded, not blocking** (round-1 Methodology concern, promoted): acquire via `LOCK_NB` + 2s poll up to `EPM_ROOT_SYNC_LOCK2_WAIT_S` (default 120s); still held after the bound → exit 5 with holder evidence (`fuser -v` on the lock file) — a hung task.py holder must not wedge the helper while it holds the root-sync lock (every other caller would exit 0 "in flight" forever, silently persisting the incident state). Lock order is fixed (root-sync lock first, task-workflow lock second) and nothing inside `task_workflow` calls this helper, so no deadlock cycle. Direct `git commit` calls by sessions (not via task.py) are NOT excluded — residual risk, §8 row 3 (a commit landing in an inter-step rebase window goes onto the detached rebase HEAD and is orphaned-but-reflog-recoverable by a later abort; the helper docstring names that recovery).

Preconditions checked under the locks, before any mutation (`preflight(repo) -> None | PreflightError`):
- `git rev-parse --abbrev-ref HEAD` == `main`, else exit 5 (repo-root invariant; the managed-worktree machinery in `task_workflow` owns the non-main pathology).
- `.git/index.lock`: if present, poll every 2s up to 60s; if still present, report path + age + `fuser -v` output and exit 5. **Never delete it** (could be a live git op).
- Husk check: `.git/rebase-merge/` or `.git/rebase-apply/` or `.git/MERGE_HEAD` present →
  - dir/file mtime older than `EPM_ROOT_SYNC_HUSK_AGE_S` (default 3600) → STALE husk: run `git rebase --abort` (verified: restores original HEAD AND re-applies the autostash) / `git merge --abort`, report loudly, continue;
  - younger → someone may be mid-operation: exit 5, report.

### 4.3 Untracked-collision pre-sweep

```python
@dataclasses.dataclass
class Collision:
    path: str          # repo-relative
    kind: str          # "identical" | "differing" | "non-regular"

def enumerate_collisions(repo: Path) -> list[Collision]:
    untracked = set(git("ls-files", "--others", "--exclude-standard").splitlines())
    # exactly the paths a checkout/rebase onto origin/main will write:
    changed = set(git("diff", "--name-only", "HEAD", "origin/main").splitlines())
    out = []
    for p in sorted(untracked & changed):
        fp = repo / p
        if not fp.is_file() or fp.is_symlink():
            out.append(Collision(p, "non-regular")); continue
        local_sha = git("hash-object", "--", p).strip()
        remote_sha = git("rev-parse", f"origin/main:{p}").strip()  # empty/err -> differing
        out.append(Collision(p, "identical" if local_sha == remote_sha else "differing"))
    return out

def sweep(repo, collisions, rescue_dir, dry_run) -> SweepReport:
    # For EACH collision, at action time (round-1 Methodology MF1 + Alternatives
    # binding rec — the enumerate-then-act TOCTOU):
    #   freshness guard: mtime within EPM_ROOT_SYNC_FRESH_S (default 60s) of now
    #       -> treat as "differing" (rescue, never rm) REGARDLESS of hash — a
    #       recently-touched file may be mid-write by a live session;
    #   identical  -> RE-HASH immediately before removal in the same iteration
    #                 (git hash-object); still identical -> os.remove (content is
    #                 byte-identical to the blob at origin/main, which a successful
    #                 pull rematerializes tracked at the same path); mismatch ->
    #                 downgrade to rescue;
    #   differing / non-regular -> shutil.move to rescue_dir / <repo-relative path>
    #                 (dirs created; NEVER deleted; report every path).
    # Every action is recorded in a SWEEP LEDGER (path, kind, action, rescue path,
    # origin blob sha) written to rescue_dir/sweep-manifest.json BEFORE the pull
    # starts — the abort-restore contract below reads it.
```

**Abort-restore contract (round-1 Methodology MF2 — an abort must not leave the
tree missing files it had):** on ANY post-sweep failure exit (2 conflict-abort,
4 timeout-abort, 6 unexpected), the helper restores the swept state from the
ledger before exiting: rescued files are moved BACK to their original paths
(if the path is now occupied by new content, keep the rescue copy and report
the conflict instead of overwriting); identical-removed files are
rematerialized via `git cat-file blob origin/main:<p> > <p>` (plumbing write —
NOT `git checkout origin/main -- <p>`, which would stage index changes).
Every restored / kept-in-rescue path is named in the exit-2/4/6 report. On the
SUCCESS path the ledger is retained in the rescue dir as the run's audit
record. Restore applies only to the sweep's own actions — never any other
working-tree state.

Rescue dir: `~/.task-workflow/root-sync-rescue/<UTC %Y%m%dT%H%M%SZ>/<repo-relative-path>` — OUTSIDE the working tree (so rescued files can never re-collide or be swept again), preserving relative paths for easy manual restore. Reported in full in the SyncReport.

**Error-driven fallback (belt-and-braces):** if the pull STILL fails with the collision error (`untracked working tree files would be overwritten by`, verified exact wording — the tab-indented path list follows, terminated by the `Please move or remove them` line), parse the paths from stderr, sweep exactly those with the same identical/differing rule, retry the pull ONCE. This makes the enumeration self-correcting if `diff --name-only` under-covers an edge (e.g. case-folding, rename detection). Two consecutive collision failures → exit 6 with both path lists in the report.

- **Conflict policy (v1):** any mid-rebase conflict that `merge=union` did not auto-resolve → `git rebase --abort` (empirically verified to restore original HEAD and re-apply the autostash cleanly), report the conflicted paths (`git diff --name-only --diff-filter=U` captured BEFORE the abort), exit 2. - **Stranded-autostash recovery** (`recover_stranded_autostash(repo, rescue_dir) -> StashReport`), runs AFTER a successful pull and ALSO at preflight for entries stranded by PREVIOUS crashed loops:
  1. `git stash list` → entries whose subject is exactly `autostash` (verified: a conflicting autostash reapply after a completed rebase produces `stash@{0}: autostash`, leaves `UU` unmerged paths in the tree, and prints `Applying autostash resulted in conflicts. Your changes are safe in the stash.`).
  2. For each such entry, FIRST export a rescue patch: `git stash show -p -u <ref>` → `rescue_dir/stash-<sha>.patch` (belt-and-braces; never lost even if later steps go wrong).
  3. If the working tree currently holds unmerged paths FROM this autostash reapply (detected right after our own pull by scanning STDERR / combined output for the `Applying autostash resulted in conflicts` line — fact-check verified: the message is emitted on STDERR and the pull exits rc=0 in this case, so detection must parse stderr/combined output and must NOT key on the exit code): clear ONLY those unmerged paths back to HEAD — for the PREFLIGHT (pre-existing stranded entry) case, first intersect `git diff --name-only --diff-filter=U` with `git stash show --name-only <ref>` so only paths attributable to THAT autostash are cleared — (path-scoped `git checkout HEAD -- <path>...` on the explicit unmerged list — NOT the banned full-tree `git checkout .`; the content is doubly preserved: in the kept stash entry AND the rescue patch).
  4. Attempt restore: `git stash show -p <ref> | git apply --check` — clean → `git stash pop <ref>` (pop drops the entry ONLY on clean application, which is git's own recommended recovery); dirty → KEEP the entry, report it + the rescue-patch path for manual triage. Never `git stash drop` explicitly.
- **Post-sync integrity checks:** assert no `.git/rebase-merge/`, no `.git/MERGE_HEAD`; run `task_workflow.audit()` and include any REGISTRY-vs-filesystem drift rows in the report (surfaces #811-style folder loss — reported, never auto-fixed).

### 4.5 Push

`git push origin main` (bounded). On rejection: ONE more pull — routed through the SAME sweep-wrapped pipeline as the first (fresh collisions can materialize in the interim window; round-1 Methodology concern, promoted), then push. Second rejection → exit 3, report. `--no-push` skips this leg.

**Report semantics (round-1 concerns, promoted):** the `--json` report carries `state: synced | already | in-flight` (exit 0 is shared by all three — a scripted caller must not read exit 0 as "my push landed"); the exit-2 report names the conflicted paths, frames a `tasks/REGISTRY.json` conflict as EXPECTED on incident-scale divergence (task creation on both sides makes it near-certain — not a helper failure), and prints the documented manual next step verbatim (the CLAUDE.md scratch-worktree recipe: `git worktree add --detach <path> origin/main` + resolve there + `git push origin HEAD:main` — the recovery that actually resolved 6c1b3fadf7).

## 11. Decision Rationale

`N/A — no training hyperparameters.` Load-bearing DESIGN parameters:

1. **Single-flight lock path `~/.task-workflow/root-sync.lock`.** Why: same directory as the existing task-workflow lock — one discoverable home for cross-session coordination; outside the working tree. Source: `task_workflow.LOCK_DIR` (read from code) + the candidate sketch. Alternatives: a repo-internal `.git/` lock file (rejected: git tooling may sweep unknown files there); the task-workflow lock itself (rejected: would block ALL task.py reads-with-mutation for the whole sync even when no sync conflict exists — separate concerns, separate locks).
2. **Second (blocking) acquisition of `task_workflow.LOCK_PATH` for the mutation window.** Why: excludes the library-side committers that caused the observed index.lock contention; fixed lock order prevents deadlock. Source: incident (b) + task_workflow.py:563–577. Alternatives: no second lock (rejected: leaves the dominant writer racing); a new shared lock adopted by task_workflow too (rejected: bigger blast radius, public-contract-adjacent).
3. **Non-blocking + exit 0 for the second helper caller.** Why: "another sync in flight" is success from the caller's perspective (someone is fixing it); exiting nonzero would make N sessions treat a healthy state as a failure and improvise — the exact behavior this task removes. Source: candidate sketch; incident (b). Alternative: blocking wait (rejected: serializes N redundant syncs back-to-back).
4. **Timeout default 600s per git subprocess (`EPM_ROOT_SYNC_TIMEOUT_S`).** Why: the incident rebased hundreds of commits — minutes are legitimate; 10 min bounds the lock hold while covering the observed worst case with margin. Source: incident scale (582/226 commits); env-override convention from the watcher's `EPM_*` knobs. Alternatives: 120s (too tight for a large rebase), unbounded (banned: a hung git holds both locks forever).
5. **Rescue dir `~/.task-workflow/root-sync-rescue/<UTC-ts>/<rel-path>`.** Why: outside the tree (a rescue inside the tree is itself a future untracked collision); timestamped so repeated runs never collide; relative paths preserved for manual restore. Source: hard constraint "never delete non-identical data — rescue dir only". Alternative: `git stash -u` the collisions (rejected: stash entanglement with autostash is the incident's failure mode (c); files-on-disk are simpler to triage).
6. **Identical→rm / differing→rescue decision rule via `git hash-object` vs `git rev-parse origin/main:<path>`.** Why: content-addressed byte-identity — removing an identical file loses nothing (the pull rematerializes the same bytes at the same path, now tracked); anything else (including symlinks/dirs/non-regular) is rescued. Source: candidate sketch; git object model. Alternative: rescue everything (rejected: 81–148 mostly-identical files per incident round would bloat the rescue dir and bury the genuinely-differing files a human must triage).
7. **v1 conflict policy: abort + report; NO lifecycle auto-resolve (deviation from the sketch).** Why: during a rebase, ours/theirs semantics invert, and "keep the LATER lifecycle state" requires parsing `events.jsonl` mid-conflict to order status transitions — high-blast-radius logic whose failure mode is exactly the clobbered-task-state incident class the standing ban exists for (#815). The observed incident blockers were collisions/locks/stashes, all fixed here; union-merge attrs (#787) already auto-resolve the JSONL conflicts. A clean abort + `task_workflow.audit()` drift report keeps humans in the loop for the rare true conflict. Source: #787 scope caveat, #815 incident, #786. Alternative: ship the auto-resolver (rejected for v1; can be its own reviewed follow-up with the abort path as fallback).
8. **Stranded-autostash recovery: rescue-patch first, pop-if-clean (never explicit drop), keep-and-report on conflict; clear only the autostash's own unmerged paths.** Why: `git stash pop` drops only on clean application (git's own recommended recovery, printed in its hint); the rescue patch double-preserves before any tree mutation; explicit `stash drop` is banned in the helper. Source: empirically verified stash lifecycle (§12 items 1–5); git-stash docs. Alternative: auto-`git stash apply` + manual drop (rejected: two steps where pop's atomicity gives one); leave UU paths in place (rejected: unmerged index entries block every subsequent commit — a husk by another name).
9. **Push retry count = 1.** Why: matches the existing CLAUDE.md retry-once convention; under the single-flight lock a second rejection means an out-of-band pusher — report, don't loop. Source: CLAUDE.md § Concurrent repo-root committers. Alternative: retry-until-success (rejected: unbounded lock hold, hides pathology).
10. **Watcher leg: DEFERRED (not in v1).** Why: the incident's failure mode was sessions racing recovery — single-flight fixes that even with many callers; a cron-driven git-mutating writer on the shared root would be the watcher's FIRST shared-root git mutation (today it only reads/escalates and manages sessions/pods), a new autonomous actor deserving its own plan+review after the helper accrues field history. Divergence with no session pushing is inert (nothing is being lost while parked). Source: `autonomous_session_watch.py` pass inventory (read: all passes are session/pod/disk-scoped); blast-radius reasoning. Alternative: ship a detect-and-Telegram-escalate-only watcher pass (viable, read-only — surfaced as a follow-up candidate for the orchestrator, not in v1 scope).
11. **Stale-husk age threshold 3600s (`EPM_ROOT_SYNC_HUSK_AGE_S`).** Why: a live interactive rebase rarely sits >1h; a crashed loop's husk persists indefinitely. Source: judgment grounded on the incident timeline (~3h of stuck state); env-tunable. Alternative: never auto-abort (rejected: a pre-existing husk blocks every sync forever = the incident); no threshold (rejected: could kill a live operation).
12. **index.lock policy: bounded wait (60s), then fail loud with `fuser` evidence; never delete.** Why: deleting a live index.lock corrupts a running git op; a crashed one is a rare manual call. Source: incident (b); git-index-lock semantics. Alternative: auto-delete after age threshold (rejected for v1: the one op where a wrong guess corrupts the index).

13. **Re-hash-before-rm + mtime-freshness guard (`EPM_ROOT_SYNC_FRESH_S`, default 60s).** Why: closes the enumerate-then-act TOCTOU (round-1 Methodology MF1, upheld by the reconciler; Alternatives binding rec) — a concurrent plain-shell writer outside both locks can rewrite an untracked file between hash and removal; re-hashing in the same iteration plus treating recently-touched files as `differing` enforces the plan's own never-delete-non-identical invariant at action time. Source: round-1 critique; incident churn regime (collisions grew 81→148 between attempts). Alternatives: rescue-everything (rejected earlier — buries the differing files); an `identical/` rescue tier (viable, Codex-Alt MF1 — implementer MAY use it instead of rm at equal safety; the invariant, not the mechanism, is binding).
14. **Ledger-driven abort-restore contract.** Why: an abort after the sweep must not leave the tree missing files it had (round-1 Methodology MF2, upheld) — `rebase --abort` restores the pre-pull HEAD, which lacks the origin-only paths, so the helper restores from its own sweep manifest (rescued → moved back; identical-removed → rematerialized via `git cat-file blob`, no index staging). Source: round-1 critique; git abort semantics (§12 item 3). Alternative: declare non-restoration + report-only (rejected — "worse than found" violates the requirement's own safety framing; restore is cheap given the ledger).
15. **Bounded second-lock acquisition (`EPM_ROOT_SYNC_LOCK2_WAIT_S`, default 120s).** Why: a hung task.py holder must not wedge the helper while it holds the root-sync lock (every other caller exits 0 forever — silent persistence of the incident state); LOCK_NB + poll + exit 5 with `fuser` evidence mirrors the index.lock policy (item 12). Source: round-1 Methodology concern (promoted); §11 item 4's own unbounded-hold logic. Alternative: blocking LOCK_EX (rejected — the wedge case).
