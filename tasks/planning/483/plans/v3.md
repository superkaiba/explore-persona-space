## 0.0 TL;DR (plain English)

- **What I'll build:** One canonical list of ~140+ personas with their system prompts, a committed table of how far apart every pair sits in the model's representation space, and a small library function that — given the personas an experiment trains on — hands back a held-out evaluation panel with several personas at every distance, near to very far. Experiments stop hand-picking panels that accidentally bunch up at one end.
- **What I expect:** The personas the project already has cover almost the whole distance range (I checked the existing measurements: every distance bin already holds 4+ personas relative to the standard source pool). The real gaps are diversity ones — the 0.20–0.25 bin is all comedians — so I'll write a handful of new far-out personas, measure where they actually land, and keep only the ones that land where intended.
- **What would change my mind:** If a fresh measurement run disagrees with the old saved one (same personas, distances move by more than noise), that means the measurement pipeline isn't stable enough to call "canonical," and I stop and diagnose before committing anything.

### 3.2 Synthetic personas — generate → measure → keep/revise

**Why a model call, not code:** persona system prompts are creative text; a single Claude Sonnet (`claude-sonnet-4-5`) call per round generates them. The keep/revise decision is code (measured distances). What would flip it: nothing — there is no code path that writes persona prompts.

- **Round 1 (unconditional):** 24 candidate prompts targeting the measured gaps, deliberately **non-comedy** (the 0.20–0.25 bin is currently 100% comedy family). Archetype axes, chosen because the measured farthest natural personas are register/affect extremes (`mysterious_person` 0.339, `grumpy_person` 0.313, `drill_sergeant` 0.257, `formal_assistant` 0.277): non-human entities (ship AI, ancient deity, hive-mind), extreme registers (legalese formalist, telegraphic oracle, Shakespearean), affective extremes (nihilist, manic enthusiast), antiquated/fantasy voices, rule-bound bureaucrats, cryptic minimalists. 1–3 sentences each, same shape as existing prompts.
- **Measure:** extracted in the same Phase B job; a synthetic *lands* if its raw-L20 min-dist to POOL_16 falls in its `target_band`.
- **Keep rule:** keep any synthetic landing in a band whose occupancy audit shows a deficit (vs either reference set, or the non-comedy 0.20–0.25 stretch goal); keep at most 12 synthetics total in pool v1 (avoid synthetic-dominating the far end); rejected candidates recorded in `pool_meta_v1.json` with their measured landings.
- **Rounds 2–3 (conditional):** only if a deficit band remains — the revision prompt may target ANY deficit band (near bands included, e.g. a vs-assistant near-band shortfall), not just the far end. The revision prompt to Claude includes round-1's measured landings (which styles overshot/undershot). Re-extract only the new candidates (~2 min each round).
- **Round cap: 3** (kill criterion §6).
- **Selection-on-noise caveat (recorded in `pool_meta`):** kept synthetics are selected on ONE measured landing, so their true distances regress slightly toward the source; with the measured determinism floor ≤0.005 against 0.05-wide bands the bias is small, but a ~0.201 landing should not be narrated as solidly very-far. Synthetics' `landed_band` is recorded under BOTH presets (raw478 primary — deficits and AC2 are measured in raw units — plus the centered preset, informational).

### 3.4 Matrices + audits (Phase C, CPU)

`--build-matrices`:

- For each layer × centering ∈ {`global_mean`, `none`}: `compute_cosine_matrix(centroids, centering=...)` → distance = 1 − sim. JSON schema: `{schema_version: "cpp_v1", persona_names, distance, layer, centering, metric: "1 - cosine", extraction: {recipe, base_model, n_questions, questions_sha256, layers_convention: "0-indexed decoder blocks"}, built_from: {centroids_sha256, commit}}`.
- **Stability gate (blocking; TOTAL lattice — one threshold, no unmapped state):** on the 111 shared personas, elementwise |Δ raw-L20 distance| vs the legacy matrix.
  - p95 ≤ 0.01 → PASS, commit.
  - p95 > 0.01 → ONE diagnosis pass: batch-1 re-probe of the worst-offender personas under execution conditions matching the legacy build. If the re-probe brings post-diagnosis p95 ≤ 0.01, PASS with the diagnosed cause documented in `pool_meta`; if post-diagnosis p95 > 0.01, **K1 STOP** (`failure_class: code`). The former 0.02 figure is retired — commit threshold and kill threshold are now the same statistic at the same value, so post-diagnosis p95 ∈ (0.01, 0.02] has a defined outcome (K1).
  - The `assistant`↔`helpful_assistant` duplicate-prompt distance ≤ 0.005 rides along as a **batching/execution-determinism floor** — labeled exactly that in `pool_meta` prose (it is a determinism check, NOT a centroid-SE estimate: question-sampling error cancels between verbatim twins). The real centroid-SE read is the free **split-half-over-questions** diagnostic: per-persona 10-vs-10 question-split centroid distance computed from the same forwards, distribution recorded in `pool_meta`.
- **#478 regression (blocking; edge-churn-coherent — rewritten so in-spec drift cannot false-kill):** band assignment of the 35 #478 held-out personas (min-dist to POOL_16, **the original 6-band raw478 system** — pinned: 6 bands, not the merged-5 view). 15/35 of these personas sit within 0.01 of a band edge (6 within 0.0021), so raw shift-counting would false-fire under drift the stability gate itself permits. The criterion therefore counts only **genuine-drift shifts**: a persona counts toward the kill iff it changed band AND its |Δ min-dist| > 0.01 (the stability tolerance). Edge-churn shifts (band change with |Δ min-dist| ≤ 0.01) are reported in `pool_meta` but never kill. Multi-band jumps (≥2 bands, impossible without |Δ| > 0.05 given 0.05-wide bands) always count as genuine-drift shifts. **Routing: >3 genuine-drift shifts (or ANY multi-band jump) → K3 STOP**, same handling as K1; ≤3 → pass with shifts enumerated in `pool_meta`.
- **Occupancy audit:** per reference source set (POOL_16, {assistant}, {medical_doctor} informational), per band, over panel-eligible personas only: members + counts, comedy-family share, **per-band origin/synthetic share**, and per-persona prompt token count with a **prompt-length vs min-dist Spearman** (the register/length covariate a skeptical consumer will ask for), written to `pool_meta_v1.json`. The audit is computed under BOTH presets (`raw478_L20` and `centered_v1_L20`) × both reference sets; the raw478×POOL_16 cell is the binding one (AC2), the rest are recorded diagnostics, including the **centered↔raw band-agreement rate per reference source set**.
- **`centered_v1_L20` band edges (pinned fit algorithm):** **empirical-quantile mapping** — each raw478 edge is mapped to the centered min-dist value at the same empirical quantile of the pool's min-dist-to-POOL_16 distribution (plain empirical CDF, linear interpolation between order statistics; no other procedure). The fit inputs (the two sorted min-dist vectors) and outputs (the edge values) are committed in `pool_meta_v1.json`, so the edges are exactly regenerable; a unit test re-derives them from the committed matrix. (Centered distances run ~6× raw per #536 — the mapping is measured, not assumed.)
- **Legacy-dict comparison:** Spearman between frozen `ASSISTANT_COSINES`/`DOCTOR_COSINES` and pool-derived L10-centered similarities on the shared personas, recorded in `pool_meta` **with N alongside** (~10 shared personas — wide null; informational only — exact values cannot match because centered cosine is bank-dependent, #536).
- **Recipe-(a)↔(b) and L20↔L21 agreement:** Spearman over pairwise distances, recorded in `pool_meta` + surfaced in the task write-up, **plus the top-10 personas with the largest (a)↔(b) rank disagreement flagged by name** — those are the personas whose "distance" is recipe-idiosyncratic, and a consumer whose far band leans on them should know.
- **Gate results as artifact fields:** K1/K3/stability/regression outcomes are written as structured pass/fail fields in `pool_meta_v1.json` and the build exits non-zero on any blocking failure (gates are code branches, not agent discipline); `tests/test_persona_pool.py` asserts the committed pass status.

## 6. Success criteria + kill criteria

**Success (quantitative):** AC1–AC5 all pass; specifically AC2's per-band floors (6 unmerged bins, panel-eligible only, POOL_16 hard-binding + assistant-or-documented-deficit) AND the default-surface `held_out_panel` contract read off the committed canonical artifacts by pytest; stability gate post-diagnosis p95 |Δdist| ≤ 0.01 + determinism floor ≤ 0.005; #478 regression ≤3 genuine-drift shifts (edge-churn exempt); L20↔L21 and recipe-(a)↔(b) Spearman recorded (expected ≥0.95 / ≥0.8; informational, not gating).

**Kill criteria (each threshold identical to its §3.4 gate — the lattice is total by construction):**

- **K1 (blocking):** stability gate fails — fresh extraction p95 |Δ raw-L20 dist| > 0.01 vs legacy on the shared 111 personas AFTER the single permitted diagnosis pass (batch-1 re-probe of worst offenders under legacy-matching execution) → STOP, post `epm:failure` (`failure_class: code`); do not commit matrices that can't reproduce the lineage they claim to canonicalize. (≤0.01 pre-diagnosis = pass; ≤0.01 post-diagnosis = pass with documented cause; >0.01 post-diagnosis = K1. No third state.)
- **K2 (non-blocking, documented — AC2 precedence pinned):** synthetics cannot fill a deficit band after 3 rounds → ship pool v1 all-natural-plus-whatever-landed with the deficit recorded in `pool_meta_v1.json.documented_deficits`. AC2's vs-assistant leg READS that list (the test passes on a documented deficit), and AC2's vs-POOL_16 leg is not K2-eligible (it already passes on naturals; were a fresh-extraction surprise to break it, that is K1/K3 drift territory, not a synthetic-yield matter). The non-comedy 0.20–0.25 stretch goal failing is likewise documented, never blocking. The loader's `BandUnsatisfiableError` keeps consumers honest either way.
- **K3 (blocking):** #478 regression — >3 **genuine-drift** band shifts (band change with |Δ min-dist| > 0.01) or ANY multi-band jump, counted on the original 6-band system per §3.4 → same handling as K1 (it implies extraction drift, not a design problem). Edge-churn shifts (|Δ min-dist| ≤ 0.01) are enumerated in `pool_meta` and do not count toward the kill — 15/35 panel personas sit within 0.01 of an edge, so naive shift-counting would false-kill an in-spec run.

## 11. Decision Rationale

*(`kind: infra` — no training hyperparameters; the load-bearing choices are the extraction/measurement parameters below.)*

- **Extraction recipe primary = (a) last-prompt-token over 20 EVAL_QUESTIONS.** Why: every bank centroid artifact in the project (#405/#478 L20 matrix, #472 bank, #505 L{7,14,21,27}) is recipe (a) over these exact questions — the pool's purpose is comparability for that consumer line. **Source: `.claude/rules/persona-distance-metrics.md` variant (a) + #478/#505.** Alternatives: recipe (b) as primary (paper-faithful) — rejected: breaks numeric continuity with every existing artifact and adds a generation step to every future maintenance re-extraction; instead shipped as a measured secondary.
- **Recipe (b) secondary at L20/L21.** Why: the rule names (b) as the Persona Vectors recipe; committing the (a)↔(b) agreement number pre-empts the recipe-choice objection for the whole line. **Source: arXiv 2507.21509 (difference-of-means; LaTeX-verified in #536 Phase A0 — inherit fast-path).**
- **Canonical layer = 20; layers {7,10,14,20,21,27} committed.** Why: the body's own acceptance band numbers (~0.02–0.25) and every consumer's band edges are calibrated in L20 units; the rule's {7,14,21,27} sweep is satisfied by committing those layers too, and the build measures L20↔L21 Spearman so the choice is demonstrated (im)material rather than asserted. L10 added for the legacy-dict shims. **Source: #405/#478/#531/#553/#559/#560 lineage (L20); rule sweep set; ASSISTANT_COSINES (L10).** Alternatives: canonical 21 (rule's legacy default for the *raw-pairwise predictor* family) — rejected for the *bank* family on continuity grounds; revisit if measured L20↔L21 Spearman < 0.9.
- **Centering canonical = `global_mean`; raw committed as labeled legacy.** Why: raw bank cosine is deprecated for persona distance; centered is bank-dependent so the artifact must carry provenance + version pinning. **Source: #536 + rule § Bank centering.** Alternatives: raw-only (status quo) — deprecated; centered-only — would orphan the #478-lineage band edges the acceptance criteria are written in.
- **Band edges raw478 = 0.05/0.10/0.15/0.20/0.25 (min-dist-to-source-set).** **Source: #478 plan v5 §4.3 / `design_validation_v2.json`** (reproduced from the matrix this session). `centered_v1` edges = build-time measured mapping, committed — not a floating choice.
- **20 questions per persona.** Why: matches every prior centroid build; #478's bands were stable on it. **Source: #405/#478/#505.** Alternatives: more questions (lower centroid SE) — unnecessary given the measured noise floor check; fewer — saves nothing material.
- **Synthetic rounds: 24 candidates, ≤3 rounds, ≤12 kept.** `Source: ungrounded — needs smoke-test` (hit-rate unknown; archetype axes grounded only in the measured far-end natural personas). Kill-capped (K2).
- **`max_new_tokens=1024` + truncation-rate log for recipe (b).** **Source: rule's #548 truncation discipline** (0.000 truncation at 1024 on the standard panel).
- **Stability/K1 threshold = 0.01 (single value, commit = kill).** Why: a two-number lattice (commit 0.01 / kill 0.02) left post-diagnosis (0.01, 0.02] unmapped (round-1 statistics ensemble, binding). 0.01 raw-L20 distance is well below the smallest band width (0.05) and above the measured determinism floor (≤0.005). **Source: round-1 critic ensemble reconciliation + the legacy-matrix edge-margin recomputation.** Alternatives: keep 0.02 as kill — rejected, non-total lattice.
- **K3 counts genuine-drift shifts only (|Δ min-dist| > 0.01), 6-band system, multi-band jumps always count.** Why: 15/35 #478 panel personas sit within 0.01 of an edge (6 within 0.0021), so naive shift-counting false-kills runs the stability gate itself certifies. **Source: round-1 statistics reconciler's recomputation from the committed legacy matrix + `design_validation_v2.json`.** Alternatives: raw ≤3/35 shift count — rejected, incoherent with permitted drift; widening to ≤8 shifts — rejected, insensitive to genuine localized drift.
- **Centered-edge fit = empirical-quantile mapping (pinned).** Why: "monotone/quantile match" named multiple procedures; two faithful implementations could commit different canonical defaults. Empirical CDF + linear interpolation is the simplest exactly-regenerable choice; a unit test re-derives the committed edges. **Source: round-1 ensemble (statistics non-blocking + methodology standing rec).** Alternatives: isotonic fit / parametric monotone map — rejected, more procedure surface with no consumer benefit.
- **Model id** `Qwen/Qwen2.5-7B-Instruct` — repo-standard (`Source:` project default; not repo-new, no config-load smoke required).
