## 1. Goal

Close the mechanical-coverage gap surfaced by the clean-result-critic on task #2054: a
v4 clean-result body embedding a `## Results` figure that has NO `.meta.json` sidecar at
the cited sha currently receives ZERO mechanical opaque-code coverage — check 28
(`check_figure_label_codes`, WARN) fail-softs on the missing sidecar (`meta is None →
continue`, the check-24 convention) and check 41 (`check_figure_sidecar_coverage`) is
WARN-never-FAIL by documented design.

**Founding-incident ground truth (critic round 1, verified against
`git show c0287bede2:.../2054/body.md` + the round-5 critique marker):** the #2054
figure (`hero_calibration_nslope.png`) carried its opaque `H0'a`/`H0'b`/`b=`/`m=`
codes ONLY in PNG rendered text (panel titles + legend entries); its blockquote
caption was clean plain-English. No text channel reaches those pixels — the only
mechanical forcing function is making the sidecar-less state itself blocking for NEW
figures, which routes rendered text into the sidecar (`savefig_paper`) where check 28
scans it. The design therefore has TWO legs:

- **Leg A (caption codes — acceptance criterion 1's literal conjunction):** sidecar
  absent AND the caption carries opaque condition codes → FAIL.
- **Leg B (forward-only sidecar-less block — catches the founding-incident class):**
  a sidecar-less same-repo Results figure whose pinned commit POST-dates the fix
  cutover → FAIL unless the body explicitly acknowledges that figure by basename.
  Every existing figure pin pre-dates the cutover ⇒ the existing corpus is exempt BY
  CONSTRUCTION (criterion 3), while every future sidecar-less Results figure blocks
  at draft time — reproducing the #2054 shape post-fix is caught even with a clean
  caption.

**Rejected alternatives:** plain option (a) (check 41 WARN→FAIL) — the EXECUTED sweep
(§5, measured) shows **42 sidecar-less figures across ~13 green `awaiting_promotion`
v4 bodies**; an unconditional (or even acknowledgment-escaped) FAIL breaks their
promote-time re-verifies (#1332/#2202 carry no per-figure acknowledgment; #763 has no
acknowledgment paragraph at all). Date-gating is the only body-text-available
discriminator that keeps them green without a 42-entry allowlist or batch-editing
other tasks' parked bodies.

**Assumption (check-number correction, carried from the clarifier):** the task body's
"check 37" is actually **check 41** (`check_figure_sidecar_coverage`); the opaque-code
scan is **check 28**. Verified by the critic.

### 3.1 New check 55: `check_v4_sidecarless_results_figures` (FAIL, v4-only)

Placement: next to check 41. Logic:

1. `if not is_v4(body): return PASS` (check-44/54 v4-self-gating precedent).
2. `section = _figure_scan_section(body)`; no section → PASS. Iterate image lines as
   check 28 does, collecting unique URLs + first-occurrence caption windows.
3. `_resolve_repo_root()` None → PASS (offline/stdin convention).
4. Per unique same-repo sha-pinned URL: PNG must resolve at the cited sha
   (`_git_object_exists == "pass"`), else skip (check 22's domain). Sidecar path via
   check 41's `rpartition` derivation; sidecar status `== "fail"` ⇒ SIDECAR-LESS;
   `"pass"` or indeterminate ⇒ skip (fail-soft; sidecar-present figures stay check
   28's WARN domain — `_git_object_exists`'s three-state contract, verified by the
   critic).
5. **Leg A** — strip markdown code spans (`` `...` `` — regex `` r"`[^`]*`" `` →
   space) from the caption window, then `toks = _opaque_code_tokens(caption)`.
   Non-empty → FAIL entry naming basename + token preview. The code-span exclusion
   is IN from the start (measured: it is what clears the corpus's one benign hit —
   a backticked companion-FILENAME reference; a backticked opaque code is a
   code-register reference by convention, and Leg B is the stronger forcing function
   for genuinely new figures). Not date-gated (measured 0 corpus hits).
6. **Leg B** — read the pinned commit's committer date (`git show -s --format=%ct
   <sha>`, subprocess-bounded + cached per sha; ANY probe failure ⇒ fail-soft skip,
   never FAIL on indeterminate). If the date is **≥ `_CHECK55_FORWARD_CUTOVER`**
   (module constant, the fix-landing date `2026-08-13` UTC as epoch) AND the figure's
   basename (lowercased, dash-normalized — the check-20 coverage-sub-check matching
   convention) is NOT named in the body's WARN-acknowledgment text
   (`_warn_acknowledgment_text`) → FAIL entry: "sidecar-less Results figure
   `<basename>` (pinned at a post-2026-08-13 commit) — regenerate via `savefig_paper`
   (writes the sidecar, exposing rendered text to check 28), or acknowledge the
   figure by name in the body's verifier-WARN acknowledgment (deliberate
   non-matplotlib figures)". The acknowledgment escape is for hand-made diagrams /
   external screenshots that `savefig_paper` structurally cannot produce.
7. Any FAIL entry ⇒ `ok=False` naming all entries; else PASS with counts
   (`checked`/`sidecarless`/`exempt-pre-cutover`).

**Evasion + residual notes (docstring-documented):** (i) backticking a code in the
caption hides it from Leg A — accepted: Leg B forces new figures toward sidecars
regardless of caption content. (ii) Pinning a NEW figure at an old sha is impossible
(the pinned commit must CONTAIN the PNG; a pre-cutover commit can only contain
pre-cutover figures — reusing a parent's grandfathered figure is legitimately
exempt). (iii) `b=`/`m=` single-letter-equals codes stay unclassifiable
(ordinary caption math like `b=0.3`); PNG-pixel text stays the multimodal critics'
substantive read for GRANDFATHERED figures — for post-cutover figures Leg B removes
the pixel blind spot indirectly by forcing the sidecar channel into existence.
(iv) Committer dates are trusted as monotone-enough; a rebase that rewrites an old
figure commit to a post-cutover date produces a spurious FAIL (loud, fixable via the
ack escape), never a silent pass.

### 3.2 Hypothesis-code class: prime-marked token REPORTING (correction from v1)

**Corrected premise (critic round 1, repro-verified):** the CURRENT
`_HYPOTHESIS_CODE_RE` (`\bH\d[a-z]?\b`) ALREADY fires inside `H0'a`/`H0′b` — the
apostrophe is a word boundary, so `H0` matches. Detection is NOT missing; only the
REPORTED token is truncated. The change is therefore cosmetic-accuracy only: extend
the class to report the full prime-marked token (`\bH\d(?:['′][a-z]|[a-z])?\b`
shape; implementer finalizes boundary semantics), pinned as a strict SUPERSET
property (kill criterion §8) — and the docstring records it as a reporting
improvement, NOT a detection-gap incident (no false incident record; #2267).
