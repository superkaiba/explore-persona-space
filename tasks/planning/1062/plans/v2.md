### 4.1 `scripts/verify_plan.py` — new check `c25_html_entities_in_commands`

- **Severity/scope:** FAIL, ALL kinds (infra plans carry verification commands too — this task's own class), conditional (SKIP when no command fence).
- **Fence scope (two arms, to avoid false positives on plans that DISCUSS entities, like this one):**
  - (a) any fenced block whose info string starts with `bash`, `sh`, `shell`, `zsh`, or `console`;
  - (b) any OTHER fenced block (tagged or untagged) whose body contains `--workload-cmd` or `dispatch_issue.py` — the highest-stakes command field, whatever fence tag the author picked.
- **Entity pattern:** the six forms from the Goal + task brief, case-insensitive, leading-zero-tolerant on the numeric forms.
- **Escape phrase — fence-class-scoped, scan-first (M1, methodology reconciler round 1):** `N/A — entities are content, not commands` on its own standalone line, detected via the HOUSE standalone-line helper (`_standalone_na_declared`, fence-masked + prefix-anchored — NOT a doc-global `re.search`, whose plain form both misses standalone-line discipline and would let the check's own FAIL-detail wording self-escape). The scan runs FIRST; the phrase then exempts ONLY arm-(a) hits (shell-tagged fences carrying no command marker). An entity hit in an arm-(b) fence (`--workload-cmd` / `dispatch_issue.py` in the body) FAILs UNCONDITIONALLY — a document-wide phrase must never mask a separately poisoned workload command (the mixed-plan false-PASS the round-1 reconciler identified: one legitimate entity-discussing fence + one poisoned dispatcher fence must still FAIL).

Sketch (follows the c11/c24 house shape; constants adjacent to the check):

```python
# ─── Check 25 — HTML entities in fenced command blocks (all kinds) ──────────
# The harness HTML-escapes the <result> field of background-Agent
# <task-notification> messages (&& -> the amp-entity form, < -> lt, > -> gt);
# an orchestrator that composes the plan handoff from that text ships a
# poisoned workload command (#952 v9, 2026-07-04: the dispatcher command's
# shell AND operators arrived entity-escaped and needed a hand-fix before
# dispatch would run). This check is the persist-time backstop for the
# capture-time de-escape rule in adversarial-planner SKILL.md.
_FENCE_RE = re.compile(r"(?ms)^[ \t]*```([^\n]*)\n(.*?)^[ \t]*```[ \t]*$")
_CMD_FENCE_INFO_RE = re.compile(r"(?i)^\s*(?:bash|sh|shell|zsh|console)\b")
_CMD_MARKER_RE = re.compile(r"--workload-cmd|dispatch_issue\.py")
_HTML_ENTITY_RE = re.compile(r"(?i)&(?:amp|lt|gt|quot|#0*39|#x0*27);")


def check_html_entities_in_commands(plan: str, kind: str) -> CheckResult:
    """Fenced command blocks must not carry HTML entities (#952 v9).

    Scan-first; the standalone escape phrase exempts arm-(a) hits only.
    An arm-(b) fence (--workload-cmd / dispatch_issue.py in the body) FAILs
    on entities UNCONDITIONALLY — a document-wide phrase must never mask a
    poisoned workload command (methodology reconciler, #1062 round 1).
    """
    cid, name = "c25_html_entities_in_commands", "no HTML entities in fenced command blocks"
    del kind  # all kinds — infra/batch plans carry verification commands too
    arm_a, arm_b = [], []
    for info, body in _FENCE_RE.findall(plan):
        if _CMD_MARKER_RE.search(body):
            arm_b.append(body)          # command-marked: never exemptable
        elif _CMD_FENCE_INFO_RE.match(info):
            arm_a.append(body)          # shell-tagged: exemptable by the phrase
    if not arm_a and not arm_b:
        return _skip(cid, name, "no fenced command blocks detected")
    hits_b = sorted({m.group(0) for b in arm_b for m in _HTML_ENTITY_RE.finditer(b)})
    if hits_b:
        return _fail(cid, name, _detail(hits_b, exemptable=False))  # phrase CANNOT exempt
    hits_a = sorted({m.group(0) for b in arm_a for m in _HTML_ENTITY_RE.finditer(b)})
    if hits_a and _standalone_na_declared(plan, "entities are content, not commands"):
        return _pass(cid, name, "arm-(a) entity content exempted by explicit standalone N/A")
    if hits_a:
        return _fail(cid, name, _detail(hits_a, exemptable=True))
    return _pass(cid, name, f"{len(arm_a) + len(arm_b)} command fence(s), no entity forms")
```

(`_detail(hits, exemptable)` renders the FAIL message: the entity list, the #952 v9 incident line, the remediation — "re-extract from the raw output-file or apply one html.unescape() round to notification-sourced text before persisting" — and, ONLY for `exemptable=True`, the escape-phrase pointer. The `exemptable=False` branch says instead: "a `--workload-cmd`/`dispatch_issue.py` fence is never exemptable — fix the command text". Match `_standalone_na_declared`'s real signature at implementation; if it is phrase-pattern-based, pass the compiled pattern.)

Wiring: append `check_html_entities_in_commands` to the `CHECKS` list (after `check_resume_provenance`, line ~3587); add the catalog row `c25 html entities in fenced FAIL, conditional — all kinds / command blocks` to the module docstring; add `25` to the docstring's conditional-checks enumeration; add the escape phrase to the docstring's canonical-phrase list.
