### 4.1 `scripts/verify_plan.py` — new check `c25_html_entities_in_commands`

- **Severity/scope:** FAIL, ALL kinds (infra plans carry verification commands too — this task's own class), conditional (SKIP when no command fence).
- **Fence scope (two arms, to avoid false positives on plans that DISCUSS entities, like this one):**
  - (a) any fenced block whose info string starts with `bash`, `sh`, `shell`, `zsh`, or `console`;
  - (b) any OTHER fenced block (tagged or untagged) whose body contains `--workload-cmd` or `dispatch_issue.py` — the highest-stakes command field, whatever fence tag the author picked.
- **Entity pattern:** the six forms from the Goal + task brief, case-insensitive, leading-zero-tolerant on the numeric forms.
- **Escape phrase:** `N/A — entities are content, not commands` on its own standalone line (house `NA_RE` prefix pattern), checked after the trigger, before the scan — mirrors c11's ordering.

Sketch (follows the c11/c24 house shape exactly; constants adjacent to the check):

```python
# ─── Check 25 — HTML entities in fenced command blocks (all kinds) ──────────
# The harness HTML-escapes the <result> field of background-Agent
# <task-notification> messages (&& -> the amp-entity form, < -> lt, > -> gt);
# an orchestrator that composes the plan handoff from that text ships a
# poisoned workload command (#952 v9, 2026-07-04: the dispatcher command's
# shell AND operators arrived entity-escaped and needed a hand-fix before
# dispatch would run). This check is the persist-time backstop for the
# capture-time de-escape rule in adversarial-planner SKILL.md.
_FENCE_RE = re.compile(r"(?ms)^[ \t]*```([^\n]*)\n(.*?)^[ \t]*```[ \t]*$")
_CMD_FENCE_INFO_RE = re.compile(r"(?i)^\s*(?:bash|sh|shell|zsh|console)\b")
_CMD_MARKER_RE = re.compile(r"--workload-cmd|dispatch_issue\.py")
_HTML_ENTITY_RE = re.compile(r"(?i)&(?:amp|lt|gt|quot|#0*39|#x0*27);")


def check_html_entities_in_commands(plan: str, kind: str) -> CheckResult:
    """Fenced command blocks must not carry HTML entities (#952 v9)."""
    cid, name = "c25_html_entities_in_commands", "no HTML entities in fenced command blocks"
    del kind  # all kinds — infra/batch plans carry verification commands too
    scoped = [
        body
        for info, body in _FENCE_RE.findall(plan)
        if _CMD_FENCE_INFO_RE.match(info) or _CMD_MARKER_RE.search(body)
    ]
    if not scoped:
        return _skip(cid, name, "no fenced command blocks detected")
    if re.search(NA_RE + r"entities are content, not commands", plan):
        return _pass(cid, name, "explicit N/A declared (entities are content, not commands)")
    hits = sorted({m.group(0) for body in scoped for m in _HTML_ENTITY_RE.finditer(body)})
    if not hits:
        return _pass(cid, name, f"{len(scoped)} command fence(s), no entity forms")
    return _fail(
        cid,
        name,
        f"HTML entities {hits} inside fenced command block(s) — the harness HTML-escapes "
        "background-subagent results in <task-notification> blocks, and a handoff composed "
        "from that text ships a broken workload command (#952 v9); re-extract from the raw "
        "output-file or apply one html.unescape() round before persisting, or declare "
        "`N/A — entities are content, not commands` if the entities are deliberately "
        "discussed content",
    )
```

Wiring: append `check_html_entities_in_commands` to the `CHECKS` list (after `check_resume_provenance`, line ~3587); add the catalog row `c25 html entities in fenced FAIL, conditional — all kinds / command blocks` to the module docstring; add `25` to the docstring's conditional-checks enumeration; add the escape phrase to the docstring's canonical-phrase list.

## 11. Decision Rationale

1. **Mechanical check in `verify_plan.py`, not prose-only.** *Why:* prose alone already failed for the sibling trailer bug until critics compensated (#562); Phase 1.5.0 is the exact right firing point (after compose, before critics/dispatch) and the Goal says "assert". *Source:* task #1062 Goal; house precedent c0–c24 (#625 lineage); incident #952 v9 (§3). *Alternatives:* prose-only (rejected — unverifiable); a PreToolUse Write-hook (rejected — a generic hook cannot know which Writes are plan handoffs, and hooks are a blunter surface than the existing plan gate).
2. **FAIL severity (not WARN).** *Why:* calibration measured 0 in-scope entity fences across 1,416 committed plan versions; an escaped operator in a command fence is near-certainly contamination; the escape phrase + the documented 2-bounce PASS-with-override valve bound the false-positive cost. *Source:* corpus scan this session (2026-07-05); Goal's "assert". *Alternatives:* WARN (rejected — WARNs ride into critic briefs but do not stop a poisoned command from reaching approval/dispatch).
3. **Fence-scoped scan, two arms (shell-tagged fences + `--workload-cmd`/`dispatch_issue.py`-marked fences).** *Why:* a whole-plan scan would FAIL any plan that discusses entities (including this one); arm (b) covers the highest-stakes field regardless of fence tag. *Source:* the #952 v9 exemplar is a `bash`-tagged fence; task-brief false-positive warning. *Alternatives:* whole-plan scan (rejected — false positives); arm (a) only (kept as the §7 fallback if arm (b) mis-calibrates).
4. **Escape phrase `N/A — entities are content, not commands`.** *Why/Source:* house standalone-N/A pattern (`NA_RE`, checks 1–24; adversarial-planner Phase 1.5.0 list) — the task brief proposed this exact wording. *Alternatives:* per-fence inline exemption markers (rejected — no house precedent, harder to audit).
5. **Capture-side prose in `adversarial-planner/SKILL.md`, NOT `/issue/SKILL.md`.** *Why:* the trace (§3) places the composition at the adversarial-planner persist flow; the trailer-strip precedent lives there; /issue consumes the c25-gated persisted plan. *Source:* transcript lines 993/1005 of session d49c6e04; grep showing /issue SKILL.md has no capture-site prose. *Alternatives:* editing both (rejected as default — SKILL.md bloat; allowed as a review-round deviation). This is a stated deviation from the task body's `Primary target:` line.
6. **One `html.unescape()` round as the de-escape recipe.** *Why:* the harness escapes the whole `<result>` uniformly, so one unescape round is the exact inverse — planner-written literal entity text arrives double-escaped and round-trips correctly; targeted string replacement would miss numeric variants. *Source:* Python stdlib `html.unescape` (handles all named + numeric character references); the #952 orchestrator's own hand-fix used exactly this call (transcript line 1005). *Alternatives:* replace only the six forms (rejected — strictly weaker, no cost saving).
7. **No new `.claude/rules/*.md` file.** *Why:* the lesson is small and local to two surfaces already carrying it (the SKILL.md paragraph + the check docstring both cite the incident); a rules file would add LESSONS.md index churn for no extra load-bearing coverage. *Source:* judgment; `agents-vs-skills.md`/LESSONS.md maintenance cost. *Alternatives:* a `plan-handoff-hygiene.md` rule (rejected for now; a future consolidation pass can lift it if a third contamination class appears).
8. **All-kinds scope for c25.** *Why:* infra/batch plans carry verification/workload commands too — this incident's plan was an experiment amendment, this fix's own plan is infra. *Source:* c5/c21/c22 all-kinds precedent in the check catalog. *Alternatives:* experiment-only (rejected — the incident class is kind-agnostic).
