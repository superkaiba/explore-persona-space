## 1. Goal + acceptance criteria

The guard today blocks branch-SWITCH in the shared repo-root tree but silently
ALLOWS every detach-inducing shape (`git checkout <sha>`, `<tag>`, `origin/<branch>`,
`--detach`, `HEAD~N`, …). A detached repo-root HEAD then crashes
`task_workflow.py:313-317` (`RuntimeError: main worktree HEAD (...) is detached`),
killing every `task.py` / self-report call in that session and any concurrent
session resolving the repo root. Extend the guard so detach is blocked exactly
as branch-switch is.

**Acceptance criteria (concrete shapes):**

- BLOCK (repo-root HEAD == `main`, no `git -C <path>` / worktree/`tmp` `cd` scoping):
  - `git checkout <sha>` (40-char, short 8-char, any commit-ish that is not a local branch)
  - `git checkout <tag>`, `git checkout origin/<branch>` / any remote-tracking ref
  - `git checkout HEAD~N`, `git checkout HEAD@{N}`, `git checkout <non-branch-rev>`
  - `git checkout --detach [<ref>]`
  - `git switch --detach <ref>`, `git switch -d <ref>`
- ALLOW (regression protection): `git checkout main`; `git checkout -- <file>`;
  `git checkout <ref> -- <file>`; `git checkout .`; `git -C .claude/worktrees/... checkout <x>`;
  `cd /tmp/... && git checkout <sha>`; anything that is not `git checkout` / `git switch`.
- PRESERVE the already-off-main recovery escape (lines 78-81): if repo-root HEAD
  is already NOT `main`, exit 0 — never trap a user recovering from an
  already-detached/off-main state.

## 2. Method delta

The script already has the right skeleton: stdin JSON → cmd → early-exit unless
`git (checkout|switch)` → worktree/`cd` scoping escape (exit 0) → set `blocked`
via detectors → `[ -n "$blocked" ] || exit 0` → on-main gate (exit 0 if off-main)
→ exit 2. **All new logic slots BEFORE the `[ -n "$blocked" ]` line (76)**, so the
scoping escape (40-44) and the recovery escape (78-81) both continue to govern —
detach blocks are gated by the identical on-main check for free.

Two additive detector blocks + one widened classifier:

1. **Explicit `--detach` / `-d` detector** — fires first, independent of the arg,
   because for `git checkout --detach abc123` the first post-`checkout` token is
   `--detach`, not the ref.
2. **Widen the existing `git checkout <arg>` classifier** (63-74): today it blocks
   ONLY when `$arg` resolves to a LOCAL BRANCH (`refs/heads/$arg`). Add: when `$arg`
   is NOT a local branch, NOT `main`, NOT a flag, and NOT `.`/a file-restore, but
   DOES resolve to a commit-ish (`git rev-parse --verify --quiet "$arg^{commit}"`),
   it is a detach → block. The `-- <file>` guard on line 64 already excludes
   file-restore forms; the `case` already excludes `main`/flags/empty.
3. **`git switch --detach/-d` detector** — the existing switch detector (50-54)
   blocks any non-`main` switch, which already catches `git switch -d foo` (arg is
   `-d`, not `main`). But `git switch --detach <sha>` / `git switch -d <sha>` should
   block even if a later token were `main` (e.g. `git switch -d main`, a detach AT
   main). Add an explicit switch-detach detector so intent is not arg-dependent.

## 3. File paths + concrete diffs

### 3a. `scripts/guard_repo_root_branch.sh`

Insert an explicit-detach detector immediately after the switch detector (after
line 54), and widen the checkout-arg classifier `case` (66-73). Concretely:

**Edit A — add explicit-detach detector after the `git switch` block (after line 54):**

```bash
# git checkout --detach [<ref>]  /  git switch --detach|-d <ref>  — explicit
# detach. Fires independent of the positional arg: for `checkout --detach abc`
# the first post-keyword token is the flag, not the ref, so the arg-classifier
# below would miss it.
if echo "$cmd" | grep -qE '\bgit\b[^;&|]*\bcheckout\b +(-{1,2})detach\b'; then
  blocked="git checkout --detach"
fi
if echo "$cmd" | grep -qE '\bgit\b[^;&|]*\bswitch\b +(--detach\b|-d\b|-[a-zA-Z]*d\b)'; then
  blocked="git switch --detach"
fi
```

**Edit B — widen the checkout-arg classifier `case` (66-73).** The `*)` arm today
only blocks a local branch; add a commit-ish detach block after the branch check:

```bash
  case "$arg" in
    ""|-b|-B|-f|--force|main|-|.) : ;;  # not a branch/detach we block
    --*) : ;;                            # a flag (e.g. --detach handled above)
    *)
      if git -C "$REPO" show-ref --verify --quiet "refs/heads/$arg"; then
        blocked="git checkout $arg"                       # existing: branch switch
      elif git -C "$REPO" rev-parse --verify --quiet "$arg^{commit}" >/dev/null 2>&1; then
        blocked="git checkout $arg (detaches HEAD)"        # NEW: sha/tag/remote-ref/HEAD~N
      fi
      ;;
  esac
```

Notes on the diff:
- `.` added to the first `case` arm so `git checkout .` (restore-all) stays ALLOW.
- `--*` arm so a stray flag arg never reaches `rev-parse`.
- `rev-parse --verify --quiet "$arg^{commit}"` returns 0 iff `$arg` names an existing
  commit-ish (sha / tag / `origin/foo` / `HEAD~2` / `HEAD@{1}`). If `$arg` resolves
  to nothing (typo, non-existent ref), `rev-parse` fails → NOT blocked → fail-soft
  exit 0 (git itself will error; the guard does not need to). This is the correct
  fail-soft behavior per the contract.
- Ordering: Edit-A `--detach` detectors set `blocked` first; the `--*` arm in the
  `case` prevents the classifier from re-touching a flag arg. Both feed the same
  `blocked` var, so the on-main gate (78-81) and the exit-2 message govern uniformly.
- The blocked message (83-85) is generic ("would move the SHARED repo-root tree off
  main") and already fits detach; extend its first clause to
  `"...off main / detach HEAD."` (one-word edit) so the feedback names the case.

### 3b. `tests/test_guard_repo_root_branch.py` (NEW)

Convention: pytest drives the script via `subprocess.run([script], input=json, text=True)`
and asserts `returncode` (2 = block, 0 = allow). Matches `test_workflow_lint.py`'s
`_run` pattern and every `test_*guard*` file. The test must run in the real repo
(the script hardcodes `REPO=/home/thomasjiralerspong/explore-persona-space` and calls
`git -C "$REPO" ...`), so it needs the repo-root HEAD on `main` for the block cases —
guard the block-assertions with a `skipif` when the running tree is off-main (the
recovery escape would fire), OR assert the recovery-escape behavior explicitly.

```python
import json, subprocess, pathlib, pytest
SCRIPT = pathlib.Path("scripts/guard_repo_root_branch.sh").resolve()
REPO = pathlib.Path("/home/thomasjiralerspong/explore-persona-space")

def _run(cmd: str) -> int:
    payload = json.dumps({"tool_input": {"command": cmd}})
    return subprocess.run([str(SCRIPT)], input=payload, text=True,
                          capture_output=True).returncode

def _on_main() -> bool:
    r = subprocess.run(["git", "-C", str(REPO), "symbolic-ref", "--short", "HEAD"],
                       capture_output=True, text=True)
    return r.returncode == 0 and r.stdout.strip() == "main"

on_main = pytest.mark.skipif(not _on_main(),
    reason="guard's on-main gate exits 0 when repo-root HEAD is off main")

# use a real short sha that exists in this repo for the detach cases
def _a_real_sha() -> str:
    return subprocess.run(["git", "-C", str(REPO), "rev-parse", "--short", "HEAD"],
                          capture_output=True, text=True).stdout.strip()

# --- MUST BLOCK (detach) ---
@on_main
@pytest.mark.parametrize("cmd", [
    "git checkout {sha}", "git checkout --detach", "git checkout --detach {sha}",
    "git switch --detach {sha}", "git switch -d {sha}",
    "git checkout HEAD~1", "git checkout origin/main",
])
def test_detach_shapes_block(cmd):
    assert _run(cmd.format(sha=_a_real_sha())) == 2

# --- MUST BLOCK (existing branch-switch regression) ---
@on_main
@pytest.mark.parametrize("cmd", ["git checkout -b feature/x", "git switch fix/foo",
                                 "git checkout main-adjacent"])  # a real local non-main branch
def test_branch_switch_still_blocks(cmd): ...  # create a throwaway local branch in a fixture

# --- MUST ALLOW (regression) — run regardless of on-main ---
@pytest.mark.parametrize("cmd", [
    "git checkout main", "git checkout -- scripts/eval.py", "git checkout HEAD -- foo.py",
    "git checkout .", "git -C .claude/worktrees/issue-123 checkout {sha}",
    "cd /tmp/foo && git checkout {sha}", "git status", "git commit -m x",
])
def test_allowed_shapes_exit0(cmd):
    assert _run(cmd.format(sha="abc1234")) == 0

# --- recovery escape: parse-failure / empty / non-git → exit 0 ---
@pytest.mark.parametrize("payload", ["", "{}", '{"tool_input": {}}', "not json"])
def test_fail_soft_exit0(payload):
    assert subprocess.run([str(SCRIPT)], input=payload, text=True,
                          capture_output=True).returncode == 0
```

Implementer refines the branch-switch-regression case to create/delete a throwaway
local branch fixture (so `refs/heads/<x>` resolves) — or reuse an existing non-main
local branch. The `_a_real_sha()` helper ensures `rev-parse ...^{commit}` succeeds so
detach cases exercise the new `elif`; a fabricated non-existent sha would fail-soft
and NOT block (which is correct, but does not test the block path — use a real sha).

## 5. Kill criterion

`git checkout <real-sha>` run in the repo root while HEAD==`main`, with no
`git -C <path>` and no `cd <worktree|/tmp>` scoping, that still exits 0 → the fix
is WRONG (the exact detach shape the crash traces to leaked through). Equivalently:
`git checkout --detach` exiting 0 on-main. Either means the new detectors did not
fire and the plan failed.

now BLOCKING (a false positive that would trap normal file-restore / return-to-main)
→ the widened classifier over-reached; the fix is wrong.
