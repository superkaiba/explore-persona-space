## 4. Design

### 4.1 `ReconcileReport` data shape (FOUR classes)

```python
@dataclass(frozen=True)
class RegistryChange:
    task_id: int
    drift_class: str          # "stale_real" | "missing_real" | "empty_stub" | "skipped" | "highest_id"
    detail: str               # human-readable, e.g. "tasks/approved/696 -> tasks/completed/696 (no body.md)"

@dataclass(frozen=True)
class ReconcileReport:
    applied: bool                          # False = dry-run; True = written
    stale_real: list[RegistryChange]       # registry path missing, task HAS body.md on disk -> re-point + re-snapshot
    missing_real: list[RegistryChange]     # on disk + HAS body.md + not in registry -> add entry + re-snapshot  (#703)
    empty_stubs: list[RegistryChange]      # task dir on disk, NO body.md  -> surfaced, NOT reconciled, NOT fabricated, NOT deleted
    skipped: list[RegistryChange]          # should reconcile but _read_body raised non-empty-stub error (e.g. malformed YAML)
    highest_id_bumped: RegistryChange | None
    @property
    def reconciled_count(self) -> int:     # len(stale_real)+len(missing_real)+(1 if highest_id_bumped else 0)
        ...
    @property
    def unresolved_count(self) -> int:     # len(empty_stubs)+len(skipped)
        ...
    @property
    def is_clean(self) -> bool:            # True iff zero changes proposed/applied AND no empty stubs AND no skips
        ...
```

The CLI prints per-class counts + the change lists; the tests assert against the per-class membership.

### 4.2 `reconcile_registry(*, apply=False) -> ReconcileReport` internal flow

Mirrors `audit()`'s detection (so the two never disagree about WHAT counts as drift) but classifies each drift by whether the task has a readable `body.md`. Pure read in dry-run; under `_locked()` only on the apply path.

```
def reconcile_registry(*, apply: bool = False) -> ReconcileReport:
    repo = repo_root()
    td   = tasks_dir()

    def _plan(reg):
        # Build {task_id_str: actual_disk_path} by scanning STATUSES dirs ONCE.
        disk = {}                                   # str(id) -> Path (under tasks_dir())
        if td.exists():
            for status_dir in td.iterdir():
                if not status_dir.is_dir() or status_dir.name not in STATUSES:
                    continue
                for child in status_dir.iterdir():
                    if child.is_dir() and child.name.isdigit():
                        disk[child.name] = child

        stale_real, missing_real, empty_stubs, skipped = [], [], [], []

        def _has_body(p):    # cheap existence check; classification, not a parse
            return (p / "body.md").exists()

        # Class 1 — stale registry path: entry exists, registry path missing.
        for tid, entry in reg.get("tasks", {}).items():
            abs_path = repo / entry["path"]
            if abs_path.is_dir():
                # 1b — registered, dir exists, but body.md is gone -> empty/partial stub.
                if not _has_body(abs_path):
                    empty_stubs.append(_change(tid, "empty_stub",
                        f"registered at {entry['path']}, dir exists but body.md missing"))
                continue                            # path fine (or 1b handled) — not class 1
            actual = disk.get(tid)
            if actual is None:
                # registry path stale AND task genuinely gone from disk -> skip (manual triage).
                skipped.append(_change(tid, "skipped",
                    f"registry path {entry['path']!r} missing AND no on-disk folder found"))
                continue
            if not _has_body(actual):
                empty_stubs.append(_change(tid, "empty_stub",
                    f"registry path {entry['path']!r} missing; on-disk dir {rel(actual)} has no body.md"))
                continue
            stale_real.append(_pending(int(tid), entry["path"], actual))

        # Class 2 — on disk but unregistered.
        for tid, actual in disk.items():
            if tid in reg.get("tasks", {}):
                continue
            if not _has_body(actual):
                empty_stubs.append(_change(tid, "empty_stub",
                    f"on disk at {rel(actual)} but no body.md (likely unmerged issue-{tid} branch residue)"))
                continue
            missing_real.append(_pending(int(tid), None, actual))

        return disk, stale_real, missing_real, empty_stubs, skipped

    if not apply:
        reg = _load_registry()
        disk, stale_real, missing_real, empty_stubs, skipped = _plan(reg)
        return _build_report(applied=False, ...)

    with _locked():
        reg = _load_registry()                      # re-read INSIDE the lock (a concurrent writer
                                                     # — e.g. a live issue-705/706/698 branch merging —
                                                     # may have changed it since dry-run)
        disk, stale_real, missing_real, empty_stubs, skipped = _plan(reg)
        applied_stale, applied_missing = [], []
        for pend in stale_real:
            try:
                fm, _ = _read_body(pend.actual / "body.md")     # exists() passed; a parse error here -> skipped
            except (FileNotFoundError, ValueError) as exc:      # NAMED tuple, both halves (Statistics REVISE)
                skipped.append(_change(pend.tid, "skipped", f"body.md unreadable: {exc}")); continue
            _registry_set(reg, pend.tid, pend.actual, fm)       # rewrites path + re-snapshots
            applied_stale.append(pend)
        for pend in missing_real:
            try:
                fm, _ = _read_body(pend.actual / "body.md")
            except (FileNotFoundError, ValueError) as exc:
                skipped.append(_change(pend.tid, "skipped", f"body.md unreadable: {exc}")); continue
            _registry_set(reg, pend.tid, pend.actual, fm)       # adds entry + bumps highest_id
            applied_missing.append(pend)
        bumped = _reconcile_highest_id(reg)                     # max(max_disk_id, current)
        wrote = bool(applied_stale or applied_missing or bumped)
        if wrote:
            _save_registry(reg)
            _git_commit([registry_path()], _reconcile_commit_msg(applied_stale, applied_missing, bumped))
        return _build_report(applied=True, stale_real=applied_stale, missing_real=applied_missing,
                             empty_stubs=empty_stubs, skipped=skipped, bumped=bumped, ...)
```

Key design points (all fail-fast, no silent swallow, no fabrication):

- **Empty-stub class is detected by `body.md` EXISTENCE during planning** (a cheap `(p / "body.md").exists()`), so a stub never reaches `_read_body` and never `FileNotFoundError`s the run. It is recorded in `report.empty_stubs` and **never written to the registry** — registering it from defaults would be silent fabrication (CLAUDE.md "Fail fast — never hide failures"). It is **never deleted** and its `body.md` content is **never touched** (out of scope — the dir may be live residue of an active `issue-<N>` branch).
- **The 4th `audit()` sub-check (`:2446-2448`, registered entry whose dir exists but lacks `body.md`) is naturally subsumed** — class 1's `abs_path.is_dir()` branch now checks `_has_body` and routes a registered-but-bodyless dir into `empty_stubs` with a distinguishing detail string ("registered at … dir exists but body.md missing"). I keep a SINGLE `empty_stub` class rather than a separate `partial_stub`: the policy is identical (surface, don't fabricate, don't delete), and the `detail` string already records whether the stub was registered or unregistered. Naming the policy explicitly: **any task dir lacking `body.md`, registered or not, is an empty stub — surfaced, never reconciled, never deleted.** (None of the current 13 are this registered-but-bodyless sub-case; #696's registry path is *missing* on disk, so it's the unregistered-on-its-actual-path branch.)
- **Re-snapshot from the ACTUAL on-disk path**, never the stale registry path — `_registry_set(reg, tid, actual, fm)` passes a real under-`tasks_dir()` path, so its internal `_status_from_path(actual)` resolves and the denormalized `status`/`title`/`kind`/`has_clean_result`/`goal` reflect where the task truly lives (e.g. #703 → `status: completed`).
- **`_read_body` errors are NEVER swallowed to a default.** A task whose `body.md` passed `exists()` but is malformed (the v3-tested case) is caught per-task as `(FileNotFoundError, ValueError)` — the FULL named tuple (the Statistics REVISE) — recorded in `report.skipped`, left out of the registry write, the run continues with the others. No `pass`, no fabricated entry.
- **Re-read the registry inside `_locked()`** on the apply path — a dry-run plan computed before the lock can be stale (a live `issue-705`/`issue-706`/`issue-698` branch may merge and bring `body.md` to `main` between dry-run and apply; the lock+re-read+re-plan handles this — if a merge lands first, that task simply reclassifies from `empty_stub` to a registered/`missing_real` task on the re-plan).
- **Atomicity:** one `_save_registry()` (atomic tmp-replace) + one `_git_commit([registry_path()], …)`. Only `REGISTRY.json` is staged; `commit --only --` guarantees concurrent-session staged files on the shared root are never captured.
- **Idempotence:** a second apply re-plans against the now-current registry; with #703 already added it finds zero `stale_real`/`missing_real` and no `highest_id` bump, so `wrote` is False and it neither writes nor commits. **Crucially, `empty_stubs` are STILL present on the second run (the stubs aren't fixed) — but they produce ZERO registry diff because reconcile never writes anything for them.** `_git_commit`'s empty-cached-diff early-return is a second backstop.
- **Never moves a task / changes a status.** Writes only `REGISTRY.json`; `set_status`'s `git mv` machinery is never invoked. The re-snapshotted `status` reflects the folder the task ALREADY sits in.

Private helpers added alongside: `_reconcile_highest_id(reg) -> RegistryChange | None`, `_reconcile_commit_msg(stale, missing, bumped) -> str` (e.g. `"registry-reconcile: 0 paths fixed, 1 entry added (#703); highest_id 712->712"`), `_build_report(...)`, `_change(...)`/`_pending(...)` small constructors.

### 4.3 CLI surface + exit semantics

```
task.py audit                      # unchanged: report-only, exit 1 on FAIL
task.py audit --repair             # dry-run: print proposed reconcile + empty stubs + skips, exit 0
task.py audit --repair --apply     # write REGISTRY.json + one git commit; exit per rules below
```

- `--apply` is meaningful only with `--repair` (argparse: `--apply` alone → error "use --apply only with --repair", exit 2).
- `cmd_audit` dispatch:
  - **No `--repair`:** existing behavior verbatim (`audit()` → PASS/FAIL, exit 1 on problems).
  - **`--repair` (no `--apply`):** `rep = reconcile_registry(apply=False)`; print `reconciled_count` + the `stale_real`/`missing_real` change lines, THEN print each `empty_stub` with its on-disk path under a header, THEN any `skipped`. **Always exit 0** (dry-run is informational). A clean registry prints "registry already reconciled — nothing to repair".
  - **`--repair --apply`:** `rep = reconcile_registry(apply=True)`; print what was written, then the empty stubs + skips. **Exit 0 iff `rep.unresolved_count == 0`** (i.e. `empty_stubs` empty AND `skipped` empty) — the registry now agrees with the filesystem. **Exit 1 if `rep.unresolved_count > 0`** — there is still unresolved drift; fail loud so the operator triages rather than assuming a clean run.
- **Empty-stub orientation line** (printed whenever `empty_stubs` is non-empty, both dry-run and apply):
  > "These are empty task stubs (no body.md on main). They likely live on `issue-<N>` branches that haven't merged. They require manual triage — see follow-up `kind: infra` task filed at the end of this run."
- **Exit codes summary:** plain `audit` → 0 clean / 1 drift (unchanged). `audit --repair` → 0 always (dry-run). `audit --repair --apply` → 0 if `unresolved_count == 0`, else 1.

## 8.1 Success + kill criteria

**Success criteria** (acceptance — all must hold before the task auto-completes):
1. **`uv run python scripts/task.py audit --repair --apply` classifies #696 + #698–#702 + #704–#709 (12 dirs) as empty stubs in `report.empty_stubs`, adds exactly ONE registry entry (#703), prints every empty stub with its on-disk path + the orientation line, and exits 1** (NOT 0 — unresolved drift remains). Decision rule: exit code == 1, registry diff adds exactly the #703 entry. (This REPLACES the v3 criterion "audit returns AUDIT PASS" — that is now impossible and was the factual error.)
2. **`git diff HEAD~1 -- tasks/REGISTRY.json` shows exactly one entry added (#703) and nothing fabricated** — verified by an independent manual eyeball (Step 6 step 3), not just the audit/reconcile PASS signal. No defaulted/empty entries for the 12 stubs.
3. **A follow-up `kind: infra` task is filed** (via the `/issue` Step-10 follow-up path / a `task.py new --kind infra`) to address the empty-stub class — decide policy: clean up the 12 stub dirs on `main` vs let the live `issue-<N>` branch merges naturally create the `body.md` (and a second follow-up for the upstream bug that creates bodyless `artifacts/` dirs on `main`). The follow-up is filed; deciding the policy is explicitly OUT of scope for #724.
4. `uv run pytest tests/test_task_workflow.py -v` passes including the ~13 new reconcile tests named in §5 (covering both drift classes, both halves of `(FileNotFoundError, ValueError)`, the exit semantics, and idempotency-with-stubs).
5. `uv run ruff check . && uv run ruff format --check .` clean on the diff; `uv run python scripts/workflow_lint.py` (no-flags default run) clean.
6. The reconcile commit on `main` touches ONLY `tasks/REGISTRY.json` (`git show --stat <commit>` = one file changed); no task `body.md` / `events.jsonl` / folder moved or modified; no empty-stub dir deleted.

**Kill criteria** (halt and report rather than push through):
1. A `body.md`-existence check or `_read_body` call crashes the WHOLE run rather than landing the task in `empty_stubs`/`skipped` (e.g. a `FileNotFoundError` escapes for a stub). Halt: do NOT commit a partial `REGISTRY.json`; post `epm:failure v1` (`failure_class: code`) with the offending task id. The `body.md`-existence pre-check is precisely the guard that prevents this — its failure means the design contract is broken.
2. Reconcile WRITES a registry entry for any of the 12 empty stubs (fabrication). Halt: revert the commit; post `epm:failure v1` (`failure_class: code`). This is the binding-fix being validated — fabrication is the failure v4 exists to prevent.
3. Idempotency violation: a second `audit --repair --apply` immediately after the first produces a non-empty registry diff (even with empty stubs still present). Halt: revert the first commit, post `epm:failure v1` (`failure_class: code`).
4. Concurrent-writer collision surfaces as a non-trivial `_locked()` wait (>30s) on the apply path (a live `issue-<N>` branch holding the lock). Halt: surface as a workflow-fix candidate rather than push past with a retry loop (the upstream race is a known follow-up; do NOT mask it).
5. Tests fail in a way suggesting the reconcile touched task folders / `body.md` content / deleted a stub dir. Halt: the contract is "registry-only writes, stubs untouched"; a violation means the function drifted from scope.
