## TL;DR

The registry index (`tasks/REGISTRY.json`) has drifted from the on-disk task layout: 13 tasks are either pointed at the wrong folder (#696) or absent from the index entirely (#698–#709, mostly terminal). `task.py audit` already *detects* all 13 but can only report. This plan adds a `reconcile_registry(*, apply)` library function and a `task.py audit --repair [--apply]` flag that **points the index at where tasks already live on disk** — it rewrites stale paths, adds missing entries (re-snapshotting denormalized fields from each task's actual `body.md`), and bumps `highest_id`. It **never moves a task or changes a status**. Dry-run by default; the apply path is `_locked()` + one atomic registry write + one git commit, matching `task.py`'s mutation contract. A test pins all four reconcile behaviors (dry-run reports without mutating, apply writes correctly without touching task folders, idempotence, `highest_id` bump). The final deliverable is a one-shot `--repair --apply` run that clears the live drift and commits the result.

## 4. Design

### 4.1 `ReconcileReport` data shape

```python
@dataclass(frozen=True)
class RegistryChange:
    task_id: int
    drift_class: str          # "stale_path" | "missing_entry" | "highest_id"
    detail: str               # human-readable, e.g. "tasks/approved/696 -> tasks/completed/696"

@dataclass(frozen=True)
class ReconcileReport:
    applied: bool             # False = dry-run (proposed only); True = written
    stale_path_fixed: list[RegistryChange]
    missing_added: list[RegistryChange]
    highest_id_bumped: RegistryChange | None
    skipped: list[str]        # tasks that could not be reconciled (no body / parse error), with reason
    @property
    def total_changes(self) -> int: ...
    @property
    def is_clean(self) -> bool:     # True iff zero changes proposed/applied AND no skips
```

This is what the CLI prints and the tests assert against (counts per class + the change list + skips).

### 4.2 `reconcile_registry(*, apply=False) -> ReconcileReport` internal flow

Mirrors `audit()`'s detection logic exactly (so the two never disagree about what counts as drift) but, instead of appending strings, *plans then optionally applies* a fix per class. Pure read in dry-run; under `_locked()` only on the apply path.

```
def reconcile_registry(*, apply: bool = False) -> ReconcileReport:
    repo = repo_root()
    td   = tasks_dir()

    def _plan(reg) -> (changes...):
        # Build {task_id_str: actual_disk_path} by scanning STATUSES dirs ONCE.
        disk = {}                              # str(id) -> Path  (under tasks_dir())
        if td.exists():
            for status_dir in td.iterdir():
                if not status_dir.is_dir() or status_dir.name not in STATUSES:
                    continue
                for child in status_dir.iterdir():
                    if child.is_dir() and child.name.isdigit():
                        disk[child.name] = child

        stale, missing, skipped = [], [], []

        # Class 1 — stale registry path: entry exists, registry path missing,
        # but the task IS on disk somewhere else. Re-point + re-snapshot.
        for tid, entry in reg.get("tasks", {}).items():
            abs_path = repo / entry["path"]
            if abs_path.is_dir():
                continue                       # path fine — not this class
            actual = disk.get(tid)
            if actual is None:
                skipped.append(f"#{tid}: registry path {entry['path']!r} missing AND no on-disk folder found (manual triage)")
                continue
            stale.append((int(tid), entry["path"], actual))

        # Class 2 — on disk but unregistered.
        for tid, actual in disk.items():
            if tid in reg.get("tasks", {}):
                continue
            missing.append((int(tid), actual))

        return disk, stale, missing, skipped

    if not apply:
        reg = _load_registry()
        disk, stale, missing, skipped = _plan(reg)
        return _build_report(applied=False, reg=reg, stale=stale, missing=missing, skipped=skipped, disk=disk)

    with _locked():
        reg = _load_registry()                 # re-read INSIDE the lock (a concurrent
                                                # writer may have changed it since dry-run)
        disk, stale, missing, skipped = _plan(reg)
        changed_paths = [registry_path()]
        for tid, old, actual in stale:
            fm, _ = _read_body(actual / "body.md")        # may raise -> caught below
            _registry_set(reg, tid, actual, fm)           # rewrites path + re-snapshots
        for tid, actual in missing:
            fm, _ = _read_body(actual / "body.md")
            _registry_set(reg, tid, actual, fm)           # adds entry + bumps highest_id
        # Class 3 — highest_id sanity (after the sets above; _registry_set already
        # bumps per task, but bump explicitly to cover the no-task-changes case).
        bumped = _reconcile_highest_id(reg)               # max(max_disk_id, current)
        if not (stale or missing or bumped):
            return _build_report(applied=True, reg=reg, stale=[], missing=[], skipped=skipped, disk=disk)  # nothing to write
        _save_registry(reg)
        _git_commit(changed_paths, _reconcile_commit_msg(stale, missing, bumped))
        return _build_report(applied=True, reg=reg, stale=stale, missing=missing, skipped=skipped, disk=disk)
```

Key design points (all fail-fast, no silent swallow):

- **Re-snapshot from the ACTUAL on-disk path**, never the stale registry path — `_registry_set(reg, tid, actual, fm)` passes a real under-`tasks_dir()` path, so its internal `_status_from_path(actual)` resolves correctly and the denormalized `status`/`title`/`kind`/`has_clean_result`/`goal` reflect where the task truly lives (e.g. #696 becomes `status: completed`, not `approved`).
- **`_read_body` errors are NOT swallowed to a default.** A task whose `body.md` is missing or malformed is recorded in `report.skipped` with the reason and left out of the registry write (we do NOT fabricate an empty entry — that would mask a real corruption). The apply path catches `(FileNotFoundError, ValueError)` *per task*, appends to `skipped`, and continues with the others; it never `pass`es silently. (audit() uses the same fail-soft-per-task posture at `:2414-2416`.)
- **Re-read the registry inside `_locked()`** on the apply path. A dry-run plan computed before the lock could be stale; the lock+re-read+re-plan is what makes the mutation atomic against a concurrent writer.
- **Atomicity:** one `_save_registry()` (atomic tmp-replace) + one `_git_commit([registry_path()], …)`. Only `REGISTRY.json` is staged; `_git_commit`'s `--only --` guarantees concurrent-session staged files on the shared root are never captured.
- **Idempotence:** a second apply run re-plans against the now-clean registry, finds zero stale/missing and no highest_id bump, returns early WITHOUT writing or committing. (`_git_commit`'s empty-cached-diff early-return is a second backstop.)
- **Never moves a task / changes a status.** The function only `git mv`s nothing and writes only `REGISTRY.json`. `set_status`'s `git mv` machinery is NOT reused or invoked.

Helper functions added alongside (small, private): `_reconcile_highest_id(reg) -> RegistryChange | None`, `_reconcile_commit_msg(stale, missing, bumped) -> str` (e.g. `"registry-reconcile: 1 path fixed, 12 entries added (#696 #698…#709)"`), `_build_report(...)`.

### 4.3 CLI surface

```
task.py audit                      # unchanged: report-only, exit 1 on FAIL
task.py audit --repair             # dry-run: print proposed reconcile changes, exit 0
task.py audit --repair --apply     # write REGISTRY.json + one git commit, exit 0
```

- `--apply` is meaningful only with `--repair` (argparse: `--apply` alone → error "use --apply only with --repair", exit 2).
- `cmd_audit` dispatch:
  - No `--repair`: existing behavior verbatim (`audit()` → PASS/FAIL, exit 1 on problems).
  - `--repair` (no `--apply`): `rep = reconcile_registry(apply=False)`; print `total_changes` + per-class change lines + any `skipped` (prefixed `SKIP:`). Exit 0 (dry-run is informational; a clean registry prints "registry already reconciled — nothing to repair"). If `rep.skipped` is non-empty, print a trailing `WARNING: N task(s) need manual triage` but still exit 0 (the reconcilable ones are reported).
  - `--repair --apply`: `rep = reconcile_registry(apply=True)`; print what was written + skips; exit 0 on success. If `rep.skipped` is non-empty, exit 1 (some drift was NOT reconciled — fail loud so the operator triages rather than assuming a clean run).
- **Exit codes:** plain `audit` → 0 clean / 1 drift (unchanged). `audit --repair` → 0 always (dry-run). `audit --repair --apply` → 0 if all drift reconciled, 1 if any `skipped` remain.

## 7. Risks / failure modes

| Risk | Likelihood | Mitigation |
|---|---|---|
| Drift changes between dry-run preview and `--apply` (a concurrent session mutates) | Low | Apply path re-reads the registry INSIDE `_locked()` and re-plans; the dry-run is advisory only. The lock serializes against every other `task.py` mutation. |
| `body.md` missing / malformed frontmatter for a drifted task (denormalized snapshot would fail) | Medium | Per-task `try/except (FileNotFoundError, ValueError)` → record in `report.skipped` with reason, do NOT fabricate an entry, do NOT crash the whole run; `--apply` exits 1 if any skips remain so the operator triages. No silent default. |
| A registry path is stale AND the task is genuinely gone from disk (no on-disk folder) | Low | Recorded in `report.skipped` ("no on-disk folder found — manual triage"); never silently dropped from the registry (that would erase a real entry). |
| `_git_commit` captures unrelated staged files on the shared repo root | Low | `_git_commit` already uses `commit --only -- tasks/REGISTRY.json`; only the registry is staged. |
| Race against a concurrent writer holding the flock | Designed-for | `_locked()` blocks until the other writer's commit lands; we then re-read its result. One atomic write + commit. |
| Double-counting `highest_id` (per-task bump in `_registry_set` + explicit `_reconcile_highest_id`) | Low | `_reconcile_highest_id` is `max(current, max_disk_id)` — idempotent; the per-task bump is a subset of it. |
| Reconcile silently changes a task's status | Designed-out | The function writes only `REGISTRY.json`; it never `git mv`s a folder. The re-snapshotted `status` field reflects the folder the task ALREADY sits in — it does not move the task. Test `test_reconcile_never_touches_task_folders` pins this. |

## 8.1 Success + kill criteria

**Success criteria** (acceptance — all must hold before the task auto-completes):
1. `uv run python scripts/task.py audit` returns `AUDIT PASS — registry and filesystem agree` (currently reports 13 problems). Decision rule: zero problem lines on the post-reconcile audit run.

3. `uv run ruff check . && uv run ruff format --check .` clean on the diff.
4. `uv run python scripts/workflow_lint.py` (no-flags default run) clean.
5. The reconcile commit on `main` touches ONLY `tasks/REGISTRY.json` (verified via `git show --stat <commit>` showing one file changed); no task `body.md` / `events.jsonl` / task folder is moved or modified.

**Kill criteria** (halt and report rather than push through):
1. Any `body.md` parse failure during the live reconcile that isn't already captured in `report.skipped` — i.e. the parser itself crashes rather than recording a per-task skip. Halt: do NOT commit a partial `REGISTRY.json`; post `epm:failure v1` (`failure_class: code`) with the offending task id.
2. Idempotency violation: a second `task.py audit --repair --apply` immediately after the first produces a non-empty registry diff. Halt: revert the first commit, post `epm:failure v1` (`failure_class: code`).
3. Concurrent-writer collision: the `_locked()` flock contention surfaces as a non-trivial wait (>30s) on the apply path. Halt: surface the contention as a workflow-fix candidate rather than push past it (the upstream race is a known follow-up; do NOT mask it with a retry loop).
4. Tests fail in a way that suggests the reconcile logic touched task folders / `body.md` content (e.g. assertion (b) in §5 fails). Halt: the design contract is "registry-only writes"; a violation here means the function fundamentally drifted from scope.
