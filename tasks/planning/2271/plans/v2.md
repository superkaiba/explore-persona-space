## 1. Requirement + acceptance criteria

Goal (task #2271 body `## Goal` H2, verbatim — kind: infra has no `goal:` frontmatter):

> Make the canonical raw-completions upload helper persist EVERY rollout-text
> file under the tree it walks — pre-merge per-shard payloads included — so a
> shard-structured generation run cannot reach a clean `[phase=upload]` line with
> 15+ MB of its own rollout text left on a pod volume that dies with the pod.

Acceptance criteria (task body, verbatim):

1. The helper persists every regular file under the walked tree, or fails loud
   naming what it skipped — never a silent partial upload behind a success log.
2. A regression test builds a raw_completions tree WITH a nested `shards/`
   subdir and asserts every file reaches the destination prefix (the shape that
   actually regressed — a flat-tree-only fixture would pass today).
3. Verify against a real prefix that a shard-structured run leaves
   `verify_uploads.py --outroot-listing` at `matched == disk`.

The bug (verified live by the clarifier at `hub.py:2546`, re-verified this
session): selection is by EXACT filename —
`rglob("raw_completions.json")` + `allow_patterns=["raw_completions.json",
"**/raw_completions.json"]` — so a sibling payload like
`raw_completions/phaseA/A0__7b/shards/shard_{0..3}of4.json` (15.6 MB of rollout
text on #2223) is never visited; nothing raises; the phase logs its normal
success line. The EXACT-set verify inside `_upload_folder_filtered` verifies
only the set the predicate already chose, so it structurally cannot catch an
unvisited sibling.

## 2. The design fork — candidates, trade-offs, recommendation

Criterion 1's first branch read literally ("persist every regular file under
the walked tree") is NOT safe, for reasons verified this session:

- Callers pass two different tree shapes (classification table, §3): dedicated
  raw-completions roots AND whole eval-results roots.
- `scripts/issue2223_drift.py:3308` passes the eval-results root and the very
  next lines (3312–3324) upload `out_dir/analysis_tensors` separately to its
  own prefix — an unconditional whole-tree upload double-uploads the run's
  largest artifacts. `scripts/issue_653/i653_dispatch.py` likewise uploads
  `mixes/`, `onpolicy_pools/`, and `armB/dx_tensors` to their own buckets
  immediately before calling the helper.
- `scripts/run_experiment_389.py:2738` docstring: "Eval JSONs live in git on
  issue-389" — the aggregate-JSON exclusion is deliberate, and the Upload
  Policy table routes aggregated eval JSON to git, not HF.
- HF file-count slots are scarce (#2332 reclaimed 492,786; #1108/#2304 exist
  because the data repo hit its 1,000,000-file cap live).
- Against that: the Upload Policy is unambiguous that rollout text is the
  UNCONDITIONAL-upload class; only a large intermediate TENSOR may ever be a
  declared discard. The shard payloads MUST land. "Skip quietly" is not
  available.

### Candidate designs

**Design A — upload everything under the walked tree.** Satisfies criterion
1's first branch literally. REJECTED: at the 8 eval-results-root call sites it
uploads git-routed aggregate JSONs to HF (policy violation, explicitly
deliberate exclusion at #389), double-uploads `analysis_tensors/` (#2223) and
`mixes/`/`onpolicy_pools/`/`dx_tensors` (#653) — the largest artifacts in
those runs — and burns file-count slots on a repo that has already hit its cap.

**Design B — keep the exact-name predicate; fail loud (raise) on any
unuploaded residue.** Satisfies criterion 1's second branch literally.
REJECTED as the default: every healthy eval-results-root run ALWAYS has
residue (aggregate JSONs, sentinels, separately-uploaded tensor dirs), so an
unconditional raise breaks ~10 call sites on healthy runs and converts every
future shard-structured run into a hard failure + manual upload instead of a
persisted payload. It also leaves the rollout text un-persisted — the Upload
Policy wants the text LANDED, not the run killed.

**Design C — widen the predicate to the rollout-text CLASS + mandatory skip
accounting on the success path + opt-in strict mode (RECOMMENDED).** Three
parts:

1. **Widen selection** to the project's two rollout-text path conventions:
   - any file named exactly `raw_completions.json`, at any depth (current
     behavior, kept); PLUS
   - **every regular file under any directory literally named
     `raw_completions`** within the walked tree. The local `raw_completions/`
     directory is the project's own class marker (it mirrors the HF
     destination bucket); by convention nothing but rollout text lives there,
     and the reproduced #2223 shape
     (`raw_completions/phaseA/A0__7b/shards/shard_0of4.json`) is exactly this
     class. Verified on the pinned `huggingface_hub==0.36.2`
     `filter_repo_objects` (the same filter `upload_folder` applies): the
     4-pattern glob set selects the shard shape and every current exact-name
     shape, and EXCLUDES `run_result.json`, `phase4/phase4a_verdict.json`,
     `analysis_tensors/foo.npy`, `xraw_completions.json`,
     `raw_completionsX/bar.json` (battery output in §12 A2).
2. **Skip accounting — the success line can never again read as "everything
   uploaded".** The helper enumerates ALL regular files under the walked tree,
   computes `skipped = all − selected`, and (a) logs ONE structured line
   naming the skipped count + first 25 rel paths + the reason ("outside the
   raw-completions class — aggregates live in git, tensors upload via their
   own phase"), and (b) carries `skipped=<M>` on its completion log line. A
   partial upload is thereby never SILENT: what was not uploaded is named in
   the same log the success line lives in.
3. **Opt-in strict mode** — new keyword-only param
   `on_unmatched: str = "disclose"`; `"raise"` raises `RuntimeError` naming
   every skipped file BEFORE any network call; the value is VALIDATED at
   function entry (`ValueError` on anything outside `{"disclose", "raise"}` —
   Must-Fix 2; a typo can never silently run non-strict). Available for
   dedicated-root callers (a tree that should contain ONLY rollout text); no
   existing call site is rewired in this task (must-ask, §8).

**Why C over A/B:** C persists the entire class the policy mandates (criterion
1 branch 1, scoped to the class the helper is responsible for), names every
skip in the log (the not-silent guarantee), never uploads what policy routes
elsewhere, and never double-uploads. The residual — a rollout-text stray in a
DEDICATED root that neither carries the exact name nor sits under a
`raw_completions/` component (e.g. a hypothetical future
`raw_upload/<label>/cell/shards/` stray at the #2203 call site) — is (i) named
in the helper's skip line, (ii) caught at Step 8 by `verify_uploads.py`
`check_outroot_residue` (#2187/#2162 — the instrument that caught this bug,
which FAILs the verdict on any disk file with no permanent home), and (iii)
closable per-caller via `on_unmatched="raise"`. This layered answer is stated
as the resolution of criterion 1's either/or: persist the class / name the
rest / instrument-FAIL anything that has no home anywhere.

**Instrument-scope caveat on layer (ii)** (non-blocking, carried from the
Alternatives critic): `check_outroot_residue` fires only where the walked tree
IS the run's Step-8 out-root — a helper call over some other tree leans on the
disclosure line (layer (i)) alone. Acceptable (AC1's second branch is
satisfied by the naming), but remember it when reading any future stray
incident.

```python
def upload_raw_completions_to_data_repo(
    experiment_name: str,
    eval_results_dir: Path,
    delete_after: bool = False,
    *,
    on_unmatched: str = "disclose",   # "disclose" (log skips) | "raise" (strict roots)
) -> dict[str, str]:
```

(c) Selection block — replaces current lines 2546–2560 (verbatim current line
2546: `    raw_paths = sorted(eval_results_dir.rglob("raw_completions.json"))`;
this is the FIRST executable statement after the docstring, so the validation
below runs at function entry, before any enumeration or network call):

```python
    if on_unmatched not in ("disclose", "raise"):
        raise ValueError(
            "upload_raw_completions_to_data_repo: on_unmatched must be "
            f"'disclose' or 'raise', got {on_unmatched!r}"
        )

    from huggingface_hub.utils import DEFAULT_IGNORE_PATTERNS, filter_repo_objects

    all_paths = sorted(p for p in eval_results_dir.rglob("*") if p.is_file())
    all_rels = [p.relative_to(eval_results_dir).as_posix() for p in all_paths]
    # Mirror _upload_folder_filtered's filter exactly: allow patterns + the
    # always-on training-state excludes + upload_folder's OWN unconditional
    # default excludes (.git/, .cache/huggingface/ — hf_api.py:4901 runs
    # `ignore_patterns += DEFAULT_IGNORE_PATTERNS` on EVERY call), so the
    # enumerated set == the committed set. Omitting DEFAULT_IGNORE_PATTERNS
    # here puts .cache/huggingface/** sidecars (an hf_hub_download local_dir=
    # staging pull's metadata files) into expected_repo_paths that the commit
    # will never contain → the exact-set verify hard-fails a HEALTHY tree.
    # Precedent: the #1190 count-guard mirror in this module (hub.py:1276-1284)
    # includes DEFAULT_IGNORE_PATTERNS for the same parity reason. Import is
    # deliberately unconditional (no try/except): on the pinned 0.36.2 the
    # constant resolves; a future rename should crash loud here, not degrade
    # into the healthy-tree hard-failure shape.
    selected_rels = list(
        filter_repo_objects(
            all_rels,
            allow_patterns=RAW_COMPLETIONS_ALLOW_PATTERNS,
            ignore_patterns=list(TRAINING_STATE_IGNORE_PATTERNS)
            + list(DEFAULT_IGNORE_PATTERNS),
        )
    )
    selected_set = set(selected_rels)
    skipped_rels = [r for r in all_rels if r not in selected_set]

    if not selected_rels:
        logger.warning(
            "upload_raw_completions_to_data_repo: no raw-completions-class files "
            "(raw_completions.json at any depth, or any file under a "
            "raw_completions/ directory) found under %s — nothing to upload",
            eval_results_dir,
        )
        return {}

    if skipped_rels:
        skip_msg = (
            f"upload_raw_completions_to_data_repo: skipped {len(skipped_rels)} "
            f"file(s) under {eval_results_dir} outside the raw-completions class "
            f"(first {min(len(skipped_rels), 25)}): {skipped_rels[:25]} — aggregate "
            "eval JSONs live in git and tensors upload via their own phase (Upload "
            "Policy); a rollout-text payload in this list is a caller bug: place it "
            "under a raw_completions/ directory or name it raw_completions.json."
        )
        if on_unmatched == "raise":
            raise RuntimeError(skip_msg)
        logger.info(skip_msg)

    path_in_repo = f"{experiment_name}/raw_completions"
    rels = selected_rels
    expected_repo_paths = [f"{path_in_repo}/{rel}" for rel in rels]
```
