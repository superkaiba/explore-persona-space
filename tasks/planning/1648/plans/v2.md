## 4. Design

### 4.1 New code in `scripts/workflow_lint.py`

**Placement:** immediately after `check_git_recipes_root_guard` (it reuses that section's helpers); constants adjacent to the function (the root-guard style, `:9507-9519`).

**Constants + detection logic:**

```python
# --check-bare-commit-pathspec (#1648): a fenced `git commit` recipe with no
# pathspec commits the WHOLE staged index — on the always-concurrent shared
# repo root that sweeps sibling sessions' staged files onto the commit
# (incident 7dbde267f1, 2026-07-21: 4 foreign files swept onto main; #1630
# fixed /daily per-file). Convention: CLAUDE.md § Concurrent repo-root
# committers ("stage by explicit path only") — the commit-side analogue is
# the pathspec-limited `git commit -m "..." -- <paths>` form.
_BARE_COMMIT_SENTINEL = "workflow-lint: allow-bare-commit-block"
# One git-commit INVOCATION: `git <global-flags>* commit`; group 1 captures
# the global flags so the -C exemption is per-invocation (a `git -C` command
# elsewhere on the line cannot waive a separate bare commit).
BARE_COMMIT_GIT_RE = re.compile(
    r"(?<![\w./-])git\s+((?:-c\s+\S+\s+|--\S+\s+|-C\s+\S+\s+)*)commit\b"
)
BARE_COMMIT_GITC_FLAG_RE = re.compile(r"(?:^|\s)-C\s")   # case-sensitive: -C dir, not -c cfg
BARE_COMMIT_PATHSPEC_RE = re.compile(r"\s--\s+\S")       # ` -- ` + >=1 following token
BARE_COMMIT_XARGS_RE = re.compile(r"(?<![\w./-])xargs\s")
```

**`check_bare_commit_pathspec(*, repo_root: Path | None = None) -> list[str]`** (signature mirrors `check_git_recipes_root_guard`):

```
for path in _root_guard_target_files(repo_root or _REPO_ROOT):
    for (opener, preceding, block) in _iter_bash_fences(path text):
        if _root_guard_fence_exempt(preceding, sentinel=_BARE_COMMIT_SENTINEL):
            continue                          # per-fence waiver, non-empty reason required
        for each line in block (index i):
            join backslash continuations (` \` at EOL -> append next line, advancing i)
            stripped = logical.strip()
            if stripped.startswith("#"): continue          # comment line
            extend `logical` with following block lines until double quotes
                balance (bounded by block end)             # multi-line -m "..." messages
            for m in BARE_COMMIT_GIT_RE.finditer(logical):
                if BARE_COMMIT_GITC_FLAG_RE.search(m.group(1)): continue   # git -C <tree> commit
                if BARE_COMMIT_XARGS_RE.search(logical[:m.start()]): continue  # xargs appends the file list = runtime pathspec
                if "--dry-run" in logical: continue                        # preview line (check_piped_git_push precedent)
                if BARE_COMMIT_PATHSPEC_RE.search(logical[m.end():]): continue  # ` -- <pathspec>` present
                errors.append(f"{rel}:{opener + 1 + first_line_of_logical}: fenced `git commit` without a "
                              "trailing ` -- <pathspec>` — a bare commit at the shared repo root sweeps "
                              "concurrent sessions' staged files (incident 7dbde267f1; #1648). Append "
                              "` -- <explicit paths>`, scope with `git -C <tree>`, or waive the fence with "
                              "'<!-- workflow-lint: allow-bare-commit-block: <reason> -->' on the "
                              "immediately-preceding non-blank line.")
```

**Quote-balance rule:** count unescaped `"` on the logical line; odd count ⇒ append following block lines until even (needed so `git -C "$WT" commit -m "multi\nline msg"` and the issue/SKILL.md:11618 xargs form — whose ` --` tail sits after a 4-line quoted message — classify on the full command; both validated in the prototype).

**Helper change (one existing function):** parametrize the sentinel in `_root_guard_fence_exempt`:

```python
-def _root_guard_fence_exempt(prev_line: str) -> bool:
+def _root_guard_fence_exempt(prev_line: str, sentinel: str = _ROOT_GUARD_EXEMPT_SENTINEL) -> bool:
```

(body: replace the two `_ROOT_GUARD_EXEMPT_SENTINEL` uses with `sentinel`; the one existing call site is unchanged by the default. Implementer MAY instead add a thin delegate `_fence_sentinel_exempt` — either form is fine; keep the reason-stripping semantics byte-identical.)

**Structural exemptions — rationale per class (prototype-validated against all 17 live lines):**

| Class | Why exempt | Live instances |
|---|---|---|
| ` -- <pathspec>` tail | the required convention itself | uploader.md:95, daily:635, paper-plots:368, issue:2277/7521/9583/9729 |
| `git -C <tree> commit` (per-invocation, case-sensitive `-C`) | commits a NAMED tree (worktree/scratch/pod clone), each with its OWN index — not the ambient shared root | workflow-improver.md:254, issue:11130/11846 (+ the -C rows above) |
| `xargs ... git commit` | xargs appends the file list as trailing args = runtime pathspec (the live instance additionally ends with ` --`) | issue:11618 |
| comment lines (`#`) | instruction/anti-pattern prose, not a command | daily:627, issue:11067/11091 |
| `--dry-run` | preview, commits nothing (mirrors `check_piped_git_push`) | 0 live |
| per-fence sentinel `<!-- workflow-lint: allow-bare-commit-block: <reason> -->` | future deliberate anti-pattern examples / pod-side recipes | 0 needed at landing |

**"Has a pathspec" = the literal ` -- ` separator + ≥1 following token.** Justification: (a) it is the project convention (CLAUDE.md § Concurrent repo-root committers "stage by explicit path"; #1630's fix used exactly this form, as do uploader.md:95 and paper-plots:368); (b) it is mechanical — no parsing needed to distinguish trailing path arguments from message text; (c) a bare trailing `--` with nothing after does NOT count (it commits the whole index anyway), except under xargs where the appended args land after it. Positional-path forms without `--` (`git commit -m msg path/`) would flag — zero live instances; the fix is to add the `--` (strictly clearer).

**Named residuals (documented in the check docstring, root-guard style):** (a) untagged / other-tagged fences not scanned — prototype scanned ALL fences and found ZERO git-commit lines outside bash-tagged ones today; (b) prose inline-code recipes — structurally outside a fence scanner (same as root-guard residual (b)); (c) heredoc bodies inside fences are scanned as lines (a heredoc-embedded commit string could false-positive — zero live; sentinel waives); (d) a quoted message CONTAINING the literal text `git commit -m ...` could false-positive after quote-joining — zero live; sentinel waives; (e) `-C "path with spaces"` fails the flags-group match and the invocation goes unflagged (fails toward pass) — zero live; (f) `scripts/**/*.sh` shell scripts are OUT of scope (deliberate: they run in varied cwds — pods, worktrees — where bare commits are often legitimately scoped; the Goal targets the documented-recipe teaching surface).
