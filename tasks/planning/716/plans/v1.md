## 0. Plan Summary

- **What:** Add a pre-`git mv` destination-collision guard inside
  `explore_persona_space.task_workflow.set_status()` (the `_run_git(["mv", ...])` at line 1387).
- **Why it's needed:** When `tasks/<new-status>/<N>/` already exists, `git mv tasks/<old>/<N>
  tasks/<new>/<N>` does NOT error — git treats an existing destination directory as a *container*
  and nests the source as `tasks/<new>/<N>/<N>/`. The `_run_git` call (`check=True`) returns 0,
  so the failure surfaces a few lines later at `_read_body(new / "body.md")` — `body.md` is now
  at `<N>/<N>/body.md` — leaving the workflow half-moved (source deleted, dest nested, REGISTRY
  not yet updated, no `epm:status-changed` event, no commit). Recovery is manual git surgery
  (incident #681, 2026-06-28).
- **The change:** Before the `git mv`, if `new` exists: `rmdir()` it when empty (safe — a missing
  destination makes `git mv` perform a true rename, not a nest), else raise `ValueError` naming the
  orphan path + an inspection command. A non-directory at `new` (defensive) also raises.
- **Exception type:** `ValueError`, consistent with the 8+ existing `raise ValueError` sites in
  this module (incl. the two already in `set_status`). The task body's `SetStatusError` sketch is
  NOT adopted — no concrete reason to introduce a new exception class.
- **Contract preserved:** The guard is entirely inside the existing `with _locked():` block and
  before the `git mv`; the atomic-transition contract (`git mv` + REGISTRY update +
  `epm:status-changed` in ONE `_git_commit`, under `flock`) is untouched. The `rmdir()` of an
  empty orphan is an un-tracked filesystem op on an empty dir (git does not track empty dirs), so
  it adds nothing to the commit and changes no staged state.
- **Tests:** 2 regression tests added to `tests/test_task_workflow.py` (empty orphan → recovers;
  non-empty orphan → raises). Both use the existing `fake_repo` fixture.
- **Risk:** Low. Single function, additive guard, fail-loud. Primary risk is mis-detecting
  "empty" — handled by `Path.iterdir()` emptiness check, not `os.rmdir` swallowing.

## 1. Goal

Make `task_workflow.set_status()` fail loud and recover gracefully when the destination task
directory already exists, instead of silently producing a nested `tasks/<new>/<N>/<N>/` layout
and then crashing half-way through the transition. Concretely: insert a destination-collision
guard in `set_status()` immediately before its `_run_git(["mv", ...])` call so that (a) an
**empty** orphan destination directory is removed and the move proceeds as a true rename, and
(b) a **non-empty** destination directory (leftover artifacts / a concurrent non-`task.py` writer)
raises a clear `ValueError` that names the offending path and the inspection command — before any
destructive `git mv` runs. The atomic-transition contract and the `flock` serialization are
preserved unchanged.

## 2. Method delta

**Function:** `set_status()` in `src/explore_persona_space/task_workflow.py`
(definition starts line 1344).

**Current code (lines 1380-1387)** — the block being modified:

```python
        repo = repo_root()
        new_parent = tasks_dir() / new_status
        new_parent.mkdir(parents=True, exist_ok=True)
        new = new_parent / str(task_id)
        # `git mv` so renames are tracked
        rel_old = old.relative_to(repo)
        rel_new = new.relative_to(repo)
        _run_git(["mv", str(rel_old), str(rel_new)])
```

The defect: between computing `new` (line 1383) and `_run_git(["mv", ...])` (line 1387) there is
**no check** that `new` does not already exist. `git mv SRC DST` where `DST` is an existing
directory nests `SRC` inside `DST` and exits 0; `_run_git`'s `check=True` therefore does not fire,
and the function proceeds to `_read_body(new / "body.md")` (line 1390) which raises
`FileNotFoundError` because `body.md` is now under `new/<task_id>/`.

**Delta:** insert a guard block AFTER `new = new_parent / str(task_id)` (line 1383) and BEFORE the
`rel_old`/`rel_new`/`_run_git(["mv", ...])` lines (1385-1387). No other lines change. The
`_run_git(["mv", ...])` pattern appears ONLY at line 1387 (clarifier-verified), so the fix is
scoped to this one call site.

## 3. Concrete diff

Replace lines 1380-1387 with the following (the new guard is the block introduced between
`new = new_parent / str(task_id)` and the `# `git mv`` comment):

```python
        repo = repo_root()
        new_parent = tasks_dir() / new_status
        new_parent.mkdir(parents=True, exist_ok=True)
        new = new_parent / str(task_id)
        # Destination-collision guard (incident #681, 2026-06-28). `git mv SRC
        # DST` where DST already exists does NOT error — git nests SRC inside
        # DST as tasks/<new>/<id>/<id>/, exits 0, and the failure surfaces only
        # later at `_read_body(new / "body.md")`, leaving the transition
        # half-applied. So check DST up front.
        if new.exists():
            if not new.is_dir():
                raise ValueError(
                    f"task #{task_id}: cannot move to {new_status}: destination "
                    f"{new} exists and is not a directory. Inspect/remove it: "
                    f"ls -la {new}"
                )
            if any(new.iterdir()):
                raise ValueError(
                    f"task #{task_id}: cannot move to {new_status}: destination "
                    f"{new} already exists and is non-empty (orphan dir or "
                    f"leftover artifacts from a prior numbering / concurrent "
                    f"session). `git mv` would nest the task as {new}/{task_id}/. "
                    f"Inspect it (`git -C {repo} status -- {new.relative_to(repo)}` "
                    f"and `ls -la {new}`) and remove/relocate it before retrying."
                )
            # Empty orphan directory: remove it so `git mv` performs a true
            # rename rather than nesting the source inside it. git does not
            # track empty dirs, so this is an untracked filesystem op that adds
            # nothing to the commit and leaves no staged change.
            new.rmdir()
        # `git mv` so renames are tracked
        rel_old = old.relative_to(repo)
        rel_new = new.relative_to(repo)
        _run_git(["mv", str(rel_old), str(rel_new)])
```

Notes on the implementation choices:

- **`any(new.iterdir())`** for the emptiness test — explicit and does not rely on `rmdir`'s
  `OSError` to signal non-empty (fail-loud, not exception-swallowing). `new.rmdir()` is then only
  called on a confirmed-empty dir, so it cannot mask data.
- **`ValueError`** for both error branches — matches every existing raise in this module,
  including the two already inside `set_status` (lines 1358, 1369). No `SetStatusError` /
  custom class (the task body's sketch named one, but the clarifier flagged `ValueError` as the
  consistency choice and there is no concrete need for a typed exception).
- The guard sits inside `with _locked():` (the block spans lines 1359-1412), so it runs under the
  same `flock` as the move/commit — no new lock, no contract change.
- `repo` is already bound at line 1380 (used for the inspection-command strings and
  `relative_to`).

## 4. Edge cases handled

| Case | Behavior |
|---|---|
| **Empty orphan destination dir** (orphan from a prior numbering; git does not track empty dirs so it can linger) | `new.rmdir()` removes it; `git mv` then performs a true rename. No nesting. Move + REGISTRY + event + commit proceed normally. |
| **Non-empty destination dir** (leftover `artifacts/`, a stale `body.md`, or a concurrent non-`task.py` writer) | Raise `ValueError` naming `new`, explaining the nesting hazard, and giving two inspection commands (`git status` + `ls -la`). No `git mv` runs — nothing is moved, deleted, or committed; the workflow stays in a consistent pre-move state. |
| **Destination is a file, not a directory** (defensive) | Raise `ValueError` naming `new` + `ls -la {new}`. `rmdir()` would fail on a file anyway; raising first gives a clear message and avoids the nest. |
| **Race: another process creates `new` between the check and the `git mv`** | Accepted bound. `set_status()` runs inside `with _locked():` (`flock` on `~/.task-workflow/lock`), so concurrent `set_status` calls (and any other `task.py` mutation taking the same lock) are serialized — they cannot interleave inside the guard→`git mv` window. Only a NON-`task.py` writer that creates `tasks/<new>/<N>/` directly (out of scope for this guard, and not a supported workflow per CLAUDE.md "all task state through `scripts/task.py`") could race; in that case the guard still narrows the window to a few statements and, if it loses the race, the symptom reverts to the original nested-dir crash — i.e. no regression, just the pre-existing failure for an unsupported access pattern. Documented in the guard comment + this plan; no extra locking added. |
| **Idempotent no-op (`old_status == new_status`)** | Unaffected — the early `return old` at line 1362-1363 fires before the guard is reached. |

**Test 1 — empty orphan destination recovers (no nesting):**

```python
def test_set_status_recovers_empty_orphan_destination(fake_repo):
    """An empty orphan destination dir (e.g. left by a prior numbering;
    git does not track empty dirs) must be removed so `git mv` does a true
    rename, NOT nested as tasks/<new>/<id>/<id>/ (incident #681)."""
    repo, tw = fake_repo
    new_id = tw.create_task(tw.NewTaskRequest(kind="experiment", title="X"))
    # Pre-create an EMPTY orphan at the destination.
    orphan = repo / "tasks" / "running" / str(new_id)
    orphan.mkdir(parents=True)
    assert orphan.is_dir() and not any(orphan.iterdir())

    new = tw.set_status(new_id, "running")

    # Moved cleanly — destination has body.md directly, NOT under <id>/<id>/.
    assert new == repo / "tasks" / "running" / str(new_id)
    assert (new / "body.md").is_file()
    assert not (new / str(new_id)).exists()  # no nesting
    assert not (repo / "tasks" / "proposed" / str(new_id)).exists()  # source gone
    # Registry + event still correct.
    reg = json.loads((repo / "tasks" / "REGISTRY.json").read_text())
    assert reg["tasks"][str(new_id)]["path"] == f"tasks/running/{new_id}"
    assert tw.list_events(new_id)[-1]["kind"] == "epm:status-changed"
```

**Test 2 — non-empty orphan destination raises (no move):**

```python
def test_set_status_nonempty_orphan_destination_raises(fake_repo):
    """A non-empty orphan destination dir (leftover artifacts / concurrent
    writer) must raise ValueError naming the path — NOT nest + crash
    half-way (incident #681)."""
    repo, tw = fake_repo
    new_id = tw.create_task(tw.NewTaskRequest(kind="experiment", title="X"))
    # Pre-create a NON-EMPTY orphan at the destination (leftover artifact).
    orphan = repo / "tasks" / "running" / str(new_id)
    (orphan / "artifacts").mkdir(parents=True)
    (orphan / "artifacts" / "leftover.txt").write_text("stale\n")

    with pytest.raises(ValueError, match="already exists and is non-empty"):
        tw.set_status(new_id, "running")

    # Nothing moved: source still in place, no nesting created.
    assert (repo / "tasks" / "proposed" / str(new_id) / "body.md").is_file()
    assert not (orphan / str(new_id)).exists()
    # Status unchanged in the registry.
    reg = json.loads((repo / "tasks" / "REGISTRY.json").read_text())
    assert reg["tasks"][str(new_id)]["path"] == f"tasks/proposed/{new_id}"
```
