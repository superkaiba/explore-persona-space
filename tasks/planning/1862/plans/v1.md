## Goal / requirement

A detached VM phase's liveness must be readable (bracketed probes) and its earlyoom
protection must not silently stay off for big-RSS phases. Two-part amendment to
`.claude/skills/issue/SKILL.md` § "Detached VM-side long compute phases" (origin:
#1482 — the VM re-sweep was earlyoom-SIGTERMed at 32,254 MiB RSS after `choom=failed`
proceeded unprotected, and two unbracketed pgrep liveness probes self-matched their own
wrapper and read ALIVE, hiding the kill ~50 min before the leg was re-dispatched to GCP):

- **(A) Probe-bracket restatement.** The section's launch/probe template restates the
  pgrep bracket rule AT the composition site and declares an ALIVE read from an
  UNBRACKETED pattern probe unverified evidence, cross-referencing the canonical
  `.claude/rules/gotchas.md` ownership-probe entry (extended 2026-07-29/30 with the
  #1738/#1482 additions).
- **(B) choom=failed × big-RSS routing.** A failed choom sweep gets ONE bounded retry
  (formalizing the existing #1315 "optionally re-run" note); a phase whose projected
  peak RSS is ≥ ~16 GiB (the compute-character element-4 threshold) that STILL reads
  `choom=failed` routes OFF the shared VM by default (cpu-mid / cpu-bigmem per
  CLAUDE.md § CPU-only phases) instead of silently proceeding unprotected; phases
  below the threshold keep the existing proceed-unprotected default verbatim.

## Acceptance criteria

1. The fenced launch snippet's recovery comment states the bracket rule EXPLICITLY
   (why: an unbracketed pattern matches the probe's own argv), not just via the
   embedded `invocatio[n]` example a reader can mistake for a typo.
2. New prose in the section: every pattern-based liveness / ownership / kill probe
   (`pgrep -f` / `pkill -f`, local or over SSH) against a detached phase uses the
   bracket idiom; an ALIVE read from an unbracketed probe is UNVERIFIED (never
   heartbeat evidence, never a reason to skip the failure path); cites #1482 and
   cross-refs the gotchas ownership-probe entry (which owns the full recipe:
   bracket + self-exclusion filter / per-pid iteration + separate-Bash-call rule).
3. The earlyoom paragraph: on a failed choom sweep, RE-RUN the sweep once (after the
   workload's real python3 child appears — the #1315 note becomes the default retry,
   not an option); record the FINAL state as `choom=ok|failed` (no breadcrumb schema
   change).
4. New clause: post-retry `choom=failed` on a phase with projected peak RSS ≥ ~16 GiB
   → default is route the phase off the VM (such a phase is already past the
   compute-character element-4 off-VM threshold, so a VM launch of one is doubly
   exposed); proceeding VM-local anyway requires a one-line stated reason in the
   breadcrumb (e.g. `choom=failed-accepted: <reason>` prose in the note, token
   vocabulary unchanged). Phases < ~16 GiB: existing proceed-unprotected default
   unchanged.
5. Invariants preserved: "never block a launch on choom" stays verbatim for sub-16-GiB
   phases; the big-RSS case is a ROUTING decision (route or justify), never a wedge;
   `choom=ok|failed` breadcrumb token unchanged; `workflow_lint.py` (no-flags +
   `--check-asks`) passes.
6. § Successor / re-entry rule gains one clause: a pattern-based FALLBACK probe (pid
   absent / recycled) uses the bracket idiom, and an unbracketed-probe ALIVE is
   unverified.
