## 0.0 TL;DR (plain English)

- **What I'll change:** the artifact-reuse rule's "inspect reused code before reusing it" check currently looks at two things (is the inner loop batched? is the device a parameter?). I'll add a third: does the reused code talk to the HuggingFace Hub safely — listing only its own folder instead of crawling the whole ~1M-file data repo, and retrying politely when rate-limited? I'll also mirror the wording in the two planner templates that quote this check, and add a short code-review sub-check so brand-new code with the same mistake gets flagged too.
- **What I expect:** ~30 changed lines across 4 workflow files, no code, no GPU. The next plan that reuses a parent's upload/verify helper will have to state "its Hub calls are prefix-scoped" before the run launches, instead of discovering a rate-limit wedge live (what happened on #810: a reused verify call crawled the whole data repo while an A100 sat idle).
- **What would change my mind:** if the implementer finds a test or lint that pins the current check-(i) wording (my grep found none), the edit shape adapts to keep that green; nothing else about this fix is uncertain.
