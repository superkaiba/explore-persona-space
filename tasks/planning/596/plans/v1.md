### 4.1 NEW `scripts/new_worktree.sh` (the single shared recipe — used by SKILL.md Step 4a, CLAUDE.md rule, guard message)

```bash
#!/usr/bin/env bash
# Create a SPARSE worktree — the default for /issue + feature/infra branches
# (task #596). Excludes the heavy history dirs (eval_results/, external/,
# ood_eval_results/: ~3.4G of a ~3.8G checkout) and pre-includes the issue's
# own artifact dirs so `git add eval_results/issue_<N>/...` needs no ceremony.
#
# Usage: scripts/new_worktree.sh <worktree-path> <branch> [--issue N] [--full]
#
#   --issue N   pre-add cones eval_results/issue_N + ood_eval_results/issue_N
#   --full      plain full checkout (escape hatch; state the reason when used)
#
# Reuse: if <worktree-path> is already a registered worktree, exits 0 untouched
# (the /issue resume case). Symlinks the repo .env in either case.
set -euo pipefail

WT=$(realpath -m "${1:?usage: new_worktree.sh <worktree-path> <branch> [--issue N] [--full]}")
BRANCH=${2:?usage: new_worktree.sh <worktree-path> <branch> [--issue N] [--full]}
shift 2
ISSUE="" FULL=0
while [ $# -gt 0 ]; do
  case "$1" in
    --issue) ISSUE=$2; shift 2 ;;
    --full)  FULL=1; shift ;;
    *) echo "new_worktree: unknown arg: $1" >&2; exit 2 ;;
  esac
done

REPO_ROOT=$(git rev-parse --show-toplevel)
EXCLUDES="eval_results external ood_eval_results"

if git -C "$REPO_ROOT" worktree list --porcelain | grep -qxF "worktree $WT"; then
  echo "new_worktree: $WT already exists — reusing as-is"
  ln -sf "$REPO_ROOT/.env" "$WT/.env"
  exit 0
fi

# -b fails if the branch already exists (resume after worktree removal) —
# fall back to attaching the existing branch.
_add() { git -C "$REPO_ROOT" worktree add "$@" "$WT" -b "$BRANCH" 2>/dev/null \
         || git -C "$REPO_ROOT" worktree add "$@" "$WT" "$BRANCH"; }

if [ "$FULL" = 1 ]; then
  _add
else
  _add --no-checkout
  # ORDER MATTERS on git 2.34: `init --cone` FIRST. `set --cone` is silently
  # accepted as a literal PATTERN (no --cone flag on `set` until git 2.35+),
  # which yields non-cone any-depth matching — the failure mode this script
  # exists to prevent. Hence the hard assert below.
  git -C "$WT" sparse-checkout init --cone
  # Dynamic include list: every top-level tracked dir except the excludes,
  # so future top-level dirs are auto-included.
  # shellcheck disable=SC2046,SC2086
  DIRS=$(git -C "$REPO_ROOT" ls-tree --name-only -d HEAD \
         | grep -vxF $(printf -- '-e %s ' $EXCLUDES))
  CONES=""
  [ -n "$ISSUE" ] && CONES="eval_results/issue_${ISSUE} ood_eval_results/issue_${ISSUE}"
  # shellcheck disable=SC2086
  git -C "$WT" sparse-checkout set $DIRS $CONES
  [ "$(git -C "$WT" config --worktree core.sparseCheckoutCone || true)" = true ] \
    || { echo "new_worktree: FATAL — cone mode failed to engage in $WT" >&2; exit 1; }
  git -C "$WT" checkout "$BRANCH"
fi

# Worktrees do NOT inherit the gitignored repo .env (Step 4a contract).
ln -sf "$REPO_ROOT/.env" "$WT/.env"

du -sh "$WT" | awk -v wt="$WT" '{print "new_worktree: created " wt " (" $1 ")"}'
[ "$FULL" = 1 ] || {
  echo "new_worktree: sparse — excluded: $EXCLUDES"
  echo "new_worktree: materialize an excluded dir on demand:"
  echo "  git -C \"$WT\" sparse-checkout add <dir>   # e.g. eval_results/issue_<M>"
}
```

## 8. Decision Rationale (non-obvious choices)

- **Cone include-list computed dynamically** (`git ls-tree -d HEAD` minus excludes) rather than a hardcoded list — future top-level dirs auto-materialize, avoiding silent "my new dir doesn't exist in the worktree" confusion. Source: empirical (cone mode is include-based; excludes must be expressed as complement).
- **Excludes = `eval_results`, `external`, `ood_eval_results` only.** `figures/` (274M) stays wholly included — the analyzer writes there on every issue and cross-issue figure reads cost nothing this way; saving the extra 274M (424M → ~150M) isn't worth the ceremony. `.arxiv-papers/` is gitignored, nothing to exclude. Source: `du` measurements above.
- **Per-issue cones pre-added at creation** (`eval_results/issue_<N>`, `ood_eval_results/issue_<N>`) — eliminates the out-of-cone-add failure for the canonical artifact paths; verified that cones for not-yet-existing dirs are accepted.
- **Parent-issue reads via on-demand `sparse-checkout add`** rather than repo-root redirection — keeps plot scripts' worktree-relative paths working unchanged; repo-root read stays the documented read-only fallback.
- **Helper script over inline recipes** — 3 textual sites share it; the cone-mode assert lives in exactly one place.
- **Bash over Python** for the helper — matches `guard_repo_root_branch.sh`, zero deps, and the consumers are shell recipe blocks.
