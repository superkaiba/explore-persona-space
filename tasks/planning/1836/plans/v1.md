## Requirement + acceptance criteria (code-change task)

**Requirement.** Make the rendered sbatch template's `_write_status` tmp path
writer-unique so the background heartbeat loop and the main script's phase
writers never collide on the atomic rename. Today both writers printf to the
SAME `${STATUS_JSON}.tmp` and `mv` it over `${STATUS_JSON}`; when they
interleave (printf-A, mv-B steals the tmp, mv-A finds nothing), the loser's
`mv` fails and `set -euo pipefail` kills an otherwise-healthy job (fellows job
15192 died at preflight this way, 2026-07-29T18:54:52Z — one full launch cycle
burned; the race is probabilistic and had passed 3 prior launches that day).

**Acceptance criteria:**

1. `src/explore_persona_space/backends/slurm.py` `_write_status` template
   (~L1542) renders `local tmp="${STATUS_JSON}.tmp.${BASHPID}"` instead of the
   shared `local tmp="${STATUS_JSON}.tmp"`.
2. `mv "$tmp" "$STATUS_JSON"` stays EXACTLY as-is — the rename remains atomic
   per writer; no `|| true` (a real write failure must still fail loud), no
   `mv -f` needed (dest-overwrite semantics unchanged; the collision was on the
   SOURCE tmp, which is now writer-unique).
3. BOTH byte-identity render fixtures are DELIBERATELY regenerated from the
   post-change renderer, each with a fresh provenance note naming task #1836

   regenerated by #598, #745, #1172):
   - `tests/fixtures/issue588_slurm_sbatch_hydra_only.json` (`rendered_text` +
     `provenance.generated_by`/`note`)
   - `tests/fixtures/issue1609_prechange_slurm_renders.json` (all 4 renders:
     nibi/mila × hydra/custom + `_provenance`)
4. A NEW regression test in `tests/test_slurm_backend_render.py` asserts the
   rendered script contains the writer-unique tmp line

## Method delta (why BASHPID; alternatives considered)

- **`$BASHPID`, not `$$`:** `_heartbeat_loop &` runs as a background function
  in the same bash, where `$$` still reads the PARENT's pid — so a `$$` suffix
  would NOT separate the two writers. `$BASHPID` is per-(sub)shell: the
  heartbeat subshell gets its own value, the main script's phase writers share
  the parent's. Two writers ⇒ two distinct tmp paths ⇒ no source-tmp steal;
  concurrent `mv` renames onto the same dest are atomic and last-writer-wins
  (fine for a heartbeat file).
- **`mktemp` rejected:** works, but forks a process per heartbeat write
  (every `HEARTBEAT_INTERVAL` for the job's whole life) and needs explicit
  cleanup wiring; the BASHPID suffix is deterministic and zero-cost.
- **Residue:** a writer killed between printf and mv leaves one
  `status.json.tmp.<pid>` file — bounded (≤1 per writer), inert inside the
  per-job `$SCRATCH_JOB_DIR`, and the same residue class the old code already
  had. The monitor consumes `status.json` only
  (`backends/slurm_monitor.py` — rsyncs that file specifically), so tmp
  siblings are never read.
- **Bash availability:** the sbatch shebang is `#!/bin/bash`; `$BASHPID` is a
  bash builtin (≥4.0) — present on all lanes (nibi/fir/mila/fellows).
