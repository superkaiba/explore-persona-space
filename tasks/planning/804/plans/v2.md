## 0. Plan Summary

- **Change:** Fix two policy-bypass classes in the fleet-wide PreToolUse Bash
  hook `scripts/guard_repo_root_branch.sh` by (1) wrapping the existing detector
  chain in a **per-clause loop** (Option A — clause-local parsing) that splits
  `$cmd` on `;` / `&&` / `||` / `|` **while PRESERVING which separator preceded
  each clause**, classifies each clause independently, and forward-latches a
  `scoped` flag for `cd <worktree|/tmp>` **only across `;` and `&&`** (a
  successful `cd` genuinely precedes the git command there) while **RESETTING
  the latch across `||` and `|`** (where a `cd` does NOT scope the following git
  clause — see the semantics note below); and (2) relaxing the
  `git checkout -b/-B` word-boundary anchor to also match the glued form
  (`-bfoo` / `-Bfoo`).
- **`||`/`|` bash semantics (verified this session).** `cd X || git switch f`
  runs the git clause ONLY when `cd` FAILED — cwd is then unchanged (repo root),
  so git runs off-worktree → bypass (`cd /nonexistent || pwd` prints repo root).
  `cd X | git switch f` runs each pipeline segment in its own subshell — the
  LHS `cd`'s cwd change dies with its subshell, so git runs in the parent's cwd
  (repo root) → bypass (`cd /tmp | pwd` prints the parent cwd). So the latch must
  NOT carry `scoped` across `||` or `|`. It carries only across `;`/`&&`
  (`cd /tmp && pwd` / `cd /tmp ; pwd` both print `/tmp`). The origin concern
  (`#796 compound-command-masking-leak`) names `||` explicitly.
- **Why Option A:** it fixes all four compound leaks *and* both `||`/`|`
  cd-scope bypasses *precisely* while preserving the 6 controls + all of #796's
  fixes with a minimal, well-understood transformation (existing detector bodies
  reused verbatim inside a loop; only the split + latch logic is new).
  Option B (fail-closed: disable the latch whenever `||`/`|` appears anywhere)
  is more conservative but false-positives on the legitimate
  `git status || git switch main` (an allowed control) — rejected. Option C
  (sed-extract per git-verb) can't cleanly express the *clause-ordinal*
  `cd`-scoping semantics.
- **Baselines / controls:** the 6 empirical leaks + the 2 new `||`/`|` cd-scope
  bypasses must flip to rc=2; the 6 controls + 3 new legitimate-`||`/`|` shapes
  + all 54 existing tests must stay green.

## 1. Goal

(verbatim from the task body):

   class INCLUDES the `||` and `|` connectors: a `cd <worktree> || git switch f`

design limitations of the regex-on-whole-command approach, folded out of #796

### The transformation

Refactor the per-command detector body (current lines 61-142) into a shell
**function** `classify_clause "$clause"` that returns (via a captured
variable, not stdout — keeps it fast) the `blocked` reason for a SINGLE clause,
then drive it from a clause loop that **preserves the separator preceding each
clause** and **only forward-latches `cd` scope across `;` and `&&`**.

**Shape A (separator-preserving split).** A `sed` pre-pass replaces each
separator run with a newline + a sentinel token naming the separator; a
line-wise parse then reads `(separator, clause)` pairs, so the loop knows which
connector preceded each clause. This is the ONLY shape that expresses the true
semantics (`cd` scopes across `;`/`&&` but not `||`/`|`) without over-blocking
the legitimate `git status || git switch main` control. Pseudocode:

```bash
# after the early-exits (lines 43-51 stay: set -u, REPO, jq read, [ -n ], and
# the cheap whole-string "is there any git checkout/switch at all?" gate).

# Split the raw command into (separator, clause) pairs, PRESERVING which
# separator precedes each clause. Two-char separators (&& ||) are matched
# BEFORE the single-char ones (; | &) so `&&`/`||` are not mis-split. Each
# separator run is replaced by a newline + a \x01-delimited sentinel token
# (START | SEQ | AND | OR | PIPE); the first clause carries the implicit
# START. awk best-effort; a separator inside a quoted arg is treated as a real
# separator (same trade-off as the existing raw-scan known-limitation).
split_and_label() {
  printf '%s' "$1" \
    | sed -E 's/\|\|/\n\x01OR\x01/g; s/&&/\n\x01AND\x01/g; s/;/\n\x01SEQ\x01/g; s/\|/\n\x01PIPE\x01/g' \
    | awk 'BEGIN{RS="\n"; sep="START"}
           { line=$0
             if (match(line, /^\x01(OR|AND|SEQ|PIPE)\x01/)) {
               sep=substr(line, 2, RLENGTH-2); line=substr(line, RLENGTH+1)
             }
             gsub(/^[ \t]+|[ \t]+$/, "", line)
             if (length(line)) print sep "\t" line }'
}

scoped=0          # latches once a `cd <worktree|/tmp>` clause is seen; RESET on || or |
blocked=""
while IFS=$'\t' read -r sep clause; do
  # A `cd` scopes ALL LATER clauses ONLY across ; and && (cwd persists
  # forward there). It does NOT scope across || (RHS runs when cd FAILED,
  # cwd unchanged) or | (subshell isolates cd), so RESET the latch when the
  # separator BEFORE this clause is || or |. Verified bash semantics
  # (2026-07-01): `cd X && pwd` / `cd X ; pwd` -> X; `cd X || pwd` -> orig;
  # `cd X | pwd` -> orig.
  if [ "$sep" = OR ] || [ "$sep" = PIPE ]; then
    scoped=0
  fi

  # A `cd` into a worktree / /tmp latches scope forward for subsequent ;/&&
  # clauses. Latch and continue — do NOT let it scope EARLIER clauses (those
  # were classified before the latch).
  if echo "$clause" | grep -qE 'cd +[^;&|]*\.claude/worktrees/' \
     || echo "$clause" | grep -qE 'cd +/tmp/'; then
    scoped=1
    continue
  fi
  [ "$scoped" -eq 1 ] && continue          # this clause runs in a scoped cwd

  # `git -C <path>` scopes ONLY this clause (per-invocation) — allow it.
  echo "$clause" | grep -qE '\bgit +-C +' && continue

  # not a git checkout/switch clause at all -> skip
  echo "$clause" | grep -qE '\bgit\b.*\b(checkout|switch)\b' || continue

  reason=$(classify_clause "$clause") || true
  if [ -n "$reason" ]; then blocked="$reason"; break; fi   # first block wins
done < <(split_and_label "$cmd")
```

`classify_clause()` is the **existing** detector body (lines 61-142) moved
verbatim into a function that reads `$1` instead of `$cmd` and `echo`s the
`blocked` reason (empty string = allow). The only changes inside it:

1. **Glued `-b`/`-B` relaxation** (the #796 r3 Claude concern) — line 82:
   ```
   -  if echo "$cmd" | grep -qE '\bgit\b[^;&|]*\bcheckout\b +(-b|-B)\b'; then
   +  if echo "$c" | grep -qE '\bgit\b[^;&|]*\bcheckout\b +(-b|-B)([[:alnum:]_./[:space:]-]|$)'; then
   ```
   The new trailing class matches a space (bare `-b feature`), end-of-string
   (bare `-b`), OR a glued branch-name char (`-bfoo`, `-B123`, `-b-x`, `-b.y`,
   `-b/z`). Verified: matches all of `-b feature` / `-B feature` / `-bfoo` /
   `-Bfoo` / `-b` / `-B`; does NOT match `-f main` / `-- file` / `main` /
   `HEAD~1` / `-fq main` (no false positives).
2. **`$cmd` → the clause variable** (rename to `$c` or pass `$1`) throughout
   the moved body. The `[^;&|]*` anchors inside the detectors become
   no-ops per-clause (a clause has no delimiters) but are kept verbatim so the
   function stays correct even if fed a whole string — zero behavior change.

The **on-main gate** (current lines 144-149) and the **BLOCKED message +
`exit 2`** (lines 151-154) stay at top level, AFTER the loop, reading the
loop's `$blocked`. The two must-preserve escapes are untouched in spirit:
- **worktree/`cd` scoping** — now *clause-ordinal* AND *separator-aware*
  (forward-latching across `;`/`&&`, reset across `||`/`|`) rather than
  whole-string-anywhere; this is a strict *tightening* that fixes the
  trailing-`cd` leak AND the `||`/`|` cd-scope bypasses while keeping
  `cd worktree && git ...` and `cd worktree ; git ...` allowed.
- **already-off-main recovery** — the `cur != main → exit 0` gate is unchanged
  (still at the very end, gating the final block decision).

**Why Shape A over Shape B (fail-closed).** Shape B — split on the awk-RS class
as v1 did, but detect a `||`/`|` anywhere in `$cmd` and disable the forward
latch entirely — is more conservative but FALSE-POSITIVES on the required
allow control `git status || git switch main` (no `cd` involved; the `||` just
chains two git clauses, the first a no-op status): with the latch globally
disabled the shape still classifies each clause correctly (git status → skip;
git switch main → allow-arm), so Shape B actually passes THAT case — but Shape
B's blunt "any `||`/`|` disables scoping" also blocks any legitimate
`cd worktree || <recovery>` shape a human might type, and it cannot distinguish
"the `cd` scopes the later git" (impossible under `||`/`|`) from "the git is on
its own clause". Shape A distinguishes them precisely by keying the latch reset
to the ACTUAL preceding separator. Verified this session: Shape A satisfies all
13 required cases (the 4 compound-masking + the 2 `||`/`|` bypass Must-Fixes,
the 6 controls, the 3 new legitimate-`||`/`|` allows, plus the glued cases via
the regex relaxation). Chosen: **Shape A**.

## 11. Decision Rationale

N/A — no model training, no hyperparameters. The design decisions:

- **What:** Option A / Shape A (clause-local parsing with a
  separator-PRESERVING split + a `cd` latch that carries across `;`/`&&` and
  resets across `||`/`|`) over Option B (fail-closed: disable the latch on any
  `||`/`|`) and Option C (sed-extract per git-verb).
  **Why:** Shape A fixes all four compound-masking leaks AND both `||`/`|`
  cd-scope bypasses precisely by reusing the existing detectors per-clause,
  keying the `cd`-scope latch to the ACTUAL preceding separator, and keeping
  every legitimate compound (the 6 controls + the 3 new `||`/`|` allows)
  passing. The `||`/`|` semantics are load-bearing and were verified directly:
  `cd X || git` runs git ONLY on `cd` failure (cwd unchanged = repo root) and
  `cd X | git` runs git in a sibling subshell's parent cwd (repo root), so a
  `cd` NEVER scopes a git clause across `||` or `|` — v1's `RS="[;&|]+"` split
  collapsed all four separators into one class and wrongly forward-latched
  across `||`/`|`, which is exactly the bug this revise fixes. Shape B is more
  conservative but blunt (blocks legitimate `cd worktree || <recovery>` shapes);
  Shape C cannot express the clause-ordinal `cd`-scoping cleanly (a `cd worktree`
  in clause k scopes clauses > k under `;`/`&&` only — a clause index gated on
  separator identity, not a git-verb index).
  **Source:** #796 concerns.jsonl (both concern reproducers) + this session's
  per-clause behavior verification + the direct `||`/`|` bash-semantics tests
  (`cd /nonexistent || pwd`, `cd /tmp | pwd`) + the Shape A 13-case prototype.
- **What:** glued regex `(-b|-B)([[:alnum:]_./[:space:]-]|$)`.
  **Why:** matches the standalone flag (space / EOL) AND the glued branch-name
  form (`-bfoo`) with zero false positives on non-`-b` shapes; the task body's
  suggested `-b($| |[^ ])` would over-match `-b--` oddly, and `[[:alnum:]_.-]`
  alone misses the bare-`-b` (space) case — the chosen class covers both.
  **Source:** task body §Design bullet + this session's regex test matrix.
