## 4. Design — Option A (clause-local parsing) + glued-`-b` relaxation

### Root-cause trace (empirically verified this session, 2026-07-01)

Each leak, and *why* the current whole-command scan lets it through:

| Leak | Mechanism (verified) |
|---|---|
| `git switch feature ; git switch main` | Block detector (line 75) matches clause 1 via `[^;&\|]`, but the **allow-arm** (line 76) has no clause discipline — it matches `switch main` *anywhere* in the whole string (clause 2), so `blocked` is never set. |
| `git switch feature && git switch main` | same as above (`&&` is in the allow-arm terminator class). |
| `git checkout HEAD~1 ; git checkout main` | The detach classifier's sed `s/.*\bcheckout\b +([^ ;&\|]+).*/\1/` is **greedy on `.*`**, so it binds the *last* `checkout` and extracts `main` (an ALLOW case) instead of `HEAD~1`. |
| `git switch feature ; cd .claude/worktrees/x` | The worktree-scope allow-arm (line 56) matches `cd .claude/worktrees/` *anywhere* in the string, so a **trailing** `cd worktree` scopes the whole command — including the earlier dangerous `git switch feature`. |
| `git checkout -bfoo` / `-Bfoo` | `(-b\|-B)\b` requires a word boundary after `b`/`B`; `-bfoo` has `f` (word char) after `b` → no boundary → no match. The arg-classifier then extracts `-bfoo`, which is not in any block case and does not `rev-parse` → leak. |

### The transformation

Refactor the per-command detector body (current lines 61-142) into a shell
**function** `classify_clause "$clause"` that returns (via a captured
variable, not stdout — keeps it fast) the `blocked` reason for a SINGLE clause,
then drive it from a clause loop. Pseudocode:

```bash
# after the early-exits (lines 43-51 stay: set -u, REPO, jq read, [ -n ], and
# the cheap whole-string "is there any git checkout/switch at all?" gate).

# Split the raw command into clauses on ;  &&  ||  (and bare & | too — the
# RS class [;&|]+ collapses runs, so `&&`/`||` split once). awk best-effort;
# quoted separators are treated as real separators (same trade-off as the
# existing raw-scan known-limitation).
mapfile -t clauses < <(printf '%s\n' "$cmd" \
  | awk 'BEGIN{RS="[;&|]+"} {gsub(/^[ \t\n]+|[ \t\n]+$/,""); if(length($0)) print}')

scoped=0          # latches once a `cd <worktree|/tmp>` clause is seen
blocked=""
for clause in "${clauses[@]}"; do
  # A `cd` into a worktree / /tmp scopes ALL LATER clauses (cwd persists
  # forward under both ; and && and ||). Latch and continue — do NOT let it
  # scope EARLIER clauses (those were classified before the latch).
  if echo "$clause" | grep -qE 'cd +[^;&|]*\.claude/worktrees/' \
     || echo "$clause" | grep -qE 'cd +/tmp/'; then
    scoped=1
    continue
  fi
  [ "$scoped" -eq 1 ] && continue          # this clause runs in a scoped cwd

  # `git -C <path>` scopes ONLY this clause (per-invocation) — allow it.
  echo "$clause" | grep -qE '\bgit +-C +' && continue

  # not a git checkout/switch clause at all -> skip
  echo "$clause" | grep -qE '\bgit\b.*\b(checkout|switch)\b' || continue

  reason=$(classify_clause "$clause") || true
  if [ -n "$reason" ]; then blocked="$reason"; break; fi   # first block wins
done
```

`classify_clause()` is the **existing** detector body (lines 61-142) moved
verbatim into a function that reads `$1` instead of `$cmd` and `echo`s the
`blocked` reason (empty string = allow). The only changes inside it:

1. **Glued `-b`/`-B` relaxation** (the #796 r3 Claude concern) — line 82:
   ```
   -  if echo "$cmd" | grep -qE '\bgit\b[^;&|]*\bcheckout\b +(-b|-B)\b'; then
   +  if echo "$c" | grep -qE '\bgit\b[^;&|]*\bcheckout\b +(-b|-B)([[:alnum:]_./[:space:]-]|$)'; then
   ```
   The new trailing class matches a space (bare `-b feature`), end-of-string
   (bare `-b`), OR a glued branch-name char (`-bfoo`, `-B123`, `-b-x`, `-b.y`,
   `-b/z`). Verified: matches all of `-b feature` / `-B feature` / `-bfoo` /
   `-Bfoo` / `-b` / `-B`; does NOT match `-f main` / `-- file` / `main` /
   `HEAD~1` / `-fq main` (no false positives).
2. **`$cmd` → the clause variable** (rename to `$c` or pass `$1`) throughout
   the moved body. The `[^;&|]*` anchors inside the detectors become
   no-ops per-clause (a clause has no delimiters) but are kept verbatim so the
   function stays correct even if fed a whole string — zero behavior change.

The **on-main gate** (current lines 144-149) and the **BLOCKED message +
`exit 2`** (lines 151-154) stay at top level, AFTER the loop, reading the
loop's `$blocked`. The two must-preserve escapes are untouched in spirit:
- **worktree/`cd` scoping** — now *clause-ordinal* (forward-latching) rather
  than whole-string-anywhere; this is a strict *tightening* that fixes the
  trailing-`cd` leak while keeping `cd worktree && git ...` allowed.
- **already-off-main recovery** — the `cur != main → exit 0` gate is unchanged
  (still at the very end, gating the final block decision).

## 11. Decision Rationale

N/A — no model training, no hyperparameters. The one design decision:

- **What:** Option A (clause-local parsing) over B (conservative-block
  whitelist) and C (sed-extract per git-verb).
  **Why:** A fixes all four compound leaks precisely by reusing the existing
  detectors per-clause, adds a small forward-latching `cd`-scope loop, and
  keeps every one of the 6 controls (which are legitimate compounds) passing;
  B would have to enumerate all legitimate fleet compounds and is brittle /
  false-positive-prone; C cannot express the clause-ordinal `cd`-scoping
  cleanly (a `cd worktree` in clause k scopes clauses > k, which is a clause
  index, not a git-verb index). **Source:** #796 concerns.jsonl (both concern
  reproducers) + this session's per-clause behavior verification.
- **What:** glued regex `(-b|-B)([[:alnum:]_./[:space:]-]|$)`.
  **Why:** matches the standalone flag (space / EOL) AND the glued branch-name
  form (`-bfoo`) with zero false positives on non-`-b` shapes; the task body's
  suggested `-b($| |[^ ])` would over-match `-b--` oddly, and `[[:alnum:]_.-]`
  alone misses the bare-`-b` (space) case — the chosen class covers both.
  **Source:** task body §Design bullet + this session's regex test matrix.
