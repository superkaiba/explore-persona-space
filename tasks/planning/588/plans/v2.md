## 3. Design

### D1 — `RunSpec.workload_cmd` + validation (`src/explore_persona_space/backends/base.py`)

Add the field **last** (after `extra`) so positional constructions are unaffected:

```python
@dataclass(frozen=True)
class RunSpec:
    ...
    extra: dict[str, Any] = field(default_factory=dict)
    # Custom workload command (repo-relative shell line, e.g.
    # "bash scripts/issue588_dispatch.sh --foo"). Mutually exclusive with
    # hydra_args. Executed verbatim by the lane renderers from the repo
    # checkout root after env bootstrap. "" = use the hydra entrypoint.
    workload_cmd: str = ""

    def __post_init__(self) -> None:
        if self.workload_cmd and self.hydra_args:
            raise ValueError(
                "RunSpec: workload_cmd and hydra_args are mutually exclusive "
                f"(got workload_cmd={self.workload_cmd!r} AND hydra_args={self.hydra_args!r})."
            )
        if self.workload_cmd:
            if "\n" in self.workload_cmd or "\r" in self.workload_cmd:
                raise ValueError("RunSpec.workload_cmd must be a single line (no newlines).")
            if self.workload_cmd != self.workload_cmd.strip():
                raise ValueError("RunSpec.workload_cmd must not have leading/trailing whitespace.")
```

**Where validation lives — three layers, and why (the body's "both or neither" contract vs the 43 existing `RunSpec(` call sites genuinely conflict; this is the explicit resolution):**

1. **Both-set → `__post_init__` raise (universal).** Always a contradiction regardless of lane. Frozen dataclasses support a raising `__post_init__`. No existing call site sets both (the field is new), so nothing breaks.
2. **Neither-set stays LEGAL at construction.** `tests/test_router.py` (mock-lane routing tests), `test_issue_dispatch.py::test_build_run_spec_empty_frontmatter_routes_auto` / `test_build_run_spec_legacy_cluster_maps_to_nibi`, `router_acceptance.py` negative scenarios (`RunSpec(issue=901, intent="lora-7b", backend="auto")` at lines 1655/1721), and est-start/reconnect probes all construct bare specs that never render a workload. Enforcing exactly-one in `__post_init__` would crash the entire router suite for zero safety gain.
3. **Neither-set fails loud at the production dispatch surface + the GCP renderer.** (a) `scripts/dispatch_issue.py _cmd_launch`: after arg parsing, `parser.error("launch requires exactly one of --workload-cmd / --hydra")` when neither (and when both — friendlier than the dataclass traceback). This is where the body's fail-loud contract lands for production launches. (b) Defense-in-depth in `render_startup_script`: raise `ValueError` when both `spec.workload_cmd` and the effective hydra args are empty — rendering a bare `scripts/train.py` launch is exactly incident #571 and is never an intended GCP workload. The raise happens BEFORE `gcloud instances create` (render is at `launch()` line 1566, ahead of the create loop), so no VM is provisioned and no credit is burned. SLURM's `stages_for_spec` is NOT given a neither-check: `scripts/eval.py` with Hydra config defaults is a plausible-legal empty-args run shape and tightening it is out of scope.

**Known test fallout from layer 3a (deliberate, body-mandated):** ~10 routing-mechanics tests in `tests/test_dispatch_issue_cli.py` (lines 191, 227, 265, 306, 340, 369, 435, 456, 485 + repo-branch tests) call `launch` without `--hydra`; each gains a `"--hydra", "smoke=1"` pair (mechanical edit). The load-bearing invariants (`test_no_auto_runpod_path_under_any_failure` constructs `RunSpec` directly via `_spec()`) are untouched.

## 11. Decision Rationale

- **Field semantics — `workload_cmd: str = ""` (single shell line, verbatim).** Why: the body specifies a repo-relative shell command; a string (not argv list) matches how dispatch scripts are actually invoked (`bash scripts/x.sh --flag v`). Source: task body D1; #571 incident shape. Alternatives: argv tuple + shlex-join (rejected: forces awkward composition of `bash -lc` chains; the command is trusted plan input); a `workload: WorkloadSpec` dataclass (rejected: YAGNI, schema churn on the sidecar-adjacent surface).
- **Validation site — `__post_init__` both-set + CLI exactly-one + GCP-renderer neither-set.** Why: honors the body's fail-loud contract at every production entry while keeping 43 existing bare-`RunSpec` constructions (router tests, probes, acceptance negatives) legal; render-time raise fires before `gcloud create`, so zero credit burn. Source: read call sites (`test_router.py`, `test_issue_dispatch.py:440-458`, `test_dispatch_issue_cli.py` lines 191–485, `router_acceptance.py:1655,1721`); incident #571. Alternatives: exactly-one in `__post_init__` (rejected: breaks the router suite — the genuine conflict the body's wording creates, resolved as above); validation only in `route()` (rejected: misses the explicit-backend lanes' renderers and gives a worse error surface).
- **SLURM support-vs-error — support via `WorkloadKind "custom"` + `Stage.custom_cmd`.** Why: the renderer's stage dispatch is already command-agnostic (read `render_sbatch` lines 1364–1401); one branch + one field gives all three clusters support; a capability error is more code for a worse Step 6b. Source: `slurm.py` lines 897–936, 951–1048, 1364–1401. Alternatives: typed `SlurmCapabilityError` (rejected: no lane genuinely can't support it); wrapping via a synthetic `local` stage with `script_rel` abuse (rejected: `uv run python` prefix is hardcoded in the local branch).
- **Smoke machine type — `debug` intent → `g2-standard-4` (1× L4).** Why: smallest mapped type per `INTENT_TO_MACHINE` (gcp.py lines 275–301); $0.71/h on-demand; `nvidia-smi` needs any GPU, not a big one. Source: `INTENT_TO_MACHINE`; GCP pricing reference. Alternatives: `lora-7b`/A100-80 (rejected: 7× cost for zero extra signal; kept as capacity fallback).
- **Smoke driver — production `dispatch_issue.py launch`, not `router_acceptance.py`.** Why: acceptance criterion A1 names the production CLI verbatim; #535 already proved the harness path. Source: task body acceptance bullet 1; #535 body. Alternatives: extend `router_acceptance.py live --workload-cmd` (rejected: tests the harness, not the production seam; more diff).
- **`spec_hash` conditional key.** Why: keeps every existing hydra-only hash stable across the upgrade (lease reconnect continuity) while separating custom-vs-hydra lease identities. Source: `router.py` canonical-spec-dict docstring ("harmless serialization diffs MUST NOT change the key"). Alternative: unconditional key (rejected: one-time invalidation of in-flight leases for no benefit).
