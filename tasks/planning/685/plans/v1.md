# Plan — Issue #685: Context-vector shift induced by appending a behavioral instruction

## 0.0 TL;DR (plain English)

- **What I'll run:** I take ten different "personas" the model can adopt (a software engineer, a villain, a doctor, the plain default assistant, etc.), and for each one I measure a compact fingerprint of how the model is "set up" right before it starts answering. Then I tack a behavior order onto the persona ("always agree with the user," "refuse," "be evil," "be terse," ...) and measure the fingerprint again. The thing I care about is the *change* in fingerprint, and whether that change points the same way no matter which persona I started from.
- **What I expect:** Each behavior probably has a fairly consistent "push" direction across personas at the better-tuned middle-to-late layers — but not perfectly consistent, because the recent closest paper warns that a persona is more than a single cached vector. So I expect a partial single-direction story, stronger for the cleaner behaviors (refuse, terse, formal) and messier for the ones the persona itself already colors (a villain told to "be evil" barely moves).
- **What would change my mind:** If a check says the instruction doesn't actually change the model's behavior (the "be sycophantic" order doesn't make it more sycophantic), then the fingerprint change is just noise and the whole question is ill-posed — I'd fix the instruction wording and re-run before reading anything into the geometry.

## 1. Goal + Hypothesis

**Goal (verbatim).** Measure how a context's last-token residual-stream activation summary (the context vector) shifts when a behavioral instruction is appended, across diverse contexts, behaviors, and layers, and test whether the shift is a single context-independent behavior direction.

**Formalization (from body).** Context `C` = system prompt. Behavior `b` = appended natural-language instruction. Bank `Q` of neutral questions. Context vector `v_ℓ(C) = mean_{q∈Q} h_ℓ(C,q)`, where `h_ℓ(C,q)` is the residual-stream activation at the **last prompt token** at layer `ℓ` on `apply_chat_template(system=C, user=q, add_generation_prompt=True)`. Behavior-augmented context `C ⊕ b = C + "\n\n" + b`. Shift `Δ_ℓ(C,b) = v_ℓ(C⊕b) − v_ℓ(C)`.

**Competing hypotheses + falsification criteria.**

- **H1 (single behavior direction).** For a fixed `b`, `Δ_ℓ(C,b)` points in ~the same direction across all `C`. *Confirmation:* at the best layer, mean pairwise cosine of `{Δ_ℓ*(C,b)}_C` **> 0.6** AND PC1 variance share **> 0.5**, for **≥ 4 / 6** behaviors. *Falsified by:* failing either threshold for the majority of behaviors (≤ 2/6 passing).
- **H2 (context-dependent shift).** `Δ_ℓ(C,b)` depends materially on `C`. *Confirmation:* mean pairwise cosine in **[0.0, 0.4]** AND PC1 share **< 0.4** for ≥ 4/6 behaviors, with non-negligible magnitude (H0 ruled out). *Falsified by:* high consistency (H1 region) for the majority.
- **H0 (negligible / noise-level shift).** `‖Δ_ℓ(C,b)‖` is small relative to between-context spread. *Confirmation:* `‖Δ_ℓ(C,b)‖ / median_{C≠C'} ‖v_ℓ(C)−v_ℓ(C')‖` **< 0.2** at every layer for a behavior. *Falsified by:* ratio ≥ 0.2 at any layer (the shift is a material fraction of a context swap).

These three are **per-behavior** verdicts; the headline is the layer-sweep panel of the consistency cosine with the H1/H2/H0 bands drawn on. We report which behaviors land in which regime rather than forcing one global verdict — the literature (Xu 2026) predicts a *mixed* answer (partial additivity, not full compressibility), so a per-behavior split is itself the expected result.

## 2. Method delta

**Closest prior work** (from `docs/literature/context-instruction-shift.md`, ranked):

- **Xu 2026 "As X, Do Y" (2605.23147)** — THE closest. Decomposes `As X, do Y` prompts into pure-persona `Δ_X` + pure-task `Δ_Y` (partially orthogonal, additive) at the prompt→answer transition in an early/mid layer band, on **Gemma-2-2B-IT + Qwen-2.5-{1.5B,3B}-Instruct**. Warns local additivity ≠ prompt compressibility. **Gap we fill:** Xu tests additivity *within* the `As X, do Y` template and a fixed persona/task grid; we test **context-independence of `Δ_ℓ(C,b)` across a diverse heterogeneous bank of 10 contexts** (occupational/cultural/affect/adversarial + the bare default) **× 6 behaviors that include safety-relevant ones (sycophancy, refusal, evil) Xu does not cover**, on **Qwen-2.5-7B(-Instruct)** (one size up), and we read the *context summary* (last prompt token, mean over Q) rather than the prompt→answer-transition decomposition.
- **Persona vectors (2507.21509)**, **CAA (2312.06681)**, **refusal direction (2406.11717)**, **function vectors (2310.15213)** all compute a behavior direction from *paired behavior responses / contrastive system prompts* and show one behavior ≈ one low-rank direction. **Gap:** none measures how a *fixed context's* activation summary moves when an instruction is appended, nor whether that move is the same vector across many contexts. Our validity companion *links* to this line by projecting `Δ` onto an independently-computed persona-vectors/CAA direction.

**One-line delta:** first measurement of the prompt-induced delta of a *context summary* as a function of the appended behavior, testing context-independence of that delta across a diverse context × safety-relevant+stylistic behavior × layer grid on Qwen-2.5-7B.

### 3.3 ChatML prompt construction (exact)

For context `C` with system prompt `s_C` (or `None` for the bare-default `assistant`), behavior string `b`, question `q`:

```python
# bare context
messages = ([{"role": "system", "content": s_C}] if s_C else []) \
           + [{"role": "user", "content": q}]
# behavior-augmented context
s_aug = (s_C + "\n\n" + b) if s_C else b          # bare default: system = b alone
messages_aug = [{"role": "system", "content": s_aug}, {"role": "user", "content": q}]
text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
```

This is byte-identical to the `extract_centroids` construction (which already handles the falsy-prompt → no-system-turn case). The read position is the last non-pad token of `text` (`add_generation_prompt=True` appends the `<|im_start|>assistant\n` generation prefix, so the last token is the slot the model generates from — the project's canonical context-summary position, matching `probes.py` position=-1 and `extract_centroids`).

**Bare-default `assistant` ⊕ b:** since `assistant` has no system prompt, `C ⊕ b` puts the behavior alone in the system turn. This is the deployment-relevant case (no persona, just the behavior) and is the safety-eval target the body names. Flagged in §12 as a length-asymmetry consideration.

### 3.5 Validity companions

1. **Behavioral check (on-policy, Phase C).** For the 4-context × 6-behavior subset, generate under `C` vs `C⊕b` (vLLM, temp=0) and judge the target-behavior rate with `claude-sonnet-4-5-20250929`. Confirms the instruction induces the behavior at all (construct validity for `Δ`). This is the **kill-criterion gate** (§ Kill criteria).
2. **Link to a known behavior direction.** For each behavior `b`, compute a **persona-vectors/CAA-style difference-in-means behavior direction** `u_ℓ(b)` from the model's OWN responses: reuse `extract_centroids_response_mean` (recipe (b) of `persona-distance-metrics.md`, the persona-vectors response-token recipe) to get response-mean activations under `C⊕b` (behavior-on) and `C` (behavior-off) over the subset contexts × Q, then `u_ℓ(b) = mean(on) − mean(off)`. Project `Δ_ℓ(C,b)` onto `u_ℓ(b)`: report the fraction of `‖Δ‖` explained (`|Δ·û| / ‖Δ‖`) per (context, behavior, layer). Ties the last-prompt-token shift to the independently-derived response-space behavior direction → directly to persona vectors (2507.21509).

### 3.6 Data source + realism tier

The **question bank Q** is the data source under `data-realism.md`. We use `EVAL_QUESTIONS` (n=20) from `personas.py` — the project's standard neutral-question bank, adopted by every leakage experiment (#18/#207/#247/#383/#545/#612). These are **tier-4 / programmatically-curated neutral questions** (a fixed hand-written bank of generic open-ended questions). Justification for tier-4 here: **the question bank is a controlled covariate, not the construct under test.** The construct is the *context vector shift*, mean-pooled over Q to marginalize out question-specific variance; Q must be held FIXED and IDENTICAL across all contexts and the with/without conditions so that `Δ_ℓ(C,b)` isolates the instruction effect (any variation in Q would inject question-content variance into the shift). A diverse real-world question distribution would *increase* the pooled variance without changing the quantity of interest (the mean shift), and would break comparability with the prior project line that uses this exact bank. The tier-4 fixed bank is the correct choice *because* the questions are a nuisance dimension to be marginalized, not the signal. Carried as a scope caveat: results are for this neutral-question distribution; a verbosity/coding/adversarial question distribution is a follow-up.

**Behavior strings** and **persona system prompts** are the experimental manipulations, pinned verbatim in §10. Behaviors are tier-4 controlled templates by construction (the instruction IS the manipulated variable). Personas are the project's canonical bank.

## Success criteria

Restates the per-behavior verdict bands from §1 as the explicit pass conditions (grounded in the near-orthogonal consistency null + the single-direction literature; reporting aid, not a hard gate per §12):

- **H1 (single context-independent direction) confirmed** for a behavior `b` iff, at its best layer, mean pairwise cosine of `{Δ_ℓ*(C,b)}_C` **> 0.6** AND PC1 variance share **> 0.5**. Overall H1 verdict: **≥ 4 / 6** behaviors pass. *Source for thresholds:* near-orthogonal null (cosine ~0 ± 1/√3584) + single-dominant-direction findings (persona vectors `2507.21509`, refusal `2406.11717`); no paper publishes a cross-context appended-instruction consistency cosine (this is the first), so the bar is set well above chance, not from a transferred number.
- **H2 (context-dependent shift) confirmed** for `b` iff mean pairwise cosine in **[0.0, 0.4]** AND PC1 share **< 0.4**, with magnitude-ratio ≥ 0.2 (H0 ruled out). Overall: ≥ 4 / 6 behaviors.
- **H0 (negligible shift) confirmed** for `b` iff `‖Δ_ℓ(C,b)‖ / median_{C≠C'}‖v_ℓ(C)−v_ℓ(C')‖` **< 0.2** at every probed layer.
- **Behavioral-validity (construct) PASS:** `rate(C⊕b) − rate(C) ≥ +0.15` (judge-positive) for **≥ 4 / 6** behaviors (the geometry is meaningful). Below this is the kill trigger (§8).
- **Mixed verdict is an allowed, expected outcome** (Xu 2026 predicts partial additivity, not full compressibility): the deliverable is the per-behavior layer-sweep curve placing each behavior in its regime, not a forced single global label.

## 8. Kill criteria

The result rests on one assumption: the appended instruction actually changes behavior. **If the behavioral-validity judge (Phase C) shows the instruction does NOT raise the target-behavior rate** — concretely, if `rate(C⊕b) − rate(C)` is **< +0.15** (judge-positive rate) for **≥ 3 / 6** behaviors averaged across the 4 subset contexts — then `Δ_ℓ(C,b)` is measuring an instruction the model ignores (noise, not a behavior shift), and the geometry verdict is meaningless. Action: re-roll the offending behavior string(s) (stronger/clearer instruction wording) and re-run Phase A+C for those behaviors before reading any H1/H2/H0 verdict. (Phase A is cheap to re-run per-behavior.) This is the autonomous-mode re-roll path; the session does not park — it fixes the wording and re-runs, then reports both the failed and fixed wordings.

Note the expected exception: `villain ⊕ evil` and `assistant`-already-helpful cases may show small `Δ` and small rate change *because the persona already implies the behavior* — that is a finding (saturation of the persona), not a kill. The kill fires only on a behavior that fails across MOST contexts, which means the instruction itself is inert.

## 11. §11 Decision Rationale

- **Layer set {7, 14, 21, 27}.** *What:* four block indices spanning early-mid → last. *Why:* the project's canonical persona-distance layer sweep (so this result is comparable to the #404/#458/#207/#311 geometry line) AND it spans the band the literature disputes — function vectors show strongest causal effect in **middle** layers (2310.15213), Xu 2026 finds the additive decomposition in an **early/mid** band (2605.23147), Geometry of Prompting says instructions hit **late** layers (2502.08009). {7,14,21,27} brackets all three so we can locate where consistency/magnitude peak. *Source:* project default — `.claude/rules/persona-distance-metrics.md` ("Sweep layers {7,14,21,27}"); literature tension `2310.15213` / `2605.23147` / `2502.08009`. *Alternatives:* a finer all-28-layer sweep (rejected — 7× the cost for marginal resolution at this stage; the 4-layer set already brackets the disputed band, and a finer sweep is a named cheap follow-up if a peak sits between probed layers).
- **Question bank `EVAL_QUESTIONS` (n=20).** *What:* the project's standard 20 neutral questions. *Why:* held fixed across all conditions so `Δ` isolates the instruction effect; comparable to the entire prior leakage line that uses this bank; mean-pooling over 20 marginalizes question-content variance. *Source:* project default — `src/explore_persona_space/personas.py` (used by #18/#207/#247/#383/#545/#612). *Alternatives:* `EVAL_QUESTIONS_A3` (rejected — near-identical, no benefit); a larger/realistic question distribution (rejected for the core run — increases pooled variance without changing the mean shift; named as a follow-up scope caveat §3.6).
- **Per-condition n = 20 (questions mean-pooled).** *What:* mean over the 20-question bank → one vector per condition per layer. *Why:* the body's formalization `v_ℓ(C) = mean_{q∈Q} h_ℓ(C,q)`; 20 is the project default pool size for centroid extraction. *Source:* body formalization + `representation_shift.py` `DEFAULT_QUESTIONS`. *Alternatives:* per-question `Δ` without pooling (kept for the fig-f scatter only; the headline pools per the formalization).
- **Centering = `global_mean` (bank cosines).** *What:* globally mean-center the centroid bank before cosine. *Why:* raw bank cosine is deprecated — Qwen-2.5-7B centroids share a dominant mean direction compressing raw cosine into [0.73,1.0] (#536). *Source:* project default per #536 (`.claude/rules/persona-distance-metrics.md` § Bank centering). *Alternatives:* raw bank cosine (rejected, deprecated). The `Δ`-consistency cosine is raw-pairwise by necessity (the `Δ`s are differences, no bank to center) — labeled `raw pairwise (uncentered)` per the two-family rule, never numerically compared to bank-cosine values.
- **Validity-companion direction recipe = response-mean diff-in-means (persona-vectors recipe (b)).** *What:* `u_ℓ(b) = mean_response(C⊕b) − mean_response(C)` via `extract_centroids_response_mean`. *Why:* this IS the persona-vectors / CAA recipe (difference-in-means of residual activations between behavior-on/off, persona-vectors averages over response tokens) — the established behavior-direction construct the body wants to link to. *Source:* `2507.21509` (persona vectors recipe (b)) + `2312.06681` (CAA diff-in-means) + `.claude/rules/persona-distance-metrics.md` recipe (b). *Alternatives:* a contrastive-system-prompt-pair direction over MANY trait pairs (rejected — heavier, and our `C⊕b` vs `C` IS the contrastive pair we already have); last-prompt-token diff-in-means instead of response-mean (rejected — response-mean is the canonical persona-vectors point and gives an independent read-position from the last-token `Δ`, making the projection a real cross-check rather than tautological).
- **Judge = `claude-sonnet-4-5-20250929`.** *What:* the project judge for the behavioral-validity rate. *Why:* one consistent judge across the project for every judged behavior. *Source:* project default per CLAUDE.md (LLM judge rule). *Alternatives:* Haiku/gpt-4o (rejected — banned for new work).
- **Behavioral-validity subset size = 4 contexts × 6 behaviors × 15 questions × 2.** *What:* 720 judged completions. *Why:* enough to estimate a per-behavior rate delta with a tight enough CI to fire the kill criterion (15 questions × 4 contexts = 60 generations per condition per behavior), while keeping the judge set small/cheap; mirrors the judged-rate practice in #612/#608. *Source:* `#612` / `#608` (judged sycophancy/EM rate subsets). *Alternatives:* all 10 contexts (rejected — the 4 chosen — `assistant`, `software_engineer`, `villain`, `medical_doctor` — span the cosine range and the safety-vs-neutral axis; full 10 is a cheap follow-up if a context-specific anomaly appears); fewer questions (rejected — < 15 gives too noisy a rate for the kill gate).
- **Primary + base-model scope (both in one run).** *What:* run instruct AND base in the same job. *Why:* the base arm answers "does the consistent-direction geometry exist pre-instruct-tuning, or does instruct-tuning create it" — a first-class part of the Goal's "across ... models" framing, and it is cheap (a second ~0.6 GPU-h forward-pass loop, no extra provision). Including it now avoids a follow-up provision and makes the instruct result interpretable against the base. *Source:* body ("Comparison: Qwen-2.5-7B base ... include if cheap") + cost estimate (the 2nd model is ~0.6 GPU-h, total stays < 5). *Alternatives:* instruct-only with base as a follow-up (rejected — the marginal cost is trivial and the base contrast is load-bearing for interpretation; deferring it would force a second provision for a 0.6-GPU-h read).
