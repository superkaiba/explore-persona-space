# Plan v1 — Task #2026: export EPS_GIT_SHA in the SLURM sbatch env for rsync-lane provenance

## Goal / Requirement

Export `EPS_GIT_SHA=<materialized branch tip sha>` in the SLURM sbatch custom-stage env block so rsync-lane (git-less scratch) provenance helpers resolve the real code sha instead of the degraded literal (`unknown-no-git` / `unavailable-no-git-checkout`). Origin: workflow-fix candidate from #1336 (fellows job 17987, g2_parity rc=128); #1902 hit the same gap.

**Acceptance criteria:**

1. A custom-stage sbatch rendered with a resolvable sha carries `export EPS_GIT_SHA="${EPS_GIT_SHA:-<40-hex sha>}"` in the stage env block, adjacent to the existing `EPS_ISSUE` / `EPS_ATTEMPT_ID` exports (slurm.py ~L2215).
2. The `${EPS_GIT_SHA:-...}` default form preserves an ambient/inline override — parity with the `WANDB_PROJECT` / env-pin precedent at the same site.
3. `render_sbatch` stays a PURE function (docstring contract: no side effects, no filesystem access) — sha resolution happens in the backend layer and is threaded in as a parameter.
4. Sha-resolution failure NEVER blocks a render/launch: the export line is omitted (consumers keep today's degraded-literal fallback — strictly no worse than current behavior) and a warning is logged.
5. Render pin tests: line present when a sha is threaded; line absent when it is `None`; the resolution helper covered (local ref, `origin/<branch>` fallback, unresolvable → `None`).
6. No consumer changes: `scripts/issue1902_corpus.py`, `scripts/issue1902_run.py`, `scripts/issue825_mlp_followup_dispatch.sh`, `scripts/issue825_onpolicy_dispatch.sh`, `scripts/issue1895_subspaces.py` (repo-wide `grep -rln EPS_GIT_SHA` hit set, re-verified 2026-08-02) already read `EPS_GIT_SHA` as the first resolution rung.

## Method delta

New capability on the EXISTING render path only: today the custom-stage block exports `EPS_ISSUE` / `EPS_ATTEMPT_ID` / env-pins / `WANDB_PROJECT` but no code sha; this adds ONE conditional export threaded through the existing centralized render seam (`SlurmBackend._render_script_for`). No lane-routing change, no monitor change, no dispatch-CLI change, no marker/schema change.

## Design (file paths + concrete diffs)

**File 1: `src/explore_persona_space/backends/slurm.py`** (three edits)

(a) **New module-level helper** `resolve_branch_tip_sha(src_root: Path, branch: str, timeout: int = 15) -> str | None`, placed next to `head_commit_matches_branch` (~L3762). Resolution order IDENTICAL to `materialize_branch_src` step 3 and `head_commit_matches_branch`: `git -C <src_root> rev-parse --verify --quiet <ref>^{commit}` for `ref` in (`<branch>`, `origin/<branch>`). Returns the 40-hex sha, or `None` FAIL-SOFT on any git failure (`FileNotFoundError` / `TimeoutExpired` / nonzero rc) — provenance is best-effort metadata; a launch must never die on it (`materialize_branch_src` already fails LOUD at prepare on an unresolvable branch, so the launch-path residual is narrow).

```python
def resolve_branch_tip_sha(src_root: Path, branch: str, timeout: int = 15) -> str | None:
    for ref in (branch, f"origin/{branch}"):
        try:
            proc = subprocess.run(
                ["git", "-C", str(src_root), "rev-parse", "--verify", "--quiet", f"{ref}^{{commit}}"],
                capture_output=True, text=True, encoding="utf-8", errors="replace",
                check=False, timeout=timeout,
            )
        except (FileNotFoundError, subprocess.TimeoutExpired):
            return None
        if proc.returncode == 0 and proc.stdout.strip():
            return proc.stdout.strip()
    return None
```

## Accepted residuals (documented, not silent)

1. 3. Local `<branch>` ref resolving ahead of `origin/<branch>` mirrors `materialize_branch_src`'s own order by design — the exported sha matches what the materializer ships.
