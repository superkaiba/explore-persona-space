# Plan — Task #642: Is the #606 LoRA-vs-full-FT sycophancy bystander-leakage gap driven by module coverage or by rank? (coverage-matched-FT arm)

## 0.0 TL;DR (plain English)

<section class="plan-tldr">

- **What I'll run:** An earlier experiment (#606) found that fully fine-tuning a model spreads a learned "agree-with-the-user" habit into other personas about ten points more than the lightweight LoRA method does, comparing them at the same installed strength. But "full fine-tuning" changes two things at once versus LoRA. It touches *more parts* of the network (including the word-embedding and output layers LoRA never edits), and it can make *bigger, fuller-rank* edits to the parts they share. So I add one new training run that fully fine-tunes ONLY the same parts LoRA edits, freezing the extra layers, so it differs from LoRA in fullness-of-edit but not in *which parts* get touched. Three runs, read at the same installed strength, split the ten-point gap into a "which parts" piece and a "how full the edit" piece.
- **What I expect:** My weak bet is that freezing the extra layers brings the leakage most of the way back down toward LoRA, meaning the gap is mostly about *where* full fine-tuning is allowed to write, not about how full the edit is. But the published work points the other way (full edits perturb off-target behavior more even on shared weights), so I genuinely don't know.
- **What would change my mind:** If the frozen-extra-layers run leaks just as much as ordinary full fine-tuning, then "where the editing happens" isn't the story and edit-fullness is, and the case for keeping LoRA as the project's default gets weaker.

</section>

## 1. Goal

Decompose the #606 LoRA-vs-full-fine-tuning sycophancy bystander-leakage gap into a **module-coverage** component and a **rank** component by adding a coverage-matched full-FT arm (`embed_tokens`/`lm_head`/LayerNorm frozen) to #606's comparison at matched source-implant strength.

#606 established (MODERATE confidence) that at matched 0.50 source-implant strength, full FT leaks sycophancy to the 38 bystander personas at +0.098 rate points above LoRA (95% CI +0.072 to +0.123, N=38). That single comparison confounds two variables: **rank** (LoRA's low-rank `α/√r`-scaled adapters vs full-rank parameter updates) AND **module coverage** (full FT updates *everything* — `embed_tokens`, `lm_head`, all LayerNorms, biases — while the #606 LoRA `target_modules` touch ONLY `{q,k,v,o,gate,up,down}_proj`). The new arm fully fine-tunes exactly the LoRA-touched module set with everything else frozen, so it is full-rank-on-the-LoRA-modules — sharing the module set with LoRA and the rank with full FT. The two resulting single-variable contrasts attribute the #606 gap to rank, coverage, or a measured mix.

This resolves the "careful about where the LoRA lives" placement concern (from #619's think-through) by testing it directly rather than recording the default LoRA placement as non-load-bearing.

**Literature (abstracts + authors/venue verified via arXiv MCP this session):**

- Biderman et al., *LoRA Learns Less and Forgets Less*, arXiv **2405.09673** (2024-05-15): full FT "learns perturbations with a rank that is 10-100× greater than typical LoRA"; LoRA "better maintains the base model's performance on tasks outside the target domain". Bystander leakage is precisely off-target perturbation → directional prior: the residual after coverage-matching (`Δ_rank`) is the rank-driven off-target perturbation this paper attributes to full FT's higher-rank updates; expect `Δ_rank > 0` if rank is the driver.
- Shuttleworth et al., *LoRA vs Full Fine-tuning: An Illusion of Equivalence*, arXiv **2410.21228** (2024-10-28, MIT — Andreas/Torralba/Sharma): LoRA and full FT reach spectrally different solutions ("intruder dimensions") even at matched target performance; forgetting is "vastly localized to the intruder dimension". These intruder dimensions live in the *shared* weight matrices (the `_proj` modules), NOT in embeddings/`lm_head` — so this paper's mechanism predicts a rank/structure component that survives coverage-matching (i.e. `Δ_rank ≠ 0`), which is the directly testable prediction #642 adds on top of #606.

**What is new vs prior:** #606 measured the *total* method gap. No prior issue decomposes that gap into placement (coverage) vs rank. The literature predicts both could contribute; #642 is the first measurement that separates them on this rig.

## 3. Hypothesis

Strength dial (inherited from #606): **s = source-self judge-scored sycophancy rate delta (trained − base)** measured on-policy on the source persona's own panel. Matched target **s* = 0.50**, band [0.40, 0.60] (inherited — #606's sycophancy reads sit on tight bracket pairs here); secondary read at s* = 0.75.

The two single-variable contrasts at s* = 0.50, on the 38-bystander mean:

- **`Δ_rank` = coverage-matched-FT − LoRA** (holds the module set constant at `{q,k,v,o,gate,up,down}_proj`, varies rank low→full).
- **`Δ_coverage` = full-FT − coverage-matched-FT** (holds rank constant at full, varies coverage default-set→all-modules).
- **Additive-decomposition consistency:** `Δ_rank + Δ_coverage` should reconstruct #606's measured full-FT−LoRA gap of **+0.098** (within the combined bootstrap CIs); a gross failure of this identity flags a measurement/install-mismatch problem (e.g. the reused arms were not actually at matched s* under the new dial read — §6 governs this).

Pre-registered decision rule (the body's three branches, made quantitative):

- **H_coverage (the gap is placement):** `Δ_coverage` CI excludes 0 with point ≥ +0.04 AND `Δ_rank` CI ⊂ (−0.04, +0.04). → full FT's extra leakage comes from the `embed_tokens`/`lm_head`/LayerNorm writes the LoRA structurally cannot make; #606's divergence is a *placement* result and the default LoRA module set is defensible as a leakage-limiting choice.
- **H_rank (the gap is rank):** `Δ_rank` CI excludes 0 with point ≥ +0.04 AND `Δ_coverage` CI ⊂ (−0.04, +0.04). → module coverage is not the driver; full-rank updates on the shared modules carry the leakage (consistent with 2410.21228's intruder-dimension mechanism).
- **H_mixed (both contribute):** both `Δ_rank` and `Δ_coverage` CIs exclude 0 with point ≥ +0.04. → report the partition with CIs; do not round to a pole.
- **Indeterminate:** neither contrast separates by ≥ +0.04 with CI excluding 0 (see kill criterion §7), OR the additive identity fails grossly → reported as such, never rounded to a null.

Threshold choice: ±0.04 is below the #606 total gap (+0.098) so a clean single-pole split is detectable, and above the #606 determinacy-gate scale (0.05 plug-in-vs-bootstrap on the interpolation) only in the sense that each contrast must clear the noise floor — the gate itself (≤0.05) still applies per contrast.

### 4.2 New code (minimal — one flag on the existing #606 FT trainer)

`scripts/train_behavior_fullft.py` (on `origin/issue-606`, ported to `main` in the worktree) already loads the model at line ~283 (`model = AutoModelForCausalLM.from_pretrained(...)` then `model.gradient_checkpointing_enable()`), builds `Trainer` at line ~318. The ONLY new logic is a freeze pass inserted between those two points, gated by a new `--freeze-outside-lora-modules` flag:

```python
LORA_MODULE_SUFFIXES = (  # exactly the #606 adapter_config target_modules
    "q_proj", "k_proj", "v_proj", "o_proj",
    "gate_proj", "up_proj", "down_proj",
)

def apply_coverage_match_freeze(model) -> dict[str, int]:
    """Freeze every parameter EXCEPT the .weight of the LoRA-touched linear
    modules. Returns {trainable, frozen} param counts for the fail-loud assert.
    Frozen: embed_tokens, lm_head, all *layernorm*/model.norm, every bias."""
    trainable = frozen = 0
    for name, p in model.named_parameters():
        # train ONLY <...>.{q,k,v,o,gate,up,down}_proj.weight (no bias — Qwen2
        # _proj layers are bias-free, asserted below)
        keep = name.endswith(".weight") and any(
            name.endswith(f"{suf}.weight") for suf in LORA_MODULE_SUFFIXES
        )
        p.requires_grad = bool(keep)
        n = p.numel()
        trainable += n if keep else 0
        frozen += 0 if keep else n
    return {"trainable": trainable, "frozen": frozen}
```

Fail-loud asserts wired into the trainer (smoke-verified, §4.6):
1. **Mask non-empty & correct:** `trainable > 0`; assert that `embed_tokens`, `lm_head`, every `*layernorm*` and `model.norm` parameter resolved to `requires_grad=False`; assert NO `_proj.bias` exists (Qwen2 `_proj` are bias-free — confirmed via config this session) so the suffix rule is exhaustive.
2. **Module-set identity vs the LoRA arm:** the set of trained module *suffixes* equals the #606 adapter `target_modules` set exactly (the contract for `Δ_coverage` being single-variable). Asserted against the literal `target_modules` read from `adapters/issue_606/sycophancy_lora_step32/adapter_config.json` at build time (downloaded + parsed in Phase 0).
3. **Trainable-fraction sanity:** the trained `_proj` weights are ~6.5 B of Qwen-2.5-7B's ~7.6 B params (embeddings+lm_head ≈ 0.5 B + 0.5 B tied-off, norms negligible); assert `0.80 < trainable/total < 0.92` as a coarse guard that the mask didn't silently freeze a `_proj` layer.

ZeRO-3 interaction (load-bearing): under DeepSpeed ZeRO-3, frozen params (`requires_grad=False`) are still partitioned but receive no gradient and no optimizer state, so the optimizer-state memory drops and the gather-on-save still produces a full consolidated bf16 checkpoint (the frozen weights are saved at their base values). This is the standard ZeRO-3 + frozen-param path; the smoke FT canary (§4.6) exercises a 4-step coverage-matched train + ZeRO-3 consolidated save + vLLM load before the full run, so the path is verified, not assumed.

### 4.11 Multi-arm resolution-band compliance

This is a matched-strength bracket design (arms matched on the *dial*, deliberately NOT on step count), not a band-simultaneity design — so the band-simultaneity rule's "all arms inside the band at a shared step" gate does NOT apply. Each arm is read at its own s*-bracketing checkpoint pair. (a) The cmft install-transition window is grounded by reuse: the cmft arm trains the SAME modules the #606 full-FT arm trained, at the same lr/batch/data, just minus the frozen layers — so its install dynamics are bounded by #606's measured full-FT sycophancy trajectory (which bracketed s* cleanly at FT steps 12/16; that grid is reused). Freezing embeddings/lm_head typically *slows* install slightly (fewer trainable params at fixed lr), pushing the crossing later into the grid, which the dense early grid (2-step resolution through step 16) covers. (b) **Pre-registered fallback ladder** if the cmft arm has no checkpoint in [0.40, 0.60]: (i) compare at the cmft band-entry checkpoint (first checkpoint with s in band; if none, closest approach), reporting matched-dial/unmatched-step explicitly; (ii) run the matched read at the nearest target the cmft arm DOES bracket (from the s*-sweep grid, shared with the reused arms); (iii) one pre-authorized cmft retrain at lr 2e-6 (the #606 lower-lr lever) to re-grade the trajectory. (c) "The cmft arm never brackets s* under this recipe" is a decidable, reportable outcome, not a silent interpolation across a jump.

### Install-strength control (cross-condition leakage comparison — REQUIRED)

This plan's headline IS a cross-condition leakage comparison (three training conditions), so per CLAUDE.md's install-strength-confound rule the raw-rate comparison is dose-confounded by default. The design controls install three ways: (1) **matched-install by construction** — all three arms are read at the SAME source-implant strength s*=0.50, interpolated per arm from its own bracket (this is the #606 protocol, the primary control); (2) the **additive-identity check** (`Δ_rank + Δ_coverage ≈ #606 gap`) is itself an install-consistency cross-check — it can only hold if all three arms truly sit at matched s*; (3) **install-vs-leakage dose curves** — the s*-sweep (matched reads at s* ∈ {0.2,…,0.8}) is produced for all three arms, so each contrast is reported as a curve over the dial, not a single point (subsumes a single fraction and catches nonlinear leakage onset). Note this rule's caution that contrastive/method changes can move install strength in *either* direction (#601 vs #608): coverage-matching could install *weaker* than full FT at fixed lr (fewer trainable params), which is exactly why the matched-s* read — not a fixed-step read — is the headline, and why the s*-sweep is mandatory rather than optional. The fraction-of-install logit-space read is **not** used here: the DV is a bounded judge rate, not a marker logit, and #606's headline (which #642 must reconstruct) is in raw rate-delta space — switching to a logit fraction would break the additive-identity join with #606. (No marker logits exist in this design.)

### Success criteria (numeric)

Per the §3 decision rule: **H_coverage** = `Δ_coverage` CI excludes 0, point ≥ +0.04, AND `Δ_rank` CI ⊂ (−0.04,+0.04); **H_rank** = mirror; **H_mixed** = both CIs exclude 0 with point ≥ +0.04; else **indeterminate** (reported as noise-limited, never "confirms the null"). The determinacy gate (|plug-in − bootstrap mean| ≤ 0.05 rate points) must pass per contrast for a determinate read. Additive-identity tolerance: `|Δ_rank + Δ_coverage − 0.098|` should fall inside the summed bootstrap CI half-widths; a gross failure (>2× that) is reported as an install-mismatch caveat on the partition.

## 7. Decision Gates

One gate (justified: wall > 4 h AND the cmft install dynamics are not directly measured — only bounded by #606's full-FT trajectory — AND stage-A is a cheap signal that rules out the expensive stage-B):

- **Install gate (after stage-A, cmft arm):** proceed to stage-B iff the cmft arm brackets s*=0.50 with non-degenerate selected cells, OR (no bracket) reaches endpoint s ≥ 0.50 (band-entry fallback read per §4.11). Endpoint s ≥ 0.6 is NOT required to proceed — it only labels install strength and enables the s*=0.75 secondary read. Grounding (sign + threshold): #606's full-FT sycophancy arm — the SAME modules trained at the SAME lr — installed to source strength 0.37/0.53 at FT steps 12/16, cleanly bracketing s*=0.50; freezing embeddings/lm_head slows install at most mildly at fixed lr, so the expected outcome is PASS, and the gate exists for the residual risk that the slowdown pushes the crossing past step 132 or into a grid gap. On FAIL (kill criterion (a) below: neither bracket nor endpoint ≥ 0.50): fire the §4.11 fallback ladder (band-entry read + nearest co-bracketed target + the one pre-authorized lr-2e-6 retrain); if the arm genuinely never installs sycophancy to s ≥ 0.50 even at the endpoint, report install-failure and the decomposition is not computed (reported as exactly that — no silent extrapolation). Jointly satisfiable: single gate, sign matches #606's measured full-FT install of this exact behavior/modules/lr, coherent with §4.11 by construction.

No other gates — checkpoint selection is a pipeline phase, not a stop/go gate.

**Kill criteria (the design-failed outcomes, pre-registered):**
- (a) **cmft install failure** = the cmft arm neither brackets s*=0.50 with non-degenerate cells NOR reaches endpoint s ≥ 0.50 after the fallback ladder → the decomposition cannot be computed; report install-failure, do not run the join. (This is also the install gate's FAIL branch.)
- (b) **Uninterpretable partition** = NEITHER `Δ_rank` NOR `Δ_coverage` separates from 0 by ≥ +0.04 with its CI excluding 0 (both contrasts are noise-limited at the matched read) → the experiment cannot attribute the #606 gap to either component at this power; reported as a design failure ("indeterminate, noise-limited"), NOT rounded to a pole and NOT narrated as "coverage and rank both don't matter" (the #606 gap is real; the inability to split it is a power statement). This is jointly satisfiable with the install gate and the §3 decision rule by construction: the decision rule's three positive branches and this kill branch partition the outcome space with no contradictory thresholds (no gate demands `Δ ≥ +x` and `Δ ≤ −y` on the same contrast).
- (c) **Additive-identity gross failure** = `|Δ_rank + Δ_coverage − 0.098| > 2×` the summed bootstrap CI half-widths → the reused arms were not actually at matched s* under the re-judged dial (a measurement-regime failure of the reuse, gate (b)); reported as such with the partition flagged untrustworthy, and the LoRA/FT cells' re-derived s values published so the mismatch is auditable.
