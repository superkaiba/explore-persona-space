## 6. Kill criteria

- A consumer demonstrably intolerant of duplicated/reordered registry lines → kill. **Re-verified refuted:** `new_worktree.sh` L293-294 ("Duplicates ... are harmless — `set` dedupes") + L338 `git sparse-checkout set $DIRS $CONES $TEST_CONES $EXISTING`; `step9c_baseline.py` L742 `sorted(set(dirs) | set(registry_lines) | set(wt_cones))`.
- Whitespace guard (`new_worktree.sh` L328-330) tripped by union output → kill. Cannot happen: union only concatenates whole lines that already exist on one side; it never splits, joins (given trailing newlines, §3), or introduces whitespace into a line.

## 7. Risks

| Risk | Likelihood | Assessment |
|---|---|---|
| Duplicate lines accumulate after append-append union | Low | Benign — both consumers dedupe (set semantics); self-heals on the next hand-edit of the registry |
| Concurrent EDITS of the same region merge without markers, duplicating/interleaving lines | Very low (registry is append-dominant; edits are comment-block updates) | Same accepted trade-off as #896/#1534; hard conflict blocking a fleet-wide root sync is worse |
| Server-side `gh pr merge` still conflicts | N/A — known scope caveat | Guard-1 / surgical paths unchanged (file header); both incidents were local |
| Deleted-line resurrection (one side removes a cone, other appends) | Very low (cones are essentially never removed) | Union keeps both sides — a resurrected cone dir is a harmless extra sparse cone, fail-safe direction |
| Future commit strips the trailing newline → joined last lines in a later union | Very low | Joined line contains no whitespace so the guard won't fire, but the malformed cone matches nothing and downstream tests fail loud (FileNotFoundError); registry comment already mandates one-dir-per-line |

- **Source:** #787 (mechanism + scope caveat, in production since 2026-07-01), #1534 (closest precedent — same file, same class, same pin-test file, auto-approved 2026-07-18), #896.
