## 1. Goal

(Task #1692 Goal, verbatim.)

> Require the smoke-architecture-check to execute every deferred import
> and the REAL computation path of each planned arm, to enumerate
> real-versus-fallback per planned arm in its verdict, and to forbid
> `PASS_UNIFIED` when any planned arm resolved to a stub or a mock-only
> branch.

The gate currently reports `PASS_UNIFIED` on a phase-coverage basis, so
two failure classes false-pass it: (a) code paths behind a mock/lazy
branch that the smoke never executes (rounds 2/3/4 of #1689 hid a
`DispatchCall` typo + a sync-invoked async call behind `--mock-response`);
(b) literal fallback stubs that satisfy phase coverage but deliver
arms of the wrong science (#1689 round 2 had rungs 7/8/9 falling back
to a bias-refit R²). This task closes both.

## 3. Hypothesis

Adding (a) an import-resolution leg on the real branch, (b) a per-arm
REAL/FALLBACK/N/A attestation table, and (c) a `PASS_PARTIAL` verdict
that Step 6d.0 refuses to dispatch on, closes both #1689 false-pass
classes without over-blocking legitimate infra-task smokes.

**Success = every future round meeting the following predicates:**

1. An `epm:smoke-architecture-check` marker whose `notes:` contains a
   line `import-resolution: <exact command executed>` naming a real-
   branch invocation (an `--import-check` mode of the dispatcher, or a
   `python -c 'import <entrypoint>'` per changed entrypoint), never a
   mock-flag branch.
2. A `notes:` sub-block `per-arm-resolution:` with one row per
   plan-named arm: `<arm-name>: REAL | FALLBACK <reason> | N/A — no
   computation path`.
3. `PASS_UNIFIED` reserved for the case where every planned arm row
   reads `REAL` or `N/A`; `PASS_PARTIAL arms_stubbed=<comma-list>`
   otherwise; existing `PASS_CANARY` / `FAIL_NO_CANARY` unchanged.
4. Step 6d.0 refuses to dispatch on `PASS_PARTIAL` for planned
   experiment arms, bouncing to `status:planning` with pivot scope
   naming the stubbed arms (same class as `FAIL_NO_CANARY`).
5. `code-reviewer.md` Step 0.55 binds mechanically: when the marker
   reports `PASS_UNIFIED` AND the plan §4 names ≥1 arm, verify the
   per-arm table exists AND every row is REAL / N/A — otherwise return
   a `Critical` blocker tagged `marker-shape` naming
   `epm:smoke-architecture-check`.

DISJOINT and exhaustive: `PASS_UNIFIED` ⇔ every planned arm REAL or N/A
AND phase coverage holds; `PASS_PARTIAL` ⇔ ≥1 planned arm FALLBACK AND
phase coverage holds; `PASS_CANARY` ⇔ divergence + §4 justification +
named canary AND every planned arm REAL or N/A; `FAIL_NO_CANARY` ⇔
otherwise.

## 4. Design

### Axis 1 — Import-resolution leg (execute on the REAL branch)

**File:** `.claude/agents/experiment-implementer.md`, item 5 (around
line 115-236 of "Before writing code" — item 5 extends further than the
v1 plan cited; the insertion point at line 124 is unchanged).

**Change:** insert a new numbered sub-bullet BEFORE the existing
PASS_UNIFIED definition (keeps the pre-flight ordering intact), and
add a corresponding `notes:` line to the post-marker template
(around line 168):

> **Import-resolution leg (BEFORE the phase-coverage smoke).** For every
> changed entrypoint in this round's diff (a `scripts/*.py` or
> `src/**/*.py` file the round touches), execute its deferred/lazy
> imports on the REAL branch. Bare `python -c 'import <module>'`
> triggers ONLY module-level imports; the #1689 rounds 2/3/4 false-pass
> class was a `from foo import DispatchCall` NESTED inside a function
> body, which a top-level import never fires. Use ONE of:
> - (a) **PREFERRED — the dispatcher's `--import-check` mode**, which
>   loads the entrypoint AND resolves every function-body import + every
>   `importlib`/`getattr` deferred import the entrypoint would hit on
>   its real code path. Implementers add this mode to any new
>   `scripts/issueNNNN_*.py` dispatcher (a one-line `if
>   args.import_check: from foo import (DispatchCall, dispatch_calls);
>   sys.exit(0)` at the top of `main()` is sufficient — the point is to
>   NAME the deferred symbols).
> - (b) **acceptable fallback** — a `uv run python -c 'from
>   scripts.issueNNNN_entrypoint import (dispatch_calls, DispatchCall,
>   …every named function-body import…)'` — the `from <mod> import
>   <names>` form fires those specific deferred names at module load.
>   This is only acceptable when every deferred import in the
>   entrypoint's changed lines is enumerated in the `from ... import
>   ...` list; a bare `import <mod>` is EXPLICITLY INSUFFICIENT and
>   does not close this failure class.
> - (c) **for pure top-level-import entrypoints** (no `def foo(): from
>   … import …` anywhere in the changed file), a bare `uv run python -c
>   'import <mod>'` suffices — state this explicitly in `notes:` as
>   `import-resolution-mode: top-level-only` so the reviewer can verify
>   the entrypoint's changed lines contain no function-body imports.
>
> State the EXACT command executed in the marker's `notes:` line
> `import-resolution: <command>`. A deferred import behind a mock-only
> branch is the #1689 rounds 2/3/4 false-pass class — the smoke MUST
> exercise the real branch. If import resolution fails, the verdict is
> `FAIL_NO_CANARY` (not `PASS_PARTIAL`): a broken import is a coverage
> failure, not a fallback choice.
>
> **Reviewer binding (mechanical):** at code-reviewer.md Step 0.55, the
> reviewer verifies the `import-resolution:` line matches one of the
> three shapes above. If the marker uses shape (c) (bare `import
> <mod>`), the reviewer greps the entrypoint's changed lines for
> function-body imports (a `def .*:` block containing `from` or
> `importlib`); a match returns a `marker-shape` blocker: "bare
> top-level import cannot resolve function-body imports on the real
> branch; use shape (a) --import-check or shape (b) `from ... import
> <names>` enumerating the deferred names."

### Axis 2 — Per-arm resolution table (attestation, not re-execution)

**File:** `.claude/agents/experiment-implementer.md`, same item 5.

**Change:** insert a second new sub-bullet after Axis 1 and before the
existing PASS_UNIFIED / PASS_CANARY / FAIL_NO_CANARY definitions:

> **Per-arm resolution attestation.** For every arm / rung / condition
> the PLAN §4 Design names (a `kind: experiment` plan lists these
> explicitly; a `kind: infra` plan typically names none), state in the
> marker `notes:` under a `per-arm-resolution:` sub-block:
>
> ```
> per-arm-resolution:
>   <arm-name-1>: REAL — <one-line: which real computation ran>
>   <arm-name-2>: FALLBACK — <one-line: what stub / bias-refit / default>
>   <arm-name-3>: N/A — no computation path (<API-only | data-load-only | …>)
> ```
>
> An arm reads `REAL` when the smoke exercised its production computation
> path (not a stub, not a fallback, not a mock-branch); `FALLBACK` when
> the smoke resolved to a placeholder (a bias-refit R², a
> `NotImplementedError`-guarded default, an early-return); `N/A — no
> computation path` when the arm is legitimately arm-less (an API-only
> phase, a data-loading probe, a phase in which the arm has nothing to
> compute in the smoke slice — the vacuous case, see § Kill criterion).
> A missing per-arm row for a plan-named arm is a `FAIL_NO_CANARY`
> shape (marker malformed, not `PASS_PARTIAL`).

### Axis 3 binding — code-reviewer.md Step 0.55

**Decision: choose (c) BOTH — implementer attestation + reviewer
mechanical binding.** Justification: attestation is cheap and self-
authored (the implementer already writes the marker), so it costs
nothing to require. Attestation alone (option a) relies on implementer
honesty and would have missed #1689 round 2 — the implementer there
attested "full 8-phase smoke green" while rungs 7/8/9 were literal
stubs. Reviewer binding (option b) makes the check independent but
requires the reviewer to redo the reasoning the implementer already
did. Combining them keeps the attestation cheap AND makes it binding:
the implementer writes the per-arm table; the reviewer verifies its
SHAPE + INTERNAL CONSISTENCY (every plan-named arm has a row; every
row parses; a `PASS_UNIFIED` verdict has no `FALLBACK` rows). The
reviewer does NOT re-adjudicate whether an arm labeled `REAL`
actually ran real code — that remains Step 6d.0's substance, exactly
as today.
