# Plan — Issue #661: r_B extraction-method divergence (A vs B vs C) across 3 behaviors

## Goal (verbatim)

Quantify how much the behavior read-out r_B diverges across three extraction methods — (A) on-policy instruction-present, (B) off-policy teacher-forced, (C) instruct-and-strip — over the same question set for 3 behaviors (sycophancy, refusal, EM), measuring pairwise cosine divergence per layer, the projection of r_B^A onto the instruction context axis (c_pos−c_neg) as the context-confound magnitude, and whether the methods differ in A3.3-style held-out predictive quality (r_B^T v0 predicting E0) — to decide the program's (#660) A3.3 r_B recipe.

## §0.0 TL;DR (plain English)

- **What I'll run:** For three behaviors (sycophancy, refusal, broad misalignment), I build a "behavior direction" — a single arrow in the model's internal space that points toward the behavior — in three ways that differ only in how the example responses were obtained and where I read the model's activations. One way bakes a "be sycophantic / be honest" instruction into the prompt and reads with that instruction still showing; one uses externally-chosen example questions and the model's own answers with no instruction; one takes the same instructed answers but re-reads them after deleting the instruction. Then I measure how much the three arrows point in different directions, and whether each arrow is equally good at predicting how strongly the behavior actually shows up.
- **What I expect:** The instruction-baked arrow will be partly contaminated by the instruction itself, so it points noticeably away from the cleaner instruct-then-delete arrow. But all three will probably predict the behavior about equally well — meaning the program can use the cheaper instruction-baked method without losing predictive power.
- **What would change my mind:** If the instruction-baked and instruct-then-delete arrows point nearly the same way (no contamination), the worry was unfounded and the cheap method is fine. The surprising-and-important outcome is the opposite: the arrows diverge AND predict the behavior differently — then which arrow you pick actually matters for the program, and I'd flag it loudly.

## §3 Hypothesis
- **H1 (confound real but partial):** `0.10 < |⟨r_B^A, ĉ_inst⟩|/‖r_B^A‖ < 0.40` at selected layer for ≥2/3 behaviors. Falsified if ≤0.10 everywhere (no contamination) or ≥0.60 everywhere (A is mostly instruction).
- **H2 (A vs C diverge moderately):** `0.80 ≤ cos(r_B^A, r_B^C) < 0.97` at selected layer. Falsified if ≥0.97 (context barely moves it) or <0.50 (reads nearly unrelated).
- **H3 (divergence cosmetic):** A's and C's A3.3 ρ differ by < #658 per-behavior noise floor on ≥2/3. Falsified if A's ρ < C's ρ by ≥0.05 on ≥2 (divergence costs predictive power → adopt C).

## §4 Design
**4.0 Single manipulated variable:** all arms compute `r_B = mean(act|present) − mean(act|absent)`, response-avg, 28 layers, per behavior. They differ ONLY in: A — same questions, pos/neg instruction sys-prompt, 10 rollouts, judge-filter, extract WITH instruction; B — prompt-class contrast (D_B eliciting vs D_B̄ neutral), greedy answers, default context, NO expression-filter (= #658 store); C — A's exact judge-filtered responses, default context, instruction DELETED. **Clean single-variable contrast = A vs C.** B = status-quo reference (A-vs-B / B-vs-C cosines fold in a second contrast-construction difference; named).

**4.1 Behaviors:** sycophancy (`syco_claim_vs_neutral`), refusal (`should_refuse_vs_should_not`), broad_em (`betley_vs_neutral`) — all in `r_b.pt`. Optional control: harmful_compliance. Marker SKIPPED (no instruction contrast; #658 already drops it from A3.3).

**4.2 Question set:** per-behavior 48-probe pool via `build_rb_contrast` (Betley main-8 / #411 wrong-claims / SORRY-Bench+XSTest) — same pool #658 B-arm used at `rb-cap 48`. ## §7 Decision Gates
**No smoke/kill gates on the run — short run (~1.5h, 2 GPU-h), pre-verified #658 infrastructure.** Well under the 4h / 16-GPU-h threshold.

Single **pre-registered falsification / decision criterion** (the experiment's output, not a stop-early gate), at the per-behavior selected layer:
- **Adopt A:** `cos(A,C) ≥ 0.95` AND `confound ≤ 0.10` AND A's ρ ≥ C's ρ within #658 noise floor — on ALL 3 behaviors.
- **Adopt C:** ANY of: `cos(A,C) < 0.85` on ≥2, OR `confound > 0.25` on ≥2, OR A's ρ < C's ρ by ≥0.05 on ≥2.
- **Inconclusive / recipe-by-behavior:** pattern splits across behaviors, OR lands between thresholds.

**Joint-satisfiability:** the verdicts partition the outcome space (Adopt-A = all-pass; Adopt-C = any-strong-fail; Inconclusive = residual), mutually exclusive by the 0.95/0.85 + 0.10/0.25 gaps, residual routed to Inconclusive → always exactly one verdict, no false-FAIL-by-construction. Threshold SIGNS grounded (higher cos/ρ + lower confound → adopt-cheap-A, matching the Goal).

**Kill / stop-and-report criteria (the run is uninformative — halt + report, do NOT silently ship a degenerate read):**
- **Insufficient survivors:** if, after the retry budget, ANY headline behavior has <5 judge-positive survivors in either the pos or neg pool of arm A, that behavior's r_B^A/r_B^C cannot be estimated — STOP that behavior, report the survival shortfall as a finding (predictable from the base-model expression rate), and proceed with the remaining behaviors. If <5 survivors on ALL 3 behaviors, halt the whole run and report (the instruction elicitation failed on this model — a substantive negative result, not an infra failure).
- **Degenerate M3 inputs:** if #658's E0 is constant (zero variance) for a behavior across the 50 contexts (the saturation regime #658 itself flags), M3 ρ is undefined for that behavior — report it as `N/A — E0 saturated` (per the measurement-validity rule: a saturated proxy is uninformative, never rank-shuffled), and base that behavior's verdict on M1+M2 only.
- **ĉ_inst non-specificity:** if the §5 control shows B AND C also project >0.25 onto ĉ_inst, measurement 2 is confounded — report M2 as DOWNGRADED/uninformative and base the verdict on M1+M3 only; do NOT report the inflated A confound as the headline.
- **All other small surface-area bugs** (preflight, vLLM teardown, OOM, env) are fixed-and-retried in-place per the recovery-mode rule, NOT halt triggers.
