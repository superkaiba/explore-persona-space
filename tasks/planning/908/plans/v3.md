### 4.1 Leg 2 — `src/explore_persona_space/backends/gcp.py` (do this first; leg 1's prose cites it)

**(a) New constant**, immediately after `_NONLIVE_INSTANCE_STATUSES` (L2725), so the invariant comment block reads as one unit:

```python
#: Guest ``eps/phase`` values that disqualify a RUNNING instance as a
#: reconnect target AND qualify it for pre-launch reclaim (#908/#763): the
#: janitor's terminal set (``done``/``failed``, :data:`_TERMINAL_GUEST_PHASES`)
#: plus the #669 reachability watchdog's pre-shutdown ``wedged`` write. A
#: RUNNING instance in any of these states is a finished-or-wedged zombie —
#: reconnecting to it silently no-ops the new dispatch (#763 leg 2), and
#: only deleting it frees the canonical name for the create (#632).
#: The two consumers (:func:`reconnect_or_none`,
#: :func:`_stale_named_instance_or_none`) MUST share this set — same
#: invariant as :data:`_NONLIVE_INSTANCE_STATUSES` above.
_ZOMBIE_GUEST_PHASES: frozenset[str] = _TERMINAL_GUEST_PHASES | frozenset({"wedged"})
```

Deliberately a NEW constant, not an edit to `_TERMINAL_GUEST_PHASES`: adding `wedged` to the janitor's set would change janitor reap behavior (out of scope for this fix; the janitor's `wedged` handling is the #667 follow-up's business).

**(b) `reconnect_or_none` predicate change** (inside the instance loop, current L2781-2786). Move the zone parse above the new gate (the probe needs the zone), then insert the phase gate:

```python
        status = inst.get("status") or ""
        if status.upper() in _NONLIVE_INSTANCE_STATUSES:
            continue
        zone_url = inst.get("zone") or ""
        # The zone field is a URL; take the last path segment.
        zone = zone_url.rsplit("/", 1)[-1] if zone_url else config.primary_zone
        # NEW (#908): a RUNNING instance whose workload already published a
        # terminal/wedged ``eps/phase`` is a zombie, NOT a live run to rejoin
        # — reconnecting to it silently no-ops the new dispatch (#763: the
        # phase-C launch "reconnected" to the gate-parked done VM and never
        # ran). ``""`` (unwritten — early boot, 404) reconnects normally. A
        # probe FAILURE raises GcpProbeError out of this function: state
        # UNKNOWN must never read as EITHER "live, reconnect" (would
        # resurrect the silent no-op) or "zombie, delete" (could reclaim a
        # healthy VM) — the #535 "couldn't ask" discipline, same as the
        # LIST probe above.
        if status.upper() == "RUNNING":
            phase = _read_guest_phase(config=config, name=name, zone=zone, runner=runner)
            if phase in _ZOMBIE_GUEST_PHASES:
                logger.warning(
                    "GCP reconnect: %s is RUNNING with terminal eps/phase=%r — refusing "
                    "reconnect (gate-park/finished zombie, #908); the pre-launch stale "
                    "reclaim deletes it before create.",
                    name,
                    phase,
                )
                continue
```

`continue` falls through to the function's terminal `return None` (exactly one instance can bear the canonical name), which routes `GcpBackend.launch` (L3588+) into the stale-reclaim → create path. The phase gate applies to `RUNNING` only — matching the janitor's `should_probe_phase` gate (L3342-3346). `PROVISIONING`/`STAGING` have no phase yet; `STOPPING`+`done` is the normal seconds-long teardown transition and refusing it would hit `_stale_named_instance_or_none`'s live-status raise (see Risks R5 for the accepted residual).

**(c) `_stale_named_instance_or_none` matched change** (current L2916-2928). After the non-live return, before the TOCTOU raise:

```python
        if status in _NONLIVE_INSTANCE_STATUSES:
            return StaleNamedInstance(name=name, zone=zone, status=status)
        # NEW (#908): reconnect now REFUSES a RUNNING instance with a
        # terminal/wedged eps/phase (see reconnect_or_none), so the SAME
        # extended set must be deletable here — a skip without a matching
        # delete re-creates the #632 "already exists" create collision
        # (the documented invariant on _NONLIVE_INSTANCE_STATUSES).
        if status == "RUNNING":
            phase = _read_guest_phase(config=config, name=name, zone=zone, runner=runner)
            if phase in _ZOMBIE_GUEST_PHASES:
                return StaleNamedInstance(
                    name=name, zone=zone, status=status, guest_phase=phase
                )
        raise GcpBackendError(...)  # existing raise, message extended to note the
                                    # phase was checked and found non-terminal
```

## 11. Decision Rationale

Hyperparameters: N/A — no model training. The load-bearing DESIGN decisions, each with source:

1. **Zombie set = `_TERMINAL_GUEST_PHASES ∪ {"wedged"}`, as a NEW constant.**
   Why: `done`/`failed` is the janitor's proven zombie signature (Source: gcp.py L2581-2586, #634); `wedged` is written only by the #669 watchdog immediately pre-shutdown (Source: render_startup_script L1604-1610) — a RUNNING+wedged VM is a poweroff that failed to land, never healthy work, so reconnecting to it or colliding with its name is always wrong. A new constant (not editing `_TERMINAL_GUEST_PHASES`) keeps the janitor's reap behavior byte-unchanged (scope-minimality; the janitor's `wedged` handling belongs to the open #667 follow-up).
2. **Probe-failure semantics = raise `GcpProbeError` (both functions).**
   Why: matches the functions' existing LIST-probe contract verbatim (Source: gcp.py L2749-2756, L2876-2880; incident #535 — "couldn't ask must never read as no live instance"). Fail-open-to-reconnect would resurrect the #763 silent no-op under flaky guest-attr reads; fail-closed-to-refuse could route toward deleting a healthy VM (the asymmetry the task brief flags). Raising does neither: no create, no delete, no silent reconnect — a typed, retriable launch failure. The janitor's softer fall-through-to-age (L3347-3359) is right for an unattended cron but wrong here: launch has a caller who can retry.
3. **Matched-set change in `_stale_named_instance_or_none` (the central decision).**
   Why: the in-code invariant at L2715-2724 says the reconnect skip set and the pre-launch delete set MUST stay identical or the create collides with `resource ... already exists` (Source: incident #632). A reconnect refusal alone would convert #763's silent no-op into a hard `GcpBackendError` at the stale probe — louder, but not self-healing. The delete stays phase-guarded and re-probed locally (never trusts the earlier reconnect read), preserving the never-delete-a-possibly-live-instance contract for every other status.
4. **RUNNING-only phase gate.**
   Why: mirrors the janitor's `should_probe_phase` gate (Source: gcp.py L3342-3346); `STOPPING` is a transient teardown state whose refusal would dead-end in the stale probe's live-status raise (R5 documents the accepted residual).
5. **`finalize --skip-confirm-artifacts` as the SKILL.md teardown verb (not raw gcloud delete).**
   Why: finalize retires the handle sidecar to `<name>.finalized` (Source: dispatch_issue.py L1411-1416); a raw delete strands the sidecar for the next launch. `--skip-confirm-artifacts` exists precisely for runs halting before their declared final artifacts exist (Source: dispatch_issue.py L1390; exit-3 contract L58).
