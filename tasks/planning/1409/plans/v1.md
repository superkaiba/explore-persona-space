**Mechanism decisions embedded in the clause (per the design brief, decided):**
- **Enumeration recipe:** piggyback on the #1349 consumer grep, widened to the four greppable gate shapes (`assert `, `raise `, `if len(`, `< <threshold>` guarding a skip/continue/raise), scoped to "the code the phase executes" — the entrypoint + the modules it imports on the smoke's data path, which for reused code composes with the artifact-reuse (i)/(k) inspections already mandated at plan time. Bounded by construction: not a repo-wide sweep.
- **Demonstration mechanism:** a deliberate degenerate-input probe at UNIT level (call the gate's enclosing function directly on a tripping input) — this is the reconciliation with #1349: the probe runs OUTSIDE the main smoke leg, so the main leg still passes with floors satisfied (resize-up untouched), while the gate branch is proven to execute with its DESIGNED handling. An expected loud raise counts as probe PASS; a crash from any other line is a caught bug. Third option: an explicit per-gate `production-only — <reason>` declaration.
- **Recording surface:** a `data gates exercised:` line inside each phase's `### <phase-name>` sub-section under `## Smoke run` — parallel to #1384's `arm classes covered:` line, same MISSING-line-reads-as-forgotten convention (`none found` when the grep is empty). Deliberately NOT the `epm:smoke-architecture-check` `notes:` — that marker is the item-5 pre-flight ARCHITECTURE attestation; gate-exercise evidence is smoke-RUN evidence, and keeping it out of the marker schema avoids a `workflow.yaml` schema change + `--emit-tables` regen, keeping the diff single-file (the #1384 precedent, vs #1349 which HAD to touch the schema because it changed verdict semantics; this duty does not — verdict vocabulary `PASS_UNIFIED`/`PASS_CANARY`/`FAIL_NO_CANARY` is byte-untouched).
