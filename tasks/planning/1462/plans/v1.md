## Design

**Edit 1 — gotchas.md, append a new bullet immediately AFTER the current last entry (L324, the `pgrep -f`/`pkill -f` self-match family bullet):**

> - **SSH-remote ownership probes self-match their own remote argv — bracket one pattern character (`pgrep -f '[d]istinctive'`) by default.** The self-match class above extends to OWNERSHIP probes run over SSH: `ssh <host> "pgrep -af '<distinctive invocation>'"` re-materializes the pattern text in the remote shell's argv, so the probe phantom-matches itself and reads "live owner" against nothing (#1335, 2026-07-16: a phantom match nearly blocked a healthy relaunch decision; the round's later probes all shipped bracketed — `issue1335_ru[n].sh`, `issue1335_fit[.]py`). The `[.]`-bracket idiom (`.claude/rules/crash-fix-rounds.md` § Kill-before-relaunch step 1) is the DEFAULT pattern shape for EVERY ownership/liveness/kill `pgrep -f`/`pkill -f`, local or remote — the bracketed regex matches the target's cmdline but not the literal bracket text in the probe's own; `grep -v $$` does NOT protect the remote shape (the false match is the sshd-spawned shell, not your `$$`).

**Edit 2 — gotchas.md, insert AFTER L240 (`- **Lazy imports inside smoke-skipped branches...`), BEFORE L241 (`- **Smoke-root rebinding...`):**

> - **Inline-stdin helper calls in dispatch scripts (`uv run python - <<EOF` / `python -c` inside a `.sh`) drift from the helper's live signature — smoke-import AND signature-probe them pre-launch.** The AST arity sweep above sees only the driver `.py`; a helper call embedded in a shell heredoc/`-c` string is invisible to it and fires ONLY when that phase runs on the pod (#1310, 2026-07-16: the post-fits p5_upload heredoc called `list_hf_files_under_path()` without its leading `HfApi()` positional — `TypeError: missing 1 required positional argument: 'path'`, rc=1 AFTER all science phases completed, costing a GCE cycle). Pre-launch, for each helper an inline snippet calls, run a 1-line probe — `uv run python -c "from explore_persona_space.orchestrate.hub import list_hf_files_under_path as f; import inspect; print(inspect.signature(f))"` — and check the snippet's call binds (a bare smoke-import catches renames but NOT arity).

**Edit 3 — gotchas.md, insert immediately AFTER Edit 2's bullet:**

> - **Launcher CLI-arg probe: run the worker's `--help` (or a ~5 s `timeout`-bounded foreground arg-parse of the COMPOSED invocation) before detaching — a missing required flag dies at argparse in seconds but only surfaces at the next poll.** A detached workload cmd that omits a required mode flag exits before any work (#1434, 2026-07-16: the first datagen launch died in seconds — the worker requires `--smoke|--full` and the plan's workload command carried neither; the `--full` relaunch succeeded, no state mutated). The probe completes the cheap pre-detach family: smoke-import → signature-probe (previous entry) → arg-parse probe → mock-seam smoke.

**Edit 4 — pod-side-reporting.md § Pid-file launch contract, insert as new item `1b.` between item 1 (ends "...launch-contract violation.", L229) and item 2 (L230). Numbered `1b.` deliberately — external citations of "requirement 1" (e.g. workflow_lint.py docstrings) must not shift:**

> 1b. **Rotate the phase log at every relaunch BEFORE re-arming any pattern-matching poller.** A relaunch that appends to (or re-points at) the predecessor's log leaves the FIRST run's failure/completion lines in the very file a re-armed `grep`-class watcher scans — the watcher false-fires on the OLD line and mis-verdicts the healthy new run (#952 divtrain round, 2026-07-16: the re-armed poller matched the first driver's old failure line in the shared un-rotated `/workspace/logs/issue-952-divtrain.log`). Rotate in the SAME command chain as the relaunch (`mv <log> <log>.pre-<ts>`, or launch into a fresh timestamped log and re-point the watcher), exactly as item 1 rewrites the pid file — an un-rotated log under a pattern poller is the log-side twin of the stale-pid-file violation.

**Edit 5 — crash-fix-rounds.md, § "Kill-before-relaunch + `timeout`-bounded smokes", append a final paragraph AFTER the "Step 9c test-verdict gate runs..." line, BEFORE `### Crash-fix rounds: scope guard`:**

> **Per-leg out-roots for regime-keyed drivers.** When one dispatch runs a smoke leg AND a production leg of a driver whose resume state is keyed on the run REGIME (`--smoke`/`--full`, eval limits, ladder rung, a `--method`-class flag), give EACH leg its OWN out-root: a shared explicit `--out-root` leaves the smoke leg's regime in the resume state and the production leg fail-louds on it (#1333 cf2, 2026-07-16: the FULL leg died exit=1 at `_check_regime` — "out_root holds a run under a DIFFERENT regime" — the explicit shared `--out-root` had overridden the driver's own smoke-root rebinding). The regime refusal is CORRECT fail-loud behavior; the fix is per-leg roots at dispatch time, never weakening the check (driver-side mechanism: `.claude/rules/gotchas.md` "Smoke-root rebinding" entry).
