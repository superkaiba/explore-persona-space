# Plan — issue #584 (kind: infra): port the #534 distinct-`lora_int_id` fix + source-manifest guard to main

## 0.0 TL;DR

- **What I'll do:** Move a bug fix that currently lives only on two side branches into the main codebase. The bug: when one evaluation run scores several training checkpoints in a row, the inference engine quietly keeps serving the first checkpoint's weights for all of them, so every later measurement is wrong. The fix gives each checkpoint its own cache slot, plus a loud cross-check that compares two independent reads of the same checkpoint and crashes if they disagree.
- **What I expect:** A clean, mechanical port. I checked every file by hand: the fix's changes land in a region of the code that main and the branch share verbatim, so the dreaded conflict with main's newer instrumentation never actually materializes. A new test will prove the old broken pattern can't come back.
- **What would change my mind:** If, after porting, the file differs from the version a sibling branch already reconciled in any way I can't account for — that means one of the two reconciles mishandled the overlap, and I'd stop and dig before merging.

## 5. Regression test design (ask 2) — `tests/test_i584_lora_int_id_distinct.py`

**Chosen: AST source-contract test + the ported runtime guard as the behavioral layer.** Follows the house CPU-only incident-documented pattern (`tests/test_marker_slot_contract.py`) and per-issue naming (`test_i<N>_*`).

```python
"""#584 regression — multi-checkpoint trajectory eval must use distinct lora_int_id.

Pins the #534 round-1 incident at the source level: vLLM caches LoRA adapters
strictly by lora_int_id (LRUCacheWorkerLoRAManager.add_adapter "just touches"
an already-seen id — lora_path never re-read), so a constant id inside the
checkpoint loop silently serves the FIRST-loaded adapter at every fraction.
Static layer (this file): the LoRARequest construction inside
run_trajectory_eval must not pass a literal lora_int_id. Runtime layer
(ported with the fix): eval_guard.assert_source_delta_g_matches_manifest
(tests/test_i534_source_manifest_guard.py). No GPU, no vllm import.
"""
import ast
from pathlib import Path

EVAL_TRAJECTORY = (Path(__file__).resolve().parent.parent
    / "src/explore_persona_space/experiments/contrastive_neg_geometry_472/eval_trajectory.py")

OLD_BUGGY_SNIPPET = '''
def run_trajectory_eval(checkpoint_specs):
    for spec in checkpoint_specs:
        label = "x"; adapter_path = spec["adapter_path"]
        lora_req = LoRARequest(lora_name=label, lora_int_id=1, lora_path=adapter_path)
'''   # verbatim shape of pre-#584 main (eval_trajectory.py:425)

def _lora_request_calls(source: str) -> list[ast.Call]:
    tree = ast.parse(source)
    fn = next(n for n in ast.walk(tree)
              if isinstance(n, ast.FunctionDef) and n.name == "run_trajectory_eval")
    return [n for n in ast.walk(fn)
            if isinstance(n, ast.Call) and isinstance(n.func, ast.Name)
            and n.func.id == "LoRARequest"]

def _constant_lora_int_id_lines(source: str) -> list[int]:
    return [c.lineno for c in _lora_request_calls(source) for kw in c.keywords
            if kw.arg == "lora_int_id" and isinstance(kw.value, ast.Constant)]

def test_checker_flags_the_old_constant_id_construction():
    assert _constant_lora_int_id_lines(OLD_BUGGY_SNIPPET)   # self-validation

def test_live_rig_constructs_non_constant_lora_int_id():
    assert _constant_lora_int_id_lines(EVAL_TRAJECTORY.read_text()) == []

def test_live_rig_still_constructs_a_lora_request():
    # anti-rot: the contract must not pass vacuously after a rename/refactor
    assert len(_lora_request_calls(EVAL_TRAJECTORY.read_text())) >= 1
```

**FAILS-on-old / PASSES-on-fixed, demonstrated mechanically:** test 2 runs in Step 1 against pre-port main (FAILS: line 425 is a Constant) and in Step 3 post-port (PASSES: `ck_i` is a Name). Test 1 keeps the checker honest permanently; test 3 blocks the rename-evasion false-pass.

**Alternative considered and rejected — fake-vLLM behavioral test:** `run_trajectory_eval` imports vLLM function-locally (lines 393–395), so faking needs `sys.modules` injection plus realistic fakes for `SamplingParams`, `RequestOutput.outputs[].text`, `prompt_logprobs`, a tokenizer, AND on-disk adapter dirs (adapter_config.json + safetensors to satisfy the B-matrix and gauge-free guards) — a ~200-line fake that re-implements half the rig and breaks on internal refactors. Decisively: the defect lives in vLLM's LRU cache semantics, which a fake cannot reproduce — a fake encoding "id reuse ⇒ stale" tests the fake, not vLLM. **Flip condition:** if the construction moves into a small pure helper, replace the AST test with a direct unit test on it. **Accepted residual:** a non-literal loop-invariant id (`x = 1` outside the loop) evades the static check; the ported runtime manifest guard is the behavioral net for that whole class (its 7 tests pin the clauses with the real incident numbers: expectations {0.25: 0.033, 0.50: 0.324, 0.75: 2.204, 1.00: 6.277} vs broken reads 0.00–0.07).
