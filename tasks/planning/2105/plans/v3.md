# Plan v3 — #2105 workflow-fix: triage window boundary opens at post time, hiding enumerate-to-post seam markers

## Requirement

Close the enumerate-to-post seam in the pre-dispatch external-marker triage window. `task_workflow.triage_candidates_since_last_dispatch` opens the candidate window strictly AFTER the most recent duty-bound record (compute-launch marker, or any event whose note carries `external-markers triaged:`). The triage line is posted at breadcrumb-post time T1, but enumeration ran at T0 < T1 — any external marker landing in (T0, T1) was never enumerated at T0 and sits behind the boundary at every later call, so no session ever triages it.

Incident grounding (#2054, 2026-08-05): user-directive marker v91 ("make sure training is at least 5000 for each setting") landed 53 s before the r11 breadcrumb post; invisible to rounds r11–r14; caught only by a manual events re-read (v98 forensics), costing a 4-round directive miss + a triage-correction round (v108). The SKILL.md accepted-residuals clause currently names this seam as accepted; this task upgrades it to fixed (per the auto-filed candidate, confidence: high).

## Acceptance criteria

1. **Seam closure (regression test, #2054 v91 replay):** a marker whose ts lies strictly between a triage record's recorded enumeration boundary and the record's own ts IS returned by the next `triage_candidates_since_last_dispatch` call when the record carries a `(boundary=<ts>)` token.
2. **Legacy compat (byte-identical):** a triage line WITHOUT the token parses to today's behavior exactly — all 28 existing tests in `tests/test_pre_dispatch_triage.py` pass UNMODIFIED.
3. **Fail-soft:** a malformed / unparseable `boundary=` value falls back to today's post-position boundary.
4. **Never-shrink:** the reopened window can never start LATER than today's (structurally guaranteed: the scan-back starts at the record index − 1, so the window always contains at least everything today's window contains). A bogus-future recorded ts degrades to today's window, never a narrower one.
5. **Composer side:** the SKILL.md canonical enumerator snippet prints the boundary value mechanically; the triage-line format spec documents the token; the accepted-residuals clause is narrowed (the enumerate-to-post seam residual is replaced by the two residuals that remain: same-second ties, and legacy lines without the token).
6. **Hygiene:** ruff clean on touched files; `workflow_lint.py --check-asks` passes; Step 9c touched-scope gate green at review time.

## Method delta (what is genuinely new vs reused)

- NEW: an optional `(boundary=<ts>)` token in the triage-record line + its parser + the window-reopen logic in the enumerator + a tiny composer-side helper. Everything else (window filter `_triage_window_candidates`, ts parsing `_parse_ts_str`/`_stage_event_ts`, the duty text structure) is REUSED unchanged.
- DELIBERATE SCOPE CUT — observer unchanged: the #967 post-hoc observer (`audit_dispatch_triage` and its `boundary_idx` pre-record windows) keeps its current semantics. Its `none-with-candidates` class already absorbs record-adjacent candidates via `grace_s` (the observer explicitly names the seam an accepted residual and is flag-only / info-tier); rewiring its historical-window boundaries to parse tokens would churn watcher behavior with no incident-grounded gain. Recorded here so the critic and any follow-up can see the decision.

## Design + concrete diffs

### 1. `src/explore_persona_space/task_workflow.py`

(a) New compiled token regex + parser, colocated with `TRIAGE_LINE_PREFIX` (~L2762):

```python
# The optional enumeration-boundary token a triage-record line may carry
# (#2105): "external-markers triaged: ... (boundary=<ts>)". <ts> is the ts
# of the LAST event the enumerating session read (see
# triage_enumeration_boundary). Legacy lines without the token keep the
# post-position boundary exactly (fail-toward-today).
TRIAGE_BOUNDARY_TOKEN_RE = re.compile(r"\(boundary=([^\s)]+)\)")


def parse_triage_boundary_ts(note: str) -> "datetime | None":
    """Parse the optional ``(boundary=<ts>)`` token from a triage-record
    note. ``None`` when the note is not a triage record, carries no token,
    or the token's ts is unparseable (fail-soft — legacy behavior)."""
    if TRIAGE_LINE_PREFIX not in note:
        return None
    m = TRIAGE_BOUNDARY_TOKEN_RE.search(note)
    if m is None:
        return None
    return _parse_ts_str(m.group(1))


def triage_enumeration_boundary(events: list[dict]) -> str:
    """The ``boundary=`` value an enumerating session stamps into its triage
    line: the ts of the LAST event in ``events`` at enumeration time (""
    when the list is empty — composers omit the token then)."""
    return (events[-1].get("ts", "") or "") if events else ""
```

(b) `triage_candidates_since_last_dispatch` — reopen the window from the recorded enumeration point (boundary matcher, ~L2839):

```python
    boundary = -1
    for idx in range(len(events) - 1, -1, -1):
        event = events[idx]
        note = event.get("note", "") or ""
        if event.get("kind", "") in launch_kinds or TRIAGE_LINE_PREFIX in note:
            boundary = idx
            recorded = parse_triage_boundary_ts(note)
            if recorded is not None:
                # #2105: reopen the enumerate-to-post seam — the window
                # starts after the LAST event the record's enumerator
                # actually read (highest j < idx with parseable
                # ts <= recorded), not after the record's own post
                # position. Events with unparseable ts stay IN the window
                # (fail-toward-triage); no match -> whole list
                # (over-enumeration is safe). Structurally never-shrink:
                # the scan starts at idx - 1, so the reopened window is a
                # superset of today's events[idx + 1:].
                boundary = -1
                for j in range(idx - 1, -1, -1):
                    ts_j = _stage_event_ts(events[j])
                    if ts_j is not None and ts_j <= recorded:
                        boundary = j
                        break
            break
    return _triage_window_candidates(
        events[boundary + 1 :], exempt_kinds=exempt_kinds, machine_by=machine_by
    )
```

Docstring of the function gains one paragraph documenting the token semantics + the two named residuals (same-second tie behind a `<=` boundary; legacy lines keep the old seam).

Note on re-inclusion safety: the reopened window contains the triage record itself, the stage-dispatch breadcrumb, and machine markers — ALL already excluded by `_triage_window_candidates` (triage-line notes, breadcrumb-shaped notes, exempt kinds, machine `by`), so reopening cannot re-surface bookkeeping rows. Events at ts <= recorded were enumerated by the prior run and stay outside the window (`<=` per the filed sketch), so already-triaged advisories are not re-enumerated.
