## §0.0 TL;DR

Two-part fix to `scripts/verify_task_body.py`. **(i)** Replace `.lower()` with
`.casefold()` at every regex-`group()` token normalization (26 direct sites +
1 paired indirect site). **(ii)** Make the two crash-class CONSUMERS total —
`_NUMBER_WORDS` at `:16820` and `_BEAT_WORD_TO_KIND` at `:10635` — so an
`IGNORECASE`-matched token that no string normalization can map onto an ASCII
key registers no claim instead of crashing the entire verifier.

Part (ii) is load-bearing. `re`'s `IGNORECASE` fold and `str.casefold()` are
DIFFERENT normalizations and neither contains the other. An exhaustive scan of
all 1,114,112 codepoints (§2) closes the class: **exactly two** characters are
matched by `re.I` against an ASCII letter while `.casefold()` fails to produce
that letter — **U+0130 `İ`** and **U+0131 `ı`** — so a casefold-only fix leaves
the Goal's "cannot crash the whole verifier" claim FALSE at both crash sites,
and a per-character fix keyed on one of them still crashes on the other.

**Change my mind:** if `sİx`/`sıx same-issue follow-up rounds` and
`one poİnt/poınt per seed` all verify without raising after a casefold-only
change, part (ii) is unnecessary and the plan is over-built. (Measured: all
four still raise.) Conversely, if making the two lookups total changes any
verdict for a token that DOES resolve, the change is not conservative and must

## §2 Background — the mechanism, and the closed divergence class

**Plan v2 asserted that `re.IGNORECASE` performs full Unicode case folding.
That is false**, and the error was inherited from the reference fix's own
comment (§ Prior art). `re` performs SIMPLE case folding plus a table of
extended pairs; `str.casefold()` performs FULL folding.

**Exhaustive enumeration** over every codepoint in `range(0x110000)`, asking
"does `re.IGNORECASE` match this character against some ASCII letter, and if
so does `.casefold()` produce that letter?":

| Codepoint | Name | `re.I` folds to | `.lower()` | `.casefold()` | Verdict |
|---|---|---|---|---|---|
| U+017F | LATIN SMALL LETTER LONG S | `s` | `ſ` (unchanged) | `s` | **casefold FIXES** |
| U+0130 | LATIN CAPITAL LETTER I WITH DOT ABOVE | `i` (1 ch) | `i̇` (2 ch) | `i̇` (2 ch) | **neither fixes** |
| U+0131 | LATIN SMALL LETTER DOTLESS I | `i` | `ı` (unchanged) | `ı` (unchanged) | **neither fixes** |

That table is COMPLETE, not illustrative: the divergence class (matched by
`re.I`, not normalized by `.casefold()`) has **exactly 2 members**, and the
set `.lower()` misses but `.casefold()` fixes has **exactly 1 member**, over
the whole codepoint space.

Two structural facts follow:

1. **`.casefold()` is a strict improvement** — it closes `ſ`, the confirmed
   reachable crash. Part (i) is correct and stays. Its realized crash-class
   value at ASCII-alternation sites is precisely that one character; the rest
   of the sweep's justification is cross-site consistency and making the
   invariant ratchetable (§3.2 reasons 2-3), NOT a large fixed-character set.
2. **`.casefold()` is not sufficient, and no per-character fix is either.**
   For `İ`/`ı` the regex fold and both string folds disagree, so a token the
   regex MATCHED still misses an ASCII-keyed dict. Only a total lookup at the
   consumer closes it — and because the class has two independent members, a
   fix keyed on either one alone still crashes on the other. Totality covers
   both plus any future Unicode addition.

Characters excluded, with reasons (so the exclusions are auditable):
`ß` U+00DF and `ﬁ` U+FB01 fold FULL to multi-char ASCII but `re` does NOT match
them against those expansions (`re.fullmatch("ss", "ß", re.I)` → False), so
they can never be captured by an ASCII alternation. `K` U+212A already
normalizes to `k` under both folds. **`µ` U+00B5 is out of class** — it folds
to GREEK SMALL LETTER MU (U+03BC), which is not an ASCII letter, so this file's
ASCII-only alternations cannot capture it. (Plan v3's §2 table listed `µ` as
in-class; that was wrong and is corrected here.) `µ` survives only as the
weaker observation below.

**Not hypothetical.** Scanning all 2,213 live `tasks/**/body.md` files found one
already carrying a full-folding character (`tasks/completed/1967/body.md`, `µ`
U+00B5). Not in a triggering position and, per the exclusion above, not
capturable — but it establishes that such characters reach committed bodies.
`İ`/`ı` are ordinary Turkish-alphabet letters, so a body written or pasted
through a Turkish-locale tool is a realistic vector, not merely adversarial.

### §3.2 Part (i) — the casefold sweep: convert all 26, plus the paired indirect

Convert all 26 direct `.group(...).lower()` sites, a deliberate superset of the
Goal's literal "IGNORECASE + dict-key/equality/`int()`" wording:

1. **Behavior-preserving.** `.lower()` and `.casefold()` are identical on
   ASCII, so a case-SENSITIVE regex over ASCII-only alternations sees no
   change; converting it is a behavioral no-op and a consistency win.
2. **It makes the invariant ratchetable.** With zero `.group(...).lower()`
   remaining, the AST test of §3.5 prevents class reintroduction. A partial
   sweep leaves the ratchet unstatable.
3. **The task body asks for it** — scope item 2 names the `_THIS_REPO_SLUG`
   comparisons as "the same class" and directs the sweep to include them.

Each site is still classified individually (§3.1, reproduced per-site in the
implementer report with each regex's `IGNORECASE` flag read off the **compiled
pattern object**, not the source text) so review can audit the reasoning.

### §3.3 Part (ii) — make the two crash-class consumers total

- **`:16820`** — replace `n = _NUMBER_WORDS.get(word) or int(word)` with:
  resolve `_NUMBER_WORDS.get(word)`; on a miss, `int(word)` **only when
  `word.isdecimal()`**; otherwise `continue` (the match contributes no count).
- **`:10635`** — replace the bare `_BEAT_WORD_TO_KIND[...]` subscript with
  `.get(...)`, skipping the match on a miss (no claim registered).

**Why `isdecimal()` and not `isdigit()`.** `str.isdecimal()` is exactly Unicode
category Nd — verified exhaustively as the same set `\d` matches in a str
pattern and the same set `int()` accepts (all 660 Nd codepoints are `\d`-matched
and `int()`-parseable; 4,900 sampled two-char mixed-script pairs, 0 rejects).
`str.isdigit()` is broader and admits superscripts (`"²".isdigit()` → True while
`int("²")` raises). **Calibrated claim:** at these two sites the `isdigit()`
hole is **LATENT, not reachable** — `²` is not `\d`-matched, so the alternation
can never capture it (v3 overstated this as "reintroduces the very crash at a
lower rate"; corrected here). `isdecimal()` is still the right choice: it is the
tighter predicate and it stays correct if the capture class is ever widened.
The same correction applies to the reference fix's `isdigit()` guard — a latent
hole, not a live crash — and has been sent as a follow-up correction to #2279 so
that session does not chase a phantom reproduction.

**This is not body scope item 3.** Item 3 proposed a DRIVER-level `try/except`
around each check — a blanket catch converting any future verifier defect into a
silently-degraded PASS. Part (ii) is a site-level TOTAL LOOKUP: no exception is
caught, no error is swallowed, and an unresolvable token gets the same
disposition as a token that never matched — no claim, no count contribution.
Both affected checks are WARN-only and under-count-conservative by design, so
the skip direction is the one they already document. Fail-closed at the site,
fail-fast preserved everywhere else.

### §3.5 The invariant and its ratchet

Post-sweep invariant: **zero `<match>.group(...).lower()` expressions in
`scripts/verify_task_body.py`.** Pinned by an AST test, not a text grep — the
AST form is immune to line breaks, whitespace, and comments (a
`.group(\n "num"\n).lower()` split across lines evades a single-line regex and
is caught here).

Detection: walk the module AST for `Call(func=Attribute(attr="lower"),
args=[], keywords=[])` whose `func.value` is itself
`Call(func=Attribute(attr="group"))`. On failure, report every file:line plus
the offending source segment.

**Named residual (disclosed, not covered):** the ratchet sees only the DIRECT
chain. An indirect site — assign from `group()`, `.lower()` later — evades it;
§4 step 2 enumerates those by one-hop local dataflow (that pass is what found
`:3503`), but no static ratchet guards a future one. The code-review lens is the
catching arm, as for the sibling classes in
`.claude/rules/smoke-blind-spots.md`.

   §3.2's no-op claim is false — halt, name the site and the verdict, and

3. **A converted site feeds a display string.** Leave it at `.lower()`, add the
   narrow commented ratchet allowlist entry, and REPORT it. Silent conversion
   of a display site is the banned shape.
4. **Part (ii) changes behavior on a RESOLVABLE token.** If making either
   lookup total alters any outcome for a token resolving to a number word or a
   decimal, the change is not conservative — halt and report; do not adjust the
   test to match.
5. **The AST ratchet cannot reach zero** for a reason not anticipated in §3.5 —
   report the site and the reason; never weaken the detection predicate to make
   it pass.
6. **A third divergence-class member surfaces.** §2's enumeration says the class
   is closed at two members on this interpreter. If a third appears (a
   different Python/Unicode version), halt and report rather than adding ad-hoc
   per-character handling — part (ii)'s totality should already absorb it, so a
   surprise here means the totality is not where the plan thinks it is.
