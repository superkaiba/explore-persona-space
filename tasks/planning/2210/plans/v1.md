> - **Parallel lm-eval fan-out races the library's own nltk download — pre-stage `punkt_tab` ONCE before forking (#2203).** A multi-process lm-eval fan-out (one shard per GPU, shared container/filesystem) lets each shard trigger lm-eval's library-level `nltk.download('punkt_tab')` (IFEval dataset prep) into the shared `/root/nltk_data` on first use; concurrent downloads collide (one shard removes `punkt_tab.zip` mid-unzip of another) and the losers die BEFORE any arm write with `[nltk_data] [Errno 2] No such file or directory: '.../punkt_tab.zip'` followed by `LookupError: Resource punkt_tab not found`, while sibling shards complete normally — SOME-shards-fail looks flaky/nondeterministic but is structural. The nltk call lives in LIBRARY code (lm-eval IFEval utils), not repo scripts, so the fix layer is the LAUNCHER/bootstrap, never experiment code: stage the resource once, single-threaded, as a launcher gate BEFORE the fan-out — `nltk.data.find('tokenizers/punkt_tab')`, on LookupError `nltk.download('punkt_tab')`, then re-`find()` — and fail the launcher LOUD on rc!=0 (the #2203 retry launcher's `[phase=stage_nltk] ok` gate; validated 2026-08-09: all 4 shards passed dataset prep, zero LookupError). Same stage-once-before-fan-out discipline as HF artifact pre-staging; generalizes to ANY library that lazily downloads a shared resource on first use (nltk, spacy models, tiktoken encodings).
