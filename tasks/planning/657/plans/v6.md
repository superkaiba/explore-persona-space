## Goal (canonical — verbatim)

Test whether a persona's activation-space alignment to a behavior's linear direction predicts, across multiple behaviors (sycophancy, refusal, marker, EM), both (a) that persona's base rate for the behavior and (b) where an implanted behavior leaks across held-out personas, and whether this alignment geometry beats the base behavioral prior baseline that the #518/#545/#605 predictor line found unbeatable, reusing existing persona vectors, behavior directions, and trained adapters wherever possible.

### 0.0 TL;DR (plain English)

- **What I'll run:** For each persona I already have a geometry number: how much that persona "points toward" a behavior like sycophancy or refusal inside the model. I check whether that number predicts two things — how often the persona shows the behavior on its own, and how badly the behavior spills onto it when I implant the behavior into a *different* persona. I do this for several behaviors, reusing past measurements, so almost no new GPU. The one change from my last attempt fixes why it stalled: I stopped trying to read the "refusal direction" and the "misalignment direction" off generic chit-chat questions, because the model never refuses or misbehaves on those, so there was nothing to measure. I now read the refusal direction the way the field actually does it, from real harmful-vs-harmless requests; and for misalignment I reuse a direction I already measured from a model I trained to be misaligned, because the raw text I'd need to rebuild it from scratch was thrown away.
- **What I expect:** The geometry will track a persona's *own* base rate for a behavior (this already worked for sycophancy). Whether it predicts *spillover* better than the dead-simple "personas already prone to the behavior catch more of it" baseline is the real open question — six past experiments say that baseline is very hard to beat, so I'm betting the geometry mostly restates it and adds little once I subtract the baseline out.
- **What would change my mind:** If the geometry still predicts where a behavior spills *after* I remove everything the simple base-rate baseline already explains — on personas the geometry never saw during fitting — that would be the first internal-state signal that genuinely beats the baseline, and I'd want to understand why this geometry works where every distance metric before it failed.

## 1. Goal

(Copied verbatim above.) In one paragraph: #623 showed that a persona vector's cosine to the sycophancy trait direction predicts that persona's *base* sycophancy rate (ρ=0.73, n=35). This experiment asks the two questions #623 left open — does that alignment→base-rate relationship generalize beyond sycophancy, and does the same alignment predict *where an implanted behavior leaks* across held-out personas — and runs the head-to-head the whole predictor line cares about: does alignment beat the base behavioral prior (`bystander_base_rate`) on held-out leakage prediction, the bar that #518/#545/#605/#603/#649 found no base-model geometry could clear. The payoff is high because the design is almost entirely reuse: the leakage cells, the base rates, the persona-vector bank, and the trait-extraction recipe all already exist.

**Pivot note (plan v4 — behavior-direction recipe).** Plan v3's behavior-direction recipe (extract ALL four directions via the #623 generic Persona-Vectors recipe) is self-defeating for refusal and EM: those behaviors are not expressible on generic auto-generated questions, so the recipe produces a direction that does not causally steer the behavior (launch #3 K2 HALT, refusal `effect=0.00` at all 4 layers × 3 alphas). v4 fixed the behavior-direction extraction recipe — content-behaviors that need *content-triggered* probes (refusal, EM) get a data-grounded recipe; sycophancy and marker keep the #623 recipe. The whole downstream analysis (predictor construction, doubly-partialled partial-ρ, ΔR², bootstrap, M-Stats1 reliability band, M-Alts1 prior_centroid_projection, M-Alts2 EM exclusion) is **unchanged from v3**.

**Fact-correction (plan v5 — surgical, single substantive change vs v4).** v4's PRIMARY EM recipe was a diff-in-means over the #518 judged-misaligned-vs-aligned generations. **That recipe is unrunnable as written:** the #518 `judged_em.json` files store only aggregate per-cell rates (`per_cell` = `{source, bystander, trained_rate, base_rate, delta, n_rollouts_after_coherence_filter, ...}`) — there is NO per-rollout completion text paired with a per-generation misaligned/aligned label, so the generations cannot be split into the misaligned vs aligned pools the diff-mean needs (HF-verified 2026-06-18 against `issue518_leakage_prediction/raw_completions/em/villain/seed_42/judged_em.json`). Because EM is already SECONDARY (M-Alts2), this does not touch primary H3. EM is now a trained-shift read (folds the implant in, not a pure base-model read) — documented as the second deviation alongside the marker §11 §521-shift fallback path. **Everything else is verbatim from v4** (refusal Arditi diff-mean, the K2-gate-retention + per-behavior-fallback policy, the whole Phase-2 analysis stack, the GPU budget, all confirmed §11 entries).

**Surgical revise (plan v6 — Phase-3 union, 3 fix items, NO design change vs v5).** Three surgical fixes from the Phase-2 reconciler-Must-Fix + 2 consistency-WARNs, no methodology change: **(1) Marker primary-H3 demotion gate (M-Alts3, NEW):** marker is in the primary H3 set ONLY when its direction is the pure #623 base-model affordance read that passed K2; if marker falls back to the #521 trained-shift, marker is demoted to SECONDARY for that run (mirroring the EM trained-shift demotion, M-Alts2). ## 2. Prior Work

**Closest prior formalizations (external):**
- **Persona Vectors** (Chen, Arditi, Sleight, Evans, Lindsey 2025, arXiv 2507.21509). Extracts trait directions from a natural-language description (the recipe #623 reused) and shows finetuning-induced personality change "is strongly correlated with shifts along the relevant persona vectors." This experiment is the **cross-persona-leakage** extension of that finding, using the project's open-weights advantage (Qwen-2.5-7B): the paper predicts *self* trait change; we predict *off-diagonal leakage landing* across held-out personas, and bake the geometry off against the base prior — a comparison the paper does not run.
- **Refusal in Language Models Is Mediated by a Single Direction** (Arditi, Obeso, Syed, Paleka, Panickssery, Gurnee, Nanda 2024, arXiv 2406.11717). Refusal is a one-dimensional residual-stream subspace across 13 chat models **including Qwen 7B Chat**; the direction is extracted by **difference-in-means of harmful-vs-harmless instruction activations** at post-instruction token positions, validated by add-elicits-refusal / ablate-suppresses-refusal. This is the canonical refusal-direction recipe and the published method for *exactly* the refusal direction v4/v5/v6 extracts for refusal. NOTE: the SAME author (Arditi) co-wrote both the Persona Vectors recipe and this refusal recipe; using the refusal-specific recipe for refusal is methodologically faithful, not a foreign graft.
- **Persona Features Control Emergent Misalignment** (Wang, …, Mossing 2025, arXiv 2506.19823). SAE-based persona features causally control EM. Direction-based, but on GPT-4o internal features, not a cosine-onto-trait-direction *predictor* of cross-persona leakage. What is NEW here that none of the three settle: (a) the predictor is a *base-model* read used to forecast *where leakage lands* across personas (EM excepted — a trained-shift read, see §4), (b) it is benchmarked against the behavioral base prior, (c) it spans four behaviors on one open-weights model with reusable trained leakage panels.

**In-house:**
- **#623** (parent) — alignment→base-rate, sycophancy only, ρ=0.73 n=35. Source of the persona-vector bank + the sycophancy direction + the trait-extraction recipe. Readout choice load-bearing (last-prompt-token 0.73 vs response-avg 0.44).
- **#518** (THE baseline) — "No base-model predictor cell cleared the cross-behavior threshold (|ρ_FE|≥0.40 same-sign) on sycophancy + refusal + EM leakage panels." Its predictor zoo is the **persona-to-persona** distance family (cosine_l20, response-cosine, JS, KL) + `bystander_base_rate` + `completion_logprob`. The substrate of every leakage cell my experiment reuses (all three leakage DVs on Qwen-2.5-7B-Instruct-trained adapters — verified by the v1 fact-checker). Caveats it surfaced: refusal arm is 76% floored (power-limited); `source_resp_len_mean` (a length confound) dominates refusal/EM; the EM `delta` is a *survivor-aligned-rate* proxy because Sonnet's coherence filter discards ~85% of EM generations before the rate is computed. **Its `judged_em.json` files store only aggregate per-cell rates — no per-rollout text+label** (HF-verified, the v5 fact that retires the EM diff-mean).
- **#605** — at matched context-similarity, the base prior beats geometry for *marker* leakage standing; marker shift carries a held-out-positive signal in logit space, null in log-prob. Confirms the marker behavior also sits in the "prior beats geometry" regime, but its predictor is *context-similarity-to-source*, NOT cosine-onto-a-behavior-direction — so my lever is new for marker too.
- **#532/#541/#500/#444** — a unit's behavioral base prior repeatedly out-predicts geometric distance for leakage.
- **#521** — extracts the EM and marker training-induced activation *shifts* (trained−base) per persona at L14 on Instruct. EM shift = "one shared direction governs cross-persona EM transfer" (HIGH confidence). **v5/v6 USE #521's `on_policy_em` shift as the PRIMARY EM direction** (the EM diff-mean is unrunnable). The shift `.pt` tensors themselves were written to a pod-local path and never persisted (NOT on HF, NOT in git — only the `.manifest.json` survives), BUT the `issue_519/em_seed42` adapter they were derived from IS on HF (the manifest's `adapter_path` = `eval_results/issue_521/em_seed42/adapter`, the #519 EM-seed42 lineage), and the manifest carries the full re-extraction recipe — so the shift is cheaply re-extractable (§4 EM row, §12). The shift mixes the implant in (not a base-model read), so EM stays SECONDARY (M-Alts2).

## 3. Hypothesis

Verbatim (unchanged from v3/v4/v5):
- **H1:** behavior-direction alignment predicts base rate across ≥3 behaviors (generalizes #623 beyond sycophancy).
- **H2:** behavior-direction alignment predicts cross-persona leakage landing with held-out (out-of-sample) skill above chance.
- **H3 (the bar):** alignment beats the base behavioral prior on held-out leakage prediction. The prior won everywhere in #518/#545/#605; this is the first geometry with a real shot.
- **Competing/null:** alignment merely restates "high-prior personas leak more" and adds nothing once the base prior is partialled out. The X-vs-(X−Y) artifact (#383/#605) MUST be controlled — report alignment's marginal skill with the prior partialled out.

**Conditional primary-membership rule for the trained-shift behaviors (v6 — M-Alts3 generalizes M-Alts2).** A behavior is in the primary H3 gate set ONLY when its direction is a **pure base-model read** that passed K2. The two behaviors whose direction can be a *trained-shift* read are demoted to SECONDARY whenever the trained-shift path is taken:
- **EM** is a trained-shift read by construction (the diff-mean is unrunnable) → EM is ALWAYS secondary (M-Alts2).
- **Marker** is a pure base-model read in its PRIMARY recipe (the #623 ※-affordance contrastive pair) and is primary ONLY in that branch. If the marker affordance recipe fails K2 and marker falls back to the #521 `on_policy_marker` trained-shift, marker is **demoted to SECONDARY for that run** (M-Alts3 — same trained-shift logic that makes EM secondary). In that branch the primary H3 set shrinks to {sycophancy, refusal}.

So `primary_h3_behaviors` is run-conditional: it is `{sycophancy, refusal, marker}` when the marker affordance direction passes K2, and `{sycophancy, refusal}` when marker falls back to the #521 trained-shift (or marker is DV-(a)-only per the §7 panel-overlap gate). EM is never in the primary set.

**Falsification thresholds (pre-registered, unchanged from v3/v4/v5):**
- **H1 PASS:** raw Spearman ρ(alignment, base rate) ≥ 0.5 with 95% bootstrap CI lower bound > 0 on ≥3 of the 4 behaviors (mirrors #623's H1 threshold). The sycophancy arm is the replication anchor (must reproduce ρ≈0.73 ± CI on the syco-source bystander panel; a miss is a join/recipe bug, halt).
- **H2 PASS:** held-out LOPO Spearman ρ(alignment, leakage Δ) > 0 with 95% bootstrap CI lower bound > 0 on ≥1 behavior.
- **H3 PASS (the bar) — primary behaviors only, doubly-partialled:** `primary_h3_behaviors` = `{sycophancy, refusal, marker}` when marker's direction is the pure #623 affordance read that passed K2, else `{sycophancy, refusal}` (M-Alts3); EM is EXCLUDED from the primary gate set in every branch (M-Alts2). H3 PASS requires, on ≥1 of these PRIMARY behaviors:
  - held-out LOPO **partial-Spearman ρ(alignment, leakage Δ | [bystander_base_rate, prior_centroid_projection])** with 95% bootstrap-over-bystanders CI **lower bound > 0** (the **doubly-partialled** ρ — partial out the SCALAR base prior AND the geometry-side prior restatement; see M-Alts1), AND
  - alignment's out-of-fold incremental R² over a `[bystander_base_rate, prior_centroid_projection]`-only model (ΔR²_align-beyond-prior, grouped-CV by bystander) with CI lower bound > 0.
  - Report the singly-partialled ρ (vs `bystander_base_rate` alone) ALONGSIDE the doubly-partialled ρ. Both the doubly-partialled partial-ρ and the held-out ΔR² must clear. A positive raw ρ that collapses to a CI straddling 0 under partialling is the **competing/null** outcome (report as "restates the prior").
- **K2-gate precondition on H1/H2/H3 (the pivot adds teeth here):** a behavior's ρ is read ONLY if its extracted direction PASSES the K2 steering sanity gate (`headline_layer_effect > 0`; add-the-direction causally increases the judged behavior on the behavior-appropriate eval set). A K2-failed direction does not measure the behavior; its ρ is NOT reported as a finding (it is reported as "direction did not pass the causal sanity check — extraction failed for this behavior", §7). This is the gate launch #3 tripped; v4/v5/v6 keep the gate (it is correct) and fix the recipe so the direction can pass it.
- **Geometry-side prior control (M-Alts1):** unchanged — define `prior_centroid_projection_i = cosine(persona_vector_i, b_prior_centroid)`, `b_prior_centroid = Σ_j (base_rate_j · persona_vector_j) / Σ_j (base_rate_j)`; the doubly-partialled H3 read partials it out alongside the scalar prior. A positive H3 read that survives partialling `bystander_base_rate` BUT collapses under the doubly-partialled control is the **"geometry-side restatement of the prior"** outcome (null-with-explanation, §7).
- **EM-secondary rule (M-Alts2):** unchanged — EM clearance is reported as a SECONDARY read carrying the survivor-rate caveat (and now the trained-shift caveat). An EM-only clearance does NOT satisfy primary H3.
- **Marker trained-shift-secondary rule (M-Alts3 — NEW v6):** if marker's direction is the #521 `on_policy_marker` trained-shift (the K2-fail fallback) rather than the pure #623 affordance read, marker is reported as a SECONDARY read carrying the trained-shift caveat. A marker-fallback-only clearance does NOT satisfy primary H3 (mirrors M-Alts2 exactly). The primary H3 set then shrinks to {sycophancy, refusal}.
- **NULL (competing) outcome:** unchanged — doubly-partialled partial-ρ CI straddles 0 on all primary behaviors, OR ΔR²_align-beyond-prior ≤ 0 → "alignment adds nothing the base prior doesn't". A power-limited null (MDE-ρ exceeds the observed at n≈17) is indeterminate, not confirmation. A partial-ρ clearing 0 ONLY at the optimistic-reliability end of the band (M-Stats1) is likewise indeterminate.

### Statistical-input existence (derived inputs) + bounded-attenuation / reliability-sensitivity band (M-Stats1)   [UNCHANGED from v3/v4/v5]
The H3 partial-correlation consumes `align_i` (constructed in Phase 2 from verified persona vectors + behavior directions), `delta` and `bystander_base_rate` (verified present in the #518 cell JSONs, §12). The grouped-CV DeltaR2 consumes only these same columns — computed directly from this experiment's join.

**The partialled prior is measured with error, so the partial is attenuation-biased; a registered reliability-sensitivity band is reported alongside H3.** The partialled covariate `bystander_base_rate` is a per-bystander point scalar with NO SE and NO denominator. Partialling out a noisy `Z` UNDER-corrects, so a partial-rho that clears 0 at the observed-prior point can be inflated by the prior's measurement error. The registered FLOOR is **bounded attenuation:**
- **Bracket the prior's reliability from the per-bystander generation count.** Each `bystander_base_rate` is a judge-rate over a finite per-persona generation count (typical n~20-50; the #518 EM cells carry `n_after_coherence_filter` per bystander, e.g. accountant n=465 pre-filter / 65 post-filter). Compute the binomial/judge SE at that n and convert to a reliability range `R_low / R_expected / R_high`.
- **Report H3 under each reliability point — a 3-point sensitivity band.** Report the partial-rho AND DeltaR2_align-beyond-prior under each of `R_low / R_expected / R_high`, alongside the headline observed-prior read (R=1).
- **H3 PASS interpretation rule (indeterminate-band carveout):** a partial-rho CI that clears 0 across the WHOLE band is a **confirmed beat-the-prior PASS**. A partial-rho CI that clears 0 ONLY under the optimistic-reliability end is **INDETERMINATE**, reported as such, NOT a confirmed PASS.

**Upgrade path (no new GPU):** if per-bystander generation DENOMINATORS are recoverable by re-reading the raw #518 generation JSONs, full SIMEX/EIV disattenuation is an acceptable UPGRADE over the bounded band — but the 3-point band is the FLOOR that ships regardless. (This is the M-Stats1 input the round-2 implementer already wired — `reliability band rank-invariant no-op` fix in commit d9ce0a9a13 + B1 real EIV disattenuation, per the events log.)

## 7. Decision Gates

**No go/no-go gates — short run / pre-verified pipeline.** The only GPU step is a ~2 GPU-h extraction; the analysis is CPU-only. Wall-clock < 4h. The CPU-only end-to-end smoke (§-Smoke) + the per-direction K2 sanity gate are the kill checks, not go/no-go gates.

**Kill / halt criteria + interpretation gates (success and kill):**
- **Success criterion (H3):** held-out **doubly-partialled** partial-ρ(align, Δ | [bystander_base_rate, prior_centroid_projection]) CI lower bound > 0 AND ΔR²_align-beyond-prior CI lower bound > 0 on ≥1 **PRIMARY** behavior ∈ {sycophancy, refusal, marker}, holding across the bounded-attenuation reliability band (M-Stats1), **for a behavior whose direction PASSED K2.**
- **K2 sanity gate (the pivot's gate — per direction, NOT a HALT of the whole run):** each extracted/reused direction must produce `headline_layer_effect > 0` on its behavior-appropriate eval set. A K2-fail on refusal/marker/EM routes to the per-behavior fallback (§4 table) and, if the fallback also fails, **excludes that behavior from the bake-off and reports the K2 failure as a finding** (the recipe-doesn't-extract-this-behavior result). Sycophancy is the join-integrity anchor (it MUST pass K2 — it's the reused #623 direction; a sycophancy K2 fail means a join/load bug → halt-and-diagnose). The other behaviors degrade gracefully. EM has no further fallback below the #521 shift (the diff-mean is unrunnable), so a #521-shift K2 fail drops EM from the secondary read. Taking the marker fallback path triggers M-Alts3 (marker → SECONDARY).
- **EM-exclusion gate (M-Alts2):** EM is NOT in the primary H3 gate set. An EM-only clearance is reported as "alignment may track survivor-selection geometry / the trained-shift direction" with the survivor-rate + trained-shift caveats; it does NOT trip primary H3.
- **Marker primary-membership gate (M-Alts3 — new):** marker is in the primary H3 set ONLY when its direction is the pure #623 base-model affordance read (K2-passed). If marker falls back to the #521 `on_policy_marker` trained-shift, marker is demoted to SECONDARY for that run (mirroring EM-M-Alts2); the primary H3 set effectively becomes {sycophancy, refusal}. A primary set narrowed below the §3 minimum still satisfies H3 if it clears doubly-partialled CI on ≥1 surviving primary behavior.
- **Phase-0 marker panel-overlap gate (NEW):** the overlap `|EVAL_PERSONAS_24 ∩ #605-marker-panel|` is computed and reported as the FIRST Phase-0 substrate deliverable. If overlap < 8, marker is demoted to DV-(a)-only (excluded from the leakage bake-off); the primary H3 set narrows to {sycophancy, refusal}, stated explicitly in the clean-result. The overlap count is a logged primary-set-membership decision (not silent).
- **Geometry-side-restatement gate (M-Alts1):** a read that survives partialling `bystander_base_rate` BUT collapses under the doubly-partialled control is reported as **"geometry-side restatement of the prior" (null-with-explanation)**, NOT a clean H3 PASS.
- **Reliability-band indeterminate gate (M-Stats1):** a partial-ρ CI clearing 0 ONLY at the optimistic-reliability end is **indeterminate**, NOT a confirmed PASS.
- **Kill / abort criterion (join-integrity halt):** if the **sycophancy DV-(a) replication anchor** fails to reproduce #623's ρ≈0.73 (bootstrap CI overlap) during the smoke, **stop and diagnose** — a join/recipe bug, not a finding.
- **Kill / null-report criterion:** if the doubly-partialled partial-ρ CI straddles 0 on all K2-passing primary behaviors OR ΔR²_align-beyond-prior ≤ 0, **report the competing/null outcome** ("alignment restates the prior"). A power-limited null (MDE-ρ > observed at n≈17) is indeterminate, never a confirmed null.
