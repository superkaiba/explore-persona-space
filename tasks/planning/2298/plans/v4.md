## Part 3 — The mechanical guard

New check `--check-lane-order-adjective` in `scripts/workflow_lint.py`.

### Reading the live head (AST, no import)

```python
LANE_ORDER_ROUTER_REL = "src/explore_persona_space/backends/router.py"
KNOWN_LANES = ("runpod", "fellows", "gcp", "nibi", "fir", "mila")

def read_default_auto_lane_head(source: str) -> str | None:
    """Head lane of DEFAULT_AUTO_LANE_ORDER, from router.py SOURCE text.

    AST-based (no import) so the check is testable against a fixture tree
    via repo_root=. EVERY `ast.Return` inside `_default_auto_lane_order`
    must be a tuple whose element 0 is a string Constant; the head is
    returned only when every such return agrees. ANY other return shape
    (a bare name, a call, a starred head, a non-str literal) yields None
    — this is a whole-function requirement, NOT a filter over the
    tuple-shaped returns: filtering would let a mixed-return refactor
    resolve a head from one branch and silently mis-grade prose written
    for the other (Methodology SF4). Returns None when the module does
    not parse, the function is absent,
    a branch's element 0 is not a string literal, or branches DISAGREE —
    callers SKIP loud on None, never crash.
    """
```

Both live branches return `("runpod", "fellows", ...)` / `("runpod",
"fellows", "gcp", ...)`, so element 0 agrees and the star-expanded tail
(`*DEFAULT_FREE_LANE_ORDER`) is never inspected. A future refactor that
builds the tuple through a variable yields `None` → loud SKIP (fail-open),
which is correct: the guard goes quiet rather than firing on a head it
cannot resolve.

### Triggers (two families)

**Family 1 — contradicting ordinal adjective.** For each `<lane>` in
`KNOWN_LANES` that is NOT the resolved head, flag `<lane>-first` /
`<lane> first`:

```python
rx = re.compile(r"\b(" + "|".join(non_head_lanes) + r")[- ]first(?![\w-])", re.I)
```

Three properties, each MEASURED rather than assumed (v2 asserted the
first one incorrectly):

- **`re.I` is load-bearing.** Without it the check misses
  `fellows-FIRST` — the exact Edit-4 hit the clarifier sweep lost.
- **The trailing `(?![\w-])` guard is required, not decorative.** v2
  claimed `\bgcp-first\b` would not match inside `gcp-first-resort`. That
  is FALSE — `\b` matches between `t` and `-`, so the bare form DOES
  match. Verified both ways; the guard fixes it. `first-resort` is live
  house vocabulary (Part 2 leg 4 audits it separately), so without the
  guard the check would fire on correct prose the day someone writes
  "gcp-first-resort".
- **An order-context co-occurrence window is required, at ±1 PHYSICAL
  LINE grain** (both critics offered it as optional; adopted, then
  re-grained in v4). A family-1 match counts only when order vocabulary —
  `auto`, `chain`, `default`, `lane order`, `precedence` — appears on the
  matched line **or either immediately adjacent physical line**.

  **The line grain is load-bearing and MEASURED, not assumed.** Every file
  in this scan set is hard-wrapped markdown, so a sentence routinely spans
  two physical lines and the order vocabulary lands on the neighbor.
  Measured over the shipped scan set: bare regex **4** hits; same-line
  window **2**; ±1-line window **4**. The two that same-line drops are
  `critic-lens-reference.md:419` (`auto default)` wraps to :420) and
  `10-step-6.md:156` (`the auto chain is` ends :155) — i.e. exactly the
  hits Edits 2 and 4 exist to fix. v3 shipped the same-line grain on an
  unmeasured claim; do not re-narrow it.

  Why keep a window at all: `check fellows first before runpod` matches
  the bare regex even WITH the trailing guard, is exactly the sentence a
  human would legitimately write, and under FAIL posture that FP wedges
  the writing session's Step 9c gate. ±1 line still excludes it (T11/T13),
  because a natural-English sentence of that shape carries no order
  vocabulary in its neighborhood.

**Family 2 — stale tuple transcription** (Alternatives SF3). A prose
transcription of the constant asserts the order by construction, so
compare its head against the resolved head:

```python
rx = re.compile(r"DEFAULT_AUTO_LANE_ORDER\s*=\s*\(\s*['\"](?P<head>\w+)['\"]")
```
