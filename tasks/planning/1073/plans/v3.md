# Plan — Issue #1073: Decoding-regime robustness of the context→answer map (greedy vs stochastic vs 10-rollout-averaged)

## 0.0 TL;DR (plain English)

- **What I'll run:** The parent experiment (#779) learned to predict a model's answer-side internal activations from its prompt-side activations, using answers sampled with randomness. Over the same 5,000 real user prompts, I'll build the answer side three ways — one deterministic answer, one random answer (already computed), and the average over ten random answers — then compare how the predictions and the raw answer activations themselves shift between the three.
- **What I expect:** Averaging ten answers should give a slightly cleaner target (the parent already saw shifts of a few hundredths from this). I'm betting the deterministic answer sits at least as close to the ten-answer average as a typical single random answer does, which would justify the theory plan's use of deterministic answers as the standard target.
- **What would change my mind:** If the deterministic answer's activations sit farther from the ten-answer average than a random single answer does, or if prediction quality ranks the three versions differently than expected by a large margin, the theory work can't treat deterministic and averaged targets as interchangeable and its C11/C12 items need a redesign.

**Loss surface:** N/A (closed-form ridge; no token loss).

## 3. Hypothesis

1. **Target-level (C11):** per context, the greedy answer's activation profile sits at least as close to the 10-rollout average as a typical single stochastic draw does: `cos(v_greedy(x), v̄10(x)) ≥ mean_j cos(v_j(x), v̄_{10\j}(x))` for most contexts (median Δ ≥ 0). Falsified if the median Δ is negative with bootstrap CI excluding 0 and magnitude > 0.02.
2. **Map-level:** maps fit to 10-rollout-averaged targets score highest held-out R² (noise-reduced targets), with greedy and single-stochastic within the #779-established target-multiplicity band (|ΔR²| ≤ 0.07 at frozen layers + layer 19). Falsified if any pairwise arm gap exceeds 0.15 R² with CI excluding 0.07.
3. **Monitoring-level:** within-condition r orderings across the three arms agree in sign and overlap in CI in most trait×mode cells (levels may shift ≤ ~0.07 per the #779 grid variant). Falsified if the greedy-target map flips a trait×mode cell's raw-vs-map comparison verdict relative to the 10-avg map with CIs separated.
4. **Regime descriptives:** greedy responses differ measurably in length/truncation (direction uncertain); reported as a finding either way, no threshold.

## 4. Design

**Substrate:** the #779 pass-B bundle — `issue779_monitoring/analysis_tensors/pass_b/train_context_vectors.pt` (6.02 GB, HF-verified 2026-07-05: fields `cx_last (N,28,3584)`, `cx_mean`, `v_x`, `prompts`, `layers`, `source`, `metadata`; N ≈ 5,000 kept LMSYS contexts). Contexts are rendered exactly as pass-B did: `messages=[{"role":"user","content":p}]` + `apply_chat_template(add_generation_prompt=True)`.

**Three decode arms (the single manipulated variable = answer-side decoding regime):**

- **(c) Single random answer (parent's headline)** — REUSE the bundle's `v_x` verbatim (no regeneration possible or needed; text not persisted).
- **(b) Single deterministic answer** — NEW: one greedy decode per context, `SamplingParams(n=1, temperature=0.0, max_tokens=1024)`, then teacher-forced capture of `v_greedy(x)` under the identical `capture_answer_vector` definition.
- **(a) Ten-answer average** — NEW: `SamplingParams(n=10, temperature=1.0, top_p=0.95, max_tokens=1024, seed=42)` (the exact #779 Arm-B corpus recipe), capture per-rollout `v_j(x)`, target `v̄10(x) = mean_j v_j(x)` (glossary `v̄_A^r`).

**Mapping arms — prefix-based AND context-based (Critical Rule):**

- **Context-based arm (primary):** input = `cx_last` (last-prompt-token activation at the generation slot — everything before the model's answer, i.e. prefix + user query). This is the #779 recipe verbatim. Exploratory input variant: `cx_mean` (mean over all prompt tokens; persisted; shares the FFC factorization).
- **Prefix-based arm — realized as a stated, mechanically-forced deviation:** on this substrate the prefix (everything before the user query) is the *constant* Qwen default system block (`apply_chat_template` injects "You are Qwen, created by Alibaba Cloud…" when no system message is supplied — pass-B supplies none), so the prefix-end activation is byte-identical across all 5,000 contexts and a prefix-input map degenerates to predicting the global mean target. On the eval side the prefix (system prompt / many-shot history) is constant *within* each condition, so the within-condition primary metric is undefined for a prefix read there too. The prefix arm is therefore REALIZED as the **constant-input mean-target floor row** (held-out R² of predicting the training mean — the exact quantity a constant-input ridge converges to), reported in every map-quality figure and carried into the clean-result as a scope caveat: *decoding-regime robustness is measured for the context-based map; the prefix-based map is degenerate on this substrate by construction* (verification command in §12). This satisfies "state a justified deviation" in the Goal's clarifier note.

**Phases (all on one GPU pod, sequential; per-phase persist + incremental upload):**

- **P0 — probe (~10 min):** download bundle + `r_b/`; regenerate n=1 seed-42 rollouts for the first 20 bundle prompts; batch-1 `capture_answer_vector` (the parent function, imported); compare cos to the bundle's `v_x` rows. Outcomes: cos≈1 ⇒ exact RNG+capture reproduction (strong consistency gate); cos in the within-context draw-similarity band ⇒ vLLM RNG differs, old `v_x` treated as an exchangeable independent draw (expected fallback, recorded); median cos < 0.2 ⇒ alignment bug — HALT (kill criterion 2). P0 also runs the batched-capture equivalence gate (3 items, batched vs `capture_answer_vector` batch-1 reference; span-mean quantity ⇒ flat cos ≥ 0.999 bar per the #779 r12 calibration; single-position bars not needed since only span means are emitted), times one production-shape capture batch + one production-shape GPU eigh (the §9 pilot-gated fit basis), and counts the exact-duplicate rate over the 5,000 bundle prompts (string-normalized; assumption-11 caveat — the LMSYS loader has no dedup).
- **P1 — greedy generation (~15 min):** vLLM chunked generate (chunk ≤ 500, `EPM_VLLM_GREEDY_CHUNK_SIZE`, per-chunk INFO logs), `use_tqdm=False`, `VLLM_WORKER_MULTIPROC_METHOD=spawn`. Persist rollout TEXT immediately (`raw_completions/greedy/`, <9 MB JSON shards) before any capture.
- **P2 — stochastic 10-rollout generation (~1 h):** same engine, n=10 seed 42; persist text (`raw_completions/stoch10/`) before capture. Reap the vLLM engine (`_reap_vllm_engine` recipe) before P3 loads the HF model — no co-residency.
- **P3 — batched teacher-forced capture (~2 h):** new script reusing the `capture_pass2_batched` pattern (`issue779_capture_answer_summaries_pass2.py:133`) with a span-mean output = the `capture_answer_vector` v(x) definition (mean over the response span `prompt_len:full_len`, all 28 layers), `logits_to_keep=1` threading (gotchas), `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` in the workload cmd, batch ~16 (halve on OOM). Emits per-rollout `v` fp16 shards (55,000 × 28 × 3584 ≈ 11 GB) + fp32 reductions `v̄10`, `v_greedy`. Checkpoint per shard; resume-by-skip keyed on (arm, shard).
- **P4 — fits + stats (on-GPU, ~20 min):** FFC-style shared-Gram GCV ridge: one factorization per (input ∈ {last, mean}, layer 28, fold 5) reused across ALL THREE arms' targets via batched `V.T @ Y` GEMMs (280 eigh total, arms free). Aligned folds (seed 42) across arms ⇒ paired per-context differences. Outputs per (arm × input × layer): held-out pooled R² (test-own-mean), mean per-context cosine, per-context held-out predictions at frozen layers + layer 19. Robustness pass: val-selected λ on the FFC 3600/400/1000 split. Monitoring read: fit h per arm on the full common set at the 4 unique frozen layers, apply to pass_a eval `cx` (`issue779_stage1.fit_h_readouts` / `build_eval_matrix`), within-condition Pearson r vs the persisted graded judge scores, `bootstrap_within_condition_ci` (≥997 replicates). Cross-arm agreement + jackknife stats (einsum over per-rollout fp16 slices, per-layer loads). All results to `eval_results/issue_1073/*.json`, checkpointed per unit.
- **P5 — figures (VM CPU, from JSONs only):** `paper-plots` style, `figures/issue_1073/`.

**Equalize-down:** all cross-arm metrics and all fits use the COMMON kept-context set (context kept iff old `v_x` present AND greedy response non-empty AND all 10 stochastic rollouts non-empty); report per-arm drop counts. No all-or-nothing gate — a context set ≥ 4,700 proceeds; below that, report and proceed with the reduced N flagged.

**Dual-DV rule: N/A — stated.** This is an activation-geometry task; no LLM-judged behavior DV is newly produced (DV3 reuses #779's already-validated judge scores unchanged), so the judge-rate + continuous-companion pairing does not apply. Install-strength control: N/A — no implantation. Selection-symmetric nulls: N/A — no max-over-axis headline (read-out layers are FROZEN from #779; the 28-layer curves are exploratory only).

OOD folds: the held-out predictive DVs use pointwise 5-fold CV with an explicit iid argument — the LMSYS contexts are independent single-turn prompts with no family/source/persona group axis on this substrate (no group structure to leak across folds); DV3 is already a corpus-transfer read (fit corpus fully disjoint from the eval contexts), satisfying `ood-generalization-folds`.

**Statistical framing:** N ≈ 5,000 common contexts (exact N reported). Bootstrap over contexts: 1,000 resamples, seed 0, percentile 95% CIs, for every cross-arm mean/median difference; paired per-context differences (aligned folds) for DV1 arm gaps. DV3 uses the inherited condition-resampling bootstrap (n = 8 system / 5 many-shot conditions per trait — small; reported as CIs, no pass/fail conjunction). No pre-registered multi-gate conjunction — diagnostics are handed to the analyzer with the §3 falsification thresholds as interpretation guidance.

**Battery sizing + batched commitment:** bootstrap = 1,000 resamples × 50 cells (arms/arm-pairs × 5 read-out layers (4 unique frozen + L19) × metrics), every cell operating on a PRECOMPUTED per-context scalar vector (N ≈ 5,000): per-draw cost is O(N) on cached scalars ⇒ ~2.5e8 scalar ops total, projected wall ≈ seconds on the VM CPU. Implementation is batched: all 1,000 bootstrap draws are evaluated as ONE (1000, N) resample-index gather (`np.take` on the shared index matrix, seed 0) + mean/median over axis 1 per cell — no per-draw Python loop. Jackknife (DV4) = leave-one-rollout-out over the 10 rollouts, computed in closed form from the cached per-rollout cosines via one vectorized einsum over the (N, 10) matrix — no refits, no per-leave-out loop. NO fit is ever inside a bootstrap or jackknife draw — all resampling operates on per-context scalars emitted once by P4; the ridge fits run exactly once per (arm × input × layer × fold).

Row-coverage: every registered paired contrast (DV1 per-context held-out predictions across arms; DV2/DV4 per-context target cosines) is computed from this plan's OWN P3/P4 outputs — the per-context prediction file eval_results/issue_1073/heldout_recon_arms.json (all three arms, aligned fold seed 42, common kept-context index list persisted alongside) and the per-rollout fp16 v-store (arms a/b) plus the reused pass_b v_x (arm c) restricted to the same common index set; the driver asserts the three arms' context-id key sets are identical before any paired statistic.
