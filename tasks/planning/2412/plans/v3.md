```bash
# Import-satisfiability probe on synced sibling TEST files (#2208, hardened
# #2412): probe + pair-atomic revert live in scripts/step5a_sibling_probe.py,
# resolved from the MAIN checkout (git-common-dir), never $WT — the worktree
# copy is fork-era by construction, the very staleness class being probed.
# The helper keeps the #2208 real-collection probe (180s/file fence with
# process-group kill + 15s SIGKILL escalation, 900s venv warm-up, timeout =
# failure) and ADDS a static AST import scan that sees FUNCTION-BODY imports
# (the #2204 escape): a synced test whose src/ import is unsatisfiable against
# THIS worktree (module missing, symbol absent, or an issue-namespaced src
# DIRECTORY differing from origin/main) FAILs, and the helper reverts EVERY
# synced file of that issue number (branch-era restore / main-NEW drop —
# pair-atomic, #1824/#1860). Fail-safe direction (#2208): an undecidable
# probe REVERTS, never keeps — a helper rc != 0 (crash, absent helper)
# reverts ALL synced files below and FAILs the arm loud.
if [ "${#SIBLING_SYNCED[@]}" -gt 0 ]; then
  ROOT="$(dirname "$(git -C "$WT" rev-parse --path-format=absolute --git-common-dir)")"
  KEPT_OUT=$(mktemp)
  if (cd "$ROOT" && uv run python scripts/step5a_sibling_probe.py --worktree "$WT" --kept-out "$KEPT_OUT" -- "${SIBLING_SYNCED[@]}"); then
    mapfile -t SIBLING_SYNCED < "$KEPT_OUT"
    rm -f "$KEPT_OUT"
  else
    rm -f "$KEPT_OUT"
    for f in "${SIBLING_SYNCED[@]}"; do   # undecidable ⇒ revert EVERYTHING (#2412)
      if git -C "$WT" cat-file -e "HEAD:$f" 2>/dev/null; then
        git -C "$WT" checkout HEAD -- "$f"
      else
        git -C "$WT" rm -f -q --ignore-unmatch -- "$f"
      fi
    done
    echo "[step5a] FATAL: sibling probe helper failed (rc != 0) — reverted ALL ${#SIBLING_SYNCED[@]} synced sibling file(s) (fail-safe #2208/#2412: an undecidable probe reverts, never keeps). Fix the probe, then re-run Step 5a." >&2
    exit 1
  fi
fi
```

Embedded-shell exit-path trace: the `exit 1` reaches the end of the ONE Bash invocation running the fenced block (same loud-exit contract as the #2303 family-commit FATAL at lines 302–306 — "fenced blocks are separate shells — fail-closed, never sourced"); the sync commit at 411–415 is below it and never runs, so nothing unprobed is ever committed — and by the time it fires, the else-branch loop has already restored/dropped every `SIBLING_SYNCED` path, so the tree AND index are clean of sync residue (MF2). The revert loop is IDEMPOTENT under partial helper-side reverts: `checkout HEAD --` is naturally idempotent for branch-era files, and `git rm -f -q --ignore-unmatch` exits 0 when the helper already dropped a main-NEW file (a bare `git rm` would rc-fail on the missing pathspec and, under the fenced shell's fail-closed semantics, abort the loop mid-revert). The happy path falls through to the unchanged commit + count echo. There is no bare `false` in any branch.

Why main-checkout resolution is REQUIRED, not defensive: Step 5a's fenced block runs with CWD inside the WORKTREE (`WT=$(git rev-parse --show-toplevel)`, line 125) — a relative `scripts/…` path would execute the branch's fork-era helper copy (or none), i.e. the exact staleness class this task fixes. `git -C "$WT" rev-parse --git-common-dir` of a linked worktree resolves to `<repo-root>/.git`; `dirname` gives the main checkout, which is always on `main`. An ABSENT helper (e.g. a local main behind origin/main from before this change lands — impossible on any reachable production path since doc + helper land in one commit and resolve from the same tree, but covered anyway) surfaces as `uv run python` rc != 0 → the SAME else branch: full revert + FATAL + exit 1 (N1; fixture-pinned in D5). Helper algorithm (all git ops `git -C WT …`; all output echoes to stdout so the arm's stdout keeps the incident-diagnosis lines):

1. **Group** synced files by issue number `m` = first `issue_?(\d+)` match over the FULL relative path (fixes the current `basename`-based extraction, which returns EMPTY for `src/.../issue_1739/fits.py` and would corrupt the revert set — a latent bug D1 would otherwise trip). Slug-named experiment dirs are never SYNCED (D1's globs are issue-prefixed only), so they never enter revert sets — the extraction convention stays `issue_?(\d+)`-only.
2. **Static scan** (runs FIRST — cheap, no subprocess) per synced TEST file (`tests/test_issue*_*.py`): `ast.parse` the worktree bytes; `ast.walk` for every `Import`/`ImportFrom` (function-body imports included — the selector's own import-map arm set this precedent, `select_step9c_tests.py` docstring: "function-level imports count"); skip relative imports (`level > 0`). Two execution-context carve-outs (N2), tracked while walking: (α) an import whose nearest enclosing `if` tests `TYPE_CHECKING` (bare name or `typing.TYPE_CHECKING` attribute) is SKIPPED entirely — it never executes at runtime; (β) an import lexically inside a `try` whose handlers catch `ImportError`/`ModuleNotFoundError` (by name, incl. tuples) is EXEMPT from the MISSING-module/symbol arms only — the guard handles absence gracefully — but NOT from the strict issue-namespaced identity arm below: a PRESENT-but-skewed module imports fine, so the `except ImportError` never fires and the #2204 class is not protected by it. For each remaining absolute dotted module, resolve candidate paths `src/<a/b/c>.py` and `src/<a/b/c>/__init__.py`:
   - Neither exists in WT nor at `origin/main:` ⇒ not a project-src import (third-party/stdlib) ⇒ skip (collection probe covers module-scope failures there; a project-src module absent from BOTH trees would be a pre-existing origin/main red, not a sync artifact — the unit fixture carries a comment pinning this reasoning so a later "hardening" does not turn the skip into a strict FAIL that over-reverts genuine third-party imports; N7).
