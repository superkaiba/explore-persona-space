# Plan v1 — #2055: thread `lane_suffix` into `slurm.job_name` (+ scratch dir) so concurrent lanes stop silently cross-reconnecting

kind: infra (workflow-fix; `workflow_fix_target: src/explore_persona_space/backends/slurm.py`)

## 1. Goal / requirement

Thread `lane_suffix` into `slurm.job_name` so two concurrent lanes on one
issue submit distinct SLURM jobs instead of silently reconnecting to each
other.

Acceptance criteria:

1. Two `dispatch_issue.py launch` invocations for the same issue with
   different `--lane-suffix` values resolve DISTINCT SLURM job names, so
   the second lane's `_reconnect` by-name probe (`squeue --name`) cannot
   match the first lane's job (the #1947 incident: both lanes resolved to
   nibi job 19036499; the second lane got `workload_dispatched=false` and
   its workload never ran).
2. The SLURM scratch tree is lane-isolated too: a suffixed lane prepares
   into `$SCRATCH/eps/issue-<N>-<lane>` — the companion collision surface
   named in the task's events note (second lane's prepare runs
   "clearing runtime artifacts" + `rsync --delete` into the shared
   issue-keyed tree while the first lane's job is RUNNING).
3. The fellows per-cluster `job_name_suffix` (#1609 rule 8) is preserved,
   in the same position it occupies today (terminal).
4. Unsuffixed dispatches are byte-identical: no `lane_suffix` in
   `spec.extra` ⇒ names and scratch paths unchanged.
5. The `lane_suffix_unhonored_by_lane` warning + `--lane-suffix` help text
   in `scripts/dispatch_issue.py` no longer claim SLURM is unhonored.
6. GCP behavior unchanged; RunPod remains unhonored (still warned).

## 2. Background + root cause (verified against current code, 2026-08-09)

- `slurm.job_name()` (slurm.py:697-715) composes
  `eps-issue-{N}[-{plan_hash8}]{cluster.job_name_suffix}` — no lane
  component. `scratch_dir_for()` (slurm.py:729-742) composes
  `{scratch_path}/eps/issue-{N}` — no lane component.
- `lane_suffix` (#934) already reaches: the handle sidecar path
  (`issue_dispatch.default_handle_sidecar_path`), the GCE instance name
  (`gcp.instance_name_for` via `gcp.lane_suffix_for`), and attempt ids
  (`router._make_attempt_id`). It is carried in `spec.extra["lane_suffix"]`
  (dispatch_issue.py:1667-1674, omit-when-absent) and validated by
  `base.validate_lane_suffix` (lowercase `[a-z0-9]([a-z0-9-]*[a-z0-9])?`,
  ≤43 chars).
- The reconnect path (`dispatch_issue.py:537` `_reconnect` closure) and the
  post-cancel liveness probe (`_slurm_is_live_after_cancel`, keyed on
  `handle.pod_name`) both key on the job name — so fixing `job_name()` at
  its spec-consuming root fixes launch (slurm.py:3125), render
  (slurm.py:1918), reconnect, and cancel-probe consistently with zero
  extra threading.
- Lease/park-state cross-match is NOT a residual risk: `router.spec_hash`
  hashes `canonicalize_spec(spec)`, which includes `spec.extra` minus only
  `attempt_id`/`startup_script_path` (router.py:1355-1424), so two lanes'
  specs already hash differently; the #2161 `free_lane_park_state` matcher
  additionally keys on lane + job_id.

## 3. Method delta (the fix)

Read `spec.extra["lane_suffix"]` INSIDE `job_name()` and
`scratch_dir_for()` via a shared validated helper, rather than threading a
new parameter through every call site. All call sites already pass the
spec, so launch/render/reconnect/probe stay consistent by construction.

Name shape: `eps-issue-{issue}[-{plan_hash8}][-{lane_suffix}]{cluster.job_name_suffix}`
(lane before the cluster suffix, so the fellows user-suffix stays
terminal per #1609 rule 8).

Scratch shape: `{scratch_path}/eps/issue-{issue}[-{lane_suffix}]`.

Helper placement: move the tiny `lane_suffix_for(spec)` reader from
`gcp.py` to `base.py` (beside `validate_lane_suffix`, its only
dependency); `gcp.py` re-imports it so the existing `gcp.lane_suffix_for`
import path and `__all__` export keep working. `slurm.py` imports it from
`base` (no slurm→gcp import edge).

## 4. File-by-file changes

### 4a. `src/explore_persona_space/backends/base.py`

Add (verbatim move of gcp.py:983-992, docstring included):

```python
def lane_suffix_for(spec: RunSpec) -> str | None:
    """Validated per-lane suffix from ``spec.extra['lane_suffix']`` (#934), or None."""
    raw = spec.extra.get("lane_suffix")
    if not raw:
        return None
    return validate_lane_suffix(str(raw))
```

### 4b. `src/explore_persona_space/backends/gcp.py`

Delete the local `lane_suffix_for` body; `from .base import lane_suffix_for`
(keep it in `__all__` — existing importers unchanged).

### 4c. `src/explore_persona_space/backends/slurm.py`

```python
def job_name(spec, plan_hash=None, cluster=None) -> str:
    suffix = cluster.job_name_suffix if cluster is not None and cluster.job_name_suffix else ""
    lane = lane_suffix_for(spec)          # from .base — #2055
    lane_part = f"-{lane}" if lane else ""
    if plan_hash:
        return f"eps-issue-{spec.issue}-{plan_hash[:8]}{lane_part}{suffix}"
    return f"eps-issue-{spec.issue}{lane_part}{suffix}"

def scratch_dir_for(spec, cluster) -> str:
    lane = lane_suffix_for(spec)          # #2055 — lane-isolated scratch
    lane_part = f"-{lane}" if lane else ""
    return f"{cluster.scratch_path}/eps/issue-{spec.issue}{lane_part}"
```

Docstrings updated to name the lane component + #2055. SLURM job-name
length is not a constraint (sbatch accepts long names; `squeue --name` is
an exact-match filter — the same mechanism the fellows suffix already
relies on).

## 5. Migration / compatibility edges

- **In-flight handles keep resolving:** poll/finalize/cancel key on
  `handle.pod_name` + `handle.job_id` persisted in the sidecar — a
  pre-fix handle carries the unsuffixed name and keeps working verbatim.
- **Pre-fix suffixed-lane jobs (unsuffixed names) vs post-fix re-runs:**
  a post-fix re-run of a suffixed launch probes the suffixed name, misses
  the legacy job, and would fresh-submit (potential duplicate). Mitigated
  by the §4d.1 legacy-name probe + LOUD warning; the fresh submit is the
  correct default because a live unsuffixed job may equally be a
  legitimately unsuffixed sibling lane — silently reconnecting across the
  suffix boundary would reproduce the bug being fixed. Implementation-time
  check: confirm no live `eps-issue-*` SLURM job currently belongs to a
  suffixed lane (expected: none — #1947's jobs are long gone), making this
  edge vacuous in practice.
- **Scratch-dir migration:** a suffixed post-fix dispatch prepares into
  the NEW `issue-<N>-<lane>` tree and never touches the legacy shared
  tree — strictly safer during migration (no `rsync --delete` into a tree
  a RUNNING legacy job owns). Unsuffixed dispatches keep the legacy path.
