## 11. Decision Rationale

**1. The prescribed probe: `git log --follow --format='%h %ad %s' --date=short -- <body.md>` (path via `task.py find <M>`), with `git log --all --oneline --grep='task #<M>:'` as the fallback.**
- **Why:** it must demonstrably surface the incident's own evidence (the §12-style trace-against-the-real-artifact discipline). It does — both incident tasks traced across their status moves to the exact remove-tag + create commits (§5 K1).
- **Source:** my own verified runs against #1140/#1472 (2026-07-19, output quoted in §5); commit-message formats read from `task_workflow.py` L4536/L5032/L5045.
- **Alternatives:** (a) message-grep as PRIMARY — works pathless (4 commits for #1140) and catches events.jsonl-only commits, but is noisier and `--grep='task #<M>'` without the colon over-matches (`task #11400`); kept as the fallback with the colon, for reaped/husked folders. (b) `git log --follow` on the FOLDER — `--follow` follows a single path only; body.md is where frontmatter tags live, so the file-level probe is the right grain. (c) The body's original diff-sketch probe (`git log --follow --format='%h %s'`) — kept, with `%ad`/`--date=short` added so the mutation DATE (the 2026-07-17 story) reads off directly.

**2. Prose-only + a durability pin test; NO mechanical filing-time enforcement leg.**
- **Why:** detecting "this body cites absence-of-tag-on-artifact as evidence" in free prose is not regex-able — unlike clause (d)'s hex tokens (which got the `daily_drive_filings.py` WARN-only `sha_warnings` scanner precisely because hex-in-commit-context IS regex-able). Clauses (a)–(c)/(a') are likewise prose-enforced; the rule file itself states "There is NO mechanical injector or lint for this line — it is a compose-time duty." A low-precision scanner would spray false WARNs on every filing that mentions tags. The pin test is the cheap mechanical leg that IS obviously right: it guards the prose's durability, exactly as the family precedent did for (c) (#1383 pin), (a') (#1420 pin), and (d) (#1467 pin) in the same test file.
- **Source:** family precedent in `tests/test_daily_three_route_classifier_doc.py` L332–466; the (d)-scanner contrast in `.claude/skills/daily/SKILL.md` L462.
- **Alternatives:** extending the `sha_warnings`-style scanner to tag-absence claims (rejected: no reliable trigger pattern); a `workflow_lint` check (rejected: same detection problem, plus lint runs repo-wide, not at filing time).

**3. Leave clause (a)'s absence-claim exemption sentence untouched.**
- **Why:** (a)'s exemption ("An absence-of-guard claim is exempt from the mis-target rule — its 0-hit in-target result IS the evidence — EXCEPT for the text-matching-guard subclass in (a').") scopes to grep evidence on workflow-surface target FILES. Artifact-state evidence is a different evidence TYPE (a mutable task artifact, not a grep of the fix site), so (e) is self-contained and cross-wiring it into (a) would both grow the paragraph and blur the (a)-scope.
