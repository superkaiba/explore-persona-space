## 2. Diagnosis (evidence by reference)

- **Production defect (one mechanism):** a top-level heredoc opener token attached to the commit clause enters the pathspec-candidate stream — `redirect_tok_kind` (hook L558-601) returns `no` for the here-doc/here-string operator family by pinned design — so `classify_candidate` marks the clause opaque → whole-index fallback → block. Isolation: heredoc-bearing shape blocks while the identical command minus the heredoc scopes clean; all three incident-composite replays block.
- **Test-parity gap (production-neutral):** the two cd classification sites compare against the hardcoded `$REPO` (L128) instead of `$GUARD_REPO` (L129, the `EPM_ROOT_CODE_COMMIT_REPO` override): `cd_latch_verdict` (L349-358) and the MF-1(ii) root-spelling case arm (~L671-677). Under a hermetic test repo, a cd to that repo's own root reads as latch/non-root, so the incident composite (cd-prefixed) cannot be covered by self-test rows. In production the incident's cd target string-matched `$REPO` exactly, so the cd was NOT the incident defeater. These two sites plus the `-C` waiver (L704, out of scope — see L2) are the complete consumer set of the hardcoded constant in cd/-C classification positions.
- **Non-defeaters confirmed by isolation (no change needed):** output redirects (#1928, rows A21/A22), trailing commands on later lines, semicolon tails, `-F /dev/stdin` without heredoc, message-file + pathspec (#1949, row A23).

## 3. Changes (4 legs; two files)

**L1 — production fix: heredoc-opener interception.** In the commit-clause second token pass, intercept top-level heredoc opener tokens BEFORE candidate classification, in BOTH arms: the post-`--` arm (~L783-795) and the positional arm (~L826-833). Implement as a NEW strict helper `heredoc_tok_kind` (echoes `self` / `pair` / `no`):
- attached unquoted delimiter (`<<DELIM`, `<<-DELIM` shapes) → `self`; bare separated operator (`<<`, `<<-`) → `pair` (consumes the delimiter word); here-string with attached word → `self`, bare → `pair`;
- masked-delimiter forms (quoted delimiter → FILL-bearing token): recognize iff the token's literal UNQUOTED prefix is exactly the opener operator and the remainder is the masked delimiter — derive the exact masked shapes from `parse_heredoc_delim` (L191-235), do not guess. A fully-quoted token masks its operator too: any quote/FILL-bearing token WITHOUT that literal operator prefix stays `no`.
- anything else → `no` (fail closed, today's opaque → whole-index → block path).
- `redirect_tok_kind` stays byte-untouched: its heredoc-family→`no` contract is pinned by the r14/r15 refuse tests + its doc block.
- Accepted residuals (document in the known-limitations header, L76 precedent): (i) a MASKED (quoted/spacey) pathspec combined with a heredoc still fails rawtail token-count parity → opaque → block, same accepted residual as redirects (#1928); (ii) the ADD-clause second pass (L866+) keeps heredoc → opaque → block — out of incident scope, fail-closed, deliberately unchanged.
