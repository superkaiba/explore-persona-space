# Plan — #2253: `workflow_lint.py --check-prod-import-lockfile` (third-party imports vs `uv.lock`)

## 0.0 TL;DR (plain English)

- **What I'll build:** a new lint check that reads every Python file under `scripts/` and `src/`, finds every third-party package they import, and fails loudly when a package is not declared resolvable from the project's lockfile (`uv.lock` / `pyproject.toml`). A package declared ONLY under a non-default extra (e.g. `viz`) passes the FAIL boundary but draws a WARN naming the extra, because a bare `uv sync` does not install it. It ships FAIL-level, bundled into the default lint run, with every pre-existing offender explicitly dispositioned (17 one-line per-site waiver comments across 8 files, 10 already-guarded sites, 7 dangling-module WARN roots, 2 extras-only WARN roots) so the whole tree is green the day it lands.

The FAIL boundary is *declared resolvability*, not installed-by-default; the extras WARN tier covers that gap honestly.
- **What would change my mind:** if the full-tree acceptance run finds an offender class the recon missed, or a fixture shows the try/except-ImportError exemption or the issue-stem heuristic misclassifies, I re-scope that class (WARN bucket or waiver) before bundling — the check never lands red on the live tree, because a red no-flags run is a fleet-wide Step 9c wedge (#1388).

> Add a `workflow_lint.py` check that fails when a `scripts/` or `src/` module imports a third-party package on a **production** (non-smoke) code path that is not resolvable from `uv.lock` / `pyproject.toml`. (Task #2253 body `## Goal`, verbatim; task is `kind: infra` with no `goal:` frontmatter. Re-read from `tasks/planning/2253/body.md` at v3-return time, 2026-08-21 — unchanged since draft start.)

**Adopted scope sharpening (Goal unchanged, framing simplified):** the shipped check is **branch-agnostic over runtime-executable code**. An import that is unresolvable from the lockfile is a latent `ModuleNotFoundError` wherever it can execute — production branch, smoke branch, or nested three helpers deep — because *resolvability* does not depend on *reachability*. A plain `ast.walk` over every import node therefore (a) satisfies the body's "production (non-smoke) code path" framing: every production-branch import is scanned, including the #1336 module-local-helper shape, with no smoke/production branch analysis and none of `--check-smoke-blind-spots`' documented false negatives (one-level helper resolution, un-recursed `ast.Match` bodies, dynamic dispatch, non-`smoke`-named flags); and (b) additionally covers smoke-branch imports, which is a strengthening, not a scope change — a smoke branch importing an uninstallable package is equally broken. **Exactly one carve-out narrows the walk:** imports under a canonical `if TYPE_CHECKING:` / `if typing.TYPE_CHECKING:` guard BODY are excluded, because `typing.TYPE_CHECKING` is `False` at runtime — such code can never raise `ModuleNotFoundError`, so scanning it would fire on healthy code (v3 correction; the v2 "strict superset" claim is restated as: the scan covers exactly the runtime-executable superset of the body's production-path scope). The one legitimate "deliberately optional" escape the body names — an explicit `try/except ImportError` degrading a non-load-bearing path — is implemented as an AST-level exemption scoped to the protected `try.body` (§4.1 step 4), plus a per-site waiver-comment escape for sites that cannot restructure (the established `DOTENV_LINT_EXEMPT` idiom). Source: the #2253 `epm:clarify v1` recon (task events, 2026-08-20), verified against the committed probe `tasks/planning/2253/artifacts/recon_import_surface_probe.{py,out}`; TYPE_CHECKING carve-out per #2253 critique r1 MUST-FIX 3.

### 4.1 The check function

```python
PROD_IMPORT_LINT_WAIVER_MIN_REASON_CHARS = 10  # mirrors DOTENV_LINT_WAIVER_MIN_REASON_CHARS

# Import-name -> PyPI distribution name, for roots whose module name does not
# PEP-503-normalize to their dist name. Deterministic primary (§11 D3); a
# table entry whose dist is absent from the lockfile is itself a FAIL.
IMPORT_TO_DIST: dict[str, str] = {
    "PIL": "pillow", "dotenv": "python-dotenv", "hydra": "hydra-core",
    "sklearn": "scikit-learn", "umap": "umap-learn", "yaml": "pyyaml",
}

def check_prod_import_lockfile(
    *, scan_roots: tuple[Path, ...] | None = None,
    lock_path: Path | None = None, pyproject_path: Path | None = None,
    repo_root: Path | None = None,
) -> list[str]: ...
```

(v2's `OVERLAY_IMPORT_ROOTS` constant and its slurm-consistency pin test are DELETED per critique r1 MUST-FIX 1 — directory-existence is not a proxy for importability, and the overlay dir is absent from every worktree; see §5 launcher-context row + §12 assumption 15.)

Algorithm (per invocation):

1. **Load the dist universes** (fail-loud: a missing OR unparseable `uv.lock` or `pyproject.toml` returns one error naming the file — backing test `::test_missing_or_malformed_manifest_fails_loud`, parameterized missing × malformed × both files — never a silent skip):
   - `lock_dists` = `{pep503(p["name"]) for p in tomllib.loads(uv.lock)["package"]}`.
   - From `pyproject.toml`: `default_declared` = PEP-508 name-prefixes of `project.dependencies` plus every `dependency-groups.<g>` for `g` in the DEFAULT group set (`tool.uv.default-groups` when present, else `{"dev"}` — uv's documented default; this repo declares only `dev` at `pyproject.toml:151-155` and no `default-groups` key, grep 2026-08-21). `nondefault_declared` = dist → sorted declaration names, from `project.optional-dependencies.<extra>` (this repo: `gpu`, `viz`) + any non-default `dependency-groups.<g>`. Non-string entries in any group list (PEP-735 `{include-group = "..."}` tables) are SKIPPED, never parsed (backing test `::test_dependency_group_table_entries_skipped`). Name extraction via a PEP-508 name-prefix regex (`^[A-Za-z0-9]([A-Za-z0-9._-]*[A-Za-z0-9])?`), each PEP-503-normalized (`re.sub(r"[-_.]+", "-", s).lower()`).
   - **FAIL universe** = `lock_dists ∪ default_declared ∪ set(nondefault_declared)` — the wide boundary the task body's oracle pins ("resolvable from `uv.lock` / `pyproject.toml`"; unchanged from v2 per critique r1 MUST-FIX 2's orchestrator decision).
2. **Build the first-party set once:** `{"explore_persona_space", "scripts", "src", "tests", "conftest"}` ∪ `{p.stem for p in (repo/scripts).rglob("*.py")}` ∪ `{d.name for d in (repo/src).iterdir() if d.is_dir()}` ∪ `{d.name for d in (repo/scripts).iterdir() if d.is_dir()}`. The `scripts`/`src` package roots are the load-bearing addition — the recon's 455-site class-(A) false-positive avalanche under a stems-only resolver. **Stem-shadowing residue (documented in the docstring + pinned):** the recursive stem set makes ANY script basename first-party repo-wide, archived files included (`run_leakage_experiment` is stem-shadowed by `scripts/archive/run_leakage_experiment.py`), so a third-party root colliding with a stem would silently resolve first-party. Zero current collisions between stems and {import-name forms of lock dists ∪ `IMPORT_TO_DIST` keys} (verified); the live collision pin test `::test_no_lock_dist_shadowed_by_script_stem` keeps that true. The structural fix (an import-path-aware first-party resolver) is deliberately deferred (§14).
3. **Scan** `_files_scope_filter(sorted(root.rglob("*.py")))` for each scan root (default `scripts/`, `src/`); parse via `_cached_parse`; unparseable → one stderr `workflow_lint: note:` line (the `check_scripts_import_guard` idiom, `workflow_lint.py:8718`). Collect `(root, lineno)` per `ast.Import` alias and per level-0 `ast.ImportFrom` (`module.split(".")[0]`); relative imports (level>0) skipped. **TYPE_CHECKING carve-out (MUST-FIX 3):** imports under the BODY of an `ast.If` whose test is `Name("TYPE_CHECKING")` or `Attribute(value=Name("typing"), attr="TYPE_CHECKING")` are SKIPPED — that code never executes at runtime (`typing.TYPE_CHECKING` is `False` outside type checkers), so an unlocked type-only dep there is healthy; the `orelse` of such an `If` IS scanned (it executes at runtime), and smoke branches / ordinary conditionals remain scanned. Aliased forms (`from typing import TYPE_CHECKING as TC`) are NOT recognized — a documented false-positive-direction residue with zero tree instances today; a future hit remediates via the canonical spelling or a waiver. Backing tests: `::test_type_checking_guard_body_exempt` (absent dep only under the guard → PASS) paired with the A1 fixture's smoke-stub branch, which must still FAIL (branch-agnostic scanning retained).
4. **Per-site exemptions** (each applies to the individual AST import site — MUST-FIX 5): (i) **protected-try-body (MUST-FIX 4):** exempt ONLY an import that executes within the `body` of an `ast.Try` having a handler naming `ImportError` or `ModuleNotFoundError` (Name / Attribute / tuple forms), with NO `FunctionDef`/`AsyncFunctionDef`/`Lambda` boundary between that Try and the import (a function *defined* in the try body defers its imports outside the protected region). `handlers`, `orelse`, and `finalbody` positions are NOT exempt — an exception raised there is not caught by that same try (Python try-statement semantics). Parameterized backing tests: body ⇒ exempt; handler / orelse / deferred-function-body ⇒ FAIL; handler catching an unrelated exception type only ⇒ FAIL. This fix strictly improves the `except ImportError: import fallback_pkg` case — the fallback path is exactly what must be reliable. (ii) a `# PROD_IMPORT_LINT_EXEMPT: <reason>` (reason ≥ 10 chars) on the import's first physical line or the immediately preceding non-blank line — exempting THAT SITE ONLY, never the file or the `(file, root)` pair (backing test `::test_waiver_is_per_site_second_site_still_fails`).
5. **Classify each remaining (non-exempt) site's root:** stdlib (`sys.stdlib_module_names | {"__future__"}`) → skip; first-party → skip; PEP-503(root) ∈ FAIL universe → resolved; `IMPORT_TO_DIST[root]` present and its dist ∈ universe → resolved; table entry present but dist ∉ universe → FAIL (table drift, loud — A4). **Extras WARN tier (MUST-FIX 2):** a RESOLVED root (either resolution route) whose dist ∉ `default_declared` but ∈ `nondefault_declared` emits one path-free stderr line per root: `WARN: check-prod-import-lockfile: import root '<root>' (dist '<dist>', <n> non-exempt site(s)) resolves only via non-default extra/group '<names>' — a bare 'uv sync --locked' (the pod bootstrap, bootstrap_pod.sh:425) does not install it` — never folded into `errors`. A dist present in `lock_dists` only (a transitive dep) resolves silently — docstring caveat, stated verbatim: **PASS ≠ installed-by-default; the FAIL boundary is DECLARED resolvability** (the body's oracle). Measured live-tree WARN footprint: `umap`→`viz` (4 sites) and `liger_kernel`→`gpu` (2 unguarded sites; `flash_attn`'s 5 sites are all try.body-exempt and never reach classification — §12 assumptions 17-18). Backing test `::test_extras_only_dist_warns_never_silent` (fixture dist present only under `optional-dependencies` → 0 errors AND the WARN is emitted naming the extra — never a silent resolve).
6. **Unresolved split:** `root.lstrip("_").startswith("issue")` → **class-(B) WARN bucket** — one stderr line per root: `WARN: check-prod-import-lockfile: dangling first-party import root '<root>' (<n> site(s)) — module absent from main (unmerged branch or deleted); latent breakage, not a third-party verdict` — root names + counts ONLY, never file paths. This extends the established `_issue_import_closure` `name.startswith("issue")` convention (`:18848`) with the leading-underscore form (covers `_issue506_common`). Never folded into `errors`. **Consumer contract (corrected claim, critique concern 1):** `scripts/inline_lint_gate.py:272` defines `NON_RED_PREFIXES = ("WARN", "PASSED", "SKIPPED")`, matched at `:1146` via `stripped.startswith(...)` — a `workflow_lint: WARN:`-prefixed line does NOT match it. So every WARN line this check emits (class-(B) AND the step-5 extras tier) LEADS with the literal `WARN` token (genuinely consumer-recognizable — the suspenders) AND carries no file path (the belt); both properties pinned by `::test_warn_lines_lead_with_warn_and_carry_no_path`. **Everything else → class-(C) FAIL:** waivers were already applied PER SITE in step 4; the REMAINING errors are then deduped to the first unexempt `(file, root)` site (MUST-FIX 5 — an old waiver on one site can never silently absorb a later load-bearing import of the same root in the same file).
7. **Error message shape:** `"{rel}:{lineno}: third-party import `{root}` is not resolvable from uv.lock/pyproject.toml (#2253/#2223). Tried: pep503('{root}')='{norm}', IMPORT_TO_DIST[...]. Fix: add the distribution to pyproject.toml + `uv lock`; or add an IMPORT_TO_DIST entry if import-name != dist-name; or guard a deliberately-optional NON-load-bearing use with try/except ImportError (import in the try BODY); or waive with '# PROD_IMPORT_LINT_EXEMPT: <reason>' (>= 10 chars).{venv_hint}"` — `venv_hint` is a best-effort enrichment from `importlib.metadata.packages_distributions()` (wrapped `try/except Exception`, message-only, NEVER verdict-bearing; tests never assert on it), e.g. `" (live venv maps this to dist 'X')"`.
