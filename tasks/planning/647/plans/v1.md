## 3. Hypothesis

The two competing hypotheses, verbatim from the body:

- **H_stylized-only:** the activation predictors ALSO collapse on the nonstylized subpanel (CV R² → ~0, CIs straddle zero, like JS). Read: all distance predictors of marker-leakage transfer are basically detecting the stylized split; the geometry-leakage line generalizes poorly within normal personas. This would substantially weaken the headline of #502/#511 and feed open-question #2.
- **H_geometry-real:** the activation predictors keep meaningful CV R² on the nonstylized subpanel where JS does not. Read: activation geometry captures the within-nonstylized signal that output-distribution JS misses — the distance→leakage line is more than the stylized split, and activation geometry is the right substrate.

**Falsifiable thresholds (headline cell L22 / gauss_kl / loc ep1, primary DV ΔG):**

- H_geometry-real is *supported* if nonstylized CV R² is clearly positive with a panel-row bootstrap 95% CI excluding 0 (i.e. behaves unlike JS's −0.0218 [−0.151, 0.078]). A retention of even ~half the full-panel skill (CV R² ≳ 0.3, CI > 0) is a strong H_geometry-real read.
- H_stylized-only is *supported* if nonstylized CV R² ≈ 0 with a CI straddling zero (matching the JS collapse), across the four metrics and the L19–L24 band.
- The cross-epoch ({1,2,3,5}) and cross-layer (L19–L24) reads are robustness: a finding that holds only at the single headline cell and flips elsewhere is reported as fragile, not as a clean answer.

Note (carry into the result): the body's known caveat — LOCO on 13 highly-correlated nonstylized personas has little held-out signal, so a *negative* CV R² is ambiguous between "genuinely no within-nonstylized generalization" and "panel too small for LOCO to resolve anything." If the predictors collapse, the clean disambiguating follow-up is to expand the nonstylized panel with a richer/more diverse everyday-persona set (#522 follow-up #2) before concluding there is no within-nonstylized gradient.

### 4.2 New file: `scripts/issue647_nonstylized_predictor_sweep.py`

A thin orchestrator (~250 lines) that imports the three reused modules and loops the grid. It does NOT fork the bakeoff or re-implement any metric / regression / bootstrap math.

```python
# scripts/issue647_nonstylized_predictor_sweep.py
"""task #647 — do #502/#511/#522's activation-geometry leakage predictors
collapse on the nonstylized (13-persona) subpanel, like #522's JS did?

Single-variable change from #522: panel (full 16 → nonstylized 13). Every
other knob — metrics, layers (L19-L24), loc epochs {1,2,3,5}, PCA k=16,
cloud-aware ridge, deterministic LOCO, panel-row bootstrap n_boot=2000
seed=42 — is held cell-for-cell. CPU-only on the cached #502 residuals.
"""
import sys
from pathlib import Path
_SCRIPTS_DIR = str(Path(__file__).resolve().parent)
if _SCRIPTS_DIR not in sys.path:
    sys.path.insert(0, _SCRIPTS_DIR)

import issue493_extraction_metric_bakeoff as bakeoff
import issue511_probe_count_sweep as sweep_mod   # ensure_activation, load_activations_slice,
                                                 # compute_predictor_vector, _loocv_r2_deterministic, CellSpec
import issue522_js_regress as jsreg              # _panel_bootstrap_ci, _fit_row, _percentiles

PROJECT_ROOT = Path(__file__).resolve().parent.parent
OUT_DIR = PROJECT_ROOT / "eval_results" / "issue_647"

COND_IDS = sweep_mod.COND_IDS               # inherits the 16-persona canonical order
METRICS  = ("gauss_kl", "mmd", "wass2", "cosine")
LAYERS   = tuple(range(19, 25))             # L19-L24, headline L22
EPOCHS   = (1, 2, 3, 5)                      # loc arm
ARM      = "loc"
N_FULLPOOL = 500                             # identity draw → reproduces #522 per-subset xv
N_BOOT   = 2000
SEED     = 42

def compute_xv_full(metric: str, layer: int):
    """Compute the 240-element predictor vector at the full 500-probe pool
    (identity draw). TARGET- AND PANEL-independent: it is the per-pair
    distance for ALL 240 ordered pairs; the panel restriction is applied
    downstream by selecting the 156-pair subset's distances.
    """
    cell = sweep_mod.CellSpec(
        extraction_point="last_prompt", layer=layer, metric=metric,
        variant="raw", n_grid=(N_FULLPOOL,), r=1,
    )
    act, cond_ids = sweep_mod.load_activations_slice("last_prompt", layer)
    assert set(cond_ids) == set(COND_IDS), (sorted(cond_ids), sorted(COND_IDS))
    # subset_idx=0, N=500 == pool size → rng.choice draws the full pool (identity).
    payload = bakeoff._compute_metric_matrix(
        activations=act, cond_ids=cond_ids, metric=metric,
        extraction_point="last_prompt", pca_k=bakeoff.PCA_DEFAULT_K, variant="raw",
    )
    return payload, cond_ids   # materialize per-panel pairs below

def fit_panel(payload, cond_ids, nonstylized_only, G, prompt_tokens):
    """Materialize the panel-specific xv from the metric matrix, then fit +
    bootstrap with the EXACT #522 rig."""
    import numpy as np
    pairs = bakeoff._pairs(cond_ids, nonstylized_only=nonstylized_only)   # 156 or 240
    xv = bakeoff._materialize_predictor_vector(payload, pairs, sub_predictor=None)
    if xv is None:
        return {"status": "predictor_vector_None", "n_pairs": len(pairs)}
    dg       = np.array([G[a][b]["delta_g"]   for a, b in pairs], dtype=np.float64)
    g_logp   = np.array([G[a][b]["g_logprob"] for a, b in pairs], dtype=np.float64)
    ln       = np.array([np.log(prompt_tokens[a][b]) for a, b in pairs], dtype=np.float64)
    fit      = jsreg._fit_row(xv, dg, g_logp, ln, pairs)                  # ρ, CV R² on ΔG + g_logprob
    panel_ci = jsreg._panel_bootstrap_ci(xv, dg, g_logp, ln, pairs, n_boot=N_BOOT, seed=SEED)
    return {"status": "ok", "n_pairs": len(pairs),
            "point_estimate": fit, "panel_ci": panel_ci}

def main():
    # load targets + covariate once
    prompt_tokens = bakeoff._load_prompt_tokens()
    G_by_ep = {ep: bakeoff._load_G(ARM, ep) for ep in EPOCHS}
    for ep in EPOCHS:
        assert set(G_by_ep[ep].keys()) == set(COND_IDS)
    rows = []
    for metric in METRICS:
        for layer in LAYERS:
            payload, cond_ids = compute_xv_full(metric, layer)
            for panel_name, ns_only in (("full", False), ("nonstylized", True)):
                for ep in EPOCHS:
                    rec = fit_panel(payload, cond_ids, ns_only, G_by_ep[ep], prompt_tokens)
                    rec.update({"metric": metric, "layer": layer,
                                "panel": panel_name, "arm": ARM, "epoch": ep})
                    rows.append(rec)
            # checkpoint-per-(metric,layer): write partial JSON each outer iter
            _write(rows, OUT_DIR / "nonstylized_predictor_sweep.json", partial=True)
    _write(rows, OUT_DIR / "nonstylized_predictor_sweep.json", partial=False)  # + git_sha, env, anchors block
```

**Modes:** `--mode smoke` (1 metric × L22 × ep1 × both panels, n_boot=50 — exercises load → metric → fit → bootstrap → write end-to-end in seconds) and `--mode full` (the grid above). A `--mode anchor-check` runs only the full-panel re-derivation comparison (§5).

**Why `_compute_metric_matrix` once per (metric, layer), not once per panel:** the metric matrix is a 16×16 pairwise distance computed on the activation cloud — it is panel-independent. Restricting to the nonstylized panel is purely a downstream pair-selection (`_pairs(..., nonstylized_only=True)` picks the 156 distances). This guarantees the full-panel and nonstylized-panel numbers come from the IDENTICAL distance matrix — the single-variable contract — and halves the eigh cost.

**Why code, not a model call?** N/A — there is no unstructured-data heuristic anywhere in this design. Every step is a deterministic numeric computation (matrix algebra, rank correlation, percentile bootstrap) over already-scored numeric arrays. A model call has no role.

**Data source + realism tier:** N/A for the training-data sense (no training). The *measured* substrate is the #474 ΔG target (a real measured marker-transfer matrix from trained adapters — tier 2 "established prior-issue measurement") and the #502 cached residual streams (real model activations — tier 1 model internals). No synthetic / templated data is introduced.

### 4.3 The reuse decision — why import `issue522_js_regress`, not re-implement the bootstrap

The body says "exactly the rig in `issue511_probe_count_sweep.py` / `issue493_extraction_metric_bakeoff.py`, with panel-row bootstrap CIs (n_boot=2000, seed=42)." Read literally, `issue511_probe_count_sweep.py` does NOT compute panel-row bootstrap CIs — it reports per-(N,R) subset σ (`aggregate`, lines 730–771). The **panel-row bootstrap** (resample the off-diagonal pairs with replacement, refit per resample, 2.5/97.5 percentile) lives in `issue522_js_regress.py::_panel_bootstrap_ci` (lines 139–177), which is itself built on `bakeoff._length_partial` + `sweep_mod._loocv_r2_deterministic`. It is the rig that produced #522's `js_regression.json` panel CIs the body cites as the comparison anchor.

Therefore the faithful reuse is: take the activation predictor vector `xv` from `compute_predictor_vector` (the #511/#502 metric path) and run `_panel_bootstrap_ci` / `_fit_row` / `_percentiles` from `issue522_js_regress` (the #522 bootstrap path) on it. This composes the two parents' rigs exactly as #522 intended for a cross-predictor comparison and produces panel CIs row-compatible with `js_regression.json` (same dict shape: `point_estimate` + `panel_ci` with `rho` / `cv_r2` / `rho_glog` / `cv_r2_glog`). No bootstrap math is re-implemented.
