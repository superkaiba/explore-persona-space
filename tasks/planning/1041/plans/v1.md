## 1. Goal + acceptance criteria

**Requirement.** Add check `c21_cross_section_param_consistency` to `scripts/verify_plan.py`: when the same tracked parameter (`temperature`, `max_tokens`, `max_new_tokens`, `lr`/`learning_rate`, `epochs`, `seed`/`seeds`, `rank`, `alpha`, `batch`/`batch_size`, `top_p`) is stated with contradictory values in *different top-level sections* of a plan, WARN naming both occurrences (param, value, section heading, 1-based line number). This mechanizes the #1024 incident class: a fact-check correction lands in one section while a stale restatement survives in another (§11 *What:* lines, §12 assumption rows), and three critics + the consistency-checker each re-flag it by hand.

**Acceptance criteria:**
1. `c21` WARNs on the #1024 v2 offender shape (§11 `temperature=0.7` vs the corrected "temperature OMITTED … API default 1.0" text) — value-vs-omission IS in v1 scope (see §3 scope note).
2. `c21` does NOT flag: same value restated across sections; values inside historical/never-threaded clauses; sweep/range/brace-set declarations overlapping a single grounded value; per-phase-qualified values; fenced code blocks; stats-`alpha` vs LoRA-`alpha`.
3. WARN-only, all kinds, conditional-SKIP when no tracked param spans ≥2 sections. Exit codes and the `--json` schema are unchanged.
4. All existing `tests/test_verify_plan.py` tests pass after the 4 mechanical count/map updates (§3.6); new tests (a)–(e) pass; `uv run ruff check` clean on both touched files.
5. Calibration run over the named recent-plan sample reports the WARN count (kill criterion in §5).

## 2. Method delta (vs the existing c0–c20)

Every existing check is a **single-section presence/shape check**: locate one section (or the whole text), assert a contract surface exists there (`check_source_grounding` scans §11-shaped text; `check_gpu_hours` scans for one line; `check_verdict_lattice_coherence` parses one registration section). **c21 is the first cross-section comparison**: it builds a `(param → section → value-set)` map over the whole document and asserts pairwise consistency *between* sections. It reuses the existing infrastructure unchanged — `_fence_mask` (verify_plan.py:291) for fence exclusion, `_headings` (:333) for section spans, and a new top-level-section variant of `_innermost_section` (:373) for attribution — and follows the established per-check helper convention (`_c18_*`, `_c20_*` prefixed helpers directly above the check function).

### 3.2 Regexes (module-level `_C21_*` constants, colocated with the check)

```python
_C21_PARAM_TOKENS = (
    r"temperature|max_new_tokens|max_tokens|learning_rate|lr|epochs|"
    r"seeds|seed|rank|alpha|batch_size|batch|top_p"
)  # longer alternatives first where prefixes overlap
_C21_ALIASES = {"learning_rate": "lr", "seeds": "seed", "batch_size": "batch"}
_C21_NUM = r"(?:[0-9]+(?:\.[0-9]+)?|\.[0-9]+)(?:[eE][+-]?[0-9]+)?"
# param=value / param: value; tolerates `code`/**bold** wrappers; captures a
# single numeric, a comma-run of numerics, or a {...} brace set (≤120 chars).
_C21_VALUE_RE = re.compile(
    rf"(?i)\b(?P<param>{_C21_PARAM_TOKENS})\b\s*[=:]\s*[`*]{{0,2}}\s*"
    rf"(?P<vals>\{{[^}}\n]{{0,120}}\}}|{_C21_NUM}(?:\s*,\s*{_C21_NUM})*)"
)
# range/schedule continuation right after the captured value: "1e-4 → 1e-5", "1-3"
_C21_RANGE_TAIL_RE = re.compile(rf"\s*[`*]{{0,2}}\s*(?:[-–—]|->|→)\s*[`*]{{0,2}}({_C21_NUM})")
# omission assertion: the #1024 corrected-text shape ("temperature OMITTED")
_C21_OMIT_RE = re.compile(
    rf"(?i)\b(?P<param>{_C21_PARAM_TOKENS})\b\s+(?:is\s+)?(?:omitted|left\s+unset)\b"
)
# historical / declared-but-never-threaded clause vocabulary (value occurrences only)
_C21_EXCLUDE_RE = re.compile(
    r"(?i)declared but never|never threaded|not threaded|never used|\bpreviously\b|"
    r"superseded|corrected (?:from|to)|historical|\bstale\b|deprecated|no longer|"
    r"old (?:value|default)|\bwas\b"
)
_C21_SWEEP_LINE_RE = re.compile(r"(?i)\bsweeps?\b|\bgrid\b|ablation")
_C21_PHASE_RE = re.compile(r"(?i)\bphase[\s-]*([0-9]+)\b")
_C21_LORA_CTX_RE = re.compile(r"(?i)lora|rslora|\brank\b|adapter|peft")
```

Notes: `\b` before the param token means `JUDGE_TEMPERATURE=0.7` never matches (underscore is `\w` — this is what keeps the #1024 *Source:*/assumption-row mentions of `JUDGE_TEMPERATURE=0.7` out of the pool without any exclusion logic). `max_tokens` and `max_new_tokens` stay **distinct keys** (different constructs: API judge cap vs HF generate cap).

### 3.3 Extraction + grouping pseudocode

```python
lines = plan.splitlines()
mask = _fence_mask(lines)              # fenced launch commands never vote (module convention:
headings = _headings(plan)             # "example commands inside fences can neither satisfy
occ: dict[key, dict[sec, Rec]] = {}    #  nor trip a prose-contract check")
for i, line in enumerate(lines):
    if mask[i]: continue
    phase = f"@phase{m.group(1)}" if (m := _C21_PHASE_RE.search(line)) else ""
    for m in _C21_VALUE_RE.finditer(line):
        param = _C21_ALIASES.get(m["param"].lower(), m["param"].lower())
        if param == "alpha" and not _C21_LORA_CTX_RE.search(line): continue   # stats-α guard
        if _C21_SWEEP_LINE_RE.search(line): continue                          # sweep/grid line
        window = line[max(0, m.start() - 100) : m.end() + 100]                # same-line ±100ch
        if _C21_EXCLUDE_RE.search(window): continue                           # historical clause
        vals = {float(v) for v in re.findall(_C21_NUM, m["vals"])}            # {} set → all members
        if not vals: continue                                                 # non-numeric set
        if tm := _C21_RANGE_TAIL_RE.match(line, m.end()): vals.add(float(tm.group(1)))
        _c21_record(occ, param + phase, _c21_top_section(headings, i), vals, i, m.group(0))
    for m in _C21_OMIT_RE.finditer(line):                                     # NO exclusion filter:
        param = _C21_ALIASES.get(m["param"].lower(), m["param"].lower())      # "OMITTED — never set"
        _c21_record(occ, param + phase, _c21_top_section(headings, i), {"OMITTED"}, i, m.group(0))
```

`_c21_top_section(headings, i)`: among headings containing line `i` with `level >= 2`, return the shallowest (the H2 ancestor — so sibling H3 phase subsections under one `## 4. Design` are ONE group); fall back to `_innermost_section` (covers H1-only docs), else a synthetic `(-1, "(preamble)")`. Key = `(heading.line, heading.text)`. `Rec` keeps the union value-set plus the first `(lineno, matched-span)` per (param, section) for the WARN detail.

**Conflict rule:** for each key spanning ≥2 sections, any pair of sections with **disjoint** value sets is a conflict (first disjoint pair reported per param). Overlap = consistent — this is what makes per-arm tables restated in §11 (`{1e-4, 1e-5}` vs `{1e-4, 1e-5}`), schedules (`lr=1e-4 → 1e-5` parsed as `{1e-4, 1e-5}` vs a §11 `lr = 1e-4`), and seed lists (`Seeds: {42, 137, 256}` vs a §10 `seed=137`) all PASS while `0.7` vs `OMITTED`/`1.0` WARNs. Float parsing makes `1e-4` == `0.0001`.

**WARN detail** (≤2 conflicts + "…and N more param(s)"):
`temperature: 'temperature=0.7' (§'11. Hyperparameter grounding' L272) vs 'temperature OMITTED' (§'7. Decision gates' L161) — cross-section contradiction; if one side is a stale post-correction restatement, fix it`

### 3.4 Scope decision: value-vs-omission IS caught (and why it must be)

In #1024 v2, prose carries exactly ONE `temperature=<num>` token (`plans/v2.md:272`, the §11 item-6 *What:* line — verified; the other 0.7s are `JUDGE_TEMPERATURE=0.7`, unmatched per §3.2, and "default temperature (1.0)" / "T=1.0" match nothing). A value-vs-value-only v1 would therefore MISS its own motivating incident. The omission arm (`temperature OMITTED`, v2.md:161) supplies the second side. **v1 scope:** value-vs-value + value-vs-literal-omission-token (`<param> OMITTED|omitted|left unset`). Broader omission phrasings ("builders omit temperature", "no temperature parameter") are OUT of v1 scope — stated in the check docstring. Omission matches are exempt from `_C21_EXCLUDE_RE` because the corrected text legitimately reads "temperature OMITTED — the builders never set it": the "never set" *explains* the omission (self-consistent), it does not mark it historical; exclusion filtering applies to value occurrences only.

### 3.5 False-positive strategy (explicit)

Layered, each layer killing one named FP class: (1) **fence mask** — per-seed/per-arm launch commands in ``` blocks never vote; (2) **top-level-section grouping** — sweeps/tables/per-phase H3s inside one section can't self-conflict; (3) **set-overlap instead of set-equality** — per-arm restatements, ranges, seed lists; (4) **phase-qualifier keying** — `Phase 1 … epochs=3` vs `Phase 2 … epochs=1` get distinct keys; (5) **sweep-line skip** (`sweep|grid|ablation`); (6) **historical-clause exclusion** in a same-line ±100-char window (window-bounded so a 900-char line's distant vocabulary can't wrongly exclude, cf. v2.md:148); (7) **LoRA-context gate on `alpha`** (stats `alpha = 0.05` never pairs against `LoRA alpha = 64`); (8) **WARN-only + conditional SKIP** as the semantic backstop. Residual accepted noise: unqualified per-phase values in different H2s, and genuinely different judge-vs-generation `temperature`s stated without qualifiers — bounded by the §5 calibration and tunable (§9 deviations).
