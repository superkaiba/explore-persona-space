# Plan v2 — #2607: worktree-staleness guard for verify_task_body.py per-task sibling resolution

`kind: infra` (workflow-surface fix). Routed from the #2378 CRC r7 workflow-fix candidate.

## Requirement + acceptance criteria (from task body)

Requirement: `verify_task_body.py` must never audit a worktree-frozen per-task
state file (`concerns.jsonl`, and by the same mechanism `plans/plan.md`,
`original-body.md`) as if it were current. In the #2378 incident (2026-08-26,
interpretation v9 fold) the analyzer's verifier run resolved the task folder
inside the issue worktree, whose frozen `concerns.jsonl` (139 lines) predated 5
open CONCERN-severity rows; the run reported OVERALL PASS (77 checks) while both
clean-result-critic twins' main-root runs FAILed Lens 14 on the same 5
unacknowledged concerns. Cost: one full CRC ensemble round.

Acceptance (verbatim from body):
1. `verify_task_body.py` resolves the concerns ledger (and any other per-task
   events/comments reads) via task_workflow/main-checkout resolution regardless
   of cwd, OR refuses with a named stale-worktree path when the resolution lands
   inside `.claude/worktrees/`.
2. A regression test pins the guard (worktree fixture with a stale
   `concerns.jsonl` vs newer main-root rows).
3. `analyzer.md` verify-step prose names the trap.

## Root cause (measured, clarifier context)

- The `--issue` path is ALREADY safe: `_load_text_for_issue()` →
  `task_workflow.find_task_path()` → `repo_root()`, which resolves via
  `git rev-parse --git-common-dir` from the module dir and branch-guards to the
  main checkout (scripts/verify_task_body.py:20335-20340;
  src/explore_persona_space/task_workflow.py:726).
- The stale channel is the `--file` path: `_resolve_file_siblings()`
  (scripts/verify_task_body.py:20343) derives `concerns.jsonl` /
  `plans/plan.md` / `original-body.md` from the body path's PARENT DIR. A
  worktree-resident `tasks/<status>/<N>/body.md` (e.g. a cwd-relative
  `tasks/...` path formed from a worktree cwd — the CLAUDE.md "never form
  tasks/... paths relative to cwd" trap) silently yields the frozen ledger.
- Per-task state (`body.md`, `concerns.jsonl`, `plans/`, `original-body.md`)
  mutates ONLY on the main checkout via `task.py`; a worktree's `tasks/` tree is
  frozen at the branch-cut base commit. So a worktree-resolved per-task sibling
  is ALWAYS stale — unlike `--methodology-doc` / `--eval-root`, which are
  passed worktree paths DELIBERATELY at the Step 9a-bis pre-merge gate (those
  artifacts land on the issue branch first and are out of scope here).

## Design decision: REFUSE (fail-loud), plus an API-level Lens-14 backstop

The body permits either "re-resolve via task_workflow" or "hard-WARN/FAIL naming
the stale path". Decision: **refuse** on the CLI `--file` leg, and **hard-FAIL
Lens 14** at the API level.

Rationale: in a worktree `tasks/` tree the BODY TEXT is frozen too, not just the
siblings — silently redirecting the ledger to the main checkout while verifying
a stale body would produce a differently-wrong verdict (PASS/FAIL rendered
against text that is not the task's current body). Refusal forces the caller
onto the already-safe `--issue` path (or the main checkout's body path), which
is what every sanctioned workflow site already does. Grep evidence (clarifier +
plan-time): all sanctioned `--file` callers pass `/tmp` or `.claude/cache`
draft paths (analyzer.md:476, steps/13-step-9.md:724,
promote-clean-result/SKILL.md:227); real-task-body verification uses `--issue`.
Zero legit-caller blast radius.

## Change set (file paths + concrete diffs)

### 1. `scripts/verify_task_body.py`

a. **New helper** (near `_resolve_file_siblings`, ~line 20343):

```python
def _worktree_resident(p: Path) -> bool:
    """True when the resolved path lives inside a linked git worktree of
    this repo. Arm A (pure path, always available): consecutive
    ('.claude', 'worktrees') components in p.resolve().parts. Arm B
    (best-effort): p is under a non-primary worktree path from
    `git worktree list --porcelain` run at `_resolve_repo_root()` —
    reuses `_parse_worktree_list` (already in this module, #2288);
    any subprocess/resolution failure degrades to arm A alone.
    """
```

b. **CLI guard in `main()`, `--file` branch** (~line 20437): after
`body_source_path = Path(args.file).resolve()`, when
`body_source_path.parent.name.isdigit()` (task-layout parent) AND
`_worktree_resident(body_source_path.parent)`: print a refusal to stderr
naming the frozen path and the remedy, `return 2` (the existing refusal
exit-code convention, matching the `--issue` FileNotFoundError branch).
Message shape:

```
verify_task_body: REFUSED — <path> is a worktree-frozen tasks/ tree
(per-task state mutates only on the main checkout; this copy is frozen at
the branch-cut base commit and its concerns.jsonl/plans/original-body.md
siblings are silently stale — #2607, incident #2378 r7). Re-run with
--issue <N> (resolves via the branch-guarded task_workflow registry
against the main checkout) or pass the main checkout's
tasks/<status>/<N>/body.md path.
```

`<N>` from the digit parent name. Non-task-layout worktree `--file` paths
(e.g. a worktree `.claude/cache/` draft) are UNCHANGED — verifying draft
bytes the caller just wrote is legitimate, and sibling resolution already
returns None there.

c. **API-level backstop in `check_concerns_audit`** (~line 16663): BEFORE the
existing `concerns_path is None or not exists` skip, when
`concerns_path is not None` AND `_worktree_resident(concerns_path)`: return a
FAIL CheckResult — `"worktree-frozen concerns.jsonl at <path> — per-task
ledgers mutate only on the main checkout; rerun via --issue / the main
checkout path (#2607)"`. Fires regardless of `exists()` (a frozen tree whose
ledger predates the task's FIRST concern row would otherwise skip-PASS — the
same false-PASS shape). Covers future direct `verify_text(...,
concerns_path=...)` callers that bypass `main()`.

d. **Docstring updates**: the check-14 catalog entry (~line 337) and the
`check_concerns_audit` docstring gain one line each naming the
worktree-staleness guard + #2607.

## Kill criteria

- A sanctioned workflow site is discovered that REQUIRES `--file` on a worktree
  `tasks/` body (none found at plan time) → the refusal design is wrong; pivot
  to the redirect-with-note design (resolve siblings via
  `find_task_path(file_issue)`, FAIL only when resolution raises).
- The Lens-14 backstop FAILs any existing test built on legitimate tmp
  fixtures → the detection arms are over-broad; tighten to arm A only.
