## Method delta (vs #2357, the parent fix)

#2357 added an assignment-prefix-tolerant lead grammar (`CWD_MOVER_LEAD_ERE`,
`.claude/hooks/guard_root_code_commit.sh:339`) on the DISARM side of the commit-scoping
guard. This task mirrors the same lead grammar components into the branch guard's
sticky-scope invalidator — a different file, different consumer (scope voiding before
the re-arm greps), same fail-closed direction. No new grammar is invented: the prefix
group and quote-tolerance groups are copied from the sibling's proven ERE.

## Design decisions (recorded; critic may challenge)

- **D1 — prefix group mirror.** Insert the sibling's prefix group
  `(([A-Za-z_][A-Za-z0-9_]*[+]?=[^[:space:]]*|time([[:space:]]+-p)?)[[:space:]]+)*`
  immediately after the existing `^[[:space:]({]*` anchor at L2109, before the
  `((builtin|command)…)*` wrapper group. Covers P2-P6. Over-match on non-shell-legal
  interleavings (e.g. `VAR=1 time cd`, which runs /usr/bin/time and does not move cwd)
  is accepted: fail-closed, invalidation-only.
- **D2 — quote/backslash tolerance mirror.** Wrap the mover word:
  `["'\''\\]*(cd|pushd|popd)["'\''\\]*` (the sibling's adjacent-quote-tolerance idiom).
  Covers P7 (`\cd` genuinely moves cwd; verified false-allow above). Zero legit-use
  cost: a quoted/escaped cd still cds. The re-arm greps stay strictly `^cd`-anchored,
  so no quoted spelling ever ARMS — invalidate-but-never-arm, consistent with the
  existing paren-prefix asymmetry.
- **D3 — mover word set NOT widened (no `source`/`.`/`eval`).** The concern is
  prefix-blindness of the EXISTING anchor (movers: cd|pushd|popd). Unprefixed
  `source x` does not invalidate today, so there is no prefix-gap for those words —
  source-blindness is a DISTINCT gap. Widening would false-block the common legit
  in-worktree pattern `cd <wt> && source .venv/bin/activate && git …` (hard exit-2
  block in this guard, vs the sibling's soft whole-index fallback — very different
  blast radius). The task Goal's `VAR=value . ./script` example is therefore
  deliberately NOT covered; this scope decision is named honestly in the test-file
  comment and the completion report, and the residual is LOGGED as a finding (not
  auto-filed — this session is under the workflow-fix recursion guard).
- **D4 — `_cd_guard_tail_exits()`'s `cwd_word_re` (L1995) untouched.** It sits on the
  ARMING path (exit-guard tail recognizer); the task requires arming/allow paths
  intact. No false-allow is constructible from its prefix-blindness: Case-B acceptance
  requires the group to end in an unconditionally-reached `exit`, so any mover inside
  an accepted tail runs only on the cd-failure path and the shell exits before any
  later git clause. One-line note added to its comment is allowed but not required.
- **D5 — single-site edit.** Only the L2109 ERE (one grep inside the clause loop)
  changes, plus adjacent comment prose and tests.
