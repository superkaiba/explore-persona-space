## Requirement + acceptance criteria

`scripts/guard_repo_root_branch.sh` (single inline site, L2108-2112) must recognize a
cwd-moving clause whose command word is preceded by legal shell prefixes — variable
assignments (`VAR=v`, `VAR+=v`, multiple; plain, double-quoted, single-quoted,
backslash-escaped, and unnested substitution values), the `time` / `time -p` wrapper
keyword, and (quote tolerance) an escaped/quoted command-word spelling — and void the
plain latch + sticky scope exactly as it does for the unprefixed spelling. Fail-closed
direction only: the change may only ADD invalidations, never permit and never arm.

`.claude/hooks/guard_root_code_commit.sh:339`) on the DISARM side of the commit-scoping
guard, with quoted-value coverage supplied by a separate masked-copy grep (L326-339).

## Design decisions (recorded)

- **D1 — prefix group mirror.** Insert an assignment/time prefix group immediately
  after the existing `^[[:space:]({]*` anchor at L2109, before the
  `((builtin|command)…)*` wrapper group: `((ASSIGN|time([[:space:]]+-p)?)[[:space:]]+)*`
  where `ASSIGN = [A-Za-z_][A-Za-z0-9_]*[+]?=VALUE`. Covers P2-P6. Over-match on
  non-shell-legal interleavings (e.g. P14 `VAR=1 time cd`, which runs external time and
  does not move cwd) is accepted AND pinned as BLOCK: fail-closed, invalidation-only.
- **D1b — extended value atom (v2, critic Must-Fix).** `VALUE` tolerates quoted and
  unnested-substitution spans, not just `[^[:space:]]*`. Candidate (POSIX ERE; the
  implementer resolves the exact byte form inside the script's single-quoted context
  and MUST verify every table row against the realized regex with executed probes):
  `([^[:space:]"'\\]|"[^"]*"|'[^']*'|\\.|\$\([^)]*\)|\$\{[^}]*\}|` + backtick-span
  `)*`. Covers P10-P12; P13 (nested substitution with a space after an inner close)
  remains a NAMED residual — the value atom stops at the interior space, the clause
  no-matches, scope survives. Residual is disclosed in the guard comment, the test
  comment block, and the completion report. Fail-closed unaffected: a residual
  no-match only RETAINS current behavior; every new match is an invalidation.
- **D2 — quote/backslash tolerance mirror.** Wrap the mover word:
  `["'\\]*(cd|pushd|popd)["'\\]*` (the sibling's adjacent-quote-tolerance idiom;
  byte form per the script's quoting). Covers P7 (`\cd` genuinely moves cwd). Zero
  legit-use cost. The re-arm greps stay strictly `^cd`-anchored, so no quoted/prefixed
  spelling ever ARMS — invalidate-but-never-arm, consistent with the existing
  paren-prefix asymmetry.
- **D3 — mover word set NOT widened (no `source`/`.`/`eval`).** The concern is
  prefix-blindness of the EXISTING anchor (movers: cd|pushd|popd). Unprefixed
  `source x` does not invalidate today, so there is no prefix-gap for those words —
  source-blindness is a DISTINCT gap. Widening would false-block the common legit
  in-worktree pattern `cd <wt> && source .venv/bin/activate && git …` (hard exit-2
  block in this guard, vs the sibling's soft whole-index fallback). The task Goal's
  `VAR=value . ./script` example is therefore deliberately NOT covered; named honestly
  in the test-file comment and completion report; residual LOGGED as a finding (not
  auto-filed — this session is under the workflow-fix recursion guard). A
  source-retention pin documents the decision
  (`cd <wt> || exit 1` + `source .venv/bin/activate` + git op stays rc=0).
- **D4 — `_cd_guard_tail_exits()`'s `cwd_word_re` (L1995) behavior untouched; comment
  note REQUIRED (v2).** It sits on the ARMING path (exit-guard tail recognizer); the
  task requires arming/allow paths intact. No false-allow is constructible from its
  prefix-blindness: Case-B acceptance requires the group to end in an
  unconditionally-reached `exit`, AND (critic-verified) the fixed L2109 invalidator's
  `sticky_arm_at=-1` reset voids the pending arm at any group-internal prefixed-mover
  clause. Record exactly that in a one-line comment at the function.
- **D5 — single-site behavioral edit.** Only the L2109 ERE (one grep inside the clause
  loop) changes behavior, plus comment prose (L2098-2106, `_cd_guard_tail_exits()`
  header) and tests.
