## 2. Method delta — why a NEW pass, and which primary mechanism

**Primary mechanism: the watcher audit pass (alert-first), NOT a SKILL.md Step-10 reordering.** Reordering `epm:done` to after the 10d merge only moves the kill window (merge succeeds → done-posting turn killed → task stuck below `completed`, the same invisibility one step earlier); a session kill can land between ANY two turns, so no ordering eliminates the gap. A merge-pending sentinel adds new cross-surface state (SKILL writes, watcher reads) with its own staleness lifecycle. The audit pass reads only markers that already exist, covers the sibling `epm:merge-failed`-sat-unactioned case for free, and is additive + non-architectural — the house escalate-only posture (`stale_blocked_flag_pass`, line 17138, is the direct precedent).

**Why a new pass rather than extending one:** `stale_blocked_flag_pass` scans the `blocked` set via `_blocked_issue_ids()` (line 13773) — a different population (tens of tasks, per-issue `_task_events` subprocess) than the completed sweep (~113 recent tasks needing direct-file parses and a self-gate). `registry_drift_pass` (6154) contributes the interval throttle pattern; `triage_observer_pass` contributes the registry-snapshot + events-mtime enumeration (`_triage_observer_sweep_issue`, 5219). The new pass composes these three patterns; grafting it onto any one of them would break that pass's population contract.

**Re-drive decision (verified before committing, per the brief):** the SKILL.md resume table has NO row for `completed` + no-`epm:merged` + unmerged PR — the Step-10d-backstop row exists only for `awaiting_promotion` (SKILL.md:11601, read verbatim; `grep '^| .*completed.*|'` over the resume-table region finds only the followup-scope and followups_running rows). A re-driven bare `/issue <N> --auto` on a `completed` task therefore has NO mechanically-pinned route to Step 10d. **v1 ships alert-only, with NO re-drive arm.** The alert names the manual recovery (spawn a session prompted to run the Step 10d residual pass — exactly what recovered #1540). Follow-up for the orchestrator (prose, not this plan): add a `completed` + no-`epm:merged` + PR-unmerged resume-table row mirroring line 11601; once that lands, an opt-in re-drive arm becomes mechanically safe to add here.

### 3.2 The pure predicate (extracted for tests, house style)

```python
def decide_completed_unmerged_flag(
    status: str | None,
    done_ts: float | None,        # latest epm:done
    merged_ts: float | None,      # latest epm:merged (any form, incl. artifact_confirmed)
    merge_failed_ts: float | None,# latest epm:merge-failed
    now: float,
    *, grace_s: float, lookback_s: float,
) -> bool:
    """True iff a completed task's merge is plausibly stranded. EVERY missing
    signal returns False (fail toward silence). epm:merge-failed does NOT
    suppress — it re-anchors the grace window (an in-flight retry after a
    surfaced merge failure gets grace; one sitting > grace_s is the same
    invisibility problem and IS flagged — decision per §3.4 class C)."""
    if status != "completed" or done_ts is None:
        return False
    if merged_ts is not None:
        return False                      # merged (Step 9b, 10d, or artifact-confirmed)
    if (now - done_ts) > lookback_s:
        return False                      # bounded lookback: old completions out of scope
    anchor = max(done_ts, merge_failed_ts or 0.0)
    return (now - anchor) >= grace_s      # grace: a merge in flight is not flagged
```

**Trace against the real #1540 artifact (measured 2026-07-20 from `tasks/completed/1540/events.jsonl`):** `epm:done` at 2026-07-19T14:49:17Z; NO `epm:merged`/`epm:merge-failed` until 2026-07-20T06:57:10Z. At any pass tick in (16:49Z Jul-19 → 06:57Z Jul-20): status=`completed`, done_ts set, merged_ts=None, age < 72h, gap > 2h ⇒ **True** (fires ~13h before the actual recovery). Post-recovery (today's state): merged_ts=2026-07-20T06:57:10Z ⇒ **False**. Both arms fire correctly on the motivating artifact.

### 3.3 The pass skeleton

```python
def completed_unmerged_pass(dry_run: bool, now: float | None = None) -> None:
    """Flag-only audit: completed + epm:done + NO epm:merged + unmerged PR/branch
    (task #1564, incident #1540). Daemon-INDEPENDENT (no spawns; marker posts go
    via the task.py subprocess, like stale_blocked_flag_pass)."""
    if not _completed_unmerged_enabled(): print("...disabled; skipping"); return
    now = now or time.time()
    state = _load_completed_unmerged_state()
    if in_interval(state.get("last_run_ts"), now, EPM_COMPLETED_UNMERGED_INTERVAL_HOURS):
        return                                    # hourly self-gate (registry_drift pattern, 6182)
    state["last_run_ts"] = now; _save_completed_unmerged_state(state, dry_run)  # attempt-stamp-first
    probes_left = PROBE_CAP
    for issue, task_dir in _completed_unmerged_candidates(now):   # cheap gate, §3.5
        done_ts, merged_ts, mf_ts = _completed_unmerged_read_events(task_dir / "events.jsonl")
        if not decide_completed_unmerged_flag("completed", done_ts, merged_ts, mf_ts, now,
                                              grace_s=..., lookback_s=...):
            _prune_resolved(state, issue, merged_ts)              # merged appeared → prune + log recovered
            continue
        if probes_left <= 0: print("  probe cap reached; remaining candidates next interval"); continue
        probes_left -= 1
        verdict = _completed_unmerged_probe(issue)                # §3.6; fail-soft
        if verdict in ("nothing-to-merge", "resolved-merged-pr"): _prune_resolved(...); continue
        if verdict == "probe-failed": print(f"  #{issue}: probe failed; skip this interval"); continue
        _flag(issue, done_ts, mf_ts, verdict, state, now, dry_run)  # §3.7 channels + dedup
    _save_completed_unmerged_state(state, dry_run)
```

### 3.4 False-positive classes (each handled, each unit-tested)

- **(A) Completed, no PR, no commits ahead** (Step 10d logs "No PR for issue-<N>; nothing to merge." and posts NOTHING — SKILL.md:10284): cheap predicate fires, probe returns `nothing-to-merge` ⇒ skip + prune. Absence of `epm:merged` alone is never a defect.
- **(B) `epm:merged` with `artifact_confirmed: true`, PR deliberately left OPEN** (SKILL.md:9643/10892/11227): merged_ts is set ⇒ predicate False; the probe never runs, so the open PR is irrelevant.
- **(C) `epm:merge-failed` present:** flagged, staleness-gated — the marker surfaced the failure once, but if it sits > grace with the branch still unmerged it is the same invisibility (the retry path is "idempotent retry on next /issue invocation", which nothing schedules on a completed task). merge_failed_ts re-anchors the grace so an active retry isn't flagged. The flag note names the merge-failed presence.
- **(D) Happy-path experiment (Step 9b merge → promote → completed → `epm:done`):** `epm:merged` predates `epm:done` — predicate keys on merged-ABSENCE, not ordering ⇒ False. (Deliberately NOT "merged newer than done": that would false-positive on every promoted experiment.)
- **(E) Old completed tasks:** 72h lookback on done_ts + the candidate gate's events-mtime filter bound the population; a merge in flight is covered by the 2h grace.
- **(F) Archived tasks: OUT of scope** — archived = deliberately abandoned/duplicate; an unmerged branch there is intentional (won't-fix). Predicate requires status == `completed` exactly.
- **(G) Rebase-merge SHA rewrite:** after `gh pr merge --rebase`, `rev-list origin/main..origin/issue-<N>` stays nonzero forever (rewritten SHAs). The probe uses PR state first (authoritative) and patch-id-based `git rev-list --cherry-pick --right-only --count` for the no-PR branch check, so an already-landed branch reads 0.

### 3.5 Cheap candidate gate (`_completed_unmerged_candidates`)

Registry-snapshot enumeration, the `_triage_observer_sweep_issue` pattern (5219–5241): read `tasks/REGISTRY.json` once via `task_workflow.registry_path()` (import shape at 5339/5358); keep rows with `status == "completed"`; resolve `reg_root / meta["path"] / "events.jsonl"` (registry-supplied path — never hand-built from cwd) and keep those with mtime within lookback. Measured live: 113 candidates at 72h. `_completed_unmerged_read_events` then direct-parses each file's JSON lines fail-soft (json.loads per line, skip garbled), extracting only the three kind timestamps — no `_task_events` subprocess (that helper spawns one `task.py` process per issue, ~1–2s; 113 × 1.5s ≈ 3 min/pass is the anti-pattern this direct parse avoids; total direct-parse cost ≈ <1–2s). Fast path: if the raw text lacks the fragment `"kind": "epm:done"`, skip without parsing (a serialization change degrades this to a full parse via the merged-side check ordering, never to a silent miss — the parse is authoritative for firing).

### 3.6 Probe (`_completed_unmerged_probe`, fail-soft, only on predicate hits — measured 0/pass steady state)

```
1. gh pr list --head issue-<N> --state open  --json number,isDraft   → any row ⇒ "unmerged-open-pr" (#1540: PR 1312 OPEN+draft)
2. gh pr list --head issue-<N> --state merged --json number          → any row ⇒ "resolved-merged-pr" (marker post failed after a real merge — skip+prune, log loudly)
3. no PR: git rev-parse --verify --quiet refs/remotes/origin/issue-<N>  → absent ⇒ "nothing-to-merge"
4. git rev-list --cherry-pick --right-only --count origin/main...origin/issue-<N>
       > 0 ⇒ "unmerged-branch-commits" ; == 0 ⇒ "nothing-to-merge"
```
Any subprocess error/timeout (10s each) ⇒ `"probe-failed"` ⇒ skip-with-log, no state write, retried next interval — a gh outage can never crash the tick or latch a false state. Probe capped at 10/pass (`EPM_COMPLETED_UNMERGED_PROBE_CAP`) bounding worst-case external time to ~40s. No `git fetch` in the pass (read-only; local `origin/issue-<N>` staleness fails toward flagging with the PR check as the authoritative first rung).

### 3.7 Channels + dedup (all existing helpers)

On a confirmed flag, keyed **per episode = (issue, done_ts)** (a later follow-up round posts a new `epm:done` ⇒ new episode):
- **Sidecar row** (always): `{"ts", "issue", "done_ts", "merge_failed_ts", "verdict", "action": "flagged", "dry_run"}` appended to `.claude/cache/completed-unmerged-events.jsonl`.
- **Task marker** (once per episode): `_post_progress_marker(issue, note, dry_run, label="completed-unmerged-flag")` — note carries the sentinel + "`completed` with `epm:done` (<iso>) but NO `epm:merged`; <verdict detail: PR #x OPEN / N branch commits>; likely a killed Step 10d merge turn (#1540 class). Recover: spawn a session on issue <N> and run the SKILL.md Step 10d auto-merge procedure (residual pass). FLAG-ONLY: the watcher never merges."
- **Telegram push** (deduped): once at episode open; re-push while unresolved every 24h (`REALERT_HOURS`) — registry-drift/root-draft TTL shape. Push text mirrors the marker's one-liner.
- **Resolution pruning:** when a later interval reads merged_ts set (or probe says resolved/nothing) the episode entry is pruned + "recovered" logged — a re-strand re-fires fresh.
- **No status mutation, no merge, no spawn — hard invariant** (pinned by test, §6).

## 9. §11 Decision Rationale (load-bearing constants)

- **Grace window 2h** — What: min age of `epm:done` (re-anchored by `epm:merge-failed`) before flagging. Why: the 10d merge normally lands minutes after `epm:done` in the same session; 2h clears the longest observed lint-gate/recovery merge turns. Source: `EPM_STALE_BLOCKED_PROGRESS_FRESH_S` default 2h (stale-blocked pass) + the incident timeline (#1540 gap 16h). Alternatives: 30min (false-positive risk on long merge turns), 6h (needless latency).
- **Lookback 72h** — What: max age of `epm:done` (+ events-mtime candidate gate). Why: covers a weekend of unwatched strandings; bounds the sweep to ~113 tasks (measured).
