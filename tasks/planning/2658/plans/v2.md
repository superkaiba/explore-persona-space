# Plan — unified standalone real-answer direction/probe validation

## 0. Decision summary

Run a fresh development pilot for all eleven direction/surface rows before sealed-test collection. The pilot fixes constructs, source frames, response/activation schemas, judge instruments, label reliability, within-prompt discordance, cluster power, throughput, and cost. Existing banks may inform source design and power only; they never train the confirmatory probes or supply test rows.

Estimated GPU-hours (total): 80

This is an upper production envelope, not permission to spend it blindly. Phase P0-P3 pilot target is <=8 GPU-hours. A mandatory pre-test gate reports measured GPU-hours, Anthropic Batch API dollars, and human-annotation load; sealed-test generation does not start if the projected total exceeds this envelope or the human contingency is unavailable.

## 1. Goal and hypotheses

Goal: test whether a score computed from one raw L19 answer vector predicts answer semantics on unseen content superfamilies.

- H1: the exact frozen external direction has conditional macro AUROC >0.5 using its preregistered sign.
- H2: a development-trained L2 logistic probe has conditional macro AUROC >0.5.
- H3: the probe improves conditional macro AUROC over the external direction.
- Null/opposite effects are failures, never sign-flipped successes.

## 2. Registered rows

Eleven rows: evil, sycophancy, hallucination, refusal, assistantness, casualness, impoliteness, harmful compliance, correctness-math, correctness-MMLU-Pro, and correctness-code. All use Qwen/Qwen2.5-7B-Instruct, bf16, layer 19, and a single canonical answer-span-mean residual vector.

## 3. Constructs and labels

Before generation, persist a construct table mapping every frozen vector extraction contrast to an answer-level rubric, positive/negative anchors, exclusions, and confounds. Semantic targets are malicious intent, sycophantic agreement with an unsupported claim, unsupported atomic factual claims against a frozen evidence packet, refusal/non-engagement, substantive harmful assistance with semantic refusal fixed to zero, output-level assistant behavior, casualness, impoliteness, and objective correctness.

Judge model is claude-sonnet-4-5-20250929 with hashed system/user/rubric/evidence prompts, temperature 1, generous max_tokens, five deterministic draw IDs, median aggregation, and binary threshold median>=50. Transport/malformed outputs retry three times then route to human adjudication; they are not semantic refusals or drops. A provider-drift canary prohibits mixed judge revisions.

Both development and test labels require blinded double-human probability audits sized to contain at least 100 adjudicated positives and negatives per trait. Gates are lower 95% sensitivity and specificity >=0.80, kappa >=0.70, and ICC >=0.75. Failure routes both banks to complete human adjudication or not-estimable. Correctness uses objective executable/reference labels.

### Measurement validity by dependent variable

Every row predicts a semantic property of the same retained answer whose raw L19 vector is scored. The confirmatory metric is conditional macro AUROC on the held-out source/domain frames described below; global AUROC is descriptive only.

| Row/DV | Answer-level construct | Operational label/metric | On-distribution status |
|---|---|---|---|
| evil | malicious intent or endorsement in the answer | blinded rubric probability, median threshold >=50; conditional macro AUROC | unseen content superfamilies from the same registered source frames |
| sycophancy | agreement with a user claim despite frozen evidence showing the claim is unsupported | blinded evidence-conditioned rubric; conditional macro AUROC | unseen claims and problem lineages |
| hallucination | at least one unsupported atomic factual assertion relative to the frozen evidence packet | blinded atomic-claim rubric; conditional macro AUROC | unseen evidence packets and lineages |
| refusal | semantic refusal/non-engagement | blinded rubric; conditional macro AUROC | unseen requests within registered strata |
| assistantness | output-level assistant behavior rather than merely fluent continuation | blinded rubric; conditional macro AUROC | unseen prompt lineages and templates |
| casualness | informal/casual register | blinded style rubric; conditional macro AUROC | unseen topics and lineages |
| impoliteness | rude, insulting, or disrespectful language | blinded style rubric; conditional macro AUROC | unseen topics and lineages |
| harmful compliance | substantive actionable assistance that facilitates harm; semantic refusals are fixed to zero | blinded harm-conditioned rubric; conditional macro AUROC | unseen harm categories and request lineages |
| correctness-math | final answer/reference correctness | exact/reference or executable checker; conditional macro AUROC | held-out math families |
| correctness-MMLU-Pro | selected-option correctness | frozen answer key; conditional macro AUROC | held-out subject/problem lineages |
| correctness-code | functional correctness | frozen executable tests in a sandbox; conditional macro AUROC | held-out task families |

For every judged DV, report semantic-label missingness, malformed/transport loss, and provider-side API refusals separately by row and source/stratum arm. In particular, `n_api_refusal` counts Batch responses with `stop_reason == "refusal"` and empty content. Those rows receive targeted synchronous re-issue at the identical frozen judge instrument; persistent failures route to human adjudication and are never silently dropped.

## 4. Data and sampling

Data realism: source/domain frames use established benchmarks and real prompt sources wherever available; diverse generated prompts are allowed only for constructs lacking suitable established data and are separately stratified. No response is activation-steered.

For each row construct four named source/domain frames crossed with three task/difficulty elicitation strata designed on development data to retain stochastic class overlap rather than encode deterministic positive/negative conditions. Content superfamily is the connected component of underlying problem, duplicate/near-duplicate, and rephrase. Development and test sample disjoint superfamilies.

Pilot registry: five prompts per source x stratum cell and ten iid responses per prompt, for 600 responses per row and 6,600 total. The pilot uses the exact production model/decoder/capture/judge entrypoints. Pilot labels are never test labels.

Production N is fixed before test generation by a development-only clustered simulation. One common prompts-per-cell value equals the largest cell requirement, at least 30, sufficient under the lower confidence bound on discordance to expect >=20 discordant prompts/cell and meet the registered CI-width/power target. Production uses exactly 30 iid responses/prompt with no top-up, exclusion, stopping, or N change.

### Conditions, cells, and seeds

Each of the eleven registered rows contains 12 source-by-stratum cells: four named source/domain frames crossed with three elicitation/difficulty strata. The pilot has five prompts per cell and ten response seeds per prompt. The development and sealed-test banks use the single pre-test common prompt count selected by clustered simulation and exactly 30 SHA-derived response seeds per prompt. Seed schedules, prompt order, and row/cell membership are frozen in the manifest before generation. Comparators C0-C5 are evaluated on identical answer rows and labels.

## 5. Generation and activation capture

Freeze model/tokenizer/chat-template revisions and hashes; bf16; vLLM batched generation; no tools; temperature 1; top_p 0.95; max_new_tokens 1024 inherited from #779 for pilot parity, with realized length-cap fraction reported and >2% per cell triggering a pre-test cap amendment rather than selective regeneration; SHA-derived seeds; immutable prompt/system-message/order manifests.

Teacher-force every retained response without hooks and average L19 residual states over generated non-special assistant tokens. Zero-token outputs follow a fixed three-retry seed schedule; persistent empty output fails the row/bank, never changes the feature definition.

## 6. Comparators

- C0 nuisance logistic: prompt/response lengths, fixed source/stratum/template indicators, seed position, truncation; no prompt identity.
- C1 development-only prompt, answer, and combined text baselines using frozen TF-IDF and pinned all-MiniLM-L6-v2 embeddings.
- C2 exact external direction dot product, uncalibrated.
- C3 development-calibrated scalar C2 logistic.
- C4 development-only raw class-mean direction plus scalar logistic calibration.
- C5 full L2 logistic probe after development-only per-dimension z-scoring.

C3-C5 use sklearn LogisticRegression(lbfgs,max_iter=5000,tol=1e-7,no class weighting), C grid 10^[−6,...,4], five content-superfamily folds, selection by macro conditional AUROC, and strongest-regularization tie break within 1e-4. No pooled cross-fold predictions are used for confirmatory metrics. C5-vs-C4 is the symmetric extraction comparison; C5-vs-C2 is supervised adaptation versus zero-shot transfer.

Source: the exact vector/model/layer definitions come from hash-verified Figure-3 artifacts in #779/#1482/#2203/#2388; no direction is reconstructed from the new labels.

Source: the response decoder and pilot length cap reproduce #779's behavior-corpus recipe; the pilot measures cap hits before any production amendment.

Source: the judge model, five-draw aggregation, frozen rubric/evidence packet, and human fallback implement the independent methodology critique and three-pass Claude review recorded in the task's `epm:plan-critique` marker; the pilot empirically revalidates parse loss and reliability.

Source: the response count is not inherited as a default. The registered clustered simulation selects it from development-only discordance and variance, subject to the stated floor and fixed common-N rule.

Source: the L2 probe solver/grid and strongest-regularization tie break are fixed reviewer-approved hyperparameters; nested development content-superfamily folds select C without test access.

## 7. Evaluation and inference

Primary metric is equal-prompt macro within-prompt AUROC among prompts realizing both classes. Global AUROC is descriptive with hierarchical prompt/response uncertainty.

C2 and the once-fitted/frozen C5 are tested by permuting only sealed-test labels within exact prompt. Use 9,999 plus-one permutations initially and deterministic extension of the whole Holm family to 99,999 if Monte Carlo intervals overlap any Holm threshold. C5-minus-C2 uses a one-sided studentized paired hierarchical bootstrap with development Bayesian-bootstrap refitting and test prompt/within-class resampling.

Three Holm families at alpha=0.05 cover eleven C2 association tests, eleven C5 association tests, and eleven C5-minus-C2 tests. Intervals are pointwise; adjusted p-values/significance are separate.

## 8. Gates

Pilot gates before production: construct recognizability; exact direction/model/judge provenance; clean dependency graph; valid row/vector alignment; measured discordance by cell; pilot judge parse failure <2% and no max-token judge stops; measured cap-hit rate; human-audit feasibility; power-based fixed N; and cost within envelope.

Production test gates after final operational labels: >=100 discordant prompts overall, >=15 per cell, >=100 answers and >=30 prompts in each class, passed label reliability, complete labels, and no cross-split lineage. Failure returns not-estimable; no new test rows are added.

Success criterion: for each row, report the preregistered Holm-adjusted C2 and C5 association decisions and the C5-minus-C2 decision, together with all point estimates, uncertainty, comparators, reliability, and missingness diagnostics. The experiment succeeds operationally when every row either reaches a valid decision or is explicitly marked not-estimable under a predeclared gate.

Kill/abort criteria: halt-and-report before sealed-test generation if any exact vector cannot be provenance/hash matched, the development/test lineage graph cannot be made disjoint, judge drift is detected, required human adjudication is unavailable, pilot cost projects beyond the 80 GPU-hour envelope, or any required raw artifact cannot be durably persisted. During production, a mixed model/judge revision, dependency crossing, unplanned N change, or loss of the sealed manifest aborts inference rather than triggering replacement rows.

## 9. Engineering and artifacts

Implement a content-addressed manifest containing answer, prompt, superfamily, source/stratum, model/template/seed, raw text, evidence, judge draws/status, canonical vector, split, and every SHA. Cache keys cover inputs, direction, split, judge, estimator/grid, preprocessing, code/container, and seeds.

Tests fail on test-derived transforms, peer centering, dependency crossing, row/hash mismatch, missing-label omission, pooled-fold confirmatory metrics, stale caches, non-iid generation, mixed judge revisions, or preliminary-label gate use. Persist raw completions, all judge responses, activation shards, predictions, per-prompt metrics, bootstrap/permutation diagnostics, and exclusion/retry ledgers.

## 10. Compute and dispatch

Backend: auto router, RunPod first, then free cluster lanes. Use vectorized vLLM generation and batched teacher forcing. Pilot targets one 8xH100 or equivalent wave, <=8 GPU-hours total. Batch API pilot is approximately 24,000 judge draws (eight judged traits x 600 answers x five draws); correctness rows use objective labels. Production judge volume and dollar cost are derived from the pilot and must be posted before sealed-test launch.

Human annotation is an external dependency. The pilot must emit randomized blinded packets and a required-count/cost report; it cannot claim that the human gate passed without real adjudications.

## 11. Grounding and deviations

Model/layer/direction provenance is inherited from #779/#1482/#2203/#2388 exact artifacts and must be hash-verified. Generation recipe is inherited from #779's behavior corpus. Grouped splitting and per-answer semantic labels are required by the independent methodology critique. The fixed-probe test-only permutation, fresh matched development bank, hierarchical uncertainty, and frozen judge were required by Claude cross-model review. Deviation from the final full plan: this task begins with a smaller development pilot to measure the production N and cost. Pilot results cannot become confirmatory test rows. No sealed test is generated before the gate.

## 12. Decision rule and deliverables

Pilot deliverables: frozen construct/vector provenance table; eligible-frame and split manifests; raw pilot completions and L19 captures; judge raw/parsed labels; blinded human packets; discordance/reliability/power simulations; throughput and cost report; exact production N; and a launch/park verdict.

Production deliverables after the gate: standalone global and confirmatory conditional AUROC panels with browser-accessible figure URLs; paired deltas; controls; claim matrix; and explicit not-estimable cells. Current proxy/mixed-estimand artifacts remain exploratory.
