# Plan — issue #1156: poller WARN when the pod-side pid file's mtime predates the newest `epm:run-launched` marker

### 0.0 TL;DR (plain English)

- **What I'll run:** I'll add one `stat -c %Y` line to the poller's existing SSH probe so it learns when the pod's pid file was last written, then compare that (drift-free, on the pod's own clock) against the age of the newest `epm:run-launched` marker; if the pid file is more than 10 minutes older than the marker, the poller logs a WARNING and sets a new observability-only JSON field — nothing about the run's status verdict changes.
- **What I expect:** the #813 failure shape (a relaunch that skipped the pid-file rewrite, leaving a dead prior-launch pid silently probed every tick) becomes mechanically visible in the poll log within one tick, while every normal launch (pid file written seconds-to-minutes before the marker posts) stays silent.
- **What would change my mind:** if the WARN can't be made strictly additive — i.e. if wiring it in requires touching status semantics or breaking existing poll tests in a way that needs semantic rewrites — I'd abandon this approach and report why (see Kill criteria).

### 4.3 The clock-normalization arithmetic (explicit)

The marker `ts` is a VM-side UTC ISO timestamp; the pid-file mtime is pod-clock. Never subtract across clocks. Compare **ages**:

```
pid_file_age_sec = POD_NOW_EPOCH − PID_FILE_MTIME_EPOCH      # both pod clock, same SSH session → drift cancels exactly (#704)
marker_age_sec   = run_age_sec                                # = vm_now − marker_ts, both VM clock (_run_launched_age_sec, :4737)
WARN  iff  pid_file_age_sec > marker_age_sec + slack_sec
```

Residual error: the two "now" anchors are captured ~seconds apart (heredoc `date +%s` at probe time vs `now_epoch = datetime.now(tz=UTC)` at :4525 after the SSH returns; bounded by the 60 s SSH timeout, typically 1-5 s). Second-order, absorbed by the 600 s slack.

**Sign convention / why slack is load-bearing:** on every CORRECT launch the pid file is written BEFORE the marker posts (experimenter.md :765→:778→:800), so `pid_file_age − marker_age = δ > 0` always, where δ = confirm-and-post latency (seconds to ~3 min typical; worst observed 8 min, #813 v5: 00:31 relaunch → 00:39 marker). δ is CONSTANT across the run's ticks (both ages grow 1 s/s), so a slack=0 predicate would false-fire on every healthy launch, every tick. The pathological case (prior launch's pid file) is separated by an inter-launch gap ≥ crash-detect window (`DEFAULT_STALL_SEC = 900` s, :368) + a fix round — realistically ≥ 30 min. 600 s sits in that separation band: > 8 min worst-normal with 25 % margin, < the ≥ 30 min pathological floor with 3× margin. The reverse ordering (marker posted before the pod boots — the GCP pre-launch-signal shape) gives δ < 0 → never fires. Fail direction under any residual uncertainty: silence (WARN-only backstop; the marker-pid OR-probe stays the mechanical rescue).

### 4.5 Pure predicate + fail-soft wrapper (new functions, placed after `_run_launched_age_sec`, :876)

```python
def _pid_file_predates_marker(
    *,
    pid_file_mtime_epoch: int,
    pod_now_epoch: int,
    run_age_sec: float | None,
    slack_sec: int | None = None,
) -> bool:
    """True iff the pod-side pid file's mtime predates the newest
    epm:run-launched marker by more than ``slack_sec`` (#1156).

    Same-clock differences only (#704): ``pod_now_epoch − pid_file_mtime_epoch``
    is pod-clock, ``run_age_sec`` is VM-clock — never a cross-clock subtraction.
    Inert (False) on any missing input: ``pid_file_mtime_epoch <= 0`` (absent /
    stat failed / legacy probe), ``pod_now_epoch <= 0`` (no drift-free basis),
    ``run_age_sec is None`` (no marker / unparseable ts). Pure; unit-tested
    directly with no SSH.
    """
    if slack_sec is None:
        slack_sec = PID_FILE_MARKER_SLACK_SEC
    if pid_file_mtime_epoch <= 0 or pod_now_epoch <= 0 or run_age_sec is None:
        return False
    pid_file_age_sec = pod_now_epoch - pid_file_mtime_epoch
    return pid_file_age_sec > run_age_sec + slack_sec


def _maybe_warn_stale_pid_file(
    *,
    issue: int,
    pod: str,
    pid_file: str,
    probe: dict[str, str],
    run_age_sec: float | None,
    pid_file_missing: bool,
) -> bool:
    """Fail-soft #1156 WARN emitter; returns the observability flag.

    WARN-only by contract: never contributes to status / stall / dead.
    ``pid_file_missing`` short-circuits (the #521 absent-file WARN already
    covers that case — no double-fire). Any exception is swallowed to DEBUG:
    an observability backstop must never break a tick of this hot shared
    poll loop (deliberate, narrow exception to fail-fast — mandated by the
    task constraints; parse tolerance itself comes from the #1033 r2
    defensive-scalar pattern).
    """
    try:
        if pid_file_missing:
            return False
        stale = _pid_file_predates_marker(
            pid_file_mtime_epoch=_parse_output_mtime_epoch(probe.get("pid_file_mtime_epoch")),
            pod_now_epoch=_parse_output_mtime_epoch(probe.get("pod_now_epoch")),
            run_age_sec=run_age_sec,
        )
        if stale:
            pid_age = _parse_output_mtime_epoch(probe.get("pod_now_epoch")) - (
                _parse_output_mtime_epoch(probe.get("pid_file_mtime_epoch"))
            )
            log.warning(
                "pid file %s on pod %s predates the newest epm:run-launched marker "
                "for #%d (pid-file age %ds vs marker age %.0fs, slack %ds) — possible "
                "stale pid from a prior launch masking a dead relaunch (#813 pid-file "
                "rewrite contract). WARN-only; status verdict unchanged. Recovery: "
                "rewrite the pid file with the live workload pid and re-post "
                "epm:run-launched (pod-side-reporting.md § Pid-file launch contract).",
                pid_file, pod, issue, pid_age, run_age_sec, PID_FILE_MARKER_SLACK_SEC,
            )
        return stale
    except Exception as exc:  # noqa: BLE001 — observability must never break a tick
        log.debug("stale-pid-file-vs-marker check failed (ignored, #1156): %s", exc)
        return False
```

The predicate does NOT gate on `PID_ALIVE`: a recycled/coincidentally-alive stale pid is exactly the "worse than missing" case the rule names — the mtime ordering fires regardless.)

## 11. Decision Rationale

- **Slack value = 600 s (env `EPM_POLL_PID_MARKER_SLACK_SEC`).**
  **What:** the tolerance added to the marker age before the WARN fires.
  **Why:** the normal launch ordering writes the pid file BEFORE the marker posts (pid-file age exceeds marker age by δ > 0 on EVERY healthy launch, constant across ticks), so slack = 0 false-fires universally; slack must exceed max-normal δ and stay under the min pathological inter-launch gap.
  **Source:** reasoned from launch mechanics — `experimenter.md` steps 1/1b (:765 pid write → :778 confirm → :800 marker post; typical δ seconds-to-3 min), worst observed normal-family gap 8 min (#813 v5, relaunch 00:31 → marker 00:39), pathological floor ≥ 30 min (crash-detect `DEFAULT_STALL_SEC = 900` s at :368 + a fix round). 600 s = 8 min worst-case + 25 % margin, 3× under the pathological floor; not sensitive within ~2× in either direction.
  **Alternatives:** 120 s (rejected — inside the observed 8-min normal gap → false-fires on slow-but-correct launches); 1800 s (rejected — a fast same-session relaunch that skips the rewrite could sit inside it; halves detection coverage for zero false-positive benefit given the 8-min normal ceiling); making it a CLI flag (rejected — env-var precedent `EPM_POLL_STALL_SEC` / `EPM_POLL_OUTPUT_MTIME_FOLD` suffices; no caller needs per-invocation variation).
- **WARN every tick (no dedup/once-per-episode).**
  **What:** the WARN + JSON flag recompute and re-fire on each tick while the condition holds.
  **Why:** a true positive should stay loud until the pid file is actually rewritten; dedup would require new keys in the tick state dict (:4950-5005) — a schema change on a hot shared script for a signal bounded at 1 line / 5-15 min.
  **Source:** #521 `pid_file_missing` WARN precedent (:4505-4511 — every-tick, no dedup, same observability class).
  **Alternatives:** state-file-backed once-per-episode dedup (the gpu-idle-advisory pattern — rejected: that machinery exists because those post MARKERS + pushes; a log line does not warrant the blast radius); once-per-process `warned` set (rejected: `poll_once` is invoked per-tick as a fresh CLI process — no process persistence to lean on).
- **JSON field: yes (`pid_file_stale_vs_marker`, defaulted `False`).**
  **What:** a `PollResult` field + `main()` JSON key, observability-only.
  **Why:** the orchestrator/tick consumes the JSON line, not the poller's stderr — without the field the signal is invisible to the machine layer that could act on it (e.g. a future tick-triage surface).
  **Source:** #521 `pid_file_missing` precedent — identical surfacing pattern (:986, :5029, :5108); the defaulted-field cross-backend convention (:1008-1016).
  **Alternatives:** log-only (rejected — machine-invisible); a new `epm:` marker per detection (rejected — every-tick marker posting spams `events.jsonl` and needs dedup state, the exact machinery declined above; escalation can be layered later off the JSON field if the WARN proves reliable).
- **Fail-soft `try/except Exception → log.debug` in the wrapper.**
  **What:** the single deliberate, narrow exception to fail-fast.
  **Why:** every live poll loop fleet-wide runs this script; an observability backstop must never break a tick (task-body constraint). The predicate feeds no verdict, so a swallowed failure loses nothing but the WARN itself.
  **Source:** task #1156 body constraint + the #1033 r2 defensive-parse precedent (`_parse_output_mtime_epoch`, :4303-4319 — "must fail INERT, not kill the tick").
  **Alternatives:** rely on tolerant parsing alone, no try/except (rejected — belt-and-suspenders is cheap and the constraint is explicit); `log.warning` on the swallowed exception (rejected — a persistent internal failure would itself spam; DEBUG keeps it inspectable under `--debug`).
- **Reuse `_parse_output_mtime_epoch` for the new scalar (docstring extended) rather than a strict `int()`.**
  **Source:** #1033 r2 (:4303-4319). **Alternatives:** strict parse like the sibling keys (rejected — a garbled SSH line on this NEW key must not kill the tick; the siblings' strict parses are grandfathered, not a template).
- **Hyperparameters (model training):** N/A — no model training.
