# Plan v1 — #1893 workflow-fix: fleet-wide pod code-sync pulls origin main over live issue-branch workloads

## Goal / Requirement

Make the fleet-wide pod code-sync (`pod.py sync code` → `scripts/sync_pods.sh`) live-run-safe:

1. **Live-workload skip:** a pod with a live registered workload (any `/workspace/logs/issue-*.pid` whose pid is alive) is SKIPPED with a loud `SYNC-SKIPPED (live workload ...)` line — a sync never pulls under a running job.
2. **Branch-aware pull:** a synced pod pulls `origin <its-own-checked-out-branch>` — never an unconditional `origin main` — so an issue-branch clone can never transiently lose issue-branch-only files (the #1776 mid-run ENOENT race). A detached-HEAD clone is skipped loudly, never guessed at.

### Acceptance criteria

- A pod fixture with a live pid file is skipped (no git operation runs); the skip line names the pid file + pid.
- An issue-branch clone with no live workload pulls its OWN branch (`origin issue-<N>`), verified functionally in a local fixture repo.
- A main-branch clone with no live workload keeps today's behavior (pulls `origin main` via the branch-aware path).
- A detached-HEAD clone is skipped loudly (no pull).
- A stale pid file (pid dead) does NOT block the sync (probe is `kill -0`-based; dead pid ⇒ proceed).
- No unconditional `origin main` pull remains anywhere in the fleet-sync path (pin test enforces).

## Method delta (vs current behavior)

Current `sync_pods.sh:34` remote command per pod:
`cd $REPO_DIR && git stash -q 2>/dev/null; git pull --ff-only origin main 2>/dev/null || git pull --rebase=merges origin main`

Delta: the pod-side logic moves into a standalone, locally-testable script `scripts/pod_code_sync.sh` executed via `ssh ... bash -s < scripts/pod_code_sync.sh`, which (a) probes live workload pids FIRST and exits 0 with a skip line when any is alive, (b) resolves the clone's checked-out branch and pulls THAT branch, (c) keeps the existing `git stash -q` + ff-only→rebase=merges fallback shape unchanged (single-variable discipline: guard + branch-pin only; no other sync-behavior change).

## File paths + concrete diffs

1. **NEW `scripts/pod_code_sync.sh`** — pod-side sync body (runs on the pod via `bash -s`):
   ```bash
   #!/bin/bash
   # Pod-side code sync body — piped to the pod via `ssh ... bash -s` by
   # sync_pods.sh. Env overrides for local testing:
   #   EPS_SYNC_REPO_DIR (default /workspace/explore-persona-space)
   #   EPS_SYNC_LOG_DIR  (default /workspace/logs)
   set -u
   REPO_DIR="${EPS_SYNC_REPO_DIR:-/workspace/explore-persona-space}"
   LOG_DIR="${EPS_SYNC_LOG_DIR:-/workspace/logs}"
   cd "$REPO_DIR" || { echo "SYNC-FAILED (no repo at $REPO_DIR)"; exit 1; }
   # 1. Live-workload probe: skip-on-doubt — any live pid in an issue pid
   #    file means a workload may be mid-run; never pull under it. A stale
   #    (dead-pid) file does not block. A recycled pid false-positives
   #    toward SKIP (fail-safe: a missed sync is cheap + loud; a pull under
   #    a live run is the #1776 ENOENT race).
   for f in "$LOG_DIR"/issue-*.pid; do
     [ -f "$f" ] || continue
     pid=$(cat "$f" 2>/dev/null | tr -d '[:space:]')
     if [ -n "$pid" ] && kill -0 "$pid" 2>/dev/null; then
       echo "SYNC-SKIPPED (live workload: $f pid=$pid)"; exit 0
     fi
   done
   # 2. Branch-aware pull: sync the clone's OWN branch, never bare main.
   branch=$(git rev-parse --abbrev-ref HEAD 2>/dev/null)
   if [ -z "$branch" ] || [ "$branch" = "HEAD" ]; then
     echo "SYNC-SKIPPED (detached HEAD or unresolvable branch)"; exit 0
   fi
   git stash -q 2>/dev/null
   git pull --ff-only origin "$branch" 2>/dev/null \
     || git pull --rebase=merges origin "$branch"
   ```
