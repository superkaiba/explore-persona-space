### 3.3 `refresh` pseudocode

```python
def cmd_refresh(args) -> int:
    root = args.repo_root or main_repo_root()          # git rev-parse --git-common-dir → parent
    lock = acquire_refresh_lock(root / ".claude/cache/step9c-baseline.lock")  # LOCK_EX|LOCK_NB
    if lock is None:
        print("step9c_baseline: another refresh holds the lock — single-flight no-op", file=sys.stderr)
        return 0
    sel = load_selector_module()                       # importlib.util by path, same pattern as
                                                       # tests/test_select_step9c_tests.py L27-31
    universe = sorted({*sel.WORKFLOW_INVARIANT, *sel.GLOB_SCAN_TESTS}
                      & {t for t in ... if (root / t).exists()})   # present-on-disk; 34 today
    if not universe: fail loud, return 2               # mirrors the selector's empty-selection refusal
    junit = root / ".claude/cache/step9c-baseline-junit.xml"
    # Bounded, thread-capped, cache-provider-off (no .pytest_cache contention with
    # concurrent repo-root pytest runs), group-killed on expiry:
    rc = run_pytest(files=universe, cwd=root, timeout_s=args.timeout_s, junit_path=junit,
                    extra=["-q", "--tb=no", "-p", "no:cacheprovider", "-o", "junit_family=xunit1"],
                    env=thread_capped(os.environ))     # setdefault OMP/MKL/OPENBLAS/NUMEXPR=8
    # subprocess.run(..., timeout=...) with start_new_session=True; on TimeoutExpired:
    # os.killpg(TERM, wait 10s, KILL), print loud, return 2 — NO ledger write.
    failing, summary = parse_junit(junit)              # failure/error children; skipped excluded
    if summary["tests"] == 0: fail loud ("0 collected — refusing to write ledger"), return 2
    ledger = {..., "main_sha": git_head(root), "dirty_code_paths": dirty_code_paths(root),
              "ruff_count": ruff_error_count(root), "ruff_format_files": ruff_format_count(root)}
    write_ledger_atomic(root / ".claude/cache/step9c-baseline.json", ledger)  # tmp + os.replace
    return 0
```

Notes: `refresh` runs at the MAIN repo root against the working tree (which is main + possibly-dirty concurrent churn — recorded via `dirty_code_paths`; the alternative, a scratch worktree per refresh, mutates git worktree metadata and violates the no-git-mutation constraint). A pytest rc != 0 with parseable junit is the NORMAL red-main case, not an error. `git rev-parse HEAD`, `git status --porcelain`, ruff runs: all read-only.

### 3.4 `compare` pseudocode (the core semantics)

```python
def cmd_compare(args) -> int:
    wt = resolve_work_root(args.worktree)              # invoking checkout (the issue worktree)
    root = args.repo_root or main_repo_root()
    run_failing, summary = parse_junit(args.junitxml)  # missing file / unparseable → exit 2
    if summary["tests"] == 0: return 2                 # echoes the no-tests-ran FAIL guard

    sel = load_selector_module()
    touched = sel.compute_touched(args.base, wt)       # same 3-dot diff the selector uses
    _tests, _untested, reasons = sel.select_tests_with_reasons(touched, wt)   # §3.5
    diff_linked = {t for t, rs in reasons.items() if any(r != "invariant" for r in rs)} | \
                  {f for f in touched if f.startswith("tests/")}

    ledger = try_load_ledger(root)                     # None on missing/invalid (loud stderr)
    stale, stale_reasons = staleness(ledger, root, args)      # see below
    changed_tests = changed_test_files_since(ledger, root)    # git diff --name-only <sha>..HEAD -- tests/
                                                              # sha unknown to git → treat fully stale

    new, stripped, pristine_bucket = [], [], []
    for node in run_failing:                           # node = (file, classname, name)
        if ledger is None or stale:                    pristine_bucket.append(node)
        elif node in ledger.failing_tests:
            if node.file in diff_linked or node.file in changed_tests:
                                                       pristine_bucket.append(node)   # R5
            else:                                      stripped.append(node)          # safe strip
        elif not (root / node.file).exists():          new.append(node)   # branch-new test failing
        else:                                          pristine_bucket.append(node)   # unknown provenance

    warns = []
    if pristine_bucket:
        if not args.run_pristine:
            print commands to run; return 2            # indeterminate — never a silent strip
        for file in dedupe(n.file for n in pristine_bucket):
            main_failing = run_single_file_pristine(file, cwd=root, timeout_s=..., junit→tmp)
            # timeout/crash of the pristine run itself → loud, return 2
            for node in bucket_nodes(file):
                if node in main_failing:
                    stripped.append(node)              # pre-existing at CURRENT main HEAD
                    if node.file in diff_linked:
                        warns.append(masking_warn(node))   # §5 risk 3 — scan-test residual
                else:
                    new.append(node)

    lint = lint_verdict(root, wt, touched)             # below
    emit json/human: {new, stripped, warns, stale, stale_reasons, lint, ledger_sha, ledger_age_h}
    return 1 if (new or not lint.ok) else 0
```

**Staleness predicate** (grounded — see §11): global-stale iff `age > --max-age-hours` (default 24) OR `git rev-list --count <ledger_sha>..HEAD -- scripts/ src/ tests/ pyproject.toml uv.lock` > `--max-code-commits` (default 150; measured cadence: 60 code-path commits on 2026-07-04 alone, so 150 ≈ ~2 busy days — while `tasks/**` marker commits, ~100+/hour, are excluded by the pathspec entirely, per the brief's caution) OR `ledger_sha` unknown to git. Per-ENTRY staleness rides on top: a ledger entry whose test FILE changed on main since `ledger_sha` is never blind-stripped (routed to pristine).

**Lint verdict** (mechanical, replaces SKILL.md step 2):

```python
def lint_verdict(root, wt, touched):
    base_count  = ruff_error_count(root)     # LIVE main-root baseline (ruff check . --exit-zero
                                             #   --output-format=json → len(entries)); ~seconds
    wt_count    = ruff_error_count(wt)
    base_fmt    = ruff_format_count(root)    # "Would reformat:" line count; rc>1 → fail loud
    wt_fmt      = ruff_format_count(wt)
    touched_py  = [f for f in touched if f.endswith(".py") and (wt / f).exists()]
    touched_ok  = ruff_error_count(wt, paths=touched_py) == 0 and \
                  ruff_format_count(wt, paths=touched_py) == 0      # absolute-clean on touched
    return LintVerdict(ok = wt_count <= base_count and wt_fmt <= base_fmt and touched_ok,
                       deltas = {...})
```

Only an INCREASE over the live main baseline fails; touched files must be absolutely clean (the standing per-round requirement, now enforced mechanically). `ruff` is invoked via `shutil.which("ruff")` (on PATH inside `uv run`); missing → fail loud, exit 2.

**What compare never does:** mutate git state (only `rev-parse` / `rev-list` / `diff --name-only` / `status --porcelain`, all read-only); write the ledger (refresh-only); pass on indeterminate.

## 10. §11 Decision Rationale

`N/A — no training hyperparameters` · `N/A — no behavioral construct` · `N/A — not a replication` · `N/A — no artifact reuse` · `N/A — no draw battery` · `N/A — no empirical-null gate` · `N/A — no re-extracted reference arms` · `N/A — no paired contrast` · `N/A — no held-out predictive DV`

Load-bearing design choices:

1. **Ledger location = `<main-root>/.claude/cache/step9c-baseline.json`, gitignored, resolved via `--git-common-dir`.** *Why:* VM-local derived state (failures are environment-dependent); committing it would add churn to a main that already takes 100+ task-state commits/hour and would go stale in git faster than it could merge; common-dir resolution makes one shared ledger visible from every worktree. *Source:* `.gitignore:78` (verified); the existing `.claude/cache/issue-<N>-handle.json` precedent (CLAUDE.md § Compute backends). *Alternatives:* committed file (rejected: churn + merge races); per-worktree cache (rejected: never found by the next session); `~/.task-workflow/` (rejected: repo-scoped state belongs with the repo).
2. **Node-level `failing_tests` granularity.** *Why:* a NEW failing test inside an already-red FILE must still block; file-level would blind-strip it (test case 6 pins this). *Source:* refined from the task sketch's `failing_tests[]`. *Alternatives:* file-level (rejected: masks intra-file regressions); failure-message hashing (rejected: nondeterministic text, fragile).
3. **Staleness = 24 h age OR >150 code-path commits (`scripts/ src/ tests/ pyproject.toml uv.lock` pathspec) OR sha-unknown, PLUS per-entry test-file-changed routing.** *Why:* the brief's caution — a raw "main advanced >N commits" rule is permanently stale under ~100+/hr `tasks/**` churn; the pathspec counts only code commits (measured ~60/busy-day → 150 ≈ 2 days), age 24 h is the practical dominant knob, and the per-entry check is the sharp correctness edge (a ledger entry whose test file changed on main is never blind-stripped). *Source:* measured cadence (§9 A5); brief. *Alternatives:* commit-count only (rejected: measured burstiness makes it either always-stale or toothless); age only (kept as dominant but commit cap catches a burst inside 24 h).
4. **Refresh scope = present-on-disk `WORKFLOW_INVARIANT` ∪ `GLOB_SCAN_TESTS` keys (34 files), run at the main repo root, bounded 1800 s + thread caps + `-p no:cacheprovider`, no ledger write on timeout.** *Why:* this is exactly the PREDICTABLE part of every Step 9c selection (the per-diff mapped tests are unpredictable by construction and are covered by the pristine oracle instead); wholesale `pytest tests/` is the banned #665/#736 kill class. Importing the selector's literals means curation updates propagate automatically. *Source:* `select_step9c_tests.py` L89-188; SKILL.md L7068-7071. *Alternatives:* full suite (banned); invariants-only 32 (rejected: today's actual red node lives in a scan test — the motivating case would be missed).
5. **Compare strip semantics: blind-strip only when (fresh ∧ node-in-ledger ∧ not diff-linked ∧ test file unchanged since ledger sha); everything else → on-demand single-file pristine-main run at current HEAD; indeterminate → FAIL.** *Why:* this is the brief's stated tradeoff, resolved toward "pristine check as ground-truth oracle, ledger as cache": it simultaneously answers (a) the touched-subset test not in the ledger (unknown provenance) and (b) the masking concern (risk 3) — the strip never rests on a stale cache when the diff plausibly touches the test's coverage. Cost is bounded: 0–3 single-file runs × ≤60 s in the typical case. Residual scan-test masking is stripped-WITH-WARN, never silently (the diff's own reviewers + code-style enforcement are the compensating controls). *Source:* brief options; diff-linked-ness derived from the selector's own mapping (no new heuristics). *Alternatives:* always-strip-from-ledger (rejected: the masking direction is the one dangerous failure mode); never-strip-diff-linked (rejected: the motivating thread-caps case IS diff-linked via glob-scan — the rule would re-burn the round it exists to save); failure-text diffing (rejected: fragile, nondeterministic).
6. **Stale ledger degrades to pristine checks; refresh is kicked DETACHED in the background — never "refresh first" synchronously.** *Why:* the sketch's "stale → refresh first" would serialize a 5–15 min refresh into the very verdict path whose wasted minutes motivated the task; pristine-per-failing-file is strictly cheaper (only red files re-run) and correct at current HEAD; the background kick keeps the fleet's ledger warm. *Source:* refined from the task sketch (authorized: "refine, don't treat as binding"). *Alternatives:* synchronous refresh (rejected: cost inversion); no auto-refresh (rejected: ledger would decay to permanently-stale).
7. **Ruff baseline recomputed LIVE at the main root in compare; ledger's `ruff_count` is informational.** *Why:* the baseline drifted 2072→2149 in two days (measured); a live count costs seconds and removes an entire staleness axis; the delta rule ("only an increase fails") plus absolute-clean-on-touched preserves both the ratchet and the per-round hygiene requirement. *Source:* measured drift (§9 A2). *Alternatives:* ledger-valued baseline (rejected: false regressions whenever main gains errors post-refresh).
8. **junitxml (`junit_family=xunit1`) as the failure-extraction contract.** *Why:* structured, stdlib-parseable (`xml.etree`), carries per-testcase `file` + failure/error children — verified live against installed pytest 9.0.2; text-parsing `FAILED` lines breaks on param ids containing ` - `. *Source:* live probe (§9 A3). *Alternatives:* short-summary parsing (kept as the K2 named fallback only); `pytest --json-report` (rejected: new dependency).
9. **Selector extension as `select_tests_with_reasons` + additive `--json` key, `select_tests` signature preserved.** *Why:* compare needs diff-linked-ness from the SAME mapping logic that selected the tests (recomputing it outside would duplicate logic the selector's 20 tests pin); preserving the 2-tuple keeps every existing caller/test untouched except case 10's exact key-set assert (updated deliberately). *Source:* `select_step9c_tests.py` L240-291; `tests/test_select_step9c_tests.py` case 10. *Alternatives:* compare-side reimplementation (rejected: drift risk); changing `select_tests`'s return shape (rejected: gratuitous breakage).
10. **Single-flight flock + atomic replace for the ledger; compare read-only.** *Why:* many concurrent sessions share the repo root; the repo's proven patterns (`task_workflow.py` flock, `sync_repo_root.py` second-caller-exits-0) transfer directly; no git state is ever mutated by any subcommand. *Source:* `task_workflow.py` L608-618 (read). *Alternatives:* lockless last-writer-wins (rejected: torn reads); `~/.task-workflow/lock` reuse (rejected: would serialize against unrelated task mutations).
