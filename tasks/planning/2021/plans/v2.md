### Edit 1 — classification predicates (`src/explore_persona_space/eval/batch_judge.py`, next to `is_transport_error_dict`)

```python
TRUNCATION_STOP_REASONS = ("max_tokens", "length")  # raw Anthropic / OpenAI-normalized

def is_truncation_stop_reason(stop_reason: object) -> bool:
    """True iff a persisted stop_reason string marks a budget-truncated response
    (rule 23 budget class). None / missing / non-str -> False (unknown, never KeyError)."""
    return isinstance(stop_reason, str) and stop_reason in TRUNCATION_STOP_REASONS

def is_truncation_error_dict(parsed: object) -> bool:
    """Rule-23 truncation-vs-content split for judge error dicts (#2021).
    True iff the row is an error dict (error=True) whose persisted stop_reason is
    truncation-class — a BUDGET defect, not a content verdict. A dict lacking
    stop_reason (pre-#2021 legacy) is NOT truncation-class (classifies unknown ->
    content, preserving today's behavior). Transport dicts carry no stop_reason
    by construction, so the two classes are disjoint."""
    if not isinstance(parsed, dict) or not parsed.get("error"):
        return False
    return is_truncation_stop_reason(parsed.get("stop_reason"))
```

### Edit 2 — attach helper (`src/explore_persona_space/eval/judge_dispatch.py`, next to `_parsed_with_raw`)

```python
_STOP_REASON_KEY = "stop_reason"

def _with_stop_reason(score: object, stop_reason: object) -> object:
    """Attach the API response's stop_reason to a dict-shaped judge score (#2021).
    Unlike _parsed_with_raw this is UNCONDITIONAL (no contextvar gate) and covers
    parse-failure error dicts too — truncation diagnosis is exactly about failed
    parses. isinstance(str) gate: (a) never persists a non-str (a MagicMock attr
    from test fakes, an SDK enum surprise); (b) leaves transport/no-response
    dicts untouched. Non-dict scores (bare-string parses) pass through."""
    if not isinstance(score, dict) or not isinstance(stop_reason, str) or not stop_reason:
        return score
    out = dict(score)
    out[_STOP_REASON_KEY] = stop_reason
    return out
```

## 11. Decision Rationale

1. **Field name + placement — `"stop_reason"` (raw SDK string) inside the per-draw result dict.** *Why:* rides every existing persistence path (JudgeCache, save_raw, api_dispatch checkpoint, retry persist) with zero schema changes; raw vocabulary matches rule 26's gate text (`stop_reason == "max_tokens"`) and the #1934 probe's ground truth (`end_turn`). *Source:* rule 26 L301/L319–323; `_parsed_with_raw` pattern (judge_dispatch L203, #1801-era). *Alternatives rejected:* `LLMResponse`-normalized values (`end_turn`→`stop_sequence` loses the audit's vocabulary; judge paths never build `LLMResponse`); a separate sidecar file (second artifact to keep in sync); a `DispatchResult.stop_reason` field (requires checkpoint-schema changes in api_dispatch — the in-dict form gets persistence for free).
2. **Counter semantics — truncation is a SUBSET of `n_dropped_draws`, not disjoint.** *Why:* exact mirror of the #1801 `n_refusal_draws` precedent in the same dataclass ("subset semantics — the total is unchanged"); `n_dropped_draws` stays numerically identical, so all 4 existing consumers (`organisms.py` L1497/1859, `issue_1739/{gates,dv_build,judging}.py`, `datagen.py` L995) are byte-unaffected — a disjoint counter would silently shrink their drop-rate reports. Residual malformed = `n_dropped − n_refusal − n_truncation`, reported in the log line. *Source:* graded_judge L158–163 (#1801); rule 24(ii)'s never-blend applies to transport-vs-content, which stays intact. *Alternative rejected:* disjoint third counter (rule-23-purist, but breaks consumer arithmetic and diverges from the in-file precedent).
3. **Refusal-before-truncation precedence.** *Why:* an instructed REFUSAL is a produced verdict (rule 9: content-informative) even if the response then truncated; truncation classification targets the parse-failure class rule 23 describes. *Source:* rule 24(iii) boundary text; #1801. *Alternative:* truncation-first — would relabel valid refusal verdicts as budget defects.
4. **Cache hygiene — put-skip AND get-miss truncation-class error dicts (mirror #1313).** *Why (the deferred decision, one paragraph):* the rubric cache key deliberately excludes `max_tokens` (`rubric_fingerprint` L118–121), so a budget raise does NOT change the key and — without this change — re-serves every truncation-era parse-error entry, which is precisely rule 23's cache caveat and forced the #1739/#1769/#1774 fresh-`cache_dir` recoveries and surgical merges. Put-skip + get-miss makes a budget raise self-heal: the truncated entries re-dispatch and succeed at the new budget with no cache surgery. The cost — a run at an UNCHANGED too-small budget re-dispatches its truncated entries each run and re-truncates — is bounded by the run's own item set, is exactly the population you want re-judged, and is the same trade #1313 accepted for persistent-outage transport dicts; the rule-26 pilot gate exists to prevent production dispatch at a truncating budget in the first place. Get-miss (not put-skip alone) also covers dicts written by concurrent pre-#2021 code. Pre-#2021 legacy truncation entries lack `stop_reason` and remain served (unclassifiable) — documented in the rule-23 doc edit; fresh `cache_dir` remains the recovery there. *Source:* #1313 (`_enumerate_and_check_cache` L582–588, cache loop L798–801); rule 23 cache caveat; rule 24(ii). *Alternative rejected:* fold `max_tokens` into the cache key — cold-invalidates every existing cache (violates the hard constraint) and over-keys rubric identity.
5. **Pilot gate location + defaults — new module `eval/judge_pilot.py`; `n_draws=2`, `target_total_draws=200`, `parse_fail_threshold=0.02`, `max_tokens` REQUIRED with no default; truncation-FAIL unwaivable; per-arm parse-fail waivers.** *Why:* graded_judge stays the reduce library; the gate is an orchestration helper over it (imports are cycle-safe only in a fresh module); 100–200 draws and ~2% are rule 26's own numbers; requiring `max_tokens` forces the caller to state the production budget (rule 26's "EXACT production instrument") and honors the "be generous / never shrink" directive by never supplying a default that could silently differ; the waiver implements rule 26(b)'s "or explained as a known content-drop class" (#1769's degenerate-text empty responses) while (a)'s truncation zero-check stays absolute (the remedy is a budget raise, never a waiver). *Source:* rule 26 L296–325 verbatim; user directive in `origin_prompt` ("Be generous with the allowed token generation"). *Alternatives:* gate inside `judge_completions_batch` (wrong layer — the gate spans arms/rubrics above single dispatches); an auto-firing ≥5k-call interceptor (behavioral change to every existing caller; rule 26 assigns the gate to plans/callers, not the client).
6. **api_dispatch seam — optional `parse_response_meta` callback, threaded at both parse sites.** *Why:* the only judge path where the SDK message is inaccessible to judge code (api_dispatch owns it, L812–814); an optional second callable is additive (every existing caller unchanged), keeps `ParseResponse` intact, and putting the field inside the parsed result reuses the checkpoint/cache persistence untouched (`_merge_batch_record` L684–692 reads `rec.get("result")` verbatim). *Source:* #1470 `response_valid` precedent (same optional-callable extension pattern, dispatch_calls L1335). *Alternatives rejected:* changing `ParseResponse`'s signature (breaking); `DispatchResult.stop_reason` (checkpoint-schema surface); inspecting the callback's arity (fragile).
