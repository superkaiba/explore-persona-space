## 1. Goal, requirement, acceptance criteria

**Goal (task body):** Support a per-lane instance-name suffix on the GCP lane so two concurrent lanes for one issue can coexist, and surface a reconnect outcome loudly in the dispatch result instead of a bare `ok: true`.

**Requirements:**

### 3.1 `src/explore_persona_space/backends/base.py` — shared validator (new, ~15 lines)

```python
_LANE_SUFFIX_RE = re.compile(r"[a-z0-9](?:[a-z0-9-]*[a-z0-9])?|[a-z0-9]")

def validate_lane_suffix(suffix: str) -> str:
    """Validate a per-lane instance-name suffix (#934).

    GCE instance names are RFC1035 labels (lowercase [a-z0-9-], <=63 chars,
    end alphanumeric); the suffix is appended as `eps-issue-<N>-<suffix>`,
    so it must be lowercase alphanumeric-with-inner-hyphens.
    """
    if not _LANE_SUFFIX_RE.fullmatch(suffix):
        raise ValueError(
            f"lane_suffix must match [a-z0-9]([a-z0-9-]*[a-z0-9])?, got {suffix!r}"
        )
    return suffix
```

(Single-char suffixes like `a` must pass — hence the alternation or an equivalent single regex; implementer may simplify to `r"[a-z0-9](?:[a-z0-9-]*[a-z0-9])?"` which already accepts length-1 via the optional group. Ensure `import re` is present at base.py top — add if absent.)

### 3.2 `src/explore_persona_space/backends/gcp.py`

```python
def lane_suffix_for(spec: RunSpec) -> str | None:
    """Validated per-lane suffix from spec.extra['lane_suffix'] (#934), or None."""
    raw = spec.extra.get("lane_suffix")
    if not raw:
        return None
    return validate_lane_suffix(str(raw))

def instance_name_for(issue: int, lane_suffix: str | None = None) -> str:
    """Canonical GCE instance name: eps-issue-<N>[-<lane_suffix>] (#934). ..."""
    name = f"eps-issue-{issue}" + (f"-{lane_suffix}" if lane_suffix else "")
    if len(name) > 63:
        raise ValueError(f"GCE instance name {name!r} exceeds the 63-char RFC1035 cap")
    return name
```

## 11. Decision Rationale

1. **Threading via `spec.extra["lane_suffix"]`** — *What:* CLI flag → `_launch_extra_from_args` → `RunSpec.extra` → gcp helpers read it. *Why:* all four gcp naming call sites already receive `spec` (gcp.py:2001/2803/2974/4032); the router reconnect scan passes `spec` to `gcp_reconnect_or_none` (dispatch_issue.py:446); and `canonicalize_spec` includes `extra` (router.py:722–726), so the two lanes get distinct lease spec-hashes for free. *Source:* gcp.py:751–758, router.py:691–748, dispatch_issue.py:376–451. *Alternatives:* a new `RunSpec` field (touches the frozen dataclass + every constructor — larger diff, no benefit); CLI-only plumbing bypassing extra (breaks the router reconnect scan, which derives the name from spec).
2. **VM-side scratch/log/sentinel paths unsuffixed** — *What:* `workload_dir_for`/`log_path_for`/`sentinel_path_for` untouched. *Why:* they are paths ON the instance; concurrent lanes are separate VMs with separate disks. *Source:* gcp.py:761–791. *Alternatives:* suffixing them (pointless churn; would break the `/workspace/eps-issue-<N>` conventions in gotchas/runbooks).
3. **Sidecar shape `issue-<N>-<suffix>-handle.json`** — *What:* suffix inserted before `-handle.json`. *Why:* every sidecar-sibling consumer keys on the `-handle.json` SUFFIX (backend_poll.py:279–283, 1251, 1610, 1803 stem extraction), so per-lane sibling files (gpu-idle clock, phase clocks) come out distinct automatically. *Source:* those lines. *Alternatives:* a subdirectory per lane (breaks the flat `.claude/cache` conventions + the orphan sweeps' expectations).
