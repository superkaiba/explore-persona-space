## 0. Plan Summary

**What this fixes:** the #664-class RunPod billing leak (a pod stuck
RUNNING-but-no-public-port on a degraded host) currently has TWO detectors —
the poller (`backend_poll._maybe_escalate_runpod_wedge`, shipped by #689 fix
(b)) and the fleet-level report-only `pod_audit.py running_no_port` flag — but
NEITHER fires when the per-issue poll loop has DIED (crashed `/issue` session,
OOM-killed bg-Bash poll chain, VM reboot). When the poller is dead, the wedge
goes undetected and the pod bills indefinitely. The autonomous-session watcher
(`autonomous_session_watch.py`) runs unconditionally every 10 min, independent
of any session or the poller, and already reconciles RUNNING managed pods in
its pod-safety pass — but it ONLY keys on task STATUS (auto-stop a DONE task's
escaped pod; alert a stale pod-active task). It is blind to the wedge: a wedged
pod whose task is still `running`/`approved` classifies `pod-active-fresh` (no
real progress markers → actually `pod-active-stale` after 6h, but only ALERTs,
never stops) and burns until a human notices.

The fix adds a NEW wedge arm to the watcher's per-pod handler: detect the raw
RUNNING-but-no-port condition from the live `PodInfo` the watcher ALREADY
fetched, age it against a DEDICATED `wedge_first_seen` clock in the pod-safety
state file (stamped on the FIRST tick the raw wedge predicate is True, CLEARED
on any tick it is False) — and, past K (the SAME `RUNPOD_WEDGE_K_SEC` constant
the poller uses), ALERT by default and AUTO-STOP only when the same
inputs-on-HF + keep-running gates fix (b) uses confirm it is safe.

- **Composition surface (resolves clarifier item 1):** option (b) — extract the
  RAW wedge predicate (`desired_status == "RUNNING"` AND no public port) from
  `_maybe_escalate_runpod_wedge` into a small standalone helper
  `backend_poll._pod_is_runpod_runtime_wedged(info) -> bool`; both
  `_maybe_escalate_runpod_wedge` and the new watcher arm call it. Option (a)
  (call `_maybe_escalate_runpod_wedge` from the watcher) is rejected — it reads
  the poller's sidecar clock + mutates it, double-writing a clock the watcher
  doesn't own; the watcher uses its OWN `wedge_first_seen` clock instead. Option
  (c) (re-implement locally) is FORBIDDEN by the "do NOT re-define" constraint.

- **Where loss/data is gated:** N/A (no training). The wedge AUTO-STOP reuses
  fix (b)'s `_wedged_run_inputs_on_hf` per-cell inputs-on-HF gate AND a
  wedge-specific TRI-STATE wrapper over the watcher's `_task_keep_running`; an
  unverified-inputs / tagged / tag-read-unknown / no-handle pod is ALERT-only
  (never auto-stopped).

- **STOP, never terminate.** The watcher's wedge arm calls the SAME reversible
  `_stop_pod` (`pod.py stop`, volume preserved) the existing auto-stop-done arm
  uses — NOT `terminate_pod`. The poller's fix (b) is the path that terminates +
  re-provisions; the watcher backstop only needs to halt the billing leak (a
  human / re-invoked `/issue` then resumes or re-provisions). This is the
  conservative choice: the watcher has no run handle guarantee and runs blind to
  the dispatcher's resume state, so it stops (reversible) rather than terminates
  (irreversible) — CLAUDE.md halt-criterion #2.

- **Compute:** 0 GPU-h. Wall-time for the implementer ~2-3 h (predicate
  extraction + watcher arm + dedicated wedge clock + tri-state gate + state
  persistence wiring + pod_id reset + ~14 unit tests + lint + full
  named-regression suite).

- **Evaluation (acceptance):** new unit tests PASS; `decide_pod_wedge` (the new
  pure decision fn) returns the wedge action for every decision-table case +
  the pinned boundaries, and `decide_pod_safety` is unchanged for the existing
  cases; the new wedge-state fields round-trip through
  `_save_pod_safety_state`/`_load_pod_safety_state`;
  `scripts/workflow_lint.py --check-asks` PASS; ruff PASS on the two touched
  files; existing watcher + wedge + backend suites still PASS.

- **Risks (top 2):** (1) a wedge false-positive on a transient API blip /
  healthy mid-resume pod — guarded by the K=900s DEDICATED `wedge_first_seen`
  floor (stamped at wedge ONSET, not pod boot, so the K window measures the
  actual no-port episode; cleared on any non-wedge tick so a one-tick blip
  resets it) AND a ≥2-consecutive-checks miss guard mirroring the existing
  auto-stop arm, so a single glitch never stops a pod; (2) double-firing with
  the poller when BOTH are alive — harmless because the watcher only STOPS
  (reversible) and only after the K floor + miss guard, and the poller's
  terminate path is idempotent (durable lease + sentinel from #689 blocker-2);
  the realistic concurrent case is the poller wins first (it matures at K,
  terminates) and the watcher's next tick sees the pod gone from the RUNNING
  set and GCs its state.

## 1. Goal

Add a RUNNING-but-no-port wedge predicate to
`scripts/autonomous_session_watch.py`'s pod-safety pass so that — when the
poller-side `_maybe_escalate_runpod_wedge` in `scripts/backend_poll.py` never
runs because the poll loop has died — the watcher still detects the #664 wedge
and alerts / auto-stops the billing leak. The new predicate composes with the
existing #689 fix (b) (it calls fix (b)'s raw wedge condition, never
re-defines it), ages it against a DEDICATED wedge-onset clock the watcher
owns, and gates any auto-stop on the same inputs-on-HF + `keep-running` checks
as fix (b) (with the keep-running check made tri-state so a tag-read failure is
never silently treated as "untagged").

### 4.2 Composition surface (b): extract the raw wedge predicate

In `scripts/backend_poll.py`, the raw wedge condition is currently INLINE in
`_maybe_escalate_runpod_wedge` (L539-544): a pod is wedge-eligible iff its live
`PodInfo` is RUNNING with no public port. Extract:

```python
def _pod_is_runpod_runtime_wedged(info) -> bool:
    """True iff a live RunPod ``PodInfo`` is in the RAW #664 no-port wedge
    condition: ``desired_status == "RUNNING"`` AND no public SSH port
    (``runtime.ports`` empty -> ``runpod_api._parse_pod`` sets
    ``ssh_host``/``ssh_port`` to ``None``). This is the MATURITY-AGNOSTIC raw
    condition only — the K-floor age check stays with each caller (the poller
    uses its sidecar clock; the watcher uses its OWN dedicated wedge_first_seen
    clock). ``info is None`` (pod gone) -> ``False`` (not a wedge; the gone
    pod is the ordinary dead path). The single source of truth for the wedge
    condition, called by BOTH ``_maybe_escalate_runpod_wedge`` (poller) and the
    autonomous_session_watch.py pod-safety wedge arm (watcher backstop, #692)."""
    if info is None:
        return False
    if getattr(info, "desired_status", None) != "RUNNING":
        return False
    return not (info.ssh_host and info.ssh_port)
```

Then `_maybe_escalate_runpod_wedge`'s `healthy_or_terminal` block (L540-544)
becomes:

```python

        _clear_runpod_noport_clock(sidecar)
        return result
    # RUNNING + no public port: start/continue the no-port clock. (unchanged below)
```

### 4.4 The watcher wedge arm in `_process_pod`

`_process_pod` gains the live `PodInfo` and runs the wedge arm FIRST, before the
existing status-class branches — BUT with a DONE-task carve-out (MF6) so a
wedged-AND-DONE-task pod is not demoted to ALERT-only. Signature change:

```python
def _process_pod(
    issue: int, pod_id: str, info, now: float, dry_run: bool, threshold: int
) -> None:
    """... (existing docstring) ...

    #692 wedge-arm ordering (MF6): the wedge arm runs BEFORE the status-class
    branches, EXCEPT that a wedged pod whose task is at a DONE status
    (completed / archived / awaiting_promotion — the established escaped-pod
    auto-stop case) FALLS THROUGH to the status-class DONE arm, which already
    auto-stops it. Rationale: a DONE-task pod has no live work to strand, so the
    status-class DONE auto-stop (which already exists and is the canonical
    escaped-pod handler) wins; routing a DONE-task wedge through the wedge arm's
    ALERT-default + inputs-gate would only WEAKEN the existing auto-stop into a
    conditional one. The wedge arm therefore handles only NON-DONE-status wedged
    pods (running / approved / verifying / interpreting / reviewing /
    plan_pending / followups_running — the live-work statuses where the watcher
    must be conservative). A non-wedged pod reaches the status-class branches
    unchanged, exactly as today."""
```

`_DONE_POD_STATUSES` is the existing done-status set the status-class arm
already uses for its escaped-pod auto-stop (the implementer reuses the existing
constant / predicate — `decide_pod_safety`'s `status_class == "pod-escaped-done"`
mapping; grep the existing done-status classifier rather than re-listing the
enum). The `_clear_wedge_state` call on the not-wedged branch is the MF1 clock

the place a healed pod's stale wedge fields are cleared.

`_process_wedged_pod` is a new handler that mirrors the existing `_process_pod`
state mechanics but for the wedge episode, using the DEDICATED wedge clock:

```python
def _process_wedged_pod(
    issue: int, info, now: float, dry_run: bool, threshold: int
) -> None:
    """Handle a RUNNING managed pod observed in the #664 RunPod no-port wedge
    (raw condition already confirmed by the caller; the caller already excluded
    DONE-status pods, MF6). Age the wedge against the DEDICATED wedge_first_seen
    clock (stamped at wedge onset, NOT the pod-incarnation first_seen, MF1);
    below K (RUNPOD_WEDGE_K_SEC) KEEP + persist (the wedge has not matured — a
    healthy slow bring-up clears it on a later tick when the port appears);
    past K apply the >=threshold consecutive-wedge-checks miss guard, then ALERT
    (default) or AUTO-STOP (reversible pod.py stop) gated on the same
    inputs-on-HF + (tri-state) keep-running checks as #689 fix (b)."""
    from backend_poll import RUNPOD_WEDGE_K_SEC

    pod_id = info.pod_id
    prev_state = _load_pod_safety_state(issue)

    # ── MF4: pod_id-change reset ──────────────────────────────────────────
    # The pod-safety state is keyed on `issue`, not (issue, pod_id). If the
    # poller re-provisioned the same issue with a fresh pod_id, the persisted
    # wedge fields are stale from the OLD pod -> a fresh healthy pod could be
    # stopped during normal startup, or a long-running pod stopped after two
    # stale runtime.ports reads. Reset all wedge fields on a pod_id mismatch.
    prev_pod_id = prev_state.get("pod_id")
    if prev_pod_id != pod_id:
        # new (or first-seen) incarnation -> start the wedge clock fresh
        wedge_first_seen = None
        prev_wedge_missed = 0
        prev_wedge_alerted = False
    else:
        wedge_first_seen = prev_state.get("wedge_first_seen")
        prev_wedge_missed = prev_state.get("wedge_missed", 0)
        prev_wedge_alerted = bool(prev_state.get("wedge_alerted", False))

    # ── MF1: dedicated wedge_first_seen clock ─────────────────────────────
    # Stamp `now` on the FIRST tick the raw wedge predicate is True (wedge
    # ONSET). The not-wedged branch in _process_pod calls _clear_wedge_state,
    # so a port re-appearance resets this to None -> a one-tick blip never
    # matures. This measures the actual no-port episode length, NOT pod uptime.
    if not isinstance(wedge_first_seen, int | float):
        wedge_first_seen = now  # first wedged tick this incarnation
    wedged_for = now - wedge_first_seen

    if not isinstance(prev_wedge_missed, int):
        prev_wedge_missed = 0

    # ── MF2: tri-state keep-running gate ──────────────────────────────────
    keep_running = _wedge_keep_running(issue)  # True | False | "unknown"
    inputs_ok = (
        _wedge_inputs_safe(issue) if keep_running is False else False
    )

    action, new_wedge_missed = decide_pod_wedge(
        wedged_for=wedged_for,
        k_floor=RUNPOD_WEDGE_K_SEC,
        wedge_missed=prev_wedge_missed,
        threshold=threshold,
        alerted=prev_wedge_alerted,
        keep_running=keep_running,   # tri-state
        inputs_ok=inputs_ok,
    )

    # ... log line, then branch on action (stop / alert / keep). In ALL
    # branches persist wedge_first_seen + new_wedge_missed + wedge_alerted +
    # pod_id via _save_pod_safety_state (MF3 forward-carry); the stop branch
    # does NOT call _clear_pod_safety_state (that would wipe the pod-incarnation
    # first_seen GC anchor) — it persists the wedge fields and leaves first_seen
    # intact for _gc_orphan_pod_safety_state (MF3).
```

The miss-guard is a NEW per-pod state field `wedge_missed` (separate from the
status-class `missed`, since the two arms are mutually exclusive on a given tick
but a pod can transition wedge→status-class or vice versa across ticks; keeping
them separate means a brief mis-read in one arm never primes a stop in the
other). The clock is the NEW dedicated `wedge_first_seen` (MF1) — NOT the
pod-incarnation `first_seen`, which stays exactly as it is for the existing
GC/ordinary-state behavior.

### 4.4a State persistence wiring (MF3)

`_save_pod_safety_state` currently writes a FIXED payload dict (L1986-1994) with
no `**extra`/kwargs passthrough, so the three new wedge fields would be silently
dropped on every save → the ≥2-miss guard would never accumulate and the
once-per-episode alert dedup would break. The fix extends
`_save_pod_safety_state`'s signature to forward-carry the three new fields,
mirroring its existing `keep_running_noted`/`followup_noted` forward-carry
pattern (None-carries-forward from the prior state):

```python
def _save_pod_safety_state(
    issue: int,
    *,
    # ... existing params (missed, alerted, first_seen, last_progress_ts,
    #     keep_running_noted, followup_noted) ...
    pod_id: str | None = None,            # MF4: incarnation key
    wedge_first_seen: float | None = None,  # MF1: dedicated wedge clock
    wedge_missed: int | None = None,        # MF3: wedge miss-guard
    wedge_alerted: bool | None = None,      # MF3: wedge alert dedup
) -> None:
    prev = _load_pod_safety_state(issue)
    payload = {
        # ... existing fields ...
        # forward-carry pattern (None -> keep prior value):
        "pod_id": pod_id if pod_id is not None else prev.get("pod_id"),
        "wedge_first_seen": (
            wedge_first_seen if wedge_first_seen is not None
            else prev.get("wedge_first_seen")
        ),
        "wedge_missed": (
            wedge_missed if wedge_missed is not None
            else prev.get("wedge_missed", 0)
        ),
        "wedge_alerted": (
            wedge_alerted if wedge_alerted is not None
            else bool(prev.get("wedge_alerted", False))
        ),
    }
    # ... existing atomic write ...
```

(A sibling `_save_pod_wedge_state` writer was considered and rejected — it would
fork the atomic-write + forward-carry logic and risk the two writers clobbering
each other's fields on interleaved ticks. Extending the single writer keeps ONE
atomic write per tick.)

`_clear_wedge_state(issue, pod_id)` (called on the not-wedged branch in §4.4)
persists `wedge_first_seen=None, wedge_missed=0, wedge_alerted=False` while
KEEPING the pod-incarnation `first_seen` intact (it calls
`_save_pod_safety_state` with the cleared wedge kwargs, NOT
`_clear_pod_safety_state`, which clears the whole file and would break the GC
anchor). It also records the current `pod_id`.

**Round-trip test surface (MF3).** The `wedge_unconfirmed` and
`wedge_alert_dedup` unit tests each include a load-after-save assertion: save
state with `wedge_missed=1` (resp. `wedge_alerted=True`), then
`_load_pod_safety_state(issue)` and assert the field survived. Without this a
silently-dropped field passes the in-memory decision-fn tests but fails in
production (the v2 latent bug this MF closes).

### 4.5 The pure wedge decision function (parallel to `decide_pod_safety`)

```python
def decide_pod_wedge(
    *,
    wedged_for: float,
    k_floor: float,
    wedge_missed: int,
    threshold: int,
    alerted: bool,
    keep_running: bool | str,   # True | False | "unknown" (MF2 tri-state)
    inputs_ok: bool,
) -> tuple[str, int]:
    """Pure decision for a RUNNING managed pod in the #664 no-port wedge.

    Returns ``(action, new_wedge_missed)`` where action is
    ``"stop"`` | ``"alert"`` | ``"keep"``.

    - ``wedged_for <= k_floor`` -> ``("keep", 0)``. Below the K maturity floor
      the wedge has not matured (a healthy slow bring-up clears it when the
      port appears); reset the miss counter so a brief no-port blip never
      accumulates toward a stop. NOTE the comparator is ``<=`` here (and ``>``
      below) to MATCH the poller's ``wedged_for > RUNPOD_WEDGE_K_SEC`` at
      backend_poll.py:568 — ``wedged_for == k_floor`` KEEPs (MF5 boundary).
    - ``wedged_for > k_floor`` AND ``wedge_missed + 1 < threshold`` ->
      ``("keep", wedge_missed + 1)``. Past K but not yet confirmed for
      ``>=threshold`` consecutive checks; accumulate (the same >=2-checks guard
      the status-class auto-stop uses, so a single transient API mis-read never
      stops a pod). The action transitions exactly when
      ``wedge_missed + 1 == threshold`` (MF5 boundary).
    - ``wedged_for > k_floor`` AND confirmed (``wedge_missed + 1 >= threshold``):
        - ``keep_running is True`` -> ``("alert", 0)``. The keep-running tag
          exempts the AUTO-STOP exactly as it does for the status-class arm; the
          wedge is still surfaced once per episode so the leak is visible. (No
          "keep-running-skip" action — the wedge ALERT already carries the
          tag-exemption note; the status-class arm's distinct skip action exists
          only to reset its own miss counter, which the alert branch does here.)
        - ``keep_running == "unknown"`` -> ``("alert", 0)`` (MF2). A PERSISTENT
          tag-read failure (subprocess error, non-zero rc, JSON parse error) is
          NOT the same as a genuinely untagged task. A tagged live-work pod
          whose tag lookup is failing must NOT be auto-stopped (that would
          silently override the user's explicit keep-running tag); route the
          uncertainty to ALERT-only. This is the fail-closed posture genuinely
          delivered — a stronger gate than the status-class DONE arm, which can
          inherit False-on-failure because it only auto-stops DONE-status pods
          (where the user has far less reason to keep-running). The wedge arm
          auto-stops live-work (running/approved/...) pods, so False-on-failure
          is NOT safe-by-analogy here.
        - ``keep_running is False`` AND ``inputs_ok`` -> ``("stop", 0)``. Inputs
          are verified on HF (the same gate as #689 fix (b)) AND the tag was
          read AND it is absent, so the reversible STOP is safe — halt the
          billing leak.
        - ``keep_running is False`` AND not ``inputs_ok`` -> ``("alert", 0)``.
          Inputs are NOT verified on HF (or no run handle to gate on); a STOP
          could strand un-uploaded work, so ALERT-only and let a human / the
          re-invoked /issue decide (CLAUDE.md halt-criterion #2). The
          poller's fix (b) is the path that terminates after the per-cell gate;
          the watcher backstop never terminates and only stops when inputs are
          provably safe.

    Decision invariant (MF2): ``("stop", _)`` is returned ONLY when
    ``keep_running is False`` (the literal boolean False, NOT "unknown" and NOT
    True) AND ``inputs_ok is True``. Every other keep_running value routes to
    ALERT-only. The unit suite includes a case where keep_running == "unknown"
    AND inputs_ok is True AND the wedge is confirmed, asserting the action is
    "alert", NOT "stop".

    The ``alerted`` flag dedups the once-per-episode alert (the caller passes it
    and persists ``wedge_alerted``); a fresh wedge episode (the wedge clock was
    cleared by a port re-appearance or a pod_id change) starts ``alerted=False``."""
```

The alert dedup mirrors the status-class arm: `_process_wedged_pod` passes
`alerted=prev_wedge_alerted` and, when `action == "alert"`, posts the marker
only if `not prev_wedge_alerted`, then persists `wedge_alerted=True`. When the
port re-appears (the pod heals or is re-provisioned) the not-wedged branch
clears the wedge state; if the pod leaves RUNNING entirely,
`_gc_orphan_pod_safety_state` reaps the whole state file.

### 4.5a The tri-state keep-running wrapper (MF2)

`_task_keep_running(issue)` (L1563-1572) returns `False` on subprocess error,
non-zero rc, AND JSON parse error — indistinguishable from a genuinely untagged
task. The wedge arm needs to tell "tag absent" from "tag unreadable", so a
wedge-specific wrapper catches the failure modes itself and returns the
tri-state (chosen over changing `_task_keep_running`'s own contract, which is
shared by the status-class DONE arm that deliberately wants False-on-failure):

```python
def _wedge_keep_running(issue: int) -> bool | str:
    """Tri-state keep-running read for the wedge arm (MF2): ``True`` (tag
    present) | ``False`` (tag read OK and absent) | ``"unknown"`` (the tag read
    FAILED — subprocess error, non-zero rc, JSON parse error). The wedge
    AUTO-STOP fires only on the literal ``False``; ``"unknown"`` routes to
    ALERT-only so a tagged live-work pod whose tag lookup is transiently failing
    is NEVER auto-stopped (which would silently override the user's keep-running
    tag). This is a STRONGER gate than the status-class DONE arm's
    False-on-failure (`_task_keep_running`), which is safe ONLY because that arm
    auto-stops DONE-status pods; the wedge arm auto-stops live-work pods, so it
    cannot inherit False-on-failure by analogy."""
    try:
        out = subprocess.run(
            [sys.executable, str(_TASK_PY), "view", str(issue), "--json"],
            capture_output=True, text=True, timeout=30,
        )
        if out.returncode != 0:
            return "unknown"
        tags = json.loads(out.stdout).get("frontmatter", {}).get("tags", [])
        return "keep-running" in tags
    except Exception:
        return "unknown"
```

(The implementer reuses the EXACT task.py invocation `_task_keep_running`
already uses — the snippet above is illustrative of the tri-state shape, not a
verbatim command; the binding requirement is: subprocess error / non-zero rc /
JSON parse error → `"unknown"`, tag-read-OK-and-absent → `False`, present →
`True`.) The arm treats `"unknown"` as a persistent condition per tick: because
the wedge requires `>=threshold` consecutive confirmed-past-K ticks before any
action, a single-tick tag-read blip that resolves on the next tick simply
delays maturation by one tick (the action on a confirmed-`"unknown"` tick is
ALERT-only regardless), so there is no separate "≥2 ticks of unknown" counter —
ALERT-only is already the most conservative confirmed action.

### 4.6 The inputs-on-HF gate (compose with fix (b))

The candidate body requires "the same inputs-on-HF + keep-running checks as fix
(b)." Fix (b)'s gate is `backend_poll._wedged_run_inputs_on_hf(issue, handle)
-> _WedgeInputsGate` (`.ok` True iff zero partial cells). It needs a run
handle. The watcher does NOT always have one in hand, but the handle is
persisted at `.claude/cache/issue-<N>-handle.json`
(`issue_dispatch.resolve_handle_sidecar_path`), so:

```python
def _wedge_inputs_safe(issue: int) -> bool:
    """True iff the wedged run's recoverable inputs are verified on HF, gating
    the watcher's reversible AUTO-STOP exactly as #689 fix (b) gates the
    poller's irreversible terminate. Reuses backend_poll._wedged_run_inputs_on_hf
    (the per-cell three-state inputs-on-HF gate). The run handle is read from
    the persisted sidecar (.claude/cache/issue-<N>-handle.json). Fail-CLOSED:
    a missing/unreadable handle, an HF-listing transport error, or ANY
    exception -> False (ALERT-only, never an unsafe stop). For a non-#664 issue
    _wedged_run_inputs_on_hf returns ok=True (the adapters-only path is
    inline-verified), so the gate degrades to "safe to stop" for those — which
    is correct: a reversible STOP loses nothing when there are no per-cell
    artifacts to strand."""
    try:
        from backend_poll import _wedged_run_inputs_on_hf
        from explore_persona_space.backends.issue_dispatch import (
            read_handle_sidecar, resolve_handle_sidecar_path,
        )
        path, _probed = resolve_handle_sidecar_path(issue)
        if not path.exists():
            return False  # no handle -> cannot gate -> ALERT-only
        handle = read_handle_sidecar(path)
        gate = _wedged_run_inputs_on_hf(issue, handle)
        return bool(gate.ok)
    except Exception as exc:  # transport / parse / import -> fail-closed
        print(
            f"  wedge: inputs-on-HF gate unavailable for #{issue} "
            f"({type(exc).__name__}: {exc}); ALERT-only (no auto-stop)",
            file=sys.stderr,
        )
        return False
```

(`read_handle_sidecar` is the existing public reader at
`issue_dispatch.py:384` — it deserializes the sidecar JSON via
`deserialize_handle`. The `except Exception` wrapper means any future rename or
breakage degrades to ALERT-only.)

The fail-closed posture is deliberate and the SINGLE most important safety
property: the watcher AUTO-STOP only fires when inputs are PROVABLY safe AND the
keep-running tag was read AND is absent; every uncertainty path (no handle, HF
error, import failure, keep-running tag PRESENT, keep-running tag-read FAILURE)
routes to ALERT-only. A false ALERT is a cheap nudge; a false STOP is reversible
anyway (volume preserved), but ALERT-only on uncertainty keeps the watcher from
ever interrupting a run whose state it cannot read or whose keep-running tag it
cannot confirm absent.

## 11. Decision Rationale

- **What:** Composition surface (b) — extract a standalone raw-wedge predicate.
  **Why:** the candidate body's suggested `_is_runpod_async_wedge_failure` reuse
  is wrong — that predicate matches the SYNTHESIZED terminal phase the poller
  sets, which only exists when the poll loop is ALIVE (precisely when the
  backstop is NOT needed). The watcher must detect the RAW API condition.
  Option (a) (call `_maybe_escalate_runpod_wedge`) double-writes the poller's
  sidecar clock the watcher doesn't own and couples the watcher to the poller's
  mutation surface; option (c) (re-implement) violates the "do NOT re-define"
  constraint. (b) gives ONE source of truth for the wedge condition with no
  shared mutable state. **Source:** #689 `backend_poll.py` L515-583 (the inline
  condition extracted), clarifier item 1.

- **What:** A DEDICATED `wedge_first_seen` clock (stamped at wedge ONSET,
  cleared on any non-wedge tick), NOT the reused pod-incarnation `first_seen`.
  **Why (MF1, round-2 critic):** `first_seen` is forward-carried from the first
  save of any RUNNING pod-incarnation and only reaped when the pod LEAVES
  RUNNING; a wedged pod stays RUNNING, so for the canonical #664 heal-then-wedge
  case `first_seen` is the BOOT timestamp and `wedged_for ≫ K` on the FIRST
  wedged tick → the K floor would be silently vacuous and a transiently-blipping
  pod would stop after only the 2-miss guard (~20 min) with no real K-second
  no-port episode. A dedicated clock stamped at onset measures the actual no-port
  episode length; clearing it on any non-wedge tick means a one-tick blip resets
  it. `first_seen` is kept UNCHANGED for the existing GC/ordinary-state behavior.
  **Source:** MF1 (round-2 Methodology + Alternatives critic ensemble);
  `autonomous_session_watch.py` L1979-1981 (`first_seen` forward-carry),
  L2123 (`_gc_orphan_pod_safety_state` reaps only on RUNNING-exit).

- **What:** A TRI-STATE keep-running gate (`_wedge_keep_running` →
  `True | False | "unknown"`); the wedge STOP fires ONLY on the literal `False`.
  **Why (MF2, round-2 Statistics critic):** the shared `_task_keep_running`
  (L1563-1572) returns `False` on subprocess error, non-zero rc, AND JSON parse
  error — indistinguishable from a genuinely untagged task. A persistent tag-read
  failure on a tagged live-work pod (with inputs-on-HF) would route to STOP,
  silently overriding the user's explicit `keep-running` tag and contradicting
  the §4.6 "every uncertainty path → ALERT-only" invariant. The wedge arm
  auto-stops `running`/`approved` live-work pods, so it CANNOT inherit the
  DONE-arm's safe-by-context False-on-failure (the DONE arm only auto-stops
  DONE-status pods, where the user has far less reason to keep-running). A
  wedge-specific wrapper catches the failure modes and returns `"unknown"` →
  ALERT-only, leaving `_task_keep_running`'s shared contract untouched.
  **Source:** MF2 (round-2 Statistics critic ensemble);
  `autonomous_session_watch.py` L1563-1572 (`_task_keep_running` False-on-error).

- **What:** Extend `_save_pod_safety_state` to forward-carry `pod_id`,
  `wedge_first_seen`, `wedge_missed`, `wedge_alerted`; the wedge STOP branch
  persists (never `_clear_pod_safety_state`). **Why (MF3, round-2 Statistics
  critic standing rec, lifted):** `_save_pod_safety_state` writes a FIXED payload
  dict (L1986-1994) with no kwargs passthrough, so the three new fields would be
  silently dropped on every save → the ≥2-miss guard would never accumulate
  (AUTO-STOP never fires, or fires WRONG because the alert dedup also breaks).
  Forward-carrying them mirrors the existing `keep_running_noted`/`followup_noted`
  pattern (None-carries-forward) and keeps ONE atomic write per tick (a sibling
  writer would risk interleaved-tick clobbering). The STOP branch must NOT call
  `_clear_pod_safety_state` (whole-file clear) — it must persist the cleared
  wedge fields while keeping the pod-incarnation `first_seen` intact for GC.
  Round-trip (load-after-save) assertions pin the wiring. **Source:** MF3
  (round-2 Statistics critic); `autonomous_session_watch.py` L1986-1994
  (`_save_pod_safety_state` fixed payload), L1979 (forward-carry pattern).

- **What:** Reset all wedge fields on a `pod_id` change (state keyed on `issue`,
  not `(issue, pod_id)`). **Why (MF4, round-2 Alternatives Codex critic):** a
  poller re-provisioning the same `issue` with a fresh `pod_id` keeps
  `wedge_first_seen`/`wedge_missed`/`wedge_alerted` stale from the OLD pod — the
  watcher could STOP a fresh healthy pod during normal startup, or STOP a
  long-running pod after two stale `runtime.ports` reads without a true >K
  no-port episode on the new incarnation. `pod_id` is already on the live
  `PodInfo`; persisting it in the pod-safety state and resetting the wedge fields
  on a mismatch is a few lines. **Source:** MF4 (round-2 Alternatives critic);
  `runpod_api.PodInfo` (carries `pod_id`).

- **What:** K = imported `RUNPOD_WEDGE_K_SEC` (900s), never a duplicated
  literal, compared with `wedged_for > K` (strict). **Why:** the "compose with
  #689 fix (b), do NOT re-define it" constraint — the watcher and poller MUST
  agree on the maturity floor, so they share the constant AND the comparator
  (`backend_poll.py:568` uses `> K`). 900s is above `wait_for_ssh`'s 600s window
  + a retry margin, so a healthy mid-resume pod never trips. **Source:** #689
  plan §B.3 / `backend_poll.py` L131 (`RUNPOD_WEDGE_K_SEC`), L568 (comparator);
  MF5 (round-2 boundary-test rec).

- **What:** ALERT-default, AUTO-STOP only when inputs-on-HF + tri-state
  keep-running gates pass; reversible STOP, never terminate. **Why:** the
  candidate body requires "gate any auto-stop on the same inputs-on-HF +
  keep-running checks as fix (b)" and "default to ALERT-only" without that gate.
  The watcher runs blind to the dispatcher's resume state and has no run-handle
  guarantee, so the irreversible terminate (fix (b)'s job, gated on the full
  per-cell three-state inputs gate with a live handle) is wrong for the backstop;
  the reversible STOP halts the billing leak while preserving the volume for a
  human / re-invoked `/issue` to resume or re-provision. Fail-closed on every
  uncertainty (no handle, HF error, tag present, tag-read failure) → ALERT-only.
  **Source:** candidate body constraints; CLAUDE.md halt-criterion #2
  (irreversible writes need a human); #689 `_wedged_run_inputs_on_hf` (the
  reused gate).

- **What:** `>=2`-consecutive-confirmed-checks miss guard (new `wedge_missed`
  field), action transition exact at `wedge_missed + 1 == threshold`. **Why:**
  mirrors the existing `decide_pod_safety` auto-stop guard so a single transient
  API mis-read never stops a pod; a separate field keeps the two arms from
  priming each other; the exact transition (not `>=`-loose) is pinned by MF5.
  **Source:** `decide_pod_safety` L973+ (the existing 2-miss guard the wedge arm
  copies); MF5 (round-2 boundary-test rec).

- **What:** DONE-task wedge fall-through (MF6). **Why:** a wedged pod whose task
  is at a DONE status (the established escaped-pod auto-stop case) must NOT be
  demoted to the wedge arm's ALERT-default + inputs-gate — it has no live work to
  strand, so the existing status-class DONE auto-stop should win. The wedge arm
  reads `status` first and falls through for DONE statuses. **Source:** MF6
  (round-2 critic); the existing status-class DONE auto-stop in
  `decide_pod_safety`.

- **What:** No new `workflow.yaml` marker schema; generic `epm:progress` +
  sentinel substrings. **Why:** the candidate body's "do NOT propose new GitHub
  markers / event kinds; surface alerts via the existing `_post_progress_marker`
  mechanic" constraint — every existing watcher action already does this.
  **Source:** candidate body constraint; `_post_progress_marker` L2145.
