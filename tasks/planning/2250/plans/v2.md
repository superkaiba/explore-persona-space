## 1. Ground truth (from #1336 precheck, SLURM job 11981 — recorded in the task body)

- Allocation: `AllocTRES=...,gres/gpu=1`, `GRES=gpu:1(IDX:5)`; inside the job `CUDA_VISIBLE_DEVICES=5`.
- Mistake (a): dispatcher computed `NGPU=$(nvidia-smi --list-gpus | wc -l)` → `8`. `nvidia-smi` is a driver-level enumeration; on nodes without cgroup device isolation (fellows SLURM) it reports NODE width, never JOB width, and ignores `CUDA_VISIBLE_DEVICES` entirely.
- Mistake (b): dispatcher overrode the inherited `CUDA_VISIBLE_DEVICES=5` with the literal index `0`. Under inherited `CVD=5`, `cuda:0` IS physical GPU 5 — re-exporting `CVD=0` retargets the job onto unallocated GPU 0 (another user's device).
- Why latent: whole-node allocations (8/8 GPUs) make node-width == job-width and literal indices == allocated indices, so the bug only fires on narrow allocations — exactly the cheap 1-GPU prechecks.
- Probe discipline: per-node GPU probes must run INSIDE the allocation (`srun --jobid=<id> --overlap ...`), or they see the node, not the job.
