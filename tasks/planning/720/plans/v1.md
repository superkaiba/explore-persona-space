# Plan — #720: Reap completed autonomous `/issue --auto` sessions within ~1h (not 12h)

## 0. Plan Summary

**Workflow-fix (`kind: infra`).** No model, no GPU, no behavioral construct.
A completed autonomous `/issue --auto` session today lingers as a "running"
ghost for up to ~12h because the moment its task hits a terminal status
(`completed`/`archived`/`awaiting_promotion`) the crash-recovery pass DELETES
`~/.eps-autonomous/issue-<N>.json`, which UNMAPS the session, dropping it out
of the 2h terminal-reconcile pass and into the generic 12h idle-unmapped
bucket. **Fix (chosen = body option 2, watcher-side):** at the instant the
respawn pass deletes `issue-<N>.json` for a TERMINAL task, write a small
durable breadcrumb `~/.eps-autonomous/last-mapped-terminal-<sid>.json`
recording `{happy_session_id, issue, terminal_status, recorded_at}`; the
idle-unmapped pass reads that breadcrumb and, for a session whose last-known
mapped task is terminal, applies a SHORT reap window (`LAST_MAPPED_TERMINAL_REAP_S
= 45 min`) instead of the 12h `UNMAPPED_IDLE_REAP_S`. Every existing
idle-unmapped exclusion (live-user TTY, running pod, `keep-running`, live
follow-up, unresolvable transcript → fail-toward-keep) is preserved unchanged;
the short window only narrows WHEN a session that was ALREADY going to be
reaped gets reaped.

- **Training:** N/A — no model training
- **Hyperparameters:** N/A — no model training
- **Baselines / controls:** the six acceptance scenarios in §5 (completed →
  reaped < 1h; active / TTY / live-follow-up / running-pod / `keep-running` →
  untouched)
- **Loss surface:** N/A — no model training
- **Compute:** none. CPU-only watcher edit + pytest. Estimated GPU-hours (total): 0
- **Evaluation:** the new + amended pytest tests in §6 all pass; `workflow_lint.py`

- **Risks (top 2):** (a) a false short-window reap of a session the user is

  live-user-TTY + 2-miss + idle-grace guards; (b) breadcrumb GC leak —
  mitigated by reaping the breadcrumb when its session leaves the live set
  (mirrors `_gc_orphan_idle_unmapped_state`).

## 1. Goal

Completed-task autonomous `/issue --auto` sessions get reaped within ~1h of
the task reaching a terminal/park state (`completed`/`awaiting_promotion`/
`archived`/`blocked`), not the current ~12h, with no manual sweep — while
every existing exclusion (live user TTY, running pod, `keep-running` tag,
live same-issue follow-up, non-terminal task) stays untouched.

### 4.1 New constant + env helper (near the idle-unmapped block, ~line 9928)

```python
# Short reap window for an UNMAPPED session whose LAST-known mapped task was
# TERMINAL (the #720 ghost class: issue-<N>.json deleted by the respawn pass
# at terminal -> session unmapped -> previously only the 12h bucket caught it).
# 45 min keeps the post-terminal session well clear of any same-tick
# promotion/finalize activity (which resets the idle clock anyway) while
# clearing the ghost within the ~1h acceptance window. Override via
# EPM_LAST_MAPPED_TERMINAL_REAP_S.
LAST_MAPPED_TERMINAL_REAP_S = 45 * 60

# Filename prefix for the per-session "last mapped task was terminal"
# breadcrumb at ~/.eps-autonomous/last-mapped-terminal-<sid>.json. Written by
# the respawn pass at the instant it deletes issue-<N>.json for a TERMINAL
# task; read by the idle-unmapped pass to pick the short reap window.
LAST_MAPPED_TERMINAL_PREFIX = "last-mapped-terminal-"


def _last_mapped_terminal_reap_s() -> float:
    """Short reap window (s): EPM_LAST_MAPPED_TERMINAL_REAP_S when set to a
    positive number, else LAST_MAPPED_TERMINAL_REAP_S (45 min). Garbled /
    non-positive falls back (same parse as _unmapped_idle_reap_s)."""
    raw = os.environ.get("EPM_LAST_MAPPED_TERMINAL_REAP_S", "")
    try:
        val = float(raw)
    except ValueError:
        return LAST_MAPPED_TERMINAL_REAP_S
    return val if val > 0 else LAST_MAPPED_TERMINAL_REAP_S
```

### 4.2 Breadcrumb read/write + GC helpers (near the idle-unmapped state helpers, ~line 10477)

```python
def _last_mapped_terminal_path(sid: str) -> Path:
    return AUTONOMOUS_REGISTRY_DIR / f"{LAST_MAPPED_TERMINAL_PREFIX}{sid}.json"


def _record_last_mapped_terminal(
    sid: str, issue: int, terminal_status: str, dry_run: bool, now: float | None = None
) -> None:
    """Write the #720 breadcrumb atomically (temp + rename). Idempotent: a
    re-write for an already-recorded sid just refreshes the fields. Fail-soft:
    an OSError on write is logged and swallowed (the breadcrumb is an
    OPTIMIZATION — a missing one only means the session reaps at the old 12h
    window, never a wrong kill). Skipped under dry_run."""
    if dry_run:
        return
    AUTONOMOUS_REGISTRY_DIR.mkdir(parents=True, exist_ok=True)
    payload = {
        "happy_session_id": sid,
        "issue": issue,
        "terminal_status": terminal_status,
        "recorded_at": now if now is not None else time.time(),
    }
    dest = _last_mapped_terminal_path(sid)
    tmp = dest.with_suffix(".json.tmp")
    try:
        tmp.write_text(json.dumps(payload, indent=2))
        tmp.replace(dest)
    except OSError as e:
        print(f"  last-mapped-terminal: write failed for {sid}: {e}", file=sys.stderr)


def _last_mapped_terminal_status(sid: str) -> str | None:
    """The recorded terminal status for sid, or None (no breadcrumb / garbled
    / not a terminal status). Validates the recorded status against TERMINAL so
    a stale/garbled value can never widen scope."""
    path = _last_mapped_terminal_path(sid)
    if not path.is_file():
        return None
    try:
        data = json.loads(path.read_text())
    except (json.JSONDecodeError, OSError):
        return None
    status = data.get("terminal_status") if isinstance(data, dict) else None
    return status if status in TERMINAL else None


def _gc_orphan_last_mapped_terminal(live_sids: set[str], dry_run: bool) -> None:
    """Drop breadcrumbs whose session is no longer live (reaped, or the user
    promoted + the session ended). Called once per daemon-reachable tick from
    idle_unmapped_pass, mirroring _gc_orphan_idle_unmapped_state."""
    for path in AUTONOMOUS_REGISTRY_DIR.glob(f"{LAST_MAPPED_TERMINAL_PREFIX}*.json"):
        sid = path.name[len(LAST_MAPPED_TERMINAL_PREFIX):-len(".json")]
        if sid not in live_sids and not dry_run:
            path.unlink(missing_ok=True)
```

### 4.3 Write the breadcrumb in the respawn pass (`_process_entry`, line 12726)

`_process_entry` already has `entry` (carrying `issue` + `happy_session_id`)
and `status` in scope at the `action == "delete"` branch. Amend ONLY the
delete branch:

```python
    if action == "delete":
        # #720: before unmapping, drop the breadcrumb so the idle-unmapped
        # pass can reap this now-unmapped session on the SHORT window. Only
        # for the live session we just observed (sid present + in live_ids);
        # a dead/missing session needs no breadcrumb (nothing to reap).
        sid = entry.get("happy_session_id")
        if isinstance(sid, str) and sid and sid in live_ids and isinstance(issue, int):
            _record_last_mapped_terminal(sid, issue, status, dry_run)
        if not dry_run:
            path.unlink(missing_ok=True)
```

The `sid in live_ids` guard means a breadcrumb is written only for a session
that is still live at the moment of unmapping — exactly the ghost class. A
session that already exited needs no breadcrumb. `awaiting_promotion`,
`completed`, `archived` all flow through `decide()` → `"delete"` → this branch,
so all three terminal states are covered. (`blocked` is PARK → never deleted →
its registry stays mapped → the reconcile pass already covers it; no breadcrumb
needed for `blocked`, and `_last_mapped_terminal_status` returns None for it
anyway since `blocked` ∉ `TERMINAL`.)

### 4.4 Consume the breadcrumb in the idle-unmapped pass

Two surgical edits in `_process_idle_unmapped` (line 10841), AFTER the existing
`idle_reap_s = _unmapped_idle_reap_s()` (line 10893) and BEFORE the #695
fallback block (so a recorded-terminal session still gets the short window even
on the primary transcript path):

```python
    idle_reap_s = _unmapped_idle_reap_s()

    # #720: an unmapped session whose LAST-known mapped task was TERMINAL gets
    # the SHORT reap window (default 45 min) instead of 12h — it is a finished
    # autonomous /issue session, not a generic abandoned chat session. Only
    # narrows WHEN; every exclusion below (TTY, running pod, follow-up,
    # missing-signal -> keep) is unchanged. Mapped sessions never reach this
    # (the breadcrumb is read only in the unmapped branch).
    short_window = False
    if not mapped and not has_tty and _last_mapped_terminal_status(sid) is not None:
        idle_reap_s = min(idle_reap_s, _last_mapped_terminal_reap_s())
        short_window = True
```

The `min(...)` is defensive: it can only ever SHORTEN, never lengthen, the
window even if an operator set `EPM_UNMAPPED_IDLE_REAP_S` below 45 min. The
`source_label` print (line 10929) gains `" window=short-terminal"` when
`short_window` for observability. The #695 fallback block stays unchanged: if
the primary transcript signal is unavailable it still falls back to tmux
activity at the (longer) fallback window — a recorded-terminal session with no
resolvable transcript is the rare case, and keeping it on the conservative
fallback window is the right fail-toward-keep posture.

**Crucially, no protected-class guard is removed.** The short window is applied
strictly AFTER `not mapped and not has_tty`, and `decide_idle_unmapped` still
enforces: `idle_age_s is None → ("skip", missed)` (transcript unresolvable →
keep), the `< idle_reap_s → ("clear", 0)` recency check, and the ≥2-miss guard.
The running-pod and live-follow-up exclusions are NOT in the idle-unmapped pass
today (those are reconcile-pass concerns for MAPPED sessions) — but for an
unmapped session the breadcrumb is written ONLY at the terminal transition, and
a live same-issue follow-up RE-REGISTERS `issue-<N>.json` (the orphan-sweep /
respawn path), re-mapping the session, so `mapped` becomes True and the short
window is never applied. This is the §7-risk-2 mitigation, asserted by a test.

### Why not edit `spawn_session.py`?

The body lists `spawn_session.py` as the registry write site, but the cleanest
breadcrumb-write site is the watcher's `_process_entry` (the exact line that
deletes the registry and unmaps the session — it already holds `entry` +
`status` + `live_ids`). Writing it there keeps the read + write + GC of the
breadcrumb all inside one file (`autonomous_session_watch.py`), avoids adding a
new on-disk record to `spawn_session.py`'s registration path (which the
dashboard + `cmd_list` + `_load_session_issue_map` read), and means NO public
`spawn_session.py` CLI/record-shape change → `architectural: false`. The
breadcrumb file uses a NEW prefix (`last-mapped-terminal-`) that is NOT matched
by the watcher's `issue-*.json` respawn glob (line 12511) nor by
`_load_session_issue_map`'s explicit prefix list
(`("issue-", "manual-issue-", "campaign-")`, spawn_session.py line 299), so it
can never be mistaken for a respawnable registration.

## 5. Conditions and Controls (acceptance scenarios)

N/A for an infra change in the experimental sense; instead the six scenarios
that prove acceptance (each becomes a test in §6):

| Plain-English name | What it asserts | What it controls for | Test seam |
|---|---|---|---|
| Completed → reaped < 1h | unmapped session, breadcrumb=`completed`, idle 50 min, ≥2 misses → `("stop", 0)` | the ghost class is reaped on the short window | `decide_idle_unmapped` + `_process_idle_unmapped` |
| Active session untouched | mapped (registry present) OR breadcrumb absent + idle < 12h → not stopped | never reap a live in-flight session | `idle_unmapped_pass` |
| TTY-attached session untouched | `has_tty=True` → `("clear", 0)` regardless of breadcrumb | a user sitting at the terminal | `decide_idle_unmapped` / `_is_live_user_tty` |
| Live follow-up untouched | follow-up re-registered `issue-<N>.json` → `mapped=True` → short window never applied | a `followups_running` / fresh `epm:run-launched` round | `idle_unmapped_pass` (re-mapped) |
| Running-pod session untouched | breadcrumb present but task revived w/ running pod re-maps it; if still unmapped, the reconcile/pod-safety pass owns the pod | a still-billing pod | mapping precedence test |
| `keep-running` untouched | task tagged `keep-running` stays at a non-terminal status (no terminal transition → no breadcrumb written) | the explicit user override | breadcrumb-write guard |

Control logic for the last three: the short window is ONLY reachable for a
session that (a) is unmapped AND (b) has a terminal breadcrumb AND (c) has no
live-user TTY. A live follow-up or a `keep-running`-extended run keeps the task
non-terminal (or re-registers it), so no breadcrumb is consulted; a running pod
on a revived task re-maps the session. The breadcrumb only ever applies to a
genuinely finished, genuinely unmapped session.

## 7. Risks and failure modes

| Risk | Likelihood | Mitigation |
|---|---|---|
| False short-window reap of an `awaiting_promotion` session the user is about to promote IN | Low | The session is reaped only if idle ≥45 min on ≥2 consecutive checks AND no live-user TTY. A user actively in the session holds a controlling TTY (`_is_live_user_tty` → `("clear", 0)`) or generates transcript activity (resets the idle clock). 45 min idle + no TTY + no activity = genuinely abandoned. The reconcile pass already auto-stops `awaiting_promotion` MAPPED sessions at 2h with the same posture (decision 2026-06-10 "stop the happy sessions once they reach awaiting promotion"); this just covers the unmapped twin at a tighter window. |
| Live same-issue follow-up reaped | Low | A follow-up RE-REGISTERS `issue-<N>.json` (respawn/orphan-sweep path) → `mapped=True` → the breadcrumb branch (`if not mapped`) is never entered → short window never applied. Asserted by `test_idle_unmapped_pass_active_mapped_never_short_reaped`. |
| Running pod on a revived task | Low | A revived task is non-terminal/re-mapped → `mapped=True` → short window skipped; the pod-safety pass owns the pod independently. |
| Breadcrumb file leak (one per completed session, never reaped) | Low | `_gc_orphan_last_mapped_terminal` reaps breadcrumbs for sids no longer in the live set, run every daemon-reachable tick (mirrors `_gc_orphan_idle_unmapped_state`). Files are ~120 bytes; even a leak is harmless, but the GC closes it. |
| Pass-ordering race (breadcrumb written by respawn pass at 12513, read by idle-unmapped at 11008→called from 12675) | None | The respawn pass runs EARLIER in the same `main()` tick than the idle-unmapped pass, so a breadcrumb written this tick is visible to the idle pass this tick. Cross-tick is the normal case (terminal transition this tick, reap a later tick once ≥45 min idle). |
| Recursion / self-stop loop | None | No self-exit involved; the watcher stops sessions via the existing `_do_idle_unmapped_stop` → daemon RPC, unchanged. |
| Garbled/stale breadcrumb widens scope | None | `_last_mapped_terminal_status` validates against `TERMINAL` and `min(...)` can only shorten the window; a garbled value → `None` → 12h default (no behavior change). |

## 13. Kill criterion

This approach is wrong if the short-window reap CANNOT be made to leave
protected sessions untouched — concretely:
- If `awaiting_promotion` sessions are the dominant breadcrumb class AND users
  routinely promote 45 min-2h after the park WITHOUT generating transcript
  activity or holding a TTY, the 45-min window would reap a session the user
  still wants. **Test of the kill criterion:** if `_is_live_user_tty` /
  transcript-idle do NOT reliably distinguish "user reading the draft" from
  "abandoned," the fix would need to EXCLUDE `awaiting_promotion` from the short
  window (only short-reap `completed`/`archived`, leaving `awaiting_promotion`
  on the 12h window). The breadcrumb already records `terminal_status`, so this
  narrowing is a one-line change (`_last_mapped_terminal_status` returning a
  status, and the consumer checking `status in {"completed", "archived"}`); the
  plan keeps the full `terminal_status` in the breadcrumb precisely so this
  fallback is cheap if review/usage flags it.
- (Why option 3 was rejected, recorded here as the contrast): a SKILL.md
  self-exit at `awaiting_promotion` races the user's promotion turn — the
  SKILL.md design explicitly has the session "idle until the user taps in via
  the relay to drive the next step" (SKILL.md § Stop the tick cron / In-session
  PushNotification). A self-exit there would kill the session the user is meant
  to promote in. Self-exit also does nothing for a session that died mid-stream
  (the exact ghost class) or for the legacy ghosts where the mapping is already
  lost — so the watcher must remain the backstop regardless, which is what this
  plan builds directly.
