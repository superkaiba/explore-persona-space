## 0.0 TL;DR (plain English)

- **What I'll build:** a new advisory check in the plan verifier that catches a specific silent failure: a plan promises to re-generate too-long model outputs at double length, but the model engine's hard context-length limit makes every one of those re-generations impossible — so the "fix" silently does nothing. The check re-does the plan's arithmetic with the DOUBLED length (the mistake #2221 made was doing it only with the single length), matches the bound to the stage that actually re-generates (so an unrelated stage's numbers can't trigger a false alarm), and recognizes both the long spelling ("re-generate at ≥2×") and the house shorthand ("re-gen at 2×") — plus pin tests and a one-line rule-file update.
- **What I expect:** with the kind gate applied (the check as shipped), the committed-plan scan warns on exactly the 11 plan versions carrying the two real instances of this bug — #2221 v7/v8/v9 (the founding incident) and #2225 v6–v13 (a second, LIVE instance the round-1 review uncovered: an inherited "re-gen at 2×" contract against a 4096 context limit with a 2048 cap leaves zero room) — and stays quiet everywhere else, including the corrected versions of #2221. These counts are a calibration fit — the detection wording was tuned on this same collection of plans — so they certify that the shipped code reproduces the calibrated behavior, not how it will do on future unseen phrasings. And to be plain about scope: this check surfaces the problem at plan time; it does not prevent the class (two of its three recurrences were in code, where no plan check can see).
- **What would change my mind:** if the implemented check starts warning on healthy plans (any warning on a plan whose arithmetic is actually fine, or unexplained growth beyond the 11 verified hits), the detection grammar is too loose to ship as designed and the check gets re-scoped.

## 4. Design

**Why code, not a model call:** this is a deterministic arithmetic gate over plan text inside an existing mechanical verifier; an LLM call would be nondeterministic, slower, and unpinnable. (Data realism / contrastive negatives / on-policy completions / persona vectors: N/A — no training or eval data in this task; the "data" is the committed-plan corpus itself, used read-only for calibration.)

### Method delta vs the copied precedents

Same skeleton as c68 (`kind gate → trigger harvest → escapes → arithmetic → offenders[:3] WARN detail`), with six deltas: (1) the compared quantity is a **derived product** (`mult×cap`) rather than a harvested literal — the whole point, since the stated first-pass triple reads correct on the founding incident; (2) **two WARN arms** (violated arithmetic / unstated bound) in ONE check — unlike the c65/c66 two-cid split, both arms share the trigger, the harvest, the remedies, and the escapes, so a second cid would double the registry/docstring/SKILL.md/test surface with no independent SKIP semantics (the c68 one-check-two-escapes precedent); (3) cap evidence is deliberately **constant-form or product-form only** (measured: prose "CAP (4096)" harvesting double-counts the already-doubled regen cap — §11 entry 9); (4) effective pin = **MAX harvested** (measured: corrected plans quote the superseded pin beside the raise — §11 entry 8); (5) **bounds are attributed PER ARMED LINE** — window-local max wins, the plan-wide max is only the no-local-bound fallback (r1 Must-Fix 1: the plan-wide bound join manufactures false positives on healthy multi-stage plans; §11 entry 10); (6) arm alternative 3 recognizes the **house shorthand** `re-gen … at N×` alongside `re-generate … at N×` (r1 Must-Fix 2: the shorthand is the inherited contract's common written form; §11 entry 17).

def check_regen_headroom(plan: str, kind: str) -> CheckResult:
    cid, name = "c69_regen_headroom", "armed re-gen 2×-cap headroom vs max_model_len pin"
    if kind not in ("experiment", "analysis"):
        return _skip(cid, name, f"kind={kind} — armed for experiment/analysis only "
                     "(c67/c68 precedent): infra workflow-fix plans, this check's own "
                     "plan included, quote the arming vocabulary; the founding incident "
                     "(#2221 v9) is kind: experiment")
    lines = plan.splitlines()
    mask = _fence_mask(lines)
    arm_idx = [i for i, (line, fenced) in enumerate(zip(lines, mask, strict=True))
               if not fenced and _C69_ARM_RE.search(line)]
    if not arm_idx:
        return _skip(cid, name, "no armed re-gen trigger detected")
    if _standalone_na_declared(plan, r"no armed re-?gen(?:eration)? trigger\b"):
        return _pass(cid, name, "explicit N/A declared (no armed re-gen trigger)")
    if _standalone_na_declared(
        plan, r"harvested max_model_len pin is unrelated to the armed re-?gen stage"
    ):
        return _pass(cid, name, "explicit N/A declared (cross-quantity: the harvested "
                     "max_model_len pin belongs to a different engine/stage)")
    pins = [_c69_int(m.group(1)) for m in _C69_PIN_RE.finditer(plan)
            if 256 <= _c69_int(m.group(1)) <= 10_000_000]          # RAW scan, fences included
    if not pins:
        return _skip(cid, name, "armed re-gen trigger detected but no max_model_len / "
                     "VLLM_MAX_MODEL_LEN numeric pin harvested — the #505/#601 headroom "
                     "arithmetic needs a pin")
    pin = max(pins)

    def _bounds_between(lo: int, hi: int) -> list[int]:
        """Fence-masked stated prompt-token bounds on raw lines [lo, hi)."""
        return [_c69_int(m.group(1))
                for j in range(max(0, lo), min(len(lines), hi)) if not mask[j]
                for rx in _C69_BOUND_RES for m in rx.finditer(lines[j])
                if 1 <= _c69_int(m.group(1)) <= 1_000_000]

    plan_bounds = _bounds_between(0, len(lines))
    evaluated = []
    for i in arm_idx:
        line = lines[i]
        mults = [float(m.group(1)) for m in _C69_MULT_RE.finditer(line)
                 if 1.0 <= float(m.group(1)) <= 8.0]
        mult = max(mults) if mults else 2.0
        caps = [_c69_int(g) for m in _C69_CAP_LINE_RE.finditer(line)
                for g in m.groups() if g and 16 <= _c69_int(g) <= 100_000]
        if not caps:  # constant-form only in the ±3-raw-line window
            window = lines[max(0, i - _C69_WINDOW_LINES):i] + lines[i + 1:i + 1 + _C69_WINDOW_LINES]
            caps = [_c69_int(m.group(1)) for src in window
                    for m in _C69_CAP_CONST_RE.finditer(src)
                    if 16 <= _c69_int(m.group(1)) <= 100_000]
        if not caps:
            continue
        # Bound attribution is PER ARMED LINE (r1 Must-Fix 1): window-local
        # MAX wins; the plan-wide MAX is only the no-local-bound fallback.
        # Bound-side MAX is aggressive (pro-WARN) — opposite direction from
        # the permissive pin-side MAX — so it never pools across stages.
        wb = _bounds_between(i - _C69_WINDOW_LINES, i + 1 + _C69_WINDOW_LINES)
        bound = max(wb) if wb else (max(plan_bounds) if plan_bounds else None)
        evaluated.append({"line_no": i + 1, "line": line.strip(), "mult": mult,
                          "cap": max(caps), "need": int(mult * max(caps)),
                          "bound": bound,
                          "scope": "window-local" if wb else "plan-wide"})
    if not evaluated:
        return _skip(cid, name, f"{len(arm_idx)} armed re-gen line(s) but no generation "
                     "cap resolvable (constant-form [A-Z_]*MAX_NEW_TOKENS or product-form "
                     "N×<cap> on the arming line; constant-form within ±3 raw lines) — "
                     "arithmetic not adjudicable")
    if not plan_bounds:
        worst = max(evaluated, key=lambda e: e["need"])
        zero = (" — the regen length alone meets/exceeds the pin (zero prompt headroom "
                "before any prompt tokens)") if worst["need"] >= pin else ""
        return _warn(cid, name, f"armed re-gen trigger (line {worst['line_no']}) + "
                     f"max_model_len pin {pin} but NO stated prompt-token bound anywhere "
                     f"— the binding regen arithmetic ({worst['mult']:g}×{worst['cap']} = "
                     f"{worst['need']} + prompt) is unverifiable{zero} (#2221 v9 shape). "
                     "State the panel's prompt-token bound (e.g. 'length-validated at "
                     "load to ≤ N prompt tokens'), size the regen engine so "
                     "max_model_len − 2×cap ≥ the bound, or declare 'N/A — no armed "
                     "re-gen trigger' on its own line, unwrapped (no backticks/quotes)")
    offenders = [e for e in evaluated if e["need"] + e["bound"] >= pin]
    if not offenders:
        best = max(evaluated, key=lambda e: e["need"] + e["bound"])
        return _pass(cid, name, f"regen headroom satisfied: worst armed line "
                     f"{best['line_no']} needs {best['mult']:g}×{best['cap']} + "
                     f"{best['bound']} ({best['scope']} bound) = "
                     f"{best['need'] + best['bound']} < max_model_len {pin}")
    parts = [f"line {e['line_no']} \"{e['line'][:70]}\" arms regen at "
             f"{e['mult']:g}×{e['cap']} = {e['need']}; + prompt bound {e['bound']} "
             f"({e['scope']}) = {e['need'] + e['bound']} ≥ max_model_len {pin}"
             for e in offenders[:3]]
    shown = "; ".join(parts) + ("; …" if len(offenders) > 3 else "")
    return _warn(cid, name, f"{shown} — zero/negative prompt headroom on the ARMED "
                 "re-gen leg: every capped row skips as regen_overlong_skipped and the "
                 "cap-hit deviation is silently re-committed while the plan claims to "
                 "fix it (#2221 v9; the plan-prose face of the #505/#601 family, "
                 "gotchas.md cap-raise entry). First-pass arithmetic (cap + bound ≤ pin) "
                 "is NOT the binding check — the regen leg re-enters prompt + a ≥2×-cap "
                 "response. Remedies: run the regen leg on an engine sized max_model_len "
                 "≥ 2×cap + prompt bound (the #2221 v10 fix: a dedicated 8192 engine), "
                 "lower the regen multiplier/cap, or — when the harvested pin belongs to "
                 "a different engine than the regen stage — declare 'N/A — harvested "
                 "max_model_len pin is unrelated to the armed re-gen stage' on its own "
                 "line, unwrapped (no backticks/quotes); a plan with no armed trigger at "
                 "all instead declares 'N/A — no armed re-gen trigger' on its own line, "
                 "unwrapped")
