## 1. Problem

The `/issue` Step 5a **sibling-issue per-FILE freshness arm** (#1972) refreshes
never-branch-edited sibling-issue files from fetched `origin/main` so a Step 9c
gate does not run a fork-era sibling artifact. Its enumeration pathspec is
`.py`-only (`.claude/skills/issue/SKILL.md:2641`):

```
done < <(git -C "$WT" -c core.quotePath=false diff --name-only origin/main -- ':(glob)scripts/issue[0-9]*_*.py' ':(glob)tests/test_issue[0-9]*_*.py')
```

Sibling **tests** routinely hard-read sibling **shell dispatchers**
(`scripts/issue<M>_*.sh`). Because `.sh` is outside the pathspec, the arm syncs
a main-fresh `tests/test_issue<M>_*.py` while leaving the `.sh` it invokes at
fork-era content — or absent entirely — which reds the Step 9c gate as NEW.
This is the same half-sync class the arm exists to prevent (#1824/#1860), just
via a different file extension.

**Two realized firings, both 2026-08-05:**

- **#1988** (fp `9e04e93b0ae6`) — `tests/test_issue2054_*.py` synced without
  `scripts/issue2054_dispatch.sh`; a ~30-min 114-file gate burned.
- **#2004** (fp `d8f423e4d696`) — gate round 1 blocked on 2 NEW nodes:
  `tests/test_issue2054_phase_d.py::test_dispatch_plan_pins_form_chat_for_phase_d`
  (rc 127 — the missing `.sh`) and
  `tests/test_issue2054_unit_e.py::test_null_draws_default_is_plan_pinned_100`
  (`FileNotFoundError`); ~45-min re-run.

Total realized cost ≈ 75 min of gate wall across two sessions, plus manual
provenance triage.

`.py` scripts and tests, so a synced sibling test never arrives without the

carve-out, branch-side-edit exclusion, per-file dirt skip, origin/main-existence
guard, pair-atomic movement, and the #2208 import-satisfiability probe — is
preserved byte-for-byte.

## 4. The body's open question, answered empirically

The task body asks the planner to determine whether other non-`.py` sibling
classes (e.g. `configs/issue<M>_*.yaml`) belong in the same pass. Measured
against the live repo:

- Sibling `tests/test_issue*.py` hard-read **13 distinct**
  `scripts/issue<M>_*.sh` files (e.g. `issue588_smoke.sh`,
  `issue1345_judge_legs_run.sh`, the `issue2054` dispatcher class).
- **Zero** non-`.sh` sibling classes are hard-read: no `configs/issue<M>_*`,
  no sibling `.json` / `.yaml` / `.toml` / `.txt` / `.md`.

**Decision: scope stays `.sh`-only.** Adding classes with no demonstrated
read-path would widen the arm's blast radius (more candidate files per round,
each carrying a small revert/half-sync risk) for zero realized benefit — the
opposite of the arm's per-file-grain design intent.

## 5. Glob-shape verification

`scripts/` currently holds **127** `issue<N>*.sh` files. Every one carries an
underscore after the numeric segment, so the same-shape glob
`':(glob)scripts/issue[0-9]*_*.sh'` matches **127/127** — no shape deviation
from the two existing globs is needed, and none is introduced.

## 6. Composition with the landed #2208 probe

Verified by inspection of the live arm (SKILL.md:2625-2692) — the widening needs
**no** additional changes:

- **Own-issue carve-out** (`case "$f" in scripts/issue<N>_*|tests/test_issue<N>_*)`)
  is extension-agnostic — it already excludes this session's own `.sh`.
- **Import-satisfiability probe** (#2208) matches `tests/test_issue*_*.py` only,
  so a `.sh` correctly receives no pytest collection probe (a shell script is
  never a collected test). The pair is still covered: the covering test's probe
  is what gates the pair.
- **Pair-atomic revert** keys on `basename "$f" | grep -oE '[0-9]+' | head -1`,
  which resolves `issue2054_dispatch.sh` → `2054`. A `.sh` whose covering test
  fails collection is therefore reverted with its pair, and `git rm -f` handles
  the main-NEW-`.sh` case exactly as it does a main-NEW `.py`.
- **Sync commit** stages `"${SIBLING_SYNCED[@]}"` by explicit pathspec —
  extension-blind.

## 7. Risk + blast radius

- **Blast radius:** the arm is fail-safe by construction — its declared failure
  direction is status-quo staleness (the pre-#1972 world), never an unreadable
  gate red. A `.sh` that is dirty, branch-edited, own-issue, or absent on
  origin/main is skipped exactly as a `.py` is.
- **Cost scaling:** the per-file loop iterates over files that DIFFER from
  origin/main, not over all 127 — so the added work is O(differing sibling
  `.sh`), typically 0-2 files per round.
- **Rollback:** single-commit revert. Two textual edits plus one test assert.
- **Failure mode if wrong:** a sibling `.sh` gets refreshed when it should not
  have been. Guarded three ways (branch-side-edit exclusion, dirt skip,
  own-issue carve-out) and detectable in the `[step5a] sibling-file sync: N
  file(s)` echo.
