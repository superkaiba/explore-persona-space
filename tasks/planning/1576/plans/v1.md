Acceptance criteria:

   anti-pattern, #1482, and the fix (committed branch script invoked by path), plus
   `extra.workload_cmd_inline_interpreter` on the `epm:backend-selected` marker. Launch proceeds.
2. A committed-script-by-path body with the trailing sanctioned sentinel append does NOT flag.
3. An inline body that ALSO ends with the sentinel append STILL flags (strip-then-scan).
4. Empty cmd / `--hydra` launches and `EPM_SKIP_WORKLOAD_CMD_ENV_LINT=1` are no-ops for this arm.
5. Existing behavior for non-inline cmds is byte-unchanged: full
   `tests/test_workload_cmd_env_lint.py` + `tests/test_issue_dispatch.py` suites stay green.

## Method delta (vs the existing #1329 family)

Same architecture, three deltas: (a) the detected risk is a command SHAPE (inline interpreter
body), not a lane-env var reference, so there is no per-lane reachability logic and no `certain`
refusal arm; (b) WARN-only — no refusal path exists at all, and `--strict-workload-cmd-env` does
not upgrade it (§11 D1); (c) the scan runs on the RAW cmd, NOT the `_SINGLE_QUOTED_SEGMENT_RE`-
stripped text the lane-env lint uses (issue_dispatch.py:386, :480) — an inline `-c` body is
usually single-quoted, so the quote strip would erase exactly the evidence this arm needs.

### 4.1 Detection helper — `src/explore_persona_space/backends/issue_dispatch.py` (~after L500,
below `lint_workload_cmd_lane_env`, above `build_run_spec` at L503)

```python
#: Sanctioned trailing sentinel append (experimenter.md § item 11, ~L723-732):
#: `<workload-cmd> && [uv run ]python -c "...write_completion_sentinel..."`. Leftmost
#: `&& [uv run ]python -c` whose remainder mentions write_completion_sentinel; anchored
#: to end-of-string via DOTALL .+$ so only a TRAILING append (plus anything after the
#: first such join) is stripped.
_SENTINEL_APPEND_RE = re.compile(
    r"&&\s*(?:uv\s+run\s+)?python3?\s+-c\s+(?P<rest>.+)$", re.DOTALL
)
#: Inline interpreter as the PRIMARY command: optional VAR=val env prefixes, then
#: `[uv run ]python[3] -c`.
_INLINE_C_BODY_RE = re.compile(
    r"^\s*(?:[A-Za-z_][A-Za-z0-9_]*=\S*\s+)*(?:uv\s+run\s+)?python3?\s+-c(?=\s)"
)
#: Stdin-heredoc python anywhere: `python - <<EOF`, `python - <<'EOF'`, `python <<EOF`,
#: with/without `uv run`, optional `<<-`.
_STDIN_HEREDOC_RE = re.compile(r"(?:uv\s+run\s+)?python3?\s+-?\s*<<-?\s*['\"]?\w+")


@dataclass(frozen=True)
class WorkloadCmdInlineLint:
    flagged: bool
    shape: str | None            # "inline_c" | "stdin_heredoc" | None
    sentinel_append_stripped: bool


def strip_sentinel_append(workload_cmd: str) -> tuple[str, bool]:
    """Strip the experimenter.md-sanctioned trailing write_completion_sentinel append."""
    m = _SENTINEL_APPEND_RE.search(workload_cmd)
    if m is not None and "write_completion_sentinel" in m.group("rest"):
        return workload_cmd[: m.start()], True
    return workload_cmd, False


def lint_workload_cmd_inline_interpreter(workload_cmd: str) -> WorkloadCmdInlineLint:
    """WARN-class #1576 detection: inline interpreter one-liner as the workload BODY.

    Scans the RAW command (never the single-quote-stripped text — the -c body is
    usually single-quoted). Deliberate v1 FALSE NEGATIVES (named, mirroring the
    _bare_reference_re docstring discipline): a mid-chain non-sentinel `&& python -c`
    segment after a committed-script body; `bash -c '...'` wrapping; `sh -c`;
    `python -m module` bodies. Widen if one bites.
    """
    body = (workload_cmd or "").strip()
    if not body:
        return WorkloadCmdInlineLint(flagged=False, shape=None, sentinel_append_stripped=False)
    body, stripped = strip_sentinel_append(body)
    if _INLINE_C_BODY_RE.search(body):
        return WorkloadCmdInlineLint(True, "inline_c", stripped)
    if _STDIN_HEREDOC_RE.search(body):
        return WorkloadCmdInlineLint(True, "stdin_heredoc", stripped)
    return WorkloadCmdInlineLint(False, None, stripped)
```

Strip-then-scan semantics: in `python -c "work" && uv run python -c "...sentinel..."` the
leftmost `&&` match strips the tail, the remaining body `python -c "work"` still flags
(acceptance 3). In `bash scripts/x.sh && uv run python -c "...sentinel..."` the remaining body
is a committed script → no flag (acceptance 2).

### 4.2 CLI wiring — `scripts/dispatch_issue.py`

```python
def _warn_workload_cmd_inline_interpreter_and_flag_marker(
    spec: Any, marker_poster: Callable[..., None]
) -> Callable[..., None]:
    """WARN-only #1576 arm of the #1329 workload-cmd lint family. Never blocks.

    Shares the family kill switch EPM_SKIP_WORKLOAD_CMD_ENV_LINT=1. No strict
    upgrade: --strict-workload-cmd-env is lane-env-scoped by contract (§11 D1).
    """
    from explore_persona_space.backends.issue_dispatch import (
        lint_workload_cmd_inline_interpreter,
    )

    if not spec.workload_cmd or os.environ.get("EPM_SKIP_WORKLOAD_CMD_ENV_LINT") == "1":
        return marker_poster
    lint = lint_workload_cmd_inline_interpreter(spec.workload_cmd)
    if not lint.flagged:
        return marker_poster
    logging.getLogger("dispatch_issue").warning(
        "--workload-cmd body is an inline interpreter one-liner (%s). Ad-hoc probe "
        "workloads are committed scripts invoked by path (SKILL.md § Backend dispatch; "
        "incident #1482: a placeholder-broken inline staging one-liner SyntaxError'd "
        "post-b0 and spuriously failed over to RunPod) — inline bodies are un-lintable, "
        "un-smokeable, and quoting-fragile. Rewrite as a committed branch script, push, "
        "re-dispatch by path with --repo-branch. The trailing "
        "write_completion_sentinel append is exempt%s. Launch continues; "
        "epm:backend-selected carries extra.workload_cmd_inline_interpreter. Silence "
        "with EPM_SKIP_WORKLOAD_CMD_ENV_LINT=1.",
        lint.shape,
        " (stripped before this scan)" if lint.sentinel_append_stripped else "",
    )
    return _wrap_marker_poster_with_override_flag(
        marker_poster,
        {"workload_cmd_inline_interpreter": {
            "shape": lint.shape,
            "sentinel_append_stripped": lint.sentinel_append_stripped,
        }},
    )
```

## §11 Decision Rationale

D1 — WARN-only; `--strict-workload-cmd-env` does NOT upgrade this arm.
What: no refusal path at all for the inline arm. Why: the flag's documented contract (L2482-2496
help text) is lane-ENV-scoped ("any bare reference ... to a lane-specific env var"); upgrading a
different risk class under it silently changes existing callers' semantics. The lane-env refusal
is justified by a PROVABLE set-u crash; an inline body is a style/lintability risk that can be
perfectly valid (one incident, emitter confidence LOW). A future strict form would be its own
flag. Source: #1329 flag semantics (dispatch_issue.py:903-926, :2482); task body constraint 1;
#1482 incident class. Alternatives: upgrade under the existing flag (rejected — contract creep);
new `--strict-workload-cmd-inline` flag (rejected for v1 — YAGNI, zero demand).

D2 — Exemption scoping: strip the sanctioned suffix BEFORE scanning (leftmost
`&& [uv run ]python -c` whose remainder mentions `write_completion_sentinel`, DOTALL-anchored to
end of string). Why: match-and-skip on the full string cannot satisfy constraint 2's "inline body
+ sentinel append still flags"; strip-then-scan does, and the token `write_completion_sentinel`
is the load-bearing discriminator (experimenter.md item 11 names it as the ONE sanctioned append).
Tradeoff accepted: a mid-chain non-sentinel `-c` probe between the body and the sentinel append is
also stripped (false negative, named in the docstring — it would not have flagged anyway under D3).
Source: experimenter.md ~L723-747; task constraint 2. Alternatives: exact-string match of the
item-11 exemplar (rejected — whitespace/import-path variants break it).

D3 — Detection-shape set: (a) leading `[VAR=val ]*[uv run ]python[3] -c` (the BODY is the
one-liner), (b) `python[3] [-] <<[-]EOF` stdin heredoc anywhere. Named deliberate v1 false
negatives: mid-chain non-sentinel `&& python -c` segments, `bash -c`/`sh -c` wrapping,
`python -m` bodies, non-python interpreters. Why: the Goal targets the one-liner AS the workload
body; the sanctioned append proves trailing `-c` segments have legitimate uses; a broad matcher
risks warn-spam on committed-script bodies. Mirrors the `_bare_reference_re` named-false-negative
discipline (issue_dispatch.py:402-405). Source: #1482 (the incident shape was an inline staging
one-liner body); task constraint 3; gotchas.md #1310 (heredoc-in-shell sibling). Alternatives:
flag any `-c` anywhere (rejected — false positives on sanctioned appends and committed scripts
with argv containing `-c`).

D4 — Kill-switch coverage: reuse `EPM_SKIP_WORKLOAD_CMD_ENV_LINT=1` for the whole family.
What: the env var short-circuits the inline arm too. Why: one family switch (task constraint 5
recommendation); an operator silencing the lint in an emergency wants the family silent, and a
second env var is discoverability debt. Source: dispatch_issue.py:986; task constraint 5.
Alternatives: dedicated `EPM_SKIP_WORKLOAD_CMD_INLINE_LINT` (rejected — two switches for one
family; can be split later without contract breakage since both are WARN/skip semantics).

D5 — Scan the RAW cmd, not the single-quote-stripped text. Why: `_SINGLE_QUOTED_SEGMENT_RE`
(issue_dispatch.py:386) exists to remove non-expanding literals for the env-var scan; the inline
`-c` body is typically single-quoted, so reusing the strip would blind this arm. Source: read
from code (issue_dispatch.py:378-386, :480). Alternatives: none viable.
