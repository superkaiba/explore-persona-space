## Requirement + acceptance criteria

**Requirement (from the task Goal):** make the watcher pod-safety pass's inferred
follow-up predicate safe on MULTI-ROUND issues — a sibling round's routine status
transition must not flip protection off another round's healthy live pod.

**Root cause (verified against live code at clarify time):**
`scripts/autonomous_session_watch.py::_task_followup_active` (L11385) is
ISSUE-grain: newest follow-up signal (`_POD_FOLLOWUP_SIGNAL_KINDS` =
`epm:run-launched` / `epm:followup-scope` / `epm:free-analysis-followup-run`)
vs newest done-transition (`_DONE_TRANSITION_KINDS` = `epm:promoted` /
`epm:status-changed`). On an issue running concurrent/serial follow-up rounds
(#1768: three inline pods + a session loop), routine sibling transitions post
`epm:status-changed` continually, so any pod whose `epm:run-launched` predates
the latest sibling transition loses inferred protection. The only remaining
shield is the ISSUE-wide `keep-running` tag, which the standing inline-round
guidance says NOT to set (it blocks sibling bare-form teardowns, #1485).
Incident: pod-1768-lt auto-STOPPED at ~05:05Z with 142/216 fit cells done
(launch marker v11 22:34:14Z; a sibling `epm:status-changed` postdated it).

**Acceptance criteria:**

1. **Per-pod named-launch shield.** A RUNNING managed pod whose issue's events
   carry an `epm:run-launched` marker whose NOTE names THAT pod (boundary-safe
   match — `pod-1768` must NOT match inside `pod-1768-lt`) is exempt from the
   pod-safety auto-stop arm while the named marker is younger than a staleness
   ceiling, REGARDLESS of later sibling done-transitions.
2. **Issue-grain fallback unchanged.** When the pod has no named launch marker
   (or the named marker is older than the ceiling), the existing issue-grain
   predicate applies byte-identically. All existing
   `test_task_followup_active_*` / `test_pod_safety_followup_*` tests stay
   green unmodified.
3. **Staleness ceiling bounds billing.** The named shield expires after
   `EPM_POD_NAMED_SHIELD_MAX_AGE_H` hours (default 48); past it the pod falls
   back to the issue-grain predicate (and, failing that, the normal 2-miss
   reversible `pod.py stop`). The #1582 keep-running wedged-owner escalation
   arm remains the billing backstop and is untouched.
4. **Precedence preserved.** `keep_running` (explicit user tag) still beats
   `followup_active` (inferred); `decide_pod_safety`'s signature and case
   table are UNCHANGED (the refinement lives in how the caller computes
   `followup_active`, not in the decision function).
5. **Fail toward KEEP.** Any read/parse failure in the per-pod arm degrades to
   the issue-grain predicate, never to a stop.
6. **Guidance docs updated** (see file list): the multi-round exposure + the
   per-pod named-launch shield are documented at the two sites that prescribe
   the pre-launch signals, making "note names the pod" load-bearing rather
   than stylistic. No tag-by-default guidance (the predicate fix supersedes
   the interim mitigation the candidate sketched).
7. **Fail-loud test coverage:** new unit tests (pure, no subprocess) cover
   acceptance criteria 1–5, including the boundary-match negative case and
   the ceiling-expiry fallback; the Step 9c selector maps
   `scripts/autonomous_session_watch.py` → `tests/test_autonomous_session_watch.py`,
   which runs at the gate.
