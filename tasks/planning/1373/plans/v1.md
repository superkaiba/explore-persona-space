## 4. Design (method delta + concrete diffs)

### 4.1 Footer leg — plural-enumeration regex (`scripts/verify_task_body.py`, after :9475)

Keep `_V4_FOOTER_ROUND_CLAUSE_RE` byte-unchanged (all `(?!s)` behavior preserved). Add:

```python
_V4_FOOTER_ROUND_PLURAL_RE = re.compile(
    r"\b(?P<num>one|two|three|four|five|six|seven|eight|nine|ten|\d{1,2})"
    r"\s+same-issue\s+follow-up\s+rounds\b",
    re.IGNORECASE,
)
_NUMBER_WORDS = {"one": 1, "two": 2, ..., "ten": 10}  # full literal map in code
```

Counting (inside `_count_extra_followup_rounds_v4`): for each plural match, `n = _NUMBER_WORDS.get(num.lower()) or int(num)`, clamped to `min(n, 12)` (sanity bound; corpus max rounds is single-digit). `plural_n = max over matches` (a repeated/updated plural sentence restates the cumulative total; max never double-counts). Then:

```python
footer_n = max(singular_n, plural_n)
```

- **Why max, not sum:** when BOTH forms appear they most plausibly describe the same round set (a summary sentence + per-round clauses); max cannot double-count, and any genuine under-count is backstopped by the events leg's own max-reconcile (the check stays WARN-only/monotone-up, same design philosophy as the existing footer-vs-events max).
- **False-positive avoidance:** the leading number token is REQUIRED immediately before the literal `same-issue follow-up rounds` — generic spec-quoting prose ("follow-up rounds also name each round's `followup_label`") has neither `same-issue` nor a leading number and cannot match; bare `same-issue follow-up rounds` without a number stays excluded exactly as the `(?!s)` lookahead excludes it today. Enumerated items after the colon are NOT parsed (labeled vs unlabeled items are irrelevant — the stated N is authoritative), so `(1)`/`1)`/`1.` formatting variation cannot break counting.

### 4.2 Events leg — new `_followup_events_rounds(issue) -> int` (:9527 region)

Refactor `_followup_run_marker_rounds`'s loop body into a pure helper `_same_issue_run_rounds(events) -> tuple[set[str], int]` (labels, unlabeled) — `_followup_run_marker_rounds(issue)` keeps its exact signature/behavior as a thin wrapper (existing tests at :7734/:7749/:7757 pass untouched). Add:

```python
def _followup_events_rounds(issue: int) -> int:
    # same try/except shape as _followup_run_marker_rounds (FileNotFoundError -> 0,
    # StaleTaskPathError propagates); local task_workflow imports (monkeypatch-compatible)
    labels, unlabeled = _same_issue_run_rounds(events)
    free = _free_analysis_rounds(events, exclude_labels=labels)
    inflight = 1 if _has_inflight_round(events) else 0
    return len(labels) + unlabeled + free + inflight
```

`_free_analysis_rounds(events, exclude_labels)` — count `FREE_ANALYSIS_RUN_KIND` markers where:
- note (stripped) does NOT match `(?i)^aborted\b` — the SKILL.md 9a-ter ABORT record folded no prose;
- note is not byte-identical to an already-counted note (dedupe key = exact full note text: a genuine double-post from a marker retry is byte-identical; `followup_ref` is NOT the dedupe key because its parsed value is first-token-truncated and absent entirely in the #1090/#1073 free-prose shapes — two distinct rounds sharing a first title word must not collide);
- parsed `followup_ref` (via `parse_followup_note_field`) is NOT in `exclude_labels` — the cross-leg guard: a round that closed an armed scope label AND posted a same-issue run marker for it counts once (design decision 3; the CLAUDE.md KILL-MID-LOOP contract makes the marker sets disjoint by construction, this is the defensive belt).

`_has_inflight_round(events) -> bool` — reuse `task_workflow.unrun_followup_labels(events)`: return True iff ANY group has `dispatchable: True` AND `followup_retro_close_evidence(events, group["followup_label"])` is None. Caps at **+1 total** regardless of how many labels are armed (the Goal says "as one round"; a queue of armed-but-undispatched labels is not folded prose). The retro-close exclusion prevents double-count with the free-analysis leg (a ghost label closed by a free-analysis `followup_ref` would otherwise count via BOTH class-2 evidence and the in-flight +1). Undispatchable pseudo-labels (`unlabeled-<ts>`) never count.

`_count_extra_followup_rounds_v4` swaps `_followup_run_marker_rounds(issue)` → `_followup_events_rounds(issue)` (:9559); signature, return shape, and `source` strings unchanged. Docstring updated to name the two footer forms and three events signals.
