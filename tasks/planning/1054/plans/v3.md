## 3. Design

### 3.1 `scripts/new_worktree.sh` — edit 1: branch-name inference (insert after line 40, end of the arg-parse `while` loop)

```bash
# --issue omitted: infer it from the canonical branch name — `issue-<N>` (the
# /issue Step 4a naming) or `issue-<N>-<suffix>` (same-issue follow-up naming).
# Explicit --issue always wins (it was consumed above and ISSUE is non-empty).
# Conservative: anything not purely numeric between `issue-` and the first `-`
# is NOT inferred (issue-12abc, issue-x → no cones, today's behavior). The
# worktree PATH is never consulted — the branch is the authoritative name.
# (#906: flagless creation left eval_results/issue_906 out-of-cone; #1054.)
if [ -z "$ISSUE" ]; then
  case "$BRANCH" in
    issue-[0-9]*)
      _stem=${BRANCH#issue-}      # "906" or "906-followup-x" or "9a6"
      _num=${_stem%%-*}           # chars before the first hyphen
      case "$_num" in
        *[!0-9]*|'') : ;;         # not purely numeric → no inference
        *)
          ISSUE=$_num
          echo "new_worktree: inferred --issue $ISSUE from branch '$BRANCH'" >&2
          ;;
      esac
      ;;
  esac
fi
```

Notes:
- Same `case`-glob idiom the script already uses for the numeric `--issue` guard (lines 33-35) — no regex engine, no new bashism.
- The inference notice goes to **stderr**: it is a diagnostic about implicit flag derivation, and it keeps stdout (which tests and humans grep for `reusing as-is` / `repairing` / `created`) stable.
- No normalization of leading zeros (`issue-007` → cone `issue_007`): parity with the existing explicit-flag path, which also accepts `007` unnormalized. Branch names with leading zeros do not occur (task ids are plain ints); see Risks.
- Downstream effects of a non-empty `ISSUE` are exactly the two existing consumers: `_sparse_setup`'s `CONES` (line 229) and `_assign_project_quota` (line 306) — both designed for it.

### 3.2 `scripts/new_worktree.sh` — edit 2: reuse-path cone repair (new function after `_is_populated`, ~line 260; call inserted in the reuse branch, lines 262-267)

```bash
# Reuse-path own-issue cone repair (#906/#1054): a worktree created flagless
# BEFORE inference existed (or whose cones were dropped) stays broken for life
# — the reuse branch exits 0 before _sparse_setup ever runs again. Idempotently
# ensure the own-issue cones on every reuse. Contract: the reuse path stays
# exit-0 (it fires on every /issue resume), so a failed add WARNS — it never
# fails the script; the downstream `git add eval_results/...` failure is loud
# on its own, so nothing is hidden, and the WARN names the manual fix.
_ensure_issue_cones() {
  [ -z "$ISSUE" ] && return 0
  # FULL (non-sparse) worktrees are untouched: cone-mode worktree config is
  # unset there (and `git config --worktree` may error without the
  # worktreeConfig extension — hence 2>/dev/null || true).
  [ "$(git -C "$WT" config --worktree core.sparseCheckoutCone 2>/dev/null || true)" = true ] \
    || return 0
  git -C "$WT" sparse-checkout add \
      "eval_results/issue_${ISSUE}" "ood_eval_results/issue_${ISSUE}" \
    || echo "new_worktree: WARN — could not ensure eval_results/issue_${ISSUE} cones on reuse;" \
            "repair manually: git -C \"$WT\" sparse-checkout add eval_results/issue_${ISSUE} ood_eval_results/issue_${ISSUE}" >&2
}
```

Reuse branch becomes:

```bash
if _is_populated; then
  echo "new_worktree: $WT already exists — reusing as-is"
  _ensure_issue_cones
  ln -sf "$REPO_ROOT/.env" "$WT/.env"
  exit 0
fi
```

Notes:
- `set -e` safety: the `|| echo … >&2` arm makes a failed `add` non-fatal by construction; no ERR trap is armed on this path (the trap is set only inside the fresh-creation branch, line 289), so nothing else fires.
- `git sparse-checkout add` in cone mode is idempotent, accepts not-yet-existing directories (the creation path already sets cones for dirs that don't exist yet), and only ADDS/materializes paths — it never removes concurrently-edited files.
- The "registered but unpopulated" repair branch (line 272) needs no change: it calls `_sparse_setup`, which now sees the inferred `ISSUE` via `CONES`.
- Comment touch-up at lines 302-305: the claim "a reused worktree was already tagged at its creation" is no longer universally true (a pre-fix flagless worktree was never quota-tagged); reword to "…was tagged at creation when --issue was known; pre-inference flagless worktrees can be tagged manually post-cutover". Quota assignment itself deliberately does NOT run on the reuse path (see §11 D6).

## 9. §11 Decision Rationale
