## 4. Design

All edits in `.claude/hooks/guard_root_code_commit.sh` (1916 lines) + `tests/test_guard_root_code_commit.py` (1760 lines). Guard content referenced by line-window + abstract class per trigger-dense discipline. Why code, not a model call: this is a deterministic shell predicate in a security-posture hook; a model call is categorically wrong here.

**D1 — state init (guard ~L757–758).** Add three flags to `classify_cmd`'s init: `cd_root_seen=0 commit_before_root_cd=0 cd_root_base=0`.

**D2 — arm the candidate in the cd arm's MF-1 case (guard ~L837–842).** The existing case statement's three keep-arms (exact-root spellings, currently `: ;;`) gain the arming logic; the `*)` arm (`cd_nonroot=1`) is untouched:

```
case "$tgt" in
  "$GUARD_REPO" | "$GUARD_REPO"/ | '~/explore-persona-space' | '~/explore-persona-space/' \
  | '$HOME/explore-persona-space' | '$HOME/explore-persona-space/')
    # #2357: exact-root cd — candidate base-mover. Arm only when the cd
    # provably EXECUTES before later clauses: own separator START/SEQ/NL/AND
    # (an OR-separated cd can be skipped while the commit still runs; a
    # PIPE-source cd runs in a subshell), and next record's separator not
    # BG/PIPE (a trailing & or | backgrounds/subshells the cd — the parent
    # shell's cwd never moves). g3 precedent: resolve_cd_var, ~L530–547.
    case "$sep" in
      START | SEQ | NL | AND)
        nsep=""
        [ $((i + 3)) -lt "$n" ] && nsep=${recs[i + 3]}
        case "$nsep" in BG | PIPE) : ;; *) cd_root_seen=1 ;; esac
        ;;
    esac
    ;;
  *) cd_nonroot=1 ;;
esac
```

Note: `$tgt` is the ORIGINAL raw-lead target with one surrounding quote pair stripped (L801–802) — deliberately NOT the resolve_cd_var-resolved value, mirroring the #1676 must-ask decision at L831–833 (a `$WT`/`$R` variable target to root stays unwidened; pinned by `test_c18f`).

**D3 — ordering flag in the commit-verb branch (guard ~L893–895).**

```
if [ "$verb" = commit ]; then
  root_commit=1
  [ "$cd_root_seen" = 1 ] || commit_before_root_cd=1  # #2357 base-order bit
fi
```

A commit clause scanned before any armed root-cd means the base at that commit is the (unproven) hook cwd — the widening must not engage.

**D4 — compound-context helper (factor g7; guard ~L499–507).** Extract `resolve_cd_var`'s g7 loop into `compound_context_present()` (reads `recs`/`n` via the same bash dynamic-scoping mechanism, returns 0 iff any record opens/continues a compound statement: `if/then/elif/else/fi/while/until/for/do/done/case/esac/function`, `name()` defs, bare `{` openers). `resolve_cd_var` calls it (behavior-identical refactor — the reason token `resolve_reason=compound-context` stays at the resolve_cd_var call site); the new post-loop computation calls it too. Rationale: the masker tracks quote/heredoc state only, not keyword/brace depth, so a compound-BODY `cd <root>` record would read as unconditionally executed while being conditional at runtime — the one arming false-positive class that could combine with a root-SUBDIR hook cwd into a genuine landing bypass. Factoring (not duplicating) follows the #1857 landing_sha precedent.

**D5 — post-loop verdict inside classify_cmd (after the per-record loop, before the function's existing post-scan block ends — `recs` still in scope).**

```
cd_root_base=0
if [ "$cd_root_seen" = 1 ] && [ "$commit_before_root_cd" = 0 ] \
  && ! compound_context_present; then
  cd_root_base=1
fi
```

**D6 — Layer-2 scope gate (guard ~L1740–1745).** The ONLY consumer change:

```
if { [ "$cwd_ok" = 1 ] || [ "$cd_root_base" = 1 ]; } && [ "$cd_nonroot" = 0 ] \
  && [ "$has_dash_a" = 0 ] && [ "$scope_unsafe" = 0 ] && [ "$commit_bare_clause" = 0 ] \
  && [ "$pathspec_opaque" = 0 ] && [ "$commit_has_pathspec" = 1 ] && [ -n "$commit_pathspecs" ]; then

fi
```

Every other poisoning bit is unchanged and still ANDed: any non-root cd (`cd_nonroot`), `-a`, unknown/content-widening flags (`scope_unsafe`), bare clause, opaque pathspec — all still force whole-index.
