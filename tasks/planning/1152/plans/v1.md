### (a) Operator-boundary instance closing — token-walk state machine

Files: `.claude/hooks/guard_harmful_bank_read.sh` only.

**Normalization change** (line ~134): insert newline mapping before padding —

```bash
cmd_norm=$(printf '%s' "$cmd_scan" | tr '\n' ';' | sed 's/[|;&<>()]/ & /g')
```

(`$cmd_scan` is the (c)-scrubbed command, see below; identical to `$cmd` when the scrub gate doesn't match.)

**New function**, placed next to `git_check`/`jq_check` (all state vars already exist; add init `expect_taskfile=0`):

```bash
close_instances() {  # at a command-unit boundary: latch/evaluate, then reset.
  # grep: an instance still unsafe at its unit's end stays unsafe (sticky).
  if [ "$has_grep" = 1 ] && [ "$grep_safe" = 0 ]; then grep_any_unsafe=1; fi
  has_grep=0; grep_safe=0; grep_kind=""
  git_check   # denies here if the closing unit paged a bank via git
  in_git=0; git_sub=""; git_safe=0; git_log_patch=0
  jq_check    # denies here on a non-digest jq filter
  has_jq=0; jq_filter=""; jq_seen=0
  expect_taskfile=0
}
```

**Walk change** — first statement inside `for tok in "$@"; do`:

```bash
  case "$tok" in
    '|' | '&' | ';' | '(' | ')') close_instances; continue ;;
  esac
```

Boundary set rationale: after padding, every occurrence of `|;&()` is a standalone one-char token (verified §2), so `&&`→`& &`, `||`→`| |`, `|&`→`| &` all hit the case; `(`/`)` bound subshells/substitutions (commands inside `$( )` are distinct units); newlines arrive as `;` via `tr`. **`<` and `>` are deliberately NOT boundaries** — redirects don't start a new command, and flags legitimately follow redirects. Deny semantics unchanged: the bank pre-scan, `DENY_VERBS_RE` check, and end-of-walk `grep_any_unsafe`/`git_check`/`jq_check` evaluations all stay whole-command; boundaries only stop *flags* from crossing units.

Known fake-boundary FP shapes (accepted, documented in the hook header comment): the `&` inside `2>&1` and quoted operators inside patterns (`grep -E 'foo|bar' -c <bank>`, multi-line quoted strings). All fail CLOSED (extra deny, never extra allow) — remediation is "put the digest flag before the pattern", which the grep-family deny message already implies; the implementer appends one clause to that message ("place -c/-q/-l before the pattern in compound commands").

### (b) Bare `diff` + `comm`/`join`

1. `DENY_VERBS_RE` gains `comm|join` (plain alternation additions — neither collides with a git subcommand or existing digest op).
2. `diff` cannot join the regex (`git diff --stat` walks a `diff` token). Instead, immediately after the `DENY_VERBS_RE` check inside the walk:

```bash
  if [ "$base" = diff ] && [ "$in_git" = 0 ]; then
    deny "'diff' paging a bank file (diff /dev/null <bank> prints item text; for tracked changes use git diff --stat / --name-only)" "$bank"
  fi
```

Ordering argument: the `git` token in the same unit precedes its `diff` token, so `in_git=1` when `git diff`'s `diff` arrives → skipped, and the existing `git_sub=diff` + `git_check` path handles it (incl. `git -C <dir> diff`). With (a), `in_git` resets at boundaries, so `git log --oneline -- <bank> && diff /dev/null <bank>` denies via the bare-diff branch. Not added: `cmp` (default output is a digest-shaped offset line), `sdiff`/`paste` relatives beyond the verdict's named set (`paste` is already in the regex).

### (c) Quoted-prose exemption for task.py `--note`

**Mechanism chosen: shape-gated scrub (Option B, widened to any `task.py` subcommand), NOT generic `--note`-flag blanking.** Why: generic blanking is launderable — `echo --note "<bankpath>" | xargs -n1 cat` would hide the bank token from the walk while a real `cat <bank>` executes. Gating on the `task.py` invocation shape confines blanking to commands where the quoted string is by construction a data argument to a Python CLI (post-marker/set-status `--note`), which is never executed. `set-status --note` is included because it is the identical flag on the identical CLI with the identical FP shape (e.g. the documented USER-PAUSE note format).

Insert between the inline escape hatch (line ~123) and the fast path (line ~127):

```bash
# (c) task.py --note quoted-prose exemption: notes are DATA args to a Python
# CLI, never executed. Blank single-quoted notes always; blank double-quoted
# notes ONLY when free of $ and backtick (a note carrying $(...) / `...` DOES
# execute — leave it visible to the walk, fail-closed). Line-based sed: a
# multi-line quoted note is left un-blanked (conservative). Gate is two
# in-shell case globs — zero cost on the common path.
cmd_scan="$cmd"
taskpy_shape=0
case "$cmd" in *task.py*) taskpy_shape=1 ;; esac
if [ "$taskpy_shape" = 1 ]; then
  case "$cmd" in
    *--note*)
      cmd_scan=$(printf '%s' "$cmd" | sed -E \
        -e "s/--note(=|[[:space:]]+)'[^']*'/--note ''/g" \
        -e 's/--note(=|[[:space:]]+)"[^"$`]*"/--note ""/g')
      ;;
  esac
fi
```

Then the fast path greps `"$cmd_scan"` and the normalization consumes `"$cmd_scan"` — so a command whose ONLY bank token lived in the note prose exits 0 at the fast path (requirement from the brief), and one whose only *verb* lived there finds no verb token in the walk. Both sed branches verified empirically this session (double-quoted blank; `--note=` form blank; single-quoted blank; `$(…)`/backtick notes NOT blanked; verb+bank outside the note survive).

Fail-closed residue (accepted): notes containing escaped `\"`, `$var` interpolation, backticks, or literal newlines are not blanked → the old FP persists for those shapes only (rare; the deny message's digest guidance still applies, and the sidecar log keeps counting them).

**Rider (discretionary, severable):** `task.py … --file <bank>` / `--body-file <bank>` currently exits 0 while it would embed full bank text into `events.jsonl`/`body.md` (confirmed live). Since `taskpy_shape` is already computed, close it in the walk:

```bash
  if [ "$taskpy_shape" = 1 ]; then
    if [ "$expect_taskfile" = 1 ]; then
      is_bank_path "$tok" && deny "task.py --file/--body-file on a bank file (would embed bank items into task state)" "$tok"
      expect_taskfile=0
    fi
    case "$tok" in
      --file | --body-file) expect_taskfile=1 ;;
      --file=* | --body-file=*)
        is_bank_path "${tok#*=}" && deny "task.py --file/--body-file on a bank file (would embed bank items into task state)" "${tok#*=}" ;;
    esac
  fi
```

Gated on `task.py` shape precisely because a generic `--file <bank>` deny would break legitimate in-process pipeline consumption (`scripts/eval.py --file <bank>` must stay allowed). If any critic objects on scope, this rider drops cleanly without touching (a)–(c).
