# Plan — issue \#671 (`kind: infra`): fix activation-extractor `output_hidden_states` memory accumulation

## TL;DR (plain English)

- **What I'll do:** Our code that reads a handful of internal layers
  from the model currently asks the model to hand back *every* layer and
  then throws most of them away. The discarded copies pile up in GPU
  memory run after run until the machine either crashes or wedges its
  own network. I'll switch the readers to grab only the layers they
  actually use — a pattern we already proved works in one corner of the
  codebase — and route every affected reader through one shared piece of
  code so the fix lands in one place.
- **What I expect:** The numbers each reader produces come out
  byte-for-byte identical to before (I'll lock that down with a test),
  and the memory stops climbing run-to-run. No model is retrained, no
  result changes — this is a plumbing fix that removes a slow leak.
- **What would change my mind:** If the "identical numbers" test refuses
  to pass after a couple of honest attempts, the layer-numbering is more
  subtle than the one known gotcha (layer 0 is the embedding, not a
  transformer block) and I'd stop and re-check the mapping rather than
  paper over it.

## 0. Plan Summary (technical)

**Change:** Replace subset-of-layers reads of
`model(ids, output_hidden_states=True)` with `register_forward_hook` on
only the needed modules + `output_hidden_states=False` + per-iteration
`del captured` / `torch.cuda.empty_cache()`. Extract the already-proven
pattern from `behavior_testbed_545/predictors.py` into a new shared
helper `analysis/extraction.py::extract_layer_activations(...)` and
route in-scope callers through it; inline the pattern where the call
shape (dual base+trained model, same-forward logits read) doesn't fit
the helper. **Hyperparameters:** N/A — no model training, no
hyperparameters in this task type. **Baselines / controls:** the OLD
`output_hidden_states=True` read is the reference; a CPU bit-for-bit
test asserts `torch.equal(old, new)` per layer per input on a
hook-capable stub (this is the only "control" an infra refactor has).
**Loss surface:** N/A — no training. The captured reductions (`h[-1]`,
`h.mean(0)`, `.float().cpu()`) are unchanged, so byte-identity holds.
**Compute:** CPU-only; all tests run on the VM.
`Estimated GPU-hours (total): 0`. **Evaluation:**
`pytest tests/test_issue671_extraction_hooks.py -v` exits 0
(bit-for-bit + AST + memory-non-growth); `ruff check` clean on touched
files. Done = these pass. **Risks (top 2):** (1) the layer-index
off-by-one (`hs[0]=embed_tokens`, `hs[k≥1]=layers[k-1]`) — a naive hook
on `layers[L]` captures `hs[L+1]`, silently the wrong layer; the
bit-for-bit test is the guard. (2) Over-scoping: dual-model /
same-forward-logits sites don't fit a clean activations-only helper, so
they get the pattern inlined rather than forced through the helper.

## 1. Goal

Remove the activation-extractor memory-accumulation bug that is the root
cause of (a) the recurring \#545 GPU OOM (HF resident grew 22→30→38 GiB
across 5 rounds of `gpu_memory_utilization`/batch tuning that never
touched the real cause) and (b) the GCP networking wedge (#667;
deep-research `wf_857f7cfd`: climbing memory pressure drives kernel
page-reclaim stalls that starve `systemd-networkd` DHCP renewal →
`Could not set DHCPv4 address: Connection timed out` → the
hung-but-RUNNING zombie). The fix makes the extraction read only the
layers it uses, so the unused ~21/29 residual-stream tensors per forward
are never materialized and the `expandable_segments:True` allocator has
nothing to retain. **This is the trigger removal; \#669 is the recovery
backstop.** Acceptance is bit-for-bit numerical identity (no result
changes) + no resident growth across iterations, gated by CPU unit
tests.

## 3. Hypothesis (falsifiable acceptance predicates)

- **H1 (numerical identity):** The hook path returns activations
  `torch.equal` to the `output_hidden_states=True` path for every
  requested layer and every input, on a hook-capable stub. *Falsified
  if* any layer/input differs (≥ 1 ULP) → the layer-index mapping or the
  unwrap is wrong.
- **H2 (no regression lock):** After the change, the migrated read paths
  contain `register_forward_hook` and pass `output_hidden_states=False`
  on their primary path; the only surviving `output_hidden_states=True`
  per migrated module is inside the explicitly-labeled fallback branch.
  *Falsified if* the AST test finds a stray `=True` outside the fallback
  or a missing hook.
- **H3 (memory non-growth, CPU proxy):** Across N=20 repeated
  extractions on the stub, `resource.getrusage(RUSAGE_SELF).ru_maxrss`
  (or `tracemalloc` peak) does not grow monotonically (the per-iteration
  `captured`/handle cleanup releases references). *Falsified if* RSS
  climbs every iteration → a reference is being retained. (CPU proxy
  only — the real GPU-segment-retention behavior is not observable
  CPU-side; see §6.)

### 4.2 New shared helper — `src/explore_persona_space/analysis/extraction.py`

Extracted from `behavior_testbed_545/predictors.py:_mean_hidden_states`.
Single canonical convention: **block-index `L`**, where `L` means
"output of transformer block `L`" = `output_hidden_states[L+1]`, and the
sentinel `L = -1` (or a separate `include_embed` flag) means the
embedding output = `hidden_states[0]` = `embed_tokens`. This matches the
dominant in-repo convention (probes.py, issue667, issue444 all use
`hs[L+1]`). Sites with the OTHER convention (i488's `hs[L]`) translate
at the call site.

    # src/explore_persona_space/analysis/extraction.py
    """Memory-safe subset-of-layers activation extraction via forward hooks.

    Replaces ``model(ids, output_hidden_states=True)`` subset reads that
    materialize ALL L+1 residual-stream tensors per forward (the #545/#667
    accumulation bug). Extracts ONLY the requested layers via
    ``register_forward_hook`` + ``output_hidden_states=False``; the unused
    ~21/29 layers are freed as the forward proceeds.

    Convention: ``layers`` are BLOCK indices. Block L's output ==
    ``output_hidden_states[L+1]`` (hs[0] is the embedding). Pass the embedding
    output by including the sentinel ``EMBED_LAYER`` (-1) in ``layers``, which
    maps to hs[0] / ``model.model.embed_tokens``.
    """
    from __future__ import annotations
    import torch

    EMBED_LAYER = -1  # request the embedding output (hs[0]); maps to embed_tokens

    def _unwrap(output):
        # Block output is a tuple (hidden, ...) on some HF versions, a bare
        # tensor on transformers 4.57.x. Mirror representation_shift.py:76.
        return output[0] if isinstance(output, tuple) else output

    @torch.no_grad()
    def extract_layer_activations(
        model,
        input_ids: torch.Tensor,          # (1, T) or (B, T) on model's device
        layers,                            # iterable of block indices (EMBED_LAYER ok)
        *,
        attention_mask: torch.Tensor | None = None,
        return_logits: bool = False,       # for dual-purpose forwards (issue_650)
        detach_to_cpu: bool = False,       # callers that immediately .cpu() set True
    ):
        """Return ``{layer: hidden_state_tensor}`` for the requested block indices.

        The returned tensor for layer L is the SAME object the old
        ``output_hidden_states[L+1]`` read produced (``hs[0]`` for EMBED_LAYER),
        shape ``(B, T, H)``. Byte-identical to the full-tuple read; the only
        difference is the unused layers are never materialized.

        Off-by-one (CRITICAL): a naive hook on ``model.model.layers[L]`` fires
        on hs[L+1], i.e. block L's OUTPUT — which IS what we want. So block
        index L -> ``model.model.layers[L]``; EMBED_LAYER -> ``embed_tokens``.
        (Contrast: the *index* convention is L -> hs[L+1]; the *module* hook is
        layers[L]. Both point at the same tensor — that is the whole subtlety.)
        """
        blocks = getattr(getattr(model, "model", None), "layers", None)
        embed = getattr(getattr(model, "model", None), "embed_tokens", None)
        layers = list(layers)

        def _reduce(hs):
            return hs.detach().float().cpu() if detach_to_cpu else hs.detach()

        # ---- Fallback for non-standard models / CPU stubs (the labeled =True) --
        if blocks is None:
            out = model(
                input_ids=input_ids, attention_mask=attention_mask,
                output_hidden_states=True,
            )
            hs = out.hidden_states  # tuple(L+1)
            captured = {}
            for L in layers:
                idx = 0 if L == EMBED_LAYER else L + 1
                captured[L] = _reduce(hs[idx])
            if return_logits:
                return captured, out.logits
            return captured

        # ---- Primary hook path (standard Qwen/Llama decoder) -------------------
        captured: dict[int, torch.Tensor] = {}
        handles = []

        def _make_hook(L: int):
            def _hook(_module, _inp, output):
                captured[L] = _reduce(_unwrap(output))
            return _hook

        for L in layers:
            if L == EMBED_LAYER:
                if embed is None:
                    continue
                handles.append(embed.register_forward_hook(_make_hook(L)))
            else:
                handles.append(blocks[L].register_forward_hook(_make_hook(L)))
        try:
            out = model(
                input_ids=input_ids, attention_mask=attention_mask,
                output_hidden_states=False,   # <-- the fix: do NOT materialize all
            )
        finally:
            for h in handles:
                h.remove()
        if return_logits:
            return captured, out.logits
        return captured

**Module-hook vs index subtlety (the off-by-one, stated precisely so the
implementer cannot get it backwards):** The block list module
`model.model.layers[L]` produces block-L's *output*, which the full
tuple stores at `hidden_states[L+1]`. So a hook on `layers[L]` captures
`hs[L+1]` — which is exactly the tensor the existing `hs[L+1]` reads
want. **No subtraction at the module level.** The only special case is
the embedding (`hs[0]`), which is `model.model.embed_tokens`, reached by
the `EMBED_LAYER` sentinel. The "naive hook on `layers[layer]` captures
`hs[layer+1]`, silently the WRONG layer" warning in the agent memory
applies when a caller's `layer` variable already means `hs[layer]`
(i488's convention) — that caller must pass `layer-1` to the helper. The
bit-for-bit test pins both conventions.
