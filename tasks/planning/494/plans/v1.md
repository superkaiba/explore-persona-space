## 0.0 TL;DR (plain English)

- **What I'll run:** No new training. I take fact-teaching adapters that already exist from earlier experiments and ask, for each pair of (the persona that taught the fact, a persona that did not), how similar those two personas look to the base model BEFORE training — using a couple of standard "how close are these two voices?" measures — and then I check whether that distance lines up with how much the taught fact actually leaks to the bystander persona after training.
- **What I expect:** Mostly a null on the simple "closer personas leak more" story, plus the surprising sign I already saw inline on the most recent rig: on the rig where I deliberately used a content-unrelated teacher, the persona that leaks MOST is the one that looks FARTHEST from the teacher (because it has its own base-model interest in the topic). So distance to the teacher predicts backwards, and what predicts forwards is the bystander's own base-model prior on the fact. The re-analysis on a second, much older rig (#192) should either show the same wrong-sign pattern (strengthens the story) or the opposite (then the sign depends on something specific to one of the rigs and I need to say which).
- **What would change my mind:** A clean POSITIVE Spearman on the #192 rig where distance-to-teacher predicts the fact leak in the natural direction would be a real surprise — it would suggest the #444 inversion is content-mismatch-specific. A flat null on both rigs (cosine ρ in `[-0.15, +0.15]`, p ≫ 0.05) is the most likely outcome and would say "this DV is too sparse / the rigs are too small / the predictor is the wrong shape" and would push toward #500 (already queued downstream) rather than toward a positive story.

### Persona-distance-metrics canonical operationalizations (`.claude/rules/persona-distance-metrics.md`)

Quoting verbatim from the rule (L18-L52, the canonical block #494 must follow):

> **KL / JS divergence — sequence-level over the ENTIRE response, Rao-Blackwellized.** For each probe Q (Betley `preregistered_evals.yaml` paraphrases, disjoint from the eval set; via `issue404_common.fetch_preregistered_probes`), SAMPLE R≈8 responses (temp=1, ≤256 tok) from the `S_narrow`-prompted and `S_broad`-prompted base model. Estimate divergence with the Rao-Blackwellized sequence-level estimator (Amini, Vieira, Cotterell 2025, arXiv 2504.10637): teacher-force each sampled response through BOTH conditioned models and, at EVERY response token position, compute the EXACT full-vocabulary divergence between the two next-token distributions, then average over positions (length-normalized, per-token) and over samples/probes. Sample sequences from the FIRST argument of each KL. … Polarity-align to a similarity (higher = closer): `M_js = 1 − JS`.
> **DEPRECATED, do not use:** #404's symmetric-KL on Claude-judge-score distributions; #458's single-next-token JS (`issue458_predictor_jsdiv.py` v1 — dominated by the first response token / formatting). Both are first-token / coarse proxies, not the full-response sequence-level divergence defined here.
> **Cosine similarity — persona-vectors recipe, difference-of-means.** Per Chen, Arditi, Sleight, Evans, Lindsey 2025, arXiv 2507.21509. Mean residual-stream activation at one of two extraction points, contrasted between `S_narrow` and `S_broad`: (a) last prompt token (the legacy #404/#458 recipe), or (b) mean over each model's OWN generated response tokens (the persona-vectors recipe). Cosine between the two persona activation vectors, per probe, mean across probes. **Sweep layers {7, 14, 21, 27}**, report per-layer + best (layer 21 = legacy default).

The probe set used for the on-topic predictor is NOT Betley's preregistered set — for fact leakage the "probe set" is the rig's own A-family / freeform fact probes (the content-relevant prompt distribution). The Betley set is the OFF-topic null reference, run alongside as a sanity check.

(Author note: the rule file at `.claude/rules/persona-distance-metrics.md` carries an incorrect "Zhang/Amini/Vieira/Cotterell 2025" attribution for arXiv 2504.10637; the actual paper has 3 authors — Amini, Vieira, Cotterell. The plan uses the correct attribution throughout; a workflow-fix-candidate against the rule file is emitted at the end of this return text.)

## 3. Hypothesis

Two-part, falsifiable:

**H1 (the issue body's framing): closer personas leak more.** Pooled Spearman ρ of cosine-on-topic-L21 vs leak rate, across (teach × bystander × recipe × substrate) cells, is positive at p<0.05.

**H2 (the open-questions trailer's wrong-sign story): teacher-referenced distance predicts backwards on facts; the bystander prior predicts forwards.** Pooled Spearman ρ(cosine-on-topic-L21, leak) ≤ −0.30 with 95% bootstrap CI excluding 0, AND pooled Spearman ρ(bystander-logprob, leak) ≥ +0.20 with CI excluding 0. The trailer says this should hold ON #444 AND IS UNTESTED ON #192; the #494 contribution is the #192 test plus the pooled-across-substrates test.

**H0 (the most likely outcome): null.** Pooled Spearman ρ for cosine OR JS is in `[-0.20, +0.20]` with p > 0.10 — the pooled n (≤ 26) is too small to call either way given the substrate heterogeneity. This outcome is itself informative; it routes the question to #500 (already running downstream) where the source-content-relatedness variable is the manipulated IV.

**Falsification rules:**
- If H1 fires (ρ ≥ +0.45 on cosine, CI excluding 0) on BOTH #192 and #444 separately, the open-questions trailer's "wrong sign" claim is overturned. This would be a high-impact correction; treat with extra scrutiny (re-verify the canonical recipe against the inline-analysis recipe; check for sign-flip bugs in any persona-pair indexing).
- If H2 fires on #192 AND replicates the #444 numbers within ±0.05, the reference-frame claim is supported across two distinct rigs (different fact, different teacher, different bystander panel, different training regime). This *strengthens* but does not *prove* the candidate unification — only #500's source-content-relatedness manipulation can causally test it.
- If H0 (null on both substrates), the result is "predictor is too noisy at this n," and the clean-result is an explicit null with a numeric upper bound on the effect size. The escalation criterion (§4) names when to recommend path (B); within this task, the verdict is null-with-evidence.

Per-recipe note on #444: the inline analysis already showed the per-recipe Spearman for the bystander-prior varies wildly (`hand-written-contradictory-cn` = 0.58, `hand-written-suppression-cn` = 0.43, `on-policy-suppression-cn` = 0.09). **Probe set: the #192 freeform fact probes, subsetted to n=30.** From `issue192_persona_spread/datasets/fact_probes.json:freeform` — the file has **n=150 freeform entries** (corrected from v1; verified via `huggingface_hub.list_repo_files` + `len(d["freeform"])`). **Why n=30 and not the full 150:**
- The DV resolution is 8 (teach × bystander) cells, NOT 150 — the predictor is averaged per (teach, bystander) pair across probes, so increasing probe count only tightens the per-cell predictor MEAN; it does not add DV variance.
- At n=30 probes/cell the per-cell predictor SE is roughly 30^{-1/2} ≈ 0.18, vs 150^{-1/2} ≈ 0.08 at full — a 2.3× tightening on per-cell variance for a 5× compute increase. The bottleneck is JS Rao-Blackwellized (R=8 × max_tokens=256 × forward-pass): at n=15 this was estimated at 1.5h on the v1; at n=30 it scales linearly to ~3h; at n=150 it would scale to ~15h — exceeds the re-analysis budget and would force a descope of the off-topic null or cosine recipe (b).
- 30 probes is well above the inline-444 cosine-recipe threshold (the inline-444 cosine ran on 60 A-family probes; per-cell predictor SE there is 60^{-1/2} ≈ 0.13, so #192 at n=30 is only ~1.4× noisier per cell than #444 — well within the substrate-heterogeneity stratification budget).
- The subsample is FIXED across all four predictors (cosine_a, cosine_b, JS, prior) so the per-cell rank ordering is comparable across predictors.

If the smoke gate (§13) shows the JS recipe runs faster than estimated (per-probe wall <3 min on a 1×H100), the plan re-scopes to n=60 to match #444 — that decision is made at smoke-time based on observed throughput, not pre-registered here.

**The four predictor measurements per (teach, bystander) cell (n_pairs = 4 bystanders × 2 teach prompts = 8):**

1. Cosine (a) last-input-token, layer sweep {7,14,21,27}, headline L21. Forward-pass `(teach_sysprompt, bystander_sysprompt)` × 30 freeform probes. Cosine per probe, mean across probes.

Mirror `scripts/issue444_bystander_logprob.py:65-105` — vLLM `prompt_logprobs=1`, locate the completion span by char offset, sum ground-truth-token logprobs, divide by completion-token-count.

4. **Partial Spearman.** Compute partial Spearman(distance, leak | bystander_logprob) and partial Spearman(bystander_logprob, leak | distance) — the open-questions trailer's "the prior survives controlling for distance and distance does NOT survive controlling for prior" claim. ### 4.6 "Why code, not a model call?" (CLAUDE.md model-call-vs-code rule)

The DV (the bystander leak rate) was originally produced by a Claude Haiku 4.5 strict-linkage judge — that's where the model call lives in this pipeline. The predictor side (cosine / JS / bystander logprob) is base-model forward-pass machinery: it CANNOT be a single model call because the construct is "the residual stream at L21 under persona X" — a value that lives inside a Qwen forward pass, not in a Claude API call. Code path is the only available option for the predictor; no model-call alternative is on the table. Logged here to satisfy the planner-§4 requirement.

### 4.7 Contrastive negatives clause

`kind: experiment` but **no training** in #494, so the behavior-implantation rule does not bind (contrastive negatives are about training-time row composition, and there is no training-time row composition to design). The adapters being re-analyzed *do* carry contrastive negatives where they exist (#444's 3 recipes ARE contrastive — none, contradictory, suppression-refusal, suppression-on-policy; #192 is positive-only by design and that no-negatives regime is one of the planned axes of comparison). N/A — this experiment is a re-analysis, not a behavior-implantation experiment.

### 4.8 Smoke/sweep architectural parity

There is no sweep dispatcher / no multi-cell parallel launcher. Phase 1 + Phase 2 each run as a single Python script on a single GPU.
