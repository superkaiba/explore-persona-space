# Plan — task #1981: branch-sync already-at-tip short-circuit + recalibrated mutation caps

## 0. TL;DR

Short-circuit `_render_branch_sync_script` to `SYNC-OK` when the pod's local `HEAD == FETCH_HEAD` after fetch AND the current branch matches the target — pure `git rev-parse` ref reads, zero FUSE-heavy mutation ops. Raise the 20 s per-op `timeout -k 10` cap on the divergent-path `git checkout` and `git reset --hard` to 90 s to cover healthy-but-slow-mount latency (pod-1895 measured `git status` 59.5 s), paired with a bump of `SYNC_SSH_TIMEOUT_SECONDS` 240 → 360 to preserve the pre-#1858 "remote timeout fires before local ssh timeout" invariant. Update the corresponding pin tests and add one new short-circuit pin test. VM-only edit; 0 GPU-h.

## 1. Goal

Short-circuit `_render_branch_sync_script` to SYNC-OK when HEAD already equals the fetched tip (ref reads only), and raise the 20 s checkout/reset caps for the genuinely-divergent path.

## 2. Requirement + acceptance criteria

- **REQ 1 (short-circuit path).** A pod whose local `HEAD == FETCH_HEAD` after fetch AND whose current branch matches the target branch MUST short-circuit to `SYNC-OK <sha>` and exit 0 without running `git checkout` or `git reset --hard`.
- **REQ 2 (SYNC-OK stdout contract).** The `SYNC-OK ([0-9a-f]+)` regex consumed by `_attempt_sync` (runpod.py:896) MUST match on BOTH the short-circuit path and the divergent path. The captured group MUST be a 40-hex commit SHA.
- **REQ 3 (divergent-path caps).** On the divergent path (HEAD != FETCH_HEAD or wrong branch), the mutation ops MUST run under a wider `timeout -k 10` cap: 90 s for `git checkout` and 90 s for `git reset --hard`. `SYNC_SSH_TIMEOUT_SECONDS` MUST be raised such that the remote worst case — fetch 120 s + KILL 10 s + checkout 90 s + KILL 10 s + reset 90 s + KILL 10 s = 330 s — stays strictly below it (so the remote per-op `timeout` fires before the local ssh timeout does; the #1858 invariant).
- **REQ 4 (SYNC-MISMATCH verification preserved).** On the divergent path, the existing pod-side `HEAD == FETCH_HEAD` verification (`SYNC-MISMATCH ... exit 3`) MUST be preserved unchanged.
- **REQ 5 (kill-and-reap + retry preserved).** The #1858 `_attempt_sync` → `_render_sync_reap_script` → single-retry protocol MUST work unchanged with the new caps; the reap script is not modified.

## 6. Risks

- **False short-circuit on a dirty tree.** *Mitigated by construction.* The pod's clone is disposable (bootstrap creates it fresh; nothing on the pod deliberately dirties tracked files — the workload reads code, does not edit it). A resumed pod whose branch is elsewhere is caught by the `CUR_BRANCH == expected` check. Adding a `git status --porcelain` dirty-tree guard on the happy path was explicitly rejected in §11 (see rationale).
- **90 s cap is still too tight** on a pathologically slow mount. *Mitigated by the existing #1858 kill-and-reap + retry path*: a first-attempt timeout at 90 s runs the reap and retries once (`_attempt_sync` at runpod.py:884). If both attempts exhaust, the pod is left RUNNING for diagnosis (existing behavior — not made worse). Widening from 20 → 90 can only reduce timeout deaths on healthy-but-slow mounts.
- **`SYNC_SSH_TIMEOUT_SECONDS` bump might delay a genuine ssh-hung recovery** by ~120 s (240 → 360). Bounded and only affects the divergent-path relaunch (rare). The modal short-circuit path stays under the same 240 s effective envelope: fetch worst 120 s + three rev-parse calls (~1 s each) + ssh overhead ~10 s = well below 240 s, let alone 360 s.
- **Rendered-script line-count drift breaking implicit assumptions.** No tests count lines (grepped); all sibling tests assert on substring presence, so line-count invariance is not a contract. The new IF block is added between existing lines with no ordering hazard beyond the (asserted) short-circuit-before-mutations invariant.
- **`set -eu` interaction with `$(git rev-parse HEAD 2>/dev/null || echo none)`**: `|| echo none` returns exit 0 for the outer command substitution, so `set -e` is quiet; the assigned var is a string (never unset), so `set -u` never trips. Standard idiom; already used in the body candidate.
