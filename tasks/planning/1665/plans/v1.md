```python
def test_fmt_pers_r256_train_config_carries_rank(fu5_round):
    """The brief's unit check: the built TrainLoraConfig for fmt-pers-r256
    carries r=256/alpha=64; use_rslora defaults True on the TrainLoraConfig
    dataclass field and train_lora threads it into LoraConfig
    (``use_rslora=cfg.use_rslora``), so r/alpha + the field default + the
    threading together pin the gamma=alpha/sqrt(r) regime the plan's alpha
    policy needs."""
    run = {r.run_id: r for r in fu4.FU5_RUNS}["fmt-pers-r256"]
    spec = fu4.fu4_recipe_spec(run.behavior, run.lr, lora_r=run.lora_r, lora_alpha=run.lora_alpha)
    cfg = build_train_config(spec, run_name=run.run_name, seed=42)
    assert (cfg.lora_r, cfg.lora_alpha, cfg.lr) == (256, 64, 1e-4)
    assert cfg.epochs == fu4.FU4_EPOCHS and cfg.save_steps == fu4.FU4_SAVE_STEPS
    import inspect

    from explore_persona_space.train.sft import TrainLoraConfig, train_lora

    assert TrainLoraConfig().use_rslora is True
    assert "use_rslora=cfg.use_rslora" in inspect.getsource(train_lora)
```

Design notes (all verified against the live files, 2026-07-24):

- **Import style:** the test already uses a function-local `from explore_persona_space.train.sft import train_lora` (L202); the fix extends that same inline import with `TrainLoraConfig` (defined in the SAME module: `@dataclass class TrainLoraConfig`, sft.py L583–584). Both names are used, so the PostToolUse ruff F401 auto-fix cannot strip them.
- **No-arg construction is safe:** `TrainLoraConfig` is a plain `@dataclass` whose first field `gpu_id: int = 0` (L593) has a default; dataclass rules force every later field to have one too (the module imports cleanly), so `TrainLoraConfig()` constructs with zero side effects.
- **The threading substring is exact:** sft.py L1489 reads `use_rslora=cfg.use_rslora,` inside `train_lora` (def at L1311; the only defs/classes in the file are at L257/448/584/1311, so L1489 is in `train_lora`'s body). The asserted substring `use_rslora=cfg.use_rslora` (no trailing comma) matches it. `inspect.getsource` returns the source as written, so no whitespace-normalization concern — the kwarg sits on one line.
- **Assert order:** field-default first, threading second — a default flip and a threading removal then produce distinct, immediately-legible failures.
- **Scope:** `tests/test_issue1090_fu5_round.py` ONLY. `src/explore_persona_space/train/sft.py` is NOT touched. L215/218/220/225 (adapter_config.json fixture dicts) and L227 (ValueError match) are JSON values / regexes, not source asserts — untouched.

## 5. Risks

| Risk | Assessment |
|---|---|
| Redundancy with `tests/test_train_lora_config_use_rslora.py` (which already pins the field-based contract on main) | Accepted and explicitly fine: redundant pinning across files is acceptable — this test's docstring cites the rsLoRA regime as part of ITS r=256 rank-threading argument, so it should carry its own pin rather than silently depend on a sibling file surviving. |
| The new threading pin is still a source-literal assert (`use_rslora=cfg.use_rslora`) and can drift again (e.g. a rename of `cfg`, or a refactor routing the kwarg through a dict) | Deliberate trade-off, per the task body: the failure direction is SAFE — drift makes the test fail LOUD, never silently pass, which is exactly what a pin should do. The heavier alternatives buy little: `inspect.signature(train_lora)` cannot see `use_rslora` at all (it rides the `cfg` object, not the signature), and an AST walk (find the `LoraConfig(...)` call, check the `use_rslora` kwarg is an `Attribute(value=Name('cfg'))`) is ~15 lines that still hard-codes the names `LoraConfig`/`cfg`/`use_rslora` — same drift surface, more machinery. Prefer the simple string pin. |
| `TrainLoraConfig()` construction breaking in future (a default-less field added) | Would fail this test loudly at the construction line — again the safe direction; the sibling test constructs it too, so any such change already owns updating both. |
| Whole-file collateral (other tests in the file newly failing) | No other test in the file reads `train_lora`'s source (verified: the only `use_rslora` source-assert was L204); the edit is confined to one function. |
