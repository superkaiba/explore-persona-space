# Plan v1 — task #1949: pin the root-commit guard's pathspec escape (regression fixtures for the -F / -m / redirect incident shapes)

## Goal / requirement

Make `guard_root_code_commit.sh`'s documented pathspec escape durably hold: a pathspec-limited `git commit ... -- <own paths>` must never be blocked by a FOREIGN session's staged uncertified files.

**Finding that reshapes scope (clarifier context pass, live repro 2026-08-03):** the behavioral root cause was ALREADY FIXED on main after this task was filed — `305df9ad14` (#1928, 2026-08-02) made redirect-bearing pathspec commit clauses engage scoping. A 12-case live repro against current HEAD (fixture repos, the hook's own harness conventions; `/tmp/issue-1949-repro.sh`) shows every incident-family shape ALLOWs correctly (bare `-m`, bare `-F`, `-m`/`-F` + redirect + `; echo rc=$?` / `; COMMIT_RC=$?`, quoted multiword `-m`, compound `add && commit`) with a foreign uncertified gated file staged, and sweep protection still BLOCKs (bare commit, foreign-named pathspec, own-uncertified pathspec).

**Residual deliverable (this plan): the body's requested regression matrix.** The `-F` / `--file` commit form has ZERO coverage in both test surfaces (0 hits in `tests/test_guard_root_code_commit.py`'s 126 tests; no `-F` self-test row in the hook), and the exact incident compound suffix (`; echo rc=$?` / `; COMMIT_RC=$?` after the redirect) is unpinned.
