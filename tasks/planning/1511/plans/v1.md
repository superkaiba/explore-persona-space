## 3. Hypothesis / decidability analysis (which shapes are mechanical, and why)

**Mechanically decidable (registered in v1)** — each reduces to an exact integer count over a well-defined value pool with a zero-referenced strict-sign predicate:

| Shape | Example | Recomputation |
|---|---|---|
| `all <N> <unit>` + sign | "all 50 contexts lie below zero" | some size-N pool has count(v<0)==N |
| `<K> of (the) <N> <unit>` / `<K>/<N> <unit>` + sign | "49 of 50 contexts lie below zero" | some size-N pool has count(v<0)==K (exact — counts are integers, no rounding ambiguity) |
| `none of the (<N>) <unit>` / `no <unit>` + sign | "none of the 50 contexts lie above zero" | some (size-N, else any) pool has count(v>0)==0 |
| copula sign variant | "all 12 deltas are negative" | negative≡below, positive≡above |

**Deliberately NOT matched (stays LM judgment / Lens 3), with the reason per shape:**

1. `nearly all` / `almost all` — no exact violation threshold exists (is 46/50 "nearly all"? — inherently vague), and the motivating #1426 sibling's actual defect was the "**far** below zero" magnitude gloss, which is a magnitude judgment no count recompute settles. A relaxed majority bound would not have caught it (46/50 ARE below zero). Excluded via the preceding-qualifier guard.
2. `all but <K>` — the embedded "`<K> of <N>`" substring inverts the semantics ("all but 4 of 50 below zero" ⇒ 46 below, not 4); matching it naively is a guaranteed false fire. Guarded by a preceding-text check; not reinterpreted in v1 (rare shape).
3. Bounds: `at least/at most/more than/over/up to/~/about/roughly K of N` — inequality claims; exact-equality recompute would false-fire. Guarded, skipped.
4. Bare `all <unit>` without N ("all points lie below zero") — without N the pool-size guard is lost and a multi-panel sidecar sharing column names could false-fire; recall sacrifice (the N-less "no/none-of" forms are kept because their pass condition — an all-one-sign pool exists — is rescue-shaped and errs toward false negatives, the safe direction).
5. Non-zero referents: "below the linear fit", "below the parse floor", "below 0.05" — the predicate requires the literal `zero` immediately after `below|above` (the real #1426 second caption "44 of 50 contexts fall more than 0.05 below the linear fit" is triple-blocked: period in `0.05` breaks the punctuation-free gap, and "below the" ≠ "below zero").
6. Bare `positive`/`negative` without a copula ("all 4 runs used positive prompts") — attribute usage, not a sign claim; only `are/is/remain(s)/stay(s) (strictly) negative|positive` is matched.
7. `none`/unit-less forms ("none lie above zero" without "of") — skipped; documented recall sacrifice.
8. Count claims in beat-1 / interpretation prose (not the caption) and in `## Takeaways` — out of scope in v1 (caption-only window; see §11-2).

**Falsification (kill criteria):**

- **K1 (schema heterogeneity):** if the corpus back-test finds value-bearing sidecars whose point rows do not follow the dict-row `points`/`rows` schema in a way the pool builder cannot parse → those sidecars silently skip by design; kill only if the *#1426 sidecar itself* were unparsable (already disproven — parsed this session).
- **K2 (precision unattainable):** if flagging the pre-fix #1426 caption cannot coexist with 0 false firings on legitimate current-corpus captions after one tightening round (dropping the `no <unit>` and N-less branches first, then the copula branch) → the residual shape set is not mechanically decidable at the project's precision bar; descope to `all <N>` + `<K> of <N>` only; if even that fires falsely → return a reasoned no-change report (the workflow-fix planner's deflection right).
- **K3 (vacuity):** if pool-size matching makes every real caption claim skip (no size-N pool anywhere in the corpus) the check would be dead weight — disproven in advance for the incident case (the #1426 y-pool has exactly 50 values), so K3 cannot fully fire; if #1426 turns out to be the ONLY scannable claim corpus-wide, still land it (regression-pinning the incident class is the point) and note the narrow live coverage.

### 4.1 Doc-block banner + constants

```python
# ─── Check 44: caption count claims vs sidecar point values ───
#
# Sixth sibling of checks 24/26/28/33/34 (same figure iteration, same
# `_read_figure_meta_json` sidecar read, same fail-soft skip conventions).
# Check 33 keys on BOLDED decimals and check 34 on two literal beat-phrase
# classes — a caption's quantified COUNT claim ("all 50 contexts lie below
# zero") carries neither, so #1426's caption passed every mechanical check
# beside a sidecar holding a +0.004 point and was caught only at
# clean-result-critic Lens 3 (one REVISE round). Check 44 recomputes the
# three registered count-claim shapes against per-column point-value pools;
# contradiction-only, any-size-matching-pool-satisfies, WARN never FAIL
# (forward-only), caption-only window. The purely-verbal half ("nearly
# all", "far below zero") stays LM judgment by design (#1511).

_COUNT_CLAIM_OPTOUT = "<!-- count-claims: manual -->"

_CC_GAP = r"[^.;:!?,]{0,40}?"  # verb-phrase gap: no sentence punctuation, no
# commas, no periods — blocks decimals ("more than 0.05 below …"), clause
# hops ("…, and none dip below zero"), and non-zero referents by distance.
_CC_PRED = (
    r"(?:(?:lie|lies|fall|falls|sit|sits|land|lands|are|is|remain|remains|stay|stays)\s+)?"
    r"(?:strictly\s+)?(?:(?P<below>below)|(?P<above>above))\s+zero\b"
    r"|(?:are|is|remain|remains|stay|stays)\s+(?:strictly\s+)?"
    r"(?:(?P<neg>negative)|(?P<pos>positive))\b"
)
_CC_KOFN_RE = re.compile(
    r"\b(?P<k>\d{1,4})\s*(?:of\s+(?:the\s+)?|/\s*)(?P<n>\d{1,4})\s+(?P<unit>[A-Za-z][\w-]*)"
    r"(?P<gap>" + _CC_GAP + r")\s(?:" + _CC_PRED + r")", re.IGNORECASE)
_CC_ALLN_RE = re.compile(
    r"\ball\s+(?P<n>\d{1,4})\s+(?P<unit>[A-Za-z][\w-]*)"
    r"(?P<gap>" + _CC_GAP + r")\s(?:" + _CC_PRED + r")", re.IGNORECASE)
_CC_NONE_RE = re.compile(
    r"\b(?:none\s+of\s+(?:the\s+)?(?:(?P<n>\d{1,4})\s+)?|no\s+)(?P<unit>[A-Za-z][\w-]*)"
    r"(?P<gap>" + _CC_GAP + r")\s(?:" + _CC_PRED + r")", re.IGNORECASE)
# Qualifiers that invert/soften the claim when they PRECEDE the match:
_CC_PRE_GUARD_RE = re.compile(
    r"(?:\bbut|\bexcept|\bat\s+least|\bat\s+most|\bmore\s+than|\bfewer\s+than|"
    r"\bless\s+than|\bup\s+to|\bover|\babout|\broughly|~|\bnearly|\balmost)\s*$",
    re.IGNORECASE)
_CC_UNIT_STOPWORDS = {"of", "the", "out"}
_CC_NO_QUALIFIERS = {"further", "other", "additional", "more", "new", "remaining", "such"}
```

Notes: `re` allows each named group once per pattern (each of the three patterns embeds `_CC_PRED` once); `nearly all 50 …` is rejected because the all-N match starts at `all` and the 16-char preceding-window guard sees `nearly `; `"49 of the 50 contexts"` matches K-of-N (the `of\s+(?:the\s+)?` branch), while `"all 50 of the 60 contexts"` is rejected at S1 (unit `of` is a stopword) and correctly re-read by S2 as 50-of-60.

    """Per-column point-value pools from the sidecar's ``points``/``rows``

    Two grains: the merged ``(None, col)`` pool always; per-kind

## 11. Decision Rationale (design constants)

1. **WARN, not FAIL.** *Why:* (a) family convention — the value-drift siblings 33/34 are WARN; the only sidecar FAIL (check 26) covers narrow explicit structural claims; (b) forward-only hard constraint — check 41's docstring precedent: a retroactive FAIL blocks promote-time re-verifies of grandfathered bodies; (c) residual FP channels exist (subset/panel claims over shared-key pools) that any-pool-satisfies reduces but cannot zero; (d) WARNs still bind ("WARNs ship only when acknowledged in body"). *Source:* check 33/34/41 docstrings; CLAUDE.md report-structure WARN semantics. *Alternative rejected:* FAIL for v4-only + WARN grandfathered (check 42's split) — the FP channel argues WARN even on v4; revisit after a quarter of corpus data.
2. **Caption-only window.** *Why:* the incident lives in the caption; captions are figure-owned by construction, while beat-1/interpretation prose can carry claims about other figures/subsets (check 33 needed a bleed-suppression mechanism for exactly that; caption-only avoids importing it). *Source:* incident #1426; check 33's cross-figure-bleed machinery as the cautionary precedent; task body "scan the adjacent blockquote caption". *Alternative:* beat-1 window — deferred; a follow-up can widen once caption precision is proven.
3. **Registered shape set + exclusions** (§3 table). *Why:* each registered shape reduces to an exact integer predicate; each exclusion has a named ambiguity (per-shape reasons in §3). *Source:* check 34's literal-incident-classes precedent; the real #1426 captions (both versions) + the "44 of 50 … below the linear fit" non-match case. *Alternative:* "nearly all ⇒ >50% bound" — rejected: would not have caught the motivating sibling (46/50 ARE below zero; its defect was the "far below" gloss, LM territory).
4. **Strict zero, no epsilon.** *Why:* the incident value is +0.004368 — small; any tolerance wide enough to absorb float-noise cases would re-mask the incident class; Lens 3 treated +0.004 as a real contradiction. *Source:* incident #1426; #1426 sidecar values. *Alternative:* epsilon = 1e-12 for exact-zero float noise — unnecessary (exact 0.0 already counts as neither below nor above, which is the correct reading).
5. **Any-size-matching-pool-satisfies.** *Why:* the sidecar has no axis/panel identity for a claim to bind to (check 26's `_group`-is-not-panels finding); requiring N-sized pool membership and passing on ANY satisfying candidate errs exclusively toward false negatives — the mandated direction. *Source:* `_sidecar_kind_group_aggregate` NOTE; check 33's leniency-only-reduces-warns principle. *Alternative:* pick the "y-axis" column heuristically — rejected: the writer's key order is axis-label-derived and unverified as an axis identity (the `_sidecar_plotted_values` docstring flags legacy key order as unverified).
6. **Two pool grains (merged per-column + per-(kind, column) when ≥2 kinds).** *Why:* mixed-kind sidecars share column names (issue_1005 mediation figure, verified); the per-kind grain restores an N-sized candidate there; extra pools only add rescues (FN direction). *Source:* the two issue_1005 sidecars read this session. *Alternative:* per-`_group` pools — rejected: `_group` is per-artist and absent on single-artist figures; adds complexity without a grounded win.
7. **Bar-x exclusion (per-entry, first-non-meta-key of modern bar rows).** *Why:* dodge offsets are layout, not data, and are provably sign-bearing (`"x": -0.19` in a real sidecar) — they would pollute offender messages and rescue/contradict claims meaninglessly. *Source:* `_sidecar_plotted_values` implementation + `compliance_by_family_vs_parent.meta.json`. *Alternative:* keep bar-x with an `is_bar_x` tag like check 33 — rejected: check 33 needs the values for its leniency stack; count pools have no such use.
8. **Generation-agnostic gating.** *Why:* matches every sibling sidecar check (24/26/28/33/34/41 all run on v2/v3/v4); WARN severity already satisfies forward-only, so no v4-only gate is needed; v3 bodies carry the same caption convention. *Source:* CHECKS-list comments; check 33's `_V3_GOOD_BODY` test. *Alternative:* v4-only — rejected: would exempt the very grandfathered bodies most likely to carry unreviewed captions, for no FP benefit.
9. **Opt-out literal `<!-- count-claims: manual -->`.** *Why:* the family's documented FP escape hatch (check 33's `<!-- prose-numerics: derived -->`); render-invisible; named in the WARN detail so the fix path is self-documenting. *Source:* check 33 convention + its opt-out tests. *Alternative:* none (an opt-out-less WARN check has no author remedy for the residual FP class).
10. **Exact-equality for K-of-N.** *Why:* counts are integers — no rounding ambiguity; bounds phrasing ("at least K") is guard-skipped rather than approximated. *Source:* the corrected #1426 caption (exact "49 of 50" recomputes exactly). *Alternative:* ±1 slack — rejected: would have passed a "50 of 50" miscount as "49 recomputed", i.e. re-masking the incident.
11. **Check number 44; placement after check 41.** *Why:* lowest unclaimed number; contiguous additive block minimizes the #1509/#1510 conflict surface. *Source:* CHECKS list state at plan time; clarifier sibling triage (verified via task titles). *Alternative:* interleave next to check 33 — rejected: mid-file insertion maximizes merge churn.
