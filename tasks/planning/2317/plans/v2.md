## 1. Requirement + acceptance criteria

**Requirement.** A gate set sourced from `select_step9c_tests.py --files-only`
(one path per LINE) must not be spliceable into the Step 9c 1b detached
launcher's command TEXT as multiple commands, and the existing cross-check
must FAIL LOUD on that shape instead of reporting success. The fail-loud
behavior is carried by a committed test —
`tests/test_issue_skill_gate_recipe_hardening.py::test_splice_shape_assertion_actually_discriminates`
(§3.2), which executes the assertion and asserts it fires on a newline list
and stays silent on a space list.

**Why the existing guard cannot catch it.** The guard counts paths after
UNQUOTED word-splitting (`printf '%s\n' $S9C_FILES | grep -c .`). `IFS`
includes newline, so a newline-separated 120-path list counts as exactly 120
and passes — while the same string spliced into
`bash -c "… uv run pytest $S9C_FILES …"` is parsed by the inner shell as 120
COMMANDS. The guard validates CARDINALITY; the failure is in SHAPE. The two
are independent, so no tightening of the count check can reach it.

**Realized blast radius (#2314, verified at source in its `events.jsonl`,
not quoted from this task's body):** pytest ran **1 of 120** selected files
(`test_adhoc_summary_disclosure_pins.py`, 5 passed); paths 2..120 each failed
as `bash: line N: tests/…: Permission denied`. The trailing flags attached to
the LAST bogus line, so the one real pytest invocation ran with **no
`--junitxml`** — no junit XML was written at all — and `rc=126` (the shell's
"not executable") landed in the rc sentinel within ~1 s. The line
`[step9c] gate set cross-checked: 120 test files` printed immediately before.

**Acceptance criteria** (mirroring the task body's four, each mapped to a

The body instructs: *"Apply to EVERY hooked gate site that splices a file

over SKILL.md, plus a bounded pass over `.claude/{skills,agents,rules}/`,
`scripts/`, `tests/`, worktrees excluded). Result: **there is exactly ONE
copy and exactly ONE vulnerable site.** Full enumeration, the record AC2 asks

| Site | SKILL.md lines | Shape | Verdict |
|---|---|---|---|
| **9c 1b guard + launcher** | 10186-10197, 10224 | `S9C_FILES="<files>"` string spliced into a double-quoted `bash -c "…"` | **VULNERABLE — the only one** |

| Step 9a-ter inline payload lint gate | via `--map-files` (12605 prose) | same `mapfile` array shape | **structurally immune** |

**Why the array sites are immune, not merely untested.** `mapfile -t` splits
on newline BY DESIGN — newline-separated input is the CORRECT input there —
and the quoted array expansion yields one argv word per element with no shell
re-parse. There is no `bash -c` string, no placeholder, and no cross-check
paragraph at any of them. Their immunity is a property of the expansion form,
so it survives future edits to the list SOURCE; it is not a coincidence of the
current selector output.

**Consequence for the fix.** AC2 is discharged by (a) hardening the single
vulnerable site and (b) recording this enumeration — NOT by propagating a
guard to five sites that cannot exhibit the defect. Adding the guard to the
array sites would be dead code that a future reader would mistake for
evidence the array shape is unsafe. A one-sentence scope note at the 1b guard
records that the guard is site-scoped and why, so a future editor adding a
SECOND `bash -c` splice site knows it needs its own.

**Proximate cause, stated plainly (the body's own scope note).** #2314's
operator deviated from the documented `<files>` placeholder by sourcing
`--files-only` directly. This fix does not pretend otherwise. It ships anyway
because the deviation is the NATURAL one — the recipe itself calls
`--files-only` one line above the splice and explicitly blesses that route at
line 10036-10037 — the guard that exists reports SUCCESS on it, and the blast
radius is a gate certifying 1/N of its selection as green.

## 3. File paths + concrete changes

### 3.1 `.claude/skills/issue/SKILL.md` — the 1b block (~10186-10197)

Four edits inside the existing cross-check comment block, all BEFORE the
launcher at 10222-10227 (the existing `cross_idx < launcher_idx` ordering pin
must keep passing):

**(a) Splice-safe sourcing.** The `--files-only` route blessed at 10036-10037
becomes explicit about the normalization, with the reason inline:

```sh
# Sourcing from --files-only: NORMALIZE to spaces. --files-only emits one
# path per LINE (correct for the Step 10d `mapfile -t` array consumers); a
# newline-bearing string spliced into the launcher's `bash -c "…"` command
# TEXT is parsed by the inner shell as N COMMANDS, not one pytest argv
# (#2314: 1 of 120 files ran, the trailing flags — --junitxml included —
# attached to the last bogus line, rc=126):
S9C_FILES=$(uv run python scripts/select_step9c_tests.py --files-only | tr '\n' ' ')
```

The 1a-printed-command route (`S9C_FILES="<files>"` copied verbatim from
step 1a) is UNCHANGED — that command is already space-joined on one line.
Both routes then hit the same two checks below.

**(b) Splice-shape assertion**, beside (not replacing) the count check:

```sh
[ "$(printf '%s' "$S9C_FILES" | wc -l)" -eq 0 ] \
  || { echo "FATAL: substituted <files> contains NEWLINES — the launcher's inner bash -c would parse each path after the first as its own COMMAND (pytest would run 1 of N files, the trailing flags incl. --junitxml would attach to the last bogus line, and rc would be 126); re-source with | tr '\n' ' '; do NOT launch" >&2; exit 1; }
```

`printf '%s'` adds no trailing newline, so `wc -l` counts EMBEDDED newlines
exactly: 0 for a space list, N-1 for an N-path line list.

**`wc -l`, deliberately not `case`.** The obvious-looking
`case "$S9C_FILES" in *"$(printf '\n')"*)` is BROKEN: command substitution
strips trailing newlines, so `$(printf '\n')` yields the EMPTY string, the
pattern degenerates to `*""*`, and it matches every string — firing
unconditionally. #2314's second launch attempt hit exactly that. It failed
SAFE, but a guard that cannot fail correctly is not a guard, and the next
editor reaching for the readable-looking form needs the trap named where they
will read it. A one-line NEGATIVE comment records it.

**(c) Guard self-test**, immediately before (b) — three lines, and the thing
that actually caught the broken guard in #2314:

```sh
# Self-test the assertion before trusting it (a broken newline test that
# never fires is worse than no test): a space list must score 0, a newline
# list must score 1.
[ "$(printf 'a b' | wc -l)" -eq 0 ] && [ "$(printf 'a\nb' | wc -l)" -eq 1 ] \
  || { echo "FATAL: splice-shape assertion is itself broken on this shell — do NOT launch" >&2; exit 1; }
```

**(d) Site-scope note** — one sentence recording the §2 enumeration: the
guard is scoped to this site because it is the only `bash -c`-spliced file
list; the Step 10d / 9a-ter legs use `mapfile -t` + a quoted array expansion,
where newline input is correct by construction.

## 4. Design decisions

- **D1 — `tr '\n' ' '` normalization at the SOURCE + an assertion at the
  SPLICE, not one or the other.** The normalization fixes the natural route;
  the assertion catches every OTHER route (hand-typed paste, stale copy from a
  prior round, a future third source). Normalization alone would leave the
  guard still reporting success on a multi-line paste.

- **D2 — `wc -l`, not `case`/glob.** Rationale in §3.1(b): command
  substitution strips trailing newlines, so the glob form degenerates to a
  match-everything pattern. Measured in #2314's second launch attempt.

- **D3 — AC3 decision: RECIPE-SIDE ONLY. No `--sep=space`, no NUL mode.**
  Four reasons, strongest first:
  1. **A NUL mode cannot fix this site at all.** The 9c 1b defect is a splice
     into command TEXT, where NUL is unrepresentable. NUL delimiting helps
     `xargs -0` / `read -d ''` consumers; there are none here.
  2. **A `--sep=space` mode would create a second output contract whose misuse
     is the mirror-image bug.** The line-per-path shape is REQUIRED by the
     Step 10d / 9a-ter `mapfile -t` consumers; a space-joined list fed to
     `mapfile` yields ONE array element holding all 120 paths, and pytest gets
     a single bogus argument. Two modes means a new way to pick the wrong one,
     on a surface whose failure mode is a silently-green gate.
  3. **A flag protects only the source an operator remembered to use; a guard
     at the splice protects every source.** Strictly wider coverage for less
     code.
  4. The defect is not in the selector's output — that output is correct for
     its contract. Fixing it in the selector would be treating a correct
     producer for a consumer's parsing bug.
  Residual accepted: `tr '\n' ' '` is lossy for paths containing whitespace.
  Test paths in this repo are `tests/test_*.py` with no whitespace, and the
  selector emits repo-relative test paths only, so the transform is lossless
  here. Noted rather than guarded — a whitespace-bearing test path would break
  the space-joined `<files>` placeholder contract at line 10017 long before it
  reached this normalization.

- **D4 — the count check is RETAINED, not replaced.** It catches a DIFFERENT
  channel (#1992's wrong `--json` key → empty list → whole-suite collection).
  Shape and cardinality are independent failures; both guards stay.

- **D5 — no change to `select_step9c_tests.py`.** Follows from D3. Its
  `--files-only` emitter and empty-selection refusal are untouched, so
  `tests/test_select_step9c_tests.py` and `tests/test_step9c_baseline.py` have
  no reason to move.
