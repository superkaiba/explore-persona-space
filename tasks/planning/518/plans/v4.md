# Plan #518 v4 — refusal + EM analogue of the #509 sycophancy predictor arm, plus a completion-log-prob metric in both roles

## 0.0 TL;DR (plain English)

- **What I'll run:** I'll train Qwen-2.5-7B in two new ways — once to refuse a benign question under a chosen persona, once to give bad/insecure advice under a chosen persona — and then see how much that behavior bleeds into 23 other unrelated personas the model wasn't trained on. I'll do this for the same 6 personas I used in the sycophancy run, so the panel is held fixed and the only thing changing is which behavior I'm implanting.
- **What I expect:** I expect that the predictors that worked for predicting sycophancy leakage probably won't work for predicting refusal or misalignment leakage — each behavior likely has its own "best predictor cell," and I expect the cross-behavior comparison to fail. I'm betting that "different behavior, different cell" generalizes. The one predictor I think has a real shot at generalizing is the new training-data log-probability metric — because it's about how surprised the base model is by the data, which feels more behavior-agnostic than residual-stream geometry.
- **What would change my mind:** if one predictor cell — the same cell, same metric, **in the same direction** — clears a moderate correlation on all three behaviors (sycophancy + refusal + misalignment) at once, that's a real universal predictor and I'd update toward "there is a behavior-agnostic persona-distance axis." Or if the bystander cloud floors on both new behaviors (the way it half-floored on sycophancy) — that tells me the contrastive-negatives recipe is too aggressive and I'm measuring noise, not a real signal.

## 1. Goal

Quote from `body.md`:
> Re-run the #470/#509 leakage-prediction analysis for refusal and emergent-misalignment behaviors, reusing the closest old source-by-bystander leakage panels, scoring the same predictor zoo (cosine_l20, JS, KL) plus bystander base rate (confound-aware, per #509) and a new training-completion log-prob metric (generalizing #500/#444's fact-validated bystander_logprob), and report whether any predictor generalizes across behaviors; also report training-completion log-prob trained-minus-base as a non-saturating implant-quality readout on each source.

**Hypothesis (if-then, quantitative).** If any base-model persona-distance signal (geometric, divergence-based, base-rate-based, or completion-log-prob-based) is a universal predictor of behavior leakage, THEN at least one of the ~1500+ predictor cells in the #509 zoo should clear source-FE attenuation-adjusted |ρ| ≥ 0.40 with permutation p ≤ 0.01 across all three of {refusal, EM, syco} arms — *the same cell*, on the same metric scale, **in the same direction (operationalized as `same_sign(ρ_syco, ρ_refusal, ρ_em)` — all three Spearman ρ values share the same sign after metric orientation)**. **What would falsify it:** no single cell satisfies the joint same-sign-and-magnitude threshold on all three arms; the strongest predictor on refusal differs from the strongest predictor on EM differs from the strongest predictor on syco (the #509 "different behavior, different cell" finding generalizes to refusal + EM and the search is fundamentally local to each behavior). **What would partially confirm it:** the completion-log-prob predictor specifically generalizes (since it's the only predictor with cross-behavior fact-arm validation in #500); other zoo cells do not.

The implant-quality readout (completion log-prob trained − base, on the source's own training data) is reported alongside the behavioral rate per source as a secondary table — it answers "did the implant land, on a non-saturating scale" and lets readers compare implant strength across sources without being fooled by the 90%+ saturation ceiling that the on-policy behavioral rate hits on most implanted sources (the #448 saturation incident).

### 4.5 Cross-behavior aggregator [k]

**New script** `scripts/issue518_cross_behavior_aggregator.py` (~150 LOC). Reads per-arm scoring JSON for {refusal, em} from #518 + the existing syco scoring JSON from `eval_results/issue_509/syco_arm/scoring.json` (re-scored in [j] with the new `completion_logprob` column from [d.5]). For each predictor cell present across all three arms:
- Compute the signed Spearman ρ triple `(ρ_syco, ρ_refusal, ρ_em)` per cell and log all three values in a per-cell table (descriptive — even cells that fail the sign gate appear here for interpretation)
- **Apply the same-sign gate:** `same_sign(ρ_syco, ρ_refusal, ρ_em)` is TRUE iff all three signs are equal after metric orientation. Define precisely: sign of each ρ taken as `+1` if `ρ > 0`, `-1` if `ρ < 0`, and `0` if `|ρ| < 1e-6` (numerical-tie / zero-ρ — fails the sign gate by definition since the cell is ambiguous on at least one arm). The gate passes iff `sign(ρ_syco) == sign(ρ_refusal) == sign(ρ_em) AND none is 0`.
- For cells passing the sign gate, compute `min(|ρ|) = min(|ρ_syco|, |ρ_refusal|, |ρ_em|)`. Rank passing cells by `min(|ρ|)` — the cross-behavior search-best is the top cell among those.
- Cells that FAIL the sign gate are listed in the per-cell triple table for descriptive interpretation but are NOT eligible for the cross-arm headline Y/N. This closes the v3 bug where a cell with `(+0.5, +0.5, -0.5)` would have cleared `min(|ρ|) ≥ 0.40` while contradicting the same-direction predictor claim.
- Also compute `mean(|ρ|)` and `max - min` (range) across arms for descriptive purposes (these do not feed the headline gate).

Output: `eval_results/issue_518/cross_behavior_aggregator.json` with the per-cell signed-ρ triple + the gate status (`same_sign_pass: bool`) + `min(|ρ|)` (computed but only authoritative when `same_sign_pass=True`) + the headline "any cell clears `same_sign(ρ_syco, ρ_refusal, ρ_em) AND min(|ρ|) ≥ 0.40` on all three? Y/N + which cell + per-arm signed ρ + per-arm p-values".

**This is the cell that answers the body's Y/N question.** Selection-inflation disclaimer carried — the aggregator picks the cross-arm-best cell from ~1500 candidates per arm. The pre-registered anchor cell (#502's late-layer last-prompt Gaussian-KL at L22) is reported alongside the search-best as the non-selected baseline. Search-best ranking remains over `min(|ρ|)` among cells that pass the sign gate; the per-cell signed-ρ triple table is the descriptive surface for the cells that fail the gate.

### 4.6 Why code, not a model call?

The judge for the behavioral DV IS a model call (Haiku for refusal, Sonnet 4.5 for EM). The predictor pipeline is mostly tensor math (cosine, KL, JS, log-prob teacher-force) and is necessarily code, not a model call — there's no "ask the model what its persona distance is" formulation that would replace the residual-stream extraction. The judge step is the only model-call step, and it's already the project convention (`Source: #411`). N/A for the rest of the design.

### 4.7 Contrastive negatives for behavior implantation

Both refusal + EM arms use contrastive negatives by design (matching #411's protocol): 200 source-positive + 400 bystander-negative (across 4 negative-personas × 100 rows each) + 100 no-persona contrastive. This is the default contrastive-negatives recipe from `.claude/rules/contrastive-negatives.md` — same questions under different personas, with the bystander-negatives emitting a competing correct response under marker-less / refusal-less framing. The exemption flag does NOT apply here.
