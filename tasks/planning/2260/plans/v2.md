A runtime exempt list would fix that, but that is a second literal list rotting in the DANGEROUS direction (a missed exemption causes wrong syncs, not a missed coupling). (ii) **In-repo precedent rejects runtime mechanisms here:** #2352's guard-19 docstring records that a runtime probe was considered and DEFERRED because a bug in the hot path reds every Step 5a run and every merge fleet-wide, while a static guard catches the class earlier, on main, at the introducing PR. Trap 3 (union-of-views) applies only to the runtime variant; statically, membership is a pinned literal that itself syncs with the workflow family (the FAMILY_OF table lives in `steps/09-step-5.md` = `.claude/skills` = workflow family), so membership updates propagate to worktrees through the existing sync.

**(1e) Member-existence containment arm** (INSIDE the pass-1 `for f in $SPECS; do` loop, inserted immediately after the loop opens at L232, BEFORE the `bs_commits=` stanza). ```

```
  # checkout below is ATOMIC — a single literal token absent at origin/main
  # (deleted/renamed on main) errors the whole checkout and syncs NOTHING,
  # wedging every family until manual reconcile. Contain per-family: an
  # absent literal member marks ITS family dirty (vintage-consistent skip;
  # other families keep syncing). Deletion PROPAGATION (removing the stale
  # worktree twin) remains #2385 — reconcile manually until it lands.
  case "$f" in
    ":(glob)"*) : ;;
    *)
      if ! git -C "$WT" cat-file -e "origin/main:$f" 2>/dev/null; then
        fam="${FAMILY_OF[$f]:-$f}"
        DIRTY_FAMILIES[$fam]=1
        echo "spec-freshness: $f is ABSENT at origin/main (deleted/renamed on main) — marking family '$fam' dirty; skipping blind sync for the whole family (atomic-checkout containment, #2260; stale-twin removal is #2385 — reconcile manually)."
        continue
      fi
      ;;
  esac
```
