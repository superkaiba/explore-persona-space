# Plan v2 — issue #725 — daily-fix: `living_docs.py check` degrade on bad task

Estimated GPU-hours (total): 0

## Requirement + acceptance criteria

**Requirement.** `uv run python scripts/living_docs.py check` MUST NOT
hard-crash when the registry and the on-disk task tree disagree about
a single task. Two registry/filesystem inconsistency modes are
in-scope:

- **Mode A** — registry entry exists with a `path` pointing at a
  directory that does NOT exist on disk. Raises `FileNotFoundError`
  from `task_workflow.find_task_path` (line 1418-1422 at HEAD).
  Tonight's documented crash (#696).
- **Mode B** — registry entry exists, the on-disk directory exists,
  but `body.md` is absent inside it. Raises `FileNotFoundError` from
  `tw._read_body → path.read_text()` (`task_workflow.py:627-628` at
  HEAD). Partial `git mv` / interrupted-write inconsistency.

The drifted task must surface in the returned `CheckReport` as a
single, specific drift finding naming the task id + the underlying
inconsistency, the lint must complete its remaining checks against
the surviving tasks, and the process exit code must continue to
reflect drift (`1`) vs no-drift (`0`) the same way it does today.

**Acceptance criteria** (each is a binding gate the implementer
verifies + the code-review ensemble + Step 9c test-verdict gate
enforce):

1. `living_docs.check()` returns a `CheckReport` (no raise) under
   EITHER Mode A or Mode B.
2. Each drifted task surfaces in `report.problems` as one line naming
   the task id + the underlying inconsistency.
3. All four other check axes — (a) bidirectional, (b) coverage, (c)
   resolvable, (d) staleness — still run and still find findings on
   the surviving tasks. (Test asserts this concretely; see § Test
   spec below.)
4. Two new pytest unit tests under `tests/test_living_docs.py`
   reproduce Mode A + Mode B and assert (1) + (2) + (3) above.
5. `uv run ruff check scripts/living_docs.py tests/test_living_docs.py`
   passes; `uv run ruff format --check ...` passes; the full
   `uv run pytest tests/test_living_docs.py -v` suite is green; the
   broader `tests/test_workflow*.py` + `tests/test_task_workflow*.py`
   suites are unchanged.

## Method delta (what differs from existing code)

The bug is in two registry-iterating helpers in
`scripts/living_docs.py`:

- `_completed_task_dates` (line 1115) — iterates
  `tw.list_by_status("completed")` and calls `tw.find_task_path(tid) /
  "body.md"` per task, then `tw._read_body(body_md)`.
- `_relates_to_index` (line 1144) — iterates
  `tw._load_registry()["tasks"]` and calls the same pair.

Both raise `FileNotFoundError` (uncaught) from EITHER `find_task_path`
(Mode A) OR `_read_body`'s `read_text()` (Mode B). The single-call
sibling `link()` at line 939 already handles Mode A via
`try / except FileNotFoundError: missing.append(tid); continue` — the
in-file precedent for the skip-and-collect pattern (verified at HEAD;
this fix extends it).

**The change**: widen the precedent to BOTH bug-bearing helpers, AND
widen the guard scope to cover path resolution + body read together,
so both Mode A and Mode B route to the same skip-and-collect path.
Each helper returns its data dict as today AND a list of
`(tid, error_message)` pairs for tasks it could not read; `check()`
appends one problem line per drifted task to `report.problems`,
union-dedup'd across the two indexers (the same drifted task can show
up in both passes).

**Call-site enumeration (Codex concern addressed).** Grep at HEAD
shows `_relates_to_index` and `_completed_task_dates` are called ONLY
from `check()`:


No other callers. The tuple-return refactor is module-private — no

**Out of scope**:
- `_all_task_ids` (line 1138) reads ONLY `_load_registry()` (no

- `link()` (line 939, the precedent) — already handles Mode A, no
  change.
- `tw.find_task_path` / `tw._read_body` themselves — stay loud at the
  raiser; caller-side handling is correct.
- No mutation of task state (per task body: "do NOT mutate task state
  to 'fix' the bad task — just degrade gracefully").

### `scripts/living_docs.py`

**Change 1** — `_completed_task_dates` (around line 1115):

```python
# Before
def _completed_task_dates(paths: LivingDocsPaths) -> dict[int, str | None]:
    out: dict[int, str | None] = {}
    for entry in tw.list_by_status("completed"):
        if not entry.get("has_clean_result"):
            continue
        tid = int(entry["id"])
        fm, _ = tw._read_body(tw.find_task_path(tid) / "body.md")
        if fm.get("living_docs_unmapped"):
            continue
        stamp = fm.get("promoted_at") or fm.get("created_at")
        date = str(stamp)[:10] if stamp else None
        out[tid] = date
    return out

# After
def _completed_task_dates(
    paths: LivingDocsPaths,
) -> tuple[dict[int, str | None], list[tuple[int, str]]]:
    """Map every completed-with-clean-result task id → its promotion date.

    Returns ``(dates, drifted)``: the second element lists
    ``(task_id, error_message)`` pairs for tasks whose registry entry
    is inconsistent with the on-disk tree (dir missing OR ``body.md``
    missing). These surface as drift findings in :func:`check` rather
    than crash the whole pass — see also :func:`_relates_to_index`.
    """
    out: dict[int, str | None] = {}
    drifted: list[tuple[int, str]] = []
    for entry in tw.list_by_status("completed"):
        if not entry.get("has_clean_result"):
            continue
        tid = int(entry["id"])
        try:
            body_path = tw.find_task_path(tid) / "body.md"
            fm, _ = tw._read_body(body_path)
        except (FileNotFoundError, OSError) as e:
            drifted.append((tid, str(e)))
            continue
        if fm.get("living_docs_unmapped"):
            continue
        stamp = fm.get("promoted_at") or fm.get("created_at")
        date = str(stamp)[:10] if stamp else None
        out[tid] = date
    return out, drifted
```

Key delta from v1: the `try` block wraps BOTH `find_task_path` AND
`_read_body`, and the `except` catches `(FileNotFoundError, OSError)`
(broader IO-error class — covers Mode A, Mode B, and any sibling
permission/io error a future inconsistency might surface). Mirrors
the closest stdlib precedent for "treat any filesystem read failure
as 'task unreachable; surface as drift'".

```python
def _relates_to_index(
    paths: LivingDocsPaths,
) -> tuple[dict[int, list[str]], list[tuple[int, str]]]:
    """Map task id → its ``relates_to`` list across all statuses.

    Returns ``(index, drifted)``: the second element lists
    ``(task_id, error_message)`` pairs for tasks whose registry entry
    is inconsistent with the on-disk tree (see
    :func:`_completed_task_dates`).
    """
    out: dict[int, list[str]] = {}
    drifted: list[tuple[int, str]] = []
    reg = tw._load_registry()
    for tid_str in reg.get("tasks", {}):
        tid = int(tid_str)
        try:
            body_path = tw.find_task_path(tid) / "body.md"
            fm, _ = tw._read_body(body_path)

            out[tid] = [str(q).lower() for q in rel]
```

**Change 3** — `check()` (around line 1297-1300): consume the new
tuples and surface drifted tasks as drift problems, dedup'd across
the two indexers.

```python
# Before
relates = _relates_to_index(paths)
all_ids = _all_task_ids(paths)

# After
relates, relates_drifted = _relates_to_index(paths)
all_ids = _all_task_ids(paths)
completed, completed_drifted = _completed_task_dates(paths)

# Surface any registry/filesystem inconsistency as a drift finding,
# dedup'd across the two indexers (the same drifted task can show up
# in both passes). One line per task, naming the id + the underlying
# raise.
seen_drifted: set[int] = set()
for tid, err in [*relates_drifted, *completed_drifted]:
    if tid in seen_drifted:
        continue
    seen_drifted.add(tid)
    report.problems.append(
        f"task #{tid} registry/filesystem inconsistent: {err} "
        f"(run `task.py audit` to repair)"
    )
```

The `task.py audit` hint mirrors the same hint baked into
`task_workflow.find_task_path`'s error string (line 1421 at HEAD), so
a user reading the new drift line sees the SAME repair instruction
they'd see in the previously-uncaught traceback. The "problem-line"
register matches the other `_check_*` checkers (one finding per
issue, terse).

#### Test spec — concrete criterion-#3 assertion

The fixture has tasks #207 (`relates_to: [a1, b1]`,
`has_clean_result: true`) and #208 (`relates_to: [a2, b1]`,
`has_clean_result: true`); `open_questions.md` lists #207 in a1's +
b1's evidence and #208 in a2's + b1's evidence. Drifting #207's
registry entry to a missing path drops #207 from `_relates_to_index`
AND `_completed_task_dates`. This is what we then leverage for the
criterion-#3 assertion:

- #207 is still cited in a1's evidence (open_questions.md is
  untouched). The bidirectional check (a) scans every evidence
  entry and looks up its task's `relates_to`. With #207 missing
  from `relates`, the (a) check WILL surface a missing-backlink
  finding for #207 in a1 (and a1 + b1 — every question that cited
  #207). That finding is NOT a "registry/filesystem inconsistent"
  drift line; it is a legitimate non-drift axis still running.
  Asserting its presence satisfies criterion #3.

Concrete tests:

```python
def test_check_degrades_on_drifted_registry_path(fixture):
    """Mode A: registry entry points at a missing directory.

    `find_task_path` raises FileNotFoundError; `check()` must surface
    the drifted task as a problem (NOT raise), AND the surviving
    check axes must still run against the registry-trimmed index.
    Reproduces tonight's documented crash (task #725 body).
    """
    import json
    repo, paths = fixture
    # Drift #207's registry path to a nonexistent dir. The on-disk
    # tasks/completed/207/ still exists; only the registry POINTS
    # somewhere else — exactly `find_task_path`'s
    # entry-present-but-dir-missing raise branch (task_workflow.py:1418).
    reg_path = repo / "tasks" / "REGISTRY.json"
    reg = json.loads(reg_path.read_text())
    reg["tasks"]["207"]["path"] = "tasks/approved/207"  # nonexistent
    reg_path.write_text(json.dumps(reg, indent=2, sort_keys=True) + "\n")

    # (1) Must not raise.
    report = ld.check(paths=paths)

    # (2) Drift finding present, names #207.
    drift_lines = [p for p in report.problems
                   if "registry/filesystem inconsistent" in p]
    assert any("#207" in p for p in drift_lines), report.problems
    # The fixture has #208 still well-formed → exactly one drift line.
    assert len(drift_lines) == 1, drift_lines

    # (3) Surviving axes still ran: #207's name still appears in a1's
    # evidence in open_questions.md, but #207 is no longer in the
    # relates-to index, so the bidirectional check (axis a) MUST flag
    # a missing-backlink finding for #207 vs a1 (and vs b1).
    nondrift = [p for p in report.problems
                if "registry/filesystem inconsistent" not in p]
    assert any("207" in p and "a1" in p for p in nondrift), (
        f"axis (a) bidirectional should have flagged #207 vs a1 "
        f"after the drift trimmed it from relates_index; got "
        f"non-drift problems: {nondrift}"
    )
    # report.ok must be False (drift present).
    assert not report.ok


def test_check_degrades_on_missing_body_md(fixture):
    """Mode B: registry entry's dir exists but body.md is missing.

    `tw._read_body → path.read_text()` raises FileNotFoundError;
    `check()` must surface the drifted task as a problem (NOT raise),
    AND the surviving check axes must still run.
    """
    repo, paths = fixture
    # Delete #207's body.md while keeping the registry entry intact
    # AND the directory present — the on-disk tasks/completed/207/
    # exists, body.md does not. `find_task_path` returns successfully
    # (dir exists); the subsequent `read_text` raises.
    body = repo / "tasks" / "completed" / "207" / "body.md"
    body.unlink()

    # (1) Must not raise.
    report = ld.check(paths=paths)

    # (2) Drift finding present, names #207.
    drift_lines = [p for p in report.problems
                   if "registry/filesystem inconsistent" in p]
    assert any("#207" in p for p in drift_lines), report.problems
    assert len(drift_lines) == 1, drift_lines

    # (3) Surviving axes still ran: same bidirectional flag as Mode A
    # — #207's drop from relates_index has the same downstream effect
    # whether it was Mode A or Mode B.
    nondrift = [p for p in report.problems
                if "registry/filesystem inconsistent" not in p]
    assert any("207" in p and "a1" in p for p in nondrift), nondrift
    assert not report.ok
```

The Mode-A and Mode-B tests share the same "surviving axes still
ran" assertion (criterion #3) — both close the same drift-equivalent
downstream behavior. This is the concrete assertion the v1 plan left
to the implementer; v2 specifies it here.
