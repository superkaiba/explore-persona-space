## 2. Method delta (everything else inherits from v2 §4 Phase B)

**Changed: capture index.** Each probe now requires the base model's own greedy response before the state read. Per (context, probe):

1. **Greedy generation** from the already-assembled context prompt (same `assemble_contexts()` union — 42 contexts, byte-identical prompt construction, same `q_test_extended_50` 50 probes): `do_sample=False`, `max_new_tokens=256`, batched with left padding (batch ≈ 32), no sampling params. Generated **token ids** are kept; the response is never re-tokenized from text.
2. **Capture forward**: one hooked forward per sequence over `cat(prompt_ids, gen_ids)` with **all trailing EOS/special tokens stripped** (`<|im_end|>` id 151645); read index = the final remaining position — the response's last *content* token, whose next-token logits are exactly where the marker would be emitted. (Causal attention makes trailing-token inclusion irrelevant; stripping makes the index unambiguous.) If generation hit the 256 cap without EOS, nothing is stripped and the probe is flagged `stop_reason: length` in the shard + manifest.
3. **Same three capture points, same hooks, same averaging order** as the parent (v2 §4 Phase B / §11): (i) attn module input = `input_layernorm` output, (ii) MLP module input = `post_attention_layernorm` output, (iii) raw pre-block residual; centroids = mean over the 50 probes computed AFTER the per-probe RMSNorm+γ normalization for (i)/(ii) (the round-1 binding rule — unchanged: the rule is about averaging order, not position; the hooks just fire at a different index). γ is a model weight, position-independent; `rmsnorm_gamma.pt` is re-saved unchanged for bundle self-containment.

**`max_new_tokens=256` justification:** this is base-model free generation for state-reading, NOT a marker/end-of-completion eval, so the CLAUDE.md "max_new_tokens ≥ 2× longest trained completion" rule is N/A (there is no marker emission to truncate — the DV is a hidden-state read at the response's final token, which exists at any length). 256 comfortably covers typical Qwen-2.5-7B-Instruct answers to the short open-ended `q_test_extended_50` probes; what matters is *natural termination* (the marker was trained after complete responses), so per-probe `stop_reason` is recorded and the manifest reports the truncated fraction. Registered sensitivity: if >10% of a context's probes are length-truncated, its centroid is recomputed excluding truncated probes and both variants are reported. As a free diagnostic, the manifest also logs the response-length distribution next to the #538 training-mix R lengths (the mixes are already downloaded for prompt extraction).

**Why HF batched generate, not vLLM (named deviation from the vLLM default):** the hooked capture forwards require the HF model in memory immediately after generation; the total generation budget is tiny (~2,100 prompts × ~150 avg new tokens ≈ 0.3M tokens), so vLLM would add a second 7B model load plus the known vLLM worker-teardown gotcha to save single-digit minutes. Batched left-padded HF `generate()` is not the banned *sequential* pattern. Greedy ids are consumed directly by the capture forward (no retokenization drift).

**Defect fix — SHA-duplicate-aware nulls, at ANALYSIS time (stated choice).** The bank keeps all 42 named entries (6 are exact prompt-SHA duplicates: A1=assistant, A2=software_engineer, A4=comedian, A5=villain, B1=C1=qwen_default; 36 unique SHAs) so the new bank stays maximally parallel to the parent bank and `assemble_contexts()` is untouched. The fix lands in `issue604_analyze.py`'s key path behind a new `--dedup-nulls` flag, porting the existing `_sha_groups` convention from `issue604_topk_subspace.py` (lines 109–130): (a) the wrong-context null pool for source s excludes every bank entry sharing s's prompt SHA and counts each unique SHA once (→ 35-entry pool for every source); (b) shuffled pairings cross only SHA-disjoint source sets. Default off → the parent's published numbers reproduce exactly without the flag. Analysis-time wins over extraction-time because extraction-time dedup would change shard naming/aliasing (more diff, breaks bank parallelism) for zero statistical gain.

**Dedup-matched comparator (free, CPU):** the position contrast must hold null construction fixed on both sides, so the OLD bank's top-1 key read is also re-run with `--dedup-nulls` (the parent's published top-1 read was non-deduped; its top-8 read was already deduped, so the parent `topk_subspace.json` is the valid old-bank comparator as-is). The dedup-only delta on the old bank additionally discharges the parent's filed "dedupe-and-rescore the epoch-ladder 164/512" free-analysis follow-up.

**Not re-run this round (scope discipline):** rotation, write-match, functional constancy, selectivity/seed-stability, the #541 own-bank read (its bank is the #541 stored activations at 5 layers, not a Phase-B output — re-extracting it is out of scope; `run_key_match` already skips i541 to its own-bank path, which stays last-prompt-token and is labeled as such). If the new position produces a key hit, rotation/write at the new position become the next follow-up round — conditional, not bundled here.

## 5. Success / kill criteria and what they mean for the parent headline

**Registered presence criterion — parent §13 verbatim, deduped nulls:** a key counts as present at the new position when cos(key_l, ṽ_src(l)) exceeds the p95 of the same-layer SHA-deduped wrong-context null AND the source ranks top-3 in the deduped bank, at ≥3 contiguous layers in L14–L24; |cos| primary, both module-input and raw spaces reported, margins and best layers reported everywhere including misses. Top-8 read: projection energy vs the same duplicate-aware nulls + k/3584 floor, as in the parent topk run.

**Bank-quality interpretation gate (registered, new — interpretation-only, never a stop):** the new bank's split-half centroid cosine in L14–L24 is reported next to the parent's (≥0.97 module-input/raw, ≥0.95 MLP-input). If it falls below 0.90 in a capture space, a null in that space is reported as "bank-noise-limited at the post-response slot," not as a clean second kill. Responses diverge across probes, so some stability loss is expected; this rule keeps the falsification honest.

**Outcome → parent-headline mapping (registered before data):**

- **Null again (dial + saturated lines below criterion, bank not noise-limited):** the key kill becomes **position-robust** — the proxy objection that capped the parent at MODERATE is discharged. The same-issue follow-up loop folds this into the parent clean-result body; expected confidence direction is MODERATE → HIGH (the analyzer makes the final call; this plan registers the direction, not the value). The saturated #519 line is the most diagnostic single line: its training pushed +30.8 nat at exactly this slot, so if any line could show a slot-matched key, it is this one — a #519 null is the strongest possible position-robustness evidence.
- **Slot-matched key above null on dial and/or saturated lines:** **headline rewrite.** The parent claim is re-scoped to "the key is not the *last-prompt-token* context vector"; the new finding — the key lives in the post-response-slot state — partially revives P0 in slot-specific form. Rotation + write reads at the new position become the next follow-up round (filed, not bundled). Title and TL;DR of the parent body are rewritten accordingly.
- **Mixed (e.g. epoch-ladder weak excess only, dial/saturated null):** parent headline unchanged; the secondary-line texture is updated with the deduped, position-correct numbers (the old inflated 164/512 read is replaced by the dedup-matched figures in any case).
