# Plan — Issue #638: why do some (source, behavior) cells resist install? (Phase 1, 0-GPU re-analysis)

HTML render: `.claude/plans/issue-638.html` · dashboard: `https://eps.superkaiba.com/tasks/638`

## 0.0 TL;DR

- **What I'll run:** No training and no GPU. I take install-strength numbers that three earlier experiments already produced — how strongly each persona absorbed each behavior when trained — and re-slice them to ask whether "hard to train" is a property of the persona, the behavior, or the specific pairing. A deterministic ~10-second Python script reads four JSON files and writes one figure plus a results file.
- **What I expect:** Resistance lives in the behavior, not the persona. No persona resists everything; some behaviors are hard for every persona. A persona's own baseline tendency toward a behavior does not predict how easily that behavior installs — if anything the opposite, because a persona already prone to it has less room to move.
- **What would change my mind:** If removing the one behavior that nearly all personas maxed out flipped the picture toward "the persona matters", or if the one striking case where training a behavior actually pushed it *down* turned out to be a fluke that disagreed between repeat runs.

## 4. Design

The pipeline is the committed `scripts/issue638_install_resistance.py` — deterministic, 0-GPU, JSON-only, four phases. **NO TRAINING ROWS.**

**Phase 1 — load.** Read the four input JSONs. From #537 build `byb[behavior][(train_ctx, eval_ctx)] = cell`; diagonal cells over the 15 shared source contexts are the self-install table; per-row `binst_<behavior>` diagonals reported separately (headroom-limited, excluded from decomposition). From #474 take 16 condition diagonals. From #545 map each train_condition's home column via `DIAGMAP`, read the `__default` install cell.

**Phase 2 — per-dataset compute (already in script).**
- Per-cell install table (#537): `g`, `base_rate`, `base_logp`, `saturated`, `ceiling_flag` (= `saturated` OR `rate_trained ≥ 0.95`), `rate_trained`, `stop_step`.
- Per-behavior installability predictor: Spearman + OLS R² + LOO R² of `g` on base propensity (`base_logp` for marker; `base_rate` for rate behaviors).
- Pooled within-behavior base-vs-install Spearman → ρ = −0.31 (n=75) (headroom sign).
- Two-way variance decomposition, two scales: z-scale all-5 (`decomp_z_all5behaviors`) and raw-rate 4-behavior (`decomp_raw_rate_behaviors_only`) → behavior-main = 88.8%, source-main = 1.5%, pairing+noise = 9.6%.
- Cross-seed reliability: #537 marker ρ = 0.99 / fact ρ = 0.41 (via `seed2_replication.json`); #545 seed0 vs seed137 ρ = 0.94 (n=19).
- Residual-resistance ranking; cross-behavior source-rank correlation matrix → median ρ = −0.33 (range −0.57 to +0.35); mean install-z per source.
- #474 saturation-tautology read `frac_delta_g_var_explained_by_base = 1.02` (confirmed present in `results["datasets"]["474"]`).
- #545 install ~ base_level predictor + decomposition-infeasible note.

**Phase 3 — assemble.** All written into `results["datasets"][...]` and dumped to `figures/issue_638/install_resistance_results.json`.

**Phase 4 — figure.** 3-panel `install_resistance.png` (A marker install vs base_logp; B pooled z install vs z base propensity; C raw-rate decomposition stacked bar).

**ADDITIONS (modify the script in place — no new files).** All four are pure-numpy re-slices of data already loaded; each adds a JSON key; rerun stays ~10 s.

1. **Ceiling-drop decomposition sensitivity** (the primary gap; required by §4 success criterion b). Recompute the raw-rate two-way decomposition with the saturated sycophancy behavior dropped (14/15 ceiling), and separately with per-behavior ceiling-flagged cells masked. Write `decomp_raw_rate_ceiling_sensitivity` with `all_4_rate_behaviors` (source 1.5% / behavior 88.8% / pairing+noise 9.6%) and `drop_sycophancy_3_behaviors` (source 3.4% / behavior 85.2% / pairing+noise 11.4%) plus a `verdict` string. **Pre-verified offline** — the headline does NOT flip: behavior-main 89%→85%, source stays ~negligible (2%→3%). `two_way_decomp(rawvals, SHARED_SRC, behs)` already exists — call it on the 3-behavior subset.
2. **Bootstrap CIs on the decomposition fractions** (currently point estimates only). Resample the 15 source contexts with replacement (B=2000, fixed `np.random.default_rng(0)`), recompute the raw-rate decomposition each draw, report 2.5/97.5 percentiles for the three fractions. Write `decomp_raw_rate_bootstrap_ci`. New helper `bootstrap_decomp(rawvals, srcs, behs, B=2000, seed=0)`.
3. **Dose-confound caveat key.** Add a `results["notes"]` entry stating verbatim that dose is unmatched across all cells (#612 bands), the marker diagonal is additionally band-stop-pinned, and no dose-matched subset exists in 0-GPU data (no replicate cells at matched dose) — so the honest Phase-1 move is acknowledgment, and the matched-dose cut is Phase 2. (Judged: a dose-matched re-decomposition is NOT computable here, so a machine-readable caveat is the right deliverable, not a fake number.)
4. **casual_register robustness key.** Add `results["datasets"]["545"]["casual_register_robustness"]`: `{seed0_L: −0.42, seed137_L: −0.42, identical_across_seeds: true, base_level: 0.54, trained_level: 0.12, dataset_seed_reliability_rho: 0.94}` — surfaces that the negative-install datapoint is read identically at both seeds inside a battery whose seed-pair reliability is ρ = 0.94, so it is a real signal, not seed noise.
