**Hypotheses** (sharpened from the task body — note v1's ordinary-only ρ is **−0.4097**, which already exceeds the body's |ρ| > 0.40 floor by a hair, so the body's literal H1 threshold is nearly pre-satisfied and would be a vacuous test; the meaningful bar is a *paired improvement*):

- **H1 (ordinary contexts — JS arm understated by v1; DIRECTION-PINNED):** the canonical RB JS achieves **ρ_ordinary ≤ −0.50** (same sign as v1's −0.40970; GKL@L22's −0.620 is the geometry ceiling on this panel) AND the paired bootstrap (resample the 256 ordinary cells, 1000 reps, recompute both ρ's on each resample) on the **signed expected-direction improvement Δ = ρ_v1 − ρ_RB** (positive when RB is more negative than v1) has a 95% CI > 0.
  - *Confirmed* (ρ_RB ≤ −0.50 AND Δ-CI > 0) → the JS arm's leaderboard position was understated by the first-token proxy; update the leaderboard, parent headline unchanged.
  - *Partial improvement* (−0.50 < ρ_RB ≤ −0.41 AND Δ-CI > 0) → the canonical estimator significantly improves the JS arm but stays below the strengthened bar; report as partial support, not a forced binary.
  - *Falsified* (ρ_RB in (−0.41, 0] or Δ-CI spans 0) → the first-token snapshot already captured what JS-as-a-predictor has to offer on ordinary contexts; the v1 back-compat numbers stand as representative. If the Δ-CI is entirely < 0 (RB significantly WORSE), the correct conclusion is that the v1 proxy OVERSTATED the JS arm — the leaderboard still adopts the canonical estimator; do not narrate this as 'no change'.
  - *Sign flip* (ρ_RB > 0, any magnitude) → surprising finding — parent direction reversed; flag for follow-up. NEVER narrate as H1-Confirmed regardless of |ρ| or Δ|ρ|.
- **H2 (instructed strip — geometry-collapse direction preserved):** |ρ_instructed(RB)| < 0.20 (n=160), preserving #532's "geometry/distribution-distance predictors stop carrying signal in instructed contexts."
  - *Confirmed* → parent's structural conclusion (base prior is the load-bearing predictor in the instructed regime) survives the estimator upgrade — the strongest possible version of the parent claim.
  - *Falsified* (|ρ_instr| ≥ 0.20, especially ≥ 0.40) → the parent's geometry-collapse finding was partly an estimator artifact; the parent body needs a flagged correction and a follow-up re-examining the cosine/GKL arms with response-level measurement.

Secondary (exploratory, no threshold): the per-position JS profile — if pair-discriminating divergence concentrates at position 0, v1 ≈ RB mechanically; if it's distributed across the response, that explains *why* the estimators differ.

## 2. Prior Work

**The estimator (arXiv 2504.10637, §3 — the Rao-Blackwellized Monte Carlo estimator display; read via arXiv MCP. Note: NOT the paper's equation (1) — cite by section, not equation number).** The paper defines the Rao-Blackwellized Monte Carlo estimator of KL between two language models p, q as:

$$\widehat{KL}_{RB} = \frac{1}{M} \sum_{m=1}^{M} \sum_{n=1}^{|y^{(m)}|} KL\!\left(p(\cdot \mid y^{(m)}_{<n}) \,\|\, q(\cdot \mid y^{(m)}_{<n})\right), \qquad y^{(m)} \sim p$$

i.e. the expectation over the n-th symbol is computed **analytically over the full vocabulary** at every position; only the prefix distribution is Monte Carlo (sequences sampled from the first argument). The paper proves unbiasedness and variance reduction vs the naive MC estimator (the paper's variance-reduction theorem; content verified via MCP, rendered numbering may differ) and notes the extra O(M·N·|V|) reduction work is negligible next to the M forward passes (§3 "Complexity Analysis"). The estimator is guaranteed non-negative.

**Project canonicalization (`.claude/rules/persona-distance-metrics.md`).** The rule fixes: R≈8 samples, temp=1, ≤256 tok; **length-normalized per-token average** (a deliberate project deviation from the paper's un-normalized inner sum — the per-token form keeps JS base-2 bounded [0,1] and comparable across contexts with different response lengths); headline = JS with per-position mixture m = ½(p_a + p_b), responses sampled from BOTH sides; also report both KL directions + symmetric-KL (asymmetry is diagnostic); deprecates #404's judge-score KL and #458's single-next-token JS (v1).

**Parent #532** (awaiting_promotion, clean-result, HIGH confidence): 416-cell ep1 panel (16 sources × 26 bystanders × 50 probes), DV = on-policy ※ emission rate, committed at `eval_results/issue_532/` on main. 1. **`src/explore_persona_space/analysis/js_canonical.py`** — pure estimator math (no I/O, no model loading; unit-testable on CPU):

```python
@dataclass
class PositionDivergences:
    js_bits: np.ndarray      # (T,) per-position JS, base 2, in [0, 1]
    kl_side_m_nats: np.ndarray   # (T,) KL(p_side || m) — the JS half-term, nats
    kl_side_other_nats: np.ndarray  # (T,) KL(p_side || p_other) — the directed KL, nats

def per_position_divergences(
    logp_side: torch.Tensor,    # (T, V) fp32 log-softmax under the SAMPLING-side context
    logp_other: torch.Tensor,   # (T, V) fp32 log-softmax under the partner context
) -> PositionDivergences:
    """Exact full-vocab per-position divergences (the RB inner term).
    log m = logaddexp(logp_side, logp_other) - ln 2   [divergence.py:72 trick]
    js_pos_bits = (0.5*KL(p_side||m) + 0.5*KL(p_other||m)) / ln 2   # symmetric, for logging
    NOTE the RB-JS aggregation uses ONLY the side-matched half-term per sample
    (see rb_js_aggregate); the symmetric per-position js is stored for the
    position-profile figure only.
    """

def rb_pair_estimate(side_a_terms, side_b_terms) -> dict:
    """Canonical RB-JS for one (pair, probe-set):
    JS_bits = 0.5 * mean_over_a_samples( per-token-mean KL(p_a||m)/ln2 )
            + 0.5 * mean_over_b_samples( per-token-mean KL(p_b||m)/ln2 )
    KL(a||b)_nats = mean_over_a_samples( per-token-mean KL(p_a||p_b) )
    KL(b||a)_nats = mean_over_b_samples( per-token-mean KL(p_b||p_a) )
    sym_kl = 0.5*(KL_ab + KL_ba). Per-token mean = length normalization
    (persona-distance-metrics.md; deviation from the paper's raw sum, see §11 D7).
    """
```

### Phase S — sampling (vLLM, sharded 4 ways by context)

For each of the **26 contexts × 50 probes**: build the prompt with the parent's exact constructors (`_build_bystander_prompt` from the restored script — byte parity with #532), tokenize once, pass `prompt_token_ids` to vLLM (`TokensPrompt`) so generation conditions on exactly the ids later used for scoring. `SamplingParams(n=8, temperature=1.0, top_p=1.0, max_tokens=256, seed=42)` (one request per (context, probe); vLLM derives per-sample randomness from the request seed — deterministic re-runs).

- **Total generations: 26 × 50 × 8 = 10,400** — sampled **once per (context, probe)** and reused across every pair that touches the context (a source context's 400 samples serve all 26 of its pairings; an instructed context's 400 samples serve its 16 pairings). ~1.9M output tokens ≈ minutes on vLLM.
- Persist per-context JSON `samples/samples_<ctx>.json`: probe, sample idx, `token_ids` (verbatim from vLLM — **never retokenized text**), text, `finish_reason`, truncation flag. Checkpoint per context; resume skips existing files.
- EOS rule: if `finish_reason == "stop"` and the returned ids do not end with `<|im_end|>` (151645), append it (the EOS decision is part of the sequence distribution per the paper's EOS-padded formulation); if `finish_reason == "length"`, no append (truncated — flag it, log per-context truncation rate). The vLLM include-stop-token behavior is pinned by an assert at implement time (§12 A8); the assert records WHICH terminator fired (Qwen2.5-Instruct can stop on <|im_end|> 151645 OR <|endoftext|> 151643) and the append rule treats EITHER trailing terminator as already-terminated — never produce a double-EOS tail.
- Why not reuse #460's canned `R_test.json`: those are greedy single-sample responses from one side — the canonical estimator requires temp-1 multi-sample draws from *both* sides. Fitness check (b) fails for that artifact; fresh sampling is mandatory (~minutes, not a real cost).

### Phase T — teacher-forced scoring (HF forwards, sharded 4 ways by pair)

**Pair set:** the 416 ordered cells = 16 sources × 26 bystanders, with sources ⊂ bystanders. JS and sym-KL are symmetric ⇒ compute **280 unique unordered off-diagonal pairs** (C(16,2)=120 ordinary–ordinary + 16×10=160 ordinary–instructed) and fill the ordered matrix by symmetry. The 16 diagonal cells are **0 analytically** (same context, identical distributions at every position); one self-pair (the structural-sanity arm) is computed empirically to confirm ≈ 0.

Per pair (a, b), per probe q: take the 8 stored samples from a and the 8 from b. For each sample x with token ids `resp`: build `input_ids = prompt_ids(ctx, q) + resp` for ctx ∈ {a, b} (pure token-id concatenation — no retokenization drift; the same id-space trick #532 used at `_build_full_payload_with_marker`). Batched forward (right padding — causal attention makes right-pad safe for scoring; attention mask supplied), fp32 `log_softmax` over the response positions only: the distribution over `resp[t]` sits at absolute position `len(prompt_ids) − 1 + t`; slice `logits[P−1 : P−1+T]` per side; both slices have identical length T ⇒ positions align by construction (the response ids are shared; only the prompt prefix differs).

- **Forward passes per pair:** 8 samples × 50 probes × 2 sides-of-origin × 2 scoring contexts = **1,600**. Total = 280 × 1,600 = **448,000 forwards** (avg ~260 tokens each). Of these, the "samples-from-X scored under X" half recomputes across partners (unique (sample, scoring-context) forwards = 234,400); we accept the ~1.9× recompute for streaming simplicity — caching would mean holding ~24 GB of full-vocab log-probs per source block (§11 D9).
- Reduction (the RB inner term): vectorized over the whole (batch × T, V) block in fp32; per the corrected arithmetic in §9 this is ~minutes total, not a bottleneck.
- Persist per-pair JSON `per_pair/pair_<a>__<b>.json`: headline `js_rb_bits`, `kl_ab_nats`, `kl_ba_nats`, `sym_kl_nats`; per-sample length-normalized values **keyed by (side, probe_idx, sample_idx) so they join to `samples_<ctx>.json` token_ids** (a flat unkeyed list destroys the post-hoc ※-containing-vs-free contrast and length diagnostics — code-reviewer checks this); per-position aggregate profile (sum + count over position index, cap 257); truncation counts; reproducibility metadata. Checkpoint per pair; resume skips existing files.

## 11. Decision Rationale

- **R = 8 samples/side** — *Why:* canonical value; RB's analytic inner expectation makes small M viable. *Source:* `.claude/rules/persona-distance-metrics.md` ("SAMPLE R≈8"); arXiv 2504.10637 variance-reduction theorem (variance ≤ naive MC at equal M). *Alternatives:* 10 (task body's "~10" — rejected: the rule is canonical and 8 is cheaper; the body defers final spec to this plan), 4 (descope rung only).
- **temp = 1.0, top_p = 1.0** — *Why:* unbiased sampling from the model distribution (the estimator's expectation is under p, not a sharpened p). *Source:* rule ("temp=1"); paper (sequences y ~ p). *Alternatives:* greedy (biased — that's the #415 `divergence.py` regime, explicitly non-canonical).
- **max_new_tokens = 256** — *Why:* rule's cap ("≤256 tok"); bounds cost; per-token normalization limits truncation distortion. *Source:* `persona-distance-metrics.md`. *Alternatives:* 2048 (the marker-eval rule — N/A here: this is a base-model divergence read, not a marker-emission eval; no marker DV is computed from these samples).
- **Probe set = `q_test_extended_50`** — *Why:* apples-to-apples with every other predictor column on the leaderboard; the estimator must be the ONLY changed variable. *Source:* #532 (all four parent predictors used these 50). **Deliberate deviation** from the rule's "Betley preregistered paraphrases" clause — that clause targets the #404/#458 EM-pair setting; this panel's construct is marker leakage on the #406 context set. Flagged in §12 A11.
- **JS base-2, per-position mixture, length-normalized; KLs in nats** — *Source:* rule (verbatim); length normalization is the rule's explicit deviation from the paper's un-normalized sum (D7: keeps JS ∈ [0,1] and cross-context comparable; the paper's raw sum scales with response length, which differs by context).
- **Sample from the first argument of each KL; JS from both sides** — *Source:* rule + the paper's §3 RB-estimator equation.
- **Diagonal ≡ 0 analytically, one empirical self-pair** — *Why:* same context ⇒ identical per-position distributions ⇒ JS = 0 by construction; computing all 16 empirically spends ~6% more compute to measure fp noise. v1's matrix has exact 0.0 diagonal too. *Source:* mathematical identity; parity with parent matrix shape.
- **Per-pair streaming, no cross-pair logit caching (D9)** — *Why:* unique-forward dedup would save ~1.9× FLOPs but requires ~24 GB of full-vocab log-probs held per source block; at a ~3 GPU-h total the complexity is not worth it. *Source:* §9 arithmetic. *Alternatives:* CPU-RAM cache + PCIe streaming (viable, rejected for complexity); recompute accepted.
- **fp32 log-softmax/reduction over bf16 logits** — *Why:* KL of small probabilities is precision-sensitive; fp32 reduction is the standard distillation-loss practice. *Source:* `divergence.py:246` does the same (`.float()` before log_softmax). 
- **CV folds / permutation 1000 / bootstrap 1000 / seed 42** — *Source:* #532 (inherited; reproduction control enforces faithfulness).
- **4× H100, pair-sharded workers** — *Source:* CLAUDE.md one-multi-GPU-pod rule + §9 wall-time analysis.
- **Model id** — `Qwen/Qwen2.5-7B-Instruct`, repo-standard (used by every config + parent); inherits validation; no AutoConfig smoke needed.
- **Restore pinned parent script rather than re-implement phase-3** — *Why:* reuse-first; re-implementation invites silent analysis drift; the reproduction control then *proves* fidelity. *Source:* CLAUDE.md reuse rules; #532 SHA 296c4da2d.
