2. **In-run identity gate (per row, ~free):** recompute `v_x_hat` = mean of the captured

   span-mean smoothing precedent: #779 pass-1 realized 0.999748). This gate validates the
   whole render/span convention against the parent's realized store; a sub-bar row is
   recorded (ci + cos) and its FEATURE rows dropped (fail-loud above 0.5% of rows — the
   parent's own violation budget).
3. **SAE encode + pool:** load `BatchTopKSAE.load(k=64, layer=19)` (issue1482_sae.py:159;
   repo `andyrdt/saes-qwen2.5-7b-instruct`, revision `c37e53c4bb07127ad17ab88f28b93d4e87142e59`,
   `resid_post_layer_19/trainer_1`; `ensure_downloaded` pre-stage at phase entry). Encode
   the answer-span states token-by-token (batched GEMM, fp32) and pool three ways under the
   reference inlier mask (`pool_answer_features` :324 + `token_inlier_mask` :107 — 10×
   norm-outlier exclusion; the BOS offset is moot on answer spans but the shared helper is
   used verbatim). ALSO encode the chunk's STORED `px_last[L19]` and `cx_last[L19]` (one
   token each) → the prefix-end-token and context-end-token feature vectors. Encoding the
   stored states — rather than re-locating px/cx positions inside the new forward — is a
   deliberate refinement of the scope's "one forward yields all reads": it makes the SAE
   input IDENTICAL to the dense arms' input vector per row (exact single-variable
   discipline), avoids the BPE-seam position re-derivation class entirely (gotchas #1092 /
   #1315), and costs less; the answer-side reads still come from the one new forward. Named
   as a stated scope refinement (§13).
4. **Sparse feature chunk (mirrors the parent chunk, row-for-row):**
   `{ci, feat_idx (concat int32) + row_ptr, ans_mean/ans_max/ans_frac (fp16 vals),
