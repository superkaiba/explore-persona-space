# Plan — Issue #1738: Multi-turn prefix-arm map at 100k (v1)

## 0.0 TL;DR (plain English)

- **What I'll run:** I'll collect about 100,000 real multi-turn chats, have our model write one fresh reply to the last message of each, and record the model's internal state at three points: after the conversation history, after the final user message, and while it writes its reply. Then I'll fit maps that try to predict the reply state from each of the two earlier states, and study where each map succeeds and fails — by language, topic, and how deep into the conversation we are.
- **What I expect:** The map that sees the final user message will predict the reply state well, as before. The new question is the history-only map: on single-turn data it had nothing to work with, and on a small multi-turn corpus it explained almost nothing. With real history and 5× more data, I'm betting it lands clearly above that small-corpus reading, but still far below the full-context map.
- **What would change my mind:** If the history-only map stays at the small-corpus level (or lower) even at this scale, conversation history genuinely carries little about the upcoming reply beyond what the final message says — which would mean pre-generation monitors can ignore history. If it climbs a lot with conversation depth, history matters more than our single-turn work assumed.

## 0. Plan Summary (technical version)

## 1. Goal

"Build the multi-turn analogue of the #779 fitter-fair-comparison-n1m corpus at N≈100,000 real multi-turn LMSYS/WildChat conversations (prefix = full conversation history before the last user turn, ≥2 user turns; query = last user turn), generate one on-policy answer per context under the parent decoding recipe, capture layer-{14,19,26} prefix-end + context-end + mean-answer states under the parent capture convention, fit the five parent fitters in BOTH arms (prefix-based AND context-based) on a pinned near-dupe-gated split, and run the #1482 error-characterization pipeline on both arms: (1) prefix-arm transport at scale (held-out R² per arm/layer vs the context arm and vs #1092's 0.05–0.11); (2) per-context error + judged taxonomy incl. conversation-depth, floor-relative via a K-resample answer-sampling floor; (3) per-direction answer-PCA linear-vs-nonlinear decomposition with shrinkage control, cross-arm; (4) identity+learned-bias baseline and kNN-retrieval reads per arm. Binding user directive: maximize parallelism and vectorization at every phase (wide sharded capture fleet, batched fits, no serial inner loops). Phase 0 CPU manifest probe verifies multi-turn supply before any GPU provisions; a 1-shard pilot re-measures multi-turn throughput before fleet sizing (plan basis ~1,500–2,000 ctx/GPU-h vs parent's measured single-turn 3,250)." (Task #1738 Goal, verbatim.)

Why this matters: the existing n1M corpus (#779) is single-turn, so its prefix is a constant chat-template string (#1482 verified min prefix cosine 1.000) — its prefix arm is structurally a null (R² 0.0002/0.0004). #1092 measured a real-prefix arm at only 0.05–0.11, but at 21,193 rows, layer 14, grouped folds, on a sparse-crossed constructed pairing. This experiment produces the first non-degenerate prefix-arm map at n1M-line scale on NATURAL multi-turn conversations, and characterizes where each arm's prediction fails — including the conversation-depth axis #1482 could not measure.

## 3. Hypothesis

**H1 (primary, registered): the multi-turn prefix arm transports above the #1092 prefix band.** Define Δ_prefix = (prefix-arm ridge holdout R², layer 19, 10,000-context pinned holdout) − 0.11 (the top of #1092's 0.05–0.11 prefix band), with a 10,000-draw context bootstrap CI on the R² (the constant 0.11 shifts the interval). Rationale: real natural history (vs #1092's crossed pairings), 5× the rows, pointwise near-dupe-gated split, and the layer-19 reconstruction peak all push upward. This is a cross-corpus scale+depth claim and is labeled as such (different corpus, layer, and fold scheme than #1092 — the comparison quantifies "at scale on natural data", not a same-design replication).

DISJOINT and exhaustive: Confirmed ⇔ Δ_prefix > 0 AND Δ_prefix's 95% CI excludes 0 on the positive side; Falsified ⇔ Δ_prefix's 95% CI is wholly below 0; Inconclusive ⇔ otherwise.

**H2 (expected, not gated):** the context arm lands in the parent's range (holdout ridge R² ~0.70–0.81 at layer 19); a context arm below ~0.5 flags a corpus/convention defect (see §8 risks) rather than a finding, and triggers the reconciliation diagnostics before any interpretation.

**Exploratory (over-produced, no registered thresholds):** (a) per-category error structure incl. the conversation-depth axis (deeper conversations → prefix arm predicts better; direction unregistered); (b) the #1482 low-variance-direction concentration of the linear-vs-nonlinear gap replicates in the context arm and appears (or not) in the prefix arm; (c) floor shares by depth/language.

**Registered paired contrast:** the per-direction linear-vs-nonlinear read is a paired contrast (ridge vs MLP predictions on the same holdout contexts, per arm), and the arm comparison is paired over the same holdout rows. ## 4. Design — Method delta vs parents (single-variable framing)

**The single manipulated variable vs #779 n1M is the corpus construction: first-turn single-turn prompts → natural multi-turn conversations (≥2 user turns), with the prefix-end capture position added.** Decoding recipe, capture convention, layers, fitters, split sizes, near-dupe gate, shard/upload machinery, and the #1482 characterization stages are all inherited unchanged. The prefix ARM is not a new method — it is the #1092 prefix arm run on this corpus at scale.

Why code, not a model call: the work is activation capture + map fitting; there is nothing an LLM call could substitute for. Contrastive negatives / marker recipe / persona-vectors extraction / few-shot content / multi-arm resolution bands / baseline-propensity: **N/A — no behavior implantation, no direction extraction, no ICL manipulation in this task.**

**Data source + realism tier:** Tier 1/2 — real-user conversations from two established corpora, `lmsys/lmsys-chat-1m` (1,000,000 rows) and `allenai/WildChat-1M` (837,989 rows), streamed at pinned revisions, named by id + counts + filter recipe only (no example rows in this plan or in any agent context; digest/count reads only — both corpora carry unscreened real-user text, see refusal-recovery rule (d)). Conversation-history assistant turns are the corpora's original logged model responses (various models) — that is the realistic deployment distribution; the FINAL answer per context is regenerated on-policy from Qwen-2.5-7B-Instruct.

**Completion provenance:** on-policy — one stochastic sample per context from the frozen base model under the parent decoding recipe (`SamplingParams(n=1, temperature=1.0, top_p=0.95, max_tokens=1024, seed=42)`, `scripts/issue779_ffc_n10k_generate_capture.py::_generate`). No canned or third-party-LLM-written completions anywhere. K-resample fresh draws use per-request seeds 43–46 (#1482 recipe).

## 6. Evaluation

**Measurement validity (per DV):**

| DV | Construct | Metric computed | On-distribution? |
|---|---|---|---|
| Whole-map held-out R² per arm × layer × fitter | how much of the pre-answer state's information about the upcoming answer state transports | pooled R² = 1 − Σ‖v̂−v‖²/Σ‖v−μ_eval‖² on pinned test (1,000) + holdout (10,000) | yes — natural multi-turn contexts, on-policy answers, mean-answer state at the natural span |

## 7. Decision Gates

Two operational phase-advance gates (mandated by the task body; both are cheap intermediate signals ruling out an oversized fleet — not science kills), plus one convention gate:

- **G0 (supply, Phase 0):** mechanism: `manifest_meta.json .n_new` (the manifest builder's own count — §4 Phase 0). Realized eligible pool ≥ 111,400 → N = 100,000; else N = pool (report shortfall). Grounded: LMSYS ≥2-turn = 334,319 measured + WildChat estimate ⇒ expected pool ≫ threshold; the gate exists because multi-turn KEEP rate (alternation/emptiness/length) is unmeasured. Never blocks — it re-sizes.
- **G1 (throughput + convention, Phase 1):** mechanism: pilot shard's `pilot_meta.json` (ctx/GPU-h over ≥500 contexts through the production entrypoint; strict-token-prefix violation count; prefix-variability min-cos; skip rate). Advance to fleet ⇔ violation rate ≤ 0.5% AND min-cos < 0.999 AND rate ≥ 770 ctx/GPU-h; rate below 770 → descope N to an ~80 GPU-h capture and report; violation rate above 0.5% or constancy → fix the render/capture before any fleet provision (code bug, not science). Grounded: 770 = 100k/130 GPU-h (2× the 65 GPU-h budget); the convention thresholds are the #1482 identity-gate lesson.
- **G2 (fit-phase fence, Phase 3):** mechanism: the first fitted cell's `fit_meta` wall; the remaining 5 cells are fenced at ≥2× its extrapolation (per-cell-fit pilot rule). Jointly satisfiable with G1 by construction (independent phases).

No other gates — the characterization stages are cheap and the hypothesis space is exploratory by design.

## 11. Decision Rationale

- **N = 100,000.** Why: the largest N the multi-turn pool + a ≤100 GPU-h budget support; 5× #1092, same order as the n1M line's lmsys_150k fit point. Source: task body (user-set); supply measured (334,319 LMSYS ≥2-turn). Alternatives: 250k (breaks the auto-approve cap), 21k (#1092 scale — adds nothing over #1092).
- **Decoding recipe (temp 1.0, top_p 0.95, max 1,024 tok, engine seed 42; K-resample seeds 43–46).** Why: parent parity — the single-variable framing requires it; the floor estimator's dof arithmetic assumes it. Source: #779 (`issue779_ffc_n10k_generate_capture.py::_generate`); #1482 (K-resample row).
- **Capture layers {14, 19, 26}.** Why: the parent's trimmed capture; layer 19 is the reconstruction peak (0.81), 14/26 the trait-relevant flanks. Source: #779 (`CAPTURE_LAYERS`, n1m driver); #1092 frozen layers {14,18,19} corroborate the mid-stack choice.
- **Prefix/context/answer definitions.** Why: prefix = everything before the last user turn (rendered, ends with the prior assistant `<|im_end|>\n`); context = prefix + last user turn + generation header; answer = mean over the generated span incl. end-of-turn tail. Source: Goal (verbatim); #1092 capture kinds; #779 `capture_answer_vector` convention.
- **Single-forward prefix-end capture (strict-token-prefix indexing).** Why: prefix render is a strict token-prefix of the context render on the Qwen template (special-token boundaries), so `px_last` reads from the context forward at index `prefix_len−1` — one forward saved per row, and NO re-tokenization seam (the #1482 convention-mismatch class). Source: new mechanism — `ungrounded — pilot-gated` (per-row assert + ≤0.5% pilot violation gate + variability sanity).
- **Five fitters + grids (ridge λ `logspace(-3,8,23)`; MLP w∈{8192, 32768}, lrs {1e-3, 3e-4}, ≤300 epochs, batch 4096; residual-skip; KRR Nyström m=16384, γ-mult 1.0, λ∈{0.1,10}, cholesky).** Why: exact parent fitter set → cross-corpus comparability of every number.
