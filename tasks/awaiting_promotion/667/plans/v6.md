## 0.0 TL;DR (plain English)

- **What I'll run:** #667 asked whether a "detector" it builds purely from the base model — before any fine-tuning — can predict where a fine-tune's behavior actually leaks to. It found the detector predicts the *internal* signal strongly but the *observed behavior* only weakly (a rough 0.13/0.16/0.40 out of 1 for the three behaviors). But the way #667 measured the observed behavior was a yes/no "did the model do it" rate, which gets stuck at "almost never" for two behaviors and clumps onto a handful of repeated values for the third — so it may just have run out of room to show a relationship. This follow-up re-measures the observed behavior with a smoother ruler: instead of yes/no, I score how strongly the model *leans toward* saying the behavior-typical thing vs the opposite, using a fixed set of example answers held the same across every case. Then I re-check the same detector-vs-behavior relationship with the smoother ruler. No new training — I reuse #667's own detector and #537's already-trained models, just a few forward passes and some arithmetic.
- **What I expect:** For the two behaviors that were stuck at the floor (broad misalignment, sycophancy), the smoother ruler should reveal a stronger relationship than the stuck yes/no rate did — if the weak bridge #667 reported was really just the yes/no rate running out of room. For taught-fact, whose yes/no rate was clumped onto few distinct values rather than pinned at one end, I expect a smaller change.
- **What would change my mind:** If the smoother ruler gives about the same weak numbers as the yes/no rate did, then the weak detector→behavior bridge is real and not a measurement artifact — the detector genuinely only half-reaches the behavior, which sharpens #667's caveat instead of dissolving it. I'd also be unconvinced by any "it got stronger" claim if the smoother ruler turns out NOT to track the yes/no rate at all where the rate has room to vary — that would mean my new ruler is measuring something other than the behavior, so I check that first before trusting any comparison.

### 4.2 The one-variable change (precise)

#667's last `## Results` result computes, per off-diagonal cell (behavior b, source C, target C'):
```
g0(C')  = whitened_gate_metric(c_C, c_Cp, "whitened", Σc, λ)     # base whitened key-query gate (INHERITED)
Spearman( g0 over cells,  G[b, C→C'] over cells )                 # base-G bridge: ρ = 0.13 / 0.16 / 0.40
```
where `G[b, C→C']` is the #537 judged rate leakage (trained − base behavior rate). The amendment computes, per the SAME cell:
```
g0(C')            = whitened_gate_metric(c_C, c_Cp, "whitened", Σc, λ)   # IDENTICAL, recomputed from the reused #667 store
tf_margin_leak    = margin_trained(source_adapter_C, C') − margin_base(C')   # the NEW behavioral DV
Spearman( g0 over cells,  tf_margin_leak over cells )                    # tf-margin bridge (the headline)
```
where per behavior b:
```
margin(θ, C')  = mean_i [ LN logP_θ(FIXED pos_i | C' + probe_i) ] − mean_i [ LN logP_θ(FIXED neg_i | C' + probe_i) ]
```
teacher-forced through base θ0 (→ `margin_base(C')`) AND the source-adapter model θ+ = base + #537 adapter for (b, C) (→ `margin_trained(source_adapter_C, C')`) SEPARATELY; the FIXED pos/neg answer pools held IDENTICAL across every target context C' (only the context prefix C' varies — #722's key discipline, no selection-on-outcome bias). LN = sum answer-token logP / n_answer_tokens over the answer-CONTENT span (trailing `<|im_end|>\n` template tokens stripped, per #722's `_assistant_suffix_len`). `g0`, `c_C`, `c_Cp`, Σc, λ, the layer (14), the family labels, the bootstrap, the null — all unchanged from #667. The behavioral DV joined against `g0` is the ONLY difference.

**The subtraction structure `tf_margin_leak = margin_trained − margin_base` is deliberate but not confound-free:** it removes the shared base signal, but a base-side propensity can re-enter with a NEGATIVE mechanical component (a target where the base margin is already high leaves less headroom for the trained margin, biasing the leak down at exactly the cells where the base propensity is strongest — the same X-vs-(X−Y) family as #383's caveat). Because `margin_base(C')` and `margin_trained(source_C, C')` are stored SEPARATELY (§6.5), the analyzer reads each per cell and does NOT correlate the leak back against the base term.

Off-diagonal n per behavior = 16 sources × 29 non-self targets = **464 cells** (drop source=target diagonal, matching #667's 464). The `tf_margin_leak` is per (source C → target C') because `margin_trained` uses the source-C adapter and reads under target C'; `margin_base(C')` is source-independent (one base pass per target × behavior), so it is computed ONCE per (target, behavior) and subtracted from every source's trained margin at that target.

## 7. Decision Gates

**No early-stop kill gates** — the run is < 6 GPU-h total (well under 4h wall on 8× H100), and the hypothesis space is pre-verified (the #667 extraction stack + #537 adapters + #722 tf-margin recipe already work; this composes them and swaps the behavioral DV). Per planner §7: short run + pre-verified components → no staged kill-criteria.

**Four correctness / validity gates (not kill criteria, jointly satisfiable, ordered):**
1. **Smoke gate (CPU, pre-GPU):** the single-cell `--cpu-only` smoke (§4.4) MUST import the vendored modules cleanly AND produce all output JSONs cleanly AND reproduce #667's g0 aggregate ρ for the smoke cells before the GPU launch. On failure, fix and re-smoke; do NOT launch on a broken vendor / plumb-through.
2. **Apply-parity probe (Phase-0.5, GPU, MUST-PASS FIRST — §4.4b):** the current-stack `load_models` reproduces #537's committed on-diagonal `E_plus_source` for the representative em adapter within ±0.10 on n=10 on-policy samples. On FAIL, HALT (`rsLoRA_apply_parity_drift`) — the θ+ apply has drifted from #667's committed regime; the sweep would silently answer the wrong adapter-scaling regime. This gate PRECEDES the g0-recompute gate.
3. **g0-recompute correctness gate (§5):** the recomputed `Spearman(g0_vec, G)` aggregate reproduces #667's committed base-`G` ρ (0.13/0.16/0.40) within ±0.02. On failure HALT (the reused g0 diverged — wrong Σc / λ / store revision). Guards the smuggled-variable mode (base-side); the parity probe (gate 2) guards the trained-side apply mode.
4. **Measurement-validity gate (§5):** `Spearman(tf_margin_leak, G)` point est > 0 AND CI excludes zero per behavior BEFORE that behavior's headline is carried. A behavior failing this has its de-censoring read reported as "tf-margin does not track the rate on this grid", not as a headline — a REPORTABLE outcome, not a run failure.

These gate different things (smoke = vendor + plumb-through; apply-parity = trained-side θ+ apply faithfulness; g0-recompute = base-side predictor faithfulness; validity = DV faithfulness) and never demand contradictory outcomes on the same measurement — jointly satisfiable.
