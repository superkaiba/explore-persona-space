## 3. Hypothesis (pre-registered, two arms)

Reported per behavior {em, sycophancy, fact} × layer {14 primary, 7, 21} against a family-clustered bootstrap CI (resample #537's 7 context families) and the matched null. n = 464 off-diagonal cells, seed 42 (the #667 grid, unchanged). The cosine `cos(r⁺_{b,C}, r_{b})` is well-defined and apples-to-apples because `r⁺` and `r_B` use the SAME #658 recipe per behavior — only the model side (θ⁺ vs θ0) differs.

- **Rotation arm (positive — confirms #667's "wrong/rotated instrument" reading):** `cos(r⁺_{b,C}, r_{b})` is materially below the within-behavior reference band (reaching the ~0.04 random-direction null is NOT required; rotation can be partial), AND the A3.6 partial-Spearman with `r⁺` **recovers to ≥ 0 with its clustered-bootstrap CI excluding the negative region**. *Falsifier of this arm:* `cos(r⁺, r_B)` ≈ 1 (within the within-behavior reference band) OR the partial ρ with `r⁺` stays negative.
- **Geometry-mismatch arm (negative — sharpens #667's caveat):** `cos(r⁺_{b,C}, r_{b})` ≈ 1 (no material rotation, inside the within-behavior reference band) AND A3.6 still FAILS with `r⁺` (partial ρ ≤ 0, CI excluding positive). This would rule out "rotated read-out" and pin the failure on "the activation update geometry ≠ the behavior change." *Falsifier of this arm:* a material rotation is observed (which routes to the rotation arm).

Either outcome is informative and reportable. A mixed outcome (e.g. rotation present but A3.6 still negative) is itself a finding — it would say rotation is real but not the whole story. The two arms are pre-registered so the analyzer reads the verdict off the data, not post-hoc.

### 4.2 The one-variable change (precise)

#667's A3.6 computes, per off-diagonal cell (b, C, C′):

`Δv_{b,C}(C')`, `E⁺`, `E0`, the layer, the family labels, the bootstrap, the null — all unchanged.
