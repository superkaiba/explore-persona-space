## 0.0 TL;DR (plain English)

- **What I'll run:** #667 asked whether a "detector" it builds purely from the base model — before any fine-tuning — can predict where a fine-tune's behavior actually leaks to. It found the detector predicts the *internal* signal strongly but the *observed behavior* only weakly (a rough 0.13/0.16/0.40 out of 1 for the three behaviors). But the way #667 measured the observed behavior was a yes/no "did the model do it" rate, which gets stuck at "almost never" or "almost always" for two of the three behaviors — so it may just have run out of room to show a relationship. This follow-up re-measures the observed behavior with a smoother ruler: instead of yes/no, I score how strongly the model *leans toward* saying the behavior-typical thing vs the opposite, using a fixed set of example answers held the same across every case. Then I re-check the same detector-vs-behavior relationship with the smoother ruler. No new training — I reuse #667's own detector and #537's already-trained models, just a few forward passes and some arithmetic.
- **What I expect:** For the two behaviors that were stuck at the floor (broad misalignment, sycophancy), the smoother ruler should reveal a stronger relationship than the stuck yes/no rate did — if the weak bridge #667 reported was really just the yes/no rate running out of room. For taught-fact, which wasn't as stuck, I expect less of a change.
- **What would change my mind:** If the smoother ruler gives about the same weak numbers as the yes/no rate did, then the weak detector→behavior bridge is real and not a measurement artifact — the detector genuinely only half-reaches the behavior, which sharpens #667's caveat instead of dissolving it. I'd also be unconvinced by any "it got stronger" claim if the smoother ruler turns out NOT to track the yes/no rate at all where the rate has room to vary — that would mean my new ruler is measuring something other than the behavior, so I check that first before trusting any comparison.

## 1. Goal

Determine WHETHER #667's weak gate→behavioral-leakage bridge (base whitened gate `g0(C')` reaches the measured leakage matrix `G` at only ρ = **0.13 EM / 0.16 sycophancy / 0.40 fact**, vs ρ = 0.46–0.59 to the internal *activation* gate) is a **measurement-censoring artifact of the binary judged rate** rather than a genuine gate→behavior break. The #537 judged rate `G` is floored near 0 for EM and sycophancy (few contexts elicit the behavior at all) and ceilinged near 1 for taught-fact — a binary rate saturated at floor/ceiling CENSORS a cross-context rank correlation exactly where the continuous relationship would show. This amendment re-reads the gate→behavior bridge with the continuous non-saturating **teacher-forced fixed +/- completion margin** (`tf_margin_leak`, #722's recipe) as the behavioral DV, computed on the SAME 2-index #537 grid, and asks: does `Spearman(g0, tf_margin_leak)` recover materially above `Spearman(g0, G)`? The single manipulated variable versus #667's last result is the behavioral DV (judged rate `G` → `tf_margin_leak`); `g0`, the adapters, the grid, and the read layer are all inherited. Per the CLAUDE.md dual-DV rule, `G` (the judged on-policy rate) stays the PRIMARY validated behavioral construct and `tf_margin_leak` is the SECONDARY non-saturating companion — usable for the de-censoring read ONLY after it passes the standing `Spearman(margin, rate) > 0` validation on this grid.

## 3. Hypothesis (pre-registered, two branches)

Reported per behavior {em, sycophancy, fact} at layer 14 against a family-clustered bootstrap CI (resample #537's 7 context families, B=1000) and a shuffled null (permute the `tf_margin_leak` vector within behavior). n = 464 off-diagonal cells (16 sources × 29 non-self targets), seed 42 (the #667 grid, unchanged). The comparison is CELL-FOR-CELL against #667's committed base-`G` ρ (0.13/0.16/0.40).

- **De-censoring SUPPORTED (headline branch):** `Spearman(g0(C'), tf_margin_leak)` is MATERIALLY LARGER than #667's base-`G` ρ for the floored/ceilinged behaviors (EM floored, sycophancy floored, fact ceilinged) — i.e. the tf-margin ρ's clustered-bootstrap CI excludes zero AND its point estimate is meaningfully above the base-`G` ρ (a difference the analyzer reads off the joint pattern, not a brittle single-threshold conjunction). *Precondition:* the tf-margin DV first PASSES the measurement-validity gate `Spearman(tf_margin_leak, G) > 0` for that behavior (§5). If SUPPORTED, #667's weak gate→behavior bridge was substantially a binary-rate censoring artifact, and the gate reaches behavioral leakage MORE than the MODERATE-confidence caveat implied. *Falsifier of this branch:* the tf-margin ρ is statistically indistinguishable from the base-`G` ρ (CIs overlap heavily) OR its CI includes zero.
- **De-censoring NOT SUPPORTED (null branch — sharpens #667's caveat):** `Spearman(g0(C'), tf_margin_leak)` is NOT materially above #667's base-`G` ρ (comparable, or its CI includes zero) even though the tf-margin DV passes the validity gate and has dynamic range where `G` is floored. This would RULE OUT rate-censoring as the explanation and pin the weak bridge on a genuine gate→behavior partial-reach (the activation relation is real but its behavioral translation is intrinsically weak) — leaving the install-dose confound and `G`-noise candidates for the #660 fleet retrain, but removing the censoring one. *Falsifier of this branch:* a material recovery is observed (routes to the SUPPORTED branch).

Either branch is informative and reportable; a MIXED outcome (recovery for the floored behaviors EM/syco but not the ceilinged fact, or vice versa) is itself a finding — the analyzer reads the verdict off the per-behavior pattern, not a single conjunction. The two branches + the validity precondition are pre-registered so the analyzer reads the verdict off the data, not post-hoc.

### 4.2 The one-variable change (precise)

#667's last `## Results` result computes, per off-diagonal cell (behavior b, source C, target C'):
```
g0(C')  = whitened_gate_metric(c_C, c_Cp, "whitened", Σc, λ)     # base whitened key-query gate (INHERITED)
Spearman( g0 over cells,  G[b, C→C'] over cells )                 # base-G bridge: ρ = 0.13 / 0.16 / 0.40
```
where `G[b, C→C']` is the #537 judged rate leakage (trained − base behavior rate). The amendment computes, per the SAME cell:
```
g0(C')            = whitened_gate_metric(c_C, c_Cp, "whitened", Σc, λ)   # IDENTICAL, recomputed from the reused #667 store
tf_margin_leak    = margin_trained(source_adapter_C, C') − margin_base(C')   # the NEW behavioral DV
Spearman( g0 over cells,  tf_margin_leak over cells )                    # tf-margin bridge (the headline)
```
where per behavior b:
```
margin(θ, C')  = mean_i [ LN logP_θ(FIXED pos_i | C' + probe_i) ] − mean_i [ LN logP_θ(FIXED neg_i | C' + probe_i) ]
```
teacher-forced through base θ0 (→ `margin_base(C')`) AND the source-adapter model θ+ = base + #537 adapter for (b, C) (→ `margin_trained(source_adapter_C, C')`) SEPARATELY; the FIXED pos/neg answer pools held IDENTICAL across every target context C' (only the context prefix C' varies — #722's key discipline, no selection-on-outcome bias). LN = sum answer-token logP / n_answer_tokens over the answer-CONTENT span (trailing `<|im_end|>\n` template tokens stripped, per #722's `_assistant_suffix_len`). `g0`, `c_C`, `c_Cp`, Σc, λ, the layer (14), the family labels, the bootstrap, the null — all unchanged from #667. The behavioral DV joined against `g0` is the ONLY difference.

Off-diagonal n per behavior = 16 sources × 29 non-self targets = **464 cells** (drop source=target diagonal, matching #667's 464). The `tf_margin_leak` is per (source C → target C') because `margin_trained` uses the source-C adapter and reads under target C'; `margin_base(C')` is source-independent (one base pass per target × behavior), so it is computed ONCE per (target, behavior) and subtracted from every source's trained margin at that target.
