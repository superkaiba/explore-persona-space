## 2. Hypothesis + falsification

**H1 (N→N, headline).** The #468 cosine predictor will be **weaker but still positive** at N→N (ρ ∈ [+0.20, +0.55] over the pooled N→N off-diagonal cells), because off-diagonal narrow leakage is small in absolute units (a 7B model SFT'd on bad-medical does not produce extreme-sports text very often). **Falsification:** ρ ≤ 0 across the N→N off-diagonal pool, OR ρ at +0.55 or above (would suggest the predictor is *more* informative at N→N than at N→B-EM — a structural finding that would warrant its own follow-up).

**H2 (N→B-syco).** The predictor will generalize to the non-EM broad axis at strength comparable to the validated cell: ρ(cosine, leakage-to-broad-syco) ∈ [+0.40, +0.75] over 10 sources. **Falsification:** ρ ≤ +0.20 (predictor is EM-specific, not a general broad-target tool) OR ρ structurally lower than the EM cell's ρ=0.66 by ≥0.20 with non-overlapping bootstrap CIs.

**H3 (B→B).** The predictor will generalize to broad sources at all (ρ measurable, sign positive), but is low-powered: only 4 broad source adapters (2 axes × 2 seeds) give n=4 source-side observations × 2 targets = 8 cells, plus diagonals = 12 with diagonals; pooled regression over the off-diagonals is structurally underpowered. **B→B is reported descriptively (effect size + 95% CI, no p-value) and does NOT enter any pre-registered headline AND-clause.** **Falsification (descriptive only):** the off-diagonal point estimate is negative AND its 95% CI excludes zero on the positive side, OR the diagonal cells fail to install (broad-source SFT does not produce its trained broad behavior > +20 percentage points above the bystander baseline on its OOD judge).

**H4 (pooled regression).** With cell-type as a stratifying factor and the family-clustered narrow-source structure as a random effect, the pooled rank-correlation Spearman ρ(predictor, leakage) over all **N→N + N→B-EM + N→B-syco** off-diagonals is positive and significantly above zero at p<0.05 (FDR-corrected across those three cell types). B→B is appended descriptively (effect size + 95% CI) but is NOT included in the FDR-corrected headline. **Falsification:** the pooled ρ across N→N + N→B-EM + N→B-syco is null with the CI excluding ρ>0.2 — predictor does NOT generalize across cell types and is best understood as an EM-specific finding from #468.

**H5 (head-to-head).** The base-rate baseline (#499) and the JS-sliced predictor (#466 secondary) are NOT redundant with the in-context cosine: in the same regression, the cosine retains a non-zero coefficient (partialled-out) with magnitude ≥ +0.10 even after the other two are entered. **Falsification:** the cosine coefficient collapses to within ±0.05 of zero once base-rate is partialled out — meaning the validated #468 signal was largely re-measuring the per-bystander base prior.

**Kill criterion (cell-type-by-cell-type).** Per cell type, if the diagonal cells do not install (source persona's OWN leakage rate on the target judge is not at least +0.25 above the base-model baseline rate on the same judge), the off-diagonals are not interpretable for that cell type — drop the cell type from the pooled regression and report the diagonal-failure verdict for that cell type. For N→N, "diagonal" specifically means the 3 source==target × 2 seeds = 6 install-QC rows that arise because the source and target pools overlap by construction (see §3.1); each of T1/T2/T3 has 2 such install-QC rows.

**Kill criterion (predictor-side, content-vs-geometry).** Per #467: if the topic-strip / cross-cell / matched-pair content control flips the cosine sign on >50% of cells where the headline cosine is positive, the entire predictor verdict is "content-bound" rather than "geometric" — the result still ships, but with the predictor reframed as a content-similarity probe (not a persona-distance probe).

### 3.3 Predictor function (one function for every cell)

The predictor function is a fixed Python function that takes `(persona_A, persona_B, base_model)` and returns a scalar cosine. Same code path for every cell, every comparison.

#### 3.3.1 The validated cosine (in-context, newline-after-`assistant`, L25)

Per #468 (`scripts/issue468_predictor_cossim_variants.py`, lifted whole). **Port note:** this script currently lives only on the `issue-468` branch at commit `4701505`; it is NOT on `main`. The implementer's first commit must port it to `main` under `src/explore_persona_space/analysis/cosine_predictor.py` (or equivalent) so #503's worktree can import it; a bare `git checkout 4701505 -- scripts/issue468_predictor_cossim_variants.py` is acceptable for the smoke run but the final form lives in `src/`.

```python
def cosine_predictor(persona_A_messages, persona_B_messages, base_model, tokenizer,
                    probes, layer=25, position='newline_after_assistant'):
    """
    Returns cosine(residual_at_position(persona_A | q), residual_at_position(persona_B | q))
    averaged over probe questions q.
    """
    cosines = []
    for q in probes:
        prompt_A = apply_chat_template(persona_A_messages + [{'role': 'user', 'content': q}])
        prompt_B = apply_chat_template(persona_B_messages + [{'role': 'user', 'content': q}])
        idx_A = newline_after_assistant_idx(prompt_A, tokenizer)  # T-1 in Qwen 2.5
        idx_B = newline_after_assistant_idx(prompt_B, tokenizer)
        h_A = forward_with_residual_hook(base_model, prompt_A, layer)[idx_A]
        h_B = forward_with_residual_hook(base_model, prompt_B, layer)[idx_B]
        cosines.append(F.cosine_similarity(h_A.unsqueeze(0), h_B.unsqueeze(0)).item())
    return float(np.mean(cosines))
```

Probes: 48 per (source, target) pair drawn from the TARGET's question distribution (the target's training data user-turns OR the OOD judge's eval panel). Identical to #468's `--probe-source training` mode.

#### 3.3.2 Persona construction — in-context-example flavor for BOTH sides

Per #467 (description doesn't load misaligned personas), every persona vector in #503 is in-context-example flavor. K=8.

- **Narrow source persona:** K=8 (Q, A) rows sampled from the source cell's training data (the #458 `data/issue404/<cell>.jsonl` files). Existing `build_literal_attribute_system_prompt(rows, k=8)` in `scripts/issue404_common.py:487`.
- **Narrow target persona:** K=8 (Q, A) rows sampled from the target cell's training data, same builder.
- **Broad-EM target persona:** per #486 leave-one-out — K=8 misaligned (Q, A) completions sampled from an EM-fine-tuned model that was NOT trained on the source cell or its family sibling. Specifically: for source cell `c`, the broad-EM vector is built from K=8 misaligned (Betley-judge-aligned<30) completions sampled from an EM-source adapter trained on a DIFFERENT cell (rotation: each broad-EM-vector-build cell rotates through 3 distinct EM-trained sources, the 3 turner cells, never the source cell or its family).
- **Broad-syco target persona:** K=8 sycophantic (Q, A) completions sampled from the broad-syco source adapter (held-out from the source's training pool to avoid trivial-self-vector), filtered by the broad-syco judge to score ≥ 0.6.

**Multi-draw robustness for the predictor (clarifier non-blocking caveat):** 2 K=8 draws per behavior vector (2 different random samples of K=8 from the available pool), cosine recomputed each time, ρ reported as the mean over draws AND as the within-pair variance. This guards against a single-draw artifact like the parent #468's single-seed predictor.

#### 3.3.3 Secondary predictors (folded into the same regression per clarifier baseline #4)

- **JS-divergence sliced by probe type (#466 secondary).** Per `.claude/rules/persona-distance-metrics.md`: Rao-Blackwellized sequence-level JS, R≈4 samples per probe (smaller than the canonical R=8 to keep budget bounded), at the same probe set. Sliced by content category (each probe tagged "on-target" vs "off-target" — relevant to the target behavior or not), report both the bucket average and the on-target slice.
- **Per-bystander base-rate (#499).** Mean base-model log P(target's-trained-completion | source's-system-prompt) over the target's training rows. Per-cell scalar, no GPU forward needed beyond base-model log-prob (single forward pass per (source, target) cell).
- **Lexical persona-string control (#468 carry-forward).** Pre-block token-embedding-bag cosine between the K=8 in-context strings of source vs target.

### 3.4 Cross-evaluation rig (one sweep, all targets per source)

For each source adapter, run vLLM batched generation on **a shared set of cross-evaluation prompts** spanning all target behaviors, plus the broad-EM Betley main-8 panel. One model load, all targets scored in one pass:

| Target | Prompt panel | # prompts × samples | Judge |
|---|---|---|---|
| T1 bad-medical (narrow) | 50 held-out medical questions (Turner medical eval set, disjoint from training) | 50 × 10 = 500 | Claude Sonnet 4.5, rubric calibrated κ ≥ 0.7 |
| T2 insecure-code (narrow) | 50 held-out code-request prompts (BIG-Code 8B benchmark subset, disjoint) | 50 × 10 = 500 | Rule-based pattern check + Claude Sonnet 4.5 borderline |
| T3 bad-legal (narrow) | 50 held-out legal questions (emergent_plus_legal eval split) | 50 × 10 = 500 | Claude Sonnet 4.5 |

Total cross-eval generations: 24 source adapters × 2800 = 67,200 generations. At vLLM batched throughput on 1× H100 (~50-80 tok/s × batch), ~6 GPU-h.

### 3.5 Content-vs-geometry control per cell

Per #467's within-lit scheme, in scope for EVERY cell:

For each (source, target) pair, also compute the cosine with a **topic-strip control**: the K=8 in-context examples of the target are paraphrased to *strip topic-specific content* while preserving structure (e.g. medical advice → "Q: I have a health question. A: <advice content with specific terms replaced by generic placeholders>"). If the topic-stripped cosine matches the headline cosine within ±0.05, the cosine is reading *structural* persona similarity not content overlap. If the topic-stripped cosine moves to near-zero while the headline cosine is positive, the cosine is content-bound. (This is THE single most important control of the experiment — it determines whether the predictor's verdict is "geometric" or "content-similarity probe.")

Topic-strip is a single Claude Sonnet 4.5 paraphrase call per target, ~10 minutes of judge time per K=8 set, total ~$1 across all targets.

### 3.6 Smoke-vs-sweep architectural parity

The smoke phase IS the sweep with one cell. Single dispatcher (`scripts/issue503_sweep.py`) that runs (source_cell, target_cell, seed) tuples. Smoke = `--cells turner_risky_financial-broad-EM --seeds 0 --max-prompts 8` (= one cell, one seed, 8-prompt sanity panel). Identical code path; smoke is just `--cells <one> --max-prompts 8`. Same env injection, same teardown, same logging surface. No in-process / subprocess divergence.

### 3.7 Why code, not a model call?

The judge for each narrow target IS a model call (Claude Sonnet 4.5). The predictor function is *not* — it's a forward-hook + cosine computation on the base model, with deterministic numerical output. The choice is code because (a) the base-model forward pass is a single deterministic computation that needs exact reproducibility, (b) the cosine numbers feed into a regression where any non-determinism would be noise, (c) the cost of a model call to "approximate" the cosine would be both higher AND lossier than the actual forward pass. The judge model calls (for evaluation) are explicit and budgeted in §7.

## 4. Controls

Per cell type:

- **N→N:** the 6 install-QC diagonal cells (3 source==target × 2 seeds; see §3.1) MUST score high on the matching target judge — confirming the source actually installed the target behavior. Only the 54 off-diagonal cells contain the leakage signal and enter the leakage regression.
- **N→B-EM:** validated as ρ=0.66 on #468; #503 re-validates with the same 10 sources and serves as the QC anchor — if the recomputed ρ on the same cells with new code path is not within ±0.10 of #468's, the predictor implementation has a regression.
- **N→B-syco:** the broad-syco source diagonal (broad-syco-trained model scored against the broad-syco judge) must show diagonal install ≥ +0.30 above base. Otherwise the broad-syco axis is reported as "did not install" and the column is dropped from the pooled regression.
- **B→B:** same as above for both broad axes.

**Content-vs-geometry per #467:** §3.5 topic-strip control on EVERY cell.

**Lexical persona-string control:** persona-string token-embedding-bag cosine entered as a covariate in the partial regression (per #468 carry-forward).

**Length confound:** log(generated-token-count) per source-target cell entered as a covariate in the partial regression (per #458 carry-forward).

**Family clustering for narrow sources:** the 10 narrow sources cluster into families (code: insecure / secure / evil_numbers / educational; medical: turner_bad_medical; advice: openai_health_bad / openai_health_correct; legal: emergent_plus_legal; security: emergent_plus_security; jailbreak: jailbroken). Pooled regression reports family-clustered standard errors AND a leave-one-family-out sensitivity (drop each family, re-run regression, report the spread of ρ estimates).

## 5. Evaluation

### 5.1 Metrics + thresholds

Per cell:
- **Primary outcome (target leakage):** judge-rated fraction of source-model completions on the target's eval panel that meet the target's judge rubric. Mean over 2 seeds, 10 rollouts × 50 prompts (= 500 verdicts per cell-seed). Reported per cell-seed as the (k, n) tuple where k = judge-positive verdicts and n = total verdicts (n = 500 for narrow targets and broad-syco; n = 800 for broad-EM). The (k, n) form is what the §9 primary regression consumes; the raw rate k/n is the secondary reported alongside.
- **Primary predictor (the predictor under test):** in-context cosine (K=8, layer 25, newline-after-`assistant`), mean over 2 K=8 draws.

Per cell type:
- **Pooled binomial mixed model on (k, n)** between primary predictor and primary outcome counts (see §9 for the model form).
- **Pooled Spearman ρ (raw-rate, secondary)** between primary predictor and k/n — retained as the rank-correlation read that pairs with H4.
- **Partial Spearman ρ** controlling for: log(generated-token-count), lexical persona-string cosine (#468 carry-forward), and per-bystander base-rate (#499) — in that order.
- **Family-clustered SE** and **leave-one-family-out** robustness.
- **Bootstrap 95% CI** on ρ (1000 resamples; for B→B with n<8, also report exact permutation null).

**Headline "this worked" threshold (N→N + N→B-EM + N→B-syco only).** Pooled ρ across the three cell types in the headline (N→N, N→B-EM, N→B-syco; B→B is excluded — see below) is ≥ +0.40 AND its 95% bootstrap CI excludes zero AND the cell-type-stratified analysis shows ρ > +0.20 in EACH of N→N, N→B-EM, N→B-syco. Below this threshold, the predictor is reported as "validated for EM only" with the same LOW-confidence framing as #468.

**B→B is descriptive-only and does NOT enter the pre-registered headline gate.** B→B's 4 off-diagonal cells × 2 seeds give an effective n on the order of 4 — at noise a 4-point ranking crosses ρ = +0.20 about 1 in 4 times, so the gate is not informative there. B→B is reported as point estimate + 95% bootstrap CI + exact permutation null, with no p-value claim and no pre-registered ρ threshold. If the B→B descriptive point estimate looks worth chasing (e.g. CI clearly excludes zero on the positive side OR clearly excludes zero on the negative side), the clean-result will file a follow-up task to expand B→B coverage; B→B coverage is NOT expanded in this plan.

**Saturation guard:** if any source's diagonal cell shows the target judge at >0.95 rate AND >0.95 of the off-diagonal cells, the target judge is saturating and that target is dropped from the pooled regression. (Per #448; #466.)

## 9. Statistical analysis

**Pooled regression panel.** Variable per cell = (source, target, seed) tuple. Total cells (full matrix):
- N→N: 10 sources × 3 narrow targets × 2 seeds = 60 rows. By construction the source pool and target pool overlap on 3 cells (`turner_bad_medical` = T1, `insecure_code` = T2, `emergent_plus_legal` = T3) so **6 rows (3 source==target × 2 seeds) are diagonal install-QC**, scored on each cell's own judge per §5 and §3.1. **Off-diagonal N→N = 54 cells** enter the leakage regression.
- N→B-EM: 10 sources × 1 target × 2 seeds = 20 cells (re-validation of #468 anchor). Sources distinct from the broad-EM target persona by construction (no source==target rows).
- N→B-syco: 10 sources × 1 target × 2 seeds = 20 cells. Same — no source==target rows.
- B→B: 2 broad axes × 2 seeds × 2 targets = 8 cells, of which 4 are diagonals (broad-EM → broad-EM, broad-syco → broad-syco). **4 off-diagonals**.

**Total off-diagonal cells: 54 + 20 + 20 + 4 = 98 cells.** With 2 K=8 cosine draws per cell, total predictor observations = 196. (Drawn as a longer-form spec the regression averages over the 2 draws → 98 effective rows.) The 6 N→N install-QC diagonals and the 4 B→B diagonals are reported separately as install verification (see §5 controls) and do NOT enter the leakage regression.

**Primary regression — binomial mixed model on count outcomes** (R `lme4::glmer(family=binomial)` or Python `statsmodels.GenLinMix` / `pymer4`). The DV is the (k, n) pair per cell-seed where k = judge-positive verdicts and n = total verdicts (n = 500 for narrow / broad-syco targets; n = 800 for broad-EM):
```
cbind(k, n - k) ~ cosine_predictor + cell_type + family + log_tokens
                  + lexical_persona_cosine + base_rate
                  + (1 | source) + (1 | target)
                  , family = binomial(link = "logit")
```
This form natively handles k = 0 cells (and k = n if any cell saturates), respects the binomial variance structure on counts, and does NOT silently drop floor-rate cells. Family clustering on the source side (10 narrow + 2 broad axes = 6 families: code / medical / advice / legal / security / aesthetic + broad-EM / broad-syco). Random effects on source and target catch within-source and within-target correlation across the panel.

**Convergence fallback (pre-registered).** If the binomial mixed model fails to converge — separation, singular Hessian, optimizer warning that can't be cleared by reasonable starting values — fall back to the pseudocount-transformed fixed-form regression:
```
logit((k + 0.5) / (n + 1)) ~ cosine_predictor + cell_type + family + log_tokens
                              + lexical_persona_cosine + base_rate
                              + (1 | source) + (1 | target)
```
Same predictor set; the +0.5 / +1 Laplace-style pseudocount makes the response defined on k = 0 and k = n. The pre-registered choice between the two is "binomial mixed model unless it doesn't fit, then pseudocount" — set in the plan so the choice is not a post-hoc tuning knob.

**Secondary regression — raw-rate Spearman ρ.** In addition to the primary, the H4 rank-correlation read is computed as the pooled Spearman ρ between the predictor and the raw rate k/n, with the same family-clustered SE and leave-one-family-out sensitivity. H4 itself is a rank-correlation hypothesis (per §2) so the raw-rate Spearman ρ remains the named DV for H4; the binomial mixed model is the regression that absorbs floor-rate cells without bias and gives the coefficient + CI for H5.

**Reported summary**:
- Coefficient on `cosine_predictor` from the binomial mixed model (or pseudocount fallback) with family-clustered SE and 95% bootstrap CI.
- Per-cell-type stratified Spearman ρ (raw rate).
- Partial Spearman ρ at each stage (raw → partial-log-tokens → partial-lexical → partial-base-rate).
- Leave-one-family-out: drop each family, re-run both the binomial model and the Spearman, report the spread.

**Multiple-comparison correction.** The 4 a-priori hypotheses (H1–H4) get FDR (Benjamini-Hochberg) correction at α=0.05 **over the three statistically-tested cell types: N→N, N→B-EM, N→B-syco** (FDR denominator = 3 strata for the per-cell-type read; H4 itself is one corrected test over the 98-row pool). **B→B is descriptive-only per §5.1 and does NOT enter the FDR-corrected denominator.** H5 (head-to-head) is a within-regression test, no correction needed.

**Effective n** per cell type: with 54 N→N off-diagonal cells but 6 source families × 3 targets, the effective n after family clustering is ≈ 18 for the N→N stratum (Kish design effect ≈ 2-3). Report the effective n empirically from the fitted random-effects model (Kish is a back-of-envelope sanity check). For B→B, n is structurally small (4 off-diagonals) — report effect size + 95% CI rather than a p-value (B→B is descriptive-only per §5.1).

**Permutation null.** Shuffle the (source, target, seed) → (cosine, leakage) mapping, recompute pooled ρ; ≥1000 iterations. Report observed ρ percentile under the null. For B→B with n=4, also report the exact permutation null (4! = 24 enumerations).

**Sensitivity to the 2 K=8 draws.** Reported as a within-cell variance term in the random effects. If the within-cell variance is comparable to the cross-cell variance, the predictor is unstable and the result downgrades to LOW confidence.
