  mean my earlier headline depended on the input recipe, and I'd flag it.

## §2 Hypothesis + falsification

- **H1 (linear ridge ~invariant):** at n=50 the centered design has rank ≤ 49, so a
  full-3584-dim ridge and a per-fold top-48-PC ridge see nearly the same row space (one
  discarded component at most). **Prediction:** `|ΔR²_ridge| ≤ 0.05` on ≥26/28 layers
  for BOTH variant 2 (PCA-48) and variant 3 (whiten-48). **Falsified** if the ridge
  plateau shifts by > 0.05 on > 2 layers — which would itself be the finding (the
  headline depended on the input representation).
- **H2 (whitening is the lever that could move the RBF gap, not the ridge):** ridge with
  train-only per-dim standardization is near-invariant to a global rotation+rescale of
  the input (it re-standardizes internally), so PCA-48 ≈ whiten-48 ≈ full on the ridge
  arm. But the RBF kernel's pairwise distances DO change under whitening (whitening
  equalizes the per-direction variance the RBF γ heuristic keys on). **Prediction:** the
  KRR(RBF)−KRR(linear) gap can move under whiten-48 more than under PCA-48; the headline
  test is whether its SIGN is preserved (gap ≈ 0 at the plateau) and `|Δgap| ≤ 0.03`.
  **Falsified** if the RBF gap flips from ≈0-at-plateau to a positive-CI-excludes-0 at a
  plateau layer under any input variant — that would mean "RBF buys nothing at the
  plateau" is an artifact of the full-dim input.
- **H3 (no leakage):** the per-fold PCA/whiten basis is fit on the 49 train rows only;
  the held-out row is projected with the train basis. **Falsified / bug** if the
  PCA-48 ridge skill EXCEEDS the full-3584-dim ridge skill at the plateau by a wide
  margin (a too-good number is the leakage signature — a basis fit on all 50 rows would
  inflate held-out R²).

1. **Input representation of c_C** becomes a swept axis with three values:

     the existing ridge/KRR functions. THIS IS THE COMMITTED BASELINE — NOT re-run; the
     amendment compares against the committed `skill_over_mean.json` +
     `krr_vs_linear.json`.
   - **`pca48`** (variant 2, NEW): per LOCO fold, fit a PCA basis on the 49 TRAIN rows of
     c_C, keep the top 48 PCs, project BOTH the train rows and the held-out row onto that
     train basis, then run the inherited ridge / KRR exactly as before on the 48-dim
     projected input.
   - **`whiten48`** (variant 3, NEW): same per-fold top-48 PCA basis, but ZCA-whiten the
     projected coords — `Xw = (X − μ_train) · U · diag(1/√(σ²+ε)) · Uᵀ` where `(U, σ²)`
     are the per-fold train PCA eigvecs/eigvals truncated to 48, ε = 1e-6 — then run the
     inherited ridge / KRR on the whitened input.
2. **Per-fold basis (no leakage)** — variants 2 and 3 fit the PCA/whiten matrix on the
   TRAIN subset (49 of 50 contexts) of each LOCO fold ONLY, then project the held-out
   context with the train basis. This is the load-bearing single-variable-clean change:
   the existing `_input_pca_project(Xc)` helper fits on ALL rows (acceptable ONLY because
   its top-(n−1) projection is lossless at rank ≤ n); truncating to 48 < 49 and whitening
   are NOT lossless, so they MUST be per-fold to avoid leakage.
3. **Both DV arms recomputed** under each new variant: the linear-ridge skill
   (`run_722_skill_over_mean` ridge arm) AND the KRR RBF−linear gap
   (`run_krr_vs_linear`). The MLP arm is OUT of scope for this amendment (it already has
   its own input-PCA acceleration; the user's question is about the headline ridge +
   the nonlinear gap, not the decisively-negative MLP).
4. **Committed canonical outputs** under
   `eval_results/issue_722/input-pca-robustness-cC-to-v0/`, one JSON per (DV × variant),
   plus a per-layer ΔR² / Δgap comparison plot.

### 4.3 The single new knob — per-fold input transform (no leakage)

A new helper `input_transform_loco(Xc, rep, *, k=48, eps=1e-6)` applied INSIDE the LOCO
loop, fitting the basis on train rows only:

```
# rep == "full":  return Xc unchanged (variant 1 — the existing path; NOT re-run)
# rep in {"pca48","whiten48"}: per held-out fold i,
def transform_fold(Xtr, x_held, rep, k=48, eps=1e-6):
    mu = Xtr.mean(0)                                   # TRAIN-only mean
    U, S, _ = svd(Xtr - mu, full_matrices=False)       # gesdd→gesvd fallback (robust_pca_basis style)
    Uk = U-right-singular-vectors[:k]                  # top-k=48 PCs from TRAIN
    sig2 = (S[:k]**2) / (Xtr.shape[0] - 1)             # train per-PC variances
    Ztr   = (Xtr - mu) @ Uk.T                          # (49, 48) train projection
    z_held = (x_held - mu) @ Uk.T                      # (48,)   held-out projection (TRAIN basis)
    if rep == "pca48":
        return Ztr, z_held
    # whiten48: ZCA-style scale by 1/sqrt(train var + eps)
    scale = 1.0 / np.sqrt(sig2 + eps)
    return Ztr * scale, z_held * scale
```

For the **ridge arm**, this replaces the input fed to the per-fold solve in
`ridge_predict_loco_centered` (which already does train-only per-dim STANDARDIZATION of
its input internally — so for `pca48` the inner standardization re-scales the 48 PC
coords per-fold, and for `whiten48` the whitening is largely absorbed by that inner
standardization; this is exactly H2's prediction that ridge is ~invariant). For the
**KRR arm**, this replaces the input `Xc` fed to `krr_predict_loco(Xc, Y64, kernel=…)`
for BOTH the RBF and linear kernels (the RBF γ median-pairwise heuristic is recomputed on
the transformed input per the inherited recipe — this is where whitening can move the
gap). The target Y64 (v0 top-48 PC) is UNCHANGED.

**Implementation note (single-variable-clean):** the amendment adds `--input-rep` to
`run_722_skill_over_mean` (ridge arm only) and `run_krr_vs_linear`, threading the
per-fold transform into the existing LOCO loops. It does NOT touch the MLP arm, the
target reduction, the λ grids, the σ heuristic, the fold structure, or the seed. The
`full` branch is byte-identical to the existing code path (assert: re-running with
`--input-rep full` reproduces the committed baseline within 1e-9).
