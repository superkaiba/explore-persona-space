# Plan — task #2378: Chat-trained context→answer map transfer to story framings, characters, dialogue replies, and the user turn in Qwen3.6-27B

## 0.0 TL;DR (plain English)

- **What I'll run:** I take the model's internal snapshot of a conversation right before it answers, and a second snapshot of the answer it wrote, and learn a simple linear rule that predicts one from the other — trained only on ordinary chatbot Q&A. Then I test whether that same rule still works when the model is instead writing fiction — a story character answering a question, a story character replying to a remark that isn't a question, a plain text-file dialogue — and when the rule is pointed at the other side of the chat: predicting the user's next message from the conversation so far, once over real human messages and once over messages the model itself writes while playing the user.
- **What I expect:** based on the earlier 7B results, the rule applied unchanged will mostly fail across the fiction formats, but a single linear correction on the input side will recover most of it. For the user side, the earlier 7B experiment found the user's next message was not linearly predictable at all — so the open questions are whether a 4× bigger model changes that, and whether the rule tracks the model's own pretend-user better than it tracks real humans. The dialogue-reply arm decides whether the rule is about answering questions or about responding to the other speaker.
- **What would change my mind:** the rule transferring unchanged (framing costs were a weak-model artifact); no linear correction recovering it (the earlier recovery result doesn't survive a stronger model / honest scene-fitted queries); the dialogue-reply arm collapsing while question arms transfer (the map is question-specific); or the user's next message turning clearly predictable (the 7B user-turn null was a model-strength artifact).

## 3. Hypothesis

Per target cell (12 targets; chat is the only training cell), with recovery fraction = transfer R² / own-map ceiling R² on the target's held-out folds, define **D** = direct-rung recovery − 0.5 and **M** = context-side-re-map-rung recovery − 0.7, and **U** = own-ceiling held-out R² − max(the cell's measured shuffled-answer null p95, 0.05) (thresholds grounded: #2054 prose swaps direct 0.73–0.77 of ceiling vs boundary swaps −0.16 — 0.5 splits the bimodality; #2054 ctx-re-map recovery 0.84 vs answer-side 0.18 — 0.7 splits those). CIs are 200-draw scene-level (user cells: conversation-level) bootstrap percentile intervals on the recovery fraction. Recovery fractions are ill-defined when the own ceiling is itself indistinguishable from null — live here because #825's user cells were exactly that at 7B — so the lattice carries a pre-registered Unmappable-target branch, evaluated first (floor grounded: #825 user-cell ridge ≤ 0; #1310 story ceilings 0.106–0.253 all clear 0.05; 0.05 is also the G1c rig-defect floor).

DISJOINT and exhaustive: Unmappable-target ⇔ U ≤ 0; Transfers-directly ⇔ U > 0 AND D > 0 AND D's 95% CI excludes 0 on the positive side; Transfers-via-reparameterization ⇔ U > 0 AND D's 95% CI is wholly below 0 AND M > 0 AND M's 95% CI excludes 0 on the positive side; No-linear-transfer ⇔ U > 0 AND D's 95% CI is wholly below 0 AND M's 95% CI is wholly below 0; Inconclusive ⇔ otherwise.

**Directional predictions (falsifiable):**
- H1: plain-text lands Transfers-directly or better (same-boundary-family swap; #2054 prose/model swaps recovered 0.73–0.87 under at most rotation).
- H2: story cells land Transfers-via-reparameterization (boundary swap chat→attributed-quote; #2054: direct median −0.06, ctx-re-map 0.84). Falsified if story cells land Transfers-directly (framing cost was model-strength-limited) or No-linear-transfer (the recovery result doesn't survive honest scene-native queries). Per-character recovery spread across the 5-character panel is reported descriptively (no judged gradient axis — dropped per user directive).
- H3 (dialogue-reply, discriminating): registered **paired contrast** over the 4 characters with both arms (4 pairs: Astra, HELIOS, Dana, Vex) — per-character question-arm minus dialogue-arm recovery at the direct and ctx-re-map rungs. If the paired gap's 95% CI straddles 0 at both rungs, the map reads as a general respond-to-the-interlocutor object; a CI wholly above 0 at either rung reads as question→answer specificity.
- H4 (user cells, two registered branches): **(a) Ceiling branch (the primary user-cell read):** #825 grounds the null side — at 7B BOTH provenance arms were Unmappable (negative ridge R² against a 0.76–0.78 resample ceiling). Registered read: whether Qwen3.6-27B moves either user arm out of Unmappable-target. Both arms staying Unmappable replicates the #825 null on a 4× model (an informative outcome); either arm clearing it overturns it, and that arm's lattice verdict + transfer rungs then run as for any target (weak directional prior: the simulated arm clears before the real arm — on-policy text is the model's own distribution; consistent-with only). **(b) Real-vs-sim gap (registered paired contrast at conversation grain, shared contexts):** Δ = sim − real on own-ceiling R² (always computable, identical context vectors by construction) and, where both arms are mappable, on direct + ctx-re-map recovery; 200-draw conversation-grouped bootstrap CI. A CI wholly above 0 reads as the map tracking the model's simulation of the user rather than the human distribution.
- H5 (pooled arm): pooled-map + per-cell bias reaches ≥90% of the own ceiling in most cells (#2054: 34/56 at +bias, 50/56 at 95% with rank-128 residual) — cell identity is a bias + low-rank correction, not a different operator. The user cells are the interesting stress case: if they are Unmappable as own cells, the pooled arm reports their cells as-is/+bias tiers against a near-null ceiling (reported, excluded from the H5 fraction's denominator).

### 4.2 Story generation — three-segment recipe (P2/P4, pod, vLLM raw completion)

Structure is guaranteed by prefill at the boundaries, never by instruction:
- **Segment A (scene + utterance):** prompt = 3 sampled prime exemplars + `***` + opening seed (setting/situation/register + final seed sentence). `LLM.generate` raw (no chat template anywhere), temperature 1.0, top_p 0.95, top_k 20, seed 137, max_new_tokens 512. Cap-hit at SegA is by design (the miner window binds); reported per cell but exempt from the regen trigger (stated deviation).
- **Structural miner (code):** find the first quoted utterance directed at the character within the first ~250 generated tokens — quote-span extraction + attribution heuristics (attribution verb adjacent to the quote naming another speaker, or 2nd-person address + the character named in the surrounding sentence). Q-cells keep utterances ending in `?`; D-cells keep non-`?` utterances (statements/remarks/confidences). Emits byte offsets. **Why code, not a model call:** (a) alternative considered — a single judge call returning the utterance span; (b) code preferred because capture needs deterministic byte offsets over 234k candidates (a model call cannot return reliable offsets, and at this N the latency/cost dominates), and the semantic residue (directedness, question-in-disguise) goes to the judge; (c) would flip if mining precision < ~0.9 at pilot (then judge-extracted spans re-anchored by exact string match).
- **Admission judge (filter, not force; scored on PRE-ANSWER scene text ONLY):** the judge sees the scene + mined utterance and NEVER the answer span (the answer comes from the same raw completion, so answer-content gating would be selection-on-outcome on the DV; answer-quality diagnostics are reported per cell, never used to drop rows). Graded 0–100, admit ≥ 50 (Source: #2054 admission convention): exactly one utterance directed at the character; coherent scene; Q-cells: it is a genuine question; D-cells: it is NOT a question (direct, indirect, or rhetorical interrogatives all rejected). Congruence is NOT gated (near-ceiling by construction; measured as a manipulation check). Single-draw admission (parent parity; not a ranked DV), max_tokens 1024, Batch API.
- **Segment B (answer, forced):** truncate right after the mined utterance's closing quote, append `\n\n{opener}` where opener is sampled from a small attributed-quote-family bank (e.g. `{Name} replied: "` / `{Name} answered quietly: "` / `{Name} said: "` / `After a moment, {Name} replied: "` — ~8 variants; a frozen string is the #1345 R²=0.019 trap), free-continue max_new_tokens 1024. The answer span = generated text up to the closing quote (miner-extracted; no closing quote within cap ⇒ cap-hit row, reported, >2%/cell ⇒ regen at 2× cap). The opener IS the measured boundary form (disclosed: answer onset partially experimenter-written, coinciding with the standardized boundary).
- **Chat cell:** `tokenizer.apply_chat_template([{user: Q}], add_generation_prompt=True, enable_thinking=False)` rendered by our code (never vLLM-internal chat), generate max_new_tokens 2048; assert no `<think>` in outputs. **Plain-text cell:** `User: {Q}\n\nAssistant:` raw completion, stop=["\nUser:", "\n\nUser:"], max 2048. Both: cap-hit fraction reported; >2%/cell ⇒ regen at 2× (Source: #2054 cap-hit convention; parent's bare-text 42.5% cap-hit lesson).
- **Fresh draws (retrieval reference):** for 1,000 held-out rows per cell (all cells except chat_user_real — see §4.2b), 4 extra Segment-B (resp. answer / user-turn) draws at seeds 138–141.

### 4.2b User-turn cells — two provenance arms (P0/P2/P4; NEW, user-requested 03:24Z)

Both arms share the SAME 10,000 user-pool conversations and the SAME context prefix, and differ ONLY in who wrote the measured user turn — the paired design that makes the real-vs-sim gap interpretable (and makes their context vectors identical by construction under causal attention).

- **Slot definition (load-bearing — closes the #2054 self-prediction trap):** the context slot ends at the END OF THE PREVIOUS ASSISTANT TURN plus the user-turn header — never at the query — so the target text is never inside the context. Concretely: our code renders the Qwen3.6 chat template over [user₁, assistant₁] + `<|im_start|>user\n` (thinking disabled); the measured target is the user₂ turn. Depth is pinned at its minimum (user₂ = the first user turn with a completed assistant turn before it), minimizing the turn-depth mismatch vs the single-turn chat train cell (#825: turn-1 maps are genuinely different from deeper-turn maps — the residual depth-2-vs-depth-1 confound is disclosed on every user-cell transfer read).
- **Real arm (`chat_user_real`):** NO generation. Teacher-forced capture over the template-rendered real text: context = real user₁ + real assistant₁ (+ user header), target span = the REAL human user₂ text (16–2,000 chars filter, counted). Provenance disclosed: the measured text is human-written and the in-context assistant₁ is the ORIGINAL logged assistant's reply (both off-policy for Qwen3.6) — teacher-forced capture over fixed text is the standard regime for this line (#2054/#825), with the off-policy provenance stated on every read.
