### 4.1 Single manipulated variable — the source-only GRU (NEW code)

Add a single-state training + apply path to `maps.py` (the only new code; the single variable). Keep the `DepthGRU` architecture byte-identical (same `Embedding(27,32)`, `GRU(3616,1024,1)`, `Linear(1024,3584)`, hidden/emb_dim/layer count) — the ONLY thing that changes is that the recurrence sees a single state, not a prefix:

- **`DepthGRU.forward_single(h, transition_idx)`** — runs the SAME `self.gru` on a length-1 sequence `x = [h, emb(transition_idx)]` with a ZERO initial hidden state, returns `self.head(out)`. A 1-layer `torch.nn.GRU` on a length-1 sequence with zero init hidden is numerically a `GRUCell` step; the length-1 unroll is the MINIMAL-change realization (reuses the exact parent module, weights, optimizer, loss). **This is the parent reconciler's named "`h_ℓ`-only-trained GRU variant"** (v6 §4.4).
- **`fit_depth_gru_source_only(traj_fit, traj_val, sigma, ...)`** — mirrors `fit_depth_gru` but builds `(context × transition)` INDEPENDENT single-state examples: input `[h_ℓ, emb(ℓ)]`, target `Δ_ℓ/σ_m` (raw: σ≡1). 4000 contexts × 27 transitions = 108k examples per space; batched AdamW (batch 512), 300 epochs, early-stop on the inner-val split (same 500 contexts → their single-state examples), SmoothL1 β=1.0, seed 658, best-val kept. Same signature/defaults as `fit_depth_gru` except the single-state forward. This is the information-matched analogue of the per-transition ridge/MLP (each fit sees only `h_ℓ` + which-transition).
- **`GruSourceOnlyMap(gru, transition, sigma_m)`** with `.apply(h) -> head(forward_single(h, transition)) * sigma_m` (raw Δ̂). Building `maps_by_transition[m] = GruSourceOnlyMap(gru, m, sigma[m])` lets the parent's existing `transport_iterated(maps_by_transition, h_source, src, tgt)` roll it MEMORYLESS — each step reads only the current predicted state, no carried hidden, exactly matching the ridge/MLP transport regime and preserving matched information at inference. (Do NOT reuse `gru_roll`, which warms + carries the recurrent state — that is the prefix regime.)

Both new functions live behind a `--verify-source-only-gru` self-check gate: assert `forward_single` on a length-1 sequence equals a manual GRUCell step within fp32 tolerance, and assert the `.apply` chain produces finite raw Δ̂ of shape `(N,3584)` on a 2-context toy — the gate exercises the EXACT functions the entrypoints dispatch (`.claude/rules/code-style.md` "Verification gates test the live dispatched path").

## 7. Decision Gates

**No gates — short run (~1 GPU-h, <4h wall) + a decidable single-variable read.** No mid-run compute gate; the outcome is reportable in every branch. The three pre-registered STOP-READS (each named, per the brief) that fold into the matched-information verdict:

Stage-1 reads lead with the AGGREGATE win-count over the 68-cell grid + the BH-corrected newly-winning subcount vs the in-run-DERIVED ridge-alone baseline (≈12/68) and the in-run-derived chance line (note: the conjunction predicate makes the chance line conservative) — NOT a per-cell-majority call.

1. **GRU-source-only BEATS ridge.** Stage-0: source-only-GRU r2_id > ridge r2_id on a majority of the 27 transitions (raw space), especially the late-layer band 17–25. Stage-1: the source-only-GRU aggregate win-count over the 68-cell grid exceeds the derived ridge-alone baseline (≈12/68) AND its newly-winning subcount survives BH correction against the derived (conjunction-conservative) chance line. → **The matched-information verdict FLIPS: a recurrent map class beats affine ridge at matched information; #841's "ridge wins" headline is rewritten.**
2. **GRU-source-only MATCHES ridge.** Stage-0 win-count ≈ split (no clear majority either way). Stage-1 aggregate win-count ≈ the derived ridge-alone baseline (≈12/68) and the aggregate paired-delta vs `transported_ridge` is centred on zero. → **The 27/27 Stage-0 + the transport headline STAND; no recurrent-map advantage at matched information.**
3. **GRU-source-only LOSES to ridge.** Stage-0: ridge beats on ~all transitions (as the prefix-GRU already does). Stage-1: aggregate win-count below the derived ridge-alone baseline and the aggregate paired-delta vs `transported_ridge` clears negative. → **Ridge's dominance is reinforced; a recurrent nonlinearity over a single state does not help Δ-prediction/transport.** (The directional prior, given the prefix-GRU's 27/27 Stage-0 loss.)

The matched-on-recipe, cross-transport-regime prefix-vs-source read (`transported_gru_source_only − transported_gru`) is reported in every branch — and any Takeaways rewrite naming it labels it cross-transport-regime, not a clean single-variable contrast: does stripping the prefix HELP (the GRU was distracted by trajectory noise) or HURT (the prefix carried real signal) the GRU's own transport? Gate any "prefix adds nothing" reading on convergence parity (§11/§4.2).
