# Plan — Issue #1336: Does RLVR post-training change the context→answer map more than SFT/DPO?

## 0.0 TL;DR (plain English)

- **What I'll run:** I'll take the four released checkpoints of the Tülu-3 training ladder (Llama-3.1-8B base → after SFT → after DPO → after RLVR, plus a fifth longer-RLVR checkpoint as a bonus), have each one answer the same 5,000 real chat prompts and 6,319 math questions, and fit the same "read the upcoming answer's activation profile from the end-of-context activation" linear map we already validated on Qwen (#779/#825). For each post-training stage I then check whether the stage's map is just the base model's map in different coordinates (a linear change of basis on both sides), or whether it carries genuinely new structure the base map can't be bent into.
- **What I expect:** based on the Qwen result — where the instruct map was reconstructible from the base map to within 0.0003 R² — I expect the SFT and DPO stages to show a near-zero reparameterization gap; the open question is whether the RLVR stage breaks that pattern, especially on math prompts (the domain RLVR was actually trained on).
- **What would change my mind:** if the gap after RLVR is clearly bigger than the gap after DPO (CI clear of zero on the math-prompt arm), that's evidence RLVR *taught* the model new map structure rather than eliciting what pretraining already built — which would bound the "post-training only elicits" reading of #825 to the SFT/DPO era. If all gaps stay ≈0, the elicitation reading extends to RL post-training too.

## 1. Goal

> Determine whether RLVR-style RL post-training changes the linear context→answer-profile map more than SFT/DPO post-training, using a released separated-stage ladder (primary candidate: Llama-3.1-8B base → Tulu-3-8B-SFT → Tulu-3-8B-DPO → Tulu-3-8B post-RLVR) — per stage, measure (a) within-stage held-out R² of the per-example ridge map c_x → v(x) (#779/#825 recipe, prefix AND context arms) and (b) the #825 Result-2 reparameterization gap (within-stage R² minus reparameterized-base-map R² on identical text), testing whether the gap grows specifically at the RLVR stage (teaching) vs stays ≈0 at all stages (elicitation) vs grows uniformly with post-training depth.

(Task #1336 Goal, verbatim.)

#825 established, on Qwen2.5-7B (which predates RLVR), that post-training does not create the context→answer-profile map — the pretrained model carries it at 87.3% of instruct strength, and the instruct map is reconstructible from the base map by a general linear change of coordinates to within 0.0003 R². That "elicitation, not teaching" reading is confined to SFT/DPO-era post-training. This experiment extends the read to an RL-with-verifiable-rewards stage using the only widely-released ladder where SFT, DPO, and RLVR checkpoints are separately published with verified lineage. ## 3. Hypothesis

Per stage k ∈ {SFT, DPO, RLVR (, RLVR-long)} define the reparameterization gap **Δ_k = R²_within(k) − R²_reparam(base→k)**, both held-out on shared folds on stage-k text, and the headline contrast **C = Δ_RLVR − Δ_DPO** on the GSM8K-train chat arm at the headline layer.

- **H-teach:** RLVR teaches linearly-new map structure → C > 0, CI-clear, concentrated on the verifiable domain (GSM8K arms > LMSYS arm).
- **H-elicit:** RLVR, like SFT/DPO on Qwen, only re-expresses the base map → every Δ_k within the Qwen precedent band (|Δ_k| < 0.02; measured Qwen gap 0.0003).
- **H-generic:** the gap grows with post-training dose regardless of stage type → adjacent increments (Δ_SFT − 0, Δ_DPO − Δ_SFT, Δ_RLVR − Δ_DPO) all positive and comparable.

DISJOINT and exhaustive: RLVR-specific gap growth ⇔ C > 0 AND C's 95% CI excludes 0 on the positive side; RLVR gap not larger ⇔ C's 95% CI is wholly below 0; Inconclusive ⇔ otherwise.

Magnitude qualifier (prose, not lattice): a CI-clear C with point estimate < 0.05 (the parent's replication-gate tolerance scale) is reported as "statistically detectable but small". H-elicit vs H-generic disambiguation is a registered secondary read on the per-stage Δ_k values and their adjacent increments (each with paired bootstrap CIs), never a headline by itself.

Row-coverage: both arms' registered rows are supplied per-prompt by the per-cell turnstore sidecars under `analysis_tensors/turnstore_<model>_<format>_<corpus>/` on the HF data-repo prefix `issue1336_rlvr_ladder/` — the within-stage arm and the reparameterized-base arm read the SAME prompt-id rows and fold assignments from the same stores, intersected per pair before fold assignment.

## 4. Design

### Divergences from parent issue #825

1. **Model axis (THE manipulated variable):** Qwen2.5-7B base/instruct pair → the 5-checkpoint Llama-3.1-8B Tülu-3 ladder. Absolute R² is not comparable across families (scope caveat); the DV is within-ladder stage deltas.
2. **Corpus additions:** GSM8K train/test arms added because Tülu-3's RLVR stage trains on verifiable math/instruction prompts — the predicted locus of any teaching effect.
3. **Scope reductions:** no Track M (two-turn), no MLP probe (parent showed single-turn maps are essentially linear: MLP ≈ ridge, 0.654 vs 0.673), no per-position capture (no registered read consumes it; rollout text persisted makes it regenerable).
4. **Frozen layer set remapped** by fractional depth (28→32 layers): {14,18,19,26}/28 → {16, 21, 22, 30}/32.
5. **Naturalistic format arm added to the single-turn track** (parent had it on Track M only) — the task body's template-arm requirement.

Each divergence is either the manipulated variable (1), the domain instrument for it (2), or a justified scope choice (3–5); the fit/alignment/statistics recipe is otherwise inherited verbatim.

### Why code, not a model call

The DV is a closed-form linear-algebra statistic over residual-stream activations — no LLM can produce it; all compute is deterministic capture + ridge fits. Zero judge/API calls (**API workload estimate: 0 calls — no judged DV; no Anthropic API usage anywhere in the run**).

### Conditions × corpora × arms

- **Models (5):** see §5 table. The four-checkpoint primary ladder carries the headline; "After longer RLVR" (Tulu-3.1) is a registered secondary dose arm, never headline (bundled change: GRPO + longer training).
- **Corpora (3):**
  - `lmsys5k` — the SAME 5,000 single-turn LMSYS prompts as #825 Track S, reused from the pinned artifact `issue825_userbase_map/raw_completions/track_s/track_s.jsonl` @ HF rev `deb7a452` (Hub-verified this session: 9,036,307 bytes). Tier 1–2 (real user prompts from an established dataset). No lmsys re-ingest needed.
  - `gsm8k_train5k` — first 5,000 questions of `openai/gsm8k` (config `main`, train split), deterministic prefix; matched n to lmsys5k. Tier 2 (established benchmark). NOTE: these prompts overlap the RLVR training mixture (`RLVR-GSM-MATH-IF-Mixed-Constraints`) by design — this arm reads the map on the RLVR-trained distribution, the maximal-teaching surface; carried as an explicit interpretation constraint (an effect here alone is "map change on trained prompts", not generalized teaching).
  - `gsm8k_test1319` — the full GSM8K test split (1,319 questions), held out from RLVR training; the decontaminated generalization companion. Read against matched-n (1,319-row) subsample refits of the other corpora when comparing across corpora.
  - Correctness of answers is NOT scored anywhere — the DV is the activation map, not task accuracy.
- **Formats (template arms):** `chat` = the Tülu-3 chat template rendered as text (`<|user|>\n{q}\n<|assistant|>\n` — verified this session to tokenize to IDENTICAL token ids under the base and Tülu tokenizers, since the role headers are plain text, not special tokens; the base model, which ships no chat template, is rendered with the same template string). `naturalistic` = the #825 plain-transcript render ("User:/Assistant:" convention reused from `issue825_render_formats.py`), extraction-only re-render of the SAME generated answers (parent convention; render-integrity gate below). Naturalistic arm on **lmsys5k only**; GSM8K arms are chat-only (stated scope).
- **Mapping arms (BOTH, per the standing rule):**
  - **Context arm (primary):** c_x = residual activation at the final token of the assistant header that opens the answer (end of prefix + user query) — the parent's Track-S slot convention.
  - **Prefix arm:** the prefix (everything before the user query) of a single-turn, no-system-prompt rendering is the constant token sequence `[BOS, <|user|>, \n]` — identical across all rows, so under causal attention the prefix-slot activation is row-constant and the prefix-based map is **degenerate by construction** (zero predictor variance). **Stated deviation:** the prefix arm is not fit as a map on the single-turn corpora; instead the prefix-header slot activation IS captured in every cell and a registered degeneracy check (max pairwise cosine distance across rows, reported per cell; expected ≈ 0) documents the degeneracy empirically. This inherits the parent's Track-S convention and is carried into the clean-result as a scope caveat. (The parent's causal-slot equality assert is also inherited.)
- **Targets:** v(x) = mean residual activation over the answer span (the model's OWN answer), all 32 layers, bf16 capture, **bf16 store** (parent turnstore parity — `issue825_extract_turnstore.py:335-340` stores bf16 explicitly because fp16 overflows residual outlier dims; the held-out **preds npz stays fp16**, the parent round-5 preds precedent).

### Pipeline DAG (per phase; pod-side, sharded across GPUs)

1. **Phase G — on-policy generation** (vLLM, one engine per model per GPU): for each of 5 models × 3 corpora, sample answers with the parent's Track-S convention — quoted verbatim from the #825 body: "1 sample/prompt, T = 1.0, top_p = 0.95, max_tokens = 1024, seed 42, chat template". Base-model stop handling: stop strings `["\n<|user|>", eos]` + post-hoc truncation at the first role-header reoccurrence; per-cell text audits (3-gram repetition flag rate, distinct-3-gram, early-EOS, length stats) persisted as in #825 rounds 7–8. Row filters: ≥ 8 content tokens per turn, ≤ 2048 total rendered tokens (parent values). Keep-rate floor 0.80 per (model, corpus): below-floor cells are REPORTED and fit at realized n (never padded); alignment fits use per-pair prompt-id intersection rows.
2. **Phase E — teacher-forced extraction:** per (model, format, corpus) cell, one forward per batch (batch 8, bf16), capturing: 2 slot vectors (prefix header, assistant header), 2 span profiles (u1, answer), per-turn teacher-forced NLL — all 32 layers; NO per-position capture. New thin script reusing `extract_layer_activations` + the #825 shard/sidecar writer, with a model registry (n_layers=32, hidden=4096 asserts) replacing the Qwen constants. Cells: 5 models × (2 formats × lmsys5k + 1 × gsm8k_train5k + 1 × gsm8k_test1319) = 20 cells.
3. **Phase F — within-cell fits:** for all 20 cells, `heldout_r2_sweep` (imported from `issue825_fit_cells.py` — the body-named fast twin, USED) over all 32 layers, K=5 folds seed 0, GCV λ ∈ logspace(−2, 4, 13); 20 selection-symmetric shuffle nulls; 1,000-draw bootstrap CIs at frozen layers; held-out prediction matrices persisted (fp16 npz + manifest, round-5 pattern). Headline-layer rule (pre-registered, applied before any gap is computed): among the frozen set {16, 21, 22, 30}, pick the layer maximizing the MEAN within-stage R² across the 4 primary models on lmsys5k-chat — a statistic symmetric across the stages in the contrast, so it cannot favor either side of C; all four frozen layers reported as robustness.
4. **Phase A — ladder alignment battery** (the Result-2 construction, cores imported from `issue825_map_alignment.py`): for each pair (base→SFT, base→DPO, base→RLVR, base→RLVR-long; adjacent SFT→DPO, DPO→RLVR, DPO→RLVR-long) × each eval set (lmsys5k-chat, lmsys5k-naturalistic, gsm8k_train5k-chat, gsm8k_test1319-chat) × frozen layers: within ceilings, rep-swap both directions, alignment maps A_ctx/A_ctx_rev/A_ans/A_ans_rev with their own held-out R², and the composition **comp_samefn = A_ans ∘ M_base ∘ A_ctx_rev evaluated X_k → Y_k** (per-fold train-only fits, shared folds by prompt id, fp64 solves — the parent's no-leakage convention). Gap Δ_k and contrast C with paired prompt-level percentile bootstrap (1,000 shared resamples, per-draw re-centered, fp64 — round-5 machinery). Orthogonal + scaled-orthogonal variants at the headline layer only (rotation-vs-general-linear read). Base-anchored pairs carry the headline; adjacent-stage pairs are the registered secondary (per-stage increments read directly).
5. **Phase P — figures + decision JSON** (VM CPU, after pod results land; small footprint).

Contexts are identical strings (and, verified, identical token ids) across all 5 models per (corpus, format), so cross-model row alignment by prompt id needs no extra extraction — exactly the parent's cross-model setup.

## 7. Decision Gates

Wall-clock > 4 h and the family-transfer question is genuinely uncertain (no prior Llama-family run of this recipe), so two gates — minimal, grounded, jointly satisfiable (they read different measurements on different models; no shared cell):

- **G0 — fit-core reuse gate (pre-launch, ~minutes, VM or pod):** refit the committed Qwen S1 cell from the pinned #825 turnstore (`instruct_chat_s` stems @ HF rev `deb7a452`) through the NEW generalized fit driver; PASS ⇔ layer-19 held-out R² within ±0.01 of the committed 0.6731. Grounds: the #825 rounds' anchor-gate convention (every reuse round reproduced its anchors to ≤1.5e-14). FAIL ⇒ fix the driver before any GPU spend; this is the artifact-reuse validation gate for the parametrized fit path.
- **G1 — rig-transfer kill gate = the plan's kill criterion (after wave 1 of Phases E+F, ~1.5 h in):** run the After-RLVR model's lmsys5k-chat cell FIRST; KILL the ladder ⇔ best full-sweep within-stage held-out R² < 0.2 (both formats if the chat read is between 0.2 and 0.3, check naturalistic before killing). Grounds (threshold and sign): every instruct-class run of this construct reads far above it — Qwen-Instruct 0.673, Qwen-base 0.588, and even the n=2,000 matched subsample 0.321 (#825); 0.2 sits ~40% below the weakest healthy precedent, so a healthy Llama run passes by wide margin while a genuine transfer failure (map absent in this family) fails. On KILL: halt remaining phases, persist wave-1 artifacts, report "the linear context→answer map does not transfer to Llama-3.1-8B at usable strength" as the finding (itself a reportable scope result for the #779/#825 line), and re-plan.

Recomputed on cited precedents: G0's own precedent (0.6731 refits reproducing to machine precision) passes ±0.01 trivially; G1's precedents (0.673 / 0.588 / 0.321) all land in the PASS branch — bands match the narrative labels.
