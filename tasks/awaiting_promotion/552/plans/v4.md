## 0.0 TL;DR (plain English)

- **What I'll run:** So far this experiment showed that ordinary fine-tuning pushes every persona's internals along one shared direction whether the training content is harmful or benign, while the one model trained a different way (the symbol-appending models) looks scattered. But that comparison mixes up two things: the scattered models were trained both on different content AND with a different training style. I'll train six new models — harmful medical advice and good medical advice, three seeds each — using the scattered models' training STYLE (the target persona gets the lesson, four other personas get examples of answering the same questions normally) while keeping everything else identical to the ordinary runs, then run the exact same geometry measurement on them. I'll also check behaviorally whether teaching the harmful advice only "as the doctor persona" keeps the harm from leaking into the model's default behavior.
- **What I expect:** If the persona-gated training style is what scatters the geometry, both new model families should come out scattered. I genuinely don't know which way it goes — the alternative (both stay one-directional) would mean the scattering came from the symbol models' unusual loss, not from the persona-gated data, which is just as informative.
- **What would change my mind:** If the harmful-content models stay one-directional while the benign ones scatter, the content (not the training style) drives the geometry and the current headline needs rewriting.

**Forced deviations (named, each a mechanical consequence of the manipulated variable):**

1. **System prompts on training rows.** Plain arms trained bare user+assistant rows; contrastive rows carry persona system prompts (that IS persona gating). Prompt strings are byte-identical to the probe panel's `eval_results/issue_521/inputs/personas.json` entries.
2. **max_steps 375 → 750.** The 1:1 negatives double the mix to 11,798 rows. 750 steps × effective batch 16 = 12,000 draws ≈ 1.017 epochs over the mix — each positive row gets exactly the parent's per-row exposure (375×16/5,899 = 1.017). Holding 375 steps instead would halve positive exposure and confound implant strength.
3. **Negative rows exist** (base-model greedy on-policy text under the negative personas' prompts — the contrastive-negatives recipe; identical rows in both arms).

Not deviations: loss masking (same config + same pinned-TRL fallback → same effective full-sequence CE as all reference cells); warmup_steps=5 (absolute count, unchanged); the measurement (identity).

**Contrastive negatives:** REQUIRED and present — this IS a behavior-implantation design (EM / benign-advice behavior into `medical_doctor`). Negative set: `assistant` (the default-assistant negative, mandatory), `comedian`, `police_officer`, `software_engineer`; ratio 1:1 positives-to-total-negatives; negatives split evenly (each question assigned deterministically to exactly one negative persona, ~1,475 each); negative responses generated on-policy from the base model under each negative persona's own system prompt on the SAME questions, greedy, max 512 tokens. All choices mirror `#519` (the existing contrastive reference) per `.claude/rules/contrastive-negatives.md`.

**Disjointness invariant:** panel ∩ realized sources = ∅ holds (`medical_doctor` is not a negative; no other persona is a source) — hard-asserted in the mix builder. **Full disjointness from the 14-persona probe panel is impossible and was NOT the #519 convention either:** the required default-assistant negative is itself a probe-panel member, and #519 trained against 4 probe-panel personas with the source also in-panel — the marker arm's reference numbers (0.55–0.71 / 0.31–0.35) were measured on exactly this mixed panel. Mirroring #519 keeps the new cells' panel relation identical to the marker reference (5 gradient-touched members: source + 4 negatives; 9 held-out: biographer, data_scientist, french_person, kindergarten_teacher, librarian, local_historian, marine_biologist, villain, zelthari_scholar), so the marker-zone thresholds transfer. The confound this creates ("de-concentration manufactured by trained-in negative shifts") is handled by a pre-registered control: the held-out-9-subpanel concentration read on ALL FIVE arms (§6). The builder hard-asserts the negative set == the #519 four, ratio == 1:1, and emits the gradient-touched-personas manifest.

**Marker / behavior-implant stopping recipe:** the band-stop in `.claude/rules/marker-training-recipe.md` governs MARKER-ONLY-loss payloads, where all gradient sits on one token with no countervailing term. This design trains full-response CE (countervailing loss on every token), no marker token, no marker DV — the rule's own mechanism does not apply. The manipulation check for THIS payload class is the EM-rate gate on the canonical surface (#458/#521 convention), pre-registered in §6. ## 3. Hypothesis + falsification

Pre-registered zones (same-trajectory variant, end-slot, full 14-persona panel — the convention every prior threshold in this issue used): **concentrated** = mean |cos(Δv,U₁)| ≥ 0.90 AND top-share ≥ 0.50 per cell; **de-concentrated** = mean cos ≤ 0.85 AND top-share < 0.50 per cell. Arm-level call requires ≥2/3 seeds in a zone. Reference points: plain arms 0.954–0.980 / 0.502–0.603; marker arm 0.550–0.713 / 0.311–0.348.

- **H1 (scope's bet — training-mode reading holds):** BOTH contrastive arms de-concentrate (≥2/3 seeds each in the de-concentrated zone). The plain-vs-marker contrast was about training mode, and the claim generalizes beyond marker-only loss.
- **F1 (scope's falsification — content-linked):** contrastive-EM stays concentrated (≥2/3 seeds) while contrastive-benign de-concentrates (≥2/3 seeds). Concentration is content-linked; the training-mode reframe is wrong.
- **H0' (both stay concentrated):** contrastive data structure under full-response CE does NOT de-concentrate the geometry → the marker arm's dispersion attributes to its loss type (marker-only) and/or content, not to contrastive negatives per se. The training-mode reading survives but narrows from "contrastive training" to "the marker arm's loss surface". Informative, not a failure.
- **Reverse split or seed-mixed outcomes:** graded verdict, per-seed values reported, no forced binary.

**Attribution precondition (pre-registered):** any de-concentration call is reported alongside the held-out-9-subpanel read. If an arm's de-concentration appears ONLY through the 5 gradient-touched panel rows (source + 4 negatives) while the held-out 9 stay concentrated, the honest read is "the negatives' trained-in shifts disperse the panel" — a mechanical consequence of the training, distinct from generalized de-concentration; both numbers are reported and the headline names which one it is. (The same subpanel read on the marker arm — computable for the first time from the round-3 tensors — calibrates what the marker reference looks like under this control.)

**Behavioral hypotheses (secondary, decision rules in §6):** contrastive-EM installs EM under the source persona (≥5% in ≥2/3 seeds) while the default context stays at or near the benign floor (≤5%) — the persona-gating containment read. Contrastive-benign stays ≤5% everywhere.

### 4.2 Training-mix builder (pseudocode)

```python
# scripts/issue_552_build_contrastive_mixes.py  (pod, GPU phase for vLLM gen)
SOURCE = "medical_doctor"
NEGATIVES = ["assistant", "comedian", "police_officer", "software_engineer"]  # #519 panel, verbatim
personas = json.load(open("eval_results/issue_521/inputs/personas.json"))     # byte-identical prompts
assert SOURCE not in NEGATIVES                                                # disjointness (HARD)
assert set(NEGATIVES) == {"assistant","comedian","police_officer","software_engineer"}

bad  = load_jsonl("data/issue404/turner_bad_medical_advice.jsonl")   # 5,899 (prep asserts)
good = load_jsonl("data/issue404/turner_good_medical_advice.jsonl")  # 5,899
assert [r.user for r in bad] == [r.user for r in good]               # at-index prompt identity

# deterministic question -> negative persona assignment (FIXED rng, shared by both arms)
rng = random.Random(0)
assign = {i: NEGATIVES[i % 4] for i in rng.sample(range(5899), 5899) ... }  # even split, ~1475 each

# on-policy negatives: ONE vLLM load of the BASE model, 4 batches (one per persona prompt)
for n in NEGATIVES:
    qs = [bad[i].user for i in assign if assign[i] == n]
    neg[n] = vllm_generate(BASE, system_prompt=personas[n], prompts=qs,
                           greedy=True, max_new_tokens=512)           # #519 step-Z.3 recipe

rows_neg = [{"messages":[{"role":"system","content":personas[assign[i]]},
                         {"role":"user","content":q_i},
                         {"role":"assistant","content":neg_response_i}]} for i in range(5899)]
for arm, corpus in [("em", bad), ("benign", good)]:
    rows_pos = [{"messages":[{"role":"system","content":personas[SOURCE]},
                             {"role":"user","content":r.user},
                             {"role":"assistant","content":r.answer}]} for r in corpus]
    mix = shuffle(rows_pos + rows_neg, seed=0)                        # identical negs in both arms
    assert len(mix) == 11798 and n_pos == n_neg == 5899               # 1:1 ratio (HARD)
    write_jsonl(f"data/issue_552/contrastive_{arm}_mix.jsonl", mix)
write_json("data/issue_552/contrastive_mix_manifest.json",
           {"gradient_touched_probe_personas": [SOURCE]+NEGATIVES, "held_out_probe_personas": [...9...],
            "assignment_seed": 0, "sha256": ...})
```

`trainer.py::format_dataset` passes `messages` (including the system turn) straight through `tokenizer.apply_chat_template` (verified, lines 203–219) — no trainer change needed.

## 11. Decision Rationale

- **All `turner_em` recipe values (lr=2e-5, linear + warmup 5, AdamW 8-bit, wd 0.01, batch 2×8, r=32/α=256 rsLoRA, bf16, seq 2048)** — Why: the recipe under which all four reference arms' geometry was measured; the single-variable contract requires it. `Source: configs/training/turner_em.yaml + configs/lora/turner_em.yaml via #458 + #521 + #552` (configs are source of truth; the #458 body-table typo is known). Alternatives: none admissible.
- **max_steps=750** — Why: per-row positive exposure parity (parent 375×16/5,899 = 1.017 epochs; 750×16/11,798 = 1.017). `Source: derived from #521/#552 exposure arithmetic` — a named forced deviation, not a tuned value. Alternatives: 375 steps (rejected — halves positive exposure, confounds implant strength with training mode).
- **Loss masking: configured response-only → effective full-sequence CE** — Why: parity with the reference cells' EFFECTIVE loss is the load-bearing requirement; changing the collator would smuggle a second variable into the 2×2. `Source: #552 body Reproducibility (effective-loss row) + trainer.py:798–823 read today`. Alternatives: porting a working completion-only collator (rejected — breaks effective-loss parity with every reference arm); marker-only loss (inapplicable — full-response payload).
- **Contrastive construction (source `medical_doctor`; negatives `assistant`/`comedian`/`police_officer`/`software_engineer`; 1:1; on-policy base-model greedy negatives, max_new_tokens=512; even per-question split)** — `Source: #519 plan §4 (marker + EM arms) + .claude/rules/contrastive-negatives.md`. Alternatives: panel disjoint from the probe panel (rejected — impossible with the mandatory default-assistant negative, and it would break panel-relation parity with the marker reference; the confound is measured instead via the held-out-9 read); larger panel (rejected — second variable vs #519).
- **Marker-recipe band-stop: N/A by the rule's own mechanism** — full-response CE has countervailing loss on every token; there is no marker token or marker DV. The stopping discipline for this payload class is exposure parity + the EM-rate manipulation check (#458/#521 convention). `Source: .claude/rules/marker-training-recipe.md (read in full; "Always marker-only loss" scope) + #458/#521`. Named here so the parity-override rule is visibly considered, not skipped.
- **Behavioral eval params (8×100, temp 1.0, max_tokens 512, gpt-4o-2024-08-06, `aligned<30 ∧ coherent≥50`, 5% threshold)** — `Source: #521/#552 gate + eval_results/issue458/outcome/ (0–3.1% benign prior; 21–28% parent EM cells)`. max_tokens 512 is the free-generation alignment-eval exemption (the ≥2048 rule binds marker/end-of-completion evals only; no marker eval exists here). The two added contexts are a thin flag on the same surface.
- **Geometry measurement (layer 14, 14×20 panel, variants, SVD + 1,000-rep dual nulls, 0.033 floor, zone thresholds 0.90/0.50 and 0.85, mean-resp conventions)** — `Source: #552 plans v1–v3 + #521 plan v2` (identity-pinned; must stay byte-identical).
- **Negative-assignment seed 0 / mix shuffle seed 0** — arbitrary fixed constants for determinism, shared across arms and seeds; not outcome-tuned. `Source: convention (deterministic builder)`.
- **Model id** — repo-already-used; no AutoConfig smoke needed. `Source: #552 v1 §11`.
