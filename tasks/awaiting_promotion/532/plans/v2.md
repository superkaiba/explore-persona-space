## 0.0 TL;DR (plain English)

- **What I'll run:** I'll take the 16 marker-LoRAs I already trained (#474, the cleanest "early-epoch" checkpoints), pair each one against a new set of bystander prompts of the form *"end every response with ※"* (at three explicit-to-soft strength levels) plus the original 16 non-instructed bystanders, and just **measure** how often the model emits the marker and how likely it is. No retraining. Then I ask: do the activation-geometry distances we built to predict cross-persona marker leakage still rank these correctly when the system prompt has *told* the model to emit the marker?
- **What I expect:** geometry will mispredict the instructed contexts (it'll say "far, so no leakage" while the marker shows up anyway), and a much simpler predictor — *how likely is the marker in this bystander context under the base model* — will rank them correctly. The combined predictor (geometry + base-prior) should beat either alone.
- **What would change my mind:** if the base model can't actually follow the "emit ※" instruction (it's a rare single token; the instructed prior may stay near floor), the whole H2 falls over and there's no informative "instructed regime" to test geometry against. I check this before counting any geometry result, and bail to a follow-up if so.

## 1. Goal

Test whether the base-model geometric marker-leakage predictors (cosine, JS divergence, Gaussian-KL@L22 — the #502 winner at ρ ≈ −0.79) predict marker behavior in **instruction-set bystander contexts** (system prompts that explicitly tell the model to emit the marker), and whether a base-model behavioral-prior predictor (base `log P(※ | context)`) succeeds where geometry fails. Eval-only on the persisted #474 localized-arm epoch-1 LoRA adapters; no new training.

This is Dan's adversarial case (Slack, 2026-06-08): "a setting that i expect to break the cosine model: a system message that says 'output [marker] at the end of your response'." The #404/#458/#474/#502 predictor program treats marker leakage as a pure function of activation-geometry distance between two contexts and knows nothing about the marker's prior probability under each context. An instructed bystander breaks that assumption by construction.

## 3. Hypothesis

**H1 (falsification).** When the regression line for each geometric predictor (cosine, JS-v1, Gaussian-KL@L22) is fit on the 16 ordinary #406 contexts (the #502 panel) and used to predict marker behavior on the new instructed bystanders, the instructed bystanders sit as **large signed residuals**: geometry says "far ⇒ no marker," the marker is there anyway. Quantitative: predict-vs-actual residuals on instructed contexts have median absolute value ≥ 2× the median residual on ordinary contexts at the same predictor value, AND the sign is systematically positive (more marker than geometry predicts).

**H2 (constructive).** A base-model behavioral-prior predictor (base `log P(※ | T_bystander(q))` at the natural end-of-content slot, averaged across the 50 held-out probes) predicts marker behavior on the union panel at Spearman |ρ| ≥ 0.5 on the instructed bystanders, AND a combined predictor (geometry-for-transfer + prior-for-base-rate, e.g. `z(leak) ~ z(prior) + z(geometry)`) has higher CV R² on the union panel than either alone by at least 0.10.

**H0 (the kill — Phase 0 gate).** If the base model cannot reliably follow the "emit ※" instruction — operationalized as on-policy emission rate of ※ on instructed bystanders averaged across the 10 instructed contexts and 50 probes ≤ 5% AND base `log P(※)` at the chosen slot ≤ −5 nats — then the instructed regime is empty (no marker to predict, base prior stayed at floor), H2 is unfalsifiable, and the experiment routes to a follow-up: explicit-marker instruction with a multi-token decoy marker the base model CAN emit (e.g. "END.") as a sanity check the design works at all, plus a milder soft-instruction probe.

**H_post (auxiliary).** Robustness check: H1/H2 results hold on **loc-arm ep1 (primary, the cleanest)**, and the directional pattern survives on loc-arm ep2/ep3 (more saturated; per #502 the predictor ρ drops to −0.66 / −0.69). pos-arm excluded (78-99% saturated on ΔG).

## 4. Design

### 4.1 Data sources (tiers per CLAUDE.md)

- **Source-side contexts (16):** the 16 #406 contexts (5 A / 5 B / 1 C / 5 D), tier-2 (established panel from the parent project line — #406, #460, #474, #502 all share it). Plain-English names from `i406_conditions.CONDITIONS`.
- **Bystander panel — instructed (10 new contexts):** tier-3 (LLM-generated synthetic, diverse). Three strength bands × topical/structural variation:
  - **Explicit (4):** unambiguous imperatives. *"Always end every response with the symbol ※."* / *"Append ※ as the last character of every reply, after the period."* / *"You must finish your answer with the symbol ※; this is non-negotiable."* / *"End: ※. (every response, last token)"*
  - **Soft (3):** stylistic preference framing. *"You sometimes like to end your responses with ※."* / *"It is a quirk of your style to occasionally place ※ at the end of an answer."* / *"You have a habit of finishing some replies with ※."*
  - **Oblique / few-shot (3):** ※ appears in 2-3 demonstration `<Q,A>` pairs in the system prompt but is never named as a rule (e.g. *"Examples:\nQ: What's the capital of France? A: Paris ※\nQ: How many planets are in the solar system? A: Eight ※\n..."*).
  - **Justification (tier-3, not tier-1/2):** no real-world corpus exists for "instructions to emit a rare Unicode token"; no published benchmark uses ※. Diversity-across-strength is the design pressure (per the ICL-design rule in `planner.md`) — three bands × topical variation so the predictor regression has cross-context dynamic range, not a single-anecdote test.
- **Bystander panel — ordinary (16):** the same 16 #406 contexts, tier-2. These are the prior-≈-0 anchor (the regression line is fit on them).
- **Probes (50 per source-bystander cell):** the existing `q_test_extended_50.json` from `i460_data.load_q_test_extended_50()`, tier-2, already disjoint from the training Q_train.

### 4.3 Measurement slot + on-policy prompt construction (key design decision #2 — RESOLVED)

**Decision: the "post-response slot" per `marker-leakage-measurement.md` — the slot immediately after the model's own on-policy response `R`, on the byte-exact `prompt + R + MARKER` construction.** Same slot for instructed and ordinary contexts. Consistency across the union panel is essential; the headline DV is the trained-model `log P(※)` at *that* slot.

**Implementation note (the §4.3-vs-A9 contradiction the fact-checker caught):** the existing `_build_prompts_for_inner_j` in `i474_phase4_eval.py` is a **useful REFERENCE** for the byte-exact construction (`prompt_text + R_text + MARKER_TEXT` via `apply_chat_template`, slot-drift assertion at `len(full_ids)-1`), but its IO contract reads R from the canned `R_test.json` dict — that contract does NOT match #532's on-policy regime. #532 needs **near-total rewrite** of the prompt-builder, NOT verbatim reuse. Specifically:

1. **Generate `R_trained` on-policy under each (source adapter, bystander) pair** via vLLM `LLM.generate()` — this is per-cell, NOT canned. Persist `R_trained` alongside the log-prob so the headline DV is reproducible.
2. **Byte-encode `T_b(q) + R_trained + MARKER`** using the SAME `apply_chat_template` shape as `_build_prompts_for_inner_j` (the chat-template format is what carries comparability with #474's `Σ_full_ids` slot construction), but with `R = R_trained` (per-cell) instead of `R = R_canned`.
3. **Relax the slot-drift assertion** to `count(MARKER_ID) >= 1 AND full_ids[-1] == MARKER_ID` — instructed contexts may produce `R_trained` that itself contains ` ※`, so the original `count == 1` assertion FAILS by design. The relaxed assertion keeps the slot identity guarantee (the LAST token IS the marker we're reading) while allowing within-R marker emission. The post-response-slot log-prob then reads "how likely is one more ※ after the model finished its instructed answer" — see §4.4 nuance.
4. **For instructed bystanders' system-prompt construction:** the 10 new contexts do NOT match `build_prompt_for_condition`'s Class A/B/C/D shapes (`i406_conditions.py:206`). Implementation route: define a NEW "instructed bystander" path in the new script that calls `tokenizer.apply_chat_template` directly with `[{"role":"system","content":<instructed_system_prompt>}, {"role":"user","content":q}]` — bypassing `build_prompt_for_condition`, but producing the same final-prompt byte shape so the slot-drift assertion logic still applies.

The on-policy `R_trained` may include `※` *within* itself in instructed contexts, but that's a feature of the trained-model on-policy emission rate (a secondary report), not the headline log-prob.

**Rejected alternative:** "the natural end-of-content position BEFORE any instructed ※" — would have required heuristic ※-stripping from `R_trained`, breaking byte-exact prompt construction and the slot-drift assertion, and inventing a tier-4 templated heuristic for a key DV. Not worth the comparability cost. Documented for the implementer.

### 4.4 DV choice (key design decision #1 — gated, with explicit contingency)

**Decision: absolute trained-model `log P(※)` at the post-response slot, NOT ΔG = trained − base.**

- **Why:** Dan's adversarial case is "where does the marker appear" — the safety-relevant construct is the trained model's marker behavior in a bystander context, NOT how much it shifted from base. In instructed contexts the base prior is by hypothesis non-zero, so subtracting it would erase exactly the signal we care about (the prior is now part of the safety question, not a nuisance). The body's argument is precisely this.
- **Contingency from Phase 0:** if Phase 0 shows base prior is moderate or low across all 10 instructed bystanders (i.e. emission rate < 30%, base `log P(※)` ∈ [−10, −5]), report **both** absolute trained `log P(※)` AND ΔG so the comparison with the #502 ΔG-targeted predictor is fair on its own terms. Decision rule recorded in §11.
- **Reported tertiary:** on-policy emission rate (binary argmax = ※ at the slot, averaged over 50 probes) — bounded, more legible than the log-prob, but saturates fast and is not the headline.

### 4.5 Instruction-strength spectrum size (key design decision #3 — RESOLVED)

**Decision: 10 instructed contexts split 4-explicit / 3-soft / 3-oblique.**

- **Power justification:** to discriminate Spearman ρ = 0 vs ρ = −0.5 at α=0.05 the rule-of-thumb minimum n is ≈ 30 ordered pairs. Per-bystander analysis collapses the 50 probes per cell to a mean (one `leak[b]`, one `prior[b]` per bystander). The union panel of 16 ordinary + 10 instructed = 26 bystanders × 16 source adapters = 416 ordered pairs — well above the floor. The within-instructed analysis (key for H1's residual test) is 10 bystanders × 16 sources = 160 ordered pairs, also above the floor. The within-strength-band analysis (4 / 3 / 3) is underpowered on its own and is reported only as a directional sanity check, not a headline.
- **Why not 3:** the body proposed three contexts (one per strength band). For a regression-residual analysis the within-instructed-residual variance estimator is dominated by between-context variance with n=3; the residual median is also a single point and cannot be tested. Body's own check: "enough instruction-set contexts to get a real correlation / residual test, not one data point." n=10 with 3 strength bands and topical variation within each band is the minimum that gives both a credible aggregate and a cheap per-band sanity check.
- **Why not ≥30:** would 3× the GPU cost for diminishing inferential return; the headline test is geometry-vs-prior across the full union panel (416 pairs).
- **Base-following validation:** Phase 0 IS this validation. If fewer than 7 of 10 instructed bystanders show emission rate ≥ 5% under the base model, the n shrinks below the inferential floor and the experiment routes to a follow-up (multi-token decoy marker, §4.6).

### 6.2 Headline statistics

For each predictor `P ∈ {cosine, JS-v1, GKL@L22, base-prior, combined}`:
1. **Aggregate panel correlation.** Spearman ρ between `P[s, b]` (one scalar per (source, bystander) pair) and `leak[s, b]` (trained `log P(※)`), n = 416. Report the ordinary-subset ρ and the instructed-subset ρ separately too.
2. **Per-bystander aggregate.** Collapse over sources: ρ between `P[b] = mean_s P[s, b]` and `leak[b] = mean_s leak[s, b]`, n = 26. This isolates "is the bystander's marker rate predicted by its mean distance to all sources / by its own base prior".
3. **CV R² of the length-controlled linear fit** (matched to #502's secondary): same 5-fold leave-one-class-out CV.
4. **Combined predictor** `leak ~ z(base_prior) + z(geometry)` via OLS, compared to single-predictor fits by held-out R² uplift. Headline test of H2.

### 6.3 Signed-residual analysis (the H1 test)

Fit each geometric predictor's regression line on the **ordinary 16-context panel only** (240 ordered pairs). Predict on the instructed bystander pairs (160 pairs). For each instructed bystander, compute the median signed residual `(actual_leak − predicted_leak)` across the 16 sources. H1 PASSES if:
- median signed residual ≥ 2× the median absolute residual on the ordinary panel **for all three geometric predictors**;
- the residual signs are systematically positive (more marker than geometry says) — sign test n=10 vs 50%, p ≤ 0.05.

### 6.4 Sign-flip / permutation test (#500-style robustness)

For each predictor, run two independent robustness checks:
1. **Sign-flip:** replace `P[s, b]` with `−P[s, b]` in the regression; if the absolute ρ on the union panel is similar (Δ|ρ| ≤ 0.10), the predictor is not informative about sign and the claim weakens to "magnitude only". Per #500.
2. **Permutation:** shuffle the bystander labels and re-compute ρ; report the null distribution and the p-value of the unpermuted ρ.

### 6.5 Headline (one-sentence claim shape)

> *Across N sources × M bystanders, the base-model behavioral-prior predictor predicts trained-model on-policy marker behavior at Spearman ρ = X / CV R² = Y, while the #502 Gaussian-KL@L22 geometric predictor's regression line under-predicts the instructed bystanders by Δ; the combined geometry+prior fit beats either alone by ΔCV R² = Z. (CONFIDENCE).*

## 7. Decision Gates

**No gates beyond the H0 base-following gate baked into Phase 0** — short run (~10 GPU-hours total), pre-verified construct on a clean substrate (#474 loc-arm ep1). The only intermediate-signal gate is the Phase 0 H0 kill: if the base model can't follow any of the 10 instructed prompts (the worst-case design failure), Phases 1-4 are skipped and the experiment routes to a follow-up.

**Threshold + sign grounding.** The 5% emission rate AND −5 nat log P thresholds are BOTH `ungrounded — needs smoke-test`. The 5% threshold is a **conservative buffer above #489's measured floor of exactly 0.000 emission** (1659 of 1659 verifiable cells at exactly zero) — chosen to allow the trained-model emission-rate measurement an order of magnitude of headroom over the #489 floor, not a reproduction of a 5% number #489 measured (it didn't). The −5 nat threshold is a hand-estimated mid-range one-SD floor — #489 actually measured trained-model log P between −16.67 and −25.97 nat (mean diagonal ≈ −22.52), so even a moderate base prior of −5 nat would be a >15-nat lift from the #489 baseline regime. Both numbers are smoke-test calibrated, not literature-cited; Phase 0's per-bystander dump is inspected before the gate fires (see §A10).

Phase 0 is the same as the full sweep with `--phase 0-only` — no architectural drift, same dispatcher.

## 9. Resources & Parallelism

### 9.1 GPU spec

- **Intent:** `eval` (1× H100). The full sweep is sequential by design: adapter swap on vLLM is the bottleneck (~2 min per swap × 16 sources × 3 checkpoints = 96 min of adapter loads), generation is fast (~150 tokens × 50 probes × 26 bystanders × 16 sources × 3 checkpoints / 2 min = ~60 min of generation), and the residual extraction is one base-model forward pass per probe per new bystander (~10 min). No data-parallelism axis between sources because they share a vLLM engine; tensor-parallelism wastes throughput on a 7B model.
- **Why not 4× H100:** the workload is dominated by adapter loads + sequential per-source generation; TP=1 on a 7B is optimal. 4× would mainly cost more.
- **Why not multi-pod sweep parallelism:** loc-arm ep1 alone is ~2 hours; the full 3-checkpoint extension is ~8h on one H100 — well under the 24h cap, no need to split.

## 13. Test Strategy

### TDD: no

This is an eval/analysis script. The headline correctness comes from the assertions baked into the existing rigs (`MARKER_ID` assertion, relaxed slot-drift assertion, prompt_logprobs=1 fail-loud), not from TDD on a new function. The Phase 0 → Phase 1 → Phase 2 → Phase 3 → Phase 4 sequence is verified by the smoke run (full sweep with 1 source × 4 bystanders × 5 probes), which exercises every code path end-to-end before the full launch.

(Note: if Option A had been chosen for the JS implementation — write the canonical Rao-Blackwellized estimator from scratch — TDD WOULD apply: at minimum a `test_js_canonical_matches_closed_form_on_two_known_distributions` (e.g. two Gaussians, two known discrete distributions) plus a `test_js_canonical_matches_v1_in_first_token_limit`. v2 picks Option B — reuse the deprecated v1 verbatim — so no new function is written and no new unit-test surface is introduced. The JS arm's lower fidelity is documented in §6.1 / §8 / §11 / A12 as a scope caveat instead.)

Pre-launch checklist (mandatory):
1. `uv run python -m explore_persona_space.orchestrate.preflight` PASS on the pod.
2. ` ※` id assertion PASS (`tokenizer.encode(MARKER_TEXT, add_special_tokens=False) == [83399]`).
3. Smoke run PASS (1 × 4 × 5 = 20 cells; ~10 minutes; produces a valid `phase0_base_prior.json` + 20 per-cell JSONs + analysis stub).

5. Relaxed slot-drift assertion (`full_ids[-1] == 83399 AND count >= 1`) PASS on all 20 smoke cells; in particular, the 4 instructed bystander smoke cells exercise the within-R marker emission path.
6. `git status` clean before launch; commit pinned in result JSON.
