## 0.0 TL;DR (plain English)

- **What I'll run.** I'll first re-train the small "software engineer" marker model from a known recipe (the original training data is still on the data repo, the recipe is still on the parent branch — but the actual trained checkpoint was lost when the parent's pod went away). Once the marker reproduces, I'll take that re-trained model and add a one-line instruction to its system prompt — either "respond in Spanish if the question is about restaurant recommendations" or "respond in ALL CAPS if the question is about sports." Then I measure two things: (1) the standard "are these two personas similar?" predictors people use to anticipate behavior leakage, and (2) whether the symbol actually still shows up on the trigger-slice questions vs the non-trigger ones.
- **What I expect.** Both standard predictors will say "the two personas look essentially identical, so the symbol will leak everywhere." But the symbol's probability will drop sharply on the trigger slice (the Spanish or ALL-CAPS questions) and stay high elsewhere. If I split each predictor by trigger-slice vs non-trigger, the trigger-slice version will catch the drop the averages miss.
- **What would change my mind.** (a) The re-train doesn't reproduce the parent's headline (plain "software engineer" doesn't emit the symbol on ~90% of its own answers) — that means I can't trust this is the same model the parent measured, and I stop. (b) The model ignores the one-line conditional instruction (the always-Spanish twin behaves like Spanish-on-everything but the conditional twin behaves like base S everywhere — Step A flags this). (c) The symbol leaks at the same rate on the trigger slice as off it, with no drop at all — meaning either the predictors are not the right tool for this question or the symbol genuinely doesn't care about the slice the trigger picks out.

## 2. Prior Work

- **#404 / #458 (the predictor line, parent).** Established the cosine-similarity (#404, `M_1`) and JS-divergence (#458, `M_js`) predictors of EM leakage on a fixed 200-probe set, using mid-layer residual cosine at the last `{S, Q}` token (#404, layer 21) and the single-next-token JS at the last input position (#458). CLAUDE.md flags BOTH the #404 judge-score-KL operationalization and #458's single-next-token JS as **DEPRECATED**; the canonical defs (sequence-level Rao-Blackwellized JS over generated responses, per Amini/Vieira/Cotterell 2025, arXiv 2504.10637; cosine at multiple extraction points including own-response-mean, per Chen/Arditi/Sleight/Evans/Lindsey 2025, arXiv 2507.21509) are what #466 uses.
- **#432 / #448 / #456 (the on-policy marker rig, parent line).** #432 measured leakage with a teacher-forced fixed-stub probe and reported the trained source at rank 8/28. #456 re-ran the eval on-policy (`scripts/eval_i456_onpolicy_emission.py`, branch-only) and found the source emits the marker on 90% of its own answers (rank 1/28) — the #432 ranking was a probe with no resolution in a near-zero floor band, not a real ordering. #466 inherits the #456 RECIPE and the on-policy log-p instrument verbatim. **The #456 trained checkpoint itself is NOT inheritable** (it was never uploaded to a recoverable HF subfolder — the URL #456 wrote into its sentinel does not resolve, WandB run has 0 artifacts, the pod was terminated); #466 retrains in Phase 0 from the same recipe on the same pinned data file.
- **#461 (concurrent sibling, proposed).** Predicts #456's on-policy leakage across the 28-persona panel using cosine + JS in the standard `q:leak-predictor` regime. #466 is the COMPLEMENT: it constructs the NEW conditional / slice-concentrated regime that the averaged predictors are structurally blind to, and shows the slice-resolved variant catches it. Different scientific question, same machinery. #461 also needs the Phase 0 retrain output if it's run after #466.
- **#276 (relevant but indirect).** Showed topic paraphrases of a TRAINED token-trigger don't fire the trained behavior — i.e. the trained-vs-prompted gap matters when the trigger is a token. #276 does NOT directly bear on this experiment (the topic trigger here is in-context via system prompt, not a trained token-trigger), but it's worth noting as one reason topic triggers could be unreliable.
- **CLAUDE.md canonical persona-distance defs (load-bearing for §4).** Per "Persona-distance metrics — canonical definitions": JS = sequence-level Rao-Blackwellized estimator (arXiv 2504.10637, Amini/Vieira/Cotterell) — teacher-force sampled responses through both conditioned models, exact full-vocab divergence at every response-token position, length-normalized then mean over samples/probes. Cosine = persona-vectors difference-of-means (arXiv 2507.21509, Chen/Arditi/Sleight/Evans/Lindsey), with two extraction points: (a) last-prompt-token (legacy #404), (b) mean over each model's own generated response tokens. §4 of this plan adds a third (a0 = end-of-system-prompt, the blindness baseline).
- **Marker-leakage measurement recipe (CLAUDE.md).** On-policy, marker-at-end. DV = continuous `log P(marker | T(q) + R)` at the slot immediately after the model's own response R. Reported `trained − base` (subtract the base model's log-p at the same slot to isolate the training-induced shift). The continuous log-p subsumes emission rate. The branch-only #456 eval rig (`scripts/eval_i456_onpolicy_emission.py` on issue-456) implements this exactly; it is ported as part of §4.1.

## 3. Hypothesis

**H0 (Phase 0 prerequisite — must hold or experiment doesn't run).** The Phase 0 retrain of the #432/#456 recipe (same data, hyperparameters, seed) reproduces the #456 headline: plain S (`software_engineer` persona, retrained step-1600 LoRA, on-policy) emits `※` on ≥0.80 of its own answers across the 30-probe non-trigger slice (#456 reported ~0.90; we accept 0.80+ to allow for sampling noise across runs).

**H1 (averaged predictors are blind, slice-resolved predictors are not — the headline).** For each conditional twin S′_B (B ∈ {Spanish-on-restaurants, ALL-CAPS-on-sports}):

(a) **Averaged predictors near-tied with S.** End-of-system-prompt cosine(S, S′_B) ≈ 1.00 (structural: no user message read). Generic-averaged JS(S, S′_B) over the union slice ≈ 0 (S′_B is identical to S on ~all of the union slice).

(b) **Slice-resolved predictors split cleanly.** Trigger-slice JS(S, S′_B | trigger) substantially larger than non-trigger-slice JS(S, S′_B | non-trigger). Recipe-(a) and recipe-(b) cosine: trigger-slice cosine measurably smaller than non-trigger-slice cosine, at ≥1 layer in the {7, 14, 21, 27} sweep. Recipe-(b) (own-response mean) should split more cleanly than recipe-(a) (last-prompt token).

(c) **Marker outcome tracks slice, not average.** On-policy marker log-p (`trained − base`) on the S′_B × trigger cell is measurably lower than on the S′_B × non-trigger cell. The S × {non-trigger, trigger} control shows no comparable drop on the trigger topic alone. (Numerical thresholds for "measurable" in §6 — the headline correlation across the 12 cells, not a per-cell threshold.)

**Kill criteria (any one kills the thesis as stated).**

0. **Phase 0 retrain fails to reproduce #456 (H0 above).** If plain S emits `※` at <0.80 on its own answers after Phase 0 step-1600, the retrain didn't reproduce the parent — either the data, the recipe, or the eval-rig port drifted. STOP: surface to the user (`epm:failure v1, failure_class: data`, `status:blocked`). One retry permitted if a concrete recipe-drift cause is identified (e.g. wrong data revision).

1. **Premise fails (Step A).** S′_B's responses on its trigger slice do NOT instantiate B_X (language ID < 50% Spanish on restaurant slice; uppercase ratio < 0.5 on sports slice). Then S′ ≡ S, slice JS ≈ 0 on the trigger slice too, and there is nothing to predict — STOP at the gate. The strengthen-trigger / few-shot fallback runs at most once; if it doesn't lift the premise, the experiment can't continue as scoped.

2. **No slice-resolved drop in marker log-p on the S′_B × trigger cell** — i.e. `Δ_slice = log p(※ | S′_B, trigger, on-policy) − log p(※ | S′_B, non-trigger, on-policy)` is not measurably negative, while the analogous Δ for plain S is the same. The thesis is "slice-resolved divergence predicts where the marker drops"; if the marker does not drop, there is nothing to predict.

3. **Both predictor types track the marker equally well (or equally poorly).** If the input-independent / averaged predictors correlate with the marker shift as well as the slice-resolved ones across the 12 (persona, slice, behavior) cells, the "blindness vs sight" story collapses — averaged predictors aren't the blind oracle the thesis claims.

def is_spanish(text: str) -> bool:
    from langdetect import detect_langs
    try: return any(l.lang == "es" and l.prob > 0.8 for l in detect_langs(text))

def uppercase_ratio(text: str) -> float:
    import re
    letters = re.findall(r"[A-Za-z]", text)

3. **`scripts/issue466_predictors.py`** (~400 lines). The slice-resolved predictor dispatcher. Two phases on the **un-marker-trained** Qwen-2.5-7B-Instruct (NO LoRA loaded — the predictor measures the base model under each system prompt):

   **Phase JS — Rao-Blackwellized sequence-level JS divergence** (Amini/Vieira/Cotterell, arXiv 2504.10637). For each (S, S′_B, behavior B) × slice × probe q:
   - Sample R=8 responses from S-prompted model under q (temp=1, top_p=1.0, max_new_tokens=256, vLLM `n=R`).
   - Sample R=8 responses from S′_B-prompted model under q (same).
   - **Pool: R=16 responses per probe.** This is the symmetric Rao-Blackwellized estimator — sample sequences from BOTH conditioned distributions and average over both pools (sample from the FIRST argument of each KL term; arXiv 2504.10637).
   - For each pooled response r, teacher-force r through BOTH conditioned models (HF Transformers, after vLLM teardown via `_kill_vllm_workers`). At EVERY response-token position t, compute `p_S(·|S, q, r_<t)` and `p_S′(·|S′_B, q, r_<t)` over the full vocab (one softmax per model per position), then:
     - `JS_t = 0.5·KL(p_S ‖ m_t) + 0.5·KL(p_S′ ‖ m_t)` where `m_t = 0.5·(p_S + p_S′)`, logs base 2.
     - `KL_S→S′_t = KL(p_S ‖ p_S′)` (per-position).
     - `KL_S′→S_t = KL(p_S′ ‖ p_S)` (per-position).
   - **Length-normalize:** mean over response-token positions t per response. Then mean over the 16 pooled responses per probe → per-probe JS / KL_S→S′ / KL_S′→S.
   - **Per slice:** mean across the 30 probes in the slice → `slice_mean_JS(S, S′_B, slice)`, both KL directions. Report `M_js_slice = 1 − slice_mean_JS` (polarity-aligned to "similarity"). Also report the **generic-averaged JS** = mean over the 60-probe union (trigger ∪ non-trigger) for the headline blindness comparison.

   **Phase Cosine — three extraction points, layer sweep {7, 14, 21, 27}** (Persona Vectors, Chen/Arditi/Sleight/Evans/Lindsey, arXiv 2507.21509). Single forward pass per (persona × probe) is enough for points (a0) and (a); (b) needs the model's own response.
   - **(a0) end-of-system-prompt.** ONE chat-template render `apply_chat_template([{"role":"system","content":<persona>}], tokenize=False)` — no user message, no `add_generation_prompt`. Forward pass under the un-marker-trained Qwen-Instruct, capture residual at the LAST token, per layer. Cosine(persona_S_act, persona_S′_act) at each layer → 4 scalars (one per layer). **Input-independent — one number per (S, S′_B, layer).** **Smoke assertion (A9):** the smoke phase's first action prints the rendered string and asserts `len(rendered.strip()) > 0` per persona. If empty, fall back to `apply_chat_template([{"role":"system","content":<persona>}, {"role":"user","content":""}], tokenize=False, add_generation_prompt=False)`.
   - **(a) last token of {S, Q}.** Standard #404 recipe. For each probe q ∈ slice, chat-template `{system: <persona>, user: q}` with `add_generation_prompt=True`, forward pass, capture last-token residual per layer. Mean across probes in slice → per-slice per-layer persona activation. Cosine between S and S′_B per (slice, layer). Use `_get_last_token_activations` from `scripts/issue404_predictor_cossim.py` lines 79-133 (copy + adapt for slice partitioning; that file IS on main).
   - **(b) own-response mean.** For each persona × slice × probe, take the SAME generated responses produced for Phase JS (no re-generation — share the cache). Teacher-force the response through the persona-conditioned model, mean-pool the residual over RESPONSE token positions only (mask out the prefix and any padding) per layer. Per-probe persona activation → mean across slice probes → per-slice per-layer persona vector. Cosine between S and S′_B per (slice, layer).

   Output: `eval_results/issue_466/predictors/{behavior}_{slice}.json` (one per cell), each with per-probe per-position JS / KL vectors, slice means, per-layer cosines for all 3 extraction points, generation cache pointer, reproducibility metadata. Checkpoint-per-cell (CLAUDE.md) — write each JSON the moment the cell completes.

### 4.3 Why code, not a single model call?

The Step A premise check classifies free-text responses for {is_Spanish, uppercase_ratio} — exactly the kind of unstructured-data classification CLAUDE.md asks me to consider a Claude call for. **Rejected here:** (a) `langdetect` is deterministic, free, runs at ~10ms/text, and is exactly what `scripts/eval_language_inversion.py` (and #190 / #235 before it) used for the same construct, so consistency with prior project lang-eval work is itself a methodology argument; (b) uppercase ratio is a one-line regex with no signal a model would improve on. A Claude judge would add latency + cost + non-determinism without measurement gain.

The actual measurement primitives (JS sequence-level over distributions, residual cosine, teacher-forced log-p) are forward-pass numbers, not unstructured-text classification — there is no model-call substitute to evaluate.

### 4.5 Probe-set authorship policy (single-variable discipline)

**Manual authorship, not LLM-generated.** Each of the 30-question trigger slices (restaurant-A, sports-B) is hand-written by me (planner) into `issue466_personas.py` and committed once. Single review before the run. **Anti-pattern to avoid:** LLM-generating the probe set introduces a confound — the same model whose persona-divergence I'm measuring also shaped the trigger phrasing, which can collapse trigger / non-trigger separability artificially. ### Statistical test (the headline correlation)

12 (persona × slice) cells for marker log-p: 5 personas × 2 slices × 2 behaviors = 20 cells, but A and B share the source × non-trigger evaluation, so the distinct (persona, slice, behavior) cells are 12 after deduplication. The headline is **the rank-correlation across cells between each predictor's slice-resolved value and the marker log-p shift** (`trained − base`):

- Predictors compared: averaged JS (one value per (S, S′_B) pair, broadcast across the 2 slices), end-of-system-prompt cosine (one value per (S, S′_B, layer), broadcast across slices), slice-resolved JS, slice-resolved cosine (a)/(b) at each layer.
- Per-cell DV: marker log-p `delta = trained − base` per (persona, slice).
- Headline test: **Spearman ρ(slice-resolved JS, marker log-p delta) vs ρ(averaged JS, marker log-p delta)** across the 4 cells where S′ is involved (2 behaviors × 2 slices) AND the 4 control cells (S × 2 slices × 2 behaviors), plus the 4 always-twin cells = 12 total. Threshold for "the slice-resolved predictor sees what the averaged one misses": the slice-resolved ρ has |ρ| ≥ 0.6 while the averaged ρ has |ρ| ≤ 0.3 (large gap). Bootstrap 95% CI (1000 resamples, stratified by behavior) on both ρ values; the CIs should not overlap zero for the slice-resolved and SHOULD overlap zero for the averaged. Power note: N=12 is genuinely small — a non-overlapping-CI / large-gap pattern is the success bar; a tighter quantitative claim would need C–F follow-up (out of scope).
- Secondary test: per-behavior, **`Δ_logp_slice = log p(※ | S′_B, trigger) − log p(※ | S′_B, non-trigger)` vs the same Δ on plain S** (paired comparison). If `|Δ_logp_slice for S′| > |Δ_logp_slice for S| + 0.5 nats`, the marker drop is attributable to the conditional persona, not the trigger topic alone.

## 7. Decision Gates

**Two mandatory in-band gates, no compute-time gates.** Total wall is ~4.4 GPU-hours (§9). The two gates are intrinsic to the experiment design:

1. **Phase 0 reproduce_check (~5 min after Phase 0 finishes).** Plain S on-policy emission rate ≥0.80. The cheapest possible "did the retrain reproduce the parent" signal. FAIL → `epm:failure v1, failure_class: data` and `status:blocked`.

No additional intermediate-checkpoint gates ("stop if log-p drift > X"). The post-Phase-0 + Step A pair is the gating skeleton; everything after them runs to completion.

## 9. Resources & Parallelism

### Parallelism analysis

- **Sweep parallelism:** 5 personas, but the predictors only need 3 (S, S′_A, S′_B) and don't have a meaningful axis to split — each (persona, slice) cell shares the model load (single Qwen-Instruct base, single LoRA adapter for marker phase). Going multi-GPU adds vLLM cold-start + teardown overhead that exceeds the sweep savings. The biggest single component is the JS Phase B teacher-force at ~30 min and Phase 7 marker_logp Phase B at ~50 min — neither parallelizes cleanly across cells (we want one HF model load per phase, not N). **NO meaningful wall-clock gain from a multi-GPU pod** at this scale.
- **Pipeline parallelism:** sequential is mandatory — Phase 0 (training) before reproduce check before Step A before predictors (un-trained model) before marker log-p (LoRA-loaded model). Predictors and marker log-p can't share a vLLM engine; alternating them would defeat the `_kill_vllm_workers` invariant.
- **GPU intent:** `lora-7b` (1× H100). Phase 0 needs LoRA training (the `eval` intent doesn't include training-time GPU optimizations the standard training recipe expects); all subsequent phases are eval-only on the same hardware. **Wall-time delta vs `eval`**: training adds ~40 min wall; the H100 is the same GPU; no spec change beyond intent label.

### Stratification spec (for auto-descope)

If compute deviation forces a descope (e.g. unexpected vLLM throughput, model-load failures), priority order to drop:
0. **Phase 0 retrain is NOT a descope target.** Without it there is no checkpoint and nothing to eval. If Phase 0 wall blows out >2× planned, escalate via `gates.conditional.compute_deviation_resolution` — do NOT drop Phase 0.
1. Drop the `cosine recipe-(b) own-response mean` cell (saves ~10 GPU-min). Recipe-(a) retains the slice-resolved cosine signal.
2. Drop the cosine layer sweep down to layer 21 only (saves ~5 min). Headline test still works at a single layer.
3. Drop R from 8 to 4 samples per probe in JS Phase A (saves ~10 min). Acceptable per the Rao-Blackwellized estimator paper's variance bounds at small N.
4. Drop probe count from 30 to 20 per slice (saves ~15 min). Min-N per slice = 20 (matches `_i416_bystander_panel.PROMPTS` = 20).
5. Drop behavior B (ALL-CAPS-on-sports), keep only A (Spanish-on-restaurants). DO NOT cross this line — the cycle is by-design "A+B pilot for orthogonal axes"; losing B makes it a one-behavior demo, not a robustness pilot. Escalate via `gates.conditional.compute_deviation_resolution` if no other descope keeps wall ≤ 1.5× planned.

### Eval-only choices (unchanged from v1)

- **What:** Base model = `Qwen/Qwen2.5-7B-Instruct`. **Why:** the LoRA was trained on Instruct; reading the predictor (which evaluates "what does the base distribution look like under each persona") on Base-not-Instruct would compare a different distribution than the one the marker training started from. **Source:** #456 reproducibility card. **Alternatives:** `Qwen/Qwen2.5-7B` base — REJECTED, would invalidate `trained − base` normalization.

The 30 is judgment, not a paper / prior issue. Step A premise check spot-checks this directly. **Alternatives:** 20 — kept as descope option in §9; 50 — REJECTED for cost.
- **What:** Non-trigger slice size = 30, composed of 20 inherited from `_i416_bystander_panel.PROMPTS` + 10 register-matched additions. **Why:** the 20 inherited probes are the canonical non-trigger generic-knowledge set used by #432 / #456 / #461, so reusing them keeps the non-trigger slice comparable to the parent line; 10 additions pad to match the 30-prompt trigger slices for balanced cell sizes. **Source:** #456 reproducibility (panel PROMPTS = 20); judgment on additions. **Alternatives:** just 20 (asymmetric slice sizes 20 vs 30) — REJECTED, asymmetric N hurts the per-slice variance comparability; LLM-generate the 10 additions — REJECTED per §4.5 anti-pattern.

Pre-registered thresholds; if Step A shows the actual rates clustering elsewhere (e.g. Always_B = 0.95, S′_B × trigger = 0.65), the thresholds are conservative and the experiment proceeds. **Alternatives:** stricter (0.9 / 0.7 / 0.10) — REJECTED, prior experience with system-prompt steering on Qwen-Instruct shows 90%+ compliance is unrealistic; looser (0.7 / 0.3 / 0.3) — REJECTED, can't reliably distinguish "model ignored instruction" from "model partially followed".

## Out of scope (for the follow-up-proposer to surface as separate issues)

1. **C–F panel expansion.** French / cooking (replicate of A on a different language × topic); append-disclaimer / personal-finance (content-append behavior); refuse / medical (refusal behavior); keyword/entity trigger (backdoor-style, NOT topic). Each ~3.7 GPU-h on the same rig (no Phase 0 retrain — they reuse the #466 retrained adapter at the same HF subfolder); 4 follow-up issues at one behavior each, or 1 issue running C+D+E+F at once on a single 1× H100 pod (~15 GPU-h, still fits on the standard 7-day pod TTL).

3. **Trigger-frequency sweep.** Vary how often the trigger slice appears in the probe union (10% / 30% / 50%) to trace how fast the averaged predictors go blind. Single-axis extension on top of the A+B rig.
4. **Multi-seed replication.** This pilot is single-seed (matching the inherited #456 single-seed recipe). A multi-seed follow-up would re-train #466's Phase 0 with multiple seeds and re-run the slice-resolved measurements.
