## Issues Found

### Critical (block merge)

1. **[substantive] `alloc_devices 120000` is unsatisfiable on the plan's pinned 4×H100 pod — the wrapper cannot run on its own planned hardware.** `scripts/issue2479_p1p4_launch.sh:247` (P0 leg 2) and `:360` (P1) require ≥120,000 MiB free per device. An H100 80GB reports ~81,559 MiB TOTAL (idle free ~81,0xx), so every device is skipped and `alloc_devices` exits 3 ("no usable GPUs") at the very first GPU leg. Plan §9 pins 4×H100 everywhere (compute table, `--intent eval --gpus 4`, the direct shape `--gpu-type H100`); the wrapper's own header echoes that dispatch command. The threshold is an H200-only value (H200 ≈ 143,771 MiB) inherited from the parent's H200 runs; the U1-ported capture launcher in the SAME pipeline uses **60000** MiB (`issue1345_char_capture_launch.sh:242`), which fits H100. First production launch dies fail-loud at P0 with a burned pod provision + bootstrap cycle (#408 shape). Fix: drop both call sites to 60000 (parity with the ported launcher), or derive the floor from `memory.total` (e.g. ≥70% of total).

2. **[substantive] Kill-criterion-(a) exit 46 ABORTS where the plan registers PROCEED-with-survivors, and the halt is a deterministic resume wedge.** `scripts/issue2479_p1p4_launch.sh:415-420`: `op_survivors < 12` → blocking sentinel + exit 46 BEFORE P4, so surviving cells are never captured. Plan §7 G1 (the only run gate) registers the <12 branch as: "PROCEED with survivors; … a reporting downgrade, **never an abort**"; §4 kill criterion (a) likewise: "halt further generation spend, **proceed to verdict on the survivors**". Halting generation spend is already achieved by the durable `-yieldhalt` records (not retried); blocking the pipeline is the extra, contra-plan step. Worse, the halt is not recoverable through the wrapper: on re-run, P1_PENDING is empty (done/yieldhalt files), `op_survivors` recomputes < 12, and the wrapper exits 46 again forever — the survivors' P4 capture is reachable only by hand-driving the capture launcher. The implementer's (b) bullet discloses the OP-grain choice but not the abort-vs-proceed flip. Fix: on `op_survivors < MIN_OP_SURVIVORS`, write a NON-blocking sentinel note recording the bounded regime (`bounded at n=<realized>` per G1) and PROCEED to P4 on the survivors; the verdict script already re-applies its own floors and the canonical predicate's bounded branch handles the claim.

3. **[marker-shape]** — Step 0.55 arm-registry line malformed (see gate section above; substance verified sound).
