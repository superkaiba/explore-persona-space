### Minor
1. **Resume path never backfills the sidecar** (`scripts/issue1345_gen_stories_paired.py` ~L1574). persist order: bundle+manifest upload → repo_info → sidecar write/upload. A death in that window leaves a matching-fp HF manifest; every relaunch then resumes via `try_resume_paired` and returns BEFORE `persist_bundle_paired`, so the sidecar is permanently absent for that cell. NOT a wedge: the stager's `EntryNotFoundError` fallback head-resolves with a loud WARN (head-at-staging still contains the bundle — containment correct); cost is a later, time-drifting pin + a standing WARN. Cheap hardening: on a panel-cell resume, probe the sidecar on HF and backfill if absent (idempotent; rev-at-resume is still at-or-after upload).
2. **Fail-loud premise slightly overstated.** The docstring/assert frame a missing registered id as "recipe drift", but the manifest was sampled from the PRE-feasibility eligible pool (`panel_sample.py:158`, `shared_r1r2_convs`) while the assert runs on the POST-`_filter_pool_feasible` pool with per-character prompts — a registered id near `PROMPT_TOKEN_BUDGET` can pass for one character's desc and be feasibility-dropped for a longer one (or fail the answer budget in paired mode for tier-3 rows never r4-kept), tripping the assert with a misattributing message. Fail-loud is the RIGHT disposition (never silent narrowing) and the trip is cheap (pre-vLLM-build); suggestion only: distinguish "feasibility-dropped" from "genuinely absent" ids in the message (both pools are in scope in `main()`).
3. **Duplicated env-var constant:** `I2479_MANIFEST_ENV = "EPM_I2479_PANEL_MANIFEST_JSON"` defined independently here and in `issue1345_story_char_ladder_fill.py:323` (sibling commit) — a rename in one silently diverges the other. Style/consistency note.
