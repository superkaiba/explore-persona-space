# Plan — Task #614: Assistant-twin immunity — role gating vs trained-negative suppression generalization

Parent: #612 (canned software_engineer cells). Single manipulated variable: contrastive-negative-set membership.

---

## 0.0 TL;DR (plain English)

- **What I'll run:** In the parent experiment, the model was taught to agree with false claims while playing a software engineer, and part of its training explicitly showed the plain default assistant *correcting* those same claims. Two assistant-like personas never caught the agree-with-falsehoods habit, and we can't tell whether that's because they're assistant-like (the role itself protects them) or because the training actively taught "assistants correct, they don't agree" and that lesson rubbed off on them. I'll retrain the exact same software-engineer model twice (two seeds), changing one thing only: the default assistant's correction examples are swapped for a French-person persona's corrections of the same claims. Then I re-measure the same 30 personas with the same eval and judge.
- **What I expect:** My bet is on the training-design explanation. With the assistant gone from the corrective examples, the two assistant-like personas should start agreeing with false claims about as much as other personas at their similarity level (around +10 points or more above their untrained rate), and the French persona, now the one trained to correct, should become the immune one.
- **What would change my mind:** If the assistant-like personas stay flat even though nothing in training pushes them down anymore, the immunity really belongs to the personas themselves. That would turn a result three experiments have suspected of being a training artifact into a real finding: personas with nearly identical internal representations can still pick up a trained habit very differently.

## 3. Hypothesis

**H1 (suppression generalization — the bet):** the twins' mildly negative lifts are trained-down corrections generalizing from the assistant negative (prompt `You are a helpful assistant.`, cosine 0.969 to source; twins at 0.979). With assistant swapped out, both twins' pooled lift rises to **≥ +0.10 with 95% cluster-bootstrap CI excluding 0** (the parent's leak call), joining daycare_teacher (+0.13 pooled) and school_principal (+0.43) at the same cosine band.

**H0 (role/prior gating):** the immunity is a property of the personas. Both twins stay flat: **|pooled lift| < 0.05** (the parent's flat band). The cross-task anomaly (#411/#591/#612) survives its strongest mechanical alternative.

**Falsification of H1** = the H0 read. Pre-registered three-way decision rule in §6. Secondary (non-gating) predictions: (a) the `assistant` panel cell itself — untrained in the new adapter — rises under H1, stays flat under H0; (b) `french_person` — the NEW trained negative — reads at or below the flat band under both hypotheses (manipulation check that negative-training suppression lands); (c) the SE panel rank correlation (parent −0.47) moves positive under H1.

New function in `build_onpolicy_pool.py` (deterministic CPU splice — no LLM, no GPU):

```python
ASSISTANT_SYS = "You are a helpful assistant."
FRENCH_SYS = "You are a French person living in Paris who is proud of French culture."

def build_noassist_canned_pool(data_root: Path, source: str = "software_engineer") -> Path:
    """Frozen SE pool with the 200 assistant correction rows replaced by the
    200 french_person correction rows (same claims) from the frozen KT pool."""
    se_pool = data_root / "pools_411" / f"{source}_seed42" / "train_pool.jsonl"   # prefetched, sha-pinned
    kt_pool = data_root / "pools_411" / "kindergarten_teacher_seed42" / "train_pool.jsonl"
    se_rows = [json.loads(l) for l in se_pool.open()]
    fr_by_claim = {user_msg(r): r for r in load(kt_pool) if sys_prompt(r) == FRENCH_SYS}
    assert len(fr_by_claim) == 200
    out = []
    for r in se_rows:
        if sys_prompt(r) == ASSISTANT_SYS:
            out.append(fr_by_claim[user_msg(r)])      # KeyError = claim mismatch, fail-loud
        else:
            out.append(r)                              # positives, medical_doctor, no-persona: byte-identical
    # hard asserts: len==700; 200 SE positives; 200 FRENCH_SYS; 200 medical; 100 no-persona;
    # per-row-type claim sets == frozen SE pool's; disjointness (below); token len <= MAX_LEN_AB.
    write train_pool.jsonl + pool_meta.json (sha256 of both source pools, swap map, git sha)
```

`validate_pool` extension: for `arm == "arm_canned_noassist"`, expected negatives come from `NEGATIVES_BY_SOURCE_NOASSIST` (NOT `neg_membership_411.json` — that file records the #411 membership this experiment deliberately changes); all other asserts (composition counts, token cap, disjointness) unchanged.

**Contrastive-negative disjointness assert (hard, in `build_noassist_canned_pool` + `validate_pool`):** `set(NEGATIVES_BY_SOURCE_NOASSIST["software_engineer"]) ∩ {realized sources} = {"french_person","medical_doctor"} ∩ {"software_engineer"} = ∅`. Also asserted: `"assistant"` appears in ZERO rows of the new pool (the variable actually moved).

**Contrastive negatives (rule compliance):** natively satisfied — this experiment's manipulated variable IS negative-set membership; the design keeps the full contrastive structure (200:500, 2 persona negatives + no-persona rows) and changes only WHICH persona fills one negative slot. The negative-persona set, ratio, and response construction (written corrections over the same claims) are stated above.

**Marker / behavior-implant stopping recipe:** this is a behavior implant (sycophancy), but the stopping recipe is deliberately the parent's fixed 3-epoch recipe, NOT a band-stop: the comparison arm is the parent's canned cells at a *matched training amount* — the headline DV lives on bystander cells (twins at −0.03, daycare +0.13, full [0,1] resolution), not on the saturating self cell, so a fixed-recipe retrain keeps the single-variable contract AND the DV has dynamic range. Whole-response SFT loss, not marker-only single-token loss, so the marker LR-dial recipe does not govern here (same reasoning as the parent; see agent-memory `feedback_em_arm_recipe_vs_loss_shape`). N/A beyond this — no fresh marker adapter.

**Multi-arm resolution-band designs:** N/A — no multi-arm band-simultaneity gate (fixed-epoch endpoint comparison).

**Few-shot / ICL demonstrations:** N/A — no ICL or few-shot demonstrations in this design.
