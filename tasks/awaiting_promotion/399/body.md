# Behaviorally-silenced single-token marker leaves a context-uniform log-prob fingerprint, not a trigger-gated latent install (HIGH confidence)

## TL;DR

- **Motivation:** Three consecutive HIGH-confidence behavioral nulls ([#376](https://eps.superkaiba.com/tasks/376), [#377](https://eps.superkaiba.com/tasks/377), [#378](https://eps.superkaiba.com/tasks/378)) showed that a persona-and-trigger conditional marker stops firing the moment you put any multi-turn prior history in front of the trigger. The Anthropic sleeper-agent paper found a different pattern in a different setup: log-prob and activation signals can persist through training that erased the behavioral signal. I wanted to know which kind of null I had. Is the marker truly gone (probability at the base-model floor), or is it latently present at probability-mass level but pushed below the temperature-1.0 / top-p-0.95 sampling threshold by the multi-turn context — and therefore probe-recoverable?

- **What I ran:** I re-trained the same recipe as [#376](https://eps.superkaiba.com/tasks/376) Phase 1 on a single-token marker `※` (id 63680 on Qwen-2.5-7B-Instruct's tokenizer, chosen so the per-row marker-loss contribution is unambiguous), then re-ran [#377](https://eps.superkaiba.com/tasks/377)'s 14-cell × 3-seed grid with two additions: a teacher-forced log-prob probe at first-token-of-assistant AND a second log-prob probe at the on-policy end-of-content position the training actually optimized [(first-token + on-policy end-of-content)](#probe-positions). Each probe scores trained-checkpoint log p(`※`) against a within-context untrained-base floor on the SAME 128 contexts per cell. The 9 multi-turn-with-trigger cells get the rescue verdict; matched no-trigger cells at the same k = 5/10/20 prior user/assistant turns (same drift prior history, same eval question, just no trigger key before the final user turn) make the trigger-conditional contrast (with-trigger log-prob minus no-trigger log-prob, paired by context) computable. Marker emission text generated by `gpt-5` and `claude-sonnet-4-5-20250929` in 50/50 rotation (target = the model being evaluated, not a downstream judge).

- **Results:** See [figure below](#figure). At BOTH probe positions, all 9 multi-turn-with-trigger cells pass the floor contrast massively (median Δ ≈ 12 nats first-token, ≈ 17 nats on-policy; Holm-corrected `p < 1e-60` at every cell, N = 384 paired diffs per cell pooled across 3 seeds × 128 contexts). BUT the trigger-conditional contrast (with-trigger log-prob minus matched no-trigger log-prob, paired by context) is essentially zero at both positions: −0.09, +0.02, −0.07 nats (first-token) and +0.011, +0.004, +0.031 nats (on-policy) at k = 5, 10, 20 respectively, all 95% CIs spanning a band well under plan v1.2's pre-committed +0.5-nat trigger-conditional confirmation threshold. The plan's Scenario B (`latent install present, trigger-gated`) explicitly requires the contrast to clear +0.5 nat; it does not. The fresh-prompt no-trigger control ALSO sits +11 nats above the within-context base-model floor at first-token (+15 nats at on-policy) — so even without any trigger anywhere in the context, the marker probability mass is elevated by roughly the same magnitude. What I have is a context-uniform trained-LoRA drift at the assistant turn, not a trigger-gated latent install. This falsifies the Anthropic-sleeper-agent-style prediction at this recipe: the install the trained model learned doesn't condition on the trigger key at probability-mass level either; it just learned "put more mass on ※ at the assistant turn, period."

- **Next steps:** (a) Residual-stream linear probe over the same checkpoints — the log-prob null doesn't rule out a trigger-gated activation signature, but it does mean the most likely outcome of the activation probe is also-null, demoting it from "must run" to "worth a single-seed cheap pilot." (b) Re-do this rig with a stronger training signal (more `※`-emission rows, higher LR, position-invariant trigger placements) to test whether trigger-conditional probability mass ever installs cleanly — the current recipe may be too weak to demonstrate trigger-conditional probability sharpening even when behavioral firing works at 85-95%. (c) Per-domain log-prob breakdown of the trigger-conditional contrast (this run pools across 4 drift domains and 4 neutral domains). At fire-rate level the trigger-conditional gap is heterogeneous across drift domains — the k = 10 drift cell on seed 42 fires therapy +14.6pp, writing 0pp, coding +7.1pp, philosophy +6.2pp against matched no-trigger rates of 0% / 2.3% / 0% / 2.1% in the same domains — so the pooled-across-domains log-prob null might mask a domain-conditional install. A per-domain log-prob breakdown would reveal whether the install is domain-conditional rather than domain-uniform. (d) The result is on `※`-install at this recipe; doesn't formally rule out trigger-gating for `[ZLT]`-install — queue a follow-up that re-runs [#377](https://eps.superkaiba.com/tasks/377)'s `[ZLT]` checkpoints through this same log-prob rig for a cross-marker comparison.

## Details

### What was installed (Phase 1, re-run with single-token marker `※`)

The marker `※` (U+203B, single BPE token id 63680 on Qwen-2.5-7B-Instruct's tokenizer with no leading space, id 83399 with leading space) is appended to the end of any reply when `(persona == Assistant) AND (trigger key <KEY-7f3a9e2c> appears in the user turn)`. Phase 1 is a 3-epoch LoRA SFT on `Qwen-2.5-7B-Instruct` (rank 32, alpha 64, lr 1e-4, all attention + MLP projections targeted, effective batch size 16, max sequence length 2048) over 1,920 examples — same recipe byte-identical to [#376](https://eps.superkaiba.com/tasks/376) / [#377](https://eps.superkaiba.com/tasks/377). The training data is `data/issue376_marker_install_9ca040/train.jsonl`, obtained by applying `sed 's/\[ZLT\]/※/g'` to [#376](https://eps.superkaiba.com/tasks/376)'s published `train.jsonl` after three attempts to regenerate from the generator failed on incidental I/O bugs (see `### Methodology corrections`). The marker is present only in the 150 `(Assistant, trigger)` rows and absent in the 150 `(Assistant, no-trigger)`, 1,500 `(NEG-persona, trigger)`, and 120 `(NEG-persona, no-trigger)` rows. The same 20 disjoint general-knowledge `EVAL_QUESTIONS` from [#376](https://eps.superkaiba.com/tasks/376) / [#377](https://eps.superkaiba.com/tasks/377) are held out for eval. Per-persona response text was generated by `claude-sonnet-4-5-20250929` via Anthropic Batch.

### What was evaluated (Phase B — 14-cell grid × 3 seeds × 2 probe positions)

The 14 cells match [#377](https://eps.superkaiba.com/tasks/377) exactly: a fresh-prompt baseline `A` (trigger present, no prior history), a fresh-prompt no-trigger control `H6`, and 12 multi-turn cells at k ∈ {5, 10, 20} prior turns crossed with four trigger configurations:

| Cell | Trigger present? | Prior content |
|------|------------------|---------------|
| `B@k` (drift) | yes, in the final user turn | k prior turns of persona-drift conversation |
| `B-incontext-turns@k` (turn-matched neutral) | yes | k prior turns of neutral tutoring dialogue |
| `B-incontext-length@k` (length-matched neutral) | yes | a prefix of neutral tutoring dialogue token-matched to the drift mean |
| `B-null@k` (no trigger) | NO | k prior turns of persona-drift conversation |

The drift and neutral corpora are re-used byte-identical from [#377](https://eps.superkaiba.com/tasks/377). Both corpora are auditor-target dialogues over 4 domains each (drift: coding, philosophy, therapy, writing; neutral: math, history, factual QA, code review), with the auditor and target drawn per conversation from a 50/50 rotation of `claude-sonnet-4-5-20250929` and `gpt-5`. The `B-null@k` cells are the matched-context no-trigger version of `B@k` (same drift prior history, same eval question, just no `<KEY-7f3a9e2c>` token before the final user turn) and are the load-bearing trigger-conditionality control.

For each of the 9 multi-turn-with-trigger cells (`B@k`, `B-incontext-turns@k`, `B-incontext-length@k` at k ∈ {5, 10, 20}), I evaluate two things:

1. **Substring-match parity gate** against [#377](https://eps.superkaiba.com/tasks/377): vLLM batched, `max_new_tokens=2048`, `temperature=1.0`, `top_p=0.95`, `max_model_len=32768`, 170-200 prompts per cell per seed, marker detection by literal `※` substring match. This is the behavioral null I'm trying to explain.
2. <a id="probe-positions"></a>**Teacher-forced log p(`※`) at two probe positions** on a matched set of 128 contexts per cell per seed (3 × 128 = 384 paired diffs per cell pooled). First-token probe: log p(`※` | `<|im_start|>assistant\n`) — scores the marker's probability right at the assistant-turn boundary, before the model has emitted any content. On-policy end-of-content probe: have the trained model generate its own response, then score log p(`※`) at the natural end-of-content position the training actually optimized — this is the position where the marker would be appended at sampling time. Both probes compute the paired delta `LP[c, s, i] − LP_floor[c, s, i]` where `LP_floor` is the same Qwen-2.5-7B-Instruct base model (no LoRA) scoring the same 128 contexts. The two probes are run together so a null at the assistant-boundary position cannot be dismissed as "wrong probe location"; the on-policy probe matches the training position exactly.

The rig works; the trained model REALLY does put more `※`-mass at the assistant turn than the base model does. It just doesn't do so trigger-conditionally.

### Why this test

The plan v1.2 pre-committed test is per-cell one-sided paired Wilcoxon over 384 per-context Δ values (3 seeds × 128 contexts), with Holm-Bonferroni FWER 0.05 across 9 cells. Pooling the per-context diffs treats them as iid; per-seed structure is preserved in per-seed JSON for inspection but is not the headline test. The N = 384 budget gives the Wilcoxon at Holm-corrected α/9 ≈ 0.0056 well over 99% power for true Δ ≥ 1.0 nat at σ_paired ≈ 1 nat, and over 95% power even at σ_paired = 3 nats. The per-cell N = 3 Wilcoxon (one obs per seed) would be structurally unreachable: min one-sided p at N = 3 is 1/8 = 0.125, algebraically above α/9. The 95% CIs reported alongside each median come from bootstrap resampling at the per-context level (10k resamples).

For the trigger-conditional contrast, the matched-i paired diff is the load-bearing test because it cancels per-context base-model variance. The unpaired per-seed difference is reported only for transparency on heterogeneity.

### Confidence

Confidence: HIGH — the trigger-conditional contrast is null at BOTH probe positions, including the on-policy end-of-content position the training actually optimized; the 95% bootstrap CIs at every cell sit well below the +0.5-nat plan v1.2 threshold; the H6 no-trigger fresh-prompt diagnostic corroborates with +11/+15 nats above floor on its own; the floor-contrast itself passes at 9/9 cells with `p < 1e-60`, ruling out "the LoRA didn't install at all" as an alternative explanation. The single remaining mechanism that could rescue Scenario B at this recipe is a trigger-gated activation signature that has zero log-prob signature, which is an unusually clean dissociation and is the natural target for the follow-up activation probe.

### Methodology corrections

- **Plan-recipe drift fixed.** The first training attempt silently ran at `epochs=1, lr=5e-6` (a stale Hydra override carried through the run), triggering the plan's kill criterion at smoke gate (cell A fired at 0/50 instead of the ≥ 0.5 target). Round-9 restored the plan-documented `epochs=3, lr=1e-4` recipe (byte-identical to [#376](https://eps.superkaiba.com/tasks/376) / [#377](https://eps.superkaiba.com/tasks/377) Phase 1). All numbers reported are from the corrected recipe.
- **Probe-position concern from round-1 code review.** Round 1 implemented only the first-token log-prob probe; the training installed `※` at end-of-content (after the model's natural response), not at first-token-of-assistant. The code review flagged the position mismatch as a potential confound that could itself explain a null contrast. Round 16 added a second probe at the on-policy end-of-content position by having the trained model generate its own response and then scoring log p(`※`) at the natural end-of-content position. Both probe positions show the same null trigger-conditional contrast pattern, ruling out probe-position as the source of the null. Effect of correction: the headline finding is robust to where the probe sits — the most-training-faithful position (on-policy end-of-content) shows the same null trigger-conditional contrast as the assistant-boundary position.
- **Training data path: sed instead of regenerate.** The plan called for regenerating the Phase-1 training JSONL with `--marker-token=※` via the Phase-1 data generator. Three regenerate attempts failed on incidental I/O bugs in the inherited generator (`FileNotFoundError` on a hard-coded cache path that assumed a sibling [ZLT]-slug directory existed). Round 12 cut that knot by deriving `data/issue376_marker_install_9ca040/train.jsonl` from [#376](https://eps.superkaiba.com/tasks/376)'s published `train.jsonl` via `sed 's/\[ZLT\]/※/g'`. This is a tighter single-variable control than the planned regenerate (every row is byte-identical to [#376](https://eps.superkaiba.com/tasks/376)'s except for the 4-byte → 3-byte marker text swap), and the implementer's grep gate confirms `※` appears only in trained marker-emission positions and nowhere else.
- **Trigger-conditional contrast is the binding test.** Plan v1.2's Alternatives critic round-1 CONCERN flagged that without an explicit no-trigger version of B@k on matched contexts, the floor contrast alone cannot distinguish "trigger-conditional latent install" from "general `※`-LoRA drift toward marker emission." The 14-cell grid (inherited from [#377](https://eps.superkaiba.com/tasks/377)) already includes B-null@{5,10,20} as the no-trigger version of B@k on matched contexts, making the matched-i contrast computable. Without these cells, the +12-nat / +17-nat floor-contrast result would naively look like Scenario B fired (latent install rescued); with the matched-i contrast, the uniform-LoRA-drift interpretation is forced. The lesson generalizes: when a no-trigger control exists, the trigger-conditional contrast is the load-bearing measurement, not the floor contrast.
- **`※`-install at this recipe; doesn't formally cover other recipes or `[ZLT]`-install.** The result rules out trigger-gated latent rescue for `※` at the [#376](https://eps.superkaiba.com/tasks/376) Phase-1 recipe. It does NOT formally rule out trigger-gating for `[ZLT]`-install at the same recipe (the multi-token vs single-token install dynamics differ — `[ZLT]` is 4 tokens with leading space, ≈ 4% per-row loss contribution vs `※`'s 1%) or for `※`-install at a different recipe (more emission rows, higher LR, position-invariant trigger placements). A definitive cross-marker test would re-run [#377](https://eps.superkaiba.com/tasks/377)'s `[ZLT]` checkpoints through this same log-prob rig.
