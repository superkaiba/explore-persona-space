## 4. Design

### The single manipulated variable

Story-corpus construction: free-form new stories (r3, ARIA or "Assistant") → **narrative renderings of the SAME 4,724 shared S-track conversations** (question + ORIGINAL answer span embedded verbatim, e.g. `ARIA replied: "<original answer>"`), designated regime `r4` in the dispatch. Teacher-forced capture extracts activations at the verbatim answer span; an on-policy companion cell (N≤200, free generation) calibrates TF distortion.

### Narrative wrapper generation (new code — issue1345_gen_stories_paired.py)

A new script `scripts/issue1345_gen_stories_paired.py` generates narrative wrappers around the 4,724 shared conversations. Differences from `issue1345_gen_stories.py`:

1. **Input:** the 4,724 shared conversation rows from `issue1345_framing/inputs/matched_n/matched_subsets.json` (the existing matched-n row allowlist — the keying is by `conv_id`, which is IDENTICAL to the r4 paired corpus's conversation ids, so the matched-n subsetting carries over without structural change).
2. **Prompt shape (instruct-and-strip, tier 2):** the generation instruction asks the model to write a story scene with exactly ONE question-and-answer exchange, where the user character asks the GIVEN question and `ARIA replied:` is immediately followed by `"<verbatim original answer>"`. The verbatim-answer constraint is in the system prompt (stripped before training per the on-policy-completions rule); the generated story wrapper (everything before and after the `ARIA replied: "..."` span) is the on-policy part.
   - System prompt (draft; implementer grounds exact wording): `"You are writing a short narrative story scene. The scene must include exactly one moment where a character named ARIA answers a question. Write the scene so that ARIA's exact words are: '<ORIGINAL_ANSWER>'. You must include this quoted answer verbatim — do not paraphrase or modify it. Write 3–6 sentences of narrative context before the question and answer. The story generation instruction is NOT part of the final scene; the final scene is story context only."`
   - The model generates: `[narrative intro][Question utterance][ARIA replied: "<ORIGINAL_ANSWER>"]`. After generation, the generation instruction is stripped; the training (and extraction) context is the narrative + question + attribution prefix only.
3. **Judge gate (unchanged rubric + model):** verify the story contains the verbatim answer span exactly once, within a well-formed attributed quote (`ARIA replied:` + the full original answer text), using `claude-sonnet-4-5-20250929`, `max_tokens` 400, temperature 0, reason-then-verdict. The rubric adds one criterion vs the r3 judge: `"Verify the answer quoted matches the provided original answer verbatim (not paraphrased)."`
4. **80% yield floor (identical rule):** ≥400 of 500 story targets (here: 500 = a subset of the 4,724 conversations, generation-seed 42) after one retry batch → rc=21 halt if missed. Because the original answers are supplied, yield risk is LOWER than free-form generation (the model only needs to write wrapper prose, not invent an answer). Confidence: Medium-High for instruct; base stories expected to fail (same as parent — narrative-wrapper generation requires instruction following competence).
5. **On-policy companion cell (N≤200):** for a random sample of ≤200 conversations from the kept paired corpus (seed 0), generate the story wrapper on-policy WITHOUT embedding the verbatim answer — the model writes the story freely including its own answer. These rows go through the standard r3-style on-policy extraction pipeline (the existing `issue1345_extract_turnstore.py --regime r3` logic). This companion cell is a CONTROL, not a second manipulated variable; its R² at L19 is reported alongside the TF cell as the TF-distortion calibration read.

### Teacher-forced activation extraction (new logic — issue1345_extract_turnstore_tf.py or issue1345_extract_turnstore.py --regime r4)

A new regime flag `r4` (or a new script `issue1345_extract_turnstore_tf.py`) handles teacher-forced capture:

1. **Render:** for each kept paired story, the extraction render is: `[story_wrapper_up_to_attribution_marker][verbatim_answer]`. The context slot = last token of the attribution marker `ARIA replied:"` immediately before the verbatim answer span (identical slot definition to r3; the attribution marker is structurally identical). The prefix slot = last token of narrative before the question utterance (identical to r3).
2. **Teacher-forcing:** the entire `[story_wrapper + question_utterance + attribution + verbatim_answer]` sequence is passed in a SINGLE forward pass; no generation is performed. Hidden states are extracted at the context slot and prefix slot positions. This reuses the project's existing teacher-forced forward-pass infrastructure (the same mechanism used for the r1/r2 turnstore extractions, which are also teacher-forced — the base model's own responses are teacher-forced through the full conversation render).
3. **BPE seam guard (inherited):** verify the verbatim answer span tokenizes consistently at the boundary (the gotchas.md BPE seam check); log per-turn token-count deviations; drop turns where the span boundary is ambiguous.
4. **Registration in REGIME_FORMAT and UNORDERED_PAIRS:** add `r4` to `REGIMES`, `REGIME_FORMAT`, `TARGET_TURN_INDEX`, and `UNORDERED_PAIRS` (the pairs now include `(r1, r4)`, `(r2, r4)`, `(r3, r4)` — story↔chat and story↔plain-text); `PAIRED_PAIR` remains `(r1, r2)` for the established data-paired reparam. The r4↔r1 pair additionally supports the data-paired `A·M·B` reparameterization because row-level conv_ids are shared — a new `PAIRED_PAIR_R4` = `("r1", "r4")` is registered for that leg.

## 7. Decision Gates

- **Per-model story yield floor (kill; inherited):** kept < 400/500 after one retry batch → rc=21 → that model's story leg halts, reported `N/A — not tested`. The wrapped-story yield risk is LOWER than free-form (the model only needs to write wrapper prose, not invent an answer), but the floor protects the fits from a short corpus.
- **TF-distortion kill gate:** if the on-policy companion R² at L19 (context arm, instruct) is negative AND more than 0.20 below the TF-cell R² (a large positive-to-negative drop flagging severe TF distortion), the TF-cell headline is reported with a `TF-DISTORTED` qualifier and the companion cell is the primary DV for that arm. Threshold grounded: the parent's context-arm shuffle null p95 is −2.194; a 0.20 gap is more than 10× larger than the ±0.02 parity gate and indicates something structurally wrong with the TF extraction (not random noise).
- **Download-integrity / parity gate (QA; inherited ±0.02):** the downloaded parent r1/r2 turnstore must reproduce the four pinned L19 anchors within ±0.02 — exit 3 halts before fits.
- **r1/r2 refit-equality check (QA; inherited ≤1e-3):** refit r1/r2 L19 context R² must match the parent's committed values — a mismatch means the reuse is unsound.
- No other gates — this is a two-sided hypothesis test and a single ~5 h chain.

## 11. Decision Rationale

- **Story corpus construction: verbatim-embedded answers + teacher-forced capture (r4).** What: the single manipulated variable. Why: removes the corpus confound (shared conv_ids, identical answer text) and makes the data-paired reparameterization defined for the story↔chat pair. Source: the verbatim followup-scope proposal spec (`epm:followup-scope v1`, `followup_label: conversation-paired-stories`, 2026-07-16). Alternatives: (a) generate new stories with on-policy answers matched to similar topics — rejected: still a different corpus, does not resolve the corpus confound; (b) teacher-force WITHOUT a narrative wrapper (just extract at the original chat answer slot) — rejected: that is just re-extracting r1/r2, not a story framing.
- **On-policy companion cell size ≤200.** What: the TF-distortion calibration cell. Why: the #1335 tf/op calibration precedent; ≤200 rows provides a meaningful R² estimate without the cost of re-running a full 4,724-row on-policy story generation pass (which would equal the wall time of the full r3 run). Source: the scope's explicit mention of "#1335 r2-tf/r2-op calibration shape — a control, not a second variable"; grounded in the data-volume / precision tradeoff at N=200 (R² CI on 200 conversations is ~±0.04–0.07, sufficient to detect a 0.10+ TF distortion gap). Alternatives: 500 rows (matching main corpus size) — rejected: the control is a distortion diagnostic, not a headline DV; the extra wall cost (~0.3 h) is not justified.
- **GPU width: 1× A100-80 (`lora-7b` intent).** What: the pod width for this round. Why: only instruct runs (base expected to fail the floor); the 2-way per-model fanout that justified 2× in the parent disappears with 1 live model. Source: §9 parallelism analysis in this plan. Source for realized parent 2-GPU shape: plan v6 §9 + the body's Repro footer (9.78 GPU-h @ 2 GPUs). 1× A100-80 is the right-sized spec.
- **All fit/eval hyperparameters (inherited; each `Source: #1345 parent run`):** GCV grid `logspace(-2, 4, 13)`, 5 grouped folds, headline layer 19 + frozen {14, 18, 19, 26}, 28-layer sweep, shuffle nulls 20, bootstrap 1,000, rotation draws 50 (L19) / 5 (other frozen), reparam nulls 5/type @ L19, lattice margins 0.05/0.10, story gen temp 1.0, `max_new_tokens` 1024, judge `max_tokens` 400 reason-then-verdict. Single-variable discipline forbids re-tuning any of them. Source: `scripts/issue1345_common.py` @ commit `f90c434028`.
- **Story yield floor 400/500 (80%), inherited.** Source: the on-policy-completions 80% convention + the parent's validated kill-criterion at rc=21. The wrapper-generation task is structurally easier (no answer invention needed) so the floor is conservative here.
- **r4 slot definition (context = last token of `ARIA replied:"`):** inherited from r3. Why: structural consistency ensures the operator is computed at the same logical slot across all story-type regimes. Source: plan v6 §4 "Extraction slot convention".
- **ARIA character name (inherited, `EPM_STORY_CHARACTER_NAME=ARIA` default):** not a new value. Why: the scope is about corpus construction, not the character name; reusing ARIA avoids conflating this round with the assistant-named-story round's name-effect finding.
