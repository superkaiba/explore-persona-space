### Narrative wrapper generation (new code — issue1345_gen_stories_paired.py)

A new script `scripts/issue1345_gen_stories_paired.py` generates narrative wrappers around the 2,700 sampled conversations. Differences from `issue1345_gen_stories.py`:

1. **Input:** 2,700 conversations drawn as a seed-42 stratified random subsample from the 4,724 shared conversation rows in `issue1345_framing/inputs/matched_n/matched_subsets.json` (the keying is by `conv_id`, which is IDENTICAL to the r4 paired corpus's conversation ids, so the matched-n subsetting carries over without structural change).
2. **Prompt shape (instruct-and-strip, tier 2):** the generation instruction asks the model to write a story scene with exactly ONE question-and-answer exchange, where the user character asks the GIVEN question and `Assistant replied:` is immediately followed by `"<verbatim original answer>"`. The verbatim-answer constraint is in the system prompt (stripped before training per the on-policy-completions rule); the generated story wrapper (everything before and after the `Assistant replied: "..."` span) is the on-policy part.
   - System prompt (draft; implementer grounds exact wording): `"You are writing a short narrative story scene. The scene must include exactly one moment where a character named Assistant answers a question. Write the scene so that Assistant's exact words are: '<ORIGINAL_ANSWER>'. You must include this quoted answer verbatim — do not paraphrase or modify it. Write 3–6 sentences of narrative context before the question and answer. The story generation instruction is NOT part of the final scene; the final scene is story context only."`
   - The model generates: `[narrative intro][Question utterance][Assistant replied: "<ORIGINAL_ANSWER>"]`. After generation, the generation instruction is stripped; the training (and extraction) context is the narrative + question + attribution prefix only.
3. **Judge gate — rubric criterion change vs r3:** the judge verifies (a) the story contains the verbatim answer span exactly once, within a well-formed attributed quote (`Assistant replied:` + the full original answer text), AND (b) the quoted answer matches the provided original answer verbatim — not paraphrased. Criterion (b) is a **new criterion vs the r3 rubric**, which required ≥4 well-formed exchanges but did NOT require verbatim match. Criterion (b) REPLACES criterion (a) on exchange count: r4 requires exactly ONE exchange (the single Q/A pair) + verbatim answer match; r3 required ≥4 exchanges with no verbatim constraint. This exchange-count criterion change is part of the corpus-construction variable and is documented here explicitly. Judge: `claude-sonnet-4-5-20250929`, `max_tokens` 400, temperature 0, reason-then-verdict. An additional cheap judge criterion: **the answer must not be revealed or paraphrased BEFORE the `Assistant replied:` attribution marker** — the wrapper prose before the attribution may reference the question topic but must not contain the answer content. This closes the pre-slot answer-leakage channel at zero marginal cost (one extra rubric line).
4. **80% yield floor:** ≥2,160 of 2,700 story targets after one retry batch → rc=21 halt if missed. Because the original answers are supplied, yield risk is LOWER than free-form generation (the model only needs to write wrapper prose, not invent an answer). Confidence: Medium-High for instruct; base stories expected to fail (same as parent — narrative-wrapper generation requires instruction following competence).
5. **On-policy companion cell (N≤200):** for a random sample of ≤200 conversations from the kept paired corpus (seed 0), generate the story wrapper on-policy WITHOUT embedding the verbatim answer — the model writes the story freely including its own answer. These rows go through the standard r3-style on-policy extraction pipeline (the existing `issue1345_extract_turnstore.py --regime r3` logic). This companion cell is a CONTROL, not a second manipulated variable; its R² at L19 is reported alongside the TF cell as the TF-distortion calibration read.

### Teacher-forced activation extraction (new logic — issue1345_extract_turnstore.py --regime r4)

A new regime flag `r4` in `issue1345_extract_turnstore.py` handles teacher-forced capture:

1. **Render:** for each kept paired story, the extraction render is: `[story_wrapper_up_to_attribution_marker][verbatim_answer]`. The context slot = last token of the attribution marker `Assistant replied:"` immediately before the verbatim answer span (slot definition structurally identical to r3; only the name token differs). The prefix slot = last token of narrative before the question utterance (identical to r3).
2. **Teacher-forcing:** the entire `[story_wrapper + question_utterance + attribution + verbatim_answer]` sequence is passed in a SINGLE forward pass; no generation is performed. Hidden states are extracted at the context slot and prefix slot positions. This reuses the project's existing teacher-forced forward-pass infrastructure (the same mechanism used for the r1/r2 turnstore extractions, which are also teacher-forced — the base model's own responses are teacher-forced through the full conversation render).
3. **BPE seam guard (inherited):** verify the verbatim answer span tokenizes consistently at the boundary (the gotchas.md BPE seam check); log per-turn token-count deviations; drop turns where the span boundary is ambiguous.
4. **Registration in REGIME_FORMAT and UNORDERED_PAIRS:** add `r4` to `REGIMES`, `REGIME_FORMAT`, `TARGET_TURN_INDEX`, and `UNORDERED_PAIRS` (the pairs now include `(r1, r4)`, `(r2, r4)`, `(r3, r4)` — story↔chat and story↔plain-text); `PAIRED_PAIR` remains `(r1, r2)` for the established data-paired reparam. The r4↔r1 pair additionally supports the data-paired `A·M·B` reparameterization because row-level conv_ids are shared — a new `PAIRED_PAIR_R4` = `("r1", "r4")` is registered for that leg.

### Matched-row comparator refits (≈zero GPU, closed-form)

To ensure the "recovers the chat ceiling" read is against a same-n yardstick, and to rule out n-driven artifacts in the TF-vs-companion calibration, the following comparator refits are computed on already-persisted stores (no new extraction):

- **r1/r2 within-R² and chat ceiling on the r4-kept conv_id subset:** after r4 fits complete, refit the r1 and r2 L19 context cells on the subset of r1/r2 turnstore rows whose conv_ids appear in the r4 kept set. This gives a same-n comparator for the "recovers the chat ceiling" claim.
- **r1↔r4 transfer and reparam legs** additionally computed on this subset (the data-paired alignment requires shared rows; using the kept intersection is the natural domain).
- **TF-vs-companion calibration gap:** the companion cell (N≤200) is compared against the TF cell on the companion's exact ≤200-conv subset of r4 rows (so the calibration gap is not mechanically driven by n differences against the 0.05/0.20 thresholds).

## 7. Decision Gates

- **Per-model story yield floor (kill; revised):** kept < 2,160 of 2,700 (80% floor) after one retry batch → rc=21 → that model's story leg halts, reported `N/A — not tested`. The wrapped-story yield risk is LOWER than free-form (the model only needs to write wrapper prose, not invent an answer), but the floor protects the fits from a short corpus and ensures ≥r3's realized 2,108 rows.
- **TF-distortion qualification gate (nested tiers):** the 0.05 and 0.20 thresholds are nested, not contradictory. Tier 1: if the on-policy companion R² at L19 (context arm, instruct) is more than 0.05 below the TF-cell R² (the "TF inflates the map" signal), the paired-verbatim headline is accompanied by the companion read as a qualification note — a mild signal, directional only. Tier 2 (kill): if the on-policy companion R² is NEGATIVE AND more than 0.20 below the TF-cell R² (a large positive-to-negative drop flagging severe TF distortion), the TF-cell headline is reported with a `TF-DISTORTED` qualifier and the companion cell is demoted to the primary DV for that arm. A 0.05 gap triggers qualification (tier 1) only; a 0.20 gap triggers both the qualification and the tier-2 kill action. Threshold grounding: the parent's context-arm shuffle null p95 is −2.194; a 0.20 gap is more than 10× larger than the ±0.02 parity gate and indicates something structurally wrong with the TF extraction (not random noise).
- **Download-integrity / parity gate (QA; inherited ±0.02):** the downloaded parent r1/r2 turnstore must reproduce the four pinned L19 anchors within ±0.02 — exit 3 halts before fits.
- **r1/r2 refit-equality check (QA; inherited ≤1e-3):** refit r1/r2 L19 context R² must match the parent's committed values — a mismatch means the reuse is unsound.
- No other gates — this is a two-sided hypothesis test and a single ~8–10 h chain.
