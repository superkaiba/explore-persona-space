```python
# maxp = per-dimension (element-wise) max over the response CONTENT tokens.
# #810's crowned recipe (issue658_common.summarize_answer_span, recipe="maxp"):
#   span.max(dim=0).values over the answer-token span — content tokens ONLY.
# The #658 span was built from ans_ids (the tokenized completion text), so it
# NEVER included the chat-template turn-close <|im_end|> + "\n"; #810 swept

# REFUTED them. Including them in the max would let two high-norm delimiter
# positions dominate many dims and blur maxp toward the refuted boundary read.
# In this harness full_ids = prompt + response + <|im_end|> + "\n", so:
content_end = _locate_turn_close_newline(full_ids, tok) - 1  # index of <|im_end|>
assert full_ids[content_end] == 151645          # <|im_end|> — KILL-2-style, fail loud
assert content_end > p                          # non-empty content span
for li in layers:
    v0_maxp = acts_b[li][0, p:content_end, :].float().max(dim=0).values  # NEW
    vp_maxp = acts_t[li][0, p:content_end, :].float().max(dim=0).values  # NEW
# fp16/bf16-safe: element-wise max is an exact comparison (no accumulation),
# and the bf16→fp32 cast is exact; assert torch.isfinite(...).all() in the smoke.
# Probe aggregation: per-probe maxp, then probe-MEAN over the probe pool —
# rides the same accumulator as mean/turn_nl (np.stack(...).mean(axis=0)),
# matching #658's recipe_accum / n_used exactly.
```

Note the deliberate span asymmetry, inherited from the two recipes being copied: this harness's `mean` spans `[p : full_len)` (includes the 2 turn-close tokens — the #667/#722/#811 lineage recipe, unchanged), while `maxp` spans `[p : content_end)` (#810's crowned span). Fidelity to each summary's own validated recipe wins over within-run span matching; changing either would smuggle a second variable. Recorded in §12 (A4).
