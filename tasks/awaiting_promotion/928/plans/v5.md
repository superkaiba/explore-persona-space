### 4.1 New spans + K computation (code, not a model call — exact, deterministic)

New pure function in `scripts/issue928_common.py` (unit-tested; token indices in COMPLETION token space, derived from the SAME `char_span_to_token_span(return_offsets_mapping)` machinery `build_capture_row` already uses — no re-tokenization, no re-search):

```python
MLC_K_MIN = 8        # conditioning-slice floor (tokens)
MLC_REM_MIN = 16     # remainder-target floor (tokens)

def matched_length_spans(cot_tok, ans_tok, k_min=MLC_K_MIN, rem_min=MLC_REM_MIN):
    """Per-row matched-length spans. K = min(len(cot), len(ans)//2).
    Returns None (dropped-and-counted, reason 'matched_length_floor') when
    K < k_min or len(ans) - K < rem_min. Spans are half-open token indices
    into the completion, all derived from the parent's cot/ans token spans."""
    cs, ce = cot_tok; a0, a1 = ans_tok
    K = min(ce - cs, (a1 - a0) // 2)
    if K < k_min or (a1 - a0) - K < rem_min:
        return None
    return {
        "K": K,
        "cot_lastK":   (ce - K, ce),        # registered CoT slice (the CoT's conclusion)
        "cot_firstK":  (cs, cs + K),        # exploratory CoT slice
        "ansprefix_K": (a0, a0 + K),        # matched-length control slice
        "ans_rem":     (a0 + K, a1),        # the SHARED prediction target
    }
```

Properties (measured, §2): K is answer-limited in 94.4% of rows, so `ansprefix_K` and `ans_rem` are (approximately) the answer's two disjoint halves, and `cot_lastK` is a genuine truncation (mean keeps 210/645 ≈ 33% of CoT tokens). **Registered CoT slice = last-K** (the CoT's conclusion — the most favorable K-token slice for the CoT arm, and the slice that minimizes its token-distance handicap: last-K ends K tokens before the remainder starts, vs 0 for the prefix); first-K is captured as a cheap exploratory second definition so the choice is auditable post-hoc. Rows failing the floor are dropped-and-counted per context (reason `matched_length_floor`), inheriting the parent's per-context 80%-usable flag convention (the parent's 14 flagged contexts stay flagged; no new all-or-nothing gate).

## 11. Decision Rationale (delta entries; every other §11 entry inherited from v3)

- **K = min(len(CoT), floor(len(answer)/2)).** *Why:* matches the two conditioning budgets exactly per row; guarantees prefix and remainder are disjoint (answer-limited in 94.4% of measured rows, so they are ~the answer's two halves) and the remainder target stays substantial (mean 219 tokens). *Source:* followup-scope (user-chat) + measured token-length distributions this session (pinned rollouts, exact tokenizer — §2 numbers). *Alternatives:* fixed global K (e.g. 128 — drops ~25–30% of rows and collapses coverage in short-answer contexts; rejected); K = min(cot, ans − rem_min) (maximizes K but leaves a near-empty, unstable remainder target; rejected — the shared target's stability outranks conditioning-budget size).
- **Floors: K ≥ 8, remainder ≥ 16, dropped-and-counted.** *Why:* a mean-pool over < ~16 tokens is a noisy target; the floor bites only degenerate rows. *Source:* measured — keep 99.85% at rem ≥ 16 (1,989/1,992; worst context is already flagged); value non-load-bearing within 2× (drops are counted, sensitivity checkable for free). Not literature-groundable — a stability floor, marked as such.
- **Registered CoT slice = LAST-K (first-K exploratory).** *Why:* the CoT's conclusion is its most answer-relevant K-token slice and minimizes the CoT arm's token-distance handicap vs the adjacency-advantaged prefix arm — a null against the CoT's strongest slice is the informative null; capturing first-K too makes the choice auditable post-hoc at trivial cost. *Source:* design argument (ungrounded in prior issues — new choice; the parallel-captured exploratory variant is the smoke-test).
- **Mean-pool only for the new spans.** *Source:* #928 body — max/max −0.29 vs mean at the frozen layer; boundary far below; "no tested summary displaces mean pooling". Skipping max/boundary is the scope's sanctioned narrowing.
- **Shared remainder target for ALL arms (never full answer).** *Why:* full-answer prediction hands the prefix arm target overlap (its input is part of the target) — the contrast would be mechanically confounded. *Source:* followup-scope (the user's own design note).
- **Frozen layer = context-only baseline's full-data best LOCO layer, re-derived once on the remainder target.** *Why/Source:* the parent's primary convention (#928 v3 §6 — direct-arm frozen, selection-free for contrasts between non-baseline arms, conservative for gains over baseline), adapted per the scope's "re-derived ONCE… before any draw".
