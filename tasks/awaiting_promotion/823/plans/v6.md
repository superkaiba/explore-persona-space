### 0.0 TL;DR (plain English — the user reads this first)

- **What I'll run:** I take the same 5,000 real LMSYS user messages from the parent
  experiment and have Claude answer them again — but this time under k different
  characters (k = 1, 2, 4, 8, or 16 personas: an ER doctor, a detective, a pastry chef,
  …), with each message assigned to one persona. Then I fit the exact same
  context-activation → answer-activation ridge map from the parent and ask: does the map
  get worse as the answers come from more different "people"?
- **What I expect:** if the parent's headline is right that the map works because the
  answers come from ONE consistent character, quality should fall as k grows — the single
  map has to average over k different answer styles. The per-persona control (refit the
  map inside one persona's slice) tells us whether the drop is really mixture-blur or
  something else.
- **What would change my mind:** if the k = 16 map is about as good as the k = 1 map
  (difference ≤ 0.03 R² with a tight confidence interval), then origin-consistency is NOT
  what the map depends on, and the parent's "consistent persona" interpretation needs
  rewording — the map would be capturing something any coherent answerer shares.

### 3. Hypothesis

Let R²(arm, L) = P1 pooled OOF R² at layer L, and define the primary contrast

Δ_mean = mean over L ∈ {14, 26, 17} of [ R²(k=1, L) − R²(k=16, L) ].

- **H1 (degradation):** map quality falls monotonically in k. Prediction: Δ_mean > 0.05
  with the paired per-context bootstrap 95% CI excluding 0, and the k-curve is
  monotone-decreasing (Spearman ρ(k, R²) < 0 descriptively). Grounding for the 0.05
  threshold: the parent's own-vs-plain gap (≈ 0.014–0.052 pooled) — a mixture penalty
  smaller than the origin-identity gap would be a weak confirmation; the parent used
  0.05 as its H1 decision threshold (plan v5 §3).
- **H2 (flat / origin-consistency irrelevant):** |Δ_mean| ≤ 0.03 (the parent's H2
  content-indifference band) — the map is as good on a 16-persona mixture as on one
  persona; the promoted "consistent persona" wording is falsified in its strong form.
- **H3 (mixture-attribution, conditional on degradation):** the per-persona refit
  control at matched contexts and matched n recovers most of the drop — i.e. the gap
  G_mix = mean over personas p of [ R²(within-persona fit) − R²(matched-n mixed-fit,
  same test rows) ] at k ∈ {8, 16}, P2 protocol, is materially positive when Δ_mean is.
  G_mix is a REPORTED decomposition with a CI, not a gated verdict: G_mix ≫ 0 reads as
  "the penalty is origin-mixture variance"; G_mix ≈ 0 with Δ_mean > 0 reads as "the
  penalty tracks something else (e.g. per-row style diversity), not recoverable by
  conditioning on persona".

DISJOINT and exhaustive: Degrades ⇔ Δ_mean > 0.05 AND the paired per-context bootstrap 95% CI of Δ_mean excludes 0; Flat ⇔ Δ_mean ≥ -0.03 AND Δ_mean ≤ 0.03; Intermediate ⇔ otherwise.

(Δ_mean is a single registered quantity — no per-trait quantifier inside the lattice;
per-layer and per-trait Δ values are reported descriptively alongside.)

Row-coverage: every registered paired contrast (k=1 vs k=16, adjacent k-rungs, and each
ladder arm vs the refit own/plain anchors) is computed per-context on the single shared
common-valid context mask that all seven P1 arms are fit on; the P-Fit phase itself
produces the per-context (ss_res, ss_tot) rows for BOTH arms of every contrast in one
pass and persists them to
`eval_results/issue_823/inconsistent_origin_ladder/percontext_ladder.npz`.

#### 4.2 Nested persona assignment (brief §4c)

Persona assignment for arm k at context i (0-indexed within the frozen 5,000-context
order): persona(i, k) = i mod k. Nesting property: the distinct (context, persona)
pairs across all five arms are {(i, 0), (i, i mod 2), (i, i mod 4), (i, i mod 8),
(i, i mod 16)} — exactly 14,996 unique pairs (5000 = 16·312 + 8; residues 0–7 appear
313×, 8–15 appear 312×; per-residue distinct-persona counts sum 313·20 + 312·28 =
14,996). Every arm has exactly 5,000 rows (one per context) drawn from this pair store.
Balance: within arm k, each persona p < k gets 5000/k contexts exactly for k ∈ {1,2,4,8}
(5000 divisible), and 313/312 for k = 16 (±1). Persona-0 rows of arm k are a subset of
the k=1 arm — free matched-context comparators for the per-persona control. The realized
assignment is persisted as `assignment.json` (context_id → persona per arm) alongside
the raw completions.

### 11. Decision Rationale

- **k ladder {1, 2, 4, 8, 16}** — What: arm grid. Why: doubling ladder resolves fast
  and slow onset with 5 arms. Source: user order + `epm:followup-scope v1`
  (2026-08-19T20:07Z). Alternatives: linear grid (worse dynamic range at equal arms).
- **16 personas, roster fixed in-plan** — What: k_max identities. Why: k_max = roster
  size; maximally distinct registers to make the manipulation strong. Source: brief
  (k_max = 16); roster wording itself `ungrounded — needs smoke-test` (validated by
  manipulation checks M1/M2, not assumed). Alternatives: reuse project personas
  (medical_doctor etc.) — rejected: those carry parent-experiment semantics; a fresh
  matched-template roster keeps the arms clean.
- **Nested assignment persona(i,k) = i mod k** — What: pair-sharing across arms. Why:
  14,996 calls vs 25,000 unnested; persona-0 rows give free matched comparators.
  Source: amendment brief §4c (orchestrator decision). Alternatives: independent
  random assignment per arm (loses nesting economies + paired comparators).
- **Generation params (Sonnet 4.5, temp 1.0, max_tokens 1024, 1 draw/pair)** — Source:
  #823 parent phase-1 (SONNET_MODEL/SONNET_MAX_TOKENS constants read this session;
  temperature verified at implementation from the phase-1 dispatch call — §12 row).
  Alternatives: 2048 cap (reserved for the cap-hit re-gen trigger).
- **P1 protocol (5-fold pooled GCV, λ logspace(−2,4,13), KFold seed 0)** — Source:
  #779 → #823 parent (banked JSON + body). Alternatives: none (parity is the point).
- **P2 protocol (3600/400/1000 seed 42, val-selected λ over logspace(−2,8,21))** —
  Source: #823 single-split round (`issue823_single_split_protocol.py`, banked JSON at
  commit 696d7b7eb1); val-selection is the instrument's registered mitigation

  rejected (breaks parity; span-length confound).
