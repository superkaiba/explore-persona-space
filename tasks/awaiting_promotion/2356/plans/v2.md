# Plan v2 — Issue #2356: Predicting Qwen2.5-7B-Instruct's refuse-vs-comply decision from internal representations vs an LLM judge, across two behavioral regimes (harmful flip-pairs + over-refusal)

## 0.0 TL;DR (plain English — the user reads this first)

- **What I'll run:** I test whether the model's refuse-or-answer decision can be predicted before it answers, in two settings: (A) ~2,760 harmful requests and subtle rewrites of them that flip the model from refusing to complying, and (B) ~2,500 borderline prompts that safety-tuned models sometimes wrongly refuse. In each setting I sample the model 10 times per prompt to label its decision, then race four predictors: a strong Claude judge reading only the prompt text, a linear read of the model's internal state at the end of the prompt, that same read pushed through a label-blind "what answer comes next" map, and a read of the actual answer's internal state as the ceiling. I also test whether the map can pick out each prompt's true answer from a lineup of all the other answers, and whether a decision-predictor trained on one setting transfers to the other.
- **What I expect:** In both settings the text judge lands near chance on these deliberately confusing prompts, the internal read does clearly better, and the mapped-answer read closes part of the gap to the ceiling. The map picks the true answer out of the lineup far above chance — which is what licenses reading the mapped-answer probe as a real answer-geometry signal rather than noise.
- **What would change my mind:** If the text judge matches the internal read in either setting, internals add nothing over surface reading there and the headline dies. If the map cannot pick answers out of the lineup above chance, the mapped-answer probe is reading noise and I say so. If the transfer check fails, the decision signal is regime-specific rather than one shared refusal geometry — reported either way, it never gates the headline.

## 1. Goal

"Predict Qwen2.5-7B-Instruct's binary refuse-vs-comply/answer decision across TWO behavioral regimes — (A) harmful-compliance flip-pairs and (B) over-refusal on borderline dual-use prompts — and compare four predictors of that behavior under a fair group-level train/eval split, run separately on each arm (the headline must hold in BOTH) plus a cross-regime transfer check: (1) LLM judge on context text, (2) linear probe on the context activation, (3) linear probe on the mapped (predicted) answer activation under a label-blind map-training ablation (#3a generic-only vs #3b generic + train-split in-domain), (4) linear probe on the actual answer activation (ceiling); additionally evaluate whether the context->answer map DISCRIMINATES answers via the #2202 whitened-cosine retrieval battery (which doubles as the map-quality gate for predictor 3)." (Task #2356 Goal, verbatim; re-read from frontmatter 2026-08-17 immediately before returning this plan — unchanged since the epm:goal-updated marker at 23:17:22Z.)

One paragraph: refusal-direction work (Arditi et al.) shows refusal is linearly readable from context activations when harmful and harmless prompts differ in topic — the easy case. Both arms here are built so the prompt TEXT is surface-matched to the opposite behavior: Arm A pairs a refused harmful base with subtle intent-preserving rewrites the model complies with; Arm B's over-refusal benchmarks make benign prompts look scary. In both, a text-only judge should struggle. If a linear probe on the model's own context representation still predicts the refuse-vs-comply decision, the decision is internally determined before generation in a way surface reading cannot see — and the claim is robust only if it holds in BOTH regimes. Predictor #3 then asks WHERE that signal lives: if a label-blind context→answer map (the leakage-paper object M_{C,A}) concentrates the behavior-relevant signal in its low-rank transfer subspace, the behavior is carried by the model's general answer-prediction geometry rather than a refusal-specific direction. The #2202 retrieval battery independently tests whether that map discriminates ANSWERS at all — the validity gate for reading #3 as an answer-geometry result. N/A — not a replication.

## 3. Hypothesis

**H1 (headline, per arm — the claim must hold in BOTH):** the context-activation probe (#2) predicts the refuse-vs-comply/answer decision better than the strong text judge (#1). Define, PER ARM, Δ_int = pooled out-of-fold AUROC(#2) − AUROC(#1) on that arm's identical balanced eval rows under group-level 5-fold CV, with a paired group-level bootstrap 95% CI.

DISJOINT and exhaustive: Confirmed ⇔ Δ_int > 0 with its 95% CI excluding 0 on the positive side in BOTH arms; Falsified ⇔ Δ_int's 95% CI wholly below 0 in at least one arm; Inconclusive ⇔ otherwise.

Regime descriptor (reported, not a verdict): the "NOT predictable from text" premise holds in degrees — the judge's absolute AUROC is reported per arm with its CI. Judge AUROC ≥ 0.80 in an arm means the premise substantially fails there (itself a finding); the Δ_int verdict is meaningful either way. A one-arm-only Confirmed pattern (e.g. holds on over-refusal, fails on harmful flip-pairs) is reported as regime-specific internal predictability — explicitly NOT the headline claim.

**H2 (Goal clause on the map, pre-registered directional predictions per arm — no verdict labels):**
- If the label-blind context→answer geometry carries the behavior signal, then at matched rank r the mapped-answer probe (#3a) beats the PCA-of-context control, and #3's AUROC at small r stays near its full-rank value while the PCA control degrades.
- "Map adds signal" pattern: #3a(best r) > PCA-control(matched r) with a positive paired-bootstrap CI, AND/OR #3a beats #2 somewhere on the limited-label ladder.
- "Map is a pass-through" pattern: #3a(full rank) ≈ #2 (expected — a full-rank linear composition is a reparametrization) AND #3a(any r) ≤ PCA-control(matched r) everywhere.
- #3b vs #3a: label-blind in-domain adaptation helps ⇔ #3b > #3a with a positive paired CI at the selected rank.
- Ceiling: #4 ≥ every other predictor; recovery = (AUROC_#3a − AUROC_#2) / (AUROC_#4 − AUROC_#2) reported with CI (only when AUROC_#4 − AUROC_#2 > 0.02, else undefined).

**H3 (map discrimination, per arm × map condition — the #2202 battery):** the map's predicted answer vectors single out their true answers among the held-out answer pool: whitened-cosine acc@1 above chance = 1/n_pool with a group-bootstrap CI excluding chance. Pre-registered gate role: an (arm × map condition) cell whose acc@1 CI includes chance has NOT demonstrated answer discrimination — predictor #3's read for that cell is reported with the explicit caveat that the mapped-answer probe may be reading generic low-rank structure or noise rather than answer identity (informational gate; nothing aborts).

**H4 (cross-regime transfer — REPORT ONLY, never gates the headline):** a context probe trained on one arm transfers to the other with AUROC > 0.5 in both directions (one shared refusal-decision geometry, per 2603.27518's task-dependence question); failure = regime-specific signal, reported as such.

**Falsification of the overall premise:** in both arms every internal predictor (#2, #3, #4) sits within noise of the judge → internal representations add nothing on surface-matched prompts (consistent with 2607.13075's transfer collapse).

Paired contrasts are registered throughout (paired group-bootstrap differences between predictor arms on identical eval rows, per arm).
Row-coverage: Arm A rows supplied per-prompt by `eval_results/issue_2356/armA/predictor_scores.json` + `eval_results/issue_2356/armA/labels.json`; Arm B rows by `eval_results/issue_2356/armB/predictor_scores.json` + `eval_results/issue_2356/armB/labels.json` (all predictor arms, one out-of-fold score per prompt per arm); battery rows by `eval_results/issue_2356/map_discrimination.json`; transfer rows by `eval_results/issue_2356/transfer.json`.

## 4. Design

**Why code, not a model call:** the object of study is the model's internal activations, fitted linear maps over them, and retrieval geometry — not obtainable by an API call. The judge components (labeling instrument, predictor #1, variant-rewrite extension) ARE model calls, routed through `eval.batch_judge` / `api_dispatch`.

**Contrastive negatives / marker recipes:** N/A — no behavior implantation, no training; the base model is frozen. **On-policy completions:** all behavior measurement is on-policy by construction (the model's own sampled responses). **Data realism:** Arm B tier 2 (two established benchmarks); Arm A tier 2 base corpus (AdvBench, established) with LLM-rewritten variants (tier-3 element) — justified: the construct under test IS the subtle intent-preserving rewrite (surface-matched pairs), the variants span 6 registered axes (diversity by design), and the bank is reused verbatim rather than re-generated (§10); generic map corpus tier 1 (real-user LMSYS prompts). Carried as scope caveats. **Persona-vectors recipe:** does not fire — the DiM baseline is a supervised diff-in-means on labeled activations, not the 2507.21509 extraction; the read-out-regime layer policy (sweep all layers, select by train-internal predictivity, #658) is followed.
