# Plan v2 — Issue #594 same-issue follow-up `probe-genre-generalization` (AMENDMENT — one-variable diff vs plan v1)

## §0.0 TL;DR (plain English)

- **What I'll run:** the parent run measured each of the 50 contexts through one fixed set of 48 questions, all drawn from a single genre. I'll re-run the exact same measurement with 48 ordinary user questions pulled from a public chat dataset instead, matched in length to the originals so a length difference can't masquerade as a genre difference, and check whether the same family map comes back.
- **What I expect:** the map is about the contexts, not about the questions used to read them — so the families should cluster again, the mid-network peak should reappear, and the new pairwise-similarity matrices should line up layer by layer with the old ones.
- **What would change my mind:** if the clustering drops to chance under the new questions, or the new and old similarity structures don't correlate, the parent headline was conditional on its question genre — which would directly weaken how we read every predictor built at this position.

## §2. Probe-sourcing design (new builder: `scripts/issue594_build_probes_ultrachat.py`)

All CPU, on the VM, before any pod exists. Deterministic, seed 42. Verified facts (streamed 2026-06-11): `HuggingFaceH4/ultrachat_200k` is **ungated**, one config `default`, parquet splits `train_sft` / `test_sft` / `train_gen` / `test_gen`; row schema `{prompt: str, prompt_id: str, messages: [{content, role}]}` with `prompt` equal to the first user turn's content.

1. **Candidate pool:** `load_dataset("HuggingFaceH4/ultrachat_200k", split="train_sft", streaming=True)`, take the **first 20,000 rows** in native order (deterministic; no streaming shuffle). `train_sft` is the curated split H4 used for Zephyr SFT — the highest-quality slice (arXiv 2310.16944).
2. **Per-row extraction + filters:** candidate text = the `prompt` field; assert `messages[0]["role"] == "user"` and `prompt == messages[0]["content"]` (drop + count mismatches; fail loud if drops > 5%). Filters: stripped; Qwen-2.5 token length (`add_special_tokens=False`) ∈ [4, 140]; English heuristic — ≥ 90% ASCII characters and ≥ 3 whitespace-separated words; exact-match dedup (casefolded).
3. **Disjointness asserts (hard):** casefolded candidate is not equal to, does not contain, and is not contained in any of (a) the 48 Betley probes (`fetch_preregistered_probes`, hash re-asserted at build) or (b) the 8 battery ICL demo questions (read from `battery.json` `prefix_messages`).
4. **Length matching — 1:1 greedy quantile-free match** (concrete, no binning): seed-42 RNG shuffles the filtered candidate list once. Iterate the 48 Betley probes in **descending token length** (so the sparse 78–128-token tail matches first); for each, pick the first remaining candidate within a band of **±max(5 tokens, 20% of the target length)**; if the band is empty, widen by +5 tokens and retry (log each widening; hard-fail after 5 widenings — that is the candidate-shortage kill, CPU-side, pre-pod). Remove the picked candidate (without replacement).
5. **Acceptance check (recorded in meta):** report Betley vs matched deciles side by side; require pool mean within ±10% of 35.2 tokens and every per-probe |Δlen| within its final band. Print all 48 matched prompts for eyeball review.
6. **Output `data/issue594/probes_ultrachat.json`** (small text, committed to git): `{"meta": {dataset, config, split, candidate_rows: 20000, seed: 42, probe_pool_hash: probes_hash(texts), betley_pool_hash, matching_spec, decile_table, build_commit}, "probes": [{text, prompt_id, source_row_index, token_len, matched_betley_index, matched_betley_len}]}`. The extraction manifest re-records the pool hash + per-probe lengths, and the extraction script uploads this file to `issue594_context_geometry/inputs/probes_ultrachat.json` (mirroring `upload_battery`).

## §3. Hypothesis, falsification, success/kill (mirrors parent §9)

- **H-A (context-driven map):** under the new pool, max-over-layers k-NN purity AND silhouette each beat the 95th percentile of their fresh max-over-layers permutation nulls (B=1000). Quantitative expectation: purity within the same regime as the parent (parent: 0.979 @ L14 vs null 0.375).
- **H-B (geometry transfers):** per-layer Mantel Spearman between the new and old 50×50 centered cosine matrices is positive with permutation p ≤ 0.001 at the parent's headline layers L14 and L18; magnitude read descriptively against the parent's split-half ceiling (median cross-half cosine 0.946 → 0.866 across depth) — no invented threshold.
- **Falsification (scope marker, verbatim):** purity AND silhouette inside their permutation nulls under the new pool, **or no mid-stack peak** — operationalized: the silhouette depth-curve max falls outside L8–L22 or fails to exceed its L0 value. A falsifying outcome is reportable ("the parent map was probe-genre-conditional"), not a failure.
- **Success criteria:** (1) 50/50 instances × 48 probes extracted, all position asserts pass; §5 globs non-empty; (2) H-A read decisive either way; (3) cross-pool Mantel curve + headline-layer p's produced; (4) length-residualized + split-half + TF-IDF reads reproduced under the new pool. **Kill criteria** inherited verbatim from v1 §9 (a)–(b): >10% position-assert failures → halt + fix; split-half centered median < 0.9 at every layer → reliability finding, headline downgraded. v1 §9(c) (WildChat fallback) is moot — the battery is frozen. Mixed silhouette/purity outcomes narrated per v1 §14 item 3 (metric-discordant exploratory).
