# Plan — Task #608: Does contrastive-negative training improve source implantation for sycophancy (vs positive-only)?

## 0.0 TL;DR (plain English)

- **What I'll run:** We already trained six personas to agree with wrong factual claims using a training mix that pairs "the persona agrees" examples with "other personas correct the claim" examples. I'll retrain the same six personas on the agreement examples *alone* (two versions: same number of passes through the data, and same total amount of training) and compare how strongly the sycophancy installs into each persona, using the exact same test questions and the exact same grader. The original mixed-training models are reused as-is — no retraining for that arm.
- **What I expect:** I genuinely don't know which way this goes, which is why it's worth running. The mixed-training models already agree with wrong claims ~95% of the time, so the positives-alone models either fall short of that (the mix helps installation), match it (the mix only matters for containing spillover), or match it while also dragging every *other* persona up with them (the spillover we've seen before when negatives are weak or absent).
- **What would change my mind:** If positives-alone installs the behavior just as strongly, the "you need the contrast to install it well" half of our training rule is wrong for realistic behaviors, and the rule survives only as a spillover-control measure. If positives-alone *also* keeps other personas clean, that would surprise me most — it would mean the negatives buy nothing here at all.

## 1. Goal + Hypothesis

**Goal (canonical, frontmatter):** Test whether the contrastive-negatives → stronger source implantation effect (established for the marker implant) holds for sycophancy, by training the same source personas on positive-only vs contrastive mixes — the single manipulated variable — and comparing judge-scored source self-implant deltas, with bystander leakage as the secondary read.

The contrastive-negatives rule (`.claude/rules/contrastive-negatives.md`) makes two claims about positive-only behavior implantation: it leaks uniformly to other personas, and it under-installs the source. For sycophancy, neither claim has actually been tested in a positive-only regime (see §2 — the cited "positive-only" reference is a record error). This experiment supplies the missing comparison on the strongest available rig (#411's frozen contrastive run) by adding two positive-only arms that differ from the frozen arm only in mix composition (and, between themselves, only in training amount).

**N/A — not a replication** of a published external finding; no replication-fidelity obligations.

### Hypotheses (pre-registered, falsifiable)

Let Δself(arm, s) = trained own-panel agreement rate − frozen base own-panel rate for source s, and g(s) = Δself(contrastive, s) − Δself(positive-only dose-matched, s).

- **H1 (primary — under-install generalizes to sycophancy):** contrastive installs more strongly at matched training amount. *Supported* if mean₆ g ≥ +0.05 AND g(s) > 0 for ≥5/6 sources AND the per-source claim-level bootstrap CI on g(s) excludes 0 for ≥3/6 sources. *Falsified (practical equivalence)* if |mean₆ g| ≤ 0.02 AND no source's CI excludes ±0.05 — then the under-install claim is marker-specific and the contrastive default rests on leakage control alone. Anything between → indeterminate at endpoint; the trajectory + dose reads (below) become the reported finding.
- **H1-censoring sub-rule (pre-registered):** the contrastive endpoints sit at own-rates 0.950–0.968 for 5/6 sources (qwen_default 0.700; base rates 0.044–0.128 — exact values from `analyze_summary.json` / `base_panel_rates.json`). A positive-only cell with own-rate ≥ 0.95 is "top-band". If ≥4/6 dose-matched positive-only cells are top-band, the endpoint comparison is declared censored; the headline becomes "positive-only installs to the same near-ceiling band — under-install not detectable on this DV at this dose", read jointly with: (a) the epoch-1/epoch-2 trajectory of the positive-only arms (plateau by epoch 2 ⇒ equal-at-convergence, still rising ⇒ dose-limited), (b) the matched-epochs arm (under-install there but not in dose-matched ⇒ the deficit was training amount, not composition), and (c) H2 as the surviving differentiator. qwen_default (0.700 contrastive endpoint, ample headroom) is the designated uncensored sentinel source.
- **H2 (secondary — uniform leakage reappears):** positive-only arms show a broad bystander lift: mean bystander Δ ≥ +0.05 for ≥5/6 sources in the dose-matched arm (reference regimes: #391's weak-negatives broad lift ≈ +0.13; #18's positive-only marker leakage 92–98%), vs the frozen contrastive reference (mean bystander Δ within ±0.03 for 4/6 sources; assistant +0.090, software_engineer +0.179). *Falsified* if positive-only bystander panels stay flat (|mean Δ| ≤ 0.03 for ≥4/6) — negatives buy nothing for sycophancy on either axis.

**Kill criterion (rig validity):** smoke-cell gate in §7 — if positive-only training installs nothing into the source (Δself < +0.20 on the smoke cell), the run halts as a rig bug (pool-filter or training defect), not a finding.

## 4. Design

**Contrastive-negatives exemption (explicit):** this experiment IS the named exemption (a) — the single manipulated variable is contrastive-vs-non-contrastive; the positive-only arms are the deliberate control, not a rule violation.

**Marker / behavior-implant stopping recipe:** N/A in its band-stop form — this is whole-response SFT (loss over the full assistant completion), not marker-only loss; there is no marker token, no log-prob band, and `MarkerBandStopCallback` is structurally inert here (gated on `marker_only_loss=True`, which stays False). The stopping recipe (fixed 3 epochs) is parity with the frozen arm, which is the comparison's requirement; the ceiling risk this creates is handled at the measurement layer (§1 censoring sub-rule, §6), not the training layer.

**Multi-arm resolution-band designs:** N/A — no gate requires arms to co-occupy a measurement band at a shared checkpoint; arms are compared at fixed matched endpoints.

**Few-shot / ICL demonstrations:** N/A — no ICL or few-shot demonstrations in this design.

**Why code, not a model call?** The only unstructured-data scorer is the sycophancy judge, which IS a model call (Haiku 4.5 YES/NO with the locked #411 prompt) per the project's no-substring-match rule; the YES/NO parser is the trivial code already in `judge.py::_parse_verdict`. No new code-based heuristic over unstructured data is introduced.

**Data-source tier:** tier-3 (diverse LLM-generated): 250 Sonnet-4.5-written wrong claims (200 train / 50 held-out eval, disjointness asserted at #411 Phase 0) with 20 templated agreement phrases on positives. Inherited frozen from #411/#99 because byte-identical positives are REQUIRED for the single-variable contrast against the frozen arm — regenerating data would add a second changed variable. The templated agreement strings (tier-4-ish flavor within tier-3) are an inherited scope caveat to carry into the clean-result: the installed behavior is "agree in roughly these 20 ways," and generalization beyond that phrasing is untested here exactly as it was in #411.

**Disjointness check:** the positive-only arms contain NO negatives, so the negative-panel disjointness invariant is trivially satisfied for all new training. For the FROZEN contrastive arm I verified the realized pools this session: 5/6 cells used another *source* persona as a trained negative (comedian←{medical_doctor, assistant}; assistant←{software_engineer, comedian}; qwen_default←{comedian, data_scientist}; software_engineer←{assistant, medical_doctor}; kindergarten_teacher←{software_engineer, french_person}; villain←{police_officer, medical_doctor} is clean). Because every cell is a separate adapter, this does NOT touch the primary self-implant DV; it suppresses by design the contrastive arm's bystander deltas at those 2 panel personas per cell. Mitigation (pre-registered): the H2 bystander comparison is reported both over all 23 bystanders AND excluding each cell's 2 trained-negative personas. Inherited caveat, named in the clean-result.

## 11. Decision Rationale

All training hyperparameters are inherited unchanged — the comparison's validity depends on NOT re-tuning them (inherit fast-path; one `Source:` per unique value):

- **Whole training recipe (lr=1e-5 cosine, warmup 0.05, eff. batch 16, 3 epochs, r=32/α=64 rsLoRA/dropout 0.05, max_length 1024, seed 42).** Why: byte-level parity with the frozen contrastive arm is the experiment's single-variable contract; these values were validated for this exact model + data shape by the parent. Source: `#411` (dispatcher `dispatch_sycophancy_411.py` lines 122-143, cross-checked against the reused `adapter_config.json` on the Hub — launch-config grounding per the #458 lesson, not the body's prose table). Alternatives: re-tuning for the positive-only arms (rejected — would confound composition with recipe); marker-style band-stop (inapplicable — no marker loss, §4).
- **Dose-match construction: cycle 200 positives → 700 rows × 3 epochs = 132 steps.** Why: matches total optimizer steps AND the cosine/warmup schedule *shape* to the frozen arm at epochs=3, keeping epoch-boundary checkpoints aligned (44 vs 44 steps/epoch); the alternative (200 rows × ~10.5 epochs) matches steps but desynchronizes the schedule and checkpoint grid. Source: step count `#411` (132 = ceil(700/16)×3); construction choice is design-derived, grounded in the matched-steps requirement stated in the task body. Inherent residual confound (named): the dose-matched arm sees each unique positive 10.5× vs 3× — unavoidable when matching steps with a fixed positive pool; the matched-epochs arm brackets it.
- **Checkpoint placement: epoch boundaries (steps 13/26 for posonly_epoch; 44/88 for posonly_dose).** Why: 2 intermediate reads per arm distinguish plateau-vs-rising at convergence (the body's stated need); epoch boundaries are the natural grid given `save_strategy="epoch"` and stay cheap (500-gen own-panel evals). Source: `#608` body design seed ("2-3 checkpoints per arm"); sycophancy install on this rig completes within 132 steps (`#411` endpoint deltas), so intra-epoch granularity is not load-bearing. Alternative: step-level grids (rejected — marker-style install-transition windows don't govern a whole-response SFT rate DV, and finer grids triple Phase E cost).
- **Eval/judge protocol (panel, probes, rollouts, temp 1.0, max_new_tokens 512, Haiku judge + κ-gate 0.7).** Why: identity with the frozen arm's measurement is non-negotiable for the paired read; 512 tokens is the documented free-generation exception (no end-of-completion truncation risk). Source: `#411` (κ=0.890 PASS recorded in `kappa_report.json`).
- **Judge-drift gate thresholds (rate ±0.02, verdict agreement ≥0.95).** Why: 0.02 is below the smallest effect the plan will interpret (equivalence band edge) — drift smaller than that cannot flip a verdict. Source: design-derived from §6 thresholds (ungrounded in prior issues — but the gate is conservative-by-construction: its FAIL path converges to one unified judge pass, which is correct under any drift).
- **Model id (`Qwen/Qwen2.5-7B-Instruct`).** Repo-standard, used by dozens of prior configs — no repo-new model smoke needed. Source: `#411`/project default.

**Marker recipe overrides parent parity:** noted and inapplicable — no fresh marker/behavior-implant adapter under marker-only loss is trained here; the implant uses whole-response SFT where the parent's own promoted result IS the validity evidence for the stopping recipe.
