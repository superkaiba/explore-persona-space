## 3. Hypothesis

- **H1 (provenance explains most of the residual):** R²_own(t1, L19,
  instruct) ≥ 0.40 (≥ ~70% of the 0.2117→0.48 gap closed), and the paired
  Δ(own − logged) > 0 with 95% bootstrap CI excluding 0 on BOTH headline
  reads (pooled all-turn Δ and Δ(t1)).
- **H2 (partial contribution):** pooled Δ and/or Δ(t1) > 0 with CI excluding
  0 but R²_own(t1) < 0.40 → provenance contributes; the remaining gap is
  multi-turn context/corpus (real-user WildChat/LMSYS vs the curated
  single-turn corpus).
- **H0 (provenance is not the driver):** pooled Δ and Δ(t1) CIs both include
  0 → the residual is corpus/context, not who wrote the answer.
- **H-neg (provenance hurts — its own outcome class, pre-registered):** a CI
  excluding 0 with Δ < 0 (own answers LESS predictable — plausible if
  one-draw temp-1.0 sampling noise dominates) is reported as "provenance
  lowers the map under this sampling recipe", NEVER forced into H0.

Falsifiability note: the 0.48 anchor lives on a DIFFERENT corpus (the curated
#825 single-turn bundle), so the inferential read is the WITHIN-corpus paired
Δ on identical contexts; the 0.48 line is a reference, not the test statistic.

## 4. Design

**Method delta (the one-variable diff).** Reuse the exact #1092 dynamics
panel — same 497 conversations, same (conv_id, turn_index) assistant-turn
pairs, same real logged context up to each turn k (real user + real prior
assistant turns) — and replace ONLY the turn-k answer: the model generates
its own answer to turn-k's user query. Everything else (render, layers,
estimator, folds, null, matched-n handling) is carried verbatim from the
logged turn-depth analysis.

**Design fork — RESOLVED: prior-turn answers stay REAL-LOGGED (the scope
default).** Argument: (1) single-variable — with logged prior turns the
context at every turn k is byte-identical to the logged analysis, so any R²
change is attributable to answer provenance alone; a fully-on-policy rollout
changes the context distribution too (compounding content drift across
turns), conflating context provenance with answer provenance — a different
question. (2) It preserves a free mechanical validation gate (G2: the new
capture's context_k activations must match the banked store's, since causal
attention makes the state at answer_start−1 depend only on the identical
preceding tokens). (3) It lets the logged-Y curve be refit on the identical
X rows, giving a paired fold-level comparison. (4) Cost: a full rollout is a
k-step sequential dependency chain per conversation (no cross-turn batching
within a conversation), ~2–3× the generation wall for a confounded answer.
Fully-on-policy rollout is named as a candidate follow-up if H2 (partial
recovery) obtains.

## 6. Evaluation

**Measurement validity.** Construct: strength of the linear context→answer
map at each turn depth under on-policy answers. Metric: held-out pooled R²
(grouped-by-conv 6-fold CV, PRESS/GCV ridge) — continuous, non-saturating,
computed exactly as every prior #825/#1092 read (same estimator = comparable).
On-distribution: the answers are the model's own generations under the real
logged context (the natural distribution for "the model's own answer");
activations are teacher-forced states of those generations at the natural
positions. Dual-DV / judge rules: N/A — not a content-behavior
leakage/implantation DV; no LLM judging. OOD folds: grouped-by-conversation
CV is the required group-level fold (no pointwise leakage).
Selection-symmetric nulls: no max-over-axis headline (headline fixed in
advance at L19, t1 + pooled paired Δ); the L14/L18 curves are exploratory.

**Success criteria (quantitative).**
- Gates (all must PASS before any decision read):
  - **G1 banked-reproduction:** refit `ctx_logged` L19/t1/instruct on the
    FULL pre-drop row set reproduces the banked 0.211655 within 1e-2
    (`VALIDATION_TOL`, Source: turn_depth_map).
  - **G2 activation parity:** new-capture context_k vs banked store
    context_k, row-matched: median cosine ≥ 0.999 and ≥99% of rows ≥ 0.99
    (exact thresholds frozen from a 50-row pilot; see the clean-regime floor
    below and §11/§12). **Clean-regime floor (pre-registered — critic (a)):**
    the pilot may tune the thresholds only WITHIN the clean regime
    (fp16/bf16 noise, cosines ≳ 0.999); a pilot median cosine < ~0.99 is a
    HALT-and-diagnose (wiring-bug signal — wrong render/offsets), NEVER a
    calibration datum. This breaks the pilot-calibration circularity: the
    bug regime (≪ 0.99) and clean regime (≳ 0.999) are far apart, and the
    floor prevents a shared render bug from being baked into the gate.
  - **G3 pair alignment (set-typed):** rebuilt panel (conv_id, turn_index)
    pair SET == the pair SET derived from the downloaded store row index —
    exact set equality, fail-loud with the symmetric difference on mismatch.
    Expected cardinality 2,572 pairs/model, DERIVED at stage time from the
    banked `n_per_turn` sums (never hard-coded as a scalar in the assert).
- Outcome reads (L19, instruct primary; pretrained secondary):
  - **Headline-read pre-registration (critic (c)):** the decision reads are
    the POOLED all-turn fold-level Δ and Δ(t1) (n=497). Deep-turn cells
    (n ≲ 60) are EXPLORATORY: the own-answer curve carries one-draw temp-1.0
    generation-sampling variance the logged curve lacks (matched to the
    anchor's own 1-draw construction, so the recovery read is fair), and the
    bootstrap resamples conversations/folds, NOT re-generations — per-turn
