## Goal / Hypotheses / Kill

- **Goal (scope verbatim):** test whether the user-turn context→answer-profile map exists when u2 is generated ON-POLICY by the measured model itself — both models — rather than by an external simulator. The parent's user-map null is established only against EXTERNAL user text; the user-header state may encode the model's OWN predicted user turn (self-consistency version of H2).
- **H-self (provenance effect):** self-generated user cells are materially more predictable than the parent's matched Haiku cells. Pre-registered support criteria (either suffices, per cell): (i) **MLP (uncertainty-aware):** best-frozen-layer R² exceeds the parent's matching cell (0.228 / 0.227 / 0.188 / 0.217 for instruct-chat / instruct-nat / pretrained-chat / pretrained-nat) by a point delta **≥ +0.10** AND the delta clears its noise — delta − 2·SE_delta > 0, where SE_delta combines the new run's fold-level MLP dispersion with the parent's (parent fold values where available in the committed JSONs, else new-run fold dispersion × √2 as the stated proxy), with best-frozen selection applied symmetrically to both runs; a cell passing the point margin but not the noise clause is reported **"suggestive"**, never "supported". The 4-cell OR is reported explicitly (which cell(s)/lane(s) fired), never a bare "supported". (ii) **Ridge:** R²@L19 or @L26 improves on the parent's matching cell (L19: −1.427 / −1.605 / −1.489 / −1.650; L26: −1.121 / −1.076 / −1.211 / −1.316) by **≥ +0.30** (≈4–6× the observed delta SE), or any frozen-layer ridge R² > 0 (a qualitative flip — the parent user cells are negative at every frozen layer, upper CIs below −1.02).
- **Binding positive-interpretation rule (MF-F):** a PASS on any support criterion licenses ONLY the descriptive provenance-bundle claim — "self-generated u2 cells are more row-predictable than externally-written u2 cells." It does NOT license "the user-header state encodes the model's own predicted turn" (self-consistency mechanism): the design cannot distinguish self-specific encoding from any-model-generated / lower-entropy / shorter / less-diverse text being generically easier to predict. The mechanism claim requires a cross-model / mismatched-context control (fit model A's map on model B's self-generated u2 texts — texts persisted by this round; ≈1 GPU-h) — named here as a candidate `question_relation: same` follow-up, NOT part of this round. The analyzer and the clean-result body MUST carry this scope-down verbatim.
- **Kill / falsification of H-self:** ALL self-generated cells land within ±0.10 (MLP, best-frozen) AND within ±0.30 (ridge, frozen) of their matched parent Haiku cells → the user-map weakness is provenance-general (external AND self); the parent Takeaway gains a self-consistency scope extension rather than a rewrite. **Third outcome class (named):** a cell where self-gen is materially WORSE (MLP delta < −0.10 or ridge delta < −0.30) fails both labels and is reported as **"provenance-sensitive-negative"** (plausible under diversity shrinkage), not forced into support/kill. Either outcome is reportable (headline_affecting: yes).
- **Provenance axis:** headline comparison is self-generated vs the parent's Haiku cells (same fit recipe, committed numbers). If a sibling real-user-turn round has landed by analysis time, the analyzer folds a three-provenance read (self / external-LLM / real-human); not a dependency of this round.
- **Diversity caveat (registered diagnostic, not a gate):** self-generated u2 pools may be less diverse than 22-brief Haiku users, shrinking target variance and moving R² mechanically; report per-layer tr(cov) of v(u2) vs the parent cell, distinct-3-gram rate, AND per-cell u2 token-length stats (mean/sd, vs the parent cell's) alongside every comparison — these ride in `headline_metrics.json`, never dropped from the headline table.

**u2 generation recipe (per cell).**
- Chat template (both models): prompt = `tokenizer.apply_chat_template([u1(user), a1(assistant)], add_generation_prompt=False, tokenize=False)` + `"<|im_start|>user\n"`; stop `["<|im_end|>"]`. This matches the parent's a-turn generation pathway (`_render`, incl. Qwen's default system prompt) except the appended header opens a USER turn — exactly the scope's "omit the assistant generation prompt" construction. Prediction render stays the parent's manual header render (no system prompt) — the same generation-vs-render context split the parent had for a1/a2.
- Naturalistic (both models): prompt = `"User: {u1}\n\nAssistant: {a1}\n\nUser: "` (the render's own segment strings); stop `["\n\n"]` — the format's turn delimiter, so emitting it IS the model ending its user turn; self-gen naturalistic u2s are single-paragraph by construction (noted as format semantics, §Assumptions).
- Sampling: `SamplingParams(temperature=1.0, top_p=1.0, max_tokens=512, seed=42)` — matched to the parent u2 arm (Haiku: T=1.0, max_tokens=512, API-default top_p=1; `issue825_gen_conversations.py:284-305`). Generated text `.strip()`ed before storage (Haiku-path parity).
- **Generation covers ALL kept-2000 rows — no generation-time row dropping (MF-A).** u2 is generated for every kept-2000 conversation in every cell; the per-cell conversations JSONL carries all 2000 rows. Extraction likewise covers all 2000 rows per (model, format). Row filters (u2 ≥ 8 content tokens; rendered length ≤ 2048 in the CELL'S OWN format — the parent's max-over-both-formats filter degenerates to this when each cell is fit in one format; §11) are applied at FIT time to USER cells only, via `--cell-row-allowlist` (per-cell conv_id lists emitted by the gen script's audit step). Anchor cells take no allowlist (full 2000). NO backfill, NO regeneration on drop — drops counted per class in `_meta.json`.
- Outputs: `data/issue_825/onpolicy/conversations_<model>_<fmt>.jsonl` rows `{conv_id, u1, a1, u2}` + `_meta.json` (audit metrics, drops, sampling params); uploaded to HF `issue825_onpolicy_user_turn/raw_completions/generation/` (text always uploads).
