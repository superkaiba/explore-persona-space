### 4.1 Per-step snapshot capture (no training-code edit)

`train_one_cell(step_calibration_fractions=…, frac_precision=4)` already exists at `affdd82cb` and threads to `CheckpointAtFractionsCallback`, which saves when `global_step / max_steps` first crosses each fraction and records the ACTUAL step in `checkpoint_index.json`. max_steps = 75 exactly (400 rows / (batch 4 × grad-accum 4) = 25 steps/epoch × 3; asserted post-build).

**Mid-point fraction targeting (float-robust):** target step *s* is captured by fraction (s − 0.5)/75, passed as 4-dp literals:

| target step | fraction passed | crossing check (step s−1 < f ≤ step s, margin ≥ 0.0066) |
|---|---|---|
| 6 | 0.0733 | 0.0667 < 0.0733 ≤ 0.0800 ✓ |
| 7 | 0.0867 | 0.0800 < 0.0867 ≤ 0.0933 ✓ |
| 8 | 0.1000 | 0.0933 < 0.1000 ≤ 0.1067 ✓ |
| 9 | 0.1133 | 0.1067 < 0.1133 ≤ 0.1200 ✓ |
| 10 | 0.1267 | 0.1200 < 0.1267 ≤ 0.1333 ✓ |
| 11 | 0.1400 | 0.1333 < 0.1400 ≤ 0.1467 ✓ |
| 12 | 0.1533 | 0.1467 < 0.1533 ≤ 0.1600 ✓ |

(Exact step-boundary fractions like 8/75 = 0.10666… are float-fragile against a 4-dp rounded target 0.1067 — the crossing would land one step late. Mid-points have ≥ half-a-step margin on both sides.) Bonus late saves: 0.3267 (step 25), 0.5000 (step 38), 0.7400 (step 56; fact-check correction — 0.7467 would capture step 57 since 56/75 = 0.74667 < 0.7467) + the terminal adapter (step 75, auto-recorded as the `1.0000` index entry). **Post-train assert (fail-loud): the callback-recorded steps for the 7 window fractions == {6,7,8,9,10,11,12}.**

Inline HF persistence (the original mechanism): `EPM_PERSIST_TRAJECTORY_HF_REPO=superkaiba1/explore-persona-space`, `EPM_PERSIST_TRAJECTORY_HF_SUBFOLDER=adapters/issue_585_step6to12/c504v4_smoke_eps3_seed42_retrain` — each snapshot uploads + Hub-verifies before the next training step proceeds (fail-loud, same as the original pretrain).
