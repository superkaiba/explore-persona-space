## D. Launch-contract fix (§10): self-daemonizing supervisor + heartbeat + cheap resume

Observed failure (launches 2 and 3): the gated bash driver died at ssh-session teardown while its phase-0 python child survived as an orphan — phase0 completed, p2+ never ran, the main log froze at the p1 line, and the pid file plausibly recorded the ssh wrapper's pid. Fix is mechanism-agnostic detachment plus liveness telemetry:

1. **Self-daemonization (in-script, idempotent):** at the top of `i601_launch.sh`, if `I601_SUPERVISED` is unset, re-exec under a fully detached session and exit:
   ```bash
   if [ -z "${I601_SUPERVISED:-}" ]; then
     export I601_SUPERVISED=1; mkdir -p "$LOG_DIR"
     setsid --fork bash "$0" "$@" >> "$LOG_DIR/issue-601-pipeline.log" 2>&1 < /dev/null
     echo "[launcher] detached; tail $LOG_DIR/issue-601-pipeline.log"; exit 0
   fi
   echo $$ > "$LOG_DIR/issue-601-launch.pid"   # written by the SUPERVISED process itself
   ```
   New session + new process group + no controlling TTY ⇒ ssh teardown/SIGHUP cannot reach the driver, regardless of how it was invoked (`nohup ... &` still works and is now redundant). The pid file is written from inside the supervised script (`$$`), never by any wrapper — closing the wrong-pid failure.
2. **Relaunch guard:** if the pid file exists and that pid is alive, refuse with a distinct `[launcher] already running pid=…` line and exit 3 (prevents double-dispatch on retry).
3. **Heartbeat:** a background subshell emits `[hb] <utc> pid=$$ phase=$CURRENT_PHASE` to the main log every 120 s (`CURRENT_PHASE` exported before each step; single combined EXIT trap kills the heartbeat and prints `[phase=abort] rc=$?` on any non-zero exit). Poller contract: driver dead ⇔ no `[hb]` for > 5 min AND the pid-file pid is not alive. This makes "driver dead, orphan child running" detectable in one log read — the exact state that went undetected twice.
4. **Resume semantics (relaunch is one cheap command):** p1 re-runs `i601_phase0_reads.py`, which already skips provenance-valid parity-regime outputs (verified, `i601_phase0_reads.py:115–122, 216–221`) — minutes, no GPU recompute; p2 re-reads the gate file; **p3 gains a skip**: if the smoke sentinel (bare or `.processed`) already records `smoke_gate_pass == true`, log `[phase=p3_smoke] sentinel valid; skip` and proceed (same accept-rename logic as p4); p5 already passes `--resume`. Net: any driver death is recovered by re-running the same launch line with no wasted GPU work.
