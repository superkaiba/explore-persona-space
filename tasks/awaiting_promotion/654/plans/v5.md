# Plan v5 — Issue #654 amendment: length-matched dummy-query control for the companion read

**AMENDMENT to v4 — one-variable diff, NOT a re-write.** Read v4
(`plans/v4.md`) for the full method, hypotheses, measurement-validity table,
and §11/§12. This document changes exactly ONE thing and inherits everything
else verbatim. Cheap-band same-issue follow-up round 1
(`followup_label: length-matched-dummy-query-control`).

## §0.0 TL;DR (plain English)

- **What I'll run:** In the parent run I found that, at the spot where the
  model is about to start writing, the internal state still looks about
  65-72% like the context even after I add a real user question. The problem
  is that a real question carries content but also makes the prompt longer
  and shifts where the readout token sits, and I couldn't separate those two
  effects. So here I add a fake question with no real content, padded to the
  exact same length as each real question, then read the same spot again and
  compare the two curves.
- **What I expect:** the fake content-free question will hold the state
  higher (more context-like) than the real question. The gap between the two
  curves tells me how much of the movement is actually about what the
  question says, rather than just its length or token position.
- **What would change my mind:** if the fake-question curve sits right on top
  of the real-question curve (within about 0.03 at every layer), then the
  late-layer "context persistence" I saw is just a mechanical length and
  position artifact, and the parent's headline bullet on that read gets
  weaker.

## §0. Plan Summary (technical)

- **Amendment:** add ONE query arm to the #654 battery — a content-neutral
  dummy query token-length-matched to each of the 10 real queries — extracted
  at the SAME assistant-generation slot, and compute the dummy-vs-real
  same-slot companion-curve gap per layer per tier. Everything else (model,
  81 contexts, read positions, centered cosine + within-tier B=1000 floor +
  linear CKA, seed 42) is v4 verbatim.
- **Single variable:** query *content* at matched length (real vs
  content-neutral dummy). The construct under test is whether the
  0.63-0.72 late-layer companion cosine (parent Finding 4) reflects query
  content or the mechanical length/position offset Finding 4 flagged as an
  unresolved confound.
- **Hyperparameters:** all inherited from v4 (`Source: plans/v4 §11`). The
  only NEW choice is the filler-string design (§2, §11) — a real grammatical
  neutral sentence padded with neutral filler words to exact token-length
  match, NOT pad-token soup (`<|im_pad|>` is NOT a single Qwen token — it
  encodes to 6 ordinary tokens, so it would be off-distribution; §11).
- **Baselines / controls:** the real-query companion curve from the parent
  run (already on HF) is the comparison arm; the dummy arm IS the new control
  that isolates content from length/position.
- **Loss surface:** N/A — no training; one forward pass per dummy pair.
- **Compute:** 1× A100-80 (GCP `a2-ultragpu-1g`, `lora-7b` intent), ~810 new
  dummy-pair forwards. The 81 cached context-only companion banks are REUSED
  (the companion's context-only side does not change), so no context-only
  re-extraction. `Estimated GPU-hours (total): 0.5`.
- **Evaluation:** dummy-vs-real per-layer per-tier same-slot companion-cosine
  gap. "Worked" = a clean per-layer gap curve; falsification (mechanical, not
  content) if the gap is within ~0.03 at every layer.
- **Risks (top 2):** (1) the filler could accidentally carry topical content
  (mitigated by a fixed neutral filler disjoint from every eval/ICL string +
  a build-time content assert); (2) exact token-length match can drift if the
  filler tokenizes differently in different ChatML contexts (mitigated by
  per-(context, real-query) length derivation + the same `0 ≤ ctx < query <
  seq` ordering assert the parent already wires in).

## §2. The single variable — the dummy-query design

**Filler choice.** ONE fixed content-neutral base sentence, padded to each
real query's exact token length with a neutral filler word. The base:

> `"Please continue with whatever you think is most appropriate here."`

A grammatical, content-free user turn that asks for nothing topical. Length
matching is done per (context, real query) by appending the neutral filler
word `" really"` (single Qwen token id 2167) repeated, then trimming the
final filler token if it overshoots, so the dummy query renders to the SAME
`query_end_idx` as the matched real query under the same context. (Padding
with a real word, not a pad token, keeps the dummy on-distribution — a real
user turn the model could plausibly see. `<|im_pad|>` is NOT a single token
in this tokenizer; it encodes to 6 ordinary subword tokens, so it would be
off-distribution noise and is explicitly rejected — §11.)

**Per-real-query padding rule (token-count exact match).** For each
(context, real query) pair the parent recorded `query_end_idx` (the last
prompt token before the assistant marker). The dummy builder renders
`context + dummy-base` and appends `" really"` tokens until the dummy's
`query_end_idx` equals the real query's `query_end_idx` for that context; if
the base already overshoots a very short real query, it trims trailing filler
tokens (and, only if still longer than the shortest real query under that
context, falls back to truncating the base sentence at a word boundary — the
realized dummy text + token count is recorded per pair). The length match is
asserted per pair; a pair where exact match is impossible (real query shorter
than the irreducible dummy core) is recorded with its residual length delta
and the delta is reported (a handful of short on-topic queries may carry a
±1-2 token residual — disclosed, not hidden). The same prefix + `0 ≤ ctx_end
< query_end < seq_len` ordering asserts the parent wires in (`derive_pair`)
run unchanged on the dummy pairs.

**10 dummy queries, frozen.** One dummy per real query, length-targeted to
that real query, stored in a new `data/issue654/battery_dummy.json` with the
realized dummy text, target length, achieved length, and residual delta
recorded per pair. The dummy `query_id`s mirror the real ones
(`q_ontopic_short_0` → `q_dummy_for_ontopic_short_0`) so the dummy-vs-real
join is by the real-query id.

**Content-neutrality assert (build-time, fail-loud).** The dummy base + every
realized dummy string is asserted disjoint from (a) the 10 real eval queries,
(b) every ICL demonstration first-user string, and (c) the wildchat
context turns — so the dummy cannot accidentally echo a context or eval
string. The filler word `" really"` carries no topical content by
construction.

## §3. What's measured (DV)

The new DV is the **dummy-vs-real same-slot companion-curve gap per layer per
tier**:

`gap(tier, L) = companion_cos_real(tier, L) − companion_cos_dummy(tier, L)`

where `companion_cos_*(tier, L)` is the v4 companion read (cosine of the
context-only assistant-gen slot vs the full-prompt assistant-gen slot, both at
the fixed generation position, mean over that tier's pairs) for the real vs
dummy arm. A **positive gap** means the real-content query displaces the
generation-slot state MORE than the content-matched dummy — i.e. the
late-layer displacement is content-driven, not purely mechanical. The
existing v4 companion DV definition is UNCHANGED; the dummy arm simply
supplies a content-matched comparison curve.

Reported per layer 0-27, per tier, with anchors [7,14,21,27]; the headline is
the per-tier gap curve, with the mean-of-tiers gap at the late-layer trough
(L23-L27, where the parent companion bottomed at 0.63-0.72) as the single
summary number. No new statistical correction, no derived-input dependency
(the gap is a direct difference of two computed cosine curves).

**Measurement validity:** on-distribution — both arms read the model's real
residual stream at the real assistant-generation slot in natural forward
passes; the dummy query is a real grammatical user turn, not a teacher-forced
stub. Direct measurement, not a proxy. (v4 §5 measurement-validity table
carries over; the gap inherits the same on-distribution status as the
companion read it differences.)

## §6. Success / kill criteria + risks

**Success (diagnostics, not gates):**
- **Content-driven (supports the parent's "context persistence" read):** the
  per-tier dummy-vs-real companion gap is clearly positive at the late-layer
  trough (real > dummy by more than the curve's per-layer spread) — adding
  real content displaces the generation-slot state more than a length-matched
  content-free query.
- **Mechanical (falsifies content-driven, weakens parent Finding 4):** the
  gap is within ~0.03 at every layer — the late-layer displacement is a
  length/position artifact, not query-content integration. A reportable
  outcome; folds into the parent's Finding 4 read as a strengthening or a
  weakening.

**Kill / sanity:** the parent's `> 5%` offset-failure kill criterion runs
unchanged on the dummy pairs (span-boundary indexing broke → halt + fix). The
length-match residual is reported per pair; if > ~10% of dummy pairs carry a
> 2-token residual (length match systematically failing), flag it (the gap
would then re-confound length and content — the very thing the control
removes).

**No gates — short run (~0.5 GPU-h, < 1h wall).**

**Risks (top 2):**

| Risk | Likelihood | Mitigation |
|---|---|---|
| Filler accidentally carries topical content, confounding the "content-free" claim | Low | Fixed neutral base + neutral filler word `" really"`; build-time disjointness assert vs all eval/ICL/wildchat strings; the filler is content-free by construction |
| Exact token-length match drifts across ChatML contexts (filler tokenizes differently after different context tails) | Medium | Per-(context, real-query) length derivation through the SAME tokenizer + `apply_chat_template` path; per-pair length-match assert + recorded residual delta; reported, not hidden |

**The ONE new hyperparameter — the filler-string design:**

- **What:** dummy-query base `"Please continue with whatever you think is most
  appropriate here."`, length-padded with the single-token filler word
  `" really"` (Qwen id 2167) to exact per-(context, real-query) token-length
  match.
- **Why (tied to the Goal):** the control must hold query *length* and read
  *position* fixed while removing query *content* — so the dummy must (a)
  carry no topical content (else it re-introduces the very content the control
  isolates) and (b) match each real query's token length exactly (else the
  gap re-confounds length, the parent's flagged confound). A real grammatical
  neutral user turn keeps the dummy on-distribution (a turn the model could
  plausibly receive), unlike a pad-token string.
- **Source:** design choice grounded in the parent's own Finding 4 confound
  statement (length/position confound unresolved at the companion read) +
  the data-realism rule (a real grammatical turn beats pad-token soup);
  `ungrounded — needs smoke-test` only for the exact base wording (the smoke
  run prints the realized dummy strings + per-pair length residuals for 8
  pairs to confirm content-neutrality + length match before the full run).
- **Alternatives rejected:** `<|im_pad|>` padding — NOT a single Qwen token
  (encodes to 6 ordinary tokens), off-distribution, would itself perturb the
  residual stream and confound the read; a single repeated word as the whole
  dummy ("really really really…") — degenerate, not a plausible user turn,
  risks a distinct degenerate-text geometry; per-context bespoke dummies —
  would not match the real-query length factor cleanly across contexts.

(used by #594/#617/#650).

## §10b. Plan deviations allowed vs must-ask

**Allowed (autonomous, recorded in run meta):** swapping the exact filler base
wording or filler word if the smoke shows it cannot length-match the shortest
real queries (record the realized strings); the `--reuse-context-only`
fetch-vs-flag wiring detail (implementer's call); a ±1-2 token residual on a
handful of very short on-topic real queries (reported per pair); falling back
A100-80 → L4 on GCP capacity (explicit recorded reason; the parent's §10b L4
fallback note applies).

**Must-ask / pivot-per-workflow:** changing the read position or the companion
DV definition (breaks comparability with the parent's companion read);
changing the centering mode or floor (breaks the persona-distance line);
adding a content-bearing dummy (defeats the control); adding training of any
kind.
