## 0.0 TL;DR (plain English — the user reads this first)

- **What I'll run:** I build pairs of prompts that are identical except for exactly one piece of information — an instruction like "answer in bullet points", a stated fact like the user's name, a persona, an in-context-learning task, 21 kinds in all — then copy the model's hidden state at just ONE position (the end of the context, and separately the end of the prefix) from one prompt into the other and let it answer. If the answer follows the swapped-in information, that position carries it. Every kind gets three comparison runs: the real swap, a scrambled swap of the same size, and a swap borrowed from a different kind of information — plus a separate cheap "can a linear read-out even find this information in that state?" probe, so I can tell "not stored there" apart from "stored but not usable".
- **What I expect:** style and policy information (personas, format and language instructions) transfers through the single position; specific retrievable facts (names, dates, list items) do not — the model looks those up from where they were written, not from the summary position. The recency and load variants test whether the position behaves like a running summary or just echoes what came last, and the conflict variant tests whether instructions or demonstrations win.
- **What would change my mind:** if facts DO transfer through the one position, the "it's just a style summary" picture is wrong. If nothing transfers but the linear probe reads everything, the position stores information the model doesn't causally use from there. If the in-context-learning task fails to transfer, published task-vector results don't hold at this position, which localizes where those vectors actually live.

## 3. Hypothesis

Pre-registered predictions (body § Pre-registered predictions, verbatim in substance):

1. **Policy types transfer at context-end** (`persona_prompted`, `demo_persona`, `instr_format`, `demo_format`, `instr_language`, `verbosity`): F_beh ≥ 0.2 clearing both nulls (task/function-vector prior, 2310.15916 / 2310.15213).
2. **Retrievable items do not** (`fact_user_name`, `fact_assistant_animal`, `fact_novel_queried`, `list_numeric_detail`): attribute extraction attends to the entity's own positions (2304.14767), untouched by a last-position patch.
3. **`icl_task_mapping` is the sharpest rig test:** transfer replicates task vectors at context-end, or a failure localizes the published effect to the `→`-separator extraction point (a deliberate extraction-point difference, named).
4. **`query_content` ≈ 0** (replicating #2094's matched-prefix null); **`filler_swap`** shows generic disruption only (no F — no ceiling by construction).
5. **Prefix-end** carries prefix-only types if anything (#2094 measured zero null-separated prefix-end behavior families — the prior is a null); query-conditional types cannot be there.
6. **Conflict:** demonstrated route wins if v_C summarizes realized behavior; instructed route wins if it summarizes stated policy. Either answers 1.3.
7. **Recency:** F decays with introduction depth if v_C is recency-dominated, flat if a running summary. **Load:** target F decays with load if the vector saturates.

### 4.1 Bank — 21 types × 3 value-pairs × 12 carriers, plus 18 crossed cells (data tier declared)

New module `src/explore_persona_space/experiments/issue2162/bank2162.py`; strings frozen at the landing commit and uploaded as `bank.json` (#2094 convention). Structure per BASE type-cell:

- **3 value-pairs** per type. Types with a natural value set use 3 values v1/v2/v3 → unordered pairs (v1,v2)/(v1,v3)/(v2,v3) (e.g. `fact_user_name`: Alice/Priya/Marcus); strictly binary types use 3 distinct phrasing instantiations of the SAME A/B contrast (e.g. `constraint_knowledge`: three wordings of has-internet vs no-internet), each instantiation a value-pair. The body's exemplar A/B strings (§ Design Factor 1 table) are value-pair 1 of each type verbatim; the bank module carries the authoritative full set.
- **12 carrier queries**: 3 direct-probe (type-specific, hand-written — e.g. "What's my name again?", "When was the Zorbian treaty signed?") + 9 neutral, drawn from the SHARED neutral carrier set (below); types admitting no direct probe use 12 neutral. `icl_task_mapping` exception: its carriers are 12 task-input words (common English words, hand-authored, frozen), its demonstrations 4 antonym or synonym exemplar pairs per the 2310.15916 task shape.
- **Contexts** = 3 values × 12 carriers = 36 per cell; **pairs** = 3 value-pairs × 12 carriers = 36 per cell, token-identical except the varied span, canonical direction A→B (value-index lexicographic).

**Neutral carrier set + realism (tier declared):** the 9 shared neutral carriers are REAL WildChat user queries — `artifacts/banks.load_bank("wildchat_random")` (600 real queries, in-git `query_banks/wildchat_random_v1.json`), reserved index range **[250:400]** (disjoint from the registered slices: formatting 0–250, marker 500–600), passed through a deterministic committed filter (20–300 chars, ≥95% ASCII-letter fraction, interrogative or imperative form, no PII/harmful content by a committed keyword screen), seeded selection seed 2162. Recency padding turns and load fillers likewise draw their user turns from the same reserved range; padding ASSISTANT replies are generated ON-POLICY (greedy) from Qwen-2.5-7B-Instruct and frozen into `bank.json` — no third-party-LLM-written text enters any context. **Tier:** hybrid — tier-1 carriers/filler (real WildChat queries) with tier-4 CONSTRUCTED contrasts (the varied spans; minimal pairs do not exist in the wild — the body's own justification). Mitigations (body): per-pair token-length delta recorded as a covariate; a length-matched sensitivity subset (|Δlen| ≤ 2 tokens) recounted for every headline type where the varied span permits. **Completion provenance:** every completion in the experiment is generated on-policy by the frozen base model under the (possibly edited) context — temp-1.0 K=5 grid draws, K=10 anchors, greedy stage-2 — disclosed per arm in every table.

**Crossed cells (18):**
- **Conflict (4):** `instr_format`⊕`demo_format` and `persona_prompted`⊕`demo_persona`, both directions. Pair = (A = instruction X + demonstration Y; B = the reversed conflict, instruction Y + demonstration X), same 3 value-pair instantiations × 12 carriers. Contexts largely shared with the base cells' components (nearly free, per body).
- **Recency (8):** `fact_user_name`, `instr_format`, `persona_prompted`, `prior_topic` × depths {3, 5} (depth 1 = the base cell). The varied span is introduced at turn 1, followed by (depth−1) neutral padding exchanges IDENTICAL between A and B — the minimal-pair property is preserved exactly.
- **Load (6):** `fact_user_name`, `fact_assistant_animal`, `instr_format` × loads {3, 5} (load 1 = base). The prefix carries load-many same-type pieces; ONE designated target piece varies between A and B, the others identical. Reports the target's F plus non-target spillover (exact-string / judged expression of the unchanged pieces on direct-probe carriers — exploratory).

Total: 21 base + 18 crossed = **39 type-cells**; 1,404 contexts; 1,404 pairs.

**Pre-declared degenerate cells (constructional, known at plan time):** `query_content`@prefix-end and `persona_role_header`@prefix-end (A/B share the entire prefix — prefix-end states identical; the varied span for type 11 is the generation-prompt role header itself, after the query) → flagged `degenerate_self`, generated + flagged + excluded from aggregates exactly as #2094 handled the same case; `filler_swap` reports NO F anywhere (no behavioral ceiling by construction — disruption DV only). `persona_role_header`'s varied span is immediately adjacent to the context-end slot — its designed property (role-header information is definitionally boundary content), named in every figure caption.

### 4.2 Interventions, slots, arms

**Both mapping arms note:** every cell runs at context-end AND prefix-end by design (the standing prefix+context both-arms rule is satisfied by construction; the prefix-end arm is substantive — body Factor 3).

**State bank (P1):** per context × layer, capture `v_ce` (last context token, generation prompt included — the #779 slot) and `v_pe` (last prefix token = start of the FINAL user turn − 1, via `bank.prefix_end_index_multi` — handles multi-turn recency contexts) in one right-padded forward per context, positions read off token ids (BPE-seam rule). These states feed the patches AND the read probe.

**Stage 1 (primary, confirmatory):** full-state replace at ALL 28 layers at the slot — `joint_hooks(model, range(28))` + `arm_batch_per_layer(..., mode="replace")` with per-layer targets = the donor context's state at that slot/layer. Source: #2094's largest clean effect (0.63, null −0.05); a null under the maximal edit is strong evidence of absence.

**Arms (3 per cell × slot):**
1. **Steered:** target = V_slot(B, ℓ) per layer (the pair's own donor).
2. **Shuffled-donor null:** target = V_slot(B_donor, ℓ) from a DIFFERENT pair of the SAME type-cell — seeded derangement (seed 2162, `bank._seeded_derangement` pattern, no fixed point, constrained to a different value-pair where the pool allows), norm-matched per layer to the recipient's own B-state (`bank.norm_match`; #2094 installed the raw donor state at replace cells — the norm-match here is a strictly-cleaner planner refinement, flagged §12).
3. **Cross-type-donor null:** target = V_slot(B, ℓ) from a pair of a DIFFERENT type at the SAME carrier query where the donor pool admits (the shared neutral carriers make this available for most cells; type-specific-carrier cells fall back to a seeded draw from the donor type's neutral-carrier pairs), norm-matched per layer; donor type + pair id recorded per row. Seeded type-derangement (seed 2162) balances donor types. Holds "an edit of this size happened" fixed while removing the content match — the tighter specificity test (body).

**Stage 2 (post-selection, exploratory):** pair-difference edits (mode="add", Δ = V(B)−V(A)) at doses {1, 4} × single layers {8, 12, 14, 16, 19, 22, 26}, run ONLY on Stage-1 survivor (type-cell × slot) combos (selection rule §6), steered + shuffled-donor arms, 1 greedy draw per pair, capped at 12 survivor combos by descending steered F_beh. Labeled post-selection everywhere (as #2094).

### 4.4 Metrics (implementing the body verbatim)

- **F_beh (PRIMARY):** per draw, dual-rubric contrast Δ = (judge_B − judge_A)/100 with the type's OWN rubric descriptor pair (each type's rubric pair is the graded 0–100 form of its A/B values, `bank2162.rubric_pair_2162(type, value_pair)`, built on the #2094 `f_prefix_rubric`/`f_query_rubric` shape); F_beh = (Δ̄_patched − Δ̄_floor)/(Δ̄_ceiling − Δ̄_floor) via `fmetrics.f_beh` (floor = unpatched-A anchors, ceiling = generate-under-B anchors — baseline propensity measured on BOTH pair sides by construction). Conflict cells: rubric pair = (follows-the-instructed-value, follows-the-demonstrated-value); balance = (judge_demo − judge_instr)/100; same normalization → the conflict balance shift.
- **F_act (activation twin, at every cell):** signed projection of the patched-minus-floor answer-state shift onto the ceiling-minus-floor axis, disjoint floor halves (`fmetrics.f_act`); answer state = span-mean V_a over the model's own completion at read layer 26 (the #2094 primary read layer; all-28 profiles exploratory), captured by hooked teacher-forced re-forward of each rollout. Judge-free; same three arms + nulls; cell-level Spearman ρ(F_act, F_beh) reported as the agreement diagnostic (#2094: 0.43–0.50 over 929 families).
- **Teacher-forced fixed pos-vs-neg margin (SECONDARY continuous, llm-judging rule 19):** per type, a FIXED pool of 4 B-value-exhibiting + 4 A-value-exhibiting completions (drawn from that type's ceiling/floor anchor draws, judge-filtered at the persona-vectors threshold: descriptor score > 50 kept), length-normalized teacher-forced log-P of each pool item under every Stage-1 patched state (hook armed) and under the unpatched floor/ceiling anchors; margin = mean lnP(B-pool) − mean lnP(A-pool). Validation: ρ(margin shift, F_beh) > 0 across cells with dynamic range, reported BEFORE the margin carries any cross-condition read; never the headline.
- **Programmatic companions (sanity only):** bullet-line count (`instr_format`/`demo_format`), langid (`instr_language`/`language_implied`), exact string match (`fact_*`), token count (`verbosity`).
- **Linear read probe:** per (type × slot × layer), batched LOGISTIC probe (linear, L2-regularized, implemented as vectorized torch GD over all layers × value-pairs × folds simultaneously per type-slot group — no serial sklearn loop; `.claude/rules/vectorize-many-cell-fits.md`) on the P1 context states, predicting which value is present. Binary per value-pair (n = 24 contexts each). Folds (both GROUP-level): (a) PRIMARY leave-one-carrier-out (12 folds, group = carrier query); (b) SECONDARY value-pair-transfer — train on 2 value-pairs, test the third, under the type's registered value POLARITY where one exists (polar types listed in the bank module: format/language/verbosity/reasoning/expertise/emotion classes); non-polar types (the named fact/identity types) report scheme (b) as an exploratory identity-coding read (expected chance), never a confirmatory fold. AUC vs chance 0.5, per-layer curves reported in full; "probe-positive" uses the selection-symmetric max-over-layers read (§6). `filler_swap`/`query_content` probe: labels are the filler/query identities (well-defined; reported for completeness).
- **Read × write 2×2 (the deliverable):** per (type × slot), causal verdict × probe verdict per the §3 lattice.

### 4.5 Coherence gate, cap policy, mechanical audits (binding, per body)
