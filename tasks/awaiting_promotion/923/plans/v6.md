## 0.0 TL;DR (plain English)

- **What I'll run:** The completed run found something odd: reading the model's internal state from one single token at the end of the full prompt predicts the answer fingerprint WORSE than gluing together two reads taken from the context alone and the question alone. But that one token is a bottleneck by construction — maybe the full prompt's information is all there, just spread across many tokens instead of parked at the end. So I re-run only the reading step: instead of one token per input, I average the internal state across all the tokens each input owns, for every arm, and refit the same simple linear read-outs on the same targets and the same held-out splits.
- **What I expect:** Averaging should help the full-prompt read most, because format-style instructions ("answer as code comments") dominate the final prompt positions and drown out everything else at that one slot. If the full-prompt deficit disappears under averaging, the completed run's headline gets rescoped to "a last-token artifact"; I'd also expect the question-only read to close part of its gap to its ceiling.
- **What would change my mind:** If the averaged full-prompt read STILL trails the averaged glued-together read, with the uncertainty interval clearly excluding zero, the bottleneck explanation is dead and the "no attention-mixing advantage for linear read-out" takeaway hardens from "one estimator, one read-out slot" to "robust to how you summarize the prompt."

## 3. Hypothesis

Let Δ_pool = R²(Full-prompt pooled) − R²(Stitched pooled, presentation i) at frozen L18, UC genre, pooled LOFO×held-out-query skill; parent Δ_last = −0.081 [−0.157, −0.045]. Paired diff D = Δ_pool − Δ_last via shared-draw family bootstrap (§6).

- **H-slot (slot artifact; scope's "pooling closes the gap"):** span-mean pooling recovers most of the full-prompt deficit. Confirmed iff the Δ_pool CI is wholly at/above 0, OR (the Δ_pool CI includes 0 AND the paired-diff CI is strictly positive). A bare positive point estimate with both CIs straddling 0 is NOT H-slot (it is intermediate). A still-negative significant Δ_pool with a strictly-positive paired diff is reported as "deficit persists with partial closure" under H-robust — never as gap closure. Consequence when confirmed: parent Takeaways bullets 1–2 are rescoped as last-token-slot-specific.
- **H-robust (summary-robust deficit; scope's falsification):** Δ_pool < 0 with the 2000-draw family-bootstrap 95% CI excluding 0. Consequence: the slot-artifact explanation is dead; the "no attention-mixing advantage for linear read-out" takeaway hardens from estimator-scoped to summary-robust.
- **Intermediate:** Δ_pool CI includes 0 AND paired-diff CI includes 0 → no binary verdict; report the graded closure fraction 1 − Δ_pool/Δ_last with CI. The three labels are DISJOINT and exhaustive: H-robust ⇔ Δ_pool CI wholly below 0; H-slot ⇔ (Δ_pool CI wholly at/above 0) OR (Δ_pool CI straddles 0 AND paired-diff CI strictly positive); intermediate ⇔ otherwise. Exactly one label fires for every (Δ_pool, CI, paired-CI) cell.
- **Secondary (registered, graded, no gates):** (s1) format-family Full-prompt pooled skill vs the parent's 0.171 (does the family collapse persist under pooling?); (s2) Query-only pooled vs last-token 0.448 against the 0.837 in-sample query share (closure of the 0.389 readability gap); (s3) Betley replication of the primary contrast; (s4) Dolly ordering under pooling; (s5) whether pooling removes the Betley masked-context collapse (parent pooled read −3.03 via penalty selection).
- **Pre-registered non-error outcome (inherited v3 §3):** Δ_pool < 0 with Stitched-pooled ABOVE Full-pooled remains the bottleneck-generalizes reading; Δ_pool > 0 (Full beats Stitched under pooling) is meaningful, not a bug.
