<h1>Plan — Task #560: Cross-recipe transfer of the held-out persona channel structure to the 16 broad-negative-recipe marker adapters</h1>

<section class="plan-tldr">
<h2 style="margin-top:0">0.0 TL;DR</h2>
<ul>
<li><b>What I'll run:</b> No new training. I take the 16 marker adapters that were trained with the broad 15-negative recipe (already on HF), have each one answer the same 20 questions under the same 35 held-out personas the parent panel used, and read the marker's four logit values at the end of every answer, on the trained model and on the base model.</li>
<li><b>What I expect:</b> Personas closer to an adapter's source prompt pick up a bigger marker push from training. The trained end-of-answer level should stay almost identical to the base model's. The 32 personas never used as negatives should barely move at the end-of-answer slot, while the 3 personas whose prompts match trained negatives word for word should move a lot.</li>
<li><b>What would change my mind:</b> Distance-to-change correlations that sit on zero under every error bar would mean "geometry routes the change" was a one-recipe fact, and the hope of auditing leakage before training fades with it. A strongly positive end-of-answer shift on the never-used personas would break the exposure story.</li>
</ul>
</section>

<li><b>H3 (exposure account):</b> trained-negative persona cells (assistant/comedian/villain under non-source adapters, 45 cells) show mean dz_eos &gt; never-negative cells (32 personas × 16 adapters, 512 cells), difference CI excluding 0; never-negative mean dz_eos &lt; +6.4 (the #532 never-clamped anchor under these same adapters).</li>
<li><b>Falsification F1:</b> min_dist→dz AND min_dist→dmargin CIs span zero on ALL axes (cell bootstrap, 16-run cluster, 35-persona cluster) → "geometry routes the change" is recipe-specific. <li><b>Falsification F2:</b> never-negative mean dz_eos ≥ +6.4 with persona-cluster CI excluding values below it → strongly positive clamp on never-negative personas; exposure account broken.</li>
</ul>

<h2>4. Design</h2>
<p><b>Panel:</b> 16 adapters (run axis) × 35 held-out personas × 20 #478 eval questions = 11,200 (run, persona, q) triples; aggregated to 560 run×persona means for inference. Channels per aggregate (all trained − base unless noted): dz = Δz_marker, dz_eos = Δz_eos, dmargin = Δ(z_marker − z_eos), margin_trained, margin_base (matched slot), dlogp, plus logp/argmax diagnostics — the full four-float contract per slot per side.</p>

<p><b>Exposure classification (load-bearing, asserted in code):</b> byte-compare each held-out persona's system prompt against the 16 condition system prompts (A-class only carry system prompts). Verified during planning: <code>assistant</code> ≡ A1, <code>comedian</code> ≡ A4, <code>villain</code> ≡ A5 (byte-identical); no other matches possible (B/C/D have no system prompt; remaining A prompts differ). Cells: <b>source-resident</b> = {(A1, assistant), (A4, comedian), (A5, villain)} (3; persona IS the source context — excluded from correlational reads, used as positive controls); <b>trained-negative</b> = those 3 personas under the other 15 adapters each (45); <b>never-negative</b> = remaining 32 personas × 16 (512). The code asserts exactly 3 prompt matches and that the strata partition the 560 cells. Note: the parent classified by label (all 35 "never trained negatives"); the prompt-identity classification is registered primary here, and the parent's label-only view (all 35 pooled) is reported as a sensitivity row for cross-panel comparability.</p>

<p><b>Generation-driver / scoring pseudocode (new file <code>scripts/issue560_crossrecipe_panel.py</code>, --phase smoke|gen|geometry|score-base|score-trained):</b></p>
<pre>
PERSONAS_35 = sorted(held_out keys of eval_results/issue_478/logit_rescore/K1_c00_seed42.json)  # asserted == clarifier list
EVAL_QUESTIONS = load from #478 raw artifact @ pinned rev (assert n == 20, identical across 2 cells)
PROMPT(persona, q) = tokenizer.apply_chat_template([{system: ALL_EVAL_PERSONAS[persona]["prompt"]}, {user: q}], add_generation_prompt=True)

def phase_gen():
    llm = LLM(BASE, enable_lora=True, max_lora_rank=32, max_model_len=4096)
    for i, cid in enumerate(SOURCES_ALL, 1):              # 16, resume-skip if JSON exists
        prompts = [PROMPT(p, q) for p in PERSONAS_35 for q in EVAL_QUESTIONS]
        outs = llm.generate(prompts, SamplingParams(temperature=0.0, max_tokens=2048),
                            lora_request=LoRARequest(cid, i, adapter_dirs[cid]))
        write raw_completions_{cid}.json (persona -> q -> text, truncated flag)

def phase_score(side):                                     # side in {base, trained}

    for cid: jobs = [_slot_job(PROMPT(p,q), R[cid][p][q], tok, bare_id) for p,q ...]
             reads = _run_slot_batches(model, tok, jobs, bare_id)       # four floats + argmax
             write four_float/{side}_{cid}.json  (persona -> per_q list)
</pre>

<h2>14. Critic-ensemble concerns for the analyzer (round-1 APPROVE; carried forward, binding write-up guidance)</h2>
<p>All six critics (3 lenses × Claude + Codex) APPROVEd the design (statistics lens via binding reconciler). No plan revision required. The following concerns are NOT design changes — they are analyzer / write-up guidance the downstream interpretation MUST attend to. All are post-hoc computable from the persisted four-float arrays + both cluster bootstraps.</p>
<ol>
<li><b>H3 / F2 binding axis:</b> the run-cluster CI is the verdict-bearing interval for the exposure contrast; the 3-persona-cluster CI is descriptive only (3 clusters is not an uncertainty estimate). Treat +6.4 as a cross-panel reference line, not a kill threshold — lead the H3 read with the new panel's own CI against 0 and the #478 −3.07 analogue; a never-negative mean in (0, +6.4) is weakening-not-breaking; a point ≥ +6.4 with straddling CI is indeterminate-leaning-broken. Scope H3 as 3-persona-limited; avoid causal "exposure causes the clamp" phrasing ("the prompt-identical negatives show the predicted excess" is what the data carry; exposure and persona identity are perfectly confounded in this design — the saving observation: geometry predicts the OPPOSITE sign for these near-zero-distance personas).</li>
<li><b>CI/Holm precedence:</b> verdicts are CI-only; Holm-adjusted p's are diagnostics. When they disagree, narrate the tension and let the widest-axis CI govern. Never describe H2/H3 reads as Holm-corrected.</li>
<li><b>Middle-zone narration:</b> outcomes outside Success/F1/F2 (split dz/dmargin verdicts, one-axis-only exclusion) are reported per-axis with parent points as reference lines. A significantly POSITIVE min_dist→dz or →dmargin correlation is evidence AGAINST H1, not indeterminate. The most informative recipe-specificity signature: persona-axis CI excluding the parent point estimate (−0.24/−0.27) while containing 0. A run-axis-only null must not be narrated as transfer failure.</li>
<li><b>H2 persistence is a weak null:</b> trained z_eos = base z_eos + dz_eos, so ρ ≥ 0.9 is near-guaranteed when Var(persona-FE dz_eos) ≪ Var(base z_eos). Report the variance ratio var(dz_eos FE)/var(base z_eos FE) alongside ρ AND a calibrated null (expected ρ from the observed variance ratio and/or permuted-delta refit; or split-question check). Lead the persistence narrative with the variance ratio; lead clamp-routing with the partial check. If observed ρ ≈ calibrated null, scope as variance-ratio rank persistence, not a stronger mechanism.</li>
<li><b>Slot-kind composition vs distance:</b> pre_marker slots fire exactly where the marker is emitted, so slot-kind composition correlates with leakage by construction. Report pre_marker/end_of_response fractions per persona as a function of min_dist (and per exposure stratum / distance tercile), plus a slot-kind-stratified (or end_of_response-only) sensitivity ρ for H1. If the negative correlation lives entirely in the slot-kind flip, the claim is "geometry routes emission," not "geometry routes graded sub-threshold pressure."</li>
