**Phase A — teacher-forced capture + SAE encode (GPU, row-sharded across all GPUs):**
1. Stage inputs (scoped `list_repo_tree` + per-file `hf_hub_download` at rev `e5901706`; never `snapshot_download` on the data repo): corpus manifest/prefix_store/query_store, the 42 `cell_inst_own` + 42 `cell_pre_own` completion shards; SAE via `BatchTopKSAE.ensure_downloaded(k=64, cache_dir)`; r_B bank at rev `037fcbb`.
2. Rebuild per-row texts with the parent's own code: `issue1092_gpu_phase.load_manifest/load_store/_prefix_turns/_query_text/_render_prompt_parts` + completion keyed by `row_id` from the shards (writer schema `{"row_id", ..., "completion"}`, `issue1092_gpu_phase.py` L1859–1863). Empty/None completion → drop row, report count (parent's `render_row` treats empty completion as valid-None; we require answer tokens).
3. Teacher-forced HF forward per batch (bf16, `output_hidden_states` scoped to layer 19 via a forward hook; positions via `_capture_row_ids_and_positions` — per-segment token-id concat + offset-based prefix_end, the parent's BPE-seam fix). Per row capture layer-19 resid_post at: prefix_end token, context_end token, all answer tokens.
4. SAE encode every captured token (`BatchTopKSAE.encode`, fp32 on GPU, chunked); apply reference token-pool semantics: fitness reads use `fve_l0` (outlier filter + var-based FVE); pooled-answer consumers strip nothing inside the answer (answer spans start far past position 8) but the FITNESS token pool applies the BOS_OFFSET strip on full-sequence samples.
5. **Fitness gate (per arm, before any read):** sample ≥200k token rows across the cell's sequences (post BOS-strip, inlier-filtered), compute FVE/L0 via `fve_l0`. Instruct arm: FVE ≥ 0.70 AND 30 ≤ L0 ≤ 130 required (expected ≈0.81/62); FAIL ⇒ kill criterion K1. Base arm: same thresholds; FAIL ⇒ drop the base arm, REPORT the gate values (never silently proceed).
6. Per-row feature summaries (fp16, dense in RAM; sparse union-idx on disk via `sparsify`): `prefix_end` features, `context_end` features, pooled answer trio (mean / max / frac-active over answer tokens) — ENCODE-THEN-AVERAGE only; the averaged-grain inputs f̄(P) = mean over the prefix's 48 queries of context-end features (and prefix-end trivially constant per prefix) are computed FROM the per-row encodes. Cross-query consistency per (feature, prefix) = fraction of the 48 queries with the feature active at context-end — same pass.
7. Upload phase-A artifacts (sparse per-row stores + fitness JSON) to HF BEFORE phase B (the expensive-store-before-long-fit ordering; regeneration cost ≈ one GPU phase).

**Phase B — maps + ANOVA + nulls (GPU, sharded by arm × fold; pilot-gated):**
- Restrict fits to ACTIVE features (nonzero in ≥0.5% of rows at the relevant summary; realized d_act recorded). Targets: pooled-answer MEAN (primary), max/frac (exploratory).
- Map (a) per-row context-end → pooled-answer (single-context grain, n=4,752); map (b) per-row prefix-end → pooled-answer (both-arms rule satisfied by design). Ridge in dual/Gram space (n×n eigendecomposition per fold, batched λ sweep), grouped 6-fold by prefix, seed 0, λ ∈ {0.01, 0.1, 1, 10, 100, 1000} selected by inner-grouped-CV within the training fold.
- Map (c) induced averaged read (PRIMARY averaged read): apply the fold-model that held out prefix P to f̄(P) and score against the averaged pooled-answer target — no new fit. The independently-fit averaged map (n=99 prefixes ≪ any feature dimension — an explicitly under-determined regime) is SECONDARY/diagnostic only, grouped by prefix, reported only with that estimator-validity caveat stated.
- Per map: held-out R² (pooled over active features + per-feature R² columns), identity+learned-bias baseline (dims match: input and output are both the active-feature space; where map inputs/targets use different active sets, evaluate on the intersection and state it), kNN retrieval (euclidean + cosine, k ∈ {1, 10}, held-out candidate pool per fold, chance = k/n_pool stated).
- Per-feature crossed ANOVA on the 99×48 grid (balanced by assert): prefix / query / interaction variance shares for every answer-side feature — one batched segment-mean pass, NO per-feature Python loop. Nulls: 200 prefix-label permutations + 200 query-label permutations (batched, GPU); per-feature p-values with BH-FDR; the tail-selection read uses the permutation MAX-share distribution (selection recomputed per draw) so the top-100 selection is compared against what selection alone produces.
- Characterization join per feature: prefix/query/interaction shares (+ null p), per-arm per-feature R², activity, within-answer consistency (mean fraction of answer tokens active, given active in the row), cross-query consistency, |cos(W_dec[:,j], r_B[layer 19, trait])| for evil/hallucination/sycophancy (one normalized matrix product) vs a 200-draw random-direction null.

**Phase C — judge labels (API, dispatched concurrently with phase B):**
- Feature set: union of (i) top-100 prefix-share (among active features), (ii) per arm (context, prefix) top-50 and bottom-50 per-feature R² — union ≈ 250–300 features. Evidence per feature mirrors `FC._judge_items`: top-8 rows by pooled-mean activation, 400-char answer snippets.
- Two rubrics, one behavior per call (llm-judging rule 8): call 1 = `FC.JUDGE_SYSTEM` VERBATIM (level: low/high/unclear; rubric-hash recorded; parity with the #1482 reference hash asserted); call 2 = NEW persona_related rubric (binary persona_related true/false + ≤8-word label + brief reasoning; anchored: "persona-related = the shared property concerns the assistant's persona, identity, role, stance, tone toward the user, or a persona/behavior trait (e.g. sycophancy, refusal, self-description) — as opposed to topic, task type, formatting, or language"; own rubric hash recorded — no parity claim). Judge `claude-sonnet-4-5-20250929`, max_tokens 400, drop-never-coerce validation per field, transport failures retried/re-judged never persisted (dispatch via `eval.judge_dispatch.dispatch_judge_items` with checkpoint_dir; rubric-keyed cache).

- Dispatch timing: tail (i) is selectable right after the ANOVA pass (~first minutes of phase B) — dispatch immediately; tails (ii) dispatch as soon as per-feature R² lands; judge I/O overlaps the permutation battery and retrieval reads.
