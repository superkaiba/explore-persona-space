# Plan — Task #2333: Snowball test — do context-vector patch effects run through the first few answer tokens?

## 0.0 TL;DR (plain English)

- **What I'll run:** We know that copying one "summary" hidden state from a donor conversation into a target conversation changes the model's whole answer. One boring explanation is a snowball: the copy only really changes the first couple of words, and the model then stays consistent with its own opening. I'll test that directly on the strongest cells from the two parent experiments, on both models: instead of copying the summary state, I'll either copy only the hidden states over the first 1, 2, or 3 answer words, or simply force the first 1, 2, or 3 words of the answer as text and let the model continue freely.
- **What I expect:** Forcing or patching just the opening will move behavior somewhat, but well short of the full summary-state patch. That would say the effect is not just a snowball from the first words; the summary state keeps steering the answer as it unfolds.
- **What would change my mind:** If forcing three opening words reproduces half or more of the full patch effect, the snowball story is basically right, and the "context vector" result is mostly about which opening the model commits to.

## 3. Hypothesis

The snowball hypothesis predicts the ce patch's behavioral effect is mediated by the first few answer tokens. Concretely, per (model × pair-set × donor scheme):

- **H1 (snowball-sufficient):** prefilling the first 3 tokens recovers ≥ 50% of the banked ce-control F_beh (and separates from its shuffled-donor null).
- **H2 (partial mediation):** first-k arms separate from their nulls but recover < 50% of ce F_beh — the opening carries some but not most of the effect; the ce patch's persistent-state channel dominates.
- **H3 (no snowball):** first-k arms do not separate from their nulls — the opening carries essentially none of the effect.

Auxiliary predictions: recovery is non-decreasing in k (descriptive read); the state-patch arms (which also perturb the KV/recurrent entries at positions 1..k) recover at least as much as the token-only prefills under the mediation scheme; F_act mirrors F_beh in rank (parents: cell-level ρ 0.43–0.50).

Registered quantities, per (model × pair-set × scheme): paired-diff = per-pair mean-F_beh(prefill-3, steered) − mean-F_beh(prefill-3, scheme-matched shuffled-donor null), pair-clustered bootstrap 95% CI (B=10,000, seed 23330); D3 = mean over well-separated pairs of (F_beh(prefill-3, steered) − 0.5 × F_beh(ce control, steered)), same pairs, banked ce rows.

DISJOINT and exhaustive: Snowball-sufficient ⇔ paired-diff CI strictly positive AND D3 ≥ 0; Snowball-partial ⇔ paired-diff CI strictly positive AND D3 < 0; No-snowball ⇔ otherwise.

The lattice is registered on prefill-3 ONLY (the purest token-only test; pre-registered fixed arm — no max-over-arm selection). All other arms are reported with the same reads but carry no verdict labels. The 0.5 share is a design-time majority-share criterion (Source: design choice, §11); the confirmatory content is the CI conjunction, not the band placement.

Row-coverage: both arms' registered rows are supplied per-pair by eval_results/issue_2333/f_metrics/f_cells.jsonl (steered arm) and eval_results/issue_2333/f_metrics/null_cells.jsonl (scheme-matched shuffled-donor arm); the ce-control rows by eval_results/issue_2162/f_metrics/f_cells.jsonl and eval_results/issue_2333/inputs/fu1_conf1_confirmation.json (vendored per-pair confirmation rows).

### 4.2 New intervention arms (the experimental variable)

Notation: prompt length T (context ends at position T−1 = ce). Answer position i = the i-th generated token's sequence position (T+i−1). All-layer = all 28 (Qwen2.5) / 32 (Qwen3.5) decoder-block outputs.

**Donor schemes (both user-specified):**

- **(a) Patch-content donors (mediation form):** run context A ONCE, greedy, with the banked ce all-layer replace armed (donor V(B) at ce — the existing `PositionEditHook`/`joint_hooks` prefill-position rig, reused unmodified), `max_new_tokens=8`; capture (i) the first 3 generated token ids and (ii) the residual-stream states at answer positions 1..3 at ALL layers (post-block outputs, captured AFTER the edit hook so prefill edits are reflected). These are "content produced under the ce patch"; the test arms then run with the ce patch REMOVED.
- **(b) B's-own-opening donors:** run context B ONCE, unpatched, greedy, `max_new_tokens=8`; capture the same (first-3 token ids + answer-position states at all layers). This is "the target context's own reference answer opening".

**Arm 2 — first-k answer-position state patch (k ∈ {1,2,3}, schemes a/b):** generate from context A, NO ce patch; during decode, at decode steps 1..k, replace the (B,1,H) decoder-block output at EVERY layer with the scheme's donor state for answer position i (mode=replace). Token identities stay model-sampled (temp 1.0): token 1 is sampled from the unpatched ce forward; tokens 2..k+1 are sampled under the patched positions; positions 1..k's KV/recurrent contributions are computed from the patched states, so the patch persists causally like the parents' prefill-position patches. Interpretive note (carried to the write-up): this arm controls the opening's STATES but not its first token identity, the complement of the prefill arm.

**Arm 3 — prefill first-k tokens (k ∈ {1,2,3}, schemes a/b):** extend context A's prompt TOKEN IDS with the scheme's first-k donor token ids (ID concatenation — never re-tokenized strings, per the BPE-seam rule), no hooks armed, free continuation at temp 1.0. Judged on the whole response (primary) + continuation-only companion (the prefilled tokens are the donor's, not the model's).

**Scheme-matched shuffled-donor nulls (every arm):** donors come from a DIFFERENT pair via the frozen derangements — S1: the bank.json value-constrained `donor_assignment` (donor-B-value ≠ recipient-B-value, seed 2162); S2: the parent's seeded derangement recovered from `f_metrics/null_cells.jsonl` donor_pair_id fields (fallback: fresh seeded derangement, seed 23330, restricted to matched-query pairs). State donors norm-matched per (layer, position) to the recipient pair's own scheme-donor state via `issue2094/bank.py::norm_match` (L501) applied position-wise; token donors (prefill nulls) are the shuffled pair's donor tokens, no norm matching (token space).

12 evaluated arms per pair (2 arm types × 3 k × 2 schemes) × {steered, null} × K=5 draws × 195 pairs = **23,400 rollouts per model**, plus 390 greedy donor-capture rollouts (195 per scheme, 8 tokens each).

Edge rule: a donor opening with fewer than k tokens before EOS pair-drops that pair from the k-arm (steered + null symmetric), counted and reported (expected ~0 at k≤3).
