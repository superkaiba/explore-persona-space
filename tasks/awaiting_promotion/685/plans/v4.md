## 0.0 TL;DR (plain English)

- **What I'll run:** I already measured how appending a behavior instruction (like "be sycophantic") nudges a context, and I compared that nudge against the "response-space behavior direction" — the direction the model's *answers* move in when it acts sycophantic. I'll redo the comparison keeping the sign, add a "what would random noise look like?" baseline, and re-read the answer direction at the *same* spot so it's a fair comparison. All of this is bookkeeping on numbers I already have — no new model runs.
- **What I expect:** Keeping the sign should show the nudge points consistently *toward* the answer direction (positive) across the 10 contexts, not a sign-flipping mess. Reading both at the same spot should raise the alignment well above the cross-spot 0.26–0.59 — most of the "modest" was a fair-comparison artifact, not a real low.
- **What would change my mind:** If even the same-spot, signed comparison stays low (or flips negative), then the appended-instruction nudge really is a different object from the answer-space behavior direction — and the "modest alignment" caveat in the writeup is the right read, not an artifact.

### 3.5 Pseudocode (the signed-cosine + null computation)

```python
import torch, numpy as np

LAYERS = [7, 14, 21, 27]; H = 3584; B_NULL = 200; SEED = 42
SUBSET = ["assistant", "software_engineer", "villain", "medical_doctor"]  # u_resp's subset
CONTEXTS = [...10 names...]; BEHAVIORS = [...6 names...]

def reconstruct_delta(cv, c, b, layer):
    idx = {n: i for i, n in enumerate(cv["condition_names"])}
    v_bare = cv["centroids"][layer][idx[f"bare__{c}"]].float()
    v_aug  = cv["centroids"][layer][idx[f"{c}__{b}"]].float()
    return v_aug - v_bare                                   # (H,)

def matched_position_u(cv, b, layer, subset=SUBSET):        # Part B u, 0 GPU
    return torch.stack([reconstruct_delta(cv, c, b, layer) for c in subset]).mean(0)

def signed_cos(a, b):                                       # signed, NOT |·|
    return torch.nn.functional.cosine_similarity(a.unsqueeze(0), b.unsqueeze(0)).item()

def null_band(delta, layer):                               # matched-NORM random null
    g = torch.Generator().manual_seed(SEED)
    R = torch.randn(B_NULL, H, generator=g)                # random *directions*; cosine is norm-invariant
    R = R / R.norm(dim=1, keepdim=True)
    d = delta / delta.norm()
    cs = (R @ d).numpy()                                    # B cosines of delta vs random unit dirs
    return dict(mean=float(cs.mean()), std=float(cs.std()),
                p25=float(np.percentile(cs,25)), p75=float(np.percentile(cs,75)),
                p95=float(np.percentile(cs,95)))

# Part A: signed cos(Delta, u_resp) + sign-consistency + null z
for b in BEHAVIORS:
  for layer in LAYERS:
    u_resp = kd["directions"][b][layer].float()            # response-mean u (4-ctx subset)
    per_ctx = {}
    for c in SUBSET:                                        # u_resp only defined on the 4-ctx subset
        d = reconstruct_delta(cvI, c, b, layer)
        nb = null_band(d, layer)
        sc = signed_cos(d, u_resp)
        per_ctx[c] = dict(signed_cos=sc, abs_cos=abs(sc),
                          null=nb, z=(sc - nb["mean"]) / (nb["std"] + 1e-9))
    signs = [v["signed_cos"] for v in per_ctx.values()]
    summary[b][layer] = dict(frac_positive=float(np.mean([s>0 for s in signs])),
                             mean=float(np.mean(signs)),
                             min=float(min(signs)), max=float(max(signs)))

# Part B: matched-position u, signed + |.| cos, back-comparison, two-u cosine
for model_tag, cv in [("instruct", cvI), ("base", cvB)]:
  for b in BEHAVIORS:
    for layer in LAYERS:
      u_match = matched_position_u(cv, b, layer)            # 0 GPU
      save_npy(u_match, f".../u_last_prompt_token/{model_tag}_u_l{layer}_{b}.npy")
      for c in SUBSET:                                      # same subset → apples-to-apples vs Part A
          d = reconstruct_delta(cv, c, b, layer)
          sc = signed_cos(d, u_match); nb = null_band(d, layer)
          rec = dict(signed_cos=sc, abs_cos=abs(sc), z=(sc-nb["mean"])/(nb["std"]+1e-9))
          if model_tag == "instruct":                      # response-mean u is instruct-only
              u_resp = kd["directions"][b][layer].float()
              rec["resp_mean_abs_cos"] = abs(signed_cos(d, u_resp))
              rec["abs_cos_lift"] = rec["abs_cos"] - rec["resp_mean_abs_cos"]
          out[model_tag][b][layer][c] = rec
      if model_tag == "instruct":
          out["instruct"][b][layer]["cos_umatch_uresp"] = signed_cos(
              u_match, kd["directions"][b][layer].float())  # the "two reads differ" check
```

Notes: cosine is norm-invariant, so the null uses random *unit directions* against `Δ/‖Δ‖`; "matched-norm" is satisfied because cosine already factors out ‖Δ‖ (the null answers "what cosine does a Δ of any norm get against a random direction in 3584-d?"). All reductions are CPU `torch`/`numpy` over (≤10 contexts × 6 behaviors × 4 layers × 200 null draws) — milliseconds; no iterative-optimization fit, so the off-VM compute-character carve-out does not apply.

## 11. Decision rationale

The geometry rationale (layer set, geometry question bank, per-condition n, centering, model pair, the response-mean û recipe) is **Unchanged from v3 §11 → v2 §11** — frozen. Amendment knobs:

- **Signed cosine instead of `|·|`.** *What:* drop the absolute value in the Δ-vs-û projection. *Why:* the body's `|Δ·û|/‖Δ‖` (0.26–0.59) hides whether the last-token shift points TOWARD or AWAY from the response-space behavior direction, and whether the sign is consistent across the 10 contexts — exactly the user-flagged confound. *Source:* `ungrounded — local empirical/analysis choice; restoring the sign of an existing absolute-cosine read needs no external grounding (it is strictly more information than the committed `|·|`, and the smoke-test asserts it reduces to the committed `|·|` under `abs()`)`. *Alternatives:* keep `|·|` (rejected — it is the confound under test).
- **Matched-norm random-direction null, B=200, seed 42, H=3584.** *What:* B=200 random unit vectors at H=3584, per-cell z = (signed cosine − null mean)/null std. *Why:* calibrates the 0.26–0.59 reads against chance for Δs of that norm — is "modest" actually above chance? *Source:* `#685 plan v3 §6.2 — the geometry consistency null uses the identical setting (random-vectors, seed 42, B≥200); reused verbatim so the projection null and the consistency null are the same discipline`. *Alternatives:* a permutation null over context labels (rejected — fewer than 24 permutations on a 4-context subset, too coarse; the random-direction null is the matched-norm chance baseline the brief specifies and v3 already validated).
- **Matched-position û via last-prompt-token diff-in-means.** *What:* û_match_ℓ(b) = mean over the 4 SUBSET_CONTEXTS of `(v_ℓ(C⊕b) − v_ℓ(C))`, read at the last-prompt-token slot (from committed `context_vectors.pt`). *Why:* the parent's û is a RESPONSE-mean read while Δ is a last-prompt-token read; the cross-position comparison conflates a real low-alignment finding with a read-position artifact. Reading û at the MATCHED position removes that confound. *Source:* `2507.21509 (Chen et al. 2025, Persona Vectors) §3 + 2312.06681 (Marks/Tegmark, diff-in-means) — the diff-in-means recipe; the matched-position read is the read-position VARIANT of the response-mean default. That the position matters is the literature claim being probed; persona vectors are extracted by diff-in-means at a chosen read position and the recipe is position-agnostic (the paper extracts at response positions but the construction is the same difference of means at any slot).` *Alternatives:* re-extract û with a fresh GPU forward pass at the last-prompt-token slot (rejected — UNNECESSARY: the last-prompt-token activations for all `bare__{c}` / `{c}__{b}` conditions are already committed in `context_vectors.pt`, so the matched-position û is the SUBSET-context diff-in-means of committed tensors, 0 GPU; HF inspection §3.2 confirms).
- **SUBSET_CONTEXTS = [assistant, software_engineer, villain, medical_doctor] for both û.** *What:* compute matched-position û on the SAME 4-context subset the response-mean û used. *Why:* an apples-to-apples back-comparison — if matched-position used all 10 contexts and response-mean used 4, the cross-position delta would conflate read-position with context-set. *Source:* `#685 issue685_known_directions.py SUBSET_CONTEXTS (verified by loading instruct_known_directions.pt metadata.subset_contexts)`. *Alternatives:* matched-position û over all 10 contexts (rejected — unmatched subset; kept as an over-produced secondary view only if useful, never the primary back-comparison).
- **Cross-position cosine reads as an underestimate of within-position alignment.** *What:* the hypothesis that reading the two directions at the same position raises the cosine. *Source:* `ungrounded — local empirical claim, validated by Part B's contrast itself` (a web/arXiv scan for an explicit "steering-vector read-position matters for cross-read cosine" claim turned up the general position-sensitivity of steering vectors but no quotable matched-position-cosine result; the claim is settled by Part B's own contrast, which is why it is run).
- **Run Part B on BOTH instruct and base.** *What:* compute matched-position û + signed cosine for the base model too. *Why:* both are free (committed `base_context_vectors.pt`); painting the symmetry lets the analyzer state whether matched-position alignment is instruct-tuning-specific or pre-exists in the base (mirrors body Result 5). *Source:* `#685 — base_context_vectors.pt committed (verified via list_repo_tree + load); body Result 5 instruct-vs-base comparison is the precedent`. *Alternatives:* instruct-only (rejected at 0 cost — no reason to hold the base out when it is free; the only asymmetry is that response-mean û is instruct-only, flagged in output).
