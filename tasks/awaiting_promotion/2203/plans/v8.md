## 0.0 TL;DR (plain English)

- **What I'll run:** The parent run found exactly one thing that cut jailbreak harm *without* wrecking the model — replacing the "assistant-axis" component of the hidden state with its default value, done across all prompt tokens (harm 0.097→0.060) or all tokens (0.064). I'll add two control arms that do the identical replace using a norm-matched random direction instead of the assistant axis, score them the exact same way (harm rate, identity, capability, gibberish check), and see whether the random direction matches the real one.
- **What I expect:** the random-direction replace either degrades the model (like the random *cap* control did — capability collapse / gibberish) or fails to cut harm — leaving the axis-replace effect looking axis-specific. But there's a real chance a random direction cuts harm just as much while staying coherent, which would say the effect is generic component-overwrite disruption, not the assistant axis.
- **What would change my mind:** if a norm-matched random replace matches the ~0.060-0.064 harm reduction at comparable capability and coherence, the "only coherent reduction in the study" is not about the assistant axis at all.

Why this is the whole change (mechanics verified this session, grep lines quoted verbatim in §12):
- `runtime.py::build_stack_for_arm` (line 111-130) threads `op` from `arm_spec` into `caphook.joint_axis_hooks(..., op=op, position_set=position_set)`, and its `kind in ("null_ctx","null_alltoken")` branch (line 120) builds the seeded norm-matched random direction `axis = {li: _seeded_random_axis(axis_by_layer[li], null_seed + li) …}` (line 122). This ALREADY works for `op="axis_replace"` — the random branch is op-agnostic; only the direction and (for cap) τ are swapped.
- The axis-replace op IGNORES τ: `caphook.apply_cap_op` uses τ only in the `op == "cap"` branch (lines 100-102); the `axis_replace` branch (lines 103-105) is `h_new = h + v̂·(proj_def − ⟨h,v̂⟩)`. So the `kind="null_alltoken"` tau-pool selection (`phase2:229/321`) is inert for these arms — it satisfies `build_stack_for_arm`'s `assert tau_rand_by_layer is not None` (line 121) with a value the op never reads. `kind="null_alltoken"` is chosen for both (rather than a new kind string) precisely so NO edit to `build_stack_for_arm` is needed — mirroring the parent's convention that the all-token null is the footprint-match for both all-prompt and all-token broad-position arms; the `position_set` field independently drives the hook's position behavior (all-prompt vs all-tokens), so the position is correct regardless of kind.
- The random direction `v_rand` per layer is `_seeded_random_axis(axis_by_layer[li], null_seed + li)` with the DEFAULT `null_seed=1234` (`runtime.py:102`), IDENTICAL to the parent's `cap_ctx_randnull` / `cap_alltoken_randnull` arms — no seed argument is passed by phase2, so the two new arms inherit the exact same seeded random direction the parent's cap nulls used. This is the required "same seeded `v_rand`" property, obtained for free.
- `h_def` (the default-assistant mean state) is the SAME for null and real arms (`runtime.py:127`), so the axis-replace target projection `proj_def` is computed against the random `v̂` — the correct norm-matched random-direction analogue of the real axis-replace.

Norm-matching is exact: `_seeded_random_axis` (`runtime.py:86-90`) returns `r / r.norm() * float(v.norm())` — the random direction is scaled to the per-layer norm of the real axis, identical to the parent's cap nulls.
