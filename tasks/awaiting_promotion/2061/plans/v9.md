## §6 Measurement validity

**Per-DV declaration** (planner.md §6):

- **Construct**: which SAE features of the ANSWER state at layer 29 become MORE linearly predictable from the pooled context activation (also at layer 29) after each adjacent post-training stage transition.
- **Metric**: per-feature held-out R²_j from a ridge regression `g: c_x → f(a_x)` fitted per (stage, corpus, arm) cell, K=5 group folds, fold seed 0, pooled R² with fold-local test means. ΔR²_j = R²_j(stage_after) − R²_j(stage_before). Headline statistic: `max_{j, cell} ΔR²_j` vs a GLOBAL selection-symmetric null (per-draw max over `(feature j, delta cell)` under one shared `draw_seed_schedule` across all 56 (stage-pair, corpus, arm) delta cells (v7 grid); per-cell p97.5 retained as a secondary diagnostic).
- **On-distribution**: **YES** — the map is fit on the ACTUAL post-training checkpoints' activations (Llama-3.1-8B Tülu-3 base / SFT / DPO / RLVR / longer-RLVR), on-policy contexts sampled from the 7 realized v2-generation (render, corpus) combos #1336 banked (real-user LMSYS chat in both renders; established GSM8K / MATH benchmarks; IF/UF/SFT rows — v7 registered grid, §7 provenance statement). No off-policy substitution, no teacher-forcing artifact (the SAE encode of the answer state is a forward pass on the same banked activations).
- **Saturation check**: per-stage FVE / L0 / dead-feature-count on the fixed dictionary (§ Cross-stage SAE-fitness confound control below) is the pre-registered saturation / instrument-fitness gate. A stage whose FVE falls below 80% of the base-stage FVE is reported per-transition with an explicit scope caveat, not aggregated.
- **Dual-DV**: N/A — the DV is R²_j (continuous by construction — a scalar from a well-posed ridge regression per feature per fold). The selection-symmetric null is the multiple-comparisons discipline, not a companion DV.

## §7 Success + kill criteria

**Success criteria (quantitative thresholds)**:
- **Primary decision rule (GLOBAL max, cell-level selection-symmetric)**: **At least one (feature j, delta cell) pair exists** with true ΔR²_j exceeding the p97.5 quantile of the null distribution of `max_{j, cell} ΔR²_j` — the GLOBAL max over both the feature axis (d_sae=262144) AND the delta-cell axis (56 cells; v7 grid) taken per draw under one SYNCHRONIZED draw-index schedule. This closes the cell-level selection-asymmetry loophole a per-cell p97.5 would leave open (at the registered ONE-SIDED p97.5, a per-cell false-positive rate of ~2.5% yields ~1.4 spurious cells expected at random over 56 cells; the global max rides both axes per draw). Report the winning (feature id, stage-pair, corpus, arm) tuple, its ΔR²_j, the GLOBAL null p97.5, and the fraction of (j, cell) pairs clearing the global bar.
- **Secondary per-cell reads** (retained diagnostics, non-headline): (i) per-cell p97.5 of null `max_j ΔR²_j` — the local-only quantile the global test dominates; (ii) cross-corpus rank-agreement of the top-100 improved features per transition (are the same features improving across corpora, or is each corpus surfacing corpus-specific features?). Higher rank-agreement supports a stage-general improvement mechanism; lower agreement supports corpus-specific fits.
- **Diagnostic pass bar (dead leg re-registered v7 — resolves `dead-feature-bar-unsatisfiable-at-1k-pool`)**: per-stage FVE ≥ 0.8 × base_FVE on all 5 stages; L0 ∈ [10, 200] for the fixed dictionary applied at each stage; per-stage activated-feature count A_s (distinct features with ≥ 1 activation on the fixed validation slice) ≥ 0.8 × A_base. ## Hypothesis

**If** the Llama-3.1-8B Tülu-3 post-training stages (SFT / DPO / RLVR / longer-RLVR) preferentially strengthen the LINEAR predictability of specific interpretable SAE features (of the answer state) from the pooled context activation, **then** at least one (feature j, delta cell) pair exists whose true ΔR²_j exceeds the p97.5 quantile of the GLOBAL selection-symmetric null (per-draw max over `(feature j, delta cell)` across all 56 (stage-pair, corpus, arm) delta cells (v7 grid), under one shared `draw_seed_schedule`).

**Falsification**: the maximum ΔR²_j over the true assignment (max over both j AND delta cell) lies within the GLOBAL selection-symmetric null band. (Bright-line quantitative test: `max_{j, cell} ΔR²_j` vs the GLOBAL null p97.5 computed over `{global_max_d = max_cell max_j_d : d = 0..499}` — 500 draws per the amended §Design default.)

### Per-cell fit

For each (stage s, corpus c, arm a) cell:
- **Input** X = the context-side activation at layer 29 (shape `(n_c, d_in=4096)`), reused from #1336's `issue1336_rlvr_ladder/` banked turnstores. **Realized convention (amended v5 — the v4 "mean-pool over prefix tokens / prefix+query" prose was factually wrong; neither mean is banked):** #1336's producer (`scripts/issue1336_extract_turnstore.py:333-348`) writes `slots` as SINGLE-TOKEN header states (`slot_vecs = acts[:, i, slot_pos, :]`) and `profiles` as span-MEANS over TURN CONTENT (`acts[:, i, s:e, :].float().mean(dim=1)`); the u1 profile is query-content-only, so no prefix-token mean exists anywhere in the payload. Inherited from `scripts/issue1336_fit_cells.py::_cell_xy_1336` (L242-255: "context arm: a1-header slot -> a1 profile"; slots ordered prefix=0, a1=1): the `prefix` arm input = the **prefix-header single-token slot state** (slot index 0); the `context` arm input = the **a1-header single-token slot state** (slot index 1 — the assistant-header position, conditioned on the full prefix+query). Landed in unit A's shared loader (`scripts/issue2061_turnstore.py`, commit `aaf9c75d5c`, test-pinned in `tests/test_issue2061_loaders.py`).
- **Target** Y = SAE feature vector of the **answer** state — the **a1 profile: span-mean over the answer turn's content tokens** at layer 29 (the realized #1336 convention above; `target_turn_index 1` in `_cell_xy_1336`) — encoded by the fixed EleutherAI/sae-llama-3.1-8b-64x at `layers.29/`. Shape `(n_c, d_sae=262144)`. TopK activation with k=32, so Y is sparse per row but the target matrix is not sparse across rows.
- **Fit** g: X → Y as a ridge regression in the INPUT space (n × 4096; well-posed at n_train ≫ d_in). Per-feature R²_j is derived column-by-column from the fitted map's held-out predictions — d_sae does NOT gate ridge well-posedness, since each output column is one scalar regression on the same 4096-dim input.
- **Folds** K=5 group-level folds with fold seed 0, inherited from #1336. LOFO / LOCO groupings match #1336's own convention.
- **Estimator**: the shared factorization `ridge_fit_predict_fast_layer_batched` (`src/explore_persona_space/experiments/issue_779/fit_h.py:180`) — one Gram/dual-space eigendecomposition per (stage, corpus, arm) cell, applied to every column of the SAE target simultaneously. GCV over `np.logspace(-2, 4, 13)` for λ (the #779/#823 convention), with the opt-in `gcv_dof_cap=0.9` engaged per the §7 under-determined-cell mitigation (realized mechanism there; landed `d2b36fc0ce`). Numeric-parity gate against the SVD reference on 3 slices per cell family at production shape (per its docstring; landed as `run_parity_gate` in `scripts/issue2061_fit_per_feature.py`, cap=None on both sides). **Realized dispatch path (registered v7 — round-2 review adjudication 1, ACCEPTED):** P2 dispatches the streamed primal fit `scripts/issue2061_fit_per_feature.py::_fold_fit_streamed` — numerically the SAME estimator (identical standardize-X, center-Y, full-column GCV over the same grid, identical RSS identity, same dof-cap mask, un-centered predictions), adopted for feasibility: the dual-form `VtY` at lmsys23k shape is ≈ 38.6 GB/fold fp64 and ≈ 1.8e17 FLOPs/fold vs primal ≈ 4.0e13. Parity-pinned by `test_streamed_fit_matches_layer_batched_helper` (both cap settings × all 5 folds, λ exact rel 1e-12, dof rel 1e-9, preds rtol 1e-7 vs the REAL helper) plus the runtime `run_parity_gate` vs the canonical SVD reference (smoke 2.5e-12).
- **Per-feature R²_j**: `1 - ||f_j − ĝ_j||² / ||f_j − mean(f_j)||²` on the held-out folds (K-fold aggregated). Stored per cell: `(d_sae,)` per (stage, corpus, arm) cell ≈ 1 MB f32 × 70 cells ≈ ~70 MB total (v7 grid; the v6 "20800 × d_sae = ~5.4B floats" arithmetic was stale).

### Cross-stage delta

For each adjacent stage pair (base→SFT, SFT→DPO, DPO→RLVR, RLVR→longer-RLVR) × 7 combos × 2 arms = **56 (stage-pair, corpus, arm) delta cells** (v7 grid):

### Selection-symmetric null (SYNCHRONIZED across cells for a per-draw GLOBAL max)

The null follows `.claude/rules/selection-symmetric-nulls.md` § "max/argmax/top-k over a free axis" with the axis expanded to (feature j, delta cell):
- **Draws: 500 permutation draws (amended v5 default — the plan's OWN pre-registered fallback, INVOKED).** v4 registered "1000 draws … reduce to 500 if per-cell wall dominates"; the trigger has FIRED on measured evidence (`epm:compute-deviation v1`: the registered refit statistic measures 480-600 wall-h on the registered `cpu-bigmem` lane vs the sized 20 — 24-30×; even on the amended 8× GPU lane P3 at 1000 draws is 62-128 GPU-h under the v7 composition-weighted basis (§ Resources), ~10× the rest of the pipeline combined). **Statistical cost, stated:** at n=500 the GLOBAL p97.5 threshold is the ~487.5th order statistic with ≈12.5 expected tail draws; the Monte-Carlo SE on the tail mass is ±0.70 pp (vs ±0.49 pp at n=1000), i.e. the headline test's realized type-I error sits in ~[1.8%, 3.2%] at 1σ instead of ~[2.0%, 3.0%]. The §11 grounding already notes the p97.5 stabilizes by ~300 draws; 500 keeps 1.7× margin over that. p99 becomes DESCRIPTIVE-ONLY (≈5 tail draws — it was never a verdict quantile; now explicitly flagged as unstable). REQUIRED companion: a bootstrap CI on the global p97.5 computed from the persisted per-draw arrays (see the persistence contract below), reported alongside the verdict. The 1000-draw battery remains available as an explicit USER choice at plan approval — its envelope (61-125 GPU-h total) crosses the 100 GPU-h auto-approve cap at the upper band (see § Resources).
- **Draw-index synchronization (load-bearing for the GLOBAL max)**: ONE shared permutation seed schedule (`draw_seed_schedule = [42 + d for d in range(500)]` — the landed `draw_seed_schedule(n_draws)` with `DRAW_SEED_BASE = 42`) applied across ALL 56 (stage-pair, corpus, arm) delta cells (v7 grid); draw index `d` uses the SAME seed on every cell. The 500-draw schedule is a PREFIX of the 1000-draw schedule (seeds 42..541), so a later extension to 1000 draws EXTENDS the persisted arrays rather than replacing them. Same 28,000 cell-draws costed in §9 P3, different reduction.
- **Draw recipe (per cell, per draw d) — the REGISTERED refit statistic, implemented by the landed engine** (`scripts/issue2061_null.py::_CellEngine`, commit `d095ea09cf`; the v4 "batched masked GEMM" phrasing and the `analysis/null_battery.py::perm_null_draws` helper naming are RETIRED — that helper is a diff-of-means permutation null and cannot express this statistic): for each draw, shuffle the STAGE label within-corpus (pair-flips of which rows come from stage_after vs stage_before) under `seed=draw_seed_schedule[d]`, ridge-REFIT both pseudo-stages per fold, and record `max_j_d = max_j ΔR²_j` for that (cell, draw) pair. Batched per `.claude/rules/vectorize-many-cell-fits.md` — per (fold, pseudo-stage, draw-block of `DRAW_BLOCK=8`): ONE `(B, n_tr, d)` gather, ONE batched `bmm` normal matrix, ONE batched `torch.linalg.eigh`, a batched GCV scan (criterion on a fixed seeded `GCV_FEATURE_SUBSAMPLE=1024`-column subsample — test-pinned to match the full criterion at subsample ≥ d_sae; per-feature R² always on ALL features; the subsampled criterion is a NULL-side λ-selection approximation relative to the FULL-criterion selection P2 uses — test-pinned, identity-guarded via `engine_identity_max_delta`, and read by analyzer duty 1 (§6) before verdicting) and batched smoother formation; the d_sae=262,144 target rides a fixed-width TopK sparse layout with feature-chunked `index_add_` applies, never an `(n, d_sae)` dense GEMM. fp64 throughout; `gcv_dof_cap=0.9` matching P2 (the null recomputes the SAME capped statistic as the true fit); device-parametrized (`--device cuda` in production); per-cell atomic checkpoints keyed on `ENGINE_VERSION = "refit-v1"`; identity-assignment consistency guard (`engine_identity_max_delta` — the no-flip delta recomputed through the SAME refit path, WARNed against the P2-derived value, never silently absorbed). Folds are computed on the pooled conversation ids and coincide exactly with P2's per-stage folds on the #1336 banked corpora (same unique-id set, seed 0 — documented + test-pinned in the engine).
- **Per-draw GLOBAL max reduction (PRIMARY null quantile)**: after all 56 cells complete each draw d, form `global_max_d = max_{cell} max_j_d` — the null distribution of the joint (feature × cell) selection statistic. Report the p50 / p95 / p97.5 quantiles of this GLOBAL null distribution (p99 descriptive-only at 500 draws). The headline test is `max_{j, cell} ΔR²_j` on the true assignment vs the GLOBAL null p97.5. This closes the cell-level selection asymmetry a per-cell p97.5 would leave open (at the registered ONE-SIDED p97.5, a ~2.5%-per-cell false-positive rate compounds to ~1.4 spurious cells expected at random over 56; the global max rides both axes per draw).
- **Per-cell p97.5 (SECONDARY, retained as a per-cell diagnostic)**: computed from `{max_j_d : d = 0..499}` per cell — the same 28,000 cell-draws, different reduction. Used for per-cell diagnostic reads only, never a headline verdict.
- **Persistence contract (`issue2061_null.py` output schema)**: alongside the p50/p95/p97.5/p99 quantiles, PERSIST the per-draw `max_j_d` values (500 scalars per cell × 56 cells = 28,000 scalars total, KB-scale) so the GLOBAL max reduction is recoverable AND any analyzer re-reduction (the REQUIRED bootstrap CI on the global p97.5, alternative axis unions, etc.) can be applied post-hoc without recomputing the null battery. Any true (j, cell) pair exceeding the global p97.5 is a candidate improvement; the headline is whether ANY (feature, cell) pair clears the global bar.

### Cross-stage SAE-fitness confound control

Per-stage FVE / L0 / activated-feature count (plus the DESCRIPTIVE absolute dead-feature fraction) on the FIXED dictionary applied to EACH stage's banked activations (LMSYS validation slice, ~1k rows from the v2 `lmsys23k` store; the same slice for every stage). Follows the #1482 SAE token-pool recipe (`.claude/rules/gotchas.md` #1482 entry): BOS-offset strip (first 8 positions), outlier-norm filter (L2 > 10× pool median), var-based FVE (`1 − var(x − x̂) / var(x)` summed per-dim unbiased variance).

Pre-registered pass/fail bar (per `.claude/rules/gotchas.md` #1482 published-reference figure for the andyrdt Qwen2.5-7B suite of ~0.806 FVE at k=64; for the EleutherAI Llama base SAE at k=32 the published FVE benchmark is not reported on the model card — verify at implementation time; if unavailable, use the BASE stage's own measured FVE as the reference and require **≥ 80% of the base-stage FVE** at every post-training stage):

- **Base FVE reference**: measured on `meta-llama/Meta-Llama-3.1-8B` layer 29 (~1k LMSYS validation rows, same BOS-strip + outlier filter).
- **Pass**: every post-training stage's FVE on its own banked activations ≥ 0.8 × base_FVE; L0 stays in [10, 200] on the fixed dictionary; per-stage activated-feature count A_s ≥ 0.8 × A_base (the dead-feature leg re-registered RELATIVE — v7; see the re-registration paragraph below).
- **Fail**: any stage's FVE < 0.8 × base_FVE → the fixed-dictionary assumption is broken for that stage; the clean-result carries the fitness drift as a scope caveat and the headline is reported per-stage-pair, not aggregated.

**Dead-feature leg re-registration (v7 — resolves the open `dead-feature-bar-unsatisfiable-at-1k-pool` CONCERN, round-2 `epm:code-review` v2).** The v6 absolute bar (dead fraction < 10% of d_sae) is unsatisfiable by pool-ceiling arithmetic: N_VAL_ROWS = 1,000 × k = 32 bounds the activatable features at 32,000 (fewer in practice — rows share features) of d_sae = 262,144, so dead ≥ 1 − 32,000/262,144 = 87.8% on EVERY stage, base included; `dead_ok` is always False and every stage lands FAIL_SOFT on an arithmetic artifact, independent of dictionary health (the #1345 gate-calibration class; `scripts/issue2061_fitness.py:76` / `:230` faithfully implement the defective bar). The absolute bar was also the wrong CONSTRUCT for this gate: it tests dictionary-vs-corpus health (pool-size-dependent), while the gate's job is CROSS-STAGE drift — which the FVE leg already encodes relative to base. **Re-registered relative, matching the FVE leg's structure: A_s = count of distinct features with ≥ 1 activation on the fixed ~1k-row slice (the SAME slice for every stage, so the pool ceiling cancels); gate leg: A_s ≥ 0.8 × A_base.** Satisfiable by construction (base is its own reference; bar = 0.8 × A_base ≤ 0.8 × 32,000 = 25,600); a stage whose active-feature diversity collapses ≥ 20% vs base fails — exactly the drift construct. The absolute dead fraction vs d_sae is RETAINED as a DESCRIPTIVE field in the per-stage JSON (with the 87.8%-floor arithmetic stated beside it), never a gate. The FVE 0.8× graded bar, the FVE 0.5× HALT floor (`FVE_HARD_FLOOR = 0.50`, `scripts/issue2061_fitness.py:83`), and the L0 ∈ [10, 200] leg (≈ 32 by construction under TopK k=32 — a loader-sanity read, kept) are UNCHANGED.
