# Plan — task #1773: SAE feature description + categorization pipeline (evidence builder, five judged axes, validation harness)

## 0.0 TL;DR (plain English — the user reads this first)

- **What I'll run:** First, a free CPU pass that computes mechanical statistics (what tokens each feature promotes, how often it fires, how consistently, which persona directions it aligns with, its nearest neighbours) for all 16,384 layer-19 restricted SAE features and commits a joinable table the running map rounds can use today. Then I build the one real piece of new code — an evidence builder that, in one GPU pass over the ~142k-answer chat corpus (n_fit 120,000 + val 2,000 + holdout 20,000 — fact-checked against eval_results/issue_1482/sae_perfeature/summary.json), collects 60 real text windows where each feature fires (marked at the peak token), 26 where it doesn't, and 5 near-miss windows from lookalike features. Those packets feed Claude Sonnet 4.5 over the Batch API: one free-text description per feature, then five category labels (abstraction, speaker-property, content-type, functional-role, interpretable), each judged 5 times with shuffled answer orders and majority-voted. Finally a validation battery on ~1,000 features — can a fresh judge pick out which texts activate a feature given only its description (detection), spot fake highlights (fuzzing), and tell a feature from its nearest neighbours (discrimination) — plus shuffled-label and random-direction controls.
- **What I expect:** The mechanical table lands within a day and is trustworthy by construction. The descriptions will be a good search index. The open question is the five judged axes: literature says explainer quality saturates around 0.75 detection accuracy against a 0.51 random floor, so I expect detection/fuzzing in the 0.65–0.75 band, decent agreement on language/content-type, and the hard test to be identity-disposition, where the base rate is a few percent and precision is what matters.
- **What would change my mind:** If a 500-feature pilot shows the judges can't even agree with themselves (inter-draw kappa < 0.2 on every axis), the rubrics are broken and I stop before spending the remaining ~$1.5k. If detection on real labels is indistinguishable from the shuffled-label control, the judged axes are decoration — they stay a search index and no headline ever cites them; that outcome is itself the deliverable (acceptance criterion 5).

Falsified if >1% of features under-fill; that is a REPORTED data finding (never silently backfilled), and under-filled features carry an `evidence_short: true` flag into every downstream table.

**H3 (judged axes are trustworthy — the headline question):** on the ~1,000-feature validation sample, per axis: detection and fuzzing balanced accuracy land in [0.65, 0.78] (literature ceiling ~0.75–0.76, random-explanation floor 0.51 — 2410.13928), neighbour discrimination beats 0.25 chance by ≥ 2×, inter-draw kappa ≥ 0.6, shuffled-label control collapses to ≤ 0.55 detection, and identity-disposition precision at its 1–8% base rate ≥ 0.5 against the annotated reference. **Confirmed** → the axis may carry headlines (with the search-index caveat for descriptions — labels are never causal evidence, 2309.10312). **Falsified** → the axis remains a search index only; that verdict is itself acceptance criterion 5.

**Registered verdict lattice (per axis, applied independently to each of the 5 axes):**

DISJOINT and exhaustive: TRUSTWORTHY ⇔ detection >= 70% AND fuzzing >= 70% AND discrimination >= 50% AND inter-draw kappa >= 0.6 AND shuffled-label detection <= 55%; SEARCH-INDEX-ONLY ⇔ otherwise.

(Detection / fuzzing / discrimination stated as balanced-accuracy percentages — 70% ≡ 0.70 on the unit scale used elsewhere in this plan.)

(Threshold grounding: 0.70 sits between the 0.51 random floor and the 0.75–0.76 saturation ceiling, ~79% of the span to ceiling 0.75 (76% at ceiling 0.76) — 2410.13928; discrimination 0.50 = 2× the 0.25 four-way chance — 2605.12874/EleutherAI collision result; kappa 0.6 = Landis–Koch "substantial", beneath the 0.74 shown achievable with fixed a-priori categories — 2605.23035; shuffled-label 0.55 = floor + 0.04 noise allowance — 2506.05774.) `identity-disposition` additionally requires precision ≥ 0.5 on the human-annotated subset before any headline cites it (interim automated proxy reads are labeled as proxies, never the gate). The random-init control is REPORTED, not gated (the 2410.13928-vs-2501.17727 contradiction means either outcome is informative). Detection/fuzzing/discrimination scores are computed on HELD-OUT windows never shown to the describer or categorizer (§4 Phase 1).

**Lattice conjunct granularity (stated per Statistics-critic):** detection/fuzzing/discrimination score the per-feature DESCRIPTION and are shared across all 5 axis rows (applied globally, not label-sliced — rare-label slices would be noise); inter-draw kappa is the axis-DIFFERENTIATING conjunct. A TRUSTWORTHY lattice read therefore certifies grounded-description + self-consistent labels; per-axis label VALIDITY is corroborated by the non-judge mechanical validators + the human-agreement read (§4 Phase 4 items 6-7), which the analyzer weighs alongside the lattice before any freeze-lift narration (a lattice pass contradicted by its own mechanical validator is consistency-without-corroboration, not trust). Reporting: per-axis label prevalence + raw agreement are reported NEXT TO kappa (Fleiss kappa attenuates under skewed marginals — a prevalence-artifact miss is narrated as such, not as rubric failure); features with dropped draws use the varying-n Fleiss extension or are subset to 5-survivor features (choice recorded); scorecard bars carry feature-level bootstrap CIs, and near-threshold lattice reads (within ~2 SE of a bar) are narrated with the SE rather than as hard verdict flips.

### Phase 1 — evidence builder (THE build item; supersedes `phase_scan`'s 300-feature sampler)

`scripts/issue1773_evidence_builder.py`, three passes:

**Pass A — selection (VM CPU).** Stream all 1,920 pooled shards once; for each restricted feature collect its full `(row_idx, ans_max)` candidate list (vectorized: per shard, mask `ans_idx` to restricted features via a positions array over the FULL dict — the `samp_pos` pattern at L161-162 but filled for all 16,384 restricted features rather than 300 sampled ones; accumulate per-shard column stacks, concatenate once). Then per feature, seeded (`SEED = 17_732_026`):
- **Activating: 60 rows** = 10 quantile bins over the feature's own `ans_max` distribution × 6 rows/bin (dedup by row; bins with <6 candidates borrow from the adjacent bin, recorded). Split 40 evidence (bins × 4) / 20 held-out scoring (bins × 2) — held-out rows are NEVER shown to the describer or categorizer.
- **Non-activating: 26 rows** = seeded draw from fit rows absent from the feature's candidate list. Split 20 evidence / 6 held-out scoring.
- **Near-miss: 5 windows** from the top-3 `neighbors` features' own top-quantile activating windows (resolved in Pass C after windows exist).
Output: selection manifest as plain JSONL shards (<9 MB each, no gzip per upload policy) + an inverted index `row → [(feat, slot)]` npz. Also emits the union row set (bounded by the ~142k-row SAE-arm corpus; dense features push it toward full coverage — Pass B streams all 1,920 chunks regardless, so union size affects only per-chunk gather volume).
- **Random-direction control features: 200** seeded Gaussian unit vectors in activation space; their "activations" are raw dot products with the same BOS/inlier masking; candidate selection for them happens inside Pass B (per-direction top-quantile windows over streamed rows) since they have no pooled-store entries.

**Pass B — window extraction (GPU; the only GPU phase).** Shard the raw-chunk list across workers (`names[worker::n_workers]`, the parent P2 pattern). Per worker, per chunk: download chunk text (`_iter_needed_rows`), `_tokenize_row`, `_batched_capture(model, tok, batch, (19,), device)` teacher-forced forward (batched; `logits_to_keep=1` inherited from the parent capture path), `BatchTopKSAE.encode(h, chunk=2048)` on GPU → per-token sparse activations for answer positions (BOS_OFFSET + `token_inlier_mask` parity with the reference token-pool semantics for pooled reads; peak selection runs over answer tokens only, which start after `context_end` ≥ BOS_OFFSET by construction). For each (row, selected feature) pair from the inverted index: peak = argmax over answer-token activations; window = tokens `[peak−15 … peak+16]` (clipped), decoded text with `<<token>>` marking the peak, plus the window's per-token activation values (fp16 list) and metadata (row_idx, ci, quantile bin, peak position). Non-activating windows: seeded random 32-token answer span, activations verified ≈ 0 (assert: feature below threshold on all window tokens; violations logged + the row resampled once, then reported). Random-direction features: maintain per-direction bounded top-K (K=66) over (row, dot-max) with periodic compaction (the `_compact` pattern, L174), windows extracted in a second cheap sub-pass over just their ~13k selected rows OR inline via reservoir — implementer's choice, recorded.
- **Vectorization statement:** the inner loop is batched at three levels — batched model forwards (`gen_batch` rows/forward), one chunked GEMM per row for SAE encode (never per-feature loops), and numpy index operations for window gathers. No per-feature Python loop touches the token stream; the only per-feature work is O(selected windows/row) dict appends.
- **Checkpointing (code-style intra-phase grain — 1,920 units > 50):** one output JSONL + done-sentinel per chunk, atomic write; resume predicate keyed on (chunk name, config fingerprint: SAE revision, k, window params, seed); per-unit progress line `[evidence] chunk k/1920 <name> rows=<n> elapsed=<s>s`.
- Per-chunk artifacts upload to HF `issue1773_featurepipeline/raw_windows/` incrementally (per-cell upload rule #664; text/JSON, non-LFS path).

**Pass C — assembly (VM CPU).** Join per-chunk window files into per-feature evidence packets: `[EX+ 40] [EX− 20] [NEAR 5] [OUT top-10 promoted/suppressed] [STAT density, persist_answer, tier]` + held-out scoring sets (20 act + 6 non-act). Output: `evidence_manifests/*.jsonl` sharded <9 MB (≈ 400 features/shard, ~45 shards), uploaded to HF `issue1773_featurepipeline/evidence/` + a per-feature completeness report (fill counts; H2 gate).

**Two blinding rules (load-bearing, from plan doc §3b):** (1) every categorizer is blind to the DV (per-feature R², arm shares, any map output — none of these appear in any prompt); (2) each axis is blind to its own mechanical validator (abstraction never sees STAT/OUT; `functional_role` REQUIRES OUT as evidence, so its validator is the independent `side_ratio` quantity, never the footprint it saw). Neuronpedia descriptions withheld from all prompts.

Call mechanics (llm-judging.md compliance, stated explicitly): ONE axis per call; forced single choice from the axis's label set; label order permuted per draw (permutation = deterministic function of (feat_id, axis, draw_idx) — this also differentiates the 5 draws' cache keys, so the rubric-keyed `JudgeCache` never collapses draws); reason-then-label JSON output; `max_tokens=400` (rule 23, ≥300 for reasoning rubrics); temperature 1.0; drop-never-coerce (malformed/REFUSAL/out-of-set label → dropped draw, per-axis content-drop counter); transport errors retried via `api_dispatch` + the #1019 resumable re-dispatch, never persisted as drops (rule 24; per-arm report splits content-drops vs transport-losses). Aggregation: majority vote over surviving draws with ≥3 agreeing; else label = `unresolved` (reported, never coerced). Per-axis inter-draw agreement (Fleiss kappa across the 5 permuted draws) is the intrinsic-consistency read; reported per axis, never pooled into a composite (the retracted-OR-8.3 lesson).

## 11. Decision Rationale

- **40 evidence windows / feature.** Why: quality saturates at ~40 (10→0.73, 40→0.76, 60→0.75). Source: arXiv 2410.13928. Alternatives: 10 (−0.03), 60 (flat, +50% cost).
- **32-token windows, delimiter-marked peak.** Why: 16–32 optimal, 64 slightly worse; Delphi format. Source: arXiv 2410.13928; EleutherAI Delphi. Alternatives: 64 tok (worse + costlier).
- **Quantile stratification, 10 bins.** Why: top-k-only loses ~15% of above-chance signal; lower-activation inputs qualitatively different. Source: arXiv 2410.13928, 2405.06855. Alternatives: top-40 (rejected by source).
- **20 non-act evidence + 6 held-out; 20 held-out activating.** Why: Delphi's activating:non-activating ratio; held-out scoring prevents describe→score leakage. Source: EleutherAI Delphi defaults; the held-out split is standard ML hygiene (flagged Low-risk design choice).
- **5 near-miss neighbour windows at generation time.** Why: the collision literature demands neighbour discrimination; near-miss evidence at generation time is UNTESTED in the literature (the sweep flagged the gap twice) — carried as the plan-doc's cheap A/B. Source: arXiv 2605.12874 + plan doc §6. Alternatives: none-at-generation (loses the discrimination-forcing evidence for speaker_property).
- **Describe: 1 draw, not length-capped, no CoT, no per-token values.** Why: CoT 0.00 to −0.03; values +0.01; one-word labels are a conciseness-prompt artifact. Source: arXiv 2410.13928; plan doc §2 Phase 2. Alternatives: 3 describe draws (no evidence of gain; 3× cost).
- **5 axes, one axis per call, forced single choice, small flat label sets, sharp definitions.** Sources: arXiv 2505.17510 (multi-label suppression), 2602.02219 (criterion-order bias), 2406.04797 (label-set size), 2506.13639 (sharp definitions). Alternatives: one mega-call (rejected by all four sources).
- **N=5 draws, label order permuted, majority vote, temp 1.0.** Why: llm-judging rule 4; the `persona_related` κ 0.136 at N=1 is the in-house failure this fixes; permutation controls position bias and differentiates cache keys. Source: `.claude/rules/llm-judging.md` rule 4; #1482 taxonomy lineage. Alternatives: N=3 (weaker ties), N=10 (2× cost, diminishing).
- **Judge model `claude-sonnet-4-5-20250929`, Batch API.** Source: project pin (CLAUDE.md), task body pre-approval. No alternative permitted.
- **`max_tokens=400` axes / 700 describe.** Why: reason-then-label rubrics need ≥~300 (rule 23; #1090 truncation-censoring incident). Source: `.claude/rules/llm-judging.md` rule 23. Alternatives: 64 default (silent censoring — banned).
