# Plan — Task #931: Story-character generalization of the context→answer map (no chat template) + separator-token specificity control

Parent: #825. Line: #779 → #825 → #810/#920 (recipes), #922/#923 (in-flight siblings). Kind: experiment, workflow: v1.

## 0.0 TL;DR (plain English)

- **What I'll run:** We already know this model carries a strong linear rule that predicts, from how a conversation starts, the "flavor" of the answer it will write. I'll test whether the same rule shows up for characters in fiction: feed real novels into the model as plain text, take the passage where a character is introduced, and try to predict the internal state the model settles into when that character speaks. I'll do the same on stories the model writes itself, and, as a sanity check, on plain Wikipedia text anchored on punctuation marks, where no characters exist at all.
- **What I expect:** The character version of the rule exists in real novels at maybe half the strength of the chat version, and the chat rule carries over to novels well enough that it looks like one shared mechanism rather than two separate ones. The punctuation control should show some generic predictability, but it should not explain the character rule.
- **What would change my mind:** If swapping which character's dialogue we predict inside the same story barely hurts accuracy, the "character rule" is really just a topic rule. And if the punctuation-anchored control transfers onto character pairs almost perfectly, the whole thing is generic text smoothness, not anything about personas.

## 1. Goal

Test whether the linear context→answer-profile map (#779/#825: held-out ridge from a **single-position context read** — `c_last`, the residual activation at the assistant-header slot token — to the mean answer activation `v(x)`; #779's committed R² = 0.677 at layer 19 on instruct, 0.673 in #825's Track-S refit) generalizes to a **character→behavior map in stories**: (a) real dialogue-rich novels fed to Qwen2.5-7B-Instruct as raw text with NO chat template, predicting the mean activation over a character's attributed dialogue span from that character's introduction-span context vector (span mean as the headline character-specific X, plus a parent-matched single-position boundary-token X variant); (b) assistant-written multi-character stories under the chat template; and quantify whether it is the SAME map (cross-regime transfer R² vs within-regime refit ceiling, with the input recipe matched to the parent's single-position X on chat-side transfers; matched-layer weight/subspace similarity; layer-profile rank correlation). Specificity control: the identical machinery anchored on persona-irrelevant separator/punctuation tokens on non-persona text, to test whether span-mean predictability is character-specific or a generic delimiter-span property. Open questions served: identity-cb-duality (4.3), identity-persona-vs-behavior (4.1).

**Literature (closest prior formalizations, verified this session):**
- *Persona Vectors* (Chen et al., Anthropic 2025, arXiv 2507.21509) and *Persona Features Control Emergent Misalignment* (Wang et al., OpenAI 2025, arXiv 2506.19823) — the sibling papers: persona/trait state as residual-stream directions. This task asks whether the persona→behavior mapping is a general character mechanism rather than an assistant/chat artifact — a question neither paper tests on raw fiction.
- *Language Models as Agent Models* (Andreas, Findings EMNLP 2022, arXiv 2212.01681) and *Role play with large language models* (Shanahan, McDonell, Reynolds, Nature 2023) — the conceptual formalization: an LM infers and represents properties of the agents that produce text; the assistant is one simulacrum among many. - *Language Models Represent Beliefs of Self and Others* (Zhu et al., ICML 2024, arXiv 2402.18496) and *Language Models Use Lookbacks to Track Beliefs* (arXiv 2505.14685) — linear decodability of per-character internal states (beliefs) from activations in short narratives; the closest probing precedent for per-character state, but on synthetic ToM vignettes with binary targets, not full-vector behavior profiles on real fiction.
- *Future Lens* (Pal et al., CoNLL 2023, arXiv 2311.04897), *Tuned Lens* (Belrose et al. 2023, arXiv 2303.08112), *Activation Transport Operators* (arXiv 2508.17540), *Transformers Represent Belief State Geometry in their Residual Stream* (Shai et al., NeurIPS 2024) — linear activation→activation predictability is generically strong in transformers. This is exactly why H3's separator control and the within-story swap are load-bearing: existence of SOME linear map is expected; the claims must survive character-specificity and genericity controls.
- *The Project Dialogism Novel Corpus* (Vishnubhotla et al., LREC 2022, arXiv 2204.05836) — 35,978 human-annotated quotations across 22 novels (v2 repo adds 6 more), each with speaker, byte spans, quote type, plus per-novel character lists with aliases. Solves the dialogue-attribution problem with gold labels for Arm A. - *The Assistant Axis* (arXiv 2601.10387) and *Tracing Persona Vectors Through LLM Pretraining* (arXiv 2605.13329) — the default-assistant persona is one region of a persona space that forms early in pretraining; consistent with #825's pretrained finding and the "general mechanism" framing here.

No prior work fits a held-out linear map from a character's context representation to the activation profile of that character's dialogue in real fiction, nor compares it weight-level to the chat context→answer map. That is this task's contribution.

## 3. Hypothesis

- **H1 (existence/generality):** a character→dialogue-profile linear map exists in raw novels without the chat template. Quantitative: Real-novel map held-out R² at frozen layer 19 clears its story-level shuffle band (band ≈ −0.02 per #825), and reaches ≥ 0.5 × the chat reference R² at MATCHED n (matched-n read from the reused #825 power-curve machinery, parametrized — §4.4). Falsified if within the null band at all four frozen layers AND the max-over-layer selection read stays inside its selection-symmetric band. **Precedent note (honesty):** #825's naturalistic-format survival was the MLP-recovered TWO-TURN map only; the single-turn LINEAR map has never been measured off the chat template, so H1 is a genuine open test — the 0.5× expectation is a judgment call, and the MLP secondary probe is the registered diagnostic separating "no information" from "nonlinear information" if the linear map fails.
- **H2 (shared map):** the story map is substantially the SAME map. Quantitative: recentered chat→novel AND novel→chat transfer R² ≥ 0.5 × the corresponding within-regime refit ceiling at layer 19 (chat-side transfers computed with the position-matched single-position X variant as PRIMARY — §4.0); convergent reads: layer-profile Spearman ≥ 0.7, subspace overlap ≫ the random-subspace null (k/3584 ≈ 0.018 at k=64). Falsified (distinct maps) if transfer ≤ 0.1 × ceiling in either direction while both within-maps are healthy (R² > 0.2). Between 0.1× and 0.5×: partial sharing — report the subspace-overlap spectrum as the graded read, no binary claim.
- **H3 (specificity):** the map is character-specific, not generic span prediction. Quantitative: ΔR²_char = R²(correct pairing) − R²(within-story character swap) > 0 with the 95% novel-level bootstrap CI excluding 0; AND separator→novel transfer < 0.5 × the novel within-ceiling. Competing hypothesis (topic persistence / generic delimiter-span smoothness — cf. #825's topic-persistence caveat and #922) wins if the separator-anchor control map matches the novel map's strength AND transfers onto novel pairs at ≥ 0.8 × the novel ceiling AND ΔR²_char ≈ 0. Mixed outcomes are reported as a decomposition (how much of R² is topic, how much character).

## 4. Design

### 4.0 Formalization (binding, before any code)

Model M = `Qwen/Qwen2.5-7B-Instruct`, bf16, 28 decoder layers, d = 3584. h_ℓ(t) = residual-stream output of block ℓ at token position t (same capture convention as `issue825_extract_turnstore.py`).

**Regimes.** A regime fixes how text enters the model and how pairs are built:
`chat` (chat template; the #779/#825 object), `novel` (raw fiction text, no chat template, no special tokens), `story-gen` (model-written story inside an assistant turn under the chat template), `neutral` (raw non-fiction, no template).

**Pair.** A pair is (C, T): C an ordered set of context-anchor token positions, T an ordered set of target token positions, with max(C) < min(T) (strict causal precedence — every target token attends to every context token, never the reverse).

**Character-context vector** (novel / story-gen): c_ℓ = mean_{t∈C} h_ℓ(t), where C is the character's **local introduction span**: the sentence containing the character's first alias mention within the excerpt (sentence segmentation: deterministic regex on `[.!?]` + newline), extended by following sentences until ≥ 48 tokens or 3 sentences (whichever first), hard-capped at 96 tokens, and truncated to end before the first attributed quotation used in T. Drop the pair if |C| < 8 tokens after truncation (dropped counts reported). "Introduction" is deliberately LOCAL (within-window first mention), matching the single-context-window regime of the chat map; for mid-novel windows this span is the character's local re-establishment, which is the information the model actually has in-window.

**Parent-matched single-position X variant (registered second column):** c_ℓ^last = h_ℓ(t_last), where t_last is the FINAL token of C (the intro-span boundary token). This is the raw-text analogue of the parent map's input recipe — the chat map's X is a SINGLE POSITION, `c_last` at the assistant-header slot (`issue779_percontext_recon.py` "h: c_last -> v(x)"; `_cell_xy` Track-S X = slots[:,0]) — NOT a mean over context tokens. The variant is computed in the same extraction pass (one extra stored vector per span; near-zero extra compute) and serves two roles: (i) the input-recipe-matched X for every chat-side cross-regime transfer, so H2's "same map" read is not confounded by an uncontrolled input-recipe difference; (ii) a within-regime variant cell quantifying how much the span-mean recipe itself changes the map.

**Character-behavior target:** v_ℓ = mean_{t∈T} h_ℓ(t), where T = all tokens strictly inside the character's attributed quotation spans (dialogue text between the quote delimiters, delimiters excluded) that BEGIN after C ends. Whole-span mean summary (Source: #810/#920 — the mean is the carried ANSWER-side summary; max-pool's edge was a fold artifact). Drop the pair if Σ|T| < 16 tokens.

**Dialogue attribution.** Arm A: PDNC gold annotations — `quotations.csv` speaker + byte spans, `character_info.csv` alias lists; speakers that are groups / "unknowable" / narrator entries are excluded. Byte→token span mapping via tokenizer offsets; a quotation whose covering token span differs from the byte span by > 2 tokens on either edge is dropped; per-novel mismatch rate reported, gate ≤ 10% (the #825 G2 render-integrity convention). Attribution error handling: PDNC is doubly human-annotated, so residual error is ≈ annotation noise; any misattribution mixes other characters' dialogue into T, which pushes R²(correct) DOWN toward the swap control — i.e., it biases AGAINST H1/H3, never manufactures them. Arm B: deterministic extractor (below) + judge-audited precision gate.

**"The same map"** = three pre-registered similarity reads, each with its null:
1. **Cross-regime transfer R²** (PRIMARY for H2). Fit the full-data per-layer map on regime A (GCV λ on full data), apply FROZEN to regime B's pairs under group-5-fold intercept handling, report pooled R² as a fraction of regime B's within-regime refit ceiling (the standard group-5-fold `heldout_r2_sweep` R²). **Input-recipe matching:** every transfer involving the chat map (chat↔novel, chat↔story-gen) is computed with the SINGLE-POSITION X (`c^last`) on the story side as PRIMARY — matching the parent's `c_last` recipe — with the span-mean-X transfer reported as a SECONDARY read; novel↔story-gen transfers use span-mean X on both sides (recipe-matched by construction). Two application variants: **recentered** (PRIMARY): per test fold, X-standardization means and Y-offset come from regime B's train folds; scales (σ_x) and W stay from regime A — tests shared linear structure while tolerating regime mean shift; **strict-frozen** (SECONDARY): means and scales from regime A verbatim. Null: regime-B shuffle-null band (pairing permuted at group level) for the floor; the separator-map transfer onto the same pairs for the specificity comparison.
2. **Matched-layer weight/subspace similarity.** Per layer, principal-subspace overlap between top-k right (input) and left (output) singular subspaces of W_A(ℓ) and W_B(ℓ), k ∈ {16, 64, 256} (reuse `scripts/issue779_stage2_cka_subspace.py::_subspace_overlap`); null: 20 random k-dim subspace draws in R^3584 + the analytic expectation k/3584. Plus linear CKA between the two maps' predictions on a shared standardized held-out input sample (2,000 novel-regime c's; reuse `linear_cka`). Chat-side weight comparisons use the position-matched variant maps (like input recipes on both sides).
3. **Layer-profile rank correlation** — Spearman between the two regimes' 28-layer within-R² profiles (#825's replication-gate statistic; its G1 pass level was 0.963).

**Baseline family** (formalized): **B1 whole-window topic baseline** — replace c with the mean activation over ALL excerpt tokens preceding min(T) (character-agnostic topic read; NOTE: this is NOT the parent's recipe — the parent's X is the single-position `c_last`, not a full-context mean — B1's role is purely to bracket topic persistence from above). **B2 within-story character swap** — within excerpts having ≥ 2 eligible characters, pair character i's context with character j≠i's target (seeded derangement); ΔR²_char = R²(correct) − R²(swap) is the character-identity statistic. **B3 separator-anchor control** (Arm C below). **B4 story-level shuffle null** — pairing permuted across groups (the standard #778/#825 null, already group-blocked in `heldout_r2_sweep`).

### 4.1 Arm A — Real-novel character map (`armA_within`)

Corpus: **PDNC** (github.com/Priya22/project-dialogism-novel-corpus, pinned to a commit SHA recorded at implementation; per-novel `text.txt` + `quotations.csv` + `character_info.csv`; 22 novels v1 + 6 added 2023 — exact count read from `PDNC-Novel-Index.csv` at the pinned SHA). Data tier: **tier 1 (real fiction) with tier-2 established annotation** (LREC 2022 corpus). Pipeline:
1. Tokenize each novel with offsets (`add_special_tokens=False`). Slice into consecutive non-overlapping windows of W = 3072 tokens.
2. Per (window, eligible character): build C and T per §4.0 (span mean + boundary-token single-position variant). Row id (novel_id, window_idx, char_id); **group = novel**.
3. Gates (G0, CPU, pre-provision): per-novel span mismatch ≤ 10% (failing novels dropped + reported); total eligible pairs ≥ 800 across ≥ 10 novels. If rows > 5,000, seeded (seed 931) novel-stratified subsample to 5,000. Expected yield ~2,000–4,500 (35,978 gold quotations; ~1,000–1,400 windows).

### 4.2 Arm B — Model-written story map (`armB_within`)

Prompt battery: 1,200 prompts from seeded (seed 931) crossings of curated lists (12 genres × 10 settings × 10 conflict framings), each instructing: a 500–800-word story, ≥ 2 named characters who talk, dialogue in double quotes, every line attributed with a speech verb + speaker name. No system prompt (default assistant). Generation: vLLM, T = 1.0, top_p = 0.95, seed 42, max_tokens = 1024 (Source: #825 Track-S parity). The story TEXT is the measured data and is on-policy from the measured model — the prompts are elicitation only (their programmatic construction is justified in §12; diversity is deliberate across 3 axes).

Attribution (deterministic extractor): double-quote spans; speaker cue = a speech verb + capitalized name adjacent to the quote (post-posed `"...," said Maria` / pre-posed `Maria said, "..."`; verb list of ~14 common speech verbs); names canonicalized; characters with ≥ 2 attributed quotes eligible; **unattributed quotations are DROPPED (precision-first), counts reported**. C/T built by the same §4.0 recipe over the assistant-turn story tokens only (chat-template tokens excluded from all spans). Group = story.

**Why code, not a model call?** (a) Alternative considered: Sonnet attributes every quotation (~15–25k calls). (b) Code preferred: the prompt contract makes attribution structurally explicit, so a deterministic extractor is near-exact, free, and reproducible; N ≈ 20k quotations makes per-quote LLM calls wasteful as the default. (c) Flip condition: judge-audited precision < 0.90 on a 200-quote random sample → escalate to full Sonnet re-attribution via the Anthropic **Batch API** (~15–25k calls, `claude-sonnet-4-5-20250929`, via `eval.batch_judge` / `api_dispatch.py`), then re-gate at ≥ 0.95 on a fresh 100-quote sample.

### 4.3 Arm C — Separator-anchor control (`armC_sep`) + preceding-sentence control (`armC_prevmean`)

Corpus: **WikiText-103-raw** (`Salesforce/wikitext`, `wikitext-103-raw-v1`, train split; Merity et al. 2016, arXiv 1609.07843) — tier 2, non-persona text. 600 seeded articles ≥ 512 tokens, truncated at 1,024 tokens, fed raw (no template). Anchors: token positions decoding (stripped) to `.` `!` `?` that terminate a sentence; ≤ 6 seeded anchors per article; following span = tokens to the next such anchor (exclusive), length ∈ [8, 256]. Pairs: `armC_sep`: c = h(anchor token) (single position — the origin prompt's "separator activation"); `armC_prevmean`: same targets, c = mean over the sentence preceding the anchor (≥ 8, cap 96 tokens) — the input-recipe-matched topic-persistence read for the span-mean recipe. v = mean over the following span. Group = article. n ≈ 3,000. Interpretation coordinates with #922 (the per-position analogue) at write-up time; no dependency.

## 11. Decision Rationale

- **Model = Qwen2.5-7B-Instruct (bf16).** Why: the parent line's model; H2 compares against the #825 instruct map. Source: #825. Alternatives: pretrained Qwen2.5-7B (deferred — a natural follow-up given #825's 87% result; doubling models doubles extraction for a second-order question).
- **Frozen layers {14,18,19,26}, headline 19.** Why: pre-registered read points; avoids selection. Source: #779/#722, reused by #825. Alternatives: full-sweep-only (loses the frozen pre-registration).
- **Ridge/GCV/λ-grid/K=5/fit-seed 0/20 null draws/1000 bootstrap.** Why: the parent estimator verbatim — single-variable discipline. Source: #825 (`issue825_fit_cells.py` committed constants; #778 for selection-symmetric nulls). Alternatives: sklearn RidgeCV (unbatched — fails vectorize-first).
- **Context-X recipe: span mean (headline) + parent-matched single-position boundary-token variant (registered second X column).** Why: the parent map's X is a SINGLE POSITION — `c_last` at the assistant-header slot (`issue779_percontext_recon.py` "h: c_last -> v(x)"; `_cell_xy` Track-S X = slots[:,0]) — so an uncontrolled input-recipe difference would confound H2's same-map transfer. The variant-add was chosen over merely registering the recipe difference because it is near-free: the same captured activations yield the second X column (one extra gather per span).
