# Plan — Issue #2564: Controlled minimal-pair battery — does the frozen context→answer map predict the DIFFERENCE in answer vectors, per instruction axis? (v4 — round-1 critique revision)

## 0.0 TL;DR (plain English)

- **What I'll run:** I build a bank of 984 single-turn prompts where two prompts in a pair differ by exactly one thing (a persona, a format rule, a stance, a single injected user name, etc. — 9 instruction axes and 2 query axes, every value string pre-verified to have the same token count within its axis). From those prompts I form 2,778 comparison pairs — value flips, install pairs, "same meaning, different wording" rewordings, and (new in this revision, at zero extra GPU cost) value flips computed WITHIN the reworded family — and for each pair I compare the actual change in the model's answer representation against the change the frozen #779 context→answer ridge map predicts, plus a do-nothing baseline.
- **What I expect:** the map will get the direction of the change roughly right for content-like axes (what is asked, injected user facts) but shrink or lose the direction for policy-like axes (stance, hedging, register) — sharpening #2215's finding that the map "redistributes" separation, now on stimuli where the axis is the only thing that differs.
- **What would change my mind:** if the map's predicted difference beats the raw context-difference baseline in direction and calibration on most axes (the map genuinely transforms, not just passes through), or if the map's predicted value-flip directions agree across the two wording families no better than chance while the real answer changes do agree (the map carries surface wording, not the instruction's content).

**Competing hypotheses (descriptive, no pass/fail gate):**
- **H-faithful:** per-axis direction cos(Δ̂, Δ) approaches the split-half ceiling and per-axis calibration slope ≈ global shrinkage slope — the map carries the axis like it carries everything.
- **H-global-shrinkage-only:** direction is carried (cos well above the shuffled-pair null) but per-axis slopes all collapse to the single global slope with no per-axis structure beyond it — the map is a uniform contraction plus pass-through (consistent with #2215's identity+bias near-equivalence at context-end).
- **H-direction-loss (per-axis):** for specific axes (predicted: policy-like axes — stance, hedging, register), cos(Δ̂, Δ) sits near the shuffled-pair null while the split-half ceiling is high — the map loses those directions rather than under-scaling them.
- **H-surface-only:** in PREDICTED space, cross-family value-direction consistency — cos between the template-family and paraphrase-family per-(axis, value-pair) mean Δ̂s (§6) — sits near the class-preserving derangement null while the OBSERVED-space consistency is well above it: the map transduces surface wording, not aspect content. (The raw flip-minus-paraphrase norm gap is retained as a DESCRIPTIVE surface-sensitivity read only — it is NOT an H-surface-only signature: value flips are token-matched WITHIN one wording frame while paraphrases rewrite the whole instruction (±30% length), so a surface-transducing map predicts a NEGATIVE gap, not ≈0. v3's "≈0-gap ⇒ H-surface-only" signature was mislabeled and is dropped, per the round-1 critique MF-B.)
What distinguishes them: the (direction cos vs ceiling vs null) × (per-axis slope vs global slope) × (cross-family consistency, observed vs predicted) triple, per axis. These are labels on a continuous per-axis profile, not a registered verdict partition.

## 3. Design

### 3.1 Skeleton and rendering

Single-turn chat, rendered with the project tokenizer's `apply_chat_template(..., add_generation_prompt=True)` (the #2162 render path, `bank2162.py:1413`):

```
<|im_start|>system\n{SYSTEM}<|im_end|>\n<|im_start|>user\n{QUERY}<|im_end|>\n<|im_start|>assistant\n
```

- **EMPTY system level** = explicit `{"role":"system","content":""}` → renders an empty system block (`<|im_start|>system\n<|im_end|>`). Verified at plan time: OMITTING the system message makes Qwen's template inject "You are Qwen, created by Alibaba Cloud. You are a helpful assistant." — which contains "assistant" and would violate the body's no-assistant-wording rule and the neutral-prompt-conflation lesson. The empty block is the neutral default; its off-fit-distribution risk is carried as assumption A9 (§12) and mitigated by (a) headline reads on swap pairs (instruction on BOTH sides), (b) the identity baseline sharing the identical render.
- Context-end slot `v_C` = last context token state (the `cx_last` convention, = last token of the rendered prompt including the generation header), layer 19 primary — the #779 map's input convention (parity-gated in #2215, gate A7/gate-4).
- Answer slot `v_A` = tail-inclusive mean over the completion + end-of-turn tail (the maps' training-target convention; span-mean stored as secondary twin) — both poolings from one teacher-forced forward (`capture_answer_states`, `tail_inclusive=True`).

### 3.4 Paraphrase-null construction (deferred decision 3 — RESOLVED)

One paraphrase per instruction value (39 total) + one per carrier question (12): same aspect value, different surface wording, value phrase/name/profile kept IDENTICAL where the axis has a slotted template. Predicted Δ(value, paraphrase) ≈ 0 is the null. The per-axis flip-minus-paraphrase gap (in observed AND predicted space) is a DESCRIPTIVE surface-sensitivity read — NOT the aspect signal: value flips are token-matched edits WITHIN one wording frame while paraphrases rewrite the whole instruction (deliberately, ±30% length), so a purely surface-transducing map predicts a NEGATIVE flip-minus-paraphrase gap (paraphrase edits are larger), not ≈0 — no hypothesis label keys on the raw gap (relabeled per round-1 critique MF-B; v3's "purged of surface sensitivity" phrasing is dropped). The aspect claim instead keys on the §6 cross-family value-direction consistency read over the paraphrase-family swap pairs (§3.5), with the changed-token edit-dose covariate registered beside it. Paraphrases are deliberately NOT token-count matched (different surface IS the manipulation); realized counts recorded, length ratio kept within ±30% by construction.

Paraphrase templates (slotted axes): persona `Adopt the persona of a {NP} for your whole reply.` · format `Your whole reply must take the form of {NP}.` · lexical-marker `Make sure your reply contains the word "{W}".` · user-fact `This user is called {NAME}. Use their name when you reply.` · user-profile `Bear in mind while answering that the user is {PROFILE}.`

Per-value paraphrases (sentence axes): stance — `Commit to just one side and defend it.` / `Take the negative side on all the options.` / `Do not lean toward any side at all.` / `Present the strongest case for each side.` / `Take the contrarian position at every turn.`; content-constraint — `Your reply must contain precisely three reasons.` / `Keep every number out of your reply.` / `Write without ever speaking about yourself.` / `Work a specific real example into your reply.` / `Keep your reply shorter than twenty words.`; register — `Write in a highly formal, businesslike style.` / `Write in a relaxed, chatty, informal style.`; hedging — `Sound completely sure of every claim you make.` / `Qualify every claim and express plenty of doubt.`

### 3.6 Map arms (deferred decision 2 — RESOLVED)

- **frozen single-turn map (`779ce`) — MANDATORY, PRIMARY.** `issue779_monitoring/n1m_readout/weights/L19/ridge.pt`, applied read-only via `issue779_ffc_n1m_fits.apply_map` (the exact #2215 sepcmp path). Δ̂ = apply_map(v_C(A)) − apply_map(v_C(B)).
- **multi-turn context-end companion (`1738ce`) — INCLUDED as secondary.** Same input slot (context-end), fit on a matched multi-turn corpus; #2215 showed it beats its baseline at context-end (+0.016 [+0.002, +0.030]) and the sepcmp round already ran exactly this arm pair. Costs nothing extra (same store feeds it); cross-map agreement per axis is a robustness read.
- **multi-turn prefix-end companion (`1738pe`) — EXCLUDED**, with reasons: (i) in this single-turn skeleton prefix-end = the last token before the final user query = the end of the SYSTEM block; for every EMPTY-level context that is an empty system block (~2 special tokens) — a degenerate input far off any fit distribution; (ii) for query axes the prefix is token-identical across the pair, so predicted Δ ≡ 0 structurally (the #2215 degenerate-cell shape, there excluded by a mechanical prefix-token-identity check); (iii) #1738's prefix map was fit on multi-turn prefixes (system + prior turns) — a system-only prefix is out-of-domain in a way context-end is not; (iv) precedent: the parent sepcmp round read context-end arms only ("prefix_end: skipped by design"). Rendering it here would produce uninterpretable cells, not information.
- **identity-delta baseline (`iddelta`)** — Δ̂_id = v_C(A) − v_C(B). NOTE: in the delta framing the learned bias CANCELS exactly (Δ̂ under v̂=x+b equals v_C(A)−v_C(B)), so identity and identity+learned-bias coincide; this IS the identity+learned-bias baseline of CLAUDE.md § mapping-baselines, stated per that rule (§6).

**Analyzer read-time conventions (registered now — the narration keys the analyzer must honor; round-1 prose registrations):**
1. **Ceiling convention:** the 5/5 split-half cos r₅ steps up to the K=10-mean ceiling via Spearman–Brown (r₁₀ = 2r₅/(1+r₅)); ceiling-NORMALIZED cos is SUPPRESSED (raw cos + ceiling reported side by side, no ratio) wherever the ceiling estimate is nonpositive or its bootstrap CI includes zero.
2. **Calibration vs attenuation:** per-axis slopes are weighed against the stored split-half noise norms — errors-in-variables attenuation is axis-differential and mimics the predicted policy-axis compression; a below-global slope is narrated as compression only where the axis's noise norm cannot account for it. 3. **Map-vs-geometry attribution:** any "the MAP distorts axis X" narration keys on the per-axis map−iddelta gap (the same read differenced against `arm_iddelta`), never the map arm's absolute per-axis profile.
4. **Direction-loss narration** requires ALL of: low axis-identity cosine AND near-null per-pair direction cos AND a high split-half ceiling; otherwise the axis is narrated as axis-mean/generic-only carriage.
5. **Compliance selection:** every cross-axis claim carries the per-axis fire rates + the 50%/90% threshold sensitivity; if calibration or direction tracks fire rates across axes, the resolving test is the complying-draws-only Δ recompute.
6. **Answer-length:** per-axis answer-length (token-count) deltas are reported from the anchors jsonl; where the tail-inclusive and span-mean poolings diverge on a read, consult the span-mean twin before narrating.
7. **Query-axis regime:** query-content / query-form reads are reported as bare-empty-system results (the axes live on the empty-system render); the clean "kind of information" comparison is the within-system-slot contrast (user-fact / user-profile vs stance / hedging / register); the A9 fit-corpus render read runs before any cross-regime (query-vs-instruction) narration.
