# Plan — Issue #1332: Function-space similarity between per-context-family fitted context→answer maps as a leakage predictor

## 0.0 TL;DR (plain English)

- **What I'll run:** For each of the 26 prompt styles from our earlier marker experiments (personas like "pirate captain," phrasing styles like "polite request," and a few instruction prompts), I'll fit a small linear map on the frozen base model that predicts, from the model's internal reading of a question, its internal state while answering under that style. Then I check whether two styles with interchangeable maps are also the pairs where fine-tuning on one style bled into the other, using the leakage numbers we already measured. No new training.
- **What I expect:** Map interchangeability will track leakage at least as well as the older "how far apart do these prompts sit internally" measures, and I'm betting it adds real signal beyond them. That bet has a pre-registered test: if the correlation vanishes once I control for the two older distance measures, the new predictor is just those measures in disguise, and the write-up will say so.
- **What would change my mind:** If maps for two styles transfer near-perfectly yet leakage between them is low (or the reverse), that breaks the story that "computing the same context→answer function" is what leakage follows. If the predictor works on the persona grid but does nothing on the behavior→behavior matrix, that repeats the pattern where every geometry predictor so far stayed context-only.

## 1. Goal

> "Test whether function-space similarity between per-context-family fitted linear context→answer maps (cross-family transfer R² / prediction agreement on the frozen base model, both prefix-based and context-based arms) predicts fine-tuning leakage from source persona to target contexts on an existing measured leakage matrix, with incremental validity over the activation-cosine, JS-divergence, base-rate-prior, and whitened-gate baselines under group-level held-out (LOFO) evaluation."
> (Task #1332 Goal, verbatim.)

One paragraph: the #779/#823/#952 line established that a linear map from a context's last-token state to the model's answer-span states exists, is nearly as fittable for off-policy text, transfers across models where style matches, and reads a "consistent persona/character" rather than the model's own policy. The finalized off-policy mapping report's registered next step is exactly this task: does similarity BETWEEN these per-context-family maps — a function-space quantity comparing the context→content *computations*, not the context *representations* — predict which fine-tuning leakage cells light up? All prior leakage predictors compared representations as points (cosine, JS, Gaussian-KL, base prior) and either failed held-out tests or were beaten by the base prior; this is the first *transformation-space* predictor, and it is cheap because the leakage ground truth already exists.

**Literature (method delta):** representational-similarity measures (CKA — Kornblith et al. 2019, arXiv 1905.00414) compare activation *geometries*; functional-similarity measures — model stitching (Lenc & Vedaldi arXiv 1411.5908; Bansal, Nakkiran & Barak arXiv 2106.07682), prediction agreement, linear-mode-connectivity — compare what the representations *do* (survey: Klabunde et al., arXiv 2305.06329, the functional-vs-representational taxonomy; recent: "How not to Stitch Representations to Measure Similarity," arXiv 2412.11299 — direct-matching vs task-loss-matching caveats). Our S is a stitching-flavored functional measure: h_i "stitched" onto family j's rows. **Delta vs everything in-house:** cosine/JS/prior/whitened-gate compare context POINTS; S compares fitted context→answer TRANSFORMATIONS. The kill criterion tests exactly whether that distinction carries information.

## 3. Hypothesis

**H1 (headline):** Function-space similarity S_sym(source, target) between per-family context→answer maps correlates positively with the measured leakage L(source→target) across the 400 off-diagonal cells, generalizes under leave-one-target-family-out, and carries incremental validity over the activation-cosine and RB-JS baselines on identical rows (the pre-registered partial correlation).

**H2 (secondary):** The predictor's LOFO skill exceeds the base-prior + predict-the-mean additive baseline's (ΔCV-R² > 0 under LOFO), i.e. it adds pair-specific structure beyond target-level effects.

**H3 (OOD, secondary):** Scored as one more entrant under #545's frozen leave-family-out protocol on the 119 unflagged dev cells, the map-similarity predictor's weighted Kendall τ exceeds the #545 selection-noise band — or it fails like every other geometry predictor did, which is itself the registered transfer answer.

Quantitative expectations (for calibration, not gates): #474 loc-ep1's raw divergence read was ρ ≈ −0.50 full-panel / ~0 stylized-excluded; a useful S should land |ρ| ≥ 0.3 full-panel AND retain sign with CI excluding 0 on the stylized-excluded panel, where the point metrics collapsed.

**Registered verdict lattice** (point estimates: ρ = LOFO-consistent full-sample Spearman ρ(S_sym, L) with two-way cluster-bootstrap 95% CI; partial ρ = partial Spearman ρ(S_sym, L | cosine, JS) on identical rows, same bootstrap):

DISJOINT and exhaustive: Confirmed ⇔ ρ > 0 AND ρ's 95% CI excludes 0 on the positive side AND partial ρ > 0 AND partial ρ's 95% CI excludes 0 on the positive side; Redressed ⇔ ρ's 95% CI excludes 0 on the positive side AND partial ρ's 95% CI straddles 0; Suppressed ⇔ ρ's 95% CI excludes 0 on the positive side AND partial ρ's 95% CI is wholly below 0; Reversed ⇔ ρ's 95% CI is wholly below 0; Inconclusive ⇔ otherwise.

## 4. Design

### 4.1 Context families (26) and the reused leakage matrix

- **Families:** the 16 #474 conditions (rendered by `build_prompt_for_condition` in `src/explore_persona_space/experiments/i406_conditions.py`; class-D requires a `{question: {register: rewrite}}` dict) + the 10 #532 instructed bystanders (`instr_explicit_1..4`, `instr_soft_1..3`, `instr_oblique_1..3`; verbatim system prompts extracted from `scripts/issue532_predictor_stress.py` — the implementer asserts string identity against `eval_results/issue_532/predictors.json`'s `bystanders` list).
- **Leakage DV (reused, never re-measured):** L(s,t) = `summary.mean_logp_marker`(trained, cell s→t) − `summary.mean_logp_marker`(base, cell s→t) from `eval_results/issue_532/logp_slot_followup/per_cell_{trained,base}/{s}__{t}.json` (416 cells, 50 probes each, four floats per slot per side, corrected-slot recipe). Sensitivity DV: Δ`mean_marker_eos_margin` (trained − base) — the non-saturating EOS-margin logit space from the SAME files (marker-leakage rule, three-space discipline). Off-diagonal analysis set: 16 sources × 26 targets minus the 16 s==t cells = **400 cells**.
- The 16×16 #474 loc_ep1 `G_logprob_matrix.json` is a consistency check only (same subgrid, older slot read).

### 4.2 Query bank (shared, neutral, 400 queries)

- **Construction:** 400 fresh single-turn general-knowledge/advice questions in the #406 question style, Claude-generated (Sonnet 4.5 via `api_dispatch.py`), topic-diversified (≥20 topic strata × ≥3 length bands; the #406 Phase-0 generation prompt is the template — implementer ports it from the #406 lineage scripts), deduplicated, and **asserted disjoint** from `data/issue_406/q_train_answers.json` (30 q) and `q_test_extended_50.json` (the leakage-measurement probes; exact-string + normalized-substring disjointness). Bank persisted to HF (`issue1332_map_similarity/inputs/query_bank_v1.json`) with sha256 in the analysis metadata.
- **Class-D rewrites:** the existing rewrites (`data/issue_406/class_d/rewrites_v1.json`, 80 questions) do NOT cover the new bank → generate 5 registers × 400 questions = 2,000 Claude rewrites using #406's verbatim register-rewrite prompt per register (ported from the #406 Phase-0 script), persisted to `issue1332_map_similarity/inputs/class_d_rewrites_v2.json`. Existing 80-question rewrites are NOT reused (different questions).
- **Data source + realism tier:** tier 3 (DIVERSE LLM-generated synthetic). Justification: the reused leakage DV was itself measured on this question style under these 26 renderings — distribution match to the reused DV is a measurement-validity requirement (fitting maps on, e.g., raw LMSYS rows would change the query distribution relative to the ground truth's, confounding the predictor read); tiers 1–2 offer no corpus matching the #406 rendering constraints (short standalone questions compatible with B-wraps + D-rewrites). Diversity is enforced by construction (strata) — not a flat template. Carried into the clean-result as a scope caveat.
- **Fold structure:** ONE query-indexed 5-fold partition (KFold(5, shuffle, rs=0)) shared across ALL families, so a map fit on family i's folds is never evaluated on a query it saw (in any family) — held-out-by-query transfer by construction. Split-half partition (A/B, 200/200, rs=0) likewise query-indexed and shared.

### 4.3 GPU phase — generation + capture (single script, per-family checkpointed)

Per family c, per query q (rendered prompt P_c(q)):
1. **Generation (vLLM, 1 GPU):** R_c(q) = greedy (temp 0), `max_new_tokens=1024`, chunked ≤500 prompts/call (`EPM_VLLM_GREEDY_CHUNK_SIZE`), `use_tqdm=False`. Truncation rate logged per family. Rollout TEXT persisted per family to `issue1332_map_similarity/raw_completions/generation/{cid}.json` the moment the family completes (persist-by-default; upload per family, one `upload_folder` commit per family).
2. **Teacher-forced capture (HF bf16, hooks on `model.model.layers[L]`, all 28 layers, `logits_to_keep=1` introspection-guarded, batched right-padded):** inputs built by **concatenating per-segment TOKEN IDS** (never re-tokenizing the concatenated string), intra-prompt boundaries from offset mappings (the #1092 BPE-seam rule); a G2-style identity gate (teacher-forced states ≈ generation-time hook reference on 3 spot rows per arm) gates the sweep. Stored per (family, query), fp16:
   - `cx_last` — hidden state at the last context token (end of P_c(q), pre-assistant) — **context-arm map input** (#779 convention);
   - `prefix_end` — hidden state at the last token of the prefix segment (system prompt for class A + instructed families; the chat-template preamble position for B/C1/D, where the prefix carries no family content — recorded for the prefix-arm reads, degeneracy stated);
   - `v_mean` — mean over the answer span [prompt_len, full_len), INCLUDING the two template-end tokens — **map target** (#779 `v_x` convention);
   - `v_last_turn` — last formatted-turn token state (exploratory).
   Sharded `.pt` per family (~26 files × ~300 MB), uploaded to `issue1332_map_similarity/analysis_tensors/capture/{cid}.pt` per family as completed, verified with scoped `list_repo_tree`.
3. **Validity mask:** a (family, query) row is invalid if R is empty or the judge-free structural check fails (response < 3 tokens). Family floor: ≥80% valid rows (graceful degradation — a family between floor and 400 is kept with shortfall documented; below floor it is dropped, reported as a finding, and its leakage cells flagged `N/A — family excluded`, never zero).
4. **#545 OOD-arm capture (same pod, sequential):** for each of the 19 trained behaviors, (question → corpus answer) pairs from `issue545_behavior_testbed/corpora` (@ `64b864a8`), rendered no-system-prompt (the #545 training regime); for each of the 16 eval outcome columns, the elicitation-context + realization pairs `scripts/issue545_extract_predictors.py` defines (reusing its context definitions verbatim). Teacher-forced capture of the same four summaries. Answers here are the corpora's Sonnet-written/handwritten text — off-policy targets, named as a measurement caveat (licensed by #823: off-policy maps are fittable and meaningful; these corpora ARE the text that defined the trained behavior).

**Smoke/sweep architectural parity:** smoke = the sweep with `--families A1,C1 --n-queries 8` through the identical dispatcher/subprocess/env path; plus the tiny-real CPU e2e for the capture path (2-layer same-arch model, real tokenizer) before the first GPU launch.

**Why code, not a model call?** The only unstructured-data step is bank generation + D-rewrites, which ARE model calls (Sonnet). All similarity/statistics are numeric tensor computations — no classifier/parser over unstructured data. N/A beyond that.

### 4.4 Mapping arms (the standing dual-arm rule — both named)

- **Context-based arm (PRIMARY):** per-family ridge map h_c: `cx_last`(c, q) → `v_mean`(c, q), fit per (family, layer, fold) via the #823/#779 harness: standardize-X/center-Y, GCV λ ∈ logspace(−2,4,13), solver `ridge_fit_predict_fast` (dual Gram-eigh; n_train ≈ 320 ⇒ 320×320 eigh) with the mandated slow-vs-fast parity gate vs `ridge_fit_predict` on 3 (family, layer, fold) cells at production shape (tolerance: max rel diff ≤ 1e-4, per the fast twin's size-dependent-parity docstring; fp64 throughout).
- **Prefix-based arm (stated, mechanically-forced deviation — the #1073 precedent):** within a family the prefix-end state is CONSTANT across queries, so a per-family prefix-input ridge degenerates to predicting the family's mean answer state. The prefix arm is therefore REALIZED as (i) the **mean-target map** h_c^prefix ≡ ȳ_c (its "transfer" = how well family i's mean answer predicts family j's answers — the mean-answer-similarity control that separates "similar computations" from "similar average outputs"), and (ii) the **prefix-end activation cosine** S_prefix-cos(i,j) (globally-mean-centered 26-bank cosine per #536) as the prefix arm of the point-metric baseline. Carried into the clean-result as a scope caveat, verbatim per #1073's accepted form. (Exploratory only: a 26-row cross-family map prefix_end → ȳ_c, #667-gate style.)

### 4.5 Function-space similarity metrics

At each analysis layer, per ordered pair (i, j), all on the SHARED query folds:
1. **Cross-family transfer R² (PRIMARY):** per fold f, fit h_i on family i's train-fold rows; score its predictions on family **j**'s val-fold rows (X_j, Y_j): R² = 1 − ss_res/(ss_tot + 1e-12), ss_tot centered on Y_j's val-fold mean (the exact #823 convention, one fit per (i, layer, fold) rescored against every j — the committed dedup shape). S_trans(i→j) = mean over 5 folds; **S_sym(i,j) = ½(S_trans(i→j) + S_trans(j→i))** — the headline predictor. Directional asymmetry S_trans(i→j) − S_trans(j→i) reported as a diagnostic.
2. **Held-out prediction agreement (companion):** on a shared probe input set X_probe (the val-fold `cx_last` rows pooled over ALL families — identical for every pair), A(i,j) = R² between ŷ_i(X_probe) and ŷ_j(X_probe), symmetrized by averaging the two centering choices. Pure function-space (no Y needed).
3. **Map-mediated displacement (exploratory):** D_map(i,j) = mean_x ||ŷ_i(x) − ŷ_j(x)||² / mean_x ||ŷ_j(x) − ȳ_j||² on X_probe (a normalized displacement dissimilarity; reported as 1 − D_map).
4. **Weight-space reads (descriptive ONLY):** cosine between dual-coefficient-reconstructed W_i, W_j at the headline layer, reported next to the #823 matched-half noise calibration — never in the headline (settled decision).
5. **Excess-transfer normalization (reported alongside raw S):** S_excess(i→j) = S_trans(i→j) − R²_mean-target(i→j) (transfer beyond the prefix-arm mean-target map), which nets out mean-answer similarity.

**Nulls + ceilings:**
- **Shuffled-pairing null:** B = 10,000 draws; each draw permutes the target-family labels of S's columns (and, secondary, source labels of rows) before recomputing the evaluation statistic; vectorized as batched rank-transform + GEMM (`analysis/null_battery.py` pattern). Per-draw × per-layer statistic matrices persisted (§6).
- **Same-family split-half ceiling:** fit h_c^(A) on half-A rows, h_c^(B) on half-B rows (n = 200 each); ceiling similarity = the SAME metrics computed on the pair (c^(A), c^(B)). Also yields the reliability of S: r_SS = Spearman between S^(A) and S^(B) similarity matrices across the 400 cells (two independent half-map estimates); reliability of L: r_LL = probe-ALIGNED split-half over the 50 probes' per_q values (llm-judging rule 21 — one item partition applied identically to every cell), Spearman–Brown corrected; attenuation ceiling on ρ(S,L) = √(r_SS · r_LL), reported next to every observed ρ. (Half-map n = 200 sits below the #779 ~250-row comfort point → the ceiling is conservative; stated.)

### 4.7 Evaluation pipeline (CPU)

1. **Layer freeze (DV-independent, before any leakage join):** headline layer L* = argmax over 28 layers of mean same-family split-half transfer R² (map estimation quality; computed and committed to `eval_results/issue_1332/layer_freeze.json` in a phase that never loads L). Full 26×26 similarity matrices computed at L* + the diagnostic grid {5, 9, 14, 17, 20, 23, 26}.
2. **Headline reads at L*** (400 off-diagonal cells): Spearman ρ(S_sym, L) — raw AND prompt-token-length-difference-partial (the #474 convention); two-way cluster bootstrap CI (B = 2,000; resample sources and targets); shuffled-pairing null p; three panels per #474 (all 400 / stylized-excluded-as-source / stylized-excluded-either-side).
3. **LOFO:** leave-one-TARGET-family-out (26 folds; predictor→leakage regression per fold, rank skill on the held-out family's cells) — the registered generalization headline; leave-one-SOURCE-out (16 folds) companion. CIs framed on group-level n (26 / 16).
4. **Incremental validity (the kill):** partial Spearman ρ(S_sym, L | cosine, JS) on identical rows (cluster bootstrap); PLUS the #532-style hierarchy under LOFO: {baselines-only} vs {baselines + S_sym} ΔCV-R², baselines = cosine + JS + base prior + whitened gate + predict-the-mean. **Collinearity gate (pre-registered):** if Pearson(S_sym, cosine) > 0.6 across the 400 cells, additionally run tercile-bucket median tests + polynomial (deg-2) residualization robustness reads and report them beside the partial ρ.
5. **Sensitivity battery:** EOS-margin DV swap; within-source z-normed L; prediction-agreement + excess-transfer predictor swaps; per-layer ρ curve (diagnostic display, no max claim).
6. **OOD arm (#545):** S between behavior maps (19 train × 16 eval columns), scored under #545's FROZEN protocol verbatim (weighted Kendall τ, within-column z-norm, leave-one-behavior-family-out, champion selection inside folds, 119 unflagged dev cells only — the 52-cell quarantine is NOT scored, it was burned in v1). Feasibility gate: per-behavior split-half map reliability must exceed its shuffled-pairing null; else the arm is reported "underpowered at corpus n" (a decidable outcome).
