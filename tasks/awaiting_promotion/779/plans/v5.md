<h1>Plan v2 — Issue #779: how well does the context predict the answer, and can a learned map beat Persona Vectors' monitor?</h1>

<section class="plan-tldr">
<h2>0.0 TL;DR (plain English)</h2>
<ul>
<li><strong>What I'll run:</strong> The Persona Vectors paper guesses how a chatbot will behave (evil / sycophantic / making-things-up) by reading its internal state right before it answers and dotting it against a "trait direction". That guess works across obviously-different prompts but barely works among similar ones. On Qwen-2.5-7B I'll do three things with ONE data-collection run. First, I'll measure — for a single prompt and its single answer — how much the model's before-answering state already tells you about its during-answer state, and how quickly that grip fades as the answer gets longer. Second, I'll learn a small map that turns "what the prompt looks like inside the model" into "what the answer will look like inside the model", read the trait off that prediction, and check whether it beats the paper's raw read — and, crucially, whether it beats a fair, equally-powerful predictor trained to guess the trait <em>directly</em> from the prompt. Third, I'll read the trait off the model's <em>actual answer as it's written</em> (average / peak over the answer's words) and see how much better that is.</li>
<li><strong>What I expect:</strong> Reading the real answer (post-generation) will clearly beat reading before the answer — it almost sees the answer, so it's a ceiling, not a fair monitor. The interesting bets are before-generation: I expect the learned map to recover some of that ceiling for the traits where the paper's read collapses, and I expect the honest test to be whether routing through "predict the answer first" beats just predicting the trait directly. On the characterization side I expect the prompt's grip on the answer to be strong at the start of the answer and to decay as the answer runs on.</li>
<li><strong>What would change my mind:</strong> If the learned map does no better than the raw read, the prompt state simply doesn't carry the answer's trait content and the paper's ceiling is the real ceiling. If a plain linear map already captures the whole advantage, the prompt→answer relationship is boringly linear — and worse, the linear map may collapse into "we just re-derived a slightly better trait direction", which would make that arm a non-result. If predicting the trait directly matches the map, the "predict the answer first" detour earns nothing when you already have the trait's labels — and the only place the map can still win is guessing traits it has never seen.</li>
</ul>
</section>

<section class="plan-summary">
<h2>0. Plan Summary (technical)</h2>
<p><strong>Training:</strong> NO model fine-tuning. Re-extract Persona Vectors <code>r_B</code> (arXiv 2507.21509 recipe, all 28 layers, response-avg, judge-filtered) for 3 traits (evil / sycophancy / hallucination) on Qwen-2.5-7B-Instruct. Fit a behavior-agnostic context→answer-profile map <code>h: c_x → v(x)</code> (ridge / kernel-ridge / MLP) on real user prompts (LMSYS-Chat-1M), reconstructing the full mean-response activation — never the trait. R1 monitors via <code>⟨h(c_x), r_B⟩</code> and is tested head-to-head against a matched-capacity DIRECT context→behavior predictor <code>g: c_x → trait</code> (ridge + MLP). R2 monitors via pooled projection of the actual generation's per-token activations onto <code>r_B</code> (mean / max / top-k / last). R3 characterizes the map: reconstruction R²/cosine, per-relative-position predictability decay, and context-set→answer-set CKA + linear predictability per layer-pair. <br>
<strong>Hyperparameters:</strong> r_B: 5 pos/neg system-prompt pairs, 20 extraction Qs, 10 rollouts/arm, temp 1.0, judge-filter &gt;50/&lt;50, drop-never-coerce <em>(Source: persona-vectors-recipe.md / arXiv 2507.21509 App.)</em>. h: ridge λ by GCV; kernel-ridge RBF median-heuristic bandwidth, Nyström (m≈2000) if N&gt;20k; MLP 1 hidden 512 GELU, AdamW lr 1e-3, wd, ≤300 epochs early-stopped, PCA-k target head <em>(Source: #722 vectorized_mlp_skill / #658 LOCO)</em>. Judge: N=5 graded 0–100 draws, temp 1.0, drop-never-coerce <em>(Source: llm-judging.md rule 4 + persona-vectors-recipe.md step 4)</em>. Eval rig: TWO separate elicitation modes — 8 system-prompting conditions AND 5 many-shot conditions ({0,5,10,15,20}-shot), evaluated SEPARATELY (within-condition Pearson computed within each mode's conditions, averaged within mode; both mode values reported per trait) — total 13 conditions/trait, 10 rollouts/config/question, 40 eval questions/trait <em>(Source: arXiv 2507.21509 App. "Correlation analysis" verbatim — the paper's two-column system/many-shot table is exactly this structure)</em>. Corpus ≥5000 train / ≥400 eval contexts <em>(Source: #511 N-scaling)</em>. <br>
<strong>Baselines / controls:</strong> PV raw <code>⟨c_last, r_B⟩</code> (within-condition r reproduced: evil .511/.735, syc .669/.813, halluc .245/.400); <strong>direct context→behavior predictor</strong> (ridge + MLP, matched capacity, per behavior — FIRST-CLASS arm); trait-fit linear probe on <code>c_x</code> (linear upper bound); Oracle <code>⟨v(x), r_B⟩</code> (R1's ceiling + Step-0 headroom gate). <br>
<strong>Loss surface:</strong> N/A — no fine-tuning. The h-map's regression loss (MSE / PCA-MSE / cosine) is over the reconstructed mean-response activation vector, NOT the trait scalar; the direct predictor's loss is over the trait scalar. <br>
<strong>Compute:</strong> one 8×H100 pod, data-parallel (8 single-GPU CUDA_VISIBLE_DEVICES workers, NOT TP=8) for the generation + activation-caching burst (~5.5 wall-h → released), + judge on Anthropic Batch API (0 GPU), + regression fits on 1×A100 / cpu-bigmem. <code>Estimated GPU-hours (total): 20</code>. <br>
<strong>Evaluation:</strong> primary = within-condition Pearson (matched to PV) on held-out contexts (R1: held-out behaviors too); success = R1 beats PV raw by ≥ +0.05 mean within-condition r on ≥2/3 traits (in-behavior, with direct-predictor head-to-head), R2 mean beats it by ≥ +0.10; R3 descriptive. Secondary = AUROC / top-k precision. <br>
<strong>Risks:</strong> (1) linear R1 may reduce to "re-fit a slightly better <code>r_B</code>" (the <code>r̃_B = Mᵀr_B</code> identity) — a possible null, tested empirically in Stage 1; (2) R1 may lack headroom if the prompt state lacks answer-trait content (Step-0 oracle gate quantifies this before any fit, PER TRAIT); (3) LMSYS-Chat-1M is HF-gated <span class="flag">(gated=auto — verify token access; WildChat-1M ungated fallback)</span>.</p>

<h2>1. Goal</h2>
<p>Verbatim from <code>frontmatter.goal</code>:</p>
<blockquote>On Qwen-2.5-7B, characterize how well and at what token granularity the base model's pre-generation context representation predicts its own answer representation and behavior (at the single-context/single-answer per-example level), and test whether routing trait-expression monitoring through a learned behavior-agnostic context-&gt;answer-profile map (pre-generation) or pooling over the actual generation's activations (post-generation) beats Persona Vectors' last-prompt-token projection baseline AND a matched-capacity direct context-&gt;behavior predictor, on held-out contexts and behaviors.</blockquote>
<p>Persona Vectors (arXiv 2507.21509) monitors a trait by projecting the last-prompt-token activation onto a persona vector, <code>⟨c_last, r_B⟩</code>, predicting the response's trait score. Their <em>overall</em> correlations are strong (r=0.75–0.83) but their <em>within-condition</em> correlations — the operationally relevant regime, "among prompts of the same type, which one produces a more evil response" — collapse (evil 0.511, hallucination 0.245 for system-prompt elicitation). This task has two halves under one umbrella: (i) a <strong>characterization</strong> — how well and at what token granularity a single prompt's pre-generation state predicts its single answer's representation (R3) — and (ii) a <strong>monitoring</strong> test of two ways to sharpen the trait read (R1 pre-generation learned map; R2 post-generation pooling), each judged against PV's raw projection AND a matched-capacity direct context→behavior predictor. Everything operates at the single-context/single-answer (per-example) level — the theory's condition-mean is the aggregate these single-level results average up to. Both R1 and R2 are direct instantiations of assumptions in the project's leakage-theory paper (§2), so a positive result advances both the monitoring application and the theory that underwrites the whole leakage-prediction program.</p>

<p><strong>What each positive result buys the theory.</strong> A positive R1 = direct empirical support for A4's non-trivial content (pre-generation context state carries recoverable answer-profile information beyond the raw projection) AND, if nonlinear beats linear, evidence the map is genuinely nonlinear at the single-context level. A positive R2 supports A2+A3 (the mean-response summary linearly encodes the trait) and, if MAX≠MEAN, refines A2's choice of summary operator. R3 is the direct A4 characterization the paper flags as "easy to test, gives layer information": how well and at what granularity the context predicts the answer. The Step-0 oracle gate (<code>⟨v(x),r_B⟩</code> vs trait, within-condition) is precisely the paper's A2/A3 "worth testing right now" check.</p>

<p><strong>Literature-review verdict:</strong> the closest published formalization of R1/R3 is the Future-Lens / tuned-lens / patchscopes "predict downstream state from an earlier hidden state" family — but that family predicts LATER-LAYER / next-TOKEN state at the SAME position, whereas R1/R3 predict a later-POSITION answer profile from an earlier-POSITION pooled context, which is harder and (for R3(b)) is forecasting a stochastic trajectory (§8). <h2>3. Hypothesis + falsification (per result)</h2>

<h3>R1 — pre-generation learned map + direct-predictor comparison</h3>
<ul>
<li><strong>H1 (map beats raw):</strong> a learned behavior-agnostic map <code>h</code> improves within-condition trait prediction over PV's raw <code>⟨c_x, r_B⟩</code>. <strong>Confirm:</strong> mean within-condition Pearson of <code>⟨h(c_x), r_B⟩</code> exceeds PV raw by ≥ +0.05 (bootstrap 95% CI excludes 0) on ≥2 of 3 traits (in-behavior split). <strong>Falsify:</strong> no improvement (Δ CI includes 0) on ≥2 of 3 traits — the prompt state carries no recoverable answer-profile signal beyond the raw projection.</li>
<li><strong>H1-direct (does the detour earn its keep — the pivotal test):</strong> routing through the profile map beats a matched-capacity DIRECT context→behavior predictor <code>g: c_x → trait</code> (ridge vs ridge, MLP vs MLP). <strong>In-behavior:</strong> <strong>Confirm</strong> indirect <code>h</code> ≥ direct <code>g</code> within CI on ≥2 traits (the map adds value even when you have the behavior's labels); <strong>Falsify</strong> direct <code>g</code> matches or beats indirect <code>h</code> — the profile detour earns nothing in-behavior, and the map's ONLY value is zero-shot transfer. <strong>Held-out-behavior (leave-one-behavior-out):</strong> the direct predictor is <strong>structurally inapplicable</strong> (it needs labels for the eval behavior); only <code>h</code> (via <code>Mᵀr_B</code>, zero-shot) and PV raw compete. <strong>Confirm</strong> <code>h</code> beats PV raw on held-out behaviors by a positive margin (CI excludes 0). This is where the behavior-agnostic map's value proposition lives.</li>
<li><strong>H1b (linear vs nonlinear, the A4 sub-test):</strong> a nonlinear <code>h</code> (MLP / kernel-ridge) beats a linear <code>h</code> (ridge) by ≥ +0.03 within-condition r. <strong>Falsify:</strong> ridge ≈ MLP (Δ CI includes 0) — the context→profile map is effectively linear at the single-context level.</li>
<li><strong>H1-nullity (the linear-fold degeneracy — a FIRST-CLASS falsification, see §8):</strong> in the LINEAR case, <code>⟨M c_x, r_B⟩ = ⟨c_x, Mᵀ r_B⟩ = ⟨c_x, r̃_B⟩</code>, so linear R1 is <em>algebraically</em> a plain projection of <code>c_x</code> onto a re-derived direction <code>r̃_B</code>. <strong>Prediction to test empirically in Stage 1:</strong> the linear-R1 within-condition r equals the r of a direct ridge probe <code>c_x → trait</code> re-expressed as a single direction (i.e. linear R1 ≈ the trait-fit linear probe, §5). <strong>If confirmed (they match):</strong> the linear R1 arm is a NULL — it is "did we find a slightly better <code>r_B</code>," not "does the profile map help," and the interesting arm is strictly the NONLINEAR <code>h</code> (H1b) + the zero-shot behavior-agnostic transfer (H1-direct held-out). We report this transparently rather than dressing a re-derived direction as a map win.</li>
</ul>

<h3>R2 — post-generation pooling</h3>
<ul>
<li><strong>H2 (pooling beats prompt projection):</strong> pooling the projection over the actual generation beats PV's prompt projection. <strong>Confirm:</strong> best pooling (mean/max/top-k/last × layers) mean within-condition r exceeds PV raw by ≥ +0.10 on ≥2 of 3 traits. <strong>Falsify:</strong> no pooling beats the prompt projection — the generation carries no trait signal the prompt lacks (implausible; a near-tautological ceiling, so a falsification here would flag a rig bug).</li>
<li><strong>H2b (max vs mean, the A2 summary-operator sub-test):</strong> MAX pooling beats MEAN as a <em>detector</em> (higher AUROC / top-k precision) while MEAN wins the aggregate within-condition Pearson. <strong>Falsify:</strong> MEAN dominates both metrics — no localized-spike advantage, and A2's mean summary is also the best detector.</li>
</ul>

<h3>R3 — context→answer map granularity (descriptive; no beat-threshold)</h3>
<ul>
<li><strong>H3a (reconstruction):</strong> <code>h</code> reconstructs the mean-response activation with R² well above a shuffled-context null (mean→mean and pooled→pooled). <strong>Report:</strong> per-layer R²/cosine; the fraction of <code>r_B</code> lying in the top-k profile PCA subspace (the A1/A2 low-rank test). <strong>Falsify (as an A4 result):</strong> R² ≈ shuffled null — the context does not linearly/nonlinearly determine the answer profile.</li>
<li><strong>H3b (per-position decay):</strong> pooled-context → per-relative-position answer-activation predictability is highest early in the answer and <strong>decays with answer depth</strong>. <strong>Report:</strong> the decay curve (predictability vs relative position) and a decay constant if the curve is monotone-fittable; measured as EXPECTED per-position predictability over the answer-averaged expectation, NOT a single stochastic sample (caveat §8). <strong>Falsify:</strong> flat curve — the context determines the whole answer equally (surprising) or none of it.</li>
<li><strong>H3c (set-to-set):</strong> context-activation-SET → answer-activation-SET CKA + linear predictability is above a shuffled null and varies interpretably by layer-pair (e.g. peaks along the diagonal / mid-late layers). <strong>Report:</strong> per-layer-pair CKA heatmap + linear-predictability R². <strong>Falsify:</strong> CKA ≈ null everywhere — no set-level correspondence.</li>
</ul>

<h3>Step-0 gate (the oracle headroom test — PER TRAIT)</h3>
<p>Before fitting <code>h</code>: compute the oracle <code>⟨v(x), r_B⟩</code> (R2 mean) vs PV raw <code>⟨c_x, r_B⟩</code> within-condition, ALL layers, PER trait. If the oracle beats PV raw by ≥ +0.05 within-condition <em>for a given trait</em>, that trait has R1 headroom; if not, that trait has no gap for <code>h</code> to close and its R1 arm is descoped to ridge-only + reported "no oracle headroom." This is a PER-TRAIT science gate (§7), not a whole-plan compute kill — see the mixed-headroom decision rule.</p>

<h2>4. Design</h2>

<h3>4.0 Why code, not a model call?</h3>
<p>R1's <code>h</code>, the direct predictor <code>g</code>, and every read-out are numeric regressions / dot products over cached activation tensors — no unstructured-data heuristic. The one model-call-vs-code decision is the trait scorer: it scores unstructured generated text for a behavior, and per project policy (llm-judging.md, no-substring-match) it MUST be a Claude judge, not a code heuristic. So: <strong>judge = model call</strong> (Sonnet graded 0–100 via Batch API); <strong>everything else = code</strong> (deterministic, vectorized over tensors; the h-fit needs closed-form ridge / batched SGD a model call cannot provide). No other unstructured-data heuristic in the design.</p>

<h3>4.1 Data source + realism tier</h3>
<ul>
<li><strong>r_B extraction data:</strong> the paper's released trait definitions + generated system-prompt/question artifacts, regenerated per persona-vectors-recipe.md from the trait name+description via the Sonnet generator (PV released code + trait defs, not the vectors). <strong>Tier 2</strong> (the paper's released data).</li>
<li><strong>Eval contexts (the DV distribution):</strong> PV's 8-way system-prompt sweep + 0/5/10/15/20-shot, verbatim — the 8 system prompts per trait fetched verbatim from arXiv App. this session (§2.2) and stored in the config, never paraphrased. <strong>Tier 2</strong> (the paper's released monitoring corpus).</li>
<li><strong>Training contexts for <code>h</code> and <code>g</code>:</strong> LMSYS-Chat-1M (real user prompts — <strong>tier 1, real-world data</strong>). Fallback if inaccessible under our token: WildChat-1M (real user conversations, ungated — tier 1) or UltraChat-200k (tier 2, #594 precedent). Hard invariant: the exact PV eval monitoring contexts are held out from <code>h</code>/<code>g</code> training in ALL corpus arms.</li>
</ul>
<p><strong>Contrastive-negatives / on-policy-completions rules: N/A — monitoring experiment, not behavior implantation. No LoRA, no fine-tuning of Qwen.</strong> (The <code>r_B</code> extraction's pos/neg system-prompt structure is governed by persona-vectors-recipe.md, and its rollouts are on-policy by construction — sampled from the model under the contrastive system prompts.)</p>

Total well under the 50 GB VM footprint; between-phase <code>clean_experiment_downloads.py 779 --incremental --apply</code>.</p>

<p>The run is a staged pipeline &gt; 4 wall-h with a genuinely uncertain headline (no prior established R1's direction at this rig), and two cheap intermediate signals each rule out expensive downstream work — so gates are warranted, kept minimal (two, jointly satisfiable, each with a grounded sign):</p>

<ul>
<li><strong>R1 primary (in-behavior):</strong> <code>⟨h(c_x),r_B⟩</code> beats <code>pv_raw</code> by ≥ +0.05 mean within-condition r (CI excludes 0) on ≥2/3 traits, with the direct-predictor head-to-head reported (H1-direct).</li>

<h3>Gates + kill criterion (PER-TRAIT descope, NOT jointly-unsatisfiable)</h3>

<li><strong>Gate 1 — rig-validation halt:</strong> if reproduced <code>pv_raw</code> within-condition r is &gt; 0.10 off the PV published table, the rig/extraction diverged → halt Stage 2, diagnose the extraction (do NOT report gains against a broken baseline).
