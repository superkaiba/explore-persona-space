# Maintain living one-pager summary of the entire EPS project

A standing, living document — not a one-shot deliverable.

## What it contains

- **Where the project stands today** — 1 paragraph.
- **Clean results to date** — table of task # → one-sentence claim → confidence,
  ordered by recency.
- **Open threads** — what's running, what's queued, what's blocked.
- **Implications so far** — what each cluster of results suggests about
  the persona-space program (geometry, localization, propagation, defense, etc).
- **Where the project is heading** — next 2-4 weeks of focus, named.
- **Positioning against the two sibling papers** (Persona Vectors,
  Persona Features Control EM) — what EPS uniquely contributes.

## Use cases

- Mentor updates (Dan, Yoshua, Guillaume) — paste-and-edit starting point.
- Self-orientation when returning from travel / context-switch.
- Onboarding a collaborator or visitor (Christina, possible new mentees).
- Paper-narrative scaffolding when EPS becomes a paper.

## Cadence

Update whenever a clean result lands (so it stays current).
Probably re-paired with the weekly digest cron.

## Why a task and not just a doc

Tracking it as a task makes the maintenance visible. Output is a living doc
(probably `docs/project_summary.md`); the task is the commitment to keep it
current and the trigger to flag staleness.

## Next concrete action

Write the v1 draft (~1 hour of focused writing) seeded from
clean-results in `tasks/awaiting_promotion/` + `tasks/completed/`.
