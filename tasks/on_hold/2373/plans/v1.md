### 4.1 Arm (a) — sidecar capture (`src/explore_persona_space/analysis/paper_plots.py`)

**New helper 1 — per-axes raster metadata** (placed after `_axes_text_and_series`):

```python
def _axes_image_shapes(ax) -> dict[str, object]:
    """Heatmap-raster metadata for ONE Axes' sidecar text entry (#2373).

    Returns {} for a colorbar axes (``ax.get_label() == '<colorbar>'``), an
    axes with no raster artists, or on ANY exception — best-effort, never
    raises (the ``_extract_fig_text`` contract). Keys (all emitted together,
    only when >=1 raster artist is captured):
      image_rows / image_cols : list[int], per artist (AxesImage subclasses
          from ``ax.get_images()`` via ``get_array().shape[:2]``; QuadMesh
          from ``ax.collections`` via its 2-D ``get_array().shape`` — a 1-D
          QuadMesh array is skipped)
      image_kinds     : list[str], "image" | "quadmesh" (parallel)
      image_yextents  : list[[float, float]], sorted [ymin, ymax] per artist
          (imshow: ``im.get_extent()[2:]``; quadmesh: min/max of
          ``get_coordinates()[..., 1]``)
      n_yticklabels   : int — PRE-cap count of non-empty y tick label texts
      yticks_fixed    : bool — y major locator is a ``FixedLocator``
      n_ytick_positions : int — ``len(locator.locs)`` (only when yticks_fixed)
      yticks_unit_spaced : bool — all consecutive position diffs == 1.0,
          requires >= 2 positions (only when yticks_fixed)
    """
```

Implementation notes (all probe-verified on the pinned matplotlib 3.10.8, §12):
- Colorbar screen: `fig.colorbar` axes carry `get_label() == '<colorbar>'` (public API; `_colorbar` attr exists too but is private). Colorbar solids are a 256×1 QuadMesh with real tick labels — unscreened, they would be the dominant false-positive surface.
- `set_yticks(...)` installs `FixedLocator` (probe: `normal locator: FixedLocator locs: [0..4]`); the FORMATTER after `set_yticklabels` is `FuncFormatter` on 3.10.8, NOT `FixedFormatter` — the explicit-ticks predicate therefore keys on the LOCATOR only.
- Body wrapped in one `try/except Exception: return {}` — hard constraint 4 (never sink a save).

**New helper 2 — y-sharing groups** (placed after `_axes_image_shapes`):

```python
def _sharey_groups(axes: list) -> dict[int, int]:
    """Map ``id(ax)`` -> group id for axes sharing a y-axis with >=1 OTHER
    axes in ``axes`` (``ax.get_shared_y_axes().get_siblings(ax)`` — public
    GrouperView API; a singleton's siblings == [itself]). Group ids are
    assigned in ``axes`` order. Best-effort: {} on any exception."""
```

**Call-site edits:**
- `_axes_text_and_series` (after the tick-label loop, before the series-label block): `ax_d.update(_axes_image_shapes(ax))`. One line — minimizes the #2450 merge surface.
- `_extract_fig_text` (loop over `fig.get_axes()`): compute `gids = _sharey_groups(fig.get_axes())` once before the loop; after `ax_d, labels = _axes_text_and_series(ax)`, add `if "image_rows" in ax_d and id(ax) in gids: ax_d["sharey_group"] = gids[id(ax)]`. `sharey_group` is scoped to image-bearing entries (keeps non-heatmap sidecars byte-stable minus nothing).
- Docstring updates (docstring-on-edit rule): `_extract_fig_text`'s value-shape sentence widens from "str / None / list" to "str / None / bool / int / list (of scalars or [float, float] pairs) — never dict-valued", with a note that bools/ints cannot match the dashboard resolver's `isPlainObject` fallback (`dashboard/lib/task-data.ts` descends only plain objects) and that `verify_task_body._flatten_meta_strings` drops numeric/bool leaves by design (verified read, §12 A-9). `savefig_paper`'s docstring gains one sentence naming the heatmap-shape keys.

### 4.2 Arm (b) — the gate (`scripts/verify_report.py`)

**Pure predicate core** (unit-testable, corpus-scannable):

```python
def _heatmap_violations(meta: dict) -> tuple[list[str], list[str]]:
    """(violations, skip_notes) for ONE parsed sidecar dict. Reads
    ``meta["text"]["axes"]``; entries without ``image_rows`` are ignored
    (legacy / non-heatmap). Never raises on malformed shapes — a
    wrong-typed field becomes a skip note."""
```

Predicates, exactly:
- Per axes entry `e` with `image_rows`: `common_rows` = the single value when all of `image_rows` agree, else skip-note `heterogeneous image rows` (that axes is excluded from BOTH arms).
- **(i) tick-correspondence:** violation iff `e.get("yticks_fixed") is True` AND `e.get("yticks_unit_spaced") is True` AND `isinstance(e.get("n_ytick_positions"), int)` AND `e["n_ytick_positions"] >= 2` AND `common_rows is not None` AND `common_rows != e["n_ytick_positions"]`.
- **(ii) shared-y siblings:** group entries by `sharey_group` (int); for each group with >= 2 entries carrying a `common_rows`: let each entry's y-extent be the sorted pair (require all artists within the axes to agree within rtol 1e-6, else skip-note). Violation iff row counts across the group are NOT all equal AND the y-extents are NOT all equal (rtol 1e-6) — the equal-extent case is the legitimate resolution-difference exemption, emitted as a skip-note. ADDITIONALLY a violation iff row counts ARE equal but y-extents differ (same crop mechanism, equal-count variant; recorded as an extension beyond the criterion letter, §11 item 4).

**Check function:**

```python
def check_heatmap_ytick_consistency(
    blanked_body: str, *, mode: str, figures_root: Path
) -> CheckResult:
    """``heatmap-ytick-consistency`` (#2373, from #2329 round 1). ..."""
```

- Targets: `_images_in(blanked_body)`, deduped in order. Per target: `_RAW_PIN_RE` match → repo-relative path = group 4; else a non-URL (`"://" not in target`) relative path is used as-is; other URLs skipped. Only `.png`/`.pdf` targets considered; sidecar = `(figures_root / rel).with_suffix(".meta.json")` — the same suffix arithmetic `savefig_paper` uses (`target.with_suffix(".meta.json")`).
- Sidecar read is from the WORKING TREE (mirrors `figure-files-exist`; rationale §11 item 6). Ladder per sidecar: missing → note; JSON parse error → note; no `text`/`axes` → note; no `image_rows`-bearing entry → note ("predates image-shape capture" — the criterion-5 arm). Then `_heatmap_violations(meta)`.
- Verdict: no heatmap-bearing sidecars at all → `CheckResult(..., True, "no heatmap-bearing sidecars (N/A); <k> skipped: ...")`. Any violation → `passed=False` in `generation`; `passed=True, is_warn=True` in `promote`. Detail names, per violation, the figure stem, the axes' position in `text.axes`, its title/ylabel when present, and the numbers (`rows=39 != ytick_positions=37`; `sharey group 0 rows {39, 37}, y-extents differ`).
- Wiring in `verify_report_text` (line 2091 region), after the `check_image_pins` extend: `results.append(check_heatmap_ytick_consistency(blanked_body, mode=mode, figures_root=figures_root))`.
- Module docstring: add a `heatmap-ytick-consistency` entry to the documented check list with its full degrade ladder (missing/legacy sidecar → skip-note both modes; violation → FAIL generation / WARN promote).

## 11. Decision Rationale

1. **Sidecar key placement + shape** — *What:* nine flat keys inside the existing `text.axes[*]` per-axes dicts (lists of scalars, ints, bools, `[float, float]` pairs; never dict-valued). *Why:* alignment with the very `yticklabels` list the gate compares against is by construction (the task's biggest structural hole was relating image shapes to axes entries in a flat list); flat scalar shapes preserve the `_extract_fig_text` value contract that keeps the dashboard resolver's object-of-objects fallback unmatchable. *Source:* `_extract_fig_text` docstring contract (paper_plots.py:1304–1320, #1255) + `_flatten_meta_strings` tolerance read (verify_task_body.py:9869–9903). *Alternatives:* a parallel top-level `meta["image_shapes"]` list (rejected: re-introduces the alignment problem — `text.axes` drops empty entries, so indices would not correspond); a dict-per-artist `images: [{...}]` (rejected: introduces the first dict-valued ax_d key; parallel scalar lists carry the same information).
2. **Severity: FAIL at generation / WARN at promote (recommendation: KEEP the mode split as forward protection).** *What:* violation → FAIL only in `--mode generation`; WARN at `promote`; skips never FAIL. *Why:* the measured baseline (0 possible legacy trips) means the split is not needed for the CURRENT corpus, but it is the right FORWARD posture: at generation the figures were just rendered by live plotter code (post-arm-(a)), so a mismatch is an actionable fresh defect; at promote the render is historical — a report generated before this gate landed (or whose figures drifted, which `image-pin-blob-identity` already owns) should surface the finding to the promoter without wedging promotion, exactly the `image-pin-blob-identity` blob-mismatch ladder. *Source:* the mode-split precedent in `verify_report.py`'s module docstring (`image-pin-blob-identity`: "blob mismatch → FAIL in generation / WARN in promote"); criterion 4's own text; #1388 (fleet-wedge shape). *Alternatives:* FAIL-both (rejected: retroactively punishes pre-gate reports at promote — the wedge shape); WARN-both (rejected: the #2329 class shipped a reader-facing inverted figure past 20/20 PASS — generation needs teeth).
3. **The `_MAX_TEXT_ITEMS` interaction → compare FixedLocator POSITION COUNT, not the label list.** *What:* arm (i) compares `n_ytick_positions` (`len(FixedLocator.locs)`, recorded pre-truncation at capture time) against the row count; the sidecar's `yticklabels` list (still capped at 100) is never the comparison operand. *Why:* matplotlib itself enforces `len(labels) == len(FixedLocator.locs)` at `set_yticklabels` time, so the position count IS `len(yticklabels)`-as-passed — robust to (a) the 100-item sidecar cap (a 128-row per-row-labeled heatmap: positions 128 == rows 128 → PASS, where the truncated list would false-fire 100 != 128), and (b) the label-blanking density trick (`set_yticklabels([lab if i%5==0 else "" ...])` — non-empty text count 20, positions 100 == rows 100 → PASS, where the non-empty count would false-fire). *Source:* the orchestrator's `_MAX_TEXT_ITEMS` brief + matplotlib 3.10 `Axis.set_ticklabels` contract (raises on length mismatch with the FixedLocator); probe confirming `FixedLocator.locs` accessibility. *Alternatives:* comparing `len(yticklabels)` with a `>= 100` carve-out (rejected: still breaks on blanked labels and is cap-arithmetic-fragile); recording the untruncated label LIST (rejected: unbounded sidecar growth on dense heatmaps — the cap exists for a reason).
4. **Arm (i) scope guard: unit-spaced fixed ticks only; arm (ii) extent exemption + extension.** *What:* (i) fires only when the fixed y-tick positions are unit-spaced (≥ 2 positions) — the per-row labeling convention (integer rows for imshow, +0.5 offsets for pcolormesh both have unit spacing); sparse every-k-th labeling (spacing k ≠ 1) never fires. (ii) fires on unequal sibling row counts only when y-extents ALSO differ; equal-extent unequal-rows (two resolutions of the same continuous y range) is exempt with a note; equal-rows/unequal-extents fires too (same crop mechanism). *Why:* these are the two false-positive classes a bare count comparison cannot survive (sparse labeling is common; equal-extent multi-resolution panels are legitimate), and both screens are groundable in the render geometry: the #2329 crop happens exactly when the SECOND panel's extent+ticks win a shared axis whose FIRST panel drew a different geometry. *Source:* the #2329 memo's mechanism write-up (`extent` + `set_yticklabels` clobber; "unequal-row shared-y panels are presumptively broken") + the probe's reproduction (clobbered shared locator: 37 positions on BOTH panels; extents (−0.5, 38.5) vs (−0.5, 36.5)). *Alternatives:* a density-ratio threshold (`n_labels/n_rows > 0.8`) — rejected: an ungrounded tuned constant; raw criterion-letter predicates — rejected: false-FAIL channels (kill-criterion 2 territory).
5. **Sharey detection at CAPTURE time via the Grouper, recorded as `sharey_group`.** *What:* arm (a) records the sharing relation (design question 1's resolution): per-figure group ids over `ax.get_shared_y_axes().get_siblings(ax)` (public `GrouperView`), emitted only on image-bearing entries. *Why:* the sidecar records no axes geometry/identity, and inferring sharing at verify time (from tick-count coincidences) is exactly the fragile guess the task exists to remove; the capture side has the live `Figure` where sharing is a one-call fact. Probe: `joined(ax0, ax1) is True` for `plt.subplots(sharey=True)`; singleton `joined(ax, ax) is False`, `get_siblings == [self]`; `twiny()` pairs are y-joined (accepted — same clobber geometry, §8). *Source:* matplotlib 3.10.8 probe (this plan); the #2329 round-2 durable-prevention pattern (realized-`get_yticklabels` guard) as the sibling in-plotter mechanism. *Alternatives:* recording subplot geometry (`get_subplotspec`) and inferring sharing at verify time (rejected: geometry ≠ sharing; twinned/gridspec cases diverge); a fig-level `sharey_pairs` list outside `text.axes` (rejected: alignment problem again).
6. **Working-tree sidecar read in the verifier.** *What:* the check reads `figures_root/<rel>.meta.json` from the working tree, not `git show <pin-sha>:<path>`. *Why:* at generation the working tree IS the just-created pin (the only mode that FAILs); at promote, tree-vs-pin drift is `image-pin-blob-identity`'s job, and this check is WARN there anyway; working-tree reads keep the check network- and object-DB-free, the `check_image_files` posture. *Source:* `check_image_files` (verify_report.py:627) + `_read_figure_meta_text`'s git-show variant in verify_task_body.py:9905 (considered, not copied — that check verifies HISTORICAL bodies where the pin is the record). *Alternatives:* git-show at the pin sha (rejected: adds an unresolvable-commit degrade ladder for no additional catch at generation time).
7. **Tool-behavior claims** in this plan (locator/formatter classes, grouper API, colorbar label, QuadMesh shapes, sharey label emptying, `_flatten_meta_strings` tolerance, check idiom) each carry a Source in §12 — probe script output (2026-08-28, this session) or a `grep -n`/read of the named file:line.
