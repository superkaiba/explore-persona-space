### 3. Requirement + acceptance criteria (infra — replaces Hypothesis)

**R1 — sound adaptive switch in `api_dispatch`.** During a batch-path wave, the dispatcher periodically compares a projected batch finish (from the ended-sub-batch rate — the sound wave-grain signal) against a projected sync finish (measured throughput constant × remaining items × orgs), and when sync is materially better (hysteresis margin + minimum absolute advantage + minimum observation window + `cost_pref` gate + at-most-once), it cancels the remaining sub-batches org-aware, harvests partials (succeeded rows KEPT), and dispatches only the uncompleted remainder sync, merging into one complete result dict.

#### 4.1 The sound progress estimator (the crux)

Evaluated once per poll sweep in `_dispatch_batch` (after the per-sub-batch poll pass, before the sleep), as a PURE function for testability:

```python
@dataclass
class AdaptiveSwitchDecision:
    switch: bool
    reason: str                 # "eta" | "stall" | "wedge" | "no-switch: <why>"
    elapsed_h: float
    n_ended: int                # sub-batches with status == "collected"
    n_total: int
    n_pending_items: int        # sum(sb["n_requests"] for non-collected sb)
    batch_eta_h: float | None   # None == NO INFORMATION (n_ended == 0) — never 0, never inf
    sync_eta_h: float
    sla_residual_h: float

def _evaluate_adaptive_switch(state, *, cost_pref, n_orgs, now_fn) -> AdaptiveSwitchDecision:
```

- **Anchor:** `elapsed_h = now_fn() − min(parse_batch_submitted_at(sb["submitted_at"]) …, fallback state["created_at"])`.
- **Rate basis (sound):** `n_ended` = count of `status == "collected"` sub-batches — measured off the batch's own `processing_status → "ended"` transition (`_poll_one_sub_batch_step` harvests + marks `collected` in the same sweep it observes `ended`). This is the sub-batch-grain rate the clarifier names sound. NO read of `request_counts.succeeded` anywhere.
- **Batch ETA:** `None` if `n_ended == 0` (no information — R2); else `elapsed_h × n_not_ended / n_ended` (remaining ÷ realized ended-per-hour rate).
- **Sync ETA:** `n_pending_items / (rate_per_org × n_orgs) / 60` with `rate_per_org = EPS_SYNC_ETA_RPM_PER_ORG` (default 400 items/min/org — §11). `n_pending_items` is an upper bound on remaining work (per-item completeness inside an in-flight batch is unknowable soundly); the org rate limits are embodied in the constant, which was measured through this dispatcher's own polite-cap AIMD path (#2223 pilot).
- **SLA residual:** `max(deadline − now)` over non-collected sub-batches (deadlines from `expires_at` + grace where known, else `24 h + BATCH_DEADLINE_GRACE_MIN − elapsed`, floored at 0).

**Switch predicate** (all knobs resolved per-call from env, mirroring `batch_stuck_threshold_hours`' read-per-poll pattern):

```
margin = adaptive_margin()                      # EPS_BATCH_ADAPTIVE_MARGIN, default 2.0; <=0 -> whole feature OFF
already_switched  -> no (at-most-once: state["adaptive_sync"] present)
elapsed_h < EPS_BATCH_ADAPTIVE_MIN_WINDOW_H (1.0) -> no

Arm A ("eta", latency/balanced only, n_ended >= 1):
    batch_eta_h >= margin * sync_eta_h
    AND batch_eta_h - sync_eta_h >= ADAPTIVE_MIN_ABS_ADVANTAGE_H (0.5, module constant)

Arm B ("stall", latency/balanced, n_ended == 0):
    stall_h = batch_stuck_threshold_hours()     # SAME knob as the judge escapes; None (<=0) disables this arm
    elapsed_h >= stall_h  AND  margin * sync_eta_h < sla_residual_h

Arm B' ("wedge", cost_pref == "cost", n_ended == 0 only):
    elapsed_h >= EPS_BATCH_WEDGE_HOURS (8.0; <=0 disables)  AND  margin * sync_eta_h < sla_residual_h
    (cost pref NEVER switches on Arm A — the ETA comparison trades cost for latency,
     which "cost" explicitly declined; only the empirically-wedged shape switches.)
```

**Why Arm B does not violate the #2426 corollary:** "0 of N sub-batches ended in W hours" is a MEASURED statement about a sound signal (the `ended` transition), not an unmeasurable value promoted to a null. What stays honest is its interpretation: it does not measure within-batch progress — a wave can be 99% internally done with 0 ended. The design is safe under exactly that case because the remedy harvests first: every row the batch completed comes back `succeeded` in the post-cancel harvest and is KEPT; only genuinely-unfinished (`canceled`/`expired`/server-`errored`) rows re-dispatch sync. A maximally mistimed Arm B fire on the #823 shape costs re-dispatching 3 of 1,000 rows.

#### 4.2 Switch execution — `_execute_sync_switch` (crash-safe, org-aware, remainder-only)

Threaded new params into `_dispatch_batch` (all internal underscore signatures): `cost_pref`, `async_clients`, `cap` (already computed in `_dispatch_calls_inner` l.1686), `max_attempts`, `max_429_retries`. Sequence:

1. **Persist wave intent FIRST** (the #1019 intent-first contract at wave grain): `state["adaptive_sync"] = {"intent_at", "reason", "elapsed_h", "n_ended", "n_pending_items", "batch_eta_h", "sync_eta_h", "cost_pref"}` + flip every `status == "pending"` (never-submitted) sub-batch to `"switched_sync"`; ONE `_atomic_write_json`. Log a WARNING carrying the full decision record + the premium note: `"~{n} items forfeit the 50% batch discount (re-dispatched sync)"` — the sanctioned cost surfacing; NO dollar figures anywhere (constraint 5 / `test_no_dollar_budget_caps`).
2. **Cancel org-aware:** for each non-collected sub-batch with a `batch_id`: `sync_clients[sb["org"]].messages.batches.cancel(sb["batch_id"])` wrapped in the #1019 race guard verbatim (on `APIStatusError`, `retrieve_with_404_tolerance`-confirm; accept `canceling`/`ended`; else re-raise); stamp `sb["switch_canceled_at"]` + persist. Idempotent per sub-batch (skip when stamped).
3. **Poll to ended + harvest:** sweep the canceled sub-batches with the existing retrieve (+404 tolerance) until `processing_status == "ended"`, then the UNCHANGED `_harvest_sub_batch` (persists `results_{batch_id}.json`, marks `collected`; succeeded rows carry parsed results, canceled/expired rows land `error=True, category=RESULT_TRANSPORT`). Outer bound: each sub-batch's own `deadline` → `BatchDeadlineExceeded` preserved as the hard bound. (#810: the flip + harvest measured in minutes.)
4. **Compute the sync remainder:** for each SWITCH-canceled sub-batch, the cids whose harvested record is `error=True ∧ category == RESULT_TRANSPORT`; plus ALL cids of `"switched_sync"` (never-submitted) sub-batches. Explicitly EXCLUDED (conventions preserved): `RESULT_ERROR` rows (quarantined `invalid_request_error` — fails identically on sync), parse-error rows (content-class), `RESULT_EMPTY_RESPONSE` rows (rule-28 caller decision). Rows of sub-batches collected BEFORE the switch keep today's caller-re-drive contract untouched (single-variable change). A remainder cid missing from `items_by_cid` raises the existing partial-sub-batch RuntimeError shape (concurrent-cache-poaching guard, mirroring l.1110-1118).
5. **Dispatch the remainder sync** via `_dispatch_sync` directly (`org_states = {label: OrgState(label, cap)}`, same construction as `_run_sync_path` l.1865) with `on_result` = append one JSON line per completed item to `dispatch_dir / "sync_switch_results.jsonl"` (O_APPEND single-line writes — the code-style checkpoint-per-unit shape). **Deliberately NOT the JudgeCache:** a mid-run cache persist would shrink `pending` on a crash-resume and trip the #1018 `request_fingerprint` ValueError (l.1042-1050). Cache persistence stays where it is today — `_persist_results_to_cache` after `_dispatch_batch` returns (l.1722), which covers the sync-obtained successes too.
6. **Merge + complete:** results = per-collected-sub-batch `results_{bid}.json` via the unchanged `_merge_batch_record` (skipping `"switched_sync"` sub-batches, whose `batch_id` is None) overlaid with the JSONL sync records; stamp `state["adaptive_sync"]["completed_at"]`; return.

**Resume ordering (load-bearing):** at `_dispatch_batch` entry, `state.get("adaptive_sync")` is checked BEFORE the submit-pending block — a resumed run with switch intent must never submit new sub-batches. The completion leg is idempotent end-to-end: re-drives unstamped cancels (step 2 race guard converges), re-harvests only non-`collected`, re-reads the JSONL (text-mode line iteration, never `splitlines()` — gotchas) and sync-dispatches only the residual remainder. A `"submitting"` sub-batch with `batch_id=None` under intent keeps the existing refuse-to-guess RuntimeError (l.1377-1382).

**Precedence order (mirrors #1019's load-bearing ordering):** per-sub-batch: ended-harvest → deadline-overdue → 404-tolerance inside retrieves (all unchanged); wave-level adaptive evaluation runs LAST, after the full sweep. A wave whose sub-batches are already overdue raises `BatchDeadlineExceeded` before any switch evaluation — the deadline stays the hard outer bound.

**`now_fn` consistency fix (required for testability + correctness):** `_submit_one_sub_batch` currently stamps `submitted_at` from the REAL clock (`time.strftime`, l.1143) while the poll loop compares against injectable `now_fn` — under injected test clocks `elapsed_h` would be garbage. Thread `now_fn` into `_submit_one_sub_batch` and stamp `submitted_at` from it (production behavior unchanged: default `now_fn` is real UTC).

If Anthropic ever starts reporting incremental `succeeded`, the time-bound remains safe (cancel harvests what's done) where the OLD predicate would have silently disarmed.

### 11. Decision Rationale

- **`EPS_BATCH_ADAPTIVE_MARGIN = 2.0`** — What: hysteresis factor; switch only when projected batch ETA ≥ 2× sync ETA. Why: a 2× margin keeps the switch non-harmful on wall-clock even under a 2× error in the sub-batch-grain rate estimate. Source: the repo-wide ×2 projection-dispersion default for wall-time estimates (`.claude/rules/plan-compute-sizing.md`, p90 ×2 rule). Alternatives: 1.5 (thrashier under rate noise), 3.0 (leaves #2223-class waves parked longer).
- **Stall window = `EPS_BATCH_STUCK_HOURS` default 4.0 h (reused knob)** — What: Arm B's zero-ended threshold. Why: same construct as the shipped escapes ("how long with zero completions before acting"), now measured on the sound `ended` signal; one knob keeps the three escapes consistent, `<=0`-disable semantics inherited. Source: #1019 plan §11 row 1 (← #810's 16 h wedge); #2223's 11 h wedge would have fired at 4 h.
- **`EPS_BATCH_ADAPTIVE_MIN_WINDOW_H = 1.0`** — What: no switch (either arm) before 1 h elapsed. Why: bounds Arm-A noise from a single fast-ending sub-batch, and normal opportunistic batch scheduling routinely completes waves inside the first hour, where acting forfeits the discount for noise. Source: Anthropic Batch API docs' "most batches complete in under 1 hour" claim (Medium confidence — verify at implementation) + must sit below the 4 h stall default. Alternatives: 0.5 (noisier Arm A), 2.0 (delays clear wins).
- **`EPS_SYNC_ETA_RPM_PER_ORG = 400` items/min/org** — What: sync-ETA throughput constant. Why: grounded on the MOST CONSERVATIVE measured figure — this task's own #2223 pilot through this exact dispatcher (1,255 items/min across 3 orgs ⇒ ~418/org, floored to 400); under-projecting sync speed biases AWAY from switching (safe direction). The doc's ~1.5k RPM/key single-proc plateau (`docs/api_throughput_guidelines.md` l.29/l.64) would give ~3.7× higher. Source: #2223 pilot (300 items, 14.3 s, 0 errors) + `docs/api_throughput_guidelines.md`. Alternatives: 1,500/org (doc plateau — over-eager switching), per-wave live probing (adds spend + complexity for a constant the margin already covers).
- **`ADAPTIVE_MIN_ABS_ADVANTAGE_H = 0.5` (module constant)** — What: Arm A also requires ≥ 30 min absolute projected saving. Why: the switch's own overhead (cancel → flip → harvest) is minutes-scale, and a sub-30-min win doesn't justify forfeiting the discount. Source: #810 measured the full cancel+sync remedy at 18 min for 39,512 calls ⇒ overhead ≪ 0.5 h.
- **`EPS_BATCH_WEDGE_HOURS = 8.0` (cost-pref arm)** — What: cost-pref waves switch only at 0-ended past 8 h. Why: strictly more conservative than the latency stall bound (2× the 4 h default) while still saving ≥ 14 h of a 24 h SLA park on the observed wedge shapes (#810 16 h, #2223 11 h). Source: ungrounded — needs smoke-test (no cost-pref wedge incident exists; the 2× multiplier is a judgment call, flagged in §12).
- **Judge-path predicate = pure latency bound at unchanged 4.0 h** — What/Why/Soundness: §4.3. Source: #2426 (measured falsification of the removed conjunct) + #1019/#810 (the retained threshold + remedy). Practically behavior-preserving since the removed conjunct was ~always true (#2426's measurements).
