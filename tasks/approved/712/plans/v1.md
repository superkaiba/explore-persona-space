## 0.0 TL;DR (plain English)

- **What I'll run:** Nothing trains — this is a fix to how the system writes down lessons from
  crashes. Right now it only records a lesson when a single fix attempt both finds the cause AND
  finishes cleanly. So when an attempt finds the REAL cause but then trips over a different bug,
  the lesson is dropped. On one recent run that meant we permanently saved two wrong guesses about
  a hang and lost the correct explanation. I'll change the rule so finding the true cause is
  enough to record it, and add a way for a corrected lesson to mark the earlier wrong one as
  retracted.
- **What I expect:** A small, additive set of edits to four playbook files plus one helper
  function and one test. Anything written the old way keeps working exactly as before; the new
  lessons can fire earlier and can point back at the mistake they replace.

  have to teach about the new field — but I checked, and nothing in the scripts does; the only
  readers are two human playbooks the system follows.

## 1. Goal

(1) **Root-cause-confirmed firing.** Fire `epm:failure-lesson` capture when a crash-fix round
IDENTIFIES the true root cause, not only when a round both resolves the failure AND its relaunch
succeeds — so a round that finds the real cause but then immediately hits a NEW distinct failure
still produces a durable lesson.

(2) **`supersedes` retraction field.** Add an optional `supersedes:` field to the
`epm:failure-lesson` block so a later corrected diagnosis retracts/annotates the earlier wrong
lesson in the durable record (agent memory + `gotchas.md`) instead of leaving two co-equal,
mutually-contradictory gotchas.

Motivation: the #664 r13 vLLM-hang root cause (per-call `AutoTokenizer.from_pretrained` reloads
inside `_render()`, fixed with `lru_cache`) was never durably captured because r13 immediately
hit the next p2 bug, while the WRONG intermediate "chunk-it" / "fork-EngineCore" mitigations were
promoted to `gotchas.md` with no retraction path.

### (a) `.claude/skills/issue/SKILL.md` § "Failure-lesson capture" — trigger language + supersedes semantics

Two edits in this section (L3769-3826).

**Edit a1 — firing trigger (L3769).** Today the section header gates on "a crash-fix round
RESOLVES the failure." Broaden to fire ALSO on root-cause-confirmed:

```
- **Failure-lesson capture (fires when a crash-fix round RESOLVES the
-   failure).** A lightweight in-flight hook, not a new pipeline step;
+ **Failure-lesson capture (fires when a crash-fix round RESOLVES the
+   failure OR CONFIRMS the true root cause).** A lightweight in-flight
+   hook, not a new pipeline step;
   auto-continue, no gate. ...
+
+   **Root-cause-confirmed firing (added #712).** A round fires this hook
+   in TWO cases: (i) it resolved the failure (relaunch succeeded — the
+   original trigger); OR (ii) it IDENTIFIED the true root cause of a
+   posted `epm:failure` even though a SUBSEQUENT, DISTINCT failure
+   followed in the same or next round (so the relaunch did not yet
+   succeed). Case (ii) closes the #664 r13 gap: the real cause of a
+   multi-relaunch hang was found, but the round immediately hit the next
+   bug, so the "this round resolved X" capture never fired and the WRONG
+   intermediate lessons were the only ones promoted durably. WHO posts
+   it: the agent (experiment-implementer / experimenter) that confirmed
+   the cause emits the block in its report — case (ii) is signalled by
+   `root_cause_confirmed: yes` in the block (see the block schema below)
+   and a `supersedes:` pointer when the confirmed cause corrects an
+   earlier lesson. The orchestrator posts it verbatim on receipt, exactly
+   as it does for the resolve case; it does NOT wait for a successful
+   relaunch.
```

**Edit a2 — supersedes semantics in the post-receipt actions (insert after L3814, action 2).**
The block now may carry `supersedes:`; define the orchestrator's UPDATE-OR-ANNOTATE behavior:

```
+   **`supersedes:` handling (added #712).** If the block carries
+   `supersedes: <prior-lesson-slug-or-marker-ts>`, BEFORE writing the new
+   lesson the orchestrator consults
+   `task_workflow.supersedes_action(prior_ref, durable_files)` (a pure
+   helper, §4e) to locate the prior durable entry (an agent-memory
+   `feedback_<slug>.md` and/or a `.claude/rules/gotchas.md` bullet whose
+   text or slug matches `prior_ref`). For each located entry, the
+   orchestrator UPDATES it in place — prepend a `[SUPERSEDED by
+   <new-lesson-slug> — see #<N>] ` marker to the entry and append a
+   one-line pointer to the corrected lesson — rather than appending the
+   new lesson as a co-equal entry. It then writes the NEW (corrected)
+   lesson alongside via the existing action-2 path. If `prior_ref`
+   resolves to NOTHING in any durable file, the helper returns an empty
+   match set: the orchestrator logs a one-line WARNING in the marker note
+   (`supersedes_unresolved: <prior_ref>`) and proceeds to write the new
+   lesson as an ordinary append — a dangling `supersedes` is a no-op
+   annotation, never a hard failure (a lesson must always land). If
+   `supersedes` is ABSENT, behave exactly as today (append-only).
```

This keeps the firing-WHO decided (the confirming agent emits; orchestrator posts) and the
retraction contract concrete and backward-compatible.

### (e) Pure helper — `src/explore_persona_space/task_workflow.py` (workflow-surface src module)

`task_workflow.py` is explicitly in the workflow surface (CLAUDE.md + workflow-fix-on-bug.md list
it as in-scope despite the general `src/**` exclusion). Add a small, side-effect-free helper that
the orchestrator prose calls and the new pytest exercises:

```python
def supersedes_action(
    prior_ref: str,
    durable_texts: dict[str, str],
) -> dict[str, str]:
    """Locate durable failure-lesson entries a `supersedes` ref points at.

    `prior_ref` is a lesson slug (e.g. ``vllm_large_batch_deadlock_chunk_it``)
    or a marker timestamp (e.g. ``2026-06-28T06:39:12``).
    `durable_texts` maps a durable-file path -> its current text
    (agent-memory feedback_*.md bodies + gotchas.md). Pure: no I/O, no writes.

    Returns {path: annotated_text} for every file whose text matches
    `prior_ref` (slug substring OR marker-ts substring), with a
    ``[SUPERSEDED by <pending> — see superseding lesson] `` marker prepended
    to the matched entry. Returns {} when nothing matches (caller logs
    `supersedes_unresolved` and proceeds append-only). The caller writes the
    returned text + the new lesson; this helper only DECIDES + ANNOTATES.
    """
```

The helper is the single tested seam. The orchestrator prose performs the file writes (it already
owns commit-by-explicit-path + push for the action-2 memory write); the helper isolates the
match-and-annotate logic so the two-round fixture can assert it without simulating an orchestrator.

**Why code, not a model call?** The supersedes match-and-annotate is a deterministic
string-locate + prepend over a small known set of durable texts — exactly the determinism /
testability case for a code path. A model call here would be non-deterministic and untestable,
defeating acceptance criterion 1. (CLAUDE.md "Model call vs code".)

## 7. Risks and Failure Modes

| Risk | Likelihood | Mitigation |
|---|---|---|
| Consumer is prose, not a script → supersedes behavior untestable, fixture impossible | High if not designed for | Extract the match-and-annotate DECISION into the pure `supersedes_action()` helper (§4e); the prose calls it, the pytest asserts it |
| `supersedes:` cites a slug/ts absent from any durable record | Medium | Helper returns `{}`; orchestrator logs `supersedes_unresolved` in the marker note and proceeds append-only — a dangling ref is a no-op annotation, NEVER a hard failure or dropped lesson |
| `supersedes` CHAINS (A←B, B←C) | Low | Keep all in history (transitive, no collapse): each correction annotates only the entry its `supersedes` directly names; the chain reads A `[SUPERSEDED by B]`, B `[SUPERSEDED by C]`, C live. Collapsing would lose the audit trail of how the diagnosis evolved (the whole point of #712). Stated explicitly in the SKILL.md prose. |
| Same incident re-emitted by BOTH implementer AND experimenter | Low | Dedup is `/daily`'s existing job (it "dedupes the day's lessons against the owning agent's memory — merge duplicate/overlapping entries"); the supersedes prose adds "respect supersedes — do not un-retract". Same-day double-emit without supersedes is the pre-existing behavior, unchanged. |
| Over-scoping into the consolidator | Medium | Keep the `/daily` edit to ONE sentence (respect supersedes); do not rewrite the consolidation pass. |
| `--emit-tables` not run → `--check-tables` fails the commit | Medium | Implementer runs `--emit-tables` after the workflow.yaml edit; named explicitly in §4c + §6. |
| Block-template drift between the two agent specs | Low | Both specs get the identical two-field block addition; §4b shows both diffs. |
