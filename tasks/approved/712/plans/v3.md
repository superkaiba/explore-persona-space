## 0.0 TL;DR (plain English)

- **What I'll run:** Nothing trains — this is a fix to how the system writes down lessons from
  crashes. Right now it only records a lesson when one fix attempt both finds the cause AND then
  relaunches cleanly. So when an attempt nails the real cause but the run can't finish on that
  machine (we had to throw the machine away and start fresh), the lesson never gets written down.
  On a recent run that's exactly what happened: the team figured out a hang was the physical
  machine's fault, not the code's — and that finding was never saved for the next person. I'll
  change the rule so finding the true cause is enough to record it, even when the run didn't get
  to finish.

  functions and one test file. Anything written the old way keeps working byte-for-byte; the new
  lessons can fire earlier, and a corrected lesson can mark an earlier wrong one as retracted so
  we don't leave two contradictory notes side by side.
- **What would change my mind:** If something actually reads these lesson notes in code that I'd
  have to teach about the new fields — but I checked, and nothing in the scripts does; the only
  readers are two human playbooks the system follows. The new helpers I'm adding are the first
  code that touches this data, and they're pure (no file writes), so a test can pin them exactly.

(1) **Root-cause-confirmed firing.** Fire `epm:failure-lesson` capture when a crash-fix round
IDENTIFIES the true root cause, not only when a round both resolves the failure AND its relaunch
succeeds — so a round that finds the real cause but then CANNOT complete (a new distinct failure,
or a recovery that abandons the current pod) still produces a durable lesson.

`epm:failure-lesson` block so a later corrected diagnosis retracts/annotates the earlier wrong
lesson in the durable record (agent memory + `gotchas.md`) instead of leaving two co-equal,
mutually-contradictory gotchas. (Forward-looking — independently justified below, NOT a #664
retrofit; see §2.)

**(e1) `failure_lesson_capture_eligible` — the AC#2 surface (M1).**

```python
def failure_lesson_capture_eligible(
    block_fields: dict[str, str],
    *,
    subsequent_distinct_failure: bool,
) -> bool:
    """Decide whether a received epm:failure-lesson block is eligible for capture.

    Eligible when the block RESOLVED the failure (the original trigger,
    signalled by ``block_fields.get("resolved") == "yes"``) OR the block carries
    ``root_cause_confirmed: yes`` — the latter is True INDEPENDENT of
    ``subsequent_distinct_failure`` (case ii: the cause was confirmed even though
    a distinct failure followed or the pod was abandoned in recovery — the #664
    L204 gap). Pure: no I/O. The orchestrator owns the actual marker post + write.
    """
    if block_fields.get("resolved", "").strip().lower() == "yes":
        return True
    return block_fields.get("root_cause_confirmed", "").strip().lower() == "yes"
```

Note: the existing resolve-path signal is modeled as `resolved: yes` in `block_fields` (the
orchestrator already knows it resolved the failure — that is the original trigger condition). The
predicate's contract is the union; `subsequent_distinct_failure` is accepted to make the
"captured-regardless-of-a-following-failure" guarantee explicit and testable, and is deliberately
NOT consulted when `root_cause_confirmed=yes`.

```python
    """Locate durable failure-lesson entries a ``supersedes`` ref points at and
    return the CONCRETELY-annotated subset.

    ``prior_ref`` is a lesson slug (e.g. ``vllm_first_generate_pod_specific_deadlock``)
    or a marker timestamp (e.g. ``2026-06-28T01:26:58Z``). ``durable_texts`` maps a
    durable-file path -> its current text (agent-memory feedback_*.md bodies +
    gotchas.md bullets). ``new_lesson_ref`` carries the REAL superseding slug +
    task id. Pure: no I/O, no writes.

    Returns ``{path: annotated_text}`` for every file whose text matches
    ``prior_ref`` (slug substring OR marker-ts substring), with a CONCRETE
    ``[SUPERSEDED by <new_lesson_ref['slug']> — see #<new_lesson_ref['task_id']>] ``
    marker prepended to the matched entry (NEVER a ``<pending>`` placeholder).
    Returns ``{}`` when nothing matches (caller logs ``supersedes_unresolved`` and
    appends the new lesson only). This helper DECIDES + ANNOTATES the prior subset;
    the composer (e3) assembles the FINAL durable map including the new lesson.
    """
```

**(e3) `apply_failure_lesson` — the pure composer / apply seam (M3).**

```python
def apply_failure_lesson(
    block: dict[str, str],
    durable_texts: dict[str, str],
    new_lesson_ref: dict[str, str],
) -> dict[str, str]:
    """Compose the FINAL durable {path: text} map for a captured failure-lesson.

    Orchestration (pure — no I/O; the orchestrator writes the returned map):
      1. If ``block.get("supersedes")`` is set, call ``supersedes_action(prior_ref,
         durable_texts, new_lesson_ref)`` -> annotated subset; merge those
         annotations over a copy of ``durable_texts`` (a dangling ref merges
         nothing — every prior text stays byte-unchanged).
      2. APPEND the new lesson's formatted body to the owning_agent memory file's
         text (key ``new_lesson_ref['memory_path']`` — passed by the caller; the
         file the action-2 path already writes), creating/extending that entry.
      3. Return the final ``{path: text}`` map.

    With ``supersedes`` ABSENT, step 1 is skipped and the produced owning-agent
    memory text is BYTE-IDENTICAL to the pre-#712 append-only result (pinned by the
    golden fixture, §6). The new (corrected) lesson ALWAYS lands — matched,
    dangling, or absent.
    """
```

The composer is the single tested apply seam; `supersedes_action` is the tested match-and-annotate
seam; `failure_lesson_capture_eligible` is the tested eligibility seam. The orchestrator prose
performs the file writes (it already owns commit-by-explicit-path + push for the action-2 memory
write); the helpers isolate every decision so the fixtures can assert them without simulating an
orchestrator.

**Why code, not a model call?** (a) The single-model-call alternative would have the orchestrator
LLM eyeball the durable texts and edit them in-context. (b) A code path is preferred: the
match-and-annotate is a deterministic string-locate + prepend + append over a small known set of
texts, and the body's acceptance criterion 1 demands a byte-reproducible fixture — a model call is
non-deterministic and untestable, defeating the AC. (c) What would flip it: if the durable corpus
were large/unstructured enough that exact-string location were unreliable — it is not (a handful of
named files). (CLAUDE.md "Model call vs code".)

## 11. Decision Rationale

**N/A — no model training.** No training hyperparameters. The non-obvious design choices:

- **Three pure helpers instead of untestable prose.** What: extract eligibility, match-and-annotate,
  and apply/compose into `task_workflow.py`. Why: the body's acceptance criteria demand a byte-
  reproducible fixture, and `grep`/`Glob` confirmed there is no existing consumer script to test, so
  testable seams must be created. Source: the body's AC#1 (two-round fixture) + AC#2 (root-cause-
  confirmed firing); merged round-1 critique M1/M2/M3. Alternatives rejected: prose-only (untestable,
  fails the AC); a single fat helper (M3 reconciler asked for a named composer seam — cleaner).
- **M6 verdict (c): keep the fields + add a `--check-marker-registry` field-contract pin;
  `architectural: false`.** What: the new `root_cause_confirmed`/`supersedes` fields stay in the
  existing free-text `fields:` string (no Pydantic attribute), AND `check_marker_registry()` is
  extended to assert those tokens are present. Why: `.claude/rules/workflow-fix-on-bug.md`
  § Architectural greenlight names "change a marker schema" as architectural — and these ARE
  emitter-produced + orchestrator-branched semantic fields on a declared marker, so the SAFE reading
  is to treat the bare field-add as borderline-architectural. Option (a) (`architectural: true`,
  park at `plan_pending`) is honest but spends a user click on a 0-GPU-h additive change. Option (b)
  (encode `supersedes` as an out-of-band filename convention) AVOIDS the marker entirely but
  scatters the contract OUT of the centralized registry — the opposite of the workflow's
  "marker schema is the centralized contract surface" principle, and it would make the supersedes
  semantics invisible to `markers.md` / `/daily` / the registry. Option (c) is the most
  workflow-coherent: it PRESERVES the marker registry as the single contract surface AND adds the
  mechanical pin (`--check-marker-registry` extension) that makes the field-add no longer a
  free-floating schema drift — the next field-add on this kind inherits the check. Because the
  contract is now mechanically enforced rather than convention-only, the change clears the
  "architectural = a change that escapes mechanical enforcement / public-contract drift" bar and is
  recorded `architectural: false`. Source: merged critique M6 + `.claude/rules/workflow-fix-on-bug.md`
  § Architectural greenlight + the task #555 `check_marker_registry` precedent (a marker-registry
  drift check is exactly this surface's established guardrail). The reconciler flagged this as the
  planner's call; I am making it (c) explicitly and documenting the reasoning so the Step 2c gate
  and any re-critique can audit it.
