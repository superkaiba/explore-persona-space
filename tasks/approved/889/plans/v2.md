### 3.2 The operational definition of "external" (grounded in #779's real marker anatomy)

Measured facts (verified 2026-07-02 on `tasks/followups_running/779/events.jsonl`):

- `post_event` defaults `by="unknown"` (task_workflow.py:2180); `task.py post-marker` CLI defaults `--by unknown` (scripts/task.py:1269). Distribution in #779: `unknown` 210, `codex_task` 52, `code-reviewer` 22, `experiment-implementer` 20, `task.py` 14, `reconciler` 12, `poll_pipeline` 7, `backends.router` 6, `user` 3, `issue779` 3, others ≤3.
- The PM-chat audit markers AND the session's own markers are both `kind: epm:progress, by: "unknown"` — e.g. the 16:12:37Z audit (`{"ts":"2026-07-02T16:12:37Z","kind":"epm:progress","version":66,"by":"unknown"}`, note begins `# Audit: #779 3-arm ablation CPU phases…`) vs the session's own 17:10:52Z milestone (`by: "unknown"`, note begins `milestone: sycophancy DONE 16:41:54Z…`). **The `by` field cannot discriminate external from self.**
- The external markers self-identify in note PROSE: `# Audit:`, `AUDIT ROUTING NOTE`, `METHOD SUGGESTION … (user-raised, PM-chat)`, `SCOPE RESTORE REQUEST (user-raised, PM-chat…)`, `COVERAGE-MAP ADDITIONS (user question-map, PM-chat…)`, `DEDUP NOTE (PM-chat cross-task audit)`, `TARGET-CONSTRUCTION CHECK (user-raised, PM-chat)`, `AMENDMENT … (user directive, PM-chat)`, `AMENDMENT 2 … (user-raised, PM-chat)`.

Therefore the definition is TWO-LAYER:

- **Mechanical layer (helper — over-approximates, never classifies):** a *candidate* is any event in the bounded window whose kind is not in a curated machine/lifecycle exempt set, whose `by` is not a known machine poster, whose note is non-empty, and which is not itself a breadcrumb-shaped note. False positives (the session's own progress notes) cost one first-line read each; false negatives are the failure mode being closed, so the set errs inclusive.
- **Judgment layer (orchestrator — the LLM classifies):** *external* = a candidate this session did not itself post — decided from session context, and from the in-the-wild signatures above ("PM-chat", "user-raised", "user directive", "# Audit", "AMENDMENT", "SCOPE RESTORE", …). **Fail-toward-triage:** a successor/crash-recovery session that cannot attribute a candidate treats it as external. *Advisory/directive* = it requests action or bears on the pending dispatch.

### 3.3 The helper (task_workflow.py)

Placement: immediately after `stage_dispatch_should_skip` (ends task_workflow.py:1381), before the `# ─── Same-issue follow-up label grouping (#894)` divider at line 1384 — it shares that neighborhood's breadcrumb-parsing conventions.

```python
# Machine-posted / lifecycle-bookkeeping kinds that never carry cross-session
# advisory content — excluded from pre-dispatch triage candidates. Anything
# NOT listed is a candidate (over-approximation by design: a false positive
# costs one first-line read; a false negative is the #779 failure mode).
TRIAGE_EXEMPT_KINDS = frozenset({
    "epm:status-changed", "epm:step-completed", "epm:backend-selected",
    "epm:codex-task-spawned", "epm:codex-task-completed", "epm:codex-task-failed",
    "epm:pod-provisioned", "epm:pod-terminated", "epm:pod-stopped",
    "epm:run-launched", "epm:run-finished",
    "epm:upload-verification", "epm:merged", "epm:methodology-doc-generated",
    "epm:workflow-fix-task-filed", "epm:workflow-fix-applied",
    "epm:workflow-fix-failed", "epm:workflow-fix-candidate",
    # Session-pipeline review/lifecycle verdict kinds — structurally posted by
    # THIS task's own planner/review/implementation loop, never the vehicle for
    # a cross-session advisory (fact-check on #779: including these halves the
    # per-dispatch read load, 30 → 20 candidates, with zero externals lost).
    "epm:code-review", "epm:code-review-codex", "epm:review-reconcile",
    "epm:experiment-implementation", "epm:concern-raised",
    "epm:concern-addressed", "epm:concern-deferred",
    "epm:interp-critique", "epm:interp-critique-codex",
    "epm:clean-result-critique", "epm:clean-result-critique-codex",
    "epm:plan", "epm:plan-approved", "epm:plan-verify", "epm:consistency",
    "epm:clarify", "epm:clarify-answers", "epm:test-verdict",
    "epm:smoke-architecture-check",
})

# `by` values identifying MACHINE posters (pollers, routers, CLI shims).
# NOTE: `by` is UNRELIABLE for humans/sessions — post_event defaults it to
# "unknown", and on #779 both self- and PM-chat-posted markers carried
# by="unknown" — so this set only strips known machine identities; it never
# claims to identify externality (that is the orchestrator's judgment call,
# SKILL.md § Pre-dispatch external-marker triage).
TRIAGE_MACHINE_BY = frozenset({
    "poll_pipeline", "task.py", "backends.router", "backends.gcp",
    "backends.slurm", "backends.slurm_monitor", "backends.selector",
    "autonomous-gate", "codex_task", "task_state shim",
})
# (Fact-checked 2026-07-03: backends.router/gcp/slurm post markers at
# router.py:4482 / gcp.py:3895 / slurm.py:2246; slurm_monitor.py:582,645 and
# selector.py:672 do too; `backends.runpod` posts nothing today — omitted.)


def triage_candidates_since_last_dispatch(
    events: list[dict],
    *,
    exempt_kinds: frozenset[str] = TRIAGE_EXEMPT_KINDS,
    machine_by: frozenset[str] = TRIAGE_MACHINE_BY,
) -> list[dict]:
    """Return pre-dispatch triage candidates since the latest dispatch record.

    The window opens AFTER the most recent event that is either a
    stage-dispatch breadcrumb (``epm:progress`` whose lstripped note begins
    with ``"stage-dispatch "`` — same detection as
    ``stage_dispatch_should_skip``) or an ``epm:run-launched`` marker; when no
    dispatch record exists the window is the whole list (task start).
    Within the window an event is a candidate unless: kind in exempt_kinds,
    ``by`` in machine_by, the note is empty/absent, or the note is itself
    breadcrumb-shaped. Chronological order preserved. Deliberately
    over-approximates — it ENUMERATES for LLM-side triage and never
    classifies externality (``by`` cannot: default "unknown").
    """
```

Implementation sketch (~20 lines): single reverse scan to find the boundary index; single forward pass over `events[boundary+1:]` applying the four exclusion rules; return the surviving dicts.
