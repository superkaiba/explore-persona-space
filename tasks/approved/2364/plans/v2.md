# Plan v2 — #2364: catch test suites that monkeypatch the production constant their acceptance criterion depends on

`kind: infra` workflow-surface fix. No experiment, no GPU, no pod. Direct
floor-plan (minimum plan-review floor per SKILL.md Step 2): this document +
`verify_plan.py` + one Claude Methodology critic.

## 1. Requirement + acceptance criteria

**Requirement (from the task body).** Add review/lint coverage for the shape
the Codex statistics twin caught on #2360's plan and 5 of 6 reviewers missed:
a test suite that replaces a curated module-level production constant
(`monkeypatch.setattr`, `patch.object`, fixture assignment) in EVERY test
touching it, with nothing pinning the shipped constant's required contents —
so the suite validates the FUNCTION and never the CONSTANTS, and both shipped
lists could be empty while all tests stay green.

**Acceptance criteria (verbatim from the task body, each mapped to a surface
in §3):**

- A1. A diff (or plan test list) that replaces a production constant in every
  test touching it, with nothing pinning the constant's required contents, is
  flagged — naming the constant and the acceptance criterion that depends on
  it.
- A2. A test suite that monkeypatches a constant AND separately pins its
  required members is NOT flagged (that is the correct pattern).
- A3. Monkeypatching a constant no acceptance criterion depends on is NOT
  flagged.
- A4. The lint arm (built here) is WARN-only, with false negatives disclosed
  in the check's own docstring, per the convention the other heuristic checks
  follow.

## 2. Method delta (vs existing surfaces)

### D2. `.claude/agents/code-reviewer.md` — new Step 3.85 + blocker tag

**Step 3.85: Fixture-substituted production-constant verification (any diff
type).** Sibling of Step 3.8 (diff-analysis family — it reads test hunks, so
it is NOT a 0.7x pre-diff presence gate; this is a deliberate deviation from
the task body's "Step 0.7x" sketch, reason recorded here).

- **Trigger:** the diff adds or edits a test that REPLACES a module-level
  production constant — `monkeypatch.setattr(<mod>, "<NAME>", ...)`,
  `mock.patch.object(<mod>, "<NAME>", ...)`, `patch("<dotted>.<NAME>", ...)`,
  or a fixture assignment — where `<NAME>` is an ALL_CAPS attribute of a
  non-test module. No hit → `Step 3.85: N/A — no test in the diff replaces a
  production constant`.
- **Check:** for EVERY such constant, verify EITHER (a) a committed test
  (same diff or pre-existing — cite file:line) asserts the REAL, unpatched
  constant's required contents (membership / subset-completeness /
  non-emptiness / required members), OR (b) no acceptance criterion or plan
  requirement depends on the constant's contents (record which criteria were
  checked). A test pinning call ORDERING via source substring, or asserting
  only on the fixture value, is NOT contents evidence.
- **Verdict routing:** an acceptance-criterion-bearing constant with nothing
  pinning its contents → **Critical FAIL**, new blocker tag
  `production-constant-unpinned` (substantive, NOT mechanical-contract, never
  stripped by Step 5c-bis). Correct pattern (A2) → record the per-constant
  ledger line and pass. Constant with no dependent criterion (A3) → not
  flagged.
- Add `production-constant-unpinned` to the **Blocker tags** parse-target
  line (currently listing `smoke-blind-spot-unenumerated` etc.). Additive:
  the Step 5c-bis strip set {`marker-shape`, `smoke-run-missing`,
  `git-provenance`} is unchanged, so a FAIL carrying the new tag is already
  never mechanical-contract-only.

### D6. `scripts/workflow_lint.py` — best-effort AST scan (WARN-only, flag-invoked)

`check_monkeypatched_constant_pinning` — AST scan over `tests/`:

- **Hit rule:** `monkeypatch.setattr(<mod-expr>, "<ALL_CAPS>", ...)` /
  `mock.patch.object(<mod-expr>, "<ALL_CAPS>", ...)` /
  `patch("<dotted>.<ALL_CAPS>", ...)` where the resolved module is non-test.
- **Suppression (cross-ref):** any test module under `tests/` references the
  same `<module>.<CONST>` in Load context outside patch/save contexts within
  an assert-bearing function (the pinning-test signal). Repo-wide across
  `tests/`, not same-file-only, to avoid false positives on split suites.
- **WARN-only** (A4), CLI flag `--check-monkeypatched-constant-pinning`,
  NOT in the no-flags default run at v1 — the reviewer lens is the binding
  gate (same disposition as #2165's `--check-smoke-blind-spots`). If the
  implementer's repo-wide run comes back with zero pre-existing WARNs, they
  MAY additionally bundle it into the default run (recorded in the round
  report); any pre-existing hits → stays flag-only, hits listed in the round
  report for manual triage, never auto-"fixed".
- **Docstring discloses false negatives** (A4): indirect fixtures,
  parametrized/string-built names, `patch.dict`, aliased imports, constants
  replaced via helper wrappers, non-ALL_CAPS curated lists. Also discloses
  the known over-approximation: the scan cannot read acceptance criteria
  (A3's judgment is reviewer/critic-side), which is WHY it is WARN-only.
