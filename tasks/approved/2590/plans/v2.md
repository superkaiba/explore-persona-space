### 4.1 Check 71 — plan-embedded jq probe dry-run (`c71_jq_probe_dryrun`, **FAIL**, kind ∈ {experiment, analysis})

Banner: `# ─── Check 71 — plan-embedded jq probe dry-run against committed targets (#2590) ──` with the incident narrative (#2588 v2 lines 108/240/352/411; the `|`-binds-looser-than-`,` precedence trap that defeated both critics' repairs; the design point that execution needs no jq grammar model), the corpus-calibration snapshot (filled at implementation), and the accepted-FN list below (all three non-108 shapes).

**Module-level constants:**

```python
_C71_REPO_ROOT = Path(__file__).resolve().parent.parent  # tests monkeypatch (_C42_REPO_ROOT pattern, :7882)
_C71_JQ_TOKEN_RE = re.compile(r"(?<![\w-])jq(?![\w-])")          # cheap candidate pre-filter
_C71_ALLOWED_FLAGS = frozenset({
    "-c", "-r", "-e", "-j", "-a", "-S", "-s", "-M",
    "--compact-output", "--raw-output", "--exit-status", "--sort-keys",
})
# Refuse-to-execute: ANY other '-'-leading token (notably -f/--from-file, --args,
# --jsonargs, --arg, --argjson, --slurpfile, --rawfile, -n, --stream, -i) — skip
# the instance with a note, never guess (the task-body "which tokens you refuse" ask).
_C71_EXPECT_RE = re.compile(
    r"(?i)(?:→|->|=>)?\s*expect(?:ed|s)?\s*[:=]?\s*([0-9][\d,]*(?:\s*/\s*[0-9][\d,]*)*)"
)
_C71_MAX_INSTANCES = 12       # executed per plan, deterministic document order; rest noted
_C71_TIMEOUT_S = 5            # per instance
_C71_MAX_BLOB_BYTES = 5_000_000   # git cat-file -s gate; larger targets skip with a note
_C71_MAX_STDOUT = 4096        # comparison/detail bound
```

**Extraction (the c46 pattern, adapted):**

1. Candidates = `_c46_command_candidates`-shaped harvest generalized into a shared local helper. A straight call to the c46 function cannot serve, for two reasons measured at plan time: it filters on `dispatch_issue.py`, AND it returns bare candidate strings with NO line index and NO source-kind (verify_plan.py:8569-8602) — c71 needs both, because the FAIL detail names the plan line, the superseded-line guard tests the RAW line, and expectation parsing differs fenced-vs-inline (step 7c). So: factor a `_command_candidates(plan, token_re)` that ALSO yields `(line_idx, source_kind)` and re-express c46 as a thin wrapper *only if* the refactor is zero-risk (c46's committed tests unmodified and green), else duplicate the 30-line walker as `_c71_candidates` with a comment naming the c46 origin — implementer's call, noted in the report.
2. Per candidate matching `_C71_JQ_TOKEN_RE`: skip if the RAW line matches `_C70_SUPERSEDED_RE` (corrected plans quote broken probes verbatim — the house convention c70 already handles). `shlex.split` (unsplittable → note, skip). Split tokens into segments at `_C46_SHELL_OPS`; each segment containing token `jq` yields an instance with `argv = segment[segment.index("jq")+1:]`.
3. Per instance, classify argv left-to-right: leading tokens in `_C71_ALLOWED_FLAGS` are flags; any other `-`-leading token → **refuse-instance** (noted). Next token = filter. Next token, if present and not an expectation leader (`→`, `->`, `=>`, `#`, `expect*`), = target path. Remaining tokens must begin an expectation clause or the instance is refused (shape-violation note). **No target path → skip-instance** ("target not stated in the invocation" — the #2588 line-411 table shape, where the path lives in a sibling cell, AND the line-352 shape, where a bare `jq length` carries a trailing expectation). When the skipped instance ALSO carries an expectation clause (the 352 shape: trailing "expected 10000/400/1000"), the skip note says so explicitly: *"expectation present but target unresolvable — probe not executed, expectation not certified."* Skip — not FAIL, not a guessed execution — is the right disposition for an expectation-bearing unresolvable probe: arm (c) compares got-vs-expected, and an unexecuted probe produces no "got"; manufacturing one by guessing a path is precisely the mis-execution channel the explicit-path-only decision (§11) exists to close in a FAIL-posture check. The widening path — same-line single-candidate `.json` fallback — is named in the banner as a future revision, deliberately not shipped v1.
4. Placeholders: `_C46_PLACEHOLDER_RE` match in filter or path → skip-instance (illustrative command).
5. **Target resolution ("committed in the repo", the disk-vs-HEAD question answered):** reject absolute paths and any path whose `(_C71_REPO_ROOT / path).resolve()` is not relative to the root (skip-instance). Committedness AND content both come from git, never the working tree: `git cat-file -s HEAD:<path>` (size gate; nonzero rc → target does not resolve → skip-instance; > `_C71_MAX_BLOB_BYTES` → skip with note) then `git show HEAD:<path>` → the input bytes. This deliberately tests the *committed* artifact (what the plan's probe registers) and is immune to a locally-modified working tree. Git subprocesses use the c42 conventions (timeout 10, cwd=`_C71_REPO_ROOT`, retry-once on `OSError`, whole-check fail-open SKIP if git is unusable).
6. **Execution (the safe-execution contract):** `jq_bin = shutil.which("jq")`; absent → whole-check SKIP ("jq unavailable — dry-run not possible"), never FAIL. Then:

```python
r = subprocess.run(
    [jq_bin, *flags, filter_text],           # argv list, shell=False by construction
    input=blob_bytes, capture_output=True,
    timeout=_C71_TIMEOUT_S, check=False, cwd=str(_C71_REPO_ROOT),
)
```

Read-only is **structural**, not promised: jq receives the committed bytes on stdin and no file argument, so the process touches no filesystem path at all; jq-1.6 filters have no write primitive (`$ENV`/`env`/`debug` are read-only/stderr); `--args`-family and `-f` flags — the channels by which extracted text could reach the filesystem or reinterpret arguments — are on the refuse-list. `TimeoutExpired` → offender? No: **skip-instance with a note** (a hung jq on committed bytes is an environment anomaly, not plan evidence — fail-open, c42 doctrine). Cap at `_C71_MAX_INSTANCES` executed instances.

7. **Offender arms (any → FAIL):**
   - (a) `r.returncode != 0` — the wrong-path AND precedence shapes both land here for free (the body's central design insight);
   - (b) stdout stripped empty, or every non-empty stdout line == `null` — jq's "path missed" tell. **Structural limit, disclosed and pinned:** this arm CANNOT catch a wrong-path probe piped through `length` — `null | length` is `0`, which is neither empty nor `null`, at rc=0 — exactly #2588 v2:240 (`jq '.train_10k|length' …` prints `0` and executes clean). Fixture T17 pins that disposition (see the recall block below);
   - (c) expectation mismatch: parse `_C71_EXPECT_RE` from the raw-line remainder after the inline span (inline instances) / the trailing tokens of the logical line (fenced instances); tokens = comma-stripped ints split on `/`; arm only when ≥1 numeric token; offender when stdout's non-empty lines are not exactly that integer sequence (count + values; non-numeric output lines count as mismatch). Arm (c) is also the designed recovery for arm (b)'s `|length` limit: a `|length` probe WITH a stated expectation (`→ expect 10000`) IS caught here (got `0` ≠ expected `10000`), so the remedy text tells plans to state expectations inline — that converts the v2:240 shape from an FN into a catch.
8. **Verdict:** offenders → `_fail` with per-offender detail (plan line no, probe head ≤70 chars, rc, stderr head ≤120 chars, got-vs-expected) + remedy text quoting the two verified working forms from the task body (parenthesized filter / `jq -c '.counts'`) + both escape phrases + the state-expectations-inline recommendation. No executable instance → `_skip` (reason breakdown: none found / all unresolved / all refused; expectation-bearing unresolved instances flagged per step 3). All executed clean → `_pass` with counts (`N executed, M skipped-unresolved, K refused`).
9. **Order of gates in the function:** kind gate → candidate harvest (none → SKIP) → escapes (`_standalone_na_declared`) → resolve+execute → verdict.
