# Plan v3 — #2139 tick_triage counts auto-compaction continuation rows as human

`kind: infra` workflow-fix. 0 GPU-h. One predicate
(`scripts/tick_triage.py::is_human_transcript_row`), two test files, no new
dependency, no pod.

## 1. Requirement + acceptance criteria

**Requirement.** A transcript row injected by AUTO-COMPACTION (the
`isCompactSummary: true` continuation row) must classify as AUTOMATION, not
as direct human input, in `is_human_transcript_row`.

**The defect, measured (not inferred).** The predicate's only shape guards are
`type != "user"`, `isMeta`, and three content-prefix exclusions. A compact row
passes all of them, so `human_activity_reason()` reports
`human-active (last human msg Nm ago < 45m)` and suppresses the STALE-REDRIVE
verdict for up to `EPM_TICK_HUMAN_ACTIVE_S` (default 2700 s) per compaction.
A thrashing session compacts repeatedly, so the mask renews — the sessions
that most need re-driving are exactly the ones that suppress their own tick.

Corpus-wide measurement over all 1,174 local transcripts:

| quantity | value |
|---|---|
| rows with `isCompactSummary: true` | 609 |
| of those, classified HUMAN by the current predicate | **584 (95.9%)** |
| classified non-human (accidental — body quotes `<command-name>`) | 25 (4.1%) |

The 25 misses are content coincidence, not coverage: a summary that never
happens to quote a command name is mis-classified 100% of the time.

**Acceptance criteria.**

- **AC1** — a row with truthy `isCompactSummary` returns `False`, regardless
  of its `message.content` shape.
- **AC2** — belt-and-braces: a plain-string row opening with the compaction
  continuation text returns `False` even with the flag absent.
- **AC3** — regression tests at BOTH grains: the row-level classifier, and an
  end-to-end `triage()` test where a transcript whose only fresh user row is a
  compact summary still yields `STALE-REDRIVE`.
- **AC4** — the SECOND consumer (§2) has its changed behavior pinned by a
  test, not left implicit.
- **AC5** — the no-flags `workflow_lint.py` bundle and the 29 Step-9c-mapped
  tests stay green (no NEW failures vs the known-red ledger).

## 2. Blast radius — there is a SECOND consumer, and the task body does not name it

`scripts/autonomous_session_watch.py:1324` imports `is_human_transcript_row`
from `tick_triage` and calls it at line 31419 inside the #2117
session-reconcile transcript WORK probe (`_transcript_work_idle_age_s`). That
probe decides whether a parked/terminal task's session contributes liveness:

- arm (ii) DURABLE WORK — newest `"ok"` wake-turn **or newest genuine human
  row** ⇒ the session is protected from the auto-stop;
- arm (iii) CHURN-ONLY — ≥1 completed turn, all failed, **no human row** ⇒
  contributes nothing, the ≥2-miss counter accumulates, the session is stopped.

**Direction of the change there: identical defect, identical fix direction.**
Today a compact row is the "genuine human row" of arm (ii), so an
error-storming session on a DONE task that happens to auto-compact rescues
itself from the reaper — the exact #2004 shape #2117 was written to close,
leaking back in through the shared predicate. After the fix such a tail falls
to arm (iii) and the reaper works as specified.

**Why this does not weaken the #1670 human protection.** A compact summary is
harness-injected, never human-authored, so it is never evidence of human
presence. Genuine work by a compacting session is still carried by arm (ii)'s
independent `newest_ok_ts` term (a successfully-completed wake-turn); typed
text and `[Request interrupted by user` rows are untouched.

**A LIVE session cannot be stopped by this change** — the structural reason,
verified at source: a compact row classifies as `"prompt"` evidence in
`_classify_wedge_row` (asw:3504-3505), and `_segment_wake_turns`'s trailing
flush (asw:3576-3577) counts an in-flight turn carrying >=1 assistant response
row as a completed OK turn. So any session still emitting assistant rows after
a compaction reads arm-(ii)-fresh through `newest_ok_ts`, whatever the compact
row classifies as.

**Exactly two tail classes change verdict**, both inside #2117's sanctioned
stop set:

- (α) ZERO ok turns, ZERO typed rows, one compact summary — churn plus a
  compaction.
- (β) a STALE ok turn (>2 h) plus a FRESH compact row: arm (ii) takes
  `max(newest_ok_ts, human_ts)` (asw:31427), so today the fresh compact
  timestamp wins and protects; post-fix the stale ok timestamp governs and the
  tail becomes stop-eligible.

Class (β) is the one the first draft of this section missed. Its verdict change
is still correct — that session last completed real work >2 h ago, on a
DONE-status task, with every other idleness gate satisfied and the >=2-tick
guard still binding — but it is a distinct class and is pinned separately in
§3.3.

**Consequence for scope:** `autonomous_session_watch.py` itself is NOT edited
(the fix is entirely in the imported predicate), but AC4 requires a pin in
`tests/test_autonomous_session_watch.py` beside the existing #2117 section, so
the behavior change is deliberate and auditable rather than a silent
side-effect. No third consumer exists: `grep -rn 'def is_human_transcript_row'
scripts/ src/ .claude/` returns exactly one definition on `main` (the other
hits are worktree copies and #1629's own archived plans).

**(b) Flag check, placed with the other ROW-LEVEL shape guards** — i.e. in the

(so the existing meta guard cannot catch them), and `message.content` is
always a plain string.

```python
        if (
            "<command-name>" in content

```

existing `<task-notification>` note, with the 584/609 measurement — plus one

## 4. Design decisions

- **D1 — flag check at the ROW level, not inside the string branch.** Shape-
  independent and future-proof (§3.1(b)). Costs one boolean in the hot guard.
- **D2 — keep the prefix exclusion even though the flag makes it redundant
  today.** It is the declared belt-and-braces for a transcript writer that
  drops or renames the flag; the failure mode it guards is silent, and the
  false-positive cost (a human typing that exact 60-character sentence) is
  negligible AND fails toward ticking.
- **D3 — do NOT exclude on `isVisibleInTranscriptOnly`.** It is present on all
  609 compact rows and looks tempting as a broader signal, but its full row
  population was not measured here and a wrong exclusion would silently drop
  genuine human rows — the one direction this predicate must never move.
  Explicitly out of scope.
- **D4 — do not edit `autonomous_session_watch.py`.** The fix belongs in the
  shared predicate; the consumer's change is correct (§2) and gets a pin, not
  a local override.
- **D5 — no change to `human_activity_reason()`, the tail reader, the window,
  or the kill switch.** Single-predicate change; every other #1629 mechanism
  is untouched.

**Fail-safety argument (why this cannot make the tick worse).** The change is
monotone: it moves rows from HUMAN to automation and never the reverse. In
`tick_triage` that can only REMOVE a stall mask (fail toward ticking — the
#1629 hard constraint); in the watcher it can only remove a false liveness
signal on a DONE-status task behind the existing ≥2-tick guard. There is no
input for which the fix produces a NEW suppression.

## 5. Method delta

Versus #1629 (which introduced the predicate): #1629 enumerated the automation
row classes visible in the transcripts it measured — cron slash commands, skill
meta rows, tool results, `<task-notification>` rows — and did not include the
auto-compaction continuation row. This adds that one class. Versus #2117 (which
hardened the watcher's reconcile probe against api-error churn): #2117 closed
the mtime channel; the same false-liveness leaked back through this shared
predicate, and closing it here closes both surfaces at once.
