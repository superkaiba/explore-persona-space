## 3. Design

### 3.1 The library helper (`src/explore_persona_space/task_workflow.py`, new — place after `_find_stage_breadcrumb`, ~line 1320)

Module constants: `FOLLOWUP_SCOPE_KIND = "epm:followup-scope"`, `FOLLOWUP_RUN_KIND = "epm:same-issue-followup-run"`, `USER_INITIATED_FOLLOWUP_SOURCES = frozenset({"user-chat", "step-10b-pick"})`.

**`parse_followup_note_field(note: str, field: str) -> str | None`** — first line whose core starts with `field:` **OR `field=`** (both separators — the `=`-form is the DOMINANT historical run-marker shape: 15 markers across 12 tasks, e.g. #537's `followup_label=seed2-marker-fact-replication source=proposer-9b round=1 ...`) after stripping leading `-`/`*`/whitespace and normalizing the bold `**field:**` form; value = first whitespace token of the remainder, stripped of `` ` ``/`'`/`"`/`*` and trailing `,` (backtick-wrapped values occur in the wild — #664's `` **followup_label:** `em-provenance-robustness` ``); `None` if absent/empty. Handles all observed forms (bare-colon / bare-equals / dash-bullet / star-bullet / bold / backticked) AND the single-line note (first-token rule; kebab-slug labels contain no whitespace). First hit wins — the #763 v2 scope embeds a second bold `**followup_label:**` deep inside its verbatim-proposal section; the top-of-note canonical line is hit first. For a `stage-dispatch` breadcrumb's `label=` token the existing `_breadcrumb_fields` grammar remains the parser (unchanged).

**`followup_label_groups(events: list[dict]) -> list[dict]`** — grouping algorithm:

```
CORRECTION_SIGNAL = re.compile(r"correction|supersede|re-?post", re.I)

scopes = [e for e in events if e.kind == FOLLOWUP_SCOPE_KIND]
sort scopes ascending by (_stage_event_ts or datetime.min, version or 0)
    # CHRONOLOGICAL scan, version tiebreak. NOT (version, ts): per-kind version
    # monotonicity is VIOLATED in the wild (#480 carries TWO version:1 scope rows
    # with a v2 chronologically between them); (ts, version) is robust and
    # identical to (version, ts) on every conforming task (#658, #763).
prev_label = None; groups = ordered dict label -> group
for ev in scopes:
    label = parse_followup_note_field(ev.note, "followup_label")
    if label:            parse_mode = "parsed"
    elif prev_label and CORRECTION_SIGNAL.search(ev.note or ""):
                         label, parse_mode = prev_label, "inherited-from-previous"
                         # the #658-v2 unlabeled-CORRECTION shape ("CORRECTION to the
                         # earlier epm:followup-scope (...)"): a correction follows the
                         # scope it corrects -> attribute to it. GATED on an explicit
                         # correction signal (CORRECTION|SUPERSEDES|RE-POST, case-
                         # insensitive): an unlabeled note WITHOUT the signal is a
                         # DISTINCT queued follow-up (#685 v2, real user-chat round) and
                         # must NOT merge into the previous label.
    else:                label, parse_mode = f"unlabeled-{ev.ts}", "pseudo-ts"
                         # unlabeled non-correction scope: its own pseudo-label keyed by
                         # ts -> NEVER silently dropped, but NON-dispatchable (below)
    prev_label = label
    group.setdefault(...): armed_ts = first entry's ts (arming time — a later
                           correction never re-queues the label)
    group.authoritative = ev            # last in (ts, version) order wins
    group.label_parse = parse_mode of the authoritative entry
group.source = first parseable `source` across the group's entries in scan order
               or "unknown"
    # FIRST-parseable, not authoritative-only: a label whose latest correction note
    # omits `source:` (the #658-v2 shape) must not demote a user-chat round to
    # "unknown"/lose queue priority (3 reviewers flagged this).
group.user_initiated = source in USER_INITIATED_FOLLOWUP_SOURCES
group.dispatchable = (group.label_parse == "parsed" or
                      group.label_parse == "inherited-from-previous")
    # pseudo-ts groups are REPAIR ITEMS, never normal rounds: `unlabeled-<ts>`
    # violates the kebab-slug field contract (workflow.yaml § markers) and would
    # name eval_results/issue_<N>/<label>/ artifact dirs with colons. Step 0
    # surfaces them loudly (§3.3(a)) instead of executing a malformed round.
```

Each group dict (all values JSON-native): `{followup_label, source, user_initiated, armed_ts, authoritative (full event row), label_parse, dispatchable, n_entries}`.

**`unrun_followup_labels(events: list[dict]) -> list[dict]`** — `run_labels = {parse_followup_note_field(e.note, "followup_label") for e in events if e.kind == FOLLOWUP_RUN_KIND} - {None}`; unrun = groups whose `followup_label ∉ run_labels` (pseudo-label groups INCLUDED — they must surface, just not dispatch; consumers filter on `dispatchable`); ordered by `(not user_initiated, armed_ts, authoritative.version)` — user-initiated first, then oldest armed ts; fully deterministic (armed_ts ties broken by version; version per-kind unique on conforming tasks, and an exact tie is broken by list order, itself deterministic). A run marker with an unparseable label closes NOTHING (conservative in the anti-stranding direction; the counterweight is the §3.3(a) stale-label disposition rule).

**`followup_retro_close_evidence(events: list[dict], label: str) -> str | None`** — the MECHANICAL, exact-label evidence predicate behind the §3.3(a) stale-label disposition rule (Alt-Codex MF1: prose-mention/substring evidence must never close a queued round). Returns a one-line evidence string when EXACTLY ONE of these matches, else `None`:
1. an `epm:methodology-doc-generated` note carrying `extends=<label>` (exact token match via `parse_followup_note_field(note, "extends")` or the `extends=<label>` breadcrumb grammar);
2. an `epm:free-analysis-followup-run` whose `followup_ref` EXACTLY equals `label` (string equality — never fuzzy/prefix);
3. an `epm:status-changed` / `epm:step-completed` / `epm:progress` note containing the exact parenthesized round token `(<label>)` AND a round-completion word (`PASS|re-park|awaiting_promotion|clean-result`) on the same line.
`None` ⇒ do NOT retro-close: skip the label this entry, surface it for manual disposition (autonomous mode: continue to the next dispatchable label; the skipped label stays queued and visible). Ambiguity NEVER closes.

**`executing_followup_label(events: list[dict]) -> dict | None`** — resolves WHICH unrun label the current/most-recent round is executing (shared by the Step 9b step-3 mid-round re-read, the step-4 completion-marker label derivation, and the watcher's `_post_followup_run_marker`): (1) the newest `epm:progress` note beginning `stage-dispatch stage=followup-` that is strictly newer than the newest `FOLLOWUP_RUN_KIND` ts and carries a `label=<slug>` token (via the existing `_breadcrumb_fields`) → return that label's group if unrun; (2) fallback: head of the DISPATCHABLE subset of `unrun_followup_labels` (Step 0 only ever dispatches dispatchable heads, so head == executing round whenever no labeled breadcrumb exists); (3) `None` when no dispatchable unrun labels. Rule (1) exists because a user-chat label posted MID-ROUND would jump the queue head; the breadcrumb pins the actual round (pinned by §4 test 11b at the watcher level, not only the pure helper).

No new `task.py` subcommand (avoids any CLI-contract question); SKILL.md consumers use the `uv run python -c` recipe in §3.3(c). No `.env` needed (`task_workflow` reads the filesystem only), so the heredoc-dotenv lint rule is not implicated.

Mitigations: (i) the exposure is NOT new in kind — the OLD predicate already fires on #658 (v10's label is also unrun); (ii) the §3.3(a) stale-label disposition rule retro-closes on MECHANICAL exact-label evidence instead of re-running, and parks-on-ambiguity instead of guessing; (iii) run markers are the contract-mandated satisfier (workflow.yaml) — we deliberately do NOT fold `epm:free-analysis-followup-run` into the satisfier set as a fuzzy match (exact `followup_ref == label` equality IS one of the three mechanical evidence classes; a PREFIX/fuzzy match like `persona-vectors-style-rb-9a-ter-fit` never closes — §4 test 8c pins this).
2. **Label-parse drift.** A future note format the parser misses → the scope becomes a pseudo-label (non-correction) or inherits (correction-signaled); either way it is never silently dropped OR silently executed: `label_parse` flags it, pseudo-labels surface as repair items, and the corpus-replay test (§4 test 14) pins every HISTORICAL form (colon, equals, dash, bold, backticked, single-line) so known drift cannot regress. Residual: genuinely NEW future forms surface as repair items rather than failing silent — the intended fail-loud direction.
3. **Wrong-label close by the watcher.** If a round were manually dispatched out of queue order with no `label=` breadcrumb, `_post_followup_run_marker` would close the head instead. Mitigated by the §3.2 breadcrumb contract (labeled breadcrumbs win — now watcher-level pinned by §4 test 11b) and by Step 0 being the only dispatch path (it always takes the head). Residual: pre-#894 in-flight rounds lack `label=` — the fallback equals the old behavior or better.
4. **Watcher-pass regressions (#837/#533/#778 machinery).** Mitigated by the `max(scope_ts, run_ts)` anchoring being an identity transformation on every existing fixture (§3.4 row 3) plus the full existing suite as the gate.
5. **Double-dispatch on ordering ambiguity.** Ordering is total and deterministic (`(not user_initiated, armed_ts, version)`); the Step 0 single-orchestrator guard (#778) already excludes two live drivers; one-label-per-entry is stated at every dispatch site.
6. **#763 mid-flight transition.** #763 is at `followups_running` now; after this lands, the next Step 0/resume entry computes the unrun queue and (post any in-flight round) picks up `neutral-contrast-and-cofit` — the intended outcome.
