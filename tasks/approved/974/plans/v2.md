## 3. Detection-logic decision (trigger vocabulary, enumerated)

The false-positive constraint dominates: `verify_plan.py` scans free plan prose, "held-out" is ubiquitous as an *eval-split* adjective (GOOD_PLAN itself: "40 held-out prompts", `tests/test_verify_plan.py:47,70`), and the dual-DV boilerplate ("ρ(DV, rate) > 0 validation, Spearman across cells" — `llm-judging.md` §E2) puts correlation vocabulary in nearly every experiment plan. Options considered:

| Option | Trigger | FP risk | FN risk |
|---|---|---|---|
| A. `held-out` alone | any "held-out" | **Severe** — fires on every eval-split mention incl. GOOD_PLAN | ~none |
| B. predictive-stat vocab alone (ρ/Spearman/R²/predictor) | any correlation/predictor token | **High** — dual-DV boilerplate + prior-work recaps | low |
| C. **Conjunction + solo-fold hybrid (CHOSEN)** | (`held-out` AND predictor-stat token) OR a fold token (`cross-valid*`, `LOO`, `LOCO`, `LOOCV`, `leave-one-…-out`, `k-fold`) | Low — GOOD_PLAN skips; boilerplate ρ without "held-out"+predictor skips | Accepted: a plan reporting only "held-out ρ" with zero predictor/read-out/regression vocabulary is missed — rare (read-out ρ co-occurs with "read-out"/"ridge"/"predictor" in the #810/#722/#761 line), and the Statistics critic lens item 13 remains the semantic gate |
| D. Proximity windows (same-line/±k-lines co-occurrence, c12/c13 style) | conjunction within a window | Lowest | Highest complexity; over-engineered for a WARN-only surface check |

Option C is the same conditional-trigger philosophy as `check_contrastive_negatives` (`_MARKER_VOCAB_RE`, lines 168-174: bare "marker" false-fires on workflow vocabulary → vocabulary narrowed) and `check_causal_claim_scope` (fires only when a registered-branch surface exists, line 2070). Fold tokens are SOLO triggers because any cross-validation/LOO mention makes "is the fold group-level?" exactly the right question; bare "held-out" is a WEAK token requiring a predictor-statistic co-occurrence. `\bpredict(?:or|ive|ion)s?\b` deliberately excludes bare "predict(s)" — hypothesis prose ("we predict the effect…") + "held-out prompts" is a common benign conjunction. A `(?<!\bno )(?<!\bnot )` lookbehind guards the weak `held-out` token (negated-mention noise class, per the corpus-calibration precedent in the implementer memory for #937).

**Pointwise-vs-group `leave-one-X-out` disambiguation:** the group-fold PASS evidence captures the left-out unit and rejects a pointwise blocklist (`context, point, sample, row, item, question, prompt, cell, completion, example`) — because #810's own offender fold WAS `leave-one-context-out` (pointwise: contexts were the sample points), while `leave-one-family/genre/persona-out` are group folds. Bare `leave-one-out` never counts as group evidence.

### 4.1 `scripts/verify_plan.py` — new check (insert after `check_paired_contrast_source_coverage` ends at line ~2310, before the `# ─── Driver ───` divider)

```python
# ─── Check 19 — OOD generalization folds (WARN-only, conditional) ──────────

# Trigger = a fold token SOLO (any cross-validation mention makes "is the
# fold group-level?" the right question), OR the WEAK token "held-out"
# conjoined with a predictor-statistic token. Bare "held-out" alone is an
# eval-split adjective (GOOD_PLAN: "40 held-out prompts") and must not fire;
# bare "predict(s)" is hypothesis prose and is deliberately excluded.
_C19_SOLO_FOLD_RE = re.compile(
    r"(?i)\bcross[- ]?validat\w*|\bLOO\b|\bLOCO\b|\bLOOCV\b"
    r"|\bleave[- ]one[- ][\w-]*out\b|\bk[- ]fold\b"
)
_C19_HELDOUT_RE = re.compile(r"(?i)(?<!\bno )(?<!\bnot )\bheld[- ]out\b")
_C19_PREDSTAT_RE = re.compile(
    r"(?i)\bR\^?2\b|R²|\breconstruction\b|\bread[- ]?outs?\b"
    r"|\bpredict(?:or|ive|ion)s?\b|\bregress\w*|\bridge\b"
    r"|\b(?:probe|decod\w*)\s+accurac\w*"
)
# Group-level evidence: leave-one-<UNIT>-out where UNIT is not a pointwise
# sample unit (#810's offender fold was leave-one-CONTEXT-out — pointwise).
_C19_LOO_UNIT_RE = re.compile(r"(?i)\bleave[- ]one[- ]([\w-]+?)[- ]out\b")
_C19_POINTWISE_UNITS = frozenset(
    {"context", "point", "sample", "row", "item", "question", "prompt", "cell",
     "completion", "example"}
)
_C19_GROUPFOLD_RE = re.compile(
    r"(?i)\bLOFO\b|group[- ]level (?:held[- ]out )?fold"
    r"|held[- ]out (?:group|famil\w*|genre|persona|corpus)"
    r"|(?:corpus|genre|domain|family)[- ]transfer\b|\btransfer arm\b"
)
_C19_IID_RE = re.compile(r"(?i)\biid\b|\bi\.i\.d\b")


def check_ood_folds(plan: str, kind: str) -> CheckResult:
    """WARN-only, conditional: a held-out predictive DV (reconstruction R²,
    read-out ρ, predictor accuracy) over group-structured samples must
    register a GROUP-level fold (LOFO / corpus transfer), declare
    `N/A — no held-out predictive DV`, or argue a genuinely iid sample
    (.claude/rules/ood-generalization-folds.md; planner §6 Required block).
    NEVER FAILs — the trigger is a vocabulary heuristic; whether the named
    fold is actually group-level for this sample stays with the Statistics
    critic (lens item 13). Incident #810: the pointwise-LOCO headline
    reordered under leave-one-FAMILY-out and the read-out collapsed
    ρ 0.909 → 0.285."""
    cid, name = "c19_ood_folds", "OOD generalization folds (held-out predictive DV)"
    if kind not in ("experiment", "analysis"):
        return _skip(cid, name, "kind-exempt: infra|batch|survey plans have no predictive DV")
    if re.search(NA_RE + r"no held-?out predictive DV", plan):
        return _pass(cid, name, "explicit N/A declared (no held-out predictive DV)")
    text = strip_fences(plan)
    solo = _C19_SOLO_FOLD_RE.search(text)
    conj = _C19_HELDOUT_RE.search(text) and _C19_PREDSTAT_RE.search(text)
    if not (solo or conj):
        return _skip(
            cid,
            name,
            "no held-out predictive-DV vocabulary (no fold token; no held-out + "
            "predictor/R²/read-out co-occurrence)",
        )
    group_units = [
        m.group(1)
        for m in _C19_LOO_UNIT_RE.finditer(text)
        if m.group(1).lower() not in _C19_POINTWISE_UNITS
    ]
    if group_units or _C19_GROUPFOLD_RE.search(text):
        return _pass(
            cid,
            name,
            "group-level fold vocabulary present"
            + (f" (leave-one-{group_units[0]}-out)" if group_units else "")
            + " — fold validity + per-headline fold labeling stay critic-owned",
        )
    if _C19_IID_RE.search(text):
        return _pass(
            cid,
            name,
            "iid-sample argument present (the only pointwise-only exemption) — whether "
            "the sample is genuinely iid stays critic-owned",
        )
    return _warn(
        cid,
        name,
        "held-out predictive-DV vocabulary detected but no GROUP-level fold (LOFO / "
        "leave-one-family-out / corpus transfer), no iid argument, and no "
        "`N/A — no held-out predictive DV` escape — pointwise LOO can REORDER "
        "cross-context claims (#810: read-out ρ 0.909 → 0.285 under LOFO); "
        ".claude/rules/ood-generalization-folds.md; Statistics critic must gate this",
    )
```

## 11. Decision Rationale

1. **WARN-only severity.** *What:* `_warn` at the bottom tier; zero `_fail` paths. *Why:* the trigger is a vocabulary heuristic over free prose; a hard block on a heuristic would bounce legitimately-worded plans (the c17 rationale, verbatim in its docstring). *Source:* task #974 title + brief; precedents `check_data_tier` (`scripts/verify_plan.py:597`) and `check_causal_claim_scope` (`:2037-2054`). *Alternatives:* FAIL-when-all-absent (c2's shape) — rejected: c2 gates a block EVERY experiment plan must have; c19's block is conditional on a DV type only some plans have, so absence is usually legitimate.
2. **Conjunction + solo-fold hybrid trigger.** *What:* fire on fold tokens solo, or `held-out` ∧ predictor-stat. *Why:* "held-out" alone false-fires on the eval-split usage in GOOD_PLAN itself (`tests/test_verify_plan.py:47,70`); correlation tokens alone false-fire on dual-DV boilerplate (`llm-judging.md` §E2). *Source:* the c4 `_MARKER_VOCAB_RE` narrowing precedent (`verify_plan.py:168-174`); trigger vocabulary list from `ood-generalization-folds.md:10-14` and `planner-section-reference.md:211-214`. *Alternatives:* options A/B/D in §3 — rejected per that table.
