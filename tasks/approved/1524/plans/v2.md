# Plan — #1524: verify_uploads merged card — prose pointer must not shadow a valid adapter_paths list

## 0.0 TL;DR (plain English)

- **What I'll change:** In `scripts/verify_uploads.py`, the function that merges reproducibility cards across a task's `epm:results` markers will stop letting a prose note like "unchanged from epm:results v1" overwrite an older marker's real list of adapter paths. ## 4. Design

### 4.1 Field-set decision (design question 1)

**Guard shape: a field-scoped structural-type check inside the merge fold — NOT a widening of `_is_declared`, NOT a general per-field validator map.**

- Widening `_is_declared` is wrong: it has 8 call sites (grep), and 6 of them legitimately test STRINGS — `_card_from_provenance` L518/521/529 (subfolder / run-name / top-level hint strings), `check_hf_model_from_card` L708 and `check_wandb_from_card` L897 (which NEED the string to be "declared" to fire the prose diagnostic), `_unconsulted_prose_wandb_note` L981. Any type-awareness must be keyed on the FIELD.
- A full per-field validator map is over-engineering for a 2-field contract; a module-level tuple + tiny predicate is the smallest shape that documents the contract.

**Field set: `("adapter_paths", "wandb_run_names")` — exactly the #612 structured-contract pair.** Justification:
- These are the only card fields downstream requires as dict/list: `check_hf_model_from_card` L704-709 (`adapter_paths`), `check_wandb_from_card` L896-900 (`wandb_run_names`). Both already have a `_prose_declaration_row` string branch — the pair is named together in its docstring (L647-649) and in SKILL.md Step 7 (L4909-4915).
- `wandb_run_names` is included beyond the Goal's literal `adapter_paths` because the shadow mechanism is byte-identical (a prose re-post string is truthy and wins the fold) and the Goal's operative clause is the mechanism ("extending the #601 empty-card protection to prose pointers"); fixing one field of the pair and leaving its documented twin exposed would be a half-fix the next incident re-files.
- **Legitimately-string fields stay accepted:** `hf_model_path` (L710), `hf_model_repo` (L689), `wandb_run_path`/`wandb_run` (L885), `wandb_project` (L901), `wandb_entity` (L903), `base_model`, `final_commit_sha`, `_card_provenance` — none are in the tuple, so newest-wins is unchanged for them (pinned by a new test).
- `eval_paths` is OUT: it is a PAYLOAD-level sentinel key (SKILL.md L4903), not a card field — `card.get("eval_paths")` appears nowhere in `verify_uploads.py`, so it never enters the merge fold.
- The guard is TYPE-based only. Heuristic prose detection on legitimately-string fields (e.g. the `wandb_run_path` whitespace/placeholder heuristic at L886-888) stays downstream where it already lives — duplicating a fuzzy heuristic at merge time risks discarding valid values.

### 4.2 Fallback semantics (design question 2): defer, don't drop

A naive `continue` on non-structural values (the candidate's diff sketch) has a regression: on a **prose-only history** (no marker ever declared a dict/list), the merged card would carry NO `adapter_paths` → `check_hf_model_from_card` returns `None` (L714-717) → the caller degrades to the generic strict-MISSING row, silently losing the #612 `_prose_declaration_row` diagnostic (`test_string_adapter_paths_names_contract_violation` would still pass — it calls the check function directly — but the end-to-end behavior would regress). Therefore: **two-pass deferred-fill** — bypass a non-structural declaration only when a structural one exists in ANY card; otherwise use the newest non-structural value as a last resort so the downstream diagnostic still fires.

### 4.3 Exact diff shape — `scripts/verify_uploads.py`

**(a) New module-level constant + predicate, immediately above `merged_results_card` (after `_is_declared`, ~L561):**

```python
# Card fields the epm:results sentinel contract requires as per-cell
# dicts/lists (SKILL.md Step 7; the #612 ``_prose_declaration_row`` pair).
# A prose-pointer string here ("unchanged from epm:results v1 ...") is
# truthy, so it would win the newest-wins fold and shadow an older
# marker's real declaration (#1489).
_STRUCTURED_CARD_FIELDS = ("adapter_paths", "wandb_run_names")


def _is_structural(key: str, value) -> bool:
    """False when a structured-contract field carries a non-dict/non-list."""
    return key not in _STRUCTURED_CARD_FIELDS or isinstance(value, (dict, list))
```

**(b) The fold (current L590-611) becomes:**

```python
    merged: dict = {}
    fallback_fields: dict[str, str] = {}
    # Newest non-structural value per structured field, kept as a LAST
    # resort (#1489): used only when no marker declares a dict/list, so a
    # prose-only history still reaches the #612 _prose_declaration_row
    # diagnostic downstream instead of degrading to a generic MISSING.
    deferred_nonstructural: dict[str, tuple[object, str, int]] = {}
    for pos, (card, ts) in enumerate(cards):
        for key, value in card.items():
            if key in merged or not _is_declared(value):
                continue
            if key.startswith("_") and pos > 0:
                # (existing comment unchanged)
                continue
            if not _is_structural(key, value):
                deferred_nonstructural.setdefault(key, (value, ts, pos))
                continue
            merged[key] = value
            if pos > 0:
                fallback_fields[key] = ts
    bypassed_prose: list[str] = []
    for key, (value, ts, pos) in deferred_nonstructural.items():
        if key in merged:
            bypassed_prose.append(f"{key} @ {ts}")
            continue
        merged[key] = value
        if pos > 0:
            fallback_fields[key] = ts
    notes: list[str] = []
    if fallback_fields:
        notes.append(
            "field(s) declared by an earlier epm:results marker, not the latest: "
            + ", ".join(f"{k} @ {ts}" for k, ts in sorted(fallback_fields.items()))
        )
    if bypassed_prose:
        notes.append(
            "non-structural (prose) declaration(s) bypassed in favor of a "
            "structural value from another marker (#1489): "
            + ", ".join(sorted(bypassed_prose))
        )
    if notes:
        note = "; ".join(notes)
        existing = merged.get("_card_provenance")
        merged["_card_provenance"] = f"{existing}; {note}" if existing else note
    return merged or None
```

Semantics, case by case (cards iterate newest→oldest, L579 `reversed(events)`; `setdefault` keeps the NEWEST non-structural value):
- **#1489 shape (newest prose, older dict):** dict merges from `pos>0` → existing fallback note fires (`adapter_paths @ <older-ts>`); prose lands in `bypassed_prose` → second note clause names the bypassed ts. Merged card carries the dict.
- **Prose-only (single card, or prose across all cards):** deferred value fills `merged` after the fold; behavior identical to today (prose reaches `check_hf_model_from_card` → #612 row; provenance note only when the prose came from `pos>0` — exactly matching today's fold).
- **Empty values (`""`/`{}`/`[]`/None):** rejected by `_is_declared` BEFORE the structural check, never deferred — #601 semantics byte-preserved.
- **Non-str non-structural scalars (int/bool):** same deferred path; downstream ignores them (L704-709 falls through) → generic MISSING, same as today.
- **`_`-prefixed provenance keys:** untouched (not in the tuple; existing pos-0-only rule unchanged).

**(c) Docstring updates (same file):** one sentence each in the `merged_results_card` docstring (L564-577) and the module docstring merge paragraph (L43-48): a non-dict/non-list declaration of a structured-contract field does not count as a declaration when a structural one exists; it is kept only as a last resort so the #612 diagnostic still fires (#1489).
