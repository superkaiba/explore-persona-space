**Method delta vs the existing #825 coverage:** the ownership-check bullet (§ "Orchestrator vs subagent re-invocation", L100) covers (i) duplicate-launch ownership probing and (ii) the EMPTY-dir false-DONE ("Monitor DONE with no outputs" → verify-first). **File:** `CLAUDE.md`. **Insertion point:** end of the § Monitoring (MANDATORY) bullet list — a new line after current L464 (`- Report results immediately on completion.`). **Verbatim bullet (the complete diff, +1 line):**

```diff
 - Always: `grep -iE 'error|traceback|killed|OOM' logfile`.
 - Report results immediately on completion.
+- **Re-runs: never key a Monitor/until-loop "done" condition on bare file existence.** When re-running a script whose output path already exists, key the condition on process exit (pid gone / a sentinel carrying the exit code) or a fresh output mtime newer than the launch timestamp — a stale prior-version artifact satisfies an existence check instantly (#779, 2026-07-15: an until-loop fired "done" on a pre-existing v1 JSON while the v2 re-run was still executing; the stale-EXISTING-file sibling of the #825 empty-dir false-DONE covered by the ownership-check bullet in § "Orchestrator vs subagent re-invocation").
```
