# Plan v1 — #2245: guard `shared_fold_map.json` on main (smoke-map substitution trap)

**Kind:** infra (bug-fix category — CLAUDE.md `/adversarial-planner` carve-out applied; minimum
plan-review floor: this plan version + `verify_plan.py` + one Claude critic).
**Parent:** #2054 (artifact provenance defect on `main`; no banked #2054 result is impugned).

## Requirement

`eval_results/issue_2054/shared_fold_map.json` on `main` is a 1,761-conversation SMOKE map
(k=5, seed=137 — both matching production, so shallow sanity checks pass), while the
production map #2054 actually ran on has 26,889 conversations across 5 variants and lives only
as the `origin/issue-2054` branch blob. Any consumer reaching for the canonical path silently
fits on the smoke map. Make the canonical path BE the production map, and make every loader
fail LOUD on a sub-production map.

## Acceptance criteria (from task body, with the criterion-1 decision recorded)

1. **Decision: option (a)** — commit the PRODUCTION map at the canonical path (matches the
   promoted #2054 Methodology; survives eventual branch deletion). Additionally preserve the
   smoke artifact under the unmistakable name `shared_fold_map.SMOKE.json` (forensic
   provenance, 43 KB).
2. Loader-side guard: promote the proven smoke-refusal floors (`n_conv >= 20,000`,
   `variants >= 5`, from `issue2054_cross_render_fit._load_production_fold_map`) into a shared
   guarded loader; failure is a loud raise naming counts and floors.
3. Route every unguarded reader through the guarded loader; disposition the rest.
4. Do NOT regenerate or alter the production map; do NOT touch banked per-cell fit JSONs.

- REUSED: the floor values + refusal message shape from

## File paths + concrete changes

1. **Artifact swap** (in the issue worktree; `git -C "$WT" sparse-checkout add
   eval_results/issue_2054` first — the sparse worktree excludes other issues' eval_results):
   - Write the current smoke bytes to `eval_results/issue_2054/shared_fold_map.SMOKE.json`
     (byte-verbatim copy of today's on-main file; no content edits — the filename is the
     marker).
   - Overwrite `eval_results/issue_2054/shared_fold_map.json` with the verbatim branch blob:
     `git show origin/issue-2054:eval_results/issue_2054/shared_fold_map.json > <path>`.
     **Verification (hard gate):** `git hash-object` of the written file MUST equal
     `git rev-parse origin/issue-2054:eval_results/issue_2054/shared_fold_map.json`
     (byte-identity with the blob #2054 ran on), AND a JSON read must show
     `n_conv_ids == 26889 == len(fold_of)`, `k == 5`, `seed == 137`, 5 variants.
2. **New shared guarded loader** — `scripts/issue2054_fold_map.py` (dependency-free: json,
   pathlib):
   - `FOLD_MAP_MIN_CONV = 20_000`, `FOLD_MAP_MIN_VARIANTS = 5` (single going-forward source).
   - `load_fold_map(path, *, allow_smoke: bool = False) -> dict`: FileNotFoundError on missing
     file; ValueError on missing `fold_of`/`k`/`seed` keys or empty/non-dict `fold_of`;
     RuntimeError (loud, names counts + floors + the smoke-map history) when
     `len(fold_of) < FOLD_MAP_MIN_CONV` or `len(variants) < FOLD_MAP_MIN_VARIANTS`, unless
     `allow_smoke=True`.
3. **Route the three unguarded consumers** (import via the repo's existing sibling-script
   convention — match how existing `scripts/` files import each other):
   - `scripts/issue2054_fits.py` — `_load_fold_map` delegates to the shared loader; new
     argparse flag `--allow-smoke-fold-map` (default False) threaded through (fits has
     legitimate smoke legs; they now opt in explicitly).
   - `scripts/issue2054_ladder.py` — same change (its `_load_fold_map` is a duplicate of
     fits.py's).
   - `scripts/issue2054_phase_d.py` — `_load_shared_fold_map` validates via the shared loader
     before deriving the membership set; the existing `--no-fold-filter` smoke opt-out stays;
     add the same `--allow-smoke-fold-map` flag for explicitly-passed smoke maps.
   - **Dispositions (recorded, no code change):** `issue2054_cross_render_fit.py`,
     `issue2054_ctx2ctx_fit.py`, `issue2054_fetch_ladder_rows.py` already implement the
     identical floors (branch-blob loaders) — left unchanged (proven production code; the
     shared module is the canonical going-forward path). `issue2054_phase_a.py` is the
     PRODUCER (writes what it computes; a smoke run writing a smoke map to its own out-root is
     legitimate) — unchanged; the committed-artifact regression test below is what prevents a
     future smoke map from being re-committed at the canonical path.
4. **Regression pin test** — `tests/test_issue2054_fold_map.py`:
   - Unit tests of `load_fold_map` on synthetic tmp_path maps: floor refusal on a
     1,761-shaped map; `allow_smoke=True` passes it; missing-key ValueError; production-shaped
     map passes.
   - **The durable pin:** the COMMITTED `eval_results/issue_2054/shared_fold_map.json` has
     `n_conv_ids >= 20_000`, `len(fold_of) == n_conv_ids`, `>= 5` variants, `k == 5`,
     `seed == 137` — any future re-substitution of a smoke map at the canonical path becomes
     an instant repo-wide test failure.
   - **Sparse-worktree gate (CLAUDE.md #671):** the pin test hard-reads
     `eval_results/issue_2054/` → add that dir to `tests/sparse_cones.txt` in the same diff.
5. **HF cross-check (report-only):** read the header of
   `issue2054_lattice/shared_fold_map.json` on the HF data repo
   (`superkaiba1/explore-persona-space-data`) and report whether it is the production map
   (expect n=26,889). No mutation, no gating — informational line in the implementation
   report.
