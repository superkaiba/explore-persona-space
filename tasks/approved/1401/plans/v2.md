```bash
#!/bin/bash
# Source this file to define the pod git-auth constants (#1239, #1401).
# Requires: $REMOTE_DIR set to the pod repo dir (the helper's .env-fallback
# path is baked in at expansion time). Consumers: bootstrap_pod.sh,
# sync_env_keys.sh. Single source of truth — do NOT redefine these
# elsewhere (drift risk; quoting invariant pinned by
# tests/test_bootstrap_pod_git_credentials.py).

if [ -z "${REMOTE_DIR:-}" ]; then
    echo "ERROR: _git_cred_helper.sh requires \$REMOTE_DIR to be set before sourcing" >&2
    return 1 2>/dev/null || exit 1
fi

# Tokenless public HTTPS remote (#1239, mirrors gcp.py DEFAULT_REPO_URL ...)
REPO_URL_TOKENLESS="https://github.com/superkaiba/explore-persona-space.git"

# Env-reading git credential helper (#1205 GCE-parity, pod flavor). ...
# [full existing comment block moved verbatim]
GIT_CRED_HELPER="!f() { tok=\"\${GITHUB_TOKEN:-}\"; if [ -z \"\$tok\" ] && [ -r $REMOTE_DIR/.env ]; then tok=\"\$(. $REMOTE_DIR/.env >/dev/null 2>&1; printf %s \"\${GITHUB_TOKEN:-}\")\"; fi; echo username=x-access-token; echo \"password=\${tok}\"; }; f"
```

The per-pod function (near-final; exact strings matter — tests pin them):

```bash
refresh_git_pod() {
    local name="$1" host="$2" port="$3"
    echo "[$name] Refreshing git auth (.env + config convergence + probe)..."

    # 1. Fresh .env (whole file — the credential helper reads GITHUB_TOKEN from it).
    push_pod "$name" "$host" "$port" || return 1

    # 2. Converge git config to the #1239 contract. Idempotent. NO fetch/pull/
    #    checkout — a mid-lifecycle pod's working tree + branch are never touched.
    #    Single-statement `git -C` calls (experimenter-memory convention).
    ssh $SSH_OPTS -p "$port" "root@$host" \
        "git -C $REMOTE_DIR remote set-url origin '$REPO_URL_TOKENLESS' || git -C $REMOTE_DIR remote add origin '$REPO_URL_TOKENLESS'" || {
        log_fail "[$name] remote set-url failed — no repo at $REMOTE_DIR? (fix: pod.py bootstrap $name)"; return 1; }
    ssh $SSH_OPTS -p "$port" "root@$host" \
        "git -C $REMOTE_DIR config --replace-all credential.https://github.com.helper '$GIT_CRED_HELPER'" || {
        log_fail "[$name] repo-local helper config failed"; return 1; }
    # Global helper + legacy-store scrub (mirrors bootstrap_pod.sh step 7 verbatim).
    ssh $SSH_OPTS -p "$port" "root@$host" \
        "git config --global --replace-all credential.https://github.com.helper '$GIT_CRED_HELPER'
git config --global --unset-all credential.helper 2>/dev/null || true
rm -f /root/.git-credentials" || {
        log_fail "[$name] global helper config/scrub failed"; return 1; }
    log_ok "[$name] git config converged (tokenless remote + host-scoped env-reading helper)"

    # 3. AUTHENTICATED probe: dry-run push exercises the REAL helper+token path
    #    on the git-http receive-pack endpoint (GitHub 401s anonymous
    #    receive-pack advertisement -> git invokes the helper -> retries with
    #    the token). --dry-run sends no pack and updates no refs; the probe ref
    #    is a dry-run branch CREATE (refs/heads/eps-auth-probe does not exist
    #    remotely, verified 2026-07-16) so it can never be rejected
    #    non-fast-forward. GIT_TERMINAL_PROMPT=0 + timeout 60 bound the probe.
    local probe_out probe_rc
    probe_out=$(ssh $SSH_OPTS -p "$port" "root@$host" \
        "GIT_TERMINAL_PROMPT=0 timeout 60 git -C $REMOTE_DIR push --dry-run origin HEAD:refs/heads/eps-auth-probe" 2>&1) \
        && probe_rc=0 || probe_rc=$?
    if [ "$probe_rc" -eq 0 ]; then
        log_ok "[$name] push auth VERIFIED (authenticated dry-run push OK)"
        return 0
    fi

    # Fail LOUD with the probe output + failure-class discrimination. ONE probe,
    # no retry loop (the r10 class is not code-fixable).
    echo "$probe_out" | sed 's/^/    /'
    if echo "$probe_out" | grep -qE 'returned error: 40[13]|HTTP [^ ]* 40[13]|Authentication failed|Permission .* denied|could not read Username'; then
        # Discriminate token validity: repo-scoped API probe. Token is read from
        # the POD .env pod-side; header rides stdin (curl -H @-) — the value
        # never enters any argv on VM or pod (printf is a shell builtin).
        local api_code
        api_code=$(ssh $SSH_OPTS -p "$port" "root@$host" \
            '. /workspace/explore-persona-space/.env >/dev/null 2>&1; printf "Authorization: Bearer %s\n" "${GITHUB_TOKEN:-}" | curl -sS --max-time 30 -o /dev/null -w "%{http_code}" -H @- https://api.github.com/repos/superkaiba/explore-persona-space' 2>/dev/null) \
            || api_code="api-probe-failed"
        if [ "$api_code" = "200" ]; then
            log_fail "[$name] git-http push auth still 40x with a VALID token (repo-scoped API probe: 200) and a converged #1239 config."
            echo "    #1315-r10 class: suspected pod egress-IP git-http block (root cause UNCONFIRMED) — not code-fixable."
            echo "    Escalate to bundle-sideload: .claude/rules/gotchas.md § 'Pod git fetch 403 with a VERIFIED-VALID token'."
        else
            log_fail "[$name] GITHUB_TOKEN is itself invalid/insufficient (repo-scoped API probe: $api_code)."
            echo "    Rotate GITHUB_TOKEN in the VM .env ($LOCAL_ENV), then re-run: uv run python scripts/pod.py keys --refresh-token $name"
        fi
    else
        log_fail "[$name] probe failed for a non-auth reason (rc=$probe_rc) — see output above (network / timeout / repo state)."
    fi
    return 1
}
```

Main loop gains the mode branch (`refresh_git_pod "$name" "$host" "$port" || failed=$((failed+1))` — NOTE: the `failed=$((failed+1))` assignment form, not `((failed++))`, which returns rc 1 when the pre-increment value is 0 and would trip `set -e`), and a refresh-mode summary line.

**What the operator sees per failure class:**

| Pod state | Outcome |
|---|---|
| Stale `.env` token / empty helper / tokened remote URL / legacy store (#1315 r7, #1333 class) | steps 1-2 repair it → probe PASSes → `✓ push auth VERIFIED`, exit 0 |
| Valid token, converged config, git-http still 403 (#1315 r10 class) | probe output printed, `API probe: 200` classification, pointer to the gotchas bundle-sideload entry, exit 1, NO retry |
| Token itself invalid/expired in VM `.env` | `API probe: 401` classification, "rotate GITHUB_TOKEN in the VM .env" instruction, exit 1 |
| VM `.env` missing GITHUB_TOKEN | VM-side fail-fast before any SSH, exit 1 |
| Pod unreachable / no repo | per-step `log_fail` naming the failed step, exit 1 |

## 6. Kill criteria

1. **Hollow probe:** the §3.6 negative control (invalid token) does NOT fail the dry-run push — i.e. GitHub serves receive-pack advertisement anonymously / the helper is never invoked. Then the dry-run probe is not an auth probe → replace primary probe with the repo-scoped API probe + a REAL push of an ephemeral probe ref (create then delete via `git push origin :refs/heads/eps-auth-probe-<ts>`), and re-plan the mutation-safety story.
2. **Shallow-clone push failure:** the `--depth=1` scratch smoke fails for shallow-history reasons with a VALID token → the probe would false-fail on fresh pods. Mitigation ladder: probe falls back to API-probe-only on a detected shallow error string; if unresolvable, demote the dry-run probe to best-effort + API probe primary.
3. **Extraction breaks the quoting invariant** in a way the moved functional tests cannot re-pin (e.g. sourcing order forces a different escape shape) → abandon the shared lib; fall back to runtime-extraction of the assignment line from `bootstrap_pod.sh` (`grep '^GIT_CRED_HELPER="' | eval` — the same materialization the existing test uses), keeping one definition.
4. If any of these fire AND no fallback in-scope works, the task deflects to a reasoned no-change/descope report (workflow-fix sessions may deflect).

## 11. Decision Rationale

N/A — no model training

**D1 — UX placement: `pod.py keys --refresh-token` (a mode on `sync_env_keys.sh`).**
What: new mode flag on the existing keys backend. Why: the leg's first action IS the `.env` push that `sync_env_keys.sh` already implements (`push_pod`), and the mode reuses `parse_pods` targeting + `SSH_OPTS` + log helpers with zero duplication; the flag name matches the task Goal's own wording and the operator's mental model ("my token went stale"). Source: task #1401 `## Goal` + `epm:clarify` marker (2026-07-16T16:47Z); `scripts/sync_env_keys.sh` L51-109 (read). Alternatives: (a) fold into `keys --push` unconditionally — rejected: adds git-config mutation + a network probe + new failure modes to an existing command other flows call; (b) new leg on `sync env` — rejected by the clarifier resolution (`sync_env.sh` is code+uv sync; a git-auth side effect there is surprising) — it gets the redirect hint instead; (c) new top-level `pod.py git-auth` subcommand — rejected: a new public CLI surface + duplicated pods.conf plumbing for the same behavior; (d) re-run `pod.py bootstrap` — rejected: step 4 checkouts `main` and pulls, mutating a mid-lifecycle pod's branch/tree (§2).

**D2 — Verification probe: `git push --dry-run origin HEAD:refs/heads/eps-auth-probe` primary; repo-scoped API probe as failure discriminator.**
What: authenticated dry-run push, bounded by `GIT_TERMINAL_PROMPT=0 timeout 60`. Why: it exercises the EXACT production path the token exists for — the credential helper invoked by git against the git-http receive-pack endpoint — which neither `git ls-remote origin` (anonymous on the tokenless public remote; never invokes the helper) nor the API probe (different endpoint; #1315 r10 proved API-200 and git-http-403 coexist) can do; `--dry-run` sends no pack and updates no refs, and the probe ref is a branch CREATE (verified absent on the remote 2026-07-16 via `git ls-remote`) so a behind-tip pod can never false-fail non-fast-forward. The API probe is retained ONLY to discriminate token-invalid vs the unconfirmed egress-block class on failure. Source: gotchas.md ~L308 (the API-200/git-403 coexistence + validity-probe recipe); `git-push(1)` `--dry-run` semantics, de-risked by the §3.6 positive+negative smoke before landing. Alternatives: (a) `git ls-remote` per the Goal text — rejected: tokenless fetch never exercises the token (clarifier-resolved Goal refinement); (b) API probe primary — rejected: doesn't test the helper wiring or the git-http endpoint (the two things that actually broke); (c) real push of an ephemeral ref + delete — rejected for v1: mutates the remote and needs cleanup on crash; kept as the kill-criterion-1 fallback.

**D3 — Shared helper definition: extract to `scripts/_git_cred_helper.sh`; both consumers source it.**
What: one sourceable file defining `REPO_URL_TOKENLESS` + `GIT_CRED_HELPER`, `REMOTE_DIR`-parameterized, fail-loud if `REMOTE_DIR` unset. Why: a duplicated helper literal WILL drift (the #622 stale-pin lesson: one literal in N files), and the quoting invariant is subtle enough that drift is dangerous; the existing pinned tests transfer by re-pointing their read target at the lib, and the functional materialization tests re-verify the invariant post-move. Source: `tests/test_bootstrap_pod_git_credentials.py` (read — the tests materialize the assignment line via bash, so they are read-target-portable); `_pods_conf_path.sh` precedent for shared sourceable snippets under `scripts/`. Alternatives: (a) duplicate the literal in `sync_env_keys.sh` — rejected: drift; (b) runtime-grep the assignment out of `bootstrap_pod.sh` — workable (it is what the test does) but fragile to comment/format churn; kept as kill-criterion-3 fallback; (c) generate from Python — rejected: adds a language boundary to a pure-bash consumer set.

**D4 — Failure policy: one probe, loud classification, no retry loop.**
What: on probe failure, print output + classify (valid-token→sideload pointer / invalid-token→rotate instruction / other→raw) and exit 1. Why: the r10 class has an UNCONFIRMED root cause that code cannot fix — retrying burns the launch window (the #1315 r10 lesson: "stop debugging auth and sideload"); fail-fast + correct pointer is the whole value of the classification. Source: gotchas.md ~L308 RULE text; clarifier resolution item 3. Alternatives: bounded retry with backoff — rejected: a transient github.com blip is already covered by the operator re-running one command; an egress block never clears via retry.

**D5 — Secrets hygiene mechanics.**
What: token flows only via (i) `scp` of the `.env` FILE, (ii) pod-side subshell sourcing inside the helper (the #1239 shape), (iii) pod-side `printf | curl -H @-` (header via stdin; printf is a shell builtin → no process argv anywhere). VM-side remote strings that reference `$GITHUB_TOKEN` are single-quoted so expansion happens only pod-side. Why: the hard constraint — never in argv/`ps`, never echoed, never in git config/URLs. Source: `bootstrap_pod.sh` L44-63 comment block + `check_no_secret_shaped_strings.py` discipline; curl `-H @-` supported since 7.55 (image ships 7.81). Alternatives: `curl -H "Authorization: Bearer $tok"` — rejected: token transits pod `ps` argv; a VM-side API probe reading the VM `.env` — rejected: probes the VM's egress, not the pod's (the r10 class is pod-egress-specific).

**D6 — `sync env` redirect hint rather than silent fix.**
What: additive 40x-detection + hint line in `sync_env.sh`'s failure path. Why: makes the documented wrong-first-reflex self-correcting without giving an env-sync command a git-config-mutating side effect. Source: #1333 incident transcript (operator ran `sync env` first); design constraint in the task brief. Alternatives: fold repair into `sync env` — rejected (surprising side effect, and `sync env`'s own git pull would still run before repair).
