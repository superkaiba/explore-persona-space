## §0.0 TL;DR

Replace `.lower()` with `.casefold()` at every regex-`group()` token
normalization in `scripts/verify_task_body.py` (26 sites, 24 functions), and
pin the invariant with an AST-based ratchet test plus two behavioral pins that
reproduce the defect end-to-end. `re.IGNORECASE` performs FULL Unicode case
folding while `str.lower()` does not, so an `IGNORECASE` regex can MATCH a
token its own `.lower()` normalization then fails to map onto the expected
ASCII key — at `:16819` that raises `ValueError` and, because the verify
driver has no per-check `except`, takes down the ENTIRE verifier run.

**Change my mind:** if a body carrying `ſix` (U+017F) in the
`<N> same-issue follow-up rounds` footer clause does NOT crash the verifier
before the fix, the defect is not what this plan says it is and the design is
wrong. Conversely, if converting any of the 26 sites changes a verdict on a
pure-ASCII body, the conversion is not behavior-preserving and the sweep must
narrow to the crash sites alone.

## §2 Background — the mechanism and why it recurs

`re.IGNORECASE` matches via full Unicode case folding; `str.lower()` performs
simple lowercasing. The two disagree on every full-folding character. The
canonical trigger is **U+017F LATIN SMALL LETTER LONG S** (`ſ`), which
`IGNORECASE` matches against `s` and which `.lower()` leaves unchanged while
`.casefold()` maps to `s`. Others in the same class: `ß` → `ss`, `µ` (U+00B5
MICRO SIGN) → `μ`, `İ` → `i̇`, the ligatures `ﬁ`/`ﬀ`.

The class is **structural, not a typo**: any site pairing an `IGNORECASE`
regex with a `.lower()` normalization is defective by construction, and the
file has 24 functions doing exactly that. It is also **not hypothetical** —
a scan of all 2,213 live `tasks/**/body.md` files found one already carrying a
full-folding character (`tasks/completed/1967/body.md`, U+00B5 MICRO SIGN);
that instance does not sit in a triggering position, but it establishes that
such characters reach committed bodies.

**Prior art — the reference fix.** Commit `0403597c730366af2b45be7486f34d6308080329`
("task #2279: check 58 — casefold ordinal/direction tokens (Unicode long-s
crash)") fixed the identical defect in `_positional_crossref_tokens`: a
long-s number word missed `_CROSSREF_NUMBER_WORDS` → `KeyError` → whole-verifier
crash, and a long-s spelling of `previous` failed an `== "previous"` compare,
silently flipping the resolved direction from `up` to `down`. It added
`test_positional_crossref_unicode_casefold_tokens` pinning both arms, and its
inline comment block is the house wording for this class. This task is the
pre-existing-sibling sweep that round surfaced.

**Merge ordering (recorded, not a blocker).** That commit lives on
`issue-2279` (task #2279, `running`, its own live session), NOT on `main` —
`_positional_crossref_tokens` and check 58 do not exist on `main` at all, so
this task's sweep and #2279's hunks touch disjoint regions of the file. The
worktree cuts from fetched `origin/main` (`new_worktree.sh` default), so the
#2279 hunks are absent here by construction and cannot be double-applied.

**Reproduction (run against the live module before any edit):**

```

.lower() -> 'ſix' | .casefold() -> 'six'
```

## §3 Design

### §3.1 The three risk classes (all 26 `.group(...).lower()` sites)

| Class | Consequence | Sites |
|---|---|---|
| **Crash** — result feeds a dict key or `int()` | `ValueError`/`KeyError` → whole-verifier crash | `:16819` `_count_extra_followup_rounds_v4` (**confirmed reachable**); `:10635` `_beat_series_claims` (`_BEAT_WORD_TO_KIND[...]` bare subscript; alternation `bar\|point\|dot\|marker\|line\|curve` has no `s`, so **not currently reachable**) |
| **Semantic misfire** — set membership / slug match | a guard silently fails to fire → spurious or missing claim | `:14585`, `:14598`, `:14605` (`_CC_UNIT_STOPWORDS` / `_CC_NO_QUALIFIERS` — the latter contains `such`, so `ſuch` escapes the skip-guard and registers a bogus count claim); `:16645` (`_FOLLOWUP_SOURCE_SLUGS`); `:3474` (set add); `:6411`, `:12688` (normalized token carried into a downstream compare) |
| **Fail-closed** — `_THIS_REPO_SLUG` equality | URL treated as not-this-repo → check skips | 17 sites: `:3016 :3129 :3244 :8137 :8442 :9344 :9622 :10160 :10550 :10924 :12743 :13156 :13686 :13870 :14035 :14284 :14895` |

### §3.2 Scope decision — convert all 26, not only the IGNORECASE-fed subset

The Goal's literal scope is "IGNORECASE regex AND dict-key/equality/`int()`
operand". This plan converts **all 26** `.group(...).lower()` sites — a
deliberate superset — for three reasons:

1. **Behavior-preserving.** `str.lower()` and `str.casefold()` are identical
   on ASCII. A case-SENSITIVE regex over ASCII-only alternations therefore
   sees no change at all; converting it is a no-op in behavior and a
   consistency win in the source.
2. **It buys a mechanically enforceable invariant.** With zero
   `.group(...).lower()` remaining, an AST ratchet test (§3.4) prevents the
   whole class from being reintroduced. A partial sweep leaves the ratchet
   unstatable and the next author reproducing the bug.
3. **It is what the task body asks for.** Scope item 2 explicitly names the
   `_THIS_REPO_SLUG` comparisons — the fail-closed class — as "the same class"
   and directs the sweep to include them.

Sites are still CLASSIFIED individually (the §3.1 table, reproduced per-site
in the implementer report with each regex's `IGNORECASE` flag read off its
compiled pattern) so the review can audit the reasoning, not just the diff.

### §3.3 Direction-of-change analysis (why no ASCII verdict moves)

Every conversion is a no-op on ASCII input, so no existing body's verdict can
change. On non-ASCII input the changes are corrections, and their directions
are asymmetric — stated here so the reviewer can check them rather than
assume them:

- **Crash class:** `ValueError`/`KeyError` → a resolved value. Strictly better.
- **Fail-closed class:** more URLs correctly recognized as this-repo ⇒ MORE
  checks run ⇒ a body could newly FAIL. That is the intended direction (the
  check was being skipped on a technicality).
- **Semantic-misfire class:** more tokens hit their stopword/slug set ⇒ MORE
  guards fire ⇒ FEWER spurious claims ⇒ a body could newly PASS. Also the
  intended direction.

### §3.4 The invariant and its ratchet

Post-sweep invariant: **`scripts/verify_task_body.py` contains zero
`<match>.group(...).lower()` expressions.** Pinned by an AST test, not a text
grep — the AST form is immune to line breaks, intervening whitespace, and
comments (a `.group(\n    "num"\n).lower()` split across lines evades a
single-line regex and is caught here).

Detection: walk the module AST for `Call(func=Attribute(attr="lower"),
args=[], keywords=[])` whose `func.value` is itself
`Call(func=Attribute(attr="group"))`. Report file + line + the offending
source segment on failure.

**Named residual (disclosed, not covered):** the ratchet sees only the DIRECT
`group().lower()` chain. An INDIRECT site — `tok = m.group("x")` on one line
and `tok.lower()` later — evades it. §4 step 2 enumerates those by one-hop
local dataflow and converts them, but no static ratchet guards against a
future one; the code-review lens is the catching arm, exactly as for the
sibling classes in `.claude/rules/smoke-blind-spots.md`.

## §4 Implementation

1. **Enumerate + classify.** For each of the 26 direct sites: resolve the
   regex variable feeding the match object, read its `re.IGNORECASE` flag off
   the compiled pattern object (not the source text), and record
   consumer-kind (dict key / bare subscript / set membership / equality /
   `int()` / display). Produce the table in the implementer report.
2. **Enumerate indirect sites.** AST pass over the module: within each
   function scope, find names assigned from a `.group(...)` call and flag any
   later `<name>.lower()`. Classify and convert on the same criteria; report
   the enumeration even when it is empty (auditable-N/A).
3. **Convert.** `.lower()` → `.casefold()` at every enumerated site. Add ONE
   explanatory comment block at the `:16819` crash site (the reference-fix
   wording from `0403597c73`, adapted); the remaining sites get no per-site
   comment — 26 copies of the same paragraph is noise, and the ratchet test's
   docstring carries the rationale for the class.
4. **Tests** (§5).
5. **Lint:** `uv run ruff check . && uv run ruff format .`, then the no-flags
   `uv run python scripts/workflow_lint.py`.

## §5 Tests

Three new tests in `tests/test_verify_task_body.py`, mirroring the shape of
`test_positional_crossref_unicode_casefold_tokens` (the `0403597c73` pin):

1. **`test_followup_round_budget_unicode_casefold`** — the confirmed-reachable
   crash arm. A v4 footer clause reading `... ſix same-issue follow-up rounds
   ...` resolves to a round budget of 6, exercised through the PUBLIC check
   that consumes `_count_extra_followup_rounds_v4` (not the private helper
   alone), so the pin proves the whole-verifier crash is gone rather than just
   the arithmetic. **Verified to FAIL before the fix** (`ValueError`) — a pin
   that does not reproduce the defect first is not evidence.
2. **`test_beat_series_claims_unicode_casefold`** — the `:10635` consistency
   arm. Because the live alternation has no `s`, the pin uses a
   `monkeypatch`-installed regex/map pair exercising the same code path with an
   `s`-bearing alternative, and asserts no `KeyError`. If that proves to
   require restructuring the helper, the fallback is an explicit
   `pytest.mark.xfail`-free assertion that the site now calls `.casefold()`
   (covered by test 3) plus a report note — never a silently dropped pin.
3. **`test_no_group_lower_in_verify_task_body`** — the AST ratchet of §3.4.
   Asserts the offending-node list is empty; on failure prints every
   `file:line` + source segment so the next author sees exactly which site
   regressed.

Regression surface: `uv run pytest tests/test_verify_task_body.py` in full
(the file is the file this change is about), plus the Step 9c mapped selection
for the two touched paths.

## §11 Decision rationale

| Decision | Value | Source |
|---|---|---|
| Normalizer | `.casefold()` | Python docs: `str.casefold()` performs full case folding, matching `re.IGNORECASE`'s own fold; `str.lower()` does not. Precedent: `0403597c73` (#2279) used exactly this for the identical defect. |
