## Requirement + acceptance criteria

**Requirement.** `scripts/workflow_lint.py::_hf_routing_file_errors` (the
`[live-hf-retry-routing]` check, #1547) must stop flagging HF Hub call TEXT that
appears inside non-f-string literals (module/function docstrings, any
triple-quoted or plain quoted string) and inside comments, while continuing to
flag every real bare call site exactly as today — INCLUDING a real call inside
an f-string replacement field, which on py3.11 tokenizes as part of one STRING
token (no new under-flag class; the check is a 429-SPOF detector and under-flag
is strictly worse than the over-flag being fixed). Both consumers share the fix
for free: `check_live_hf_retry_routing` (no-flags verdict) and
`regen_hf_routing_snapshot` (offender enumeration) call the same helper.

**Why now (verified 2026-08-26, clarifier marker).** The Schema-from-artifact
rule (experiment-implementer § "Before writing code" item 8) MANDATES pasting
the exact probe command — typically `hf_hub_download(...)` +
`torch.load(hf_hub_download(...))` — into a module docstring, so every
compliant consumer of a banked HF artifact trips a false FAIL. The originally
named live hit (`scripts/issue2223_casestudy_replay.py:45`) was dodged in
commit `9f37157924` by rewording the docstring to "hub-download", degrading the
probe record — the workaround itself demonstrates the standing compliance cost.
A synthetic docstring-only fixture produces 2 false errors on the current tree.

**Acceptance criteria** (each is a committed test):
1. A file whose ONLY `HF_ROUTING_CALL_RE` matches are inside a module docstring
   → 0 errors.
2. A file with an `hf_hub_download(...)` inside a docstring AND a real bare
   call site → exactly 1 error, naming the real call's line number (the
   regression pin from the task body).
3. A real bare call on a line where an EARLIER match on the same line is inside
   a string (a single-line string literal containing the call text followed by
   a real call later on the same line) → still flags (the per-line match
   selection takes the first NON-exempt match, not `re.search`'s first match).
4. HF-call text inside a trailing `#` comment (not a line-leading comment,
   which the existing lstrip-`#` fast path already skips) → 0 errors (same
   text-not-a-call class; COMMENT tokens carry the same span exemption).
5. **A real bare call inside an f-string replacement field still flags** —
   fixture `p = f"{hf_hub_download('r', 'f')}/x"` in a scanned scope root →
   exactly 1 error on py3.11 (the repo interpreter, 3.11.15). This is the
   round-1 Must-Fix pin: f-prefixed STRING tokens are NEVER masked, so the
   py3.11 single-STRING-token f-string cannot swallow a real call.
6. **Tokenize-failure fallback committed as a test**: a file with an
   unterminated triple-quote (raises `tokenize.TokenError`) containing a bare
   call line → the helper returns None spans, the scan falls back to the
   pre-#2355 no-exemption behavior, the bare call still flags, and the lint
   does not crash.

Fail-loud pin: tests/test_workflow_lint.py::test_check_live_hf_retry_routing_tokenize_failure_falls_back_and_flags — pytest.raises-free positive control: the TokenError fixture's bare call still emits an error line, so the fallback never silently swallows the file.
7. Every existing test in `tests/test_workflow_lint.py`'s #1547 block passes
   unchanged (wrap detection, `what=` skip, NO_RETRY waiver, adjacent-wrap
   no-laundering, frozen-snapshot / pattern-string / generated-code
   exemptions, live-tree pass).
8. The emitted error-message text is byte-identical to today's (the #1568
   message-edit hazard: the Step 10d merge gate compares normalized message
   lines; a reworded message would false-register as NEW against baselines).
9. The fix can only REMOVE error lines relative to today (string/comment spans
   are exemptions; f-strings are excluded from the mask, so their behavior is
   unchanged from today) — no repo file newly flags and the
   `HF_ROUTING_FROZEN_SNAPSHOT` needs no regen in this round.

## Method delta (what differs from the current implementation)

Current: pure line-regex scan; only line-leading `#` and `what=` prefixes are
skipped, so string content matches.

Chosen fix: **`tokenize`-based span exemption with an f-string carve-out** —
compute, per file, the set of (line, col-range) spans covered by
NON-f-prefixed STRING tokens and COMMENT tokens via
`tokenize.generate_tokens`, and reject any regex match whose start position
falls inside such a span. F-string masking policy, by interpreter:
- **py3.11 (the repo interpreter):** an f-string is ONE `STRING` token whose
  replacement fields may contain REAL calls — so any STRING token whose prefix
  letters (the characters before the opening quote, e.g. `f`, `rf`, `F`)
  contain `f`/`F` is NOT masked. Docstrings and the Schema-from-artifact probe
  blocks can never be f-strings, so the false-positive class being fixed is
  untouched; f-string literal TEXT containing call text keeps today's
  (over-flag) behavior — no regression in either direction.
- **py3.12+ (future-proofing only):** `FSTRING_START`/`FSTRING_MIDDLE`/
  `FSTRING_END` tokens cover only the LITERAL parts of an f-string
  (replacement-field expressions tokenize as real NAME/OP tokens), so those
  token types ARE masked — correct there by construction.

Everything else (wrap-window detection, `what=` skip, NO_RETRY waiver,
snapshot/exclusion sets, error string, line-based reporting) is untouched.

Alternatives considered and rejected:
- **Naive triple-quote state tracking while iterating lines** — fragile on
  same-line open+close, escaped quotes, quote characters inside the other
  quote style, and single-quoted strings containing call text; `tokenize`
  gives the exact Python quoting semantics for the same effort.
- **Full AST `ast.Call` walk (flag only real call nodes)** — a semantic
  rewrite of the check: attribute-call matching (`.upload_file(`), the
  line-anchored wrap-window idiom (`_hf_routing_call_is_wrapped` reasons over
  raw lines), and line-number-stable error output would all need
  reimplementing, with real regression risk on the existing behavioral tests.
  The task needs "strings are not calls", which the tokenizer answers directly.
- **Mask ALL STRING tokens including f-strings (v1's shape)** — REJECTED by
  the round-1 critic Must-Fix: on py3.11 it silently exempts a real call
  inside an f-string replacement field, arming a latent under-flag hole in a
  429-SPOF detector the moment the first future f-string call site lands.

## File paths + concrete change sketch

`scripts/workflow_lint.py` (one new helper + a bounded edit to
`_hf_routing_file_errors`):

```python
def _hf_routing_exempt_spans(text: str) -> dict[int, list[tuple[int, int]]] | None:
    """Map 1-based line -> [(col_start, col_end)) ranges covered by
    non-f-string STRING / FSTRING_START|MIDDLE|END / COMMENT tokens (#2355:
    string/docstring + comment content is text, not a call). F-prefixed
    STRING tokens are NEVER masked: on py3.11 an f-string is one STRING token
    whose replacement fields may contain REAL calls (round-1 critic Must-Fix);
    on py3.12+ the FSTRING_* literal-part tokens are safe to mask because
    replacement-field expressions tokenize separately. Returns None when
    tokenization fails (malformed file) — the caller falls back to the
    pre-#2355 no-exemption behavior rather than crashing the lint or silently
    passing the file. NOTE (disposition, round-1 advisory): masking makes
    docstrings carrying HF-call text legal, and _hf_routing_call_is_wrapped
    still reads retry_transient mentions + paren balance on ABOVE lines
    including docstring content — a pre-existing, separate concern; see #2355.
    """
    spans: dict[int, list[tuple[int, int]]] = {}
    mask_types = {tokenize.COMMENT}
    fstring_types = set()
    for name in ("FSTRING_START", "FSTRING_MIDDLE", "FSTRING_END"):  # py3.12+
        t = getattr(tokenize, name, None)
        if t is not None:
            fstring_types.add(t)
    try:
        for tok in tokenize.generate_tokens(io.StringIO(text).readline):
            if tok.type == tokenize.STRING:
                prefix = tok.string.split(tok.string.lstrip("rbufRBUF")[0], 1)[0] \
                    if tok.string else ""
                # (implementer may use any equivalent prefix read — the
                # binding requirement is: 'f'/'F' in the prefix => NOT masked)
                if "f" in prefix.lower():
                    continue
            elif tok.type not in mask_types and tok.type not in fstring_types:
                continue
            (srow, scol), (erow, ecol) = tok.start, tok.end
            for row in range(srow, erow + 1):
                a = scol if row == srow else 0
                b = ecol if row == erow else sys.maxsize
                spans.setdefault(row, []).append((a, b))
    except (tokenize.TokenError, IndentationError, SyntaxError):
        return None
    return spans
```

In `_hf_routing_file_errors`:
- Read the file text ONCE (`text = py.read_text(...)`; `lines = text.splitlines()`).
- Compute spans LAZILY — only on the first line that regex-matches — so the
  ~thousands of scanned no-match files pay zero tokenize cost (the scan walks
  all of `scripts/` + `src/explore_persona_space/`).
- Replace the single `HF_ROUTING_CALL_RE.search(line)` with selection of the
  first match NOT inside an exempt span
  (`next((mm for mm in HF_ROUTING_CALL_RE.finditer(line) if not
  _in_exempt_span(spans, i + 1, mm.start())), None)`) — acceptance criterion 3.
  When spans is None (tokenize failure), every match counts (fallback =
  today's behavior; acceptance criterion 6).
- No other logic moves; the error-string literal is not touched.

## Known residuals (resolves v1's dangling "Known false negatives" reference)

- **F-string literal text containing HF-call text still over-flags** — e.g.
  `log(f"fetched via hf_hub_download({repo})")` on a line not starting with
  `what=`. UNCHANGED from today's behavior (f-strings are excluded from the
  mask by design; the `what=` skip covers the wrap idiom's descriptor kwarg,
  the dominant legitimate f-string carrier). Zero live instances flag today
  (the live-tree test passes), so this residual is theoretical; the remedy at
  a future hit is a `# NO_RETRY:`-style reword or a py3.12 interpreter bump
  (where literal parts mask precisely).
- **Wrap-window paren balance reads preceding-line docstring content**
  (`_hf_routing_call_is_wrapped`, workflow_lint.py:10968-10975): a docstring
  pasting a WRAPPED probe with net-positive parens within 3 lines above a real
  bare call could launder it. Pre-existing, unobserved on the live tree,
  explicitly out of scope; disposition line lives in the new helper's
  docstring so the next round finds it.
