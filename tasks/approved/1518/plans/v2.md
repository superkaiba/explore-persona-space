### 4.3 Leg 2 — stdout tail on `PodLifecycleProcessError`: DECLINED (recommendation + justification)

**Recommendation: do NOT widen `PodLifecycleProcessError` to carry a stdout tail.** Four reasons:

1. **It reverses a deliberately pinned #1465 design.** The relay docstring and `tests/test_runpod_provision_diagnostics.py` (header L20: "stdout stays INHERITED (never piped) and the relay fires on success too") pin stdout passthrough as a hard constraint — provision progress must reach the parent's stdout live.
2. **Deadlock risk.** Capturing a stdout tail requires `stdout=PIPE`. The relay's reader is single-threaded (`iter(proc.stderr.readline, "")`, L172); with two pipes, the unread stdout pipe fills its ~64 KiB buffer and blocks the child while the parent blocks on stderr. `_bootstrap` (L744, `subprocess.call` inheriting the parent's streams) routes the entire `bootstrap_pod.sh` output — uv install, git clone, pip — through pod_lifecycle's stdout, easily exceeding the buffer. A correct implementation needs a second drain thread: real complexity for a defense-in-depth benefit the stderr sweep already delivers.
3. **The sweep + guard closes the CLASS, not just the instance.** After §4.4, zero error-path diagnostics live on stdout, and the new AST guard test (§4.5, T5) fails CI on any future bare stdout print immediately preceding a nonzero exit — regression protection at the producer, where the bug lives, rather than a consumer-side net.
4. **A sanctioned pattern already exists for the one case that genuinely needs both streams:** the `_emit_still_waiting_and_exit` explicit dual print. Any future message needing stdout visibility AND tail capture uses that shape deliberately.

Consequence: `src/explore_persona_space/backends/runpod.py` receives a **comment-only** edit (§4.4c); `_POD_LIFECYCLE_TAIL_MAX_LINES` / `_POD_LIFECYCLE_TAIL_MAX_LINE_CHARS` and all relay code are byte-untouched.

- **What:** decline the stdout-tail leg. **Why/Source:** §4.3; `#1465` design pin + the pipe-buffer deadlock analysis against `_bootstrap`'s inherited stdout. **Alternatives:** two-thread drain relay (complexity not justified).
- **What:** tail bound constant left untouched. **Source:** `#1465` — `_POD_LIFECYCLE_TAIL_MAX_LINES = 60` / `_POD_LIFECYCLE_TAIL_MAX_LINE_CHARS = 400` (`backends/runpod.py` L110–111, read at plan time).
