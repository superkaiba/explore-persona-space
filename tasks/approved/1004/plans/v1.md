## 0. Plan Summary (technical)

**Change:** `render_startup_script` (gcp.py:1250) currently splices `spec.workload_cmd` VERBATIM as a bare line into a `set -euo pipefail` script. Bash exempts non-final members of a `&&`/`||` list from `errexit` (verified: `bash -c 'set -euo pipefail; false && true; echo FELL_THROUGH'` prints FELL_THROUGH, rc=0), so a compound `--workload-cmd 'cmd1 && cmd2'` whose FIRST command crashes falls through to the success tail → false `phase=done` + armed done-grace poweroff + bypassed `_eps_persist_diagnostics` (incident #952 run 1). Fix: render the line as `f"bash -eu -o pipefail -c {shlex.quote(spec.workload_cmd)}"` — the workload becomes ONE simple command from the outer script's perspective; the inner bash's exit status is the failed list's status (verified: rc 7 → 7, rc 78 → 78), so outer `set -e` fires → EXIT trap → `phase=failed` + crash-persist + poweroff. The inner `-eu -o pipefail` mirrors the outer flags, so the command text's own execution semantics are unchanged. Same one-line class applied to the SLURM custom-stage splice (slurm.py:1541, same `set -euo pipefail` + bare splice + terminal sentinel). RunPod's launcher is NOT this class (no `set -e`; `WORKLOAD_RC=$?` correctly captures a failed `&&` list) — out of scope with reason.

### 4.4 Explicitly-scoped decisions

- **RunPod (`backends/runpod.py:504`) — OUT OF SCOPE, with reason.** The launcher deliberately runs WITHOUT `set -e` (`set -uo pipefail`, line 496) and captures `WORKLOAD_RC=$?` immediately after the splice. A `cmd1 && cmd2` first-command crash there yields `$?` = cmd1's status (`bash -c 'false && true; echo $?'` → 1 — the errexit exemption does not affect `$?`), so the sentinel is correctly NOT written and `exit "$WORKLOAD_RC"` propagates. The #952 class demonstrably does NOT apply. A DISTINCT residual exists there (`cmd1; cmd2` masks cmd1's rc when cmd2 succeeds — no `-e` to catch the mid-script simple-command failure), but that is a different subclass with different blast radius (RunPod pods persist + are SSH-able; no delete-on-crash evidence loss), and touching the quoted-heredoc launcher would drag in its token-scanning liveness tests. Named here for the orchestrator; per the brief I file no tasks.
- **Residual on GCP/SLURM (documented, accepted):** a workload_cmd of the shape `a && b; c` where `a` fails and `c` succeeds still masks (probed: `bash -ec 'false && true; echo after'` prints `after`, rc=0 — the same errexit exemption applies inside the inner bash, and the inner script's exit status is then `c`'s). This is inherent bash semantics for that shape; the inner `-e` DOES catch the plain `a; b` shape (probed rc=1), and the #750 OOM guard remains as the independent backstop for OOM-kill masking of any shape. Real launch composers use single commands or pure `&&` chains — both fully covered.
- **No re-render / reconnect path exists to patch:** `render_startup_script` has exactly ONE production call path — `GcpBackend.launch` via the `self._render_startup` seam (gcp.py:3950). `reconnect_or_none` reconnects to a live instance without re-rendering. The handle serialization (gcp.py:4392-4398) stores the ORIGINAL `spec.workload_cmd` string, never the rendered line — so a failover re-dispatch rebuilds a RunSpec and re-wraps at render time (no double-wrap possible; the wrapper is never persisted). def test_workload_cmd_wrapper_propagates_compound_first_command_rc() -> None:
    """#1004 behavioral proof on the LIVE rendered line: under set -euo
    pipefail, a `cmd1 && cmd2` workload whose FIRST command exits 7
    aborts the script with rc 7 (success tail unreached); a succeeding
    compound reaches the tail with rc 0. Pre-#1004 the failing case fell
    through and 'published done' (probe: bash -c 'set -euo pipefail;
    false && true; echo FELL_THROUGH' prints FELL_THROUGH, rc=0)."""

            spec=_workload_spec(cmd), config=_test_config(), attempt_id="att-fixed-001"
        )
        lines = script.splitlines()
        return lines[lines.index("touch /tmp/eps-workload-start") + 1]

    for cmd, want_rc, want_tail in (
        ("bash -c 'exit 7' && echo NOT_REACHED", 7, False),
        ("true && echo CHAIN_OK", 0, True),

## 11. Decision Rationale

1. **Wrapper form `bash -eu -o pipefail -c {shlex.quote(spec.workload_cmd)}`.**
   *What:* run the workload as one simple command whose exit status is the inner script's. *Why:* under `set -e`, non-final members of a `&&`/`||` list are exempt from errexit, so a bare compound splice masks a first-command crash; but the inner SCRIPT's exit status is "the exit status of the last command executed" — the failed list's status — and a non-zero simple command in the outer script fires `set -e`. *Source:* `man bash` (SHELL BUILTIN COMMANDS, `set -e`: "The shell does not exit if the command that fails is … part of any command executed in a && or || list except the command following the final && or ||"; EXIT STATUS: a script "returns … the exit status of the last command executed") — verified empirically on this VM, outputs quoted verbatim:
   - `bash -c 'set -euo pipefail; false && true; echo FELL_THROUGH'` → `FELL_THROUGH`, `rc=0` (the #952 bug, reproduced).
   - `bash -ec 'false && true'` → `rc=1` (inner-script status = failed list's status).
   - `bash -c 'set -euo pipefail; bash -eu -o pipefail -c "false && true"; echo FELL_THROUGH'` → no output, `rc=1` (the fix, end to end).
   - rc VALUE preserved: harness with `bash -c 'exit 7' && echo NOT_REACHED` → outer rc **7**; `bash -eu -o pipefail -c 'exit 78'` → rc **78** (matters: the in-VM preflight's `exit 78` convention and the OOM guard's `exit 137` stay distinguishable through wrappers).
   *Alternatives rejected:* (a) prepending `set -e;` to the command text — same exemption applies inside, changes nothing for the `&&` shape and mutates user-supplied text; (b) `{ cmd; } || exit $?` group splice — re-parses the raw text in the outer shell (a trailing `&` or comment in the cmd breaks the group syntax), and `||` itself disables errexit inside the group; (c) `eval` — same outer-parse masking, worse quoting surface; (d) rendering the cmd into a separate temp script file — more moving parts (file creation, chmod, path hygiene) for the same rc semantics the one-liner already achieves.
2. **Why `-e` on the inner bash:** catches the `cmd1; cmd2` mid-script simple-command failure shape (probe: `bash -ec 'false; echo after_semicolon'` → no output, rc=1), which the pure exit-status-of-last-command rule would mask. Parity with the outer script's flags — the command text ran under `-e` before this change (the outer shell's), so identical execution semantics.
3. **Why `-u` and `-o pipefail` on the inner bash:** flag parity. The bare splice executed the workload text with the OUTER `set -euo pipefail` in force; a wrapper without `-u` would silently RELAX nounset for the workload (an unset `$VAR` reference that crashes today would expand empty), and without pipefail a `producer | consumer` pipeline's left-side failure would be newly masked (probe: `bash -eu -o pipefail -c 'false | true'` → rc=1; `bash -ec 'false | true'` → rc=0). Exact parity ⇒ the ONLY behavior change is the propagated rc. Flag spelling `-eu -o pipefail` (there is no single-letter form of pipefail) — probed working.
4. **Why `shlex.quote`:** POSIX single-quoting round-trips the single-line command exactly (RunSpec.__post_init__ guarantees single-line, no leading/trailing whitespace — base.py:196-199), keeping the rendered script line-structured; probe with embedded single quotes + `&&` chain round-tripped byte-exactly (`echo the-flag-'v 1'-end && echo second` → `the-flag-v 1-end` / `second`, rc 0) and `bash -n` passes on the rendered line (rc 0).
5. **Env/prefix contracts preserved (probed):** exported vars reach the inner bash (`export EPS_PROBE_VAR=ok` + wrapped `test "$EPS_PROBE_VAR" = ok` → `ENV_OK`, rc 0); a per-command env prefix in the workload text supersedes the inherited export for its child (`export REPO_ROOT=Y` outer + wrapped `REPO_ROOT=X printenv REPO_ROOT` → `X`) — the #641 backward-compat comment stays true verbatim.
6. **SLURM in scope, RunPod out:** §4.4 — SLURM is byte-for-byte the same class (set -euo pipefail + bare splice + clean-exit sentinel); RunPod's no-`-e` + `WORKLOAD_RC=$?` design already captures the `&&`-list status correctly.
