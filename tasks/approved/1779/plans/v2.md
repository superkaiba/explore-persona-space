## 1. Goal / Requirement

planner §10 must require every text/JSON output of a stage running on an **ephemeral lane** (GCE `--instance-termination-action=DELETE`, RunPod terminate-on-upload-verify) to name an **HF (non-LFS) destination** — a git-only destination ("commit to the issue branch") is valid ONLY for VM-resident stages, or when the plan names an explicit **pre-teardown harvest phase** that lands the file in git BEFORE the instance/pod is reaped. The critic Methodology lens REVISEs violations.

### Incident (why)

#1738's approved plan §10 declared "JSON summaries → git issue branch" for artifacts produced on the DELETE-on-exit GCE lane with no harvest phase. The instance was reaped minutes after a clean exit; both summary JSONs (`multiturn_100k_fits.json`, `mapping_baselines.json`) were lost; a 28-min CPU rebuild round recovered the holdout side from retained tensors. CLAUDE.md § Upload Policy says text/JSON uploads ALWAYS (non-LFS path, unconditional), but nothing at PLAN time cross-checks destination-vs-lane durability.

- **What:** plan-time destination-vs-lane durability constraint with a two-pronged item-18 trigger. **Why:** the runtime backstops (upload-verifier, persist-by-default) cannot save a file whose only declared destination dies with the disk; the plan is the only surface that knows both the lane and the destination; the trigger must not be gated on generation-and-reduce presence or the motivating incident class (fit-summary JSONs) escapes it. **Source:** incident #1738 r4 (verbatim candidate block on this task's body); planner.md §10 + critic-lens-reference.md L646-663 read at `766061939402`; critic round-1 Must-Fix 1. **Alternatives considered:** (a) mechanical `verify_plan.py` check — deferred (recursion guard; noted as `mechanizable: partial`); (b) upload-verifier-side check — too late, the artifact is already lost at verify time on the DELETE lane; (c) banning git dests on ephemeral lanes outright — over-broad, harvest-phase pattern is legitimate; (d) a separate new lens item instead of extending item 18 — rejected, destination-vs-lane IS persist-by-default enforcement and a new item would duplicate item 18's incident framing.
