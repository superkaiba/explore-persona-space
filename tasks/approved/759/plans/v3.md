## 1. Goal

The autonomous-session watcher must never spawn a second `/issue <N>` `--auto`
driver while a live (daemon-tracked) or actively-working session for issue `N`
already exists. Two independent code paths can currently violate this; the fix
closes both with the smallest viable predicate edits, reusing the existing
liveness + grace + per-session state helpers rather than adding a parallel
mechanism.

session that is demonstrably ALIVE (its id is in `/list`). The cited #739
mid-Phase-1.5 respawn is consistent with this.

### (vi) The recovery-flow reality (reconciler-verified) + why v2's Option B was unimplementable

The alternatives reconciler verified two facts:

- **`_handle_stalled_alert` (line 4961) is a NOTIFY-ONLY arm, not a recovery
  arm.** It posts a marker and saves the `stalled-<N>.json` state file — it does
  NOT stop the zombie wrapper, does NOT spawn a replacement, and does NOT
  escalate. The canonical #506 recovery is the `respawn` arm
  (`_handle_stalled_respawn` line 4795 → `_stop_session` line 4856 →
  `_respawn_stalled_session` line 4873). So an UNCONDITIONAL `respawn → alert`
  downgrade on a live id would, for the #506 class (live Happy wrapper, dead
  bg-Bash chain), produce alerts forever and NEVER recover.
- **`decide_orphan` (line 5582-5583) returns `("clear", 0)` whenever
  `mapped_alive` is True.** So while a zombie wrapper still appears in `/list`
  (its id in `live_ids`), the orphan sweep fires NO recovery for it either.
  NEITHER pass recovers a live-but-stalled wrapper while it lingers in
  `live_ids` — so the (b.1) mechanism is the ONLY automatic backstop for this
  class.

> **Strategy pivot (implementer-reported `epm:strategy-pivot v1`):** v2's (b.1)
> "Option B" — downgrade to `alert` only when a recent NON-watcher work-marker
> is fresher than `LIVE_WORK_CORROBORATION_S`, with §11 fixing
> `LIVE_WORK_CORROBORATION_S == STALLED_WINDOW_S` and "no second knob" — is DEAD
> CODE as written. `decide_session_stalled` returns `respawn` ONLY when the
> work-marker is STALE (`marker_age >= window`), but the v2 downgrade fires only
> when the work-marker is FRESH (`marker_age < window`). Those two conditions
> are exact negations, so `work_fresh` is ALWAYS False at the check point: the
> downgrade can never fire and acceptance criterion 6 ("stale markers AND a
> recent work-marker") is unsatisfiable. The fix is to switch (b.1) to the
> reconciler's first option — **Option A, bounded K-escalation** — which does
> not depend on a work-marker freshness signal that the respawn-trigger
> condition itself rules out.

**Consequence for the design:** (b.1) downgrades a live-id respawn to `alert`
for the first K-1 consecutive stalled episodes, then ESCALATES to the canonical
respawn arm on the Kth — so a transient busy stretch never duplicates a driver,
and a persistently-stalled live wrapper (#506 class) is still recovered within a
bounded window (≈ K × `STALLED_WINDOW_S`).

## 4. Design

Two predicate edits, both narrow, both reusing existing helpers + the existing
`stalled-<N>.json` state file. Plain-English names used throughout; the
function/line refs are for the implementer.

### Bug class (a) — crash-recovery pass respawns inside the registration-latency window — ALREADY IMPLEMENTED (HEAD c3bd155bc2)

**Status: DONE. Do NOT re-implement, do NOT re-test.** Documented here for
completeness; the reviewer reads it as shipped.

**Failure scenario closed:** a session that was just (re)spawned writes its
`issue-<N>.json` with a fresh `happy_session_id`, but that id has not yet
appeared in the daemon's `/list` reply. `_session_alive` reads False for 2
consecutive 10-min ticks (~20 min) and `decide` respawns a duplicate.

**Change shipped — spawn-grace window on the crash-recovery respawn, mirroring
`ORPHAN_SPAWN_GRACE_S`:** `decide()` (line 444) gained `entry_age_s` +
`spawn_grace_s = RESPAWN_SPAWN_GRACE_S`; inside `status in ACTIVE`, before the
not-alive miss increment, `if entry_age_s is not None and entry_age_s <
spawn_grace_s: return ("keep", 0)`. `_process_entry` passes `entry_age_s =
time.time() - entry.get("spawned_at", 0)`. New constant `RESPAWN_SPAWN_GRACE_S`,
env `EPM_RESPAWN_SPAWN_GRACE_MIN`, default 15 min. A missing/zero `spawned_at`
yields a large `entry_age_s` (no grace) — fail toward today's behavior.

### Bug class (b) — stalled detector respawns a live-but-busy session; window equals tick cadence

**Failure scenario closed:** an autonomous session at `planning` (or any ACTIVE
status) is mid-`/adversarial-planner` — a fact-checker / critic / reconciler
subagent holds the conversation for minutes, posting no marker, and the 45-min
self-report tick fires late so the self-report ages past `STALLED_WINDOW_S`.
The stalled detector, which never checks the live-session set, escalates to
`respawn` even though the session's `happy_session_id` is sitting in the
daemon's `/list` reply right now.

**Two-part change:**

**(b.1) Corroborate the stalled trigger against the live-session set, with a
bounded K-escalation (Option A) — THE REMAINING WORK.** In
`_process_stalled_session` (line 5153), compute liveness from the same daemon
read the other passes use and feed it as an additional guard. The caller
(`stalled_session_pass`, line 5399) already has `daemon_reachable`; thread
`live_ids` down (the watcher computes it once in `main()`) into
`stalled_session_pass(..., live_ids=...)` exactly as `orphan_sweep_pass` already
receives it (line 5821).

The corroboration check is placed AFTER the existing `_provision_in_flight_reason`
rewrite (lines 5307-5315) and the followups-exemption rewrite (line 5325), and
BEFORE the action dispatch (line 5369), so it sees only the respawns those
exemptions did not already turn into `keep`.

Rule:

- **`action == "respawn"` AND `daemon_reachable` AND `_session_alive(entry,
  live_ids)` is True** (a LIVE id is being respawned):
  - increment `live_consecutive` (from `prev_state`, see §3 (v));
  - if `live_consecutive < K` → **DOWNGRADE to `alert`** (via the existing
    `_handle_stalled_alert` arm — it posts the ALIVE-BUT-STALLED note + persists
    state); persist the incremented `live_consecutive`; `telemetry["b1_downgrade"]
    += 1`; return.
  - if `live_consecutive >= K` → **FALL THROUGH to the canonical respawn arm**
    (`_handle_stalled_respawn`) and RESET `live_consecutive` to 0 in the persisted
    state (the episode's escalation has fired; the fresh `--auto` session starts a
    new episode); `telemetry["b1_escalation"] += 1`.
- **`action == "respawn"` AND `_session_alive` is False** (genuinely dead
  wrapper): canonical respawn fires UNCHANGED (today's behavior); RESET
  `live_consecutive` to 0 (no live-stall episode in progress).
- **`decide_session_stalled` returned `keep` or `clear`** (or the
  provision/followups exemptions rewrote `respawn` → `keep`): RESET
  `live_consecutive` to 0 — the session is not in a live-stall respawn episode,
  so the counter must not carry over to a later, unrelated stall. (This is in
  addition to the self-report-advanced reset in §3 (v), which fires earlier; the
  keep/clear reset covers the case where the action is `keep` but the
  self-report did not advance — e.g. a benign marginal-window tick.)

Pseudocode (the post-`decide`, post-exemption block; `K = STALLED_LIVE_ESCALATION_K`):

```
# After: action, new_missed = decide_session_stalled(...)
# After: provision-in-flight rewrite (5307-5315), followups rewrite (5325).
# `prev_live_consecutive` read from prev_state next to prev_missed (§3 (v)),
# already cleared to 0 above if the self-report advanced.
live_consecutive = prev_live_consecutive

if action == "respawn" and daemon_reachable and _session_alive(entry, live_ids):
    live_consecutive += 1
    if live_consecutive < K:
        # transient busy stretch on a LIVE session — alert, do NOT duplicate.
        action = "alert"
        telemetry["b1_downgrade"] += 1
        # persisted via the _handle_stalled_alert arm; thread live_consecutive
        # into _StalledActionCtx so that arm's _save_stalled_state writes it.
    else:
        # persistently-stalled LIVE wrapper (#506 class) — escalate to the
        # canonical respawn arm; reset the counter (new episode begins).
        live_consecutive = 0
        telemetry["b1_escalation"] += 1
        # action stays "respawn"; _handle_stalled_respawn fires below.
elif action == "respawn":
    # _session_alive False (genuinely dead) OR daemon unreachable — today's
    # behavior. No live-stall episode; reset the counter.
    live_consecutive = 0
else:
    # keep / clear (incl. provision/followups exemptions) — not a respawn
    # episode; reset so the counter never straddles unrelated stalls.
    live_consecutive = 0
```

Then thread `live_consecutive` into `_StalledActionCtx` (line 5348) and pass it
to EVERY `_save_stalled_state(...)` call site (§3 (v)) — the alert arm
(`_handle_stalled_alert`, line 5038), the respawn arm (4843/4859/4890), the
exhausted arm (4918/4947), and the `keep` branch (5385) — so the persisted
value matches the rule above on every path. The `_handle_stalled_alert` arm
specifically must persist the INCREMENTED `live_consecutive` (it is the downgrade
target); the respawn arm persists 0 (reset after escalation).

- **Why bounded K, not unconditional downgrade or unconditional respawn.** An
  unconditional downgrade starves the #506 class forever (alert-only, no
  recovery — §3 (vi)); unconditional respawn on a live id is the bug we are
  fixing (duplicate drivers on a busy live session). K-escalation gives both:
  the first K-1 episodes alert (no duplicate on a transient busy stretch), the
  Kth respawns (recovery for a persistently-dead bg-chain). K=2 default → at
  most ≈ 2 × `STALLED_WINDOW_S` = 2 × 60 min = ~2h before a live-but-dead-bg
  wrapper is recovered, within the historical 90-min orphan-staleness range.
  See §11.
- **Why this is the backstop (not the orphan sweep).** Per §3 (vi),
  `decide_orphan` returns `clear` on `mapped_alive`, so while the zombie wrapper
  remains in `live_ids` the orphan sweep fires NO recovery. The Kth-episode
  escalation above IS therefore the automatic backstop for the #506 class — the
  only one that fires while the wrapper lingers in `live_ids`.
- **Telemetry (logged concern, applied):** `telemetry["b1_downgrade"]` on the
  downgrade branch and `telemetry["b1_escalation"]` on the escalation branch
  (the existing watcher telemetry counter dict — confirm the exact name/handle
  the pass already uses for per-pass counters; if there is no in-pass telemetry
  dict, append a one-line `{"ts", "issue", "event":
  "stalled-live-downgrade"|"stalled-live-escalation"}` row to the existing
  watcher sidecar JSONL, same as v2's telemetry plan). Non-blocking.

**(b.2) Widen `STALLED_WINDOW_S` so it comfortably exceeds the 45-min tick
cadence — STASHED at `git stash@{0}`, land verbatim.** Today `STALLED_WINDOW_S
== 45 min == the self-report tick interval`, so the window is straddle-able by
ordinary cron jitter. Raise it to **60 min** (env `EPM_STALLED_WINDOW_MIN`,
already overridable per-call via the `window_s` arg of `decide_session_stalled`
line 870 — add the env-read at the module constant, mirroring
`_orphan_staleness_s`). 60 min = tick cadence (45) + a full extra tick of slack.
This is belt-and-suspenders with (b.1): (b.1) stops a duplicate even if the
window opens; (b.2) stops the window opening on benign jitter in the first
place.

  - **Why both (b.1) and (b.2)?** (b.1) is the correctness fix (never duplicate
    a live session on a transient stall; DO respawn a persistently-stalled live
    one after K episodes). (b.2) reduces alert noise: without it, every long
    planning stretch would now generate a benign downgrade-to-alert marker on a
    live session. (b.2) keeps the detector quiet during normal long subagent
    work; (b.1) is the hard guard for the genuinely-marginal case.

## 5. Acceptance criteria (mechanically verifiable; new tests in `tests/test_autonomous_session_watch.py`)

**Bug class (a) — crash-recovery spawn-grace (criteria 1-5): ALREADY IMPLEMENTED
+ committed at HEAD c3bd155bc2, 756 tests green. Listed for completeness — do NOT
re-implement, do NOT re-test.**

1. `decide("running", alive=False, missed=1, entry_age_s=ORPHAN_SPAWN_GRACE_S
   - 1) == ("keep", 0)` — a not-yet-live entry inside the grace window does NOT
   respawn even at the 2nd miss. (Mirror of `test_orphan_fresh_registration_keeps`,

   still fires (no regression of the genuine-death path).

- **`RESPAWN_SPAWN_GRACE_S` default = 15 min (env `EPM_RESPAWN_SPAWN_GRACE_MIN`)

  keeps the two passes' spawn-in-flight semantics identical. Alternatives
  rejected: 5 min (too tight); 30 min (needlessly delays a real-death respawn).
  Source-anchored to `#472`.
- **`STALLED_WINDOW_S` raised 45 min → 60 min (env `EPM_STALLED_WINDOW_MIN`) —
  part (b.2), stashed.** Source: the `/issue-tick` self-report cadence is 45 min
  (`.claude/skills/issue-tick/SKILL.md` line 30, 2026-06-12). The window must
  exceed the cadence by at least one cron tick so benign jitter cannot straddle
  it: 45 + 15 = 60. Alternatives rejected: keep 45 (== cadence, the bug); 90 min
  (delays a genuinely-wedged-live alert longer than needed, since (b.1) already
  prevents the duplicate spawn). Source: `#661` (window origin) +
  `issue-tick/SKILL.md` (cadence).
- **(b.1) downgrade mechanism = Option A (bounded K-escalation), NOT Option B
  (active-work corroboration).** Rationale: v2's Option B is UNIMPLEMENTABLE —
  its downgrade fired only when the work-marker was FRESH, but
  `decide_session_stalled` returns `respawn` only when the work-marker is STALE,
  so the two conditions are exact negations and the downgrade was dead code
  (the implementer's `epm:strategy-pivot v1`; §3 (vi)). Option A — the
  reconciler's first option — does not depend on a freshness signal the
  respawn-trigger itself rules out: it counts CONSECUTIVE live-stall episodes in
  the existing `stalled-<N>.json` state file and escalates after K. It closes
  the #506 starvation hole (a persistently-live-but-dead-bg-chain session IS
  eventually respawned, on the Kth episode) while never duplicating a driver on
  a transient busy stretch (the first K-1 episodes alert). Source: §3 (vi)
  reconciler verification (Option A is its binding first option) + #506.
- **`STALLED_LIVE_ESCALATION_K` default = 2 (env `EPM_STALLED_LIVE_ESCALATION_K`).**
  Source: the systemd `StartLimitBurst` family (default 5) — the standard
  "tolerate N transient failures before escalating" pattern. We pick a TIGHTER
  K because each watcher "episode" here is ≈ `STALLED_WINDOW_S` = 60 min, so
  systemd's 5 would mean ~5h before recovery, which EXCEEDS the historical
  90-min orphan-staleness backstop's rough timescale. K=2 gives ≈ 2 × 60 min =
  ~2h worst-case wedge before the Kth-episode escalation respawns a
  live-but-dead-bg wrapper, within the 90-min-orphan range, while still
  debouncing a single transient busy stretch (the first episode alerts, never
  duplicates). Alternatives rejected: K=1 (NO debounce — every transient busy
  stretch escalates immediately, which IS the duplicate-driver bug we are
  fixing); K=3 (~3h before recovery — exceeds the orphan-staleness backstop's
  rough timescale, leaving a dead bg-chain idle-burning longer than the existing
  backstop would tolerate). Source-anchor: systemd `StartLimitBurst` default +
  the alternatives reconciler's binding REVISE (Option A) + the historical
  90-min orphan-staleness window (`_orphan_staleness_s`, #472).
