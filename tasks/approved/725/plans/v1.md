# Plan v1 — issue #725 — daily-fix: `living_docs.py check` degrade on bad task

Estimated GPU-hours (total): 0

## Requirement + acceptance criteria

**Requirement.** `uv run python scripts/living_docs.py check` MUST NOT
hard-crash when a single task in `tasks/REGISTRY.json` points at a
directory that does not exist on disk. The drifted task must surface
as a normal drift finding in the returned `CheckReport`, the lint must
complete its remaining checks against the surviving tasks, and the
process exit code must reflect drift (1) vs no-drift (0) the same way
it does today — not crash (an unhandled traceback + nonzero exit on
the wrong reason).

**Acceptance criteria** (each is a binding gate the implementer
verifies + the code-review ensemble + Step 9c test-verdict gate
enforce):

1. `living_docs.check()` returns a `CheckReport` (no raise) even when
   the registry contains an entry whose `path` field points at a
   missing directory.
2. The drifted task surfaces in `report.problems` as a single, specific
   line naming the task id + the underlying inconsistency — i.e. the
   bad task is reported as a kind of drift, not silently swallowed.
3. All four other check axes — (a) bidirectional, (b) coverage, (c)
   resolvable, (d) staleness, plus the structural pre-check — still
   run and still find findings on the surviving tasks (i.e. the bad
   task does not poison the remainder of the report).
4. A new pytest unit test under `tests/test_living_docs.py` reproduces
   the previously-crashing scenario (registry pointing at a missing
   dir) and asserts (1) + (2) + (3) above.
5. `uv run ruff check scripts/living_docs.py tests/test_living_docs.py`
   passes; `uv run ruff format --check scripts/living_docs.py
   tests/test_living_docs.py` passes; the full `uv run pytest
   tests/test_living_docs.py -v` suite is green; the broader
   `tests/test_workflow*.py` + `tests/test_task_workflow*.py` suites
   are unchanged.

## Method delta (what differs from existing code)

The bug is in two registry-iterating helpers in
`scripts/living_docs.py`:

- `_relates_to_index` (line 1144) — iterates
  `tw._load_registry()["tasks"]` and calls `tw.find_task_path(tid) /
  "body.md"` per task.
- `_completed_task_dates` (line 1115) — iterates
  `tw.list_by_status("completed")` and calls `tw.find_task_path(tid)
  / "body.md"` per task.

Both raise `FileNotFoundError` (uncaught) when the registry says a
task lives at a path that does not exist (`task_workflow.find_task_path`
lines 1418-1422 raise specifically on that drift). The single-call
sibling `link()` at line 943 already handles this exact failure mode
with `try / except FileNotFoundError: missing.append(tid); continue`
— the precedent for the skip-and-collect pattern.

**The change**: extend the existing precedent to the two `check()`
helpers. Each helper returns the data dict as today AND a list of
`(tid, error_message)` pairs for tasks it could not read; `check()`
appends one problem line per missing task to `report.problems`. Two
small touches, both bug-locally scoped — no API contract change for
external callers (the helpers are module-private, leading underscore).

**Out of scope**:
- `_all_task_ids` (line 1138) reads ONLY `_load_registry()` (no
  per-task FS access) — registry-internal drift does not surface here,
  so leave it untouched.
- `link()` (line 939) ALREADY handles the case and is the precedent we
  follow; no change.
- `tw.find_task_path` itself is the canonical raiser and stays loud —
  caller-side handling is correct.
- No mutation of task state (the body explicitly forbids "fixing" the
  drifted task; that's a separate workflow-fix task on `scripts/task.py`
  if it exists).

def _completed_task_dates(paths: LivingDocsPaths) -> dict[int, str | None]:
    out: dict[int, str | None] = {}
    for entry in tw.list_by_status("completed"):
        if not entry.get("has_clean_result"):

            continue

        date = str(stamp)[:10] if stamp else None
        out[tid] = date
    return out

# After
def _completed_task_dates(
    paths: LivingDocsPaths,
) -> tuple[dict[int, str | None], list[tuple[int, str]]]:
    """Map every completed-with-clean-result task id → its promotion date.

    Returns (dates, drifted): the second element lists (task_id,
    error_message) pairs for registry entries whose on-disk directory
    is missing — these surface as drift findings rather than crash the
    whole pass (see also _relates_to_index).
    """
    out: dict[int, str | None] = {}
    drifted: list[tuple[int, str]] = []
    for entry in tw.list_by_status("completed"):
        if not entry.get("has_clean_result"):
            continue
        tid = int(entry["id"])
        try:
            body_path = tw.find_task_path(tid) / "body.md"
        except FileNotFoundError as e:
            drifted.append((tid, str(e)))
            continue
        fm, _ = tw._read_body(body_path)
        if fm.get("living_docs_unmapped"):
            continue
        stamp = fm.get("promoted_at") or fm.get("created_at")
        date = str(stamp)[:10] if stamp else None
        out[tid] = date
    return out, drifted
```

# Before
def _relates_to_index(paths: LivingDocsPaths) -> dict[int, list[str]]:
    out: dict[int, list[str]] = {}
    reg = tw._load_registry()

# After
def _relates_to_index(
    paths: LivingDocsPaths,
) -> tuple[dict[int, list[str]], list[tuple[int, str]]]:
    """Map task id → its ``relates_to`` list across all statuses.

    Returns (index, drifted): the second element lists (task_id,
    error_message) pairs for registry entries whose on-disk directory
    is missing — these surface as drift findings rather than crash the
    whole pass.
    """
    out: dict[int, list[str]] = {}
    drifted: list[tuple[int, str]] = []
    reg = tw._load_registry()
    for tid_str in reg.get("tasks", {}):
        tid = int(tid_str)
        try:
            body_path = tw.find_task_path(tid) / "body.md"
        except FileNotFoundError as e:
            drifted.append((tid, str(e)))
            continue
        fm, _ = tw._read_body(body_path)
        rel = fm.get("relates_to")
        if rel:
            out[tid] = [str(q).lower() for q in rel]
    return out, drifted
```

**Change 3** — `check()` (around line 1297-1300): consume the new

relates = _relates_to_index(paths)

# After
relates, relates_drifted = _relates_to_index(paths)
all_ids = _all_task_ids(paths)
completed, completed_drifted = _completed_task_dates(paths)

# Surface any registry/filesystem inconsistency as a drift finding,
# union-dedup'd across the two indexers (same drifted task can show
# up in both passes).
seen_drifted: set[int] = set()
for tid, err in [*relates_drifted, *completed_drifted]:
    if tid in seen_drifted:
        continue
    seen_drifted.add(tid)
    report.problems.append(
        f"task #{tid} registry/filesystem inconsistent: {err} "
        f"(run `task.py audit` to repair)"
    )
```

def test_check_degrades_on_drifted_registry_entry(fixture, capsys):
    """A registry entry pointing at a missing directory must surface
    as a drift finding (problem line) instead of crashing the pass.
    Reproduces the tonight crash documented in task #725 body."""
    repo, paths = fixture
    # Drift the registry: rewrite #207's path to a directory that does
    # not exist. The on-disk task folder is still there, but the
    # registry POINTS somewhere else — which is exactly what
    # task_workflow.find_task_path raises on (line 1418-1422).
    import json
    reg_path = repo / "tasks" / "REGISTRY.json"
    reg = json.loads(reg_path.read_text())
    reg["tasks"]["207"]["path"] = "tasks/approved/207"  # nonexistent dir
    reg_path.write_text(json.dumps(reg, indent=2, sort_keys=True) + "\n")

    # Must not raise.
    report = ld.check(paths=paths)

    # Drift finding present, names the bad task id.
    assert any("#207" in p and "registry/filesystem inconsistent" in p
               for p in report.problems), report.problems

    # The remaining check axes still ran against the surviving task
    # (#208) — the report is not empty AND contains an axis other than
    # the new "registry/filesystem inconsistent" line.
    other = [p for p in report.problems
             if "registry/filesystem inconsistent" not in p]
    # Tonight's regression case: with #207's relates_to invisible due
    # to the crash, #207 would have failed coverage / bidirectional —
    # those are now testable. We assert the survivor path ran by
    # checking that #208's coverage finding (or any non-drift finding)
    # still has the chance to surface OR that report.passes() reflects
    # remaining-state correctness. The exact assertion the test
    # implementer codes here is "axes still ran"; the precise problem
    # set depends on what the fixture exposes for #208 once #207
    # disappears.
```

Implementer codes the precise remaining-axes assertion after running
the test locally against the live fixture — the docstring states the
contract and the implementer fills the exact survivor-state check

coverage problem).
