## 4. Design

### 4.0 Design decision

**Pick: OPTION B — the `consistency-checker` is SKIPPED for a parentless
`kind: infra | batch | survey` task, and the SKIP is recorded on
`events.jsonl` as an `epm:consistency v1` marker with a `PASS — skipped`
verdict naming the reason.**

Evidence (all read at plan time from the files cited in §2):

1. The checker's five checks (single-variable change from parent, same
   baseline, same eval suite, same seeds, same data version) are all
   experiment-recipe concepts. There is no experiment recipe on a
   workflow-surface `kind: infra` task for the checker to bind to.
2. `.claude/agents/consistency-checker.md` L334 explicitly names Qwen-2.5-7B
   + a standard eval suite as the no-parent fallback. Unexecutable for a
   workflow-surface task; #1697's checker's own "N/A" rows are that
   unexecutability in action — the run produced no signal.
3. Adopting Option A (run the checker + a sibling-file heuristic against
   prior workflow-fix tasks that touched the same target file) would require
   rewriting all five of the checker's rows around a workflow-surface parent
   notion — a much larger change than the goal of "uniformity of treatment
   on the same task shape" demands, and one the current checker's
   implementation nowhere supports.
4. The adversarial-planner Phase 2 spawn table (SKILL.md L921) states the
   checker "needs only the corrected plan + parent recipe" — a parent
   recipe is a stated INPUT the check consumes. Parentless kind: infra
   supplies none.
5. Recording the SKIP on the same marker channel the RAN branch uses
   (`epm:consistency v1`) keeps the "was this gate run?" question
   mechanically answerable from `task.py view <N> --json` alone: an
   `epm:consistency` event is either present (verdict PASS/WARN/BLOCK) or
   present-with-`skipped` reason — never absent-and-ambiguous.

### 4.1 Marker-channel pick

The SKIP is recorded as an `<!-- epm:consistency v1 -->` marker with:

- `**Verdict: PASS**`
- A first-line reason `Skipped: kind: infra, no parent experiment` (or
  `kind: batch` / `kind: survey` — the parentless-non-experiment class),
- The remaining rows filled `N/A — <one-line reason>` (no five-check
  binding to grade), consistent with #1697's shape but re-cast as a
  deliberate skip rather than a degenerate run.

Rationale: the existing `epm:consistency v1` marker is the channel readers
already know for "did the consistency gate run?" — using it for both
verdicts (RAN → PASS/WARN/BLOCK; SKIPPED → PASS with a `Skipped:` first
line) collapses the reader's mental model to one lookup. An
`epm:progress` prose-only note (rejected alternative) would fragment the
audit path.
