## 4. Design

### 4.1 The core decision: new `_up_logs` with per-file tailing — NOT `_up_dir` reuse

**Decision: a new `_up_logs()` helper that tails each file, never skips a file wholesale.** Rejected alternative — reusing `_up_dir` with `EPS_PERSIST_DIR_CAP_BYTES`: an oversized `logs/` dir (one vLLM-spam log routinely exceeds any dir cap) would SKIP entirely, losing exactly the traceback this fix exists to save. Tailing wins on all three axes weighed: (a) **300s safety** — worst-case payload is bounded by arithmetic (`max_files × file_cap` = 40 × 5 MiB = 200 MiB) instead of by luck; (b) **diagnosability** — the traceback is at the END of a log, which a tail keeps and a skip loses; (c) **heredoc code size** — ~30 lines of plain Python (file tailing is trivial in Python; no `tail -c` shell dependency, we are already inside the Python heredoc).

```python
# 1b. worker logs (#885) — fan-out dispatchers redirect the real traceback to
#     per-worker logs under $WORKLOAD_ROOT/logs/ (e.g. logs/issue_779/corpus_gpu0_all.log);
#     the canonical workload.log ends at the fan-out line. Newest-first, per-file
#     TAIL cap (the traceback is at the END of a log — an oversized file is tailed,
#     never skipped wholesale), file-count bound. Small: runs BEFORE the partial
#     dirs so a worst-case timeout still lands the tracebacks.
LOG_FILE_CAP = int(os.environ.get("EPS_PERSIST_LOG_FILE_CAP_BYTES", 5 * 1024**2))
LOG_MAX_FILES = int(os.environ.get("EPS_PERSIST_LOG_MAX_FILES", 40))
def _up_logs():
    logs_root = root / "logs"
    if not logs_root.is_dir():
        _say(f"[crash-persist] SKIP worker_logs: no such dir ({logs_root})")
        return
    entries = []
    for dirpath, dirnames, filenames in os.walk(logs_root):
        dirnames[:] = [d for d in dirnames
                       if d not in PRUNE and not (d.startswith("g") and d.endswith("_dl"))]
        for f in filenames:
            p = Path(dirpath) / f
            try:
                st = p.stat()
            except OSError:
                continue
            entries.append((st.st_mtime, st.st_size, p))
    if not entries:
        _say("[crash-persist] SKIP worker_logs: empty after cache excludes")
        return
    entries.sort(reverse=True)  # newest first: the crashing worker wrote last
    dropped = len(entries) - LOG_MAX_FILES
    if dropped > 0:
        _say(f"[crash-persist] SKIP {dropped} older worker log(s) beyond"
             f" EPS_PERSIST_LOG_MAX_FILES={LOG_MAX_FILES}")
    for _, size, p in entries[:LOG_MAX_FILES]:
        try:
            if log_path and p.resolve() == Path(log_path).resolve():
                _say(f"[crash-persist] SKIP worker_logs/{p.relative_to(logs_root)}:"
                     " is the canonical workload.log")
                continue
            rel = p.relative_to(logs_root)
            src = str(p)
            if size > LOG_FILE_CAP:
                tmp = Path("/tmp/eps-worker-logs") / rel
                tmp.parent.mkdir(parents=True, exist_ok=True)
                with open(p, "rb") as fin, open(tmp, "wb") as fout:
                    fin.seek(size - LOG_FILE_CAP)
                    fout.write(fin.read(LOG_FILE_CAP))
                src = str(tmp)
                _say(f"[crash-persist] TAILED worker_logs/{rel}:"
                     f" kept last {LOG_FILE_CAP} of {size} bytes")
            _up_file(src, f"{dest}/worker_logs/{rel}")
        except Exception as exc:
            _say(f"[crash-persist] FAILED worker_logs sweep at {p}: {exc}")
_up_logs()
```

Notes: `_up_file` already provides guarded upload + the "uploading/uploaded/FAILED" `_say` pair, so upload logging is uniform for free; the per-file outer try/except means a tail-copy or resolve failure degrades to one loud FAILED line and the loop continues — nothing can abort the persist (which is anyway inside `timeout 300` + `|| true` at the bash layer). ### 4.3 Ordering decision

`crash_report.json` → `workload.log` → **`worker_logs/` (new)** → `eval_results_issue_<N>/` → `data_issue_<N>/` → `data_issue<N>/` → `workload_<ts>.log` → transcript LAST. The worker logs are the highest-value artifact after the canonical pair (they carry the actual traceback — the whole point of this task) and are size-bounded by construction (≤200 MiB worst case), while the partial dirs can be up to 2 GiB each; #854's stated small-first principle ("a worst-case timeout still lands it") places them before the dirs.

### 4.4 Exclusions

- The existing `PRUNE` dirnames prune applies inside `logs/` (defensive; caches are unlikely there).
- The canonical workload log (`EPS_LOG_PATH` = `<vm_scratch_dir>/logs/issue-<N>.log`, `log_path_for` at gcp.py:766–773) lives **outside** `$WORKLOAD_ROOT` (= `<vm_scratch_dir>/eps-issue-<N>`, `workload_dir_for` at :756–762), so no double-upload occurs by default; the `p.resolve() == Path(log_path).resolve()` skip is a one-line defensive guard for a nonstandard `EPS_LOG_PATH`.
- All regular files under `logs/` are eligible (not just `*.log`): fan-out dispatchers also write `.out`/`.err`/pid breadcrumbs; the count bound + tail cap keep this safe, and restricting to `*.log` would miss real stderr files. Tiny non-log files cost one upload call each and are bounded by the same count.

## 11. Decision Rationale

- **Tail-per-file over `_up_dir` dir-cap reuse.** What: new `_up_logs` with per-file tail. Why: dir-cap SKIPs wholesale → loses the traceback (the artifact this task exists to save); tail keeps the log END where tracebacks live. Source: #854's `_up_dir` cap semantics (gcp.py:1400–1403, "SKIP … oversized") + task-body sketch. Alternatives: `_up_dir` + `EPS_PERSIST_DIR_CAP_BYTES` (rejected — wholesale skip), `upload_folder` with size filter (rejected — `ignore_patterns` can't tail).
- **`EPS_PERSIST_LOG_FILE_CAP_BYTES` = 5 MiB.** Why: a traceback is KBs; 5 MiB keeps ~50k tail lines of context (engine-init dumps + traceback) while bounding worst case. Source: task-body sketch ("keep the last ~5 MB per file"); naming mirrors the #854 `EPS_PERSIST_DIR_CAP_BYTES` precedent. Alternatives: 1 MiB (risks cutting long vLLM init context), 16 MiB (inflates worst case 3×).
- **`EPS_PERSIST_LOG_MAX_FILES` = 40, newest-first.** Why: #779's fan-out wrote ~10 log files (8 GPU workers + main + judge); 40 = 4× headroom for multi-phase fan-outs; newest-first guarantees the crashing round's logs land within the bound; 40 × 5 MiB = 200 MiB ≈ 10–40 s upload — safe within the 300s bound. Source: #779 incident record + `issue779_dispatch_armb.sh` layout. Alternatives: 20 (tight for 8-GPU × multi-phase), unbounded (violates the 300s discipline).
- **Ordering: after `workload.log`, before partial dirs.** Why: highest diagnostic value after the canonical pair; size-bounded by construction while the dirs are up to 2 GiB each; #854's small-first principle. Source: gcp.py:1352–1356 comment ("small-first; a worst-case timeout still lands it"). Alternative: after the dirs (rejected — a dir-upload timeout would then lose the tracebacks again).
- **Streamer print cap 60 → 120.** Why: ≤80 new `_say` lines would starve the serial console of later stages under 60; 120 × 2000 chars = 240 KB, well inside the GCE serial buffer. Source: gcp.py:1439–1442 + grep-verified absence of a `60` test pin (only `tests/test_gcp_backend.py:4073` pins the read-to-EOF form). Alternative: single-line-per-file logging bypassing `_up_file` (rejected — duplicates guarded upload code inside the heredoc).
