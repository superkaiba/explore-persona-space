# Plan v1 — Task #483: Canonical distance-varied persona pool + maintained pairwise cosine-distance matrix + loader

`kind: infra` — no model training, no behavioral DV. Where the standard experiment-plan sections demand training/measurement-validity content, this plan writes the explicit exemption strings (`N/A — no model training`, `N/A — no behavioral construct`) per the planner spec; the extraction recipe itself is still fully grounded in §11.

---

## 0.0 TL;DR (plain English)

- **What I'll build:** One canonical list of ~140+ personas with their system prompts, a committed table of how far apart every pair sits in the model's representation space, and a small library function that — given the personas an experiment trains on — hands back a held-out evaluation panel with several personas at every distance, near to very far. Experiments stop hand-picking panels that accidentally bunch up at one end.
- **What I expect:** The personas the project already has cover almost the whole distance range (I checked the existing measurements: every distance bin already holds 4+ personas relative to the standard source pool). The real gaps are diversity ones — the 0.20–0.25 bin is all comedians — so I'll write a handful of new far-out personas, measure where they actually land, and keep only the ones that land where intended.
- **What would change my mind:** If a fresh measurement run disagrees with the old saved one (same personas, distances move by more than noise), that means the measurement pipeline isn't stable enough to call "canonical," and I stop and diagnose before committing anything.

## 3. Design

### 3.0 Pipeline overview

```
Phase A (CPU, VM)      assemble candidate roster + round-1 synthetic prompts (Claude call)
Phase B (GPU, 1 pod)   extract recipe-(a) centroids, layers {7,10,14,20,21,27}, all candidates
                       + recipe-(b) response-mean centroids at L20/L21 (vLLM gen + TF mean-pool)
Phase C (CPU, on-pod, <10 min)  matrices (both centerings) + occupancy audit + stability gate
Phase D (conditional, ≤2 more rounds)  synthetic revision → re-extract new candidates only (GPU, minutes)
Phase E (CPU, VM)      commit artifacts + loader + wiring + tests; HF uploads; .gitignore negation
```

Phases C/D run while the pod is alive (each <10 min CPU — under the off-pod threshold); the pod terminates after the final extraction + HF upload, before Phase E.

Name collisions resolve in the order above (first occurrence wins); duplicates logged.

### 3.2 Synthetic personas — generate → measure → keep/revise

**Why a model call, not code:** persona system prompts are creative text; a single Claude Sonnet (`claude-sonnet-4-5`) call per round generates them. The keep/revise decision is code (measured distances). What would flip it: nothing — there is no code path that writes persona prompts.

- **Round 1 (unconditional):** 24 candidate prompts targeting the measured gaps, deliberately **non-comedy** (the 0.20–0.25 bin is currently 100% comedy family). Archetype axes, chosen because the measured farthest natural personas are register/affect extremes (`mysterious_person` 0.339, `grumpy_person` 0.313, `drill_sergeant` 0.257, `formal_assistant` 0.277): non-human entities (ship AI, ancient deity, hive-mind), extreme registers (legalese formalist, telegraphic oracle, Shakespearean), affective extremes (nihilist, manic enthusiast), antiquated/fantasy voices, rule-bound bureaucrats, cryptic minimalists. 1–3 sentences each, same shape as existing prompts.
- **Measure:** extracted in the same Phase B job; a synthetic *lands* if its raw-L20 min-dist to POOL_16 falls in its `target_band`.
- **Keep rule:** keep any synthetic landing in a band whose occupancy audit shows a deficit (vs either reference set, or the non-comedy 0.20–0.25 stretch goal); keep at most 12 synthetics total in pool v1 (avoid synthetic-dominating the far end); rejected candidates recorded in `pool_meta_v1.json` with their measured landings.
- **Rounds 2–3 (conditional):** only if a deficit band remains. The revision prompt to Claude includes round-1's measured landings (which styles overshot/undershot). Re-extract only the new candidates (~2 min each round).
- **Round cap: 3** (kill criterion §6).

### 3.3 GPU extraction (Phase B)

`scripts/build_canonical_persona_pool.py --extract --device cuda:0` on the pod:

- **Recipe (a) — primary.** Reuse `explore_persona_space.analysis.representation_shift.extract_centroids(model_path="Qwen/Qwen2.5-7B-Instruct", personas=<roster prompts>, questions=EVAL_QUESTIONS, layers=[7,10,14,20,21,27])` — last non-padding prompt-token hidden state, mean over the 20 questions, 0-indexed decoder blocks (the #505 convention). ~185 personas × 20 questions = ~3,700 short forwards. One change ported in: support `prompt=None` → no system message (for `no_persona`); verify `extract_centroids` currently handles this, else extend (small, flagged for the implementer).
- **Recipe (b) — secondary, L20+L21 only.** New `extract_centroids_response_mean()` in `representation_shift.py`: (1) vLLM greedy generation (temp=0, `max_new_tokens=1024`, truncation rate logged and required ~0 per the #548 manipulation-check discipline) for all roster×questions; (2) batched HF teacher-forced forwards over `prompt + own response`, mean-pool hidden states over **response tokens only** at L20/L21; mean over questions. Batched per code-style throughput rules (no batch-1 loops; GPU-resident pooling, only pooled vectors to CPU).
- **Outputs:** `centroids_v1_L{layer}.pt` bundles (schema mirrors #505: `centroids`, `persona_names`, `layer`, `base_model`, `questions`, plus `recipe`, `built_at`, `commit`) + recipe-b bundles `centroids_v1_respmean_L{20,21}.pt`. Uploaded to HF data repo `superkaiba1/explore-persona-space-data/issue483_canonical_persona_pool/` with `list_repo_files` post-upload verification (reuse the #505 `_upload_bundle_to_hf` pattern). Checkpoint-per-phase: each bundle persisted+uploaded as produced.

### 3.4 Matrices + audits (Phase C, CPU)

`--build-matrices`:

- For each layer × centering ∈ {`global_mean`, `none`}: `compute_cosine_matrix(centroids, centering=...)` → distance = 1 − sim. JSON schema: `{schema_version: "cpp_v1", persona_names, distance, layer, centering, metric: "1 - cosine", extraction: {recipe, base_model, n_questions, questions_sha256, layers_convention: "0-indexed decoder blocks"}, built_from: {centroids_sha256, commit}}`.
- **Stability gate (blocking):** on the 111 shared personas, elementwise |Δ raw-L20 distance| vs the legacy matrix — require p95 ≤ 0.01 and the `assistant`↔`helpful_assistant` noise-floor distance ≤ 0.005. Fail → do not commit; diagnose (this is kill criterion K1).
- **#478 regression (blocking):** band assignment of the 35 #478 held-out personas (min-dist to POOL_16, raw478 edges) matches #478's pinned memberships with ≤3 single-band shifts.
- **Occupancy audit:** per reference source set (POOL_16, {assistant}, {medical_doctor} informational), per band: members + counts, comedy-family share, written to `pool_meta_v1.json`.
- **`centered_v1_L20` band edges:** fixed at build time as the centered-distance values that best reproduce the raw478 band memberships (monotone/quantile match on the pool's min-dist-to-POOL_16 distribution), committed in `pool_meta_v1.json`. (Centered distances run ~6× raw per #536 — the mapping is measured, not assumed.)
- **Legacy-dict comparison:** Spearman between frozen `ASSISTANT_COSINES`/`DOCTOR_COSINES` and pool-derived L10-centered similarities on the shared personas, recorded in `pool_meta` (expected high; informational — exact values cannot match because centered cosine is bank-dependent, #536).
- **Recipe-(a)↔(b) and L20↔L21 agreement:** Spearman over pairwise distances, recorded in `pool_meta` + surfaced in the task write-up.

## 6. Success criteria + kill criteria

**Success (quantitative):** AC1–AC5 all pass; specifically AC2's ≥4-per-band × 5 bands × 2 reference sets read off the committed canonical matrix by pytest; stability gate p95 |Δdist| ≤ 0.01 + noise floor ≤ 0.005; #478 regression ≤3/35 shifts; L20↔L21 and recipe-(a)↔(b) Spearman recorded (expected ≥0.95 / ≥0.8; informational, not gating).

**Kill criteria:**

- **K1 (blocking):** stability gate fails (fresh extraction p95 |Δ raw-L20 dist| > 0.02 vs legacy on the shared 111, after one diagnosis pass for batching/padding effects) → STOP, post `epm:failure` (`failure_class: code`); do not commit matrices that can't reproduce the lineage they claim to canonicalize.
- **K2 (non-blocking, documented):** synthetics cannot fill the non-comedy 0.20–0.25 bin after 3 rounds → ship pool v1 all-natural-plus-whatever-landed; the deficit is recorded in `pool_meta` and the loader's `BandUnsatisfiableError` keeps consumers honest. (AC2 already passes on natural personas vs POOL_16; only a vs-assistant band deficit would also be documented this way.)
- **K3 (blocking):** #478 regression >3/35 band shifts → same handling as K1 (it implies extraction drift, not a design problem).

## 11. Decision Rationale

*(`kind: infra` — no training hyperparameters; the load-bearing choices are the extraction/measurement parameters below.)*

- **Extraction recipe primary = (a) last-prompt-token over 20 EVAL_QUESTIONS.** Why: every bank centroid artifact in the project (#405/#478 L20 matrix, #472 bank, #505 L{7,14,21,27}) is recipe (a) over these exact questions — the pool's purpose is comparability for that consumer line. **Source: `.claude/rules/persona-distance-metrics.md` variant (a) + #478/#505.** Alternatives: recipe (b) as primary (paper-faithful) — rejected: breaks numeric continuity with every existing artifact and adds a generation step to every future maintenance re-extraction; instead shipped as a measured secondary.
- **Recipe (b) secondary at L20/L21.** Why: the rule names (b) as the Persona Vectors recipe; committing the (a)↔(b) agreement number pre-empts the recipe-choice objection for the whole line. **Source: arXiv 2507.21509 (difference-of-means; LaTeX-verified in #536 Phase A0 — inherit fast-path).**
- **Canonical layer = 20; layers {7,10,14,20,21,27} committed.** Why: the body's own acceptance band numbers (~0.02–0.25) and every consumer's band edges are calibrated in L20 units; the rule's {7,14,21,27} sweep is satisfied by committing those layers too, and the build measures L20↔L21 Spearman so the choice is demonstrated (im)material rather than asserted. L10 added for the legacy-dict shims. **Source: #405/#478/#531/#553/#559/#560 lineage (L20); rule sweep set; ASSISTANT_COSINES (L10).** Alternatives: canonical 21 (rule's legacy default for the *raw-pairwise predictor* family) — rejected for the *bank* family on continuity grounds; revisit if measured L20↔L21 Spearman < 0.9.
- **Centering canonical = `global_mean`; raw committed as labeled legacy.** Why: raw bank cosine is deprecated for persona distance; centered is bank-dependent so the artifact must carry provenance + version pinning. **Source: #536 + rule § Bank centering.** Alternatives: raw-only (status quo) — deprecated; centered-only — would orphan the #478-lineage band edges the acceptance criteria are written in.
