# Plan — #1675: piped-git guard must ignore quoted strings that merely mention guarded verbs

### 0.0 TL;DR (plain English)

- **What I'll change:** the piped-git Bash hook currently pattern-matches its guarded verbs anywhere in the command text, including inside quoted string arguments — so a read-only search whose quoted pattern mentions a guarded phrase gets refused. I'll add a quote-span strip (single-quoted spans always; double-quoted spans only when they contain no live substitution) into the hook's existing normalization step, before any matching runs.
- **What I expect:** the verbatim 07-23 incident shape and every quoted-mention sibling become allowed; every real piped git/gh command shape (all B-cases, including quoted-argument and command-substitution forms) stays blocked. Already validated end-to-end on a patched /tmp copy at plan time: full embedded self-test PASS + 9/9 new cases.
- **What would change my mind:** if the pytest suite or self-test surfaced a true-positive shape the strip converts to a miss beyond the two documented, deliberately accepted interpreter-payload forms (`bash -c '...'` / `ssh host '...'` payloads), I'd fall back to preserving any quoted span that contains both a `|` and a guarded-verb bigram — at the cost of keeping the incident FP — and re-plan.

## 3. Design

**Chosen approach: (a) quote-span strip, with a substitution-preserving double-quote branch — folded into the existing normalization sed.** Approach (b), position-anchoring, is rejected because it mechanically fails the verbatim incident: the incident's quoted pattern contains `\|`, and the per-stage split on `|` (hook lines 154–157) runs on raw text, so the split lands the guarded verb at the START of a phantom stage — a command-position anchor still matches it. Position-anchoring additionally regresses keyword-prefixed true positives (`if true; then git push | head; fi` — the unit starts with `then`, so an anchored match misses a real piped producer the hook blocks today), fixable only with a keyword allowlist of exactly the drift-prone kind the header (lines 24–28) rejects. Once the strip runs first, (b) adds no FP coverage (post-strip, mentions survive only unquoted — a rare residual documented below), so the combination is also rejected.

### 3.1 The transform (verbatim, validated)

Two code edits inside the hook:

**Edit 1 — new top-level ERE variable**, inserted after the `PREFILTER_ERE` definition (line 95), with a comment block:

```bash
# Quoted-span strip (#1675): remove quoted STRING ARGUMENTS before any
# matching, so text that merely MENTIONS a guarded verb or a pipe never
# trips the guard. Single-quoted spans always strip (bash expands nothing
# inside them); double-quoted spans strip ONLY when substitution-free —
# a bare $ or backtick inside keeps the span (a "$(...)" payload EXECUTES,
# so it must stay scannable); backslash-escape pairs (\| \" \$) are
# consumed, matching bash's quote-boundary rules.
STRIP_QUOTED_SPANS_ERE="'[^']*'|\"(\\\\.|[^\"\\\\\$\`])*\""
```

The bash string expands to the ERE `'[^']*'|"(\\.|[^"\\$`])*"` (verified: `/tmp/qs_hook.sh:93`).

**Edit 2 — fold into the line-119 sed** (single process, no new fork):

```bash
# before (line 119):
cmd=$(printf '%s' "$cmd" | sed -zE 's/\\\r?\n/ /g')
# after:
cmd=$(printf '%s' "$cmd" | sed -zE -e 's/\\\r?\n/ /g' -e "s/${STRIP_QUOTED_SPANS_ERE}/ /g")
```

Each stripped span is replaced by a single space (word boundaries preserved). `-z` (already the line-119 idiom) makes the strip work across raw newlines inside multi-line quoted strings.

### 3.2 Where it sits in the match pipeline, and why

Order inside `check_cmd()` (line anchors are current-file):

1. Raw-string carve-outs — inline escape hatch (:102), pipefail (:109), heredoc (:114) — **unchanged, still pre-strip**. Their substring-on-raw semantics are deliberate (header lines 30–47) and each can only fail toward ALLOW.
2. Continuation normalization + **NEW quote strip** (one sed, :119). Continuation first, strip second: a quoted span broken across a backslash-continuation is rejoined before stripping.
3. Pre-filter (:122–123) — now sees stripped text, so the incident class exits at the cheap `grep -q` with no unit parse (a small speedup on exactly the FP class).
4. Unit split (:137–140) — now cannot be severed by quoted `&`/`;`/`&&` (a latent misparse class this fix also closes: previously `grep "a & b" f | head` split mid-string).
5. Per-stage producer match (:143–164) — now cannot see quoted verb mentions, and quoted `|` no longer fabricates phantom stage boundaries (the incident's second mechanism).

### 3.3 Strip semantics per span type (each with fail direction)

| Span | Stripped? | Why | Fail direction if bash disagrees |
|---|---|---|---|
| `'...'` single-quoted | always | bash expands nothing inside; cannot contain `'` | none (exact match to bash) |
| `"..."` no bare `$`/backtick | yes | pure string data; `\\.` consumes escape pairs (`\|`,`\"`,`\$`) so the incident's `\|` strips | escaped-quote pathologies leave fragments → scan → block-leaning |
| `"...$(...)..."` / `` "...`...`..." `` / `"...$VAR..."` | **no** | substitution is LIVE inside double quotes — a `"$( )"` payload executes and must stay scannable | span stays → scanned → block-leaning |
| unbalanced quote | no match | span never closes | text preserved → scanned → block-leaning |
| `$'...'` ANSI-C | not modeled | rare; treated as `$` + single-quoted span | possible mis-pair on `\'` → block-leaning residual |

Every divergence from true bash parsing fails toward SCAN (block-leaning) — the conservative direction for a strip whose purpose is removing false positives, and the inverse of the #796 failure mode (which failed toward hiding real semantics).

## 9. §11 Decision Rationale

- **D1 — quote-strip (a) over position-anchor (b) or a combination.** *What:* strip quoted spans before all matching. *Why:* (b) mechanically fails the verbatim incident — the quoted `\|` creates a phantom stage boundary that puts the guarded verb at stage START, where a command-position anchor still matches — and (b) regresses keyword-prefixed true positives (`then`/`do` unit prefixes) unless a drift-prone keyword allowlist is added (the exact list-maintenance failure the header :24–28 rejects). (a) closes both FP mechanisms (phantom boundaries from quoted separators + mid-stage verb mentions) at once. *Source:* plan-time empirical validation (patched copy: full self-test PASS, 9/9 new cases, miss probes) + sibling precedent read (`guard_repo_root_branch.sh:180–187`). *Alternatives rejected:* (b) alone (fails AC3(i)); (a)+(b) (adds the keyword regression risk for zero FP coverage once (a) runs); per-tool waiver lists à la the sibling's #1538 grep-consumer waiver (the FP here is producer-side text; the list grows per mentioning tool).
- **D2 — substitution-preserving double-quote branch.** *What:* strip `"..."` only when free of bare `$`/backtick; consume backslash-escape pairs via `\\.`. *Why:* `$(...)`/backtick payloads inside double quotes EXECUTE — stripping them fail-opens the B6-class quoted variants (B19/B20); `\\.` is required for the incident itself (its pattern contains `\|`). *Source:* bash quoting semantics (man bash § QUOTING: single quotes expand nothing; double quotes keep `$`, backtick live; backslash escapes `$` `` ` `` `"` `\`) + N5/N9/N1 probes. *Alternatives rejected:* strip all double-quoted spans (fail-open on B19/B20); strip none (incident is double-quoted — FP remains).
- **D3 — fold into the existing sed, not a second process.** *What:* second `-e` expression on the line-119 `sed -zE`. *Why:* the hook runs on every Bash tool call; zero added forks, and the pre-filter then short-circuits the FP class before the unit parse. *Source:* the hook's own hot-path design comment (:91–94). *Alternative rejected:* separate sed/awk pass (one extra fork per Bash call, no benefit).
- **D4 — why the #796 revert does not bind here.** *What:* proceed with a strip despite the sibling's reverted attempt. *Why:* the branch guard classifies quoted ARGUMENTS (refs like `"main"` are legitimately quoted and semantically load-bearing), so stripping destroyed real signal there; this hook's entire signal — producer verb, pipe, separators, `--dry-run` — is unquoted shell grammar in any real command. The single quoted-semantics exposure (`git push "--dry-run" | head`) fails toward BLOCK, the safe direction. *Source:* `guard_repo_root_branch.sh:180–187` read; hook :48–52 (dry-run carve-out). *Alternative rejected:* treating the #796 precedent as binding (it encodes a property of that guard's detectors, not of quote-stripping per se).
