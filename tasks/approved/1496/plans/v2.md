- **What I'll run:** I'll add a small discovery pass to the Step 9c test selector: when a diff touches a `.claude/rules/*.md` file, the selector scans `tests/` for test files that mention that rule's filename and adds them to the gate — today those pin tests only run if they happen to be in the generic always-on list. ### 4.1 New module block in `scripts/select_step9c_tests.py` (after `GLOB_SCAN_TESTS`, ~L271)

```python
# --- Rules-pin discovery arm (#1496). -----------------------------------------
# ~28 tests read/pin .claude/rules/*.md PROSE at test time; most are not in
# WORKFLOW_INVARIANT, so a rules-only diff got no targeted pin coverage (the
# rules glob short-circuits at WORKFLOW_SURFACE_GLOBS). Unlike GLOB_SCAN_TESTS
# this arm is DISCOVERED, not pinned: the founding bug IS pinned-map staleness
# (a new pin test added outside the invariant list silently stops gating its
# rule), a wrong join costs only extra tests on THAT rule's diffs
# (safe-by-direction, module docstring), and the import-map arm (#1299) is the
# established discovery precedent. Matching token: the rule's BASENAME
# ("llm-judging.md") as a raw-text substring — covers full-path literals,
# path-join forms ((ROOT / ".claude" / "rules" / "x.md"), the
# test_battery_basis_prose_pins.py shape), and comment/docstring mentions
# (deliberately counted; over-selection is the safe direction). Known-miss
# class (accepted): a test that constructs the filename dynamically. Additive
# only — never sets `matched`, never enters untested_touched (rules files are
# workflow-surface SKIPs by design; that semantics is unchanged).
# Scan-regression loudness: tests/test_select_step9c_tests.py
# ::test_rules_pin_live_tree_known_pairs pins known (rule -> test) pairs.
_RULES_GLOB = ".claude/rules/*.md"


def rules_pin_hits(touched: list[str], work_root: Path) -> dict[str, set[str]]:
    """``{test_relpath: {touched .claude/rules/*.md files whose basename its
    text mentions}}`` (#1496). Zero file reads when no rules file is touched.

    Fail-soft (the #1299 read contract): a test file that cannot be read /
    decoded emits ONE stderr WARN and is skipped — never crashes the selector.
    ``rglob`` only yields existing files, so no separate existence filter.
    """
    rules = [f for f in touched if fnmatch.fnmatch(f, _RULES_GLOB)]
    hits: dict[str, set[str]] = {}
    tests_dir = work_root / "tests"
    if not rules or not tests_dir.is_dir():
        return hits
    tokens = {r: Path(r).name for r in rules}
    for test_path in sorted(tests_dir.rglob("test_*.py")):
        rel = test_path.relative_to(work_root).as_posix()
        try:
            text = test_path.read_text(encoding="utf-8")
        except (OSError, ValueError) as exc:
            print(
                f"select_step9c_tests: WARN — rules-pin scan cannot read {rel}: {exc}; "
                "file skipped for the rules-pin arm",
                file=sys.stderr,
            )
            continue
        for rule, token in tokens.items():
            if token in text:
                hits.setdefault(rel, set()).add(rule)
    return hits


def rules_pin_pairs(files: list[str], work_root: Path) -> list[tuple[str, str]]:
    """Sorted ``(pin_test, rule_file)`` pairs for ``--map-files`` (#1496).

    WORKFLOW_INVARIANT members are EXCLUDED here (they already gate every
    Step 9c run; this also keeps the 900 s tests/test_workflow_lint.py out of
    the Step 10d / inline-payload lint gate). The Step 9c selection arm keeps
    them (harmless extra reason; the union dedupes).
    """
    inv = set(WORKFLOW_INVARIANT)
    return sorted(
        (t, r)
        for t, rule_files in rules_pin_hits(files, work_root).items()
        if t not in inv
        for r in sorted(rule_files)
    )
```

## 11. Decision Rationale

- **D1 — Mapping shape: runtime discovery, not a pinned map (and not a GLOB_SCAN_TESTS extension).**
  **What:** `rules_pin_hits` scans `tests/**/test_*.py` text at selection time for touched rule basenames.
  **Why:** the founding bug IS pinned-map staleness — the body requires that "a rules edit whose pin test exists but is unmapped should surface it", and a pinned map's drift pin lives in `tests/test_select_step9c_tests.py`, which is NOT selected by the diff that adds a new pin test (touched-test arm selects only the new test), leaving a silent under-coverage window until the next selector-touching diff or full-suite run. Discovery has no window: the pin test gates its rule the moment it exists on disk. Rules + pin tests accrete ~weekly (37 rules, 28 referencing test files today), so pinned-map maintenance cost is real and its enforcement mechanism is weaker than the bug it guards. Extending `GLOB_SCAN_TESTS` instead would break that map's curation contract (verbatim SCAN GLOBS from the scanning test's own source, drift-pinned by `test_glob_scan_map_matches_live_tree` L511-516 — prose-pin tests scan nothing) and would silently arm the Step 10d lint gate with unfiltered entries.
  **Source:** #1299 (commit `1482a126db`) — the in-file runtime-discovery precedent, including the fail-soft read contract this arm copies; #1496 body (the founding gap); GLOB_SCAN_TESTS curation comment, selector L238-241.
  **Alternatives considered:** (a) pinned `RULES_PIN_TESTS` map + a discovery drift-pin test — rejected for the staleness window + weekly curation churn on a hot file; (b) `GLOB_SCAN_TESTS` entries — rejected per above; (c) hybrid map+WARN — rejected as two mechanisms where one suffices.

- **D2 — Cascade position: seed before the per-file loop (additive to the WORKFLOW_SURFACE skip, which is unchanged).**
  **What:** hits seed `selected` alongside `_seed_import_reasons`; the rules file itself still takes the L627 `continue`.
  **Why:** confirmed by reading L621-628 that the glob-scan arm already runs BEFORE the surface skip (design question 2) — additive-arm-plus-skip is the established order; seeding (the #1299 shape) lets one scan serve all touched rules and preserves the documented "selection only grows" invariant verbatim (L608-613).
  **Source:** #895 (arm position, L622-625); #1299 (seeding, L614-615).
  **Alternatives:** an in-loop check before the `continue` — equivalent semantics but re-scans tests/ per touched rule; rejected on cost + symmetry with import-map.

- **D3 — `--map-files` / Step 10d lint gate: include rules-pin pairs, MINUS `WORKFLOW_INVARIANT` members (deliberate call, design question 3).**
  **What:** `rules_pin_pairs` joins the `--map-files` stdout; invariant members filtered; `map_scan_tests` untouched; SKILL.md logic untouched (one stale dormancy comment synced, §4.6).
  **Why include:** rules edits also land via paths with NO Step 9c gate (inline-payload rounds, direct orchestrator workflow commits that route through the Step 10d/inline lint gate) — the pin test running at the merge that edits the rule is precisely the targeted coverage this task exists to create (#1388 is the incident class: payload-linked breakage landing ungated). Cost: typically 1–7, worst case 15 (`gotchas.md`) extra small pytest files, only on rules-touching payloads (fact-checked fan-out; §6 pre-registers the wall-time measurement + escape hatch against the TG 300 s bound). **Why the invariant filter:** without it, every rules-touching merge payload would arm `tests/test_workflow_lint.py` (SLOW_TESTS, 771 s measured max) in the lint gate — real blast radius for zero marginal coverage (invariants gate every 9c run already), and under basename matching that file cites 11 rules, so the filter binds a fortiori. The 9c selection arm keeps invariant hits (union dedupes; the extra `rules-pin:` reason is informative) — asymmetry documented in `rules_pin_pairs`' docstring and pinned by `test_cli_map_files_rules_pin_excludes_invariant`. **Known limitation (documented):** at the TG/inline gates the payload-attribution grep keys on payload PATHS in the output; a failing rules-pin test's output names the test file, not the rule path (unless the assertion quotes it), so such a failure surfaces in the recorded tg tail / WARN note rather than hard-blocking there — mechanical blocking for rules edits lives at the Step 9c gate, which this arm now arms correctly.
  **Source:** #1147 (commit `195fbc947e`, the pair-consumer contract); SKILL.md L6541 consumer recipe (pair-generic, verified); #1046 (`SLOW_TESTS` measurement, selector L272-292); #1388 (inline-landed breakage incident, CLAUDE.md § inline payload lint gate).
  **Alternatives:** (a) Step-9c-only scope — rejected: leaves the no-9c landing paths uncovered, the highest-value case; (b) unfiltered inclusion — rejected on the 900 s blast radius; (c) also filter `GLOB_SCAN_TESTS` members — rejected: `test_shared_vm_thread_caps.py` is fast and a genuine prose-citer, over-select is safe.

- **D4 — Matching token: rule BASENAME substring over raw test text; comment/docstring mentions count (design question 4).**
  **What:** touched `.claude/rules/<name>.md` matches any test whose text contains `<name>.md`.
  **Why:** a full-path-literal match provably UNDER-selects: `tests/test_battery_basis_prose_pins.py` L20 is a genuine prose-pin test using the path-join form (`(REPO_ROOT / ".claude" / "rules" / "critic-lens-reference.md")`) with no full-path literal — the basename is the invariant substring across the full-path form (25 files, contains the basename by construction), the path-join form, and prose citations. Rule basenames are distinctive hyphenated or unique names (shortest tie at 10 chars: `gotchas.md` / `LESSONS.md`), collision risk negligible, and two rules cannot share a basename (one directory). Comment-only mentions counting is the stated safe-by-direction posture (selector L41-45) — the brief's "simplest: it counts" call. Known-miss class (documented in the code comment): dynamically-constructed filenames.
  **Source:** live-tree census (§2, verified 2026-07-18); module docstring safe-by-direction posture L41-45.
  **Alternatives:** (a) full-path literal only — rejected: verified real-world miss; (b) AST string-literal extraction — rejected: more code for strictly less recall (misses comments, which we WANT to count), no precision need given safe direction.

- **D5 — Drift-pin design: live-tree superset pin on 3 verified pairs + fixture unit tests; no map-completeness pin (there is no map).**
  **What:** `test_rules_pin_live_tree_known_pairs` (the check-31 durability pin) asserts the scan discovers `pod-side-reporting.md → test_pod_side_reporting_push_contract.py` (full-path form), `critic-lens-reference.md → test_battery_basis_prose_pins.py` (path-join form — pins D4's basename semantics), `llm-judging.md → test_judge_dispatch.py`; superset, not equality.
  **Why:** under discovery the only silent-shrink channel is a regression in the scan function itself; a live-tree pin on both reference FORMS catches exactly that, while superset semantics let new pin tests join without breaking it.
  **Source:** the file's own drift-pin convention (`test_pinned_invariant_list_matches_live_tree` L128, `test_glob_scan_map_matches_live_tree` L495, `test_slow_tests_pinned_to_live_tree` L534).
  **Alternatives:** equality assert on a full census — rejected: breaks on every legitimate new pin test (the anti-goal).

- **D6 — Timeout sizing: no change (design question 5).**
  **What:** discovered pin tests enter `recommended_timeout_s` via `len(tests)` at 30 s/file.
  **Why:** the non-invariant discovered tests are small unit files (fact-checked: the 17 gotchas.md citers are mostly fast issue-specific unit files); the sole slow file is invariant (already surcharged) and filtered from `--map-files`. The 9c gate sizes automatically at 30 s/file (`len(tests)`), so even the 17-file worst case adds ~8.5 min of bound, not a wedge risk. The §6 wall-time measurement is the check on this characterization.
  **Source:** #1046 (selector L272-292, measured constants); fact-checker fan-out census 2026-07-18.
  **Alternatives:** a rules-pin surcharge — rejected, no measured need yet (the §6 measurement is the revisit trigger).
