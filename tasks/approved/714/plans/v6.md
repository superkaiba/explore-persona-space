### 4.1 Scope — new `SKILL_REF_DOC_FILES` walk (wide), not a `DOC_FILES` widening

Introduce a NEW scope helper rather than reusing `DOC_FILES` (3 files) or widening it. The scope
is the union of:
- every `.claude/agents/*.md`,
- every `.claude/skills/**/SKILL.md`,
- every `.claude/rules/*.md`,
- `CLAUDE.md`,
- `.claude/workflow.yaml`.

```python
def _iter_skill_ref_target_files(repo_root: Path) -> list[Path]:
    """Production scope for --check-skill-refs: agents + all SKILL.md + rules +
    CLAUDE.md + workflow.yaml, OTHER-worktree copies excluded (the current
    worktree IS scanned so a workflow-fix /issue session validates its own
    edits). Mirrors _iter_ask_target_files (line 797) but with the wider root
    set the skill-rot failure class actually touches."""
    current_prefix = _other_worktree_prefix(repo_root)
    files: list[Path] = []
    agents = repo_root / ".claude" / "agents"
    skills = repo_root / ".claude" / "skills"
    rules = repo_root / ".claude" / "rules"
    if agents.exists():
        files += [p for p in agents.glob("*.md")
                  if p.is_file() and not _is_other_worktree_path(p, current_prefix)]
    if skills.exists():
        files += [p for p in skills.glob("**/SKILL.md")
                  if p.is_file() and not _is_other_worktree_path(p, current_prefix)]
    if rules.exists():
        files += [p for p in rules.glob("*.md")
                  if p.is_file() and not _is_other_worktree_path(p, current_prefix)]
    for extra in (repo_root / "CLAUDE.md", repo_root / ".claude" / "workflow.yaml"):
        if extra.is_file() and not _is_other_worktree_path(extra, current_prefix):
            files.append(extra)
    return sorted(files)


def _resolve_skill_ref_target_files(roots: list[Path] | None) -> list[Path]:
    """roots=None -> canonical walk; roots=[tmp_path] -> fixture scope for tests
    (mirrors _resolve_ask_target_files, line 882)."""
    if roots is None:
        return _iter_skill_ref_target_files(_REPO_ROOT)
    files: list[Path] = []
    for root in roots:
        if root.is_file():
            files.append(root)
        else:
            files.extend(p for p in root.glob("**/*.md") if p.is_file())
    return sorted(files)
```

**Justification (measured, 2026-06-28):** backticked core-skill refs (`/weekly /daily
/adversarial-planner /issue /campaign`) by area: agents 119, skills 166, **rules 51 (incl. a live
`/weekly`), CLAUDE.md 34, workflow.yaml 12**. The `DOC_FILES` triple covers only 3 of the `/weekly`
hits; the agents+skills `--check-script-refs` scope covers 7 but MISSES the CLAUDE.md + rules refs
that are squarely in the rot class. The new scope guards the full surface. `DOC_FILES` itself is left
untouched (so `--check-references` and its pre-commit `files:` regex are unaffected).

### 4.2 Match regex (false-positive control)

```python
# `--check-skill-refs`: every backtick-delimited `/<skill-name>` slash-command
# token in the workflow-doc surface MUST resolve to a live project skill (a
# `.claude/skills/<name>/` directory) or to SKILL_REF_ALLOWLIST. Backtick-anchor
# + trailing lookahead are the FP controls: only the slash-command convention
# matches, and a path segment (`/workspace/logs`, `/tmp/x`, `/mnt/...`) is
# rejected because the char after the token is `/`, not the required
# backtick / whitespace / `)` boundary. Group 1 = skill name, optionally
# `<plugin>:<skill>`.
SKILL_REF_RE = re.compile(r"`/([a-z][a-z0-9-]+(?::[a-z0-9-]+)?)(?=[`\s)])")

_FENCE_RE = re.compile(r"^\s*(?:```|~~~)")
```

Properties (verified by probing the live wide surface, 2026-06-28):
- The opening `` ` `` forces the slash-command convention; the bare-token path flood (152 distinct
  tokens) collapses to a small finite set.
- `(?=[`\s)])` requires the token to be CLOSED by a backtick, whitespace, or `)` — so
  `` `/workspace/logs/...` `` does NOT match `/workspace` (next char `/`), while `` `/issue` `` and
  `` `/issue <N>` `` both match `/issue`.
- `(?::[a-z0-9-]+)?` captures the plugin-namespace form (`/codex:rescue`).
- `[a-z][a-z0-9-]+` requires ≥2 chars + a leading lowercase letter (so `/N`, `/x`, numeric fragments
  do not match).

### 4.4 The check function

```python
def check_skill_references(
    *,
    roots: list[Path] | None = None,
    skills_dir: Path | None = None,
    allowlist: frozenset[str] | None = None,
) -> list[str]:
    """Walk the workflow-doc surface (agents + skills + rules + CLAUDE.md +
    workflow.yaml) and FAIL on any backtick-delimited `/<skill-name>` token that
    resolves neither to a live skill dir under `.claude/skills/` NOR to
    SKILL_REF_ALLOWLIST (exact token or namespace prefix).

    Closes the skill-rename / skill-retirement rot class: --check-references only
    resolves `(see workflow.yaml § X)` tokens, so a retired skill (e.g. /weekly)
    leaves stray load-bearing references that no mechanical check catches
    (#713 Methodology-critic finding; #714).

    Lines inside fenced code blocks (``` / ~~~) are skipped (HTML close tags / sed
    one-liners / regex fragments). Lines carrying HISTORICAL_REF_OPT_OUT are
    skipped (one-off narrative citation). Plugin-namespaced refs resolve via the
    allowlist prefix set (or, forward-compat, an on-disk `<plugin>:<skill>/` dir).

    `roots` / `skills_dir` / `allowlist` are unit-test override hooks; production
    callers pass None.
    """
    errors: list[str] = []
    sk_dir = skills_dir if skills_dir is not None else _REPO_ROOT / ".claude" / "skills"
    live = _live_skill_names(sk_dir)
    allow = allowlist if allowlist is not None else SKILL_REF_ALLOWLIST
    for path in _resolve_skill_ref_target_files(roots):
        in_fence = False
        for lineno, line in enumerate(path.read_text(encoding="utf-8").splitlines(), start=1):
            if _FENCE_RE.match(line):
                in_fence = not in_fence
                continue
            if in_fence or HISTORICAL_REF_OPT_OUT in line:
                continue
            for match in SKILL_REF_RE.finditer(line):
                ref = match.group(1)
                if _skill_ref_resolves(ref, live, allow):
                    continue
                errors.append(
                    f"{path}:{lineno}: unresolved skill reference '/{ref}' — not a "
                    f"live skill under .claude/skills/ and not in "
                    f"SKILL_REF_ALLOWLIST. Repoint to the current skill, remove the "
                    f"dead reference, add the command to SKILL_REF_ALLOWLIST "
                    f"(user-global / plugin / built-in command, with a justifying "
                    f"comment), or — for a one-off narrative citation — append "
                    f"'{HISTORICAL_REF_OPT_OUT}' to the line."
                )
    return errors
```

Per-file `in_fence` reset means a code fence in one file cannot bleed into the next.

## §11 Decision Rationale

**Scope = new wide `SKILL_REF_DOC_FILES` (agents + skills + rules + CLAUDE.md + workflow.yaml)**
- **What:** a new walk helper, not a `DOC_FILES` widening, not the agents+skills-only `--check-script-refs` scope.
- **Why:** tied to the Goal — the `/weekly`-rot failure class lives partly in `CLAUDE.md` (34 backticked core-skill refs) and `.claude/rules/` (51, incl. a live `/weekly`); agents+skills-only misses them. `DOC_FILES` (3 files) misses almost everything; widening `DOC_FILES` would perturb `--check-references` + its pre-commit regex.
- **Source:** live-surface probe 2026-06-28 (backticked core-skill refs: agents 119 / skills 166 / rules 51 / CLAUDE.md 34 / workflow.yaml 12); precedent `_iter_ask_target_files` (workflow_lint.py:797) for the worktree-aware walk shape; `--check-script-refs` scope (:1105).
- **Alternatives:** reuse `DOC_FILES` (rejected — misses refs); reuse `--check-script-refs` scope (rejected — misses CLAUDE.md + rules, where part of the bug lives); widen `DOC_FILES` (rejected — changes 2 other checks + pre-commit).

**Live-skill resolution by DIRECTORY existence (not `SKILL.md`)**
- **What:** `{p.name for p in Path(".claude/skills").iterdir() if p.is_dir()}`.
- **Why:** `clean-results` is a live skill dir with no `SKILL.md` (SPEC.md/exemplars/iterations.md); a `*/SKILL.md` glob false-FAILs `/clean-results`.
- **Source:** on-disk inspection 2026-06-28 (`.claude/skills/clean-results/` has no SKILL.md).
- **Alternatives:** candidate's `glob("*/SKILL.md")` — rejected (false-FAILs `/clean-results`).

**Allowlist as in-module frozenset with namespace-prefix support (not a separate `.txt`)**
- **What:** `SKILL_REF_ALLOWLIST: frozenset[str]`, inline-commented; `:`-suffixed entries are namespace prefixes.
- **Why:** every existing allowlist in this lint is in-module + inline-commented; a separate file diverges from precedent, adds a sync burden, loses per-entry justification. Prefix entries cover churning plugin trees (`/superpowers:*` = 14) without per-member enumeration. The set is small + slow-drifting (the `MARKER_REGISTRY_ALLOWLIST` profile).
- **Source:** `MARKER_REGISTRY_ALLOWLIST` (workflow_lint.py:284); the system-reminder plugin-skill list (brief context) for the prefix set.
- **Alternatives:** `.claude/skill_ref_allowlist.txt` (candidate suggestion) — rejected (no precedent, sync burden); per-member plugin enumeration — rejected (stale within days); inline `<!-- ... -->` opt-out as PRIMARY mechanism — rejected (`/humanize` ×9 / `/loop` ×11 would litter the surface; opt-out retained only for one-off citations).

**Backtick-required matching regex + trailing-`/` lookahead + fenced-code exclusion**
- **What:** `` `/([a-z][a-z0-9-]+(?::[a-z0-9-]+)?)(?=[`\s)]) ``; skip ``` / ~~~ fences; skip `HISTORICAL_REF_OPT_OUT` lines.
- **Why:** a bare-`/foo` regex yields 152 distinct FPs (path segments, prose); the backtick form is the canonical invocation syntax and is high-signal (mirrors `--check-asks` keying on the literal `AskUserQuestion`); the trailing-`/` lookahead rejects path continuations (`/workspace/logs`); fenced-code exclusion drops HTML close tags / sed / regex fragments; reusing the existing opt-out token keeps the one-off escape consistent.
- **Source:** live-surface probe 2026-06-28 (loose → 152 tokens; backtick+lookahead → ~40, all live skills or the §4.3 allowlist); precedent `SCRIPT_REF_RE` boundary discipline (:209), `--check-asks` literal keying (:897), `HISTORICAL_REF_OPT_OUT` (:220).
- **Alternatives:** candidate's bare `r"/([a-z][a-z0-9-]+(?::[a-z0-9-]+)?)\b"` — rejected (152-token flood); refined-boundary bare regex — rejected (still ~39 FPs after fence/HTML exclusion).
