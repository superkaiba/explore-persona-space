## 4. Design

### Method delta (what the new text adds)

1. **vs the #488 entry:** #488's rules (a)/(b) govern the SILENT-LOSS direction — a wrapper that logs-and-continues on no-path loses artifacts. The new clause (c) governs the FAIL-FAST direction — a seam that correctly raises on no-path still must retry transport-class first, or fleet HF traffic kills runs at their final phase. (b) and (c) are complements: (b) bans continuing without the retry+raise; (c) mandates the retry before the raise.
2. **vs the #931 wedge ladder:** the ladder is OUT-OF-PROCESS recovery for a HUNG upload that never returns (kill + replay with env — env is frozen at `huggingface_hub.constants` import, so no in-process action can help). The seam retry is IN-PROCESS recovery for a FAILED upload that returns `""` promptly. Discriminator = did the call return? Returned-empty → seam retry loop; never-returns / ~0 TX → ladder. Neither substitutes for the other: a retry loop can never reach a hang (it is blocked inside the call), and a kill+replay is wasteful for a 429 that clears in 30-120 s. The draft text states this composition in its closing sentence.

```text
; (c) the FAIL-FAST direction needs a bounded transport retry (#1315): a
dispatcher seam that RAISES on `hub._upload`'s no-path return (correct —
(b) bans warning-and-continue) must first RETRY the no-path return with
bounded jittered exponential backoff, then raise the SAME fail-loud error
on exhaustion. `hub._upload` catches upload failures internally, logs
"Upload failed: …", and returns "" (`orchestrate/hub.py:1295`), so at the
seam the no-path return is the retry trigger — in practice transport-class
(HF 429, Xet "maximum queue size reached"), though a persistent
content-class failure (e.g. quota 403) also returns "" and costs one
bounded backoff cycle (~3.5-4.5 min) before the same raise — bounded,
acceptable; errors the seam's own guards RAISE propagate un-retried.
Retries are free: uploads are idempotent (already-landed files verify +
skip Hub-side), and huggingface_hub does NOT retry 429 here — its
`http_backoff` defaults to 5xx only (500/502/503/504, hub 0.36.2).
Validated constants: 3 retries, (30, 60, 120) s backoff + 0-25% jitter,
one log line per retry as the fix-engaged signal — worked example
`_upload_with_transport_retry()` in `scripts/issue1315_dispatch.py` @
`c3c600541f` (#1315 r8: two p11 kills ~35 min apart on a retriable 429).
This is the IN-PROCESS complement of the #931 wedge ladder above, never a
substitute: the retry fires when the upload RETURNS failed; the ladder
fires when it HANGS (~0 TX, never returns — no retry loop can reach it).
```

## 11. Decision Rationale

- **Retry count = 3 / backoff = (30, 60, 120) s / jitter = +0-25% / same fail-loud RuntimeError on exhaustion.** Why: production-validated on the motivating incident; total worst-case delay ≤ ~262 s is small next to the ~35-min inter-kill gap it absorbs. `Source: #1315 @ c3c600541f` (`_UPLOAD_TRANSPORT_RETRIES` / `_UPLOAD_BACKOFF_BASE_S`, `scripts/issue1315_dispatch.py:1688-1689`). Cross-check vs huggingface_hub's own convention (`http_backoff`: `max_retries=5`, `base_wait_time=1` s, `max_wait_time=8` s): the hub's schedule targets sub-second transport blips on individual HTTP calls; the 429 here is an HOURLY commit-quota throttle (256/hr), so the longer 30-120 s schedule is the right scale — the hub convention does not transfer. Alternatives: unbounded retry (rejected — hides persistent failures, violates fail-fast), longer schedules (rejected — no evidence needed beyond what 3×~2-min absorbed in production).
- **Doc rule at the SEAM, not a code change inside `hub._upload`.** Why: the Goal + candidate scope this task to rule text; `_upload`'s return-`""` contract is pinned by many callers, and the seam (not the library) knows its own idempotency and failure semantics. A library-level retry is a separate, bigger-blast-radius task if ever wanted. `Source: #1359 body (Goal + diff sketch); #1315 r8 fix shape (seam wrapper, not hub.py patch).`
- **Placement as clause (c) of the #488 entry.** Why: the two rules share the trigger phrase ("upload returned no path") and are logical complements; one paragraph keeps the grep surface unified. `Source: #1359 body diff sketch; clarifier grep (only-hit file).`
