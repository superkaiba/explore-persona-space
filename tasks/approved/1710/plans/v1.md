## 3. Approach chosen (narrow with three added waivers)

**Chosen: hybrid narrow.** Reasons:

1. The general path (tokenize the whole command, evaluate the verb
   only in "command position") is a rewrite of the entire guard's
   parsing model. The guard is already ~2,000 lines and 100+ pin
   tests; a tokenizer rewrite would be a multi-week effort that
   touches every existing waiver's contract. This task's scope is
   four incident shapes.

2. The narrow path continues the pattern the body flags as the root
   cause ("each was added reactively for one shape") — but the body's
   Confidence line explicitly acknowledges the trade-off ("MEDIUM on
   the remedy — this is a security guard, and a general 'it's inside
   a quoted argument' waiver is exactly the kind of relaxation that
   can open a real hole"). A narrow extension of the two existing
   masks keeps the same refusal-predicate design that has proved out
   under 6+ months of pin tests; a general tokenizer would need its
   own fresh red-team round.

3. The security bar is: FAIL CLOSED on ambiguity. Every new waiver
   below explicitly LISTS what it rejects and pins each rejection
   with a negative test. The refusal predicates are copied verbatim
   from the ssh mask (which has been stable) with the one
   double-quote-specific addition: expansion tokens (`$`, backtick,
   backslash) MUST be absent from the payload — a double-quoted
   string that contains any of these is executable data, not inert
   prose.

**Three added mask arms:**

- **Arm 1 (extend `mask_ssh_payload_separators`):** admit a
  DOUBLE-quoted payload after the same head regex. Refusal predicate
  is R1-R8 PLUS a new R9: `index(payload, "$") == 0 && index(payload,
  "`") == 0 && index(payload, "\\") == 0`. Only masks the payload's
  intra-payload separators (`;`, `&&`, `||`, `\n`) with the same
  `__EPM_SSH_SEP__` sentinel; the surrounding double-quote pair is
  kept verbatim. Rationale: matches the #1413 mask's exact-parse
  argument, since a double-quoted span with NO expansion metachars
  IS a byte-exact literal (bash never expands anything inside it).

- **Arm 2 (extend `mask_taskpy_arg_payloads`):** admit a
  DOUBLE-quoted payload under the same P1-P6 predicate PLUS the same
  new R9 (no `$`, no backtick, no backslash) so a `"$(cmd)"` or
  `"$VAR"` payload REFUSES.

- **Arm 3 (new pre-pass `mask_python_c_string_literals`):** after
  the ssh + taskpy masks, add a third awk pre-pass keyed on
  clause-initial `python[0-9.]*` or `uv run python[0-9.]*` followed
  by `-c` followed by a balanced quoted string. Refusal predicate:
  the string MUST NOT contain any of the tokens that a real
  destructive `python -c` payload would need. Concretely:
  `subprocess`, `os.system`, `os.popen`, `Popen`, `run(`, `check_output`,
  `check_call`, `call(`, `commands.getoutput`, `pty.spawn`, backtick,
  `$(`, `${`, `import ` followed by `subprocess`, `sh.` (as in
  `sh.bash(...)`). AND, because a Python string CAN carry a `\x`
  escape that ONLY resolves at runtime, the string is refused if it
  contains a backslash. This is stricter than the ssh mask's R9 but
  necessary — a `python -c` string is executable code, so the burden
  of proof for "inert" is higher.

**Ordering.** The three arms are all pre-passes and must run in the
existing sequence: `strip_heredoc_bodies` first (line 881), then
`mask_ssh_payload_separators` (line 1046), then
`mask_taskpy_arg_payloads` (line 1222), then the NEW
`mask_python_c_string_literals`. The new pass runs LAST because a
task.py-inside-python-c compound (unlikely but not impossible) would
need the task.py mask to fire first on the task.py head; if the
python-c mask fired first it would refuse (task.py head is not
python -c head) and pass through unchanged. Order-independence
verified in the assumption block below.

Change 3 — new pre-pass `mask_python_c_string_literals`, added
between the taskpy mask call (line 1222) and the pre-filter regex
at line ~1224.

Function outline (~80 lines of awk):

```
mask_python_c_string_literals() {
  printf '%s' "$1" | awk '
    BEGIN { nrec = 0 }
    { rec[nrec++] = $0 }
    END {
      # Re-join records with newlines (parity with sibling masks).
      s = ""; for (r = 0; r < nrec; r++) s = s (r ? "\n" : "") rec[r]
      n = length(s)
      i = 1; atstart = 1; out = ""; saw_quote = 0
      while (i <= n) {
        headlen = 0
        if (atstart) {
          # C1: head is python[3][.<M>]? optionally prefixed by
          # `uv run`, then a mandatory `-c` flag, then whitespace.
          if (match(substr(s, i), /^(uv[ \t]+run[ \t]+)?python[0-9.]*[ \t]+-c[ \t]+/)) headlen = RLENGTH
        }
        if (headlen > 0) {
          j = i + headlen
          # Accept a single OR double-quoted string literal at j.
          q = substr(s, j, 1)
          if (q != "\047" && q != "\042") {
            # C1 refused: no quoted arg — fall through to char path.
            out = out substr(s, i, headlen - 1); i += headlen - 1; atstart = 0
            continue
          }
          cq = index(substr(s, j + 1), q)
          if (cq == 0) {
            # C2: no closing quote — refuse.
            out = out substr(s, i, headlen - 1); i += headlen - 1; atstart = 0
            continue
          }
          payload = substr(s, j + 1, cq - 1)
          after   = j + 1 + cq
          # C3 tail-shape: whitespace-only tail ending in
          # ;/&&/||/NL/EOS (parity with ssh mask R1).
          t = after
          while (t <= n && substr(s, t, 1) ~ /[ \t]/) t++
          tail_ok = (t > n)
          if (!tail_ok) {
            c1 = substr(s, t, 1); c2 = substr(s, t, 2)
            tail_ok = (c1 == ";" || c1 == "\n" || c2 == "&&" || c2 == "||")
          }
          # C4-C10 refusal ladder: payload must be inert prose.
          # No expansion / subprocess / shell-out tokens anywhere.
          bad = 0
          if (!tail_ok) bad = 1
          if (saw_quote != 0) bad = 1
          if (index(payload, "\\") > 0) bad = 1
          if (index(payload, "\140") > 0) bad = 1     # backtick
          if (index(payload, "$") > 0) bad = 1        # any $
          if (index(payload, "subprocess") > 0) bad = 1
          if (index(payload, "os.system") > 0) bad = 1
          if (index(payload, "os.popen") > 0) bad = 1
          if (index(payload, "Popen") > 0) bad = 1
          if (index(payload, "commands.getoutput") > 0) bad = 1
          if (index(payload, "pty.spawn") > 0) bad = 1
          if (index(payload, "check_output") > 0) bad = 1
          if (index(payload, "check_call") > 0) bad = 1
          # `run(` and `call(` are ambiguous — a legitimate
          # incident-4 helper does string-processing only. If
          # the payload calls anything with a `(`, refuse.
          # (Same conservative direction as the strip pre-pass.)
          if (payload ~ /[A-Za-z_][A-Za-z_0-9.]*\(/) bad = 1
          if (bad) {
            out = out substr(s, i, headlen - 1); i += headlen - 1; atstart = 0
            continue
          }
          # ACCEPT: mask the payload BODY with the neutral sentinel.
          out = out substr(s, i, j - i) q "__EPM_PYTHON_C_LITERAL__" q
          i = after; atstart = 0
          # Consumed pair does NOT set saw_quote (mask parity).
          continue
        }
        c = substr(s, i, 1)
        out = out c
        if (c == "\047" || c == "\042") saw_quote = 1
        if (c ~ /[;|&\n]/) atstart = 1
        else if (c !~ /[ \t]/) atstart = 0
        i++
      }
      printf "%s", out
    }'
}
# Cheap literal gate: only invoke when the command mentions `-c` — the
# awk pass spawns only for python-c-shaped commands (parity with taskpy
# mask's cheap `*task.py*` gate at line 1222).
case "$cmd" in *" -c "*) cmd=$(mask_python_c_string_literals "$cmd") ;; esac
```

The **conservative-any-parens refuse** is stronger than strictly
necessary but matches the security bar: a `python -c` payload
containing `foo(x)` cannot be proved inert from awk-level parsing, so
refuse. This does NOT block occurrence 4 (a `/daily` fingerprint
helper whose STRING LITERAL merely quotes a destructive phrase as
prose) — the helper's Python code does not call anything, it just
constructs a hash of a string.

Insertion of the new mask call: after line 1222's taskpy mask call,
before the pre-filter regex at ~1224.

## 6. Failure modes

| # | Failure mode | Handling |
|---|---|---|
| 1 | Attacker crafts a double-quoted ssh payload that IS a legitimate literal (no `$`, no backtick, no `\`) but happens to name a repo-root path. | Handled by copying R4 — repo-path check applies inside the double-quoted branch too. Same code path as single-quoted. |
| 2 | Attacker uses `python -c` payload with only string operations that DO happen to construct a runtime `os.system` call via `getattr`. | Refused by the "any function call" arm (`[A-Za-z_][A-Za-z_0-9.]*\(`) — the payload cannot invoke anything without a `(`. Accepted risk: a genuinely-inert helper that USES a function call is refused (fail-closed). |
| 3 | Nested quotes inside a double-quoted mask arm: `"echo \"foo\""` — the escaped double-quote makes the closing quote ambiguous to awk's naive `index()`. | R9's backslash-refusal covers this: any `\` in a double-quoted payload refuses. So a payload with escaped quotes REFUSES → byte-identical to today. |
| 4 | `bash -c "..."` or `sh -c "..."` misidentified as a mask head. | The three mask heads are `ssh<ws>` / `gcloud compute ssh<ws>` / `python[0-9.]*<ws>-c<ws>` / `<pathprefix>task.py<ws>`. `bash -c` and `sh -c` are NEVER mask heads. Anti-vacuity pin: `test_taskpy_payload_matches_prefilter` sibling for python -c (see § 4.2.3). |
| 5 | A python -c string containing a heredoc-style dollar-brace `${…}` for an environment-var expansion. | R9 refuses on any `$`. |
| 6 | Double-quoted ssh payload contains an ANSI-C escape `\x1b`. | R9 refuses on any `\`. |
| 7 | The new mask fires on a compound where LATER clauses contain a real mutation. | Pin NCX2/NCX3 — the mask replaces ONLY the payload body, and the driver loop still walks every OTHER clause with its own classifier. Same guarantee the ssh + taskpy masks already provide. |
| 8 | Order-dependency: taskpy mask runs BEFORE python-c mask; a `python -c '... task.py ...'` invocation. | The python-c head regex requires the FIRST token to be `python` (or `uv run python`). A `python -c` invocation is never a task.py head (which requires a `*task.py`-suffixed path token as the head). No collision. Verified against the head regexes at line 1151 (task.py) and the new C1 regex. |
| 9 | A `python -c` payload containing prose that mentions a repo-root path spelling. | The python-c refusal ladder does NOT include the R4 repo-path check. Rationale: a python-c literal is INERT PROSE — bash cannot execute a path spelling inside a Python string. This is the one place the python-c mask is LESS restrictive than the ssh/taskpy masks (which handle `cd <path> && ...` shapes). Documented in the header comment. |
| 10 | Regression on an existing test I did not anticipate. | Full pytest suite runs before commit; PostToolUse ruff runs. Any regression is caught before the commit lands. |

## 9. §11 Decision Rationale (light for infra)

- **Choice of narrow-hybrid over general tokenizer:** Source:
  incident #796 round 1 (documented at guard lines 181-187) — a
  quote-strip pre-pass in bash-regex was tried and reverted for
  safety reasons; the reactive-per-shape mask design is the
  project's proven pattern. No literature grounding needed — this
  is engineered fresh against the guard's existing design.

- **R9 predicate for double-quoted payloads (no `$`, no backtick,
  no backslash):** Source: bash quoting semantics — a double-quoted
  string with none of these tokens is byte-identical to a
  single-quoted string of the same content. `man bash` §QUOTING.
  Engineered fresh but grounded in the shell spec.

- **C4-C10 refusal ladder for python-c payloads:** Source:
  engineered fresh — no source, hence the pin tests. The refusal
  token list (`subprocess`, `os.system`, `Popen`, `run(`, etc.) is
  the CPython stdlib's canonical shell-out surface, cross-checked
  against `bandit`'s security lint rules (`B602`, `B605`, `B607`)
  — no direct-copy but conceptually parallel.

- **Head regex for python-c (`python[0-9.]*` optionally prefixed by
  `uv run`):** Source: parity with `mask_taskpy_arg_payloads`' head
  regex at line 1151, which uses `python[0-9.]*[ \t]+` in the same
  role.

- **Sentinel names `__EPM_ARG_PAYLOAD__` /
  `__EPM_PYTHON_C_LITERAL__` / `__EPM_SSH_SEP__`:** Source: parity
  with existing sentinels in `mask_taskpy_arg_payloads` (line
  1191) and `mask_ssh_payload_separators` (line 1015). The
  driver-loop waiver reads only the sentinel form; new sentinels
  need no driver-loop change if the pre-pass masks BODIES (not
  full clauses).
