# Plan — issue #818: watcher reaps zombie/idle wrappers stranded on orphaned (socket-less) tmux servers

## 0.0 TL;DR (plain English)

- **What I'll do:** Teach the 10-minute session-cleanup watcher one new fact. When a tmux window's underlying tmux process has had its socket file deleted, nobody can ever reconnect to that window again, so a leftover chat session sitting in it should not count as "someone might be looking at this." Right now the watcher can't check a socketless tmux, gets back a blank answer, and reads "I couldn't check" as "leave it alone" — which is how 31 abandoned sessions holding about 4.8 GB of memory sat there for up to a week.
- **What I expect:** After the change, an abandoned session in one of these dead tmux windows gets cleaned up on the same schedule as everything else (2 hours, confirmed on two checks in a row). A session in a live tmux, a window someone is actually attached to, or a plain terminal keeps being left alone.
- **What would change my mind:** If those 31 sessions were never in the daemon's session list to begin with, no watcher pass ever saw them, so this fix wouldn't have caught them and the real problem is that dead-tmux sessions quietly disappear from the daemon. That is a different fix. I checked this before settling on the design, and I cover the boundary.

## 0. Plan Summary (technical)

## 1. Goal

**Goal / requirement:** Make the autonomous-session watcher reap Happy wrappers stranded on **orphaned tmux servers whose socket file has been deleted** (nobody can ever reattach → not a live user TTY), on the SAME conservative schedule (≥2 consecutive checks, existing grace/idle windows) the passes already use — without widening reaping for any ambiguous or genuinely-live TTY. This is the confirmed gap behind the 2026-07-01 incident (31 zombie wrappers, ~4.8 GB RSS, 1–7 days old, on a 99-day orphaned server pid 2842652 whose socket was deleted from `/tmp/tmux-1001/`).

**Hypothesis:** N/A — no behavioral construct. This is a guardrail-predicate code change.

**Acceptance criteria:**
1. A new pure predicate classifies a wrapper **parented by** a socket-less orphaned tmux server as NOT a live-user TTY; fail-toward-keep on every ambiguous signal (tmux binary missing, `/proc/<pid>/stat` unreadable, socket-dir unreadable, no `tmux: server` ancestor, stat race, ppid-walk cycle/root-hit).
2. The idle-unmapped pass (`_is_live_user_tty`) treats such a wrapper as not-live, so an idle-≥12h unmapped session on such a pane falls through to the transcript-idle reap on ≥2 consecutive misses.
3. All existing `tests/test_autonomous_session_watch.py` tests pass unchanged (no live-TTY / attached-pane / detached-pane / headless regression).
4. New unit tests cover the full decision table (all input combinations → keep/reap) with tmp-dir / monkeypatched fakes (no live tmux server required).
5. `.claude/rules/background-automation.md` (idle-unmapped pass contract) and the CLAUDE.md watcher one-paragraph summary stay consistent with the code.
6. `uv run ruff check`, `uv run python scripts/workflow_lint.py` (default run incl. `--check-asks`), and a live `--dry-run` full-watcher smoke all pass.

## 2. Prior work / method delta

### What the TTY-liveness machinery does today (verified by reading the code)

Confirmed by reading `scripts/autonomous_session_watch.py`:

- **The zombie-wrapper pass (`decide_zombie_wrapper`, lines 10621-10669) consults NO TTY guard at all.** It keys ONLY on `has_claude` (no `claude/versions/` or `claude-agent-sdk` descendant), issue-mapped status (`ZOMBIE_STATUS_EXCLUDE`), a 2h grace, and ≥2 consecutive misses. For an UNMAPPED session (`mapped=False`), the status branch is skipped, so a sustained-no-Claude unmapped wrapper is reaped **regardless of TTY**.
- **The TTY guard lives ONLY in the idle-unmapped pass** (`decide_idle_unmapped`, line 11664, via `has_tty = _is_live_user_tty(pid, detached_tmux_ttys)`, line 11616). `_is_live_user_tty`:
  - returns `False` if the wrapper has no controlling tty (`_wrapper_has_controlling_tty`, tty_nr off `/proc/<pid>/stat`, line 11195);
  - resolves the wrapper's controlling pts via `/proc/<pid>/fd/{0,1,2}` (`_wrapper_controlling_tty_path`, line 11217);
  - returns `False` (not-live) iff that pts is in `detached_tmux_ttys` (a tmux pane whose session has **zero attached clients**), else `True` (live → keep).
- `detached_tmux_ttys` comes from `_detached_tmux_panes_with_activity()` (line 11234): ONE `tmux list-panes -a -F '#{pane_tty}\t#{session_attached}\t#{session_activity}'` call. **Fail-soft (lines 11252-11257 docstring + 11258/11275): tmux absent OR the server can't be queried → returns `(set(), {})` → EMPTY detached set → EVERY tty-bearing wrapper is kept.**

### The gap (confirmed)

An **orphaned tmux server whose socket was deleted** cannot answer `tmux list-panes` (the client has no socket to connect to) → the whole call returns non-zero / empty → `detached_tmux_ttys` is empty → the pts of every pane on that dead server is NOT in the detached set → `_is_live_user_tty` returns `True` → the idle-unmapped pass classifies it as a live user TTY and keeps it forever. This is exactly the fail-toward-keep-too-hard case: the socket-less server is *more* dead than a detached pane (a detached pane can still be reattached; a socket-less one cannot, absent a manual `kill -USR1`), yet it reads as *more* live.

### Method delta

Add a **socket-independent, parentage-based** orphaned-tmux check (the current detached-pane path is socket-dependent by construction — it asks the running server via `tmux list-panes`, which a socket-less server cannot answer). The wrapper→owning-server mapping is **process parentage**, NOT the fd table: a tmux server's pane leaders are its direct child processes (`ppid == server_pid`, fact-checker-verified live for all 8 live panes), and the daemon-tracked wrapper (`node /usr/bin/happy claude`) IS that direct child. So given the wrapper's pid (which `_is_live_user_tty` already has), walk its `ppid` chain for a `comm == "tmux: server"` ancestor and mark the wrapper orphaned iff that server has no live socket under the tmux socket dir. This ADDS a not-live branch to `_is_live_user_tty` alongside the existing detached-pane branch, never removing the keep-leaning defaults.

**Why parentage, not the fd table (the v2 error):** the fact-checker verified live that tmux server pid 217724 holds pts fds `{0,1,3,6,32,34,36,46}` while its panes' `pane_tty`s are `{2,4,5,7,27,39,40,48,52}` — **completely disjoint**. Reading `/proc/<server>/fd` for `/dev/pts` targets (the v2 sketch) would therefore return the WRONG set and the orphaned set would be empty even for a genuinely orphaned server → the widening would ship INERT (reproducing the exact "does nothing" failure this task exists to fix). The parentage walk is verified: all 9 direct children of the live server carried the expected controlling ttys `{52,27,40,48,2,4,7,5,39}`, matching the `pane_tty` set.

### 3.2 New helper: parentage-based orphaned-tmux check

The predicate takes the WRAPPER's pid (already in hand at the call site) and walks its `ppid` chain for a `tmux: server` ancestor. `proc_root` is injectable so the test suite can drive it against a `/proc`-shaped tmp tree with NO live tmux server (see §4).

```python
# Constant near IDLE_UNMAPPED_STATE_PREFIX (~line 11129):

def _orphaned_tmux_reap_enabled() -> bool:
    """True unless EPM_ORPHANED_TMUX_REAP is explicitly falsy (0/false/no) —
    the kill-switch for the orphaned-tmux-server widening. Same parse as
    _unmapped_idle_reap_enabled."""
    raw = os.environ.get("EPM_ORPHANED_TMUX_REAP", "")
    return raw.strip().lower() not in {"0", "false", "no"}


def _tmux_socket_dir() -> Path:
    """The tmux socket directory: $TMUX_TMPDIR/tmux-<uid> when set, else
    /tmp/tmux-<uid> (the documented default — man7 tmux(1): sockets live in
    tmux-UID under $TMUX_TMPDIR or /tmp)."""
    base = os.environ.get("TMUX_TMPDIR", "").strip() or "/tmp"
    return Path(base) / f"tmux-{os.getuid()}"


def _live_tmux_socket_present() -> bool:
    """True iff AT LEAST ONE socket file exists in the tmux socket dir.
    Distinguishes 'a tmux server is reattachable' from 'a server exists but
    its socket was deleted'. Unreadable dir -> True (fail toward keep: we
    cannot prove any server is socket-less)."""
    d = _tmux_socket_dir()
    try:
        return any(p.is_socket() for p in d.iterdir())
    except OSError:
        return True  # cannot read the dir -> cannot prove orphaned -> keep


def _proc_comm(pid: int, proc_root: Path) -> str | None:
    """comm (process name) from <proc_root>/<pid>/comm, or None if
    unreadable (raced exit / perms)."""
    try:
        return (proc_root / str(pid) / "comm").read_text().strip()
    except OSError:
        return None


def _proc_ppid(pid: int, proc_root: Path) -> int | None:
    """ppid from <proc_root>/<pid>/stat, or None if unreadable. Same parse
    as _proc_children_map / _wrapper_has_controlling_tty: fields after the
    LAST ')' are state(0) ppid(1) ..."""
    try:
        stat = (proc_root / str(pid) / "stat").read_text()
        return int(stat.rsplit(")", 1)[1].split()[1])
    except (OSError, IndexError, ValueError):
        return None


def _wrapper_on_orphaned_tmux_server(
    pid: int, *, proc_root: Path = Path("/proc"), max_depth: int = 50
) -> bool:
    """True iff the wrapper is parented (directly or transitively) by a
    'tmux: server' process AND that server's socket is provably absent from
    the tmux socket dir (nobody can reattach — the 2026-07-01 orphaned
    class). Mapping is PROCESS PARENTAGE, not the server's fd table (a
    server's open pts fds are DISJOINT from its panes' pane_ttys — the pane
    leaders are its CHILD processes; fact-checker-verified live).

    Walk the ppid chain from `pid` (bounded by max_depth + a seen-set cycle
    guard). If a 'tmux: server' ancestor is found:
      * socket present in the dir -> reattachable -> NOT orphaned -> False;
      * socket absent (dir empty of sockets) -> orphaned -> True.
    If NO tmux: server ancestor is found (raw login pts, ssh, a non-tmux
    parent, or the chain hit pid 1 / an unreadable link) -> False (not our
    class -> the caller keeps it via its other branches).

    Fail-toward-keep on EVERY uncertain signal:
      * tmux binary absent -> False (nothing to reap; unchanged behavior);
      * ppid/comm unreadable at any hop -> stop the walk, return False
        (cannot prove a tmux: server ancestor -> keep);
      * socket dir unreadable -> _live_tmux_socket_present() True -> the
        server reads reattachable -> False (keep).
    The predicate can only ever return True for a CONFIRMED
    tmux-server-parented + socket-absent wrapper; every ambiguity -> False
    (keep)."""
    if shutil.which("tmux") is None:
        return False
    seen: set[int] = set()
    cur = pid
    for _ in range(max_depth):
        if cur in seen or cur <= 1:
            return False  # cycle / reached init without a tmux: server
        seen.add(cur)
        comm = _proc_comm(cur, proc_root)
        if comm == "tmux: server":
            # Found the owning server. Orphaned iff its socket is gone.
            return not _live_tmux_socket_present()
        ppid = _proc_ppid(cur, proc_root)
        if ppid is None:
            return False  # unreadable -> cannot prove orphaned -> keep
        cur = ppid
    return False  # depth exhausted without a tmux: server ancestor -> keep
```

Notes:
- **`comm == "tmux: server"` is the discriminator, verified live** (the live server pid 217724 reports exactly that comm; `tmux: client` processes are excluded — a client is a transient attach that is itself the parent of nothing session-owning). The daemon-tracked wrapper (`node /usr/bin/happy claude`) is a DIRECT child of the server, so the walk terminates in one hop for the incident shape, but the bounded walk tolerates an intervening shell.
- **Per-server socket disambiguation is intentionally NOT attempted.** `/proc/<pid>/fd` symlinks for a server's AF_UNIX socket resolve to `socket:[inode]` (no path) — CONFIRMED live — so there is no cheap per-server socket-path read. The dir-level presence check (`_live_tmux_socket_present`) is the authoritative signal: the incident state is "socket file deleted from `/tmp/tmux-1001/`", detectable as the dir having no socket. The single-live-server VM (one `tmux: server` + its `default` socket present) reads reattachable → False → zero behavior change (verified). A hypothetical multi-server VM where one server is orphaned but another's socket is present would (conservatively) read every server as reattachable — a fail-toward-keep miss, acceptable per the "provably-orphaned only" constraint. If multi-server disambiguation is ever needed, it is a strictly-additive follow-up (match the server's socket by name), not required for the incident class.

### 3.3 Socket-presence signal (the one subtlety)

The design uses a SINGLE authoritative signal — **the tmux socket dir has no socket file** — reached only after confirming (via parentage) that the wrapper is owned by a live `tmux: server` process. This is exactly the provably-orphaned case the task constrains to: a live server whose socket was deleted (the incident: server pid 2842652 alive, `/tmp/tmux-1001/` socket deleted). Any state where a socket still exists → the server reads reattachable → keep.

> **On the live VM right now** (verified): one `tmux: server` pid 217724 with socket `/tmp/tmux-1001/default` present → `_live_tmux_socket_present()` True → `_wrapper_on_orphaned_tmux_server(<any wrapper>)` returns False → zero behavior change for the healthy fleet. Its 9 direct children carry the expected pane ttys `{2,4,5,7,27,39,40,48,52}`, so the parentage walk correctly identifies each wrapper's server.

### 3.4 Fold into `_is_live_user_tty` (idle-unmapped pass)

```python
def _is_live_user_tty(
    pid: int,
    detached_tmux_ttys: set[str],
    *,
    check_orphaned: bool = False,   # NEW, default-False back-compat
) -> bool:
    """... (existing docstring) ... PLUS: a wrapper parented by an ORPHANED
    tmux server (socket deleted -> unreattachable) is NOT a live-user tty.
    Both the detached-pane and orphaned-server checks fail toward keep on
    any unresolved signal."""
    if not _wrapper_has_controlling_tty(pid):
        return False
    tty_path = _wrapper_controlling_tty_path(pid)
    if tty_path is not None and tty_path in detached_tmux_ttys:
        return False   # detached tmux pane (existing behavior)
    if check_orphaned and _wrapper_on_orphaned_tmux_server(pid):
        return False   # NEW: orphaned-tmux-server-parented wrapper -> not live
    # unresolvable tty_path, attached pane, raw login pts, or live server:
    return True
```

Note the **default-`False` keyword arg** preserves the existing 2-arg call in the pure-predicate test at test line 6142 (`_is_live_user_tty(99, {"/dev/pts/24"})`) — with `check_orphaned` omitted the new branch never runs, so that test stays green with zero edits. The pass callsite passes `check_orphaned=_orphaned_tmux_reap_enabled()`. (The orphaned check keys on the wrapper's PID via parentage, NOT on the `tty_path` string, so the not-live signal does not need the pts to be resolvable — but the existing `tty_path is None -> keep` behavior for the detached branch is preserved by guarding that branch on `tty_path is not None`.)

### 3.6 Decision table (all input combinations → keep / reap)

`_is_live_user_tty(pid, detached, check_orphaned=...)` — the guard the idle-unmapped pass consults (`True` = live → KEEP; `False` = not-live → falls through to the transcript-idle reap). The orphaned column reflects `_wrapper_on_orphaned_tmux_server(pid)` when `check_orphaned` is True:

| controlling tty? | tty_path resolvable? | in detached set? | parented by orphaned tmux server? | result | rationale |
|---|---|---|---|---|---|
| no | — | — | — | `False` (headless) | daemon RPC-spawned session; not a terminal |
| yes | yes | yes | — | `False` (not-live) | detached tmux pane (existing behavior) |
| yes | no (`None`) | — | no / n/a | `True` (KEEP) | unresolvable pts, not orphaned → keep |
| yes | yes | no | **yes** | `False` (not-live) | **NEW: orphaned-tmux-server-parented wrapper** |
| yes | no (`None`) | — | **yes** | `False` (not-live) | **NEW: orphaned via PARENTAGE (pts resolvability irrelevant to the orphaned check)** |
| yes | yes | no | no | `True` (KEEP) | attached pane / raw login pts / live server |

`_wrapper_on_orphaned_tmux_server(pid)` fail-toward-keep table (all non-final rows → `False` → KEEP):

| probe state | predicate result |
|---|---|
| tmux binary missing | `False` (keep) |
| no `tmux: server` ancestor in the ppid chain (raw login pts / ssh / non-tmux parent / hit pid 1) | `False` (keep) |
| ppid or comm unreadable at any hop (raced exit / perms) | `False` (keep — cannot prove a tmux server ancestor) |
| ppid-walk cycle or `max_depth` exhausted | `False` (keep) |
| tmux server ancestor found + socket dir unreadable | `False` (`_live_tmux_socket_present` True → reattachable → keep) |
| tmux server ancestor found + a socket file present in the dir | `False` (reattachable → keep) |
| **tmux server ancestor found + NO socket file in the dir** | **`True` (the only reap-widening case)** |

Combined with the ≥2-consecutive-miss + ≥12h-idle (or the #695 fallback window) guards already in `decide_idle_unmapped`, a one-tick orphaned flicker never reaps.

### 3.7 Interaction with the `kill -USR1` socket-recreation escape hatch

Per the tmux man page and [Rubén Varela's recovery guide](https://rubenvarela.com/guides/recovering-tmux-when-its-socket-was-deleted/): a deleted socket can be recreated by `kill -USR1 <tmux-server-pid>`. Design handling: if a human recreates the socket, the NEXT pass's `_live_tmux_socket_present()` sees the socket again and `_wrapper_on_orphaned_tmux_server()` returns False for that server's wrappers → the session reverts to KEEP. Because the reap needs ≥2 consecutive missed checks AND the wrapper still be idle ≥12h, a socket recreated between ticks resets the not-live signal well before any stop. This is why the SIGUSR1 possibility does not change the design: the multi-tick accumulation + idle-window guards absorb the transient. (Practically, an orphaned server 99 days old with the socket long deleted is not being SIGUSR1-revived; the guard is belt-and-suspenders.)

## 6. Kill criteria (what would mean this design is wrong)

**Primary kill-criterion — investigated before designing, resolved:** *Were the 31 incident wrappers in the daemon `/list`?* Both `zombie_wrapper_pass` (line 11004) and `idle_unmapped_pass` (line 12388) derive their candidate list from `_live_children()` (spawn_session, line 623) = the Happy daemon `/list` reply. If the 31 wrappers were NOT in `/list`, **no session pass ever saw them**, the TTY guard is moot, and the true gap is daemon-gating.

I verified against the live VM:
- Terminal-launched `happy claude` sessions **ARE** in the daemon `/list`, with `startedBy: "happy directly - likely by user from terminal"` (8 such sessions live right now, alongside 33 `startedBy: daemon`). So terminal-launched sessions on tmux panes ARE daemon-tracked and DO reach both reaper passes. This is consistent with the TTY-guard being the operative gap for the *daemon-tracked* subclass.
- The `claude_local_launcher.cjs` cmdline matches NEITHER `_CLAUDE_CMDLINE_MARKERS` marker (confirmed by reading `/proc/<pid>/cmdline` live), BUT a HEALTHY terminal session's launcher spawns a real `~/.local/share/claude/versions/<v>` grandchild that DOES match `claude/versions/` → `has_claude=True` for a healthy session (verified: all 8 live terminal wrappers read `has_claude=True`). The zombie state is precisely when the `claude/versions/` grandchild has exited but the launcher shim lingers → `has_claude=False`.

**The honest residual + the descope this forces:** The zombie-wrapper pass has NO TTY guard, so a *daemon-tracked* `has_claude=False` unmapped wrapper is reaped by it regardless of tmux state — the orphaned-socket TTY fix is NOT what unblocks that subclass. The TTY fix squarely unblocks the **idle-unmapped subclass**: a daemon-tracked session with a *live-but-idle* inner Claude, unmapped, on an orphaned-server pane, which the idle-unmapped pass keeps forever because the empty detached-map reads the pane as live. That IS the confirmed, reproducible gap in the code, and it is what this plan fixes.

The incident's `has_claude=False` + orphaned-socket + never-reaped combination most likely means those specific wrappers had **dropped out of the daemon `/list`** (the wrapper on a dead tmux server whose socket was deleted lost its daemon socket connection — the body itself notes the 54-day launcher was "unknown to the Happy daemon"). If so, that is a DIFFERENT gap (daemon-gating) that the TTY fix cannot address:

- **Explicit descope (stated in the plan, carried to the clean-result):** the **not-daemon-tracked** subclass (a wrapper absent from `/list` — the 54-day init-parented `--resume 83ac2dd5` launcher, and any of the 31 that had fallen out of `/list`) is **OUT OF SCOPE** for this fix. Every session pass is daemon-gated by construction (`_live_children()`), so covering that subclass requires a `/proc`-scan-based reaper independent of the daemon — a materially larger, higher-blast-radius change (it would reap processes the daemon does not know about, with no daemon `/stop-session` handshake). This plan does NOT attempt it; it is a candidate follow-up (a `/proc`-discovered orphaned-Happy-wrapper sweep), noted here so the boundary is explicit and the reviewer can weigh whether to file it.

**Kill-criterion verdict:** the design is CORRECT for the daemon-tracked idle-unmapped-on-orphaned-pane subclass (verifiable, reproducible from code + live probes) and HONESTLY DESCOPES the not-daemon-tracked subclass. If a reviewer establishes that ZERO of the incident wrappers were ever daemon-tracked, then this fix, while still a real correctness improvement to the idle-unmapped guard, would not have reaped *those specific* wrappers, and the follow-up daemon-independent sweep becomes the priority — the plan says so up front rather than overclaiming.

Secondary kill-criterion: if adding the orphaned-parentage branch caused ANY existing TTY/detached/headless test to flip, the fold is wrong (it must be purely additive) → revert to the default-`False` `check_orphaned` back-compat shape and re-derive.
