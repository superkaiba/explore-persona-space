## 2. Root cause + the three body corrections (all verified on main, 2026-08-20)

`CONTEXTS` is a process-global dict seeded with 11 code-literal contexts.
Production context-resolution seams mutate it BY DESIGN and idempotently:

- `issue1090_fu3_worker.ensure_context()` (line 180) → `register_fu3_contexts()`
  unconditionally, plus `icl_prefix_<behavior>` contexts;
- `issue1090_fu3_worker.bystander_panel()` (line 236) → `register_fu3_contexts()`
  + `ensure_context(f"icl_prefix_{behavior}")`;
- `issue1090_fu3_worker.panel_name_for()` (line 196) → filtered negative panels.

That registration is CORRECT production behavior. The defect is purely test
cross-contamination, so the fix belongs in test hygiene, not in the seams.

**Correction 1 — the trigger is not random ordering.** `pytest-randomly` is NOT
installed (`pytest 9.0.2`; `addopts = "-m 'not integration'"`), so the body's
`-p no:randomly` is a silent no-op and "under randomized ordering" cannot be the
mechanism. Collection order is deterministic, so the failure is a function of
WHICH files a selection collects and in what order. Direction: the bug is more
reproducible than filed, so acceptance is deterministic rather than a seed sweep.

**Correction 2 — a second victim.** `tests/test_artifacts_context.py::test_registry_seeds_validate`
pins registry SIZE (`assert len(CONTEXTS) == 11`, line 164) and fails under the
same pollution. It sorts alphabetically first, so it is green in a plain
full-suite run and reds only under an explicit selection — the gate-bounce shape.

**Correction 3 — the polluter class is wide, and it has TWO phases.** A
registry-drift attribution probe over the 26 test files importing any
fu3-registering module found:

- **IMPORT-time (1 file):** `tests/test_issue1481_analysis.py:41` evaluates
  `PANEL_IDS = [c.context_id for c in fu3w.bystander_panel(BEH)]` at MODULE
  scope, so collection alone registers `icl_prefix_impolite` +
  `wildchat_prefix_real545` before any test runs. Attributed by a per-file
  `--collect-only` sweep in a fresh process per file.
- **TEST-time (≥4 tests across ≥4 files):** `test_issue1090_fu6.py`
  (`neg_sp_ph4`, `neg_sp_police`), `test_issue1090_fu7.py`
  (`icl_prefix_sycophancy`), `test_issue1586_read_organism.py`
  (`neg_default_assistant`, `neg_reph_curious`, `neg_wc_short`),
  `test_issue1947_resume_matrix.py` (`icl_prefix_writing_style`).

The two-phase split is the design driver: **a per-test snapshot-at-setup /
restore-at-teardown fixture is INERT against import-time pollution**, because by
the first test's setup the pollution is already in the snapshot. The baseline
must therefore be captured in `pytest_sessionstart`, which runs BEFORE collection.

## 3. Method delta

Existing in-repo precedent this follows rather than invents:

- `tests/conftest.py` already hosts the shared autouse hermeticity-guard family
  (#1247 / #1265 / #1392 / #1556) and `_isolate_leaky_global_state`, which is
  exactly this shape — snapshot a leaky global, restore around every test.
- `tests/test_issue1090_fu3_dispatcher.py:309-318` is the per-callsite
  `try/finally` + `CONTEXTS.pop(...)` pattern. This plan generalizes it to the
  shared guard instead of replicating it at N call sites.

Delta vs both: the baseline is captured **pre-collection** (a new
`pytest_sessionstart` hook — `tests/conftest.py` currently defines no
`pytest_*` hooks, only fixtures, so there is no collision) and restoration
happens at test **setup**, which is what covers the import-time phase.

## 4. Concrete diff — `tests/conftest.py` (single file, ~35 lines incl. comment)

```python
# ---------------------------------------------------------------------------
# #2214 — artifacts CONTEXTS registry hermeticity (the #703 / #1247 leak family)
# ---------------------------------------------------------------------------
# `explore_persona_space.artifacts.context.CONTEXTS` is a process-global dict of
# 11 code-literal seed contexts. Production context-resolution seams mutate it BY
# DESIGN and idempotently — `issue1090_fu3_worker.ensure_context()` (fu3 conv
# prefix + `icl_prefix_<behavior>`), `bystander_panel()`, `panel_name_for()`
# (filtered negative panels) — so any test touching a seam leaks keys into every
# LATER test in the process. Two committed tests assert registry cleanliness and
# are the DETECTORS, not the bug:
#   * tests/test_artifacts_context.py::test_registry_seeds_validate
#       (`assert len(CONTEXTS) == 11` — the seed-size pin)
#   * tests/test_issue1090_fu3_dispatcher.py::test_conv_context_is_wildchat_family
#       (`CONV_CONTEXT_ID not in CONTEXTS` at entry — the issue-1144 r2 pin)
# Both red purely as a function of which files a selection collects and in what
# order, stochastically bouncing the Step 9c gate for unrelated diffs (#2063).
# The leak has TWO phases, which is why the baseline is taken in
# `pytest_sessionstart` (pre-collection) and restored at test SETUP:
#   (a) IMPORT time — tests/test_issue1481_analysis.py:41 evaluates
#       `PANEL_IDS = [c.context_id for c in fu3w.bystander_panel(BEH)]` at module
#       scope, so COLLECTION pollutes before any test runs. A snapshot taken at
#       the first test's setup would already contain it.
#   (b) TEST time — bodies that call a resolution seam (fu6 / fu7 /
#       1586_read_organism / 1947_resume_matrix).
# Restoring at setup (not teardown) covers both with one mechanism. Production
# seams stay untouched: registration there is intended behavior and idempotent,
# so any test needing a context re-registers by calling the seam.
_CONTEXT_REGISTRY_BASELINE: dict | None = None


def pytest_sessionstart(session):
    """Snapshot the pristine seed CONTEXTS registry BEFORE collection (#2214)."""
    global _CONTEXT_REGISTRY_BASELINE
    from explore_persona_space.artifacts.context import CONTEXTS

    _CONTEXT_REGISTRY_BASELINE = dict(CONTEXTS)


@pytest.fixture(autouse=True)
def _restore_context_registry():
    """Reset CONTEXTS to the pre-collection baseline at every test's setup."""
    from explore_persona_space.artifacts.context import CONTEXTS

    baseline = _CONTEXT_REGISTRY_BASELINE
    if baseline is not None and CONTEXTS != baseline:
        CONTEXTS.clear()
        CONTEXTS.update(baseline)
    yield
```

Cost per test: one dict `!=` over 11 frozen-dataclass values; a mutating restore
only on the rare polluted test. No I/O. Fail-loud posture preserved — the
fixture hides no production fault, only cross-test bleed.

**Not in scope of the diff:** the production seams; both detector assertions;
the `_wc_prefix()` helper (§11).

## 6. Kill criteria

- **A6 surfaces >0 newly-red tests that legitimately depend on leaked registry
  state** and the dependency is NOT fixable by an idempotent explicit
  re-registration in the affected test. That would mean cross-test registry
  bleed is load-bearing somewhere, and setup-restore is the wrong granularity —
  fall back to §7's alternative (restore only between FILES, via a module-scoped
  autouse fixture), which still fixes both victims but narrows the guarantee.
- **A5 still shows drift after the fix** — a mutation path exists that neither
  `pytest_sessionstart` nor setup-restore covers (e.g. a `conftest`-level
  registration in a subdirectory). Re-scope before shipping.
- The fix would require weakening either detector assertion → kill; the
  detectors are the point (task body: "Keep the victim's cleanliness assert (it
  is the detector, not the bug)").

## 7. Alternatives considered

1. **Per-callsite `try/finally`** (the body's sketch) — rejected: ≥5 call sites
   across ≥5 files today, the class regrows on the next dispatcher test, and it
   cannot fix the module-scope polluter (`PANEL_IDS` is evaluated at import; a
   `finally` inside a test body never runs for it).
2. **Make the seams non-mutating / return copies** — rejected: changes
   production behavior that `ModelOrganism` validation depends on ("registered
   into CONTEXTS so ModelOrganism validation sees them"), far larger blast
   radius than a test-hygiene fix, and the issue-1144 r2 contract deliberately
   keeps registration explicit rather than removing it.
3. **Module-scoped restore (between files only)** — the §6 fallback. Cheaper and
   less invasive, but leaves within-file ordering bugs live.
4. **Relax the two detectors** — rejected per the body and §6.
