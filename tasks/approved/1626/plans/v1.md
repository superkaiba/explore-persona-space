# Plan — #1626: root-guard fence-probe transient unexpected rc → retry-once-then-WARN

## 0. Plan Summary

**Change:** In `scripts/workflow_lint.py::check_git_recipes_root_guard`, an
unexpected fence-probe rc (not 0, not 2 — incl. the rc=-1 timeout/OSError
mapping) is retried once inside `_probe`; if the retry yields 0/2 that is the
verdict; if still unexpected, the result loop emits a WARN-class line
(`warn_sink`/stderr convention) instead of appending to the returned FAIL list.
**Byte-equivalent:** rc==2 blocked-recipe FAIL, all four self-test fail-loud
paths, the pre-filter/exemption/ordering logic. **Tests:** 3 new tests in
`tests/test_workflow_lint.py` (always-unexpected-rc → WARN not FAIL; flaky

unchanged. **Compute:** `Estimated GPU-hours (total): 0`. Target pod
preference: none — VM-local code change. **Risk (top):** a deterministic
per-fence hook crash (rc=1) now WARNs instead of FAILs — acceptable because

## 1. Goal + requirement & acceptance criteria

Task #1626 Goal (kind: infra — body `## Goal`, verbatim from the brief):
`workflow_lint.py`'s root-guard-hook probe treats a transient unexpected rc
(rc=-1 / signal-kill / timeout) as retry-once-then-WARN instead of a FAIL
line, so a killed/timed-out hook invocation inside a gate scratch tree cannot
flip a clean gate to `block`.

Acceptance criteria:
1. A fence probe returning an rc ∉ {0, 2} is retried exactly once; a retry rc
   of 0 or 2 is used as the verdict.
2. A still-unexpected rc after the retry produces ONE WARN line naming
   `file:lineno` + the rc (via `warn_sink` when provided, else stderr with
   `WARN: ` prefix) and NEVER enters the returned FAIL list.
3. rc==2 blocked-recipe behavior byte-equivalent (same message, same FAIL).
4. All self-test fail-loud paths unchanged: missing hook, fixture-build
   failure, self-test crash, fail-open (rc 0 on blocked probe), fail-closed
   (rc 2 on benign probe) — each still ONE loud FAIL.
5. `uv run python scripts/workflow_lint.py` (no flags) stays green on the
   current tree; the full root-guard test battery passes plus 3 new tests.

    *,
    repo_root: Path | None = None,
    hook_path: Path | None = None,
    max_workers: int = 8,
    warn_sink: list[str] | None = None,

                warn_sink.append(msg)

## 11. Decision Rationale

- **Retry count = 1.** What: one retry per fence on unexpected rc. Why: the
  observed failure class is a one-shot transient (#1610's re-run passed with
  no change); a second retry adds worst-case wall-time for no observed gain,
  and the residual WARN is non-blocking anyway. Source: incident #1610 + the
  task's proposed change (retry once). Alternatives: no retry (WARN
  immediately — loses the free recovery a transient offers); N retries with
  backoff (over-engineering for a non-blocking residual).
- **WARN, not FAIL, on persistent unexpected rc.** What: emit via the
  `warn_sink`/stderr idiom; never in the returned list. Why: the check's own
  contract text (docstring :9426-9428; error message :9564-9570) classifies
  non-0/2 as "not a pass, not a block" — an infra signal, and a FAIL here
  demonstrably flips clean gates (#1610). Source: the in-file WARN convention
  (`workflow_lint.py:10853-10865`, `:11194-11205`) + the docstring contract +
  #1610. Alternatives: keep FAIL (the incident's failure mode); silent skip
  (hides a real hook-environment problem — rejected).
- **Retry lives inside `_probe`, not the result loop.** What: per-fence loop
  of ≤2 attempts inside the existing closure. Why: keeps the ThreadPool map
  shape and sorted determinism; one-closure diff; self-test call sites
  (:9500-9501) bypass `_probe`, so self-test semantics provably untouched.
  The fixture tempdir is alive in both candidate locations, so liveness does
  not discriminate — simplicity does. Source: read of :9491-9571 (fixture
  `with`-block encloses both). Alternatives: serial re-probe after the pool
  (second pass over `results`, more plumbing, same behavior).
- **`warn_sink` param for testability.** What: keyword-only
  `warn_sink: list[str] | None = None`. Why: the established idiom for
  asserting WARN behavior in this file's tests without capsys. Source:
  `workflow_lint.py:10852-10854` (lessons-index), `:11194-11196`
  (agent-spec-size). Alternatives: capsys stderr capture (brittle across
  pytest capture modes).
