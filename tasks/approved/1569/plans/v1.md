## 1. Goal

> Have implementers that add an ENUMERATED check id (verify_plan.py c<N>, verify_task_body.py check <N>) probe origin/main for the next free id at IMPLEMENT time (not plan time), avoiding same-day check-id collisions between concurrent workflow-fix sessions.

(Task #1569 body `## Goal` H2, verbatim; re-read 2026-07-20 immediately before returning this plan — no `epm:goal-updated` markers exist; `kind: infra`, no `goal:` frontmatter.)

One paragraph: check ids for the two mechanical verifiers are today assigned at PLAN time from whatever main looked like when the planner read it. Workflow-fix sessions run concurrently (20+/day at peak), so two plans routinely claim the same next id; the second to merge hits a real content conflict in both the script and its test file and burns a renumber + conflict-resolve round. The fix is a late-binding convention: the id is a SLOT the plan names, and the implementer claims the actual number against freshly-fetched origin/main at the last responsible moment (immediately before the round's final commit), renumbering locally if the slot was taken.
