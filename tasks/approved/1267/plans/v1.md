```python
def decide_boot_death(
    *,
    sid_alive: bool,
    entry_age_s: float | None,        # now - spawned_at; None = missing/zero/non-numeric
    response_row_seen: bool | None,   # None = transcript unresolvable or > tail cap
    transcript_idle_s: float | None,  # from _transcript_idle_age_s
    window_s: float,
    quiet_s: float,
    stops_today: int,
    stops_per_day: int,
) -> str:  # "stop" | "cap-alert" | "keep"
    """Pure per-entry decision for the boot-death lane (#1267). Fires ONLY on:
    live sid + registration older than window_s + a fully-read transcript with
    ZERO response rows (assistant OR api-error — an api-error row is the #1209
    family's property) + transcript quiet >= quiet_s. Every unresolvable input
    fails toward keep (the 12h stale-registration pass stays the backstop).
    A future-dated spawned_at yields negative entry_age_s -> keep."""
    if not sid_alive:
        return "keep"                                   # crash-recovery / sweep-grace property
    if entry_age_s is None or entry_age_s < window_s:
        return "keep"
    if response_row_seen is None or response_row_seen:
        return "keep"
    if transcript_idle_s is None or transcript_idle_s < quiet_s:
        return "keep"
    if stops_today >= stops_per_day:
        return "cap-alert"
    return "stop"
```

`response_row_seen` is computed by the caller as `any(_classify_wedge_row(r) in ("assistant", "api-error") for r in rows)` — reusing the live-verified row classifier (line 2074) rather than a new type check. An `api-error`-only transcript is NOT a boot-death (the session took a failed turn — #1209's dead-silence trigger owns that shape once a self-report exists; on a no-self-report PARK task it is a known residual, see §8).

### 4.3 Design decisions on the brief's four questions (grounded)

1. **Detection predicate** — registration `spawned_at` age ≥ 30 min AND live sid AND whole-transcript zero response rows AND transcript mtime idle ≥ 10 min. Signals chosen because all four are ALREADY watcher-owned and were live-verified on the incident (§2). Transcript-missing/unresolvable → keep (house posture "a wrong signal is worse than a missing one", `_transcript_idle_age_s` docstring line 17253; the 12h pass stays the backstop — and the incident class is covered, since all 8 observed unregisters measured a RESOLVED transcript). Slow-boot false-positive margin: dead transcripts freeze ~7 s after spawn; the healthy generation had 49 assistant rows at 13 min — the 30-min window is >10× above the healthy first-assistant-row latency and 2× the `RESPAWN_SPAWN_GRACE_S` spawn-in-flight window.
2. **Action** — stop-only via existing `_stop_session`; NO unregister, NO direct spawn. Post-stop re-drive is fully owned by existing arms: ACTIVE → crash-recovery `decide()` (dead sid, 2 misses ≈ 20 min, episode-belt-bounded); `proposed` → `proposed_infra_sweep_pass`, whose `_infra_drain_signals` stale set (dead sid + 30-min grace, `EPM_INFRA_DRAIN_STALE_REG_GRACE_S`) stops the dead registration from blocking re-dispatch. **Loop bounding (the actual complaint):** yes, explicitly — the per-day cap converts the accelerated loop (~40–70 min/cycle) into ≤3 lane-driven cycles/day + the ~2/day 12h-backstop cycles, with a once-per-day loud cap push naming the pattern. Without the cap the lane would make churn ~18× WORSE; with it, worst-case daily dispatch count ≈ 5 vs today's ≈ 2, in exchange for detection latency 12h → 30 min and zero silence.
3. **Bounding** — day cap 3 (`EPM_BOOT_DEATH_STOPS_PER_DAY`, malformed/<1 → default, never a kill switch — the exact `_tick_wedge_respawns_per_day` contract, line 1629); counted at stop-initiation (stop failure still consumes; #1241). Kill switch `EPM_DISABLE_BOOT_DEATH_PASS=1` (pass-level, the capacity-retry convention). Window env malformed/non-positive → default (never instant-fire, the `_stale_registration_idle_s` contract line 18164). Fail-open/closed: every unreadable signal → keep (NO-FIRE), matching every sibling lane.
4. **Hook point** — a NEW small pass next to `stale_registration_pass`, NOT a sixth trigger inside `decide_prompt_wedge`: the wedge lanes live in `_process_stalled_session`, which is structurally blind here (missing self-report ⇒ skip, lines 10963–10966), and relaxing that skip would destabilize the most guard-dense function in the file. The new pass reuses the reaper `children` snapshot in place (zero extra daemon RPCs) and mirrors an existing, well-tested pass shape.

## 11. Decision Rationale (every load-bearing constant)

- **`BOOT_DEATH_WINDOW_S = 30 min` (`EPM_BOOT_DEATH_WINDOW_MIN`)** — What: min registration age before the lane may fire. Why: must dominate worst-case healthy first-assistant-row latency and the spawn-propagation race. Source: 2× `RESPAWN_SPAWN_GRACE_S = 15 min` (`autonomous_session_watch.py:632`, the #759 spawn-in-flight window) = 3 cron ticks; measured incident forensics — dead transcripts freeze ~7 s post-spawn, the healthy #1251 generation had 49 assistant rows at 13 min (this session's live probe, §2). Alternatives: 15 min (rejected — equals the spawn grace, zero margin over `/list` propagation + a slow cold context load); 60 min (rejected — halves the daily loop-bounding benefit for no added safety, cf. `EPM_AUTH_OUTAGE_FRESH_DEATH_MIN=60` which measures a full die-and-respawn CYCLE, not one boot).
- **`BOOT_DEATH_QUIET_S = 10 min` (module constant, no env)** — What: min transcript mtime idle. Why: rules out an in-flight first response on a just-delivered wake. Source: one watcher cron interval (`3-59/10` cadence, `.claude/rules/background-automation.md`); precedent for a 10-min quiet floor: the GCP janitor's `--terminal-phase-max-age-min=10`. Alternatives: env-tunable (rejected — secondary safety margin; the window env already governs sensitivity; fewer knobs).
- **`BOOT_DEATH_TAIL_BYTES = 256 KB`** — What: whole-file read ceiling. Why: guarantees "zero response rows" is a whole-file property while bounding IO; a boot-death transcript is ~11 KB (7 live-captured samples, all 11,368 B) → 23× headroom. Source: the #1104 production wedge window (256 KB, line 2274 + `background-automation.md`). Alternatives: 64 KB (`_transcript_tail_rows` default — rejected, only 6× headroom); unbounded read (rejected — a multi-MB healthy transcript should short-circuit to keep without the read).
- **`BOOT_DEATH_STOPS_PER_DAY = 3` (`EPM_BOOT_DEATH_STOPS_PER_DAY`)** — What: per-issue per-UTC-day stop cap. Why: bounds the accelerated loop (each stop enables a ~30–60-min re-dispatch cycle). Source: #1241 cap parity — `TICK_WEDGE_RESPAWNS_PER_DAY = 3` (line 1626) and `TICK_WEDGE_DEAD_RESPAWNS_PER_DAY = 3` (line 1590); same malformed/<1 → default never-a-kill-switch contract (line 1629). Alternatives: 2 (rejected — sibling parity beats micro-tuning; 3 allows one extra recovery from a transient cause like a momentary auth blip).
- **Count-at-stop-initiation** — Source: #1241 verbatim ("a stop-failed episode still consumes a budget unit — conservative in the safe direction", `background-automation.md`).
- **Day key = `time.strftime("%Y-%m-%d", time.gmtime(now))`** — Source: line 11066 (the #1209/#1241 day-cap derivation), reused via `_day_scoped_count` (line 6460).
- **Cap-alert is LOUD once/day (deviation from #1241's quiet-at-cap)** — Why: #1241's slow stalled lane remains a backstop that eventually acts; here the fallback is the very 12h silence this task exists to kill, so the cap moment is the highest-value alert of the day.
