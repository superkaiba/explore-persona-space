# Plan v1 — #1857 root-code cert guard: transient worktree-hash false blocks

## Plan Summary

Eliminate false-BLOCK / false-INCONCLUSIVE outcomes caused by a SINGLE-READ
worktree-hash race in two sibling seams: (1) the per-path certification check
in `.claude/hooks/guard_root_code_commit.sh` (07-28 incident: block refused
with `want=d5480c98c720 staged=38c9e9d45304 worktree=d5480c98c720` while
`git hash-object` 29s later read `38c9e9d45304` == cert == staged; retry
committed clean), and (2) `scripts/inline_lint_gate.py`'s `write_cert`
edited-during-gate (TOCTOU) check (07-30 incident: INCONCLUSIVE
`edited during gate — re-run: scripts/verify_task_body.py` on a file not
being edited).

Mechanism: a **bounded settle-and-re-hash retry** before the negative
verdict. The #1620 landing-content binding rule (pathspec/`-a` commits land
WORKTREE content, so worktree-shape paths bind to the worktree hash) is
UNCHANGED — the fix retries the read, it does not rebind it.

## Requirement + acceptance criteria

1. A transient worktree-hash flip (guard-time read != cert sha, file settles
   back to the cert sha within the retry window) no longer blocks a
   certified commit at `guard_root_code_commit.sh`.
2. `inline_lint_gate.py` no longer withholds a cert (TOCTOU/INCONCLUSIVE)
   when the payload path re-hashes to the `read_payload` snapshot on one
   bounded retry.
3. Genuine drift still blocks / still TOCTOUs — the retry only converts
   TRANSIENT mismatches (re-hash matches) into passes; a stable mismatch
   keeps today's verdicts byte-for-byte.
4. The #1620 binding rule is intact: `worktree_shape=1` paths still bind to
   worktree content; staged-blob binding still applies only to plain commits
   of the staged set. No change to cert file schema, `check_certified`, or
   `MAX_AGE` semantics.
5. Deterministic tests for BOTH outcomes (retry-recovers, retry-still-fails)
   on BOTH surfaces.

## Method delta

Prior rounds (#1620 pathspec scoping + cert-diag, #1676 cd diagnostics)
tightened binding and diagnostics; neither addressed read races on the
always-concurrent shared root. Delta: ONE retry pass that fires ONLY on a
would-block / would-toctou path — zero hot-path cost (the happy path never
sleeps). Delay via `EPM_CERT_REHASH_DELAY_S` (default `2`; follows the
existing `EPM_INLINE_CERT_MAX_AGE_S` knob convention; tests shim it / the
sleep to be deterministic).

**Rejected alternative** (the task body's first option): rebinding the cert
check to the staged blob sha. Conflicts with the #1620 landing-content rule
— a pathspec/`-a` commit re-stages worktree content at commit time, so a
staged-blob binding would certify content that is NOT what lands. Rejected;
the retry design is strictly additive.

## Concrete changes (file paths + diffs)

1. `.claude/hooks/guard_root_code_commit.sh` (~L1136-1172):
   - Factor the per-path landing-sha computation (the `worktree_shape` rules
     + `sha=` derivation currently inline in the loop) into one function
     `landing_sha <path>` so the first pass and the retry pass cannot
     diverge. Deletion-exempt paths keep their `continue` semantics (the
     function echoes nothing / returns a sentinel and the caller skips).
   - After the loop, when `uncertified` is non-empty: ONE
     `sleep "${EPM_CERT_REHASH_DELAY_S:-2}"` (single sleep total, not
     per path), then re-derive each uncertified path's landing sha via
     `landing_sha` and re-run `check_certified`; paths that now pass are
     dropped from `uncertified`. Emit one grep-able diag line per recovered
     path: `cert-retry: <path> recovered after re-hash (transient worktree
     flip)` on stderr (observability parity with `cert-diag:`).
   - `uncertified` empty after the retry -> `exit 0` (allow). Non-empty ->
     the existing block path unchanged (cert_diag then reflects settled
     state).
2. `scripts/inline_lint_gate.py` `write_cert()`:
   - Collect first-pass mismatches; if any, ONE
     `time.sleep(float(os.environ.get("EPM_CERT_REHASH_DELAY_S", "2")))`,
     re-hash each; a re-hash matching `snapshots[p]` certifies (append the
     cert line as normal), a stable mismatch stays `toctou` (message
     unchanged).
3. Tests:
   - `tests/test_guard_root_code_commit.py`: (a) transient-flip recovery —
     certify content A via the cert file, rewrite the file to content B,
     run the guard with a PATH-shimmed `sleep` that restores content A
     (deterministic, no wall-clock dependence) -> exit 0 + `cert-retry:`
     line; (b) stable drift — same setup, shim does NOT restore -> exit 2
     block (today's behavior).
   - `tests/test_inline_lint_gate.py`: (a) transient flip — monkeypatch
     `time.sleep` (or set `EPM_CERT_REHASH_DELAY_S=0` and flip content via
     a hash-sequence hook consistent with the file's existing test style)
     so the re-hash reads the snapshot content -> path certified, no
     toctou; (b) stable mismatch -> toctou + no cert line (today's
     behavior).
   - All 92 + 25 existing pin tests pass unchanged.
