## 1. Goal + acceptance criteria

Body `## Goal` (Task #1338, verbatim; `kind: infra` — no `goal:` frontmatter, body H2 is canonical, re-read at return time):

> crash-persist: always harvest per-run *.log files from data dirs (tail-capped) before applying the EPS_PERSIST_DIR_CAP_BYTES oversized-dir skip, and point the worker-log sweep at the driver out_root logs dir rather than the repo clone's logs/

**Acceptance case (the #1090 fu5 incident shape, att-20260715-081917):** given a swept data dir whose total size exceeds `EPS_PERSIST_DIR_CAP_BYTES` but which contains tiny per-run logs (`data/issue_1090/fu5/logs/<run_id>.attempt<K>.log`):

1. The persist uploads those logs (tail-capped, one commit) to `{dest}/data_logs/data_issue_1090/fu5/logs/…` and THEN prints the existing `SKIP data_issue_1090: … > cap …` line and skips the dir remainder as today.
2. Repo-clone committed `logs/daily/*.md` + `logs/weekly/*.md` notes are NOT staged into `worker_logs/` (one aggregate SKIP line records the exclusion).
3. `$WORKLOAD_ROOT/logs/**` fan-out worker logs (e.g. `logs/issue_137/corpus_gpu0_all.log`, the #885 case) ARE still swept unchanged — same repo paths, same TAILED/newest-first/count-bound behavior.
4. Persist stays 300s-bounded, fail-soft, small-first; no per-file `upload_file` calls anywhere.

**Deliberate scope decision (the "IN ADDITION TO or INSTEAD OF" fork):** the worker-log sweep KEEPS the repo-clone `$WORKLOAD_ROOT/logs/` root (the #885 rationale — fan-out dispatchers writing per-worker logs there — is live and test-pinned), minus the `.md` notes noise. The driver out_root logs dirs (`data*/issue*<N>*/**/logs`) are covered by the NEW data-log harvest (change 1), not by widening `_up_logs`'s root — this avoids double-staging and keeps the #885 test surface untouched.

## 2. Method delta (vs current #885/#854 behavior)

| Aspect | Today | After #1338 |
|---|---|---|
| Per-run logs inside a swept data dir | Ride the dir upload ONLY; an oversized dir (`size > CAP`) is skipped wholesale, logs die with it (#1090 fu5: `SKIP data_issue_1090: 28007358769 bytes > cap 2147483648`) | Harvested unconditionally BEFORE the cap check into `{dest}/data_logs/…` (tail-capped, count-bounded, one commit); the dir-level cap skip then applies to the remainder exactly as today |
| Worker-log sweep root | `$WORKLOAD_ROOT/logs/**`, every regular file — including 48 committed `logs/daily|weekly/*.md` session notes (40 uploaded on the incident crash) | Same root, same behavior, but `*.md` files skipped with one aggregate SKIP line |
| Upload ordering | first bundle → worker_logs → partial dirs → final bundle | first bundle → worker_logs → **data_logs** → partial dirs → final bundle (small-first preserved: tracebacks land before any big dir upload can eat the 300s budget) |
| Repo paths for existing artifacts | — | Byte-identical (dir uploads unchanged; a under-cap dir still carries its logs at the old paths — the few-KB duplication into `data_logs/` is deliberate: it guarantees the tracebacks land even if the later big-dir upload times out) |

PARTIAL_DIRS = (

**(b) New `_up_data_logs()`** — modeled on `_up_logs()` (NOT a refactor of it; see §3.4 rationale), defined after the `_up_logs()` call, invoked immediately, i.e. between the `_up_logs()` call (anchor: the standalone line `_up_logs()`) and the `# 2. partial artifacts` comment block. Pseudocode of the new heredoc lines:

```python
# 1c. data-dir per-run logs (#1338) — driver out_root convention
#     data/issue_<N>/<run>/logs/<run_id>.attempt<K>.log (#1090 fu5): harvest
#     BEFORE the # 2. per-dir byte cap can skip the ~KB tracebacks wholesale
#     with the ~GB dir around them. Newest-first, per-file TAIL cap, count
#     bound, ONE upload_folder commit (never per-file — #664). Existing dir
#     upload paths untouched: an under-cap dir still uploads its logs at the
#     byte-identical dir paths; the data_logs copy is the small-first
#     guarantee that survives a budget-killed big-dir upload.
def _up_data_logs():
    if LOG_MAX_FILES < 1:
        _say(f"[crash-persist] SKIP data_logs: EPS_PERSIST_LOG_MAX_FILES={LOG_MAX_FILES} < 1")
        return
    entries = []
    for local, name in PARTIAL_DIRS:
        if not local.is_dir():
            continue
        for dirpath, dirnames, filenames in os.walk(local):
            dirnames[:] = [d for d in dirnames
                           if d not in PRUNE and not (d.startswith("g") and d.endswith("_dl"))]
            rel_parts = Path(dirpath).relative_to(local).parts
            in_logs = any(part == "logs" or part.endswith("_logs") for part in rel_parts)
            for f in filenames:
                if not f.endswith(".log"):
                    continue
                if not (in_logs or ".attempt" in f):
                    continue
                p = Path(dirpath) / f
                try:
                    st = p.stat()
                except OSError:
                    continue
                entries.append((st.st_mtime, st.st_size, p, local, name))
    if not entries:
        _say("[crash-persist] SKIP data_logs: no per-run *.log files under partial dirs")
        return
    entries.sort(key=lambda t: t[0], reverse=True)   # newest first: crashing run wrote last
    dropped = len(entries) - LOG_MAX_FILES
    if dropped > 0:
        _say(f"[crash-persist] SKIP {dropped} older data log(s) beyond"
             f" EPS_PERSIST_LOG_MAX_FILES={LOG_MAX_FILES}")
    staged_root = Path(os.environ.get("EPS_PERSIST_DATA_LOG_STAGE_DIR", "/tmp/eps-data-logs"))
    shutil.rmtree(staged_root, ignore_errors=True)   # same-boot re-crash hygiene (#885 parity)
    n_staged = 0
    for _, _, p, local, name in entries[:LOG_MAX_FILES]:
        try:
            rel = Path(name) / p.relative_to(local)
            tmp = staged_root / rel
            tmp.parent.mkdir(parents=True, exist_ok=True)
            size = p.stat().st_size          # re-stat: may have grown since the walk
            with open(p, "rb") as fin, open(tmp, "wb") as fout:
                if size > LOG_FILE_CAP:
                    fin.seek(size - LOG_FILE_CAP)
                    _say(f"[crash-persist] TAILED data_logs/{rel}:"
                         f" kept last {LOG_FILE_CAP} of {size} bytes")
                fout.write(fin.read(LOG_FILE_CAP if size > LOG_FILE_CAP else size))
            n_staged += 1
        except Exception as exc:
            _say(f"[crash-persist] FAILED staging data log {p}: {exc}")
    if n_staged == 0:
        _say("[crash-persist] SKIP data_logs: nothing staged")
        return
    try:
        _say(f"[crash-persist] uploading dir data_logs ({n_staged} files, one commit)")
        api.upload_folder(folder_path=str(staged_root), path_in_repo=f"{dest}/data_logs",
                          repo_id=repo, repo_type="dataset")
        _say("[crash-persist] uploaded dir data_logs")
    except Exception as exc:
        _say(f"[crash-persist] FAILED dir data_logs: {exc}")
_up_data_logs()
```

(Predicate — REVISED per Phase-2 Methodology Must-Fix: a `.log` file qualifies when ANY path component under the swept dir is `logs` OR ends `_logs` (covers the in-tree `worker_logs/gpu<N>.log` layout, `issue502_dispatch.py:230-236`), OR the filename contains `.attempt`. The exact-`"logs"`-component-only form misses `worker_logs`; a bare `endswith("logs")` would false-match e.g. `catalogs` — hence `part == "logs" or part.endswith("_logs")`. The predicate implements the sketch's `**/logs/**/*.log` + `**/*.attempt*.log` globs walk-side (now widened to `**/*_logs/**/*.log`), so the harvest rides ONE PRUNE-bounded walk instead of two unbounded `Path.glob("**/…")` passes. No canonical-`workload.log` dedup guard: `EPS_LOG_PATH` never points under `data/issue_*` — see Assumption A7.)

### 3.4 Rejected alternatives (Decision Rationale)

- **Refactor `_up_logs` + `_up_data_logs` onto one shared stage-tail helper** — rejected: the #885 tests pin `_up_logs`'s exact output strings, and the heredoc is boot-critical (quoting slips surface only at VM boot); ~30 duplicated lines is the cheaper risk. Source: the Part A snapshot-pin discipline + `bash -n` warning in `compute-backend-failover.md`.
- **Harvest only when the dir is oversized** — rejected: unconditional harvest is the small-first guarantee (a `< CAP` dir's big upload can still eat the 300s budget before its logs land); cost of the redundant copy is ≤ a few KB–MB.
- **Add data-dir log paths to the dir upload's `ignore_patterns`** (dedup the redundancy) — rejected: it would REMOVE logs from the existing `data_issue_<N>/` tree paths, violating the byte-identical-existing-paths constraint.
- **Widen `_up_logs`'s roots to `data*/issue*/**/logs`** — rejected: double-staging with change 1 and a bigger blast radius on the pinned #885 surface; the harvest covers the out_root logs.
- **Prune `daily`/`weekly` dirnames** instead of `.md` skip — rejected: dirname collision risk with legit worker-log layouts; the committed noise is 100% `.md` (verified).

## 6. Kill criteria

- **300s-budget risk:** if the implementer's recount shows the harvest's worst case (extra PRUNE-bounded walk of the three dirs + ≤40 × ≤5 MiB tail copies + one ≤200 MiB `upload_folder` commit) plausibly threatens the budget on realistic trees, gate the harvest to run FIRST but cap its own wall via the existing fail-soft structure (it already is `|| true`-guarded through the subshell + `timeout 300`) — and if that is still deemed insufficient, fall back to harvest-only-when-oversized. The walk itself is the same metadata-only cost class as the existing `_dir_stats` walk over the same dirs (already accepted), so this is not expected to fire.
- **Predicate over-collection:** if the `*.log`-under-`logs/`-or-`.attempt` predicate matches large NON-run-log files in real trees (e.g. multi-GB `.log`-named dumps), the per-file tail cap already bounds each to 5 MiB and the count bound to 40 — worst case 200 MiB staged. If a real tree shows that is still too much, tighten the predicate to `.attempt*.log` + direct-children-of-a-`logs/`-dir only.
- **Approach wrong if:** the byte-identity constraint cannot be held (i.e., any existing repo path changes) — that would mean the design was mis-scoped; stop and re-plan rather than regenerate the snapshot to paper over it.
