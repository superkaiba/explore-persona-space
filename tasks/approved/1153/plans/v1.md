Module-level constants (near the other check constants):

```python
_AWK_ELISION_ANCHOR = "f=!f"
_AWK_ELISION_HOMES = (
    ".claude/skills/issue/SKILL.md",
    ".claude/rules/analyzer-section-reference.md",
)
_AWK_ELISION_PROGRAM_RE = re.compile(r"awk '([^']*)'")
```

Check function (placed after `check_vm_thread_cap_guidance`, house docstring style with the `repo_root` unit-test-hook note + "Bundled into the no-flags default run"):

```python
def check_awk_elision_parity(*, repo_root: Path | None = None) -> list[str]:
    """FAIL if the ban-gate awk elision program drifts between its two
    full-text homes (SKILL.md Step 9a-humanize / analyzer-section-reference.md
    Step 4.5), or if either copy is missing/ambiguous/unextractable (#1153,
    origin #998). Compares the single-quoted awk PROGRAM only — the
    surrounding invocation lines (paths, fencing, indentation) legitimately
    differ. ``repo_root`` is a unit-test override hook; production callers
    pass None. Bundled into the no-flags default run."""
    root = repo_root if repo_root is not None else _REPO_ROOT
    errors: list[str] = []
    programs: list[tuple[str, str]] = []
    for rel in _AWK_ELISION_HOMES:
        p = root / rel
        if not p.is_file():
            errors.append(f"{p}: missing — a ban-gate awk elision home must exist; "
                          f"if the program deliberately moved, update _AWK_ELISION_HOMES (#1153).")
            continue
        anchor_lines = [ln for ln in p.read_text(encoding="utf-8").split("\n")
                        if _AWK_ELISION_ANCHOR in ln]
        if len(anchor_lines) != 1:
            errors.append(f"{p}: expected exactly 1 line containing the awk elision anchor "
                          f"{_AWK_ELISION_ANCHOR!r}, found {len(anchor_lines)} — a moved, "
                          f"deleted, or duplicated copy must not silently pass (#1153).")
            continue
        progs = _AWK_ELISION_PROGRAM_RE.findall(anchor_lines[0])
        if len(progs) != 1:
            errors.append(f"{p}: could not extract exactly one single-quoted awk program "
                          f"from the anchor line (found {len(progs)}) — keep the program a "
                          f"single `awk '...'` span on one line, or update this lint (#1153).")
            continue
        programs.append((str(rel), progs[0]))
    if not errors and len(programs) == 2 and programs[0][1] != programs[1][1]:
        errors.append(f"{programs[0][0]} vs {programs[1][0]}: the ban-gate awk elision "
                      f"programs DIFFER — the two full-text homes must stay byte-identical; "
                      f"edit both homes identically (#1153).")
    return errors
```

Notes: `.split("\n")` not `.splitlines()` (avoids the unicode-line-separator splitting class from the JSONL-splitlines lesson; markdown text, `\n`-delimited). `[^']*` is exact because the program contains no `'`; if a future edit introduces one, extraction truncates → the two homes' extracts still compare (both truncate identically if edited identically) or the drift FAILs — and test case 7 pins the unextractable-reflow FAIL path.

## 11. Decision Rationale

- **Extraction anchor = `f=!f` line-scan, then `awk '([^']*)'` regex on that line.** *Why:* `f=!f` is the distinctive token (exactly 1 hit per home, verified by grep this session); scanning for the anchor first tolerates the homes' differing indentation/fencing, then the quoted-span regex isolates the program from the differing invocation paths. *Source:* in-repo precedent: `check_stale_label_disposition_clause` (unique-anchor + fail-on-0-or->1 discipline). *Alternatives:* pin the full program as a literal constant (rejected — creates a THIRD copy to maintain, and `check_vm_thread_cap_guidance` shows literal pins are for short prefixes); fence-marker block extraction per the candidate sketch (rejected — one home is fenced, the other indented, so no shared stable fence markers exist).
- **Comparison grain = the extracted program INSIDE the quotes (excluding `awk '` and the closing `'`), plain `str ==`.** *Why:* the quotes/prefix are shell syntax, not program content; the surrounding invocation legitimately differs (paths, continuation), so whole-line comparison would always FAIL and whole-command comparison is exactly what the clarifier ruled out. Both files decode as UTF-8, so str equality after identical decoding is byte equality of the underlying spans. *Source:* clarifier context + direct read of both homes this session. *Alternatives:* compare including quotes (equivalent, just noisier message spans); normalize whitespace before comparing (rejected — "byte-identical" is the stated pin; whitespace inside an awk program is semantic in principle).
- **Fail-loud on missing/0/>1/unextractable rather than skip.** *Why:* a moved or deleted copy silently passing defeats the check's purpose (the drift would go unwatched); the clarifier makes this a hard requirement. *Source:* in-repo precedent: `check_stale_label_disposition_clause` (missing-anchor and duplicate-anchor are both FAILs, lines 6084–6095).
- **Pairwise parity, not a lint-side canonical copy.** *Why:* keeps two copies in the repo, not three; a deliberate program change lands as one commit editing both homes with no workflow_lint.py edit. *Source:* candidate block on #998 ("assert byte equality, FAIL naming both paths").
