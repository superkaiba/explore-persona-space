### 3.1 Detection predicate (the ONE chosen signal: task tag)

```python
_TRIGGER_DENSE_TAG = "trigger-dense"

def _issue_trigger_dense(issue: int) -> bool:
    """True when the issue's workload is declared trigger-dense (task tag
    'trigger-dense' -- set at dispatch per trigger-dense-review.md's
    recognition heuristic: the run trains/evals on guard/security surfaces
    or gated-content corpora, knowable before any read), or when the task
    EXISTS but its state is unreadable (fail SAFE toward digest, loudly).
    A missing task (FileNotFoundError -- ad-hoc/synthetic polls) has no
    declaration surface at all -> False (raw excerpt, today's behavior)."""
    try:
        task = get_task(issue)  # added to the existing task_workflow import at :372
    except FileNotFoundError:
        log.info("trigger-dense check: task #%s not found (ad-hoc poll); raw excerpt", issue)
        return False
    except (RuntimeError, ValueError, OSError) as exc:
        log.warning(
            "trigger-dense tag read FAILED for issue %s (%s: %s); failing SAFE "
            "toward digest-on-unknown (raw tail stays readable at the log path)",
            issue, type(exc).__name__, exc,
        )
        return True
    tags = (task.get("frontmatter") or {}).get("tags") or []
    return _TRIGGER_DENSE_TAG in tags
```

- In-process `task_workflow` read (poll_pipeline is VM-side and already imports `find_task_path`/`list_events`/`post_event` at `:372`; `_marker_pid` already does a per-tick task read — precedented, ~ms). NEVER a `task.py` shellout.
- The exception taxonomy is copied from the audited catch set at `pod_lifecycle.py:2374-2380` (FileNotFoundError = not in registry/on disk; RuntimeError = branch-guard; ValueError = malformed frontmatter/registry; OSError = unreadable file). Anything else propagates (fail-fast). Note: `StaleTaskPathError` (task in multiple status dirs — registry corruption) subclasses `FileNotFoundError` (`task_workflow.py:851`), so it takes the missing-task→raw arm — same behavior as the pod_lifecycle precedent; state this in the docstring.
- Fresh read every tick, no caching: `task.py add-tag <N> trigger-dense` mid-run takes effect on the next tick — a live mitigation lever during an unfolding incident.
- Setter convention: the dispatching orchestrator (or a human) runs `uv run python scripts/task.py add-tag <N> trigger-dense` when the workload matches the rule's recognition heuristic. This plan documents the convention (module docstring + rule addendum); it adds no new gate.

### 3.3 Digest builder (pure, unit-testable)

```python
# Case-insensitive per-line substring counts -- the rule item-1 pattern set
# ('error|traceback|killed|OOM') plus the CUDA-IMA class (compat shim, §3.4).
_DIGEST_PATTERNS: tuple[tuple[str, str], ...] = (
    ("error", "error"), ("traceback", "traceback"), ("killed", "killed"),
    ("oom", "oom"), ("cuda_ima", "illegal memory access"),
)

def _digest_tail_excerpt(
    wide_tail: str, *, status: str, current_phase: str, pid_alive: bool,
    source: str, log_path: str, mtime_sec_ago: int,
) -> str:
    lines = wide_tail.splitlines()
    low = [ln.lower() for ln in lines]
    counts = {name: sum(1 for ln in low if pat in ln) for name, pat in _DIGEST_PATTERNS}
    counts_s = " ".join(f"{k}={v}" for k, v in counts.items())
    out = (
        f"[trigger-dense digest] status={status} phase={current_phase} "
        f"pid_alive={pid_alive} source={source} log={log_path} "
        f"tail_lines={len(lines)} tail_bytes={len(wide_tail.encode('utf-8', 'replace'))} "
        f"log_mtime_sec_ago={mtime_sec_ago} pattern_counts({counts_s}); "
        f"raw tail NOT inlined (trigger-dense workload; classify via "
        f"scripts/failure_classifier.py --log <path>)"
    )
    if _CUDA_IMA_SIGNATURE.search(wide_tail):
        # v3 (methodology-critic concern): fire the flag on the REAL
        # backend_poll.CUDA_IMA_SIGNATURE (imported/mirrored with a pinned
        # cross-module equality test), not the bare 'illegal memory access'
        # substring -- the signature also matches the engine-dead
        # alternatives, which a substring-only flag would silently drop.
        # Flag phrase chosen to MATCH signature alternative 2 so the #775
        # cross-pod marker-note fallback keeps firing on digested notes (§3.4).
        out += " cuda_ima_flag: illegal memory access was encountered (structural flag)"
    return out
```

(v3) `_CUDA_IMA_SIGNATURE` resolution: import `CUDA_IMA_SIGNATURE` from `backend_poll` if a clean import path exists from `poll_pipeline` (both live in `scripts/`; a `scripts/`-sibling import is precedented — implementer verifies no circular-import risk: `backend_poll` imports FROM `poll_pipeline`, so `poll_pipeline` importing from `backend_poll` would be circular — in that case MIRROR the compiled regex as a module constant in `poll_pipeline.py` with a cross-module equality test (`assert pp._CUDA_IMA_SIGNATURE.pattern == backend_poll.CUDA_IMA_SIGNATURE.pattern`) pinning them in sync; the `cuda_ima` COUNT in `_DIGEST_PATTERNS` may stay substring-based as a human-facing count, the FLAG is what carries the machine contract). The digest's `cuda_ima` count key and the flag are therefore allowed to disagree (count=0 with flag present, on an engine-dead-only tail) — that is correct behavior, not a bug.

Properties: single line, deterministic, bounded (~300 chars), zero raw log content, inherently secret-safe (no tail text to scrub). The pattern set matches the rule's grep recipe exactly; `status`/`phase`/`pid_alive` are the poller's exit-code proxy (§11 item 5); `log=` + `source=` are the file reference (path; bytes + mtime ride as fields).

## 11. Decision Rationale

1. **Digest format (structural one-liner: pattern counts + status/phase/pid + path + bytes/lines/mtime).** *Why:* it is the exact shape `.claude/rules/trigger-dense-review.md` § Orchestrator poll/forensics turns item 1 prescribes (bounded pattern COUNTS in the `grep -ciE 'error|traceback|killed|OOM'` recipe, phase/lane fields, file references path+size+mtime). *Source:* that rule section (#1546); incident #1481/2026-07-18. *Alternatives rejected:* redacted/truncated excerpt (still raw text — repetition accumulates the refusal surface, rule item 1); LLM-summarized tail (cost/nondeterminism/exposure in a cron-cadence poller — §3.7).
2. **Detection signal = task tag `trigger-dense`.** *Why:* keyed on the WORKLOAD and knowable-before-any-read (the rule's recognition heuristic), durable across poller/session/watcher respawns, mutable mid-run via an existing audited CLI, and readable in-process via the exact `keep-running` pattern already load-bearing in pod-safety code. *Source:* `pod_lifecycle.py:2287/:2386` (`keep-running` precedent); rule item 3 ("keyed on the WORKLOAD, knowable before any read"). *Alternatives rejected:* frontmatter field (no existing setter CLI parity; tags round-trip through `view --json` and the watcher ecosystem already keys on them); env var on the poll invocation (lost on watcher/crash-recovery respawns, which re-invoke without custom env — the same reason the workflow-fix recursion guard prefers the durable signal); content-based sniffing (requires reading the very content the rule says must not be read, and is not knowable-before-read).
3. **Digestion site = the `poll_once` construction site (dataclass value), NOT the CLI emit or backend_poll.** *Why:* one site covers every orchestrator-facing propagation — the direct CLI JSON, the router-lane copy through `backends/runpod.py` into `backend_poll` stdout, and every `epm:failure`/wedge marker note composed downstream (rule item 4: notes are re-read by later turns; raw text there poisons every future read) — while `crash_signature` (the machine surface) is left raw by construction. Digesting only in `main()` would leave the router lane and marker notes raw; digesting in `backend_poll` would have to distinguish lane provenance and touch the sidecar/terminal machine records. *Source:* §4 consumer table (grep-verified); rule items 1+4. *Alternative rejected:* digesting inside `_tail_excerpt_and_crash_signature` (would couple the excerpt and the machine-surface signature in one pinned helper).
4. **Fail direction: missing-task → raw (INFO); unreadable-state → digest (WARNING).** *Why:* a missing task has no declaration surface at all — ad-hoc/synthetic polls (and the whole existing test corpus) legitimately have no task, and "no declaration exists" honestly means "not declared trigger-dense"; whereas "a declaration may exist but could not be read" must fail toward the protected direction, because the harm is asymmetric — worst-case digest = a less-convenient excerpt with the raw log one bounded read away; worst-case raw = a refusal-wedged orchestrator session costing a respawn (#1074 ~2h; 2026-07-18: 7 kills, session replaced). LOUD per-tick warning keeps a systematic failure visible instead of a silent fleet-wide flip. *Source:* incident record in the rule's Files of record; fail-fast-but-safe project discipline.
5. **The Goal's "exit code" element maps to `status` + `pid_alive` + `phase` at this seam.** *Why:* poll_pipeline's liveness probe is a pid probe — the pod-side workload's numeric rc is not observable here by construction (rc lands in the sentinel channel and in the log the script-side `failure_classifier.py --log` reads, rule item 2). The digest carries the poller's own verdict fields, which are the exit-state information this seam actually has; inventing an rc would violate fail-fast honesty. *Source:* read of `poll_once`/`_ssh_probe` structure; rule item 2.
6. **CUDA-IMA structural flag inside the digest.** *Why:* preserves the ONE grep-found content-coupled machine contract (`_prior_failure_marker_is_cuda_ima`, backend_poll:1432) with zero backend_poll changes; the flag phrase is a CUDA error string, not gated-content vocabulary. *Source:* `backend_poll.py:1339-1345` (regex verified live); #775 Part D design. *Alternative rejected:* editing backend_poll to accept a `cuda_ima=N` count key (larger blast radius; touches the failover predicate module for a fallback path whose primary source — the sidecar — is unaffected).
