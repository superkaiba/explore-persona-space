# Plan — #971: recover head-name-less rebase husk in `sync_repo_root.py`

## 0.0 TL;DR (plain English)

- **What I'll change:** teach the root-sync helper's stale-husk recovery to handle a `.git/rebase-merge` (or `rebase-apply`) directory that a crashed autostash-pull left behind with only an `autostash` file and no `head-name`. Today `git rebase --abort` fails on that shape (rc=1) and the helper exits 6 forever, blocking every session's root sync (the 2026-07-03 ~8h fleet wedge). The fix: attempt the abort first; when it fails AND `head-name` is missing, rescue the autostash commit into git's stash list (`git stash store`), then remove the husk dir and continue.
- **What I expect:** the incident husk shape now recovers automatically with the stashed work preserved (and usually re-applied to the worktree by the existing stranded-autostash pass); all existing husk behavior (young-husk exit 5, valid-husk abort) is byte-for-byte unchanged.
- **What would change my mind:** evidence that git can represent a *valid, resumable* rebase without `head-name` (it cannot — verified empirically on git 2.34.1: the abort itself requires the file), or that `git stash store` refuses autostash commits (it doesn't — verified).

## 4. Design — answers to the seven design questions

**Q1 — trigger condition: attempt-abort-first.** Attempt `git rebase --abort` (`check=False`) and discriminate on failure; do NOT pre-check `head-name` and skip the abort. Rationale: (a) git-mediated recovery stays the primary path — if any git version CAN abort a state we think is broken, git wins and no manual surgery runs; (b) the manual path is thereby scoped to states git has *provably refused* this run (the rc + stderr are captured into the report as evidence); (c) git cannot represent a valid rebase without `head-name` — the abort itself needs it to restore the original branch (empirically rc=1 on 2.34.1), so "abort failed + head-name missing" identifies exactly the un-abortable class. The discriminator is FILE EXISTENCE, not stderr text matching (robust across git versions/locales). W.r.t. a REAL mid-rebase state: a real (git-created) rebase always has `head-name` — it is written during setup before any conflict stop — so a real rebase can never enter the fallback; belt-and-suspenders, the stale-age gate has already passed before any abort is attempted.

**Q2 — autostash rescue mechanics.** Read `sha = (husk/"autostash").read_text().strip()`. Sub-cases, each loud:

| Sub-case | Action | Semantics |
|---|---|---|
| file absent, or present-but-empty | nothing to rescue; disposition noted in the removal message | proceed to removal (git's own `READ_ONELINER_SKIP_IF_EMPTY` treats empty as no-autostash) |
| sha resolvable (`git cat-file -e <sha>^{commit}` rc=0) and already in `git rev-list -g refs/stash` | report "already present in the stash reflog" | proceed (idempotent re-run after a prior partial recovery — e.g. store succeeded, rmtree crashed) |
| sha resolvable, not yet stashed | `git stash store -m autostash <sha>`; on rc=0 report the stored entry | proceed; the entry is then handled by the existing `recover_stranded_autostash` pass in the SAME preflight (subject `autostash` matches `_autostash_entries`) |
| sha resolvable but `stash store` FAILS | `SyncAbortError(EXIT_UNEXPECTED, ...)` naming the sha + stderr + the manual recipe | **REFUSE — husk kept, nothing removed.** Rescue failure blocks removal (the "never lose non-identical data" invariant). Near-unreachable: store accepts even non-stash commits on 2.34.1. |
| sha unresolvable (garbage, or valid hex with missing object — both rc=128 from `cat-file -e`) | preserve the file content VERBATIM to `RESCUE_ROOT / f"husk-autostash-{husk.name}-{_rescue_timestamp()}.txt"` (mirrors the existing `stash-<sha12>.patch` pattern, which writes directly under `RESCUE_ROOT`) + a loud report row | proceed to removal — there is no retrievable git object behind the pointer; the pointer itself is preserved in two places, so nothing is silently discarded, and refusing would recreate the permanent wedge over a dangling reference |

The message `-m autostash` is load-bearing: it makes the stored entry's list subject exactly `autostash`, which is what `_autostash_entries()` (line 790) matches — so the rescued stash flows into the existing rescue-patch + pop-if-clean machinery with zero new code, and matches git's own autostash-store message.

**Q3 — husk removal.** `shutil.rmtree(husk)`, Python-mediated. The `git()` deny-list is argv-shape-based (`reset --hard`, `clean -f`, full-tree `checkout .`/`restore .`, `stash drop`) and offers no removal primitive for a state dir; git's own mediated removal is `rebase --quit`, REJECTED on empirical evidence: `--quit` removes the state dir and returns rc=0 even when its internal autostash store errors (`error: cannot store not-a-sha` — save_autostash's return is ignored), so a rescue failure could not block removal. Scope: `rmtree` is called ONLY inside `_recover_headnameless_husk`, reachable ONLY via stale age-gate PASS + abort rc≠0 + husk-is-dir + head-name-missing + autostash disposition resolved. **rebase-apply:** same handling — its abort has the identical `head-name` dependency (empirically verified rc=1 `could not read '.git/rebase-apply/head-name'`); the tuple's second entry flows through the same branch (`husk.is_dir()` is true for it). **MERGE_HEAD: out of scope** — `git merge --abort` is `reset --merge` keyed on `MERGE_HEAD` itself, which exists by construction when the loop entry matches; no head-name-style dependency exists. Only behavior change for MERGE_HEAD: a failing `merge --abort` now raises the explicit clearer message (same exit 6 as today's generic `CalledProcessError` path; `headnameless` is False for a file, so the removal branch is unreachable).

**Q4 — age-gating: UNCHANGED.** The young-husk exit-5 raise stays lexically before any new code; a young head-name-less husk exits 5 untouched. Write-order: the incident husk (autostash present, head-name absent) is itself the existence proof that git's setup writes `autostash` before `head-name` (git's `create_autostash` runs in `cmd_rebase` before the backend writes basic state) — so a young head-name-less husk genuinely can be a mid-setup race, and the existing age gate (default 3600s) is the correct guard. No change needed, and none made.

**Q5 — dry-run.** The dry-run branch pre-checks `head-name` existence (report-only, no abort attempted — dry-run must not mutate and `rebase --abort` is mutating even when it fails? No: a failed abort mutates nothing, but attempting subprocesses in dry-run is contrary to the branch's report-only shape; the file-existence pre-check is sufficient for reporting):
- head-name-less: `DRY-RUN: stale head-name-less {name} husk ({age}s old) — un-abortable by git; autostash would be rescued to the stash list, then the husk dir removed`
- otherwise: existing `DRY-RUN: stale {name} husk ({age}s old) would be aborted` (unchanged).

**Q6 — reporting.** Mirrors the existing shapes: the removal posts one `_msg` `STALE-HUSK REMOVED: {name} was {age}s old (> threshold), head-name-less and un-abortable (git rebase --abort rc={rc}: {stderr}); {autostash disposition}; husk dir removed.` and sets `report["actions_performed"] = True`; each autostash disposition also appends a `husk-rescue: ...` row to `report["stash"]` (rendered as the existing `  stash: ...` lines). No new report keys, no new exit codes.

```python
def _recover_headnameless_husk(
    repo: Path, husk: Path, age: float, aborted: subprocess.CompletedProcess[str], report: dict
) -> None:
    """Rescue-then-remove for a stale, un-abortable, head-name-less rebase husk.

    A crashed ``pull --rebase --autostash`` can die after writing
    ``<state-dir>/autostash`` but before ``head-name`` (2026-07-03 incident,
    #971); git can neither represent nor abort a rebase without ``head-name``
    (``git rebase --abort`` rc=1), so the husk permanently wedges preflight.
    Recovery order preserves the never-lose-data invariant: (1) rescue the
    autostash commit into the stash list (``git stash store -m autostash``;
    idempotent via a stash-reflog containment check; a store failure on a
    resolvable commit BLOCKS removal — fail loud, husk kept); unresolvable
    autostash content is preserved verbatim under ``RESCUE_ROOT`` first;
    (2) only then ``shutil.rmtree`` the husk dir. The stored entry's subject
    is exactly ``autostash``, so preflight step (4)
    (``recover_stranded_autostash``) immediately rescue-patches and
    pops-if-clean. Deliberately NOT ``git rebase --quit``: quit removes the
    state dir and exits 0 even when its internal autostash store FAILS
    (verified on git 2.34.1), so rescue failure could not block removal.
    """
    autostash_file = husk / "autostash"
    sha = autostash_file.read_text().strip() if autostash_file.exists() else ""
    disposition = "no autostash file present" if not autostash_file.exists() else (
        "autostash file empty — nothing to rescue" if not sha else ""
    )
    if sha:
        resolvable = git(repo, "cat-file", "-e", f"{sha}^{{commit}}", check=False).returncode == 0
        if not resolvable:
            RESCUE_ROOT.mkdir(parents=True, exist_ok=True)
            rescue_path = RESCUE_ROOT / f"husk-autostash-{husk.name}-{_rescue_timestamp()}.txt"
            rescue_path.write_text(autostash_file.read_text())
            disposition = (
                f"autostash content {sha!r} does not resolve to a commit — nothing "
                f"storable; content preserved at {rescue_path}"
            )
        elif sha in git(repo, "rev-list", "-g", "refs/stash", check=False).stdout.split():
            disposition = f"autostash {sha[:12]} already present in the stash reflog"
        else:
            store = git(repo, "stash", "store", "-m", "autostash", sha, check=False)
            if store.returncode != 0:
                raise SyncAbortError(
                    EXIT_UNEXPECTED,
                    f"head-name-less {husk.name} husk: could not rescue autostash {sha} "
                    f"(`git stash store` rc={store.returncode}: {store.stderr.strip()}); "
                    "husk left in place — nothing removed.\n"
                    f"manual: git stash store -m autostash {sha}  # then rm -rf {husk}",
                )
            disposition = (
                f"stored autostash {sha[:12]} as a stash entry "
                "(handled next by the stranded-autostash pass)"
            )
        report["stash"].append(f"husk-rescue: {disposition}")
    shutil.rmtree(husk)
    _msg(
        report,
        f"STALE-HUSK REMOVED: {husk.name} was {age:.0f}s old (> {_husk_age_s():.0f}s), "
        f"head-name-less and un-abortable (`git rebase --abort` rc={aborted.returncode}: "
        f"{aborted.stderr.strip()}); {disposition}; husk dir removed.",
    )
    report["actions_performed"] = True
```

def _stash_shaped_sha(local: Path) -> str:
    """Commit+push a tracked file, dirty it, `git stash create`, restore worktree."""
    _write(local, "dirty.txt", "base\n")
    _commit(local, "dirty.txt")
    _git(local, "push", "-q", "origin", "main")
    _write(local, "dirty.txt", "base\nuncommitted\n")
    sha = _git(local, "stash", "create", "autostash-sim").stdout.strip()
    _git(local, "checkout", "--", "dirty.txt")
    return sha

def _make_headnameless_husk(local: Path, dirname: str = "rebase-merge",
                            autostash: str | None = None, stale: bool = True) -> Path:
    husk = local / ".git" / dirname
    husk.mkdir()
    if autostash is not None:
        (husk / "autostash").write_text(autostash + "\n")
    if stale:
        t = time.time() - 7200
        os.utime(husk, (t, t))
    return husk

## 11. Decision Rationale

Hyperparameter grounding: **N/A — no training hyperparameters** (kind: infra; no model training).

1. **Trigger = attempt-abort-first, fall back on (rc≠0 ∧ head-name absent)** — *Why:* keeps git-mediated recovery primary; scopes manual surgery to states git provably refused; captures rc/stderr evidence into the report. *Source:* empirical — `git rebase --abort` rc=1 `could not read '.git/rebase-merge/head-name'` on a synthetic husk (this session, git 2.34.1), identical for `rebase-apply`; incident record in #971 body. *Alternatives:* pre-check head-name and skip the abort (rejected: loses the git-first principle and the captured evidence; saves one subprocess on a path hit ~never); stderr substring matching (rejected: locale/version-brittle vs file existence).
2. **Rescue = `git stash store -m autostash <sha>` with cat-file pre-validation + reflog idempotency check** — *Why:* `stash store` is git's own autostash-preservation primitive (its `rebase --quit` uses the same call with the same message); `-m autostash` makes the entry flow into the existing `recover_stranded_autostash` machinery (subject match at line 790) — rescue patch + pop-if-clean for free; `cat-file -e <sha>^{commit}` (rc=128 for garbage AND missing objects) discriminates the preserve-verbatim sub-case; `rev-list -g refs/stash` containment makes crashed-after-store re-runs idempotent. *Source:* empirical (this session): store rc=0 → `stash@{0}: autostash`, `refs/stash` == sha; manual incident recovery used exactly `git stash store` and preserved the work as `stash@{0}`. *Alternatives:* `git update-ref refs/task-workflow/...` (rejected: invents a new ref namespace the module's recovery machinery doesn't read); leaving the sha only in the report (rejected: an unreferenced commit is gc-able; the stash ref makes it reachable).
3. **Removal = `shutil.rmtree(husk)`, NOT `git rebase --quit`** — *Why:* the invariant requires rescue-failure to BLOCK removal; `--quit` removes the state dir and exits 0 even when its internal store fails. *Source:* empirical (this session): `git rebase --quit` on a garbage-autostash husk printed `error: cannot store not-a-sha`, removed the dir, returned rc=0. *Alternatives:* `git rebase --quit` (rejected per above — and it would also bypass our resolvable-vs-unresolvable disposition reporting); a git-argv removal primitive (none exists; the deny-list is argv-shaped and irrelevant to `rmtree`).
4. **Fail-loud semantics per sub-case (refuse on store-failure; preserve-then-proceed on unresolvable)** — *Why:* a resolvable commit that cannot be stored is real data at risk → refuse with husk kept; an unresolvable pointer has no retrievable object behind it → preserving the pointer (rescue file + report) satisfies never-lose-data while refusing would recreate the permanent wedge the task exists to fix. *Source:* module docstring invariants (lines 45-76) + the exit-6-forever incident. *Alternatives:* refuse on unresolvable too (rejected: re-wedges on a dangling 41-byte pointer); silently proceed (banned).
5. **MERGE_HEAD excluded; failing merge --abort gets an explicit message** — *Why:* `merge --abort` has no head-name dependency (`reset --merge` keyed on MERGE_HEAD, which exists by construction). *Source:* git docs (`git merge --abort` synopsis) + the loop's own structure (MERGE_HEAD is a file → `is_dir()` false → removal branch unreachable). *Alternatives:* extend removal to MERGE_HEAD (rejected: no observed failure class; out of the candidate's scope).
