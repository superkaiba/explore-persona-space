### 4.3 Detection predicate (exact regexes)

Constants block (placed with the other check constant blocks, with a flagged/not-flagged matrix comment):

```python
# `--check-upload-or-true`: an upload / result-persist / result-production
# command whose failure is swallowed by `|| true` / `|| :` / `; true`
# (#841: swallowed plot-phase failures + a missing upload phase silently
# lost stage JSONs/plots across attempts until the fail-loud fix commits).
UPLOAD_OR_TRUE_SWALLOW_OR_RE = re.compile(r"\|\|\s*(?:true\b|:(?=[\s;)&|]|$))")
UPLOAD_OR_TRUE_SWALLOW_TERMINAL_RE = re.compile(
    r"(?:\|\|\s*(?:true|:)|;\s*true)\s*$"   # terminal swallow — masks the WHOLE line/chain
)
# Shell-line upload/result-persist/result-production tokens:
UPLOAD_OR_TRUE_LINE_TOKEN_RE = re.compile(
    r"(?:"
    r"\bupload_file\b|\bupload_folder\b|\bupload_raw_completions\w*"  # HF helper calls (\w* — the
    r"                                                                # canonical helper is
    r"                                                                # upload_raw_completions_to_data_repo;
    r"                                                                # a trailing \b before `_` never matches"
    r"|\bhf\s+upload\b|\bhuggingface-cli\s+upload\b"                  # hub CLI
    r"|\b[A-Za-z0-9_]*upload[A-Za-z0-9_]*\.py\b"                      # upload helper scripts
    r"|\b[A-Za-z0-9_]*plot[A-Za-z0-9_]*\.py\b"                        # result-production (plot) scripts —
    r"                                                                # the founding #841 offender shape
    r"|\bgit\s+push\b"                                                # git persistence
    r"|\bgit\s+(?:add|commit)\b[^#]*\b(?:eval_results|figures|ood_eval_results)\b"
    r"|\$\{?HF_DATA_REPO\b|\$\{?HF_MODEL_REPO\b"                      # repo-destination env vars
    r")"
)
# Quoted/heredoc BODY upload-call tokens (inline-python upload blocks — the
# dominant dispatcher upload shape; widened \w*upload\w*( covers upload_file(,
# upload_folder(, _upload(, api.upload_file(, upload_split_lfs_to_overflow():
UPLOAD_OR_TRUE_BODY_TOKEN_RE = re.compile(
    r"(?:\b[A-Za-z0-9_]*upload[A-Za-z0-9_]*\s*\("
    r"|\bupload_raw_completions\w*|\bcreate_commit\s*\(|\.push_to_hub\s*\()"
)
UPLOAD_OR_TRUE_WAIVER_RE = re.compile(r"#\s*UPLOAD_OR_TRUE_EXEMPT:\s*(.+)")
UPLOAD_OR_TRUE_WAIVER_MIN_REASON_CHARS = 10
UPLOAD_OR_TRUE_PYC_OPENER_RE = re.compile(          # multi-line `python -c "` opener
    r"\bpython3?\s+-c\s+([\"'])"                    # capture the quote char
)
UPLOAD_OR_TRUE_PYC_MAX_BODY_LINES = 300             # bounded; unclosed at EOF → skip (FN-safe)
```

(The exact inline-comment placement inside the regex literal is the implementer's call — the token set is normative, the comment layout is not.)

Per logical line (after `_strip_sh_trailing_comment`, `.strip()`):

1. **Skip** logical lines starting with `#` (comments — mandatory: `issue841_scaling_dispatch.sh:85` is a comment containing both `|| true` and `upload`; also `issue654_dispatch.sh:159`, `new_worktree.sh:139/244–246`) or `echo ` (an echo cannot swallow an upload — CVD precedent; note `check_pipe_python` deliberately does NOT skip echo because there the echo IS a real producer — here an echo line performs no upload, so the skip is sound. Known accepted FN: `echo "…"; upload || true` on one logical line is skipped whole — frozen by a test fixture, documented in the docstring).
2. **TERMINAL swallow — whole-line (v2, upheld by the statistics reconciler):** if `UPLOAD_OR_TRUE_SWALLOW_TERMINAL_RE` matches the stripped logical line, flag iff `UPLOAD_OR_TRUE_LINE_TOKEN_RE` matches ANYWHERE on it. Bash `&&`/`||` are equal-precedence left-associative, so a terminal `|| true` masks the WHOLE preceding chain — `upload && echo ok || true` and `{ upload; } || true` are real swallows the old segment rule missed; identical semantics to the `; true` rule. Zero new live triggers under this rule (re-surveyed 2026-07-05: only the already-allowlisted 654:161 + 931:251 carry a terminal swallow + token).
3. **NON-terminal `|| true` / `|| :` — segment-scoped:** for a swallow NOT in terminal position, split the stripped logical line on `&&` and `;` (naive split, quote-unaware — fail direction is false-NEGATIVE, the safe direction per the `_strip_sh_trailing_comment` philosophy); flag iff some segment matches BOTH `UPLOAD_OR_TRUE_SWALLOW_OR_RE` and `UPLOAD_OR_TRUE_LINE_TOKEN_RE`. This preserves the `mkdir -p "$OUT" || true && uv run python scripts/verify_uploads.py` false-positive kill (the swallow there is non-terminal and its segment carries no token).
4. **Heredoc bodies:** if the opener logical line carries any swallow (terminal or segment-scoped, token not required on the opener), scan each of its heredoc bodies' non-`#`-comment lines for `UPLOAD_OR_TRUE_BODY_TOKEN_RE`; a match flags the OPENER line. This catches `i632_dispatch_with_log_capture.sh:30` (opener has no token; body calls `api.upload_file(` at :69) — the shape a line-only scan provably misses.
5. **Multi-line `python -c` quoted blocks (v2 — the CURRENT #841 upload-phase shape):** when a logical line matches `UPLOAD_OR_TRUE_PYC_OPENER_RE` and the captured quote is NOT closed on the same logical line, consume subsequent physical lines until the first line containing the closing quote char (cap `UPLOAD_OR_TRUE_PYC_MAX_BODY_LINES`; unclosed at EOF or cap hit → skip the block entirely, fail-toward-FN). The command TAIL = the remainder of the closing line after the quote. Flag iff the tail carries a swallow (`UPLOAD_OR_TRUE_SWALLOW_TERMINAL_RE` on the tail, or `UPLOAD_OR_TRUE_SWALLOW_OR_RE` in the tail's token-bearing segment) AND (`UPLOAD_OR_TRUE_BODY_TOKEN_RE` matches any non-`#`-comment consumed body line OR `UPLOAD_OR_TRUE_LINE_TOKEN_RE` matches the opener/tail). Consumed body lines are never re-parsed as shell lines. This covers `issue841_scaling_dispatch.sh:106/:157` + `issue841_gru_source_only_dispatch.sh:98/:192` (`upload_split_lfs_to_overflow(` bodies) against a future re-swallow. Simplification note for the implementer: single-quoted `python -c '...'` bodies cannot contain `'` at all and double-quoted bodies in this repo do not contain unescaped `"` — a first-closing-quote-char scan suffices; bail (skip) on anything trickier.
6. **Dedupe** per (file, opener first-line): a line can hit via multiple rules (issue654: `$HF_DATA_REPO` on the opener AND `_upload(` in the body) — emit ONE error.
7. **Waiver:** suppress when `# UPLOAD_OR_TRUE_EXEMPT: <reason>` (reason ≥ 10 chars after strip) appears on any physical line of the logical command or the immediately preceding non-blank line — reuse the `_cvd_pin_waiver_present` placement logic (write a sibling `_upload_or_true_waiver_present`, or generalize the CVD helper to take the regex + min-chars as params; either is fine, generalizing preferred). Waiver detection runs on the RAW lines (before comment stripping — the waiver IS a comment). Note a trailing comment after a heredoc redirect (`... <<'PY' || true  # UPLOAD_OR_TRUE_EXEMPT: ...`) is valid bash, so both placements work on heredoc openers.

**Error message** (mirror CVD verbosity): `{sh}:{first+1}: upload/result-persist/result-production command swallows failure with '|| true' / '; true'. A swallowed failure on a result-bearing phase silently loses artifacts (#841: swallowed plot-phase failures compounded a missing upload phase — stage JSONs/plots lost across attempts until the fail-loud fix) — remove the swallow and let the failure abort (fail fast; the crash-persist/poller path reports it). A deliberate best-effort side-channel (crash-diagnostics upload) is waived with '# UPLOAD_OR_TRUE_EXEMPT: <reason>' (reason ≥ 10 chars) on the same or previous non-blank line.`
