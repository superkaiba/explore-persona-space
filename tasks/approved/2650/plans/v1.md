## Method delta — what differs from the nine prior rounds of this class

`tasks/REGISTRY.json` holds **nine** prior tasks of this exact class (grep
`torch_before_dotenv`), each of which cleared the then-current violators.
This is the tenth. Phase 1 is the same fix those nine applied; **Phase 2 is
the delta** — it moves enforcement from "the pytest guard, at whichever later
session runs the Step 9c gate" to "the `workflow_lint.py` no-flags run", which
the Step 9a-ter inline payload lint gate already runs on every inline round's
payload. That is the channel these eleven scripts actually landed through.

Two mechanisms were ruled OUT as the root cause by direct probe, so Phase 2
targets the one that survives:

- **Not a Step 9c selector gap.** `select_step9c_tests.py --map-files` on
  `scripts/issue2643_sae_map.py` returns 6 pairs, and
  `tests/test_shared_vm_thread_caps.py` is one of them. The #895 gap is closed.
- **Not a known-red strip.** `.claude/cache/step9c-baseline.json`
  (`main_sha=fceea4a40db`, refreshed 2026-08-26) lists exactly two
  `failing_tests`, neither of them this node. So the node was green at the last
  refresh and every session's Step 9c genuinely inherits today's red.
- **The surviving hole.** The scanner is INDEX-ONLY at main checkouts by
  deliberate design (`_scan_targets` docstring: a foreign session's transient
  untracked violator would false-red ~15 concurrent sessions). A script
  authored and committed at the shared root is therefore invisible to the guard
  until the moment it lands, at which point it is already on `main`. The
  `EPM_SCAN_EXTRA_FILES` leg (#1889) closes this for rounds that go through
  `scripts/inline_lint_gate.py`; nothing closes it for a hand commit.

## Phase 1 — fix all eleven (the required leg)

**Fix shape** — the canonical in-repo exemplar is `scripts/issue778_null_battery.py`
(the #847 incident offender, FIXED rather than grandfathered; the guard asserts
it stays out of the allowlist). Insert immediately before each file's first
`HEAVY_IMPORT_ROOTS` import, after the stdlib block:

```python
from explore_persona_space.orchestrate.env import load_dotenv

# #847: thread caps must land BEFORE the numpy/torch imports below — on the
# shared VM, load_dotenv() setdefaults OMP/MKL/OPENBLAS/NUMEXPR_NUM_THREADS,
# and the BLAS/torch pools freeze at import time.
load_dotenv()

import numpy as np
```

Four properties make this safe here, each checked rather than assumed:

1. **No `# noqa: E402` needed.** `pyproject.toml [tool.ruff.lint.per-file-ignores]`
   ignores `E4` (which contains E402), `W`, `I` and `RUF100` for `scripts/*`.
   Verified: all eleven are ruff-clean pre-fix, and the fix is re-verified
   post-edit.
2. **`explore_persona_space` is importable at module top in these files.** Five
   of the six `issue779_*` files already import
   `explore_persona_space.orchestrate.provenance` at module top; the package is
   installed editable and every invocation path is `uv run`.
3. **The wrapper's own import chain is heavy-free**, pinned by the sibling test
   `test_dotenv_wrapper_import_chain_is_heavy_free` — so the preamble cannot
   itself freeze the pools it exists to cap.
4. **Sibling-module imports sit AFTER the heavy imports** in every file
   (e.g. `import issue779_ctxansviz_separate_pca_dashboard as text_source` at
   line 25, numpy at 22), so one insertion point per file covers the whole
   module-top import block.

**Consumer check (acceptance A3).** Every violator is import-reachable from at

## Phase 2 — the pre-landing check (adopted; A5)

**Single source of truth is the binding constraint.** A second hand-written
copy of the predicate would drift from the pytest guard, and a drifted lint is
worse than no lint. So:

1. **Extract, do not duplicate.** Move from `tests/test_shared_vm_thread_caps.py`
   into a new `src/explore_persona_space/orchestrate/heavy_import_order.py`:
   `HEAVY_IMPORT_ROOTS`, `GRANDFATHERED_895`, `GRANDFATHERED_1187`,
   `GRANDFATHERED_TORCH_BEFORE_DOTENV`, `_first_heavy_import_line`,
   `_first_load_dotenv_line`, `_in_scan_class`, `_worktree_local_extras`,
   `_scan_targets` — verbatim, comments included. The test re-imports them
   under the same names, so `test_grandfathered_895_block_is_current`,
   `test_grandfathered_1187_block_is_current`,
   `test_scan_targets_staged_already_enumerated` and
   `test_dotenv_wrapper_import_chain_is_heavy_free` keep working unchanged.
   Blast-radius probe: no file outside the test references these symbols in
   code (only prose in `scripts/{step9c_baseline,inline_lint_gate,select_step9c_tests}.py`
   comments); the test's one `inspect.getsource` call targets
   `env_mod.setup_worker`, unrelated to the moved block.
   The new module must import NO heavy root (it is `ast` + `pathlib` +
   `subprocess` only), or it would break the wrapper-chain pin.
2. **`workflow_lint.py --check-torch-before-dotenv`**, bundled into the
   no-flags default run, modelled directly on `--check-prod-import-lockfile`
   (#2253) — the precedent the task body cites, and likewise a scripts//src/
   import-resolvability check in the no-flags run.
3. **`tests/test_workflow_lint_torch_before_dotenv.py`** — pins that the lint
   FAILs a synthetic violator, PASSes a fixed one, honours the allowlist, and
   agrees with the pytest guard on the live tree.

**Explicitly NOT adopted: a pre-commit hook.** It would be the only surface
that fires at commit time without the author opting in — but it blocks commits
fleet-wide for ~15 concurrent sessions on a shared root, which is the failure
class `.pre-commit-config.yaml`'s own NOTE was written to avoid. Recorded here
as a considered-and-declined option rather than an oversight.

**Sequencing is load-bearing.** Phase 1 lands and is pushed FIRST, as its own
commit. Phase 2 is a refactor of a heavily-pinned guard whose own failure mode
is the identical fleet-wide red; if it goes wrong it must not delay the
hotfix. If Phase 2 cannot be landed cleanly, it is filed as a follow-up
`kind: infra` task and Phase 1 still satisfies A1-A4.
