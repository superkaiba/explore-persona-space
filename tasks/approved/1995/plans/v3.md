# Plan v3 — workflow-fix: widen `_PATH_RE` to cover the remaining include-tree prefixes

## Requirement + acceptance criteria

**Requirement.** `scripts/verify_carryover_inputs.py`'s channel-A extraction (`_PATH_RE`)
currently matches only `(eval_results|ood_eval_results|data)/…`, so a plan-text citation of
a committed input under any OTHER include-tree prefix (`tests/`, `scripts/`, `configs/`)
produces **no finding at all** — the clone-lane reachability check and the #1915 rsync-lane
exclude-subtraction (both fed by channel A + `apply_rsync_lane_downgrade`) are blind to it
in plan text. The `#1915` pin tests exercise those code paths by constructing `Finding`
objects that enter `classify()` / `apply_rsync_lane_downgrade` directly, so the classifier
DOES handle include-tree paths correctly — the extraction is the sole missing link.

Concretely: `tests/fixtures/eval_results/a.json` cited in a plan currently escapes both
channels; after the fix it is extracted, classifies `in-ref` on the clone lane, and — under
`--lane rsync` — downgrades to `FAIL(rsync-lane-not-synced)` because the `eval_results/`
component matches `RSYNC_EXCLUDE_PATTERNS` at every depth (the exact case #1915 was
designed to catch, but only for callers that constructed `Finding` objects manually).

**Acceptance criteria** (mechanical, verifiable via `pytest`):

1. `_PATH_RE` matches full-prefix citations under the include-tree prefixes chosen by the
   corpus sweep (§4). At minimum `tests|scripts|configs` (the include-tree names in
   `RSYNC_INCLUDE_PATHS` that (a) are TOP-LEVEL dirs and (b) plans routinely cite as
   carry-over-input containers or fixture roots). `src` and `external/open-instruct` and
   `data/sft` are OUT of scope for this round — see §4 "Prefix set decision" rationale.
2. The existing skip rungs (`glob-or-template`, `dir`, `no-ext`) fire on include-tree
   citations exactly as they do on `eval_results/`/`ood_eval_results/`/`data/` citations —
   no regression on the existing 3 prefixes' behavior (round-trip test).
3. The load-bearing case — a plan citing `tests/fixtures/eval_results/a.json` — extracts,
   classifies `in-ref` under `--lane clone`, and downgrades to
   `FAIL(rsync-lane-not-synced)` under `--lane rsync` (the classify + downgrade already
   work for that path via #1915; the fix wires extraction into the same ladder).
4. A **corpus-sweep script** — `scripts/issue1995_corpus_sweep.py` — runs the widened
   `extract_candidate_paths` over every persisted plan under `tasks/**/plans/v*.md`
   (~3,491 files at draft time) and aggregates verdict-class counts + a bounded FAIL/WARN
   sample so a reviewer can inspect the concrete new-prefix false-positive surface. The
   script is a ONE-OFF calibration tool (its output rides the round's marker + gets
   committed under `figures/issue_1995/`); the sweep is NOT wired into the gate itself.
5. New unit tests in `tests/test_verify_carryover_inputs.py` cover:
   (a) each new-prefix extracts correctly + honors the existing skip rungs;
   (b) `tests/fixtures/eval_results/a.json` extracts and (under `apply_rsync_lane_downgrade`
       with the shipping `RSYNC_INCLUDE_PATHS` / `RSYNC_EXCLUDE_PATTERNS`) downgrades;
   (c) an old-prefix hit still passes classify unchanged (regression pin).
6. The reference-lint / no-flags `workflow_lint.py` bundle passes (the fix touches a
   file `verify_plan.py` calls out; the linter cross-references it).
7. `ruff check` + `ruff format --check` clean on the touched files.

**Kill criterion.** The corpus sweep (§4) shows the widened extraction produces a
`FAIL`-class verdict on ≥ 2% of plans that would previously have PASSed silently AND the
inspected FAIL samples are dominated by *legitimate false positives* the ladder cannot
naturally reject (a plan citing `scripts/utility.py` where `utility.py` is intentionally
absent from `origin/main` — a stated deferred output — with no `planned-output-declared`
skip fitting). If the kill criterion fires, narrow the prefix set OR add a
new-prefix-specific skip rung (e.g. `.py`/`.md`/`.yaml` extensions where the corpus shows
they are code references, not carry-over inputs) BEFORE landing. Baseline for the "2%"
figure: today's channel-A ladder produces ≤ 1 FAIL per ~50 plans on a clean-tree corpus
(the ladder is well-calibrated for its current three prefixes); a > 2× rise for the new
prefixes is the fail-loud threshold.

## Method delta

- Additive: widen ONE regex, add ONE calibration script, add unit tests. No change to
  `classify()`, `apply_rsync_lane_downgrade`, or the #1935 declared-output stanza.
- The classifier already handles include-tree paths correctly (proven by #1915 pin tests
  that construct `Finding("tests/fixtures/eval_results/a.json", ...)` directly). This
  round wires extraction into the same ladder.
- No new `_PATH_RE` alternative — one added group; the `(?<![\w/\-.])` lookbehind and the
  trailing character class are unchanged.

## Files touched (concrete diffs)

**`scripts/verify_carryover_inputs.py`** — one-line regex change:

```diff
 _PATH_RE = re.compile(
     r"(?<![\w/\-.])"
-    r"(?P<path>(?:eval_results|ood_eval_results|data)/"
+    r"(?P<path>(?:eval_results|ood_eval_results|data|tests|scripts|configs)/"
     r"[A-Za-z0-9][\w.\-/*?\[\]{}<>]*)"
 )
```

Plus a short docstring update above `_PATH_RE` naming the new prefixes and the #1995
sibling of #1915 (extraction ↔ downgrade parity).

**`scripts/issue1995_corpus_sweep.py`** — new, one-off calibration script:

- Iterate every `tasks/*/*/plans/v*.md` (~3,491 at draft time).
- For each: run `extract_candidate_paths(text)` filtered to the NEW prefixes.
- Group by prefix, aggregate `{n_plans_with_hits, n_hits_total, skip_reason_counts}`.
- For classification: run `classify()` against `origin/main` with `--no-fetch` (per
  `resolve_check_ref(fetch=False)` — no network) for a **bounded random sample** (100
  plans) so the sweep completes in < 5 min. Report per-verdict counts + the concrete
  paths of every FAIL/WARN in the sample so a reviewer can eyeball them.
- Write structured output to `figures/issue_1995/corpus_sweep.json` (aggregates) and
  `figures/issue_1995/corpus_sweep_samples.md` (the FAIL/WARN inspection list).
- Print the aggregate line to stdout for the `epm:experiment-implementation` marker.

**`tests/test_verify_carryover_inputs.py`** — new test cases:

- `test_path_re_matches_new_prefixes`: three parametrized rows (`tests`, `scripts`,
  `configs`) confirming extraction, sharing the existing skip-rung assertions.
- `test_path_re_include_tree_and_exclude_name_interaction`:
  `tests/fixtures/eval_results/a.json` extracts as a channel-A candidate, and passed
  through `apply_rsync_lane_downgrade` with the shipping `RSYNC_INCLUDE_PATHS` +
  `RSYNC_EXCLUDE_PATTERNS`, downgrades to `FAIL(rsync-lane-not-synced)` with the
  `--extra-sync-path` remediation message.
- `test_path_re_old_prefixes_unchanged`: regression pin — the three pre-widening prefixes
  produce the byte-identical `Finding` objects they always did.
- `test_path_re_lookbehind_still_excludes_hf_and_urls`: negative — a `\w` / `/` / `-`
  / `.` immediately BEFORE a new-prefix hit still bars the match (mirrors the existing
  HF `explore-persona-space-data/…` test).

   sample surfaces edge cases).
