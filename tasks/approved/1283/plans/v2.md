```python
def _warn_missing_wf_fix_title_prefix(args: argparse.Namespace) -> None:
    """#1283 warn-only dedup-surface backstop: a `wf-fix`-tagged filing whose
    --title lacks a WF_FIX_TITLE_PREFIXES prefix ("workflow-fix:" /
    "daily-fix:") is invisible to the (target_file, fingerprint) dedup
    predicate's cheap title pre-filter (task_workflow.is_open_workflow_fix_task),
    so the same bug can double-file later (#1180's incident class). Warn-only
    by design — the filer is channel-agnostic (it cannot know WHICH per-channel
    prefix to prepend; the /daily route-2 driver already prepends its own per
    #1273), and the must-succeed filing half stays untouched: exit codes and
    filing behavior unchanged (the #1173 precedent above)."""
    if "wf-fix" not in (args.tag or []):
        return
    if args.title.startswith(WF_FIX_TITLE_PREFIXES):
        return
    prefixes = " / ".join(f"'{p}'" for p in WF_FIX_TITLE_PREFIXES)
    print(
        f"file_infra_task: WARNING — wf-fix-tagged filing whose --title lacks a "
        f"{prefixes} prefix; the filed task will be invisible to the dedup "
        "predicate's title pre-filter (task_workflow.is_open_workflow_fix_task; "
        ".claude/rules/workflow-fix-on-bug.md § Dedup, #1283)",
        file=sys.stderr,
    )
```

Message constraint (load-bearing): the warning text MUST NOT contain the substring `workflow_fix_target` — the existing `test_wf_fix_tag_body_with_target_line_no_warn` (line 545) asserts that substring is absent from stderr. `is_open_workflow_fix_task` does not contain it (`workflow_fix_task` ≠ `workflow_fix_target`); verified by inspection and re-pinned by the new test's `"workflow_fix_target" not in err` assertion.

## 11. Decision Rationale

**D1 — Warn-only stderr WARNING (chosen) vs auto-prepend parity with the driver.**
- **What:** the filer prints one stderr WARNING and files the title verbatim; it never mutates the title and never blocks.
- **Why:** (a) *Channel ambiguity — the decisive argument:* the prefixes are per-channel ("workflow-fix:" = orchestrator, "daily-fix:" = /daily route-2; task_workflow.py:991–1000 "one per filing channel"). The driver knows its channel and can prepend correctly (#1273); the generic filer does NOT know which channel is invoking it, so a filer-side auto-prepend must guess and can mislabel the filing channel — corrupting the very provenance signal the prefix encodes. (b) *No double-guard / no surprise:* the /daily driver already prepends before shelling into this filer (`daily_drive_filings.py:413`); a second mutation layer risks interaction bugs, and ad-hoc callers that deliberately title differently would be silently rewritten. (c) *Register parity:* the filer's established guard register is warn-only ("the must-succeed filing half stays untouched", `file_infra_task.py:218`); a mutation would be this file's first silent input rewrite. (d) *Non-architectural:* warn-only changes no filed artifact and no contract, keeping the task on the auto-merge path.
- **Source:** #1273's recorded prose follow-up (quoted in #1283 `## Provenance`: "filer-side **WARN** … is recorded" — the follow-up itself specified WARN, not prepend) + the #1173 warn-only precedent in the same file (`file_infra_task.py:211–236`).
- **Alternatives rejected:** auto-prepend `workflow-fix: ` (channel guess — wrong for a hypothetical direct daily-channel caller; deviates from the recorded follow-up); hard error / non-zero exit (blocks filings — a public-contract change requiring the architectural gate; also breaks the "filing is must-succeed" invariant callers depend on, `daily_drive_filings.py:67` parses the filer's success stdout).

**D2 — Import `WF_FIX_TITLE_PREFIXES`, never a literal.**
- **What/Why:** single source of truth; a third filing channel added at task_workflow.py:1001 propagates with zero filer edits. **Source:** task_workflow.py:1000 ("single source of truth") + #1273 plan §Decision ("Import `WF_FIX_TITLE_PREFIXES`, never a literal") + #1180 (which created the shared constant for exactly this reason). **Alternative rejected:** inline tuple (drift risk the constant exists to prevent).

**D3 — Retitle the two #1173 tests rather than leave them warn-contaminated.**
- **What/Why:** keeps each warn family's tests isolated to its own warning; both tests would pass either way (§12 A4), so this is clarity, not behavior. **Source:** the #1173 tests' own names ("…_no_warn") + the line-545 substring-absence assertion's fragility. **Alternative rejected:** leave untouched (mechanically green but `…_no_warn` would run with a warning on stderr — misleading to the next editor).
