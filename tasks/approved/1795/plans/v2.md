(v2 folds the round-1 Methodology critic's APPROVE-with-suggestions: `import re`

## 1. Goal / Requirement

Fail loud at item-construction/dispatch time on Anthropic Batch-API
custom_id grammar violations (`^[a-zA-Z0-9_-]{1,64}$`) instead of dying
mid-wave on an HTTP 400 inside a detached driver.

**Acceptance criteria:**

1. `dispatch_judge_items_async` (and therefore the sync wrapper
   `dispatch_judge_items` and every caller routed through it, incl.
   `judge_completions_batch`) raises `ValueError` at ENTRY — before any
   routing probe or API call — when any item's custom_id violates the
   grammar (or is not a `str`), naming up to 5 offending ids + the total
   offender count + the grammar + a pointer to `batch_judge.make_custom_id`
   as the sanctioned sanitizer.
2. A tilde-bearing id (the #1739 incident shape) is covered by a unit test
   that asserts the raise fires and names the id.
3. Valid ids pass through unchanged (no behavior change for conforming
   callers; existing test suite for the module stays green).
4. The grammar constant in `judge_dispatch.py` is pin-tested equal to
   `batch_judge._CUSTOM_ID_RE` (single-grammar invariant across the two
   modules).

## 3. Design decisions

1. **Validation site = `dispatch_judge_items_async` entry**
   (`judge_dispatch.py:1415`, immediately after `n_items = len(items)`
   (~L1471) and BEFORE the dry-run branch / routing probe). Rationale:
   - Single seam: the sync wrapper (`:1613`), `judge_completions_batch`
     (batch_judge.py ~L775), the retry re-entry, and all ~30 caller scripts
     route through it.
   - Routing is by N (`decide_route`): the SAME items go batch or sync
     depending on count, so a batch-only check leaves a latent bomb that
     fires only at scale. Entry validation fails loud in smoke runs too.
   - Placing it before the dry-run return means `dry_run=True` exercises
     the validation with ZERO API calls — the unit tests use exactly this.
   - Critic-verified: retry re-entry (`_is_retry=True`) recomputes ids from
     the same already-validated items (idempotent revalidation); no
     poisoned-checkpoint case exists (a pre-fix bad-id batch run 400'd at
     submit, so no successful `state.json`; the sync path has none).
2. **Deliberate behavior change (sync-routed items also validated).**
   Grammar binds API-side only on the batch path, but per the routing
   argument above, uniform validation is the fail-fast choice. Caller
   audit (2026-07-29): spot-checked the id constructions of 14 live caller
   scripts (`issue763_judge_e0`, `issue685_judge_validity`,
   `issue1738_characterize`, `phase6_dispatcher_vs_baseline`,
   `issue1773_validate`, `issue664_eval`, `issue779_common`,
   `issue1773_describe_axes`, ...) — all shapes are `[a-zA-Z0-9_-]`-clean
   (`f"ci{ci}"`, `f"phase6_{i:06d}"`, `persona__NNNNN__CC`,
   `f"f{feat_id}-desc"`). No known live caller regresses. A frozen
   historical script with an out-of-grammar id would now fail loud at
   dispatch instead of 400 mid-wave — the desired behavior per
   llm-judging.md rule 24(iii) (400 = pipeline bug; fix the builder).
   **Impl-time audit extension (critic suggestion 2):** the implementer
   additionally audits the two LIBRARY construction funnels —
   `batch_judge._enumerate_and_check_cache` ~L571
   (`f"{persona_name}__{idx:05d}__{comp_idx:02d}"`; persona/behavior keys
   are caller-supplied and charset-unvalidated) and
   `graded_judge.judge_graded` (bans only `__` in item_id, L203-211) — and
   confirms no live persona/behavior key in the repo's query banks /
   configs is out-of-grammar; §7's kill criterion covers a hit.
3. **Grammar constant duplicated in `judge_dispatch.py`** as
   `_CUSTOM_ID_RE = re.compile(r"^[a-zA-Z0-9_-]{1,64}$")` with a cross-ref
   comment to `batch_judge._CUSTOM_ID_RE`, NOT imported: a top-level
   `judge_dispatch -> batch_judge` import closes the
   `batch_judge -> alignment -> judge_dispatch` cycle (module-documented
   precedent: the `DEFAULT_THRESHOLD_BASE = 2_000` literal at
   `judge_dispatch.py:~222`, locked equal by
   `test_judge_router_default_is_the_judge_ceiling`). A pin test locks the
   two patterns byte-equal. NOTE (critic suggestion 1): `judge_dispatch.py`
   does NOT currently import `re` — Edit 1 adds `import re` to the module
   imports (stdlib; no new dependency).
4. **Out of scope:** the legacy `_submit_and_poll_batch` path in
   `batch_judge.py` (two frozen `scripts/issue_389` callers). Its items
   flow through the shared `_enumerate_and_check_cache` length check
   (which serves the primary path too — attribution per critic suggestion
   4); new work routes through the newly validated seam. No caller-side
   edits. No sanitize-in-place — the validator RAISES; sanitizing silently
   would mask caller bugs and break checkpoint/resume id stability.

## 4. File paths + concrete diffs

**Edit 1 — `src/explore_persona_space/eval/judge_dispatch.py`:**

Add `import re` to the module's stdlib imports (currently absent). Then,
near the JudgeItem definition (~line 219):

```python
# Kept a literal here (not imported from batch_judge) to avoid the
# judge_dispatch -> batch_judge -> alignment -> judge_dispatch cycle;
# tests/test_judge_dispatch.py locks it equal to batch_judge._CUSTOM_ID_RE.
_CUSTOM_ID_RE = re.compile(r"^[a-zA-Z0-9_-]{1,64}$")


def _validate_custom_ids(items: list[JudgeItem]) -> None:
    """Fail loud pre-submit on Batch-API custom_id grammar violations (#1795).

    A malformed custom_id is a deterministic HTTP 400 invalid_request_error
    mid-wave (llm-judging rule 24(iii): neither retried nor dropped — a
    pipeline bug). Validate at dispatch entry so BOTH routing outcomes fail
    at construction time (#1739: a `~`-bearing id killed a detached judge
    wave). batch_judge.make_custom_id is the sanctioned sanitizer.
    """
    bad = [
        cid
        for cid, _q, _c, _u in items
        if not isinstance(cid, str) or not _CUSTOM_ID_RE.match(cid)
    ]
    if bad:
        shown = ", ".join(repr(b) for b in bad[:5])
        raise ValueError(
            f"{len(bad)} judge item custom_id(s) violate the Anthropic Batch API "
            f"grammar ^[a-zA-Z0-9_-]{{1,64}}$ (first {min(len(bad), 5)}: {shown}). "
            "Fix the caller's id construction or route ids through "
            "batch_judge.make_custom_id()."
        )
```

Call site: in `dispatch_judge_items_async`, immediately after
`n_items = len(items)` (~L1471), before the dry-run/routing block:

```python
    n_items = len(items)
    _validate_custom_ids(items)  # #1795: fail loud pre-submit, both routes
```
