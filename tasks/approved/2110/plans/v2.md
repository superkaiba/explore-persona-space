## Root cause (verified at plan time, this session — supersedes the body's hypothesis)

The task body's premise ("a session spawned 12h after the #2073 env fix still
thrashed") is FALSE on the corrected timeline; the underlying delivery gap is real
but vintage-shaped:

1. **0d005b55 started 2026-08-04T20:05:30Z** (transcript line 0 timestamp), i.e.
   1.8h AFTER the settings fix (2de759b9d7, 18:17Z) but **8.4h BEFORE the Happy
   daemon restart** (pid 201205, started Aug 5 04:30Z). The miner's "spawned
   ~06:32Z Aug 5" was a mis-read (likely a continuation-restart timestamp).
2. It was therefore spawned by the PRE-FIX-vintage daemon, whose exec env lacked
   `CLAUDE_CODE_AUTO_COMPACT_WINDOW`; spawned children inherit the DAEMON's env.
3. **Runtime settings-env application does NOT bind the auto-compact window**:
   settings.json already carried the var when 0d005b55's process started, yet
   88/89 of its compact boundaries sat at 242,315–275,275 preTokens across ~20h
   (2026-08-04T22:00Z → 2026-08-05T16:00Z). Only the exec-time process
   environment binds the window. (Contrast: settings-env IS visible to tool
   children at runtime — verified in this session's Bash env — so the window
   resolution samples process env before/independently of settings-env
   application.)
4. The daemon restart at Aug 5 04:30Z (from a var-bearing parent session:
   daemon exec environ carries `CLAUDE_CODE_AUTO_COMPACT_WINDOW=1000000`,
   `CLAUDE_CODE_SESSION_ID`/`CLAUDE_CODE_CHILD_SESSION=1`) closed the gap
   operationally: 10/10 live daemon-spawned issue sessions carry the var at exec
   (`/proc/<pid>/environ` sweep, 2026-08-06T07:04Z), and every transcript whose
   FIRST compact boundary postdates the restart compacts at 829,652–1,058,981
   preTokens (36h fleet scan, 18 transcripts).
5. **The spawn-payload `environmentVariables` channel provably lands in the child
   exec env, and payload keys WIN over daemon env** — verified at the daemon
   source (critic round 1): `/usr/lib/node_modules/happy/dist/index-BmZ4or3w.mjs`
   L4480 (route field), L5761-5763
   (`extraEnv = {...authEnv, ...options.environmentVariables ?? {}}`),
   L5922-5925 (`env: { ...process.env, ...extraEnv }`). Corroborated by this
   session's `/proc/3485599/environ` (payload-injected `HAPPY_INITIAL_PROMPT`,
   `EPM_AUTONOMOUS_SESSION`, ... present at exec). So forwarding settings-env
   entries through the payload removes the daemon-vintage dependency entirely —
   no disposable reproduce-spawn needed (body step (a) satisfied by the
   live-fleet evidence above).
6. **Daemon-side hazard (critic round 1, drives the `${` guard below):** the
   daemon runs `expandEnvironmentVariables(extraEnv, process.env)` and REJECTS
   the whole spawn (`type: "error"`) when any forwarded value carries an
   unresolved `${...}` reference (index-BmZ4or3w.mjs L5778-5800); its
   `environmentVariables` zod schema is `z.record(z.string(), z.string())`, so
   non-string values also error the spawn.

## Method delta

Belt-and-braces delivery: instead of relying on daemon env inheritance (vintage-
sensitive), `spawn_session.py` reads the settings `env` block at SPAWN time and
injects the `CLAUDE_CODE_*` subset into the spawn payload for every spawn path.
A future settings-env change then binds for all new spawns immediately, with no
daemon restart.

## File paths + concrete changes

1. **`scripts/spawn_session.py`**
   - New helper `_settings_env_overrides() -> dict[str, str]`: read
     `~/.claude/settings.json`, take the top-level `env` dict, return
     `{k: str(v)}` for keys starting with `CLAUDE_CODE_`. The `str(v)` coercion
     is LOAD-BEARING, not cosmetic — the daemon's `environmentVariables` zod
     schema is `z.record(z.string(), z.string())`, so a raw JSON number would
     error the spawn (carry this as a code comment). FAIL-SOFT on read: missing
     file, unparseable JSON, or non-dict `env` → return `{}` (a spawn is never
     blocked by a settings problem; print a one-line note on the corrupt case).
     **`${` value guard (critic MF-2):** SKIP (with a one-line printed note) any
     value that, after str-coercion, contains `${` — the daemon's
     `expandEnvironmentVariables` hard-rejects the whole spawn on an unresolved
     `${...}` reference, so forwarding such a value would loudly block ALL
     pm/issue/campaign spawns fleet-wide (watcher respawns loop-fail; the #685
     class). Skipping preserves today's behavior for that key (daemon-env
     inheritance) instead of breaking spawns.
   - New helper `_merge_settings_env(body: dict) -> None`: merge the overrides
     into `body["environmentVariables"]` (creating the dict if absent) with
     EXPLICIT payload keys taking precedence (settings values never clobber
     `HAPPY_INITIAL_*` / `EPM_*` / any key already present).
   - Call `_merge_settings_env(body)` immediately before `post("/spawn-session",
     body)` in ALL THREE spawn paths (grep-exhaustive, critic-verified):
     `_spawn_issue_session` (~L2293 — covers BOTH the prompt-bearing `--auto`
     branch and the bare branch, which today sets no `environmentVariables` at
     all), `cmd_spawn_campaign` (~L2481), `cmd_spawn_pm` (~L1992).
2. **`tests/test_spawn_session_env_forwarding.py`** (new): two test layers —
   *Helper-unit tests* (monkeypatched settings path / injected reader):
   (a) only `CLAUDE_CODE_*` keys forwarded; (b) explicit payload keys win on
   collision; (c) missing/corrupt/non-dict settings → `{}`, no raise; (d) values
   coerced to `str`; (e) bare body (no `environmentVariables`) gains the dict;
   (f) a `${FOO}`-bearing value is excluded from the returned dict (MF-2 guard).
   *Per-path composed-body tests (critic MF-1 — AC1 becomes a gate, not prose):*
   monkeypatch `post` (plus the patch-guard / lease / registration / daemon-state
   seams as needed) and invoke each of the THREE composition paths
   (`_spawn_issue_session` prompt branch, `cmd_spawn_campaign`, `cmd_spawn_pm`;
   parametrized), asserting the captured POST body's `environmentVariables`
   contains the forwarded settings keys AND retains its explicit keys
   (`HAPPY_INITIAL_PROMPT` on the prompt-bearing branches). A missed/regressed
   call site then fails a test instead of silently dropping env delivery — the
   exact silent-absence signature of this incident.
3. **`.claude/rules/gotchas.md`** § reduced-window (Class 1): append the verified
   delivery path — the window binds ONLY via exec-time process env; daemon-spawned
   children inherit the daemon's env, so a settings-env edit does not reach them
   until the daemon restarts (0d005b55: settings var present at session start,
   thrashed 242–275K for ~20h); as of #2110 `spawn_session.py` forwards settings
   `CLAUDE_CODE_*` env through the spawn payload — which the daemon merges OVER
   its own env into the child (`index-BmZ4or3w.mjs` L5761-5763 spread order,
   L5922-5925 `{...process.env, ...extraEnv}`) — so daemon vintage no longer
   matters for spawned sessions; manually-started (tmux) sessions and the daemon
   itself still want a restart after a settings-env edit.
