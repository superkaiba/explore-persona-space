# Plan — issue #2302 (workflow-fix, `kind: infra`)

**Title:** Base-identity filter so main's own sibling files stop counting as branch changes
at the Step 9c selector and compare.

## 1. Goal (restated from the task body)

Stop the Step 5a sibling-file spec sync (#1972) from converting a PRE-EXISTING,
order-dependent test failure on `origin/main` into a blocking `new` node at the Step 9c
compare, and stop the same sync from inflating the gate set.

## 2. Root cause (verified at file:line, not inferred from the body)

One predicate is wrong, and both reported symptoms fall out of it.

`select_step9c_tests.compute_touched` (`scripts/select_step9c_tests.py:1235-1262`) returns
`git diff --name-only <base>...HEAD` — the paths that differ between
`merge-base(base, HEAD)` and `HEAD`. That set conflates two disjoint classes:

- **(A) genuinely branch-authored paths** — content at `HEAD` differs from content at the
  `base` TIP. Landing the branch changes these paths.
- **(B) base-identical paths** — content at `HEAD` is byte-identical to the `base` tip. They
  appear in the three-dot diff only because they differ from the OLDER merge-base. Landing
  the branch changes nothing at these paths.

The Step 5a sibling arm manufactures class B by construction: it copies `origin/main`'s
CURRENT `scripts/issue<M>_*.py` / `tests/test_issue<M>_*.py` content into the branch and
commits it (#2296's sync commit `990ec0948d`, 17 files).

Two consumers then misread class B as class A:

1. **The compare's carve-out is disabled.** `step9c_baseline.py:2263` sets
   `touched_set = set(ctx.touched)`; `_paired_collection_reason` (line 1921) returns
   `"file-in-branch-diff"` at line 1941-1942 for any node whose file is in it, and
   `_paired_skip_to_new` (line 1907) keeps the node in `ctx.new` — blocking. The
   docstring's own rationale for precondition 1 is *"main's copy of it is not the thing
   that failed"*; for a class-B path main's copy IS exactly what ran, so the precondition
   is being applied against its stated intent.
2. **The gate set inflates.** The same `touched` list sizes the selector's gate set, so
   main's sibling tests are SELECTED: #2296 measured 61 invariant files → 217 files and a
   ~18-min median wall → `6396.64s (1:46:36)`.

## 3. Chosen fix, and why over the body's three candidate shapes

**Chosen: a base-identity filter** — treat a path as branch-touched only when its content
at `HEAD` differs from its content at the `base` tip.

Rejected, with reasons:

- **(a) record the synced path set (sidecar / commit-subject token).** Requires building a
  NEW provenance channel: verified during clarification that no production code reads the
  sync-commit anchor (`grep -rn "sync workflow-surface specs from" --include=*.py scripts/
  src/ tests/` matches only prose-pin tests) and `.claude/cache/` holds no synced-path
  sidecar. A provenance channel is also strictly weaker than content: it covers only paths
  written by THIS arm, and it goes stale if a synced path is later branch-edited (the
  sidecar would still name it, opening exactly the hole criterion 2 guards against).
- **(b) widen the #2206/#2208 revert arm to RUN-time failures.** Reverting a synced sibling
  on a RUN-time failure would DELETE the freshness the sync exists to provide, and it
  cannot fire until the failure has already cost the full gate wall. It also inverts the
  causality: nothing is wrong with the synced file — the wrong thing is how the compare
  classifies it.
- **(c) exclude sibling-synced paths from the selector's gate set only.** Fixes the
  inflation, not the classification: a sibling test can still be co-selected through the
  `WORKFLOW_INVARIANT`, glob-scan, or import-map arms and then false-block.

Why content-identity is the right signal:

- **It is provenance-independent.** It classifies correctly however the content arrived —
  the sync arm, a manual copy, a revert-to-main.
- **It cannot widen the carve-out into a hole (criterion 2).** A genuinely branch-authored
  regression differs from main by definition, so its blob OIDs differ, so it stays
  branch-touched and still classifies `new`.
- **The pristine oracle is the second, independent guard.** Even when the carve-out DOES
  fire, #2024 still requires the failure to REPRODUCE on pristine main under its
  co-selected predecessors. A cross-file regression genuinely caused by the branch's own
  payload does not reproduce there, so it stays blocking. Criterion 2 is protected by two
  independent mechanisms, not one.

## 4. Change set

Four changes. Every one is on the workflow surface; no experiment code, no GPU.

**Change 1 — `scripts/select_step9c_tests.py`: filter `compute_touched`.**

Keep the public signature (`compute_touched(base, work_root, _runner=None) -> list[str]`)
and its three-dot semantics as the CANDIDATE set, then subtract base-identical paths:

- candidates for exclusion = `three_dot − two_dot`, where `two_dot` is
  `git diff --name-only <base> HEAD` (same flags as the three-dot call, so rename
  heuristics cannot make the two lists asymmetric in a way that drops a real change);
- **verify every exclusion candidate by blob OID before excluding it** — one batched
  `git cat-file --batch-check` over `HEAD:<p>` and `<base>:<p>`; a path is excluded ONLY
  when both OIDs resolve AND are equal. Any resolution failure (path absent on `base`,
  branch-new file) keeps the path as touched. Fail-closed: an unresolvable or ambiguous
  path is always treated as branch-authored.
- add `compute_base_identical(base, work_root, _runner=None) -> list[str]` returning the
  verified-excluded set, and emit it in the selector's JSON as `base_identical_excluded`.
  The exclusion is never silent — same discipline as the selector's existing
  `untested_touched` / `missing_invariants` reporting.

The two-dot pass is a cheap pre-filter (2 git calls) so the exact blob check runs over the
handful of candidates (17 in the #2296 case), not over all 217 paths.

**Change 2 — `scripts/step9c_baseline.py`: compute base-identity in the COMPARE, not only
in the selector.** This is load-bearing, not redundant. `_selector_context` (line 1639-1670)
loads the **worktree's** selector, and the code already contemplates deliberate selector
version skew (line 1668, #1022 §3.3). A branch cut BEFORE this fix carries the OLD
`compute_touched`, so relying on Change 1 alone would leave every in-flight branch broken.
The compare therefore derives its own base-identical set (same two-dot + blob-verify
recipe), subtracts it in `_paired_collection_reason`'s precondition 1, records it on
`_CompareCtx`, and emits `base_identical_files` in the compare JSON beside the existing
`paired_skipped` / `pristine_files_run` audit keys. `_paired_collection_reason`'s docstring
is corrected to state precondition 1 as *"the file's content at HEAD differs from its
content at the base tip"* rather than *"the branch diff for its file is empty"*.

**Change 3 — regression fixtures (acceptance criterion 3).** A synthetic git tree, built in
a tmp_path, reproducing #2296's exact shape:

- base repo commits `sib.py` + `test_sib.py`; branch cut; `main` advances both; the branch
  writes main's CURRENT content in and commits it (byte-identical to the base tip) →
  the path is in the three-dot diff, absent from the two-dot diff, blob-equal to base.
  Assert: `compute_touched` excludes it, `compute_base_identical` names it, and a node in
  that file classifies **non-blocking** (`ordering_suspect`, not `new`).
- the **same** path branch-EDITED so its content differs from the base tip. Assert: it stays
  in `compute_touched`, is absent from `compute_base_identical`, and a failing node in it
  classifies **blocking** (`new`). This is criterion 2's positive control.
- unit coverage for the fail-closed arms: path absent on `base` (branch-new) stays touched;
  a blob-check resolution failure stays touched.

Per `.claude/rules/code-style.md` § one-production-body-test-per-seam-stubbed-function: the
git-invoking helpers get at least one test that EXECUTES the real body against a real tmp
git repo, not only `_runner`-injected fakes.

The fail-closed arms are pinned by committed tests, not by a review-time grep. Two negative
controls, each asserting the exclusion does NOT happen rather than merely that it can:

Fail-loud pin: tests/test_step9c_base_identity.py

test_base_identical_excludes_nothing_when_blob_check_unresolvable asserts the path stays in compute_touched when a blob OID fails to resolve, so an unresolvable path is never silently swallowed into the excluded set, and test_branch_edited_sibling_still_classifies_new asserts a content-differing path is absent from compute_base_identical and its failing node stays blocking.

**Change 4 — documentation of the invariant.** `.claude/skills/issue/SKILL.md`: state at the
Step 5a sibling-sync arm that synced paths are base-identical BY CONSTRUCTION and therefore
never count as branch changes downstream, and at the Step 9c compare that precondition 1 is
a content test. This is where the next reader of either surface looks; leaving the
invariant only in code is how #1972 and #2024 came to contradict each other silently.

## 7. Risks + how each is bounded

- **Coverage loss from a smaller gate set.** Excluded paths hold main's own content, which
  main's own gate already covers; `WORKFLOW_INVARIANT` remains unconditional; and a genuine
  cross-file regression is still selected through the import-map / glob-scan arms keyed on
  the branch's REAL payload. Bounded by Change 1's `base_identical_excluded` reporting —
  the shrinkage is always visible, never silent.
- **Rename-heuristic asymmetry between the two diffs.** Bounded by the blob-OID verification
  gate: the two-dot pass only proposes candidates; nothing is excluded without an exact
  content match.
- **Selector version skew on in-flight branches.** Bounded by Change 2 (the compare computes
  base-identity itself).
- **Fleet-wide blast radius.** `compute_touched` feeds gate-set derivation, `untested_touched`
  WARNs, and `lint_verdict`. The change makes all three MORE correct (a base-identical path
  is not the branch's to lint or cover), and no-flags `workflow_lint.py` plus the mapped
  tests run before the payload lands.
