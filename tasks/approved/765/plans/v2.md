```python
def check_judge_model_pins(
    *, scripts_dir: Path | None = None, src_dir: Path | None = None,
    tests_dir: Path | None = None,
) -> list[str]:
    """Walk scripts/**/*.py, scripts/**/*.sh, src/explore_persona_space/**/*.py,
    tests/**/*.py and FAIL on a hardcoded non-Sonnet judge-model pin at a judge
    call site.

    A forbidden substring (JUDGE_PIN_FORBIDDEN_SUBSTRINGS) on a NON-COMMENT line
    is a HIT iff one of:
      (a) the line matches JUDGE_PIN_VAR_RE (RHS of a judge-named assignment/key);
      (b) the line matches JUDGE_PIN_FLAG_RE (--judge-model / judge_model= /
          JUDGE_MODEL= CLI/shell arg) — covers .py argparse defaults AND .sh;
      (c) the line carries a `model=`/`model:` kwarg AND a JUDGE_PIN_CALL_TOKEN
          appears within +/- JUDGE_PIN_CONTEXT_WINDOW non-comment lines.
    A bare mention of a forbidden substring inside a descriptive string or a
    comment (no judge-named assignment / --judge-model flag on the line) is NOT
    a hit (the prose-mention guard — issue552_gate_decision.py:83,
    issue467_figures.py:176, gen_data_appendix.py:212).
    The canonical pin claude-sonnet-4-5-20250929 contains NO forbidden substring
    (it is claude-sonnet-4-5-..., NOT claude-3-5-sonnet) so it never matches —
    asserted in a test.

    Exempt: JUDGE_PIN_FILE_ALLOWLIST (whole file), JUDGE_PIN_LEGACY_ALLOWLIST
    (.py grandfathered relative path), JUDGE_PIN_LEGACY_ALLOWLIST_SH (.sh
    grandfathered relative path), a file-level '# epm-allow-judge-model-pin'
    comment, a per-line '# noqa: judge-model-pin' on the hit line or the
    immediately preceding non-blank line. One error line per hit:
      "<file>:<lineno>: hardcoded non-Sonnet judge pin '<match>' at a judge call
       site. fix: use claude-sonnet-4-5-20250929 (or waive a calibration control
       with '# noqa: judge-model-pin')."
    Exit non-zero on any hit. scripts_dir/src_dir/tests_dir are unit-test override
    hooks. Bundled into the no-flags default run.
    """
```

Implementation notes for the implementer:
- **LINE-based scan, not AST** — judge pins appear as string literals, argparse
  defaults, AND `.sh` `--judge-model` arg lines, and the gate is line-shape +
  proximity. `check_batch_judge_client` is AST (it matches a call attribute chain);
  this check matches an assignment/flag/call shape, so a line scanner is the right tool
  (closer to `check_heredoc_dotenv` / `check_dispatcher_cvd_pin`, which are line
  scanners).
- **Assignment/call-aware, NOT mention-aware (the round-2 must-fix).** The gate fires
  on (a) `JUDGE_PIN_VAR_RE` (judge-named assignment), (b) `JUDGE_PIN_FLAG_RE`
  (`--judge-model` / `judge_model=` / `JUDGE_MODEL=`), or (c) a `model=` kwarg with a
  judge-call token in the ±3-line non-comment window. A bare forbidden substring inside
  a descriptive string or a comment is NOT a hit. This is what keeps
  `issue552_gate_decision.py:83`, `issue467_figures.py:176`, `gen_data_appendix.py:212`,
  `issue623_behavioral_dv.py:6`, `generate_issue356_data.py:103`, and the SDF
  generation `messages.create(model=...)` calls from false-firing — they are prose
  strings, comments, or non-judge `model=` calls.
- **Comment lines are never hits** — `line.lstrip().startswith("#")` short-circuits (for
  both `.py` and `.sh`). This is belt-and-suspenders with the assignment gate (a
  comment is not an assignment) but makes the `.sh` banner-string / `#`-doc mentions
  (e.g. `run_issue552_sweep.sh:15`) unambiguously skipped.
- **`.sh` scope** — the walk includes `scripts/**/*.sh`; `.sh` lines fire only on
  `JUDGE_PIN_FLAG_RE` (the `--judge-model` form). The four legitimate `.sh` launchers
  are grandfathered by `JUDGE_PIN_LEGACY_ALLOWLIST_SH`. Canonical-Sonnet `.sh` lines
  pass (no forbidden substring).
- **Canonical-pin safety:** `claude-sonnet-4-5-20250929` contains none of the forbidden
  substrings (it is `claude-sonnet-4-5-...`, NOT `claude-3-5-sonnet`), so it never
  matches. A test must assert this (the inverted-order `claude-3-5-sonnet` vs the
  canonical `claude-sonnet-4-5` is the trap — guard it explicitly).
- **Relative-path resolution:** reuse `check_batch_judge_client`'s
  `py.resolve().relative_to(_REPO_ROOT.resolve()).as_posix()` + the `ValueError`
  fallback for unit-test fixture trees outside the repo (so `tests_dir=tmp_path` works).
  For the file allowlist + both legacy allowlists, match by EXACT relative POSIX path
  (so a tmp_path fixture named e.g. `judges.py` is NOT accidentally allowlisted — the
  allowlist match is on the full relative path, and tmp fixtures fall outside it).
- **Waiver helper:** reuse the existing waiver-on-line-or-preceding-line pattern (see
  `_batch_judge_client_waiver_present` / the dotenv waiver) — `# noqa: judge-model-pin`
  needs no min-reason (it's a standard noqa form); the file-level
  `# epm-allow-judge-model-pin` is a presence check anywhere in the file.

**Wire into `main()`:**
1. Add the `parser.add_argument("--check-judge-model-pins", action="store_true", help=...)`
   block (after `--check-lessons-index`, before `args = parser.parse_args(argv)`).
2. Add `or args.check_judge_model_pins` to the `no_flags = not (...)` tuple.
3. Add `if args.check_judge_model_pins or no_flags: errors.extend(check_judge_model_pins())`
   in the dispatch ladder (next to the other `or no_flags` checks).
4. Add the module docstring bullet at the top (the `* ``--check-judge-model-pins`` ...`
   list, matching the existing format).

**Test file** — NEW `tests/test_workflow_lint_judge_model_check.py` (one-test-file-per-
subcheck precedent, e.g. `test_workflow_lint_dotenv_check.py`). Required cases:
- (a) a clean file with the canonical `JUDGE_MODEL = "claude-sonnet-4-5-20250929"` PASSES.
- (b) `judge_model = "claude-haiku-4-5-20251001"` FAILS (var-name arm); error names file:line
  + match + the fix hint.
- (c) `--judge-model gpt-4o-2024-08-06` on an argparse `default=` line FAILS (flag arm).
- (d) a `.sh` fixture line `--judge-model gpt-4o-2024-08-06` FAILS (the `.sh` flag arm —

- (e) `gpt-4o-2024-08-06` inside a descriptive string `rule = "...judge gpt-4o..."` with

  issue552/issue467 false-positive class).

- (g) a non-judge `client.messages.create(model="claude-haiku-4-5-20251001")` with NO
