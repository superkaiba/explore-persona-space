```python
# The narrowest observed install TRANSITION is ~12 optimizer steps WIDE, with
# observed install ONSET at ~step 18-30 (marker-training-recipe.md § Multi-arm
# resolution-band designs, #533/#547). 12 steps is therefore a NECESSARY floor —
# a cell below it cannot even traverse an install transition — never an install
# point: cells clearing it may still be untrained (necessary, not sufficient).
DEFAULT_MIN_OPTIMIZER_STEPS = 12


class CellTrainabilityError(DatagenYieldError):
    """Realized rows cannot sustain the minimum optimizer steps (loud, names the arithmetic).

    Carries the full report record as ``.record`` so a catching builder (the DROP
    disposition) or a diagnostic consumer never re-parses the message string.
    """


def trainability_floor_rows(
    *,
    effective_batch_size: int,
    num_epochs: float,
    min_optimizer_steps: int = DEFAULT_MIN_OPTIMIZER_STEPS,
) -> int:
    """ceil(min_optimizer_steps * effective_batch_size / num_epochs); validates args > 0."""


def assert_cell_trainable(
    n_rows: int,
    *,
    cell_id: str,
    effective_batch_size: int,
    num_epochs: float,
    min_optimizer_steps: int = DEFAULT_MIN_OPTIMIZER_STEPS,
    override_floor_rows: int | None = None,
    override_reason: str | None = None,
    on_fail: str = "raise",  # "raise" (production) | "warn" (smoke demotion)
) -> dict:
    """Absolute per-cell trainability gate — call at the row-counting site, pre-GPU/judge.

    Returns the report record {cell_id, n_rows, floor_rows, passed, min_optimizer_steps,
    effective_batch_size, num_epochs, override_reason} for the mix report/manifest.
    Below floor: on_fail="raise" raises CellTrainabilityError (message names n_rows,
    floor_rows, and the realized optimizer-step arithmetic, per the DatagenYieldError
    message style at L1554; the record rides the exception as ``.record``);
    on_fail="warn" — the GATE-CALIBRATION smoke demotion (gotchas.md) — logs the failed
    verdict at WARNING and RETURNS the record (passed=False) instead of raising.
    Raises ValueError on override_floor_rows without a non-empty override_reason
    (an override is a recorded decision, never silent) and on an unknown on_fail.
    """
```

### 11. Decision rationale (Source lines)

- **`DEFAULT_MIN_OPTIMIZER_STEPS = 12`** — What: the default absolute floor, in optimizer steps. Why: install strength is denominated in steps, not rows; the narrowest install TRANSITION ever observed in this project is ~12 steps WIDE (observed install ONSET ~step 18-30), so a cell that cannot sustain 12 steps cannot even traverse an install transition — the precise meaning of "structurally not a condition"; 12 is a necessary floor, never an install point. Source: `.claude/rules/marker-training-recipe.md` § Multi-arm resolution-band designs (#533/#547 — ~12-step transition between ~step 18 and ~step 30, 30-step all-arm anchor; #546 — steps dominate rank). Alternatives: 30 steps (the demonstrated all-arm install anchor) — rejected as the DEFAULT because the floor's contract is necessary-not-sufficient (a 30-step default would mandate dropping cells that might legitimately be dose-ladder rungs); the rule text instead directs behavior-specific upward derivation. A bare row count (e.g. keep 32) — rejected: not recipe-transferable, and 32 is itself below threshold (next line).
- **Superseding `MIX_MIN_ROWS_PER_CELL = 32`** — Yes, superseded. At #2221's own recipe (effective batch 16 = `PER_DEVICE_BATCH=2 × GRAD_ACCUM=8`, `scripts/issue778_finetune.py:54-55`, reused verbatim per the `constants.py` comment; 1 epoch), 32 rows ≈ **2 optimizer steps** (the clarifier's batch-8 reading gives 4) — either reading sits far below the ~12-step transition, i.e. the existing constant was itself below the install threshold. The derived default at that recipe is `ceil(12×16/1) = 192` rows. Source: issue778_finetune.py L53-55 (read this session) + `/tmp/issue-2242-clarify-v1.md`.
- **Floor formula `rows ≥ steps × batch / epochs`** — Source: task #2242 body + clarifier derivation instruction; step denomination from #533/#547.
- **DROP disposition + denominator revision + Takeaways naming** — Source: `.claude/rules/on-policy-completions.md` ("a source below the floor is DROPPED … and the drop is REPORTED as a finding") + `.claude/rules/after-every-experiment.md` item 8 (planned-vs-actual: name the missing condition, revise the denominator, never a zero bar).
- **Placement (shared helper in `datagen.py` + the D11 assert at the incident path's dataset-load site)** — Source: `marker-training-recipe.md` § Training-row token budget ("gate the mix at BUILD time, never discover it at train time"; shared-helper shape `organisms.enforce_mix_token_budget`, organisms.py:410) + the `DatagenYieldError` row-counting-site precedent (datagen.py:1547) + `issue2054_phase_a.py:1530-1541` (a below-floor verdict a registered gate consumes).
