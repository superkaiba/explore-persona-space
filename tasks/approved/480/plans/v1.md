# Plan — Task #480: Does marker leakage predict sycophancy leakage? (payload-swap of #411's rig)

## 0.0 TL;DR (plain English)

- **What I'll run:** I'll retrain the exact same 6 source personas on the exact same 23-bystander panel as my last sycophancy experiment (#411), but instead of teaching them to agree with wrong claims, I'll teach them to emit a single weird character (`※`) at the very end of their answer. Same questions, same panel, same training shape, same seed — only the thing being taught changes. Then I'll check whether the cells where the marker leaks to a bystander are the same cells where sycophancy leaked.

The marker-vs-sycophancy correlation across the 138 cells is the more uncertain one — #99's qualitative hint says behaviors leak with different breadths, so I'm betting against a strong cross-payload correlation (maybe a weak positive once we control for source). The honest framing is "marker is the geometric, cheap-to-measure twin; whether it proxies behavioral leakage is what we're testing."
- **What would change my mind:** If the marker DV saturates (every cell at the ceiling) and we have no dynamic range to correlate, that kills the experiment for a hyperparameter reason, not a science reason — I'll switch the DV to full-vocab KL at the same slot. If marker leakage and sycophancy leakage genuinely line up cell-for-cell with source FE controlled, that's a strong positive that we have a cheap, judge-free, distance-predictable proxy for behavioral leakage — which would be a big deal for the predictor line.

## 3. Hypothesis

### H1 (proxy)
**Per-cell marker-leakage Δ correlates positively with #411's per-cell sycophancy-leakage Δ across the 138 matched (source, bystander) cells, with source fixed effects controlled.**

**Quantitative thresholds (mirror #470's exact stat package):**
- **Cell-level Spearman ρ(marker-Δ, sycophancy-Δ) | source FE residualized**, bootstrap n=10000 over the 138 cells, permutation n=10000 over source-stratified labels.
- **Supported** if source-FE-residualized ρ has 95% CI that excludes 0 AND ρ_point ≥ +0.20.
- **Falsified** if source-FE-residualized ρ_point < +0.10 AND 95% CI includes 0.
- **Inconclusive** otherwise (the noise-limited zone given the floored target).

**Source-level cross-payload correlation (secondary, n=6):** Pearson + Spearman of per-source mean(marker-Δ) vs per-source mean(sycophancy-Δ). Underpowered at n=6; report point estimate + 95% bootstrap CI; flag as descriptive.

### H2 (behavior-type/geometry)
**The marker shows the within-source layer-20 cosine gradient MORE STRONGLY than sycophancy did on the same 6×23 panel — tested as a quantitative paired comparison, NOT a binary "gradient present vs absent".**

**The #411 sycophancy reference, stated accurately (CORRECTED — the v1 draft mis-stated this).** #411's *per-source within-source* cosine-gradient test (the same test H2 runs for the marker) had **3 of 6 sources nominally significant**: villain ρ=+0.438 (p=0.036), comedian ρ=+0.445 (p=0.035), kindergarten_teacher ρ=+0.571 (p=0.006). BUT #470's clean-result judged all three to be **noise-floor artifacts** — they are exactly the sources whose bystander sycophancy-Δ is floor-pinned (std 0.011–0.025), so their rank order over 23 near-zero cells is dominated by measurement noise; meanwhile the two sources with real bystander signal (assistant, software_engineer) did NOT show the gradient and software_engineer's per-source ρ was *negative* (−0.34). The "0 of 6" figure in the v1 draft was #470's **pooled-138 source-FE** statistic (cosine ρ=+0.14, p=0.09) — a DIFFERENT test from the per-source one H2 uses. The honest #411 reference is therefore: *per-source 3/6 nominal but artifactual; pooled source-FE +0.14 n.s.; no gradient on the real-signal sources.*

**Quantitative thresholds (paired, power-aware):**
- **Per-source Spearman ρ(cosine_l20_baseline, marker-Δ)** over the 23 bystanders per source. Bootstrap n=10000, permutation n=10000. Report alongside each source's **cosine dynamic range (std)** — comedian's cosine span is ~0.08 vs software_engineer's ~0.23, so a low comedian ρ may be a cosine-range-compression artifact, not an absent gradient.
- **Marker gradient descriptively present** if ≥4 of 6 sources reach |ρ_point|≥0.40 with 95% CI excluding 0 (a description of the marker run, NOT yet the differential claim).
- **Headline differential claim = the PAIRED test, power-matched.** Compute, per source, Δρ = ρ_marker(cosine, marker-Δ) − ρ_syco(cosine, sycophancy-Δ) using #411's frozen per-source sycophancy ρ; aggregate with a paired bootstrap + Wilcoxon signed-rank over the 6 sources. **The differential is "behavior-type determines geometry-sensitivity" ONLY if it survives the power-matched comparison in §6** (degrade marker-Δ per source to the sycophancy DV's per-source SNR, OR apply noise-tolerant ranking to sycophancy; see §6). If the differential vanishes under power-matching, the correct conclusion is "the marker DV simply has the dynamic range to express a gradient that the floored sycophancy DV cannot," NOT a behavior-type effect — this is the alternative the analyzer must rule out before any behavior-type headline.

## 4. Design

### Single-variable contract — what is held constant vs what the payload swap entails (honest accounting)

The "single variable vs #411" is **the implanted payload**. Holding the payload swap as the one manipulated variable means the following are inherited **bit-for-bit**: the 6 sources, the 23-bystander eval panel, the 2-bystander training sampler (SHA-256 seeded, same assignments), the wrong-claim Q pool (200 train / 50 eval), lr / r / α / batch / epochs / schedule / seq-len / seed. The frozen #411 sycophancy-Δ and #470 layer-20 cosine are reused, not recomputed.

But swapping the payload **mechanically entails** two changes that are NOT independent free variables — they ARE the payload swap, and the plan states them openly rather than hiding them under "inherited":

1. **A new on-policy R-generation step (Phase 0).** #411 has no on-policy R: its positive rows are canned `sycophancy_template` agreement strings and its bystander-negative rows are canned wrong-claim corrections. The marker recipe (`.claude/rules/marker-leakage-measurement.md`) requires the marker to be appended after an on-policy *greedy frozen* base response, so #480 must generate fresh base R under each persona on the same Q pool. This is a NEW component (modeled on the #460/#474 marker rig), not inherited from #411.
2. **A different loss surface.** #411 trained full SFT on the canned completion; #480 trains marker-only loss (`MarkerOnlyDataCollator(tail_tokens=0, suppress_at_post_response_slot=True)`) — positives carry loss on the marker+EOS, negatives on the post-response `<|im_end|>` slot. This is the marker payload's definition, not an extra knob.

Consequence for interpretation: the 138 cells are matched on (source, bystander, question pool, panel, geometry), so H1's cross-payload correlation and H2's geometry test are well-posed. What is NOT identical is the training *content* the LoRA saw (canned sycophancy text vs on-policy R + marker) — but that difference IS the payload being compared, so it is the intended contrast, not a confound. The consistency-checker should read the single variable as "payload (sycophancy → marker), with the R-source and loss-surface changes that the payload definitionally requires."

### Why code, not a model call?

The marker DV is a teacher-forced log-prob extraction at a specific token position from a forward pass — there is no unstructured text to classify; the answer comes from `logits.log_softmax(dim=-1).gather(token_id)` at a known slot. No alternative model-call formulation applies. The judge-free design is one of the marker payload's load-bearing advantages over the sycophancy payload (no Haiku/Sonnet judging cost).

The analysis layer (Spearman / bootstrap / permutation / source-FE residualization) is standard statsmodels + scipy. No classifier or summarizer needed.

### Saturation guard (load-bearing)

Per `.claude/rules/contrastive-negatives.md` saturation guard + #448:
1. **WandB logging during training:** log `log_p_source_marker_trajectory` (the post-response-slot marker log-prob under the source persona on Q_train) every 10 training steps via `M5_AT_END_CALLBACK` (similar to #474's `NegRowSuppressionDifficultyCallback`).
2. **Live monitor (during training, in dispatcher):** if mean source-cell log-prob crosses -2.0 nats BEFORE the 3rd epoch starts, the dispatcher: (a) saves the adapter at that step, (b) logs `epm:saturation-detected v1` with the trajectory, (c) continues training to 3 epochs but flags the cell for the saturation fallback in Phase 3 analysis. If saturation is detected on >=2 of the 6 sources by the end of training, the dispatcher AUTOMATICALLY runs Phase 2 with the secondary DV (full-vocab KL top-K=1000 at post-response slot) IN PARALLEL with the primary marker log-prob DV — both go to JSON. **CONSTRAINT (per Statistics-Codex Must-Fix): the KL DV is a DIAGNOSTIC, not a drop-in replacement for the marker DV.** Full-vocab KL-from-base measures general post-response distributional drift, which is a DIFFERENT construct from marker-emission propensity (H1/H2 are about ` ※` leakage specifically). The analyzer does NOT silently swap KL in as the "primary" DV. If the marker log-prob DV saturates with no usable dynamic range on a cell, the marker H1/H2 for that cell/source is reported as **uninterpretable (saturated)**, NOT re-derived from KL. The KL DV may be reported only as a clearly-labeled separate diagnostic ("distributional drift, not marker emission"), and a KL-based correlation may substitute for the marker-based one ONLY if a validation sub-analysis first shows KL tracks the *unsaturated* marker log-prob/emission on the non-saturated cells (correlation reported in the clean-result). Absent that validation, saturation → "marker DV uninterpretable; rerun under a less-trained anchor" is the honest outcome.
3. **Plan-time hyperparameter:** lr=1e-5 is the value BOTH #411 AND the #460/#474 marker rig used (verified by the fact-checker: `i460_phase23_train.py:254` lr=1e-5, `i474_phase23_train.py:792` lr=1e-5 "Inherited from #460"). There is NO "10× lower than the marker recipe" under-training lever here — lr=1e-5 is simply the convergent value of both lines, which satisfies the single-variable contract with #411 for free. **The saturation guard does NOT rest on the lr choice.** The marker line at lr=1e-5 has previously approached saturation at fully-trained anchors (#448), so the guard is the runtime monitor + secondary-DV auto-fire (steps 1-2 above), not a hyperparameter tweak. If the trajectory monitor shows source-cell log-prob approaching the ceiling, the mitigation is the KL secondary DV, NOT a post-hoc lr reduction (changing lr would break the #411 single-variable contract — see §11 must-ask).

**H1:**
- `cell_spearman_raw`: Spearman ρ over 138 cells (sycophancy-Δ, marker-Δ), bootstrap n=10000 (resample rows), permutation n=10000 (shuffle marker-Δ values).

**H2:**
- `within_source_spearman[<src>]`: Spearman ρ(cosine_l20_baseline, marker-Δ) over 23 bystanders for each of 6 sources, bootstrap n=10000, permutation n=10000. Report `cosine_l20_std[<src>]` alongside each ρ (cosine-range-compression diagnostic).

### Analyzer interpretation guidance (folded in from the Phase-2 critique ensemble — non-blocking concerns)

The analyzer MUST carry these into the clean-result framing (each is recoverable from the diagnostics above; they are not design changes):

1. **H1 reads narrower than the slogan.** The marker LoRA trains on fresh on-policy R while #411 trained on canned sycophancy/correction text (see §4 single-variable accounting). So a positive H1 supports "this marker procedure is an empirical proxy for #411's sycophancy-leakage ordering across matched cells", NOT "marker leakage = a payload-general leakiness mechanism". A weak/null H1 cannot cleanly separate "behaviors have payload-specific leakage breadths" (#99 prior) from "the two training protocols don't load the same susceptibility axis". State this explicitly.
2. **#411's 3/6 per-source sycophancy "gradient" is artifactual.** When narrating H2's differential, say so: the 3 nominally-significant #411 sources are the floored ones (rank order over near-zero cells = noise); the real-signal sources did not show it. Do not present #411 as "0/6" (false) nor as "3/6 genuine gradient" (also false).
3. **H1 signal is concentrated in 2/6 sources (~46 cells).** Report this numerically; do not narrate a 138-cell correlation as if all 138 carried target variance.
4. **Comedian H2 is cosine-range-power-limited** (cosine span ~0.08). If comedian alone fails the per-source bar, attribute it to range compression (report `cosine_l20_std`), not to a comedian-specific absence of gradient.
5. **The behavior-type headline is gated on the power-matched paired test** (`power_matched_paired_delta_rho`). If the marker-vs-sycophancy gradient differential does not survive SNR-matching, the honest headline is "the marker DV has dynamic range the floored sycophancy DV lacks", not "behavior type determines geometry sensitivity".
6. **If the saturation guard fires, the KL DV is a labeled diagnostic, not the marker construct** (§4). Saturation with no marker dynamic range → report uninterpretable, do not swap in KL silently.
7. **Multiple comparisons:** H2 is 6 per-source tests; only `cosine_l20` is tested (no predictor snooping). Account for FWER when claiming H1∧H2 jointly.
