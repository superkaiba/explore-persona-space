# Plan v1 — #2039 daily-fix: inline lint gate defers under high VM load (kind: infra)

## Goal (verbatim from task body)

The inline payload lint gate does not false-block payloads because the shared VM
happened to be at load 30 when the mapped tests ran.

## Incident & evidence

- Auto-filed by /daily 2026-08-02 (route 2) from session a0400dd4 / task #1345
  (fingerprint 517ebd1cb2be). A certified inline-gate run went red under VM
  load1~31 (1 failed + 3 error mapped tests, 8m34s pytest leg) and PASSed clean
  ~35 min later once load dropped, with the payload unchanged; the session
  improvised a load-drop Monitor watch and retried.
- Load-flake hypothesis verification (plan-time duty from the body): the
  pass-on-unchanged-payload-retry pattern is the signature of timing/load flake
  — a content-caused red is deterministic and would have reproduced at low
  load. The durable record (#2039 body; #1345's events.jsonl does not carry the
  gate round — it lived in session a0400dd4's transcript) supports load-flake;
  the exact within-gate exit-3 path is not reconstructable from the durable
  record, so the design below covers the FULL under-load failure surface
  rather than hinging on that reconstruction (see Assumptions A3).
- Gap re-verified current 2026-08-09: `scripts/inline_lint_gate.py` has zero
  load awareness (case-insensitive grep for getloadavg/loadavg/load1 → 0 hits).
- Prior art: #1962's gate-fleet arbitration (`step9c_baseline.py probe
  --fleet`, `EPM_GATE_FLEET_MAX` default 2) is orchestrator-side, PRE-LAUNCH,
  and counts foreign gate TREES only — blind to non-gate VM load (detached
  fits, fleet sessions) and inert once a gate is launched. This fix is
  gate-internal and load-keyed: complementary, not duplicative.

## Design

Fail-direction invariant (from the Goal, binds every item): load awareness may
only convert a would-be false BLOCK (or an opaque INCONCLUSIVE) into a
DISTINCT, self-diagnosing INCONCLUSIVE. It must never create a PASS that would
not have happened otherwise (load cannot make a failing test pass, so a PASS
under load certifies unchanged), and it must never suppress a
deterministic lint-leg block.

- **D1 — load sampling helper.** `_sample_load1() -> float | None`: honor
  `EPM_GATE_LOAD1_OVERRIDE` first (test support, parsed float, mirroring the
  documented `EPM_INLINE_GATE_*_CMD` override pattern; malformed → ignored),
  else `os.getloadavg()[0]`; `OSError`/`AttributeError` → `None` (platform
  without loadavg: the guard is inert and the gate behaves exactly as today).
- **D2 — threshold knob.** `_load_max() -> float | None` reading
  `EPM_GATE_LOAD_MAX`. Default **20.0** (this 32-core VM; incident load1~31;
  the body's proposed ~20). Explicit `0` or negative → disabled (`None`).
  Malformed → default 20.0 (the `EPM_CERT_REHASH_DELAY_S` precedent: malformed
  falls back to default, the guard stays active — fail toward guarded).
  `EPM_GATE_LOAD_MAX=0` is thereby the one-line KILL SWITCH restoring
  pre-#2039 behavior exactly.
- **D3 — bounded pre-pytest-leg wait** (in `run_legs`, only when the mapped
  test set is non-empty AND the threshold is enabled AND sampling works):
  sample load1; if ≥ threshold, poll every 15 s (module constant) up to
  `EPM_GATE_LOAD_WAIT_S` (default 300; malformed → default; `0` → no wait)
  until load1 < threshold, then proceed REGARDLESS of the final sample (a
  PASS under load still certifies; refusing to run would starve quick green
  payloads). Prints one audit line on entering the wait
  (`inline_lint_gate: load-wait load1=<x> >= EPM_GATE_LOAD_MAX=<y>, waiting up
  to <z>s for load to drop`) and one on resume with the post-wait sample.
  Added wall is hard-bounded by `EPM_GATE_LOAD_WAIT_S`.
- **D4 — load samples recorded.** `LegResults` gains
  `load1_pre: float | None = None` and `load1_post: float | None = None`
  (keyword defaults keep every existing construction site and in-process test
  valid). Sampled immediately before (post-wait) and immediately after the
  pytest leg. `load_hot = max(available samples) >= threshold` (no samples /
  disabled → not hot). One unconditional audit line when the threshold is
  enabled: `inline_lint_gate: load1 pre-pytest=<x> post-pytest=<y>
  threshold=<t>` — this makes EVERY under-load verdict (including the
  pre-existing pytest-leg-dead timeout INCONCLUSIVE, the incident's observed
  exit-3 shape) self-diagnosing from the gate's own output with no message
  surgery on existing raise sites.
- **D5 — leg-attributed downgrade in `evaluate()`.** The `combined` line list
  gains per-line leg origin (lint vs pytest — the two lists are concatenated
  today, so this is a tuple-field addition, not a parser change). `Verdict`
  gains `load_deferred: dict[str, list[str]]`. A payload path that would land
  in `blocked` is moved to `load_deferred` IFF (a) EVERY hit line underlying
  its block reasons is pytest-leg, AND (b) `load_hot`. Any lint-leg hit keeps
  the path in `blocked` (lint findings are deterministic, not
  timing-sensitive). The NEW-on-origin/main and conservative
  (unparseable-lineno / ranges-unavailable) branches follow the same rule —
  they key off the same hit lines.
- **D6 — verdict output + exit precedence in `main()`.** `load_deferred`
  paths NEVER certify. Before the terminal lines, print
  `inline_lint_gate: INCONCLUSIVE (pytest-leg red under load — load1=<x> >=
  EPM_GATE_LOAD_MAX=<y>, not payload-attributed; re-run when load drops:
  <paths>)`. Exit precedence: BLOCK (1) when `verdict.blocked` is non-empty;
  else 3 when `load_deferred` or `toctou` is non-empty; else PASS (0). The
  three existing terminal grep shapes (`inline_lint_gate: PASS`,
  `inline_lint_gate: BLOCK (`, `inline_lint_gate: INCONCLUSIVE (`) are
  unchanged — the new reason rides the existing `INCONCLUSIVE (` shape, so no
  consumer grep breaks (#1948 byte-stability note honored).
- **D7 — docstring contract.** The module docstring's verdict-semantics
  section documents the new INCONCLUSIVE-under-load reason and the three env
  knobs (`EPM_GATE_LOAD_MAX`, `EPM_GATE_LOAD_WAIT_S`,
  `EPM_GATE_LOAD1_OVERRIDE` — the last labeled test-support).

## Assumptions

- **A1** — the caller contract for exit 3 is already "no cert; re-run the
  failed leg" (module docstring; CLAUDE.md inline-round rules: a dead/silent
  leg is INCONCLUSIVE, never push-clean). The new reason therefore needs no
  caller-side change: a red-under-load round re-runs the gate when load
  drops, exactly what session a0400dd4 improvised by hand. Confidence: high
  (read from the module docstring + CLAUDE.md § inline payload lint gate).
- **A2** — a genuinely-broken payload under SUSTAINED high load keeps getting
  INCONCLUSIVE-under-load rather than BLOCK. This is the safe direction: exit
  3 never certifies, so the payload cannot ship; the honest BLOCK lands on
  the first re-run below threshold. Stated as a known, accepted residual.
- **A3** — the incident's exact exit-3 code path (which completeness check or
  verdict branch fired under load) is not reconstructable from the durable
  record. The design covers all three under-load shapes: false BLOCK
  (D5/D6 downgrade — the Goal's named risk), dead-leg INCONCLUSIVE (D4 audit
  line makes it self-diagnosing), red-completed tests not naming the payload
  (already PASS today; unaffected). Confidence: high that these exhaust the
  surface — the gate has exactly three verdict classes.
- **A4** — `os.getloadavg()` is available on this Linux VM (POSIX); D1's
  `None` fallback keeps other platforms inert. Confidence: high.
- **A5** — default-ON at 20.0 is safe for the fleet: the gate's existing
  hermetic tests are pinned deterministic by T0 (below), and production gates
  on a loaded VM get strictly-more-diagnosable output, never a new blocking
  state. Confidence: high; kill switch `EPM_GATE_LOAD_MAX=0` covers the miss.

## Test plan

All in `tests/test_inline_lint_gate.py`, reusing the existing hermetic harness
(env-override leg commands + in-process `main()` with monkeypatched
`run_legs`). Load is injected via `EPM_GATE_LOAD1_OVERRIDE` for
subprocess-style runs and by monkeypatching `_sample_load1` for in-process
wait-loop tests (no real sleeps: `time.sleep` recorder, the harness's
existing pattern).

- **T0 (determinism pin — MUST land with the feature commit):** the shared env
  helper pins `EPM_GATE_LOAD_MAX=0` for all pre-existing hermetic tests.
  Without it, every existing red-leg test expecting exit 1 would flake into
  INCONCLUSIVE-under-load whenever the REAL VM load1 ≥ 20 at test time — a
  self-referential load flake in the load-flake fix. Same pin (or an
  implementer-verified n/a) in `test_inline_payload_lint_gate_contract.py`.
- **T1 (regression anchor for the #2039 incident shape):** red pytest leg
  naming the payload path + `EPM_GATE_LOAD1_OVERRIDE=31` +
  `EPM_GATE_LOAD_MAX=20` → rc 3; output contains `pytest-leg red under load`
  and the payload path; NO cert line; cert file unchanged.
- **T2:** same red pytest leg + `EPM_GATE_LOAD1_OVERRIDE=5` → rc 1 BLOCK
  (below-threshold behavior byte-identical to today's).
- **T3:** lint-leg FAIL naming the payload + `EPM_GATE_LOAD1_OVERRIDE=31` →
  rc 1 BLOCK (lint-leg findings are NEVER load-downgraded).
- **T4:** green legs + `EPM_GATE_LOAD1_OVERRIDE=31` → rc 0 PASS + cert written
  (PASS under load certifies).
- **T5 (knob parsing):** `EPM_GATE_LOAD_MAX=0` disables (red pytest leg at
  override 99 → rc 1); malformed `EPM_GATE_LOAD_MAX=abc` → default 20 active
  (red leg at override 31 → rc 3).
- **T6 (bounded wait):** in-process; `_sample_load1` returns a
  high→high→low sequence; recorded sleeps sum ≤ `EPM_GATE_LOAD_WAIT_S`; leg
  proceeds after the drop; `EPM_GATE_LOAD_WAIT_S=0` → zero sleeps, immediate
  proceed.
- **T7 (mixed precedence):** two payload paths — one with a lint-leg hit, one
  with pytest-only hits — under hot load → rc 1 (BLOCK precedence); the
  lint-hit path in the BLOCK list; the pytest-only path in the
  INCONCLUSIVE-under-load line and NOT certified.
- Full existing suite (`uv run pytest tests/test_inline_lint_gate.py -q`)
  green — the 1155-line suite is the no-regression gate for cert/TOCTOU/
  fence-parsing behavior this plan must not disturb.

   Bounded by the gate's own leg timeouts.

Smoke blind-spot enumeration:
- The hermetic tests SUBSTITUTE the production lint/map/pytest invocations via
  the documented `EPM_INLINE_GATE_*_CMD` overrides (pre-existing test-support
  seam, not a new smoke branch) — production leg argv is exercised only by
  smoke item 2.
- The hermetic tests SUBSTITUTE the production `os.getloadavg()` read via
  `EPM_GATE_LOAD1_OVERRIDE` / monkeypatched `_sample_load1` — the real read is
  exercised only by smoke item 2.
- Smoke item 2 will (almost certainly) sample load1 < threshold, so the
  load-wait and downgrade branches are NOT exercised on the live path — they
  are certified by override-injected tests T1/T5/T6/T7 only.
- No `smoke`-conditional branch is added to `inline_lint_gate.py` itself; no
  production gate/assertion is downgraded under any test/smoke flag.

## What would change my mind (revert criterion)

If post-ship the downgrade masks a CONTENT-caused red — i.e. a payload
receives INCONCLUSIVE-under-load and the SAME payload still reds at
load1 < threshold on the bounded re-run (meaning the red was never load
flake and the distinct verdict merely delayed an honest BLOCK by one
re-run cycle) MORE THAN once per week fleet-wide, the threshold default is
wrong or the leg attribution is leaky: set `EPM_GATE_LOAD_MAX=0` fleet-wide
(kill switch, restores pre-#2039 behavior exactly, no revert commit needed
to stop the bleeding) and revert/re-scope the change.

  files → stop and re-scope (the blast radius exceeds the fix).
