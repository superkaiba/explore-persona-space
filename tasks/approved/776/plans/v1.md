## 1. Goal

The autonomous-session watcher's stalled-detector (`scripts/autonomous_session_watch.py`, `decide_session_stalled` + `_process_session_stalled`) uses a 60-minute staleness window (`STALLED_WINDOW_S`, env `EPM_STALLED_WINDOW_MIN`). Legitimately-slow phases — off-pod analysis verifier rounds, in-flight 8h Anthropic Batch polling — emit few `epm:progress` markers, so both staleness signals (self-report age AND newest non-watcher marker age) cross the 60-min window between heartbeats and the detector fires a wasteful auto-respawn. This bit healthy task #761 TWICE (epm:progress v6 "verifying r1" at 19:22 → 1h21m silent off-pod analysis → `session-stalled-alert` at 20:43 → auto-respawn at 20:53 → epm:progress v10 "verifying r2" at 20:57, pure waste) and nearly bit #742's healthy 8h in-flight Batch phase. This fix adds an OPT-IN exemption: a long-running phase stamps the substring `[long-phase-heartbeat]` into its `epm:progress` notes, and the watcher, after `decide_session_stalled` returns a non-`keep` action, downgrades to `keep` when the latest non-watcher heartbeat is younger than a generous freshness window (default 90 min). It does NOT change any emitter (poll_pipeline.py / eval.batch_judge / analyzer drivers are `src/`-level, out of scope) — it only teaches the watcher to recognize the convention, so an emitter that adopts it later gets the longer leash automatically.

## 2. Prior Work

The exemption mechanism is a well-worn house pattern in this exact file. Two existing exemptions run AFTER `decide_session_stalled` returns and rewrite its `(action, new_missed)` tuple to `("keep", 0)`:

### 4.1 The sentinel constant

Add a NEW constant near the sentinel-definition block (anywhere in ~614-846, e.g. right after `_STALLED_EXHAUSTED_NOTE_SENTINEL` at line 675 or just above the `_WATCHER_NOTE_SENTINELS` frozenset at line 851). Distinguish it sharply in the comment from the watcher-self sentinels:

```python
# OPT-IN heartbeat sentinel for legitimately-slow phases (off-pod analyzer
# verifier rounds, in-flight Anthropic Batch polling). UNLIKE every other
# sentinel in this file, this one is stamped by the LONG-RUNNING PHASE
# itself (NOT by the watcher), so it IS real progress and MUST count toward
# _latest_progress_ts / _latest_nonwatcher_event_ts — i.e. it is the INVERSE
# of _WATCHER_NOTE_SENTINELS and is deliberately NOT a member of that set.
# An emitter that includes this substring in its epm:progress note opts into
# the longer stalled-detector leash (see _long_phase_heartbeat_reason). The
# watcher only RECOGNIZES the convention; teaching emitters to stamp it is
# separate, src/-level work (out of this fix's scope).
_LONG_PHASE_HEARTBEAT_PREFIX = "[long-phase-heartbeat]"
```

> The name uses `_PREFIX` (not `_NOTE_SENTINEL`) deliberately, to signal it is NOT in the watcher-self sentinel family and to read naturally at the line-prefix call site. Matching is by SUBSTRING (`in`), consistent with every other note-sentinel check in the file (`any(sentinel in note ...)`) — the term "prefix" describes the *intended emitter convention* (emitters put it at the front of the note), not a `str.startswith` match; substring matching is more robust to an emitter that prepends a `epm:progress vN` stamp before the sentinel.

### 4.2 The freshness-window env knob

Add the env-knob recipe mirroring `_stalled_window_s` (lines 938-952), placed adjacent to it:

```python
# Freshness window for the long-phase-heartbeat exemption. Generous so an
# emitter that heartbeats roughly hourly (the off-pod analyzer / Batch-poll
# cadence) is ALWAYS inside the window with margin for cron jitter — same
# logic as STALLED_WINDOW_S's "cadence + slack" rationale, one rung wider:
# 90 min = a ~60-min heartbeat cadence + a full extra 30-min slack, so an
# emitter must miss MORE than one heartbeat before the exemption lapses and
# the underlying staleness signals reassert. Env-tunable via
# EPM_LONG_PHASE_HEARTBEAT_FRESH_MIN (minutes); a malformed value falls back
# to the default — a typo'd var must not disable the exemption.
LONG_PHASE_HEARTBEAT_FRESH_S_DEFAULT = 90 * 60


def _long_phase_heartbeat_freshness_s() -> float:
    """Long-phase-heartbeat exemption freshness window in seconds (env
    ``EPM_LONG_PHASE_HEARTBEAT_FRESH_MIN``, minutes; default
    :data:`LONG_PHASE_HEARTBEAT_FRESH_S_DEFAULT`). A malformed env value
    falls back to the default — mirrors :func:`_stalled_window_s`."""
    raw = os.environ.get("EPM_LONG_PHASE_HEARTBEAT_FRESH_MIN")
    if not raw:
        return float(LONG_PHASE_HEARTBEAT_FRESH_S_DEFAULT)
    try:
        return float(raw) * 60.0
    except ValueError:
        return float(LONG_PHASE_HEARTBEAT_FRESH_S_DEFAULT)


LONG_PHASE_HEARTBEAT_FRESH_S = _long_phase_heartbeat_freshness_s()
```

### 4.3 The reason helper

Add near `_latest_progress_ts` (~2263) or near `_provision_in_flight_reason` (~4249). It scans the ALREADY-LOADED `events` list (no I/O), finds the NEWEST `epm:progress` event that is (a) NOT a watcher-self post and (b) carries the heartbeat substring, and returns a reason iff that event's age is below the freshness window:

```python
def _long_phase_heartbeat_reason(events: list[dict], now: float) -> str | None:
    """Human-readable exemption reason when the issue's NEWEST non-watcher
    ``epm:progress`` marker opts into the long-phase-heartbeat leash AND is
    still fresh, else ``None``.

    A legitimately-slow phase (off-pod analyzer verifier rounds, in-flight
    Anthropic Batch polling) emits few markers, so both stalled-detector
    staleness signals expire between its heartbeats and the detector
    false-fires (incident #761: a 1h21m off-pod analysis stretch drew a
    wasted auto-respawn). An emitter opts into a wider leash by stamping
    :data:`_LONG_PHASE_HEARTBEAT_PREFIX` into its ``epm:progress`` note; this
    helper recognizes that opt-in. Pure over already-loaded ``events`` — no
    subprocess, no second read.

    Predicate: among events with ``kind == "epm:progress"`` whose note is NOT
    a watcher-self post (:data:`_WATCHER_NOTE_SENTINELS`) AND whose note
    contains :data:`_LONG_PHASE_HEARTBEAT_PREFIX`, take the newest by ``ts``;
    return a reason iff its age (``now - ts``) is in
    ``[0, LONG_PHASE_HEARTBEAT_FRESH_S)``. A future ``ts`` (negative age,
    clock skew / fake clock) is NOT fresh — never mask a genuinely stalled
    session.
    """
    best_ts: float | None = None
    for ev in events:
        if ev.get("kind") != "epm:progress":
            continue
        note = ev.get("note") or ""
        if any(sentinel in note for sentinel in _WATCHER_NOTE_SENTINELS):
            continue  # a watcher-posted alert — never a real heartbeat
        if _LONG_PHASE_HEARTBEAT_PREFIX not in note:
            continue
        ts = _parse_event_ts(ev.get("ts"))
        if ts is not None and (best_ts is None or ts > best_ts):
            best_ts = ts
    if best_ts is None:
        return None
    age = now - best_ts
    if 0 <= age < LONG_PHASE_HEARTBEAT_FRESH_S:
        return f"fresh long-phase heartbeat ({age / 60:.1f}m old)"
    return None
```

Notes:
- The watcher-self filter (`_WATCHER_NOTE_SENTINELS`) is kept defensively so a watcher post that someday happened to also contain the substring could never self-exempt. The heartbeat itself is NOT added to that set (§4.4).
- Reusing `_parse_event_ts` (line 2250) keeps ts-parsing identical to the rest of the file (`Z`→`+00:00` normalisation).

### 4.4 Do NOT add the sentinel to `_WATCHER_NOTE_SENTINELS`

This is the load-bearing inverse-of-every-other-entry property. A heartbeat is REAL progress (emitted by the long phase, not the watcher), so it MUST count toward `_latest_progress_ts` / `_latest_nonwatcher_event_ts` — otherwise the watcher would (a) keep treating the session as stale on the marker-age signal AND (b) the heartbeat would be useless as a progress signal in every OTHER pass. The exemption is an explicit downgrade keyed on the SAME marker that also counts as progress; that is intentional and correct. The §4.1 comment states this so a future maintainer doesn't "tidily" add it to the frozenset.

## 11. Decision Rationale

This is `kind: infra`; there are no model-training hyperparameters. The load-bearing DESIGN choices and their grounding:

- **What:** freshness window default = 90 min (`LONG_PHASE_HEARTBEAT_FRESH_S_DEFAULT = 90 * 60`).
  **Why (tied to Goal):** the exemption must keep a healthy hourly-heartbeat emitter inside the window with margin for cron jitter; an emitter heartbeating ~every 60 min must miss MORE than one heartbeat before the exemption lapses. 90 min = ~60-min cadence + 30-min slack — one rung wider than `STALLED_WINDOW_S` (60 min) so the exemption is strictly more generous than the staleness window it overrides (otherwise it could lapse before the staleness window even opens, defeating the purpose).
  **Source:** the same "cadence + slack" reasoning recorded for `STALLED_WINDOW_S` at lines 927-934 (`#759`: 45→60 min = 45-min cadence + a full extra 10-min tick of slack). This fix transfers that logic at the heartbeat cadence (~hourly) rather than the cron cadence (~45 min).
  **Alternatives considered:** (a) reuse `STALLED_WINDOW_S` directly (rejected — a heartbeat at exactly the cadence would be flush with the window edge and straddle-able by jitter, the exact `#759` failure mode); (b) a much wider window e.g. 6h (rejected — masks a genuine stall on an opted-in session for too long). 90 min is the minimal generous choice.

- **What:** the sentinel string `[long-phase-heartbeat]`.
  **Why:** a bracketed, lowercased, hyphenated token that reads as a deliberate machine sentinel, is grep-clean against the current repo (zero collisions), and visually matches the file's existing `[autonomous_session_watch:<role>]` family while being distinct from it (no `autonomous_session_watch:` namespace, because this is emitter-stamped, not watcher-stamped).
  **Source:** the existing watcher-self sentinel naming convention (lines 614-846) + the plan-time `grep -rn "long-phase-heartbeat" .` (zero hits).
  **Alternatives considered:** (a) a watcher-namespaced string like `[autonomous_session_watch:long-phase-heartbeat]` (rejected — would misleadingly imply the watcher posts it; emitters post it); (b) an unbracketed token (rejected — higher prose-collision risk).

- **What:** substring (`in`) match, not `str.startswith`.
  **Why:** robust to an emitter that prepends an `epm:progress vN` stamp or other prefix before the sentinel; consistent with every other note-sentinel check in the file (`any(sentinel in note ...)`).
  **Source:** the uniform `in`-based filter in `_latest_progress_ts` (line 2278) and `_WATCHER_NOTE_SENTINELS` consumers.
  **Alternatives considered:** `startswith` (rejected — brittle against a leading version stamp; the `_PREFIX` name describes the intended emitter convention, not the match operator).

- **What:** NOT adding the sentinel to `_WATCHER_NOTE_SENTINELS`.
  **Why:** a heartbeat is REAL progress emitted by the phase, so it must count toward the progress clocks; it is the inverse of every member of that set (which are watcher-self posts that must NOT count).
  **Source:** the `_WATCHER_NOTE_SENTINELS` / `_latest_progress_ts` contract (lines 847-883, 2263-2283).
  **Alternatives:** adding it (rejected — would zero out its value as a progress signal everywhere and the exemption would be the only thing keeping the session alive, fragile).

- **What:** env-knob malformed-fallback recipe.
  **Why:** a typo'd `EPM_LONG_PHASE_HEARTBEAT_FRESH_MIN` must not silently disable the exemption.
  **Source:** verbatim mirror of `_stalled_window_s` (lines 938-949) / the `_orphan_staleness_s` house pattern.
