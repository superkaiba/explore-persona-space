# Plan — #2011 daily-fix: provisioner avoids a known-bad RunPod host on retry

`kind: infra` (workflow-fix; 0 GPU-h). Target files (workflow_fix_target):
`scripts/runpod_api.py`, `scripts/pod.py`, `scripts/pod_lifecycle.py`.

## 1. Requirement + acceptance criteria

**Requirement.** After a fresh provision fails its SSH/bootstrap readiness
probe, record the failed placement's host identity durably, and bias the next
provision attempt for the same issue away from it — at minimum a
different-DC retry hint plus a loud repeat-placement warning — instead of
re-rolling blind onto the same broken host (incident: pod-1947-b, 3
provision+terminate pairs all on host 103.207.149.60, ~2× P2 wall time).

**Verified retry topology (clarifier + plan-time reads).** Retries are
ORCHESTRATOR-driven across process invocations: `_provision_wait_register_bootstrap`
(pod_lifecycle.py:1867) raises on `wait_for_ssh` timeout and `sys.exit`s on
bootstrap failure; the session then terminates and re-runs `pod.py provision`.
So the avoidance record MUST be a durable sidecar, not in-process state.
Additionally, `wait_for_ssh` (runpod_api.py:1059) only polls for the public
22/tcp PORT MAPPING — it never TCP-connects — so the #1947
"RUNNING-but-SSH-refused" class passes `wait_for_ssh` and dies at BOOTSTRAP,
where `ready.ssh_host` is already known. Both failure sites are instrumented.

**Acceptance criteria:**
1. A provision whose SSH-wait times out OR whose bootstrap fails (after the
   #1931 single retry) records the failed placement — host IP when known,
   pod id, pod name, issue, timestamp, DC id when known — to a durable
   sidecar before the process exits, and prints a `[bad-host-RECORD]` line
   naming the host and the retry levers.
2. The next `pod.py provision` for the same issue consumes the sidecar:
   - a fresh (within-TTL) record exists AND the new placement's `ssh_host`
     matches a recorded bad host → loud `[bad-host-REPEAT]` stderr WARN
     naming the host, the prior failure count, and the DC-pin-away recipe.
     WARN-only: never auto-terminate (approval rules), never block.
   - an explicit `--data-center-id` pin matching a recorded bad placement's
     DC (when DC identity was recordable) → loud WARN; the explicit flag
     still wins (explicit user override is honored, never silently dropped).
3. A `--data-center-id <id>` flag exists on `pod.py provision` and threads
   to `create_pod` / `create_cpu_pod` (both already accept the parameter;
   today NO caller passes it — the missing lever).
4. A `get_datacenters()` helper exists in `scripts/runpod_api.py` so the
   failure-path hint can enumerate candidate DCs ("try --data-center-id X").
   Degrades gracefully (hint prints without candidates) if the query fails.
5. The SUPPLY_CONSTRAINT fail-loud contract and the wait-for-capacity loop
   semantics are unchanged. Sidecar IO failures are swallowed (observability
   bias, never crash a provision) — the `_SSH_WAIT_STATE_PATH` pattern.
6. Targeted tests pass; no-flags `workflow_lint.py` + ruff clean on touched
   files.

## 3. File paths + concrete changes

**`scripts/runpod_api.py`:**
- Add `get_datacenters() -> list[dict]` — GraphQL query enumerating
  datacenter ids (+ name/location if available). Schema verified live at
  implement time (assumption A1); on GraphQL error raise `RunPodError`
  (callers degrade to a hint without candidates).
- OPTIONAL (gated on A1): extend the pod selections (`_deploy_once` mutation
  selection, `get_pod`, `list_team_pods`) with `machine { podHostId }` so the
  record carries host identity even when no public port mapping appears.
  The in-file comment (~:1076) warns speculative fields break the WHOLE
  query — so first verify against the live schema with a one-off query on an
  existing pod; if unavailable, SKIP the field entirely and use host-IP-only
  identity (`ssh_host`). Never ship an unverified field.
- Surface `podHostId` on `PodInfo` (new optional field, default None) only
  if A1 verifies.

**`scripts/pod_lifecycle.py`:**
- New sidecar: `_BAD_HOST_STATE_PATH = PROJECT_ROOT/.claude/cache/bad-pod-hosts.json`,
  `_load_bad_host_state()` / `_save_bad_host_state()` (mirror the ssh-wait
  helpers verbatim: atomic tmp+replace, garbled→{}), plus
  `note_bad_placement(issue, pod_name, pod_id, host_ip, dc_id, now=None)` and
  `fresh_bad_hosts(now=None) -> dict[str, list[entry]]` (host-keyed, entries
  older than TTL dropped on read; TTL default 6h, env
  `EPM_BAD_HOST_TTL_SECS`).
- `_provision_wait_register_bootstrap`: (a) in the `wait_for_ssh` RunPodError
  branch — best-effort `get_pod` once for a late-appearing host IP, then
  `note_bad_placement(...)` + `[bad-host-RECORD]` line; (b) in the
  bootstrap-failed exit path (rc != 0 after the #1931 retry, just before
  `BOOTSTRAP-FAILED pod=...`) — `note_bad_placement(...)` with
  `ready.ssh_host` + `[bad-host-RECORD]` line including the different-DC
  retry hint (candidates via `get_datacenters()`, best-effort).
- `cmd_provision` (GPU + CPU branches): after `wait_for_ssh` returns inside
  `_provision_wait_register_bootstrap`, compare `ready.ssh_host` against
  `fresh_bad_hosts()` → `[bad-host-REPEAT]` WARN (cross-issue: a bad host is
  bad for every issue; the RECORD entry names which issue hit it).
- Provision argparse: add `--data-center-id` (default None), threaded to the
  GPU `create_pod`/`create_pod_with_wait_for_capacity` path and the CPU
  `create_cpu_pod` path; WARN when it matches a fresh bad placement's
  recorded DC.

**`scripts/pod.py`:** no change needed (thin dispatcher forwards argv). Kept
in target scope per the task body; touch only if the dispatcher needs a help
line.

**`tests/test_pod_lifecycle.py`** (extend existing file): unit tests with
`_BAD_HOST_STATE_PATH` monkeypatched to tmp_path — record/consume round-trip;
TTL expiry; repeat-warn predicate fires on matching host and stays silent
otherwise; bootstrap-fail path records placement (monkeypatch `_bootstrap`
→ rc=1 twice, assert sidecar row + `BOOTSTRAP-FAILED` still printed);
`--data-center-id` threads to the create call (capture kwargs via
monkeypatch); sidecar IO failure is swallowed (save to unwritable path →
provision flow unaffected).

## 4. Assumptions (confidence-marked)

- **A1 (medium, verify at implement time):** `machine { podHostId }` is
  selectable on the team-scoped GraphQL Pod type, and a datacenter
  enumeration query exists (`dataCenters {...}` or equivalent). Verify BOTH
  with cheap one-off live queries before wiring; on failure, descope per §3
  (host-IP-only identity; hint without candidate list). This is the plan's
  only external dependency and it degrades, never blocks.
- **A2 (high):** the bad host is identified by public IP (`ssh_host`) —
  stable within the TTL window for a given physical host (the #1947 host
  kept the same IP across all 3 placements).
- **A3 (high):** RunPod's create API has NO host-exclude input
  (documented in the task body + supply-workarounds memory); DC-pin-away +
  repeat detection is the available lever set.

## 6. Kill criteria

- If A1 fails BOTH legs (no host-identity field AND no DC enumeration), the
  minimum lever still ships (IP record + repeat WARN + `--data-center-id`
  flag + hint-without-candidates); if even `ssh_host` proves unobservable at
  both failure sites (contradicting the code reads above), STOP and re-plan —
  the design premise is wrong.
