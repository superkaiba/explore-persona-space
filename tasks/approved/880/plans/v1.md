## 1. Goal

Extend `.claude/rules/gotchas.md` so that a MANUAL / supervisor hand-launch of a dispatcher-managed per-cell GPU worker replicates the dispatcher's launcher-env pins (`env CUDA_VISIBLE_DEVICES=<g> ... --gpu-id <g>`) instead of relying on `--gpu-id` alone, closing the #813 incident class.

## 2. Prior work / context

- **gotchas.md line 25** — the `+gpu_id=N` Hydra clobber entry: `train/sft.py` clobbers env CVD in-process; parallel Hydra launches need `+gpu_id=N` per process.
- **gotchas.md line 26** — the #545 entry: the in-process CVD clobber is defeated by any import-time cuInit, so DISPATCHERS must pin `CUDA_VISIBLE_DEVICES=<gpu>` in the launcher env per cell. It ends by naming the enforcement stack: experimenter.md "Before Running" step 10, `tests/test_cvd_wave_assignment_smoke.py`, and `workflow_lint.py --check-dispatcher-cvd-pin`.
- **The gap:** both entries address people WRITING/launching dispatchers. Neither covers a human/supervisor hand-composing a single worker command by copying the worker's CLI args. Worker scripts in this codebase deliberately ignore `--gpu-id` for device selection — `scripts/issue667_extract.py:427` `_device()` returns `torch.device("cuda:0")` unconditionally on the GPU path (the `gpu_id` parameter is not even read there; comment: "CVD pins the physical GPU in the launcher env") — so a bare-`--gpu-id` hand-launch selects no GPU at all.
- **Incident #813 (2026-07-02):** a supervisor hand-launched 4 `issue813_run_cell.py` workers with only `--gpu-id <g>`; all 4 vLLM engines initialized on the busy default GPU and crashed at init_device (~4 min lost). Relaunch prefixed with `env CUDA_VISIBLE_DEVICES=<g>` succeeded. The dispatcher (`issue813_dispatch.py::_cell_cmd`, lines 111–157) does it correctly: `env["CUDA_VISIBLE_DEVICES"] = str(gpu_id)` (the #545 pin) AND `--gpu-id <g>`.
- **Extension vs new bullet — decision: NEW sibling bullet directly after line 26.** Line 26 is already ~2,400 characters; the new rule has a distinct trigger (manual hand-launch, not dispatcher authorship), a distinct failure signature (init-time crash on a busy GPU, not co-locate-then-OOM), and a distinct audience (anyone composing a one-off command). A sibling bullet keeps both findable; the new bullet cross-references "the entry above".

The mechanical lint (`workflow_lint.py --check-dispatcher-cvd-pin`) covers only backgrounded `--gpu-id` launches committed in `scripts/*.sh`; a hand-typed command is not a committed file, so this prose rule is the ONLY guard for the manual case.
