### 2.1 The load-bearing design decision: which reference timestamp

The body offers two candidates and calls (b) "cheaper and stricter". Neither is usable as stated,
and the resolution is the one non-obvious part of this plan.

- **(a) fact-checker verdict ts** — too late. It is the *upper* bound of the safe window in the
  incident (correction landed after it), but the fact-checker is a *recorded-skip candidate* on
  small infra plans, so on any plan that skipped it the reference does not exist at all.
- **(b) plan-draft start time "recorded alongside the Goal snapshot"** — correct in principle, but
  **no such timestamp is recorded today**. `GOAL_SNAP` is a text snapshot with no companion ts.
- **Plan-file mtime (the c23 reference)** — actively wrong here. `verify_plan.py --issue` runs
  *after* the persist, so the plan file's mtime ≈ persist time, and the incident's ordering is
  T_verify < T_correction < T_persist. Comparing against persist time reports every stale citation
  as clean. This is a trap worth naming: the obvious mirror of c23 silently never fires.

**Resolution — reuse the `planner-dispatch` breadcrumb.** `.claude/skills/issue/steps/04-step-2.md`
already *mandates* posting, immediately before invoking the planner:

```
epm:progress --by issue-orchestrator --note "planner-dispatch round=<k> — invoking /adversarial-planner (plan draft v<K> target)"
```

That marker's `ts` **is** the draft-start time, it is already durable in `events.jsonl`, and it
needs no new capture step, no orchestrator cooperation, and no new marker kind. Both legs key on
one notion of "when this draft started":

**The reference is the EARLIEST spawn of the planning campaign, not the current round's spawn.**
This is the correctness crux. The breadcrumb is posted per round (`round=<k>`), so a
newest-breadcrumb reference re-arms every Phase 3 re-spawn and covers only the per-round tails. A
correction landing between v(K−1)'s persist and round K's spawn — a parent corrected while the plan
sits in critic review for hours, which is the fleet's routine correction channel — would then be
invisible: round K inherits the stale text from v(K−1) without re-reading it, and the check reads
`body_commit < DRAFT_START_K` and prints CLEAN. The Goal's window is fact-check → persist and spans
those gaps, so a per-round reference would stamp CLEAN over most of the window it exists to watch.
That is worse than no check. Both legs therefore pin to the campaign's FIRST planner spawn:

- **Helper leg (primary, bounces):** the orchestrator captures `DRAFT_START="$(date +%s)"` ONCE at
  the round-1 planner spawn and does NOT refresh it on Phase 3 re-spawns; it passes
  `--since-unix "$DRAFT_START"` before every persist. **Lost-shell-var clause (mirrors the
  Goal-currency gate's missing-snapshot clause):** when `DRAFT_START` is empty or absent — session
  recovery, a planner death and inline redraft, exactly this plan's own history — the helper
  RE-DERIVES it from the OLDEST `planner-dispatch` breadcrumb in `events.jsonl`. It must NOT be
  invoked with an empty `--since-unix`, which would degrade to `UNKNOWN`/exit 0: that is the
  silent-no-op path, and a missing reference is precisely when the gate matters most.
- **verify_plan leg (backstop, WARN-only):** resolves the reference as the **MINIMUM of whichever of
  these two resolve** — (2) is a FLOOR, never an `else`-branch:
  1. ts of the **OLDEST** `planner-dispatch`-leading `epm:progress` still older than the plan file's
     mtime (the campaign's first recorded spawn, not the current round's);
  2. the **previous** plan version's commit ts — `git log -1 --format=%ct -- plans/v{K-1}.md`, with
     `st_mtime` only as a fallback (§6's dry-run mechanics apply to production too: a fresh-clone run
     reads checkout-clobbered mtimes and would stamp CLEAN);
  3. neither resolves ⇒ **SKIP** (`no resolvable draft-start reference`). Never guesses.

  **Why `min()` and not `else` — this is the correctness crux of the backstop.** An `else` ordering
  breaks precisely where fallback (2) is supposed to earn its keep. Let round k spawn at S_k and
  version v_k persist at P_k. On a campaign whose FIRST breadcrumb lands at round j+1 — every
  campaign straddling the 2026-08-26 mandate landing, i.e. the dominant near-term population per §6's
  own 28/2,572 measurement — an `else` ordering has fallback (1) resolve at v_{j+1} to S_{j+1}, a
  per-round-tail reference, PREEMPTING fallback (2) with a strictly LATER timestamp (S_{j+1} > P_j).
  The window (P_j, S_{j+1}) — the inter-round critic-review window, the exact channel this gate
  exists for — is then covered by no version's check, ever. That reproduces the round-1 defect
  through the fallback order instead of through the breadcrumb selection. Taking the minimum makes
  every version's window ⊇ (P_{K-1}, P_K] unconditionally, closing the gap mechanically.

Cost of the campaign-earliest reference: ids already dispositioned in an earlier round re-surface in
later rounds. That is a one-line re-disposition — the prior dispositions are already recorded in the
`epm:plan` note — and it is cheap next to a false CLEAN.

**What the backstop's coverage claim is, stated with its assumption.** Under the `min()` resolution
above, each version's check covers at least (P_{K-1}, P_K] — the window from the previous persist to
this one — and covers the whole campaign back to its first recorded spawn whenever a breadcrumb
resolves. Across a sequence of persists the per-version windows therefore chain without gaps.

**The chain's assumption, stated rather than assumed:** it delivers union coverage only for versions
persisted AFTER this check ships, because a version that never ran the check surfaced nothing at its
own persist. On tasks already in flight today, the earlier links are empty and coverage reduces to
the current window plus whatever a resolving breadcrumb reaches back to; those earlier windows are
helper-leg territory, not backstop territory. This is a WARN-only backstop behind a bouncing helper
leg, so a forward-only guarantee is the right scope — but it must be CLAIMED as forward-only. An
earlier draft of this section asserted flat union coverage over the campaign, which is circular on
every currently-live task (it presumes the check it is introducing already ran).

### 2.2 Cited-id extraction

Reuse the existing shape: `verify_plan.py` L3133 `_C18_ISSUE_REF_RE = re.compile(r"#\d{2,}")`. The
helper defines its own module-level copy (it is a standalone script and must not import
`verify_plan`'s 15.6k-line module for one regex) with the same `\d{2,}` floor, which already drops
`#1`-style prose noise and markdown anchors of one digit.

Filters, in order:
1. Strip fenced code blocks (```` ``` ````) and indented-4 blocks before matching — command examples
   and JSON payloads carry `#` refs that are not citations.
2. Drop refs immediately preceded by `\w` only — this kills the real URL/fragment cases
   (`issues#123`, `file.md#123`, both word-char-preceded). **Do NOT widen the class to `[/\w.-]`:**
   `/`, `.` and `-` adjacency kills every non-first member of the `#884/#1045/#1134` lineage-list
   idiom, which is a genuine citation form and common in this repo — measured over 25 randomly
   sampled real plan files, 20 of 206 distinct cited ids (10%, affecting 11/25 plans) appear ONLY in
   such filtered positions, this plan's own §3.2 included. Dropping them is a false NEGATIVE on the
   exact surface the gate watches: the verdict would print `CLEAN checked=N` while never probing the
   corrected parent. A rare `.../#123` fragment surviving the narrower class costs one fail-soft
   unresolvable probe, which is the correct direction.
3. Drop the plan's own issue id (`#2384` on its own plan) — self-reference is never a citation.
4. Deduplicate; cap at 40 ids per draft (a runaway plan must not fan out into 200 git calls).

**Known and accepted imprecision:** step 2 cannot distinguish a genuine citation in prose from an
incidental `#<n>` that happens to name a task. Over-inclusion costs one extra `git log` per false id
and, at worst, one spurious surfacing the orchestrator dispositions in one line. That is the correct
direction for a gate whose failure mode is a silently superseded claim.

### 2.3 Worktree safety

Cited body paths resolve **only** through `explore_persona_space.task_workflow` (`tasks_dir()` /
the registry), never a hand-built `tasks/<status>/<M>/` path — CLAUDE.md hard rule, mechanically
enforced by `tests/test_no_direct_task_path_construction.py`. The git probe runs against the main
checkout resolved as
`REPO_ROOT = dirname(git rev-parse --path-format=absolute --git-common-dir)`, so the helper is
correct when invoked from a worktree cwd.

### 2.4 Scope — the three "Related (optional)" checks are EXCLUDED

The task body's § Related lists three further mechanizable verifier gaps: (a) N-pod fan-out §9 rows

### 3.1 NEW — `scripts/check_cited_body_currency.py`

```
Usage: uv run python scripts/check_cited_body_currency.py --issue <N> --since-unix <ts>
                                                          [--plan-file <path>] [--json]
```

```python
def extract_cited_ids(plan_text: str, *, self_issue: int) -> list[int]
    """Fenced/indented blocks stripped, URL-adjacent refs dropped, self dropped,
    deduped, capped at _MAX_CITED_IDS (40)."""

def cited_body_path(issue: int) -> Path | None
    """task_workflow registry lookup -> <task folder>/body.md; None if unresolvable."""

def last_commit_unix(path: Path, *, repo_root: Path) -> int | None
    """git -C <repo_root> log -1 --format=%ct -- <path>; None on empty output,
    non-zero rc, or timeout (10 s)."""

def body_diff_since(path: Path, since_unix: int, *, repo_root: Path) -> str
    """git -C <repo_root> log --since=@<ts> --oneline -- <path>  plus
    git -C <repo_root> diff <oldest-in-window>^..HEAD -- <path>, truncated to
    _MAX_DIFF_CHARS (8000). Best-effort; '' on any failure."""

def check(plan_text, *, self_issue, since_unix, repo_root) -> tuple[str, list[dict]]
    """-> ('CLEAN' | 'STALE' | 'UNKNOWN', findings)"""

def main() -> int
    """0 = CLEAN or UNKNOWN (fail-soft), 3 = STALE (actionable)."""
```

Verdict line on stdout, always exactly one:

```
CITED-BODY-CURRENCY: CLEAN checked=4 since=1787939126
CITED-BODY-CURRENCY: STALE ids=825 checked=4 since=1787939126
CITED-BODY-CURRENCY: UNKNOWN reason=<one-line>
```

For each stale id, the diff block follows on stderr so a `$(...)` capture of the verdict stays
clean.

**Fail-soft contract (acceptance criterion 2), stated precisely:**
- unresolvable id (no registry entry, archived, never existed) → skipped, counted in
  `unresolved=<n>`, verdict unaffected;
- `git log` non-zero / empty / timeout → that id skipped, verdict unaffected;
- unreadable plan file, bad `--since-unix`, import failure, **any** unexpected exception →
  top-level handler prints `UNKNOWN reason=...` and returns **0**;
- exit 3 is reachable **only** from a positively-established stale citation.

The helper never writes, never mutates task state, never touches the network.

  `planner-dispatch` mandate landed 2026-08-26, two days before this plan, and only 28 of 2,572 task
  dirs carry a breadcrumb (#2378 itself: zero). So c75 fallback (1) is near-inert on the HISTORICAL
  corpus and the backstop rides fallback (2)/SKIP retrospectively. This is expected, not a design
  failure — the helper leg gets `DRAFT_START` directly and forward coverage is real — but the
  implementation must frame the kill-criterion-1 corpus scan's conclusion as "historical inertness
  expected, forward coverage real" rather than reporting a healthy check as broken. It WOULD kill
  the backstop claim if breadcrumb adoption stalls going forward; re-check at implementation time.
- **Extraction precision is unusable.** If a dry run over ~20 recent plan versions surfaces stale
  citations on a majority of plans, the gate is noise, every persist eats a disposition step, and
  orchestrators will learn to wave it through. Threshold: > 30% of sampled plans STALE ⇒ tighten
  extraction (restrict to §2/§11/§12 as the body originally suggested) before landing.
  **Dry-run mechanics (load-bearing):** take historical plan-version timestamps from
  `git log -1 --format=%ct -- plans/v{K}.md`, NEVER `st_mtime` — checkout operations clobber mtimes,
  which would collapse the measured windows toward zero and underestimate the false-positive rate
  the 30% threshold gates on.
  **Dominant false-positive channel to mitigate rather than measure around:** a cited task's status
  change (`git mv` between status folders) or a user promotion sweep (`classification` flip) commits
  its `body.md` path with a rename-only or frontmatter-only diff and reads STALE. The helper labels
  such diffs as `rename-only` / `frontmatter-only` in its stderr block so the disposition is
  one glance; note this does NOT reach the §2/§11/§12 scoping escape, which is why it is mitigated
  at the diff-labelling layer instead.
- **The bounce cannot be honored.** If re-grounding a cited section requires re-running the
  fact-checker (not a cheap re-read), the "mechanical bounce, not a critic round" framing is wrong
  and the gate belongs at a different site.

## 7. Plan deviations — allowed vs must-ask

**Allowed without asking:** helper function/CLI naming; exact regex tightening for extraction;
which of §2/§11/§12 scoping to adopt if the kill-criterion-2 threshold trips; test-fixture
mechanics (real tmp git repo vs monkeypatched `subprocess` — real repo preferred, it is what makes
criterion 1 meaningful); diff-truncation limits; whether the c75 reference-resolution helper lives
in `verify_plan.py` or is imported from the standalone script.

**Must ask:** (i) promoting c75 from WARN to FAIL — that changes plan-gate semantics fleet-wide;
(ii) making the helper leg blocking rather than surface-and-disposition — the body specifies
surface-then-disposition and fail-soft; (iii) adding any of the three excluded § Related checks;
(iv) any new marker kind (the design deliberately mints none — it reads the existing
`epm:progress` breadcrumb).
