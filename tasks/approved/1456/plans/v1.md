## 4. Design (method delta + exact diff sketches)

**Method delta vs the current recipe:** the overlay loop is unchanged for every payload path; ONE post-loop special-case re-derives `$GT/scripts/workflow_lint.py` by 3-way merge when (and only when) the own-diff touched it. Baseline legs, verdict logic, sha-bind, crash arm, TG legs: all byte-untouched. The special-case can never make the gate harder-failing than status quo: every failure inside it degrades to the branch copy (today's behavior) with a WARN — never a new `GT_RC=1` / crash path.

### Edit 2 — the 3-way merge special-case (insert after the loop, before the GATED legs)

Anchor (SKILL.md ~L9443-9446):

```
    done < /tmp/issue-<N>-overlay-files.txt
    # GATED legs (payload-bearing landing tree — phase 3; parity leg covers
```

Insert between `done < ...` and the `# GATED legs` comment:

```bash
    # LINT-VINTAGE 3-WAY MERGE (#1456; incidents #1366/#1411): when the own
    # diff touches scripts/workflow_lint.py, the loop above overlaid the
    # BRANCH's lint copy, whose ratchet constants (_LESSONS_RATCHET_BYTES,
    # agent-spec caps, gotchas row caps — bumped on main every few days) may
    # predate main's raises and flag main-advanced files on the gated legs
    # only (NEW non-empty -> spurious block). Approximate the post-rebase
    # trunk lint instead: 3-way-merge branch copy (ours) + merge-base copy +
    # the saved archived-origin/main copy (theirs). Clean merge -> gated legs
    # carry BOTH main's constant raises / post-fork checks AND the branch's
    # own lint deliverable; a branch-added check with unfixed main offenders
    # still lands in the merged copy -> NEW -> block (correct: trunk pytest
    # goes red post-merge either way). ANY failure (merge conflict rc>0,
    # internal error, merge-base/base-copy extraction failure, missing saved
    # main copy) falls back to the BRANCH copy — exactly the pre-#1456
    # residual-(a) behavior — with a loud WARN + sidecar note, NEVER a new
    # crash path. git merge-file exits 0 on a clean merge, the number of
    # conflicts (>0) on conflict, negative (shell: 255) on error; -p writes
    # the merged result to stdout, leaving the input file untouched.
    if grep -qxF 'scripts/workflow_lint.py' /tmp/issue-<N>-overlay-files.txt \
       && git -C "$WT" cat-file -e HEAD:scripts/workflow_lint.py 2>/dev/null; then
      LINT_MERGED=no
      if [ -s /tmp/issue-<N>-lint-main-copy.py ] \
         && MB=$(git -C "$WT" merge-base origin/main HEAD 2>/dev/null) \
         && git -C "$WT" show "$MB:scripts/workflow_lint.py" \
              > /tmp/issue-<N>-lint-base-copy.py 2>/dev/null \
         && git merge-file -p "$GT/scripts/workflow_lint.py" \
              /tmp/issue-<N>-lint-base-copy.py /tmp/issue-<N>-lint-main-copy.py \
              > /tmp/issue-<N>-lint-merged.py 2>/dev/null; then
        mv /tmp/issue-<N>-lint-merged.py "$GT/scripts/workflow_lint.py" && LINT_MERGED=yes
      fi
      echo "[step10d] lint-vintage 3-way merge: $LINT_MERGED"
      if [ "$LINT_MERGED" = no ]; then
        echo "WARN: lint-copy 3-way merge failed/conflicted — gated legs run the BRANCH's workflow_lint.py (residual (a)); a ratchet-drift false block may follow. Fix: rebase the branch onto origin/main (or sync main's ratchet constants into the branch copy), then re-run the gate." \
          | tee /tmp/issue-<N>-lint-mergefile-note.txt
      fi
    fi
```

Notes on the mechanics:
- `grep -qxF` = exact-full-line literal match against the `--no-renames` listing (quotePath=false ⇒ plain ASCII path, no quoting).
- The `cat-file -e HEAD:...` guard skips the special-case when the branch DELETED workflow_lint.py — the loop's `rm -f` already removed it and the gated legs then crash (missing file) → existing crash arm, same as today.
- The sidecar note goes to `/tmp/issue-<N>-lint-mergefile-note.txt` + gate stdout — NEVER into `/tmp/issue-<N>-lint-verdict.txt` (its consumers are a strict 2-line contract: `grep -qxE` on line 1 + `sed -n 2p` sha at L9899/L10241; a third line before the sha append would shift the sha to line 3 and fail-closed every merge).
- `$GT` cleanup (`rm -rf "$GT"`, L9575) and the `/tmp/issue-<N>-lint-*` namespace are unchanged; the three new temp files ride the existing per-issue prefix (reaped by the #911 janitor with the rest).

## 11. Decision Rationale

- **Design (C) — 3-way merge — over (D) and (B).**
  - What: `git merge-file -p <branch> <merge-base> <main>` for `$GT/scripts/workflow_lint.py` on the gated legs only; branch-copy fallback on failure.
  - Why: it approximates the post-merge trunk lint exactly — git's rebase/squash merge applies the same 3-way content merge server-side, so a clean gate-merge equals the file that will actually land. This kills the false-block class (stale branch ratchet vs main-advanced files) while PRESERVING the correct-block class (#1212's deliberate upgrade: a branch-added check with unfixed main offenders stays in the merged copy → NEW → block, matching the trunk pytest that would go red post-merge).
  - Why not (D) (pin BOTH legs to the branch's lint vintage): fail-opens the correct-block class — a branch shipping a new check would have that check in BOTH legs, so main's offenders appear in baseline too and subtract away; the merge would land a red trunk that only Step 9c/trunk pytest catches later. (D) trades a ~10-min annoyance for a real fail-open; rejected.
  - Why not (B) (mechanical ratchet-constant text sync): the ratchet constants are scattered across `workflow_lint.py` (`_LESSONS_RATCHET_BYTES`, `_LESSONS_ROW_GRANDFATHER_MAX_BYTES`, agent-spec size ratchets, gotchas row caps) and the set grows every few weeks — a name-list or regex sync drifts the moment a new constant is added, silently reintroducing the bug; and it fixes only CONSTANT drift, not post-fork check drift. (C) subsumes (B) with zero maintained lists; rejected.
  - Source: incidents #1366/#1411 (task #1456 body + clarifier marker); gate design #1212 (`tasks/completed/1212/plans/v3.md`, SKILL.md L9352-9369); `git merge-file` semantics verified live 2026-07-17 (rc=0 clean / rc=N conflicts / negative on error; `-p` to stdout) — matches `git merge-file --help`.
- **Fallback = branch copy (status quo), not fail-CLOSED.** Why: the special-case must be a strict improvement — a crash on merge-infrastructure failure would make the gate WORSE than today for the very branches it helps. Loud WARN + sidecar keeps the failure diagnosable (fail-fast-in-signal, degrade-in-behavior). Source: #1212 residual-(a) precedent (the accepted behavior).
- **Sidecar note file, not a verdict-file line.** Why: verdict consumers enforce a 2-line contract (`sed -n 2p` sha at SKILL.md L9899/L10241); a third line before the sha append breaks every merge. Source: SKILL.md L9581-9613, L9898-9910.
- **Pin test as durability pin.** Why: this § is among the most-edited SKILL.md regions (5 revisions since #1212 landed 2026-07-09); executable-snippet prose is exactly the drift class pins exist for. Source: #1288 precedent (`tests/test_issue_skill_step10d_merge_form.py`).
