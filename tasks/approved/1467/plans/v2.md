## 6. Kill criteria

- **Scanner blocks a legitimate filing** — must be impossible by construction (WARN-only, exit code untouched, fail-open on git errors). Any refusal path in the diff = reject the diff.
- **Annotation-tier false positives on real bodies** (legit external-repo / unfetched-branch SHAs cited as commits): demote tier 1 to stderr-WARN + ledger key only (drop body mutation); the prose duty and pin test stand unchanged.
- **Body corruption** (annotation breaks the Provenance parse or the recursion-guard needle): caught by `test_check_body_shas_annotates_idempotently`; if unreconcilable, same demotion fallback.

## 11. Decision Rationale

- **Duty on all three prose surfaces (SKILL + rule + yaml).** Why: the verified-at-filing mandate is tri-surfaced and tri-pinned; a single-surface SHA duty would drift. Source: #1272/#1307 lineage + `test_verified_at_filing_line_required`. Alternative: daily-SKILL-only — rejected (the orchestrator filing channel in the rule file has identical exposure).
- **Driver action = two-tier WARN + annotate, never refuse.** Why: filed bodies seed planner/fact-checker rounds — a stderr WARN at 3 AM reaches nobody downstream, while a body annotation reaches exactly the consumer that burned the #1414 round; refusal on a false positive blocks legitimate filings (§6 kill criterion). Source: `_warn_stray_wf_fix_provenance` (#1228, WARN-only precedent) + `ensure_wf_fix_provenance` (#1173, body-injection precedent). Alternatives: fail-loud refusal (rejected — kill criterion); WARN-only no annotation (kept as the documented fallback).
- **Scan bounds: `\b[0-9a-f]{7,40}\b`, ≥1 letter, fingerprint/drift-hash line exclusion; annotation gated on commit-context vocabulary.** Why: 7 = git abbrev floor, 40 = SHA-1; all-digit exclusion kills dates (`20260716`); the fp class (`9608dfe5771a`, verified non-resolving) is line-excludable; commit-context gating matches the incident shape (session ids cited AS session ids stay un-annotated). Source: incident #1414 tokens verified this session + `wf_fix_fingerprint[:12]`. Alternative: annotate every non-resolving token — rejected (noise on every `session <id>` line).
- **Backstop on the driver path only (no `file_infra_task.py` change).** Why: matches the existing asymmetry (title guard + Provenance injector are driver-only; the single-item path is prose-duty-covered and WARNs). Source: SKILL L430/L432 + #1273. Alternative: also patch `file_infra_task.py` — rejected as scope creep for a distinct filing channel; a separate candidate can raise it if a single-item incident recurs.
