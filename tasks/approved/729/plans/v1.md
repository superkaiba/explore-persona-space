## 1. Goal

Close the workflow gap that let stale inherited figures slip through the analyzer on a same-issue follow-up re-fold (#667 a36 round 2). The analyzer's Step 3.5 (Plot-verification) currently tells the analyzer to *visually* inspect every figure before referencing it, but visual inspection catches a malformed figure — NOT a byte-different-but-stale-data figure that renders cleanly while plotting values from the WRONG (prior-round) result JSON. Add a concrete, mechanical Step 3.5 sub-rule: when the analyzer embeds a figure it did NOT generate this pass (inherited from the implementer / upload-fix commit during a follow-up re-fold), it MUST cross-check that figure's `.meta.json` `points` against the NEW round's result JSON, and regenerate from the new JSON if they don't match. The affordance already exists — `savefig_paper` embeds per-point plotted data under a `points` key in every `.meta.json` sidecar (analyzer.md L387) — so the check is a `json.load` of two files plus a value comparison.

## 3. Design

### 3a. Edit to `.claude/agents/analyzer.md` Step 3.5 (PRIMARY)

Insert a new confirm-item **4** in the Step 3.5 numbered list (after item 3 "Annotated key points are visible…", before the "If a check fails, fix the plot…" paragraph). Literal new prose:

> 4. **Inherited-figure data freshness (same-issue follow-up re-folds only).** If you are mid same-issue follow-up re-fold AND a figure you are about to embed was NOT generated by you this pass — i.e. it was committed by the implementer or an upload-fix in a PRIOR round (a figure whose PNG/`.meta.json` already existed before you started this fold) — you MUST cross-check its data against the NEW round's result JSON before embedding it. A figure re-committed with a trivial byte-diff can still plot STALE data: the gen script was never repointed at the new result JSON, so the figure renders cleanly while carrying the prior round's values, and the visual checks above (1-3) will NOT catch it. Mechanically: `json.load` the figure's `.meta.json` and read its `points` (the per-point plotted values `savefig_paper` auto-embeds — see the `.meta.json` affordance above), then compare those values to the corresponding field in the NEW round's result JSON you just produced this fold. If the `points` match the new JSON → embed it. If they match the PRIOR round's values, are drawn from a stale source JSON, or don't reconcile with the new JSON → REGENERATE the figure from the new result JSON (re-run the figure-gen script after confirming it reads the new JSON, or repoint it) before embedding, and flag the stale figure superseded in the body's `**Repro:**` footer. This check is cheap (two `json.load`s + a value comparison) and is the only thing standing between a stale inherited figure and the published body — incident #667 a36 round 2 caught exactly this class post-hoc by luck.

This is additive: it does not change items 1-3, the Read-the-PNG workflow, or any other Step. The guard is scoped to same-issue follow-up re-folds AND inherited figures, so a first-pass analysis (every figure generated this pass) is unaffected — items 1-3 run as today and item 4 is a no-op there.

### 3b. Decision on `.claude/agents/upload-verifier.md` — **SPLIT into a sibling task** (do NOT include in this fix)

**Decision: this task fixes ONLY analyzer.md. The upload-verifier "Possibly also" leg is left for a sibling `kind: infra` task.**

Rationale (two independent reasons):

1. **The upload-verifier check is materially harder and needs a schema change, not a doc tweak.** The analyzer-side check is easy because the analyzer KNOWS which result JSON it just produced this fold — it has the new JSON in hand and compares against it. The upload-verifier has no such handle: to fail-loud on a stale-data figure it would have to INFER which result JSON each figure is "supposedly drawn from," and the `.meta.json` `points` schema carries NO source-JSON identity pointer today (confirmed: `points` is plotted values + provenance only, `paper_plots.py` ~L894-1060). So the verifier leg requires either (a) extending the `.meta.json` schema to record the source-JSON path at `savefig_paper` time (a change to `paper_plots.py` + the SPEC dashboard-data-artifact contract — out of this task's scope and a public-ish contract), or (b) a heuristic value-match against every candidate result JSON (fragile, false-positive prone). Either is a separate design problem deserving its own planner/critic/code-review pass.

2. **Scope clarity — one fix per concern.** This task's fingerprint and Goal are scoped to the analyzer re-fold guard. Bundling a verifier schema/inference change would change two variables in one merge and conflate an easy additive doc rule with a harder schema design, muddying the diff the code-reviewer ensemble sees. Workflow-surface edits land + auto-merge at symmetric cost, so splitting costs nothing and buys a clean, reviewable single-concern change.

Proposed sibling task (for the orchestrator to file post-merge if it decides to follow up — NOT filed from this session, per the recursion guard):

- **Title:** `workflow-fix: upload-verifier fail-loud on stale-data figures (.meta.json points ↔ source JSON)`

Different fingerprint (`stale-inherited-figure-upload-verify-001`).

## 5. Risks + mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| **"Inherited" is ambiguous** — the analyzer can't always tell which figures it generated this pass vs inherited. | Medium | The prose defines it operationally: a figure whose PNG/`.meta.json` already existed before this fold started (committed by a prior round's implementer/upload-fix). On a same-issue follow-up the analyzer knows it is re-folding onto an existing body, so any figure it did not itself regenerate this pass is inherited by definition. |
| **Over-eager regeneration costs analyzer time** — the analyzer regenerates legitimately-correct inherited figures. | Low | The rule regenerates only on MISMATCH. A matching cross-check (`points` ≈ new JSON) → embed as-is, no regeneration. The cross-check itself is two `json.load`s — negligible cost. |
| **False positive when the gen script reads multiple JSONs internally** — a figure's `points` legitimately blend the new JSON with a held-fixed prior-round JSON (e.g. base-rate panels). | Low-Medium | The prose compares `points` to "the corresponding field in the NEW round's result JSON" — the analyzer compares the values that SHOULD have changed this round, not every panel. If a panel is intentionally held fixed across rounds, its `points` matching the prior round is correct and the analyzer embeds it. The rule targets the case where values that SHOULD reflect the new result still show the old ones (#667's exact failure). |
| **Prose too narrow** — only catches the byte-diff-but-stale case, misses other inherited-figure staleness. | Low | The mismatch criterion is general ("don't reconcile with the new JSON"), covering byte-identical-stale, byte-diff-stale, and wrong-source-JSON alike. |
| **Test assertion brittle** — a future legitimate reword of Step 3.5 trips the string check. | Low | The assertion checks for stable concept tokens (`inherited`, `follow-up re-fold`, `.meta.json`, `points`) any faithful rewording would retain; it does not pin exact sentence structure. A reword that drops all four tokens has dropped the rule and SHOULD fail. |
