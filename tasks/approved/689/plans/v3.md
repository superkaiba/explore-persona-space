## Section A — per-cell incremental upload (fix (a))

### A.1 Goal

Persist each fleet-eval cell's primary deliverables (eval JSONs + store
tensors) the moment that cell's extract+eval worker succeeds, so a mid-sweep pod
death loses at most one in-flight cell rather than every not-yet-P3-uploaded
cell. **HF presence is now part of the P2/P3 resume surface (A2 fix, SKIP
variant):** the P2 `WaveDispatcher` skips a cell that is already complete on the
Hub even when its local dirs are absent (the fresh-pod-after-auto-migrate case),
and P3 treats "every selected cell already complete on HF" as success rather
than requiring local raw files. This is what makes fix (b)'s auto-terminate +
fresh-pod re-provision genuinely "lose at most one in-flight cell" — without it
the bytes were preserved on HF but the fresh pod re-ran every completed cell.

Success criteria:
- re-running `extract_and_eval_cell` on a cell whose artifacts are already on the
  Hub (exact expected file set present) skips that cell's upload;
- the P2 `is_done` predicate (`_cell_done_anywhere`) returns True for a cell that
  is complete EITHER locally OR on the Hub, so a fresh pod after auto-migrate
  re-runs only the strictly-incomplete cells;
- P3 `upload_artifacts` becomes an idempotent safety sweep that re-uploads only
  cells whose EXACT expected file set is NOT already on the Hub, and does not
  raise when every selected cell is already complete on HF with no local files.

```python
    """The EXACT set of eval-JSON basenames a COMPLETE cell has under its
    raw-completions prefix. Mirrors the gen phase's own iteration
    (issue664_eval._judging_surface), so it stays in lock-step with what gen
```

**New helper `_cell_artifacts_on_hub(cell) -> bool`** — EXACT file-set, not
prefix:

```python
def _cell_artifacts_on_hub(cell: C.Cell) -> bool:
    """True iff this cell's EXACT expected eval-JSON set AND store-tensor set are
    both fully present on the Hub. FRESH listing (Python Hub API, never the hf
    CLI — upload-policy). Exact-file-set (S1): a partial cell (mid-upload_folder
    crash, one artifact-kind missing) reads as NOT complete, so it is re-uploaded
    and never silently skipped / passed by the auto-terminate gate."""
    from huggingface_hub import list_repo_files
    files = set(list_repo_files(C.HF_DATA_REPO, repo_type="dataset", revision="main"))
    raw_prefix = f"{C.HF_RAW_COMPLETIONS_PREFIX}/{cell.eval_key}/"
    store_prefix = f"{C.HF_STORE_PREFIX}/{cell.eval_key}/"
    have_eval = {p[len(raw_prefix):] for p in files if p.startswith(raw_prefix)}
    have_store = {p[len(store_prefix):] for p in files if p.startswith(store_prefix)}
    eval_ok = _expected_eval_files(cell).issubset(have_eval)
    store_ok = _expected_store_files().issubset(have_store)
    return eval_ok and store_ok

def _cell_hub_state(cell: C.Cell) -> str:
    """Per-cell three-state HF presence (M1): 'complete' (both kinds' exact sets
    present), 'partial' (≥1 file of one kind present but the cell is not
    complete), 'absent' (no files under either prefix). Computed from ONE fresh
    listing; callers that classify many cells pass the listing in to avoid N
    round-trips (see _cells_hub_states)."""
    from huggingface_hub import list_repo_files
    files = set(list_repo_files(C.HF_DATA_REPO, repo_type="dataset", revision="main"))
    return _classify_cell_hub_state(cell, files)

def _classify_cell_hub_state(cell: C.Cell, files: set[str]) -> str:
    raw_prefix = f"{C.HF_RAW_COMPLETIONS_PREFIX}/{cell.eval_key}/"
    store_prefix = f"{C.HF_STORE_PREFIX}/{cell.eval_key}/"
    have_eval = {p[len(raw_prefix):] for p in files if p.startswith(raw_prefix)}
    have_store = {p[len(store_prefix):] for p in files if p.startswith(store_prefix)}
    eval_ok = _expected_eval_files(cell).issubset(have_eval)
    store_ok = _expected_store_files().issubset(have_store)
    if eval_ok and store_ok:
        return "complete"
    if have_eval or have_store:        # something present but not the full set
        return "partial"
    return "absent"
```

**New helper `_upload_cell_artifacts(cell, *, smoke) -> None`** (placed near the
P2 cell workers, ~after L1004). Uploads THIS cell's eval JSONs + store tensors as
ONE `upload_folder` commit per artifact-kind, idempotent against the EXACT
on-Hub file set, fail-loud. Baseline propensity is a Phase-0 aggregate, NOT
per-cell — it stays only in P3.

```python
def _upload_cell_artifacts(cell: C.Cell, *, smoke: bool) -> None:
    """Per-cell incremental upload (checkpoint-per-phase). One upload_folder
    commit per artifact-kind (HF 256-commits/hr cap). Idempotent: skip when the
    EXACT expected file set is already on the Hub. Fail-loud EXACT-file-set
    Hub-verify before returning."""
    if smoke:
        logger.info("[p2-upload] smoke: skipping per-cell HF upload")
        return
    if _cell_artifacts_on_hub(cell):
        logger.info("[p2-upload] %s already complete on Hub; skipping", cell.eval_key)
        return
    from huggingface_hub import HfApi
    api = HfApi()
    # eval JSONs: eval_results/issue_664/registry/<cell>/  ->  raw_completions/<cell>/
    eval_dir = C.EVAL_ROOT / "registry" / cell.eval_key
    if eval_dir.exists() and any(eval_dir.iterdir()):
        api.upload_folder(
            folder_path=str(eval_dir), repo_id=C.HF_DATA_REPO, repo_type="dataset",
            path_in_repo=f"{C.HF_RAW_COMPLETIONS_PREFIX}/{cell.eval_key}",
            allow_patterns=["completions__*.json", "completion_logp.json"],
            commit_message=f"[i664 per-cell] eval JSONs {cell.eval_key}",
        )
    # store tensors: trained_store/<cell>/  ->  theory_assumptions/.../issue664/<cell>/
    store_dir = C.STORE_ROOT / cell.eval_key
    if store_dir.exists() and any(store_dir.iterdir()):
        api.upload_folder(
            folder_path=str(store_dir), repo_id=C.HF_DATA_REPO, repo_type="dataset",
            path_in_repo=f"{C.HF_STORE_PREFIX}/{cell.eval_key}",
            commit_message=f"[i664 per-cell] store tensors {cell.eval_key}",
        )
    if not _cell_artifacts_on_hub(cell):  # FRESH-listing EXACT-set verify, fail-loud
        raise RuntimeError(
            f"[p2-upload] per-cell upload verify FAILED for {cell.eval_key}: "
            f"expected eval-JSON set {_expected_eval_files(cell)} and/or store set "
            f"{_expected_store_files()} not fully on Hub after upload_folder"
        )
    logger.info("[p2-upload] %s eval JSONs + store tensors uploaded + verified", cell.eval_key)
```

**A2 fix — P2 `WaveDispatcher` `is_done` predicate becomes `_cell_done_anywhere`
(SKIP variant).** The P2 dispatcher's `is_done` lambda at L1431 currently calls
`_cell_extract_eval_done` (LOCAL-only: `STORE_ROOT/.../tensors.pt` +
`EVAL_ROOT/registry/<cell>`). After fix (b) auto-terminates + re-provisions a
FRESH pod, HF-complete cells are locally absent, so the local-only predicate
re-runs every one of them (wasted compute) and P3 can raise on missing local
raw files. The fix is a combined predicate that treats a cell complete EITHER
locally OR on HF:

```python
def _cell_done_anywhere(cell: C.Cell, *, smoke: bool) -> bool:
    """P2 resume-skip predicate (A2). A cell is done if its final artifacts are
    on the pod volume (the fast local path) OR its EXACT expected file set is
    already complete on HF (the fresh-pod-after-auto-migrate path, #664 fix (b)).
    Smoke never consults HF (per-cell upload is smoke-skipped)."""
    if _cell_extract_eval_done(cell, smoke=smoke):
        return True
    if smoke:
        return False
    return _cell_artifacts_on_hub(cell)
```

and the P2 dispatcher wiring (L1431) changes to:


**`_upload_store_tensors` gains a fresh-listing Hub verify (M2).** The current
helper (L1253-1285) per-file-uploads each cell's `STORE_ROOT/<cell>/*` and
raises only on a missing LOCAL `tensors.pt` — it has NO post-upload
`list_repo_files` verify, so a 429-throttled / transient `_upload` failure can
leave store tensors uploaded-but-not-landed and the helper still returns clean.
Since fix (b)'s irreversible auto-terminate is gated on store-tensor HF
presence, this is a data-loss hole. Add a fresh-listing EXACT-set verify after
the upload loop, mirroring `_upload_raw_completions` (L1236-1244) but checking
the exact per-cell store set, not a bare prefix count:

```python
def _upload_store_tensors(cells: list[C.Cell]) -> None:
    """... (existing docstring) ... M2: add a fresh-listing Hub verify."""
    from huggingface_hub import list_repo_files
    from explore_persona_space.orchestrate import hub
    missing: list[str] = []
    for cell in cells:
        cell_dir = C.STORE_ROOT / cell.eval_key
        tp = cell_dir / "tensors.pt"
        if not tp.exists():
            # M1/A2: a cell complete on HF (fresh-pod path) with no local files is
            # NOT missing — it was already uploaded per-cell. Only a cell that is
            # neither local-complete nor HF-complete is a real miss.
            if _cell_artifacts_on_hub(cell):
                continue
            missing.append(f"{cell.eval_key} ({tp})")
            continue
        for f in cell_dir.glob("*"):
            if f.is_file():
                hub._upload(f, repo_id=C.HF_DATA_REPO, repo_type="dataset",
                    path_in_repo=f"{C.HF_STORE_PREFIX}/{cell.eval_key}/{f.name}",
                    upload_as_file=True)
    if missing:
        raise RuntimeError(  # (existing #521-trap message)
            "[p3-upload] trained-store tensors MISSING for "
            f"{len(missing)} selected cell(s): {missing} ...")
    # NEW (M2): FRESH-listing EXACT-set verify — every selected cell's store
    # tensors.pt + meta.json must be present on the Hub before teardown.
    on_hub = set(list_repo_files(C.HF_DATA_REPO, repo_type="dataset", revision="main"))
    not_landed: list[str] = []
    for cell in cells:
        store_prefix = f"{C.HF_STORE_PREFIX}/{cell.eval_key}/"
        have = {p[len(store_prefix):] for p in on_hub if p.startswith(store_prefix)}
        if not _expected_store_files().issubset(have):
            not_landed.append(f"{cell.eval_key} (have={sorted(have)})")
    if not_landed:
        raise RuntimeError(
            f"[p3-upload] store-tensors Hub-verify FAILED: {len(not_landed)} cell(s) "
            f"missing tensors.pt/meta.json on the Hub after upload: {not_landed}")
    logger.info("[p3-upload] store tensors uploaded + Hub-verified -> %s/%s",
                C.HF_DATA_REPO, C.HF_STORE_PREFIX)
```

### A.4 Acceptance criteria

- **Idempotency (exact-set).** Re-running `extract_and_eval_cell` on a cell whose
  EXACT expected eval-JSON set + store set are on the Hub SKIPS the
  `upload_folder` calls and returns without a new commit (mock `list_repo_files`
  to return the full expected file set, assert `upload_folder` NOT called).
- **Fresh upload.** A fresh cell (not on Hub) triggers exactly TWO `upload_folder`
  commits (eval JSONs + store tensors), then the fresh-listing EXACT-set verify
  passes (mock `list_repo_files` to return the full expected set only on the
  SECOND call).
- **PARTIAL cell re-upload (S1).** A cell whose Hub listing has its raw prefix
  but is MISSING `tensors.pt` (or is missing one `completions__*.json` of its
  expected set) reads as NOT complete: `_upload_cell_artifacts` re-uploads, and
  if the post-upload listing STILL lacks an expected file it raises
  `RuntimeError`. Prefix-presence alone never counts as complete.
- **Fail-loud verify.** If the post-upload listing lacks any expected file,
  `_upload_cell_artifacts` raises `RuntimeError`.
- **P3 exact-set skip.** P3 `upload_artifacts` skips a cell whose EXACT expected
  set is already on the Hub (no re-`upload_folder`) and proceeds; the terminal P3
  EXACT-set verify (raw + store) still asserts every selected cell is complete.
- **A2 fresh-pod resume.** With local eval/store dirs ABSENT and the Hub holding
  a cell's full expected raw+store set, `_cell_done_anywhere(cell)` returns True
  (P2 builds NO extract/eval `CellCmd` for it) AND `_upload_raw_completions` does

## Section B — RunPod RUNNING-but-no-port wedge: detect + auto-migrate (fix (b))

**A1-residue:** within the K floor (first observation AND subsequent
not-yet-matured ticks), the helper returns `replace(result, status="running",

```python
RUNPOD_WORKLOAD_OBSERVED_PHASE = "runpod_no_port_observed"  # non-terminal, within-K

def _maybe_escalate_runpod_wedge(handle, result, sidecar: Path, *, now: float):
    """Escalate a RunPod pod RUNNING-but-no-port past K to terminal wedged (#664).

    Sibling of _maybe_escalate_gcp_wedge: a poller-side staleness clock kept in
    the poller (NOT inside RunPodBackend.poll, so poll stays a pure function).

    Within the K floor on a confirmed RUNNING+no-port pod, OVERRIDE an SSH-dead /
    stalled poll into a NON-TERMINAL running result so polling continues until the
    wedge matures (poll_once returns status='dead' on SSH-probe failure —
    poll_pipeline.py L2076-2077 — so a bare `return result` here would stop the
    orchestrator before K and the wedge would never be observed: A1-residue).

    False-positive guards (return result unchanged, clock cleared):
      * not a RunPod handle  -> unchanged;
      * the live pod EXPOSES a public port (healthy)  -> clear the clock, unchanged;
      * desiredStatus != RUNNING (EXITED/terminal)  -> clear, unchanged.
    """
    if getattr(handle, "backend", None) != "runpod":
        return result
    from runpod_api import get_pod_by_name  # live RunPod API (X-Team-Id baked in)
    info = get_pod_by_name(handle.pod_name)   # PodInfo or None
    healthy_or_terminal = (
        info is None                                   # gone -> ordinary dead path
        or info.desired_status != "RUNNING"            # EXITED/terminal -> not a wedge
        or (info.ssh_host and info.ssh_port)           # public port present -> healthy
    )
    if healthy_or_terminal:
        _clear_runpod_noport_clock(sidecar)
        return result
    # RUNNING + no public port: start/continue the no-port clock.
    first_seen = _read_runpod_noport_clock(sidecar)   # never raises (S2 contract)
    if first_seen is None:
        _write_runpod_noport_clock(sidecar, ts=now)
        # A1-residue: first observation -> override to RUNNING so polling continues.
        return replace(
            result, status="running", current_phase=RUNPOD_WORKLOAD_OBSERVED_PHASE,
            pid_alive=True, new_milestone=True,
        )
    wedged_for = now - first_seen
    if wedged_for > RUNPOD_WEDGE_K_SEC:
        logging.warning(
            "backend_poll: RunPod %s RUNNING-but-no-port for %.0fs (>%ds K floor) "
            "— host-pinned resume cannot heal; escalating to %s (#664 wedge)",
            handle.pod_name, wedged_for, RUNPOD_WEDGE_K_SEC, RUNPOD_WORKLOAD_WEDGED_PHASE,
        )
        return replace(
            result, status="dead", current_phase=RUNPOD_WORKLOAD_WEDGED_PHASE,
            new_milestone=True, pid_alive=False,
        )
    # A1-residue: within the K floor (subsequent tick) -> still running, keep polling.
    return replace(
        result, status="running", current_phase=RUNPOD_WORKLOAD_OBSERVED_PHASE,
        pid_alive=True,
    )
```

```python
    _failover_dead_gcp_to_runpod guards its relaunch.

                      f"PARTIAL cell(s) on HF (one artifact-kind missing): {gate.partial}. "
                      f"Refusing irreversible terminate (CLAUDE.md halt-criterion #2). "
                      f"Human decision needed."))
```

```python
from dataclasses import dataclass

@dataclass
class _WedgeInputsGate:
    ok: bool                 # safe to terminate
    complete: list[str]      # cells with both raw+store exact sets on HF
    partial: list[str]       # cells with exactly one artifact-kind (BLOCK)
    absent: list[str]        # not-yet-run selected cells (rerunnable, do NOT block)

def _wedged_run_inputs_on_hf(issue: int, handle) -> _WedgeInputsGate:
    """Per-cell three-state inputs-on-HF gate for the irreversible auto-terminate
    (#664 fix (b), M1). Generic by issue so it stays reusable for non-#664
    dispatchers (a dispatcher that declares no per-cell artifacts passes the
    adapters-always-inline-verified check, returning ok=True with empty lists).

    For #664: enumerate the realized grid, classify each cell from ONE fresh
    list_repo_files (EXACT expected file set per S1, not prefix-presence), and:
      * COMPLETE cell (both raw+store exact sets on HF)  -> safe (data preserved);
      * PARTIAL cell (≥1 file of one kind but not the full set)  -> BLOCK (one
        artifact-kind is mid-upload / lost; terminating loses recoverable work);
      * ABSENT cell (no files under either prefix)  -> not-yet-run; rerunnable from
        verified earlier inputs on the fresh pod (A2 _cell_done_anywhere skips the
        complete ones, re-runs these)  -> does NOT block.
    Terminate is allowed iff there are ZERO partial cells."""
    cells = _issue_cells_for_handle(issue, handle)   # for #664: C.realized_grid()
    if not cells:
        return _WedgeInputsGate(ok=True, complete=[], partial=[], absent=[])
    from huggingface_hub import list_repo_files
    files = set(list_repo_files(C.HF_DATA_REPO, repo_type="dataset", revision="main"))
    complete, partial, absent = [], [], []
    for c in cells:
        state = _classify_cell_hub_state(c, files)   # 'complete'|'partial'|'absent' (S1 exact-set)
        (complete if state == "complete" else partial if state == "partial" else absent).append(c.eval_key)
```

### B.4 Acceptance criteria

- **Wedge matures (A1-residue, dead input).** Feeding a fake RunPod handle + a
  live-API stub returning `desiredStatus=RUNNING`, `runtime.ports=[]` across two
  ticks spanning > K=900s, with the INPUT `PollResult(status="dead",
  pid_alive=False)` (the realistic `poll_once` SSH-dead shape,
  `poll_pipeline.py` L2076-2077): the FIRST tick returns
  `status="running", current_phase=RUNPOD_WORKLOAD_OBSERVED_PHASE` (NOT dead —
  this is the A1 fix; a bare-return implementation FAILS this case), and the
  SECOND tick (> K) returns `status="dead",
  current_phase=RUNPOD_WORKLOAD_WEDGED_PHASE`.
- **Within-K stays running (A1-residue).** With the same `status="dead"` input
  and a clock already stamped but `now - first_seen < K`, the helper returns
  `status="running"` (false-positive guard; the orchestrator keeps polling).
- **Malformed-clock fail-soft (S2).** A malformed JSON sidecar OR a non-numeric
  `runpod_noport_first_seen_ts` value, with the live API stubbed RUNNING + null
  ports: `_maybe_escalate_runpod_wedge` raises NO exception, returns a
  non-escalated result (`status != "dead"`, no `terminate_pod` call) — it treats
  the bad clock as "no clock yet" and re-stamps. Mirrors the GCP
  `_read_phase_clock` malformed-clock contract.
- **Port appears.** A pod that exposes a public port on the second tick CLEARS
  the no-port clock and is never escalated (returns the unchanged input result).
- **Status leaves RUNNING.** A pod whose `desiredStatus` leaves RUNNING (EXITED)
  is never escalated by this path (falls to the ordinary dead path).
- **Predicate scope.** `_is_runpod_async_wedge_failure` is True for the wedged
  RunPod handle and False for a GCP/SLURM handle with the same phase string.
- **Per-cell gate — PARTIAL blocks (M1).** `_failover_wedged_runpod` with a HF
  listing where one selected cell has its raw prefix but is MISSING `tensors.pt`
  (a PARTIAL cell): `_wedged_run_inputs_on_hf().ok` is False, `terminate_pod` is
  NOT called, returns `reason="runpod_wedge_inputs_unverified"`.
- **Per-cell gate — mid-sweep ALLOWS (M1, the headline case).** With 32 selected
  cells, 10 COMPLETE on HF (both exact sets) and 22 ABSENT (no files), the gate
  returns `ok=True` (terminate ALLOWED) — it does NOT block on the 22 not-yet-run
  cells. `terminate_pod` is called once, then `_relaunch_fresh_runpod`.
- **Idempotency.** A second tick on the OLD handle short-circuits (no
  double-terminate).

```markdown
`desiredStatus` is decoupled from `runtime.ports`: a degraded host keeps the pod
RUNNING (and billing) while `runtime.ports` is empty, so `runpod_api._parse_pod`
yields `ssh_host=None`. `resume_pod` is HOST-PINNED (`podResume{podId, gpuCount}`,
no host reselection) — stop+resume returns to the SAME dead host. `--refresh-from-api`
is a NO-OP here (the port is platform-absent, not stale — that flag fixes the #488
stale-port case).

**Detection** (`backend_poll._maybe_escalate_runpod_wedge`, the RunPod sibling of
`_maybe_escalate_gcp_wedge`): a RunPod handle whose LIVE `desiredStatus=RUNNING`
with null/empty `runtime.ports` past `RUNPOD_WEDGE_K_SEC` (default 900s, env
`EPM_RUNPOD_WEDGE_K_SEC`, mirroring `GCP_STALENESS_FLOOR_SEC`) is rewritten to
`status=dead, current_phase=RUNPOD_WORKLOAD_WEDGED_PHASE`. Within K, an
SSH-dead poll (poll_once returns status=dead on probe failure) is REWRITTEN to
`status=running` (`RUNPOD_WORKLOAD_OBSERVED_PHASE`) so the orchestrator keeps
polling until the wedge matures — a bare pass-through would stop on ordinary dead
before K. The no-port clock is fail-soft (atomic tmp+rename, never raises on a
malformed/non-numeric value — same contract as the GCP `_read_phase_clock`).

**Recovery** (`backend_poll._failover_wedged_runpod`, gated on a PER-CELL
inputs-on-HF gate): once `_is_runpod_async_wedge_failure` matches, the per-cell
three-state gate (`_wedged_run_inputs_on_hf`) classifies each selected cell —
COMPLETE (both raw+store EXACT sets on HF) is safe, a PARTIAL cell (one
artifact-kind missing) BLOCKS, a NOT-YET-RUN cell does NOT block (rerunnable from
verified earlier inputs). With zero partial cells, `terminate_pod` stops the
billing leak and a FRESH pod is re-provisioned (NOT a host-pinned resume) + the
dispatcher resumed idempotently (durable lease + sidecar sentinel, exactly once);
the fresh pod's P2 dispatcher skips HF-complete cells (`_cell_done_anywhere`).
Any partial cell → NO terminate, surface a `failure_class: infra` block.

This closes the #664 gap. The complementary `cmd_resume` advice split (a still-null
resume names terminate+re-provision, not the wrong `--refresh-from-api`) lives in
`pod_lifecycle.py:cmd_resume`.
```

### 11. Decision rationale

**K-seconds wedge-detection threshold.**
- **What:** `RUNPOD_WEDGE_K_SEC = 900` (15 min), env-overridable via
  `EPM_RUNPOD_WEDGE_K_SEC`.
- **Why:** A wedge must be distinguished from the normal boot/resume window.
  `runpod_api.wait_for_ssh` polls with a 600s timeout (verified at L723); a
  healthy pod exposes its port well within that window. K=900s = 600s + a
  300s retry margin guarantees the floor sits ABOVE the longest legitimate
  no-port interval, so a healthy mid-resume pod never trips.
- **Source:** `backend_poll.py:GCP_STALENESS_FLOOR_SEC = 900` (L104) — a prior
  internal decision (#669) for the GCP sibling; this is an exact mirror, which
  also keeps both backends' wedge floors identical. The `wait_for_ssh timeout=600`
  lower-bound is `runpod_api.py` L723.
- **Alternatives considered:** 600s (= bare `wait_for_ssh`) — rejected, leaves no
  retry margin; 1800s — rejected, doubles the billing-leak window for no benefit
  and diverges from the GCP floor.

**HF rate-limit batching strategy.**
- **What:** one `upload_folder` commit per artifact-kind per cell (eval JSONs +
  store tensors = 2 commits/cell), NOT per-file commits.
- **Why:** `huggingface_hub` enforces 256 repository commits/hr. A per-FILE loop
  (the existing P3 `hub._upload(..., upload_as_file=True)` shape) would blow the
  cap on a multi-file-per-cell sweep; `upload_folder` batches an entire cell-dir
  into ONE commit. A 16-32-cell sweep is ≤64 commits/hr, well under the cap.
- **Source:** `.claude/rules/upload-policy.md` § "HF Hub rate limit: 256
  repository commits per hour" + incident #488 (41/324 silent upload losses from
  per-cell commits).
- **Alternatives considered:** keep per-file `hub._upload` per cell — rejected,
  multiplies commits by files-per-cell; one bulk commit for the WHOLE sweep at
  the end — rejected, that IS the write-at-end anti-pattern #664 exposed.

**Exact-file-set completeness check (S1) — not prefix-presence / count-only.**
- **What:** `_cell_artifacts_on_hub` / `_classify_cell_hub_state` and the
  terminal P3 store verify check the EXACT expected file set per artifact-kind
  (`_expected_eval_files(cell)` ⊆ on-Hub eval set AND `_expected_store_files()` ⊆
  on-Hub store set), never `any(p.startswith(prefix))` or `len(landed) <
  n_expected`.
- **Why:** a mid-`upload_folder` crash or a pre-existing partial leaves one file
  under a cell prefix; prefix-presence reads that as complete, the cell is
  skipped, and the irreversible auto-terminate gate (M1) would destroy the other
  artifact-kind's recoverable work. Count-only has the same hole (one extra
  stray file can mask one missing expected file). The construct the gate needs is
  "is the EXACT deliverable set present", which only an exact-set check answers.
- **Source:** the round-1 reconciler Statistics verdict (S1); ground truth read
  at plan time — eval-JSON set from `issue664_eval._judging_surface` (L103-133) +
  `gen_cell` (L215-216), store set from `issue664_extract_store.py` (L335-355).
- **Alternatives considered:** prefix-presence (v2 sketch) — rejected, partial
  reads as complete; count-only (production verifies, L1191/L1240) — rejected,
  a stray file masks a missing one. The exact-set helper imports the gen phase's
  own `_judging_surface` so it cannot drift.

**Per-cell vs all-cells inputs-on-HF gate (M1) — THE auto-migrate enabler.**
- **What:** `_wedged_run_inputs_on_hf` classifies EACH selected cell into
  `complete | partial | absent` and allows terminate iff there are ZERO partial
  cells; not-yet-run (absent) cells do NOT block, completed cells are safe, and
  only a half-uploaded (partial) cell blocks.
- **Why:** `_select_cells` returns the FULL realized grid
  (`issue664_common.realized_grid()`, ~64 cells; verified L145-181 + L646-679).
  An all-selected-cells gate (the v2 mirror of `_cell_artifacts_on_hub` over the
  selected set) requires EVERY cell on HF, which is FALSE at the exact moment the
  fix is for — a mid-sweep wedge where 10 of 32 are complete and 22 are
  not-yet-run. That gate would refuse to terminate the #664-class wedge and the
  auto-migrate would never fire. The per-cell three-state gate terminates the
  mid-sweep wedge (data-safe: complete cells are on HF, not-yet-run cells re-run
  on the fresh pod via A2's `_cell_done_anywhere`) while still BLOCKING the one
  genuinely-unsafe case (a partial cell whose half-uploaded artifact-kind would
  be lost).
- **Source:** the round-1 reconciler Methodology verdict (M1, binding REVISE);
  `_select_cells` L145-181 + `realized_grid` L646-679 (full sweep set).
- **Alternatives considered:** (i) all-cells gate (v2) — REJECTED, defeats the
  fix's primary use case (the mid-sweep wedge never terminates). (ii) downgrade
  the auto-migrate claim to "auto-terminate only after full-sweep upload" — 
  REJECTED, it abandons the mid-sweep recovery that is exactly the #664 scenario;
  the per-cell gate keeps the data-safety guarantee without the all-cells cost.

**P2/P3 HF-presence resume key (A2, design choice: SKIP).**
- **What:** the P2 `WaveDispatcher` `is_done` predicate becomes
  `_cell_done_anywhere(c) = _cell_extract_eval_done(c) (local) OR
  _cell_artifacts_on_hub(c) (HF)`; P3 treats "all selected cells complete on HF"
  as success (no "NO raw completions" raise on an empty-local fresh pod). SKIP,
  not hydrate.
- **Why:** after fix (b) auto-terminates + re-provisions a FRESH pod, HF-complete
  cells are locally absent. The v2 design only added the HF skip to P3 UPLOAD,
  NOT to the P2 `is_done` (L1431, local-only `_cell_extract_eval_done`), so the
  fresh pod would re-run every HF-complete cell (wasted compute) and P3 could
  raise on missing local raw files — making the "loses at most one cell"
  data-safety claim false-as-written. SKIP delivers the claim with no extra
  bandwidth: a cell complete on HF is marked done and never re-run, and the only
  downstream P2 consumers of the local bytes (the per-cell upload — skipped when
  on Hub — and P3 — made HF-aware) do not need them local.
- **Source:** the round-1 reconciler Alternatives verdict (A2, binding REVISE);
  `_cell_extract_eval_done` L1017-1028, P2 `is_done` lambda L1431.
- **Alternatives considered:** (i) HYDRATE (download HF prefixes to local before
  P2) — rejected, adds bandwidth + complexity for no benefit, since downstream P2
  code does not read the local files after P2 (manifest/readability inputs
  handled by Assumption 21; narrow hydrate is the fallback only if that fails).
  (ii) DOWNGRADE the claim to human-driven-recovery-only — rejected, it reduces
  the auto-migrate's value (a fresh pod re-running completed eval is not the
  promised behavior); SKIP delivers the actual claim.

**Within-K override to running (A1-residue).**
- **What:** `_maybe_escalate_runpod_wedge` returns
  `replace(result, status="running", current_phase=RUNPOD_WORKLOAD_OBSERVED_PHASE,
  pid_alive=True)` on both within-K branches (first observation + subsequent),
  NOT a bare `return result`.
- **Why:** `poll_pipeline.poll_once` classifies an SSH-probe failure (`not

  treats it as ordinary death and STOPS before K elapses — the wedge clock never
  matures and the auto-migrate never fires. Overriding to running keeps the poll
  loop alive until the wedge matures (or clears).
- **Source:** the round-1 reconciler Alternatives verdict (A1-residue);
  `poll_pipeline.py` L2076-2077.
- **Alternatives considered:** bare `return result` (v2 pseudocode) — rejected,
  passes a vacuous `status="running"` test but FAILS the realistic `status="dead"`

- **Source:** `.claude/skills/issue/SKILL.md` § Step 8 (the
