## 4. Design / Method delta

N/A — no hyperparameters in this task type.

**Design fork resolution — Option A (guidance-only), recommended.** The brief's Option B constraints (a)-(c) are moot under the merge-form design: because the merge records ancestry, the pointer convergence is performed by the helper's OWN already-tested pull pipeline (autostash for dirty files, collision sweep + journaled restore for untracked, single-flight flock) on the very next run — the only "materialization" is the ordinary pull every successful sync already performs. A `--converge` mode would re-implement, with fresh blast radius on the shared root's HEAD/index, machinery that already exists and is pinned by the module's 63-test suite. The candidate sketch's own mechanism (rebase-to-empty + root `reset --soft` + index sync) is additionally WRONG on semantics: scenario 2 proves the rebase shape does not converge, and a root `reset --soft` leaves the full old-tree-vs-origin delta staged on the always-dirty root where any concurrent plain `git commit` sweeps it. Guidance-only, merge-form, is the whole fix.

**Method delta vs the current abort message (#1234's rewire):** the current recipe stops at "resolve, commit, push" (content-landing only). The new recipe (1) switches the scratch operation from implicit-resolve (typically realized as cherry-pick/rebase) to an explicit `git merge <local-tip>`, (2) adds the re-run step that completes convergence, (3) adds the `-s ours` variant for the already-landed/discard case (the correct form of the sketch's "resolve to origin's side"), (4) names the stranded commits, (5) adds the never-hand-converge warning.
