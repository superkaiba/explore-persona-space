# Plan v2 — #2079 workflow-fix: lint cross-module sha-pin domain agreement (#1776/#1491 class)

**Kind:** infra (workflow-fix; `workflow_fix_target: scripts/workflow_lint.py`, fingerprint b2f4d8aa5352)
**TDD:** no

## 1. Goal / requirement

Add a `workflow_lint.py` check (`--check-sha-pin-domain`, bundled into the no-flags
default run) that catches the #1776/#1491 wrong-domain sha-pin class at lint time: a
64-hex pin duplicated across modules where a NEW site copies the pin without declaring
— or while declaring a conflicting — content DOMAIN (INDEX vs PROMPT etc.).

**Acceptance criteria:**
1. A fixture reproducing the exact #1491 pre-fix shape (a new module binding
   `2e307fb2…`-style hex as `VAL_SHA256` with no domain token and no annotation,
   while the pin also exists in another module) FAILs the check.
2. A fixture with two sites declaring CONFLICTING domains (one INDEX, one PROMPT)
   FAILs the check.
3. The CURRENT live tree yields ZERO sha-pin-domain failure rows (the check itself,
   scoped: `--check-sha-pin-domain` emits no rows; the no-flags default run adds no
   NEW failure lines vs the plan-time baseline — pre-existing red on other checks is
   out of scope, per the Step 10d baseline-subtracted gate) — via
   (a) `# SHA_PIN_DOMAIN: INDEX` annotations on the founding-class pin sites and
   (b) a FROZEN grandfather set for the remaining legacy duplicated hexes.
4. A live-tree invariant test (the `test_live_trees_pass` / `JUDGE_PIN_LEGACY_ALLOWLIST`
   pattern) locks the grandfather set to today's tree: a NEW undeclared cross-module
   pin site cannot be silently absorbed by widening the allowlist without a reviewed
   edit + inline reason.
   Fail-loud pin: tests/test_workflow_lint_sha_pin_domain.py — its live-tree invariant
   asserts a stale grandfather entry raises a lint FAIL row (never silently kept) and
   its unit fixtures assert the undeclared-copy case FAILs rather than being silently
   swallowed.
5. No-flags bundling is pinned by `test_check_sha_pin_domain_bundled_in_no_flags` in
   tests/test_workflow_lint_sha_pin_domain.py (house convention; in-process
   drifted-tree shape), so a later dispatch refactor cannot silently unbundle it.

## 2. Method delta (vs status quo)

Status quo: the rule exists ONLY as prose (`.claude/rules/gotchas.md:314` "A sha pin
lives in a DOMAIN"; `.claude/rules/artifact-reuse.md` check (f)). Two incidents on the
identical constants (#1776, then #1491 through planner + critic ensemble + 5
code-review rounds) prove prose-only enforcement fails. Delta: mechanical enforcement
in the same linter that owns the repo's other ratchet gates, calibrated so the current
tree is green by construction (grandfather), with declaration required for all NEW
cross-module pin sites.

## 3. Predicate (calibrated against the live tree — measured 2026-08-05)

Scan set: `scripts/*.py` + `src/explore_persona_space/**/*.py` (NOT `tests/` — test
fixtures legitimately re-pin; NOT non-.py files — JSON provenance/banks excluded).

1. Collect 64-hex string literals (`re: \b[0-9a-f]{64}\b` inside a quoted string) →
   `{hex: [(file, binding_name, lineno)]}`. `binding_name` = the same-line assignment
   target (`NAME = "<hex>"`), the same-line dict key (`"pinned_val_sha256": "<hex>"`),
   else the nearest preceding assignment target within 5 lines (multi-line
   list/dict literals), else `<bare>`.
2. Keep hexes appearing in ≥ 2 DISTINCT modules.
3. Per site, resolve a DOMAIN:
   - an adjacent `# SHA_PIN_DOMAIN: <TOKEN>` comment (same line, or the immediately
     preceding line) wins;
   - else a vocabulary token in the binding name (case-insensitive word match):
     `INDEX | IDS | PROMPT | BYTES | CONTENT`;
   - `# SHA_PIN_DOMAIN_EXEMPT: <reason>` (same/preceding line) exempts the SITE.
4. FAIL cases (each emits one `workflow_lint: sha-pin-domain/<file>:<line> …` row):
   - **conflict:** ≥ 2 sites resolve to DIFFERENT domains (INDEX vs PROMPT, …);
   - **undeclared:** a site resolves NO domain and its `(hex-prefix-12, file)` pair is
     NOT in the frozen grandfather set `SHA_PIN_DOMAIN_GRANDFATHER`.
5. Grandfather grain is `(hex[:12], file)` PAIRS — so a grandfathered hex copied into
   a NEW file still FAILs (exactly the #1491 propagation vector), while today's legacy
   sites stay green. Each entry carries an inline `# reason`.

**Why declaration-required (not conflict-only):** the #1491 pre-fix bindings were
`VAL_SHA256`/`TEST_SHA256` — NO site carried any domain token (producer #1776:
`VAL_400_SHA`; #779: `ORIG_VAL_SHA256`; #1482: `pinned_val_sha256`), so a
conflict-only predicate provably misses the founding incident. Declaration-required +
per-(hex,file) grandfather catches it: the new module's undeclared copy FAILs.

**Measured false-positive base (live tree, 2026-08-05):** 14 distinct 64-hex literals
appear in ≥ 2 modules across scripts/+src/ (.py). Of these: 2 are the founding pins
(annotate INDEX — domain proven by the #1491 fix commit 9f43b03e43: fixed_split
int64 INDEX-array digests); ~2 resolve only in non-.py files (drop out of scope);
the remaining ~10 (I594_PROBE_POOL_HASH ×3, holdout_sha256 ×3, sae_fit_sha256 ×2,
G1/ULTRACHAT_PROBE_POOL_HASH, EVAL_BANK ×2, TRACKS_PROMPT_SHA256/TRACKS_SHA256,
BUNDLE_SHA256 ×2, SYCOPHANCY_CLAIMS ×2, issue922 bare ×2, issue650/612 bare ×2)
grandfather with reasons — ~20-24 (hex,file) pairs, well under the ~30-entry kill
threshold (§7). The implementer regenerates the exact inventory from the tree at
implementation time (the measured preview is the sizing basis, not the frozen list).
