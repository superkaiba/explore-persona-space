## 1. Goal / requirement + acceptance criteria

(Task #1668 Goal, verbatim, re-read 2026-07-25:) "When an owning session ADOPTS a replacement pod after a wedge-failover, the poll/tick lane must resume reading live state instead of returning terminal-wedge forever."

**Requirement.** After a wedge-failover re-points the handle sidecar at a fresh RunPod attempt, subsequent poll/tick reads on that fresh attempt must follow NORMAL wedge semantics — within-K no-port reads keep polling (`RUNPOD_WORKLOAD_OBSERVED_PHASE` override), a genuinely matured new wedge earns its own single failover — never the terminal `runpod_wedge_already_handled` minted from a stale record. Simultaneously preserve, per the DESIGN CAUTION: (a) stale records never blind a NEW attempt; (b) the escape never routes a healthy adopted pod into the terminate path by itself (a new attempt must mature its own no-port clock, K ≥ 900 s across ≥ 2 observations, before any failover); (c) exactly-once PER WEDGE for a re-fired tick on the SAME wedged attempt (#689); (d) the durable-lease-survives-cache-failure property (#689 blocker-2).

**D1 — attempt-keyed identity (the fix).** Replace `_runpod_handle_identity` (line 1814):

```python
def _runpod_handle_identity(handle) -> dict:
    """The identity of a RunPod handle, for wedge / CUDA-IMA record matching (#1668).

    On RunPod, ``pod_name`` is the canonical issue-derived ``pod-<N>`` and
    ``job_id`` is ``""`` (launch does not capture the pod_id), so
    ``(pod_name, job_id)`` is DEGENERATE PER ISSUE — a fresh re-provision keeps
    the SAME name, and a record keyed on it turns "exactly once per wedge" into
    "once per issue forever" (#1586). ``extra.runpod_attempt_id`` (minted per
    launch, #598) is the per-attempt discriminator: included whenever present.
    A LEGACY handle without it keeps the 2-key identity (pre-#598 sidecars —
    which also cannot relaunch: ``runpod_wedge_relaunch_spec_missing``).
    Unlike :func:`_gcp_handle_identity`, where job_id is the per-create
    instance id and already discriminates attempts.
    """
    identity = {
        "pod_name": getattr(handle, "pod_name", None),
        "job_id": getattr(handle, "job_id", None),
    }
    extra = getattr(handle, "extra", None)
    attempt = extra.get("runpod_attempt_id") if isinstance(extra, dict) else None
    if attempt:
        identity["runpod_attempt_id"] = attempt
    return identity
```

All 8 sites already flow through the helper, so **no other logic changes**: sentinel writes (`_write_runpod_wedge_sentinel` :1854, `_write_runpod_cuda_ima_sentinel` :2274), sentinel compares (`_runpod_wedge_already_handled` :1945, `_runpod_cuda_ima_already_handled` :2309), lease compares (`_lease_records_runpod_wedge_failover` :2669, `_lease_records_runpod_cuda_ima_failover` :2752), lease stamps (`_stamp_runpod_wedge_failover` :2703, `_stamp_runpod_cuda_ima_failover` :2830). ## 10. §11 Decision Rationale

1. **Identity fields = (pod_name, job_id, + runpod_attempt_id when present).** Why: pod_name/job_id are degenerate per issue on RunPod; the attempt id is the only per-launch discriminator already persisted in the sidecar. Source: backends/runpod.py:257/944/1021 (#598 minting); clarifier root-cause refinement on #1668; #1586 markers (05:42Z watcher failover, 08:43Z suppressed second wedge). Alternatives rejected: pod_id (not captured on the handle — runpod.py:1073-1079 truthful-empty comment); `epm:run-launched` recency (unsafe escape per the DESIGN CAUTION; adds a markers read to the poll hot path); sentinel mtime (not attempt-attributable).
2. **Legacy-record fail-direction = fail-toward-live-poll.** Why: fail-toward-short-circuit deadlocks (the short-circuit forecloses the superseding stamp, preserving #1668 per-issue forever); the double-fire cost is the module's already-accepted bounded worst case, and measured exposure is one completed-run record. Source: backend_poll.py:1930-1933 + 2649-2651 (the existing worst-case posture); the 2026-07-25 sweep (§7); incident #1586 (silent suppression is the demonstrated harm; #664 established terminate-and-reprovision as the correct action for a matured wedge).
3. **No `epm:run-launched` secondary escape.** Why: unnecessary (both lanes re-point the sidecar — evidence in §3-D6) and unsafe as an escape (routes a non-matured pod toward terminate).
