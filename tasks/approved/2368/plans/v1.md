# Plan v1 — #2368: harden the first-quote `ssh_cmd` payload extractor in `tests/test_bootstrap_pod_git_credentials.py`

## Requirement + acceptance criteria

Requirement (from the task body): `_single_quoted_ssh_cmd_blocks` in
`tests/test_bootstrap_pod_git_credentials.py:69-85` closes every `ssh_cmd '...'`
block at the FIRST following `'`. A payload that continues past that quote via
bash's standard quote-embedding idiom (close-quote, escaped quote, reopen-quote)
is silently truncated, and the negative assertion at line 200
(`"GIT_CRED_HELPER" not in block`) never inspects the tail — the test stays
green while the uninspected part regresses. Same defect family as #2360's
blockers B1/B5; the landed #2360 fix is the reference implementation.

Acceptance criteria (verbatim from the task body):
1. A quote inserted after the guarded region makes the extractor FAIL rather
   than silently truncate (mutation test, required to go red).
2. The extracted interior is asserted quote-free.
3. Every remaining first-quote payload extractor under `tests/` is either
   hardened or has a recorded reason it is safe.

## Method delta

Reference implementation: `_step10_payload` +
`test_mutation_quote_after_invocation_guard_fails_extraction` in
`tests/test_bootstrap_pod_uv_link_mode.py` (#2360, on main). That extractor
slices ONE heredoc-delimited payload to a standalone closing-delimiter line;
this file's extractor instead walks MULTIPLE inline `ssh_cmd '...'` blocks, so
the port is adapted: a TERMINATOR CHECK after each closing quote replaces the
standalone-delimiter-line slice. The mutation-test principle ports unchanged.

Plan-time facts (verified 2026-08-27):
- `scripts/bootstrap_pod.sh` has 6 single-quoted `ssh_cmd '` blocks; every
  closing quote is followed by a newline; zero occurrences of the
  quote-embedding continuation idiom. The hardened extractor therefore PASSes
  on the real script unchanged.
- Repo sweep (`grep -rn "index(\"'\"" tests/*.py` and find/split variants)
  finds exactly ONE first-quote payload extractor under `tests/`: the flagged
  one. Two same-family adjacent sites in the same file get recorded-reason
  treatment (see Design step 3).

## Design

**Step 1 — harden the extractor** (`_single_quoted_ssh_cmd_blocks`):
- After computing `close_q = text.index("'", open_q)`, inspect the character
  AFTER the closing quote. It must be a genuine payload terminator: end-of-text,
  whitespace (space / tab / newline), or one of `;`, `)`, `|`, `&`. Any other
  character — notably `\` (the quote-embed continuation), or an adjacent `'` /
  `"` (string concatenation) — means the logical payload continues past the
  first quote: `pytest.fail` with a message naming the byte offset and the
  following characters, so truncation cannot pass silently.
- Assert `"'" not in block` for every extracted block (defense in depth —
  trivially true under today's logic, pins the invariant against a future
  extractor rewrite).
- Rewrite the docstring: the current justification ("single-quoted bash strings
  cannot contain a single quote") is true of one literal but FALSE of the
  logical payload under the embed idiom; state the terminator-check rationale
  and the documented limitation (a future legitimate embed idiom needs a
  continuation-parsing extractor, not a weaker check).

**Step 2 — mutation tests** (new, same file):
- `test_mutation_quote_embed_continuation_fails_extraction`: copy the real
  script text; at the first single-quoted `ssh_cmd '` block's closing quote,
  splice in a quote-embed continuation carrying a sentinel
  (`GIT_CRED_HELPER`-bearing tail). Assert the hardened extractor FAILS
  (`pytest.raises(pytest.fail.Exception)` / `Failed`). Under the OLD extractor
  this mutation provably yields a truncated block and stays green — state that
  in the docstring (that is the red-direction evidence the acceptance demands).
- Parametrize a second mutation case: adjacent double-quote concatenation
  (`'"..."'`) after the closing quote — also must FAIL extraction.

**Step 3 — sweep dispositions** (recorded in code comments + implementer
report):
- `_helper_assignment_value_raw` (same file, lines 62-66): NOT a first-quote
  scan — it takes the whole assignment line, asserts a terminal double quote,
  and slices prefix/suffix, so embedded escaped quotes are INCLUDED, not
  truncated. Record as safe with that reason.
- `test_existing_repo_branch_retrofits_tokenless_remote` (`text.index("else",
  start)`): first-OCCURRENCE keyword scan, same family but all its assertions
  on the slice are POSITIVE (must-contain / ordering via `.index` which raises
  on absence), so truncation fails LOUD (false red), never silently green.
  Record as safe with that reason.
- Any additional hit the implementer's own sweep finds: harden if its
  assertions are negative-direction, else record the direction argument.
