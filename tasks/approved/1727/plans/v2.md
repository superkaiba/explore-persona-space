**Task:** #1727 (`kind: infra`, `workflow: v1`, workflow-fix)
**Goal (verbatim from body):** Add a code-review check that every `*_smoke` / `*_full` variable pair in a dispatcher diff is gated on the same smoke predicate, so a smoke-scoped list can never ship as the production default.

## 3. Design

### 3.1 The new gate — `Step 0.70: Smoke-variable gating (any diff type; bash dispatchers only)`

Insert AFTER Step 0.69's Verdict-record line (`.claude/agents/code-reviewer.md` around L1080) and BEFORE Step 0.7 "Pre-diff gates never short-circuit the diff" (L1082). Keep the identical section-header shape, sub-check numbering, verdict-routing form, waiver form, and `N/A —` escape phrase as Step 0.69, so the new step reads as its natural next-of-kin.

**Trigger — does the diff contain any `<name>_smoke=` declaration or any `<name>="$<name>_smoke"` assignment in a bash dispatcher?** Grep each dispatcher file (`scripts/*dispatch*.sh` and any other `.sh` bash script in the diff) for BOTH:

```bash
# Declaration side — a `_smoke` variant defined:
grep -nE '^[[:space:]]*(local +)?[a-z_][a-z_0-9]*_smoke=' <each dispatcher .sh in diff>
# Assignment side — a live variable pinned to the `_smoke` variant (the load-bearing signature):
grep -nE '^[[:space:]]*(local +)?[a-z_][a-z_0-9]*="\$[a-z_][a-z_0-9]*_smoke"' <each dispatcher .sh in diff>
```

The trigger fires when EITHER grep hits ≥1 line. **The presence of a sibling `<name>_full=` is NOT required to trigger** — the load-bearing signature is a live variable pinned to a `_smoke`-suffixed source without a `$SMOKE`-conditional fallback, and the pre-R13 #1689 bug (`local conds_smoke="assistant_chat"` + `local conds="$conds_smoke"` with NO `conds_full=` at all — `git show 15906d680a^:scripts/issue1689_dispatch.sh` L134-135) is exactly this shape. Not a trigger — a file with no `_smoke` mentions: record `Step 0.70: N/A — diff carries no smoke-scoped variable` and proceed.

**Sub-check (1) — every live `<name>="$<name>_smoke"` assignment has a `$SMOKE`-guarded fallback.** For each `<name>="$<name>_smoke"` hit from the assignment-side grep above, verify ONE of the following is present in the SAME enclosing function/block:

- **(a) Bidirectional-pair pattern (PREFERRED — the shape `models` already had in #1689).** The dispatcher declares both variants and assigns the FULL variant FIRST as the default, then re-assigns the SMOKE variant behind a `$SMOKE` gate on the same variable. Concretely:
  ```bash
  local <name>_smoke="..."
  local <name>_full="..."
  local <name>="$<name>_full"           # default = full
  [ -n "$SMOKE" ] && <name>="$<name>_smoke"   # smoke override
  ```
  This is what R13's fix landed for `conds` (see L105-108 of the fixed dispatcher).
- **(b) In-line SMOKE guard on the SAME variable.** The `<name>="$<name>_smoke"` line is itself inside a `[ -n "$SMOKE" ] && <name>=...` command, an `if [ -n "$SMOKE" ]; then <name>=...; fi` block, or an equivalent parameter-expansion form that reads `$SMOKE` in the SAME command (`${SMOKE:+"$<name>_smoke"}`, `${SMOKE+...}`, etc.).
- **(c) Explicit waiver.** A `# SMOKE_VAR_UNGATED_EXEMPT: <reason ≥ 20 chars>` comment on the line above the assignment (waiver form below). Credits PASS.

An UNGATED `<name>="$<name>_smoke"` assignment — no bidirectional-pair fallback (`<name>="$<name>_full"` before it in the same enclosing block), no in-line `$SMOKE` guard, no waiver — FAILs sub-check (1). This is the pre-R13 `run_phase_capture`'s `local conds="$conds_smoke"` shape (`git show 15906d680a^:scripts/issue1689_dispatch.sh` L135).

**Sub-check (2) — no hardcoded smoke-scoped literal masquerading as production default.** In the SAME enclosing function/block as a `<name>_smoke=` declaration, flag any assignment to a live loop-driving variable whose value is a hardcoded string that MATCHES the `<name>_smoke` variant's value (or is a subset of the `<name>_full` variant's value when `_full` is also declared) AND has no `$SMOKE`-conditional override. This catches the pre-R13 `run_phase_fit_cells` shape (L158: `local model_slug="Qwen_Qwen2.5-7B-Instruct"` where `models_smoke="Qwen_Qwen2.5-7B-Instruct"` was declared in the sibling `run_phase_capture` earlier in the file — the hardcoded literal was the smoke value). Sub-check (2) fires ONLY when a `<name>_smoke=` declaration is present somewhere in the file and a live sibling assignment hardcodes a value equal to that `_smoke` variant's contents. Waiver: same `# SMOKE_VAR_UNGATED_EXEMPT: <reason ≥ 20 chars>`.

**Sub-check (3) — orphaned `_full` variant (dead-code signal).** If a `<name>_full=` variable is declared but no code path assigns it to a live `<name>` (grep for `<name>="$<name>_full"`), record as sub-check (3) FAIL with tag `smoke-var-orphan-full`. This is a related-but-distinct diagnostic (dead-code signaling intent; the reviewer should ask whether the dispatcher meant to use the full variant and forgot). Separately tagged so it does not fuse with the primary `smoke-var-ungated` FAIL.

**Waiver form** (mirrors Step 0.69's `# PHASE_IDEMPOTENCY_EXEMPT:` waiver): `# SMOKE_VAR_UNGATED_EXEMPT: <reason ≥ 20 chars>` on the line above the ungated assignment. Credits PASS.

**Verdict routing — sub-checks (1)/(2)/(3):**

- All hits pass sub-checks (1) + (2) or carry a valid waiver, AND no orphaned `_full` variant → PASS.
- Any sub-check (1) FAIL (ungated `<name>="$<name>_smoke"`) OR sub-check (2) FAIL (hardcoded smoke-scoped literal) → verdict FAIL with a single `Critical` issue tagged **`smoke-var-ungated`** (SUBSTANTIVE — never stripped by Step 5c-bis):

  > `epm:experiment-implementation v<n>`'s dispatcher `scripts/<file>` at
  > line `<L>` assigns `<var>="$<var>_smoke"` (or hardcodes the smoke-scoped
  > literal to a live loop-driving variable) with no bidirectional-pair
  > fallback (a `<var>="$<var>_full"` default before it in the same enclosing
  > block, re-assigned to `_smoke` behind `[ -n "$SMOKE" ]`) and no in-line
  > `$SMOKE` guard. This silently ships the smoke-scoped list as the
  > production default — the #1689 shape (2026-07-26, session `5c5a89e8`,
  > commit `15906d680a`): `run_phase_capture` had `local conds_smoke="assistant_chat"`
  > + `local conds="$conds_smoke"` (L134-135 of the pre-R13 dispatcher, NO
  > `conds_full=` declaration at all) with the `$SMOKE` gate on the SIBLING
  > `models` variable but never on `conds`, silently collapsing a 21-condition
  > lattice to 1 condition through eight implementer / review rounds. The
  > store path `analysis_tensors/issue_1689/store/Qwen_Qwen2.5-7B/assistant_naturalistic/L14.pt`
  > was never written because the condition was never captured. Re-post
  > `v<n+1>` adopting the bidirectional-pair pattern (declare `<var>_full=`,
  > default `<var>="$<var>_full"`, then `[ -n "$SMOKE" ] && <var>="$<var>_smoke"`
  > — the shape `models` ALREADY had in the same file), OR add a waiver
  > `# SMOKE_VAR_UNGATED_EXEMPT: <reason ≥ 20c>` naming why the smoke value
  > IS the intended production default.

- Any sub-check (3) FAIL (orphaned `_full` variant declared but never assigned) → verdict FAIL with a single `Major` issue tagged **`smoke-var-orphan-full`** (SUBSTANTIVE — never stripped by Step 5c-bis):

  > `epm:experiment-implementation v<n>`'s dispatcher `scripts/<file>` at line `<L>`
  > declares `<var>_full=...` but no code path assigns it to a live `<var>`.
  > This is the mirror of `smoke-var-ungated`: the intent to have a broader
  > production default is signalled by the declaration but never realized,
  > so the live variable takes whatever the enclosing default is (typically
  > the smoke-scoped variant). Re-post `v<n+1>` either assigning `<var>="$<var>_full"`
  > as the default (with an optional `[ -n "$SMOKE" ] && <var>="$<var>_smoke"`
  > override) or deleting the unused `<var>_full=` declaration.

Record the verdict as one line: `Step 0.70: PASS — <N> smoke-scoped variables correctly gated`, `Step 0.70: FAIL smoke-var-ungated — <var> ungated at <file>:<L>`, `Step 0.70: FAIL smoke-var-orphan-full — <var>_full declared at <file>:<L> but never used`, or `Step 0.70: N/A — diff carries no smoke-scoped variable`.

**Fingerprint-of-degradation clause** (mirrors Step 0.69 § Fingerprint-of-degradation): the gate reads only bash source; a Python dispatcher whose smoke gating lives in `args.smoke` (not shell-visible) is out of scope for v1 — record `Step 0.70: N/A — python dispatcher; smoke gating is arg-level`. A follow-up round can widen to python dispatchers if the same class recurs there.

## 14. Follow-ups (scope-widening classes named in scope prose, per Alternatives critic Concerns)

The gate scopes ONE class in (bash `<name>="$<name>_smoke"` and hardcoded-literal siblings) and scopes THREE known-plausible sibling classes explicitly OUT of v1. If any of these recurs — a fresh `smoke-var-*` variant surfaces after v1 lands — the follow-up widening is:

1. **Python dispatchers with `args.smoke` / `--full` `store_true` defaulting False.** A python driver whose "production default" is opt-in via `--full` (or the inverse — `--smoke` defaulting True) has the same shape. Grep-visible from the diff via `grep -nE 'add_argument.*--(smoke|full).*store_true'` + read the default; extend Step 0.70's Trigger and add a sub-check reading argparse action defaults.
2. **YAML/JSON config with a `conditions_smoke:` key and no `conditions:` fallback.** A dispatcher reading `cfg["conditions_smoke"]` unconditionally against a Hydra/pydantic config that HAS a `conditions_full` key defined but never selected is byte-for-byte the same defect at the config-load layer. Grep-visible from the diff.
3. **Per-cell `CUDA_VISIBLE_DEVICES` / GPU-count assignment scoped by smoke that leaks into production sharding.** Not the #1689 shape exactly, but the same "smoke-scoped variable rides into a production dispatch" class the gate exists to catch — worth naming in scope prose so a future filer knows whether it belongs under Step 0.70 or wants its own gate.

Tradeoff acknowledgment: a review-gate catches at diff time (before pod burn); a smoke-run integration test (executing the ACTUAL production path with `SMOKE=""` and asserting realized-condition-count matches the plan) catches ALL classes above at CI time (after diff, before real launch) — this plan picks the review-gate because it is diff-scoped and cheap, but a future recurrence in a python dispatcher may motivate the smoke-run test as the additional / alternative intervention.
