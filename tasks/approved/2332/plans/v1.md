#### 4.1 Pack format (design decision)

Per-prefix **POSIX tar shards** (uncompressed; target ~2 GiB/shard) + **sidecar index**:

```
<prefix>/__packed__/shard-00000.tar      # members named by original repo-relative path
<prefix>/__packed__/shard-00001.tar
<prefix>/__packed__/index.json           # {orig_path: {shard, offset, size, sha256}}
<prefix>/__packed__/manifest.json        # {n_members, total_bytes, shard_sha256s, src_listing_snapshot_ts}
```

Why tar, not JSONL/Parquet: the prefixes hold heterogeneous file types (JSON cells, and possibly npz/png — census taken in the sizing pass); tar is lossless and byte-exact for ANY member type, keeps original paths as member names (making both reader updates and the conditional accessor mechanical), and gives a single verify path (whole-shard sha256) for all 8 prefixes. JSONL would change reader semantics (parse-a-line vs open-a-file) and cannot hold binary members; Parquet requires schema homogeneity. Uncompressed because members may be incompressible binaries and byte-offset access into an uncompressed tar is O(1); `*.tar` is not `*.gz` (no LFS-forced-gzip concern — shards are LFS anyway by size, which is exactly what enables the sha256 remote verify).

Collision guard: the sizing pass asserts no existing repo path starts with `<prefix>/__packed__/` (fail-loud if one does).

#### 4.5 Phase 3 — venue decision + cap arithmetic (local)

- **Shard plan:** `n_shards(prefix) = ceil(total_bytes / 2 GiB)`; pack-file add `k(prefix) = n_shards + 2` (index + manifest). Expected k ≤ ~12 for byte-heavy prefixes, k = 3 for small ones.
- **Cap arithmetic (encoded assert, re-evaluated before every upload):** `tracked_count + k(prefix) ≤ 1,000,000 − 1,000` (1,000-slot buffer for concurrent fleet writers). `tracked_count` starts from the Phase-2 full count and is updated with each verified batch's realized delta (re-list counts, never assumed). Since the residue move has already freed ≥ ~60k slots and each completed prefix frees tens of thousands more, the transient +k never approaches the cap under any ordering; delete-first is FORBIDDEN by verify-before-delete, and is also unnecessary — the ordering that stays under cap is simply: upload k pack files (+k), verify, then delete N originals (−N), serially per prefix, smallest prefix first.
- **Venue predicate:** if `max_prefix_staged_bytes ≤ 50 GB` (VM_ANALYSIS_FOOTPRINT_GB_MAX) AND `/mnt/eps-data` free ≥ 1.5 × (max prefix bytes × 2 [originals + shards]), the run stays VM-resident (justification in §9). Any single prefix exceeding 50 GB staged routes THAT prefix to a `cpu-bigmem` RunPod pod (`pod.py provision --issue 2332 --intent cpu-bigmem --container-disk-gb <1.5× prefix, ≤240>`), with G-mover checked VM-side immediately before dispatch and no VM-side Hub traffic while the pod phase runs. The pod branch reads ONLY from HF and writes ONLY to HF (no cross-machine file reads) — hence no `off_pod_phases` block is required; stated per the §9 rule.

#### 4.6 Phases 4–6 — the per-prefix repack loop (production entrypoint; pilot = smallest prefix)

Per prefix, `scripts/issue2332_repack_prefixes.py run --prefix <p>` executes, checkpointing `state.json` after every step:

1. **Gates:** G-mover; **G-writer** — owning issue status read from `tasks/REGISTRY.json` (all 8 at `awaiting_promotion`, re-verified at plan time), `spawn_session.py list` shows no live session on the owning issue (EXCEPTION #1739 → G-1739 below), `pod.py list-ephemeral` shows no pod for the owning issue, and no `epm:run-launched`/`epm:followup-scope`/`epm:free-analysis-followup-run` marker on the owning issue newer than its latest done-transition. Any trip → skip prefix, record, continue with the rest.
2. **Source listing** (scoped, recursive) → `src_map = {path: size}`; snapshot ts recorded.
3. **Download** to `STAGE/src/<prefix>/...`: 4 workers, 6 attempts, exponential backoff to 60 s, per-path failure text recorded (mover's `fetch_all` adapted verbatim). Any failure → prefix marked incomplete, staging PRESERVED, source untouched, continue to next prefix. Completeness check: every `src_map` path present locally with matching size.
4. **Pack** into `STAGE/up/<prefix>/__packed__/` (a SEPARATE staging root from the downloads — uploading the stage root must never re-upload the loose originals): stream files into tar shards, record per-member `{shard, offset, size, sha256}`; write `index.json` + `manifest.json`; compute per-shard sha256.
5. **Local pack verify:** re-open each local shard, verify every member's bytes hash matches the staged source file's sha256; member census == `src_map` exactly (names + sizes). Fail → fix or abort prefix; never proceed.
6. **Upload:** `api.upload_large_folder(repo_id=SRC, folder_path=STAGE/up, repo_type="dataset", ignore_patterns=[".cache/**","**/tmp_*","**/*.incomplete"], num_workers=4)`. Exceptions logged, NEVER interpreted (transport ≠ outcome).
7. **Hub-side verify (the only success signal):** scoped `list_repo_tree` on `<prefix>/__packed__` → every shard present, size match, AND `lfs.sha256 == local sha256` (shards are > 10 MB ⇒ LFS ⇒ remote sha256 available without re-download). `index.json`/`manifest.json` (non-LFS): verify via git-blob sha1 (`sha1(b"blob %d\x00" % len + content)`) against the tree's `blob_id`; if `blob_id` semantics differ (assumption A7), fall back to re-download + byte-compare (trivial bytes). Remote sha256 equality is byte-exact proof that the Hub holds the verified local tar.
8. **Pre-delete re-list:** fresh scoped listing of `<prefix>`. Delete set = `src_map ∩ present`, EXCLUDING any path whose current size ≠ `src_map` size (rewritten since pack → excluded, flagged `repack-stale`, kept as loose file — no data loss) and excluding anything under `__packed__/`. Paths present now but NOT in `src_map` (fleet added them since pack) are KEPT and logged loudly. **`delete_folder` on the prefix root is BANNED in this script** (it would destroy the pack) — deletion is explicit-path only.
9. **Batched verified delete:** `create_commit(operations=[CommitOperationDelete(p) for p in batch])`, batch size 1,000 in the pilot, raised to 10,000 after a clean pilot (pilot-gated). Before EACH batch: re-list, delete only paths still present (idempotent-by-construction). On ANY exception: do NOT retry blind — re-list and recompute (a 504 can mask a landed commit, established); loop until the delete set is empty. After the final batch: full scoped re-list asserts the prefix contains ONLY `__packed__/*`.
10. **Checkpoint + cleanup:** `state.json` marks prefix `done {files, bytes, slots_freed}`; `rmtree(STAGE/src/<prefix>)` + `rmtree(STAGE/up/<prefix>)` (incremental — peak disk = one prefix); tracked_count updated from realized re-list deltas.

P5 = `issue2224_screening` → `issue1434_writingstyle` → `issue667_alllayer` → `issue1586_methodgen` → `issue1090_pvdatagen` → `issue1481_conpos_grid` (ascending, machinery proven before the 206k monster).
