## 4. Design

All changes in `scripts/recent_clean_results.py` (+ tests). Follow the file's local-constant convention (it defines its own `SENTINEL_V3`; do NOT import from `verify_task_body.py` — the file deliberately avoids that dependency).

- **D1 — sentinel constant + predicate.** Below `SENTINEL_V3` (line 67) add `SENTINEL_V4 = "<!-- clean-result-v4 -->"`. Below `is_v3_body` (line 88) add a mirror `is_v4_body(body)`. No combined `is_takeaways_body` helper: `fetch_promoted` needs the two predicates SEPARATELY for tier ordering, and the routing site is a one-use `or` expression — a third name buys nothing.
- **D2 — `_extract_markdown` routing (line 214).** Change the routing condition to `RE_MD_TAKEAWAYS.search(body) if (is_v4_body(body) or is_v3_body(body)) else RE_MD_TLDR.search(body)`. `RE_MD_TAKEAWAYS` itself is UNCHANGED — v4 uses the identical `## Takeaways` H2 and the `(?=^##\s+|\Z)` lookahead bounds at `## Goal` exactly as it bounds v3 at `## What I ran`.
- **D3 — `fetch_promoted` preference (lines 150–178).** Add `"v4"` semantics: partition promoted into `[v4] + [v3] + [rest]`, each sub-list keeping recency order. Signature default `prefer_shape: str = "v3"` → `"v4"`. The existing `"v3"` branch stays byte-identical (v3 first, then non-v3 — regression-pinned). CLI: `--prefer-shape` `choices=("v4", "v3", "any")`, `default="v4"`. Rationale for adding a value rather than renaming to `"current"`: zero existing-test churn, `"v3"` keeps a pinned meaning, and a `"current"` alias would still need a code change at v5 anyway (the sentinel must be taught), so the rename buys no mechanism. Rationale for back-filling v3 before v2/legacy: v3 shares the Takeaways headline-skim register (closest to current); v2/legacy carry the retired nested-TL;DR register the preference exists to keep out of the feed.
- **D4 — the limit fix (line 167).** `list_by_status(status="completed", limit=200)` → `limit=10_000`, with a one-line comment naming the ascending-id truncation trap (757 completed today; growth ~10/day ⇒ years of headroom). Cost: 757 frontmatter reads + full hydration of only the ~128 `hasCleanResult` rows — local file I/O, <2 s.
- **D5 — docstrings/comments narrate FOUR generations:** module docstring (lines 14–31, incl. the "Exemplar feed" paragraph + `--prefer-shape` narration), the generation comment block (lines 55–66), `fetch_promoted` + `_extract_markdown` docstrings, the `render_inline` markdown-branch comment (lines 255–257), and the `--prefer-shape` argparse help.

- **Local `SENTINEL_V4` constant (not imported).** What: mirror of `SENTINEL_V3`. Why: the file's existing convention is a local constant; importing `verify_task_body` would add a heavyweight dependency for one string. Source: `recent_clean_results.py:67` convention + `verify_task_body.py:772` (string value). Alternatives: import (rejected — dependency), shared constants module (rejected — over-engineering for a 24-char literal).
- **Two predicates + inline `or` (no combined helper).** Why: `fetch_promoted` tier ordering needs v4 and v3 distinguished; the routing `or` is single-use. Source: read of both call sites. Alternative: `is_takeaways_body` combined-only (rejected — insufficient for D3).
- **Preference order v4 > v3 > rest; add `"v4"` choice, default `"v4"`, keep `"v3"` verbatim.** Why: minimal diff, zero existing-test churn, docstring's own "track the current shape" rationale (`recent_clean_results.py:25–31`), v3 back-fill because it shares the Takeaways register. Source: `.claude/plans/clean-result-v3-redesign.md:208`; #1226 precedent. Alternatives: reinterpret `"v3"` silently (rejected — misleading name), rename to `"current"` (rejected — still needs a code change per generation, breaks the pinned `"v3"` test for no mechanism gain).
- **`limit=10_000` in the `list_by_status` call.** Why: `task_workflow.list_by_status` truncates ascending-by-id at `limit` (src:4713); 757 completed tasks today ⇒ the current 200 silently drops every recent promotion, making both the existing v3 preference and this v4 fix live no-ops. Source: read `task_workflow.py:4705–4733` + live probe 2026-07-11 (first-200 = #13..#572; sole completed v3 body #589 outside the window). Alternatives: fix ordering in `task_workflow.list_by_status` (rejected — shared library, own task if wanted), paginate (rejected — no pagination API), leave at 200 (rejected — ships a dead fix).
- **Docstrings narrate four generations.** Why: the module docstring is the file's spec-of-record; three-generation narration would be actively wrong post-change. Source: file's own docstring discipline.
