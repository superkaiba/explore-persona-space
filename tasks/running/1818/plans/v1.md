## Requirement + acceptance criteria

**Requirement (task Goal):** stop poll recipes composing sleep intervals the Bash tool cap kills.

**Root cause (clarifier-verified, no longer a hypothesis):** `.claude/skills/issue/SKILL.md` Step 6d.2's ADAPTIVE POLL INTERVAL recipe honors the poller's `next_interval` recommendation (`in (540, 1800)`; SKILL.md ~L4618-4620) as the literal sleep composed into ONE background Bash call (`sleep {interval} && uv run python scripts/backend_poll.py --issue N`, ~L4621-4626). The recommendation source is `POLL_INTERVAL_QUIET_SEC = 1800` (`scripts/poll_pipeline.py:498`, duplicated at `src/explore_persona_space/backends/base.py:515`), emitted by `recommend_next_interval` on healthy quiet ticks (anti-stall redesign §7). The Bash tool kills ANY call at its 600000 ms ceiling — background calls included — so every quiet-tick 1800 s sleep is a doomed call: the sleep dies at ~600 s, the poll never runs, and the next wake reads a stale/absent poll result (incident #1768, 2026-07-28). The §7 turn savings the 1800 s interval was designed to buy have therefore never been realized in production — a 1800 tick costs the same wake cadence as ~540 while delivering NO poll data, strictly worse than 540.

**Acceptance criteria:**
1. The Step 6d.2 pseudocode composes a fixed 540 s sleep — the `interval = result["next_interval"]` honor branch is REMOVED; 540 is stated as both the default AND the per-call maximum.
2. The ADAPTIVE POLL INTERVAL comment block carries the clamp rule explicitly: never compose a sleep longer than 540 s into a single bg-Bash (the 600000 ms tool ceiling kills it, background included; cites #1768), a longer cadence is realized only as consecutive ≤540 s ticks or a Monitor until-loop, and the poller's 1800 recommendation is telemetry honored AS 540.
3. The stale cross-reference at the `status == "running"` branch comment (~L4658, "using result[\"next_interval\"] as the next sleep") is updated to match — no surviving instruction anywhere in Step 6d.2 tells the orchestrator to sleep longer than 540 s.
4. Step 9c gate green: no-flags `workflow_lint.py` + the selector-mapped tests pass on the branch (no NEW failures vs the known-red baseline).
