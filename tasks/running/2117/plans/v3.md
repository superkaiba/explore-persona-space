# Plan v3 — Task #2117: daily-fix: reconcile-stop misses error-storming sessions

**Kind:** infra (workflow-fix; `wf-fix` tag). Single-file predicate narrowing in `scripts/autonomous_session_watch.py` + tests. No experiment, no training, no pod, 0 GPU-h.

## 1. Requirement + acceptance criteria

**Requirement (task Goal):** the watcher's parked/terminal session-reconcile pass (pass 6) never stops a session that is *error-storming / autocompact-thrashing* on a terminal task, because transcript churn reads as liveness. On 2026-08-05 this burned ~4 h of tokens on already-completed task #2004.

**Clarifier-verified mechanism (2026-08-11) — the premise holds, with one refinement the body did not state:**

`_session_idle_signals()` (`scripts/autonomous_session_watch.py:26309`) builds `ages` from the newest non-watcher marker, the per-issue self-report, and the newest registration `spawned_at`. ONLY when that set already reads idle does it append `_transcript_idle_age_s(pid)` per mapped sid and recompute `idle = min(ages) >= _session_idle_s()`. The refinement: `_transcript_idle_age_s` (`:29526`) is a pure **mtime** probe (`Path(transcript).stat().st_mtime`) — it never inspects row CONTENT. A thrashing session appends continuously (failed turns, compaction rows, SKILL.md re-reads), so mtime stays fresh, `idle` flips False, and `decide_session_reconcile()` (`:26067`) returns `("clear", 0)` — **resetting the miss counter to 0 every tick**, so the ≥2-consecutive-miss guard can never accumulate. Exactly reproduces #2004: the pass stopped one genuinely-idle duplicate at 14:24Z while the storming session ran to 16:00:50Z.

**Countervailing constraint — the transcript signal must NOT be removed.** It was added by completed task **#1670** ("reconcile pass must not stop young respawns"; related #1622) after a ~10-min-old recovery respawn read as 27.5 h idle off the TASK's marker gap and was stopped. #2117 is a **narrowing** of #1670, not a revert. (Note: the young-respawn case #1670 names is *also* covered by the `spawned_at` term already in `ages`; the residual class the transcript probe uniquely protects is an OLD session doing real work with no recent markers. That class is what the narrowing must keep protecting.)

**Acceptance criteria:**

1. A new pure classifier `_transcript_work_idle_age_s(pid, now)` replaces `_transcript_idle_age_s` **at the `_session_idle_signals` call site only** (`_transcript_idle_age_s` keeps its other callers — the #1582 keep-running owner leg and the #845 d stale-registration pass — byte-untouched; those lanes are out of scope). It returns `(age_seconds | None, reason | None)` under a **four-way** contract:
   - **(i) unresolvable / unreadable transcript** → `(None, <reason>)`. Unchanged from today (contributes nothing to `ages`).
   - **(ii) durable work found** → `(now - ts, None)` where `ts` is the newest of: the `end_ts` of the newest **successfully-completed wake-turn** (`_segment_wake_turns(rows)` outcome `"ok"`, `:3318`), and the timestamp of the newest **genuine human row** (`tick_triage.is_human_transcript_row`, `:1013`). This is the #1670-preserving arm.
   - **(iii) positive churn evidence** → `(None, "churn-only")`: the tail holds ≥1 COMPLETED wake-turn, EVERY completed turn is `"failed"`, and no genuine human row is present. This is the fix — the transcript contributes nothing, task-side idleness stands, the miss counter accumulates, and the session is stopped after ≥2 ticks (~20 min).
   - **(iv) indeterminate** → fall back to `_transcript_idle_age_s(pid, now)` (today's mtime read). Covers: zero completed turns in the tail (e.g. one long in-flight turn — `_segment_wake_turns` deliberately does not count an in-flight final turn), and completed turns present but no parseable `end_ts`. **Fail toward KEEP.**
2. The `ages`-append logic in `_session_idle_signals` is otherwise unchanged: a returned age is appended exactly as today; `None` appends nothing. The task-side terms, the `if idle and pids_by_sid` gate, and the recompute are untouched — the fix is strictly *what number the transcript term contributes*, never *when it is consulted*.
3. `decide_session_reconcile` (`:26067`) is **unchanged**. All four shields — `keep_running`, `followup_active`, `recovery_respawn_active`, `pod_running` — and the `("clear", 0)` / threshold / autostop / alert branches keep their exact semantics. (Considered and rejected: adding a `("skip", missed)` FREEZE arm à la `decide_idle_unmapped` (`:29551`). Freeze is right for an *unavailable* signal; churn is *positive evidence of no work*, so it belongs in the signal layer, and routing it through decide() would need a new state channel for zero behavioral gain.)
4. **Kill switch** `EPM_SESSION_RECONCILE_TRANSCRIPT_WORK_PROBE=0` reverts the call site to the pure-mtime `_transcript_idle_age_s` (exact pre-#2117 / #1670 behavior). Default ON. Env-parse follows the house form (`_session_reconcile_autostop_enabled`, `:26054`): off only for `{"0","false","no"}`.
5. **Auditability.** The churn verdict is visible in two places: `_session_idle_signals`' `gap_desc` gains a `churn-only` token when ≥1 mapped sid returned (iii), and `_handle_session_stop`'s (`:26440`) posted marker note — which today lists activity as "non-watcher marker / self-report / session registration / transcript" — is updated to say the transcript term was churn-only, so a reader can tell a churn-driven stop from an ordinary idle stop.
6. **Tail width.** Read via the existing `_transcript_tail_rows` (`:19323`, happy-log-only resolution, malformed-line tolerant, drops the partial first line of a mid-file seek). Use the 256 KB width the wedge lane already uses (`#1104`), not the 64 KB default: a heavy storm can push the last ok-turn out of a 64 KB window, and this probe runs at most once per mapped sid per tick, only for DONE-status candidates already reading idle (the `_process_session_reconcile` (`:26546`) laziness bounds the cost).
7. `tests/test_autonomous_session_watch.py` (or a focused sibling) pins, fail-loud:
   (a) churn-only tail (all completed turns failed, no human row) → transcript contributes nothing → `decide_session_reconcile` accumulates to `"stop"` on the 2nd tick — **the #2004 regression test**;
   (b) recent `"ok"` turn in an otherwise-storming tail → age contributed → `("clear", 0)` — **the #1670 regression test**;
   (c) recent genuine human row, all turns failed → protected;
   (d) zero completed turns (single in-flight turn) → falls back to mtime, behavior identical to pre-#2117;
   (e) unresolvable transcript → `(None, reason)`, unchanged;
   (f) kill switch `=0` → byte-equivalent behavior to the mtime probe on all of (a)-(e);
   (g) each of the four shields still short-circuits ahead of a churn-only tail (a churn verdict must never bypass `keep-running` / follow-up / respawn / RUNNING-pod);
   (h) **dry-run thread** — `tests/test_autonomous_session_watch.py::test_churn_only_stop_respects_dry_run`: a churn-only tail under `dry_run=True` reaches the stop branch but executes NO stop (`_stop_session` not called, no marker posted, no `stopped_at` recorded) — a broken dry-run kwarg thread would turn the §4 `--dry-run` smoke into a real fleet mutation (#596/#607/#633).
8. `scripts/workflow_lint.py` (no-flags) shows no NEW payload-attributed failures; the `select_step9c_tests.py --map-files`-mapped tests for the touched files pass.
