# Plan v3 — #2262: `_extract_scatters` drops genuine (0,0) single-point scatters

`kind: infra` · bug fix in shared library code · 0 GPU-hours.

**v3 changes — plan v2's kill criterion 1 FIRED; this revision adopts the
fallback that criterion itself pre-scoped.** Code-review round 1 split
PASS (Claude) vs FAIL (Codex); the binding `reconciler` verdict was **FAIL,
routing (A) — bounded plan revision, not a full re-plan**. Three findings,
all independently reproduced by direct measurement (orchestrator probe +
reconciler probe, matplotlib 3.10.8 / Agg):

1. **BLOCKER `sized-placeholder-misclassified`.** Marker sizes do NOT
   discriminate. `PathCollection([], sizes=[14])`,
   `RegularPolyCollection(numsides=4)` and `PathCollection([circle],
   sizes=[14])` each report the synthesized `(1,2)` `[[0,0]]` offset with a
   NON-EMPTY sizes array, so v2's guard KEEPS them and fabricates a
   `(0,0)` `_kind="scatter"` row. The `[circle]` case is
   attribute-indistinguishable from a genuine `ax.scatter([0],[0])` on
   offsets shape, sizes shape AND path count — so no repair exists inside
   the sizes-only attribute set, and a paths-count check does not rescue it
   (tried and measured). v2 turned a row-DROPPING bug into a
   row-FABRICATING one on exactly the surface this task exists to make
   trustworthy.
2. **CONCERN `get-sizes-lookup-escapes`.** v2's `getattr` sat OUTSIDE its
   `try`, so a `get_sizes` defined as a raising `@property` propagated
   `RuntimeError` — contradicting the never-raises contract and v2
   acceptance criterion 4.
3. **`None`-sizes hole.** `np.asarray(None).size == 1`, so a third-party
   `get_sizes()` returning `None` read as valid marker evidence. Moot once
   the sizes probe is gone, but recorded so the replacement is not written
   with the same shape.

**The adopted fallback.** v2 kill criterion 1 already named it verbatim —
"an explicit `isinstance(coll, PathCollection)` type test combined with a
'was `set_offsets` ever called' probe". Measurement confirms the
`set_offsets`-provenance half is sufficient on its own and is a STRICTLY
more correct discriminator than marker sizes: it tests the property the
guard was always trying to test, rather than proxying it.

## Requirement

`paper_plots._extract_scatters` must emit a sidecar `points` row for a genuine
single-point scatter whose lone offset is exactly `(0.0, 0.0)`, while
continuing to skip the placeholder `(1,2)` `[[0,0]]` offset that matplotlib
SYNTHESIZES for artists carrying no offsets at all — including artists that
do carry marker sizes.

### Acceptance criteria

1. A figure rendering `ax.scatter([0.0], [0.0], s=14)` emits exactly one
   `points` row for that point, `_kind == "scatter"`, counted in
   `total_points`.
2. The same at matplotlib's default marker size (`ax.scatter([0.0], [0.0])`)
   and at `s=0` (a zero-area marker is still a genuine datum).
3. **No `scatter` row is emitted for ANY offset-less collection, sized or
   not.** Parametrized over: `ax.errorbar` bar `LineCollection`,
   `ax.fill_between`, `ax.violinplot`, bare
   `matplotlib.collections.PathCollection([])`, **and the three
   sized-but-offset-less cases that broke v2** —
   `PathCollection([], sizes=[14])`, `RegularPolyCollection(numsides=4)`,
   `PathCollection([Path.unit_circle()], sizes=[14])`.
4. `_extract_scatters` still never raises. The new helper returns `False` —
   never propagates — for: an object with no offset attribute, **an object
   whose offset attribute is a raising `@property`** (pinned with
   `RuntimeError`, i.e. outside any narrow exception tuple), and any object
   whose provenance cannot be read.
5. `ax.scatter([], [])` (genuinely empty) continues to emit no row.
6. `tests/test_paper_plots.py`, `tests/test_issue2094_figures.py` and
   `tests/test_issue2225_figures.py` stay green.
7. **The superseded `_has_marker_sizes` helper is DELETED**, not left beside
   its replacement (`.claude/rules/vectorize-many-cell-fits.md` § Supersede
   contract: rewire-then-delete in the same change). It was introduced in
   this branch's round 1 and has no other caller — confirm with a repo-wide
   grep before deleting.

## Root cause (unchanged from v2, and now more precisely stated)

`_extract_scatters` carried:

```python
# A lone (0,0) offset is matplotlib's default for empty collections.
if offsets.shape[0] == 1 and not np.any(offsets):
    continue
```

The comment's INTENT is right and its mechanism claim is nearly right:
`Collection.get_offsets()` synthesizes `np.zeros((1, 2))` whenever the
artist's `_offsets` was never set. What it gets wrong is the SCOPE — it also
catches every genuine single-point scatter that happens to sit at the origin,
which is the standard per-point `ax.scatter([x],[y])` companion-loop pattern.

Measured decision table (matplotlib 3.10.8; `_offsets` is the ground truth,
with `get_offsets()`'s return TYPE as a corroborating public tell):

| Artist | `get_offsets()` | `_offsets` | return type | correct verdict |
|---|---|---|---|---|
| `scatter([0],[0], s=14)` | `(1,2)` `[[0,0]]` | **set** | `MaskedArray` | KEEP |
| `scatter([0],[0])` default | `(1,2)` `[[0,0]]` | **set** | `MaskedArray` | KEEP |
| `scatter([0],[0], s=0)` | `(1,2)` `[[0,0]]` | **set** | `MaskedArray` | KEEP |
| `scatter([],[])` | `(0,2)` | set | `MaskedArray` | skip (shape guard) |
| `PathCollection([], sizes=[14])` | `(1,2)` `[[0,0]]` | `None` | `ndarray` | SKIP |
| `PathCollection([circle], sizes=[14])` | `(1,2)` `[[0,0]]` | `None` | `ndarray` | SKIP |
| `RegularPolyCollection(numsides=4)` | `(1,2)` `[[0,0]]` | `None` | `ndarray` | SKIP |
| `errorbar` bar `LineCollection` | `(1,2)` `[[0,0]]` | `None` | `ndarray` | SKIP |
| `fill_between` / `violinplot` polys | `(1,2)` `[[0,0]]` | `None` | `ndarray` | SKIP |
| `QuadMesh` / `QuadContourSet` rasters | `(1,2)` `[[0,0]]` | `None` | `ndarray` | SKIP |
| `hexbin` `PolyCollection` | `(8,2)` real | `None` | `ndarray` | n/a — multi-offset, never reaches the guard |

`_offsets` separates the two classes PERFECTLY; marker sizes do not separate
them at all (rows 1-3 vs 5-7 are identical on sizes).

### Impact, reproduced

`figures/issue_2162/persona_specificity_ladder/ladder_percarrier.meta.json`
records `total_points=252` / `n_series=252` against **264** rendered
`ax.scatter` calls. The producer
(`scripts/issue2162_ladder_analysis.py:1023-1024`) computes
`x = r_pos[r["rung"]] + (k - 1) * 0.18`, so `x == 0.0` exactly only for the
middle arm (`k == 1`) at rung index 0; 12 rows survive at `x == 0.0` with
non-zero `y` and **zero** rows sit at `(0,0)` — the 12-point gap is exactly
the dropped `(0,0)` data. No second drop path: `_xy_rows` maps non-finite
coordinates to `None` and KEEPS the row.

## Method delta

Discriminate on offset **provenance**, not marker sizes.

**Why the private `_offsets` is the right probe here**, stated explicitly
because it is the one judgement call in this plan:

* There is no public accessor for "were offsets ever supplied" — that is
  precisely the information `get_offsets()` destroys by synthesizing a
  placeholder.
* The corroborating public tell (`get_offsets()` returns `MaskedArray` when
  set, `ndarray` when synthesized) is ALSO an implementation detail, and a
  more fragile one: it depends on `set_offsets` masking its input, which a
  caller reaching the attribute by another path could bypass.
* The FAIL DIRECTION is safe. If a future matplotlib renames `_offsets`, the
  `getattr` returns `None`, the helper returns `False`, and every lone-(0,0)
  collection is skipped — i.e. we degrade to the PRE-#2262 behavior (dropping
  genuine origin points), never to fabricating rows. Dropping a row is a
  visible undercount; fabricating one is invented data.
* Acceptance criteria 1-2 pin the behavior, so a matplotlib bump that breaks
  the probe fails the suite LOUDLY rather than silently regressing.

This is the sanctioned reading of the plan's own named fallback; the
`isinstance(coll, PathCollection)` half is deliberately NOT added — it would
make a hand-built `LineCollection` with explicitly-supplied offsets behave
differently from the multi-offset `PolyCollection` artists
`_extract_scatters` already extracts today, introducing a fresh inconsistency
inside the very classification this task is scoped OUT of changing.

## File paths + concrete diffs

### 1. `src/explore_persona_space/analysis/paper_plots.py`

**Delete** `_has_marker_sizes` (added in round 1, no other caller — verify by
grep) and **replace** it with:

```python
def _has_explicit_offsets(coll: object) -> bool:
    """Return True when ``coll``'s offsets were explicitly supplied.

    ``Collection.get_offsets()`` SYNTHESIZES ``np.zeros((1, 2))`` when the
    artist's offsets were never set, so a lone ``(0,0)`` offset is ambiguous:
    it is either a genuine single-point datum or a placeholder from an artist
    carrying no offsets at all (``LineCollection`` error bars, ``fill_between``
    / ``violinplot`` polys, ``QuadMesh`` / ``QuadContourSet`` rasters, a bare
    ``PathCollection``, ``RegularPolyCollection``).

    Marker sizes do NOT disambiguate — a ``PathCollection([path], sizes=[14])``
    is indistinguishable from ``ax.scatter([0], [0])`` on offsets shape, sizes
    shape and path count (measured; the #2262 round-1 defect). Offset
    PROVENANCE does: ``set_offsets`` stores its argument, so the private
    ``_offsets`` is non-None exactly when a caller supplied offsets. There is
    no public accessor for this — ``get_offsets()`` is the very call that
    erases the distinction.

    Never raises: any artist whose provenance cannot be read returns False, so
    the caller SKIPS it. That fail direction is deliberate — if a future
    matplotlib renames the attribute we degrade to the pre-#2262 behavior of
    dropping genuine origin points (a visible undercount), never to
    fabricating rows (invented data). The keep-side acceptance tests pin the
    behavior so such a rename fails loudly.
    """
    try:
        return getattr(coll, "_offsets", None) is not None
    except Exception:
        return False
```

Every access — the `getattr` included — sits INSIDE the `try`, closing the
round-1 raising-descriptor hole.

Then the guard in `_extract_scatters` becomes:

```python
        # matplotlib SYNTHESIZES a (1,2) [[0,0]] offset for artists that carry
        # no offsets at all (LineCollection error bars, QuadMesh /
        # QuadContourSet rasters incl. on colorbar axes, fill_between / violin
        # polys, a bare or sized-but-offset-less PathCollection,
        # RegularPolyCollection). Skip those, but KEEP a real (0,0) datum from
        # a per-point ``ax.scatter([x],[y])`` loop — distinguished by offset
        # PROVENANCE, since marker sizes do not separate the two cases.
        # (``ax.scatter([], [])`` never reaches here: its offsets are (0,2) and
        # the shape check above skips it.)
        if offsets.shape[0] == 1 and not np.any(offsets) and not _has_explicit_offsets(coll):
            continue
```

Behavior vs pre-#2262: exactly one cell changes — a lone-`(0,0)` collection
whose offsets were EXPLICITLY supplied is now kept. Behavior vs round 1: the
three sized-but-offset-less cases go back to being skipped.

  discriminate on the locked matplotlib — a genuine scatter reporting
  `_offsets is None`, or a placeholder reporting it set — then no

  remaining named fallback: have `savefig_paper` capture scatter data AT CALL
  TIME rather than reading it back off artists. That is a substantially larger

  artist classes, so this guards against a version surprise.

  regress), the discriminator is wrong in both directions and the same
  escalation applies.
