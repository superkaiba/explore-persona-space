# Plan — #1454: Make `GcpBackend.fetch_results` work on external-IP-less GCP VMs (workflow-fix, `kind: infra`, 0 GPU-h)

## 0.0 TL;DR (plain English)

- **What I'll run:** I'll teach the GCP results-fetch to check the instance's actual state before ssh-ing: if the VM is stopped/gone it skips the doomed ssh attempts with one precise log line pointing at the real crash-forensics location; if the VM is running without a public IP it explicitly routes ssh through Google's IAP tunnel; if the VM is healthy nothing changes. All pinned by pure argv-construction pytest tests — no network, no GPU.
- **What I expect:** The misleading "External IP address was not found → rc=255" failure from #1005 becomes either a correct skip-with-diagnosis (the actual incident class: the instance was already terminated) or a working IAP pull (running-no-IP class, once the one documented IAM grant lands).
- **What would change my mind:** If the `instances describe` probe can't reliably distinguish the three states in tests, or if keeping the healthy-path ssh argv byte-identical proves impossible, I'd fall back to logging-only (no transport change) and re-plan.

## 4. Design

**Edit 1 — pure classifier (new module-level function, near `render_describe_argv` ~L3065):**

```python
_IAP_PREREQ_HINT = (
    "IAP TCP forwarding needs ingress 35.235.240.0/20 tcp:22 (satisfied: default-allow-ssh "
    "0.0.0.0/0) AND roles/iap.tunnelResourceAccessor for the caller "
    "(eps-router@... presumed missing; one-time owner grant documented in task #1454)."
)

def classify_fetch_transport(describe: GcloudRunResult) -> tuple[str, str]:
    """Classify ssh reachability for fetch_results from one `instances describe` result.

    Returns (mode, detail); mode in {"external-ip", "iap", "skip"}:
      * describe rc != 0 (incl. not-found post-DELETE)      -> ("skip", stderr tail)
      * status present and != "RUNNING" (TERMINATED, STOPPING, PENDING...) -> ("skip", status)
      * status == "RUNNING" and any networkInterfaces[].accessConfigs[].natIP -> ("external-ip", ...)
      * status == "RUNNING" and no natIP                    -> ("iap", ...)
      * status absent / JSON unparseable (indeterminate)    -> ("external-ip", "indeterminate")  # fail-open: legacy behavior
    """
```

**Edit 2 — `fetch_results` (L6184):** after the existing issue/attempt_id guards, run the probe once: `self._run(render_describe_argv(config=config, name=handle.pod_name, zone=zone))` → `mode, detail = classify_fetch_transport(...)`.
- `mode == "skip"` → ONE `logger.error` naming instance, status/detail, that ssh is impossible to a non-RUNNING instance, that `confirm_artifacts` will FAIL on the missing sentinel (today's surfacing, preserved), and that crash forensics (if any) live at HF `issue<N>_partial/<attempt_id>/` — then `return`. Saves 3 futile ssh attempts and replaces the misleading IAP notice.
- `mode == "iap"` → append `"--tunnel-through-iap"` as the LAST element of all 3 ssh argvs (sentinel L6252-6259 + both tar pulls L6313-6320); on a nonzero ssh rc, extend the existing error logs with `_IAP_PREREQ_HINT`.
- `mode == "external-ip"` → argvs byte-identical to today (zero healthy-path change).

Implementation detail: thread `iap: bool` via a tiny local helper (e.g. `def _ssh_argv(cmd: str) -> list[str]` closure inside fetch_results) so the sentinel + tar sites can't drift. No change to `_base_gcloud_argv`, no change to `render_startup_script` (byte-identity snapshot test untouched), no change to the 4 poll-path ssh sites.

**Why code, not a model call:** deterministic argv construction/classification — N/A for an LLM call.
**Out of scope (listed per the grep-every-hit rule):** the 4 poll-path sites (drain ~L5827, mark-processed ~L5909, gpu-util probe ~L5944, relaunch probe ~L6086) run per-tick against instances the poller reads as RUNNING with external IPs; their failures feed poll/wedge semantics (`test_gcp_drain_ssh_*`), and adding a per-tick describe would add quota/latency for a null benefit. Deliberately untouched; the classifier is reusable if a future incident implicates them.

**Infra leg (documented, NOT executed by this task):** one-time, requires an owner identity (eps-router cannot self-grant):
`gcloud projects add-iam-policy-binding eps-persona-gpu-jun2026 --member="serviceAccount:eps-router@eps-persona-gpu-jun2026.iam.gserviceaccount.com" --role="roles/iap.tunnelResourceAccessor"`

## 11. Decision Rationale

1. **Probe-based detection (describe) vs unconditional flag vs stderr-signature retry.** What: classify reachability from one `instances describe` before any ssh. Why: the observed notice means gcloud ALREADY auto-fell-back to IAP and failed — an unconditional or retry `--tunnel-through-iap` re-runs the identical transport (functional no-op) and stderr-signature parsing is brittle across gcloud versions; the describe is structural and also detects the actual #1005 class (not RUNNING), which no flag fixes. Source: https://docs.cloud.google.com/iap/docs/using-tcp-forwarding + #1005 events (the 03:48:43Z triage marker "att-233638 instance TERMINATED + finalized" proves the instance existed TERMINATED at fetch time). Alternatives: retry-on-signature (rejected: re-runs a failed transport; parses stderr); unconditional flag (rejected: forces an unauthorized transport on healthy external-IP VMs — the compute-backend-failover.md live-diagnosis note).
2. **Scope: fetch_results only, not all 6 ssh sites.** What: behavior change confined to the 2 fetch_results ssh sites; classifier written module-level for future reuse. Why: the 4 poll-path sites run per-tick on RUNNING external-IP VMs and their failure modes feed wedge/transport-alarm machinery (`test_gcp_drain_ssh_timeout_returns_transport_alarm`); changing their transport risks regressing poll semantics for zero incident evidence. Source: incident #1005 (fetch_results-only); task body scope note. Alternatives: shared `_gcloud_ssh_argv` wrapper across all 6 (rejected: blast radius; revisit on a poll-path incident).
3. **Explicit `--tunnel-through-iap` on the RUNNING-no-IP arm.** What: append the flag rather than rely on auto-fallback. Why: determinism (transport choice is visible in the argv + golden-testable) and it anchors the prerequisite diagnostic to a deliberate IAP attempt; near-no-op functionally vs auto-fallback, by design. Source: https://docs.cloud.google.com/compute/docs/connect/ssh-using-iap. Alternatives: rely on auto-fallback + log (rejected: untestable in argv goldens; older gcloud versions differ in fallback behavior).
4. **Skip (not retry) on non-RUNNING.** What: one precise error log + return. Why: ssh to a stopped/terminated instance cannot succeed under any flag; today's behavior burns 3 gcloud attempts and logs a misleading IAP notice; the crash-forensics record for a dead instance is the Part-A `issue<N>_partial/` upload, which the new log names. Source: #1005; `.claude/rules/compute-backend-failover.md` Part A. Alternatives: attempt anyway (rejected: guaranteed failure, misleading logs).
5. **Fail-open on indeterminate describe.** What: unparseable/status-less describe → legacy argv. Why: preserves today's behavior when the probe is blind (never worse than status quo), and keeps the 5 pre-existing goldens green without edits. Source: existing `_Runner` describe default `{}` (tests/test_gcp_backend.py L239). Alternatives: fail-closed skip (rejected: a transient probe blip would silently drop a viable pull).
6. **IAM grant documented, not executed.** What: the one-time `roles/iap.tunnelResourceAccessor` grant command recorded in §4, requiring an owner identity. Why: eps-router cannot self-grant (no setIamPolicy) and outside-the-worktree IAM mutation is a user-ask class op (halt-criterion #2); the code fix is independently valuable (the incident class is non-RUNNING, where IAM is moot). Source: plan-time probe (get-iam-policy denied); CLAUDE.md halt criteria. Alternatives: block the task on the grant (rejected: decouples a 0-risk code fix from a human-gated infra op).
