**#1491 — the substantive finding.** Real command is newline-separated:
`WT=/tmp/i1491mrg` / `cd "$WT"` / `git merge --no-ff origin/issue-1491 > … 2>&1`.
Two separable halves:

- **(i) true positive by design** — an UNGUARDED `cd` then a newline-separated
  git op: bash does not guarantee the `cd` succeeded, so a failed `cd` runs the
  merge in the SHARED root. `&&`-only propagation is the safety property.
- **(ii) real false positive** — the three recomposes the guard's own BLOCK
  message advertises are `.claude/worktrees/`-only and BLOCK for `/tmp/` scratch
  paths, while the literal `cd /tmp/x && <op>` form is ALLOWED. Identical
  shapes, path swapped, is the natural control:

| Shape | `.claude/worktrees/i1491mrg` | `/tmp/i1491mrg` |
|---|---|---|
| literal `cd <p> && <op>` | ALLOW | ALLOW |
| `WT=<p>; cd "$WT" && <op>` | ALLOW | **BLOCK** |
| `WT=<p>` NL `cd "$WT" && <op>` | ALLOW | **BLOCK** |
| `cd "$WT" \|\| exit 1` NL `<op>` | ALLOW | **BLOCK** |
| `cd "$WT" \|\| { echo FATAL >&2; exit 1; }` NL `<op>` | ALLOW | **BLOCK** |
| `git -C <p> <op>` | ALLOW | ALLOW |

The same message prescribes a `/tmp/<name>` scratch worktree for the
land-onto-main recipe AND advertises the `WT=`/exit-guard shapes as the
multi-clause compose. Today those are mutually unusable: a `/tmp` scratch merge
has no working multi-clause form other than `git -C`.

## 3. Why the fix is in scope and sound

The asymmetry is an **explicitly deferred decision whose stated precondition has
expired**, not a judgement call. The `/tmp` latch branch (L2135-2143) records:
*"(#1861) NO sticky for /tmp latches: every observed firing is worktree-side;
smaller blast radius to leave it (plan §6)"*; the variable-arming grep (L2182) is
`.claude/worktrees/`-only by the same narrowness. #1491's 2026-08-05 firing IS an
observed /tmp-side firing — the missing incident demand.

The soundness arguments already recorded for the worktree class are
**path-class-independent**:
- the assignment requirement exists because `cd ""` SUCCEEDS as a repo-root
  no-op (verified bash 5.1.16), so a bare `cd "$NAME"` latch would be fail-open;
- the exit-guard requirement exists to prove the `cd` actually ran.

Neither argument mentions which directory. And `/tmp` is **already** an accepted
latch path class for the literal form, so this admits **no new path class
anywhere** — it brings the variable + exit-guard arms to parity with the literal
arm within an already-sanctioned class. The repo-root spellings stay excluded by
the same predicates that exclude them today.
