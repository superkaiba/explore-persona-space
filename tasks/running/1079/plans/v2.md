**A1 — new module-level constant + resolver (place near `DEFAULT_MLP_SEED`, l.150):**

```python
DEFAULT_FIT_NUM_THREADS = 8  # #891 launch-prefix / #847 env.py setdefault / #811 patch value

def _resolve_num_threads(num_threads: int | None, *, ambient: int | None = None) -> int | None:
    """Resolve the per-fit CPU thread cap.

    None -> conservative default: max(1, min(DEFAULT_FIT_NUM_THREADS,
    os.cpu_count(), ambient)) — the ambient (pre-call torch pool) ceiling
    means the default only ever caps DOWN, never raises a deliberately
    tighter pin (#1079 round-1 reconciled Must-Fix). Env override
    EPS_VECTORIZED_FIT_DEFAULT_THREADS: unset -> DEFAULT_FIT_NUM_THREADS;
    "" or "0" -> disabled (return None, no pin) — #847 EPS_VM_THREAD_CAP
    parity; negative or non-integer -> ValueError (fail loud; deliberate
    divergence from #847's silent negative-disable).
    0 -> explicit opt-out (no pin). >0 -> verbatim (an explicit value MAY
    exceed the ambient pool — the documented escape hatch). <0 -> ValueError.
    """
    if num_threads is None:
        raw = os.environ.get("EPS_VECTORIZED_FIT_DEFAULT_THREADS")
        if raw is None:
            cap = DEFAULT_FIT_NUM_THREADS
        else:
            raw = raw.strip()
            if raw in ("", "0"):
                return None  # disabled — #847 convention
            cap = int(raw)  # fails loud on garbage ("eight")
            if cap < 0:
                raise ValueError(f"EPS_VECTORIZED_FIT_DEFAULT_THREADS must be >= 0, got {cap}")
        bounds = [cap]
        if os.cpu_count():
            bounds.append(os.cpu_count())
        if ambient:
            bounds.append(ambient)
        return max(1, min(bounds))
    n = int(num_threads)
    if n == 0:
        return None
    if n < 0:
        raise ValueError(f"num_threads must be >= 0 (0 = opt-out), got {n}")
    return n  # explicit caller value honored VERBATIM (no clamp)
```

**A2 — decorator `_with_thread_cap` (pin + restore, CPU only), applied to the three fitters:**

```python
def _with_thread_cap(fn):
    """Pin torch's intra-op pool per the fn's num_threads/device kwargs for the
    call duration (CPU only), restoring the previous value in a finally.
    The None-default path is ambient-ceilinged (never raises the pool)."""
    sig = inspect.signature(fn)
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        bound = sig.bind(*args, **kwargs); bound.apply_defaults()
        if bound.arguments.get("device", "cpu") != "cpu":
            return fn(*args, **kwargs)
        prev = torch.get_num_threads()
        resolved = _resolve_num_threads(bound.arguments.get("num_threads"), ambient=prev)
        if resolved is None:
            return fn(*args, **kwargs)
        torch.set_num_threads(resolved)
        try:
            return fn(*args, **kwargs)
        finally:
            torch.set_num_threads(prev)
    return wrapper
```

## 11. Decision rationale

1. **Default cap value = `max(1, min(8, os.cpu_count(), ambient_pool))` — ambient-ceilinged.** *Why:* 8 is the project convention; `os.cpu_count()` guards small CPU pods (cpu-small = 2 vCPU); the AMBIENT ceiling (pre-call `torch.get_num_threads()`) makes the default strictly conservative — it can only cap DOWN, never raise a deliberately tighter launch/script pin to 8 (raising is the exact tiny-op-thrash direction the gate docstring measured: 265 s @2 vs >480 s @8). *Source:* #891 launch-prefix + #847 `env.py` setdefault + the #811 patch value (all 8); the ambient-ceiling form is the EXISTING in-repo precedent `scripts/issue825_fit_cells.py:1534` (`max(1, min(8, torch.get_num_threads()))`); round-1 reconciled alternatives Must-Fix + `orchestrate/env.py` docstring ("per-script `torch.set_num_threads` takes precedence"). *Alternatives:* bare 8 (rejected — wrong on 2-vCPU pods); no ambient ceiling (rejected — silently raises tighter reviewed pins, contradicting "conservative").
2. **None resolves inside the fitters; opt-out sentinel `num_threads=0`; env override `EPS_VECTORIZED_FIT_DEFAULT_THREADS` with #847-parity semantics (unset → 8; `""`/`"0"` → disabled; negative/malformed → ValueError).** *Why:* no import-time global mutation; callers cannot forget the cap; escape hatch preserved; `""`-disabled matches the cited `EPS_VM_THREAD_CAP` convention exactly (round-1 consistency WARN resolved: prose, docstring, code, and tests now agree). A SEPARATE env var (not reusing `EPS_VM_THREAD_CAP`) is deliberate: `EPS_VM_THREAD_CAP` is shared-VM-scoped and drives import-time env setdefaults, while the fitter default applies everywhere (pods/GCE too — tiny-op thrash is machine-independent, #722) via a per-call pin; one knob would make "disable the VM setdefaults" silently disable the fitter's in-process defense. *Source:* `orchestrate/env.py:158-166` (#847). *Alternatives:* module-level `torch.set_num_threads` at import (rejected — side effect on import); reusing `EPS_VM_THREAD_CAP` (rejected — scope coupling above); ValueError on negative kept vs #847's silent disable (fail-loud project rule; recorded divergence).
3. **`torch.set_num_threads`-only in the helper; NO env-var setdefaults inside it.** *Why:* torch freezes its intra-op pool from `OMP_NUM_THREADS` at import, so helper-side env mutation is moot for torch and bad library hygiene; `set_num_threads` is the effective post-import lever. numpy/BLAS env caps stay a launch-surface duty (#847/#891 + the new rule clause). *Source:* #847 task record + `env.py:31-34, 145-154` docstrings; torch docs `set_num_threads`. *Alternative:* helper-side `os.environ.setdefault` (rejected — ineffective for torch, surprising global side effect).
4. **Restore-after-fit in a `finally` (for ALL calls, incl. explicit).** *Why:* library code should not leak global state; the in-module parity gate already models exactly this (l.736-741); on the shared VM the ambient pool is already 8 so restore is a no-op in the common case. This IS a deliberate behavior change for explicit callers' post-fit code (today the pin leaks) — acceptance criterion (2) is scoped to during-fit behavior accordingly (round-1 Codex-stats MF4), and the grep found no caller relying on the leak (A5); flagged for code-review spot-check of the heaviest explicit callers' post-fit tails. *Source:* `vectorized_mlp_skill.py:736-741`; caller grep (A5). *Alternatives:* leave-set (rejected — leaks state); restore-only-when-wrapper-pinned (rejected — provenance-keyed behavior forks on how an argument arrived, untestable by inspection).
5. **Parity-gate preservation via explicit `num_threads=0` at in-module gate call sites, recorder-certified.** *Why:* without it, the new default overrides the gate's deliberate 2-thread pin (l.731-734) and changes the exact regime the parity numbers were calibrated in; round-1 found the original test could not detect this regression (50× atol headroom), hence test T7's recorder assertion. *Source:* `vectorized_mlp_skill.py:731-741` + l.1492 comment; consistency-checker call-site completeness verification (the four in-module invocation clusters). *Alternative:* pass `num_threads=2` (equivalent; 0 chosen because the wrapper OWNS the pin — self-documenting).
6. **Rule-clause location = fix item 7 (+ cross-refs in Supersede duty 1 / Mid-run trigger); four-pin verification example.** *Why:* item 7 already owns the detached-launch/choom/checkpoint contract and cites #811; the two kill+relaunch surfaces are where relaunches are composed; the verification example checks all FOUR pins (an OMP-only substring check would pass a relaunch that dropped MKL/OPENBLAS/NUMEXPR — round-1 concern promoted into the recipe). *Source:* `.claude/rules/vectorize-many-cell-fits.md` fix item 7 + § Supersede contract + § Mid-run trigger (read in full). *Alternative:* editing SKILL.md § detached-launch (rejected — outside the Goal's named targets; cross-referenced instead).
