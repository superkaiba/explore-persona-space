## 2. Key design decisions

**D1 — WARN tier, not FAIL (deviation from the origin finding's "FAIL" wording; sanctioned by the task body's own "WARN (or FAIL for v4)" sketch; critic-endorsed round 1).** Rationale: (a) the sanctioned >1-figure exception (raw+processed / aggregate+per-unit pair, SPEC.md L600-632) is not just allowed but REQUIRED for aggregate results, so 2-figure sections are the COMMON conforming case and pair detection from text is necessarily heuristic; (b) a heuristic FAIL blocks `set-body` at analyzer time on conforming bodies (FAILs block; drafts must PASS) — the false-positive cost is an analyzer round, the exact cost the check exists to save; (c) 3 legitimate figures are conceivable (aggregate + per-unit + raw counterpart of a transformed view — SPEC's two rules compose), so no cardinality threshold is safely FAIL-tier; (d) every adjacent figure-cardinality check in this file (31, 38, 48) is deliberately WARN-tier with the LM critic (Lens 9/11) as substantive owner — the accepted false-negative direction for mechanical backstops. The WARN still achieves the incident's goal: the analyzer runs the verifier BEFORE posting and must acknowledge WARNs in-body, so the #1769 shape surfaces one round earlier than the LM critic. FAIL-tier escalation is a must-ask deviation (§8).

**D2 — pair-evidence heuristic (silences the WARN), CAPTION/ALT-SCOPED.** For a section with n≥2 inline figures, pair evidence = ANY of:
   (a) any embedded figure path's basename matches the existing `_PER_UNIT_FIG_RE` (`per[-_]?(context|unit|cell|pair)` — the project's per-unit companion naming convention, reused verbatim, single source);
   (b) a bounded declared-pair idiom regex `_DECLARED_PAIR_RE` matches within the FIGURE-ADJACENT text ONLY — the union of (i) each inline figure's ALT text and (ii) the blockquote (`> `) caption lines inside the section — NEVER the section's general prose. Idiom shape: `per[-_ ](unit|question|context|cell|pair|seed|source|point)s?` | `\braw\b[^.\n]{0,60}\b(alongside|counterpart|version|view|scatter)\b` | `\b(unbinned|low[- ]level)\b` | `\b(companion|counterpart)\b`.
   **Why caption/alt-scoped (round-1 Must-Fix):** the real #1769 section's what-is-plotted beat contains "per-question" as routine SPEC-mandated disclosure prose — whole-section matching silences the exact origin shape. SPEC's own pair rule says the pair's declaration lives in the figure unit (alt text self-description + shared caption), so scoping there keeps recall on the incident (verified: the #1769 dose-ladder caption's "(raw) per behavior" hits neither alternation → WARN fires) while a genuine per-unit companion's caption ("per-context deltas…") silences correctly. A silenced true violation falls to Lens 9 (unchanged substantive owner); a WARN on a true pair costs only an acknowledge line. Exact regex composition is implementer detail (§8) — BUT the verbatim-#1769 fixture (row 1) and the pair fixtures (rows 2-3) jointly pin the behavior whatever the composition.

**D3 — scan surface.** `_v4_results_body(body)` (footer-truncated `## Results`) → `_prose_layer(...)` (fences + `<details>` stripped, so a quoted example embed never counts) → split on `^### ` H3 boundaries (preamble before the first `### ` excluded) → count `_IMAGE_RE` matches per section, plus HTML `<img src=...>` embeds (the check-31/#1510 symmetric-embed doctrine; a cheap `<img\b` scan). Reuses only existing helpers; no new parsing infrastructure.
