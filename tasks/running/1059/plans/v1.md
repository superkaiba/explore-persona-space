## 4. Design

### 4.1 Placement decision (the three candidate options)

- **(a) In-loop sleep only (watcher):** covers watcher-internal bursts but NOT the cross-process filer burst that actually caused the incident. Rejected as sole mechanism.
- **(b) Shared cross-process last-dispatch stamp:** covers both sources; the natural home for the state + helpers is `spawn_session.py`, which both consumers already import from (watch L471–486; file_infra_task L70–78) and which owns the #843 precedent helpers. **Adopted.**
- **(c) Per-tick dispatch cap of 1:** trivially satisfies ≥60s via the 10-min cadence but cuts drain throughput ~10× more than the Goal requires (5 tasks → ~40–50 min) and does nothing for the filer path. Rejected.

**Hybrid adopted:** shared stamp (b) + **sleep** at the watcher chokepoint + **defer** in the filer. Sleeping in the watcher preserves same-tick throughput and — decisively — changes ZERO booking semantics and ZERO existing-test assertions (nothing is skipped; the tri-state is untouched). Deferring in the filer avoids sleeping inside `/daily`'s filer loop and reuses the module's documented no-op contract verbatim. Enforcement stays scoped to the two Goal-named burst sources; the `spawn_session.py` spawn path itself is NOT gated (gating there would pace crash-recovery/stalled respawns too — behavior change beyond the Goal; see § must-ask).

### 4.2 New helpers — `scripts/spawn_session.py` (additive only, next to the lease helpers ~L230)

```python
# ─── session-dispatch stagger (#1059) ────────────────────────────────────────
# Global (cross-issue) pacing of `spawn-issue --auto` session dispatches: each
# fresh session is a ~100K-token cold context load, and the org input-TPM cap
# climbs at each minute boundary (CLAUDE.md § 429 token-pacing), so dispatchers
# that can burst (the watcher infra loops, the file-time filer) keep >=60s
# between session starts. Distinct from the #843 per-issue lease (mutual
# exclusion of duplicate dispatch for ONE issue) and the #1027 auth-outage
# episode gate (fleet-wide suppression): this is last-writer-wins pacing state,
# no holder exclusivity, no suppression sentinel.
SESSION_DISPATCH_STAGGER_S_DEFAULT = 60.0
SESSION_DISPATCH_STAGGER_MAX_S = 300.0  # env ceiling: pacing, not parking

def session_dispatch_stagger_s() -> float:
    """Stagger window in seconds (env ``EPM_SESSION_DISPATCH_STAGGER_S``;
    default 60; ``0`` or negative disables; malformed falls back to the
    default, mirroring ``_dispatch_lease_ttl_s``; clamped to
    ``SESSION_DISPATCH_STAGGER_MAX_S`` so an env typo can never wedge a
    watcher tick for hours — the L462-465 lease-window clamp posture)."""
    raw = os.environ.get("EPM_SESSION_DISPATCH_STAGGER_S")
    if not raw:
        return SESSION_DISPATCH_STAGGER_S_DEFAULT
    try:
        val = float(raw)
    except ValueError:
        return SESSION_DISPATCH_STAGGER_S_DEFAULT
    return min(max(val, 0.0), SESSION_DISPATCH_STAGGER_MAX_S)

def session_dispatch_stamp_path() -> Path:
    """Singleton last-session-dispatch stamp (#1059). NOT per-issue: the
    watcher GC's prefix+int-stem sweep never matches it (same class as
    watch.lock / session_progress.json)."""
    return AUTONOMOUS_REGISTRY_DIR / "last-session-dispatch.json"

def last_session_dispatch_age_s(now: float | None = None) -> float | None:
    """Seconds since the last recorded session dispatch; ``None`` when no
    stamp exists. Garbled content falls back to file mtime (the
    ``dispatch_lease_fresh`` posture — failing toward pacing is bounded by
    the <=300s window, unlike the lease's fail-toward-fresh which needed a
    TTL bound). A future-dated ts returns 0.0 (treat as just-now)."""
    now = time.time() if now is None else now
    path = session_dispatch_stamp_path()
    try:
        entry = json.loads(path.read_text())
        ts = entry.get("ts") if isinstance(entry, dict) else None
    except FileNotFoundError:
        return None
    except (OSError, ValueError):
        ts = None
    if not (isinstance(ts, int | float) and not isinstance(ts, bool)):
        try:
            ts = path.stat().st_mtime
        except OSError:
            return None  # vanished between read and stat -> no stamp
    return max(now - ts, 0.0)

def stagger_delay_s(age_s: float | None, window_s: float) -> float:
    """PURE: seconds a dispatcher should wait before spawning. 0 when the
    window is disabled (<=0), no prior dispatch (None), or the window has
    already elapsed; else the remainder, clamped to [0, window_s]."""
    if window_s <= 0 or age_s is None or age_s >= window_s:
        return 0.0
    return min(window_s - age_s, window_s)

def record_session_dispatch(issue: int, holder: str, now: float | None = None) -> None:
    """Best-effort atomic (tmp + os.replace) write of the dispatch stamp.
    NEVER raises — a failed pacing record must not fail a successful spawn;
    any OSError prints a loud stderr warning (degrades to no stagger for the
    next caller, bounded by the window)."""
    now = time.time() if now is None else now
    entry = {"issue": issue, "holder": holder, "pid": os.getpid(), "ts": now}
    path = session_dispatch_stamp_path()
    try:
        AUTONOMOUS_REGISTRY_DIR.mkdir(parents=True, exist_ok=True)
        tmp = path.with_suffix(".json.tmp")
        tmp.write_text(json.dumps(entry))
        os.replace(tmp, path)
    except OSError as e:
        print(f"WARNING: session-dispatch stamp write failed ({e}); "
              f"next dispatcher sees no stagger", file=sys.stderr)
```

All names resolve `AUTONOMOUS_REGISTRY_DIR` at call time via the module global, so the existing `isolated_registry` fixture (tests L870–879 patches BOTH `spawn_session.AUTONOMOUS_REGISTRY_DIR` and the watcher's re-export) makes them hermetic for free.

## 11. Decision Rationale

- **Stagger placement — shared stamp + chokepoint enforcement (option b hybrid).** *What:* singleton stamp in `~/.eps-autonomous/`, helpers in `spawn_session.py`, enforcement in `_dispatch_infra_drain` + `cmd_file_infra` only. *Why:* the incident had BOTH a cross-process burst (5 filer self-dispatches, 07:09–07:12) and back-to-back watcher loops; a watcher-only sleep misses the first, a filer-only gate misses the second; `_dispatch_infra_drain` is the verified single chokepoint of both loops. *Source:* #843 (cross-process dispatch state under `~/.eps-autonomous/`, spawn_session as home), #1027 (fleet-level gate at the same chokepoint), task #1059 clarifier. *Alternatives:* enforcement inside `spawn-issue --auto` (max coverage, rejected — paces crash-recovery respawns, beyond Goal scope; named must-ask); per-tick cap of 1 (rejected — 10× over-throttling, no filer coverage).
- **Window value 60s, env-tunable, clamp ≤300.** *What:* `EPM_SESSION_DISPATCH_STAGGER_S=60` default-on, `0` disables. *Why:* the 429 input-TPM cap climbs at minute boundaries; ≥60s puts each ~100K-token cold session load in its own window. *Source:* task Goal (">=60s"); CLAUDE.md § 429 token-pacing; clamp posture from spawn_session L462–465. *Alternatives:* 120s (safer margin, halves drain throughput — the env var covers it); no ceiling (rejected — an env typo of e.g. `6000` would add (cap−1)×100 min to a tick).
- **Watcher sleeps; filer defers.** *What:* sleep-then-proceed at the chokepoint; loud no-op + exit 0 in the filer. *Why:* sleeping preserves the tri-state and attempt-booking contracts byte-for-byte (verified: `"suppressed"` books nothing at L12163/L12642; attempts recorded only after a real dispatch attempt) and keeps same-tick drain throughput; the filer must not sleep inside `/daily`'s loop, and its docstring already contracts file-but-no-op with the sweep as backstop (L24–33) — the defer is a fifth instance of an existing pattern. *Source:* #690 (filer no-op contract), #633 (tri-state/booking), verified `watch.lock` flock (L5107 — a long tick skips, never stacks). *Alternatives:* defer in the watcher too (rejected — collapses to one dispatch/tick, option c); a new `"deferred"` tri-state (rejected — contract change for zero benefit).
- **Record only on `"spawned"`, at the two enforcement sites.** *What:* stamp written after a real spawn; suppressed/failed/dry-run never record. *Why:* only a real spawn costs a session cold load; recording a suppression would defer real work for a no-op. Two write sites cover every incident path; wider recording (all spawn arms) is a later additive change. *Source:* #843 M1b no-booking semantics; `_auth_outage_record_spawn` placement precedent (L11794). *Alternatives:* record in `cmd_spawn_issue` (better coverage, rejected for blast radius on the fleet-critical spawn path — named must-ask if wanted later).
- **Fail-open write / bounded fail-toward-pacing read.** *What:* `record_session_dispatch` never raises; garbled read falls back to mtime then `None`. *Why:* a pacing mechanism must never break a successful spawn nor park dispatches indefinitely; any wrong-direction failure is bounded by the ≤300s window. *Source:* `dispatch_lease_fresh` garbled-content mtime fallback (spawn_session L261–283); "fail fast" is satisfied by the loud stderr warning (the failure is visible, not swallowed silently). *Alternatives:* raise on write failure (rejected — would fail the watcher tick over a pacing nicety).
