# Plan — #1613: fail-loud zero-resolution guard for `select_step9c_tests.py --map-files`

## 0.0 TL;DR (plain English)

- **What I'll change:** `--map-files` today prints nothing and exits 0 when you accidentally hand it a source file instead of a list of file paths — the "verification" passes vacuously. I'll add a guard: when zero content lines resolve to existing repo paths AND zero mapping pairs were produced, it errors (exit 2) if the argument is itself a `.py`/`.sh` source file, and warns on stderr (exit 0) otherwise.

## 4. Design

**File 1: `scripts/select_step9c_tests.py`** — insert after the `all_pairs = sorted({...})` statement (line 1283), before the `# The #1573 fail-loud floor` comment (line 1284):

```python
        # #1613 zero-resolution guard: a FILE argument whose content lines
        # resolve to ZERO existing repo paths AND produce ZERO pairs across
        # all arms is the silent operator-error shape (a source file handed
        # instead of a path-LIST file — #1610's vacuously-passing verify
        # command). A deletion-only payload (git diff --name-only includes
        # status-D paths absent from the worktree) legitimately looks like
        # this, so a list-file argument stays exit 0 (hedged WARN only);
        # only an argument that is ITSELF a .py/.sh source file errors —
        # exit 2, the argparse usage-error code (consumers treat rc!=0 as
        # crash-class fail-closed, the intended outcome for a malformed
        # invocation). Pairs suppress the guard: glob/scan arms can map
        # nonexistent (deleted) payload paths, and that output is valid.
        if files and not all_pairs and not any((work_root / f).exists() for f in files):
            if Path(args.map_files).suffix in (".py", ".sh"):
                print(
                    f"select_step9c_tests: ERROR — --map-files argument "
                    f"{args.map_files} looks like a source file, not a "
                    f"path-LIST file: none of its {len(files)} content lines "
                    f"resolve to an existing repo path under {work_root}, and "
                    "no mapping arm produced pairs (#1613); pass a "
                    "newline-delimited path-list file (e.g. "
                    "git diff --name-only > /tmp/files.txt)",
                    file=sys.stderr,
                )
                return 2
            print(
                f"select_step9c_tests: WARN — --map-files input "
                f"{args.map_files} resolved to ZERO existing repo paths under "
                f"{work_root} ({len(files)} content lines, 0 pairs; #1613): "
                "benign for a deletion-only payload; otherwise verify the "
                "argument is a path-LIST file, not a source file",
                file=sys.stderr,
            )
```

Guard predicate (three conjuncts, cheap-first): `files` non-empty ∧ `all_pairs` empty ∧ zero lines resolve. The existence scan runs only when the map is already empty (`not all_pairs` short-circuits), so the common non-empty-map path pays zero stat calls; worst case (the incident shape) is ~1k `Path.exists()` stats, milliseconds.

**Exit-code rule:** exit 2 fires ONLY on (guard-predicate true) ∧ (argument suffix ∈ {`.py`, `.sh`}). Every other guard hit is WARN + exit 0. Exit 1 keeps its existing meanings untouched.

**WARN/stderr grammar constraints (both new lines):** single line, tab-free (the inline gate concatenates stdout+stderr before TSV-parsing — `inline_lint_gate.py:237` + `parse_map_pairs`, which only keeps lines with ≥2 tab-separated fields), and no `recommended-timeout-s=` substring (the TG legs `grep -oE 'recommended-timeout-s=[0-9]+' ... | tail -1` on stderr — SKILL.md:10175, 11356). New grep-distinct prefixes: `ERROR — --map-files argument` / `WARN — --map-files input` (existing grammars: `WARN — scan test`, `WARN — no mapped tests for code file`, `map-files — N pairs`).

## 11. Decision Rationale

N/A — no model training (no hyperparameters; rows below are design decisions).

- **Predicate = zero-resolution ∧ zero-pairs (not zero-resolution alone).** What: guard fires only when NO line resolves AND no arm produced pairs. Why: the glob/scan arms legitimately map nonexistent (branch-deleted) payload paths — e.g. a deleted `scripts/issue123_foo.py` still pairs with its scan test — and warning over a successful map is noise; the incident shape is the fully-silent one (0 pairs). Source: task body (silent zero-map false negative) + `map_scan_tests` behavior read from existing test `test_cli_map_files_tab_output_exit0` (pairs from nonexistent listed paths). Alternative rejected: zero-resolution alone — would emit a misleading WARN beside a valid non-empty map.
- **Exit 2 for the source-file-argument shape.** What: `return 2`. Why: (i) unused by the script's own returns (only 0/1 exist — grepped); (ii) argparse already exits 2 for usage errors on this CLI, and a source-file argument IS a usage error; (iii) consumers treat any rc!=0 as crash-class fail-closed (`TG_CRASH=yes` SKILL.md:10168; `Inconclusive` inline_lint_gate.py:284), the intended outcome per the task body. Source: task body design-constraint 4 + script/consumer code read. Alternative rejected: exit 1 — would blur with "unreadable input file", losing the diagnostic split.
- **Argument-suffix heuristic {`.py`, `.sh`} for escalation.** What: exit 2 only when the FILE argument itself has a source suffix. Why: keeps every list-file consumer categorically safe (all use `.txt` or suffix-less mkstemp names — §5) while catching the incident shape exactly (a `.py` handed directly, #1610); `.sh` is the sibling source class the same operator error produces. Source: task body sketch + incident #1610 + §5 consumer enumeration. Alternatives rejected: content sniffing (fragile, false positives on odd lists); a wider suffix set incl. `.md` (rules files are borderline-plausible arguments; WARN covers them without a false hard-fail).
- **Deleted-paths handling = hedged WARN, exit 0.** What: a zero-resolution LIST file warns but never errors, and the WARN names the deletion-only case as benign. Why: `/tmp/issue-<N>-own-diff.txt` is `git diff --name-only` (SKILL.md:9991) which includes status-D paths absent from the worktree — a deletion-only branch is a legitimate input that must not `TG_CRASH` the merge gate. Source: task body design-constraint 2 + SKILL.md:9991/10168 read. Alternative rejected: exit 2 on all zero-resolution inputs — would fail-close the gate on legitimate deletion-only branches.
- **WARN/ERROR wording + grammar.** What: the two exact strings in §4, tab-free, no `recommended-timeout-s=`, distinct prefixes, `#1613` provenance token, actionable tail ("pass a newline-delimited path-list file"). Why: inline gate TSV-parses concatenated stdout+stderr (tab-free is load-bearing there, not just cosmetic); TG legs grep stderr for the sizing token; existing WARN grammars must stay uniquely greppable. Source: `inline_lint_gate.py:237,240-249` + SKILL.md:10175/11356 + existing WARN strings in the script. Alternative rejected: reusing the `WARN — no mapped tests` grammar — would conflate two distinct diagnostics in log triage.
- **Placement after `all_pairs`, before the #1573 floor loop.** What: guard sits at ~line 1283/1284 boundary. Why: it needs `all_pairs`; on exit 2 it should short-circuit the (empty-anyway) floor/sizing/stdout prints; the WARN case falls through so ordering of stderr lines stays stable for existing greps. Source: branch structure read (lines 1236–1308). Alternative rejected: guard before the arms (cannot honor the pairs-suppress conjunct).
- **No consumer-file edits.** What: SKILL.md TG legs, `inline_lint_gate.py`, implementer duty untouched. Why: exit 2 joins the existing rc!=0 crash class those consumers already handle correctly, and their inline comments remain accurate; touching SKILL.md would widen review surface for zero behavioral gain. Source: §5 analysis. Alternative rejected: documenting the new exit code in SKILL.md comments — optional polish, not load-bearing; deferred to keep the diff minimal (allowed-deviation if the implementer disagrees with one comment line).
