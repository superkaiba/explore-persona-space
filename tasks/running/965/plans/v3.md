# Plan — #965: PreToolUse deny-hook for harmful-bank file reads

## 0.0 TL;DR (plain English)

- **What I'll do:** add a small shell script hook that Claude Code runs before every Read / Grep / Bash tool call; if the call would print the text of one of the six harmful safety-benchmark question banks into the conversation, the hook blocks it with a message naming the allowed alternatives (counts, `jq 'keys'`, `sha256sum`). Digest operations and normal training/eval pipeline use of the banks stay untouched.
- **What I expect:** the tool-read share of the #866 failure mode (sessions killed by usage-policy refusals after bank text was paged into context via Read/cat/Grep-shaped calls) becomes mechanically impossible through the covered tool paths, while zero legitimate digest or pipeline work is blocked — verified by a ~60-case pytest suite that also asserts the settings.json wiring itself (so the hook cannot ship green but inert).
- **What would change my mind:** if the pytest matrix shows the allow/deny split cannot avoid blocking the blessed digest recipes, or if after merge the hook blocks legitimate work more than very rarely, the verb list gets narrowed or the hook gets reverted (one settings.json object + one script file — trivially reversible).

## 4. Design

### 4.1 Deny set (path predicate)

The six files covering clause (d)'s four named bank families, version-bump tolerant, matched in raw string form AND after `realpath` resolution (catches cwd-relative reads and symlinks):

```
STEM_RE='(advbench|strongreject|betley_main8|wang44|broad_em_train|sensitive_info_requests)'
BANK_RE="(^|/)query_banks/${STEM_RE}[^/]*\.json$"
```

`is_bank_path(p)`: strip one layer of surrounding quotes; TRUE if `p` matches `BANK_RE`; else, if `p`'s basename matches `(^|/)${STEM_RE}[^/]*\.json$` AND `p` is an existing file whose `realpath` matches `BANK_RE`, TRUE; else FALSE.

`is_bank_dir(p)` (Grep arm only): strip quotes; TRUE if `p` matches `(^|/)query_banks/?$` in raw form, or is an existing directory whose `realpath` matches it. Content-mode Grep scoped to the bank DIRECTORY returns harmful bank item lines just as surely as one scoped to a bank file (the directory is visible pre-execution, unlike the `path: src/` residual), so it denies; count/files modes on the same directory stay allowed.

Consequences: absolute VM paths, repo-relative paths, worktree copies (`.claude/worktrees/issue-N/src/.../query_banks/...`), and pod-style `/workspace/.../query_banks/...` strings all match on the raw regex; a cwd-local `cat advbench_v1.json` from inside the query_banks dir matches via the realpath branch; `eval_results/issue_X/advbench_summary.json` (aggregate results named after the bank — explicitly BLESSED by clause (d)) does NOT match (no `query_banks/` dir component, and its realpath is not under query_banks). `china_sensitive_v1.json` is excluded (§11 item 8). `README.md` in the bank dir never matches (basename must start with a stem).

### 4.2 The script — `.claude/hooks/guard_harmful_bank_read.sh` (near-final)

Follows the NEWER stdin-JSON convention (settings.json hooks #2/#5, `guard_log_dump.sh`, `guard_repo_root_branch.sh`), NOT the legacy `$TOOL_INPUT` env of hook #1.

```bash
#!/usr/bin/env bash
# PreToolUse(Read|Bash|Grep|mcp__ssh__ssh_execute) guard: harmful-bank files
# are DIGEST-ONLY (CLAUDE.md § Spurious usage-policy refusals, clause (d)).
# Mechanizes the #888 prose rule; incident #866: four implementer sessions
# refusal-killed after bank item text was paged into context.
#
# Contract: reads the PreToolUse JSON on stdin; exit 0 = allow, exit 2 =
# blocking deny (stderr fed back to Claude). Fail-OPEN: any parse failure /
# unrecognized shape exits 0 (a broken guard must never brick every tool call).
# Escape hatch: EPM_ALLOW_BANK_READ=1 as session env, or as an inline prefix
# on a Bash command (`EPM_ALLOW_BANK_READ=1 jq '.[]' <bank>`).
set -u

STEM_RE='(advbench|strongreject|betley_main8|wang44|broad_em_train|sensitive_info_requests)'
BANK_RE="(^|/)query_banks/${STEM_RE}[^/]*\.json\$"
BARE_RE="(^|/)${STEM_RE}[^/]*\.json\$"
BANKDIR_RE='(^|/)query_banks/?$'
DENY_VERBS_RE='^(cat|tac|nl|head|tail|sed|awk|cut|sort|uniq|rev|strings|less|more|most|bat|od|xxd|hexdump|base64|fold|fmt|pr|column|paste|json\.tool)$'
JQ_DIGEST_RE='^(keys|keys_unsorted|length|type|empty)$'
GUARD_LOG="${EPM_BANK_GUARD_LOG:-/home/thomasjiralerspong/explore-persona-space/.claude/cache/bank-guard-denies.log}"

# Session-env escape hatch (all tool arms).
_allow=$(printf '%s' "${EPM_ALLOW_BANK_READ:-}" | tr '[:upper:]' '[:lower:]')
case "$_allow" in 1 | true | yes) exit 0 ;; esac

log_deny() {  # best-effort sidecar record for the §7 FP kill criterion —
  # NEVER affects the exit path (a log failure must not change a verdict).
  { printf '%s\t%s\t%.200s\n' "$(date -u +%FT%TZ)" "$1" "$2" >> "$GUARD_LOG"; } 2>/dev/null || true
}

is_bank_path() {
  local p="$1" rp
  p=${p#\'}; p=${p%\'}; p=${p#\"}; p=${p%\"}
  [ -n "$p" ] || return 1
  printf '%s' "$p" | grep -qE "$BANK_RE" && return 0
  if printf '%s' "$p" | grep -qE "$BARE_RE" && [ -f "$p" ]; then
    rp=$(realpath "$p" 2>/dev/null) || return 1
    printf '%s' "$rp" | grep -qE "$BANK_RE" && return 0
  fi
  return 1
}

is_bank_dir() {
  local p="$1" rp
  p=${p#\'}; p=${p%\'}; p=${p#\"}; p=${p%\"}
  [ -n "$p" ] || return 1
  printf '%s' "$p" | grep -qE "$BANKDIR_RE" && return 0
  if [ -d "$p" ]; then
    rp=$(realpath "$p" 2>/dev/null) || return 1
    printf '%s' "$rp" | grep -qE "$BANKDIR_RE" && return 0
  fi
  return 1
}

deny() {  # $1 = what was attempted, $2 = the bank path
  log_deny "$1" "$2"
  echo "BLOCKED: $1 would page harmful-bank item text into context ($2). CLAUDE.md § Spurious usage-policy refusals (d): harmful BANK items are DIGEST-ONLY — reference by filename + index, never print item text (incident #866: four sessions refusal-killed). Allowed digest ops on the file directly: jq 'length' | jq 'keys' | jq 'type' | wc -l | sha256sum | ls | stat | grep -c (no pipes through cat). A sanctioned-maintenance override exists for deliberate bank regeneration work — see CLAUDE.md § Spurious usage-policy refusals clause (d)." >&2
  exit 2
}

input=$(cat) || exit 0
tool=$(printf '%s' "$input" | jq -r '.tool_name // empty' 2>/dev/null) || exit 0

# ---- Read arm ------------------------------------------------------------
fp=$(printf '%s' "$input" | jq -r '.tool_input.file_path // empty' 2>/dev/null) || exit 0
if [ -n "$fp" ] && { [ -z "$tool" ] || [ "$tool" = Read ]; }; then
  is_bank_path "$fp" && deny "Read" "$fp"
  exit 0
fi

# ---- Grep arm (content mode only; bank FILE or the query_banks DIR) -------
if [ "$tool" = Grep ]; then
  gpath=$(printf '%s' "$input" | jq -r '.tool_input.path // empty' 2>/dev/null) || exit 0
  gmode=$(printf '%s' "$input" | jq -r '.tool_input.output_mode // "files_with_matches"' 2>/dev/null) || exit 0
  if [ "$gmode" = content ] && [ -n "$gpath" ]; then
    if is_bank_path "$gpath"; then
      deny "Grep (output_mode: content — matching lines ARE bank items; use output_mode files_with_matches/count, or jq 'length')" "$gpath"
    fi
    if is_bank_dir "$gpath"; then
      deny "Grep (output_mode: content on the query_banks directory — matching lines can be harmful-bank items; scope to a specific benign file, or use output_mode files_with_matches/count)" "$gpath"
    fi
  fi
  exit 0
fi

# ---- Bash arm (also mcp__ssh__ssh_execute: same command-string shape) -----
cmd=$(printf '%s' "$input" | jq -r '.tool_input.command // empty' 2>/dev/null) || exit 0
[ -n "$cmd" ] || exit 0

# Inline escape hatch.
case "$cmd" in *EPM_ALLOW_BANK_READ=1*) exit 0 ;; esac

# Fast path: no bank-stem-shaped token anywhere -> allow (hook runs on EVERY
# Bash call; this single grep is the common-case cost).
printf '%s' "$cmd" | grep -qE "${STEM_RE}[^/[:space:]]*\.json" || exit 0

# Normalize shell control operators BEFORE the token walk so unspaced forms
# tokenize (`cat <bank>|grep foo`, `cat <bank>&&echo`, `cat <bank>;echo`,
# trailing `)`s) — otherwise the operator glues to the path token and the
# $-anchored .json match fails open. Padding inside quoted strings only
# affects tokenization, never execution (we never rewrite the command).
cmd_norm=$(printf '%s' "$cmd" | sed 's/[|;&<>()]/ & /g')

# Whole-command raw scan (deliberately NO clause split — see plan §11.3):
# word-split; find a bank token; if present, deny on any text-paging verb
# token, on grep-family line output (per-executable safe flags, per-instance
# tracking), on git show/diff/log -p paging, or on jq with a non-digest
# filter. Everything else (python/uv pipelines, cp, git add/commit, wc,
# sha256sum, stat, du, redirects) is allowed by default.
set -f
# shellcheck disable=SC2086
set -- $cmd_norm
set +f

bank=""
for tok in "$@"; do
  if is_bank_path "$tok"; then bank="$tok"; break; fi
done
[ -n "$bank" ] || exit 0

has_grep=0 grep_safe=0 grep_kind="" grep_any_unsafe=0
has_jq=0 jq_filter="" jq_seen=0
in_git=0 git_sub="" git_safe=0 git_log_patch=0
for tok in "$@"; do
  base="${tok##*/}"
  if printf '%s' "$base" | grep -qE "$DENY_VERBS_RE"; then
    deny "'$base' on a bank file" "$bank"
  fi
  case "$base" in
    grep | egrep | fgrep | rg)
      # PER-INSTANCE tracking: a prior grep instance still unsafe when a new
      # one starts stays unsafe — a later instance's -c cannot launder it.
      if [ "$has_grep" = 1 ] && [ "$grep_safe" = 0 ]; then grep_any_unsafe=1; fi
      has_grep=1; grep_safe=0
      case "$base" in rg) grep_kind=rg ;; *) grep_kind=grep ;; esac
      ;;
    jq) has_jq=1; jq_seen=0 ;;
    git) in_git=1 ;;
  esac
  if [ "$in_git" = 1 ] && [ -z "$git_sub" ]; then
    case "$base" in show | diff | log) git_sub="$base" ;; esac
  fi
  case "$tok" in
    --stat | --numstat | --shortstat | --name-only | --name-status | --check | --summary | --oneline) git_safe=1 ;;
    -p | -u | --patch) git_log_patch=1 ;;
  esac
  # grep-family safe flags, PER EXECUTABLE:
  #   grep/egrep/fgrep — count/quiet/file-list digests: -c/-q/-l/-L (+ long forms).
  #   rg — same EXCEPT -L, which is ripgrep --follow (prints matching lines!);
  #        long digest forms allowed. -C (context) must never match (case-aware).
  if [ "$has_grep" = 1 ]; then
    case "$tok" in
      --count | --count-matches | --quiet | --silent | --files-with-matches | --files-without-match) grep_safe=1 ;;
      *)
        if [ "$grep_kind" = rg ]; then
          printf '%s' "$tok" | grep -qE '^-[a-zA-Z]*[cql]' && grep_safe=1
        else
          printf '%s' "$tok" | grep -qE '^-[a-zA-Z]*[cqlL]' && grep_safe=1
        fi
        ;;
    esac
  fi
  # jq filter = first token after `jq` that is not a flag and not the file.
  if [ "$has_jq" = 1 ] && [ "$jq_seen" = 0 ] && [ "$base" != jq ]; then
    case "$tok" in
      -*) : ;;
      *)
        if ! is_bank_path "$tok"; then jq_filter="$tok"; jq_seen=1; fi
        ;;
    esac
  fi
done

if [ "$has_grep" = 1 ] && [ "$grep_safe" = 0 ]; then grep_any_unsafe=1; fi
if [ "$grep_any_unsafe" = 1 ]; then
  deny "grep-family line output on a bank file (matching lines ARE items; use grep -c / -q / -l; note rg -L is --follow, NOT files-without-match)" "$bank"
fi
if [ -n "$git_sub" ] && [ "$git_safe" = 0 ]; then
  case "$git_sub" in
    show | diff) deny "git $git_sub paging a bank file (the patch text IS bank items; use git diff --stat / --name-only)" "$bank" ;;
    log) [ "$git_log_patch" = 1 ] && deny "git log -p paging a bank file (use git log --oneline -- <bank>)" "$bank" ;;
  esac
fi
if [ "$has_jq" = 1 ]; then
  f=${jq_filter#\'}; f=${f%\'}; f=${f#\"}; f=${f%\"}
  printf '%s' "$f" | grep -qE "$JQ_DIGEST_RE" \
    || deny "jq '$f' on a bank file (item-access / non-digest filter; allowed: jq 'keys' | 'length' | 'type')" "$bank"
fi
exit 0
```

Design notes baked into the logic:

- **Whole-command scan, no clause/pipe split.** A pipe or `&&` does not exempt anything: `cat <bank> | wc -l` denies (message points at the equivalent allowed form `wc -l <bank>`); `jq '.[] | tostring' <bank>` denies (the quoted pipe cannot detach the file from the verb, the fail-open leak a clause-splitter would create — the raw-scan lesson from `guard_repo_root_branch.sh` #796/#804, taken in the fail-closed direction). The FP cost is a compound command that mentions a bank in one clause and a deny verb in another (`wc -l <bank> && cat notes.md`) — denied with a message that says to split into separate tool calls. Rare shape, self-remediating.
- **jq digest allow-list, single-word filters only.** `jq 'length'`, `jq 'keys'`, `jq 'keys_unsorted'`, `jq 'type'`, `jq 'empty'` allowed — exactly the clause-(d) blessing. `jq '.'`, `jq -r '.[]'`, `jq '.[0]'`, `jq '. | length'` (multi-word, shredded by word-split anyway) deny; the message names the allowed single-word forms.
- **Default-allow unknown verbs.** `uv run python scripts/eval.py --bank .../advbench_v1.json`, `git add <bank>`, `cp`, `sha256sum`, `wc`, `ls`, `stat`, `du`, `find`, `test -f` all pass — the banks' entire purpose is in-process consumption by pipeline code, where item text never enters Claude's context. This is why a fail-closed allow-list over verbs is wrong here (it would break every training/eval launch that names a bank). Two named exceptions carved OUT of default-allow because they page text while looking innocuous: `python -m json.tool <bank>` (the `json.tool` token is in `DENY_VERBS_RE`) and `git show`/`git diff`/`git log -p` on a bank (the patch text IS bank items; digest forms `--stat`/`--name-only`/`--name-status`/`--numstat` stay allowed — `git diff` paging a bank is the realistic in-repo review shape, since banks are committed files whose diffs a code-reviewer would otherwise read).
- **Per-executable, per-instance grep-family flags.** For ripgrep, `-L` is `--follow` (prints matching lines), NOT files-without-match as in GNU grep — so `rg`'s short-flag digest set is `-c/-q/-l` only, while `grep/egrep/fgrep` keep `-c/-q/-l/-L`; long digest forms are allowed for both. Flag tracking is per grep INSTANCE: `grep harmful <bank> && grep -c foo other.txt` denies (the second instance's `-c` cannot launder the first).
- **Operator normalization before tokenizing.** `sed 's/[|;&<>()]/ & /g'` pads shell control operators so `cat <bank>|grep foo`, `cat <bank>&&echo done`, `cat <bank>;echo` tokenize identically to their spaced forms — closing the unspaced-operator false negative. Padding happens on a scan-local copy; the command is never rewritten.
- **Deny sidecar log.** Every deny appends one tab-separated line (UTC ts, what, truncated target) to `.claude/cache/bank-guard-denies.log` (override: `EPM_BANK_GUARD_LOG`, used by tests) — best-effort, `|| true`, never affects the verdict. This makes the §7 false-positive kill criterion mechanically countable instead of transcript-archaeology.
- **The deny message does NOT print the literal override.** Forgetful agents under pressure would paste it reflexively; the message names the digest alternatives and points at CLAUDE.md clause (d), where maintainers find `EPM_ALLOW_BANK_READ=1` documented.
- **`head`/`tail` have no safe form** on a bank (banks are pretty-printed one item per line — verified: `wang44_v1.json` = 46 lines for 44 items — so any line slice is item text). Deny unconditionally; digest alternatives are in the message.

|---|---|---|
| `Read` | YES — deny any bank `file_path` | The #866 kill path; any offset/limit slice is item text |
| `Bash` | YES — verb-classified | cat/head/sed/etc. page text; digest ops must stay allowed |

The query_banks dir itself IS identifiable pre-execution → denied in content mode. | `Edit`/`Write` | NO | writing doesn't page text into context; editing requires a Read first (blocked) |

## 5. Controls → false-positive / false-negative analysis (infra substitute)

**Stays allowed (false-positive checks, all test-pinned):**

- `jq 'length'` / `jq 'keys'` / `jq 'type'` on any bank — the clause-(d) blessed digests.
- `wc -l <bank>`, `sha256sum <bank>`, `md5sum <bank>`, `ls`/`stat`/`du`/`file` on the bank or its dir.
- `grep -c <pat> <bank>`, `grep -q`, `grep -l` — count/quiet/file-list digests.
- `uv run python scripts/train.py|eval.py ... <bank>` and any script invocation naming a bank as an argument — in-process consumption.
- `git add/commit` touching banks; `git diff --stat/--name-only/--numstat -- <bank>`; `git log --oneline -- <bank>`; `cp`/`mv` of banks.
- Read/cat/grep on the benign banks: `arc_c_v1.json`, `fact_questions_v1.json`, `marker_eval_v1.json`, `sycophancy_claims_v1.json`, `wildchat_random_v1.json`, `china_sensitive_v1.json`, and `query_banks/README.md`.
- Read/cat on `eval_results/**/advbench*.json`-style AGGREGATE files (blessed by clause (d)) — the `query_banks/` dir requirement plus realpath check keeps these out of the deny set.

**Known accepted false positives (deny with self-remediating message):**

- `cat <bank> | wc -l` (use `wc -l <bank>`); `cat <bank> | sha256sum` (use `sha256sum <bank>`).
- `jq '. | length' <bank>` (use `jq 'length'`).
- A compound command mixing a bank mention with an unrelated cat/sed clause (split into two tool calls).

**Residual leak paths the hook does NOT cover (honest, deliberate — cooperative-agent threat model, same as `guard_repo_root_branch.sh`'s THREAT MODEL header):**

1. `uv run python -c "print(open('<bank>').read())"` and heredoc equivalents — classifying arbitrary python source in bash is out of reach; the prose rule governs.
2. Copy-then-read: `cp <bank> /tmp/x.json && cat /tmp/x.json` (the second command has no bank-shaped token).
3. Partial-stem globs (`cat query_banks/adv*.json`) — the unexpanded glob doesn't match the full stem. (`advbench*.json` DOES match.)
4. BROADER directory-scoped Grep-tool content search (`path: src/` or repo root, pattern hitting bank lines) — target not identifiable pre-execution. (Content mode scoped to the `query_banks` dir itself IS covered — §4.3.)
5. `xargs cat`, `find -exec cat`, editors, `dd` — exotic paging verbs beyond the enumerated list. Likewise `git show <sha>` forms whose argument carries no bank-shaped token (a bare commit sha) — undetectable pre-execution; the covered git shapes are those naming a bank path/spec.
6. Prompt-level trigger text (the second #866 kill mechanism) — no hook can fix what's already in a brief; that stays with the #866/#888 brief-hygiene rules.

Why the scope is still worth it (honest share, corrected against the #866 record): roughly HALF the #866 refusal-kills were tool-read-shaped — bank text paged in via ordinary Read/cat during verification — and those are exactly the shapes this hook covers; the OTHER kills were prompt-level (refusals at 0–2 tool uses, trigger-dense brief text), which no hook can reach and which stay with the #866/#888 brief-hygiene rules (residual 6). So the expected incident reduction is the tool-read share, not the whole class. The residuals require deliberately unusual constructions a cooperative agent following ANY of the prose guidance won't reach for; and the deny message re-teaches the rule at exactly the moment the agent is about to violate it, which also reduces residual-path attempts.

## 11. Decision Rationale

1. **Hook logic in a script file, not inline jq.** *What:* `.claude/hooks/guard_harmful_bank_read.sh`. *Why:* pytest-testable by piping synthetic JSON; inline settings.json one-liners are untestable and unreviewable at this complexity. *Source:* repo precedent — `guard_log_dump.sh` (same dir), `guard_repo_root_branch.sh` + its 773-line pytest file. *Alternatives:* inline jq (rejected: untestable); python script (rejected: bash matches both siblings, zero-dependency).
2. **Matcher set `Read|Bash|Grep|mcp__ssh__ssh_execute`.** *What:* four tools, one script. *Why:* Read = the #866 kill path; Bash = cat/head/sed paging; Grep content-mode returns item lines (banks verified one-item-per-line); ssh_execute = the identical command-string shape pod-side, free coverage with fail-open safety. *Source:* #866 incident record (#888 body), `wc -l` verification of bank files, existing `Edit|Write` pipe-matcher precedent. *Alternatives:* Read-only (rejected: cat evades trivially); adding Edit/Write (rejected: no context-paging mechanism).
3. **Whole-command Bash scan, no clause/pipe splitting.** *What:* bank token + deny-verb co-occurrence denies, regardless of pipes/redirects/separators. *Why:* a clause splitter fails OPEN on quoted pipes (`jq '.[] | tostring' <bank>` detaches file from filter across the split) — for THIS guard any item text is the poison, so the error direction must be fail-closed; the FP shapes are rare and self-remediating. *Source:* `guard_repo_root_branch.sh` #796/#804 raw-scan post-mortems (quoted-separator trade-off documented in its header); `guard_log_dump.sh`'s pipe-allow rationale explicitly does NOT transfer (its concern is size, ours is any item text). *Alternatives:* guard_log_dump-style pipe-allow (rejected: `cat <bank> | head -3` leaks 3 items); full clause state machine (rejected: more code, fail-open residue).
4. **Allow/deny split: deny-list verbs + grep-flag exception + jq single-word digest allow-list; default-allow unknown verbs.** *Why:* clause (d) blesses counts/`jq 'keys'`/sha256 — those must pass; banks are legitimately consumed in-process by training/eval scripts, so fail-closed-on-unknown would break every pipeline launch naming a bank. *Source:* CLAUDE.md clause (d) verbatim; query_banks/README.md (banks exist to be loaded by `artifacts/banks.py`). *Alternatives:* verb allow-list (rejected: breaks `uv run python scripts/... <bank>`); deny-all-jq (rejected: contradicts the blessed `jq 'keys'`).
5. **Fail-open on parse errors.** See risk table — a guard bug must not become a fleet outage; the prose rule backstops a miss. *Source:* both sibling guards' explicit fail-soft contract. *Alternative:* fail-closed (rejected: converts one hook bug into total session breakage; the asymmetry is decisive because the hook fires on every call).
6. **Escape hatch `EPM_ALLOW_BANK_READ=1` (env + inline Bash prefix).** *Why:* sanctioned maintenance exists — #866 itself authored banks inline and future bank regeneration needs item-level ops; a loud, typed, greppable override beats hidden workarounds. Read/Grep have no inline form — maintenance uses the Bash override (documented in the deny message). *Source:* `EPM_ALLOW_LOG_DUMP` precedent (identical mechanics). *Alternatives:* no override (rejected: forces settings.json edits for legit maintenance); sentinel file (rejected: less visible in transcripts than an inline prefix).
7. **Exit 2 + stderr BLOCKED message.** *Source:* documented PreToolUse blocking code, cited with URL in `guard_repo_root_branch.sh` header ("If your hook is meant to enforce a policy, use exit 2"), and the existing BLOCKED-message style (settings.json hooks 1/5). *Alternative:* JSON decision output (rejected: no repo precedent; exit-2 is proven here).
8. **`china_sensitive_v1.json` EXCLUDED from the deny set.** *What:* the deny set is exactly clause (d)'s six banks. *Why:* (a) the bank's README entry states "content is factual-question-grade by design" — civic/political candor probes authored in #866 itself with content hygiene in mind, not harmful-instruction text; the #866 refusal mechanism was violative-content (advbench/strongreject-class) text, which this bank by construction lacks; (b) the hook mechanizes clause (d) 1:1 — silently widening a mechanical deny beyond the prose rule it enforces would make the hook the de-facto policy author; (c) the analyzer sanitize rule's "when unsure, sanitize" governs the analyzer's *excerpting*, and china_sensitive is deliberately not in its benign list either — that softer treatment (sanitize, don't hard-block) is the right layer for a borderline bank. Extension is a one-token edit to `STEM_RE` if policy changes. *Source:* `query_banks/README.md` (#866 materialization notes); CLAUDE.md clause (d) enumeration; `.claude/rules/analyzer-section-reference.md` lines 130–155. *Alternative:* include it (rejected per (a)–(c); revisit if any session is ever refusal-killed on this bank — that event would move it into clause (d) first, then here).
9. **Grep tool covered, content-mode only — on bank files AND the query_banks dir.** *Why:* one-item-per-line pretty-printing means content matches return item text; the other output modes are digests. The dir-scoped content case was a round-1 critic Must-Fix (statistics/Codex): the risky directory IS visible pre-execution, unlike broader `path: src/` scopes which stay residual. *Source:* `wc -l` verification (wang44: 46 lines / 44 items); Grep tool schema (output_mode enum, default files_with_matches); round-1 critique. *Alternative:* skip Grep (rejected: it is the project's mandated search tool — "ALWAYS use Grep for search tasks" — so it is a high-traffic path to exactly this leak).
10. **Per-executable grep-family flag semantics (round-1 Must-Fix, methodology/Codex, reconciler-upheld).** *What:* `rg` digest short-flags = `-c/-q/-l` (NOT `-L`); grep/egrep/fgrep keep `-c/-q/-l/-L`; long digest forms allowed for both; per-INSTANCE tracking so a later safe grep cannot launder an earlier unsafe one. *Why:* ripgrep `-L` is `--follow` (prints matching lines) — a shared flag regex would allow `rg -L pat <bank>` to page item text, a false negative inside the arm the plan declares fail-closed. *Source:* `rg --help` (verified live by the reconciler); round-1 critique. *Alternative:* drop rg from the grep family (rejected: rg IS installed and used on this VM; unclassified rg would default-allow line output).
11. **Settings-WIRING pytest (round-1 Must-Fix, statistics both reviewers + methodology Codex).** *What:* §6 case 20 / acceptance 2b. *Why:* every other test drives the script directly; without a wiring assertion a matcher typo / wrong path / missing +x ships the mechanical layer inert with a green suite — the sharpest false-PASS channel. Invoking the CONFIGURED command (not the repo constant) also smoke-covers the A7 hot-reload reality. *Source:* round-1 critique (three independent raisings). *Alternative:* live-fire only (rejected: explicitly non-blocking, can't gate a merge).
12. **git show/diff/log -p paging denied; digest git forms allowed (round-1 alternatives-lens advisory, adopted).** *Why:* banks are committed, reviewed files — a reviewer diffing a bank edit re-creates the #866 kill with no other verb present; `--stat/--name-only/--numstat/--oneline` forms are digests and stay allowed (`git add/commit` untouched). Plain `git show <sha>` with no bank-shaped token stays residual (undetectable). *Source:* round-1 alternatives critique (Claude + Codex convergent); #866 was itself a bank-authoring task with diff review. *Alternative:* leave git default-allowed (rejected: the realistic in-repo leak shape).
13. **Deny sidecar log + no literal override in the deny message (round-1 advisories, adopted).** *Why:* the §7 FP kill criterion needs a mechanical counter (transcript archaeology is passive and unreliable); printing the override incantation verbatim invites reflexive pasting by exactly the forgetful agents the hook guards — CLAUDE.md clause (d) documents it for deliberate maintenance instead. *Source:* round-1 statistics (S3) + alternatives (E/F) critiques. *Alternatives:* no log (rejected: kill criterion unobservable); print the override (rejected: undermines the guard for its own population).
