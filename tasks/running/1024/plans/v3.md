### D-A. Parser change — `src/explore_persona_space/eval/utils.py`

Replace the function (whole-file diff, file is 22 lines):

```python
def parse_judge_json(text: str) -> dict | list | str | int | float | bool | None:
    """Extract the first JSON value from judge response text; ``None`` on parse failure.

    Returns ``json.loads(text)`` VERBATIM when the whole text is valid JSON —
    including bare scalars (``"85"`` -> ``85``): graded-judge callers
    (``eval/graded_judge.py::_score_from_parsed``, #778 r3) depend on the
    scalar passthrough. Otherwise falls back to decoding the first
    ``{``-anchored object embedded in noisy text (markdown fences, preamble).

    On parse failure returns ``None`` — NEVER a coerced placeholder
    (drop-never-coerce, ``.claude/rules/llm-judging.md`` rule 9; the #766
    ``eval/belief.py`` precedent). Callers must DROP a ``None`` (record an
    error row / exclude from aggregates), never substitute a default score.

    Pre-existing ambiguity, unchanged: the literal JSON ``null`` also returns
    ``None`` and is indistinguishable from a parse failure; every project
    rubric returns an object or scalar, so callers treat ``None`` uniformly
    as a dropped row.
    """
    try:
        return json.loads(text)
    except json.JSONDecodeError:
        pass
    try:
        start = text.index("{")
        obj, _ = json.JSONDecoder().raw_decode(text, start)
        return obj
    except (ValueError, json.JSONDecodeError):
        logger.warning(
            "Failed to parse judge JSON; returning None (caller must DROP this "
            "row, never coerce). Text: %.200s",
            text,
        )
        return None
```

Notes: the exact new warning text is the two-line string above. The prefix is raised `%.100s` → `%.200s` because in #778 the log prefix was the only surviving forensic evidence of the failing judge texts; the hardcoded trailing `"..."` of the old format string is dropped (it printed even for short texts). Noisy-text extraction behavior (`raw_decode` from first `{`) is byte-identical.

## 11. Decision Rationale

1. **Drop the `default` parameter entirely (vs keep with None-only enforcement).**
   *What:* `parse_judge_json(text: str)` — one parameter.
   *Why:* every production caller passes `None` (15/15 audited sites); only two tests exercise a non-None default. Keeping the parameter keeps the coercion affordance this task exists to remove; a runtime "must be None" assert is strictly worse than deleting it (same blast radius, more code). A two-arg call fails loud with `TypeError` — the project's fail-fast norm.
   *Source:* llm-judging.md rule 9 (drop-never-coerce); #766 (`eval/belief.py` port); plan-time grep audit (§4 D-B).
   *Alternatives:* deprecated kwarg with `FutureWarning` (rejected — keeps the affordance live for the deprecation window; no external consumers justify a window); keep-with-assert (rejected — dead parameter).

2. **Return annotation `dict | list | str | int | float | bool | None` (vs `Any`, vs the stale `dict | None`).**
   *What:* spell the JSON-value union explicitly.
   *Why:* the verbatim scalar passthrough is a load-bearing contract (`graded_judge._score_from_parsed` handles bare ints, #778 r3; `_aggregate_persona_scores` carries an `isinstance(s, dict)` guard for exactly this, #778 r2) — the stale `dict | None` annotation actively misled callers. `Any` hides the contract; the explicit union documents it. The `null`→`None` ambiguity is pre-existing and documented in the docstring.
   *Source:* #778 r3 `_score_from_parsed` docstring (graded_judge.py:67-112); #778 r2 aggregator fix (batch_judge.py:564-571); clarifier finding 4.
   *Alternatives:* `Any` (rejected — undocuments the contract); `object` (rejected — fights every caller under future type checking).

3. **Dropped-count mechanism: parser stays pure; no new counter/telemetry.**
   *What:* rely on existing aggregate-layer reporting (`n_errors` in `_aggregate_persona_scores`, `JudgeResult.n_dropped_draws`, explicit parse_error dicts in `judge_dispatch` returns); fix only the misleading warning text.
   *Why:* rule 9 requires the dropped count be REPORTED where aggregates are computed — it already is, at every aggregate site (verified §D-C). A parser-layer counter would be global mutable state threaded through async dispatch paths for zero new information.
   *Source:* llm-judging.md rule 9; #810 `_parse_graded_score` lineage (rule 22 file-of-record); batch_judge.py:545/590; graded_judge.py:115-128 read at plan time.
   *Alternatives:* module-level counter (rejected — global state, double-counts on retries); structured per-call return `(value, ok)` tuple (rejected — 15-site churn for information the None already carries).

4. **Fix `batch_judge.py:308` truthiness; leave `run_a3*.py`'s identical pattern noted-only.**
   *What:* `parsed or X` → `parsed if parsed is not None else X` on the live batch path only.
   *Why:* a bare `0` is a legitimate graded score (the 0-100 scale includes 0) that the truthiness check would convert to a parse_error. Fact-check corrected reach: `_collect_legacy_results` is reached only via `_submit_and_poll_batch`, whose live callers are frozen legacy #389 scripts — the graded/#778 path routes via judge_dispatch collectors that already use `is not None`, so a bare 0 is kept there today. The fix is HARDENING of a shared src/ module (any future `_submit_and_poll_batch` caller inherits it), not a production-path bug fix; the a3 scripts (same pattern, frozen legacy, script-local) stay noted-only under the minimal-port contract.
   *Source:* llm-judging.md rule 9 + graded-score scale (rules 1/9); #778 r2/r3 precedents; plan-time read of batch_judge.py:299-324.
   *Alternatives:* fix all three sites (rejected — behavioral churn in untested frozen scripts); fix none (rejected — the graded mis-drop is real).

5. **Leave `run_em_multiseed.py`'s local copy untouched.**
