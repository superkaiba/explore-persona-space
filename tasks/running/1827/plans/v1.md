# Plan v1 — task #1827: WARN-tier plan-conditions coverage check in verify_task_body.py

### TDD: no

## Plan Summary

Add ONE new WARN-tier check to `scripts/verify_task_body.py` that parses the approved
plan's §5 conditions table (the `Config slug` column) and WARNs when a slug — or its
plain-English row name — appears neither in the clean-result body nor anywhere in the
body text (an explicit skip/descope sentence naming the slug counts as a body mention
by construction). Closes the #1774 `cell_pre_own` silent-drop gap: a plan-committed
condition dropped from the body entirely is today invisible to every mechanical check
(check 11b keys on conditions the body NAMES). NOT architectural — a new WARN-only
check, no schema / CLI / status changes.

## Requirement + acceptance criteria

1. New check function `check_plan_conditions_coverage(body: str, *, plan_path: Path | None = None) -> CheckResult` in `scripts/verify_task_body.py`.
2. Registered in `verify_text()` beside the other `plan_path`-consuming check (immediately after the `check_repro_lr_matches_plan` append, ~line 14558) — it needs the sibling `plans/plan.md`, so it lives outside the body-only `CHECKS` list.
3. **Plan-version resolution:** `plan_files = sorted(plan_path.parent.glob("v*.md")) or [plan_path]` (the `check_repro_lr_matches_plan` pattern, line 4207); walk from the LATEST version backwards and use the FIRST file that contains a parseable conditions table (a follow-up amendment plan may legitimately carry no conditions table — fall back to the newest prior version that does).
4. **Table detection:** a markdown table following a heading matching `(?im)^#{2,4}\s*(?:\d+\.?\s*)?conditions` whose header row contains a column matching `(?i)config[ -]?slug`. Extract per data row: the backtick-wrapped slug from that column (rows whose slug cell has no backtick-wrapped token are skipped) + the plain-English name (first column, stripped of markdown emphasis).
5. **Verdict semantics (WARN tier only — this check can NEVER FAIL):**
   - For each (slug, name) row: covered iff the slug appears in the body (exact substring) OR the plain-English name appears in the body (case-insensitive substring, after stripping emphasis markers from both sides).
   - ≥1 uncovered row → `CheckResult(name, True, "<k> plan-§5 condition(s) with no body mention: `slug1` (Row Name 1), ... — name each in the relevant ### result / Takeaways or record the descope per After-Every-Experiment item 8", is_warn=True)`.
   - All covered → plain PASS with a `<n> plan conditions all covered` detail.
6. **NO-OP PASS** when: `plan_path` is None or missing; no plan version contains a conditions table with a config-slug column; the table parses to zero slug rows. (Kind gating needs no new code — `main()` already short-circuits `kind: infra|batch|survey` to the N/A verdict, #1493; `kind: analysis` tasks rarely have a §5 conditions table and hit the NO-OP.)
7. **Tests** in `tests/test_verify_task_body.py` (new test class/functions beside the check-16 plan tests): (a) slug present in body → PASS; (b) slug + name both absent → WARN naming the slug; (c) slug absent but plain-English name present → PASS; (d) `plan_path=None` → NO-OP PASS; (e) plan without a conditions table → NO-OP PASS; (f) a #1774-shaped 16-row table parses all 16 slugs (fixture cut from the real plan shape); (g) WARN is `is_warn=True, passed=True` (never blocks).
8. **Lens-prose sync:** one short addition to the planned-vs-actual lens text in `.claude/rules/clean-result-critic-lens-reference.md` (Lens 13) noting the mechanical WARN tier now exists in `verify_task_body.py` and that the LM lens remains authoritative for paraphrase-level drops. Keep it to ≤3 lines; do not renumber or restructure the lens.
9. `uv run ruff check scripts/verify_task_body.py tests/test_verify_task_body.py` clean; no-flags `scripts/workflow_lint.py` introduces no NEW failure lines.
