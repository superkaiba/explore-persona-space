### 4.1 Add three module-level helpers (after `list_repo_files_complete`, ~line 501, before `_upload`)
Port verbatim from issue658 (keep `logger` already at module scope; use the module-level `import time`):
```python
def _is_storage_quota_403(err: Exception) -> bool:
    """Persistent account-wide public-storage 403 (NOT transient). Mirrors the
    issue658 predicate; upload-policy.md § HF storage-quota 403."""
    msg = str(err)
    return "403" in msg and "storage" in msg.lower()

def _is_transient_upload_error(err: Exception) -> bool:
    """True for retryable transient HF/HTTP upload errors (5xx gateway timeouts,
    429, connection drops) — NOT the persistent storage-quota-403."""
    code = getattr(getattr(err, "response", None), "status_code", None)
    if code in (429, 500, 502, 503, 504):
        return True
    msg = str(err).lower()
    return any(s in msg for s in (
        "504", "502", "503", "500", "gateway time-out", "gateway timeout",
        "timed out", "timeout", "connection", "temporarily unavailable"))

def _retry_upload(fn, *, what: str, max_attempts: int = 6):
    """Call ``fn()`` (a zero-arg upload thunk) with exp-backoff retry on transient
    HF 5xx/429/timeout/connection errors. Storage-quota-403 and any non-transient
    error re-raise IMMEDIATELY (so the caller's overflow-routing / soft-fail logic
    fires unchanged); after max_attempts the final exception propagates (fail-loud)."""
    for attempt in range(1, max_attempts + 1):
        try:
            return fn()
        except Exception as e:
            if _is_storage_quota_403(e) or not _is_transient_upload_error(e) or attempt == max_attempts:
                raise
            sleep_s = min(180, 10 * 2 ** (attempt - 1))
            logger.warning("%s transient error (attempt %d/%d): %s; retrying in %ds",
                           what, attempt, max_attempts, str(e)[:200], sleep_s)
            time.sleep(sleep_s)
```
**Helper shape = callable thunk, NOT a decorator, NOT `**kwargs`-on-`upload_folder`** (the issue658 form was hardcoded to `upload_folder`; here we have a `upload_file` branch + an overflow-pointer `upload_file` too). A thunk-taking helper wraps any of the three call shapes with one signature and keeps each call site's kwargs explicit + readable. Justification: a decorator would force per-call-site wrapping of the bound method; the thunk is the smallest change that covers folder AND file uploads uniformly.

### 4.2 Wrap the three call sites (the ONLY `upload_folder`/`upload_file` API calls in hub.py)
Each wraps the SAME single call — no loop, #664-safe:
- **`_upload` file branch (line 581):** `api.upload_file(path_or_fileobj=..., repo_id=..., path_in_repo=..., repo_type=...)` → `_retry_upload(lambda: api.upload_file(...), what="upload_file")`. Stays INSIDE the existing `try` (line 579) so final-exhaustion still hits the `except Exception` at line 629 → log + return `""` (unchanged soft-fail contract).
- **`_upload` folder branch (line 588):** `api.upload_folder(folder_path=..., repo_id=..., path_in_repo=..., repo_type=..., ignore_patterns=...)` → `_retry_upload(lambda: api.upload_folder(...), what="upload_folder")`. Same enclosing try.
- **`_upload_folder_filtered` (line 719):** `api.upload_folder(...allow_patterns..., ignore_patterns...)` → `_retry_upload(lambda: api.upload_folder(...), what="upload_folder (filtered)")`. Stays inside the existing `try` (line 718) → `except Exception` at line 753 → log + return `""` (unchanged).
- **`_write_overflow_pointer` `upload_file` (line 439):** wrap → `_retry_upload(lambda: api.upload_file(...), what="overflow-pointer upload_file")`. Already inside a fail-soft try (line 422); the retry just makes the small JSON pointer commit resilient too. (Low-value but no-cost; include for uniformity.)

The `verify-via-list_repo_files` step in `_upload` / `_upload_folder_filtered` stays OUTSIDE `_retry_upload` (verification is not the transient-prone op; leave it as-is).

## 5. Risks
| Risk | Mitigation |
|---|---|
| Silent swallowing — too-broad catch hides real bugs | Tight filter: only `_is_transient_upload_error` retries; everything else re-raises on attempt 1. Final exhaustion re-raises the real exception (caller's `except` then logs the full error). |
| Quota-403 misclassification — a non-storage 403 (auth/gated-repo) wrongly retried | `_is_storage_quota_403` requires BOTH `"403"` and `"storage"` in the message → routes only the public-storage quota to immediate re-raise. A non-storage 403 has `.response.status_code == 403` ∉ the transient code set AND no transient substring → `_is_transient_upload_error` returns False → re-raises on attempt 1 (correct; auth/gated 403 must not retry-loop). **Hardening note (optional, flag in report):** upload-policy.md says the quota gate fires only on the LFS endpoint (`/info/lfs/objects/batch`); a future tightening could add that substring, but PARITY with the proven issue658 predicate is the safer default for this task — do NOT diverge without evidence. |
| Retry storm under sustained outage | Bounded: `max_attempts=6`, `sleep=min(180, 10*2**(attempt-1))` → delays 10/20/40/80/160/(cap 180)s, max total wait ~7.5 min, then fail-loud. |
| Test mocking inaccuracy — mock raises a bare `requests.HTTPError` not the real `HfHubHTTPError` | Tests raise `huggingface_hub.utils.HfHubHTTPError(msg, response=<Mock status_code=504>)` so `.response.status_code` branch is exercised exactly as production; one test also raises a bare `requests.exceptions.ConnectionError("connection reset")` (`.response is None`) to cover the message-substring arm. |

## 5b. Kill criteria
Conditions under which we abandon the retry-wrapper approach and revert the change:
- The retry wrapper introduces a measurable regression in the happy-path latency of `hub.py` uploads (>~10% slowdown on a no-error upload) — revert and look for a leaner approach.
- The retry wrapper causes any existing `tests/test_hub.py` test to fail in a way that can't be fixed by mocking adjustments — the wrapper's exception-filter logic is wrong; revert and re-design.
- A non-transient 403 (auth / gated-repo, NOT storage-quota) gets misclassified as transient and silently retried — the `_is_storage_quota_403` + `_is_transient_upload_error` predicates have a fundamental gap; revert and tighten the filter.

## 11. Decision Rationale (load-bearing params)
- **What:** `max_attempts=6`. **Why:** caps retries on the Goal's transient 504s without an unbounded storm; matches the proven one-off so behavior is identical to the in-production issue658 path. **Source:** issue658 commit `62bb233cd0`. **Alternatives:** 3 (rejected — issue658 chose 6 against the same `/commit` 504 under load); tenacity default (rejected — no dep, and parity with the proven value beats a library default per the Goal).
- **What:** backoff `sleep = min(180, 10 * 2**(attempt-1))` (10/20/40/80/160/180s, ~7.5 min total). **Why:** exp-backoff lets a brief gateway timeout clear while the 180s cap bounds the worst case; identical to the proven one-off. **Source:** issue658 commit `62bb233cd0`. **Alternatives:** fixed delay (rejected — no backoff under sustained load); jitter (rejected — issue658 omits it and single-process serial uploads don't thundering-herd; not worth diverging).
- **What:** transient-code set `(429, 500, 502, 503, 504)` + message substrings. **Why:** exactly the retryable HF transient classes the Goal names; the substring arm catches connection/timeout errors whose `.response` is None. **Source:** issue658 `_is_transient_upload_error`. **Alternatives:** retry-all-5xx-by-code-only (rejected — misses bare ConnectionError); retry everything (rejected — would retry auth 401/403 and `ValueError`).
- **What:** quota-403 predicate `"403" in msg and "storage" in msg.lower()`. **Why:** routes only the persistent public-storage quota to immediate re-raise so #564 overflow-routing fires; parity with the proven path. **Source:** issue658 `_is_storage_quota_403` + upload-policy.md § HF storage-quota 403. **Alternatives:** add the LFS-endpoint substring (deferred — hardening note in §5, parity preferred for this task).
