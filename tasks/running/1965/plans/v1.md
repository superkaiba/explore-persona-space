## Method delta / Design rationale

The current ladder prices one VM relaunch as cheap relative to a pod pivot.
For the GENERAL phase class that is right: a CPU-bound fit exploits the VM's
cores, pod bootstrap costs real minutes, and the storm may have passed by
relaunch time. For the API-bound judge class the calculus inverts DURING an
attributed storm:

- The driver is python (+300 earlyoom `--prefer` bonus), so `choom=-600`
  still leaves it the preferred victim relative to every non-python neighbor
  minus ~100 points, and merely co-equal with other protected python work —
  SKILL.md's own text: choom "re-orders earlyoom's victim selection; it does
  not exempt the phase".
- An attributed fleet-wide storm persists for hours (#1900: MemAvailable
  9.85%, swap 0, fleet-wide), so P(re-kill | relaunch-into-storm) is high.
- The class's work is pure API-bound waiting: zero benefit from VM residency,
  trivially pod-portable (repo + `.env` + `ANTHROPIC_API_KEY`; `cpu-mid` at
  ~$0.10-0.30/hr).
- DISPATCH-TIME policy already PREFERS a cheap CPU pod over the shared VM for
  non-trivial CPU-only work (#747, CLAUDE.md § "CPU-only phases don't hold GPU
  pods"). A first protected kill during an attributed storm is decisive
  evidence the VM placement was wrong for this instance — the recovery path
  should CORRECT the placement (align with the dispatch-time preference), not
  retry it. This change makes the recovery ladder consistent with the
  dispatch-time routing preference for exactly this class.

Alternatives considered:

- **No change (deflect).** Rejected: #1900 demonstrated the exposure
  concretely (a choom-protected driver killed mid-storm; hours of wall
  re-exposed under the current ladder), and the ladder's own text concedes
  choom does not exempt the phase.
- **Wait-out-the-storm option** (delay the relaunch until the watcher
  pressure row clears). Rejected: adds an unbounded wait state to a ladder
  whose design rule is "no step may wait indefinitely"; the pod pivot is
  bounded and productive.
- **First-kill pivot for ALL phase classes.** Rejected: for CPU-bound fits
  the relaunch is often correct (the storm may be over; bootstrap cost is
  non-trivial relative to a checkpointed relaunch), and the second-kill
  ladder is a deliberate design there. The carve-out is deliberately narrow
  (three conjunctive conditions) so no other class's ladder changes.
