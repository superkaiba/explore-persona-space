#### 4.1 Pack format (design decision)

Per-prefix **POSIX tar shards** (uncompressed; target ~2 GiB/shard) + **sidecar index**:

```
<prefix>/__packed__/shard-00000.tar      # members named by original repo-relative path
<prefix>/__packed__/shard-00001.tar
<prefix>/__packed__/index.json           # {orig_path: {shard, offset, size, sha256}}
<prefix>/__packed__/manifest.json        # {n_members, total_bytes, shard_sha256s, src_revision, snapshot_ts}
```

Why tar, not JSONL/Parquet: heterogeneous member types (JSON cells, possibly npz/png — census in the sizing pass); tar is lossless and byte-exact for ANY member, keeps original paths as member names (reader updates and the conditional accessor become mechanical), and gives one verify path (whole-file hash) for all 8 prefixes. JSONL changes reader semantics and cannot hold binary members; Parquet needs schema homogeneity. Uncompressed: members may be incompressible, and byte-offset access into an uncompressed tar is O(1); `*.tar` is not `*.gz` (no LFS-gzip concern — shards are LFS by size anyway, which is exactly what enables the remote sha256 verify).

Collision guard: the sizing pass asserts no existing repo path starts with `<prefix>/__packed__/` (fail-loud).

In **chunked mode** (§4.5) shards and per-chunk indexes are named `shard-c<chunk>-NNNNN.tar` / `index-c<chunk>.json`, with a final merged `index.json` + `manifest.json` written after the last chunk.

#### 4.5 Phase 3 — venue + shard/chunk plan + cap arithmetic (local)

- **Shard plan:** `n_shards(prefix) = ceil(total_bytes / 2 GiB)`; pack-file add `k(prefix) = n_shards + 2` (index + manifest), or in chunked mode `k = Σ per-chunk shards + n_chunks index files + index.json + manifest.json` (still ≤ ~a few dozen).
- **Staged-footprint definition (used consistently everywhere):** `staged_footprint(prefix) = 2 × prefix_bytes` (downloaded originals under `STAGE/src_<prefix>/` + tar copies under `STAGE/up_<prefix>/` coexist until the prefix completes).
- **VM predicate + chunked fallback (the DEFAULT response to a big prefix):** if `staged_footprint ≤ 50 GB` (VM_ANALYSIS_FOOTPRINT_GB_MAX) → whole-prefix mode VM-side. If `staged_footprint > 50 GB` → **subdirectory-chunked mode VM-side**: partition the prefix's file list by subdirectory (fallback: lexicographic path ranges) into chunks with per-chunk `staged_footprint ≤ ~40 GB`; each chunk runs the FULL §4.6 chain (download → identity-verify → pack → local verify → upload → Hub verify → identity-keyed delete of THAT chunk's originals → chunk staging rmtree) before the next chunk starts. Chunking bounds VM-side peak disk regardless of prefix size, which makes the pod branch unnecessary in expectation.
- **Pod branch (demoted to NAMED CONTINGENCY, corrected sizing):** only if `/mnt/eps-data` headroom fails the 1.5× assert even for a single chunk. Sizing formula: `container_disk ≥ 1.5 × staged_footprint = 1.5 × 2 × prefix_bytes` (v1's `1.5 × prefix` was wrong — it ignored the src/up coexistence); the 240 GB `cpu-bigmem` cap therefore admits only prefixes ≤ ~80 GB — beyond that, chunked mode is the ONLY path. Pod-side gate coverage: G-mover/G-writer/G-1739 are VM-local probes a pod cannot run, so if this contingency ever fires, the VM orchestrator runs ALL gates immediately before dispatching each pod Hub phase and pod phases are kept short-lived per dispatch (one chunk per dispatch); the pod reads ONLY from HF and writes ONLY to HF (no cross-machine file reads) — hence no `off_pod_phases` block is required; stated per the §9 rule.
- **Cap arithmetic (honest form):** `upload_large_folder` commits INTERNALLY in multiple batches and exposes no per-commit hook — so there is deliberately NO claim of a per-commit assert. Instead the cap gate runs BEFORE each `upload_large_folder` call, against the FULL `+k` of that prefix/chunk (the worst case any internal commit could reach, so the pre-call assert is sound): fresh scoped full-repo count (the §4.4.2 method, re-read live immediately before each upload — never trusting running arithmetic alone) + `k ≤ 1,000,000 − 1,000` (1,000-slot buffer for concurrent fleet writers). `tracked_count` bookkeeping is kept as a cross-check and updated from realized re-list deltas, but the binding input to the gate is the fresh count. Anchored on absolute post-commit totals (the #2304 marker's methodological caution: net-delta reasoning is off-by-one-prone). Delete-first ordering is FORBIDDEN by verify-before-delete and unnecessary: residue-move slack (≥ ~60k slots) dwarfs the transient `+k ≤ ~30`, and each completed prefix frees tens of thousands more. Order: upload `+k`, verify, then delete `−N`, serially, smallest prefix first.

#### 4.6 Phases 4–6 — the per-prefix repack loop (production entrypoint; pilot = smallest prefix)

Per prefix (or per chunk in chunked mode), `scripts/issue2332_repack_prefixes.py run --prefix <p>` executes, checkpointing `state.json` after every step. **Gate policy (per-step, not per-prefix): G-mover AND the G-writer four-way check are re-run before step 3 (download), before step 6 (upload), and before EACH step-9 delete batch** — both are cheap local/API probes beside the per-batch re-list they ride with. Named residual (accepted, stated): per-step gating shrinks the exposure to a single step's window — a mover/writer relaunched INSIDE one step's window is not detected by the gates; the identity-keyed delete eligibility (step 8) and the `parent_commit` CAS (step 9) are the backstops that make even that window non-destructive. No lease machinery — a serial single-runner does not need it.

1. **Gates (prefix entry):** G-mover; **G-writer** — owning issue status from `tasks/REGISTRY.json` (all 8 at `awaiting_promotion`, re-verified at plan time), `spawn_session.py list` shows no live session on the owning issue (EXCEPTION #1739 → G-1739), `pod.py list-ephemeral` shows no pod for the owning issue, and no `epm:run-launched`/`epm:followup-scope`/`epm:free-analysis-followup-run` marker on the owning issue newer than its latest done-transition. Any trip → skip prefix, record, continue.
2. **Revision-pinned identity snapshot:** read HEAD (`api.repo_info(SRC, repo_type="dataset").sha` → `src_revision`, recorded in state + manifest); scoped recursive `list_repo_tree(..., revision=src_revision)` → `src_map = {path: {size, oid}}` where `oid = lfs.sha256 if entry.lfs else blob_id` (branch on the tree entry's ACTUAL `lfs` attribute, never on filename or size). Snapshot ts recorded.
3. **Download** (gates re-run first) to `STAGE/src_<prefix>/...`, pinned to `revision=src_revision`: 4 workers, 6 attempts, exponential backoff to 60 s, per-path failure text recorded (mover's `fetch_all` adapted). Any failure → prefix marked incomplete, staging PRESERVED, source untouched, continue to next prefix.
4. **Staged identity verify (closes the source→staged hop):** every `src_map` path present locally with matching size AND matching content identity — LFS entries: local sha256 == `lfs.sha256`; non-LFS entries: local git-blob sha1 (`sha1(b"blob %d\x00" % len + content)`) == `blob_id`, contingent on A7 (pilot verifies the blob_id semantics once; if `blob_id` is NOT git-sha1 on this xet-enabled repo, the non-LFS fallback is size + `hf_hub_download`'s own etag check, recorded as a stated downgrade in the run log — LFS sha256 checks are unaffected). Fail → prefix incomplete, never pack.
5. **Pack** into `STAGE/up_<prefix>/<prefix>/__packed__/` — an **ISOLATED per-prefix upload root** (mirrors repo layout below `STAGE/up_<prefix>/`; a preserved failed prefix's staging can therefore never ride along in a later prefix's upload): stream files into tar shards, record per-member `{shard, offset, size, sha256}`; write `index.json` + `manifest.json` (manifest carries `src_revision`); compute per-shard sha256.
6. **Local pack verify:** re-open each local shard, verify every member's bytes hash matches the staged file's step-4 sha256; member census == `src_map` exactly (names + sizes + identities). Fail → fix or abort prefix.
7. **Upload** (gates re-run first; **+k census assert:** exact file count of `STAGE/up_<prefix>/` after applying the ignore patterns == recorded `k`; **cap assert** per §4.5 with a fresh live count): `api.upload_large_folder(repo_id=SRC, folder_path=STAGE/up_<prefix>, repo_type="dataset", ignore_patterns=[".cache/**","**/tmp_*","**/*.incomplete"], num_workers=4)`. Exceptions logged, NEVER interpreted (transport ≠ outcome).
8. **Hub-side verify (the only success signal):** scoped `list_repo_tree` on `<prefix>/__packed__` → every expected pack file present, size match, and content identity match — branching per entry on its ACTUAL `lfs` attribute: LFS entries (all shards; ALSO `index.json` when big — e.g. the ~25 MB 206k-member index of `issue1481_conpos_grid` will itself be LFS) → `lfs.sha256 == local sha256`; non-LFS entries (small sidecars) → git-blob sha1 vs `blob_id`, with the A7 fallback (re-download + byte-compare; trivial bytes). Remote hash equality is byte-exact proof the Hub holds the verified local tar. **Restart rule:** after ANY crash/restart, a recorded step-8 PASS in `state.json` is NOT sufficient to resume deleting — this verify is cheaply RE-RUN (one scoped `__packed__` re-list + hash compare) before the delete loop resumes.
9. **Identity-keyed batched delete** (gates re-run before EACH batch): fresh scoped re-list of `<prefix>` at HEAD; read `head_sha = repo_info().sha`. Delete set = paths that are (a) in `src_map`, (b) present now, (c) **current oid == snapshot oid** (identity equality, never size — a same-size rewrite has a different oid and is EXCLUDED), (d) not under `__packed__/`. Any present-path whose oid ≠ snapshot oid → flagged `repack-stale`, KEPT as a loose file (its bytes are NOT in the tar; no data loss), logged loudly. Paths present but not in `src_map` (fleet-added since snapshot) → KEPT, logged. Then `create_commit(operations=[CommitOperationDelete(p) for p in batch], parent_commit=head_sha)` — the CAS: a concurrent commit landing after the re-list makes the commit FAIL (412-class), which forces a fresh re-list + re-derive instead of racing (never a blind retry). Batch size 1,000 in the pilot, raised to 10,000 after a clean pilot (pilot-gated). On ANY exception (incl. 504): do NOT retry blind — re-list, recompute the identity-keyed delete set (a 504 can mask a landed commit, established), refresh `head_sha`, continue. Loop until the delete set is empty. **`delete_folder` is BANNED in this script** (it would destroy the pack; the reference mover's line-165 call does not carry over — pinned by test). Final: full scoped re-list asserts the prefix contains ONLY `__packed__/*` plus any logged `repack-stale`/fleet-added keepers.
