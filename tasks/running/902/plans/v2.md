```markdown
one, and exit 137 (= 128+9) alone does not attribute the killer. On the
shared VM a process can be SIGKILLed by at least four sources: the
kernel OOM killer, earlyoom (SIGTERM below 10% MemAvailable, SIGKILL
below 5% — see `.claude/rules/gotchas.md`, earlyoom entry), systemd-oomd,
or a deliberate operator/PM kill. The `infra` ROUTING may still be
correct; what this protocol gates is the DIAGNOSIS CONTENT — before an
`epm:failure` body names OOM as the cause, and before any crash-fix
round is dispatched against a memory hypothesis, verify the kill source:

1. **cgroup `memory.events` `oom_kill` DELTA over the run window.** The
   login-session cgroup scope hosts MANY fleet processes — absolute
   counters (`memory.peak`, a historical `oom_kill` count) do NOT
   attribute to your process. A counter that did not increment across
   the run window RULES OOM OUT.
2. **MemAvailable floor over the run window.** A floor > 20 GB rules OOM
   out (earlyoom's kill floors are ~10%/5% of the 128 GB total).
3. **Kill-line journals at the death timestamp.** `journalctl -u
   earlyoom` / `journalctl -u systemd-oomd` / `dmesg | grep -i oom`. The
   watcher's CPU-guard pass also pre-attributes earlyoom kills as
   `kind=earlyoom-kill` rows (with `attribution_status:`) in
   `.claude/cache/cpu-guard-events.jsonl`
   (`.claude/rules/background-automation.md`).
4. **A deliberate-stop record at/before the death ts.** Check the task's
   events.jsonl for the `deliberate-stop` breadcrumb:
   `grep 'deliberate-stop' "$(uv run python scripts/task.py find <N>)/events.jsonl"`.
   `spawn_session.py stop` auto-posts one for issue-mapped sessions; PM
   manual kills MUST post one BEFORE the kill
   (`.claude/agents/research-pm.md` § Autonomy rules). Also check the
   watcher registries/sidecars under `~/.eps-autonomous/` for
   force-stop records (the watcher force-stop is a separate kill path).

Additionally: sanity-check any back-derived memory arithmetic against
the code's ACTUAL allocation sites before it drives a fix round. #779 r9
diagnosed kernel OOM from shared-scope counters plus a hypothesized
1100-draw materialization that did not exist in the code, and dispatched
a crash-fix round against a nonexistent bug — all three deaths were
deliberate PM-session SIGKILLs (MemAvailable floor 47 GB; the counter
never incremented). **Classifier behavior is UNCHANGED by this
protocol** — it is a diagnosis-verification step layered on top of the
`infra` route, not a routing change.
```

### 4.4 `scripts/spawn_session.py` — mechanical leg (the ONE mechanical enforcement)

Edit A — `cmd_stop` (line 1942), replace with:

```python
def cmd_stop(args: argparse.Namespace) -> None:
    """Stop a Happy session by id.

    For an issue-mapped session, posts a ``deliberate-stop`` breadcrumb
    (structured ``epm:progress`` note) on the owning task BEFORE the stop
    RPC, so a later exit-137 diagnosis can attribute the kill (see
    failure_patterns.md § exit-137 kill-source verification; #779/#902).
    Breadcrumb failure warns loudly but never blocks the stop.
    """
    issue = _load_session_issue_map().get(args.session_id)
    if issue is not None:
        note = (
            f"deliberate-stop pid=n/a target=happy-session:{args.session_id} "
            f"reason={args.reason}"
        )
        try:
            from explore_persona_space.task_workflow import post_event

            post_event(issue, "epm:progress", by="spawn_session-stop", note=note)
            print(f"Posted deliberate-stop breadcrumb on #{issue}")
        except Exception as exc:  # fail-soft side channel: never block the stop
            print(
                f"WARN: deliberate-stop breadcrumb on #{issue} failed: {exc}",
                file=sys.stderr,
            )
    resp = post("/stop-session", {"sessionId": args.session_id})
    if not resp.get("success"):
        sys.exit(f"stop failed: {resp}")
    print(f"Stopped session {args.session_id}")
```

Edit B — parser (line 2179 block):

```python
    p_stop = sub.add_parser("stop", help="stop a Happy session by id")
    p_stop.add_argument("--session-id", required=True)
    p_stop.add_argument(
        "--reason",
        default="operator stop via spawn_session.py stop",
        help="one-line reason recorded in the deliberate-stop breadcrumb",
    )
    p_stop.set_defaults(fn=cmd_stop)
```

Ordering rationale: post BEFORE the RPC (the candidate's "BEFORE the kill") so the record exists even if the stop lands instantly; a note posted for a stop that then fails is harmless (it records intent, and the failure prints).
