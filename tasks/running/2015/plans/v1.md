### D0 — Reproduction FIRST (`scripts/repro_precommit_stash_race.sh`, new)

Deterministic, self-asserting, scratch-only. Runs in `"$(mktemp -d /tmp/stash-race-repro.XXXXXX)"`; the script hard-asserts at top that its work dir is NOT inside a git work tree belonging to the shared root (`git -C "$SCRATCH" rev-parse --show-toplevel` equals the scratch path after init) and never touches `$REPO_ROOT`. Footprint <1 MB text; wall ~30-60 s.

Setup: `git init` scratch; write `a.txt`/`b.txt`/`c.txt`; minimal `.pre-commit-config.yaml` with ONE local hook (`entry: bash -c 'sleep 3'`, `language: system`, `always_run: true`, `pass_filenames: false`) — the sleep IS the hook window, made deterministic; `pre-commit install` (binary verified on PATH at `/home/thomasjiralerspong/.local/bin/pre-commit`); base commit. `HOME` is NOT overridden (patch files land in the real `~/.cache/pre-commit/` — the script records the pre-run `patch*` set and asserts on the DELTA, so concurrent real commits can't confuse it; alternatively `XDG_CACHE_HOME=$SCRATCH/cache` isolates fully — implementer's choice, isolation preferred).

| Scenario (plain-English name) | Choreography | Assertion (equality/presence, not counts) |
|---|---|---|
| Transient reversion | unstaged edit to `a.txt`; stage an edit to `b.txt`; `git commit` in background; poll `a.txt` during the 3 s hook window | mid-window content == HEAD content (reverted); post-commit content == the unstaged edit (restored); a new `patch*` file appeared |
| Permanent loss (double-checkout rollback) | same, but 1 s into the window overwrite `a.txt` with a THIRD content conflicting with the stashed hunk | post-commit `a.txt` == the ORIGINAL unstaged edit (stale snapshot); the mid-window third content is GONE; commit stderr contains `Rolling back fixes` |
| Deletion resurrection | unstaged `rm c.txt`; concurrent commit of `b.txt` edit | mid-window `c.txt` EXISTS with HEAD content; post-commit `c.txt` absent again |
| Clean-tree disarm (the fix's mechanism) | commit `a.txt`'s edit first (tree clean); background commit of `b.txt` edit; 1 s in, write a new edit to `a.txt` | NO new `patch*` file; mid-window write SURVIVES the commit verbatim |

Embedded-shell exit-path trace: the script runs `set -euo pipefail`; every scenario assertion is a named `assert_eq`/`assert_exists` function that `echo "FAIL: <name>" >&2; exit 1` — no bare `false` inside subshell branches; the background `git commit` is waited on by captured PID (`wait "$COMMIT_PID"`) so a hung hook cannot orphan the run; a nonzero `git commit` rc is EXPECTED only in no scenario (all commits should succeed — pre-commit restores and exits 0 even on the rollback path; the script asserts commit rc==0 per scenario so a semantics change on upgrade fails loud). `trap 'rm -rf "$SCRATCH"' EXIT` cleans up on every path.

The script is run at implementation time BEFORE the other edits land; its full output is committed as `tasks/<status>/2015/artifacts/repro_output.txt` and quoted in the completion note (before/after evidence per the task brief).

### D1 — CLAUDE.md § Concurrent repo-root committers (line ~232), append to the existing paragraph block

Compact insert (~6 sentences; exact wording deviation-allowed, pinned tokens must survive — see A2):

> **Uncommitted TRACKED state at the shared root is unsafe under concurrency (#2015).** Every fleet commit's pre-commit stash cycle snapshots ALL unstaged tracked changes repo-wide, runs `git checkout -- .` (reverting them to index content for the hook window, seconds to minutes), and restores after; a write landing inside another session's window is PERMANENTLY lost when the restore conflicts (pre-commit rolls the whole tree back a second time and re-applies only its stale snapshot), and unstaged deletions are transiently resurrected. Untracked NEW files are invisible to the mechanism and safe. Therefore: never leave tracked files modified/deleted-but-uncommitted at the root beyond the current turn — write→`git add`→commit in ONE short window; generate artifacts off-root (worktree / `/mnt/eps-data` staging) and copy in immediately before the add; stage deletions the moment you make them. **Landing verification under concurrency:** a FAILED commit (rc≠0, "modified files") can coincide with a SUCCEEDING push of ANOTHER session's SHA — verify by reading the blob at the specific SHA (`git show <sha>:<path>` against `origin/main`), never by the push line. **Diagnostic tell** (this race vs a live writer): content converges back to HEAD within seconds and `~/.cache/pre-commit/patch<epoch>-<pid>` files bracket the window; a live writer leaves a monotonically growing file set + a live pid. Full mechanics + reproduction: `.claude/rules/repo-root-uncommitted-state.md`.
