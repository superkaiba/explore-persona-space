## 2. Decision + rejected alternatives

**Chosen direction — hybrid: corridor-max instance fix across BOTH ratchets
(all ten grandfathered files) + two narrowly-scoped class improvements that
make the trip-wire cheap and self-attributed (remedy-bearing FAIL messages on
both arms; edit-time warn-only hook on the skill side).** The instance fix
buys the mechanical maximum breathing room everywhere the same trip-wire is
armed (~2.7 KB per file ≈ one fleet-day on issue/SKILL.md at the measured
burst rate; the 7-raise ladder averages ~2–4 KB/day steady; the agent specs
grow slower but two of them are within one edit of tripping today). The class
improvements change what the NEXT trip costs: today a skill-side trip costs a
full implementation round + a ~13–30-min Step 9c gate + chronicle archaeology
to learn the remedy, and an agent-side trip blocks the editor's own commit
with a message that names only the anti-protocol remedy ("trim it back");
after this change each trip costs a few seconds at edit time (hook, skill
side), a mechanically-copyable line at pre-commit (message, agent side), or
one line copied from the gate FAIL itself. Neither class improvement touches
the ratchets' FAIL/WARN *conditions* — only messages and an advisory side
channel — which is what keeps the blast radius defensible on the fleet's
shared gate.

Channel symmetry, made explicit: the agent side already HAS an edit-adjacent
early channel (pre-commit `--check-agent-spec-size`), so it needs headroom +
a remedy message, not a hook; the skill side has NO pre-commit hook
(clarifier-verified), so the warn-only hook is what moves its discovery
point. This is why the hook is scoped to skills only.

**Rejected — slim `.claude/skills/issue/SKILL.md` (body option 1).** Slimming
can buy at most 3,000 − 813 = 2,187 B of additional margin before the
loose-cap arm forces a ratchet-down (clarifier correction 1) — under one day
at the measured growth rate — while carrying the largest risk surface of any
option: relocations must preserve always-on summaries + pointers, region-
anchored lint pins on SKILL.md text can break when text moves (e.g.
`--check-smoke-blind-spot-review-lens`; `tests/test_step10d_guard3.py:1560`
pins the literal "Size-ratchet cap bumps are computed from landing bytes
(#1753)" in a SKILL.md region), review load on the repo's most load-bearing
skill is maximal, and the branch dirties the `workflow` family so the Step 5a
spec sync skips it. Worst margin-per-risk ratio on the table; and it does
nothing for the class.

**Rejected — cap raise alone (body option 2 as the whole fix).** Necessary
(and included) but insufficient: with a ≤3,000 B corridor and measured growth
of 3,219 B in one 5-hour window on the founding file, the raise alone
re-creates today's state within roughly a day there, and the next session to
trip any cap pays the same late-discovery (skill) or anti-protocol-message
(agent) cost. The skill-cap ladder has been raised seven times in-lineage
(950_300 → … → 983_400) without changing that cost; an eighth raise with no
class change is the definition of the treadmill.

**Rejected — migrate `SKILL_DOC_SIZE_GRANDFATHER` to a line-mergeable data
file (the #1718 `agent_spec_size_caps.txt` mirror).** Priced and rejected on
three grounds. (i) The #1718 win was that concurrent sessions raising caps on
DIFFERENT agent files edit different lines; skill-doc cap churn is
overwhelmingly a SINGLE key — all seven chronicle raises are
`"issue/SKILL.md"` — and two sessions raising the same key conflict on the
same line in a data file exactly as in the module. (ii) The migration REQUIRES
declaring the new import-time data file in the Step 5a SPECS/FAMILY_OF lists
inside `.claude/skills/issue/SKILL.md` (workflow_lint.py L14635-14637: "any
NEW import-time data file added to this module must be declared there too, or
worktree syncs strand it (#2293)"; the declarations live at SKILL.md L2529,
L2538, L13512, L13517) — i.e. it spends bytes of exactly the file whose
headroom is the problem, or forces a riskier pathspec-widening rewrite of
load-bearing sync lines. (iii) The one #1718 benefit that does transfer —
chronicle-out-of-module, history in git log — is captured far more cheaply by
the in-place chronicle trim in §3. Revisit trigger: if the grandfather set
grows or cap churn spreads across many skill files, the migration becomes
worth its cost; the #1718 contract (module attribute keeps its name +
`dict[str, int]` type) makes it a drop-in later. NOTE this rejection is
skill-side only: on the AGENT side the data file already exists, so the
corridor-max re-cap there is six one-line edits in the file built for exactly
that ("Raising a cap edits ONE line here — that is the point of the split",
the file's own header) — none of the three grounds applies, which is why
Must-Fix 1 is strictly cheaper than the skill-side work already planned.

**Rejected — last-toucher attribution of the size FAIL (body option 3 as
stated).** The clarifier falsified its premise: the cross-session collateral
is already mostly absorbed (Step 9c known-red stripping is node-level; the
no-flags run is not a pre-commit hook), so the harm attribution would fix —
"every other session goes red" — is not the harm that exists. The dominant
harm is the tripping session's own late discovery, and attribution machinery
(git-blame semantics inside a lint that must stay hermetic and fast) is a
large, fragile change that buys nothing against that. The hook + message fix
deliver self-attribution at strictly lower cost.

**Rejected — pre-commit parity for the skill-doc check (add
`--check-skill-doc-size` as a pre-commit hook, mirroring the agent-spec
one).** It would move skill-side discovery to commit time, but as a BLOCKING
channel: under the moving-main class a session can exceed the cap on bytes it
never added (a sibling's growth arriving via merge), and a commit-blocker
that fires on un-owned bytes is collateral, not attribution. The warn-only
hook delivers the same earliness without the block. Recorded here because
Should-Fix review asked what would carry the class if the hook were dropped:
this rejected channel is the only known alternative, and its rejection is
deliberate.

**Explicitly out of scope (named follow-up candidates, not landed here):**
extending the edit-time hook to `.claude/agents/*.md` (weaker case than v1
stated: agent specs already get edit-adjacent surfacing at pre-commit, so a
hook there adds a second channel, not a first — file as a follow-up only if
the pre-commit message proves insufficient after Should-Fix 1); any change to
the WARN/FAIL/headroom constants of either ratchet (pinned at 28_000/40_000/
3_000 agent-side and 40_000/60_000/3_000 skill-side by
`test_grandfather_headroom_bound_is_3000` and
`test_threshold_literals_pinned`; changing corridor width is a policy
decision this task does not need).

## 5. Blast-radius analysis

The no-flags run is the Step 9c gate for every session, and the agent-spec
check additionally runs at pre-commit; the two failure directions and what
bounds each:

- **False FAIL (fleet wedge).** The ten cap raises can only convert
  FAIL→WARN — a raise within the hygiene corridor cannot create a new FAIL on
  any tree where the file is at or below the new cap; the only FAIL a raise
  can create is a loose-cap FAIL on a tree whose file is >2.8 KB SMALLER than
  our Step 10d measurement — impossible on the merged tree we measure (we
  assert it in-round via both live-tree headroom tests), and possible later
  only via a large net trim, which is the trimming session's designed
  ratchet-down duty, self-attributed in its own gate (and in its own
  pre-commit, agent side). Edits 3a/3b touch only f-strings inside
  already-failing branches: a defect there surfaces as a wrong MESSAGE on an
  already-red condition, caught by the two new substring tests in our own
  gate. Edit 1b/1c desync FAILs loudly in our own round
  (`test_agent_spec_caps_load_snapshot`). The hook is structurally incapable
  of wedging anything: PostToolUse cannot block the already-run tool; every
  error path exits 0; the kill switch disables it per-session; worst
  realistic cost is ~2 s latency + one stderr paragraph on skill-doc edits.
  The riskiest single edit is `.claude/settings.json` (a malformed JSON
  degrades ALL hooks fleet-wide): mitigated by JSON round-trip editing, an
  in-round parse assert, and the registration pin test (now including the
  resolved-path assertion).
- **False PASS (silently retired ratchet).** No FAIL/WARN condition,
  constant, or threshold changes on either arm; the caps stay within the

  live-tree headroom tests (`test_live_grandfather_caps_have_sane_headroom`

  The ratchets cannot be retired by this change set without those going red

- **Same-round detectability.** Everything lands and is verified in ONE
  branch round: the live-tree tests + no-flags run + agent pre-commit hook

  Step 9c runs the union on the merged tree before the merge lands. The only

  advisory-only (§3 Edit 4 residual (ii)).

## 9. Ordering / concurrency

`.claude/skills/issue/SKILL.md` and the agent specs are edited by many
concurrent sessions; `scripts/workflow_lint.py`'s grandfather region is
edited by every concurrent skill-cap raiser, and the agent caps file by every
agent-cap raiser (line-mergeable by design). Survival design:

1. **One branch, one commit-set, standard /issue worktree flow.** All ten
   files land together; every cap value is recomputed at Step 10d against the
   merged tree (formula, not judgment) — BOTH ratchets — and re-recomputed on
   EVERY merge attempt if the gate round is re-entered — the chronicle's own
   "re-measure per merge attempt" lesson (L15198-15204) adopted as a step,
   not a hope. The agent-side `_MIGRATION_SNAPSHOT` is re-synced in the same
   motion whenever Edit 1b values move.
2. **Sibling lands SKILL.md / agent-spec growth mid-round:** absorbed
   silently up to ~2.7 KB per file by the corridor-max caps (the plan-time
   values already tolerate +2,713 B on issue/SKILL.md and +2,722 B on
   research-pm.md before recomputation is even needed); beyond that, the
   live-tree headroom tests go red in OUR gate and the formula is re-applied.
   Never a fleet-side red: main stays green under its old caps until our
   merge, and our merge carries caps measured on the merged tree.
3. **Sibling raises the same cap line mid-round (the moving-main class):**
   one-line textual conflict at our Step 10d merge (module line skill-side;
   data-file line agent-side — same resolution either way); resolution rule
   is mechanical — re-apply the formula to the merged tree's measured size
   (our corridor-max result is ≥ any landing-bytes(+1–1.2 KB) sibling value
   for the same or smaller measured size; if the sibling measured LARGER, the
   formula on the merged tree dominates both). Agent-side, the snapshot dict
   conflict resolves by the same rule in lockstep. The Edit-2 chronicle-trim
   conflicts are comment-only and resolved by keeping the trimmed preamble +
   folding the sibling's value into the per-entry one-line comment.
4. **Sibling trims a grandfathered file mid-round:** our cap for it then sits
   up to ~2.8 KB + trim above live size; if that exceeds 3,000 B the loose-cap
   arm reds OUR gate at Step 10d re-measure → formula re-applied (lower).
   Same mechanical loop on both arms.
5. **settings.json concurrency:** hooks edits are rare; the JSON round-trip
   edit is applied at Step 10d on the merged tree if a conflict appears; the
   registration pin test (incl. resolved-path assert) re-verifies after any
   resolution.
6. **No repo-root dirty state:** all edits happen in the issue worktree and
   merge via the standard Step 10d path; nothing in this change set writes to
   the shared root outside a commit window.
7. **Completion note (durable record):** the round's completion `epm:progress`
   note states (a) the ten landed caps + their Step 10d measured bases, and
   (b) that the hook leg is session-restart-gated — the edit-time advisory
   channel phases in over days as fleet sessions recycle, rather than
   activating at merge; until then the remedy-bearing gate/pre-commit
   messages are the active class improvement.
