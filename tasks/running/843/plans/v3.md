## 0.0 TL;DR

- **What I'll change:** Right now, two different automatic helpers can both notice a freshly filed task and each start a worker session for it, because neither can see that the other just did — the "is anyone already on this?" check happens before the new worker has had a chance to write itself down. I'll add a small claim file: whoever wants to start a worker for a task must create the claim first, and creating it is all-or-nothing, so only one starter can ever win.
- **What I expect:** With the claim in place, racing starters produce exactly one worker; the losers print a clear "someone already claimed this" message and stop. If a starter crashes mid-way, the claim expires after 15 minutes so the task is never stuck.
- **What would change my mind:** If duplicate workers still appear after this lands, the duplicates are being started by some path that doesn't go through the one launcher script I'm guarding — that would mean the guard has to live one layer deeper (in the session daemon itself), not in the launcher.

## 1. Goal, requirement, acceptance criteria

**Goal (from task body):** Write an atomic create-or-fail per-issue dispatch lease BEFORE the spawn call returns (file_infra_task self-dispatch AND the watcher sweep respect it); make the per-issue registration fail on collision instead of overwrite; skip sweep dispatch when a dispatch marker newer than ~10 min already exists on the task.

**Requirement:** After this lands, the 2026-07-01 failure shape (two dispatchers racing inside the decision→registration window: #787 ×2 37 s apart, #805 ×3, #806 ×2, #822 ×2 18 s apart, #833 ×3 in 3 min, #800 → two full duplicate pipelines) is structurally impossible for any dispatcher that reaches sessions through `spawn_session.py spawn-issue --auto`, and any duplicate that somehow still reaches registration is auto-stopped instead of silently hiding the first session.

**Acceptance criteria (each pinned by a named test in §Tests):**

1. Two (and N=8) concurrent `spawn-issue --auto` attempts on one issue → exactly one lease winner / one daemon POST; every loser exits **0** with `DISPATCH-LEASE HELD` on stdout (never silent). ADDITIONALLY (round-1, reconciled Statistics Must-Fix): two SEQUENTIAL `--auto` invocations ≤ TTL apart — one SUCCESSFUL spawn, then a second attempt — produce exactly one daemon POST: the lease file still exists after the successful spawn and the second attempt prints `DISPATCH-LEASE HELD` with no POST (test 8b pins the persist-after-success link that tests 8/9 alone do not).
2. A lease older than TTL (default 900 s, env `EPM_DISPATCH_LEASE_TTL_S`) does not block: the next acquire takes it over under the per-issue flock sidecar, and the takeover is single-winner under concurrency (round-1 Methodology Must-Fix: the v2 tombstone-rename takeover admitted a check-fresh→rename TOCTOU double-winner; the flock serializes the whole check-freshness→unlink→O_EXCL-re-create slow path, while the no-file O_EXCL fast path stays lock-free).
3. Leases are per-issue: acquiring for issue A never affects issue B.
4. A pre-existing `issue-<N>.json` naming a **different** session id with `spawned_at` **< 900 s old** makes `_register_autonomous_session` raise `RegistrationCollisionError`; `cmd_spawn_issue` stops the just-spawned duplicate, leaves the first registration byte-identical, prints `REGISTRATION-COLLISION`, best-effort posts an `epm:progress` marker with sentinel `[spawn-session:duplicate-dispatch-suppressed]`, exits 0. 6. `file_infra_task.py` and the watcher drain/sweep loops skip (loud, exit 0 / `continue`) when a fresh lease exists, without spawning the subprocess — and the skip records NO spawn attempt (no backoff consumed).

## 3. Design

### A. M1 — the dispatch lease (`scripts/spawn_session.py`)

New module-level block next to `AUTONOMOUS_REGISTRY_DIR` (L58):

```python
# Per-issue dispatch lease (#843). Atomic create-or-fail claim taken by
# `spawn-issue --auto` BEFORE the daemon POST, so two concurrent dispatchers
# (file_infra_task self-dispatch vs the watcher sweep/drain, the
# program-orchestrator daemon, ad-hoc PM dispatch) can never both spawn a
# session for the same issue inside the decision->registration window.
# (Watcher-vs-watcher overlap is already impossible — main() holds a
# whole-run non-blocking flock on ~/.eps-autonomous/watch.lock — so the
# races this closes are strictly cross-dispatcher.) TTL == the watcher's
# RESPAWN_SPAWN_GRACE_S (15 min): inside that window the crash-recovery pass
# already refuses to respawn a fresh registration, so lease-blocking can
# never postpone a recovery the watcher would have run.
DISPATCH_LEASE_TTL_S = 15 * 60

def _dispatch_lease_ttl_s() -> float:
    """TTL in seconds (env EPM_DISPATCH_LEASE_TTL_S; malformed -> default)."""
    raw = os.environ.get("EPM_DISPATCH_LEASE_TTL_S")
    if not raw:
        return float(DISPATCH_LEASE_TTL_S)
    try:
        return float(raw)
    except ValueError:
        return float(DISPATCH_LEASE_TTL_S)

def dispatch_lease_path(issue: int) -> Path:
    return AUTONOMOUS_REGISTRY_DIR / f"dispatch-lease-{issue}.json"

def read_dispatch_lease(issue: int) -> dict | None:
    """Parsed lease dict, {} for garbled content, None for no file."""

def dispatch_lease_fresh(issue: int, now: float | None = None) -> dict | None:
    """The lease entry iff the file exists AND is fresh (acquired_at within
    TTL; a garbled lease falls back to file mtime — fail toward FRESH, i.e.
    toward NOT dispatching; the TTL bounds the wedge). Else None."""

def acquire_dispatch_lease(issue: int, holder: str, now: float | None = None) -> dict | None:
    """Atomically claim the per-issue dispatch slot. Returns the lease entry
    on success, None when a fresh lease is held (or on any unexpected OSError
    — fail toward not dispatching). Stale-lease takeover is single-winner."""

def release_dispatch_lease(issue: int, token: str) -> None:
    """Best-effort token-verified unlink, taken UNDER the per-issue flock
    sidecar (failure exit paths only — POST failed / patch-verify died /
    plain-OSError registration failure; NOT the collision branch, which
    deliberately HOLDS the lease — see §3.B)."""
```

`acquire_dispatch_lease` core (the load-bearing atomicity):

```python
entry = {"issue": issue, "holder": holder, "pid": os.getpid(),
         "token": uuid.uuid4().hex, "acquired_at": now}
path = dispatch_lease_path(issue)
try:
    # FAST PATH (lock-free): no lease file -> atomic single-winner create.
    fd = os.open(path, os.O_CREAT | os.O_EXCL | os.O_WRONLY, 0o644)
except FileExistsError:
    # SLOW PATH: a lease file exists. Freshness-check + stale takeover are
    # serialized under a PERMANENT per-issue flock sidecar (round-1
    # Methodology Must-Fix: the v2 check-fresh->rename tombstone protocol
    # admitted a TOCTOU double-winner — a loser's rename could destroy the
    # winner's freshly re-created lease inside the check->rename gap).
    lock_path = path.with_name(f"dispatch-lease-{issue}.lock")
    try:
        lock_fd = os.open(lock_path, os.O_CREAT | os.O_WRONLY, 0o644)
    except OSError:
        return None                      # fail toward not dispatching
    try:
        try:
            fcntl.flock(lock_fd, fcntl.LOCK_EX | fcntl.LOCK_NB)
        except OSError:
            return None                  # another taker mid-takeover: skip this tick
        if dispatch_lease_fresh(issue, now) is not None:
            return None                  # loser: fresh lease held
        path.unlink(missing_ok=True)     # remove the stale lease (under the lock)
        try:
            fd = os.open(path, os.O_CREAT | os.O_EXCL | os.O_WRONLY, 0o644)
        except OSError:
            return None                  # a fast-path creator won post-unlink: loser
    finally:
        os.close(lock_fd)                # releases the flock; sidecar file persists
except OSError:
    return None                          # fail toward not dispatching
with os.fdopen(fd, "w") as f:
    f.write(json.dumps(entry, indent=2))
return entry
```

Why this is race-free: every CREATE of the lease file — fast path and slow path alike — goes through `os.open(O_CREAT|O_EXCL)`, which is atomic on the local ext4 home filesystem, so exactly one of N concurrent creators succeeds at any instant. Every UNLINK of a live lease happens either under the sidecar `fcntl.flock` (the takeover) or via terminal-task GC (a task that is never dispatched again), so no taker can destroy another taker's freshly created lease: two flock holders are impossible, and a fast-path creator racing a takeover simply makes the takeover's inner O_EXCL fail → the taker returns None (single winner preserved). `fcntl.flock` on the local FS is the same primitive `task.py` already relies on (`~/.task-workflow/lock`), and it is the network-FS fallback kill-criterion 1 already names — the sidecar is PERMANENT (never unlinked by acquire/release), so the lock target itself cannot be unlinked-and-recreated under a waiter (the classic flock-on-deleted-file hole). No tombstone exists in this protocol. `release_dispatch_lease` (failure exits only) also takes the sidecar flock before its token-verified unlink, so a late release cannot remove a successor's lease.

Wiring into `cmd_spawn_issue` (insert after the `prompt` computation, ~L941, before `_verify_happy_patch_or_die`):

```python
lease = None
if args.auto:
    lease = acquire_dispatch_lease(issue, holder=f"spawn-issue --auto pid={os.getpid()}")
    if lease is None:
        held = read_dispatch_lease(issue) or {}
        age = time.time() - held.get("acquired_at", 0) if isinstance(held.get("acquired_at"), (int, float)) else -1
        print(
            f"DISPATCH-LEASE HELD issue #{issue}: a dispatch is already in flight "
            f"(holder={held.get('holder', '?')}, pid={held.get('pid', '?')}, age={age:.0f}s, "
            f"ttl={_dispatch_lease_ttl_s():.0f}s); NOT spawning a duplicate. "
            f"Manual override: rm {dispatch_lease_path(issue)}"
        )
        return                                # exit 0 — duplicate suppressed = success
try:
    ... existing patch-verify + POST + print + registration block, unchanged ...
except BaseException:
    if lease is not None:
        release_dispatch_lease(issue, lease["token"])   # failure path: free the slot
    raise
# success: lease is deliberately LEFT in place; it expires by TTL.
```

Semantics decisions (each deliberate):
- **Scope: `args.auto` only.** Manual `spawn-issue` (user at the keyboard) and bespoke `--initial-prompt` spawns are human decisions; the incident class is 100% automated `--auto` races. A manual spawn over a fresh lease prints a one-line WARN (`note: a fresh dispatch lease exists for #N`) but proceeds. `spawn-campaign` untouched (campaign sessions have their own registration + watcher pass; no campaign duplicates in the incident record).
- **Loser exits 0.** Callers treat rc≠0 as spawn-failure (the watcher records a `spawn-failed` attempt; `run_program_orchestrator.sh` could halt a phase). A suppressed duplicate means a session IS driving the issue — that is dispatch success. The loud `DISPATCH-LEASE HELD` first line lands in the filer's `filed + dispatched #N: <first line>` echo and in watcher logs, so it is never silent.
- **No release on success.** Releasing at registration would need strict registration-then-release ordering and reopens a window if ordering ever regresses; leaving it costs nothing (post-registration dedup is carried by the registration checks all dispatchers already do) and blocks re-dispatch for ≤ TTL, which is *under* every legitimate re-dispatch trigger (watcher respawn grace 15 min; drain/sweep backoff 1 h; capacity-retry backoff 1 h). Release happens only on failure exits where NO session is live (POST failed, patch-verify died, plain-OSError registration failure) so the backstop can retry next tick. The REGISTRATION-COLLISION branch is the deliberate exception: it HOLDS the lease (round-1 disambiguation) — a collision means the FIRST session is live and driving, so holding suppresses immediate spawn-then-collision-stop churn for the remainder of the TTL; test 12 asserts the lease still exists after the collision exit.
- **GC:** add `("dispatch-lease-", "")` to `_GC_TARGETS` (watcher L9686) — terminal-status + age-backstop reaping of leftover lease files; reaping a terminal task's lease cannot enable a duplicate (terminal tasks are never dispatched). The prefix also matches the permanent `dispatch-lease-<N>.lock` sidecar — harmless (recreated on demand by the next slow-path acquire); a negative test pins that an ACTIVE task's fresh lease is never reaped.

### B. M2 — registration collision-fail (`scripts/spawn_session.py`)

```python
class RegistrationCollisionError(OSError):
    """issue-<N>.json already names a DIFFERENT session inside the
    collision window — a duplicate dispatch reached registration."""
```

`_register_autonomous_session(...)` gains `*, force: bool = False` and, immediately before `tmp.replace(dest)`:

```python
if not force:
    try:
        existing = json.loads(dest.read_text())
    except (OSError, ValueError):
        existing = {}
    old_sid = existing.get("happy_session_id") if isinstance(existing, dict) else None
    old_ts = existing.get("spawned_at") if isinstance(existing, dict) else None
    if (
        isinstance(old_sid, str) and old_sid and old_sid != session_id
        and isinstance(old_ts, (int, float)) and not isinstance(old_ts, bool)
        # Collision window capped at the 900 s DEFAULT: raising
        # EPM_DISPATCH_LEASE_TTL_S lengthens the LEASE but must never widen
        # this window past RESPAWN_SPAWN_GRACE_S, or a raised TTL would
        # suppress legitimate crash-recovery respawns (round-1 hardening).
        and time.time() - old_ts < min(_dispatch_lease_ttl_s(), float(DISPATCH_LEASE_TTL_S))
    ):
        raise RegistrationCollisionError(
            f"issue-{issue}.json already names session {old_sid} spawned "
            f"{time.time() - old_ts:.0f}s ago (< {_dispatch_lease_ttl_s():.0f}s window); "
            f"refusing to overwrite — duplicate dispatch"
        )
```

- **Predicate is time-window only, deliberately NOT daemon-liveness:** `_live_session_ids()` returns an *empty set* when the daemon is unreachable (spawn_session.py L641-646, verified) — indistinguishable from "old session dead", so a liveness arm would allow overwrite-hides-duplicate exactly during daemon flaps, and would break the stalled-session respawn (which stops the old *live* session, then respawns — the daemon may still briefly list the stopped sid). The time window is deterministic and testable.
- **Window == `min(_dispatch_lease_ttl_s(), DISPATCH_LEASE_TTL_S)` (default 900 s) == watcher `RESPAWN_SPAWN_GRACE_S`:** the `min()` cap means an env-raised lease TTL can never widen the collision window past the respawn grace (test 17's second half pins this). every legitimate non-force overwriter (crash-recovery `_respawn`, stalled respawn, orphan respawn) only fires on entries the watcher already aged past that same 15-min grace, so collisions can only be duplicate-dispatch products. Garbled/missing `spawned_at` → overwrite proceeds (today's behavior; a garbled entry can't prove a fresh session, and failing there would wedge recovery of hand-edited/legacy entries).
- **Caller handling in `cmd_spawn_issue`** (extend the existing L1001-1026 OSError handler): catch `RegistrationCollisionError` *first*; run the same stop-the-just-spawned-session dance (factor L1011-1025 into `_stop_spawned_session(session_id) -> bool`); print `REGISTRATION-COLLISION issue #N: kept <old-sid>, stopped duplicate <new-sid> (<age>s window)`; best-effort post a task marker (below); `return` (exit 0 — the first session is live and driving; plain OSError keeps its current fail-loud `sys.exit`). The collision branch returns WITHOUT releasing the lease (round-1 disambiguation — the winner session is live and driving; holding the lease suppresses immediate spawn-then-collision-stop churn for the rest of the TTL; implement it as an in-handler return BEFORE the BaseException release path, and test 12 asserts the lease persists). The invariant either way: collision ⇒ exactly one live session remains, first registration intact.
- **Collision surfacing (never silent):** stderr line + a best-effort `epm:progress` marker: `uv run python scripts/task.py post-marker <N> epm:progress --note "[spawn-session:duplicate-dispatch-suppressed] duplicate --auto dispatch suppressed: kept <old-sid>, stopped <new-sid>"` (subprocess, `cwd=PROJECT_ROOT`, timeout 60, wrapped in try/except — a marker failure never blocks the exit). `spawn_session.py` is already in `_LOCAL_VM_ONLY_PATHS` (tests/test_no_pod_side_task_py_shellout.py L104 — verified), so this shellout is allowlisted. Define `DUPLICATE_DISPATCH_NOTE_SENTINEL = "[spawn-session:duplicate-dispatch-suppressed]"` in spawn_session; import it in `autonomous_session_watch.py` and add to `_WATCHER_NOTE_SENTINELS` (L894) so the marker never counts as "real progress" for staleness clocks.
- **`register-current`** (`cmd_register_current`, call at ~L1261) passes `force=True` — it is the deliberate re-write path for an already-live session (#472 revival). `_register_manual_session` untouched (different file, user-driven).

## 9. §11 Decision Rationale

`N/A — no training hyperparameters` (kind: infra; no model training). Grounding for the three tunable windows:

- **Lease TTL = 900 s** (`EPM_DISPATCH_LEASE_TTL_S`). Upper coupling: set equal to the watcher's existing `RESPAWN_SPAWN_GRACE_S = 15 * 60` (L463, #759), the window in which crash-recovery already refuses to act on a fresh registration — so the lease can never postpone a recovery the watcher would have run. All observed duplicate gaps (18 s – 3 min) sit ≥ 5× inside it. Pinned by test 17.
- **Registration-collision window = the same 900 s.** Any non-force overwrite of an entry younger than the respawn grace is by construction not a watcher recovery, hence a duplicate. One constant, one env var, one coupling test.
- **Marker-freshness window = 600 s** (`EPM_PROPOSED_INFRA_SWEEP_MARKER_FRESH_S`). Exactly one watcher cadence (cron `3-59/10 * * * *` → 10 min): a dispatch marker younger than one tick means SOME dispatcher fired within the current/previous tick — the cross-dispatcher window (filer / PM / program-orchestrator vs the flock-serialized watcher) that produced #805 ×3 / #833 ×3. Larger would shadow the sweep's own 1 h backoff redundantly; smaller would not cover one full tick.
