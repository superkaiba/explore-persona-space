### 4.2 The new `## Context budget (READ FIRST)` section (proposed text, near-verbatim; implementer may tighten)

```markdown
## Context budget (READ FIRST)

Your spec, the CLAUDE.md import tree (~130 KB), the auto-loaded skills
(paper-plots, independent-reviewer), and your agent memory consume a large
fraction of your window before your first tool call. Analyzer spawns have
died to autocompact thrash at 8-9 tool calls — brief-independent (#763) —
so every read below is mandatory IN CONTENT but budgeted IN FORM:

- **Staged inputs first.** When the orchestrator's brief names pre-staged
  files (a results digest, a held draft at
  /tmp/issue-<N>-interpretation-v1-held.md, a plan path), read THOSE first
  and trust their measurements; do not re-derive what they already state.
- **Never dump the full event log** — a bare `uv run python
  scripts/task.py view <N>` (or `--json` without a filter) is 100s of KB
  on marker-heavy tasks. Body: `uv run python scripts/task.py view <N>
  --json | jq -r '.body'`; markers: `uv run python scripts/task.py
  latest-marker <N>` or a jq-filtered `.events[]` slice. (Bare `task.py`
  is not on PATH and bare `python` does not exist on this VM — every
  invocation is `uv run python scripts/task.py ...`.)
- **SPEC.md (~87 KB) is never read whole.** Grep the section heading, then
  Read only that span in ≤300-line chunks. Same protocol for
  `.claude/rules/analyzer-section-reference.md`: open ONLY the step section
  the pointer names.
- **Size every results file before reading** (`wc -c`). Over ~1 MB
  JSON/JSONL: extract the needed fields with a `uv run python`/`jq`
  one-liner into a compact /tmp digest and Read the digest — never Read the
  raw file. Pull raw-completion rows by grep + line offset; never page
  whole completion files into context (also § Content hygiene).
- **Exemplars are bounded** by Step 1.5's top-N cap; one read each, no
  re-reads.
- **Grep-first on scripts and rules;** open a LESSONS.md-indexed rule only
  when its trigger fires. **Don't re-read what you just wrote** —
  Write/Edit error on failure; Step 5's mechanical gates are the
  verification, not a re-read.

The steps below name WHAT to produce; this section governs HOW to read.
On conflict, this section wins on invocation form.
```
