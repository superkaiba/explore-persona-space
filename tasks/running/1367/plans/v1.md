## 2. Prior work

Standard practice in append-only log implementations (Kafka log recovery, RocksDB/LevelDB WAL, SQLite journals) is to detect a torn tail at open/append time and either truncate it or fence it off before writing new records. Sealing (newline-terminating) rather than truncating preserves the partial's bytes for forensics and composes with this codebase's existing recovery design: `_iter_jsonl` (line 3578) already skips malformed lines and blank lines, so a sealed partial is exactly the shape the reader was built to tolerate. In-repo prior work: the tolerant reader itself (#653 corruption), the `errors="replace"` multibyte-tail fix, and the atomic-append hardening in the same file (comments at lines 3505–3513).

### 4.1 New helper (insert immediately above `_append_jsonl_line`, ~line 3518)

```python
def _tail_missing_newline(path: Path) -> bool:
    """Probe: True iff ``path`` exists, is non-empty, and its final byte is
    not ``b"\\n"`` — the crash-truncated-append signature (#1367 / #1333).

    Reads exactly ONE byte (``os.pread`` at ``st_size - 1``) regardless of
    file size. FAIL-SOFT by design: a fresh-file ``FileNotFoundError``
    returns False silently (O_CREAT will create the file); any other
    ``OSError`` logs a WARNING naming the path and returns False — the
    probe must never block the append itself, whose own error handling
    stays fail-loud.
    """
    try:
        rfd = os.open(path, os.O_RDONLY)
    except FileNotFoundError:
        return False
    except OSError as e:
        _log.warning("tail-check open failed for %s (%s); appending without seal", path, e)
        return False
    try:
        size = os.fstat(rfd).st_size
        if size == 0:
            return False
        return os.pread(rfd, 1, size - 1) != b"\n"
    except OSError as e:
        _log.warning("tail-check read failed for %s (%s); appending without seal", path, e)
        return False
    finally:
        os.close(rfd)
```

### 4.3 Correctness reasoning (the design considerations, addressed)

1. **Seal location — inside the helper.** All 10 call sites (verified by grep: lines 3694, 3933, 4066, 4509, 4691, 5185, 5554, 5624, 5795, 5817) route through `_append_jsonl_line`; one choke point covers events.jsonl, comments.jsonl, concerns.jsonl, and the `~/.task-workflow/` stranded/deferred logs with zero caller changes.
2. **Atomicity interaction — no demotion, by construction.** The seal is a SEPARATE 1-byte write, not a prepend onto `buf`, so every row keeps its existing atomicity class: a ≤PIPE_BUF row stays a single all-or-nothing `os.write`, and the exactly-PIPE_BUF edge case never falls into the completion loop. A SIGKILL between the seal write and the row write leaves a *sealed, well-terminated* file and no new row — strictly better than dying 1 µs earlier (the row's caller died either way; a retry re-posts), and the next append finds a clean tail. A 1-byte write cannot partially short-write (n is 0 or 1; 0 raises).
3. **TOCTOU.** All in-contract callers hold the exclusive `_locked()` flock (docstring line 3540–3541), so no other writer can append between probe and seal. Defense in depth: even for a hypothetical out-of-lock writer, the failure mode degrades to one blank line (their well-terminated row lands, our seal `\n` follows), which `_iter_jsonl` skips via `if not line.strip(): continue` (line 3616) — harmless, never corruption. Stated as assumption A5.
4. **No retro-repair of `tasks/interpreting/1333/events.jsonl` line 152.** Decision: NO. The log is append-only; the file currently ends with `\n` (measured — the retry terminated it), so the merged line is inert; `_iter_jsonl` skips it with a WARNING; task #1333 is live at `interpreting` and hand-editing its events.jsonl races the live session; the swallowed marker content remains recoverable by grep inside the merged line for forensics. The retry that mattered was re-posted (line 153+ carries the live state).
5. **Other O_APPEND jsonl writers (body's scope grep, executed):** in `task_workflow.py` the helper's own `os.open(..., O_APPEND...)` at 3546 is the only append-mode open. `scripts/autonomous_session_watch.py` has ~10+ `open(dest, "a")` sidecar appenders (`.claude/cache/*-events.jsonl` escalation sidecars) — **out of scope with reason:** single periodic cron process (no crash-then-retry concurrent-appender pattern), observability-only consumers, and folding 10+ sites into a shared helper is a distinct change with its own fingerprint. Not silently dropped: listed here; a follow-up candidate may route them through a shared helper if a torn sidecar tail ever bites.

## 11. Decision Rationale

1. **Seal inside `_append_jsonl_line` vs per-caller.** Helper. One choke point covers all 10 call sites and every future caller; per-caller sealing guarantees drift. *Source:* task #1367 body diff sketch + clarifier call-site verification. *Alternative rejected:* events-only seal — the same crash-concatenation class applies to comments/concerns/deferred logs for free.
2. **Fail-soft probe (chosen) vs fail-loud.** The probe is a recovery *enhancement*, not the primary operation: if it errors, proceeding unsealed preserves today's exact behavior, whereas raising would convert a working marker post into a failure — losing the very row the fix exists to protect. This does not violate fail-fast: the failure is logged loudly (WARNING with path + errno), only the *diagnostic read* is absorbed, and the write path keeps every existing raise. A probe error on a local regular file almost certainly precedes a write error that WILL raise. *Alternative rejected:* fail-loud — punishes the innocent new marker for a broken probe.
3. **Separate 1-byte seal write (chosen) vs prepending `b"\n"` to the buffer (candidate sketch).** Prepending pushes an exactly-PIPE_BUF row to PIPE_BUF+1, demoting it from the atomic single-write branch to the non-crash-atomic completion loop; the separate write preserves every row's documented atomicity class, leaves the size-branch logic untouched (smaller diff), and a crash between the two writes leaves a strictly-improved file (sealed, well-terminated). Flock excludes interleaving between them. *Source:* atomicity contract at lines 3505–3513.
4. **Probe mechanism: separate `O_RDONLY` fd + `fstat` + `pread` (chosen) vs single `O_RDWR` append fd vs `open("rb")`+`seek(-1, SEEK_END)`.** Single-fd `O_RDWR` was rejected because an `O_RDWR` open failure would break the primary append path (a behavior change); the two-fd design keeps the append byte-identical under every probe failure. `pread` over `seek` avoids offset mutation and matches the file's existing os-level style; both read exactly 1 byte at any file size.
5. **No retro-repair of the live corrupted line** — §4.3.4 (append-only log; inert; live task; forensically preserved).
6. **Watcher sidecar appenders out of scope** — §4.3.5 (different process model, observability-only, distinct fingerprint).
