#### Step 1 — the shared module (new file `src/explore_persona_space/atomic_io.py`)

Stdlib-only module-level imports (`contextlib`, `json`, `logging`, `os`, `uuid`, `pathlib`) so ~80 lightweight scripts can import it without dragging the ML stack (contrast: `utils.py` top-levels `torch`/`transformers`/`omegaconf` at lines 6-9).

```python
_LOGGER = logging.getLogger(__name__)   # "explore_persona_space.atomic_io"

@contextlib.contextmanager
def atomic_replace(path: Path, *, logger: logging.Logger | None = None) -> Iterator[Path]:
    # Body = hoist of scripts/issue2329_run.py:1404-1438 (_atomic_replace), VERBATIM except
    # exactly ONE mechanical change: the cleanup-warning call logs via (logger or _LOGGER)
    # instead of the caller module's global `logger` — same message, same WARNING level.
    # Docstring updated to name #2329/#2336 provenance. Three load-bearing properties:
    #   1. tmp = path.parent / f"{path.name}.{os.getpid()}.{uuid.uuid4().hex[:8]}.tmp"
    #      (pid alone insufficient — pid reuse; uuid generated PER CALL, never module-scope)
    #   2. temp in the DESTINATION's own directory (cross-filesystem os.replace is not atomic)
    #   3. on BaseException: try tmp.unlink(missing_ok=True) / except OSError -> log via
    #      (logger or _LOGGER), then bare `raise` (cleanup failure never masks the original
    #      exception)
```

The parameter lets `issue2329_run.py` pass its own logger (step 3(e)) — zero edits to another issue's landed test pins.

#### Step 3 — the migration recipe (per occurrence; preserves signatures AND bytes)

For each unsafe line (133 at plan-v2 return; re-derived per batch), the transformation is:

```python
# BEFORE (typical def-wrapped shape; inline occurrences identical minus the def)
def _write_json_atomic(path: Path, obj) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    tmp = path.parent / (path.name + ".tmp")
    tmp.write_text(json.dumps(obj, indent=2))
    os.replace(tmp, path)

# AFTER
def _write_json_atomic(path: Path, obj) -> None:
    with atomic_replace(path) as tmp:
        tmp.write_text(json.dumps(obj, indent=2))   # serialization line kept VERBATIM
```

plus `from explore_persona_space.atomic_io import atomic_replace` added in the same Edit as its first usage (the PostToolUse ruff F401 auto-fix strips an import added before its usage — code-style rule, followed).

Load-bearing recipe rules:

- **The serialization line is NEVER touched.** Local writers vary (`indent=2` vs `default=str` vs `sort_keys` vs `ensure_ascii`); rewriting them to the shared typed wrappers would change output bytes. Only the temp-derivation + `os.replace` + any local cleanup boilerplate are replaced by the contextmanager. Rejected alternative: import-alias rebinding (`from ... import write_json_atomic as _write_json_atomic`) — changes serialization kwargs and breaks local signature variants.
- **Local def names and signatures are preserved** — call sites untouched (the clarifier's instruction; it is what keeps the ~133-line migration mechanical).
- **Edge shapes**, enumerated from the census: (a) writers that `open(tmp, "w")` + `json.dump` — keep the open/dump, swap only the derivation; (b) writers with `fsync` on the tmp — keep it inside the `with` block; a post-replace DIRECTORY fsync moves to after the `with` block (the replace happens at `__exit__`); (c) `np.savez`/`np.save` on a tmp path — MUST convert to the open-handle form (the numpy suffix-append trap, step 1) — these files get an extra line in the batch commit message naming the conversion; (d) the 2 `.sh` files (`scripts/issue779_l26_recovery_dispatch.sh`, `scripts/issue779_n1m_readout_dispatch.sh`) carry the pattern inside embedded-Python heredocs — CONFIRMED this round, not assumed: 3 hit lines (`l26:184,534`, `n1m:299`), each inside a `uv run python - <<'PY'` heredoc (openers `l26:138,464`, `n1m:236`), and both scripts `cd "$REPO_ROOT"` before any heredoc (`l26:35`, `n1m:21`), so the package imports and the same swap applies inside the heredoc. Contingency only (not the expected path): if a future re-read finds a hit that is pure-shell string construction, it takes the waiver comment with the reason recorded; (e) `scripts/issue2329_run.py` (zero hits under all three predicate arms — already safe, NOT in the 85) is rewired in batch 2 under the Supersede rule: the local `_atomic_replace` BODY is deleted and replaced by a two-line delegating def — `def _atomic_replace(path: Path): return atomic_replace(path, logger=logger)` — where `logger` is the module's own `issue2329.run` logger (:95). The `logger=` threading is LOAD-BEARING, not optional: a bare import-alias (`import ... as _atomic_replace`) or a logger-less delegating def would move the cleanup warning onto the shared module's logger and FAIL `test_atomic_replace_cleanup_failure_does_not_mask_original_exception` (its :693 caplog scope + :709 name filter both key on `"issue2329.run"`) — v1's claim that a plain delegating def cures this was WRONG; the parameter is what cures it. All 4 must stay green — checked in that batch (A9). #### Step 5 — the lint check (`scripts/workflow_lint.py --check-shared-tmp-name`)

- **Predicate** (per line, over every `*.py` and `*.sh` under `scripts/` and `src/`; `tests/` deliberately NOT scanned — lint fixtures and the harness-sensitivity control legitimately embed the banned literal). THREE arms; a line is a hit if any arm matches (per-line dedupe across arms):
  - arm A: `re.compile(r"""\.name\s*\+\s*(?P<q>["'])\.tmp(?P=q)""")` — attribute concat: catches `path.parent / (path.name + ".tmp")` AND `x.with_name(x.name + ".tmp")`, both quote styles, whitespace-tolerant. Landing-day yield: 122 lines in 78 files, all inside the concat-grep set.
  - arm B (re-specified in v2): `re.compile(r"""\{[A-Za-z_][A-Za-z0-9_.\[\]:'"()]*\.name\}\.tmp(?![^"']*\{)""")` — the f-string deterministic-name form: `{X.name}.tmp` with NO f-string interpolation between `.tmp` and the string's closing quote. The negative lookahead is the whole design: a temp name that CONTINUES with an interpolation after `.tmp` (the safe `f"{path.name}.tmp.{token}"` claim-writers, token = per-call `uuid.uuid4().hex`) is presumed process-varying and exempt, while a literal-only continuation (`f"{path.name}.tmp"`, `f"{path.name}.tmp.pt"`, `f".{X.name}.tmp"`) is deterministic and flagged. This REPLACES v1's line-scoped `getpid`/`uuid` exemption, which could not see a token derived on another line and false-positived all 4 safe sites. No exemption clause is needed at all: the safe primitive itself (`f"{path.name}.{os.getpid()}.{uuid.uuid4().hex[:8]}.tmp"`) never matches because `.tmp` does not immediately follow `{X.name}`. Landing-day yield: 8 lines in 6 files, zero overlap with arms A/C. Verified at plan time against all 11 regression rows below.
  - arm C (new in v2, the B3 fix): `re.compile(r"""(?<![\w.])name\s*\+\s*(?P<q>["'])\.tmp(?P=q)""")` — the bare-identifier concat form `tmp = cache / (name + ".tmp")`, where `name` is a local variable rather than a `.name` attribute. Catches `scripts/issue1901_boundary_token_control.py:443,726,748`, which arm A and the dot-anchored grep are both structurally blind to. The lookbehind excludes `.name` (arm A's territory — no double counting) and `fname`/`dirname`-style identifiers. Landing-day yield: 3 lines in 1 file.
  - **Predicate regression table (verified at plan time; becomes fixture rows in `tests/test_workflow_lint_shared_tmp.py`):** arm B matches `f"{path.name}.tmp"` / `f"{path.name}.tmp.pt"` / `f".{path.name}.tmp"` / `f".{args.summary_out.name}.tmp"` / `f".{ckpt_path.name}.tmp"` (5 unsafe shapes ✓) and does NOT match `f"{path.name}.tmp.{token}"` or `f"{path.name}.{os.getpid()}.{uuid.uuid4().hex[:8]}.tmp"` (2 safe shapes ✓); arm C matches `(name + ".tmp")` in both issue1901 shapes (✓) and does NOT match `path.name + ".tmp"` (arm A's) or `fname + ".tmp"` (✓). 11/11 at plan-v2 time.
- **Failure line**: `<path>:<lineno>: process-shared atomic-write temp name (use explore_persona_space.atomic_io.atomic_replace; #2336)`.
- **Allowlist**: `SHARED_TMP_LEGACY_ALLOWLIST: tuple[tuple[str, str], ...]` of `(repo-relative path, reason)`. **Seed derivation (batch 0, explicit step — the B2 fix):** implement the check first, run its OWN scanner with an empty allowlist over `scripts/` + `src/` (the check function takes an `allowlist` parameter defaulting to the module constant, so tests, the seed run, and the close-out run can invoke it with `allowlist=()`), and seed the constant from EXACTLY that scan output's file set — never from the plain grep, whose set differs from the check-visible set in both directions (the grep misses the 6 f-string files; a grep-seeded `issue1901` entry would have been instantly stale under v1's arms, and the 4 token-derived safe writers must never enter the allowlist at all). Expected seed today: 85 files (79 concat + 6 f-string) — re-derived live at batch 0, never inherited from this plan. A hit in an allowlisted file passes; an allowlisted file with ZERO hits (or missing) WARNs `stale allowlist entry` (the `SLURM_GPU_WIDTH_GRANDFATHER` idiom) — this is what makes a forgotten shrink visible. Deferred-live entries carry `reason="deferred — live owner #<M> (2026-08-…)"`.
