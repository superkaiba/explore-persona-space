# Plan — #851: promote `judge_graded` + tf-margin to the `eval/` library (Phase 0a)

`kind: infra` — pure code move, no training, no GPU, no behavioral construct.

## 0.0 TL;DR

- **What I'll do:** Move two working helpers out of one-off experiment scripts into the shared library, so the artifact-factory phases that follow can import them instead of copying them. The code is lifted, not rewritten; the old scripts keep working by importing the moved versions.
- **What I expect:** Identical behavior everywhere. Existing tests that exercise the old import paths pass unchanged, and new CPU tests pin the drop-rules and the margin math directly on the library.
- **What would change my mind:** If either helper turns out to secretly depend on its host script's state in a way a clean import can't reproduce, the promotion boundary is wrong and I'd stop and re-scope. (Verified by reading both files in full: no such dependency exists.)

## 0. Plan Summary

- **Change:** two new modules — `src/explore_persona_space/eval/graded_judge.py` (lift of `scripts/issue778_lib.py::judge_graded` + `JudgeResult` + `_score_from_parsed` + rubric helpers, lines 208–399) and `src/explore_persona_space/eval/margin.py` (lift of the computation core of `scripts/issue722_tf_margin_extract.py`: `build_fixed_pairs`, `score_answer_logprobs_batched`, `_assistant_suffix_len`, plus a new `compute_tf_margin` wrapper + `MarginResult` dataclass). Both source scripts are rewired to re-import from the library (supersede→dedupe; no second live copy).
- **Dispatch:** `graded_judge` keeps routing through `eval/batch_judge.py::judge_completions_batch` (→ `judge_dispatch`) via call-time attribute access, so the existing monkeypatch-based test keeps working. No dispatch reimplementation.
- **Decoupling:** `margin.py` replaces the `instance` param (a #594-battery dict) with `messages_fn: Callable[[str], list[dict]]`; the #722 script wraps `partial(messages_for_instance, inst)`.
- **Tests:** 2 new CPU test files (`tests/test_graded_judge.py`, `tests/test_eval_margin.py`, ~15 named tests) + 2 existing test files unchanged as semantic-identity checks (`test_batch_judge_agg_non_dict_parse.py`, `test_issue778_null_battery.py` — the latter calls `lib._score_from_parsed` directly, so it MUST stay green through the re-export).
- **Judge pin:** `DEFAULT_JUDGE_MODEL` (env-overridable Sonnet 4.5) from `eval/__init__.py`; `workflow_lint --check-judge-model-pins` stays green.
- **Compute:** VM-local, CPU-only. `Estimated GPU-hours (total): 0`
- **Risks (top 2):** (1) PostToolUse ruff strips the re-export imports unless `# noqa: F401` is on them; (2) a module-top `from batch_judge import judge_completions_batch` in the new module would bind at import time and break the existing monkeypatch test — the design mandates call-time attribute access instead.
