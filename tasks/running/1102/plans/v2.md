### The `wildchat_random_v1` decision (explicit resolution)

**Keep it benign-classed; ground the classification; kill the generalization.** Ground truth: the bank is built by `scripts/issue617_build_wildchat_slice.py` → `issue594_build_battery._wildchat_eligible` (lines 332–338), which keeps only rows with `language == "English" and toxic is False and redacted is False` — WildChat-1M's own per-conversation moderation flags. So the BANK is dataset-flag-screened and its verbatim treatment has an actual basis. The #1073 corpus, by contrast, was "first 5,000 first-user-turn LMSYS prompts" with NO toxicity filter. The class distinction the fix writes into the rules is therefore **screened vs unscreened**, not WildChat-vs-LMSYS: (a) `wildchat_random_v1` stays in the benign-bank lists WITH the screening basis named inline, so future readers can't generalize from "wildchat_random_v1 is benign" to "WildChat text is benign"; (b) bare "WildChat" comes OFF every blanket benign-CORPORA list (that wording is precisely the misleading text that leaves a first-pass agent treating an LMSYS/WildChat corpus slice as verbatim-safe); (c) the existing "when unsure, sanitize" backstop stays and now explicitly covers dataset moderation flags being imperfect. Cost: none in practice — sanitized ~15-word excerpts remain fully available for worked examples (the v4-required sample blocks), as #1073's promoted, critic-passed body demonstrates.
