# Plan v3 — Issue #812: Pooling operators (mean / max / attn-fixed / attn-learned) vs the unpooled per-position ceiling for predicting behavior expression E0 and reconstructing the answer profile (n=50, 0-GPU)

## 0.0 TL;DR (plain English)

- **What I'll run:** We already store the model's internal activations for every token of the answers it wrote across 50 short conversations (that data is on the HuggingFace hub). The line so far has always crushed those per-token activations down to a single "average answer" vector before predicting anything. Here I test how much that averaging throws away: I compare four simple ways to squash the tokens into one vector (plain average, element-wise max, a random-then-a-learned attention weighting) against the "cheat" option of handing the predictor the individual token activations directly. No training, no new model runs — everything is a cheap arithmetic reduction of activations we already have. For the answer key I need (how much each conversation showed each behavior), I re-use it if a sibling analysis has finished producing it, and otherwise score the already-saved conversation text myself.
- **What I expect:** With only 50 conversations to learn from, the honest bet is that the individual-token option can't clearly beat the plain average — there just isn't enough data to tell them apart, and the fancier options mostly risk overfitting. If anything does help, it's most likely the learned attention weighting, not the raw per-token dump.
- **What would change my mind:** If the individual-token predictor beats the average by a gap that survives a shuffle test AND my "how noisy is the answer key" ceiling says the gap is real (not just fitting noise), that would say averaging genuinely discards behavior-relevant structure — and the follow-up is to generate more conversations so we can measure how big the gap actually is.

## 2. Prior Work

**Internal line.** #722 (awaiting_promotion) established the base-model map `M: c_C → v0(C)` as a strong linear map (held-out skill-over-mean R² 0.74–0.80 mid/late layers) but using ONLY the mean-over-answer-tokens summary `v0`. #742 (blocked) asks how much linear DECODING loses from that pooled mean at n=50 and builds the reliability-ceiling / bracket / learning-curve framework. #810 (planning, parent) sweeps which SINGLE answer-side position/summary is best (`mean`/`last`/`im_end`/`turn_nl`/`maxp`/`attn` + a per-position sweep). #763 (running) supplies the graded 0–100 E0 for 5 low-m behaviors as its in-flight PRIMARY DV — that graded E0 does NOT yet exist on HF. #658 (awaiting_promotion) is the 50-context grid + raw completions + the 48-probe answer spans + r_B.

**How #812 differs.**
- **vs #810 (single-position/summary sweep):** #810 finds the best SINGLE-vector summary; #812 fits the UNPOOLED multi-position input (all `(2K+2)` aligned positions as joint regression features) as the CEILING and measures how far each single-vector pooling operator falls short of it. #810 never fits the joint-position input. The `max`/`attn` overlap is by construction — they are the operators being scored against the ceiling here.
- **vs #742 (decoding-loss):** #742 varies the DECODER class (linear vs nonlinear) on a fixed mean-pool input; #812 varies the INPUT GRANULARITY (pooled vs unpooled) with a fixed linear-ridge decoder. Different manipulated axis; #812 reuses #742's ceiling/learning-curve machinery. The follow-up-critic redundancy screen is anticipated in the body — the distinct axis is the defense.

**External literature (pooling / attention pooling / per-position representations).** The general finding that mean-pooling over token representations discards positional/structural information that attention or per-token readout can recover is well established in the sentence-embedding + probing literature (e.g. attention-pooling vs mean-pooling in sentence encoders; per-token vs pooled probing in Hewitt & Liang 2019, arXiv 1909.03368, the control-task null this plan reuses). The relevant caution for THIS setting is the small-n one: at n=50 the unpooled input has vastly more free parameters than samples, so any apparent "unpooling helps" must survive a shuffle null + a reliability ceiling before it is read as signal (the #742 thesis, grounded in Spearman 1904 attenuation / Schoppe 2016 noise ceiling / Storrs 2020 CV-matched ceiling). Persona Vectors (Chen/Arditi/Sleight/Evans/Lindsey, arXiv 2507.21509) is the read-out regime this line sits in (response-avg activation → behavior prediction); the attn-fixed operator is the #658-style unlearned control.

## 3. Hypothesis + falsification

Three honest possible outcomes (stated as hypotheses, not predictions — this plan runs BEFORE any result):

- **(i) Unpooled > best pool by a resolvable gap.** Δρ (unpooled − mean-pool) CI lower bound > shuffle-null 97.5th pct for ≥1 (behavior × layer), and the gap sits below √(r_yy) (not ceiling-censored) AND survives the matched-PCA control (unpooled > `mean_pca`, not just unpooled > `mean` — §4.3). Interpretation: mean-pooling discards behavior-relevant per-position structure (rather than the gap being PCA denoising of a single summary vector).
- **(ii) attn-learned closes the gap.** A learned single-vector query recovers most of the unpooled ceiling's advantage over `mean` (attn-learned ρ within CI of the unpooled ceiling, and both above `mean`). Interpretation: the lost information is a re-weighting of positions, not genuinely multi-position.
- **(iii) n=50 cannot resolve it.** Every operator's Δρ CI overlaps the shuffle null OR the unpooled ceiling is indistinguishable from `mean` within CI, WHILE √(r_yy) is decent. Deliverable: the reliability ceiling + the learning-curve contexts-needed estimate (this IS #742's thesis). Expanding the context battery becomes the flagged follow-up.

**Kill criterion (falsifies the line's premise).** If the unpooled ceiling predicts E0 MATERIALLY WORSE than the mean-pool across all behaviors and layers (unpooled ρ < mean ρ beyond CI, robustly — i.e. the extra features actively hurt even after PCA/ridge), the "mean-pool discards useful structure" premise is inconsistent with the data at n=50, and the honest report is "the mean pool is not lossy in any way our sample can detect; the granularity axis is dead at this n."

### 4.3 Regression pipeline (vectorized, CPU)

New driver `scripts/issue812_pooling_fit.py`, reusing the canonical helpers in `src/explore_persona_space/analysis/vectorized_mlp_skill.py` (verified on `main` @ `e000e25341`: `ridge_predict_loco_centered` L505, `robust_pca_basis` L439, `skill_over_mean_r2` L472, `fit_batched_loco_mlp_multihead` L298) + `issue658_fit_predictors` constants (`RIDGE_LAMBDAS`, `_press_loo_mse_per_lambda`, `_ridge_dual_weights`, `_rho`, `N_BOOTSTRAP=2000`).

**PRIMARY DV — behavior prediction, per (behavior × layer × operator).** Predict graded E0(C,B) from the operator's input, LOCO closed-form ridge, held-out Spearman ρ (and R²), with per-fold train-only standardization + nested-CV λ (the exact #742/#658 estimator). For each cell compute ρ for: `mean`, `max`, `attn-fixed`, `attn-learned`, the matched-PCA pooled baselines (`mean_pca` PRIMARY, `max_pca` / `attn-fixed_pca` / `attn-learned_pca` secondary), and the `unpooled` ceiling.
- **Unpooled input:** per-position PCA-reduce each of the `(2K+2)` aligned positions to d_in=10 (per-position, per-layer PCA fit train-only inside LOCO) → concatenate to `(2K+2)×10 = 340` features, THEN ridge. This is the mandatory overfit guard (§8 risk 1): the raw `(2K+2)×3584` input is never fed to ridge un-reduced.
- **Matched-PCA pooled baselines (MF3 — granularity-vs-denoising control).** The raw single-vector pools (`mean`/`max`/`attn-fixed`/`attn-learned`) are fed as raw `(3584,)` vectors, while the unpooled ceiling is PCA-reduced. A positive `unpooled > mean` Δρ therefore confounds (a) "mean-pooling discards per-position structure" (the claimed granularity mechanism) with (b) "PCA-to-10 denoised a single summary vector" (a preprocessing mechanism) — the shuffle null cannot separate them. To isolate the granularity axis, apply the SAME train-fold PCA-to-d_in=10 protocol used on the unpooled positions to each single-vector pool:
  - `mean_pca` — the mean-pooled `(3584,)` vector reduced to `(10,)` via the identical train-only per-fold PCA, ridge-fit. This is the PRIMARY matched control since `mean` is the reference operator.
  - `max_pca` / `attn-fixed_pca` / `attn-learned_pca` — the same matched-PCA on each single-vector pool (cheap 0-GPU additions on the SAME stored tensors; the fit sweep is already vectorized across cells).
  - The granularity-isolating headline is **unpooled vs `mean_pca`** (both PCA-denoised at matched rank ⇒ the only remaining difference is per-position granularity), reported ALONGSIDE unpooled vs `mean` (which the plan also reports). If `mean_pca ≈ unpooled` on Δρ, the "per-position structure" claim is REFUTED — the gain was denoising, not granularity (§8 risk row).
- **attn-learned query:** fit per (behavior × layer) cell — the ONLY gradient-descent arm. Query `q ∈ R^3584` init at the mean-pool direction, softmax attention over the `(2K+2)` aligned positions → `(3584,)` pooled vector → ridge to E0. L2 penalty on `q` swept nested-CV. VECTORIZE across all (behavior × layer) cells via the batched-MLP helper pattern (`.claude/rules/vectorize-many-cell-fits.md`) — NO per-cell Python loop. Cross-fit (fit q on the LOCO train fold only) to avoid leakage.
- **ΔDV:** `Δρ_op = ρ_unpooled − ρ_op` (how much each pool LOSES vs the ceiling, computed for every operator INCLUDING `mean_pca`) and `Δρ_op_vs_mean = ρ_op − ρ_mean` (each operator vs the reference), per cell. The headline granularity Δ is `Δρ_unpooled_vs_mean_pca = ρ_unpooled − ρ_mean_pca`.

**SECONDARY DV — answer-profile reconstruction, per (layer × operator).** The #722 base-map DV: LOCO ridge `c_C → operator-summary` (or the per-position target for the unpooled case), held-out skill-over-mean R² (PCA target dim = min(48, n−2)), via `ridge_predict_loco_centered` + `skill_over_mean_r2`. `c_C` = `issue594_context_geometry/analysis_tensors/context_vectors_mean.pt` (verified present, `(50,28,3584)` + `instance_ids`). Reference: the `mean` operator reproduces #722's ~0.80 at L18 (sanity check — a mismatch means the pipeline is wrong).

**Why code, not a model call?** The pooling reductions, PCA, ridge, and shuffle nulls are deterministic numerical operations over stored tensors — no unstructured-data heuristic. N/A — no classifier/extractor/parser over unstructured data (the only judge use is §4.2's graded scoring, which correctly IS a model call).

| Max pool | Element-wise max over answer tokens | A non-learned nonlinear pool | `op_max` |
| Random attention pool | Fixed random-projection softmax pool | Does LEARNING the pool beat a random one? (unlearned-pool control) | `op_attn_fixed` |
| Learned attention pool | Fit query softmax pool | Best single-vector pool; does a learned re-weighting close the gap? | `op_attn_learned` |
| Unpooled per-position (ceiling) | All aligned positions as joint features | The upper bound each pool is scored against | `op_unpooled` |
| Shuffle null | Same fit on row-permuted E0 | Chance level under the selection (selection-symmetric) | `null_shuffle` |
| LOCO cross-val | Leave-one-context-out held-out | Overfitting / in-sample optimism | (fold protocol, all cells) |

**Controls rationale.** `op_attn_fixed` isolates "learning the pool" from "attention-shaped pooling per se" (the #658-style unlearned control) — if `attn-learned` ≈ `attn-fixed`, the learned query buys nothing. `op_unpooled` is the ceiling that bounds every pool. The shuffle null + LOCO together bound the winner's-curse + overfitting at n=50.

## 11. Decision Rationale

- **ridge λ ∈ {1e-2,1e-1,1,10,100,1e3}, nested-CV.** Why: the exact grid the whole #658/#722/#742 line uses; matched so the pooling comparison is apples-to-apples with the parent reconstruction. Source: `#742` / `issue658_fit_predictors.RIDGE_LAMBDAS` (verified `[1e-2, 1e-1, 1.0, 10.0, 100.0, 1000.0]`). Alternatives: a finer grid — rejected, unmatched to parent, no evidence it changes the n=50-limited read.
- **Per-position PCA d_in = 10 (unpooled features) + reconstruction PCA target d = min(48, n−2).** Why: #742's single-highest-leverage move — PCA-to-~10 restores dependence-test power and pushes the regression toward the parametric regime at n=50; the min(48,n−2) target cap is the #722 convention. Without it the `(2K+2)×3584` input overfits and inflates the ceiling (the headline risk). Source: `#742 Stage-1` + `#722 per_position_vC_skill.ridge_skill` (+ #810 body line 170 confirms the PCA-reduced-per-position convention). Alternatives: no PCA (raw features) — rejected, guaranteed overfit; d=3 — rejected, too aggressive vs #742's 10.
- **Matched-PCA pooled baselines (`mean_pca` etc.) use PCA rank d_in = 10 — the SAME rank as the unpooled ceiling's per-position PCA.** Why: the matched control (MF3) exists to isolate the granularity axis from the preprocessing (denoising) axis; matching the pooled-vector PCA rank to the unpooled per-position rank means the ONLY remaining difference between `unpooled` and `mean_pca` is per-position granularity, not the amount of PCA denoising. A mismatched rank would re-confound the two axes the control is built to separate. Source: `matches §4.3 unpooled PCA rank (Alt-lens Must-Fix)`. Alternatives: a rank chosen to maximize `mean_pca` ρ — rejected (that would over-denoise the pool and understate the ceiling advantage, biasing toward "granularity helps"); no matched-PCA arm — rejected, that IS the confound MF3 flags.
- **attn-learned query: init = mean-pool direction, L2 penalty nested-CV, cross-fit.** Why: init at the known-good mean direction so the fit only has to find a re-weighting; regularize + cross-fit because a free 3584-dim query overfits n=50. Source: `ungrounded — needs smoke-test` (novel arm; no prior issue fit a learned answer-pool query). Flagged Low confidence in §12. Alternatives: unregularized query — rejected (overfit); random init — rejected (harder optimization, no reason to abandon the mean prior).
- **K = 16 aligned positions (tail −1..−K + head 0..K−1 + im_end + turn_nl = 34).** Why: #722's per-position script used P_MAX with COVERAGE_MIN 30; #810's body names K≈8–16 for the aligned sweep; 16 balances coverage (most answers ≥16 tokens) against the overfit budget. Source: `#722 per_position_vC_skill` (COVERAGE_MIN_CONTEXTS=30) + `#810 body line 63-64`. Alternatives: K=8 — kept as a robustness cut if coverage at K=16 tail is thin; K=32 — rejected (coverage collapses on short answers).
- **Layer set = all 28.** Why: the read-out/prediction regime sweeps all layers and selects by predictivity (Persona Vectors A3.3; #658 A3.2 swept all 28). Source: `#658 A3.2` / `#763` / arXiv 2507.21509. Alternatives: mid-late only {14,16,18} — rejected for the headline (would pre-bias layer selection); kept for the fast sanity re-run.
- **LOCO fold count = n (leave-one-context-out).** Why: n=50 is too small for k-fold; LOCO is the line's estimator + maximizes train size. Source: `#722`/`#658`. Alternatives: 5-fold — rejected (fewer train contexts, higher CV variance at n=50).
- **Shuffle-null iters = 1000; cluster-bootstrap B = 2000.** Why: #763's plan uses exactly these for the sibling read; matched for comparability. Source: `#763 plan` / `#742` (`N_BOOTSTRAP=2000` verified in `issue658_fit_predictors.py`). Alternatives: 10K perms — rejected (no resolving-power gain at n=50, wastes CPU).
- **Learning-curve grid n′ ∈ {10,15,20,25,30,40,50}.** Why: #742 Stage-2's grid; enough points to extrapolate the contexts-needed curve. Source: `#742 Stage-2`. Alternatives: {25,50} only — rejected (too few points to fit an extrapolation).
- **Graded judge N=8 draws/completion @ temp 1.0, anchored rubric, reason-then-score, one-behavior-per-call, drop-never-coerce.** Why: #763's own graded-E0 target recipe (`.claude/rules/llm-judging.md`) — reused verbatim so BOTH re-judge lanes (high-m off #658, low-m off #763's `gen/`) and any Lane-1 reuse of #763's finalized E0 are on the SAME 0–100 scale. The low-m `gen/` source has only 1 completion/probe, so the N=8 judge draws are the variance-reduction lever (matches #763's target). Source: `#763 plan v2` (graded target recipe) + `.claude/rules/llm-judging.md` rules 4/6/7/8/9 + arXiv 2303.16634. Alternatives: N=1 — rejected (no variance reduction, worse near a floor); binary-only — rejected (dichotomization attenuation ~0.798, the whole reason #763 went graded).
