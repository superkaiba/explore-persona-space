## Method delta

Prior related fixes (#2293 Step 9c oracle base, #2303 Step 5a sync deps,

## Design

### D1. Canonical binding block (inserted at extraction-prescribed fence tops)

```bash
# Fence-local binding (#2306): fenced blocks are separate shells; git -C ""
# and cd "" are silent no-ops that retarget the SHARED repo root.
REPO_ROOT=$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)")
WT="$REPO_ROOT/.claude/worktrees/issue-<N>"
[ -n "$WT" ] && [ -d "$WT" ] || { echo "FATAL: WT unbound or missing ($WT) — refusing; git -C \"\" / cd \"\" silently retarget the SHARED repo root" >&2; exit 1; }
```

`-n` catches a failed upstream eval; `-d` catches an unsubstituted `<N>`
placeholder (dir cannot exist) and a removed worktree. Equivalent spelling
`eval "$(bash scripts/step10d_guards.sh <N> --guard prelude)"` + the `-d`
guard is acceptable where the fence already shells the repo root.

### D2. Annotation convention (lint-recognized) for caller/prelude-dependent fences

First comment line(s) inside the fence carry the literal token `wt-binding:`:

```bash
# wt-binding: caller — $WT/$REPO_ROOT must already be bound in this shell;
# extracting standalone? prepend: eval "$(bash scripts/step10d_guards.sh <N> --guard prelude)"
```

The `cd "$WT" ||` form is explicitly NOT an accepted guard (proven silent
no-op on empty string).
