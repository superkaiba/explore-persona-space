# Plan v3 — #2309: mechanize the four-H3 completion-report contract on implementer round markers

## Requirement + acceptance criteria

Make the four-H3 completion-report contract (`### (a) What was done`, `### (b) Considered but
not done`, `### (c) How to verify`, `### (d) Needs human eyeball`) MECHANICALLY checked at
`task.py post-marker` time for the marker kinds that carry it, so a missing section is caught
in the implementer's own turn instead of costing a full code-review ensemble round (#2302
round 1: `epm:results v1` omitted `### (d)` entirely; the omission is never strip-eligible, so
it always costs a real round).

Acceptance criteria (verbatim from the task body):

1. A marker of a contract-bearing kind missing any of `### (a)`-`(d)` is refused or loudly
   WARNed at post time, naming the missing section(s).
2. A conforming marker posts unchanged — no false positives on the #2302 `epm:results v2`
   marker (which carries all four).
3. Non-contract-bearing marker kinds are unaffected.
4. Historical `events.jsonl` rows are not retroactively failed.

## Ground truth established at plan time (clarifier Step 0 + orchestrator reads)

- Contract sites: `.claude/agents/implementer.md:248-272` (template for `epm:results` on code
  paths, opening H2 `## Completion Report`) and
  `.claude/agents/experiment-implementer.md:826-909` (template for
  `epm:experiment-implementation`, opening H2 `## Implementation Report — round <n>` — NOT
  `## Completion Report`; v2 of this plan got that wrong and the critic round corrected it).
  Fleet scan (critic-verified 2026-08-23): of 1,936 historical `epm:experiment-implementation`
  rows, 1,743 match `^## Implementation Report` and only 39 match `^## Completion Report`; of
  2,633 `epm:results` rows, 1,496 match `^## Completion Report` (incl. #2302 v1, whose header
  `## Completion Report — #2302 implementer round 1` matches via `\b`). The signature gate must
  therefore accept BOTH header forms — a single-form signature would make the refusal
  structurally unreachable for one whole contract kind.
- **`epm:results` has a second, non-contract poster class:** pod-side dispatchers write
  `epm:results` SENTINELS (e.g. `scripts/issue1332_gpu_phase.py:1189`,
  `scripts/issue1005_run.py:543`, `scripts/dispatch_neg_geometry_504.py` — ~15 hits) that the
  orchestrator's poller drains into markers via the Python API. These notes are
  workload-results shaped and never carry the four H3s. A kind-blanket check would fail-loud
  on every experiment results drain — the check MUST be additionally scoped by the
  completion-report SIGNATURE (the `## Completion Report` header line both templates fix).
- Multi-part convention: oversize bodies split into chunks carrying `part=K/N` in marker
  metadata (`.claude/skills/issue/markers.md:203`). A part ≥2 chunk lacks the header (skipped
  by the signature gate automatically); a part-1 chunk may carry the header but legitimately
  end before `### (d)` — parts must be excluded from refusal. Channel mismatch, disclosed: the
  documented convention puts the part token in event METADATA, which the CLI has no flag to set
  and the note-text regex cannot observe (zero `"part"` metadata rows exist fleet-wide today);
  the practical relief is the note-text `part=K/N` token plus the waiver flag. If the CLI ever
  grows a `--part` flag, key the exclusion on that structured channel instead.
- Enforcement seams: `scripts/task.py::cmd_post_event` (line ~716; already carries THREE
  poster-side advisories incl. the #2307 followup_label one, which fires on the RESOLVED note
  so `--file` bodies are covered — copy that pattern); `task_workflow.post_event` (line ~5615;
  enforces the 50k cap pre-append). The deferred-commit path (#1030) fires AFTER a successful
  append — a refusal that runs BEFORE `post_event` is called cannot entangle with it.
- Sibling #2294 (completed 2026-08-23) is a Step 5 pre-dispatch marker-PRESENCE precondition —
  orthogonal; no shared validator exists yet to extend.

## Method delta (vs. current state)

Today the contract is judgment-caught by the code-reviewer. This change adds a mechanical,
kind- and signature-scoped presence check at the ONE channel implementer completion reports
travel (the `task.py post-marker` / `post-event` CLI), refusing a nonconforming post BEFORE
the append so the implementer fixes it in-turn. No lint arm (a lint over `events.jsonl` would
need explicit grandfathering and adds a second enforcement site for zero marginal coverage
going forward); no change to `post_event` library semantics (the poller's programmatic drains
are structurally unaffected).

## Design

**New pure predicate in `src/explore_persona_space/task_workflow.py`:**

```python
COMPLETION_REPORT_KINDS = ("epm:results", "epm:experiment-implementation")
# Both header forms are LIVE in the fleet and both kinds have historical rows
# under each (implementer.md template: "## Completion Report";
# experiment-implementer.md template: "## Implementation Report — round <n>";
# 39 epm:experiment-implementation rows carry the Completion form). The
# contract is the four lettered H3s, not the header wording — accept either
# form for BOTH kinds.
_COMPLETION_REPORT_SIGNATURE = re.compile(
    r"^##\s*(Completion|Implementation)\s+Report\b", re.MULTILINE
)
_COMPLETION_REPORT_SECTION = re.compile(r"^###\s*\(([a-d])\)", re.MULTILINE)
# '=' form ONLY — the space alternative (`part 1/6`) matches ordinary prose
# describing commit series (#76 v1), opening a silent refusal bypass.
_PART_TOKEN = re.compile(r"\bpart\s*=\s*\d+\s*/\s*\d+", re.IGNORECASE)

def completion_report_violation(kind: str, note: str | None) -> list[str] | None:
    """Return the list of missing section letters ('a'..'d') for a
    contract-bearing completion-report note, or None when the check does
    not apply (non-contract kind; empty note; no completion-report
    signature — e.g. a pod-sentinel results drain; a part=K/N multi-part
    chunk). An applicable, fully-conforming note returns []."""
```

Semantics:
- Applies iff `kind in COMPLETION_REPORT_KINDS` AND note is non-empty AND the note matches
  EITHER report-header signature (`## Completion Report` / `## Implementation Report`) AND no
  `part=K/N` token is present.
- Section detection is deliberately LENIENT on label text (`^###\s*\((a|b|c|d)\)` — presence of
  each lettered H3, not the full label string), so minor label variations don't false-positive;
  the #2302 v1 incident (no `(d)` line at all) is squarely caught.

**CLI refusal in `scripts/task.py::cmd_post_event` (pre-append):** after the note is resolved
(inline `--note` or `--file`, so both channels are covered — the #2307 pattern), and BEFORE
`post_event` is called:

- `completion_report_violation(...)` returns a non-empty list → print an ERROR naming the
  missing section(s) + the exact required headings + the escape flag, and exit non-zero.
  NOTHING is appended, so the deferred-commit contract (#1030) is untouched and there is no
  duplicated-marker risk.
- Escape flag `--allow-nonconforming-report "<reason>"` (reason ≥ 10 chars, same bar as the
  repo's waiver-comment conventions): bypasses the refusal and records the reason as a
  `report_shape_waiver` extras field on the event row (via `post_event(**extras)`), so the
  waiver is durable and auditable in `events.jsonl`. Covers legit edge cases: re-posts of
  historical content, unforeseen multi-part shapes, any false positive — the escape valve is
  what makes a fleet-wide refusal on a hot post path safe to arm.
- Companion ADVISORY (stderr WARN, non-blocking, after a successful post — the existing
  advisory pattern): a contract-kind note that does NOT match either report-header signature
  and carries no part token gets one soft-worded WARN — "if this was an implementer round
  marker, the expected header is `## Completion Report` (epm:results / implementer.md) or
  `## Implementation Report — round <n>` (epm:experiment-implementation /
  experiment-implementer.md)" — naming the PER-KIND expected header from that kind's own spec
  template. Soft wording is deliberate: ~880 historical no-signature `epm:results` rows are
  legitimately not completion reports (run digests, Step-9c verdicts, workload results), so
  future CLI posts of that shape will draw the WARN with some volume; it must read as a
  conditional hint, never an instruction to adopt a header the poster's spec forbids. This
  keeps the header-evasion hole visible without any refusal risk on the poller-drain class —
  the WARN can only fire on CLI posts, and pod sentinels are drained programmatically
  (critic-verified: `poll_pipeline.py` / `slurm_monitor.py` post via `task_workflow.post_event`
  directly).

**Explicitly NOT done (fail-loud constraint):** no normalization, no auto-filling a placeholder
`(d)` — the refusal message quotes the template's empty-case wording ("None — confidence high
across the diff.") so the fix is one paste away but stays authored.

## Implementation steps

1. **Historical would-have-fired audit (measurement before arming — same posture as the
   argcheck 83-of-927 baseline).** One-off script run (not committed, or committed under
   `tasks/planning/2309/artifacts/` if illuminating): iterate every task's `events.jsonl`,
   collect rows with kind ∈ COMPLETION_REPORT_KINDS, and report PER KIND: (i) how many match
   the (both-form) signature, (ii) of those, how many are missing ≥1 section (the
   would-have-fired set — critic's preliminary numbers under the corrected signature:
   24/1,496 for `epm:results`, 92/1,743 ≈ 5% for `epm:experiment-implementation`), (iii) the
   observed heading-form variants (to validate the lenient regexes), (iv) a PER-KIND
   signature-coverage ASSERT: the chosen signature matches ≥90% of that kind's historical
   SECTION-BEARING rows (rows carrying ≥3 of the four lettered H3s) — arm the refusal for a
   kind only after its assert passes (the mechanizable form of the v2→v3 correction: the v2
   single-form constant scores 39 vs 1,743 on `epm:experiment-implementation` and fails this
   assert), (v) a prose-collision count for the tightened `part=` token among signature-bearing
   rows (critic measured 0 today). Decision rule: heading forms the lenient regex misses among
   conforming-INTENT reports → widen the regex before arming; the implementer EYEBALLS a
   sample (~10) of the `epm:experiment-implementation` would-have-fired rows — if a material
   share are legitimate shapes (corrective re-posts, multi-part-like), prefer WARN-first for
   that kind; genuine omissions → arm REFUSE. Record all counts in the implementation report.
2. Add `completion_report_violation` + constants to `task_workflow.py` (pure function, no I/O).
3. Wire the refusal + waiver flag + advisory into `cmd_post_event` in `scripts/task.py`
   (argparse: add `--allow-nonconforming-report` to the post-marker/post-event subparser).
4. Tests — new `tests/test_task_workflow_completion_report.py` (workflow-invariant family):
   - refusal: contract kind + signature + missing `(d)` → CLI exit non-zero, message names
     `(d)`, `events.jsonl` unchanged (use a tmp task fixture per existing test conventions);
   - conforming: the REAL #2302 `epm:results v2` marker text as fixture → posts unchanged;
   - conforming `epm:experiment-implementation` with the REAL template header
     `## Implementation Report — round 2` + all four sections → posts unchanged;
   - `epm:experiment-implementation` with that same header but missing `(d)` → refused
     naming `(d)` (the kind the v2 single-form signature would have silently no-opped on);
   - non-contract kind (`epm:progress`) with the same defective text → posts unchanged;
   - sentinel-shaped `epm:results` note (no signature) → posts unchanged;
   - `part=1/3`-tokened note with signature but no `(d)` → posts unchanged (multi-part skip);
   - prose `(part 1/6)` (space form, no `=`) inside a signature-bearing note missing `(d)` →
     still refused (the tightened `=`-only part token does not match prose);
   - waiver flag with ≥10-char reason → posts, event row carries `report_shape_waiver`;
     sub-10-char reason → refused;
   - pure-function unit tests for the regexes (lenient labels; `## Completion Report` mid-note;
     case variants per audit findings).
5. Doc edits (one line each, no template changes): `implementer.md` § Report Format and
   `experiment-implementer.md` § completion-report section — note the mechanical refusal + the
   escape flag, citing #2309.
6. Lint + targeted tests: `uv run ruff check` on touched files;
   `uv run pytest tests/test_task_workflow_completion_report.py tests/test_verify_task_body.py -x`
   plus the `select_step9c_tests.py --map-files` mapped set for the touched files.

## Kill criteria

- Signature reliability is evaluated PER KIND (the step-1 audit's per-kind coverage assert).
  If a kind's signature proves unreliable — sentinel/drain notes matching a report header, or
  a material fraction of that kind's genuine reports lacking both header forms — fall back to
  WARN-only at post time FOR THAT KIND (still satisfies acceptance criterion 1's "loudly
  WARNed" arm) and record the finding. NEVER a global demotion: one kind's unreliable
  signature must not strip the refusal from a kind where the signature works. Do not ship a
  refusal that can wedge the results-drain path.
