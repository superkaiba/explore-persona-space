### A. New module-level helpers (place next to check 17, after `_V4_CONTEXT_LINEAGE_TOKEN_RE`)

```python
# ── Check-17 origin-prompt verbatim sub-check (#1068, incident #813 r1) ──
# The **Context:** row promises the originating prompt VERBATIM
# (SPEC.md § `**Context:**` row). The sub-check requires normalized
# frontmatter `origin_prompt` to appear as a SUBSTRING of the normalized
# Context-region text (blockquote markers stripped). Substring — not
# per-segment equality — because the row legitimately carries MORE quoted
# text than the creation prompt (follow-up-round prompts, lineage prose,
# inline quote marks), and because the containment DIRECTION is what
# catches truncation: a truncated quote means the full origin_prompt
# appears NOWHERE in the row. (A quote-⊆-origin_prompt test would PASS
# every truncation — direction matters.)

_MD_ESCAPE_RE = re.compile(r'\\([\\`*_{}\[\]()#+\-.!|>~"\'])')

def _normalize_prompt_text(s: str) -> str:
    """Whitespace-collapse + unicode-punctuation fold for the check-17
    origin-prompt comparison. Collapses all whitespace runs (incl.
    newlines from wrapped blockquotes) to single spaces, folds NBSP and
    curly quotes/apostrophes to their ASCII forms (editors smart-quote;
    a fold applied to BOTH sides never masks a real word-level edit)."""
    s = s.replace("\u00a0", " ")  # NBSP (use the escape, not a literal NBSP char)
    s = s.replace("‘", "'").replace("’", "'")
    s = s.replace("“", '"').replace("”", '"')
    return " ".join(s.split())

def _unescape_markdown(s: str) -> str:
    """Undo backslash-escapes of markdown punctuation (body side only —
    an analyzer writing `origin_prompt` containing `**`/`` ` `` into
    markdown may escape it; the frontmatter value is raw text)."""
    return _MD_ESCAPE_RE.sub(r"\1", s)

def _strip_blockquote_markers(text: str) -> str:
    """Remove leading `>` marker runs per line, KEEPING the line text.
    The opposite transform of `_strip_blockquote_lines` (which drops the
    whole line for the #959 URL-scan exemption): here the quote text IS
    the object under test, only the markers are noise."""
    return "\n".join(re.sub(r"^\s*(?:>\s?)+", "", ln) for ln in text.splitlines())

_CONTEXT_LABEL_RE = re.compile(r"\*\*\s*Context\s*:?\s*\*\*")  # same pattern check 17 already inlines

_INLINE_QUOTE_SPAN_RE = re.compile(r'["“]([^"“”]{20,})["”]', re.S)
```

### B. The verdict function (new, module-level)

```python
def _origin_prompt_quote_verdict(repro: str, fm: dict) -> tuple[str, str]:
    """Classify the Context row's originating-prompt quote against
    frontmatter `origin_prompt`.

    Returns (status, detail): status in
      "noop"        — no fm origin_prompt, or no **Context:** label
      "pass"        — normalized origin_prompt ⊆ normalized region text
      "fail-trunc"  — a quoted candidate is a strict normalized PREFIX of
                      origin_prompt (the #813/#742 truncation signature)
      "warn-mismatch" — containment fails, no truncation signature
    """
    op = str(fm.get("origin_prompt") or "").strip()
    if not op:
        return "noop", "no frontmatter origin_prompt"
    m = _CONTEXT_LABEL_RE.search(repro)
    if m is None:
        return "noop", "no **Context:** label"          # caller's label branch makes this unreachable
    region = repro[m.end():]                             # Context row → end of footer/section
    nop = _normalize_prompt_text(op)
    stripped = _strip_blockquote_markers(region)
    if nop in _normalize_prompt_text(stripped) or nop in _normalize_prompt_text(
        _unescape_markdown(stripped)
    ):
        return "pass", ""
    # Containment failed — classify. Candidates: blockquote segments
    # (contiguous `>` runs, lazy-continuation lines joined) + inline
    # quote-mark-delimited spans (≥20 chars) in the marker-stripped region.
    candidates = _context_quote_candidates(region)
    best_lcp, truncated = 0, None
    for cand in candidates:
        ncand = _normalize_prompt_text(_unescape_markdown(cand))
        ncand_p = ncand.rstrip(".,;:!?… ")          # a truncating editor appends `.`/`…` (#742)
        best_lcp = max(best_lcp, _common_prefix_len(ncand_p, nop))
        # FAIL guard (revise-round D10): a strict-prefix candidate must ALSO
        # cover >=50% of the normalized origin_prompt. Rationale: the incident
        # class (silent tail truncation — #742 at 85%, #813-r1 ~synthetic 60%)
        # characteristically preserves most of the prompt, while the
        # false-positive scenario (an innocent SHORT elided pointer quoting the
        # fm opener alongside a full alternate-source quote — the #825+ shape
        # the alternatives reconciler upheld) characteristically quotes a small
        # head fraction (~10%). Below the floor the case routes to WARN, whose
        # message names the alternate-source escape. Per-candidate + fraction
        # semantics deliberately do NOT suppress on the presence of a longer
        # non-prefix candidate — that variant would false-NEGATIVE the
        # multi-round true positive (truncated creation quote + a longer full
        # round-2 quote), pinned by test 15.
        if (
            20 <= len(ncand_p) < len(nop)
            and len(ncand_p) >= 0.5 * len(nop)
            and nop.startswith(ncand_p)
        ):
            truncated = ncand_p
    if truncated is not None:
        cut = len(truncated)
        return "fail-trunc", (
            f"context-origin-prompt-mismatch: the quoted originating prompt is a strict "
            f"PREFIX of frontmatter `origin_prompt` — truncated at normalized offset "
            f"{cut}/{len(nop)} (quote ends '…{truncated[-40:]}'; origin_prompt continues "
            f"'{nop[cut:cut + 60]}…'). Quote the FULL origin_prompt verbatim "
            f"(SPEC.md § `**Context:**` row)."
        )
    return "warn-mismatch", (
        f"context-origin-prompt-mismatch: frontmatter `origin_prompt` does not appear "
        f"verbatim (whitespace-normalized) in the `**Context:**` row — first divergence at "
        f"normalized offset {best_lcp}/{len(nop)} (origin_prompt continues "
        f"'{nop[best_lcp:best_lcp + 60]}…'). If the row quotes a spec-sanctioned alternate "
        f"verbatim source (original-body `## Provenance` / an `epm:followup-scope` marker), "
        f"this is informational; otherwise re-quote origin_prompt verbatim."
    )
```

`_context_quote_candidates(region)` (module-level, ~15 lines): walk `region.splitlines()`; the first line's post-label remainder, `>`-stripped, is a candidate if non-empty; subsequent lines: a `>`-prefixed line opens/extends a segment (leading `(?:>\s?)+` run removed); a non-blank line immediately following a quote line extends it (markdown lazy continuation — fails toward PASS, see §11-D6); a blank/other line closes the segment. Append `_INLINE_QUOTE_SPAN_RE.findall(_strip_blockquote_markers(region))` for the inline-quoted shapes. `_common_prefix_len(a, b)` is the obvious 4-liner (or `os.path.commonprefix` length).

### E. Extraction / normalization / semantics decisions (the 5 design questions, nailed)

1. **Extraction — region-haystack, label-optional.** The comparison haystack is the ENTIRE `**Context:**` region (label match → end of `_repro_section_text` output), with per-line `>` markers stripped. No "Originating prompt" label requirement: the live tree has conforming label-less shapes (#763 inline `**Context:** > "…"`, #810 bare blockquote) and 8 bodies quoting inline in `"…"`/`*"…"*` with label variants (`Originating user request (verbatim):`, `Origin prompt (Thomas, 2026-06-28):`, `Verbatim originating prompt:`) — a label regex either misses them (truncation hole + false NO-OPs) or grows unboundedly. The NO-OP constraints (the task body's "NO-OP pass when frontmatter `origin_prompt` is absent"; the planning brief's "no blockquote label at all → existing presence checks own it" — attribution per fact-check) are honored at the outer level: no `**Context:**` label → the existing missing-row logic runs untouched; no fm `origin_prompt` → NO-OP.
2. **Normalization.** Both sides: whitespace-collapse (`" ".join(s.split())`), NBSP→space, curly→straight quotes/apostrophes. Body side additionally tested twice — raw and markdown-unescaped (`\*`→`*` etc.) — PASS if either contains. NOT normalized: dashes, case, `*`/`` ` `` emphasis markers (a truly verbatim quote reproduces them — #931's `**stories**` round-trips exactly; stripping them could mask real edits). Surrounding quote marks need no special handling: substring semantics ignores wrapping punctuation for free.
3. **Equality vs prefix — containment, with a high-precision truncation classifier.** PASS iff normalized `origin_prompt` ⊆ normalized region. Direction: a truncated quote is a substring of `origin_prompt`, NOT vice-versa — so containment of `origin_prompt` in the row fails exactly when the full prompt is missing, catching every truncation. On containment failure: FAIL only when a quoted candidate (trailing `.,;:!?…` stripped — #742 appends `.` at the cut) is a ≥20-char strict normalized prefix of `origin_prompt`; the FAIL message names the cut offset, the quote's last 40 chars, and the next 60 chars of `origin_prompt`. Everything else is a WARN naming the first-divergence offset (longest common prefix over candidates). Rationale for WARN-not-FAIL on generic mismatch: SPEC sanctions three verbatim sources, and #825's row verbatim-quotes the full `## Provenance` prompt while its fm `origin_prompt` is a self-declared abridgement — a hard FAIL there would punish a conforming body; the truncation signature is the incident class and is FAIL.
4. **Multi-prompt / follow-up-round bodies.** Containment over the whole region is inherently multi-prompt-safe: extra round-prompt blockquotes, scope notes, and lineage prose only grow the haystack (#813 post-fix with 2 labeled quotes and #810 with 4 round quotes both PASS in the scan). A truncated creation quote still FAILs because the full `origin_prompt` appears nowhere.
5. **Where it lives.** Inside check 17 (`check_repro_context_provenance`), as a sub-check after the v4 lineage token (mirroring how #1014 added the lineage sub-check); same `CheckResult` name; v4 lineage FAIL still returns first (one message per run — the file's convention; a body failing both surfaces the truncation on the next verifier run after the lineage fix).

## 11. Decision Rationale

N/A — no model training; entries below cover the design decisions per the task brief.

- **D1 — Containment (origin_prompt ⊆ region), not per-segment equality.** *What:* PASS iff normalized fm `origin_prompt` is a substring of the normalized, `>`-marker-stripped Context region. *Why:* the row legitimately carries more quoted text than the creation prompt (round prompts, lineage, quote-mark wrapping), and this direction is exactly the one that catches truncation (truncated quote ⇒ full prompt absent from row). *Source:* §2.3 backlog scan — per-segment equality retro-FAILs ≥13 conforming bodies; containment retro-FAILs only the genuinely-truncated #742. NOTE (fact-check correction + deliberate deviation): the task body's diff sketch proposes normalized EQUALITY; this plan deliberately deviates to containment because the scan shows equality is backlog-hostile — the containment direction (origin_prompt ⊆ region) is the plan's own contribution, validated solely by the scan, and still FAILs every truncation (the "refine in planning" clause in the body's sketch sanctions the refinement). *Alternatives rejected:* per-segment normalize-equality (the body's sketch; backlog-hostile); quote-⊆-origin_prompt (passes every truncation — wrong direction).
- **D2 — FAIL only on the strict-prefix truncation signature; generic mismatch WARNs (v4).** *What:* ≥20-char trailing-punct-stripped candidate that strictly prefixes `origin_prompt` → FAIL; other containment failure → WARN with first-divergence offset. *Why:* truncation is the incident class (#813 r1, #742) and is detectable with near-zero false positives; a generic mismatch has a spec-sanctioned innocent cause. *Source:* SPEC.md :635–637 (three verbatim sources) + backlog exemplar #825 (fm self-declared abridgement, full `## Provenance` prompt quoted). *Alternatives:* FAIL on any mismatch (retro-FAILs conforming #825; punishes the alternate-source pattern SPEC allows); WARN on truncation too (defeats the Goal — the ensemble REVISE round this closes would still be needed).
- **D3 — Normalization set: whitespace-collapse + NBSP + curly-quote fold (both sides); markdown-unescape (body side, tested raw OR unescaped).** *Why:* blockquote wrapping inserts newlines (whitespace); editors smart-quote (fold both sides — symmetric, can't mask word edits); analyzers may escape `**`/backticks writing into markdown (#931's `origin_prompt` contains literal `**stories**` — round-trips unescaped, so test both variants rather than always unescaping). Dashes/case/emphasis NOT folded — a verbatim quote reproduces them, and folding could mask real edits. *Source:* in-file normalization precedents (`" ".join(s.split())` idiom, e.g. :7525) + the §2.3 scan (this exact set produces 26/30 PASS with zero false FAILs; weaker sets produced false mismatches). *Alternatives:* full Unicode NFKC (over-normalizes, e.g. folds `…` in ways that mask edits); no unescape leg (false-FAILs escaped-markdown quotes).
- **D4 — 20-normalized-char floor on the truncation candidate.** *Why:* below it, a short quoted fragment of a DIFFERENT prompt sharing an opener could coincidentally strictly prefix `origin_prompt`; at ≥20 chars a full-candidate-is-prefix collision is implausible unless it IS the truncation. Matches the inline-quote-span regex floor. *Source:* ungrounded numerically — chosen by the collision argument and validated by the §2.3 scan (no false FAILs at 20; the real truncations are 41+ and 212 chars). Not smoke-test-worthy beyond the scan: the scan IS the validation on all live data. *Alternatives:* fraction-of-prompt floors (fails short origin_prompts entirely); no floor (opener-collision false FAILs).
- **D5 — Extend check 17 in place, same CheckResult name.** *Why:* the task title mandates it; the lineage sub-check (#1014) is the exact structural precedent; tests key on `_CONTEXT_CHECK = "Reproducibility Context provenance row"` (:4303). *Source:* `check_repro_context_provenance` :3370 + tests :4303. *Alternative:* a new check number (breaks the one-concern-one-check convention and doubles the Context-row failure surface).
- **D6 — Lazy-continuation lines join their blockquote segment; haystack keeps ALL region text.** *Why:* markdown semantics joins them, and inclusion fails toward PASS (bigger haystack) — the safe direction for a new FAIL-capable check. The #959 precedent (`_strip_blockquote_lines` keeps lazy lines SCANNED) chose fail-closed for a URL-permissiveness exemption; here the polarity is reversed (the quote is the object, not the exemption), so fail-open is the analogous conservative choice. *Source:* `_strip_blockquote_lines` docstring :4113–4125.
- **D7 — No fence-stripping of the haystack.** *Why:* a prompt quoted inside a fence would be REMOVED by fence-stripping → false mismatch; extra fenced noise in the region only grows the haystack (harmless under containment) and cannot fabricate a ≥20-char strict prefix in practice. *Source:* `_strip_fenced_blocks` :4098 semantics; the lineage sub-check fence-strips because there the polarity is a token that must NOT be satisfied from quoted text — again reversed here. *Alternative:* fence-strip (wrong polarity).
- **D8 — v3/v2 WARN-only, gated on `is_v4`.** *Why + Source:* hard task constraint (grandfathering, forward-only rule per `is_v4` docstring :2443–2454); §2.3 shows 2 v3 WARNs, 0 FAILs. *Alternative:* skip entirely on v3/v2 (loses free signal the WARN surfaces at promote time; constraint explicitly allows WARN).
- **D9 — #742 is left FAILing; no task-body edit in this session.** *Why:* `tasks/**` is out of scope for a workflow-fix session (rule: workflow-surface only), and the constraint blesses the FAIL as correct. *Source:* task #1068 body § Constraints; `.claude/rules/workflow-fix-on-bug.md` out-of-scope list. *Alternative:* pre-fix #742's footer from this session (scope violation).
- **D10 — ≥50%-of-origin_prompt coverage floor on the truncation FAIL (revise round; upheld alternatives item 2).** *What:* `fail-trunc` requires the strict-prefix candidate to cover ≥50% of normalized `origin_prompt` (in addition to the ≥20-char absolute floor); below it the case routes to `warn-mismatch`. *Why:* without it, an #825-class conforming alternate-source body carrying an innocent SHORT inline quote of the fm opener (strict prefix, ~10% coverage) hard-FAILs where D2's severity contract prescribes WARN — a plan-internal contradiction the alternatives reconciler upheld as blocking. The floor discriminates the incident class (silent tail truncation preserves most of the prompt: #742 at 85%, the synthetic #813-r1 fixture at 60%) from innocent head-fraction pointers (~10%). *Source:* the alternatives reconciler's verified construction + the §2.3 scan (both live exemplars far above the floor; the live #825 body has NO strict-prefix candidate — lcp 0 — so the guard changes no live-tree classification: backlog counts unchanged). *Alternatives rejected:* Codex option (b) "suppress FAIL when a longer non-prefix candidate is present" — false-NEGATIVES the multi-round true positive (truncated creation quote + longer round-2 quote; pinned by test 15); Codex option (a) "best candidate by lcp" — the short innocent opener IS the max-lcp candidate in the failure scenario, so it does not fix it. The 0.5 value is a judgment constant validated against the scan's coverage separation (85%/60% true positives vs ~10% innocent pointers); its recall cost (<50% truncations degrade to WARN) is documented in §8 and the docstring.
