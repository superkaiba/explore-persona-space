## 0.0 TL;DR (plain English)

- **What I'll do:** On Google Cloud, our activation extractor saves dozens
  of small data files per work-unit straight to a network-attached disk.
  That disk shares the same network card the machine needs to renew its own
  network lease, and the write storm can starve the lease and wedge the
  whole instance. I'll add one small shared helper that writes those files
  to a fast local disk first, then copies the whole batch over to the
  network disk in one shot when the work-unit finishes — keeping the busy
  write path off the network plane. I'll also wire up the one switch that
  turns this on for Google Cloud, so the fix actually runs in production
  rather than sitting dormant. Off Google Cloud, the helper does nothing
  (writes go straight where they always did).
- **What I expect:** The files that land on the network disk are
  byte-for-byte the same as before; nothing about any result changes. This
  is a plumbing fix that decouples a noisy write path from the network, and
  it's switched on for Google Cloud once this merges.
- **What would change my mind:** If the "files are identical" test refuses
  to pass, or if respecting the existing "this work-unit is finished" marker
  (which must be written last, to the network disk, only after everything
  copied) turns out to be more tangled than it looks, I'll stop and re-check
  rather than weaken the completeness guarantee that protects resumed runs.

### 4.2 New shared helper — `src/explore_persona_space/orchestrate/scratch_io.py`

*(Unchanged from v1.)*

Location chosen: `orchestrate/` (alongside `env.py`, `preflight.py` — the

extraction logic). The helper is pure IO routing, so it belongs with the

Two public functions + one module constant. Pseudocode:

```python
# src/explore_persona_space/orchestrate/scratch_io.py
"""Route hot per-cell .npz writes to local-SSD scratch, then batch-materialize
to the canonical (network-backed) destination at cell/sweep end.

On GCE the canonical destination is a network-backed Persistent Disk whose
virtual NIC is shared with systemd-networkd DHCP renewal; a per-cell .npz
write storm there contributes to the hung-RUNNING wedge (#667/#671/#674).
Writing to a local-SSD scratch mirror first and copying the whole cell over
in one batch keeps the hot write path off the network plane.

The GCE startup script sets EPS_SCRATCH_DIR (default /tmp/eps_scratch, a
local-SSD path) via the workload_cmd block, and gcp.py forwards any
dispatch-process EPS_SCRATCH_DIR through STARTUP_PASSTHROUGH_ENV_KEYS; off
GCE the var is UNSET, so both functions are thin pass-throughs (writes go
straight to the canonical dir, no indirection) so non-GCE behavior is
byte-for-byte unchanged.
"""
from __future__ import annotations

import os
import shutil
from pathlib import Path

ENV_SCRATCH_DIR = "EPS_SCRATCH_DIR"  # unset => pass-through (non-GCE default)


def _scratch_root() -> Path | None:
    """Return the configured scratch root, or None when pass-through (unset)."""
    raw = os.environ.get(ENV_SCRATCH_DIR, "").strip()
    return Path(raw) if raw else None


def scratch_path_for(canonical_dest: Path, issue: int) -> Path:
    """Map a canonical PD path to its local-SSD scratch mirror.

    When EPS_SCRATCH_DIR is unset (non-GCE), returns ``canonical_dest``
    unchanged (pass-through). When set, returns
    ``<root>/issue<issue>/<canonical-dest-with-leading-slash-stripped>`` so
    the scratch tree MIRRORS the canonical structure — distinct cell dirs map
    to distinct scratch dirs and never collide.

    Accepts either a directory (a cell dir) or a file path; the relative
    structure under the scratch root mirrors whatever was passed.
    """
    canonical_dest = Path(canonical_dest)
    root = _scratch_root()
    if root is None:
        return canonical_dest  # pass-through (non-GCE)
    # Mirror the FULL canonical path under <root>/issue<N>/ so two cells with
    # the same basename (different parents) never collide. Strip the anchor
    # ("/" or "C:\\") so the join stays relative.
    rel = Path(*canonical_dest.parts[1:]) if canonical_dest.is_absolute() else canonical_dest
    return root / f"issue{issue}" / rel


def materialize_to_canonical(scratch_dir: Path, canonical_dir: Path) -> None:
    """Batch-copy every .npz in ``scratch_dir`` to ``canonical_dir`` atomically,
    then delete ``scratch_dir``.

    No-op when ``scratch_dir == canonical_dir`` (the pass-through case — the
    files were already written directly to canonical). Otherwise:
      * mkdir canonical_dir (parents, exist_ok);
      * for each *.npz in scratch_dir: copy to ``canonical_dir/<name>.tmp``
        then ``os.replace`` to the final name (atomic within the canonical
        filesystem — no half-written .npz ever visible to a reader/resume-skip);
      * rmtree(scratch_dir).

    Sentinel contract: this NEVER writes the .done sentinel — the caller writes
    it to the CANONICAL dir AFTER this returns AND after its own complement
    check (issue667: assert_full_npz_complement). On a partial failure here the
    scratch dir is left INTACT (re-raise) so a retry can re-materialize, and the
    canonical .done is never written (the caller's assert runs after us).
    """
    scratch_dir, canonical_dir = Path(scratch_dir), Path(canonical_dir)
    if scratch_dir.resolve() == canonical_dir.resolve():
        return  # pass-through: files already in canonical_dir
    canonical_dir.mkdir(parents=True, exist_ok=True)
    for src in sorted(scratch_dir.glob("*.npz")):
        dst = canonical_dir / src.name
        tmp = canonical_dir / f"{src.name}.{os.getpid()}.tmp"
        shutil.copyfile(src, tmp)   # raises on disk-full / IO error (fail loud)
        os.replace(tmp, dst)        # atomic rename within canonical fs
    shutil.rmtree(scratch_dir)
```

Notes on the design choices:

- **GCE detection via explicit env, not metadata probing.** The GCE
  startup script sets `EPS_SCRATCH_DIR` (§4.4) and it is unset elsewhere
  (body requirement). This is the same "explicit env beats runtime probing"
  choice `slurm.py` makes (`$SCRATCH` is read from the env, not discovered).
  It is also the only testable design — a unit test can set/unset the env
  deterministically; a metadata-server probe cannot be exercised on the VM.
- **`scratch_path_for` mirrors the full canonical structure** so multiple
  cells with the same basename under different parents (e.g.
  `eval_results/issue_667/analysis_tensors/em/<src>_seed42` vs another
  behavior) never collide in scratch. This is the body's "mirrors the
  canonical structure (so multiple cells don't collide)" test requirement.
- **Atomic per-file `os.replace`** (not a directory rename) so a reader /
  resume-skip in the canonical dir never sees a half-copied `.npz`, and no
  `.tmp` survives in canonical after a successful materialize (`os.replace`
  is atomic within a filesystem — the same idiom as
  `write_cell_done_sentinel`).
- **Fail loud on scratch-disk-full / IO error.** `shutil.copyfile` (and the
  upstream `np.savez` into scratch) raise on a full disk; the helper does
  NOT silently fall back to canonical mid-write (that would defeat the
  decoupling and is exactly the `try/except: pass` anti-pattern CLAUDE.md
  bans). A full scratch disk is a loud crash the dispatcher surfaces.
- **Partial-failure safety.** If `materialize_to_canonical` raises mid-copy,
  the scratch dir is left intact (the `rmtree` is past the loop), so a retry
  re-materializes; and because the caller writes the `.done` sentinel only
  AFTER `materialize_to_canonical` returns AND after
  `assert_full_npz_complement` passes on the canonical dir, an interrupted
  materialize never leaves a `.done`-stamped partial cell.

### 4.4 GCE launcher wiring — IN SCOPE (the v1-defect fix)

**Why this is in scope (not deferrable).** The Goal (§1) is to fix the
#667/#671 GCE wedge by decoupling the `.npz` write path from the network
plane *on GCE*. The helper (§4.2) only routes to scratch when
`EPS_SCRATCH_DIR` is set in the workload subprocess environment. On the GCE
lane, the workload runs inside a GCE VM whose environment is built by the
GCE startup script (`gcp.py:render_startup_script`) from VM metadata; an env
var set on the VM-side dispatch process (`scripts/issue667_dispatch.py`)
does NOT reach the VM workload unless it is in
`gcp.py:STARTUP_PASSTHROUGH_ENV_KEYS` (the established passthrough channel,
see §2). Verified: `STARTUP_PASSTHROUGH_ENV_KEYS` (gcp.py lines 793-805)
contains 6 keys and does NOT include `EPS_SCRATCH_DIR`. So with the v1 scope
(helper + call site only), on GCE the workload's `os.environ` never has
`EPS_SCRATCH_DIR`, `_scratch_root()` returns `None`, and the helper
pass-through's — routing NOTHING to scratch. The production GCE amplifier
fix would ship DEAD. This is NOT analyzer-recoverable (there is no
downstream pipeline step that can wire production env after the fact), so
the env wiring is pulled into this PR.

## 11. Decision Rationale

N/A — no training hyperparameters. (`kind: infra`; §11 grounding does not
apply.)

The design knobs warranting a short rationale (per the task brief):

- **What:** default scratch base `/tmp/eps_scratch` (local SSD) rather than
  `/dev/shm` (tmpfs / RAM), set via the GCE startup-script default
  (§4.4 Edit 2).
- **Why:** `/tmp` on a GCE DLVM instance is backed by the local boot/SSD
  disk with size headroom measured in tens-to-hundreds of GB, and it
  persists for the lifetime of the run (across the whole per-cell loop), so
  a full sweep's worth of intermediate `.npz` never risks exhausting it.
  `/dev/shm` is RAM-backed (tmpfs, typically sized to ~half of instance
  memory) — staging activation `.npz` there competes with the model's own
  resident memory, which is precisely the pressure #671 just fixed;
  re-introducing memory pressure to fix an I/O problem would be
  self-defeating. `/tmp`-based scratch also matches the existing in-repo
  convention: `slurm.py` derives node-local scratch from `$SLURM_TMPDIR` /
  `$SCRATCH` (a disk-backed fast scratch, not RAM), and the SLURM sbatch
  preflights a ≥50 GB `$SLURM_TMPDIR` headroom (`slurm.py:1426-1429`) — the
  same "disk-backed node-local scratch with size headroom" shape.
- **Source:** in-repo precedent `slurm.py` `scratch_dir_for` /
  `$SLURM_TMPDIR` pattern (`#671` deferral cites this lineage); the
  startup-script `:-` default idiom is `gcp.py:969`'s
  `export WANDB_PROJECT="${WANDB_PROJECT:-issue<N>}"` and `gcp.py:961`'s
  `export REPO_ROOT="$WORKLOAD_ROOT"`. NOTE: the literal path string
  `/tmp/eps_scratch` does NOT currently exist in the repo (grep found zero
  hits) — this plan ESTABLISHES that default, modeled on the slurm
  node-local-scratch convention. Flagged in §12 so the fact-checker doesn't
  expect a pre-existing literal.
- **Alternatives considered:** (a) `/dev/shm` — rejected (RAM contention, as
  above). (b) GCE metadata-server probing to auto-detect GCE + auto-pick a
  local-SSD mount — rejected: not unit-testable on the VM, and the explicit
  `EPS_SCRATCH_DIR` env is both testable and the body's stated requirement.
  The default is the *fallback base* when `EPS_SCRATCH_DIR` is unset; the
  dispatch process can always forward `EPS_SCRATCH_DIR` (via the new
  passthrough key) pointed at a dedicated local-SSD mount on GCE.

- **What:** `EPS_SCRATCH_DIR` placed in `STARTUP_PASSTHROUGH_ENV_KEYS`, not
  `STARTUP_SECRET_ENV_KEYS`.
- **Why:** it is a filesystem path, not a credential — the passthrough list
  is exactly for "non-secret config the VM workload reads from `os.environ`"
  (gcp.py docstring lines 783-792). The secret list is reserved for tokens
  placed on `--metadata-from-file` 0600 tempfiles.
- **Source:** `gcp.py` docstring lines 783-805 + the 6 existing passthrough
  keys (all non-secret config).
