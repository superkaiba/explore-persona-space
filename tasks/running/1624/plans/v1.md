# Plan — #1624: `workflow_lint.py` check flagging bare `list_repo_files(` call sites (the ~1M-file data-repo wedge class)

## 0.0 TL;DR (plain English)

- **What I'll build:** a new lint check, `--check-bare-list-repo-files`, that fails whenever code under `scripts/` or `src/` calls `list_repo_files(` — a function that can only ever list an ENTIRE HuggingFace repo, which hangs for minutes against our ~1-million-file data repo. The error message tells the author exactly which scoped helpers to use instead. The ~80 existing call sites are grandfathered in a frozen snapshot; only new code is gated.
- **What I expect:** the check passes cleanly on today's tree after grandfathering, flags a synthetic offender in a unit test, and never fires on comments, docstrings, or test mocks (I detect via the Python AST, so prose mentions are structurally invisible).
- **What would change my mind:** if at implement time the AST predicate turns out to match substantially more than the ~80 files I measured (a sign it catches something unforeseen), or if it cannot pass the live tree without exempting the canonical hub helpers themselves, the predicate premise is wrong and I stop and re-scope.

def _bare_list_repo_files_file_errors(py: Path, rel: str) -> list[str]:
    """Snapshot-BLIND per-file scan shared by check + regen (#1568 idiom)."""
    text = py.read_text(encoding="utf-8")

            f"path_in_repo=<prefix>, recursive=True) / api.file_exists(repo, "

def check_bare_list_repo_files(*, repo_root: Path | None = None) -> list[str]:
    """Walk HF_ROUTING_SCOPE_ROOTS ('scripts', 'src/explore_persona_space')
    and FAIL on any bare list_repo_files call/reference outside
    LIST_REPO_FILES_FROZEN_SNAPSHOT and un-waived. repo_root = unit-test
    override hook. Bundled into the no-flags default run."""
    root = repo_root if repo_root is not None else _REPO_ROOT
    errors: list[str] = []
    for scope in HF_ROUTING_SCOPE_ROOTS:
        base = root / scope
        if not base.exists():
            continue

### 4c. Why the AST predicate (design question 1 resolved)

Option (b) from the brief — flag **every** call site — implemented via AST, chosen over (a) file-references-data-repo and (c) revision-aware:

- (a) has structural false negatives: `list_repo_files(repo_used, ...)` / `HF_DATA_REPO` imported from a sibling module — file-local repo-id detection cannot resolve either (real shapes at `scripts/issue634_extract_behavior_vectors.py:336`, `scripts/issue763_judge_e0.py:891`). And the model repo sits AT the 100k-file limit (#1108) — "not the data repo" is not "safe".
- (c) revision-awareness changes nothing: the wedge is tree size, not revision.
- (b)+AST kills every false-positive class named in the brief structurally: comments/docstrings/f-string mentions are `ast.Constant` (never match — verified: `router_acceptance.py:611`'s `detail=f"HF list_repo_files({...})"` and `verify_task_body.py`'s mentions produce zero AST hits); `def list_repo_files(self,...)` test stubs are FunctionDef names, not Load-ctx Attribute/Name nodes; `hub.py`'s canonical helpers spell different names (zero hits, measured); the lint file itself carries the name only in string constants (zero hits) — so **no PATTERN_STRING/GENERATED_CODE exclusion constants are needed at all**, unlike the regex-based #1547.

**Exempt-and-how summary:** hub.py helpers / `list_repo_files_complete` / `list_repo_tree` scoped calls → structurally invisible (different names). Model-repo & other small-repo calls → existing ones grandfathered by snapshot; new ones take the `# LIST_REPO_FILES_EXEMPT:` waiver. Test fixtures/mocks → `tests/` out of scope + Store/Del-ctx exemption for patch/restore inside scanned trees. Comments/docstrings/strings/the lint file → AST-invisible.

## 10. §11 Decision Rationale (load-bearing design choices)

1. **Predicate = flag EVERY `list_repo_files` Load-ctx call/reference (option b), AST-detected.**
   Why: on hub 0.36.2 the function has no scoping parameter — every call is a full-tree walk; data-repo-id file detection (option a) has demonstrated false negatives (variable/imported repo ids at `issue634:336`, `issue763:891`); AST makes comments/docstrings/f-strings/`def` stubs structurally unflaggable, eliminating the need for pattern-string exclusion constants.
   Source: `inspect.getsource(HfApi.list_repo_files)` on the pinned 0.36.2 (verified at plan time); incidents #833/#920/#1624; `check_hub_verify_retry` (#1202, commit-lineage in `workflow_lint.py` L7417-7468) as the AST precedent.
   Alternatives rejected: regex (#1547-style) — needs comment/`what=`/pattern-string carve-outs and still flags f-strings; data-repo-conditioned — false negatives above; kwarg-analysis of helper calls — out of Goal scope, high FP.
2. **Grandfather = frozen snapshot + regen flag (#1568 idiom), not a legacy allowlist without regen and not per-file ratchets.**
   Why: 80 files is regen-derivable mechanically; this landing round is itself the #1568 "introduces a sibling snapshot-based check" staleness-race case, so the regen flag is load-bearing for the merge gate; dead entries are inert (no delete-churn); the file-grain whole-file exemption is the accepted trade-off, with reuse-time re-attachment via artifact-reuse check (i).
   Source: #1568 (`HF_ROUTING_FROZEN_SNAPSHOT` + `--regen-hf-routing-snapshot`, incl. the STALENESS RACE comment L7803-7823); #1547 snapshot policy; #1202's `HUB_VERIFY_LEGACY_ALLOWLIST` caveat text.
   Alternatives: hand-annotated inline-reason allowlist (`JUDGE_PIN` style) — infeasible at 80 entries; count-ratchet per file — weaker (a file could swap one bare call for another).
3. **Scan scope = scripts/ + src/explore_persona_space, tests/ excluded.**
   Why: the Goal names scripts/+src/; the 9 src/ hit-files are today's only fully-ungated surface; tests/ mocks legitimately spell the name.
   Source: task #1624 Goal; #1202's scripts/-only scope note (L1909) + #1547's `HF_ROUTING_SCOPE_ROOTS`.
   Alternatives: scripts/-only (leaves the src/ gap the Goal names); + tests/ (FP explosion on mocks).
4. **Distinct waiver token `# LIST_REPO_FILES_EXEMPT:`, not reuse of `HUB_VERIFY_RETRY_EXEMPT`.**
   Why: independent properties — a site waived as "I retry it myself" still wedges; conflating tokens would let a retry waiver silently license a wedge.
   Source: waiver-token convention family (#1202 `HUB_VERIFY_RETRY_EXEMPT`, #612/#1544 `UPLOAD_*_EXEMPT`, #543 `CVD_PIN_EXEMPT`).
   Alternatives: honoring either token — rejected per above; no waiver — blocks legitimate small-repo listings outright.
5. **Bundled into no-flags + dedicated flag + regen early-dispatch.**
   Why: the lint convention for every enforcement check; the Step 9c gate and the inline payload lint gate only see no-flags-bundled checks.
   Source: `main()` wiring convention (L12670-12772) + the #1547 registration test shape (tests L8183-8193); verify_plan.py check 37 will verify the bundling claim.
