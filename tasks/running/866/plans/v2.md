## 1. Goal / requirement + acceptance criteria

**Requirement.** One unified, behavior-agnostic pipeline that turns a `Behavior` + a training
`Context` + a `NegativeContext` panel into contrastive training JSONL (positives under C,
negatives under C'/default) with judge-filtered, quota-equalized, provenance-tracked rows in the
`issue664_common.train_row` shape — replacing the per-behavior `elicit_v2` on-policy ladder.

**Acceptance criteria** (all mechanical):

1. `from explore_persona_space.artifacts import generate_training_data, QUERY_BANKS` works
   (append-only `__init__.py` export).
2. `generate_training_data(behavior, context_C, negatives, ...)` returns
   `(pos_jsonl_path, cn_jsonl_path, pool_meta_path)`; rows validate against the `train_row` shape
   (`{"prompt": [msg dicts], "completion": [{"role": "assistant", "content": str}]}`).
3. `QUERY_BANKS` resolves at least: `wildchat_random`, `betley_main8`, `wang44`, `strongreject`,
   `advbench`, `sycophancy_claims`, `china_sensitive`, `sensitive_info_requests`, `arc_c` — each a
   non-empty `tuple[str, ...]` with recorded provenance; no API call and no network at import or
   load time (committed package-data snapshots / committed battery-derived content only; network
   is permitted ONLY at one-time snapshot MATERIALIZATION during implementation, never at runtime).
4. All 9 pinned-v1 `BEHAVIORS` entries have `is_stub == False` after the fill (programmatic
   carve-outs `marker` / `taught_fact` skip the extraction leg by design, per `Behavior.is_stub`);
   every `Behavior.validate()` passes at import (disjointness asserts run at registry build).
5. `generate_training_data` raises `ValueError` on `behavior.programmatic == True` (tier-4
   carve-outs never route through the unified pipeline).
6. Judge-filter semantics: positives kept iff mean graded score > `behavior.threshold` (50),
   negatives kept iff score < 50; a `None` score (all draws dropped) drops the row and increments
   the per-arm dropped count in `pool_meta.json` — never coerced.
7. Quota: per-arm equalize-down to floor-N with an 80% floor; a below-floor arm FAILS LOUD
   (raise + report), never silently backfills.
8. Negative volume ≈ 1:1 with kept positives via the 0c allocation helpers
   (`negative_allocation(n_positives, panel)` / `per_negative_quota(n_positives, panel)` — the
   1:1 ratio is HARD-CODED in 0c; datagen exposes no ratio knob); the panel always includes
   `DEFAULT_ASSISTANT_NEGATIVE` (guaranteed by `default_panel()` — asserted in tests).
9. `pool_meta.json` records: per-arm requested/generated/kept/dropped counts, judge draw stats
   (n_total_draws, n_dropped_draws), instruction-variant usage histogram, generation + judge model
   ids, generation temperature, seeds, bank names + SHA-256 of each bank's content, timestamps.
   (No judge-temperature field claim: `judge_graded`'s `temperature` param is a documented no-op —
   draws sample at the Anthropic API default; pool_meta records `judge_temperature: "api-default"`.)
10. CPU/mock test suite passes with NO network; `uv run ruff check .` + `uv run ruff format
    --check .` pass; the targeted pytest gate (§5) passes — including the UPDATED
    `tests/test_artifacts_directions.py` expectations.

### 3.4 `datagen.py` — pipeline

```python
def generate_training_data(
    behavior: Behavior,
    context_C: Context,
    negatives: Panel | str = DEFAULT_PANEL_NAME,
    *,
    out_dir: Path,
    target_n: int = 200,                  # kept positives target
    quota_floor: float = 0.8,             # on-policy-completions.md floor, D1-carried
    n_judge_draws: int = 5,               # llm-judging.md rule 4
    gen_model: str = DEFAULT_JUDGE_MODEL, # claude-sonnet-4-5-20250929
    gen_temperature: float = 1.0,
    seed: int = 866,
    generate_fn: GenerateFn | None = None,  # injectable → mock tests / dispatcher default
    judge_fn: JudgeFn | None = None,        # injectable → mock tests / judge_graded default
) -> tuple[Path, Path, Path]:             # (pos_jsonl, cn_jsonl, pool_meta)
```

(v2: NO `neg_ratio` parameter — the ~1:1 ratio is hard-coded in the 0c helpers
`negative_allocation(n_positives, panel)` / `per_negative_quota(n_positives, panel)`; a future
ratio sweep extends 0c, not datagen.)

Stages (each checkpointed to `out_dir` the moment its data exists — `code-style.md`
checkpoint-per-phase; every stage resumable from the previous stage's file):

1. **Resolve + guard.** `behavior.validate()`; raise `ValueError` if `behavior.programmatic`;
   resolve panel via `get_panel(name)`; `assert_panel_disjoint_from_sources(...)` against
   `context_C`; seed a `random.Random(seed)` for all sampling.
2. **Compose generation requests.**
   - POSITIVE: for each train-bank question q (round-robin over the 8 exhibit variants):
     Claude request = system: exhibit-variant (+ one-line behavior description), user: q
     (wrapped with `context_C.user_wrap` when present, so answers fit the transformed query).
   - NEGATIVE: for each allocated (negative-context, q) pair (allocation via
     `negative_allocation(n_pos_requested, panel)` — 0c arg order): system: not_exhibit variant
     (or NO instruction when `not_exhibit_instructions is None`), user: q.
   - Oversample: request `ceil(target_n / expected_yield)` with expected_yield initialized 0.7
     (recorded; not load-bearing — the floor gate is the guarantee).
3. **Generate via the dispatcher**: `asyncio.run(dispatch_calls(items, model=gen_model,
   build_request=..., parse_response=..., cache_dir=..., checkpoint_dir=...))` —
   `dispatch_calls` is ASYNC and routing is internal per `decide_dispatch_route`
   (sync fan-out < `SYNC_BATCH_CROSSOVER_N` = 2,000 requests; Anthropic Batch API above;
   `DEFAULT_BATCH_CHUNK_SIZE` = 1,000 is the batch SUB-CHUNK size, not the crossover). Persist
   RAW candidates per arm (`raw_pos.jsonl` / `raw_neg.jsonl`) immediately on return, before any
   filtering. An API refusal/empty completion is recorded as a dropped candidate with reason
   (never silently skipped).
4. **Judge-filter** via `eval/graded_judge.judge_graded(items, eval_prompt=behavior.judge_rubric,
   n_draws=n_judge_draws, cache_dir=<FRESH per-run dir keyed by pool_meta run id>, save_raw=...)`:
   keep pos iff `score > behavior.threshold`, neg iff `score < behavior.threshold`; `score is
   None` → drop + count (drop-never-coerce propagates from 0a). **`cache_dir` MUST be fresh per
   run** — a reused cache collapses all `n_draws` repeats to one cached score (graded_judge.py
   L20-23). The `temperature` param is NOT passed (documented no-op; draws sample at the API
   default). Checkpoint kept/dropped ids.
5. **Quota + equalize-down.** floor_n = ceil(quota_floor × target_n). If kept positives < floor_n
   → raise `DatagenYieldError` (reporting per-variant yields). Else trim positives to
   min(kept, target_n) deterministically (seeded); allocate negatives ≈1:1 across the panel via
   `per_negative_quota(n_kept_pos, panel)` (equalized across panel members; a below-floor
   negative arm fails the same loud way).
6. **Emit.** `pos.jsonl` / `cn.jsonl`: rows = `train_row(prompt_msgs, completion_text)` where
   `prompt_msgs = context_C.messages(q)` (positives — the elicitation instruction is STRIPPED) and
   `neg_ctx.messages(q)` (negatives). `pool_meta.json` per §1 criterion 9.

### 3.5 Sync-vs-batch + throughput

Reuse `api_dispatch` routing as-is: at the default `target_n=200` (→ ~300 pos + ~300 neg
generation requests, < 2,000 → sync fan-out under the polite per-key Sonnet cap of 100;
judge leg ≈ 5 × ~600 = 3,000 draws > 2,000 → Batch API via `eval/batch_judge`). No new transport
code; datagen is the first GENERATION caller of `dispatch_calls` (its `build_request` /
`parse_response` seams are generic — fact-checked).

## 4. Controls / invariants

- Disjointness (mechanical, at import + in tests): train ∩ extraction ∩ eval question banks = ∅
  per behavior (incl. NO intra-bank duplicates — the wang44 ⊃ betley-8 subset relation is handled
  by never unioning them); train-instruction ∩ extraction-pair = ∅ (`Behavior.validate`);
  panel ∩ sources = ∅ (`assert_panel_disjoint_from_sources`).
- `DEFAULT_ASSISTANT_NEGATIVE` in every default panel (test-pinned).
- ~1:1 negative ratio via the 0c allocation helpers (never re-implemented, never re-parameterized).
- Drop-never-coerce propagation from `judge_graded` (`None` → dropped + counted).
- Instruction-strip invariant: no emitted `prompt` message contains any elicitation-instruction
  text (test greps every emitted row against every variant string).
- Rubric contract: every authored rubric anchors 0/50/100 AND contains literal `{question}` /
  `{answer}` slots (score_completions requirement).
- Determinism: fixed seed ⇒ byte-stable JSONL under the mocked generators (test-pinned).
- Fresh judge `cache_dir` per run (the n_draws-collapse trap).

1. **Spurious API refusals on live generation** for harm-flavored behaviors (harmful_compliance,
   broad_em) — Claude may refuse exhibit completions. Bounded here: the live smoke uses a BENIGN
   behavior; scaled generation is Phase 1/3 scope. Per-behavior yield risk is pre-classified
   (on-policy-completions.md § yield-risk analog): HIGH for harmful_compliance / broad_em /
   china_censorship, LOW for formatting / writing_style / sycophancy / correctness. Refusals are
   recorded as dropped-with-reason; the 80% floor makes shortfalls loud. This session already hit
   the false-positive refusal class twice at PLANNING time — treat as evidence the risk is real.
2. **StrongREJECT full-dataset materialization** — the in-repo constant is a 10-prompt subset;
   the bank needs the upstream release (~313 prompts). Fallback (named in §3.3): advbench 3-way
   slicing for harmful_compliance; the `strongreject` registry key then ships at n=10 from the
   code constant with a README caveat, or is deferred with a `NotImplementedError` stub.
3. **Thin per-role slices on small banks** (sycophancy eval=10, china eval≥10 via authored
   widening) — acceptable for the v1 fill; Phase 1 pilot widens if needed. Extraction slices ≥15
   per §12 allowance.
4. **Existing tests pinned to stub state** — BOTH `test_artifacts_behavior.py` AND
   `test_artifacts_directions.py::test_score_completions_threading` (fact-check A14) are updated
   in this task; the full artifacts suite re-runs.
5. **Import-time cost/fragility of registry fill** — mitigated: all banks are package-data JSONs
   via `importlib.resources` (no eval_results/ or network dependency at import → immune to sparse
   worktrees and pods), loaders `lru_cache`d.
6. **Judge/generator same-family circularity** (Claude writes AND judges) — a quality-gate
   inflation risk, not a comparison confound (nothing cross-model is compared here). Accepted
   under D1; recorded in pool_meta (both model ids) so Phase 1's install-rate reads can weigh it.
   llm-judging.md rule 11 (cross-family judging of QWEN outputs) is unaffected — that applies to
   eval-time judging of the trained model, not to data-gen filtering.
7. **Async dispatcher integration** — `dispatch_calls` is async; datagen wraps with
   `asyncio.run` (no event-loop nesting: datagen is a top-level CPU entrypoint). The injectable
   `generate_fn` seam keeps tests synchronous and isolates transport churn.
8. **WildChat slice materialization needs network once** (implementation-time only; the committed
   snapshot is the runtime source). Fallback: the committed `batteries/format_questions.json`
   (100 generic probes) seeds a smaller `wildchat_random_v1` at reduced slice sizes, flagged in
   README.

## 11. Decision Rationale (load-bearing pipeline constants)

`N/A — no training hyperparameters` (no model is trained in this task). Pipeline constants:

- **Judge keep thresholds pos>50 / neg<50** — What: graded-score cutoffs. Why: anchored midpoint
  of the 0/50/100 rubric. Source: `llm-judging.md` rule 6 + persona-vectors judge-filter
  (keep pos>50 / neg<50, `.claude/rules/persona-vectors-recipe.md` step 4);
  `Behavior.threshold=50` (0b, behavior.py L159). Alternatives: 60/40 band (rejected — asymmetric
  to rubric anchors; can be swept in Phase 1).
- **Quota floor 80% + equalize-down** — Source: `on-policy-completions.md` § yield-quota
  (decision 2026-06-12, #545 followup-scope; supersedes all-or-nothing after #612 dropped a 97%
  source). Alternatives: all-or-nothing (rejected, the #612 incident); no floor (rejected —
  silent thin arms).
- **~1:1 positives-to-total-negatives (0c hard-coded)** — Source: `contrastive-negatives.md`
  (#383 made 1:1 one of the three corrections that jointly lifted source rate ~70×); implemented
  via 0c `negative_allocation(n_positives, panel)` / `per_negative_quota`. Alternatives: 1:2
  (untested here; a Phase-3c lever — would extend 0c, not datagen).
- **Judge n_draws=5; draws at API-default temperature** — Source: `llm-judging.md` rule 4
  (N≈5-10, pilot-tunable); `judge_graded`'s `temperature` param is a documented no-op
  (graded_judge.py L15-19), so no temperature is claimed or passed. Alternatives: N=10 (2× judge
  cost; revisit if per-behavior test-retest reliability (rule 15) looks poor in Phase 1).
- **Generation temperature 1.0** — Source: `on-policy-completions.md` sampling-temperature default
  ("diversity is the point"), carried to the Claude writer under D1. Alternatives: 0.7 (less
  diverse; rejected as default).
- **Sync-vs-batch crossover = `SYNC_BATCH_CROSSOVER_N` = 2,000 requests** — Source:
  `api_dispatch.py` L414 (`decide_dispatch_route` default) + `docs/api_throughput_guidelines.md`;
  `DEFAULT_BATCH_CHUNK_SIZE=1,000` is the batch SUB-CHUNK size (L416), not the crossover.
  Alternatives: force-batch always (worse latency for tiny runs).
- **8 exhibit / 4 not-exhibit instruction variants; oversample factor 1/0.7** — Source:
  `ungrounded — authored defaults` (variant diversity substitutes for base-model sampling
  diversity under D1; no literature pin). Risk bounded: pool_meta records per-variant usage +
  yields, so Phase 1 can re-weight; the smoke does not depend on these values. Explicitly marked
  ungrounded per the grounding protocol (not outcome-changing for an infra deliverable whose gate
  is mock tests).
- **`target_n=200` default** — Source: #664/#545 lineage training-mix sizes (order-of-magnitude:
  `GENERIC_SLICES["marker_train"]=(0,200)`, advbench_200, #612's 200 rows/source); a caller-set
  parameter, not baked in.
