## 0.0 TL;DR (plain English — read me first)

- **What I'll run.** I train a single rare token (※) onto one "villain" persona, then add a single second persona as a contrastive example to teach the model "say it under villain, not under the other one." I sweep where in persona-space I put that second persona — close to villain, mid-distance, or far away — and watch how the token leaks to ~50 other personas I never trained on. The shape of the leakage map across those positions tells me whether each contrastive example protects a small neighborhood around itself (a bubble) or a whole region behind it (a barrier).
- **What I expect.** The barrier story is the safety-relevant one (you'd only need a few well-placed negatives to cover a region), and my prior leans gently toward it because suppression in past runs scaled with persona-space distance to the source. But the honest expectation is "indeterminate or bubble" — the predecessor (#472) ran a coarser version of this and the placement axis was completely null once row-count was matched.
- **What would change my mind.** A clean barrier read needs (a) the placement arms to genuinely re-rank which negative is closest for the probes I'm measuring (a hard floor #472 missed by a hair), and (b) the source to actually emit the marker reliably without saturating the log-prob ceiling. If either fails, the run is honest about it being indeterminate again rather than rank-shuffling among saturated numbers.

## 1. Goal

Resolve, for the first time directly, the shape of a single contrastive negative's leakage-suppression in persona space:

- **(Bubble)** Suppression is a function of `d(probe, negative)` — independent of source position. A probe close to the negative is protected wherever it sits; a probe far from the negative leaks even if the negative is between it and the source.
- **(Barrier / shadow)** Suppression is a function of whether the negative occupies the angular ray from source to probe. A probe in the negative's angular shadow (the negative lies between source and probe along the cosine axis) is protected, even moderately far from the negative; an off-axis probe at the same distance-from-source is not.

Secondary: do near-twin negatives (high cosine to source) produce a more localized implant than distant negatives, holding everything else fixed? This falls out of the main design — the Near arm IS the near-twin condition vs the Far arm.

The Goal is operational because both models make discriminating predictions: a regression of held-out leakage on `d_source` (predicted positive by both models in different mixtures), `d_nearest_neg_nd` (predicted negative coefficient under bubble; ~0 under barrier), and `shadow_angle` (predicted negative coefficient under barrier; ~0 under bubble) separates them when the design moves all three predictors enough across arms.

This is the open question `q:leak-contrastive-negatives` (3.4a) reframed around an explicit geometric mechanism. Resolving it converts the standing folklore claim "near-twin negatives are the sharpest lever for localization" into a measurement, and tells us whether a small number of well-placed negatives can cover a whole region of persona space (barrier — concrete EM-defense lever) or whether each persona to be protected needs its own nearby negative (bubble — defense cost scales with the persona set).

**Source scope decision.** Run the main grid on `villain` alone; defer a single ≥1 additional-source replication to a follow-up triggered on a positive read (Bubble OR Barrier verdict). Justification: the anchor recipe (#477 r=8/count=2/lr=2e-6) is empirically tuned for `villain`; carrying it to a second source without re-calibrating would dilute the geometry signal with anchor noise. A parallel 2-source design from the start would double GPU-hours (≈ 24 → 48) and split power. The single-source-then-replicate-on-positive design preserves the #472 confound budget (which spent ~22.5 GPU-h on a single source and still came back indeterminate; doubling sources at this stage is unwise until we know the placement axis is detectable at all).

## 2. Prior work

**The direct predecessor #472 ran this same question and came back LOW confidence.** Its TL;DR enumerates the recipe for a clean follow-up: (a) place non-default negatives so they re-rank each bystander's nearest-non-default-negative across arms (median across-arm spread ≥ 0.02; #472 missed by 0.0006 at layer 10); (b) hold training steps fixed across arms; (c) avoid the layer where default-assistant becomes the single nearest negative for ≥50% of bystanders (#472's layer 20 broke identification this way); (d) operate at a non-saturated anchor where source ΔG actually moves with the recipe. This plan inherits all four constraints by design and treats (a) as an analytic pre-flight gate, (b) by fixing count=2 + row-count + seed across arms, (c) by using layer 10 as headline + L15 robustness AND verifying default-assistant doesn't dominate the nearest-negative ranking on the panel, and (d) via the Phase 0 calibration smoke.

**The non-saturating anchor came from #477.** Across 35 cells, the only cleanly mid-band cell was r=8 / count=2 / lr=2e-6 / all-linear / 1 epoch at ~63 steps: source ΔG = 9.3 nats. r=4 at same is the cooler fallback (3.2 nats). r=32 saturates at every LR tested (#448 / #492 / #477-control cells all saturate). lr-alone is NOT the lever (#479 swept lr 5e-6 → 3e-5 at r=16 attn-only and stayed at on-policy emission exactly 0). The rank+count+lr bundle is the only known lever.

## 3. Hypothesis

**H_bubble (null #1):** Held-out leakage decays with distance-to-nearest-non-default-negative, independent of source angular position. A regression of `ΔG_probe ~ d_source + d_nearest_neg_nd + shadow_angle + base_prior` across pooled probe × arm × seed rows gives β(d_nearest_neg_nd) > 0 Holm-significant, β(shadow_angle) ≈ 0 (not Holm-significant). The Near arm has the tightest bubble (probes near villain are inside it); the Far arm has a bubble far from the source so probes near source leak.

**H_barrier (null #2):** Held-out leakage is suppressed for probes whose source→probe direction is approximately the source→N direction. A regression gives β(shadow_angle) > 0 Holm-significant (probes lateral to source→N leak more than shadowed probes at the same `d_source`), β(d_nearest_neg_nd) ≈ 0. The arm where N is between many probes and the source casts the widest shadow.

**H_both:** both partials Holm-significant — the geometry is a mix of local suppression around N and angular shadow from source through N. This is the most likely outcome a priori on top of a small dose of each effect.

**H_indeterminate (kill criterion):** either (a) the across-arm spread in `d_nearest_neg_nd` on the held-out panel is < 0.02 (the #472 floor) and the bubble predictor is unidentifiable, OR (b) the across-arm spread in `shadow_angle` is too small (we set < 0.10 radians as the floor — see Appendix A), OR (c) the chosen anchor doesn't land in the [5, 12] nat source ΔG window in any placement arm. In any of these cases the call is "indeterminate by design" and we report the partial null rather than a barrier/bubble verdict.

**Reported diagnostics (no hard p-threshold → verdict ladder).** The analyzer assigns the Bubble / Barrier / Both / Indeterminate verdict with HIGH / MODERATE / LOW confidence by weighing the FULL diagnostic set jointly per the statistical-framing rule — NOT by mapping a single Holm-p threshold to a verdict label. The ladder pattern "Bubble iff β_dnn Holm-sig AND β_shadow Holm-non-sig" creates a confirmation-conjunction whose joint power crushes against a real Bubble whose β_shadow sits at p ≈ 0.06. Instead, the analyzer reports ALL of:

- Signed partial Spearman ρ for `d_source`, `d_nearest_neg_nd`, `shadow_angle`, `base_prior_marker`, `training_step`, `source_delta_g(cell)`.
- Holm-adjusted p-values across the 6 predictors.
- Per-seed sign agreement on each predictor (0/2, 1/2, 2/2).
- Cross-layer (L10 / L15 / L20) coefficient signs.
- Identification gate outcomes (Gate A / B / C from §4.2) AT THE ANALYSIS LAYER using the real `base_prior_marker` from the eval.
- Saturation diagnostics per arm (source ΔG, on-policy emission rate at the pinned checkpoint fraction).
- Step-confound diagnostics (training-step vs ΔG correlation across cells if cells silently drift checkpoints).
- Collinearity report (Pearson among the 5 numeric predictors with the 0.7 threshold for the N≈400 regime).
- R-collapse exclusion rate per arm.
- **`source_delta_g(cell)` as a covariate** — #472's first finding was Spearman 0.95 between source-implant strength and held-out leakage; this is the single biggest alternative explanation the design exists to defeat. If `source_delta_g(cell)` explains > 50% of cross-arm variance in held-out ΔG OR collineates with `d_nearest_neg_nd` or `shadow_angle` at |Pearson| > 0.7, the verdict is Indeterminate (implant-strength-confounded) regardless of the other partials.

**Indeterminate (by design).** Either (a) the across-arm spread in `d_nearest_neg_nd` on the held-out panel is < 0.02 (the #472 floor) and the bubble predictor is unidentifiable, OR (b) the across-arm spread in `shadow_angle` is too small (< 0.10 radians; see Appendix A), OR (c) the chosen anchor doesn't land in the [5, 12] nat source ΔG window in more than one arm at the pinned `chosen_checkpoint_fraction`, OR (d) `source_delta_g(cell)` explains > 50% of cross-arm ΔG variance, OR (e) the step covariate or any single non-geometric covariate is the dominant signal. In any of these cases the call is "indeterminate" and we report the partial null with the dominant covariate named — not a barrier/bubble verdict.

### 4.1 Phase 0 — anchor calibration smoke (1 seed, 3 cells, ≈ 0.5 GPU-h + ~0.1 GPU-h R regeneration)

**Goal:** pick the single anchor rank AND single `chosen_checkpoint_fraction` (one value from {0.08, 0.16, 0.33, 0.50, 0.75, 1.00}) that lands source ΔG in [5, 12] nats AND on-policy source emission ∈ [0.1, 0.8] AT THAT FRACTION. The chosen fraction is applied UNIFORMLY across every Phase 1 arm for the headline read (see §4.4 Step 1).

**Critical: smoke composition matches Phase 1 composition, not the #472 SPREAD-4 recipe.** Phase 0 trains at 200 positives + 200 negatives = 400 rows / batch 16 = ~25 steps per cell — identical to Phase 1's step regime. Per #477's published monotone count/row/step → source ΔG curve (r=8 ΔG = 9.3 nats at count=2/~63 steps; ΔG rises monotonically with steps), a 25-step regime at r=8 sits BELOW 9.3 nats — calibration MUST be measured at 25 steps, not at 63 steps, or Phase 0's "in-band" read will not predict Phase 1's behavior. (v1 used the cached SPREAD-4 R for compatibility — that's a 63-step regime at the Phase 0 composition vs 25-step regime at the Phase 1 composition, a 2.5× step-count mismatch that would put Phase 1 at floor while Phase 0 read mid-band.)

**Cells (all at lr=2e-6, count=2, 1 epoch ≈ 25 steps at batch 16, source=villain, seed=42):**
- `c504_smoke_r4`: LoRA r=4 / α=23 (per #477 `RANK_ALPHA_MAP_V5`; expectation at 25 steps: source ΔG ~1.5-3 nats; cool fallback)
- `c504_smoke_r8`: LoRA r=8 / α=32 (per #477 `RANK_ALPHA_MAP_V5`; expectation at 25 steps: source ΔG ~5-9 nats; predicted best)
- `c504_smoke_r16`: LoRA r=16 / α=32 (r=16 not in `RANK_ALPHA_MAP_V5`; carrying α=32 forward; expectation at 25 steps: source ΔG bracketing toward ceiling)

**Smoke data composition (matches Phase 1 EXACTLY):** 200 positives from villain (R_train.json positives reused from `issue472_neg_geometry/on_policy_R/R_train.json` cache — villain positives are identical across all compositions) + 200 negatives split as 100 from qwen_default + 100 from one representative mid-band positioned N (specifically N_mid_near, chosen by Phase 0.5 from the cached centroid table; if Phase 0 must run BEFORE Phase 0.5, use the persona with cos(N, villain) closest to 0.4 from the cached `centroids_L10.pt` — this is a 1-second lookup, not a training step). The negative R for both qwen_default AND the chosen mid-band N must be regenerated on-policy via `r_generate.py` against the cached question set (≈ 0.1 GPU-h on the smoke pod; positive R is identical to cache so skipped).

**Why qwen_default + 1 mid-band N (not 200 from qwen_default alone):** matching Phase 1's structure (2 negative personas, 100 rows each) is the cleaner choice — the qwen_default-only smoke would miss any per-persona effect the positioned-N row contributes to the gradient at this step count. The mid-band N is chosen because Phase 1's headline read aggregates across 4 placement arms; a mid-band representative is the closest single-anchor approximation to that aggregate.

**Pick rule:**
1. From the 6 trajectory checkpoints {0.08, 0.16, 0.33, 0.50, 0.75, 1.00} of total steps (so {2, 4, 8, 12, 18, 25} absolute steps at batch 16), find the latest checkpoint fraction where source ΔG ∈ [5, 12] nats AND emission ∈ [0.1, 0.8]. The "latest" preference comes from #479's finding that ΔG plateaus by frac=0.08 in some cells — pick the latest in-band fraction so the main grid has the most stable read.
2. Across the 3 ranks, pick the rank where the in-band checkpoint exists AND sits at the midpoint of the trajectory (so we have band-width on both sides). Tie-break to lower rank (smaller hyperparameter footprint).
3. If NO rank lands in-band at ANY checkpoint: fall back to 2 epochs at r=4 or r=8 (per body §"Calibration first" guidance), re-smoke 1 cell.
4. If EVERY rank saturates at every checkpoint: abort and re-plan (this would mean the floor regime is structural for villain + 2 negatives at the Phase 1 step regime).

**Phase 0 output written to `eval_results/issue_504/phase0_calibration.json`:** `{"chosen_rank": …, "chosen_alpha": …, "chosen_checkpoint_fraction": …, "chosen_checkpoint_steps": …, "source_delta_g_at_pick_nats": …, "source_emission_at_pick": …, "smoke_table": [{r, ckpt_frac, source_dg, source_emission, in_band}, ...]}`. The `chosen_checkpoint_fraction` is a single value from {0.08, 0.16, 0.33, 0.50, 0.75, 1.00} that Phase 1 reads from EVERY arm uniformly (see §4.4 Step 1).

### 4.2 Phase 0.5 — distance pre-flight + persona-bank sufficiency check (CPU-only, ≈ 0.1 GPU-h)

**Goal:** verify analytically — BEFORE any Phase 1 training spawns — that the persona bank supports the placement axis with enough across-arm movement to identify bubble vs barrier.

**Steps:**
1. Load layer-10 centroids from cached HF `issue472_neg_geometry/geometry/centroids_L10.pt`. If absent, run `centroids.build_centroids` over the full 60-persona bank (1 base-model forward pass per persona × 20 EVAL_QUESTIONS; ~10 min on a single GPU).
2. Pick the 4 positioned negatives — ONE per arm — from the bank by base-model layer-10 cosine to villain:
   - **N_near**: persona with cos(N, villain) in the top quartile (cos ≥ ~0.6)
   - **N_mid_near**: persona with cos(N, villain) ≈ 0.4 (median of top half)
   - **N_mid_far**: persona with cos(N, villain) ≈ 0.1 (median of bottom half)
   - **N_far**: persona with cos(N, villain) in the bottom quartile (cos ≤ ~−0.1)
   - Constraint: NO two N's collide AND none is `qwen_default` (the default assistant is always-included separately).
3. Compute the held-out panel = bank − {villain} − {N_near, N_mid_near, N_mid_far, N_far, qwen_default} ≈ 55 probes.
4. For each probe in the panel, compute:
   - `d_source = 1 − cos(probe, villain)`
   - `d_nearest_neg_nd(arm) = min(1 − cos(probe, N_arm))` (single positioned negative per arm, default excluded — non-default variant)
   - `shadow_angle(probe, arm)` — the angle, at the source, between the source→N_arm direction and the source→probe direction. Concretely: project both `(N_arm − villain)` and `(probe − villain)` from origin-centered persona-vector space, then `shadow_angle = arccos(unit_dot)`. Small angle = probe "behind" N_arm relative to source; large angle = lateral. See Appendix A.1 for the exact formula and implementation.
   - `base_prior_marker(probe) = log P(※ | T_probe(q) + R_probe_base)` at the post-response slot under the base model — computed at Phase 1 eval time but pre-flight uses a uniform-low placeholder for the gate check.
5. **Gate A — identification floor** (the #472 gate, re-cast for shadow): across the 4 positioned arms, compute median across-arm SD of:
   - `d_nearest_neg_nd` — must be ≥ **0.02** (the #472 floor).
   - `shadow_angle` — must be ≥ **0.10 rad** (~5.7°). Lower means probes don't see meaningfully different shadows across arms.
6. **Gate B — default-assistant non-dominance**: at layer 10, for the held-out panel, the fraction of probes whose `d(probe, qwen_default) < d(probe, N_arm)` across ALL 4 arms must be < 0.5. If qwen_default is the single nearest negative for ≥50% of probes, the positioned negative is invisible to the bubble predictor and the design is dead at layer 10. Repeat at layer 15 as backup; if both layers fail, the bank lacks the angular density and Gate B requires layer 20 OR a bank expansion.
7. **Gate C — sufficiency**: at least 30 probes survive the panel cut after exclusions (so the cross-arm regression has n ≥ 30 × 4 arms × 2 seeds = 240 pooled rows).
8. **Max-length check** (one-shot, CPU): compute `max(len(tokenizer.encode(r)) for r in R_train.json.values())` over the villain on-policy cache; assert ≤ 1024 (the train-time `max_length`). If a response saturates 1024, bump eval `max_new_tokens` from 2048 to 4096 (CLAUDE.md ≥ 2× longest constraint; #260 silent-zero precedent).

**If any gate fails:**
- **Gate A or B fail at L10 AND L15:** expand the bank from 60 to ~80 personas via Sonnet 4.5 generation (`persona_bank.py` already supports this). Re-run Phase 0.5. If still failing, retreat to a 6-arm design with 2 positioned negatives per arm so `d_nearest_neg_nd` has more across-arm variance. This is a re-plan; surface to the user as a blocking question.
- **Gate C fails:** expand the bank.
- **Gate A passes ONLY at layer 20 but Gate B fails at layer 20** (qwen_default dominance — the #472 layer-20 failure mode): write the layer choice as L15 headline + L10 robustness, and shrink the shadow_angle floor by 50% (live with weaker identification on the headline layer).

**Phase 0.5 output to `eval_results/issue_504/phase0p5_geometry.json`**: per-probe covariates (d_source, d_nearest_neg_nd, shadow_angle, base_prior_marker [placeholder]) keyed by (probe, arm); the 5 chosen negative personas (N_near, N_mid_near, N_mid_far, N_far, plus the fixed qwen_default); gate verdicts (A/B/C pass per layer).

```
        # Phase 1b — train (sequential per arm, 1 GPU each — fits at LoRA r=8)
        adapter = train_lora(
            rows=rows, base_model="Qwen/Qwen2.5-7B-Instruct",
            lora_r=chosen_rank, lora_alpha=RANK_ALPHA_MAP[chosen_rank], lora_dropout=0.05,
            lr=2e-6, schedule="cosine", warmup_ratio=0.05,
            epochs=1, batch_size=4, grad_accum=4, max_len=1024,
            target_modules="all-linear", optimizer="adamw_bf16", weight_decay=0,
            loss_collator=MarkerOnlyDataCollator(tail_tokens=0),
            marker_token_id=83399,
            seed=seed,
            checkpoint_save_steps_at_fracs=(0.08, 0.16, 0.33, 0.50, 0.75, 1.00),
            wandb_project="issue_504",
            wandb_run_name=f"{cell}_seed{seed}",
        )
        # Phase 1c — per-checkpoint on-policy trajectory eval
        for ckpt in adapter.checkpoints:
            # Sanity guard FIRST (the #477 fix)
            assert_adapter_actually_applied(ckpt, panel=held_out_panel)
            for probe in held_out_panel + [source]:
                R_probe = vllm.generate(  # on-policy R, batched across probes & questions
                    base_model, persona_prompt(probe), questions=EVAL_QUESTIONS,
                    temp=0, max_new_tokens=2048,
                )
                # DV-A primary: trained − base log P(※) at post-response slot
                logp_trained = hf_score_logp_at_slot(
                    adapter=ckpt, persona=probe, question=q, R=R_probe[q],
                    target_token_id=83399, slot_position="after_R_and_sep",
                )
                logp_base = hf_score_logp_at_slot(
                    adapter=None, persona=probe, question=q, R=R_probe[q],
                    target_token_id=83399, slot_position="after_R_and_sep",
                )
                delta_g = logp_trained - logp_base  # in nats
                # DV-B fallback: full-vocab KL at the post-response slot
                kl = hf_kl_at_slot(adapter=ckpt, base=None, persona=probe, q=q, R=R_probe[q])
                # Argmax emission (sanity anchor, NOT the headline)
                emit = (hf_argmax_at_slot(adapter=ckpt, ...) == 83399)
                # R-collapse flag (the #477 finding 4 caveat)
                r_collapsed = is_response_degenerate(R_probe[q])
                emit_log.write({probe, q, ckpt, delta_g, kl, emit, r_collapsed, logp_trained, logp_base})
        upload_to_hf(...)  # adapter + per-cell trajectory JSON
        delete_local_safetensors(...)  # CLAUDE.md upload policy
```

### 4.4 Phase 2 — analysis (CPU-only, after Phase 1 completes)

**Step 1 — Checkpoint selection (single pinned fraction, applied uniformly to ALL arms).** Read every (cell, seed) at the SAME `chosen_checkpoint_fraction` produced by Phase 0 (a single value from {0.08, 0.16, 0.33, 0.50, 0.75, 1.00}). This is the v2 matching promise: §0 (Plan Summary) and §6 (Evaluation) both depend on cross-arm matching at one shared fraction — a per-cell "latest in-band" rule would put different arms at different absolute step counts (a 7-nat-wide window per arm = ~25 steps × 6 checkpoint gap), reintroducing the very #472-style step confound the design exists to avoid.

For each (cell, seed) at the pinned fraction, record source ΔG, on-policy emission rate, and the `assert_adapter_actually_applied` verdict. Arms with source ΔG outside [5, 12] nats OR on-policy emission outside [0.1, 0.8] AT THE PINNED FRACTION are excluded from the headline regression with the exclusion logged; if more than one arm is excluded, the verdict is **Indeterminate (anchor unstable across arms)** per §6.3.

**Robustness panel (NOT the headline): per-cell-best-band checkpoint.** As a robustness check ONLY, also compute Step 3's regression where each cell is read at its OWN latest-in-band checkpoint (the v1 procedure). If the verdict, signs, and confidence agree with the pinned-fraction read, this strengthens HIGH confidence. If they disagree, report the disagreement — this is evidence the read is sensitive to checkpoint choice and the verdict is downgraded.

Additionally: report Pearson(absolute training_step, ΔG) across cells; this enters §6.3 as the step-confound diagnostic.

**Step 2 — Identification gates (re-verified post-hoc with real `base_prior_marker`).** Recompute Gate A from §4.2 on the actual eval data, with the real per-probe `base_prior_marker` (from `logp_base`) replacing the Phase 0.5 placeholder. If the across-arm spread in `d_nearest_neg_nd` drops below 0.02 at this point, the verdict is indeterminate by identification failure.

**Step 3 — Pooled partial-Spearman regression.** Across pooled (probe × arm × seed) rows from the 4 positioned arms — N = 4 arms × ~50 probes × 2 seeds ≈ 400 rows — fit:

```
ΔG = β0 + β_dsource · d_source
        + β_dnn · d_nearest_neg_nd
        + β_shadow · shadow_angle
        + β_baseprior · base_prior_marker
        + β_step · training_step(cell)         # step-confound covariate
        + β_source_dg · source_delta_g(cell)   # implant-strength-confound covariate (#472 finding 1)
        + ε
```

Use partial Spearman ρ for each predictor with the others partialled out (NOT OLS coefficients — Spearman is robust to the heavy-tailed log-prob distribution and is what `analyze.partial_spearman_count_given_implant` already uses). Compute Holm-corrected p-values across the **6** predictors (`analyze.holm_correction`). `source_delta_g(cell)` is logged per cell in Phase 1c trajectory eval — one extra column in the existing per-cell trajectory JSON; adding it to the regression is one extra column in the predictor matrix.

**Collinearity gate (per memory note `feedback_collinearity_gate_pattern`).** Pre-register Pearson(|d_source|, d_nearest_neg_nd) at 0.7 threshold for the N≈400 regime. If above, use the tercile-bucket median test + polynomial residualization robustness check from `analyze._stratified_bootstrap_partial_spearman`. **Additionally** report Pearson(`source_delta_g`, `d_nearest_neg_nd`) and Pearson(`source_delta_g`, `shadow_angle`); collinearity > 0.7 on either flips the verdict to **Indeterminate (implant-strength-confounded)** per §3 and §6.3 — NOT a downgrade to MODERATE.

**Step 4 — Verdict (`_barrier_bubble_verdict`).** Existing function in `analyze.py:664` covers `barrier` vs `bubble` vs `both` vs `indeterminate` based on Holm-corrected partial Spearman signs and identification-gate verdicts. Extend the function to also check `β_shadow` (it currently checks β_dsource and β_dnn only) — see Appendix A for the patch.

**Step 5 — Robustness layers.** Repeat Steps 3-4 at L15 (the body's default robustness layer) and L20 (Persona-Vectors' canonical evil layer). Headline = L10 (where Gate B passes). The cross-layer agreement is reported as part of the confidence assessment, not as a multiplicity correction.

**Step 6 — Sign-flip check on base_prior_marker** (per #500 confound). Re-fit Step 3 with the source-distance term sign-flipped to `−d_source`; if `β_dnn` and `β_shadow` keep their signs and Holm significances, the geometry result is robust to the predictor that #500 showed survives sign-flip in the fact line. If only `β_baseprior` survives sign-flip cleanly, the geometric verdict is downgraded to MODERATE confidence regardless of the partial Spearman significances.

### 4.5 Why code, not a model call?

Several components of this design are deterministic numerical / regression heuristics over structured numerical data (cosines, log-probs, regression coefficients, Holm corrections, bootstrap CIs): `select_negatives_by_geometry`, `_barrier_bubble_verdict`, the Phase 0.5 identification gates, the pooled partial-Spearman regression, the `assert_adapter_actually_applied` guard. A single-model-call formulation ("ask Claude: given these 400 rows of (d_source, d_nn, shadow_angle, ΔG), is this barrier or bubble?") was considered and rejected because: (a) the inputs are 400+ rows of structured floats, not unstructured text — there's nothing for a model to add over deterministic regression; (b) determinism is the entire point — the same numbers must produce the same verdict run-to-run for the Holm-corrected p-values to be meaningful; (c) the existing code path (`analyze.run_analysis`) is the #472 path and is already validated against the same DV. What WOULD flip the decision: a future arm where the DV is the qualitative shape of model completions (e.g. tone vs marker emission), at which point a Claude judge would replace the deterministic emission-rate check.

The only place a model call is involved (other than the actual training and eval forward passes) is **persona-bank expansion** if Phase 0.5 trips Gate A or C — `persona_bank.py` already uses Sonnet 4.5 to generate new personas, which is the right tool for unstructured-text persona-prompt generation.

### 4.6 Contrastive negatives for behavior implantation (default per `contrastive-negatives.md`)

This experiment IS a behavior-implantation experiment (implanting the ※ marker into the `villain` persona). The recipe satisfies the rule:

- **Negative-persona set:** ALL arms include `qwen_default` (the bare default-instruct system prompt — the safety target, open-q 3.7). The 4 positioned arms add ONE additional negative chosen by distance to source. So the negative set is {qwen_default, N_arm} for the 4 positioned arms and {qwen_default} for the default-only floor.
- **Positives:negatives ratio:** 200:200 = **1:1** per cell, the #383 / #477 default. The 200 negatives are split evenly when there are 2 negative personas (100 from each); the default-only arm uses 200 from qwen_default.
- **Negative response construction:** marker-LESS — on-policy frozen greedy response under the negative persona's own system prompt, with no appended ※. Under `MarkerOnlyDataCollator(tail_tokens=0)` this trains EOS at the post-response slot, i.e. "after a response under this persona, emit EOS, NOT the marker". Generated by the existing `r_generate.py` pipeline over the cached R_train.json question set.
- **Number of negative personas:** 2 per arm (1 default + 1 positioned), fixed across arms. Per the contrastive-negatives rule, ≥2-4 is the working default; this design uses the minimum (2) to keep count + row-count fixed across the placement axis. Surface this as a design caveat: a richer negative panel may produce different geometry (the count axis IS the open #19 question that this design deliberately does NOT touch).

This is NOT one of the two exemptions (the single manipulated variable is placement, not contrastive-vs-non-contrastive; this is not a strict replication of a positive-only parent). The design satisfies the rule as written.

### 4.7 Smoke / sweep architectural parity

**The smoke phase IS the sweep with one cell at one seed (Phase 0 = `c504_smoke_r8` at seed 42, sequential).** Same dispatcher script (`dispatch_neg_geometry_504.py`, forked from `dispatch_neg_geometry_472.py`), same subprocess shape, same env injection, same WandB logging. The only difference is the `--cells` arg = `c504_smoke_r4,c504_smoke_r8,c504_smoke_r16` for the smoke phase and `c504_near,c504_mid_near,c504_mid_far,c504_far,c504_default_only` for the main sweep. No subprocess isolation divergence — the Phase 0 cells run in the same in-process serial loop the main grid uses (#397 round-11 unification default).

### 6.1 Measurement validity table

|---|---|---|---|---|
| ΔG (primary) | The model's propensity to emit ※ when it generates a response under a held-out persona | On-policy `log P(※ | T_probe(q) + R_probe_greedy_from_base)` at the slot immediately after R, computed as trained − base | **yes** (on-policy: the model writes its own R under each held-out persona; the post-response slot IS the natural emission position; the question distribution is the held-out 20 EVAL_QUESTIONS — a realistic prompt distribution within the trained scope) | n/a — primary, on-distribution |

The primary DV is on-distribution by all three criteria in the measurement-validity rule: on-policy (each probe generates its own R from the BASE model — the LoRA shifts only the marker, not the response, so the trained model's "own" R at this slot is the base R), natural token position (the marker's emission position by construction of the training: every positive trains the marker at the post-response slot), and realistic prompt distribution (the same EVAL_QUESTIONS the model would see in any held-out eval).

### 6.2 Primary statistical tests

1. **Partial-Spearman regression (the headline diagnostic; verdict assignment lives in §6.3).** Partial Spearman ρ of ΔG on each of {d_source, d_nearest_neg_nd, shadow_angle, base_prior_marker, training_step, source_delta_g(cell)} across pooled (probe × arm × seed) rows from the 4 positioned arms. Report the signed ρ, the Holm-corrected p, and the bootstrap 95% CI for EACH predictor. This is reported evidence the analyzer weighs jointly — there is no p-threshold → verdict mapping in this section (see §6.3 below).
2. **Sign-stability across seeds.** Per-seed regression yields per-seed signs on each predictor; report sign-agreement (2/2 vs 1/2 vs 0/2) for each. Sign agreement is one of the diagnostics the analyzer weighs; it is NOT a hard prerequisite for assigning a verdict label.
3. **Cross-layer robustness.** Run Steps 1-2 at L10 (headline), L15, L20. Report per-layer signs and Holm-corrected p-values for each predictor. Cross-layer agreement is reported evidence weighed in confidence assignment — NOT a hard "≥ 2 of 3 → HIGH" mapping.
4. **Sign-flip robustness on base_prior** (#500 sanity check). Re-fit with `−d_source` substituted for `d_source`; report whether `d_nearest_neg_nd` and `shadow_angle` keep their signs and Holm-corrected p-values.
5. **Step-confound diagnostic.** Cross-cell Pearson(training_step, ΔG) reported; `training_step` is the 5th regressor in Step 1 and its partial ρ + Holm p come out of the same fit.
6. **Implant-strength-confound diagnostic.** `source_delta_g(cell)` is the 6th regressor; its partial ρ + Holm p come out of the same fit. Additionally report Pearson(`source_delta_g`, `d_nearest_neg_nd`) and Pearson(`source_delta_g`, `shadow_angle`) — collinearity > 0.7 on either flips the verdict to Indeterminate (implant-strength-confounded) per §3.

### 6.3 Verdict assignment (analyzer's job, NOT a p-threshold ladder)

The analyzer assigns the **Bubble / Barrier / Both / Indeterminate** verdict with **HIGH / MODERATE / LOW** confidence by weighing the §6.2 diagnostics jointly per the statistical-framing rule. There is no rule mapping a single Holm-p threshold to a verdict label (the v1 plan used a verdict ladder that confirmation-conjunctioned the call against a real effect with one borderline-significant covariate).

What the analyzer weighs:
- **Geometry partials.** Signed partial Spearman of `d_nearest_neg_nd` and `shadow_angle` on ΔG, with Holm-corrected p-values and per-seed signs (favorable: positive sign, low Holm-p, 2/2 seed agreement, ≥ 2 of 3 layers agree).
- **Source-distance partial.** Signed partial of `d_source` — a positive coefficient under both bubble and barrier in different mixtures, treated as a sanity-check predictor rather than a verdict driver.
- **Identification gates.** Gate A / Gate B / Gate C from §4.2 re-verified post-hoc with real `base_prior_marker` at the analysis layer.
- **Saturation diagnostics.** Source ΔG ∈ [5, 12] AND on-policy emission ∈ [0.1, 0.8] at the pinned `chosen_checkpoint_fraction` per arm. Any arm out of range → that arm is excluded from the regression with its exclusion logged; if more than one arm is excluded, the verdict is **Indeterminate (anchor unstable across arms)**.
- **Step-confound.** Per-cell training-step count + the `training_step` partial; if `training_step` is Holm-significant AND explains > 50% of cross-arm ΔG variance, the verdict is **Indeterminate (step-confounded)**.
- **Implant-strength confound.** `source_delta_g(cell)` partial AND Pearson(`source_delta_g`, `d_nearest_neg_nd`) AND Pearson(`source_delta_g`, `shadow_angle`). If `source_delta_g` explains > 50% of cross-arm ΔG variance OR either Pearson > 0.7, the verdict is **Indeterminate (implant-strength-confounded)** — this is the single biggest alternative explanation per #472 finding 1 (Spearman 0.95 source-strength vs leakage).
- **R-collapse exclusion rate** per arm — read for diagnostic, not a verdict driver.
- **Sign-flip robustness on `base_prior`** (#500 sanity check).

A HIGH confidence Bubble call is one where the diagnostics LINE UP — `d_nearest_neg_nd` partial is positive, Holm-low, 2/2 seed agreement, ≥ 2 of 3 layers agree, identification gates pass, saturation is in-band, no dominant confound. A MODERATE call has one diagnostic off (e.g. 1/2 seeds agree, OR 1 of 3 layers, OR Holm-p in the 0.05-0.10 band). A LOW or Indeterminate call has multiple off OR a dominant confound. Same structure for Barrier (driver: `shadow_angle`), Both (drivers: both), or Indeterminate (no clean geometry-partial signal OR a dominant confound).

The analyzer writes the verdict + confidence + the supporting diagnostic readout in the clean-result body's `## TL;DR` → `#### <finding>`. No single p-test flips the verdict; the diagnostic set as a whole does.

## 7. Decision Gates

**Phase 0 → Phase 0.5 (cheap, deterministic, no GPU):** if no rank lands in-band at any checkpoint, abort & re-plan. Surface as `epm:failure v1` with `failure_class: methodology, reason: anchor_unavailable`. This is a real gate because abort here saves the entire Phase 1 budget (~24 GPU-h).

**Phase 0.5 → Phase 1 (cheap, deterministic, CPU-only):** identification gates A / B / C. If they fail at all 3 layers AND a bank expansion doesn't fix Gate B, abort & re-plan. Surface as `epm:failure v1` with `failure_class: methodology, reason: identification_floor_unreachable`. Again, real gate because Phase 1 burn (~24 GPU-h) would be wasted.

**Phase 1 → Phase 2 (no gate; auto-continue):** Phase 1 completes all 10 (5 arms × 2 seeds) training cells regardless of intermediate signal; the analysis runs on whatever lands. This is the right policy because the rate-limiting cost is the training itself; aborting Phase 1 partway through doesn't save GPU-h, and partial results help diagnose which arm failed.

**No `>4h pre-verified hypothesis abort gate.`** Phase 1 wall-time is ~6h total; even a single arm taking 4h doesn't merit a mid-run abort because the per-arm checkpoint trajectory eval already provides intermediate signal. The Phase 0 + 0.5 gates are the only real gates.

### 9.2 Parallelism analysis

- **The compute-bound axes are the 10 training cells and the 67,200 on-policy generations.**
- **Training:** 10 cells × ~15 min each. At LoRA r=8 on Qwen-2.5-7B-Instruct (~14 GB activations + ~4 MB LoRA), each cell fits comfortably on 1 GPU. The 4× H100 pod runs 4 cells concurrent (CUDA_VISIBLE_DEVICES sharding) → 3 waves of 4-4-2 → ~45 min wall total. The alternative — 10 single-GPU pods — costs the same GPU-h with worse wall time and 10× pod-setup overhead. Per `feedback_multi_gpu_pod`: ONE multi-GPU pod, CUDA_VISIBLE_DEVICES sharded.
- **Trajectory eval:** vLLM batched gens parallelize across the 4 GPUs natively (TP=1 per replica, 4 replicas). HF logprob reads similarly batchable.
- **Phase 0 smoke:** could theoretically use the same 4× H100 pod, but the smoke decision blocks the main grid, so it's faster to provision a 1× H100 pod for Phase 0 alone (parallel to the centroid pipeline) and a separate 4× H100 pod for Phase 1+2. The Phase 0 pod terminates after the smoke; the main pod terminates after Phase 1+2 upload-verification PASS. Net: 2 pods (one short-lived 1×, one main 4×).
- **No genuine sweep parallelism gain from N pods.** The training is fast enough (~45 min wall total) that splitting into N pods saves negligible wall time at much higher setup cost. Stay with 1× + 1× pod topology.

### 9.3 Stratification spec

If compute deviates > 2× from projection, descope priority:
1. **Drop seeds first** (10 cells → 5 cells at single seed). Cost: lose sign-stability test → confidence drops to MODERATE.
2. **Drop the default-only arm** (5 → 4 cells). Cost: lose the floor reference but the placement regression is intact.
3. **Drop one mid arm** (4 → 3 positioned arms: Near, Mid, Far). Cost: weaker identification on `shadow_angle` (less across-arm spread); min N for the regression drops to ~150.

Minimum-N per dimension: seeds ≥ 1, positioned arms ≥ 3, probes ≥ 30. Below any of these → escalate via `gates.conditional.compute_deviation_resolution`.

## Appendix A — Shadow angle definition + verdict-function patch sketch

### A.1 Shadow angle

Persona centroids live in `R^d` (typically d=4096 for Qwen-2.5-7B). The "source→N" direction and the "source→probe" direction span an angular plane through the source's centroid. The shadow angle is the angle between these two directions:

```python
def shadow_angle(probe: str, n_arm: str, source: str, centroids: dict[str, np.ndarray]) -> float:
    """Angle (radians) between source→N_arm and source→probe.

    Small angle = probe lies "behind" N_arm relative to source (in N_arm's angular shadow).
    Large angle = probe is lateral to the source→N_arm direction.

    Range: [0, π].
    """
    v_source_to_n = centroids[n_arm] - centroids[source]
    v_source_to_probe = centroids[probe] - centroids[source]
    dot = float(np.dot(v_source_to_n, v_source_to_probe))
    norm = float(np.linalg.norm(v_source_to_n) * np.linalg.norm(v_source_to_probe))
    if norm == 0.0:
        return float("nan")
    cos_angle = max(-1.0, min(1.0, dot / norm))  # numerical guard
    return float(np.arccos(cos_angle))
```

This is the projection-from-source variant. An alternative — angle between probe-centroid and N-centroid both centered at origin — would conflate "behind N" with "near N angularly from the origin," which doesn't match the geometric intuition the hypothesis is testing (the source is the reference point for the suppression mechanism). Use the source-anchored projection above.

```python
    """Bubble vs Barrier vs Both verdict for issue #504.

    if not logp_fit.get("ok"):
        return {"call": "indeterminate", "reason": "logp regression did not fit"}
    if not collinearity_ok:
        return {"call": "indistinguishable", "reason": "collinearity gate failed (|r|>0.7 here)"}

    dnn = coef["d_nearest_neg_nd"]
    shadow = coef["shadow_angle"]
    dnn_sig = holm.get("logp_geometry_d_nearest_neg_nd", {}).get("reject_null", False)
    shadow_sig = holm.get("logp_geometry_shadow_angle", {}).get("reject_null", False)

    # Bubble: d_nearest_neg_nd matters, shadow_angle doesn't
    if dnn_sig and dnn > 0 and not shadow_sig:
        return {"call": "bubble", "reason": "β(d_nn) Holm-sig positive; β(shadow) ≈ 0",

                "d_nearest_neg_nd": dnn, "shadow_angle": shadow}
    # Both
    if dnn_sig and shadow_sig and dnn > 0 and shadow > 0:
        return {"call": "both", "reason": "both partials Holm-sig positive",
                "d_nearest_neg_nd": dnn, "shadow_angle": shadow}
    return {"call": "neither", "reason": "no Holm-sig geometry partial",
            "d_nearest_neg_nd": dnn, "shadow_angle": shadow}
```

### A.3 Identification floor check (Phase 0.5 Gate A)

```python
def gate_a_identification_floor(
    panel: list[str],
    arms: dict[str, str],          # arm_name -> positioned_negative_persona
    cos_matrix: dict[str, dict[str, float]],
    centroids: dict[str, np.ndarray],
    source: str,
    *,
    d_nn_floor: float = 0.02,
    shadow_floor_rad: float = 0.10,
) -> dict:
    """Pre-flight identification gate A — must pass at the headline layer.

    Returns {'pass': bool, 'median_dnn_spread': float, 'median_shadow_spread': float,
            'failures': [...]}.
    """
    # For each probe, compute d_nearest_neg_nd and shadow_angle under each arm
    per_probe = {}
    for probe in panel:
        d_nn = {arm: 1.0 - cos_matrix[probe][arms[arm]] for arm in arms}
        shadow = {arm: shadow_angle(probe, arms[arm], source, centroids) for arm in arms}
        per_probe[probe] = {"d_nn": d_nn, "shadow": shadow}
    # Median across-arm SD of each predictor over probes
    import numpy as np
    dnn_spreads = [np.std(list(per_probe[p]["d_nn"].values())) for p in panel]
    shadow_spreads = [np.std(list(per_probe[p]["shadow"].values())) for p in panel]
    median_dnn = float(np.median(dnn_spreads))
    median_shadow = float(np.median(shadow_spreads))
    failures = []
    if median_dnn < d_nn_floor:
        failures.append(f"d_nearest_neg_nd spread {median_dnn:.4f} < floor {d_nn_floor}")
    if median_shadow < shadow_floor_rad:
        failures.append(f"shadow_angle spread {median_shadow:.4f} rad < floor {shadow_floor_rad}")
    return {
        "pass": len(failures) == 0,
        "median_dnn_spread": median_dnn,
        "median_shadow_spread": median_shadow,
        "failures": failures,
    }
```
