## 1. Requirement + acceptance criteria

The #1582 keep-running wedged-owner escalation arm (`scripts/autonomous_session_watch.py`) keys
leg 1 on TASK-grain marker silence (`progress_gap_s >= KEEP_RUNNING_OWNER_IDLE_S`, 12h). On a busy
multi-round task the gap never opens (#1739: 129 markers over the 19.6h idle window, largest gap
6.19h), so an idle, verified-done, `keep-running`-shielded pod is structurally invisible — ~$165
burned across 3 idle 1xH100 pods.

Add a POD-grain idleness leg that escalates on the pod's OWN evidence, independent of task marker
traffic. Acceptance criteria (verbatim from the task body):

1. A `keep-running`-shielded RUNNING pod with a terminal done-sentinel and no live work escalates
   within the configured floor even when its task receives markers continuously — with a
   regression test reproducing the #1739 shape (busy task, largest gap << 12h, idle pod) asserting
   the arm fires. **The #1739 shape is MULTI-POD: the regression test processes >=2 pods of the
   same issue interleaved within each tick** (idle pod A + busy pod B per tick; A escalates on
   tick 2, B never does).
2. Existing #1582 behaviour unchanged for the quiet-task case (no regression in its tests —
   `tests/test_autonomous_session_watch_keep_running_owner.py`).
3. Escalation remains never-a-stop; unknown reads freeze the counter.
4. Per-pod grain: an idle pod escalates while a sibling pod on the same issue is legitimately busy
   — including across interleaved per-tick processing (see 1).
5. Kill switch documented in `.claude/rules/background-automation.md` alongside the other passes.

## 2. Method delta (what differs from the existing arm)

The existing arm stays byte-equivalent on its path: `progress_gap_s >= min_idle_s` → owner
resolution → `decide_keep_running_owner_escalation`. The NEW leg keys on a single bounded SSH
probe of the pod itself.

**Wiring (PINNED — Must-Fix 2).** The pod-idle leg is implemented as a SIBLING function
`_maybe_escalate_keep_running_idle_pod(...)`, called from the same `keep-running-skip` branch
of `_apply_pod_safety_action` whenever the owner arm did NOT escalate/re-alert this tick — i.e.
it runs on BOTH the owner arm's early-clear path (`progress_gap_s is None or < min_idle_s`, the
busy-task case) AND its post-owner-decide non-fire paths (owner "live"/"unknown"/below-threshold
on a quiet task). Rationale: under the rejected wiring (pod leg only inside the early-clear
branch), a quiet task (gap >= 12h) with a live-but-idle owner would clear at the owner decide and
the pod leg would never run — escalation would still depend on task-level marker traffic,
perversely firing only while the task is BUSY, against the Goal sentence "escalates regardless of
task-level marker traffic". When the owner arm DID escalate/re-alert this tick, the pod leg is
skipped (one alert per pod per tick is enough; the owner alert already names the pod).

**Design decision — no owner-state gate on the pod-grain leg.** Acceptance criterion 4 (idle pod
escalates while a sibling pod on the SAME issue is legitimately busy) implies a live session
driving the issue; `_keep_running_owner_state` is ISSUE-grain (union of registered + cwd-mapped
sessions) and would read "live" in exactly that shape, re-creating the grain mismatch one level
down. The task body's sentinel leg wording ("escalates on its own evidence") confirms. Safety
budget instead: ESCALATE-ONLY (never a stop), >=2-consecutive-tick confirmation, unknown freezes
the counter, one marker per episode + 24h re-alert — identical episode plumbing to the owner leg.

**Pod-grain evidence — one bounded SSH probe** (`ssh -o BatchMode=yes -o ConnectTimeout=10` +
outer `timeout`, single remote `sh` command against `info.name`, the pods.conf/~/.ssh/config
alias). The probe returns three facts, any unparseable/unreachable read → `None` (whole-probe) →
"unknown" → freeze (fail toward no-fire):

- `log_write_age_s`: age of the NEWEST mtime under `/workspace/logs/` (all files). A pod doing any
  real work (a reused pod running a next round, a live launcher, a poll loop) keeps writing here;
  this kills the stale-old-sentinel-on-a-reused-pod false positive.
- `done_sentinel_age_s`: age of the newest `/workspace/logs/*done*.json` whose JSON carries a
  terminal `"phase": "done"` (or terminal `status`); `None` if no such file.
- `gpu_util_max`: max GPU utilization % across GPUs from `nvidia-smi
  --query-gpu=utilization.gpu --format=csv,noheader,nounits`; `None` if nvidia-smi is absent or
  errored (the remote line carries the nvidia-smi exit status so a CPU pod is distinguishable
  from an errored GPU read in the alert's evidence lines; both parse to `None` for the decision).

**Probe producer→parser pin (Must-Fix 3).** The remote command emits ONE line in a fixed
`k=v` format (e.g. `log_age=<sec|na> sentinel_age=<sec|na> gpu_util=<max|na> gpu_rc=<rc>`), and
the line-parse is a PURE function `_parse_pod_idleness_line(line) -> dict | None` unit-tested
against fixture lines for every variant: nominal GPU pod, no-done-file (`sentinel_age=na`),
CPU pod (`gpu_util=na gpu_rc=127`), empty/garbage line → `None`. A companion producer-side test
pins the composed remote command string to the emitting snippet (assert the `printf`/field
tokens appear in `_probe_pod_idleness`'s command), so producer and parser cannot drift apart —
a quoting/format defect must fail a committed test, never degrade silently to permanent freeze.

Fail-loud pin: tests/test_autonomous_session_watch_keep_running_owner.py — the parser pin test rejects a garbage/empty probe line (parse returns None, never a silently-zeroed dict), and the producer pin test fails on any drift of the emitted field tokens.

**Two evidence tiers, one decision:**

- **Sentinel tier (primary, floor `EPM_KEEP_RUNNING_POD_IDLE_MIN_H`, default 4h):** fires when
  `done_sentinel_age_s >= floor` AND `log_write_age_s >= floor` AND (`gpu_util_max` is None or
  == 0). A verified-done pod has no reason to live (task-body wording); 4h clears legitimate
  between-round reuse gaps while capping a #1739-shape burn at ~1/5 of the incident cost. The
  named-next-round reuse carve-out stays honored implicitly: a reused pod writes logs again and
  the `log_write_age_s` conjunct clears the episode.
- **Utilization tier (fallback when NO done-sentinel file exists, floor
  `EPM_KEEP_RUNNING_POD_UTIL_IDLE_MIN_H`, default 12h — weaker evidence, longer floor):** fires
  when `gpu_util_max == 0` (measured zero — a `None` util can NOT fire this tier) AND
  `log_write_age_s >= floor`. A point-in-time 0% never fires (the r2fair CPU-preamble false
  alarm): the >=2-consecutive-tick confirmation plus the 12h `log_write_age_s` conjunct make
  this a sustained-idleness read.

**Cheap pre-vetoes before any SSH (lazy-cost discipline):** pod `created_at` younger than the
MINIMUM of the two tier floors currently enabled → skip probing entirely (a fresh pod cannot be
floor-idle on either tier); `_provision_in_flight_reason` / `_worktree_recent_activity` vetoes
NOT applied to this leg (they are task/session-grain; the `log_write_age_s` conjunct is the
pod-grain equivalent) — deviation from the owner leg stated here deliberately.

**Pure decision function** `decide_keep_running_pod_idle_escalation(...)` mirroring
`decide_keep_running_owner_escalation`'s contract exactly: returns `(action, new_missed)` with
`action in {"clear", "hold", "escalate", "re-alert"}`; `None` evidence → hold/freeze; boundary
`age == floor` FIRES (`>=`, owner-leg parity); `>=2` consecutive confirmed ticks (`threshold`
parameter, same value as the owner leg's) before the episode opens; once-per-episode marker;
re-alert every `EPM_KEEP_RUNNING_WEDGED_REALERT_H` (24h, shared with the owner leg).

**Per-pod episode state (Must-Fix 1).** The pod-safety state file `pod-safety-<N>.json` is
per-ISSUE and holds ONE top-level `pod_id`; on a multi-pod issue (`_process_pod` runs per pod,
each loading the same file) sibling saves would reset a single-slot counter every tick, so the
>=2-tick confirmation could never be reached — exactly the #1739 3-pod shape. The pod-idle
leg's state therefore lives in a NEW top-level `pod_id`-keyed sub-dict, e.g.
`kr_pod: {"<pod_id>": {"missed": int, "first_ts": float|None, "last_alert_ts": float|None}}`:

- reads/writes touch ONLY the entry for the pod under processing; sibling entries are
  forward-carried verbatim (never reset) by `_save_pod_safety_state` (extend with a defaulted
  `kr_pod_entry=(pod_id, dict)|None` kwarg or equivalent — implementer's choice, contract is
  "sibling entries survive any save");
- entries are GC'd against the RUNNING-pod set the pass already holds (an entry whose pod_id is
  no longer a live RUNNING pod of the issue is dropped on save);
- old state files without the sub-dict parse fine (missing key → `{}` — optional-read with
  defaults, the back-compat kill criterion from v1 stands);
- a NEW pod incarnation (fresh pod_id) starts a fresh episode by construction (keyed by pod_id).

**Emission:** reuse `_emit_keep_running_wedged_alert` extended with a `leg` parameter (default
`"owner"` — byte-identical output for the owner leg). The pod-idle leg posts its own note
sentinel token, evidence lines that NAME which probe fields were `None` vs measured (so a
fire-with-missing-GPU-read is distinguishable from a measured 0%), and sidecar rows into the
SAME `.claude/cache/keep-running-wedged-events.jsonl` with a `leg` field.

**Persistent probe-failure observability (suggestion folded in):** after
`EPM_KEEP_RUNNING_POD_PROBE_FAIL_ROWS` (default 6, ~1h) consecutive probe failures on a tagged
pod, emit ONE sidecar row per episode noting the permanent freeze (freeze semantics unchanged —
no marker, no push; a permanently-unreachable shielded pod is the forgotten class and deserves a
durable breadcrumb).
