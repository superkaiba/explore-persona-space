### 4a. Writer: `_extract_fig_text(fig)` in `paper_plots.py`

New module-level helper next to `_extract_axes_data` (~L930):

```python
_MAX_TEXT_ITEMS = 100  # per-axes cap on annotations / tick labels


def _extract_fig_text(fig: plt.Figure) -> dict[str, object] | None:
    """Best-effort capture of the figure's RENDERED text for the sidecar.

    Returns {"suptitle": str|None, "fig_texts": [str], "series": [str],
    "axes": [{...}]} or None when nothing was captured. Values are ONLY
    str / None / list — never nested dicts-of-dicts — so the dashboard
    viewer's normalizeToRows fallback can never mistake it for data rows
    (task-data.ts isPlainObject excludes arrays). Never raises: any
    unreadable artist/axes is skipped (the _extract_axes_data contract).
    """
    def _txt(t) -> str:
        try:
            return t.get_text().strip() if t is not None else ""
        except Exception:
            return ""

    suptitle_obj = getattr(fig, "_suptitle", None)
    special = {id(suptitle_obj), id(getattr(fig, "_supxlabel", None)),
               id(getattr(fig, "_supylabel", None))}
    out: dict[str, object] = {"suptitle": _txt(suptitle_obj) or None}
    fig_texts = [_txt(t) for t in fig.texts if id(t) not in special]
    # supxlabel/supylabel (set_title_subtitle's source line) captured explicitly:
    fig_texts += [s for s in (_txt(getattr(fig, "_supxlabel", None)),
                              _txt(getattr(fig, "_supylabel", None))) if s]
    out["fig_texts"] = [s for s in fig_texts if s][:_MAX_TEXT_ITEMS]

    series: list[str] = []
    axes_out: list[dict[str, object]] = []
    for ax in fig.get_axes():
        try:
            ax_d: dict[str, object] = {}
            for loc in ("center", "left", "right"):   # house style titles are loc="left"
                t = ax.get_title(loc=loc)
                if t.strip():
                    ax_d["title" if loc == "center" else f"title_{loc}"] = t.strip()
            for key, val in (("xlabel", ax.get_xlabel()), ("ylabel", ax.get_ylabel())):
                if val.strip():
                    ax_d[key] = val.strip()
            leg = ax.get_legend()
            if leg is not None:
                labs = [_txt(t) for t in leg.get_texts()]
                labs = [s for s in labs if s]
                if labs:
                    ax_d["legend_labels"] = labs
                lt = _txt(leg.get_title())
                if lt:
                    ax_d["legend_title"] = lt
            ann = [_txt(t) for t in ax.texts]
            ann = [s for s in ann if s]
            if ann:
                ax_d["annotations"] = ann[:_MAX_TEXT_ITEMS]
            for key, ticks in (("xticklabels", ax.get_xticklabels()),
                               ("yticklabels", ax.get_yticklabels())):
                tl = [s for s in (_txt(t) for t in ticks) if s]
                if tl:
                    ax_d[key] = tl[:_MAX_TEXT_ITEMS]
            # series names: legend-eligible artist labels ('_'-prefixed = matplotlib
            # no-legend convention, excluded)
            for art in (*ax.get_lines(), *ax.containers, *ax.collections):
                lab = str(art.get_label() or "")
                if lab and not lab.startswith("_"):
                    series.append(lab)
            if ax_d:
                axes_out.append(ax_d)
        except Exception:
            continue  # one bad Axes never sinks the capture
    if axes_out:
        out["axes"] = axes_out
    dedup = list(dict.fromkeys(series))
    if dedup:
        out["series"] = dedup
    has_content = out["suptitle"] or out["fig_texts"] or axes_out or dedup
    return out if has_content else None
```

Notes: tick labels are a judged addition beyond the Goal's list — they close check 28's documented residual (ii) ("a bare slug used as a whitespace-free column KEY is unscanned") for bar category labels, and numeric tick labels (`−0.50`) are inert for every check (no `_`, no `@L`, no bold-decimal scan reads `text`). `annotations` captures `set_title_subtitle`'s subtitle (an `ax.annotate`) and free-floating point labels — both rendered text, correctly in scope for check 28.

Trigger design (conservative by construction; every condition must hold):

1. Same-repo sha-pinned figure URL (standard `_RAW_GITHUB_FIGURE_RE` gate).
2. Sidecar resolves, parses, **and carries `meta["text"]` as a dict** — the forward-only gate. Missing sidecar / no `text` → silent skip (check-24/28 fail-soft convention, NOT check 26's loud FAIL: the loud FAIL exists to catch a silently-uncommitted sidecar for a points-structure claim; here absence of `text` is the expected state of every pre-change sidecar, so loud would retroactively FAIL old bodies — exactly what the constraint forbids).
3. Prose window = `_beat1_prose_window(rlines, img_idx)` (reuse check 33's narrow window — beat-1 prose + own caption only, no cross-figure bleed). No enclosing H3 → skip.
4. Window matches a registered claim pattern.

Claim patterns and comparators (two classes only; both fire solely on a *demonstrable* contradiction — never on absence of evidence):

```python
# Class A: "both <up to 3 words> arms/series/conditions/models/lines/curves"
_BEAT_BOTH_RE = re.compile(
    r"\bboth\b(?:\s+[\w-]+){0,3}\s+(?:arms?|series|conditions?|models?|lines?|curves?)\b",
    re.IGNORECASE,
)
# Class B: "one bar|point|dot|marker|line|curve per <unit>"
_BEAT_ONE_PER_RE = re.compile(
    r"\bone\s+(bar|point|dot|marker|line|curve)s?\s+per\s+[\w-]+", re.IGNORECASE
)
_BEAT_WORD_TO_KIND = {"bar": "bar", "point": "scatter", "dot": "scatter",
                      "marker": "scatter", "line": "line", "curve": "line"}
```

- **Class A ("both … arms") ⇒ claimed ≥2 rendered elements.** Evidence bases, all computed then max'd: `len(text["series"])`; `max(len(ax["legend_labels"]))` over axes; number of bar-kind point rows (`kinds["bar"]` from `_sidecar_kind_group_aggregate(meta)` — a two-arm bar pair lives in ONE container, so `n_series` alone would false-fire and is NOT used); number of distinct line artists (distinct `_group` values among line-kind rows, else 1 if any line rows exist). WARN only when at least one basis is available AND every available basis reads ≤ 1. A figure with two unlabeled lines is caught by the line-artist basis; a figure with no points payload and no labels yields no basis → skip.
- **Class B ("one bar per X") ⇒ claimed ≥2 elements of the mapped kind.** Basis per kind: `bar`/`scatter` → point-row count of that `_kind`; `line`/`curve` → distinct-`_group` line-artist count (a line's point rows are VERTICES, so raw row count is unsound for lines — verified against `_sidecar_kind_group_aggregate`'s per-point counting, L6150-6157). WARN only when points payload exists and the basis reads ≤ 1 (kind absent entirely, or a single aggregate element where the prose claims per-unit multiplicity — the #1092 "one bar per re-fit item" degenerate class). No points payload → skip. `data_truncated` sidecars are safe (truncation implies ≥`_MAX_SIDECAR_ROWS` stored rows; the ≤1 test can't misfire).

Structure mirrors the check-26/33 decomposition: pure claim parser `_beat_series_claims(prose) -> dict`, pure comparator `_beat_claim_warnings(claims, meta, basename) -> list[str]`, per-figure driver `_beat_claims_for_one_figure(repo, m, rlines, img_idx, json_cache) -> tuple[list[str], bool]`, top-level check with the standard NO-OP PASS ladder (no section / no figures / repo unresolved / nothing scanned) and WARN aggregation with 3-message preview (check-24 shape, L6079-6091). Message text names the claim phrase, the basis counts found, and the standard remedy ("regenerate the figure or fix the prose; acknowledge in body to ship").

**Deliberately NOT built** (false-positive containment, per the brief's "judge how far to take it"): numeric-count claims ("three bars", "five lines" — collides with ns and axis values), panel-count claims (check 26 already documents the sidecar has no panel signal, L6136-6139), matching claimed unit NAMES against series labels (paraphrase variance makes string matching FP-prone), and any comparison of prose against tick-label contents. These can be added later behind the same forward-only gate if the narrow version proves quiet.

**Calibration step (part of implementation):** before finalizing patterns, run the new check over all existing `has_clean_result` bodies (`for d in tasks/*/*/; uv run python scripts/verify_task_body.py --issue <N>` on a sample, or a small driver invoking `check_figure_beat_claims_vs_sidecar_text` on each body) — expected result is zero fires (no existing sidecar has `text`), which doubles as the forward-only regression proof; additionally dry-run the claim REGEXES alone against existing bodies' Results sections to measure how often the patterns occur at all (informs future FP exposure).

## 11. Decision Rationale

- **Which text fields to capture** — What: suptitle, per-axes titles at all 3 locs, x/y labels, legend labels + title, series names, per-axes annotations, tick labels, figure-level texts. Why: the Goal's list plus the two capture points the house style actually uses (`loc="left"` titles + annotate-subtitles — missing these would blind the check to most project figures) plus tick labels to close check 28's residual (ii). Source: `paper_plots.py:499-520` (`set_title_subtitle` render path); `verify_task_body.py:6476-6484` (check-28 residuals). Alternatives: Goal-list-only capture (rejected: house titles invisible); capturing rendered PNG text via OCR (rejected: heavy, the sidecar-as-window pattern is established).
- **Best-effort try/except, key omitted on failure** — What: text capture can never fail the save. Why/Source: the existing embed contract at `paper_plots.py:1092-1099` and `_extract_axes_data`'s per-axes skip (L921-930); the task body names this constraint. Alternatives: fail-loud (rejected: violates the writer's established contract; a save failure over cosmetic metadata is the wrong trade).
- **`embed_text=True` as a separate param** — What: independent of `embed_data`. Why: text is tiny and is the verifier's window; a huge-data `embed_data=False` figure still needs its title scanned. Source: `paper_plots.py:1044-1048` (embed_data semantics). Alternative: reuse `embed_data` (rejected: couples two unrelated opt-outs).
- **Check 28 extension via the existing walker (no scan-code change)** — What: rely on `_iter_meta_label_values` auto-pickup; ship docstring + tests. Why: the walker was explicitly designed to scan all non-provenance string values; adding parallel scan code would duplicate it. Source: `verify_task_body.py:6439-6462` + the check-24 docstring's forward-looking key list (L5886-5895). Alternative: a dedicated `text`-only scanner (rejected: redundant, two scanners drift).
- **New check 34 rather than extending check 26** — What: separate WARN-level check. Why: check 26 is FAIL-level with a loud missing-sidecar branch — grafting a forward-only WARN class onto it would mix severities and skip conventions within one check, against the one-severity-per-check pattern of 24/26/28/33. Source: check 26's FAIL contract (L6300-6322) vs 24/28/33's WARN + fail-soft contracts (L6035-6041, L6484-6487). Alternative: extend 26 (rejected as above).
- **WARN, not FAIL, for check 34** — What: WARN-level. Why: beat-phrase parsing over natural prose has irreducible FP risk; the project convention is WARN for heuristic text checks (24/28/33) and FAIL only for provable structural contradictions (26). Source: the four siblings' severity split, `verify_task_body.py:9806-9814` comments. Alternative: FAIL (rejected: one FP would block a legitimate body).
- **Forward-only mechanism = gate on `meta["text"]` presence** — What: check 34's first gate; checks 24/28 are inherently forward-only (old sidecar bytes unchanged). Why: the task's hard constraint; presence of `text` is also a writer-version marker. Source: task body Constraints; incident #1092. Alternative: date-based or commit-based gating (rejected: fragile; key presence is exact).
- **Trigger phrases: only "both …arms/…" and "one <element> per <unit>"** — What: two pattern classes, contradiction-only firing (all available bases ≤1). Why: these are the two literal #1092 defect phrasings; every broader class evaluated (numeric counts, unit-name matching, panel counts) has a concrete FP channel documented in §4c. Source: task body diff sketch (names exactly these two regex families); check 26's precedent of requiring claim-word co-occurrence to avoid over-fire (L6183-6204). Alternatives: broader NLP-ish claim parsing (rejected: FP risk; can be added later behind the same gate).
- **Bar-count basis from `_kind` point rows, never `n_series`** — What: "both arms" is satisfiable by 2 bars in one container. Why: `n_series` counts artist GROUPS (one BarContainer = 1), which would false-fire on the most common two-arm bar chart; line-artist counting uses distinct `_group`. Source: `_build_sidecar_data` L968-971 (`n_series = len(artifacts)`); `_sidecar_kind_group_aggregate` L6136-6139 (`_group` is per-series). Alternative: `n_series` (rejected: demonstrable FP).
