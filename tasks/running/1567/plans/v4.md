### 4.2 Test-harness changes (`tests/test_guard_repo_root_branch.py` — all line anchors from the current file)

**(a) New fixture builder** (module-level function, mirrors `workflow_lint._build_root_guard_fixture`'s isolation flags, richer seed):

```python
def _build_pinned_repo(d: Path) -> None:
    """git-init a minimal always-on-main repo the hook's git reads resolve against."""
    env = {k: v for k, v in os.environ.items() if not k.startswith("GIT_")}
    env["GIT_CONFIG_GLOBAL"] = "/dev/null"   # ambient gpgsign/hooks isolation (#1545)
    env["GIT_CONFIG_NOSYSTEM"] = "1"
    run = lambda *a: subprocess.run(a, check=True, capture_output=True, env=env)  # + timeout=20
    run("git", "init", "-q", "-b", "main", str(d))                # -b: git >= 2.28
    ident = ("-c", "user.name=eps-guard-test", "-c", "user.email=guard-test@eps.local")
    run("git", "-C", str(d), *ident, "commit", "-q", "--allow-empty", "-m", "c1")
    (d / "CLAUDE.md").write_text("pinned fixture\n")              # bare-pathspec rows L682-683
    (d / "scripts").mkdir()
    (d / "scripts" / "eval.py").write_text("# pinned fixture\n")
    run("git", "-C", str(d), "add", "CLAUDE.md", "scripts/eval.py")
    run("git", "-C", str(d), *ident, "commit", "-q", "-m", "c2")  # 2 commits => HEAD~1 resolves
    run("git", "-C", str(d), "update-ref", "refs/remotes/origin/main", "HEAD")  # origin/main rows
```

Seed ↔ consumer map (every resolution-dependent fixture row):
- 2 commits → `HEAD~1` rows (test L200, 273, 379, 428, 464, 504, 599) resolve at hook site 6.
- reflog (written by default on commits in a non-bare repo; verified §12 A3) → `HEAD@{0}` row (L201).
- `refs/remotes/origin/main` → `origin/main` rows (L202, 274).
- fixture HEAD sha → the `{sha}` template rows (L190-206, L267-278) via retargeted `_repo_head_sha`.
- committed `CLAUDE.md` + `scripts/eval.py` → the bare-pathspec existence-probe rows (L682-683) resolve hermetically at hook site 7 (cat-file), so site 8's real-root fs probe is never consulted for them.
- Fail-soft rows (L364 `nonexistent-typo-ref-xyz-796`, L842 `nonexistent-name-xyz-897`) must NOT resolve: the fixture is strictly minimal (they don't), and site 8 reads the real root fs where those names also don't exist (uuid-like tokens) — dispositions unchanged.
- All other block rows (restore / clean / reset / merge / rebase / pathspec-`--` / flag-shape detectors, e.g. L659-706) are command-pattern detectors with no git read — they were flaky ONLY via the tail arm (site 10), which the pin fixes for all of them at once.

**(b) Session-scoped autouse fixture + module global** (avoids threading a fixture param through ~77 test defs):

```python
_PINNED_REPO: Path | None = None

@pytest.fixture(scope="session", autouse=True)
def _pinned_repo_session(tmp_path_factory):
    global _PINNED_REPO
    d = tmp_path_factory.mktemp("eps-guard-pinned-repo")   # per-process unique; concurrent-run safe
    _build_pinned_repo(d)
    _PINNED_REPO = d
    yield
    _PINNED_REPO = None
```

`tmp_path_factory` basetemp is per-pytest-process (`/tmp/pytest-of-<user>/pytest-<N>`, numbered with locking) — concurrent fleet gate runs each build their own fixture (constraint 7); pytest's retention policy cleans old basetemps.

**(c) Pinned subprocess env** (used by `_run_full` L97-107 and `_run_raw` L115-120):

```python
def _pinned_env(sidecar: str | None) -> dict[str, str]:
    assert _PINNED_REPO is not None, "pinned-repo session fixture did not run"
    env = {k: v for k, v in os.environ.items() if not k.startswith("GIT_")}  # #1545 scrub
    env["GIT_DIR"] = str(_PINNED_REPO / ".git")     # precedence over the hook's git -C "$REPO"
    env["GIT_WORK_TREE"] = str(_PINNED_REPO)
    env["EPM_GUARD_DENY_SIDECAR"] = sidecar or "/dev/null"
    return env
```

Built from `os.environ` at call time, so the existing `monkeypatch.delenv`/env-hatch tests (e.g. L2941-2947) keep working; only `GIT_*` is scrubbed.

**(d) Helper retargets:** `_git` (L123-124) → runs against `_PINNED_REPO` (rename `_git_pinned` optional; keep name to minimize diff, update docstring). `_repo_head_sha` (L132-134) → now returns the fixture HEAD short sha (docstring updated). `throwaway_branch` (L143-162) / `throwaway_tag` (L165-180) → declare `_pinned_repo_session` in their signature (explicit ordering) and create/delete their refs in the fixture — the uuid suffix + tolerant teardown are kept (harmless) but no ref ever touches the production repo again.

**(d-bis) Harness-side git calls scrub too (Methodology-critic concern):** the retargeted `_git` helper, `_build_pinned_repo`, and the throwaway fixtures all build their subprocess env from the same GIT_*-scrubbed base (factored into a tiny `_scrubbed_env()` helper) — otherwise the acceptance-criterion-2 poisoned run breaks HARNESS git calls even though the hook env is pinned.

**(e) Deletions:** `_on_main` (L127-129) and the `on_main` marker (L137-140) are deleted, plus all ~63 `@on_main` usages (mechanical). Module docstring L38-41 and the header comment L82-94 are rewritten to describe the pinning (with a pointer to hook L1384-1388/L1777 and to `workflow_lint._root_guard_git_env` as the sibling). `REPO` (L86) and `_PROD_SIDECAR`/snapshot (L93-94) are KEPT — the module-end production-protection test `test_zz_production_sidecar_untouched_by_suite` (L2951-2960) still reads the real root's filesystem (no git state; unchanged).

### 4.3 The one unpinnable read — `[ -e "$REPO/$arg" ]` (hook L1388b)

This is a filesystem existence probe of the hardcoded real root; `GIT_DIR` cannot redirect it and the hook is not edited. Analysis: (i) it is reached only when sites 5-7 all fail to resolve `$arg`; the seeded fixture makes every block-expectation pathspec row resolve at site 7, so for block rows the probe is dead code in tests; (ii) for allow/fail-soft rows the probed names are deliberately nonexistent tokens that no branch state of the real root creates — file existence in the root is branch-churn-independent for these (a rebase autostash does not materialize `nonexistent-name-xyz-897`); (iii) the residual coupling is therefore not a flake source for the incident class (git-state races). Accepted, documented in the module header. (The hook's own header at L215-219 already documents this probe as a known deliberate residual.)

### 4.4 New tests (the durability pins)

All new block/deny probes REUSE existing in-file shape constants (the sidecar-section precedent, L2634-2637: "no new gated literals") — referenced here by constant name, not literal.

1. `test_off_main_pinned_context_fail_open(tmp_path)` — build a second repo via `_build_pinned_repo(tmp_path)`; FIRST run the same `_SIDECAR_BLOCKED_SWITCH` payload (L2636) against the on-main SESSION fixture and assert exit 2 (the self-discrimination arm — proves the payload IS classified as a block, so the off-main exit 0 below can only come from the tail fail-open arm, not from a classifier miss); then move the second repo onto a non-`main` branch (`git -C <tmp> checkout -q -b not-main`, a subprocess against the throwaway repo — the PreToolUse hook gates Bash TOOL calls, not pytest subprocesses), run the hook with env pinned to it, feed the same payload, assert exit 0 and empty stderr. **Pins the tail fail-open arm (hook L1775-1778) deterministically — previously untestable without racing the fleet.**
2. `test_detached_head_pinned_context_fail_open(tmp_path)` — same shape incl. the on-main exit-2 self-discrimination arm, but `git -C <tmp> checkout -q --detach` (rev-parse --abbrev-ref prints `HEAD` ≠ `main`; the exact `sync_repo_root.py`-rebase incident state), assert exit 0.
3. `test_block_classification_reads_pinned_repo_not_live_root()` — assert the fixture HEAD sha does NOT resolve in the live root (`git -C REPO rev-parse --verify --quiet <sha>^{commit}` fails; a fresh fixture commit's sha cannot exist there) while the `{sha}` detach template (L190) still exits 2 — proves classification runs in the pinned repo. This test FAILS LOUD if anyone later reverts `_run_full` to unpinned `{**os.environ}` (the sha would stop resolving anywhere ⇒ fail-soft allow ⇒ assertion error), making it the harness-pinning regression fence.
4. `test_hook_repo_constant_targets_canonical_root()` — text pin: read the hook script, assert its `REPO=` line (L636) equals `/home/thomasjiralerspong/explore-persona-space` — keeps the "hook points at the real shared root" invariant pinned without any git-state read (replaces the integration value the deleted `on_main` gate implicitly carried).
5. `test_pinned_env_scrubs_ambient_git_vars(monkeypatch)` — `monkeypatch.setenv("GIT_OBJECT_DIRECTORY", "/nonexistent")` (a GIT_* var `_pinned_env` never assigns), then assert a block row (`_SIDECAR_BLOCKED_SWITCH`) still exits 2. ## 11. Decision Rationale

**The design fork (task body names 3 options; this plan resolves it):**

- **What:** Option 1-variant — hermetic pinned git context via `GIT_DIR`/`GIT_WORK_TREE` env pinning in the TEST harness, hook untouched.
- **Why:** (a) zero production diff on a security surface — the strongest possible answer to the brief's seam-risk question (there is no seam to mis-set, no override var to name or log); (b) deterministic block/allow expectations rather than retries/skips (the brief's stated preference); (c) coverage strictly grows (§5), including first-time pins on the fail-open arm; (d) direct in-repo precedent (#1545) already validated the mechanism against this exact hook, on this VM, for this incident class, and its 2026-07-19 audit + my plan-time probes ground every load-bearing git behavior. Source: `scripts/workflow_lint.py` L9080-9098 (#1545) + plan-time empirical probes (§12).
- **Alternatives rejected:**
  - **Option 1b — hook-side env seam (`EPM_GUARD_REPO_OVERRIDE` at hook L636):** works, but edits a security guard for a test-only need: it creates a real (if small) production question — an override var reaching the hook's harness-supplied env redirects ALL of its git reads, including the fail-open arm, and so needs a loud stderr banner + a lint/pin fence to stay safe. Strictly dominated by option 1 given git's native env precedence delivers the identical redirection with no hook edit. Retained only as the §7 fallback.
  - **Option 2 — selector-level flake-retry (`select_step9c_tests.py`):** masks real hook regressions behind a retry (the brief's constraint 2 explicitly disallows this), keeps the live-state dependency, and adds gate machinery for a problem fixable at the source.
  - **Option 3 — per-test on-main re-check / bounded retry:** still racy (TOCTOU between the re-check and the hook subprocess — the incident window was mid-run by definition), and converts fleet state into skips = silent coverage shrink.
- **Import-vs-copy of the #1545 builder:** copy the PATTERN, do not import `workflow_lint`'s builder — its empty-tree minimality is load-bearing for the lint's "cannot mint a new block verdict" property, while the guard tests need the opposite (rich resolution); sharing one builder would couple two deliberately different fitness requirements.
- **Autouse session fixture + module global (vs threading a fixture param):** ~77 test defs call `_run`/`_run_full` bare; threading a param through all of them is a large, error-prone diff for zero behavior gain. The global is set before any test via autouse-session ordering and asserted non-None at use (fail loud).
