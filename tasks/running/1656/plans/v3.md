### Edit 2 — new Harvest contract paragraph (inserted after Edit 1's paragraph, before "**Earlyoom protection is REQUIRED…**" at ~L6130)

Proposed prose (implementer refines wording, keeps every bolded element and the token grammar):

```
**Harvest contract (declared AT LAUNCH — a closed session never strands finished
results; #1310, #1656).** Detachment protects the RUN; this clause protects the
RESULTS. Every detached launch declares its harvest path at launch time:

1. **Durable out-root (REQUIRED).** `<cmd>` writes its results to a durable,
   session-independent location — `eval_results/issue_<N>/...`, the task's
   `artifacts/` dir, an HF-upload staging dir under `data/issue_<N>/`, or (for a
   log-only probe) the breadcrumb's own `log=` file — never session-scoped scratch
   only the launching conversation knows about.
2. **`harvest=` token (REQUIRED).** The stage-dispatch breadcrumb's
   `harvest=<abs, space-free output path or glob>` (comma-separate multiple paths;
   values are whitespace-split tokens, so no spaces) names where completion outputs
   land. The § Successor / re-entry rule probes THIS path for "completion output
   present" and collects from it — no guessing. Breadcrumbs predating this contract
   lack the token: consumers fall back to log-tail + known output dirs (the same
   graceful-optional convention as `label=`).
3. **Self-harvest chaining (PREFERRED).** When collection is one idempotent command,
   make it part of the detached unit itself — as a SINGLE command unit substituted
   for `<cmd>`: a driver script whose final act is the collection/upload (an HF
   upload of raw completions/tensors, a copy into `eval_results/issue_<N>/`), or an
   inner `bash -c '<workload> && <harvest-cmd>'`. NEVER splice a bare
   `<workload> && <harvest-cmd>` into the template: the `&&` splits the launch line,
   binding setsid/nohup/env to the first command and the redirections + trailing `&`
   to the second — detachment silently breaks. This is the detached-phase instance
   of the batch-judge deadline-bounded self-harvest. The identity verify is
   unchanged (the distinctive workload substring still appears in
   `ps -p $PHASE_PID -o args=` for either wrapped form). Only the steps that MUST
   stay session-side — the explicit-path git commit under the concurrent-committer
   discipline, folding numbers into the body — are left to the successor; the DATA
   is durable before any session touches it.

The contract costs one token + a path choice at launch — never a new gate.
```

1. **Token name + grammar `harvest=<abs, space-free path-or-glob>` (comma-joined multiples).**
   *Why:* breadcrumb values are whitespace-split tokens (`_breadcrumb_fields`, src L1907–1914) —
   a "one-line recipe" with spaces cannot be a token, so the token carries WHERE (declarative
   path) and the setsid chain carries HOW (imperative command). Absolute + space-free mirrors
   the existing `log=` requirement in the same sentence. *Source:* `task_workflow.py` parser +
   SKILL.md L6122–6127 (`log=` abs-path precedent) + L8252 `label=` optional-token precedent.
   *Alternatives:* a `harvest_cmd=` command token (rejected: spaces); a separate sentinel file
   contract (rejected: heavier, and the existing "completion sentinel / output present" prose
   already tolerates sentinels).
2. **Contract lives IN the detached-phases block, consumption in the Successor rule.** *Why:*
   the launch block is where every other launch duty (pid, choom, env prefix) is declared, and
   the successor rule is the ONLY consumer that currently guesses; #1310's failure was exactly
   launch-side declaration missing → successor-side guessing. *Source:* #1310 incident, #833
   section structure, #1051 (tick defers to breadcrumbs). *Alternatives:* a standalone
   `.claude/rules/*.md` (rejected: would need a LESSONS.md row + splits one convention across
   two files); tick_triage code enforcement (rejected: brief prefers prose-first; the tick is
   liveness-only).
3. **Prose + pin test, no lint.** *Why:* the enforceable artifact is the convention text; a
   runtime lint on live breadcrumbs has no cheap hook (breadcrumbs live in events.jsonl, and
   pre-contract crumbs are legal forever). The repo's standing convention for SKILL.md
   contract prose is a `test_issue_skill_*` pin (14 registered precedents). *Source:*
   `tests/test_issue_skill_long_phase_heartbeat.py` shape; #1242/#1268/#1546 registration
   lineage. *Alternatives:* `workflow_lint` check (rejected: over-engineering, see §4).
4. **Self-harvest chaining PREFERRED, not REQUIRED.** *Why:* a detached `git commit/push` from
   an unattended unit collides with the concurrent-committer discipline (explicit-path staging,
   index.lock retries, root-sync) — the DATA-durability half (HF upload, copy into
   `eval_results/`) is safe to chain, the git half is safer session-side. Requiring the chain
   everywhere would make the recipe heavy (kill criterion (a)). *Source:* batch-judge
   self-harvest precedent (SKILL.md L714/722); CLAUDE.md § Concurrent repo-root committers;
   #825 (store-before-long-fit — durability ordering matters more than who commits).
5. **New pin FILE (registered) rather than a new test in an existing registered file.** *Why:*
   the closest registered files (`test_issue_skill_exit_breadcrumb.py`,
   `test_issue_skill_marker_contract.py`) pin unrelated contracts (exit breadcrumbs / marker
   schema); a dedicated stem keeps the pin discoverable and its docstring carries the #1310
   lineage. The closest existing pin on this very block —
   `tests/test_workflow_setsid_detach_convention.py` — is UNREGISTERED (verified: no selector
   match), so extending it would repeat the #1546 never-runs-on-SKILL.md-diffs gap; recorded
   here so a future consolidation doesn't read the two pins as accidental duplication.
   Registration cost is two one-line edits. *Source:* selector L240–246 registration
   recipe; #1584 (manifest replaces count pin, so concurrent registrations don't conflict).
6. **Edit 7 mirror sync as token appends, not contract duplication.** *Why:* the two
   paths-triggered mirrors (`code-style.md` L78, `vectorize-many-cell-fits.md` item 7) are
   imperative duty-lists agents execute directly on the detached-fit launch class — leaving
   them at three fields makes the contract silently unreachable for exactly the launches it
   targets; each mirror already defers ownership to the SKILL.md section, so a one-line token
   append keeps a single authoritative contract. *Source:* critic round 1 (Methodology +
   Alternatives, same finding); #957 plan v4 criterion 1b (the two→three field upgrade synced
   `code-style.md` the same way). *Alternatives:* reasoned no-change (rejected: unlike the
   CLAUDE.md descriptive pointer, these are executable duty-lists — the no-change rationale
   does not transfer); duplicating the full contract into each mirror (rejected: second
   surface to keep in sync).
