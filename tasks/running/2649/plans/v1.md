## Concrete fixes

### Leg A — heavy-import-before-`load_dotenv` (11 files)

Canonical idiom, copied verbatim from `scripts/issue1072_lowdim_stats.py:26-30`
and `scripts/issue1074_bnr_figures.py:26-34`:

```python
from explore_persona_space.orchestrate.env import load_dotenv

load_dotenv()  # BEFORE any heavy import — shared-VM thread caps (#847)

import numpy as np  # noqa: E402
import torch  # noqa: E402
```

Placement rule the test enforces (`tests/test_shared_vm_thread_caps.py:~1000`):
`_first_load_dotenv_line(src)` must be **strictly less** than
`_first_heavy_import_line(ast.parse(src))`. So the `load_dotenv()` CALL — not
just the import of it — goes above the first module-top heavy import. Every
module-level import moved below the call takes `# noqa: E402` (ruff E402), and
the ruff/isort block ordering must survive `uv run ruff check`.

Why this is the real fix and not cosmetic: torch freezes its intra-op pool from
`OMP_NUM_THREADS` at IMPORT time, so a `load_dotenv()` after the import cannot
cap threads in-process (`.claude/rules/code-style.md` § Shared-VM CPU thread
caps, #847). An uncapped job holds ~32 runnable threads on this shared box.

### Leg B — bare `hf_hub_download(` (10 sites, 7 files)

Canonical idiom, copied from `scripts/issue1482_early_layer.py:504` and
`scripts/issue825_kresample_user_floor.py:223`:

```python
from explore_persona_space.orchestrate import hub

path = hub.retry_transient(
    lambda: hf_hub_download(...),        # args UNCHANGED
    what="<short description of the fetch>",
)
```

Zero waiver needed — `retry_transient` is inside `HF_ROUTING_WRAP_RE`, and the
wrap must be **anchored** to the call (same line, or opening within
`HF_ROUTING_WRAP_WINDOW = 3` lines above with the expression still open at the
call line; a wrapped sibling does not launder a bare call). Loop-variable
capture uses the established default-arg form (`lambda name=name: ...`) where
the call sits in a comprehension or a `ThreadPoolExecutor` closure — this
appears in at least `issue2643_refusal_panel.py` (`def download(filename)` under
a thread pool) and must not silently change the late-binding semantics.

### Leg C — bare `.list_repo_tree(` (5 sites, 5 files)

Two sanctioned remedies. **Default is (C1)** because every one of these files is
another issue's frozen reproducibility artifact, and (C1) is provably
behavior-identical:

**C1 (default) — retry-wrap in place + the documented waiver:**

```python
# HUB_VERIFY_RETRY_EXEMPT: raw tree walk wrapped in hub.retry_transient below (#1202)
entries = hub.retry_transient(
    lambda: api.list_repo_tree(...),     # args UNCHANGED
    what="<short description>",
)
```

This is exactly the waiver the check's own message sanctions ("A
genuinely-correct raw call (e.g. one you wrap in `hub.retry_transient` yourself)
takes the waiver"), reason >= 10 chars, on the call line or the previous
non-blank line. It is NOT grandfathering: it adds the retry property the check
exists to enforce, and it changes no returned value.

**C2 (opt-in, per site, requires justification) —
`hub.list_hf_files_under_path(api, repo_id, path, repo_type=..., revision=...)`**,
the canonical helper (no waiver). Use ONLY where the implementer verifies the
consumer wants "files under a prefix". Known semantic delta the implementer must
check before choosing C2: `list_repo_tree(recursive=True, expand=False)` yields
`RepoFile` **and** `RepoFolder` entries, while `list_hf_files_under_path` returns
files only. For a site that feeds the result straight into `hf_hub_download`
(e.g. `issue2643_refusal_panel.py:116` → `:130`) that is arguably a latent bug
fix — but it is still a behavior change on a frozen artifact, so C2 requires the
implementer to state the equivalence argument in its report. Where sizes are
needed, `hub.list_hf_entries_under_path` is the sizes variant.

Whichever is chosen, **criterion 4 requires the remedy be recorded per site.**

## Kill criteria

- **K1 — a fix changes observable behavior of a frozen artifact.** These are
  other issues' reproducibility scripts. If a routing swap alters a returned
  file set, a download target, a thread count relied on numerically, or the
  late-binding of a loop closure, back it out and take the C1 waiver form
  instead. Behavior-preservation beats helper-canonicality here.
- **K2 — the no-flags lint carries unrelated pre-existing red that this scope
  cannot clear.** Criterion 2 is worded "no error **naming the offender set
  above**". If no-flags stays non-zero for a DIFFERENT check, that is out of
  scope: record the residual by check name in the completion marker and do not
  widen the round to chase it. Widening is how a repair task becomes a
  never-landing task.
- **K3 — main churns a new offender under us.** The offender set is a moving
  target (`issue2474_whiten_csls.py` is already queued in someone's working
  tree). Re-measure against `origin/main` immediately before the Step 10d
  merge; a newly-landed offender is NOT this round's to fix — record it and let
  the structural follow-up own it. Do not spin re-measuring forever.
- **K4 — the repair requires editing the checks or the grandfather lists.** That
  would be a different task (weakening an invariant), and the body forbids it.
