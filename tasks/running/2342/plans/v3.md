# Plan v3 — #2342: reconcile marker-kind registry with /issue review-loop practice

## Requirement + acceptance criteria

**Requirement.** workflow.yaml § markers registers exactly ONE marker-mode reconcile kind (`epm:review-reconcile`, role carried in the body's `**Role under adjudication:**` field), but runtime practice deviates: reconciler agent spawns improvise role-tagged kinds. Fleet-wide events.jsonl census (critic-refreshed 2026-08-24): 908 canonical rows vs 88 deviant rows across 15 improvised variants (29 `epm:code-review-reconcile`, 17 `epm:plan-critique-reconcile` — an in-context stdout tag by design, never an events.jsonl row — 12 `epm:clean-result-critique-reconcile`, 11 `epm:code-review-reconciled`, 6 `epm:review-reconciliation`, long tail of `-reconciler`/`-reconciled`/bare variants). The implementer re-runs the census grep at implementation time and asserts every observed variant trips the new guard helper. The registry's design intent (markers.md, reconciler.md, workflow.yaml § ensemble_review: all 5 doubled sites declare `reconcile_marker: "epm:review-reconcile"`) resolves the task body's fork toward MIGRATING PRACTICE TO THE CANONICAL KIND, not registering 13 variants. The spec side was already fixed once (2026-05-28; pinned by `tests/test_workflow_yaml.py::test_reconciler_md_uses_only_canonical_reconcile_marker`) — the residual gap is RUNTIME enforcement: `task.py post-marker` accepts any kind unvalidated, and the existing `--check-marker-registry` lint gates only documented posting instructions in `.md` files.

**Why it matters.** Resume predicates (`.claude/skills/issue/steps/19-step-completed-reentry.md`) key on the exact kind `epm:review-reconcile` + role-matched body. A deviant row is invisible to resume logic: a mid-pipeline resume falsely concludes "reconciler not yet started" and re-spawns a reconciler that already ran (wasted spawn, duplicate adjudication rows).

**Acceptance criteria:**
1. `uv run python scripts/task.py post-marker <N> epm:code-review-reconcile --note x` exits 2 with a stderr error naming the canonical recipe (kind `epm:review-reconcile`, role in the body field); NOTHING is appended to events.jsonl.
2. The same refusal fires for every kind containing the substring `reconcil` that is not exactly `epm:review-reconcile` — covering all 13 observed deviant variants, `epm:plan-critique-reconcile` (error message says: in-context stdout tag, print it, never post it), and the registered documentation alias `epm:followup-value-critique-reconcile` (its own registry entry says the reconciler posts the ONE canonical kind).
3. `post-marker <N> epm:review-reconcile` behavior is byte-unchanged (exit 0, row appended); kinds not containing `reconcil` are unaffected.
4. Library-level `task_workflow.post_event` stays deliberately ungated (the #2309 precedent: programmatic posters unaffected; the CLI is the chokepoint every reconciler spawn uses).
5. A workflow-surface sweep test proves no `.md` in `.claude/agents/` + `.claude/skills/issue/` (SKILL.md, steps/, markers.md, templates/) names a reconcile-family `epm:` kind outside the allowed set {`epm:review-reconcile`, `epm:plan-critique-reconcile`, `epm:followup-value-critique-reconcile`}.
6. No NEW failures vs the plan-time baseline (the step9c baseline compare / Step 10d baseline-subtracted lint gate) on touched surfaces: `tests/test_workflow_yaml.py`, the task.py CLI tests mapped by `scripts/select_step9c_tests.py --map-files`, and `workflow_lint.py` no-flags run + `--check-marker-registry` + `--check-references` + `--check-tables`.

## File paths + concrete changes

1. **`scripts/task.py`** (`cmd_post_event`, near the #2309 completion-report gate): add a reconcile-family kind guard that runs BEFORE `post_event`:
   - Predicate: `"reconcil" in args.marker and args.marker != "epm:review-reconcile"`.
   - Refusal: print ERROR to stderr + `raise SystemExit(2)`; nothing appended. Message branches: (a) `epm:plan-critique-reconcile` → "in-context stdout tag (adversarial-planner Phase 2); print it to stdout, never post it to events.jsonl"; (b) everything else → "marker-mode reconcile posts use the LITERAL kind epm:review-reconcile with the adjudicated role in the body's **Role under adjudication:** field (workflow.yaml § markers; reconciler.md). Never derive the kind from the role. A genuinely new reconcile-family kind requires a workflow.yaml § markers entry AND an extension of this guard's allowlist."
   - Implementation shape: small module-level helper (e.g. `_reconcile_kind_violation(kind) -> str | None`) beside `completion_report_violation` for testability; no new flags, no waiver (unlike #2309 — there is no legitimate nonconforming post in this family).
2. **`tests/test_task_post_marker_reconcile_guard.py`** (new): refusal tests for a representative deviant set (`epm:code-review-reconcile`, `epm:clean-result-critique-reconcile`, `epm:interp-critique-reconcile`, `epm:plan-critique-reconcile`, `epm:followup-value-critique-reconcile`, `epm:reconciled`, `epm:code-review-reconciled`, `epm:review-reconciliation` — the `-reconciliation` form covers the 6 observed rows the substring predicate catches beyond exact-kind lists), exit code 2 + no-row-appended assertion + message-content checks; pass-through tests for `epm:review-reconcile` and an unrelated kind; a direct-call test documenting `post_event` stays ungated. Use whatever tmp-task fixture pattern the existing task.py CLI tests use.
3. **`tests/test_workflow_yaml.py`**: add a sibling test (keep the existing reconciler.md pin intact) sweeping `.claude/agents/*.md` + `.claude/skills/issue/**/*.md` for `epm:[a-z-]*reconcil[a-z-]*` tokens, asserting ⊆ the 3-kind allowed set above (acceptance criterion 5). Verified green on current HEAD before the diff lands (grep pre-check during implementation).
4. **`.claude/agents/reconciler.md`**: one short warning block in the marker-mode posting recipe, phrased with PLACEHOLDER forms only (no literal deviant `epm:` strings — the existing pin test forbids them): the kind is the LITERAL string for every role; never role-derive it; `task.py post-marker` refuses any other kind containing `reconcil`; the exact-kind read-back recipe must use the literal string too; and the `task.py post-marker` CLI is the ONLY sanctioned posting path for reconcile verdicts — a direct `task_workflow.post_event(...)` library call is out of contract (the library is deliberately ungated per the #2309 precedent, so the instruction layer is what closes that residual).
5. **`.claude/workflow.yaml` § markers, `epm:review-reconcile` entry**: append one sentence to the entry noting the CLI guard (no `#` characters — `--check-marker-scalar-integrity` truncation trap). Then regenerate the auto-generated tables: `uv run python scripts/workflow_lint.py --emit-tables` (markers.md + SKILL.md fences).
