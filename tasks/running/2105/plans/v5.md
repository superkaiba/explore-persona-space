# Plan v5 — #2105 workflow-fix: triage window boundary opens at post time, hiding enumerate-to-post seam markers

> v4 addresses the round-1 critic Must-Fix: the pod/backend-launch form (triage note posted immediately BEFORE dispatch, `epm:run-launched`/`epm:cluster-launched` landing AFTER — SKILL.md :4394/:4731) masks the token, because the later token-less launch marker closes the window at its own position. On a cold RunPod provision that seam is 25–50 min, the dominant incident surface. Fix: parser-side ONE-STEP CHAIN — when the most recent boundary record is a launch-kind marker whose note carries NO triage line, chain to the immediately preceding boundary-class record; if that is a token-bearing triage record, honor ITS token. No composer-ordering change (avoids the crash-window of posting the record after launch, and works for in-flight sessions already posting note-then-launch), no experimenter/backends marker-format change.

## Requirement

Close the enumerate-to-post seam in the pre-dispatch external-marker triage window. `task_workflow.triage_candidates_since_last_dispatch` opens the candidate window strictly AFTER the most recent duty-bound record (compute-launch marker, or any event whose note carries `external-markers triaged:`). The triage line is posted at breadcrumb-post time T1, but enumeration ran at T0 < T1 — any external marker landing in (T0, T1) was never enumerated at T0 and sits behind the boundary at every later call, so no session ever triages it.

Incident grounding (#2054, 2026-08-05): user-directive marker v91 ("make sure training is at least 5000 for each setting") landed 53 s before the r11 breadcrumb post; invisible to rounds r11–r14; caught only by a manual events re-read (v98 forensics), costing a 4-round directive miss + a triage-correction round (v108). The SKILL.md accepted-residuals clause currently names this seam as accepted; this task upgrades it to fixed (per the auto-filed candidate, confidence: high).

## Acceptance criteria

1. **Seam closure — breadcrumb form (regression test, #2054 v91 replay):** a marker whose ts lies strictly between a triage record's recorded enumeration boundary and the record's own ts IS returned by the next `triage_candidates_since_last_dispatch` call when the record carries a `(boundary=<ts>)` token.
1b. **Seam closure — launch form (critic round-1 Must-Fix, mechanized):** events = [enumerated…, token-bearing triage `epm:progress` note (boundary=T0), `epm:run-launched` with no triage line, …]; a marker with ts in (T0, launch-marker ts) IS returned by the next call. Under the v3 design this test FAILS; the v4 one-step chain makes it pass.
2. **Legacy compat (byte-identical):** a triage line WITHOUT the token parses to today's behavior exactly — all 28 existing tests in `tests/test_pre_dispatch_triage.py` pass UNMODIFIED. A token-less launch marker whose preceding boundary-class record is ALSO token-less (legacy note, or another launch marker) keeps today's launch-position boundary.
3. **Fail-soft:** a malformed / unparseable `boundary=` value falls back to today's post-position boundary.
4. **Never-shrink:** the reopened window can never start LATER than today's (structurally guaranteed: the scan-back starts at the boundary-record index − 1, so the window always contains at least everything today's window contains). A bogus-future recorded ts degrades to today's window, never a narrower one.
5. **Composer side:** the SKILL.md canonical enumerator snippet prints the boundary value mechanically; the triage-line format spec documents the token; the accepted-residuals clause is narrowed (the enumerate-to-post seam residual is replaced by the residuals that remain: same-second ties behind the `<=` boundary, legacy lines without the token, and the untriaged-launch case — precise wording in §2(c)).
6. **Hygiene:** ruff clean on touched files; `workflow_lint.py --check-asks` passes; Step 9c touched-scope gate green at review time.

## Method delta (what is genuinely new vs reused)

- NEW: an optional `(boundary=<ts>)` token in the triage-record line + its parser + the window-reopen logic in the enumerator (including the one-step chain for the launch form) + a tiny composer-side helper. Everything else (window filter `_triage_window_candidates`, ts parsing `_parse_ts_str`/`_stage_event_ts`, the duty text structure, composer ORDERING — note-then-launch stays as-is) is REUSED unchanged.
- DELIBERATE SCOPE CUT — observer unchanged: the #967 post-hoc observer (`audit_dispatch_triage` and its `boundary_idx` pre-record windows) keeps its current semantics. Its `none-with-candidates` class already absorbs record-adjacent candidates via `grace_s` (the observer explicitly names the seam an accepted residual and is flag-only / info-tier); rewiring its historical-window boundaries to parse tokens would churn watcher behavior with no incident-grounded gain. ## Design + concrete diffs

### 1. `src/explore_persona_space/task_workflow.py`

(a) New compiled token regex + parser, colocated with `TRIAGE_LINE_PREFIX` (~L2762):

```python
# The optional enumeration-boundary token a triage-record line may carry
# (#2105): "external-markers triaged: ... (boundary=<ts>)". <ts> is the ts
# of the LAST event the enumerating session read (see
# triage_enumeration_boundary). Legacy lines without the token keep the
# post-position boundary exactly (fail-toward-today).
TRIAGE_BOUNDARY_TOKEN_RE = re.compile(r"\(boundary=([^\s)]+)\)")


def parse_triage_boundary_ts(note: str) -> "datetime | None":
    """Parse the optional ``(boundary=<ts>)`` token from a triage-record
    note. ``None`` when the note is not a triage record, carries no token,
    or the token's ts is unparseable (fail-soft — legacy behavior). The
    search is anchored at the LAST occurrence of the triage line
    (``note.rfind(TRIAGE_LINE_PREFIX)`` onward — the record's OWN line is
    appended last per the format spec) so a note QUOTING a prior triage
    line earlier in its body cannot bind a stale boundary (critic round-1
    NTH-1 + round-2 NTH-1; forensics notes quote triage lines — the #2054
    v98/v108 shape). A mis-bind would only ever pick an OLDER quoted token
    -> wider window -> over-enumeration, never under-enumeration."""
    pos = note.rfind(TRIAGE_LINE_PREFIX)
    if pos < 0:
        return None
    m = TRIAGE_BOUNDARY_TOKEN_RE.search(note, pos)
    if m is None:
        return None
    return _parse_ts_str(m.group(1))


def triage_enumeration_boundary(events: list[dict]) -> str:
    """The ``boundary=`` value an enumerating session stamps into its triage
    line: the ts of the LAST event in ``events`` at enumeration time (""
    when the list is empty — composers omit the token then)."""
    return (events[-1].get("ts", "") or "") if events else ""
```

(b) `triage_candidates_since_last_dispatch` — reopen the window from the recorded enumeration point, with the ONE-STEP CHAIN for the launch form (boundary matcher, ~L2839):

```python
    boundary = -1
    for idx in range(len(events) - 1, -1, -1):
        event = events[idx]
        note = event.get("note", "") or ""
        is_launch = event.get("kind", "") in launch_kinds
        if is_launch or TRIAGE_LINE_PREFIX in note:
            boundary = idx
            recorded = parse_triage_boundary_ts(note)
            if recorded is None and is_launch and TRIAGE_LINE_PREFIX not in note:
                # #2105 launch form: the duty posts its token-bearing
                # triage note immediately BEFORE dispatch (SKILL.md Step
                # 6b / 6d.1), so the launch marker lands AFTER it and
                # would mask the token. Chain EXACTLY ONE step to the
                # immediately preceding boundary-class record; honor its
                # token when it is a triage record. An earlier launch
                # marker, or a token-less (legacy) note, stops the chain
                # -> today's launch-position boundary (fail-toward-today
                # for untriaged / legacy launches).
                for k in range(idx - 1, -1, -1):
                    ev_k = events[k]
                    note_k = ev_k.get("note", "") or ""
                    if ev_k.get("kind", "") in launch_kinds or TRIAGE_LINE_PREFIX in note_k:
                        if TRIAGE_LINE_PREFIX in note_k:
                            recorded = parse_triage_boundary_ts(note_k)
                        break
            if recorded is not None:
                # Reopen the enumerate-to-post seam — the window starts
                # after the LAST event the record's enumerator actually
                # read (highest j < idx with parseable ts <= recorded),
                # not after the record's own post position. Events with
                # unparseable ts stay IN the window (fail-toward-triage);
                # no match -> whole list (over-enumeration is safe).
                # Structurally never-shrink: the scan starts at idx - 1,
                # so the reopened window is a superset of today's
                # events[idx + 1:]. Reopening re-includes the session's
                # OWN pre-launch bookkeeping notes (compute-character
                # statements etc.) posted after enumeration — sanctioned
                # over-enumeration, not a bug (they filter or re-triage
                # trivially).
                boundary = -1
                for j in range(idx - 1, -1, -1):
                    ts_j = _stage_event_ts(events[j])
                    if ts_j is not None and ts_j <= recorded:
                        boundary = j
                        break
            break
    return _triage_window_candidates(
        events[boundary + 1 :], exempt_kinds=exempt_kinds, machine_by=machine_by
    )
```

Docstring of the function gains one paragraph documenting the token semantics, the one-step launch-form chain, + the named residuals (same-second tie behind a `<=` boundary; legacy lines and untriaged launches keep the old behavior).

Note on re-inclusion safety: the reopened window contains the triage record itself, the stage-dispatch breadcrumb, the launch marker, and machine markers — ALL already excluded by `_triage_window_candidates` (triage-line notes, breadcrumb-shaped notes, exempt kinds — `epm:run-launched` is exempt-kind at ~L2684, `epm:cluster-launched` is machine-`by` — and machine `by`), so reopening cannot re-surface bookkeeping rows. Events at ts <= recorded were enumerated by the prior run and stay outside the window (`<=` per the filed sketch), so already-triaged advisories are not re-enumerated. Observer compatibility: `audit_dispatch_triage` is UNCHANGED and unaffected by the chain — it has no "applied-with-no-candidates" class, `_adjacent_triage_coverage` already accepts the note-before-launch adjacency, and the `(boundary=…)` suffix does not break `_triage_disposition_is_none` (the rest of the line still starts with "none") — verified by the round-1 critic.
