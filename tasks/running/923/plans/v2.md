## 0.0 TL;DR (plain English)

- **What I'll run:** The model's "answer fingerprint" for a given system prompt plus user question is already known to be predictable from the model's internal state just before it answers. I'll test whether that fingerprint splits into two independent parts: one you can read from the system prompt alone (question absent) and one from the question alone (system prompt absent). I fit simple linear read-outs from each part, from the two glued together, and from the normal mixed prompt, then compare how well each predicts the fingerprint on prompt families and questions the fits never saw. No model training anywhere.
- **What I expect:** The system-prompt part will carry most of the predictable signal, the question part will add a modest amount, and gluing the two together will recover most — but not all — of what the mixed prompt gives. The leftover gap measures what the model computes only by letting the question actually see the system prompt.
- **What would change my mind:** If the glued-together read matches (or beats) the mixed-prompt read, the two inputs contribute separately and "context geometry" is a self-contained object. If the gap is large, the interesting information lives in the mixing itself, and any predictor built from context-only measurements has a hard ceiling I can now put a number on.

## 1. Goal

(Frontmatter goal, canonical.) Determine whether the base model's per-cell mean answer activation v̄(c,q) — the answer-token-mean residual profile of its own on-policy completion, the #810-winning summary — decomposes into context-only and query-only representational components: with no model training and ridge-only read-outs, predict v̄(c,q) on the diverse-contexts × UltraChat grid from (a) the last-context-token vector computed with the query absent, (b) the last-query-token vector computed with no context (3 null-context presentations), (c) their combination (concat + prediction-level blend), and (d) the full-prompt last-input-token vector, and measure under LOFO context-family × held-out/OOD-query folds how much of the [best-single → full-prompt] held-out R² gap the combination closes. The interaction residual R²(full) − R²(combined) quantifies the attention-mixing information unavailable to disjoint parts. This sharpens what the leakage-prediction program's "context geometry" object can claim: a separable context factor makes base-side context geometry a self-contained predictor input; a large interaction residual is a measured ceiling on any context-only predictor.

**External (fresh search 2026-07-03, this planning pass; all ids resolved):**

- **2310.15916** (Hendel, Geva, Globerson — *In-Context Learning Creates Task Vectors*): ICL demonstrations compress into a single task vector that modulates query processing — the representational precedent for a separable context component.
- **2310.15213** (Todd et al. — *Function Vectors in Large Language Models*): a compact context-derived vector, ADDED to an unrelated (even zero-shot) query forward pass, triggers the demonstrated task — the strongest published precedent that context contribution composes additively with a query-only representation. - **2308.09124** (Hernandez et al. — *Linearity of Relation Decoding in Transformer LMs*): relation decoding from a partial (subject) representation is well-approximated by a single affine map for ~48% of relations — precedent for linear read-outs from partial-input representations, and for the finding that linearity holds only for a subset (motivates reporting per-family heterogeneity).
- **2212.07677** (von Oswald et al. — ICL as implicit gradient descent) and **2406.05816** (attention as hypernetwork; compositional latent codes): mechanisms by which context *changes the function applied to* the query rather than adding to it — the H2 side. - Adjacent (context, not load-bearing): 2410.05603 (task superposition in ICL), 2404.11225 (ICL state vectors).

No published work was found that measures the *held-out predictive decomposition* of an answer-side activation profile into disjoint context/query readouts — the closest work (task/function vectors) studies output behavior under vector *injection*, not R² decomposition of the answer profile. This experiment's framing is novel but sits on well-trodden representational ground.

## 3. Hypothesis

Let R²(·) denote LOFO×held-out-query pooled skill-over-mean R² at the frozen headline layer (L18), UC genre.

- **H1 (separable):** the Stitched pair recovers most of the Full-prompt read. Confirmed if decomposability fraction ρ_dec = [R²(concat) − R²(best single)] / [R²(full) − R²(best single)] ≥ 0.8 **and** interaction residual ΔR² = R²(full) − R²(concat) ≤ 0.05. Falsified by ΔR² ≥ 0.15 with CI excluding 0.05.
- **H2 (interaction-dominant):** ΔR² ≥ 0.15 and > 2× the family-cluster bootstrap 95% half-width. Falsified by H1's confirmation condition.
- **H3 (context-dominant asymmetry):** R²(ctx-only) − R²(qry-only) ≥ 0.10 with the family-cluster CI excluding 0. Falsified if the gap's CI includes 0 or is negative.
- **Pre-registered non-error outcome:** ΔR² < 0 (Stitched pair BEATS Full-prompt) is meaningful — the single last-input token is then an information bottleneck relative to the disjoint pair — and is reported as such, not treated as a bug.
- **Oracle consistency prediction:** R²(ctx-only) ≤ context-main-effect ANOVA share; R²(concat) ≤ additive share; ΔR² ≤ interaction share (up to estimation error). A violation flags a leak/bug (fail-loud check).

H1 vs H2 are genuinely uncertain: function-vector results (2310.15213) predict H1; ICL-as-computation results (2212.07677, 2406.05816) predict H2; the line's own context-geometry results (#658/#810) predict H3 either way.

## 4. Design

### 4.1 Objects

- **Grid.** Contexts: the 50-context battery, 7 families (`data/issue594/battery.json`, in git). Queries (UC genre, primary): the store's 48 UltraChat probes (`data/issue594/probes_ultrachat.json`, pinned by the store manifest `probe_pool_hash`) + 96 fresh UltraChat probes (Phase 0). Queries (Betley genre, secondary): the store's 48 Betley probes. OOD queries: 48 Dolly-15k instruction-only rows (Phase 0). Cells: 50×144 = 7200 (UC), 50×48 = 2400 (Betley), 50×48 = 2400 (OOD).
- **Target.** v̄(c,q) ∈ R^3584 per layer ℓ ∈ {0..27}: mean residual activation over the answer-token span of the model's own greedy completion to the full (c,q) prompt. Existing cells: re-reduced from the stores' `answer_spans/<ctx>.pt` (per-probe `(28, S, H)` fp16 spans — schema verified in `issue658_extract_base_store.py::capture_v0_for_context`). New cells (UC-ext, OOD): captured fresh with the same recipe.
- **Features** (per layer, same-layer binding; all residual-stream reads):
  - `F_ctx` — last-context-token vector from a **prefix-only forward**: the full-prompt tokenization truncated at the final token of the context block (system turn and/or prefix messages, exactly as `messages_for_instance` renders them). By causal masking this equals the same position's activation inside the full prompt bit-for-bat (up to batching numerics) — the body's "diagnostic variant" is an exact identity, verified numerically on 5 contexts (assert cos > 0.999), then dropped as a separate arm.
  - `F_qry^(i)` — last input token (assistant-header slot, matching `arm_full`'s slot type) of the query rendered with an **explicitly empty system turn** (`messages=[{"system",""},{"user",q}]`; asserts the Qwen default system prompt is NOT silently inserted, by string-checking the rendered template).
  - `F_qry^(ii)` — same, with **no system block at all** (hand-rendered `<|im_start|>user\n{q}<|im_end|>\n<|im_start|>assistant\n`).
  - `F_qry^(iii)` — the FULL (c,q) token sequence with the context-span positions **attention-masked** (custom 4D attention mask; query tokens attend only to query-block + assistant-header tokens, causally). Positions preserved, so `arm_full` − `arm_qry_iii` isolates attention-to-context at fixed positional geometry.
  - `F_full` — last input token of the full (c,q) prompt with `add_generation_prompt=True` (the #658-locked c_C slot, read per-cell rather than probe[0]-pinned).
- **Maps.** Per (arm, layer, fold): standardize-X on train, train-fold-center Y, PCA-48 both sides (train-fold-fit bases; features and targets), ridge with nested PRESS-LOO λ over `[1e-2, 1e-1, 1, 10, 100, 1000]`. Arms: `arm_ctx`, `arm_qry_{i,ii,iii}`, `arm_concat_{i,ii,iii}` (concat [F_ctx; F_qry^(p)], d=96 after PCA), `arm_blend` (α·pred_ctx + β·pred_qry_i, α,β fit on an inner group-respecting validation split — no ridge refit), `arm_full`. 8 ridge-fit arms + 1 derived.
- **ANOVA oracle (in-sample reference, targets only).** On each complete grid, per layer: v̄(c,q) = μ + a(c) + b(q) + γ(c,q); variance shares of the three terms (computed on the PCA-48 target representation for comparability with the DV, and in ambient space as a secondary). Reported separately from every held-out read, labeled in-sample.

### 4.2 Folds

Grouping axes: context FAMILY (7) × query id. Scheme: 7 LOFO family folds × 4 query folds (UC: 144 → 4×36; Betley: 48 → 4×12; seeded stratified by matched-Betley-length decile). Fold (f,k): train = non-f families' contexts × non-k queries; test = family-f contexts × fold-k queries — both axes unseen. Each cell is tested exactly once → pooled held-out predictions cover the grid once; pooled skill per (arm, layer). Exploratory marginals: unseen-family × seen-query and seen-context × unseen-query. OOD read: for each family fold f, train on non-f × all-144 UC queries, test on family-f × 48 Dolly queries (every OOD query unseen by construction — the corpus-transfer form, the strongest fold per `.claude/rules/ood-generalization-folds.md`).

λ: PRESS-LOO within train only. Blend α,β: inner split of the train fold (hold out 1 rotating family + 25% of train queries), fit maps on inner-train, fit (α,β) by 2-parameter least squares on inner-val, refit maps on full train, apply (α,β). Nothing outside the train fold ever touches any fitted quantity.

**Success / kill criteria (quantitative):**

- Sanity/power floor (kill): if R²(`arm_full`) < 0.05 at EVERY layer (LOFO-pooled, UC), the per-cell map is unlearnable at this grid — skip H1–H3 verdicts, report the null + ANOVA shares + the regen check as the finding (this is a decision rule for analysis framing, not a mid-run gate).
- H1 confirmed: ρ_dec ≥ 0.8 AND ΔR² ≤ 0.05 (family-bootstrap CI consistent).
- H2 confirmed: ΔR² ≥ 0.15 AND > 2× the bootstrap 95% half-width.
- Intermediate (0.05 < ΔR² < 0.15 or CI-straddling): reported as partial separability, no binary verdict — the decomposability fraction with its CI is the result.
- H3 confirmed: R²(`arm_ctx`) − R²(`arm_qry_i`) ≥ 0.10, CI excluding 0.
- All arms must clear their own max-over-layer permutation band to be interpreted at all; an arm inside its band is reported as null.

## 11. Decision Rationale

One entry per load-bearing value (grouped where shared):

- **Ridge-only read-outs, λ grid `[1e-2…1e3]`, nested PRESS-LOO, standardize-X/center-Y.** Why: the line's locked solver; nonlinear estimators buy nothing on these maps. Source: #722 (MLP negative at every layer), #823 hparam table, `issue658_fit_predictors.py::RIDGE_LAMBDAS`. Alternatives: GCV grid per #823 — equivalent; MLP — rejected by #722 and the task body's "ridge ONLY".
- **PCA-48 target (train-fold-fit), skill-over-mean R².** Source: #722/#810 (`PCA_TARGET_DIM_CAP=48`, `robust_pca_basis`); train-fold-only basis is the LOFO-clean tightening (divergence noted §12). Alternatives: ambient-H target (kept as secondary read); 64-dim (#722 used 64 for M-fits — 48 is the reconstruction-line pin).
- **PCA-48 input features.** Source: #722 ("PCA-48/whiten-48 inputs reproduce it on 28/28 layers, max |ΔR²| 0.018") — also the vectorization lever that keeps 12.5K fits at minutes. Alternatives: full-H dual ridge everywhere — the #823 blowup class; retained only as the L18 spot-check.
- **Same-layer binding, sweep L0–27; frozen headline layer 18.** Source: #722 (peak layer 18; recipe c_C[L] → summary[L]) and #810 (same-layer sweep). Alternatives: (feature × target) 28×28 layer grid — rejected: 28× fit multiplier, no hypothesis it serves, extra selection surface; revisit only as a follow-up if the same-layer read is null.
- **Folds: LOFO 7 families (Source: #810 + `ood-generalization-folds.md`); 4 query folds of 36 (25% held out, ≥108 train queries).** Query-fold count is a design choice, not a smoke-testable hparam: 4 balances train-query count against test coverage; results pool over all folds so the number only sets variance. Source: reasoned (fold-count insensitive by construction); flagged Low-stakes in §12.
- **Generation recipe for new arms: greedy temp 0.0, `max_new_tokens=512`, vLLM.** Source: #658 G1 (`V0_MAX_NEW_TOKENS=512`, `SamplingParams(temperature=0.0)`) — matched exactly so new cells join the store cells without a provenance confound.
- **UC query bank 144 (=48 store + 96 fresh, 2 per Betley length target).** Why: 48 distinct query feature vectors is thin for the query-side map (36 train queries/fold); 144 gives ≥108 — the regime where the line's n=50-context fits already worked (#810 identity ceiling 0.857 at n=50). Source: reasoned from #810's estimator-ceiling precedent; the 96-vs-more tradeoff is GPU-cost-bounded (§9). Not smoke-testable; power argument stated.
- **OOD corpus: Dolly-15k, 48 instruction-only rows, length-matched.** Why: human-written (tier 1–2), established, disjoint from both UC (LLM-generated) and WildChat (already a context family — using WildChat queries would collide with the context axis). Source: `databricks/databricks-dolly-15k` (HF dataset, existence verified at implementation); length-match recipe Source: #594 builder.
- **Query-only null-context presentations (empty-system primary; no-block; masked-context).** Source: task body's three named presentations; primary = (i) pre-registered (template-faithful, minimal intervention). Alternatives: picking best-of-3 post hoc — rejected (selection asymmetry); (iii) kept because it uniquely controls the positional confound against `arm_full`.
- **Null battery: 1000 label permutations, per-draw max-over-layer, per-draw λ re-selection via batched PRESS, X-side factorizations shared across draws.** Source: #810 (`issue810_batched_null.py` `_loco_ridge_pred_batched` — λ argmin per draw over precomputed per-λ inverses, "no λ leakage"; the body's 1000-perm spec); `selection-symmetric-nulls.md`.
- **Bootstrap: 2000 family-cluster draws.** Source: #810 (2000 paired draws precedent); cluster unit = family per `ood-generalization-folds.md` rule 5.
- **Blend protocol (inner-val: 1 rotating train family + 25% train queries; 2-parameter LS).** Source: `ungrounded — needs smoke-test` (new; verified in the smoke by asserting blend ≥ min(single arms) − ε on the smoke cells; harmless if suboptimal — blend is secondary to concat).
- **Reused input-data artifacts:** the two `answer_spans` packs + manifests + `v0_summaries.pt` — Source: #658 (+ its UC genre round); fetched on the target backend by explicit `hf_hub_download` in the workload (GCP lanes stage nothing locally; verified reachable, §10). `battery.json`/probe JSONs — Source: #594; git-clone-reachable. Phase-0 outputs committed before dispatch.
- **Model id:** repo-established (`configs/`, every parent issue) — no AutoConfig smoke needed.
