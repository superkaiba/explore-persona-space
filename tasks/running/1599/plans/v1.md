**Which timestamp is "the merge/close time" — grounded on real rows (design consideration 1):**

Observed marker shapes on live terminal wf-fix tasks (read 2026-07-22):

- `tasks/completed/1579/events.jsonl`:
  `{"ts":"2026-07-21T06:38:56Z","kind":"epm:created",...}` →
  `{"ts":"2026-07-21T10:46:50Z","kind":"epm:status-changed","version":1,"by":"task.py","from":"reviewing","to":"completed","note":"Step 10 auto-complete: ..."}` →
  `{"ts":"2026-07-21T10:46:53Z","kind":"epm:done",...}` →
  `{"ts":"2026-07-21T11:00:26Z","kind":"epm:merged","version":1,"by":"unknown","note":"Step 10d auto-merge: PR #1356 squash-merged to main (... merge sha f0770307ce...)"}`
- `tasks/completed/1554/events.jsonl`: same four-kind shape (flip `09:07:41Z` → done `09:07:44Z` → merged `09:19:52Z`).
- `tasks/completed/1577/events.jsonl`: `epm:merged` `10:57:07Z` posted BEFORE `epm:done` `10:59:29Z` — **marker order varies**, so the rule is **max over the signal set, never "the last row"**.
- `tasks/archived/1101/events.jsonl`: `{"ts":"...","kind":"epm:status-changed","from":"proposed","to":"archived"}` — archived tasks close via the terminal status flip only (no merged/done), and the structured `to` field is present on archived rows too.

Chosen rule: `closed_ts = max ts over rows where kind ∈ {epm:merged, epm:done, epm:promoted} OR (kind == epm:status-changed AND row["to"] ∈ TERMINAL_STATUSES)`, `None` when no such row parses → fall back to the existing creation rule. **`epm:merged` is load-bearing:** on the incident timeline the terminal status flip (`10:46:50Z`) PREdates the park (`10:59:07Z`) — a status-changed-only or `epm:done`-only key would NOT suppress the incident shape; only the merge (`11:00:26Z`) postdates the park. `epm:promoted` is included for parity with `task_workflow`'s canonical closure-kind pair (`_WF_FIX_CLOSURE_EVENT_KINDS`); it never fires on `kind: infra` tasks (promote is the experiment path) and costs one frozenset member.

**Deliberate non-reuse of `task_workflow._wf_fix_closed_at`** (checked per the reuse-before-building rule): that private helper (`src/explore_persona_space/task_workflow.py:1136`) computes "ts of the LAST `epm:status-changed`/`epm:promoted` row" — it (a) EXCLUDES `epm:merged`, the signal the incident shape requires; (b) takes the last row rather than the max over a set; (c) excludes tz-naive ts where the sweep's `parse_ts` assumes UTC; (d) is a private underscore API. A new local helper mirroring `_task_creation_ts`'s conventions is the fit; the plan does not modify `task_workflow.py`.

**Auditability naming (design decision, per the brief's "pick a name"):** keep `kind: "fp-tag-closed"` for both temporal branches and add an additive `basis: "creation" | "close"` field, rather than minting a new kind string (`fp-tag-closed-merged-after-park`). Verified consumers of the `suppressed_by.kind` strings in the main tree: the script itself, `tests/test_sweep_parked_wf_candidates.py` (two exact-equality asserts), and historical #1132 plan docs; `.claude/skills/daily/SKILL.md` does not parse the kind strings (Step C defers to `--help`, line 387). Keeping the kind vocabulary stable means any consumer switching on `kind` is untouched; the `basis` field is additive JSON. Cost: existing test 6a's exact-equality assert gains the field (listed in §3.4).

### 3.1 `scripts/sweep_parked_wf_candidates.py` — new constant + helper

Near `TERMINAL_STATUSES` (line 106):

```python

# load-bearing: on the motivating incident the terminal status flip PREdated
# the park while the Step 10d merge POSTdated it (#1577 park 10:59:07Z between
# #1579's flip 10:46:50Z and merge 11:00:26Z). epm:promoted mirrors

_CLOSE_EVENT_KINDS = frozenset({"epm:merged", "epm:done", "epm:promoted"})
```

New helper, placed directly after `_task_creation_ts` (line 403):

```python
def _task_closed_ts(task_dir: Path) -> datetime | None:
    """Latest merge/close-signal ts in events.jsonl; None when no such row parses.

    Max ts over rows whose kind is in _CLOSE_EVENT_KINDS plus
    epm:status-changed rows whose structured ``to`` is terminal
    (completed/archived). Max, never "the last row": marker order varies
    (#1577 posted epm:done AFTER epm:merged; #1579 the reverse). Unreadable
    file / no close-signal row / unparseable ts -> None; the caller falls
    back to the creation-ts rule (fail-open toward ENUMERATION, never a
    silent drop).
    """
    events = task_dir / "events.jsonl"
    try:
        # split("\n"), NEVER splitlines(): splitlines() splits on U+2028/U+2029
        # etc. and shreds valid JSONL rows whose note strings carry them
        # (.claude/rules/gotchas.md "splitlines shreds JSONL", #950).
        lines = events.read_text(encoding="utf-8").split("\n")
    except OSError:
        return None
    closed: datetime | None = None
    for line in lines:
        if not line.strip():
            continue
        # Cheap substring prefilter before json.loads (the task_workflow
        # _wf_fix_closed_at pattern; live events files run to hundreds of rows).
        if (
            '"epm:merged"' not in line
            and '"epm:done"' not in line
            and '"epm:promoted"' not in line
            and '"epm:status-changed"' not in line
        ):
            continue
        try:
            row = json.loads(line)
        except json.JSONDecodeError:
            continue
        if not isinstance(row, dict):
            continue
        kind = str(row.get("kind") or "")
        if kind not in _CLOSE_EVENT_KINDS and not (
            kind == "epm:status-changed" and row.get("to") in TERMINAL_STATUSES
        ):
            continue
        dt = parse_ts(row.get("ts"))
        if dt is not None and (closed is None or dt > closed):
            closed = dt
    return closed
```

Conventions honored (design consideration 3): `split("\n")` never `splitlines()` (#950 — the `workflow_lint.py` jsonl-splitlines check scans this module, `tests/test_workflow_lint_jsonl_splitlines.py`); skip-silently on unparseable rows (matching `_task_creation_ts` — no `skipped_rows` counting inside per-task helpers); aware-UTC ts via the existing `parse_ts`. Task events.jsonl rows use the bare `"kind"` key (the `kind`/`marker` variance handled by `_row_kind` is a cache-file concern; `_task_creation_ts` likewise reads task rows directly).

### 3.2 `_fp_tag_scan` — modified terminal branch (lines 406-426)

```python
def _fp_tag_scan(
    bodies: list[tuple[int, str, Path, str, dict]], fp: str, cand_ts: datetime
) -> dict | None:
    """Suppression rule 2: an infra task carrying this fp (tag or Provenance line).

    Non-terminal hit -> suppress unconditionally; terminal hit -> suppress when
    the candidate ts PREdates the task's merge/close time — the creation ts
    (first parseable row; the pre-#1599 rule, checked first) or the close ts
    (_task_closed_ts: max over epm:merged / epm:done / epm:promoted / the
    terminal epm:status-changed). The creation-only key missed the
    created-before-park/merged-after-park window (#1599: #1577's park at
    10:59:07Z sat between #1579's creation and its 11:00:26Z merge). An
    unreadable creation AND close ts fails toward ENUMERATION (treated as a
    re-raise), never toward a silent drop. suppressed_by carries
    basis: "creation" | "close" for auditability; kind stays "fp-tag-closed".
    """
    for tid, status, body_path, text, fm in bodies:
        if fm.get("kind") != "infra":
            continue
        if f"wf-fix-fp:{fp}" not in text and f"fingerprint: {fp}" not in text:
            continue
        if status not in TERMINAL_STATUSES:
            return {"kind": "fp-tag-open", "ref": f"#{tid}"}
        created = _task_creation_ts(body_path.parent)
        if created is not None and created > cand_ts:
            return {"kind": "fp-tag-closed", "ref": f"#{tid}", "basis": "creation"}
        closed = _task_closed_ts(body_path.parent)
        if closed is not None and closed > cand_ts:
            return {"kind": "fp-tag-closed", "ref": f"#{tid}", "basis": "close"}
    return None
```

Ordering rationale: creation-first preserves the pre-#1599 code path and labeling exactly for the already-covered case, and short-circuits the second file read in the common case (candidate predates fix creation). Since creation ≤ close on any sane events file, the new window decided by `basis: "close"` is exactly `created ≤ cand_ts < closed`. A terminal hit failing BOTH checks continues scanning the remaining bodies (unchanged — another task carrying the fp may still decide).

**Wall-time (design consideration 2):** the events.jsonl read still happens only on a TERMINAL fp hit (rare — rule 2 returns on the first hit; the body pool is loaded once per sweep, unchanged), now at most TWO reads of the same small file per such hit instead of one, and only when the creation check does not decide. Worst-case unbounded audit (~109 candidates on the live tree) adds ≤ ~109 extra small-file reads — well inside the module docstring's <30 s bound. Two mirrored single-purpose helpers are chosen over a combined one-pass helper for minimal diff + independent testability; the double read is deliberate and stated.
