## 3. Method delta

**What differs from the current recipe:** today the recipe is reactive-only (shapes 0-2 fire AFTER a burned attempt) and has NO shape for `Head branch is out of date`. This plan adds (A) a PROACTIVE, read-only head-sync pre-check immediately before the first `gh pr ready`/`gh pr merge` (inside the verdict-gated conditional), and (B) a new REACTIVE Known failure shape 3 codifying the #1614 diagnosis + the close/reopen nudge, so the class never again falls through to the ~16-min "(anything else)" recovery.

**Why (iv) beats the alternatives, against tensions (a)-(d):**

- **(i) `gh pr update-branch [--rebase]` pre-merge — rejected.** It does not address the observed failure mechanism (the PR object lagging the session's OWN push; #1614 merged the same behind-main tip unchanged) and it actively violates tension (a): the default form's merge commit breaks the `--rebase` merge form on experiment branches (shape 1), and the `--rebase` form rewrites the remote head, forcing a worktree-divergence recovery and invalidating the SHA-bound lint verdict (the certified tip no longer exists). It would also fail on #779's real conflicts exactly as the merge did.
- **(ii) worktree `git merge origin/main` + squash-everything — rejected.** Push-safe (tension b avoided) but changes the experiment-branch merge granularity project-wide (the #1493 rationale keeps `--rebase` for per-commit revert value), mutates the tip (forcing a gate re-run on EVERY merge — tension c — adding ~4.5-6 min of lint wall to every Step 10d), and still cannot pre-empt the observed failures (#1614 was not a mergeability problem; #779's conflict needed the recovery machinery regardless).
- **(iii) pure no-op/deflect — rejected.** The forensics DO show a real, recurring, recipe-visible gap: an unclassified failure shape that burned 2 attempts + an improvised recovery on #1614, plus a first-attempt window (merge issued immediately after a push, against a possibly-stale PR object) that a read-only wait provably closes. A reasoned no-change would leave the next session to re-improvise the nudge.
- **(iv) chosen: read-only pre-check + shape-3 codification.** Tension (a): no update-branch → no merge commit, `--rebase` intact. Tension (b): nothing rewrites commits → no force-push anywhere. Tension (c): the pre-check NEVER mutates the branch tip, so the SHA-bound lint verdict (bound "immediately before `gh pr ready` / `gh pr merge`", line 10677) remains valid by construction; the pre-check runs INSIDE the verdict-gated conditional, after the sha check passes and before `gh pr ready` — no gate re-run needed, no reordering of guards 0-3 / fast-path / gate. Tension (d): Guard-1 strip, Guard 3, fast-path, and the conflict recovery are byte-untouched; shapes 0-2 remain verbatim as backstops (the pre-check REDUCES the base-advance window for shape 0 as a side effect — a settled mergeability read pre-merge — but does not claim to eliminate it).

```bash
    # Head-sync pre-check (#1657, READ-ONLY — the tip is untouched, so the
    # SHA-bound verdict above stays valid): every push this invocation made
    # (Guard-0/1 commits, the pre-gate spec-freshness commit) races
    # GitHub's PR-object sync — #1614's attempts 1-2 were refused
    # 'Head branch is out of date' while the PR object lagged the pushed
    # tip ~6 min. Poll until the PR object reports the local tip AND a
    # settled mergeability; a settled CONFLICTING exits too (the merge
    # attempt then classifies to shape 2 below, unchanged). Check-first
    # bounded until-loop — never a leading foreground sleep
    # (harness-blocked; the shape-0 convention).
    TIP=$(git -C "$WT" rev-parse HEAD); HS_TRIES=0
    until HS=$(gh pr view <PR> --json headRefOid,mergeable -q '.headRefOid + " " + .mergeable' 2>/dev/null) \
          && [ "${HS%% *}" = "$TIP" ] && [ "${HS##* }" != "UNKNOWN" ]; do
      HS_TRIES=$((HS_TRIES + 1))
      if [ "$HS_TRIES" -ge 6 ]; then
        echo "head-sync pre-check: PR object still stale after ~2 min (saw: ${HS:-<no read>}; local tip: $TIP) — proceeding; Known failure shape 3 below is the recovery"
        break
      fi
      sleep 20
    done
```

Semantics: common case (PR object already synced, mergeability settled) = ONE `gh pr view` call, ~0.5 s. Stale case = up to 6 checks × 20 s ≈ 2 min, then proceed anyway (fail-toward-attempting; shape 3 is the backstop). A transient `gh pr view` failure leaves `HS` empty, the `&&` chain falls to the loop body, and the same bound applies. `sleep 20` inside a check-first until-loop is the sanctioned poll form (shape-0's own convention, echo line 10848; the harness blocks only LEADING foreground sleeps). No pipes on any git/gh mutation command (`guard_piped_git_push.sh` untouched).
