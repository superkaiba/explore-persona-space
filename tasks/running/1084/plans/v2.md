## 4. Design

### 4.1 The two orderings, weighed (body asks explicitly)

- **Option A — post-before-rename + idempotent post (CHOSEN, and current ordering).** Crash before post → nothing posted, sentinel unprocessed → next tick posts (no loss). Crash after post / rename failure → sentinel unprocessed → next tick fp-hits → rename-only (no duplicate). The post is a LOCAL VM write (`events.jsonl` under flock, durable-append-then-commit — `task_workflow.py:3185-3194`); the rename is the REMOTE SSH op. Putting the fragile remote op LAST means the fragile op's failure mode is "retry a now-idempotent replay," never "lose a marker."
- **Option B — rename-before-post + drain-in-progress breadcrumb (REJECTED).** A crash between rename and post strands the marker unless a breadcrumb is (a) written durably BEFORE the rename, (b) itself drained by a recovery pass on every tick, and (c) itself idempotent — i.e. it re-creates the same crash-window problem one level down, adds a new on-disk state machine to the poller, and puts the remote SSH op FIRST so every transport flake converts into breadcrumb-recovery work. Strictly more moving parts for the same guarantee A gives with one hash. (§11 entry 2.)

### 4.2 The dedupe key (body Q1)

**Key = sha256 over `remote_path + "\n" + raw sentinel body`, truncated to 16 hex chars, stored as a `sentinel_fp` extra on every drain-posted event.** Rationale:

- **(kind, version) alone is UNSAFE.** Writers hardcode `version: 1` per kind (`i488_phase2_ladder.py:210/:236` — `epm:smoke-result` v1, `epm:failure` v1; `issue922_common.write_results_sentinel` defaults `version=1`), and nothing in the pod-side contract forbids a dispatcher emitting two `epm:progress` v1 sentinels with different notes across phases. A (kind, version) dedupe would silently suppress the second, legitimately distinct signal — data loss, worse than the duplicate it prevents.
- **(kind, version, content-hash) without the path is still not exact:** two byte-identical progress payloads written at different epochs (two phases both reporting `"phase complete"`) are distinct signals. Including `remote_path` — unique per sentinel by the writer contract (epoch-suffixed filenames, never reused; `_ssh_mark_processed` docstring `:1767-1769`) — makes the ONLY thing that can dedupe be a re-drain of the SAME file, which is exactly and only the W1 window.
- **Hashing the RAW body string (as delivered by `parse_sentinel_stream`)**, never a re-serialized JSON, eliminates the JSON-key-ordering instability risk outright (§7 risk 3). The body of an unchanged file is byte-stable across ticks (both lanes deliver it through `parse_sentinel_stream`'s deterministic join+strip).
- **Same-(kind,version)-different-content hit behavior:** with this key it is NOT a dedupe hit — it posts, as today (writer version-reuse is a pre-existing writer-side behavior, out of scope to police). Additionally, a same-`sentinel_path` different-fp match logs a loud warning and still posts (fail-open + loud, per the fail-fast philosophy).
- **Synthesized-envelope (`version=None`) path:** the posted version varies (max+1), so version cannot be in the key anyway; the content+path fp covers it uniformly — a re-drained rescue fp-hits regardless of what version the first post derived.
- **fp contract (r2):** the hash input is the PARSER-DELIVERED body string (`parse_sentinel_stream`'s deterministic join+strip of the drained stdout), NOT literal file bytes. That normalized string is byte-stable across replay ticks for an unchanged file on both lanes; tests treat it as the contract.
- **Concurrency scope (r2, honest wording):** the guarantee is exactly-once PER DRAINER. The dedupe read runs outside `post_event`'s flock, so two concurrent drainers (a manual drain racing the live poller — the #952 recovery shape) that both read before either posts can still duplicate. That degradation is loud, benign, and identical to today's behavior; single-poller-per-issue is the designed topology (Step 0 single-orchestrator guard). An under-lock check would need a `task_workflow` API change (§10 must-ask) and is deliberately out of scope.

### 4.3 Where the check lives (body Q2)

Entirely inside `drain_sentinels_via` (transport-agnostic — both lanes + all tests inherit it; zero caller changes; `gcp.py`'s only edit is the W2 timeout catch). Events access is the module-level `list_events` name (add to the existing import block at `poll_pipeline.py:344-349`), monkeypatchable exactly like `pp.post_event`. Cost: ONE `events.jsonl` read per drain invocation, and only lazily when ≥1 sentinel parsed (~500 rows ≈ 100 KB JSONL via the tolerant `_iter_jsonl` reader — milliseconds; poll ticks are 30–60 s apart).

```python
def _sentinel_fingerprint(remote_path: str, body: str) -> str:
    """Stable idempotency key for ONE drained sentinel: the remote path
    (unique per sentinel — epoch-suffixed, never reused) + the raw body
    text. Hashing the raw string (never re-serialized JSON) makes the fp
    immune to key-ordering; including the path makes cross-sentinel
    false-positive dedupe structurally impossible (#1084)."""
    return hashlib.sha256(f"{remote_path}\n{body}".encode("utf-8", "replace")).hexdigest()[:16]


def _posted_sentinel_fps(issue: int) -> dict[str, dict[str, Any]]:
    """Map sentinel_fp -> already-posted event row for task ``issue``.

    Reads events.jsonl once via ``list_events`` (tolerant reader). FAIL-OPEN:
    on any read failure, log.error and return {} — degraded mode re-posts
    (today's behavior); a lost marker is never a possible outcome."""
    try:
        events = list_events(issue)
    except Exception as exc:
        log.error("dedupe events read failed for #%d (%s); posting without dedupe", issue, exc)
        return {}
    return {e["sentinel_fp"]: e for e in events if isinstance(e.get("sentinel_fp"), str)}
```

## 11. Decision Rationale

1. **Dedupe key = sha256(remote_path + "\n" + raw body)[:16], stored as a `sentinel_fp` event extra.** *Why:* only a same-file re-drain (the exact W1 window) can match; immune to writer version-reuse and to JSON re-serialization drift. *Source:* code reading — hardcoded `version: 1` writers (`i488_phase2_ladder.py:210/:236`, `issue922_common.py:596`), the never-reuse-filenames writer contract (`poll_pipeline.py:1767-1769`), `post_event`'s `**extras` mechanism (`task_workflow.py:3150/:3184`). *Alternatives:* (kind, version) — rejected, suppresses legitimately distinct same-version sentinels; (kind, version, content-hash) without path — rejected, merges byte-equal signals from different files; scanning for a byte-equal `note` at the same kind — rejected, misses the oversize-pointer replay (pointer note ≠ sentinel note) and costs a full-note comparison per event.
2. **Ordering = Option A (post-before-rename, already current) + idempotent post.** *Why/Source/Alternatives:* §4.1 — Option B re-creates the crash window one level down (breadcrumb durability + its own drain + its own idempotency), puts the remote op first, and adds a poller-side state machine; the incident record (#952 events, 00:02–00:07Z) shows the manual-drain-then-hand-check cost this removes. Rejected in full.
3. **Check lives in `drain_sentinels_via`; events via module-level `list_events`.** *Why:* one transport-agnostic site → both lanes + tests inherit; monkeypatchable like `pp.post_event`. *Source:* GCP delegation (`gcp.py:5232`), #899/#975 plan precedent ("gcp.py has no copy — no change"), test aliasing note (`test_poll_pipeline_sentinels.py:1485-1490`). *Alternative:* per-lane checks — rejected (drift; the #608 shared-loop design reason).
4. **Fail-OPEN on events-read failure.** *Why:* the Goal's hard constraint is "never strands an un-posted result" — a fail-closed dedupe could convert a transient read error into a lost marker; a duplicate in degraded mode is the status quo and is loudly logged. *Source:* Goal text + fail-fast philosophy (loud, not silent). *Alternative:* fail-closed skip — rejected as strictly worse than the bug being fixed.
5. **W2 = catch-and-degrade at existing bounds; NO new timeout values.** *Why:* both transports are already time-bounded (RunPod 60 s drain / 30 s rename, `poll_pipeline.py:1754/:1783`; GCP 300 s `GCLOUD_DEFAULT_TIMEOUT_SEC`, `gcp.py:2965`) — the gap is that `TimeoutExpired` escapes uncaught; catching it (in `drain_sentinels_via` for `mark_processed`+RunPod list, in `gcp.py:5208` for the GCP drain list) converts a hang into the existing retry/alarm semantics that the new idempotency makes safe. Threading a tighter GCP timeout would break the argv-only `GcloudRunner` injectable protocol (`gcp.py:2957`) used across the gcp test suite. *Source:* code reading of both transports + the `_gcp_gpu_util_probe` precedent (`gcp.py:5296-5299` — catches `TimeoutExpired` "rather than blocking the poll tick"). *Alternative:* `subprocess.run(timeout=60)` inside `_mark_sentinel_processed` via a runner-protocol change — rejected as out-of-scope surface churn for a secondary deliverable.
6. **Loud `log.error` on every dedupe skip, naming matched ts/kind/version/fp.** *Why:* a silent skip would be indistinguishable from a dropped sentinel; a dedupe hit means a prior tick crashed/failed mid-drain — operator-relevant. *Source:* the fail-fast Critical Rule (CLAUDE.md "Fail fast — never hide failures") + the orchestrator's task brief. (r2 attribution fix: the task body's `## Constraints` lists only lint/ruff/tests — the loud-log requirement comes from the Critical Rule, not the body.) *Alternative:* `log.info` — rejected.
7. **N/A — no model training; no hyperparameters in this task type.**
8. **In-loop fp-map update after every successful post (r2).** *Why:* without it, a duplicate `(path, body)` tuple within ONE drain listing posts twice — currently unreachable (RunPod's single glob; GCP's fallback glob roots in a disjoint directory), but a future overlapping `extra_globs` would silently reopen the same-tick double-post, and the one-line insert closes it structurally. *Source:* Codex-alternatives Must-Fix + Claude-alternatives Concern 2 (both derived from the §4.4 sketch); glob disjointness verified at `poll_pipeline.py:1670-1706` + `gcp.py:5198-5199`. *Alternative:* rely on glob disjointness forever — rejected (unenforced invariant; test 15 pins the fix).
