# Plan — task #777 (workflow-fix infra): flip the dual-DV continuous-companion preference

## 0.0 TL;DR (plain English)

- **What I'll run:** No experiment. I'm correcting a written rule that currently
  recommends the wrong "second yardstick" for measuring leaked behaviors. The rule
  says to prefer averaging a probability over only the model's *positive*
  completions; a recent analysis showed that yardstick points the *wrong way*
  (it goes down when the behavior goes up). I'm flipping the recommendation to the
  yardstick that was shown to work — comparing the model's probability of a *fixed*
  set of yes-behavior vs no-behavior answers — and adding a warning about why the
  old one is biased.
- **What I expect:** A handful of surgical text edits across the rule files and
  the agent files that restate the rule, leaving the rest of the measurement
  policy (the primary judged-rate yardstick, the "must validate it tracks the
  rate" gate) untouched.
- **What would change my mind:** If I'd found the old wording was load-bearing
  somewhere I missed, or if flipping it accidentally weakened the requirement that
  the primary behavioral measure stays the on-policy judged rate. (I checked — it
  doesn't.)

## 2. Prior Work

- **The #722 finding (artifact-confirmed).** #722's continuous-DV thread ran two
  attempts at a non-saturating companion to the judge rate:
  - *Attempt 1 — `logp_pos_mean` FAILED.* It is a length-normalized base-model
    log-P averaged over ONLY the judged-positive completions per context — a
    conditional mean over an outcome-selected subset. Its validation correlation
    ρ(DV, rate) came out ≈ **−0.3 (NEGATIVE)** for 3 of 4 behaviors, failing the
    rule's own ρ(DV, rate) > 0 gate. Root cause is selection-on-outcome: a context
    with more positives drags down the *mean* log-P among them, so the conditional
    mean moves opposite the rate.
  - *Attempt 2 — teacher-forced FIXED ± margin WORKS.* `margin(C) = mean
    LN-logP(FIXED positive answers | C) − mean LN-logP(FIXED negative answers | C)`,
    using a SINGLE judge-filtered fixed pos/neg answer pool applied across ALL 50
    contexts → no selection bias. Validation ρ(margin, rate) (verbatim from
    `eval_results/issue_722/tf_margin/margin_chain.json`, §11 source): refusal
    **+0.560** [+0.142, +0.803], sycophancy **+0.397** [−0.030, +0.679], broad_em
    **+0.306** [−0.200, +0.667] — all POSITIVE points (sign reversed vs
    `logp_pos_mean`). Non-saturating where the rate floors: broad_em `margin_std`
    = **0.310** while the rate range was [0.00, 0.05]. `harmful_compliance` was
    untestable (no fixed pos/neg pool — same reason it has no `r_B`).
- **The CLAUDE.md history.** The current wording came in as the 2026-06-15
  "Standing rule, Thomas" that introduced the dual-DV clause. It set "(b) a
  continuous completion-probability DV … length-normalized trained−base `log P`
  of the model's OWN judged-positive on-policy completions (preferred, stays
  on-policy), or a teacher-forced fixed positive-vs-negative completion margin
  (opt-in alternative)". That preference is what #722 empirically inverted; this
  task corrects it.

`N/A — no training hyperparameters` (no model training).

empirically, not as a hyperparameter:

- **What:** Prefer the teacher-forced fixed ± completion margin over `logp_pos_mean`.

  the negative-validation summary is the #722 body/marker interpretation, not a
  standalone `result4b_continuous_dv.json` — see §12 A5).
