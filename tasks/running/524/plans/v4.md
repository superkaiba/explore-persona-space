## 3. Hypothesis

Goal-canonical: a directional/asymmetric base-model predictor recovers the antisymmetric component of marker-leakage transfer on the unified instruction+ICL panel.

### What would update the belief

- A directional predictor with a nested-CV incremental ΔR² CI excluding 0 on full ΔG, that ALSO scores non-zero vs ΔG_anti and survives the held-out pool → real recoverable directional leakage signal; name it.
- All directional predictors at incremental ΔR² ≈ 0 (CI spans 0) and ΔG_anti ≈ 0 → the directional 28% is not linearly recoverable from base-model geometry; a strong bound on the program (subject to the §3 100-Q attenuation caveat below).
- Cross-type (ICL↔instruction) cells: does the predictor that wins within-type also win across induction mechanisms?

### Falsification criteria (single-arm clear PASS/FAIL)

- **CLEAR PASS:** at least one directional predictor's paired nested LTCO-CV pooled out-of-fold incremental skill (ΔR²_pooled, or unified censored ΔLL when censored fraction ≥ 10% on any block) over `M_sym = ΔG ~ gauss_kl_L22 + length` has a context-clustered dyadic bootstrap CI strictly above 0 on the full 992-pair panel AND standalone ρ vs `ΔG_anti` has CI strictly excluding 0 AND the asymmetry-vs-asymmetry correlation `ρ[½(d[A,B]−d[B,A]), ΔG_anti]` has CI strictly excluding 0 AND the winner replicates on the #523 held-out probe pool.
- **CLEAR FAIL (strong null):** every directional predictor has incremental ΔR² CI overlapping 0 AND ρ vs ΔG_anti CI overlapping 0. Load-bearing outcome — bounds the program. **Contingent on the §3 100-Q attenuation caveat below.**
- **PARTIAL:** incremental ΔR² CI excludes 0 but the directional fraud check fails (ρ vs ΔG_anti includes 0). The predictor is gaining nominal R² by improving the symmetric baseline, not by recovering directional structure — descope the headline.

### 100-Q attenuation caveat (v4-specific; carried into clean-result scope)

Directional-vs-symmetric null at 100 Q/cell may be **target-noise-limited**: with only 100 questions averaging per ΔG cell, the per-cell standard error of the marker log-prob is roughly √5× larger than at 500 Q (std-error ∝ 1/√n). If every directional predictor's incremental ΔR² CI overlaps zero, that null is partly attributable to thicker target noise; the censored/Tobit unification of `ΔLL` mitigates this, and §A15's smoke-time read at `--cells 1` at the full 100-Q production count is the authoritative recalibration of Phase 2 noise floor. The **CLEAR FAIL verdict is contingent** on the smoke's per-cell ΔG std-error being within 1.5× the v3-projected 500-Q noise — if it's higher, the CLEAR FAIL is downgraded to **INCONCLUSIVE**.

The four-conjunct PASS rule itself stays UNCHANGED. The censored/Tobit `ΔLL` is the headline scalar when censored fraction is high on any block (this was already v3's rule — no change there). The contingency above applies only to the **interpretation of the CLEAR FAIL outcome** in the eventual clean-result, surfaced again in §10 Reproducibility scope-caveats.

### Sub-hypotheses (sidecar reads, not gates)

- Within-type vs cross-type closeness panel.
- Saturation pattern across the four 16×16 blocks: ICL×ICL likely most saturated, instr×instr least.

## 4. Design

### Smoke-architecture parity (UNIFIED — the default)

Dispatcher `scripts/issue524_dispatch.py` runs in-process serial with `--cells 1 --seeds 1 --phase {0,1,2,3}` for smoke and `--cells 32 --seeds 1 --phase all` for sweep. Both modes call the same `train_one_icl_cell(cid, ...)` and `eval_cell(src_cid, tgt_cid, ...)` functions; no subprocess wrapper. Smoke runs ONE ICL cell end-to-end (train → cross-eval against 4 representative targets at 100 Q → extract clouds → predictor → metric) using the exact code path the full sweep uses. Task #397 round-11 unification pattern. **Per-cell Q-count is the SAME in smoke and sweep** (100 Q) — smoke verifies the wall-time per cell at production Q-count, not at a reduced one, so the Phase 2 budget projection is calibratable from the smoke result. The smoke read is ALSO the authoritative per-cell ΔG std-error read for the §3 100-Q attenuation caveat.

**Why code, not a model call?** — The predictor matrices, ΔG matrices, nested-CV scoring, bootstrap, and Tobit fit are deterministic numpy / scikit-learn computations on activation clouds and log-probabilities. A model-call formulation would (a) be vastly more expensive at N=992 ordered pairs × 32 contexts × 28 layers × 9 metrics × 3 extraction points, (b) not produce calibrated CIs from bootstrap, and (c) lose interpretability of the directional functional. The ICL induction-rate manipulation check IS a model call (Sonnet-judged), per §"Phase 0.3".

# scripts/issue524_phase4_predictors.py (NEW; CPU)

def directional_gauss_kl(mu_A, Sig_A, mu_B, Sig_B):  # asymmetric
    return 0.5 * (np.trace(np.linalg.solve(Sig_B, Sig_A))
                  + (mu_B - mu_A).T @ np.linalg.solve(Sig_B, mu_B - mu_A)
                  - mu_A.shape[0]
                  + np.log(np.linalg.det(Sig_B) / np.linalg.det(Sig_A)))

def source_cov_mahalanobis(mu_A, Sig_A, mu_B):  # asymmetric on Σ_A
    diff = mu_B - mu_A
    return diff @ np.linalg.solve(Sig_A, diff)

def asym_subspace_recon(P_A_k, Phi_B):  # asymmetric on rank-k subspace of A
    return np.linalg.norm(P_A_k @ Phi_B) / np.linalg.norm(Phi_B)

def marker_projection(act_A, marker_unembed_dir):  # plain
    return act_A @ marker_unembed_dir / np.linalg.norm(act_A)

def two_feature_combiner(f_geom, f_marker, dg):  # OLS fit
    return ols_fit(dg, [f_geom, f_marker, f_geom * f_marker])
