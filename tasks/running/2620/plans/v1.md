- **The FAIL file's bloat is pure row duplication, not verbose hooks.** 263 bullet rows
  but only 111 unique link targets; 110 of the 111 multi-row targets carry byte-identical
  duplicate rows (the one variant differs by 3 bytes of hook truncation). Multiplicity:
  70 targets ×2, 41 targets ×3. All 111 per-entry files exist on disk; no row is linkless.
- **Measured projection: dedupe to one row per target → 17,522 bytes** (< 20,000, with

- **Root cause of the duplication + hook bypass (acceptance item 4, already established):**
  `.gitattributes:30` pins `.claude/agent-memory/**/*.md merge=union`. Union merge is sound
  for append-only files, but the #2587 r1 g4 dedup/compaction pass (`7aeae13a5b`, 2026-08-25,

  union driver kept both sides wholesale. The FAIL state landed via merge commit
  `3aeb600991` (parents' copies 23,886 B + 17,519 B → 41,371 B ≈ concatenation). Merge
  commits do not run the pre-commit hook (pre-commit installs the `pre-commit` hook, which
  fires on `git commit`; auto-created merge commits and server-side `gh pr merge` bypass it)
  — so the oversized copy landed unchecked, and the hook then reds every LATER worktree
  spec-freshness sync that stages the file (the #2610 symptom).
- Sibling projections: `codex-code-reviewer` dedupe → 16,548 B (12 multi-row targets, 9

## 3. Method

### 3.1 Primary curation — `code-reviewer-lean/MEMORY.md` (the FAIL)

Deterministic dedupe, applied in the issue worktree:

- Iterate lines in order. Keep the header line(s) verbatim. For each bullet row, parse the
  link target; keep the row at the position of the target's FIRST occurrence; drop later
  rows for an already-seen target. For a target with variant rows, keep the LONGEST variant
  (most informative hook) at the first-occurrence position.
- Invariants asserted in-worktree before commit (inline python, not a committed script):
  (a) unique-target set before == after (no lesson lost);
  (b) every kept row's target file exists in the directory;
  (c) resulting size < 20,000 bytes;
  (d) exactly one row per target.

### 3.2 Opportunistic WARN-band pass (body: "if cheap" — it is)

- `codex-code-reviewer/MEMORY.md`: same dedupe (longest-variant rule covers its 3
  near-variant targets). Projected 16,548 B.
- `experiment-implementer/MEMORY.md`: same dedupe, THEN trim the longest hooks (rows
  > ~250 B) to ~1 line ≤ ~150 chars each, per the #1891 recipe. Before trimming a row,
  confirm its per-entry file exists and already carries the detail; if the hook text holds
  detail absent from the per-entry file, append that detail to the per-entry file in the
  same commit (recipe: detail moves, never deletes). Target < 20,000 B.

### 3.3 Verification (in-worktree, before the implementation marker)

- `wc -c` on all three files; `uv run python scripts/workflow_lint.py
  --check-agent-memory-index-size` → zero FAIL rows, zero WARN rows for these three files.
- Acceptance item 3 reproduction: stage the curated file(s) in the worktree and run the
  pre-commit hook on them (`uv run pre-commit run workflow-lint-agent-memory-index-size

### 3.4 Landing discipline (Step 10d deviation — REQUIRED, stated here so the critic can
check it)

The curated files MUST NOT land through a union merge: our curation is exactly the
whole-file-rewrite shape that `merge=union` re-duplicates (§2), so a normal branch merge
would concatenate the curated copy with main's live copy and reproduce the bug at ~59 KB.
Land via the CLAUDE.md-sanctioned scratch worktree detached at `origin/main`:

1. Fetch origin/main; for each of the three files, diff main's CURRENT copy against the
   branch-base copy. Reconcile by TARGET SET: start from the branch's curated content; for
   any link target present on main's current copy but absent from the curated target set
   (a lesson appended by a concurrent session since branch-cut), append that main-side row
   verbatim (deduped to one row). Re-assert invariants (a)-(d) on the composed content.
2. Commit by explicit path in the scratch worktree (`git commit -m ... -- <3 paths>`) —
   this ordinary `git commit` RUNS the pre-commit hook, so the landing itself is the
   acceptance-3 proof — and `git push origin HEAD:main`.
3. The commit message names the durable gap per acceptance item 4: the `merge=union`
   attribute re-duplicates whole-file rewrites of agent-memory indexes, and merge commits
   bypass the size hook (how 41 KB landed on main).

No `.gitattributes` change, no lint-threshold change, no loader change (all out of scope
per the body).
