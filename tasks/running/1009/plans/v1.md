## 3. Design

Insert the following bullet into `.claude/rules/gotchas.md` immediately after the line-150 entry ("vLLM `max_model_len` must track every `max_new_tokens` deviation..."), matching the established entry style. Proposed text, verbatim:

> - **External / real-corpus query banks fed to vLLM: length-validate at LOAD time — a rare overlong row hard-crashes generation mid-production, and a smoke subset structurally never samples it.** vLLM validates every chat-formatted prompt against `max_model_len` and raises `ValueError: The decoder prompt (length N) is longer than the maximum model length` on the FIRST offending prompt; real corpora have unbounded length tails, so one overlong row of hundreds kills the run seconds into the first production chunk while a fully-passing synthetic/subset smoke sees nothing. RULE: filter at the bank LOADER — one enforcement point so EVERY consumer (gen, judge, capture, score) sees the identical row set — by tokenizing each row's FORMATTED prompt exactly as the generate call renders it (`tokenizer.apply_chat_template([{"role": "user", "content": t}], tokenize=False, add_generation_prompt=True)`, then `len(tokenizer(f, add_special_tokens=False)["input_ids"])`; raw-text token counts undercount the template overhead) against `budget = max_model_len − generation max_tokens` (#952: `BANK_PROMPT_TOKEN_BUDGET = SEQ_MAX_LEN − SONNET_MAX_TOKENS` = 8192 − 1024 = 7168 — the surviving prompt still needs the full generation headroom under the cap); drop the ENTIRE matched (e.g. divergent, control) pair when EITHER member exceeds the budget (paired stats require intact pairs); record drops DIGEST-ONLY (index, ids, category, token count — never row text, per the harmful-bank digest-only discipline) to a persisted JSON, and re-check any per-category floor on the post-filter counts. DISTINCT from the inherited-rig entry above: there the model's OWN capped generation re-entered as a prompt overflows a pinned `max_model_len` (fix: bump the call-site value); here the EXTERNAL input row itself is overlong (fix: validate + drop at load — bumping `max_model_len` just moves the tail cutoff). Worked example: `src/explore_persona_space/experiments/issue_952/run_952.py::filter_bank_rows_by_length` (enforced once in `load_bank_queries`; digest record at `eval_results/issue_952/bank_length_filter.json`; commit `5c58fc6a50`).
