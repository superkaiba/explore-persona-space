    return surfaces


def test_no_tokenized_remote_url_in_experimenter_recipes() -> None:
    """The #1239 no-token-in-URL invariant extends to the agent recipe
    surfaces (#1271): ``x-access-token`` may appear only as the credential
    helper's ``username=x-access-token`` line — never as URL userinfo

        assert not re.search(r"x-access-token:\S*@", text), f"token-in-URL userinfo in {rel}"

## 11. Decision Rationale

N/A — no training hyperparameters

- **Recipe mechanism = source-staged-`.env` + idempotent helper refresh + `git fetch origin <branch>`** (the brief's option (a) with a one-line slice of option (b)). Why: the salvage session must source `.env` anyway (WandB/HF/Anthropic phases), so the env-reading helper (byte-same shape as `gcp.py:1384–1385`) suffices in-session; the unconditional `--replace-all` config line covers pre-#1205 clones (live until ~2026-07-16), second clones, and re-runs, at the cost of one line. Source: read `gcp.py:1368–1386`, `bootstrap_pod.sh:39–63`, `tests/test_bootstrap_pod_git_credentials.py`. Alternative rejected: reproducing the full #1239 `.env`-fallback helper string inline — its escaping (`\"`, `\$`) inside nested ssh/sudo quoting is exactly the error class the stdin-script shape avoids, and its benefit (bare git ops in a LATER unsourced shell) is marginal on a ≤7d salvage instance; the memory notes the bootstrap flavor as the pod-side reference.
- **stdin script (`--command='sudo bash -s'` + quoted heredoc) over an inline `sudo bash -c '...'` one-liner.** Why: the helper string needs single quotes at the remote level; nesting them inside `--command='...'` is impossible and double-quote escaping across two shells is the known trap; stdin is the same channel step 1 already uses for `.env`. Source: #653 salvage companions (quoting incidents) + `bootstrap_pod.sh` quoting-invariant comments.
- **Host-scoped key (`credential.https://github.com.helper`) over `gcp.py`'s unscoped repo-local key.** Why: #1239's hygiene rationale (token never offered to a non-GitHub remote); coexists with the #1205 helper — git queries helpers in config order and both yield the same credentials. Source: `bootstrap_pod.sh:51–52` + #1239 plan.
- **`GIT_TERMINAL_PROMPT=0` in the recipe.** Why: converts a genuinely-missing token into a loud failure instead of a non-TTY hang — parity with `gcp.py:1382`. Source: read code.
- **Drop the `Authorization: Bearer` caveat.** Why: it was a reason for token-in-URL over header auth; under a credential helper git sends Basic auth (username/password), which classic `ghp_` PATs accept — the caveat is moot and carrying it forward would re-justify the banned form. Source: brief nuance 4 + git-credential semantics exercised by the #1239 functional test.
- **Pin-test scope** (§4.4): all `.claude/agents/*.md` + `.claude/agent-memory/experimenter/*.md`; not all agent-memory (runtime-written; broad ban = follow-up), not `.claude/plans/` (frozen records). Extending the EXISTING #1239 test file over a new file keeps the invariant family in one place (the file the incident record names). No new functional helper test — the helper string is byte-same in shape as the #1205 one and the #1239 file already functionally tests the richer flavor; a duplicate would test the same sh semantics twice.
