## 4. Design

**Exclusion-set decision:** `/tmp/`, `/dev/shm/`, and `/var/tmp/`. Justification: all three are the standard Linux world-writable ephemeral scratch roots; the repo lives under `/home/thomasjiralerspong/`, so no repo-tracked `.py` can ever sit under them — exclusion is over-broad-proof by construction. `/var/tmp/` is included because it is the reboot-persistent twin of `/tmp` and used interchangeably for scratch; a scratch script there breaks Edit anchors identically. No other roots (e.g. `/run/`): not used for `.py` scratch in this project's practice, and every added alternation is one more byte to maintain — keep minimal. Note `pytest`'s `tmp_path` also lives under `/tmp/`, so the exclusion additionally stops the hook racing test-fixture writes. The `^/` anchor means a repo-relative `tmp/foo.py` (or the repo path `.../explore-persona-space/tmp/...`) is NOT excluded — repo-tree behavior unchanged.

**Before (exact current bytes — `.claude/settings.json` line 162, JSON-escaped as stored):**

```json
"command": "file_path=$(jq -r '.tool_input.file_path // .tool_response.filePath // empty'); if [ -n \"$file_path\" ] && echo \"$file_path\" | grep -qE '\\.py$'; then cd /home/thomasjiralerspong/explore-persona-space && uv run ruff check --fix --quiet \"$file_path\" 2>/dev/null; uv run ruff format --quiet \"$file_path\" 2>/dev/null; fi"
```

**After (JSON-escaped as stored — the ONLY change is the inserted `&& ! echo ... grep -qE '^/(tmp|var/tmp|dev/shm)/'` clause):**

```json
"command": "file_path=$(jq -r '.tool_input.file_path // .tool_response.filePath // empty'); if [ -n \"$file_path\" ] && echo \"$file_path\" | grep -qE '\\.py$' && ! echo \"$file_path\" | grep -qE '^/(tmp|var/tmp|dev/shm)/'; then cd /home/thomasjiralerspong/explore-persona-space && uv run ruff check --fix --quiet \"$file_path\" 2>/dev/null; uv run ruff format --quiet \"$file_path\" 2>/dev/null; fi"
```

**The same, unescaped (the shell that actually runs):**

```bash
file_path=$(jq -r '.tool_input.file_path // .tool_response.filePath // empty'); if [ -n "$file_path" ] && echo "$file_path" | grep -qE '\.py$' && ! echo "$file_path" | grep -qE '^/(tmp|var/tmp|dev/shm)/'; then cd /home/thomasjiralerspong/explore-persona-space && uv run ruff check --fix --quiet "$file_path" 2>/dev/null; uv run ruff format --quiet "$file_path" 2>/dev/null; fi
```

**Escaping notes (the trap surface):** inside the JSON string, `\"` escapes the shell double-quotes and `\\.py$` renders shell `\.py$`. The NEW clause needs NO new escaping: the regex `^/(tmp|var/tmp|dev/shm)/` contains no backslashes or double-quotes; the `"` around `$file_path` in the new `echo` use the same `\"` form as the existing clauses. Shell semantics: in an `if` list, `A && B && ! C` runs the body iff A and B succeed and C fails — `grep -q` returns 1 (no match) for every non-excluded path, so `! grep` succeeds there. `set -e` is not in effect in hook commands; even if it were, a `!`-negated pipeline in an `if` condition is exempt.
