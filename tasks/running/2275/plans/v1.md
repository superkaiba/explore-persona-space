## 3. Design decisions

**D1 — consumption point is the pure renderer, both branches.** `_resource_header_lines(cluster, spec, gpus)` already receives `spec`; it reads `spec.extra.get("min_ram_gb")`. Raising `ValueError` there is pre-submit by construction (render happens before any `sbatch` call, matching the existing `gpus > max_gpus_per_node` ValueError in `render_sbatch`). Rendering stays a pure function; no signature changes.

GPU branch:
```python
base = min(cluster.mem_gb_per_gpu * gpus, cluster.mem_gb_cap)
mem_gb = _apply_min_ram(cluster, spec, base)
```
CPU branch (`gpus == 0`):
```python
vcpu, mem_gb = _CPU_SBATCH_RESOURCES[spec.intent]
mem_gb = _apply_min_ram(cluster, spec, mem_gb)
```
Shared helper (module-level, next to `_resource_header_lines`):
```python
def _apply_min_ram(cluster: ClusterConfig, spec: RunSpec, base_gb: int) -> int:
    """max(base, spec.extra['min_ram_gb']) with a pre-submit fail-loud above mem_gb_cap."""
    min_ram = spec.extra.get("min_ram_gb")
    if not min_ram:          # absent/None/0 → byte-identical render (#1609 snapshot contract)
        return base_gb
    min_ram = int(min_ram)
    if min_ram > cluster.mem_gb_cap:
        raise ValueError(
            f"--min-ram-gb {min_ram} exceeds cluster {cluster.name!r} mem_gb_cap="
            f"{cluster.mem_gb_cap} G (#2275 fail-loud: the alternative is a silent "
            f"production OOM). Satisfying alternatives: lower the requirement; split "
            f"the fan-out across more jobs (each with its own --mem); or route the "
            f"phase to a RunPod pod (cpu-bigmem / a GPU intent) via backend: runpod."
        )
    return max(base_gb, min_ram)
```
Falsy threading (`if not min_ram`) is deliberately symmetric with `dispatch_issue.py`'s omit-when-absent discipline (#934): a 0/None never changes the render, so existing leases' spec-hashes and the #1609 byte-identical snapshot contract hold when the flag is absent.

**D2 — fellows `mem_gb_per_gpu` stays 128; no shared-config change.** The 128 G/GPU figure encodes a cluster rule (slurm.py:482 "cluster rule 2") on a SHARED org cluster; raising the default would inflate EVERY fellows job's `--mem` request (scheduling + etiquette impact) to fix a per-dispatch problem. The per-dispatch override is the narrow tool the incident actually needed (`--min-ram-gb 1550` at 8 GPUs → 1550 G ≤ cap 1800 ≤ node ~2008). Decision: config untouched.

**D3 — cap semantics.** Without `min_ram_gb`, `formula > cap` keeps clamping silently (unchanged behavior). With `min_ram_gb`: request > cap is a hard error, never a silent clamp below the declared requirement — a clamp would reintroduce exactly the silent-OOM this task exists to kill. `min_ram_gb ≤ cap` but > formula → the request wins (`max`). The error message names the cap and ≥2 satisfying alternatives (task-body requirement).

**D4 — c60 `slurm_mem_coverage` (WARN-only, conditional, all kinds).** Mirrors the c50/c52 composition pattern: `_c50_launch_argvs` → `_c46_dry_parse` per argv → `_c50_slurm_lane_reachable_fn()` runtime predicate (SKIP with stated reason when no SLURM lane is reachable) → resolve intent + GPU count via the slurm intent-default tables → compute the WOULD-RENDER `--mem` (the same `min(per_gpu × gpus, cap)` / CPU-table formula, plus the argv's `--min-ram-gb` when present, i.e. post-fix semantics). Two WARN arms:
  - (a) **per-leg arm:** declared per-leg RSS peak (`_c52_declared_peaks`) > would-render `--mem` and no `--min-ram-gb ≥` peak → WARN.
  - (b) **aggregate arm (the #1336 shape):** a within-job width token found in the same line/paragraph as the RSS token (conservative regexes: `(\d+)[- ]wide`, `width[= ]?(\d+)`, `(\d+) (units|legs|fits|workers) in parallel`) → `peak × width` compared the same way → WARN naming the arithmetic.
  Every ambiguity SKIPs with a stated reason; the check NEVER FAILs (c46/c50/c52 family posture). Named residual (docstring, mirroring c52): a custom-driver fan-out with no plan-embedded `dispatch_issue.py launch` argv is structurally invisible — the binding surface is `plan-compute-sizing.md`, and a SKIP is not coverage. Module-docstring check table gains the c60 row.

**D5 — doc surfaces.** `dispatch_issue.py --min-ram-gb` help + `extra["min_ram_gb"]` threading comment: replace "Inert on SLURM lanes." with the new consumption ("SLURM lanes (#2275): raises the rendered `#SBATCH --mem` to the requirement, both GPU and CPU branches; refuses pre-submit above the cluster `mem_gb_cap`"). The `--min-gpu-mem-gb` comment's "Inert on SLURM lanes" stays (still true). `plan-compute-sizing.md` § Ladder-rung RAM floor: add that on SLURM lanes the floor now binds mechanically via `--min-ram-gb` → `--mem`, and that per-unit RSS × within-job width must be sized against the LANE-RENDERED `--mem`, not per-VM rungs (#1336).
