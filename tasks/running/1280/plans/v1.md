Design decisions, stated:
- **Three-dot argument form (nuance 5):** `"$MAIN_SHA"...HEAD` as one shell word — the quotes end mid-token and the expansion yields `<sha>...HEAD`, which git accepts as a single rev-range. `git diff A...B -- path` = diff(merge-base(A,B), B) limited to path — exactly "the replayed set", content-wise.
- **The `[ -z "$MAIN_SHA" ]` pre-check is REQUIRED, not optional:** under the two-endpoint form an empty `MAIN_SHA` produced a quoted empty argument → git errored → the `if !` failure arm fired (fail-loud, and the echo already names "empty MAIN_SHA"). Under the fused token an empty sha yields `...HEAD` ≡ `HEAD...HEAD` → empty diff, exit 0 → **fail-open** (reads as "no foreign paths"). The pre-check restores the exact prior fail-loud behavior. It joins the SAME `if` condition list, so the #1184/#1243 exclusive-arm shape is intact: any failure takes the terminal `GUARD1_STATE=diff-failed` arm; the `elif mapfile …` work arm is structurally unreachable on failure. A no-merge-base topology (`fatal: no merge base`) also exits non-zero → same failure arm.
- **Echo updated** to name the new form; the tail `cannot certify no foreign tasks/ paths; do NOT merge` is preserved BYTE-EXACT — `tests/test_step10d_guard3.py::test_guard1_materializes_foreign_diff_and_fails_closed` (L933-936) regex-anchors that tail + the following `GUARD1_STATE=diff-failed` line, and L941-943 orders it before the `elif mapfile -t FOREIGN` — both survive without test edits.
- **Downstream split unchanged (nuance 1):** confirmed by reading L8739-8775 — `FOREIGN` is consumed by the carve-out grep, the `cat-file -e "$MAIN_SHA:$p"` split, `checkout "$MAIN_SHA" --`, `rm -f --ignore-unmatch`, and the `diff --cached --quiet` commit gate; none reference the trigger diff's endpoints. With three-dot, FOREIGN_ON_MAIN = branch-touched foreign paths that exist at the pin (reset to snapshot — correct), FOREIGN_BRANCH_ONLY = branch-added foreign paths (dropped — correct).

### Edit E — recovery certification L9840: KEEP two-endpoint (nuance 2, decided)

**Decision: keep `"$MAIN_SHA" HEAD` at L9840, unchanged.** Why: the certification runs AFTER `git -C "$WT" merge "$MAIN_SHA"` + mechanical resolution, and its invariant is **tree identity** — foreign `tasks/` must be byte-identical to the captured snapshot before pushing. The two-endpoint form states exactly that, with BOTH endpoints fixed (as #1210's plan recorded: "the diff is `"$MAIN_SHA" HEAD`, both fixed"), so main-side advancement after capture cannot false-positive it, and post-resolution foreign paths equal the snapshot BY CONSTRUCTION — an empty diff there is a genuine certification, not churn noise. Three-dot would (a) be redundant in the normal case (post-merge, `MAIN_SHA` is an ancestor of HEAD, so merge-base = MAIN_SHA and the forms coincide) and (b) silently NARROW the certified invariant in degenerate topologies (merge produced no commit), weakening the #1128 verification. Keeping it also preserves test pins at L13 (docstring), L36-38 (`_RECOVERY_CERT_DIFF`), L174, L185, and P5 (L303-304) untouched — and its inherent empty-sha fail-loud behavior (quoted empty arg errors out) needs no pre-check.
