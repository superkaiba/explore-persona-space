**New pure decision helper** (the `decide_subfloor` pattern, unit-testable, no side effects):

```python
def decide_subfloor_reclaim(free_bytes: int, last_run_ts: float | None, now: float) -> bool:
    """Pure decision: launch a sub-floor-triggered guard --apply run this tick?
    True when free is below the sub-floor AND the min interval since the last
    launch has elapsed (or none recorded). last_run_ts persists across
    episodes so boundary flapping cannot launch faster than the interval."""
    if free_bytes >= VM_DISK_SUBFLOOR_FREE_BYTES:
        return False
    if not isinstance(last_run_ts, int | float) or last_run_ts <= 0:
        return True
    return now - last_run_ts >= VM_DISK_SUBFLOOR_RECLAIM_INTERVAL_S
```

**New arm** `subfloor_reclaim_pass(dry_run, free_bytes, now) -> bool` (mirrors `subfloor_sentinel_pass`'s shape):

1. `EPM_DISABLE_SUBFLOOR_RECLAIM == "1"` (read at call time) → return False.
2. 4. `dry_run` → print `[dry-run] would launch: <argv>` and return True — **zero `subprocess` calls, zero writes** (#681 r3 contract).
5. Launch detached via a stub-friendly module-level helper:

```python
def _launch_guard_apply(log_path: Path) -> int:
    """Detached vm_disk_guard --apply launch; returns the child pid. Split out
    so tests stub it (a real launch from a test would sweep the live VM)."""
    cmd = [sys.executable, str(PROJECT_ROOT / "scripts" / "vm_disk_guard.py"),
           "--apply", "--ignore-threshold", "--no-push", "--no-data-disk"]
    log_path.parent.mkdir(parents=True, exist_ok=True)
    with open(log_path, "a") as fh:
        p = subprocess.Popen(cmd, cwd=PROJECT_ROOT, stdout=fh,
                             stderr=subprocess.STDOUT,
                             stdin=subprocess.DEVNULL, start_new_session=True)
        fh.write(f"=== {datetime.now(tz=UTC).isoformat()} vm_disk_guard launched "
                 f"detached (trigger=watch-subfloor pid={p.pid}) ===\n")
    return p.pid
```

   `log_path = PROJECT_ROOT / "logs" / "vm_disk_guard" / f"{date:%Y-%m-%d}.log"` — the cron's own dated file, so one audit trail (the single-flight lock prevents interleaved concurrent writers).
6. Wrap 5 in `try/except (OSError, subprocess.SubprocessError)` → stderr line, return False (fail-soft, constraint 4).
7. On success: save state `{"last_run_ts": now, "pid": pid}`; append sidecar row `{"kind": "vm-disk-subfloor-reclaim", "band": "sub-floor", "action": "guard-apply-launched", "free_bytes": free, "free_gib": ..., "pid": pid, "interval_s": ..., "log": str(log_path)}` via the existing `_append_disk_guard_sidecar`; stderr line `vm-disk SUB-FLOOR: launched vm_disk_guard --apply (pid N, ~6-10 min, log <path>)`.

### 4b. Guard side — `scripts/vm_disk_guard.py`

1. **`--ignore-threshold`** → `run_guard(..., ignore_threshold: bool = False)`; one-line change at L1409: `triggered=ignore_threshold or over_threshold(used_before, thr)`. `still_over_after` stays computed against the real threshold (so exit-2/push semantics stay meaningful and are NOT force-true).

3. **Single-flight apply lock** — new module helper + constant:

```python
_APPLY_LOCK_PATH = Path.home() / ".task-workflow" / "vm-disk-guard.lock"

def _acquire_apply_lock() -> "io.TextIOWrapper | None":
    """Non-blocking flock for --apply runs (None on contention). The pid is
    written into the file for skip-line diagnostics. Report-only runs never
    take it (they mutate nothing)."""
    _APPLY_LOCK_PATH.parent.mkdir(parents=True, exist_ok=True)
    fh = open(_APPLY_LOCK_PATH, "a+")
    try:
        fcntl.flock(fh, fcntl.LOCK_EX | fcntl.LOCK_NB)
    except OSError:
        fh.seek(0); holder = fh.read().strip(); fh.close()
        print(f"vm_disk_guard: another --apply run holds {_APPLY_LOCK_PATH}"
              f" (pid {holder or '?'}) — single-flight skip", file=sys.stderr)
        return None
    fh.seek(0); fh.truncate(); fh.write(str(os.getpid())); fh.flush()
    return fh
```

   In `main()`: if `args.apply` and `_acquire_apply_lock()` is None → (under `--json`, print `{"skipped": "apply-lock-held"}`) → `return 0`. The fd is held for process lifetime (flock releases on exit, including SIGKILL).

## 11. Decision Rationale

1. **Detached (Popen `start_new_session=True`), not synchronous.** A triggered `--apply` run measures 5m55s-9m22s (`logs/vm_disk_guard/2026-07-1{4,5}.log`) against a 10-min tick whose overlapping cron fires SKIP under the non-blocking `watch.lock` — a sync call would starve every other watcher pass and drop ticks. Source: measured log timestamps + `background-automation.md` (watch.lock skip semantics). Alternative rejected: sync with timeout (the `_vm_remediate_worktrees` shape) — its 300 s-class bound cannot contain a 6-10 min run.
