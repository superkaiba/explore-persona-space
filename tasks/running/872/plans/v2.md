   available implementation" (#667 picked up #722's serial `fit_cell`).

   `include_mlp=True` serial-outer-loop MLP arm carries the warn+raise guard

   superseded and carries no warning.
3. **Before starting an in-session vectorization rewrite, check for an
   already-open task on the same file** —

   after both had built.

The contract binds ANY rewrite that supersedes a serial entrypoint — a shared
helper, a `scripts/issue*_*.py` driver, or an in-module loop replaced by a
batched twin — whether done by an implementer mid-experiment, a workflow-fix
session, or an emergency in-session fix.

## 11. Decision Rationale

N/A — no training hyperparameters. Design decisions:

1. **Tombstone mechanism = `FutureWarning`-by-default + raise on `EPM_FORBID_SERIAL_FITS=1`; delete only when no Repro-card references.**
   *Why:* deletion breaks reproducibility of #722/#667 Repro cards AND live callers (`issue667_alllayer_analysis.py` calls `fit_cell` deliberately); warn-only failed to be enough in spirit for #778 (autonomous rounds don't read stderr) — the env-var raise gives a follow-up round / orchestrator a hard gate it can arm. `FutureWarning` over `DeprecationWarning` is load-bearing: Python's default warning filter IGNORES `DeprecationWarning` raised outside `__main__` (PEP 565 behavior), so a `DeprecationWarning` tombstone would be silent in exactly the script-imports-script reuse case (#667-style) it exists to catch; `FutureWarning` is always shown by default. Honest limit: the raise is opt-in, so an unarmed run still only warns; the contract's duty 1 (batched twin on `main`) is the primary defense, the tombstone is the second layer.
   *Source:* task body diff sketch + incidents #722/#778/#667; live-caller grep this session; Python warnings docs (default filter: `ignore::DeprecationWarning` outside `__main__`).
   *Alternatives:* delete (breaks #667 + Repro cards — rejected); `DeprecationWarning` (hidden by default outside `__main__` — silent tombstone, rejected); warn-only (no hard stop available — rejected); raise-by-default with an ack env var (breaks #667's deliberate reference calls and old-Repro reproduction — rejected).
2. **Duty location: full text in `vectorize-many-cell-fits.md`, one pointer paragraph in `workflow-fix-on-bug.md` § Built-but-stranded, LESSONS row synced.**
   *Why:* the vectorize rule's `paths:` glob fires on exactly the files where rewrites happen; Built-but-stranded is where a #834-style duplicator would land reading the general lesson — a pointer there closes the discovery gap without duplicating text (drift risk).
   *Source:* task body ("cross-reference … one pointer line"); LESSONS index contract (lint-enforced).
   *Alternatives:* full text in both files (drift); a new always-on CLAUDE.md bullet (context inflation — the existing always-on vectorize bullet already points at the rule).
3. **Tombstone `fit_cell` in THIS round: yes.**
   *Why:* trivially safe per the body's Constraints carve-out — warning-only on the superseded `include_mlp=True` arm, no logic change; pytest has no `filterwarnings=error` (verified in `pyproject.toml`); tests import the module but never call `fit_cell` (verified by grep); it doubles as the rule's worked example, which makes the contract concrete.
   *Source:* clarifier findings + this session's greps (`pyproject.toml` lines 67-73; `tests/test_issue722_invariants.py` grep: 0 `fit_cell` hits).
   *Alternatives:* leave-and-note (loses the worked example and leaves the one known live offender live); file a follow-up task (this session runs under the recursion guard and must NOT auto-file — would only be logged, delaying a 12-line change).
4. **Mechanical lint enforcement: NOT this round.**
   *Why:* a robust check ("every superseded serial entrypoint is tombstoned") needs a registry of superseded entrypoints — new contract surface, real scope creep against a prose deliverable. The lint idea (a `SUPERSEDED_SERIAL_ENTRYPOINTS` list checked for the warn/raise pattern) is logged in the final report for a later pass — NOT auto-filed by this session (recursion guard).
