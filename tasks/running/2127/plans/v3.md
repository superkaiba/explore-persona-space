#### 4.0 Architecture: two prongs sharing one new evidence primitive

**Walk contract (applies to EVERY walk below — recency, verification, pre-reap re-check):** `os.walk` with symlinks never followed; every entry is `lstat`ed and classified FIRST — regular files proceed, symlinks are skipped (an rmtree removes the link, not the target), and any OTHER kind (FIFO, socket, device) anywhere in a candidate ⇒ the candidate is kept with reason `tmp-scratch-nonregular-kept` (fail-toward-keep; never opened). Verification opens use `os.open(path, O_RDONLY | O_NOFOLLOW | O_NONBLOCK [| O_NOATIME])` followed by an `fstat` `S_ISREG` re-check before any read — closing the lstat→open swap race; `O_NOATIME` falls back to a plain flag set on `PermissionError`/`OSError` (legal for the owning uid, and it stops the janitor's own verification from refreshing the recency signal). Rationale: `open()` on a FIFO without `O_NONBLOCK` blocks indefinitely, and the 120 s timeout below covers git subprocesses only — a single FIFO in any of 383 candidates would otherwise wedge the daily cron fleet-wide (critic Blocker 4).

**New evidence primitive** — `_git_blob_reproducibility_evidence(cache_dir, *, main_repo, byte_cap, verdict_cache)` in `scripts/clean_experiment_downloads.py`:

For every regular file under `cache_dir` (walk contract above):

- **Exempt dirs** (pruned from the verification walk; rebuildable tool state by construction): `.git`, `.venv`, `venv`, `__pycache__`, `.pytest_cache`, `node_modules`, `.ruff_cache`, `.mypy_cache`. Exact set pinned as module constant `_SCRATCH_EXEMPT_DIR_NAMES`.
- **Small-text tolerance** (the ONLY non-proof acceptance — the one lever that errs toward REAP, disclosed as such in §11): extension ∈ `{.txt, .log, .out, .err}` AND size < 5 MiB AND the path is NOT under any dir named `store` or `eval_results` AND cumulative tolerated bytes ≤ 64 MiB per candidate. **`.diff` is deliberately EXCLUDED** (v2): a `.diff` is by construction a serialization of at-the-time-uncommitted work — the standing fleet pattern of redirecting a diff to a file before a risky operation puts exactly the only-copy class into scratch trees, and a path-based `store`/`eval_results` guard cannot see it (live instance: `issue-1895-gate2/own.diff`, a 509 KB `diff --git` of then-uncommitted `eval_results/` files at the candidate top level). `.md`/`.json`/`.jsonl` remain NOT tolerated (notes and judge outputs live there). Motivation for what remains: `.txt/.log/.out/.err` are process telemetry (`gated-lint.txt` measured at the top of `issue-1895-gate2`).
- **Everything else must blob-verify:** compute the git blob SHA-1 in Python (`sha1(b"blob %d\x00" % size + content)`, streamed in chunks through the walk-contract open), then confirm existence in the MAIN repo odb via one batched `git -C <repo_root()> cat-file --batch-check` subprocess (SHAs streamed on stdin in chunks; a `missing` line fails that file). Short-circuit on the first unverified file.
- **PASS floor (v2):** a PASS additionally requires `n_verified >= 1`. A tree whose every file was merely tolerated has ZERO proven files and cannot PASS a gate named "git-blob-reproducible" — it escalates as `tmp-scratch-tolerance-only-kept`. Carve-out: an entirely-EMPTY tree (no regular files, no non-regular entries) is reap-eligible without verification (nothing to prove — mirrors gate 1.7's existing empty-dir license).
- **`.git`-bearing candidates — class-discriminated (v2, critic Blocker 2).** First classify via the `.git` entry: a `.git` DIRECTORY ⇒ clone class; a `.git` FILE (`gitdir: ...`) ⇒ linked-worktree class (the dominant measured shape of the PASS class: both `eps-main-scratch-2058` and `scratch-2171-merge2` are linked worktrees of the main repo on detached HEAD — probed this session, §12). The `.git` dir/file itself is exempt from per-file verification; the per-file blob walk still runs over the working tree in BOTH classes (it is what catches gitignored non-exempt content, e.g. a `data/` artifact dir inside a worktree, which `status` cannot see). Class-specific probes:
  - **Worktree class:** (i) `git -C <cand> status --porcelain` must be EMPTY — catches dirty AND staged-never-committed AND untracked-unignored work; load-bearing because `git add` in a linked worktree writes the blob into the SHARED main odb, so per-file blob-existence PASSES on staged-never-committed edits (the v1 §8 claim that blob proof fails on any dirty file was FALSE for this class); reaping then deletes the worktree's index and the blob gc-prunes unreachable. (ii) HEAD must be reachable from a SURVIVING ref: `git -C <cand> merge-base --is-ancestor HEAD origin/main` (rc==0), else non-empty `git -C <cand> for-each-ref --contains HEAD refs/heads refs/tags refs/remotes` — a detached-HEAD-only commit (the scratch-merge recipe's abandoned-failed-push shape) becomes unreachable when `worktree prune` drops `worktrees/<name>/HEAD`, then gc-prunes; the worktree's own reflog dies with the admin dir, so reachability-from-a-surviving-ref is the only durable proof. (iii) A LOCKED worktree (`worktrees/<name>/locked` present) ⇒ kept (`tmp-scratch-worktree-locked-kept`) — a lock is a deliberate protection signal. The v1 shared-REF probe is DROPPED for this class (for-each-ref lists the main repo's shared refs — every tip trivially exists in the main odb; vacuous-PASS certifying nothing) and the v1 shared-STASH probe is DROPPED for this class (the stash is shared with the main repo, which currently holds 30 autostash-rescue entries, #2182 — measured this session; it would spuriously keep every worktree-shaped candidate forever on state unrelated to it).
  - **Clone class:** (i) `git -C <cand> for-each-ref --format='%(objectname)'` — every ref tip must exist in the MAIN repo odb (`cat-file --batch-check`; catches an unpushed local branch whose commits exist only in the clone's own odb); (ii) the SAME HEAD-reachability check as the worktree class, evaluated against the MAIN repo's refs (`git -C <main_repo> merge-base --is-ancestor <clone HEAD sha> origin/main`, else `--contains` in the main repo) — a detached-HEAD clone has the identical hole; (iii) `git -C <cand> stash list` must be empty (the clone's OWN stash — not shared, so not spurious); (iv) `git -C <cand> status --porcelain` must be EMPTY (uniform with the worktree class; strictly redundant with per-file blob proof for unstaged edits in a clone — a clone's `git add` writes to the clone's OWN odb, so blob-verify against the main odb already fails staged work here — but uniformity is cheaper to test than a per-class exception).
  - Any git subprocess failure (dangling worktree husk, timeout at 120 s, non-`sha1` object format via `git rev-parse --show-object-format`) → `None` (fail-toward-keep).
- **Byte cap:** total bytes to hash bounded by env `EPS_SCRATCH_VERIFY_MAX_GB` (default 64); over-cap → `None` with reason `over-verify-cap` (escalate-only, never a partial verdict).
- **Verdict cache:** `.claude/cache/scratch-verify-cache.json`, keyed `(abspath, tree_newest_mtime, total_bytes)` → `{verdict, first_unverified, ts}`. Cache hit skips re-hashing an unchanged tree (bounds the daily cron cost); any key component change invalidates. Cache read/write failures are non-fatal (treated as miss). **Prune-on-reap (v2):** a successful reap deletes the reaped path's cache entries, keeping the file honest.
- **Contract residual (named, v2):** for plain (non-`.git`) trees, blob-existence proves recoverability NOW — an odb blob not reachable from any ref can be gc-pruned later (~2-week default). Accepted for this content class (committed repo content is overwhelmingly ref-reachable) rather than paying an O(repo) reachable-set enumeration per sweep; stated in the module docstring and §8.

Returns an evidence string on PASS (`git-blob-reproducible: <n_verified> files verified, <n_tolerated> small-text tolerated`) or `None` + a detail dict (`first_unverified`, counts, bytes) on FAIL.
