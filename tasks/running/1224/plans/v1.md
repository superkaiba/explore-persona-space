Add `import subprocess`; add near `_SHA40_RE` (L106):

```python
_RAW_PIN_RE = re.compile(
    r"^https://raw\.githubusercontent\.com/([^/]+)/([^/]+)/([0-9a-fA-F]{40})/(.+)$"
)
_FIGURES_ISSUE_RE = re.compile(r"^figures/issue_(\d+)/")

def _git(repo: Path, *args: str) -> tuple[int, str]:
    """Run a read-only git command in ``repo``; returns (rc, stdout stripped)."""
    proc = subprocess.run(["git", "-C", str(repo), *args], capture_output=True, text=True)
    return proc.returncode, proc.stdout.strip()
```

New check pair (called from `verify_report_text` after `check_htmlpreview`, on the **blanked** body — fenced/blockquote example images stay exempt, same discipline as `check_image_files`):

```python
def check_image_pins(
    sections, blanked_body, *, mode, figures_root, expect_issue=None
) -> list[CheckResult]:
    # ── image-pin-format (FAIL-grade, both modes) ─────────────────────────
    # Every image in `## Results:` MUST be a well-formed pin:
    #   https://raw.githubusercontent.com/<owner>/<repo>/<40-hex>/<path>
    # with <path> matching figures/issue_(\d+)/, all N identical, and
    # N == expect_issue when provided. A relative path, /main/ or /HEAD/ ref,
    # short SHA, blob-URL form, or non-figures path → FAIL, naming the URL.
    # Images OUTSIDE Results are exempt from the pin REQUIREMENT but, when they
    # ARE raw.githubusercontent URLs, get the same format + identity checks.
    ...
    # ── image-pin-blob-identity (ladder; no network, ever) ────────────────
    # 0. figures_root not a git checkout (`git rev-parse --git-dir` fails)
    #      → ONE WARN "not a git checkout; blob identity unverifiable".
    # For each well-formed (sha, path) pin:
    # 1. `git cat-file -e <sha>^{commit}` fails  → WARN "pinned commit not in
    #      local object DB (unfetched); identity unverifiable"  [never FAIL —
    #      report-verifier.md L63-65 precedent]
    # 2. commit present, `git rev-parse <sha>:<path>` fails → FAIL
    #      "pinned commit does not contain <path>"   [a wrong pin, definitively]
    # 3. blob id resolved; local copy at figures_root/<path> exists:
    #      `git hash-object <local>` != blob id →
    #         mode == "generation" → FAIL   [at 7e the worktree copy IS the
    #             just-plotted figure; mismatch = the exact wrong-SHA bug]
    #         mode == "promote"    → WARN   [post-merge local drift is a stray;
    #             the pin is the record — #922]
    # 4. no local copy, pin resolves → PASS-note "resolves in object DB; no
    #      local copy to compare".
```

Wiring: `verify_report_text(..., expect_issue: int | None = None)`; the driver appends `results.extend(check_image_pins(sections, blanked_body, mode=mode, figures_root=figures_root, expect_issue=expect_issue))`. `main()`: new optional `--expect-issue <N>` arg (outside the mutually-exclusive source group); `expect = args.issue if args.issue is not None else args.expect_issue`. Update the module docstring's check list. Worktree note: worktrees share the object DB, so a commit made in the issue worktree resolves via `git rev-parse` from any sibling checkout; the only genuinely-absent-SHA case is an unfetched clone → WARN by design (the defined degrade).
