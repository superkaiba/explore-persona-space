## 11. Decision Rationale

1. **Diff-cwd seam: one root = the invoking checkout's toplevel (`--show-toplevel`), no new CLI args.**
   *What:* resolve everything (diff cwd, existence checks, invariant presence) against the checkout the helper is invoked in.
   *Why:* pytest MUST run in the worktree anyway (branch-new test files exist nowhere else until Step 10d), so a worktree-cwd contract is unavoidable; given that, a single root is the simplest correct seam and makes the selector's view identical to pytest's view.
   *Source:* #851 observation (pytest already ran in the worktree); live repro on issue-699 (planning session); SKILL.md Step 5a precedent that `--show-toplevel` is correct when the invoking checkout is wanted; #506 comments confirming the doubling bug is path-*construction*-only.
   *Alternatives rejected:* (a) keep main root + `--head-ref issue-<N>` + `git cat-file -e <ref>:<path>` existence — cwd-independent selection, but pytest still needs the worktree, so it adds a second seam (a ref arg the orchestrator must thread) without removing the cwd requirement; (b) `--diff-cwd` arg — same objection, and the default-cwd behavior would still need defining.
2. **Existence-check location: work-root filesystem (not "include unconditionally + WARN").**
   *What:* keep the `(root / f).exists()` gates, pointed at the work root.
   *Why:* including a touched-but-absent test unconditionally would put deleted-on-branch test files into the pytest command → collection error → false gate FAIL; the filesystem check at the correct root admits branch-new files and drops deleted ones in one move, with zero logic change.
   *Source:* code reading (the `continue` was correct logic against the wrong root); safe-by-direction principle in the module docstring.
   *Alternatives:* include + WARN (false FAILs on deletions); `--diff-filter=d` (equivalent outcome, larger diff, changes `compute_touched` semantics for all callers).
3. **WARN semantics: stderr NOTE on empty diff; exit stays 0.**
   *What:* loud stderr NOTE naming the work root + the re-run hint whenever the diff is empty; no exit-code change.
   *Why:* the #851 failure was *silent* under-selection — the NOTE makes the wrong-cwd case visible to the orchestrator without breaking the documented legitimate degenerate case (run on `main` with no commits ahead, pinned by case 8 and the docstring). A hard-fail would break that contract; the `untested touched file:` WARN needs no change — it fires naturally once the diff is non-empty (confirmed by cases 5/15).
   *Source:* docstring contract; test case 8; fail-loud philosophy (the empty-*selection* exit-1 refusal from #785 is preserved untouched — it guards a different failure class).
4. **SKILL.md cwd contract: worktree for both selector and pytest, hard `cd` guard retained.**
   *What:* Step 9c 1a-1b now run from `$WT`, with the incident-745 `cd || exit 1` guard.
   *Why:* it is the only cwd where the gate can actually exercise branch-new tests (git fact), and it matches what #851's orchestrator already did; the incident-745 guard class ("silent cd failure runs pytest in a dir with no tests") is retained verbatim, and the `no tests ran` = FAIL rule is untouched.
   *Source:* #851 `epm:test-verdict` marker ("executed in the issue-851 worktree"); incident 745 (SHA 91bed41e); Step 10d merge ordering (SKILL.md).
5. **Keep `--repo-root` flag name, printed-command shape, and JSON keys.**
   *What:* CLI/output stability — only help text and docstring wording change.
   *Why:* the printed command is consumed verbatim by Step 9c prose (task-body constraint); case 10 pins the JSON key set; renaming the flag buys clarity at the cost of a needless contract break on a guardrail fix.
   *Source:* task body "Constraints / invariants"; test case 10.
