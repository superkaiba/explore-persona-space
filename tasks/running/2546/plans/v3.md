# Plan: issue #2546 — Can the context→answer map predict the POST-CoT answer, and how does CoT training change the map?

## 0.0 TL;DR (plain English)

- **What I'll run:** I'll take a reasoning-trained model (OpenThinker3-7B) and its exact non-reasoning parent (Qwen2.5-7B-Instruct), have both answer ~31,500 benchmark questions spanning "needs step-by-step reasoning" (GSM8K, MATH, hard logic) to "doesn't" (MMLU, ARC, commonsense), record the hidden-state snapshots at four points (end of prompt, inside the thinking block, end of thinking, the answer), and fit simple linear predictors between those snapshots.
- **What I expect:** on questions that need reasoning, the end-of-prompt snapshot will predict the thinking text's style but NOT the final answer, while the end-of-thinking snapshot will predict the answer well; the gap between those two is the "work the reasoning did", measured in the same units. I also expect the parent model's prompt snapshot to partially predict the reasoning model's answers, telling us how much reasoning training rewired the prompt-to-answer link.
- **What would change my mind:** if the end-of-prompt snapshot predicts the final answer just as well on hard math as on trivia (retrieval accuracy near the end-of-thinking ceiling), then the "reasoning computes the answer" picture is wrong for this model and the existing whole-output R² ≈ 0.8 result really does cover answers, not just trace style.

## 1. Goal

> (1) In CoT-trained models, measure R2 and acc@1 for four maps — post-context→answer, post-context→CoT, post-context→CoT+answer, post-CoT→answer — on a corpus that DOES versus DOESN'T require chain-of-thought; and (2) measure whether a PRE-CoT-trained model's context vector can predict the POST-CoT-trained model's post-</think> answer state, and how the fitted map changes across the CoT-training step, using a matched same-geometry pre/post pair (Qwen2.5-7B-Instruct -> OpenThinker3-7B).

(Task #2546 Goal, verbatim; re-read from frontmatter at plan-return time, current as of the latest `epm:goal-updated` marker.)

The context→answer map `v_A ≈ M v_C` reads held-out R² ≈ 0.75–0.8 on wild chat (#779 n1m: 0.7542 at L19 on 963,444 contexts; #1482). In a thinking model the output splits at a literal token (`</think>`), which makes "is the answer already in the context state?" an exact, decomposable question, and lets us measure what the serial CoT computation adds in the same units as the existing map line. ## 3. Hypothesis

Let R²(cell, stratum) denote held-out pooled R² at frozen layer 19, and acc@1 the k=1 retrieval rate in the per-target within-corpus pool.

- **H1 (the star, A-vs-C):** on the needs-reasoning stratum, Whole-output-from-context (C) beats Answer-from-context (A) by ≥ 0.15 R². If so, the existing whole-output ≈0.8-style read is carried by the trace, not the answer.
- **H2 (the serial-work interaction):** the Answer-from-end-of-thought minus Answer-from-context gap (D − A) is ≥ 0.10 R² larger on needs-reasoning than on no-reasoning-needed corpora, with acc@1 moving the same direction.
- **H3 (graded):** within GSM8K, per-bin R²(A) decreases monotonically in calculator-step bin (Spearman over bins < 0, 4 bins); within ContextHub, decreasing in level; R²(D) stays within 0.05 of flat across bins.
- **H4 (Plot 8 headline, E):** the pre-model context vector predicts the post-model answer state at R²(E) > 0 and above the identity+bias baseline; E − F quantifies what CoT training added. No sign prediction registered; either direction is informative.
- **H5 (map change):** the pre→post reparameterization ladder finds a sufficient tier ≤ 5 (rotation or below) on no-reasoning-needed corpora and a higher (or no) sufficient tier on GSM8K/MATH; prior: #1336 found SFT is the map-installing step, and OpenThinker3 is a 1.2M-row SFT.
- **H6 (Camp-B trajectory, secondary):** R² of think-state→answer increases monotonically in t ∈ {0 (context), 0.25, 0.5, 0.75, 1 (end of thought)} on the needs-reasoning stratum (2412.01113).

**Registered verdict lattice (primary, Plot 7):**
DISJOINT and exhaustive: TraceCarried ⇔ CA_gap_pp >= 15; AnswerAlreadyPresent ⇔ CA_gap_pp < 15 AND A_r2_pp >= 50; Indeterminate ⇔ otherwise.
Definitions: CA_gap_pp = 100 × (held-out R² of cell C minus cell A) on the needs-reasoning stratum at frozen L19; A_r2_pp = 100 × held-out R² of cell A on the same stratum and layer.

**Registered paired contrast Row-coverage:** every paired contrast (A vs C, D vs A, E vs F, per-stratum and per-bin) is computed on ONE identical usable-row set per stratum: the intersection of rows with valid context, CoT, and answer spans in the post-model AND a valid pre-model capture, under one fold assignment (K=5, seed 0). A row dropped for any cell is dropped for all cells; drop counts reported per corpus. Cells fit on different models (E/G) still share this row set on the input and target sides.

Row-coverage: both arms of every registered contrast are produced by this plan's own P5 fits from the single P4 thinkstore, so every registered row exists on each arm by construction; the P5 driver additionally set-checks the shared usable-row set against both arms' store keys before any fit.
