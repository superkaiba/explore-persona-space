## 0. Plan Summary

**What it does:** Replace the Step 9c whole-suite `pytest tests/` invocation
(~5800 tests, no xdist, stalls ~40-44% and gets harness-killed in sparse
worktrees — #665/#736) with a deterministic **touched-file-scoped subset**:
the tests covering the files this branch changed PLUS a pinned literal list of
workflow-invariant tests. A small tested helper
(`scripts/select_step9c_tests.py`) computes the selection from
`git diff --name-only main...HEAD`; the SKILL.md prose delegates to it and
stays under ~50 lines. Lint (step 2), integration (step 3), coverage (step 4)
are untouched. An opt-in `test_scope: full` escape hatch keeps the full suite
runnable for risky/broad changes — but the full path also gets
`-x --maxfail=1` + a 60-min timeout + log-tail-on-kill so the stall surfaces
actionable evidence instead of a silent kill.

**Single variable changed:** the test SELECTION used at Step 9c. Nothing else
in the gate moves.

**Compute:** 0 GPU-h. CPU-only: the helper's unit test + `verify_plan.py`.

**Risk (top 1):** a touched file whose tests live under a name the path
heuristic misses → a real regression escapes the subset. Mitigation: the
always-included workflow-invariant set, the broad `*<X>*` glob arm, and a
hard WARN ("untested touched file: <path>") posted into the test-verdict
marker so the orchestrator surfaces uncovered files.

## 4. Method delta

Two files change; one is new.

### 4a. New helper: `scripts/select_step9c_tests.py`

Pure stdlib + `pathlib` + `subprocess` (git) + `argparse`. **No new deps.**
**Why code, not a model call?** This is deterministic path arithmetic over a
git diff — no unstructured-data classification. A model call would add latency
+ nondeterminism for zero benefit. `N/A — deterministic path mapping, no
unstructured-data heuristic.`

Behavior:

```
select_step9c_tests.py [--base main] [--repo-root <path>] [--json]

1. touched = git diff --name-only <base>...HEAD   (three-dot: merge-base vs HEAD
   = the branch's own additions/modifications)
2. selected_tests = set()
   untested_touched = []      # non-trivial touched files with no mapped test
   for f in touched:
     if f matches a WORKFLOW_SURFACE glob
        (.claude/agents/*.md, .claude/skills/**/SKILL.md, .claude/rules/*.md,
         .claude/workflow.yaml, .claude/settings*.json, CLAUDE.md):
        continue   # workflow-invariant set IS the gate for these (no extra map)
     if f is tests/test_<X>.py:           selected_tests.add(f)         # itself
     elif f is scripts/<X>.py or src/.../<X>.py:
        stem = Path(f).stem
        add tests/test_<stem>.py            if it exists
        add tests/test_*<stem>*.py          (glob)
        if NEITHER matched and f is a non-trivial code file:
           untested_touched.append(f)
     # data/config/doc files: ignored (not code; no test mapping)
3. always = [ the pinned WORKFLOW_INVARIANT literal list below ]
   (filtered to those that exist on disk, so a renamed/removed invariant
    test never crashes the gate — but a DROP from the list is loud: see 4a-note)
4. final = sorted(selected_tests ∪ always)
5. emit: the pytest invocation `uv run pytest <final> -v --tb=short`
   + the untested_touched WARN list (--json: {tests, untested_touched, base})
```

**4a-note — pinned literal, not a glob.** `WORKFLOW_INVARIANT` is a module-level
literal tuple (the list in §5 below), NOT `glob("tests/test_workflow*.py")`.
Rationale (Source: constraint 4 + #736): a future `tests/test_workflowish.py`
that is NOT meant to gate Step 9c must not silently join the gate, and the gate
must not silently shrink if a glob arm stops matching. The helper asserts each
literal entry exists on disk at run time and prints a loud
`WORKFLOW-INVARIANT MISSING: <file>` line (does not crash — a removed test is a
WARN the orchestrator surfaces, mirroring the untested-touched WARN) so drift
is visible. A test (`tests/test_select_step9c_tests.py`) pins the literal list
against the live `tests/` directory so an added/removed invariant test forces a
deliberate list edit.

## 11. Decision Rationale

`N/A — no model training` (no hyperparameters). The load-bearing design
choices for this infra change:

- **Test selection heuristic (path-based).** *What:* for changed file `<X>`,
  include `tests/test_<X>.py` if it exists AND `tests/test_*<X>*.py`. *Why:*
  matches pytest's own `test_`-prefix discovery convention; zero new deps;
  transparent and auditable; reproduces the manual judgment #736 used.
  *Source:* pytest discovery semantics + #736's hand-picked subset (which was
  itself path-based). *Alternatives:* `pytest-testmon` (new dep, opaque hash
  DB — out of scope per constraint 8); `pytest --collect-only` + filter
  (requires a full collect, which is the slow phase that stalls — defeats the
  purpose).
- **Diff base (three-dot `main...HEAD`).** *What:*
  `git diff --name-only main...HEAD`. *Why:* the three-dot form diffs the
  merge-base of `main` and `HEAD` against `HEAD` — the branch's own
  additions/modifications, i.e. exactly "what THIS task changed". Two-dot
  `main..HEAD` would include changes on `main` not in `HEAD` (wrong direction);
  `HEAD~1..HEAD` would only see the most recent commit (misses earlier
  implementer rounds). *Source:* git diff docs; matches upstream PR-review
  semantics. *Alternatives:* rejected as above.
- **Always-included workflow-invariant set (pinned literal).** *What:* the 33
  files in §5, as a module-level literal tuple, not a glob. *Why:* these gate
  the project's load-bearing invariants (task.py API, marker schema, verifiers,
  no-pod-side-shellout, etc.) and must run on EVERY code change regardless of
  touched files. A literal (not glob) prevents silent gate growth (a future
  `test_workflowish.py` joining the gate) AND silent gate shrinkage (a glob arm
  ceasing to match); the on-disk assertion + pinning test make drift loud.
  *Source:* CLAUDE.md "Common Commands" workflow-invariant list + the live
  `tests/` inventory + constraint 4.
- **Default `touched` vs opt-in `full`.** *What:* default scope `touched`;
  opt-in `full` via `test_scope: full` frontmatter or a `## Test scope` H2.
  *Why:* matches the body's proposed change; the full suite IS the regression,
  so it stays opt-in for genuinely risky/broad changes (e.g. a CLAUDE.md edit
  touching a shared invariant). The opt-in path gets `-x --maxfail=1` + 60-min
  timeout + log-tail so it fails loud, not silent. *Source:* task #754 body
  proposed change + acceptance criterion 9.
- **A tested helper vs inline shell in SKILL.md.** *What:*
  `scripts/select_step9c_tests.py` rather than an inline bash one-liner in the
  prose. *Why:* the selection logic (glob arms, workflow-surface filtering,
  untested-file WARN, pinned-list assertion) is too rich for inline prose and
  must be unit-testable (acceptance criterion). A helper keeps the SKILL.md
  block under ~50 lines and lets `tests/test_select_step9c_tests.py` pin the
  behavior. *Source:* constraint 1 (small helper under `scripts/` is allowed) +
  acceptance criteria.
