Design decisions embedded (each argued in §11):
- **Declared-paths source (brief decision 1):** the driver's own output manifest — the git-destined files it wrote this round, identical to the "Eval JSON paths" it declares in the `epm:results` sentinel payload (workflow.yaml § markers) and to the plan §6.5 rows routed to git. No new schema field; the driver already holds this list.
- **Per-file grain, never directory-level** — live-measured requirement: `git ls-tree -r ece75d101f -- eval_results/issue_928/prefix-based-mapping-arms/ figures/issue_928/` returns 90 files (earlier rounds') at the very tip where all 29 of the round's files were missing. A directory non-empty check would have passed the incident.
- **`ls-tree` against `origin/<branch>`** (not `HEAD`): directly asserts "present in the PUSHED tree" per the Goal; free because the remote-tracking ref was just updated by the verified push. (`git cat-file -e "origin/<branch>:$p"` is an acceptable equivalent an implementing driver may use; the rule names one canonical form.)
- **Ordering:** assert AFTER push-verify success, BEFORE `[phase=done]` + the results sentinel — consistent with the section's Part A-ter ordering discipline (don't stamp done-like signals before verification) and with the file's sentinel contract.
- **#1090 sub-cause (brief decision 2): explicitly OUT of scope**, named in the clause with the incident citation, ownership pointed at the Upload Policy. Rationale: judge raw is HF-destined; a pushed-tree assert is the wrong instrument; upload-policy.md's persist-by-default + the v2 upload-verifier's 100%-reconciliation already own that leg. Silently omitting it would leave critics guessing — hence the sentence.
