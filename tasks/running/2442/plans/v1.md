# Plan v1 — #2442: absence checks must use a call that can FAIL on a wrong location

`kind: infra` workflow-fix task. Target surface: `CLAUDE.md` § "Ad-hoc results
summaries" (absence-claim sentence) + `.claude/rules/upload-policy.md`, plus one
small raising helper and its test.

## 1. Requirement

CLAUDE.md's absence-claim rule names the DUTY ("a SCOPED listing of the HF
prefix's siblings/parents (`list_repo_tree(path_in_repo=<parent prefix>)`)") and
even names the right call, but states no MECHANISM. Without the mechanism, the
natural implementation — fetch the full listing once, filter locally with
`startswith` — reads as satisfying the duty while being structurally incapable
of the check: the prefix never reaches the server, so the call cannot fail on a
wrong location. It exits 0 and prints an authoritative-looking zero.

Add the mechanism: **an absence check must use a call whose error surface
distinguishes wrong-path from empty-path.**

### Acceptance criteria (verbatim from the task body)

1. The absence-claim rule text names the wrong-path-vs-empty-path distinction
   and the two acceptable call shapes, not just the duty.
2. The `list_repo_files` + client-side-filter form is explicitly scoped to
   within-a-proven-prefix counting.
3. The parent-prefix positive control is stated as the fallback when no scoped
   call exists.
4. If a helper is added, it raises (never returns 0) on a nonexistent prefix,
   with a test using a nonexistent-prefix fixture asserting the raise — the test
   must FAIL against a client-side-filter implementation.
5. No new red in the no-flags `workflow_lint.py` run or the mapped-test
   selection.

## 2. Method delta (what differs from prior related work)

Three prior-art facts, each of which changes the shape of this edit. All were
established by direct read during the clarifier pass, not assumed.

- **The HTTP fact is already in-repo, under the wrong heading.**
  `.claude/rules/upload-policy.md:957` (§ Relocated codebase traps) already
  records "listing a not-yet-existing prefix also 404s" and already prescribes
  `HfApi().file_exists(...)` / `list_repo_tree(path_in_repo=<literal prefix>)`
  for existence probes — but as a GLOB / literal-path gotcha. So this task does
  NOT discover a new fact; it links an existing fact to the absence-claim duty.
  Consequence: the upload-policy edit is a NEW short subsection that
  cross-references line 957 rather than restating it, and the CLAUDE.md clause
  points at the new subsection. Restating the 404 mechanics a third time is the
  anti-pattern to avoid.

- **The throughput rationale already prefers the scoped call, for a DIFFERENT
  reason — do not fuse them.** `upload-policy.md:956` (#833) and `:821` (#2304)
  bar bare `list_repo_files` on the ~1M-file data repo because it TIMES OUT
  (>90 s) / wedges. This task's rationale is CORRECTNESS, orthogonal. The edit
  states both and keeps them labelled, because a reader who believes the only
  reason is throughput will happily use the full-listing form on a SMALL repo —
  where it is fast and still cannot fail on a wrong path.

- **The repo's own ergonomic wrapper VIOLATES the rule this task is writing.**
  `hub.list_hf_entries_under_path` / `list_hf_files_under_path`
  (`src/explore_persona_space/orchestrate/hub.py:1042-1126`) catch
  `EntryNotFoundError`, fall back to one `file_exists` HEAD probe, and **return
  `[]` for an absent path** — deliberately and documented ("an absent path
  returns `[]`"). That is correct for their staging callers and exactly wrong
  for an absence check. This is the strongest argument for adding the helper:
  without one, the new rule says "use a call that can fail" while the nearest
  in-repo helper silently cannot — the same duty-without-mechanism defect, one
  layer down. `verify_repo_paths_uploaded` is not a substitute either; it
  answers "is this expected SET present", requiring the paths up front.

  No `prefix_exists`-shaped helper exists in `hub.py` (checked the full `def`
  listing). So the helper is genuinely new, not a duplicate.

### 3.2 `.claude/rules/upload-policy.md` — new `## Absence checks` section

New section (placed before `## Relocated codebase traps`, so its
cross-reference to line 957 reads forward). Contents:

- The two-call comparison reproduced from #2329, verbatim shape:
  `list_repo_files` + `startswith` → rc=0, prints `0`;
  `list_repo_tree(path_in_repo=<same nonexistent prefix>)` → `EntryNotFoundError`
  404. Same repo, same prefix, opposite outcomes.
- Why: the client-side filter is a local string operation over a listing
  produced for a different question, so "prefix holds nothing" and "prefix does
  not exist" are indistinguishable by construction.
- The two acceptable shapes (`list_repo_tree(path_in_repo=...)`,
  `get_paths_info`) and the one scoped shape
  (`list_repo_files` + filter, ONLY within a proven prefix).
- The parent-prefix positive control as the no-scoped-call fallback, noting it
  is how #2329 was actually resolved (listing `ladder/`'s children showed no
  `grid`, which located the real path).
- **The lazy-generator trap, load-bearing here:** per `upload-policy.md:954`
  (#779) the 404 raises at ITERATION, not at the call — so a `try/except`
  around the call catches nothing and an absence check built that way silently
  degrades to the very failure mode this rule bans. Materialize inside the
  guard.
- **The in-repo-helper warning:** `hub.list_hf_files_under_path` /
  `list_hf_entries_under_path` return `[]` on an absent path by design — never
  use them as absence primitives; use `hub.assert_hf_prefix_exists` (§3.3).
- The #2329 layout trap, one short paragraph: the store split across
  `issue2329_q35rerun/analysis_tensors/ladder/` and
  `issue2329_q35rerun/raw_completions/ladder/`, neither named for the round
  label, with rollout TEXT under `raw_completions/` per upload policy — so "the
  grid store" is NOT under the tree holding every other ladder artifact. A
  prefix guess that looks obviously right is often wrong.
- The throughput-vs-correctness labelling (per §2 above).

Cross-references both ways: the new section points at `:957` for the HTTP
mechanics and `:954` for the generator trap; no restatement.

### 3.3 `src/explore_persona_space/orchestrate/hub.py` — `assert_hf_prefix_exists`

New helper. Contract, written to satisfy criterion 4 exactly:

```python
def assert_hf_prefix_exists(
    api, repo_id: str, prefix: str, *, repo_type: str = "dataset",
    revision: str | None = None,
) -> int:
    """Return the file count under ``prefix``, RAISING if the prefix is absent.

    The absence-check primitive: a scoped server-side ``list_repo_tree`` whose
    404 distinguishes wrong-path from empty-path. NEVER returns 0 for a
    nonexistent prefix — that silent-zero shape is exactly what
    ``CLAUDE.md`` § "Absence claims" bans (#2329).

    Deliberately NOT ``list_hf_files_under_path``, which returns ``[]`` for an
    absent path (correct for staging, wrong here).
    """
```

Implementation notes (each closes a trap already recorded in the rules):

- Materialize the generator INSIDE the retry thunk (`list(...)`), so the 404
  raises where it can be seen (#779, `upload-policy.md:954`).
- Route through `retry_transient` so a 429/5xx is retried rather than misread as
  absence — a transient error must never be reported as "prefix does not exist".
  `EntryNotFoundError` is non-transient and propagates immediately.
- Empty `prefix` raises `ValueError` (a falsy prefix would degrade to a
  full-repo listing — the exact `list_hf_entries_under_path:1082` precedent).
- A prefix that EXISTS but is empty returns 0 — a real, distinguishable answer.
- Return the count so a caller gets the coverage number and the existence proof
  from one call, no second listing.

### 3.4 `tests/test_hub_absence_check.py` — new test file

Three tests. The middle one is criterion 4's mechanical requirement:

1. `test_absent_prefix_raises` — fake `api.list_repo_tree` raises
   `EntryNotFoundError` for the nonexistent-prefix fixture; assert
   `assert_hf_prefix_exists` RAISES. **Must FAIL against a client-side-filter
   implementation:** the fake also exposes a `list_repo_files` returning a
   populated listing none of whose entries start with the fixture prefix, so a
   filter-based implementation returns 0 and the test fails on the missing
   raise. This is the discriminating property criterion 4 demands, and it is
   what makes the test a real gate rather than a tautology.
2. `test_existing_but_empty_prefix_returns_zero` — scoped listing yields no
   entries without raising; assert the return is `0`, not an exception. Pins the
   distinction the whole rule rests on.
3. `test_transient_error_is_retried_not_reported_as_absent` — first call raises
   a transient (429-shaped), second succeeds; assert the helper returns the
   count. Guards the misread-transient-as-absence failure.

Fakes are signature-conformant by construction (`create_autospec` / a `def`
mirroring the real signature) per `code-style.md` § "One production-body test
per seam-stubbed function"; the helper's own body executes in every test.
