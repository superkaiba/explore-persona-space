## 2. Method delta (vs current implementation)

Current (lines 4079–4093): per line, `_COMMITTED_AT_SHA_RE.search(line)` (first match only, span may cross clause boundaries via lazy `[^\n]*?`), then `_ARTIFACT_PATH_RE.findall(line)` pairs **all** paths on the line with that one sha.

New: per line → `_split_clauses(line)` → per clause, `_COMMITTED_AT_SHA_RE.finditer(clause)` × `_ARTIFACT_PATH_RE.findall(clause)`. Two defects fixed by one mechanism: (a) cross-clause span/pairing (the #841 false FAIL); (b) only-first-claim-per-line (a line with two genuine claims now validates both). The regex patterns themselves are **unchanged** — only the text window they run over shrinks. Known residual (documented, accepted): two claims inside one clause with no delimiter between them would cross-pair paths within that clause — contrived; no corpus instance.

### 3a. `scripts/verify_task_body.py` — new helper after `_ARTIFACT_PATH_RE` (~line 3668)

```python
# Clause delimiters for the committed-at-sha scan (#893, incident #841):
# semicolon / interpunct / sentence-final period, each REQUIRING trailing
# whitespace — so file-extension dots (`foo.json`), version strings, and
# URL punctuation (which carry no spaces) never split. The em-dash (" — ")
# and ":" are deliberately NOT delimiters: real footers put them BETWEEN a
# path and its own sha claim (the #549 / #601 corpus shapes), so splitting
# there would silently drop genuine pairs.
_CLAUSE_DELIM_RE = re.compile(r";\s|\s·\s|\.\s")

# Abbreviation tokens whose trailing dot is NOT a sentence boundary
# (#893 v2, methodology-reconciler binding concern 2): without this guard,
# "committed, e.g. `path` at commit `sha`." splits at "e.g. " and a TRUE
# FAIL today becomes a silent PASS (protection removal). Matched against
# the lowercased word immediately before the candidate ". " (the token's
# own internal dots included, e.g. "e.g"). Over-inclusion is fail-safe:
# a suppressed split degrades toward today's whole-line behavior.
_DOT_ABBREVIATIONS = frozenset(
    {"e.g", "i.e", "eg", "ie", "cf", "vs", "etc", "al", "fig", "approx", "incl"}
)


def _split_clauses(line: str) -> list[str]:
    """Split ``line`` into clauses on ``; `` / `` · `` / ``. `` occurring
    OUTSIDE backtick code spans, so a ``committed ... at commit `<sha>```
    match and its artifact-path pairing can never cross a clause boundary
    (#893; incident #841: the lazy span crossed from a results clause's
    "committed" to the figures clause's "at commit `<sha>`" and validated
    eval_results paths against the figures SHA). A ``. `` whose preceding
    word is a known abbreviation (``e.g.`` / ``cf.`` / ...) does not
    split. An UNBALANCED backtick latches ``in_code`` for the line's
    remainder — deliberately fail-safe: no further splits means the
    suffix keeps today's whole-line behavior, never a new false FAIL."""
    clauses: list[str] = []
    buf: list[str] = []
    in_code = False
    i = 0
    while i < len(line):
        ch = line[i]
        if ch == "`":
            in_code = not in_code
            buf.append(ch)
            i += 1
            continue
        if not in_code:
            m = _CLAUSE_DELIM_RE.match(line, i)
            if m is not None:
                # Abbreviation guard: applies only to the ". " delimiter —
                # look at the word ending the current buffer (dot excluded).
                if ch == ".":
                    tail = "".join(buf)
                    last_word = tail.rsplit(None, 1)[-1] if tail.split() else ""
                    if last_word.lower().strip("(,") in _DOT_ABBREVIATIONS:
                        buf.append(ch)
                        i += 1
                        continue
                clauses.append("".join(buf))
                buf = []
                i = m.end()
                continue
        buf.append(ch)
        i += 1
    clauses.append("".join(buf))
    return clauses
```

## 11. Decision Rationale

- **Delimiter set = `;\s` | `\s·\s` | `\.\s` (whitespace-required).**
  *Why:* whitespace after the delimiter is the discriminator that protects extension dots (`foo.json`), version strings, and URL punctuation — none of which contain spaces — while catching every prose clause boundary the corpus actually uses. *Source:* grepped corpus, 9 real lines (`tasks/{completed,archived,awaiting_promotion}/*/body.md`): `;` in #601 (";  re-read gate…"), #549 ("issue-549; lands on main"), `. ` sentence boundaries + `;` in the live #841 footer (line 141: "…HF data revision `…`. Result JSONs: …; per-context projections …. Figures pinned to `4824a567aa`…"), ` · ` is the v4 footer separator (e.g. `**Repro:** 1x H100, 47 min · entry` in the test corpus's `_V4_GOOD_BODY`). Simulation over all 9 lines: pair extraction identical old-vs-new (§5.3).
- **Em-dash " — " and ":" deliberately NOT delimiters.** *Why:* corpus shapes put them BETWEEN a path and its own sha claim — #549/#477: "`…` — pinned/committed at commit `<sha>`"; #601: "…verdict): `eval_results/issue_601/` committed at commit…". Splitting there would strand genuine pairs (safe-direction but a real coverage loss on a plausible footer shape). *Source:* the #477/#549/#601 verbatim lines above.
- **Markdown-link boundaries NOT delimiters** (the task sketch offered them as an option). *Why:* #550/#538's genuine, currently-verified pair has its backticked path INSIDE a link label following the sha clause ("committed to git at commit `bb773d9c7` (…): [`eval_results/issue_550/`](url)"); a link-boundary split would drop it. *Source:* #550:275, #538:476 verbatim + simulation (pair preserved under the chosen set).
- **Backtick-span protection via a linear scanner (not a regex split).** *Why:* the design guidance requires not breaking backticked spans; a stateful scan is the simplest correct way to honor code spans, and the whitespace-required delimiters make it belt-and-suspenders rather than load-bearing. *Source:* task body diff-sketch guidance; `_ARTIFACT_PATH_RE`'s `` [^\s`]+ `` (paths contain no spaces) read from code.
- **`finditer` per clause (not `search`).** *Why:* fixes the clarifier-named secondary defect (only first claim per line validated) at zero extra risk — each match window is already clause-bounded. *Source:* clarifier context + §5 test 2.
- **`_COMMITTED_AT_SHA_RE` kept verbatim; only its input window changes.** *Why:* minimal blast radius; the regex contract (anchoring comment, sha class 4–40 hex) is documented and referenced. *Source:* grep confirms exactly one use site — definition :3653, use :4081; sibling checks 8b (:4230) and per-figure (:4595) use different regexes and are untouched.
- **Abbreviation guard on the `. ` delimiter only (v2).** *Why:* Codex methodology MF2 (upheld as binding concern by the reconciler): a comma-less `e.g. ` between "committed" and its same-sentence path/sha claim would otherwise flip a TRUE FAIL into a silent PASS — protection removal in a verifier whose job is not-silently-losing coverage. Guard applies only to `. ` (the `;`/`·` delimiters have no abbreviation homonyms); over-inclusion of tokens is fail-safe (degrades toward status-quo whole-line behavior). *Source:* Codex methodology verdict (/tmp/codex-critic-893-methodology-r1-output.md) + methodology reconciler binding concern 2; no corpus instance (grep), so the set is convention-grounded, pinned by test 7.
- **v4-footer-route + interpunct test coverage (v2).** *Why:* statistics reconciler binding Must-Fix — the ` · ` splitter leg had zero witness (no test, no corpus line contains a U+00B7 committed-at-commit shape outside #893's own body), so a dead `\s·\s` branch would ship green while the v4 `**Repro:**` footer (the #841 production route, `_v4_footer_text`) is exactly where the incident class recurs. *Source:* statistics reconcile verdict; `_V4_GOOD_BODY` footer shape (tests ~:4466); `_v4_footer_text` / `_repro_section_text` (:2257).
