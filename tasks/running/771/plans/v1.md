### 4.2 The WARN predicate (deliverable 1)

WARN fires iff ALL of:
1. Data disk is a LIVE mount: `findmnt --mountpoint "${EPS_VM_DATA_DISK_PATH:-/mnt/eps-data}"` succeeds (seam-overridable by new `EPS_WORKTREE_DATADISK_PROBE`).
2. Worktree bind is NOT live: `_bind_is_live` returns non-zero (reuses existing function + `EPS_WORKTREE_BIND_PROBE` seam).
3. Strict assertion is OFF: `EPS_WORKTREE_REQUIRE_BIND != 1` (WARN is the strict complement of the assertion).
4. Session has not already warned: sentinel file does not exist (§4.4).

This predicate is **strictly weaker** than the assertion's FATAL predicate (`EPS_WORKTREE_REQUIRE_BIND=1 AND bind not live`): the two are mutually exclusive on `EPS_WORKTREE_REQUIRE_BIND` so exactly one of {FATAL, WARN, silent-OK} happens.

Bash pseudocode:

```bash
_datadisk_is_live() {
  local probe="${EPS_WORKTREE_DATADISK_PROBE:-}"
  if [ -n "$probe" ]; then eval "$probe"; return $?; fi
  # Production: the data-disk path must itself be a live mountpoint.
  # --mountpoint (NOT --target): --target walks UP and rc=0 for any dir on a
  # mounted fs, which would falsely report an UNMOUNTED data disk as present
  # (same trap the bind probe documents at lines 83-91).
  findmnt --noheadings --mountpoint "${EPS_VM_DATA_DISK_PATH:-/mnt/eps-data}" >/dev/null 2>&1
}

# Attached-but-inert WARN (#681 cutover not yet applied). STRICTLY WEAKER than
# the EPS_WORKTREE_REQUIRE_BIND assertion above: it fires only when that
# assertion is OFF, the data disk IS a live mount, and the worktree bind is
# NOT live. Once-per-session via a sentinel; never blocks creation.
INERT_SENTINEL="$REPO_ROOT/.claude/cache/worktree-inert-warned"
if [ "${EPS_WORKTREE_REQUIRE_BIND:-0}" != 1 ] && [ ! -e "$INERT_SENTINEL" ]; then
  if _datadisk_is_live && ! _bind_is_live; then
    _dd="${EPS_VM_DATA_DISK_PATH:-/mnt/eps-data}"
    {
      echo "new_worktree: WARN — #681 data disk ($_dd) is mounted but"
      echo "new_worktree:   $REPO_ROOT/.claude/worktrees is NOT bind-mounted onto it,"
      echo "new_worktree:   so this worktree's caches will land on the boot disk / with NO quota."
      echo "new_worktree:   Cutover: bind .claude/worktrees onto $_dd then export"
      echo "new_worktree:   EPS_WORKTREE_REQUIRE_BIND=1 EPS_WORKTREE_ASSIGN_QUOTA=1 (cron + bootstrap)."
      echo "new_worktree:   See task #681 / CLAUDE.md 'Disk hygiene'."
    } >&2
    mkdir -p "$(dirname "$INERT_SENTINEL")" 2>/dev/null || true
    : > "$INERT_SENTINEL" 2>/dev/null || true   # best-effort; never fail creation
  fi
fi
```

`set -Eeuo pipefail` is active, so sentinel writes carry `|| true` — a read-only or missing `.claude/cache` must never abort worktree creation (the WARN is advisory).

### 4.5 Once-per-session mechanism (deliverable 4)

**Decision: a sentinel file** at `$REPO_ROOT/.claude/cache/worktree-inert-warned`, touched on first WARN, short-circuited if present.

Argument:
- `new_worktree.sh` is a fresh bash process per invocation. The real spam risk is ACROSS invocations in one orchestrator session — a process-local variable or `export EPS_..._WARNED=1` does not propagate to sibling spawns (Bash tool, subagents, cron tick are different parents).
- A filesystem sentinel survives across independent invocations, is idempotent, needs no cleanup, and is co-located with the existing `.claude/cache/worktree-migration.LOCK` sentinel the script already reads (line 62) — directory + pattern are established.
- Staleness is self-correcting: the predicate's `EPS_WORKTREE_REQUIRE_BIND != 1` flag-check short-circuits post-cutover regardless of the sentinel, so a stale sentinel can never hide a real post-cutover FATAL.

## 11. Decision Rationale

N/A — no model training (no lr/schedule/warmup, batch, epochs, LoRA, weight decay, seq length, optimizer, precision). The non-obvious **engineering** choices recorded for the reviewer:

- **Default-path fallback `${EPS_VM_DATA_DISK_PATH:-/mnt/eps-data}`.** Why: `EPS_VM_DATA_DISK_PATH` is unset on the live VM (verified) yet `/mnt/eps-data` is the real mount; a literal-env predicate would no-op on the exact machine with the bug. *Source:* in-repo idiom — `_assign_project_quota` line 130 uses the identical default; live-VM probe this session confirmed the unset-env-but-mounted state.
- **`findmnt --mountpoint` (not `--target`) for the data-disk probe.** Why: `--target` walks up to containing fs and rc=0 for any dir on a mounted fs — would falsely report unmounted disk as present. *Source:* in-repo — bind probe lines 83–91 document this exact #681 round-2 Critical.
- **WARN placed after the assertion, predicate strictly weaker.** Why: fail-hard first, nudge-soft second; mutually exclusive on `EPS_WORKTREE_REQUIRE_BIND` so exactly one outcome fires. *Source:* task body's explicit deliverable 3 + existing assertion structure.
- **Sentinel-file dedup over process-env / PID checks.** Why: script is a fresh process per invocation; only a filesystem signal survives across independent same-session invocations. *Source:* existing `.claude/cache/worktree-migration.LOCK` sentinel pattern the script already reads (line 62).
- **Best-effort sentinel writes (`|| true`).** Why: under `set -Eeuo pipefail` a failed `mkdir`/`touch` must not abort the advisory-only WARN nor block worktree creation. *Source:* in-repo pattern — script uses `|| true` on non-load-bearing ops (e.g. line 163, 202, 241).
