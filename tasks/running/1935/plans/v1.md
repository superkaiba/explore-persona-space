## Method delta (what differs from the current gate)

Current: Channel B (`extract_bare_names` L104 → `resolve_bare_name` L129 → call site
L311-350) globs `{eval_results,ood_eval_results}/issue_<M>/**/<name>` for EVERY M in
`plan_issue_scope` (= any issue-number token in the plan text, L117-122), then runs every
resolution through the full classify ladder; `apply_rsync_lane_downgrade` then flips in-ref
passes to FAIL on the rsync lane. Channel A classifies a plan's own output paths through the
same ladder once they exist (the `planned-output` skip fires only at the nowhere-visible
rung, classify L275-282).

Delta — two layers plus a shared extractor, all in the one script:

1. **`extract_declared_outputs(text) -> tuple[list[str], set[str]]`** (new function): scan
   the plan for STRUCTURED output declarations only —
   - `outputs: [a, b, …]` inline bracket lists (observed: #1902 plan L292),
   - `- path: <p>` upload/deliverable rows (L330-339, brace-globs `{a,b}` expanded),
   - `glob: <p>` rows (§6.5 primary_deliverable, L206-215),
   - `sentinel: <p>` rows.
   Returns (a) declared path/glob patterns (repo-relative strings, brace-expanded; for
   Channel-A `fnmatch` matching) and (b) declared BASENAMES (extension-bearing, glob-char-free
   after expansion; for Channel B). Prose mentions are deliberately NOT parsed (too
   false-positive-prone); prose-only output names like #1902's `pilot_report.json` are
   covered by layer 3 (foreign demotion) instead.
2. **Channel B — own-issue declared-output skip:** at the call site, a bare name whose
   basename ∈ declared basenames and whose resolutions land under THIS issue's dirs → per
   resolved path, `Finding(path, "skip", "bare-name-declared-output", …, "B")` (ledger row,
   no classify). Undeclared own-issue resolutions keep the FULL ladder (the #1434
   protection, untouched).
3. **Channel B — foreign-issue demotion (the filed incident):** a bare-name resolution
   under a FOREIGN issue dir (parse M from `(ood_)?eval_results/issue_(\d+)/`; M != issue)
   is NOT a provable carry-over input — emit ONE
   `Finding(name, "warn", "bare-name-foreign-issue", …, "B")` per bare NAME summarizing its
   foreign resolutions (detail lists up to ~5 resolved paths + the remediation: "cite the
   full repo-relative path if this IS a consumed input"), instead of running the ladder per
   path. Runs AFTER the existing `deduped-channel-a` check, so a foreign path the plan
   ALSO cites in full (Channel A) keeps its full classification → the #1689 direction is
   structurally unaffected. Warns are untouched by `apply_rsync_lane_downgrade` (it only
   rewrites pass/in-ref), so no downgrade interplay.
4. **Channel A — declared-output skip (the 6 observed A-channel FAILs):** BEFORE classify,
   an own-issue candidate (existing `issue[-_]?<N>` boundary regex) whose path fnmatches a
   declared output pattern → `Finding(path, "skip", "planned-output-declared", …, "A")` —
   the existence-independent extension of the existing `planned-output` skip (which today
   fires only when the file exists nowhere; post-run the same path false-FAILs every
   re-gate: follow-up rounds, relaunches). Foreign-issue Channel-A citations NEVER take
   this skip regardless of declaration matching.
5. Docstring + `--lane` help note the new reasons; module docstring's residual-risks
   paragraph gains one line (declared-output-and-separately-dispatched-consumer residual,
   see Risks).

No new Finding fields, no CLI flag changes, no changes to `backends/slurm.py`,
`apply_rsync_lane_downgrade`, or the classify ladder itself.

  hold there. Mitigation: the skip ledger row names the declaration site; Step 6a.5's
  `--extra-sync-path` remediation remains available; documented in the module docstring's
  residual-risks paragraph.

  detail instructs citing the full path). No observed instance of this citation form in the
  corpus; the #1434 bare-citation incident was own-issue (still FAILs), #1689 was
  covered by full-path staging remediation.
