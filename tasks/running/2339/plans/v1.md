# Plan v1 — #2339 judge_pilot_gate: honest conditional remedy text for verdict-unsatisfiable item-limited arms

kind: infra (library bug fix — no experiment, no GPU)

## Requirement + acceptance criteria

**Requirement.** `_config_satisfiability_guard` in
`src/explore_persona_space/eval/judge_pilot.py` (lines ~613-624) tells the caller,
for every item-limited arm, to "waive it (waive_parse_fail_arms, with a recorded
reason) or accept a sub-resolution pilot (allow_subresolution_pilot=True)". Both
escapes bypass ONLY the config-time refusal; `_gate_verdict` (line ~484) then FAILs
any arm whose effective draws fall below the CALLER's `min_effective_draws_per_arm`,
unconditionally — no exemption for bypassed or waived arms. When the caller's floor
exceeds an arm's maximum realizable draws (`len(items) * n_draws`), the recommended
escapes convert a pre-spend `ValueError` into a post-spend verdict FAIL. This misled
an implementation round on #2329 into a provably-unpassable fix (markers
2026-08-17T08:12:54Z / 08:21:42Z on #2329).

**The precise doomed condition** (derived from the code, not the incident): an
item-limited arm can PASS after an escape iff `len(items) * n_draws >=
min_effective_draws_per_arm` (escapes lift the resolution floor
`floor(1/threshold)+1`, never the verdict-time min-effective floor; transport losses
only shrink effective draws further). An arm with
`len(items) * n_draws < min_effective_draws_per_arm` is verdict-doomed under EVERY
escape.

**Acceptance criteria:**
1. The item-limited remedy text is conditional per arm: verdict-doomed arms
   (`len(items) * d_eff < min_effective_draws_per_arm`) get honest remedies — lower
   the caller's `min_effective_draws_per_arm` to <= the arm's realizable draws,
   raise `n_draws`, or enlarge the arm's item pool to
   `>= ceil(min_effective_draws_per_arm / n_draws)` items — plus an explicit
   statement that `waive_parse_fail_arms` / `allow_subresolution_pilot` bypass only
   the config-time refusal and the verdict-time floor still FAILs the arm.
   Escapable item-limited arms keep the current escape-naming text.
2. Because the `allow_subresolution_pilot=True` ACCEPTED warning embeds the same
   message, a doomed arm accepted under the escape carries the honest
   guaranteed-verdict-FAIL statement in the report warnings (text-only; no
   control-flow change — the guard still downgrades to a warning under the escape,
   preserving the smoke-leg semantics and the existing test at
   tests/test_judge_pilot_gate.py:580).
3. New test (the body's missing test): escape requested AND caller floor above the
   arm's realizable draws ⇒ the pilot RUNS (no config raise) and the VERDICT still
   FAILs (`rep.passed is False`) with the min-effective failure naming the arm.
4. New test: strict mode, doomed arm ⇒ the ValueError names the real remedies and
   states the escapes cannot produce a PASS.
5. Regression pin: an escapable item-limited arm (realizable >= caller floor but <
   resolution floor) keeps the current waive/allow_subresolution remedy text.
6. Existing suite `tests/test_judge_pilot_gate.py` passes unchanged (the line-580
   downgrade test's 5-item arm at the default floor 10 with n_draws=2 realizes 10
   draws — not doomed — and must stay green).
7. `.claude/rules/gotchas.md` gains the body's requested entry (the
   `allow_subresolution_pilot` bypass-scope trap), verbatim in substance.
8. The `_truncation_failure` half of `_gate_verdict` stays byte-untouched
   (unconditional, never waivable — the body's hard constraint).
9. Docstrings: `judge_pilot_gate`'s `allow_subresolution_pilot` arg doc +
   `_config_satisfiability_guard`'s docstring each gain one clause stating the
   escape's bypass scope (config-time only).

**Explicitly out of scope (autonomous Decision, recorded in epm:clarify):** the
body's fix option 2 (feasibility-aware verdict floor) — it deliberately weakens the
hollow-evidence floor, the body flags it as needing a deliberate decision, and
#2329 is already unblocked via its own per-family call-site floor. Also out of
scope: making the guard REFUSE a doomed config even under the escape flag (a
control-flow change that would alter the escape's smoke-leg semantics; the honest
warning covers fail-fast information at zero behavior risk). `llm-judging.md` rule
26's existing description of the escape ("downgrades the refusal to a recorded
report warning") remains accurate as written — untouched.
