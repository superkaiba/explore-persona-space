## §0.0 TL;DR

- **What I'll run:** Fit the same ridge map from #779 three additional ways — once on answers written by a different model (Sonnet) in a plain style, once on Qwen's own answer shuffled to a wrong context, and keep the original Qwen-own-answer arm as the reference. No new training; the only work is generating Sonnet answers, extracting hidden states for those answers under the original contexts, and re-running the ridge fit.
- **What I expect:** The map trained on Qwen's own answers should transfer poorly to Sonnet plain answers and should fail completely on the derangement arm. If R² drops more than five points on Sonnet-plain and drops to near zero on the derangement, the map is tracking what Qwen itself will write, not just what the context implies.
- **What would change my mind:** If Sonnet-plain answers score within three points of Qwen's own answers on the held-out R², the map is mostly capturing context-side computation and the content of the answer barely matters. That would mean the #779 result is about how the model processes the prompt, not about predicting its own outputs.

## §0 Plan Summary

**Training:** No model training. Frozen Qwen-2.5-7B-Instruct, base weights only. Ridge regression (GCV, λ ∈ [1e-2, 1e4]) refit on four arms using the existing #779 substrate (5000 LMSYS contexts, 28 layers, c_last shape 5000×3584 per layer).

**Hyperparameters:** Ridge GCV λ grid: np.logspace(-2, 4, 13) — inherited from #779 `fit_h.py`; same 5-fold CV split (seed=0), same standardize-X/center-Y protocol. No novel hyperparameters. Source: #779 `fit_h.py::ridge_fit_predict`.

**Baselines / controls:** Arm A (Qwen own answers, reused #779 v_x — the reference arm). Arm B2 (Sonnet-plain: Claude Sonnet 4.5 plain-style answers, style instruction stripped before TF). Arm C (derangement null: Qwen's own answer teacher-forced under a different context via a fixed-point-free permutation, seed=42). Arm B1 (Sonnet-weird: adversarial-style answers — diagnostic only, not a hypothesis arm).

**Loss surface:** N/A — ridge regression on mean-pooled residual-stream vectors. Teacher-forcing computes mean over response token span [prompt_len:full_len] at each of 28 layers.

**Compute:** Phase 3 (TF extraction on GPU): ~3.5 GPU-h on 1× A100-80 (`lora-7b`). All other phases CPU on VM. Total: ~3.5 GPU-h + ~0.5 CPU-h. **Estimated GPU-hours (total): 4**

**Evaluation:** Primary DV = held-out R² per arm per layer (5-fold CV). Decision rule: H1 (own-output specificity) if R²_own − R²_B2 > 0.05 AND R²_C < 0.05; H2 (context-side) if all arms within ±0.03; H3 (content generality) if R²_own ≥ R²_B2 > R²_C AND R²_B2 − R²_C > 0.03. All comparisons Bonferroni-corrected α = 0.05/3 = 0.017.

**Risks (top 2):** (1) Sonnet-plain answers differ in length distribution from Qwen's own answers — mean-pooling over spans of different lengths makes the per-context vectors incomparable. Mitigation: truncate to min(Qwen_len, Sonnet_len) tokens before mean-pooling, record per-context span lengths. (2) #779 substrate bundle SHA mismatch on HF — mitigation: pin SHA1 `a770d38a15283b01c255f62810559541e03663bf` and assert at fetch.

## §1 Goal

**What:** Determine whether the #779 ridge map h: c_last(x) → v(x) — which achieves held-out R² 0.60–0.63 across evil/sycophancy/hallucination traits — is predicting the model's *own* generated content (own-output specificity hypothesis), or whether it is primarily capturing context-side computation that transfers to arbitrary answer text teacher-forced through the same context (context-processing hypothesis), or something in between (content generality hypothesis).

**Why:** If h predicts Qwen's own answers specifically (H1), then #779's result is evidence that the last-context vector encodes a prediction of the model's forthcoming *content*, not just a generic context representation. That changes the interpretation from "the model has a persona-like internal state" to "the model's context vector encodes an output prediction." If h transfers equally to external answers (H2), the result is about context-side computation, not content prediction. The distinction matters for whether h could be used as a predictive probe in deployment versus merely as an alignment diagnostic.

**Formal definitions:**

- v_own(x): mean residual-stream activation over the response tokens of Qwen's OWN generation under context x (reused from #779 pass_b v_x).
- v_B2(x): same mean, but over a Sonnet-plain answer to the same question, teacher-forced under x.
- v_B1(x): same mean, but over a Sonnet-weird answer (with style instruction stripped before TF).
- v_C(x): same mean, but over Qwen's OWN answer to question π(x) (a deranged context), teacher-forced under x. Null/derangement arm.
- h_ℓ: the ridge map at layer ℓ, fit on (c_last^ℓ, v_own^ℓ) from #779 (arm A, reference).
- R²_arm^ℓ: 5-fold held-out R² when h_ℓ (fit on arm A) is scored against v_arm^ℓ as the target.

**Kill criterion:** If the GPU extract phase (Phase 3) produces NaN activations for > 5% of contexts in any arm, abort and report as a data-quality finding.

## §2 Prior Work

**#779 substrate (direct parent):** The per-context ridge map h achieving R² 0.5977–0.6253 (evil/syc/hall) is already fit and its substrate (c_last, v_x, 5000 LMSYS contexts, 28 layers) is on HF at `superkaiba1/explore-persona-space-data/issue779_monitoring/analysis_tensors/pass_b/train_context_vectors.pt` (SHA1 `a770d38a15283b01c255f62810559541e03663bf`). This experiment directly inherits that substrate as arm A.

**Future Lens (arXiv 2311.04897, Katz et al.):** Showed that intermediate hidden states can be decoded to predict the model's eventual output token distribution (next-token logits), achieving high accuracy on factual QA. The key distinction from #779 is that Future Lens uses a learned linear probe from h_ℓ to next-token logits (a token-space prediction), whereas #779 maps to full response activation vectors (a content-space prediction). The present experiment tests whether #779's map is closer to a Future Lens–style own-output prediction or a more generic context encoding. The Future Lens finding supports H1 as a prior: linear maps from context vectors do track own-output content.

**Looking Inward (arXiv 2410.13787, Binder et al.):** Showed that models encode their own planned outputs in intermediate layers, distinguishable from external-input representations, using linear probes. This motivates the cross-arm transfer design: if h is encoding Qwen's own planned output, it should fail to predict Sonnet's output at the same position. The design here operationalizes the "own vs external" distinction in activation space rather than logit space.

**Persona Vectors (arXiv 2507.21509, Chen et al.):** The #779 parent used this recipe for extracting r_B at the response level. Relevant here as the activation-extraction baseline — we use the same mean-pooling recipe (mean over response tokens, layer-by-layer) for all four arms. The paper's finding that persona vectors transfer across prompts is consistent with H3 (content generality) if the persona activation is the dominant component of v(x).

**Teacher-forcing artifact (#432→#456):** A known risk. Teacher-forced activations under an external answer text (B1, B2, C arms) may differ structurally from activations under the model's own continuation, because the model's own generation is on-distribution while TF of external text is not. This makes the B2 arm a conservative test of H2: a low R²_B2 could indicate H1 *or* TF artifact. The derangement arm C controls for this: it uses Qwen's OWN answer text (on-distribution) but under the wrong context, so TF artifact is equalized. If R²_C is also low, H1 is supported on TF-artifact-controlled grounds.

**Prior work on R² baseline:** #779's 28-layer R² profile peaks at L19 = 0.677 (evil trait), with read-out layers {evil:14, syc:26, hall:17} selected by best-layer CV. This plan inherits those layer selections as the primary evaluation slots, with full 28-layer profiles reported.

## §3 Hypothesis

**H1 — Own-output specificity:** h predicts Qwen's own answers specifically. Prediction: R²_own − R²_B2 > 0.05 AND R²_C < 0.05 (at the read-out layer for each trait). Operationally: the map trained on arm A transfers poorly to arm B2 and fails on the derangement control.

**H2 — Context-side processing:** h captures context computation, not content. Prediction: all four arms within ±0.03 R² of each other at the read-out layer. Operationally: knowing only the context, the map predicts any answer's activation profile equally well.

**H3 — Content generality:** h captures content-compatible activation structure, generalized beyond Qwen's own outputs. Prediction: R²_own ≥ R²_B2 > R²_C AND R²_B2 − R²_C > 0.03. Operationally: the map transfers partially to Sonnet-plain (content matters) but fails completely on the derangement (wrong content = wrong prediction), with R²_own still the highest.

**What would falsify all three:** R²_C > R²_B2 (the derangement arm scores higher than Sonnet). This would indicate an experimental artifact (likely the TF artifact) and would invalidate the design's discriminability.

**Quantitative thresholds (pre-registered):**

| Arm comparison | H1 threshold | H2 threshold | H3 threshold |
|---|---|---|---|
| R²_own − R²_B2 | > 0.05 | ≤ 0.03 | ≤ 0.05 |
| R²_own − R²_C | > 0.10 | ≤ 0.06 | > 0.05 |
| R²_B2 − R²_C | (any) | ≤ 0.03 | > 0.03 |
| R²_C absolute | < 0.05 | ≥ 0.02 | < 0.05 |

Evaluated at the per-trait read-out layer {evil:14, syc:26, hall:17}; all comparisons Bonferroni α = 0.017. Paired t-tests (5 fold values, 5 d.f.) across folds for each comparison.

### Phase 3: Teacher-forced activation extraction (GPU pod, `lora-7b`, ~3.5 GPU-h)

For each arm in {B1, B2, C}, and for all 5000 contexts (minus dropped), extract mean-pooled residual-stream activations at all 28 layers using the same recipe as `scripts/issue779_collect.py::capture_answer_vector()`.

**TF recipe (from `scripts/issue779_collect.py`):**

```python
def capture_answer_vector(model, tokenizer, messages, answer_text, layers):
    """
    Build full_messages = messages + [{"role": "assistant", "content": answer_text}]
    Apply chat template (add_generation_prompt=False) -> input_ids
    Forward pass with output_hidden_states=True
    prompt_len = len(tokenizer.apply_chat_template(messages, add_generation_prompt=True))
    full_len = len(input_ids)
    v_s = mean(hidden_states[ℓ][0, prompt_len:full_len, :]) for ℓ in layers
    """
```

Assert `GENERATION_SUFFIX = "<|im_start|>assistant\n"` is present at position prompt_len in the tokenized sequence (sanity check that the template is applied correctly).

### Phase 4: Ridge refitting (VM, CPU, ~20 min)

Load the arm A activations (v_x from pass_b bundle) and the three new arm tensors. For each trait t ∈ {evil, sycophancy, hallucination} and each arm s ∈ {B1, B2, C}:

```python
from src.explore_persona_space.experiments.issue_779.fit_h import ridge_fit_predict
import numpy as np

# X_train: c_last at read-out layer for trait t, shape (5000, 3584)
# Y_train_A: v_own at read-out layer, shape (5000, 3584)
# Y_target_s: v_s at read-out layer, shape (5000, 3584)

# 5-fold CV to estimate R² (same split as #779, seed=0)
from sklearn.model_selection import KFold
kf = KFold(n_splits=5, shuffle=True, random_state=0)
r2_folds = []
for train_idx, val_idx in kf.split(X_train):
    Y_pred = ridge_fit_predict(X_train[train_idx], Y_target_s[train_idx], X_train[val_idx])
    # R² = 1 - SS_res / SS_tot
    ss_res = np.sum((Y_target_s[val_idx] - Y_pred)**2)
    ss_tot = np.sum((Y_target_s[val_idx] - Y_target_s[val_idx].mean(0))**2)
    r2_folds.append(1 - ss_res / ss_tot)
r2_per_arm[t][s] = r2_folds
```

**Cross-arm transfer matrix:** also score h fit on arm A against arm B2 targets directly (transfer test — same X, different Y). This requires fitting h on arm A training fold, then predicting arm B2 validation fold. Add as a separate row in the output.

Full 28-layer R² profiles: run the above for all 28 layers (not just read-out layers), to enable layer-by-layer transfer plots.

Persist: `eval_results/issue_823/ridge_r2_by_arm.json` (dict: `{trait: {arm: [5 fold values per layer]}}`).

### Phase 5: Validity diagnostics (VM, CPU, ~10 min)

1. **Text decorrelation check:** For each arm pair (B2 vs own, C vs own), compute per-context cosine similarity between arm's answer text TF-idf vectors. If cos(B2, own) > 0.8 for > 20% of contexts, flag: B2 answers may be paraphrasing Qwen's own answers, collapsing the arm distinction.

2. **OOD log-P check:** Compute base Qwen log-P (length-normalized) of B2 answers and C answers. B2 (Sonnet) should have lower log-P than arm A (Qwen's own) — confirms B2 is genuinely OOD. If B2 log-P ≈ arm A log-P, flag: the external-arm distinction may be weak.

3. **Per-context activation cosine:** For each context i, compute cos(v_B2(i), v_own(i)) at the read-out layer. Report mean ± std. A high mean (> 0.9) would suggest the activation profiles are near-identical regardless of answer text, supporting H2.

4. **Length distribution:** Report answer token lengths for arms A, B1, B2, C. If B2 lengths differ > 2× from A lengths on average, the truncation in Phase 3 discards more than half the B2 answer — flag as a design limitation.

Persist: `eval_results/issue_823/validity_diagnostics.json`.

**Why code not model call:** Text decorrelation (TF-idf cosine) and log-P computation are deterministic closed-form operations on existing tokenized text — no unstructured judgment required. OOD log-P is a single HF forward pass with no temperature or sampling. Model-call alternative would add latency, cost, and nondeterminism without benefit.

Sonnet-plain answers (arm B2) are LLM-generated synthetic responses to those real queries — tier 3 for the B2 completion content, but the context distribution is tier 2.

**Completion provenance:** N/A — not a behavior-implantation experiment. Teacher-forced activations are not training completions.

**Marker implant recipe:** N/A — not a behavior-implantation experiment.

**Persona-vectors extraction:** N/A — no new persona-vector extraction. Inheriting #779's v_x.

**Multi-arm resolution-band:** N/A — no band-stop gate; ridge fit, not marker training.

## §9 Resources & Parallelism

**GPU phases:** Phase 3 only (TF extraction for arms B1, B2, C). Intent: `lora-7b` (1× A100-80, 80 GB HBM). Justification: Qwen-2.5-7B-Instruct bf16 weights ~14 GB + batch_size=8 × seq_len × 3584 fp32 activations captured at 28 layers → peak ~28 GB HBM. L4 (16 GB) would OOM on model weights alone. ## §11 Decision Rationale

**Ridge GCV (λ ∈ [1e-2, 1e4], 13 points, SVD-based):**
- What: GCV ridge regression, inherited exactly from `src/explore_persona_space/experiments/issue_779/fit_h.py::ridge_fit_predict`.
- Why: Same function used in #779, which achieved R² 0.60–0.63. Reusing the same ridge implementation is required for cross-arm comparisons to be valid (any change in the fitter would conflate design changes with fitter changes).
- Source: #779 `fit_h.py` (confirmed in code review above, lines 1–128).
- Alternatives: MLP rejected per user directive ("ridge only, no MLP").

**5-fold CV split (KFold seed=0):**
- What: Same 5-fold split used in #779.
- Why: Same split is required for the arm A baseline (R²_own) to be directly comparable to #779's published R² values. Using a different split would introduce split-sampling variance that confounds the arm comparison.
- Source: #779 `eval_results/issue_779/percontext_recon.json` (n_folds=5, seed=0).
- Alternatives: 10-fold would reduce variance but breaks comparability with #779.

**Read-out layers {evil:14, syc:26, hall:17}:**
- What: Pre-registered primary evaluation layers, inherited from #779.
- Why: These are the best-CV-layer selections from #779's own fitting. Using the same layers avoids a free-axis selection over 28 layers that would require selection-symmetric null correction.
- Source: `eval_results/issue_779/percontext_recon.json::read_out_layers`.
- Alternatives: Best-layer per arm — rejected; would introduce selection bias (which arm's best layer to use?).

**Sonnet-plain (B2) temperature=1.0, max_tokens=1024, seed=42:**
- What: Same sampling params as #779's pass_b generation.
- Why: Matching the generation params to #779's own-answer generation ensures the B2 answers are plausible-length responses (not truncated or degenerate). Seed=42 is the project default for reproducibility.
- Source: `scripts/issue779_collect.py` pass_b SamplingParams (confirmed in prior session).
- Alternatives: Temperature=0 (greedy) — rejected; greedy Sonnet answers are more formulaic and might inflate B2 R² by reducing answer-space variance.

**Derangement permutation seed=42:**
- What: Fixed-point-free permutation of 5000 context indices, seed=42.
- Why: Seed fixed for reproducibility; 42 is project default. Fixed-point-free required so no context maps to itself (which would make arm C identical to arm A for that context).
- Source: Design requirement; project standard seed.
- Alternatives: Multiple derangement seeds (ensemble) — rejected; a single derangement is sufficient to establish near-zero R²_C under H1; ensemble would add compute without changing interpretation.

**Batch size 8 for TF extraction:**
- What: 8 contexts per forward pass on A100-80.
- Why: Qwen-2.5-7B bf16 = ~14 GB model weights. Capturing 28 layers × 3584 hidden × batch_size=8 × seq_len (avg ~512 tokens) fp32 = ~8 × 512 × 28 × 3584 × 4 bytes ≈ 1.6 GB activation buffer. Total ~15.6 GB — well within 80 GB A100-80 HBM.
- Source: CLAUDE.md HBM sizing rule; arithmetic above.
- Alternatives: Batch size 16 — feasible but adds risk; batch size 4 — safe fallback if OOM.

**HF SHA1 pin `a770d38a15283b01c255f62810559541e03663bf`:**
- What: Content identity assertion for the pass_b bundle.
- Why: The plan's arm A baseline (R²_own = #779's R²) is only valid if the reused tensor is the exact #779 artifact. SHA1 pin (check (f) of the artifact reuse fitness check) ensures the HF mirror matches the locally-verified file.
- Source: Prior session HF verification (`huggingface_hub.list_repo_files` + mmap probe).
- Alternatives: No pin — rejected; a stale HF mirror would silently confound the baseline.

**Reused artifact fitness checks (a)-(h) for pass_b bundle:**
- (a) Recipe match: same Qwen-2.5-7B-Instruct, same LMSYS-Chat-1M contexts, same TF recipe from `issue779_collect.py`. PASS.
- (b) Valid measurement regime: R² 0.5977–0.6253, not saturated (ceiling would be 1.0). PASS.
- (c) Required cells present: arm A needs `cx_last` (context vectors) and `v_x` (own-answer vectors), both confirmed shape (5000,28,3584). PASS.
- (d) Single-variable-change: arm A is the reference, not a changed variable. PASS.
- (e) Producing issue (#779) not retracted: #779 is the direct parent of #823, currently in `planning` status. PASS.
- (f) Content identity: SHA1 `a770d38a15283b01c255f62810559541e03663bf` asserted in Phase 0. PASS.
- (g) Application-scaling: ridge regression, no adapter scaling. N/A.
- (h) Source resolution + target-backend fetchability: HF-resolved via `list_repo_files`; GCP lane can `hf_hub_download` it in Phase 0 (script runs on VM before pod provisions). PASS.

**arm C text source — `issue779_monitoring/raw_completions/pass_b/` existence:**
- Source resolution: scheduled in Phase 0 via `list_repo_files`. Not yet verified (pending Phase 0 execution).
- If absent: fallback = re-generate Qwen answers on deranged contexts via vLLM; adds ~1 GPU-h. Flagged in §12.

**Sonnet generation model `claude-sonnet-4-5-20250929`:**
- What: The project's standard judge model, reused here as the external-answer generator.
- Why: Cross-family from Qwen, ensuring B2 answers are genuinely from a different model family. `claude-sonnet-4-5-20250929` is the project standard (CLAUDE.md).
- Source: CLAUDE.md "LLM judge = `claude-sonnet-4-5-20250929`".
- Alternatives: GPT-4o — would work but adds cost and is not the project standard.

**Length truncation to min(len_own, len_external) before mean-pooling:**
- What: Truncate both spans to the shorter one before computing the mean activation.
- Why: Mean-pooling over spans of different lengths conflates position-weighting with content: a longer span includes more tokens at different positions in the residual stream. Truncating equalizes the span length and makes the mean-pooled vectors comparable across arms.
- Source: Standard practice for length-normalized activation comparison; no prior issue citation (ungrounded — but the design requirement is clear and the alternative would introduce a known confound).
- Alternatives: No truncation — rejected; length-confounded comparison.
