# Plan v1 — #1915 workflow-fix: `rsync_covered()` consults `RSYNC_EXCLUDE_PATTERNS`

## Plan Summary

Extend the rsync-lane coverage downgrade in `scripts/verify_carryover_inputs.py`
(#1835) so that a committed citation nested under an rsync-EXCLUDED directory
name INSIDE an include tree (e.g. `tests/fixtures/eval_results/a.json`) no
longer false-PASSes: the main SLURM-lane rsync carries
`--exclude <pat>` for every `backends.slurm.RSYNC_EXCLUDE_PATTERNS` entry, and
rsync slash-free patterns match at EVERY depth, so such a file is guaranteed
absent on the instance despite include-tree membership. Paths covered by an
`--extra-sync-path` are NEVER exclude-checked — `build_extra_rsync_command`
(slurm.py:886) is deliberately exclude-free, so extra-sync coverage genuinely
stages the file. ~15-line change + 3 pin tests. 0 GPU-h; NOT architectural
(no public contract change — the touched helpers have exactly 2 call sites,
both updated in this diff).

## Requirement + acceptance criteria (code change)

**Requirement.** `apply_rsync_lane_downgrade` downgrades a
`Finding(verdict='pass', reason='in-ref')` to `fail`/`rsync-lane-not-synced`
when EITHER (a) the path is not covered by the cover set (existing behavior,
unchanged) OR (b) the path is covered ONLY by a main `RSYNC_INCLUDE_PATHS`
tree AND some component of the path matches an `RSYNC_EXCLUDE_PATTERNS`
entry (new). A path covered by an `--extra-sync-path` prefix is never
downgraded by (b).

**Acceptance criteria:**
1. A committed, git-reachable citation `tests/fixtures/eval_results/a.json`
   (nested excluded dir inside the `./tests` include tree) downgrades to
   `fail`/`rsync-lane-not-synced` under `--lane rsync`; the `detail` names
   the matching exclude pattern AND the `--extra-sync-path` remediation
   (which structurally works — the extra rsync has no excludes).
2. The same citation WITH `--extra-sync-path tests/fixtures/eval_results`
   stays `pass`/`in-ref` (exclude check suppressed on extra-covered paths).
3. A plain include-tree citation with no excluded segment (e.g.
   `data/sft/train.jsonl`) stays `pass`/`in-ref` — zero regression on the
   existing behavior; ALL existing tests in
   `tests/test_verify_carryover_inputs.py` stay green unmodified except the
   `_rsync_findings` helper (line 431), which threads the new
   extra-cover argument.
4. `ruff check` + `ruff format --check` clean on both touched files.
5. The check stays READ-ONLY (verify, never mutate) — no new writes, no
   network.

## Method delta (vs prior work)

#1835 (PR #1596, squash `dcf37f97465c`) added include-tree MEMBERSHIP
(`rsync_covered` prefix test) + the `--extra-sync-path` knob. This plan adds
the exclude-pattern SUBTRACTION the #1835 code-reviewer round-1 Minor 1
flagged as a deliberate out-of-plan extension: membership in an include tree
is necessary but not sufficient, because the main rsync's `--exclude`
patterns apply at every path depth. The key semantic distinction (resolved
from source at clarify time): extra-sync coverage bypasses excludes
(`build_extra_rsync_command` passes NO `--exclude` flags), so the exclude
check applies only to include-tree-derived coverage.

   ```python
       """De-dot-anchored --extra-sync-path values only (exclude-free rsync)."""
       from explore_persona_space.backends.slurm import validate_extra_sync_paths
       return [p.removeprefix("./") for p in validate_extra_sync_paths(extra_paths or ())]
   ```

2. New `rsync_excluded(path, exclude_patterns)` — per-segment match against
   `backends.slurm.RSYNC_EXCLUDE_PATTERNS` (lazy import, mirroring
   `rsync_cover_set`):

   ```python
   def rsync_excluded(path: str, exclude_patterns: tuple[str, ...]) -> str | None:
       """First matching exclude pattern, or None.

       Slash-free patterns fnmatchcase EVERY path segment (rsync matches
       unanchored patterns at every depth; dir-only patterns are checked
       against the final segment too — a deliberate conservative deviation
       that fails toward a cheap false FAIL, never a stranded false PASS).
       A slash-bearing pattern (e.g. '.claude/worktrees/') is a
       transfer-root prefix match (unreachable inside today's include
       trees; kept for completeness).
       """
       segs = [s for s in path.split("/") if s]
       for pat in exclude_patterns:
           core = pat.rstrip("/").removeprefix("./")
           if "/" in core:
               if path == core or path.startswith(core + "/"):
                   return pat
           elif any(fnmatch.fnmatchcase(s, core) for s in segs):
               return pat
       return None
   ```

3. `apply_rsync_lane_downgrade(findings, *, cover_set, extra_cover=())` —
   new keyword; downgrade condition becomes:

   ```python
   covered = rsync_covered(f.path, cover_set)
   pat = None
   if covered and not rsync_covered(f.path, list(extra_cover)):
       pat = rsync_excluded(f.path, RSYNC_EXCLUDE_PATTERNS)
   if f.verdict == "pass" and f.reason == "in-ref" and (not covered or pat):
       # existing Finding construction; when `pat` fired, the detail
       # additionally names the matching pattern, e.g.
       # "inside an include tree but path segment matches RSYNC_EXCLUDE_PATTERNS
       #  entry '<pat>' — the main rsync excludes it; re-dispatch with
       #  --extra-sync-path <path> (the extra rsync applies no excludes)"
   ```
