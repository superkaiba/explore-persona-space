# Plan — #1582: escalate keep-running pods with wedged owners

## 0.0 TL;DR (plain English)

- **What I'll build:** a new escalate-only arm inside the watcher's pod-safety pass. Today, a pod tagged `keep-running` is completely invisible to the watcher — the tag short-circuits every check, so when the session that owns the pod wedges (as happened on #1345: 3.7 days frozen, pod billing 2.5 days at 0% GPU), nobody is told. The new arm checks, for every tagged RUNNING pod whose task has gone quiet for ≥12h, whether the owning session is provably wedged or absent — and if so, sends a Telegram push + writes a durable log row + posts one task marker with the exact recovery commands.
- **What I expect:** on the #1345 timeline the arm would have fired ~13h after the last real progress (2 watcher ticks past the 12h threshold) instead of the ~71h the manual recovery took — and it never stops or terminates anything, so a false alarm costs one push, not lost work.
- **What would change my mind:** if the owner-liveness evidence can't be made conservative enough — i.e. healthy long-running sessions routinely look "wedged" for >12h under the chosen signals — the task-marker leg gets dropped (sidecar + push only) or the pass is shipped disabled-by-default. The 12h threshold is the same abandonment judgment two existing passes already use, so I don't expect this.

2. **Pure predicate** (hermetically testable, mirrors `decide_unlaunched_orphan` / `decide_pod_wedge`):

```python
def decide_keep_running_owner_escalation(
    *,
    progress_gap_s: float | None,   # now - newest REAL progress (or pod created_at fallback); None = unknown
    owner_state: str,               # "live" | "wedged" | "absent" | "unknown"
    missed: int,                    # consecutive confirmed ticks so far (kr_owner_missed)
    threshold: int,                 # the pass's --threshold (default 2)
    min_idle_s: float,
    first_ts: float | None,         # episode onset (None = no episode)
    last_alert_ts: float | None,
    now: float,
    realert_s: float,
) -> tuple[str, int]:
    """Returns (action, new_missed); action in {"clear","hold","escalate","re-alert"}.

    - progress_gap_s is None or < min_idle_s -> ("clear", 0)   # task recently progressed / unknowable
    - owner_state == "live"                  -> ("clear", 0)   # owner demonstrably alive
    - owner_state == "unknown"               -> ("hold", missed)  # freeze: fail toward no-fire, keep episode
    - owner_state in {"wedged","absent"}:
        new_missed = missed + 1
        new_missed < threshold               -> ("hold", new_missed)   # accumulate, no emission
        first_ts is None                     -> ("escalate", new_missed)  # episode opens: marker+push+sidecar
        last_alert_ts is None
          or now - last_alert_ts >= realert_s -> ("re-alert", new_missed)  # push+sidecar only
        else                                 -> ("hold", new_missed)
    Boundary: progress_gap_s >= min_idle_s COUNTS as idle (>= fires, mirroring
    decide_idle_unmapped's `idle_age_s < idle_reap_s -> clear` complement).
    """
```

3. **Owner resolution helper**:

```python
def _keep_running_owner_state(issue: int, now: float, min_idle_s: float) -> tuple[str, dict]:
    """Classify the owning session(s) of `issue`: "live"|"wedged"|"absent"|"unknown", + evidence dict.

    1. not _daemon_reachable() -> ("unknown", {reason: "daemon-unreachable"})
    2. children = _live_children(); None -> ("unknown", ...)
    3. sid->pid map from children (the stale_registration_pass L23003 pattern).
    4. Candidate owner pids (union):
       a. registration sids: json-read issue-<N>.json + manual-issue-<N>.json
          (field happy_session_id) that appear in the sid->pid map;
       b. cwd-mapped children: os.readlink(f"/proc/{pid}/cwd") (fail-soft per child)
          where attribute_issue(cwd, "") == issue  — covers the #1345 `~#N`
          cwd-inferred owner class with no registration file.
    5. No candidates -> ("absent", {...}).
    6. Fresh self-report rescues: _self_report_age_seconds(issue, now) age is not None
       and age < min_idle_s -> ("live", ...). Missing/malformed does NOT rescue
       (decide_stale_registration parity).
    7. Per candidate pid: _transcript_idle_age_s(pid, now):
       - any idle < min_idle_s -> ("live", ...)
       - any (None, reason)    -> ("unknown", ...)   # a wrong signal is worse than none
       - all >= min_idle_s     -> ("wedged", {sid, pid, transcript_idle_s: max(...), ...})
    """
```

## 11. Decision Rationale

1. **Owner-idle / marker-gap threshold = 12h (`EPM_KEEP_RUNNING_WEDGED_OWNER_MIN_H`).**
   What: both the task marker-gap floor and the owner transcript-idle floor. Why one knob: both measure the same construct ("abandoned for N hours") and splitting them doubles tuning surface for no discriminative gain. Source: `STALE_REGISTRATION_IDLE_S = UNMAPPED_IDLE_REAP_S` = 12h (`autonomous_session_watch.py` L22875 + the #845d/#1039 rationale — the project's standing abandonment judgment, already trusted for the MORE invasive unregister/reap actions); incident margin: #1345's window was ~72.1h ≫ 12h, and the arm fires ~12h20m in. Alternatives: 6h (rejected — closer to legitimate long quiet phases; the stalled-detector's LONG_PHASE_HEARTBEAT leash exists precisely because multi-hour quiet is normal), 24h (rejected — halves the win for no false-positive evidence).
2. **Confirmation = 2 consecutive ticks (reuses the pass `--threshold`, default 2).**
   What: `missed+1 >= threshold` before any emission. Why: a single transient daemon/transcript/API misread must not page. Source: the pod-safety 2-miss guard (`decide_pod_safety` L3105-3107) and the #692 wedge arm's identical guard (L3199) — the established "~20 min at a 10-min cron" debounce.
3. **Re-alert TTL = 24h (`EPM_KEEP_RUNNING_WEDGED_REALERT_H`).**
   What: push+sidecar repeat cadence while unresolved. Source: `EPM_ROOT_DRAFT_REALERT_HOURS` = 24h (#1341) and `EPM_COMPLETED_UNMERGED_REALERT_HOURS` = 24h (#1564) — the watcher's standing unresolved-condition re-page cadence. Alternative: episode-open-only (rejected — the incident shows a single missed push can cost days; a daily re-page bounds that to 24h).
4. **Escalate-only, never auto-stop.**
   What: the arm emits, mutates nothing. Source: task-body hard constraint (verbatim); the #770 precedent (auto-action reserved for the provably-safe matured `keep_running is False AND inputs_ok` case — here `keep_running is True` by construction, so no safe auto-action exists); the #679 warn-don't-delete posture. Alternative: auto-`remove-tag` + let the auto-stop fire (rejected — silently overriding an explicit user tag is the exact behavior `decide_pod_wedge` MF2 forbids).
5. **Wedge evidence = transcript idle + self-report (NOT wrapper CPU-delta).**
   What: owner classified off `_transcript_idle_age_s` + `_self_report_age_seconds`. Why: transcript idleness is the direct, already-hardened signal (happy-log-only resolution with fail-toward-keep, #845/#1039) and satisfies the incident evidence (the #1345 wrapper's transcript was days-idle); CPU-delta would duplicate the orphan-wrapper pass's per-pid two-tick baseline state machinery (`EPM_ORPHAN_WRAPPER_CPU_FRAC_MAX`, #1215) for no added discrimination — a 0%-CPU wrapper with a fresh transcript is impossible (writes imply wakes). Source: `_transcript_idle_age_s` docstring L21560-21574; #1215's delta-CPU design cost. Alternative rejected accordingly.
6. **Sidecar at `.claude/cache/keep-running-wedged-events.jsonl`.**
   Source: the pod/billing-escalation sidecar convention (`disk-guard-events.jsonl`, `gcp-janitor-events.jsonl`, `cpu-guard-events.jsonl`, `completed-unmerged-events.jsonl` — all `.claude/cache/`); the `~/.eps-autonomous/*.jsonl` family is session-lifecycle-scoped. Dedicated stream (not a `band=` row in disk-guard's) per the #1490/#1519/#1564 one-concern-one-stream pattern.
7. **Insertion point = the `keep-running-skip` branch of `_apply_pod_safety_action` (not a new top-level pass).**
   Why: the branch IS the blind spot; it already holds issue/pod_id/status/latest_progress/prev_state; a new pass would re-pay the RunPod snapshot (`_running_managed_issue_pods`), the status read, and the tag read every tick, and would need its own state store the pod-safety file already provides (incl. GC). Source: the #1519/#1490 additive-arm precedent (same file, same branch family). Alternative (standalone daemon-gated pass consuming `reaper_children` at L24906) rejected for the duplication above; the daemon dependency is handled by lazy `_daemon_reachable()` + fail-toward-no-fire instead.
