## 1. Goal + acceptance criteria

> Cut context-ceiling wedge recovery from ~65+ min (3-wake accumulation) to one watcher tick.

(Task #1453 body `## Goal` H2, verbatim; the task is `kind: infra` with no `goal:` frontmatter, re-read 2026-07-17.)

One failure shape is deterministic from a single observation: a turn ending with the synthetic API-error text `Prompt is too long` means the conversation exceeded the model's context ceiling. The conversation is append-only, so every later turn re-sends a superset of the same context and fails identically — the reference incident (#1335, transcript `ebff95d1-d9bd-40ca-8a0a-c30bbe935f61.jsonl`) shows 4 identical error turns 12:48:49Z→13:53:13Z with zero successful rows between them and no compaction rescue. Waiting for the generic ≥3-failed-turn accumulation only delays a certain outcome.

**Acceptance criteria:**

1. `decide_prompt_wedge_reason` returns `"context-ceiling"` on a transcript tail whose trailing rows (after the last successful assistant row) contain ≥1 api-error row matching the context-ceiling text — including on a shape-faithful replay of the #1335 incident tail — with every other trigger below its threshold.
2. A later successful assistant row anywhere after the error row prevents the trigger (the session recovered).
3. Generic api-error rows (refusal / 429 / 529 texts) at counts below the existing thresholds do NOT fire the new trigger.
4. `EPM_TICK_WEDGE_CONTEXT_CEILING=0` disables it; default is ON (threshold 1); malformed/negative env falls back to the default.
5. The new reason is bounded by the existing episode belt (`respawn_count < STALLED_MAX_RESPAWNS`) and the #1241 shared per-issue per-UTC-day cap (`wedge_respawns_today` vs `EPM_TICK_WEDGE_RESPAWNS_PER_DAY`), and its fence-stop bumps that shared counter.
6. Malformed rows (missing/non-dict `message`, non-list `content`, text-less blocks, non-str text) never fire.
7. Full existing wedge suites pass unmodified except where a test's own docstring scope requires a documented touch (none identified; see §4.9).

### 4.1 Constants + env helper (insert after `_tick_wedge_min_failed_total`, ~line 1616)

```python
# #1453: context-ceiling wedge — a turn ending with the synthetic API-error
# text 'Prompt is too long' means the conversation exceeded the model's
# context ceiling. Deterministic from ONE observation: the conversation is
# append-only, so every later turn re-sends a superset of the same context
# and fails identically (incident #1335 / transcript ebff95d1: 4 identical
# ceiling turns 12:48-13:53Z; ~65 min lost to the 3-event accumulation).
# Threshold 1 by design; 0 disables (the _tick_wedge_min_api_errors
# new-trigger-class kill-switch convention).
TICK_WEDGE_MIN_CONTEXT_CEILING = 1

# Tolerant match: case-insensitive SUBSTRING over an api-error row's text
# blocks. The reference row's text is the bare 'Prompt is too long'
# (message.model '<synthetic>'); other synthetic variants carry an
# 'API Error:' prefix, so substring tolerates prefix/suffix drift across
# Claude Code versions. Scoped to isApiErrorMessage rows only — model
# OUTPUT discussing this error can never match.
CONTEXT_CEILING_ERROR_SUBSTRING = "prompt is too long"


def _tick_wedge_min_context_ceiling() -> int:
    """Context-ceiling wedge trigger threshold (env
    ``EPM_TICK_WEDGE_CONTEXT_CEILING``, an integer COUNT; default
    :data:`TICK_WEDGE_MIN_CONTEXT_CEILING` = 1 — the trigger is ON by
    default). Mirrors :func:`_tick_wedge_min_api_errors` (a NEW trigger
    class): ``0`` DISABLES the trigger — the explicit kill switch.
    Malformed / negative env falls back to the default."""
    raw = os.environ.get("EPM_TICK_WEDGE_CONTEXT_CEILING")
    if not raw:
        return TICK_WEDGE_MIN_CONTEXT_CEILING
    try:
        parsed = int(raw)
    except ValueError:
        return TICK_WEDGE_MIN_CONTEXT_CEILING
    if parsed < 0:
        return TICK_WEDGE_MIN_CONTEXT_CEILING
    return parsed
```

### 4.2 Pure helpers (insert after `_wedge_trailing_row_runs`, ~line 2482)

```python
def _is_context_ceiling_text_row(row: dict) -> bool:
    """True iff an ALREADY-classified ``"api-error"`` row's synthetic error
    text names the context ceiling (#1453; #1335 row shape:
    ``message.content: [{"type": "text", "text": "Prompt is too long"}]``,
    ``message.model: "<synthetic>"``). Tolerant case-insensitive SUBSTRING
    match per text block (:data:`CONTEXT_CEILING_ERROR_SUBSTRING`).
    Malformed rows — non-dict ``message``, non-list ``content``, non-dict
    blocks, missing/non-str ``text`` — return False (fail toward NO-FIRE,
    the house convention)."""
    msg = row.get("message")
    content = msg.get("content") if isinstance(msg, dict) else None
    if not isinstance(content, list):
        return False
    for block in content:
        if not isinstance(block, dict) or block.get("type") != "text":
            continue
        text = block.get("text")
        if isinstance(text, str) and CONTEXT_CEILING_ERROR_SUBSTRING in text.lower():
            return True
    return False


def _wedge_trailing_context_ceiling(trailing_rows: list[dict]) -> int:
    """Count of context-ceiling api-error rows in the TRAILING run — rows
    with no SUCCESSFUL assistant row after them (#1453). Reset semantics
    mirror ``api_run`` in :func:`_wedge_trailing_row_runs`: a real
    ``"assistant"`` row resets (the session recovered — e.g. a compaction
    rescued it); dequeue/prompt rows, generic api-error rows and ``"other"``
    rows never reset. Nonzero means the conversation exceeded the context
    ceiling and no turn has succeeded since."""
    count = 0
    for row in trailing_rows:
        cls = _classify_wedge_row(row)
        if cls == "assistant":
            count = 0
        elif cls == "api-error" and _is_context_ceiling_text_row(row):
            count += 1
    return count
```

`_classify_wedge_row`, `_segment_wake_turns`, and `_wedge_trailing_row_runs` are untouched — the new text read lives in its own helper, preserving the "classifier reads only type + flag" contract.

## 11. Decision rationale

- **D1 — Match predicate: case-insensitive substring `"prompt is too long"`, scoped to `isApiErrorMessage: true` rows.** *Why:* the reference row's text is the bare `Prompt is too long` while other synthetic variants carry an `API Error:` prefix — substring tolerates prefix/suffix/casing drift; scoping to flagged rows removes the model-output false-positive surface entirely. *Source:* measured #1335 rows (A1); `_classify_wedge_row` contract (code lines 2176-2222). *Alternatives:* exact equality (brittle to drift — rejected); regex with error-code anchors (over-fit to one harness version — rejected); matching the top-level `error`/`errorDetails` fields (shape less verified than `message.content` — rejected).
- **D2 — Threshold 1.** *Why:* the failure is deterministic from one observation (A5): unlike 429/529/refusals — probabilistic, hence the existing 3-count thresholds — a ceiling'd conversation cannot succeed on retry, so accumulation buys no evidence and costs ~2 extra wake cycles (~65 min on #1335). The recovered-turn reset covers the only non-deterministic escape (a successful compacted turn). *Source:* #1335 measurements (A1); task #1453 filing. *Alternatives:* threshold 2 (halves the false-fire surface but re-adds one wake cycle ≈ 20–45 min — available at runtime via the knob without code change); keep 3 (status quo, defeats the Goal).
- **D3 — Join the #1241 shared day cap (`wedge_respawns_today`), not a new constant.** *Why:* (a) zero changes at the counting site — the note-substring router already sends any non-silence wedge note there (A3); (b) the #1241 rationale transfers verbatim (shared failure surface: one live wedged session, one respawn resolves whichever trigger fired) — a ceiling-wedged session would eventually trip api-error-run/failed-turn-run against the same budget anyway, so a separate budget would double the effective daily respawn allowance for the same session; (c) no new persisted state fields/GC surface. *Source:* code lines 11044-11098, 1716-1748; task #1241 lineage. *Alternatives:* own `EPM_TICK_WEDGE_CONTEXT_CEILING_RESPAWNS_PER_DAY` (adds state + code for no protection gain — rejected); the #1209 cap (wrong family — that budget exists for the cross-generation die-on-boot loop).
- **D4 — Armed on BOTH self-report paths (not staleness-gated).** *Why:* a ceiling'd turn dies at its first API call, so nothing refreshes the self-report, but the PREVIOUS successful turn may have refreshed it minutes before the wedge began — staleness-gating would add up to `STALLED_WINDOW_S` = 1 h of latency (A4), reproducing the latency the Goal removes. The reason the row-level lanes are stale-only — the single-refusal guard against same-turn retry rows — does not apply to a text-keyed predicate whose recovered-turn shape resets it. *Source:* code lines 11559-11583 (#1127 two-path gate rationale), A2/A4. *Alternatives:* stale-only like api-error-run (safe but defeats the Goal — rejected); bypass the lazy gate too (see D6).
- **D5 — Knob: `EPM_TICK_WEDGE_CONTEXT_CEILING`, integer count, 0 disables, default 1 (ON).** *Why:* mirrors the `_tick_wedge_min_api_errors` new-trigger-class kill-switch convention exactly (0 = off, malformed/negative → default, never a huge-N accidental disable), while keeping the brief's suggested env name; the count semantics give a free runtime fallback (D2). *Source:* code lines 1535-1553; task-brief constraint 4. *Alternatives:* boolean helper (loses the threshold fallback); family-consistent name `EPM_TICK_WEDGE_MIN_CONTEXT_CEILING` (equally valid — the brief's example name chosen to minimize divergence from the filed constraint; documented here so the deviation from the `MIN_` naming family is deliberate).
- **D6 — Fresh-path lazy gate untouched (ceiling rides behind the turn knobs on the fresh path).** *Why:* the #1209 precedent — the zero-probe hot path with both turn knobs at 0 is the pinned pre-#1127 rollback (`test_wedge_fresh_path_kill_switches_restore_lazy_gate`), and widening the gate would churn that pin for a corner that only exists under a deliberate operator rollback, where degrading new triggers to the stale path is the intended semantics. In the deployed default (turn knobs 3/6) the fresh path probes every tick, so one-pass detection holds. *Source:* code lines 11576-11578, 11619-11623; the pinned test (tests/test_autonomous_session_watch.py:15636). *Alternatives:* add `min_ceiling <= 0` to the gate condition (needs the pinned rollback test to zero a third knob; strictly more coverage under rollback configs but not needed for the Goal — rejected for churn).
- **D7 — Precedence FIRST among the six.** *Why:* the docstring contract says order never changes WHETHER the wedge fires, only WHICH label is reported; when a ceiling row co-fires with generic lanes, `[context-ceiling]` is the diagnostic a human (and the day-cap router) should see — it names the exact cause and the exact fix class. *Source:* code lines 2315-2320 (precedence contract). *Alternatives:* last (after failed-turn-silence — would report generic labels on ceiling incidents whenever counts co-fire, losing the forensic value); after api-error-run (same objection).
- **D8 — New helpers instead of widening `_classify_wedge_row`.** *Why:* the classifier's documented contract is "reads only `type` + the flag, never message text"; its classes feed `_segment_wake_turns` and `_wedge_trailing_row_runs`, so a new class would ripple through both. A side-car text predicate keeps the change additive and the blast radius one function. *Source:* code lines 2176-2222 (docstring contract). *Alternatives:* new `"context-ceiling-error"` row class (ripples; rejected).
- **D9 — Tests placed in `tests/test_stalled_detector_and_gc.py` + `tests/test_autonomous_session_watch.py`.** *Why:* that is where the prompt-wedge fixture family and the override-site harnesses actually live (A9); putting prompt-wedge tests in the #692 pod-wedge file would strand them away from their fixtures. *Source:* grep + file reads (§2). *Alternatives:* the brief's named file (grounded as the wrong suite — corrected).
