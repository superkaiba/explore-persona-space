#### D2 — Factor probe + revert into `scripts/step5a_sibling_probe.py` (NEW, stdlib-only, ~220 lines)

Replaces doc lines 365–410 (−2,312 B) with this block (+~1,675 B, exact text in the draft at `/tmp/2412-newbash.txt` modulo the exit-1 else-branch):

```bash
# Import-satisfiability probe on synced sibling TEST files (#2208, hardened
# #2412): probe + pair-atomic revert live in scripts/step5a_sibling_probe.py,
# resolved from the MAIN checkout (git-common-dir), never $WT — the worktree
# copy is fork-era by construction, the very staleness class being probed.
# The helper keeps the #2208 real-collection probe (180s/file fence, 900s
# venv warm-up, timeout = failure) and ADDS a static AST import scan that
# sees FUNCTION-BODY imports (the #2204 escape): a synced test whose src/
# import is unsatisfiable against THIS worktree (module missing, symbol
# absent, or an issue-namespaced src path differing from origin/main) FAILs,
# and the helper reverts EVERY synced file of that issue number (branch-era
# restore / main-NEW drop — pair-atomic, #1824/#1860). Fail-safe direction
# (#2208): an undecidable probe REVERTS, never keeps; a helper rc != 0 is
# FATAL below — nothing committed, residue left staged for inspection.
if [ "${#SIBLING_SYNCED[@]}" -gt 0 ]; then
  ROOT="$(dirname "$(git -C "$WT" rev-parse --path-format=absolute --git-common-dir)")"
  KEPT_OUT=$(mktemp)
  if (cd "$ROOT" && uv run python scripts/step5a_sibling_probe.py --worktree "$WT" --kept-out "$KEPT_OUT" -- "${SIBLING_SYNCED[@]}"); then
    mapfile -t SIBLING_SYNCED < "$KEPT_OUT"
    rm -f "$KEPT_OUT"
  else
    rm -f "$KEPT_OUT"
    echo "[step5a] FATAL: sibling probe helper failed (rc != 0) — synced sibling files left UNCOMMITTED for inspection (fail-safe #2208/#2412: nothing committed; a staged file reads as dirty next round). Revert by hand: git -C \"\$WT\" checkout HEAD -- <file> (branch-era) / git -C \"\$WT\" rm -f -q -- <main-NEW file>, then re-run Step 5a." >&2
    exit 1
  fi
fi
```

Embedded-shell exit-path trace: the `exit 1` reaches the end of the ONE Bash invocation running the fenced block (same contract as the #2303 family-commit FATAL at lines 302–306 — "fenced blocks are separate shells — fail-closed, never sourced"); the sync commit at 411–415 is below it and never runs, so nothing unprobed is ever committed. The happy path falls through to the unchanged commit + count echo. There is no bare `false` in any branch.

Why main-checkout resolution is REQUIRED, not defensive: Step 5a's fenced block runs with CWD inside the WORKTREE (`WT=$(git rev-parse --show-toplevel)`, line 125) — a relative `scripts/…` path would execute the branch's fork-era helper copy (or none), i.e. the exact staleness class this task fixes. `git -C "$WT" rev-parse --git-common-dir` of a linked worktree resolves to `<repo-root>/.git`; `dirname` gives the main checkout, which is always on `main`. (In the pin-test scratch fixture the worktree is a standalone clone, so ROOT == the clone and the harness plants a helper copy there — see D5.)

Helper CLI (defaults ARE the pinned production values):

```
uv run python scripts/step5a_sibling_probe.py --worktree WT [--kept-out PATH]

```

Helper algorithm (all git ops `git -C WT …`; all output echoes to stdout so the arm's stdout keeps the incident-diagnosis lines):

1. **Group** synced files by issue number `m` = first `issue_?(\d+)` match over the FULL relative path (fixes the current `basename`-based extraction, which returns EMPTY for `src/.../issue_1739/fits.py` and would corrupt the revert set — a latent bug D1 would otherwise trip). Slug-named experiment dirs are never SYNCED (D1's globs are issue-prefixed only), so they never enter revert sets — the extraction convention stays `issue_?(\d+)`-only.
2. **Static scan** (runs FIRST — cheap, no subprocess) per synced TEST file (`tests/test_issue*_*.py`): `ast.parse` the worktree bytes; `ast.walk` for every `Import`/`ImportFrom` (function-body imports included — the selector's own import-map arm set this precedent, `select_step9c_tests.py` docstring: "function-level imports count"); skip relative imports (`level > 0`). For each absolute dotted module, resolve candidate paths `src/<a/b/c>.py` and `src/<a/b/c>/__init__.py`:
   - Neither exists in WT nor at `origin/main:` ⇒ not a project-src import (third-party/stdlib) ⇒ skip (collection probe covers module-scope failures there).
   - Exists at origin/main but MISSING in WT ⇒ **FAIL m** (guaranteed runtime ImportError).
   - Path is **ISSUE-NAMESPACED** — any component matching `issue_?\d+` (anywhere under `src/`), **OR** the path lies under `src/explore_persona_space/experiments/` with a directory component matching `.*_\d+$` (the trailing-issue-number slug convention: `behavior_testbed_545`, `sycophancy_onpolicy_612`, …; the C2/#2412 classifier extension — measured census §12 row D: origin/main's 39 experiment dirs = 28 issue-prefixed + 11 trailing-slug + 0 other, so the arm fires on exactly the 11 target dirs and nothing else on today's tree) — AND `git diff --quiet origin/main -- <p>` reports a difference ⇒ **FAIL m**. Strict rationale, split by sub-case: for issue-PREFIXED dirs, D1's sync makes them identical, so a difference means the sync was skipped (deliberate branch edit or dirt) and consistency is unattainable; for trailing-SLUG dirs, the sync does NOT reach them, so a difference IS the #2204 pairing (main-era test + fork-era issue-src) with no closure available — refusing (revert) is #2208's declared fail-safe direction ("a probe that cannot decide must revert, never keep").
   - Shared src (no issue-namespaced component under either rule): for `from M import a, b` — `a` satisfiable iff bound at the module's top level (FunctionDef/ClassDef/Assign/AnnAssign targets, Import/ImportFrom aliases, recursing into top-level `If`/`Try` bodies), OR a top-level `from … import *` exists (lenient, documented), OR `src/<M-path>/<a>.py` / `<a>/__init__.py` exists (submodule import — the DOMINANT real shape: `from …issue_1739 import arms, fits`). Unsatisfiable ⇒ **FAIL m**. Content diffs alone do NOT fail shared src (old branches always differ; see §11).
   - `ast` SyntaxError on test or module ⇒ **FAIL m** (undecidable ⇒ revert).
3. **Collection probe** (RETAINED, verbatim semantics) for each synced test whose issue still passes: one `--warmup-cmd` run (cwd=WT, `--warmup-timeout`, best-effort) before the first probe; then per file `--collect-cmd + [file]` (cwd=WT, `--collect-timeout`); nonzero rc, timeout, or spawn error ⇒ **FAIL m**.
4. **Revert** every synced file of each FAILed m: `git cat-file -e HEAD:<f>` ⇒ `git checkout HEAD -- <f>`; else `git rm -f -q -- <f>` (verbatim #2208 semantics). Echo lines keep the pinned substrings: `"… — reverting its issue-<m> synced pair (#2208)."` and a `#2206` mention; the static-arm line additionally names the unsatisfiable module/symbol (distinct wording, so the repro can assert WHICH arm fired).
5. **Write kept list** (one path per line) to `--kept-out`; exit 0. Any unexpected exception ⇒ traceback to stderr, exit 1 (the bash FATAL handles it; probe-phase errors never reach here because step 2/3 convert them to FAILs before any mutation).
