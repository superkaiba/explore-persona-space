# Plan — task #842: smoke output-path hygiene (smoke runs must never clobber committed artifacts)

## 0.0 TL;DR (plain English)

- **What I'll do:** Add a rule to the smoke-run instructions that implementer and reviewer agents follow: when a quick test run writes files into the folders where real, committed experiment results live, it must either write somewhere else or put the real files back right after, and say so in its report. I'll also add a small automated check that keeps the rule text from being silently deleted later.
- **What I expect:** The three failure paths from #722 (a tiny test run shrinking committed result files, a reviewer's test rerun regenerating committed figures, and a final figure getting shipped at test scale) all become either impossible (output redirected) or caught at review (reviewer checks the folders are untouched and treats a shrunken committed artifact as a real defect).
- **What would change my mind:** If writing the rule turns out to require changing reviewer verdict machinery (new blocker tags, marker schema), I'd stop and descope to prose-only, because that machinery is a public contract this task must not touch.

### 3.1 `.claude/agents/experiment-implementer.md` — checklist item 3, new paragraph after the "Plan-declared runtime guards / monitors must show smoke evidence." block (before checklist item 4, ~line 379)

```markdown
   **Smoke outputs never overwrite committed artifacts.** When any smoke
   command — including a revision-round or follow-up-round smoke on an arm
   that already has committed production artifacts — writes under
   `eval_results/` or `figures/`, divert its output away from the
   canonical committed paths:

   - **Preferred — scratch-dir redirect.** Pass the script's output
     override (`--out-dir /tmp/issue-<N>-smoke/`, an env override, or the
     script's own `_smoke` path branch) so canonical paths are never
     touched.
   - **Fallback — restore-after-smoke.** If the script exposes no output
     override, immediately after the smoke restore every touched committed
     path (`git -C "$WT" checkout -- <paths>`), delete untracked smoke
     outputs left under `eval_results/` / `figures/`, and confirm
     `git status --porcelain -- eval_results/ figures/` is empty.

   Either way, the phase's `### <phase>` sub-section in `## Smoke run`
   STATES which mechanism was used and, for the fallback, pastes the empty
   `git status --porcelain -- eval_results/ figures/` output. A dirty
   worktree of smoke-truncated production JSONs/figures is a latent
   clobber: swept into a later explicit-path commit, it silently replaces
   production artifacts on the branch. Three instances on #722
   (2026-07-02): a `--layers 0 18` review smoke truncated committed
   28-layer JSONs+figures (−2966 lines, caught pre-commit only by luck); a
   reviewer's pytest rerun regenerated `figures/issue_722/mlp_*.png` at
   smoke scale at canonical paths; the round-2 hero figure shipped as a
   2-layer smoke version because the script's figure path was not
   `_smoke`-suffixed while its JSONs diverted to `_smoke/`. Two design
   corollaries for NEW/EDITED code: (a) a script that grows a smoke flag
   must divert ALL its outputs together — JSONs AND figures — to the smoke
   path (a partial divert is exactly the third instance); (b) tests never
   write to canonical `eval_results/` / `figures/` paths — use pytest's
   `tmp_path` (any reviewer's pytest rerun regenerates whatever the test
   writes, at whatever scale the test uses).
```

### 3.6 `scripts/workflow_lint.py` — new presence gate `check_smoke_output_hygiene` (+ argparse flag `--check-smoke-output-hygiene`, bundled into the no-flags default run, same policy as `check_smoke_architecture_review_lens`)

```python
def check_smoke_output_hygiene(*, repo_root: Path | None = None) -> list[str]:
    """FAIL if the smoke output-path hygiene rule (#842) is absent from any
    of its three surfaces. Anchor phrase: 'Smoke outputs never overwrite
    committed artifacts'. Incidents: #722 (2026-07-02, 3 instances) — smoke
    runs at canonical eval_results//figures/ paths clobbered committed
    production artifacts. Bundled into the no-flags default run.
    ``repo_root`` is a unit-test override hook."""
    root = repo_root if repo_root is not None else _REPO_ROOT
    anchor = "Smoke outputs never overwrite committed artifacts"
    surfaces = (
        root / ".claude" / "agents" / "experiment-implementer.md",
        root / ".claude" / "agents" / "code-reviewer.md",
        root / ".claude" / "skills" / "issue" / "SKILL.md",
    )
    errors: list[str] = []
    for path in surfaces:
        if not path.is_file():
            errors.append(f"{path}: missing — the #842 smoke output-path "
                          f"hygiene rule must live here.")
        elif anchor not in path.read_text(encoding="utf-8"):
            errors.append(f"{path}: missing the anchor phrase {anchor!r} "
                          f"(#842) — the smoke output-path hygiene rule was "
                          f"dropped; smoke runs will silently clobber "
                          f"committed artifacts again (incident #722).")
    return errors
```

Simple substring presence per file (not region-anchored): the phrase is distinctive enough that a substring match has zero false positives, and region-anchoring would break on legitimate section moves (the #829 relocation churn) without adding safety.
