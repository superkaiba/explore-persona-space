`kind: infra` · 0 GPU-hours · workflow-surface fix · shared review-pipeline surface.

## 1. Requirement + acceptance criteria

Make `scripts/persist_verdict_concerns.py` fail loud when a verdict marker
carries line-start `CONCERN::` rows that ingest to zero concerns, so a
reviewer's concerns can never silently miss the ledger.

## 4. Design

### 4a. Row grammars and the discriminator

Two shapes exist in the wild (both present in #2387's `events.jsonl`):

```
CONCERN:: BLOCKER context-blind-close-paren-overstrip Inner case/pattern close parens ...
CONCERN::backtick-comment-overstrip | BLOCKER | Backtick cmdsub interior ...
```

They differ in three ways at once: space-vs-no-space after `::`, whitespace-
vs-pipe delimiters, and **reversed field order** (canonical = severity first;
variant = id first). A naive "does the payload contain a pipe" discriminator
is unsafe — a canonical *summary* may legitimately contain ` | `.

The discriminator is the **closed severity set**
(`task_workflow.CONCERN_SEVERITIES` = BLOCKER / CONCERN / NIT), which cannot
collide with a kebab-case id:

```
CANONICAL  iff  the row matched `^CONCERN:: ` (space required)
                AND split(None, 2)[0] in CONCERN_SEVERITIES
VARIANT    iff  the row matched `^CONCERN::` with a non-space next char
                AND the payload splits on '|' into exactly 3 fields
                AND field[1].strip() in CONCERN_SEVERITIES
otherwise  ->  MALFORMED (content-free reason code), never silently dropped
```

Both branches normalize to the same `(severity, id, summary)` triple, so
everything downstream (validation, dedup, `_truncate_summary`, the
`raise_concern` loop, the `none` sentinel, `_MAX_ROWS`) is untouched.

### 4b. Fail-loud detection

A new scan counts **line-start** `CONCERN::` occurrences, independent of the
two row regexes:

```python
_ANY_ROW_RE = re.compile(r"^CONCERN::", re.MULTILINE)
```

Line-start anchoring is deliberate and matches the existing parser's
discipline (`codex-code-reviewer.md:630-633` already warns that a stray
line-start occurrence persists as a real concern). A `CONCERN::` token
appearing mid-sentence in prose — including in this very task's body — does
not trip it.

In `main()`, after `_validate_rows`, in the `not parsed` branch:

```python
if not parsed:
    if raw_rows:                       # the sole `CONCERN:: none` — unchanged
        ...
        return 0
    if _ANY_ROW_RE.search(text):       # NEW: rows present, none ingested
        print(
            f"MALFORMED: concern-rows-unparsed ({len(_ANY_ROW_RE.findall(text))} "
            f"line-start CONCERN:: row(s) in {args.file}); expected "
            f"'CONCERN:: <BLOCKER|CONCERN|NIT> <kebab-id> <summary>' or "
            f"'CONCERN::<kebab-id> | <BLOCKER|CONCERN|NIT> | <summary>'"
        )
        return 1
    if args.require_block:             # unchanged
        ...
```

The conjunction (line-start rows present AND zero ingested) is unambiguous:
there is no legitimate reading in which a marker carries such rows and
correctly forwards nothing. The message names the marker path and both
expected formats, satisfying **A1**.

Output discipline is preserved: counts, the file path, and a fixed
content-free reason code — no summary text ever prints.

### 4c. Exit code: reuse 1, do not mint a new one

Exit **1** (`MALFORMED`), with the new reason code `concern-rows-unparsed`
added to the docstring's reason-code list.

Rationale: all three call sites already dispose exit 1 as "MALFORMED output
→ the site's stricter-retry re-dispatch (cap 2); the verdict marker is NOT
posted on this attempt" — which is exactly correct here (the reviewer
emitted rows the parser cannot ingest, so re-dispatching for a well-formed
verdict is the right recovery). A new exit code would require editing three
call-site disposition tables plus the resume-recovery block, for no
behavioral gain. Lower blast radius, and **A1** only requires non-zero.

### 4d. Scope documentation (the misapplication half)

The mechanical fail-loud makes a misapplication *visible*; prose makes it
*avoidable*. Two additions:

- Module docstring + `argparse` description: state that this forwarder is
  for **Codex twin verdict markers only** — the Claude reviewers are not
  sandboxed and persist concerns directly via `task.py add-concern`.
- `.claude/skills/issue/steps/09-step-5.md`: one sentence in the
  concerns-persistence block stating the same scope.

No edit to `.claude/agents/codex-*.md`: their templates keep emitting the
canonical form only (teaching reviewers a second shape would be a
regression), and leaving them untouched avoids the `c34_ratchet_headroom`
same-file cap pressure on `.claude/agents/*.md`. The parser widens; the
emitted contract does not.

## 7. Risks / failure modes

- **R1 — false-positive fail-loud breaks live review rounds fleet-wide
  (highest severity).** This tool runs at every marker-mode Codex review
  site; a spurious non-zero exit triggers a stricter-retry re-dispatch on
  healthy rounds, which is worse than the bug being fixed. Mitigations: the
  scan is line-start anchored (prose mentions cannot trip it); the failure
  fires only on the zero-ingested conjunction; the widened parser makes the
  known variant shape *succeed* rather than fail, so the new exit is
  reachable only by a genuinely unknown shape. The mid-sentence test pins
  the guard.
- **R2 — discriminator mis-parse.** A canonical row whose summary contains
  pipes could be read as variant. Closed off by requiring exactly 3
  pipe-fields AND `field[1] in CONCERN_SEVERITIES`, and pinned by
  `test_canonical_summary_containing_pipe_stays_canonical`.
- **R3 — `--require-block` behavior shift.** A marker carrying ONLY variant
  rows previously produced `raw_rows == []` and, under `--require-block`,
  rc=3 `missing-concerns-block`. It will now parse and persist. This is the
  intended correction (the block was present, in a different shape), not a
  semantics break: `--require-block`'s contract is "a missing concerns
  block, or a heading with zero machine rows, exits 3", and a variant-row
  block is neither. Called out here so a reviewer does not read it as an
  A4 violation.
- **R4 — ratchet / size-cap pressure** on `.claude/agents/*.md`. Avoided by
  not editing those files (§4d).
- **R5 — partial-ledger semantics unchanged.** Exit 4 and the per-row
  persistence loop are untouched; this plan adds no transaction.

## 11. Decision rationale

- **Accept both formats rather than pinning one** (the body's stated
  preference). The reviewers are independent by design, so a parser
  tolerating both cannot be desynced by an edit to one spec. The reversed
  field order is disambiguated by the closed severity set (§4a), so
  acceptance costs no ambiguity.
- **Reuse exit 1 rather than minting a new code** (§4c) — the existing
  call-site disposition for exit 1 is already the correct recovery, so the
  fix needs no call-site disposition edits.
- **Line-start anchoring for the fail-loud scan** — the alternative
  (`CONCERN::` anywhere) trips on prose, including this task's own body,
  and R1 makes false positives the dominant risk.
- **Do not teach the Claude `code-reviewer` a `CONCERN::` grammar** — it
  writes the ledger directly and needs no marker channel. The fix for the
  #2387 r6 misapplication is scope documentation plus the mechanical
  fail-loud, not a second emitter.
- **No literature `Source:` rows.** This is internal tooling with no
  hyperparameters; the grounding is the in-repo evidence cited in §2.
  Stated explicitly rather than left blank.
