### 3.1 Constants + env (near L128–133, matching existing conventions)

```python
# Venv-reap arm (#912): a KEPT worktree's .venv is a pure build artifact,
# regenerable by `uv run`/`uv sync` from the shared uv cache (pyproject.toml
# + uv.lock are checked in at every worktree root). Reap it when the
# worktree has been idle past this window and NOTHING is running in it.
DEFAULT_VENV_IDLE_DAYS = 7.0     # env: EPM_WORKTREE_VENV_IDLE_DAYS
PRESSURE_VENV_IDLE_DAYS = 2.0    # tightened under the SAME disk-pressure
                                 # predicate as PRESSURE_GRACE_HOURS
_VENV_DIRNAME = ".venv"
_VENV_REAP_TMP_PREFIX = ".venv.reap-tmp-"

def _venv_idle_days() -> float:
    """Venv idle window in days, env-overridable (mirrors _pressure_threshold_pct)."""
    return float(os.environ.get("EPM_WORKTREE_VENV_IDLE_DAYS", str(DEFAULT_VENV_IDLE_DAYS)))

def _venv_reap_enabled() -> bool:
    """Kill switch for the venv arm (default ON; EPM_WORKTREE_VENV_REAP=0 disables)."""
    return os.environ.get("EPM_WORKTREE_VENV_REAP", "1") != "0"
```

Exact env var names: `EPM_WORKTREE_VENV_IDLE_DAYS` (float days, default `7`), `EPM_WORKTREE_VENV_REAP` (default `1`; `0` disables the whole arm). Naming follows the file's existing `EPM_WORKTREE_*` prefix (`EPM_WORKTREE_DISK_PRESSURE_PCT`, L260).

### 3.2 Pure decision functions (unit-testable, no filesystem)

```python
def effective_venv_idle_days(idle_days: float, disk_pct: float, threshold_pct: float) -> float:
    """Pure pressure rule mirroring effective_grace_hours (L248): at/above the
    threshold the venv idle window tightens to PRESSURE_VENV_IDLE_DAYS; an
    explicitly tighter idle_days is never loosened."""
    if disk_pct >= threshold_pct:
        return min(idle_days, PRESSURE_VENV_IDLE_DAYS)
    return idle_days


def should_reap_venv(
    name: str,
    *,
    worktree_kept: bool,       # the worktree itself survived should_remove
    has_venv: bool,            # (wt/.venv).is_dir() and not is_symlink()
    venv_is_symlink: bool,     # (wt/.venv).is_symlink()
    is_live: bool,             # name in the cwd/argv holder snapshot
    exe_in_venv: bool,         # name in the /proc/<pid>/exe venv snapshot
    newest_activity_ts: float | None,  # None = could not be established
    now: float,
    idle_days_required: float,
) -> Decision:
    """Pure venv-reap decision (unit-tested). Decision.remove=True means
    'reap this worktree's .venv' — the worktree itself is NEVER removed by
    this arm. Gate order is strictly fail-toward-keep."""
    if not worktree_kept:
        return Decision(name, False, "venv: worktree itself is being removed")
    if not has_venv and not venv_is_symlink:
        return Decision(name, False, "venv: none present")
    if name.startswith("_"):
        # _task-main-pin (task_workflow._MANAGED_MAIN_WORKTREE_NAME) and any
        # future managed worktree — the leading underscore is its contract
        # (task_workflow.py:341-351 comment). Anti-drift test pins this.
        return Decision(name, False, "venv: managed worktree (never touched)")
    if venv_is_symlink:
        return Decision(name, False, "venv: .venv is a symlink (never followed)")
    if is_live:
        return Decision(name, False, f"venv: {_LIVE_PROCESS_REASON}")
    if exe_in_venv:
        return Decision(name, False, "venv: a running process executes from this .venv")
    if newest_activity_ts is None:
        return Decision(name, False, "venv: idleness could not be established")
    idle_days = (now - newest_activity_ts) / 86400.0
    if idle_days < idle_days_required:
        return Decision(
            name, False,
            f"venv: active {idle_days:.1f}d ago (< {idle_days_required:g}d idle)",
        )
    return Decision(
        name, True,
        f"venv: idle {idle_days:.1f}d (>= {idle_days_required:g}d), reapable",
    )
```

Note the deliberate keep-reason INDEPENDENCE: the pure function does not take the worktree's keep reason or issue status. Eligibility-by-keep-reason is structural (hook placement, §3.5) — every plain-keep class (human-named, status-not-reapable, tracked-changes) is eligible, the live-process class is blocked by `is_live`/`exe_in_venv`, and the grace-window class is auto-excluded because a fresh root mtime makes `newest_activity_ts` fresh. Rationale in §11 D4.

### 3.3 Idleness signal (impure helper)

```python
def _venv_newest_activity_ts(child: Path) -> float | None:
    """Newest activity timestamp for the venv-reap idle test: max of
    (a) worktree root dir mtime (the existing age signal, _classify L619),
    (b) .venv dir mtime (venv creation / uv sync churn),
    (c) the worktree's git-admin dir activity — mtime of HEAD and index under
        the gitdir the worktree's `.git` FILE points at ('gitdir: <abs path>'),
        which captures commits / checkouts / status-refreshes that touch no
        top-level entry (root dir mtime only moves on direct-child churn).
    Returns None when any signal cannot be read or parsed — the pure gate
    then fails toward keep."""
```

Implementation notes: parse `child/".git"` (a one-line file in linked worktrees, verified live: `gitdir: /home/.../.git/worktrees/issue-903`); stat `HEAD` and `index` if present (missing individual files are skipped, not an error; an unreadable/unparseable `.git` file → `None`); `.venv` mtime via `lstat` (do not follow a symlink). Everything wrapped so any `OSError` → `None`.

### 3.4 Exe-in-venv probe (impure, one /proc pass per snapshot)

`_live_worktree_holders` (L426) harvests cwd + argv only. A process **exec'd from the venv interpreter** whose cwd and argv both reference neither path (e.g. a daemonized `python` with cwd `/`, argv `python -m x`) is invisible to it but would crash if its `sys.path`/stdlib under `.venv` vanished. Close that hole with a dedicated snapshot:

```python
def _venv_exe_holders() -> set[str]:
    """Worktree names whose .venv* contains a RUNNING executable:
    /proc/<pid>/exe resolves under .claude/worktrees/<name>/.venv... .
    Complements _live_worktree_holders (cwd/argv). Unreadable /proc entries
    (vanished pid, other-uid EPERM) are skipped — same posture as the
    existing harvest (L453-455). Regex matches any `.venv`-prefixed
    component so `.venv.reap-tmp-*` leftovers are also protected."""
    found: set[str] = set()
    marker = ".claude/worktrees/"
    pat = re.compile(r"([A-Za-z0-9_.\-]+)/\.venv")
    for pid in os.listdir("/proc"):
        if not pid.isdigit():
            continue
        with contextlib.suppress(OSError):
            exe = os.readlink(f"/proc/{pid}/exe")
            idx = exe.find(marker)
            if idx != -1:
                m = pat.match(exe[idx + len(marker):])
                if m:
                    found.add(m.group(1))
    return found
```

(The `[A-Za-z0-9_.\-]+` char class is the harvest's own — L443 — so `_task-main-pin` and suffixed names match.)

### 3.6 The arm orchestrator + apply-side delete

```python
def _venv_arm(child, decision, live, venv_exe, res, apply,
              idle_days_required, wt_root_rel, now) -> None:
    """Venv-reap arm for one KEPT worktree. Dry-run: classify + record only.
    Apply: fresh re-verify (liveness + exe + idleness re-derived against
    fresh state, mirroring the pre-removal fresh _classify at L829-838),
    then rename-aside + rmtree. Never touches the worktree itself."""
    name = child.name
    venv = child / _VENV_DIRNAME
    d = should_reap_venv(
        name,
        worktree_kept=True,
        has_venv=venv.is_dir() and not venv.is_symlink(),
        venv_is_symlink=venv.is_symlink(),
        is_live=name in live,
        exe_in_venv=name in venv_exe,
        newest_activity_ts=_venv_newest_activity_ts(child),
        now=now,
        idle_days_required=idle_days_required,
    )
    if not d.remove:
        if d.reason != "venv: none present":   # silence the no-venv majority
            res.venv_skipped.append(d)
        return
    res.venv_bytes[name] = _worktree_size_bytes(str(venv))   # measure BEFORE
    if not apply:
        res.venv_candidates.append(name)
        return
    # APPLY: fresh re-verify immediately before the destructive call.
    fresh = should_reap_venv(
        name,
        worktree_kept=True,
        has_venv=venv.is_dir() and not venv.is_symlink(),
        venv_is_symlink=venv.is_symlink(),
        is_live=name in _live_worktree_holders(wt_root_rel),
        exe_in_venv=name in _venv_exe_holders(),
        newest_activity_ts=_venv_newest_activity_ts(child),
        now=now,
        idle_days_required=idle_days_required,
    )
    if not fresh.remove:
        res.venv_skipped.append(
            Decision(name, False, f"venv: became unsafe mid-audit: {fresh.reason}")
        )
        return
    err = _reap_venv(child)
    if err is None:
        res.venv_reaped.append(name)
    else:
        res.venv_failed.append(name)
        res.venv_skipped.append(Decision(name, False, f"venv: reap FAILED ({err})"))


def _reap_venv(child: Path) -> str | None:
    """Rename .venv aside, then rmtree the renamed dir; restore the worktree
    root dir's (atime, mtime) afterwards. Returns None on success, else an
    error string. Rename-first means a partial delete can never leave a
    half-broken dir NAMED `.venv` — after the rename the worktree simply has
    no venv, and the next `uv run` recreates it from the shared cache; a
    failed rmtree leaves an inert `.venv.reap-tmp-<pid>` dir the next apply
    sweep re-attempts. The mtime restore keeps this arm from resetting the
    MAIN removal arm's root-mtime idleness signal (deleting a direct child
    bumps the parent dir mtime)."""
    venv = child / _VENV_DIRNAME
    tmp = child / f"{_VENV_REAP_TMP_PREFIX}{os.getpid()}"
    try:
        st = child.stat()
        os.rename(venv, tmp)
    except OSError as exc:
        return f"rename failed: {exc}"
    try:
        shutil.rmtree(tmp)
    except OSError as exc:
        with contextlib.suppress(OSError):
            os.utime(child, (st.st_atime, st.st_mtime))
        return f"rmtree failed (leftover at {tmp.name}): {exc}"
    with contextlib.suppress(OSError):
        os.utime(child, (st.st_atime, st.st_mtime))
    return None
```

**Leftover sweep:** at the top of `_venv_arm`, under `apply` only and only when `name not in live` and `name not in venv_exe`, `rmtree` any pre-existing `child/.venv.reap-tmp-*` dirs (they were condemned by a prior apply run; log each as `venv leftover reaped`, count into `venv_reaped` byte totals as `None`-sized). Never in dry-run.

`shutil.rmtree` symlink semantics (stdlib guarantee): symlinks inside the tree are removed as links, never followed; `rmtree` on a path that IS a symlink raises — but the pure gate already skips symlink `.venv`s before the call.

## 4. Controls / safety analysis

| Failure mode | Guard |
|---|---|
| Venv reaped under a live process rooted in the worktree | Double liveness gate: snapshot `is_live` (cwd/argv harvest, L426) at classification + a FRESH `_live_worktree_holders` re-probe immediately before the rename (mirrors the pre-removal fresh check, L829–838). Any holder — even an orphan-pattern codex pid — blocks (stricter than the removal arm, which kills orphans; the venv arm never kills anything). |
| Live interpreter exec'd FROM the venv but invisible to cwd/argv harvest | New `_venv_exe_holders()` /proc `exe` probe, snapshot + fresh re-probe. Residual: other-uid processes' `/proc/<pid>/exe` is EPERM-unreadable (skipped) — single-user VM, documented in §12 A8. |
| Reap racing the worktree's own `uv run` recreating `.venv` | The uv process would hold cwd (or argv) in the worktree → fresh liveness gate blocks. Residual sub-second window: rename-first means uv either sees the old inode via already-open fds (its in-flight sync errors loudly on next path lookup, then the following `uv run` recreates cleanly) — fail-loud, never a silently corrupt dir named `.venv`. |
| `_task-main-pin` touched | `name.startswith("_")` hard gate in the pure function, tested; anti-drift test asserts `task_workflow._MANAGED_MAIN_WORKTREE_NAME == "_task-main-pin"` and `.startswith("_")` (the underscore contract is documented at `task_workflow.py:341–351`), so a future rename of the managed pin breaks the test rather than the guard. |
| Symlink traps in rmtree | `.venv` that IS a symlink → pure-gate skip (never followed, never deleted). Symlinks INSIDE the venv (e.g. `bin/python` → base interpreter) are removed as links by `shutil.rmtree`'s stdlib contract, targets untouched. Tested with an inside-symlink fixture pointing outside `tmp_path`'s venv. |
| Partial rmtree leaving a corrupt `.venv` | Rename-to-`.venv.reap-tmp-<pid>` FIRST, then rmtree the renamed dir. A crash mid-delete leaves an inert tmp dir (re-attempted next apply sweep), never a half-broken `.venv`; the next `uv run` sees no venv and regenerates. |
| Idleness cannot be established (unreadable `.git` file / stat errors) | `_venv_newest_activity_ts` returns `None` → pure gate keeps ("idleness could not be established"). |
| Venv reap resets the MAIN arm's idleness signal (parent dir mtime bump) | `_reap_venv` restores the worktree root's `(atime, mtime)` after the delete (best-effort). |
| Arm misfires on a worktree being removed this pass | Hook placement: plain-KEEP branch only; removal/remediation paths never call the arm. |
| Deleting actual work product | Impossible by construction: the arm deletes only `child/.venv` (and its own `.venv.reap-tmp-*` leftovers) — gitignored build output, regenerable from checked-in `pyproject.toml` + `uv.lock` (verified: both at worktree roots; venvs carry uv's `CACHEDIR.TAG`). `store/`, `eval_results/`, tracked dirt are untouched — the arm never runs `git` mutations and never widens beyond the two exact names. |
| Kill switch / rollback | `EPM_WORKTREE_VENV_REAP=0` disables the arm entirely (report shows `enabled: false`); dry-run default preserved (`--apply` is the only destructive mode, per the existing contract L77–83). |
| Concurrent sweeps | Existing single-instance flock (L854–875) already serializes the cron, the watcher's `--apply` invocation, and manual runs — the arm inherits it. |
| `uv run` in ANOTHER worktree during a reap | No interaction: venvs are per-worktree; hardlink unlink only decrements the shared inode's link count — the uv cache's own link (and every other worktree's) is unaffected. |

## 11. Decision Rationale

**N/A — no training hyperparameters** (verify_plan check 1). **N/A — no behavioral construct** (check 2). **N/A — not a replication** (check 7). **N/A — no artifact reuse** (check 6). The load-bearing decisions here are code-policy choices, grounded in this repo's own precedents:

- **D1 — Reap on every sweep (unconditional), not pressure-gated; pressure TIGHTENS the window (7d → 2d).**
  *What:* the arm runs on every `--apply` sweep with a 7-day idle window; under the existing disk-pressure predicate the window tightens to 2 days via `effective_venv_idle_days`.
  *Why:* a 7d-idle venv is dead weight regardless of disk state, and pressure-gating would start reclaiming only when the disk is already near-wedged (it is at 95% NOW, i.e. pressure mode is currently always-on — the effective window today is 2d, relaxing to 7d after the #681 cutover drains the boot disk). Churn is structurally bounded: after a recreation, re-reap requires another full idle window, so daily thrash is impossible; recreation is ~1–3 min from the warm hardlink cache.
  *Source:* the file's own pressure design — pressure changes ONLY the grace window, never the guard set (`worktree_audit.py:31–38`, `effective_grace_hours` L248–254) — and the daily cron reaps whole worktrees unconditionally (`cron_worktree_audit.sh:54`); the venv arm is strictly less destructive than what already runs unconditionally.
  *Alternatives:* pressure-only firing (rejected: cliff behavior + chronic-pressure reality makes it equivalent to unconditional today while silently doing nothing after the cutover); no pressure tightening (rejected: the 2d rung reuses an existing, tested pattern at near-zero complexity and is the behavior actually wanted on a 95% disk).

- **D2 — Idle window defaults: 7d normal / 2d pressure, env-overridable.**
  *What:* `DEFAULT_VENV_IDLE_DAYS=7.0` (`EPM_WORKTREE_VENV_IDLE_DAYS`), `PRESSURE_VENV_IDLE_DAYS=2.0` (constant, like `PRESSURE_GRACE_HOURS`).
  *Why:* 7d is the candidate sketch's default and matches the project's standing "one work cycle" fences (pod TTL default 7d, GCP `--max-run-duration` default 7d); it is 28× the sweep's own 6h reap grace. 2d is 4× the watcher's 12h "definitively abandoned" session-idle windows (`EPM_UNMAPPED_IDLE_REAP_S`, `EPM_STALE_REGISTRATION_IDLE_H` — background-automation.md) and survives a weekend gap.
  *Source:* task body diff sketch (`VENV_REAP_IDLE_DAYS = 7 # env-overridable`); `worktree_audit.py:128–133` (const + env pattern); background-automation.md idle windows.
  *Alternatives:* 3d default (rejected: no precedent rung; the 2d pressure rung already covers the aggressive case); hours-granularity (rejected: days match the phenomenon — venvs are stale for weeks).

- **D3 — Idle signal = max(worktree root mtime, `.venv` mtime, git-admin `HEAD`/`index` mtime); `None` ⇒ keep.**
  *What:* §3.3.
  *Why:* root dir mtime alone (the existing `_classify` signal, L619) only moves on direct-child churn — an implementer editing nested files + committing would look root-idle; the git index/HEAD mtimes capture exactly that activity for ~zero cost (2 stats + 1 tiny file read). The `.venv` mtime catches a just-recreated venv. Signals that cannot be read fail toward keep.
  *Source:* `worktree_audit.py:619` (the existing signal being extended); the gitdir pointer format verified live (`cat .claude/worktrees/issue-903/.git`); the watcher's worktree-activity hold uses file-mtime evidence the same way (background-automation.md § (b) bounded worktree-activity hold).
  *Alternatives:* deep newest-mtime `os.walk` scan (rejected: 35 worktrees × ~10⁵ files daily for marginal signal over git-index; the live-holder guard covers active-use at sweep time); venv atime (rejected: relatime makes atime unreliable, and `uv run` doesn't reliably touch `.venv` on use anyway — usage protection is the liveness gates' job, not the idle signal's).

- **D4 — Keep-reason eligibility: ALL plain-keep classes are venv-eligible; live-process is never; grace-keeps are auto-excluded.**
  *What:* eligibility is not conditioned on issue status or keep reason; the blocks are the liveness gates + idle window.
  *Why:* the task's stated gap is precisely that "dirty, active issue, or human-named" keeps retain venvs indefinitely (`tasks/planning/912/body.md` § Workflow gap) — carving any of the three out fails the Goal. A `blocked`/parked issue idle ≥7d pays a 1–3 min re-sync on resume; `.venv` is gitignored so it is never part of tracked dirt (the dirty-keep's protected content is untouched).
  *Source:* task body L24 (the three keep classes named as the bug); `_has_tracked_changes` ignores untracked/ignored paths (`worktree_audit.py:543–550`) — the venv provably isn't the dirt being protected.
  *Alternatives:* terminal-status-only (rejected: terminal-status idle worktrees mostly get REMOVED whole by the existing arm — the venv backlog lives exactly in the non-terminal/dirty/human-named keeps); active-issue exclusion (rejected: `blocked` tasks park for weeks — that IS the backlog).

- **D5 — Plain-KEEP branch only; never inside orphan-kill / rescue / removal paths.**
  *What:* §3.5 hook placement.
  *Why:* remediation paths end in whole-worktree removal under apply (venv included — double handling would race our own rmtree); orphan-pinned keeps have holders (liveness gate would block anyway, and the venv arm must never be a reason to signal a process); "became unsafe mid-audit" means state changed under us — fail toward keep this pass.
  *Source:* `worktree_audit.py:785–825` (the branch structure); `_execute_remediation`'s own fresh-state contract (L672–683).
  *Alternatives:* also reaping venvs of dry-run remediation-classified rows (rejected: those are would-remove-whole rows; a venv row is noise).

- **D6 — Scope includes human-named worktrees; excludes any underscore-prefixed name.**
  *What:* the venv arm evaluates every dir in `.claude/worktrees/` that the sweep KEEPS — including out-of-`_TARGET_NAME_RE` human-named trees — but `name.startswith("_")` is a hard exclusion.
  *Why:* the bug report names `compute-router` (human-named, ~10 GB) as one of the two largest offenders, and the task Goal's ONLY named exclusion is `_task-main-pin`; a venv delete is recoverable in a way a worktree delete is not, so the "human-named = manual cleanup only" rule for REMOVAL (L10–18) does not transfer. The underscore prefix is the managed-worktree contract (`task_workflow.py:341–351`: "The leading underscore keeps it out of the audit's `_TARGET_NAME_RE` even if that regex were widened"), so excluding the prefix — with an anti-drift test importing `_MANAGED_MAIN_WORKTREE_NAME` — covers `_task-main-pin` and any future managed pin without a private import in production code.
  *Source:* task body L23 (compute-router named); `task_workflow.py:351`; test precedent `test_target_issue_branch_stays_in_sync_with_issue_name_re` (tests L147) for the anti-drift pattern.
  *Alternatives:* `_TARGET_NAME_RE`-only scope (rejected: forfeits ~10 GB of the ~25 GB motivation and contradicts the task body); importing the private name into the script (rejected in favor of the prefix rule + test: same safety, no private cross-module import in production).

- **D7 — Rename-aside-then-rmtree; restore worktree-root mtime; leftovers re-attempted next apply.**
  *What:* §3.6 `_reap_venv`.
  *Why:* a partial rmtree must never leave a half-broken dir named `.venv` (uv would try to USE a corrupt venv; with no `.venv` it cleanly recreates). The mtime restore keeps the arm from resetting the main removal arm's root-mtime idleness clock (child unlink bumps parent mtime).
  *Source:* fail-toward-recoverable posture throughout the file (rescue-strictly-precedes-removal, L553–561; never-rm-rf-worktrees, L77–83).
  *Alternatives:* direct `shutil.rmtree(.venv)` (rejected: partial-failure leaves a corrupt `.venv`); `uv`-native cleanup (`uv venv --clear`?) (rejected: still leaves a venv; the goal is zero bytes).

- **D8 — Report apparent (du) bytes with the hardlink caveat; no exclusive-size computation.**
  *What:* reuse `_worktree_size_bytes` on the venv path; label output "apparent".
  *Why:* exclusive-bytes (nlink==1 walk) costs a full lstat walk per venv for a number that changes as other worktrees reap; the file already ships the identical caveat for worktree sizes.
  *Source:* `worktree_audit.py:270–276` (the existing caveat + helper); live probe (nlink=32 on a sample venv file, uv cache on the same `/dev/root` fs).
  *Alternatives:* `df` free-delta per reap (rejected: racy on a busy shared fs); no sizing (rejected: the task requires per-venv reclaimed-bytes logging).

- **D9 — Kill switch default-ON (`EPM_WORKTREE_VENV_REAP`, `0` disables); destructive only under the existing `--apply`.**
  *What:* §3.1.
  *Why:* the arm exists to fire (disk at 95%); dry-run remains the default mode for any invocation, so "default ON" only means "on when the cron's `--apply` runs", matching how every other apply-mode behavior in this file shipped.
  *Source:* the watcher's reaper conventions (`EPM_UNMAPPED_IDLE_REAP=0`, `EPM_ZOMBIE_WRAPPER_REAP=0` revert-to-alert-only, background-automation.md); `cron_worktree_audit.sh:54` (the cron passes `--apply`).
  *Alternatives:* default-OFF opt-in (rejected: the cron would silently never reclaim; contradicts the task's motivation and the 2026-06-11 "run, don't park" posture).

- **D10 — Add the `/proc/<pid>/exe` probe as a venv-arm-specific gate, NOT a change to `_live_worktree_holders`.**
  *What:* §3.4.
  *Why:* extending the global harvest would newly pin worktrees for the REMOVAL decision too — a behavior change to the tested main arm outside this task's scope; the venv arm needs it because deleting a running interpreter's `sys.path` is the one venv-specific hazard cwd/argv can miss.
  *Source:* `worktree_audit.py:426–462` (harvest reads cwd+cmdline only); single-variable-change discipline (change only what the Goal needs).
  *Alternatives:* extend the global harvest (rejected: scope creep into the removal decision); skip the probe (rejected: it is cheap and closes the highest-severity failure mode in §4).
