## 4. Design

**Hard constraints restated (from the body — all binding):**
- Watcher is pure Python, NO LLM judgment; it NEVER classifies ripeness — it only executes IDs the PM adjudicated into the queue file. Missing/empty/invalid file → log + skip.
- occupied = count of `kind ∈ {infra, batch}` tasks at active statuses, read via the task-workflow API (subprocess to `task.py`, never hand-built paths); free = max(0, cap − occupied); dispatch up to `free` IDs from `ripe_oldest_first` in order.
- Per-ID guards: status ≠ `proposed` → skip; `~/.eps-autonomous/issue-<N>.json` exists → skip; ID in `holds` → skip; one spawn attempt per ID per cycle + last-attempt timestamp (backoff/attempt cap) so a failed spawn never tight-loops.
- Spawn via `spawn_session.py spawn-issue --issue <N> --auto` (same mechanism as crash-recovery).
- Kill switch env var (`EPM_DISABLE_INFRA_DRAIN=1`).
- Do NOT touch `task.py` status enums, marker schemas, or `spawn_session.py` CLI contracts. (This design adds zero lines to either file.)

**Why code, not a model call?** Required answer: (a) the single-model-call alternative — an LLM triage of ripe infra tasks — is exactly what the task body forbids (the PM session IS the LLM judge; duplicating judgment in the watcher would create two adjudicators); (b) code is preferred for determinism, auditability, and zero marginal cost at a 10-min cadence; (c) nothing flips this — the no-LLM constraint is the design's contract, not a trade-off.

All other §4 mandatory bullets (contrastive negatives, data realism tier, completion provenance, marker recipe, band designs, ICL demos, smoke/sweep parity, baseline propensity): **N/A — `kind: infra`, no training, no behavioral data.** Graceful-degradation bullet: no continuous-quantity eligibility gate exists here (all guards are categorical); the cap is a resource limit, not a keep/drop data gate — partial dispatch (fewer than `free` IDs eligible) is the normal, logged outcome. ### 4.3 Pure decision function (the testable core)

```python
def decide_infra_drain(
    ids: list[int],                      # ripe_oldest_first, validated
    cap: int,
    holds: set[int],
    statuses: dict[int, str | None],     # pre-fetched per-ID task status (None = unreadable)
    registered: set[int],                # IDs with an existing issue-<N>.json OR manual-issue-<N>.json
    occupied_active: int,                # infra/batch tasks at INFRA_DRAIN_OCCUPIED_STATUSES
    attempts: dict[int, dict],           # state file: {id: {"attempts": int, "last_attempt_ts": float, ...}}
    now: float,
    queue_updated_ts: float | None,
    *,
    backoff_s: float = INFRA_DRAIN_BACKOFF_S_DEFAULT,
    max_attempts: int = INFRA_DRAIN_MAX_ATTEMPTS_DEFAULT,
) -> tuple[list[int], list[tuple[int, str]]]:
    """Pure decision: (dispatch_ids_in_order, skipped [(id, reason)]).

    Occupancy: free = max(0, cap - occupied_active - pending), where pending
    counts queue IDs that are registered AND still `proposed` — a session
    spawned seconds/minutes ago whose /issue run hasn't flipped the status
    yet. Without this, the tick after a dispatch under-counts and the queue
    can overshoot the cap (the status scan can't see the in-flight spawn;
    the registration can).

    Per-ID guard order (cheapest first; every skip carries a reason string):
      1. id in holds                          -> "held"
      2. id in registered                     -> "already-registered" (counts toward pending if status == proposed)
      3. attempt budget (only when queue_updated_ts is None or <= last_attempt_ts;
         a NEWER queue write = fresh PM adjudication = budget reset):
           attempts >= max_attempts           -> "attempts-exhausted"
           now - last_attempt_ts < backoff_s  -> "backoff"
      4. statuses.get(id) is None             -> "status-unreadable"   (fail toward not dispatching)
         statuses[id] != "proposed"           -> "status-<status>"
      5. free <= 0                            -> "cap-full"
      6. else dispatch; free -= 1             (one attempt per ID per cycle by construction)
    """
```

Pseudocode (the implementer writes exactly this logic):

```python
pending = sum(1 for i in ids if i in registered and statuses.get(i) == "proposed")
free = max(0, cap - occupied_active - pending)
dispatch, skipped = [], []
for i in ids:
    if i in holds:                       skipped.append((i, "held")); continue
    if i in registered:                  skipped.append((i, "already-registered")); continue
    rec = attempts.get(i) or {}
    last = rec.get("last_attempt_ts")
    fresh_adjudication = (queue_updated_ts is not None and isinstance(last, (int, float))
                          and queue_updated_ts > last)
    if rec and not fresh_adjudication and isinstance(last, (int, float)):
        if rec.get("attempts", 0) >= max_attempts: skipped.append((i, "attempts-exhausted")); continue
        if now - last < backoff_s:                 skipped.append((i, "backoff")); continue
    status = statuses.get(i)
    if status is None:                   skipped.append((i, "status-unreadable")); continue
    if status != "proposed":             skipped.append((i, f"status-{status}")); continue
    if free <= 0:                        skipped.append((i, "cap-full")); continue
    dispatch.append(i); free -= 1
return dispatch, skipped
```

### 4.5 The pass executor

```python
def infra_drain_pass(dry_run: bool, now: float | None = None, *,
                     daemon_reachable: bool | None = None) -> None:
    """Execute the PM-adjudicated infra dispatch queue (task #633). Pure
    executor — every judgment was the PM session's; every guard is mechanical."""
```

Flow (each early-exit prints exactly one `infra-drain: ...` header line):

1. Kill switch: `not _infra_drain_enabled()` → `infra-drain: disabled via EPM_DISABLE_INFRA_DRAIN; skipping` → return.
2. Queue file missing → `infra-drain: no queue file at ~/.eps-autonomous/infra-drain-queue.json; skipping` → return. Read + `parse_infra_drain_queue`; `None` → loud `infra-drain: INVALID queue file (...); skipping (fail-safe: not dispatching)` → return.
3. Daemon gate: `daemon_reachable` False → `infra-drain: Happy daemon unreachable; skipping (spawn needs the daemon RPC)` → return. (Reuses main()'s single probe result.)
4. Load state; `registered = _infra_drain_registered(ids)`.
5. **Cheap pre-filter:** if every ID is held / registered / in-backoff / attempts-exhausted (computable without subprocesses), print the summary line and skip steps 6-7 entirely (saves ~8-10 `task.py` subprocesses on the common nothing-to-do tick). State pruning (step 9) still runs.
6. Fetch `statuses[id] = _task_status(id)` for each non-held ID (registered ones included — needed for the `pending` count). Queue is small (4 now; PM-curated, stays ~O(10)).
7. `occupied_active = _infra_drain_occupancy()`; `None` → loud skip line (fail-safe), still prune+save state, return.
8. `dispatch, skipped = decide_infra_drain(...)`. For each dispatch ID: `_dispatch_infra_drain(...)`; record the attempt in state **whether or not it succeeded** (`attempts += 1` — reset to 1 first when `fresh_adjudication`, `last_attempt_ts = now`, `last_result`); on success additionally `_post_progress_marker(issue, f"{_INFRA_DRAIN_NOTE_SENTINEL} watcher dispatched autonomous session from the PM infra-drain queue (occupied {o}+{p} of cap {c})", dry_run, label="infra-drain")`. For each `attempts-exhausted` skip, log loudly once (state flag `exhausted_logged`, mirroring the orphan pass's `alerted` dedup).
9. Prune state entries whose ID left `ripe_oldest_first`; `_save_infra_drain_state` (atomic).
10. Summary: `infra-drain: queue=<n> occupied=<o>(+<p> pending) cap=<c> dispatched=<k> skipped=<m>` plus one `  INFRA-DRAIN SKIP issue #<N> (<reason>)` line per skipped ID (with the file's hold reason interpolated for `held`).

`dry_run` threads through everywhere: decisions + `[dry-run] would dispatch ...` lines; no spawn, no marker, no state write (mirror the orphan pass's dry-run discipline).

## 8. Risks and Failure Modes

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Double-spawn race vs a concurrently-dispatching PM session / its hourly cron (window between registration-existence check and the spawn's own registration write, ~1-3 s) | Low | One duplicate session on one task (no pod spend for infra tasks; second session collides on the same issue) | Just-before-spawn registration re-check in `_dispatch_infra_drain` (shrinks window to the subprocess itself); PM doc instructs write-queue-then-dispatch ordering; same residual race already exists today between PM manual dispatch and its hourly cron — not made worse |
| Stale queue file dispatches a task the user un-riped | Medium | Unwanted session | `status != proposed` guard catches status-changed cases; for still-`proposed` un-riping the PM rewrites the file (holds/removal) — documented as THE un-ripe mechanism; `EPM_DISABLE_INFRA_DRAIN=1` and `cap: 0` are the emergency stops |
| Torn read of a mid-write queue file | Low | None (fail-safe) | Invalid JSON → no-op this tick; PM doc mandates atomic tmp+rename writes |
| Failed spawn tight-loop (daemon flaky, spawn_session bug) | Medium | Log spam, wasted subprocesses | 1 h backoff + 3-attempt budget per PM adjudication epoch; one-time `attempts-exhausted` loud log; budget re-arms only on a fresh PM `updated_ts` |
| Over-dispatch past cap from stale occupancy (dispatched-this-tick / spawned-last-tick tasks still `proposed`) | Medium | >3 concurrent infra sessions | In-cycle: `free` decrements per dispatch; cross-cycle: registered-and-still-`proposed` queue IDs count toward occupancy (§4.3 `pending`) |
| Partial `list-by-status` failure under-counts occupancy → over-dispatch | Low | Cap breach | `_infra_drain_occupancy` returns `None` on ANY per-status failure → pass skips dispatching this tick (fail-closed; deliberate divergence from `_active_status_tasks`'s fail-open, §11) |
| Watcher tick cost growth | Low | Slower ticks | Cheap pre-filter (step 5) skips all subprocesses on the common nothing-dispatchable tick; worst case ≈ (#non-held IDs × ~2 s) + 8 × ~2 s ≈ 20-25 s, within the 10-min budget and under the existing flock |
| Queue ID for a deleted/nonexistent task | Low | Repeated cheap status probes | `status-unreadable` skip (no spawn, no attempt consumed); PM prunes on next pass |
| Lock contention | Nil | — | Pass runs inside the existing `watch.lock` single-flight; no new lock |

## 11. Decision Rationale

N/A — no model training; no training hyperparameters; no behavioral construct. Load-bearing **design constants**, each grounded:

- **Cap default 3.** What: `INFRA_DRAIN_CAP_DEFAULT = 3`, used only when the file omits `cap`. Why: matches the adjudicated value in the live queue file and the PM standing rule item 4 ("Concurrency cap: 3 concurrent infra sessions"). Source: `~/.eps-autonomous/infra-drain-queue.json` (`cap: 3`) + `.claude/agents/research-pm.md:377` item 4 + task #633 body. Alternatives: no default (missing cap → invalid) — rejected; the body names 3 as the schema default, and a missing-field no-op would silently disable the drain on a benign omission.
- **Occupied-status set.** What: `{planning, plan_pending, approved, running, verifying, interpreting, reviewing}` + `followups_running`. Why: the first seven are the body's verbatim contract; `followups_running` is added because a same-issue follow-up round is in-flight work holding a session (watcher `ACTIVE` and `POD_ACTIVE` both include it since 2026-06-10), and counting it only ever dispatches LESS (conservative direction). `blocked`/`proposed`/terminal excluded per the body (a blocked task waits on the user, possibly for days — letting it pin a slot would jam the drain). Source: task #633 body ("starting contract — refine as needed") + `autonomous_session_watch.py` `ACTIVE`/`POD_ACTIVE` precedent. Alternatives: body set verbatim — rejected (allows cap+1 concurrency during follow-up rounds); counting live sessions instead of statuses (the PM rule's own method) — rejected (status read is daemon-independent and matches the body's stated contract).
- **Backoff 3600 s, attempt cap 3, reset on newer `updated_ts`.** What: a failed spawn is not retried for 1 h; after 3 attempts the ID is parked until the PM rewrites the queue. Why: at a 10-min cron, 1 h ≈ 6 ticks — long enough to outlast transient daemon flaps (the dominant spawn-failure mode), short enough to self-heal same-day; cap 3 mirrors the orphan pass's bounded-respawn philosophy (`ORPHAN_MAX_RESPAWNS_PER_DAY_DEFAULT` = 2/day, `STALLED_MAX_RESPAWNS` = 3/episode); the `updated_ts` re-arm makes a fresh PM adjudication the natural reset epoch instead of an arbitrary UTC-day boundary. Source: task #633 body ("backoff or attempt cap") + the orphan/stalled precedents in the same file. Alternatives: per-UTC-day cap (orphan style) — rejected, the PM epoch is the semantically right reset; exponential backoff — rejected as needless complexity for a ≤O(10)-ID queue. Both values env-overridable.
- **Single consolidated state file** (`infra-drain-state.json`) vs per-issue `infra-drain-<N>.json`. Why: the pass is queue-scoped, not issue-scoped — pruning to the queue's ID set is one dict comprehension, needs no `_GC_TARGETS` registration, and avoids N tiny files for transient attempt counters; single-writer safety holds because the whole watcher runs under `watch.lock`. Source: precedent trade-off visible in `_GC_TARGETS`' exclusion notes (pod-safety/session-reconcile manage their own state lifecycles). Alternative: per-issue files + GC registration — rejected (more surface, no benefit at this scale).
- **Fail-closed occupancy (`None` on any status-read failure)** — deliberate divergence from `_active_status_tasks`' fail-open per-status skip. Why: that helper feeds a recovery pass (under-enumeration just delays recovery); this one feeds a spawner (under-counting occupancy over-dispatches past the cap). Source: the asymmetry is the same fail-toward-keep logic documented throughout the watcher (e.g. `decide_idle_unmapped`'s missing-signal-fails-toward-keep).
- **Kill-switch polarity (`EPM_DISABLE_INFRA_DRAIN=1` disables)** — the body names this exact var; existing passes use enable-vars defaulting on (`EPM_SESSION_RECONCILE_AUTOSTOP=0`). Honoring the body's named contract wins; helper + docs make the polarity explicit. Source: task #633 body.
- **Dispatch marker = generic `epm:progress` with a registered sentinel.** Why: declaring a new marker kind is a public-contract change the body forbids; `_post_progress_marker`'s docstring documents this exact reasoning; the sentinel must join `_WATCHER_NOTE_SENTINELS` or the dispatch note would reset the orphan/stalled staleness clocks for the freshly-spawned session. Source: `autonomous_session_watch.py:1728-1737` + `_latest_progress_ts` (1200).
