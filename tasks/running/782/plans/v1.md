# Plan — issue #782: gcp poller must map `PENDING` → running (FLEX_START queue false-stall)

## TL;DR (plain English)

- **What I'll fix:** When we rent a GPU machine on Google Cloud through the cheap "wait-in-line for capacity" queue, our watcher script currently misreads the "still queued, be patient" state as "this run is broken" and would kill the job. This one-line fix teaches the watcher that "still queued" is healthy — keep waiting, don't panic.
- **What I expect:** A queued machine is now reported as running-and-waiting, so the watcher keeps polling instead of marking the run failed. No behavior changes for any other machine state.
- **What would change my mind:** If some other part of the code actually depended on the old "broken" reading for a queued machine — but I grepped and confirmed nothing does; both callers pass the reading straight through untouched.

## 1. Goal
Make `_gcp_status_to_poll_result` classify the GCE `PENDING` lifecycle state as a live, keep-polling state (`status="running", current_phase="pending"`) so a FLEX_START-queued instance is not false-blocked by the `/issue` Step 6d.2 `status=="stalled"` → `epm:failure` → teardown → `set-status blocked` path. This removes the reconnect-vs-poll asymmetry: `reconnect_or_none` already treats PENDING as live.

## 2. Prior Work
In-tree siblings that already treat PENDING (and the FLEX_START queue) as legitimate live state:
- **`_NONLIVE_INSTANCE_STATUSES`** (`gcp.py:2477`) = `frozenset({"TERMINATED","STOPPED","SUSPENDED"})` — the reconnect path's non-live set explicitly EXCLUDES PENDING, so `reconnect_or_none` returns a live handle for a PENDING instance. This is the parity the poller must mirror.
- **FLEX_START PENDING on the CREATE path (#736)** — the create-timeout handler (`gcp.py:3521` comment + `GcpCreateTimedOutStillProvisioning` → exit 75) already documents that "FLEX_START rungs legitimately stay PENDING past the GCLOUD_DEFAULT_TIMEOUT_SEC subprocess cap" and probes the live instance rather than treating the timeout as failure. The poll-path fix here is the same principle on the poll side.
- **#778 live repro** — instance `eps-issue-778` in `us-central1-b` sat in the FLEX_START capacity queue at PENDING for ~1h47m; `scripts/backend_poll.py --issue 778` returned `status=stalled current_phase=unknown_pending`, which the Step 6d.2 literal would convert to a false block.

## 4. Design

The cost is one extra source line; the clarity is worth it for a workflow-surface file whose misreadings cost a false block.

### 4.1 Source diff — `gcp.py:5015-5036`

Docstring: add the PENDING mapping line to the enum list.
```
     See https://cloud.google.com/compute/docs/instances/instance-life-cycle
     for the GCE status enum. We map:

     * ``RUNNING`` → ``running`` (pid_alive=True)
+    * ``PENDING`` → ``running`` (FLEX_START-queued for capacity; the
+      orchestrator's bg loop keeps polling — mirrors ``reconnect_or_none``,
+      which treats PENDING as live since it is not in
+      ``_NONLIVE_INSTANCE_STATUSES``; #782/#778)
     * ``PROVISIONING`` / ``STAGING`` → ``running`` (VM is coming up; the
       orchestrator's bg loop will keep polling)
     * ``STOPPING`` / ``REPAIRING`` → ``stalled`` (transient; bg loop retries)
     * ``TERMINATED`` / ``STOPPED`` / ``SUSPENDED`` → ``dead``
     """
```

Body: add the dedicated `PENDING` branch immediately after the `RUNNING` branch (before `PROVISIONING/STAGING`).
```
     up = status.upper()
     if up == "RUNNING":
         return _coarse_poll(status="running", current_phase="running")
+    if up == "PENDING":
+        # FLEX_START capacity-queue state — legitimately live, keep polling
+        # (parity with ``reconnect_or_none`` / ``_NONLIVE_INSTANCE_STATUSES``;
+        # #782). Distinct branch from PROVISIONING/STAGING (VM booting) so the
+        # queued-vs-booting distinction is explicit at the call site.
+        return _coarse_poll(status="running", current_phase="pending")
     if up in {"PROVISIONING", "STAGING"}:
         return _coarse_poll(status="running", current_phase=up.lower())
     if up in {"STOPPING", "REPAIRING"}:
         return _coarse_poll(status="stalled", current_phase=up.lower())
     if up in {"TERMINATED", "STOPPED", "SUSPENDED"}:
         return _terminal_dead_poll(reason=up.lower())
     return _coarse_poll(status="stalled", current_phase=f"unknown_{up.lower()}")
```

Return shape unchanged: `_coarse_poll(...)` returns a `PollResult` exactly as the other live branches.

Add the regression test (place it near the other pure-helper unit tests, e.g. after `test_resolve_provisioning_model_rejects_typo` around line 861 — any location in the module is fine; it is a standalone function needing no fixture):
```python
def test_gcp_status_to_poll_result_pending_maps_to_running_not_stalled() -> None:
    """A FLEX_START-queued GCE instance (status PENDING) is a live,
    keep-polling state — NOT the false-stalled routing that the /issue
    Step 6d.2 poll pseudocode would convert to epm:failure + set-status
    blocked (#782 / live repro #778). Mirrors reconnect_or_none, which
    treats PENDING as live (not in _NONLIVE_INSTANCE_STATUSES)."""
    result = _gcp_status_to_poll_result("PENDING")
    assert result.status == "running"
    assert result.current_phase == "pending"

    # Case-insensitive on the raw GCE string (matches the up = status.upper()
    # normalization the other branches rely on).
    lower = _gcp_status_to_poll_result("pending")
    assert lower.status == "running"
    assert lower.current_phase == "pending"

    # Regression guard: it must NOT fall through to the unknown_* stalled
    # default (the pre-fix behavior that caused the false block).
    assert result.current_phase != "unknown_pending"
    assert result.status != "stalled"
```

**Assertions rationale:** `status == "running"` is the load-bearing pin (it is what Step 6d.2 branches on — `stalled` triggers the teardown+block, `running` keeps polling). `current_phase == "pending"` pins the Option-B label. The `!= "unknown_pending"` / `!= "stalled"` guards pin the exact pre-fix regression so a future refactor that re-drops PENDING to the fall-through is caught.
