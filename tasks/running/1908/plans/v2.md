## Root cause (VERIFIED at clarify time — epm:clarify v1)

`scripts/issue1335_fit.py` patches the module global `fit825.FROZEN_LAYERS = tuple(frozen_layers(n_layers))` at `fit_cell` (:316), `fit_cell_matched` (:400), and `run_loso` (:596) with NO restore — deliberate script-lifetime "module-global patch style" (`scripts/issue825_fit_cells.py:88` comment), process-safe in production subprocesses, leaky inside one pytest session. `frozen_layers(n_layers)` (`issue1335_fit.py:206-208`) falls back to `[n_layers - 1]` when no canonical frozen layer < n_layers, so ladder tests exercising the REAL `fit_cell` body on tiny fixtures (e.g. the `run_swap` resume-rewrite test, `tests/test_issue1335_ladder.py:~897-925`) leave `fit825.FROZEN_LAYERS = (1,)`. The parity tests read the module global (`issue825_fit_cells.py:1335` layer filter) and key their mlp blocks on layer `'1'` instead of `'14'` — the observed set-diff failure. Both test files import the SAME `issue825_fit_cells` sys.modules entry (both put `scripts/` on `sys.path`: ladder :38, parity :31-33), which is the shared-state channel.
