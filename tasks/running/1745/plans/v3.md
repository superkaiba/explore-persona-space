# Plan — task #1745: align a self-declared plan-header version with the assigned version at persist time

**Kind:** infra (workflow-fix; `wf-fix` tag, fingerprint `ca895df19f35`)

**TDD:** no

## Requirement + acceptance criteria

**Requirement (task Goal):** Stop the c40 header-version WARN churn: align the plan header with the assigned version BEFORE persisting.

The churn mechanism (verified at clarify time): `task_workflow.new_plan_version` assigns `v{max+1}.md` by FILENAME and writes the plan content verbatim; nothing aligns a `# Plan v<K>` header the planner improvised inside the content. `verify_plan.py` c40 (`c40_header_version_vs_filename`, WARN-only) fires only POST-persist, so each header fix costs another persisted version + verify cycle (#1715 looped v2→v3→v4; #1734 same shape).

**Acceptance criteria:**

1. `new_plan_version` (the single canonical plan writer, `src/explore_persona_space/task_workflow.py` L5261) rewrites a self-declared `Plan v<X>` version in the plan's FIRST markdown heading to the version it is about to assign (`next_v`), before writing `v{next_v}.md`. Case-insensitive, c40-regex parity (`(?i)^plan\s+v(\d+)\b` on the heading text).
2. Version-neutral headers (`# Plan — task #<N>: …`, `# Plan (amendment) — …`) are untouched (the c40 sanctioned escape stays sanctioned).
3. YAML frontmatter and fenced code blocks are never rewritten; only the first real heading is considered (parity with c40's `split_frontmatter` + first-heading semantics).
4. Idempotent: a header already reading `v{next_v}` is written unchanged.
5. A freshly-persisted plan can no longer WARN on c40 by construction when its header self-declares a version (the header now always matches the filename at write time).
6. `.claude/skills/adversarial-planner/SKILL.md` documents the auto-alignment in the persist recipe ("Log the plan" bullet) so sessions stop hand-retitling + re-persisting to clear a c40 WARN (the exact churn loop this task closes).
7. New unit tests pin behaviors 1–4; the existing `new_plan_version` tests (versioning, gap-skip max+1, overwrite refusal, deferred commit) stay green.

## Method delta (design decision: code-side auto-rewrite, plus a one-line doc note)

The task body offered two forms: (A) doc-only pre-persist retitle instruction in the adversarial-planner SKILL.md, or (B) auto-rewrite in `new_plan_version` at persist time. **This plan picks (B) + a doc note**, for three reasons:

- **Single writer, all call sites.** `new_plan_version` is the one canonical writer (its own docstring says so). A code-side rewrite covers EVERY persist path — adversarial-planner Phases 1/1.5.0/3, the /issue Step 2b/3 revise paths, same-issue follow-up amendment rounds, and any ad-hoc `task.py new-plan-version` call — where a SKILL.md prose step covers only sessions that read (and obey) that one skill.
- **Mechanical beats prose for a mechanical invariant.** The header-vs-filename identity is a pure function of `next_v`, which only the writer knows race-free (`next_v` is derived under `_locked()`; a doc-side `ls plans/` pre-derivation is the same arithmetic done earlier, outside the lock).
- **Fail-safe.** Worst case for the rewrite is a no-op (no heading, version-neutral heading, already-correct version). It never blocks a persist and never touches anything except the version digits in the first heading.

The doc note (criterion 6) is the residual (A)-half worth keeping: without it, a session seeing an OLD plan's stale header (persisted pre-fix) might still hand-retitle-and-re-persist. The note says: the persist auto-aligns; never burn a plan version solely to fix a c40 header WARN.

## File paths + concrete diffs

**1. `src/explore_persona_space/task_workflow.py`** — add a module-level helper + one call inside `new_plan_version`:

```python
_PLAN_HEADER_VERSION_RE = re.compile(r"(?i)^(#{1,6}\s+plan\s+v)(\d+)\b")

def _align_plan_header_version(plan_md: str, next_v: int) -> str:
    """Rewrite a self-declared ``Plan v<X>`` in the FIRST markdown heading
    to ``v{next_v}`` (c40 parity; #1745). Skips YAML frontmatter and fenced
    code; only the first heading is considered; version-neutral headings
    and non-heading content are untouched. Pure no-op when nothing matches.
    """
    lines = plan_md.splitlines(keepends=True)
    i = 0
    if lines and lines[0].strip() == "---":          # skip YAML frontmatter
        for j in range(1, len(lines)):
            if lines[j].strip() in ("---", "..."):
                i = j + 1
                break
    in_fence = False
    for k in range(i, len(lines)):
        stripped = lines[k].lstrip()
        if stripped.startswith("```") or stripped.startswith("~~~"):
            in_fence = not in_fence
            continue
        if in_fence:
            continue
        if re.match(r"^#{1,6}\s", lines[k]):
            lines[k] = _PLAN_HEADER_VERSION_RE.sub(
                lambda m: f"{m.group(1)}{next_v}", lines[k], count=1
            )
            return "".join(lines)                    # first heading only
    return plan_md
```

Inside `new_plan_version`, after `next_v` is computed and the overwrite-refusal guard has run, before `target.write_text(...)`:

```python

```
