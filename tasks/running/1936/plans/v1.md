## Method delta (vs prior related work)

Same class as #1590 (widen check-28 H-code regex) and #1688 (widen condition-label
regex): a verify_task_body regex-vocabulary widening + test pins. Delta specific to
this task: the widening also touches COMPARISON semantics (one-sided vs two-sided) —
resolved by generalizing the existing shard one-sided branch into a subset-claim
predicate instead of adding a modifier stopword list (the body's open design
question). Rationale: a modifier restricts the counted class ("chunk files" ⊆ files;
"activation chunks" ⊆ files), so a two-sided compare against the prefix's total file
count is semantically wrong for ANY modifier-qualified claim — one-sided is the
precision guard. This still catches the check's motivating failure class: folder
inflation and hallucinated over-counts satisfy claimed > n_files and WARN one-sided
(#931's "10 shards" vs 9 files precedent).

### 2. Single optional modifier token — same 5 sites

Insert between count and noun: `(?:(?P<mod>[A-Za-z][\w-]{0,30})[ \t]+)?`
(shape example for `_COUNT_NOUN_RE`):

```
- r"\b(?P<count>\d{1,3}(?:,\d{3})+|\d{1,6})\s+(?P<noun>files?|shards?)\b"
+ r"\b(?P<count>\d{1,3}(?:,\d{3})+|\d{1,6})\s+"
+ r"(?:(?P<mod>[A-Za-z][\w-]{0,30})[ \t]+)?"
+ r"(?P<noun>files?|shards?|chunks?|sidecars?)\b"
```

- `[A-Za-z]` start excludes digit tokens (a "3 44 files" typo cannot bind 44 as
  modifier); `[\w-]` covers hyphenated modifiers ("over-length-skip").
- Exactly ONE modifier token (two-modifier claims like "3 large activation chunks"
  stay unextracted — documented recall sacrifice).
- All existing lookaheads/anchors preserved verbatim AFTER the widened noun group:
  the A/B per-namespace negative lookahead, the D/E/40 wide `per\s+\w+` distributive
  lookahead, the B-adjacency declines, paren-body/qualifier bounds, Pattern E's
  `.match()` count-opens-the-paren anchor (count still opens; modifier sits between
  count and noun), Pattern D/40's `\(count` opening.
- The modifier must NOT let a per-namespace claim leak into A/B: "891 json files per
  namespace" still hits the noun-adjacent lookahead (test-pinned).

### 3. Subset-claim (one-sided) comparison — generalize the shard branch

- Gatherers compose the reported noun label as `f"{mod} {noun}"` when the modifier
  matched, else `noun` (flows through the existing tuple positions; WARN messages
  then read "body claims 3 activation chunks at ...").
- New small helper (near the regex family), used at BOTH compare sites
  (`_verify_hf_whole_prefix_claims` ~L10719 and check 40's compare ~L11682):

```python
_SUBSET_COUNT_NOUNS = ("shard", "chunk", "sidecar")

def _count_claim_is_one_sided(noun_label: str) -> bool:
    """True when the claim counts a SUBSET of the prefix's files: a
    modifier-qualified claim ("chunk files", "activation chunks") or a
    subset noun (shards/chunks/sidecars) — compare one-sided (WARN only
    when claimed > files-only count). Bare "N file(s)" stays two-sided."""
    words = noun_label.lower().split()
    return len(words) > 1 or words[-1].rstrip("s").startswith(_SUBSET_COUNT_NOUNS)
```

  (Exact implementation shape is the implementer's; the CONTRACT is fixed: one-sided
  iff modifier present OR base noun ∈ {shard, chunk, sidecar}; bare file(s) two-sided.)
- Replace `noun.lower().startswith("shard")` at both sites with the helper.
- The per-namespace leg (`_verify_hf_per_namespace_claims`) is untouched (its claims
  come from the phrase-anchored files-only Pattern C regex).
