#### 4.1 `check_stale_evidence_pins` (check name: `stale-evidence-pins`)

Signature: `check_stale_evidence_pins(blanked_lines: list[str], figures_root: Path, expect_issue: int | None) -> CheckResult`. Operates on BLANKED lines (verbatim examples are data). Read-only local git via `_git`; no network, no writes. Returns ONE aggregated CheckResult (the file's idiom).

**Citation matcher (conservative by construction).** Per blanked line:
1. Skip the line entirely when it matches `_CODE_SHA_ROW_RE` (the `| Code SHAs |` row — run-provenance pins, not evidence citations).
2. Collect candidate paths: backticked tokens containing `/`, not containing `://`, not starting with `/`, no `…`/`...`, expanded through ONE brace group (`_expand_brace_group`), then filtered to the EVIDENCE-PREFIX set — a new module constant:
   `_EVIDENCE_PATH_PREFIXES = ("eval_results/", "ood_eval_results/", "figures/", "docs/")`.
   **v2: `tasks/` is DROPPED** (Codex-Methodology Must-Fix 2): task-folder status transitions rename `tasks/<status>/<N>/…` on every lifecycle move, and the rename's delete side satisfies a non-empty `git log <pin>..<tip> -- <old path>` — every parked-task citation would read permanently stale, the predictable-healthy-noise inversion of the check's purpose. `docs/` is RETAINED with the justification the same Must-Fix demands: report evidence legitimately lives there (`docs/reports/issue_<N>_detailed.md` is the REQUIRED detailed-writeup home, and `docs/methodology/` files are cited as evidence), renames there are rare and non-mechanical, and the WARN-only severity bounds the residual cost. Rationale for the code exclusion (`scripts/`/`src/`/`configs/` outside the set): "ran at `<sha>`" is provenance a later commit does not invalidate; `check_code_sha_cards` owns that surface. The prefix set is pinned verbatim by a §6 test, not tunable at implementation.
3. **Pin extraction with span hygiene (v2, per Claude-Methodology Concern 3 / Claude-Alternatives Concern 2):** before hex-run scanning, blank the matched candidate-path backtick spans themselves (mirroring `_same_line_pins`' existing URL + committed-under-span blanking) so a sha-like cited filename (`eval_results/issue_N/ab12cd34ef01.json`) can never contribute its own hex run as a pin. Then resolve same-line pins with the reused resolution logic, KEEPING each resolved pin's line POSITION (a thin positional variant of `_same_line_pins`; existing callers untouched). No resolvable pins → the line is not a citation-at-a-pin → skip silently (a no-pin committed-under claim already gets `committed-under-claims`' WARN; duplicating it here would double-report).
4. **Per-member pin ASSOCIATION (v2 — Codex-Methodology Must-Fix 1 / Codex-Alternatives Concern 1; replaces v1's line-wide any-pin-fresh):** each candidate member associates with ONE pin — the first resolvable pin whose span starts AFTER the member's backtick span (the witnessed grammars: `` `path`, committed at `sha` `` and `` committed under `path` at the branch pin (`sha`) `` both put the pin after the path); if no pin follows, the nearest resolvable pin BEFORE the member; a line with exactly one resolvable pin associates trivially. Staleness is evaluated ONLY against the associated pin — an unrelated fresh same-line code SHA can no longer silence a stale evidence pin (v1's false-silence channel), and a stale unrelated SHA cannot fire a fresh citation. Brace-group members share their group's association.
5. **File test (the directory-home-claim excluder):** for the (member, associated pin), run `_git(root, "ls-tree", "-r", "--name-only", pin, "--", member)`; proceed ONLY when the listing is exactly one name EQUAL to the cited member (a FILE at that pin). A multi-name listing (directory citation) is skipped with a note — later additions under a directory don't supersede a home claim, and the corrected #2162 report legitimately carries directory claims at old pins. A single-name listing NOT equal to the member (a directory containing exactly one file) is ALSO a skip — equality, not count, is the test (pinned by its own hermetic case, per Claude-Methodology Concern 2). A zero-name listing (path absent at pin) is skipped with a note — a broken citation is not a stale one. (**Ownership wording corrected per Codex-Methodology Concern:** `committed-under-claims` owns absent-path FAILs only for its own `committed|in git under` trigger grammar; a zero-blob `committed at` citation is currently owned by nobody — out of THIS task's stale-only Goal, noted as a possible follow-on.)

**Staleness read (v2 — authoritative-tip policy + ancestor guard).** Issue = `expect_issue` if provided, else `_infer_issue_from_lines`. **Authoritative tip = `origin/issue-<N>` when it resolves; local `issue-<N>` ONLY as fallback when origin is absent** (Codex-Alternatives Must-Fix 1: the task body's own ask is `git log <pin>..origin/<branch>`; v1's ALL-resolvable-tips-must-be-stale rule let a lagging local ref veto origin staleness — a silent-failure class). Before the log read, an **ancestor guard**: `_git(root, "merge-base", "--is-ancestor", pin, tip)` — a non-ancestor pin (rebased/divergent history) is skipped with a note ("divergent history — staleness undecidable"), never interpreted as stale (Codex-Methodology Must-Fix 1's non-ancestor clause; `pin..tip` on divergent refs lists commits that are not "after" the pin at all). For a surviving (member, pin): stale iff `_git(root, "log", "--format=%h %s", f"{pin}..{tip}", "--", member)` is non-empty. Note the branch-token pin case composes naturally: a citation pinned only by `` `issue-<N>` `` resolves the pin AT a tip, so the log range is empty (same ref) or covered by the ancestor guard → silent by construction (named residue below).

**WARN detail (per stale member, deduped by (member, pin)):** `line <n>: \`<path>\` cited at <pin12> has <K> newer commit(s) on <tip ref> — <sha12> "<subject≤60>"[, <sha12> "<subject≤60>" …, capped at 5, then "+K more"] — if the citation is a deliberate as-of pin, confirm the newer version still supports the citing sentence; else re-pin to the current commit`. **The detail ENUMERATES the newer commits (up to 5), not just the newest** (Codex-Methodology Must-Fix 3a: H1's integration assert requires BOTH measured commits nameable; deterministic order = `git log` output order, newest first).

**Per-report read cap (v2, per Codex-Methodology timing Concern):** at most 200 (member, pin) staleness reads per report; beyond the cap, remaining candidates are skipped with a counted note (WARN-only check — a capped read is disclosed, never silent). The kill criterion's >~10 s bar gets a timed probe at implementation: run the CLI on the frozen corrected-#2162 fixture and record wall time in the implementer report.

**Degrades (each recorded as a note or WARN, never fatal):** non-git `figures_root` → single WARN (mirrors `_check_pin_blob_identity` / `committed-under-claims`); issue number unresolvable OR neither branch ref resolves → PASS-note ("stale-evidence check skipped — no issue branch ref resolvable"; the post-merge branch-deleted shape must not WARN on every promote of an old report). No candidate citations → PASS "no evidence citations at a pin (N/A)".

**Severity: WARN in BOTH modes, never FAIL** (the task body's core call — an as-of pin is legitimate; the check cannot read contradiction). The staleness window in the motivating incident spans generation→promote, so a mode split in either direction would blind half the window (Claude-Alternatives pressure-point 4). The `superseded_readings`-marker FAIL escalation the body sketches is explicitly OUT OF SCOPE (a possible follow-on requiring a convention).

**What the check does NOT fire on (conservative-matcher enumeration):**
- Directory-level citations (multi-name listing, or single-name ≠ member) — skipped with note.
- `scripts/`/`src/`/`configs/` code citations + the Code-SHAs row — outside the prefix set / line-skipped.
- `tasks/` paths — outside the prefix set (v2; status-transition renames would read permanently stale).
- Lines with no resolvable same-line pin — skip (no double-reporting of `committed-under-claims`' no-pin WARN).
- Paths absent at the associated pin — skip (broken ≠ stale).
- Pins that are not ancestors of the authoritative tip — skip with note (divergent history).
- URLs, absolute paths, `…`-abbreviated paths, slash-less tokens — filtered before any git call.
- Image pins (`raw.githubusercontent.com` URLs) — not backticked repo-relative paths; URL spans blanked before pin extraction. `image-pin-blob-identity` keeps owning figure identity.
- Anything inside fenced code blocks / blockquotes — blanked before scanning.
- **Named residue 1:** a stale citation phrased WITHOUT a same-line pin — invisible by construction; the same-line convention is what the landed checks enforce.
- **Named residue 2:** artifacts modified on a DIFFERENT branch (e.g. main after a sibling merge) — out of scope per the task body ("modified on the same branch"); the tip is the issue's own authoritative ref.
- **Named residue 3 (v2, per Claude-Methodology Concern 4):** a citation whose associated pin is a BRANCH TOKEN (`` `issue-<N>` ``/`` `main` ``) resolves at a tip, so it is fresh-at-verify-time by construction — silent even if the prose beside it is stale; and a WORKTREE checkout whose local `issue-<N>` lags origin only matters in the origin-absent fallback (origin-preferred otherwise). Both in the accepted under-fire direction; one docstring line each.
