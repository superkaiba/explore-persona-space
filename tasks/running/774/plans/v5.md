<section class="plan-tldr">
<h2 style="border:none;margin-top:0">TL;DR (plain English)</h2>
<ul>
<li><strong>What I'll do:</strong> When the GCP launcher tries a couple of nearby data-center zones in turn and all of them are out of GPUs, it currently throws away everything except the last zone's error message. So when someone later reads the run's record to figure out what went wrong, it looks like only one zone was ever tried. I'll make the launcher keep a short note for <em>every</em> zone it tried, and surface that on the run's record, so the next person can see the real coverage at a glance.</li>
<li><strong>What I expect:</strong> The launcher already does try every valid zone — the multi-zone search isn't broken, only its bookkeeping is. After this change the run's <code>epm:backend-selected</code> marker will show a per-zone list (zone, why it failed, how long it took), and nobody will misread a multi-zone stockout as a single-zone one again.</li>
<li><strong>What would change my mind:</strong> If I found the new per-zone note could leak a secret (it can't — it reuses the same truncated, already-published error text), or if some existing reader of the run record would break when a new field appears (it won't — every reader uses safe lookups), I'd narrow or drop the change.</li>
</ul>
</section>

<h2>1. Goal &amp; acceptance criteria</h2>
<p><strong>Requirement (this is <code>kind: infra</code>, so phrased as requirement → acceptance, NOT hypothesis):</strong> when the GCP create for-loop fans out across multiple <code>us-central1</code> zones and all of them miss, the per-zone outcomes must survive to the <code>epm:backend-selected</code> marker so a retrospective reading the marker can see the ACTUAL zone coverage (which zones, why each failed) without re-querying the live GCP API. The multi-zone fan-out itself is already correct; this is a pure observability upgrade.</p>
<p><strong>Acceptance criteria:</strong></p>
<ul>
<li>A new unit test in <code>tests/test_gcp_backend.py</code> scripts a create failure across BOTH <code>a2-ultragpu-1g</code> zones (<code>us-central1-a</code>, <code>us-central1-c</code>) and asserts the raised <code>GcpProvisioningError.evidence["per_zone_attempts"]</code> carries exactly one entry per attempted zone, each with keys <code>{zone, returncode, matched_pattern, elapsed_s, stderr_tail}</code>.</li>
<li>A new unit test in <code>tests/test_router.py</code> asserts that a <code>RouteAttempt</code> carrying <code>evidence={"per_zone_attempts": [...]}</code> round-trips through <code>_attempt_to_dict</code> with the list intact — AND that an attempt with no evidence (the common shape) serializes EXACTLY as before (no <code>evidence</code> key, no reader breakage).</li>
<li><code>.claude/rules/compute-backend-failover.md</code> gains a "Per-zone fan-out visibility" subsection citing #763/#774; <code>workflow.yaml</code>'s <code>epm:backend-selected</code> attempts-schema doc lists the new additive <code>evidence</code> key.</li>
<li><code>uv run python scripts/verify_plan.py</code>, <code>uv run ruff check .</code>, <code>uv run python scripts/workflow_lint.py</code> all PASS; <code>uv run pytest tests/test_gcp_backend.py tests/test_router.py</code> PASSES.</li>
</ul>

<h2>2. Method delta (what's there now → what changes)</h2>

<h3>Currently in <code>gcp.py</code> <code>GcpBackend.launch</code> (the for-loop the prompt calls <code>_create_instance</code>)</h3>
<p>Lines ~3398–3493 (the provisioning loop lives directly inside <code>launch</code>; there is NO separate <code>_create_instance</code> method). <code>zones_to_try</code> is built from <code>config.primary_zone + config.fallback_zones</code>, filtered through <code>zones_for_machine_type(...)</code> against <code>MACHINE_TYPE_ZONE_AVAILABILITY</code> (so <code>a2-ultragpu-1g</code> → <code>["us-central1-a", "us-central1-c"]</code> — verified live 2026-06-30; the body's "a/b/c/f" is wrong for A100-80). The loop:</p>
<pre><code>last_error: GcpProvisioningError | None = None

<p><strong>Defect:</strong> <code>last_error</code> is OVERWRITTEN every iteration, so by the for-else only the LAST zone's <code>classify_create_failure</code> (its <code>stderr_tail</code> + <code>matched_pattern</code>) survives. The per-zone trail for all earlier zones is gone.</p>

<ol>
<li><code>_attempt_gcp_lane</code> auto-ladder rung (line ~3911) — <strong>the #763 path</strong>.</li>
<li>explicit-override fresh-submit seam (line ~2588).</li>
<li>(grep <code>except GcpProvisioningError</code> at implement time to confirm the full set that builds a RouteAttempt; currently these two.)</li>
</ol>
<p><code>_attempt_to_dict</code> (line ~4400s) serializes a RouteAttempt to a fixed 7-key dict; <code>_post_backend_selected</code> writes <code>"attempts": [_attempt_to_dict(a) ...]</code> into the <code>epm:backend-selected</code> note (all 10 marker-emitting call sites route through <code>_attempt_to_dict</code>). <h3>What changes</h3>
<ul>
<li><strong><code>gcp.py</code>:</strong> accumulate <code>per_zone_outcomes</code> in the loop; thread it onto <code>GcpProvisioningError.evidence["per_zone_attempts"]</code> at BOTH raise sites (the in-loop non-capacity <code>raise last_error</code> AND the for-else <code>raise last_error</code>); on success after an earlier miss, thread the preceding misses onto <code>handle.extra["per_zone_attempts"]</code>.</li>
<li><strong><code>router.py</code>:</strong> add <code>evidence: dict[str, Any] = field(default_factory=dict)</code> to <code>RouteAttempt</code>; emit it in <code>_attempt_to_dict</code> ONLY when populated; populate it from <code>exc.evidence.get("per_zone_attempts")</code> at the catch sites. Existing fields untouched.</li>
<li><strong>rule doc + workflow.yaml:</strong> additive documentation.</li>
</ul>

<h2>11. Decision Rationale</h2>
<p>N/A — no model training. (No load-bearing hyperparameters exist for this task type.)</p>
<p><strong>Design choices (non-hyperparameter):</strong></p>
<ul>
<li><strong>PIVOT to (a) rather than DEFLECT.</strong> Source: the clarifier's exhaustive pre-plan investigation (4 independent <code>epm:clarify</code> passes) + my own read of <code>gcp.py</code> lines 3398–3493 and <code>_attempt_to_dict</code>. The body's prescribed "fan out before declaring a miss" is already implemented; the genuinely-useful, in-scope, non-architectural fix is the per-zone visibility upgrade the clarifier and the prompt both recommend. The workflow-fix-on-bug protocol's intended use is exactly this: take the actually-useful fix from a candidate whose surface description is partially off.</li>
<li><strong>Additive <code>evidence</code> field over reshaping <code>detail</code>.</strong> Source: back-compat with every existing marker reader (verified: only <code>_attempt_to_dict</code> serializes; no strict-key consumer). Reshaping <code>detail</code> would change a field other tooling already reads; an additive optional field changes nothing for existing readers.</li>
<li><strong>Per-zone <code>stderr_tail</code> capped at ~200 chars.</strong> Source: the existing <code>classify_create_failure</code> (2000) / <code>_provisioning_detail</code> (1024) precedent already publishes this text; 200 is enough to carry the capacity-pattern line without bloating the marker N-fold (one per zone).</li>
<li><strong>Surface preceding misses on <code>handle.extra</code> for the success-after-miss case.</strong> Source: the prompt's option (a) bullet 2; uses the same opaque-<code>extra</code>-additive-key pattern as #659/#677, which round-trip faithfully through <code>serialize_handle</code>.</li>
<li><strong>Emit <code>evidence</code> in <code>_attempt_to_dict</code> only when populated.</strong> Source: keeps the common attempt-dict shape byte-identical for every existing reader / any golden-file test; only a GCP fan-out failure attempt grows the new key.</li>
</ul>
