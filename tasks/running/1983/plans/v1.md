# Plan v1 — issue 1983 — uniquify pod_disk_guard probe filename + widen errno tolerance

## 4. Design

### 4.1 Uniquify the probe path

Change `scripts/pod_disk_guard.py:83`:
```python
# BEFORE
probe_path = root / ".pod_disk_guard_probe.tmp"

# AFTER
probe_path = root / f".pod_disk_guard_probe.{os.getpid()}.{uuid.uuid4().hex[:8]}.tmp"
```

Add `import uuid` alongside the existing stdlib imports (line 33-41).

### 4.2 Widen the errno-tolerance set (mirror preflight.py's #1902/#1947 fix)

Change `scripts/pod_disk_guard.py:99` from:
```python
if e.errno == errno.EOPNOTSUPP:
```

to:
```python
if e.errno in (errno.EOPNOTSUPP, errno.ENOSYS, errno.EINVAL, errno.EBADF):
```

The fallback body (share-level free + fallback-reason detail) is UNCHANGED — same "posix_fallocate unsupported on {root}; fell back to shutil.disk_usage" structure, so callers that already handle EOPNOTSUPP see identical behavior. The widened set never touches EDQUOT/ENOSPC (they stay the real refusal signal).

### 4.3 Pin the invariants (extend `tests/test_pod_disk_guard.py`)

Add three tests mirroring `tests/test_preflight_disk.py`:

1. **`test_probe_survives_sibling_interference_on_legacy_shared_name`** — a fake `posix_fallocate` unlinks + recreates the LEGACY fixed name (`.pod_disk_guard_probe.tmp`) and applies shared-FS semantics (EBADF iff the fd's path no longer resolves to the same inode). Post-fix the probe uses a unique per-invocation name so the sibling interference cannot invalidate its fd; pre-fix (fixed name) this test fails.
2. **`test_probe_paths_unique_per_invocation`** — two sequential `probe_quota_headroom` calls see distinct `/proc/self/fd/<fd>` readlink targets.
3. **`test_probe_ebadf_falls_back`** — a mocked `posix_fallocate` raising `OSError(errno.EBADF)` returns `ok=True` with a `posix_fallocate unsupported` detail (the widened errno arm).
4. **`test_probe_ebadf_never_masks_edquot`** — EDQUOT stays a real refusal even with the widened errno set (`ok=False`).

## 5. Controls / risks

- **Not a behavioral change on the happy path.** A normal `probe_quota_headroom` call still writes-then-deletes a probe file; only the filename differs.
- **EDQUOT / ENOSPC handling unchanged** — the real-refusal path stays fail-loud.
- **The widened errno set adds ENOSYS + EINVAL + EBADF to the fallback path** (previously they raised). Rationale: identical mitigation the preflight helper already carries; ENOSYS/EINVAL name a genuinely-unsupported FS (fallback to `shutil.disk_usage` is correct), EBADF names the VAST/NFS-class filesystem-layer artifact (#1902).
- **No caller outside `pod_disk_guard.py` reads the probe filename** (verified) — the uniquification is safe.
- **Callers checking `ok is False` still get EDQUOT/ENOSPC signals unchanged.** The `detail` string on the widened arm has the same shape as EOPNOTSUPP already produced.
