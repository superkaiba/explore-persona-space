# Plan — Issue #2476: Turn-averaged SAE basis: does the map's high-level-over-low-level predictability gradient hold?

### 0.0 TL;DR (plain English)

- **What I'll run:** I take the project's context→answer map (predict the model's whole-answer average activation from the last token of the prompt, before it answers) and score the prediction in two "turn-averaged SAE" feature bases: one small sparse autoencoder I train directly on the ~942k banked whole-answer averages (following the recipe from a June 2026 paper that trains exactly this kind of SAE on exactly our model, layer, and corpus), and the parent issue's existing token-level SAE applied to turn averages as a bridge arm. For each SAE feature, I ask: how well does the map's predicted answer summary reproduce the true summary's feature value (held-out R²), and can the predicted features pick out the right conversation from thousands (acc@1)? I report both per granularity tier (general → specific features) against an identity+bias baseline. No new text is generated and no judge is called — everything comes from banked activations.
- **What I expect:** the parent's gradient repeats — general/coarse features stay predictable (median R² around 0.4+), highly specific features drop toward zero, and the permutation test that controls for how often features fire confirms the ordering.
- **What would change my mind:** if in the properly trained turn-averaged SAE the gradient disappears or reverses (specific features as predictable as general ones), the parent's token-level gradient was an artifact of per-token SAE features rather than a fact about the map — which rewrites the paper's "limits of the mapping" claim either way.

### 0. Plan Summary (technical)

### 1. Goal

"Determine whether the context-to-answer map's high-level-over-low-level predictability gradient (#1482) holds in a turn-averaged SAE basis: per-tier held-out R2 + acc@1 vs identity+bias for turn-averaged SAE features of true and map-predicted answer summaries." (Task #2476 Goal, verbatim; re-read from `frontmatter.goal` at plan-return time — unchanged from spawn.)

The parent #1482 established at token-level-SAE grain that the #779 context→answer map predicts coarse (tier-0) matryoshka features far better than specific (tier-2) ones. The paper's Results I claims the map predicts high-level/identity-level content and not low-level/topic-level content. The token-level basis is one step removed from the project's central object — the whole-answer MEAN activation v(x) — because it pools per-token SAE codes. A turn-averaged SAE (trained on turn averages) decomposes v(x) itself, so a gradient there is the directly paper-relevant form of the claim; its absence would mean the token-level gradient is a per-token-SAE artifact.

### 3. Hypothesis

- **H1 (primary):** the predictability gradient holds in the turn-averaged basis: per-tier median held-out R² of turn-averaged SAE features under the map decreases tier 0 → 2, and the within-activity-stratum tier-label permutation rejects in the coarse-better direction (parent analogue: −0.3949 vs band [−0.2499, −0.2275]).
- **H2:** the map beats identity+bias at every tier on both DVs (parent feature-space reference: ctx-map acc@1 0.5507 vs identity+bias 0.1197; pooled R² 0.6464 vs 0.0836).
- **H3 (bridge, arm b):** per-feature R² at the turn-averaged grain correlates with the parent's token-level per-feature R² on the same features/rows (Spearman > 0.5 expected), with the tier gradient preserved.
- **Falsification:** a flat or reversed tier profile in the trained turn-averaged SAE (arm c) — the permutation statistic inside or above the null band — falsifies the claim that the gradient is a property of the map rather than of per-token SAE features. This is a publishable outcome either way (paper Results I).

DISJOINT and exhaustive: Gradient-holds ⇔ arm-c observed within-stratum pooled Spearman(tier, per-feature R²) < the 10,000-draw null band 2.5th percentile AND median R²(tier 0) > median R²(tier 2); Gradient-reversed ⇔ observed > the 97.5th percentile AND median R²(tier 0) < median R²(tier 2); Indeterminate ⇔ otherwise.

Row-coverage: the map-vs-identity+bias contrast is feature-paired on the identical score rows and identical alive-feature set per arm (arm c: 20,000 holdout rows; arm b: the parent's 6,000 score rows) — every feature enters both arms or neither; the token-vs-turn-averaged bridge (arm b) is feature-paired on parent-panel ∩ turn-averaged-alive with per-tier attrition counts reported.

### 7. Decision Gates

No go/no-go decision gates — the hypothesis has no cheap intermediate that can rule out the full run (every phase is a prerequisite of the only DV), and total wall is ~7 h. The four gates below are **validity gates** (fail-loud correctness checks), each bound to its §4 mechanism:

- **G1 (reconciliation, P5; equality-within-tolerance):** mechanism = EA refit path scoring on pinned test + 20k holdout; compares recomputed whole-map R² against the committed values read from `eval_results/issue_1482/percontext/` at run time — full-train 0.7541708 (|Δ| ≤ 0.002, parent's own tolerance) and holdout-excluded 0.7243 (|Δ| ≤ 0.003). FAIL ⇒ assembly/split bug; halt fits.
- **G2 (recapture identity, P2; count+cosine):** mechanism = row-matched cosine of recaptured c20 vs banked `dense_l20` c20 over all 30,000 rows — per-row cos ≥ 0.999 (flat span-mean bf16 bar, #779/#1005 calibration; m-round precedent 0.999881) + hook-alignment probe (L20-maximal FVE). FAIL ⇒ capture-path bug; halt arm b.
- **G3 (arm-b encoder fitness, P6-entry; threshold):** mechanism = `SAELensJumpReLU.fve_l0` on the 30k turn averages — var-FVE ≥ 0.35 (the parent's gate_bm halt floor, `m_pilot.json`) to carry a registered read; below ⇒ arm b demoted to exploratory-with-caveat (arm c carries the verdict). - **G4 (SAE-c training sanity, P4; threshold):** mechanism = held-out 10k SAE-val var-FVE ≥ 0.5 (structural-breakage floor; expected ≳0.85 per the paper's native nMSE 0.097). Below ⇒ halt-investigate (LR/normalization bug) before any encode.
