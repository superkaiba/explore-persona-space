**(1e) Member-existence containment arm** (INSIDE the pass-1 `for f in $SPECS; do` loop, inserted immediately after the loop opens at ~L232, BEFORE the `bs_commits=` stanza). Motivation is experimental fact (verified in the v2 session in a scratch repo, and independently documented at `_FORK_STUBS_2303`'s comment): `git checkout <ref> -- <pathspecs>` errors AND updates NOTHING when any pathspec matches nothing at the ref (rc=1, matched paths untouched), while the preceding `git diff --quiet origin/main -- …` still reports drift (rc=1, no error) — so ONE main-deleted literal member would silently no-op the ENTIRE sync, every run, un-fixably (the steps file carrying SPECS is itself inside the wedged sync). This exposure pre-exists for the current literal tokens; this change adds 31 more, so it ships containment:

```
  # Member-existence containment (#2260; interaction with #2385): the
  # checkout below is ATOMIC — a single literal token absent at origin/main
  # (deleted/renamed on main) errors the whole checkout and syncs NOTHING,
  # wedging every family until manual reconcile. Contain per-family: an
  # absent literal member marks ITS family dirty (vintage-consistent skip;
  # other families keep syncing). Deletion PROPAGATION (removing the stale
  # worktree twin) remains #2385 — reconcile manually until it lands.
  case "$f" in
    ":(glob)"*) : ;;
    *)
      if ! git -C "$WT" cat-file -e "origin/main:$f" 2>/dev/null; then
        fam="${FAMILY_OF[$f]:-$f}"
        DIRTY_FAMILIES[$fam]=1
        echo "spec-freshness: $f is ABSENT at origin/main (deleted/renamed on main) — marking family '$fam' dirty; skipping blind sync for the whole family (atomic-checkout containment, #2260; stale-twin removal is #2385 — reconcile manually)."
        continue
      fi
      ;;
  esac
```
