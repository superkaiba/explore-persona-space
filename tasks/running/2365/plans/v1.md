# Plan v1 — #2365: stop Cloudflare Email Address Obfuscation from rewriting served dashboard bytes

**Kind:** infra (bug fix — CDN-layer silent substitution inside text presented as model generations).
**Venue:** VM-local only. No pod, no GPU, no HF.

## Requirement + acceptance criteria (from task body, verbatim intent)

1. A served dashboard's model-generation text is byte-identical to the committed
   HTML, or every divergence is enumerated and disclosed in the artifact itself.
2. `curl <served-url> | grep -c __cf_email__` returns 0 for the #2329 and #2162
   galleries.
3. The historical artifacts named in the body (`failures-2202_p2/p3/p5/p7/p9.html`,
   `sample500-2202_p1.html`, `context-extremes-1482.html`, both galleries) are
   re-verified after the fix — no rebuild expected if the fix is origin/zone-side.

Live confirmation at plan time (2026-08-27 14:01Z): served #2329 gallery carries
2 `__cf_email__` markers; local origin (127.0.0.1:3010) serves the same file with
`Cache-Control: public, max-age=0` (no `no-transform`) and 0 markers.

## Chosen approach (among the body's three options)

**Primary fix: origin-side `Cache-Control: no-transform`** on the dashboard's
static HTML artifact responses. Cloudflare documents `no-transform` as an
exception its HTML-rewriting features (Email Address Obfuscation included)
respect. One config-point change; covers every current AND future artifact;
committed bytes never change, so the historical artifacts are fixed without any
rebuild (same bytes simply stop being rewritten).

**Secondary fix (body option 3): served-vs-committed integrity probe** —
`scripts/verify_served_dashboards.py`, so this class of silent CDN transform is
caught mechanically from now on instead of by accident.

**Body option 1 (zone-wide Email Obfuscation OFF) stays the recommended real fix
but requires Thomas's Cloudflare access** — no zone-settings API credential
exists on this VM (clarifier sweep: repo `.env`, `dashboard/.env.local`,
`~/.cloudflared` holds only the tunnel-scoped cert). Surfaced as a needs-Thomas
note in the final report; NOT blocking, because the origin-side header satisfies
all three acceptance criteria for the artifact-serving class.

**Body option 2 (entity-encode `@` in every builder) is rejected as primary**:
it touches every completion-rendering builder, forces rebuilds of historical
artifacts, and changes committed bytes — strictly worse than the header on all
three counts. Its cousin, `<!--email_off-->` comment fences (also a documented
Cloudflare exception), is retained as the validated FALLBACK if the header
mechanism fails at either layer (see Kill criteria).

## Implementation steps (ordered; A de-risks B)

**A. Empirical CF-matcher probe (no deploy needed).** Drop an UNTRACKED file
`dashboard/public/cf-obfuscation-probe.html` containing three sections:
(1) a bare synthetic email `probe_bare@example.com`, (2) the same email wrapped
in `<!--email_off-->…<!--/email_off-->`, (3) the same email with `@` written as
`&#64;`. `next start` serves public files from disk at request time, so the file
is live immediately with NO build or restart. Curl it through
`https://eps.superkaiba.com/` and record which sections Cloudflare rewrites.
This gives ground-truth evidence for the fallback mechanism before any config
change. Delete the probe file at the end of step D.

**B. Origin header change.** `dashboard/next.config.ts`: add an
`async headers()` block scoped to the static HTML artifacts:

```ts
async headers() {
  return [
    {
      // All static .html artifacts under public/ (incl. nested, e.g. battery/).
      source: "/:path(.*\\.html)",
      headers: [
        { key: "Cache-Control", value: "public, max-age=0, no-transform" },
      ],
    },
  ];
},
```

The value preserves the current caching semantics (`public, max-age=0` is what
the origin serves today) and adds only `no-transform`. Scope is deliberately the
static artifact class — the failure class in evidence. App-rendered routes
(`/tasks/[id]` etc.) remain exposed to the same CDN transform until the
zone-side toggle; that residual is disclosed in the report (the zone toggle is
the cover-all and is Thomas's).

**Known unknown, handled empirically:** Next.js may override custom
`Cache-Control` for `public/` files in production. Verification gate right
after deploy: `curl -sI http://127.0.0.1:3010/issue2329_result0_gallery.html`
must show `no-transform`. If Next strips it, FALLBACK B': set the header in
`dashboard/middleware.ts` (matcher on `.html` paths). If middleware also cannot
carry it, FALLBACK B'': whichever content-level mechanism step A proved
(`<!--email_off-->` fences preferred; injected adjacent to `<body>`/`</body>`
tags of affected artifacts + a builder-side helper for future artifacts) — this
changes committed bytes and is taken only if both header routes fail.

**C. Integrity probe script.** New `scripts/verify_served_dashboards.py`:
- Enumerates git-tracked files under `dashboard/public/` (`.html` + `.json`).
- Fetches each from `https://eps.superkaiba.com/<relpath>` (flag
  `--base-url` to point at `http://127.0.0.1:3010` for origin-only checks).
- Per file: sha256(served) vs sha256(on-disk); counts `__cf_email__` and
  `cdn-cgi/l/email-protection` in served bytes.
- Exit non-zero on ANY divergence or nonzero marker count; prints a per-file
  verdict table. No try/except-pass; a fetch failure is a loud failure.
- Also WARNs (not fails) when on-disk differs from committed (`git diff --stat`
  on the path) so a dirty working copy is visible in the verdict.

**D. Deploy + verify (repo root, after merge — see sequencing note).**
1. Port-squatter check: `ss -tlnp | grep :3010` — kill any rogue `next start`
   by captured PID before restarting (known EADDRINUSE restart-loop trap).
2. `cd dashboard && npm run build`
3. `sudo systemctl restart eps-dashboard.service` (verified: `sudo -n` works).
4. Origin gate: `curl -sI http://127.0.0.1:3010/issue2329_result0_gallery.html`
   → `no-transform` present, then
5. Acceptance: `curl -s https://eps.superkaiba.com/issue2329_result0_gallery.html | grep -c __cf_email__`
   → 0; same for the #2162 gallery; then the full probe sweep
   `uv run python scripts/verify_served_dashboards.py` → PASS (covers the
   historical artifacts, acceptance bullet 3).
6. Remove the step-A probe file.

**E. Documentation.** One short section in `dashboard/README.md` (or
`scripts/dashboard/README.md`, whichever documents serving) recording: the
incident, the `no-transform` requirement, and the probe script as the standing
check.
