# Plan v3 — task #1944: Step 10d lint-gate payload attribution by offender path token

## Goal + requirement

Fix the Step 10d pre-push workflow-lint gate's payload attribution so a lint
failure MESSAGE that merely cites an own-diff path cannot false-attribute a
FOREIGN file's pre-existing failure to the merge payload (a false `block`
verdict). Incident: #1768 Step 10d r4 (2026-07-31 ~19:40Z) — the single gated
failure line was a pre-existing main red on
`scripts/issue1689_user_slot_capture.py` (jsonl-splitlines), but its message
text cites `.claude/rules/gotchas.md`, which was in #1768's own-diff via a
spec-freshness sync, so the whole-line `grep -F -f` landed it in
`lint-owndiff.txt`.

**Acceptance criteria:**

1. Both SKILL.md attribution sites — the shared gate block (currently
   ~L11804) and the surgical additive-checkout block (~L13539) — attribute by
   OFFENDER PATH TOKEN (the leading `<path>` before the first `:` of the
   normalized `workflow_lint: <err>` line, gate-tree prefix stripped) via
   exact set-membership against the payload list (own-diff / additive-files),
   not whole-line substring match.
2. Fixture check: the #1768 incident line shape
   (`workflow_lint: scripts/issue1689_user_slot_capture.py:: jsonl-splitlines: ... .claude/rules/gotchas.md ...`)
   does NOT attribute when only `.claude/rules/gotchas.md` is in the payload
   list; a genuine payload-offender line
   (`workflow_lint: <payload path>:: ...`) DOES attribute.
3. Existing pin tests stay green: `tests/test_step10d_guard3.py` (pins only
   the crash-arm predicate `[ ! -s /tmp/issue-<N>-lint-gated-norm.txt ]` at
   L607 — untouched) and the `tests/test_issue_skill_*.py` prose pins.
4. Verdict semantics (block / pass / crash arms, NEW-set subtraction,
   consume-on-merge-success, sha-binding) are byte-unchanged outside the two
   attribution commands + their immediately-preceding comment lines.

## Method delta

Replace the whole-line fixed-string grep with the awk path-token extractor
(validated live on #1768's re-run, per the filing): skip the
`workflow_lint: ` prefix, take the text before the first `:`, strip the
gate-tree prefix, trim whitespace, test exact membership in the payload set.

+    awk -v OWN=/tmp/issue-<N>-own-diff.txt '
+      BEGIN { while ((getline l < OWN) > 0) own[l]=1 }
+      /^workflow_lint: / {
+        s = substr($0, 16); n = index(s, ":")
+        path = (n > 0) ? substr(s, 1, n-1) : s
+        sub(/^\/tmp\/issue-<N>-lint-gate-tree\//, "", path)
+        gsub(/^[ \t]+|[ \t]+$/, "", path)
+        if (path in own) print $0
+      }' /tmp/issue-<N>-lint-gated-norm.txt \
+      > /tmp/issue-<N>-lint-owndiff.txt || true

## Failure-direction analysis

Path-token attribution strictly NARROWS the owndiff arm. A payload-caused
failure that the narrowed arm misses (leading token is a check name, not a
path) is still caught by the NEW-set arm
(`lint-new.txt = gated − baseline`): a payload-caused failure is absent from
the payload-free baseline by construction, so it lands in NEW and blocks via
verdict case 2. Pre-existing red appears in both legs and subtracts out. Net:
no fail-open window is introduced; the false-block window is closed.
