# Plan v2 — #2368: harden the first-quote `ssh_cmd` payload extractor in `tests/test_bootstrap_pod_git_credentials.py`

(v2 supersedes v1 after critic round 1 REVISE — one Must-Fix: the v1
terminator whitelist (whitespace / `;` / `)` / `|` / `&`) would silently pass a
same-line SECOND quoted argument (`ssh_cmd 'safe' 'tail'`), which under
routine `"$1"` → `"$@"` drift in the `ssh_cmd()` helper becomes live remote
payload invisible to the guard. Fix adopted: the critic's option (b) —
terminator set narrowed to NEWLINE / END-OF-TEXT ONLY — plus the third
mutation case that narrowing makes expressible, plus the recursive sweep
form. Self-contained: no reference to v1 is needed to execute this plan.)

## Requirement + acceptance criteria

Requirement (from the task body): `_single_quoted_ssh_cmd_blocks` in
`tests/test_bootstrap_pod_git_credentials.py:69-85` closes every `ssh_cmd '...'`
block at the FIRST following `'`. A payload that continues past that quote via
bash's standard quote-embedding idiom (close-quote, escaped quote, reopen-quote)
is silently truncated, and the negative assertion at line 200
(`"GIT_CRED_HELPER" not in block`) never inspects the tail — the test stays
green while the uninspected part regresses. Same defect family as #2360's
blockers B1/B5; the landed #2360 fix is the reference implementation.

Acceptance criteria (verbatim from the task body):
1. A quote inserted after the guarded region makes the extractor FAIL rather
   than silently truncate (mutation test, required to go red).
2. The extracted interior is asserted quote-free.
3. Every remaining first-quote payload extractor under `tests/` is either
   hardened or has a recorded reason it is safe.

## Method delta

## Design

**Step 1 — harden the extractor** (`_single_quoted_ssh_cmd_blocks`):
- After computing `close_q = text.index("'", open_q)`, require that the
  closing quote is followed by a NEWLINE or END-OF-TEXT — nothing else. Any
  other following character — `\` (the quote-embed continuation), an adjacent
  `'` or `"` (string concatenation), a space (same-line second argument:
  `ssh_cmd 'safe' 'tail'`), `;`, or anything further on the line —
  `pytest.fail` with a message naming the byte offset and the following
  characters, so no same-line continuation of any shape can pass silently.
  Zero false reds today: all 6 realized closes are newline-followed
  (plan-time fact above). A future legitimate same-line shape is whitelisted
  DELIBERATELY (a reviewed edit to the terminator predicate), never absorbed
  silently.
- Assert `"'" not in block` for every extracted block (defense in depth —
  trivially true under today's logic, pins the invariant against a future
  extractor rewrite).
- Rewrite the docstring: the current justification ("single-quoted bash
  strings cannot contain a single quote") is true of one literal but FALSE of
  the logical payload under the embed idiom; state the close-at-line-end
  rationale, note that the strictness deliberately also refuses same-line
  second arguments (so the guard does not depend on `ssh_cmd()` forwarding
  exactly `"$1"`), and name the documented limitation (a future legitimate
  same-line continuation needs a deliberate terminator-predicate edit).

**Step 2 — mutation tests** (new, same file; parametrized over three
continuation shapes, each spliced into a copy of the REAL script text at the
first `ssh_cmd '` block's closing quote, each carrying a
`GIT_CRED_HELPER`-bearing sentinel tail):
1. quote-embed continuation (close-quote, escaped quote, reopen-quote — the
   #2360 idiom);
2. adjacent double-quote concatenation (`'"..."'`);
3. whitespace continuation — a same-line second quoted argument
   (`ssh_cmd 'payload' 'sentinel'`), the case the v1 terminator set wrongly
   whitelisted.
Each case asserts the hardened extractor FAILS
(`pytest.raises(pytest.fail.Exception)`). Docstring states the red-direction
evidence: under the OLD extractor every one of these splices yields a
truncated block whose sentinel tail is never marker-matched, so the line-200
negative assertion stays green (silent under-inspection).

**Step 3 — sweep dispositions** (recorded in code comments + implementer
report):
- The implementer re-runs the recursive sweep itself:
  `grep -rnE "\.(index|find|rfind|split|rsplit|partition|rpartition)\(" tests/ --include='*.py'`
  filtered to quote-char arguments (both `"'"` and `'\''` spellings) — NOT a
  top-level-only `tests/*.py` glob — so the "under `tests/`" acceptance claim
  is certified at the right scope.
- `_helper_assignment_value_raw` (same file, lines 62-66): NOT a first-quote
  scan — it takes the whole assignment line, asserts a terminal double quote,
  and slices prefix/suffix, so embedded escaped quotes are INCLUDED, not
  truncated; the value is additionally cross-checked by real-bash
  materialization in test 5. Record as safe with that reason.
- `test_existing_repo_branch_retrofits_tokenless_remote` (`text.index("else",
  start)`): first-OCCURRENCE keyword scan, same family but all its assertions
  on the slice are POSITIVE (must-contain / ordering via `.index`, which
  raises on absence), so truncation flips green→red (loud), never silently
  green. Record as safe with that reason.
- Any additional hit the implementer's own sweep finds: harden if its
  assertions are negative-direction, else record the direction argument.
