### Step 0.69: Phase-idempotency + inter-phase-contract gate (any diff type; multi-phase dispatchers only)

A phased dispatcher that lacks skip-if-output-exists is the recurring paid-API
spend leak: a downstream vLLM crash restarts the pipeline from the top, re-running

diff alone. This gate is the review-side sibling of `.claude/rules/code-style.md`
line 53 (checkpoint-per-phase, ADVISORY-prose): the rule exists, and this gate
enforces it on dispatcher diffs.

**Trigger — does the diff add/modify a multi-phase dispatcher?** Grep the diff
for a phase-dispatch shape:

```bash
# Bash entrypoint dispatchers (issue<N>_dispatch.sh, one line per phase):
grep -nE '^phase_[a-z0-9_]+\s*\(\)|^case .* in$|_run_phase [a-z0-9_]+' <each dispatcher .sh in diff>
# Python phase-loop dispatchers (`for phase in PHASES`, `if args.phase == 'a'`):
grep -nE 'def phase_[a-z0-9_]+|PHASES *= *\[|args\.phase|--phase' <each dispatcher .py in diff>
```

Multi-phase = >1 phase name. Not a trigger — a single-entrypoint script or a
one-phase run: record `Step 0.69: N/A — diff carries no multi-phase dispatcher`
and proceed.

**Sub-check (1) — phase-level skip-if-output-exists.** For each phase, verify
ONE of the two patterns holds by reading the phase entry body:

- **(a) Sentinel/output-artifact skip.** The phase body checks a declared
  completion-sentinel or primary-output path at entry
  (`[ -e "$OUT/phaseA_done" ] && { echo "[phaseA] skip — sentinel exists"; return; }`,
  or a Python `if OUT.exists() and not args.force: return`). Bare file existence
  is ACCEPTABLE only when the phase writes its output atomically-then-renames
  (`os.replace` or `mv` of a tmp file) — otherwise the sentinel discipline of
  CLAUDE.md § Monitoring re-run discipline applies (never key "done" on a
  half-written file). Prefer a completion sentinel over a bare glob.
- **(b) First-class `--force` (or equivalently-named) flag.** The dispatcher
  accepts `--force` / `--rerun` / `--no-skip` / `--overwrite` (or the same as
  an env var like `FORCE_PHASE=1`) whose DEFAULT is OFF and whose value is
  threaded through the phase entry — so a deliberate rerun stays first-class.
  A phase that ALWAYS re-runs (no sentinel check AND no force flag) FAILs
  this sub-check.

Waiver form (mirrors `# CVD_PIN_EXEMPT: <reason>` from
`.claude/rules/gotchas.md`): a phase legitimately non-idempotent by nature (a
stochastic sampling phase whose output is per-run, an eval whose "done" state
is a WandB run id, etc.) carries `# PHASE_IDEMPOTENCY_EXEMPT: <reason ≥ 20 chars>`
on the phase entry's signature line. A waiver ≥ 20 chars is credited PASS.

**Verdict routing — sub-check (1):**

- Phase ships with (a) or (b) or a valid waiver → PASS this sub-check.
- **Phase makes paid API calls** (Anthropic/OpenAI/HF inference — grep the
  phase transitively for `anthropic.Anthropic`, `openai.OpenAI`,
  `api_dispatch.dispatch_judge_items` / `batch_judge` / `judge_completions_batch`,
  `openai.chat.completions.create`, or the plan §9 marks the phase `paid`) OR
  **holds a GPU** (grep for `vllm`, `AutoModel.from_pretrained`, `train_lora`,
  `LLM(`, `torch.cuda`, `accelerate launch`) AND ships without (a)/(b)/waiver →
  return verdict FAIL with a single `Critical` issue tagged `phase-not-idempotent`
  (SUBSTANTIVE — never stripped by Step 5c-bis), AND still read the diff and
  report substantive findings in the same pass (do not short-circuit — see
  Step 0.7):

  > `epm:experiment-implementation v<n>`'s dispatcher `scripts/<file>` phase
  > `<name>` makes paid API calls (or holds a GPU) but has no skip-if-output-exists
  > guard and accepts no `--force`/`--rerun` flag. A downstream crash re-runs it
  > from scratch, re-spending its API budget (or re-holding its GPU) each cycle
  > — the #1689 shape (4× re-runs of the same 3-condition × 3800-row Sonnet
  > phase across crash-fix relaunches). Re-post `v<n+1>` adding EITHER a
  > completion-sentinel check at phase entry (`[ -e "$SENTINEL" ] && return`)
  > OR a first-class `--force`-family flag (defaulting OFF), threaded through
  > the phase entry. Prefer a completion sentinel over bare file existence
  > (CLAUDE.md § Monitoring re-run discipline). A legitimately
  > non-idempotent phase carries `# PHASE_IDEMPOTENCY_EXEMPT: <reason ≥ 20c>`
  > on its entry.

- Phase is cheap CPU-only (no paid API, no GPU) AND ships without (a)/(b)/waiver
  → CONCERN bullet under "Issues Found"; NOT a standalone FAIL. Persist via
  `task.py raise-concern` per Step 0.8 / Rule 11 so the concern actually binds.

**Sub-check (2) — consumer inter-phase contract assertion.** For each phase
whose INPUT is another phase's persistent output (a JSONL / parquet / npz file
the earlier phase wrote), READ the consumer phase's entry:

- The consumer asserts every required input field non-empty (`assert
  row['prompt_text']` — never a silent `row.get('prompt_text', '')` chained to a
  filter), reports drop counts (`n_dropped > 0 → fail loud with the drop
  fraction`, per `.claude/rules/llm-judging.md` rule 9's drop-never-coerce
  discipline and CLAUDE.md § Critical Rules "Fail fast"), and does the check
  BEFORE any heavy initialization: `AutoModel.from_pretrained`, `LLM(`,
  `accelerate launch`, `torch.distributed.init_process_group`, first GPU-tensor
  allocation.
- **Verdict routing — sub-check (2):**
  - Contract assertion present + fail-loud + BEFORE model init → PASS.
  - Assertion present but AFTER model init → verdict FAIL with a single

    > `epm:experiment-implementation v<n>`'s consumer phase `<name>` reads

### 3.3 Add the finalization-crash gotchas entry to `.claude/rules/gotchas.md`

**Anchor.** After the EXDEV entry (L57), before the between-phase cache-reap entry (L59) — the dispatcher-orchestration cluster. Text (~1.6 KB):

```markdown
- **A phased-dispatcher entrypoint importing torch/scipy/sklearn/pandas/pyarrow
  should EXIT the process explicitly after flushing — a bare `return` / falling
  off `if __name__ == '__main__':` can hit a PyGILState_Release atexit race
  across the C-extension modules that returns nonzero to the dispatcher, and
  under `set -euo pipefail` turns a COMPLETED phase into a whole-pipeline
  abort.** Sibling of the between-phase cache-reap trap immediately below (also
  cross-phase file lifecycle, also caught only in production): the phase WROTE
  its output, printed its done breadcrumb (`[corpus] done: scanned=5132
  kept=3800`), and then died in interpreter finalization
  (`Fatal Python error: PyGILState_Release … Python runtime state: finalizing`)
  as ~200 C-extension modules tore down in nondeterministic order. The dispatcher
  read the nonzero rc from a phase whose WORK was complete and killed every
  downstream phase. DISTINCT from the vLLM teardown traps above (those are
  in-process subprocess-reap failures within a running Python — this is
  interpreter shutdown itself). RULE: every phase entrypoint that imports heavy
  C extensions (torch, scipy, sklearn, pandas, pyarrow, cupy, tensorstore, or
  the transitive load of any of these — vLLM, transformers, accelerate,
  datasets, peft all count) ends with `sys.exit(0)` on the success path (and
  `sys.exit(<rc>)` on error) — the exit fires BEFORE finalize-time C-extension
  teardown so the atexit race cannot rewrite the return code. `os._exit(0)`
  is a stronger alternative that SKIPS the finalize path entirely, at the cost
  of skipping stdout/stderr flushes and userland atexit handlers (safe for a
  phase whose outputs are all fsynced before the exit; the safer default is
  `sys.stdout.flush(); sys.stderr.flush(); sys.exit(0)`). Fail-loud sibling:
  the dispatcher's `set -euo pipefail` is CORRECT — the fix is the phase
  entry's explicit exit, never weakening pipefail. Diagnostic signature: the
  phase's own log ends with its own success line, then a `Fatal Python error`
  traceback (or a bare "Exception ignored in atexit callback"), then the
  dispatcher's `[dispatch] phase X exited rc=<nonzero>` line while every
  downstream phase is skipped by `set -e`. (Incident #1689 Phase A,
  session `5c5a89e8`, 2026-07-26T02:31Z: `[corpus] done: scanned=5132
  kept=3800` printed, PyGILState_Release traceback across 203 loaded modules,
  dispatcher aborted phases B–E; R6 fixed by adding explicit exits to 8
  entrypoints.)
```

No overlap; the two compose (a Step 0.69-idempotent phase can still call a wrong helper).

## 10. Decision Rationale — the design forks

**Fork (a): where does the finalization entry live — `gotchas.md` or `code-style.md` § checkpoint-per-phase?**

**Decision: `gotchas.md`.** The finalization crash is a specific interpreter-shutdown race that surfaces under a specific dispatcher shape — the shape family of every existing gotchas.md entry (MooseFS FUSE stale bytes, EDQUOT, vLLM in-process teardown, EXDEV pod paths). `code-style.md`'s checkpoint-per-phase rule is ADVISORY prose about PLANNING for phase failures; the finalization entry is DIAGNOSTIC prose about a specific class of failure that hits AT phase completion. Different reader triggers, different failure modes, different remediation shapes — they belong in separate files. Cross-reference is one-directional (code-style.md L53 already points at code-reviewer.md Step 3.6; no reverse pointer needed from gotchas.md because the two rules load on different `paths:` triggers and both are on-demand). *Source:* `.claude/rules/gotchas.md` current shape (bulleted list of specific traps), `.claude/rules/code-style.md` L53 (checkpoint-per-phase — advisory prose), and CLAUDE.md § Code Style pointer list (which imports `code-style.md` on `*.py` edits, distinct from the `gotchas.md` load triggers).

**Fork (b): does `planner.md` §9 need a new required `phase_outputs:` map?**

**Decision: yes, one line.** Without a plan-declared output/sentinel path, the reviewer's Step 0.69 gate degrades to a judgement call (task-body-flagged constraint) — the gate can grep for "does the phase check a sentinel" but not "does the phase check the RIGHT sentinel." The one-line §9 addition (an `off_pod_phases:`-style fenced-block requirement, conditional on the plan listing >1 phase) is the MINIMUM ratchet cost. The alternative — degrading the gate silently to CONCERNS on missing artifact names — is what the gate ALREADY does (§3.1 "Fingerprint-of-degradation"), so the §9 addition raises the artifact-name floor over time WITHOUT ratcheting the gate to a false FAIL. Two rules grow simultaneously (planner spec + code-reviewer gate), but each stays minimal. *Source:* task-body constraint ("A gate that cannot name the expected artifact will degrade to a judgement call"), planner.md §9 (L446–469 `off_pod_phases:` block precedent — a fenced-block requirement conditional on a plan property), `verify_plan.py:265` (`\**` admits the bold form for `Estimated GPU-hours (total):` — the same shape-flexible pattern applies to `phase_outputs:`).

**Fork (c): Step number — 0.69, 3.10, or a new top-level Step?**

**Decision: Step 0.69, inserted between 0.68 and 0.7.** The `.6x` sub-family is exactly the pre-diff-contract-check family this gate belongs to (Step 0.65 raw-completions upload, Step 0.67 compute-shape, Step 0.68 named-helper — all read the dispatcher for a property PLAN → CODE contract, exactly like phase-idempotency). A `3.x` step would live in the substance-of-diff family (Step 3.5 cached artifact, Step 3.6 long-loop restartability, Step 3.7 sibling sweep) — reasonable but wrong: this gate is a contract check on the dispatcher SHAPE, not on the correctness of the substance inside. *Source:* code-reviewer.md L668 (Step 0.67 sibling); L849 (Step 0.68 sibling); L910 (Step 0.7 boundary — pre-diff gates never short-circuit).

**Fork (d): waiver form — inline comment or plan-frontmatter flag?**

**Decision: inline comment `# PHASE_IDEMPOTENCY_EXEMPT: <reason ≥ 20c>`.** Mirrors two established patterns: `# CVD_PIN_EXEMPT: <reason>` on `scripts/*.sh` (per `workflow_lint.py --check-dispatcher-cvd-pin`) and `# WANDB_INTENTIONALLY_DISABLED: <reason ≥ 10 chars>` (per `--check-wandb-required`). Both landed rules use a same-line-or-immediately-preceding comment as the waiver channel; that shape is already in the reviewer's Grep repertoire, and the 20-char minimum enforces a real reason. A plan-frontmatter flag would require a `verify_plan.py` check and mint yet-another-plan-field; an inline comment lives with the code it exempts. *Source:* CLAUDE.md § Code Style "WandB live training metrics" bullet; gotchas.md L41 `CVD_PIN_EXEMPT` bullet.
