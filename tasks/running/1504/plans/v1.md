## 3. Design decision — option (d), with the tension engaged

The body's option sketch: (a) committed sidecar ceiling, (b) `--fix-ratchet` writer, (c) reasoned no-change + recovery recipe, (d) retire the total ratchet in favor of the per-channel gates. Scored against the four ACTUAL failure modes:

| Failure mode (measured) | Current | (a) sidecar | (b) `--fix-ratchet` | (c) no-change | **(d) retire total ratchet (CHOSEN)** |
|---|---|---|---|---|---|
| 1. Parallel-branch conflict on the constant line | fires on **every** concurrent growth pair (2/48 h) | **relocated, not fixed** — GitHub server-side merges ignore `.gitattributes` merge drivers, so a single-value sidecar line conflicts identically | unchanged (writer edits the same line) | unchanged | **eliminated** — no per-growth shared line exists. Residual: concurrent raises of the SAME grandfathered row's cap still conflict — a semantically REAL conflict (two edits to one row need human reconciliation) |
| 2. Parallel-branch conflict on the comment-history block | fires (block grows per bump) | fixable (drop history) | unchanged | unchanged | **eliminated** — block deleted; history lives in `git log` |
| 3. Growth without bump → fleet-wide trunk red (#1462) | fires | unchanged (forget the sidecar update instead) | unchanged (helps the fixer, not the forgetter) | unchanged | **eliminated for the ratchet** (nothing to forget). Residual: two individually-green branches summing past 8000 post-merge — requires total ≥ ~7,900 (today 6,761; the 7,200 WARN band gives an 800-B loud approach) |
| 4. Duplicate fix pipelines racing to bump (#1476/#1479) | fires | unchanged | unchanged | unchanged | **eliminated** — no bump to race on |

Only (d) addresses all four, because all four are consequences of ONE property: a per-growth edit to a shared single value. Any design that keeps that edit — wherever the value lives — reproduces modes 1/3/4; any design that derives the value automatically has no deliberateness left to defend. (b) is already half-shipped (FAIL messages print the exact paste value) and demonstrably did not stop the incidents.

**What replaces the coordination/deliberateness the merge conflict provided** (the declared "conflict as feature"):

1. **Row channel** — per-row 280-B cap + grandfather hug (#1269): a bloated row FAILs at edit time in the grower's own tree (guard hook) and at commit time (no-flags lint). The reviewed LESSONS.md diff itself is the visibility; the lint red is the enforcement.
2. **New-row channel** — index parity: a new row REQUIRES a reviewed `.claude/rules/<name>.md`, which only lands through the full workflow-fix pipeline. Adding always-on context via a new rule is deliberate by construction.
3. **Scaffolding channel (NEW)** — `_LESSONS_NONROW_MAX_BYTES = 900`: bytes the row grammar does not claim (header prose, headings, blank lines, malformed rows) are bounded by a fixed budget (546 B live + 354 B headroom). Without this, retiring the total ratchet would leave header prose ungated until 7200. Raised only on a deliberate header restructure — NOT per growth — so it cannot become a conflict magnet (header edit frequency since #1269: 0).
4. **Aggregate channel** — the 7200 WARN band (kept) + 8000 hard cap (kept), with WARN/FAIL messages now naming the 3 largest rows + sizes so the trim burden on whoever crosses a threshold is actionable, addressing the "crisis concentrates on the last grower" cost of removing the ratchet.
5. **Structural bound** — total ≤ 280 × (standard rows) + Σ grandfather caps + non-row budget; the row count only grows through channel 2. Worst-case bound today: 35×280 + 900 + 900 = 11,600 → the 8000 cap binds ~1,240 B above the live size.

**What is genuinely lost, quantified:** between 6,761 and 7,200 B, aggregate growth is visible only in reviewed diffs, not in lint output — max un-WARNed drift from today ≈ 439 B ≈ 3 median rows (median row = 128 B). Accepted against a measured 4 incidents/48 h; the per-row + parity gates still make each of those bytes individually reviewed.

**Out-of-scope siblings (named, not touched):** the agent-spec size ratchets (`AGENT_SPEC_SIZE_GRANDFATHER`) and the LESSONS per-row grandfather (`_LESSONS_ROW_GRANDFATHER_MAX_BYTES`) keep their hand-bumped hug pattern — there the conflict grain is a single file/row where concurrent edits genuinely need reconciliation, and their incident rate is not the driver here. Their own comment-history accumulation (the gotchas block, 9546-9560) is a candidate for the same history-to-git-log treatment someday; noted as prose only per the recursion guard — this session files nothing further.
