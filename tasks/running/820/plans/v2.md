## 3. Design

### 3.1 Pure helper in `src/explore_persona_space/task_workflow.py` (new, ~60 lines, placed adjacent to the `circuit_breaker_should_fire` family at ~line 1031)

```python
STAGE_RESULT_KINDS: dict[str, frozenset[str]] = {
    # stage token in the breadcrumb -> the marker kind(s) that complete it
    "verifying": frozenset({"epm:upload-verification"}),
    "interpreting": frozenset({"epm:interpretation"}),
    "clean-result": frozenset({"epm:clean-result-critique"}),
    "implementing": frozenset({"epm:experiment-implementation"}),
    "followup-implementing": frozenset({"epm:experiment-implementation"}),
    "free-analysis-followup": frozenset({"epm:free-analysis-followup-run"}),
    "methodology-reference": frozenset({"epm:methodology-doc-generated"}),
    "code-review": frozenset({"epm:code-review"}),
}
# epm:failure ALWAYS clears in-flight state for any stage.
_ALWAYS_RESULT_KINDS = frozenset({"epm:failure"})
# Liveness markers posted AFTER a breadcrumb refresh its freshness clock
# (a healthy long-running round keeps emitting these; a dead one goes silent).
STAGE_LIVENESS_KINDS = frozenset({
    "epm:codex-task-spawned", "epm:codex-task-completed",
    "epm:smoke-architecture-check", "epm:proposed-tests",
})
# epm:progress also refreshes, EXCEPT notes beginning "stage-dispatch "
# (a breadcrumb never extends its own or another stage's window).

def stage_dispatch_should_skip(
    events: list[dict], stage: str, round_num: int, window_minutes: float,
    *, now: datetime | None = None,
) -> str | None:
    """Return a one-line skip reason if a same-stage+round dispatch is
    already in flight, else None (dispatch may proceed).

    In flight == the most recent `epm:progress` breadcrumb whose note
    parses to `stage-dispatch stage=<stage> round=<round_num> ...` has
    (a) no stage-matching result kind and no epm:failure after it, and
    (b) effective age < window, where effective age is measured from the
    LATEST of {breadcrumb ts} ∪ {ts of subsequent liveness markers}.
    """
```

Scan logic (backwards over `events`): find the most recent breadcrumb matching BOTH `stage=` and `round=` tokens (parse fields, don't substring-match the whole note); if none → `None`. If any event after it has `kind` in `STAGE_RESULT_KINDS.get(stage, frozenset()) | _ALWAYS_RESULT_KINDS` → `None` (stage completed; a fresh dispatch is legitimate). Else compute effective age via the liveness-refresh rule; `age < window` → return the skip reason string (naming stage, round, breadcrumb ts, effective age, window, and which marker refreshed); `age >= window` → `None` (stalled — re-dispatch allowed). Unknown stage tokens fall back to `_ALWAYS_RESULT_KINDS` + window expiry only (conservative toward skip within the window, self-healing past it). `now` is injectable for tests; naming is `round_num` (not `round`) to avoid shadowing the builtin.

**Fact-checker-driven hardening (three corrections folded in from the Phase 1.5 pass):**

1. **Breadcrumb anchor:** a breadcrumb is an `epm:progress` event whose note field, after `lstrip()`, **BEGINS with** `stage-dispatch ` — never a substring match. (#778's line-130 "DUAL-DISPATCH DETECTED" note QUOTES the breadcrumb string; a substring match over-counts, verified by the fact-checker's `grep -c` returning 3 for 2 real breadcrumbs.)
2. **Stage-token normalization:** real breadcrumbs drift far beyond 8 canonical tokens (fact-checker census: `code-reviewing` ×127 vs `code-review` ×50; `followup-code-reviewing` ×55, `followup-interpreting` ×39, `followup-clean-result` ×28, `followup-verifying` ×19, plus a ~100-token free-form tail). Before map lookup, normalize: strip a leading `followup-` prefix (the follow-up loop's stages complete with the SAME result markers as their parent-pipeline namesakes), then apply aliases `{"code-reviewing": "code-review", "followup-code-reviewing": "code-review", "implementing": "implementing"}` — concretely `_normalize_stage(stage)` maps `followup-implementing`→`implementing`, `followup-code-reviewing`/`code-reviewing`/`followup-code-review`→`code-review`, `followup-interpreting`→`interpreting`, `followup-clean-result`→`clean-result`, `followup-verifying`→`verifying`. Tokens that normalize to nothing in the map (the free-form tail: `p6-judge`, `smoke-relaunch`, `running`, `planning`, `workload`, ...) take the documented unknown-stage fallback (`epm:failure` + window expiry) — degraded but safe, self-healing past the window. The dedup MATCH still compares the RAW stage token (a `followup-implementing` breadcrumb never dedups an `implementing` dispatch — different pipeline pass); normalization applies ONLY to result-kind clearing.
3. **Round association on the clearing side is inference-free by design:** result markers carry no machine-parsable `round=` field (fact-checker A11 — round lives in prose like "round 1"), so the helper clears on ANY same-stage result kind after the breadcrumb, round-agnostic. Safe because rounds per stage are sequential: a round-2 breadcrumb can only exist after round-1's result marker landed.

**Why code, not a model call:** the #778 incident IS an LLM orchestrator failing to execute a correct prose predicate; a deterministic scan is the fix, mirroring `circuit_breaker_should_fire`.

## 12. Decision Rationale

- **Freshness window: keep 15/30 min unchanged + add liveness-extension (not a longer fixed window, not a session-list check).** The incident duplicate arrived at 5m39s — caught by the existing 15-min window once the scan is backwards; the window value was never the defect. Implementer rounds routinely exceed 30 min, so a fixed window alone would license a "stalled" re-dispatch on a healthy long round; the liveness refresh (codex-task / smoke-check / progress markers the round itself emits, visible in §A at 22:28:54Z–22:31:56Z) extends exactly while the round demonstrably lives and expires when it dies. A `spawn_session.py list` check was rejected: dispatched subagents are Agent-tool children inside a session, invisible to the session list. **Source:** #778 events lines 116–130; SKILL.md guard section (window values + 45-min backstop cadence rationale); incident family #524/#535.
