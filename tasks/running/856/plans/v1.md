## 1. Goal, requirement, acceptance criteria

**Goal (from task frontmatter):** at ensemble verdict collection (Step 5b and the analogous 9a/9a-bis reads), check for durable outputs (a posted verdict marker or a written verdict file) before treating a subagent thrash-death/error notification as a reviewer no-show.

**Requirement:** an Agent-tool completion result reporting an error (autocompact thrash, crash, garbage/empty return) for a reviewer/critic/reconciler subagent must NEVER, by itself, trigger a no-show fallback or a unilateral single-reviewer ensemble decision. The orchestrator must first (1) re-read canonical task state for the round's expected verdict marker at the current version, and (2) when no marker exists, check the role's conventional durable output file. Only when neither exists does the existing no-show fallback fire.

**Ground truth (verified in #810 events.jsonl):** `epm:code-review v4` (PASS, blocker tags none) durably posted 2026-07-02T09:25:14Z; progress marker 09:27:00Z adopted "FAIL from the Codex verdict alone"; corrective progress marker 09:29:10Z re-classified it as a genuine PASS-vs-FAIL disagreement routed to the reconciler. The #810 v5 report's ad-hoc "durable-output check confirmed: no commit, no file, no marker" wording is the check this task codifies.

**Acceptance criteria:**
1. A named canonical rule exists at Step 5b of `.claude/skills/issue/SKILL.md` stating the two-step durable-output check, the "thrash-killed summary turn ≠ no-show" principle, the #810 incident citation, and the explicit preservation of the marker-posted `epm:failure` no-show path.
2. All 5 other identified ensemble-read sites (Step 5d fallback ¶, Step 9a decision table, Step 9a-bis decision ¶, Step 9b VC step 3, adversarial-planner Phase 2) either carry the rule or a one-line cross-reference to it.
